# F-52c632543366

## Purpose

The supplied static representation describes a non-returning sequence of indirect calls, byte accesses, and 32-bit memory accesses. After an initial traversal, execution repeats the same sequence using values produced near the end of the preceding traversal.

No application-level purpose is established. In particular, the evidence does not establish that the accessed locations are objects, device registers, buffers, or allocated storage. Descriptions such as initialization, serialization, or cleanup would be inferred intent rather than a supported contract.

The contract below preserves the visible ordering and data dependencies without assigning meanings to unknown callees. Arithmetic simplifications are conditional on the 32-bit machine-word interpretation described below.

### Width and notation

For the trace below:

- \(W(x)\) means the low 32 bits of \(x\).
- \(S_n(x)=W(x\,2^n)\).
- \(B(x)\) means an unsigned 8-bit read at address \(x\).
- A **selected byte write through \(x\)** means: first read \(B(x+1)\), then write one byte at address \(B(x+1)+17\).
- A **word write** writes 32 bits.
- Every stored byte is truncated to its low eight bits.
- Address arithmetic is described using 32-bit wrapping arithmetic, conditionally on that being the correct machine interpretation.

Thus a selected byte write uses the byte read as an address component, not as a pointer-sized value. Its destination lies between addresses 17 and 272 inclusive, before any platform-specific address interpretation.

The supplied signed expressions do not establish portable signed-overflow semantics. The wrapping model describes the apparent machine operations; it is not a claim that equivalent signed operations are well-defined in a high-level language.

The dependencies are unresolved. The opaque identifiers `F-D01` through `F-D24` below identify ordered **call-site groups**, not known implementations. Within a group, calls occur in the listed order.

A “four-call tail returning \(x\)” means four consecutive calls with no explicit arguments in the supplied representation; only the fourth call's result is used as \(x\). A discarded result is not evidence that the call has no side effects.

Every memory operation below occurs after all preceding listed calls have returned and before the next listed call. Unknown callees may modify memory or global state between these operations.

2. Three targets with no explicit arguments.
3. A target returning a 64-bit quantity.

\[

## Acceptance examples

These examples are conditional static expectations, not executed tests.

1. **Initial field truncation.** If the fourth argument has bits 20–27 equal to `0xAB`, the first selected byte write stores `0xAB`, regardless of bits 28–29. Bits 30–31 are masked away.

2. **Fresh selector reads.** If a dependency changes the selector at \(Q+1\) between steps 3 and 4, the two zero writes may reach different destinations. Reusing the first selector would not match the visible behavior.

3. **Retained selector.** If step 13 reads selector 7 and a subsequent dependency changes \(H+1\) to 9, step 14 still writes its word at address 27, not 29.

4. **Shift collapse.** Under 32-bit arithmetic, the first argument of the third call in step 5 is zero for every \(c\). Treating the intermediate value as an unbounded integer would change the contract.

5. **Parity boundary.** If \(q\) is odd, the step 11 word write stores `0x80000000`; if \(q\) is even, it stores zero.

6. **Unaligned access.** If the compact-address calculation yields 21, the word read is attempted at address 21. The visible body neither rounds the address nor rejects it. Success depends on the execution environment.

7. **Callee interference.** The direct zero write to \(H+1\) in step 10 does not prove that a later selected write uses selector zero: intervening dependencies may change that byte.

8. **No ordinary completion.** If all calls return and all memory accesses succeed, the final write is followed by another traversal, not a return to the caller.
