# F-8882bf052070

## Purpose

F-8882bf052070 performs a width-limited, integer-like conversion using a mutable descriptor, descriptor-selected callbacks, and digit-classification dependency F-1a5edad330b3.

It recognizes an optional sign when enabled, handles a leading zero and an eligible hexadecimal prefix, and accumulates nonnegative contributions returned by F-1a5edad330b3. A successful match may produce a destination write or may suppress assignment. Successful returns report a conversion count rather than an assignment count.

The integer-scanning interpretation is inferred intent. Established behavior consists of the reads, calls, comparisons, arithmetic, state transitions, and writes specified below. Standard formatted-input semantics—including whitespace skipping, end-of-input handling after the initial loop, and character pushback—must not be assumed.

## Interface

| Argument | Representation | Established use |
|---|---|---|
| First argument | 32 bits | Not directly used |
| Callback argument | 32 bits | Passed unchanged to input and restoration callbacks |
| Radix | Signed 32-bit integer | Used in radix selection, classification calls, and accumulation |
| Descriptor address | Address of mutable four-byte slots | Supplies flags, width, callback addresses, and destination-list cursor |

The callback argument’s interpretation as a pointer, handle, or other value is unknown.

The descriptor fields directly accessed are:

| Byte offset | Field | Access |
|---|---|---|
| 0 | Destination-list cursor | Read and advanced only on successful, nonsuppressed assignment |
| 4 | Flags | Read once before any external call |
| 8 | Signed conversion width | Read once before any external call |
| 24 | Input callback address | Read separately for each input invocation |
| 28 | Restoration callback address | Read when restoration is invoked |
| 32 | Initial-status callback address | Read separately for each initial-status invocation |

Other descriptor fields are not directly accessed by this function. External calls may access additional storage; their access sets are unknown.

Before invoking a descriptor-selected callback, the function masks its stored address with `0xfffffffc`, discarding the low two bits. No meaning for those bits is established.

### Flags

Only these flag bits directly affect this function:

| Mask | Effect |
|---|---|
| `0x1` | Suppress destination assignment and destination-cursor advancement |
| `0x8` | Select a two-byte destination write unless `0x800` is set |
| `0x40` | Enable recognition of a leading plus or minus and application of a recognized minus |
| `0x800` | Select a one-byte destination write, overriding `0x8` |

With neither destination-width flag set, assignment writes four bytes.

### Results

The result is represented as a signed 32-bit integer:

- **`-1`** when the input result from the terminating iteration of the initial callback loop is exactly `-1`.
- **`-2`** when processing reaches restoration without establishing a match.
- **The accumulated conversion count** when a match is established, whether or not assignment is suppressed.

There is no distinct result for narrowing, accumulator overflow, or assignment suppression. Count-overflow behavior is unresolved; successful results must not be promised to remain nonnegative outside the representable range.

### Storage and execution preconditions

Descriptor slots, destination-list entries, and represented addresses are four bytes wide. A successful, nonsuppressed conversion advances the destination-list cursor by four bytes regardless of the selected destination-write width.

Defined execution requires usable descriptor storage and callable resolved callback addresses. Assignment additionally requires a readable destination-list entry and writable destination bytes. No explicit null, bounds, alignment, address-validity, radix-validity, or destination-range checks are present.

These requirements continue across external calls. If a callback or F-1a5edad330b3 invalidates storage that is subsequently accessed, the function supplies no protective check or recovery path.

No direct allocation or release operation is present. Ownership transfer, retention, and release by external calls remain unknown.

## Behavior

### Initial state and captured configuration

The function reads flags first and conversion width second, before invoking any callback or F-1a5edad330b3.

Those values become local snapshots. Later changes to the descriptor’s flags or width do not replace the captured flags or the locally tracked remaining width. Callback addresses and the destination-list cursor are not captured at this point; they are read when needed.

The accumulator starts at zero. No minus sign or successful match is initially recorded.

### Initial input/status loop

At least one iteration occurs. Each iteration invokes:

1. The currently selected input callback, with the callback argument.
2. The currently selected initial-status callback, with no explicit argument.

A nonzero status result repeats the loop. A zero status result ends it. Only the input result from the terminating iteration becomes the current character for conversion.

The initial-status callback is not explicitly passed the input result. Any relationship between those results depends on external state or callback behavior.

For \(k\) completed iterations, the initial conversion count is \(k-1\), provided the count arithmetic remains representable. Thus discarded input results from earlier iterations contribute to a later successful count.

After the loop, a current input result exactly equal to `-1` causes immediate return of `-1`. This path does not invoke restoration, directly advance the destination cursor, or directly write a destination. An earlier input result of `-1` does not terminate the loop when its following status result is nonzero.

No whitespace classification is established by this loop. If status never becomes zero, this function does not progress to conversion or restoration.

### Optional leading sign

Sign recognition requires both positive remaining width and captured flag `0x40`.

- Character value `0x2b` is recognized as plus.
- Character value `0x2d` is recognized as minus and records a negative-sign state.

Either recognized sign adds one to the conversion count, consumes one width unit, and causes another input callback invocation. No initial-status callback accompanies this replacement input or any later input.

A sign does not establish a match. The replacement input is obtained even when the sign consumes the final available width unit. In that case digit processing is bypassed, restoration occurs, and the result is `-2`.

When sign recognition is disabled, those character values receive no special treatment here. If reached with positive width, their acceptance depends on F-1a5edad330b3.

### Leading zero and radix selection

When width remains positive after sign handling and the current character is `0x30`, the function directly accepts a leading zero. This:

- Establishes a provisional match.
- Adds one to the conversion count.
- Consumes one width unit.
- Obtains another input result.

The leading zero is not classified by F-1a5edad330b3. Its direct acceptance therefore does not depend on that dependency’s radix rules.

Subsequent behavior depends on remaining width, the new character, and the radix:

**No width remains, or the new character is neither `0x78` nor `0x58`.**  
Radix zero becomes 8. Any nonzero radix is retained. The leading zero continues to establish a match.

**Width remains, the new character is `0x78` or `0x58`, and radix is zero or 16.**  
A hexadecimal prefix is recognized. The provisional match is cleared, another width unit is consumed, another count unit is added, and another input result is obtained. Radix becomes 16.

The prefix alone is insufficient: at least one subsequent contribution must be accepted to reestablish a match. The input after the prefix is obtained even when the prefix exhausts the width.

**Width remains, the new character is `0x78` or `0x58`, and radix is neither zero nor 16.**  
The prefix is not recognized. Only the zero has been consumed by this special handling. The following character remains current for classification under the supplied radix, and the zero remains a successful match.

When leading-zero handling is not entered, radix zero becomes 10. This includes paths on which no positive width remains; such a radix decision need not lead to a classification call.

### Digit classification and accumulation

While remaining width is positive, the function invokes F-1a5edad330b3 with the current character and current radix.

A negative result stops digit processing. Any nonnegative result is accepted as a contribution. The function does not independently require that contribution to be less than the radix.

For each accepted contribution, the function:

- Multiplies the accumulator by the radix and adds the contribution.
- Establishes a match.
- Consumes one width unit.
- Adds one to the conversion count.
- Invokes the currently selected input callback for another current character.

The input call occurs even after the last permitted digit exhausts the width. That final input result is not classified when no width remains.

Only the initial-loop result has a local `-1` check. Later input results, including `-1`, are passed to F-1a5edad330b3 if width remains positive. Their rejection is not established without a contract for that dependency.

Accumulator multiplication, addition, count changes, and final negation use 32-bit integer representations. No wider accumulator, overflow check, saturation, or range error is shown. Reliable signed wrapping must not be inferred.

F-1a5edad330b3 may also have effects beyond its returned contribution. Such effects can change storage consulted by subsequent calls or assignment; they do not replace the captured flags or locally tracked width.

### Restoration

Except for the initial `-1` return, every returning path invokes the restoration callback once after digit processing or its bypass.

The callback receives the callback argument, not the current character. Its return value is ignored.

Restoration occurs even when:

- Original width is zero or negative.
- A sign exhausts the width.
- A hexadecimal prefix exhausts the width.
- No contribution is accepted.
- Assignment is suppressed.

“Restoration” describes inferred intent, not an established effect. The call does not prove pushback, successful reversal of input, or any particular resulting stream position.

### Match result and assignment

After restoration, absence of a match produces `-2`, without direct destination-list access or destination assignment.

A match with captured flag `0x1` set returns the conversion count without directly accessing the destination-list cursor.

For a match without assignment suppression, the observable assignment accesses occur in this order:

1. Read the destination-list cursor from descriptor offset 0.
2. Write that field with the cursor advanced by four bytes.
3. Read the destination address from the entry identified by the old cursor.
4. Negate the accumulator if an enabled minus sign was recognized.
5. Write the selected-width result to the destination.

Cursor advancement precedes reading the old list entry. If the list entry overlaps the cursor field, the address read can therefore reflect the cursor update.

The destination write is one byte for `0x800`, two bytes for `0x8` without `0x800`, and four bytes otherwise. Narrow writes retain the low 8 or 16 bits; no narrowing-range error is reported. Bytes outside the selected destination region are not directly written by this assignment.

## Side effects

The function directly invokes descriptor-selected callbacks and F-1a5edad330b3. Its direct storage writes are the conditional destination-cursor update and destination assignment.

Effects of **all** external calls are otherwise unconstrained by the supplied evidence. In particular, F-1a5edad330b3 is not established to preserve:

- Global state.
- Descriptor storage.
- Callback-address slots.
- Destination-list storage or destination contents.
- Ownership state, including whether storage remains allocated.

The same preservation guarantees are absent for descriptor-selected callbacks.

These unknown effects matter at specific later observations:

- An input callback can affect the initial-status callback address read immediately afterward.
- Any external call can affect later callback-address reads.
- F-1a5edad330b3 can affect the input callback selected after an accepted contribution.
- A negative classification result can still be accompanied by effects that influence restoration and assignment.
- Restoration and earlier calls can alter the destination cursor or list entry before assignment reads them.
- Changes to descriptor flags or width do not override the invocation’s captured configuration.

A failure or suppressed assignment therefore does not imply unchanged descriptor, global, destination, or ownership state. It means only that the function omits its own corresponding assignment accesses.

The conversion count is not established as net input consumption. It includes discarded initial-loop results, does not explicitly count the final lookahead input, and cannot account for unknown restoration behavior.
