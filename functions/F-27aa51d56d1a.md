# F-27aa51d56d1a

## Purpose

F-27aa51d56d1a performs a synchronous traversal controlled by mutable state, object-provided results, and two selectors. Each completed iteration operates on the current object, installs that object’s link as the current-object pointer, operates on the replacement object, enumerates and processes dependency-provided object pointers, and samples a continuation byte.

Enumeration does not establish removal of the returned objects, depletion of the associated collection, or an empty collection afterward. The subsequent collection-related dependency has unknown semantics.

Normal termination clears a state byte, conditionally invokes a pending-item callback, optionally invokes a completion callback, and finalizes a temporary context.

“Current object,” “pending item,” and “collection” describe observable roles. Activation, destruction, reference release, and ownership transfer are not established meanings of the calls.

## Behavior

### Entry and ordered stop checks

The function invokes F-17c2f3b940d8 with the invocation-wide temporary context and integer zero. After that returns, it establishes a local continuation value of one and writes one to state byte `0x0C`.

At the start of each iteration, the following conditions select normal termination, with short-circuiting in this order:

1. The state’s current-object pointer is null.
2. The retained continuation value is zero.
3. The stop identifier at `0x08` is nonzero, and the current object’s slot-`0x68` result equals the stop identifier.

A null current object therefore prevents both the continuation-dependent object work and the stop query. A zero retained continuation prevents the stop query. A zero stop identifier also prevents that query.

The initial continuation value does not come from an object. An initial object’s byte at `0x20` cannot, by itself, suppress the first iteration.

The stop identifier is read to decide whether to call slot `0x68`, and is read again for equality after that call. A mutation by the call can therefore change the value used in the comparison.

### Normal termination

The normal termination sequence is:

1. Write zero to state byte `0x0C`.
2. Examine the pending-item word at `0x20`.
3. If nonzero, obtain the callback through the address at `0x00` and invoke it with the state address, pending-item word, and auxiliary byte at `0x24`.
4. After that callback returns, write zero to the pending-item word, then zero to the auxiliary byte.
5. Examine the completion target at `0x28`; if nonzero, invoke it with the word at `0x2C`.
6. Finalize the invocation-wide temporary context.
7. Return.

If the pending-item word is zero, neither pending-item dispatch nor either associated clearing write occurs. A nonzero auxiliary byte can consequently survive normal termination.

The pending-item callback observes the state byte already cleared, but runs before the pending fields are explicitly cleared. Values it writes into those fields are overwritten by the subsequent clearing writes if it returns normally.

The completion-target check occurs after pending-item handling. The pending-item callback can therefore affect that check and the completion argument. No explicit clearing of the completion target or argument is shown.

### Initial-object operation within an iteration

If no stop condition applies, invoke the current object’s slot `0x74` and test its 32-bit result for zero.

Two operation paths follow:

- **Paired path:** slot `0x54` with the current-object pointer and integer zero, followed by slot `0x54` with the current-object pointer and integer one.
- **Alternate path:** slot `0x58`.

Selection is as follows:

| Slot `0x74` result | Mode | Byte `0x21` observations | Operation sequence |
|---|---|---|---|
| Zero | Zero | Not read for selection | Paired path |
| Zero | Nonzero | Read once | Alternate if nonzero; paired otherwise |
| Nonzero | Zero | Not read for selection | Slot `0x80`, then paired path |
| Nonzero | Nonzero | First read is nonzero | Alternate path; no slot `0x80` |
| Nonzero | Nonzero | First read is zero | Slot `0x80`, then another byte read; alternate if now nonzero, paired otherwise |

The slot-`0x80` result is stored but has no subsequent observable use in this function. It does not directly choose the operation path. Its call remains observable, including any mutations it causes.

In nonzero mode, the post-`0x80` byte read is a fresh read through the state’s current-object pointer. It need not observe the same value, or even the same object, as the earlier read.

Current-object and dispatch-table accesses recur across the call sequence. The function does not establish a stable object snapshot spanning these calls.

### Link transition

After the initial-object operation:

1. Capture the current-object pointer from state.
2. Read the captured object’s link at `0x14`.
3. Store that link into state field `0x04`.
4. If the captured pointer is nonnull, invoke its slot `0x04`.
5. Reload state field `0x04`.
6. If the reloaded pointer is null, invoke F-a817d8d58c10, annotated as nonreturning.

The old-object call occurs after the link has been installed. It can change the state’s current-object field before the null check.

The conditional old-object call does not make a null captured pointer safe: the link dereference precedes that condition. This matters if an earlier indirect call changes the current-object field to null.

A null link does not unconditionally imply failure. The old-object call can replace it with a nonnull pointer before the reload. Conversely, a nonnull link does not guarantee avoidance of failure if that call clears the field.

### Mode recomputation

With a nonnull reloaded replacement pointer:

- If the primary selector is nonzero, invoke that object’s slot `0x98`. Mode becomes zero on a 32-bit match and one on a mismatch. The secondary selector is ignored.
- Otherwise, if the secondary selector is nonzero, invoke slot `0x68`. Mode becomes zero on a 32-bit match and one on a mismatch.
- If both selectors are zero, mode becomes zero without either selector-query call.

The recomputed mode controls replacement-object handling and remains the mode for the next iteration’s initial-object handling.

Some intermediate values are represented in a 64-bit container in the supplied evidence. Only the low 32 bits participate in selector equality. This does not establish 64-bit identifiers or 64-bit pointers.

### Replacement-object operation

With nonzero mode, read byte `0x21` through the state’s current-object pointer:

- If nonzero, invoke slot `0x58` on the object captured by that selection.
- If zero, take the paired sequence below.

With zero mode, take the paired sequence without reading byte `0x21` for selection:

1. Invoke slot `0x54` with the current-object pointer and integer zero.
2. Invoke slot `0x6C`.
3. If its 32-bit result is nonzero, invoke slot `0x78`.
4. Invoke slot `0x54` with the current-object pointer and integer one.

The slot-`0x78` result is stored but not subsequently used observably by this function. Its conditional execution and effects remain significant.

Calls within the paired sequence reload the current-object field and dispatch information. Unknown callees are not assumed to preserve either.

### Enumeration and continuation sampling

After replacement-object handling:

1. Invoke F-8ca21d3a8cca with the enumeration temporary context and state address plus `0x10`.
2. Repeatedly invoke F-b38a3aba0e18 with that context and an object-pointer output location.
3. For each nonzero 32-bit enumeration result, inspect the output pointer. If nonnull, invoke its slot `0x04`.
4. Stop requesting elements when the enumeration result is zero.
5. Invoke F-d0d3f100effc on the enumeration context.
6. Invoke F-58eb88c5871a on state address plus `0x10`.
7. Read byte `0x20` through the then-current object and retain it as the continuation value.
8. Return to the opening stop checks.

A nonzero enumeration result with a null output pointer skips only that element’s indirect call. Enumeration continues. A zero enumeration result prevents processing of that call’s output pointer.

These calls establish enumeration and conditional processing, not collection removal. Neither the zero enumeration result, context finalization, nor the subsequent collection-related call establishes an empty collection.

The continuation byte is sampled after all collection-related calls. There is no explicit null check before this read. If a dependency leaves the current-object field null or invalid, no safe completion of that read is demonstrated.

## Side effects

Established direct effects are:

- Writes of one and zero to state byte `0x0C` at entry and normal termination.
- Installation of a link into the current-object field during each iteration.
- Conditional clearing of the pending-item word and auxiliary byte.
- Ordered callback, dispatch-slot, and direct-dependency calls.
- Reads of state configuration, object links, branch bytes, continuation bytes, and dependency results.

No direct allocation, deallocation, reference-count change, or ownership transfer is shown. Slot `0x04` must not be interpreted as release or destruction without additional evidence.

Collection membership and depletion are not direct effects established here. The enumeration and subsequent dependency may have such effects, but their contracts are unavailable.

Unknown callees may mutate reachable memory or globals, including callback configuration, current-object state, collection-related state, and object lifetime. No preservation guarantee is supplied.

The explicit nonreturning path occurs before collection enumeration and normal-termination cleanup. No local rollback, error result, or recovery is shown. Exceptional exits from other dependencies have no established cleanup behavior.

All explicit address calculations use fixed byte offsets. No variable-length arithmetic or size-overflow handling is shown; valid addressability remains a precondition.

## Acceptance examples

These are conditional consequences of static evidence, not executed tests. Unless a case specifies mutation, dependencies are assumed to return normally and preserve the memory required by that case.

1. **Initially null current object.** Invocation-context initialization occurs, then state byte `0x0C` is written one and zero. No object dispatch occurs. Pending-item handling, optional completion, and context finalization retain their normal order.

2. **Initial continuation byte is zero.** A nonnull initial object is not stopped solely by its byte at `0x20`. The local continuation initially equals one.

3. **Stop match.** With a nonnull current object, nonzero retained continuation, and a nonzero stop identifier matching slot `0x68`, termination occurs before slot `0x74` or link replacement.

4. **Stop query changes the identifier.** If slot `0x68` changes the stop identifier, equality uses the field read after that call, not necessarily its earlier nonzero value.

5. **Absent pending item.** With a zero pending word and nonzero auxiliary byte, termination skips pending dispatch and leaves that byte unchanged.

6. **Pending callback rewrites pending fields.** If the callback installs another pending value and auxiliary byte, the following explicit zero writes overwrite both. A completion target installed by the callback can be observed afterward.

7. **Branch changes during slot `0x80`.** With nonzero mode, nonzero slot-`0x74` result, and initially zero byte `0x21`, slot `0x80` executes. If the subsequent byte read is nonzero, slot `0x58` follows instead of the paired calls.

8. **Replacement remains null.** If the stored link is null and the old-object call leaves the current-object field null, F-a817d8d58c10 is reached. Normal completion and enumeration are not reached.

9. **Replacement is repaired.** If a null link is stored but the old-object call installs a valid nonnull current object, the post-call check does not select the explicit nonreturning path.

10. **Primary-selector precedence.** With both selectors nonzero, slot `0x98` determines mode. A mismatch selects one even if a secondary-selector query would have matched.

11. **Null enumerated pointer.** A nonzero F-b38a3aba0e18 result with null output causes no slot-`0x04` call for that output, but another enumeration request follows.

12. **Enumeration ends.** A zero enumeration result leads to context finalization and F-58eb88c5871a. Acceptance requires that call order, not proof of removals or an empty collection afterward.

13. **Sampled continuation is zero.** After collection-related calls, a zero continuation byte makes the next opening check terminate without a stop-identifier query, provided the necessary pointer accesses remain valid.
