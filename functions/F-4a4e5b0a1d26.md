# F-4a4e5b0a1d26

## Purpose

The supplied representation describes a routine that interleaves unresolved indirect calls with computed-address byte and 32-bit memory writes. It forwards selected inputs, call results, and ambient machine state to those calls. Its visible tail terminates at an invalid-instruction boundary rather than an ordinary return.

No application-level purpose is established. Describing this routine as an initializer, allocator, serializer, or cleanup operation would exceed the evidence.

This contract specifies the observable sequence represented by the supplied material, conditional on execution reaching each operation. It does not establish that the recovered control flow is executable or complete. The supplied material explicitly warns of invalid instruction data and overlapping global storage.

## Side effects

### Memory effects

Visible writes have widths of one or four bytes. There is no visible bulk-memory operation whose extent can be established independently of unresolved callees.

Repeated byte-selected destinations have the form “unsigned byte plus 17,” giving addresses 17 through 272. The retained-byte word write at \(s_0+68\) targets an address from 68 through 323.

Absolute address 36 receives four separate zero-word writes. Those writes must not be collapsed into one final-state assertion: intervening calls can observe or modify the location.

Computed addresses may alias:

- Each other.
- Absolute address 36.
- Bytes used in subsequent address selection.
- Storage affected by unresolved calls.

Consequently, the final memory contents cannot generally be derived by considering each apparent field independently.

### Errors and partial effects

## Acceptance examples

These examples are conditional static expectations, not executed tests.

1. **Unused first input.** If all other explicit and ambient inputs, dependency behavior, and memory observations are identical, changing only the first explicit input introduces no difference in the operations visibly represented here.

2. **First-call arguments.** If the second input is `0x11223344`, the third input is 15, and the relevant ambient register is 63, F-0100 receives `0x11223344`, `0x11223344`, 15, and 7.

3. **Input-derived address.** Under the 32-bit address model, third inputs 0 through 7 each select address 36 for the first third-input store. Third input 8 selects address `0x80024`. The stored value remains the complete third input.

4. **Address wraparound.** A third input of `0x00010000` gives a shifted value of `0x2000`; multiplication by `0x80000` wraps to zero under the stated model. The selected address is therefore 36, and the stored word is `0x00010000`. This is not evidence of validity checking.

5. **Byte-address selection.** If a byte read at \(B+1\) returns 255, the following byte write targets address 272. It does not target an address loaded as a full-width pointer.

6. **Fresh selector reads.** If an intervening dependency changes the byte at \(B+1\) from 2 to 9, the two byte writes around F-1100–F-1106 target addresses 19 and 26 respectively.

7. **Retained selector.** If the read defining \(s_0\) returns 7, the later zero-word write targets address 75 even if F-1400–F-1404 changes the byte at \(C+1\).

8. **Byte truncation.** A final-stage value \(y=65\) makes the low-byte form of \(4y\) equal 4. The byte write does not retain the full value 260.

9. **Masked extraction.** \(E(\texttt{0xffffffff})\) is 255: the mask and shift produce `0x3ff`, and byte storage discards its upper two bits.

10. **Repeated global clearing.** A dependency that writes a nonzero value to address 36 between visible clears does not invalidate the contract. A later visible clear writes zero again; no final zero guarantee survives arbitrary later dependency effects.
