# F-94c6d688b044

## Purpose

F-94c6d688b044 selects one of two stored receiver pointers and makes one indirect call through the selected receiver’s first dispatch-table entry. It forwards one 32-bit value read from caller-supplied storage, two additional 32-bit values, and a final zero argument.

The established behavior is a selection-and-dispatch operation. The meaning of the two receiver slots, the operation performed by the selected target, and the meaning of the forwarded values are unknown. Describing the slots as particular operating modes, resources, or ownership categories would exceed the available evidence.

## Interface

The function accepts five arguments, in this order:

| Position | Contract role | Established representation and use |
|---|---|---|
| 1 | Container address | Address-bearing value represented as a 32-bit integer. Used to locate receiver-pointer slots at byte offsets 4 and 8. |
| 2 | Value address | Pointer to storage from which one 32-bit value is read. The loaded value, not this address, is forwarded. |
| 3 | First forwarded value | A 32-bit value passed to the indirect target without visible modification. |
| 4 | Second forwarded value | A 32-bit value passed to the indirect target without visible modification. |
| 5 | Selector | A 32-bit integer tested for equality with zero. Zero chooses the slot at offset 4; every nonzero value chooses the slot at offset 8. |

The function exposes no return value. If the indirect target returns normally, this function returns afterward without exposing a result from that target.

The container must make the selected receiver-pointer slot readable:

| Byte offset from container address | Use |
|---|---|
| 4 | Receiver-pointer slot selected when the selector equals zero |
| 8 | Receiver-pointer slot selected when the selector is nonzero |

The selected receiver participates in a two-level dispatch layout:

1. Its initial word supplies a dispatch-table address.
2. The initial entry of that table supplies the callable target.

The selected receiver itself is passed as the target’s first argument. The dispatch-table address is not substituted for the receiver argument.

The supplied representation indicates a 32-bit address model: the container address is carried in a 32-bit integer, and a receiver’s initial 32-bit word is used as a table address. The complete platform ABI, pointer alignment requirements, and byte order are not supplied. Those details remain platform prerequisites rather than independently established properties.

## Behavior

### Receiver selection

The selector is tested only for zero versus nonzero. It is not used as an array index and is not restricted to the values zero and one.

- A zero selector selects the receiver pointer stored at container offset 4.
- Any nonzero selector selects the receiver pointer stored at container offset 8.

Negative selector values therefore take the same branch as positive nonzero values. Selector magnitude does not change the chosen offset.

The selected pointer is loaded before the subsequent indirect-call expression is evaluated. The other receiver slot is not visibly read.

### Target resolution and argument construction

The selected receiver’s initial word is interpreted as a dispatch-table address. The first entry of that table supplies the call target. No nonzero dispatch-entry offset is visible.

The indirect target receives five arguments, in this order:

| Target argument | Value supplied |
|---|---|
| 1 | The selected receiver pointer |
| 2 | The 32-bit contents read through the value address |
| 3 | The first forwarded value |
| 4 | The second forwarded value |
| 5 | Zero |

The value address is not itself forwarded. The wrapper reads its 32-bit contents and passes those contents as the second target argument. If that value encodes an address, handle, flags, or another structured quantity, interpreting it is outside this function’s visible behavior.

The two forwarded values undergo no visible arithmetic, masking, normalization, or semantic validation. Their 32-bit representations are carried into the call.

The final argument is fixed at zero and is independent of all five incoming arguments. Its semantic type and purpose are unknown; the evidence does not establish whether the target treats it as an integer, Boolean, null address, option field, or another ABI-compatible value.

### Ordering guarantees and limits

The visible ordering establishes that:

1. The selector determines which receiver slot is used.
2. The selected receiver pointer is loaded.
3. The target and outgoing argument values are obtained for the call.
4. The indirect target is invoked.
5. If it returns normally, the wrapper returns.

Target resolution has a necessary dependency order: the receiver’s initial word must supply the table address before the table’s first entry can supply the callable target.

The evidence does **not** establish a total order between the 32-bit value read and the reads used to resolve the target. Both are part of evaluating the indirect call. A behavioral contract must not promise, for example, that the value read occurs before the dispatch-table entry read, or the reverse.

No explicit reread of the selected container slot is visible after its pointer has been obtained. Consequently, a later change to that slot does not, by itself, replace the receiver value already selected for this invocation. Concurrent mutation, synchronization, and memory-model guarantees are otherwise unspecified.
