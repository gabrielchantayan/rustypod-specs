# F-422afe36d401

## Purpose

The supplied static representation establishes an ordered sequence of memory writes, with an optional initialization-like phase, two unresolved indirect calls, and substantial dependence on machine state not represented by the four explicit arguments.

The function does not expose a defined return value. Its observable results are memory changes and any effects of the indirect calls.

An interpretation as initialization, dispatch setup, or low-level machine configuration is **inferred intent**, not an established contract. In particular, several addresses are produced by multiplying integer or pointer-shaped values, and the unconditional phase can access very low addresses. These operations must not be normalized into conventional structure initialization.

This contract describes the supplied representation independently of whether it accurately models executable instructions.

The first and fourth arguments are represented as signed integer values, although both are used to construct addresses. The second and third arguments have no established signedness.

### Address and arithmetic model

Explicit word-sized memory transfers are 32 bits, halfword transfers are 16 bits, and the first indirect call’s captured result is 64 bits. Pointer arithmetic is represented in a 32-bit address space.

For ordinary, non-overflowing calculations, the address formulas below are established directly. Where multiplication or addition exceeds the represented signed range, exact executable behavior is **documented_only**: the supplied text does not establish overflow semantics independently of its recovered integer expressions.

Narrowing to 16 bits retains the low 16 bits. No byte order is established. A 64-bit write therefore specifies a width and bit pattern, not an ordered pair of 32-bit words.

The representation requests word writes at potentially unaligned addresses. Whether those accesses succeed, fault, split into smaller accesses, or have device-specific effects depends on the execution environment.

## Behavior

All ordering below is conditional on preceding accesses and calls completing normally. A fault or nonreturning dependency can prevent all later operations.

### 1. Optional phase

This phase executes only when the fourth argument is nonzero.

For clarity, “first source word” and “second source word” mean the values read during this phase. They are snapshots, not requirements to reread the source later.

1. Write a 32-bit address value equal to the first argument plus `0x12` at the address equal to the first argument plus `0x52`.

2. Read a 32-bit word from the ambient source address.

3. Read a second 32-bit word from that source address plus four bytes.

4. Write the low 16 bits of the second source word to the ambient initial halfword destination.

5. Form the doubled scale value by multiplying the ambient scale word by two.

6. Write the low 16 bits of the doubled scale value to the same initial halfword destination. This is a second write, not a replacement for the preceding write in the observable sequence.

7. At the doubled scale address plus four bytes, write the original scale word as a 32-bit value.

8. At the doubled scale address, write the doubled scale value as a 32-bit value.

9. Form a second address by doubling the numeric value of the initial halfword destination.

10. Again write the doubled scale value as a 32-bit value at the doubled scale address.

11. At the doubled scale address plus four bytes, write the newly formed doubled-destination address as a 32-bit value.

12. At the doubled scale address plus eight bytes, write the first source word as a 32-bit value.

13. At the address equal to four times the initial halfword destination plus `0x20`, write the first source word as a 32-bit value.

14. At the doubled-destination address, write the low 16 bits of the second source word.

These writes are ordered even where an earlier value is subsequently overwritten. In particular:

- The initial halfword destination receives two distinct write events.
- The doubled scale address receives the same 32-bit value twice.
- The word at doubled scale plus four receives two potentially different values.

Aliasing can make other writes overwrite one another as well. No distinctness between any supplied or derived addresses is established.

### 2. First indirect call and result record

Still within the nonzero-fourth-argument phase, execution invokes **F-UNRESOLVED-01**.

Its target address is the ambient return-address-like word with its bottom two bits cleared, followed by an addition of `0x328`.

The three represented arguments are:

1. The fixed value `0x0897f21c`.
2. The arithmetic right shift by 31 bits of the doubled-destination address interpreted as a signed 32-bit value.
3. The fixed value `0x87000000`.

The second argument is consequently zero when the doubled-destination address has a clear sign bit and all-one bits when it has a set sign bit, under the represented arithmetic-shift interpretation.

The call produces a captured 64-bit result. After it returns, a record destination is formed by bitwise AND between:

- The numeric value of the original initial halfword destination.
- The previously captured first source word.

The following writes then occur in order:

| Record offset | Width | Value |
|---:|---:|---|
| `0x00` | 64 bits | Captured result of F-UNRESOLVED-01 |
| `0x08` | 32 bits | Fourth explicit argument |
| `0x0c` | 32 bits | Captured first source word |
| `0x10` | 32 bits | Captured second source word |

These are offsets in bytes. In particular, the last write is at offset `0x10`, not immediately after the initial 64-bit result.

The record destination can be zero or overlap earlier destinations. It is not established as an allocated object.

The captured source words are not explicitly reloaded after the call. However, this does not establish that the callee preserves unrelated globals or memory.

### 3. Unconditional global-pointer sequence

This phase executes whether the fourth argument is zero or nonzero.

First, the low 16 bits of the pointer-valued global are assigned to the global scalar.

Next, the scalar’s value is written through the pointer-valued global.

The source establishes these as separate assignment steps. It does not establish a permanently cached pointer across them. If the scalar assignment aliases storage used by the pointer-valued global, the destination of the subsequent indirect write can change.

The indirect write’s exact storage width is **documented_only**, because the declaration of the global pointer’s pointed-to type is not provided. The value assigned to the scalar is established as the low 16-bit extraction; that does not by itself prove the width of every subsequent global access.

### 4. Unconditional fourth-argument-derived writes

After the global-pointer sequence:

1. Form an address equal to the fourth argument plus `0xf4`.

2. At the address equal to the fourth argument plus `0x134`, write that formed address as a 32-bit pointer value.

3. At the formed address, write its own low 16 bits.

4. Form an address equal to 16 times the fourth argument plus `0x11`.

5. At this new address, write the address itself as a 32-bit value.

6. Double the address previously formed as the fourth argument plus `0xf4`, interpret the doubled value as signed, and arithmetic-right-shift it by ten bits. Treat the resulting value as another address.

7. At that shifted address, write its own low 16 bits.

8. Repeat exactly the same halfword write at the shifted address.

9. At the fourth argument plus `0xf6`, write the 16-bit value `0x0050`.

The two identical halfword writes must remain separate observable operations. They may matter for volatile or device-backed memory even if ordinary RAM would retain the same final value after either one.

No null check, address-range check, alignment check, or allocation check is represented.

### 5. Fixed global assignments and final dispatch

Next, three global slots receive the following values in order:

1. `0xf430`.
2. `0x0897f430`.
3. Zero.

Their exact store widths are not established by the supplied declarations. The numeric assignments and their order are established.

Execution then reads the global selector, converts it to a 32-bit address-like value, and writes the 32-bit value `0x0897f430` at that address.

Finally, execution invokes **F-UNRESOLVED-02** at an address formed by adding `0x0897f314` to the ambient dispatch base.

Its four represented arguments are:

1. The selector-derived destination address, advanced by 16 bytes, then multiplied by `0x01000000`.
2. Zero.
3. `0x5000`.
4. `0x56`.

The 16-byte advance follows from advancing a pointer to 32-bit elements by four elements.

Under a 32-bit wrapping arithmetic interpretation, the first argument depends only on the low byte of the address after that advance. Whether that interpretation matches the executable is not independently established.

No return value from this final dependency is consumed. If it returns normally, this function ends.

## Side effects

### Memory and ordering

The function performs:

- Explicit 16-bit, 32-bit, and 64-bit memory writes.
- Two explicit 32-bit source reads in the optional phase.
- Global reads and writes with partially unspecified declarations.
- Two indirect calls when the fourth argument is nonzero, otherwise only the final call.

The ordered duplicate writes are part of the contract. A final-memory snapshot is insufficient to demonstrate all represented behavior.

There is no established separation between source memory, destinations, globals, or code-adjacent addresses. Earlier writes can therefore affect later reads, including the final selector read. Conversely, the two optional-phase source values are captured before the later writes in that phase.

The supplied representation does not establish synchronization, atomicity, memory barriers, or volatile-access guarantees.

No allocation or explicit release operation is visible.

That does not prove that either unresolved dependency avoids allocating, freeing, transferring, or invalidating memory. No ownership transfer can be inferred from the pointer-shaped arguments or the 64-bit result.

The caller or surrounding environment must provide whatever address validity and object lifetime the actual execution requires. The necessary readable and writable regions depend on ambient state and on aliasing.

### Errors and partial execution

Invalid addresses, unsuitable alignment, inaccessible indirect-call targets, or dependency failures may stop execution after a prefix of the writes. The function does not explicitly undo those effects.

## Acceptance examples

These examples are conditional static acceptance criteria, not runtime observations.

### Zero fourth argument does not make execution inert

Given a fourth argument of zero, and assuming all preceding operations succeed:

- The optional phase and F-UNRESOLVED-01 are skipped.
- The first explicit argument is not directly used.
- A 32-bit value of `0x000000f4` is written at address `0x00000134`.
- A halfword value of `0x00f4` is written at address `0x000000f4`.
- A 32-bit value of `0x00000011` is written at address `0x00000011`.
- Doubling `0xf4` and shifting right by ten produces zero, so two halfword writes of zero target address zero.
- A halfword value of `0x0050` is written at address `0x000000f6`.

This example requires an environment in which those low-address accesses complete. Otherwise, only the prefix before the first fault is required.

### Source-halfword narrowing

Given a nonzero fourth argument and a captured second source word of `0x1234abcd`, the first write to the initial halfword destination carries `0xabcd`.

The next write to that same destination instead carries the low 16 bits of twice the ambient scale word. Both events occur even if the values happen to match.

### Indirect result layout

Given that F-UNRESOLVED-01 returns a particular 64-bit bit pattern, that exact pattern is written at offset zero of the AND-derived record destination.

The fourth argument follows at offset eight, the captured first source word at offset twelve, and the captured second source word at offset sixteen. This criterion does not impose a byte order.

### Aliasing changes final contents, not the prescribed sequence

If the doubled scale address equals the record destination, the later 64-bit result write can overwrite earlier scale-related data.

Acceptance must account for that alias rather than requiring both logical values to survive simultaneously. Earlier accesses still remain part of the required trace.

### Dependency effects remain visible

If F-UNRESOLVED-01 changes the final selector global, and no intervening operation changes it again, the unconditional selector read observes the changed value.

The contract must not substitute the selector’s value from function entry.
