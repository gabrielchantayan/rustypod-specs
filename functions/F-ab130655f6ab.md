# F-ab130655f6ab

## Purpose

F-ab130655f6ab conditionally updates a caller-supplied mutable object using a position and a mode-dependent value supplied by a second object.

The established behavior is a sequence of helper calls controlled by a 16-bit field in the mutable object. The requested position remains fixed throughout the invocation. Progress through the repeated phase therefore depends on changes to the mutable object, not on advancing the position.

The structure suggests a position-based replacement or reduction operation over four-byte entries. That interpretation is **inferred intent**, not an established semantic contract: the meanings of the entries, the sentinel value, and the helper operations are unavailable.

## Behavior

### 1. Temporary setup and initial admission

The first observable operation is a call to **F-c41e7e373603**, receiving the temporary's address. This happens even when the requested position will subsequently exceed the mutable object's leading field.

After that call returns, the function reads the descriptor's unsigned 16-bit position. It retains both its original 16-bit value and an unsigned 32-bit representation. These represent the same number, from 0 through 65,535.

The function then reads the mutable object's leading unsigned 16-bit field.

- If the position is greater than that field, no further local processing occurs.
- Otherwise, the function enters the repeated-phase decision.

Initialization therefore precedes both the descriptor-position read and the admission comparison. Any changes caused by F-c41e7e373603 occur before those reads.

### 2. Repeated processing at a fixed position

The repeated phase runs while the retained position is strictly less than the mutable object's current leading field. That field is read again for each condition evaluation.

Each iteration performs these operations in order:

1. Read the temporary's associated four-byte slot and the mutable object's four-byte field at offset 4. Invoke **D-01** with those two values and a byte quantity equal to four times the retained position.
2. Write the originally captured 16-bit position into the first 16-bit slot of the temporary.
3. Invoke **F-c5cc0d64a43b** with the temporary's address.
4. Invoke **F-eca0b6384dc0** with the retained position and the mutable object's address.
5. Select a helper according to the mode:
   - If the mode is exactly 1, read the descriptor's four-byte field at offset 8 and invoke **F-7913cbe7fa05** with that value and the mutable object's address.
   - Otherwise, read the descriptor's two-byte field at offset 6 and invoke **F-7d066c616443** with that value and the mutable object's address.
6. Invoke **F-5d01188e4589** with the temporary's address and the mutable object's address.

The loop then reevaluates its condition.

The retained position is never incremented or otherwise changed. The descriptor's position is not reread. Conversely, the mutable object's leading field, its offset-4 field, and the selected descriptor payload are not established as immutable cached values: the relevant reads occur at their respective use sites.

The source does not specify the relative evaluation order of argument reads within an individual call. It does establish the ordering between the calls and the explicit write to the temporary.

There is no locally enforced iteration limit. If the dependencies keep returning while leaving the mutable object's leading field greater than the retained position, this phase does not terminate.

### 3. Final eligibility and sentinel check

After the repeated phase, the function determines whether to perform a final update.

The visible decision first compares the leading field with the retained position for equality. It then evaluates whether the position is less than or equal to the leading field. When that latter comparison holds, the eligibility result is replaced by a sentinel test:

- Read the mutable object's offset-4 field as an address.
- Address the four-byte entry at byte displacement \(4p - 4\), where \(p\) is the retained position.
- Read that entry as a 32-bit signed value.
- Continue only if that value is −1.

Thus equality alone does not authorize the final update.

Under stable memory between these reads, the repeated phase exits with the leading field no greater than the retained position. The consequences are:

- A leading field smaller than the position prevents the final update.
- A leading field equal to the position requires the preceding entry to contain the all-one 32-bit pattern.
- The equality case still performs the sentinel read when the position is zero.

The separate reads are observable distinctions if the storage can change outside the visible local operations. No synchronization or atomic snapshot is established.

### 4. Final update

When final eligibility succeeds, the function performs these operations in order:

1. Invoke **F-e25ca5aeb3ea** with the mutable object's address followed by the temporary's address.
2. Select another helper according to the same exact mode comparison:
   - Mode 1: read the descriptor's four-byte field at offset 8, then invoke **F-5d01188e4589** with that value followed by the mutable object's address.
   - Any other mode: read the descriptor's two-byte field at offset 6, then invoke **F-e2836660e375** with that value followed by the mutable object's address.
3. Read the mutable object's leading field and compare it with the retained position.
   - If the position is strictly smaller, decrement the leading 16-bit field by one, write it back, and invoke **F-c5cc0d64a43b** with the mutable object's address.
   - Otherwise, invoke **F-e25ca5aeb3ea** with the temporary's address followed by the mutable object's address.

The final comparison occurs after the preceding dependencies return. It must not be replaced by an earlier comparison result: those dependencies may change the leading field.

The argument order of F-e25ca5aeb3ea differs between its two call sites. Those calls are not interchangeable.

### Integer and address boundaries

The position is zero-extended from 16 to 32 bits. Four times the position ranges from 0 through 262,140, so that multiplication does not overflow a 32-bit unsigned quantity.

For positive positions, the sentinel displacement ranges from 0 through 262,136. Position zero is special: the sentinel address is four bytes before the loaded base under the displayed 32-bit address arithmetic. There is no visible guard excluding that access. An empty logical collection therefore cannot be assumed safe without additional storage guarantees.

The decrement branch requires the current leading field to be greater than the nonnegative position. With stable memory across its comparison and read-modify-write, the field is at least 1, and subtracting one does not underflow its 16-bit range.
