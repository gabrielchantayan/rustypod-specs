# F-65d760197311

## Purpose

F-65d760197311 coordinates an object-associated operation involving geometry records, two groups of resource submissions, an optional indicator submission, and a final object callback.

A vertically segmented rendering control is **inferred intent**. The established contract concerns direct memory accesses, argument values, branching, call order, and the distinction between cached scalars and later reads of exposed storage. Actual geometry production, drawing, context initialization, and cleanup effects require dependency contracts that are not supplied.

### Records and arithmetic

Four-word geometry records are interpreted by this caller as `(left, top, right, bottom)`. Width means right minus left; height means bottom minus top. Coordinates, dimensions, division values, and repetition counters are treated as signed 32-bit quantities.

Two residual calculations specifically retain the low 16 bits of a difference and interpret that result as signed, giving a range of −32,768 through 32,767. They must not be replaced with unrestricted 32-bit differences. Signed halving truncates toward zero.

The caller provides no explicit validation of pointers, storage sizes, resources, dimensions, arithmetic bounds, or repetition progress. Defined, terminating use therefore requires accessible storage and whatever additional conditions the dependencies need.

Throughout this contract:

- **Geometry query** means an invocation of F-c24767c70ad0 followed by the caller reading the supplied storage as geometry.
- **Destination construction** means an invocation of F-66c32a9130af with storage and four coordinates.
- **Transformation** and **submission** name the apparent roles of F-ee8733a08210 and F-945301cd184f.

These terms describe caller expectations, not guarantees that unavailable dependencies write records, preserve arguments, or draw anything.

## Behavior

The caller then reads a word at byte displacement `0x1C` from that address, adds 4, and passes the result to F-42388505f940. Which dependency, if any, makes that word valid is unknown.

Original extent and working rectangle are separate storage. Direct changes to one do not update the other. Neither is guaranteed immune to dependency-mediated mutation after exposure.

### Optional working-rectangle adjustment

A nonzero read of `0xC0` enables two geometry queries: indicator resource `0xC4` first, trailing repeating resource `0xDC` second.

After both calls, the caller compares the widths currently in their records. If repeating width is smaller than indicator width, it invokes destination construction on the working rectangle. The supplied coordinates inset left and right by half the width difference, and top and bottom by half the indicator height.

Equal or greater repeating width produces no such invocation. Halves truncate toward zero; there is no separate allocation of an odd remainder. The call does not itself establish that the working rectangle changes as requested.

### Division and ordinary submissions

The object operation at dispatch offset `0x114` is invoked next. Its returned word, the object, the then-read fields `0xAC` and `0xB0`, and the working-rectangle address are passed to F-0a7faecb7263.

The signed 32-bit return from F-0a7faecb7263 is called the **division**. The caller does not clamp it.

Ordinary segment submissions use this order: prepare source storage; invoke destination construction; perform any specified post-construction scalar update; invoke F-ee8733a08210 on source and then destination, each with the prepared input record; finally invoke F-945301cd184f with the retained resource, working context, source, destination, and scalar `255`.

Dependencies may affect previously exposed storage. Working coordinates and heights below mean reads at the stated stage, not an automatically cached rectangle.

### Leading top

The entire leading phase is skipped only when division is zero.

Otherwise, the function retains resource `0xE4`, queries its geometry, and copies the four words to source storage. If division is smaller than queried height, source bottom becomes queried top plus division.

Before destination construction, the function caches the signed-16-bit residual of division minus the selected source height. Destination coordinates start at working left and top, with queried width and selected height.

Construction, transformations, and submission follow. Later mutation of source or query storage does not recompute the cached residual. Negative division is not rejected and may select a negative height.

### Leading repetition and bottom

A nonzero leading residual enables further processing. The function retains repeating resource `0xF4`, queries it, and copies its geometry to source storage. It then queries bottom resource `0xEC`.

Available height is read as working height minus that bottom record’s height. Repeating work initially equals the cached residual. If available height is below division, repeating work is reduced by division minus available height. The bottom residual is then cached as the signed-16-bit narrowing of the preceding residual minus repeating work.

A fresh read and query of top resource `0xE4` supplies the initial repeating vertical offset through the height subsequently read from its record.

Repetition continues while remaining work is **nonzero**, not while it is positive. Each iteration queries the retained repeating resource again and copies its geometry to source storage. If remaining work is smaller than queried height, source bottom becomes queried top plus remaining work.

Two observations control each iteration:

- Before destination construction, consumed height is cached as selected source bottom minus queried top. It supplies destination height.
- After construction, but before transformation, vertical offset advances by a fresh source-bottom-minus-source-top read.

After transformation and submission, remaining work decreases by the cached consumed height. Consequently, destination construction can make vertical advancement differ from counter consumption if it changes exposed source storage.

If the cached bottom residual is nonzero, the function rereads `0xEC` and queries that resource. Destination start is working bottom minus the resource’s full queried height. A residual below that height shortens source bottom to queried top plus residual. Construction uses the selected height, followed by the ordinary transformations and submission.

A partial leading bottom therefore retains the start position calculated from full resource height.

### Trailing top

Trailing processing occurs independently of whether the leading phase ran.

The function retains resource `0xCC`, queries it, and copies its geometry to source storage. Trailing position initially equals division.

If division is smaller than queried height, source top becomes division itself—not queried top plus division. Destination construction receives top equal to working top plus division and bottom equal to working top plus queried bottom.

After construction returns, trailing position is assigned from the then-current source-bottom word. Transformations and submission follow. Later changes during those calls do not cause another assignment to trailing position.

These rules do not normalize nonzero resource origins.

### Trailing repetition

The function queries bottom resource `0xD4`. It enters repetition preparation when current trailing position is below current working height minus current bottom-record height.

On entry, it retains repeating resource `0xDC`, queries it, and copies that geometry to source storage. Only afterward does it initialize remaining work, using fresh reads of working height and bottom-record height, less current trailing position.

The entry boundary is not cached. The intervening query can therefore change the records used for initialization. There is no second entry-condition check: zero initialized work skips iterations; negative work enters the nonzero loop.

Each iteration queries the retained repeating resource again, copies its geometry, and shortens source bottom if remaining work is smaller than queried height. Consumed height is cached before destination construction. Destination top is working top plus trailing position; destination height uses the cached consumption.

After construction, trailing position advances using a fresh source-bottom-minus-source-top read. Transformations and submission follow, then remaining work decreases by cached consumption.

The preliminary repeating-resource query and the per-iteration queries are distinct observable invocations.

### Trailing bottom

After repetition, division is compared with the then-current working height. If division is smaller, the function rereads `0xD4`, queries that resource, and copies its geometry to source storage.

Available trailing height is working height minus division. If this is below queried resource height, source top becomes queried resource height minus available trailing height. The original queried top is not added.

Destination bottom is working bottom. Destination top is evaluated as working height minus the quantity “queried bottom minus selected source top,” then plus working top. With representable intermediates, this equals working bottom minus that selected quantity. Width is the full queried width.

The ordinary transformations and submission follow. There is no trailing-bottom submission when division is at least working height at the branch comparison.

### Optional indicator

The caller rereads `0xC0`; this later flag independently controls indicator processing.

If enabled, it invokes dispatch offset `0x114` again. It subtracts current `0xAC` from that result, separately computes current `0xB0` minus current `0xAC`, and reads mode `0xF8`.

For mode 5, the indicator is suppressed when the first difference is zero or is signed-greater-than-or-equal to the range difference. The latter comparison uses a subtraction-overflow-aware signed comparison. Other modes impose neither suppression rule. A negative, nonzero first difference is not generally suppressed.

When permitted, the caller retains resource `0xC4`, queries it, and copies its geometry into source and indicator-destination storage. It also writes another local record using original-extent coordinates and original-extent top plus division. That record is not explicitly passed to another dependency after these writes.

F-d156b0b83eb3 receives the indicator destination, first scalar equal to original-extent top plus division minus half queried indicator height, and second scalar zero. F-33ca0546dba1 then receives the working context and `1`; F-945301cd184f receives the indicator submission with `255`.

The indicator does not use F-ee8733a08210. Its placement expression uses original-extent top rather than adjusted working top.
