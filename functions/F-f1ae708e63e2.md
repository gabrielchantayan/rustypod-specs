# F-f1ae708e63e2

## Purpose

F-f1ae708e63e2 produces a 32-bit Boolean-like decision from two caller-supplied memory records and the result of a conditional dependency call. Its return value is exactly 0 or 1.

The established decision structure is:

- Invoke an initial dependency unconditionally.
- Require a nonzero threshold and a candidate value strictly below that threshold.
- Apply an optional unsigned distance limit.
- Obtain another value from a second dependency and apply another unsigned distance limit.
- Compare two products using 32-bit unsigned arithmetic.

The function’s broader application meaning is unknown. Interpreting the fields as capacity, usage, elapsed time, or percentages would be inferred intent, not an established contract. The multiplication by 100 supports a possible proportional interpretation, but the actual observable rule includes unsigned wraparound and must not be replaced by an idealized ratio calculation.

## Behavior

### Initial call and unconditional context reads

The first observable action established by the supplied body is a call to **F-c9ae8ae96286**, with:

1. The second argument.
2. The fourth argument.

This call occurs even when later fields force an immediate rejection.

After that call returns, the function reads the context threshold at +0x28, then the context adjustment at +0x20. Both reads occur regardless of whether the threshold is zero. Consequently, a zero threshold does not eliminate the requirement that +0x20 be readable.

The initial dependency’s return is received as a 32-bit unsigned value, but it cannot affect the final decision:

- With a zero threshold, the function rejects without using that result in a successful path.
- With a nonzero threshold, the decision-record value at +0x08 replaces it before the comparison.

The call remains behaviorally significant because its side effects, failure to return, and changes to subsequently read memory are unknown.

### Threshold and candidate gate

If the retained threshold is zero, the function returns 0. It does not directly read any field from the decision record on this path.

If the threshold is nonzero, the function reads the unsigned candidate at decision offset +0x08. It proceeds only if:

**candidate < threshold**

Equality rejects. A larger candidate also rejects. Rejection here prevents the baseline read, all later decision-record reads, and the second dependency call.

After this gate passes, the function reads and retains the baseline at context offset +0x24.

### Optional first distance gate

The function next reads the unsigned limit at decision offset +0x10.

If that read yields zero, the first distance comparison is bypassed and execution proceeds toward the second dependency call. The context value at +0x1c is not directly read on this bypass path.

If the limit is nonzero, the function evaluates the difference between the signed-loaded context value at +0x1c and the retained baseline. The subtraction’s result is converted to unsigned 32-bit form and must be strictly less than a further read of the decision limit at +0x10.

The condition therefore does not establish a single stable snapshot of the optional limit. The zero check and the comparison contain separate reads. If memory can change between them, the value used in the comparison need not equal the value that enabled the comparison.

For a representable signed subtraction, a negative difference becomes a large unsigned value. This is not a signed “less than the limit” test, and it is not an absolute-distance test.

If this gate fails, the function returns 0 without calling F-baf994e199e9.

### Conditional dependency and second distance gate

After the optional gate passes or is bypassed, the function reads the opaque value at decision offset +0x04 and passes it to **F-baf994e199e9**.

The dependency returns a value treated as signed 32-bit. The function subtracts the retained baseline from that result, converts the difference to unsigned 32-bit form, and requires it to be strictly less than the unsigned limit at decision offset +0x0c.

That limit is read after the dependency returns. Changes made by the dependency to this field can therefore affect this invocation.

A zero limit at +0x0c cannot pass this unsigned comparison. Unlike the limit at +0x10, zero here is not a bypass value.

The baseline is not reread after the dependency. A dependency-induced change to context offset +0x24 does not replace the retained baseline used by this comparison.

If the comparison fails, the function returns 0 and does not read the final factor at decision offset +0x14.

### Final unsigned product gate

If the preceding comparison passes, the function reads the factor at decision offset +0x14 and evaluates:

**unsigned-factor × (threshold + unsigned-adjustment) < threshold × 100**

For this comparison:

- The threshold is the value retained from the initial context read.
- The adjustment is the value retained from context offset +0x20.
- The factor is read only when this final gate is reached.
- The addition, both multiplications, and the comparison use 32-bit unsigned arithmetic.
- The signed-loaded adjustment and factor are converted to unsigned 32-bit values in these expressions.
- Each unsigned arithmetic result is reduced modulo 2³².

The comparison is strict. Equal products reject.

The function returns 1 precisely when this comparison succeeds. It otherwise returns 0.

This rule must not be rewritten using division, floating-point percentages, wider products, saturation, or overflow rejection. Those alternatives can produce different decisions.

These are conditional static acceptance examples, not executed tests. Unless stated otherwise, memory is valid and stable, dependencies return normally without modifying relevant fields, and signed subtractions are representable.

### Zero threshold

- F-c9ae8ae96286 is called.

- The function returns 0.
- No decision-record field is directly read.
- F-baf994e199e9 is not called.

### Candidate equality

Given a threshold of 10 and a candidate of 10, the function returns 0. Context offset +0x24 is not read, and the second dependency is not called.

### Optional-limit bypass

Given a nonzero threshold and a candidate below it, a zero value at decision offset +0x10 bypasses the first distance comparison. Context offset +0x1c is not directly read.

The second dependency and all remaining gates still apply.

### Strict distance boundaries

Given a retained baseline of 100 and an optional limit of 5:

- A context value of 104 produces distance 4 and passes the optional gate.
- A context value of 105 produces distance 5 and fails it.
- A context value of 99 produces signed difference −1, converted to 4,294,967,295, and fails against limit 5.

Similarly, with baseline 100 and a second limit of 5, dependency results of 104 and 105 respectively pass and fail the second distance gate.

### Complete accepting case

Given:

- Threshold 100 and candidate 99.
- Adjustment 0 and baseline 20.
- Optional limit 0.
- Second dependency result 23.
- Second limit 4.
- Final factor 99.

The optional gate is bypassed. The second distance is 3, which is below 4. The final comparison is 9,900 < 10,000. The function returns 1.

Changing only the factor to 100 makes the final products equal and changes the return to 0.
