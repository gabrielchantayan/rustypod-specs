# F-ea490577ce35

## Purpose

The supplied static representation describes a routine that performs a sequence of low-address and caller-derived memory writes, updates an external state location, and then either reaches an invalid-instruction termination marker or transfers control through two unresolved indirect targets.

A higher-level purpose is not established. The representation contains explicit warnings about invalid instruction data, overlapping global symbols, and an unrecovered indirect transfer. Consequently, this contract distinguishes:

- **Established static evidence:** operations and ordering expressly present in the supplied representation.
- **Conditional interpretation:** consequences of applying the recovered 32-bit arithmetic and pointer model consistently.
- **Unknown behavior:** details requiring instruction-level evidence, declarations, calling-convention information, or runtime observation.

The recovered operations do not establish a conventional safe buffer-processing API. In particular, several destinations are small numeric addresses rather than offsets within an identified allocation.

## Behavior

### 1. Derive the initial destinations

Define the **selector** as the top five bits of the incoming unsigned 32-bit implicit value. Its range is 0 through 31.

Read an unsigned 16-bit value at the first argument’s address plus 48 bytes. Zero-extend it and use it as the **base address**. Thus the initial base address ranges from 0 through 65,535; it is not a pointer loaded at full pointer width.

The field at offset 48 is subsequently read again. The representation does not justify replacing the two reads with one.

### 2. Perform the initial memory operations

Subject to successful execution of each preceding operation, the recovered sequence is:

1. Read the 16-bit field at the first argument’s address plus 48 again, and write that value as a halfword at **base address + selector**.
2. Write the second explicit argument as a 32-bit word at the base address.
3. Write the fourth argument’s pointer value as a 32-bit value at **base address + 4**.
4. At the numeric address **twice the quantity base address + 8**, write the pointer value **base address + 8**.
5. Write the implicit incoming 16-bit value at the numeric address equal to the selector.
6. Write the low 16 bits of the implicit signed 32-bit value at an address 14 bytes beyond that value interpreted as an address.
7. Write the low 16 bits of the fourth argument’s address at the numeric address obtained by shifting the selector left by 20 bits.
8. Read an unsigned halfword from another selector-derived address, described below.
9. Write the selector as a halfword at byte offset 32 from the fourth argument.
10. Write a zero halfword at the address obtained by adding 40 to the unsigned halfword read in step 8.

The destination in step 4 is a doubled numeric address, not the location eight bytes beyond the base. Since the base is initially at most 65,535, the doubled destination ranges from 16 through 131,086 without requiring arithmetic wraparound.

For step 8, the recovered expression shifts the selector left by 28 bits, treats the result as signed, shifts it right by 16 bits, and adds 32.

Under 32-bit truncating left shift and arithmetic right shift, this is equivalent to:

- Retain the selector’s low four bits.
- Interpret those four bits as a signed value from −8 through 7.
- Multiply by 4,096.
- Add 32.

The resulting signed numeric address ranges from −32,736 through 28,704. The selector’s fifth bit does not affect this address under that interpretation. This equivalence is conditional on the recovered shift semantics; it is not independent evidence that the instructions have been decoded correctly.

Step 10 uses the value actually read in step 8, not the address used for that read. Its destination therefore ranges from 40 through 65,575.

### 3. Establish the loop state

The initial termination flag is the signed-overflow result of adding 105 to the implicit signed 32-bit value.

Under ordinary signed 32-bit overflow detection, the flag is true exactly when that input exceeds 2,147,483,542. Negative inputs cannot overflow when adding this positive constant.

The initial loop-store address is the selector masked with hexadecimal `08960CB8`. Because the selector has only five significant bits, this reduces to the selector masked with hexadecimal `18`. The initial address is therefore one of:

- 0
- 8
- 16
- 24

This reduction concerns the initial loop-store address only.

### 4. Execute the loop body

Each represented iteration performs these actions in order:

1. Read a 32-bit value through the external pointer-valued binding.
2. Compute a 32-bit quantity from the fourth argument’s address by interpreting that address as signed and shifting it right by four bits.
3. Write the numeric value 20 to the external state location.
4. At the current loop-store address, write a 32-bit word equal to that same address.
5. Write the halfword value 20 at byte offset 12 from the fourth argument.
6. Repeat the same 32-bit self-address write from step 4.
7. Inspect the termination flag.

If the flag is true, the representation writes 20 to the external state location again and then reaches an invalid-instruction termination marker. No later operation is represented on that path.

If the flag is false, the representation sets it to true, replaces the loop-store address with the 32-bit value read at the start of the iteration, and evaluates the continuation condition.

The condition compares two signed-overflow results:

- Overflow when adding 20 to the shifted pointer quantity.
- Overflow when adding either zero or one to that sum, where the added bit is bit 3 of the fourth argument’s address.

The loop continues only if the two overflow results differ.

### 5. Conditional loop reachability

Under the recovered 32-bit signed arithmetic-shift model, the shifted pointer quantity lies between −134,217,728 and 134,217,727.

Adding 20, and then at most one more, cannot overflow a signed 32-bit integer anywhere in that range. Both overflow results are therefore false, and the continuation condition is false.

Consequently, under this model:

- A true initial termination flag reaches the invalid-instruction marker during the first iteration.
- A false initial termination flag executes one iteration and proceeds to the tail.
- A second iteration is unreachable.

This is an arithmetic consequence of the recovered expressions, not evidence of runtime execution. It also means the externally read word does not become a subsequently used memory destination on the normally continuing path.

### 6. Perform the tail operations

After leaving the loop, the representation:

1. Writes the low 16 bits of the fourth argument’s address to the halfword at that argument’s address.
2. Records the fourth argument’s pointer value in a recovered stack location at displacement 24.
3. Performs an indirect call through a target obtained by adding hexadecimal `E16` to the incoming link/control value.

The first indirect call is represented with three arguments, in order:

1. The 32-bit constant hexadecimal `012C0000`.
2. The fourth explicit argument.
3. The shifted pointer quantity masked with hexadecimal `08961504`.

If this call returns, the representation performs a second unresolved indirect transfer. It renders that transfer as a call, while warning that the underlying jump table could not be recovered.

No argument contract can be inferred for the second transfer merely because its displayed call expression contains no explicit arguments. If it returns as represented, the enclosing routine then returns.

## Side effects

### Memory mutation and aliasing

The routine has no recovered bounds, null, alignment, or permission checks before the listed accesses.

Successful execution requires every reached read, write, and control transfer to be supported by the execution environment. Otherwise a fault or other platform-specific result may occur before the later operations.

Destinations can overlap one another, caller-owned storage, external state, or the field supplying the initial base. Therefore:

- Later writes may replace earlier writes.
- Earlier writes may change values obtained by later reads.
- The listed access order matters.
- The two repeated loop stores must not be collapsed into one observable store.

The initial base is retained from its first read. The second read of the offset-48 field supplies a stored value; it does not replace the already derived base.

The supplied warning about overlapping global symbols further prevents assuming that named external storage is independent of other storage.

### External state

The external state location receives 20 once on the normally continuing path and twice on the invalid-instruction path, assuming both writes are reached.

Its storage width and architectural meaning are unknown. Its name in the supplied representation is insufficient to establish that the operation changes interrupt state, a processor mode, or any particular hardware register.

### Ownership and lifetime

The routine visibly writes through several addresses but contains no explicit allocation or release operation.

That does not establish ownership transfer, retention, or non-retention. Either unresolved target may allocate, release, retain pointers, mutate global state, or perform additional control transfers. None of those behaviors may be assumed absent.

### Errors and partial completion

No error code, exception translation, cleanup, or rollback is represented.

Any failure after earlier writes can leave partial effects. The invalid-instruction marker occurs only after the first iteration’s external read and memory writes have been attempted.
