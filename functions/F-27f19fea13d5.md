# F-27f19fea13d5

## Purpose

F-27f19fea13d5 conditionally exchanges fixed-width units within an existing memory region. It supports two format selectors:

- **16:** each exchanged unit occupies two bytes.
- **32:** each exchanged unit occupies four bytes.

A nonzero mode reverses the order of selected units within each selected row. A zero mode reverses the order of selected rows while preserving unit order within each row, provided the selected storage does not overlap.

The interpretation as a rectangular image or buffer operation is inferred intent. The established behavior is address calculation followed by an ordered sequence of fixed-width exchanges.

A significant addressing distinction applies to format 32: the initial column displacement is **two bytes per starting column**, although subsequent units are four bytes apart. This contract does not replace that behavior with conventional four-byte column addressing.

The function supplies no clipping, bounds checking, allocation, or error status.

## Interface

The function accepts three inputs and produces no return value.

| Input | Meaning |
|---|---|
| Buffer descriptor | Reference to a record containing a base-address field, byte stride, and format selector. |
| Region descriptor | Reference to four signed coordinate fields defining starting and ending rows and columns. |
| Mode | Integer selecting within-row reversal when nonzero, or row-order reversal when zero. |

Negative and positive nonzero mode values select the same branch.

### Descriptor layouts and widths

The supplied representation indicates the following apparent 32-bit layout:

| Buffer descriptor byte offset | Field |
|---|---|
| 0 | Base address, held in an integer-sized field |
| 4 | Signed row stride in bytes |
| 8 | Format selector |

| Region descriptor byte offset | Field |
|---|---|
| 0 | Starting row, \(r_0\) |
| 4 | Starting column, \(c_0\) |
| 8 | Ending row, \(r_1\) |
| 12 | Ending column, \(c_1\) |

Coordinate differences, loop counts, stride products, and intermediate integer address calculations use the signed integer representation shown by the supplied body, apparently 32 bits. Two-byte and four-byte exchange widths are explicit. An independent ABI declaration confirming pointer width, integer representation, and calling convention is not supplied.

For representable calculations, define:

\[
H=r_1-r_0,\qquad W=c_1-c_0
\]

\[
A=B+Sr_0+2c_0
\]

where \(B\) is the base address, \(S\) is the signed byte stride, and \(A\) is the initial selected address. Let \(E\) be the exchanged unit size: two bytes for format 16 and four bytes for format 32.

For ordinary nonnegative extents, the ending coordinates behave as exclusive limits. No complete buffer dimensions or allocation bounds are provided.

### Preconditions and ownership

The buffer descriptor must be readable through every field accessed on the chosen path. A nonzero base and supported format also require readable region fields.

Every exchanged unit must permit a read and write of the selected width. Required alignment, valid pointer formation, valid arithmetic, and accessible storage are environmental preconditions; the function does not enforce them.

Stable descriptor contents are required for the simple rectangular interpretation. The body contains repeated field reads and does not establish a coherent snapshot under concurrent mutation.

**Ownership of the descriptors and referenced storage is not established.** The function performs no explicit allocation, deallocation, ownership transfer, or release. Possession of a descriptor does not establish that its supplier owns the referenced memory.

## Behavior

### Dispatch and descriptor access

The first established memory access reads the buffer descriptor’s base-address field.

If that value is zero, the function returns immediately:

- No format or stride field is read.
- No region field is read.
- No exchanged storage is accessed.

A nonzero base causes a comparison of the format against 16. If that comparison fails, the format is read again for comparison against 32. A value that fails both comparisons causes a return without region access or element exchange.

Consequently, an unsupported format is silently ignored rather than reported as an error. The two comparisons do not establish a single captured format value if descriptor contents change between reads.

For a supported format, the mode selects the operation. The selected branch reads its stride and coordinate inputs before any exchange writes.

In nonzero mode, the branch obtains the stride and forms the initial address from the starting coordinates. It then obtains the height and width differences. The starting row and starting column are read again when those differences are formed.

In zero mode, the branch obtains the stride, ending column, and starting column before forming the initial address. It then obtains the height difference, including another read of the starting row.

Where an address expression contains multiple operand reads, the supplied representation does not independently establish their machine-level evaluation order. The ordering claims here concern separately expressed operations and the explicit exchange sequence.

### Nonzero mode: reverse units within each row

The branch calculates \(A\), \(H\), and \(W\) before testing whether there are any rows to process.

For positive \(H\), logical rows are visited in increasing order. Selected row \(k\) begins at:

\[
A_k=A+kS,\qquad 0\leq k<H
\]

For each row, the function first forms a pointer one selected width beyond the row’s initial address:

\[
A_k+EW
\]

That pointer is moved back by one unit before the first exchange. Exchanges then proceed from the outermost pair toward the center:

\[
(A_k+jE,\; A_k+(W-1-j)E)
\]

For ordinary nonnegative \(W\), the number of exchanges per row is \(\lfloor W/2\rfloor\).

Observable consequences include:

- An odd width leaves the middle unit unaccessed by the exchange loop.
- Width zero or one causes no exchanges.
- A negative width produces no positive exchange count under the displayed signed-division and loop test.
- A nonpositive height prevents row iterations.
- Each visited row is followed by a byte-stride advance, including the final visited row.

The per-row end pointer is formed even when that row performs no exchanges. The initial address and extent calculations also precede the height test. Therefore, an empty exchange set is not a guarantee that all intermediate arithmetic or pointer formation is harmless.

For distinct, nonoverlapping units and rows, this branch reverses the selected unit sequence independently within every selected row.

### Zero mode: reverse selected row order

This branch forms the initial address \(A\), calculates \(H\), and forms the opposing row address:

\[
A_{\mathrm{back}}=A+(H-1)S
\]

The opposing address is calculated before testing the row-pair count.

The row-pair count is obtained by a signed right shift of \(H\) by one. For nonnegative representable \(H\), this is \(\lfloor H/2\rfloor\).

For each row pair, the function exchanges corresponding units in increasing column order. Pair \(k\) uses:

\[
A_{\mathrm{front},k}=A+kS
\]

\[
A_{\mathrm{back},k}=A+(H-1-k)S
\]

For each positive-width column index \(j\), the exchanged addresses are:

\[
A_{\mathrm{front},k}+jE
\quad\text{and}\quad
A_{\mathrm{back},k}+jE
\]

After each pair, the front address advances by \(S\), and the back address retreats by \(S\). These updates also occur after the final processed pair.

Consequences for ordinary nonnegative dimensions are:

- An odd height leaves the middle row unaccessed by the exchange loops.
- Height zero or one causes no exchanges.
- Width zero or a negative width causes no element exchanges, even if the outer row-pair loop executes.
- An outer iteration with no element exchanges still performs its row-address updates.

For negative \(H\), the signed-right-shift result depends on the target semantics. Under an arithmetic signed shift, it is not positive and no row-pair iteration occurs. Portable behavior for negative shift operands is not established by the supplied material.

### Initial column displacement

Both formats calculate the initial column contribution as \(2c_0\).

After that initial calculation, units are separated by their actual exchange width:

| Format | Initial column contribution | Subsequent unit spacing |
|---|---:|---:|
| 16 | \(2c_0\) bytes | 2 bytes |
| 32 | \(2c_0\) bytes | 4 bytes |

Thus, format 32 with starting column one begins at a two-byte displacement from the selected row base, not a four-byte displacement.

This may select bytes inside an externally defined four-byte element or produce an address unsuitable for four-byte alignment. The function neither corrects nor rejects this condition.

### Exchange ordering and overlap

Every exchange has the following established data-access order:

1. Read the left or front unit and retain its value.
2. Read the right or back unit.
3. Write the second value to the left or front location.
4. Write the retained first value to the right or back location.

The exchange is not an atomic two-location operation.

Within-row exchanges proceed inward from the ends. Row-order reversal processes outer row pairs first and columns in increasing order within each pair.

If selected storage overlaps, later reads can observe earlier writes. Results must then follow this traversal order, rather than a conceptual reversal of an immutable snapshot.

The function contains no explicit descriptor-field writes. However, selected storage can alias descriptor bytes. Such aliasing can cause exchange writes to modify a descriptor. The branch has already obtained its control values before those writes and does not reread descriptor fields inside the exchange loops.

## Side effects

The direct side effect is an ordered series of two-byte or four-byte reads and writes to the selected addresses.

The supplied body contains no:

- Allocation or deallocation.
- Callable dependency.
- Explicit global-variable access.
- Logging, callback, or status update.
- Explicit ownership-transfer or release operation.
- Explicit descriptor update.

These observations do not establish who owns either descriptor or the referenced storage.

For disjoint selected rows and units, only units participating in exchanges are written. Odd-width centers in nonzero mode and odd-height middle rows in zero mode are not accessed merely to preserve their values.

Units are opaque bit patterns. The operation does not interpret channels, numeric values, or byte order.

There is no rollback mechanism. If an access fails after earlier exchanges or part of an exchange, prior writes are not undone by any operation shown in the body. Exact fault signaling and partial-access behavior remain environmental.

## Acceptance examples

These are conditional consequences of static evidence, not runtime test results. Except where explicitly varied, assume stable readable descriptors, representable arithmetic, valid pointer formation, suitably aligned accessible storage, and nonoverlapping selected units.

### 1. Zero base

Given a readable buffer descriptor with base zero:

- The function returns after reading that field.
- Neither the format nor the region is inspected.
- No exchange occurs.

An unreadable buffer descriptor is not accepted by this case.

### 2. Unsupported format

Given a nonzero base and a stable format of 24:

- Both format comparisons fail.
- No region field is read.
- No selected-storage access occurs.
- No error status is returned.

### 3. Odd-width within-row reversal

Given format 16, nonzero mode, and two selected rows of width five:

| Row | Before | After |
|---|---|---|
| First | A B C D E | E D C B A |
| Second | F G H I J | J I H G F |

Each row receives two exchanges. The first row is processed before the second. The center units C and H are not accessed by the exchange loops.

### 4. Odd-height row-order reversal

Given zero mode and three disjoint selected rows of width three:

| Row | Before | After |
|---|---|---|
| First | A B C | G H I |
| Middle | D E F | D E F |
| Last | G H I | A B C |

The first and last rows exchange corresponding units from left to right. The middle row is not accessed by the exchange loops.

### 5. Mode distinction

For one selected row of width four:

- Zero mode performs no exchanges.
- Nonzero mode reverses the four selected units.

For four selected rows of width one:

- Nonzero mode performs no exchanges.
- Zero mode exchanges the single units of the first and fourth rows, then those of the second and third rows.

### 6. Format 32 column addressing

Given format 32, starting row zero, starting column one, width two, height one, and nonzero mode:

- The selected start is \(B+2\).
- The four-byte units at \(B+2\) and \(B+6\) are exchanged.
- The expected addresses are not \(B+4\) and \(B+8\).

Acceptance requires those four-byte accesses and intermediate pointers to be valid on the target.

### 7. Empty extents

For nonzero mode with height zero, no row iteration occurs, but initial address and extent calculations still occur.

For zero mode with positive height and width zero, row pairs may be traversed without element accesses. Opposing-address calculation and row-address updates still occur.

Neither case establishes safety for overflowing coordinates or invalid pointer formation.

### 8. Negative stride

With a valid negative stride, increasing logical row order moves toward lower addresses. Both modes use that signed stride directly.

### 9. Overlapping logical rows

Given nonzero mode, format 16, stride zero, height two, and selected width three, both logical rows refer to the same physical units.

Starting from A B C:

- The first row visit produces C B A.
- The second row visit produces A B C.

The final storage equals its initial contents because the same reversal executes twice, not because the operation suppresses overlapping rows.
