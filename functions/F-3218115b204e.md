# F-3218115b204e

## Purpose

F-3218115b204e conditionally returns a 32-bit value through one of two object-associated cache slots.

An initial dependency gates further processing. If that dependency permits processing, an unsigned index is checked against an object count. An admitted request selects one cache slot according to whether the selector is zero or nonzero. A zero selected slot triggers a dependency call whose result is stored in that slot. A nonzero final slot value supplies the base for a four-byte memory read.

The entry address is calculated using unsigned 32-bit arithmetic, modulo \(2^{32}\). Consequently, large admitted indices can wrap to addresses also reached by smaller indices or to the nominal table prefix. Wrapping does not itself reject the request.

The function returns zero when the initial gate fails, the bounds check fails, or the final selected slot is zero. It can also return zero from a successful entry read. The return value does not distinguish these outcomes.

“Gate,” “cache,” and “population” describe roles visible in this function. They do not establish the dependencies’ broader purposes or a complete cache-management protocol.

## Interface

### Inputs and result

| Input | Representation | Use |
|---|---|---|
| Object reference | 32-bit integer-shaped address | Locates the count and two cache slots. Zero receives special handling during count acquisition. |
| Index | Unsigned 32-bit integer | Participates in the unsigned bounds comparison and modular entry-address calculation. |
| Selector | 32-bit integer | Zero selects the first slot; every nonzero value selects the second. |

The selector’s magnitude and sign have no further significance. When population is needed, the dependency receives a normalized mode of zero or one, not the original selector.

The result is a raw 32-bit value. The evidence does not establish whether an entry represents a pointer, identifier, signed number, status, or another kind of data.

### Object access layout

Offsets are byte offsets relative to the supplied object reference.

| Offset | Width | Role |
|---|---:|---|
| `0x30` | 4 bytes | Unsigned count used to admit or reject the index. |
| `0x910` | 4 bytes | First cache slot, selected by a zero selector. |
| `0x914` | 4 bytes | Second cache slot, selected by a nonzero selector. |

This is an access layout, not a complete object definition. No other object fields are directly accessed by the supplied function representation.

### Table access layout and arithmetic

Let \(B\) be the 32-bit value obtained from the final selected-slot read, and \(I\) the unsigned 32-bit index. When \(B\) is nonzero, the address of the four-byte read is:

\[
A = \bigl(B + ((4I) \bmod 2^{32}) + 4\bigr) \bmod 2^{32}.
\]

The multiplication and both additions operate modulo \(2^{32}\). This is established arithmetic behavior, not an unresolved dependency contract.

For small indices and addresses that do not wrap, the access pattern resembles a table with a four-byte prefix followed by four-byte entries:

- Index zero reads at \(B+4\).
- Index one reads at \(B+8\).
- Each successive index advances the calculated address by four bytes, modulo \(2^{32}\).

The function does not separately inspect or validate a prefix. However, modular arithmetic can make the requested read address equal \(B\), so the four bytes at the nominal prefix are not categorically excluded from reads.

Nothing establishes that a prefix contains a count, that the allocation is contiguous for every admitted index, or that either cache has capacity matching the object count.

### Access and lifetime preconditions

For normal completion, every reached memory operation must have valid backing storage and satisfy the execution environment’s access requirements:

- A reached count read requires readable object storage at the count field.
- A reached selected-slot read requires readable storage at that slot.
- A population path requires the selected slot to remain writable after the dependency returns.
- A reached entry read requires four readable bytes at the calculated address \(A\), including when the calculation wraps.
- Storage must remain usable across dependency calls before subsequent accesses.

Wrapping arithmetic is not excluded by these preconditions. Address accessibility and the consequences of an invalid access are separate questions.

A zero object reference avoids direct object access by this function because its effective count is zero. The initial dependency still executes. A nonzero invalid object reference receives no comparable protection.

## Behavior

### Initial gate

Every invocation first calls F-06f4ceb6a4f2 with no explicit arguments.

If its result is zero, the function returns zero immediately. The function itself performs no object or table access on that path and does not call F-7ba762d0bbe8.

Any nonzero gate result permits processing to continue. That result is used only as a condition; it is not returned.

The gate executes before the function checks the object reference or index. Its effects, if any, therefore precede all direct object accesses described below.

### Count acquisition and admission

After the gate succeeds:

- A zero object reference supplies an effective count of zero without an object read.
- A nonzero object reference causes a four-byte count read at offset `0x30`.

The function admits the request only when the unsigned 32-bit index is strictly less than the unsigned 32-bit count.

Accordingly:

- A zero count rejects every index.
- An index equal to the count is rejected.
- A zero object reference always leads to a zero result after the gate returns normally.
- An index with its high bit set is a large unsigned value, not a negative index.
- Rejection occurs before either cache slot is inspected.

The count is acquired after the initial dependency returns, so changes that dependency makes can affect admission. The count is not read again later.

### Slot selection

An admitted request selects exactly one slot:

| Selector condition | Selected offset | Population mode |
|---|---:|---:|
| Zero | `0x910` | 0 |
| Nonzero | `0x914` | 1 |

Both modes use the same object count. There is no separate per-table bounds check.

The function does not directly read or write the unselected slot. This does not constrain what either dependency may do.

### Population and final slot read

The function first reads the selected slot and tests it against zero.

If that initial read is nonzero, population is skipped. The function then reads the selected slot again to obtain the value used for the final zero check and address calculation.

If the initial read is zero:

1. F-7ba762d0bbe8 is called with the original object reference and normalized mode.
2. The dependency’s returned 32-bit value is written into the selected slot.
3. The selected slot is read again for the final zero check and address calculation.

The write occurs even when the dependency returns zero. There is no distinct cached-failure marker. A later eligible, admitted invocation that observes a zero slot attempts population again.

If the dependency writes a different value into the selected slot before returning, the function’s subsequent write replaces that value with the dependency’s return value. No guarantee is assumed that the dependency preserves the object, globals, either slot, or storage lifetime.

The function does not repeat the bounds check after population. A dependency-induced count change does not alter the admission decision already made.

### Final read and return

If the final selected-slot read yields zero, the function returns zero without an entry read.

Otherwise, it calculates \(A\) using the modular arithmetic defined above, reads four bytes at \(A\), and returns those 32 bits without further interpretation.

The nonzero check applies to \(B\), not to the calculated address \(A\). A nonzero base can therefore produce a zero read address after wrapping. There is no additional check that suppresses such a read.

There is also no explicit rejection for:

- Multiplication or addition wrapping.
- An address landing at the nominal prefix.
- An address outside the intended allocation.
- Insufficient table capacity.
- Misalignment or inaccessible storage.

The arithmetic result is established even when its resulting access is invalid. The invalid-access outcome is not established.

## Acceptance examples

These are conditional static acceptance criteria, not executed tests. Unless an example states otherwise, dependencies return normally, all reached accesses are valid, and no intervening mutation changes the specified values. Wrapping arithmetic follows the stated 32-bit rules.

1. **Gate rejection**  
   If F-06f4ceb6a4f2 returns zero, the function returns zero for any inputs. No direct object or table access follows, and population is not called.

2. **Zero object reference**  
   If the gate succeeds and the object reference is zero, the effective count is zero. Every index is rejected without a count-field or cache access.

3. **Strict bound**  
   With count three, index three returns zero before either slot is inspected. Index two passes admission.

4. **Unsigned comparison**  
   With count three, index `0xFFFFFFFF` is rejected as a large unsigned value. Even with count `0xFFFFFFFF`, that same index is rejected because equality does not pass.

5. **Existing first slot**  
   With selector zero, index one, count greater than one, and both selected-slot reads yielding the same nonzero base, population is skipped. The result comes from address \((B+8)\bmod 2^{32}\).

6. **Nonzero selector normalization**  
   Selectors one, minus one in the 32-bit integer representation, and any other nonzero value select offset `0x914`. If population is required, each supplies mode one.

7. **Successful population**  
   If the selected slot initially contains zero and population returns a usable nonzero base, that value is written into the selected slot before its final read and the entry access.

8. **Zero population result**  
   If population returns zero, zero is written to the slot. If the final slot read is also zero, the result is zero without an entry read. A later qualifying request may retry population.

9. **Zero-valued entry**  
   If the calculated entry address contains a zero 32-bit value, the function returns zero despite successful admission and an actual entry read.

10. **Count change during population**  
    If the original count admits the index and population subsequently reduces the count, admission is not reconsidered. The final slot value still controls whether the calculated read occurs.

11. **Population-side slot write replaced**  
    If population writes one value into the selected slot but returns another, the returned value overwrites that slot before the final read.

12. **Multiplication wrap**  
    Index `0x40000000` passes a count of `0x40000001`. Multiplication by four produces zero modulo \(2^{32}\). For a final base of `0x00001000`, the read address is `0x00001004`, the same address reached by index zero with that base.

13. **Wrap reaches the nominal prefix**  
    Index `0x3FFFFFFF` passes a count of `0x40000000`. Its scaled displacement is `0xFFFFFFFC`; adding the trailing four bytes wraps the total displacement to zero. The read address equals \(B\), so the function reads the nominal prefix location rather than excluding it.

14. **Base addition reaches address zero**  
    With index zero, count greater than zero, and final base `0xFFFFFFFC`, the calculated read address is zero. The base passes its nonzero check. If address zero supports the required read, its value is returned; otherwise, the invalid-access outcome is unresolved, not a specified zero return.
