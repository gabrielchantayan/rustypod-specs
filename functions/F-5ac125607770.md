# F-5ac125607770

## Purpose

F-5ac125607770 constructs a packed 32-bit word and writes it, a zero-valued leading word, and one or two supplied payload words into caller-provided output storage.

Selectors 0–3, 6, and 7 select a two-payload form. Both payload values must have their low two bits clear. Selectors 4 and 5 select a one-payload form, require an exact sentinel in an input field, and do not impose that payload restriction.

Established behavior consists of input reads, validation, unsigned bit packing, ordered output writes, and a returned status. Interpreting the output as a control record is inferred intent. Its domain-specific meaning is not established.

The function receives storage addresses; this does not establish ownership or allocation provenance for either region.

## Behavior

### Arithmetic model

Packing uses unsigned 32-bit arithmetic. Left shifts discard bits beyond bit 31. Right shifts fill with zero.

Let \(I_n\) denote input word \(n\), \(A\) Payload A, and \(B\) Payload B. The first input-derived field is:

\[
H=(I_3 \mathbin{\&} \texttt{0x1F}) \ll 7.
\]

Only the low five bits of input word 3 affect this field. The intermediate byte-sized conversion in the supplied representation does not change that result.

All field combinations use bitwise OR. There is no arithmetic carry between fields and no overwrite precedence between overlapping contributions.

The formulas below assume stable input storage disjoint from output storage. When the regions overlap, the access ordering specified later determines which input values are observed.

### Selectors 0–3

Selectors 0, 1, 2, and 3 have identical behavior.

Both payloads must have their low two bits clear:

\[
((A \mathbin{|} B) \mathbin{\&} 3)=0.
\]

Failure returns `0xFFFFFF0D` without writing output storage.

On success, output word 2 receives \(A\), output word 3 receives \(B\), and the packed word is:

\[
C =
H
\mathbin{|} (I_0 \mathbin{\&} 3)
\mathbin{|} ((I_1 \mathbin{\&} 3) \ll 2)
\mathbin{|} ((I_4 \ll 18) \bmod 2^{32})
\mathbin{|} (I_2 \mathbin{\&} \texttt{0x30}).
\]

The field layout is:

- Bits 0–1: input word 0, bits 0–1.
- Bits 2–3: input word 1, bits 0–1.
- Bits 4–5: input word 2, bits 4–5.
- Bits 7–11: input word 3, bits 0–4.
- Bits 18–31: input word 4, bits 0–13.

Bits 6 and 12–17 remain zero. Higher bits of the input fields are discarded. The particular selector within 0–3 is not encoded.

### Selectors 6 and 7

\[

H
\mathbin{|} (I_0 \mathbin{\&} 3)
