# F-99579940fdac

## Purpose

F-99579940fdac initializes two working records, processes two bit selectors against separate tables, and publishes a 12-byte result. A packed return from F-870c4fcf7295 determines the selectors and the finalization path. Selected positions invoke F-bbd1fe9881a1; its 64-bit returns update accumulated payloads.

The established behavior includes address-source reads, record initialization, arithmetic, loop-condition accesses, dependency calls, and output publication. Bit-selected accumulation is inferred intent. No mathematical interpretation of the records or dependency operations is established.

This contract is based on the supplied static representation. No runtime tests have been performed.

### Working records and external storage

Each working record contains an 8-byte payload followed by a 4-byte auxiliary field. A temporary record used during second-table processing has the same observed 12-byte layout.

Initialization uses two separate shared address sources: one for the first working record and one for the second. Each source is read independently for each of its three word-load expressions. Neither seed-address source is explicitly captured once for the whole record.

Each expression combines its current source value with a fixed seed-specific address adjustment and a word offset of zero, four, or eight bytes. Those offsets are relative to the source value read by that particular expression. Treating the three loads as accesses to one contiguous seed record requires the relevant source value to remain stable across all three reads.

The first table has a 12-byte entry stride. Selected entry addresses are passed directly to F-bbd1fe9881a1; this function does not explicitly read their contents.

## Behavior

### Ordered seed-address and seed-data reads

Initialization performs six source/data read pairs in this order:

1. Read the first shared seed-address source; read the first record’s first payload word using that value and the first fixed adjustment.
2. Read that same shared source again; read the first record’s second payload word using this newly read value, the same adjustment, and an additional four bytes.
3. Read that source a third time; read the first record’s auxiliary word using this third value, the same adjustment, and an additional eight bytes.
4. Read the second shared seed-address source; read the second record’s first payload word using that value and the second fixed adjustment.
5. Read the second source again; read the second record’s second payload word using this newly read value, the second adjustment, and an additional four bytes.
6. Read the second source a third time; read the second record’s auxiliary word using this third value, the second adjustment, and an additional eight bytes.

Each data read is four bytes. Each obtained word initializes its corresponding working-record field. All first-record initialization expressions precede all second-record initialization expressions, and all six pairs precede the first dependency call.

Thus initialization includes **six shared address-source reads as well as six seed-data reads**. A source change between expressions can change the underlying origin of later words. The result need not be a copy of any single contiguous external record.

This differs from table-base handling: each table base is resolved once immediately before its loop and retained within that loop. Seed initialization contains no corresponding once-per-record capture. The static representation does not establish concurrent-access semantics or atomicity.

### Selector preparation

After initialization, F-870c4fcf7295 is called with:

- The primary integer increased by `0x1B9B`.
- The constant `0x37`.

Its return supplies upper and lower 32-bit halves of a 64-bit value.

After that call returns, the first working record’s payload is read into the first accumulator. It equals the initialized payload only if intervening dependency effects preserved the record.

Selector construction is:

- Interpret the upper half as signed 32-bit and subtract `0x1B`, retaining the resulting 32-bit pattern.
- Save whether that pattern, interpreted as signed 32-bit, is nonnegative.
- If negative, use its unsigned 32-bit negation as the first selector; otherwise use the pattern unchanged.
- Interpret the lower half as signed 32-bit and subtract `0x80`, retaining that pattern as the lower selector. No absolute-value transformation is applied.

The saved upper sign decision later controls finalization.

The input adjustment and both half-word subtractions involve signed arithmetic. Overflow behavior is not independently established. The upper-pattern negation is unsigned and modular at 32 bits: negating `0x80000000` leaves that pattern unchanged.

### First-table resolution and processing

After F-870c4fcf7295 returns, the first-table address source is read and combined with its fixed address adjustment. This occurs even if the first selector is zero. The resulting base is retained throughout the first loop.

Consequently, a dependency change to that source before resolution can affect this loop. Changes to the source during the loop do not redirect its retained base. Table contents are not thereby frozen.

Positions begin at zero and advance by one for every processed selector position, including clear bits.

**Every first-loop condition evaluation first reloads the second working record’s payload into the second accumulator, then tests the first selector.** This includes the initial evaluation and the terminating evaluation.

For a clear least-significant bit, there is no selected-entry call or explicit first-table data read.

For a set bit, the function:

- Writes the first accumulator into the first working record’s payload.
- Calls F-bbd1fe9881a1 with that record first and the retained first-table base plus 12 bytes per current position second.
- Replaces the first accumulator with the dependency’s 64-bit return.
- Overwrites the first working record’s auxiliary field with the adjustment integer.

The returned value controls the next first accumulator, rather than any payload mutation left in the record by the dependency. Before a later selected call, the accumulator is written back into that record.

The first selected call sees the record’s then-current auxiliary field. Identifying it with the seed auxiliary word requires preservation by earlier dependency activity. Subsequent selected calls ordinarily see the adjustment integer because of the explicit post-call overwrite, subject to other interference.

After each iteration, the position advances and the selector is shifted right after conversion to signed 32-bit. An unconditional zero-filling shift is not established.

### Second-table resolution and processing

After the first loop’s terminating condition reload, the position counter is reset. The second-table address source is then read and combined with its fixed adjustment. Resolution occurs even if the lower selector is zero.

The second-table base is retained throughout its loop. First-loop dependency effects on its source can therefore affect the chosen base; later changes to that source do not redirect the loop.

Every second-loop condition evaluation performs these operations in order:

1. Write the first accumulator into the first working record’s payload.
2. Write the second accumulator into the second working record’s payload.
3. Test whether the lower selector is nonzero.

These payload writes occur on the initial and terminating evaluations as well as between iterations. They do not explicitly alter auxiliary fields.

Positions start at zero. A clear bit causes no explicit second-table entry read or selected-entry call.

For a set bit:

1. Select the entry at the retained second-table base plus 16 bytes per current position.
2. Read its first, second, and third four-byte words into the temporary record, in that order.
3. Read its fourth word for comparison with the signed negation of the adjustment integer.
4. If equal, add the adjustment integer to the temporary auxiliary field.
5. Call F-bbd1fe9881a1 with the second working record first and the temporary record second.
6. Replace the second accumulator with the dependency’s 64-bit return.
7. Overwrite the second working record’s auxiliary field with the adjustment integer.
8. Reload the first accumulator from the first working record’s payload.

The conditional addition changes the temporary copy, not the table entry. The fourth word is not copied into the record passed onward.

The first selected second-loop call sees the second record’s then-current auxiliary field. First-loop dependencies have no established preservation contract for that field. After a selected second-loop call, the explicit overwrite establishes the adjustment integer, absent other interference.

Reloading the first accumulator after the call preserves any first-record payload mutation visible at that point. The next condition evaluation writes that reloaded value back.

After every iteration, the position advances and the lower selector is right-shifted through a signed 32-bit interpretation.

### Finalization and publication

After the lower loop terminates:

- A nonnegative saved upper decision selects F-bbd1fe9881a1, with the second working record first and the first working record second.
- A negative saved upper decision selects F-78d399bb1bbd, with no explicit arguments.

The selected dependency’s 64-bit return is stored at destination offset zero. The adjustment integer is then stored at offset eight.

No accumulator is explicitly passed to F-78d399bb1bbd. Its possible reliance on ambient state is unknown.

### Arithmetic and termination boundaries

A selector within the nonnegative signed 32-bit range reaches zero under repeated right shifts, with at most 31 examined positions.

Under sign-extending right shift, a negative selector does not reach zero: it eventually becomes all-one bits and remains there. This affects negative lower selectors and the first selector pattern `0x80000000`, which survives unsigned negation unchanged.

There is no bounded-completion guarantee for those cases. Invalid table access or index/address arithmetic failure may occur before any indefinitely repeating behavior.

Negating the most-negative adjustment integer and overflowing the temporary auxiliary-field addition are further signed-arithmetic boundaries. Their behavior is not independently established.

## Acceptance examples

These are conditional static examples, not executed tests. They assume valid accesses and arithmetic, normally returning dependencies, and any preservation conditions stated.

### Stable seed-address sources

### Changing seed-address source

Suppose the first source supplies values A, B, and C on its successive reads. Let D denote its fixed seed-address adjustment.

The first payload word comes from A + D, the second from B + D + 4, and the auxiliary word from C + D + 8. A single record rooted at A + D is not implied. The second source is read separately three times afterward; stability or changes of the first source establish nothing about the second.

This example specifies the address selections if such values are observed; it does not establish a supported concurrency mechanism.

### Zero selectors

If F-870c4fcf7295 returns upper half `0x1B` and lower half `0x80`:

- Both table bases are still resolved, in their respective phases.
- The first-loop terminating condition reloads the second payload.
- No table position is selected.

Preserved initialized records supply the finalization inputs. Each initialized record represents one contiguous seed only under the source-stability condition.

### Separated first-selector bits

Upper half `0x20` produces first selector five. With lower half `0x80`, first-table positions zero and two are selected, in order; position one causes no call.

Before the second selected call, the first record receives the previous return payload and ordinarily retains the adjustment integer written after the first call. The second payload is reloaded on every first-loop condition, including termination.

### Phase-dependent source changes

If F-870c4fcf7295 changes the first-table address source, resolution observes its later value. A subsequent first-loop call changing that source does not redirect remaining first-loop selections.

A first-loop call changing the second-table source can affect its later resolution. Changes to either seed-address source after initialization do not cause new seed loads.

### Cross-record mutation

With both selectors equal to one, suppose the first-loop dependency changes the second working record’s payload and auxiliary field.

The first-loop terminating condition reloads the changed payload. The initial second-loop condition writes it back. The first second-loop call sees the changed auxiliary field, not necessarily its initialized value. Only after that call returns is the field explicitly replaced with the adjustment integer.

### Copied-field adjustment

For lower half `0x81` and adjustment integer seven, second-table position zero is selected. A fourth word representing negative seven causes seven to be added to the copied auxiliary field, provided the addition is valid. A different comparison word leaves it unchanged.

The temporary record is passed onward; the function does not explicitly rewrite the table.

### Negative finalization and shift boundaries

Upper half `0x1A` and lower half `0x80` select first-table position zero, then finalize through F-78d399bb1bbd. Its return, not the first accumulator directly, is published.

Lower half `0x7F` produces negative one without subtraction overflow. Under sign-extending shift, it remains negative one.

Upper half `0x8000001B` yields the most-negative displacement after subtraction. Unsigned negation leaves `0x80000000`; under sign-extending shift, that first selector also fails to reach zero.
