# F-79e7676a2ca1

## Purpose

F-79e7676a2ca1 inspects a five-byte working window, selects among several ordered fixed-data comparisons, and reports either a one-byte classification or failure.

Established behavior:

- The window’s source address is derived from a dependency’s return value and the first argument.
- The first three working bytes undergo a numeric transformation before delimiter detection.
- Delimiter position selects one of three comparison families.
- A recognized case produces a classification from 0 through 5, writes exactly one output byte, and returns the 32-bit value 0.
- An unrecognized case returns the 32-bit value 1 without a direct write to the output byte.

The structure suggests suffix classification, but the underlying text format, reference contents, and meanings of the classification values are unknown. Those interpretations are not contractual.

The byte transformation is particularly important: under the integer-promotion rules of the supplied expression, it is **not limited to uppercase ASCII letters**. Ordinary period bytes in the first three positions are transformed away; a different input byte can become a period.

### Return and output contract

- Return **0** means the function has directly stored one classification byte at the output address.
- Return **1** means the function has not directly stored a classification byte.

Return 0 does not mean classification 0; all six classification values use return 0.

## Behavior

### Preparation and dependency order

The directly visible order is:

1. Initialize the two scratch words from the third and fourth arguments.
2. Call F-1cb585febd84 without explicit arguments.
3. Form a source-address value by adding the first argument to that return value and then subtracting 5.
4. Call F-fac138f80b6d with the scratch start address, the calculated source-address value, and the numeric argument 5.
5. Transform working positions 0, 1, and 2, in that order.
6. Select a delimiter branch and perform its ordered comparisons.
7. Either write one classification byte and return 0, or return 1 without that direct output write.

There is no visible check that the calculated address is readable, that at least five bytes are available there, or that the value returned by F-1cb585febd84 represents a usable address base. F-fac138f80b6d’s return value, if any, is not inspected.

### First-three-byte transformation

Each of positions 0, 1, and 2 is read as an unsigned eight-bit value. Under the ordinary integer-promotion semantics of the supplied expression:

- Values from hexadecimal 00 through 5A inclusive are increased by hexadecimal 20.
- Values from hexadecimal 5B through FF inclusive are unchanged.
- A write occurs only for a byte in the first range.
- Positions 3 and 4 are not directly transformed.

The addition cannot overflow an eight-bit destination: the largest transformed value is hexadecimal 7A.

This rule includes ASCII uppercase-to-lowercase conversion, but also changes smaller byte values. For example:

| Before | After | Consequence |
|---|---|---|
| 41, ASCII `A` | 61, ASCII `a` | Uppercase letter changes. |
| 5A, ASCII `Z` | 7A, ASCII `z` | Upper boundary changes. |
| 5B, ASCII `[` | 5B | First value above the boundary is unchanged. |
| 2E, ASCII period | 4E, ASCII `N` | An ordinary period no longer acts as a delimiter. |
| 0E | 2E, ASCII period | A non-period byte becomes a delimiter. |
| 00 | 20, ASCII space | A zero byte is not preserved. |

There is no visible terminator handling: a zero byte does not stop preparation or comparison.

### Delimiter priority and classification

Delimiter checks use the transformed working bytes. Their priority is position **1**, then position **0**, then position **2**. This is not a left-to-right search.

#### Period at position 1

If position 1 contains a period, the function compares positions 2–4 against R01 through R12, stopping at the first zero result.

| First zero comparison | Classification |
|---|---:|
| R01 | 0 |
| R02 or R03 | 1 |
| Any of R04–R10 | 2 |
| R11 | 3 |
| R12 | 4 |

If all twelve comparisons return nonzero, the function returns 1 without a direct output write.

Each comparison receives the same working start address, position 2, and length 3. Position 2 has undergone transformation; positions 3 and 4 have not. Therefore, even if the dependency performs exact byte comparison, this is not general case normalization of the complete three-byte range.

A failed position-1 branch does not fall back to either other delimiter branch.

#### No period at position 1, but period at position 0

The function compares positions 1–4 against R13, then R14, using length 4.

- A zero result from either comparison selects classification 1.
- If both return nonzero, the function returns 1 without a direct output write.

Positions 1 and 2 have undergone transformation; positions 3 and 4 have not.

A failed position-0 branch does not fall back to the position-2 branch.

#### No period at positions 1 or 0

The function checks position 2.

- If position 2 is not a period, it returns 1 without any comparison call.
- If position 2 is a period, it compares positions 3–4 against R15 using length 2.
- A zero result selects classification 5.
- A nonzero result returns 1 without a direct output write.

Neither byte in this final comparison range undergoes the direct transformation.

### Completion

Every recognized path directly writes its classification to the output address once, then returns 0. There is no additional directly visible dependency invocation after that store.

Comparison families are exclusive. Recognition failure in one selected family does not trigger another family.
