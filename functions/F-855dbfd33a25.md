# F-855dbfd33a25

## Purpose

F-855dbfd33a25 selects one of three paths using a 16-bit input discriminator and, when that discriminator is nonzero, a 16-bit context field:

- **Zero discriminator:** invokes a transfer-like dependency, sets one bit in a caller-addressed object, and returns zero.
- **Nonzero discriminator with context field `0x4244`:** constructs a local record, invokes shared processing, and conditionally invokes a transformation and finalization.
- **Other nonzero discriminator:** invokes a transfer-like dependency before shared processing, then conditionally invokes another transfer-like operation and finalization.

The established behavior comprises the wrapper’s reads, writes, argument preparation, dependency-call order, and status propagation. Application-level meanings, transfer direction, dependency access requirements, and resource ownership are not established.

All behavior described below assumes that the relevant memory operations are valid and each invoked dependency returns normally. No runtime tests have been performed.

## Interface

The function accepts five arguments in this order:

| Argument | Established role |

| Context address | On nonzero-discriminator paths, provides a pointer field at byte offset `0x154` and a 16-bit field at byte offset `2`. |
| Object address | On the zero-discriminator path, provides a byte at offset `0x0C` and an address formed by adding `0x2C`. |
| Input address | Provides the initial 16-bit discriminator. Its subsequent use depends on the selected path. |

| Auxiliary value | A 32-bit value stored in the local control state on either nonzero path. |

The supplied representation has 8-bit bytes, 16-bit short values, and 32-bit integer and pointer representations. These widths govern truncation, storage, and status conversion.

### Result

The result is a signed 32-bit status:

| Condition | Returned value |
|---|---|
| Zero discriminator, after the dependency returns and the flag update completes | Zero |
| Shared processing produces a nonzero signed 16-bit status | That status sign-extended to 32 bits |
| Special-path transformation produces a nonzero 32-bit result | That complete 32-bit result |
| Finalization is reached | Its signed 16-bit status sign-extended to 32 bits |

There is no common error-code translation. In particular, the transformation result is not narrowed to 16 bits.

### Direct storage requirements and address passing

Every invocation directly reads a 16-bit discriminator at the input address.

Additional direct accesses are branch-dependent:

- **Zero discriminator:** the wrapper reads and writes the object byte at offset `0x0C`. It also forms the object address plus `0x2C` and passes that address to F-70a021fc7c24 with count `64`. The wrapper does not itself access the resulting 64-byte range.
- **Either nonzero path:** the wrapper reads a 32-bit pointer representation at context offset `0x154`, reads a 32-bit value through that pointer, and reads the context’s 16-bit field at offset `2`.
- **Special nonzero path:** the wrapper directly reads a 16-bit input element at byte offset `2`. Separately, it forms and passes input addresses at byte offsets `4` and `8` to F-ef04bf9ca82f. Passing those addresses does not establish that the dependency reads them, uses 16-bit accesses, or requires any particular accessible extent.
- **Ordinary nonzero path:** the wrapper passes the input address to F-70a021fc7c24 with count `12`. That call does not independently establish an input read or its extent.

The visible body contains no explicit null, alignment, extent, or address-overflow checks. Input offsets `4` and `8` arise from advancing a pointer to 16-bit elements by two and four elements, respectively.

Dependency-specific validity, alignment, and accessible-storage requirements remain unknown. In particular, no readable extent at input offsets `4` or `8` can be derived solely from this wrapper.

## Behavior

### Initial discrimination

The wrapper first reads the 16-bit value at the input address and compares it with zero.

- Zero selects the short path.
- Any nonzero bit pattern selects context-dependent processing.

The nonzero discriminator’s magnitude and sign are not otherwise interpreted by the wrapper. This discriminator read precedes the direct context and object accesses described below.

### Zero-discriminator path

The observable sequence is:

1. Invoke F-70a021fc7c24 with the data value, the object address plus `0x2C`, and count `0x40`, or `64`.
2. After that dependency returns, read the object byte at offset `0x0C`.
3. Write the same byte with bit `0x80` set.
4. Return zero.

Any result from F-70a021fc7c24 is ignored. This path contains no explicit failure-status branch.

The flag update preserves the other seven bits as observed **after** the dependency call. It does not preserve an earlier snapshot. If the dependency changes that byte before returning, the wrapper’s bitwise update uses the changed value.

This path does not directly read the context or invoke shared processing, the special transformation, or finalization. F-70a021fc7c24 may have effects beyond those visible in the wrapper; neither transfer direction nor a lack of other effects is established.

### Shared setup for nonzero discriminators

For either nonzero path, the wrapper performs the following reads in order:

1. Read the pointer stored at context offset `0x154`.
2. Read a 32-bit value through that pointer and retain it.
3. Read the 16-bit context field at offset `2`.
4. Select the special path if that field equals `0x4244`; otherwise select the ordinary path.

The retained 32-bit value is supplied to shared processing and, if reached, finalization. The wrapper does not fetch the context pointer or its pointee again for finalization.

This retention does not imply that dependencies preserve context storage, globals, or state reachable through the retained value.

### Special nonzero path

#### Record preparation

When the context field equals `0x4244`, the wrapper prepares a local record in this order:

1. Set record byte `0` to `7`.
2. Directly read the 16-bit input element at byte offset `2`; store its low eight bits in record byte `1`.
3. Pass the input address plus `4` to F-ef04bf9ca82f.
4. Pass that dependency’s 32-bit result and the address of record byte `2` to F-946cac4b59bc.
5. Pass the input address plus `8` to F-ef04bf9ca82f.
6. Store the low 16 bits of the second result in record bytes `6` and `7`, using the target’s native 16-bit storage representation.

The two calls to F-ef04bf9ca82f establish address passing and result use, not memory reads at those addresses. Their access direction, access width, and required storage extent are **documented_only**.

F-946cac4b59bc receives the start of a four-byte local field at record bytes `2` through `5`. The wrapper does not directly store the first conversion result there. Whether the dependency writes that field completely, what representation it uses, and what else it changes are unknown.

Considering the 12-byte record range used elsewhere in this function, this path explicitly stores bytes `0`, `1`, `6`, and `7`, and delegates possible preparation beginning at byte `2`. It does not explicitly initialize bytes `8` through `11`.

#### Processing-state preparation

After record preparation, the wrapper initializes local processing state in this order:

1. Set a mutable 32-bit pointer slot to the special scratch address.
2. Set a 16-bit control field to zero.
3. Set a 32-bit size field to `12`.
4. Set another 32-bit field to `1`.
5. Store the auxiliary argument in a 32-bit field.

The special scratch region is 12 bytes in the supplied local layout. Its contents are not explicitly initialized by the wrapper before processing.

The wrapper invokes F-7cae4aaa5e45 with these arguments, in order:

1. The retained indirect 32-bit value.
2. The control-area address.
3. The 32-bit bit pattern `0xFFFFFFFF`.
4. The address of the mutable pointer slot.
5. The address of a separate local output region.
6. The same control-area address used for argument two.

Arguments two and six therefore alias exactly.

The returned status is interpreted as signed 16-bit. A nonzero status is sign-extended and returned immediately. Neither the transformation nor finalization is then invoked.

#### Transformation

If shared processing returns zero, the wrapper invokes F-28387a174838 with:

- The data value.
- The original special scratch address.

This is the fixed scratch address, not a value reloaded from the mutable pointer slot. A replacement pointer supplied by shared processing does not redirect this call.

A nonzero transformation result is returned at its full 32-bit width, without finalization. A zero result permits common finalization.

### Ordinary nonzero path

When the context field differs from `0x4244`, the wrapper first invokes F-70a021fc7c24 with:

1. The input address.
2. The local record address.
3. Count `12`.

Its result is not checked. The wrapper alone does not establish which address is read or written, nor that this call initializes all 12 record bytes.

After that call returns, the wrapper prepares processing state in the same order as on the special path:

1. Set the mutable pointer slot to the ordinary scratch address.
2. Zero the 16-bit control field.
3. Set the 32-bit size field to `64`.
4. Set the other 32-bit field to `1`.
5. Store the auxiliary argument.

It then invokes F-7cae4aaa5e45 with the same argument arrangement as on the special path.

A nonzero signed 16-bit processing status is immediately sign-extended and returned. If processing returns zero, the wrapper invokes F-70a021fc7c24 with:

1. The data value.
2. The original ordinary scratch address.
3. Count `64`.

The result is ignored. This call uses the fixed ordinary scratch address even if processing changed the mutable pointer slot. Normal return from this dependency leads to finalization.

### Common finalization

Finalization is reached only after:

- Successful special processing followed by a zero transformation result; or
- Successful ordinary processing followed by normal return from its second transfer-like call.

The wrapper invokes F-02816309a5ec with:

1. The retained indirect 32-bit value.
2. The control-area address.
3. The address of the mutable pointer slot.
4. The first 16-bit value read from the local output region previously supplied to processing.

The output region is not explicitly initialized by the wrapper before processing. Its value at finalization therefore depends on dependency behavior or other guarantees absent from the supplied evidence.

The finalization result is interpreted as signed 16-bit, sign-extended to 32 bits, and returned. No subsequent operation is shown.

## Side effects

### Caller-addressed storage

The only direct write through a caller-supplied address is the zero-path flag update at object offset `0x0C`.

Dependencies may modify caller-addressed storage, reachable objects, local storage supplied to them, or globals. The wrapper does not establish preservation of the input, data, context, or object merely because it lacks direct writes to those locations on a particular path.

Aliasing among arguments or with dependency-reachable state can therefore affect observations. The specified call and access order matters.

### Ownership and lifetime

The wrapper passes addresses of automatic local storage. It contains no explicit allocation or release operation.

The evidence does not establish whether processing allocates resources, replaces the pointer with owned storage, transfers ownership, or requires cleanup. Finalization cannot be characterized as a deallocator merely because it is called last.

Processing failures and special transformation failures bypass finalization. Whether those exits satisfy resource-management obligations is unknown. Any retention of local addresses beyond the call requires a dependency-specific lifetime contract not supplied here.

## Acceptance examples

These are conditional static expectations, not executed tests.

1. **Flag update uses the post-call byte.**  
   With a zero discriminator, if F-70a021fc7c24 returns normally and the object flag byte is then `0x25`, the wrapper writes `0xA5` and returns zero. Shared processing and finalization are not called.

2. **Special-path direct read and address passing are distinct.**  
   With a nonzero discriminator and context field `0x4244`, if the directly read 16-bit input value at byte offset `2` is `0x12AB`, record byte `1` becomes `0xAB`. The wrapper subsequently passes addresses at offsets `4` and `8` to F-ef04bf9ca82f. This example makes no claim that either address is dereferenced or requires readable storage; those requirements depend on the dependency.

3. **Second conversion is narrowed.**  
   If the second F-ef04bf9ca82f call returns `0x1234ABCD`, the wrapper stores the 16-bit pattern `0xABCD` in record bytes `6` and `7`. Their individual byte order is not established here.

4. **Processing failure skips later stages.**  
   On either nonzero path, a processing status with 16-bit pattern `0xFFFE` produces signed 32-bit result `-2`. Branch-specific follow-on work and finalization are skipped.

5. **Transformation failure retains full width.**  
   If special processing succeeds and the transformation returns `0x00010000`, the wrapper returns `65536`, not zero. Finalization is skipped.

6. **Ordinary success preserves call order.**  
   With a nonzero discriminator and a context field other than `0x4244`, normal successful execution calls the 12-count operation, shared processing, the 64-count operation, and finalization in that order. Processing failure prevents the latter two calls.

7. **Pointer replacement does not redirect follow-on work.**  
   If processing changes the mutable pointer slot and returns zero, the transformation or ordinary 64-count operation still receives its original scratch address. Finalization receives the pointer-slot address and can observe its then-current contents.

8. **Final status is sign-extended.**  
   If finalization is reached and returns 16-bit pattern `0xFFFF`, the wrapper returns signed 32-bit `-1`. A zero finalization status yields zero.
