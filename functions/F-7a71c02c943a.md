# F-7a71c02c943a

## Purpose

F-7a71c02c943a performs a forward scan over fixed-stride records. It stops when either the current record address equals a stored end address or a four-byte value in the current record equals a supplied comparison value.

The function exposes no search result: it returns no value, writes no match address or status, and performs no explicit memory writes. Its established behavior is the traversal and associated memory reads, followed by termination when a stopping condition is met.

A search-like intent is inferred from the comparison and traversal. The supplied representation does not establish why the scan is useful to its caller, whether it originally had another purpose, or whether the reads have externally observable significance.

### Record layout

The traversal stride is 12 bytes. For each visited record whose address differs from the current end address, the function reads a four-byte value at byte offset 8 within that record.

It does not explicitly read the first eight bytes of a record. Their meaning is unknown. The 12-byte stride does not independently prove that every record belongs to one allocated array or that the first eight bytes are valid for access.

## Behavior

### Initialization

The function first reads the four-byte field at container offset 8 and uses that value as its current-record address.

This initial address is not reloaded from the container during traversal. A later change to that container field therefore does not, by itself, redirect the scan.

Neither the opaque third argument nor the incoming fourth argument influences this initialization.

### Per-iteration read and stop order

Each iteration begins by reading the four-byte end-address field at container offset 12. The function compares that value with the current-record address.

If the addresses are equal:

- The function terminates.
- It does not read the record field at current address plus 8.
- It does not advance the current-record address.
- The incoming or previously assigned scratch value is irrelevant to this termination.

If the addresses differ:

- The function reads the four-byte field at current address plus 8.
- It compares that value with the comparison argument.
- Equality terminates the function immediately.
- Inequality advances the current-record address by 12 bytes, after which another iteration begins.

Consequently, the represented access order is:

1. One initial-address read.
2. An end-address read.
3. A record-field read only if the current address differs from that end address.
4. Further end-address and conditional record-field reads as traversal continues.

These are the access expressions established by the supplied representation. They are not a guarantee of a particular hardware instruction sequence or of volatile, atomic, or synchronization semantics.

### Boundary behavior

The end address is an exclusive traversal boundary when the range is well formed. A record-field value at that address is not inspected.

The function tests address equality only. It does not test whether the current address is below the end address, has passed it, or lies within an allocation. An end address that is not reachable by repeated 12-byte advances does not provide a reliable stopping condition.

There is no special null-address handling. Zero-valued address fields participate in the same equality checks and address calculations as other values. Equality between the initial and end addresses avoids a record-field read, but does not avoid the two container-field reads.

### Value comparison

Record values and the comparison argument are represented as 32-bit integers. The stopping test is equality, not ordering. No special treatment is shown for zero, negative values, high-bit-set values, or any sentinel value.

No arithmetic is performed on a record value. The function merely reads it and tests equality.

### Changes during traversal

The end address is reread on every iteration, whereas the initial address is read only once. If externally changing memory is otherwise valid under the execution model, a later iteration can therefore encounter a different end address.

The function provides no synchronization, consistency check, or snapshot. The supplied evidence does not define concurrent access behavior or establish that unsynchronized modifications are permitted. It also does not guarantee termination when relevant memory changes during execution.
