# F-346a985a4f4b

## Purpose

F-346a985a4f4b recognizes either of two selector categories and conditionally dispatches to the corresponding dependency. It reports whether a category was recognized, not whether the dispatched operation succeeded.

The categories are referred to here as **deletion** and **selection**. These are descriptive labels suggested by the supplied constant names. Their application-level meanings and actual selector representations are not established.

A recognized category produces the 32-bit result `1`, including when dispatch is suppressed because the supplied state value matches a shared state value. An unrecognized selector produces the 32-bit result `0`.

This contract describes the supplied static representation. No runtime tests have been performed.

## Interface

### Inputs

The function receives three arguments:

| Argument | Recovered width | Contract role |
|---|---:|---|
| Context | 32 bits | Forwarded as the first argument of a dispatched operation. Not otherwise interpreted by this function. |
| Selector | 32 bits | Passed to a comparison dependency, first against the deletion-selector constant and, if necessary, against the selection-selector constant. |
| Candidate state | 32 bits | Compared for equality with shared state and forwarded as the second argument of a dispatched operation. |

The context and selector are recovered as untyped four-byte values. The supplied evidence does not establish whether either is a pointer, handle, integer, or other encoded value. In particular, this function does not visibly dereference either argument.

The candidate state is represented as an integer. Its only local use, apart from forwarding, is an equality comparison. There is no arithmetic, ordering comparison, range check, or signedness-dependent branch.

### Result

On normal completion, the result is a four-byte value with one of two exact values:

- `0`: neither comparison recognized its category.
- `1`: the deletion category or selection category was recognized.

There is no separate result for “recognized but not dispatched.” A dispatched dependency’s return value does not determine the wrapper’s result.

### Shared state and selector constants

The function accesses one shared integer state location. This contract calls it **shared state** without assigning an application meaning.

Two distinct selector operands are supplied to the comparison dependency:

The supplied representation does not expose their bytes, lengths, encodings, termination rules, or complete storage layouts. Their descriptive labels do not establish those details.

## Behavior

### Recognition and precedence

The deletion comparison always occurs first. The comparison dependency receives the selector as its first argument and the deletion-selector constant as its second argument.

An exact zero result recognizes the deletion category. Any nonzero result rejects that category and permits the selection comparison.

If deletion is recognized, selection is not compared. Deletion therefore has precedence if the comparison dependency would return zero for both category operands.

After the first comparison returns, the supplied representation evaluates shared state and retains that value for possible use on the selection path. This happens before the branch that either handles deletion or proceeds to selection.

If deletion was not recognized, the comparison dependency is called again, now with the same selector value and the selection-selector constant.

- A nonzero second result causes an immediate result of `0`.
- An exact zero second result recognizes selection and proceeds to its state check.

The comparison dependency is only known to supply zero or nonzero outcomes used by this wrapper. The evidence does not establish string comparison, case sensitivity, normalization, pointer comparison, or any other matching algorithm.

### Deletion path

When the first comparison returns zero, the candidate state is compared with a shared-state expression evaluated on the deletion path.

If they differ, F-b0ae49f0a11f is invoked with:

1. the original context;
2. the original candidate state.

If they are equal, that invocation is skipped.

After either outcome, the function returns `1`, provided any invoked dependency returns normally. The function does not inspect or propagate a dispatch result.

The earlier retained shared-state value is not the value explicitly used by the deletion condition in the supplied representation. The deletion condition refers to shared state again. The distinction is relevant to the represented evaluation order, although the exact number of physical memory loads cannot be established from this representation alone.

### Selection path

When the first comparison is nonzero and the second comparison is zero, the candidate state is compared with the shared-state value retained **after the first comparison and before the second comparison**.

If they differ, F-838da10ba247 is invoked with:

1. the original context;
2. the original candidate state.

If they are equal, that invocation is skipped.

The selection condition does not visibly reevaluate shared state after the second comparison. Thus, a shared-state change made by that comparison does not, in the supplied representation, replace the retained value used for the selection decision.

After either dispatch or suppression, the function returns `1`, provided any invoked dependency returns normally.

### Unrecognized path

If both comparisons return nonzero:

- neither dispatch dependency is invoked;
- the function returns `0`.

The shared-state evaluation following the first comparison has already occurred. Consequently, an unrecognized selector does not imply an absence of shared-state access.

### Ordering constraints

At the level of the supplied representation, the following ordering is established:

1. The deletion comparison completes.
2. Shared state is evaluated and retained.
3. One of these paths follows:
   - recognized deletion: evaluate the deletion-path shared-state condition, optionally invoke F-b0ae49f0a11f, then return `1`;
   - rejected deletion: perform the selection comparison;
4. Following the selection comparison:
   - rejection returns `0` without dispatch;
   - recognition compares against the retained state, optionally invokes F-838da10ba247, then returns `1`.

There is no loop, retry, fallback dispatch, or subsequent comparison after a category is recognized.

## Side effects

The function directly:
