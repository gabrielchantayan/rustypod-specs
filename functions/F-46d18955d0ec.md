# F-46d18955d0ec

## Purpose

F-46d18955d0ec conditionally updates four portions of a caller-supplied memory object. Each input independently controls whether its corresponding update occurs. After each selected update, the function reads a shared 16-bit field and writes it back with one additional bit set.

Two updates are performed directly: a 16-bit value store and a one-byte copy. Two updates are delegated to F-35c2e4297234 using addresses inside the object.

**Established behavior:** selection depends on whether each controlling input is zero or null, not on whether the eventual stored value is nonzero. Updates are ordered and are not transactional.

**Inferred intent:** the shared 16-bit field appears to record which portions have been supplied. Its bits are not established as validity, ownership, completion, or success indicators. In particular, delegated updates have no inspected success result.

## Behavior

### Selection and execution order

The function considers the optional updates in this fixed order:

1. Scalar update.
2. Byte update.
3. First delegated update.
4. Second delegated update.

Each selection is independent. An omitted earlier update does not prevent a later selected update. An earlier failure or non-returning dependency call can, however, prevent later operations from being reached.

No shared field value is cached across these stages. Each selected stage separately reads the 16-bit field at offset 20 after its data operation or dependency call.

### Scalar update

If the scalar selector/value is zero, this stage performs no direct memory access.

Otherwise:

- The low 16 bits of the input are stored at offsets 16–17.
- The 16-bit field at offsets 20–21 is read.
- That field is written with mask 0x0001 set, preserving all other bits of the value just read.

The selection test applies to the original integer input, before narrowing. Consequently, a nonzero input whose low 16 bits are zero still selects this stage, stores a zero 16-bit pattern, and sets mask 0x0001.

The stored pattern does not establish a signed interpretation for subsequent consumers. For example, an all-ones 16-bit pattern may be interpreted differently by signed and unsigned readers.

### Byte update

If the byte-source address is null, this stage performs no direct memory access.

Otherwise:

- Exactly one byte is read from the supplied address.
- That byte is written at offset 18.
- The 16-bit field at offsets 20–21 is read.
- That field is written with mask 0x0002 set, preserving all other bits of the value just read.

A non-null source containing a zero byte still selects the update and sets the mask.

The byte is read when this stage executes, not when the function is entered. If the source aliases memory changed by the preceding scalar stage, the copy observes the already-updated memory. If the source aliases the shared field, it observes that field before this stage adds mask 0x0002, but after any preceding scalar-stage update.

### First delegated update

If the first delegated argument is zero, this stage makes no dependency call and performs no direct shared-field update.

Otherwise:

- F-35c2e4297234 is called with the address at object offset 8 and the unchanged first delegated argument.
- If the call returns normally, the 16-bit field at offsets 20–21 is read.
- That field is written with mask 0x0004 set, preserving all other bits of the value read after the call.

The dependency’s return value, if any, is not inspected. No status-dependent branch is established.

The shared-field read occurs after the call. The dependency may therefore change the field before the mask is added. It may also change other memory or global state; this function provides no preservation guarantee on its behalf.

### Second delegated update

If the second delegated argument is zero, this stage makes no dependency call and performs no direct shared-field update.

Otherwise:

- F-35c2e4297234 is called with the address at object offset 12 and the unchanged second delegated argument.
- If the call returns normally, the 16-bit field at offsets 20–21 is read.
- That field is written with mask 0x0008 set, preserving all other bits of the value read after the call.

The function then returns normally. There is no additional completion operation.

### Shared-field semantics

Each direct shared-field update sets its own mask without directly clearing another bit. This preservation applies to the value read at that particular stage, not necessarily to the value present on entry.

If dependency calls leave the shared field unchanged and no other actor modifies it, the final field is its entry value combined with the masks for all selected stages.

Without those conditions, that formula is not guaranteed. A later dependency may clear bits set earlier, and the subsequent direct update restores only its own mask.

## Side effects

Direct effects are limited to the selected scalar destination, byte destination, and shared-field accesses described above. The function does not directly allocate, release, or transfer memory ownership.

That observation does not constrain F-35c2e4297234. Its ownership effects, retained references, allocation behavior, releases, global changes, and accessed memory extent are unknown. Neither delegated argument may safely be described as borrowed, copied, consumed, or retained on the available evidence.

Updates are incremental. There is no rollback path. If execution stops after an earlier update, that update may remain visible even though later updates did not occur.

No synchronization or atomic operation is established. In particular, the shared-field operations are separate reads and writes. Concurrent mutation can invalidate simple final-value expectations or lose another actor’s changes. This function is not established as thread-safe, reentrant, or suitable for memory-mapped device access.

If all four optional inputs are absent—zero scalar, null byte source, and both delegated arguments zero—the function performs no shown memory access and no dependency call. The object base is not dereferenced on that path.

8. **Aliased byte source.** If the byte source addresses the scalar destination, the copied byte comes from the newly stored scalar pattern. Its numeric value depends on byte order and the selected byte address; neither is assumed here.

9. **Non-returning dependency.** If the first dependency does not return normally, its following mask update and the second delegated stage are not reached through the shown normal control flow. Earlier completed updates have no shown rollback.
