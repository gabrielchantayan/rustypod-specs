## Acceptance examples

These are conditional consequences of static control flow, not executed tests. They assume normal returns and valid storage throughout each scenario.

1. **Closed gate.** If F-30953398b064 returns zero, the sequence is activity-byte set, initial dependency, gate, activity-byte clear, and return zero. No context or workspace calls occur.

2. **Immediate probe failure.** If position 31 produces validity 2, that probe is finalized and processing begins at 0. Nonzero validity alone is insufficient.

3. **Partial descending success.** If 31 and 30 succeed and 29 fails, all three probes are finalized in order, and the first processing position is 30.

4. **Complete descending success.** If all 32 probes succeed, processing begins at 0. No probe receives the all-ones 32-bit position.

5. **Repeated null objects.** If processing begins at 7 and every attempt is valid but resolves to null, all 32 attempts use position 7. No status operation occurs, retained status remains 3, and no completion callback is eligible.

6. **Repeated status 3.** If every attempt at position 7 produces status 3, F-8414980ac530 is called 32 times with position 7. Each call receives the record value read at that call site. No resource-removal outcome is required by this example.

7. **Wraparound.** If a nonfinal attempt at 31 takes an advancing branch, the next attempt uses 0.

8. **Status-5 exit.** A first-attempt status of 5 causes F-8affc51b0705, F-3bd872610d9c, and workspace finalization in that order. No second attempt occurs, and the completion callback is ineligible.

9. **Persistent zero status.** If an object returns status 0 and every remaining attempt is invalid or resolves to null, retained status stays zero. A nonnull completion callback is invoked with the then-current offset-24 field.

10. **Callback suppression.** If the object callback is present but the offset-52 operation returns nonzero, the callback is skipped and the offset-20 status operation still follows.

11. **External-data change during setup.** If the external location changes between the retained-value read and the setup-argument read, setup may receive the newer value while finalization receives the earlier retained value. The body supplies no synchronization preventing this scenario.
