# F-354f64802e98

## Purpose

F-354f64802e98 performs a state-gated operation on a caller-supplied object. On its ordinary path, it conditionally invokes two object-dispatched operations, initializes a temporary four-field record, and conditionally passes that record to additional dependencies. It returns a 64-bit composition of the record’s first two fields.

The function clears an object byte before checking the gate. A nonzero gate selects a separate call sequence whose final dependency is annotated as non-returning.

This contract describes the supplied static representation. Object semantics, dependency implementations, and instruction-level memory-access widths are not established. In particular, the condition associated with object offset `+0xA0` uses a **32-bit integer-typed source access followed by conversion to an 8-bit character value**. Its byte-valued condition must not be confused with evidence of an 8-bit memory load.

Without instruction-level evidence, whether the implementation loads a byte, a word, or uses another equivalent access sequence is **documented_only**.

The entry write at `+0xA1` falls within that four-byte storage region. It is nevertheless distinct from the later character-converted comparison; clearing `+0xA1` does not establish that the later condition succeeds.

### Return value

The ordinary return is a 64-bit bitwise composition:

- Bits 31–0 are the final 32-bit contents of record offset `+0x00`.
- Bits 63–32 are the final 32-bit contents of record offset `+0x04`.

Neither field is dereferenced to construct the return. The composition does not establish that the result is one pointer, an ownership token, or any other application-level type.

Without intervening mutation, the low half is the object address and the high half is the object-plus-`0x80` address. Dependency changes to these record fields affect the returned halves.

## Behavior

### 1. Entry write and gate

The first represented operation writes zero through an 8-bit-typed access at object offset `+0xA1`.

The function then reads the 32-bit gate at `+0x15C`.

For a nonzero gate:

1. F-282eebd7c413 is called.
2. If it returns, F-feee9156a257 is called.
3. The latter call is annotated as non-returning.

No ordinary return or record initialization is established on this branch. The entry byte clear has already occurred. The annotation does not identify whether the final dependency terminates execution, raises an exception, or transfers control by another mechanism.

For a zero gate, the function explicitly stores a 32-bit zero back to `+0x15C` and continues. This store is part of the represented behavior even though the preceding read observed zero.

The gate is not explicitly checked again. Later dependency changes to it do not cause the function to repeat the gate decision.

### 2. First predicate and optional dispatch

The function calls F-3fac671648b8 with the object address. Its represented 32-bit result is compared with zero.

If the result is zero, the function skips the flags-field read and both indirect calls.

If the result is nonzero, the function reads the 32-bit field at `+0x48` and tests mask `0x10`. Other bits do not prevent dispatch when this bit is set.

When both the predicate and mask test succeed, the function invokes:

1. The operation selected through dispatch-table byte offset `+0x120`.
2. The operation selected through dispatch-table byte offset `+0x118`.

Each receives the object address.

The table address is obtained from the object’s first 32-bit field. The second call uses a fresh lookup after the first call returns. Changes made by the first operation to the object’s table address or the second table entry can therefore change the second target.

There is no repeated predicate or flags check between these calls. Once this branch is selected, changing the flags during the first call does not itself suppress the second call.

### 3. Record initialization and second predicate

After the optional dispatch sequence, the function initializes the record fields in the order listed in the interface: object address, interior address, third argument, fourth argument.

It then invokes F-3fac671648b8 again. No explicit arguments are recovered for this invocation. Its effective inputs cannot be assumed to match those of the first invocation.

The second result is independently tested; the earlier result is not reused.

Conditional record processing requires all of the following, in order:

1. The second predicate result is nonzero.
2. The 32-bit integer value accessed at object offset `+0xA0`, after character conversion, compares equal to zero.
3. The character value reached through a global pointer compares unequal to zero.

These conditions short-circuit:

- A zero second predicate result skips the `+0xA0` source access and the global check.
- A nonzero character-converted value from the `+0xA0` integer skips the global check.
- A zero global target value skips record processing.

The global check uses a pointer held in global storage and a character-valued dereference through it. No relationship between that global pointer, its target, and the object is established.

The object condition is specifically a word-typed access followed by a byte-valued comparison. It neither requires the entire word to be zero nor establishes that only one byte of object memory is loaded.

### 4. Conditional record processing

If all three conditions succeed, the function performs this sequence:

1. Read and save the 32-bit integer at object offset `+0x34`.
2. Call F-e57b05520b65 with the record address and two identical object-plus-`0x80` addresses.
3. If the saved integer is nonzero, call F-ee8733a08210 with the record address and the saved integer plus `0xD0`.
4. Call F-ffe0d92c57b7 with the object address.
5. If its represented 32-bit result is nonzero, call F-c9b5d17d8d1e with that result and the record address.
6. If that call returns, call F-4d037ecf0f82 with the same saved result and the record address.

The optional F-ee8733a08210 call uses the value captured before F-e57b05520b65. It does not reread `+0x34`. Changes to the object field during that dependency cannot alter this branch decision or substitute a different operand for the addition.

Similarly, the result from F-ffe0d92c57b7 is retained for both following calls. There is no second lookup or explicit validity check between them.

The function does not inspect return values from F-e57b05520b65, F-ee8733a08210, F-c9b5d17d8d1e, or F-4d037ecf0f82. Normal continuation depends on those calls returning.

### 5. Ordinary return

If execution reaches the return, the first two current record fields are composed into the 64-bit result described above.

There is no explicit record destruction or cleanup before this return. No rollback of earlier object writes appears.

## Side effects

### Direct state changes

The body directly represents:

- An unconditional zero write through an 8-bit-typed access at `+0xA1`.
- A zero write through a 32-bit integer access at `+0x15C`, only on the zero-gate path.
- Initialization of the four local record fields.

Forming the object-plus-`0x80` address does not itself read the contents at that address.

Dependencies may change object storage, globals, record contents, dispatch entries, or resource state. The body supplies no preservation guarantees. Its direct stores therefore do not guarantee the same values remain present at return.

### Ownership and lifetime

No direct allocation, deallocation, reference-count operation, or explicit ownership transfer appears.

The record has local-call lifetime, and its address is exposed to dependencies. Retention of that address beyond its lifetime is not made safe by anything visible here. Whether dependencies retain it, release resources referenced by it, or change ownership is unknown.

The function uses the caller-supplied object and derived addresses without an explicit ownership operation. This does not establish that callees treat those addresses as non-owning.

### Preconditions and failure behavior

There are no visible null, bounds, alignment, dispatch-target, or arithmetic-overflow checks.

For defined source-level execution, reached accesses require suitably accessible and aligned storage. In particular, reaching the condition at `+0xA0` requires validity for the **32-bit integer-typed access**, not merely a readable byte at that offset. A byte-valued comparison does not justify weakening this precondition to one byte. Executable-level access requirements cannot be refined without instruction evidence.

Selected dispatch paths require a readable table address, accessible selected entries, and callable targets. Reaching the global check requires valid global pointer storage and a readable target.

The object-plus-`0x80` value is formed using pointer arithmetic in the represented 32-bit model. The saved `+0x34` value is represented as a 32-bit integer, and its addition by `0xD0` is integer arithmetic. No checked-overflow behavior is shown. A portable wraparound guarantee must not be inferred for that signed integer addition; overflow and invalid address cases remain unresolved.

There is no visible local recovery for invalid accesses, invalid dispatch, dependency exceptions, or nonlocal transfers.

## Acceptance examples

These are conditional static acceptance criteria, not executed tests. They assume valid storage and normal dependency returns where continuation is described.

1. **Nonzero gate:** With a nonzero gate, the entry clear precedes F-282eebd7c413. If that dependency returns, F-feee9156a257 follows. No ordinary return is established.

2. **Zero gate:** Observing zero at `+0x15C` is followed by an explicit 32-bit zero store there before the first predicate call.

3. **First predicate false:** A zero first predicate result skips the flags read and both indirect calls. Record initialization and the second predicate invocation still follow.

4. **Flags mask:** With a nonzero first predicate, flags values `0x10` and `0x30` both enable dispatch; `0x20` does not.

5. **Dispatch replacement:** If the first indirect call replaces the object’s table address and returns, the second target is selected through the updated table at `+0x118`.

6. **Word value versus converted value:** If the second predicate is nonzero and the integer obtained at `+0xA0` is `0x00010000`, the character-converted value is zero, so the global check follows. An integer value of `0x00010001` fails that comparison. These examples concern the integer value obtained at the comparison point, after earlier writes and calls; they do not prescribe a machine-load width.

7. **Access precondition:** Making only one byte at `+0xA0` readable is insufficient to establish a valid execution of the represented integer access, even when only the converted low byte affects the branch.

8. **Short circuit:** A zero second predicate skips the word-typed access at `+0xA0`. A nonzero converted value from that access skips the global pointer-target check.

9. **Saved associated value:** If the saved `+0x34` value is nonzero and its addition is valid, F-ee8733a08210 receives that saved value plus `0xD0`, even if F-e57b05520b65 changes the object field. A saved zero continues to suppress the call even if the field becomes nonzero.

10. **Lookup and return mutation:** A zero F-ffe0d92c57b7 result suppresses both following calls. If a reached dependency modifies either of the first two record fields and execution returns, the corresponding return half reflects that modification.
