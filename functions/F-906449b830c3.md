# F-906449b830c3

## Purpose

F-906449b830c3 conditionally computes a 32-bit adjustment, stores it in an input object, and submits an adjusted value to a receiver captured from that object. A nonzero result from the receiver operation causes a further operation on the input object.

The established behavior is a gated sequence of dependency calls, one explicit object-field write, and up to two indirect calls. The application meaning of the adjustment, the numeric representation of the dependency results, and the purposes of the indirect operations are not established.

Normal returns are:

- **0:** the active sequence executes and the receiver operation returns zero.
- **3:** the gate fails, or the receiver operation returns nonzero and the subsequent object operation returns normally.

These are output values, not established success or error classifications.

## Behavior

### Receiver capture and gate

The first object-field read obtains the receiver address from offset `0x010`.

If that value is zero, the function returns 3. It does not read the threshold, call the listed dependencies, read the two global operands, write the adjustment, or perform either indirect operation.

For a nonzero receiver, the function reads the threshold at offset `0x428`. The active sequence executes exactly when the threshold is **strictly greater than the comparison value under signed 32-bit ordering**.

The comparison accounts for signed subtraction overflow and separately excludes equality. It is not unsigned address ordering, and it is not equivalent to testing only the sign of a wrapped difference.

Thus:

- Equal bit patterns fail the gate.
- A signed-smaller threshold fails the gate.
- A signed-greater threshold passes the gate.
- A value with bit 31 set is negative for this decision.

A failed gate returns 3 without entering the remaining sequence.

### Captured field and initial dependency calls

On the active path, the function reads the word at object offset `0x430` and retains it.

It then makes these calls in order:

1. F-9e5e664c8ae7 with the captured `0x430` word.
2. F-9e5e664c8ae7 with the word subsequently read from `0x418`.
3. F-b3a54d881220 with the original comparison value.

Each result is represented as 64 bits.

The `0x418` read occurs after the first call returns. A mutation made by that call can therefore affect the second call’s input.

The captured `0x430` word is retained independently of its storage location. Later changes to that field do not replace the retained value used by this function.

### Global reads and intermediate transformation

After F-b3a54d881220 returns, its 64-bit result is separated into a low 32-bit word and a high 32-bit word. The high word is obtained from the upper half of the unsigned 64-bit representation.

F-596e18a33aec then receives five arguments:

1. Low word of the F-b3a54d881220 result.
2. High word of that result.
3. Value read from global operand A.
4. Value read from global operand B.
5. Original fourth input argument.

The two global operands occupy the corresponding word-sized argument positions. Their declarations and contents are not supplied.

Both global reads belong to preparation of this call, after F-b3a54d881220 has returned and before F-596e18a33aec begins. The supplied expression does not establish whether A or B is read first. No stronger ordering between those two reads is part of this contract.

Any earlier dependency may have changed either global location. Consequently, neither argument can be specified as the value present at function entry. The two reads also do not establish an atomic snapshot of the pair.

The 64-bit result of F-596e18a33aec is combined through two sequential calls to F-c4b34006a13c:

- The first call receives the F-596e18a33aec result as its first word pair and the second F-9e5e664c8ae7 result as its second word pair.
- The second call receives the preceding combination result as its first word pair and the first F-9e5e664c8ae7 result as its second word pair.

Within every pair, the low word precedes the high word.

This establishes operand flow, not numeric meaning. Multiplication, division, floating-point interpretation, fixed-point interpretation, and scaling are not established by the available body.

### Adjustment write and receiver operation

The function subtracts the secondary output from the retained F-f6366b6b2161 result and stores the resulting 32-bit word at object offset `0x438`.

The stored representation is the low 32 bits of that difference.

After this store, it reads object offset `0x420` and adds that word to the computed adjustment. The low 32 bits of the sum form the receiver operation’s third argument.

The receiver is the address captured at entry. The function does not reread object offset `0x010` to choose a replacement receiver.

The receiver operation has these visible arguments:

1. Captured receiver address.
2. Callable address selected through the receiver’s dispatch table at offset `0x014`.
3. Computed adjustment plus the later-read `0x420` word.
4. Zero.
5. Zero.

The call target is also selected through the receiver’s dispatch table at offset `0x014`. The supplied expression includes separate dispatch accesses for the call target and the callable-address argument; it does not justify treating those accesses as a single retained lookup.

The adjustment store precedes the `0x420` read, receiver dispatch accesses, and receiver invocation. Their complete relative evaluation order is not established. Under stable dispatch storage, the target and callable-address argument select the same slot; behavior under intervening dispatch mutation is not resolved as an atomic lookup.

### Final branch

If the receiver operation returns zero, the function returns 0 immediately. The stored adjustment is not rolled back, and the final object operation is not invoked.

For any nonzero receiver result, the function reads the object’s dispatch information through offset `0x000` and invokes the operation selected at table offset `0x024`. Its sole visible argument is the original object address.

These object dispatch accesses occur after the receiver operation returns. They can therefore observe changes made by that operation.

The final object operation’s result is ignored. If it returns normally, F-906449b830c3 returns 3.

## Acceptance examples

These are conditional static contract examples, not runtime test results. Active-path examples assume valid storage and dispatch targets, normally returning calls, and the stated dependency outputs.

1. **Absent receiver.**  
   A zero receiver field produces return 3 without reading the threshold or global operands, calling dependencies, or explicitly writing `0x438`.

2. **Equality.**  
   A nonzero receiver with identical threshold and comparison bit patterns produces return 3 without entering the active sequence.

3. **Signed rather than unsigned ordering.**  
   Threshold `0xFFFFFFFF` and comparison `0x00000000` fail the gate because −1 is not greater than 0. Reversing these operands passes it.

4. **Overflow-sensitive gate.**  
   Threshold `0x7FFFFFFF` and comparison `0xFFFFFFFF` pass the gate. Signed 2,147,483,647 exceeds −1 even though their wrapped subtraction has its sign bit set.

5. **Global mutation before argument preparation.**  
   Suppose global operand A contains 10 at entry, and F-b3a54d881220 changes it to 20 before returning. If it remains unchanged until its argument read, F-596e18a33aec receives 20 as its third argument, not 10. No acceptance condition requires A to be read before B.

6. **Word-width adjustment and addition.**  
   If F-f6366b6b2161 supplies 2 and the secondary output is 5, `0x438` receives `0xFFFFFFFD`. If the later `0x420` read yields 4, the receiver operation’s third argument is 1.

7. **Zero receiver result.**  
   A zero receiver-operation result produces return 0, skips the final object operation, and causes no explicit rollback of the adjustment store.

8. **Nonzero receiver result.**  
   Any nonzero receiver-operation result invokes the final object operation. If that operation returns normally, the final return is 3 regardless of its result.

9. **Captured versus later-read state.**  
   If the first dependency changes `0x418`, the second conversion receives the changed word. Changes to `0x430` or `0x010` do not replace the already captured field value or receiver address.
