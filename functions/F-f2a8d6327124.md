# F-f2a8d6327124

## Purpose

F-f2a8d6327124 traverses a linked collection, derives a two-word candidate for each entry, applies an explicit threshold filter, and conditionally updates a selected value through an opaque comparison dependency. If any explicit selection update occurs, it invokes two final operations.

The established behavior is a selection procedure. The supplied evidence does not establish that it selects a minimum, computes a deadline, schedules an event, or operates on any particular unit.

The function takes no explicit arguments and returns no explicit result. Observable behavior consists of dependency calls, shared-state accesses, and effects produced by those dependencies.

## Behavior

### 1. Construct and capture

The function first zeroes both words of capture storage. It then calls F-7a117b899bf6 with the temporary-object address.

After that call returns, it initializes selected-value storage to the pattern specified above and clears the selection flag.

It then invokes U-2 through the constructed object’s dispatch table, passing:

1. The temporary-object address.
2. The capture-storage address.

No return value from construction or indirect dispatch is tested.

Capture storage subsequently serves as an operand to each entry’s first transformation. Capturing it once does not establish immutability: dependencies receive its address, and their mutation or retention behavior is unknown.

### 2. Obtain context and evaluate the roots

U-1 is called first.

After U-1 returns, the global root reference is evaluated and retained for later use. The setup argument is then obtained through a **separate evaluation of the global root reference**, followed by reading the +4 field of the root supplied by that evaluation.

F-23aadb16b673 receives:

1. The result of U-1.
2. The +4 field obtained through the separate global-root evaluation.

It does **not** receive a field established by the representation as coming from the retained root.

The two root evaluations may be identified with the same object only under an additional stability assumption. No such assumption is supplied. This distinction concerns the represented evaluations; it does not guarantee a particular number of physical machine-memory loads.

After F-23aadb16b673 returns, the collection head is read from +8 of the **retained root**. Accordingly:

- Setup can affect the initial traversal head if it modifies that retained object.
- A change to the global root reference does not by itself redirect traversal.
- The retained object is not snapshotted; its fields can still change.
- No explicit dependency call appears between retaining the root and evaluating the setup field, but that does not establish a synchronization or root-stability guarantee.

### 3. Derive each candidate

For every non-null current entry, the function performs the following dependency calls and copies in order:

1. F-927372e9397c receives an intermediate output-region address, the capture-storage address, and the address at entry offset +8.
2. F-927372e9397c receives a second output-region address, the address at entry offset +16, and the intermediate-region address.
3. Both words of the second output are copied into candidate storage.
4. F-04f46bd4cf22 receives threshold-output storage and the current value of the separate global 32-bit scalar.

The operand positions differ between the two transformation calls. No addition, subtraction, commutativity, normalization, or unit interpretation is established.

The scalar used for threshold production is evaluated separately for each entry, after that entry’s transformation calls and candidate copy. It is not captured once before traversal.

The threshold dependency may have additional effects. In particular, previously exposed storage and globals cannot be assumed unchanged merely because they are not explicit inputs to this call.

### 4. Apply the threshold filter

The filter compares candidate and threshold words using unsigned first-word and signed second-word interpretations.

A candidate passes exactly when:

- Its first word is unsigned-less-than the threshold’s first word; or
- The first words are equal and its second word is signed-less-than-or-equal to the threshold’s second word.

Thus:

- A smaller first word passes regardless of the second word.
- A larger first word fails regardless of the second word.
- Equal first words defer to the signed secondary comparison.
- Equality of both words passes.

This is a mixed-signedness lexicographic test, not an established unsigned 64-bit comparison.

### 5. Handle a passing candidate

For a passing candidate, F-6489aed099b0 receives the candidate address and selected-value address. Its signed 32-bit result is tested against the exact value one.

If the result equals one:

- The function performs no explicit copy into selected-value storage.
- The function does not set the selection flag during this iteration.

For every other result:

- The selection flag is set.
- The candidate’s first word is copied into the selected first word.
- The candidate’s second word is copied into the selected second word.

The copies occur after the dependency returns. Consequently, they use candidate contents available after that call, not necessarily the candidate contents previously tested against the threshold.

Both argument regions are exposed to the dependency. Even when it returns one, preservation of selected-value storage is not established. The flag controls whether final operations occur; it is not a guarantee that selected storage remained untouched.

Once set, the flag is never explicitly cleared.

### 6. Handle a failing candidate

For a candidate that fails the filter, F-04f46bd4cf22 is called again, with candidate storage as output and the 32-bit value one as input.

This branch does not invoke F-6489aed099b0, set the flag, or explicitly copy candidate storage into selected storage.

The replacement candidate is not subsequently consumed by the visible selection logic for that entry. The call nevertheless remains required observable behavior because its other effects are unknown.

### 7. Follow the link

After the entry’s processing finishes, its next pointer is read from offset +0.

The link is not prefetched before the transformation, conversion, or comparison calls. A dependency-induced change to the current entry’s link can therefore affect the next entry visited, subject to the execution environment’s memory semantics.

Traversal ends when the current pointer is null.

### 8. Perform conditional final operations

If the selection flag is clear, both final operations are skipped.

If it is set, the sequence is:

1. Call U-1.
2. Read the current +4 field of the retained root.
3. Call F-aa02b30efe51 with that accessor result, that field value, and selected-value storage.
4. Call U-1 again.
5. Read the +4 field of the retained root again.
6. Call F-8becc2a0337c with the second accessor result and the newly read field value.

The accessor results need not match. The two field values need not match. The field used here belongs to the retained root, not necessarily the root used for the setup argument.

The second final operation follows return from the first; no success result is tested.

### 9. Finalize on normal completion

F-ec22bd8215d3 receives the temporary-object address after traversal and any conditional final operations.

It runs on both ordinary selection and ordinary no-selection paths. The evidence does not establish finalization after a fault, exception, nonreturning dependency, or nonterminating traversal.

## Acceptance examples

These are conditional expectations, not executed tests.

### Separate setup and retained roots

If the retained-root evaluation yields object A and the separate setup evaluation yields object B:

- F-23aadb16b673 receives B’s +4 field.
- The initial collection head is subsequently read from A’s +8 field.
- Conditional final operations use A’s +4 field.

This example does not assert that differing evaluations occur in a particular runtime. It identifies behavior without assuming equality or a physical load count.

### Empty collection

If the retained root’s head is null after setup returns, no per-entry transformation, threshold production, or candidate comparison occurs. Both final operations are skipped. Construction, capture, the setup accessor and setup operation, and normal finalization still occur.

### Equal first words

If the values present at the filter are candidate `(10, −1)` and threshold `(10, 0)`, the candidate passes. The second comparison is signed.

Candidate `(10, 1)` fails against that threshold. Exact equality passes.

### Unsigned primary ordering

Candidate first word `0xffffffff` fails against threshold first word `0x7fffffff`, regardless of the second words.

Candidate first word 9 passes against threshold first word 10, regardless of the second words.

### Exact comparison result

Assuming F-6489aed099b0 preserves both argument regions:

- Result one leaves the flag and selected value explicitly unchanged.
- Results zero, two, and negative one each set the flag and copy the candidate.

If every passing candidate returns one and no explicit selection occurs, final operations are skipped.

### Mutation during comparison

If a passing candidate’s comparison call changes candidate storage and returns a value other than one, the changed candidate words are copied. The function does not repeat the threshold test after that mutation.

### Failed filter after selection

If an earlier entry sets the flag and a later entry fails its filter, the later entry still invokes F-04f46bd4cf22 with input one. It does not clear the flag. Final operations remain enabled if traversal completes normally.

### Mutation of the current link

If a dependency changes the current entry’s next pointer before the end-of-iteration read, traversal uses the pointer supplied by that later read, subject to memory semantics. An implementation that unconditionally follows a link cached before processing would not preserve this behavior.
