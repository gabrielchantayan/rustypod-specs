# F-186f2ae037a6

## Purpose

F-186f2ae037a6 receives a 20-byte message and conditionally updates indexed records, shared comparison state, and indirect notification targets.

The initial operation byte selects one of four paths:

- **0–5:** compare against shared state; if not suppressed, update metadata and shared comparison state, then notify.
- **7:** set a shared flag, then write a secondary record marker.
- **8:** clear shared state, write a secondary marker, notify using existing record fields, then invoke a record operation.
- **All other values:** update metadata and a secondary marker, then optionally notify or query a record.

These are initial dispatch groups, not guarantees that subsequent reads observe the same operation or index. The temporary message can alias other accessed storage, and dependencies may retain its address and mutate it during later calls.

“Duplicate suppression,” “metadata,” and “notification” describe inferred roles. Application meanings are not established.

## Interface

### Arguments and return

The represented execution model uses 32-bit arguments and addresses.

| Argument | Established use |
|---|---|
| 1 | Address-like value 64 bytes beyond the owner base |
| 2 | Must be zero for processing |
| 3 | Must be zero for processing |
| 4 | Opaque argument forwarded to F-000000000001 |
| 5 | Must equal 20 for processing |

The owner base, **B**, is argument 1 minus 64 bytes. Address derivation alone is not a memory access.

If arguments 2 or 3 are nonzero, or argument 5 is not 20, processing returns without a dependency call or explicit memory write. No meaningful return value or status is established.

### Temporary message

An admitted call gives F-000000000001 a temporary 20-byte destination, argument 4, and size 20. No transfer status is inspected.

| Offset | Width | Interpretation |
|---|---:|---|
| 0 | 8 bits | Unsigned operation |
| 1–3 | 24 bits | Not directly interpreted |
| 4 | 32 bits | Unsigned category |
| 8 | 32 bits | Signed index |
| 12 | 32 bits | Payload |
| 16 | 32 bits | Comparison or metadata value |

The category filter accepts **0–21 inclusive and 100**. Other unsigned values cause return after transfer and after capture of the shared pointer.

The destination is not established as immutable or private after transfer. Its address has been supplied to a dependency. Later reads of its fields must use their then-current contents unless a value has explicitly been captured.

Byte order is not independently established.

### Owner and record layout

For an index **i**, define the record address:

**R(i) = B + 72 + 28 × i**

This notation describes address selection, not a bounds check or a permanently selected record.

| Record offset | Width | Role |
|---|---:|---|
| 0 | 32 bits | Operation-table pointer |

| Shared offset | Width | Role |

No explicit null, bounds, allocation-size, or arithmetic-overflow checks are present.

### Captures versus fresh reads

The function captures:

- The owner base.
- The shared pointer immediately after transfer, designated **S**.
- An initial record address, **R₀**, calculated from the index after category acceptance and before dispatch.
- The low category byte at that same stage, designated **C**.

R₀ is used as the receiver of the record operations. Most record field accesses instead calculate their address from a fresh read of the temporary index. They do not necessarily address R₀.

C remains the category used in metadata writes even if the temporary category subsequently changes.

## Behavior

### Admission and initial reads

The established sequence is:

1. Apply the argument gate.
2. Invoke F-000000000001.
3. Read the global shared pointer and capture S.
4. Read and validate the temporary category.
5. Calculate R₀ and capture C.
6. Read the temporary operation for initial dispatch.

Transfer may alter globals, owner contents, operation tables, tokens, or other storage before these reads occur. Capturing S does not itself access the pointed-to bytes.

Category validation is not repeated. Subsequent changes to the temporary category do not cause rejection.

Unless expressly captured, message fields and global-pointer values are read again where used. Within an individual expression, relative ordering of operand reads is not fully established; the ordered writes and separate captures below do not establish an additional operand-evaluation order.

### Initial operations 0–5: comparison

The comparison accesses shared storage through the global pointer location, not necessarily through S:

1. Read shared byte 0.
2. If it is nonzero, read the temporary operation and the shared comparison-operation byte.
3. If those operations match, read the shared 32-bit comparison value, then the temporary value.
4. Return if both comparisons match.

A zero flag avoids the remaining comparisons. An operation mismatch avoids the value comparison.

Suppression does not compare category, index, or payload. On suppression, no subsequent explicit record write, shared write, or notification occurs.

The global pointer is not established as a single captured pointer for this comparison sequence. Its accesses must not be equated with S without an additional stability assumption.

### Initial operations 0–5: unsuppressed update

The following stores occur in order. Each record address uses the temporary index read for that access:

1. Write the current temporary operation to the primary marker.
2. Write C to the category byte.
3. Write the current temporary payload to the payload field.
4. Write the current temporary value to the value field.
5. Write the current temporary index to the full-index field.
6. Write the packed combination of C and the current temporary index.
7. Read a record value field using the then-current temporary index, and write that value as 32 bits to S + 8.
8. Invoke F-000000000002 with the owner and the operations-0–5 token.
9. After the call returns, read the temporary operation again and write it to S + 1.

Only two explicit arguments are established for this notification.

The notification target and token are obtained for the call after the S + 8 write. Their relative read order within the call expression is unresolved.

The final comparison-operation write is not necessarily the originally dispatched operation. Notification may mutate the escaped transfer destination. Changing the global pointer alone does not redirect this final write: its destination remains S + 1.

No secondary-marker or shared-flag write is explicit on this path. Aliasing can nevertheless change those locations.

### Initial operation 7

The function:

1. Writes 1 to shared byte 0 through the global pointer location.
2. Writes the current temporary operation to the secondary marker selected using the current temporary index.
3. Returns.

The marker is therefore **7 only if the operation remains 7 until its read**. The shared write can itself change the temporary message.

There is no explicit metadata refresh or notification on this path.

### Initial operation 8

The ordered actions are:

1. Write zero to shared byte 0 through the global pointer location.
2. Write zero separately to S + 8, S + 9, S + 10, and S + 11, in that order.
3. Write 15 to S + 1.
4. Read and capture the operation-8 notification token.
5. Write the current temporary operation to the secondary marker selected using the current temporary index.
6. Invoke F-000000000002 with the owner, captured token, a record packed field, and a record value field.
7. After notification returns, resolve the record operation-table entry at byte offset 44 through R₀ and invoke F-000000000004 with R₀.

The marker is not unconditionally 8. The preceding shared writes can change both the temporary operation and index.

Both notification record fields use the temporary index as read for their respective accesses after the marker write. They are not unconditionally fields of R₀. The owner target and these argument reads have no further established relative order within the call expression.

The captured token survives a subsequent aliasing marker write to token storage. The four clearing writes are individual byte writes, not an established atomic 32-bit reset.

The final record receiver remains R₀ even if shared writes or notification change the temporary index. Its operation target is resolved only after notification returns. Continued validity of R₀ is a precondition for that access, not a dependency guarantee.

### All other initial operations

This path performs these stores in order, using a fresh temporary-index read for each record address:

1. Category byte receives C.
2. Payload receives the current temporary payload.
3. Value receives the current temporary value.
4. Full-index field receives the current temporary index.
5. Packed field receives C combined with the current temporary index.
6. Secondary marker receives the current temporary operation.

It then reads the temporary operation again for a **second dispatch**. This selector can differ from the initial selector because preceding writes may alias the message.

For second-dispatch operations **6, 9, 10, and 11**, the sequence is:

1. Read and capture a record value using the current temporary index.
2. Read and capture a record packed field using the current temporary index.
3. Resolve the owner notification target.
4. Read the token associated with the second-dispatch operation.
5. Invoke that target with owner, token, packed field, and value.

For second-dispatch operation **14**, the sequence is:

1. Resolve the record operation-table entry at byte offset 40 through R₀.
2. Invoke F-000000000003 with R₀ and capture its 32-bit result.
3. Read a record packed field using the temporary index **after the query returns**.
4. Resolve the owner notification target.
5. Read the operation-14 token.
6. Notify with owner, token, packed field, and query result.

The query receiver and the record supplying the later packed field can differ. In particular, F-000000000003 may mutate the temporary index through a retained transfer-destination pointer.

All other second-dispatch values return without notification. This includes 0–5, 7, 8, 12, 13, and 15–255. A second-dispatch value of 7 or 8 does not enter the initial operation-7 or operation-8 path.

### Packed arithmetic

For ordinary indices where the represented signed arithmetic is valid, the packed field combines C with the index shifted left 16 bits.

Every accepted category is below 128, so extending C introduces no high set bits. Under a 32-bit bit-vector interpretation, the packed field contains C in its low byte and the index’s low 16 bits in its upper half. The separate index field can retain all 32 bits.

Negative indices, overflowing signed shifts, and overflowing address calculations lack a fully established language-level contract. No wraparound safety guarantee is implied.

## Side effects

Explicit stores affect selected record locations and shared storage. F-000000000001 receives the temporary destination; its actual writes and other effects are unknown.

The temporary message must be included in the aliasing model alongside records, owner storage, shared storage, token storage, and the global-pointer location. No pair of these regions is proven disjoint.

Consequences include:

- An earlier record store may change the index used by a later store.
- A shared write may change the operation or index before a marker write.
- Metadata writes may change the second-dispatch selector.
- A dependency retaining the transfer destination may change fields read after it returns.
- Token or table storage may be modified before its later read.

The function contains no explicit allocation, release, ownership transfer, reference-count adjustment, synchronization, rollback, or error reporting. This does not constrain dependencies.

Safe completion requires valid addresses, initialized fields when read, writable destinations, callable targets, and continued validity of captured addresses through their last use. If a dependency releases storage that is subsequently accessed, the function contains no explicit protection.

Retention permissions, temporary lifetime guarantees, concurrent-access rules, and fault behavior are not established. Earlier effects are not explicitly undone when later execution fails or does not return.

## Acceptance examples

These are conditional static examples, not executed tests. Except where stated otherwise, assume valid disjoint storage, stable message contents after transfer, no concurrent mutation, and normally returning dependencies that preserve subsequently accessed storage. These assumptions are example premises, not established dependency contracts.

1. **Argument rejection.** Argument 3 nonzero prevents transfer and all subsequent processing.

2. **Category boundaries.** Categories 21 and 100 pass. Categories 22, 101, and `0xFFFFFFFF` return after transfer and shared-pointer capture. Transfer effects are not undone.

3. **Cross-record suppression.** If comparison reads observe nonzero flag, operation 3, and value 900, a message whose compared operation and value are 3 and 900 is suppressed regardless of category, index, or payload.

4. **Disabled comparison.** A zero flag bypasses comparison-operation and comparison-value reads. Matching stored comparison values do not suppress the message.

5. **Packed representation.** With stable index 2 and accepted category 100, a metadata-writing path stores packed value `0x00020064` and full index 2.

6. **Ordinary operation 7.** With stable operation and index, operation 7 writes shared flag 1 and secondary marker 7 without explicitly refreshing metadata.

7. **Operation-7 message alias.** Suppose transfer makes the global shared pointer designate the temporary destination. With other storage disjoint and index unchanged, the flag write changes temporary byte 0 from 7 to 1. The subsequent secondary-marker write stores **1**, not 7.

8. **Operation-8 message alias.** Suppose S and the global shared pointer both designate the temporary destination, whose initial operation is 8 and index is valid nonzero k. With other storage disjoint, the shared writes change the operation to 0 and index to 0. The marker write stores 0 in record 0; notification reads record 0’s fields. The final record operation still receives the previously captured R(k).

9. **Operation-8 token capture.** If the token read yields T, a later marker write changing that token’s storage does not change the notification token T, provided execution remains valid.

10. **Post-notification operation mutation.** On an unsuppressed initial operation-3 path, suppose notification changes temporary operation byte 0 to 9 through a retained destination pointer. The final write to S + 1 stores **9**. Merely redirecting the global shared pointer does not redirect that destination.

11. **Query changes selected record.** Suppose the initial index is k and the second selector is 14. If the query receives R(k), returns Q, and changes the temporary index to valid j, the later packed-field read selects R(j). Notification uses Q and the packed value read there, not necessarily R(k)’s packed value.

12. **Second dispatch changes.** If an earlier metadata store changes the temporary operation from 12 to 6, the secondary marker and second dispatch can observe 6. Under otherwise stable valid conditions, the operation-6 notification occurs despite the initial selector being 12.
