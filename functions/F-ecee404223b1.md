# F-ecee404223b1

## Purpose

On normal completion, it returns the component initializer’s result minus `0xE0`. It does not necessarily return the incoming destination or the base initializer’s result.

The constructor-like role, descriptor interpretation, coordinate interpretation, and resource-attachment interpretation are inferred intent. The established behavior is the ordered calls, memory accesses, constants, and address calculations described below.

## Behavior

### 1. Capture the default pointer and select the descriptor

The function first reads the default-descriptor global and retains the resulting address as the captured default descriptor. This read occurs even when an explicit, non-null Descriptor is supplied.

If Descriptor is non-null, it becomes the effective descriptor. The function performs neither preliminary Destination write.

If Descriptor is null, the function performs these operations:

1. Reads the default-descriptor global again, obtaining the reloaded default descriptor.
2. Reads the first 32-bit word through that reloaded address.
3. Reads the Default destination marker and writes it at Destination plus `0x9A4`.
4. Writes the previously obtained descriptor word at Destination plus `0x00`.
5. Selects the captured default descriptor—not the reloaded address—as the effective descriptor.

The initial capture and the later reload are distinct global-pointer reads. Without a stability assumption, they need not produce the same address. Consequently, the descriptor supplying the preliminary Destination word need not be the descriptor used after base initialization.

The preliminary descriptor-word read precedes both Destination writes. The write at `0x9A4` precedes the write at `0x00`. This stage does not explicitly write Destination’s second word.

### 2. Invoke base initialization

The function calls F-60d99bc349ed with these arguments, in order:

2. Argument 3;
3. Argument 4;
4. Argument 5;
5. Argument 6.

Its result becomes B.

The effective descriptor’s first and second words used for subsequent initialization are read after this call. The function does not snapshot both words before calling the dependency.

On the default path, the dependency may change the contents at the captured descriptor address before those reads. Changing the default-descriptor global alone does not replace the already selected effective descriptor.

### 3. Install markers and descriptor-derived state

After base initialization returns, the following statement-level sequence is established:

1. Read the Intermediate marker and write it as a 32-bit word at B plus `0xA4`.
2. Read and retain the Final marker.
3. Read and retain the effective descriptor’s first 32-bit word.
4. Write that descriptor word at B plus `0x00`.
5. Write the retained Final marker at B plus `0xA4`.
6. Perform the descriptor-directed assignment described below.

For that assignment, the function obtains:

- A 32-bit displacement from twelve bytes before the address encoded by the retained first descriptor word.
- The effective descriptor’s second 32-bit word, at descriptor offset `0x04`.

It writes the second word to B plus the displacement.

**The relative evaluation order of the displacement read and the second-word read is not established by the supplied expression.** Both are operands involved in the same assignment. The contract therefore does not require either read to occur first. Both belong to the descriptor-directed assignment after the Final marker write and before the fixed-field initialization that follows.

The metadata address uses the retained first descriptor word. It is not obtained by rereading that word from the effective descriptor or from B.

The displacement is a byte displacement, not a word index. The represented value is 32 bits, with no visible range, alignment, sign, or overflow check. A negative displacement can designate storage before B when that address calculation and access are valid in the execution environment. Unchecked arithmetic does not establish that overflow or address wraparound is valid.

The Intermediate marker write remains part of the observable write sequence even though the Final marker subsequently targets the same four bytes.

The descriptor-directed destination may overlap earlier or later fields. There is no disjointness check.

## Acceptance examples

These examples are conditional static acceptance criteria, not executed tests.

### Explicit descriptor

Given a valid non-null Descriptor, the function still performs the initial default-descriptor-global read. It omits the reload and both preliminary Destination writes. Reads of the effective descriptor used to initialize B occur after F-60d99bc349ed returns.

### Distinct captured and reloaded default pointers

Suppose the initial global-pointer read yields address A, while the null-path reload yields address C. Assume both addresses and all subsequent accesses are valid.

The preliminary word written to Destination comes from C. The effective descriptor is A. The post-base-initialization descriptor reads therefore use A, not C.

This example does not assert that such a change occurs in any particular execution or that concurrent unsynchronized mutation is valid.

### Descriptor mutation during base initialization

Suppose the effective descriptor’s first word changes while F-60d99bc349ed executes. The later initialization uses the word read after that call, not a preliminary value.

On the default path, this remains true even when the captured and reloaded descriptor pointers happen to be equal.

### No imposed operand-read order

Suppose both the metadata displacement and the descriptor’s second word are valid to read. Acceptance must not require a trace in which one of these two reads precedes the other.

The descriptor-directed write must nevertheless follow the preceding Final marker assignment and precede the subsequent write of zero at B plus `0xAC`.

### Negative displacement

Suppose the metadata displacement represents negative sixteen and the second descriptor word is `0x12345678`.

If the address calculation and four-byte destination at B minus `0x10` are valid, the descriptor-directed assignment writes `0x12345678` there. There is no explicit rejection of a negative displacement.

### Overlap with later initialization

Suppose the descriptor-directed destination is B plus `0xAC`. The second descriptor word is written there first. The next fixed-field initialization overwrites those four bytes with zero.

This conclusion assumes no other alias effects invalidate the stated inputs or accesses.

### Component result differs from its argument

Suppose H differs from B plus `0xE0`. Component-relative writes still use H. F-08381bb55f88 receives H minus `0xE0`, and that same calculated value is returned.

### Byte-width preservation

With valid independent storage and no overlapping writes or dependency modifications, the write at H plus `0x8C0` changes only one byte. It does not directly clear the adjacent three bytes.
