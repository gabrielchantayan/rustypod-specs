# F-82594ed9ba4b

## Purpose

F-82594ed9ba4b combines a caller-supplied 32-bit word with a second 32-bit word through two ordered calls to F-870c4fcf7295. It conditionally adjusts the second packed result, stores one 32-bit component through the caller’s pointer, and returns a separately composed signed 32-bit value.

The established structure is a split-word calculation followed by adjustment of a negative packed result. A division-like interpretation is plausible, but not established: the dependency’s mathematical contract is unavailable. This specification therefore does not designate any component as a quotient, remainder, or divisor.

All behavior below is derived from static evidence. Conditional word-pattern calculations are distinguished from portable signed-arithmetic guarantees. No runtime tests have been performed.

## Interface

The function receives three arguments:

1. **A pointer to an unsigned 32-bit word.** Its initial contents are read once. On normal completion, the function overwrites that location.
2. **An unsigned 32-bit value.**
3. **A signed 32-bit adjustment parameter.** The same value is passed to both dependency calls and participates in the local adjustment loop.

For exposition, **A** denotes the captured pointed-to word, **B** the second argument, and **D** the third argument.

The pointer must support the initial 32-bit read and the final 32-bit write if execution reaches it. The function contains no visible null, alignment, bounds, or accessibility checks. Dependency-specific input restrictions are unknown.

### Outputs

These outputs are separate components. Neither has an established error-code interpretation.

### Widths and packed layout

The visible calculation uses 32-bit signed and unsigned quantities and 64-bit packed dependency results.

For a packed result:

- Its **lower word** comprises bits 0–31.
- Its **upper word** comprises bits 32–63.
- Its sign, when tested as a signed 64-bit value, is determined by bit 31 of the upper word.

For a 32-bit input:

- Its **lower halfword** comprises bits 0–15 and is treated as unsigned.

The logical bit layout does not establish memory byte order or calling-convention details.

Where this contract gives a result modulo \(2^{32}\), it describes a 32-bit word pattern. Some operations have defined unsigned modular semantics; others require the separate signed-arithmetic qualifications in **Uncertainties**.

### Negative-result adjustment

The function extracts Q’s unsigned upper word and tests Q as a signed 64-bit value.

If Q is nonnegative, no adjustment occurs.

If Q is negative, each adjustment replaces its two words independently:

- The upper word is increased by D using unsigned 32-bit arithmetic.
- The lower word is decremented through a signed 32-bit interpretation.
- The two resulting words are reassembled as a packed 64-bit value.
- The upper word is extracted again and the packed sign is tested again.

#### Upper-word arithmetic is defined modulo \(2^{32}\)

The upper-word operand is unsigned 32-bit, while D is signed 32-bit. The usual arithmetic conversions convert D to unsigned 32-bit before addition.

Both that conversion and the resulting unsigned addition have defined modular behavior. For example:

- D equal to −1 contributes the unsigned pattern `0xFFFFFFFF`.
- Adding 1 to upper word `0xFFFFFFFF` yields zero.
- Adding −1 to upper word `0x80000000` yields `0x7FFFFFFF`.

This upper-word addition does **not** introduce signed-overflow uncertainty or an implementation-defined out-of-range signed conversion.

#### Lower-word arithmetic remains qualified

The lower-word update instead uses a signed 32-bit conversion followed by subtraction of one. Its portability is therefore a separate issue. A signed decrement at the minimum signed value can overflow; conversion from the packed signed value to signed 32-bit can also be out of range.

Under the recovered word-pattern model, the lower word decreases modulo \(2^{32}\). This decrement does not borrow from the upper word. The update is not an ordinary 64-bit subtraction or addition.

Writing the initial words as \(H_0\) and \(L_0\), after \(n\) adjustments the word-pattern model is

\[
H_n =
\left(H_0+n(D\bmod 2^{32})\right)\bmod 2^{32},
\]

\[
L_n=(L_0-n)\bmod 2^{32}.
\]

The upper-word recurrence has defined unsigned semantics. The lower-word recurrence is subject to the signed-operation qualifications above.

The loop stops at the first tested state whose upper word has bit 31 clear. An upper word of zero stops the loop regardless of the lower word. No additional dependency calls occur within this loop.
