# F-838218ef65c4

## Purpose

F-838218ef65c4 selects between an attempted result-producing operation, a fallback operation, and a return without either operation. Selection depends on a byte in a caller-supplied object and, on one branch, a 32-bit field in that object.

The established behavior is dispatch and result transfer:

- F-148a31e02bc5 receives an address through which it can replace a selected result pointer. A nonzero dependency result causes this function to copy one selected word to the caller’s output and return the following word.
- F-629f530c5a82 is called only on the selector-2 fallback path. Its return value is returned directly.
- An unsupported selector returns zero without an explicit output write.

Zero is not an unambiguous failure indication. It can result from an unsupported selector, selector-1 failure handling, fallback, or successful extraction of a zero second word.

The domain meaning of the object and its fields is not established. Describing the dependencies as lookups, validators, or allocators would add unsupported semantics.

## Behavior

### Initialization and selector comparisons

The function initializes a local result-pointer slot with the original output address before dispatch.

It first reads the selector byte and compares it with 1. If that comparison fails, it reads the selector byte again and compares it with 2.

For stable selector storage, this produces selector-1, selector-2, and unsupported-selector cases. More generally, the first observation determines whether selector 1 is taken; if it is not, the second observation determines whether selector 2 is taken. The function does not establish a single selector snapshot.

If the first observation is not 1 and the second observation is not 2, the function returns zero. Neither dependency is called, and no explicit write to the original output occurs.

### Selector 1

When the first selector observation equals 1, the function reads the 32-bit field at object offset 4 and calls F-148a31e02bc5 with:

1. The offset-4 field value.
2. Context A.
3. Context B.
4. The address of the local result-pointer slot.

This call occurs even if the offset-4 value is zero.

The dependency result is tested for zero. Any nonzero result selects common result extraction; the status itself is not returned.

If the dependency returns zero, the function writes a 32-bit zero to the original output address and returns zero. It does not dereference the selected result pointer on this path.

The zero write occurs after the dependency returns. Subject to valid memory and completion of that write, it overwrites whatever the dependency left in the original output word. Replacing the selected result pointer does not redirect this write.

There is no selector-1 fallback call.

### Selector 2: separate test and argument reads

Selector 2 is reached only when the first selector comparison fails and the second comparison observes 2.

The function first reads the 32-bit field at offset 24 for a zero test.

- If this first field read observes zero, F-148a31e02bc5 is skipped. There is no second offset-24 read on this path, and fallback follows.
- If this first field read observes nonzero, the function reads the offset-24 field again. This second value supplies the first argument to F-148a31e02bc5.

The dependency’s remaining arguments are Context A, Context B, and the address of the local result-pointer slot.

The first offset-24 observation controls whether the call occurs. The second observation supplies the argument. The second value is not tested again before calling the dependency.

Consequently, the argument can be zero or a different nonzero value if the observed contents change between reads. A zero second observation does not cancel the call or independently select fallback.

For stable storage only, the two observations agree: zero skips the call, while nonzero causes a call with that same nonzero value. No sign-based dispatch is visible; the test distinguishes only zero from nonzero.

After the call:

- A nonzero dependency result selects common result extraction.
- A zero dependency result selects fallback.

### Fallback

Fallback occurs only after entering selector 2, either because the first offset-24 read observed zero or because F-148a31e02bc5 was called and returned zero.

At fallback time, the function reads the 32-bit field at object offset 4 and calls F-629f530c5a82 with:

1. That offset-4 value.
2. Context A.
3. Context B.
4. The original output address.

The dependency’s 32-bit result becomes this function’s return value without further interpretation. This function performs no explicit output write after the fallback call and does not extract words through the selected result pointer.

If fallback follows F-148a31e02bc5, the offset-4 read occurs after that dependency returns. Changes it made to that field can therefore affect the fallback argument. The function does not use a value cached before the earlier call.

Any replacement result pointer left by a zero-returning F-148a31e02bc5 is not used for fallback. The fallback receives the original output address. The wrapper does not clear output before making that call.

### Common result extraction

After a nonzero result from F-148a31e02bc5, the visible extraction order is:

1. Read the first 32-bit word through the selected result address.
2. Write that value to the original output word.
3. Read the second 32-bit word, four bytes after the selected result address.
4. Return the second word.

The output write precedes the second-word read. The function does not snapshot both words before writing.

If the selected result pointer remains unchanged, extraction reads the original output word and writes it back, then reads the word immediately following it for the return value. Thus, an unchanged pointer on a nonzero-status path requires more than a single accessible output word.

If the original output address is the selected second word’s address, the output write replaces that word before its return-value read. For otherwise stable, valid storage, the returned value then equals the selected first word.
