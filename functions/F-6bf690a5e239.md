# F-6bf690a5e239

## Purpose

F-6bf690a5e239 selects a record from a context-referenced table and invokes an indirectly selected handler. If the selected record’s cached word is zero, it first performs a sequence of dependency calls. A failure in that sequence causes further dependency interaction, clears the cache, disables the record, and terminates the invocation without selecting a replacement.

Selection distinguishes three candidate groups. For stable record fields, their precedence depends on record class, mode, and whether a classification’s low ten bits equal 9. Several fields are read repeatedly rather than captured once; changing fields can therefore produce behavior outside the stable-field selection rules.

The result contains a 32-bit handler result and a 32-bit companion word. The companion preserves the requested selector unless the zero-cache preparation path is entered, in which case it is zero.

“Preparation,” “cache,” and “disable” describe visible control flow and storage effects. They do not establish resource type, ownership, or application-level purpose.

- **Bits 0–31:** zero when no handler runs or preparation fails; otherwise the handler’s 32-bit result.

## Behavior

### Traversal and basic eligibility

Traversal proceeds in increasing index order from zero, advancing the record address by 20 bytes per visited entry.

For each record, the selector is read first. Only a selector match permits the eligibility-gate read. Only a matching selector and nonzero gate permit the class read.

The selector comparison uses the full unsigned 32-bit request against a zero-extended unsigned 16-bit record selector. Requests above 65,535 cannot match.

The index is unsigned 32-bit. Its increment clears bit 16, but that masking does not affect an ordinarily reachable traversal index: the unsigned 16-bit count permits visits only through index 65,534. For a stable count of 65,535, exactly indices 0 through 65,534 are visited.

Unrecognized classes contribute no candidate. A zero gate excludes a record regardless of its other fields.

### Candidate accumulation

Three candidates start absent. The rules below describe stable record fields; the subsequent read-order requirements govern changing fields.

**General candidate.** Each eligible class-0 or class-2 record replaces this candidate. The final candidate is the last eligible record in either class.

**Class-1 candidate.** Each eligible class-1 record whose entire classification field is zero replaces this candidate. A nonzero classification does not qualify, even if its low ten bits are zero.

**Class-3 candidate.** A class-3 record must pass both a classification-related replacement condition and a mode condition:

- With no existing class-3 candidate, the replacement condition passes without reading classification at that point.
- With an existing class-3 candidate, the current record’s classification is read before any mode check. Its low ten bits must equal 9; otherwise no mode is read and no replacement occurs.
- The mode condition first reads the mode as unsigned 16-bit and accepts values below 2. Only if that comparison fails does a second mode read test equality with 10.
- After acceptance, classification is read to save whether its low ten bits equal 9. The current index becomes the class-3 candidate.

Thus, with stable fields, the first mode-eligible class-3 record qualifies regardless of classification. Later records replace it only when their low ten classification bits equal 9 and their mode is 0, 1, or 10.

The saved special-classification flag comes from the post-acceptance classification read. Where an existing candidate caused an earlier classification read, the two reads are distinct. A record can pass replacement using one classification value and save the flag using another.

A general candidate cannot displace an available class-1 or class-3 choice. Selection uses the saved class-3 flag, not a fresh classification read.

### Handler-slot reads and target capture

Three separate indirect slots supply the common, class-1, and alternate targets.

For a selected general candidate, the common slot is read. For a selected class-1 candidate, the class-1 slot is read. Neither path performs a final mode check.

For a selected class-3 candidate, the ordering is significant:

- The common-handler slot is read first, before either final mode check.
- The mode is then read and compared as unsigned 16-bit against 1. A value of 0 or 1 retains the captured common target, without a second mode read.
- If that first value exceeds 1, the selected target is cleared. A second mode read then tests equality with 10.
- Only when this second read equals 10 is the alternate-handler slot read and its value selected.

Consequently, the common slot is read even when its value is later discarded. The alternate slot is not read merely because the first mode value exceeds 1; the second mode read must equal 10.

For stable fields, class-3 modes 0 and 1 select the common handler, while mode 10 selects the alternate handler. Changing fields can produce a null target despite earlier class-3 acceptance.

The selected record address and target must both be nonzero before any cache read or preparation. If either check fails, no preparation or handler call occurs, and the return remains zero in the low word with the requested selector in the upper word.

The chosen target is captured before the cache check and all preparation calls. Dispatch uses that captured target, not a later reread of its slot.

## Acceptance examples

These are conditional static expectations, not executed tests. Except where changes are explicitly described, memory, fields, and slots remain stable; required pointers are valid; selected targets are nonzero; and calls return normally.

1. **No selector match.** With requested selector 7 and no matching record, no dependency or handler runs. The low word is zero and the upper word is 7.

2. **Selector width.** Request 65,536 does not match a record selector of zero. No record can match that request; the upper word remains 65,536.

3. **General replacement.** If the only eligible candidates are class 0 followed by class 2, the latter is selected. With a nonzero cache and common-handler result 23, the return words are 23 and the requested selector.

4. **Class-1 precedence.** A class-1 candidate with classification zero defeats a class-3 candidate whose saved special flag is false, regardless of table order.

5. **Special class-3 precedence.** Classification 1,033 has low ten bits equal to 9. A mode-10 class-3 candidate with that classification defeats an available class-1 candidate. The common slot is read and discarded before the alternate slot is read.

6. **Class-3 replacement sequence.** For mode-eligible classifications 4, 5, 9, then 6, the first record initially qualifies, the second does not replace it, the third replaces it, and the fourth does not.

7. **Repeated classification reads.** Suppose a class-3 candidate already exists. A later record is read as classification 9 before its mode checks, passes those checks, and is read as classification 4 afterward. It replaces the candidate but saves a false special flag. An available class-1 candidate consequently wins final resolution.

8. **Repeated final mode reads.** Suppose the selected class-3 record’s final first mode read is 2 and its second is 0. The common slot has already been read, but its target is discarded. The alternate slot is not read, and no cache check or dispatch follows.

9. **Captured target survives slot changes.** Suppose preparation starts after a common target has been captured. A preparation dependency replaces the common slot, but all statuses are zero. Dispatch still uses the earlier captured target, subject to its remaining callable.

10. **Successful preparation with zero cache result.** F-6dd003795db7 returns zero and leaves status zero; both later stages return zero. The handler still runs. Its result supplies the low word, and the upper word is zero.

11. **Immediate preparation failure.** F-6dd003795db7 returns a word and writes nonzero status. The later two stages are skipped. F-bf7242c98d06 receives the current cache; afterward the cache halves and gate are cleared in order. The full return is zero.

12. **No fallback after failure.** Even with other eligible candidates present, failure of the selected record ends this invocation without dispatching another record.
