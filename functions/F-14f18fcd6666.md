# F-14f18fcd6666

## Purpose

The supplied static representation describes an operation dominated by indirect calls and interleaved memory updates. It forwards the second explicit argument to an initial dependency, installs the third explicit argument at two computed locations, updates several 32-bit slots, repeatedly modifies byte-selected locations, and clears both computed slots and the 32-bit location at address `0x24`.

A higher-level purpose—such as initialization, serialization, allocation, or device configuration—is not established. None of those interpretations is part of this contract.

The visible path ends at an instruction-decoding failure. Successful completion, a normal return, and the behavior beyond that boundary are **documented_only unknowns**. This contract describes the visible prefix, conditional on execution reaching each operation.

## Behavior

### Reading this sequence

All stages below are ordered. A later stage is reached only if preceding calls and memory accesses complete and control continues along the displayed path.

An “intervening four-call interval” means four successive indirect calls with no explicit arguments shown, with the fourth result used when stated. Calls whose results appear unused remain observable; they cannot be removed from this contract.

Dependency targets are unresolved. Their unknown behavior means that a later read cannot be replaced with an earlier value merely because the function itself has not visibly changed the relevant memory.

### 1. Initial forwarding and first linked slots

The operation first calls a dependency with the second explicit argument. It then calls another dependency without explicit arguments and forwards that dependency’s 32-bit result to the next call.

After an intervening four-call interval, the last result determines a word address: four times that result, plus `0x14`. The incoming 32-bit register value, logically shifted right by three, is written there. A dependency is then called with four times the same result.

After another four-call interval, its last result determines two different scaled quantities:

- A word slot at sixteen times the result, plus `0x14`.
- A stored value equal to four times the result.

The scaled value is written to that slot. Next, the function reads a 32-bit word at the scaled value plus `0x14`, logically shifts the read value right by three, and passes the shifted value to a dependency.

After another four-call interval, the function writes the previously retained scaled value to a word slot at four times the latest result, plus `0x14`. It then calls a dependency with four times that latest result.

The factor-of-four and factor-of-sixteen layouts are distinct. The evidence does not justify merging them into one record layout.

### 2. Establishing the principal retained values

After another four-call interval, the final result is treated as an unsigned 32-bit value. For the remainder of this description, it is the **principal value**.

Before the next call, the third explicit argument is written to the address formed from the separate incoming register value multiplied by `0x80000`, plus `0x24`.

Three quantities are then retained:

- The **principal base**: sixteen times the principal value.
- The **reduced value**: the principal value masked with `0x3FFFFFFF`, then logically shifted right by one.
- The principal value itself.

A dependency is called with the principal base and the principal value shifted left by two.

Following four more calls, the third explicit argument is written at principal base plus `0x24`. The function then reads the word at principal base plus `0x74` and passes it to a dependency.

The two argument stores are separate operations at independently derived addresses. They may alias, but equality is not established.

### 3. First byte-selected updates

After four further calls, the final 32-bit result is retained for later shift arguments.

The function reads one unsigned byte at principal base plus one. That byte is used directly as an address base, without multiplication or a further pointer load. At that byte value plus `0x11`, it stores the low eight bits of the principal value masked with `0x3FFFFFFF` and shifted right by twenty.

A dependency is called with the retained call result shifted left by two. Another dependency produces a 32-bit value, which is forwarded to the next dependency.

After four more calls:

1. The byte at principal base plus one is read again.
2. Zero is stored at the newly selected byte address plus `0x11`.
3. A dependency receives the latest call result shifted left by two.

The second selector read is not constrained to equal the first. Calls between them may modify the selector or its surrounding memory.

### 4. Reduced-value byte clearing and shift arguments

After four further calls, the function:

1. Stores a zero byte at reduced value plus `0x0F`.
2. Forms the **intermediate base** as reduced value multiplied by `0x400`.
3. Reads the byte at intermediate base plus one.
4. Stores zero at that byte value plus `0x11`.

The earlier retained call result supplies a four-argument dependency call: its value shifted left by twenty-three is passed three times, followed by its value shifted left by twenty-five.

A producer call follows, and its 32-bit result is forwarded to another dependency.

After four more calls, the byte at intermediate base plus one is read again and retained. Zero is written at that retained byte plus `0x11`. A dependency receives the latest call result shifted left by two.

After another four-call interval, a zero word is written at the retained byte plus `0x44`. A zero word is then written at absolute address `0x24`.

The retained selector is an 8-bit value. Consequently, this particular word destination ranges from `0x44` through `0x143`, before any architectural access restrictions.

### 5. Repeated word clearing

A dependency receives four explicit arguments: zero, `0x98`, the intermediate base, and `0x98`.

The next producer result is forwarded to a dependency. Another producer result is then forwarded to another dependency. Following four further calls, the operation:

1. Writes a zero word at four times the latest result, plus `0x44`.
2. Writes a zero word at absolute address `0x24`.
3. Calls a dependency with four times that result.

After four further calls, the last result is represented as 64 bits. Its halves have separate uses:

- The low 32 bits, shifted left by two, are passed to a dependency.
- After that call, a zero word is written at twice the high 32 bits, plus `0x44`.
- A zero word is then written at absolute address `0x24`.

A secondary register output associated with the intervening call supplies another invocation’s arguments: zero, that register output, and that output shifted left by two. Its meaning and validity are unknown.

After one further no-explicit-argument call, a dependency receives the reduced value masked with `0x3FFFFF` and shifted left by seven. Denote this derived quantity as the **packed value**.

After four more calls, the function clears a word at four times the latest result plus `0x44`, then clears the word at address `0x24`, then calls a dependency with four times that result.

There are four explicit zero-word stores to address `0x24` across this stage and the preceding stage. Intervening dependencies may change that location between stores.

### 6. Clearing and rebuilding slots at offset `0x14`

A dependency is then invoked with that result repeated in its first three explicit argument positions and the packed value in the fourth.

After four further calls, another word at four times the latest result plus `0x14` is cleared. A dependency receives four times that result.

Following another four-call interval, the function writes four times its final result to a word slot at sixteen times that result plus `0x14`. It passes the stored scaled value to a dependency.

After another four calls, that retained scaled value is written to a word slot at four times the latest result plus `0x14`. A dependency then receives four times the latest result.

After another four calls, the function again writes four times the latest result to a word slot at sixteen times that result plus `0x14`. A dependency receives both scaled forms: four times the result and sixteen times the result.

### 7. Installing the packed value

After four more calls, the packed value is written to a word slot at four times the latest result plus `0x14`. A dependency receives four times that result.

After another four-call interval, the final result becomes a new retained unsigned 32-bit value. The function forms the **late selector base** by multiplying the reduced value by `0x4000000`.

It reads the byte at late selector base plus one and stores the low eight bits of the new retained result shifted left by two at the selected byte address plus `0x11`. A dependency receives the same result shifted left by two.

### 8. Final byte updates and visible endpoint

A producer result is forwarded to a dependency. After four more calls, the selector byte at late selector base plus one is read again. The selected destination receives the low eight bits of the retained unsigned result masked with `0x3FFFFFFF` and shifted right by twenty.

A dependency receives the latest call result shifted left by two.

After four further calls, the final result replaces the retained unsigned value. The selector at late selector base plus one is read once more and retained. At that selector plus `0x11`, the function stores the low eight bits of the new retained value multiplied by four. The next dependency receives the zero-extended selector byte itself—not its shifted form and not the destination address.

A producer result is forwarded to another dependency. After four additional calls, the function reads a byte at eight times the retained unsigned value plus one. At that byte value plus `0x11`, it stores the low eight bits of the retained value masked with `0x3FFFFFFF` and shifted right by twenty.

A dependency receives the latest call result shifted left by two. Four further calls are visible. The supplied representation then terminates at an invalid-instruction boundary.

## Acceptance examples

These are conditional static acceptance examples, not executed tests.

1. **Initial shift:** If the incoming unsigned register value is `0xFFFFFFFF`, the first direct word store contains `0x1FFFFFFF`, provided its destination is accessible and execution reaches it.

2. **Third-argument preservation:** If the third explicit argument is `0x89ABCDEF`, each of its two direct stores writes that exact 32-bit pattern. Later dependencies may overwrite either destination.

3. **Selector width:** If a selector read returns `0xFF`, the corresponding byte destination is address `0x110`. The selector is not sign-extended.

4. **Selector rereading:** If a dependency changes the byte at principal base plus one between the initial field store and the later zero store, the later store uses the changed selector.

5. **Field truncation:** If a masked right-shift-by-twenty expression produces `0x3FF`, its byte store writes `0xFF`. The mask and shift do not restrict the intermediate result to eight bits.

6. **Low-bit byte multiplication:** If a late retained result has low byte `0xC1`, its multiply-by-four byte store writes `0x04`.

7. **Packed value:** If the reduced value is `0x00400001`, masking with `0x3FFFFF` leaves one. The packed value is therefore `0x80`, and the corresponding shift-by-four argument is `0x10`.

8. **Repeated absolute clearing:** If a dependency writes a nonzero word at address `0x24` between two explicit clears, the next reached clear writes zero again. The earlier clear does not make the later one redundant.

9. **Inaccessible destination:** If a computed destination cannot be written, the visible representation supplies no recovery behavior or guarantee that later operations occur.

10. **Completion boundary:** Reaching the final visible calls does not establish a successful return.
