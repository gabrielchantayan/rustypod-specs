# F-df700ce24369

## Purpose

F-df700ce24369 obtains an event-bearing wrapper, conditionally updates three 32-bit fields in an associated state object, and sends every nonempty event through a downstream processing sequence. Both empty and nonempty events reach a common exit check that may invoke a global indirect target.

“Event,” “wrapper,” “enqueue-like,” and “notification-like” are inferred roles. The established contract consists of the visible accesses, comparisons, writes, and calls. The evidence does not establish allocation success, ownership transfer, synchronization, or asynchronous execution.

Dispatch depends on **two ordered accesses to a threshold global**, not one captured threshold value. The second access occurs only if equality against the first observation fails. Consequently, the final dispatch branch is not unconditionally a greater-than branch.

## Interface

### Input and result

The function accepts one 32-bit address-bearing input. At byte offset +4 of the input object, it reads a 32-bit address identifying the state object.

The function has no established return value. There is no explicit validation, error result, or recovery path.

## Behavior

### 1. Construct the initial wrapper and capture the state address

The function calls F-0a77364c41cc with 12. It passes the returned value, the first opaque global descriptor, and zero to F-afb630a7107c. The latter result is treated as the wrapper address.

Only after these calls does the function read the state-object address from input offset +4. Earlier dependencies therefore must not be assumed to preserve the input storage before this read.

The function next calls F-338d16f9ce72 with the address of state offset +0x10C. It then reads the event address from wrapper offset +8.

Subsequent work uses the captured state-object address. No later reread of the input’s state-address field is shown.

### 2. Handle an empty event

If the event address is zero, the function checks whether the wrapper address is nonzero. For a nonzero wrapper, it reads the wrapper’s dispatch-table address and invokes the table target at byte offset +4, passing the wrapper address.

It then proceeds to the common exit check.

The indirect operation resembles release or destruction, but its ownership effect is unknown. The wrapper-address check occurs after the wrapper has already been dereferenced; it does not provide safe null-wrapper handling.

This path skips discriminator dispatch and the entire nonempty-event downstream sequence. Dependencies already called, the wrapper-table target, and the common exit target may still have side effects.

### 3. Route a nonempty event using ordered threshold observations

For a nonzero event address, the function reads the signed 32-bit discriminator at event offset +4. That discriminator is retained for the subsequent comparisons.

Routing proceeds as follows:

1. Access the threshold global and compare the discriminator for equality with that first observation.
2. If equal, select the equality action. There is no second threshold access on this path.
3. If unequal, access the threshold global again and compare the discriminator with that second observation using signed less-than.
4. If the second comparison succeeds, select the less-than action group.
5. Otherwise, select the residual action group.

The less-than group therefore requires both inequality against the first observation and signed less-than against the second.

The residual group requires inequality against the first observation and signed greater-than-or-equal against the second. **Only if both threshold accesses observe the same value is this necessarily a strict greater-than group.** If the observations differ, a discriminator equal to the second observation can enter the residual group. No equality action is retried against that second observation.

Numeric-code recognition occurs only within the selected group. A code associated with another group does not receive that other group’s action.

### 4. Equality action

Equality against the first threshold observation causes a 32-bit write of 1 to the first state field at +0x140.

This action performs no direct write to the second state field or payload field.

### 5. Less-than action group

This group recognizes the following discriminator values:

| Discriminator | Direct action |
|---|---|
| 0x6600000D | Clear the second field, then clear the first |
| 0x66000014 | Query the second field if it is −1, then increment it |
| 0x66000015 | Query the second field if it is −1, then conditionally decrement it |
| 0x66000017 | Clear the second field, then clear the first |

Other discriminators in this group cause no direct dispatch-field write.

For either reset code, the write of zero to state offset +0x144 precedes the write of zero to +0x140.

For 0x66000014, the function first reads the second field. If it is −1, it calls F-87be4aa684d1, reads the returned object’s dispatch table, and invokes the target at table offset +0x16C. No explicit arguments to that target are shown. The 32-bit query result is stored in the second field.

Whether or not a query occurred, the function then reads the second field and writes its value plus one back to that field. Thus a query result is stored before the increment result. There is no upper-bound check or clamp.

For 0x66000015, the same sentinel check, query, and intermediate store apply. The function then reads the second field for a signed-positive test. If positive, it reads the field again, subtracts one, and stores the result. Otherwise, it performs no decrement write.

The positivity-test read and subtraction-source read are distinct in the supplied representation. Their values must not be assumed identical under unspecified concurrent mutation. With stable storage, zero and negative values are not decremented.

A query result of −1 is not queried again during the same action. Other negative query results are not normalized.

### 6. Residual action group

This group is selected when equality against the first threshold observation fails and signed less-than against the second observation also fails.

| Discriminator | Direct action |
|---|---|
| 0x6600001A | Write zero to the first field |
| 0x6600001B | Conditionally exchange first-field values 1 and 2 |
| 0x66000024 | Copy an indirectly referenced payload word into the payload field |

Other discriminators in this group cause no direct dispatch-field write.

For 0x6600001B, the function reads the first field. If it is −1, it calls F-87be4aa684d1 and invokes the returned object’s table target at byte offset +0x18C, with no explicit arguments shown. The returned value becomes the effective value for the decision; it is not unconditionally stored.

An effective value of 1 causes a write of 2. An effective value of 2 causes a write of 1. Every other effective value causes no direct write.

Consequently, an initial −1 followed by a query result of 9 does not itself cause either 9 or another replacement value to be stored. Dependencies may independently modify the field.

For 0x66000024, the function reads the address at event offset +12, reads the 32-bit word at that address, and writes that word to state offset +0x148. It copies the pointed-to word, not the pointer.

No direct initialization of the first word of the 8-byte object is shown.

The original wrapper is not directly released on this path. Passing its address inside the new object is consistent with a handoff, but does not establish ownership transfer or eventual release.

### 8. Perform the common exit check

The function reads an address from state offset +0x10C after the preceding path-specific calls.

If that address is zero, it returns. Otherwise, it reads the first 32-bit word at the referenced address. A zero word also causes return.

If both are nonzero, the function invokes the target supplied by separate global storage, with no explicit arguments shown. It returns if that target returns.

The referenced object’s first word is a condition, not the call target. The check uses late reads; it is not a cached observation from before the earlier dependencies.

### Integer boundaries

Field operations are 32-bit. Threshold ordering, state sentinel comparisons, and the decrement positivity test use signed interpretations.

For stable second-field values below 2,147,483,647, increment produces the ordinary value one greater. At the signed maximum, there is no explicit overflow guard. Exact overflow behavior remains documented_only without stronger instruction-level evidence.

With stable storage, decrement is selected only for positive signed values and cannot underflow. If storage changes between the positivity test and the subtraction-source read, that bound is not established.

## Acceptance examples

These are conditional static expectations, not executed tests. Unless an example specifies differing observations, assume valid storage, returning dependencies, stable threshold observations, and no intervening mutation affecting the stated results.

1. **Empty event.** A valid wrapper contains a zero event address. Its table target at +4 is called with the wrapper. No threshold access or 8-byte downstream request occurs. The common exit check still occurs.

2. **Equality precedence and access count.** The discriminator and first threshold observation are both 0x66000014. The function writes 1 to the first field, performs no second threshold access, and does not take the increment action.

3. **Stable-threshold reset.** Both threshold observations exceed 0x6600000D. That discriminator clears the second field before the first, then takes the full downstream sequence.

4. **Changed threshold selects less-than.** The discriminator is 0x66000014. The first threshold observation is 0x66000013 and the second is 0x66000015. Equality fails, signed less-than succeeds, and the increment action is selected despite the discriminator exceeding the first observation.

5. **Equality only on the second access.** The discriminator is 0x6600001B. The first threshold observation is 0x6600001A and the second is 0x6600001B. The residual group is selected. A stable first-field value of 1 becomes 2; the equality action does not run.

6. **Stable-threshold residual routing.** Both threshold observations are below 0x6600001B. For that discriminator, effective first-field values 1 and 2 become 2 and 1 respectively.

7. **Increment after query.** The increment action sees −1 and queries 7. It stores 7, then reads and stores 8.

8. **Decrement boundaries.** In the decrement action, stable second-field values 1 and 0 respectively become 0 and receive no decrement write. A query result of −3 is stored without decrement.

9. **Unstored first-field query result.** The switch action sees −1 and queries 9. It makes no direct first-field write; absent dependency mutation, the field remains −1.

10. **Indirect payload copy.** The residual group selects 0x66000024. Event offset +12 points to a word containing 0xA5A5A5A5. That word is written to state offset +0x148.

11. **Code in the wrong group.** Discriminator 0x66000014 fails equality and is greater than both stable threshold observations. It enters the residual group and does not increment. Downstream processing still occurs.

12. **Exit gating.** A zero address at state offset +0x10C, or a zero first word at its nonzero referenced address, suppresses the global exit invocation. Two nonzero observations permit it.
