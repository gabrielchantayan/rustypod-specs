# F-8372815b68a4

## Purpose

F-8372815b68a4 prepares a destination through a dependency, installs two 32-bit values from a selected source record, invokes an indirectly selected operation with a metadata-located region address, and returns the prepared-object pointer.

A non-null source selects the caller-supplied record. A null source selects a global-record path that first seeds the original destination, calls an additional dependency, and derives the destination used for preparation from that dependency’s result.

The established contract concerns memory accesses, address calculations, call order, and the returned value. Construction, copying, registration, allocation, and ownership transfer are not established semantic purposes.

## Interface

### Inputs

The visible interface has three arguments:

1. **Destination pointer.** On the null-source path, its first 32-bit word is written, and its address plus 176 bytes is supplied to F-af167f4d7e19. On the non-null-source path, this function passes it directly to F-bf74dfda5df0 without a preceding direct dereference.
2. **Source pointer.** Null selects the global-source path. Otherwise, it identifies the record supplying the two installation values. Those values occupy consecutive 32-bit words, at offsets 0 and +4.
3. **Preparation argument.** An opaque 32-bit value passed unchanged to F-bf74dfda5df0. Its signedness, semantic type, and ownership significance are not established.

A source record need not retain its entry-time contents. The contract depends on the values present when each source word is actually read.

### Output

On normal completion, the function returns the pointer returned by F-bf74dfda5df0.

No visible check establishes that this pointer equals the original destination, the destination passed to preparation, the selected source, or the receiver used for the indirect operation.

The indirect operation’s result, if any, is discarded.

## Behavior

### Global pointer capture and source selection

Before testing whether the explicit source is null, the function captures the pointer stored in a designated global pointer location.

Capturing that pointer does not snapshot the referenced record’s contents.

With a non-null explicit source:

- The original destination is retained for preparation.
- The explicit source remains selected.
- The preliminary destination write and F-af167f4d7e19 call are skipped.
- The captured global pointer does not supply either installation value.

With a null explicit source:

1. The function uses the designated global pointer to read a record’s first 32-bit word and writes that value to the original destination’s first word.
2. It calls F-af167f4d7e19 with the original destination address plus 176 bytes.
3. It subtracts 176 bytes from that call’s returned address-sized value.
4. The adjusted address becomes the destination supplied to preparation.
5. The global pointer captured before the branch becomes the selected source.

The preliminary write precedes F-af167f4d7e19 and is therefore visible to that dependency if it accesses the affected storage.

The representation references the global pointer separately for the preliminary read while retaining the earlier captured pointer for later source selection. It supplies no synchronization or atomicity guarantee. If those references observe different pointer values, the seed record and later selected source need not be the same record. Whether such an execution is supported by the target environment remains unresolved.

The adjusted destination is derived from F-af167f4d7e19’s result. The function does not check that the dependency returned the interior address it received.

### Preparation

F-bf74dfda5df0 is called with the retained or adjusted destination and the unchanged 32-bit preparation argument.

Its returned pointer becomes the prepared object. That pointer is retained for subsequent direct object accesses and for the eventual return.

The selected source’s first word for the main installation is read only after preparation returns. On the null-source path, F-af167f4d7e19 also precedes this read. Mutations by either dependency can therefore affect the installed value.

There is no visible null-result check before writing through the prepared-object pointer.

### First installation

The function reads the selected source’s first 32-bit word and retains that value.

It writes the retained value to the prepared object’s first word. It then uses that same retained value as an address-bearing value for the first displacement lookup, reading a 32-bit displacement from 12 bytes before the represented address.

This lookup does not depend on rereading the prepared object’s first word. An alias-induced change to the original source word after its capture does not change the retained value used for this lookup.

### Second installation

The selected source’s second 32-bit word is written to the address obtained by adding the first displacement to the prepared-object address.

This is a metadata-directed write. It is not necessarily a write to the prepared object’s second consecutive word.

The first installation is complete before the second assignment. Consequently, the second source read can observe a value written by the first installation. In particular, if the selected source’s second word occupies the prepared object’s first-word address, its earlier contents are replaced before the second source read.

The supplied expression does not establish a portable ordering between reading the second source word and reading the displacement used for this assignment. Both contribute to the same assignment; neither should be assigned an additional read-order guarantee.

No visible branch checks the displacement or confines the resulting write to an allocation.

### Dispatch receiver acquisition

After the second installation has completed, the function calls F-df3f6f4fe2dc without explicit arguments.

The returned pointer is the receiver for the indirect operation. The function reads its first word as a dispatch-table address and selects the callable entry at byte offset +152.

No identity relationship between this receiver and the prepared object is established.

### Fresh region calculation and indirect call

The indirect operation receives:

1. The receiver returned by F-df3f6f4fe2dc.
2. A region address calculated from the prepared object using a fresh metadata lookup.

For that region calculation, the function rereads the prepared object’s first word, reads a displacement from 12 bytes before the address represented by that word, and adds the displacement to the prepared-object address.

This lookup occurs after F-df3f6f4fe2dc returns. It need not produce the displacement used for the second installation. The second installation itself, aliasing, or dependency effects may have changed the prepared object’s first word or the metadata.

The representation does not establish a portable evaluation order between obtaining the indirect callable address and calculating the region argument. Both are evaluated after receiver acquisition and before entering the indirect operation.

If the operation returns normally, its result is ignored and the retained prepared-object pointer is returned.

## Side effects

### Direct writes

The function directly performs:

- One preliminary 32-bit write to the original destination, only for a null source.
- One 32-bit write to the prepared object’s first word.
- One metadata-directed 32-bit write relative to the prepared object.

These writes can overlap each other, the selected source, metadata, or other accessible storage. The representation imposes no general non-aliasing condition.

There is no visible rollback. Earlier writes are not restored if a subsequent access fails or a dependency does not return normally.

### Explicit source with noninterfering storage

Assume:

- The explicit source is non-null.
- Its first word identifies metadata whose displacement remains +32 throughout the relevant accesses.
- Its second word contains the 32-bit pattern 0x12345678 when the second source read occurs.
- Preparation returns a valid prepared object.
- Neither installation overwrites the selected source or relevant metadata.
- Receiver acquisition does not change the prepared object’s first word or relevant metadata.

Expected behavior:

- F-af167f4d7e19 is skipped.
- Preparation receives the original destination and unchanged preparation argument.
- The prepared object’s first word receives the value read from the source’s first word after preparation.
- Prepared object +32 receives 0x12345678.
- The indirect operation receives the acquired receiver and prepared object +32.
- The function returns the preparation result.

The second-word expectation concerns its actual read time, not merely its entry-time contents.

### Aliasing without dependency mutation

Assume the source’s second word occupies the prepared object’s first-word address. Its initial contents are 0x12345678. The source’s first word contains an address-bearing value identifying stable metadata with displacement +32. Dependencies do not mutate the relevant storage, and the write at prepared object +32 does not disturb the later metadata lookup.

Expected behavior:

- The first installation replaces the source’s second word with the address-bearing value read from the source’s first word.
- The second source read observes that replacement.
- Prepared object +32 receives the address-bearing value, not the initial 0x12345678.

Stable metadata and absence of dependency mutation do not eliminate this aliasing effect.

### Null source with a redirected destination

Assume a valid global record, a null explicit source, and no change to the global pointer during source selection. F-af167f4d7e19 returns an address whose value minus 176 differs from the original destination.

Expected behavior:

- The original destination is seeded before F-af167f4d7e19 runs.
- That dependency receives original destination +176.
- Preparation receives the adjusted returned address, not the original destination.
- The later source is the global record pointer captured before the branch.
- The eventual return remains the preparation result.

### Source mutation during preparation

Assume preparation changes the selected source’s first word before returning, with the changed value supporting the required metadata access.

Expected behavior: the main first installation uses the changed value. The function does not install an entry-time snapshot.

### Metadata mutation during receiver acquisition

Assume the second installation uses displacement +24. F-df3f6f4fe2dc subsequently changes the prepared object’s first word so that its metadata lookup yields +40.

Expected behavior:

- The second installation occurs at prepared object +24.
- The indirect operation receives prepared object +40.

Reusing the earlier displacement would not preserve this behavior.

### Zero or negative displacement

With a zero first displacement, the second installation targets the prepared object’s first word and can replace the first installation. Normal completion then additionally requires that the replacement support the later metadata lookup.

A negative displacement is not rejected by a visible branch. Its resulting addresses must still satisfy all access requirements; acceptance does not imply unrestricted validity before the prepared object.
