# F-113e31d4dce6

## Purpose

F-113e31d4dce6 delegates an operation to F-0a08bd5d35c9 and conditionally returns a quantity derived from two fields in caller-associated storage.

Its observable result has two classes:

- A nonzero dependency result causes this function to return zero without directly reading either field.
- A zero dependency result causes this function to read the fields after delegation and derive its return value from their signed difference, shifted right by four bits.

These branch conditions are established static evidence. They do not establish that the dependency reports success with zero, or that a zero result from this function means failure.

**Inferred intent:** The field calculation resembles converting a span into a count of 16-byte units. The evidence does not establish that the fields are addresses, that they delimit a valid region, or that the returned quantity counts objects. Those interpretations are not requirements of this contract.

This document describes the supplied static representation. No runtime tests have been performed.

### Dependency-result distinction

Every nonzero dependency result has the same direct consequence: this function returns zero. Positive and negative nonzero results are not distinguished, and their original values are discarded.

On that branch, neither field is directly read by this function. This does not prohibit the dependency from reading those fields or requiring their storage to be valid.

### Field-derived result

The calculation uses the signed value at the higher offset less the signed value at the lower offset. A four-bit signed right shift is applied to that difference.

The shift applies to the difference as a whole. It is not a separate scaling of each field before subtraction.

For a representable, nonnegative difference, the return value is the number of complete groups of 16 in that difference. For example:

- Differences from 0 through 15 produce zero.
- Differences from 16 through 31 produce one.
- Differences from 32 through 47 produce two.

No local check requires the difference to be divisible by 16. There is no separate remainder result, rounding adjustment, or clamp to a nonnegative value.

Likewise, no local rule rejects negative field values, equal field values, or a higher-offset value numerically smaller than the lower-offset value.

### Observable ordering

The established ordering constraints are:

- Obtaining the global argument precedes execution of the dependency.
- The dependency’s normal return precedes either conditional field read.
- The result uses both field values before applying the final shift.

The relative order of the two field reads is not established. Neither increasing-offset nor decreasing-offset order is required.

The two reads are not established as an atomic snapshot. The evidence provides no guarantee that concurrent or externally driven changes cannot occur between them. It also provides no synchronization contract under which concurrent access is necessarily valid.

### Arithmetic limits

The field interpretations and subtraction are recovered as signed 32-bit operations. No wider subtraction intermediate is established.

Individually valid signed 32-bit field values can still have an out-of-range mathematical difference. For such a difference, this contract does not promise wrapping, saturation, a widened result, a fault, or any particular return value.

For a representable negative difference, the operation is a signed right shift. The exact result remains **documented_only** without additional execution-environment evidence. Under arithmetic-right-shift semantics, the result rounds toward negative infinity: a difference of −1 produces −1, rather than zero.

The address-bearing additions also depend on execution-environment rules. The evidence does not establish wrapping address formation or valid behavior when signed address calculations overflow.
