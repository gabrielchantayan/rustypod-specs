# F-868e5d53f111

## Purpose

F-868e5d53f111 conditionally performs a state-dependent operation, supplies one of two local-storage addresses to a final dependency, and returns a 64-bit value assembled from two local 32-bit slots.

The conditional operation is selected when the unsigned 32-bit value initially read at state offset +8 is nonzero and strictly less than the unsigned 32-bit value subsequently read at state offset +4. On that path, three dependencies are called, and a retained result is written to state offset +8. On every normally completing path, a final dependency is called.

These mechanics are established by the supplied static evidence. The meanings of the state fields, the dependency operations, and the returned words are not established. Descriptions such as allocation, resizing, transfer, or cleanup would be inferred intent rather than a supported contract.

## Interface

### Inputs

The function accepts three machine-level inputs:

| Input | Width and interpretation | Established use |
|---|---|---|
| Context word | Opaque 32-bit value | Copied into a local slot and passed as the first argument to the final dependency |
| State address | Address represented by a 32-bit input | Used to access fields at byte offsets +4 and +8, passed to conditional dependencies, and copied into a local return slot |
| Comparison argument | Unsigned 32-bit value | Replaced by the field at state offset +4 whenever the field at offset +8 is nonzero; otherwise it cannot affect branch selection |

The incoming comparison argument has no direct influence on the visible calls, explicit state write, or result construction. When it could otherwise participate in the comparison, it has already been replaced by a state-field value. When it is not replaced, the nonzero prerequisite fails and the conditional operation is skipped.

This conclusion concerns the visible body. It does not assert that unknown dependencies cannot inspect argument registers, caller storage, or other execution state outside their explicit interfaces.

### State layout

The visible state accesses are:

| Byte offset from state address | Width | Access |
|---|---:|---|
| +4 | 32 bits | Read when the initial +8 value is nonzero; read again on the conditional path |
| +8 | 32 bits | Read unconditionally; written on the conditional path |

The fields are interpreted as unsigned 32-bit values for the branch comparison. The value read again at +4 is passed onward as an opaque 32-bit argument.

No field at offset +0 is explicitly accessed. No complete structure size, field ownership, byte order, or alignment guarantee is established.

### Output

The normal return is a 64-bit concatenation:

- Bits 31–0 come from the local slot initially assigned the context word.
- Bits 63–32 come from the local slot initially assigned the state-address word.

These slots are read for return construction after the final dependency completes. The result therefore must not be described unconditionally as a concatenation of the original inputs: on the conditional path, dependencies receive an address associated with those local slots and may change accessible storage.

The return operation concatenates two 32-bit bit patterns. It does not sign-extend the state-address word, add the words, or return either local address.

### Preconditions

For the explicitly shown accesses to complete normally:

- The state address must permit a 32-bit read at offset +8.
- If that value is nonzero, the address must also permit a 32-bit read at offset +4.
- On the conditional path, the second read at +4 and the later write at +8 must be valid when they occur.
- Every invoked dependency must accept its supplied arguments and return normally.

A readable state pointer is required even when the comparison argument is zero. There is no null check or explicit bounds check.

## Behavior

### Initial preparation and branch selection

Two local 32-bit slots are initialized to zero. They provide the alternate local-storage address used when the conditional operation is skipped.

The function then reads the unsigned 32-bit field at state offset +8. This value is retained for branch selection and, if the branch is taken, for the first dependency call.

If that initial value is nonzero, the function reads the unsigned 32-bit field at state offset +4 and substitutes it for the incoming comparison argument.

Two other local slots are assigned the original context word and original state-address word. These are the slots later used to construct the return value.

The conditional operation occurs exactly when:

- The initial value from offset +8 is nonzero; and
- That value is strictly less than the value read from offset +4 during branch preparation.

The comparison is unsigned and 32-bit. Equality does not qualify. A value with its highest bit set is treated as a large positive unsigned value, not as a negative signed value.

If the initial +8 value is zero, the first +4 read is skipped. No conditional dependency is called.

### Conditional operation

When the condition holds, the visible sequence is:

1. **Call F-41ba7d9bb9e3.**  
   Its arguments are the original state address and the retained initial 32-bit value from offset +8. Its result is retained as an opaque 32-bit word.

2. **Read state offset +4 again.**  
   This is a new read, not reuse of the branch-selection value. It occurs after F-41ba7d9bb9e3 returns. Any change that dependency makes to the field can therefore affect the next call.

3. **Call F-1f25076df2ed.**  
   Its four arguments, in argument-position order, are:
   - The original state address.
   - The 32-bit result from F-41ba7d9bb9e3.
   - The newly read 32-bit field at offset +4.
   - The same retained result from F-41ba7d9bb9e3 again.

   Its result is retained as another opaque 32-bit word.

4. **Call F-3bb948305a79.**  
   Its arguments are:
   - The address of the local slot initially assigned the context word.
   - The retained result from F-41ba7d9bb9e3.
   - The retained result from F-1f25076df2ed.

5. **Write state offset +8.**  
   After F-3bb948305a79 returns, the function writes the retained result from F-1f25076df2ed to the original state address at offset +8.

The final store uses the retained result, not a reread of the state field or a new result from F-3bb948305a79. Consequently, any earlier dependency write to that field is superseded by this explicit store if execution reaches it.

The local-storage address selected for the final dependency remains the address of the slot initially assigned the context word.

### Skipped conditional operation

If the condition does not hold:

- F-41ba7d9bb9e3 is not called.
- F-1f25076df2ed is not called.
- F-3bb948305a79 is not called.
- The function performs no explicit write to state offset +8.
- The address selected for the final dependency is the address of the first of the two zero-initialized local slots.

This alternate address is distinct in purpose from the local slots used for return construction. No explicit copy from the zero-initialized slots into the return slots occurs.

### Final call and return

Both paths call F-2aaa2ea360f2 with:

1. The original context-word argument.
2. The selected local-storage address.

The first argument remains the original context input even if an earlier dependency has changed the local slot that initially held a copy of it.

The final dependency’s return value is not used in the visible result construction.

After that dependency returns, the function reads the two return slots and concatenates their current 32-bit contents into the 64-bit result. On the conditional path, modifications through the supplied local-storage address may therefore affect the result.

## Side effects

### Explicit accesses and ordering

Ignoring dependency-internal activity, the externally addressed state accesses occur in this order:

- Read offset +8.
- If the initial value is nonzero, read offset +4.
- If the conditional operation is selected, call F-41ba7d9bb9e3, then read offset +4 again.
- Call F-1f25076df2ed.
- Call F-3bb948305a79.
- Write the retained result to offset +8.
- Call F-2aaa2ea360f2.

For a skipped conditional operation, the sequence ends with the final dependency call after the applicable initial reads.

No synchronization, atomic access, retry loop, or consistency check is visible. The contract does not require the two reads at +4 to agree.

### Ownership and lifetime

The function passes addresses of its own local storage to dependencies. It does not explicitly allocate or release memory.

The lifetime of that local storage does not extend beyond this invocation. Whether dependencies retain those addresses, modify storage beyond the addressed slot, allocate memory, release memory, or transfer ownership is **documented_only**.

An address passed to a dependency is not, by itself, evidence that ownership is transferred.

### Errors and abnormal completion

There is no explicit error result, validation failure branch, or rollback.

Dependency results are not checked for zero, all-one bits, or any other failure sentinel. If a dependency returns normally with such a value, that value is forwarded or stored according to the ordinary sequence.

If an access faults or a dependency does not return normally, the supplied evidence establishes neither a normal return nor recovery behavior. Effects already performed are not visibly undone.

## Acceptance examples

These are conditional acceptance cases derived from static evidence, not executed tests. Assume valid accesses and normally returning dependencies unless stated otherwise.

### Zero initial field

Given offset +8 initially contains zero:

- Offset +4 is not explicitly read.
- The three conditional dependencies are skipped.
- F-2aaa2ea360f2 receives the original context word and the alternate zero-initialized local-storage address.
- No explicit state write occurs.

If the final dependency leaves the return slots unchanged, the returned low word equals the original context word and the high word equals the original state-address word.

### Equal fields

Given offset +8 contains 12 and the first read at +4 yields 12, the conditional operation is skipped. Strict inequality is required. Changing the incoming comparison argument does not change that decision.

### Unsigned boundary

Given offset +8 contains 0x80000000 and the first +4 read yields 0x7fffffff, the conditional operation is skipped.

Given those values in the opposite fields, the conditional operation is selected. Signed comparison would produce a different result and would not match this contract.

### Field changes during a dependency

Given the initial +8 value is 3 and the branch-selection +4 value is 10, the conditional operation is selected.

If F-41ba7d9bb9e3 then changes offset +4 to 2, F-1f25076df2ed receives 2 as its third argument. The branch is not reevaluated. Its second and fourth arguments still contain the retained result of F-41ba7d9bb9e3.

### Retained result controls the store

Suppose F-1f25076df2ed returns 0x12345678 and F-3bb948305a79 subsequently writes another value to state offset +8.

On normal completion of F-3bb948305a79, the function writes 0x12345678 to offset +8 before calling F-2aaa2ea360f2. The final dependency may change the field again; its preservation behavior is unknown.

### Local mutation affects the result

On the conditional path, suppose a dependency validly changes the addressed context-copy slot to 0xaabbccdd and that value survives the final call.

The returned low 32 bits are then 0xaabbccdd, not necessarily the original context word. The final dependency nevertheless receives the original context word as its first argument.
