## Behavior

### Access-order rule

The following phases occur in order. Within a phase, the described sequencing matters wherever a read can observe an earlier write.

A pointer field read later in the routine is not necessarily equal to an earlier read of that field. Aliasing can make intervening byte or word stores change subsequent pointer values. Consequently, object labels below identify values captured at particular reads; they do not imply permanently stable object relationships.

The representation contains no explicit conditional branch, loop, validation step, or error return before the final indirect call.

### Initial context mutation

The routine first writes context C into context B’s four-byte field at `0x44`, then writes the second argument into context B’s byte at `0x11`. It captures the four-byte value at context B offset `0x74`; call this captured value **P-01**.

It next writes the low byte of context C at context B offset `0x0D`. The first argument is stored as four bytes at context A offset `0x10`. Context B offset `0x44` is then written with context C again.

A separate one-byte store places the low byte of the first argument at context A offset `0x10`. This is an actual additional access, not merely a description of the preceding four-byte store. Whether it leaves the complete four-byte field unchanged depends on byte order.

The first argument is also stored at context B offset `0x54` and context A offset `0x60`.

The routine then reloads context B offset `0x74`; call that value **P-02**. It replaces the field with context C and stores the first argument at P-02 offset `0x40`. Context B’s byte at `0x0D` is replaced with the low byte of P-01.

P-02 offset `0x44` is read and retained. Context B offset `0x54` becomes a self-reference to context B, and the third-argument base receives its own value at offset `0x54`.

### First pointer-chain updates

P-02 offset `0x14` supplies another address, **P-03**. The low byte of the previously captured P-02 `0x44` value is stored at context C offset `0x11`.

The four-byte value at context C offset `0x14` is read, narrowed to a byte, and written at P-03 offset `0x15`. Context C offset `0x14` is then read again to obtain **P-04**. Those two reads cannot be merged in an alias-sensitive contract.

Context B offset `0x64` is read and retained as **V-01**. The routine writes the four-byte constant `0x73` at P-04 offset `0x20`, then reads context B offset `0x64` again as **V-02**. V-02’s low byte is written at P-04 offset `0x09`.

P-04 offset `0x74` supplies **P-05**. The routine writes context B’s low byte at P-05 offset `0x0D`, performs a four-byte read followed by a four-byte write of the same fetched value at P-05 offset `0x54`, and writes byte `0x74` at P-05 offset `0x09`.

That read/write pair is observable even when it leaves ordinary memory unchanged.

Context B offset `0x44` receives V-01. P-05 offset `0x34` receives context B. P-05 offset `0x04` then supplies **P-06**.

### Arithmetic-address tail and indirect call

The routine reads G-01, then reloads context B offset `0x74` as **P-17**.

It writes P-17’s low 16 bits to the address formed by adding P-17 and context B. It then writes G-01’s low 16 bits to the address formed by doubling P-16.

A single byte is read from the address formed by adding P-14 and context B. The representation treats this as a plain character converted to an unsigned 32-bit value; call the resulting value **V-08**. Signed-character handling is unresolved, as detailed below.

The routine next:

- Stores P-17’s low 16 bits at the address G-01 plus P-17.
- Repeats the two-byte store of P-17’s low 16 bits at P-17 plus context B.
- Stores four-byte constant `0x45` at V-08 plus `0x45`.

Only after that four-byte store does it read G-02, G-03, and context B offset `0x44`, in that order. The last captured value is **V-09**.

It then stores byte `0x44` at V-08 plus `0x44`, stores G-03 as four bytes at twice G-02, and stores G-02’s low 16 bits at P-07 plus G-02.

Finally, the unresolved indirect target receives:

1. V-08 bitwise-OR `0x44`;
2. the captured G-02 value;
3. V-09.

The first argument is a bitwise OR, not the addition used for the preceding memory destinations.

## Acceptance examples

These are conditional static acceptance criteria, not executed tests.

1. **Explicit byte argument.** Given valid writable context B memory, the initial write to its offset `0x11` must contain the eight-bit second argument. A final-memory check alone cannot establish this behavior because a later write replaces that location.

2. **Distinct reads of one field.** If context B offset `0x64` changes between its two early reads because the intervening store aliases it, V-01 and V-02 may differ. The store to context B offset `0x44` must use V-01; the store to P-06 offset `0x24` must use V-02.

3. **Repeated access preservation.** An access trace must include both successive byte writes to context B offset `0x0D`, even if they store identical values. It must also include the read and write at P-05 offset `0x54`.

4. **Narrowing.** If P-17 has bit pattern `0x12345678`, each tail store described as containing its low 16 bits carries `0x5678`. The destination address still uses the full address-shaped P-17 value.

5. **OR versus addition.** If V-08 is `0x04`, the two nearby destinations are `0x49` for the four-byte `0x45` store and `0x48` for the byte `0x44` store. The first indirect-call argument is `0x44`, not `0x48`.

6. **Character conversion.** If the tail byte is `0x80`, signed-character interpretation yields unsigned 32-bit value `0xFFFFFF80`; unsigned-character interpretation yields `0x00000080`. Acceptance of either interpretation requires external evidence about the underlying instruction or character model.

7. **Failure after partial mutation.** If the arithmetic-derived read is inaccessible after all preceding accesses succeeded, the visible representation provides no recovery path or rollback guarantee.
