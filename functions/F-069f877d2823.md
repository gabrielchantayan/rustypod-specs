# F-069f877d2823

## Purpose

F-069f877d2823 conditionally invokes operations on a caller-supplied object and returns a 32-bit result. An initial dependency establishes whether processing may continue. If two local values both differ from their respective all-bits-one sentinel representations, the function inspects signed status fields in the object, optionally performs two preparatory calls, and invokes a final dependency.

The names “selection,” “companion,” and “status” below are descriptive labels, not established domain meanings. The supplied evidence does not establish whether this function searches, removes, updates, releases, or otherwise manages a resource.

The decisive distinction is between:

- **Eligibility:** two local sentinel checks determine whether object-field inspection and the final dependency call occur.
- **Optional preparation:** two signed object-field checks determine whether two additional dependencies are called before the final dependency.

Failure of the optional preparation checks does not itself prevent the final dependency call.

## Behavior

### 1. Initialize local eligibility state

Before calling any dependency, the function initializes the selection value to signed `-1` and the companion value to its all-bits-one sentinel.

These are distinct sentinel tests. Neither is a general validity test:

- The selection check rejects exactly `-1`, not every negative integer.
- The companion check rejects the represented all-bits-one value, not every address that might be invalid.
- A zero companion value is not rejected by this wrapper.

An internal pointer-shaped temporary initially refers to the companion’s local storage. That initial address does not independently permit processing: when the selection remains `-1`, the subsequent eligibility condition fails.

### 2. Invoke the initial dependency

The function calls F-d2964719b92c with:

1. The incoming object-address value.
2. The address of the local selection value.

The dependency’s return value, if any, does not control this wrapper’s result or branches. The wrapper instead examines local state after the dependency returns.

The initial dependency is called regardless of object-field contents and regardless of the initial sentinel values. No object-field read at either documented offset precedes this call.

The supplied body does not show an explicit companion output argument. It consequently establishes the wrapper’s behavior if the companion changes, but does not establish the mechanism or validity of such a change.

### 3. Determine eligibility

After the initial dependency returns, processing continues only when:

- The selection value is not signed `-1`; and
- The companion value used by the eligibility comparison is not its all-bits-one sentinel.

If either check fails, the function returns the 32-bit value zero. On this path, it does not directly read either documented object field and does not call F-69390fee919d, F-03a561fa0ffb, or F-045e31462f77.

This statement concerns the wrapper’s own actions. F-d2964719b92c may have performed reads, writes, or calls internally; its behavior is not supplied.

### 4. Inspect object status in a fixed order

If eligibility succeeds, the wrapper first reads the signed 32-bit field at byte offset `0x2D4`.

- If that value is negative, the wrapper skips the read at `0x2CC` and skips both preparatory dependencies.
- If that value is nonnegative, the wrapper reads the signed 32-bit field at byte offset `0x2CC`.

The preparatory calls occur only if this second value is also nonnegative. Zero satisfies both nonnegative comparisons.

The order is significant: the lower-offset field is read second, not first, and is conditionally unread. The wrapper does not reread the first field to confirm that it remains nonnegative.

### 5. Optionally perform preparation

When both status values read as nonnegative, the wrapper invokes these dependencies in order:

1. F-69390fee919d with the incoming object-address value.
2. F-03a561fa0ffb with the incoming object-address value, the selection value, and the companion value.

The wrapper does not branch on either call’s return value. A returned status indicating failure, if those dependencies have such a convention, does not cause the wrapper to skip the next call.

The object fields are not checked again between these calls. Consequently, mutations by F-69390fee919d do not cause the wrapper to reconsider the preparation decision already made from the earlier reads.

No claim is made that these dependencies preserve the object, globals, memory ownership, or indirectly reachable local state.

### 6. Obtain and return the final result

Whenever eligibility succeeds, the wrapper calls F-045e31462f77 with:

1. The incoming object-address value.
2. The selection value.
3. The companion value.

This call follows F-03a561fa0ffb when preparation occurs. Otherwise it follows the status inspection directly.

The local argument values are those available when the corresponding call arguments are evaluated. The body does not create immutable snapshots of both local values for all subsequent calls. Without dependency contracts, equality between values passed to separate calls must not be assumed if intervening operations can mutate their storage through a valid alias.

The wrapper returns the final dependency’s 32-bit result without a visible transformation.
