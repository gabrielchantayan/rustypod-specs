# F-921e1720c217

## Purpose

F-921e1720c217 performs an ordered sequence of destination-manipulating calls, byte-keyed table searches, cross-table probes, and a final comparison that conditionally triggers two additional calls.

Its apparent purpose is to construct a value from an initial value, category information, and a selector-dependent suffix. That interpretation is inferred intent. The established contract is the sequence of reads, dependency calls, and branch decisions described below. Neither the resulting literal content nor its user-visible meaning is established.

A successful table match does not necessarily end category selection. Later stages may be searched or bypassed according to key bytes at an inherited row index. More than one category emission can occur in one invocation.

## Interface

The function accepts four inputs and has no explicit return value.

| Input | Representation | Established use |
|---|---|---|
| Record address | 32-bit address-like value | Locates a 32-bit selector at byte offset 4 and a 32-bit packed field at byte offset 16. |
| Destination slot | Address of a 32-bit address-bearing slot | Passed to destination-manipulating dependencies and dereferenced during final comparison. |
| Initialization argument 1 | Opaque 32-bit value | Third argument of the initial dependency call. |
| Initialization argument 2 | Opaque 32-bit value | Fourth and fifth arguments of the initial dependency call. |

There is no explicit success result, error result, null check, bounds check, or local recovery mechanism.

### Referenced objects and layouts

The following names identify roles without assigning textual contents:

- **Initial value:** a fixed-address object used during initialization and final comparison.
- **Separator value:** a fixed-address object passed between other destination operations.
- **Primary-table global:** a global address source used for A and for separately calculating C–E.
- **Secondary-table global:** a global address source used for B.
- **Final-table global:** a global address source used for F.
- **Label-array global:** a global pointer to 32-bit entries.

The table addressing rules are distinct:

| Table | Retained address used for payloads | Address used for search keys and later probes |
|---|---|---|
| A | First post-initialization read of the primary-table global | Search keys use fresh global reads; A’s post-emission probe uses A’s retained address. |
| B | Secondary-table global captured when B’s search begins | Fresh secondary-table global reads. |
| C | Separate post-initialization read of the primary-table global, plus 296 bytes | C’s retained address. |
| D | Another post-initialization read of the primary-table global, plus 408 bytes | D’s retained address. |
| E | Another post-initialization read of the primary-table global, plus 480 bytes | E’s retained address. |
| F | Final-table global captured when F’s search begins | Fresh final-table global reads. |

C–E are **not** calculated from A’s retained address. A common originating primary-table address requires a stability assumption across the four separate reads.

Each table has an 8-byte row stride:

| Byte offset within row | Access |
|---|---|
| 0 | Unsigned 8-bit search key; also used for zero/nonzero probes. |
| 1–3 | Not directly read by this function. |
| 4–7 | Opaque 32-bit payload, read on emission. |

A zero key terminates a search and cannot match a category key. No table extent or row count is supplied.

Label entries are 32 bits wide and numbered from zero. Capturing the label-array address does not capture its contents.

The destination address has an associated unsigned 32-bit metadata word four bytes before it. A length interpretation is plausible but unestablished.

### Preconditions and validity

Normal completion requires every reached access and dependency invocation to be valid. In particular:

- Record fields must be readable when actually accessed.
- The destination slot and reached preceding metadata words must be readable.
- Reached label entries and matched-row payloads must be readable.
- Searches must reach a match or zero terminator before invalid addressing or index overflow.
- Cross-table probes must be valid at inherited indices, independently of whether those indices are within a table’s searchable extent.
- Dependencies must accept the supplied arguments and return for subsequent behavior to occur.

These are path-dependent requirements. For example, the selector need not be read on a path that omits the suffix.

## Behavior

### Initialization and ordered address captures

The first dependency invocation is F-0fdd13c3e50f, with five arguments in this order:

1. Destination slot.
2. Initial-value address.
3. Initialization argument 1.
4. Initialization argument 2.
5. Initialization argument 2 again.

After it returns, the function performs these reads in order:

1. Capture the label-array global.
2. Read the primary-table global and retain the result as A’s payload base.
3. Read the primary-table global again, add 296 bytes, and retain C’s base.
4. Read the primary-table global again, add 408 bytes, and retain D’s base.
5. Read the primary-table global again, add 480 bytes, and retain E’s base.

No dependency call intervenes between these captures. Nevertheless, the supplied body establishes separate reads, not a single shared snapshot. Without a guarantee excluding asynchronous mutation, the four primary-table observations need not agree.

The captured label-array address and C–E bases are not subsequently refreshed. A’s retained payload base likewise remains fixed, although A’s search-key reads use the live primary-table global.

### Search key and emission

The record’s category key is bits 16–23 of its 32-bit field at byte offset 16. For every inspected nonzero search key, the function rereads that field and extracts the category byte. It does not capture one category key for the entire invocation.

A category emission consists of three dependency calls:

1. F-0fdd13c3e50f with the destination slot and selected label value.
2. F-5732b2d5ea03 with the destination slot and separator address.
3. F-5732b2d5ea03 with the destination slot and matched row’s 32-bit payload.

The label mapping is:

| Table | Label entry |
|---|---:|
| A | 0 |
| B | 8 |
| C | 9 |
| D | 10 |
| E | 11 |
| F | 12 |

A’s label is obtained through a fresh read of the label-array global. B–F use the retained label-array address. In every case, the selected entry’s contents are read for the call, rather than being an initialization-time snapshot.

The payload is read only after the first two emission calls return. Either call can therefore affect the later payload value if it mutates reachable storage. “Emission” describes this call sequence; it does not establish replacement, concatenation, formatting, or ownership semantics.

### A search

A’s search starts at row zero. Each iteration reads the row key through the current primary-table global.

- Zero ends A’s search and starts B’s search at row zero.
- A nonzero mismatch advances the row index by one.
- A nonzero match emits A, using A’s retained payload base.

After A’s emission, the function rereads the matched row’s key through **A’s retained address**, not through a refreshed global:

- Zero starts B’s search at row zero.
- Nonzero bypasses B’s search and performs B’s probe at A’s matched index.

Thus A’s search key, payload, and post-emission probe can refer to different observations of storage. Even after a match, the transition depends on a new byte read.

### B search and probe

When B’s search is entered, the function captures the secondary-table global for payload addressing and resets the row index to zero.

Search-key reads use the current secondary-table global:

- Zero starts C’s search at row zero.
- A nonzero mismatch advances the index.
- A nonzero match emits B, then performs B’s probe at the matched index.

B’s probe also occurs when reached directly from A. It reads the key byte using the current secondary-table global and the inherited index:

- Zero starts C’s search at row zero.
- Nonzero bypasses C’s search and performs C’s probe at the same index.

A probe does not compare its byte with the record category. A nonzero B probe following an A match does not establish that B contains a matching row.

### C, D, and E searches and probes

C, D, and E use their respective retained addresses for search keys, payloads, and probes. Those addresses came from separate primary-table global reads.

Each search starts at row zero. It reads a key, stops on zero, and compares each nonzero key with a freshly read record category. A match emits the corresponding category and then probes that same table at the matched index.

A probe reads only one key byte at the current index. Its transitions are:

| Stage | Zero probe | Nonzero probe |
|---|---|---|
| C | Start D’s search at row zero. | Probe D at the same index, without searching D. |
| D | Start E’s search at row zero. | Probe E at the same index, without searching E. |
| E | Start F’s search at row zero. | End category selection. |

Search exhaustion also moves forward:

- C exhaustion starts D’s search.
- D exhaustion starts E’s search.
- E exhaustion starts F’s search.

A post-emission probe is a new read after all three emission calls. It is not assumed to equal the key that matched earlier.

An inherited probe can bypass a search entirely. For example, a nonzero B probe leads to C’s probe; a nonzero C probe then leads to D’s probe without searching either C or D.

### F search

If reached, F captures the final-table global as its payload base and resets the index to zero. Search keys use fresh reads of that global.

- Zero ends category selection.
- A nonzero mismatch advances the index.
- A nonzero match emits F and ends category selection.

There is no post-emission F probe.

### Final comparison

Every normally completing category-selection path reaches the same final comparison sequence:

1. Read the destination address from its slot, then read the unsigned 32-bit metadata word four bytes before that address.
2. Call F-1cb585febd84 with the initial-value address and obtain its unsigned 32-bit result.
3. Reread the destination address and its preceding unsigned 32-bit metadata word.
4. Retain the unsigned minimum of the two metadata observations.
5. Read the destination address for a call to F-7f14f1ab6851, passing that address and the initial-value address.

No explicit comparison length is passed to F-7f14f1ab6851. The two metadata observations may come from different destination addresses if F-1cb585febd84 changes the slot.

The suffix is omitted exactly when both conditions hold:

- F-7f14f1ab6851 returns zero.
- The retained metadata minimum equals F-1cb585febd84’s result.

Any nonzero comparison result selects the suffix path. A zero comparison result also selects that path when the unsigned metadata minimum is either less than or greater than the reference result. The intermediate ordering values are not returned.

### Conditional suffix

On the suffix path, the function first calls F-5732b2d5ea03 with the destination slot and separator address.

Only after that call returns does it read the 32-bit selector at record byte offset 4 and select an entry through the retained label-array address:

| Selector | Label entry |
|---|---:|
| 6 | 2 |
| 8 | 3 |
| 9 | 4 |
| 10 | 5 |
| 11 | 6 |
| 12 | 7 |
| Every other 32-bit value, including 7 | 1 |

It then calls F-5732b2d5ea03 with the destination slot and selected label value, and returns.

The separator call may affect the later selector or label contents. Replacing the label-array global alone does not redirect this suffix lookup because its array address was retained earlier.

## Acceptance examples

These are conditional static acceptance cases, not executed tests. Except where mutation is specified, assume stable referenced state, returning dependencies, and valid accesses.

1. **Separate primary-table captures.** If the primary-table global remains stable across all four reads, A’s retained base and C–E’s bases share that origin with offsets 0, 296, 408, and 480. This relationship is conditional on stability, not guaranteed by one snapshot.

2. **Different values during capture.** If the primary-table global changes between its four reads, each retained base reflects its own observation and offset. A change before C’s read can alter C without retroactively changing A. This describes the access sequence, not a guarantee that concurrent mutation is supported.

3. **No table contains the category key.** Searches visit A through F in order, each stopping at a zero terminator. No category emission occurs. Initialization and final comparison still occur.

4. **A matches row 2 and all subsequent inherited probes are nonzero.** A is emitted. B, C, D, and E are probed at row 2 without being searched or emitted. F is skipped.

5. **A matches and its retained-address post-emission probe is nonzero, but B’s probe is zero.** B is not searched. C’s search starts at zero and may emit C, demonstrating that one invocation can emit multiple categories.

6. **A misses; B matches; B and C probes are nonzero; D’s probe is zero.** B is emitted. C and D are not searched. E’s search starts at zero.

7. **C matches, then an emission dependency changes its matched key to zero.** C’s fresh probe observes zero and starts D’s search. Reusing the earlier matching key would violate the established read order.

8. **The category byte remains zero.** No row matches because zero row keys terminate searches before comparison. Final comparison still decides whether a suffix is added.

9. **The comparison result is zero and the metadata minimum equals the reference result.** No suffix calls occur.

10. **The comparison result is zero but the metadata minimum differs.** A separator and suffix label are supplied. Selector 10 selects entry 5.

11. **The comparison result is nonzero.** The suffix path is taken regardless of metadata ordering. Both 1 and the all-one 32-bit value select that path.

12. **Metadata observations are 20 and 12.** The retained minimum is 12. With a zero comparison result and reference result 12, the suffix is omitted.

13. **The suffix separator call changes the selector to 8.** The subsequent selector read selects entry 3, irrespective of the selector’s earlier value.
