# F-f7394e0ee59f

## Purpose

F-f7394e0ee59f conditionally requests an operation based on a selector, a prerequisite check, and a state byte associated with a supplied object address.

Two selector values are recognized:

- Selector 1 requires a successful prerequisite check for value 1 and an object state byte equal to 2.
- Selector 2 requires a successful prerequisite check for value 2 and an object state byte equal to 1.

When both conditions for the selected case hold, the function invokes an action dependency with the selector value and returns 1. Otherwise, it returns 0.

The established behavior is this conditional dispatch. Interpreting the two cases as transitions between complementary states is plausible intent, but is not established: this function does not itself write the state byte, and the action dependency’s effects are unknown.

## Behavior

### Selector recognition

The selector is examined before either dependency is called.

If it is neither 1 nor 2, the function returns 0. That path has no direct object-memory read and no dependency invocation.

The two recognized cases are mutually exclusive. One invocation cannot enter both cases, and there is no fallback from one recognized case into the other.

### Prerequisite check

For selector 1, the function invokes F-8be29a2d06e5 with the integer value 1.

For selector 2, it invokes F-8be29a2d06e5 with the integer value 2.

The prerequisite result is tested for zero versus nonzero. It is not required to equal 1. Under the supplied integer representation, negative results and positive results other than 1 both satisfy the nonzero condition.

If the prerequisite returns zero, the function returns 0 without reading the object-state byte. If it returns nonzero, the function proceeds to the state read.

There is exactly one prerequisite invocation for a recognized selector on a normally progressing execution. No retry is shown.

### State observation and matching

After a nonzero prerequisite result, the function reads one byte at object offset 0x450.

The required byte value is complementary to the selector:

| Selector | Required state byte |
|---|---|
| 1 | 2 |
| 2 | 1 |

If the byte does not equal the required value, the function returns 0 without invoking the action dependency.

The read occurs after the prerequisite call returns. A conforming description must therefore use the byte observable at that point, not assume a snapshot taken before the prerequisite call. If that dependency changes the relevant memory through some independent means, the subsequent read can observe that change.

The evidence shows one direct state-byte read on a path that reaches this comparison. It shows no second validation before action dispatch and no readback afterward.

### Action dispatch and return

When the prerequisite result is nonzero and the state byte matches, the function invokes F-0c9c5c0621c3:

- With value 1 for selector 1.
- With value 2 for selector 2.

The action argument is the selector value, not the complementary state-byte value.

No action result is inspected. If the action dependency returns normally, this function returns 1 unconditionally. There is no local success check, rollback, or verification of a resulting state.

If a dependency does not return normally, the evidence provides no basis for claiming that this function reaches an explicit return.
