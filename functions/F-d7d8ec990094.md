# F-d7d8ec990094

## Purpose

F-d7d8ec990094 transfers three four-byte fields and one one-byte field from a source memory region to a destination memory region. Its destination footprint is 13 bytes, not a complete 16-byte record.

The transfer has a specific access order. The second and third source fields are captured before any destination write. The first source field is then transferred, followed by the captured fields. The final source byte is read only after all three four-byte destination writes have occurred.

This ordering matters when source and destination overlap. The behavior is not generally equivalent to copying a snapshot of the original 13 source bytes.

Established behavior is limited to this memory transfer. A higher-level interpretation, such as assigning a record containing three fields and a flag, is plausible but unproven.

## Behavior

### Access order

The visible operation establishes the following sequence:

1. Read the four-byte source field at offset 4 and retain its value.
2. Read the four-byte source field at offset 8 and retain its value.
3. Read the four-byte source field at offset 0 and write that value to destination offset 0.
4. Write the retained second field to destination offset 4.
5. Write the retained third field to destination offset 8.
6. Read the one-byte source field at offset 12.
7. Write that byte to destination offset 12.

The first and final transfers each require their source read before their corresponding destination write. No destination read is visible.

This is the ordering expressed by the supplied representation. It does not establish processor-level transaction boundaries, synchronization, or the exact instruction sequence used for these accesses.

### Nonoverlapping regions

For valid, stable, nonoverlapping regions, the destination receives the source’s three four-byte values and final byte. No destination byte beyond offset 12 is explicitly written.

The source is not explicitly modified. This conclusion depends on the regions being nonoverlapping and on ordinary memory behavior; it does not describe read side effects of devices or other specialized mappings.

### Identical regions

If source and destination identify the same valid storage, each field is written back with its own value, assuming no intervening external modification.

The operation still performs the visible reads and writes. Equal addresses do not trigger an early return or suppress writes.

### Partially overlapping regions

Overlap is not detected, rejected, or handled through a separate path. Its result follows from the access sequence.

The second and third source values are protected from subsequent destination overwrites because they are read before the first write. The final source byte is not protected in this way: it is read only after the three four-byte writes. If those writes overlap source offset 12, the byte transferred last can differ from the byte present at function entry.

The first source field is read after the second and third source fields, but before any destination write. Thus, in a stable single-threaded memory setting, all three four-byte values are obtained before this operation can overwrite them.

These properties do not amount to a general snapshot-copy guarantee. In particular, overlap can change the final byte’s source.

### Widths and address arithmetic

The visible field spacing is four bytes. The last field begins 12 bytes after the respective base address.

There is no data arithmetic, sign extension, truncation between the four-byte fields, or arithmetic on field values. The final transfer is one byte wide; it does not read a fourth four-byte source field.

Pointer width and address-overflow behavior are not established. The contract does not assume address wraparound makes an otherwise invalid region usable.

## Acceptance examples

These examples are conditional predictions from static evidence, not results of runtime tests. Unless otherwise stated, assume stable ordinary memory, valid accesses, supported alignment, and no external modification.

### Separate source and destination

Let the source contain four-byte values A, B, and C at offsets 0, 4, and 8, followed by byte T at offset 12.

Acceptance requires:

- Destination offsets 0, 4, and 8 contain A, B, and C respectively.
- Destination offset 12 contains T.
- Destination offsets 13–15 retain their prior contents, if those bytes exist.
- The source remains unchanged.

A transfer that overwrites all four bytes at destination offset 12 does not match the visible write footprint.

### Source equals destination

Given the same initial fields, the final bytes equal their initial contents.

Acceptance must not require the implementation to skip accesses. The visible behavior includes writes even though their ordinary-memory values are unchanged.

### Destination begins four bytes after source

Let the destination address equal the source address plus four bytes. Assume the combined region supports every required access.

The second and third original source fields, B and C, are captured first. The resulting destination fields are A, B, and C.

Writing C to destination offset 8 also writes it at source offset 12. Consequently, the final source-byte read obtains the byte of C stored at the lowest address of that four-byte write. That byte is then stored at destination offset 12.

Acceptance therefore requires that byte, not necessarily the original T. Its relationship to the numeric value of C depends on representation; it must not be described unconditionally as C’s least-significant byte.

### Destination begins four bytes before source

Let the destination address equal the source address minus four bytes, with sufficient valid storage.

The three destination fields become A, B, and C. Although the writes overwrite some source fields, B and C were already captured. None of those three writes reaches source offset 12, so the final destination byte receives the original T.
