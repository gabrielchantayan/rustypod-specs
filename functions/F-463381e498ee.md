# F-463381e498ee

## Purpose

F-463381e498ee mutates memory through a fixed sequence of byte, halfword, and word accesses, captures a destination from memory, and transfers control through that destination. Its address calculations depend on explicit arguments, additional incoming machine state, and values read during execution.

The supplied static representation establishes an access sequence, not an application-level purpose. It does not establish that the accessed locations belong to objects, that the mutations maintain a data structure, or that the final destination belongs to a valid dispatch table.

This contract describes the represented behavior without assuming valid addresses, successful completion, ownership of affected memory, or preservation guarantees from the destination.

## Interface

### Explicit arguments

| Argument | Represented width | Established role |
|---|---:|---|
| Address displacement | Signed 32 bits | Added to two incoming values to form the initial write addresses. |
| Opaque argument | 32 bits | Not explicitly read by the represented body. |
| Selector word | Unsigned 32 bits | Its most significant byte determines a scaled offset. |

Only bits 31–24 of the selector word directly influence the body. Their unsigned value is multiplied by four, producing the **selector offset**, a multiple of four between 0 and 1020 inclusive. This calculation does not overflow a 32-bit signed or unsigned integer.

The opaque argument has no explicit use. That does not establish whether its incoming machine location remains observable to the final destination.

### Additional incoming state

The body consumes two 32-bit incoming values whose definitions are absent:

- **Incoming base:** contributes to the first write address and a later byte-read address.
- **Incoming word:** supplies the first word-store payload and contributes to the second write address.

Their provenance and calling-convention roles are unknown. They must not be assumed to equal any explicit argument or any value read from memory.

The body also depends on:

- A storage location supplying a 32-bit **seed**.
- Byte storage represented at absolute addresses 0xC4 and 0xCB.
- Storage reached through calculated addresses.
- A separate storage location supplying a late 32-bit invocation argument.

The seed and late-argument locations are distinct dependencies in the representation; their addresses and possible overlap with other accesses are not established here.

### Result and completion

The represented interface has no return value. The final indirect transfer is represented as an invocation whose result is unused, followed by a return.

The static material explicitly leaves uncertainty about whether the underlying transfer is a conventional call. Consequently, returning to the caller is conditional on the represented invocation model being accurate and the destination returning normally.

There is no represented status result, validation failure result, or recovery branch.

### Widths and memory interpretation

The explicitly typed data accesses use:

- 8-bit bytes.
- 16-bit halfwords.
- 32-bit words.

Byte values used in address calculations are zero-extended. Narrow stores preserve the low bits of their source: eight bits for a byte store and sixteen bits for a halfword store. One final address calculation uses a signed 16-bit load, with values from −32768 through 32767.

A function-pointer value is also loaded. Its exact storage width and encoding are not independently established by the supplied material. The surrounding integer representation supports a 32-bit address model, but this is not sufficient to resolve every pointer or ABI detail.

Byte order, alignment requirements, signed-overflow behavior, and address-space rules remain unspecified. Address formulas below describe the represented operands and additions; they do not impose wrapping or validity rules absent from the evidence.

## Behavior

The following order is established by the supplied static representation. Descriptive names identify captured values, not object fields or source-level variable identities.

### Initial capture and mutation

The seed is read before either initial store.

| Order | Access | Address | Payload |
|---:|---|---|---|
| 1 | 32-bit write | Incoming base plus address displacement | Incoming word |
| 2 | 16-bit write | Address displacement plus incoming word | Low 16 bits of the seed |

The second address uses the incoming word itself, not a value reloaded from the first destination.

If the first store overlaps the seed’s storage, the second store still uses the previously captured seed. If the two destinations overlap, the later halfword store determines the overlapping bytes under ordinary sequential-memory semantics. Their exact byte values depend on byte order.

### Control and byte captures

After the initial writes, the routine reads a byte from 0xC4, called the **early control byte**. It then derives the selector offset.

The subsequent reads occur in this order:

| Order | Read address | Captured value |
|---:|---|---|
| 1 | 0xCB | **Index byte** |
| 2 | 0xC4 | **Late control byte** |
| 3 | Incoming base plus 0x13 | **Base byte** |
| 4 | Zero-extended index byte plus 6 | **Linked byte** |
| 5 | Selector offset plus 2 | **Selected byte** |

These are byte reads. The two reads from 0xC4 are separate observations. Although no explicit store lies between them, the contract does not assume stable storage or exclude external changes.

All values in this group are captured before the next six stores. None is reloaded during that store group.

### Six byte mutations

The routine performs six byte stores in this order:

| Order | Destination | Payload |
|---:|---|---|
| 1 | Selected byte plus 0x1D | Base byte |
| 2 | Selector offset plus 0x19 | Linked byte |
| 3 | Selector offset plus 0x14 | Selected byte |
| 4 | Late control byte plus 0x0E | Early control byte |
| 5 | Linked byte plus 9 | Selected byte |
| 6 | Base byte plus 3 | 0xAC |

Each byte-derived address component is nonnegative, between 0 and 255 before the stated addition. These formulas do not include an identified allocation base. For example, a selected byte of 0xFF contributes 255, not −1.

Destinations may coincide or overlap storage used elsewhere. A later store supersedes an earlier store at the same byte address under ordinary sequential-memory semantics. Overwriting the original storage of a captured byte does not change the captured value.

### Word captures and mutations

After the six byte stores, three 32-bit reads occur:

| Order | Read address | Captured value |
|---:|---|---|
| 1 | Index byte plus 0x5C | **First link word** |
| 2 | Base byte plus 0x40 | **Transfer word** |
| 3 | Selected byte plus 0x24 | **Second link word** |

The two link words later participate in address calculations. Their names do not establish pointer validity, object membership, or ownership. The transfer word is an uninterpreted 32-bit payload.

All three reads precede these four 32-bit stores:

| Order | Destination | Payload |
|---:|---|---|
| 1 | First link word plus 0x6C | Selector offset |
| 2 | Selected byte plus 0x4C | Zero-extended index byte |
| 3 | Second link word plus 0x2C | First link word |
| 4 | Selected byte plus 0x0C | Transfer word |

These are full word stores. In particular, storing the index byte writes its zero-extended 32-bit value, not merely its low byte.

Earlier byte mutations can affect these word reads if their ranges overlap. The four word stores cannot retroactively change the three captured words, but they can affect subsequent reads.

### Final captures

The routine next obtains the following values in order:

1. A byte at second link word plus first link word, called the **terminal byte**.
2. A 16-bit payload at selector offset plus first link word, called the **call halfword**.
3. A function-pointer value at selector offset plus index byte, called the **captured destination**.
4. A signed 16-bit value at first link word plus 0xAC, called the **terminal displacement**.

The pointer-storage address need not be aligned: the selector offset is divisible by four, but the index byte need not be.

The terminal displacement is signed. A stored halfword pattern of 0xFFFF therefore contributes −1, not 65535, to the next destination calculation.

### Final mutations

Using those captures, the routine performs three stores:

| Order | Width | Destination | Payload |
|---:|---:|---|---|
| 1 | 8 bits | Second link word plus terminal displacement | Low 8 bits of the second link word |
| 2 | 16 bits | Captured destination plus second link word | Low 16 bits of the captured destination’s represented address |
| 3 | 32 bits | Second link word plus zero-extended terminal byte | Zero-extended terminal byte |

The second store uses the captured destination both as an address component and as the source of a narrowed payload. The representation does not establish a portable interpretation of function-pointer arithmetic or function-pointer narrowing. The table preserves the represented relationship without asserting an independently verified encoding.

The captured destination and call halfword are not reloaded after these stores. Overwriting either original storage location does not select a new destination or payload. This capture rule does not guarantee unchanged executable contents if a store modifies memory used for execution.

### Indirect transfer

After all fifteen explicit stores, the routine obtains a 32-bit value from the late-argument storage location and presents three represented arguments to **F-U1** through the captured destination:

| Position | Argument |
|---:|---|
| 1 | Selector offset |
| 2 | Late-read 32-bit value |
| 3 | Captured call halfword |

The second argument is a late observation, not an entry-time snapshot. Any preceding store that overlaps its storage can affect it.

The third argument has an established 16-bit payload. Its wider ABI slot, extension rules, and interpretation by F-U1 are unknown.

No destination validation, argument validation, or explicit recovery path precedes the transfer.

## Acceptance examples

These examples are conditional static consequences, not runtime tests. Each assumes that the relevant arithmetic, accesses, and transfer are supported. Where final memory contents are stated, ordinary sequential-memory semantics and the absence of later overlapping writes are also required.

### Selector extraction

Selector words 0x12000000 and 0x12FFFFFF both produce selector offset 0x48. With otherwise equivalent inputs and memory observations, their low 24-bit difference does not directly alter the represented body.

A top byte of 0 produces offset 0. A top byte of 0xFF produces offset 1020. The resulting offset is the first represented argument to F-U1.

### Separate control observations

If the early control read produces 0x12 and the late control read produces 0x34, the fourth store in the six-byte group writes 0x12 at address 0x42.

The example does not require or identify a mechanism for changing the storage between reads.

### Unsigned byte addressing

If the selected byte is 0xFF, the first store in the six-byte group targets address 0x11C. A negative interpretation of that byte would not satisfy the represented calculation.

### Captured input survives an overlapping write

If the first initial store overwrites the seed’s storage, the following halfword store still uses the seed captured before that overwrite. It does not reload the seed.

### Full-width index store

If the index byte is 0xFF, the second store in the four-word group writes the 32-bit value 0x000000FF. It is not a one-byte write, and it does not write a sign-extended value.

### Negative terminal displacement

If the terminal displacement has halfword pattern 0xFFFF, the first final store targets one byte below the second link word’s address, where supported. Its payload is the low byte of the second link word.

### Captured destination and late argument differ in timing

If a final store overwrites the destination’s original storage slot, the transfer still uses the captured destination.

If a final store instead changes the late-argument storage, the second argument reflects the later read of that storage. The two dependencies therefore have different capture times.

### Store accounting

An execution that reaches the indirect transfer has performed seven byte stores, two halfword stores, and six word stores in this body. Coincident destinations do not reduce these operation counts. A failure before the transfer can leave only a prefix completed.

### Partial mutation on failure

If the function-pointer read is unsupported after all preceding accesses succeed, the earlier stores are not accompanied by any represented rollback, and the transfer need not occur.

Established static observations include:
