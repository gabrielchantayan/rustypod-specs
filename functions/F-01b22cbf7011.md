# F-01b22cbf7011

## Purpose

F-01b22cbf7011 conditionally initializes a control area near the end of a caller-supplied region and delegates work in batches. It records an initial dependency result, accumulates delegated item counts, and records a further dependency result after each batch.

An inactive state returns immediately. An active state with a nonzero operation selector invokes an indirect callback instead of initializing or processing the region.

The static evidence establishes control flow, argument construction, memory accesses, and return selection. It does not establish the application meaning of the region, the arithmetic dependency, or the delegated operations. “Region,” “item,” “stride,” and “progress” below are descriptive terms, not proven domain semantics.

## Interface

The function accepts five arguments:

| Argument | Observed representation | Role |
|---|---|---|
| State address | Pointer to a structure accessed through 32-bit words | Supplies activation state, an indirect-call table, arithmetic parameters, and a writable control-area address field. |
| Region base | 32-bit address-valued argument | Used to locate the control area and form batch addresses. |
| Region extent | Unsigned 32-bit value | Used in endpoint alignment and an arithmetic dependency argument. |
| Operation selector | 32-bit integer | Zero selects initialization and batching; nonzero selects the indirect callback when the state is active. |
| Mode address | Pointer to at least one readable byte on paths that inspect it | An exact byte value of 1 suppresses initial batching or stops batching after a completed batch. |

The return value is 32 bits. Directly established return cases are:

- **3:** state is inactive, or the nonzero-selector callback path finishes.
- **2:** initialization finishes with the mode byte equal to 1, or a completed batch is followed by a mode-byte read equal to 1.
- **0:** initialization permits batching, but the derived total item count is zero.
- **Last batch dependency result:** the loop reaches its count-based completion condition after at least one batch.

These are return values, not established success or error classifications. A delegated result equal to 2 or 3 is indistinguishable at this interface from the corresponding direct return value.

### State layout

Offsets are byte offsets from the state address. Each listed field is accessed as a 32-bit word.

| Offset | Observed use |
|---|---|
| `0x000` | Address of a table used for indirect dispatch. |
| `0x010` | Activation field; zero is inactive, any nonzero value is active. |
| `0x428` | First operand of a subtraction used to derive an available amount. |
| `0x438` | Stride-like arithmetic parameter; initially cached, and later reread for batch-address construction. |
| `0x43C` | Argument to the initial F-8abffcbfb4aa call and second operand of the available-amount subtraction. |
| `0x440` | Destination for the computed control-area address. |

The dispatch table is accessed at byte offset `0x24` to obtain the callback target.

### Memory preconditions

The function performs no visible null, extent, alignment, writability, or overlap checks.

For a path to complete normally, every access taken on that path must be valid. In particular:

- The activation word must be readable.
- The callback path requires valid table and target accesses.
- Initialization requires the state destination word and four region-relative words to be writable.
- A mode-byte read requires a valid readable mode address.
- Dependencies may impose additional requirements not established here.

No allocation, ownership transfer, or release is directly visible. Passing an address to a dependency does not establish whether that dependency retains, modifies, or releases associated storage.

## Behavior

### 1. Activation and operation selection

The activation word at state offset `0x010` is read first.

If it is zero, the function returns 3. It does not directly initialize the region, read the mode byte, or call the dependencies described below.

If activation is nonzero and the operation selector is nonzero:

1. The table address is read from state offset `0x000`.
2. The callback target is obtained from table offset `0x24`.
3. That target is invoked with the state address as its sole visible argument.
4. If the callback returns normally, this function returns 3, regardless of the callback’s result.

The activation word is not visibly rechecked.

### 2. Control-area initialization

For an active state and a zero operation selector, define the endpoint as the region base plus the region extent with its lowest two bits cleared.

Clearing those extent bits rounds the **extent** down to a multiple of four. It does not ensure an aligned endpoint if the region base is unaligned.

The following operations occur in order:

1. Store the endpoint minus 28 at state offset `0x440`.
2. Store a 32-bit zero at endpoint minus 4.
3. Store a 32-bit zero at endpoint minus 8.
4. Read state offset `0x43C` and invoke F-8abffcbfb4aa with the state address and that value.
5. Store the returned 32-bit value at endpoint minus 12.
6. Store a 32-bit zero at endpoint minus 16.
7. Read the mode byte.

Relative to the stored control-area address, the directly initialized words are:

| Relative offset | Initial contents |
|---|---|
| `+12` | Zero; subsequently replaced after each batch by an F-8abffcbfb4aa result. |
| `+16` | Initial F-8abffcbfb4aa result. |
| `+20` | Zero; subsequently incremented by each batch’s item count. |
| `+24` | Zero. |

The first 12 bytes beginning at the stored control-area address are not directly initialized by this function. The evidence does not establish their purpose or contents.

If the mode byte is exactly 1, the function returns 2 immediately after initialization. Other byte values, including other nonzero values, proceed to batch setup.

### 3. Batch setup

The arithmetic is described using 32-bit quantities. Unsigned comparisons are significant. Products, subtractions, and increments used as unsigned values retain their low 32 bits; they are not unbounded mathematical arithmetic.

Let:

- **S** be the word read from state offset `0x438` after the initial mode check.
- **H(a, b)** denote a call to F-d7be9cfb4000 with arguments `a` and `b`.
- **Q** be the result of H(65,536, S).
- **N₀** be the result of H(region extent minus 16, S plus 12).
- **D** be the unsigned difference between state offsets `0x428` and `0x43C`, read after those two dependency calls.
- **P** be the low 32 bits of N₀ multiplied by S.

The two calls to H occur in the order shown. The available-amount fields are read afterward, so dependency mutations of those fields can affect D.

The total item count **N** and total amount **T** are selected as follows:

- If D is not less than P under unsigned comparison, N is N₀ and T is P.
- If D is less than P, another call computes H(D, S). Its result becomes N, and T becomes D.
- In that latter case, if the low 32 bits of N multiplied by S are less than D under unsigned comparison, N is incremented once.

This resembles a capacity calculation followed by a ceiling adjustment, but that interpretation depends on H’s unknown semantics. The contract does not assume H performs division.

The source supplies no guard against:

- An extent below 16, whose subtraction produces a wrapped unsigned argument.
- Zero or unusually large S.
- Overflowing products.
- Wrapped differences between the state fields.
- A zero Q.
- Arithmetic-dependency results inconsistent with the apparent batching intent.

### 4. Batch execution and termination

The loop begins with:

- Scheduled position zero.
- Remaining item count N.
- Remaining amount T.
- Last batch result zero.

Before each possible batch, the loop compares the scheduled position against N using unsigned ordering. If the scheduled position is at least N, it returns the last batch result. Thus N equal to zero returns 0 without invoking the batch dependency.

For each batch:

- The selected item count is the unsigned minimum of the remaining item count and Q.
- The selected amount is the unsigned minimum of the remaining amount and the low 32 bits of S multiplied by Q.
- The batch address is the region base plus the scheduled position multiplied by a **fresh read** of state offset `0x438`.

The cached S controls the amount calculation. The freshly read state value controls the batch address. They need not remain equal if dependencies modify the state.

The function invokes F-0a6cbb6f26d1 with:

1. The state address.
2. The computed batch address.
3. The selected amount.
4. The selected item count.

Its return value replaces the last batch result. No visible success/failure test is applied to that value.

After the call returns, the function:

1. Subtracts the selected item count from the remaining item count.
2. Subtracts the selected amount from the remaining amount.
3. Reads the word at endpoint minus 8, adds the selected item count, and writes the result back.
4. Calls F-8abffcbfb4aa with the state address and T minus the remaining amount.
5. Stores that dependency’s result at endpoint minus 16.
6. Reads the mode byte.

If the mode byte is 1, the function returns 2, overriding the last batch result.

Otherwise, the scheduled position advances by Q, not by the selected item count, and the loop condition is evaluated again.

The endpoint used by these updates is the originally computed endpoint. It is not recovered from the state field at `0x440`; changing that field does not redirect these direct writes.

There is no independent termination check based on remaining bytes, remaining items, or the batch result. In particular, Q equal to zero with N greater than zero does not advance the scheduled position. Normal termination is then not guaranteed; a mode change to 1 can still end the loop after a batch.

## Side effects

Directly established writes are limited to:

- State offset `0x440`.
- Endpoint minus 4.
- Endpoint minus 8.
- Endpoint minus 12.
- Endpoint minus 16.

The word at endpoint minus 8 is updated by read-add-write after every batch. It is not recomputed solely from internal counters. Changes made to that word by a dependency therefore affect the next accumulated value.

Dependency side effects are unknown. They may affect later state reads, mode reads, or region accesses. No preservation of globals, state fields, or caller-owned memory is assumed.

Overlap is not checked. If state storage, region control words, or the mode byte overlap, earlier writes can change later reads. The layout and ordering above remain applicable; an independent-buffer interpretation does not.

No rollback is visible. If execution faults or a dependency does not return, initialization or earlier batch updates may already have occurred.

No synchronization or atomicity guarantee is established for the counter update, mode observation, or state accesses.

## Acceptance examples

These are conditional static acceptance examples, not executed tests. Unless stated otherwise, accesses are valid, buffers do not overlap, dependencies return normally, and dependencies leave relevant state and control words unchanged.

1. **Inactive state**

   With activation zero, the result is 3. There are no direct region writes, mode-byte reads, or dependency calls, regardless of the operation selector.

2. **Nonzero selector**

   With activation nonzero and selector nonzero, exactly the indirect callback path is taken. If the callback returns, the result is 3. Control-area initialization is not performed.

3. **Immediate mode stop**

   With activation nonzero, selector zero, and the first mode-byte read equal to 1, initialization and the initial F-8abffcbfb4aa call occur. Neither arithmetic setup nor batch execution occurs. The result is 2.

4. **Zero derived count**

   If the initial mode read is not 1 and setup yields N equal to zero, no batch call occurs. The result is 0, and the count word remains at its initialized zero under the stated preservation assumptions.

5. **Two batches with a short final batch**

   Suppose S is 16, Q is 4, N is 6, and T is 96. The two batch calls receive item counts 4 and 2, and amounts 64 and 32. With the state stride unchanged, their addresses are the region base and region base plus 64.

   The count word becomes 4 and then 6. The subsequent F-8abffcbfb4aa calls receive amount arguments 64 and 96. If neither post-batch mode read is 1, the function returns the second batch result.

6. **Stop after delegated work**

   If a batch returns some value R and the following mode read is 1, the counter update and progress-result store still occur. The function returns 2, not R.

7. **Zero batch quantum**

   If Q is zero and N is positive, each batch receives zero items and zero amount. The scheduled position remains zero. If the mode never becomes 1 and dependencies continue returning, this path does not reach count-based completion.

8. **Extent underflow**

   An extent of 8 supplies H with `0xFFFFFFF8` as the first operand of the extent-minus-16 calculation. There is no local rejection of this input. Subsequent behavior depends on H’s result and memory validity.
