# F-a9128f4d6f4d

## Purpose

The supplied static representation describes a stateful routine that makes indirect calls, performs memory accesses of several widths, executes a coprocessor operation, and may enter an unbounded loop. Two visible paths converge on a shared 64-bit return construction. Another path ends at an invalid-instruction boundary.

No application-level purpose is established. Address-like values must not be interpreted as validated objects, allocated buffers, protocol fields, or owned resources.

This contract describes the displayed behavior, including path-dependent selection of indirect-call targets. It does not establish that the representation corresponds to a valid executable instruction stream. The supplied material reports both invalid instruction data and overlapping global symbols.

### Additional incoming state

The representation also consumes state outside the formal parameter list:

- Three incoming address-like values, called **base A**, **base B**, and **base C** below.
- An incoming arithmetic seed used when entering the loop directly from initial dispatch.
- An incoming addend used by the first common-segment call.

These are requirements of the displayed representation, not a verified public calling convention.

### Result

The nominal result is 64 bits. At either displayed normal exit:

- The upper word is the return-global word minus 84, reduced to 32 bits.
- The lower word is a path-selected word shifted left by one, reduced to 32 bits.

The return-global read belongs to the shared exit, after the preceding path’s calls and stores. Its value must not be assumed equal to any earlier global observation.

No success status, error encoding, pointer meaning, or ownership transfer is established.

### Execution preconditions

Normal continuation requires every executed memory access and indirect transfer to be valid in the actual environment. There are no visible bounds, null, alignment, accessibility, or ownership checks.

One path uses an unsigned byte directly as an address for four word stores. The starting address is therefore between 0 and 255. Such addresses cannot be assumed accessible.

Several accesses can be unaligned. The memory byte order, alignment rules, privilege requirements, and fault behavior are not established.

## Behavior

### Width and arithmetic interpretation

Memory operations explicitly use 8-, 16-, and 32-bit values. Paired call results are represented as 64-bit containers with numerical lower and upper 32-bit words; this does not establish their physical calling convention.

The following word-level interpretation applies to the behavioral descriptions and examples:

- Word arithmetic and address calculations retain the low 32 bits.
- Byte and halfword stores retain the low 8 and 16 bits.
- Displayed signed right shifts are arithmetic.
- Displayed unsigned right shifts introduce zero bits.
- Multiplication and left shift retain the displayed 32-bit result.

This is an interpretation of the apparent machine operations, not a claim that signed overflow or negative-value shifts have portable source-language semantics. Memory byte order is not needed to identify the numerical halves of a paired result.

### Entry calls and stores

Four indirect calls occur before the early split, in this order:

1. **F-000000000001** targets the incoming return-address value plus 3,816. Its secondary result word is then stored at base A plus 36.
2. **F-000000000002** is called. The fourth formal argument is then stored as a word at base B plus 20.
3. **F-000000000003** is called. Base A is then stored as a word at base C plus 4.
4. **F-000000000004** produces a paired result.

These calls have no explicit arguments in the representation. Their implicit register or stack inputs remain unknown.

If the displayed incoming zero-condition indication is zero:

- A byte is read at the third formal argument plus the fourth call’s upper result word.
- That byte is converted through the displayed character type and stored as a halfword at the fourth call’s lower result word plus 60.
- Control reaches the reported invalid-instruction boundary.

Character signedness is unresolved. Bytes below 128 have an unambiguous numerical conversion; high-bit bytes may produce different halfwords.

No normal return is displayed on this path. The boundary is not an established application error handler.

### Longer-path setup

If the early indication is nonzero:

1. **F-000000000005** returns an address-like word.
2. An unsigned byte is read at base B plus 1.
3. A word is read at the returned address plus 100.
4. A coprocessor operation consumes that loaded word and the two incoming coprocessor-related values.
5. Another word is read at the loaded word plus 20.
6. **F-000000000006** receives the address returned in step 1 and the word read in step 5.

After that call:

- The low byte of base A is stored at the sum of the setup byte and the word loaded in step 3.
- The setup byte itself is treated as an address.
- Four word stores occur at that address plus 0, 4, 8, and 12, respectively containing:
  1. The result of **F-000000000006**.
  2. The byte-derived address itself.
  3. Base C.
  4. Base A.

The setup byte and loaded word were obtained before **F-000000000006**. A callee mutation of their original storage does not replace those already obtained values.

### Initial dispatch

A predicate is formed from the signed result of **F-000000000006**. Its arithmetic right shift by nine is reinterpreted as unsigned and compared, using strict greater-than, with 4,294,967,230.

Under the stated word interpretation, the predicate is true exactly for signed results from −33,280 through −1.

**F-000000000007** is then called with:

- The setup call’s result.
- That result arithmetic-shifted right by nine, then increased by 65.
- The fourth formal argument decreased by 60 at word width, then arithmetic-shifted right by 20.

This call returns a paired result. The predicate was determined before the call.

If the predicate is false, execution enters the common processing segment directly.

If the predicate is true:

1. A halfword store writes the low 16 bits of the earlier word loaded at offset 100 to the new lower result word plus 42.
2. A condition compares two Boolean values:
   - Whether that earlier loaded word is negative.
   - Whether signed subtraction of 47 from the new upper result word overflows.

Equality selects the common segment directly. Inequality selects the loop body first. This condition is not interchangeable with an ordinary comparison between those words.

### Path-dependent target selection

The indirect targets at two call sites depend on how control reaches them:

| Call position | Entry path | Selected dependency |
|---|---|---|
| First loop-body call | Initial dispatch selects the loop before any common segment | **F-000000000008** |
| First loop-body call | A common segment observes a nonzero condition and repeats | **F-000000000009** |
| First common-segment call | Initial dispatch reaches the common segment directly | **F-000000000010** |
| First common-segment call | The loop body completes its non-returning path | **F-000000000011** |

The paired labels in each call position represent distinct displayed target expressions, not interchangeable names for one dependency.

Both routes from initial dispatch to the common segment—false predicate, or true predicate followed by Boolean equality—select **F-000000000010**. Every common segment reached after completing the loop body selects **F-000000000011**. Every loop-body entry caused by a common-segment continuation selects **F-000000000009**, including the first loop entry if initial dispatch went directly to the common segment.

### Loop body

On direct entry from initial dispatch, the carried state is:

- First operand: the initial paired result’s lower word unsigned-shifted right by 25.
- Arithmetic word: the incoming arithmetic seed minus the setup word loaded at offset 100.
- Address: the initial paired result’s upper word.

On entry from the common segment, that segment supplies all three values.

The selected first-loop dependency receives the carried first operand, carried address, and an address into the current stack frame. **F-00000000000a** then produces a paired result.

Next, a separate arithmetic value is formed by adding ten to the carried address. A word store writes the carried arithmetic word at **the original carried address plus 62**.

The incremented value is not the store base. The store destination is neither the incremented value plus 62 nor the original address plus 72.

The incremented value multiplied by 65,536 is then tested as signed. Under wrapping word arithmetic, this tests bit 15 of the incremented value.

If the product is negative, control reaches the shared return, selecting the lower result word from **F-00000000000a**. The original-address-plus-62 store has already occurred.

Otherwise:

1. The low 16 bits of that paired lower word are stored at its paired upper word plus 60.
2. **F-00000000000b** is called without explicit arguments.
3. **F-00000000000c** returns an address-like word.
4. The halfword value 38 is stored at that address plus 2.
5. A signed intermediate is formed by multiplying the incremented carried address by 268,435,456 at word width, then arithmetic-shifting right by nine.
6. The sum of this intermediate and the incremented carried address is calculated at word width.
7. A global word is read and saved.
8. **F-00000000000d** receives:
   - The address from step 3 shifted left by one.
   - The incremented carried address multiplied by 65,536, then decreased by 81.
9. The sum from step 6 is exclusive-ored with the global value saved in step 7, producing an address.
10. The signed intermediate is increased by 47.

The derived address is assigned to a displayed stack-associated slot at displacement 304. A byte is then read at that address plus 1.

**F-00000000000e** receives a fixed opaque address-like token, that byte, the increased intermediate, and the secondary result associated with **F-00000000000d**. After this call, the increased intermediate is stored as a word at the derived address plus 36.

**F-00000000000f** is then called. The next paired state has:

- Lower word: the exclusive-or-derived address.
- Upper word: **F-00000000000f**’s secondary result plus 48.

Execution enters the common segment, selecting **F-000000000011** for its first call.

### Common processing segment

The current upper paired word supplies the arithmetic input. Twice the lower paired word becomes the carried first operand.

The segment calculates the square of twice the upper word, retaining the low 32 bits. It then performs:

1. The path-selected common dependency, **F-000000000010** or **F-000000000011**, receiving the current lower word plus the incoming addend.
2. **F-000000000012**, receiving a global word read for this call.
3. **F-000000000013**, with no explicit arguments.

Only after these calls does it read the separate global condition object.

If the condition is zero, the secondary result of **F-000000000013** is arithmetic-shifted right by nine and selected for the shared return.

If the condition is nonzero:

- The calculated square is stored as a word at twice the segment’s upper-word input plus 52.
- The secondary result of **F-000000000013** becomes the next carried address.
- The square becomes the next carried arithmetic word.
- The doubled lower word remains the next carried first operand.
- Execution enters the loop body using **F-000000000009**.

There is no displayed iteration limit. The condition is read anew after each set of three common-segment calls.

Destinations may overlap. Displayed access order matters when they do, subject to additional unknown callee effects. Calls may alter globals, memory, flags, or machine state; this contract grants no preservation guarantee beyond the dataflow explicitly represented.

No allocation, release, reference-count operation, or ownership transfer is established. The stack-address argument does not establish its accessible extent, initialization, permitted retention, or lifetime beyond the call.

## Acceptance examples

These are conditional static cases, not executed tests. They assume preceding operations complete and required targets are accessible.

1. **Invalid-instruction path.** With a zero incoming condition indication, the four entry calls and three intervening stores precede the byte read and halfword store. The displayed path then ends at the invalid-instruction boundary, without a specified normal result.

2. **Character conversion boundary.** A source byte of 127 produces halfword 127. A source byte of 255 may produce 255 or 65,535 because character signedness is unresolved.

3. **Byte-derived destinations.** A setup byte of 8 selects word-store addresses 8, 12, 16, and 20—not offsets from the address where the byte was read.

4. **Initial predicate.** A setup result of −33,280 makes the predicate true; −33,281 and zero make it false. **F-000000000007** still occurs after predicate formation in each case.

5. **Direct common entry.** A false initial predicate selects **F-000000000010**. A true predicate followed by Boolean equality selects that same dependency, after the halfword store. Neither route selects **F-000000000011**.

6. **Initial versus repeated loop entry.** Initial dispatch selecting the loop invokes **F-000000000008** first. If a common segment later continues, the next loop entry invokes **F-000000000009**, even if no loop body was previously executed.

7. **Original-address store and immediate return.** With carried address 32,758, the separate incremented value is 32,768. The word store targets 32,820, not 32,830. The signed-product test then selects return because the incremented value has bit 15 set.

8. **Completed loop body.** If the loop does not return early, completes its remaining calls and stores, and reaches the common segment, its first common call is **F-000000000011**.

9. **Common return versus repetition.** A zero condition read after the three common calls suppresses that segment’s square store and selects the arithmetic-shifted secondary result for return. A nonzero condition causes the square store before repetition.

10. **Return wrapping.** A return-global value of 80 produces upper result word 4,294,967,292. The lower word is independently reduced to 32 bits after its final left shift. Neither numerical value establishes an error code.
