# F-a5a48d5c4640

## Purpose

F-a5a48d5c4640 performs a straight-line sequence of indirect calls, low-address memory accesses, word transfers, byte updates, and global-state replacements.

**Established static behavior:** the supplied representation contains no explicit conditional branches or loops. If every call returns normally and every memory access succeeds, execution reaches an indirect call whose target is zero, followed by a nominal return.

**Inferred intent:** some operations resemble transfers between indexed records, compact selectors, and byte-sized state fields. The evidence does not establish a domain-level purpose, valid object model, or meaningful success condition. This contract therefore specifies the observable operations without labeling them as initialization, allocation, dispatch, or cleanup.

**Execution status:** no runtime tests have been performed. The following requirements describe the supplied static representation, not verified machine behavior.

## Interface

### Explicit inputs and result

The represented interface has three explicit inputs:

| Input | Represented width | Established direct use |
|---|---:|---|
| First input | 32 bits | No explicit value use in the body |
| Second input | 32 bits | No explicit value use in the body |
| Third input | Unsigned 32 bits | Logically shifted right by 23; the resulting value participates in an address calculation and a word store |

The represented result is void. Results of intermediate calls are consumed internally; no explicit result is returned to the caller.

The absence of explicit uses of the first two inputs does **not** establish that they are irrelevant to the executable behavior. Indirect calls have unresolved calling conventions and may observe incoming register state.

### Additional incoming and call-produced state

The function also depends on:

- An incoming link-register-like value used to form the first indirect call target.
- An incoming 32-bit register value later written to memory.
- Secondary-register outputs of several calls, used as indices, pointers, and repeated arguments.
- Three global locations, described below as **G1**, **G2**, and **G3**.
- A byte read from address 1 on multiple occasions.
- Memory at addresses calculated from helper results and extracted bit fields.

These are behavioral inputs even though they are absent from the three-argument interface.

### Width and notation

For this contract:

- A **byte**, **halfword**, and **word** are respectively 8, 16, and 32 bits.
- A **wide result** is the represented 64-bit result of a call. Its low and high halves are each 32 bits.
- **Low byte** means the least significant eight bits of a value, not necessarily the byte stored at the lowest address.
- Unsigned right shifts insert zeros.
- Byte stores discard all but the low eight bits.
- The expression “scaled by four” describes the represented multiplication or left shift; it does not establish a valid allocation or record type.

The representation strongly suggests a 32-bit address environment. Signed multiplication, signed left shifts, overflow, and pointer conversion are not sufficiently specified to establish portable arithmetic semantics. Acceptance examples involving such operations assume values for which the distinction does not arise.

### Preconditions

Normal progression requires all reached call targets to be callable and all reached memory locations to support the indicated access widths. This includes low addresses, potentially unaligned word accesses, a helper-produced byte pointer, and eventually call target zero.

No bounds, null, alignment, or permission checks are visible. No general safe-input range can be derived because dependencies can supply arbitrary addresses and indices.

## Behavior

The following phases specify the order of explicit operations. Calls between memory operations are significant: their effects are unknown, and they must not be treated as inert separators.

### 1. Initial word publication and clearing

1. Invoke the entry-context-derived dependency.
2. Invoke another dependency and retain its word result.
3. Extract the third input’s upper nine bits by logically shifting it right by 23. Call this value **input selector**; its range is 0–511.
4. Pass the retained word result to a dependency.
5. Continue through the intervening indirect calls until a call supplies an integer index.
6. Store the incoming auxiliary register word at address **four times that index, plus 20**.
7. Pass the scaled index, without the added 20, to the next dependency.
8. Continue through further calls.
9. Using the represented secondary-register output, store a zero word at **four times that output, plus 20**.
10. Invoke the next dependency with that secondary-register output.

The index used for the second store is not established to be the index used for the first.

### 2. Input-selector storage and first byte update

After another result-forwarding call sequence:

1. Obtain a new integer index.
2. Store the input selector as a word at **four times that index, plus 20**.
3. Read a word from an address formed by masking the applicable secondary-register output with `0x1fffffff`, shifting right by 19, and adding 20. Preserve this word as **first sampled word**.
4. Invoke the next dependency with the scaled index, then execute the intervening calls.
5. Shift the first sampled word logically right by 22. Preserve the resulting value as **first extracted field**; it is in the range 0–1023.
6. Read a byte from **input selector plus 1**.
7. Store the low byte of the first extracted field at **that byte value plus 17**.
8. Invoke a dependency with four explicit arguments: the current represented secondary-register word repeated three times, followed by zero.

The word read precedes the intervening calls. The selector-byte read follows them. Consequently, a dependency may affect which byte destination is selected without changing the already sampled word.

### 3. Byte clearing and a second extracted selector

The next sequence includes:

1. A dependency invocation with explicit argument zero, obtained by shifting a locally established zero right by 23.
2. Further calls producing an integer result.
3. A byte read from **four times the first extracted field, plus 1**.
4. A zero-byte store at **that byte value plus 17**.
5. A dependency invocation with the integer result scaled by four.
6. Further calls producing another integer result.
7. A dependency invocation receiving that result scaled by four twice.
8. A call producing a new unsigned word, followed by a call receiving that word and another intervening call.
9. A byte read from address 1 and a zero-byte store at **the byte value plus 17**.
10. A dependency invocation with a secondary-register integer repeated three times. Preserve that integer as **saved shift operand**.

The zero used in the first invocation is not the third explicit input.

A subsequent call produces a word that is passed together with the preceding unsigned word’s upper nine bits to another dependency. More calls follow, then:

- Read address 1 again.
- Preserve this new byte value as **saved byte base**.
- Write zero at **saved byte base plus 17**.

The two reads from address 1 are separate observable reads and may return different values.

### 4. First G1 replacement and low-byte copies

After additional calls, a dependency receives a newly obtained integer scaled by four twice. A later dependency produces a word, here called **published word**.

The function then:

1. Stores the published word into **G1**, a 32-bit global location.
2. Passes the published word to a dependency and invokes another dependency.
3. Reads a word from **saved byte base plus 116**.
4. Stores that word’s low byte at **saved byte base plus 1**.
5. Calls a dependency with the saved shift operand shifted left by 11.
6. Obtains a wide result from another dependency.
7. Calls a dependency with the wide result’s low half, its high half, and the published word shifted logically right by 23.

After more calls, a new index is scaled by four. Call the result **first copy base**.

The function reads a word at **first copy base plus 116**, then writes its low byte to **first copy base plus 1**. It passes the first copy base to a dependency and continues through more calls.

A later call supplies another integer. Its fourfold value is preserved as **saved scaled value**. Before using that value in a subsequent call, the function repeats the word-read/low-byte-write operation at the **first copy base**. This is a fresh read, not reuse of the earlier word.

The next dependency receives:

- The saved shift operand shifted left by 12.
- The saved scaled value.
- The saved scaled value again.
- The newly supplied integer shifted left by 18.

### 5. Word replication and link-like storage

Following result-forwarding calls:

1. Obtain a new index and scale it by four to form **second copy base**.
2. Read a word at **second copy base plus 116**. Preserve the complete word as **replicated word**.
3. Store its low byte at **second copy base plus 1**.
4. Pass the second copy base to a dependency.
5. After further calls, obtain another integer and store the replicated word at **16 times that integer, plus 20**.
6. Call a dependency with **the saved scaled value logically shifted right by two, then shifted left by 16**.
7. Execute the intervening result-forwarding calls.
8. Obtain another integer and store the replicated word at **four times that integer, plus 20**.
9. Pass that integer scaled by four to a dependency.

The right shift in step 6 operates on the already computed 32-bit saved scaled value. It is not generally equivalent to recovering an unbounded original integer and shifting it left by 16.

After further calls, another integer is shifted left by two. The resulting word is:

- Stored at **the saved scaled value with its low two bits cleared, plus 20**.
- Passed twice to the following dependency.

After another call sequence, a new index selects a word at **four times that index, plus 20**, which is cleared to zero. The scaled index is then passed to a dependency.

### 6. Wide-result-derived stores and global-based sampling

Another dependency produces a wide result:

- Its low half is shifted left by two to form **derived word**.
- Its high half is used as an index.
- The derived word is stored at **four times the high half, plus 20**.

The function then reads **G2**, treating the value as a memory base. This read occurs before the following dependency invocation.

That dependency receives four explicit arguments: derived word, high half, derived word, derived word.

After further calls:

1. Obtain another index.
2. Store the derived word at **four times that index, plus 20**.
3. Read a word at **the previously sampled G2 base plus 20**. Preserve this as **global-based word**.
4. Pass the new index scaled by four to a dependency.
5. Continue through calls producing another wide result. Preserve its low half as **final selector word** and its high half as an argument word.

The G2-derived base is sampled earlier than the word read through it. Changes to the G2 global between those events do not replace the saved base, but changes to the memory addressed by that base can affect the later word read.

### 7. Final selector-byte updates

The function next:

1. Reads a byte at **the replicated word logically shifted right by 23, plus 1**.
2. Stores the low byte of the global-based word at **that byte value plus 17**.
3. Calls a dependency with the latest wide result’s high half repeated three times and its low half shifted left by two as the fourth argument.
4. Executes further result-forwarding calls.
5. Reads a byte at **the final selector word masked with `0x3fffffff`, shifted right by 21, plus 1**.
6. Stores the low byte of **the global-based word logically shifted right by 22** at **that byte value plus 17**.
7. Passes a newly obtained integer shifted left by two to a dependency.
8. Executes more calls, including a call receiving another integer shifted left by two twice.

For step 5, the selector is in the range 0–511. The byte read can therefore address locations 1–512.

### 8. Terminal state changes and zero-target call

The final call sequence produces a byte result and a represented secondary-register byte pointer.

In order, the function:

1. Stores a zero byte through that pointer.
2. Reads a three-byte global quantity, **G3**.
3. Replaces G1 with a word whose low eight bits are the final call’s byte result and whose upper 24 bits come from G3.
4. Stores a zero halfword at **the final selector word masked with `0x3fffffff`, then logically shifted right by 7**.
5. Invokes call target zero with three explicit zero arguments.
6. Reaches the represented void return only if that invocation returns.

The final halfword address ranges from zero through `0x007fffff`; alignment is not enforced.

## Side effects

The explicit memory writes comprise:

- Indexed 32-bit stores at offsets of 20.
- Byte writes through byte-valued selectors, generally at offsets of 17.
- Copies of a sampled word’s low byte into a location at offset 1.
- Two replacements of G1.
- A final zero-byte store through a helper-produced pointer.
- A final zero-halfword store through a masked and shifted address.

The three-byte G3 quantity is read after the helper-produced pointer is cleared. If those locations overlap, the clear may affect the value used to construct G1.

Likewise, low-address selector tables, destination bytes, word fields, and globals are not established to be disjoint. All operations must retain their stated order. No final “all cleared” invariant is justified: later operations or dependencies may overwrite earlier stores.

**Ownership:** no explicit ownership transfer, allocation, deallocation, or lifetime protocol is established. Values used as pointers are neither validated nor visibly released by this body. Dependencies may have additional ownership effects; those effects are unknown.

**Errors:** there is no explicit error return, recovery branch, rollback, or cleanup path. A failing access or nonreturning dependency prevents later operations. Earlier side effects may remain.

## Acceptance examples

These are conditional static acceptance examples, not executed tests.

1. **Input-selector width.** If the third input is `0xffffffff`, its selector is 511. The selector word store writes 511, and the corresponding selector-byte read addresses 512. It does not use the full input as that byte address.

2. **Extraction followed by truncation.** If the first sampled word is `0xffffffff`, the first extracted field is 1023. Its first byte store writes 255. The later byte lookup based on four times that field addresses 4093.

3. **Byte-valued destination selection.** If a relevant selector-byte read returns 200, the following offset-17 byte store addresses 217. No additional pointer-sized indirection is established.

4. **Fresh reads remain observable.** If the word at the first copy base plus 116 changes between its two reads, the second low-byte copy uses the later value.

5. **Complete-word replication.** If the replicated word is `0x123456ab`, the byte copy writes `0xab`, while the two subsequent replication stores write the complete word `0x123456ab`, assuming intervening calls return normally.

6. **G1 can change twice.** The published word is stored into G1 before its following dependency invocation. The terminal G1 replacement is separately observable and does not imply that dependencies preserved the earlier value.

7. **Terminal composition.** If G3 supplies the 24-bit quantity `0x123456` when read and the final byte result is `0xab`, the terminal G1 value is `0x123456ab`.

8. **Failure preserves only a prefix.** If an access faults before the terminal halfword clear, neither that clear nor the zero-target invocation is required to occur. The body supplies no rollback of earlier writes.
