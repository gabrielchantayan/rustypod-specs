## Behavior

### Ordered initialization

Before either call, the function performs these four-byte object writes in order:

1. Clear `+0x0C` to zero.
2. Set `+0x10` to 2.
3. Read external word A and store the value obtained at `+0x18`.
4. Set `+0x1C` to 16.
5. Read external word B and store the value obtained at `+0x14`.

A and B designate distinct external source locations. Their values, initialization guarantees, mutability, and meanings are not supplied.

For this contract, **a** and **b** mean the values actually obtained by the respective initialization reads. They do not mean values observed at function entry. An earlier object write can affect either read if the external source aliases that storage.

For example, if external word B is the same four-byte storage as object offset `+0x0C`, its initialization read obtains zero after the initial clear, regardless of its earlier contents. The copy to `+0x14` therefore receives zero.

The callback is resolved and invoked only after all five initialization writes. Consequently, the resolution reads observe memory after initialization, not an entry-time snapshot. Whether the callback can access the object depends on its implicit context and reachable memory; the object is not visibly passed as an explicit callback argument.

### Callback result and retained field value

After the callback returns, the function:

- Stores the callback’s 32-bit result at `+0x3C`.
- Reads the 32-bit value at `+0x0C` and retains it for later use.

Let **R** denote the callback result and **C** denote that subsequent read from `+0x0C`.

C is not necessarily zero. The callback may have modified `+0x0C` after its initial clearing. The store of R precedes the capture of C.

A callback write to `+0x3C` is replaced by the function’s store of R. The subsequent argument calculation uses retained R, not a fresh read of `+0x3C`.

C is captured before the call to F-d7be9cfb4000. A later change to `+0x0C` does not replace C.

### Call to F-d7be9cfb4000

The function calls F-d7be9cfb4000 once on the normal path with two explicit arguments:

| Argument | Value |
|---|---|
| First | Eight times the difference between R and C: \(8(R-C)\). |
| Second | The four-byte value read from object offset `+0x14` for this call. |

The second argument is read after the callback. It need not equal b: the callback may have changed `+0x14` after initialization.

Both arguments are prepared before entry to F-d7be9cfb4000. The supplied representation does not establish a relative ordering between reading the second argument and evaluating the first argument’s arithmetic.

No operation performed by F-d7be9cfb4000 is established beyond this interaction. In particular, its name or argument pattern does not justify specifying division, normalization, validation, conversion, allocation, or any particular error convention.

### Operations after the second call

Let **H** denote the 32-bit result returned by F-d7be9cfb4000.

After that call returns, the function:

1. Stores \(1000H\) at `+0x08`.
2. Stores retained C at `+0x20`.
3. Reads the then-current values at `+0x28` and `+0x10`, multiplies them together and then by 2, and stores the result at `+0x24`.
4. Returns zero.

The store at `+0x20` does not reread `+0x0C`. If F-d7be9cfb4000 changes `+0x0C`, the later copy still uses C.

The final operand reads occur after F-d7be9cfb4000 returns and after the writes to `+0x08` and `+0x20`. Either dependency may have changed the operands. The initial assignment of 2 to `+0x10` therefore cannot replace its later read in the general contract.

The relative order of the reads from `+0x28` and `+0x10` is not established. Both precede the store at `+0x24`.

## Acceptance examples

These are conditional criteria derived from static evidence, not executed tests. Unless otherwise specified, they assume valid memory, normal dependency returns, no concurrent interference, and representable arithmetic intermediates.

### Baseline using initialization-read values

Let a and b be the values actually obtained when A and B are read during initialization. Assume the callback returns 12 without changing relevant fields, F-d7be9cfb4000 returns 7 without changing relevant fields, and `+0x28` contains 3 at its final read.

Required results:

- F-d7be9cfb4000 receives 96 and b.
- `+0x3C` receives 12.
- `+0x08` receives 7000.
- `+0x20` receives zero.
- `+0x24` receives 12.
- The function returns zero.

Under these preservation assumptions, `+0x18` retains a, `+0x14` retains b, and the other initially assigned fields retain their initialized values.

This example does not equate a or b with entry-time contents. Aliasing may already have changed their source storage before the respective reads.

### External word B aliases the cleared field

Assume B occupies the same four bytes as `+0x0C` and contains 37 on entry. Assume the callback returns 12 and both dependencies preserve the relevant fields.

Required behavior:

- The initial clear changes B’s storage to zero.
- B’s later initialization read obtains zero, so b is zero.
- `+0x14` is initialized to zero.
- F-d7be9cfb4000 receives 96 and zero.

Requiring its second argument to be the entry-time value 37 would contradict the ordered accesses.

### Callback changes subsequently read fields

Assume the callback returns 12, changes `+0x0C` to 5, and changes `+0x14` to q.

Required behavior:

- C is 5.
- F-d7be9cfb4000 receives 56 and q.
- The later store at `+0x20` uses 5.

### A later mutation does not replace retained C

Assume C is captured as 5, then F-d7be9cfb4000 changes `+0x0C` to 99.

The function must store 5 at `+0x20`. It does not directly restore `+0x0C`; absent another effect, that field remains 99.

### Final operands reflect post-call state

Assume F-d7be9cfb4000 leaves `+0x28` as 6 and `+0x10` as 4, with neither changing before its final read.

The store at `+0x24` must be 48. Producing 24 by substituting the initial value 2 for the later `+0x10` read would not match the contract.

### Later stores overwrite dependency stores

The function subsequently replaces those values with 7000, retained C, and the final product, respectively. No general restoration of other modified fields is required.
