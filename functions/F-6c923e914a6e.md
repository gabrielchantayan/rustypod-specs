# F-6c923e914a6e

## Purpose

F-6c923e914a6e conditionally produces a 32-bit integer through a caller-supplied output location and returns a separate 32-bit success indicator.

The operation selects among three recognized behaviors using a selector and two external 32-bit values:

- Retrieve a value through a dependency chain, accepting it only when a dependency-provided status has a nonzero low byte.
- Return a record’s stored base value, optionally adjusted by a dependency-produced value minus one.
- Return zero through the output location without consulting the record.

Other selector combinations return failure without a direct output write.

These behaviors are established by the supplied static representation. The application meaning of the selectors, record fields, external values, and dependency results is unknown. “Success” means that this function returns one; it does not establish that dependencies validated their inputs or completed without side effects.

## Behavior

### Selection and external reads

The first decision tests the 32-bit sum of the selector and a read of selector bias A.

If that sum is zero, the function follows the lookup behavior.

If that sum is nonzero, it evaluates a further expression containing the selector, another access to selector bias A, and an access to selector bias B. The earlier sum is not retained as the sole basis of this second decision.

Consequently, a contract that replaces these accesses with one cached bias value is not established when the external storage can change between accesses. The supplied representation does not establish a synchronization mechanism or an evaluation order between the individual operands of the second expression.

The resulting second sum selects:

| Second sum | Behavior |
|---|---|
| Zero | Adjusted-base behavior |
| `0x7f6` | Constant-zero behavior |
| Any other word | Immediate failure |

The second sum is evaluated only when the first decision was nonzero. A zero first sum takes precedence over any result that a hypothetical second sum might have produced.

### Lookup behavior

The function first reads the record word at offset `0x1c`.

If this word is zero, it returns zero. It does not directly read offsets `0x20`, `0x24`, or `0x34`, and it does not directly write the output.

If the word is nonzero:

1. The word at offset `0x20` is read and passed to F-283eda65a14c.
2. That dependency’s 32-bit result is passed to F-682adfd5a561 together with the literal argument 5.
3. A local, pointer-shaped scratch slot is set to zero.
4. F-cd792cea84cd is called with:
   - The result from F-682adfd5a561.
   - The lookup token.
   - A read of the record word at offset `0x24`.
   - The address of the scratch slot.
5. After that call returns, the low eight bits of the scratch slot’s value are tested.

If those low eight bits are nonzero, the function stores the 32-bit return value of F-cd792cea84cd through the output address and returns one.

If those low eight bits are zero, the function returns zero without a direct output write.

The acceptance condition is **not** whether the entire scratch word is nonzero. For example, a scratch value of `0x00000100` has a zero low byte and therefore does not authorize the output write.

The low-byte test concerns the scratch value itself. It is not a dereference of the address numerically represented by that value.

### Adjusted-base behavior

The function reads the record word at offset `0x34` and retains it as the base result. It then reads the word at offset `0x1c`.

If the condition word is zero, the function stores the retained base result through the output address and returns one. No dependency is called.

If the condition word is nonzero:

1. The record word at offset `0x20` is passed to F-283eda65a14c.
2. Its result is passed to F-682adfd5a561 together with the literal argument 5.
3. F-5710a8628cba is called with:
   - The result from F-682adfd5a561.
   - The adjustment token.
   - A read of the record word at offset `0x24`.
4. The output becomes the retained base plus the return value of F-5710a8628cba, minus one, using the 32-bit arithmetic model.
5. The function writes that result and returns one.

There is no separate success-status check on F-5710a8628cba. A returned zero therefore contributes an adjustment of minus one; it is not treated as a failure indication by this function.

The base is read before any dependency is called. A dependency’s later modification of the record’s `0x34` field does not replace the retained base. Conversely, the `0x24` field is read for the final dependency call after the first two calls have completed; it is not snapshotted with the base.

### Constant-zero behavior

The function stores the 32-bit value zero through the output address and returns one.

It does not directly read any record field or invoke any dependency on this path.

### Unrecognized selector combination

The function returns zero immediately.

It does not directly read the record or directly write the output.

## Side effects

### Direct effects

The direct externally visible write is one 32-bit store through the output address on each normally completed success path.

The function also initializes a local scratch slot and exposes its address to F-cd792cea84cd on the lookup path. The slot’s value is subsequently used as a status carrier.

No direct write to the record or external selector/token storage is shown. No allocation, release, or ownership transfer is explicitly performed by this function.

### Dependency effects and ordering

For paths that invoke dependencies, the call order is fixed:

1. F-283eda65a14c.
2. F-682adfd5a561.
3. Either F-cd792cea84cd or F-5710a8628cba.

Each call must return before the next one is reached. The direct output store occurs after the final call and, on the lookup path, only after the scratch-status check.

The lookup and adjustment tokens and the record word at `0x24` are inputs to the final call. The supplied representation does not establish a relative evaluation order among those final-call argument reads.

Dependencies may change memory, external values, ownership, or other process state. No preservation guarantee is available. In particular, the `0x24` field and relevant token must not be assumed to retain values they had before earlier calls.

### Aliasing and lifetime

No prohibition against aliasing is shown. If the output overlaps a record field or external storage, the final output write can modify that storage.

The scratch address refers to function-local storage. The observed function consumes its status immediately after the dependency returns. Whether F-cd792cea84cd retains that address is unknown; safe retention beyond the containing invocation is not established.

Invalid accesses, dependency faults, non-returning dependencies, and other exceptional execution are not converted into explicit failure returns by any shown handling.

## Acceptance examples

These are conditional contract examples, not executed tests. Unless stated otherwise, selector biases remain stable during selection, required addresses are valid, and dependencies return normally.

1. **Unrecognized selection**

   If the selector plus bias A is nonzero and the subsequent three-term sum is 7, the function returns zero. There is no direct record read or output write.

2. **Constant-zero success**

   If the first sum is nonzero and the second sum is `0x7f6`, the function writes zero and returns one. Record contents do not contribute to this result.

3. **Base without adjustment**

   If the first sum is nonzero, the second sum is zero, the base field is 42, and the condition field is zero, the function writes 42 and returns one without dependency calls.

4. **Adjusted base**

   Under the same selection with a nonzero condition field, if the retained base is 42 and F-5710a8628cba returns 9, the function writes 50 and returns one.

5. **Zero adjustment result is not failure**

   With a retained base of 42 and a final adjustment result of zero, the function writes 41 and returns one.

6. **Word-width boundary**

   With a retained base of zero and an adjustment result of zero, the recovered 32-bit arithmetic produces `0xffffffff`. The function writes that word and returns one.

7. **Lookup disabled**

   If the first sum is zero and the condition field is zero, the function returns zero without directly writing the output.

8. **Lookup accepted**

   If lookup is selected, the condition field is nonzero, F-cd792cea84cd returns 73, and the scratch value after that call is `0x00000101`, the function writes 73 and returns one.

9. **Nonzero scratch word rejected**

   Under the same lookup conditions, a scratch value of `0x00000100` causes a zero return and no direct output write, regardless of the dependency’s return value.

10. **Retained base versus later field changes**

    If the adjusted-base path initially reads base 42, and an earlier dependency later changes that field to 100, a final adjustment result of 9 still produces 50. If a dependency changes offset `0x24` before its later read, the final call receives the value read at that later point.
