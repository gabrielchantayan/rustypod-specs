# F-84652ce813be

## Purpose

F-84652ce813be conditionally writes a four-byte value into storage described by three 32-bit address fields. Its ordinary interpretation is appending one element to a vector-like sequence, growing storage when the recorded end equals the capacity limit.

That interpretation is conditional. The established behavior consists of address comparisons, arithmetic, memory reads and writes, and dependency calls. The supplied body does not establish that the dependencies allocate, transfer, or release storage as their apparent roles suggest.

Two principal paths are present:

- If the initially recorded end differs from the capacity limit, the function advances the end and conditionally writes at the former end.
- If those addresses are equal, stable descriptor contents select a growth path involving three dependencies and eventual descriptor replacement.

A residual in-place insertion path also exists. Its selection requires descriptor observations inconsistent with stable contents during the initial checks.

Aliasing is behaviorally significant. Neither the returned storage address nor the insertion destination is checked for overlap with the descriptor. Explicit writes can therefore change fields used by later calculations, even when dependencies themselves preserve memory.

## Interface

### Inputs and representation

The function receives:

1. A descriptor address.
2. An address identifying a four-byte input value.

The descriptor contains three consecutive four-byte fields:

| Offset | Name used in this contract | Observed role |
|---|---|---|
| 0 | Base | Beginning of recorded storage |
| 4 | End | Address immediately after recorded elements |
| 8 | Capacity limit | Address immediately after recorded capacity |

Addresses and address-bearing fields are represented at 32-bit width. Element operations use a four-byte stride. The body does not establish a broader public type, external calling convention, or portable memory model.

The input value is not captured on entry. Its four bytes are read only when execution reaches an input-copy operation. Descriptor updates, dependency effects, and preceding element writes can therefore change what is ultimately copied.

### Output

There is no explicit return value or status result.

Observable results include:

- Descriptor writes.
- Four-byte writes at computed destinations.
- Dependency invocations and their arguments.
- Any effects produced by those dependencies.
- Possible failure or nontermination where accesses or arithmetic lack a valid interpretation.

### Preconditions for ordinary sequence behavior

The ordinary append interpretation requires:

- A readable and writable descriptor.
- Valid, suitably aligned storage for every accessed element.
- A consistent ordering of base, end, and capacity limit.
- Four-byte-aligned element distances.
- Readable input at the moment it is accessed.
- Valid arithmetic for the executed path.

The ordinary growth interpretation additionally requires suitable dependency behavior, preservation of relevant descriptor values until their specified reads, and storage that remains valid throughout those reads and writes. An insertion destination disjoint from the descriptor is necessary for the ordinary final-size conclusion.

These conditions are not checked locally. In particular, a nonzero address is not proof of validity, and the returned storage address is not checked for success, alignment, size, freshness, ownership, or overlap.

## Behavior

### Initial observation and immediate path

The function first saves the descriptor’s end address and compares that saved address with the capacity limit.

This is an inequality test, not an ordered bounds check. An end above the capacity limit still takes the immediate path if the two addresses differ.

When they differ, execution proceeds in this order:

1. Write the saved end advanced by four bytes into the descriptor’s end field.
2. If the saved end is nonzero, read four bytes from the input address and write them at the saved end.
3. Return without invoking a dependency.

The descriptor update precedes the input read. If the input identifies the end field, the copied value is the updated end, assuming the destination write does not interfere with that read.

The destination can itself overlap the descriptor. Thus, the initial end update is established, but a final end equal to the saved end plus four is not unconditional.

If the saved end is zero, the function writes four into the end field and skips both the input read and the element write. It does not need a readable input address on that execution.

### Counts and full-storage branch selection

When the initial end equals the capacity limit, the function rereads the end and reads the base to derive an element count. The signed 32-bit difference between that later end and base is shifted right by two; the resulting bit pattern is then used as an unsigned 32-bit count.

A capacity count is derived from the capacity limit and base in the same signed-difference-and-shift manner and compared as unsigned.

For valid nonnegative aligned distances, these are the ordinary element count and capacity count. Negative distances, signed overflow, and the portability of right-shifting negative values are not resolved by this contract.

The growth branch is selected when the unsigned capacity count is less than or equal to the unsigned element count. With stable descriptor contents, the initial equality of end and capacity limit makes these counts equal.

The saved entry-time end remains available for later operations; it is not replaced by subsequent end reads.

### Growth size and storage request

Let \(n\) be the derived unsigned 32-bit element count. The selected capacity is the larger unsigned 32-bit result of:

- \(n + 32\)
- \(n + \lfloor n/2 \rfloor + \lfloor n/8 \rfloor\)

The fractional terms use unsigned shifts. Additions wrap at 32-bit width before comparison. Consequently, the selected capacity is not guaranteed to exceed \(n\).

F-871e64ddc6de is called with:

1. The selected capacity shifted left by two at 32-bit width.
2. Zero.

Its returned 32-bit quantity is retained as the new-storage address. The byte-count shift can discard high bits. There is no local failure check.

No descriptor-preservation property follows from the returned address. F-871e64ddc6de may have changed descriptor fields, input memory, or other state before subsequent reads unless an external contract excludes those effects.

### First transfer dependency

After the storage-request dependency returns, F-unknown-transfer is called with:

1. The descriptor’s base, read after that return.
2. The saved entry-time end.
3. The returned new-storage address.
4. The descriptor address.

The result is ignored.

A transfer of the prefix before the insertion position is an inferred role, not an established effect. The body does not determine whether the dependency copies, moves, constructs, destroys, changes ownership, mutates the descriptor, or changes global state.

The first argument need not equal the entry-time base because the storage-request dependency has already executed.

### Conditional insertion write

After the first transfer returns, the function reads the descriptor’s base again.

It computes an insertion destination by subtracting this base from the saved entry-time end, clearing the low two bits of the resulting 32-bit offset, and adding the new-storage address.

The mask rounds the offset down to a multiple of four at the bit-pattern level. It does not validate a source range, establish meaningful pointer subtraction, or align an otherwise unaligned new-storage address.

If the destination is nonzero:

- Read four bytes from the input address.
- Write those bytes at the computed destination.

If the destination is zero, both accesses are skipped.

This input read follows the storage request and first transfer. An input pointing into the descriptor or old storage is not guaranteed to retain its entry-time value.

The insertion write can change any descriptor field it overlaps. Such changes affect subsequent operations that reread those fields.

### Second transfer dependency

F-unknown-transfer is invoked again, with:

1. The saved entry-time end.
2. The descriptor’s current end.
3. A recomputed destination using the current base, saved end, new-storage address, and an additional four-byte displacement.
4. The descriptor address.

The recomputation uses the same masked offset as the insertion calculation, followed by an advance of four bytes.

The destination is not necessarily the prior insertion destination plus four: an intervening insertion write may have changed the base. Likewise, the second source boundary can reflect an end field changed by the insertion.

Under ordinary append assumptions, the source boundaries identify an empty suffix. The dependency is still invoked; an empty source range does not establish that it has no effects.

### Traversal and apparent release

After the second transfer returns, the function captures the descriptor’s current base and end.

It then advances a local address from that captured base in four-byte steps until it equals the captured end. The traversal contains no explicit element read, element write, or dependency call.

For a valid finite stepped range, this traversal has no explicit memory effect. For incompatible endpoints or arithmetic outside its valid interpretation, termination is not established.

F-ff1bdc376dcd is subsequently called with:

1. The captured base.
2. The signed difference between the descriptor’s capacity limit and the captured base, shifted right by two.
3. Zero.

The capacity limit is read for this call after the base/end capture. It is not frozen by that capture.

Although the second argument resembles an element capacity, the dependency’s required units and semantics are unknown.

### Final descriptor replacement

After F-ff1bdc376dcd returns, the descriptor is written in this order:

1. **Base:** the retained new-storage address.
2. **End:** that address plus four times the signed, right-shifted difference between captured end and captured base, plus four.
3. **Capacity limit:** that address plus four times the selected capacity.

The final end calculation uses the base and end captured before the release dependency. It does not use replacement descriptor values that dependency might have written.

The capacity displacement uses the selected unsigned capacity at 32-bit width. Signed portions of the final end calculation retain their signed-arithmetic limitations; this contract does not replace them with unrestricted mathematical arithmetic.

With valid aligned counts, preserved relevant fields, and no insertion overlap with the descriptor, the final recorded size is the original size plus one. Without those conditions, the captured size can differ.

### Residual in-place insertion branch

The residual branch requires initial end/capacity equality followed by an unsigned capacity count greater than the later element count. Stable descriptor contents do not produce that combination.

If selected, it:

- Writes the later-read end advanced by four into the end field.
- If that former end is nonzero, copies the preceding four-byte element into it.
- Starts a backward position one element before that former end.
- Until that position equals the saved entry-time end, moves backward one element and copies the predecessor into the following position.
- Reads the input and writes it at the saved entry-time end.

The final input read and write have no nonzero-destination guard. The initial predecessor copy and repeated backward copies require their own valid addresses.

No dependency is called on this branch. Practical reachability, valid movement ranges, and termination remain documented_only outside stable-descriptor execution.

## Side effects

### Established ordering

The following ordering is explicit:

- Immediate path: end update before conditional input read and destination write.
- Growth path: storage request, first transfer, conditional insertion, second transfer, traversal, apparent release, final descriptor replacement.
- Final replacement: base, then end, then capacity limit.

The supplied representation does not establish the relative evaluation order of every read used to assemble a single dependency call’s arguments.

Aliasing and dependency mutation are independent concerns. Even memory-preserving transfer and release dependencies do not prevent the function’s own insertion write from changing the descriptor.

### Ownership and external state

Passing an old-storage address to F-ff1bdc376dcd and later publishing a replacement address supports an inferred storage-replacement role. It does not establish a complete ownership contract.

No dependency is known to:

- Preserve descriptor fields or globals.
- Preserve input bytes or source elements.
- Return disjoint or uniquely owned storage.
- Acquire or release ownership.
- Preserve source lifetimes.

The traversal does not explicitly call an element destructor.

### Errors and partial updates

No local error report, rollback, or recovery path is shown.

An immediate-path failure can occur after the end update. A growth-path failure can occur after dependency effects or an insertion write but before final descriptor replacement.

A zero storage result is processed without a dedicated error branch. Invalid access, dependency failure, nonlocal control transfer, and nontermination have no established recovery behavior. No atomic-update or strong exception guarantee is supported.

## Acceptance examples

These examples are conditional static deductions, not executed tests.

### Spare capacity

Assume a valid nonzero end below the capacity limit, independent readable input, valid arithmetic, and a destination disjoint from the descriptor.

The end advances by four, the input’s four bytes are written at the former end, and base and capacity limit remain unchanged. No dependency is called.

### Input identifies the end field

On the immediate path, assume the input identifies the end field and the destination is valid and disjoint from the descriptor.

The function first updates the end. It then copies that updated four-byte field value, rather than the entry-time end value.

### Zero end with unequal limit

With end zero and a nonzero capacity limit, the end becomes four. The input is not read, no element write occurs, and no dependency is called.

This is explicit branch behavior, not evidence of valid sequence storage.

### Empty full descriptor with ordinary replacement storage

Assume all three descriptor fields are initially zero, all dependencies return normally and preserve those fields until final replacement, the returned address is nonzero, the insertion destination is valid and disjoint from the descriptor, and the input remains readable.

Then:

- Selected capacity is 32 elements.
- F-871e64ddc6de receives 128 and zero.
- Both transfer calls occur.
- The input is written at the returned address.
- F-ff1bdc376dcd receives zero, zero, and zero.
- Final base is the returned address.
- Final end is that address plus four.
- Final capacity limit is that address plus 128.

### Empty full descriptor with insertion into its end field

Let the descriptor reside at nonzero address \(D\), initially containing three zero fields. Assume:

- F-871e64ddc6de returns \(R = D + 4\) **and leaves all three descriptor fields unchanged before returning**.
- The independent input contains the 32-bit value four.
- Both transfer calls and F-ff1bdc376dcd return without modifying memory.
- All required accesses and arithmetic are valid.

The insertion destination is \(R\), the descriptor’s end field, so the insertion changes end to four.

The second transfer receives source boundaries zero and four, with destination \(R + 4\). The later capture obtains base zero and end four. The traversal advances once, and the release dependency receives zero, zero, and zero.

Final descriptor fields are:

- Base: \(R\).
- End: \(R + 8\).
- Capacity limit: \(R + 128\).

The recorded size is two. This does not establish two valid stored elements; it demonstrates descriptor overlap.

Allocator preservation is essential to these stated call arguments. If instead F-871e64ddc6de changes only the capacity limit to four while returning the same \(R\), with all other assumptions unchanged, F-ff1bdc376dcd receives zero, one, and zero. The returned address alone cannot distinguish these cases.

### Full descriptor containing 64 elements

Assume valid aligned storage, preservation of relevant descriptor fields by every dependency, intended transfer behavior, preserved input, disjoint insertion storage, and nonoverflowing arithmetic.

The growth candidates are 96 and 104 elements. The request is 416 bytes. The insertion is 256 bytes after the new base. Final end is 260 bytes after that base, and capacity limit is 416 bytes after it.

### Zero storage result

For an initially all-zero descriptor, assume all dependencies return normally and preserve relevant descriptor fields, and F-871e64ddc6de returns zero.

The insertion destination is zero, so the input read and insertion write are skipped. Both transfer calls and the release call still occur. Final fields are base zero, end four, and capacity limit 128.

This establishes absent local failure handling, not successful allocation.
