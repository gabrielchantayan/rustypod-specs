# F-24f21ea35031

## Purpose

F-24f21ea35031 conditionally populates a destination record from a source record whose leading 16-bit discriminator selects one of two supported layouts.

The established behavior is an ordered sequence of dependency calls, source reads, and explicit destination writes. The apparent intent is to initialize a 108-byte record, preserve or restore an associated reference, transfer descriptive data, and encode selected numeric fields. That interpretation is **inferred intent**, not a complete contract for the dependencies.

Discriminator values 1 and 2 select supported paths. Other values return after the initial dependency sequence; they do not bypass that sequence.

The routine has no explicit return value, status code, validation failure, or recovery path.

## Behavior

### 1. Unconditional entry sequence

Before inspecting the source discriminator, the routine performs these operations in order:

1. Calls F-4055be9c3f18 with destination address plus `0x12`, retaining its 32-bit result.
2. Calls an unmapped external dependency with the destination base and the numeric argument `0x6C`, decimal 108.
3. Calls F-946cac4b59bc with the retained result and destination address plus `0x12`.
4. Retains the 32-bit result of this last call for a later nonzero test.
5. Extracts bits 8–15 of the third argument for subsequent byte output.
6. Reads the source discriminator.

The second operation appears consistent with clearing or initializing a 108-byte destination record. Its body is unavailable, so clearing is not established. Similarly, the pair of calls around it suggests saving and restoring a reference associated with destination offset `0x12`, but the dependency semantics are unknown.

These entry calls remain observable even when the discriminator is unsupported.

### 2. Discriminator selection

A discriminator read equal to 2 selects the discriminator-2 path.

Otherwise, the routine reads the discriminator again and proceeds only if that read equals 1. If it does not, the routine returns without executing the supported-path operations below.

For stable source memory, this amounts to support for values 1 and 2 only. The two reads on the non-2 route are not a single cached read. Concurrent modification is not defined by the supplied evidence and must not be treated as a supported synchronization mechanism.

### 3. Optional associated-data operations

Both supported paths begin with the same conditional sequence.

If the retained result of the entry call to F-946cac4b59bc is zero, this sequence is skipped.

If it is nonzero:

1. Read the 32-bit value at source offset `0x210`.
2. Call F-fac138f80b6d with the retained nonzero result, that source value, and `0xFF`, decimal 255.
3. Read the 32-bit value at source offset `0x210` again.
4. Call F-1cb585febd84 with this newly read value.
5. Compare its result as an unsigned 32-bit quantity against `0xFE`, decimal 254.
6. If the result is greater than 254, call F-4055be9c3f18 again with destination plus `0x12`, then write a zero byte at offset `0xFE` from that call’s returned value.

The second source read is important: the routine does not preserve the first value across F-fac138f80b6d. If that dependency changes the source field, F-1cb585febd84 receives the changed value.

The final zero-byte write uses the freshly obtained result from F-4055be9c3f18, not the earlier nonzero result. There is no explicit validity or nonzero check on this fresh result.

**Inferred intent:** this sequence resembles bounded string transfer followed by termination at byte index 254 when the input length is at least 255. Neither string semantics nor ownership is established by the call sites alone.

### 4. Shared supported-path setup

After the optional operations, either supported path performs the following sequence:

1. Calls the unmapped three-argument external dependency with destination plus `0x20`, source plus `0x30`, and size argument `0x10`.
2. Calls the same dependency with destination plus `0x54`, source plus `0x40`, and size argument `0x10`.
3. Reads a 16-bit value from destination offset `0x28`.
4. Calls F-0ec8efa9c769 with that value.
5. Writes the returned 16-bit value explicitly: low byte to destination `0x28`, then high byte to destination `0x29`.
6. Writes zero to destination `0x10`, then zero to destination `0x11`.
7. Writes the third argument’s low byte to destination `0x1C`, then its bits 8–15 to destination `0x1D`.

The block-transfer calls precede the destination `0x28` read. If the external dependency copies the requested blocks, this read observes a field within the first transferred block, subject to any intervening dependency effects. Copy semantics and overlap handling remain unknown.

The explicit two-byte writes use low-byte-first ordering regardless of how native multibyte reads are represented.

### 5. Discriminator-2 fields

For discriminator 2, the routine next:

1. Reads the 16-bit source field at `0x02` and writes its low 8 bits to destination `0x1E`.
2. Reads the 32-bit source field at `0x08` and calls F-946cac4b59bc with it and destination plus `0x30`.
3. Reads the 32-bit source field at `0x58` and calls the same dependency with destination plus `0x36`.
4. Reads the 32-bit integer at source `0x64`, multiplies it by the fourth argument, and calls the same dependency with the product and destination plus `0x3A`.
5. Reads the 32-bit source field at `0xA8` and calls the same dependency with destination plus `0x40`.
6. Reads the 32-bit integer at source `0xB4`, multiplies it by the fourth argument, and calls the same dependency with the product and destination plus `0x44`.

Each field is read at its point in this sequence, after preceding calls have returned. The routine does not first snapshot all source fields.

Both products use 32-bit integer operands and a 32-bit result passed onward; no widening, saturation, range validation, or explicit overflow handling is visible. Exact out-of-range behavior is **documented_only** pending confirmation of the underlying arithmetic semantics.

### 6. Discriminator-1 fields

For discriminator 1, the routine instead:

1. Writes the constant `0x10` to destination `0x1E`.
2. Reads the 32-bit source field at `0x08` and calls F-946cac4b59bc with it and destination plus `0x30`.
3. Reads the 32-bit source field at `0x04`.
4. Writes that field’s low byte to destination `0x34`, followed by bits 8–15 to destination `0x35`.

The upper 16 bits of the source `0x04` field do not contribute to these explicit writes. The multiplier is not used on this path.

### 7. Shared completion

Both supported paths finish in this order:

1. Read source `0x0C`; call F-946cac4b59bc with that 32-bit value and destination plus `0x48`.
2. Read source `0x10`; call the same dependency with destination plus `0x4C`.
3. Read source `0x1C`; call the same dependency with destination plus `0x50`.
4. Read the 32-bit source field at `0x20C` once.
5. Write its successive bytes, least significant first, to destination offsets `0x64`, `0x65`, `0x66`, and `0x67`.

The final four bytes come from one retained field value; the source is not reread between these writes.

## Side effects

Established direct writes are limited to the byte stores described above, including the conditional zero store through a dependency-returned address. Additional writes can occur inside every dependency whose implementation is unavailable.

The destination is acted on before source-type validation. Unsupported source types therefore do not imply an unchanged destination.

No allocation, release, ownership transfer, or lifetime extension is explicit in this routine. Passing a 32-bit value to a dependency does not establish whether it is an owned pointer, borrowed pointer, handle, or scalar. No assumption may be made that dependencies preserve global state or refrain from releasing memory.

There is no rollback. If an operation fails after earlier calls or writes, this routine supplies no visible transaction boundary or restoration logic.

Source/destination aliasing is not rejected. Because destination processing precedes source reads, and source reads are interleaved with dependency calls, aliasing can affect later inputs. A snapshot-style interpretation requires additional nonaliasing or dependency guarantees.

The bytes left untouched by the routine’s direct stores cannot generally be called unchanged or zero: the initial external operation and subsequent dependencies may modify them.

## Acceptance examples

These are conditional static acceptance criteria, not reports of execution.

1. **Unsupported discriminator, stable source.** With a discriminator of 3, observe the initial F-4055be9c3f18 call, the external initialization call with 108, and the initial F-946cac4b59bc call, in that order. No supported-path block calls or explicit field writes follow.

2. **Zero retained result.** On either supported path, if the initial F-946cac4b59bc result is zero, neither F-fac138f80b6d nor F-1cb585febd84 is called. The block operations and remaining supported-path work still occur.

3. **Unsigned threshold boundary.** With a nonzero retained result, an F-1cb585febd84 result of 254 does not trigger the extra lookup and zero store. A result of 255 does. A result with bit 31 set also passes this unsigned threshold.

4. **Low-16-bit tag output.** For a third argument of `0xA1B2C3D4`, either supported path explicitly writes `0xD4` at destination `0x1C` and `0xC3` at `0x1D`.

5. **Path-specific byte.** On path 2, a source `0x02` field of `0x12AB` produces an explicit `0xAB` write at destination `0x1E`. On path 1, the explicit write is `0x10`, regardless of that source field.

6. **Representable multiplication.** On path 2, with multiplier 3 and unchanged source fields of 7 at `0x64` and −2 at `0xB4`, the corresponding F-946cac4b59bc calls receive 21 and −6, respectively. No assertion about encoded destination bytes follows without that dependency’s contract.

7. **Final byte ordering.** If the final source `0x20C` read yields `0x12345678`, the routine’s last four explicit writes are `0x78`, `0x56`, `0x34`, and `0x12` at destination `0x64` through `0x67`.

8. **Mutation between calls.** If F-fac138f80b6d changes source `0x210` and returns normally, the subsequent F-1cb585febd84 argument must come from the new read, not the earlier value.
