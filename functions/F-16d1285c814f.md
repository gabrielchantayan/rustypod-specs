# F-16d1285c814f

## Purpose

F-16d1285c814f conditionally modifies a structured object using a signed 32-bit selector. Its observable behavior depends on the current object’s header:

- A first unsigned 32-bit word below 4001 selects a single-byte bit-clearing operation.
- A first word of at least 4001, together with a nonzero word at offset 8, selects traversal through a dependency-chosen child.
- A first word of at least 4001, together with a zero word at offset 8, selects terminal processing involving two external calls, a header reset, and a fixed-size scan.

Removal from a collection is a plausible interpretation, but it is not an established end-to-end guarantee. In particular, the available evidence does not establish that terminal processing copies, clears, or reconstructs a collection. Those interpretations depend on unavailable dependency behavior.

This contract describes the supplied static evidence. It does not claim runtime verification.

## Interface

### Arguments and result

| Argument | Representation | Contractual role |
|---|---|---|
| Initial object reference | Pointer to storage addressed as 32-bit words | Identifies the first object examined. Traversal can replace the current reference with a child reference. |
| Initial selector | Signed 32-bit integer | Determines a compact-object bit position, supplies a traversal dependency argument, or acts as the exclusion value during terminal scanning. |

There is no explicit return value or error result. Completion is observable through memory accesses, writes, and dependency calls.

The initial reference is dereferenced without a null check. Null is recognized only when obtained as a child reference during traversal.

### Object representation

Offsets below are byte offsets relative to the current object.

| Offset | Access width | Established use |
|---|---:|---|
| 0 | 32 bits, unsigned | Selects compact processing when below 4001; otherwise selects the large-object cases. |
| 4 | 32 bits | Receives zero during terminal processing. |
| 8 | 32 bits | Distinguishes traversal from terminal processing for large objects. |
| 12 onward | Path-dependent | Contains bitmap bytes, child-reference slots, or storage addressed by the terminal dependencies. |

These are access roles, not a complete type definition. The evidence does not establish that every object has the same payload capacity or that the first word denotes a count.

Child-reference slots occupy 32 bits. The compact path also converts the object reference into a 32-bit integer before computing its target address. Consequently, portable behavior on a wider-pointer system is not established.

### Preconditions

Defined, normally completing execution requires:

- Valid readable storage for every header and child slot actually accessed.
- A readable and writable target byte on the compact path.
- Valid writable storage at offset 4 on the terminal path.
- Addresses and extents acceptable to the dependencies.
- Defined values for local entries when they are examined.
- Valid arithmetic and conversions for the path taken, subject to the qualifications below.
- Continued validity of every object or storage region subsequently accessed after a dependency returns.

There are no explicit range checks for selectors or child indices, no capacity checks, no cycle detection, and no lifetime validation.

The function does not establish ownership transfer. It neither explicitly allocates nor explicitly releases storage; dependency behavior may nevertheless affect ownership or lifetime.

## Behavior

### Dispatch and traversal

The current object’s first word is read as an unsigned 32-bit value. Values from 0 through 4000 select compact processing. Values from 4001 through 4,294,967,295 select large-object processing.

Only a large object has its offset-8 word inspected. A nonzero value requests traversal; zero requests terminal processing. The offset-4 word does not participate in this decision.

For traversal, F-d7be9cfb4000 receives the current selector decreased by one using signed arithmetic. Its 64-bit result supplies two 32-bit portions:

- The low portion is converted to a signed child index.
- The high portion is converted to a signed value and increased by one to obtain the replacement selector.

The child reference is read from the 32-bit slot whose word index is the child index plus three. Where the index arithmetic is defined, an index of zero selects offset 12, an index of one selects offset 16, and an index of minus one selects offset 8. No negative-index rejection is present.

The dependency call precedes the child-slot read. Therefore, the slot is read from memory as it exists after that call. The header conditions are not rechecked between the dependency’s return and that fetch.

The child-slot read precedes replacement-selector calculation, and replacement-selector calculation precedes the null-child check. Thus, a null child does not bypass potentially problematic selector arithmetic.

A null fetched reference ends the operation without terminal processing on the parent. A nonnull reference becomes the current object, and dispatch repeats with the replacement selector.

No traversal depth or cycle bound is enforced. Completion therefore depends on the sequence of dependency results and object contents.

### Compact-object update

The compact path interprets the selector through unsigned 32-bit arithmetic. Subtracting one yields a zero-based bit position modulo \(2^{32}\).

The position’s quotient on division by eight identifies a byte displacement from offset 12. Its remainder identifies a bit numbered 0 through 7 within that byte. The function reads the byte and writes back a value with that bit cleared and all other bits preserved from the read.

The byte write is present even when the selected bit was already clear. After the write, the function returns without invoking a dependency or reading the offset-8 word.

Examples of the position calculation:

| Selector | Payload byte displacement | Bit |
|---:|---:|---:|
| 1 | 0 | 0 |
| 8 | 0 | 7 |
| 9 | 1 | 0 |
| 0 | 536,870,911 | 7 |

Negative selectors also produce large unsigned positions. Neither zero nor a negative selector is treated as a special no-op.

The dispatch word supplies no bound for this calculation. For example, a first word of 1 does not restrict processing to selector 1.

Address formation has a separate portability constraint: it passes through an integer representation of the object reference. In the shown 32-bit arithmetic model, the unsigned address sum wraps modulo \(2^{32}\). That numerical property does not establish that the resulting integer converts to a valid pointer or identifies storage within the object.

### Terminal processing

Terminal processing uses invocation-local storage consisting of 125 signed 32-bit entries, totaling 500 bytes. This storage has no explicit initialization before the first terminal dependency call.

Two unmapped dependencies are assigned document-local opaque identifiers here:

- F-U01 receives the local storage address, the current object’s address plus 12, and the numeric extent 500.
- F-U02 receives the current object’s address plus 12 and the numeric extent 500.

These identifiers distinguish call sites; they do not assert identities or implementations beyond the supplied evidence.

The established ordering is:

1. F-U01 is invoked and must return normally for execution to continue.
2. F-U02 is invoked and must return normally for execution to continue.
3. The current object’s 32-bit word at offset 4 is written with zero.
4. Local entries are examined in increasing order, covering positions 0 through 124.
5. Processing ends after the final position.

At each position, zero is excluded first. Only a nonzero entry is compared with the active selector. A nonzero entry unequal to that selector causes one call to F-469a239057a8, with the current object reference as its sole explicit argument.

The qualifying entry is not explicitly passed. Nor is the selector supplied as an additional argument. Any result from this dependency is unused.

The scan has a fixed extent of 125 entries; it does not derive its length from a header field. Equal qualifying values at different positions can each cause a call. There is no deduplication.

The active selector is the value associated with the terminal object. After traversal, it need not equal the initial selector.

The evidence contains separate nonzero and inequality checks; it does not justify a general guarantee that a nonzero entry is read only once. Furthermore, later entries are examined after any earlier scan-triggered calls return. If dependencies can affect the local region through an escaped address or other accessible state, call eligibility must be determined from values observed during the scan, not from an assumed immutable snapshot.

## Side effects

### Direct memory effects

The mutually exclusive normal-completion paths have these direct effects:

- **Compact processing:** one target-byte read followed by a byte write clearing one bit.
- **Traversal ending at a null child:** no direct object write by this function before return.
- **Terminal processing:** one 32-bit zero write at offset 4, after both terminal helper calls and before any scan-triggered call.

Traversal dependencies can still mutate storage even when this function performs no direct write.

The offset-4 write is an ordering guarantee, not a final-state guarantee. A later F-469a239057a8 invocation may change that word.

### Dependency effects and ownership

No dependency is established to preserve globals, object headers, payload contents, allocation state, or object lifetime.

F-U01 receives an address into invocation-local storage. Passing that address does not establish permission to retain it or access it after the invocation ends. Conversely, the supplied body does not prove that the dependency refrains from retaining it.

If a dependency invalidates the current object, subsequent slot reads, header writes, or dependency calls are not protected by a validity check. The evidence establishes neither a safe release protocol nor recovery from invalidation.

### Errors and termination

There is no explicit validation failure, status code, exception handling, or recovery path.

Normal return follows a compact update, a null-child selection, or completion of the terminal scan. Invalid accesses, unsupported conversions, signed overflow, dependency failures, and nonlocal exits have no handled outcome established here.

No synchronization is shown. Concurrent modification is outside the established contract.

## Dependencies

### F-d7be9cfb4000

Called only when the current object has a first word of at least 4001 and a nonzero word at offset 8.

Its signed argument is the active selector minus one. Its 64-bit result supplies the child index and replacement-selector components described above.

Its mathematical mapping, valid input range, state effects, and failure behavior remain unknown. Splitting its result into two portions is not evidence that it computes a quotient and remainder.

### F-469a239057a8

Called during terminal scanning for each position whose observed entry is nonzero and unequal to the active selector.

It receives only the current object reference explicitly. Its result is not consumed. No insertion, reconstruction, ownership, or global-state guarantee is established.

### F-U01 and F-U02

F-U01 receives local storage, object offset 12, and extent 500. F-U02 receives object offset 12 and extent 500. Neither result is consumed.

The argument shapes are consistent with transferring a payload and then clearing it, but those effects are inferred intent only. Their parameter contracts, memory accesses, initialization behavior, and ownership effects remain `documented_only`.

## Acceptance examples

These are conditional acceptance criteria, not executed tests. Unless otherwise stated, addresses are valid, arithmetic is defined, dependencies return normally, and any values used during scanning are defined.

### Compact bit selection

For a compact object with selector 1 and hexadecimal FF at offset 12, the byte written is hexadecimal FE. No dependency is invoked.

For selector 8 with the same initial byte, the byte written is hexadecimal 7F.

For selector 9, the target is bit 0 at offset 13. Offset 12 is not the direct target of this update.

An initially clear target bit remains clear, but the byte write still occurs.

### Dispatch boundary

A first word of 4000 selects compact processing regardless of the offset-8 contents.

A first word of 4001 requires reading offset 8 and choosing traversal or terminal processing. It must not be classified as compact.

### Child read after dependency effects

Suppose traversal begins with a nonzero offset-8 word. F-d7be9cfb4000 returns a zero low portion and changes the word at offset 12 before returning.

The child selection uses the changed word. It does not use a previously captured child value.

If that word is zero and replacement-selector calculation is defined, the operation returns without invoking F-U01, F-U02, or F-469a239057a8 on the parent.

### Replacement selector

Suppose traversal selects a valid compact child and the result’s high portion is 8. The child is processed with selector 9, targeting bit 0 at the child’s offset 13.

This criterion does not extend to a high portion whose signed conversion or increment has unsupported behavior.

### Terminal filtering and call order

Assume the terminal dependencies leave stable, defined local entries. Let the active selector be 7, the first five entries be 0, 7, 11, 11, and minus 3, and the rest be zero.

Exactly three F-469a239057a8 calls occur, in the order associated with the two entries containing 11 and the entry containing minus 3. Each receives the same current object reference, not the entry value.

F-U01 precedes F-U02. Both precede the offset-4 zero write, which precedes all three scan-triggered calls.

The final offset-4 value is not constrained if those calls modify it.

### Selector zero

During terminal processing with selector zero, every observed nonzero entry qualifies, and zero entries remain excluded.

During compact processing, selector zero instead selects displacement 536,870,911 and bit 7 before address formation. It is not a benign no-op, and this calculation alone does not establish a valid access.
