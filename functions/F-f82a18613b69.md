# F-f82a18613b69

## Purpose

F-f82a18613b69 transfers successive bytes from a source address to a destination address. It always attempts at least one transfer. After each destination write, it rereads the source byte used for that transfer and stops if that reread yields zero.

The returned integer counts transfers, including the transfer associated with the terminating zero observation. Under ordinary, stable-memory conditions, this is a zero-terminated byte-string copy whose result includes the terminator in the count.

The distinction between the initial source read and the later source reread is part of the established behavior. Termination is determined by the latter, not by a saved copy of the byte initially read.

No destination capacity, source length, allocation information, or error-reporting mechanism is supplied.

## Interface

|---|---|---|
| First | Destination base | Address at which successive one-byte writes begin |
| Second | Source base | Address at which successive one-byte reads begin |

These arguments are used as addresses, rather than as numeric data to be copied.

The supplied representation uses integer-typed address arguments, a signed integer counter, and an integer return value. A 32-bit address-and-counter model is plausible, but the supplied material does not independently establish an ABI or an explicit integer width. Accordingly, exact address width, counter width, and overflow semantics remain documented_only uncertainties. In particular, a 64-bit address interface or automatic widening must not be assumed.

Each individual memory transfer is exactly one byte. There is no multibyte element layout, byte-order conversion, alignment adjustment, text decoding, or character normalization.

### Output

On normal completion, the function returns the number of completed iterations. Each iteration contains one destination-byte write.

Under stable, ordinary-memory conditions, if the first zero source byte is at offset \(L\), the result is:

\[
L + 1
\]

The destination then contains the source bytes at offsets zero through \(L\), including the zero byte at offset \(L\).

The result is not a destination address and is not the number of nonzero bytes alone. A successful return is never zero within the representable, non-overflowing execution domain.

## Behavior

### Transfer sequence

Processing begins at byte offset zero with a transfer count of zero. There is no initial check for an empty source, invalid address, or zero capacity.

For each reached offset, the observable memory-access sequence is:

1. Read one byte from the source at that offset.
2. Write that byte to the destination at the same offset.
3. Reread the source byte at that offset to decide whether to continue.

Between the destination write and the termination reread, the function advances its internal count to include the transfer just performed. That updated count is the result if the reread observes zero.

If the reread observes a nonzero byte, processing advances to the next byte offset. If it observes zero, the function returns without accessing the next source or destination byte.

The source reread is therefore a distinct access in the supplied representation. The contract must not replace it with an assumption that the initially read byte is retained for the termination decision.

### Stable, nonoverlapping memory

With unchanged source contents and valid, nonoverlapping regions:

- Every source byte preceding the first zero is copied in ascending address order.
- The first zero byte is also copied.
- The function then returns the number of bytes written.
- Destination bytes beyond the copied zero are not written.
- Source bytes beyond the copied zero are not accessed by this function.

A source beginning with zero still causes one source-to-destination transfer, followed by the source reread, and returns one.

### Termination and copied contents can diverge

The byte written to the destination comes from the initial source read. The stop decision comes from the later source reread.

If those two reads produce different values, the copied byte and the stop decision need not agree:

- An initial nonzero value followed by a zero reread causes a nonzero byte to be written, followed by termination.
- An initial zero value followed by a nonzero reread causes a zero byte to be written, followed by continued processing.

These are conditional consequences of the access order, not guarantees about unsynchronized concurrent memory access or device-memory semantics. The supplied material does not establish whether such environments are supported.

### Overlapping regions

There is no overlap detection or alternate transfer direction. Accesses always proceed from lower offsets to higher offsets.

When both bases designate the same ordinary writable memory, each write stores back the byte just read. With stable contents, the function reaches the existing zero byte and returns the ordinary terminator-inclusive count. The writes still occur; equality of the addresses does not turn the operation into a read-only scan.

When the destination begins below the source, writes can affect source locations already processed. Under ordinary, stable-memory conditions and without address wraparound, this does not overwrite future source bytes.

When the destination begins above the source and overlaps it, a write can change a source byte that has not yet been processed. The function may consequently copy values it previously wrote rather than the original source contents. It can overwrite an original zero before reading it, extend processing beyond the original terminated sequence, or fail to reach a zero within valid memory.

No general overlap-safe copying guarantee is established.

### Arithmetic and bounds

Offsets advance by one per completed transfer. There is no explicit length limit.

The relevant upper bound is not merely the number of nonzero source bytes. The terminating transfer also needs a representable count and valid source and destination addresses.

For example, under a signed 32-bit counter interpretation, the maximum positive result would be 2,147,483,647. A stable string containing that many nonzero bytes would require one additional transfer for its terminator and would exceed that result range. The supplied material does not establish what happens at such an overflow, so wrapping to a negative result is not an accepted behavior.

Address overflow, crossing inaccessible memory, and encountering an indefinitely nonzero region likewise have no established successful outcome.

## Side effects

The established external side effects are one-byte destination writes, performed in ascending offset order.

Source memory is read twice per completed iteration in the supplied representation: once to obtain the copied byte and once after the destination write to decide whether to stop. These accesses may matter for memory whose reads have externally visible effects, but support for such memory is not established.

There is:

- No allocation or deallocation.
- No ownership transfer.
- No release of either supplied region.
- No explicit global-state access.
- No explicit external call.
- No rollback after a partial transfer.
- No explicit status update separate from the integer result.

The caller retains responsibility for both memory regions and their lifetimes. The function does not retain either address after returning.

If an access fails after earlier writes have occurred, the supplied material provides no recovery or restoration mechanism. Earlier destination modifications must not be assumed to have been undone. The particular fault, exception, signal, or other platform response is unknown.

## Acceptance examples

These examples are conditional specifications derived from static evidence. They are not runtime test results. Unless stated otherwise, they assume stable ordinary memory, valid addresses, sufficient writable capacity, no arithmetic overflow, and no interfering accesses.

### Empty byte string

The source begins with byte `00`. The destination initially contains arbitrary data.

Expected behavior:

- Read the source byte.
- Write `00` to the first destination byte.
- Reread the first source byte and observe zero.
- Return one.
- Leave subsequent destination bytes unchanged.

### Two nonzero bytes followed by zero

The source begins with `41 42 00`. The destination has at least three writable bytes.

Expected behavior:

- Write `41`, then `42`, then `00` to successive destination positions.
- Return three.
- Do not access the fourth source byte.
- Do not write the fourth destination byte.

The result is three, not two.

### Nonzero bytes with the high bit set

The source begins with `80 FF 00`.

Expected behavior:

- Copy all three bytes without conversion.
- Return three.

Only equality with zero controls termination. Whether a nonzero byte would be interpreted as a negative character value does not change this result.

### Identical source and destination

Both arguments designate the same writable region containing `61 00`.

Expected behavior:

- Perform a write at each of the two processed positions.
- Leave the byte values unchanged under the stated stable-memory assumptions.
- Return two.

The operation is not write-free merely because the final contents match the initial contents.

### Forward overlap destroys the original terminator

A memory region initially begins with `41 00`. The destination begins one byte after the source.

Expected behavior:

- The first transfer writes `41` over the original zero.
- The first termination reread observes the original first source byte, `41`, so processing continues.
- The next transfer reads the overwritten source position rather than the original zero.

A result of two and termination at the original zero are not guaranteed. No specific eventual result is required without additional valid-memory and termination conditions.

### Source changes between its two reads

Assume the environment permits a source byte to yield `7A` on the initial read and `00` on the termination reread.

Expected consequence of the represented access order:

- The destination receives `7A`.
- The function stops after that iteration.
- If this is the first iteration, the result is one.

A terminating return therefore does not universally prove that the last destination byte is zero.
