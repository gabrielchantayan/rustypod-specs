# F-78974f33a1c9

The established behavior is the sequence of memory accesses and calls described below. The surrounding domain is not established. ## Behavior

### 1. Publish initial context state

The function first writes the initial address input plus 0x58 to context offset 0x3C.

It then writes the low eight bits of the state value to context offset 0x38.

These writes precede every dependency call. The initial selected address is therefore observable to dependencies, even though the function later overwrites that field during address selection.

The arithmetic is represented as a 32-bit address calculation. At the represented machine level, retaining 32 bits would wrap an overflowing sum. The supplied material does not independently establish source-language overflow rules or make a wrapped result a valid address.

### 2. Invoke the initial dependency sequence

2. F-517e99e95751, with the backing-object address read from context offset 0x00.
3. F-09c38c5d7c66, with no explicit arguments shown.

Nothing supplied establishes that these dependencies preserve context fields, global storage, or other reachable memory. Later reads must therefore be interpreted at their actual positions in the sequence.

### 3. Select an address from the current backing object

After F-07b0c4a2a001 returns, the function reads context offset 0x00 and retains that backing-object address for the initial branch and associated field accesses.

It reads the 32-bit field at offset 0xD8 of that object.

**If the tested value is zero:**

- Context offset 0x3C receives the retained backing-object address plus 0x58.
- No direct write to object offset 0xDC occurs in this branch.
- F-c8d3272420bf is not called by this branch.

**If the tested value is nonzero:**

- The object’s field at offset 0xD8 is read again, and that value is written to context offset 0x3C.
- The field at offset 0xD8 is read again, and that value is written to offset 0xDC of the retained object.
- F-c8d3272420bf is called with:
  - an address formed by reading the current backing-object address from the context and adding 0x58;
  - a 32-bit value read at offset 0xD8 of a backing object obtained through a context read.

The alternate path contains distinct reads of offset 0xD8. The value used for the branch test is not a single cached value reused for all later operations. Likewise, the call arguments use context-based reads rather than being expressed solely through the retained object address.

For ordinary stable memory, these reads can yield the same object and alternate address. That equality is conditional, not guaranteed by the visible operations. Aliasing, externally changing storage, or special memory semantics could make the distinction observable.

The supplied representation does not establish the evaluation order between the two argument expressions of F-c8d3272420bf.

### 4. Apply the selected address and notify the embedded subobject

The function next calls F-74367d9e9387 with:

- The backing-object address read from context offset 0x00.
- The selected address read from context offset 0x3C.

On the alternate path, these reads occur after F-c8d3272420bf returns. If that dependency changes either context field, the values then present are used; the function does not visibly restore the earlier selection.

F-5ce800dd0f39 is then called with a fresh read of the backing-object address from context offset 0x00.

After that call returns, the function performs indirect dispatch:

1. Read the dispatch-table address from context offset 0x0C.
2. Read the callable entry at dispatch-table offset 0x30.
3. Invoke that entry with the address of context offset 0x0C as its visible argument.

The argument is the address of the embedded context subregion, not the context base and not the dispatch-table address.

No visible result from these calls is used to choose a branch or report an error.

### 5. Write the output byte and evaluate the final condition

It then reads the byte at context offset 0x09.

This order matters if the output-byte destination aliases that condition byte, or if the callback modifies the condition. The branch uses the byte present after both the callback and the output write.

If the condition byte is zero, the function returns without executing the final conditional sequence.

### 6. Perform the conditional final sequence

1. Write the full 32-bit state value to context offset 0x04.
2. Call F-e8d8b1a840f0 with the backing-object address read from context offset 0x00.
3. Clear the byte at context offset 0x39.
4. Write 1 to the first global destination.
5. Write 0 to the second global destination.
6. Return.

The conditional call to F-e8d8b1a840f0 differs from its earlier call site: this later invocation shows an explicit argument.

The byte clear and global writes occur after that call returns. If it does not return normally, those later operations are not established to occur.

### State-value truncation

- Context offset 0x38 receives the byte 0xAB.
- The output-byte destination later receives 0xAB.

### Output aliasing the condition

- A state value whose low byte is zero causes the subsequent condition read to observe zero, absent another intervening agent.
- A state value whose low byte is nonzero causes the conditional final sequence to run under the same assumption.
