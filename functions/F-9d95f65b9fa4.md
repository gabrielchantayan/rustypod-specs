# F-9d95f65b9fa4

## Purpose

F-9d95f65b9fa4 prepares a temporary context, obtains two sets of scalar measurements, computes an initial placement coordinate, and invokes a processing dependency repeatedly across two index ranges. The first range uses a primary handle. The second range uses an optional secondary handle.

The initial coordinate is calculated from the full nominal range, including both portions, even when the secondary portion is subsequently skipped because its handle is zero.

**Inferred intent:** The calculation resembles centering a sequence of equally sized elements, separated by a spacing value, within an available interval. The primary and secondary handles may represent different appearances or processing modes. Neither rendering semantics nor the meanings of the measured coordinates are established by the supplied evidence.

This contract distinguishes direct observations from interpretations. It does not assume that dependencies preserve object fields, initialize every output byte, or release resources.

## Behavior

### 1. Preparation and measurement

1. F-bc9f8e2b0615 is invoked without explicit arguments.
2. F-a4c26c2b4842 receives the address of the temporary context.
3. F-88dd67d704e5 receives the object address and the context address.
4. F-412e4635fdb0 receives the object address and the region-result address.
5. The 32-bit value at region-result offset `+4` is copied into the first placement slot.
6. The current primary handle is read from object offset `0xB4` and passed, with the primary-measurement address, to F-c24767c70ad0.

The primary-measurement call occurs regardless of whether either processing loop will execute. A zero primary handle is not rejected or skipped by this function.

This sequence matters if dependencies modify shared state. In particular, the first placement slot is initialized from the region result before the primary-measurement call. No assumption is made that the latter call preserves globals, object fields, or previously exposed temporary storage.

### 2. Initial placement calculation

Using descriptive names for the quantities involved:

- **Start** is the signed 32-bit value read from object offset `0xAC`.
- **End** is the signed 32-bit value read from object offset `0xB0`.
- **Count** is `End − Start`.
- **Lower** is the region-result value at offset `+4`.
- **Upper** is the region-result value at offset `+12`.
- **Element extent** is the primary-measurement value at offset `+12` minus its value at offset `+4`.
- **Spacing** is the signed 32-bit value read from object offset `0xBC`.

For arithmetic whose intermediate results are representable, the first placement slot is adjusted by:

\[
\operatorname{trunc}_0
\left(
\frac{
(\text{Upper}-\text{Lower})
-
\left[
\text{Spacing}\times(\text{Count}-1)
+
\text{Count}\times\text{Element extent}
\right]
}{2}
\right)
\]

Here, \(\operatorname{trunc}_0\) denotes signed division rounded toward zero.

The adjustment is added to the value already present in the first placement slot. Under the additional condition that dependencies have not changed that slot or the relevant region result, the resulting coordinate is therefore:

\[
\text{Lower}
+
\operatorname{trunc}_0
\left(
\frac{
(\text{Upper}-\text{Lower})
-
\left[
\text{Spacing}\times(\text{Count}-1)
+
\text{Count}\times\text{Element extent}
\right]
}{2}
\right)
\]

The split index does not participate in this calculation. The secondary handle does not participate either. The primary measurements determine the nominal extent for both loop portions.

The calculation is performed even when Count is zero or negative. There is no clamping, range normalization, or special case for an empty nominal range.

### 3. First processing range

The first loop initializes its signed 32-bit index from the current value at object offset `0xAC`.

Before every iteration, the index is compared with the current signed value at offset `0xA8`. An iteration occurs only while the index is strictly less than that value.

Each iteration performs these actions in order:

1. Read the current primary handle from offset `0xB4`.
2. Invoke F-bda93122a121 with that handle, the context address, and the placement address.
3. Increase the first placement slot by the primary-measurement difference plus the current spacing value.
4. Increment the loop index by one.

The primary-measurement difference used in the update is the value at measurement offset `+12` minus the value at offset `+4`. These locations are read again after the processing call; the difference is not established as an immutable cached value.

The loop index is not passed to the processing dependency. Its visible role is iteration control.

### 4. Optional second processing range

After the first loop finishes, the function reads the secondary handle at offset `0xB8`.

- If it is zero, the second loop is skipped.
- If it is nonzero, the second loop initializes its signed index from the current split index at offset `0xA8`.

Before every second-loop iteration, the index is compared with the current signed ending index at offset `0xB0`. An iteration occurs only while the index is strictly less than that ending index.

Each iteration:

1. Reads the current secondary handle from offset `0xB8`.
2. Invokes F-bda93122a121 with that handle, the same context address, and the same placement address.
3. Advances the first placement slot using the same primary-measurement difference and current spacing.
4. Increments the index by one.

The placement coordinate is not reset between loops.

The nonzero test for the secondary handle occurs once, before second-loop entry. The handle is nevertheless read again for each processing call. Consequently, if a dependency changes it to zero during that loop, subsequent calls may receive zero; there is no repeated nonzero guard.

### 5. Finalization

After both loop phases, F-282eebd7c413 receives the context address. The function then returns without a result.

This finalization call also occurs when neither loop executes, provided all earlier operations return normally. No visible mechanism guarantees it after a dependency fault, nonlocal exit, or nonreturning call.
