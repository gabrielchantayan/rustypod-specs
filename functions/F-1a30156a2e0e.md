# F-1a30156a2e0e

## Purpose

F-1a30156a2e0e adjusts an integer input, obtains intermediate values from dependencies, passes one derived value and an output pointer to another dependency, and performs three ordered character stores through that pointer.

The established contract is the sequence of calls, conversions, arithmetic, external reads, and stores below. Constants 60 and 3,600 suggest a time-related decomposition, but that is **inferred intent**, not established behavior. The function has no explicit return value. Observable results consist of output-storage changes and dependency effects.

### Widths and conversions

The represented operations distinguish:

- signed 32-bit working values;
- an opaque 32-bit payload;
- conversion of the payload to signed 16-bit;
- conversion of the selector to plain character;
- conversion of one dependency result to unsigned 8-bit;
- a separate conversion from that unsigned 8-bit value to plain character when storing at output offset 2;
- unsigned 32-bit arithmetic after that store;
- plain-character conversions for the remaining results.

Plain-character signedness is unresolved. An unsigned 8-bit value can represent 0 through 255. If plain character is signed with range −128 through 127, values above 127 are outside its representable range.

Consequently, narrowing a dependency result to unsigned 8-bit does **not**, by itself, establish the character value or bit pattern subsequently stored at offset 2. That assignment performs another conversion. Exact stored-byte claims for values above the signed-character range require an additional target-conversion assumption.

The unsigned 8-bit local remains distinct from the converted output value. Subsequent arithmetic uses the unsigned local, not a value read back from output storage.

Out-of-range conversions to signed types must not be assumed to preserve low bits universally. The explicit unsigned 32-bit arithmetic is modulo \(2^{32}\); conversion of its result back to signed 32-bit is a separate boundary.

Pointer width, endianness, and dependency-specific alignment requirements are not established.

## Behavior

### 1. Optional correction lookup

The function copies the selector and payload into local storage.

If the initial selector is zero, F-59067e4d309c is not invoked and no correction is applied. A nonzero payload does not independently trigger lookup.

Otherwise, F-59067e4d309c receives, in order:

1. the address of the local payload;
2. the address of the local selector.

A zero return suppresses correction. Any nonzero return enables it, including a negative return.

When enabled, correction uses the post-call local values:

- the payload is converted to signed 16-bit and promoted to the working integer type;
- the selector is converted to plain character and promoted;
- the contributions are added;
- their sum is multiplied by 60;
- that product is added to the working input.

Under an ordinary low-bit signed-16-bit conversion rule, a payload with low halfword 65,535 contributes −1. That interpretation is conditional for an out-of-range source value.

The selector contribution likewise depends on character signedness and conversion rules. Under ordinary eight-bit low-bit conversion, a low byte of 255 contributes −1 with signed characters or 255 with unsigned characters.

A zero lookup return does not roll back mutations. Modified local selector and payload values remain available to later operations even when correction is suppressed.

### 2. Bias and first arithmetic call

After optional correction, the function reads G-bias and adds it to the working input. Call the resulting signed working value **T**.

It invokes F-d7be9cfb4000 with four supplied arguments:

1. T;
2. G-factor;
3. the current full-width local selector;
4. the current full-width local payload.

Call the returned integer **Q**.

The narrow conversions used for correction do not replace the full-width local copies. Upper bits remain available in these arguments unless the lookup changed them.

No mathematical meaning for Q is established. In particular, “quotient” would imply an unverified dependency contract.

### 3. Output-producing call

After the first arithmetic call returns, the function reads G-origin and invokes F-a062a6eb1219 with:

1. Q plus G-origin;
2. the original output pointer.

Its return value, if any, is ignored.

This call precedes all three explicit output stores. If execution reaches those stores, they replace any values previously written at the corresponding locations. Dependency effects occurring later can still affect earlier stores.

The dependency’s format, write extent, capacity requirement, ownership rules, and state-preservation behavior are unresolved.

### 4. Scaled adjustment

After F-a062a6eb1219 returns, the function reads G-scale and adjusts the retained working value.

Where the relevant arithmetic is representable:

\[
U = T + (Q \times G\text{-scale}) \times 128.
\]

The multiplication groups Q with G-scale before multiplication by 128. Intermediate representability matters; an equivalent unbounded mathematical expression does not establish behavior if an intermediate signed operation exceeds its range.

G-scale is read after the output-producing call, not captured at entry. Changes made by earlier dependencies can therefore affect U.

### 5. Call using 3,600 and store at offset 2

F-d7be9cfb4000 is invoked with:

1. U;
2. 3,600.

The result is converted to an unsigned 8-bit local, **H**. For an integral result, this conversion yields its residue modulo 256.

The function then assigns H to the plain-character output element at offset 2. This introduces a **second conversion**, from unsigned 8-bit to plain character. Call the converted character **C₂** when that conversion completes normally.

The distinctions are:

- H is the unsigned local used by subsequent arithmetic.
- C₂ is the character supplied by the assignment to offset 2.
- The stored representation of C₂ is not unconditionally established to be H’s bit pattern.

If H is representable as plain character, the assignment preserves its numeric value. Thus H = 1 produces character value 1 regardless of character signedness.

If H is above 127 and plain character is signed with an eight-bit signed range, the source value is not representable. Its converted result is unresolved without the target’s conversion rules. A low-bit-preserving stored representation is a conditional outcome, not an unconditional guarantee.

For example, a dependency return of 456 produces H = 200. The offset-2 assignment must convert 200 to plain character, while the next arithmetic step still uses unsigned H = 200.

### 6. Unsigned adjustment

After the offset-2 assignment, the function explicitly converts H to unsigned 32-bit before multiplying it by negative 3,600.

Under the represented 32-bit model:

1. negative 3,600 is converted to unsigned 32-bit for multiplication;
2. multiplication is modulo \(2^{32}\);
3. U is converted to unsigned 32-bit for addition;
4. addition is modulo \(2^{32}\);
5. the result is converted back to the signed working type.

Let **W** be the unsigned result:

\[
W =
\left(
(U \bmod 2^{32})
+
H(2^{32}-3600)
\right)
\bmod 2^{32}.
\]

Thus W is the unsigned residue of \(U-3600H\).

This calculation uses H, not C₂ and not output storage. An out-of-range character conversion at offset 2 does not replace the unsigned local with a signed character value.

If W is at most 2,147,483,647, its conversion to signed 32-bit yields the same value. Above that bound, the signed result depends on the applicable conversion rules.

Call the resulting signed working value **R**. The simpler equation \(R=U-3600H\) is valid only where representability and conversion rules support it. This step is not merely signed subtraction.

### 7. Call using 60 and remaining stores

F-d7be9cfb4000 is invoked with:

1. R;
2. 60.

The result is converted to plain character, **M**, and stored at output offset 1.

This call occurs after the offset-2 store. Without a preservation guarantee, it may modify that earlier location through independently accessible or retained storage.

For the final store, the function:

- promotes that character for arithmetic;
- adds M multiplied by negative 60;
- converts the result to plain character for assignment at offset 0.

The narrowing of R occurs before this arithmetic. The operation is not established as a full-width remainder calculation.

Under ordinary eight-bit low-bit conversion semantics, the final stored byte is congruent to \(R-60M\) modulo 256. This statement is conditional on those conversion semantics.

The explicit store order is offset 2, then offset 1, then offset 0. The function then returns without an explicit result.

## Acceptance examples

These are conditional examples, not executed tests. Unless stated otherwise, assume valid storage, normally returning dependencies, representable arithmetic, and no additional dependency effects.

### Zero selector bypasses lookup

With initial selector zero, F-59067e4d309c is not invoked and correction is skipped. The first arithmetic call receives zero as its third argument and the original payload as its fourth. G-bias is still added.

### Lookup mutations survive a zero return

If lookup changes the local selector to 7 and payload to 9, then returns zero, no correction is added. The first arithmetic call nevertheless receives 7 and 9 in its third and fourth positions.

### Signed payload contribution

Suppose lookup returns nonzero, the payload’s low halfword is 65,535, and the selector converts to character value 2.

Under a low-bit signed-16-bit conversion rule, the correction is:

\[
(-1+2)\times60=60.
\]

Upper payload bits do not affect that narrow contribution, but remain in the full-width argument unless lookup changed them.

### Conditional nonnegative decomposition

Assume T = 3,661, Q = 0, and the later arithmetic calls perform integer division for these inputs.

Then U = 3,661. The call using 3,600 returns 1, giving H = 1 and C₂ = 1. The unsigned adjustment yields W = 61 and R = 61. The call using 60 returns 1. The remaining stores write character value 1 at offsets 1 and 0.

If no intervening effect changes offset 2, the final prefix is **[1, 1, 1]**. This does not establish division as the dependency’s actual operation.

### Unsigned narrowing precedes adjustment

Suppose U = 10,000 and the call using 3,600 returns 257.

H is 1, the offset-2 character value is 1, and W = R = 6,400. The next call receives 6,400, not a value obtained by subtracting \(257\times3,600\).

### Offset-2 conversion does not change the arithmetic operand

Suppose U = 720,005 and the call using 3,600 returns 200.

H is 200. The subsequent unsigned adjustment yields W = R = 5.

The offset-2 assignment is separate:

- with unsigned plain character, C₂ is 200;
- with signed eight-bit plain character, conversion of 200 is out of range and its outcome requires the target’s conversion rules;
- under low-bit-preserving signed-character conversion, C₂ is −56 with the corresponding low-bit representation.

If that assignment completes normally, the arithmetic still subtracts \(200\times3,600\), not \((-56)\times3,600\).

### Unsigned result outside the signed range

With U = 0 and H = 1, W is 4,294,963,696.

Its conversion to signed 32-bit is out of range. Under a two’s-complement low-bit conversion rule, R would be −3,600. That result is conditional.

### Late scale read

If F-a062a6eb1219 changes G-scale from 2 to 3 and nothing changes it before the subsequent read, the scaled adjustment uses 3.

### Offset 2 is not protected

Suppose C₂ = 1 is stored, then the call using 60 changes that location to character value 9 through accessible storage. The function does not explicitly restore offset 2; its remaining stores target offsets 1 and 0.
