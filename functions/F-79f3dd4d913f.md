# F-79f3dd4d913f

## Purpose

The supplied body does not establish a higher-level purpose. In particular, it does not establish that the argument denotes a buffer, that any result is a status code, or that the arithmetic implements a conventional comparison.

## Interface

### Input and result

The interface has one integer argument and an integer result. The supplied representation uses signed integer types for both, but their ABI widths are not independently established.

The argument is initially retained without dereferencing it. Particular states can save it, distinguish zero from nonzero, and propagate it into the base of a computed byte-store address.

Consequently:

- Zero is a state-selection input, not an unconditional error.
- A nonzero argument is not validated as an address.

## Behavior

### Arithmetic qualifications

The state transitions and access ordering below are established from the supplied body. Numerical simplifications require additional assumptions.

The **word model** used here assumes 32-bit integer bit patterns, arithmetic modulo \(2^{32}\) where needed, and bit-preserving conversions between the relevant signed and unsigned representations. The **byte model** additionally assumes eight-bit stored bytes and ordinary truncation to the low eight bits.

These are conditional interpretations, not a claim that all expressions have defined language-level behavior for every input. Some intermediate expressions involve signed arithmetic before assignment to unsigned storage. A later unsigned conversion does not itself make earlier signed overflow valid.

Integer-to-pointer and pointer-to-integer conversions require separate qualification. Arithmetic right shift of a signed 32-bit value is also an assumption, not an established portability guarantee.

### Initialization and dispatch

The function captures \(M\) first. It initializes its recurrence accumulator, two output factors, recurrence difference, transformed value, working result, saved argument, selected address base, and byte-store base to zero.

The retained dispatch base is one reference to \(D\), decreased by eight. A separate, later reference to \(D\) supplies the initial current state. These are not established to be a single shared snapshot.

Each dispatch entry references \(S\) before selecting a case. That value is retained for the byte-write tail, even though many cases do not use it.

The dispatch index is the current state minus the retained dispatch base. Cases 0 through 10 have explicit handling; all other indices share case 0.

If both initialization references to \(D\) agree and the dispatch arithmetic is valid, the initial case is 8.

### Argument retention and selection: cases 8 and 2

Case 8 obtains its next state from \(U_8\), then saves the original argument. It does not dereference the argument.

Case 2 chooses a next-state value using whether the saved argument is zero. With a stable \(B\) and valid arithmetic:

- A nonzero saved argument selects \(B\).
- A zero saved argument selects \(B+1\).

The source expression contains two references to \(B\). Both are present for either argument class; multiplication by zero is not short-circuit evaluation. Their relative evaluation order is not established.

After assigning the next state, case 2 copies the saved argument into the selected address base. That base is not yet necessarily the base used by a byte store.

### Redirects and configured result: cases 1, 3, 4, and 5

### Zero store: case 9

The pointed-to type is absent. Therefore, the width of this store is unresolved; it must not be specified as one byte, four bytes, or one pointer-sized object.

### Recurrence initialization: case 7

Case 7 sets the recurrence accumulator to four and supplies an address-shaped intermediate with bit pattern `0xFFFFFFD4` to a shared transformation tail.

That tail converts the intermediate to an integer, multiplies it by retained \(M\), saves the transformed value, and then obtains the next state from \(U_w\).

Under bit-preserving 32-bit conversions, the transformed value is congruent to \(-44M\) modulo \(2^{32}\). There is no dereference of the address-shaped intermediate.

### Byte output: case 0 and unmatched indices

This path updates the recurrence accumulator to the scale \(S\) times the sum of \(M\) times its old value and \(T\). It then calculates the working result as another reference to \(S\), multiplied by \(M\) and the updated accumulator.

These two references to \(S\) are separate from each other and from the dispatch-entry reference.

The working result is also the byte-store offset. One byte is stored at the address formed by adding that offset to the retained byte-store base. There is no visible bounds or validity check.

The stored byte can be characterized independently as a family of affine maps over byte residues:

- Let the **slope** be 65 times the low byte of the first output factor, reduced modulo 256.
- Let the **multiplier selector** be the predecessor of the second output factor, reduced to a byte, with bit positions 0, 1, 3, and 7 forced to one. Bit positions are numbered from the least significant bit.
- At transformed value zero, the output is the slope multiplied by the byte residue of 37 plus retained \(M\) times that selector.
- Increasing the low byte of the transformed value by one increases the output by the slope, modulo 256.

These properties specify the byte mapping under the byte and word models without requiring a signed-versus-unsigned interpretation of plain-character intermediates. Relevant alternative extensions differ by multiples of 256.

Consequences include:

- A first output factor divisible by 256 produces a zero byte, but does not suppress the store.
- Only the selector’s unforced bits—positions 2, 4, 5, and 6—can distinguish second-factor residues after taking the predecessor.
- Only low-byte residues affect the stored value under this interpretation.

After the store, the shared transformation tail uses the scale retained at dispatch entry, multiplied by the retained recurrence difference. It converts that address-shaped intermediate back to an integer and multiplies by \(M\) to replace the transformed value. It then references \(U_w\) for the next state.

Thus, under bit-preserving word conversions, the new transformed value is the product of retained \(M\), the dispatch-entry scale, and the retained recurrence difference. No fresh reference to \(S\) supplies that post-store scale.

### Decision and output preparation: case 10

Case 10 first constructs two decision inputs:

- A **scaled position**, obtained from a fresh reference to \(S\), retained \(M\), and the recurrence accumulator.
- A **comparison word**, obtained from retained \(M\), the accumulator, and \(E\), increased by one.

Their evaluation is completed before the decision result replaces the working result. The dispatch-entry reference to \(S\) is distinct from the reference used for the scaled position.

The decision is a configurable arithmetic/bitwise mixture. The body does not justify calling it a range check, comparison, or validity test.

Under the word model, an independently normalized characterization is a modular sum of two contributions:

**Displacement contribution.** Take the difference between the scaled position and the comparison word with the \(K_1\) bits forced on, adjusted downward by one reference to \(H\). Its bits are toggled wherever the predecessor of the other reference to \(H\) has a set bit.

**Selected correction.** First consider the correction word whose numerical value is \(L\) minus the scaled position plus the comparison word with \(K_3\) bits forced on. The selected correction is characterized bit by bit:

| Bit in the predecessor of the scaled position | Selected-correction bit |
|---|---|
| One | Zero |
| Zero | The corresponding correction-word bit, toggled when the corresponding bits of \(K_2\) and \(K_4\) differ |

The working result is the modular sum of the displacement contribution and selected correction.

This normalization preserves the word-model result while replacing the nested arithmetic/bitwise tree with a displacement and a selectively enabled correction. It does not extend the domain of defined signed arithmetic.

The decision calculation contains:

- One reference each to \(S\), \(E\), \(L\), and each of the four masks.
- Two references to \(H\), not necessarily equal if its storage can change.

No ordering between references within the compound decision expression is established. In particular, “one” and “other” \(H\) references identify their operand roles, not a guaranteed evaluation order.

After assigning the decision result, case 10 performs the following ordered preparation:

1. The first output factor becomes the transformed value plus \(A\).
2. The recurrence difference becomes the transformed value minus \(T\).
3. The next state is assigned using \(N\), the dispatch base, and a selector derived from the decision result.
4. The second output factor becomes the transformed value multiplied by \(J\).
5. The byte-store base becomes the selected address base.

The selector is the negation of the signed result shifted right by 31, with the unsigned conversion present in the supplied expression. Under 32-bit arithmetic-right-shift assumptions, it equals one for a negative result and zero otherwise. Under those assumptions:

- A negative result selects the retained dispatch base, so the next dispatch index is zero.
- A nonnegative result selects the value supplied by \(N\).

The reference to \(N\) is unconditional in the arithmetic expression. It remains present even when its multiplier is zero. It follows the recurrence-difference assignment and precedes the reference to \(J\).

Without the stated width and shift assumptions, the selector need not be Boolean, and the next-state calculation must not be replaced by this two-way interpretation.

## Acceptance examples

These are conditional static consequences, not executed tests.

1. **Initial retention.** Equal initialization references to \(D\), with valid arithmetic, select case 8 first. The argument is saved without dereferencing it.

2. **Return without result replacement.** If case 8 selects case 6, the result is zero. Both dispatch entries contain references to \(S\); their runtime observability is unresolved.

3. **Configured result.** Case 4 followed by case 6 returns the value referenced through \(C\), provided nothing changes the result between those cases.

4. **Zero store.** Case 9 followed by case 6 stores zero through a valid \(Z\) destination and returns zero. The number of bytes cleared is not established.

5. **Argument selection.** With stable \(B\), saved zero selects \(B+1\), and saved nonzero selects \(B\). Both source references to \(B\) remain present.

6. **Recurrence initialization.** Under bit-preserving word conversions, case 7 establishes accumulator four and transformed value \(-44M\) modulo \(2^{32}\), without writing through the address-shaped constant.

7. **Byte mapping.** Under the byte model, a zero first-factor residue stores zero. A first-factor residue of one, retained \(M\) equal to zero, and transformed-value residue zero produce byte value 101. Changing that transformed-value residue to one produces 166. The destination must still be valid.

8. **Decision boundary.** Under the word model, an accumulator of zero makes the scaled position zero and comparison word one. If all decision offsets and masks are also zero, the decision result is zero. No higher-level meaning follows from that value.

9. **Negative decision.** Under arithmetic right shift, a negative decision selects dispatch index zero. The reference to \(N\) still occurs at the source level before the reference to \(J\).

10. **Nonnegative decision.** Under the same assumptions, a nonnegative decision selects the state supplied by \(N\). Output preparation completes before the next dispatch.

11. **Default and cycles.** An unmatched dispatch index takes the byte-write path, not an error path. A redirect selecting itself can dispatch indefinitely.
