# F-ce86f0721c89

## Purpose

F-ce86f0721c89 is represented as a nonterminating sequence of indirect calls, byte-sized control writes, and 32-bit word writes. Results obtained from indirect calls determine subsequent addresses, values, and call arguments. State produced near the end of an iteration becomes input to the next iteration.

No application-level purpose is established. In particular, the evidence does not establish that the addressed locations are ordinary memory, device registers, allocated objects, or a particular data structure. References below to “selectors,” “bases,” and “words” describe observable operations, not inferred application semantics.

This contract describes the supplied static representation. It does not establish that the representation accurately reconstructs executable behavior on its original platform. No runtime tests have been performed.

## Interface

### Explicit inputs

The represented interface has four explicit arguments:

| Argument | Represented width | Observed use |
|---|---:|---|
| First | 32 bits | Passed to the first indirect call of an iteration. Replaced before the next iteration. |
| Second | 32 bits | Passed with the first argument. Replaced before the next iteration by an incompletely characterized secondary call result. |
| Third | 32 bits | No explicit use appears. |
| Fourth | 32 bits, unsigned interpretation | Supplies a byte-field extraction early in the first iteration. Replaced by a computed value before subsequent iterations. |

The displayed return type is void, but there is no represented normal return.

### Additional entry state

The body also consumes machine state not supplied by the four explicit arguments:

- A 32-bit entry base used to locate a selector byte.
- A 32-bit entry word used as an initial stored value and as a shifted call argument.
- An entry dispatch anchor used to determine the first indirect-call destination.
- A global 32-bit word read partway through each iteration.
- A secondary register result observed near the iteration boundary.

These dependencies prevent a complete portable calling convention from being established from the explicit signature alone.

### Width and notation conventions

For the behavioral ledger below:

- All scalar tokens denote 32-bit bit patterns unless explicitly identified as bytes or 64-bit results.
- Address arithmetic and left shifts are described using their low 32 bits. This is the intended machine-width interpretation of the representation, not a claim that every displayed signed expression has defined portable-language semantics.
- A byte write stores only the low eight bits.
- A word read or write transfers 32 bits.
- Right shifts of explicitly unsigned values are logical.
- A split 64-bit result supplies its low 32 bits first and its high 32 bits second when both are forwarded.
- A **selector write through base \(B\)** means: read an unsigned byte at \(B+1\), zero-extend it to an address, then write one byte at that address plus \(0x11\). It does not mean writing at \(B+0x11\).
- A **selection chain** means five ordered indirect calls: an initiating call with the stated arguments, three calls with no explicit arguments, and a final call with no explicit arguments whose result is retained.

“Without explicit arguments” describes only what is shown. It does not establish that a destination ignores registers, memory, or other ambient state.

Symbols introduced in the ledger are contract notation for retained results, not implementation identifiers.

## Behavior

### Execution and ordering rules

The represented body repeats indefinitely. Each iteration executes the following ledger in order, provided every call returns and every access completes.

Indirect calls separate memory operations throughout the ledger. They cannot be treated as inert separators: their memory effects, register effects, termination behavior, and ownership behavior are unknown. A selector read performed after a call must therefore not be replaced with a selector value read before that call.

Distinct selection chains do not imply a shared helper function. They describe repeated call shapes at different call sites.

### 1. Initial word publication and control-byte update

1. Execute a selection chain initiated with the current first and second arguments. Retain its final result as \(A\).
2. Write the current entry word to address \(4A+0x14\).
3. Execute a selection chain initiated with \(4A\). Retain its result as \(B\), and retain \(P=4B\).
4. Through the current entry base, perform a selector write containing the low byte of:
   \[
   (\text{fourth argument}\ \&\ 0x3fffffff)\mathbin{\gg}20.
   \]

The extraction before byte truncation can contain ten bits. The resulting stored byte contains original argument bits 20–27; bits 28–29 are discarded by the byte store, and bits 30–31 were masked out.

### 2. First split-result exchange

1. Make an indirect call with the current entry word shifted left by 12.
2. Make a no-explicit-argument call and retain its 32-bit result.
3. Pass that result and \(P\) shifted left by 28 to another indirect call.
4. Make a no-explicit-argument call returning a represented 64-bit value.
5. Pass its low and high halves, in that order, to another call.
6. Make one no-explicit-argument call, then another whose result is retained as \(C\).
7. Re-read the selector through the current entry base and write zero to its selected byte.
8. Execute a selection chain initiated with \(4C\). Retain its result as \(D\), and define \(Q=4D\).
9. Write \(Q\) to address \(4096P+0x14\).

The earlier and later selector writes need not target the same byte: intervening calls may modify the selector source.

### 3. Word replication and formation of a sparse base

1. Execute a selection chain initiated with four arguments, in order:
   \[
   1024P,\quad1024P,\quad B\ll14,\quad Q.
   \]
   Retain its result as \(E\).
2. Write \(Q\) to \(4E+0x14\).
3. Execute a selection chain initiated with \(4E\), retaining \(F\).
4. Define \(R=4F\). Write \(R\) to \(16F+0x14\).
5. Execute a selection chain initiated with \(R,R,R\), retaining \(G\).
6. Write \(R\) to \(4G+0x14\).
7. Execute a selection chain initiated with \(4G\), retaining \(H\).
8. Define \(S=4H\) and \(T=H\times0x40000000\).
9. Write \(S\) to \(16H+0x14\).
10. Execute a selection chain initiated with \(S,S,S\), retaining \(I\).
11. Write \(S\) to \(4I+0x14\).
12. Execute a selection chain initiated with \(4I\), retaining \(J\).

Under the stated 32-bit interpretation, \(T\) is determined solely by the low two bits of \(H\).

### 4. Direct clears, word lookup, and retained result

1. Write zero directly to \(T+0x11\), then directly to \(T+1\). These are not selector writes.
2. Make a call with \(4J\), a no-explicit-argument call whose result is retained, and a call receiving that result.
3. Make four no-explicit-argument calls; retain the fourth result as \(K\).
4. Again write zero directly to \(T+0x11\), then to \(T+1\).
5. Execute a selection chain initiated with \(4K\), retaining \(L\).
6. Define \(U=4L\). Write \(I\ll31\) to \(16L+0x14\).
7. Read a 32-bit word from:
   \[
   ((J\ \&\ 0x3fffffff)\gg20)+0x14.
   \]
   Retain the loaded word as \(V\).
8. Make a call with \(U\), followed by a no-explicit-argument call whose result is retained as \(W\).

The lookup address ranges from \(0x14\) through \(0x413\), inclusive. No alignment check appears. A platform requiring aligned word reads therefore needs an additional environmental guarantee.

The stored value \(I\ll31\) is either zero or \(0x80000000\), depending on the low bit of \(I\).

### 5. Further byte programming and cached-selector word write

1. Execute a selection chain initiated with:
   \[
   (V\gg22)\ll28.
   \]
   Retain its result as \(X\).
2. Write a zero word to \(4X+0x14\).
3. Execute a selection chain initiated with \(4X\), retaining \(Y\).
4. Through base \(T\), perform a selector write containing the low byte of \(4Y\).
5. Make a call with \(4Y\), then a no-explicit-argument call whose result is retained.
6. Pass that result and \(Y\ll30\) to another call.
7. Make four no-explicit-argument calls; retain the fourth result as \(Z\).
8. Read the selector byte at \(T+1\) and cache it as byte \(b\).
9. Write the low byte of \((Y\ \&\ 0x3fffffff)\gg20\) to \(b+0x11\).
10. Execute a selection chain initiated with \(4Z\); its final result is not explicitly used.
11. Write \(4W\) to \(b+0x14\), using the cached byte rather than re-reading \(T+1\).
12. Read the global 32-bit word and retain it as \(N\).

The cached-selector rule is significant: calls in step 10 may change \(T+1\), but the word write still uses \(b\).

The first shifted argument in this phase retains only bits 22–25 of \(V\), positioned at bits 28–31. The second argument \(Y\ll30\) retains only the low two bits of \(Y\).

### 6. Global-derived selector update and scaled word publication

1. Execute a selection chain initiated with \(U\), retaining a represented 64-bit result.
2. Define \(P_2\) as four times that result’s low half.
3. Through base \(T\), perform a selector write containing the low byte of \(N\gg22\).
4. Call an indirect destination with the high half of the 64-bit result.
5. Make a no-explicit-argument call and retain its result.
6. Pass that result and \(P_2\ll28\) to another call.
7. Make four no-explicit-argument calls; retain the fourth result as \(A_2\).
8. Through base \(T\), perform a newly resolved selector write of zero.
9. Execute a selection chain initiated with \(4A_2\), retaining \(B_2\).
10. Execute a selection chain initiated with \(4B_2,4B_2\), retaining \(C_2\).
11. Define \(Q_2=4C_2\). Write \(Q_2\) to \(4096P_2+0x14\).
12. Execute a selection chain initiated with \(P_2\ll14\), retaining \(D_2\).
13. Write \(Q_2\) to \(4D_2+0x14\).

The global is sampled once at the stated point. Later calls do not cause that retained sample to be refreshed.

### 7. Final exchanges and next-iteration state

1. Execute a selection chain initiated with \(4D_2\), retaining a represented 64-bit result.
2. Define \(R_2\) as four times its low half.
3. Through base \(16384P_2\), perform a selector write containing the low byte of:
   \[
   (Q_2\ \&\ 0x3fffffff)\gg20.
   \]
4. Call an indirect destination with the high half.
5. Make a no-explicit-argument call and retain its result.
6. Define \(T_2=R_2\times0x10000000\). Pass the retained result to another call.
7. Make a no-explicit-argument call returning 64 bits; pass its low and high halves to another call.
8. Make two no-explicit-argument calls, retaining the second result as \(E_2\).
9. Through base \(T_2\), perform a selector write of zero.
10. Execute a selection chain initiated with \(4E_2\), retaining \(F_2\).
11. Set the next entry base to \(4R_2\). Through that base, perform a selector write of zero.
12. Call an indirect destination with \(R_2\ll10\), make a no-explicit-argument call retaining its result, then pass that result and \(W\ll28\) to another call.
13. Make four no-explicit-argument calls, retaining the fourth result as \(G_2\).
14. Through the next entry base, perform another freshly resolved selector write of zero.
15. Execute a selection chain initiated with \(4G_2\). Its final result is not explicitly used.
16. Set the next entry word to \(F_2\ll14\). Write it to \(4096(4F_2)+0x14\).
17. Replace the fourth argument with that next entry word.
18. Call an indirect destination with \((4F_2)\ll14\), then make one no-explicit-argument call.
19. Establish the next dispatch anchor, set the first argument to the fourth argument shifted left by 28, and set the second argument from the represented secondary register result.
20. Repeat from phase 1.

Under 32-bit arithmetic, the next entry word has fourteen low zero bits. Consequently, the next first argument is zero. This consequence applies to subsequent iterations, not necessarily the initial invocation.

## Side effects

The function explicitly performs:

- Indirect calls with observable ordering.
- Byte reads used as low-address selectors.
- Byte writes, including repeated zero writes.
- Word writes to call-result-derived addresses.
- A word read from a small, potentially unaligned address.
- A global word read.
- Iteration-to-iteration updates of explicit and hidden state.

Byte-selected destinations lie between \(0x11\) and \(0x110\); cached-selector word destinations lie between \(0x14\) and \(0x113\). These accesses are literal addresses in the representation, not offsets from the original selector base.

No allocation, release, ownership transfer, synchronization primitive, error return, or rollback operation is explicitly identified. Dependencies may perform such actions; their absence cannot be assumed. Repeated writes are not established as redundant, particularly if memory is externally observable.

Most destinations are formed from fixed dispatch anchors with a common displacement. Several use different displacements, and the first destination depends on incoming machine state. Exact target identities, target aliasing, calling conventions, and hidden arguments remain unresolved.

## Acceptance examples

These examples are conditional static expectations, not executed tests.

1. **Initial field truncation.** If the fourth argument is \(0x3ff00000\), the first selector write stores \(0xff\), not the ten-bit value \(0x3ff\).

2. **Selector indirection.** If a selector byte read yields \(0x80\), its selected byte destination is \(0x91\), regardless of the address from which the selector was read.

3. **Selector mutation between writes.** If a dependency changes the entry-base selector between phase 1 and phase 2, the later zero write follows the new selector. It is not required to clear the earlier destination.

4. **Cached selector.** If phase 5 caches selector \(0x20\), its later word write targets \(0x34\), even if intervening calls change the selector source to \(0x40\).

5. **Sparse-base arithmetic.** If \(H=5\), then \(T=0x40000000\). Phase 4 first clears \(0x40000011\), then \(0x40000001\).

6. **Low-bit-dependent word.** If \(I\) is even, phase 4 writes zero at its specified word destination. If \(I\) is odd, it writes \(0x80000000\).

7. **Iteration recurrence.** If \(F_2=1\), the next entry word and fourth argument are \(0x4000\), the corresponding word destination is \(0x4014\), and the next first argument is zero.

8. **Interrupted dependency.** If any dependency does not return, subsequent ledger events do not occur. No compensating write or cleanup is established.
