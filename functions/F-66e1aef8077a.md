# F-66e1aef8077a

## Purpose

F-66e1aef8077a performs a cache-gated update involving two associated objects. Two externally stored 32-bit values determine whether an update is necessary. If either differs from its cached counterpart, the function derives geometry from the first value, derives complementary values from the second, updates both caches, and invokes an ordered sequence of object operations.

A cache match suppresses the entire update, even if dimensions, object references, or other context fields have changed independently.

**Established behavior:** the field accesses, arithmetic relationships, conditional adjustment calls, cache writes, dependency arguments, and call ordering specified below.

**Inferred intent:** the operation resembles a visual transition with scaling, cropping, and complementary opacity or intensity. Those interpretations do not establish the meaning of any dependency.

## Behavior

### Cache gate and input lifetime

The first external value is obtained through the address at `0x50`; the second is then obtained through the address at `0x54`. Both external reads occur before either cache comparison determines the result.

The first cache entry, at `0x58`, is always read. The second cache entry, at `0x5c`, is read only when the first external value matches its cache.

If both comparisons match, the function returns 1 with:

- No direct context writes.
- No dependency calls.
- No reads of the dimensions, selector, object values, or final partner values.

A mismatch in either value activates the complete update. A change only in the second value does not restrict the update to complementary-value operations: geometry is recalculated and all subsequent operations still occur.

The external values are captured once. Later operations use those captured values rather than refreshing the external records.

### Arithmetic model

Scalar calculations use the supplied 32-bit representation, not unlimited-precision arithmetic. Unsigned operations retain 32-bit results; unsigned right shifts insert zeros. Signed division by two truncates toward zero.

Some expressions contain signed arithmetic or conversions between unsigned results and signed values. Their out-of-range behavior is not fully determined by the supplied representation. The ordinary-range relationships below apply where those operations are representable. They must not be extended into an unconditional promise of wrapping for every expression.

### Target dimensions and independent bounds

The width target comes from the first external value by adding 32,767, shifting right by 16 positions, and clearing the lowest two result bits. For nonnegative inputs without signed addition overflow, this is an upward-biased conversion to an integer followed by alignment downward to a multiple of four. It is not ordinary rounding to the nearest multiple of four.

The height target is three quarters of the width target, using a **32-bit unsigned product by three followed by a logical right shift of two**. This relationship uses the width target before either dimension is bounded. Overflow in that unsigned product therefore affects the height target.

The stored width is read before the stored height. Each dimension is selected independently:

- When four times the stored dimension is unsigned-less-than its target, the selected dimension is that fourfold quantity.
- Otherwise, the selected dimension is the unsigned maximum of the target and the stored dimension’s signed quarter, truncated toward zero and then interpreted as a 32-bit unsigned quantity.

For ordinary nonnegative dimensions without overflow, this bounds the target between one quarter and four times the stored dimension. That description is not a general signed-size clamp: negative dimensions can become very large unsigned comparison operands.

The stored-width fourfold comparison and corresponding width shift use unsigned 32-bit arithmetic. The stored-height fourfold expression includes signed multiplication before an unsigned comparison; its overflow behavior cannot simply be equated with the width case.

The selected height is not recomputed from the selected width. Independent bounding can change their aspect ratio.

### Optional adjustment

Initially, both adjustments are zero, the remaining source dimensions equal the stored dimensions, and the output dimensions equal the selected dimensions.

Adjustment occurs only when the stored width is **unsigned-less-than the selected width**. There is no independent height-growth test. Consequently, width growth causes both adjustment calls, while height growth alone causes neither.

On this branch, each selected dimension supplies a margin:

- Horizontal margin: the logical half of the selected width, less 160.
- Vertical margin: the logical half of the selected height, less 120.

F-d7be9cfb4000 receives the horizontal margin multiplied by the stored width, together with the selected width. Its result supplies the horizontal adjustment. A second call receives the vertical margin multiplied by the stored height, together with the selected height; its result supplies the vertical adjustment. The horizontal call completes before the vertical call.

The dependency is not established to perform division, proportional scaling, or rounding. Its return values are accepted without local validation.

Each output dimension is reduced by twice its corresponding margin. Each remaining source dimension is reduced by twice the corresponding returned adjustment. Under representable arithmetic, the resulting output width is 320 for an even selected width and 321 for an odd selected width; the analogous height is 240 or 241. Thus “320 by 240” is not an unconditional branch result.

Products, doubled adjustments, and reductions can encounter signed-range or conversion issues. No saturation, minimum source extent, or rejection of excessive adjustments is shown.

### Positions and cache commitment

The horizontal position is the signed half of the stored width, truncated toward zero, less the logical half of the output width. A result interpreted as negative is replaced with zero. The vertical position follows the same rule using height.

The cache writes occur after any adjustment calls and before the geometry call, in this order:

1. Captured second external value to `0x5c`.
2. Captured first external value to `0x58`.

More precisely, the horizontal position calculation precedes these writes; its negative clamp follows them. The vertical position calculation follows the cache writes.

Both caches therefore record the captured inputs before the object-operation sequence completes. There is no rollback or delayed commitment if a later dependency fails to return.

Position subtraction combines signed halves with unsigned output halves. Ordinary representable examples have the centering-and-zero-clamping behavior described above; portable behavior for out-of-range signed conversions remains unresolved.

### Complementary values

The second external value is converted independently of geometry:

- Add 32,767 using unsigned 32-bit arithmetic.
- Retain only the lowest 24 bits.
- Shift that retained quantity right by 16 positions.

Call the result the converted value. It is always between 0 and 255. Its complement is 255 minus the converted value.

This is masked conversion, not saturation. In particular, a value representing 256 whole units at a scale of 65,536 converts to zero.

Only after this call returns is the selector byte read. A zero selector assigns the converted value to the first object and its complement to the second. Any nonzero selector reverses those assignments.

These assignments are two ordered calls to F-460b2abbbbbe:

- The first object is read from `0x20` for the first call.
- The second object is read from `0x24` after the first call returns.

The selector is not retested between those calls. Mutation during the first call can change the second target, but does not select a different assignment branch. The second target also need not equal the target used by the earlier geometry call.

## Acceptance examples

These are conditional static acceptance examples, not executed tests. Unless stated otherwise, assume valid storage, representable arithmetic, returning dependencies, and no dependency mutation of context.

### Cache match

If both external values equal their caches, the result is 1, with no calls and no writes. Both external records are nevertheless read. The second cache is read only after the first comparison matches.

Changing only a stored dimension while leaving both external values matched does not trigger an update.

### Equal dimensions without adjustment

With a first external value of 640 × 65,536, stored dimensions 640 by 480, and at least one cache mismatch:

- Selected and output dimensions are 640 by 480.
- Neither adjustment call occurs.
- Both positions and adjustments are zero.
- Remaining source dimensions are 640 by 480.

Geometry follows both cache writes.

### Centered reduction

With the same first external value and stored dimensions 1280 by 960:

- Selected dimensions are 640 by 480.
- No adjustment calls occur.
- Positions are 320 and 240.
- Remaining source dimensions stay 1280 by 960.

This constrains arguments, not the geometry dependency’s effect.

### Height growth does not independently trigger adjustment

With that first external value and stored dimensions 640 by 120:

- Selected dimensions are 640 by 480.
- The width-growth condition is false.
- Neither adjustment call occurs.
- Output dimensions remain 640 by 480.
- Positions are both zero after clamping.
- Remaining source dimensions remain 640 by 120.

### Conditional adjustment results

With that first external value and stored dimensions 160 by 120:

- Selected dimensions are 640 by 480.
- Horizontal adjustment arguments are 25,600 and 640.
- Vertical adjustment arguments are 14,400 and 480.

**If** the dependency returns 40 and 30 respectively, output dimensions are 320 by 240, remaining source dimensions are 80 by 60, and both positions clamp to zero. Geometry receives adjustment 30 before adjustment 40.

Those return values are assumptions, not claims about dependency behavior.

### Complement direction and wrapping

A second external value of 128 × 65,536 yields converted value 128 and complement 127.

- Zero selector: first object receives 128; second receives 127.
- Nonzero selector: first receives 127; second receives 128.

A second external value of 256 × 65,536 yields converted value zero and complement 255, not a saturated converted value of 255.

### Mutation-sensitive targets

If geometry changes the selector before returning, the subsequent selector read observes the changed byte. If the first complementary-value call changes `0x24`, the second call uses that changed target. It does not reuse the earlier geometry target.
