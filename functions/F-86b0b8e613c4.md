# F-86b0b8e613c4

## Purpose

F-86b0b8e613c4 examines the beginning of a byte sequence, directly assigns a 32-bit token code, and returns a 32-bit unsigned extent.

Its apparent purpose is lexical classification. Punctuation, comments, quoted regions, numeric-looking sequences, prefixed forms, and ordinary words are useful descriptive categories, not independently established token names. The numeric codes and consumption rules below define the observable contract.

The function processes one initial token. It does not skip whitespace to find another token, decode quoted contents, convert numbers, or return an advanced input pointer. Some paths call dependencies after assigning a provisional code; without an output-preservation assumption, that assignment does not necessarily determine the final output object.

## Interface

### Inputs and outputs

The function receives:

- An address of input bytes, each 8 bits wide.
- An address of writable storage for one 32-bit token code.

It returns an unsigned 32-bit extent. There is no input-length argument and no separate error result.

Code `0x90` is directly assigned for several rejected or incomplete forms. It is not a universal malformed-input indicator: unterminated nonempty block comments receive `0x93`, for example.

An extent normally identifies consumed bytes, including an accepted closing delimiter and excluding the stopping byte. It need not be a positive length under arbitrary classification tables. It also need not exclude a zero terminator: an initial `!` not followed by `=` returns 2 even when its second byte is zero.

### Widths and representation

- Input elements and classification entries are 8 bits.
- Extents and position arithmetic are unsigned 32-bit quantities.
- Token-code stores are 32 bits.
- A signed 32-bit counter counts qualifying bytes in prefixed forms.
- The hash-form decision interprets its unsigned extent as signed 32-bit.
- The classification provider returns an address of an object containing a 32-bit table address.
- Continuation-table references also appear as 32-bit address values.

The evidence does not independently establish output byte order, alignment requirements, or a portable pointer representation.

### Preconditions

The caller must provide readable storage for all examined positions, writable output storage, and accessible table data. No supplied length bounds the scans.

Zero termination alone does not guarantee termination of table-driven scans. Some loops test classification entries without first excluding zero. Matching-quote scanning also examines the byte after a potential closing quote to distinguish closure from doubling.

Normal token semantics require scans to terminate before arithmetic overflows. Input/output overlap is not established as supported: early output stores can affect later input reads if the objects overlap. The behavioral descriptions below assume disjoint objects except where access ordering is discussed.

No ownership transfer, allocation obligation, or release obligation is established by this interface.

## Behavior

### Classification predicates and reference timing

Two tables participate:

- A classification table obtained through F-2a4c402ba617, indexed by an unsigned byte from 0 through 255.
- A continuation table whose address is available through a global reference.

The following predicates are distinct:

- **Exact-class byte:** its classification entry equals `0x20`.
- **Low-bit-class byte:** bit 0 of its classification entry is set.
- **Continuation byte:** its high bit is set, or it lies between `0x20` and `0x7f` inclusive and the corresponding continuation-table entry is nonzero.

For ASCII-range continuation lookups, the index is the input byte minus `0x20`. High-bit bytes qualify without consulting that table. Zero is never a continuation byte, but its classification entry can still equal `0x20` or have bit 0 set.

The continuation-table address used by numeric suffixes and prefixed forms is captured before the initial input-byte dispatch. Ordinary-word checks instead consult the global continuation-table reference during scanning.

Classification scans commonly retain the provider’s returned reference object and read the table address through it for successive checks. Exponent processing captures a table address for that phase.

### Whitespace-like runs

Initial bytes `0x09`, `0x0a`, `0x0c`, `0x0d`, and `0x20` select this branch. Initial `0x0b` does not.

The first byte is included without testing its classification entry. After calling F-2a4c402ba617, scanning starts at position 1 and continues while classification bit 0 is set. The stopping position is returned, and `0x91` is stored after scanning.

There is no independent zero check. A zero whose classification has bit 0 set can be consumed.

### Comments

An initial `--` scans from position 2 until zero or line feed. The stopping byte is excluded; code `0x93` is stored.

An initial `/*` selects block-comment scanning only when position 2 is nonzero. Scanning ends at the first `*/`, including that pair, or at zero, excluding zero. Both outcomes assign `0x93`. Nested openings have no special meaning.

Consequently:

- `/*` immediately followed by zero consumes only `/`, with code `0x51`.
- A nonempty unterminated block comment still receives `0x93`.
- Terminated and unterminated comments are not distinguished by this code.

### Quoted and bracketed regions

An initial single quote, double quote, or backtick selects matching-delimiter scanning.

A matching delimiter followed by another matching delimiter is consumed as a doubled pair. Scanning then continues. An undoubled matching delimiter closes the token, is included in the extent, and produces `0x58`.

Zero before closure produces `0x90`, excluding zero. Backslashes have no special treatment. Contents are neither decoded nor copied.

An initial `[` uses a different rule: the first following `]` closes the region, is included, and produces `0x17`. There is no doubled-bracket escape. Zero before closure produces `0x90`, excluding zero.

### Numeric-looking sequences

An initial ASCII digit selects numeric scanning. An initial `.` calls F-2a4c402ba617 and selects numeric scanning only if the following byte has exact class `0x20`; otherwise it assigns `0x70` and returns 1.

Numeric scanning first assigns `0x7c`, then calls F-2a4c402ba617. It consumes exact-class bytes beginning at position 0. Thus the initial digit test is literal ASCII, but subsequent consumption is table-driven.

If the stopping byte is `.`, the function includes it, consumes another exact-class run, and assigns `0x7d`. No byte after the dot is required.

At the resulting position, `e` or `E` introduces an accepted exponent-like extension if its next byte:

- Has exact class `0x20`; or
- Is `+`, without any requirement on the byte after that sign; or
- Is `-` and the byte after that sign has exact class `0x20`.

Acceptance advances two bytes from the exponent marker, consumes an exact-class run from there, and assigns `0x7d`. The unconditional `+` alternative and conditional `-` alternative are distinct behavior.

Finally, continuation bytes are consumed as an invalidating suffix. Every consumed suffix byte causes a direct `0x90` store. The suffix remains part of the returned extent rather than becoming a separate token.

Without compatible tables, a digit-started scan can return extent zero. Because the initial `0x7c` store precedes a dependency call, a path making no later direct store does not independently guarantee a final output value of `0x7c`.

### Question-mark and hash forms

An initial `?` assigns `0x80`, calls F-2a4c402ba617, and consumes exact-class bytes starting at position 1. It returns the stopping position without another direct output assignment.

An initial `#` calls the same dependency and scans the same run. If the signed 32-bit interpretation of the resulting extent is greater than 1, it assigns `0x7f` and returns that extent. Otherwise it enters prefixed-form processing, resetting the extent to 1.

For nonoverflowing short inputs, the hash decision means that at least one exact-class byte after `#` selects `0x7f`. The signed comparison remains relevant outside that range.

### Prefixed forms

Initial `:`, `@`, and `$`, and the hash fallback, assign `0x80` and start scanning at position 1 with a zero qualifying-byte count.

Each continuation byte is included and increments the signed count. A pair of colons is also included when its first colon is not a continuation byte, but the pair does not increment that count. Zero or an otherwise unaccepted byte stops the body.

An opening parenthesis receives special treatment only when it is not a continuation byte and the qualifying-byte count is positive:

- The opening parenthesis is included.
- Each following byte is captured from input.
- A captured zero stops scanning, is excluded, and causes a `0x90` store.
- For each captured nonzero byte, F-2a4c402ba617 is called before classification.
- The captured value—not a reread of that input position—is used for classification and the closing-parenthesis decision.
- A captured `)` closes the form and is included, even if its classification has bit 0 set.
- Any other captured low-bit-class byte stops scanning, is excluded, and causes a `0x90` store.

Parentheses are not nested or balanced. Dependency mutation of the current input position cannot change the already captured byte’s identity, although it can affect later reads and the classification data.

At completion, a zero qualifying-byte count causes a direct `0x90` assignment. A nonzero count causes return without a final code store. Thus colon pairs alone are insufficient, and successful parenthesized completion does not itself restore `0x80` after dependency effects.

### Hexadecimal-looking quoted forms

Initial `x` or `X` followed immediately by a single quote selects this branch before ordinary-word handling.

The function assigns `0x7e` and examines payload positions beginning at offset 2. At each position it captures the byte before any dependency call:

- A captured zero ends scanning, is excluded, and forces a direct `0x90` store.
- A captured single quote ends scanning and is included.
- Any other captured byte causes a call to F-2a4c402ba617 and is then classified using that captured value.

The classification expression refers to the selected entry twice. With stable classification data, the byte passes exactly when entry bits 7 and 5 differ. A failing payload byte causes a direct `0x90` store, but scanning continues.

A closing quote after an odd payload length causes a direct `0x90` store. An even payload length does not cause a final restoring store. Empty payloads therefore receive the initial `0x7e`.

This function never directly restores `0x7e` after invalidation. A later dependency call can nevertheless alter the output object; permanent invalidation is guaranteed only under an appropriate dependency-preservation assumption. The captured payload byte is not reread after the call.

### Ordinary words and unrecognized bytes

If no earlier branch applies, a non-continuation initial byte causes code `0x90` and extent 1. This includes initial zero.

A continuation initial byte begins a maximal continuation run. The function calls F-ab03ddc82f92 with the original input address and the unsigned 32-bit extent. After that call, it stores the dependency’s returned 32-bit value and returns the previously determined extent.

No terminator is appended. The stopping byte is excluded from the supplied extent. Dependency mutation does not trigger a rescan.

## Side effects

Direct output stores occur at different phases:

- Numeric scanning stores a provisional code before its provider call, then may overwrite it after fractional, exponent, or suffix processing.
- Question-mark, prefixed, and hexadecimal-looking forms store their provisional codes before completing their scans.
- Whitespace, comments, bracketed regions, and matching-quoted regions store their result after scanning.
- Ordinary words store the classifier’s return value after its call.
- Equality stores its code before second-byte lookahead.

A dependency can run after an output assignment and may change that object indirectly. Only subsequent direct stores establish the value again. No assumption of output, input, or global preservation is implicit.

The continuation-table reference is read before initial input dispatch. No direct input mutation, allocation, deallocation, or explicit global write is visible. Equivalent restrictions on dependencies are unknown.

Invalid memory, inaccessible tables, concurrent mutation, and overflow are not converted into defined token errors.
