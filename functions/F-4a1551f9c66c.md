# F-4a1551f9c66c

## Purpose

The supplied static representation describes a procedure that interleaves indirect calls with byte, halfword, and word accesses to computed addresses and shared storage. Its visible effects include clearing bytes, storing scaled dependency results, copying low bytes from words, updating a shared word twice, and finally attempting a call to address zero.

No application-level purpose is established. In particular, the representation does not establish that this procedure allocates objects, initializes a valid data structure, installs a handler, or performs a successful supervisor operation. Such interpretations would require evidence about its execution environment and dependencies.

This contract distinguishes:

- **Established static evidence:** operations and ordering explicitly represented in the supplied material.
- **Conditional interpretation:** behavior that follows if the represented widths, calling convention, and address arithmetic accurately describe the executable.
- **documented_only:** unresolved behavior that cannot safely be supplied as an implementation requirement.

No runtime tests have been performed.

## Behavior

### Width and address conventions

The representation distinguishes 8-bit, 16-bit, 32-bit, and paired 64-bit values.

Unsigned right shifts are logical. Consequently:

- A 32-bit value shifted right by 22 is in the range 0–1023.
- A 32-bit value shifted right by 23 is in the range 0–511.
- Applying a further right shift of 23 to that latter result produces zero.
- Masking with `0x1fffffff`, then shifting right by 19, produces a value in the range 0–1023.
- Masking with `0x3fffffff`, then shifting right by 21, produces a value in the range 0–511.
- Masking with `0x3fffffff`, then shifting right by 7, produces a value in the range 0–8,388,607.

Byte stores retain the low eight bits of their source value.

Multiplications by 4, 16, and 8192 and left shifts by 2, 11, 12, 16, and 18 appear in address or argument formation. Some operands are represented as signed 32-bit values. The supplied material does not establish portable signed-overflow behavior. A 32-bit wrapping interpretation may be appropriate for a particular target, but is not established independently here.

A paired 64-bit result is explicitly split into low and high 32-bit portions. This does not establish a single semantic 64-bit return value; it may reflect two machine-register outputs.

### Entry and initial clearing

The first dependency target is derived from the incoming link-related value plus `0xffc`. It receives the first explicit input.

Following another call, its 32-bit result and two copies of the fourth input shifted right by 22 are supplied to a subsequent call. Several additional calls occur before the first explicit memory effect.

The procedure then:

- Reads one byte at the first input plus 1.
- Uses that byte as an unsigned numerical address component.
- Writes zero to the address equal to that byte plus `0x11`.

Thus the destination is in the range `0x11`–`0x110`. It is not represented as a write to the first input plus `0x11`.

A preceding dependency result is shifted left by 2 and passed onward after this byte store. A later result is likewise shifted left by 2 and retained across further calls. The procedure then writes a zero byte at the retained scaled result multiplied by 8192, plus 9.

The intervening calls are observable boundaries. They must not be assumed pure or reordered around these accesses.

### Establishing a retained base and linked word values

A later 32-bit dependency result is retained as a base value. Another retained word is passed both unchanged and shifted right by 22 to the call that follows.

After further calls, including one producing a paired result:

- The low byte of the retained base value is written at that base plus 9.
- A word is read from the retained base plus `0x34`.
- A subsequent call receives the low portion of the paired result shifted left by 2, its high portion, and the word just read.

A later secondary-register output participates in two distinct address calculations:

1. The retained base is stored as a word at four times that output plus `0x14`.
2. A word is then read at that output plus `0x14`, without the multiplication by four.

The read must not be replaced by the value just stored. Their addresses are generally different, and their relationship depends on the secondary-register value.

After another group of calls, the retained base is stored at four times a newly returned value plus `0x14`. The procedure next reads a word at the earlier loaded word shifted right by 22, plus `0x14`.

The newly read word is used in two ways:

- Its unsigned half, obtained by a logical right shift of one, selects a word destination at four times that half plus `0x14`. The value stored there is another dependency result shifted left by 2.
- Its unshifted value selects a word read at that value plus `0x14`.

Following more calls, the same shifted dependency result is stored at another four-times-result-plus-`0x14` destination.

### Shared-state extraction and zero-derived addressing

The first read of shared 32-bit storage occurs after those stores. Its value is shifted right by 23 and retained. Separately, the most recently loaded address-selected word is shifted right by 22.

The latter value is stored at four times a secondary-register output plus `0x14`. A call then receives that secondary output twice, the shifted shared value, and the shifted loaded word.

After further calls:

- The shifted loaded word is stored again at a new four-times-result-plus-`0x14` destination.
- Zero is stored as a word at four times a later secondary-register output plus `0x14`.
- The shared value, already shifted right by 23, is shifted right by 23 again and stored at another such destination.

Under the represented unsigned 32-bit widths, this last stored value is necessarily zero.

A word is then read at `0x14` plus the value obtained by masking the later secondary output with `0x1fffffff` and shifting it right by 19. The address range is therefore `0x14`–`0x413`; word alignment is not guaranteed.

That word is shifted right by 22. Its low byte is written through a byte-selected destination:

- The selector address is one plus the twice-shifted shared value.
- The selector byte is read there.
- The destination is that byte plus `0x11`.

Because the twice-shifted shared value is zero, the represented selector read is at address 1.

A following call receives three copies of another secondary-register value and an explicit zero. A later call receives zero obtained from a right shift of an explicitly zero value.

### Further clears and first shared-word update

A byte is read at four times the most recent 22-bit-shifted word value, plus 1. Zero is written at the selected byte plus `0x11`.

After further calls, a byte from address 1 selects another zero-byte destination at selector plus `0x11`.

A secondary-register result is retained across the subsequent sequence. Another read of the byte at address 1 occurs later; its value is retained separately and used to clear one byte at that value plus `0x11`.

These address-1 reads are distinct. Dependencies between them may change memory.

A later dependency result is written to the shared destination word. The write occurs before the next call receiving that result. After that call and another call, the procedure reads a word at the retained address-1 byte value plus `0x74` and writes its low byte at that retained byte value plus 1.

The retained byte is not implicitly refreshed before this operation.

### Word-to-byte copies and scaled links

The retained secondary-register result is shifted left by 11 and passed to a dependency. A later paired result is passed onward as two words together with the first shared-word update value shifted right by 23.

A subsequent dependency result is multiplied by four to form a base. A word at that base plus `0x74` is read, and its low byte is stored at the base plus 1.

After intervening calls, that word-to-byte copy is performed again at the same retained base. It is a fresh word read, not a required reuse of the earlier word.

A call then receives:

- The retained secondary-register result shifted left by 12.
- Two copies of a new dependency result shifted left by 2.
- That same unscaled dependency result shifted left by 18.

The left-by-2 result is retained for later argument and destination calculations.

Following more calls, a new four-times-result base is formed. A word is read at that base plus `0x74`, retained, and copied in low-byte form to the base plus 1.

The retained full word is subsequently stored twice:

- At sixteen times a dependency result plus `0x14`.
- At four times a later dependency result plus `0x14`.

Between these stores, calls receive an argument formed by logically shifting the retained scaled result right by 2 and then shifting left by 16. This operation does not generally recover bits lost in the earlier left shift.

A later dependency result shifted left by 2 is stored at `0x14` plus the retained scaled result masked with `0xfffffffc`. The mask must be retained in the contract even though the represented scaled value has its low two bits clear.

Further calls lead to:

- A zero-word store at four times a returned value plus `0x14`.
- A paired-result operation storing its low word shifted left by 2 at four times its high word plus `0x14`.
- A second read of the shared source word.
- Another store of the same shifted low word at a newly returned four-times-result-plus-`0x14` destination.
- A word read at the newly sampled shared source value plus `0x14`.

The second shared-source read must not be replaced by the first snapshot.

### Final byte-selected writes and termination

A further paired result supplies another low/high pair. Before the next call:

- A selector byte is read at one plus the retained copied word shifted right by 23.
- The low byte of the word loaded through the second shared-source snapshot is written at selector plus `0x11`.

The following call receives three copies of the new high word and the new low word shifted left by 2.

After further calls, another selector byte is read at one plus the new low word masked with `0x3fffffff` and shifted right by 21. At selector plus `0x11`, the procedure stores the low byte of the loaded word shifted right by 22.

More calls follow, including one whose target uses a displacement of `0xb0` rather than the common larger displacements. A final dependency produces an 8-bit result.

The last explicit effects are ordered as follows:

1. Write zero through a final secondary-register pointer.
2. Replace the shared destination word with the final 8-bit result as its low eight bits and a represented 24-bit memory-associated value as its upper 24 bits.
3. Store a zero halfword at the new low word masked with `0x3fffffff` and shifted right by 7.
4. Attempt a call to address zero with three explicit zero arguments.

The exact byte-to-word interpretation of the 24-bit component requires target layout evidence. The halfword destination is not guaranteed even-aligned.

## Side effects

The explicit memory effects comprise:

- Byte-selector reads, often followed by byte writes to addresses in `0x11`–`0x110`.
- Word reads and writes using unrelated scaled and unscaled addresses.
- Repeated reads of potentially mutable shared storage.
- Two writes to the same represented shared-word destination.
- A final byte clear and halfword clear.

The representation also warns that some shared symbols overlap smaller storage at the same address. Distinct symbolic descriptions therefore do not establish disjoint memory regions.

Aliasing matters. A byte or word write may affect a later read, including a selector or shared-value read. The contract does not permit treating all computed locations as separate objects.

No allocation, ownership transfer, release, reference-count adjustment, locking, or rollback is explicitly established. Dependencies may nevertheless perform such effects. Passing an address or integer to a dependency does not establish who owns the referenced storage.

There is no transactional guarantee. If execution fails partway through, earlier effects may remain visible.

## Acceptance examples

These examples are conditional static acceptance criteria, not executed tests.

- **Early input extraction:** If the fourth input is `0xffffffff`, the early call receives 1023 in each of its two shifted-input positions. A signed shift or shift by 23 would not match.

- **Byte-selected clearing:** If the byte at the first input plus 1 is `0x7a` when read, the first explicit zero-byte destination is `0x8b`, subject to valid address arithmetic and memory mapping.

- **Distinct word addresses:** If the relevant secondary output is 3, storing the retained base occurs at `0x20`, while the following word read occurs at `0x17`. Reading back `0x20` would change behavior.

- **Repeated shift:** For every unsigned 32-bit shared-source value, two consecutive logical right shifts by 23 yield zero. The later selector based on that result is read from address 1.

- **Truncation:** If a word-to-byte copy reads `0x123456ab`, it writes byte `0xab` and retains the full word where subsequent word stores require it.

- **Fresh reads:** If a dependency changes a retained base’s word at offset `0x74` between the two copies from that location, the second copy uses the changed word.

- **Shared-state mutation:** If dependencies change the shared source between its two explicit reads, later address formation uses the second sampled value.

- **Termination failure:** If address zero is not callable, the procedure does not successfully return merely because the preceding stores completed. The environment determines the resulting fault behavior.
