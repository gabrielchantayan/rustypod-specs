### Byte-selector phase

After operation 16, the routine derives a **selector base** from the unsigned four-times-result value written there: clear bit 31, then shift logically right by seven. Its mathematical range is 0–16,777,215.

Several later stores use the following two-access pattern:

1. Read one unsigned byte at selector base plus one.
2. Zero-extend that byte, add 17, and write one byte at the resulting address.

The read byte is an address component, not a pointer-sized load. Under the represented arithmetic, the write destination is between 17 and 272 inclusive.

Each occurrence performs its own selector-byte read. Intervening calls or earlier writes may change the selected destination. There is no established guarantee that all these stores target the same address.

In order, the byte phase performs:

1. A selector-based write of the low eight bits of a fresh unsigned result shifted left by two.
2. After intervening calls, a selector-based write of the low eight bits of that same result after masking to 30 bits and shifting right by 20.
3. A direct byte write at the packed input’s upper byte shifted right by seven, plus 28. Its value is the low eight bits of another fresh unsigned result shifted left by two.
4. A selector-based zero write.
5. After more calls, another selector-based zero write.
6. A zero write through a different byte selector, described below.

The second write retains bits 20–27 of its captured result. Masked bits 28–29 are discarded when the value is narrowed to one byte.

The direct destination in step 3 is either address 28 or address 29, because the upper byte shifted right by seven is either zero or one.

The final selector address uses the left-shifted result from step 3, multiplied by 1,024, plus one. A byte is read there; a zero byte is then written at that byte’s zero-extended value plus 17.

That selector address is reused by the terminal loop. The selector byte itself is reread for each loop write.

A dependency receives twice that quantity. A following dependency result supplies the first argument for the first loop iteration.

Every represented iteration then:

- Performs further dependency calls.
- Reads the byte at the late selector address and writes zero at the selected low address.
