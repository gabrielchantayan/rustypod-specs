# F-2be8d706175c

## Purpose

F-2be8d706175c performs ordered, state-sensitive dispatch using a receiver and an event record. It conditionally issues a notification, conditionally invokes an initial handler, invokes one selected main handler, and conditionally invokes a final handler.

The result is the first nonzero indirect-handler result, unchanged, or zero if no invoked handler produces a nonzero result. The notification’s result is ignored.

“Receiver,” “event,” “notification,” and “handler” identify structural roles. Event-processing intent is inferred; application meanings are not established. In particular, zero and nonzero results must not be interpreted as success and failure without additional evidence.

An important established property is **reclassification after calls**. Later decisions reread relevant state rather than relying on an entry-time classification. A dependency can therefore affect later eligibility, target selection, and memory validity.

## Interface

### Inputs and representation

The operation receives two explicit inputs:

- **Receiver address:** identifies storage containing a dispatch-table address and conditionally accessed fields.
- **Event address:** identifies storage containing a tag and a context-dependent field.

The supplied representation uses 32-bit integer fields and 32-bit address quantities. All offsets below are byte offsets. This represented layout does not independently establish a native calling convention, byte order, alignment requirement, or portable pointer representation.

Every indirect handler receives the original receiver and event addresses. No record copy is visible. The notification receives the receiver address and a converted receiver-field value; it does not explicitly receive the event address.

### Accessed fields

| Base | Offset | Represented width | Role |
|---|---:|---:|---|
| Receiver | 0x00 | 32 bits | Dispatch-table address |
| Receiver | 0x50 | 32 bits | Comparison value for final dispatch |
| Receiver | 0x124 | 32 bits | Integer source for the notification’s character conversion |
| Event | 0x04 | 32 bits | Tag |
| Event | 0x08 | 32 bits | Payload address for tag 0x16; comparison value for tag 0x0F |
| Payload | 0x04 | 32 bits | Nested discriminator |

The payload address is obtained from event offset 0x08 only during a tag-0x16 classification. During the final tag-0x0F comparison, that same field is treated as a value and is not dereferenced.

No read of event offset 0x00 is established. No payload-field access other than the discriminator read is established.

### Dispatch-table slots

| Offset from current table address | Role |
|---:|---|
| 0x124 | Optional handler for a currently observed zero discriminator |
| 0x10C | Main handler for a currently observed discriminator of 0x2A |
| 0x110 | Default main handler |
| 0x0E0 | Final handler for a currently observed tag of 0x0F with matching comparison fields |

These offsets identify target-storage locations, not function identities. Multiple slots may contain the same target.

Receiver offset 0x124 and table offset 0x124 are distinct locations relative to different bases.

### Result

The result is a represented 32-bit integer. Any nonzero indirect-handler result terminates dispatch and is returned without Boolean normalization. Negative values are terminal in the same way as positive values.

If no indirect handler returns nonzero, the result is zero. A final-handler result of zero therefore produces the same function result as skipping that handler.

### Preconditions and errors

Normal completion requires:

- Every actually accessed field and target slot to be readable.
- Address calculations needed by the executed path to identify valid storage under the applicable execution model.
- Every invoked target to be callable with the supplied arguments.
- Each dependency whose return is needed for continuation to return normally.
- Any required character conversion to complete without preventing continuation.

These requirements are path-dependent. An unused payload, receiver field, or table slot need not be valid merely because another path would access it.

No explicit null check, bounds check, diagnostic return, or recovery mechanism is established. Invalid accesses, invalid targets, abnormal dependency exits, and conversion signals have no established recoverable outcome.

## Behavior

### Ordered opportunities

The operation exposes the following opportunities in order:

| Opportunity | Eligibility when reached | Effect of normal completion |
|---|---|---|
| Notification through F-87ff73d6c0d0 | Tag 0x16 and the initial arithmetic condition | Result ignored; continue |
| Optional handler at slot 0x124 | Fresh tag 0x16 and discriminator zero | Nonzero returns immediately; zero continues |
| Main handler | Always selected if this stage is reached | Nonzero returns immediately; zero continues |
| Final handler at slot 0x0E0 | Fresh tag 0x0F and equal comparison fields | Its result determines the function result |

Exactly one main handler is invoked on a normally progressing execution that reaches main dispatch. The special main slot replaces the default slot; it does not precede or follow it as an additional main call.

The maximum visible call count is one notification plus three indirect-handler calls. Reaching that maximum requires changes to relevant state between opportunities. Unchanged state cannot simultaneously satisfy all notification, optional-handler, special-main, and final-handler conditions.

### Initial notification classification

The operation first reads the event tag at offset 0x04.

If the tag is not 0x16, this classification does not read the payload address or discriminator and cannot issue the notification.

For tag 0x16, it reads the payload address from event offset 0x08 and then the discriminator at payload offset 0x04. The represented arithmetic subtracts 0x2500 from that signed 32-bit discriminator and compares the result with 2.

For inputs on which the subtraction is defined without signed overflow, the notification condition selects exactly discriminator 0x2502. Behavior for inputs that overflow this subtraction remains documented_only; a wrapping interpretation is not established.

### Notification argument conversion

When the notification condition matches, the operation reads the receiver’s 32-bit integer field at offset 0x124 and converts it to the plain character type before supplying it to F-87ff73d6c0d0.

The conversion contract depends on the target character representation:

- If the source value is representable in the destination character type, the conversion preserves its numeric value.
- If plain character is unsigned, conversion follows the unsigned destination’s modulo range.
- If plain character is signed and the source value is unrepresentable, the supplied conversion rules permit an implementation-defined result or an implementation-defined signal.

**An eight-bit character width alone does not establish low-eight-bit retention.** Width does not settle plain-character signedness or the implementation-defined treatment of an unrepresentable value.

Low-bit retention may be used as a conditional model only when a suitable modulo-narrowing implementation is explicitly assumed. Under that assumption, an eight-bit destination retains the low eight bits; any signed interpretation of the retained pattern and subsequent argument extension must still follow the applicable implementation.

If conversion raises a signal that prevents continuation, neither notification invocation nor later dispatch is guaranteed. If conversion completes and F-87ff73d6c0d0 returns normally, its result is ignored regardless of value.

### Optional handler

After the notification opportunity, the operation reads the event tag again. A notification may have changed the tag or reachable state.

Only a freshly observed tag of 0x16 causes another payload-address read and another discriminator read. If that discriminator is zero, the operation obtains the current receiver table address, reads its slot at offset 0x124, and invokes the selected target.

A nonzero result is immediately returned. A zero result continues to main dispatch.

A skipped optional handler also leads to main dispatch. Its eligibility is not remembered from the initial notification classification.

### Main dispatch

Main selection starts with another fresh event-tag read.

For a current tag of 0x16, the operation rereads the payload address and discriminator. Discriminator 0x2A selects table slot 0x10C. Every other classification selects table slot 0x110.

The default slot therefore covers:

- Any current tag other than 0x16.
- Tag 0x16 with discriminator zero.
- Tag 0x16 with discriminator 0x2502.
- Every other tag-0x16 discriminator except 0x2A.

The selected target is obtained through the receiver’s current dispatch-table address. There is no table snapshot spanning calls.

A nonzero main result is returned immediately. A zero result allows the final classification.

### Final dispatch

The final classification rereads the event tag. Only tag 0x0F permits further final-stage field reads.

For that tag, the operation reads the event field at offset 0x08 and then the receiver field at offset 0x50. It compares their represented 32-bit values for equality. This comparison does not dereference the event field.

If the values differ, the result is zero. If they match, the operation obtains the receiver’s current table address, reads slot 0x0E0, and invokes that target. Its nonzero result is returned unchanged; its zero result leads to zero.

The event need not have had tag 0x0F on entry. An earlier dependency can create or remove final eligibility.

### Observable read and call ordering

The static representation establishes these access-order constraints:

- Each classification begins with its own event-tag read.
- A tag-0x16 classification obtains the payload address before reading the discriminator through it.
- The notification-source field is read only after the initial discriminator condition matches.
- Character conversion precedes notification invocation.
- Each indirect target is obtained after the classification selecting it, through a receiver-table read followed by a selected-slot read.
- The final comparison reads the event comparison field before the receiver comparison field.
- A final tag other than 0x0F avoids both comparison-field reads.
- A nonzero indirect-handler result prevents every later classification and call.

These are static control-flow and access-order properties. They do not establish atomicity, synchronization, or a coherent snapshot under concurrent mutation.

## Side effects

No direct store to the receiver, event, payload, dispatch table, or globals is visible. No direct allocation, release, or record copy is visible.

This does not make the operation read-only. Invoked dependencies may modify state reachable through the inputs, change globals, replace dispatch tables, retain addresses, allocate storage, release storage, or fail to return. Their internal effects are not supplied.

In particular, later classifications may observe changes to:

- The event tag or payload address.
- The nested discriminator.
- Receiver comparison or notification fields.
- The receiver’s dispatch-table address.
- Individual table entries.

Passing an address does not establish an ownership transfer, borrowing discipline, lifetime guarantee, or prohibition on retention. No dependency is established to preserve globals or preserve either input.

Safe continuation requires the original input addresses and all subsequently accessed storage to remain valid. Returning zero from an optional or main handler exposes later reads. Returning nonzero prevents those later reads, but that fact alone does not grant a memory-release permission.

An implementation-defined character-conversion signal is another possible effect when signed plain-character conversion receives an unrepresentable value. No signal handling, cleanup, exception handling, or recovery behavior is visible.

## Acceptance examples

These are conditional obligations derived from static evidence, not runtime observations. Unless otherwise stated, assume valid accesses, callable targets, normal dependency returns, defined arithmetic, and unchanged relevant state.

### Unmatched tag with no usable payload

For a tag other than 0x16 or 0x0F, event offset 0x08 need not designate readable payload storage for this operation’s own accesses.

The notification and optional handler are skipped. Slot 0x110 supplies the main handler. Its nonzero result is returned unchanged; its zero result leads to zero.

This does not constrain accesses performed inside that handler.

### Zero discriminator and early termination

For tag 0x16 with discriminator zero, slot 0x124 runs before main dispatch.

If it returns −7, the function returns −7 without main or final dispatch. If it returns zero without changing relevant state, slot 0x110 runs next.

### Special main selection

For tag 0x16 with discriminator 0x2A, the notification and optional handler are skipped. Slot 0x10C runs instead of slot 0x110.

If it returns zero and leaves the tag unchanged, final dispatch is ineligible and the result is zero.

### Representable notification character

For tag 0x16 with discriminator 0x2502, suppose the receiver notification field contains 0x2A.

That numeric value is representable in the plain character type under the supplied integer-conversion model, so the converted value is 0x2A. If the notification returns normally, its result is ignored. With unchanged state, main dispatch uses slot 0x110.

### Out-of-range notification character

For the same discriminator, suppose the receiver field contains 0x0000012A and characters are eight bits wide.

Width alone does **not** establish a notification argument of 0x2A.

Under an explicitly assumed modulo-narrowing implementation, conversion yields the retained pattern 0x2A and the numeric value 42. Under an eight-bit signed plain-character implementation without that additional assumption, the conversion’s result or signal behavior remains documented_only.

If a conversion signal prevents continuation, no notification or subsequent dispatch sequence is required by this contract.

### Mutation across all opportunities

Suppose the initial discriminator is 0x2502 and the notification conversion completes. The notification changes the discriminator to zero and returns normally.

The optional handler is then eligible. Suppose it changes the discriminator to 0x2A and returns zero. Main dispatch selects slot 0x10C.

Suppose that main handler changes the event tag to 0x0F, makes the comparison fields equal, and returns zero. The final handler at slot 0x0E0 is then invoked.

### Replacement table

Suppose the optional handler returns zero after replacing the receiver’s dispatch-table address. Main dispatch obtains its target from the replacement table, not from a table retained before the optional call.

### Final equality and mismatch

With unchanged tag 0x0F, the default main handler runs first. A nonzero result prevents final classification.

After a zero main result, equal comparison fields permit the final call; unequal fields produce zero without it. The event comparison field need not designate readable memory.

### Invalid payload discriminator location

For tag 0x16 with an unreadable discriminator location, normal completion is not established. There is no specified fallback to the default main handler when the required nested read cannot complete.
