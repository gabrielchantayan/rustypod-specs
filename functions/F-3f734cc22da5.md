# F-3f734cc22da5

## Purpose

F-3f734cc22da5 is an ordered dispatcher over an object and a message-like record. It may perform a preliminary notification, invoke a special handler, select one of two primary handlers, and invoke a final handler. Handler results control early return.

The established behavior is the dispatch sequence and its conditions. Descriptions such as “object,” “message,” “notification,” and “handler” describe structural roles, not an established application protocol.

A central requirement is that dispatch decisions use values reread at their respective stages. Earlier callees may change the object, the message, or indirectly referenced storage. The function does not establish a snapshot of the initial inputs.

## Interface

### Inputs and result

The function receives two arguments:

- **Object reference:** an address used to access a dispatch-table pointer and selected object fields.
- **Message reference:** an address used to access a discriminator and a payload field.

It returns an integer. A nonzero result from any result-bearing handler is returned immediately and unchanged. If no such handler returns a nonzero result, the function returns zero.

The supplied representation uses 32-bit integers and represents addresses in 32-bit fields. The layout and access descriptions below use that model. Exact platform types, calling convention, and pointer-representation guarantees are not independently established.

### Object layout accessed

Offsets are byte offsets from the object reference.

| Offset | Accessed representation | Role |
|---|---|---|
| `0x00` | Address-sized field, represented as 32 bits | Address of the current dispatch table |
| `0x50` | 32-bit integer | Comparison value used by the final dispatch condition |
| `0x10C` | 32-bit integer, narrowed to a character argument | Argument source for the preliminary dependency |

The object field at `0x10C` is distinct from the dispatch-table entry at `0x10C`: their base addresses differ.

### Message layout accessed

Offsets are byte offsets from the message reference.

| Offset | Accessed representation | Role |
|---|---|---|
| `0x04` | 32-bit integer | Message discriminator |
| `0x08` | 32-bit field | Either a nested-record address or a directly compared value, depending on the discriminator |

When the discriminator is `0x16`, the field at message offset `0x08` is interpreted as a nested-record address. A 32-bit value at nested-record offset `0x04` determines several dispatch conditions.

When the discriminator is `0x0F`, the field at message offset `0x08` is compared directly with the object field at `0x50`. That final comparison does not dereference the message payload as a nested record.

No access to message offset `0x00` is established.

### Dispatch-table layout accessed

The object’s field at offset `0x00` supplies the dispatch-table address. The following byte offsets within that table contain callable targets:

These opaque IDs distinguish call sites. They do not establish distinct underlying function identities: two or more entries could contain the same target.

## Behavior

### 1. Preliminary notification

The function first reads the message discriminator at offset `0x04`.

If that discriminator is not `0x16`, this stage performs no nested-record read and makes no call.

If it is `0x16`, the function:

1. Reads the nested-record address from message offset `0x08`.
2. Reads the 32-bit value at nested-record offset `0x04`.
3. Subtracts `0x2500` from that value.
4. Tests whether the result equals `2`.

If the test succeeds, the function reads the 32-bit object field at `0x10C`, converts it to a character-width argument, and calls F-4fd087f2325e with:

- the original object reference;
- the converted character value.

For the non-overflowing input `0x2502`, the subtraction produces `2`, so this notification occurs.

No result from F-4fd087f2325e is used to determine this function’s return value. After that call returns, processing continues with a fresh message-discriminator read.

The exact signedness and argument representation of the character conversion are not established. The source explicitly narrows the object field rather than passing its full 32-bit value unchanged.

### 2. Special zero-subtype handler

The function rereads the message discriminator at offset `0x04`, including after any preliminary dependency call.

If the discriminator is `0x16`, it rereads the nested-record address at message offset `0x08` and then the nested 32-bit value at offset `0x04`.

If that nested value is zero, the function:

1. Reads the object’s current dispatch-table address.
2. Reads the callable target at table offset `0x124`.
3. Calls F-U01 with the original object and message references.

A nonzero result from F-U01 is returned immediately. A zero result allows processing to continue.

If the discriminator is not `0x16`, or its nested value is not zero, this handler is skipped.

The condition uses the state observed at this stage. A preliminary call can therefore make F-U01 eligible or ineligible by changing the message or its reachable record.

### 3. Primary handler selection

Unless an earlier handler has returned nonzero, the function rereads the message discriminator.

For discriminator `0x16`, it reads the current nested-record address and the nested value at offset `0x04`.

It then selects exactly one primary handler:

- F-U02, from dispatch-table offset `0x10C`, if the current discriminator is `0x16` and the current nested value is `0x2A`;
- F-U03, from dispatch-table offset `0x110`, otherwise.

The function obtains the current dispatch-table address from the object and calls the selected target with the original object and message references.

A nonzero result is returned immediately. A zero result advances execution to the final stage.

This primary call is not limited to discriminator `0x16`. Messages with any other discriminator take the F-U03 route.

If F-U01 ran and returned zero, the primary selection observes subsequent reads, not the values that originally selected F-U01. The function does not require F-U01 to preserve either input’s contents.

### 4. Final matching handler

After the primary handler returns zero, the function rereads the message discriminator.

If the discriminator is not `0x0F`, no final handler is called, and the function returns zero.

For discriminator `0x0F`, the function reads:

1. the 32-bit message field at offset `0x08`;
2. the 32-bit object field at offset `0x50`.

If those values differ, it returns zero.

If they are equal, it reads the object’s current dispatch-table address, obtains the target at table offset `0x0E0`, and calls F-U04 with the original object and message references.

A nonzero result from F-U04 is returned unchanged. A zero result leads to a zero return.

The equality comparison is between the stored 32-bit values. No range check, normalization, string comparison, or dereference of the message field is established.

### Overall result and ordering

For an execution in which all invoked dependencies return normally:

- The preliminary dependency may run at most once.
- F-U01 may run at most once.
- Exactly one of F-U02 and F-U03 runs if execution reaches primary dispatch.
- F-U04 may run at most once, and only after the selected primary handler returns zero.
- The first nonzero result from F-U01, the selected primary handler, or F-U04 determines the function’s result.
- Zero is returned only if no invoked result-bearing handler returns nonzero.

Negative handler results are nonzero and therefore trigger the same immediate propagation as positive results.
