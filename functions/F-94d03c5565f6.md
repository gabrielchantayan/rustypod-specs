# F-94d03c5565f6

## Purpose

F-94d03c5565f6 performs a fixed sequence of dependency calls, modifies a caller-designated object, chooses between two numeric selectors using an indirect callback, invokes a final dependency, and clears one byte in a second object.

The apparent intent is to coordinate an object reset or state transition. That interpretation is **inferred**, not established: the supplied material does not identify the objects, name their fields, or define the operations performed by the dependencies.

The established behavioral contract is the ordering of calls, the values forwarded between them, the two explicit memory writes, and the zero-versus-nonzero selector rule. A successful invocation has no explicit return value.

## Side effects

### Direct writes

The function itself explicitly performs only these two stores:

1. Four bytes of `0xFF` at first-input offset `0x8C`, after F-2320532e2ef5 returns.
2. One zero byte at retained-target offset `0xD7`, after F-1c60e26b3436 returns.

The second write must not be interpreted as clearing a full word. Conversely, the first write must not be reduced to a byte store.

Intervening dependencies may overwrite the first location or modify neighboring memory. Consequently, the first location’s value at function return cannot be guaranteed solely from its earlier direct store.

### Aliasing and ordering

No non-aliasing relationship is established among the first input, accessor results, dispatch-related objects, and final target. If accessible locations overlap, the observed call and store order still applies; the contract does not assume independent objects.

The final byte store occurs after the final dependency call. An observer inside that dependency cannot rely on this function having already performed the byte clear.

## Acceptance examples

The following are conditional acceptance criteria, not observed test results. They assume valid memory and normal returns unless stated otherwise.

### Zero callback result

If the indirect callback returns exactly zero, F-1c60e26b3436 must receive selector `7`. The third and fourth original inputs must occupy the third and fourth explicit operand positions. The target byte at offset `0xD7` is cleared only after that dependency returns.

### Nonzero callback result

If the indirect callback returns `1`, the selector must be `8`. The same selector is required for a callback result whose 32-bit pattern is `0xFFFFFFFF`; the decision distinguishes zero from nonzero, not positive from negative.

### Different accessor results

If the first F-d189d16d5a68 invocation returns address A and the second returns address B, the field supplied to F-fc5dbbc1ee79 comes from A plus `0x28`. F-5812b0720631 receives B and zero. Reusing A for the second operation would not satisfy the visible behavior.

### Marker-write timing

If F-2320532e2ef5 changes the word at first-input offset `0x8C`, the function’s subsequent direct store replaces that word with `0xFFFFFFFF`. The visible body does not perform this marker write before either of the two dependencies receiving the first input.

### Final byte-store width

If the final target remains valid and no concurrent actor interferes, the direct final store sets offset `0xD7` to zero without itself modifying adjacent bytes. Dependencies may independently have modified those bytes; this criterion applies to the width of the direct store.

### Retained target

If a global target reference changes after F-6ac70711bbb5 returns, the visible final call and final byte store still use the retained result of that earlier call. There is no second retrieval to select a replacement target.

### Final dependency does not return

If F-1c60e26b3436 does not return normally, the subsequent byte clear is not guaranteed. An implementation that clears the byte before invoking that dependency changes observable ordering.
