# F-a5bc00364bd0

## Purpose

F-a5bc00364bd0 updates the requested extent of a tagged storage descriptor. It conditionally replaces the descriptor’s backing storage, transfers a bounded portion of the previous contents, and releases the previous storage through a dependency.

The established behavior is a descriptor update with a selective replacement policy. Interpreting the descriptor as a resizable buffer, its third word as capacity, and its fourth word as logical length is inferred intent, not a separately established type contract.

The function returns a 32-bit status value. It reports an invalid descriptor or a failed replacement allocation through distinct nonzero values. It does not itself validate the backing storage, verify a length-versus-capacity invariant, initialize newly exposed storage, or handle errors from the transfer and release dependencies.

## Interface

### Inputs

The function accepts two inputs:

- **Descriptor:** a pointer to a writable record containing at least four consecutive 32-bit words.
- **Requested extent:** an unsigned 32-bit integer, denoted below by **R**.

The source model uses 32-bit integer words and stores the backing address in an integer-valued field. This contract describes that represented interface; it does not establish portability to an ABI with wider pointers.

The descriptor layout is:

| Byte offset | Width | Contract role |
|---|---:|---|
| 0 | 32 bits | Backing-storage address |
| 4 | 32 bits | Validation tag |
| 8 | 32 bits | Stored allocation extent, denoted **C** |
| 12 | 32 bits | Stored logical extent, denoted **L** |

The role names describe how the fields participate in this function. Their units and interpretation by other functions are not established.

A separate global 32-bit value supplies the expected validation tag. Its numeric value and initialization are not provided.

### Return values

| 32-bit result | Signed interpretation | Meaning established here |
|---|---:|---|
| `0x00000000` | 0 | Accepted operation completed |
| `0xffffffce` | −50 | Descriptor is null or its validation tag does not match |
| `0xffffff94` | −108 | Replacement was selected, but the allocation dependency returned zero |

The signed interpretations identify the bit patterns; no broader error-code namespace is established.

### Preconditions and validity boundaries

A null descriptor is an explicitly handled input. A nonnull descriptor must be readable far enough to inspect its validation tag. To complete an accepted operation, the relevant descriptor fields must also be readable and writable.

Tag equality is the only descriptor-validity check. In particular, the function does not check:

- Whether the backing address is nonzero or valid.
- Whether the logical extent is within the allocation extent.
- Whether the descriptor aliases its backing storage.
- Whether the requested extent fits an allocator-specific limit.
- Whether a transfer of the selected extent is safe.
- Whether releasing the backing address is permitted.

Memory safety therefore depends on descriptor consistency and dependency contracts beyond the validation performed here.

## Behavior

### 1. Validate the descriptor

The null check occurs before any descriptor dereference.

For a nonnull descriptor, the function compares the word at offset 4 with the global expected tag. If they differ, it returns `0xffffffce`.

For either invalid-input case, no descriptor write or dependency call is visible in this function. An unreadable nonnull descriptor is not converted into an invalid-descriptor status; its access behavior is outside the established contract.

### 2. Decide whether replacement is required

After successful validation, the function reads the allocation extent into a local 32-bit unsigned value **C**.

Replacement is selected when either of these conditions holds:

1. **Growth beyond the allocation:** C < R.
2. **A sufficiently large reduction:** R < L, and at least one of:
   - C − R > 2047.
   - R < floor(C / 2).

All comparisons in this decision are unsigned. The half-allocation comparison uses an unsigned right shift by one, so odd values of C are rounded down.

The subtraction is a 32-bit unsigned operation. It is reached only after C < R has evaluated false, so C ≥ R on that path and the subtraction does not wrap.

The reduction condition is gated by R < L. A large unused allocation does not, by itself, trigger replacement if the requested extent is equal to or greater than the logical extent read for this decision.

The boundaries are strict:

- A difference of exactly 2047 does not satisfy the difference condition.
- A difference of 2048 does.
- Equality with floor(C / 2) does not satisfy the half-allocation condition.
- A request equal to L does not enter the reduction condition.

The decision has short-circuit read behavior. If C < R is true, the logical extent is not needed for the replacement decision. Otherwise, the logical extent is read to evaluate R < L.

### 3. Complete without replacement

If replacement is not selected, the function writes R to the descriptor’s logical-extent field and returns zero.

On this path:

- The allocation dependency is not called.
- The transfer dependency is not called.
- The release dependency is not called.
- The backing-address and allocation-extent fields are not written by this function.
- Existing backing-storage contents are not directly accessed by this function.

This path can increase the logical extent within the stored allocation extent. No initialization or zero-filling of newly exposed contents is visible.

### 4. Request replacement storage

If replacement is selected, the function calls **F-638beded7699** with these two numeric arguments, in order:

1. R.
2. The constant 4.

The meaning of the second argument is unknown. It must not be assumed to specify alignment, an allocation class, or ownership.

A zero result causes an immediate return of `0xffffff94`. No descriptor field has been explicitly written by this function before that return, and neither the transfer dependency nor the release dependency is subsequently called.

This is a local no-write guarantee, not a guarantee that the complete descriptor or global state remains unchanged: effects of F-638beded7699 are not supplied.

A nonzero result is retained as the replacement backing address.

### 5. Select the transfer extent

After the allocation dependency returns a nonzero result, the function reads the descriptor’s logical extent again. It does not retain the logical extent from the replacement decision.

The visible accesses include an initial read of that field and another read for comparison with R. Under stable descriptor state, the selected transfer extent is:

**T = min(L, R)**

This bounds the transfer by the requested new extent and the current logical extent, not by the stored allocation extent.

The minimum expression is valid only when those reads observe a stable logical extent. Concurrent mutation, reentrant mutation, or dependency-induced mutation must not be silently excluded when interpreting the actual access sequence.

### 6. Transfer and release

The function invokes **D-UNMAPPED-1**, the transfer dependency, with:

1. The replacement address.
2. The descriptor’s backing address as read for this call.
3. T.

The dependency’s exact API contract and the units of T are not supplied. A byte-copy operation is inferred intent, not established behavior.

After that call returns, the function invokes **F-8349c252c168** with:

1. The descriptor’s backing address, read again after the transfer call.
2. The constant 4.

The second backing-address read is significant. The function does not save the old backing address and reuse that saved value for both calls. If the transfer dependency changes the descriptor’s backing-address field, the release dependency receives the changed value.

Neither dependency’s return value is inspected. No recovery path is visible for a transfer failure, release failure, or nonlocal interruption.

### 7. Publish the replacement

After the release dependency returns, the function performs these descriptor writes in order:

1. Allocation extent ← R.
2. Backing address ← replacement address.
3. Logical extent ← R.

It then returns zero.

The order is not an atomic descriptor replacement. The release call occurs before publication of the replacement address. The allocation extent is written before the backing address, and the logical extent is written last.

For ordinary, non-aliasing descriptor storage, the tag is not explicitly rewritten.

## Side effects

### Direct effects

The function directly reads the expected-tag global and relevant descriptor fields. Its explicit writes are limited to:

- The logical extent on every successful operation.
- The allocation extent and backing address on successful replacement.

It contains no explicit write to the expected-tag global.

The function itself contains no loop that initializes or clears backing storage. Any storage modification during replacement is delegated to D-UNMAPPED-1 or is an unknown effect of a dependency.

### Ownership and lifetime

The visible call sequence expresses an intended ownership transition:

- Obtain a replacement address.
- Transfer selected existing contents.
- Request release of the prior backing address.
- Store the replacement address in the descriptor.

Actual ownership acquisition and release are not proven without the dependency contracts. In particular:

- A nonzero allocation result is treated as usable storage without further validation.
- The release dependency is called before the descriptor points to the replacement.
- A zero allocation result does not trigger a release call from this function.
- No dependency is assumed to preserve globals, descriptor contents, or unrelated memory.
- No dependency is assumed to own or release memory merely because of its apparent role.

If the descriptor resides inside storage affected by transfer or release, later descriptor accesses may be invalid or may observe changed values. The function does not detect or prevent such aliasing.

### Zero requested extent

R = 0 has no dedicated branch.

Depending on C and L, it can either update the logical extent without replacement or request an allocation with extent zero. If that allocation returns zero, the result is `0xffffff94`; the function does not reinterpret zero as a successful empty allocation.

After a nonzero allocation result, a transfer call with T = 0 still occurs. The transfer dependency’s behavior for a zero extent is unknown.

## Acceptance examples

These are conditional static acceptance examples, not executed tests. Unless stated otherwise, they assume a matching tag, stable descriptor state, non-aliasing storage, normally returning dependencies, and no dependency-induced descriptor mutation.

| Initial state and request | Required behavior |
|---|---|
| Descriptor is null | Return `0xffffffce`; do not dereference the descriptor or call a dependency. |
| Nonnull descriptor has a mismatched tag | Return `0xffffffce`; do not explicitly write descriptor fields or call a dependency. |
| C = 100, L = 80, R = 90 | No replacement. Write logical extent 90; retain allocation extent 100 and the backing address. |
| C = 100, L = 80, R = 100 | No replacement. Equality with C does not trigger growth. Write logical extent 100. |
| C = 100, L = 80, R = 101 | Request replacement with arguments 101 and 4. On nonzero result, select transfer extent 80, invoke transfer then release, and publish allocation and logical extents of 101. |
| C = 4096, L = 3000, R = 2048 | Replacement occurs because C − R = 2048, even though R equals floor(C / 2). |
| C = 4096, L = 3000, R = 2049 | No replacement: the difference is 2047 and R is not below half the allocation. |
| C = 1000, L = 900, R = 499 | Replacement occurs through the half-allocation condition, despite a difference smaller than 2048. |
| C = 1000, L = 900, R = 500 | No replacement: equality with half the allocation does not suffice. |
| C = 10000, L = 100, R = 100 | No replacement despite substantial unused allocation: R < L is false. |
| Any valid state selecting replacement, followed by a zero allocation result | Return `0xffffff94`; make no transfer or release call and no explicit descriptor write. |
| C = 1, L = 1, R = 0 | No replacement: the difference is only 1 and 0 is not below floor(1 / 2). Set the logical extent to zero. |
| C = 2, L = 1, R = 0 | Replacement is selected through the half-allocation condition. A nonzero allocation result leads to a transfer call with extent zero. |

An additional ordering example does not assume dependency state preservation: if D-UNMAPPED-1 changes the descriptor’s backing address before returning, F-8349c252c168 receives the changed address, not necessarily the address previously passed as the transfer source.

## Uncertainties

The following remain **documented_only**:

- The expected tag’s value and lifecycle.
- Whether extents count bytes, elements, or another unit.
- The dependency meaning of the constant 4.
- The exact identity and semantics of D-UNMAPPED-1.
- Dependency ownership, memory-release, and failure contracts.
- Whether callers guarantee L ≤ C or otherwise ensure transfer safety.
- Whether callers prohibit descriptor/backing-storage aliasing.
- Whether concurrent access or reentrant mutation is supported.
- Whether dependencies preserve any global or descriptor state.
- The validity of using the represented integer-width address fields on other ABIs.

No locking, atomic publication, rollback, or exception handling is established. A dependency that does not return normally can interrupt the operation before its final descriptor writes.
