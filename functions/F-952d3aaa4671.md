# F-952d3aaa4671

## Purpose

F-952d3aaa4671 initializes a caller-supplied record using three supplied 32-bit values and a seven-bit value extracted from a 16-bit field in another memory region.

The established behavior consists of seven 32-bit destination writes, three one-byte destination writes, and one 16-bit source read. Two destination fields receive the same supplied value. Another destination field retains the address-bearing input used for the source read.

The apparent intent is record initialization. The available evidence does not establish a record type, field names, resource-management role, or protocol meaning. In particular, the two equal fields must not be described as cursors, bounds, or ownership references without additional evidence.

### Extraction

The source access reads an unsigned 16-bit quantity at source-relative byte offset 28. The destination field at offset 12 receives that quantity shifted right by nine bit positions and represented as a 32-bit unsigned value.

Equivalently, the extracted value comprises bits 9 through 15 of the 16-bit source quantity. Its range is 0 through 127 inclusive. Source bits 0 through 8 do not affect the result.

Because the source quantity is unsigned, the extraction does not sign-extend bit 15. For example, a source halfword with only bit 15 set produces 64, not a negative result.

The evidence does not independently establish byte order. The numeric extraction is defined on the 16-bit value obtained by the target’s load; a portable byte-level encoding cannot be specified from this material alone.

### Aliasing and boundary behavior

No explicit overlap check separates source and destination storage.

If the source field overlaps bytes written by the first three destination writes, the extraction uses the source halfword as it exists after those writes. It must not be specified as an unconditional read of the source’s entry-time contents.

Conversely, if the source field overlaps destination bytes written only after the source read, the extraction occurs before those later writes alter them. For example, when source and destination addresses are equal, the source halfword occupies destination offsets 28 and 29. It is read before those bytes are cleared.

These overlap consequences describe the supplied access sequence. The evidence does not establish whether a broader calling contract permits every overlapping arrangement.

There is no arithmetic on the supplied values except address formation for memory access and the right shift used for extraction. In particular, the repeated value is not incremented, normalized, or range-checked.
