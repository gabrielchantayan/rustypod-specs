# F-bd3f94a688c0

## Purpose

F-bd3f94a688c0 selects a small unsigned increment from one byte in caller-supplied memory and adds that increment to a value supplied as two 32-bit words. It returns the resulting 64-bit bit pattern, with carry propagated from the lower word to the upper word.

The established selection is:

| Byte value | Increment |
|---|---:|
| `0x00` | 0 |
| `0x01` | 8 |
| `0x02` | 6 |
| Any other byte | 10 |

The operation is consistent with adjusting a position, size, or counter according to a byte-sized discriminator. That interpretation is inferred intent only. The supplied evidence does not establish the application-level meaning of either the byte or the accumulated value.

## Interface

The function accepts four inputs in this order:

1. **Selector address.** A pointer to memory from which the function reads one byte. The pointer is not used as a string: no terminator search, length calculation, or subsequent-byte inspection is established.
2. **Unused 32-bit input.** The supplied body does not read or otherwise use this argument.
3. **Lower word.** A 32-bit unsigned value forming bits 0–31 of the initial value.
4. **Upper word.** A 32-bit word forming bits 32–63 of the initial value. The supplied representation presents this argument as a signed integer, but its bits are used as the upper half of the returned value.

The output is one 64-bit value. Its low 32 bits contain the adjusted lower word, and its high 32 bits contain the upper word adjusted for any carry.

\[

## Behavior

### Selector read and classification

The function first reads the byte at the selector address. This read occurs even when the byte is zero and the numerical result will be unchanged.

Only the captured byte determines the increment. The four selection cases are exhaustive:

- Zero selects no change.
- One selects an increment of eight.
- Two selects an increment of six.
- Every other byte selects an increment of ten.

There is no established rejection of an unrecognized selector. For example, `0x03`, `0x7F`, `0x80`, and `0xFF` all select ten.

The supplied representation uses a character type for this read. Whether that type is signed does not change the selection: the only distinguished values are zero, one, and two; every remaining byte representation takes the same default case.

### Zero selector

When the byte is zero, the function returns the original word pair without numerical adjustment:

- The lower return word equals the lower input word.
- The upper return word equals the upper input word’s bit pattern.

This remains true when either input word has its most significant bit set. The branch does not normalize, clamp, or reinterpret those bits.

### Nonzero selector

For a nonzero byte, the function adds the selected increment to the lower word using 32-bit unsigned arithmetic.

The lower return word is the sum reduced modulo \(2^{32}\). A carry is generated exactly when the mathematical sum exceeds `0xFFFFFFFF`.

The upper return word is the original upper word plus that carry. Because the largest selected increment is ten, the low-word addition can produce only a carry of zero or one.

The carry thresholds are:

| Selected increment | Lowest lower word producing carry |
|---|---|
| 8 | `0xFFFFFFF8` |
| 6 | `0xFFFFFFFA` |
| 10 | `0xFFFFFFF6` |

Immediately below each threshold, the lower-word result is `0xFFFFFFFF` and the upper word is unchanged. At the threshold, the lower-word result becomes zero and the upper word increases by one.

The function provides no separate overflow indicator for the complete 64-bit value. At the returned bit-pattern level, a carry beyond an all-ones upper word is discarded.

### Return layout and ordering

The return places the adjusted upper word in bits 32–63 and the adjusted lower word in bits 0–31. This is a bit-position contract, not a statement about byte order in memory or a particular return-register convention.

The established externally relevant ordering is:

1. Read the selector byte.
2. Select the increment and determine the adjusted words.
3. Return the assembled 64-bit result.

No intermediate result is written through the selector address or another supplied pointer.
