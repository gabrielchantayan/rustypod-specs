## Behavior

The function then invokes the callable obtained from that slot. The shown path contains one indirect invocation and no alternate dispatch path.

The callable is selected before invocation. Changes made by the callable to the original input storage or to the table slot do not retroactively select a different target for this invocation. The visible function does not reload either location after the call.

### Result extraction

After the indirect call returns normally, its result is used as an address. The function reads four bytes from that address and returns the resulting value.

This final read occurs after the call. Consequently, the returned value reflects the memory available at the returned address at the time of that read, not necessarily any value present before the call.

There is no visible second read of the returned storage, comparison, retry, or fallback. The four-byte value is returned regardless of its bit pattern, provided the read completes normally.

A zero-valued payload is therefore a possible ordinary result. It must not be confused with a null returned address: the former is data obtained by a successful read; the latter would be used as a read address without a visible guard.
