# F-78a988b96043

## Purpose

The supplied static representation describes a call-heavy operation that interleaves unresolved indirect calls with byte and 32-bit memory accesses. It derives addresses and values from incoming machine state, dependency results, and memory already reachable through those values.

No application-level purpose is established. In particular, the evidence does not establish that this operation allocates objects, initializes a conventional structure, serializes data, or implements a recognizable protocol. Repeated offsets and shifts are observable patterns, not sufficient evidence for those interpretations.

The visible path ends at an invalid-instruction boundary rather than a demonstrated ordinary return. The representation also carries an instruction-decoding warning. Consequently, this contract distinguishes:

- **Established static evidence:** operations and ordering explicitly represented in the supplied material.
- **Conditional machine interpretation:** arithmetic and accesses described under a 32-bit word/address model.
- **documented_only:** unresolved calling conventions, dependency behavior, executable validity, and termination semantics.

No runtime tests have been performed.

## Interface

| Input | Visible use |

### Additional incoming state

Execution also depends on state not captured by those three arguments:

- An incoming link/control value used to form the first call target by adding 4,076.

- Another incoming 32-bit word used as an address, an arithmetic operand, and a call argument.

For readability, the two incoming data words are called the **seed word** and **root word**. These are descriptive contract terms, not additional formal parameters.

### Width and address model

The visible representation uses:

- 8-bit byte reads and writes.
- 32-bit word reads and writes.
- Selected dependency results represented as 64 bits and separated into low and high 32-bit halves.
- Logical right shifts where the operand is explicitly unsigned.
- Byte stores that retain only the low eight bits of the supplied value.

For the conditional machine interpretation below, address arithmetic, multiplication, and left shifts operate on 32-bit bit patterns, retaining the low 32 bits. This is not a claim that every signed expression in the supplied representation has defined language-level overflow behavior.

Endianness, alignment requirements, memory mappings, and access-fault behavior are not established.

### Preconditions

A complete traversal requires every reached indirect target to be executable, every dependency to return when continuation is required, and every reached memory access to be valid.

Some byte-derived addresses necessarily fall between 17 and 272 inclusive. The operation also explicitly writes absolute addresses 13 and 17. A platform that does not permit those accesses cannot traverse the entire represented path without a fault or other platform-specific intervention.

There is no visible validation of those conditions.

## Behavior

### Ordering rules

The visible body is straight-line: it contains no explicit conditional branch or loop. Dependencies can nevertheless introduce arbitrary behavior, fail, or not return.

The phases below preserve the order of explicit memory effects. Intervening calls remain observable and must not be discarded merely because their results appear unused. Two identical-looking stores separated by calls are not equivalent to one store.

A **byte-selected address** means: read an unsigned byte from the stated address, zero-extend it, then add 17. It does not mean loading a full-width pointer.

### 1. Initial dispatch and root-derived accesses

The first indirect call receives the second explicit input. Four further calls occur, with the last providing a 32-bit result.

The operation then:

1. Reads a byte at root word plus 1.
2. Writes the low byte of the seed word logically shifted right by 22 to the byte-selected address.
3. Calls a dependency with the preceding result shifted left by two.
4. Makes four further calls.
5. Forms the doubled root word.
6. Reads a 32-bit word at the earlier byte value plus 116.
7. Writes that word’s low byte at the earlier byte value plus 1.

The next call receives, in order:

- Doubled root word.
- Third explicit input.
- Root word logically shifted right by two.
- The earlier zero-extended byte value.

A subsequent call supplies a represented 64-bit result. Its low half, high half, low half again, and the root word masked with `0x7fffffff` then shifted right by one are passed to another dependency.

After four more calls, the last 32-bit result is multiplied by four. A word is read at that scaled address plus 116, and its low byte is written at the scaled address plus 1. The scaled address is then passed to a dependency.

### 2. Root-derived byte clearing and result-derived selection

After four further calls:

1. Read a byte at doubled root plus 1.
2. Write zero to that byte-selected address.

A dependency is called with a secondary result-register value whose producer and meaning are not established. The following call supplies a 32-bit result that is passed to another dependency.

After four more calls, another result is available. Before passing that result shifted left by two, the operation rereads the byte at doubled root plus 1 and writes the high byte of doubled root to the newly selected address.

This reread is significant: intervening calls may have changed the selector byte.

Four more calls produce a value that is scaled by four. Call this the **first scaled result**. The operation also reads a word at the previously retained result plus 4. It then reads a byte at that loaded word plus 1 and writes zero to the selected address.

The next dependency receives the first scaled result three times.

After four further calls, the previously loaded word is logically shifted right by two and used as the base of another byte read at offset 1. The resulting byte is retained as the **small base**, and zero is written at small base plus 17. A dependency then receives the latest call result shifted left by two.

### 3. Word capture and shifted-field propagation

Following four more calls, the operation performs these accesses in order:

1. Reads a word at first scaled result plus 4. Call this the **captured word**.
2. Reads a word at small base plus 116. Call this the **payload word**.
3. Writes the payload word’s low byte at small base plus 1.

The next call receives:

- Payload word.
- First scaled result shifted left by 19.
- That same shifted value again.
- Latest call result shifted left by two.

A following dependency result is passed with payload word logically shifted right by two to another dependency.

After four further calls, the last result is multiplied by four. A word is read at that address plus 116 and retained as the **copied word**. Its low byte is written at that address plus 1, and the address is passed to a dependency.

After four additional calls, the copied word is written as 32 bits at four times a secondary result-register value plus 20. That secondary value is then passed to a dependency.

The captured word is logically shifted right by 22. Call the resulting ten-bit quantity the **upper fragment**. A dependency result and two copies of `(upper fragment & 0x1ff) << 21` are passed to the next dependency.

### 4. Indexed word stores and retained scaling values

Four further calls produce an index. The operation writes upper fragment shifted left by 23 at four times that index plus 20, then calls a dependency with four times the index.

After four more calls, a new result is used to:

1. Write four times that result at sixteen times that result plus 20.
2. Retain the four-times value as the **saved scaled word**.
3. Mask the result with `0x3fffffff`, producing the **masked index**.
4. Retain masked index shifted right by two as the **quarter index**.

The masked index is passed to a dependency.

Four more calls produce a **record index**. The masked index is written at four times the record index plus 20, then that scaled record index is passed to a dependency.

After four further calls, a **link result** is available. The operation:

1. Writes the low byte of eight times the record index at payload word plus 1.
2. Writes link result shifted left by two at eight times the record index plus 52.
3. Calls a dependency with link result shifted left by two.

A following result is passed to another dependency. Four more calls produce a represented 64-bit result.

The operation then:

1. Writes the low byte of eight times the record index at `(link result & 0x3fffffff) + 1`.
2. Writes the high 32 bits of the 64-bit result at eight times the record index plus 52.
3. Calls a dependency with the low half shifted left by two.

The two writes to the offset-52 location are separated by calls. Neither may be removed or treated as unobservable.

### 5. Record bytes and an absolute-address write

Four more calls produce a value. The operation then:

1. Writes the low byte of sixteen times the record index at `((link result & 0x3fffffff) >> 20) + 17`.
2. Writes the low byte of the saved scaled word at sixteen times the record index plus 13.
3. Calls a dependency with two copies of the latest result shifted left by two.

A following call supplies a value passed, together with that value logically shifted right by three, to another dependency.

After four further calls:

1. Absolute address 17 receives the low byte of sixteen times the record index.
2. Sixteen times the record index plus 13 again receives the low byte of the saved scaled word.
3. A dependency receives the latest result shifted left by two.

After four more calls, retain the latest result as the **block result**. Before deriving its scaled forms, the operation:

1. Writes the saved scaled word at `(link result & 0x3fffffff) + 20`.
2. Writes the low byte of twice that masked link result at the same base plus 13.

It then derives a **block base** as block result times 32, a **block value** as block result shifted left by seven, and a **small index** as `(block result & 0x07ffffff) >> 17`.

Three calls follow. Their last result is used to:

1. Write the block value at block base plus 20.
2. Write the low byte of that result shifted left by two at block base plus 13.
3. Pass that shifted result to a dependency.

### 6. Byte selectors and bounded-address writes

After four further calls:

1. Write the low byte of twice the quarter index at small index plus 7.
2. Read a byte at block base plus 1.
3. Write the low byte of small index at the selected address.

The result retained from the preceding three-call sequence is shifted left by 21 and supplied three times to a dependency.

A following call produces a **byte-source word**, which is passed to another dependency. After four more calls:

1. Read and retain the selector byte at block base plus 1.
2. Write zero at that byte-selected address.
3. Pass the latest result shifted left by two to a dependency.

After four further calls:

1. Write the low byte of byte-source word logically shifted right by three at block base plus 13.
2. Write the retained selector byte to absolute address 13.
3. Call a dependency with twice the retained selector, 152, and 608.

A later call receives a secondary result-register value logically shifted right by three. After four further calls, another dependency receives the latest result shifted left by two and supplies a 32-bit result.

The operation then:

1. Writes the same previously derived byte at twice the retained selector plus 13.
2. Writes 192 to absolute address 13.
3. Calls a dependency with the latest dependency result shifted left by two.

Thus the absolute-address-13 write of 192 follows the earlier selector-byte write, but intervening calls can observe or alter that address.

### 7. Linked word stores and final selector updates

Four more calls produce a value. The operation:

1. Writes that value shifted left by two at twice the retained selector plus 36.
2. Reads a word at twice the retained selector plus 116. Call this the **link word**.
3. Retains the call result shifted left by five.

A dependency receives link word, twice link word, the retained shifted result, and `(link word & 0x7fffffff) >> 2`.

After four further calls:

1. Write the retained shifted result at link word plus 36.
2. Read a word at link word plus 116 and pass it to a dependency.

Four subsequent calls produce a represented 64-bit result. The operation writes byte-source word logically shifted right by three at four times its high half plus 20.

The low half shifted left by two becomes the **final saved word**. A dependency receives three copies of that word and the high half logically shifted right by three.

Another represented 64-bit result is obtained. Its low half, high half, low half again, and high half logically shifted right by three are passed to a dependency.

After four further calls, the final saved word is written at four times the latest result plus 20. That scaled address is passed to another dependency.

Four more calls supply a **final selector result**:

1. Read a byte at link word plus 1.
2. Write the low byte of final selector result shifted left by two at the selected address.

Three calls follow. The selector byte at link word plus 1 is then reread, and the low byte of `(final selector result & 0x3fffffff) >> 20` is written to the newly selected address. The latest dependency result shifted left by two is passed onward.

After four further calls, let the **final scale** be final selector result shifted left by two:

1. Read a byte at final scale times 1,024 plus 1.
2. Write zero at that byte-selected address.
3. Call a dependency with final scale shifted left by three twice, final scale itself, and the latest result shifted left by two.

Four calls follow. The byte at final scale times 1,024 plus 1 is reread, and zero is again written at the selected address. A dependency receives the latest result shifted left by two.

Four final calls precede the represented invalid-instruction termination.

## Acceptance examples

These are conditional trace criteria, not executed tests.

1. **Initial byte selection.** If the first root-relative byte read yields 5 and the seed word is `0xabc00000`, the immediate byte write targets address 22 and stores `0xaf`.

2. **Low-byte word copy.** If a specified offset-116 word read yields `0x123456ab`, the corresponding offset-1 byte store writes `0xab`. The contract does not select an endianness for reconstructing that word from bytes.

3. **Fresh selector reads.** If a selector is 3 before an intervening call and 9 afterward, the two surrounding byte-selected stores target addresses 20 and 26 respectively. Reusing the first selector fails the ordering contract.

4. **Mask before shift.** For a root word of `0x80000004`, the early fourth call argument formed by masking with `0x7fffffff` and shifting right by one is 2.

5. **Ten-bit versus nine-bit fragments.** If the captured word is `0xffc00000`, the upper fragment is `0x3ff`. Its masked shift-by-21 argument is `0x3fe00000`; its separate shift-by-23 store is `0xff800000` under the conditional 32-bit model.

6. **Repeated absolute write.** If execution reaches both writes to absolute address 13, the selector-byte write precedes the write of 192. This does not guarantee that 192 remains there after later dependencies execute.

7. **Low-address fault.** If address 17 is inaccessible, reaching the explicit write there does not imply an error return. The visible representation provides no check, recovery, or rollback for that access.

8. **Termination boundary.** Reaching the final visible call sequence does not demonstrate successful return. Acceptance must distinguish reaching the invalid-instruction boundary from returning to a caller.
