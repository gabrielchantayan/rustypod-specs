# F-328c2d1f70fa

## Purpose

F-328c2d1f70fa repeatedly executes an ordered sequence of dependency calls, memory accesses, address transformations, and software breakpoint `0x92`. The supplied static representation contains an unconditional back edge and no normal return path.

Its application-level purpose is not established. Addresses and fields described here must not be assumed to represent objects, devices, queues, or allocated storage.

A fully traversed iteration:

- Makes 37 dependency calls.
- Performs 15 explicit stores, interleaved with reads and calls.
- Reaches a software breakpoint before the later updates.
- Decreases a frame-like base by `0xF4`.
- Replaces a link-like value before the final call.
- Begins another iteration if execution continues.

These are static behavioral observations, not evidence that an iteration can execute successfully in any particular environment.

## Behavior

### 1. Entry calls and captured byte-store base

Each iteration establishes a zero byte and calls `F-000000000001` with two explicit zero arguments. Its target is the current link-like value plus `0xFFE`.

On first entry, that link-like value is ambient. Near the iteration boundary, the routine explicitly replaces it with `0x08712031`. If nothing changes it before the next iteration’s first call, that call targets `0x0871302F`.

The next observable operations are:

1. Call `F-000000000002`.
2. Call `F-000000000003`.
3. Read the first global pointer slot and retain its value as the initial byte-store base.
4. Call `F-000000000004`.
5. Call `F-000000000005`, obtaining a paired result.
6. Call `F-000000000006`.

The two explicit arguments to `F-000000000006` are the paired result’s low word and the 32-bit sum of its high and low words. A separately established zero byte also contributes to the represented sum without changing its value.

The routine then stores an additional byte return channel from `F-000000000006` at captured-base offset `0x11`. After `F-000000000007`, it stores zero at captured-base offset `0x15`.

Both destinations use the previously captured base, not a reload of the global slot. A dependency’s change to the slot therefore does not redirect these explicit stores.

### 2. Halfword initialization and first paired-result transformation

`F-000000000008` supplies a 16-bit result and an additional address return channel. The result is stored as a halfword at offset `0x0C` from that address.

`F-000000000009` supplies another paired result. The routine then:

- Stores a zero halfword at offset `0x2C` from its high word, treating that word as an address.
- Stores its low word logically shifted right by 26 bits into the 32-bit frame slot at offset `0x26C`.

The shifted value is between 0 and 63 inclusive.

Next, the routine calls `F-000000000010`, reads a 32-bit destination base from frame offset `0x320`, and calls `F-000000000011` and `F-000000000012`, in that order.

It writes the low word from `F-000000000009`, shifted left by two bits with only 32 result bits retained, to offset `0x54` from that captured destination base. The frame slot is not reloaded after the two intervening calls.

### 3. Fixed-address read and breakpoint boundary

The routine calls `F-000000000013` through `F-000000000017` in order.

It then reads an unsigned halfword at absolute address `0x21C48994`. The zero-extended value itself becomes an address base for later reads. There is no additional pointer lookup through the fixed-address region.

After `F-000000000018`, the routine reads a word from frame offset `0x280` and passes it to `F-000000000019`. That call’s result is retained for later scaling.

There is no explicit recovery branch or ordinary error result associated with the breakpoint. All remaining behavior is conditional on execution resuming at the following operation.

### 4. Post-breakpoint reads and retained destination

After resumption, the routine:

- Shifts the result from `F-000000000019` left by two bits.
- Derives `0x21C4` by logically shifting `0x21C48960` right by 18 bits and multiplying by four.
- Reads a 32-bit address at offset `0x44` from the zero-extended halfword obtained at `0x21C48994`.

The address from the last read becomes a retained destination base for later word stores and a later address-derived halfword value.

The routine calls `F-000000000020`, then obtains a word result from `F-000000000021`.

`F-000000000022` receives two explicit arguments:

1. The word returned by `F-000000000021`.
2. A word read at offset `0x04` from the earlier zero-extended halfword address base.

The reads at offsets `0x44` and `0x04` therefore share that same small, halfword-derived address base. The second read occurs after the intervening dependency calls and may observe their memory effects.

### 5. Global-derived halfword and fixed-derived pointer

- Plus the result from `F-000000000019` shifted left by two bits.

It then calls `F-000000000025` to obtain another address and stores halfword `0x21C4` at offset `0x04` from that returned address.

Calls `F-000000000026` and `F-000000000027` follow.

### 6. Late paired result and frame-base change

### 7. Mirrored word fields and byte transfer

After `F-000000000030`, the same zero-extended value is written to the **32-bit** field at retained-destination offset `0x64`.

These are separate stores with a dependency call between them, not an atomic paired update.

After `F-000000000031`, the routine stores the low sixteen bits of the retained destination base at an address formed by adding:

- The low word from `F-000000000028`, shifted left by six bits.
- An additional address return channel from `F-000000000031`.

It then calls `F-000000000032` and `F-000000000033`.

After `F-000000000034`, the captured byte is stored at the sum of:

- The zero-extended halfword read through the high word of `F-000000000028`.
- The ambient address register.
- `0x19`.

### 8. Final word update and back edge

After `F-000000000036`, it explicitly sets the link-like value to `0x08712031`.

It then reads a word at offset `0x44` from the four-times-high-word address and passes that word to `F-000000000037`.

Execution returns to the beginning of the loop without testing a result, completion flag, or loop counter. The next first-call target is `0x0871302F` only if the intervening final call or other external effects have not changed the link-like value.

These are conditional static expectations, not executed tests. Unless otherwise stated, assume dependencies return, the breakpoint resumes, accesses are valid, relevant addresses do not alias, and no unspecified interference changes the named operands.

7. **Global-derived halfword.** A second-global value of `0x12345678` and an index result of `3` produce halfword destination `0x12345684` and stored value `0x5678`.
