# F-79553cd72430

## Purpose

F-79553cd72430 orders two memory-resident records using two successive criteria:

1. Unsigned 32-bit keys returned by F-4055be9c3f18.
2. If those keys are equal, values extracted from counted sequences of unsigned 16-bit units through shared lookup storage.

The signed 32-bit result is normally −1, 0, or +1. An early zero-count path instead returns an arithmetic count difference, allowing results throughout −65535 to +65535.

The lookup behavior suggests normalization or collation with suppression of selected units. This is inferred intent, not an established character encoding or collation standard. In particular, low-valued units mapped to zero behave differently from high-valued units mapped to zero.

Sequence transformation can be described as a function of individual raw values only when the relevant sequence storage, shared base, and table entries remain stable. The established access behavior includes an additional sequence-unit read on each high-value path and separate acquisitions of the shared base for separate lookup expressions.

## Behavior

### Primary-key comparison

The function first calls F-4055be9c3f18 with the first record’s address plus two bytes. It then calls the same dependency with the second record’s address plus two bytes.

Both calls precede every count-field read performed directly by this function. The returned keys are retained and compared as unsigned 32-bit quantities:

- First key greater than second: return +1.
- First key less than second: return −1.
- Equal keys: proceed to the counts.

A first key of \(2^{32}-1\) therefore sorts after a second key of zero.

The calls are ordered, not independent. Effects of the first may affect the second. Effects of either may affect subsequent record reads, the shared base, or table storage. The function does not take a record or table snapshot before calling the dependency.

### Count handling

After equal primary keys, the first record’s count at offset +6 is read once and widened from unsigned 16 bits to unsigned 32 bits.

If that count is zero, the function reads the second count for the return expression and returns zero minus that value. There is no earlier second-count read on this path.

If the first count is nonzero, the function reads the second count and retains it. A nonzero second count allows sequence comparison. A zero second count selects the early-return path, which reads the second count again and subtracts that newly read value from the retained first count.

Consequently, the read order is:

- First count zero: first-count read, second-count read, return.
- First count nonzero and second count zero: first-count read, second-count read, second-count reread, return.
- Both retained counts nonzero: one read of each count, then sequence comparison.

The early-return decision and subtraction need not use the same second-count observation. No synchronization or concurrent-mutation guarantee follows from this fact.

The subtraction is 32-bit unsigned arithmetic. Its signed 32-bit return representation gives the corresponding mathematical difference within −65535 through +65535. Under stable storage, counts of zero and 12 produce −12; counts of 12 and zero produce +12.

Once sequence comparison begins, the retained counts become remaining-unit counters. The count fields are not read again.

### Lookup storage and base acquisition

Lookup entries are unsigned 16-bit quantities, widened without sign extension. Each reached lookup expression separately references the shared base:

| Lookup kind | Entry address relative to the base acquired for that expression |
|---|---|
| Low-value mapping | Minus 512 bytes, plus twice the initially read unit |
| High-value selector | Plus twice the high byte obtained from a separate sequence-unit read |
| Selected high-value mapping | Plus twice the sum of the retained selector and the initially read unit’s low byte |

There is no function-local snapshot of the shared base covering extraction, a comparison round, or the whole call. In particular, selector lookup and selected mapping use separate base acquisitions. The base’s stability is not established independently of table-entry stability.

The selector lookup expression uses both the shared base and a reread of the current sequence address. The supplied representation does not establish which of those operands is evaluated first. Both contribute to the selector-entry address; the selector entry must be obtained before its value determines whether a selected mapping is performed.

This contract preserves those distinct source-level accesses. It does not establish volatile access semantics, synchronization, or a guaranteed physical machine-load schedule.

### Extraction from one sequence

Each comparison round begins with a comparison value of zero for each side. Extraction from the first side completes before extraction from the second side begins.

If a side has no remaining units, its extracted value is zero without any further sequence-unit or table-entry read.

Otherwise, extraction initially reads the unsigned 16-bit unit at the current sequence position and retains that value. This consumes one counted unit: the remaining count decreases by one, and the next sequence position is two bytes later. A reread of the same position on a high-value path does not consume a second counted unit.

#### Initially read unit below 256

The function acquires the shared base for a low-value lookup and reads the corresponding entry from the 256-entry region immediately before that base.

The entry becomes the extracted value. Extraction ends for this side even if that entry is zero. There is no additional sequence-unit read for this unit on this path.

#### Initially read unit from 256 through 65535

The function reads the same sequence address again as an unsigned 16-bit quantity. The high byte of this second observation, not necessarily the high byte of the initially retained value, supplies the selector index.

That reread occurs on both sides’ high-value paths, including when the selector ultimately obtained is zero. It is not a read of the next sequence position.

The selector expression also acquires the shared base. No relative evaluation order between that acquisition and the sequence reread is established. The selector entry is then read using the resulting address.

- **Selector zero:** the initially retained whole unit becomes the comparison value. No selected-mapping entry is read.
- **Selector nonzero:** the function separately acquires the shared base for the selected mapping. It reads an entry indexed by the selector plus the low byte of the initially retained unit. That entry becomes the comparison value.

Thus, on the selected-mapping path, the selector index comes from the second sequence observation, while the low-byte contribution comes from the first observation.

The selector-plus-low-byte sum uses widened arithmetic. Its maximum is \(65535+255=65790\); it is not truncated to 16 bits before address formation. The maximum scaled offset is therefore 131580 bytes, subject to the address-validity preconditions.

A nonzero comparison value ends extraction. A zero value from a selected high-value mapping causes extraction to continue with the next counted unit, if any. Exhaustion after such suppression yields zero.

Lookup results are not transformed recursively.

### Stable-storage interpretation

When the repeated sequence read observes the same value and the base and entries remain stable, extraction has this simpler interpretation:

- Units below 256 use the low-value map, and a zero result ends extraction.
- Higher units with a zero selector preserve their original value.
- Higher units with a nonzero selector use the selected mapping.
- A zero selected-mapping result suppresses that unit and continues extraction.

This interpretation must not erase the additional high-value sequence read or the separate base acquisitions from the access contract.

If storage can change between accesses, a single retained raw value and a single fixed table base are not sufficient to describe the expression dependencies. The function supplies no supported concurrent-mutation protocol.

### Comparison and termination

After first-side extraction and then second-side extraction:

- First value less than second: return −1.
- First value greater than second: return +1.
- Equal nonzero values: start another comparison round.
- Equal zero values: return 0 immediately.

Extracted values lie within 0 through 65535 and are compared without sign extension.

An equal zero pair terminates comparison even if counted units remain. A low-value mapping to zero can therefore make later sequence contents irrelevant. High-value zero mappings instead continue extraction until another value is obtained or the count is exhausted.

There is no final comparison of original counts after equal extracted values. Counts affect ordering through the early count branch and through exhaustion yielding zero.
