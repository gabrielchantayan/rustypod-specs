# F-525fd5fd6e02

## Purpose

F-525fd5fd6e02 conditionally consumes one entry from an object-associated three-byte record area, copies selected record bytes into object fields, and marks that the nonzero-count branch was entered. It first invokes a dependency on an embedded object location. After processing the count and selector, it evaluates an object-associated pointer and a value reached through that pointer. If both are nonzero, it reads an indirect invocation target from a separate global function-pointer slot and invokes that target.

“Consumes” means that the count is decremented; the selected record is not explicitly cleared. “Restoration” describes the relationship between the record bytes and their destinations. A history stack, undo operation, or synchronization protocol is inferred intent, not an established interface guarantee.

The global function-pointer slot is distinct from both the object-associated pointer and the value read through it. Those two values gate dispatch; neither supplies the invocation target.

## Interface

### Argument and completion

The function accepts one argument represented as a 32-bit integer carrying an object address.

- A nonzero argument is used directly as the object address.
- A zero argument causes F-bb50a072e902 to be called without explicit arguments. Its result supplies the object address.
- The resolved address is not checked for zero or validity before use.

The function has no explicit result value. It can complete without indirect invocation or after the invoked target returns. No caller-visible return-register value is established.

The supplied representation uses a 32-bit address model and 32-bit integer count operations. Exact machine behavior for signed overflow, address overflow, and out-of-range indexing is not established.

## Behavior

### Object resolution and preliminary dependency

For a zero argument, F-bb50a072e902 is called before any object-relative operation shown here. For a nonzero argument, this resolver is skipped.

F-338d16f9ce72 is then called with the address of the location at object offset `0x28`. The argument is the embedded location’s address, not the pointer value stored there. The dependency’s return value is unused.

This call precedes:

- The count test and decrement.
- Selector and record reads.
- Restoration and marker writes.
- The final object-associated pointer lookup.
- Any read of the global invocation-target slot.

Subsequent operations use memory as it exists after this dependency returns. Neither dependency is assumed to preserve the object, unrelated globals, or the global function-pointer slot. No earlier snapshot of those fields or of the invocation target is shown.

### Count gate and decrement

The function reads the 32-bit count at `0x5c` and tests it against zero.

If the tested count is zero, the direct restoration stage is skipped. The function does not decrement the count, inspect the selector, read record bytes, or write the restoration destinations or marker. It still proceeds to the final pointer inspection.

If the tested count is nonzero, the supplied representation shows a second count read. One is subtracted from that second value, and the result is stored back at `0x5c`. That result also determines the record index for any subsequent restoration.

The gate is a nonzero test, not a positive-count test. Negative counts are not rejected.

The decrement write precedes selector inspection and record access. A subsequent failure does not trigger any shown rollback of that write.

The two count reads need not be treated as one atomic operation. Under stable memory they observe the same value; no synchronization or supported concurrent-update contract is established.

### Selector-dependent byte transfers

After storing the decremented count, the function reads the selector byte at `0x90`.

If this first read is zero, the function performs two ordered byte transfers:

1. It reads the selected record’s first byte and writes it to `0x54`.
2. It then reads the selected record’s second byte and writes it to `0x55`.

The first destination write precedes the second source read. This is not an established two-byte snapshot or wider copy. If source and destination locations overlap, the second read observes memory after the first write.

If the first selector read is nonzero, the function reads the selector again. If the second value equals `1`, it reads the selected record’s third byte and writes that byte to `0x56`.

If the first read is nonzero and the second read is not `1`, no record byte is read by the restoration branch and no restoration destination is directly written.

For a stable selector:

| Selector value | Direct restoration |
|---|---|
| `0` | First and second record bytes to `0x54` and `0x55` |
| `1` | Third record byte to `0x56` |
| Any other byte value | None |

Only the record bytes required by the selected branch are read. In particular, an unsupported selector does not require an indexed record access, although the count has already been decremented.

Repeated selector reads are established by the supplied representation, not evidence of an intended concurrency protocol.

### Marker update

Every nonzero-count path that reaches the marker operation writes byte value `1` at `0x24`, after any selected restoration.

This write also occurs when the selector requests no restoration. The marker therefore records entry into the nonzero-count branch, not necessarily a change to restoration fields.

The zero-count path does not directly write or clear the marker.

### Pointer gates and global target lookup

After the count/restoration stage, the function reads the pointer stored at object offset `0x28`.

- If this pointer is zero, no pointee read or indirect invocation occurs.
- If it is nonzero, the function reads the first 32-bit value at that address.
- If the pointed-to value is zero, no indirect invocation occurs.
- If both the pointer and pointed-to value are nonzero, the function obtains the invocation target from the separate global function-pointer slot and invokes it.

The established ordering is:

1. Complete the applicable count, restoration, and marker operations.
2. Read the object-associated pointer.
3. If nonzero, read its first 32-bit value.
4. If both gates pass, read the global function-pointer slot.
5. Invoke the target obtained from that slot.

No earlier target snapshot is shown. In particular, the target is not captured before either preliminary dependency, before restoration, or before the pointer/value inspection. Changes made to the global slot by preceding dependencies are not excluded by this contract.

The pointer and its first value are only dispatch gates. The function does not invoke either as the target and does not pass the pointed-to value as an explicit argument.

The global-slot value is not separately tested for zero or validity before invocation. The invocation is represented without explicit arguments. Its actual calling convention, implicit machine-state inputs, effects, and return behavior remain unknown. If it returns normally, no further object-relative access is shown.

## Side effects

### Direct writes

The function’s explicit writes are:

- A 32-bit decremented count at `0x5c`.
- Depending on the selector, byte writes at `0x54` and `0x55`, or at `0x56`.
- A byte value of `1` at `0x24`.

This is an access description, not a guarantee that distinct logical fields remain unaffected by aliasing. Indexed record addresses are unchecked and may overlap other locations.

The function does not explicitly clear record bytes or write the global function-pointer slot. The slot is read only when the dispatch gates pass.

### Dependency effects and ownership

Dependencies and the indirect target may produce additional memory or global effects. They are not constrained to preserve the object or the global slot.

No allocation, release, reference-count adjustment, or ownership transfer is explicitly established. Passing an embedded address does not prove borrowing, retention, locking, unlocking, or destruction. Reading a pointer does not establish ownership of its storage.

### Errors and partial completion

There is no explicit error result, exception handler, recovery branch, or transaction boundary.

If a dependency fails, an access is invalid, or indirect invocation cannot complete normally, no local recovery behavior is documented. Earlier effects may already have occurred. For example, count decrement precedes record access, and restoration and marker writes precede the global target lookup.

## Acceptance examples

These are conditional deductions, not executed tests. Unless stated otherwise, assume accessible memory, representable arithmetic, stable relevant fields, nonaliasing locations, and dependencies that return normally without changing the stated example state.

### Zero count skips restoration, not final inspection

Given a nonzero argument and a count of zero after F-338d16f9ce72:

- F-bb50a072e902 is skipped.
- F-338d16f9ce72 receives the address at `0x28`.
- The count, restoration destinations, and marker are not directly written.
- Final pointer inspection still occurs.

A marker already equal to `1` is not cleared.

### Selector zero restores two bytes

Given count `2`, selector `0`, and record index `1` containing `0x12`, `0x34`, `0x56`:

- The count becomes `1`.
- `0x54` receives `0x12`.
- `0x55` receives `0x34`.
- `0x56` is not directly written.
- The marker becomes `1`.

The selected record is index `1`, because selection uses the decremented count.

### Selector one restores the third byte

Given count `1`, selector `1`, and record index `0` with third byte `0xa7`:

- The count becomes zero.
- `0x56` receives `0xa7`.
- `0x54` and `0x55` are not directly written.
- The marker becomes `1`.

### Unsupported selector still decrements

Given count `3` and stable selector `2`:

- The count becomes `2`.
- No record byte is read by the restoration branch.
- No restoration destination is directly written.
- The marker becomes `1`.

There is no rejection or compensating increment.

### Resolver result is used without a null-result guard

Given a zero argument and a valid address returned by F-bb50a072e902, subsequent object-relative operations use that address.

If the resolver returns zero, no local null-result exit protects the following dependency call and accesses. Normal completion is not guaranteed.

### Dispatch gates control the global-slot read

After the restoration stage:

| Pointer at `0x28` | First pointed-to 32-bit value | Required direct behavior |
|---|---|---|
| Zero | Not read | No global target-slot read or invocation |
| Nonzero | Zero | Pointee read; no global target-slot read or invocation |
| Nonzero | Nonzero | Read global target slot, then invoke its value |

A nonzero gate value is not itself used as the target.

If the selected global target is null, both gates still pass; no additional null-target guard is shown. Successful invocation cannot be promised.

### A dependency can change the selected global target

Suppose the global slot initially designates one target, and F-338d16f9ce72 changes it to another valid target. If both final gates subsequently pass and the slot remains stable, the later target is selected. No pre-dependency target snapshot is shown.

### Negative counts are not rejected

Given stable count `-1` and selector `0`, the count becomes `-2`. The first and second source offsets are then `0x5a` and `0x5b`.

This demonstrates unchecked negative indexing, not a valid-record guarantee.
