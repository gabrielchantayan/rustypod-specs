## Behavior

### 1. Initial object writes and first invocation

The function first stores the byte value one at B + `0x69`.

It next stores the byte value one at B + `0x6A`.

It then invokes **F-unmapped-01**, a locally assigned opaque dependency label, with three arguments in this order:

1. B;
2. the integer value four;
3. the integer value one.

Both byte writes precede this invocation. The write to B + `0x68` has not yet occurred.

The dependency may therefore observe the two newly written bytes, subject to its own behavior and the execution environment. This contract does not assume that the dependency leaves those bytes, other object fields, or shared data unchanged.

### 2. Third byte write and unconditional dependencies

If F-unmapped-01 returns normally, the function stores the byte value zero at B + `0x68`.

It then invokes F-da2d75c0df8d without explicit arguments.

After that dependency returns normally, it invokes F-338d16f9ce72 with R as its sole explicit argument.

These operations occur in that order. The function does not examine an explicit result from either invocation. Their side effects remain relevant to all later reads.

For example, the comparison field at B + `0x8C` is read after these dependencies have run. It is not an entry-time snapshot.

### 3. Conditional invocation based on the four-byte field

After F-338d16f9ce72 returns normally, the function reads the four-byte field at B + `0x8C` and compares it for equality with K.

If they are equal, it invokes F-77781c8e0ff9 with:

1. the four-byte value read from B + `0x94`;
2. A;
3. the address B + `0x6C`.

The four-byte read at B + `0x94` is conditional: it is not part of this function’s direct behavior when the comparison is unequal.

The source does not establish an externally meaningful order among the evaluations of these three argument expressions. It establishes that their values are supplied to the invocation after the comparison succeeds.

If the comparison is unequal, this invocation is skipped.

No return value from F-77781c8e0ff9 is inspected. No error branch is shown for it.

### 4. Unconditional replacement of the comparison field

After the comparison branch completes, the function writes T into the four bytes starting at B + `0x8C`.

This write happens whether the comparison was equal or unequal, provided execution reaches this point normally.

When F-77781c8e0ff9 is invoked, the replacement occurs after that dependency returns. Consequently, any change that dependency makes to the same four-byte field is overwritten by this function’s subsequent store.

The replacement is exactly four bytes. The source does not establish a larger copy, a terminator write, or a change to adjacent bytes.

The textual label attached to the static source value is insufficient to establish T’s numeric value, byte sequence, text encoding, or endianness-independent interpretation.

### 5. Shared-root traversal and optional indirect invocation

After writing T, the function dereferences R to obtain an address, called **P** in this contract.

If P is zero, it does not read through P and does not invoke J.

If P is nonzero, the function reads one four-byte integer from the address P. If that integer is zero, it does not invoke J. If that integer is nonzero, it invokes the target obtained through J.

The terminal decision therefore depends on two distinct conditions:

- the address obtained by dereferencing R is nonzero; and
- the four-byte value at that address is nonzero.

A nonzero address alone does not cause dispatch.

The indirect invocation has no explicit arguments in the supplied representation. Its real calling convention, implicit register inputs, and relationship to a possible tail transfer are unresolved.

If the indirect target returns normally, F-e9f23510bd57 returns. There are no further explicit object writes or dependency invocations in the supplied body.

## Acceptance examples

These are conditional static acceptance scenarios, not executed tests. They assume valid memory, compatible dependency interfaces, normal returns, and no unmentioned concurrent interference.

### Unequal comparison with a zero root result

Suppose the four-byte field read at B + `0x8C` differs from K, and dereferencing R later yields zero.

Accepted behavior:

- The three initial byte writes and the first three dependency invocations occur in the stated order.
- F-77781c8e0ff9 is skipped.
- This function does not directly read B + `0x94`.
- T is written to B + `0x8C`.
- No read through the zero address occurs.
- J is not invoked.

### Equal comparison with a nonzero sentinel

Suppose the comparison succeeds, dereferencing R later yields a valid nonzero address, and the four-byte integer at that address is negative.

Accepted behavior:

- F-77781c8e0ff9 receives the current four-byte value at B + `0x94`, A, and B + `0x6C`.
- T is written after that dependency returns.
- The negative integer qualifies as nonzero.
- J is invoked after the replacement write.

The terminal condition is not restricted to positive integers.

### Earlier dependencies change the comparison outcome

Suppose the field differs from K at entry, but an earlier dependency changes it so that it equals K when the comparison occurs.

Accepted behavior: F-77781c8e0ff9 is invoked.

Conversely, entry-time equality does not require that invocation if an earlier dependency changes the relevant state before the comparison.

### Conditional dependency changes the replacement field

Suppose F-77781c8e0ff9 writes another value to B + `0x8C` and then returns normally.

Accepted behavior: this function subsequently overwrites those four bytes with T. Whether T remains there at return depends on later indirect effects.

### Nonzero root result with a zero integer

Suppose dereferencing R yields a valid nonzero address whose four-byte integer is zero.

Accepted behavior: the integer is read, but J is not invoked.

### First dependency does not return

Suppose F-unmapped-01 does not return normally.

The established completed prefix consists of the writes at `0x69` and `0x6A`, followed by that invocation. This function provides no visible guarantee that the write at `0x68` or any later operation occurs.
