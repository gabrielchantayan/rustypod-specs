# F-cc12c7415348

## Purpose

F-cc12c7415348 conditionally rearranges fixed-width elements in an existing memory buffer. It supports elements selected by format values 16 and 32, transferring two and four bytes per element respectively. Other format values leave the buffer unchanged.

The operation is a sequence of in-place exchanges whose coordinates are determined by two signed extents and an element stride. When both extents describe the same positive square size, the resulting arrangement is a reflection across that square’s anti-diagonal. This geometric interpretation is inferred from the address relationships; the exchange sequence itself is the established behavior.

For unequal extents, the function does not implement a general rectangular reflection or rotation. In particular, the second extent limits which first-side elements participate, but does not bound all partner addresses.

The function returns no value and provides no explicit success or failure indication.

## Interface

### Input and object layout

The sole argument is an address identifying a caller-supplied object. The supplied representation uses 32-bit address and integer quantities.

The function accesses the following storage:

| Location | Width | Interpretation |
|---|---:|---|
| Input object, offset `0x1c` | 4 bytes | Address of a descriptor |
| Descriptor, offset `0x04` | 4 bytes | Buffer address |
| Descriptor, offset `0x08` | 4 bytes | Signed byte-pitch input |
| Descriptor, offset `0x0c` | 4 bytes | Format selector |
| Descriptor, offset `0x18` | 4 bytes | First extent’s lower endpoint |
| Descriptor, offset `0x1c` | 4 bytes | Second extent’s lower endpoint |
| Descriptor, offset `0x20` | 4 bytes | First extent’s upper endpoint |
| Descriptor, offset `0x24` | 4 bytes | Second extent’s upper endpoint |

The two uses of offset `0x1c` belong to different objects: one selects the descriptor, and the other contributes an extent endpoint.

Define the following descriptive quantities:

- **W**: first upper endpoint minus first lower endpoint.
- **H**: second upper endpoint minus second lower endpoint.
- **E**: element width in bytes, either 2 or 4.
- **P**: signed element stride obtained by dividing the byte-pitch input by E, rounding toward zero.
- **B**: the buffer address read from the descriptor.

Endpoint values affect only W and H. The lower endpoints are not separately added to the buffer address. Thus the operation is based at B, not at an independently calculated endpoint-relative origin.

### Preconditions for defined memory effects

The input object and descriptor must be readable at every accessed field. Neither address is checked for null before dereferencing it.

When exchanges occur, all resulting element addresses must designate readable and writable storage of the selected width. Alignment requirements depend on the target’s two-byte and four-byte access behavior; the function performs no alignment checks.

For the ordinary mathematical interpretation in this contract:

- Signed extent differences must be representable.
- Stride multiplication and address arithmetic must remain representable under the target’s arithmetic model.
- Descriptor values must remain stable while they are being collected.
- The buffer must not overlap descriptor storage in a way that invalidates the intended layout or subsequent accesses.

The function does not enforce these conditions.

### Output and ownership

There is no returned data object or status code. The output is the final content of the existing buffer.

No allocation, deallocation, ownership transfer, or explicit lifetime change appears in the supplied body. The function does not establish that any supplied address owns its storage.

## Behavior

### Entry and format selection

The observable control sequence begins as follows:

1. Read the descriptor address from the input object.
2. Read B from the descriptor.
3. If B is zero, return immediately.
4. Read the format selector.

The zero-buffer return precedes format, pitch, and extent processing. A zero buffer therefore suppresses accesses to those later fields, but does not make an invalid input-object or descriptor address safe.

If the first format read yields 16, the function selects two-byte elements.

Otherwise, it reads the format field again. If that second read yields 32, the function selects four-byte elements. Any other value on that second read causes return without buffer access.

Consequently, format selection is not a single snapshotted read on the non-16 path. With stable descriptor storage, the supported formats are exactly 16 and 32. If the field changes between reads, the branch is determined by the values actually observed: a first value other than 16 followed by 32 selects the four-byte path.

### Stride and extents

For the two-byte path, P is the signed byte-pitch input divided by two, rounding toward zero.

For the four-byte path, the supplied expression uses sign adjustment followed by an arithmetic right shift. With a stable pitch field, its result is signed division by four, rounding toward zero. The pitch field appears twice in that expression. Exact ordering of those reads is not established by the supplied representation.

A byte pitch need not be divisible by E. Any remainder is discarded. For example:

- A byte pitch of 7 gives a two-byte element stride of 3, so adjacent logical rows begin 6 bytes apart.
- A byte pitch of 7 gives a four-byte element stride of 1, so adjacent logical rows begin 4 bytes apart.
- A byte pitch of −7 gives strides of −3 and −1 respectively.

The effective row spacing is therefore E × P, not necessarily the original byte-pitch value.

The function computes W and H from their endpoint pairs. It then checks W. If W is less than one, it returns without element accesses.

There is no corresponding early-return check for H. When W is positive but H is zero or negative, the outer traversal still advances through W positions, but no element exchanges occur.

The arithmetic operands are represented as signed 32-bit integers. The supplied body does not establish a portable overflow policy for extent subtraction, multiplication, or address construction. Unrestricted mathematical integers must not be assumed.

### Exchange domain and order

For W greater than zero, the outer coordinate r advances in increasing order from 0 through W − 1.

At each r, the inner coordinate c advances in increasing order through all nonnegative values satisfying both:

- c < W − r
- c < H

If the smaller of W − r and H is nonpositive, that outer position has no exchanges.

For each participating coordinate, the function exchanges these two element locations:

| Location | Logical row | Logical column |
|---|---:|---:|
| First side | r | c |
| Partner side | W − c − 1 | W − r − 1 |

A logical element at row x and column y has byte address:

**B + E × (P × x + y)**

These coordinates describe address formation only. They do not assert that the caller’s actual allocation has those dimensions.

The outer coordinate is bounded by W, not H. Partner coordinates also derive from W. For positive H, both locations have logical row and column coordinates within 0 through W − 1, but the partner column is not generally less than H.

Therefore, a buffer sized merely as W rows of H elements is not necessarily sufficient. Every computed address must be valid independently of such a shape assumption.

### Per-exchange memory effects

Each exchange performs the following element accesses in order:

1. Read the first-side element.
2. Read the partner-side element.
3. Write the value from the partner read to the first-side address.
4. Write the value from the first read to the partner-side address.

Each transfer is exactly E bytes in the supplied representation. The values are treated as opaque bit patterns; there is no channel interpretation, numeric conversion, byte rearrangement within an element, or comparison of element values.

Address-calculation details and updates of traversal counters do not change this element-access order.

When both locations are identical, the function still performs the reads and writes. Such self-exchanges occur along the anti-diagonal where r + c = W − 1, provided the second-extent limit admits that coordinate.

No atomicity, locking, or synchronization is established. The access sequence must not be treated as an atomic exchange.

### Result under ordinary non-overlapping storage

If H is at least W, the second extent does not restrict the traversal. The exchange domain is the triangular region r + c < W. Its non-diagonal coordinates exchange with coordinates on the opposite side of the anti-diagonal; anti-diagonal coordinates exchange with themselves.

For an ordinary W-by-W layout with distinct element locations, the final mapping is:

**Output at row r, column c equals input at row W − c − 1, column W − r − 1.**

This result is an anti-diagonal reflection, not a clockwise or counterclockwise quarter-turn.

If 0 < H < W, only part of that exchange domain is processed. The result is a partial rearrangement, potentially touching partner elements outside the first H columns.

If stride choices cause rows to overlap, or different logical coordinates to share physical storage, the ordered exchange sequence remains the governing description. The square-reflection result must not be assumed in that case.

## Side effects

The function can write only through the computed buffer-element addresses in its explicit body. It has no explicit descriptor-field or input-object-field writes.

That distinction is about access paths, not guaranteed storage separation. If the buffer aliases the descriptor or input object, buffer writes can modify those objects physically. No alias check prevents this.

There are no explicit calls, allocations, frees, I/O operations, callbacks, or global-variable accesses in the supplied body.

Potential invalid-memory access, alignment failure, arithmetic failure, or externally observable memory behavior is not converted into a documented error result. There is no rollback or recovery path. A failure during an exchange or after earlier exchanges can leave storage partially modified.

For memory-mapped or concurrently observed storage, even a self-exchange can be observable because it still performs reads and writes. The source representation does not establish volatile semantics or the exact machine-instruction access sequence.

## Acceptance examples

These are conditional acceptance criteria derived from static evidence, not results of executed tests. Unless stated otherwise, descriptor fields are stable, arithmetic is representable, and all accessed storage is valid and non-overlapping.

### Zero buffer

Given a readable input object and descriptor whose buffer field is zero, the function returns without reading the format, pitch, or extent fields and without accessing element storage.

### Unsupported format

Given a nonzero buffer and a stable format value other than 16 or 32, the function returns without reading pitch or extent fields and without accessing elements.

A format of 16 is selected on the first format read. A stable format of 32 is selected after the second format read.

### Nonpositive first extent

Given either supported format and W equal to zero or a negative representable value, the function performs no element reads or writes. Pitch and extent processing precedes this decision.

### Nonpositive second extent

Given W = 3 and H = 0, no elements are accessed. The same absence of element accesses applies to negative H, although the outer traversal still progresses.

### Three-by-three square

Given W = H = 3, element stride P = 3, and initial rows:

| Row | Column 0 | Column 1 | Column 2 |
|---|---|---|---|
| 0 | A | B | C |
| 1 | D | E | F |
| 2 | G | H | I |

The final rows are:

| Row | Column 0 | Column 1 | Column 2 |
|---|---|---|---|
| 0 | I | F | C |
| 1 | H | E | B |
| 2 | G | D | A |

The traversal performs exchanges in this coordinate order:

1. (0, 0) with (2, 2).
2. (0, 1) with (1, 2).
3. (0, 2) with itself.
4. (1, 0) with (2, 1).
5. (1, 1) with itself.
6. (2, 0) with itself.

The example applies to either supported element width, with each letter representing one whole element.

### Restricted second extent

Given W = 2, H = 1, P = 2, and initial rows [A, B] and [C, D], the final rows are [D, B] and [C, A].

The operation exchanges (0, 0) with (1, 1), then self-exchanges (1, 0). This demonstrates that H = 1 does not restrict all accesses to column zero.

### Second extent larger than the first

Given W = 2 and H = 5, the same exchange domain is used as for W = H = 2. H does not enlarge the domain beyond the limit imposed by W − r.

### Single element

Given W = 1 and H ≥ 1, the function reads the element at B twice and writes it twice as a self-exchange. Its ordinary stored value is unchanged.
