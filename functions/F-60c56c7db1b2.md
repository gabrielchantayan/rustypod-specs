# F-60c56c7db1b2

## Purpose

F-60c56c7db1b2 searches a dependency-provided sequence for an entry whose stored 32-bit value equals a selection value held in a caller-supplied object. On a match, it returns the supplied integer adjusted downward for certain preceding entries. If no match is returned, it returns −1.

The adjustment depends on a byte reached indirectly through each preceding, nonmatching entry. A nonzero byte causes one decrement; a zero byte causes none. The matching entry’s byte is not inspected and does not contribute a decrement.

An inferred purpose is to translate a position or rank while excluding marked predecessors. That interpretation is not established: the meanings of the selection, initial integer, and marker byte are unknown. The contract below describes their observable use without assigning domain semantics.

## Interface

### Inputs

The function takes two values:

- **Object address:** a value used as the base address of an externally supplied object.
- **Initial result:** an integer carried through the search and returned, potentially decremented, when a matching entry is found.

The supplied representation uses 32-bit integer and address-bearing fields. Its loop comparisons are signed. The index passed to the entry-access dependency is narrowed to a signed 16-bit value and then promoted back to the dependency’s integer argument width.

The following object-relative fields are accessed:

| Offset | Width | Use |
|---|---:|---|
| 0x18 | 4 bytes | Argument supplied to both sequence dependencies |
| 0x1c | 4 bytes | Initial search gate and subsequently re-read match value |

Each entry-access result is used as an address with this layout:

| Offset | Width | Use |
|---|---:|---|
| 0x08 | 4 bytes | Value compared with the object’s current selection; on mismatch, re-read and used as an address |

For every nonmatching entry, the function reads one byte at decimal offset 100, equivalently 0x64, from the address obtained through the entry’s offset-0x08 field.

These are accessed offsets, not complete structure definitions. No significance is established for intervening bytes.

### Output

The nominal return width is 32 bits.

- On a match, the function returns the current result value.
- Otherwise, it returns −1.

A return of −1 does not uniquely identify failure: a successful match may also return −1 if the initial value or preceding decrements produce that value. There is no separate success indicator.

### Preconditions

Normal completion requires that every address actually accessed be valid for the corresponding read and that both dependencies return normally.

In particular:

- The object’s offset-0x18 field must be readable before any selection-based shortcut is possible.
- The object’s offset-0x1c field must be readable after the count dependency returns.
- Every entry address returned during a reached iteration must support a four-byte read at offset 0x08.
- Following a mismatch, the re-read value at entry offset 0x08 must support a byte read at offset 0x64.

The function performs no visible null checks or address validation. An input violating these requirements has no established ordinary return behavior.

## Behavior

### Initial dependency call and search gate

The first established external operation is a four-byte read from object offset 0x18. That value is passed to F-d0b90560f1fd.

The dependency’s returned integer becomes the fixed signed upper bound for this invocation’s search. The function does not refresh that bound later.

Only after this dependency returns does the function read object offset 0x1c:

- If this selection value is zero, the function returns −1 without requesting any entry.
- If it is nonzero, the function considers entries using a logical index beginning at zero.

Consequently, a zero selection does not bypass the count dependency. Mutations made by that dependency can affect the selection used by the gate.

A nonpositive bound permits no entry-access calls. With either a zero selection or a nonpositive bound, the initial result does not become the return value.

### Entry access and index width

For each iteration whose logical index is less than the saved signed bound, the function:

- Re-reads the four-byte value at object offset 0x18.
- Supplies that newly read value to F-0ff4e60503e7.
- Supplies an index obtained by narrowing the logical index to signed 16 bits and promoting it to an integer.

The full-width logical index controls termination. The narrowed index controls which argument the entry-access dependency receives. These are not interchangeable.

Under the conventional two’s-complement interpretation of the displayed narrowing operation:

- Logical indices 0 through 32,767 are passed unchanged.
- Logical index 32,768 is passed as −32,768.
- Logical index 65,535 is passed as −1.
- Logical index 65,536 is passed as zero.

Thus a sufficiently large bound can cause negative or repeated dependency indices. There is no visible range check limiting the bound to the nonnegative signed-16-bit range. The precise out-of-range narrowing semantics remain subject to the representation limitation documented under Uncertainties.

### Match decision

After F-0ff4e60503e7 returns an entry address, the function compares:

- The current four-byte selection at object offset 0x1c.
- The four-byte value at entry offset 0x08.

The selection is re-read for each comparison. It is not a saved copy of the initial gate value. Changes made by either dependency can therefore affect subsequent matching.

The relative evaluation order of the two reads within this equality comparison is not established by the supplied representation. Both belong to the comparison following the entry-access call.

If the values are equal, the function immediately returns the current result. It does not read the marker byte for that entry, request further entries, or perform a decrement for the matching entry.

The gate’s earlier nonzero result does not impose a continuing nonzero-selection requirement. If the selection later becomes zero, zero may match a zero value at entry offset 0x08. Such a match returns before using that zero as an address.

### Mismatch processing

If the values differ, the logical index advances by one. The function then re-reads the four-byte value at entry offset 0x08, uses it as an address, and reads one byte at offset 0x64.

The second read of entry offset 0x08 is distinct from the read used in the equality comparison. The contract does not replace it with a cached value or assume that both reads must observe the same contents.

The marker byte affects the result as follows:

- Zero: leave the current result unchanged.
- Any nonzero byte: decrement the current result by one.

Only zero versus nonzero matters. No interpretation as a Boolean encoding, signed quantity, or particular flag bit is established.

This mismatch processing occurs even for the final entry allowed by the bound. The function does not first determine that another iteration will be needed. Therefore, an invalid marker address on the final nonmatching entry can prevent normal completion even though the search would otherwise be exhausted.

After marker processing, the next iteration is considered using the incremented logical index and the original saved bound.

### Exhaustion and arithmetic

If no iteration returns on equality, the function returns −1. Any accumulated result adjustment is discarded as a return value on this path.

For executions in which subtraction remains representable, a successful return equals the initial result minus the number of nonzero marker bytes observed on preceding nonmatching iterations.

The loop index itself does not need to overflow to exhaust a positive signed 32-bit bound. Starting from zero, it advances at most to that bound. Result subtraction is different: an initial result at the minimum signed value can underflow on the first decrement. The supplied representation establishes no guard, saturation, or explicit error response for that case.

## Side effects

The visible function body contains no explicit writes to the object, entries, or marker-bearing storage. Its direct operations are reads, dependency calls, local arithmetic, and return.

That does not establish global purity:

- F-d0b90560f1fd is always called on the ordinary entry path.
- F-0ff4e60503e7 is called once per reached iteration.
- Either dependency may change reachable storage or other external state.
- The function deliberately re-reads several fields after dependency calls.
- Reads may have observable effects if the underlying storage is device-backed or otherwise read-sensitive.

No allocation, release, ownership transfer, reference-count operation, or retention of a returned entry is explicit in this body. The dependencies’ ownership behavior is unknown. Their calls must not be treated as preserving globals, object fields, or storage lifetimes without a separate contract.

If a dependency fails to return normally, or an access faults, no successful-match or exhausted-search return is established. Operations completed before that interruption are not rolled back by any visible mechanism.

## Acceptance examples

These examples are conditional: all reached accesses are valid, dependencies return normally, and values remain stable except where a change is explicitly stated. Arithmetic examples avoid signed overflow.

1. **Zero selection still invokes the count dependency.**  
   F-d0b90560f1fd returns 5, after which the selection is zero. The result is −1. No entry-access call occurs.

2. **A nonpositive bound yields no entry request.**  
   The selection is nonzero, but the saved bound is zero or negative. The result is −1, regardless of the initial result.

3. **The first entry matches.**  
   The bound is positive, the first retrieved entry’s offset-0x08 value equals the current selection, and the initial result is 12. The return is 12. That entry’s marker address need not be dereferenceable because no marker read is reached.

4. **Only nonzero predecessor markers reduce a successful result.**  
   With initial result 12, the first three entries mismatch and expose marker bytes 0, 7, and 255. The fourth entry matches. The return is 10. The fourth entry’s marker is not read.

5. **Exhaustion discards the adjusted value.**  
   With bound 2 and initial result 12, both entries mismatch and both marker bytes are nonzero. The return is −1, not 10.

6. **The final mismatch still requires a marker read.**  
   With bound 1, the only entry mismatches. The function accesses its marker byte before exhausting the search. An unreadable marker address is not avoided merely because no further entry can be searched.

7. **A later zero selection can match.**  
   The initial gate observes a nonzero selection. During the first entry-access call, the selection changes to zero, and the returned entry’s offset-0x08 value is zero. The function returns the current result without attempting a marker read through address zero.

8. **The sequence argument is not cached across calls.**  
   The count dependency receives one value from object offset 0x18 and changes that field before returning. The first entry-access call receives the replacement value.

9. **Large logical indices expose signed narrowing.**  
   If a bound above 32,768 is reached without an earlier match or failure, the entry request for logical index 32,768 receives −32,768 under conventional two’s-complement narrowing. A contract requiring only nonnegative entry indices would therefore need an additional precondition not enforced here.

10. **Success can be indistinguishable from failure by return value alone.**  
    With initial result zero, one nonmatching entry has a nonzero marker and the following entry matches. The successful return is −1.
