# F-de70a5256fd2

## Purpose

F-de70a5256fd2 interprets a sequence of four-byte descriptors against an input cursor held in a context object. Descriptors can:

- Decode one, two, three, or four input bytes into an integer and store that integer at a destination-relative address.
- Advance the input cursor without decoding a value.
- Advance the input cursor and invoke an external dependency with a destination-relative address.
- Invoke a context operation with a 16-bit descriptor operand.
- Terminate interpretation.

The established behavior is a cursor-driven descriptor interpreter. The semantic meanings of the context operation and external callback are unknown. In particular, the evidence does not establish that either dependency allocates, releases, copies, or validates memory.

This contract describes static evidence only. No runtime tests have been performed.

## Interface

### Inputs

The function accepts three machine-level arguments:

| Argument | Established use |
|---|---|
| Context address | Addresses a structure containing an input cursor at byte offset `0x20` and a comparison limit at byte offset `0x24`. Also passed to two dependencies. |
| Descriptor address | Addresses the first four-byte descriptor. Successive descriptors begin four bytes apart. |
| Destination base | Added to an unsigned 16-bit descriptor operand to form an address for a value store or external call. |

The supplied representation uses 32-bit integer values and address arithmetic. Native pointer representation, native byte order, and alignment requirements remain properties of the execution environment; they are not defined independently by this function.

### Context layout

Only these context fields are directly identified:

| Byte offset | Field |
|---|---|
| `0x20` | Input cursor pointer, initially read and later conditionally written or reloaded. |
| `0x24` | Input limit pointer, read by cursor-advance descriptors. |

These offsets do not establish the full size or ownership of the context.

### Descriptor layout

Each descriptor occupies four bytes:

| Byte offset | Meaning |
|---|---|
| `0` | Operation tag. |
| `1` | Output storage selector for decoding operations; unsigned byte count for cursor-advance operations. |
| `2–3` | Native-order unsigned 16-bit operand. Used as a destination-relative offset or passed to a dependency, depending on the tag. |

The 16-bit operand is a native 16-bit access, not an explicitly big-endian or little-endian decoding operation. It is distinct from the explicit byte-order conversions performed on input data.

### Return value

The function returns an integer status:

- `6` on the explicit null-argument rejection path, provided execution reaches that check.
- `0` on ordinary termination without a preceding nonzero dependency result or cursor-advance error.
- The nonzero result returned by F-d036abe1e536 when that dependency fails.
- `0x55` when a cursor-advance descriptor produces a cursor greater than the context limit.

The return value of the external dependency used by tag `0x18`, if any, is not used. The return value of F-9787e15c337d is also not used.

### Preconditions

For defined, successful execution, the caller must provide:

- A context readable at offset `0x20` before relying on the explicit argument checks.
- Readable descriptor memory through a terminating descriptor or an earlier exit.
- Sufficient readable input memory for each decoding operation.
- Writable destination memory of the width selected by each decoding descriptor.
- Valid native 16-bit operand accesses and native-width output stores for the target environment.
- Pointer arithmetic and comparisons meaningful for the referenced memory regions.

There is no descriptor-count argument, source-length argument, destination-capacity argument, or iteration limit.

## Behavior

### Entry and working state

The function first loads the input cursor from context offset `0x20`. Only afterward does it reject a null context address or null descriptor address.

Consequently, the explicit null-context check does **not** establish safe handling of a null context: the preceding context read can already fail. A null descriptor address with an otherwise readable context takes the status-`6` path after that initial cursor read.

For accepted nonnull arguments, the function initializes its status to zero and records that no successful F-d036abe1e536 operation has yet occurred.

The interpreter maintains a local working input cursor. Ordinary decoding and cursor-advance operations update this local cursor, not the context cursor field. The distinction determines what remains visible after errors.

### Descriptor dispatch and termination

The operation byte is read at the start of each iteration.

Recognized tags are:

- `0x04`
- `0x08` through `0x19`, inclusive

Every other tag terminates interpretation. This includes `0x05`, `0x06`, `0x07`, `0x0A`, and `0x0B`, which explicitly follow the termination path.

On this ordinary termination path, the function:

1. Stores the local working input cursor into context offset `0x20`.
2. Calls F-9787e15c337d with the context address if at least one earlier F-d036abe1e536 call returned zero.
3. Returns the current status.

The terminating descriptor does not consume input, produce an output store, or advance to another descriptor.

After each successfully completed nonterminating descriptor, the descriptor address advances by four bytes. Interpretation then reads the next operation byte.

### Integer-decoding operations

The following table defines input consumption and value interpretation:

| Tag | Input bytes | Input byte order | Value interpretation |
|---|---:|---|---|
| `0x08` | 1 | Not applicable | Unsigned 8-bit |
| `0x09` | 1 | Not applicable | Signed 8-bit |
| `0x0C` | 2 | Big-endian | Unsigned 16-bit |
| `0x0D` | 2 | Big-endian | Signed 16-bit |
| `0x0E` | 2 | Little-endian | Unsigned 16-bit |
| `0x0F` | 2 | Little-endian | Signed 16-bit |
| `0x10` | 4 | Big-endian | Full 32-bit pattern |
| `0x11` | 4 | Big-endian | Full 32-bit pattern |
| `0x12` | 4 | Little-endian | Full 32-bit pattern |
| `0x13` | 4 | Little-endian | Full 32-bit pattern |
| `0x14` | 3 | Big-endian | Unsigned 24-bit |
| `0x15` | 3 | Big-endian | Signed 24-bit |
| `0x16` | 3 | Little-endian | Unsigned 24-bit |
| `0x17` | 3 | Little-endian | Signed 24-bit |

For widths below 32 bits, odd-numbered tags sign-extend the decoded value to 32 bits. Even-numbered tags zero-extend it. For four-byte input, the odd-tag transformation has a zero shift count, so paired signed and unsigned tags retain the same 32-bit pattern.

The input width is determined exclusively by the operation tag. Descriptor byte `1` does not change how much input is consumed.

After input bytes have been read and the local cursor has advanced, the function loads the unsigned 16-bit descriptor operand and adds it to the destination base. It then reads descriptor byte `1` to choose the store width:

| Descriptor byte `1` | Store |
|---|---|
| `1` | Low 8 bits |
| `2` | Low 16 bits |
| Any other value | Full 32 bits |

Thus `0`, `3`, and values above `4` all select a four-byte store. There is no rejection of an unusual selector.

Two-byte and four-byte stores use native memory representation. Explicit input byte order does not imply the same output byte order.

No context-limit check precedes these input reads. A decode can read beyond the limit stored at offset `0x24`; that field is not consulted by decoding operations.

### Cursor-advance operations

Tags `0x18` and `0x19` both:

1. Read descriptor byte `1` as an unsigned count from `0` through `255`.
2. Add that count to the local working input cursor.
3. Read the context limit at offset `0x24`.
4. Compare the resulting cursor with that limit.

Equality is accepted.

If the resulting cursor is greater than the limit, the function sets status `0x55` and takes the error exit described below. The attempted advance is not committed to the context cursor by this path.

If the resulting cursor is at or below the limit:

- Tag `0x19` continues to the next descriptor without an external call.
- Tag `0x18` loads the unsigned 16-bit operand, adds it to the destination base, and passes the resulting address to an external dependency.

The operand is not needed on the rejected advance path. Tag `0x19` does not use it at all.

Neither operation reads the skipped input bytes. A zero count still performs the limit comparison, and tag `0x18` still invokes the external dependency if that comparison succeeds.

No explicit overflow check accompanies cursor advancement or destination-address addition.

### Context operation: tag `0x04`

Tag `0x04` loads the native unsigned 16-bit operand and calls F-d036abe1e536 with:

- The context address.
- That operand.

Descriptor byte `1` is not used by this operation.

If the dependency returns zero:

1. The function reloads the local input cursor from context offset `0x20`.
2. It records that a successful context operation has occurred.
3. It advances to the next descriptor.

This reload replaces any previous local cursor, including advances not yet committed to the context field.

If the dependency returns nonzero:

1. That result becomes the function’s return status.
2. Interpretation stops immediately.
3. The local cursor is not written to context offset `0x20` by this exit path.
4. F-9787e15c337d is called only if an earlier F-d036abe1e536 call in this invocation succeeded.

A first failing call does not itself enable that final dependency call. An earlier success continues to enable it even if a later call fails.

### Error exits and final dependency call

Both a failed cursor advance and a nonzero F-d036abe1e536 result bypass the normal cursor writeback.

They nevertheless invoke F-9787e15c337d if any preceding context operation succeeded. That dependency receives the context state as it exists at the time of the call, including any modifications made by dependencies. The caller must not assume that it receives the local working cursor.

The saved status is returned without incorporating the final dependency’s return value.

## Side effects

### Direct memory effects

The function directly:

- Reads the initial context cursor before validating arguments.
- Reads descriptor operation bytes and operation-specific fields.
- Reads input bytes for decoding operations.
- Writes one, two, or four bytes per decoding descriptor.
- Writes the context cursor only on ordinary descriptor termination.
- Reloads the context cursor after a successful F-d036abe1e536 call.
- Reads the context limit for cursor-advance descriptors.

Earlier output writes are not rolled back if a later descriptor fails.

### Ordering and aliasing

The operation byte is captured before the selected operation executes. Later descriptor fields are read when needed; the function does not snapshot the entire descriptor.

For decoding operations, input reads precede the destination store. The destination operand is loaded before the output-width selector is consulted. For two-byte input operations, the established read sequence accesses input offset `1` before input offset `0` for big-endian decoding, and offset `0` before offset `1` for little-endian decoding. For larger multi-byte expressions, the evidence establishes which bytes contribute, but not a portable total ordering among all byte reads.

Source, descriptors, destinations, and context are not checked for overlap. Consequently:

- A destination store can alter later descriptors or unread input.
- A destination store can modify context fields.
- The normal final cursor write can overwrite an overlapping prior destination write.
- A successful context operation can replace the cursor used for subsequent decoding.

External calls may also modify reachable memory. The function does not save and restore arbitrary context fields or globals around them. In particular, the external call for tag `0x18` does not trigger a cursor reload.

### Ownership

No direct allocation or release operation is established. Passing an address to a dependency does not establish ownership transfer, retention, or lifetime extension.

## Acceptance examples

These examples are static, conditional expectations—not observed test results. Unless otherwise stated, memory is valid, addresses do not overflow, regions do not overlap, dependencies return normally, and a terminating descriptor follows.

1. **Unsigned one-byte decode.** With tag `0x08`, input byte `FE`, and storage selector `4`, the function stores the 32-bit value `0x000000FE`. The committed cursor advances by one byte.

2. **Signed one-byte decode.** With tag `0x09`, input byte `FE`, and storage selector `4`, the stored 32-bit pattern is `0xFFFFFFFE`.

3. **Input width differs from output width.** With tag `0x0C`, input bytes `12 34`, and storage selector `1`, the function consumes two bytes but stores only `0x34`.

4. **Signed little-endian input.** With tag `0x0F`, input bytes `00 80`, and storage selector `4`, the stored pattern is `0xFFFF8000`.

5. **Signed 24-bit input.** With tag `0x15`, input bytes `80 00 01`, and storage selector `4`, the stored pattern is `0xFF800001`. Tag `0x14` with the same bytes stores `0x00800001`.

6. **Unexpected storage selector.** With tag `0x08`, input byte `7F`, and storage selector `0`, the function performs a four-byte store of `0x0000007F`; it does not perform a zero-byte store.

7. **Advance exactly to limit.** If a tag-`0x19` advance lands exactly on the context limit, interpretation continues. A following terminator commits that cursor.

8. **Advance beyond limit after output.** If a decode succeeds and a following cursor advance exceeds the limit, the function returns `0x55`. The earlier output remains written, but the function does not commit its local cursor on that error exit.

9. **Successful context operation followed by termination.** If F-d036abe1e536 returns zero and changes the context cursor, subsequent interpretation uses that changed cursor. Termination writes back the working cursor before calling F-9787e15c337d.

10. **First context operation fails.** If the first F-d036abe1e536 call returns `17`, the function returns `17`, does not directly write back the local cursor, and does not invoke F-9787e15c337d.

11. **Success followed by failure.** If one context operation succeeds and a later one returns `17`, the function calls F-9787e15c337d and returns `17`, without normal cursor writeback.

12. **Unrecognized initial tag.** With a valid context and a first descriptor tagged `0xFF`, the function writes the initially loaded cursor back to the context and returns zero.

## Uncertainties

Descriptor stride, operation dispatch, explicit endian conversions, truncation widths, sign extension, status selection, cursor writeback paths, and dependency-call conditions are directly supported by the supplied representation.

### Inferred intent

The context fields appear to represent an input cursor and limit. The descriptor operand appears to identify destination-relative storage for decoding operations. These interpretations explain usage but do not establish allocation boundaries or ownership.

### documented_only

The following remain undocumented:

- Whether dependencies preserve globals, retain addresses, or release memory.
- External-call failure reporting beyond the explicitly inspected result of F-d036abe1e536.
- A required terminator value beyond the established set of terminating tags.

No bounds validation or ownership guarantee may be inferred from these unknowns.
