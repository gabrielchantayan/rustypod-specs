# F-946a6e6c5697

## Purpose

F-946a6e6c5697 is an externally state-dependent operation that interleaves indirect calls with byte, halfword, and word stores. Its visible effects include propagating opaque values, deriving addresses from shifted words, updating a shared four-byte location, and finally attempting an indirect call through address zero.

No application-level purpose is established. In particular, the supplied material does not establish that this operation initializes an object, implements a supervisor service, manages a collection, or releases resources.

This contract describes the visible access sequence and data dependencies. It does not treat suggestive storage names or apparent calling conventions as proof of meaning.

## Interface

**Explicit input:** one opaque 32-bit value. The first indirect call receives this value. No later direct use of the explicit input is shown.

**Additional execution inputs:**

- An incoming link-related value used to derive the first call target.
- An incoming base-like value used for the first byte store and an early word read.
- An incoming 32-bit payload used in two early word stores.
- Several secondary call-result values not represented as ordinary return values.
- Shared memory, including a word read twice at separate times, a four-byte destination written twice, a three-byte source used near completion, and the byte at address 1.
- All ordinary results, secondary results, and side effects of the indirect dependencies.

These are execution-state requirements, not a complete public calling convention. Their initialization and ownership are unknown.

**Output:** no explicit return value is exposed. A return is shown after the final call, but successful completion depends on that call returning.

**Access widths:**

| Kind | Width |
|---|---:|
| Byte reads and writes | 8 bits |
| Final clearing store | 16 bits |
| Word reads, writes, and most opaque values | 32 bits |
| Selected compound call results | 64 bits, consumed as two 32-bit halves |

A byte store retains the low eight bits of its source. A compound result’s low and high halves are selected numerically; this does not establish memory endianness.

**Preconditions for normal progress:** every reached indirect target must be executable under the actual platform rules; every reached memory access must be permitted at its width; and every required dependency must return. No local validation establishes these conditions.

## Behavior

### Interpretation and ordering rules

The following notation describes address calculations, not a recovered object model:

- A **four-scaled slot** for a value is its value multiplied by four, followed by addition of `0x14`.
- A **sixteen-scaled slot** is its value multiplied by sixteen, followed by addition of `0x14`.
- A **byte-selected destination** is formed by reading an unsigned byte at a specified address and adding `0x11` to that byte’s value.
- **Shared source word** denotes the same shared word location read on two separate occasions.
- **Shared result word** denotes the four-byte location written in the middle and at the end.

Multiplication, shifts, and address addition are represented using 32-bit operands in the supplied material. Unsigned right shifts discard low bits and introduce zero bits. Left shifts and scaling can discard high bits under a 32-bit machine interpretation. Exact overflow behavior for expressions represented with signed operands is documented_only; neither mathematical unbounded arithmetic nor checked overflow is established.

Execution is straight-line at this level: no local conditional branch, loop, retry, bounds check, or status check is shown. Every later event is conditional on earlier calls and accesses completing.

Indirect calls occur between many accesses listed below. They are ordering boundaries, not implied no-ops. A dependency can modify memory before a later read; a previously captured value and a fresh read must therefore remain distinct.

### 1. Initial calls and first stores

Five indirect calls occur first. Only the first has an explicit argument: the public 32-bit input. The fifth supplies a compound 64-bit result.

The operation then:

1. Writes the low byte of the incoming base-like value at that value plus 9.
2. Reads a 32-bit word at the incoming base-like value plus `0x34`.
3. Calls a dependency with the low half of the compound result shifted left two bits, its high half, and the word just read.

After another sequence of calls, a secondary result selects an address. The incoming payload is written to its four-scaled slot. A word is then read at the unscaled secondary result plus `0x14`. Call this captured word the **first lookup word**.

The distinction between those addresses is material: the store scales the selector by four; the following read does not.

Further calls include one receiving that selector, a result-forwarding call pair, and a call returning another selector. The incoming payload is written again, this time to the new selector’s four-scaled slot.

Next, a word is read at:

- the first lookup word shifted right 22 bits;
- plus `0x14`.

Call this the **second lookup word**. A dependency then receives the second store’s selector multiplied by four.

### 2. Shifted lookup propagation

After further calls, a returned 32-bit value is shifted left two bits to form a **scaled payload**.

The operation:

1. Writes the scaled payload to the four-scaled slot selected by the second lookup word shifted right one bit.
2. Reads a word at the original, unshifted second lookup word plus `0x14`.
3. Calls a dependency with the right-shifted selector.

Call the new read the **third lookup word**.

Following more calls, the same scaled payload is written to a slot selected by a newly returned value. The shared source word is then read and captured as the **early shared snapshot**. A dependency receives that most recent selector multiplied by four.

After another call sequence:

- the third lookup word is shifted right 22 bits, producing a value in the range 0–1023;
- the early shared snapshot is shifted right 23 bits, producing a value in the range 0–511;
- the first of these values is stored at a slot selected by another secondary result.

A four-argument dependency receives that selector twice, followed by the shifted shared snapshot and shifted third lookup word.

More calls follow, including a result-forwarding pair. The shifted third lookup word is then stored at another returned selector’s four-scaled slot.

The shifted shared snapshot is itself shifted right 23 bits. Because it was already at most 511, this second shift produces zero.

### 3. Zero stores and low-address byte writes

After further calls, zero is written to a slot selected by an unsigned secondary result. A dependency receives that selector.

A later returned selector chooses another slot, which also receives zero: its source is the early shared snapshot after two successive 23-bit right shifts.

The operation then reads a word at:

- the earlier unsigned secondary result masked with `0x1fffffff`;
- shifted right 19 bits;
- plus `0x14`.

Call this the **masked lookup word**. The offset before addition is at most 1023; the access is not visibly scaled or aligned.

After intervening calls, the masked lookup word is shifted right 22 bits, yielding 0–1023.

The next byte store has an unusual, established dependency:

1. Read a byte at address 1, because the twice-shifted shared snapshot is zero.
2. Add `0x11` to that byte’s unsigned value.
3. Store the low byte of the shifted masked lookup word there.

The destination consequently lies between `0x11` and `0x110`, inclusive, if the preceding access succeeds.

A dependency receives a secondary result three times and zero as its fourth argument. Subsequent calls include one explicitly receiving zero.

Another byte is then read at four times the shifted masked lookup word plus 1. Its value selects a byte destination by addition of `0x11`; zero is stored there.

### 4. Repeated clearing and shared-result publication

Additional calls pass a shifted return value once and later pass another shifted return value twice. A subsequent call produces a new 32-bit value, which is forwarded to a dependency.

The operation then:

1. Reads the byte at address 1.
2. Writes zero at that byte’s value plus `0x11`.
3. Captures a secondary result for later shifted arguments.
4. Calls a dependency with that secondary result repeated three times.

A later result-forwarding call receives both an opaque result and the previously captured 32-bit value shifted right 23 bits.

After more calls, the byte at address 1 is read again. This is a fresh read, not reuse of the previous byte. Its value is captured as the **retained small base**, and zero is written at that base plus `0x11`.

Further calls again use a shifted value once and another shifted value twice. A returned word is then written to the shared result word before being passed to a dependency. This is the first visible write to that shared location.

### 5. Byte copies from word fields

Following another call, the operation reads a word at the retained small base plus `0x74` and writes its low byte at that base plus 1. The base remains the earlier captured byte even though intervening calls may have changed memory at address 1.

A dependency receives the retained secondary result shifted left 11 bits.

A later compound result is split into low and high halves. Both halves, plus the word previously written to the shared result word shifted right 23 bits, are passed to another dependency.

A subsequent returned selector is multiplied by four to form a **retained scaled base**. The operation reads a word at that base plus `0x74` and writes its low byte at that base plus 1.

After additional calls, another returned selector is shifted left two bits to form a **retained scaled index**. The word-to-byte copy at the retained scaled base is then repeated using a fresh word read. This second copy cannot be replaced by reuse of the previous read without assumptions about intervening callees.

A four-argument dependency receives:

- the retained secondary result shifted left 12 bits;
- the retained scaled index twice;
- the latest unscaled selector shifted left 18 bits.

Several result-forwarding calls follow.

### 6. Word propagation and later pointer-like stores

Another returned selector is multiplied by four. A word at that base plus `0x74` is captured as the **retained payload word**, and its low byte is written at that base plus 1.

After further calls:

1. The retained payload word is written to a sixteen-scaled slot selected by a returned value.
2. A dependency receives the retained scaled index logically shifted right two bits and then shifted left 16 bits.
3. Additional result-forwarding calls occur.
4. The retained payload word is written to a four-scaled slot selected by another return value.

The right shift in step 2 does not restore high bits lost when the retained scaled index was originally formed.

A later returned selector is shifted left two bits. That shifted value is written at the retained scaled index masked with `0xfffffffc`, plus `0x14`. Because the index was formed by a two-bit left shift, its low two bits are already zero under the 32-bit interpretation.

A dependency receives the newly shifted value twice. Following more calls, zero is written to another returned selector’s four-scaled slot.

A compound result then provides:

- a low half, shifted left two bits to form a **final scaled payload**;
- a high half, used as a selector.

The final scaled payload is written to the high half’s four-scaled slot. The shared source word is read again, creating a **late shared snapshot**, before a four-argument call receives the final scaled payload, the high half, and the final scaled payload twice more.

After additional calls, the final scaled payload is written to another returned selector’s four-scaled slot. A word is then read at the late shared snapshot plus `0x14`. Call it the **final lookup word**.

### 7. Final byte writes, clears, and terminal call

A subsequent compound result supplies a low half retained as the **final address source** and a high half used in a call.

Before that call, the operation:

1. Reads a byte at the retained payload word shifted right 23 bits, plus 1.
2. Uses that byte plus `0x11` as a destination.
3. Stores the low byte of the final lookup word there.

The following dependency receives the compound result’s high half three times and its low half shifted left two bits.

After another call sequence, a second byte-selected write occurs:

- read a byte at the final address source masked with `0x3fffffff`, shifted right 21 bits, plus 1;
- store the low byte of the final lookup word shifted right 22 bits at that byte’s value plus `0x11`.

More calls pass shifted return values once and twice, followed by a separately derived indirect call and result forwarding. A final dependency supplies an 8-bit result and a secondary pointer-like result.

The closing accesses occur in this order:

1. Write zero through the secondary pointer-like result, with byte width.
2. Read the three-byte source and combine it as the upper 24 bits of a word whose low byte is the final 8-bit result.
3. Write that combined word to the shared result word.
4. Write a zero halfword at the final address source masked with `0x3fffffff`, then shifted right seven bits.
5. Attempt an indirect call through address zero with three zero arguments.
6. Return only if that call returns.

The final halfword address is not explicitly aligned. The zero-address call is not established as either a valid service or an intentional fault.

## Side effects

All effects are incremental. No rollback or transactional boundary is shown. A fault or nonreturning dependency can leave any completed prefix of the writes visible.

Direct stores may overlap one another, shared state, or data subsequently read. No disjointness guarantee is established. In particular:

- Low-address byte stores can affect later byte reads.
- The final pointer-directed clear occurs before the three-byte source read.
- The final halfword clear occurs after publication of the final shared result word.
- Unknown callees may change shared memory between apparently similar operations.

No allocation, deallocation, ownership transfer, reference counting, or lifetime extension is directly established. Passing a value to a dependency does not prove whether that dependency borrows it, retains it, or interprets it as an address.

## Acceptance examples

These are conditional static examples, not executed tests.

1. **Initial truncation:** if the incoming base-like value is `0x12345678`, the first direct store writes byte `0x78` at `0x12345681`, provided the preceding calls return and the address is writable.

2. **Scaled versus unscaled access:** if the first relevant secondary selector is 3, the incoming payload is stored at `0x20`, while the following word read is at `0x17`. Treating both as accesses to one array element is inconsistent with the visible calculations.

3. **Repeated right shift:** for any 32-bit early shared snapshot, shifting right 23 bits twice yields zero. The associated slot store writes zero, and the associated byte-selector read uses address 1.

4. **Byte destination range:** if a byte-selector read returns `0xff`, its selected destination is `0x110`, not `0x10`. Addition occurs after byte promotion; only the stored value is truncated.

5. **Fresh read requirement:** if an intervening dependency changes the word at the retained scaled base plus `0x74`, the repeated word-to-byte copy uses the changed word.

6. **Final shared publication:** if the final byte result is `0xa5` and the three-byte source contributes numeric upper bits `0x123456`, the final shared word is `0x123456a5`. This does not prescribe byte order in memory.

7. **Partial completion:** if the final halfword store faults, the preceding shared-word write has already been attempted. The zero-address call is not reached.

8. **Terminal target:** if address zero is not callable, no successful return is established, even when all earlier operations complete.
