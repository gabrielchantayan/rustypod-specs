# F-4d9839ed802a

## Purpose

F-4d9839ed802a conditionally replaces a two-bit field in caller-supplied storage. It accepts the operation only when the supplied address is non-null, the leading 32-bit value equals a global reference value, and the unsigned 32-bit selector is less than three.

On acceptance, the function reads the 16-bit field at byte offset 6, replaces bits 4 and 5 with the selector’s two-bit representation, writes the resulting 16-bit value, and returns zero. Other field bits retain their values from that field read.

On ordinary rejection, the function returns decimal 26, hexadecimal `0x1A`, without performing the field store. Invalid memory accesses are outside this normal-return guarantee.

The field may overlap the global reference storage. No non-aliasing requirement is established. Consequently, an accepted field store can also modify the global reference after the admission comparison has read it.

The application meanings of the leading value, selected bits, and rejection value are unknown. Interpreting them as an object-validity marker, a mode, or a particular error category is inferred intent, not established behavior.

## Behavior

### Admission and read ordering

The conditions are evaluated with short-circuiting in this order:

1. The region address is non-null.
2. The leading 32-bit value equals the global reference value.
3. The unsigned selector is less than three.

For a null address, the function returns 26 without explicitly reading the region or the global reference.

For a non-null address, the equality comparison is evaluated before the selector bound. Both comparison operands must be obtained, but the supplied representation does not establish their relative read order. The contract therefore requires neither a leading-value-first read nor a global-reference-first read.

If the compared values differ, the function returns 26. It does not perform the explicit 16-bit field read or write.

If the values match, selectors 0, 1, and 2 admit the update. Every other unsigned 32-bit value produces return value 26 without the explicit field read or write.

An unsupported selector therefore does not protect an invalid non-null region from the leading-value access. Nor does it suppress the global reference read required for the preceding comparison.

### Accepted field replacement

After all admission conditions pass, the function reads the 16-bit value at byte offset 6 and writes a replacement to the same address.

Bits are numbered from zero at the least significant bit of the numeric field value.

| Selector | Resulting bit 5 | Resulting bit 4 |
|---:|---:|---:|
| 0 | 0 | 0 |
| 1 | 0 | 1 |
| 2 | 1 | 0 |

The replaced positions have mask `0x0030`. Positions preserved from the field read have mask `0xFFCF`.

This operation replaces the selected bits rather than accumulating set bits. A previously set bit 4 or bit 5 is cleared when the selected pattern requires zero. Selector 3 is rejected even though it is representable in two bits.

The 16-bit store occurs even when the resulting numeric value equals the value read. There is no change-detection condition that suppresses the store. After the store, the function returns zero.

### Aliasing with the global reference

No direct assignment names the global reference as its destination. Nevertheless, the destination field can overlap the storage from which that reference was read.

The admission comparison precedes the accepted field read and store. If the store overlaps the reference, it can change some of the reference’s stored bits after the equality condition has already succeeded. The function does not then re-read the reference, repeat the comparison, undo the store, or change the success return on account of that change.

Consequently:

- Acceptance depends on the reference value read during the comparison, not its value after the field store.
- A successful invocation need not leave the global reference equal to the leading value.
- The global reference’s preservation cannot be asserted without a non-overlap condition or additional facts about the value written.
- Overlap does not necessarily change the reference numerically: the stored bits may already have the selected values.
- Even when the numeric value is unchanged, the 16-bit store still occurs.

The exact effect on the numeric global reference depends on the overlap geometry, byte order, and previous contents. No particular overlap geometry is established.

### Widths and address arithmetic

The selector bound is unsigned and 32 bits wide. Thus `0xFFFFFFFF` is rejected as a large unsigned value, not accepted as a negative value.

Only selectors 0, 1, and 2 reach the update. Their placement at bit position 4 yields numeric values 0, 16, and 32. These values fit in 16 bits; narrowing therefore loses no selector information on accepted paths. The masks restrict replacement to bits 4 and 5.

The field address is formed using the supplied representation’s 32-bit integer address handling and an offset of six bytes. The source does not establish a portable overflow, wraparound, or pointer-conversion policy. Inputs requiring invalid address formation are outside the valid-memory preconditions.

The field transformation is specified numerically. Target byte order is not established, so this contract does not assign the changed positions to a particular byte at offsets 6–7.

## Side effects

The only explicit data write is the accepted-path 16-bit store at region offset 6. Every ordinary rejection path omits that store.

No direct assignment targets the leading value, bytes 4–5, or the named global reference. This does **not** establish that the global reference remains unchanged: the field destination may overlap its storage. With non-overlapping storage and no external interference, this function’s field store does not modify the global reference. With overlap, preservation depends on the actual bytes written.

The operation is a field read followed by a field write, not an established atomic read-modify-write. Preserved bits come from the value read by this invocation. Changes made by another actor after that read are not guaranteed to survive the store.

No lock, synchronization operation, retry, or concurrent-update detection is shown. Neither comparison stability nor atomicity is established.

No allocation, deallocation, ownership transfer, callback, logging operation, or external function call appears in the supplied body. The supplied address is not visibly retained for later use. Existing ownership and lifetime responsibilities are not validated or transferred.

The contract describes ordinary numeric memory accesses. Device-specific effects, volatile access semantics, fault handling, and other special-memory behavior remain unresolved. An unchanged-value store must not be treated as absent merely because ordinary memory contents would remain numerically equal.

## Acceptance examples

These are conditional criteria derived from static evidence, not executed tests. Ordinary-memory examples assume valid accesses and no interfering concurrent actor. Non-overlap is specified where a preservation claim depends on it.

### Null region

Given a null region address and any unsigned selector:

- Return 26.
- Perform no explicit region read.
- Perform no global reference read.
- Perform no field store.

The selector does not alter this path.

### Nonmatching comparison values

Given a non-null region and valid comparison reads that produce unequal values:

- Obtain both comparison operands, without requiring a particular relative read order.
- Return 26.
- Perform no explicit 16-bit field read or write.

If global reference storage overlaps field bytes, those bytes may nevertheless be read through the global reference access.

### Matching values with an unsupported selector

Given valid comparison accesses, matching values, and selector 3:

- Evaluate the equality comparison before rejecting the selector.
- Return 26.
- Perform no explicit field read or store.

The same criterion applies to selector `0xFFFFFFFF`.

An inaccessible field does not itself prevent this ordinary rejection when all required comparison accesses remain valid. If the global reference overlaps that field, its required read must still be valid.

### Replacement of previously set bits

Given matching comparison values, valid field access, and an old numeric field value of `0xABFF`:

| Selector | Required stored field value | Return |
|---:|---:|---:|
| 0 | `0xABCF` | 0 |
| 1 | `0xABDF` | 0 |
| 2 | `0xABEF` | 0 |

Each case preserves all positions outside bits 4 and 5. These outcomes demonstrate replacement rather than bit accumulation.

If the reference storage does not overlap the destination, the field store does not modify it. If it overlaps, the resulting reference value additionally depends on that overlap.

### Unchanged numeric result

Given matching comparison values, selector 1, and an old field value of `0x0010`:

- Read the field.
- Perform a 16-bit store of `0x0010`.
- Return zero.

This remains a store even if the destination overlaps reference storage and all overlapping bytes retain their previous values.

### Accepted store changes the global reference

Given valid storage, successful admission, and an overlap between the destination field and global reference storage:

- If the replacement changes bits within that overlap, the store changes the reference storage.
- The function still returns zero after the store.
- No second reference comparison is required.
- Equality between the leading value and the post-store reference is not guaranteed.

A concrete numeric post-store reference cannot be prescribed without the overlap placement and byte order.

### Invalid non-null region

Given an inaccessible non-null region address, even with selector 3:

- Do not require return value 26.
- Do not assume selector rejection precedes the leading-value access.
- Treat the invalid-access outcome as outside established normal-return behavior.

Likewise, a matching comparison and accepted selector do not guarantee normal success if the field cannot be read or written, including when the field overlaps read-only reference storage.
