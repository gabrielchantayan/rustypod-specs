# F-e97f4578141f

## Purpose

F-e97f4578141f conditionally sets one bit in byte-addressed bitmap storage. Two coordinate inputs and an alignment quantity determine a candidate boundary. For an adjacent reversed range, a mode selects either the lower boundary or a rounded midpoint. Two modes also apply record-based rejection checks and inspect an existing bitmap bit before permitting the final update.

The function returns no value and reports no explicit status. Its only explicit memory write is a byte read-modify-write that preserves existing bits and sets the selected bit. Early returns perform no explicit stores.

“Bitmap,” “boundary,” and “alignment” describe the observable arithmetic and bit operations. Their application-level meanings are not established.

## Behavior

### Arithmetic model

The represented integer operations use 32-bit values. Unsigned sums, differences, negation, and products wrap modulo \(2^{32}\). Where a signed interpretation is required, this contract uses the corresponding two’s-complement signed value.

Define:

\[
M=-q \pmod {2^{32}}
\]

\[
U=(q+a-1)\mathbin{\&}M
\]

\[
L=b\mathbin{\&}M
\]

The arithmetic forming \(U\) uses the bit pattern of \(a\) in an unsigned expression. The selected bit mask is:

\[
K=128\mathbin{\gg}(x\mathbin{\&}7)
\]

Consequently, horizontal residues zero through seven select byte bits from `0x80` through `0x01`.

For suitable power-of-two values of \(q\), the boundary expressions resemble upward and downward alignment. The function neither checks that \(q\) is a power of two nor substitutes another alignment algorithm for unusual values. The expressions above govern those values too.

Signed right shifts are described below as arithmetic right shifts. Exact target semantics, particularly for excessive shift counts, remain qualified in **Uncertainties**.

### Initial boundary selection

The alignment quantity is read once and retained for the boundary calculations.

The initial comparison interprets \(U\) and \(L\) as signed 32-bit values:

- If \(U\le L\), the selected boundary is \(U\). Neither the mode field nor the records are read.
- If \(U>L\), the function requires the wrapping equality \(q+L=U\). Failure returns without reading the mode or writing the bitmap.
- If \(U>L\) and that equality holds, the initial selected boundary is \(L\), and the mode word is read and converted to a character.

The adjacency condition is a 32-bit equality, not an overflow-free mathematical distance test.

### Mode selection

The following behavior applies only to an adjacent reversed range:

| Mode | Selected boundary | Additional conditions |
|---:|---|---|
| 1 | \(L\) | No midpoint or guarded checks. |
| 2 | \(L\) | Midpoint is calculated; guarded checks must permit continuation. |
| 4 | Rounded midpoint | No guarded checks. |
| 5 | Rounded midpoint | Guarded checks must permit continuation. |
| Other | None | Return without writing. |

For every mode other than 1, the midpoint calculation occurs before the remaining mode classification.

The midpoint first forms the wrapping 32-bit sum \(a+b+1\), interprets that result as signed, and divides it by two with truncation toward zero. Let \(T\) denote the resulting 32-bit bit pattern. The rounded midpoint is:

\[
V=(T+q-1)\mathbin{\&}M
\]

Modes 4 and 5 select \(V\). Mode 2 calculates the midpoint but retains \(L\).

This midpoint is not generally an overflow-free average. Signed division also differs from an arithmetic right shift for negative odd totals.

### Guarded record checks

Modes 2 and 5 apply the following ordered rejection conditions:

1. Read Record P at `0x1c`. Only if it equals Record Q is Record P at `0x10` read. A signed value below one rejects the operation.
2. If the first check permits continuation, read Record Q at `0x1c`. Only if it equals Record P is Record P at `0x14` read. Equality of that value with \(x\) rejects the operation.
3. If both record checks permit continuation, perform the guarded bitmap probe.

A rejection in the first check prevents every read in the second check and the probe. A rejection in the second check prevents the probe. Record P’s `0x14` field is not read when Record Q’s link comparison fails.

### Guarded bitmap probe

The probe uses the original upper boundary \(U\), regardless of which boundary would ultimately be marked.

The probe configuration reads occur in this order:

1. Read the shift word and derive the probe row \(r_p\) by arithmetically shifting signed \(U\) by the word’s low eight bits.
2. Read the stride \(S_p\).
3. Read the bitmap base \(B_p\).
4. If signed \(S_p>0\), read a row limit \(H_{pa}\) for address adjustment.
5. If signed \(r_p\ge0\), read a row limit \(H_{pv}\) for probe validation.

The two row-limit reads in steps 4 and 5 are distinct. They must not be treated as one snapshot or assumed to return the same value.

The probe byte address is formed before the row-validity decision:

\[
A_p=B_p+\operatorname{ASR}_{32}(x,3)-S_p r_p
\]

For signed-positive stride, it additionally includes:

\[
S_p(H_{pa}-1)
\]

The byte-column term interprets \(x\) as signed. It is not unsigned division by eight.

For every nonnegative probe row, including zero, validation uses the separately read \(H_{pv}\). The bitmap byte is read exactly when:

\[
0\le r_p<H_{pv}
\]

where both comparisons use signed 32-bit interpretations. If that byte contains \(K\), the function returns without writing. Otherwise, processing continues.

A negative probe row skips the validation-limit read and the bitmap-byte read. A nonnegative row equal to or above the validation limit skips the bitmap-byte read. An out-of-range probe does not itself reject the operation.

A positive stride still causes the address-adjustment limit read even when the probe row is negative or later fails validation. Conversely, a zero or negative stride omits that adjustment read but does not omit the validation-limit read for a nonnegative row.

After a successful probe, mode 2 retains \(L\); mode 5 selects \(V\).

### Final validation and marking

The selected boundary is converted to the final row \(r_f\) using a newly read shift word. This read is separate from the guarded probe’s shift read.

For a negative final row, the function returns without reading the final row limit.

For every nonnegative final row, including zero, the function reads a row limit \(H_f\). The final write is allowed exactly when:

\[
0\le r_f<H_f
\]

Signed equality with the limit rejects the row. Zero is not independently excluded: a zero row is accepted whenever the signed row limit is positive.

For an accepted row, the function reads the final stride \(S_f\), then the final bitmap base \(B_f\). The address is:

\[
A_f=B_f+\operatorname{ASR}_{32}(x,3)-S_f r_f
\]

If signed \(S_f>0\), it adds:

\[
S_f(H_f-1)
\]

Unlike the probe, final address adjustment uses the row limit already captured during final validation. It does not perform another row-limit read for that adjustment.

The function then reads the byte at \(A_f\) and writes that byte ORed with \(K\). All previously set bits are preserved. The represented behavior includes the byte store even if \(K\) was already set.

There is no separate final test requiring the destination bit to be clear.

## Side effects

The only explicit store is the final one-byte bitmap update. There are no direct context or record writes, function calls, allocation operations, release operations, or diagnostic outputs.

A no-write return can still have performed context reads, record reads, and a guarded bitmap-byte read. In particular, rejection is not equivalent to performing no memory accesses.

Configuration is not globally snapshotted:

- Alignment is captured at entry and reused.
- The mode is read only for an adjacent reversed range.
- A guarded path reads probe shift, stride, and base separately from final marking.
- A positive-stride probe reads one limit for address adjustment and, for a nonnegative probe row, another for validation.
- Final marking reads its own validation limit and reuses that captured value for positive-stride address adjustment.

The final update is a read followed by a write, not an evidenced atomic bit-set operation. No locking or synchronization is shown. Overlapping storage or concurrent mutation can affect values observed by later reads. Portable behavior for data races or device-memory interactions is not established.

## Acceptance examples

These are conditional analytical examples, not executed tests.

Unless overridden, assume valid, stable storage; \(q=8\); shift count 3; signed row limit 10; stride 2; bitmap base \(B\); and \(x=9\). The byte-column offset is 1 and the bit mask is `0x40`. Row \(r\) then maps to:

\[
B+19-2r
\]

### Ordinary range bypasses mode and records

With \(a=9\) and \(b=31\), the boundaries are \(U=16\) and \(L=24\). The selected row is 2, and the function writes byte \(B+15\) ORed with `0x40`.

Neither mode nor record fields are read.

### Nonadjacent reversed range rejects early

With \(a=25\) and \(b=15\), the boundaries are \(U=32\) and \(L=8\). The adjacency equality fails because \(8+8\ne32\).

The function returns without reading the mode or accessing a bitmap byte.

### Modes select different final rows

With \(a=17\) and \(b=16\), the boundaries are \(U=24\), \(L=16\), and the midpoint is 17.

- Mode 1 marks row 2 at \(B+15\).
- Mode 4 rounds the midpoint to 24 and marks row 3 at \(B+13\).
- An unsupported mode returns without a bitmap write.

### Mode 2 probes one row and marks another

For the preceding coordinates in mode 2, assume the record checks permit continuation.

The probe reads row 3 at \(B+13\). A set `0x40` bit rejects the operation. A clear bit permits marking row 2 at \(B+15\).

A preexisting selected bit at the final destination does not independently reject the write.

### Record rejection short-circuits later reads

In a guarded mode, if Record P’s `0x1c` value equals Record Q and its signed `0x10` value is zero, the function returns before reading Record Q or the probe configuration.

Alternatively, after the first check passes, equality of Record Q’s `0x1c` value with Record P causes Record P’s `0x14` value to be read. If that value is 9, the operation is rejected before probing.

### Row zero is writable

With \(a=0\) and \(b=7\), the ordinary path selects boundary zero and final row zero.

The function reads the row limit, accepts \(0<10\), and writes byte \(B+19\) ORed with `0x40`.

With \(a=80\) and \(b=87\), the selected row is 10. Equality with the limit rejects that row without accessing the destination byte.

### Row zero is also probe-eligible

Set \(a=-7\), \(b=2^{32}-8\), and mode 5. Then \(U=0\), signed \(L=-8\), and the adjacency equality holds. The midpoint is \(-7\), whose rounded boundary is zero.

Assuming the record checks pass, the probe validates row zero and reads byte \(B+19\). A set `0x40` bit rejects the operation. A clear bit permits the final row-zero update.

### An out-of-range probe need not prevent marking

Set the stable row limit to 3 and use \(a=17\), \(b=16\), mode 2, and passing record checks.

The probe row is 3, equal to its validation limit, so no probe byte is read. Final row 2 is valid and is marked at \(B+1\).

### Distinct row-limit reads have distinct roles

Use the same mode-2 coordinates and passing record checks, but conditionally suppose the probe’s adjustment-limit read returns 10, its validation-limit read returns 4, and final validation reads 3.

The probe address is \(B+13\), calculated using 10. Probe row 3 is eligible because validation uses 4. If the selected probe bit is clear, final row 2 is accepted using 3 and marked at \(B+1\).

This example specifies the effect of distinct observed values; it does not establish a synchronization mechanism that would safely produce them.
