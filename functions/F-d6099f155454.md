# F-d6099f155454

## Purpose

F-d6099f155454 repeatedly examines a global linked structure, removes a head-derived record, updates a separately retained entry and its associated object, advances bookkeeping, and selects a payload-transfer continuation according to an incoming width.

A dependency runs before the first head examination, including when the structure is initially empty. A null result from a particular head read selects termination: an optional dependency call, an unconditional final dependency call, and an explicit 32-bit zero return.

**Established static evidence:** distinct reads of global state, fixed-offset accesses, link and flag writes, counter updates, width-dependent transfers, dependency calls, and the explicit return.

**Inferred intent:** the structure resembles a work queue, the destination resembles indexed storage, and one global resembles a high-water mark. These descriptions establish neither ownership nor application semantics.

**Unknown:** the explicit arguments do not supply all observed inputs. Additional incoming machine state provides contexts, transfer width, and an index boundary.

## Behavior

### Initial dependency call

Before any bookkeeping or head examination, invoke **F-2489d48d501c** with:

- A computed address: transfer width multiplied by an arithmetic seed, plus the value read from the storage-base cell.
- The 32-bit field value read from current object +16.

Initially, the seed is the numeric constant **0x08001fbc**, not the contents of that address. The current object is initially the explicit object argument.

For subsequent calls reached through the other-width continuation, the seed is a captured index value and the current object is the associated object obtained during entry processing. The second argument is the +16 field value itself; this call site does not directly read payload through it.

These are 32-bit target expressions without visible bounds checks or overflow-rejection branches. Exact overflow behavior for arithmetic represented as signed remains **documented_only**. The representation does not establish an evaluation order among independent reads within a call-argument expression.

### Bookkeeping and retained head

Each bookkeeping pass performs these represented accesses and decisions:

1. Read the peak-like value into a temporary snapshot.
2. Increment the iteration counter.
3. Read the peak-like value again and compare it with count as unsigned 32-bit values.
4. If the peak-like value is smaller, read count for assignment and write that value into the peak-like cell.
5. Test count for equality with one. Only on equality, read the gate. If the gate is nonzero, invoke **F-6ad030b1b8cc**.
6. Read head and retain that address as the **processing entry**.
7. Independently read head again for the null test.

Updating the peak-like cell does not itself refresh the earlier snapshot. When F-6ad030b1b8cc runs, an additional outgoing 32-bit machine value replaces that snapshot. No application meaning for this output is established.

The processing-entry snapshot does not control the null test. A non-null snapshot followed by a null test read terminates without processing that entry. A null snapshot followed by a non-null test read proceeds toward accesses through the null retained address; there is no separate retained-entry validity check.

Dependencies before these reads may affect global state. Their preservation behavior is unknown.

### Null-head termination

If the head read used for the null test is zero:

1. Read primary context +8.
2. If nonzero, invoke **F-unresolved-A** with that word. Neither comparison-context field nor primary +1 is read on this branch.
3. Otherwise, read comparison context +8, then comparison context +12.
   - If unequal, invoke F-unresolved-A with the +8 word.
   - If equal, read the unsigned byte at primary +1. Invoke F-unresolved-A with its zero-extended value only if nonzero.
4. Invoke **F-unresolved-B**.
5. Return the 32-bit value zero if execution reaches the explicit return.

The optional call is therefore omitted exactly when primary +8 reads as zero, the comparison words read equal, and primary +1 reads as zero.

The comparison-context +12 read replaces the temporary snapshot before the equality comparison. Neither the initial peak-like snapshot nor the additional output from F-6ad030b1b8cc supplies that comparison operand.

No removal or retained-entry update follows this termination decision.

### Removal through independently obtained addresses

If the null-test read is nonzero, read head again and read the word at +0 through that newly obtained address. This field supplies the **prospective successor**, independently of the retained processing entry.

If the prospective successor is zero, write zero into head. The additional accesses described next are omitted.

If the prospective successor is nonzero:

1. Read head again.
2. Read +0 through this latest head-derived address to obtain the **backlink-update target**.
3. Write the prospective successor into head.
4. Write 0x08001fd0 into backlink-update target +4.
5. Read head again.
6. Write the value from that final read back into head.

Thus, the non-null-successor path has four distinct head reads before its first head write: the processing-entry snapshot, null test, successor extraction, and backlink-target extraction. A fifth read follows the target +4 write.

The prospective successor and backlink-update target need not be equal. The backlink-update target is not separately checked for null. The final head reread can observe an effect of the +4 write if that write aliases the head cell.

With stable ordinary memory, the head-derived records and their +0 values coincide as expected for ordinary linked-list removal. That conditional simplification must not replace the separate represented accesses.

### Updates through the retained entry

Subsequent entry processing uses the address retained before the independent null test.

Read the 32-bit flags at entry +28, clear bit 7, and write the resulting word back. If the entire masked word is zero:

- Read primary context +8.
- Write that value into entry +0.
- Write the retained entry address into primary context +8.

Otherwise, omit these linking accesses. Clearing bit 7 is insufficient to trigger linking if any other flag bit remains set.

Next, read entry +8. If nonzero, invoke **F-f46257aeeddc** and, after it returns, write 0x08001fcc into entry +8. No explicit arguments are visible for this call. Its presence does not establish that the entry remains alive or that ownership changes.

Then:

1. Read entry +16 to obtain an intermediate-record address.
2. Read intermediate record +4 to obtain the associated-object address.
3. Use that associated object as the current object.
4. Write 0x08001fcc into associated object +4.
5. Increment count.
6. Increment index.
7. Read index for equality comparison with the incoming boundary. On equality, write 0x08001fcc into index.

The boundary replacement is an address constant, not zero and not the count value.

Count is unsigned 32-bit storage, so its increment has modulo-\(2^{32}\) unsigned behavior in the supplied representation. Exact overflow behavior for the signed-represented index and iteration-counter increments remains **documented_only**.

Earlier writes may alter the index by aliasing before its increment. The value observed at function entry is not sufficient to determine the value incremented here.

### Width-selected continuation and additional index read

Width selection occurs after entry processing and boundary handling.

| Width | Additional continuation-seed read | Payload action | Next stage |
|---:|---|---|---|
| 0 | None on this continuation. | None. | Bookkeeping. |
| 1 | None on this continuation. | Copy one byte to storage base plus index. | Bookkeeping. |
| 2 | None on this continuation. | Copy two bytes to storage base plus twice index. | Bookkeeping. |
| 4 | Read index into the arithmetic seed **before testing for width 4**. | Copy four bytes to storage base plus four times a **separate index read**. | Bookkeeping. |
| Any other value | Read index into the arithmetic seed **before testing for width 4**. | No direct payload transfer. | F-2489d48d501c, then bookkeeping. |

The additional seed read belongs to the shared continuation reached when width is nonzero and unequal to both 1 and 2. It occurs before the width-4 decision, so **width 4 also performs this read**, even though its direct destination does not use the captured value.

For width 4, destination arithmetic reads index again. The seed capture and destination index read are distinct represented accesses; their values must not be equated without a stability assumption.

For all other values reaching this shared continuation, the captured seed supplies the next F-2489d48d501c address calculation. That calculation reads the storage-base value and current object +16 as described for the initial dependency call.

Each direct transfer reads a 32-bit source address from current object +16 and transfers exactly the selected number of bytes through that address. Its destination expression reads the storage-base and index cells, incorporating boundary replacement and any intervening memory effects.

The representation does not establish source-versus-destination operand evaluation order within an individual transfer expression. The separate seed capture on the width-4 path precedes that transfer in the represented control flow, but this is not a claim about physical bus ordering.

Unsupported-looking widths are not rejected. Any value other than 0, 1, 2, or 4 selects another dependency call rather than a direct transfer of that many bytes.

## Acceptance examples

These are conditional static expectations, not executed tests. Unless overridden, assume accessible, suitably aligned memory; stable incoming state and ordinary reads; normally returning dependencies that preserve relevant state; and non-overlapping globals, records, contexts, and payload storage. Address calculations must also be representable and destinations accessible.

1. **Empty head still invokes the initial dependency.**  
   F-2489d48d501c runs using the initial constant seed before bookkeeping and the null test. A null test result then selects termination and, if dependencies return, a zero result.

2. **Termination-call selection.**  
   Primary +8 equal to 9 makes F-unresolved-A receive 9 without reading comparison fields or primary +1. With primary +8 zero, equal comparison words, and primary +1 zero, omit that call. F-unresolved-B runs in both cases.

3. **Different retained and tested head values.**  
   Override read stability so the retained snapshot is an accessible entry but the null-test read is zero. Terminate without removing or updating the retained entry.

4. **Different processing and removal records.**  
   Let the retained snapshot name one entry and the successor-extraction head read name another record whose +0 is zero. Write head to zero, then process flags and other fields through the original retained entry.

5. **Different successor and backlink target.**  
   If successor extraction yields one address and the later target extraction yields another, install the first as head and write 0x08001fd0 into the second address’s +4 field. Then reread head and write that reread value back.

6. **Flag boundary.**  
   Flags 0x00000080 become zero and trigger linking. Flags 0x00000081 become 0x00000001 and do not.

7. **One-byte destination.**  
   With width 1, index 4 immediately before increment, and boundary 0, index becomes 5. A source byte 0xa7 is copied to storage base plus 5. This width does not take the shared continuation-seed read.

8. **Index aliasing before increment.**  
   Override non-overlap so associated object +4 aliases index. Its update writes 0x08001fcc before increment. With no intervening change, index becomes 0x08001fcd; width 1 uses that value, not an earlier index.

9. **Boundary replacement.**  
   Index 4 immediately before increment and boundary 5 cause replacement with 0x08001fcc. Width 2 uses twice that replacement in destination arithmetic.

10. **Width 4 has two continuation-related index reads.**  
    After entry processing, read index into the seed, then select width 4, then read index again within destination arithmetic. With stable index 5, the destination is storage base plus 20. No additional F-2489d48d501c call occurs on this continuation.

11. **Width-4 reads can differ.**  
    Override read stability so the shared seed capture observes 5 and the destination-expression index read observes 7. The four-byte destination uses storage base plus 28, not plus 20. This example describes represented accesses, not supported concurrency or physical bus timing.

12. **Width 3 versus width zero.**  
    Both perform entry updates. Width 3 captures index on the shared continuation and uses it as the next dependency-call seed; it performs no direct three-byte transfer. Width zero skips both that seed capture and the intervening dependency call, returning directly to bookkeeping.
