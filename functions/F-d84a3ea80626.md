# F-d84a3ea80626

## Purpose

F-d84a3ea80626 scans a working buffer for CR- and LF-terminated records and conditionally invokes a replaceable callback with a record address, byte length, and record number.

Established behavior includes:

- CR (`0x0D`) and LF (`0x0A`) terminate records.
- One immediately following complementary terminator is absorbed without creating another record, including across reads.
- Empty records and records beginning with `0x23` or `0x1A` do not invoke the callback, but advance the record number when processing continues.
- A callback can replace the callback used for subsequent eligible records.
- An unterminated region remaining after a zero-count read is not delivered as a final record.
- Buffer capacity begins at 1,024 bytes and can grow through 65,536 bytes.
- Growth carries forward the **old capacity**, rather than the actual incomplete-fragment length, as the next read’s append offset. After a short read, this can bring bytes not initialized by this function into the scanned region.
- The explicit status assignments include `6` for a missing initial callback or prohibited growth. The actual return is the status storage’s value **after cleanup**, not necessarily the value assigned before cleanup.

The apparent intent is numbered, filtered line processing. That intent does not establish that callbacks always correspond exclusively to bytes supplied by the reader: growth can introduce a scan gap containing unspecified bytes.

## Interface

The function accepts four arguments and returns a 32-bit integer.

| Argument | Established use |
|---|---|
| Input object | A 32-bit address-like value. Its four-byte field at byte offset `0x1C` is read before the initial callback is checked. The original input-object value is passed to the reader. |
| Initial callback | A function address. A zero address selects the missing-callback exit. |
| User value | An opaque four-byte value passed to each callback. |
| Record-number output | Address of a writable 32-bit integer. Explicitly written on end-of-input and callback-requested termination, but not on other exits. |

The field read at offset `0x1C` supplies the context argument for allocation, resizing, and cleanup. The function captures it once; it does not reread the field for subsequent requests.

The callback receives these arguments in order:

1. An address at the start of the record within the working buffer.
2. A 32-bit byte length excluding the terminating CR or LF.
3. The current 32-bit record number, initially `1`.
4. The address of a mutable callback-address slot.
5. The opaque four-byte user value.

A callback result of zero selects continuation. A nonzero result selects termination. The result is assigned to the function’s status storage before that decision.

### Preconditions and interpretation limits

For bounded memory access along an exercised path:

- The input object must permit the initial context-field read, even if the initial callback is zero.
- Successful allocation must return writable storage covering the requested capacity.
- Successful resizing must leave the retained content available in the returned buffer.
- The reader must respect its destination extent and return a corresponding count no greater than the requested count.
- Fragment copying must safely handle overlapping source and destination ranges.
- Invoked callback addresses must be valid and use the expected calling convention.
- The record-number output must be writable whenever execution reaches an explicit output write.

These conditions do **not** establish reader-only record semantics. After growth from a short fragment, scan bounds include a gap between the actual fragment end and the old capacity. This function does not initialize that gap.

Statements about particular final status values additionally require that dependencies do not modify the status storage after the relevant assignment. Statements that an output remains unchanged require absence of external or aliased writes to that output.

## Behavior

### Initialization and initial allocation

The function reads and captures the input object’s context field, establishes a zero working-buffer address, and initializes status to zero.

If the initial callback is zero, it assigns status `6` and proceeds to cleanup:

- No allocation request occurs.
- No reader invocation occurs.
- No explicit record-number output write occurs.
- Cleanup receives the captured context and a zero buffer address.

Otherwise, F-6dd003795db7 receives:

- The captured context.
- Fixed value `1`.
- Old size `0`.
- New size `1,024`.
- A zero previous-buffer address.
- The address of the 32-bit status storage.

The returned address becomes the active buffer address **before** the function checks status. Nonzero status selects cleanup without an explicit record-number output write.

On status zero, the function writes zero to the first buffer byte, sets the record number to `1`, initializes the active callback from the supplied address, and starts reading. It does not initialize the rest of the buffer.

### Read placement and scan bounds

Each call to F-e7f7f4b25f23 receives the original input-object value, a destination within the active buffer, and the available capacity after that destination.

The read result is treated as an unsigned 32-bit count. The scan limit is formed by adding that count to the append offset established for the read.

There are three relevant append-offset cases:

| Situation | Append offset for the next read |
|---|---:|
| Initial read | `0` |
| After compaction | Actual incomplete-fragment byte count |
| After successful growth | Capacity before growth |

Thus, “append after the fragment” is accurate for compaction but not generally for growth.

No independent check rejects a returned count larger than requested. Under the bounded-count precondition, capacities and scan positions stay within 65,536 bytes. Invalid counts can invalidate those bounds and subsequent pointer accesses.

A zero count is used as the end-of-input condition when scanning reaches a region without a terminator. There is no separately recognized read-error result.

### Record scanning and eligibility

Scanning searches the available region for LF or CR. Other byte values, including zero and `0x1A`, do not terminate scanning.

For each terminator found, the function:

1. Saves its byte value.
2. Overwrites that buffer byte with zero.
3. Reads the first byte at the record start.
4. Calls the active callback if the record has positive length and its first byte is neither `0x23` nor `0x1A`.
5. On continuation, increments the record number.
6. Restores the saved terminator byte.
7. Advances past it and remembers its complementary terminator.

The callback’s explicit length is the distance from record start to terminator. Embedded zero bytes do not shorten that length. A positive-length record beginning with zero is eligible.

No whitespace stripping occurs. A record beginning with a space followed by `0x23` is eligible. A record beginning directly with `0x23` is suppressed.

`0x1A` is not a global input terminator. At record start it suppresses delivery; elsewhere it is ordinary content.

Suppressed and empty records still advance the record number on continuation.

### Complementary terminators

After LF, the function allows one immediately following CR to be consumed without another record. After CR, it similarly allows one LF.

The consumed complementary byte:

- Does not invoke a callback.
- Does not increment the record number.
- Clears the pending complementary-byte state.

The pending state can survive a read boundary. Repeated identical terminators do not form a pair. For example, a record ending in CR followed by another CR is followed by an empty terminated record.

These decisions operate on scanned bytes regardless of their origin. A gap byte introduced into the scan bounds by growth can participate in terminator recognition or pairing.

### Callback termination and replacement

A nonzero callback result is assigned to status and selects immediate termination:

- The current record number is written to the output.
- That number is not incremented.
- The terminator remains overwritten with zero.
- Cleanup runs.
- The status storage is read for the return value after cleanup.

Consequently, the callback result determines the control-flow exit, but is the final returned value only if it survives subsequent effects on status storage.

A callback returning zero may replace the callback-address slot. The replacement is used for the next eligible record, including one already buffered. There is no validation of a replacement address before invocation.

Suppressed records do not invoke the callback. An invalid replacement can therefore remain unused through suppressed records.

The supplied record address points into the active working buffer; the function makes no separate record allocation. Later processing may overwrite, move, resize, or pass that storage to cleanup. The function provides no durable ownership transfer or independent lifetime guarantee.

The callback also receives mutable addresses. No isolation protects the buffer or callback slot from callback writes. Arbitrary mutation of later record bytes can change subsequent processing; broader mutation and lifetime rules remain unresolved.

### Compaction

When no terminator is found after a positive-count read and the incomplete fragment starts beyond buffer offset zero, the function invokes the copying dependency.

It copies the actual remaining fragment to buffer offset zero. The next read:

- Begins immediately after that fragment.
- Requests capacity minus the actual fragment length.
- Produces a scan bound equal to actual fragment length plus the returned count.

Source and destination can overlap. The call site alone does not establish the copying dependency’s overlap guarantees.

### Growth and its scan gap

When no terminator is found after a positive-count read and the incomplete fragment begins at offset zero, the function attempts growth. It does not first require that the buffer be full.

If the capacity exceeds `65,535`, the function assigns status `6` and exits through cleanup without an explicit record-number output write.

Otherwise, it requests twice the current capacity from F-6dd003795db7, passing the captured context, fixed value `1`, old capacity, doubled capacity, current buffer address, and status-storage address.

The returned address replaces the active buffer address before status is checked. A nonzero status selects cleanup.

After successful growth, the next append offset is the **old capacity**, not the number of fragment bytes actually present. Capacity doubles, so the next request size also equals the old capacity.

For example, after an initial two-byte positive read with no terminator:

- Capacity grows from 1,024 to 2,048 bytes.
- The next read destination is buffer offset `1,024`.
- The requested count is `1,024`.
- The next scan limit is `1,024` plus the returned count.
- Offsets `2` through `1,023` enter the scanned region without this function having initialized them.

This occurs even if the next reader result is zero. Preserving the two actual fragment bytes during resizing does not define the gap contents.

Gap bytes may extend callback lengths, introduce terminators, begin suppressed records, or alter record numbering. No allocator initialization guarantee is established.

When the actual fragment already fills the old capacity, there is no such gap. Capacities progress through 1,024, 2,048, and successive powers of two up to 65,536.

### End-of-input and exit reporting

After a zero-count read, scanning still processes any terminators within the computed scan bounds. Only when scanning reaches an unterminated remainder does the function write the current record number and exit through cleanup.

That remaining region is not delivered. However, this does not guarantee that all reader-supplied unterminated bytes were withheld: a gap terminator may already have caused their delivery as part of a terminated scanned record.

| Exit selection | Status action before cleanup | Explicit record-number write |
|---|---|---|
| Missing initial callback | Assign `6` | None |
| Allocation or resize reports nonzero status | Observe that status | None |
| Growth prohibited | Assign `6` | None |
| Callback returns nonzero | Assign callback result | Current record number |
| Zero-count read reaches unterminated remainder | No new status assignment at this exit | Current record number |

On continuing paths, the current record number is one plus the number of processed record terminators, excluding absorbed complementary bytes, subject to unresolved overflow behavior. It is not a callback count and need not be a count of reader-origin records.

## Acceptance examples

These are conditional static acceptance criteria, not executed tests. Unless qualified, assume valid bounded dependencies, successful allocation, overlap-safe compaction, callbacks returning zero, a final zero-count read, and no external mutation of status or output storage. Numeric return expectations depend on that status-preservation assumption.

1. **Empty input.** An initial zero-count read produces no callback, writes record number `1`, and returns `0`.

2. **Terminated record.** An initial read containing `a`, `b`, LF invokes the callback with length `2` and number `1`. The terminator position contains zero during the callback. Completion writes `2`.

3. **Final fragment through compaction.** An initial read containing `a`, LF, `b`, `c`, followed by a zero-count read, delivers only `a`. The two-byte remainder is compacted with its actual length and is not delivered. Completion writes `2`.

4. **Short initial fragment with a growth gap.** An initial read containing only `a`, `b`, followed by successful growth and a zero-count read, does not by itself determine callback behavior or the final record number. The second read is requested at offset `1,024`, and scanning covers offsets below `1,024`. If all gap bytes are nonterminators, no callback occurs and completion writes `1`. If offset `2` contains LF and all later gap bytes are nonterminators, `ab` is delivered and completion writes `2`.

5. **Embedded zero.** A read containing `a`, zero, `b`, LF delivers length `3`. A positive-length record beginning with zero is also eligible.

6. **Pairing across reads.** A first read containing `a`, CR and a second containing LF, `b`, LF, CR delivers `a` and `b` as records `1` and `2`. Completion writes `3`.

7. **Identical terminators.** Input `a`, CR, CR in one read delivers only `a`, but completion writes `3`: the second CR terminates an empty record.

8. **Filtering.** Terminated records beginning with `0x23` or `0x1A` are suppressed and advance numbering. A record beginning with space and then `0x23` is delivered.

9. **Replacement.** If record `1` installs a valid replacement callback and returns zero, the next eligible buffered record uses that replacement.

10. **Callback stop.** A callback returning nonzero on record `4` selects termination and causes an explicit output write of `4`. The terminator remains zero. The final return equals that callback result only if cleanup and other effects preserve status.

11. **Full-capacity limit.** A 65,536-byte unterminated fragment reached without gaps selects the prohibited-growth exit: status is assigned `6`, no explicit record-number write occurs, and cleanup runs.

12. **Missing callback.** With a readable context field and zero initial callback, no allocation or read occurs. Status is assigned `6`, no explicit record-number write occurs, and cleanup receives a zero buffer address.
