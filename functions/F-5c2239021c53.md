# F-5c2239021c53

## Purpose

F-5c2239021c53 selects a numbered record through a stream-like context, publishes the selected record’s length and location, and decodes its bounded payload into a caller-supplied output structure.

The established behavior includes a mandatory 13-byte header, flag-controlled optional fields, an optional dependency-mediated section, and a mandatory five-byte trailer. A separate input controls whether the trailer requires one additional byte.

The operation is not transactional. It can return an error after publishing metadata or decoded fields. Fields absent from a record are not initialized or cleared.

The record-selection and stream-operation terminology describes inferred intent. The observable contract is the dependency-call sequence, output writes, byte interpretation, bounds checks, and return behavior specified below.

## Interface

### Inputs

Five arguments are supplied:

1. **Output storage.** A writable region addressed as 32-bit words. The implementation can write through byte offset 47, requiring at least 48 writable bytes for a fully decoded record. It does not verify the pointer or capacity.
2. **Context.** A 32-bit context reference passed to the stream-related dependencies. After payload acquisition, a pointer-sized field at context byte offset 32 supplies the payload base.
3. **Record selector.** Although represented as a byte pointer in the supplied material, this argument is not dereferenced. Its 32-bit representation is compared with an unsigned 16-bit count and multiplied by five for a dependency argument. Its established use is numeric, not as a byte buffer.
4. **Initial position argument.** A 32-bit value passed unchanged to the first positioning dependency. Its interpretation and permitted range depend on that dependency.
5. **Extended-trailer control.** A 32-bit integer tested only for equality with zero. Zero selects the five-byte trailer. Any nonzero value requires a sixth byte and extends one decoded field.

The intended selector domain is a nonnegative record number. The supplied material does not establish portable behavior for arbitrary pointer representations or out-of-range arithmetic.

### Return value

The result is a 32-bit status:

- **0:** the selected payload completed the required parsing path and reached final cleanup.
- **6:** the selector is not below the count obtained from the first count read.
- **8:** the locally checked payload is too short for a required parsing stage.
- **Other nonzero statuses:** propagated from a dependency that reports failure.

A dependency may itself return 6 or 8. The return value alone therefore does not uniquely identify the failure stage.

The final cleanup dependency’s result is not used to replace the selected return status.

No semantic units are established for these values. The function’s direct writes to optional fields occur only when their controlling flags are present.

## Behavior

### 1. Locate the selected entry

The function performs these dependency operations in order:

1. Call **F-e40a3ceddab2** with the context and initial position argument. Return immediately on a nonzero result.
2. Call **F-8f49ed59b67e** with the context and a writable status location. Return that status immediately if nonzero.
3. Keep only the low 16 bits of the returned value as the entry count. If the selector is greater than or equal to that count, return 6.
4. Call **F-d8528f8db63b** with the context and the selector multiplied by five. Return immediately on a nonzero result.
5. Call **F-8f49ed59b67e** again. Its low 16 result bits become the selected payload length. Return immediately if its reported status is nonzero.
6. Call **F-5a4c5b970f94** with the context and a writable status location. Its full 32-bit result becomes the selected payload location. Return immediately if its reported status is nonzero.

The five-byte multiplier suggests a fixed-width entry table, but the dependency implementations are unavailable. No stronger claim about table navigation is established.

No output write is directly performed by this function before these steps succeed. Dependencies may have their own effects.

### 2. Publish metadata and acquire the payload

The function writes the payload location at output offset 4, then the payload length at output offset 0.

It then:

1. Calls **F-e40a3ceddab2** with the context and payload location.
2. If that succeeds, calls **F-d036abe1e536** with the context and payload length.

A nonzero result from either call is returned immediately. The metadata remains published. These early exits do not call the final cleanup dependency.

After both calls succeed, the function reads the payload base from context offset 32. The checked payload interval begins there and has the selected, zero-extended 16-bit length.

All subsequent local parsing outcomes converge on final cleanup. This includes locally detected truncation and errors returned by the optional-section dependency.

### 3. Decode the fixed header

The payload must contain at least 13 bytes before any fixed-header field is written.

The first twelve bytes hold four consecutive signed, big-endian, 24-bit values. They are decoded and written in order to output offsets 8, 12, 16, and 20. Each value is sign-extended from its high input byte:

- `00 00 01` represents 1.
- `7F FF FF` represents 8,388,607.
- `80 00 00` represents −8,388,608.
- `FF FF FF` represents −1.

Byte 12 is then read as the flags byte. Parsing continues after this byte.

If fewer than 13 bytes are available, the function takes the local invalid-record path without directly writing any of the four header fields.

### 4. Preflight and decode flag-controlled fields

The function first calculates the total number of bytes needed for the directly decoded optional fields. It checks that entire region before writing any of those optional fields.

| Flag condition | Required bytes | Effect |
|---|---:|---|
| Bit `0x04` set, bit `0x08` clear | 1 | First optional value |
| Bits `0x04` and `0x08` set | 2 | First optional value |
| Bit `0x04` set and both low bits clear | Additional 3 | Optional signed value |
| Bit `0x10` set, bit `0x20` clear | 1 | Second optional value |
| Bits `0x10` and `0x20` set | 2 | Second optional value |

The maximum preflight requirement is seven bytes.

If this region does not fit, the function takes the local invalid-record path. The four fixed-header fields have already been written, but none of these optional-field writes occurs.

When it fits, decoding proceeds in this order:

1. **First optional value:** Present only when bit `0x04` is set. Bit `0x08` chooses an unsigned big-endian 16-bit value instead of an unsigned byte. The result is written at offset 28.
2. **Optional signed value:** Present only when bit `0x04` is set and the low two flag bits are both zero. The next three bytes are decoded as signed big-endian 24-bit and written at offset 36.
3. **Second optional value:** Present only when bit `0x10` is set. Bit `0x20` chooses an unsigned big-endian 16-bit value instead of an unsigned byte. The result is written at offset 32.

Bit `0x08` alone does not create a first optional value. Bit `0x20` alone does not create a second optional value. The low two bits suppress the optional signed value when either is set; no further meaning for them is established.

Bit `0x80` has no direct local parsing effect.

### 5. Process the dependency-controlled section

If flag bit `0x40` is set, the function calls **F-129dd09ab861** with:

- A writable reference to the current payload cursor.
- The payload-end pointer.

A nonzero result becomes the function’s return status after final cleanup. This error does not invoke the local invalid-record diagnostic.

On success, trailer parsing uses the cursor value left by this dependency. The function does not locally verify that the updated cursor remains at or after the payload base, or that it has moved monotonically forward. Correct cursor behavior is a dependency precondition, not an established property of the callee.

When bit `0x40` is clear, this dependency is not called.

### 6. Decode the trailer

At least five bytes must remain at the current cursor. Otherwise, the function takes the local invalid-record path.

For a five-byte trailer consisting of bytes A, B, C, D, and E:

- Output offset 40 receives the unsigned 16-bit value 256 × A + B.
- Output offset 44 receives the unsigned 24-bit value 65,536 × C + 256 × D + E.

These two output writes happen before the extended-trailer requirement is checked.

If the extended-trailer control is zero, parsing succeeds at this point.

If it is nonzero, a sixth byte F must be available. If absent, the function takes the local invalid-record path, leaving both five-byte trailer results already written. If present, output offset 40 is rewritten as:

65,536 × F + 256 × A + B.

The additional byte is the most significant byte of this extended value, despite appearing after the second trailer value in the payload.

Trailing bytes beyond the required trailer are accepted. The function does not require the parser cursor to equal the payload end.

### 7. Diagnose and clean up

A local bounds failure calls **F-4457a9a44a68** with a fixed invalid-record diagnostic, selects status 8, and proceeds to final cleanup.

Every path that reaches payload parsing calls **F-9787e15c337d** with the context exactly once before returning. This includes success, local truncation, and an error from **F-129dd09ab861**.

Failures before payload parsing return without that cleanup call.

## Side effects

### Output mutation

Output writes are incremental, with no rollback:

1. Location at offset 4.
2. Length at offset 0.
3. Four fixed-header fields.
4. Present optional fields, in the order described above.
5. The two five-byte trailer fields.
6. A replacement first trailer value when extension is enabled and available.

The function does not directly write offset 24 or clear omitted optional fields.

These are direct-write guarantees only. They do not establish preservation against dependency effects, including effects through global state or aliased storage.

### Context and external state

Context operations precede and surround parsing. Their effects on stream position, buffers, error state, globals, or external resources are not established beyond their arguments, results, and ordering.

No direct allocation or deallocation appears in the supplied function. Calling the acquisition and cleanup dependencies does not establish which component owns or releases payload memory.

### Preconditions

Defined operation requires valid output storage, a valid context, a readable acquired payload, and valid address arithmetic. The function does not locally validate these conditions.

Output storage must not destructively overlap payload bytes or context state needed later. In particular, fixed-header writes occur before the flags byte is read, and optional-field writes precede trailer reads. Overlap could therefore change subsequent parsing inputs.

The bounds checks assume payload-end construction and cursor additions do not wrap. They are not general protection against invalid pointers or address-space overflow.

## Acceptance examples

These examples are conditional static expectations, not executed tests. Unless stated otherwise, dependencies succeed, storage is valid and nonoverlapping, address arithmetic is valid, and dependencies do not independently alter the output.

1. **Selector outside the count.** A first count result whose low 16 bits are 3 rejects selector 3 with status 6. No entry adjustment, metadata publication, acquisition, or final cleanup follows.

2. **Count narrowing.** A successful first count result of `0x00010002` supplies count 2. Selector 1 passes the count check; selector 2 fails.

3. **Metadata survives a positioning failure.** If entry lookup yields length 18 and location 4096, those values are written before the second positioning call. A nonzero result from that call is returned without final cleanup or rollback.

4. **Minimum ordinary payload.** A length-18 payload with flags zero consists of the 13-byte header and five-byte trailer. With extension disabled, it returns 0 after final cleanup. Offsets 28, 32, and 36 receive no direct write.

5. **Truncated fixed header.** A successfully acquired length-12 payload causes the diagnostic call, final cleanup, and return 8. Metadata is written; fixed-header fields are not.

6. **Atomic optional-region preflight.** Flags `0x3C` require seven optional bytes: two for the first value, three for the signed value, and two for the second value. Only six available bytes cause status 8 without any of those three optional writes.

7. **Signed interpretation.** Header bytes `FF FF FE` produce the 32-bit representation of −2, not the unsigned value 16,777,214.

8. **Missing extension byte.** A complete five-byte trailer with extension enabled writes offsets 40 and 44, then returns 8 if no sixth byte exists.

9. **Extended byte order.** Trailer bytes `12 34 56 78 9A BC`, with extension enabled, produce `0xBC1234` at offset 40 and `0x56789A` at offset 44.

10. **Optional-section failure.** With bit `0x40` set, a nonzero result from F-129dd09ab861 is propagated after final cleanup. The local invalid-record diagnostic is not called, and trailer fields are not directly written.

11. **Extra payload bytes.** With extension disabled and no dependency-controlled section, a valid header and five-byte trailer may be followed by unused bytes without rejection.
