## Behavior

### Iteration ordering

Each iteration has the following observable sequence:

1. Read the first 32-bit word through the input pointer.
2. Call F-2979ae55a86a with that read value as its sole argument.
3. Retain the 32-bit value returned by F-2979ae55a86a.
4. Call F-058a888cc60e with the original input pointer followed by two identical copies of the retained value.
5. Inspect the integer result from F-058a888cc60e.
6. If that result is zero, return the retained 32-bit value. Otherwise, begin another iteration with a new input-word read.

The first input read and the call to F-2979ae55a86a occur before the first continuation decision. There is no path that returns normally without calling both dependencies.

The two value arguments supplied to F-058a888cc60e come from the same completed call to F-2979ae55a86a. The function does not call F-2979ae55a86a twice to populate them. Nor does it reread the pointed-to word to obtain either value argument.

### State carried between iterations

The input pointer remains unchanged within this function. The generated value is replaced on each iteration by the newest result from F-2979ae55a86a.

A nonzero result from F-058a888cc60e causes the function to read the input word again. It does not reuse the word read before the preceding dependency calls. Thus, any change to that storage that is visible at the next read can affect the next argument to F-2979ae55a86a.

Neither dependency is assumed to preserve globals or memory. Although F-2979ae55a86a receives only a word, it could affect the pointed-to storage through an independent alias or shared state. F-058a888cc60e receives the pointer directly and may also affect it. Whether either dependency actually does so is unknown.

The function has no visible iteration counter, accumulated result, or fallback value. Earlier generated values are not returned after a later iteration completes.

### Termination and return selection

Only a zero result from F-058a888cc60e triggers the function’s normal return.

The generated value itself does not control continuation. A generated value of zero still goes to F-058a888cc60e twice and is returned only if that dependency returns zero. Conversely, any nonzero generated value can be returned when the continuation result is zero.

The return value is retained from before the final call to F-058a888cc60e. It is not obtained by rereading the input storage afterward. A modification of the input word during that final call therefore does not, by itself, replace the return value.

If every completed call to F-058a888cc60e returns nonzero, there is no normal termination established by this function. If either dependency fails to return, the function cannot reach its next step.
