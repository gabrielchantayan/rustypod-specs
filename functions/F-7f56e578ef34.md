# F-7f56e578ef34

## Purpose

F-7f56e578ef34 conditionally copies a four-word record from an associated object into temporary storage, submits that record to processing dependencies, and may adjust it before invoking an object-selected callback.

Processing requires an associated object, an index within a signed half-open interval, and a clear disabling flag. Every eligible invocation that proceeds through normally returning dependencies calls **three dependencies before testing the secondary-object gate**, in this order:

1. F-870c4fcf7295.
2. F-d156b0b83eb3.
3. F-6d16652f2d03.

A nonnull secondary object with bit 1 set in its flag word enables two further F-b01436b9ce2b calls, another F-870c4fcf7295 call, a temporary-record adjustment, and an indirect callback.

**Inferred intent:** The record, differences, and adjustments suggest coordinate or region processing. The evidence does not establish dimensions, units, geometric conventions, clipping behavior, or rounding policy. Those interpretations are not requirements.

## Behavior

### Eligibility and early exits

Eligibility uses short-circuit evaluation in this order:

1. Read the associated-object pointer at primary offset `0xEC`. If it is zero, return.
2. Read the signed lower bound at `0x100`. If the index is less than this bound, return.
3. Read the signed upper bound at `0x104`. If the index is greater than or equal to this bound, return.
4. Read the flag word at `0x124`. If bit 0 is set, return.

A rejected invocation makes no dependency call and performs no working-record copy. Conditions after the rejecting condition are not evaluated by the visible logic.

With stable bounds, the accepted interval includes the lower bound and excludes the upper bound. Equal bounds or a lower bound greater than the upper bound admit no signed index. Primary flag bits other than bit 0 do not affect eligibility.

### Record capture and initial calculation

Once eligible, the function uses the associated-object pointer captured during the first eligibility check. It reads and copies the four words in increasing offset order: `0x80`, `0x84`, `0x88`, then `0x8C`.

It calculates:

- A signed record difference: copied third word minus copied first word.
- A signed primary-object difference: the field at `0xD8` minus the field at `0xD0`.

It then calls F-870c4fcf7295 with the primary-object difference first and the record difference second.

The copy and record-difference calculation precede this call. The supplied representation does not establish an ordering between the two independent primary-field reads used to form the primary-object difference.

### Offset calculation and record transformation

After the first F-870c4fcf7295 call returns, the function rereads the lower bound at primary offset `0x100`.

Let:

- \(i\) be the input index.
- \(L\) be this reread lower bound.
- \(r\) be the signed 32-bit result from the first F-870c4fcf7295 call.
- \(d\) be the previously calculated record difference.

The calculated offset is:

\[
\bigl(((i-L)+r)-1\bigr)\times d
\]

The function calls F-d156b0b83eb3 with:

1. The writable working-record address.
2. Zero.
3. The calculated offset.

The arithmetic is represented as signed 32-bit subtraction, addition, and multiplication. The formula does not imply wider intermediate precision, saturation, or defined wrapping. Overflow behavior remains unresolved.

The record difference is not recomputed after any dependency call. A dependency’s changes to record contents do not retroactively change the captured difference used in this offset.

The meaning of the zero argument and F-d156b0b83eb3’s transformation are unknown. No return value from this call is consumed.

### Primary-object processing

Next, the function calls F-6d16652f2d03 with:

1. The primary object address.
2. The working-record address, including any changes made by F-d156b0b83eb3.

This is the third dependency call on every eligible, normally progressing invocation.

F-6d16652f2d03 supplies a 32-bit result, but that result does not control the eventual adjustment or callback:

- If the subsequently selected secondary object is null, the secondary gate rejects processing independently of the result.
- If the secondary object is nonnull, the result is replaced by the secondary flag word masked with the value 2 before the relevant flag decision.

This caller therefore establishes no success, failure, or callback-permission meaning for that result.

### Secondary-object selection and gate

Only after F-6d16652f2d03 returns does the function read the secondary-object pointer at primary offset `0x34`.

If that pointer is null, processing ends. Otherwise, the function reads its flag word at offset `0x48` and tests bit 1. A clear bit ends processing; a set bit enables the remaining adjustment and callback.

No other secondary flag bit affects this decision.

The timing permits earlier dependencies to change which secondary object is selected. Once selected, the secondary pointer is retained for all remaining operations. The primary field at `0x34` is not reread.

### Final adjustment

When the secondary gate passes, the function performs these calls in order:

1. Reread the associated-object pointer at primary offset `0xEC`, add `0x80`, and pass that address to F-b01436b9ce2b.
2. Pass the captured secondary-object pointer plus `0x80` to F-b01436b9ce2b.
3. Call F-870c4fcf7295 with the second F-b01436b9ce2b result first and the first result second.

Let \(a\) be the first F-b01436b9ce2b result, \(b\) the second result, and \(q\) the subsequent F-870c4fcf7295 result. The function updates the current third working word as follows:

\[
\text{new third word}=(b-a\times q)+\text{current third word}
\]

Multiplication precedes subtraction, which precedes addition to the current word. These are signed 32-bit operations in the supplied representation, without an established overflow policy.

The current third word includes any changes already made through the working-record address. The function does not restore its initially copied value.

A remainder-like interpretation would require additional knowledge of F-870c4fcf7295. Neither division semantics nor a remainder invariant is established here.

### Callback dispatch

After the adjustment calls and the third-word update, the function reads the dispatch-table pointer through the captured secondary object and obtains the target at table offset `0x148`.

The callback receives the captured secondary object and the working-record address. Earlier dependencies can therefore affect the dispatch target by changing the selected object’s dispatch data before this lookup.

The function consumes no callback result and performs no explicit post-callback record or object update before returning.

## Acceptance examples

These are conditional acceptance criteria, not executed tests. They assume valid reached storage, normally returning dependencies, and representable arithmetic intermediates.

1. **Missing association:** If the initial associated-object pointer is zero, neither interval bound nor the disabling flag is read, no record is copied, and no dependency is called.

2. **Lower-bound rejection:** With a nonzero associated pointer, lower bound 10, and index 9, processing stops before reading the upper bound or disabling flag.

3. **Half-open interval:** With stable bounds 10 and 13 and bit 0 clear, indices 10, 11, and 12 are eligible. Index 13 is rejected before the disabling flag is read.

4. **Disabling flag:** An otherwise eligible invocation with primary bit 0 set makes no dependency call. Other primary flag bits alone do not disable it.

5. **Three pre-gate calls:** An eligible invocation whose secondary pointer is null still calls F-870c4fcf7295, F-d156b0b83eb3, and F-6d16652f2d03 in that order. It performs no F-b01436b9ce2b call or callback.

6. **Initial offset:** If copied words one and three are 3 and 7, the index is 12, the reread lower bound is 10, and the first F-870c4fcf7295 result is 2, F-d156b0b83eb3 receives offset 12.

7. **Changed lower bound:** If the preceding example’s lower bound was 10 during eligibility but is 11 when reread, the offset is 8. Eligibility is not checked again.

8. **Secondary gate and ignored result:** A secondary flag value of 1 suppresses adjustment and callback; a value of 2 enables them. Changing only F-6d16652f2d03’s return value does not alter either decision.

9. **Final adjustment:** If the two F-b01436b9ce2b results are 6 and 20, the following F-870c4fcf7295 result is 3, and the current third word is 40, the callback receives a record whose third word is 42.

10. **Changed association:** If a dependency changes the primary associated-object pointer before its callback-path reread, the first F-b01436b9ce2b call uses the changed pointer plus `0x80`. The initial record copy still came from the originally selected object.

11. **Retained secondary selection:** If an adjustment dependency changes primary offset `0x34`, the remaining operations still use the already captured secondary pointer. If it changes that captured object’s dispatch-table pointer, the later callback lookup uses the changed table, assuming it remains valid.
