# F-63fb19e4e31c

## Purpose

F-63fb19e4e31c conditionally prepares a local context, acquires two associated values, and repeatedly invokes processing dependencies. Iteration ends when an indirect context query returns nonzero, a processing result disables continuation, or a separate per-iteration check requests early exit.

The established contract is orchestration: ordered dependency calls, local storage preparation, a shared counter increment, a processing-header replacement, and two cleanup calls. The domain meanings of the context, acquired values, processing block, counter, and headers are not established.

The explicit return values are the 32-bit words `0` and `1`. A result of `1` does not establish that processing occurred or that a dependency-defined operation succeeded.

## Behavior

2. F-f5176063ec53 receives the context address, A6, `1`, and `0`, in that argument order.

### Loop admission

Every loop-condition evaluation first invokes the indirect context query. The body is entered only when:

- the query returns zero; and
- the current continuation state is nonzero.

The query is therefore invoked even when continuation has already become zero. A processing result of zero does not eliminate the next query.

A nonzero query result ends the loop without running the per-iteration early-exit check for that condition evaluation. The dispatch lookup is expressed through the context on each evaluation; no query target is explicitly cached across iterations.

Only zero versus nonzero matters for the query and continuation results. A nonzero continuation result need not equal `1`.

### Per-iteration early exit

At the beginning of every entered body, F-8a3117e4f769 is called without arguments.

If it returns nonzero, the function:

1. Calls F-c41d7e529dcd with the primary slot’s address.
2. Calls F-efef8be39528 with the context address.
3. Returns `0`.

This branch skips all processing dependencies for that iteration, the direct counter increment, the header replacement, and the final address-adjustment call chain.

The branch does not reverse any effects of initialization, acquisition, earlier iterations, queries, or the early-exit check itself.

### Processing and separate root references

If the early-exit check returns zero, the iteration proceeds as follows:

1. F-d75e978923d6 receives A1, A3, A4, and the current companion value.
2. Its 32-bit result is retained for F-146408cdf7de.
3. The current context-root global is read and captured for the later counter update.
4. The context-root global is referenced separately to obtain the four-byte field at offset `+8`.
5. F-146408cdf7de receives the processing-block address, the current primary value, the result from F-d75e978923d6, and that `+8` field value.
6. F-5cd8d226cdb3 receives the processing-block address.

The two context-root references have distinct roles and occur in the stated order. The `+8` field access is not specified as traversing the captured counter root. Equality of the roots used by these references requires stability assumptions not supplied here. There is no explicit dependency call between the two references, but that alone does not establish a general shared-state preservation or concurrency contract.

F-d75e978923d6 runs before both root references. Changes it makes to the root can therefore affect the captured counter root as well as the subsequent reference used for the `+8` field.

The return value of F-146408cdf7de is unused. Neither processing dependency’s result is interpreted as an error code by this function.

### Counter update

- A four-byte counter at offset `+0x298` through the resulting address is incremented by one.

The visible operation is an ordinary four-byte read/add/write, not an atomic increment. ## Acceptance examples

These are conditional obligations derived from static control flow, not executed tests. Unless otherwise stated, required addresses and call targets are valid and dependencies return normally.

1. **Gate skips the operation.** If F-865a80ef6be3 returns nonzero, the result is `1`. No subsequent dependency call or direct initialization write occurs.

2. **First query stops processing.** If the gate returns zero and the first query returns nonzero, initialization and acquisition still occur. No body executes. Cleanup runs in its specified order, followed by return `1`.

3. **Early exit in the first body.** If the gate and first query return zero, and F-8a3117e4f769 returns nonzero, cleanup occurs and the result is `0`. No processing call or direct counter increment occurs.

4. **Zero continuation still completes the iteration.** If F-5cd8d226cdb3 returns zero, the counter update, header replacement, and final dependency chain still occur. The query is invoked once more before cleanup and return `1`, even if that query returns zero.

5. **Nonzero continuation is not restricted to one.** A nonzero processing result permits another body only if the next query also returns zero. A nonzero query ends processing regardless of continuation.

6. **Root mutation before capture can redirect the counter.** If F-d75e978923d6 changes the root from one valid object to another before returning, the subsequent capture can select the new root. The counter is not tied to the root that existed before that dependency call.

7. **Root mutation after capture does not replace the capture.** If F-146408cdf7de or F-5cd8d226cdb3 changes the global root after capture, the current iteration still uses the captured root for the counter traversal. A mutation to the captured root’s `+4` field can nevertheless change the nested counter target.

9. **Zero acquisition is not locally rejected.** If F-a38f2a56f255 returns zero, zero is stored and execution continues. Whether subsequent dependencies accept it is documented_only.

10. **The header is not reset to the initial constant each iteration.** The explicit initial value is `0x00008000`. After each processed iteration, the explicit replacement is the then-current replacement-header global, not necessarily that constant. Intervening dependency mutations remain possible.
