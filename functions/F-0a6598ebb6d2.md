# F-0a6598ebb6d2

## Purpose

F-0a6598ebb6d2 processes an optional request for an entry selected by a context record. It first resets a context field and clears one flag bit in state reached through the selected entry. It then either reports an immediate outcome, performs direct processing, or invokes a text-oriented processor.

The established outer return values are the 32-bit values **0**, **1**, and **7**. These identify control-flow outcomes; their application-level success or failure meanings are unknown. A text-processor result of 7, for example, produces an outer return of 1, whereas an already-set owner marker produces an outer return of 7.

“Owner,” “selected entry,” “request key,” and “text” are descriptive roles inferred from use. They do not establish domain types, ownership rights, or text encoding.

## Behavior

### Initial accesses and flag update

Before testing the request address, the function performs this sequence:

1. Reads and retains the owner address from context +0.
2. Reads and retains the selected index from context +4.
3. Writes 32-bit zero to context +12.
4. Reads the table address from retained owner +8.
5. Uses that table address and the retained index to read the selected entry’s associated-state address at entry +20.
6. Reads the 16-bit field at associated state +90.
7. Clears bit 0x0004 and writes the resulting 16-bit value back to the same field.
8. Initializes a local 32-bit cell with the auxiliary argument.
9. Reads the byte at retained owner +30.

The flag transformation is a 16-bit mask with **0xFFFB**. Other bits in the value read are retained. The masked value is also retained separately for possible use by F-cf5dd1ff88c3; that later argument is not obtained by rereading the flag field.

The initial context write precedes the first table lookup. Consequently, if context +12 overlaps storage subsequently read, even the initial lookup can observe the effect of that write.

### Owner-marker early exit

If owner +30 is nonzero:

- The function reads request +0.
- It calls F-8cb87819e3ea with the context address, that request value, and an explicit zero third argument.
- It returns **7**.

This branch precedes the request-null check and all checks of request +4 or +8. The initial context reset and flag update have already occurred.

### Null request and zero second word

If the owner marker is zero and the request address is null, the function returns **0**, without calling a dependency.

Otherwise, it reads request +4. If that 32-bit value is zero:

- It reads request +0.
- It calls F-8cb87819e3ea with the context address, that value, and an explicit zero third argument.
- It returns **1**.

Request +8 is not inspected on this branch.

### Direct-versus-text selection

When the tested request +4 value is nonzero, the function reads request +8.

- A zero address selects direct processing without a target-byte read.
- A nonzero address causes one byte at that address to be read.
- A zero first byte selects direct processing.
- A nonzero first byte selects text processing.

No broader validation of the target is visible.

### Direct processing

The function reads request +0 to distinguish two cases.

**Zero key.** It calls F-8cb87819e3ea with the context address and two explicit zero arguments, then returns **0**.

**Nonzero key.** Before calling F-cf5dd1ff88c3, it performs a **second read of retained owner +8**, resolves an entry using this newly read table address and the original selected index, and reads the 32-bit field at that entry’s +0.

This second table-address read occurs after the initial associated-state flag write and after the owner-marker, request-second-word, and direct-path selection checks. It is not reuse of the first table-address value. No dependency call intervenes on this path before F-cf5dd1ff88c3, but overlapping storage can still make the two table-address reads differ.

F-cf5dd1ff88c3 receives:

1. The retained owner address.
2. The request’s first word as obtained for this call.
3. The entry +0 value obtained through the second table lookup.
4. The retained masked 16-bit flag value.
5. The request address.

The relative evaluation order among independent reads used to construct this call is not established beyond their placement after the branch checks and before the call.

If F-cf5dd1ff88c3 returns zero, no returned-object field is accessed. Otherwise, its result is treated as an address and the 32-bit field at result +20 is read:

- If that field is nonzero, this function does not initialize it.
- If it is zero, request +4 is read again, F-b902b5c89b26 is called with that value, and its 32-bit result is written to result +20.

The outer return is **0** in all of these normally returning direct-path cases.

The request +4 value supplied to F-b902b5c89b26 need not equal the earlier zero-tested value: F-cf5dd1ff88c3 executes between those reads. Likewise, a zero returned-object field observed before F-b902b5c89b26 is not rechecked before the subsequent write.

### Text processing

The text path executes the following sequence:

1. Writes the original selected index to retained owner +120.
2. Reads request +4 and calls F-b902b5c89b26 with that value.
3. Writes its 32-bit result to retained owner +124.
4. Reads request +8 again.
5. Calls F-f2daf800ed06 with the retained owner address, this newly read request +8 value, two explicit zeros, and the address of the local auxiliary cell.
6. After that dependency returns, writes 32-bit zero to retained owner +120.

The second request +8 read is not a cached use of the address whose first byte selected the text path. The preceding owner writes or F-b902b5c89b26 may have changed overlapping or reachable storage. No second nonnull or first-byte check is performed before F-f2daf800ed06 receives the reread value.

If F-f2daf800ed06 returns zero, the outer function returns **0**. It does not call F-94cb53877c15 on this outcome.

For every nonzero processor result:

- The result is written as a 32-bit value to context +12.
- If the result is **7**, owner +30 is written with byte value **1**.
- If the result is **9**, no reporting call is made.
- For every other nonzero result, F-8cb87819e3ea is called with the context address and a newly read request +0 value. Only **two explicit arguments** are present at this call site.
- F-94cb53877c15 is then called with the current 32-bit contents of the local auxiliary cell.
- The outer function returns **1**.

The result handling distinguishes zero, 7, and 9 by equality. No other range or sign restriction on the processor result is established.

## Side effects

| Location | Write |
|---|---|
| Context +12 | Initial zero; later a nonzero text-processor result when applicable |

These are ordered direct writes, not unconditional final-state guarantees. Dependencies may modify reachable state after or between them. Aliasing can also cause one listed write to change another logically named field.

In particular, the initial associated-state flag write can overlap owner +8. The nonzero-key direct path then reads the altered table-address field and may obtain entry +0 from a different table, while still passing the masked flag value derived through the original lookup.

No direct allocation, release, synchronization, rollback, or exception-handling mechanism is visible. Stored dependency results cannot be classified as owned pointers, borrowed pointers, handles, or scalar identifiers from this body alone.

The local auxiliary cell remains live through the synchronous calls and until this function returns. Whether F-f2daf800ed06 retains its address is unknown; the body does not establish permission for use after return.

## Acceptance examples

These are conditional consequences of the static representation, not executed tests. Unless an example specifies aliasing or mutation, assume valid nonoverlapping storage, dependency preconditions satisfied, normally returning dependencies, and no dependency side effects beyond those stated.

1. **Null request with clear marker.**  
   With owner +30 zero, a null request produces outer return 0. Context +12 is reset. An initial flag value of 0xFFFF is written back as 0xFFFB. No dependency is called.

2. **Marker precedence.**  
   With a valid request and nonzero owner marker, F-8cb87819e3ea receives the context, request +0, and explicit zero. The outer return is 7 even if request +4 is zero.

3. **Zero second word avoids third-word access.**  
   With clear marker and request +4 zero, the reporting call occurs and the outer return is 1. Request +8 need not be accessed, even if its stored value would be unusable as an address.

4. **Null or empty target.**  
   With nonzero request +4, either a zero request +8 or a readable target whose first byte is zero selects direct processing. A zero key then produces the three-argument reporting call with two zero values after the context and outer return 0.

5. **Second lookup observes an aliased flag write.**  
   Suppose the initially resolved associated-state flag field overlaps owner +8, clearing bit 0x0004 changes that table-address field, and both relevant lookups remain valid. On the nonzero-key direct path, F-cf5dd1ff88c3 receives entry +0 from the table designated by the **changed** owner +8 value. The original selected index is used, and the flag argument remains the value computed during the initial lookup.

6. **Conditional returned-object initialization.**  
   If F-cf5dd1ff88c3 returns a valid object with +20 zero, F-b902b5c89b26 is called and its result is stored there. A nonzero +20 suppresses that call and store. A null result suppresses the field read as well.

7. **Request mutation before conversion.**  
   If F-cf5dd1ff88c3 changes request +4 before returning an object requiring initialization, F-b902b5c89b26 receives the changed value, including zero if that is now stored.

8. **Text-address reread.**  
   If F-b902b5c89b26 changes request +8, F-f2daf800ed06 receives the changed address rather than the address whose first byte originally selected text processing.

9. **Zero processor result.**  
   Owner +120 is zeroed after the processor returns. The outer return is 0, and F-94cb53877c15 is not called.

10. **Processor results 7, 9, and another nonzero value.**  
    Result 7 is stored in context +12, sets owner +30 to 1, omits reporting, and leads to F-94cb53877c15 and outer return 1. Result 9 follows the same outcome without the marker write. Another nonzero result, such as 2, adds the two-explicit-argument reporting call before F-94cb53877c15.
