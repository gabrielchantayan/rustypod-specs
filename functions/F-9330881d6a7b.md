# F-9330881d6a7b

## Purpose

F-9330881d6a7b selects a format-dependent starting displacement, scans callback-backed input for a designated identifier, and conditionally reconstructs a record for a processing dependency.

A matching identifier causes the function to clear a caller-provided discriminator. If allocation and processing succeed, it publishes a processing output. Every matching path subsequently requests positioning at the supplied base position plus 24.

This is not an established general-purpose record validator. The visible behavior does not enforce complete reads, a minimum record length, forward progress, successful positioning, or containment of a complete record within the scan bound.

The description as a record scanner and reconstruction routine is **inferred intent**. The contract below separates visible operations from unavailable dependency semantics.

## Interface

The function accepts seven arguments and returns a 32-bit integer.

| Argument | Established role |
|---|---|
| Input object | Pointer to an object whose first machine word identifies a callback table. |
| Opaque word | A 32-bit value copied into local storage, with no further visible use. |
| Base-position low word | Unsigned low 32 bits used to construct positioning requests. |
| Base-position high word | High 32 bits supplied through an integer argument. |
| Scan bound | Signed 32-bit bound compared with the signed interpretation of the running displacement. |
| Format selector | A 32-bit value selecting the starting displacement and serving as the matching-path fallback return value. |
| Result storage | Caller-owned writable storage receiving a one-byte discriminator and, conditionally, a 32-bit output at byte offset four. |

The callback table contains a read-like entry at byte offset 16 and a positioning-like entry at byte offset 20. These offsets and the visible word operations are consistent with a 32-bit interface. The complete external ABI is **documented_only**.

### Result-storage layout

The function explicitly performs these writes:

| Condition | Write |
|---|---|
| Entry into the matching path | Zero to byte offset 0 |
| Processing returns zero | Three to byte offset 0 |
| Immediately after that discriminator write | Processing output word to bytes 4–7 |

Bytes 1–3 are not explicitly written. Bytes 4–7 are not explicitly cleared when allocation is skipped, allocation fails, or processing returns nonzero.

The caller must provide accessible storage for the writes reached, including suitable alignment for the 32-bit store. This layout does not establish a complete structure definition. Final contents also depend on whether dependencies can reach and modify the storage.

### Return value

An unsupported selector produces an immediate return of zero.

For recognized selectors, the returned value is the contents of the function’s 32-bit identifier storage at exit. Its address is passed to the read callback, so its contents are not necessarily attributable only to the most recent identifier read.

On a matching path:

- The selector is assigned to identifier storage before allocation is considered.
- If no nonnull allocation is obtained, there is no later explicit reassignment.
- If a nonnull allocation is obtained, the selected fallback or replacement value is assigned after the release dependency returns.
- The final positioning callback runs after those assignments and before the return.

A dependency retaining the identifier destination can therefore change the returned value during later calls while that storage remains alive. Descriptions such as “returns the selector,” “returns the replacement value,” or “returns the last identifier” require preservation conditions.

The return is not a uniform success/error enumeration.

## Behavior

### Selector recognition

Two unavailable global 32-bit constants determine selector recognition: a selector base and a secondary delta.

The following relationships are tested in order:

| Relationship | Initial displacement |
|---|---:|
| Selector minus selector base equals zero | 32 |
| Selector minus selector base equals secondary delta | 102 |
| Selector minus selector base minus secondary delta equals 167,772,160 | 52 |
| Selector minus selector base minus secondary delta equals 184,549,376 | 62 |

The first matching branch determines the displacement. Otherwise, the function returns zero without callbacks, allocation, processing, or explicit result-storage writes.

These relationships describe the visible 32-bit arithmetic. They do not establish portable signed-overflow semantics for an independent high-level implementation. The actual selector constants are unavailable.

### Initial positioning and target capture

For a recognized selector, the function makes a positioning-like call with:

1. The input object.
2. The positioning callback’s own address.
3. The low word of the supplied base plus the initial displacement.
4. The corresponding high word.
5. Mode zero.

The low-word addition carries into the high word. Each initial displacement is positive and below 128, so its sign-extension contribution is zero. The resulting high word is a 32-bit word.

The positioning return is ignored. The function does not verify movement.

Only after this call returns does the function sample and save the global target identifier. A global change during initial positioning can therefore affect the selected target. Later ordinary changes to that global do not replace the saved comparison value.

### Scan state and read ordering

Three length-related values must be distinguished:

- The running 32-bit displacement.
- Address-exposed 32-bit record-length storage.
- A separately captured allocation length whose address is not supplied to the read callback.

Before each loop-condition evaluation, the captured allocation length is reset to zero. An iteration is entered only when the running displacement, interpreted as signed 32-bit, is less than the signed scan bound.

Each entered iteration performs, in order:

1. A read-like call into record-length storage, requesting 4 units with mode 1.
2. A read-like call into identifier storage, requesting 4 units with mode 2.
3. Examination of the second callback’s return value.

The first callback’s return is ignored. Neither destination is visibly initialized before its first read. Entering an iteration does not establish that either destination becomes fully initialized: callback write behavior is unknown, and a return value alone does not prove which bytes were written.

If the identifier callback returns anything other than exactly 4, scanning stops with captured allocation length zero.

If it returns exactly 4, the function captures the record-length storage’s then-current value as the allocation length. This capture occurs after the identifier callback. That callback may have modified length storage through an address retained from the preceding call.

The function then compares identifier storage with the saved target. Equality stops scanning.

### Nonmatching-record advancement

For an exact-four identifier return with a nonmatching identifier, the function requests positioning with mode 1.

The requested low displacement is the current record-length word minus 8. The high displacement is the sign extension of that 32-bit difference. The call also receives the input object and the positioning callback’s own address.

After the positioning callback returns, the function reads record-length storage again and adds that value to the running displacement. Thus:

- The skip request uses the length available before positioning.
- The displacement increment uses the length available after positioning.
- The earlier captured allocation length is separate from both.
- The next loop-condition evaluation resets the captured allocation length to zero.

A callback retaining the length destination can make the requested skip and the displacement increment disagree. The positioning return is ignored.

Displacement advancement is a 32-bit operation, followed by a signed bound comparison. There is no explicit check for wraparound, backward movement, or lack of progress.

### Post-scan matching decision

After scanning stops, the function compares the current identifier-storage contents with the saved target, regardless of why scanning stopped.

Consequently:

- An exact-four identifier read containing the target reaches the matching path.
- A non-four return can also reach that path if identifier storage nevertheless contains the target. Its captured allocation length remains zero.
- A nonmatching record’s positioning callback can change identifier storage. If the next bound check stops scanning, that changed value controls the post-scan decision.
- If no iteration executes, identifier storage has not been visibly initialized.
- Even after an entered iteration, comparisons can depend on indeterminate or stale bytes if callbacks do not fully write the destination.

If the comparison is nonmatching, there is no final positioning call and no explicit result-storage write. The function returns the current identifier-storage contents, subject to the initialization limitations above.

### Matching-path allocation and reconstruction

On entering the matching path, the function first clears result byte 0 and then assigns the format selector to identifier storage.

Allocation is attempted only when the captured allocation length is strictly positive under a signed 32-bit comparison. F-d33f6d597e5d receives that captured length.

If the length is not positive, allocation is skipped. If allocation returns null, reconstruction and processing are skipped. Both paths still proceed to final positioning.

For a nonnull allocation, the function populates the buffer as follows:

| Buffer range | Contents or use |
|---|---|
| Bytes 0–3 | Captured allocation length, most-significant byte first |
| Bytes 4–7 | Bytes 0x73, 0x69, 0x6E, 0x66, spelling “sinf” |
| Starting at byte 8 | Destination of the payload-read request |

The payload callback receives the input object, the buffer address plus 8, captured length minus 8, and mode 2. Its return is ignored.

The reconstructed length bytes and payload request use the captured allocation length, not a later value of address-exposed length storage.

The function does not require a captured length of at least eight. A positive length below eight still causes eight explicit header-byte writes and a negative length-minus-eight payload count. Safe capacity and interpretation of that count are not established.

### Processing and publication

After the payload callback, the function fetches the processing context by dereferencing a global pointer. Changes to that global during the payload callback can affect the context used.

F-8b597b2bcb25 receives, in order:

1. That context.
2. The reconstructed buffer.
3. The captured allocation length.
4. Zero.
5. Zero.
6. One.
7. An address for a 32-bit output word.

The output word is not visibly initialized before this call.

Only a zero processing return selects the publication branch. On zero, the function:

- Writes three to result byte 0.
- Copies the processing output word to result bytes 4–7.
- Calls F-8b02797ad6c4.
- Selects that dependency’s return as the replacement for the selector fallback.

A defined published output requires the processor to supply a defined output word. Its zero return alone does not establish that write.

Whether processing returns zero or nonzero, the function next passes the temporary-buffer pointer to F-5e3309c9d083.

Only after this dependency returns does the function assign the selected fallback or replacement value to identifier storage. This overwrites earlier modifications to that storage during the allocated-buffer branch. It does not protect against the subsequent final callback.

### Final positioning

Every matching path requests positioning at the original supplied base plus 24, with mode zero.

The low word is the original base low word plus 24. The high word is the original base high word plus one exactly when the original low word exceeds 0xFFFFFFE7, with a 32-bit high-word result.

This request occurs after the release call when a buffer was allocated. It also occurs when allocation was skipped or returned null. Its return is ignored.

The function then returns the current identifier-storage contents. A previously retained identifier destination remains live during this final callback and can affect the returned value.

## Side effects

Established explicit effects include callback calls, conditional caller-storage writes, temporary-buffer writes, processing, and a release-dependency call.

The input object and caller’s result storage are not explicitly released. Every nonnull allocation reaching the allocated-buffer branch is passed once to F-5e3309c9d083 after processing returns. This establishes call order, not actual release semantics or compatible ownership rules.

Read callbacks receive addresses into active local storage. Retention can affect subsequent behavior during this invocation. It does not establish permission to access that storage after return.

Callback entries are obtained from the object’s table at call sites. Later calls are not guaranteed to use the same implementation if dependencies modify that table.

There is no visible rollback after read failure, positioning failure, allocation failure, or processing failure. The final positioning request is base plus 24, not restoration of a captured entry position.

No general preservation guarantee is established for globals, caller-accessible storage, escaped local storage, or dependency-owned state. All subsequent-call descriptions assume preceding calls return normally.

## Acceptance examples

These are conditional static expectations, not executed tests. Memory validity and dependency preservation apply only where explicitly assumed.

1. **Unsupported selector.** A selector satisfying none of the four relationships returns zero without callbacks, allocation, or explicit result writes.

2. **Immediate match.** Suppose the initial displacement is 32, the bound exceeds 32, the header callbacks fully supply length 16 and the target identifier, and the identifier callback returns 4. With a valid, sufficiently large nonnull allocation, the sequence includes initial positioning at base plus 32, two header reads, discriminator clearing, allocation for 16, eight reconstructed header bytes, an eight-unit payload request, processing, release, and positioning at base plus 24.

3. **Successful processing.** Under example 2, processing writes a defined output and returns zero. The function writes discriminator three and that output, calls F-8b02797ad6c4, releases the buffer, and assigns the replacement value to identifier storage. That value is returned if the final callback preserves the storage.

4. **Processing failure.** Under example 2, a nonzero processing return suppresses publication and F-8b02797ad6c4. Release and final positioning still occur. The selector is assigned after release and is returned if the final callback preserves identifier storage.

5. **Allocation failure.** A matching positive-length record whose allocation returns null clears the discriminator but performs no reconstructed-header writes, payload read, processing, or release call. Final positioning occurs. The selector is returned only if allocation and final positioning preserve identifier storage after its selector assignment. Result bytes 4–7 are not explicitly cleared.

6. **Nonmatching record reaches the bound.** With displacement 32, bound 48, length 16, and a nonmatching identifier, a preserving relative callback receives skip 8. The displacement becomes 48, preventing another header read. If identifier storage is preserved, that identifier is returned without final positioning.

7. **Length changes during positioning.** In example 6, suppose the relative callback changes retained length storage from 16 to 24. The already-issued skip remains 8, but the next displacement is 56. The function does not reconcile these values.

8. **Final callback changes the return.** A read dependency retains the identifier destination. After the matching path assigns its selected return value, final positioning writes another 32-bit value through that address. The newly written value is returned.

9. **Non-four return with a complete target.** An identifier callback returns 2 but nevertheless leaves the complete target in its destination. The function enters the matching path with captured length zero, clears the discriminator, skips allocation, and requests final positioning.

10. **Position carry.** With base low word 0xFFFFFFF0 and displacement 32, initial positioning uses low word 0x00000010 and an incremented high word. Final positioning independently uses low word 0x00000008 and the original high word incremented once.

11. **Initialization is not established by loop entry.** If no iteration executes, there is no visible initialization of identifier storage. If an iteration executes but the identifier callback leaves bytes unwritten, entering that iteration does not establish a defined comparison or return value. Neither case supports a deterministic identifier expectation without additional preconditions.

## Uncertainties

The following remain **documented_only**:

- Actual selector constants, target identifier, and processing-context identity.
- Whether the target identifier denotes “sinf.”
- Read-count units, callback byte-order conversion, and input-position advancement.
- Whether positioning modes zero and one mean absolute and relative positioning.
- Dependency ownership, preservation, reentrancy, retention, and error contracts.
- Complete ABI details and arithmetic semantics beyond the visible 32-bit operations.

Visible hazards prevent a stronger safety guarantee:

- If no iteration executes, identifier storage has not been visibly initialized. Entering an iteration also does not guarantee initialization: the callback’s write behavior is unknown, and incomplete writes can leave indeterminate or stale bytes.
- An ignored or incomplete length read can leave an indeterminate or stale length.
- Positive lengths below eight still cause eight header-byte writes and a negative payload count.
- Zero lengths can prevent progress. Negative lengths, callback mutations, and wraparound can affect direction and termination.
- The bound is checked before a header, not against the complete header or payload extent.
- Ignored payload results can expose unwritten buffer contents to processing.
- Escaped local addresses permit later calls to alter scan state and return contents.

Safe operation requires caller and dependency preconditions that this function does not itself enforce.
