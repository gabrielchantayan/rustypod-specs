# F-c5749e6447fb

## Purpose

F-c5749e6447fb determines whether an adjusted signed value qualifies near one endpoint of an admitted interval. Qualification updates a context state byte and requests completion through a dependency.

Three ordinary results are established:

| Result | Contract |
|---|---|
| 0 | Entry is ineligible, a restriction prevents evaluation, the selected endpoint is unavailable, proximity fails, or completion reports nonzero status. |
| 1 | Proximity qualifies and completion reports zero status. |
| 3 | Adjustment reports nonzero status, or the adjusted candidate fails interval admission. |

These results do not describe a transaction. A result of 0 may occur after threshold writes, a state change, and dependency side effects. A result of 3 does not rule out adjustment side effects. A result of 1 does not guarantee the final contents of state storage after completion.

“Candidate,” “endpoint,” “threshold,” and “completion” describe relationships established by the available static evidence. Their application-specific meaning is unknown. Interpreting the operation as authorizing a transition near an endpoint is **inferred intent**, not an additional requirement.

No runtime tests have been performed.

## Interface

### Arguments and return value

The interface has four 32-bit argument positions and a 32-bit result.

| Position | Established interpretation |
|---|---|
| First | Context address represented by a signed 32-bit value. Passed unchanged to both dependencies. |
| Second | Unsigned 32-bit input. Its incoming value does not influence ordinary defined behavior. |
| Third | Opaque 32-bit input unused by this function. |
| Fourth | Initial signed 32-bit candidate. |

Eligible, unrestricted execution places the candidate in invocation-local writable storage and passes its address to F-794999814d51. Following zero adjustment status, the value left in that storage is the candidate evaluated by this function. There is no separate adjusted-candidate return value.

The incoming second argument is immaterial: ineligible entry rejects independently of it, while eligible entry replaces it with the restriction observation before deciding whether to continue.

### Preconditions and arithmetic domain

Ordinary results require valid reached memory accesses, defined reached arithmetic, and returning dependencies. No ordinary error result is specified for invalid addressing, arithmetic outside the represented model, or a dependency that does not return.

Signed arithmetic is represented at 32 bits. Signed addition, subtraction, and multiplication require representable results. Division by two truncates toward zero. Signed shift-doubling requires a nonnegative operand whose doubled value is representable.

Operation-specific safe operand ranges are:

| Operation | Operand range |
|---|---|
| Selection multiplied by 80 | −26,843,545 through 26,843,545 |
| Scale multiplied by 2 | −1,073,741,824 through 1,073,741,823 |
| Scale doubled by signed shift | 0 through 1,073,741,823 |
| Scale multiplied by 15 | −143,165,576 through 143,165,576 |

These ranges are not sufficient to establish whole-invocation safety. Address additions, endpoint subtraction, and proximity-boundary arithmetic have their own requirements.

Adjustment-payload addressing has a distinct unsigned stage. The initial signed record origin is first displaced by 0x1000 using signed arithmetic. That result is converted to unsigned 32 bits. Payload displacements of 0x24C, 0x28E, and 0x250 then use modulo-\(2^{32}\) addition. This later wrapping does not legitimize an earlier signed overflow or establish that the resulting address is valid.

Alignment, byte order, address interpretation, and allocation boundaries remain **documented_only**.

## Behavior

### Eligibility and adjustment boundary

Only entry-state value 4 permits evaluation. Every other state returns 0 without a selection read or dependency call.

For eligible entry, the initial selection determines the restriction location and adjustment payload locations. A nonzero restriction returns 0 without reading the payloads or invoking adjustment. Initial record-origin calculation and its additional signed 0x1000 displacement precede restriction rejection; their arithmetic must therefore be defined even when restriction prevents further work.

A zero restriction permits candidate initialization and the call to F-794999814d51. Nonzero adjustment status produces result 3 without a post-adjustment selection read.

Zero adjustment status permits admission. It does not guarantee preservation of the context, selection, state, endpoints, policy bytes, scale, threshold, or other accessible storage. Neither entry state nor restriction is checked again.

### Record identity and admission

Successful adjustment separates two record-selection observations:

- The initial selection supplies restriction and adjustment data.
- A fresh selection after adjustment supplies admission and all subsequent record-relative accesses.

The second record origin is retained. Later changes to selection do not redirect those accesses. The second record’s restriction is not checked.

Admission requires the adjusted candidate to be at least the observed lower endpoint and at most the observed upper endpoint. The lower comparison precedes the upper-endpoint admission read. A candidate below the lower endpoint returns 3 without that upper read.

The admission lower endpoint is retained for lower-endpoint availability and, when applicable, the lower-policy half-span. Later endpoint observations specified below are fresh reads.

With stable endpoint values, admission is inclusive: either endpoint may be admitted. Equal endpoints admit only their shared value. Reversed endpoints admit no candidate. There is no endpoint normalization or separate malformed-interval result.

### Endpoint selection and availability

The first endpoint-policy observation selects the lower endpoint only when its value is 2. Every other byte value selects the upper endpoint.

Availability is asymmetric:

| Selected endpoint | Availability condition |
|---|---|
| Lower | The retained admission lower endpoint is nonzero. Negative endpoints are available. |
| Upper | The upper-availability byte is nonzero. The upper endpoint itself may be zero. |

Unavailable lower selection returns 0 before reading lower policy or writing threshold storage. Unavailable upper selection returns 0 before reading scale or writing threshold storage.

Upper selection includes a second endpoint-policy observation after the initial threshold write. That observation controls threshold policy only; it does not reconsider endpoint selection. For example, an initial value of 0 followed by 2 still evaluates upper proximity.

### Threshold policy

Threshold storage is persistent output. Its write history is part of the contract even when proximity ultimately fails.

#### Upper endpoint

The scale is captured once and written as the initial threshold. If the second endpoint-policy observation is anything other than 1, this is the only threshold write.

Policy 1 also calculates a half-span from freshly observed upper and lower endpoints: their signed difference divided by two, truncated toward zero.

The final threshold is determined by ordered comparisons:

| Condition | Selected threshold |
|---|---|
| Half-span is strictly less than twice captured scale | Shift-doubled captured scale |
| Otherwise, half-span is strictly greater than fifteen times captured scale | Fifteen times captured scale |
| Otherwise | Half-span |

Equality does not trigger either replacement. These are precedence-sensitive rules, not an unconditional mathematical clamp.

For policy 1, the threshold write sequence is captured scale, then half-span, then a replacement if selected. Calculation timing matters:

- Half-span calculation and multiplication by two occur before the half-span write.
- When the lower comparison selects replacement, shift-doubling also occurs before that write.
- Multiplication by fifteen occurs only when the lower comparison does not select replacement, and occurs after the half-span write.

Consequently, multiplication by fifteen may be bypassed entirely. If that multiplication is reached and violates the arithmetic precondition, threshold storage has already received both the initial scale and half-span writes.

#### Lower endpoint

A zero lower-policy byte selects shift-doubled scale as the sole threshold write. This case does not calculate a half-span.

A nonzero lower-policy byte uses a half-span calculated from a fresh upper endpoint and the retained admission lower endpoint. That half-span is written before scale is read. It is replaced by shift-doubled scale only when strictly less than twice the subsequently captured scale. Equality retains the half-span. No fifteen-times limit applies.

Negative scale is not explicitly rejected. It can participate in defined paths that do not shift it. A reached signed shift of negative scale has no specified ordinary result under the represented arithmetic model.

### Proximity and completion

Proximity uses a fresh observation of the selected endpoint and a read of threshold storage:

| Selection | Qualification requirement |
|---|---|
| Upper | Candidate is strictly greater than upper endpoint minus threshold. |
| Lower | Candidate is strictly less than lower endpoint plus threshold. |

Equality at either proximity boundary returns 0. The boundary addition or subtraction must be representable. Admission is not repeated against the freshly observed endpoint.

Qualification writes state byte 1 before calling F-d806c27da772. Zero completion status produces result 1; nonzero status produces result 0. There is no direct rollback and no post-completion state check.

For stable relevant values, noninterfering storage, and defined arithmetic, an admitted candidate cannot qualify with a nonpositive threshold. This is a consequence of inclusive admission combined with strict proximity, not an explicit threshold-validation operation.

## Side effects

The function’s direct persistent writes are limited to threshold storage and the state byte.

| Ordinary result | Possible direct persistent writes |
|---|---|
| 0 | None; threshold writes only; or threshold writes followed by state 1 |
| 1 | Threshold writes followed by state 1 |
| 3 | None |

This table excludes invocation-local candidate initialization and all dependency effects. It describes writes performed, not guaranteed final values.

Observable ordering includes the following constraints:

- Entry eligibility precedes selection processing.
- Initial address preparation precedes restriction rejection.
- Restriction acceptance precedes local candidate initialization, payload reads, and adjustment.
- Successful adjustment precedes reselection and admission.
- Lower admission precedes the upper admission read.
- Endpoint availability precedes threshold writes.
- Upper scale capture and its threshold write precede the second endpoint-policy observation.
- Nonzero lower policy places the half-span write before scale capture.
- Qualification precedes the state-1 write, which precedes completion.

The relative order of the three adjustment-payload reads is unresolved. The fresh endpoint reads contributing to the upper half-span are also unordered by the available evidence. Within either proximity boundary, the relative order of endpoint and threshold reads is unresolved.

These are static observation constraints, not guarantees of physical access counts, atomicity, synchronization, visibility, or supported concurrent mutation.

No direct allocation or release is established. Candidate storage belongs to the invocation. Passing its address does not establish ownership transfer, permission to release it, or valid retention beyond the invocation.

## Acceptance examples

These examples are conditional deductions from static evidence, not executed tests.

Unless an example says otherwise, assume valid storage, defined reached arithmetic, entry state 4, zero restriction, successful adjustment, stable relevant values, and noninterfering storage. Candidate values are post-adjustment. “Qualifies” means state 1 is written and completion is invoked; result 1 additionally requires zero completion status.

| Condition | Required observation |
|---|---|

| Restriction is nonzero | Result 0, with no payload reads or adjustment; preceding address arithmetic remains required. |
| Only incoming second and third arguments differ | Ordinary defined behavior is unchanged. |

Zero upper availability prevents the scale read and all threshold writes. An initial endpoint-policy value of 0 followed by 2 keeps upper selection and uses the scale-only threshold.
