# F-37c57bf0af98

## Purpose

F-37c57bf0af98 conditionally reads and overwrites bytes through an address supplied as its third argument. Its control flow, addressing, counter progression, and byte transformation depend on eighteen externally stored 32-bit values whose contents are not supplied.

**Established static evidence:** the routine has a dispatcher, two bounded counters, an accumulator, saved address components, byte reads, and byte writes. Its only explicit return is a 32-bit zero.

**Inferred intent:** the state organization resembles a nested traversal that accumulates information from selected bytes and writes one result for an outer iteration. The evidence does not establish an ordinary row/column traversal, a particular reduction operation, or even that the relevant cases are reachable.

**documented_only:** concrete traversal order, input dimensions, buffer extent, termination, and the mathematical meaning of the transformation remain unresolved.

This contract describes conditional behavior established by the supplied static body. No runtime tests have been performed.

### Source-byte addressing and accumulator update

Case 3 reads one byte from the current base plus a computed displacement.

The displacement is constructed by multiplying the saved outer factor by the addressing coefficient and the prepared inner address factor, adding the current outer address component, and applying the addressing coefficient to that combined offset.

This address uses the **current** base but the **saved** outer factor. It also uses prepared address components rather than directly using the current counter values. Consequently, reaching case 3 without fresh preparation can reuse older components.

The source byte is read before the accumulator and inner counter are updated.

The byte transformation has these established properties:

- It depends on the read byte, old accumulator, and three external arithmetic coefficients.
- The shared arithmetic coefficient is interpreted through its signed low 16 bits. A doubled version is narrowed into signed 16-bit storage.
- Separate source-derived and accumulator-derived masks are narrowed to 16 bits, with their low eight bits forced to one.
- The source mask incorporates multiplication by 22017. The accumulator mask incorporates multiplication by 123.
- The source-derived arithmetic additionally incorporates the fixed multiplier 179.
- Two separate arithmetic results are narrowed into signed 16-bit intermediates.
- Those intermediates are combined through coefficient-dependent arithmetic and a bitwise union involving decremented products. The combination includes a fixed subtraction of 97 and final multiplication by −24979.
- Only the low eight bits of the final result become the new accumulator.

The 16-bit masks are promoted for subsequent arithmetic and complements. They must not be interpreted as eight-bit complements merely because their low eight bits are forced to one.

The evidence does not establish that this operation is a sum, exclusive-or reduction, checksum, minimum, maximum, or other conventional byte operation.

After the accumulator update, the inner counter is replaced by the low 16 bits of a product involving the saved counter precursor, the wide-state mixing coefficient, and that coefficient increased by 2496. The precursor comes from case 2; case 3 does not recompute it from the current inner counter.

### Output addressing and outer update

## Acceptance examples

These are conditional static expectations, not executed tests.

1. **Immediate return.** If the initial dispatch difference selects case 6, the result is 32-bit zero. No buffer-byte read or write occurs, although dispatch-control storage is read.

2. **Truncated argument product.** If case 1 executes and the scaled second argument has low 16 bits equal to 65535, the saved value is 65535. Higher product bits do not enlarge that saved value.

3. **Selective reset.** If case 5 executes, the accumulator and inner counter become zero. The pending output byte and saved output base are not cleared by that case.

4. **Pending-byte lifetime.** If case 2 executes with accumulator 1, the pending output byte becomes 123. A later case 3 may change the accumulator, but a subsequent case 8 still writes 123 unless another case 2 has replaced the pending byte.

5. **Saved precursor reuse.** If multiple case-3 executions occur without another case 2, their inner-counter updates reuse the same saved precursor. An ordinary incrementing traversal must not be assumed.

6. **Read-before-update.** A case-3 read uses the already prepared address components. Its subsequent inner-counter update cannot change the address of that same read.

7. **Write-before-update.** Case 8 performs its byte store before updating the outer counter. If the store validly aliases a coefficient read afterward, the later update can observe altered coefficient storage.

8. **Default processing.** An unmatched dispatch difference executes outer preparation and selection. It is not an invalid-input return.

9. **Gate sign boundaries.** Under arithmetic signed-right-shift semantics, zero takes the unchanged inner or outer selector. A negative result takes the inner selector increased by five or outer selector reduced by five, subject to target arithmetic.

10. **Invalid address.** If a reached address is inaccessible, no explicit error-return branch handles that condition. Fault behavior belongs to the target environment, not to a visible recovery contract.
