# F-082c6eec1c39

## Purpose

F-082c6eec1c39 is a globally controlled routine that can replace bytes in caller-addressed storage. Each replacement depends on an existing caller byte, reference data, numeric working state, and arithmetic globals. Global destinations determine whether execution initializes state, processes another byte, performs a decision, returns, or cycles.

Every explicit return produces the 32-bit value zero. Zero does not establish success, equality, a processed-byte count, or even that caller storage was accessed. Termination is not established for arbitrary global contents.

**Inferred intent:** the reference-dependent replacement and subsequent decisions suggest transformation or checking. No particular encoding, cryptographic operation, validation protocol, or success convention is established.

Caller storage, reference storage, and global storage are not required by the visible routine to be disjoint. A caller-byte store can therefore change reference data, a control destination, a coefficient, or part of the reference-base value.

## Behavior

The representation distinguishes:

The normalized relations below are conditional on a machine model with 32-bit wrapping arithmetic where needed, arithmetic signed right shifts, low-bit narrowing, and two’s-complement signed interpretations. Complete target-language overflow and address-conversion rules were not supplied.

Notation:

### Entry and dispatch

The caller base, both status fields, active value, companion value, phase, residue, and transition seed begin at zero. The initial-control global is captured once.

Every dispatch performs these reads in order:

1. Read coefficient B into a 32-bit dispatch snapshot.
2. Read coefficient A into a separate 32-bit dispatch snapshot.
3. Read the selector-base global.

The selector is the current control value minus that freshly read selector base. Recognized selectors are 0 through 11. Any other selector returns zero.

These reads occur even for a selector that immediately returns. Dispatch snapshots remain separate from later coefficient reads; subsequent stores do not retroactively change them.

### Ordered reads and the byte store

2. Reread coefficient A and narrow the captured value to signed 16 bits.

4. Derive companion-dependent quantities.
5. Load the old caller byte.
6. Evaluate the replacement, including a second reference load through another fresh reference-base read.

- Updates the companion from the transition seed.

## Side effects

Each completed processing operation performs:

- Two pre-store reference-byte loads, each with its own reference-base read.
- One old-caller-byte load.
- One caller-byte store.
- One additional post-store reference-byte load only if a special discriminator branch executes.

There is one explicit external write site, and its width is one byte. Repeated visits can overwrite the same byte.

No explicit global assignment is visible. Nevertheless, a caller-byte store can modify global storage through aliasing. The effect of changing one byte of a wider global depends on layout and byte order.

## Acceptance examples

These are conditional static acceptance criteria, not executed tests.

1. **Immediate return still reads globals.**  
   If the entry dispatch selects 7 or an unrecognized selector, it reads B, then A, then the selector base before returning zero. No processing store occurs.

2. **Normalized replacement.**  
   Suppose a completed processing operation captures companion byte zero, old caller byte 10, second reference byte 3, coefficient A low byte 7, and coefficient B low byte 2. Under the stated arithmetic model, it stores:
   \[
   [10+157(3)+15(7-2)+143]_{256}=187.
   \]

3. **First reference value is not permission to omit its load.**  
   Holding all captured replacement operands fixed, changing only the first reference byte does not change the stored byte. An unreadable first reference address can nevertheless prevent the operation from reaching the store.

4. **Pre-store ordering remains observable.**  
   The first reference load precedes the separate A and B captures and the old-caller-byte load. The second reference load occurs before the store.

5. **Post-store exact alias.**  
   If a special branch’s later reference address identifies the stored caller byte, and ordinary memory remains stable after the store, that reference load observes the replacement.

6. **Reference-base alias can redirect access.**  
   If the caller store changes the reference-base global, the special branch uses the changed value when forming its later reference address. An earlier caller/reference alias does not guarantee a later alias.

7. **Sufficient conditions for equal reference samples.**  
   Equal effective addresses and stable ordinary-memory contents are sufficient to guarantee equal reference-byte results. They are not necessary: different addresses can contain equal bytes, and changing contents can produce equal sampled values. Disjoint caller and reference data alone does not guarantee address stability if the caller store can modify the reference-base global.

8. **Captured and fresh B differ.**  
   In a discriminator-one operation that changes B through the caller store, the replacement-side decision quantity still uses dispatch-captured B; the reference-side quantity uses a fresh B read.

9. **Nonspecial companion.**  
   Companion byte 1 produces discriminator −87. The caller store still completes, but neither special post-store reference load occurs.

10. **Signed offset boundary.**  
    In the qualified processing–continuation sequence, offset 127 is followed by −128. This is modulo-256 progression, not forward contiguous addressing across that boundary.

11. **Partial progress persists.**  
    A later fault or control cycle does not undo an already completed byte store.
