# F-c5a232e4455b

## Purpose

F-c5a232e4455b selects between two sources of a pointer-sized result:

- When a 32-bit field in the supplied object equals the supplied 32-bit selector, it attempts to remove and return the first entry from an object-associated chain.
- When the fields differ, or the matching object has an empty chain, it returns the result of F-5e43693288bd.

The established behavior is a conditional head removal followed, when necessary, by a fallback call. Describing the chain as a free list, the selector as an allocation size, or the surrounding calls as locking and unlocking is inferred intent, not an established contract.

The function does not itself initialize the returned entry, clear its first word, validate the selector, or check whether the fallback result is null.

This specification describes the supplied static representation. No runtime tests have been performed.

## Interface

### Inputs

The function has two explicit inputs:

| Input | Represented width | Role |
|---|---:|---|
| Object reference | 32 bits | Address of storage containing the comparison field and chain-head field. |
| Selector | 32 bits | Compared with the object’s comparison field and forwarded unchanged to the fallback dependency. |

The object reference is represented as an integer used in address calculations. Its operational role is an address, not an arithmetic quantity supplied for calculation.

The selector is represented as a signed integer, but its local use is an equality comparison. No ordering comparison, sign-dependent branch, scaling, or range check appears. Consequently, the local decision depends on equality of the represented 32-bit values, including values whose high bit is set.

### Object and entry layout

The function accesses the following locations relative to the object reference:

| Byte offset | Accessed width | Meaning within this function |
|---:|---:|---|
| 8 | 32 bits | Comparison field. |
| 24 | 32 bits | Address of the current chain head, or zero for an empty chain. |

A nonzero chain head must refer to storage whose first 32-bit word can be read. That word is used as the next chain-head value.

These are access requirements, not a complete object layout. The representation establishes neither the total object size nor the meaning of intervening fields. It also does not establish the size or structure of an entry beyond its readable first word.

### Output

The return value is represented as a pointer to 32-bit words.

There are two sources for that value:

1. The nonzero chain-head address captured after F-338d16f9ce72 returns.
2. The result of F-5e43693288bd, interpreted as the function’s pointer result.

The fallback result is returned without a local null check or other validation. A zero result from the fallback is therefore returned as zero if the dependency returns normally.

### Preconditions for defined execution

The object’s comparison field must be readable at entry. A null or otherwise invalid object reference is not rejected before this read.

On the matching branch, after F-338d16f9ce72 returns, the chain-head field must be readable. If its value is nonzero, the pointed-to first word must be readable and the chain-head field must be writable.

The fallback path also requires the global reference used to obtain its first argument to be readable.

No explicit bounds, alignment, address-overflow, or pointer-validity checks appear. Required alignment and fault behavior depend on the actual execution environment and remain unspecified here.

## Behavior

### Initial comparison

The first represented object access reads the 32-bit comparison field at byte offset 8. Its value is compared with the selector.

This comparison occurs before either object-oriented dependency is called.

If the values differ, the function skips both F-338d16f9ce72 and F-1333331b2da1. It also skips any direct access to the object’s chain-head field and proceeds to the fallback.

If the values match, the function calls F-338d16f9ce72 with the object reference.

There is no second comparison after that call. A change to the comparison field during the call does not cause the function to reconsider the branch already selected.

### Matching branch with a nonempty chain

After F-338d16f9ce72 returns normally, the function reads the 32-bit chain-head field at byte offset 24.

If this field is nonzero, the function:

- Captures that address as the eventual return value.
- Reads the first 32-bit word at that address.
- Writes the word just read into the object’s chain-head field.
- Calls F-1333331b2da1 with the object reference.
- Returns the captured address if that call returns normally.

The read of the entry’s first word precedes the write to the object’s chain-head field. The write precedes the call to F-1333331b2da1.

The returned address is the captured head, not a fresh read of the object’s head after F-1333331b2da1. That dependency may change the object or other state; no preservation guarantee is established.

The removed entry’s first word is not cleared or rewritten directly by this function. In an ordinary non-aliasing layout, it retains the successor value that was read. Dependencies may nevertheless modify that storage, and aliasing can make the head-field write affect it.

No fallback call occurs on this path when the represented calls return normally.

### Matching branch with an empty chain

If the chain-head read after F-338d16f9ce72 yields zero, the function calls F-1333331b2da1 with the object reference and then proceeds to the fallback.

This empty-chain path performs no direct write to the object’s head field and no entry-word read.

The fallback remains selected even if F-1333331b2da1 subsequently populates the chain. The function does not re-read the head or retry the removal.

### Fallback

The fallback is reached in either of these cases:

- The initial comparison does not match.
- The initial comparison matches, but the head read after F-338d16f9ce72 is zero.

The fallback sequence is:

1. Call F-2fd8826557a4 with no explicit arguments.
2. Obtain the first fallback argument by dereferencing the global reference represented in the supplied evidence.
3. Call F-5e43693288bd.
4. Return its result without further local processing.

The eight represented argument positions supplied to F-5e43693288bd are:

| Position | Supplied value |
|---:|---|
| 1 | Value obtained through the global reference. |
| 2 | Original 32-bit selector. |
| 3 | Zero. |
| 4 | Two. |
| 5 | Zero. |
| 6 | Zero. |
| 7 | Zero. |
| 8 | Incoming link-register-related value shown by the static representation. |

The global dereference occurs after F-2fd8826557a4 returns. On the matching-but-empty path, it also occurs after F-1333331b2da1 returns. The function must not be understood as having captured the first fallback argument before either call: either dependency could affect the global state used to obtain it.

The meaning and exact calling-convention status of the eighth represented argument are uncertain. It is not a third explicit input in the displayed function interface.

### Arithmetic and edge behavior

The local address calculations use fixed byte offsets of 8 and 24. The selector is not used to compute an address or byte count within this function.

No local arithmetic is performed on the selector. Zero, high-bit-set values, and other selectors follow the same equality-and-fallback decision structure.

No cycle detection or chain validation occurs. For example, if a head entry’s first word contains its own address, the function writes that same address back as the head and returns it. The local operation does not guarantee that the head advances.

## Side effects

The only explicit memory write performed by the function is the update to the object’s chain-head field on a matching, nonempty path.

That write copies a 32-bit value read from the selected entry. It does not construct, validate, or normalize the successor address.

Additional effects may occur inside any called dependency. The supplied evidence does not establish that these calls:

- Preserve global state or object fields.
- Leave entry storage allocated or unchanged.
- Acquire or release a lock.
- Allocate, free, or transfer ownership of memory.
- Return normally.
- Provide synchronization or memory-ordering guarantees.

The calls surrounding the head operation resemble a guarded region, but that interpretation is inferred. The direct head read and write are not shown as an atomic read-modify-write operation. Thread safety therefore cannot be established from this function alone.

On normal paths, each call to F-338d16f9ce72 is followed by one call to F-1333331b2da1. This is an ordering observation, not a guarantee of cleanup after faults or nonlocal control transfer.

Returning an entry address establishes only which address is returned. It does not establish ownership transfer, permission to free the entry, or a lifetime guarantee. In particular, the function calls F-1333331b2da1 between capturing that address and returning it.

## Acceptance examples

These are conditional static acceptance cases, not observed test results. Each assumes the required accesses are valid and the relevant dependencies return normally.

### Matching selector and one available entry

Suppose the comparison field equals the selector. After F-338d16f9ce72, the head points to an entry whose first word is zero.

Expected behavior:

- The head becomes zero before F-1333331b2da1 is called.
- The captured entry address is returned after that call.
- Neither fallback dependency is called.

This does not imply that the returned entry’s contents or lifetime survive F-1333331b2da1.

### Matching selector and multiple linked entries

Suppose the head observed after F-338d16f9ce72 points to entry A, and A’s first word contains the address of entry B.

Expected behavior:

- The function writes B’s address to the object’s head field.
- It then calls F-1333331b2da1.
- It returns A’s captured address, regardless of whether that dependency changes the head again.

With distinct, non-aliasing storage and no dependency mutation, A’s first word remains B’s address.

### Mismatching selector despite an available head

Suppose the comparison field differs from the selector, while the object otherwise contains a nonzero head.

Expected behavior:

- Neither object-oriented dependency is called.
- The function does not directly read or update the head.
- It calls F-2fd8826557a4 and then F-5e43693288bd.
- It returns the latter dependency’s result.

The presence of a usable entry does not override the mismatch.

### Empty matching chain populated by the later call

Suppose the initial comparison matches, but the head read after F-338d16f9ce72 is zero. F-1333331b2da1 then installs an entry.

Expected behavior:

- No second head read occurs.
- The function still takes the fallback.
- The newly installed entry is not selected by this invocation’s local removal operation.

### Head changed by the first dependency

Suppose the object’s head is zero before entry, but F-338d16f9ce72 installs a nonzero head.

Expected behavior:

- The function uses the post-call head.
- It reads that entry’s first word and updates the head.
- It returns the captured entry after F-1333331b2da1, rather than taking the fallback.

### Null fallback result

Suppose fallback is selected and F-5e43693288bd returns zero.

Expected behavior: the function returns zero without retry, local error conversion, or an additional dependency call.

### Invalid entry address

Suppose the matching branch observes a nonzero head that does not permit reading its first 32-bit word.

The representation contains no validation or recovery before that read. Fault behavior, and whether any later call occurs, are outside the established contract. A guaranteed call to F-1333331b2da1 must not be assumed in this case.
