# F-733c25c05777

## Purpose

F-733c25c05777 constructs three-field memory records, invokes a sequence of dependencies, replaces address-bearing state, and conditionally repeats either the dependency cycle or the record stage.

Its observable behavior consists of ordered memory accesses, shared-state assignments, indirect calls, and a conditional selector-4 software breakpoint. No ordinary return, completion notification, or error result is visible.

The application purpose is unknown. Record writes do not establish publication, synchronization, persistence, or ownership transfer.

This contract describes static evidence only. Some expressions have unresolved execution semantics, particularly an entry-selecting right shift by the apparent operand width. Described paths are therefore conditional on applicable arithmetic, conversion, memory-access, and continuation rules.

## Behavior

### Numerical rules

Unsigned 32-bit calculations retain their results modulo \(2^{32}\). This applies to the unsigned payload and working-word calculations and to address additions explicitly performed in unsigned 32-bit form.

That rule does not establish wrapping behavior for signed expressions. Signed overflow, signed shifts, pointer-to-signed-integer conversions, and out-of-range narrowing require execution rules not supplied here.

The following distinctions are material:

- Explicit upper-half extraction selects bits 63–32 of a 64-bit result.
- Converting a complete 64-bit result to signed 32-bit or signed 16-bit form does not itself establish low-bit truncation.
- Converting a complete 64-bit result to a pointer does not establish a 32-bit address.
- Storing a numerical value does not establish its byte order.

### Record stage

Each record stage first captures the composite’s upper 32 bits as a pointer. This captured pointer has two conditional uses:

- On zero entry, it receives the updated index in a four-byte store.
- On nonzero entry, after breakpoint continuation, its signed 32-bit conversion supplies the working-word calculation.

Capturing the pointer does not read through it. The two uses belong to alternative entry paths.

After capture, the explicit effects occur in this order:

| Order | Effect |
|---:|---|
| 1 | Store the current record pointer, using pointer width, at the address calculated by multiplying the signed index by two. |
| 2 | Store the complete eight-byte composite at the address obtained by converting that complete composite to a pointer. |
| 3 | Replace the index with four times the record pointer’s signed 32-bit conversion. |
| 4 | Derive the working word by shifting the source pointer’s signed 32-bit conversion left by eight and assigning the result to unsigned 32-bit state. |
| 5 | Write the three record fields in increasing address order. |

The record layout is:

| Byte offset | Width | Content |
|---:|---:|---|
| 0 | 4 bytes | Current payload |
| 4 | 4 bytes | Working word |
| 8 | 4 bytes | Source pointer converted to unsigned 32-bit form |

The index calculations and working-word derivation contain signed arithmetic. Their validity cannot be inferred from the eventual destination type.

The computed stores may overlap the record or other storage used later. No nonaliasing guarantee is supplied.

### Zero entry

If the branch quantity is zero:

1. Assign numerical zero to the shared destination.
2. Increase the current index by the payload.
3. Store the updated index in four bytes through the pointer captured from the composite’s upper half.
4. Enter the dependency cycle with signed immediate argument zero.

The addition combines signed 32-bit index state with an unsigned 32-bit payload. It therefore uses unsigned 32-bit arithmetic before assignment back to signed index state. Conversion of an out-of-range result back to signed form remains unresolved.

This path retains the record-stage working word. It does not explicitly invoke the breakpoint or perform the nonzero path’s link-state initialization.

### Nonzero entry

If the branch quantity is nonzero:

1. Store the branch quantity in four bytes at payload multiplied by 256, plus 32. Both arithmetic operations are unsigned 32-bit.
2. Set link state to the entry continuation.
3. Prepare the immediate argument by converting the unsigned 32-bit product of payload and 256 to signed 32-bit form, then shifting right by 29.
4. Invoke the selector-4 software breakpoint.
5. If execution continues, replace the working word with the captured upper-half pointer’s signed 32-bit conversion shifted right by 18, assigned to unsigned 32-bit state.
6. Enter the dependency cycle.

The post-breakpoint working word uses the same captured pointer that the zero path uses as its index-store destination. It does not use a newly extracted pointer or dereference that pointer.

The immediate argument is derived from an unsigned product followed by signed conversion; it is not a signed multiplication of the original payload. Negative signed right shifts and breakpoint effects remain unresolved.

F-DEP-01 receives the signed 32-bit immediate argument and supplies a 64-bit result. Its target depends on current link state.

After F-DEP-01 returns, these accesses occur in order:

|---:|---|

The first stored value is a conversion of the complete 64-bit result, not an explicit selection of its lower 16 bits.

For the fourth access, the signed 16-bit pointer conversion is promoted for addition. Adding four fits within signed 32-bit arithmetic, but the result can exceed signed 16-bit range when stored. - Its explicitly extracted upper 32 bits replace the record pointer.
- Its complete value is converted to signed 32-bit form and multiplied by 32 using signed arithmetic. Assignment to unsigned 32-bit state produces the decision word.

Before testing the decision word, the operation stores it in four bytes at the address represented by that same word.

The unsigned comparison selects:

- Decision words from 0 through 19: repeat the dependency cycle with immediate argument zero.
- Decision words greater than 19: perform the outer transition.

Repetition captures a fresh cycle-entry byte. There is no intervening explicit working-word replacement or restoration of the nonzero-entry link initialization.

If the signed conversion and multiplication are defined, the resulting decision word is a multiple of 32. Under those conditions, zero is the only repeating value. Its four-byte store at address zero still precedes repetition.

### Both uses of the captured pointer

Suppose the composite’s upper half represents address 262,144.

On zero entry, the updated index is stored in four bytes at address 262,144.

On nonzero entry, if the breakpoint continues and signed conversion yields 262,144, shifting right by 18 produces working word 1. That calculation does not read memory at address 262,144 and does not perform the zero-entry index store.

Thus the captured pointer participates in both entry alternatives, with different roles.

### Entry argument

On zero entry, the shared zero assignment precedes the updated-index store, and the cycle receives immediate argument zero without an explicit breakpoint.

On nonzero entry with payload `0x00800000`, unsigned multiplication by 256 produces `0x80000000`. If signed conversion yields −2,147,483,648 and negative right shift is arithmetic, the immediate argument is −4. The breakpoint precedes the working-word replacement and dependency cycle.

### Complete-result conversions

If F-DEP-01 returns 4,660, signed 16-bit conversion is representable and the first cycle store receives that numerical value.

A result of `0x0000000100001234` does not establish the same stored value merely because its lower 16 bits match. That requires an additional narrowing rule.

If F-DEP-05 returns 1, the defined signed calculation produces decision word 32. The four-byte store of 32 at address 32 precedes the outer transition.

A result of `0x0000000100000001` requires an additional complete-result conversion rule before asserting the same outcome.

### Repetition and aliasing

A zero decision requires a four-byte zero store at address zero before repetition. Address-zero writability is not implied.

If the two-byte pointer-fragment store overlaps replacement-pointer lookup storage, the pointer read occurs after that store. Moving the lookup before the store would violate the explicit order.

### Retained byte and final destinations

Assume cycle-entry payload `0x123456AB`, a source read yielding 32, no relevant dependency interference, and an outer transition.

F-DEP-04 receives 32; F-DEP-05 receives 4. The retained byte pattern is `0xAB`, not a byte recaptured from 32. It supplies the shared assignment, subject to that destination’s conversion rules, and the first final byte store.

If F-DEP-07 returns 16, the final byte destinations are addresses 32 and 24. Its extracted upper half is zero.

A result of `0x0000000100000010` establishes those same destinations only under an additional complete-result conversion rule; its extracted upper half is instead one.
