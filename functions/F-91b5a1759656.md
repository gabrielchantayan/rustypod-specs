## Acceptance examples

These are conditional static acceptance examples, not executed tests. Each assumes the required calls return and relevant accesses are valid.

1. **Fourth-input extraction.** A fourth input of 0xFFFFFFFF supplies 511 as F-D001’s third displayed argument. A value of 0x007FFFFF supplies zero. Changing only the lower 23 bits does not change that argument.

2. **Low-byte copy and repeated read.** If the first index is 0x100, the initial word read is at 0x474 and the byte write is at 0x401. A source word of 0x123456AB produces a byte value of 0xAB. If intervening calls change the source word’s low byte to 0xCD, the repeated copy writes 0xCD.

3. **Scaling truncation.** Under 32-bit bit-pattern arithmetic, a second index of 0x40000001 produces a second scaled value of 4. F-D025 receives 0x00010000, not a reconstruction retaining the original top bits.

4. **Captured-word distribution.** If the third-index word read yields 0xA1B2C3D4, the immediate byte write uses 0xD4. The later writes through the fourth and fifth indices use the complete captured word, not fresh reads from its original source address.

5. **Wide-result split.** If F-D052 supplies high word 3 and low word 5, the next word write stores 20 at address 0x20. F-D053 receives 20, 3, 20, and 20.

6. **Table-mediated addressing.** If the first table lookup returns byte 0xFE and the saved-base word is 0x123456AB, the resulting byte write stores 0xAB at address 0x10F.

7. **Second extracted byte.** A saved-base word of 0xFFC00000 contributes 0xFF to the second table-mediated write, because bits 22–29 are selected.

8. **Final halfword clear.** If the second low word is 0xFFFFFFFF, the final halfword-clear address is 0x007FFFFF. This address is odd; success depends on the target’s alignment behavior. If the preceding byte clear faults, the halfword clear and F-D080 are not reached.
