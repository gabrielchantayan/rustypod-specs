# F-ae42cf8694e5

### Opening direct-memory effects

The direct-memory region begins after the last invocation of the leading phase. Its bases include a final low result scaled by 256, the final high result portion, earlier captured values shifted or scaled by 2²⁵, and a doubled extracted quantity.

The opening access order is significant. A word is first written at offset 0x14 from the final high portion, followed by a byte at offset 9 from an earlier shifted base. A word write at offset 0x54 from the final low portion scaled by 256 precedes an overwrite of that same offset-9 byte.

The function then clears a word at offset 0x14 from the 2²⁵-scaled base, reads an unsigned byte at offset 5 from that base, clears a word at offset 0x14 from the doubled extracted base, and copies the captured byte as a zero-extended word to offset 0x34 from the 2²⁵-scaled base.

A subsequent word read at offset 0x14 from the scaled base supplies further addressing. The earlier clear does not make this read unconditionally zero: intervening writes may alias it, and external or nonordinary memory behavior is not excluded.

Duplicate clears and duplicate byte writes remain separate represented accesses.

### Early absolute inputs and writes

The read at absolute 0x05 occurs after the initial clears and duplicated calculated-address byte writes, and **before** the byte write at absolute 0x01.

The value observed at 0x05 is converted to an unsigned 32-bit address-base value and retained. The byte written to 0x01 is the low byte of the doubled extracted quantity. Subsequent operations use the retained 0x05-derived value, including a byte destination at offset 0x15 and a word source at offset 0x54.

The word at that offset-0x54 source is captured before the same location is overwritten with the earlier read-after-clear value. This captured word subsequently drives scaling and self-relative writes. Call it the **link seed**; that label establishes no object type.

Later, a 32-bit write to absolute 0x54 stores the link seed shifted left by one. This occurs before the byte write to absolute 0x15. Between those absolute writes, the function writes the link seed twice to a calculated offset-0x14 word destination and writes the low byte of four times the link seed twice to a calculated offset-0x15 byte destination. The later absolute 0x15 store receives the low byte of the doubled extracted quantity.

Thus, absolute 0x54 and absolute 0x15 are ordered state changes, not merely addresses appearing in an access inventory. Calculated accesses between them can overlap either location.

### Pointer-derived updates and mixed-width constants

A later word obtained through an offset-5 byte-derived base is doubled to form a base retained through the final phase. In the remainder of this contract:

- **Retained working base** means that captured doubled value.
- **Adjusted value** means four times the link seed, reduced by 0x96.

Absolute 0x67 is subsequently read twice more:

1. The next read supplies a byte store at buffer-base offset 9, after intervening writes involving the buffer base, captured global base, and retained working base.
2. Following a byte write at retained-working-base offset 9, a word write of the captured absolute-0xa9 value at buffer-base offset 0x44, and a word read at buffer-base offset 0x54, another fresh 0x67 read supplies another byte store at buffer-base offset 9.

## Acceptance examples

These are conditional review scenarios, not executed tests.

### Unsigned widening and repeated writes

If an explicit unsigned byte load observes 0xe3, its word-width copy is 0x000000e3, not a sign-extended value.

If an observer records the opening offset-9 destination, both represented byte writes must appear in order. Retaining only the final byte value is insufficient.

### Early global ordering

If execution reaches the early absolute accesses, the read at 0x05 precedes the byte write at 0x01. Later calculated accesses use the value captured from 0x05, even if an intervening store changes that absolute input.

The word store at absolute 0x54 precedes the later byte store at absolute 0x15. The intervening calculated writes are not omitted.

### Global-base capture

Suppose the global-base input contains one address when captured, and the immediately following absolute 0x60 word store aliases and changes that input. Subsequent global-relative destinations still use the captured address, not its overwritten contents.

This scenario is conditional on a platform layout permitting that alias.

### Absolute byte reloads

Suppose absolute 0x67 receives 0x11 from the captured 0xa9 word. If intervening calculated writes change 0x67 to 0x22 before a later read, that read supplies 0x22. If the first calculated offset-9 store itself changes 0x67 again, the final read must observe the value then available, not a cached predecessor.

### Final captures survive mutation

Suppose retained-working-base offset 0x14 contains 0x11223344 at its early capture and is later overwritten. The third argument remains 0x11223344.

If the companion-base offset-0x74 source changes because of the preceding halfword or decimal-100 store, the fourth argument reflects its later load. Changes caused by the remaining final writes do not retroactively change that captured argument.

### Width and arithmetic boundaries

The three 0x3a stores require distinct 8-, 16-, and 32-bit accesses.

For unsigned 0xffffffff, retaining 20 bits and shifting right by 10 produces 1023. Under confirmed low-32-bit arithmetic, zero-derived addresses are still used without a represented rejection branch; their platform consequence remains unresolved.
