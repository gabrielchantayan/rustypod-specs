# F-a2ac4e171e52

## Purpose

F-a2ac4e171e52 replaces a 16-byte state in place with bytes selected from caller-supplied lookup memory.

When the function’s observations of one global word agree, each destination uses its own 256-byte lookup region. A fixed permutation determines which state byte indexes that region. Under ordinary, non-overlapping memory conditions, the result is a position-dependent substitution of the permuted entry-state bytes.

Agreement of the global observations is a condition of that simplified description, not an enforced precondition. Unequal observations can move lookup addresses outside their nominal regions, including outside the nominal 4,096-byte table.

The function neither snapshots lookup memory nor checks for overlap. Its ordered reads and writes therefore matter when the state overlaps lookup storage.

No particular cryptographic algorithm or application-level purpose is established.

## Interface

The function accepts two explicit inputs and has no explicit return value.

| Input | Meaning | Requirement for successful ordinary execution |
|---|---|---|
| State address | Beginning of the mutable state | State offsets 0 through 15 must be readable and writable. |
| Lookup base | Integer-valued address used as the origin for lookup accesses | Every address selected during execution must be readable. |

There is no length, capacity, table descriptor, ownership descriptor, or error-output argument.

The state consists of 16 consecutive bytes. All explicit state accesses are single-byte accesses. No stronger alignment requirement is evident.

The lookup base is supplied as an integer rather than a typed table pointer. Its conversion to an address depends on the target execution model.

The function also observes one global integer-valued storage location. There are three source-level observations of that same location, all before the first state write. No explicit assignment to the global location appears.

The three observations have different roles:

| Observation | Timing | Use |
|---|---|---|
| Saved observation | Before reading state offset 0 | Used by every lookup except the first |
| Reference observation | After reading state offset 0 | Influences all 16 lookup addresses |

All three refer to the same global storage location. They are not three independent global inputs.

The reference observation is retained in incremented form by the supplied representation. The normalized address rule below describes its effect using the observed word before that increment; it does not require an extra global read.

The first-lookup observation occurs before the first lookup byte is read and before the first state byte is written. The expression containing it does not establish a finer evaluation order among its arithmetic operands.

After the first write, subsequent lookups use retained global-derived values. No further source-level global observations appear.

### Normalized lookup-address contract

Unequal observations do not imply rejection or a separate processing mode. They alter the selected address.

For one lookup, define:

- \(d\): destination offset, from 0 through 15.
- \(x\): selected byte, from 0 through 255.
- \(B\): the reference observation.
- \(R\): the first-lookup observation for destination 0, or the saved observation for every other destination.

Represent \(B\) and \(R\) as integers from 0 through \(2^{32}-1\). Let \(\operatorname{byte}(z)\) denote the residue of any integer \(z\) in the range 0 through 255.

The selected address is the lookup base plus the nominal offset \(256d+x\), adjusted by a correction \(C\), with the completed address reduced modulo \(2^{32}\).

The correction has two input ranges.

**For selected bytes 0 through 108:**

\[
C=B-R.
\]

In this range, the difference between the observations directly shifts the nominal lookup address.

**For selected bytes 109 through 255:**

Define a byte phase:

\[
p=147(x-109).
\]

Then:

\[
C=(R-B)+2\bigl(\operatorname{byte}(B-p)-\operatorname{byte}(R-p)\bigr).
\]

This range depends on both the full-word observation difference and the observations’ byte residues relative to the selected byte. It cannot generally be modeled as the same constant shift used for bytes 0 through 108.

These are normalized behavioral formulas, not a prescribed evaluation sequence. Their intermediate differences are mathematical integers; the final address is a 32-bit word under the stated model.

Several consequences follow:

- If \(R=B\), the correction is zero for every selected byte.
- Equal observations therefore recover the destination-specific 256-byte regions.
- Destination 0 can deviate while all later lookups follow the nominal rule, if only the first-lookup observation differs.
- Conversely, destination 0 can follow the nominal rule while later lookups deviate.
- Unequal observations do not guarantee an out-of-region address, but confinement to the nominal region is no longer assured.
- Full-word differences matter. Comparing only the low bytes of the observations is insufficient.

For the upper range, the phase lies between 0 and 21,462. Each byte residue lies between 0 and 255, so the doubled residue difference lies between −510 and 510. This bounded term does not bound the full correction, which also contains the full-word observation difference.

### Aliasing and external changes

No overlap check appears.

If a state write changes a byte that a later lookup selects, that later lookup uses the changed byte. A complete lookup-memory snapshot taken at entry is therefore not generally equivalent.

If state storage aliases the global location, state writes may change that storage. However, all three source-level global observations have already occurred before any state write. Such later changes do not cause the function to refresh its retained global-derived values.

External changes to not-yet-read state or lookup bytes can affect later accesses. This observation does not establish a supported concurrency model: synchronization, atomicity, memory-mapped-device behavior, and language-level data-race semantics are not supplied.

## Acceptance examples

These are conditional static acceptance criteria, not executed test results. Unless stated otherwise, assume the 8-bit-byte, 32-bit modular model, valid addresses, ordinary memory, and no external modification.

### Destination-specific substitution

Assume all global observations agree and state storage is separate from lookup storage.

If entry-state byte 13 is 42 and lookup offset 298 contains 167, destination byte 1 becomes 167:

\[
298=256\cdot1+42.
\]

The lookup must not use region 13 merely because state offset 13 supplies the index.

### Index boundaries

With equal observations, selected bytes 0, 108, 109, and 255 select offsets 0, 108, 109, and 255 within the destination’s region.

The transition between selected bytes 108 and 109 does not create a discontinuity in the equal-observation result. Selected byte 255 addresses the last byte of its region, not the first byte of the next region.

### Identity regions

Suppose every region stores its byte index: position 0 contains 0, position 1 contains 1, and so forth through 255.

With equal observations, separate storage, and entry-state bytes 0 through 15 respectively, the final state is:

**0, 13, 10, 7, 4, 1, 14, 11, 8, 5, 2, 15, 12, 9, 6, 3.**

### Retained source value

Suppose entry-state byte 1 is 23 and entry-state byte 13 is 91.

With equal observations and separate storage, destination 1 uses region 1, index 91. Destination 5 later uses region 5, index 23, despite the intervening overwrite of state offset 1.

### Unequal observation affecting only the first lookup

Suppose the saved and reference observations are both 0, the first-lookup observation is 1, and state byte 0 is 0.

The first lookup selects the address one byte before the lookup base, interpreted through the target’s modular address model. Later lookups have zero global correction.

The byte before the base must be readable for this example to complete; an ordinary 4,096-byte table alone does not establish that requirement.

### Different effects across the two byte ranges

Suppose the saved and first-lookup observations are 256, while the reference observation is 0.

If state byte 0 is 0, destination 0 reads at lookup offset −256.

If state byte 4 is 109, destination 4 reads at lookup offset 1,389:

\[
256\cdot4+109+256=1389.
\]

Thus the same observation difference shifts these two lookups in opposite directions.

### Byte-residue boundary

Suppose state byte 0 is 110, the reference observation is 146, and the first-lookup observation is 147.

For this selected byte, the phase is 147. The two relevant byte residues are 255 and 0, producing a correction of 511. The first lookup therefore reads offset 621, not offset 109 or 111.

This case distinguishes the upper-range rule from an assumed uniform one-byte shift.

### Lookup overlap

Suppose an earlier destination write aliases the address selected by a later lookup. If no intervening operation changes that address, the later lookup reads the value written earlier.

Acceptance must follow the access schedule, not a hypothetical entry-time lookup snapshot.
