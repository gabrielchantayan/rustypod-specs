# F-722079fa46fb

## Purpose

F-722079fa46fb conditionally associates a derived object with a target interface, then consumes a stream of unsigned 32-bit values. Each nonzero stream value selects a bitmap word and a bit within that word. A query dependency determines whether this function performs a counter increment and a bit-setting update for that value.

Processing can end before association when either the target-interface lookup returns zero or a subsequently obtained descriptor pointer is zero. Once association returns, stream processing is optional: an externally selected initial cursor may be zero.

“Target,” “descriptor,” “association,” “counter,” and “bitmap” identify observable roles, not established application concepts. In particular, the evidence does not establish that the counter measures distinct values, that the query inspects the bitmap modified here, or that association transfers ownership.

This contract describes static evidence and its limits. It does not assert successful execution for invalid addresses, unchecked arithmetic overflow, or dependencies that fail to return normally.

## Behavior

### Eligibility and descriptor resolution

The first pair word supplies the argument to F-283eda65a14c. F-682adfd5a561 receives that result together with the literal value 5.

A zero result from F-682adfd5a561 ends processing. On this path there is no call to F-ed4b1fd8953e, no descriptor preparation, no association, and no cursor access.

For a nonzero target interface, F-ed4b1fd8953e receives the original context and selector. Its result supplies the descriptor-pointer field at offset 8. A zero descriptor pointer ends processing before preparation or association. This early exit does not protect against an invalid containing result: the field read has already been attempted.

### Preparation and derived-object acquisition

Preparation uses three dependencies in a fixed call order: F-9d0ecc5f6adf, F-5710a8628cba, and F-59c1430f85c2.

F-5710a8628cba receives the result of F-9d0ecc5f6adf, a value read from an external datum, and the descriptor’s first word. Its argument reads therefore occur after F-9d0ecc5f6adf returns. Their relative order is not established.

F-59c1430f85c2 receives writable selector storage, the result of F-5710a8628cba, the low 16 bits of the descriptor word at offset 4, and the descriptor byte at offset 12. Those descriptor reads occur after F-5710a8628cba returns; their relative order is not established.

The return value of F-59c1430f85c2 is ignored. Changes made through the selector address can nevertheless determine the next dispatch. They do not change the selector value already passed to F-ed4b1fd8953e.

Derived-object acquisition uses the selector copy as it exists after preparation. Its least significant bit is cleared; the remaining 32-bit value identifies an object whose dispatch-table entry at offset 40 is invoked. This indirect dependency is designated **D-01**.

No explicit arguments to D-01 are established. A hidden receiver, register argument, or other calling-convention state remains unresolved. D-01’s return value is retained as the derived object, without a zero or error check.

### Association and late-bound inputs

The target interface’s dispatch-table entry at offset 84 is designated **D-02**. It receives the target interface, the pair’s second word, and the derived object.

The second pair word is read after D-01 returns, not during the initial lookup. Earlier dependencies can therefore change the value used for association if they can modify that storage.

The ordering between that pair-word read and the target’s dispatch-table reads is not established. All belong to preparation of the D-02 invocation and precede its execution.

D-02’s result is ignored. Normal return leads to cursor initialization without an additional success check.

Cursor selection is also late-bound. After D-02 returns, the function reads an external pointer to a cursor slot, then obtains the cursor stored in that slot. Both the selected slot and its contents may therefore reflect changes made by D-02 or earlier dependencies.

If this initial cursor is zero, no stream-advance call occurs. Association and both cursor-initialization reads have already occurred.

### Stream consumption and query-controlled updates

A nonzero initial cursor enables traversal through F-d3922c7fe0ec. That dependency receives the address of private cursor storage and may modify it. Its unsigned 32-bit return value controls continuation:

- Zero terminates traversal without a query or direct object update.
- A nonzero value identifies a word position and bit position for F-88658862e573.

The word position is the integer quotient of the stream value divided by 32. The bit position is the remainder. Their respective ranges are 0–134,217,727 and 0–31.

F-88658862e573 receives the derived object and both positions. Any nonzero query result suppresses this function’s direct counter and bitmap updates for that iteration. This says nothing about effects performed inside the query itself.

A zero query result enables two ordered updates. First, the signed 32-bit counter at derived-object offset 4 is incremented. After that complete counter update, the selected unsigned bitmap word is combined with a one-bit mask and written back.

The word’s byte displacement from the bitmap base is four times the word position. Its maximum is 536,870,908 bytes. No range check verifies that the selected word exists.

For bit positions 0–30, the signed one-bit shift used by the supplied representation yields the corresponding positive mask under ordinary 32-bit signed-integer semantics. All other bits of the word read by the update are preserved.

Bit position 31 needs a separate qualification. The mask is formed from a signed literal; shifting it into the sign position is not defined under the ordinary language-level arithmetic rules applicable to the representation. A mask of 0x80000000 is therefore a conditional machine interpretation, not an established unconditional result.

The bitmap-base field is referenced separately for the source-word access and destination address. Their relative evaluation order is not established, and the evidence does not establish one captured base value shared by both. With stable storage, both references identify the same selected word.

Only the initial cursor is checked for zero by this function. After traversal begins, continuation depends on the advance dependency’s return value. If that dependency writes a zero cursor but returns a nonzero stream value, the value is processed and another advance call follows.

## Side effects

### Direct changes and ordering

Direct writes affect private selector, auxiliary, and cursor-related storage, plus the derived-object counter and selected bitmap words when enabled by a zero query result.

No direct write to the original pair, descriptor, external cursor-pointer location, or external cursor slot is established. Dependencies may modify any storage accessible to them; preservation must not be assumed.

Association precedes cursor initialization and all stream processing. Within an update-enabled iteration, the counter update precedes the bitmap expression. No rollback is shown. Consequently, an access failure during the bitmap operation may follow an already completed counter write.

No synchronization, atomic operation, or transaction mechanism is established. Claims about a stable bitmap base, consistent shared fields, or preserved unrelated bits require the relevant storage not to change during the operation. The evidence does not supply concurrent-use guarantees.

### Ownership and lifetime

The function contains no explicit allocation, release, retention, or reference-count adjustment. This does not establish that its dependencies lack such effects.

Passing the derived object to D-02 does not establish either ownership transfer or ownership preservation. Likewise, passing addresses of private selector and cursor storage does not establish permission to retain those addresses after their valid lifetime.

No explicit cleanup occurs on early exit or normal completion. Whether any acquired value requires cleanup is unresolved.

### Failure and arithmetic boundaries

There is no diagnostic result. The two checked zero values—the target-interface result and descriptor-pointer field—cause ordinary early completion. Other invalid addresses, invalid dispatch entries, or abnormal dependency outcomes have no explicit recovery path.

Counter arithmetic is signed 32-bit arithmetic. Incrementing 2,147,483,647 is not established to wrap; it exceeds the defined signed range under the ordinary language-level interpretation.

The bitmap displacement fits in unsigned 32 bits. Combining that displacement with the signed bitmap-base value uses unsigned 32-bit arithmetic in the supplied representation. Numeric address wrap does not make the resulting memory access valid.

Separately, some fixed-offset field and dispatch-address calculations use signed address-bearing arithmetic. Near signed representational limits, their definedness is not established. Neither arithmetic facts nor nonzero checks prove that an address is accessible.

## Acceptance examples

These examples are conditional consequences of static evidence, not executed tests. Unless a case states otherwise, they require valid accesses, normally returning dependencies, stable relevant storage, no interfering aliasing, and defined arithmetic.

### Early completion

If F-682adfd5a561 returns zero, only the initial pair-word lookup path is reached. No descriptor lookup, association, or cursor access follows.

If the target is nonzero but the descriptor field is zero, preparation and association are skipped. The containing result must still permit the offset-8 read.

### Descriptor selection and dispatch

A descriptor word of 0xabcd1234 at offset 4 contributes 0x1234 to F-59c1430f85c2. The separate byte argument comes from offset 12.

If the selector copy contains 0x00001001 after preparation, derived-object dispatch uses the object address 0x00001000. This establishes bit clearing, not address validity.

### Late observation of association inputs

If an earlier dependency changes the pair’s second word before D-02 is prepared, association uses the changed word.

If D-02 changes the external cursor pointer from slot A to readable slot B, initialization selects B. If B contains zero, no advance call occurs. This remains true even if A contained a nonzero cursor before association.

### Defined bitmap updates

For stream value 32, the query receives word position 1 and bit position 0. A zero query result changes a counter of 7 to 8 and sets bit 0 of bitmap word 1.

For stream value 30, a zero query result enables the corresponding update to word 0 with mask 0x40000000.

If the query returns nonzero for either value, this function performs neither direct update.

### Repeated values and termination

If stream value 33 occurs twice and both queries return zero, a counter of 7 becomes 9. Both bitmap updates set bit 1 of word 1; the second write may leave that word numerically unchanged. There is no independent deduplication.

A zero stream return terminates without querying position zero. If an advance call instead writes a zero cursor while returning 33, value 33 is processed and another advance call is attempted.

### Bit 31 and overflow limits

For stream value 31, the query receives word position 0 and bit position 31. A nonzero query result avoids the problematic mask operation entirely.

With a zero query result, no unconditional final state follows from the ordinary language-level interpretation because of the signed shift. Under an additional machine interpretation that produces mask 0x80000000, the expected update increments the counter and sets bit 31. That interpretation is not established here.

Similarly, a zero-query iteration starting with counter 2,147,483,647 has no established wrapping result.
