# F-c736df487767

## Purpose

F-c736df487767 performs an ordered sequence of indirect calls and memory updates, then enters a loop with no visible normal exit.

The supplied static representation establishes data movement and call ordering, but not an application-level purpose. In particular, it does not establish that the affected memory represents ordinary objects, device registers, encoded pointers, or a particular protocol. Such interpretations are **documented_only**.

This contract describes the visible execution path conditionally: each operation is reached only if all preceding calls return and preceding memory accesses complete. The supplied representation carries instruction-decoding and unreachable-region warnings, so it is not sufficient to establish that this path exhausts the executable’s behavior.

## Interface

### Explicit inputs

The interface exposes four 32-bit arguments:

| Input | Interpretation established by the representation |
|---|---|
| A | Unsigned 32-bit value; stored unchanged, passed to the first dependency, and used to derive a byte-read address. |
| B | Signed 32-bit value; used to calculate the address of the first 32-bit store. |
| C | Unsigned 32-bit value; logically shifted right by seven before one dependency call. |
| D | Unsigned 32-bit value; stored unchanged and later used to derive a byte-store address and a dependency argument. |

The declared return type is void. The visible path has no return operation and ultimately repeats indefinitely if its dependencies continue returning.

### Implicit inputs

Execution also depends on:

- An incoming control-flow value used to calculate the first indirect-call destination.
- Values returned by numerous dependencies.
- Bytes read from calculated addresses.
- Memory and machine state accessible to dependencies.

These implicit inputs are not validated by the visible function.

### Width and address conventions

The visible word stores are 32 bits; the visible byte accesses are eight bits. Unsigned right shifts are logical. Byte stores retain only the low eight bits of their supplied value.

For describing address calculations, this contract uses a conditional 32-bit machine interpretation: additions, multiplications, and left shifts retain their low 32 bits. This interpretation must not be confused with a portable language-level guarantee. Several expressions involve signed operands, and the supplied representation does not establish overflow, negative-shifted-value, or pointer-validity semantics.

No alignment, readable-range, writable-range, or callable-target checks are visible. Validity of every address actually accessed is therefore a precondition for uninterrupted execution. Required alignment and the byte order of 32-bit stores are **documented_only**.

### 6. Unconditional loop

1. Invoke a dependency with H as its first explicit argument and U logically shifted right by eight as its second.
2. Invoke **F-d052**, **F-d053**, and **F-d054**, with empty argument lists.
3. Invoke **F-d055**, with an empty argument list, obtaining a signed 32-bit result W.
4. Read one byte at V, then write zero at the address formed by adding 17 to that byte.
5. Invoke **F-d056**, with **W shifted left by two**.
6. Invoke **F-d057**, **F-d058**, and **F-d059**, with empty argument lists.
7. Invoke **F-d060**, with an empty argument list, obtaining a signed 32-bit result Z.
8. Replace H with **Z shifted left by two**, and replace U with **Z shifted left by 26**, interpreted as a 32-bit unsigned bit pattern for the next iteration.

The dependency in step 1 differs by iteration:

- The first iteration uses **F-d051**.
- Subsequent iterations use **F-d061**.

The visible target calculation changes after the first iteration; it must not be flattened into one assumed callee.

On the first iteration, the second argument is necessarily zero because the initial U is at most 31. On later iterations, under 32-bit shift semantics, that argument equals the low six bits of the preceding Z shifted left by 18. It is therefore a multiple of 262,144 between zero and 16,515,072.

## Side effects

The visible function performs:

- Four 32-bit stores before the byte-oriented phase.
- Six byte stores before loop entry.
- One byte store during every completed loop iteration.
- A fresh selector-byte read for each selector-directed byte store.
- All indirect calls in the stated order.

These counts exclude memory activity inside dependencies.

No direct allocation, release, ownership transfer, synchronization operation, or error-reporting operation is established. Passing an argument to a dependency does not establish whether that dependency treats it as an address, retains it, modifies related state, or releases memory.

All dependencies may have additional side effects. No global-preservation, memory-preservation, or ownership guarantee is assumed.

Address aliasing can affect subsequent reads. For example, a selector-directed zero store may overwrite the selector byte itself if the calculated destination aliases its source address. Such effects follow from the stated read/write order; they are not excluded by a visible check.

There is no transactional behavior or rollback. If execution stops partway through, earlier stores and dependency effects have already occurred.

## Acceptance examples

These are conditional static acceptance criteria, not executed tests. They assume relevant accesses succeed and dependencies return as stipulated.

1. **First observable store.** With A equal to 305,419,896 and B equal to 3, the first word store writes 305,419,896 at address 32. It occurs before F-d001 receives A.

2. **High-bit masking differs between inputs.** With A equal to 2,147,483,648, Q is zero, so the A-derived selector read uses address 1. With D equal to the same value, the D-derived byte-store address is 16,777,244. A’s sign bit is cleared for its selector calculation; D’s is not.

3. **Repeated selector reads are not cached.** Suppose the selector at Q + 1 is 5 for the first R-derived byte write and 9 for the second. The destinations are 22 and 26, respectively. Using 22 for both would violate the visible behavior.

4. **Byte truncation.** If R is 1,023, the first R-derived byte store writes 252, while F-d025 receives 4,092 in each of its three explicit argument positions.

5. **Intermediate-width distinction.** If R is 1,073,741,823, the second R-derived byte expression yields 1,023 before truncation; the actual byte written is 255.

6. **Two word writes to one retained address.** If K is 2, the first store at address 52 writes 8. After F-d015 through F-d019 return, the second store at address 52 writes 32. Intervening dependency effects are not constrained.

7. **First versus subsequent loop calls.** If T is 1,073,741,823, initial U is 31. F-d049 receives 62, and F-d051 receives zero as its second argument. If the first F-d060 result is 65, the next iteration uses F-d061, with first argument 260 and second argument 262,144.

8. **No visible error short circuit.** A zero return from a dependency whose result supplies an address calculation is used in that calculation. The visible function does not convert it into a failure return.
