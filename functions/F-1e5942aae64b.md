# F-1e5942aae64b

## Purpose

F-1e5942aae64b conditionally obtains an object associated with a caller-supplied record, gathers several object-derived values, and submits three values to output dependencies at cursor-derived addresses within that record. It also updates a one-byte cursor after each output call.

The submitted values are:

- A 32-bit flag word assembled from nonzero predicate results and an optional auxiliary query.
- A previously captured 32-bit object-derived value.
- The low 16 bits of another previously captured 32-bit result.

This description establishes the arguments and sequencing visible at the call boundary. It does **not** establish that the output dependencies actually encode four, four, and two bytes, respectively. Their implementations and byte order are unavailable.

The apparent intent is to append a ten-byte representation of object properties. That interpretation is inferred from the cursor advances and argument truncation, not independently established by the available dependency contracts.

| Record address | A pointer to caller-supplied storage. Its first 32-bit word is passed to an object lookup operation. Its byte at offset 6 is used as a cursor. Output addresses are derived from the original record address. |

The visible representation uses 32-bit words and pointer-shaped values. The cursor occupies one byte. Pointer validity, alignment requirements, and the concrete calling convention are not independently documented.

## Behavior

The sequence below describes ordinary control flow **conditional on each dependency returning normally**. Calls may have additional effects that are not visible here.

### 1. Prepare auxiliary state and obtain a provider

The function creates:

- A mutable local pointer initially containing the original record address.
- A mutable local 32-bit word initially containing the initial auxiliary word.
- A local object slot initially containing the fourth input.

It then calls F-b7af80e829ec without visible arguments.

If that call returns a null pointer, the function skips lookup, object queries, output calls, and F-feee9156a257. It proceeds directly to F-a817d8d58c10.

If the returned provider is nonnull, the function reads the record’s first 32-bit word and invokes the provider’s indirect operation at dispatch-table byte offset `0xf4`. That operation receives the provider pointer and the word read from the record.

The lookup result replaces the local object slot, including when the result is null.

The record’s first word is read **after** F-b7af80e829ec returns. The supplied material gives no basis for assuming that dependency leaves record storage or global state unchanged.

### 2. Gate object processing

For a nonnull lookup result, the function calls the object’s indirect operation at dispatch-table byte offset `0x08`.

- A zero result suppresses all subsequent property queries and output calls.
- A nonzero result enables property collection.
- A null lookup result bypasses this gate operation entirely.

Whether lookup returns null, the gate returns zero, or output processing completes, the provider-present path next calls F-feee9156a257 with the current local object pointer. In particular, a null lookup result is passed to F-feee9156a257 without a local null guard.

### 3. Capture values and assemble flags

For a nonnull object whose gate result is nonzero, the object’s indirect operations are called in this order:

| Dispatch-table byte offset | Use of returned value |
|---|---|
| `0xa0` | Capture a 32-bit value for the second output call. |
| `0xf0` | Set flag `0x00000001` if nonzero. |
| `0x138` | Capture a 32-bit value; set flag `0x00000002` if nonzero. |
| `0xe0` | Set flag `0x00000004` if nonzero. |
| `0xec` | Set flag `0x00000008` if nonzero. |
| `0x118` | Enable the auxiliary-query branch if nonzero. |

Each predicate uses a zero-versus-nonzero test; its magnitude does not determine additional bits. Negative signed results, where represented as signed, are also nonzero.

The result from offset `0x138` has two distinct uses:

1. Its entire 32-bit value determines whether flag `0x00000002` is set.
2. Only its low 16 bits are submitted in the third output call.

Consequently, a nonzero value with low 16 bits equal to zero still sets `0x00000002` while submitting zero as the third value.

The value from offset `0xa0` and the value from offset `0x138` are captured before the later queries. Subsequent calls do not cause those values to be queried again.

### 4. Perform the optional auxiliary query

If the operation at offset `0x118` returns nonzero, the function calls F-d266e8cfbbe8 with:

1. The context word.
2. The address of the mutable auxiliary word.
3. The address of the mutable local record pointer.

The dependency may change either pointed-to local value. Its ownership effects and any other memory effects are unknown.

After it returns:

- Flag `0x00000080` is set regardless of its return value.
- Flag `0x00000100` is set only when its 32-bit return value is zero **and** the low eight bits of the auxiliary word, read after that call, equal one.

If the dependency returns nonzero, flag `0x00000100` remains clear even if the auxiliary word’s low byte equals one.

If the operation at offset `0x118` returns zero, F-d266e8cfbbe8 is not called, and both `0x00000080` and `0x00000100` remain clear.

Changing the local record pointer through F-d266e8cfbbe8 does not, by itself, redirect the three later output calls. Those addresses are computed from the original record input, not from the mutable local pointer. Writes performed through either address may nevertheless affect shared storage if the addresses alias.

Only flag bits `0x01`, `0x02`, `0x04`, `0x08`, `0x80`, and `0x100` are introduced by the visible logic.

### 5. Submit outputs and update the cursor

The function performs three output calls in a fixed order. It does not inspect their return values.

**First output**

1. Read the current byte at record offset 6.
2. Call F-b9d9c0b9bfab with the address at original record base plus 7 plus that unsigned byte, and the assembled 32-bit flag word.
3. After the call returns, reread the byte at offset 6.
4. Add four and store the low eight bits back to offset 6.

**Second output**

1. Use the byte value just stored by the preceding increment to form an address at original record base plus 7 plus that value.
2. Call F-b9d9c0b9bfab with that address and the captured result from offset `0xa0`.
3. After the call returns, reread the byte at offset 6.
4. Add four and store the low eight bits back to offset 6.

**Third output**

1. Use the byte value just stored by the preceding increment to form an address at original record base plus 7 plus that value.
2. Call F-3a7a47316439 with that address and the captured result from offset `0x138`, masked to its low 16 bits.
3. After the call returns, reread the byte at offset 6.
4. Add two and store the low eight bits back to offset 6.

The repeated cursor reads are significant. An output dependency can affect the next increment if it changes the cursor, directly or through aliasing. The visible implementation does not simply capture one initial cursor and use fixed offsets throughout.

If the three output dependencies leave the cursor unchanged, and no other effects interfere with these accesses, an initial cursor of \(c\) produces destination offsets:

- \(7+c\)
- \(7+((c+4)\bmod 256)\)
- \(7+((c+8)\bmod 256)\)

The final stored cursor is \((c+10)\bmod 256\).

Wraparound is not rejected. The address addition uses the resulting byte value; wrapping the cursor can therefore move a later destination toward the beginning of the record rather than continuing after the earlier destination.

### 6. Final calls

On the provider-present path, F-feee9156a257 is called with the lookup result after any enabled output processing.

If control continues past that call, F-a817d8d58c10 is called without visible arguments. The provider-absent path also reaches F-a817d8d58c10.

## Side effects

The directly established record modification is three conditional writes to its cursor byte: increments of four, four, and two, each reduced to eight bits. These writes occur only after the corresponding output dependency returns.

Other effects are delegated:

- F-b9d9c0b9bfab receives two computed destination addresses and two 32-bit values.
- F-3a7a47316439 receives a third destination address and a value restricted to 16 significant bits.
- F-d266e8cfbbe8 can modify two local slots through supplied addresses.
- Provider and object operations, as well as final dependencies, may affect memory or global state.

There is no visible allocation, explicit deallocation, rollback, or locally handled error. Passing the object to F-feee9156a257 is established; describing that call as release, destruction, or ownership transfer is not.

The function offers no transaction boundary. If an output call fails to return, earlier calls and cursor updates may already have occurred, while later updates and final calls do not occur.
