# F-603e9a6e7c54

## Purpose

The available static representation describes a call-heavy operation that interleaves indirect calls with six 32-bit memory accesses and four byte accesses. It forwards its explicit input to an initial dependency, derives addresses and arguments from later dependency results, and reaches an invalid-instruction termination marker rather than an ordinary return.

No application-level purpose is established. In particular, the evidence does not establish that the accessed addresses represent objects, allocated storage, device registers, or a serialization buffer.

This contract describes the visible sequence conditionally: execution must reach each operation, every preceding dependency must return, and the relevant memory access must be valid. The supplied representation includes a bad-instruction warning, so it is not sufficient to establish that the entire sequence is executable as presented.

## Interface

**Explicit input**

- One 32-bit value. No interpretation as an integer, pointer, handle, or flag set is established.
- This value is passed unchanged as the sole visible argument of the first indirect call.

**Implicit inputs**

- An incoming link/return-address value, used to compute the first call target by adding `0xFFE`.
- An incoming 32-bit register value, stored to memory after the fifth call. Its provenance and initialization requirements are unknown.
- Results returned by subsequent indirect calls.
- Memory contents at dynamically computed addresses, including one 32-bit value and two separately observed bytes.

**Output**

- No ordinary return value is exposed.
- The visible path ends at an invalid-instruction termination marker after the final indirect call.
- Whether actual execution traps, transfers control elsewhere, or fails earlier is not established.

**Arithmetic notation**

For the sequence below:

- `word(x)` denotes the low 32 bits of a value.
- `byte(x)` denotes the low 8 bits.
- Address expressions use byte offsets.
- Lettered values are explanatory labels for retained call results, not implementation identifiers.
- Products and left shifts are expressed using a 32-bit bit-pattern model where needed.

The 32-bit model makes truncation explicit; it does not prove the machine’s address width or resolve the signed-overflow ambiguities in the supplied representation. Any acceptance example requiring overflow or a left shift of a negative signed value is conditional on the recovered execution semantics matching that model.

## Behavior

### Dependency naming and execution conditions

The opaque dependency IDs below identify **call sites**, not verified, distinct function identities. Their implementations and externally assigned identities are unavailable. Two sites could ultimately reach the same implementation.

A “no-argument call” means no explicit arguments are visible in the supplied representation. It does not establish the absence of implicit register, memory, stack, or global-state inputs.

All calls and direct memory operations occur in the order specified below. Dependencies may themselves perform arbitrary observable operations; those operations are not characterized here.

### 1. Forward the input and store incoming register state

1. Invoke **F-U001**, passing the explicit 32-bit input.
2. Invoke **F-U002**, **F-U003**, and **F-U004**, in that order, with no visible arguments.
3. Invoke **F-U005**, with no visible arguments, and retain its 32-bit result as **A**.
4. Write the incoming register value as a 32-bit quantity to address `word(4 × A + 0x14)`.
5. Invoke **F-U006**, passing `word(4 × A)`.

No visible result from the first four calls is consumed by the caller. Their side effects may still affect subsequent execution.

### 2. Write a scaled result, then read a potentially different location

1. Invoke **F-U007**, **F-U008**, and **F-U009**, in order, with no visible arguments.
2. Invoke **F-U010**, with no visible arguments, and retain its result as **B**.
3. Form **P** as `word(4 × B)`.
4. Write **P** as a 32-bit quantity to address `word(16 × B + 0x14)`.
5. Read a 32-bit unsigned value from address `word(P + 0x14)` and retain it as **R**.
6. Invoke **F-U011**, passing **P**.

The write address and read address have different scale factors. They must not be treated as the same location without evaluating them. If they alias, the read follows the write and observes the resulting memory according to the applicable memory semantics.

### 3. Store the high 20 bits of the captured word

1. Invoke **F-U012**, **F-U013**, and **F-U014**, in order, with no visible arguments.
2. Invoke **F-U015**, with no visible arguments, and retain its result as **C**.
3. Form **Q** as `word(4 × C)`.
4. Write the 32-bit value `R >> 12` to address `word(Q + 0x14)`.
5. Invoke **F-U016**, passing **Q**.

The shift is logical because **R** was read as an unsigned 32-bit quantity. The written value lies between `0` and `0x000FFFFF`, inclusive. It is derived from the earlier captured read, not from a fresh read after these intervening calls.

### 4. Produce another scaled value and make a three-argument call

1. Invoke **F-U017**, **F-U018**, and **F-U019**, in order, with no visible arguments.
2. Invoke **F-U020**, with no visible arguments, and retain its result as **D**.
3. Form **S** as `word(4 × D)`.
4. Write **S** as a 32-bit quantity to address `word(16 × D + 0x14)`.
5. Invoke **F-U021** with these three visible arguments, in order:
   - `(Q & 0x3F) << 14`;
   - **S**;
   - `word(C << 30)`.

The first argument uses **Q**, the scaled value, not the unscaled result **C**. Under the 32-bit model it depends only on the low four bits of **C** and ranges from `0` through `0x000F0000` in increments of `0x10000`.

The third argument retains only the low two bits of **C**, placed in bits 30–31, under that same model.

### 5. Store the retained scaled value through another computed address

1. Invoke **F-U022**, **F-U023**, and **F-U024**, in order, with no visible arguments.
2. Invoke **F-U025**, with no visible arguments, and retain its result as **E**.
3. Write **S** as a 32-bit quantity to address `word(4 × E + 0x14)`.
4. Invoke **F-U026**, passing `word(4 × E)`.

The stored value is the previously retained **S**. There is no visible reread of the earlier destination to recover it.

### 6. Read a byte as an address component and perform the first byte write

1. Invoke **F-U027**, **F-U028**, and **F-U029**, in order, with no visible arguments.
2. Invoke **F-U030**, with no visible arguments, and retain its unsigned 32-bit result as **U**.
3. Form **L** as `word(U << 2)`.
4. Read one unsigned byte from address `word(C × 0x10000000 + 1)`.
5. Zero-extend that byte and add `0x11` to obtain the destination address.
6. Write `byte(L)` to that destination.
7. Invoke **F-U031** with three visible arguments:
   - **L**;
   - **L** again;
   - `word(U << 4)`.

The source byte is an address component, not a pointer-width load. Its value is between `0` and `255`; consequently, the byte destination lies between `0x11` and `0x110`, inclusive.

The stored byte is `(U & 0x3F) × 4`. Its low two bits are zero.

The target-construction offset for **F-U031** is `0xFEC`; the other visible calls use `0xFFE`. The evidence does not justify normalizing this difference.

### 7. Forward an intermediate result and perform the second byte write

1. Invoke **F-U032**, with no visible arguments, and retain its 32-bit result as **T**.
2. Invoke **F-U033**, passing **T**.
3. Invoke **F-U034**, **F-U035**, and **F-U036**, in order, with no visible arguments.
4. Invoke **F-U037**, with no visible arguments, and retain its result as **V**.
5. Read another unsigned byte from address `word(C × 0x10000000 + 1)`, retaining the zero-extended value as **H**.
6. Write `byte((U & 0x3FFFFFFF) >> 20)` to address `H + 0x11`.
7. Invoke **F-U038**, passing `word(V << 2)`.

The byte source is reread after several intervening calls. The second destination is therefore not required to match the first destination.

The second stored byte is bits 20–27 of **U**. Although the masked, shifted intermediate can contain ten significant bits, the byte store retains only eight. Bits 28–31 do not affect the byte written.

### 8. Make the final calls and reach the termination marker

1. Invoke **F-U039**, **F-U040**, and **F-U041**, in order, with no visible arguments.
2. Invoke **F-U042**, with no visible arguments, and retain its result as **W**.
3. Invoke **F-U043**, passing:
   - `word(W << 2)`;
   - **H**, the byte captured before **F-U038**.
4. Invoke **F-U044**, with no visible arguments.
5. Reach the invalid-instruction termination marker.

The second argument of **F-U043** is the retained byte value, not the destination address `H + 0x11` and not a new memory read.

## Acceptance examples

These are conditional acceptance criteria, not executed tests. They assume valid call targets, valid memory, returning dependencies, and the stated arithmetic interpretation.

1. **Input forwarding and ambient-state storage.**  
   If the explicit input is `0x12345678`, **F-U001** receives that exact 32-bit value. If **A** is `3`, the incoming register value is written at `0x20`, followed by **F-U006** receiving `12`.

2. **Distinct word-access scale factors.**  
   If **B** is `2`, the operation writes `8` at `0x34`, then reads a word at `0x1C`. It must not replace that read with the just-written value merely because both expressions derive from **B**.

3. **Logical shift of a captured word.**  
   If **R** is `0xFEDCBA98` and **C** is `3`, the later word write is `0x000FEDCB` at `0x20`. An intervening dependency changing the original read location does not change this retained **R**.

4. **Three-argument bit derivation.**  
   With **C** equal to `3` and **D** equal to `2`, **F-U021** receives `0x00030000`, `8`, and `0xC0000000`, assuming the 32-bit left-shift interpretation. The word write preceding that call stores `8` at `0x34`.

5. **Two byte destinations may differ.**  
   If **U** is `0x2AB00003`, the first byte written is `0x0C` and the second is `0xAB`. If the first source-byte read yields `5`, its destination is `0x16`. If the later source-byte read yields `9`, its destination is `0x1A`, and **F-U043** later receives `9` as its second argument.

6. **Repeated destination overwrites.**  
   If both source-byte reads yield `5`, both byte stores target `0x16`. The second store follows the first and replaces its value, subject to intervening dependency effects.

7. **No normal completion requirement.**  
   If every dependency returns and all accesses succeed, the visible sequence reaches the invalid-instruction marker after **F-U044**. A normal return or success status is not supported by this evidence.
