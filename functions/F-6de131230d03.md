# F-6de131230d03

## Purpose

F-6de131230d03 requests storage, arranges two prefix transfers and two dependency-controlled contributions, writes a trailing byte, and publishes a buffer address and recorded length into a selected pair of output fields.

Construction proceeds only when the allocation dependency returns a nonzero value. A zero result ends the function without direct buffer or output-field writes. There is no explicit return value or failure status.

The supplied static evidence establishes the operations and their ordering, not the meaning of the resulting bytes. Text encoding, termination conventions, contribution format, allocation ownership, and bounds guarantees remain unresolved.

The three sources used during construction are obtained through **global pointer slots read at different stages**. Neither their pointer values nor their pointee bytes are established as immutable.

### Address publication and separate length evaluation

After the trailing-byte store, the function selects the output pair:

- Selector zero: address field at byte offset 8, length field at byte offset 12.
- Selector nonzero: address field at byte offset 0, length field at byte offset 4.

It first writes the retained buffer address into the selected address field.

Only after that address write does it read the offset cell again and evaluate offset plus one for the selected length field. Let this later offset read produce \(l\). For an in-range addition, the recorded length is:

\[
L=l+1.
\]

The two offset reads must not be conflated. The trailing-byte store or the address-publication store can change the offset cell if their destinations alias it. Therefore, the unconditional relationship is **not** \(L=d+1\).

That simpler relationship holds only when the cell is unchanged between the destination-offset read and the later length-offset read, and the addition is defined:

\[
l=d \quad\Longrightarrow\quad L=d+1.
\]

The function performs no consistency check between the trailing-byte destination and the recorded length.

Address and length publication are separate writes, in that order. No atomic pair update or synchronization is shown.
