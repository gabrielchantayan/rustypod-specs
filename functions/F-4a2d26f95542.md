# F-4a2d26f95542

## Purpose

F-4a2d26f95542 performs a bounded lookup of one 32-bit value in caller-addressed storage. It accepts an address-bearing base argument and an unsigned index. For indices from 0 through 17, inclusive, it returns the 32-bit contents at a fixed offset from that base. For every other index, it returns the bit pattern `0xFFFFFFFF` without reading the addressed storage.

This is a raw, strided lookup, not a validated container operation. The visible behavior establishes an index bound, a byte displacement, and a read width. It does not establish a record type, a declared allocation size, or the meaning of the returned bits.

The apparent intent is to select one field from an 18-entry layout whose selected fields are 36 bytes apart. That interpretation is inferred; the address calculation and bounds behavior are established by the supplied static evidence.

Address formation and the resulting read must also be valid under the execution environment’s addressing and alignment rules. For a rejected index, the addressed-storage precondition is not needed: the function returns its fixed result without using the base to read memory.

There is no separate success flag. A returned value of `0xFFFFFFFF` is therefore ambiguous: it can be the rejection result, or it can be the actual contents of a successfully selected location.

## Behavior

### Index decision

The function first compares the index against 18 using an unsigned comparison.

- Indices 0 through 17 select a memory read.
- Indices 18 through `0xFFFFFFFF` select the fixed rejection result.
- The decision does not depend on the base argument or on the contents of addressed storage.

Because the index is unsigned, a caller-supplied bit pattern that might represent a negative number in a signed interpretation does not select a negative position here. For example, an index bit pattern of `0xFFFFFFFF` is outside the accepted range.

### Accepted-index lookup

For an accepted index, the selected byte offset is:

**36 × (index + 1)**

The function reads exactly one 32-bit value beginning at the base plus that offset and returns the value read.

The initial 36-byte displacement is significant. Index 0 does not select the address equal to the base; it selects the address 36 bytes beyond it. Each increase of one in the index advances the selected address by another 36 bytes.

Selected locations include:

| Index | Offset from base, decimal | Offset from base, hexadecimal |
|---:|---:|---:|
| 0 | 36 bytes | `0x24` |
| 1 | 72 bytes | `0x48` |
| 16 | 612 bytes | `0x264` |
| 17 | 648 bytes | `0x288` |

A successful read at index 17 covers byte offsets 648 through 651, inclusive. Thus, if the caller represents all possible selected locations using a single contiguous region beginning at the base, that region must extend through byte offset 651: 652 bytes in total. This is a sufficient layout description, not evidence that the function checks or reads that entire region.

Only the selected four-byte location is read. The function does not scan preceding entries, inspect a header, or read intervening bytes.

The offset arithmetic itself is bounded after the index check. The accepted index never exceeds 17, so the multiplication and displacement produce offsets from 36 through 648, well within 32-bit integer range. This does not establish that adding the offset to an arbitrary base produces a valid address.

The returned bits are not transformed. No mask, sign interpretation, byte-order conversion, or application-level validation is visible after the read.

### Rejected-index result

For any index of 18 or greater, the function returns the 32-bit all-ones bit pattern, `0xFFFFFFFF`.

This branch does not read the selected storage, check the base, or report why the index was rejected. There is no visible diagnostic, retry, fallback lookup, or separate error-state update.

### Observable order

At the level established by the static evidence, the relevant ordering is:

1. Determine whether the unsigned index is below 18.
2. If accepted, calculate the selected address and perform the single 32-bit read.
3. Return either the loaded value or the fixed rejection result.
