# F-66b0707de5b8

## Purpose

F-66b0707de5b8 performs a one-time startup followed by an indefinitely repeated sequence of indirect calls and address-derived memory transfers. Its observable behavior includes byte-selector reads, byte writes, 32-bit transfers, a 32-bit global snapshot, and changes to state carried between iterations.

The supplied static representation establishes these operations and their order, but not their application-level purpose. It does not establish whether the accessed locations are ordinary memory, device registers, object fields, or tables.

The repeated body has no visible exit condition or normal return. Continued execution depends on every reached call returning and every reached memory access completing.

## Interface

### Entry state and outputs

The displayed interface declares no arguments and no return value. Nevertheless, it consumes incoming machine state:

| Initial byte | Eight-bit value written during startup |

The routine also carries an iteration value and a call-target base from startup into the repeated body. The call-target base differs between the first iteration and all subsequent completed iterations.

There is no established conventional invocation procedure, ABI, stack contract, or register-preservation contract. A conventional no-argument invocation is not, by itself, an established safe interface.

No normal output value is visible. Outputs consist of completed calls, memory effects, and continued execution.

### Widths and arithmetic

The static representation distinguishes:

- Unsigned eight-bit selector reads and eight-bit writes.
- Thirty-two-bit values, address calculations, reads, and writes.
- Two-word call results separated into low and high 32-bit halves.
- One explicit external 32-bit global read per completed iteration.

Arithmetic descriptions below use a 32-bit machine-word model: multiplication and left shifts retain the low 32 bits; byte writes retain the low eight bits. This is not a claim that equivalent signed expressions have defined behavior in a higher-level language.

Right shifts of the described packed unsigned values are logical. Byte order, alignment tolerance, address permissions, and instruction-address interpretation are not supplied.

### Memory-access vocabulary

A **selected-byte write through a base** reads the unsigned byte at base plus 1, adds 0x11 to that byte, and writes one byte at the resulting address. The base is **not** added to the final destination.

Consequently, selected-byte destinations range from 0x11 through 0x110. A word destination formed from a retained selector byte plus 0x14 ranges from 0x14 through 0x113.

A **direct byte write** instead writes at the stated base plus offset, without reading a selector.

A **word location** denotes a computed address used for a 32-bit access. It does not imply an array, allocation, valid alignment, or ownership.

## Behavior

### Call notation and target selection

Every visible call is indirect. **F-000000000000** denotes an unresolved dependency at an individual call occurrence. Reusing that designation does not establish equal targets or equal behavior.

A **five-call sequence** means one call with the specified explicit arguments followed by four calls with no explicit arguments shown. Unless otherwise stated, its result is the fifth call’s result. Intermediate calls remain observable and cannot be omitted. Absence of explicit arguments does not establish absence of implicit machine-state inputs.

Target arithmetic is partly established even though dependency identities are unresolved. In particular, the first call in phase 1 uses the carried call-target base plus 0xfc4:

### Startup

Startup first calls F-000000000000 at the incoming entry call base plus 0xffe and retains its 32-bit result.

It then performs a selected-byte write through the incoming selector base, storing the initial byte. Both the selector read and the byte write occur after the first call.

A five-call sequence follows. Its first explicit argument is the retained startup result shifted left by two. The fixed target base used for that sequence’s first call is 0x0882d49f, with offset 0xffe.

Before the fifth startup call, the carried phase-1 target base is set to 0x0882d4b3. The fifth call’s result supplies the initial iteration value. Startup then enters phase 1. Startup is not repeated at the back edge.

### Phase 1 — Publish the packed byte and acquire a transfer word

The iteration value is scaled by four.

A selected-byte write through the current selector base stores bits 20–27 of the packed input. The displayed extraction clears the top two bits and shifts right by 20; byte truncation discards the surviving bits 28–29.

Seven calls follow:

1. A call with the shift input shifted left by 12.
2. A call producing a 32-bit intermediate.
3. A call with that intermediate and the scaled iteration value shifted left by 28.
4. A call producing a two-word result.
5. A call with its low word, then its high word.
6. A call with no explicit arguments.
7. A call producing a 32-bit result.

The first of these calls uses the carried target base plus 0xfc4: 0x0882e477 on the first iteration, and 0x0882dfff after each completed back edge. Its explicit argument follows the same shift rule in both cases. The target difference is established independently of any knowledge of callee semantics.

A fresh selected-byte write through the current selector base stores zero.

A five-call sequence receives the seventh result shifted left by two. Four times its final result becomes the **first transfer word**, which is stored at the scaled iteration value multiplied by 0x1000, plus 0x14.

Because the iteration value was already scaled by four, the earlier argument formed by shifting that scaled value left by 28 retains only the original iteration value’s bottom two bits, in bits 30–31.

### Phase 2 — Transfer through computed word locations

A five-call sequence receives four arguments: two copies of the scaled iteration value multiplied by 0x400, the original iteration value shifted left by 14, and the first transfer word. Its result selects a location at four times that result plus 0x14, which receives the first transfer word.

A five-call sequence receives four times that selector. Four times its result becomes a **second transfer word**, stored at sixteen times that result plus 0x14.

A five-call sequence receives three copies of the second transfer word. Its result selects a location at four times that result plus 0x14, which receives the same word.

Another five-call sequence receives four times the latest selector. Four times its result becomes a **third transfer word**. The same result multiplied by 0x40000000 becomes the **working byte base**. The third transfer word is stored at sixteen times the result plus 0x14.

A five-call sequence receives three copies of the third transfer word. Its result becomes the **retained selector**, and the third transfer word is stored at four times that selector plus 0x14.

A further five-call sequence receives four times the retained selector and produces the **retained packed word**.

Under 32-bit wrapping arithmetic, the working byte base is one of zero, 0x40000000, 0x80000000, or 0xc0000000. Validity of these addresses is not established.

### Phase 3 — Clear direct bytes and read a lookup word

The routine directly writes zero at working byte base plus 0x11, then at working byte base plus 1.

Seven calls follow: one receiving the retained packed word shifted left by two; one producing an intermediate; one receiving that intermediate; and four further calls, the last producing a result.

The direct zero stores repeat in the same order: offset 0x11, then offset 1.

A five-call sequence receives the latest result shifted left by two. Its final result becomes the **lookup-location selector**. At sixteen times this selector plus 0x14, the routine stores the retained selector shifted left by 31. Only the retained selector’s least significant bit can affect that stored word.

The routine next reads a 32-bit **lookup word**. Its address is the retained packed word, masked with 0x3fffffff and shifted right by 20, plus 0x14.

The extracted index ranges from zero through 0x3ff and is not multiplied by four. The read can therefore be unaligned.

### Phase 4 — Retain a result and update selected storage

A call receives four times the lookup-location selector. A following call produces a **retained result** used later in the iteration.

A five-call sequence receives the lookup word shifted right by 22 and then left by 28. Under the stated width model, lookup bits 22–25 occupy argument bits 28–31. The final result selects a location at four times that result plus 0x14, where a 32-bit zero is stored.

A five-call sequence receives four times that latest selector and produces a **new packed word**.

A selected-byte write through the working byte base stores the new packed word shifted left by two, truncated to eight bits.

Seven calls follow: one receiving the new packed word shifted left by two; one producing an intermediate; one receiving that intermediate and the new packed word shifted left by 30; and four further calls, the last producing a result.

The routine then reads and retains the byte at working byte base plus 1. At the retained byte plus 0x11, it writes bits 20–27 of the new packed word.

A five-call sequence receives the latest call result shifted left by two. After all five calls, the routine writes the earlier retained result shifted left by two at the retained byte plus 0x14.

This word destination uses the saved byte. It does not reread selector storage after the intervening calls.

### Phase 5 — Snapshot the global and begin another transfer

Immediately after that word store, the routine reads the external 32-bit global.

A five-call sequence receives four times the lookup-location selector from phase 3. Its final call produces a two-word result. Four times the low word becomes a **retained scaled value**.

A selected-byte write through the working byte base stores the global snapshot shifted right by 22 and truncated to a byte, exposing snapshot bits 22–29.

Seven calls follow: one receiving the high word; one producing an intermediate; one receiving that intermediate and the retained scaled value shifted left by 28; and four further calls, the last producing a result.

A fresh selected-byte write through the working byte base stores zero.

A five-call sequence receives the latest result shifted left by two. Another five-call sequence receives two copies of four times the preceding sequence’s final result.

Four times the second sequence’s final result becomes another **transfer word**. It is stored at the retained scaled value multiplied by 0x1000, plus 0x14.

A five-call sequence receives the retained scaled value shifted left by 14. Its result selects a location at four times that result plus 0x14, which receives the same transfer word.

### Phase 6 — Update selector-derived state

A five-call sequence receives four times the latest selector and produces a two-word result.

A selected-byte write through a base equal to the retained scaled value multiplied by 0x4000 stores bits 20–27 of the transfer word.

Four times the latest two-word result’s low word becomes the **next scaled value**.

Seven calls follow: one receiving the high word; one producing an intermediate; one receiving that intermediate; one producing another two-word result; one receiving its low word and high word; and two further calls, the last producing a 32-bit result.

A selected-byte write through a base equal to the next scaled value multiplied by 0x10000000 stores zero.

A five-call sequence receives the seventh result shifted left by two and produces the **tail result**.

The next iteration’s selector base becomes four times the next scaled value. A selected-byte write through this new base stores zero.

### Phase 7 — Complete the iteration and establish back-edge state

Seven calls follow: one receiving the next scaled value shifted left by 10; one producing an intermediate; one receiving that intermediate and the phase-4 retained result shifted left by 28; and four further calls, the last producing a result.

A selected-byte write through the next selector base stores zero. A five-call sequence then receives the latest result shifted left by two.

The tail result shifted left by 14 becomes both the next shift input and the next packed input. This word is stored at four times the tail result multiplied by 0x1000, plus 0x14.

Seven calls follow: one receiving four times the tail result shifted left by 14; one with no explicit arguments; one receiving the next packed input shifted left by 28 and the unresolved secondary machine result; and four further calls, the last producing a selector.

The next shift-input word is stored at four times that selector plus 0x14.

A final five-call sequence receives four times the selector. Before its fifth call, the carried phase-1 target base is set to 0x0882d03b. The fifth call supplies the next iteration value.

Execution returns to phase 1 with the updated iteration value, selector base, packed input, shift input, and target base. Thus the next phase-1 first call computes 0x0882dfff, not the first iteration’s 0x0882e477.

The tail argument formed by shifting the next packed input left by 28 is necessarily zero under the 32-bit model: that input was already formed by a left shift of 14. The call still occurs, and its secondary argument remains unresolved.

## Side effects

Observable effects are the ordered indirect calls, byte reads and writes, word reads and writes, and the global read. No explicit allocation, deallocation, ownership transfer, locking, rollback, or exception handling is visible.

This absence does not constrain dependency behavior. Dependencies may modify memory or globals, allocate or release storage, perform I/O, or fail to return.

Selected-byte writes normally perform fresh selector reads. Calls or prior stores can therefore redirect later selected writes through the same base. The phase-4 retained byte is an explicit exception: its later word destination does not change when selector storage changes.

Aliasing is unrestricted. Computed accesses may overlap selectors, selected destinations, the external global, or other word locations. No disjointness checks are visible.

If a call does not return or an access faults, the representation provides no local recovery path. It establishes no rollback of previously completed effects.

## Acceptance examples

These are conditional static expectations, not executed tests.

1. **Startup selection.** If the startup selector read yields 0x07 and the initial byte is 0xa5, the byte destination is 0x18. The first startup call precedes the selector read.

2. **Target transition.** If startup completes, phase 1’s first call calculates target 0x0882e477. If an iteration subsequently completes its final five-call sequence and takes the back edge, the next phase-1 first call calculates 0x0882dfff. This establishes different target values, not different semantic behavior.

3. **Packed-byte extraction.** Packed input 0x3ff00000 produces byte 0xff. Changing only bits 30–31 does not change that byte.

4. **Fresh selection.** If one selected write reads selector 2 and a later selected write reads selector 9, their destinations are 0x13 and 0x1a, respectively.

5. **Retained selection.** If phase 4 retains selector byte 5, its byte destination is 0x16 and its later word destination is 0x19. Intervening selector changes do not redirect that word store.

6. **Unscaled lookup.** A lookup index of 3 produces a word-read address of 0x17, not 0x20. Successful access depends on the memory system.

7. **Direct clears.** With working byte base 0x40000000, each clear pair writes first to 0x40000011 and then to 0x40000001, without selector reads.

8. **Continuation and zero argument.** If all operations complete, execution starts another iteration rather than returning. The specified tail argument is zero under 32-bit arithmetic, but that does not remove its call.
