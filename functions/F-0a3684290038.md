# F-0a3684290038

## Purpose

F-0a3684290038 classifies the character at a caller-supplied address. It returns true when that character has numeric value 3 or 4, and false otherwise.

The classification concerns only the character at the supplied address. It does not search a string, inspect subsequent characters, require a terminator, or interpret the surrounding storage as a structured object.

The accepted values are established by the supplied static evidence. Their application-level meaning is unknown. No protocol role, command meaning, encoding convention, or validation purpose is established.

### Output

- **True:** the evaluated character satisfies the classification for numeric value 3 or numeric value 4.

### Evaluation order

1. The character at the supplied address is evaluated for equality with numeric value 3.
2. If that comparison succeeds, the result is true without evaluating the comparison against numeric value 4.

## Acceptance examples

The following are conditional acceptance criteria derived from static evidence. They are not reports of executed tests.

### Accepted character values

Given a live, readable character whose value remains 3 throughout the call:

- The function returns true.
- The comparison against numeric value 4 is not evaluated at the source-language level.
- The input character remains unchanged.

Given a live, readable character whose value remains 4 throughout the call:

- The first comparison fails.
- The comparison against numeric value 4 succeeds.
- The function returns true without modifying the input.

### Rejected character values

Given a live, readable character whose stable value is 0, 2, or 5, the function returns false.

On an eight-bit-character implementation, a stable character with representation 0xFF also produces false. Whether that representation denotes a negative or positive plain-character value does not make it equal to 3 or 4.

### Independence from neighboring storage

Given two valid input objects whose first characters have the same stable value, differing subsequent characters do not change the classification.

For example, an object beginning with value 3 is accepted whether its next character is zero, another accepted value, or an unrelated value. No next character is required at all if the first character is independently readable.

### Not a string search

Given a valid object beginning with value 2 and containing value 3 at a later position, the function returns false. An accepted value elsewhere in the object does not compensate for a rejected first character.

### Invalid-storage cases

A null pointer has no required Boolean outcome under this contract.

Likewise, a pointer to expired storage or a one-past-the-end address does not satisfy the precondition, even if nearby storage contains an accepted value. These cases are not acceptance criteria for returning false.
