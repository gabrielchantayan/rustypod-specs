# F-c0054a2bd59a

## Purpose

F-c0054a2bd59a accepts three 32-bit argument words, performs an ordered prefix of unresolved indirect invocations, mutates fixed and computed memory locations, and invokes an unresolved terminal target with four visible argument words.

No application-level purpose is established. Repeated offsets, self-reference stores, and character-like constants do not establish formatting, allocation, serialization, container management, or hardware control.

This contract distinguishes:

- **Established static evidence:** represented operations, explicit access widths, value dependencies, and ordering.
- **Inferred intent:** possible interpretations, none adopted as requirements.

### Invocation prefix and retained acquisitions

The prefix includes transfers with no explicit arguments and transfers consuming shifted primary results, secondary result words, duplicated values, and zeros. The third-argument field is consumed within this prefix. Some results survive intervening invocations.

No conditional branch or loop is represented in the prefix. This establishes ordering, not guaranteed progress: a dependency may fault, fail to return, or modify memory later observed by this function. An unused result does not make its invocation dispensable.

The following supplying results are acquired in this order, with other invocations intervening:

**Packed-base result → retained-shifted-word result → shifted-base result → compact-half-base result → final pair.**

| Contract quantity | Derivation |
|---|---|

### Opening mutation and early snapshots

The opening mutation stores the packed base as a 32-bit word at the final pair’s upper word + 0x14, then stores that upper word’s low byte at packed base + 9.

A 32-bit store publishes the shifted base at 256 times the final pair’s lower word + 0x54. Only afterward does a second byte store at packed base + 9 publish the packed base’s low byte, conditionally zero. Both stores remain distinct.

Shifted base + 0x14 is cleared as a word before an explicitly unsigned byte read at shifted base + 5. Compact base + 0x14 is then cleared before the captured byte is widened and stored as a word at shifted base + 0x34.

A word read at shifted base + 0x14 supplies the **retained early word**. Another clear of compact base + 0x14 follows, then two successive byte stores publish the retained early word’s low byte at compact base + 0x15.

The retained early word is the actual read result, not universally zero. Intervening accesses can overlap the cleared word.

### Selection from 0x05 and early fixed assignments

After those duplicate byte stores, the function observes the named global at 0x05 and converts its value to an unsigned 32-bit **selected base**. This observation precedes the named-global assignment at 0x01.

The selected base is not unconditionally restricted to 0–255. That range requires additional metadata establishing an unsigned 8-bit source, or equivalent value constraints. A signed-byte source can instead produce large unsigned word values after conversion.

The assignment at 0x01 receives the compact base narrowed to eight bits. An explicit byte store at selected base + 0x15 receives the compact half-base’s low byte.

Before the word at selected base + 0x54 is captured, the function:

- Stores the retained shifted word’s low byte at shifted base + 0x11.
- Stores the retained shifted word as a word at retained early word + 0x54.
- Replaces the byte at shifted base + 0x11 with zero.

The selected + 0x54 word becomes the **saved chain word**. The same location is then replaced, as a word, with the retained early word.

The early named-global assignment order is:

**0x01 → 0x54 → 0x15.**

Computed accesses intervene. Before the assignment at 0x54, effects include publishing the compact half-base at compact base + 0x34, following offset-0x74 words, and making self-reference and replacement stores.

The assignment at 0x54 receives twice the saved chain word. Compact base + 0x14 then receives the saved chain word twice through explicit word stores. Two byte stores at compact base + 0x15 receive the low byte of four times that word. Only afterward does the assignment at 0x15 receive the compact base narrowed to eight bits.

Only under the unsigned-byte source assumption does selected base + 0x54 range from 0x54 through 0x153 before address-space interpretation. Without that assumption, these bounds do not apply.

## Acceptance examples

These are conditional static expectations, not executed tests.

1. **Argument boundaries.** Third-argument values zero and 1023 produce zero for the extracted field. Value 1024 supplies duplicated values of 2048. Value 0x000FFFFF supplies duplicated values of 0x001FF800.

2. **Acquisition order.** Supplying results of 3, 5, and 7 for the packed base, retained shifted word, and shifted base derive 0x06000000, 0x00000500, and 0x0E000000 under word semantics. Their acquisitions occur in that order.

3. **Compact range.** A compact-half-base supplying result of 127 yields half-base 508 and compact base 1016. Compact base 1017 is impossible under the stated derivation.

4. **Explicit byte widening.** An explicit unsigned-byte indirect read returning 0xFE supplies numeric value 254 when widened for a word store. This rule does not automatically apply to the named global at 0x05.

5. **Conditional selection bounds.** If missing metadata establishes an unsigned 8-bit source at 0x05 and its observed value is 0x80, the selected destinations are 0x95 and 0xD4. If instead the source is a signed byte holding −128, conversion to an unsigned 32-bit value yields 0xFFFFFF80; the byte-bounded address conclusion is invalid.

6. **Assignment operand versus storage.** The operand assigned at 0x67 is narrowed to eight bits. Metadata establishing a wider destination would require modeling that wider assignment, not substituting a byte store. The assignment at 0x21 must likewise use its actual destination type.

7. **Fresh observations.** If an intervening write changes the value observed from 0x67 before its third observation, the third explicit byte destination receives the new observation after destination conversion, not necessarily the original snapshot byte.

8. **Retained global base.** A later overlapping write cannot retroactively change the captured global-derived base. Its acquisition remains before the assignment at 0x60, whatever those named-global access widths are.

9. **Terminal boundary.** If late chain base + 0x54 overlaps loaded terminal base + 0x64, the terminal data word is captured before the store of 100. An overlap with loaded terminal base + 0x74 can affect the later trailing capture.

10. **Partial progress.** Normal completion requires every reached operation to complete and the terminal target to return. A failing access does not imply rollback.
