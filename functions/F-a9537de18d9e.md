# F-a9537de18d9e

## Purpose

F-a9537de18d9e is an indirect-dispatch wrapper. It forwards its input pointer and a signed value derived from a fixed-position word in the pointed-to storage to a dynamically selected target.

The established behavior is limited to selecting that target, forming the two arguments, and transferring control. The supplied representation does not establish what the selected target does, whether it returns normally, or whether it changes or releases any reachable storage.

An object-method interpretation is plausible: the first word resembles a dispatch-table address, and a fixed displacement selects an entry. That interpretation is inferred intent, not a prerequisite for describing the observed accesses.

## Behavior

### Target selection

The wrapper obtains a value from the first integer word at the input pointer. It adds a fixed displacement of 356 bytes, hexadecimal 0x164, to that value and treats the resulting address as the location of a callable-pointer entry.

It then loads the callable pointer from that location and uses it as the indirect transfer target.

The displacement is added to the integer-valued dispatch base. It is not an index scaled by the size of an integer or a callable pointer. In particular, the represented entry location is 356 bytes after the base, not 356 entries after it.

The first word is not itself used directly as the callable target. The representation includes an additional load through the address formed from that word and the fixed displacement.

### Forwarded scalar argument

The wrapper also obtains the integer word at input-relative byte offset 88. It converts that word to a signed 16-bit value and then converts that result to a signed 32-bit integer.

Under the conventional fixed-width interpretation represented by these casts:

- The low 16 bits determine the forwarded value.
- The original upper 16 bits do not determine the result.
- Low-16-bit values from 0 through 32767 remain nonnegative.
- Low-16-bit values from hexadecimal 0x8000 through 0xFFFF become values from −32768 through −1.
- Widening preserves the signed value. It does not reinterpret the narrowed value as an unsigned quantity.

This is a conversion of the represented integer word, not evidence of a separate 16-bit memory read. The physical bytes accessed and their order cannot be established from the supplied representation alone.

### Indirect invocation

The selected target receives two represented arguments, in this order:

1. The original input pointer.
2. The signed 32-bit value obtained through the narrowing and widening described above.

The visible body represents one indirect invocation and no surrounding loop, retry, fallback, or secondary target selection.

There is no visible branch that suppresses invocation for a particular scalar value. Zero, negative values, and the signed 16-bit endpoints all follow the same dispatch path when the required memory and target are valid.
