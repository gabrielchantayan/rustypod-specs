# F-31d98408104a

## Purpose

F-31d98408104a adds an unsigned increment to the lower word of a two-word state value and increments the upper word when the lower-word addition produces a carry.

The established behavior is an in-place update of two fields relative to a supplied base address. Interpreting those fields as a single extended counter is inferred intent, not a separately established interface guarantee.

The operation is not atomic as a whole. The lower-word store precedes any upper-word read or store. A concurrent observer could therefore see the updated lower word while the upper word still has its previous value.

## Behavior

### Lower-word update

The function reads the lower field and combines its word value with the increment using unsigned addition.

Under the 32-bit interpretation, let the original lower value be \(L\), the increment be \(I\), and the stored lower result be \(R\). Each is in the range \(0\) through \(2^{32}-1\), and:

\[
R = (L + I) \bmod 2^{32}.
\]

The lower result is stored before the carry-dependent upper-field access.

The lower field is read through a signed-integer view in the supplied representation, but the addition also has an unsigned operand. Consequently, a lower word whose most significant bit is set participates as an unsigned value; it is not rejected or treated as a request to subtract.

The function performs the lower-field store even when the increment is zero or the resulting bit pattern equals the previous bit pattern. That distinction can matter for specially mapped storage. Whether such storage is a supported use is not established.

### Carry decision

After storing the lower result, the function compares that computed result with the increment. It takes the carry branch exactly when:

\[
R < I.
\]

For two 32-bit unsigned operands, this condition identifies overflow of their lower-word sum beyond \(2^{32}-1\).

The comparison uses the computed result, not a fresh read of the lower field. Thus the established operation does not re-read the lower field to decide whether to update the upper field.

There can be at most one carry from this addition. Both operands are single unsigned words; their sum cannot require an upper increment greater than one.

### Upper-word update

When the carry condition is true, the function reads the upper field, adds one, and stores the result back to that field.

The upper value is obtained only after the lower-field store. There is no earlier captured upper value in the supplied evidence. If another actor changes the upper field before this read, the function has no visible mechanism for preserving an entry-time upper value or detecting the change.

When the carry condition is false, the function does not read or write the upper field.

The upper increment is expressed through signed-integer accesses and signed addition in the supplied representation. Incrementing a representable signed value whose successor is also representable has a clear result. The supplied evidence alone does not establish the result when the upper field contains the maximum signed value and carry requires adding one. In particular, unconditional wraparound of the complete two-word state is not an established guarantee.

### Access order

For a normal invocation that completes without an access failure, the evidence establishes this order:

1. Read the lower word.
2. Compute the unsigned lower sum.
3. Store the lower result.
4. Evaluate the carry condition using the computed result and increment.
5. Only on carry, read the upper word and then store its incremented value.
6. Return without an explicit result value.

This is the access order represented by the supplied static evidence. It is not a claim of a particular processor memory-ordering guarantee, indivisible word access, or synchronization with other threads.
