# F-494c11edf385

## Purpose

F-494c11edf385 produces a signed 32-bit selection from an object and a signed 32-bit request. Its externally distinguishable responsibilities are admission control, selection determination, and selection-dependent calls to other operations.

The value −1 is a completion exemption, not an unambiguous error code. It can represent validation rejection, an accepted request of −1, or a selection derived from an extent observation. Those cases have different preceding behavior but share the absence of completion activity.

For other selections, normal completion requires a mandatory indirect operation followed by F-d6032bc0598f. An additional indirect operation applies when a strict relationship between the selection and an observed extent holds. These obligations are subject to representable arithmetic, valid storage, and normal continuation from dependencies.

The terms “admission,” “extent,” “selection,” and “completion” name observable roles. They do not establish application semantics, successful mutation, or resource-management responsibilities.

This contract is based on static evidence only. No runtime tests have been performed.

## Behavior

### Admission

Admission checking is conditional on the character-converted gate field:

| Converted gate value | Admission obligation |
|---|---|
| Zero | F-0d1bcade3bad is omitted |
| Nonzero | F-0d1bcade3bad receives the object and original request |

F-0d1bcade3bad permits continuation with a zero result. Any nonzero result refuses admission; its sign and magnitude have no further locally established significance.

Refusal requires F-4e292a3dd745, followed by F-feee9156a257 if the first dependency returns normally. Neither has explicit arguments in the supplied representation. This does not exclude hidden inputs or dependence on machine state.

An admission dependency that permits continuation may nevertheless change state. Subsequent extent and dispatch observations are not required to reflect their entry values.

### Selection

There are two selection policies.

**Extent-derived policy.** A maximum original request together with a strictly positive eligibility extent selects this policy. Ordinary validation is omitted. The selection is the predecessor of a subsequent extent observation.

**Ordinary policy.** Every other case requires F-402eef64af83 with the object and original request. A zero dependency result rejects the request and produces −1 without completion. Any nonzero result accepts the original request as the selection.

Admission and validation therefore have opposite result polarities: zero permits admission but rejects ordinary validation. A validation result is never itself substituted for the request. For example, result −2 accepts original request 7 as selection 7.

The policy decision is not revisited because of later state changes:

- Positive eligibility commits to extent-derived selection without ordinary validation.
- Nonpositive eligibility sends the maximum request through ordinary validation.
- If that validation accepts the maximum request, the retained selection remains the maximum even if validation changes the extent to a positive value.

The eligibility observation and the selection-producing observation have distinct roles. With a stable positive extent, extent-derived selection lies between zero and 2,147,483,646. Without stability, the positive eligibility observation does not prove that the later decrement operand is positive or that its predecessor is representable.

No additional local bounds check is established for an accepted ordinary request. A selection can be negative, equal to an extent, or greater than an extent.

### Completion obligations

Selection −1 exempts the operation from all completion activity. This includes the comparison used to decide conditional completion, the conditional endpoint observation, both indirect-target lookups, both indirect calls, and F-d6032bc0598f. Admission or validation already performed is not undone.

For every other selection, the completion relationship is:

| Relationship, where arithmetic is defined | Required indirect operations |
|---|---|
| Selection’s successor is strictly below the comparison extent | F-U001, then F-U002 |
| Selection’s successor equals or exceeds the comparison extent | F-U002 only |

F-d6032bc0598f follows F-U002 and receives the object and retained selection. If all required evaluations and calls complete normally, the operation returns that selection.

Equality suppresses only F-U001. It does not reject the selection or remove F-U002 or F-d6032bc0598f.

Each later call requires normal return from the preceding required call. Results returned by F-U001, F-U002, or F-d6032bc0598f do not replace the selection. No retry, rollback, compensation, or recovery is represented when continuation is interrupted.
