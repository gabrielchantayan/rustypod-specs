## Behavior

### Initial conditional transfer

The function forms an address-sized value by multiplying the control word by \(2^{24}\).

Under the 32-bit model, this value is zero exactly when the control word’s low byte is zero.

When that low byte is nonzero:

- The initial transfer is skipped.
- The guarded arithmetic chains do not activate.
- Execution reaches the terminal loop with the incoming link address as its first-call base.

When the low byte is zero:

1. A derived address is formed from the link address, the control word’s bit-6 indicator, and the stack-position address shifted right by one.
2. A second control-derived address is formed by multiplication by \(2^{25}\).
3. A transfer destination is formed by adding the displacement word to the incoming transfer address as a **byte displacement**.
4. A 16-bit value is read from the incoming transfer address.
5. Updated transfer-related state is formed by subtracting the adjustment word from the destination.
6. The previously read 16-bit value is written to the destination.

The source read precedes the destination write. If source and destination alias, the store uses the value already read. There is no overlap handling beyond that single transfer.

On this branch, the low byte is zero, so the bit-6 indicator is also zero. Both control-derived addresses are zero under the stated 32-bit model.

No bounds, alignment, null-address, or access-permission checks precede the transfer.

### Guarded zero-condition processing

Several later stages are enabled only when the immediately preceding arithmetic result is zero. An unexecuted stage does not independently activate a later stage.

Although the representation includes variable shifts and carry propagation, shifts within the active zero-conditioned chains have a zero shift count: the shift count is taken from the low byte of a result already required to equal zero.

For the initial chain to advance beyond its first stages, all of these relationships are required:

- The initial transfer branch was taken.
- The incoming link address is zero.
- The derived link-and-stack address is zero.
- The displacement and comparison words are equal.
- The updated transfer-related address equals the adjustment word.
- The accumulator word is zero.
- The stack-position address plus twice the displacement word is zero modulo \(2^{32}\).

Under the stated model, the zero derived link-and-stack address, together with a zero link address, requires the stack-position address to be either zero or one. The final zero sum excludes one because twice a 32-bit word is even. Consequently, this deeply guarded path requires a zero stack-position address.

This is an arithmetic reachability condition, not evidence that a real execution environment permits such an entry state.

### Deeply guarded 16-bit update

If the preceding conditions hold, the representation performs another memory update:

- It changes a special stack-like processor-state location using the numeric stack-position address multiplied by 64.
- It forms a new link-derived address using the same byte-scale factor of 64.
- It reads a 16-bit quantity through the previous link address.
- It treats that quantity, zero-extended, as the destination address.
- It writes the quantity plus 15, truncated to 16 bits, to that destination.
- It advances a separate address-sized value by two bytes.

The supplied expression uses the link-addressed 16-bit value both to form the destination and to form the stored value. It does not establish whether there is one physical read or more than one. Stable ordinary memory is therefore a precondition for treating those uses as the same observed value.

Under the normalized reachability conditions above, the link address and stack-position address are both zero. This region therefore requires a read through address zero. Address zero must not be assumed valid.

If this region completes, the following zero-condition chain stops when it compares the two-byte-advanced value against zero-derived state: its result is two, not zero.
