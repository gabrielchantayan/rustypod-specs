# F-e0540021e757

## Purpose

F-e0540021e757 derives two output fields from a record’s source position and extent, optionally adjusts them against a 64-unit grid, and marks the record as processed.

Established behavior includes:

- Returning early when the processed flag is already set, after two context reads.
- Calling an opaque conversion dependency for source position and source extent.
- Supporting channel-specific bypass of all subsequent adjustment.
- Optionally replacing the initial position with positioning relative to another record.
- Optionally normalizing the output extent.
- Choosing whether to align the leading or trailing edge.
- Optionally applying a final center-based adjustment.

“Position,” “extent,” “channel,” and “centering” describe the arithmetic relationships. Their application-level meanings and physical units are inferred, not established.

## Interface

The displayed interface has four inputs and no returned value:

| Input | Representation and use |
|---|---|
| Record address | Address of writable storage containing at least the six 32-bit fields below |
| Context base | 32-bit address value used for channel-dependent reads and a dependency argument |
| Channel selector | Signed 32-bit value used in address arithmetic and channel-specific branches |
| Control base | 32-bit address value used to read control bytes |

The record layout is:

| Byte offset | Width | Meaning within this contract |
|---|---:|---|
| 0 | 32 bits | Source position |
| 4 | 32 bits | Source extent |
| 8 | 32 bits | Output position |
| 12 | 32 bits | Output extent |
| 16 | 32 bits | Flags |
| 20 | 32 bits | Related-record address; zero means absent |

The processed flag is mask `0x00000008`, meaning bit index 3. Other flag bits are preserved by the explicit completion operation.

The selected context address is the context base plus 204 times the channel selector, using 32-bit address arithmetic. The function accesses:

| Offset from selected context address | Width | Use |
|---|---:|---|
| 12 | 32 bits | Reference extent, read only on a particular extent-adjustment path |
| 200 | 32 bits | Opaque conversion parameter, captured before the processed check |
| 204 | 32 bits | Position offset, captured before the processed check |

Offset 204 is one complete stride beyond the selected address. The evidence does not justify moving this field or redefining the stride.

A separate dependency receives the context base plus 412 on the non-bypassed channel-1 path.

Control fields are byte-sized:

| Offset from control base | Applicable channel | Meaning |
|---|---|---|
| 120 | 0 | Zero selects bypass |
| 121 | 1 | Zero selects bypass |
| 122 | 0 | Nonzero enables final centering when bypass is not selected |
| 123 | 1 | Nonzero enables final centering when bypass is not selected |
| 124 | Every non-bypassed selector | Nonzero enables extent adjustment |

Only zero versus nonzero matters for these bytes.

**Preconditions:** Every address actually accessed must support the indicated access. There is no visible null check for the principal inputs, no channel-range check, and no address-overflow check. A related record must provide the fields actually accessed. Recursive processing has additional unresolved interface and termination requirements.

## Behavior

### Arithmetic interpretation

Scalar arithmetic and address calculations operate on 32-bit values. Additions, subtractions, negations, and address multiplication retain their 32-bit results; this contract does not replace them with unbounded arithmetic.

Signed comparisons interpret a 32-bit pattern as a signed integer. The visible right shifts used for halving are signed arithmetic shifts. They apply to source extents, the related record’s output extent, and transformed extents. **Source positions are not halved:** each enters its source-center calculation directly, with half its source extent added.

For a signed negative odd operand, arithmetic halving rounds toward negative infinity.

Define the grid-rounding operation:

\[
R(x)=((x+32)\bmod 2^{32})\mathbin{\&}\texttt{0xffffffc0}.
\]

For ordinary values away from wraparound, this rounds to a multiple of 64, with an exact midpoint choosing the higher grid point. Clearing the low six bits without first adding 32 is a different operation.

Conditional negation used to obtain a magnitude is also 32-bit. Negating the most-negative signed value leaves the same bit pattern; it does not produce a representable positive magnitude.

There is no visible validation of negative extents, arithmetic overflow, or coordinate range.

### Entry and processed-state check

The selected context address is calculated first. The conversion parameter at offset 200 is read and retained, followed by the position offset at offset 204. Only then are the record flags checked.

If the processed mask is already present, the function returns:

- Neither conversion call occurs.
- No explicit record write occurs.
- The two context reads have nevertheless occurred.

Thus an already-processed record does not make an invalid context safe.

### Initial conversion and control selection

For an initially unprocessed record, F-74efb2674226 is called first with the source position and the captured conversion parameter. Its 32-bit result, plus the captured position offset, becomes the provisional output position.

The source extent is then read for a second call to F-74efb2674226 using the same captured conversion parameter. Its result becomes the retained provisional output extent.

The second source-field read occurs after the first call. Dependency effects may therefore influence that read. The context values already captured are not refreshed for these calls.

For channel 0, control byte 120 selects bypass; for channel 1, byte 121 does so. A zero applicable byte causes this ordered publication:

1. Write provisional output extent.
2. Write provisional output position.
3. Read the flags then present and write them with the processed mask added.
4. Return.

Bypass omits final-centering control reads, the channel-1 dependency, related-record lookup, extent adjustment, and edge alignment.

On a non-bypassed channel-0 or channel-1 path, the corresponding centering byte is read and its zero/nonzero decision retained. Later changes to that byte do not cause it to be checked again.

Selectors other than 0 and 1 have neither channel-specific bypass nor final centering. They still select context addresses and reach shared adjustment behavior.

### Related-record positioning

On every non-bypassed path, the retained provisional extent is written to output offset 12 before further dependency activity.

For channel 1, F-758b8ec59e77 is then called with:

- The context base plus 412.
- The 32-bit sum of the current record’s source position and source extent, read for this call.

The related-record address is read only after this call returns. Consequently, this dependency can affect which related-record address is subsequently observed.

If the related-record address is nonzero, its flags are checked. When its processed mask is clear, a recursive invocation of F-e0540021e757 occurs. The displayed invocation supplies only the related-record address and context base, despite the four-input interface. The effective recursive channel and control inputs remain unresolved.

After the optional recursion, the related record’s output extent is captured, then its output position is captured. A third call to F-74efb2674226 converts the difference between the source centers:

\[
(\text{current source position}+\operatorname{half}(\text{current source extent}))
-
(\text{related source position}+\operatorname{half}(\text{related source extent})).
\]

All arithmetic is 32-bit. Here and below, “half” means signed arithmetic halving.

The new provisional position is the captured related output position, plus half its captured output extent, plus the third conversion result, minus half the current record’s retained provisional extent.

This replaces the initial converted-position-plus-offset result. The initial position conversion still occurred.

The related output fields are captured before the third conversion call. In contrast, the source-center expression is evaluated for that call after any recursive processing.

After related-record handling, the function writes the retained provisional extent and then the provisional position. These writes also occur when no related record exists.

### Optional extent adjustment

Control byte 124 is now read. If zero, extent adjustment is skipped.

If nonzero, the retained provisional extent is interpreted as signed.

**Extent at most 64:** The position becomes the low-six-bits-cleared value of the provisional position plus half the provisional extent. The extent becomes 64. This branch includes zero and negative extents and does not read the reference extent.

**Extent greater than 64:** The selected context’s reference extent at offset 12 is read. The function subtracts it from the provisional extent and conditionally negates a negative signed result.

If this signed magnitude-like result is less than 40, the reference extent is adopted. Exactly 40 does not qualify. The most-negative subtraction result remains negative after negation and therefore also satisfies the signed comparison with 40.

The resulting candidate extent is normalized as follows:

- A signed candidate below 48 is first replaced by 48.
- A signed candidate greater than 191 is rounded using \(R\), completing this normalization.
- Otherwise, including after the replacement with 48, the low-six-bit rules below apply.

| Low six bits | Result |
|---:|---|
| 0–9 | Preserve them |
| 10–31 | Replace them with 10 |
| 32–53 | Replace them with 54 |
| 54–63 | Preserve them |

The upper bits are retained during this low-bit normalization.

The fallback to 48 is **intermediate, not final**: 48 falls in the 32–53 band and consequently becomes 54. For example, provisional extent 65 with reference extent 47 adopts 47, substitutes 48, and finishes normalization at 54.

### Edge alignment

Let \(P\) and \(W\) denote the position and extent after any extent adjustment. The two candidate corrections are:

\[
\text{leading correction}=R(P)-P
\]

\[
\text{trailing correction}=R(P+W)-P-W.
\]

Each expression uses 32-bit arithmetic. The signed magnitude-like values of the corrections are compared.

The trailing correction is selected only when its magnitude is strictly smaller. A tie selects the leading correction.

The selected correction is added to the position. The function writes the corrected position first, then the current extent.

### Optional final centering

If the earlier channel-specific centering decision was enabled, the function uses the output fields stored after edge alignment.

The stored extent is checked as signed:

- Below 64: select a new extent of 64.
- Otherwise: obtain the stored extent for rounding and select \(R\) of that value.

A center candidate is formed from the stored output position plus half the new extent.

The adjustment depends on mask `0x00000040` in the new extent:

- Mask present: clear the center candidate’s low six bits, then add 32.
- Mask absent: add 32, then clear the low six bits.

The new extent is written first. The adjusted center minus half that extent is then written as the output position.

For ordinary positive multiples of 64, this selects half-grid centers for odd multiples and full-grid centers for even multiples. No positive-range restriction is enforced before the arithmetic.

### Completion

Every normally completing, initially unprocessed path finishes by reading the current flags and writing their bitwise OR with `0x00000008`.

Other flag bits are preserved as they exist at completion, not necessarily as they existed at entry.

## Side effects

Explicit record writes affect output position, output extent, and flags. The function contains no explicit assignment to source position, source extent, or the related-record address.

Intermediate values are published before completion:

- Provisional extent precedes the channel-1 dependency.
- Related-record processing precedes publication of the current record’s post-related position.
- Provisional output fields precede extent adjustment and edge alignment.
- Edge-aligned fields precede optional final-centering writes.
- The processed mask is written last.

No atomic publication, locking, rollback, explicit allocation, explicit release, or ownership transfer is visible.

Dependencies may affect memory or ownership in ways not established here. In particular, neither dependency may be assumed to preserve global state, record storage, context storage, or object lifetime. Safe continuation requires that subsequent accesses remain valid.

Aliasing is not checked. If record fields overlap context or control storage, explicit writes may influence later reads. The access ordering above remains relevant; disjoint storage is not an established invariant.

There is no error result or visible recovery path for invalid addresses, dependency failures, or nonterminating recursion.

## Acceptance examples

These are conditional static deductions, not executed tests. Unless specified otherwise, calls return normally, relevant memory remains valid and unchanged by dependencies, storage is disjoint, arithmetic does not wrap, and no related record is present.

1. **Already processed.** With the processed mask set, the conversion parameter and position offset are still read. No conversion or explicit record write follows.

2. **Channel bypass.** For channel 0 with byte 120 zero, suppose the position conversion returns 100, the captured offset is 7, and extent conversion returns 23. Extent 23 is written before position 107, then the processed mask is set. Bytes 122 and 124 are not consulted.

3. **Other selector.** A selector other than 0 or 1 still selects context storage and reaches shared edge alignment. It does not use channel-specific bypass or final centering.

4. **Small extent.** With extent adjustment enabled, provisional position 100, provisional extent 20, and final centering disabled, small-extent adjustment produces position 64 and extent 64. Edge alignment leaves them unchanged.

5. **Adopted reference below 48.** With provisional position 0, provisional extent 65, reference extent 47, extent adjustment enabled, and final centering disabled, the difference is 18. The reference is adopted, raised to the intermediate value 48, and low-bit normalized to 54. Edge alignment favors the already-aligned leading edge, producing position 0 and extent 54.

6. **Reference threshold.** Provisional extent 100 and reference extent 139 differ by 39, so 139 is adopted and normalized to 138. Reference extent 140 differs by exactly 40, so 100 is retained and normalized to 118.

7. **Trailing edge wins.** With extent adjustment and final centering disabled, position 20 and extent 40 give leading correction −20 and trailing correction +4. The output position becomes 24; extent remains 40.

8. **Tie favors leading edge.** Under the same controls, position 16 and extent 32 give corrections −16 and +16. The output position becomes 0.

9. **Final centering.** If the fields entering final centering are position 0 and extent 96, the new extent is 128. Its center is placed at 64, leaving final position 0.

10. **Processed related record.** Suppose the current source position and extent are 100 and 20, its provisional output extent is 20, and the related record has source position 80, source extent 40, output position 200, output extent 80, and the processed mask set. The center difference is \(110-100=10\), not a difference of halved source positions. If the third conversion returns 10, the replacement provisional position is \(200+40+10-10=240\). Recursion is skipped, but the third conversion is not.
