It does not establish an application-level purpose, a concrete object type, or a successful completion condition.

The strongest supported contract is therefore an execution-order contract: which values are derived from inputs and call results, which addresses are read or written, and where external calls intervene.

### Arithmetic conventions

The behavioral equations below use 32-bit bitvector arithmetic:

- Addition, multiplication, and left shifts retain the low 32 bits.
- Right shifts of explicitly unsigned values are logical.
- Byte stores retain the low eight bits.
- A 32-bit store writes four bytes; byte order is unspecified.

This is the intended machine-level reading of the displayed operations. The signed-looking expressions in the representation do not independently establish portable overflow or signed-shift semantics.

For compactness:

- **W(value)** means the low 32 bits of a value.
- **B(value)** means the low eight bits.
- **selector write at basis S** means: read one unsigned byte from address W(S + 1), then write a byte to the address equal to that byte’s numeric value plus 17.

Thus a selector write targets addresses 17 through 272. It does not implicitly dereference a full-width pointer.

2. **Byte-selector interpretation.** If W(S + 1) contains 0xfe when a selector operation occurs, its destination is address 271. It is not S + 17 and not an address formed by loading four bytes.
