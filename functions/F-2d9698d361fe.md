# F-2d9698d361fe

## Purpose

F-2d9698d361fe conditionally populates a caller-supplied object's configuration references and ordered collections of dependency results.

Its behavior has three distinct controls:

- A 32-bit field at offset `0xC4` suppresses all initialization when already nonzero.
- An 8-bit selector at offset `0xA8` chooses preliminary allocation and construction work.
- Subsequent control flow selects either a 60-entry result collection or a 46-entry collection with an optional 16-entry extension.

**Established static evidence:** the function performs the reads, dependency calls, and writes described below. It has no explicit success or error return value.

**Inferred intent:** this resembles mode-dependent, guarded resource initialization. The supplied material does not establish what the resources represent or whether a nonzero guard proves complete initialization.

This contract describes the supplied function body, not the internal behavior of its dependencies.

A fully accessible object region through offset `0x237` is sufficient for all direct object accesses described here. Individual paths need less accessible storage. Dependencies may impose additional requirements that are not established.

## Behavior

### Entry and suppression

The function first captures the shared argument, then the base construction argument. It next reads the 32-bit field at `0xC4`.

If that field is nonzero, the function returns immediately:

- No dependency is called.
- No object field is directly written.
- Neither control byte is read by the remaining initialization logic.
- The two entry captures have nevertheless already occurred.

The guard is tested only once. Later changes to `0xC4` do not cause another suppression decision during this invocation.

If the guard is zero, the function reads the selector byte at `0xA8`.

### Preliminary work selected by the initial selector

#### Initial selector 0

The function requests eight bytes from F-8157a180d901. It treats the returned value as the address of two consecutive 32-bit words and writes:

1. Decimal 30 at record offset 0.
2. Decimal 30 at record offset 4.

It then publishes that same returned address into the object in this order:

1. `0xBC`
2. `0xB4`
3. `0xB8`
4. `0xC0`

Thus four fields receive the same reference; this is not four independent small-record requests.

Next, the function performs two construction operations:

- Request 200 bytes, call F-637a7738122d with that request's result, the context, and the captured base construction argument, then store the returned 32-bit value at `0xCC`.
- Request another 200 bytes, read the mode-0 alternate argument, call F-637a7738122d with that request's result, the context, and the newly read argument, then store the returned value at `0xC4`.

The stored construction result is not required by this body to equal the allocation result.

#### Initial selector 1

No eight-byte record is requested, and the function makes no direct writes to `0xB4` through `0xC0`.

Three construction operations occur, in order:

| Request size | Third construction argument | Result destination |
|---|---|---|
| 200 bytes | Captured base construction argument | `0xCC` |
| 200 bytes | Mode-1 second argument | `0xC4` |
| 200 bytes | Mode-1 third argument | `0xC8` |

Each request is followed by its construction call and result store before the next request. The second and third external arguments are read after their respective allocation calls, not captured at entry.

#### Initial selector 2

Two separate eight-byte requests occur.

For the first returned record, the function writes 32-bit values 10 and 42 at offsets 0 and 4, respectively, then publishes the address at object offset `0xB4`.

For the second returned record, it writes 32-bit values 63 and 80 at offsets 0 and 4, respectively, then publishes the address at `0xB8`.

“Separate requests” does not establish that the returned addresses differ.

The function then requests 200 bytes and calls F-637a7738122d using:

- The allocation result.
- The context.
- The captured base construction argument plus `0x840`, or 2112 decimal.

It stores the construction result at `0xC4`. It makes no direct preliminary writes to `0xBC`, `0xC0`, `0xC8`, or `0xCC`.

The adjustment is expressed on a 32-bit integer-like value. Overflow semantics are not established; a portable contract must not silently widen the operation or promise signed wraparound.

#### Any other initial selector

The function skips all preliminary allocation and construction work and proceeds directly to the common collection.

This is not an error path in the supplied body. In particular, it does not directly establish a nonzero value at `0xC4`.

### Collection selection and control-byte rereads

After preliminary work for initial selectors 0, 1, or 2, the function rereads `0xA8`.

- If the reread value is 2, it populates the extended collection and returns.
- Otherwise, it populates the common collection and then considers the optional extension.

Consequently, the initial selector does not irrevocably determine the collection. Dependency-induced changes to the selector can affect this later decision.

For an initial selector outside 0, 1, and 2, there is no corresponding reread before collection selection: that path goes directly to the common collection.

### Extended collection

The extended collection contains exactly 60 calls to F-5710a8628cba.

Each call receives:

1. The original context.
2. The shared argument captured at entry.
3. The current value from the corresponding extended descriptor location.

Results are written as consecutive 32-bit words beginning at `0x148` and ending at `0x234`, in descriptor order.

Each call's result is stored before the next collection call. The descriptor for a later call is read for that call rather than all descriptors being snapshotted at entry.

After the final store, the function returns. It does not populate the common collection or read the optional-extension flag on this path.

### Common collection and optional extension

The common collection contains exactly 46 calls to F-5710a8628cba, using the context, captured shared argument, and common descriptors in order.

Their results occupy consecutive 32-bit words from `0xD0` through `0x184`. Each result is stored before the next call.

Only after all 46 results have been stored does the function read the byte at `0xA9`:

- Zero causes immediate return.
- Any nonzero byte causes 16 additional collection calls using the optional descriptors.

Optional results occupy consecutive 32-bit words from `0x1C0` through `0x1FC`, again with each store preceding the next call. The function then returns.

The optional flag is tested once. It is not restricted to the value 1.

## Side effects

### Direct writes and preservation limits

The function writes only the selected object fields and the first two words of each requested eight-byte record. It does not directly initialize the contents of the 200-byte allocations.

Fields outside the selected path's destinations receive no direct writes from this body. This is not a guarantee that they remain unchanged: dependencies may modify the object, external data, or aliased memory.

Neither control byte is directly written by this function.

The guard result at `0xC4` is published before collection population. A nonzero guard can therefore coexist with incomplete collections if a later operation fails or does not return. There is no final completion-marker write.

### Ownership and allocation

There is no explicit release, reference-count adjustment, rollback, or cleanup call.

- Initial selector 0 publishes one small-record reference into four fields.
- Initial selector 2 publishes results of two small-record requests into two fields.
- Construction dependencies receive allocation results, but ownership transfer, retention, replacement, and release behavior are unknown.
- Existing references overwritten in object fields are not explicitly released here.

The body provides no basis for assigning ownership of collection results to this function or its caller.

### Failure behavior and partial state

No allocation or construction result is checked for failure.

An unusable eight-byte allocation result is used as a write address. The function does not provide a controlled failure return for that case.

A 200-byte allocation result is forwarded to F-637a7738122d even if it has a failure-like representation. Likewise, zero or otherwise failure-like construction and collection results are stored without branching.

There is no transaction boundary. Earlier writes remain published when later work fails, subject to whatever the dependency or execution environment does. Exceptions, faults, termination, and nonlocal exits cannot be characterized from this body alone.

## Acceptance examples

These are conditional acceptance scenarios, not executed tests. Unless stated otherwise, assume dependencies return normally, provide usable record storage, and do not mutate controls, relevant external data, or previously published results.

### Nonzero entry guard

Given any nonzero 32-bit value at `0xC4`, accept only a trace with the two entry captures followed by the guard read and return. There must be no dependency calls or direct object writes.

### Selector 0, optional flag zero

Given guard zero, selector 0, and optional flag zero:

- Request sizes are 8, 200, and 200.
- The small record contains two 32-bit values of 30.
- Its address is published to `0xBC`, `0xB4`, `0xB8`, and `0xC0`, in that order.
- Two construction results are published to `0xCC`, then `0xC4`.
- Exactly 46 collection calls populate `0xD0`–`0x184`.
- No optional collection calls occur.

### Selector 1, optional flag nonzero

Given guard zero, selector 1, and any nonzero optional flag:

- Three 200-byte requests and three construction calls occur.
- Construction-result destinations are `0xCC`, `0xC4`, then `0xC8`.
- Exactly 62 collection calls occur: 46 common calls followed by 16 optional calls.
- No small-record requests occur.

### Selector 2

Given guard zero and a selector that remains 2:

- Request sizes are 8, 8, and 200.
- The small records receive `(10, 42)` and `(63, 80)`.
- Their references are published at `0xB4` and `0xB8`.
- The construction call uses the adjusted base argument.
- Exactly 60 collection calls populate `0x148`–`0x234`.
- The optional flag is not read.

### Unsupported selector

Given guard zero and an initial selector of 3:

- No allocation or construction calls occur.
- The common collection runs.
- The optional flag determines whether the additional 16 calls occur.
- This body makes no direct write to the guard.

If dependencies also leave the guard zero, a later invocation remains eligible to repeat initialization.

### Selector changed during preliminary work

Given initial selector 0, if preliminary dependencies cause the reread selector to equal 2, the small-record and construction work remains that of selector 0, but the 60-entry extended collection follows.

Conversely, initial selector 2 followed by a non-2 reread produces selector-2 preliminary work followed by the common collection.

### Zero construction result

If the construction result destined for `0xC4` is zero, the function still continues into collection processing. It does not retry or report failure. A later invocation is not suppressed by that zero unless some other operation changes the guard.
