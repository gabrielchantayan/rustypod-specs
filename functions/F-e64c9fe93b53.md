# F-e64c9fe93b53

## Purpose

F-e64c9fe93b53 selects between two processing paths for an input object identified by a 16-bit format tag:

- With a zero mode argument, it forwards the object’s payload and derived dimensions to a construction dependency.
- With a nonzero mode argument, it obtains three opaque values from an allocation-like dependency, invokes a format-specific processing dependency, constructs a result, and passes that result together with the three values to an attachment-like dependency.

The allocation, conversion, construction, and attachment interpretations are inferred intent. The established behavior is the dependency-call sequence and its arguments; the supplied evidence does not establish what those dependencies actually allocate, convert, retain, or release.

Only format tags `0x0565` and `0x1888` have defined processing branches in the supplied representation. Other tags reach a return whose value is not established.

## Behavior

### Initial reads and null handling

The function first reads all four endpoint fields, in this order:

1. The 32-bit field at `0x98`.
2. The 32-bit field at `0x9C`.
3. The 32-bit field at `0xA0`.
4. The 32-bit field at `0xA4`.

It then compares the object argument with zero.

Consequently, the zero comparison is not an effective pre-dereference null guard. A zero object argument can cause invalid memory access before the branch that returns zero is reached. A contract that promises a safe zero result for a null object would exceed the evidence.

The four endpoint values are retained for later calculations. The shown body does not reload those fields after dependency calls.

### Arithmetic

For representable signed 32-bit arithmetic, the function derives:

- Horizontal extent from the horizontal endpoint difference.
- Vertical extent from the vertical endpoint difference.
- Area-like quantity from the product of those extents.

On the nonzero-mode path, it also derives a signed quarter-area quantity. The displayed shift-and-correction expression computes division by four with truncation toward zero when its input is a valid signed 32-bit area value. Thus a negative area of `−15` produces `−3`, not `−4`.

The quarter-area quantity is computed separately for the second and third calls described below. Both calculations use the retained endpoint values; intervening dependency calls do not cause those fields to be reread.

The evidence does not establish a portable result for an overflowing endpoint subtraction or multiplication. Exact overflow behavior is documented_only rather than specified as wrapping, saturation, rejection, or a wider intermediate calculation.

### Zero-mode path

No calls to F-638beded7699 occur when the mode is zero.

The function reads the 16-bit discriminator:

- If the first discriminator read equals `0x0565`, the format is accepted immediately.
- Otherwise, the displayed body reads the discriminator again and compares that value with `0x1888`.
- If neither comparison accepts the object, the function returns an unspecified 32-bit value.

For either accepted format, it reads the payload field at `0x04` and calls F-798fb9f4fe09 with nine ordered arguments:

| Position | Value |
|---:|---|
| 1 | `3` |
| 2 | Horizontal extent |
| 3 | Vertical extent |
| 4 | Vertical extent again |
| 5 | `2` |
| 6 | Payload field value |
| 7 | `0` |
| 8 | `0` |
| 9 | `0` |

It returns that dependency’s 32-bit result directly.

This path does not invoke either format-specific dependency or F-aaa12137cb38. No success check is performed on the returned value.

### Nonzero-mode preparation

Before checking the discriminator, the function makes three calls to F-638beded7699, in order:

1. Area-like quantity and the constant `0x35`, decimal `53`.
2. Quarter-area quantity and `53`.
3. Quarter-area quantity and `53`.

Call their opaque 32-bit results the primary value, secondary value, and tertiary value.

The second and third requests have equal numeric size arguments when the arithmetic is defined, but they are distinct calls. Their results need not be equal. No result is checked for zero, an error sentinel, or any other failure indication.

These calls precede format validation. Therefore, an unsupported format does not prevent the three calls or any effects they produce.

### Nonzero-mode format processing

After the three preparation calls, the function reads the discriminator.

If it equals `0x0565`, the function reads the payload field and calls F-28199ab2af9a with six ordered arguments:

1. Vertical extent.
2. Horizontal extent.
3. Payload field value.
4. Primary value.
5. Secondary value.
6. Tertiary value.

Otherwise, it reads the discriminator again. If that read equals `0x1888`, it reads the payload field and makes the corresponding six-argument call to F-c0ab5b5d32b8, with the same argument ordering.

If neither comparison accepts the format, the function returns an unspecified 32-bit value. There is no explicit cleanup call on this exit.

Any return value from the selected format-specific dependency is ignored. The function does not explicitly check whether processing succeeded.

### Nonzero-mode result construction

After either supported format-specific call returns, the function calls F-798fb9f4fe09 with these nine arguments:

| Position | Value |
|---:|---|
| 1 | `0` |
| 2 | Horizontal extent |
| 3 | Vertical extent |
| 4 | Vertical extent again |
| 5 | `2` |
| 6–9 | `0` in each position |

It retains the returned 32-bit value and calls F-aaa12137cb38 with five arguments:

1. The retained result.
2. Primary value.
3. Secondary value.
4. Tertiary value.
5. `0`.

The result of F-aaa12137cb38, if any, is ignored. F-e64c9fe93b53 then returns the retained result from F-798fb9f4fe09.

There is no explicit check between construction and the final call. In particular, a zero construction result is still passed to F-aaa12137cb38 if the construction dependency returns normally.

## Side effects

### Direct memory access

The shown body directly reads object fields but contains no explicit store into the object or its payload.

This does not establish that the object or payload remains unchanged. The dependencies receive opaque values that may identify accessible memory, and their mutation behavior is unknown.

Endpoint reads occur before any dependency call. On the nonzero-mode path, discriminator and payload reads occur after the three preparation calls. Therefore:

- Dependency-induced changes to endpoint storage do not alter the already retained endpoint values.
- Dependency-induced changes to the discriminator or payload storage can affect subsequent reads, if the dependencies can reach that storage.
- The two displayed discriminator reads must not be treated as an atomic snapshot when describing concurrent or externally induced mutation.

The supplied representation establishes the displayed read sequence, not whether the original compiled execution used every displayed load under all memory-model assumptions.

### Ownership and lifetime

No ownership transfer is established.

The function forwards values returned by F-638beded7699 to the selected format-specific dependency and then to F-aaa12137cb38. It does not explicitly release those values on any path.

That absence is not proof of a leak: allocation status, ownership, and release responsibilities are unknown. It is also not proof that the values remain valid after any dependency call.

Likewise, zero mode forwards the payload value to F-798fb9f4fe09, but the evidence does not establish whether that dependency copies, borrows, retains, transforms, or assumes ownership of the referenced data.

### Errors and interruption

The body contains no explicit error-reporting channel, exception handling, rollback, or allocation-failure recovery.

If a dependency fails to return normally, later calls and the final return are not guaranteed to occur. No assumption is made that dependencies preserve globals, thread-local state, external resources, or memory ownership.

## Acceptance examples

These are conditional static acceptance criteria, not results of executed tests. Unless stated otherwise, assume valid field access, representable arithmetic, stable discriminator storage, and normally returning dependencies.

### Supported format with zero mode

Given endpoints that produce horizontal extent `8` and vertical extent `6`, mode zero, and tag `0x0565`:

- No preparation or format-specific calls occur.
- F-798fb9f4fe09 receives `(3, 8, 6, 6, 2, payload, 0, 0, 0)`.
- Its result is returned directly.

The same constructor arguments apply to tag `0x1888`, though the displayed format-selection logic reaches it through a second discriminator read.

### Supported format with nonzero mode

Given extents `8` and `6`, mode `−1`, and tag `0x1888`:

- F-638beded7699 receives `(48, 53)`, then `(12, 53)`, then `(12, 53)`.
- F-c0ab5b5d32b8 receives vertical extent `6` before horizontal extent `8`, followed by the payload and the three retained results.
- F-798fb9f4fe09 receives `(0, 8, 6, 6, 2, 0, 0, 0, 0)`.
- F-aaa12137cb38 receives that construction result, the three retained results, and zero.
- The construction result is returned.

Changing the mode from `−1` to any other nonzero 32-bit value does not change this branch selection.

### Negative and non-divisible area

Given horizontal extent `−5`, vertical extent `3`, and nonzero mode:

- The preparation quantities are `−15`, `−3`, and `−3`.
- The function does not reject the negative extents or round the quarter-area downward to `−4`.
- Whether dependencies accept these values is unknown.

### Zero extent

Given one zero extent and nonzero mode, all three preparation size arguments are zero. The three calls still occur. The function has no special empty-object return.

### Unsupported format

For a stable discriminator other than the two supported values:

- Zero mode reaches no dependency call.
- Nonzero mode performs all three preparation calls before rejection.
- Neither path has a specified return value for this case.
- No explicit release occurs in the shown body.

### Failure-like dependency results

If a preparation call returns zero, that zero is forwarded without a check on a supported path.

If nonzero-mode construction returns zero, F-aaa12137cb38 is still called with zero as its first argument. Acceptance of that argument is not established.
