## Acceptance examples

These are conditional static acceptance criteria, not executed tests.

1. **Different values from the layout reads.**  
   If the first layout-global read yields `0x1000` and the second yields `0x2000`, the direct store at initial-object offset `0x00` must receive `0x2000`; the subsequent store at `0x18` must receive `0x10A0`. Using either read for both stores would violate the visible data dependencies.

2. **Stable layout global.**  
   If both layout reads yield `0x1000`, the corresponding stores receive `0x1000` and `0x10A0`. This equality case does not justify collapsing the two reads into one in the contract.

3. **Address-preserving initialization.**  
   If all calls in the three initializer families return their address arguments unchanged, and the arithmetic and accesses are valid, the fourth F-5b24edfb22c0 result is initial object plus `0xAC`; the third F-40173c838070 result is initial object plus `0xD0`; and the final anchor is initial object plus `0x2FC`. The returned address then equals the initial-object address.

4. **Different final initializer result.**  
   If the fourth F-a891c2749310 call returns another usable address, subsequent result-relative setup and normal return must use that address minus `0x2FC`. Earlier initial-object stores remain based on the original acquisition result.

5. **Byte boundaries.**  
   The direct clear at initial-object offset `0x88` does not itself clear bytes `0x89` through `0x8B`. Likewise, the service-result store at result-relative `0xC6` does not itself assign neighboring bytes. Dependencies may independently change those bytes.

6. **Configuration mutation during construction.**  
   If F-1058afc38c04 changes the second configuration global before returning, F-c085f24c0914 receives the value read afterward, not a pre-construction value.

7. **Distinct repeated service results.**  
   If the two F-b7af80e829ec calls return different usable objects, the first `0x00` dispatch uses the first object’s table; the `0x108` dispatch uses the second object’s table.

8. **Later field modification.**  
   If F-c807de8b89bb changes result-relative offset `0x80`, the function does not restore decimal 100 afterward. Acceptance must distinguish the earlier assignment from the final memory value.

9. **Invalid initial acquisition.**  
   If F-c91745d68354 returns an unusable address, there is no visible graceful-rejection branch before the first direct store. A required clean failure result would exceed the evidence.
