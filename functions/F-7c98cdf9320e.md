# F-7c98cdf9320e

## Purpose

F-7c98cdf9320e conditionally retrieves a four-byte value from a caller-supplied memory region. A selector in the range 0–4 is first translated through an externally located byte table. The translated byte determines which four-byte value is returned, except that translated value 4 suppresses the retrieval and produces zero.

The supplied static evidence establishes three distinct zero-return cases:

- The original selector is at least 5 under an unsigned comparison.
- The four-byte control field at offset `0xC4` from the supplied address is zero.
- The selected translation-table byte equals 4.

Zero can also be the contents of a successfully retrieved four-byte value. The return value does not distinguish these cases.

A plausible intent is an indexed lookup with an optional translation table and a reserved “no value” selector. That interpretation is inferred intent, not an additional constraint on memory contents or permitted translated selectors.

## Interface

### Inputs

The function has two arguments:

| Argument | Recovered width and interpretation | Role |
|---|---|---|
| Region address | 32-bit integer used as an address | Locates the control field and the eventual four-byte result |
| Original selector | Unsigned 32-bit integer | Gates execution and selects a byte within a translation table |

The recovered interface represents the first argument as an integer, not as a structured object or a pointer with an established ownership contract. “Region address” describes its observed use.

The function also depends on an external table-base datum that is not an explicit argument. The supplied evidence does not establish how that datum is initialized, updated, or owned.

### Return value

The return is exactly four bytes. It is either:

- All zero bits; or
- The four-byte contents read from the result address determined by the translated selector.

The return type does not establish whether a nonzero result is an integer, address, handle, flag set, or another representation. The function does not inspect or dereference the returned value.

### Relevant memory layout

Let the supplied region address be the origin for these offsets:

| Location | Access width | Meaning established by use |
|---|---:|---|
| Offset `0xC4` | 4 bytes | Control value; zero disables retrieval, while nonzero selects an external table slot |
| Offset `0x38 + 4 × translated selector` | 4 bytes | Returned value, unless the translated selector is 4 |

The external lookup has two levels:

1. A slot in a table of four-byte address values, selected using the control value.
2. A single byte at the selected address plus the original selector.

For a positive control value of 1, the first four-byte slot is selected. A control value of 2 selects the next slot. The observed slot displacement is four times the control value, minus four.

This does not establish that control values must be positive. Nonzero negative values are not rejected.

## Behavior

### Initial unsigned range gate

The original selector is compared with 5 as an unsigned 32-bit value.

Values 0, 1, 2, 3, and 4 continue to the lookup path. Every other 32-bit value returns zero without an explicit read of the supplied region or external lookup data.

Consequently, a bit pattern that would represent a negative signed integer is not accepted through this interface. For example, `0xFFFFFFFF` is a large unsigned selector and takes the immediate zero-return path.

### Control-field read

For an original selector below 5, the function reads the four-byte control field at region offset `0xC4`.

That value is retained for subsequent decisions and address selection. If it is zero, the function returns zero. In that case, it does not read the external address table, a translation byte, or a result entry.

The zero control value disables retrieval even when the original selector would otherwise identify an ordinary result position. There is no untranslated fallback lookup.

### Translation-table selection

For a nonzero control value, the function uses the external table-base datum to locate a four-byte slot. The slot displacement is four times the control value, minus four.

The slot’s four-byte contents are then used as the address of a byte translation table. The original selector supplies the byte displacement within that table.

Only one translation byte is read. The function does not scan the table or read all five potential entries.

The byte is converted to an unsigned 32-bit value. Its resulting range is therefore 0–255. Bytes with the high bit set remain values 128–255; they are not sign-extended into negative selectors.

There is no check that the slot address or the address loaded from it is nonzero. There is also no check that the translation table contains five readable bytes; only the byte needed for the current call is explicitly accessed.

### Translated-selector decision

The translated selector is compared with 4.

If it equals 4, the function returns zero without reading a result entry.

Otherwise, the function reads and returns four bytes at region offset `0x38 + 4 × translated selector`.

There is no second range check against 5. In particular, translated selectors greater than 4 are accepted for result-address calculation. A behavioral model that restricts successful results to translated selectors 0–3 would omit behavior present in the supplied evidence.

For the full translated-byte range:

- The smallest result offset is `0x38`, for translated selector 0.
- Offset `0x48`, corresponding to translated selector 4, is excluded from the final read.
- The largest result offset is `0x434`, for translated selector 255.
- That largest four-byte read spans offsets `0x434` through `0x437`, inclusive.

These bounds describe result offsets, not a verified allocation size.

### Read ordering and aliasing

The explicit data-read sequence is conditional:

1. Read the control field, after the initial selector gate succeeds.
2. For a nonzero control value, obtain the external table base and read the selected four-byte address slot.
3. Read the selected translation byte.
4. If that byte is not 4, read the four-byte result.

The result-location formula can overlap other meaningful storage in the supplied region. In particular, translated selector 35 produces offset `0xC4`, the control-field location. On that path, the function performs a later four-byte read from the same address used for the earlier control read.

The evidence does not justify replacing that later read with the earlier retained control value. If memory changes between reads, the final contents could differ. Thread-safety, atomicity, and the legality of such concurrent changes are not established.

No disjointness requirement is shown between the region, the external slot table, and the translation table.

## Acceptance examples

These examples are conditional specifications derived from static evidence. They have not been executed. Unless stated otherwise, all required addresses are valid, arithmetic is representable, and relevant memory remains unchanged during the call.

### Selector rejected before memory access

Given an original selector of 5, the result is zero. No explicit control-field, address-slot, translation-byte, or result read occurs.

The same applies to selector `0xFFFFFFFF`, because the initial comparison is unsigned.

### Disabled lookup

Given an original selector of 2 and a control field containing zero, the result is zero.

Only the control field is explicitly read. Contents at the external table base and at region offset `0x40` do not affect this call; the function does not use the original selector directly as a fallback result index.

### Ordinary translated retrieval

Given:

- Original selector 2.
- Control value 1.
- The first external address slot identifies a readable translation table.
- Translation byte 2 contains 3.
- Region offset `0x44` contains the four-byte value `0x12345678`.

The function returns `0x12345678`.

The result location follows translated selector 3, not original selector 2.

### Reserved translated value

Given an accepted original selector and a nonzero control value, if the selected translation byte contains 4, the result is zero.

The function does not read the four-byte location at region offset `0x48`.

### Original selector 4 can still retrieve a value

Given original selector 4, a nonzero control value, and selected translation byte 0, the function returns the four bytes at region offset `0x38`.

The original selector 4 is accepted. The reserved-value rule applies to the translated byte, not directly to the original selector.

### Translation beyond the initial range

Given original selector 0, a nonzero control value, and selected translation byte 255, the function reads and returns the four bytes beginning at region offset `0x434`.

A conforming description must not add a rejection merely because the translated value exceeds 4.

### Overlapping control and result storage

Given a selected translation byte of 35, the final result read occurs at region offset `0xC4`.

If that location remains unchanged after the initial control read, the returned four-byte pattern equals the control field’s contents. The final read nevertheless remains a separate access in the observed behavior.

### Successful retrieval of zero

Given a valid translated selector other than 4 and a selected result entry containing all zero bits, the function returns zero after completing the result read.

This outcome cannot be distinguished from a gated zero return using the return value alone.
