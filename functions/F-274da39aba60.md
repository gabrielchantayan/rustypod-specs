# F-274da39aba60

## Purpose

F-274da39aba60 conditionally applies a 32-bit target to an object and its associated records. It first checks object state, may adjust the target, and may attempt a range-dependent operation before entering a broader update path.

The established return values are:

- **0:** no broader update was completed, either because a gate suppressed it or because the range-dependent operation returned zero.
- **1:** the broader update reached its normal completion condition.
- **3:** an early rejection or a dependency-reported failure occurred.

These descriptions distinguish observable control flow, not a proven application-level status enumeration. In particular, a return of 3 does **not** guarantee that the object was left unchanged.

The apparent intent is to coordinate a target-position transition across an object, its records, and an associated object. The units of the target and the meaning of the states are not established.

## Interface

The function accepts:

1. **Object reference:** a pointer to writable storage containing 32-bit fields, byte-sized state fields, associated-object references, record storage, and a virtual-dispatch reference.
2. **Requested target:** an unsigned 32-bit value.

It returns a 32-bit value equal to 0, 1, or 3 on every shown normal-return path.

All offsets below are byte offsets from the supplied object unless marked as record-relative. The visible layout uses four-byte words and four-byte pointer representations.

## Behavior

### Initial rejection and target adjustment

The first visible object access examines the byte at 0x1390. If it equals 3, the function returns 3 immediately. No dependency is called on this path.

Otherwise, the function reads the unsigned 32-bit value at 0x108C. The effective target initially equals the requested target. It changes only when both conditions hold:

- The value at 0x108C is no greater than the requested target, using an unsigned comparison.
- That value is greater than 5000.

When both hold, the effective target becomes that value minus 5000. Otherwise, the requested target is retained.

Consequences include:

- A value of exactly 5000 does not trigger adjustment.
- A value greater than the request does not trigger adjustment.
- When adjustment occurs, subtraction cannot underflow.
- The effective target remains a 32-bit bit pattern; subsequent branches do not all interpret it with the same signedness.

### Optional range-dependent path

After target adjustment, the function examines the byte at 0x1384.

If it is not 4, execution proceeds to the broader-update gates.

If it is 4, the function calls **F-d4c824a654fe**, passing the object and addresses for two 32-bit output values. The low 32 bits of its returned value are checked first. A nonzero low half causes immediate return 3.

On a zero low half, the first output is interpreted as a signed range start. A usable interval exists only when:

- The start is nonnegative.
- The second output, interpreted as a signed end, is strictly greater than the start.
- The effective target, interpreted as signed 32-bit, is at least the start and strictly less than the end.

A negative start, an empty or reversed interval, or a target outside this half-open interval sends execution to the broader-update gates.

The dependency’s returned upper 32 bits appear in intermediate handling for a negative start. They do not enable entry into the range-dependent operation: a negative start independently forces the broader path.

For a usable interval containing the target:

1. A local unsigned 32-bit output is initialized to zero.
2. The associated object referenced at 0x107C is invoked through virtual slot 0x38, receiving the address of that output.
3. If its return is not 3 **and** the output is no greater than the effective target under unsigned comparison, execution proceeds directly to the broader-update gates.
4. Otherwise, **F-e1cd4dd64631** is called with the original object and effective target.
5. A nonzero result from F-e1cd4dd64631 sends execution to the broader-update gates. A zero result causes return 0.

Thus, virtual-slot return 3 does not itself terminate this function with 3. It selects the F-e1cd4dd64631 branch, regardless of the output value.

### Broader-update gates

The broader update is considered only if:

- An external byte reached through a global reference equals zero.
- The object byte at 0x1393 is neither 2 nor 1.

The global byte is tested first. When it is nonzero, the object-byte test is skipped. If either gate suppresses the update, the function returns 0.

Passing these gates causes dispatch through the original object’s virtual slot 0x3C:

- If that call returns zero, execution proceeds without calling F-fb9b4756e838.
- If it returns nonzero, **F-fb9b4756e838** is called with the object.
- A nonzero result from F-fb9b4756e838 causes return 3.
- A zero result allows execution to continue.

Next, **F-f0216cff9365** is called with the opaque handle read from 0x1380, using the one-argument call form. A nonzero result causes return 3.

### Record updates

After a zero result from that one-argument call, records are processed in ascending index order, beginning at index zero.

The count at 0x1080 is interpreted as signed. A zero or negative count produces no record iterations, but does not prevent the subsequent object-wide update.

For each visited record, the visible order is:

1. Call F-f0216cff9365 with the current handle from 0x1380 and the address at record-relative offset 0x30.
2. Call **F-2bb3dbfa7286** with a newly read handle from 0x1380 and the same record address.
3. Read the 32-bit source field at record-relative offset 0x00 and write it to offset 0x1C.
4. Write all one bits to the 32-bit field at offset 0x24.
5. Read the source field at offset 0x00 again and write it to offset 0x0C.
6. Clear the 32-bit field at offset 0x10.
7. Write byte value 2 at offset 0x38.
8. Write the effective target to the 32-bit field at offset 0x28.
9. Clear the 32-bit field at offset 0x2C.

The return values of the two per-record calls are ignored. Their effects are not undone.

The record count is read again for subsequent loop conditions. It is not a fixed entry-time snapshot. The handle is likewise reread for each call rather than retained across calls.

Under ordinary stable-memory conditions, the two copies of a record’s source value match. The evidence establishes two separate reads, not an atomic snapshot or a concurrency guarantee.

### Object-wide update and completion

After all record iterations:

1. The byte at 0x106D is written with 2.
2. The byte at 0x1384 is written with 1.
3. The associated object currently referenced at 0x107C is invoked through virtual slot 0x10 with the effective target.
4. If that call returns zero, the byte at 0x13B1 is written with 1 and the provisional result is 1.
5. If it returns nonzero, the provisional result is 3. No clearing or replacement of the byte at 0x13B1 is shown.
6. F-2bb3dbfa7286 is called with the current handle from 0x1380 and the address at object offset 0x13A8.
7. If this final call returns zero, the provisional result is returned. Otherwise, the function returns 3.

The final dependency call occurs even when virtual slot 0x10 reports failure. It is not reached when the initial one-argument F-f0216cff9365 call fails.

## Side effects

Direct writes are confined to the listed record fields, object bytes, and local output storage. No direct allocation, deallocation, or ownership transfer is visible.

The function passes object-contained addresses and local output addresses to dependencies. Their retention, allocation, synchronization, and release behavior are unknown. The calls must not be described as acquiring or releasing a resource solely from their placement.

Dependencies may mutate the object, associated objects, the global gate, or other shared state. No preservation guarantee is established. Consequently:

- A later handle read may differ from an earlier one.
- A later loop-bound read may observe a changed count.
- The associated object used for the final update may differ from the one used during range handling.
- Early return 3 after a dependency call does not imply absence of dependency side effects.

There is no visible rollback. Records and state bytes are modified before the final status is known. A return of 3 can therefore accompany a partially or fully applied local transition.

The byte at 0x13B1 is set only on one success branch. A previously set value may remain set when a later attempt fails.

## Acceptance examples

These are conditional acceptance cases derived from static evidence, not executed tests. Unless specified otherwise, dependencies return normally and preserve the state needed for the example.

1. **Immediate rejection.** If the byte at 0x1390 equals 3, the result is 3, with no dependency calls and no direct writes.

2. **Adjustment threshold.** With the value at 0x108C equal to 5000 and a request of 9000, the effective target remains 9000. With that value equal to 5001 and the same request, it becomes 1. A value of 9001 does not adjust a request of 9000.

3. **Half-open interval.** Suppose range mode is active and F-d4c824a654fe succeeds with start 100 and end 200. Target 100 enters the range-dependent path; target 200 does not. An end equal to 100 also selects the broader path.

4. **Mixed signedness.** With a nonnegative valid interval, an effective target of 0x80000000 is interpreted as negative for interval membership and therefore cannot enter the range-dependent path. Its original 32-bit bit pattern remains available to the broader update.

5. **Range operation selected by status.** For a target inside the interval, if virtual slot 0x38 returns 3 and F-e1cd4dd64631 returns zero, the function returns 0 without entering the broader gates.

6. **Range operation bypassed.** For target 150, if virtual slot 0x38 returns 0 and writes 120, F-e1cd4dd64631 is not called; execution proceeds to the broader gates.

7. **Suppressed broader update.** If the external gate byte is nonzero, the function returns 0 without invoking slot 0x3C. The same suppression occurs with a zero external gate and object byte 0x1393 equal to 1 or 2.

8. **Zero-record completion.** With count zero, all broader gates passing, the one-argument F-f0216cff9365 returning zero, virtual slot 0x10 returning zero, and the final F-2bb3dbfa7286 returning zero, the result is 1. No record calls occur; the object-wide state writes still occur.

9. **Failure after mutation.** If records have been updated and virtual slot 0x10 returns nonzero, the final dependency is still called. The result is 3 even if that final call returns zero; earlier writes remain.

10. **Final failure overrides success.** If virtual slot 0x10 returns zero but the final F-2bb3dbfa7286 returns nonzero, the result is 3. The write of 1 to byte 0x13B1 has already occurred.
