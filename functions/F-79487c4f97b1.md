# F-79487c4f97b1

## Purpose

F-79487c4f97b1 consumes a two-word record header from a caller-managed input cursor, converts both header words through F-4e1ee8e86ebb, and processes the following data according to the sign of the converted first word.

The established behavior has two paths:

- **Negative first word:** advance over a region whose signed length is the converted second word. Do not copy bytes, invoke the processing dependency, or explicitly write the result slot.
- **Nonnegative first word:** reject a converted second word greater than 512, copy the indicated bytes into caller-provided storage, and invoke F-fca51b715561. A zero dependency return produces result value 1. A nonzero dependency return produces result value 0 and additionally advances by the current first-word output, subject to a bounds check.

The function returns a separate 32-bit status. Status zero does not imply that the result slot was written or that its value is zero.

The framing interpretation above describes observed operations. The meanings of the converted words, the copied bytes, and the dependency’s return value are not established.

### Return values

## Behavior

### 1. First-word acquisition

The function first reads the count slot and checks whether the input limit is less than that value plus four.

If the check fails, it returns 7 without explicitly writing any caller storage or invoking either dependency.

Otherwise, the observable sequence is:

1. Read a four-byte word from the address in the cursor slot.
2. Write that raw word to the first-word slot.
3. Increase the cursor-slot value by four.
4. Increase the count-slot value by four.
5. Invoke F-4e1ee8e86ebb with the conversion context and the current first-word-slot value.
6. Write the returned 32-bit value to the first-word slot.

The sign of this returned value selects the path. It is the returned conversion value that determines this branch, not a later reread of the first-word slot.

The raw-word write is observable before conversion. The cursor and count already include the first header word when the conversion dependency runs.

### 2. Second-word acquisition

Both paths next check whether the input limit is less than the current count-slot value plus four.

If so, the function returns 3. The first-word acquisition and conversion are not rolled back.

Otherwise, the function:

1. Reads a four-byte word from the current cursor address.
2. Writes that raw word to the second-word slot.
3. Increases the cursor-slot value by four.
4. Increases the count-slot value by four.
5. Invokes F-4e1ee8e86ebb with the conversion context and the current second-word-slot value.
6. Writes the returned value to the second-word slot.

The dependencies’ side effects matter here: the second-word check and read use state current after the first conversion call, not necessarily the entry count and cursor plus four.

### 3. Negative-first-word path

After the second conversion, the function saves the current cursor address. It checks whether the input limit is less than the current count plus the returned second conversion value.

If the check fails, it returns 4. Both header words have already been consumed and converted. This function has not yet advanced past the following data.

If the check passes:

1. Increase the count slot by the returned second conversion value.
2. Write the saved cursor address plus that value to the cursor slot.
3. Return 0.

This path has no 512-byte upper-bound check. It does not read the skipped data, copy bytes, invoke F-fca51b715561, or explicitly write the result slot.

There is also no explicit lower-bound check on the converted second word. A negative value can decrease both count and cursor when the arithmetic is valid and the signed upper-bound comparison passes. That is established behavior, not an endorsement of negative lengths as valid input.

### 4. Nonnegative-first-word path: length check and copy

After the second conversion, the function first checks whether its returned value is greater than 512.

If so, it returns 1. Both headers have already been consumed and converted. The function has not copied data, called F-fca51b715561, or explicitly written the result slot.

Otherwise, it saves the current cursor address and checks whether the input limit is less than the current count plus the returned second conversion value.

If that check fails, it returns 4 before copying any bytes.

If it passes, the function performs a forward byte copy from the saved cursor address into the copy destination:

- The first copied byte uses offset zero.
- Each successive iteration uses the next integer offset.
- Each iteration reads a source byte and writes the corresponding destination byte.
- The loop condition rereads the second-word slot.
- The function appends no terminator and performs no padding.

For an unchanged, nonnegative second-word value, exactly that many bytes are copied. Zero copies no bytes. A negative second-word value also copies no bytes, because the initial loop offset is zero and the signed comparison fails.

The upper-bound check alone does not establish that the value lies between zero and 512.

### 5. Processing-dependency call

After the copy, the function computes a saved end address using the saved source address plus the then-current second-word-slot value. It then increases the count slot by the second-word-slot value.

Next, it invokes F-fca51b715561 with:

1. The processing context.
2. The copy-destination address.
3. The then-current second-word-slot value.

The count has therefore been advanced before this call. The cursor has not yet been explicitly updated to the saved end address.

The length used for copying, saved-end calculation, count advancement, and the dependency argument comes from separate reads of the second-word slot. They coincide under stable, non-overlapping storage, but the evidence does not justify treating them as one immutable captured value in every possible aliasing or mutation scenario.

### 6. Zero processing-dependency return

If F-fca51b715561 returns zero:

1. Write the saved end address to the cursor slot.
2. Write 1 to the result slot.
3. Return 0.

The function performs no additional accounting check and no additional count-slot write after this dependency return.

Consequently, any dependency mutation of the count slot remains effective. A dependency mutation of the cursor slot is overwritten by the saved end address.

### 7. Nonzero processing-dependency return

If F-fca51b715561 returns nonzero, the function reads the current first-word-slot value and adds it to the current count-slot value.

If the input limit is less than this sum, it returns 4 immediately.

At that failure point:

- The byte copy and dependency call have already occurred.
- The pre-call count advancement has already occurred.
- The function does not commit its saved end address to the cursor slot.
- The function does not explicitly write the result slot.
- Dependency changes are not rolled back.

If the check passes:

1. Write the checked sum to the count slot.
2. Write the saved end address plus the first-word value read after the dependency call to the cursor slot.
3. Write 0 to the result slot.
4. Return 0.

This extra cursor advance does not read or copy the additionally skipped bytes.

The first-word value used here is reread after the processing dependency. It need not equal the converted value that originally selected the nonnegative path.

## Side effects

### Partial progress is retained

The function is not transactional. Later errors retain earlier writes, copies, and dependency effects.

Under distinct slots and dependencies that do not mutate caller state:

| Exit | Cursor and count progress explicitly retained |
|---|---|
| 7 | None |
| 3 | First four-byte header word |
| 1 | Both four-byte header words |
| Initial data-region failure with status 4 | Both four-byte header words |
| Post-processing failure with status 4 | Count includes the copied-data length; cursor still identifies the data start |
| Successful negative-first-word path | Both headers plus the converted second-word advance |
| Successful nonnegative path, zero dependency return | Both headers plus the copied-data length |
| Successful nonnegative path, nonzero dependency return | Both headers plus the copied-data length and the post-call first-word advance |

These are conditional descriptions, not guarantees against dependency or aliasing effects.

### Result-slot writes

The function explicitly writes the result slot only after F-fca51b715561 returns and the selected completion path passes its checks.

It does not explicitly initialize that slot on entry, on the negative-first-word path, or on any early error.

“Not explicitly written” does not guarantee unchanged storage if the result slot aliases another written location or a dependency can access it.

### Aliasing and overlap

The supplied evidence establishes no non-aliasing guarantee.

Aliasing among slots, input storage, and destination storage can affect later reads. In particular:

- The copy loop rereads its length slot.
- Forward copying can overwrite bytes that later iterations will read when source and destination overlap.
- Writes to aliased state slots can change later accounting or addresses.
- The result-slot write occurs after the cursor-slot write and can overwrite it if they identify the same storage.

The copy must not be specified as overlap-safe. Detailed outcomes for arbitrary aliases are not established as a supported interface.

## Dependencies

### F-4e1ee8e86ebb

Called once for each header word that passes its four-byte availability check.

Inputs are the conversion context and the raw word held in the corresponding output slot. Its return replaces that slot’s contents.

Established uses of its returns:

- First return: signed path selection and initial first-word output.
- Second return: signed length-related checks and initial second-word output.

Its conversion algorithm, valid contexts, error conventions, global mutations, memory effects, and ownership behavior are unknown. A negative return is not independently treated as a conversion error by this function.

### F-fca51b715561

Called only on the nonnegative-first-word path after the upper-bound check, initial data-region check, byte copy, and count advancement.

Its inputs are the processing context, copy destination, and current second-word value.

The caller distinguishes only zero from nonzero:

- Zero selects result 1 without the extra first-word advance.
- Nonzero selects a checked extra advance and, if accepted, result 0.

Its effects on copied bytes, caller state, globals, ownership, and retained references are unknown. No preservation assumptions are justified.

## Acceptance examples

These examples assume distinct slots, valid memory, representable arithmetic, and dependencies that do not mutate caller state except through their stated returns. Let the entry count be **C** and the entry cursor be **P**.

1. **First header unavailable.**  
   If the input limit is less than C + 4, return 7. No header read, dependency call, or explicit output write occurs.

2. **Only the first header fits.**  
   If C + 4 is permitted but C + 8 is not, return 3 after the first conversion. Cursor is P + 4; count is C + 4. The second-word and result slots are not explicitly written.

3. **Negative first word, accepted skip.**  
   If the first converted word is −1, the second is 6, and C + 14 is permitted, return 0 with cursor P + 14 and count C + 14. Do not copy data or call F-fca51b715561. Leave the result slot explicitly untouched.

4. **Upper-bound rejection.**  
   If the first converted word is nonnegative and the second is 513, return 1 after both conversions. Cursor is P + 8 and count is C + 8. This rejection precedes the data-region accounting check.

5. **Boundary length accepted.**  
   A second word of 512 is not rejected by the upper-bound check. If accounting permits it, copy 512 bytes and call F-fca51b715561 with length 512.

6. **Zero processing return.**  
   With first word 10, second word 3, and sufficient input accounting, copy three bytes. If F-fca51b715561 returns zero, return 0, write result 1, and finish at cursor P + 11 and count C + 11. Do not advance by 10.

7. **Nonzero processing return.**  
   With the same words, if the dependency returns nonzero and C + 21 is permitted, return 0, write result 0, and finish at cursor P + 21 and count C + 21.

8. **Failure after processing.**  
   If C + 11 is permitted but C + 21 is not in the preceding example, return 4 after copying and calling the dependency. Count is C + 11; cursor remains P + 8; the result slot is not explicitly written.

9. **Negative second word.**  
   With a nonnegative first word and second word −2, the 512 check passes and no bytes are copied. If the arithmetic and accounting check permit continuation, count decreases by two before the processing call, whose length argument is −2. Whether that dependency accepts such an argument is unknown.

Equality with an accounting boundary passes: the checks reject only when the input limit is strictly less than the computed sum.
