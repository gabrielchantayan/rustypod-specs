# F-b8a0e35a1400

## Purpose

F-b8a0e35a1400 initializes a four-word record associated with a context and, when suitable dependent objects are available, applies a selected record to an object through indirect operations.

The established behavior has two parts:

1. Obtain and initialize a record using the context’s current pair of key words.
2. Attempt to find an applicable object, copy a selected record into that object, and invoke operations using a selection value that may be derived from a bounded search.

Descriptions such as “key,” “record,” and “selection” are behavioral labels, not established domain meanings. The supplied evidence does not establish whether the records represent persistent settings, navigation state, or another application concept.

## Behavior

### 1. Obtain and initialize the entry record

The function reads the context’s words at +0x20 and +0x24 and calls F-f7490d12dfa0 with:

- The context.
- Those two key words.
- A final argument of one.

The returned address is used without a null check. The function performs four 32-bit writes in this order:

1. Zero at record offset +0x04.
2. Zero at record offset +0x00.
3. The payload at record offset +0x08.
4. All bits set at record offset +0x0C.

Consequently, successful writable storage from this first dependency call is a precondition for ordinary execution. No controlled error path is shown for a null or otherwise invalid result.

The key-field reads used for the call precede the call. Their relative evaluation order is not established by the supplied representation.

### 2. Capture keys and obtain an initial lookup value

After the four record writes, the function reads the context’s +0x20 word again, then its +0x24 word. These later values are retained for subsequent record lookups.

This rereading matters if the initial dependency or record writes affect the context through aliasing. The later keys need not equal those supplied to the first call.

The function then invokes D-01, an indirect dependency selected through the context’s +0x34 reference and dispatch-table offset +0xE4. No explicit arguments are recoverable for this invocation.

If either of the following is true, the function returns normally:

- D-01 returned zero.
- The retained first key is zero.

D-01 is invoked even when the retained first key is zero. Both retained keys are captured before D-01 runs; later changes to the context fields do not automatically change these retained lookup arguments.

### 3. Resolve the target object

When neither early-return condition applies, the function calls F-682adfd5a561 with:

- The nonzero result from D-01.
- Discriminator 0x1700.

If this call returns zero, the function returns normally. The entry-record initialization has already occurred.

No explicit release or compensating operation accompanies either normal early return.

### 4. Obtain the selected record

With a nonzero target object, the function calls F-f7490d12dfa0 using:

- The context.
- The retained first key.
- The retained second key.
- A final argument of zero.

If this returns zero, the function retries once using the same context and first key, but a second key of zero and a final argument of zero.

If both calls return zero, the function invokes F-a817d8d58c10. The supplied representation marks this dependency as non-returning. There is no established recovery behavior if it returns unexpectedly.

A zero retained second key does not suppress the fallback. If the first lookup fails with that key already zero, the same argument tuple is issued again.

### 5. Copy selected-record values into the target object

For a successful selected record, the function reads its words at +0x04, +0x08, and +0x0C, in that order. It then reads the word at +0x00 and writes that value to target offset +0x108.

The previously read values are subsequently written to target offsets +0x10C, +0x110, and +0x114, respectively.

This is not an atomic record transfer. In particular:

- The source words are not all read in ascending address order.
- Three source words are captured before any destination write.
- The first source word is read when preparing the first destination write.
- No synchronization or alias exclusion is shown.

The function then makes two indirect calls, in order:

1. D-02, selected from the target’s dispatch table at +0x15C, with the target as an explicit argument.
2. D-03, selected at dispatch offset +0x1A0, with the target and a fresh read of the selected record’s primary value.

The primary value passed to D-03 is not necessarily the value previously copied to target +0x108. D-02 may have changed the selected record or other reachable state.

Each dispatch uses the target’s dispatch structure as accessed for that call; a single immutable dispatch table is not established.

### 6. Establish the selection and optionally search

After D-03 returns, the function reads the selected record’s base selection at +0x08. This becomes the selection unless the optional search produces a replacement.

The function next reads the selected record’s match value at +0x04. If it is zero, the search is skipped entirely.

For a nonzero match value:

1. Read the target word at +0x38.
2. Call F-682adfd5a561 with that word and discriminator six.
3. Read two global 32-bit words, first the word used as the third explicit argument to F-9dfe5f6048f1, then the word used as its second explicit argument.
4. If the lookup result is zero, invoke F-a817d8d58c10.

The global reads occur after the lookup call and before its zero-result check. The lookup dependency is not assumed to preserve the globals.

For a nonzero lookup result, the function starts a search using the signed 32-bit value at target +0x100. Before each iteration, it compares the current signed index against a fresh read of the signed exclusive bound at target +0x104.

For each index strictly below that bound, it calls F-9dfe5f6048f1 with:

- The nonzero lookup result.
- The two captured global words, in their established argument positions.
- The current index.
- Five additional 32-bit argument values whose origins are not established.

After each resolver call, the function rereads the selected record’s match value and compares it with the resolver’s 32-bit result.

If they are equal:

- The selection becomes the current index.
- The selected record’s relative adjustment is read as a signed 32-bit value.
- If the adjustment is nonnegative, the selection becomes the index plus a fresh read of that adjustment.
- The search stops at this first match.

If they are unequal, the index is incremented by one and the bound is checked again.

The match value is not frozen at search entry. A dependency may change it, including changing it to zero, and equality is tested against the current value after each resolver call. Conversely, the two global argument words are captured once and are not refreshed between iterations.

If the initial index is not less than the bound, or no iteration matches, the previously captured base selection is retained.

### 7. Apply the selection through two final calls

The function invokes:

1. D-04, at target dispatch offset +0x190, with the target, selection, and a final argument of one.
2. D-05, at target dispatch offset +0x174, with the target and the same selection.

The selection is not recomputed between these calls. D-04 may change memory or dispatch state, but the selection argument passed to D-05 remains the retained value.

A normal return follows D-05 if it returns.

- Four words in the entry record.
- Four words at target offsets +0x108 through +0x114.

Additional side effects may occur inside every dependency, including the indirect dependencies. Their memory writes, allocation behavior, global-state changes, and ownership effects are not established here.

There is no explicit allocation, deallocation, reference-count adjustment, or ownership transfer performed directly by F-b8a0e35a1400. A returned address is used as accessible storage or an object reference; that use alone does not establish ownership.

No rollback is shown. Entry-record initialization remains performed on ordinary early-return paths. Likewise, target-copy writes precede any later search-related failure.

No concurrency guarantees, locking, atomic snapshot, or reentrancy protection are shown. The documented read order must not be interpreted as a coherent snapshot under concurrent mutation.

## Acceptance examples

These are conditional behavioral examples derived from static evidence, not executed tests.

1. **Zero first key after initialization.**  
   Given valid entry-record storage and a retained first key of zero, the four initialization writes and D-01 must still occur. No discriminator-0x1700 lookup follows, regardless of D-01’s result.

2. **Unavailable target object.**  
   Given nonzero gating values but a zero result from the discriminator-0x1700 lookup, the function returns after entry-record initialization. It does not perform the selected-record lookup or final target calls.

3. **Fallback record succeeds.**  
   Given a failed selected-record lookup using the retained second key and a successful lookup using zero instead, the successful fallback record supplies the copied values and subsequent selection behavior.

4. **Repeated zero-key lookup.**  
   Given a retained second key of zero and failure of the first selected-record lookup, a second call with the same arguments still occurs. Failure of both leads to F-a817d8d58c10.

5. **Search disabled by current record state.**  
   Given that D-03 returns with base selection 27 and match value zero, D-04 receives selection 27 and final argument one. D-05 subsequently receives selection 27. No discriminator-six lookup occurs.

6. **First match with negative adjustment.**  
   Given an active search over indices 4 through 7, with the first equality at index 6 and a relative adjustment of −1, the selected value is 6. No resolver call for index 7 follows.

7. **First match with nonnegative adjustment.**  
   Given first equality at index 6, a stable relative adjustment of 3, and representable arithmetic, both final selection calls receive 9.

8. **Empty signed interval.**  
   Given active search, successful discriminator-six lookup, initial index 8, and exclusive bound 8, there are no resolver calls. The captured base selection is retained.

9. **Dependency mutation affects comparison.**  
   Given a resolver call that changes the selected record’s match value before returning, equality is evaluated against that changed value, not necessarily the nonzero value that enabled the search.

10. **Search lookup fails.**  
    Given an active search and zero result from the discriminator-six lookup, both global reads occur before F-a817d8d58c10 is invoked. The final selection calls are not reached under the represented non-returning behavior.
