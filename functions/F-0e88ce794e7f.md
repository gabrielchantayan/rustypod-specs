## Behavior

### Condition interpretation

The represented control flow uses a repeated selection condition:

Its alternative holds only when Z is clear and N equals V.

These conditions describe the supplied representation. They do not prove that an actual processor would evaluate every operation against unchanged entry flags after intervening interrupts.

### Ordered event sequence

Subject to continued execution, events occur in the following order.

1. **Initial interrupt pair.**  
   When the selected condition holds, two consecutive software-interrupt events carry selector **0x1DDF1D**. Otherwise, neither event is present.

2. **Zero-clear interrupt.**  
   When Z is clear, one software-interrupt event carries selector **0x1EDF1D**. When Z is asserted, this event is absent.

3. **Selected block or alternative transfer.**
   - When the selected condition holds:
     - Seven consecutive software-interrupt events carry selector **0x1CDF1C**.
     - One coprocessor transfer-like operation follows, with fixed numeric operands **0xF, 7, 0**, followed by two occurrences of incoming value C.
     - One software-interrupt event carries selector **0x1CDEFC**.
     - One software-interrupt event carries selector **0x1DCEBB**.
     - Ten consecutive software-interrupt events carry selector **0x1DDF1D**.
   - Otherwise:
     - One alternative coprocessor transfer-like operation occurs, with fixed numeric operands **0xF, 5, 0**, followed by incoming values B and D, respectively.
     - None of the interrupt events belonging to the selected block occurs.

4. **Conditional address-bearing operation.**  
   When N equals V, one coprocessor load-like operation occurs with fixed numeric operand **5**, incoming value A, and an address expression equal to the incoming base value plus **0x25C**. When N differs from V, this operation is absent.

5. **Final interrupt group.**  
   When the selected condition holds, four consecutive software-interrupt events carry selector **0x1CDF1C**. Otherwise, this group is absent.

6. **Invalid-instruction boundary.**  
   All represented paths reach an explicit invalid-instruction termination marker if preceding operations permit continuation. No ordinary return is shown.

Repeated interrupt events are distinct events. Their multiplicities and ordering are part of the represented behavior; they must not be collapsed into a single event per selector.
