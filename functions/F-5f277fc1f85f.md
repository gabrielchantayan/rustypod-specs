# F-5f277fc1f85f

## Purpose

It obtains an initial count, conditionally adjusts the horizontal position and byte range, invokes a principal dependency, stores a context-relative horizontal result, and invokes a final dependency.

## Behavior

### Entry capture and initial selection

Before the initial dependency call, the function reads the context word at offset 40 and retains its low eight bits. Subsequent calls use that captured byte rather than rereading offset 40.

The function calls **F-d4f370b64986** with these arguments:

1. The resource-like value at context offset 28.
2. The original byte pointer.
3. The original requested count.
4. The context address at offset 32.
5. The captured byte.
6. The available width.
7. The address of a local signed 32-bit width slot.
8. Zero.

The return is retained as an unsigned 32-bit selected count.

Passing the width slot’s address permits a dependency write; it is **not** a direct write by F-5f277fc1f85f and does not prove that the dependency initializes the slot. No initialization of that slot is shown before this call.

The function does not validate the returned count against the requested count. It does not check whether a width was supplied or recognize a failure indication.

### Selector 1: half-gap adjustment

For selector 1, the function uses the width slot to calculate the available width minus the measured width, then adds one, then applies a signed right shift by one. It adds that result to the current horizontal position and writes the sum to context offset 0.

For a nonnegative gap with representable intermediate arithmetic, the adjustment is half the gap rounded upward. Behavior for negative shifted values depends on the target’s signed-right-shift rules.

This path consumes the width slot supplied to the initial dependency. Meaningful behavior requires that the slot have been initialized before this read.

The byte pointer and selected count remain unchanged.

### Selector 2: equal counts

When selector 2 is used and the selected count equals the requested count, the function adds the full difference between available width and the width slot to the current horizontal position. It writes the result to context offset 0.

This path also requires the initial width slot to have been initialized meaningfully. It does not call the replacement-width or per-byte dependencies. The byte pointer and count remain unchanged.

### Selector 2: unequal counts

Any inequality between selected and requested counts enters this branch. It is not restricted to a selected count smaller than the requested count.

First, the function calls **F-b193d9cb24df** with:

1. The then-current resource value at offset 28.
2. The original byte pointer.
3. The initial selected count.
4. The context address at offset 32.
5. The captured byte.
6. Zero.

The function **directly assigns** this dependency’s signed 32-bit return to the local width slot. This explicit assignment replaces any earlier contents and does not depend on F-d4f370b64986 having initialized the slot.

Using that replacement width, the function forms a candidate horizontal position equal to the current horizontal position plus available width minus replacement width.

It then considers removing leading bytes. Each loop condition first compares the candidate with the current horizontal position at context offset 0. If the candidate is strictly smaller, it also checks that the remaining requested count is nonzero.

For each iteration that passes both checks:

- One byte is read at the current byte pointer.
- **F-122d0efb9091** is called with the current resource value, that byte, the context address at offset 32, and the captured byte.
- Its signed 32-bit return is added to the candidate position.
- The byte pointer advances by exactly one byte.
- The remaining requested count decreases by one.

The horizontal-position threshold is reread for each comparison. It is not a saved entry value. Dependency mutations can therefore change whether another iteration occurs.

There is no requirement that a per-byte return be positive. Zero or negative returns do not themselves stop removal. The nonzero remaining-count check bounds the number of iterations by the original requested count, assuming calls return and accesses remain valid.

After the loop, the function writes the candidate to context offset 0. It replaces the selected count with the remaining requested count. Consequently, the final count is the original requested count minus the number of bytes removed, **not** the initial selected count minus that number.

No direct horizontal-position write occurs inside the loop body. Byte removal is byte-based; no local operation identifies character boundaries or validates an encoding.

### Other selectors

The function still invokes all common downstream dependencies. Bypassing its own alignment write does not guarantee that context state is unchanged by those dependencies.

### Relative-position write and final call

After the principal dependency returns, the function reads context offset 44 again. It subtracts this freshly read horizontal offset from the returned coordinate and writes the result to context offset 0.

This read is distinct from the offset read used to form the principal operation’s horizontal argument. A mutation during the principal call can make the two offset values differ.

Finally, **F-967c9cbe906b** receives:

1. The context pointer.
2. The current byte pointer.
3. The current selected count masked to its low 16 bits.

Only this final call receives the count reduced modulo 65,536. The principal operation receives the full 32-bit count.

There is no subsequent direct context write. The final dependency receives the context itself, so the preceding horizontal-position write is not guaranteed to remain the exit value.

## Side effects

### Direct writes and local state

The function directly writes context offset 0:

- Once during selector-1 or selector-2 alignment processing.
- Once after the principal dependency returns, on every normally completing path.

In selector 2’s unequal-count branch, the alignment write occurs after the removal loop, not during individual iterations.

The local width slot has two distinct possible sources:

- **Possible indirect write:** F-d4f370b64986 receives its address. Whether that dependency writes the slot is unknown.
- **Established direct assignment:** In selector 2’s unequal-count branch, F-5f277fc1f85f assigns the return from F-b193d9cb24df to the slot.

The function also updates its local candidate, count, pointer, and retained results. Advancing the local byte pointer does not directly update a caller-owned pointer variable. The adjusted pointer is observable through subsequent dependency arguments.

### Indirect effects and ownership

No allocation, release, byte-buffer write, or ownership transfer is directly shown. That absence does not establish that dependencies allocate nothing, release nothing, retain no pointers, or preserve byte storage.

The width slot is local storage, not a returned object. Whether a dependency retains its address is unknown; safe post-invocation retention cannot be inferred. Buffer ownership and resource lifetime are likewise unresolved.

### Errors and arithmetic

There is no explicit error result, validation branch, rollback, or local failure-status discrimination. Dependency returns are used directly as counts, widths, advances, adjustments, or coordinates.

Position and width calculations use signed 32-bit values. No checked or saturating arithmetic is shown. The supplied representation does not establish a portable overflow policy; defined numerical examples require all intermediate signed results to be representable.

## Acceptance examples

These are conditional consequences of the static behavior, not runtime observations. Unless stated otherwise, assume valid storage, returning dependencies, representable arithmetic, initialized width storage when read, and no relevant dependency mutations.

1. **Selector 1 with an odd positive gap.**  
   Horizontal position 100, available width 11, and initial width 6 produce an alignment write of 103. With horizontal offset 7, the principal operation receives horizontal coordinate 110.

2. **Selector 2 with equal counts.**  
   Requested and selected counts of 4, horizontal position 100, available width 20, and initial width 12 produce an alignment write of 108. Neither replacement measurement nor per-byte removal is called.

3. **Unequal counts with two removed bytes.**  
   Requested count 5, selected count 3, horizontal position 100, available width 10, and replacement width 16 produce candidate 94. Advances of 4 and 3 move it to 98 and then 101. Two bytes are removed; the principal operation receives the original pointer plus two bytes and count 3.

4. **Unequal counts without removal.**  
   Requested count 5, selected count 3, available width 10, and replacement width 8 produce a candidate two units beyond the unchanged horizontal threshold. No byte is removed. The principal operation receives count 5, not 3.

5. **No initial width write in the unequal-count branch.**  
   If the initial dependency leaves the width slot untouched, selector 2 with unequal counts still explicitly assigns the replacement dependency’s return before using the slot. By contrast, selector 1 and selector 2 with equal counts read the slot without that replacement assignment; a missing initial write leaves their width behavior unresolved.

6. **Unrecognized selector without an initial width write.**  
   Selector 3 does not locally read the width slot. It bypasses alignment adjustment and proceeds to the vertical-adjustment, principal, and final calls.

7. **Nonpositive advances.**  
   If the candidate stays below the current threshold, zero or negative advances do not stop removal. The loop can consume the entire requested count.

8. **Dependency-modified threshold.**  
   If a per-byte dependency changes context offset 0, the next comparison uses that changed value. It need not behave like a comparison against the original position.

9. **Final count truncation.**  
   A current selected count of 65,537 is passed as 65,537 to the principal operation and as 1 to the final dependency.

10. **Changed horizontal offset.**  
    If the principal operation returns 250 and changes offset 44 to 20, the following direct horizontal-position write is 230, regardless of the offset used for the earlier coordinate argument.

11. **Zero requested count.**  
    The initial dependency still runs. If selector 2 takes the unequal-count branch, replacement measurement still runs, but the loop performs no direct byte read. The remaining count becomes the selected count, namely zero.
