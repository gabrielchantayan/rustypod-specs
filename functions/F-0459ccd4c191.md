# F-0459ccd4c191

## Purpose

F-0459ccd4c191 retrieves a four-byte value from the beginning of a selected 12-byte slot in indirectly addressed storage. Before accessing that storage, it obtains an unsigned 32-bit value from F-32a0cd51a77a and compares it with the requested slot index. If the index is greater than or equal to that value, it invokes F-a817d8d58c10, which is annotated as not returning normally.

The inferred intent is a bounds-checked lookup. The established behavior is narrower: the comparison value comes from a dependency that receives no explicit arguments. The supplied evidence does not establish that this value is the length of the particular storage addressed by the first argument.

This contract describes the visible operation and its dependency boundaries. It does not establish the validity of the storage, the meaning of the returned four bytes, or the behavior inside either dependency.

## Interface

**Explicit inputs**

- **Storage descriptor address:** an address identifying a readable 32-bit cell. That cell supplies the base-address bits used for the eventual slot access. It is not itself the slot-storage base.
- **Slot index:** an unsigned 32-bit integer, ranging from 0 through 4,294,967,295.

**Output**

On an ordinary return, the result is the four-byte value loaded at the computed slot address. The result has no established semantic type beyond its 32-bit width. In particular, the evidence does not establish that it is an integer, pointer, handle, or owned resource.

**Relevant storage layout**

The visible access uses two levels of addressing:

1. Read the 32-bit base value from the storage descriptor.
2. Read four bytes beginning at the base plus 12 times the slot index.

The slot stride is 12 bytes. Only the first four bytes of the selected slot are explicitly read. No fields, padding, or meanings are established for the remaining eight bytes.

The descriptor layout is limited to the single 32-bit cell used by this operation. There is no visible length field read from it and no visible access to another descriptor field.

**Preconditions for the normal retrieval path**

- F-32a0cd51a77a must return normally.
- The comparison must admit the index, or F-a817d8d58c10 must unexpectedly return despite its non-return annotation.
- The descriptor cell must be readable when it is accessed.
- The computed slot address must support the four-byte read under the execution environment’s memory-access rules.

The visible operation does not establish these storage preconditions itself. Requirements for alignment, mapping, object lifetime, and concurrent access remain environment-dependent.

## Behavior

### Dependency call and range decision

The first visible action is a call to F-32a0cd51a77a with no explicit arguments. Its returned value is treated as unsigned and 32 bits wide.

The function then compares that value with the unsigned 32-bit slot index:

- If the index is strictly less than the dependency result, execution proceeds toward the storage read without calling F-a817d8d58c10.
- If the index equals or exceeds the dependency result, F-a817d8d58c10 is called with no explicit arguments.

Equality therefore takes the failure-designated path. A comparison result of zero admits no index.

F-a817d8d58c10 is annotated as non-returning. Under that annotation, invoking it prevents this function from reaching its ordinary return or performing its later explicit storage reads. The annotation does not identify how control fails to return: termination, an exception, a nonlocal transfer, or another mechanism is not specified.

The visible control flow contains no separate rejection return value. If F-a817d8d58c10 did return normally contrary to its annotation, the remaining storage access would still follow. Such a return must not be treated as a successful validation guarantee.

### Descriptor read and slot read

On the path that reaches retrieval, the function first reads the descriptor’s 32-bit base value. It then forms the slot address using the index and a 12-byte stride, reads four bytes at that address, and returns those bytes as the result.

The comparison dependency executes before the function’s explicit descriptor read. Consequently, this operation does not snapshot the descriptor before calling the dependency. If F-32a0cd51a77a changes the descriptor cell and returns normally, the later read observes the descriptor as it exists at that later access, subject to the execution environment.

The same caution applies if F-a817d8d58c10 unexpectedly returns after modifying relevant state. No dependency is assumed to preserve globals, descriptor contents, mappings, or storage lifetime.

There is no visible iteration, retry, read of the rest of the slot, or post-read validation.

### Width and address arithmetic

The comparison is unsigned 32-bit comparison. A value whose high bit is set remains a large nonnegative index for this decision; it is not interpreted as a negative index.

The stride calculation also uses 32-bit unsigned arithmetic. Multiplying the index by 12 retains the low 32 bits. Combining this offset with the 32-bit base likewise yields a 32-bit address representation. No wider intermediate address calculation or arithmetic-overflow rejection is visible.

This matters independently of the range comparison. Even an admitted index can produce a wrapped offset or wrapped final address. For example, index 357,913,942 produces a mathematical byte offset of 4,294,967,304, whose low 32 bits are 8. The visible arithmetic therefore selects an offset of 8, not a non-wrapping offset beyond the 32-bit address range.

That arithmetic fact does not establish that the resulting address is readable. A successful comparison alone is insufficient to prove a valid storage access.

### Invalid memory and interrupted execution

No explicit descriptor-null check, base-null check, memory-protection check, or alignment check appears in the visible operation. An admitted index can therefore lead to an invalid descriptor read or an invalid slot read.

The function does not visibly translate such failures into a defined status value. Any fault, trap, exception, or other response depends on the execution environment.

If either dependency does not return normally, later actions are not reached through this function’s ordinary sequential path.

## Side effects

- One 32-bit descriptor-cell read after the comparison path reaches retrieval.
- One four-byte slot read after obtaining the base value.

There is no explicit write to the descriptor, slot storage, or another memory location. This is not a whole-call purity guarantee: both dependencies can have side effects whose scope is unknown.

For a call where both dependencies return normally when invoked, the visible ordering is:

1. Call F-32a0cd51a77a.
2. Decide whether to call F-a817d8d58c10.
3. Complete that second call if it was invoked and returns.
4. Read the descriptor cell.
5. Read the selected four-byte value.
6. Return that value.

These are the function’s explicit accesses. A dependency may independently access the same memory before them.

No allocation, deallocation, reference-count operation, or ownership transfer is explicit in this function. The returned bytes must not be interpreted as transferring ownership. Whether a dependency allocates, releases, retains, or invalidates memory is unknown.

No synchronization is visible. Atomicity, consistency across concurrent changes, and behavior for special memory such as memory-mapped devices are not established.

### Equal-to-bound index

### Wrapped offset

### Failure-designated dependency unexpectedly returns
