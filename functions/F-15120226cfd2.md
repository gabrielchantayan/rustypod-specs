# F-15120226cfd2

## Purpose

F-15120226cfd2 invokes two dependencies in a fixed order using addresses derived from a caller-supplied base address. After both dependencies return, it reads a pointer-valued field and, when that pointer is non-null, reads a 32-bit integer through it. A non-null pointer combined with a nonzero integer selects an indirect control transfer.

On the selected branch, a separately addressed global slot supplies the indirect target. The source-level read of that slot occurs after both dependency invocations, the pointer-field read, and the pointed-to integer read. An entry-time snapshot of the target slot is not equivalent: neither dependency is known to preserve that slot.

This is an established description of the supplied static representation, not an application-level interpretation. Initialization, destruction, notification, and similar purposes remain unestablished.

The function accepts one explicit input: an integer-represented base address, called **B** in this contract.

The supplied representation supports a 32-bit interpretation of the address-bearing values and integer accesses. ## Behavior

### Ordered dependency invocations

The first visible dependency invocation is **F-338d16f9ce72**, with B + 80 as its explicit argument. No pointer-field read by F-15120226cfd2 precedes this invocation.

If that dependency returns normally, the function invokes **F-b8a325ddd21b**, with B + 100 as its explicit argument. No visible branch between these invocations depends on the field at B + 80.

Consequently, an entry-time null field does not suppress either invocation. Neither dependency’s result is explicitly used. Their state changes, memory accesses, and failure behavior are unknown.

If the first invocation does not return normally, the second invocation and subsequent operations are not reached through the visible normal path. If the second does not return normally, the subsequent field read is not reached through that path.

### Post-dependency pointer read

After both invocations return, the function reads the pointer-valued field at B + 80.

This obtained pointer, rather than an entry-time value, controls the remaining object-dependent behavior. Either dependency may have installed, cleared, or replaced the field. Their effects are not confined to their explicit argument locations by any available contract.

The visible representation retains the obtained pointer for its null tests and possible dereference. It does not show a second read of the field after the integer access.

### Conditional integer read

If the obtained pointer is null, the function does not dereference it. The indirect transfer is not selected.

If the pointer is non-null, the function reads one 32-bit integer at that address. No further field traversal or sequence scan is visible.

The integer is tested only for zero versus nonzero. A zero value suppresses the indirect transfer. Every nonzero 32-bit value satisfies the integer portion of the condition, including values interpreted as negative. Positivity and equality to one are not requirements.

A non-null pointer does not by itself establish validity. The function performs no visible alignment, lifetime, range, or accessibility check before the integer read.

### Conditional global-target read and transfer

The indirect branch is selected only when both conditions hold:

- The obtained pointer is non-null.
- The integer read through that pointer is nonzero.

Only on this selected branch does F-15120226cfd2 read the separately addressed global target slot to obtain the transfer destination. At the source level, the relevant order is:

1. Completion of F-338d16f9ce72.
2. Completion of F-b8a325ddd21b.
3. Read of the pointer field at B + 80.
4. Read of the pointed-to integer.
5. Read of the global target slot.
6. Indirect transfer using the target supplied by that slot.

For the null-pointer path, the fourth through sixth operations are absent. For the non-null pointer with a zero integer, the integer read occurs but the target-slot read and transfer do not.

This ordering is part of the source-facing contract. A target captured before either dependency would not preserve it when a dependency changes the slot. Likewise, the function does not visibly obtain the destination directly from the pointer field or the decision integer.

Separate addressing does not imply disjoint storage. If relevant locations alias, that overlap is not excluded by the available evidence. The accesses must still be understood in their established source-level order rather than as reads of necessarily independent objects.

No explicit arguments are shown for the indirect invocation. This does not establish a zero-argument machine interface: implicit context, register contents, stack state, and the recovered signature remain unresolved.

The source shows no null check or other validation of the target obtained from the global slot. If the selected target is invalid, no local recovery is established.

When the condition is false, the function returns without the target-slot read or transfer. When the condition is true, no further object access or cleanup by this function is visible after the transfer. Whether the target returns or instead terminates or redirects execution is unknown.
