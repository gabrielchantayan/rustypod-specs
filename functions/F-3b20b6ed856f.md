# F-3b20b6ed856f

## Purpose

F-3b20b6ed856f performs a bounded, dependency-controlled search using a signed remainder. It resets two object fields before searching. If a subtraction makes the remainder negative, it computes a 32-bit result, stores that result, and invokes a downstream operation. Otherwise, exhaustion of the dependency-supplied traversal limit produces a zero return.

The two completion modes have different effects:

- **Limit completion:** returns zero without directly accessing the result field or invoking the result-production and publication dependencies.
- **Result completion:** stores a computed value, invokes publication, and returns the result field as it exists after publication.

The search resembles selection within a sequence of spans, but that is **inferred intent**. The available evidence establishes arithmetic, memory accesses, and dependency interactions—not the application meaning of the values.

This contract describes normal execution within the established signed arithmetic range. Dependency internals and exceptional behavior remain unresolved.

## Behavior

### Search state and selection rule

The search begins with ordinal zero and the supplied initial remainder. Each candidate is eligible only if the signed 32-bit value returned by F-94897b9fa187 is strictly greater than the current ordinal. That dependency receives the address at `0x24`.

An ineligible candidate ends the operation immediately with a zero return. Consequently, a first limit value of zero or any negative value prevents all subtraction and result-production activity.

For an eligible candidate, F-109c9c9c928d receives the same address and supplies a signed 32-bit subtraction amount. Selection depends on the remainder **after** subtracting that amount:

- A negative remainder selects the current ordinal for result production.
- A zero or positive remainder advances the ordinal and requires a new eligibility decision.

The limit is therefore dynamic, not a count captured once at entry. Every advance is followed by another call to F-94897b9fa187. Changes made by earlier dependencies can affect later eligibility.

An exact subtraction boundary is not selected. Reaching zero continues the search. An initially negative input does not bypass eligibility or subtraction; only the post-subtraction sign controls selection.

The subtraction amount is not validated as positive. Zero can leave the remainder unchanged. A negative amount can increase it. These cases still use the same post-subtraction decision, provided the signed arithmetic remains within range.

### Result value

On selection, the selected ordinal is supplied, together with the address at `0x24`, to F-ec0422790b62 and then F-e541a293a856.

The computed result is the sum of:

- The value returned by F-ec0422790b62.
- The selected negative remainder.
- The value returned by F-e541a293a856.

The first return value and the remainder are combined before the second return value is added. Both intermediate addition and final addition matter when assessing signed-range validity; a representable final mathematical sum does not by itself establish that the represented evaluation stays in range.

The selected ordinal is not advanced before these calls. Both dependencies receive that same ordinal. The first dependency’s return value remains available across the second call; no preservation of object fields or globals by either dependency is assumed.

The computed four-byte value is stored at `0x50`. There is no visible rejection of either dependency’s returned value and no special handling of an apparent error code.

### Publication and returned state

After the result store, F-5abdb0329a40 receives the address at `0x54` and returns a 64-bit value. Its two 32-bit halves have distinct uses:

- The low half supplies an address from which one four-byte value is read.
- The high half supplies a separate 32-bit argument.

F-3475b4980949 receives five arguments, in order:

1. The four-byte value obtained by dereferencing the low-half address.
2. The high-half value.
3. The computed result retained from the arithmetic.
4. Zero.
5. Zero.

The first argument is the dereferenced value, not the address itself. The third argument is the retained computed result, not a fresh read of the result field.

After F-3475b4980949 returns, the function rereads `0x50` and returns those four bytes. Its return can therefore differ from both the initial result store and the third publication argument. The publication dependency’s own return value is unused.

### Integer boundaries and traversal bound

The limit comparison and remainder sign test are signed 32-bit operations. No wrapping, saturation, trapping, or other overflow outcome is established for remainder subtraction or result addition.

The ordinal increment is different: under the established signed comparison, it cannot overflow during normal execution. An eligible ordinal must be smaller than a signed 32-bit limit, whose maximum is 2,147,483,647. Thus an increment can raise the ordinal at most to that maximum. At that ordinal, every possible signed 32-bit limit causes immediate limit completion.

Accordingly, assuming dependencies return normally and the other arithmetic remains valid:

- At most 2,147,483,647 subtraction calls can occur.
- At most 2,147,483,648 limit calls can occur.
- There is no unbounded traversal caused solely by unchanged remainders or changing limits.

These bounds do not guarantee completion if a dependency fails to return or execution encounters behavior outside the established arithmetic or memory conditions.

## Side effects

### Direct memory effects

The first direct object write resets `0x24`; the second resets `0x28`. Both occur before any dependency call. The result field is not initialized as part of these resets.

Limit completion performs no direct read or write at `0x50`. This does not guarantee that dependencies leave it unchanged.

On result completion, the observable ordering constraints are:

- All traversal calls precede the two result-production calls.
- F-ec0422790b62 precedes F-e541a293a856.
- Both result-production calls precede the result store.
- The result store precedes F-5abdb0329a40.
- That dependency’s return precedes the four-byte indirect read used for publication.
- Publication precedes the final result-field read.

No direct write through the publication address is established.

### Aliasing and dependency mutations

No non-aliasing guarantee is available. The address encoded in the low half of the publication data may identify object-related storage, shared storage, or other storage satisfying the dependency’s requirements.

The indirect publication read observes memory after F-5abdb0329a40 has returned. The final result-field read observes memory after F-3475b4980949 has returned.

Neither dependency is assumed to preserve the object or globals. In particular, changing `0x50` during either call can alter the final return, but does not alter the retained computed value supplied as the third publication argument.

### Ownership and errors

No direct allocation, deallocation, reference-count operation, or ownership transfer is established. Overwriting the entry fields does not itself release any resource they may previously have represented.

Ownership behavior inside dependencies is **documented_only**. Receiving an address or a four-byte argument does not establish borrowing, retention, transfer, or release.

There is no explicit error channel, rollback, or cleanup path. If execution stops abnormally after an entry reset or result store, restoration of earlier state is not established.

## Acceptance examples

These examples are conditional static consequences, not executed tests. Unless a mutation is stated, assume valid memory, normal dependency returns, no interfering mutations, and signed arithmetic within range.

### Immediate limit completion

If the first limit is zero or negative, the function returns zero after resetting the two entry fields. No subtraction, result-production, or publication dependency is called. The function itself leaves `0x50` untouched.

### First-candidate selection

With initial remainder 3, first limit 1, and subtraction amount 5, the selected remainder is −2 and the selected ordinal is zero.

If the two result contributions are 100 and 20, the computed value is 118. The function stores 118, supplies 118 as the third publication argument, and returns 118 if dependencies leave the result field unchanged.

### Exact boundary and refreshed limit

With initial remainder 5, first limit 1, and subtraction amount 5, the remainder becomes zero and the ordinal advances to one.

If the next limit is 1, limit completion returns zero. No result is produced for the exact boundary. The second limit call is required even though the earlier limit was also 1.

### Initially negative input still requires subtraction

With initial remainder −3, a first limit of zero ends the operation without subtraction.

With a permissive first limit and subtraction amount −5, the updated remainder is 2. That candidate is not selected despite the initially negative input.

### Publication address is dereferenced

If the low half returned by F-5abdb0329a40 identifies four readable bytes containing 7, and the high half is 9, the first two publication arguments are 7 and 9.

### Mutation separates publication from return

Suppose the computed value is 118. If F-5abdb0329a40 changes `0x50` to 41, publication still receives 118 as its third argument.

If F-3475b4980949 subsequently changes `0x50` to 42, the function returns 42.

### Zero subtraction cannot defeat the ordinal bound

Even if every subtraction amount is zero and every limit is the largest signed 32-bit value, the search cannot advance beyond ordinal 2,147,483,647. At that ordinal, the limit comparison ends traversal without another subtraction.
