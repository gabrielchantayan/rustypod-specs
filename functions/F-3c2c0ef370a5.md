# F-3c2c0ef370a5

## Purpose

F-3c2c0ef370a5 performs a position-dependent operation on a collection-like object and writes a resulting position descriptor to caller-provided storage.

**Inferred intent:** insert one 32-bit element at a requested position, using an endpoint operation for special positions and shifting the shorter side for an interior position.

**Established static behavior:** two ordered comparisons select endpoint paths. Otherwise, an unsigned position quantity is compared with half of a 32-bit collection field. One of two mutation-and-shift paths runs, a 32-bit input value is written to a computed slot, and a position descriptor is constructed in the output storage.

The insertion interpretation depends on opaque dependencies. The supplied fragment does not independently establish descriptor semantics, endpoint-helper behavior, allocation policy, or collection invariants.

## Acceptance examples

These are conditional static acceptance criteria, not executed tests.

### First comparison takes precedence

If the first comparison returns any nonzero value, including two:

- F-b3b2c7e983f9 receives the original element-input address.
- Result storage is constructed from the collection.
- The second classification comparison, offset calculation, direct field read, and both shift loops are skipped.

### Second endpoint selection

- F-7f2f11fcbaac receives the original element-input address.
- The result is derived with quantity one from a freshly constructed descriptor sourced at collection byte offset 16.
- No direct interior element assignment occurs.

### Unsigned midpoint boundary

Assume both classification comparisons return zero and the directly read field equals ten.

- Offset four selects the first interior path.
- Offset five selects the second interior path.
- Offset six also selects the second interior path.

If the field equals nine, the threshold is four, not five. Offset four selects the second path.

A field with its high bit set remains unsigned for this calculation.

### Exact loop termination

If a loop comparison returns one immediately, that loop performs no element-copy iteration, but its post-loop descriptor-construction call and common completion still occur.

If it returns two, the loop body executes. Nonzero alone does not terminate either loop.

### Late input aliasing

If element input aliases a slot modified during shifting, and all accesses remain valid, the final target store uses the value read after shifting. Acceptance must not require preservation of the input value as it existed on function entry.

### Backward-loop read ordering

If the source-address dependency yields a valid element address, the source value is read before the destination-address dependency runs. Any destination-side effect changing the source slot does not change the value already captured for that iteration.
