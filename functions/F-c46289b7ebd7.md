# F-c46289b7ebd7

## Purpose

F-c46289b7ebd7 repeatedly evaluates a selected record and routes status values through several dependencies until one of two terminal outcomes occurs.

The established behavior is a polling and dispatch loop with:

- A record selected by a 32-bit input and a fixed byte stride.
- Special handling for status values zero and four.
- Conditional calls involving the selected record.
- A secondary decision function that receives either the evaluated status or a fixed value of one.
- A 32-bit return value restricted to zero or one on the visible return paths.

The meanings of the record, status values, and terminal outcomes are not established. In particular, zero and one must not be labeled “success” and “failure” without additional evidence.

## Behavior

### Entry and repeated status evaluation

The record address is selected before the first dependency call.

Each loop iteration begins by calling **F-dc8516e7f798** with the input. Its returned status determines the next path:

- **Zero:** enter the common completion checks.
- **Four:** perform the special record handling described below, then either enter the common completion checks or dispatch status four.
- **Any other value:** dispatch that returned status directly.

All statuses other than zero and four take the same dispatch route. There is no visible range restriction or special handling for negative statuses.

### Special handling for status four

When the status is four, the function first reads the 32-bit field at record offset 0.

If that field is zero, the function proceeds directly to the common completion checks. It does not inspect offset 136 or call F-c9cecf23d64a on this path.

If the field at offset 0 is nonzero, the function reads the 32-bit field at offset 136:

- If offset 136 is nonzero, it skips F-c9cecf23d64a and dispatches status four.
- If offset 136 is zero, it calls **F-c9cecf23d64a**, passing the selected record address.

The result of F-c9cecf23d64a controls routing only:

- A nonzero result causes dispatch of status four.
- A zero result causes another read of the field at offset 0.

The dependency’s nonzero result is **not** substituted for status four. For example, a result of seven from F-c9cecf23d64a still leads to F-17ae00df9c6f receiving four.

After a zero result from F-c9cecf23d64a:

- If the newly read offset-0 field is nonzero, the function calls **F-ff425fbb8604** with the original input and a fixed second argument of one.
- If the field is zero, that call is omitted.

Both cases then enter the common completion checks.

The second read matters: the function does not reuse the value observed before F-c9cecf23d64a. Likewise, after F-ff425fbb8604 returns, the common completion checks perform their own record read rather than assuming the call preserved or changed the field.

### Common completion checks

This path is reached after an evaluated status of zero and after the non-dispatching status-four cases.

The checks occur in this order:

1. Read the field at record offset 0.
2. If it is nonzero, return one immediately.
3. Otherwise, call **F-8d5d13cf8690** with the original input.
4. If that dependency returns any nonzero value, return one immediately.
5. Otherwise, call **F-17ae00df9c6f** with the original input and a fixed second argument of one.
6. If that dependency returns exactly one, return zero.
7. If it returns any other value, begin another iteration by calling F-dc8516e7f798 again.

There is no visible record read between the return from F-8d5d13cf8690 and the call to F-17ae00df9c6f.

There is also no record check or F-ff425fbb8604 call between an exact-one result from this common-path F-17ae00df9c6f call and the return of zero. A dependency may therefore have changed the record without causing a further visible inspection on this terminal path.

### Status dispatch

The dispatch path calls **F-17ae00df9c6f** with:

- The original input.
- The evaluated status, including four when the special status-four handling selected dispatch.

If F-17ae00df9c6f returns anything other than exactly one, the function starts another iteration. No record check or F-ff425fbb8604 call occurs between that result and the next status evaluation.

If F-17ae00df9c6f returns exactly one, the function:

1. Reads the field at record offset 0.
2. Calls F-ff425fbb8604 with the original input and fixed second argument one if the field is nonzero.
3. Returns zero.

If the field is zero, it returns zero without calling F-ff425fbb8604.

If the call is made, its result is ignored, and there is no subsequent record check before returning zero.

### Important path distinctions

Although both uses of F-17ae00df9c6f can receive a second argument of one, they are not interchangeable:

- The **common path** reaches that call only after a zero record field and a zero result from F-8d5d13cf8690. An exact-one result returns zero without a further record read.
- The **dispatch path** may receive status one directly from F-dc8516e7f798. An exact-one result then causes a record read and a possible F-ff425fbb8604 call before returning zero.

A behavioral model must preserve the path distinction rather than merging calls solely because their argument values match.
