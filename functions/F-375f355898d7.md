# F-375f355898d7

## Purpose

The supplied static representation describes a low-level routine that performs an initial 16-bit memory write, executes a sequence of calls, reads a four-word record from a computed low address, constructs another four-word record at a fixed low address, updates two fields through a separately loaded base address, and reaches an invalid-instruction boundary.

A successful application-level purpose is not established. The representation includes unresolved incoming register state, unresolved auxiliary register results, potentially unaligned memory accesses, and explicitly truncated control flow. These features prevent treating the routine as an ordinary, fully recovered callable interface.

This contract describes the observable operations represented by the supplied material, conditional on execution reaching them. It does not establish that the material corresponds to a valid executable path.

## Behavior

### 1. Initial write and calls

The first represented memory effect is a 16-bit write of `0x002F` to the address obtained by doubling the hidden address seed.

The multiplication is represented at the machine-word level. No bounds check or alignment check precedes the store. Whether an invalid destination faults, aliases another object, or is permitted is outside the supplied evidence.

After this write, the routine performs the following calls in order:

1. **F-000000000001** receives two copies of the explicit 32-bit input. Its target is calculated by clearing the low two bits of the incoming link value and adding `0xC00`.
2. **F-000000000002** is invoked with no explicit arguments shown. Its 32-bit result is retained.
3. **F-000000000003** receives that retained word. Its 32-bit result is retained.

“No explicit arguments shown” does not establish that a dependency is independent of machine state or memory.

### 2. Computed record address and nibble argument

The routine calculates a record address from the hidden selector seed:

- Subtract `0x33` using unsigned 32-bit arithmetic.
- Logically shift the result right by 24 bits.
- Interpret the resulting word as an address.

Consequently, the represented address is in the inclusive range `0x00` through `0xFF`. It is not an index scaled by the size of a word. It is not necessarily word-aligned.

The routine then invokes **F-2cc1255261f3**, passing the high four bits of the result from **F-000000000003**. This argument is an unsigned value from 0 through 15.

The record address has already been calculated, but the record itself has not yet been read. Calls between calculation and use may therefore change the memory subsequently read.

### 3. Three further call pairs

The following six calls occur in order:

1. **F-000000000004** produces a represented 32-bit result.
2. **F-000000000005** receives that result.
3. **F-000000000006** produces a represented 32-bit result.
4. **F-000000000007** receives that result.
5. **F-000000000008** produces a represented 32-bit result.
6. **F-000000000009** receives that result.

For the first call in each pair, no explicit arguments are shown. No ordinary return value from the second call in a pair is used by the visible expressions.

That absence of a visible result use does not imply absence of side effects. In particular, the representation later uses an auxiliary register word whose provenance is not fully resolved.

### 4. Record reads and fixed-address writes

After those calls, the routine performs four 32-bit reads from the calculated record address, in this order:

| Relative byte offset | Read value’s later role |
|---|---|
| `0` | First argument to F-000000000010 |
| `4` | Fourth argument to F-000000000010 |
| `8` | Third word of the fixed-address output record |
| `16` | Fourth word of that record and a later local value |

There is no represented read at relative offset `12`.

The routine then constructs a four-word record starting at address `0xC3`:

| Address | Width | Stored value |
|---|---:|---|
| `0xC3` | 32 bits | An unresolved auxiliary register-result word |
| `0xC7` | 32 bits | The address `0xC3` |
| `0xCB` | 32 bits | The word previously read at record offset `8` |
| `0xCF` | 32 bits | The word previously read at record offset `16` |

The stores occur in the listed order. The second word is a pointer back to the start of this output record.

These are unusually low, unaligned word addresses. Their literal appearance is established by the representation; their validity on the intended target is not.

All four source reads precede all four destination writes. Thus, if source and destination storage overlap, the four represented source values are captured before these destination writes occur. This does not exclude interference from dependencies, other execution contexts, or access faults.

### 5. Base capture and four-argument call

Next, the routine reads a 32-bit base-address word from a fixed data location.

It then calls **F-000000000010** with four arguments, in order:

1. The source word read at offset `0`.
2. The same unresolved auxiliary word used in the first output-record store.
3. The address `0xC3`.
4. The source word read at offset `4`.

The base-address read occurs before this call. The captured value is used afterward without a represented reload. The dependency may change the memory from which that base was loaded; such a change would not itself change the already captured value.

No assumption is made about whether the dependency reads, modifies, retains, or releases anything reachable through its arguments.

### 6. Selector read, field write, and branch

After **F-000000000010**, the routine:

1. Reads a 32-bit selector from another fixed data location.
2. Writes an unresolved auxiliary register-result word to the captured base plus `0x68`.
3. Compares the selector with 8 using unsigned comparison.

The write at base plus `0x68` occurs before the branch, including when the selector exceeds 8.

If the selector is greater than 8, the visible path terminates at an invalid-instruction boundary. No normal return or structured error report is shown.

If the selector is 0 through 8 inclusive, execution continues.

### 7. Selector-accepted path

For selectors 0 through 8, the routine invokes **F-000000000011**, which has a represented 64-bit result.

After that call, the routine performs these operations in order:

1. Writes the selector’s low byte to the captured base plus `0x0F`.
2. Writes a 16-bit value to the address `selector + 0x28`.
3. Stores the unsigned value `0xC3` shifted right by 14 bits into a local 32-bit slot.
4. Stores the source word previously read at offset `16` into another local 32-bit slot.
5. Calls **F-000000000012** with three arguments:
   - The low 32 bits of the 64-bit result.
   - The high 32 bits of that result.
   - The word `0x74`.
6. Reaches a second invalid-instruction boundary.

The 16-bit value in step 2 is the low 16 bits of the first local slot’s address plus `0x398`, reduced to the stored 16-bit width. It is not established to be a usable pointer or offset.

For the accepted selector range, this 16-bit store starts at an address from `0x28` through `0x30`. Odd selectors produce odd starting addresses.

The local value in step 3 is zero: `0xC3` is smaller than `2^14`. The representation nevertheless makes the local slot’s address relevant before assigning that zero.

## Acceptance examples

These examples are conditional static expectations, not executed tests. Each assumes earlier calls return and required accesses complete.

1. **Repeated explicit input.** For an explicit input of `0x12345678`, F-000000000001 receives `0x12345678` as both arguments.

2. **Nibble extraction.** If F-000000000003 returns `0xA1234567`, F-2cc1255261f3 receives 10. Changes confined to the lower 28 bits do not change that argument.

3. **Unsigned address calculation.** A hidden selector seed of `0x00000033` produces source address zero. A seed of `0x00000032` underflows during subtraction and produces source address `0xFF`. The calculation does not clamp negative-looking differences.

4. **Source-record layout.** If the four reads at offsets `0`, `4`, `8`, and `16` produce four distinct words, the third and fourth are stored at `0xCB` and `0xCF`. The first and second become the first and fourth arguments to F-000000000010.

5. **Upper accepted boundary.** A loaded selector of 8 takes the continuing path. After F-000000000011 returns, the byte stored at base plus `0x0F` is 8, and the 16-bit store starts at `0x30`.

6. **First rejected value.** A loaded selector of 9 still permits the preceding base-plus-`0x68` write. It then reaches the first invalid-instruction boundary without invoking F-000000000011 or F-000000000012.

7. **Unsigned rejection.** A selector of `0xFFFFFFFF` is greater than 8. It does not enter the continuing path as a negative signed value.

8. **64-bit splitting.** If F-000000000011 returns `0x1122334455667788`, F-000000000012 receives `0x55667788`, `0x11223344`, and `0x74`, in that order.

9. **Captured base.** If F-000000000010 changes the memory holding the base-address word, subsequent visible base-relative stores still use the value captured before that call, provided no unrepresented mechanism invalidates the recovered dataflow.
