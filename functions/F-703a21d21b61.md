# F-703a21d21b61

## Purpose

F-703a21d21b61 interprets a byte sequence beginning with marker `0x1E` as a nibble-encoded numeric value. It accumulates an integer component, optionally accumulates a fractional component, optionally applies a decimal exponent, and constructs a 32-bit result using a 16-bit left shift and an optional dependency-produced contribution.

The returned representation resembles a signed fixed-point value. That interpretation is inferred intent, not a complete established numeric contract: the fractional conversion and integer-division dependencies are not defined here, and the result combines their outputs without enforcing a 16-bit fractional boundary.

If the initial byte is not `0x1E`, the function takes a separate dependency-based return path rather than parsing the sequence.

Malformed or incomplete marked input can return zero. Zero is also a possible successful numeric result; there is no separate status channel.

## Interface

### Input descriptor

The function accepts a pointer to a descriptor containing at least two consecutive 32-bit words:

| Offset | Meaning |
|---|---|
| 0 bytes | Address of the initial input byte |
| 4 bytes | Exclusive end address used during marked-input parsing |

The displayed representation uses 32-bit words for addresses and arithmetic state. The descriptor is read but is not explicitly modified.

Both descriptor words are loaded before the initial input byte is inspected. The first byte is read without first checking whether its address is below the supplied end address.

Consequently, the caller must provide:

- A readable descriptor covering both words.
- A readable initial byte, even when the supplied range is empty or reversed.
- A meaningful address ordering for subsequent comparisons against the exclusive end.
- Readable input storage for every byte that passes those comparisons.

The function does not receive an output buffer, a consumed-length destination, or an error destination.

### Return value

The return value is a 32-bit unsigned word. Its principal forms are:

- A dependency result shifted left by 16 bits, for an initial byte other than `0x1E`.
- Zero when marked-input parsing needs another byte but reaches or passes the supplied end.
- A constructed numeric word after a terminating nibble has been consumed.

There is no returned cursor. Success, truncation, and some dependency-produced results may be indistinguishable.

### Arithmetic state

The marked-input path maintains separate 32-bit arithmetic quantities for:

- Integer accumulation, initially zero.
- Fractional numerator accumulation, initially zero.
- Fractional denominator accumulation, initially one.
- Decimal exponent accumulation, initially zero.

It also maintains a negative-sign flag, initially clear.

The displayed operations use signed integer intermediates in several places. Their intended behavior outside the signed representable range is not established by this source alone. Defined, portable acceptance claims therefore require those intermediates to remain representable unless target arithmetic semantics are supplied separately.

## Behavior

### Initial dispatch and byte bounds

The function first reads the initial input byte.

If it is not `0x1E`, the function:

1. Calls F-f089df22028c with no explicit arguments.
2. Shifts that dependency’s returned integer left by 16 bits.
3. Returns the resulting word.

This branch does not perform a range check against the supplied end and does not scan subsequent input bytes.

If the initial byte is `0x1E`, the function begins parsing at the next byte. Before reading that byte, it checks whether its address is at or beyond the exclusive end. If so, it returns zero.

The marker itself contributes no numeric digit.

### Nibble order

Parsing proceeds in byte-address order, processing each byte’s high nibble before its low nibble.

Each nibble extraction reads the current byte. The implementation does not establish a single immutable snapshot of a byte for both of its nibbles. Callers requiring stable interpretation must keep the input unchanged while the function executes.

Before advancing to and reading a new byte, the parser checks that the new address is below the end. It does not require an additional byte after a terminating nibble.

A nibble’s meaning depends on the active phase.

### Integer and sign phase

The initial phase accepts these nibble classes:

| Nibble | Effect |
|---|---|
| `0`–`9` | Append a decimal digit to the integer accumulator |
| `E` | Set the negative-sign flag and continue |
| `A` | Begin fractional-digit parsing |
| `B` | Begin exponent parsing with positive polarity |
| `C` | Begin exponent parsing with negative polarity |
| `D` or `F` | Finish the value without an explicit exponent |

Appending a digit multiplies the previous integer accumulator by ten and adds the digit.

The `E` nibble is not restricted to a leading position. It may appear between integer digits or multiple times. It sets a flag; it does not toggle the sign and does not alter the accumulated magnitude.

A digit or `E` nibble does not finish the value. If input ends after such a nibble without a terminating transition, the function returns zero when it next needs a byte.

There is no explicit requirement that the integer phase contain any digits.

### Fractional phase

An `A` nibble starts fractional parsing. Subsequent decimal digit nibbles are consumed until the first nibble greater than nine.

For each fractional digit, the function consults a shared fractional-accumulation threshold. If the current denominator compares less than that threshold, it:

- Multiplies the fractional numerator by ten and adds the digit.
- Multiplies the denominator by ten.

Otherwise, it consumes the digit without updating either quantity.

Thus the threshold limits accumulation, not scanning. Digits beyond the threshold do not themselves produce an error, and the parser must still find a nondecimal nibble. No rounding operation is visible for skipped digits.

The threshold condition is tested separately for each fractional digit. It is not expressed as a fixed number of accepted digits. Its type, configured value, and initialization are not established here.

The first nondecimal nibble ends fractional scanning:

- `B` starts positive-exponent parsing.
- `C` starts negative-exponent parsing.
- Any other nondecimal nibble finishes parsing without an explicit exponent.

In particular, `E` encountered here does **not** set the negative-sign flag. That behavior belongs only to the integer/sign phase. A second `A` also ends fractional scanning rather than starting another fractional section.

No fractional digit is required after `A`. The next nibble may immediately terminate the section or introduce an exponent.

### Exponent phase

Exponent parsing begins only when `B` or `C` is interpreted as an exponent introducer, either directly from the integer/sign phase or as the terminator of fractional scanning.

The exponent magnitude is reset to zero. Decimal nibbles are appended by multiplying the accumulated magnitude by ten and adding each digit.

The first nondecimal nibble ends exponent scanning. That nibble is consumed, but its specific value has no further grammatical effect:

- It does not set the negative-sign flag.
- It does not start a fractional section.
- It does not introduce another exponent.

For `C`, the accumulated exponent magnitude is negated after scanning. For `B`, it is retained.

No exponent digit is required. An immediate nondecimal nibble therefore yields exponent zero.

An exponent requires its own terminating nondecimal nibble. Reaching the end after exponent digits returns zero rather than accepting the digits as a complete exponent.

### Decimal scaling

Once parsing has reached completion, the exponent is applied before result construction.

For each positive exponent unit:

- The integer accumulator is multiplied by ten.
- The fractional numerator is multiplied by ten.
- The fractional denominator is unchanged.

For each negative exponent unit:

- F-870c4fcf7295 is called with the current integer accumulator and the integer value ten.
- Its return replaces the integer accumulator.
- The fractional denominator is multiplied by ten.
- The fractional numerator is unchanged.

Calls for a negative exponent occur sequentially; each call receives the preceding call’s result.

The source does not transfer any remainder from integer division into the fractional numerator. If F-870c4fcf7295 implements ordinary truncating integer division, a value containing only integer digits loses the divided-off remainder during negative scaling. A real-number or decimal-preserving interpretation must not be assumed.

### Result construction

The function constructs the result in this order:

1. Shift the final integer accumulator left by 16 bits.
2. If the fractional numerator is nonzero, call F-73d099a86adb with the final numerator and denominator.
3. Combine that dependency’s entire returned word with the shifted integer contribution using bitwise OR.
4. If the negative-sign flag is set, negate the combined word.
5. Return the resulting 32-bit word.

There is no explicit mask restricting the dependency result to the low 16 bits. Any bits it supplies in the upper half participate in the OR operation.

If the fractional numerator is zero, F-73d099a86adb is not called, irrespective of the denominator’s value.

Sign application occurs after combination. It is not separately applied to the integer and fractional accumulators.

## Acceptance examples

These examples assume readable stable input, normal dependency returns, and representable signed intermediates. Nibble sequences are listed in consumption order after the initial marker. Nibbles following a consumed terminator are not part of the parsed value.

### Integer and sign behavior

- Marker followed by nibbles `1, 2, 3, F` returns `0x007B0000`. No fractional conversion or negative-exponent dependency call is needed.
- Marker followed by `E, 1, 2, F` returns `0xFFF40000`, the 32-bit negation of `0x000C0000`.
- Marker followed by `1, E, 2, E, F` has the same result as the preceding example. Embedded or repeated `E` nibbles set the same flag.
- Marker followed immediately by `F` returns zero without requiring a digit.
- A range containing only the marker returns zero.
- A range ending after nibbles `1, 2`, without a terminator, returns zero rather than the encoding of twelve.

### Fractional behavior

- For `1, A, 2, 5, F`, if both fractional digits pass the threshold condition, the final fractional conversion is F-73d099a86adb with numerator 25 and denominator 100. The result is that returned word ORed with `0x00010000`.
- For `1, A, 0, F`, the numerator remains zero. The result is `0x00010000`, and F-73d099a86adb is not called.
- For `1, A, E`, the `E` terminates the fractional section. It does not make the result negative. With no fractional digits, the result is `0x00010000`.
- For `A, 2, 5, 9, F`, if the threshold is ten, only the first digit is accumulated: the denominator becomes ten, and subsequent digits fail the strict comparison. The fractional conversion receives numerator two and denominator ten. All three digits are nevertheless consumed.

### Exponent behavior

- For `1, 2, B, 2, F`, positive scaling produces integer 1200 and result `0x04B00000`.
- For `1, 2, C, 1, F`, F-870c4fcf7295 is called once with 12 and ten. If it returns one, the result is `0x00010000`; no fractional contribution is created for the discarded remainder.
- For `1, B, F`, the exponent contains no digits and is zero. The result is `0x00010000`.
- For `1, B, 2, E`, the `E` terminates exponent scanning but does not set the negative-sign flag. The result is positive 100 shifted left by 16 bits.
- For `1, B, 2` with no terminating nibble before the end, the result is zero.

### Initial mismatch and result combination

- If the initial byte is not `0x1E`, F-f089df22028c is called even when the supplied end would reject that initial address as part of a marked range. If its return is seven, the returned word is `0x00070000`.
- If a nonzero fractional numerator causes F-73d099a86adb to return a word containing upper-half bits, those bits remain in the OR result. Acceptance must not silently mask them away.

## Uncertainties

### Established static behavior

It also establishes that truncation returns zero without updating a caller-visible cursor.

### Inferred intent

The encoding appears to represent a decimal value with an optional sign, decimal fraction, and signed decimal exponent. The final shift suggests a representation with 16 fractional bits.

Neither inference overrides the actual operations. In particular, negative-exponent handling does not visibly preserve integer remainders, and the fractional dependency’s result is not masked.
