## Behavior

### 1. Capture the three source values

The function copies source word A into the first local word, then source word B into the second local word, then source word C into the third local word.

All three copies precede the transformation loop and all dependency calls. Consequently, the local preparation is based on values captured before any of the three dependencies executes.

The evidence establishes this source-level ordering. It does not establish atomic reads, synchronization, volatile access semantics, or a coherent snapshot if another execution context can change the source data concurrently.

### 2. Transform the local words in reverse order

The function visits the three local words in this order:

1. C, at offset 8.
2. B, at offset 4.
3. A, at offset 0.

For each word, it reads the local 32-bit value, shifts it right by one with zero fill, and writes the result back to the same local word.

For an unsigned input value \(x\), the result is \(\lfloor x/2 \rfloor\). The original least-significant bit is discarded. The original most-significant bit moves to bit 30, and bit 31 becomes zero.

This is not signed division or an arithmetic right shift. For example, an input word of `0xFFFFFFFF` becomes `0x7FFFFFFF`, not `0xFFFFFFFF`.

Exactly three local words are transformed. The adjacent eight-byte area is not included in this loop. There is no carry transfer, bit propagation, or other arithmetic relationship between neighboring words.

The transformation changes the local copies. The visible body does not write the transformed values back to their static sources.

### 3. Write the boundary byte

After all three shifts, the function writes zero to the first byte of the adjacent eight-byte area, at offset 12 from the preparation-region start.

It does not explicitly initialize the remaining seven bytes of that area. It also does not initialize the separate 40-byte workspace before passing it to a dependency.
