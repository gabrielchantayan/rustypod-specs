# F-991340996841

## Purpose

F-991340996841 processes groups of byte positions using eight resolved input streams and six resolved output streams. Each position produces one copied byte and five weighted, clamped, fixed-point results.

The function also advances address-bearing frame state. Three output states advance before each termination check, including the check that ends execution. Other stream states advance only after an entered group completes.

**Established static evidence:** the supplied body specifies fourteen address-resolution calls per entered group, eight input-byte reads and six output-byte writes per processed position, and the state transitions described below.

**Inferred intent:** the weighted expressions resemble a filtering or resampling operation. No image format, channel assignment, sample interpretation, or application-level purpose is established.

The visible two-argument interface is not a complete standalone calling contract. The function additionally consumes incoming register state, frame-resident state, and external coefficient storage whose initialization is not supplied.

## Behavior

### Group entry and termination

At every outer-loop entry, the function adjusts the O4, O5, and O6 address-bearing fields, in that order. Each receives its existing value plus four times the current advance factor times its associated stride.

Only afterward does it compare the group limit with progress using a signed comparison:

- If the limit is less than or equal to progress, execution returns.
- Otherwise, the group is entered.

Thus an invocation processing no groups still performs three state adjustments. A terminating entry following completed groups also performs them.

For an entered group, the current third-output state is assigned to the O3 field before address resolution.

### Address resolution

F-33d55115462b is called fourteen times, in this order:

1. S1 through S8.
2. O1 through O6.

Each call receives the address of the corresponding frame field. Its returned 32-bit value is retained as that group’s byte-stream base.

All fourteen calls precede byte processing, even if the byte count is zero or negative. There are no such calls on an entry that terminates at the group-limit check.

The dependency’s side effects are unknown. In particular, later calls may observe changes made by earlier calls. The function does not establish that descriptors, strides, coefficient storage, the byte count, or the group limit retain their entry values across resolution.

### Position processing and input reads

The position starts at zero. Processing continues while the signed position is less than the current signed byte count, increasing the position by one after each completed iteration.

The count is not explicitly snapshotted before the loop. If reachable writes alter it, later loop conditions may observe the altered value.

For each position, one unsigned byte is read from each resolved input base plus that position. The established read order is:

### Fixed-point conversion

Define **Q** on the evaluated signed 32-bit intermediate:

- Below zero: produce byte 0.
- Above 0x0ff00000: produce byte 255.
- Otherwise: discard the low twenty bits and store the remaining value as one byte.

The upper threshold is exactly 267386880, or 255 × 2²⁰. At the threshold, the result is also 255. There is no rounding increment.

The clamp operates after the weighted expression has been evaluated. It does not prevent overflow in that expression.

### Group completion

After the position loop finishes, including when it processes no positions, the function:

1. Advances S1 through S8 state, in stream order, by 20 times each current associated stride.
2. Sets the advance factor to 6.
3. Increases progress by 5.
4. Advances O1 state by 24 times its current stride.
5. Advances O2 state by 24 times its current stride.
6. Derives the next third-output state as the current O3 field plus 24 times its current stride.

The last operation prepares a value for the next entered group; it does not itself assign that value back to the O3 field. A following terminating entry does not perform the O3 assignment.

The next entry advances O4–O6 by 24 times their respective strides before testing termination.
