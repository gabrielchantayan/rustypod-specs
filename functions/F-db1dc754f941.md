# F-db1dc754f941

## Purpose

F-db1dc754f941 accepts an opaque 32-bit word, forwards it to an indirect dependency, performs an extensive dependency-driven sequence of bit transformations, updates memory through computed and absolute addresses, and ends with a four-word indirect transfer.

No domain-level purpose is established. Character-like constants do not establish text output; repeated offsets do not establish an object layout.

This contract distinguishes **established static evidence**, **[INFERENCE]**, and **documented_only** uncertainties. Acceptance examples are conditional deductions, not observed executions. No runtime tests have been performed.

## Interface

### Explicit input and output

The sole represented parameter is a 32-bit opaque word. Signedness, valid range, pointer interpretation, and sentinel meanings are unspecified.

The first indirect invocation receives this word unchanged. No validation or direct dereference of the explicit parameter precedes that invocation.

There is no represented explicit return value. A return follows the final indirect transfer in the supplied representation, but whether that transfer returns normally is unresolved.

### Environmental inputs and preconditions

Additional inputs include incoming control state, indirect targets, primary and secondary dependency results, global state, and memory contents. The first invocation’s target is formed from incoming control state plus 0xffe.

Completion requires all preceding dependencies and memory accesses to complete. No null, bounds, alignment, permission, lifetime, or target-validity checks are represented.

### Widths and arithmetic

Memory operations distinguish 8-bit bytes, 16-bit halfwords, and 32-bit words. Paired results occupy represented 64-bit containers with separately consumed low and high 32-bit portions; this does not establish a language-level return convention.

Byte and halfword stores retain the low eight and sixteen bits respectively. Byte reads used as address contributions or words are zero-extended. Unsigned right shifts are logical.

Where explicitly assumed below, **32-bit bit-vector semantics** mean that addition, multiplication, and left shifts retain the low 32 bits. Intermediate truncation is significant: widening a later operation cannot restore discarded bits.

Some represented calculations use signed quantities. Actual signed-overflow rules, signed right-shift behavior, excessive shift counts, and address-overflow behavior remain **documented_only**. Byte order and unaligned-access behavior are likewise unresolved.

## Behavior

### Dependency-driven phase

An extensive straight-line sequence of indirect invocations precedes the first explicit data-memory store. Dependencies may themselves branch, change memory, fail, or not return.

The opening three invocations respectively receive the explicit input, have no represented explicit arguments, and produce a paired result. The next consumer receives three words:

- The paired result’s low word shifted left eight bits.
- Its high word unchanged.
- The same high word shifted left six bits.

Later consumers use primary results, secondary result words, paired-result portions, earlier retained results, and explicit zeros. Transformations include low-bit masks, left shifts through thirty-one bits, logical right shifts, and 64-bit extraction shifts greater than thirty-two bits.

Observable trace requirements include preservation of producer-before-consumer ordering, calls with no explicit arguments, secondary-result distinctions, and equality of repeated arguments. Earlier retained results remain associated with their original producer across intervening calls. An unused primary result does not make its producing invocation removable.

Intermediate widths must be respected. For example, two successive 32-bit left shifts by twenty-eight yield zero under bit-vector semantics; they are not a widened fifty-six-bit shift. Explicitly zeroed values remain zero through subsequent defined shifts and masks.

The complete per-site dependency trace is not enumerated here; its unenumerated details remain **documented_only**, not permission to omit or reorder calls.

### Memory roles

These descriptive roles identify retained values, not recovered object types:

| Role | Meaning |
|---|---|
| **Result base** | High word of the final paired result before direct stores |
| **Shifted base** | Retained paired-result low word shifted left twenty-five bits |
| **Scaling precursor** | Retained call result used for the following scaling calculations |
| **Scaled base** | Scaling precursor multiplied by \(2^{25}\) |
| **Extract** | A call result shifted left eight bits, masked with 0x7fff, then logically shifted right six bits |
| **Small base** | Twice Extract |
| **Payload** | Another retained call result shifted left eight bits |

All offsets below are byte offsets. Unless another width is stated, stores and reads described as words are 32-bit. Computed regions may overlap each other or absolute addresses.

### Initial stores and zero read-back

The first mutation episode stores Shifted base at Result base plus 0x14. A byte at Shifted base plus 9 first receives Result base’s low byte. Scaled base is then stored at the final paired result’s low word multiplied by 256 plus 0x54. The byte at Shifted base plus 9 is subsequently overwritten with Shifted base’s low byte.

Under bit-vector semantics, Shifted base has twenty-five zero low bits, making that second byte zero. The earlier byte store remains an observable intermediate effect.

Next, Scaled base plus 0x14 is cleared. A byte read at Scaled base plus 5 is retained; Small base plus 0x14 is cleared; and the retained byte is stored, zero-extended, at Scaled base plus 0x34. The word at Scaled base plus 0x14 is then read back. Small base plus 0x14 is cleared again, followed by two byte stores of the read-back value at Small base plus 0x15.

In ordinary stable byte-addressed memory, without access side effects or external modification, **the read-back is zero**. An overlapping Small-base clear only writes zero bits. The Scaled-base offset-0x34 store is disjoint from its offset-0x14 word and cannot introduce a nonzero read-back.

Device semantics, unusual address mapping, or concurrent modification could invalidate that ordinary-memory deduction; none is established.

### Byte-derived addressing and absolute updates

A byte at absolute 0x05 is read and zero-extended as **Byte-derived base**. Absolute byte 0x01 then receives Small base’s low byte.

Extract’s low byte is stored at Byte-derived base plus 0x15. Payload’s low byte is stored at Scaled base plus 0x11; Payload is stored as a word at the earlier read-back value plus 0x54; and Scaled base plus 0x11 is cleared. Under the ordinary-memory conditions above, the Payload word targets absolute 0x54.

The word at Byte-derived base plus 0x54 is read as **Retained word**, then overwritten with the earlier read-back value. Small base plus 0x34 receives Extract.

A word read at Scaled base plus 0x74 supplies **Other base**. Its offset-0x54 word first receives Scaling precursor shifted left twenty-six bits and later receives Payload. Between those stores, Small base plus 0x74 is read twice in one expression: one read supplies a destination base and the other supplies its stored word. Their relative evaluation order is unresolved; they must not be presumed to be one stable read.

Retained word is stored twice at its own base plus 0x24. Other base plus 9 receives Retained word’s low byte twice, with the Payload overwrite between the two pairs of stores.

Small base plus 0x14 then receives the twenty-six-bit-shifted precursor. **Absolute word 0x54 receives Retained word shifted left one bit**, after which Small base plus 0x14 receives Retained word twice.

Define **Quad base** as four times Retained word and **Octuple value** as eight times Retained word. Small base plus 0x15 receives Quad base’s low byte twice. **Absolute byte 0x15 then receives Small base’s low byte.** Only afterward does Quad base plus 0x54 receive Payload, followed by Small base plus 0x34 receiving Quad base.

Absolute accesses are distinct from computed accesses with numerically identical offsets.

### Relationships, overlapping widths, and Terminal-link acquisition

A word read at Small base plus 0x74 is doubled as **Doubled link**. Quad base plus 0x54 receives Quad base; its offset-0x15 byte receives Octuple value’s low byte; and Retained word plus 0x44 receives Doubled link.

A byte read at Quad base plus 5 supplies a zero-extended address contribution. The word at that contribution plus 0x74 becomes **Lookup base**, whose offset-0x44 word receives Doubled link.

Quad base plus 0x15 is then overwritten with Quad base’s low byte. Lookup base’s low byte is stored at Quad base plus 0x0d, followed by a self-word at Quad base plus 0x14 and Quad base at offset 0x54. A word read at Quad base plus 0x64 supplies another base whose offsets 0x0d and 0x14 receive Lookup base’s low byte and a self-word.

A word read at Quad base plus 4 supplies **Source base**. Doubled link plus 9 receives Lookup base’s low byte, and Doubled link plus 0x44 receives Octuple value.

Source base plus 5 is read twice as a byte. After the first read, Quad base plus 9 receives Doubled link’s low byte, then Lookup base plus 0x44 receives the zero-extended byte. Quad base plus 0x14 receives Octuple value. Doubled link’s offsets 0x15 and 0x44 then receive Source base’s low byte and Quad base.

**The second Source-base byte read does not immediately acquire Terminal link.** Its zero-extended result is retained, and **Quad base plus 0x15 first receives Octuple value’s low byte**. Only after that byte store is the word at the retained byte-derived address plus 0x74 read as **Terminal link**.

After Terminal link has been read:

- Quad base plus 0x15 receives Source base’s low byte.
- Quad base plus 0x54 receives Quad base.
- Quad base plus 9 receives the low byte of twice Terminal link.
- Quad base plus 0x14 receives Octuple value.

The byte store between the second Source-base read and the Terminal-link word read can overlap that word. Terminal link therefore reflects that store under ordinary-memory semantics. The later Source-base-byte overwrite cannot be moved ahead of the Terminal-link read.

The two Source-base byte reads need not agree: intervening computed stores may overlap their source.

### Constants and repeated publication

Define:

- **Tail base:** twice Terminal link.
- **Publication payload:** four times Terminal link.
- **Adjusted value:** Quad base minus 150 decimal.
- **Publication region:** four times Adjusted value.

The constant 0x3a is stored as a byte at Publication payload, as a halfword at eight times Terminal link, and as a word at Publication payload plus 0x20, in that order.

Publication region plus 0x20 successively receives words 0x20, 0x2f, the zero-extended byte freshly read at Publication region plus 4, and 0x20.

The publication-base global is then read and saved as **Publication base**, **before** absolute word 0x60 receives 0x20. Publication uses the saved value even if that absolute store changes the global’s storage.

Each publication group has four ordered effects:

1. Destination base plus 0x54 receives Publication payload as a word.
2. Publication base plus 0x19 receives Publication region’s low byte.
3. Publication region plus 0x11 receives Publication base’s low byte.
4. Publication base plus 0x34 receives Destination base as a word.

The first group uses Octuple value as Destination base. Subsequent explicitly repeated groups use eight times Adjusted value. No traversal or Publication-base reload is represented.

The exact repetition count is not independently enumerated in this contract; count-specific acceptance remains **documented_only**. The representation shows a fixed repeated block, not a data-dependent loop.

### Final fixed-address and computed accesses

After publication, the represented order is:

- Read absolute word 0xa9 as **Saved global word**.
- Read Publication payload plus 0x74 as **Earlier link word**.
- Store at absolute byte 0x3a the low byte of eight times Adjusted value plus 0x30.
- Read Tail base plus 0x14 as **Saved tail word**.
- Read Publication region plus 4 as **Saved region word**.

The last two reads occur after the absolute byte update; aliasing can make that placement significant.

Tail base plus 0x0d receives Publication region’s low byte. Publication region’s offsets 8, 0x0d, and 9 receive byte 0x6c, Publication base’s low byte, and Publication base’s low byte respectively. Tail base plus 0x54 receives Tail base.

Absolute byte 0x67 receives Saved global word’s low byte. Tail base plus 0x44 is then read as **Tail-derived word**. A fresh read of absolute byte 0x67 supplies absolute byte 0x21.

Tail-derived word supplies a byte at Publication region plus 0x10 and a word at Publication base plus 0x54. Its signed right-shifted result supplies a byte at Tail base plus 1, with Publication region’s low byte as the shift count. Publication base plus 0x54 is subsequently overwritten with Publication region.

A fresh word read at Publication region plus 0x40 supplies a later word overwrite at Publication region plus 0x10. Between that read and overwrite, Publication base plus 0x74 receives Saved region word. Publication base plus 0x44 then receives Tail base.

A fresh absolute-0x67 byte read supplies Publication region plus 9. Tail base plus 9 receives Publication region’s low byte, and Publication region plus 0x44 receives Saved global word. Publication region plus 0x54 is read as **Late destination**, followed by another fresh absolute-0x67 read for another byte store at Publication region plus 9.

These absolute-0x67 reads cannot be replaced with a preserved Saved-global-word byte: intervening computed writes may overlap absolute 0x67.

### Closing accesses and final transfer

Late destination plus 0x0d receives Earlier link word’s low byte. Tail base plus 0x54 is restored from Saved tail word. A fresh word read at Publication region plus 0x14 is saved as **Closing byte source**.

Tail base plus 0x11 then receives Earlier link word’s low byte. Publication region plus 9 receives Late destination’s low byte, followed by its offset-0x44 word receiving Late destination.

The closing sequence preserves this interleaving:

- Tail base plus 4 is read as **Closing base**.
- Halfword 0x65 is stored at twice Closing base.
- Closing base plus 0x64 is read as **Closing value**.
- **Only now does Late destination plus 0x11 receive Closing byte source’s low byte.**
- Late destination plus 0x54 receives word 100.
- Closing base plus 0x74 is read as **Final link word**.
- Tail base plus 0x64 is read as **Closing destination**.

Thus, the Late-destination byte store occurs after the Closing-value read but before the word-100 store and Final-link read. Its value comes from the saved Closing byte source, not a reload. Aliasing does not justify moving the store earlier or later.

Finally, Tail base plus 9 receives Closing base’s low byte. Closing destination plus 0x54 receives Closing value, and the word at twice Closing value receives Closing destination.

The final indirect transfer receives four words, in order: **0x72, Closing value, Saved tail word, Final link word**.

## Acceptance examples

All examples assume the described phase is reached and relevant accesses complete.

1. **Input forwarding.** Input 0x89abcdef reaches F-U001 unchanged as a 32-bit word.

2. **Paired-result widths.** Opening paired-result words 0x12345678 and 3 produce consumer arguments 0x34567800, 3, and 0xc0 under bit-vector semantics.

3. **Intermediate truncation.** Two successive 32-bit left shifts by twenty-eight produce zero, regardless of the starting word.

4. **Zero extension.** A byte-derived address contribution of 0xfe means 254, not negative two.

5. **Early zero read-back.** In ordinary stable memory, the Scaled-base offset-0x14 read returns zero even if an intervening Small-base clear overlaps it.

6. **Absolute updates.** If Retained word is 0x12345678, absolute word 0x54 receives 0x2468acf0 at its specified later update. If Small base is 0x100, absolute byte 0x15 receives zero.

7. **Terminal-link intervening store.** Assume little-endian ordinary memory, Quad base 0x80, Octuple value 0x100, and a second Source-base byte read of 0x21. The Terminal-link word starts at 0x95, the same address as Quad base plus 0x15. If that word initially contains 0x11223344, the intervening zero-byte store makes Terminal link 0x11223300. A subsequent Source-base-low-byte overwrite cannot retroactively change the retained Terminal link.

8. **Saved publication base.** A publication-base read returning 0x1000 remains the value used for publication even if the following absolute-0x60 store changes its original storage.

9. **Fresh absolute byte.** If an intervening computed write changes absolute 0x67 to 0x42, the following fresh read supplies 0x42, not the originally stored Saved-global-word byte.

10. **Closing byte-store placement.** Assume little-endian ordinary memory, Closing base 0x1000, Late destination 0x1053, and Closing byte source low byte 0xaa. Late destination plus 0x11 aliases Closing base plus 0x64. If the Closing-value read returns 0x11223344, the later byte store may change that memory to 0x112233aa, but the retained Closing value remains 0x11223344. The final transfer and Closing-value-derived stores use that retained value.

11. **Partial failure.** A late access fault provides no rollback guarantee for earlier stores.
