# F-789728274fbc

## Purpose

F-789728274fbc transfers four individually read bytes from a cursor-selected location into a destination buffer while updating the caller-provided cursor storage four times.

The defining behavior is not merely a four-byte copy followed by a cursor increment. Each cursor update occurs before its corresponding source-byte read, and all four source reads occur before the first destination-byte write. These ordering properties matter when the source, destination, and cursor storage overlap.

**Established static behavior:** The operation has a fixed transfer size of four bytes. It does not inspect the second argument, validate addresses, check available input or output space, or report a status.

**Inferred intent:** The function appears intended to consume a four-byte field from a moving input cursor and copy its byte representation into caller-provided storage. No numeric interpretation of that field is established.

## Behavior

### Initial cursor acquisition

The function first reads the cursor slot and retains the resulting source address for the duration of the transfer.

This is the only read of the cursor slot as a cursor value. Later writes to that slot do not redirect the remaining source accesses, including when the destination eventually overwrites the slot.

### Ordered source acquisition and cursor updates

The function performs four source-byte acquisitions. Before each acquisition, it writes a new value to the cursor slot:

| Acquisition | Cursor value written first | Source byte read afterward |
|---|---|---|
| First | Initial source address plus 1 byte | Offset 0 from the initial source address |
| Second | Initial source address plus 2 bytes | Offset 1 from the initial source address |
| Third | Initial source address plus 3 bytes | Offset 2 from the initial source address |
| Fourth | Initial source address plus 4 bytes | Offset 3 from the initial source address |

Each cursor-slot write precedes the source read in its row. The source read in each row precedes the cursor-slot write in the next row.

Consequently, the cursor already denotes one byte beyond the byte being read at the time that read is attempted. If execution stops on a source access, the preceding cursor update has already occurred in the supplied operation order.

The function retains the four acquired byte values separately. It does not write a destination byte immediately after reading the corresponding source byte.

### Ordered destination writes

After acquiring all four source bytes, the function writes them to destination offsets 0, 1, 2, and 3, in that order.

Each write is one byte wide. Destination offset 0 receives the first acquired byte, destination offset 1 the second, and so forth.

There is no byte reversal, word assembly, numeric conversion, sign extension, terminator insertion, or length-dependent behavior. The four-byte payload is treated as an ordered sequence of bytes.

### Completion

After the fourth destination-byte write, the function returns without a value.

If the destination window does not overlap the cursor slot and no external modification intervenes, the cursor slot contains the initial source address plus four bytes on normal completion.

That final-cursor statement is conditional. If the destination overlaps the cursor slot, the later destination writes may replace some or all of the bytes encoding the final cursor value. The function does not restore or revalidate the cursor afterward.

### Overlapping regions

**Source and destination overlap, with the cursor slot separate:** All four source bytes are acquired before any destination-byte write. Therefore, for ordinary stable memory, destination writes cannot change the bytes collected during this call. This applies whether the destination begins before, at, or after the source address.

**Source and cursor slot overlap:** A cursor update can alter a source byte before that byte is read. The resulting payload is then the sequence actually observed after the relevant cursor writes, not necessarily the four bytes present at function entry.

The exact byte values in this case depend on the memory representation of the cursor values, including byte order. Nevertheless, the remaining source addresses still derive from the original cursor value.

**Destination and cursor slot overlap:** Destination writes occur after all four cursor updates and source reads. They can overwrite the final cursor representation in destination-offset order. This does not affect already acquired bytes.

**All three overlap:** Both effects apply. Cursor writes can influence source acquisition, and later destination writes can alter the cursor slot. No special-case path removes either effect.
