# F-c859b7b263d8

## Purpose

F-c859b7b263d8 conditionally invokes an indirect callback on an address derived from a caller-provided object and a pair of 32-bit values returned by F-4677636484bc. After the callback returns, it examines a byte through a pointer stored in the caller-provided object. A nonzero byte is cleared and forces the function’s result to zero.

The established behavior is a gated callback followed by conditional byte consumption. Interpreting the callback argument as a record address, or the byte as a pending flag, is inferred intent rather than an established data-model guarantee.

Zero is not a distinct error indication. It can result from a rejected gate, a zero callback result, or the post-callback byte-clearing path.

## Behavior

### 1. Null-input handling

The function starts with a zero result.

If the input pointer is null, processing ends immediately. The visible body does not read the global callback slot, call F-4677636484bc, invoke the indirect callback, or access either object field.

### 2. Callback capture and gate evaluation

For a nonnull input, the function first reads a callback pointer from a global slot. It captures that pointer before calling F-4677636484bc.

The callback slot is not visibly reread after that dependency returns. Consequently, a change to the slot during F-4677636484bc does not redirect the callback invocation made by this function. It does not, however, establish that the previously captured target remains valid.

After F-4677636484bc returns, processing continues only when both of these conditions hold:

1. H is less than L using signed 32-bit comparison.
2. Q is nonnegative using signed 64-bit comparison.

The first comparison is evaluated before the second condition in the supplied expression. The second condition is not a test of L alone.

Together, these conditions imply the following accepted range:

**0 ≤ H < L ≤ 2,147,483,647.**

In particular:

- A zero L cannot pass.
- Equal halves cannot pass.
- A low half whose top bit is set cannot pass.
- A high half whose top bit is set cannot pass.
- A nonnegative complete 64-bit result is necessary but not sufficient.

If the gate fails, the function returns zero. It does not visibly read the input object’s fields or invoke the indirect callback on that path. Side effects already performed by F-4677636484bc remain possible.

### 3. Callback argument construction and invocation

When the gate passes, the function reads the 32-bit field at offset 40 from the input object. Call this value **B**.

The visible address expression contains an index contribution that is initialized to zero and has not changed before use. Accordingly, L participates in gate validation but contributes no nonzero term to the callback address. The effective mathematical expression is:

**B + 40 × H.**

The multiplier is 40 bytes, not 40 input-object elements. Thus, H selects an offset in units of 40 bytes.

The expression is represented using 32-bit integer operations. No bounds check, overflow check, pointer validation, or record-size validation is visible. When the signed intermediate operations are representable, the expression above describes the argument directly. Cases involving signed 32-bit overflow are documented_only: the supplied representation does not independently settle the original execution semantics for those cases.

The function invokes the previously captured callback once, passing this derived address-like value as its single visible argument.

The low 32 bits of the callback’s result become the provisional return value. Its high 32 bits are extracted in the supplied representation, but they do not affect any final result or visible write:

- If the post-callback pointer-like field is nonzero, the high-half value is replaced by the byte read.
- If that field is zero, the later condition cannot enter the clearing branch.

No callback-success interpretation is applied before the subsequent object access. A callback result of zero still proceeds to the post-callback inspection.

### 4. Post-callback pointer and byte handling

After the callback returns, the function reads the 32-bit field at offset 0 of the input object.

This read is deliberately ordered after the callback in the visible body. If the callback changes the field, the later read observes the field as it exists after the callback, subject to the execution environment’s memory semantics.

If the field is zero:

- No byte is read through it.
- No byte is cleared.
- The provisional callback result is returned.

If the field is nonzero, the function reads one unsigned byte at offset 30 from that address.

If the byte is zero:

- No write to that byte is visible.
- The provisional callback result is returned.

If the byte is any nonzero value:

- The function selects zero as its result.
- It writes a single zero byte to the same offset-30 location.
- It returns zero.

All nonzero byte values receive the same treatment. There is no visible bit mask or preservation of individual bits.
