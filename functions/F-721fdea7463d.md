# F-721fdea7463d

The established behavior is the ordering and conditional selection of those requests. The available evidence does not establish a higher-level purpose, a normal return path, a memory ownership protocol, or the runtime meaning of the coprocessor operations.

## Behavior

### Predicate definitions

For this contract, two predicates describe the represented decisions:

- **Interrupt predicate:** the zero-condition value is true, or the negative and overflow values differ.
- **Load predicate:** the negative and overflow values are equal.

These predicates are not complements. Both are true when the zero-condition value is true and the negative and overflow values are equal.

The supplied representation refers to the same implicit condition inputs at each decision. It does not show an explicit refresh of those inputs from processor status after a dependency executes. This establishes the represented branch structure, not a guarantee about live processor flags surviving an interrupt or coprocessor operation.

### First conditional operation group

If the interrupt predicate is true, the function requests two software interrupts, both using selector **0x1DDF1D**.

Their order is sequential:

1. The first request is reached.
2. The second request is reached only if execution continues from the first.

The two requests are separate operations. They must not be collapsed into a single request or interpreted as a retry protocol without additional evidence.

If the interrupt predicate is false, the function instead issues one coprocessor transfer-like request. Its represented operands are:

- Selector **0xF**.
- Selector **5**.
- Selector **0**.
- Two of the 32-bit opaque coprocessor-related input values, in their represented argument order.

The transfer direction, actual source and destination registers, and externally visible result cannot be established solely from the operation’s descriptive label. The function shows no explicit assignment receiving a result.

The two branches of this first group are exclusive in the supplied control-flow representation.

### Conditional load-like request

After the first group, if execution continues, the function evaluates the load predicate.

When the negative and overflow values are equal, it issues a coprocessor load-like request containing:

- Selector **5**.
- The remaining 32-bit opaque coprocessor-related input value.
- An address-like expression formed by adding **0x25C**, or **604 decimal**, to the address-base input.

This request is not restricted to the non-interrupt branch. In particular, a true zero-condition value combined with equal negative and overflow values selects the first two interrupt requests and then this load-like request.

The displacement is expressed as an addition with no explicit multiplication or scaling in the supplied representation. The evidence does not establish the address unit, access size, alignment requirement, byte order, number of transfers, or architectural meaning of the operation’s “long” characterization.

There is no explicit bounds check, alignment check, mapping check, or overflow check before the request.

The expression alone does not justify specifying modular wraparound. If the addition exceeds the applicable integer or address range, its behavior remains **documented_only** pending a confirmed execution model.

When the negative and overflow values differ, this request is skipped.

### Final interrupt group

If execution continues, the function again selects on the interrupt predicate.

When it is true, the function requests four software interrupts, each using selector **0x1CDF1C**.

The requests are sequential and distinct. Each later request is reachable only if execution continues from the preceding one.

When the interrupt predicate is false, all four requests are skipped.

There is no demonstrated retry counter, success test, handler-result inspection, or early-exit condition between these requests. Their repetition is established; its purpose is unknown.
