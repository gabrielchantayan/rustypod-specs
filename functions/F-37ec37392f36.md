# F-37ec37392f36

## Purpose

F-37ec37392f36 combines an interpolated signed 16-bit source sample with two signed 16-bit input channels and writes a two-channel output frame. It selects among three gain-processing paths, advances a fixed-point source position, updates a persistent progress counter, and can terminate after a frame when a boundary condition is satisfied.

The numerical operations and two-channel layout are established by the supplied static body. Audio mixing, resampling, and playback termination are inferred purposes, not additional interface requirements.

Two independently observed reads of an external 32-bit shared value have distinct roles:

- The first read occurs before the state snapshots. Its low 16 bits supply the output pattern for positive overflow throughout the invocation.
- A second read occurs only when the two snapshotted gains are equal. This later value supplies the unsigned gain-path threshold.

The two reads are not required by the supplied evidence to return equal values. Neither read occurs inside the frame-processing loop.

Boundary termination also differs from ordinary completion: it occurs after output and progress-counter updates, but before adopting the next local source position.

## Behavior

### Entry reads and gain-path selection

The established entry-read order is:

1. Read the external shared 32-bit value for positive-overflow output.
2. Read the first-channel gain.
3. Read the second-channel gain.
4. Read the position increment.
5. Read the initial source position.

These five values become local snapshots.

The function then compares the two gain snapshots:

- **Unequal gains:** select separate gain multiplication for the two channels. No second shared-value read occurs.
- **Equal gains:** read the external shared value again, then compare the common gain against this later value using unsigned 32-bit comparison.
  - Common gain below the later value: select common-gain multiplication.
  - Common gain equal to or above the later value: select direct use of the interpolated source, without gain multiplication.

This selection precedes the first Count read. Consequently, an equal-gain call performs both shared-value reads even when Count is initially zero. An unequal-gain call performs only the first read.

The gain path remains fixed for the invocation. Later writes to gain fields or the external shared location do not change the local gain snapshots, the selected path, or the saved positive-overflow pattern.

### Loop limit and frame addressing

Before each frame, an unsigned 32-bit loop count is compared with the value currently read through Count. The requested count is not snapshotted.

The first frame uses the supplied Input and Output addresses. After each completed frame, both addresses advance by four bytes. The source address is selected independently from the current local fixed-point position.

A zero limit on the first comparison skips all frame processing, but not entry reads, path selection, or final writes.

### Source reads and interpolation

Let:

- \(p\) be the current unsigned 32-bit position.
- \(i=\lfloor p/65536\rfloor\) be its upper 16 bits.
- \(f=p\bmod65536\) be its lower 16 bits.
- \(w=\lfloor f/2\rfloor\).

The function first reads the signed 16-bit source sample at index \(i\) into a local value. Only afterward does it read the signed 16-bit sample at index \(i+1\).

Calling those values \(a\) and \(b\), the interpolated value is

\[
s=a+\operatorname{ASR}_{15}\!\left(w(b-a)\right),
\]

where \(\operatorname{ASR}_{15}\) denotes a signed arithmetic right shift by 15 bits.

The ordering is established: indexed sample first, successor second, both before the first output write.

Relevant arithmetic properties:

- \(w\) ranges from 0 through 32767.
- Fractions differing only in their least significant bit produce the same weight.
- The sample difference ranges from −65535 through 65535.
- The weighted difference fits signed 32-bit arithmetic.
- Negative shifted values round downward, not toward zero.
- The interpolated result remains within the signed 16-bit sample range.
- The successor is read even at fraction zero.

The source index ranges from 0 through 65535. The successor of index 65535 is sample 65536; it is not wrapped to sample zero.

### Gain arithmetic

The direct-use path contributes \(s\) to both channels.

Each multiplying path instead obtains a contribution by:

1. Multiplying the interpolated value by the applicable 32-bit gain.
2. Retaining the low 32 bits.
3. Interpreting those bits as a signed 32-bit value.
4. Applying an arithmetic right shift by 15 bits.

Thus multiplication is reduced to 32 bits before shifting. Replacing it with an unrestricted mathematical product followed by division would change behavior.

The common-gain multiplication path computes one contribution for both channels. The unequal-gain path applies each gain separately.

A shifted multiplication result lies between −65536 and 65535. Adding a signed 16-bit input sample therefore fits signed 32-bit arithmetic.

### Channel mixing and output order

For each channel, add the signed input sample to its source contribution. For mixed sum \(x\), select the output word as follows:

| Condition | Stored 16-bit pattern |
|---|---|
| \(x\ge32768\) | Low 16 bits of the **first** shared-value read |
| \(-32768\le x<32768\) | Low 16 bits of \(x\) |
| \(x<-32768\) | `0x8000` |

The later threshold read, when present, is not the positive-overflow output source.

The observable channel order is:

1. Read the first-channel input.
2. Write the first output word.
3. Read the second-channel input.
4. Write the second output word.

Accordingly, an output write overlapping the second-channel input can alter that later read. Exact in-place Input/Output processing preserves each channel until its own read, assuming no other relevant aliases.

### Progress update and boundary decision

After both output writes, compute the next position by unsigned 32-bit addition:

\[
q=(p+d)\bmod2^{32},
\]

where \(d\) is the increment’s 32-bit bit pattern.

The integer-position difference is

\[
\Delta=\left\lfloor q/65536\right\rfloor
       -\left\lfloor p/65536\right\rfloor.
\]

The function reads the current progress counter, adds this difference using the expression’s 32-bit arithmetic, and writes the resulting 32-bit pattern back to `0x88`. Its signed interpretation is then used by the boundary expression.

This counter is read afresh each frame. It is not an entry snapshot. Position wrap can make \(\Delta\) a large negative difference rather than a small forward displacement.

After the counter write, the completed-frame count is incremented. The function then reads the signed boundary value and tests whether it is at most the updated signed counter plus one.

Only if that comparison succeeds does it read Mode:

- Mode equal to 1 suppresses termination.
- Any other Mode value causes termination.

On boundary termination, the function writes byte value 1 to `0x8c` and proceeds to final writes without adopting \(q\). Otherwise, it replaces \(p\) with \(q\) before the next loop-limit read.

The boundary decision uses the locally computed updated counter, not another read of `0x88`. Aliasing can nevertheless affect the boundary or Mode reads because they occur after the counter write.

The boundary check never prevents the current frame’s reads or output writes. Even an already-satisfied boundary is checked only after a frame completes.

Behavior of the signed “updated counter plus one” expression at the maximum signed 32-bit value remains unresolved.

### Final writes

Every ordinary return, including zero-frame and boundary exits, performs these writes in order:

1. Write the completed-frame count through Count as 32 bits.
2. Write \(p\bmod65536\) to `0x4c` as a 32-bit value.

The saved position’s upper 16 bits are therefore always cleared.

On ordinary loop completion, the saved fraction includes the final position advance. On boundary termination, it belongs to the position used for the stopping frame.

If Count aliases the position field, the position write occurs last and determines the final overlapping bytes.
