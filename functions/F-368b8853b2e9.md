# F-368b8853b2e9

## Behavior

### Empty input

When the starting node is zero, the function returns without reading node memory or calling F-1b2e0c144326.

A recursive invocation given zero has the same behavior. Thus a zero recursive link contributes no dependency invocation and causes no link reads within that recursive invocation.

### Processing a nonzero current node

Each nonzero current-node occurrence has the following observable ordering:

1. Read the four-byte recursive reference at offset 12.
2. Invoke F-368b8853b2e9 with the same context and that reference.
3. After the recursive invocation returns, read the four-byte continuation reference at offset 8 of the current node.
4. Save that continuation value.
5. Invoke F-1b2e0c144326 with the context, the current node reference, and the constant value 1, in that argument order.
6. If the dependency returns, continue traversal using the saved continuation value.

The recursion occurs even when the recursive reference is zero; that invocation immediately returns.

The continuation is processed by the enclosing invocation’s iteration rather than by an additional recursive call. Recursive nesting therefore follows offset-12 links, while offset-8 continuation links advance the current traversal level.

### Traversal ordering

For a stable, finite, non-sharing structure, every node reachable through a current node’s recursive reference is processed before the dependency is invoked on that current node. The current node is then processed before traversal advances to its continuation.

“Processed” here means that F-1b2e0c144326 is invoked. It does not imply that the dependency succeeds, releases storage, or makes any particular state change.

There is no visited-node set, duplicate suppression, or cycle detection. The function operates on node occurrences reached through links, not on a deduplicated collection of addresses. The same node address can therefore cause multiple dependency invocations if it is reached more than once and remains usable.

### Effects of mutation during traversal

The timing of the two reads is significant.

The recursive reference is read before recursive processing begins. Later changes to that current node’s offset-12 field do not change the reference already passed into that recursive invocation.

The continuation reference is not read until recursive processing returns. Calls made during that recursion may modify the parent’s offset-8 field, and the enclosing invocation then reads the resulting value. Traversal is therefore not based on an entry-time snapshot of both links.

Conversely, the continuation is saved before F-1b2e0c144326 is invoked on the current node. A change that this dependency makes to the current node’s offset-8 field does not replace the saved next reference. Such a change may still matter if some later traversal reaches the node again.

Neither rule guarantees that the saved destination remains valid. A dependency may alter or invalidate memory associated with a pending reference. The function contains no visible revalidation.

With stable links, a cycle consisting of continuation links can prevent the enclosing iteration from ending. A cycle reached through recursive links can cause unbounded recursive nesting. Mixed-link cycles can likewise revisit nodes or prevent completion.

An invalid memory access, exhausted stack, or dependency failure has no defined recovery behavior in the supplied evidence.
