# F-a96698e403cf

## Purpose

F-a96698e403cf selects one of four fixed sequences of dependency calls and direct 16-bit memory accesses. Supported selectors return zero after completing their sequence. Every other selector returns decimal 19 without making a dependency call or directly writing memory.

The call patterns suggest configuration, activation, saved-state capture, and restoration. Those descriptions are **inferred intent**, not established device semantics. The established behavior is the ordered calls, literal arguments, memory transfers, and return values described below.

Two calls expose only one argument to a dependency that elsewhere receives two. Their second-argument behavior is unresolved and must not be filled in by assuming zero, a recently stored field, or a previous argument.

## Interface

### Input

One 32-bit integer selector, compared for exact equality with 1, 2, 3, and 4.

The function does not interpret the selector as a bitmask or range. Negative values and values greater than 4 take the unsupported-selector path.

### Output

A 32-bit result:

| Selector | Result on normal completion |
|---|---:|
| 1 | 0 |
| 2 | 0 |
| 3 | 0 |
| 4 | 0 |
| Every other value | 19 |

Dependency return values are not inspected or propagated. “Normal completion” assumes that every invoked dependency returns and that each required memory access completes.

### Global inputs and memory layout

The following descriptive labels identify storage roles, not additional API parameters:

| Label | Role |
|---|---|
| **Primary-base slot** | Global storage containing the address of a structure or memory-mapped region. |
| **Auxiliary-value slot** | Global scalar storage supplying one argument during selector 1. |
| **Copy-source slot** | Global storage containing the base address used for two selector-3 reads. |
| **Copy-destination slot** | Global storage containing the destination address used during selector 3. |

Immediately on entry, before testing the selector, the function reads the primary-base slot and retains that address as the **entry base**. Subsequent dependency calls do not cause this retained address to be refreshed.

The directly accessed fields are:

| Base | Byte offset | Access width | Use |
|---|---:|---:|---|
| Entry base | 4 | 16 bits | Written by every supported selector. |
| Fresh primary-base value | 6 | 16 bits | Read by selector 4. |
| Entry base | 8 | 16 bits | Read and masked by selector 4. |
| Copy-source base | 50 | 16 bits | First selector-3 source value. |
| Copy-source base | 52 | 16 bits | Second selector-3 source value. |
| Copy destination | 0 | 16 bits | First selector-3 destination. |
| Captured copy destination | 2 | 16 bits | Second selector-3 destination. |

Offsets are in bytes. No larger enclosing structure layout is established.

The address operations are represented through a 32-bit integer/address model in the supplied evidence. A valid execution requires addresses and offsets to resolve to accessible storage with whatever alignment the target requires. Endianness is not established; the contract describes 16-bit values rather than their byte ordering.

## Behavior

### Common entry and completion rules

The first established operation is the primary-base-slot read that produces the entry base. This happens even for an unsupported selector.

For supported selectors, dependency calls and direct accesses occur in the order below. A later operation is reached only if earlier operations complete. There is no visible retry, rollback, or dependency-status check.

The sequences do not establish atomicity. Dependencies may modify shared storage, including any of the global slots or addressed fields. Accordingly, the distinction between the entry base, freshly loaded bases, and a captured copy destination is observable.

### Selector 1

The function performs this sequence:

1. Calls **F-000000000001** with the ordered arguments `(6, 0, 1)`.
2. Calls **F-7a15737ebecd** with `(6, 1)`.
3. Calls **F-34ea75d5d6e0** with no supplied arguments.
4. Calls **F-86393e9907da** with `(25, 192)`.
5. Calls **F-86393e9907da** with `(7, 66)`.
6. Writes the 16-bit value 96 at entry-base offset 4.
7. Calls **F-86393e9907da** with `(26, 480)`.
8. Reads the auxiliary-value slot and supplies its value as the second argument of **F-86393e9907da**, whose first argument is 34.
9. Calls **F-86393e9907da** with `(37, 288)`.
10. Calls **F-86393e9907da** with `(36, 3)`.
11. Calls **F-2cf379ad0812** with `(67, 8, 8)`.
12. Calls **F-86393e9907da** with `(24, 256)`.
13. Calls **F-2cf379ad0812** with `(24, 4, 4)`.
14. Calls **F-2cf379ad0812** with `(27, 64, 64)`.
15. Returns zero.

The write at offset 4 uses the entry base even if an earlier dependency changed the primary-base slot.

The auxiliary value is read at its position in this sequence, not cached on entry. Earlier dependency effects may therefore affect the argument supplied at step 8. Its signed interpretation and declared storage type are not established.

### Selector 2

The function:

1. Calls **F-2cf379ad0812** with `(5, 8, 8)`.
2. Calls **F-86393e9907da** with `(25, 0)`.
3. Writes the 16-bit value zero at entry-base offset 4.
4. Calls **F-86393e9907da** with the sole explicitly recoverable argument `26`.
5. Returns zero.

The call in step 4 does not establish a second argument. In particular, the immediately preceding zero write does not establish that the call receives zero as an additional argument.

### Selector 3

Selector 3 performs a copy phase, then the same trailing sequence used by selector 2:

1. Calls **F-2cf379ad0812** with `(5, 8, 8)`.
2. Reads the copy-destination slot and retains its address as the **captured copy destination**.
3. Reads a 16-bit value at offset 50 from the base obtained through the copy-source slot, and writes it to offset 0 of the destination obtained through the copy-destination slot.
4. Reads a 16-bit value at offset 52 from a base obtained through the copy-source slot, and writes it at offset 2 of the captured copy destination.
5. Calls **F-2cf379ad0812** again with `(5, 8, 8)`.
6. Calls **F-86393e9907da** with `(25, 0)`.
7. Writes the 16-bit value zero at entry-base offset 4.
8. Calls **F-86393e9907da** with the sole explicitly recoverable argument `26`.
9. Returns zero.

There are **two** calls with `(5, 8, 8)`, separated by the copy phase. They are not a single operation and cannot be collapsed in a behavior-preserving account.

The first destination is obtained through the global destination slot; the second uses the address captured before the first transfer. Likewise, the two source accesses obtain their bases through the source slot rather than establishing one retained source base for both transfers.

The first 16-bit transfer completes before the second source read. This is not an atomic 32-bit copy or a snapshot of both source values. If destination storage overlaps the second source location, the first write can affect the value subsequently read.

Within the first transfer, the evidence does not establish the relative evaluation order of the source-base-slot read and the destination-slot read. It does establish that the source value must be obtained before it is written.

### Selector 4

The function:

1. Reads the primary-base slot again and reads the 16-bit value at offset 6 from that freshly obtained base.
2. Calls **F-86393e9907da** with first argument 25 and that value as the second argument.
3. Reads the 16-bit field at entry-base offset 8.
4. Applies the mask 120, hexadecimal `0x0078`, and writes the resulting 16-bit value at entry-base offset 4.
5. Calls **F-86393e9907da** with the sole explicitly recoverable argument `26`.
6. Calls **F-2cf379ad0812** with `(5, 8, 0)`.
7. Returns zero.

The offset-6 read and the offset-8 read need not use the same base. The former uses a fresh primary-base-slot read; the latter uses the entry base.

The offset-8 read occurs after the call with first argument 25. Any change that dependency makes to the field at entry-base offset 8 can therefore influence the masked result.

The mask retains only bit positions 3 through 6 of the 16-bit value and clears all other positions. The result is between 0 and 120 inclusive. There is no addition, multiplication, saturation, or carry-producing arithmetic in this transformation.

### Unsupported selectors

After reading the primary-base slot, the function returns 19.

It makes no dependency call and performs no direct access through the loaded base. Consequently, an invalid pointee is not itself dereferenced on this path, although the primary-base slot must still be readable.

## Side effects

### Direct memory effects

On normal execution:

- Selector 1 writes one 16-bit field at entry-base offset 4.
- Selector 2 writes one 16-bit field at entry-base offset 4.
- Selector 3 performs two ordered 16-bit destination writes, then writes the field at entry-base offset 4.
- Selector 4 writes a masked 16-bit value at entry-base offset 4.
- Unsupported selectors perform no direct writes.

These are direct effects only. A dependency may produce additional writes, device effects, synchronization, or other externally observable behavior.

A direct write is not necessarily the final value observed after the function returns. Later dependencies may overwrite the same storage. Aliasing may also make one listed write affect another listed storage role.

### Ownership and lifetime

The function contains no explicit allocation, release, ownership transfer, or retention of a caller-provided object. It has no pointer parameter; addresses come from global storage.

This does not establish ownership behavior inside dependencies. No assumption is made that they preserve globals, leave memory allocated, or keep the entry-base region valid.

### Errors and partial execution

The only explicit status distinction is zero versus 19.

No visible mechanism handles inaccessible memory, invalid addresses, dependency failure, or a dependency that does not return. An interrupted supported sequence may leave its earlier calls and writes observable. No rollback is established.

## Acceptance examples

These are conditional static acceptance examples, not reports of executed tests.

### Unsupported input

Given selector 0 and a readable primary-base slot:

- The slot is read once.
- No dependency is called.
- No access is made through the loaded base.
- The result is 19.

The same behavior applies to selector −1 or 5.

### Selector 1 with stable storage

Assume all dependencies return normally, preserve the relevant global slots, and do not overwrite the directly written field. If the auxiliary-value slot supplies `0x1234`:

- The call at position 8 is **F-86393e9907da** with `(34, 0x1234)`.
- Entry-base offset 4 becomes the 16-bit value 96.
- The final dependency call is **F-2cf379ad0812** with `(27, 64, 64)`.
- The result is zero.

Without the no-overwrite assumption, the direct write of 96 remains required, but a final field value of 96 is not guaranteed.

### Selector 2 with a changed global base

Suppose the first dependency changes the primary-base slot from address A to address B, while leaving A valid:

- The subsequent direct zero write still targets A plus 4.
- The function does not redirect that write to B plus 4.
- The call following the write has only argument 26 explicitly established.

### Selector 3 with stable, nonoverlapping storage

Suppose the source fields at offsets 50 and 52 contain `0x1234` and `0xABCD`, respectively, and all relevant storage remains stable:

- The destination receives `0x1234` at offset 0.
- It then receives `0xABCD` at offset 2.
- Both calls to **F-2cf379ad0812** with `(5, 8, 8)` occur.
- Entry-base offset 4 is subsequently written with zero.

### Selector 3 with overlapping storage

Suppose the first destination is exactly the second source field, the source base remains stable, and the two original source values differ:

- The first transfer overwrites the second source field.
- The second transfer reads that overwritten value.
- Both destination transfers therefore use the original first source value.

An implementation that first snapshots both source fields would not satisfy this ordering.

### Selector 4 masking

If the field read at entry-base offset 8 is `0xFFFF`, the direct write at offset 4 is `0x0078`.

If that source field is `0x0087`, the direct write is zero.

If the preceding dependency changes that field before returning, the mask applies to the changed value, not an entry-time snapshot.
