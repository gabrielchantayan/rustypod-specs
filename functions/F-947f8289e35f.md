# F-947f8289e35f

## Purpose

F-947f8289e35f constructs or updates a destination object from a source object. For three recognized source categories, it compares the source’s associated value with a category-specific marker. A zero comparison result selects a replacement value obtained through two dependencies. Other categories, and recognized categories with a nonzero comparison result, take a fallback path.

The established behavior is a dispatch, comparison, replacement, and destination-update sequence. Interpreting the replacements as localized phone labels is **inferred intent**, not an established dependency contract.

The routine returns the original destination pointer on every visible normal-return path. Its return value does not distinguish replacement from fallback.

## Interface

**Inputs**

- **Destination:** a pointer to writable storage.
- **Source:** a pointer to storage containing at least three consecutive 32-bit words:
  - Offset 0: a word not directly read by this routine.
  - Offset 4: an associated value passed to dependencies.
  - Offset 8: the category discriminator.

Offsets are byte offsets in the supplied 32-bit-word representation. The destination receives direct writes at offsets 0 and 4 on some paths. Dependency requirements may demand additional accessible storage.

The source’s category discriminator is read as a 32-bit quantity. Exact values 1, 2, and 8 are recognized. All other bit patterns select fallback without invoking the comparison dependency. No arithmetic is performed on the discriminator, so signed versus unsigned interpretation does not change this dispatch.

The associated source value, category-specific replacement selector, dependency results forwarded as values, and destination metadata are each represented as one 32-bit word in the supplied evidence. Their semantic types are unknown: they may be pointers, handles, identifiers, or another representation.

**Output**

On normal completion, the result is exactly the destination pointer supplied by the caller.

The routine does not visibly allocate a separate destination, return a status code, or return a null pointer to report failure. Dependencies may allocate or fail, but those behaviors are not established here.

**Preconditions**

- The source category word must be readable when entry execution reaches its initial read.
- On a recognized-category path, the source associated-value word must be readable when preparing the comparison call.
- The destination’s first word must be writable on every normal path.
- The destination’s second word must be writable on the replacement path and on fallback when the two pointers differ.
- All invoked dependencies’ preconditions must also hold; those preconditions are undocumented here.

There is no visible null-pointer check, bounds check, alignment repair, or storage-capacity check. Invalid pointers or inadequate storage are outside the established safe-use contract.

Pointer identity is explicitly tested on fallback. Distinct pointers are not tested for overlapping storage.

## Behavior

### Category selection

The first explicit source-field read obtains the 32-bit discriminator at offset 8.

The selected category determines both a comparison marker and a corresponding 32-bit value loaded from global storage:

| Discriminator | Comparison marker | Selected global value |
|---|---|---|
| 2 | `<<<cell_phone>>>` | Cell-category selector |
| 1 | `<<<home_phone>>>` | Home-category selector |
| 8 | `<<<work_phone>>>` | Work-category selector |

These selector names describe their roles in this contract; they do not establish their numeric values or meanings.

For a recognized category, the selected global selector value is captured before the comparison dependency is invoked. Consequently, a later change to that global by a dependency does not cause the routine to reload the selector for the current invocation.

For every unrecognized discriminator, execution proceeds directly to fallback. No comparison marker or category selector is used on that path.

### Comparison for recognized categories

For a recognized category, the routine reads the source associated value at offset 4 and calls **F-634a31ef9eb5** with:

1. That associated value.
2. The selected category marker.

Only the distinction between zero and nonzero in the returned 32-bit result controls the next step:

- Zero selects replacement.
- Any nonzero result selects fallback.

The evidence does not establish that this dependency is an ordinary string-comparison function. In particular, it does not establish encoding, case sensitivity, input termination requirements, or the meaning of a nonzero result beyond branch selection.

The routine does not reread the source discriminator after this call. A dependency-induced category change therefore does not alter the already-selected marker or replacement selector for this invocation.

### Replacement path

When the comparison returns zero, the following operations occur in order:

1. **F-9d0ecc5f6adf** is called without explicit arguments.
2. Its result and the previously captured category selector are passed to **F-c0b020cd3882**, in that order.
3. The resulting 32-bit value is retained for the final dependency call.
4. The routine reads the replacement-path metadata value from global storage and writes it into the destination’s first word.
5. The destination’s second word is set to the 32-bit value zero.
6. **F-151ab4bfe553** is called with the destination pointer and the retained replacement value.
7. The destination pointer is returned if the dependency returns normally.

The replacement-path metadata global is read after the two value-producing calls, not captured alongside the category selector. This distinction matters if dependencies can mutate global state.

There is no pointer-identity exemption on this path. When source and destination are the same pointer, the destination’s first two words are still explicitly overwritten before the final dependency call.

The routine makes no explicit source-field read after a zero comparison result. Nevertheless, dependencies may access the source indirectly through shared state or through values already passed to them.

### Fallback path

Fallback is selected either by an unrecognized category or by a nonzero comparison result.

The routine first reads the fallback metadata value from global storage and writes it to the destination’s first word. Only after that write does it test whether the destination and source pointers are identical.

If the pointers are identical:

- The routine returns the destination immediately.
- It does not explicitly clear the destination’s second word.
- It does not invoke **F-151ab4bfe553** on this fallback path.

If the pointers differ:

1. The destination’s second word is set to zero.
2. The source’s associated value at offset 4 is read.
3. **F-151ab4bfe553** is called with the destination pointer and that source value.
4. The destination pointer is returned if the dependency returns normally.

For recognized categories whose comparison returns nonzero, the fallback source-value read is a fresh read after the comparison call. It need not equal the value previously passed to the comparison dependency if that dependency changed the source or related storage.

Likewise, fallback metadata is read after the comparison call on recognized-category fallback. The routine does not assume that the comparison dependency preserves globals.

### Pointer identity and overlap

The fallback identity check prevents explicit second-word initialization and the final dependency call only when the two pointer values are exactly equal. It does not prevent the first-word metadata write.

For different but overlapping pointers, explicit writes occur before the fallback associated-value read. Such writes can change the value subsequently read from the source. The supplied evidence does not establish that partial overlap is supported, forbidden, or safe for the final dependency.

Exact identity and partial overlap therefore must not be treated as equivalent cases.

## Side effects

**Established direct writes**

- Every normal path writes the destination’s first 32-bit word:
  - Replacement uses one global metadata value.
  - Fallback uses a separately identified global metadata value.
- Replacement always writes zero to the destination’s second word before invoking the final dependency.
- Fallback does the same only when destination and source differ.

The numeric metadata values, and whether the two globals contain equal or different bits, are not supplied.

There are no explicit writes to the source through the source pointer. This does not imply source immutability: destination aliasing and dependency behavior may modify source storage.

The routine does not explicitly initialize or copy the destination’s third word. The source discriminator is used for dispatch, not directly copied into destination storage.

**Dependency-mediated effects**

The final dependency may further change the destination. Consequently, the explicit zero written at offset 4 is an intermediate state, not a guaranteed final postcondition.

No dependency’s effects on globals, referenced objects, memory ownership, or external state are established. A final-state claim must distinguish this routine’s direct writes from subsequent dependency effects.

**Ownership**

There is no visible allocation, deallocation, retain, release, or ownership-transfer operation whose semantics are independently established.

In particular:

- Clearing an existing destination word is not evidence that its previous referent is released.
- Passing a source-associated value to the final dependency is not evidence of copying, retaining, borrowing, or transferring ownership.
- The replacement-producing dependency’s result has no established lifetime.
- The pointer-identity branch is not sufficient evidence of general alias safety.

**Errors and interruption**

No dependency result is checked for an error condition except the comparison result’s zero/nonzero branch. The result of **F-c0b020cd3882** is forwarded to the final dependency without a visible validity check.

If a dependency fails to return normally, the final destination-pointer return is not guaranteed. There is no visible rollback. In particular, interruption during the final dependency occurs after destination metadata and, on applicable paths, its second word have already been written.

## Acceptance examples

These are conditional acceptance criteria derived from static evidence, not results of executed tests.

### Recognized category with zero comparison

Given a valid source with discriminator 2, if **F-634a31ef9eb5** returns zero:

- It receives the source-associated value and `<<<cell_phone>>>`.
- The cell-category selector is captured before that comparison call.
- **F-9d0ecc5f6adf** is called, followed by **F-c0b020cd3882**.
- Replacement metadata and then zero are written to the destination’s first two words.
- **F-151ab4bfe553** receives the destination and the replacement-producing call’s result.
- Normal completion returns the original destination pointer.

Discriminators 1 and 8 follow the same contract with their respective markers and selectors.

### Recognized category with nonzero comparison

Given discriminator 1 and different source and destination pointers, if the comparison returns any nonzero value:

- Neither replacement-producing dependency is called.
- Fallback metadata is written, followed by zero in the destination’s second word.
- The source-associated value is read again after those writes.
- That newly read value is passed to **F-151ab4bfe553**.

A negative comparison result and a positive comparison result both select this fallback behavior.

### Unrecognized category

Given discriminator 0, or any value other than 1, 2, and 8:

- The comparison dependency is not called.
- The replacement-producing dependencies are not called.
- Fallback executes according to pointer identity.

### Identical pointers on fallback

Given identical source and destination pointers and an unrecognized category:

- The first word is replaced with fallback metadata.
- The second word is not explicitly changed.
- The final dependency is not called.
- The same pointer is returned.

This is not a whole-object no-op because the first word is written.

### Identical pointers on replacement

Given identical pointers, a recognized category, and a zero comparison result:

- Both replacement-producing calls occur.
- The first word is written with replacement metadata.
- The second word is cleared.
- The final dependency is invoked despite pointer identity.

### Dependency mutation between reads

If a recognized-category comparison returns nonzero after changing the source-associated value, and no intervening aliasing write changes it again, the final dependency receives the changed value.

If that comparison instead returns zero after changing the category-selector global, the replacement-producing call still receives the selector captured before the comparison.

## Uncertainties

The following remain **documented_only**:

- Concrete metadata and category-selector values.
- Complete object layouts and required allocation sizes.
- Pointer representation beyond what the supplied 32-bit-word accesses establish.
- Dependency semantics, ownership rules, and error behavior.
- Marker encoding and comparison rules.
- Whether callers permit overlapping objects.
- Thread safety, reentrancy, and synchronization of shared globals.
- Whether these operations implement localization, placeholder substitution, or another application-level policy.

The marker vocabulary and two-stage replacement lookup suggest human-readable phone-category substitution. That interpretation is **inferred intent** and must not replace the observed zero/nonzero decision rule.
