# F-0b7cac069844

## Purpose

F-0b7cac069844 transforms a 32-bit numeric value according to object-level control bits, a selector, and optional reference values stored in a selected record.

Established behavior includes:

- An enable bit that bypasses numeric transformation when clear.
- Different transformation rules depending on the selector and control bits.
- Optional reuse of a nearby reference value.
- Quantization using 64-unit boundaries.
- Restoration of the input’s original sign after transformation.

The constants and boundary rules suggest a magnitude-adjustment or snapping operation. That interpretation is inferred intent, not an established application-level meaning. No unit, domain, or semantic meaning for the numbers is supplied.

The function returns a 32-bit bit pattern. It does not report errors separately and contains no explicit memory writes or calls to other functions.

## Behavior

### Initial reads and disabled behavior

The function first reads the object’s control word and its record-array address, then forms the selected-record address.

Only after those operations does it inspect the enable bit.

If control bit `0x04` is clear:

- The numeric input is returned unchanged, bit for bit.
- No selected-record field is read.
- The record-array address field has nevertheless already been read.

Consequently, disabling transformation does not remove the requirement that the object fields themselves be readable.

### Sign handling

When transformation is enabled, the function records whether the numeric input is negative under signed-32-bit interpretation.

For a negative input, it negates the input before applying the main transformation. For ordinary negative values, this produces their positive magnitude.

After the transformation, the function negates the computed result if the original input was negative. This is arithmetic negation, not a sign-bit insertion.

The input encoding `0x80000000` is exceptional: a positive magnitude of \(2^{31}\) is not representable as a signed 32-bit integer. Under wrapping bit-pattern interpretation, its negation retains the same encoding, and later signed comparisons still see it as negative. Ordinary magnitude-based descriptions do not apply to that case.

For the remainder of this section, “working value” means the value after this initial sign handling.

### Mode selection

The function chooses between two modes:

- For selector exactly 1, control bit `0x02` selects reference-search mode.
- For every other selector, control bit `0x01` selects reference-search mode.

When the applicable bit is clear, the function uses the limited-adjustment mode below.

### Limited-adjustment mode

This mode first reads the selected record’s signed count.

If the count is zero, the function does not read a reference value and proceeds directly to fallback adjustment.

If the count is nonzero, including negative, the function reads the first reference value. It accepts that reference when the following unsigned-32-bit expression is at most 78:

\[
(\text{working value} - \text{first reference} + 39) \bmod 2^{32}
\]

For ordinary nonwrapping values, this corresponds to an inclusive difference range of −39 through +39. The modular expression, rather than an unbounded absolute-distance test, is the established rule.

When the first reference is accepted:

- If its signed interpretation is below 48, the transformed value becomes 48.
- Otherwise, the transformed value is the reference itself.

No later reference entries are inspected in this mode.

When the count is zero or the first reference is rejected, fallback adjustment applies:

1. **Working value signed-less-than 54:**  
   Add half of the signed difference between 54 and the working value, with division truncating toward zero.

   For ordinary nonnegative inputs below 54, this moves the value halfway toward 54 without necessarily reaching it.

2. **Working value from 54 through 191:**  
   Divide the bit pattern into a 64-unit-aligned base and a remainder from 0 through 63.

   - Remainders 10 through 21 become 10.
   - Remainders 42 through 53 become 54.
   - All other remainders remain unchanged.

   The result is the aligned base plus the resulting remainder.

3. **Working value signed-at-least 192:**  
   Leave it unchanged.

The original sign is restored after either accepted-reference handling or fallback adjustment.

### Reference-search mode

#### Reference selection

The function initializes its selected candidate to the working value and its best-distance threshold to 98.

It then scans entries beginning at index zero. Before each iteration, it reads the record’s signed count and continues only while the current index is signed-less-than that count.

For each scanned reference:

- It subtracts the reference from the working value as a 32-bit difference.
- It interprets that difference as signed.
- If negative, it negates the difference.
- It replaces the candidate only if the resulting signed distance is strictly less than the current threshold.

For ordinary values without signed-distance overflow, this has the following consequences:

- Only references at distance below 98 can initially replace the working value.
- Distance exactly 98 is excluded.
- Equal-distance later references do not replace the earlier selected reference.
- A zero or negative count causes no entry reads.
- If no reference qualifies, the candidate remains the working value.

The absolute-distance interpretation has an exception when the difference encoding is `0x80000000`. Under wrapping negation it remains signed-negative, making it compare below the initial threshold and all ordinary nonnegative distances. This is not safely describable as mathematical absolute distance.

#### Candidate adoption window

Selecting a candidate does not necessarily cause the working value to adopt it.

The function forms a boundary by adding 32 to the candidate with 32-bit wrapping and clearing its low six bits. For ordinary nonnegative candidates this is nearest-64 rounding, with midpoint values rounded upward.

It then uses signed comparisons:

- If the working value is below the candidate, adoption requires the working value to be strictly above the boundary minus 48.
- Otherwise, adoption requires the working value to be strictly below the boundary plus 48.

The endpoint comparisons are strict. Arithmetic for the boundary and its offsets is 32-bit arithmetic.

If adoption succeeds, the working value becomes the candidate. Otherwise, the working value retains its previous value.

#### Final quantization for selector exactly 1

After candidate handling:

- A working value signed-less-than 64 becomes 64.
- Otherwise, add 16 and clear the low six bits.

The original input sign is then restored.

Control bit `0x08` does not affect this selector’s behavior.

#### Final quantization for other selectors

If control bit `0x08` is clear:

- Below 48 by signed comparison: add 64, interpret the result as signed, and arithmetic-right-shift by one.
- From 48 through 127: add 22 and clear the low six bits.
- At least 128 by signed comparison: add 32 and clear the low six bits.

If control bit `0x08` is set:

- Below 64 by signed comparison: produce 64.
- Otherwise: add 32 and clear the low six bits.

The original input sign is restored afterward.

These intervals describe ordinary nonnegative working values. Wrapped intermediate values remain governed by the specified bit-pattern arithmetic and signed comparisons.
