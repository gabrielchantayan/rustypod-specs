# F-e646991e34b1

## Purpose

F-e646991e34b1 processes a message-like record against a receiver object. It recognizes two discriminator values, performs narrowly defined receiver-specific actions, and otherwise delegates processing to F-147f81afa77f.

The established behavior has three principal paths:

- Discriminator **15**, with a pointer-valued field matching a particular embedded receiver address: write a one-byte flag, invoke F-936a8728139d on that embedded address, and return **1**.
- Discriminator **19**: obtain another record through an indirect call, compare a field in that record with a receiver field, conditionally invoke a receiver callback, then independently compare the record field with **32384** and potentially invoke the callback again.
- All other cases, including discriminator 15 with a mismatching pointer: return the result of F-147f81afa77f.

“Message,” “receiver,” “flag,” and “callback” are descriptive terms, not established application-level meanings. The supplied evidence does not identify the surrounding protocol or the semantic meaning of either recognized discriminator.

## Behavior

### Discriminator selection

The function first reads the message discriminator and compares it with **15**.

If that comparison succeeds, it examines the message’s pointer-valued field at offset `0x08`. The discriminator-19 branch is not considered on this path.

If the first comparison fails, the supplied representation evaluates the discriminator again for comparison with **19**. It does not explicitly retain one discriminator value for both tests. Thus, the represented access sequence contains a second discriminator evaluation on the non-15 path. This does not establish compiled behavior for volatile memory, concurrent mutation, or memory-mapped devices.

### Discriminator 15 with matching embedded address

The message’s pointer-valued field must equal the address at receiver offset `0x16C`.

This is address equality. There is no comparison of the contents at either address and no dereference of the message’s pointer-valued field for this check.

On equality, the observable local sequence is:

1. Write the value **1** into the single byte at receiver offset `0xA8`.
2. Invoke F-936a8728139d with the address at receiver offset `0x16C`.
3. If that invocation returns normally, return **1**.

The write precedes the dependency call. The source does not write the surrounding bytes as part of this assignment.

The dependency’s return value is not used. The function does not clear the byte afterward or verify its value after the call. Consequently, the byte is known to receive 1 before the call, but its value at function return is not established without a contract for the dependency.

### Discriminator 15 with a different address

If the pointer-valued field does not equal the embedded receiver address, the function calls F-147f81afa77f with the receiver and message addresses, in that order, and returns its result.

This path does not perform the local one-byte write and does not invoke F-936a8728139d.

### Discriminator 19: obtaining the comparison record

On this path, the supplied representation initializes an intermediate address value to zero and conditionally performs the message-side indirect call if the message address is non-null.

That null comparison does not make a null message valid: discriminator reads have already occurred. Moreover, if the indirect call is skipped, the subsequent access still uses offset `0x0C` from the zero intermediate address.

For a non-null message, the function obtains the indirect target from its dispatch table at offset `0x14` and calls it with:

- the message address;
- the integer **3072**.

The result is used as the base address for later field reads. There is no explicit validation of the returned address, no error-code branch, and no fallback for a null or otherwise unusable result.

### First comparison and callback

The function reads the four-byte field at offset `0x0C` from the accessor result and compares it with the receiver’s four-byte field at offset `0x44`.

It retains the Boolean outcome of this comparison for the eventual return value. The supplied expression does not establish a relative evaluation order between the two operand reads.

If they compare equal, the function obtains the receiver callback from the receiver’s current dispatch table at offset `0xD4` and invokes it with the receiver address.

If they differ, that callback invocation is skipped.

### Second comparison and callback

After the optional first callback returns, the function reads the field at offset `0x0C` from the accessor result again and compares it with **32384** (`0x7E80`).

This is a fresh field read. It is not a comparison against the value retained from the first read. A callback that changes the record can therefore change the outcome of this second comparison.

If the second read equals 32384:

- the receiver callback target is obtained again from the receiver’s dispatch table;
- that target is invoked with the receiver address;
- the function returns **1**, provided the call returns normally.

Otherwise, the function returns the first comparison’s retained Boolean as unsigned **0** or **1**.

The receiver comparison field is not read again to determine this return value. Changes to that field during a callback do not retroactively change the retained Boolean.

This path never delegates to F-147f81afa77f, even when neither comparison matches.

### All other discriminators

If neither discriminator branch is selected, the function invokes F-147f81afa77f with both original input addresses and returns its result.

There is no local conversion of that result into a handled/unhandled Boolean.

## Side effects

The only explicit local memory write is the one-byte assignment at receiver offset `0xA8` on the matching discriminator-15 path.

Other effects arise through calls:

- F-936a8728139d is called once on that matching path.
- The message-side indirect target is called once on a normally traversed, non-null discriminator-19 path.
- The receiver callback is called zero, one, or two times on discriminator 19.
- F-147f81afa77f is called once on a delegated path.

Two receiver callback calls are possible because the comparisons are independent. If the first comparison succeeds and the second read equals 32384, both calls occur.

Each receiver callback dispatch is resolved separately. If the first callback changes the receiver’s dispatch-table pointer or relevant table entry, the second invocation can target a different function.

The function does not establish that callees preserve receiver memory, message memory, the accessor result, dispatch tables, globals, or resource ownership. In particular, use of the accessor result after the first receiver callback requires that the later field read remain valid. The function performs no explicit lifetime check or reacquisition.

No local recovery, rollback, or conversion of call failures into a status result is shown. Every stated post-call action is conditional on the preceding call returning normally.
