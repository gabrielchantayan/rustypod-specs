# F-b090a72e8f4b

## Purpose

F-b090a72e8f4b conditionally resolves a supplied 32-bit value, applies a value derived from the resolution result to an object, constructs a temporary descriptor, and optionally submits an operation.

An object byte selects an abbreviated path that only stores the supplied value. On the full path, a mode result of exactly `8` suppresses submission but does not suppress descriptor construction or normal-completion work.

When submission requires a 16-bit object field, its displacement is obtained by reading a global data location at that stage. This is a runtime read, not an established constant: earlier dependencies, including the immediately preceding context query, may change the displacement.

The evidence establishes these operations and their ordering, not their domain meaning. “Object,” “resolved entry,” “context,” and “descriptor” describe observed roles rather than confirmed semantic types.

### Preconditions

Every direct access actually reached must address storage readable or writable for the indicated width. Requirements are branch-specific:

- Every invocation needs a readable selector byte at `0x110`.
- The abbreviated path needs a writable 32-bit destination at `0x108`.
- The full path needs a writable byte at `0x10C` and, if reached, readable fields in the first two acquired contexts.
- Normal full-path completion needs a writable 32-bit destination at `0x108`.
- Only the eligible submission branch needs readable storage for the global displacement and the resulting 16-bit object field.

The global displacement and resulting field need not be readable for this function’s direct accesses when the mode is `8`, the selection argument is nonzero, or the operation argument is zero. Dependencies may impose additional requirements independently.

No explicit null, bounds, alignment, or address-overflow checks are shown. Dependency-specific preconditions remain unknown.

## Behavior

### Initial selector and abbreviated path

The first direct access reads the byte at object offset `0x110`.

If that byte is nonzero, the function writes the supplied 32-bit value at object offset `0x108` and returns. It does not directly write `0x10C`, call any listed dependency, or construct or finalize a descriptor.

If the byte is zero, execution enters the full path. The selector is not read again; later changes to that byte do not cause this function to reconsider the path.

### Resolution and application

On the full path, the byte argument is first written at object offset `0x10C`.

F-1f46730b1ced is then called with:

1. The address at object offset `0xD8`.
2. The supplied 32-bit value.

Its result is represented as a 32-bit address-like value. A zero result selects a call to F-a817d8d58c10.

The supplied representation marks F-a817d8d58c10 as non-returning. Under that stated control-flow property, execution ends there: the earlier byte write remains observable, but no descriptor is constructed and no final supplied-value store occurs. There is no visible rollback.

That non-returning property is not independently verified by a dependency body. If the dependency unexpectedly returns, the shown function contains no explicit return immediately after the call; such behavior is outside the stated non-returning assumption.

For a nonzero resolution result, the following calls occur in order:

1. F-d2f99870cc43 receives the resolved entry and produces a 32-bit value.
2. F-bf557f07179f receives the object address and that derived value.
3. F-fa8898fa75ae receives the resolved entry.

No result from the latter two calls is used. The original resolved entry remains available as a later submission argument. This reuse does not establish its ownership or prove that F-fa8898fa75ae preserves its lifetime; the necessary dependency contract is unavailable.

### Descriptor construction from separate observations

After those calls return normally:

1. F-fdd8589eca2d is called.
2. A byte is read at offset `0x2C` from its returned address and retained.
3. F-fdd8589eca2d is called again.
4. A 32-bit value is read at offset `0x28` from this second returned address.
5. F-2c5a9f9c1eb3 is called with the local storage address, the second context’s 32-bit value, and the retained byte, in that order.

The two context acquisitions are distinct observable calls. They may return different addresses or observe different state. The byte is read before the second acquisition, so changes made by the second call do not replace that retained byte.

There is no visible initialization of the local storage before F-2c5a9f9c1eb3 receives it. Any initialization needed by later dependencies must follow from dependency behavior, not from direct writes established here.

### Mode and submission eligibility

After descriptor construction, F-5c5958cfd5fe is called. Its represented 32-bit result is compared with exactly `8`.

If the result equals `8`, submission is skipped. There is:

- No third context acquisition.
- No read of the global displacement.
- No read of the displacement-selected 16-bit object field.
- No call to F-818c773e8c8a.

Resolution, application, and descriptor construction have already occurred. Execution proceeds to normal completion.

For every other mode result, a third call to F-fdd8589eca2d occurs. Its result is retained as the first submission argument.

The selection argument is tested before this third call:

- If selection is nonzero, the third context acquisition occurs and the selected 16-bit value is zero.
- If selection is zero, the third context acquisition occurs before the operation argument is tested. A zero operation argument selects a 16-bit zero.

Only when selection is zero and the operation argument is nonzero does the function obtain the field value from memory.

### Dynamic displacement and conditional field read

On that eligible branch, the ordering is:

1. Complete the third call to F-fdd8589eca2d.
2. Read the global data location supplying the displacement.
3. Use that read value with the object address to form the field address.
4. Read 16 bits from that field address.

The global read is part of the behavior, not merely background information used to describe the field. The function does not establish an earlier snapshot of the displacement.

Any preceding dependency may change the global’s contents. In particular, if the third context acquisition changes the displacement, the subsequent field access uses the value read after that acquisition. Moving the global read earlier or caching it across dependencies would not match this ordering.

The supplied expression does not establish the global’s declared width, signedness, or displacement-extension rules. It establishes its participation in the address calculation. Validity of that calculation and of the resulting address is required; wrapping or out-of-range behavior is not specified.

### Submission and normal completion

When the mode is not `8`, F-818c773e8c8a receives five arguments:

1. The third context acquisition’s result.
2. The local descriptor storage address.
3. The original resolved entry.
4. The original 32-bit operation argument.
5. The selected 16-bit value.

The selection argument is not forwarded. When no field read is eligible, the fifth argument is zero; the fourth argument remains unchanged.

After submission returns, or directly after submission is skipped:

1. The supplied value is written as 32 bits at object offset `0x108`.
2. F-920630e53283 receives the local descriptor storage address.
3. The function returns without an explicit result.

No submission or finalization status is inspected. The final explicit object store precedes finalization. Because finalization’s indirect effects are unknown, the object’s value after return is not guaranteed solely by that store.

## Side effects

The full-path ordering of direct accesses and intervening calls is:

1. Read the selector byte at `0x110`.
2. Write the byte argument at `0x10C`.
3. Resolve the supplied value and perform the three entry/application calls.
4. Acquire the first context and read its byte at `0x2C`.
5. Acquire the second context and read its 32-bit field at `0x28`.
6. Pass local storage and those fields to descriptor construction.
7. Query the mode.
8. If the mode is not `8`, acquire the third context.
9. Only if selection is zero and operation is nonzero, read the global displacement, then read the selected 16-bit object field.
10. If the mode is not `8`, submit.
11. Write the supplied value at `0x108`.
12. Finalize the descriptor.

This ordering is conditional on each preceding operation completing normally. Dependencies may introduce additional reads, writes, callbacks, allocation, release, or global changes. No dependency is assumed to preserve object fields, the displacement global, context storage, or other shared state.

The local storage address is exposed to construction, optional submission, and finalization. Its storage is local to the invocation. Whether a dependency retains it is unknown; valid use after the invocation cannot be established.

No explicit heap allocation, deallocation, synchronization, exception handler, or error-code return appears in this function. Their absence inside dependencies is not established. The apparent construction/finalization pairing alone does not establish ownership.

## Acceptance examples

These are conditional acceptance criteria from static evidence, not executed tests. Each assumes valid reached memory accesses and normally returning dependencies except where stated otherwise.

### Abbreviated path

With a nonzero selector byte, the supplied value must be written at `0x108`, with no dependency calls and no direct write at `0x10C`. Neither the global displacement nor the selected object field is read.

### Zero resolution

With a zero selector and zero resolution result, the byte argument must already have been written at `0x10C` when F-a817d8d58c10 is called. Under its stated non-returning property, no later descriptor operation or final `0x108` store occurs.

### Mode equal to eight

With successful resolution and mode `8`, descriptor construction still uses two context acquisitions. There is no third acquisition, displacement-global read, selected-field read, or submission. The final `0x108` store precedes finalization.

### Submission selection matrix

For successful resolution and a mode other than `8`:

| Selection | Operation | Third context call | Global displacement read | 16-bit field read | Fifth submission argument |
|---|---|---|---|---|---|
| Zero | Nonzero | Yes | Yes, after the call | Yes, after the global read | Field value |
| Zero | Zero | Yes | No | No | Zero |
| Nonzero | Nonzero | Yes | No | No | Zero |
| Nonzero | Zero | Yes | No | No | Zero |

Every row forwards the original operation argument as the fourth submission argument.

### Displacement changes during context acquisition

Suppose the eligible branch is reached and the third context acquisition changes the displacement global from one valid displacement to another. If the newly selected field contains a different 16-bit value, submission must receive that newly selected value. Reading the old field because the displacement was captured before the query would violate the established ordering.

### Separate descriptor observations

If the first two context acquisitions return different addresses, construction must receive the byte from the first address’s `0x2C` field and the 32-bit value from the second address’s `0x28` field. Neither address may be substituted for the other.

### Finalization observes the explicit store

If finalization can observe the object through an alias, the explicit `0x108` store has occurred before finalization begins. This does not require finalization to preserve that value.
