2. Read the saved word at the resulting address plus `0x14`.
3. Read the second context’s address-bearing field again.
4. Write Input 4 as four bytes at this newly obtained address plus `0x14`.
5. Read the word at saved word plus `0x14` and form the selection base.
6. Write Input 3 as four bytes at Input 3 plus `0x54`.
7. Write the narrowed saved word at first context plus `0x11`.

The second read of the context field is a separate access. Reusing its earlier value is not an equivalent access pattern.

The read used in forming the selection base occurs after the Input 4 replacement. Overlap can therefore make that read observe replacement bytes. The selected-word read occurs after both the first Input 3 store and the first-context byte store; those stores can also affect its observation.

The assignment at frame offset `0x108` occurs at selection time, not during the later bulk frame preparation.

## Acceptance examples

These are conditional static acceptance criteria, not executed tests. Each assumes earlier required accesses succeed and arithmetic is defined. Unless explicitly stated, interfering overlap is excluded.

### Width-sensitive effects

If the initial payload is `0x123456AB`, the first-context store at `0x09` supplies one byte, `0xAB`. The selected-word store at `0x64` supplies four bytes.

Writing the complete initial payload at `0x09` violates the width requirement. The byte order of a four-byte store remains unresolved.

### Independent context-field reads

If the first read of the second context’s field produces one address and the second read produces another, the saved word comes from the first address plus `0x14`, while Input 4 is written at the second address plus `0x14`.

Always reusing the first address does not preserve this behavior.

### Selection after overlapping writes

If Input 3 plus `0x54` overlaps the selected-word location, selection occurs after the first Input 3 store and the intervening first-context byte store.

The selected-word observation must reflect applicable earlier writes, not an unconditional entry-state value.

### Initial versus refreshed payload

If the initial payload has low byte `0xAA` and an intervening first-context write changes that payload location’s low byte to `0x55`, the first-context update at `0x09` uses the earlier `0xAA`.

The later payload-relative update at `0x11` uses `0x55` from the fresh read, provided no other interference occurs. Using one cached observation for both fails this criterion.

### Arithmetic byte origin

For payload base `0x00001234`, doubling produces `0x00002468` without signed overflow. The final byte supplied at destination base plus `0x09` is `0x68`.

Memory contents at address `0x00002468` do not determine that byte.

With noninterfering storage, preparation assigns two copies of the former and four copies of the latter at the listed offsets. This does not resolve negative or overflowing shifts.

### Later global observation
