# F-08fb88178805

## Purpose

F-08fb88178805 transfers two opaque 32-bit values into two caller-supplied destinations and returns a 32-bit zero on normal completion.

Source selection involves **two evaluations of a global pointer**, not one shared evaluation. The first evaluation captures a base address for the later second-word read. The second evaluation selects the address for the first-word read. Consequently, without a stability assumption, the two values need not originate from the same two-word region.

The transfer is ordered rather than an atomic snapshot. The first value is read and written before the second value is read. A first destination overlapping the location used for the second read can therefore change the second output.

The established behavior is a small memory-transfer operation. Its interpretation as a two-word getter is inferred intent; the meanings of the values and the surrounding ownership or synchronization protocols are unknown.

## Behavior

### Ordered operation

The supplied static representation establishes this logical sequence:

1. Evaluate the global source pointer and retain that address for the later second-word access.
2. Evaluate the global source pointer again to select the first-word address.
3. Read one 32-bit value at the address obtained by the second evaluation.
4. Write that value to the first destination.
5. Read one 32-bit value at offset 4 bytes from the address retained by the first evaluation.
6. Write that value to the second destination.
7. Return a 32-bit zero.

The first destination write therefore occurs after both global-pointer evaluations, but before the second source-word read.

This is an access-order description at the level of the supplied representation. It does not establish hardware load counts, indivisible accesses, memory barriers, or a cross-thread synchronization guarantee.

### Source selection and retained address

The address retained by the first global-pointer evaluation determines where the second value will be read. The subsequent global-pointer evaluation independently determines where the first value will be read.

If the global pointer is stable across both evaluations, the function reads the first and second words of the same selected region. Stability must not be inferred merely because both evaluations reference the same global storage.

If the evaluations obtain different addresses under an environment where such behavior is defined, the first output can originate from one region and the second output from another. The function does not compare the addresses, detect a change, restart, or reconcile the selections.

A first destination write that overlaps the global pointer storage occurs too late to change either pointer value already selected for this invocation. In particular, it does not replace the retained address used for the second-word read. It can still affect that read if the written bytes also overlap the second source-word location itself.

Any resulting change to global pointer storage may affect later invocations. No restoration is visible. Whether a 32-bit destination write can validly replace all or part of that pointer storage depends on the target’s pointer representation and access rules.

### Source and destination overlap

The first source value is read before its destination is written. Writing that value back over its own source location does not change the value already obtained.

The second source value is read only after the first destination write. If the first destination identifies the 32-bit location at offset 4 from the retained base, the first write replaces the value that the second read would otherwise obtain. In ordinary stable memory without an intervening modification, both writes then carry the first-read value.

That consequence does not require the two global-pointer evaluations to return the same base. It requires only that the first destination overlap the actual location selected for the second read in the stated way.

The second destination write happens after both source-word reads. It cannot change either value already obtained, but it may overwrite the first destination, source storage, or global pointer storage.

Partial overlap is not rejected. Exact final byte patterns for partially overlapping words depend on the target’s byte order, permitted accesses, and storage model.
