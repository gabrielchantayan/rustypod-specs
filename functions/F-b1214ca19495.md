# F-b1214ca19495

## Purpose

F-b1214ca19495 updates three adjacent 64-bit state fields according to a signed position and a table’s signed count.

When the position is less than the count, the function:

- Selects a 24-byte table entry.
- Copies two words from that entry into the state.
- Constructs a 64-bit operand from a state word and two entry words.
- Calls F-1e0edc6e0bc9 with that operand and another state word.
- Stores the dependency’s result and a sum involving that result.

Otherwise, it writes a fixed terminal state: two fields contain the bit pattern `0x7FFFFFFFFFFFFFFF`, and one contains zero.

These state transitions are established by the supplied static representation. Interpretations such as “timestamp,” “duration,” “scaling,” or “end-of-stream marker” are not established. The dependency’s operation is unknown; this contract does not assume it performs division.

## Behavior

### Branch selection

The function first reads the signed position from state offset `0xC4`, then reads the descriptor address from state offset `0x38`, then reads the descriptor’s signed count.

It selects the entry-processing branch exactly when:

**signed position < signed count**

There is no additional requirement that the position be nonnegative. Equality selects the terminal branch.

The initial position and descriptor address are retained for subsequent use. The count is not reread to validate the decision.

### Entry-processing branch: capture and copy

The function first reads the entry-storage address from descriptor offset `0x04`. It selects an entry using that address plus 24 times the saved position.

From this first selected address, the source-level access order is:

1. Read the 32-bit word at entry offset `0x0C`.
2. Read the 64-bit value at entry offset `0x08`, retaining it as the later addend.
3. Read the 32-bit word at entry offset `0x08` again.
4. Write that last 32-bit word to state offset `0xC8`.
5. Write the previously captured word from entry offset `0x0C` to state offset `0xCC`.

The separate word read at entry offset `0x08` matters. The copied words are not specified as one atomic eight-byte snapshot, and the copied value need not match the saved 64-bit addend if the underlying storage changes between accesses.

These are source-level accesses, not a guarantee about individual processor transactions or atomicity.

### Entry-processing branch: operand construction

After the two state writes, the function:

1. Reads the 32-bit arithmetic input at state offset `0x9C`.
2. Rereads the entry-storage address from descriptor offset `0x04`.
3. Selects an entry again using the saved position and the 24-byte stride.
4. Reads the entry’s word at offset `0x00`.
5. Uses the entry’s word at offset `0x04` to complete the operand.

The second entry-storage read is significant. The entry used for arithmetic is not unconditionally the same storage used for the earlier addend and copy. Aliasing or external mutation can make the descriptor’s entry-storage address change between the two reads.

Let:

- \(r\) be the unsigned bit pattern of the state word at `0x9C`;
- \(a\) be the unsigned word at arithmetic-entry offset `0x00`;
- \(b\) be the unsigned word at arithmetic-entry offset `0x04`;
- \(p=r\times a\), evaluated as an unsigned 64-bit product.

The first dependency argument is the low 32 bits of \(p\).

The second dependency argument is the following 32-bit bit pattern:

\[
H=\left(\left\lfloor p/2^{32}\right\rfloor+r b+s a\right)\bmod 2^{32}
\]

Here \(s\) is zero when bit 31 of \(r\) is clear and `0xFFFFFFFF` when that bit is set.

Thus, the sign-bit contribution is zero for a nonnegative signed interpretation of \(r\), and contributes \(-a\) modulo \(2^{32}\) otherwise.

Under the represented sign-extending right-shift behavior, the two arguments together are the low 64 bits of the product of:

- the signed 32-bit interpretation of \(r\); and
- the 64-bit bit pattern whose low word is \(a\) and high word is \(b\).

The explicit word formula is authoritative for this contract. Overflow in the high-word arithmetic is discarded modulo \(2^{32}\).

### Dependency call and completion

F-1e0edc6e0bc9 receives four 32-bit arguments, in this order:

1. The constructed low word.
2. The constructed high word.
3. The word read from state offset `0x64`.
4. Zero.

The source does not establish an evaluation order among the remaining reads performed while forming the call arguments, including the third-argument state read and the arithmetic-entry high-word read.

If the dependency returns normally, its 64-bit result is written to state offset `0xD8`.

The function then adds that result to the 64-bit addend captured from the first selected entry and writes the sum to state offset `0xD0`.

The addend is not reread after the call. No range check or saturation operation is visible. The supplied representation expresses signed 64-bit addition; exact overflow behavior is not independently established. Non-overflowing sums have the ordinary signed 64-bit result.

### Terminal branch

When the signed position is greater than or equal to the signed count, the function performs these writes in order:

1. Write `0xFFFFFFFF` to state offset `0xC8`.
2. Write `0x7FFFFFFF` to state offset `0xCC`.
3. Write zero to the 32-bit word at state offset `0xD8`.
4. Write zero to the 32-bit word at state offset `0xDC`.
5. Write the 64-bit value `0x7FFFFFFFFFFFFFFF` to state offset `0xD0`.

It does not access entry storage or call F-1e0edc6e0bc9 on this branch.

The interpretation of the two words at `0xC8` and `0xCC` as the same positive 64-bit value depends on the target’s word ordering. Their individual stored values are explicit regardless.

## Side effects

The function explicitly writes only the state regions at `0xC8`–`0xCF`, `0xD0`–`0xD7`, and `0xD8`–`0xDF`.

It does not explicitly increment the position, update the count, allocate storage, free storage, or transfer ownership. No ownership transfer is established by this interface.

On the entry-processing branch, the copied words are written before the dependency call. The result field is written after the dependency returns, followed by the final sum field. An observer must not assume all three fields change atomically.

No rollback or recovery is visible. Failure during an access or dependency invocation can leave earlier writes in place. In particular, the copied words may already have changed before the dependency fails.

The dependency may have additional effects on memory or global state. Those effects are unknown. This contract does not assume that it preserves unrelated state or leaves allocations untouched.

Aliasing is not excluded. State writes can affect later reads if the descriptor or entry storage overlaps the state. A disjoint-storage requirement may be sensible for callers, but is not checked or established here.

## Acceptance examples

These are conditional acceptance cases derived from static evidence, not executed tests. Unless stated otherwise, they assume valid, stable, nonoverlapping storage and a normally returning dependency.

### Position equals count

Given a position and count both equal to 3:

- No entry is accessed.
- The dependency is not called.
- State words `0xC8` and `0xCC` become `0xFFFFFFFF` and `0x7FFFFFFF`.
- State field `0xD8` becomes zero.
- State field `0xD0` becomes `0x7FFFFFFFFFFFFFFF`.

### Ordinary selected entry

Given position 1 and count 2, selection uses the entry-storage address plus 24 bytes.

Suppose the arithmetic input is 3, the entry’s arithmetic words are 5 and zero, and the saved addend is 100. The first two dependency arguments are 15 and zero.

If the dependency returns 7, the function writes 7 at `0xD8` and 107 at `0xD0`. The copied state words come from entry offsets `0x08` and `0x0C`.

### Negative arithmetic input

Given arithmetic-input bits `0xFFFFFFFF`, entry low word 2, and entry high word zero, the constructed argument words are:

- Low: `0xFFFFFFFE`.
- High: `0xFFFFFFFF`.

This distinguishes the represented sign-adjusted construction from ordinary unsigned multiplication of the input bit pattern.

### Negative position

Given position −1 and count 0, the entry-processing branch is selected. The first entry address is 24 bytes before the entry-storage address.

Acceptance is conditional on that address being valid. This case must not be reclassified as terminal merely because the position is negative.

### Changed entry-storage address

If descriptor offset `0x04` changes between its two reads, the saved addend and copied words come from the first selected storage, while the arithmetic words come from the second selected storage.

The contract does not promise a coherent entry snapshot.
