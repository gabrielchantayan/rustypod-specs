# F-b48496d78169

## Purpose

F-b48496d78169 coordinates externally selected processing actions with two independent result channels:

- A signed 32-bit return value.
- Signed 32-bit writes to caller-supplied output storage.

Processing may invoke F-b09db3398a5a or F-3d0cbc9c0022, consume a 32-bit input payload, retain intermediate values, and publish a value derived from an invocation-local temporary. None of these activities inherently completes the invocation.

The established behavior is a routing-controlled protocol, not a fixed sequence of validation, processing, and completion. External values determine which actions occur and whether they repeat. Consequently, successful dependency returns do not establish eventual termination, output publication, or result capture.

An interpretation as staged processing with separate status and output channels is **inferred intent**, not an established application-level contract. No success convention or payload meaning is known.

### Access requirements

The saved arguments and the addresses used for memory access are distinct. Both active addresses initially are null. Address activation installs the saved input address and then the saved output address.

Each dependency invocation requires a valid four-byte read through the active input address. Each publication requires a valid signed 32-bit write through the active output address. A valid saved argument does not satisfy an access attempted before activation.

Conversely, an argument that is never accessed need not be dereferenceable merely because it was supplied. Readiness inspection checks nullness only; it does not establish accessibility, alignment, permissions, or lifetime.

No non-aliasing requirement is established. Input and output may refer to the same compatible storage. In that situation, publication may affect the payload consumed by a later dependency invocation.

## Behavior

### Routing contract

Routing uses signed 32-bit coordinates relative to an origin retained at entry. The relative displacement is formed by signed subtraction; that subtraction must be representable.

Entry observes the secondary scale before the primary scale. It then makes three separate references to one external routing source. The first supplies the origin after subtraction of six; the second supplies a retained preparation destination after addition of one; the third supplies the initial route. Both signed adjustments must be representable.

Agreement among all three references makes activation the initial action and capture the preparation destination. Agreement is not guaranteed: separate references do not establish a snapshot, synchronization, or an exact physical-load count.

The routing vocabulary is defined by these displacements:

- **Completion and result handling:** displacement 1 returns; 7 captures; 8 prepares zero; 9 and 10 prepare an external result.
- **Output:** displacement 3 publishes zero; 12 publishes the scaled temporary.
- **Address handling:** displacement 6 activates the saved arguments; 4 inspects readiness.
- **Continuation handling:** displacement 0 obtains a shared continuation; 5 selects a character-sensitive continuation.
- **Dependency processing:** displacement 11 invokes F-3d0cbc9c0022. Every other displacement, including 2, invokes F-b09db3398a5a.

Unlisted displacements are therefore not rejected as invalid routes.

Only the return action normally terminates the function. No iteration bound, cycle detection, timeout, or cancellation behavior is established.

### Address activation and inspection

Activation observes its external continuation before installing either active address. It then installs input before output. It does not dereference either address. Repeated activation restores the original arguments rather than preserving any alternative active addresses.

Inspection has three distinct effects:

1. The routing condition records active-output nullness: one for non-null, zero for null.
2. The signed temporary becomes zero.
3. Active-input nullness determines the continuation.

For null active input, the continuation comes from an inspection-routing reference increased by five. For non-null input, it comes from an unadjusted reference to that same source.

Both source references participate in the arithmetic selection. The plus-five adjustment must be representable even when its contribution has zero weight. Their relative evaluation order is not established. Inspection itself performs neither a payload read nor an output write.

### Dependency calls and retained processing values

Every dependency invocation obtains a fresh payload through the active input address. Previously consumed payloads are not cached for subsequent calls.

F-b09db3398a5a receives the payload, the numeric arguments one, zero, zero, and an external option, in that argument order. Payload acquisition and option observation occur before dependency entry, but their relative evaluation order is not established.

F-3d0cbc9c0022 receives the temporary’s address, the current unsigned transfer value, zero, and a freshly read payload, in that argument order. There is no automatic temporary reset immediately before this call. Its incoming value may therefore be the initial zero, a zero established by inspection, or a value retained from previous activity. The boundary does not guarantee that the dependency writes the temporary.

Both dependencies return a signed 32-bit value used in subsequent arithmetic. Their returns are not themselves routes, published outputs, or captured function results.

For either normally returning dependency, processing uses two signed products:

- The **primary product** multiplies the primary scale by the secondary scale first, then multiplies that intermediate by the dependency return.
- The **secondary product** multiplies the secondary scale by the dependency return first, then multiplies that intermediate by an external third factor referenced after the call.

Every signed intermediate must be representable. A zero dependency return does not excuse overflow in an earlier multiplication of the two scales.

The two dependencies update different retained values:

- After F-b09db3398a5a, the primary product, converted to unsigned 32-bit, replaces the transfer value. That replacement precedes secondary-product calculation. The working value becomes the bitwise union of the transfer value and the secondary product converted to unsigned 32-bit.
- After F-3d0cbc9c0022, the signed primary and secondary products are combined by bitwise union and complemented in the signed domain. Conversion to unsigned 32-bit supplies the working value. This processing does not directly replace the transfer value. No relative evaluation order between the two product expressions is established.

The post-call third-factor reference may observe changes made by the dependency. The retained entry scales are not expressly refreshed.

### Condition derivation and dependency continuations

After either dependency’s processing, the working value determines the routing condition through conversion to signed 32-bit, signed right shift by 31, negation, and conversion back to unsigned 32-bit.

Under bit-preserving unsigned-to-signed conversion and arithmetic right shift, the condition is zero for a clear high bit and one for a set high bit. That interpretation is conditional. Out-of-range unsigned-to-signed conversion and negative signed right shift depend on target rules not supplied here.

Preparation, publication, and capture do not independently refresh this condition.

After F-b09db3398a5a, routing combines two references to a post-call routing source. One reference is decreased by eight and weighted by the condition exclusive-OR one; the other is weighted by the condition. The combination uses unsigned 32-bit arithmetic before conversion to signed routing storage.

Thus, condition zero selects the adjusted reference, and condition one selects the unadjusted reference. Other condition values produce an arithmetic combination rather than Boolean selection. Both references participate, and the signed minus-eight adjustment must remain valid even when weighted by zero.

After F-3d0cbc9c0022, the corresponding unsigned combination uses the retained origin with weight “condition exclusive-OR one” and a fresh external target with weight “condition.” Condition zero therefore selects the origin; condition one selects the fresh target. The fresh target reference participates even when its weight is zero.

### Character-sensitive continuation

The character-sensitive action converts the routing condition to plain character type before selecting its continuation.

A converted character value of zero selects a routing reference increased by seven. A converted value of one selects a separate, unadjusted reference to the same source. Both references participate, and the signed plus-seven adjustment must be representable regardless of its eventual weight.

Other converted values do not behave as Boolean conditions. The adjusted contribution uses the promoted character value exclusive-OR unsigned one; the unadjusted contribution multiplies a routing reference by the promoted character value.

Character width, signedness, conversion, and integer promotion therefore affect the result. Any multiplication performed in the signed domain must be representable. The relative order of these routing references is not established.

### Publication and completion

Publication, preparation, capture, and return are independent actions.

**Zero publication** stores signed 32-bit zero through active output before observing the shared continuation. It does not inspect the old output value.

**Scaled publication** stores the product of the primary scale, secondary scale, and current temporary. The scale pair is multiplied first; both signed intermediates must be representable. Its next route is the retained origin, which selects the shared-continuation action.

Neither publication directly changes the temporary, transfer value, working value, condition, or retained return result. Effects through aliasing or dependencies are separate from these direct updates.

**Preparation** replaces the working value with zero or with an external result converted to unsigned 32-bit. The two external-result preparation routes have identical established behavior. All preparation actions route to the destination retained at entry; that destination is not necessarily capture when entry references disagree.

**Capture** multiplies the primary scale by the unsigned working value using unsigned 32-bit arithmetic, modulo \(2^{32}\). The product is converted to signed 32-bit and replaces the retained return result before the capture continuation is observed. An out-of-range conversion to signed remains target-dependent.

**Return** reports the most recently captured result. Without capture, the return value remains zero, regardless of dependency activity or output publication.

## Acceptance examples

These examples are conditional static deductions, not executed tests. They assume valid accesses and representable signed arithmetic unless the example specifically discusses a violated precondition.

1. **Consistent entry routing.** If all three entry-routing references equal the same value, activation occurs first and preparation targets capture. Activation still obtains its continuation before installing either active address.

2. **Saved addresses do not activate themselves.** If routing selects a dependency before activation, its payload read uses the initially null active input address. Valid original arguments do not satisfy that read’s precondition.

3. **Nullness is not access validation.** After activation with non-null but inaccessible output storage, inspection sets the condition to one without proving that a later publication is valid.

4. **Publication does not determine return.** If publication occurs and return is later reached without any capture, the function returns zero. This holds even when scaled publication writes a nonzero value.

5. **Zero return from F-b09db3398a5a.** With valid signed products, a zero dependency return makes transfer, working value, and condition zero. Routing then uses the post-call reference decreased by eight. Overflow in the scale-pair multiplication would invalidate these premises.

6. **Zero return from F-3d0cbc9c0022.** Under two’s-complement signed representation, bit-preserving unsigned-to-signed conversion, and arithmetic negative right shift, valid zero products produce an all-ones working value and condition one. Routing uses the fresh continuation target. The temporary’s value remains dependent on the dependency’s effects.

7. **Temporary persistence and reset.** If the temporary contains seven and F-3d0cbc9c0022 leaves it unchanged, that call alone does not clear it. A subsequent inspection resets it to zero.

8. **Aliased input and output.** With primary scale two, secondary scale three, and temporary seven, scaled publication stores 42. If input refers to the same compatible word, a later payload read consumes that stored representation unless an intervening effect changes it.

9. **Unsigned capture differs from signed publication.** Capturing working value \(2^{31}\) with primary scale two produces modular product zero and retained result zero. This does not permit signed overflow during scaled publication.

10. **Preparation need not capture.** If entry references disagree, preparation can change the working value and route elsewhere. Neither the retained return result nor condition changes merely because preparation occurred.

11. **Unused contributions still matter.** With condition zero after F-3d0cbc9c0022, the selected route is the origin, but the fresh target reference still participates. Likewise, inspection’s plus-five and character selection’s plus-seven adjustments must remain valid when their contributions receive zero weight.

12. **Termination is conditional.** A repeating sequence of continuations that never selects return does not complete, even if every dependency invocation returns normally.
