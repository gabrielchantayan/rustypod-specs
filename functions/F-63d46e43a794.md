## Behavior

The function first retains the current global state-object reference for subsequent processing.

Before calling the dependency, it examines the entry-condition field through the global state reference. If that field is nonzero, it writes the four-byte value one to the activity flag through that global reference.

If the entry condition is zero, this entry step does not write the activity flag. In particular, it does not clear an already nonzero flag.

The function then calls F-78aeb390f956 once. This call occurs even if the retained state object already has a nonzero status. There is no status-based early return before that first call.

### 2. Initial consumption phase

For each dependency result examined in this phase, checks occur in this order:

1. Interpret the result as signed 32-bit and test whether it is negative.
2. If it is nonnegative, read the status field from the retained state object.
3. If that status is zero, classify the result.

The order determines both field access and failure precedence.

#### Negative result

A negative result causes the function to write 0x0000000E to the retained object’s status field and return zero.

The function does not first read that status field on this path. Consequently, this explicit write can replace an existing nonzero status, including one left by the dependency.

This path does not explicitly clear the activity flag.

#### Existing nonzero status

For a nonnegative result, a nonzero status causes an immediate return of zero.

No classification of that result takes place. There is no explicit status replacement, sequence update, or activity-flag update on this branch.

Any state effects already performed by the dependency remain subject to that dependency’s unknown behavior.

#### Masked candidate recognition

With a nonnegative result and zero status, the result is a sequence candidate exactly when:

**result AND 0x000000F8 equals 0x000000D0.**

This test constrains bits 3–7 and leaves bits 0–2 available as the candidate sequence. It does **not** require the entire result to be a byte or to lie numerically between 0xD0 and 0xD7.

Accordingly:

- 0x000000D0 through 0x000000D7 qualify.
- A nonnegative value such as 0x000001D3 also qualifies.
- A value with bit 31 set is rejected by the earlier negative-result branch, regardless of its low byte.

A qualifying candidate proceeds to sequence comparison.

#### Exact continuation value

If the result is not a candidate, the function checks whether the complete 32-bit result equals 0x000000DC.

An exact match causes another call to F-78aeb390f956, followed by the same initial-phase checks.

This equality is not a low-byte comparison. For example, 0x000001DC is not accepted as the continuation value.

There is no visible limit on the number of consecutive exact 0xDC values consumed.

#### Other results

Any remaining nonnegative result, provided the status read was zero, causes the function to write 0x0000000E to the status field and return zero.

This path does not explicitly change the expected sequence or activity flag.

### 3. Sequence comparison and advancement

For a recognized candidate, the low three bits of the result are compared with the complete unsigned 32-bit expected-sequence field.

The stored field is not masked before comparison. Therefore, a stored value outside 0–7 cannot match any candidate sequence, even if its low three bits match.

A mismatch causes a status write of 0x0000000E and a return of zero. No further dependency call occurs on that path, and the expected-sequence field is not explicitly changed.

On a match, the function writes the next sequence value to the expected-sequence field. The update adds one and retains only the low three bits:

- 0 advances to 1.
- 1 through 6 advance to their immediate successors.
- 7 advances to 0.

Under ordinary execution without an intervening mutation of that field, the successful comparison ensures that the value being advanced is in 0–7. The resulting stored value is also in 0–7.

The sequence write occurs **before** the next call to F-78aeb390f956. It is not rolled back if later processing terminates.

### 4. Post-match consumption phase

After advancing the sequence, the function calls F-78aeb390f956 and enters a different processing phase.

For each result in this phase:

1. A negative signed 32-bit result causes the activity flag to be written with zero, followed by a return of zero.
2. Otherwise, the function reads the status field.
3. A nonzero status causes a return of zero.
4. A zero status causes another dependency call.

Candidate masks, exact 0xDC recognition, and sequence comparisons are no longer applied in this phase.

The negative-result check again precedes the status read, but its consequence differs from the initial phase:

- It clears the activity flag.
- It does not explicitly assign 0x0E to status.
- It does not inspect status before returning.
- It does not undo the earlier sequence advancement.

For a nonnegative result with nonzero status, the activity flag is not explicitly cleared.

If the dependency continually returns nonnegative results and leaves status zero, this phase does not terminate through any visible internal limit.
