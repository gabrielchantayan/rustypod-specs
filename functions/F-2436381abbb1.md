## Behavior

### Dispatch sequence

The established order is:

1. Read the base value from the memory addressed by the input.
2. Form the selected slot address by adding 292 bytes to that value.
3. Read the callable address from the selected slot.
4. Invoke that callable.
5. Return normally if the callable returns normally.

The second read depends on the first read’s result. The control transfer depends on the second read’s result. There is no visible alternative dispatch path, iteration, fallback operation, or second invocation.

Each of the two dispatch-related reads appears once in the supplied representation. This is a statement about the recovered operation sequence, not a guarantee about physical bus transactions, cache behavior, speculative execution, or device-memory semantics.

### Selection and mutation

The selected callable is determined by the value read from the slot before the invocation. If that callable subsequently changes the original base-containing memory or replaces the slot, the function does not visibly reread either location after the call.

There is also no visible restoration of dispatch state after the call. A change made by the selected callable is not undone by this function.

No guarantee is made about concurrent mutation between the reads. The evidence supplies no synchronization, atomicity, or consistency mechanism. An environment that requires a stable relationship between the base and its selected slot must provide that stability outside this function.
