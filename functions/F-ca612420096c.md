# F-ca612420096c

## Purpose

F-ca612420096c conditionally processes a record, an associated collection, and that collection’s entries, then invokes dynamically selected operations.

The established contract is an ordered sequence of reads, dependency calls, and indirect calls. A teardown or cleanup purpose is **inferred intent**. The supplied representation does not establish that any dependency frees memory, destroys an object, accepts null, preserves globals, or returns normally.

A nonzero control word suppresses all processing. Otherwise, the function visits collection entries in descending index order, submits two fields and then each entry address to F-5990a26eaaa3, conditionally submits the collection handle to F-9aef742d6dcd, submits the record’s first word to F-5990a26eaaa3, and performs the dispatch sequence.

The dispatch sequence contains **two distinct reads of the global dispatch root**. The first supplies a retained table address for later operations. The second supplies the table address used to select the initial optional target. These reads have different uses and are not established to return the same value under concurrent mutation.

## Behavior

### Control gate

The first established operation is a 32-bit read of the record’s +4 control word.

If that word is nonzero, the function returns immediately. It does not read the collection handle, read the record’s +0 word, call a listed dependency, or read the dispatch root.

If the control word is zero, processing continues. There is no explicit second control check. A later change to that word does not cancel the remaining visible sequence.

### Collection capture and count

The function reads the record’s +8 word and retains it as the collection handle for this invocation.

It calls F-10b760faca36 with that handle, including when the handle is zero. The result supplies a signed 32-bit count. The function does not query the count again.

Entry lookups and the later conditional collection operation use the captured handle. Changes to the record’s +8 field do not redirect those operations because that field is not explicitly reloaded.

### Descending entry processing

The count is decremented before the first signed comparison. An iteration occurs if the resulting signed 32-bit index is nonnegative. The same decrement-and-compare pattern controls subsequent iterations.

For a positive count \(n\), the ordinary lookup sequence is \(n-1\) through 0, inclusive. Assuming valid accesses and normally returning calls, this gives \(n\) iterations.

Each iteration has this observable order:

1. F-6bbddce1b930 receives the captured collection handle and current index.
2. The returned entry’s 32-bit +8 field is read.
3. F-5990a26eaaa3 receives that field value.
4. The same entry’s 32-bit +4 field is read.
5. F-5990a26eaaa3 receives that field value.
6. F-5990a26eaaa3 receives the entry address.
7. The next decrement and signed comparison determine whether processing continues.

The fields are not captured as a single snapshot. The call using the +8 value occurs before the +4 read. If that call changes the +4 field and leaves the entry readable, the later read obtains the changed value. If the call invalidates the entry, the subsequent read has no established safe behavior.

There is no explicit zero check for the returned entry address before either field read. Neither field value is checked before being passed to F-5990a26eaaa3. Equal values and repeated entry addresses are not deduplicated.

A count of zero becomes −1 and causes no entry processing. Negative counts other than −2,147,483,648 also become negative after the first decrement and cause no entry processing. Decrementing −2,147,483,648 crosses the signed 32-bit boundary; its behavior is unresolved rather than assumed to wrap.

### Collection and record-field processing

After the entry loop, the function checks the captured collection handle:

- If nonzero, it calls F-9aef742d6dcd with that handle.
- If zero, it skips that call.

This check does not suppress the earlier F-10b760faca36 call or any iterations resulting from its return value.

Next, the function reads the record’s +0 word and passes it to F-5990a26eaaa3. This call is unconditional on the active path, including when the word is zero.

The +0 read occurs after all entry operations and after the conditional collection call. Mutations made by those operations can therefore affect the submitted value. No earlier copy of this field is established.

### Dispatch-root reads and target selection

After F-5990a26eaaa3 returns from the call using the record’s +0 word, the dispatch sequence proceeds in this order:

1. Read the global dispatch root and retain the resulting table address.
2. Read the global dispatch root again.
3. Use the address from the **second** read to read the callable slot at +0x30.
4. If that slot is nonzero, invoke the selected initial optional target.
5. Read the +0x18 callable slot from the table retained by the **first** root read.
6. Invoke that target unconditionally with the record address.
7. Read the +0x30 callable slot from that same retained table.
8. If this final slot value is nonzero, invoke its target with the two shown argument values 0 and 1; otherwise return without that invocation.
9. Return if the final invocation returns normally.

No dependency or indirect call intervenes between the two root reads. Nevertheless, the supplied evidence does not establish stability under concurrent mutation, so equality of their results is not a contract condition.

For the initial optional call, the outgoing representation identifies the record address, zero, the selected callable address itself, and the fourth incoming argument, in that order. Four further machine-context values appear in the representation, but their meaning and status as formal arguments are not established. This is not sufficient evidence for a portable callback signature.

Once the first root value is retained, a later change to the global root does not redirect the explicit +0x18 and final +0x30 reads. This does not imply that the initial +0x30 read used the retained table: it used the separate second root value.

Mutations to the retained table can affect later selection:

- The initial optional call occurs before the retained table’s +0x18 slot is read.
- The mandatory call occurs before the retained table’s final +0x30 slot is read.

The initial and final optional calls may select different targets, including targets from different tables. Either optional call can occur without the other.

## Acceptance examples

These are conditional consequences of the supplied static representation, not executed tests. Unless stated otherwise, they assume valid accesses and normally returning dependencies and targets.

1. **Nonzero control word.**  
   With a control word of 7, the function returns after the control-word read. No collection or dispatch operation occurs.

2. **Two entries.**  
   With a zero control word and count 2, F-6bbddce1b930 receives index 1 before index 0. For each entry, F-5990a26eaaa3 receives the +8 value, the subsequently read +4 value, and the entry address, in that order.

3. **Empty nonzero collection.**  
   A nonzero collection handle and count 0 cause no lookup. F-9aef742d6dcd still receives the handle, followed by record-field processing and dispatch.

4. **Zero collection handle.**  
   F-10b760faca36 receives zero. If it returns 0, no lookup occurs and F-9aef742d6dcd is skipped. The record’s +0 word is still read and submitted, even if that word is also zero.

5. **Mutation between entry reads.**  
   If the call using an entry’s +8 value changes its +4 field while preserving readable storage, the next submission uses the changed +4 value.

6. **Late record-field mutation.**  
   If collection processing changes the record’s +0 word, its later submission uses the changed value.

7. **Different root-read results.**  
   If the first global-root read yields table A and the second yields table B, the initial optional target comes from B’s +0x30 slot. The mandatory target comes from A’s +0x18 slot, and the final optional target comes from A’s +0x30 slot. No equality between A and B is required.

8. **Root replacement during the initial optional call.**  
   If that call changes the global root to table C, later explicit slot reads still use table A retained from the first root read, provided A remains readable. The initial call need not itself have been selected from A.

9. **Retained-table slot replacement.**  
   If the mandatory call replaces table A’s +0x30 slot with another nonzero target, the final optional invocation selects that replacement and uses the shown argument values 0 and 1.

10. **Independent optional decisions.**  
    A zero initial slot does not suppress the mandatory call or the final slot read. A nonzero initial slot does not guarantee a final optional call. If both relevant +0x30 reads yield zero, only the mandatory dispatch call occurs. Its target is not explicitly checked for zero.

11. **Negative count boundary.**  
    A count of −1 produces no entry lookup after decrementing to −2. No corresponding expected iteration count is specified for −2,147,483,648 because its decrement behavior is unresolved.
