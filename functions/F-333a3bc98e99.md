# F-333a3bc98e99

## Purpose

F-333a3bc98e99 is a table-assisted, multiword integer arithmetic routine. It accepts four 32-bit words and returns one 64-bit bit pattern. Its computation consists of reciprocal-like estimation, multiply-and-subtract refinement, three final conditional subtractions, residual-dependent low-bit setting, and conditional left normalization.

**Inferred intent:** the first two words appear to form a numerator-like quantity, and the last two words appear to form a divisor-like quantity. The result resembles a normalized quotient or significand with a sticky indication of a nonzero residual.

**Not established:** the supplied evidence does not prove that the return value is an ordinary integer quotient, an IEEE floating-point encoding, or a correctly rounded result for any specified mathematical operation. No such interpretation is part of the established contract.

The routine has one explicit data-memory dependency: a byte table indexed by the most significant byte of the fourth input. The table contents and the caller’s input restrictions are unavailable. Consequently, a complete numerical oracle cannot be derived from the supplied material alone.

## Interface

### Inputs

The interface exposes four unsigned 32-bit inputs, identified here by position:

| Input | Established use |
|---|---|
| First word | Contributes its upper 31 bits to an initial cross-word right shift; its least significant bit becomes a separate high-positioned residual bit. |
| Second word | Contributes its least significant bit to that cross-word shift, and contributes its upper portions to quotient estimation. |
| Third word | Split into upper and lower 16-bit halves for partial products; later reconstructed as a complete 32-bit subtraction operand. |
| Fourth word | Supplies the table index, reciprocal-estimation input, and upper and lower 16-bit partial-product operands; later reconstructed as a complete subtraction operand. |

No input is an explicit pointer. No input buffer, length, callback, or ownership token is present.

The arithmetic is consistent with the second word being more significant than the first, and the fourth word being more significant than the third. That pairing is an interpretation of the arithmetic, not evidence of a surrounding storage format or calling convention.

### Output

The result is a 64-bit bit pattern assembled from a 32-bit upper word and a 32-bit lower word:

\[
\text{return value}=2^{32}\times\text{upper word}+\text{lower word}.
\]

This specifies numerical bit placement, not the byte order used if a caller later stores the result.

There is no separate status return, exception indicator, or error object in the visible interface.

## Behavior

### Table access and operand preparation

The routine explicitly reads one unsigned byte from a fixed table. The byte offset is the fourth input shifted right by 24 bits, so the index is in the inclusive range 0–255.

The table read occurs before the reciprocal refinement and all final correction decisions. It is unconditional in the visible computation: zero inputs, unusual operand relationships, and a zero divisor-like pair do not bypass it.

The third and fourth words are each split into two 16-bit unsigned halves. Their original 32-bit values are recoverable from those halves and are reconstructed for the final correction stage.

The initial numerator-like state includes:

- A middle word formed by shifting the first input right by one bit and inserting the second input’s least significant bit at bit 31.
- A lower residual word whose bit 31 equals the first input’s least significant bit and whose other bits are zero.
- An upper contribution derived from the second input shifted right by one bit.

Both possible values of the first input’s least significant bit explicitly determine the lower residual word. Despite an apparently incoming register value in the supplied representation, that value is overwritten on both branches before use; it is not an established external input.

### Reciprocal-like estimation

The table byte seeds a reciprocal-like approximation based on the upper portion of the fourth input. The computation uses the constants \(2^{23}\), \(2^{29}\), and a bias of two, together with right shifts and truncated products.

A subsequent refinement combines the seed with the fourth input shifted right by 13 bits. Another multiply-and-shift calculation uses the upper and lower 16-bit portions of an intermediate word to produce the approximation used in the quotient-estimation stages.

These are fixed-width calculations. In particular, products feeding a right shift are not automatically full-width products: where the supplied arithmetic retains a 32-bit product, overflow bits are already lost before the shift.

The reciprocal-like value is computed once and reused. The routine does not reread the table during refinement.

### Quotient estimates and residual refinement

Four estimate contributions are produced. For describing their roles, call them the first, second, third, and fourth estimates; these are specification terms, not additional interface values.

The first estimate uses the reciprocal-like value and the upper 16 bits of the second input. It is applied to the prepared multiword state using products with the 16-bit halves of the third and fourth inputs.

The second estimate uses a high residual portion shifted right by two bits. Its product contributions are aligned differently: the subtraction arithmetic uses boundaries corresponding to shifts of 19 and 3 bits, with complementary extracted portions at 13 and 29 bits.

The residual is then repacked across word boundaries with a six-bit right shift. Bits crossing a word boundary are carried into the adjacent word rather than discarded independently.

The third estimate comes from a product involving a high residual portion shifted right by 15 bits. The upper 16 bits of that 32-bit product are used for residual subtraction. A separate portion of the same product, shifted right by 26 bits, contributes to the eventual upper result word.

The fourth estimate again uses a high residual portion shifted right by two bits and the reciprocal-like approximation.

Across these stages, the third and fourth inputs participate through 16-bit partial products. Subtraction decisions explicitly propagate borrows between words. Unsigned comparison and modular subtraction are integral to those decisions; treating an intermediate word as a signed residual would change the behavior.

No general invariant such as “every intermediate residual is nonnegative” or “every estimate is an underestimate” is established without the missing table contents and input-domain constraints.

### Three final correction decisions

After estimate subtraction, the routine constructs a shifted residual state and performs three ordered correction decisions against the reconstructed third and fourth words.

For each decision:

- The candidate residual is compared with the divisor-like pair using unsigned word comparisons.
- If subtraction is selected, both residual words are updated, including the borrow from the lower-word subtraction.
- The decision contributes one bit to a three-bit correction value.

The second and third decisions follow another leftward residual shift. Each shift incorporates a carry from a lower fragment. A carry out of the upper residual word participates directly in deciding whether subtraction occurs.

Equality is included in the subtraction condition. A candidate residual equal to the divisor-like pair is therefore reduced, rather than left unchanged.

The first decision becomes the most significant of the three correction bits, and the third becomes the least significant. The resulting value is between zero and seven and is placed at bit position 9 in the pre-normalized low result word.

These are exactly three correction decisions. There is no visible loop that continues until the residual becomes smaller than the divisor-like operand.

### Result assembly

The result is assembled from the estimates and the three-bit correction value.

The pre-normalized lower word combines:

- The third estimate scaled by \(2^{22}\).
- The fourth estimate scaled by \(2^9\).
- The three-bit correction value scaled by \(2^9\).

These additions are 32-bit additions. Carries from the estimate combination and the subsequent correction addition contribute separately to the pre-normalized upper word.

The upper word also includes:

- The first estimate scaled by \(2^{16}\).
- The second estimate scaled by eight.
- The third estimate’s originating product shifted right by 26 bits.

After correction, the routine tests the two retained residual words. If either is nonzero, bit 0 of the pre-normalized lower result word is set. If both are zero, that operation contributes zero.

This is a residual-dependent bit operation, not a demonstrated round-to-nearest rule. The routine contains no visible tie-breaking comparison or rounding-mode input.

### Conditional normalization

The pre-normalized upper word determines the final transformation:

- If its bit 31 is set, the upper and lower words are returned without a further shift.
- If its bit 31 is clear, the entire two-word result is shifted left by one bit. Bit 31 of the lower word becomes bit 0 of the upper word, and the lower word is doubled modulo \(2^{32}\).

Only one such shift is performed. The routine does not repeatedly shift until a leading one appears.

The residual-dependent bit is set **before** this normalization. In the shifted branch, it consequently moves from bit 0 to bit 1 of the returned lower word. It is not reapplied at bit 0 afterward.

## Acceptance examples

These are conditional static acceptance cases, not runtime test results.

1. **Table selection by the fourth input**

   If the fourth input is `0x7F123456`, the selected table index is `0x7F`. Changing only its low 24 bits leaves the selected index unchanged, although it may change the subsequent arithmetic and result.

2. **A zero table seed**

   If the selected table byte is zero, the initial seed expression produces two because the table-dependent product terms vanish. The routine continues through refinement; it does not report a missing-table-entry error. No particular final quotient is implied.

3. **First-input parity**

   With the second input held fixed, first-input values zero and one produce the same first-input contribution to the cross-word right-shifted word. Their separate low residual words differ: zero versus `0x80000000`. A replacement must not discard this distinction.

4. **Correction at equality**

   If a correction candidate equals the reconstructed divisor-like pair and no extra upper carry is present, subtraction is selected. The residual pair becomes zero and that correction decision contributes a one bit.

5. **Nonzero final residual**

   If either retained residual word is nonzero after the third correction, bit 0 is set in the pre-normalized lower word. This requirement concerns the retained residual state, not an independently calculated mathematical remainder.

6. **Unshifted normalization branch**

   If result assembly produces upper word `0x80000000` and lower word `0x00000201`, the returned bit pattern is `0x8000000000000201`.

7. **Shifted normalization branch**

   If result assembly produces upper word `0x40000000` and lower word `0x80000201`, the returned bit pattern is `0x8000000100000402`. The lower word’s top bit crosses into the upper word, and its low sticky bit moves to bit 1.

8. **Zero divisor-like pair**

   If both final input words are zero, no explicit divide-by-zero rejection occurs. The table index is zero, and arithmetic continues if that table byte is readable. A numeric division result or fault cannot be required from the available evidence.
