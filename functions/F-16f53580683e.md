# F-16f53580683e

## Purpose

F-16f53580683e performs an ordered sequence of reads and writes over an implicitly supplied address graph, then makes an unresolved indirect control transfer represented as a three-argument invocation.

The static material establishes memory operations, not an application-level purpose. It does not establish conventional node types, list operations, string processing, allocation records, or ownership relationships. Values recovered from fields are variously reused as data, byte sources, and addresses.

This contract distinguishes directly represented behavior from environmental assumptions and unresolved behavior. No runtime tests have been performed.

## Interface

### Entry state

The displayed interface declares no parameters or result, but consumes four incoming machine-state values:

| Contract designation | Use |
|---|---|
| A | Address of storage receiving byte and four-byte accesses. |
| B | Address-bearing value also used as a source of low-order bytes. |
| C | Address used for the initial read and an early byte write. |
| D | Four-byte value stored intact and truncated to a byte. |

These are documentary designations, not recovered parameter names or types. Their delivery mechanism and calling convention are **`documented_only`**.

Three external four-byte data sources, **G1**, **G2**, and **G3**, are read near the end. Their designations identify distinct source locations, not guaranteed distinct values.

### Width and notation

Unless otherwise stated:

- A field read or write is four bytes.
- A byte write retains the low eight bits of its source.
- A two-byte write retains the low sixteen bits.
- Offsets and constants are hexadecimal.
- “Self-address” means the address of the designated storage, represented in the four-byte address-bearing model.
- A **capture** retains the value from that particular read; it does not imply a later reread.

Thus decimal 100, 110, and 116 appear as `0x64`, `0x6e`, and `0x74`.

The representation uses four-byte integer and address-bearing values. It does not establish endianness, alignment requirements, or the execution environment’s signed-overflow and address-wrap rules. Arithmetic must not silently be widened to a different host address width.

### Preconditions and completion

Successful completion requires each dynamically selected address to support its actual access width. No validation, null check, graph-shape check, or recovery path is represented.

Storage regions may overlap. Earlier writes can therefore change later field reads, traversal destinations, external data sources, or arithmetic-address accesses. Documentary names do not imply disjoint objects.

There is no established explicit return value. Observable outputs are the ordered memory operations, resulting state changes, and final indirect transfer. The displayed representation returns if the indirect invocation returns; actual transfer and return behavior remain unresolved.

## Behavior

### Ordering requirements

The following phases are in represented order. Within each phase, the described ordering is significant. Captured values remain distinct from fresh reads even when their source addresses coincide.

Same-value rewrites, repeated writes, and temporary field contents are included. Their physical observability depends on the environment; they must not be discarded merely because a final-memory comparison would miss them.

### 1. Entry captures and initial graph selection

The first access captures C `+0x74` as the **entry capture**. C `+0x09` then receives the low byte of B. A `+0x54` receives the entry capture, A `+0x10` receives `0x6e`, B `+0x44` receives C, and A `+0x20` receives `0x6e`, in that order.

B `+0x64` is captured as the **initial B value**. Its low byte is written to A `+0x09`. A `+0x74` then selects **P**, whose `+0x54` is captured.

The next byte writes occur in this order:

- A `+0x1c`: `0x79`.
- B `+0x11`: low byte of the initial B value.
- B `+0x09`: low byte of D.
- A `+0x1c`: `0x68`.
- B `+0x11`: the same retained byte.
- P `+0x11`: low byte of B.

A `+0x50` is captured as the **A payload**. B `+0x44` receives D; B `+0x64` is rewritten with the initial B value; B `+0x34` receives that value; and A `+0x11` receives its low byte.

B `+0x74` is captured as the **initial B link**. A `+0x10` receives the A payload, and P `+0x54` is rewritten with its earlier capture.

A’s first byte receives the low byte of the A payload. Next, A `+0x09` receives the low byte of B; B `+0x14` selects **W**; P `+0x11` receives the low byte of A; A `+0x44` receives W; and A’s first-byte write is repeated.

P `+0x74` is captured as the **backward base**, followed by a read of P `+0x14` selecting **T**. A `+0x54` then receives A’s self-address.

### 2. Initial linked updates and backward-relative write

T `+0x04` selects a target receiving the low byte of the initial B link at `+0x11`, then byte `0x64` at `+0x10`. W `+0x54` receives `0x64` before that target receives `0x64` at `+0x60`.

The current W `+0x74` target is captured. W `+0x74` is replaced with T, and the captured former target receives `0x64` at `+0x30`.

T `+0x14` selects a child receiving the low byte of the initial B link at `+0x09`. W `+0x54` then receives W’s self-address.

A four-byte backward-relative write follows: the address twenty hexadecimal bytes before the backward base receives the value seventy-four hexadecimal bytes before that base.

The selected child’s `+0x14` is read to select a descendant. T `+0x11` receives the low byte of the entry capture. A fresh T `+0x14` read is retained as the **child-link capture**, whose low byte is written to the descendant’s `+0x15`.

T `+0x14` is read again to select **H**. W `+0x64` is captured as **O**, then rewritten with O. H `+0x0c` receives byte `0x73`; W `+0x15` receives the low byte of O; and T `+0x34` receives the child-link capture.

H `+0x74` is captured as the **early H link**. H `+0x54` receives H’s self-address; T `+0x0d` receives the low byte of W; T `+0x54` receives the child-link capture; and T `+0x14` receives H.

### 3. The `0x74` replacement group

A fresh W `+0x64` read is captured as **F**. O and F are separate captures, even if equal.

H `+0x10` receives byte `0x74`; W `+0x54` receives four-byte `0x74`; and H `+0x10` receives four-byte `0x74`. H `+0x74` is then captured as the **later H link**. T `+0x54` receives T’s self-address, followed by four-byte `0x74` at H `+0x30`.

The subsequent operations preserve these source distinctions and ordering:

1. W `+0x01` receives the low byte of O.
2. Address O `+0x09` receives the low byte of F.
3. W `+0x74` receives F.
4. W `+0x11` receives byte `0x74`.
5. H `+0x60` is captured as the **H payload**.
6. W `+0x11` receives the low byte of O.
7. W `+0x34` receives F.
8. H `+0x10` receives the low byte of the H payload.

W `+0x14` then selects **M**. T `+0x11` receives the low byte of the early H link; W `+0x44` receives T; and W `+0x11` receives the low byte of F.

Thus the three W `+0x11` writes in this group use, respectively, literal `0x74`, the older W `+0x64` capture O, and the fresh capture F.

### 4. The `0x66` group and following captures

W `+0x74` is captured as the **pre-update link**. W `+0x0d` receives the low byte of T.

M receives four-byte `0x66` at `+0x10`; W `+0x44` receives T again; M receives byte `0x66` at `+0x10`; W `+0x54` receives four-byte `0x66`; and M receives four-byte `0x66` at `+0x60`.

A fresh W `+0x74` read selects **R**. W `+0x74` is replaced with T, and R `+0x40` receives `0x66`. W `+0x0d` receives the low byte of the pre-update link.

R `+0x44` is now captured as the **R payload**, before either following self-address store. W `+0x54` receives W’s address, then the later H link’s target receives its own address at `+0x54`.

R `+0x14` selects a target. T `+0x11` receives the low byte of the R payload. A fresh T `+0x14` read supplies the byte written to that target’s `+0x15`.

T `+0x14` is read once more to select **L**. W `+0x64` is captured as **E1**; L `+0x20` receives `0x73`; and another W `+0x64` read is captured as **E2**. L `+0x09` receives the low byte of E2.

L `+0x74` selects **N**. N `+0x0d` receives the low byte of W. N `+0x54` is read and rewritten with that read value, then N `+0x09` receives byte `0x74`.

W `+0x44` receives E1, and N `+0x34` receives W. N `+0x04` selects **J**, which receives E2 at `+0x24`. W `+0x19` receives the low byte of E1.

J `+0x74` is then captured as **K**, followed by a read of J `+0x04` captured as the **replacement payload**. K is retained through the remainder of the function and supplies an address operand in the final two-byte store.

### 5. Later rewiring and retained-byte propagation

A fresh W `+0x74` read selects **R2**. R2 `+0x14` selects a target whose `+0x54` receives K. R2 `+0x04` then selects another target.

W `+0x0d` receives the low byte of E2 twice consecutively. W `+0x64` receives the replacement payload. The target selected through R2 `+0x04` receives `0x74` at `+0x30`.

R2 `+0x04` is read again, and that freshly selected object’s `+0x74` selects the **current traversal object**, designated **CT**.

A fresh W `+0x64` read supplies a retained byte **B64**, which is written to W `+0x1d`. The full read is not later substituted for B64.

W `+0x44` is read, and that value’s `+0x14` selects the **new W child**. CT `+0x34` receives K before W `+0x14` receives the new W child.

W `+0x54` is now captured as **S54**, before the new W child receives the low byte of W at `+0x09`.

CT `+0x04`, followed by the selected object’s `+0x74`, selects **S**. S `+0x15` receives the low byte of K. W `+0x54` then receives W’s self-address; W `+0x11` receives the low byte of CT; and S `+0x11` receives the low byte of S54. This last write uses the earlier capture, not the intervening self-address value.

S `+0x64` is captured as the **selected payload**. Immediately afterward, W `+0x09` receives B64. Only then is CT `+0x04` read afresh to select **U**. The W `+0x09` write does not use the selected payload’s byte.

U `+0x09` receives the low byte of W. U `+0x50` is captured as the **U payload**. U `+0x11` receives the low byte of the selected payload, and U `+0x09` again receives the low byte of W.

W `+0x14` receives the selected payload; W `+0x0d` receives the low byte of U; and U’s first byte receives the low byte of the U payload.

### 6. Final ordinary-field operations

CT `+0x74` is captured as **V**, then CT `+0x14` is captured as **X**. Both reads occur before U `+0x54` receives U’s self-address.

Only after that self-address store is X `+0x04` read to select **Y**. This separation matters if U’s storage overlaps CT or X.

The following writes occur in order:

- Y `+0x10`: byte `0x64`.
- W `+0x54`: four-byte `0x64`.
- Y `+0x40`: four-byte `0x64`.
- W `+0x0d`: low byte of the selected payload.
- X `+0x09`: low byte of Y.
- W `+0x24`: selected payload.
- X `+0x11`: low byte of W.

### 7. Arithmetic-address tail and indirect transfer

G1 is read, followed by W `+0x74`, captured as **Z**. The remaining accesses occur in this order:

1. Two bytes containing the low sixteen bits of Z are written at address Z plus W.
2. Two bytes containing the low sixteen bits of G1 are written at twice Y.
3. A character-typed byte is read at V plus W and converted to unsigned four-byte value **Q**.
4. Two bytes containing the low sixteen bits of Z are written at G1 plus Z.
5. The two-byte write at Z plus W is repeated.
6. Four-byte `0x45` is written at Q `+0x45`.
7. G2 is read, then G3.
8. W `+0x44` is captured as the **transfer payload**.
9. Byte `0x44` is written at Q `+0x44`.
10. G3 is written as four bytes at twice G2.
11. The low sixteen bits of G2 are written as two bytes at K plus G2.

The final destination uses K—the retained J `+0x74` capture made after W `+0x19` and before J `+0x04`. It does not use V, X, Y, Z, or a fresh traversal read.

The character conversion requires an environmental qualification. If the character load is signed, bytes `0x80`–`0xff` become negative before conversion to unsigned four-byte Q; for example, `0xff` yields `0xffffffff`. If the character type is unsigned, it yields `0x000000ff`. Character signedness is not independently established by the supplied type spelling.

Finally, **F-unresolved-01** is represented as invoked with:

1. Q bitwise-OR `0x44`.
2. G2.
3. The captured transfer payload.

The first argument uses OR, not addition. The third argument is captured before the final three writes and is not reread afterward.

## Acceptance examples

These are conditional static criteria, not executed tests.

1. **Entry truncation:** If B’s low byte is `0xab`, C `+0x09` receives `0xab` after the initial C `+0x74` capture.

2. **Distinct `0x74`-group captures:** If O’s low byte is `0x12` and F’s is `0x34`, W `+0x11` receives `0x74`, then `0x12`, then `0x34`. W `+0x01` receives `0x12`, while O `+0x09` receives `0x34`.

3. **Post-`0x66` propagation:** If R `+0x44` yields a value ending in `0x56`, the later T `+0x11` write uses `0x56`, regardless of intervening self-address stores.

4. **Retained W byte:** If B64 is `0x27` and the selected payload ends in `0x91`, W `+0x09` receives `0x27` immediately before the fresh read selecting U.

5. **Retained W `+0x54`:** If S54 ends in `0x42` but W’s address ends in `0x80`, S `+0x11` receives `0x42` despite the intervening W `+0x54` self-address store.

6. **Aliasing around U:** If U `+0x54` overlaps a CT link field, V and X retain their pre-store captures. Conversely, the later X `+0x04` read can observe the self-address store if its accessed bytes overlap.

7. **Final retained address:** If K and G2 are `0x1000` and `0x0200`, and this addition is valid in the execution environment, the final two-byte destination is `0x1200` and the stored value is `0x0200`.

8. **Tail conversion and OR:** Under signed-character interpretation, tail byte `0xff` gives Q equal to `0xffffffff`. For Q equal to `0x44`, the first transfer argument is `0x44`, not `0x88`.

9. **Partial failure:** A fault in a late two-byte write does not imply restoration of earlier ordinary-field mutations.
