# F-f04235044d6a

## Purpose

F-f04235044d6a selects one of two passkey-related resources from an object’s mode byte, obtains a 32-bit value through a preparation dependency, and passes that value to an indirectly dispatched object operation. After a cleanup dependency returns, it writes a corresponding one-byte state value into the object and returns the 32-bit value 1.

The established distinction between the two paths is:

- A zero mode byte selects the resource identified as `SwitchLayout_EnterPasskey` and ultimately writes state byte 0.
- Any nonzero mode byte selects the resource identified as `SwitchLayout_NewPasskey` and ultimately writes state byte 1.

The resource names suggest a passkey-layout transition. Actual display behavior, passkey handling, and the meaning of the state byte are not established by this function alone.

- Exactly zero selects the enter-passkey path.

## Acceptance examples

These examples are conditional behavioral criteria, not reports of executed tests.

### Zero selector

Given a valid object whose byte at `0xBD` is zero when read, and dependencies that return normally:

- Preparation receives the enter-passkey resource.
- Dispatch receives the preparation result.
- Cleanup receives the fourth-argument slot address.
- The final direct write stores one byte of value 0 at `0xBC`.
- The function returns 1.

The function itself does not write `0xBD`.

### Nonzero selector

Given the same validity conditions, but with selector byte `0xFF` when read:

- Preparation receives the new-passkey resource.
- The final direct write stores one byte of value 1 at `0xBC`.
- The return remains 1.

No branch requires the selector to equal exactly 1.

### Initial dependency changes selection

Suppose the selector is zero at entry, but F-dc842e45211e causes it to become nonzero before returning. If execution otherwise remains valid, the new-passkey branch is selected because the selector read occurs after that call.

This example does not assert that the dependency actually performs such a mutation.

### Selector changes after selection

Suppose the selector is zero at the actual read, and the indirect operation later changes it to a nonzero value. If cleanup returns normally and the object remains writable, the final state write is still 0. The selector is not re-read.

### Dispatch observes state before the final assignment

Suppose the state byte at `0xBC` initially contains `0x7E`, and neither initial processing nor preparation modifies it. The indirect operation is invoked before this function replaces that byte. The function does not guarantee that dispatch observes 0 or 1 merely because one will be written later.

### Unusual preparation result

Suppose preparation returns a 32-bit value of zero. The visible function still passes zero to the indirect operation; it does not treat zero as an error or skip dispatch. Whether that operation accepts zero is a separate dependency precondition.

### Cleanup does not return normally

If cleanup does not return normally, neither the final direct state assignment nor return value 1 is established. There is no visible fallback assignment before cleanup.
