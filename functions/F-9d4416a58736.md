# F-9d4416a58736

## Purpose

F-9d4416a58736 produces an eight-word result from a four-word input using fixed-width multiplication, doubling, addition, and explicit carry propagation.

Under the 32-bit word interpretation described below, with stable input and disjoint input/output storage, the mathematical result is the exact square of an unsigned 128-bit integer. The input and result use least-significant-word-first layouts. The result occupies 256 bits; no significant square bits are discarded.

This mathematical characterization does not establish an application purpose such as cryptography. It also does not establish support for in-place operation. The routine writes output before completing its input reads, so overlapping storage can change subsequent calculations.

No runtime tests have been performed. The contract below separates the arithmetic interpretation supported by static inspection from environmental and machine-level details that remain unknown.

## Behavior

### Fixed-width arithmetic model

The supplied arithmetic decomposes operand words into low and high 16-bit portions. It reconstructs word products using those portions and carries between 32-bit words.

For the numerical contract:

- Ordinary word results retain their low 32 bits.
- Right shifts of unsigned words are logical.
- A carry from adding two words is the overflow bit beyond bit 31.
- Unsigned comparisons detect wraparound where used.
- Carry information is explicitly propagated into higher result positions.

The 16-bit products themselves fit in 32 unsigned bits. Sums of products, doubled products, and shifted partial products can exceed one word; that overflow is material to the result.

Some intermediate quantities are represented with a signed integer type in the supplied material. The surrounding operations use them as 32-bit product fragments and carry accumulators. The mathematical characterization therefore assumes their intended machine-level wrapping behavior. It is not a claim that the representation has identical semantics under every language implementation or signed-overflow policy.

### Mathematical result for stable, independent storage

The arithmetic covers the four individual word squares and all six distinct cross-products:

\[
\begin{aligned}
A^2={}&a_0^2
+2a_0a_1B\\
&+(a_1^2+2a_0a_2)B^2\\
&+(2a_0a_3+2a_1a_2)B^3\\
&+(a_2^2+2a_1a_3)B^4\\

These are overlapping multiword contributions, not independent output words. Carries from each position feed the next position.

In particular, doubling a two-word cross-product can require a third bit above that product’s original width. The routine tracks that contribution rather than merely doubling each product word independently. It also accounts for carries produced when adding an already-accumulated contribution to a doubled product.

With the stated preconditions,

\[
R=A^2.
\]

Since \(0\leq A<2^{128}\), its square fits in the eight-word result.

### Overlap and changing input

For example, if both addresses identify the same first word, the first store replaces input word 0 before that word is read again. The routine therefore cannot be specified as generally supporting in-place squaring.

Likewise, externally changing input can affect separate half-word extractions or later cross-products. There is no visible snapshot, retry, consistency check, or synchronization mechanism. No coherent result is specified for concurrent mutation.
