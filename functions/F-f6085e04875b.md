# F-f6085e04875b

## Purpose

F-f6085e04875b replaces an association in a primary object, conditionally raises a 32-bit numeric field using unsigned ordering, and conditionally inserts the primary object at an address selected through a table.

The established behavior includes two unconditional dependency calls, one conditional dependency call, ordered field accesses, wrapping 32-bit table-address arithmetic, and conditional link updates. Interpreting the association as an owned reference, the numeric field as a rank, or the table as a collection of scheduling queues is **inferred intent**, not established behavior.

The function has no explicit return value. Its observable results are dependency calls and memory changes.

## Interface

### Explicit inputs

The function receives two 32-bit values used as addresses:

- **Primary address:** identifies the object whose association, numeric field, links, and flag may change.
- **Secondary address:** is passed to a dependency and subsequently stored in the primary object.

Neither input is locally checked for null, alignment, accessibility, or structural validity.

### Global input and indirection

A global location contains a 32-bit pointer value identifying a readable 32-bit cell. The cell’s contents can be used as a table base.

The function does not perform just one global-pointer evaluation:

1. It reads the global pointer value and retains that value as a **captured cell address**.
2. It evaluates the global pointer again, then reads through the pointer obtained by this second evaluation. That dereferenced value becomes the first argument of F-03b9616af95f.
3. Later, it reads through the captured cell address from step 1 to obtain the table base.

The second evaluation of the global pointer and the later read through the captured pointer are distinct operations. They need not be described as reads from the same cell without a stability assumption.

No synchronization or support for concurrent changes is established.

### Primary-object layout

Offsets are byte offsets from the primary address.

| Offset | Width | Established use |
|---|---:|---|
| +0x08 | 32 bits | Compared as unsigned with a derived secondary value; conditionally replaced; reread to derive an index. |

The +0x0C and +0x10 fields behave as backward and forward links under ordinary non-overlapping, stable-storage assumptions. That interpretation does not establish a broader list API or list invariant.

### Secondary-object layout

| Offset | Width | Established use |
|---|---:|---|
| +0x08 | 32 bits | Read after association replacement and incremented to form a comparison candidate. |

F-2609ef4ae406 receives the secondary address before this field is read. Validity on entry alone is insufficient: the later field access must remain valid after the dependencies return.

### Table addressing

The table contains four-byte values interpreted as object addresses or zero. For a 32-bit table base \(B\) and index bits \(j\), the selected address is:

\[
A = \bigl(B + ((4j)\bmod 2^{32})\bigr)\bmod 2^{32}.
\]

Both the unsigned multiplication by four and the addition of the table base wrap modulo \(2^{32}\).

Consequences include:

- Index 0 addresses \(B\).
- Index 0x40000000 also addresses \(B\).
- Index 0x7FFFFFFF addresses \((B-4)\bmod 2^{32}\).

A large accepted index therefore does not necessarily select a correspondingly distant entry. This arithmetic supplies neither a table-bounds guarantee nor a guarantee that different accepted indices select different addresses.

### Preconditions for normal completion

Normal completion requires:

- Each reached dependency call returns normally.
- The global pointer location is readable for both initial evaluations.
- The pointer obtained by the second global evaluation permits the initial dereference.
- The captured cell address permits its later dereference, regardless of dependency effects on the global location.
- Each primary and secondary field access is valid at the time it occurs.
- If insertion occurs, the wrapped selected table address is readable and writable.
- If the first final read of primary +0x10 is nonzero, the address obtained by the **second** final read permits a write at offset +0x0C.

The last condition is not merely a requirement that the original table head be valid. The destination comes from a later, separate field read.

These are access requirements, not checks performed by the function. No allocation sizes or table length are available.

## Behavior

### 1. Capture one pointer, evaluate the global pointer again, and call two dependencies

The function first reads the global pointer and retains the resulting cell address.

It then separately reads the global pointer again and dereferences the pointer obtained from that second evaluation. F-03b9616af95f receives:

1. The 32-bit value obtained by that dereference.
2. The primary address.

The function next calls F-2609ef4ae406 with the secondary address.

No local pointer check guards either call or the initial dereference. No return value from either dependency is consumed.

If the two initial global-pointer evaluations produce different addresses, the first dependency’s argument is read through the second address, while the first address remains captured for later use. This describes access order, not a concurrency guarantee.

### 2. Inspect the association and conditionally call a third dependency

After both unconditional calls return, the function reads primary +0x20.

- If the 32-bit value is nonzero, it calls F-029930293dcb.
- Otherwise, it omits that call.

No explicit argument is supplied to F-029930293dcb. In particular, the existing association is not explicitly passed.

The decision uses the association value observed after the first two calls. Its entry-time value is not sufficient to determine the branch. There is no comparison with the secondary address: an existing association equal to that address still triggers the call if nonzero.

### 3. Replace the association

After the conditional call, if any, returns, the function writes the secondary address to primary +0x20.

This write precedes the read of secondary +0x08. Aliasing can therefore affect the numeric value subsequently observed.

No rollback is shown if a later operation fails. No explicit allocation or deallocation appears. Ownership transfer and reference-management semantics remain unknown.

### 4. Compute a candidate and conditionally update the primary numeric field

The function reads secondary +0x08 and adds one to form a 32-bit candidate.

In the recovered 32-bit operational interpretation, the candidate wraps modulo \(2^{32}\):

- 0 becomes 1.
- 0x7FFFFFFF becomes 0x80000000.
- 0xFFFFFFFF becomes 0.

It then reads primary +0x08 and compares it with the candidate using **unsigned 32-bit ordering**.

- If the primary value is smaller, the candidate is written to primary +0x08.
- Otherwise, no local write to that field occurs.

Thus a wrapped candidate of zero cannot raise any unsigned primary value. A primary value of 0x80000000 is greater than 1 for this comparison, not less.

The displayed signed-looking addition does not establish the original source language’s overflow rules. No explicit overflow check or overflow-recovery branch is shown; original-language provenance remains unresolved.

### 5. Read the table base through the captured pointer

The function reads the 32-bit contents at the captured cell address. That value becomes the table base.

This access occurs after all dependency calls, association replacement, and the possible numeric update. It does **not** reevaluate the global pointer at this stage.

Consequently:

- A dependency’s change to the contents of the captured cell can change the table base used.
- A dependency’s change only to the global pointer does not redirect this later dereference.
- Preservation or continued validity of the captured cell is not guaranteed by any established dependency contract.

This table-base read occurs even if insertion will subsequently be skipped.

### 6. Derive the index and decide whether to insert

The function rereads primary +0x08 and subtracts one in the recovered 32-bit interpretation to obtain index bits \(j\).

If the signed 32-bit interpretation of \(j\) is nonnegative, it reads primary +0x14 and examines bit 0. If that signed interpretation is negative, it does not read the flag byte for this decision and does not insert.

Insertion therefore requires both:

1. The observed primary numeric value lies in the unsigned range 1 through 0x80000000, inclusive.
2. Bit 0 of the observed flag byte is clear.

Boundaries:

| Observed primary value | Index bits | Sign gate |
|---|---:|---|
| 0 | 0xFFFFFFFF | Fails |
| 1 | 0 | Passes |
| 0x40000001 | 0x40000000 | Passes |
| 0x80000000 | 0x7FFFFFFF | Passes |
| 0x80000001–0xFFFFFFFF | 0x80000000–0xFFFFFFFE | Fails |

The sign gate is not a bounds check. For passing indices, the actual access uses the wrapped address formula, not an unbounded mathematical offset.

### 7. Perform the conditional insertion

If either insertion condition fails, the function performs no local link, table-entry, or flag write. Earlier calls and field updates remain effective.

Otherwise, it performs these accesses in order:

1. Writes zero to primary +0x0C.
2. Reads the 32-bit value at the selected wrapped table address.
3. Writes that value to primary +0x10.
4. Writes the primary address to the selected table address.
5. Reads primary +0x14, sets bit 0, and writes the resulting byte back.
6. Reads primary +0x10 for a nonzero test.
7. If that test is nonzero, reads primary +0x10 **again** to obtain a destination address, then writes the primary address at destination +0x0C.

The flag read used by the update is separate from the earlier eligibility read. Bits 1–7 are preserved from the byte observed by the update.

The two final link reads are also separate. The destination write does not reuse the value tested in step 6. No stability guarantee between these reads is established, and the second value is not independently checked for zero. If the first value is nonzero and the second is zero, the subsequent write targets offset +0x0C from zero, subject to the target’s address behavior.

With valid, disjoint, stable storage, these operations prepend the primary object to the selected chain. That ordinary postcondition depends on those assumptions; it is not unconditional under aliasing or interference.

## Acceptance examples

These are conditional consequences of static evidence, **not executed tests**. Unless stated otherwise, assume normal dependency returns, no dependency mutations, valid non-overlapping storage, stable values between reads, and valid access at each selected wrapped address.

### Empty selected chain

Given primary numeric value 2, secondary numeric value 4, zero association, clear membership bit, and zero at table base +16:

- The first two dependencies are called in order; the third is omitted.
- The association becomes the secondary address.
- The primary numeric field becomes 5.

### Existing head

- Primary +0x0C becomes zero.
- Primary +0x10 receives the head address.
- The selected entry becomes the primary address.
- Bit 0 becomes set.
- Primary +0x10 is read for the nonzero test and read again for the destination.
- Under the stability assumption, the head’s +0x0C becomes the primary address.

### Already marked

Given primary numeric value 7, secondary numeric value 1, and bit 0 set:

- The primary numeric value remains 7.
- The association is replaced.
- The captured cell is still read for the table base.
- No local insertion writes occur.

No link-consistency repair is established.

### Nonzero existing association

If primary +0x20 is nonzero after the first two calls, F-029930293dcb runs before association replacement. This remains true when that association already equals the secondary address.

### Wrapped candidate and rejected index

Given secondary numeric value 0xFFFFFFFF, the candidate is zero and cannot raise the primary field.

If the primary field is also zero, index bits are 0xFFFFFFFF. Insertion is skipped without reading the membership byte for eligibility.

### Wrapped table addresses at accepted indices

Given final primary numeric value 0x40000001 and a clear membership bit, index 0x40000000 passes the sign gate and selects the table base itself.

Given final primary numeric value 0x80000000 and a clear membership bit, index 0x7FFFFFFF passes and selects table base minus four modulo \(2^{32}\). Normal completion requires that wrapped address to be valid; a conventionally large forward table is not sufficient by itself.

Given final primary numeric value 0x80000001, insertion is skipped.

### Captured pointer versus changed global pointer

Suppose both initial global evaluations identify cell A, and the first dependency receives A’s contents.

If a dependency subsequently changes the global pointer to identify cell B but leaves A valid, the later table-base read still accesses A. If it also replaces A’s contents, the replacement contents become the table base.

### Distinct final link reads

Conditionally, if the first final read of primary +0x10 is nonzero but the second yields a different address, the +0x0C write uses the second address. It does not use the tested value or an independently saved former head. This access rule does not establish that concurrent changes producing such observations are supported.
