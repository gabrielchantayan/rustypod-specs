# F-a70c1a932691

## Purpose

The supplied static representation describes a state-dependent routine that performs indirect calls, reads values from implicit execution state, writes memory through several derived addresses, and selects one of two substantially different continuations.

A higher-level purpose is not established. The memory operations resemble updates to linked records or execution contexts, but neither a data-structure interpretation nor a business meaning is justified.

This contract records the behavior represented by the supplied material. Its reliability is limited by explicit warnings about invalid instruction data and an unrecovered indirect transfer. It does not establish that the represented routine is executable as shown.

## Interface

### Explicit interface

The apparent interface has no declared arguments and no declared return value. That is not evidence of a self-contained, argument-free operation: the body consumes substantial incoming machine state.

The apparent ordinary-return continuation ends with an unresolved indirect transfer represented as a call, followed by a return. Whether that transfer actually returns is unknown.

### Widths and layouts

The represented memory accesses use 8-bit, 16-bit, and 32-bit quantities. A 64-bit call result is treated as two 32-bit halves; this does not establish a floating-point interpretation or an ABI-level aggregate type.

All offsets below are byte offsets. P is accessed at offsets 0, 4, 8, and 100. T is read at offsets 0 and 4, and its address plus 12 is later truncated for storage.

Values loaded as unsigned 16-bit quantities are zero-extended. Consequently, H, J, K, and L are each in the range 0 through 65,535 when first established. Their later use as addresses is literal in the representation; they must not be silently reinterpreted as offsets into an invented object.

## Acceptance examples

These examples are conditional static acceptance criteria, not observed test results.

### Repeated field writes remain observable

Given valid storage and dependencies that return, the common prefix writes H plus 52 first with P, later with H, later with J, and finally with H. An observer in the intervening dependencies may distinguish all four writes. Retaining only the final write would not satisfy this contract.

### Signed byte argument

If the fresh byte read for F-A22 is 128, the corresponding signed 32-bit argument is negative 128, not positive 128. This remains true regardless of the byte previously returned by F-A20.

### Independent halfword reads

If F-A24 changes the halfword at H plus J, F-A25 receives the sign-extended value of the later read, not a cached value from the earlier call preparation.

### Narrow-address behavior

If K is 256 and the halfword at address 260 is 512, L becomes 512. In the overflow-clear continuation, the direct store involving W0 targets address 512 plus J, subject to the execution environment’s address arithmetic and accessibility rules.

### Overflow-selected path without a loop iteration

If the interrupt returns and the zero condition is set at the first loop check, F-B20 and F-B21 are not invoked. The later writes at U plus 13 and U plus 9 use the low byte of G.

### Overflow-selected path with an iteration

If the loop executes at least once and later exits, those two stores use byte value 96. If the zero condition never becomes set and the loop calls keep returning, the later stores and breakpoint are not reached.

### Shift-derived argument

Assuming the represented signed value is retained across the intervening calls, an initially negative R produces negative one as the argument to F-C18. An initially nonnegative R produces zero.

### Interrupted execution

If software interrupt 115 does not return, the store preceding it may have occurred, but no subsequent overflow-selected table reads or final byte writes are required to occur.
