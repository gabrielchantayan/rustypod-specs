# F-19e9375c0de5

## Purpose

F-19e9375c0de5 attempts to insert a record consisting of a 20-byte header and a caller-supplied payload into a buffer-backed container. It selects or checks an identifier, determines an insertion location, requests a storage change, updates container metadata, constructs the record, and optionally publishes its buffer-relative offset.

“Container,” “record,” “length,” “count,” and “ordinal” describe inferred field roles. The established contract is the observable argument handling, arithmetic, dependency calls, memory accesses, status-global reads, and return ordering described below.

The operation is not demonstrably transactional. A failure can occur after dependencies have changed storage or after explicit metadata writes. No rollback is visible.

## Interface

Eight ordered arguments are accepted. The result is a 32-bit status.

| Argument | Representation | Role |
|---|---|---|
| Container reference | Pointer to a 32-bit buffer-address cell | Supplies the buffer base; dependencies receive this reference and may modify the cell. |
| Container offset | Signed 32-bit integer | Selects a header relative to the buffer base. Zero is normalized to 12 only after identifier selection. |
| Record type | Unsigned 32-bit integer | Must be nonzero; used in lookups and record construction. |
| Requested identifier | Unsigned 32-bit integer | Nonzero requests that identifier; zero requests automatic selection. |
| Insertion ordinal | Signed 32-bit integer | Zero requests automatic selection; the effective ordinal must be positive. |
| Payload length | Signed 32-bit integer | Participates in size calculations and is passed unchanged to the copy dependency. |
| Payload source | 32-bit address-like value | Passed to the copy dependency; zero is rejected only for nonzero payload length. |
| Optional result destination | Pointer to a 32-bit cell, or null | Receives an offset only after record construction and the copy call. |

Address and size calculations use 32-bit quantities. The supplied representation also exposes signed 16-bit narrowing and byte-reversal operations. Arithmetic descriptions here preserve the represented 32-bit bit patterns and narrowing behavior; they do not authorize unbounded arithmetic or assume that signed overflow is portable across implementation languages.

### Preconditions and validation limits

The function checks a null container reference, but does not establish the validity of the referenced buffer address, selected header, insertion location, payload source, or output destination. It does not check allocation bounds, capacity, alignment, aliasing, or arithmetic overflow.

Negative payload lengths are not explicitly rejected when the payload source is nonzero. Zero length permits a zero source, and the copy dependency is still called.

No ownership transfer, allocation policy, release policy, or synchronization guarantee is established. Dependencies must not be assumed to preserve the buffer-address cell, status globals, or referenced storage.

## Behavior

### Initial validation and state gate

A null container reference causes an immediate read of the null-reference status global and return of that sampled 32-bit value. No dependency is called.

Otherwise, a zero record type causes an immediate read of the zero-type status global and return of that value. No buffer-address read or dependency call precedes this return.

For remaining inputs, two calls to F-c19b4c0cb7f7 are made in order:

1. Read the buffer-address cell, add 10, and call the dependency at that address. Retain the result’s low byte.
2. Independently read the buffer-address cell again, add 10, and call the dependency at that newly calculated address. Retain bits 8–15.

Both calls occur before the selected portions are tested. If the first dependency changes the buffer-address cell, the second call uses the changed base; these are not necessarily reads from the same address.

If either selected portion is nonzero, call F-cf3f46523dd1 and return −117. Otherwise continue.

### Identifier selection

Identifier lookups use F-4384ab7eb5a7 with the container reference, the original container offset, record type, zero ordinal, candidate identifier, and three trailing zeros. In particular, an original offset of zero remains zero during this phase.

For a nonzero requested identifier, perform exactly one such lookup. A nonzero result causes an immediate read of the identifier-conflict status global and direct return of that sampled value. F-cf3f46523dd1 is not called on this return path. A zero lookup result accepts the requested identifier.

Automatic selection starts at identifier 1. After an occupied candidate, advancement retains the incremented value’s low 16 bits, interprets them as signed, and sign-extends into the 32-bit candidate. The sequence is therefore:

- 1 through 32767;
- 4294934528 through 4294967295, representing −32768 through −1;
- zero.

This is not a search through unsigned identifiers 1–65535. Zero is looked up if reached, but cannot be accepted. Whether that lookup returns zero or nonzero, reaching candidate zero leads to F-cf3f46523dd1 followed by return of −108.

### Header selection and observations

After selecting an identifier, call F-577314e8c690. Then normalize a zero container offset to 12.

Read the current buffer-address cell and add the normalized offset to form a retained absolute header address. Subsequent observations in this phase use that retained address rather than reconstructing it after every dependency.

At header offset 0, call F-c223c8c1cf8e four times. Assemble a 32-bit quantity using:

- the first result’s low byte as the most significant byte;
- the second result’s bits 8–15 as the next byte;
- the third result’s bits 16–23 as the next byte;
- the fourth result’s bits 24–31 as the least significant byte.

With stable conventional raw loads, this decodes a big-endian 32-bit field. Separate calls may supply inconsistent observations.

If the assembled value is greater than 20 under unsigned comparison:

1. Call F-c19b4c0cb7f7 twice at retained header address plus 14.
2. Retain the first result’s low byte and the second result’s bits 8–15.
3. Read the header-state status global.
4. Test the retained byte portions.

If both portions are zero, retain the sampled status across a call to F-cf3f46523dd1 and return it. Do not reread the global after that call.

The status-global read also occurs when either portion is nonzero and execution continues. It does not occur on this branch when the assembled length is at most 20.

For continuing execution, independently perform two more F-c19b4c0cb7f7 calls at header offset 14, followed by four more F-c223c8c1cf8e calls at header offset 0. Subtract 20 from this second assembled 32-bit length and retain the difference.

Set the special sizing condition when the newly selected count-byte portions are both zero and the retained length difference is nonzero.

The first length observation governs only the rejection branch; the second supplies the retained difference. Under stable conventional reads, zero count with length greater than 20 is rejected, but zero count with length below 20 can activate special sizing.

### Ordinal selection and argument checks

If the supplied ordinal is zero, call F-0104b49ee457 with the container reference, normalized container offset, and record type. Increment its result, retain the low 16 bits, and interpret them as a signed 16-bit ordinal.

Reject either of the following with F-cf3f46523dd1 followed by return of −50:

- Effective ordinal less than 1.
- Nonzero payload length with zero payload source.

An explicitly supplied positive ordinal has no upper-bound check and is not narrowed at this validation stage.

### Insertion-location selection

Call F-4384ab7eb5a7 with the container reference, normalized offset, record type, effective ordinal, zero identifier, and three trailing zeros.

A nonzero result supplies the absolute insertion address directly.

For a zero result:

- If the ordinal is 1, form the insertion address from a fresh buffer-base read, the normalized header offset, the retained length difference, and 20.
- Otherwise, look up the preceding ordinal after signed 16-bit narrowing, again with zero identifier and three trailing zeros.

Immediately after the predecessor lookup, read the missing-predecessor status global, before testing the lookup result. This read occurs even when the predecessor exists.

If the predecessor result is zero, retain that sampled status across F-cf3f46523dd1 and return it without rereading the global. If nonzero, continue by making four F-c223c8c1cf8e calls at the retained predecessor address, assembling its leading field as above, and adding that value to the predecessor address.

Finally, convert the selected absolute insertion address to a relative offset by subtracting a fresh buffer-base read.

A large explicit ordinal can therefore pass validation but cause a negative signed 16-bit predecessor ordinal to be supplied to the lookup dependency.

### Storage-change request

Calculate the storage delta as payload length plus 20 using the represented 32-bit arithmetic. If special sizing is active, subtract the retained length difference.

Call, in order:

1. F-cf3f46523dd1 with the container reference.
2. F-8fe91a385499 with the container reference, insertion offset, zero, and storage delta.
3. F-577314e8c690 with the container reference.

The third call occurs regardless of the storage-change result. That result is retained across it.

For a nonzero storage-change result, call F-cf3f46523dd1 and return the retained status. No subsequent explicit metadata or record writes occur on this path. Dependency effects are not undone.

### Container metadata updates

After a zero storage-change result, reconstruct the absolute header address using the current buffer-address cell and retained normalized offset.

Then perform these operations in order:

1. Make four F-c223c8c1cf8e calls at the reconstructed header address and assemble the current length.
2. Add the storage delta.
3. Pass the byte-reversed 32-bit result to F-38272e1956e5 at header offset 0.
4. Make two F-c19b4c0cb7f7 calls at header offset 14.
5. Assemble the selected bytes in reversed order, increment, and pass the reversed low 16-bit result to F-192d46d1d024 at header offset 14.
6. Call F-7c73e97e8565 with the container reference, normalized header offset, storage delta, and zero.

Under conventional accessors, the count increment wraps modulo 65536. There is no overflow rejection.

The absolute header address remains fixed throughout these accesses, even if a dependency changes the buffer-address cell.

If F-7c73e97e8565 returns nonzero, call F-cf3f46523dd1 and return that retained status. The already-issued length and count writes are not explicitly reversed.

### Record construction and output publication

After a zero metadata-adjustment result, replace a zero insertion offset with 12. Add the resulting offset to a fresh buffer-base read to form the record address.

Issue the following writes in order:

| Record-relative offset | Width | Supplied value |
|---|---:|---|
| 0 | 32 bits | Byte-reversed payload length plus 20 |
| 4 | 32 bits | Byte-reversed record type |
| 8 | 32 bits | Byte-reversed selected identifier |
| 12 | 16 bits | Zero |
| 14 | 16 bits | Zero |
| 16 | 32 bits | Zero |

F-38272e1956e5 receives the 32-bit writes; F-192d46d1d024 receives the 16-bit writes. Conventional raw stores yield a big-endian record header. The record size is payload length plus 20, not necessarily the storage delta.

Call F-70a021fc7c24 with payload source, retained record address plus 20, and the original payload length. Its result is ignored.

If the optional result destination is nonnull:

- For a zero absolute record address, write zero without reading the buffer base for subtraction.
- Otherwise, read the buffer-address cell at publication time, subtract it from the retained record address, and write that 32-bit difference.

Finally call F-cf3f46523dd1 and return the retained zero result from F-7c73e97e8565. Neither the copy result nor a later status-global value replaces that result.

## Side effects

The principal mutation sequence is storage-change request, container-length write, container-count write, metadata-adjustment call, six record-header writes, payload-copy call, optional output write, and final dependency call.

The function also reads external status globals at distinct observable points:

| Status role | Read timing |
|---|---|
| Null reference | Immediately on that return path; no dependency calls. |
| Zero type | Immediately on that return path; no dependency calls. |
| Identifier conflict | After the nonzero requested-identifier lookup result; direct return without final dependency. |
| Header state | On the greater-than-20 branch, after both count-accessor calls and before testing their selected bytes, including continuing paths. |
| Missing predecessor | Immediately after predecessor lookup and before testing its result, including successful predecessor paths. |

These are sampled global values, not established immutable constants. For header-state and missing-predecessor returns, the sampled value survives the final F-cf3f46523dd1 call; later changes to the global do not replace it.

No explicit output-destination write occurs on failure, but dependencies and aliased buffer writes may still affect that location. Aliasing among the container-reference cell, payload, output, and modified buffer is not checked.

The record address is retained across all record writes and the copy call. Dependencies changing the base do not cause those destinations to be recomputed. The final dependency call occurs after output publication and may have further unknown effects.

## Acceptance examples

These are conditional static criteria, not executed tests.

1. **Null reference:** Read and return the null-reference status global immediately, without any dependency calls, regardless of the remaining arguments.

2. **Changing base during state reads:** If the initial base is A and the first F-c19b4c0cb7f7 call changes it to B, the calls receive A plus 10 and B plus 10 respectively. Both calls occur even when the first selected byte is nonzero. A nonzero selected portion causes F-cf3f46523dd1 and return of −117.

3. **Requested-identifier conflict:** A nonzero lookup result is followed by a read of the conflict-status global and immediate return. A value changed by the lookup is observable; no final dependency is called.

4. **Header-status sampling on continuation:** If the first assembled length exceeds 20 and either selected count portion is nonzero, read the header-state status global after both accessors, then continue. Do not omit that global read merely because no error is returned.

5. **Retained header error:** If that branch’s selected count portions are both zero and the sampled status is S, return S after F-cf3f46523dd1, even if that dependency changes the status global to T.

6. **Predecessor-status sampling:** After a predecessor lookup, read the missing-predecessor status global whether the lookup succeeds or fails. On failure, retain the sampled value across the final dependency call.

7. **Automatic identifier boundary:** After occupied identifiers 1 through 32767, check 4294934528 next. If selection reaches zero, look it up but return −108 rather than accept it.

8. **Automatic ordinal overflow:** A result of 32767 from F-0104b49ee457 yields effective ordinal −32768 after increment and narrowing. Return −50 without requesting storage change.

9. **Empty payload:** Zero length and zero source pass the payload-source check. On otherwise successful execution, write record size 20 and invoke the copy dependency with length zero.

10. **Storage failure:** A nonzero F-8fe91a385499 result is followed by F-577314e8c690 and F-cf3f46523dd1, then returned unchanged. Do not issue subsequent explicit metadata or record writes.

11. **Late metadata failure:** A nonzero F-7c73e97e8565 result occurs after the length and count writes. Do not construct the record or publish the output.

12. **Ordinary insertion:** With stable bases, conventional accessors, no special sizing, payload length 3, and successful checked dependencies, request delta 23, write record size 23, construct the specified header, and request a three-byte copy.

13. **Short zero-count header:** With stable length 16 and count zero, retain difference −4. For zero payload length, request delta 24 but write record size 20.

14. **Publication after base change:** If the copy dependency changes the base, publish the retained record address minus that changed base, unless the retained record address is zero.
