# F-df71a03c61e0

## Purpose

The established behavior is an unconditional loop of indirect dependency calls, memory reads and writes, a software-breakpoint operation, and changes to implicit machine state. No normal return, success result, termination condition, or recovery path is represented.

An application-level purpose is not established. Repeated state processing is a possible interpretation, but remains **inferred intent**, not a requirement of this contract.

Every operation described below is conditional on execution reaching it. A dependency that does not return, an inaccessible memory location, or a non-resuming breakpoint can prevent subsequent operations.

## Interface

### Explicit interface

- No explicit parameters are declared.
- No return value is declared.
- No return operation is represented.
- Observable outputs are dependency invocations, memory effects, the breakpoint operation, and implicit-state changes.

The absence of declared parameters does not imply independence from the entry environment.

### Implicit inputs

Execution depends on:

- A link/control value used to calculate the first call target of each iteration.
- An implicit address base, designated **B**.
- An incoming register value, designated **R**, used in a byte-store address.
- Two global 32-bit pointer-like values, read at separate points in each iteration.
- Memory reachable through fixed addresses, computed addresses, loaded pointers, and dependency results.
- Primary and secondary outputs of dependencies.
- Dependency behavior, including effects on memory and implicit machine state.

B and R are contract notation, not additional declared parameters.

### Widths and layout

| Item | Represented width or interpretation |
|---|---|
| Byte access | 8 bits |
| Halfword access | 16 bits |
| Word access | 32 bits |
| Pointer-like load | 32 bits |
| Paired result | 64 bits, consumed as two 32-bit halves |
| Address and ordinary integer calculations | 32-bit quantities |

Unsigned halfword reads are zero-extended. Halfword and byte writes retain the low 16 and low 8 bits, respectively.

For a paired result, **low** denotes bits 0–31 and **high** denotes bits 32–63. The right shift applied to the second paired result’s low half is logical.

Offsets below are byte offsets. They establish accessed locations, not complete object layouts, field meanings, allocation sizes, or ownership.

For derived 32-bit values, this contract uses low-32-bit arithmetic to describe the represented machine-width result. Some source expressions involve signed integer arithmetic; overflow, signed left shifts, and integer-to-address conversion are not thereby established as portable language-level operations. Exact exceptional behavior remains **documented_only**.

Byte order, alignment requirements, and memory-ordering guarantees are not established.

### Preconditions

Uninterrupted execution requires every reached call target to be executable, every reached access to be permitted by the platform, and every dependency to return compatibly with the represented continuation.

These are execution conditions, not checks performed by the function. No explicit null, bounds, allocation-success, or error-status validation is represented.

### 1. Opening calls and first retained address

1. Invoke F-000000000001 with two explicit zero arguments. Its target is the current link/control value plus `0xFFE`.
2. Establish the separate zero-byte term used in the argument calculation below.
3. Invoke F-000000000002.
4. Invoke F-000000000003.
5. Read the first global 32-bit pointer-like value; retain it as **P**.
6. Invoke F-000000000004.
7. Invoke F-000000000005 and capture its paired result.

Let that result’s halves be **L₁** and **H₁**. Invoke F-000000000006 with:

- First argument: L₁.
- Second argument: the low 32 bits of H₁ + L₁.

The represented calculation includes an additional zero-byte term, which does not change the second argument. Sites 005 and 006 calculate the same target address.

After site 006 returns:

1. Store its represented secondary 8-bit output at P + `0x11`.
2. Invoke F-000000000007.
3. Store the retained zero byte at P + `0x15`.
4. Invoke F-000000000008.
5. Store that call’s 16-bit result at its represented secondary address output + `0x0C`.

P is captured once. Intervening dependencies are not assumed to preserve either the global location from which P was read or the storage addressed by P. There is no re-read or validity check before these stores.

### 3. Indexed result and breakpoint

### 5. Third paired result and base adjustment

Then:

1. Invoke F-000000000034.
2. Store the retained byte at W + R + `0x19`.
3. Invoke F-000000000035.
4. Store M as a word at A + `0x44`.
5. Invoke F-000000000036.

## Acceptance examples

These are conditional static examples, not executed tests. Each assumes the relevant operation is reached, accesses succeed, and intervening effects do not invalidate the stated conditions.

1. **Upper-bit extraction.** If L₂ is `0xFC000003`, the word stored at B + `0x26C` is 63. The later word at Q + `0x54` is `0xF000000C`.

2. **Secondary destination.** If site 008 supplies halfword `0xBEEF` and secondary address `0x1000`, its halfword store targets `0x100C`. This establishes no ownership.

3. **Indexed truncation.** If T is `0x12345678` and J is 3, D is 12. The indexed halfword store targets `0x12345684` and writes `0x5678`.

4. **Fixed address.** The word supplying V is read at `0x2218`, independently of T, U, and the site-025 result.

5. **Zero-extension.** If the halfword at H₃ + `0x14` is `0xFFFF`, both W propagation stores write `0x0000FFFF`, not `0xFFFFFFFF`.

6. **Base adjustment.** If B is `0x1000` at the L₃ store and remains so until the decrement, that store targets `0x1258`; the explicit decrement changes B to `0x0F0C`.

7. **Byte retention.** If K is 7, the byte source is address 35. If W is 2 and R is `0x2000` at the destination calculation, the destination is `0x201B`. The stored byte is the value read before site 034, even if that dependency changes the source byte afterward.

8. **Equal targets.** Sites 005 and 006 must be modeled as calls to the same calculated target, not arbitrarily independent dependency targets. Different argument uses do not erase that relationship.

9. **Next-iteration target.** If the assigned link/control value survives site 037 unchanged, the next site-001 target is `0x0871302F`. If it does not survive unchanged, this specific target is not guaranteed.

10. **Breakpoint interruption.** If the breakpoint does not resume, the U-relative address read and every later operation in that iteration are not reached.
