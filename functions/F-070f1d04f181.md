# F-070f1d04f181

## Purpose

F-070f1d04f181 prepares a byte sequence from a caller-supplied cursor, optionally transforms that sequence, and submits it to F-704ab9e25f00 together with a resolved selector and a descriptor.

Its observable responsibilities include:

- Resolving the selector and decoding arguments.
- Performing a preliminary resolution step for selector −4 under restricted conditions.
- Obtaining a sequence length, an updated working cursor, and two byte-valued flags from F-38f7a73546d9.
- Selecting a direct-input, cursor-span, or transformed-buffer representation.
- Adding a zero byte after one form of transformed payload.
- Updating the caller’s cursor only when F-704ab9e25f00 returns nonzero.
- Conditionally releasing temporary storage according to a mutable ownership word.
- Reporting selected failures through F-4fc89ec41a6d.

These are established structural behaviors. Interpretations such as “parser,” “decoder,” “allocator,” or “consumer” describe apparent roles, not independently established dependency contracts.

## Interface

The function accepts eight arguments and returns a signed 32-bit integer.

| Position | Contract-level name | Representation and use |
|---|---|---|
| 1 | Destination | A 32-bit value passed unchanged to F-704ab9e25f00. Zero causes immediate diagnostic failure. Whether a nonzero value is a pointer, handle, or identifier is unknown. |
| 2 | Cursor reference | Address of a writable 32-bit cursor cell. The function reads this cell and, on downstream success, replaces it with the working cursor. |
| 3 | Context | An opaque 32-bit value forwarded to F-38f7a73546d9. |
| 4 | Descriptor | Address of a byte-addressable object. Byte offset 0 is inspected; a 32-bit field at byte offset 4 is conditionally read. The original address is later passed to F-704ab9e25f00. |
| 5 | Requested selector | A signed 32-bit value. Its role depends on descriptor byte 0. |
| 6 | Decode option | An opaque 32-bit value forwarded to the main decoding call, except when explicitly replaced with zero. |
| 7 | Mode | A signed 32-bit value used in the selector −4 eligibility check and forwarded unchanged to the main decoding call. |
| 8 | Auxiliary byte reference | A possibly null byte pointer forwarded to decoding calls. The function itself writes zero through it only on the resolved-selector −3 path after successful main decoding. |

The observed representation uses 32-bit integers, 32-bit address-bearing values, and one-byte flags. The descriptor’s complete layout, alignment requirements, and total size are not established. A non-5 first byte requires a readable 32-bit field beginning at offset 4; a first byte equal to 5 avoids that field read.

### Preconditions

For defined execution along the selected path:

- A nonzero destination requires a readable descriptor byte at offset 0.
- The cursor reference must support all reads and any successful cursor commit.
- Cursor-derived data and lengths must satisfy the requirements of the invoked dependencies.
- Any nonnull auxiliary byte reference must satisfy the dependencies’ requirements and, when the resolved selector becomes −3, support a one-byte write.
- Any temporary-buffer pointer and length produced by dependencies must support the terminator write and possible release described below.

The function does not visibly validate pointer accessibility, input bounds, negative lengths, address arithmetic overflow, or descriptor consistency.

### Return values

There is no established Boolean-only return contract.

- Selected diagnostic failures return 0.
- A main decoding result of −1 is returned immediately.
- A nonzero result from F-704ab9e25f00 changes the eventual return value to 1.
- Otherwise, the eventual return normally remains the main decoding result.

Consequently, downstream failure can coexist with a positive return value. A caller must not infer that the cursor was committed merely because the result is positive.

## Behavior

### 1. Initial selection

The ownership word begins as a 32-bit zero.

A zero destination causes a call to F-4fc89ec41a6d with arguments 13 and 108, followed by return 0. This path does not visibly dereference the descriptor or cursor reference.

For a nonzero destination, descriptor byte 0 determines two working values:

- If the byte equals 5, the requested selector becomes the resolved selector, and the effective decoding selector starts as −1.
- Otherwise, the resolved selector is read as a 32-bit value from descriptor offset 4, and the requested selector becomes the effective decoding selector.

The function retains the original descriptor address for downstream use. It does not make a snapshot of the complete descriptor.

### 2. Preliminary handling for resolved selector −4

If the resolved selector is −4, the function rejects the request when either:

- The effective decoding selector is nonnegative; or
- The mode is nonzero.

Rejection uses the diagnostic call with arguments 13 and 108 and returns 0.

Otherwise, the current caller cursor is copied into a working cursor and F-38f7a73546d9 is called in a preliminary-resolution configuration:

- Its first argument is zero.
- It receives a writable reference to the resolved selector.
- It receives a four-byte local output region whose first byte is subsequently inspected.
- Two intervening output arguments are zero.
- It receives a reference to the working cursor and the context.
- Its selector argument is the all-one 32-bit value.
- The next two arguments are zero.
- It receives the auxiliary byte reference.

Only a zero return from this preliminary call is treated as failure. In particular, a return of −1 is not independently rejected at this stage.

On a nonzero return, a nonzero first byte in the preliminary output region forces the resolved selector to −3. If that byte is zero, any selector value written by the dependency is retained.

The working cursor from this preliminary call is not directly carried into the main decoding call. The function reloads the caller’s cursor cell afterward. Dependency side effects on that cell, including effects through aliases, can therefore affect the main call.

### 3. Main decoding

The working cursor is loaded from the caller’s cursor cell.

If the effective decoding selector is −1, it is replaced with the current resolved selector, and the decode option is forced to zero. Other negative effective selectors are not normalized.

F-38f7a73546d9 then receives:

1. A reference to a 32-bit sequence length.
2. Zero.
3. Zero.
4. A four-byte output region, whose first byte becomes the conversion flag.
5. A four-byte output region, whose first byte becomes the representation flag.
6. A reference to the working cursor.
7. The context.
8. The effective decoding selector.
9. The effective decode option.
10. The mode.
11. The auxiliary byte reference.

The length, flags, and working cursor are dependency outputs. Only the first byte of each flag region is inspected by this function.

A zero result causes diagnostic failure and return 0. A result of −1 is returned immediately, with no subsequent conversion, submission, cursor commit, or cleanup by this function. Every other result enters payload preparation and is retained as the provisional return value.

### 4. Payload preparation for selectors 16, 17, and −3

Resolved selectors 16 and 17 require a nonzero representation flag. A zero flag causes diagnostic failure and return 0.

Resolved selector −3 enters the same payload-preparation family without requiring a nonzero representation flag. Before doing so, it writes zero to the auxiliary byte if that reference is nonnull. This write occurs after main decoding and before conversion or downstream submission. It is not rolled back if later work fails.

For these three selectors, the function rereads the caller’s cursor cell as a span origin.

If the conversion flag is zero:

- The submitted payload address is that reread origin.
- The working cursor advances by the decoded length.
- The submitted length becomes the distance from the reread origin to the advanced working cursor.
- The temporary-buffer pointer field is explicitly set to zero.

Thus, the submitted span may include bytes between the caller’s cursor and the working cursor returned by main decoding, not merely the decoded-length suffix.

If the conversion flag is nonzero, F-c305688d2b8e is called with:

- A zero first argument.
- A reference to the working cursor.
- The decoded length.
- The conversion flag byte.
- Two all-one 32-bit arguments.

A zero conversion result skips downstream submission and proceeds to cleanup and return. It does not issue the diagnostic used by other failure paths.

For a nonzero conversion result:

- The submitted payload address is the reread caller cursor.
- The submitted length is the updated working cursor minus that origin.

No temporary-buffer pointer initialization is visible in this nonzero-conversion-flag branch.

### 5. Payload preparation for other selectors

For every other resolved selector, the representation flag selects the representation.

If the representation flag is zero:

- The payload address is the working cursor returned by main decoding.
- The working cursor advances by the decoded length.
- The submitted length remains the decoded length.
- No terminator is added.

The conversion flag is not used to choose a conversion in this branch.

If the representation flag is nonzero, three adjacent 32-bit local fields are initialized to zero. They are subsequently used as a temporary-output record containing a length-like field, a pointer field, and a third field of unknown meaning.

F-c305688d2b8e receives the address of the first field, a reference to the working cursor, the decoded length, the conversion flag byte, an all-one 32-bit argument, and zero.

Immediately after that call, the first field is copied into the submitted-length value. A zero conversion result skips submission and proceeds to cleanup and return.

On nonzero conversion success, F-9a8ea7637eda receives the temporary-output record and a requested size equal to the first field plus one.

A zero result from this call causes diagnostic failure and return 0. This failure bypasses the common cleanup tail.

On nonzero success:

- One zero byte is written at the temporary-buffer pointer plus the previously copied submitted length.
- The ownership word becomes 1.
- The temporary-buffer pointer becomes the submitted payload address.

The submitted length is not incremented for the added zero byte. It is also not reloaded from the record after F-9a8ea7637eda returns. That dependency must therefore provide storage suitable for the previously captured length, even if it changes record contents.

### 6. Submission, cursor commit, and cleanup

F-704ab9e25f00 receives:

1. The original destination.
2. The prepared payload address.
3. The prepared length.
4. The resolved selector.
5. A reference to the 32-bit ownership word.
6. The original descriptor address.

A nonzero return causes two actions, in order:

- The eventual return value becomes 1.
- The caller’s cursor cell is overwritten with the working cursor.

A zero return leaves the provisional main-decoding result unchanged and performs no explicit cursor commit.

Cleanup inspects only the low eight bits of the ownership word. If that byte is nonzero and the temporary-buffer pointer is nonzero, F-5990a26eaaa3 is called with that pointer. The function then returns the retained result.

F-704ab9e25f00 can modify the ownership word before cleanup. Its nonzero or zero return does not itself determine whether release occurs.

## Side effects

### Cursor state

The explicit caller-cursor write occurs only after a nonzero submission result. It precedes any final release call.

This does not guarantee transactional cursor behavior. Dependencies receive state-bearing arguments and may have additional effects; aliases may expose the caller’s cursor cell. Failure means “no explicit commit by this function,” not “all caller state is unchanged.”

### Auxiliary byte

The function explicitly clears the auxiliary byte only for resolved selector −3, after main decoding succeeds with a result other than −1. Dependencies also receive this pointer and may modify it independently.

### Temporary storage and ownership

The buffered representation explicitly writes a trailing zero and initially marks the buffer for cleanup.

The mutable ownership word suggests a transfer-or-retain protocol, but that interpretation is inferred. Established behavior is narrower:

- Only its low byte controls cleanup.
- The downstream dependency may change it.
- A zero pointer prevents release even with a nonzero low byte.
- Several non-buffered paths do not visibly initialize the temporary-buffer pointer.
- A size-adjustment failure bypasses common cleanup.

No guarantee is established that conversion failure or size-adjustment failure releases dependency-created storage.

### Diagnostics

F-4fc89ec41a6d is called with the fixed pair 13 and 108 for:

- A zero destination.
- An ineligible selector −4 request.
- A zero preliminary-resolution result.
- A zero main-decoding result.
- A zero representation flag for selector 16 or 17.
- A zero size-adjustment result.

Conversion failure and downstream submission failure do not directly invoke that diagnostic.

## Acceptance examples

These are conditional static acceptance examples, not executed tests. They assume dependencies return and provide valid outputs for the stated scenario.

1. **Zero destination.**  
   With destination zero, the function calls F-4fc89ec41a6d with 13 and 108 and returns 0 without explicitly reading the descriptor or cursor cell.

2. **Descriptor byte 5 overrides the descriptor-field route.**  
   With descriptor byte 0 equal to 5 and requested selector 7, the resolved selector is 7. Main decoding receives selector 7 and decode option zero. The 32-bit field at descriptor offset 4 is not read by this function.

3. **Ineligible preliminary resolution.**  
   With resolved selector −4 and effective decoding selector 0, diagnostic failure occurs before preliminary decoding. A nonzero mode also rejects the request even when the effective decoding selector is negative.

4. **Preliminary −1 is not terminal.**  
   If an eligible preliminary call returns −1, the function continues because only zero is rejected there. If its first output byte is nonzero, the resolved selector becomes −3.

5. **Main −1 is terminal.**  
   If main decoding returns −1, the function returns −1 without submission or an explicit caller-cursor commit.

6. **Expanded cursor span.**  
   For selector 16, suppose the representation flag is nonzero, the conversion flag is zero, the reread caller cursor is 100, the decoded working cursor is 104, and the decoded length is 3. Submission receives address 100 and length 7. A nonzero submission result commits cursor 107.

7. **Conversion failure preserves the decoding result.**  
   If main decoding returns 2 and a subsequently required conversion returns zero, submission is skipped and the eventual return is 2, subject to cleanup. The function performs no explicit cursor commit and adds no diagnostic for that conversion failure.

8. **Terminator is outside the submitted length.**  
   If buffered conversion produces a captured length of 4, successful size adjustment is requested for 5. A zero byte is written at buffer offset 4, while submission receives length 4.

9. **Submission failure is not necessarily return zero.**  
   If main decoding returns 2 and submission returns zero, the function returns 2 after applicable cleanup and does not explicitly commit the working cursor.

10. **Ownership uses one byte.**  
    If submission leaves the ownership word equal to 256, its low byte is zero and cleanup does not call F-5990a26eaaa3. If it leaves the word equal to 1 and the temporary pointer is nonzero, cleanup calls that dependency after any successful cursor commit.

## Uncertainties

The following are **documented_only**:

- The semantic meaning of selector values, descriptor tags, both flag bytes, and the mode.
- The complete descriptor and temporary-output-record layouts.
- Signedness of promoted flag bytes when forwarded to conversion.
- Dependency output guarantees, especially on nonzero results other than 1.
- Allocation, resizing, retention, and release responsibilities.
- Global-state effects and aliasing across dependency calls.
- Behavior when downstream code requests cleanup on a path without an initialized temporary-buffer pointer.
- Behavior for invalid pointers, negative lengths, overflowing address calculations, or insufficient output capacity.

Length addition, cursor addition, cursor subtraction, and the length-plus-one request use 32-bit integer-valued expressions in the supplied representation. There are no visible overflow checks. Exact machine behavior at signed-overflow boundaries is not established; mathematical unbounded arithmetic must not be assumed. Endianness is also not established by the supplied representation.
