The supplied static representation does not establish an application-level purpose. Descriptions such as initialization, serialization, or device control would be inferred intent, not demonstrated behavior. No runtime tests have been performed.

## Behavior

### Arithmetic interpretation

Define:

- \(\operatorname{lo8}(v)\): the low eight bits of \(v\).
- \(\operatorname{lo16}(v)\): the low sixteen bits of \(v\).
- \([P]\): 1 if predicate \(P\) holds, otherwise 0.
- \(\lor\): bitwise OR.

The principal derived values are:

\[
X=x^2
\]

\[

\[
L=X+0x41+[K=0]

\[

\[

The final comparison, \(R\leq D\), is unsigned. The comparison between \(T\) and \(A\) involves code-address-like values; its concrete ordering semantics are not recovered. It must not be replaced with an assumed signed-integer comparison.

These formulas express dependencies, not a guarantee of portable signed arithmetic. In particular, squaring, addition, negation, and address formation may exceed represented signed ranges.

For the **conditional 32-bit machine interpretation**, arithmetic and addresses are reduced modulo \(2^{32}\), and narrow stores retain their low bits. The numerical acceptance examples use this interpretation. It does not establish source-language overflow rules.

### Layout, aliasing, and overwrite behavior

No structure, array, or object layout is established beyond the listed byte, halfword, and word accesses. Byte order is unspecified.

Writes 2 and 5 have the same destination and payload because both use retained \(A\) and its captured low halfword. They remain separate stores. Intervening stores, device semantics, or observers can distinguish them.

They share a starting address only when those address calculations agree. Under modular 32-bit arithmetic, equality of the samples is sufficient but not necessary: doubling also gives equal addresses for samples differing by \(2^{31}\).

If their starting addresses agree and both writes complete as ordinary memory accesses, write 14 replaces the earlier byte and writes three additional bytes. A later overlapping write, including write 15, may change that region again.

Other destinations may overlap completely or partially. There is no visible overlap detection or normalization. Final ordinary-memory contents depend on actual destinations, store order, widths, byte order, and any subsequent dependency effects.

## Acceptance examples

These are conditional static examples, not executed tests. Unless stated otherwise, they assume modular 32-bit arithmetic, accessible ordinary memory, successful preceding operations, no interference, and no unintended aliases.

### Initial narrowing

With \(x=0x12345678\) and \(O=0x10\), write 1 targets \(0x12345688\) and stores the 16-bit value \(0x5678\).

This establishes neither byte order nor address validity. The later square uses the full original \(x\), not its narrowed halfword.

### Comparison-dependent destination and payload

For \(B_1=0x100\):

- If \(T\leq A\) is true, \(K=0x147\); write 4 targets \(0xfffffd72\) and stores \(0xb9\).
- If false, \(K=0x146\); write 4 targets \(0xfffffd74\) and stores \(0xba\).

The comparison changes both address and payload.

For \(B_1=0xffffffba\), a false comparison gives \(K=0\) and \(L=X+0x42\). A true comparison gives \(K=1\) and \(L=X+0x41\). The zero test applies to \(K\), not directly to \(B_1\).

### Stable late-seed samples

If \(I_1=I_2=0x20\), writes 11 and 14 both begin at \(0x40\). Write 11 stores \(\operatorname{lo8}(D)\); write 14 later stores \(H\) as a 32-bit value there.

The overwrite statement assumes successful ordinary-memory accesses and no later overlapping modification when assessing final contents.

### Different late-seed samples

If the two reads instead yield \(I_1=0x20\) and \(I_2=0x30\):

- Write 11 targets \(0x60\).
- Write 14 targets \(0x40\).
- Write 15 targets \(y+0x20\) and stores \(0x0020\).
- \(N\) is calculated from \(0x20\), not \(0x30\).

This case requires an environment capable of yielding different samples despite no intervening explicit store.

### Unsigned comparison and distinct unsigned-base samples

Let \(I_1=0x20\), \(D=0x100\), and \(R=0x80\). The unsigned comparison is true, so \(N=0x6f\).

If \(J_1=0x1000\) and \(J_2=0x2000\), write 13 stores \(0x6f\) at \(0x206f\), while the explicit call argument is \(0x106f\).

If \(R=0x101\), with those other samples unchanged, \(N=0x6e\), the destination is \(0x206e\), and the call argument is \(0x106e\).

### Addition is not OR

With \(N=0x6f\) and stable \(J_1=J_2=0x60\), write 13 targets \(0xcf\), but the call argument is \(0x6f\). Equal samples do not make the two operations interchangeable.

### Earlier stores can affect later sampling

If a preceding store changes the location supplying \(B_1\), write 12 uses twice the subsequently read \(B_2\), not twice the earlier \(B_1\).

Conversely, changing the storage originally supplying \(A\) does not change the retained address value or captured halfword used by subsequent stores.
