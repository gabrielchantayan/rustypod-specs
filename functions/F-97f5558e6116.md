# F-97f5558e6116

## Purpose

F-97f5558e6116 consumes a counted sequence of bytes, conditionally forwards each byte’s low seven bits to a context-dependent operation, and then performs a finalization sequence. Its result is either zero or the first 32-bit word of a temporary record associated with an object obtained from global state.

The supplied static representation establishes the call sequence, field accesses, branch conditions, and explicit return values described below. It does not establish the domain meaning of the context, input bytes, global records, or returned value.

An interpretation such as “process input, finalize, and optionally update an associated object” is inferred intent only. In particular, the nonzero return value must not be assumed to be a status code, allocation, or owned object.

## Interface

### Arguments

The interface has four arguments in a 32-bit address and integer model:

1. **Context address:** a 32-bit value used as an address and passed unchanged to several dependencies. This function directly reads one-byte fields at context offsets `0xA1` and `0xDA`.
2. **Input descriptor address:** an address of a word-oriented descriptor. The directly used layout is:
   - Offset `0x00`: a 32-bit address of the first input byte.
   - Offset `0x04`: not directly accessed.
   - Offset `0x08`: a 32-bit count, represented as a signed integer in the supplied material.
3. **Record payload:** a 32-bit unsigned value placed in the third word of a temporary record when the finalization path finds a nonzero object address.
4. **Initial scratch value:** a 32-bit unsigned value initially assigned to the same scratch word later used for byte processing and the temporary record. No observable use of its incoming value is established: byte processing overwrites it before passing its address, and object finalization overwrites it with the third argument before exposing the record.

The descriptor count is read before the descriptor’s input address. Both are captured before byte processing begins. Later changes to the descriptor fields do not directly change those captured values.

### Result

The result is a 32-bit integer:

- Zero if the context field at `0xDA`, examined after the initial finalization calls, is zero.
- Zero if that field is nonzero but the selected global record’s object field is zero.
- Otherwise, the first word of the temporary record after all applicable dependency calls.

The temporary record initially contains the object address in its first word. Dependencies receiving the record address may change that word. Therefore, the result is not necessarily the original object address.

### Preconditions and memory validity

For the ordinary, bounded interpretation of the input loop:

- The descriptor must support the two 32-bit reads described above.
- The count must be nonnegative.
- For a positive count, the input address must identify that many readable bytes.
- The context and any subsequently selected global records and objects must support every field access actually reached.
- Address additions must identify valid storage without unsupported address overflow.

A zero count requires no input-byte dereference, although the input-address word is still read from the descriptor.

The supplied material contains no explicit null checks for the context, descriptor, or global record base. The nonzero checks on selected object-related fields do not validate the storage behind those addresses. Behavior following an invalid access is not specified by this contract.

## Behavior

### 1. Input processing

For a nonnegative count, the function processes exactly that many bytes in increasing address order.

For each byte:

1. It reads the byte and advances its private input position by one.
2. It replaces the scratch word with the byte masked to its low seven bits. The resulting 32-bit value is in the range 0 through 127.
3. It reads the context’s one-byte field at offset `0xA1`.
4. If that field is 0, 2, 3, 4, 5, or 6, it invokes F-5b70037ac2cd with the context address and the address of the scratch word.
5. For field value 1, or any value outside the listed accepted set, it consumes the byte without invoking F-5b70037ac2cd.

The context field is read separately for every byte, after that byte has been read. It is not captured once for the whole input sequence. If a dependency changes the field, that change can affect later bytes.

F-5b70037ac2cd receives a writable address, not merely the masked value. Its return value is not used by this function. Any modification it makes to the scratch word is superseded by the next byte’s masked value, or by the third argument if the object-finalization path is subsequently reached.

Changes made by dependencies to unread input bytes can affect subsequent reads. Conversely, changes to the descriptor’s count or input-address fields do not cause this function to reload those fields.

### 2. Mandatory finalization

After all input bytes have been consumed, including when the initial count is zero, the function calls:

1. F-aefe67f0fd0e with the context address.
2. F-92bea7c30bd6 with no explicit arguments.

Only after those calls does it capture the global record base used for later cached-base accesses.

It then reads the context byte at offset `0xDA`. If that byte is zero, it returns zero immediately. Input processing and both mandatory finalization calls have already occurred on this path.

### 3. Conditional global-record processing

If the context byte at `0xDA` is nonzero:

1. It reads the 32-bit field at offset `0x08` from the global record selected by the global record reference. If that field is nonzero, it calls F-92bea7c30bd6 again.
2. It reads the 32-bit field at offset `0x0C` using the previously captured global record base. If that field is nonzero, it calls F-92bea7c30bd6 again.
3. It reads the 32-bit field at offset `0x10`, again using that captured base, to obtain an object address.

These accesses are sequential, not a snapshot of all three fields. A conditional call between accesses may change fields that have not yet been read.

The retained base is significant: if a conditional call changes the global record reference, the later `0x0C` and `0x10` reads still use the previously captured base. They do not follow the newly selected record.

If the object field is zero, the function returns zero.

### 4. Temporary record construction

For a nonzero object address, the function constructs a three-word temporary record with the following layout:

| Offset | Width | Initial value |
|---|---:|---|
| `0x00` | 32 bits | Object address |
| `0x04` | 32 bits | Object address plus `0x80` |
| `0x08` | 32 bits | Third argument |

The record occupies temporary storage within this invocation. Its address is passed to dependencies only in the conditional processing described below.

The function then invokes F-3fac671648b8 with no explicit arguments.

### 5. Optional object processing

Further processing occurs only if all three conditions hold, evaluated in this order:

1. F-3fac671648b8 returned a nonzero 32-bit value.
2. The byte at object offset `0xA0` is zero.
3. A byte accessed through a separate global byte reference is nonzero.

The second condition is not read if the first fails. The third is not read if either earlier condition fails. The object byte and global byte are read after F-3fac671648b8 returns, so changes made by that dependency can affect the decision.

If any condition fails, the function returns the temporary record’s first word without invoking the remaining object-processing dependencies.

If all conditions hold:

1. It captures the 32-bit related-object field at object offset `0x34`.
2. It invokes F-e57b05520b65 with the temporary record address and two identical address arguments, each equal to the original object address plus `0x80`.
3. If the captured related-object field is nonzero, it invokes F-ee8733a08210 with the temporary record address and the captured address plus `0xD0`.
4. It invokes F-ffe0d92c57b7 with the original object address.
5. If F-ffe0d92c57b7 returns a nonzero value, it invokes F-c9b5d17d8d1e and then F-4d037ecf0f82. Each receives that returned value as its first argument and the temporary record address as its second argument.
6. It returns the temporary record’s current first word.

The related-object address is captured before F-e57b05520b65. A change to the object’s `0x34` field during that call does not change the address used for the conditional F-ee8733a08210 call.

Likewise, changes to the record’s first word do not redirect later uses of the original object address. F-ffe0d92c57b7 still receives the original object address.

## Side effects

The function explicitly writes its private processing state, including the scratch word and temporary record. It does not directly write the caller’s descriptor, input bytes, context fields, global record fields, or object fields.

That direct-write limitation does not imply those locations remain unchanged. Dependencies may mutate shared state or reachable memory. In particular:

- F-5b70037ac2cd receives the context and a scratch-word address.
- Several dependencies receive the temporary record address.
- Other dependencies may access globals even when they receive no explicit arguments.

For a nonnegative input count, F-92bea7c30bd6 is called at least once and at most three times. The second and third calls depend on the context flag and the two sequential global-record field tests.

No direct allocation, deallocation, or ownership transfer is shown. Ownership and lifetime effects inside dependencies are unknown. The function does not establish that any object remains valid across those calls.

The temporary record address is valid during the invocation. Safe retention beyond the invocation is not established. The returned value is a record word, not the temporary record’s address.

## Acceptance examples

These are conditional contract examples, not executed tests. They assume valid reached memory accesses and normal dependency returns.

1. **Empty input with finalization disabled.**  
   With count zero and context offset `0xDA` zero when examined, no input byte is read and F-5b70037ac2cd is not called. F-aefe67f0fd0e and the mandatory F-92bea7c30bd6 call still occur. The result is zero.

2. **Seven-bit normalization.**  
   With input bytes `0x80`, `0xFF`, and `0x41`, and context offset `0xA1` equal to 2 at each check, F-5b70037ac2cd observes initial scratch values 0, 127, and 65, respectively. The high bit is discarded independently for every byte.

3. **Consumption without dispatch.**  
   With a positive count and context offset `0xA1` equal to 1 throughout, every input byte is still read and consumed, but none causes a F-5b70037ac2cd call. Finalization still follows.

4. **Mode changes between bytes.**  
   If the first byte sees mode 0 and its F-5b70037ac2cd call changes the mode to 1, the second byte is consumed without dispatch, provided no intervening effect changes that mode again.

5. **Conditional finalization calls.**  
   With context offset `0xDA` nonzero and both tested global-record fields nonzero when read, F-92bea7c30bd6 is called three times total. If the later object field is zero, the result is nevertheless zero.

6. **Object gate rejected.**  
   With a nonzero object and F-3fac671648b8 returning zero, the object’s `0xA0` byte and global gate byte are not read. No later object-processing dependency runs. The result is the original object address.

7. **Captured related-object address.**  
   If the `0x34` field is nonzero before F-e57b05520b65 but that dependency clears it, F-ee8733a08210 still receives the previously captured address plus `0xD0`.

8. **Modified record result.**  
   If applicable record-processing dependencies leave the first record word equal to a value different from the original object address, that modified value is returned. A zero replacement yields a zero result.

9. **Fourth argument has no established effect.**  
   Two invocations differing only in the fourth argument have no differing explicit branch, dependency argument value, or return value established by this function’s data flow. This is not a guarantee about external observation of arbitrary temporary storage.
