# F-d2f7d724437e

## Purpose

F-d2f7d724437e interprets a short prefix of a caller-supplied byte region and delegates further processing to F-cd7e1905512f.

The prefix has two possible sizes. A first byte equal to 4 selects a three-byte prefix containing a two-byte field. Every other first-byte value selects a two-byte prefix containing a one-byte field. The function passes the original context value, a fixed zero, the first-byte value, the decoded field, a pointer past the prefix, and a masked remaining-length value to the dependency.

The established behavior is prefix interpretation and delegation. A packet format, command protocol, validation role, or meaning for the decoded field is not established.

## Behavior

### Prefix selection

The function first reads the character at offset 0.

- If that value equals 4, it selects a prefix size of three bytes.
- Otherwise, it selects a prefix size of two bytes.

Plain-character signedness does not affect whether the byte pattern for 4 selects the three-byte case. It can affect the discriminator value subsequently forwarded for bytes whose high bit is set.

The selected size remains fixed for the remainder of the function. The function does not reselect the prefix size when preparing the dependency call.

### Field extraction

In the two-byte-prefix case, the field is the byte at offset 1 interpreted as unsigned. Its numeric range is 0 through 255. Conversion to the 16-bit unsigned field representation does not change its value.

In the three-byte-prefix case, the function exchanges the two bytes of the native unsigned 16-bit value accessed at offset 1. The resulting field has a numeric range of 0 through 65,535.

For example, with stable input bytes `12 34` at offsets 1 and 2:

- A little-endian native 16-bit access produces a final field value of hexadecimal `1234`.
- A big-endian native 16-bit access produces a final field value of hexadecimal `3412`.

The supplied expression references the 16-bit location twice. Stable ordinary memory gives the same result as exchanging the bytes of one native 16-bit value. The listing does not establish a single-load guarantee, an atomic snapshot, or a defined ordering between those two references.

### Dependency arguments

After field extraction, the function invokes F-cd7e1905512f once on the normal path, with six positional arguments:

| Position | Value |
|---|---|
| 1 | Original opaque context value |
| 2 | Integer zero |
| 3 | Character at input offset 0, converted to `int` |
| 4 | Extracted unsigned 16-bit field value |
| 5 | Input address advanced by the selected prefix size |
| 6 | Supplied length minus the selected prefix size, masked with hexadecimal `FFFF` |

The third argument comes from a further reference to offset 0, rather than an explicitly retained copy of the initial discriminator. With stable input, the two observations agree. If an external actor changes the input, the function does not establish snapshot consistency between prefix selection, field extraction, and the forwarded discriminator.

The final argument preserves only the low 16 bits of the subtraction result. Assuming defined signed subtraction, its numeric range is 0 through 65,535. It is not a saturating subtraction and is not an error indicator.

Consequences include:

- A supplied length equal to the prefix size produces zero.
- A supplied length one less than the prefix size produces 65,535.
- A difference of 65,536 produces zero.
- A negative supplied length can produce a large nonnegative forwarded value.

The mask occurs after subtraction. It does not establish defined behavior if the preceding signed subtraction overflows. In particular, values near the minimum representable signed integer require care.
