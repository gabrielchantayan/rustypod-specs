# F-5ae03d3507dc

## Purpose

F-5ae03d3507dc conditionally updates a 32-bit state field in a caller-supplied object. It supports two selector values, both requiring the object’s classification to equal hexadecimal 0x16.

- Selector 1 stores a supplied 32-bit value. For a nonzero value, it inspects a nested object’s classification and may pass a nested payload to a dependency before clearing the payload field.
- Selector 2 stores a Boolean-like result indicating whether an outer link or a nested payload is null.
- Any unsupported selector or initial classification invokes a diagnostic dependency and, if that dependency returns normally, returns zero.

These operations are established by the supplied static evidence. The higher-level meaning of the classifications, state field, links, and payload is unknown. In particular, the payload-processing call is not established to free memory.

## Interface

### Inputs and result

The function receives three arguments:

| Argument | Contract |
|---|---|
| Object address | Address used as the base for fixed-offset memory accesses. The visible representation uses a 32-bit address-bearing argument. |
| Selector | A 32-bit integer compared for equality with 1 and 2. All other bit patterns take the unsupported-operation path after the initial classification call. |
| Supplied value | An unsigned 32-bit value. Used only by the accepted selector-1 path. |

The result is an unsigned 32-bit value:

- Accepted selector 1: the supplied value, unchanged.
- Accepted selector 2: exactly 0 or 1.
- Unsupported operation: 0, provided the diagnostic dependency returns normally.

The supplied value is not converted to a Boolean for selector 1. Values such as 2 or 0xFFFFFFFF are stored and returned without normalization.

### Preconditions

For a normally completing invocation:

- The root’s field at offset 0x10 must be readable before any selector-specific behavior.
- A successful selector-1 or selector-2 operation requires the root’s state field to be writable.
- Additional readable or writable locations are required only when the selected path reaches them.
- Address-bearing links that are dereferenced must identify accessible storage at the relevant offsets.
- Dependencies must permit the arguments passed to them and must return normally for the corresponding return behavior to apply.

A zero outer link is explicitly handled only on the accepted selector-2 path. A zero inner link is not explicitly handled. The visible implementation does not define a safe failure result for invalid memory.

## Behavior

### Common classification and dispatch

Every invocation begins by reading the root field at offset 0x10 and passing that four-byte value to F-2eb743f270d1.

This call occurs even when the selector is unsupported. The function does not first reject selectors outside 1 and 2.

The returned classification controls dispatch:

- Selector 1 is accepted only when the result equals 0x16.
- Selector 2 is accepted only when the result equals 0x16.
- Every other combination invokes F-4fc89ec41a6d with arguments 0x21 and 0x68, then returns zero if the call returns.

For an unsupported combination, the function itself does not write the root state or traverse the nested links. This does not imply that the classification or diagnostic dependencies leave memory unchanged.

### Selector 1: store the supplied value

After selector 1 and classification 0x16 have been established, the function writes the supplied value to the root state field at offset 0x0C.

This write occurs before any nested-link traversal.

#### Zero supplied value

When the supplied value is zero, the function returns zero immediately after the state write.

On this path, the function itself:

- Does not read the root’s outer link.
- Does not inspect the nested classification.
- Does not call F-aea2075beb12.
- Does not clear a payload field.

Thus, inaccessible nested links do not matter to this path, provided the initial classification operation and root state write are valid.

#### Nonzero supplied value

For a nonzero supplied value, the function:

1. Reads the root’s outer link.
2. Reads the inner link at offset 0x14 of the outer-linked object.
3. Reads the classification input at offset 0x10 of the inner-linked object.
4. Calls F-2eb743f270d1 with that input.

There is no explicit null check during this traversal.

If the nested classification differs from 0x15, the function returns the supplied value. It performs no direct payload-field read, payload-processing call, or payload clear on that branch.

If the nested classification equals 0x15, the function obtains a payload by traversing the links again:

1. Reread the root’s outer link.
2. Read that object’s inner link.
3. Read the payload at offset 0x14 of that inner-linked object.
4. Pass the payload to F-aea2075beb12.

After F-aea2075beb12 returns, the function traverses the links yet again and writes zero to the resulting inner-linked object’s payload field.

The function then returns the original supplied value.

The nested classification does not establish the identity of the later payload target. The links are reread after the nested classification call and again after the payload-processing call. A dependency that changes these links can therefore cause:

- The classified object and the payload-source object to differ.
- The payload-source object and the cleared object to differ.
- A later traversal to fail even if an earlier traversal succeeded.

There is no explicit payload-nonzero test before calling F-aea2075beb12. A zero payload is passed when the nested classification is 0x15 and the payload read yields zero.

### Selector 2: compute and store a nullness result

After selector 2 and classification 0x16 have been established, the function reads the root’s outer link.

If the outer link is zero:

- No inner-link or payload read is performed.
- The function writes 1 to the root state.
- The function returns 1.

If the outer link is nonzero:

- The function reads the inner link at offset 0x14 of the outer-linked object.
- It reads the payload at offset 0x14 of the inner-linked object.
- It writes 1 to the root state if that payload is zero; otherwise it writes 0.
- It returns the value written.

A nonzero outer link does not make a zero inner link safe. There is no intervening check before accessing the inner-linked object’s payload.

Selector 2 does not inspect the nested classification and does not invoke F-aea2075beb12. Its supplied-value argument has no effect on this path.

### Widths and arithmetic

The observable state and payload accesses are four bytes wide. Address-bearing fields are also loaded as four-byte quantities.

No arithmetic is performed on the supplied value. Its full 32-bit pattern is preserved on selector 1.

Selector 2 normalizes its result to exactly 0 or 1; it does not preserve a payload’s numeric magnitude.

Address calculations use fixed byte offsets. The evidence contains no overflow checks for those calculations. Behavior at invalid, wrapped, misaligned, or otherwise unsupported addresses is not established as a recoverable error.

## Side effects

### Direct memory writes

The visible function performs only these direct writes:

| Condition | Write |
|---|---|
| Accepted selector 1 | Supplied value to root offset 0x0C |
| Accepted selector 1, nonzero supplied value, nested classification 0x15, payload-processing call returns | Zero to the payload field selected by the post-call traversal |
| Accepted selector 2 | Computed 0-or-1 result to root offset 0x0C |

These are individual writes, not an atomic transaction. In particular, selector 1 updates the root state before operations that may fail or fail to return. There is no visible rollback.

The function does not reread the state field to determine its return value. Consequently, the result remains the supplied value on selector 1 even if a dependency changes the state field or the final payload clear aliases it.

### Dependency effects and ownership

No dependency is established to preserve globals, object fields, links, or memory ownership.

Calling F-aea2075beb12 does not, by itself, establish ownership transfer or deallocation. The subsequent payload clear establishes only a four-byte zero write at the location obtained by the final traversal.

If that dependency invalidates storage needed by the final traversal, the visible function has no explicit protection against the resulting invalid access.

There are no visible direct allocations or direct deallocations in this function. Effects performed inside dependencies remain outside the supplied evidence.

## Acceptance examples

These are conditional static acceptance cases, not executed tests. Unless stated otherwise, assume valid accessed storage, normal dependency returns, and no dependency-induced mutation of relevant fields.

1. **Selector 1 with zero.**  
   Initial classification is 0x16 and the supplied value is zero. The root state becomes zero and the result is zero. No nested-link traversal occurs.

2. **Selector 1 with an arbitrary nonzero value.**  
   Initial classification is 0x16, supplied value is 0xFFFFFFFF, and nested classification is not 0x15. The root state becomes 0xFFFFFFFF and the result is 0xFFFFFFFF. No payload-processing call or direct payload clear occurs.

3. **Selector 1 with payload processing.**  
   Initial classification is 0x16, supplied value is 7, and nested classification is 0x15. The root state is written with 7 before nested inspection. F-aea2075beb12 receives the payload. After that call returns, the selected payload field is cleared, and the result is 7.

4. **Zero payload still processed.**  
   Under the preceding classification conditions, the payload is zero. F-aea2075beb12 is still called with zero. The payload field selected afterward is written with zero.

5. **Selector 2 with a null outer link.**  
   Initial classification is 0x16 and the outer link is zero. The root state becomes 1 and the result is 1, without accessing an outer-linked object.

6. **Selector 2 with a zero payload.**  
   Initial classification is 0x16, both links permit the required accesses, and the payload is zero. The root state and result are 1.

7. **Selector 2 with a nonzero payload.**  
   Under the same accessibility conditions, a nonzero payload produces root state 0 and result 0. The supplied-value argument is irrelevant.

8. **Unsupported selector.**  
   Selector is 3. The initial classification call still occurs. F-4fc89ec41a6d then receives 0x21 and 0x68. If it returns normally, the result is zero; this function performs no direct state write.

9. **Unsupported root classification.**  
   Selector is 1 or 2, but the initial classification is not 0x16. The diagnostic path is taken without the corresponding direct state update.

10. **Links change during payload processing.**  
    If F-aea2075beb12 changes a link, the final zero write follows the new link chain. Acceptance must not require clearing the original payload-source field.
