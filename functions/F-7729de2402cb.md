# F-7729de2402cb

## Purpose

The supplied static representation establishes the operations described below. It does not establish a higher-level purpose such as parsing, rendering, allocation, or device control. No such purpose is assumed.

## Behavior

### 1. Initial writes and calls

The first explicit memory operation stores the low 16 bits of the fourth argument at the first argument’s address minus 21.

The routine then invokes F-U01 through a target derived from incoming link state. The returned 32-bit value is treated as an address base. At that address plus 36, the routine stores the low 16 bits of the ambient halfword source.

Next, it invokes F-U02 and then F-U03. Neither call has explicit arguments in the supplied representation. F-U03 supplies a 32-bit result used in the following calculations.

Before invoking the next dependency, the routine captures a Boolean condition:

- Arithmetically shift the F-U03 result right by nine.
- Interpret that shifted bit pattern as unsigned.
- Test whether it is greater than `0xFFFFFFBE`.

Under the stated 32-bit arithmetic model, this condition is true exactly when the signed F-U03 result lies between −33,280 and −1, inclusive.

The routine invokes F-U04 with three explicit arguments, in order:

1. The F-U03 result.
2. That result arithmetically shifted right by nine, then increased by 65.
3. The fourth argument minus 60, with 32-bit wrapping, then arithmetically shifted right by 20.

F-U04 returns a represented 64-bit pair. Its lower 32 bits become an address-like component; its upper 32 bits become a signed control component.

The previously captured Boolean is not recomputed from the F-U04 result.

### 2. Initial branch selection

If the captured Boolean is false, execution immediately enters the common path described below.

If it is true, the routine first stores the low 16 bits of the ambient halfword source at the lower F-U04 result plus 42.

It then compares two Boolean values:

- Whether the ambient halfword source is negative.
- Whether signed subtraction of 47 from the upper F-U04 result would overflow.

If those Boolean values are equal, execution enters the common path.

If they differ, execution enters the iteration body directly. Its initial state is:

- Control component: the upper F-U04 result.
- First call argument: the lower F-U04 result logically shifted right by 25.
- Pending stored value: ambient difference base minus ambient halfword source, modulo \(2^{32}\).
- Indirect-call selector: the initial selector established before F-U04.

The overflow test is not a signed comparison of the upper result against 47. In particular, overflow occurs only for upper-result values from −2,147,483,648 through −2,147,483,602, inclusive.

### 3. Iteration body

The body first invokes F-U05. Its target is derived by aligning the current selector down to a four-byte boundary and applying a fixed displacement. It receives:

1. The current first call argument.
2. The current control component.
3. An address into this routine’s stack storage.

The stack pointer argument permits the callee to access that storage. Its intended structure and valid extent are not established.

The routine then invokes F-U06, which supplies another represented 64-bit result.

Next, it:

1. Forms an incremented control value by adding ten to the current control component.
2. Stores the current pending value as a 32-bit word at the old control component plus 62.
3. Tests whether the low-32-bit result of multiplying the incremented control value by 65,536 is negative.

The store occurs before the test can cause an exit.

The test is equivalent to checking bit 15 of the incremented control value. It is not a test of whether the incremented control value itself is negative.

If the test succeeds, execution takes the shared exit. The return value’s lower component is twice the lower half of the F-U06 result, modulo \(2^{32}\).

If the test fails, execution continues as follows:

1. Store the low 16 bits of the F-U06 result at its upper 32-bit component plus 60.
2. Invoke F-U07.
3. Invoke F-U08 and treat its result as an address base.
4. Store the 16-bit value 38 at that address plus two.

The routine then derives a signed shifted value from the incremented control value:

- Multiply by `0x10000000`, retaining the low 32 bits.
- Interpret that result as signed and arithmetically shift right by nine.

An intermediate address candidate is the shifted value plus the incremented control value, modulo \(2^{32}\).

Before the next call, the routine reads the fixed 32-bit XOR operand. It invokes F-U09 with:

1. Twice the F-U08 result, modulo \(2^{32}\).
2. The incremented control value multiplied by 65,536, minus 81, modulo \(2^{32}\).

The pending stored value becomes the shifted value plus 47. The routine also assigns the XOR-derived address to a represented 32-bit stack slot at displacement 304.

It then reads one byte at the XOR-derived address plus one and invokes F-U10 with four explicit arguments:

1. A fixed address-valued constant.
2. The byte just read.
3. The new pending stored value.
4. A secondary register output associated with F-U09.

After F-U10 returns, the routine stores the pending value as a 32-bit word at the XOR-derived address plus 36.

It invokes F-U11 and forms a new 64-bit pair:

- Lower component: the XOR-derived address.
- Upper component: a secondary register output associated with F-U11, plus 48.

Execution then enters the common path.

### 4. Common path

The common path consumes a 64-bit pair from either F-U04 or the preceding iteration-body operations.

Before its calls, it derives:

- A saved control value from the pair’s upper component.
- A next first-call argument equal to twice the pair’s lower component.
- A pending stored value equal to four times the square of the saved control value, modulo \(2^{32}\).

It then performs these calls in order:

1. F-U12, with the lower pair component plus the ambient address addend.
2. F-U13, with the value read from the fixed common-call data location.
3. F-U14, with no explicit arguments shown.

The target used for F-U12 depends on whether this common path was entered from initial setup or from the iteration body. These alternatives must not be assumed to resolve to the same function.

After F-U14 returns, the routine reads the fixed-location continuation flag.

If the flag is zero, execution takes the shared exit. The return value’s lower component is the secondary register output associated with F-U14, arithmetically shifted right by nine and then shifted left by one.

If the flag is nonzero, the routine:

1. Stores the pending squared value as a 32-bit word at twice the saved control value plus 52.
2. Replaces the control component with the secondary register output associated with F-U14.
3. Enters the iteration body.

For this next iteration, the first call argument remains twice the lower component of the common-path input pair. The selector used to derive F-U05’s target is the common-path selector.

## Acceptance examples

These are conditional static acceptance examples, not executed tests. They assume valid accessed memory and returning callees.

1. **Initial halfword truncation.** If the fourth argument’s bit pattern is `0x12345678`, the initial store writes the 16-bit value `0x5678` at the first argument minus 21. Byte order remains target-dependent.

2. **Initial-condition boundaries.** If F-U03 returns −33,280 or −1, the captured condition is true. If it returns −33,281 or zero, the condition is false. A false condition bypasses the initial pair-relative halfword store and enters the common path.

3. **Overflow-sensitive selection.** With a true captured condition, a nonnegative ambient halfword source, and upper F-U04 result zero, both compared Booleans are false; execution enters the common path. Changing only the upper result to −2,147,483,648 makes the subtraction-overflow Boolean true and selects the iteration body.

4. **Iteration-local exit boundary.** If the current control component is 32,758, adding ten sets bit 15, so the iteration exits after its control-relative word store. A control component of 32,757 produces 32,767 and does not exit by that test.

5. **Shared return composition.** Suppose the fixed return-data value is 100 and the iteration-local exit uses an F-U06 lower component of three. The returned upper component is 16, and the lower component is six.

6. **Common-path exit shift.** If the continuation flag is zero and F-U14’s relevant secondary output is −1, the lower return component is `0xFFFFFFFE`. The continuation-only squared-value store does not occur.

7. **Captured XOR operand.** If F-U09 changes the fixed XOR operand’s memory, the address calculation still uses the value read before F-U09. This does not imply that other memory or register state survives the call unchanged.
