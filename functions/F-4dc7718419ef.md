# F-4dc7718419ef

## Purpose

F-4dc7718419ef selects a result pointer from a table of byte-string keys while consulting and conditionally advancing an external input state.

The established behavior is a narrowing search:

- Each table entry associates a zero-terminated byte sequence with a result pointer.
- When the input-state predicate reports nonzero, the function selects the first remaining entry whose current key byte is zero.
- Otherwise, it obtains an unsigned comparison value, retains entries whose current key byte equals that value, and advances the input if any entries survive.
- Once exactly one entry survives, it checks the remaining key directly rather than continuing table filtering.
- A pointer value with all 32 bits set is used for several failure paths.

This resembles recognition of a keyword or token from an input stream. That purpose is inferred, not established: the dependencies’ meanings are unavailable, and one no-match return path does not reliably retrieve a result from the corresponding table entry.

The contract below preserves that irregular behavior rather than replacing it with an intended longest-prefix, exact-match, or fallback-selection algorithm.

## Interface

### Inputs and representation

The recovered interface has two inputs:

1. A 32-bit integer-like value used as a context address. The function passes this value to F-8ff6310c8504 and reads a four-byte field at byte offset 108 from that address.
2. A pointer to a descriptor containing:
   - At byte offset 0: a signed 32-bit entry count.
   - At byte offset 4: a pointer to the first table entry.

The observed layout uses four-byte pointer slots. Each table entry occupies eight bytes:

| Entry offset | Contents |
|---|---|
| 0 | Pointer to the current key byte |
| 4 | Associated result pointer |

The descriptor’s count and table pointer are read to establish the initial candidate range. They are not reread to refresh that range after dependency calls.

Each key is treated as a sequence of unsigned eight-bit bytes. A zero byte has terminal significance, except when it equals the comparison value and therefore takes the matching branch first.

The result pointer is an opaque value. This function does not dereference the selected result.

### Return value

The function returns a pointer-width value that can be:

- A result pointer obtained from a candidate entry.
- The all-ones 32-bit pointer value, numerically `0xffffffff`.
- A value read from an unwritten or stale slot in temporary storage on the irregular no-match path described below.

No separate status accompanies the pointer. A null result pointer is not rejected. A table result equal to the all-ones sentinel is not distinguished from failure.

### Preconditions and limits

For ordinary, defined operation under the recovered layout:

- The context address must support any field reads and dependency operations actually reached.
- The descriptor must be readable.
- A positive-count table must provide the corresponding readable eight-byte records.
- Every key byte actually examined must be readable.
- Key traversal must eventually reach a readable zero byte or a mismatch/end condition.
- Count multiplication and candidate-range address arithmetic must remain representable in the applicable execution model.
- No filtering pass may append more than 40 matching records to the temporary candidate array.

The last restriction concerns matching records, not total input records. A larger table can be scanned without overflowing temporary storage if no pass retains more than 40 entries.

The function performs no explicit validation of these conditions.

## Behavior

### 1. Establish the candidate range

The function reads the table pointer and count from the descriptor. It forms the initial end position by advancing two pointer slots per entry.

The count is signed, and the displayed arithmetic multiplies it by two before pointer scaling. There is no explicit overflow check, unsigned normalization, or rejection of negative values.

For a valid zero-count range, the candidate start and end are equal. Negative counts and overflowing calculations are outside the reliable contract; they must not be treated as supported empty-table encodings.

A fixed temporary array contains 80 pointer slots, enough for 40 candidate records. Its contents are not initialized on entry.

### 2. Consult the input-state predicate

At the start of each general filtering iteration, the function calls F-8ff6310c8504 with the context value.

A nonzero result takes the terminal-selection path. Zero takes the comparison-and-filtering path. The function distinguishes only zero from nonzero; it does not interpret particular nonzero values as separate statuses.

### 3. Select a terminal candidate when the predicate is nonzero

The function scans the current candidate range in order:

1. It checks whether another candidate remains.
2. It reads that candidate’s current key byte.
3. If the byte is nonzero, it proceeds to the next candidate.
4. If the byte is zero, it returns that candidate’s result pointer.

If no terminal candidate exists, it returns the all-ones sentinel.

This path does not call F-a3abf174e781 or F-1c4d822fa26c. For a valid empty candidate range, it returns the sentinel without reading a candidate key.

When multiple terminal candidates exist, the first in current candidate order wins.

### 4. Obtain a comparison value and filter candidates

When the predicate returns zero, the function reads the four-byte context field at offset 108 and passes that value to F-a3abf174e781.

The returned comparison value is treated as an unsigned 32-bit quantity. Each candidate’s current key byte is zero-extended from eight bits before comparison. The comparison is not restricted to the low byte of the dependency result. A result greater than 255 cannot equal any key byte.

Before scanning, the provisional return value is set to the all-ones sentinel.

Candidates are examined in order. For each candidate:

- If its current byte equals the comparison value, the function appends a record to temporary storage. That record contains the key pointer advanced by one byte and the candidate’s result pointer.
- Otherwise, if its current byte is zero, the function replaces the provisional return value using the temporary-storage read described below.
- Otherwise, it retains neither the candidate nor any result from it.

Survivors retain their relative order. Duplicate matching entries are not deduplicated.

#### Irregular terminal fallback read

For a zero key byte that does not equal the comparison value, the function does **not** obtain the result pointer from that candidate.

Instead, it reads the result-pointer slot of the next temporary output record—the record position where the next match would be appended.

Consequences:

- In the initial filtering pass, that slot has not yet been written during this invocation. Reading it does not establish a deterministic result pointer.
- In later passes, the temporary array is also the candidate source. The slot can contain an earlier-pass value, including a result unrelated to the terminal candidate currently being examined.
- Every encountered nonmatching zero byte replaces the provisional return value; the last such assignment wins if the pass produces no matches.
- If at least one candidate survives, this provisional return value is not returned by that iteration.

This read can itself exceed temporary storage: after 40 matches have filled the array, a later nonmatching terminal candidate attempts to read the result slot of a nonexistent forty-first output record.

### 5. Handle a pass with no survivors

If filtering appends no candidate records, the function immediately returns the provisional value.

There is no call to F-1c4d822fa26c on this path.

Thus:

- No matching candidates and no zero-byte candidates produce the all-ones sentinel.
- A nonmatching zero-byte candidate can cause an unwritten or stale temporary value to be returned instead.

For a valid empty table with a zero predicate result, F-a3abf174e781 is still called before the sentinel is returned.

### 6. Advance after a successful filtering pass

If at least one candidate survives, the function rereads the four-byte context field at offset 108 and calls F-1c4d822fa26c with that newly read value.

The dependency’s return value, if any, is ignored.

The reread matters: the context field supplied to this call need not equal the value previously supplied to F-a3abf174e781. No preservation guarantee is established for intervening dependency calls.

After this call:

- Exactly one survivor enters direct suffix checking.
- Two or more survivors become the next candidate range, stored in the same temporary array.

Later filtering compacts that array in place. For in-bounds matching records, the output position never lies after the candidate currently being processed. This supports ordinary forward compaction, but does not make the irregular fallback read valid.

### 7. Check the suffix of a sole survivor

The function begins with the survivor’s already-advanced key pointer and saved result pointer.

It repeats the following behavior:

- If the current key byte is zero, return the saved result immediately.
- Otherwise, call F-8ff6310c8504 with the context.
- If that call returns nonzero, return the all-ones sentinel.
- Otherwise, read the context field at offset 108 and call F-a3abf174e781.
- If the unsigned 32-bit comparison value differs from the current unsigned key byte, return the sentinel.
- On equality, reread the context field, call F-1c4d822fa26c, and advance the key pointer by one byte.

The terminal-byte check precedes the predicate call. A sole surviving key can therefore succeed as soon as its suffix ends, without checking whether additional input remains.

A mismatch does not call F-1c4d822fa26c for the mismatching byte. Earlier successful advances are not undone.

### Zero comparison values

The equality test precedes the zero-byte terminal test during general filtering.

If F-a3abf174e781 returns zero, a candidate positioned at its zero terminator survives as a match and its key pointer advances beyond that terminator. Subsequent behavior may read bytes beyond the nominal string.

Zero therefore cannot simply be described as an end-of-input value for this function. Safe string-based use requires an external invariant preventing this case, or readable storage with explicitly understood post-terminator behavior.

## Side effects

Established direct effects are limited to:

- Reading the descriptor, candidate records, key bytes, and context field.
- Writing candidate records into a fixed local temporary array.
- Calling the three dependencies in the order described.

The function does not directly update the descriptor or original table, allocate memory, free memory, or copy key contents. Temporary records contain advanced pointers into existing key storage.

Input progression is inferred from the position of F-1c4d822fa26c calls. Its actual state changes are unknown. Failure after earlier successful comparisons does not trigger rollback or compensating calls.

No ownership transfer is established. Returning a result pointer does not establish allocation origin, lifetime, mutability, or responsibility for release.

Dependency side effects may alter context fields, key contents, table records, globals, or other accessible state. The function does not establish that such data remain unchanged across calls. Preconditions must cover the actual reads reached under those effects.

## Acceptance examples

These examples are conditional on readable storage, valid arithmetic, stable candidate data unless otherwise specified, and dependencies producing the stated values. They are static acceptance cases, not runtime test results.

1. **Immediate terminal selection.**  
   The initial predicate returns nonzero. The table contains a nonempty key followed by two empty keys. The result of the first empty key is returned. Neither comparison nor advance dependency is called.

2. **No terminal candidate at predicate stop.**  
   The predicate returns nonzero and every current key byte is nonzero. The sentinel is returned without advancing.

3. **Empty table.**  
   With count zero, a nonzero predicate result produces the sentinel immediately. A zero predicate result causes one comparison-dependency call, then returns the sentinel. Neither case advances.

4. **Unique key accepted without checking trailing input.**  
   The sole key is “ab”. Predicate and comparison results permit matching “a”, then “b”. There are two advance calls. Once the suffix pointer reaches its zero byte, the associated result is returned without another predicate call, even if external input remains.

5. **Unique suffix mismatch.**  
   The sole key is “ab”. “a” matches and causes an advance; the next comparison value corresponds to “x”. The function returns the sentinel with only the earlier advance performed.

6. **Shared prefix narrowed by a later byte.**  
   The keys are “ab” and “ac”. Matching “a” retains both and advances once. Matching “c” retains only the second and advances again. Its empty suffix causes its result to be returned.

7. **Shared prefix stopped by the predicate.**  
   The keys are “a” and “ab”. After matching and advancing past “a”, the next predicate returns nonzero. The first candidate now has a zero current byte, so its result is returned without another comparison.

8. **Initial empty-key fallback is not a defined result lookup.**  
   The table contains an empty key and “a”; the predicate returns zero and the comparison value corresponds to “z”. Neither candidate survives. The function attempts to return the value obtained from an unwritten temporary result slot, not the empty key’s associated result.

9. **Full-width comparison.**  
   The comparison value is 256 and all current key bytes are nonzero. No byte matches; the sentinel is returned without an advance. The value is not truncated to zero.

10. **Capacity boundary.**  
    Forty matching candidates fill temporary storage. A forty-first matching candidate causes an out-of-bounds write. Even without a forty-first match, a subsequent nonmatching zero-byte candidate causes an out-of-bounds temporary-slot read.
