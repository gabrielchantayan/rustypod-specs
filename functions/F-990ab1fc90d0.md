# F-990ab1fc90d0

## Purpose

F-990ab1fc90d0 performs an unsigned bounds check and selects one of two completion paths:

- If the requested index is outside the bound read from an input record, it invokes a completion dependency with a zero result.
- Otherwise, it obtains a storage value, prepares a local 32-bit value, invokes a construction dependency, delivers that dependency’s result, and then invokes a finalization dependency on the local value.

The established behavior is this sequence of reads and dependency calls. Interpreting it as indexed object construction is inferred intent, not a verified semantic description. The supplied evidence does not establish what the input record represents, what the constructed result contains, or whether any dependency allocates, retains, transfers, or releases ownership.

## Behavior

### Entry and branch selection

The function first initializes a local 32-bit slot from the fourth argument. This is a value copy, not evidence of a deep copy, reference-count adjustment, or ownership transfer.

It then reads the unsigned 32-bit bound at record offset 8 and compares it with the unsigned 32-bit index.

The out-of-range condition is:

- The bound is less than or equal to the index.

The in-range condition is:

- The index is strictly less than the bound.

Equality is therefore out of range. A zero bound makes every possible index out of range.

The comparison is unsigned. Values whose most significant bit is set remain large nonnegative index values for this decision; they are not interpreted as negative indices.

The function performs no index multiplication, subtraction, increment, or element-address calculation. It forwards the original index to a dependency if the initial check succeeds.

### Out-of-range path

On an out-of-range input, the function invokes F-cd649951dc44 with:

1. The original completion context.
2. A 32-bit zero value.
3. A zero value.

After that dependency returns normally, the function returns.

This path does not directly read the record fields at offsets 4 or 12. It does not invoke the storage provider, local-value preparation dependency, construction dependency, or finalization dependency.

Although the local slot has already been initialized from the fourth argument, this path does not pass its address to a dependency or explicitly finalize it.

The zero result is an established argument value. Whether it denotes absence, failure, an empty object, or another condition is unknown.

### In-range path

When the index is strictly below the bound, the following order is established.

1. **Request storage or an opaque resource value.**  
   F-8157a180d901 is called with the numeric argument 88, equivalent to hexadecimal 0x58. Its returned 32-bit value is retained for the later construction call.

2. **Read the preparation input.**  
   After F-8157a180d901 returns, the function reads the 32-bit field at record offset 4.

3. **Prepare the local slot.**  
   F-56a266ab3332 is called with the address of the local slot and the value just read from offset 4. The slot initially contains the fourth argument’s bits. This dependency can potentially read or modify the slot through the supplied address; its exact effects are unknown. No return value from this call is used.

4. **Read the construction input.**  
   After preparation returns, the function reads the 32-bit field at record offset 12.

5. **Construct or obtain the result.**  
   F-6e1b08786933 is called with:
   - The value returned by F-8157a180d901.
   - The address of the same local slot.
   - The value just read from offset 12.
   - The original unsigned index.

   Its returned 32-bit value becomes the result used for completion. The earlier storage-provider value is not independently delivered.

6. **Deliver the result.**  
   F-cd649951dc44 is called with the original completion context, the construction dependency’s returned value, and zero.

7. **Finalize the local slot.**  
   Only after the completion dependency returns normally, F-176c75806347 is called with the address of the same local slot.

8. **Return.**  
   The function returns after finalization returns normally.

There is no second bounds check. Changes to the offset-8 field after the initial comparison do not alter this function’s selected branch.

### Read timing and intervening mutations

The record fields are not captured as a single snapshot.

- The offset-8 bound is read before any dependency call.
- The offset-4 value is read after F-8157a180d901 returns.
- The offset-12 value is read after F-56a266ab3332 returns.

If an intervening dependency can modify the relevant record through an alias or other reachable state, the later read uses the value present at that later point, under the execution environment’s memory semantics. The source does not justify assuming that dependencies preserve shared state.

The local slot likewise is not restored between calls. Construction receives the same slot address that preparation received. Finalization receives that address after both construction and completion have returned. Its contents may therefore differ from the original fourth argument.

These observations do not establish thread safety or data-race semantics.

## Side effects

The function’s directly visible memory effects are limited to local-slot initialization and the record reads described above. It contains no explicit write to the input record, no direct global-state write, and no explicit release of the storage-provider result.

Dependency calls may have additional effects. Their implementation contracts are unavailable, so this function cannot be specified as globally side-effect-free or as preserving caller-owned memory.

### Lifetime and ownership

The local slot is temporary storage belonging to this invocation. Its address is exposed to preparation, construction, and finalization dependencies. It remains available throughout those calls and ceases to be valid local storage when the function returns.

The function does not establish whether those dependencies retain the address. Any safe retention contract would require additional evidence.

The storage-provider result is passed to construction without an intervening validity check. There is no explicit separate cleanup of that value on the shown path. This does not establish a leak: construction or another dependency may consume or manage it. Nor does it establish successful ownership transfer.

Completion occurs before local finalization. Any interpretation of the returned result that depends on the local slot’s underlying resources must account for that ordering. The evidence does not establish whether construction copies, borrows, or takes ownership of anything reachable through the slot.

### Failure behavior

No dependency result is tested for failure.

In particular:

- A zero storage-provider result is still passed to construction if the provider returns normally.
- A zero construction result is still passed to completion.
- There is no explicit retry, rollback, alternative result, or error translation.
- There is no explicit exceptional cleanup path.

The normal-return sequence is established. If a dependency traps, terminates execution, throws, or transfers control nonlocally, later steps are not guaranteed by the supplied source. In particular, finalization is not shown to run if completion does not return normally.

## Acceptance examples

These are conditional acceptance criteria derived from static evidence. They are not runtime test results.

1. **Equality rejects the index.**  
   Given a bound of 7 and an index of 7, completion receives the original context, zero, and zero. None of the four in-range-only dependencies is invoked.

2. **Zero bound always rejects.**  
   Given a bound of zero, index zero and index 4,294,967,295 both select the out-of-range path.

3. **Unsigned high-bit behavior.**  
   Given a bound of 2,147,483,648 and an index of 2,147,483,647, the in-range path is selected. Reversing those values selects the out-of-range path.

4. **Maximum bound boundary.**  
   Given a bound of 4,294,967,295, index 4,294,967,294 is in range, while index 4,294,967,295 is out of range.

5. **Normal in-range call order.**  
   If the index is in range and every dependency returns normally, calls occur in this order: F-8157a180d901, F-56a266ab3332, F-6e1b08786933, F-cd649951dc44, F-176c75806347. Completion receives construction’s result, not necessarily the storage-provider result.

6. **Later field changes remain observable.**  
   If the storage provider changes the offset-4 field through a valid alias before returning, preparation receives the subsequently read value. If preparation changes the offset-12 field before returning, construction receives the subsequently read value.

7. **The initial range decision persists.**  
   If the original check succeeds and a dependency subsequently reduces the record’s bound below the index, this function still proceeds to construction. It does not revalidate the index.

8. **Zero results are forwarded.**  
   If the storage provider returns zero normally, construction still receives zero as its first argument. If construction returns zero normally, completion receives zero and finalization follows after completion returns.

9. **Finalization follows delivery.**  
   On the in-range path, finalization must not precede completion. If completion does not return normally, the supplied evidence provides no guarantee that finalization occurs.
