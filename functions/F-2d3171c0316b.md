# F-2d3171c0316b

## Purpose

F-2d3171c0316b dispatches an input record according to a 32-bit discriminator. For one discriminator, selection also depends on exact equality between an address stored in the record and specified addresses within a receiver object.

The supplied static representation establishes three special cases:

- **15:** select a receiver-relative action. The selection at receiver +0x11C completes locally with result 1; all other selections proceed to fallback dispatch.
- **30:** invoke a receiver callback four times, then proceed to fallback dispatch.
- **33:** invoke a receiver callback and return its result immediately if nonzero; otherwise proceed to fallback dispatch.

All other discriminator values proceed directly to fallback dispatch.

Fallback dispatch first invokes a receiver callback to obtain an object. A null result ends processing with result 0. Only a non-null result leads to a callback on that object, with the original record address supplied as an argument.

These are dispatch and result-propagation behaviors. Domain meanings such as “notification,” “registration,” or “handled event” are not established.

## Interface

### Inputs and representation

The function accepts two address-valued inputs:

1. **Receiver:** the base address of an object containing a dispatch-table pointer and receiver-relative regions.
2. **Record:** the base address of the input record.

The supplied representation uses four-byte integers, pointer fields, and dispatch-table entries. This contract uses those widths to describe the observed layout. It does not independently establish the native ABI, source-level types, or calling convention.

### Record layout

| Byte offset | Width | Established access |
|---|---:|---|
| +0 | Not established | No explicit access by this function |
| +4 | 4 bytes | Discriminator, read once for local selection |
| +8 | 4 bytes | Associated address, read only for discriminator 15 |

The record address is also passed to certain callbacks. Their requirements for additional record fields are unknown.

### Receiver layout

| Byte offset | Width or extent | Established use |
|---|---:|---|
| +0 | 4 bytes | Dispatch-table pointer |
| +0x44 | Address only | Compared with the associated address; subsequently supplied to F-ec4cfa552cce on this selection |
| +0x70 | 4 bytes | Argument supplied to the callback at table offset +0x110 |
| +0x78 | Address only | Compared with the associated address; subsequently supplied to F-ec4cfa552cce on this selection |
| +0xEC | Address only | Compared with the associated address |
| +0x11C | Address only | Compared with the associated address |

These are **byte offsets**. The receiver-relative arithmetic in the supplied representation scales four-byte elements: the relevant comparison addresses are +0x44, +0x78, +0xEC, and +0x11C.

Forming or comparing these addresses does not itself read the contents of the corresponding receiver regions. Region sizes are not established.

### Dispatch-table entries

Each listed entry occupies four bytes in the supplied representation.

| Receiver table offset | Explicit arguments | Result handling |
|---|---|---|
| +0x58 | Receiver and shared values; four invocations with differing argument lists | Ignored |
| +0xCC | None represented | Null or fallback-object address |
| +0x110 | Receiver, four-byte receiver field at +0x70 | Ignored |
| +0x17C | Receiver | Ignored |
| +0x1D8 | Receiver, record | Returned immediately if nonzero |

A non-null fallback object is interpreted as containing its own four-byte table pointer at offset +0. The entry at byte offset +0x30 in that table is invoked with the fallback object and original record address. Its result becomes the function result.

An invocation with no explicit arguments does not establish the absence of implicit execution-context inputs or a complete source-level prototype.

### Output

The represented result is a 32-bit integer:

- Exactly **1** after normal completion of the discriminator-15, receiver +0x11C path.
- The exact nonzero result of the receiver’s +0x1D8 callback when that callback completes processing.
- Exactly **0** if fallback acquisition returns null.
- Otherwise, the exact result of the fallback object’s +0x30 callback.

Forwarded callback results are not normalized to Boolean values. A negative nonzero result from the +0x1D8 callback therefore selects immediate return just as a positive nonzero result does.

### Preconditions

Every memory access and indirect call actually reached must be valid. In particular:

- The record must permit the four-byte discriminator read.
- Discriminator 15 additionally requires the associated-address read.
- Reached receiver-table accesses require a valid receiver, table pointer, and callable entry.
- The +0x44 selection requires the four-byte field at receiver +0x70.
- A non-null fallback result must support the object-table access and subsequent invocation.

There are no explicit checks for these conditions other than the null check on the fallback-acquisition result.

## Behavior

### Entry read and selection

Before reading the record discriminator, the function reads one shared four-byte value and retains it as an **entry snapshot**. This read occurs on every path, including paths that never use the retained value.

The discriminator at record +4 is then read and compared with 15, 30, and 33. Local selection is not restarted after callbacks. Later mutations of the record discriminator do not cause another local dispatch.

### Discriminator 15: associated-address selection

The function reads the associated address from record +8. Selection is by exact address equality, not by equality of the bytes stored at those addresses.

The comparisons distinguish receiver +0x11C first, then +0x44, then +0x78, and finally +0xEC. Under ordinary valid object-address arithmetic these are distinct addresses. Address-overflow behavior is not established.

#### Associated address equals receiver +0x11C

The call order is:

1. F-fdd8589eca2d, with no explicit arguments.
2. F-bfa7e30ab583, with no explicit arguments.
3. F-bd1d23e27781 with the receiver, **only if** F-bfa7e30ab583 returned zero.
4. F-a314e4501960 with the receiver.
5. Return 1.

Any nonzero result from F-bfa7e30ab583 suppresses only F-bd1d23e27781. F-a314e4501960 still runs, and the normal final result remains 1.

No fallback acquisition occurs on this path.

#### Associated address equals receiver +0x44

The function invokes the receiver’s table entry at +0x110 with:

- The receiver address.
- The four-byte value read from receiver +0x70.

After that callback returns, the function forms receiver +0x44 and passes that address to F-ec4cfa552cce. It then proceeds to fallback dispatch.

The subsequent address supplied to F-ec4cfa552cce is computed from the receiver, not obtained by rereading record +8. A callback mutation of the associated-address field therefore cannot redirect this call.

The representation does not establish the relative evaluation order of the table-target read and the +0x70 argument read within the invocation.

#### Associated address equals receiver +0x78

The function invokes the receiver’s table entry at +0x17C with the receiver.

After that callback returns, it forms receiver +0x78 and passes that address to F-ec4cfa552cce. It then proceeds to fallback dispatch.

Again, mutation of record +8 does not change the address passed to F-ec4cfa552cce.

#### Associated address equals receiver +0xEC

The function invokes F-503526540fa2 with the receiver, ignores its result, and proceeds to fallback dispatch.

#### Any other associated address

No selection-specific callback is invoked. Processing proceeds to fallback dispatch.

A null associated address is not separately rejected or handled. It follows the same equality comparisons as any other address value.

### Discriminator 30: four invocations

The receiver’s table entry at +0x58 is invoked four times in sequence.

For this contract:

- **Primary storage** is the shared four-byte location read at entry.
- **Auxiliary A**, **auxiliary B**, and **auxiliary C** are three other shared four-byte locations.

The explicit argument lists are:

| Invocation | Arguments, in order |
|---|---|
| First | Receiver, freshly read primary value, freshly read auxiliary A |
| Second | Receiver, entry snapshot, freshly read auxiliary B |
| Third | Receiver, entry snapshot, freshly read auxiliary C |
| Fourth | Receiver, entry snapshot |

The primary value for the first invocation is obtained by a second read of primary storage. It is not specified to equal the entry snapshot.

The auxiliary B read occurs after the first callback returns. The auxiliary C read occurs after the second callback returns. Earlier callbacks can therefore affect the auxiliary values observed by later invocations.

Changes to primary storage after the entry read do not replace the retained snapshot supplied to invocations two through four.

Each invocation uses a receiver-table lookup. The representation does not establish that all four calls reach the same target if a callback changes the receiver’s dispatch table or its entries.

All four results are ignored. After the fourth callback returns, processing continues to fallback dispatch.

The fourth invocation has only two explicit arguments. No third argument, default value, repeated auxiliary value, or zero fill is established.

### Discriminator 33: conditional completion

The receiver’s table entry at +0x1D8 is invoked with the receiver and original record address.

- A nonzero result is returned unchanged, with no fallback acquisition.
- A zero result leads to fallback dispatch.

Record mutations by the callback remain possible, but they do not trigger a new discriminator read or local selection.

### Other discriminator values

All other 32-bit discriminator patterns lead directly to fallback dispatch after the entry snapshot and discriminator reads.

No additional local behavior is established for negative signed interpretations, large values, or unrecognized values.

### Fallback dispatch

Whenever processing reaches fallback:

1. The receiver’s table entry at +0xCC is invoked with no explicit arguments.
2. If it returns null, the function returns 0 immediately.
3. If it returns a non-null object address, that object’s table pointer is read.
4. The object’s table entry at +0x30 is invoked with the object and original record address.
5. That callback’s result is returned unchanged.

**The original record address reaches the fallback object’s callback only when acquisition returns non-null.** Merely reaching fallback acquisition does not imply that the record is passed onward.

Fallback acquisition occurs after all preceding local callbacks on that path. The table lookup may therefore observe changes those callbacks made to receiver state. A downstream callback receives the original record address, but the record contents may have changed.

## Side effects

No direct store to receiver memory, record memory, or shared storage is visible in the supplied body. Explicit memory operations are reads; state-changing behavior is delegated to dependencies.

This does not establish a read-only operation. Dependencies may mutate the receiver, record, shared storage, dispatch tables, or external resources. No dependency is assumed to preserve globals.

The body establishes no allocation, reference-count operation, ownership transfer, or release:

- Passing an embedded receiver address to F-ec4cfa552cce does not establish ownership or destruction semantics.
- Fallback acquisition does not establish whether the returned object is borrowed, retained, newly allocated, or otherwise managed.
- No explicit release of a non-null fallback object follows its callback.
- Retaining the original record address for later use does not establish that its storage remains valid after intervening calls.

Every reached callback is expected to return normally for the described continuation to occur. The function contains no visible recovery for invalidated objects, invalid targets, exceptional transfers, or non-returning dependencies.

Zero has several distinct control-flow uses: it enables one optional local call, permits fallback after discriminator 33, and is the result of null fallback acquisition. These uses do not establish a unified error convention.

## Acceptance examples

These are conditional expectations derived from static evidence, not executed tests. Each assumes valid reached accesses and normal return from preceding calls.

1. **Local completion with the optional call enabled.**  
   With discriminator 15, associated address receiver +0x11C, and F-bfa7e30ab583 returning zero, the dependency order is F-fdd8589eca2d, F-bfa7e30ab583, F-bd1d23e27781, F-a314e4501960. The result is 1. Fallback acquisition is not invoked.

2. **Nonzero suppresses only the optional call.**  
   Under the same selection, a result of −1 from F-bfa7e30ab583 skips F-bd1d23e27781. F-a314e4501960 still runs, and the result is 1.

3. **Record mutation does not redirect the embedded-address call.**  
   With discriminator 15 and associated address receiver +0x44, suppose the +0x110 callback changes record +8. F-ec4cfa552cce still receives receiver +0x44. Fallback acquisition then occurs. **If acquisition returns non-null**, that object’s +0x30 callback receives the original record address, potentially containing the mutation. **If acquisition returns null**, the result is 0 and no fallback-object callback receives the record.

4. **Equal contents do not establish address identity.**  
   With discriminator 15 and an unrelated associated address containing bytes identical to those at receiver +0xEC, F-503526540fa2 is not selected. The associated address itself must equal receiver +0xEC.

5. **Snapshot arguments survive primary-storage mutation.**  
   With discriminator 30 and entry snapshot 7, suppose the first +0x58 callback changes primary storage to 9. Invocations two through four still receive 7 in the snapshot position. Auxiliary B and C are read for their respective calls after earlier callbacks return.

6. **Later auxiliary reads observe earlier mutation.**  
   With discriminator 30, suppose the first callback changes auxiliary B to 12 and no subsequent change occurs before its read. The second invocation receives 12 as its third explicit argument. The fourth invocation still has no represented third argument.

7. **Nonzero completion preserves the result.**  
   With discriminator 33 and a +0x1D8 result of −5, the function returns −5 without invoking fallback acquisition.

8. **Zero allows either fallback outcome.**  
   With discriminator 33 and a zero +0x1D8 result, null acquisition produces final result 0 without an object callback. Non-null acquisition instead leads to the acquired object’s +0x30 callback, whose result is returned unchanged.

9. **A local action does not determine the fallback result.**  
   With discriminator 15 and associated address receiver +0xEC, F-503526540fa2 runs first. If acquisition returns a valid non-null object and its +0x30 callback returns −8, the final result is −8. If acquisition returns null, the final result is 0.
