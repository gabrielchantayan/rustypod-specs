# F-d189d16d5a68

## Purpose

F-d189d16d5a68 requests an object-like address from F-283eda65a14c using the fixed selector **0x3280**. If the returned address is null, it performs no dispatch. Otherwise, it obtains a callable target through the returned object’s leading value and dispatches with the object address and the same selector.

The established behavior is a conditional lookup-and-dispatch operation. A registry lookup followed by an object method invocation is a plausible interpretation, but neither “registry” nor “method” is an established semantic role. The lookup could have other effects, and the leading value need not identify a conventional virtual-method table.

This contract describes the supplied static representation. No runtime tests have been performed.

## Behavior

### Null result

A null return terminates the wrapper’s represented work.

On this path:

- No leading value is read through the returned address.
- No dispatch-entry address is formed from object contents.
- No indirect target is invoked.
- No status value is explicitly reported to the caller.

Null is therefore an explicitly handled no-dispatch outcome. It is not established as an error, an allocation failure, or an indication that a particular resource is absent. Those interpretations require knowledge of F-283eda65a14c.

The null path also does not imply that the invocation had no side effects: the dependency has already executed.

### Non-null result and dispatch layout

A non-null return is used immediately as an object-like address. The wrapper reads an integer-sized value at offset zero from that address.

That leading value is used as the base address for a second access. The second access is located at byte offset **0x14**, or **20 bytes**, from the represented base. The value obtained there is interpreted as a callable target.

The effective layout requirements are:

| Location | Required interpretation |
|---|---|
| Returned non-null address, offset zero | Integer-sized value used to derive a dispatch-table-like base address |
| Derived base address, byte offset 20 | Callable-target pointer representation |

Only these locations are established. The representation does not define a complete object layout, a table length, neighboring entries, or any data preceding the returned address.

The 20-byte displacement is a byte offset, not an established entry index. Calling it the sixth table entry would require an additional assumption that entries are four bytes wide, contiguous, and counted from offset zero.

### Indirect invocation

The resolved target receives two explicit arguments, in this order:

1. The same object-like address returned by F-283eda65a14c.
2. The fixed value 0x3280.

The first argument is not the leading value read from the object and is not the computed dispatch-entry address.

There is no represented null check on the leading value or on the resolved target. There is also no represented validation that the target is executable or compatible with the supplied arguments. A non-null lookup result is sufficient to enter the dispatch path, but it is not sufficient to establish that the path is safe.

The target’s return value, if any, is not explicitly consumed by the wrapper.

### Widths and arithmetic

The supplied representation uses an integer-typed read for the object’s leading value. Under the conventional 32-bit integer model associated with that representation, this is a four-byte read. The source data does not independently establish the underlying ABI, pointer width, or exact machine-level conversion from that integer to an address.

The callable-target read has the width required by the target environment’s callable-pointer representation. A four-byte pointer width is plausible but is not independently proven by the supplied text.

1. Invoking F-283eda65a14c.
2. On a non-null result, reading the leading object value.
3. Reading the callable-target entry at the derived byte offset.
4. Invoking that target with the returned address and fixed selector.
