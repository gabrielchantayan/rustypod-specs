# F-a13f467821fd

## Purpose

F-a13f467821fd allocates a new storage block and updates a caller-supplied, 32-bit-word state object through one of three paths:

1. Initialize a map and two four-word descriptors.
2. Append a block reference into an existing map with remaining trailing space.
3. Replace a map whose trailing space is exhausted, copy its active entries, append the new block reference, and rebuild both descriptors.

This is the established structural behavior. A segmented container with beginning and ending descriptors is a plausible interpretation, but container semantics, element types, and descriptor meanings are not established.

The function returns two words produced through descriptor construction. It does not return an explicit success flag. Allocation failures, invalid addresses, arithmetic overflow, and dependency failures have no visible local handling.

## Interface

### Inputs

The function receives four arguments:

- **State address:** a pointer represented in the supplied material as a 32-bit address.
- **Seed word 1:** a 32-bit value.
- **Seed word 2:** a 32-bit value.
- **Seed word 3:** a 32-bit value.

The last three arguments are initially placed into a temporary four-word record. The first word of that record initially contains the state address itself.

These arguments are not demonstrably element values or constructor arguments. Their meanings depend on F-db05bcc6b488.

### State layout

The function accesses a state object containing at least eleven consecutive 32-bit words, requiring at least 44 accessible bytes.

| Byte offset | Contract label | Established use |
|---|---|---|
| 0–15 | Descriptor A | Four words read or replaced on initialization and map replacement |
| 16–31 | Descriptor B | Four words replaced on every completed path |
| 32–35 | Uninterpreted word | No direct access by this function |
| 36–39 | Map address | Address used to locate map entries and identify the old map to a dependency |
| 40–43 | Map count | Count used in map sizing, midpoint placement, and trailing-boundary calculation |

The fourth words of Descriptor A and Descriptor B, at offsets 12 and 28 respectively, are used as map-entry addresses.

Each directly accessed map entry is four bytes wide. A newly allocated block address is stored as one such entry.

The uninterpreted word is not directly read or written. This does not establish that it remains unchanged across dependency calls.

### Temporary record and result

A temporary record of four 32-bit words is initialized as:

1. State address.
2. Seed word 1.
3. Seed word 2.
4. Seed word 3.

F-db05bcc6b488 receives the address of this record and can modify it. The same record is reused if that dependency is called twice.

The result is a 64-bit bit-pattern:

- Bits 0–31 contain temporary-record word 0.
- Bits 32–63 contain temporary-record word 1.

The result uses the record contents after the final descriptor-construction call on the selected path. It is not necessarily a pointer, integer count, or status code.

### Preconditions

For defined, useful completion:

- The state object and all directly accessed addresses must support the required 32-bit reads and writes.
- Allocation results must identify sufficient writable storage for the subsequent accesses.
- Existing map-entry addresses must describe a valid range when the replacement path is taken.
- Dependencies must return normally.
- Dependencies must not invalidate storage that this function subsequently uses.

The implementation does not check these conditions locally. It also provides no explicit alignment, null-pointer, count-range, or overflow validation.

## Behavior

### Arithmetic model

Address-like values, count values, and stored words are represented as 32-bit quantities in the supplied material. The return value is 64 bits.

The following distinctions matter:

- Allocation sizes derived by shifting a word left by two use a 32-bit expression.
- Initialization midpoint calculations use an **unsigned** right shift by one.
- The replacement-path entry-distance calculation uses a **signed** right shift by two.
- The replacement placement offset explicitly clears its lowest two bits.
- Comparisons against calculated map boundaries test equality, not ordering.

For ordinary valid sizes and addresses, the formulas below describe the intended address relationships directly. For overflowing expressions, they describe the 32-bit bit-pattern calculations presented by the supplied material; language-level overflow guarantees and target exception behavior are not established.

### Common prefix

Every path begins in this order:

1. Initialize the temporary four-word record from the arguments.
2. Call F-d908bb83bef8.
3. Multiply that result by four through a two-bit left shift and pass the resulting size, followed by zero, to F-871e64ddc6de.
4. Retain the returned address as the new block address.
5. Call F-18dde3a4696c with the state address.
6. Select initialization if that call returns nonzero; otherwise inspect the existing map.

Thus, allocation of the new block occurs before the initialization predicate is evaluated. The function neither defers that allocation until it knows the branch nor explicitly releases the block on a later failure.

Results from separate calls to F-d908bb83bef8 are not assumed equal.

### Initialization path

When F-18dde3a4696c returns nonzero:

1. Call F-d908bb83bef8 again.
2. Store its result into the state’s Map count.
3. Request another allocation from F-871e64ddc6de, using four times that result as the 32-bit size and zero as the second argument.
4. Store the returned address into Map address.
5. Read the current Map count, interpret its bit pattern as unsigned, halve it with a right shift, and use that as a map-entry index.
6. Store the previously allocated new block address into that midpoint entry.
7. Call F-d908bb83bef8 a third time.
8. Call F-db05bcc6b488 with:
   - The temporary-record address.
   - The new block address plus four times the unsigned half of the third count result.
   - The map-entry address computed from the current Map address and current unsigned half of Map count.
9. Copy all four temporary-record words into Descriptor A, in increasing word order.
10. Copy Descriptor A into Descriptor B, again in increasing word order.
11. Return the first two temporary-record words packed into the 64-bit result.

Three independent count results participate:

- The first sizes the new block.
- The second sizes the map and is stored as Map count.
- The third selects a position within the new block for descriptor construction.

The function does not verify that these results are mutually consistent. In particular, it does not prove that the third result selects an address inside the first allocation.

The map and block allocation results are stored or used without null checks. The chosen map entry is written before F-db05bcc6b488 runs.

Descriptor B receives values read from Descriptor A after Descriptor A has been written; it is not populated directly from the temporary record on this path.

### Existing map with trailing space

When initialization is not selected, the function reads the fourth word of Descriptor B as the current trailing map-entry address.

It compares that address against:

**Map address + four times Map count − four.**

If they are unequal, the function takes the trailing-space path. This is not a bounds comparison: an address before, beyond, or otherwise inconsistent with the map can still satisfy the inequality.

The path proceeds as follows:

1. Increase the saved trailing map-entry address by four.
2. Store that increased address into Descriptor B’s fourth word.
3. Store the new block address at that increased map-entry address.
4. Call F-db05bcc6b488 with:
   - The temporary-record address.
   - The new block address.
   - The then-current fourth word of Descriptor B.
5. Copy the four resulting temporary-record words into Descriptor B, in order.
6. Return the first two temporary-record words packed into the result.

Descriptor A, Map address, and Map count receive no direct writes on this path. Dependencies may nevertheless affect them.

The early write to Descriptor B’s fourth word is observable before descriptor construction. The later four-word copy replaces that word again with the dependency-produced fourth word.

### Existing map at its trailing boundary

If the saved trailing map-entry address equals the calculated final map-entry address, the function replaces the map.

Define the following values from the represented 32-bit arithmetic:

- **Distance:** the saved trailing entry address minus Descriptor A’s fourth word, followed by signed right shift by two.
- **Entry count:** Distance plus one, retained as an unsigned 32-bit value.
- **Placement offset:** twice Entry count, with the lowest two bits cleared.

For aligned, increasing addresses without overflow, Entry count is the number of active map entries from Descriptor A’s fourth word through the saved trailing entry, inclusive.

The replacement sequence is:

1. Request an allocation of eight times Entry count from F-871e64ddc6de, passing zero as its second argument.
2. Retain the returned replacement-map address.
3. Read Descriptor B’s fourth word again after allocation.
4. Set the copy destination to replacement-map address plus Placement offset.
5. Copy four-byte entries forward, starting at the then-current Descriptor A fourth word, until the source address equals the re-read Descriptor B fourth word plus four.
6. Call F-ff1bdc376dcd with the current Map address, current Map count, and zero.
7. Store the retained replacement-map address into Map address.
8. Store the new block address into the replacement map immediately after the copied entries under the ordinary valid-range interpretation.
9. Call F-db05bcc6b488 to rebuild Descriptor A.
10. Copy its four output words into Descriptor A.
11. Call F-db05bcc6b488 again to construct Descriptor B.
12. Copy its four output words into Descriptor B.
13. Store twice Entry count into Map count.
14. Return the first two temporary-record words from the second construction call.

Several ordering and arithmetic details are contractual.

The copy reads and writes one 32-bit entry at a time in forward order. It is not an overlap-safe bulk move. Its termination condition is address equality; malformed endpoints need not produce a bounded copy.

Entry count and the allocation size are calculated before the allocation call. The copy endpoints are read after that call. If the allocator changes the state, the number of entries actually copied can differ from the earlier calculation.

The appended entry address is calculated as the replacement-map address plus:

**Four times [Distance + unsigned-half of (Entry count with its top bit cleared)] + four.**

Under ordinary valid arithmetic, this is Placement offset plus four times Entry count.

The first descriptor-construction call receives:

- The temporary-record address.
- The then-current first word of Descriptor A.
- The current Map address plus Placement offset.

The second receives:

- The same temporary-record address, retaining the first call’s output as its starting contents.
- The new block address.
- The current Map address plus Placement offset plus four times Distance plus four.

The old-map dependency call occurs before the replacement Map address is stored, and before either descriptor is rebuilt. Map count is not changed until both descriptor constructions and descriptor writes have completed.

## Side effects

### Direct memory effects

Depending on the path, the function directly writes:

- One new block-reference entry in a map.
- A replacement copy of every entry traversed by the replacement loop.
- Descriptor B.
- Descriptor A on initialization and replacement.
- Map address and Map count on initialization and replacement.

It does not directly initialize the contents of the newly allocated block.

State updates are incremental, not transactional. Dependencies can observe intermediate states, including:

- A changed Map count before map allocation on initialization.
- A newly stored Map address before descriptor construction.
- An advanced Descriptor B map-entry address before its replacement descriptor exists.
- Old descriptors still referring to the old map when F-ff1bdc376dcd is called.
- A replacement Map address paired temporarily with the old Map count.

### Ownership and failure behavior

The function requests one new-block allocation on every path and another allocation on initialization or replacement.

F-ff1bdc376dcd receives the old map only on replacement. Its name-independent effect is unknown: release, ownership transfer, notification, or another operation cannot be established from this call site alone. Its second argument is the map count, not an explicitly byte-scaled size.

There is no visible rollback, retry, explicit failure return, or compensating release. If a dependency fails to return or a memory access faults, earlier effects may already have occurred.

No assumptions are made that dependencies preserve globals, state contents, allocations, or the temporary record beyond their observed arguments.

## Acceptance examples

These examples are conditional static expectations, not executed tests. They assume successful, suitably aligned allocations, ordinary nonoverflowing arithmetic, and no dependency mutation except the stated temporary-record outputs.

### Initialization with consistent counts

Suppose all three count calls return eight, the block allocation returns address B, and map allocation returns address M.

Expected effects:

- Both allocations request 32 bytes.
- Map count becomes eight.
- The block address is stored at M + 16.
- Descriptor construction receives B + 16 and M + 16.
- If its output record is four words R0 through R3, both descriptors receive those words.
- The return value has R0 in its low half and R1 in its high half.

### Unequal initialization counts

Suppose the three count calls return eight, six, and ten.

Expected effects:

- The block allocation requests 32 bytes.
- The map allocation requests 24 bytes.
- Map count becomes six.
- The map entry at M + 12 receives the block address.
- Descriptor construction receives B + 20 and M + 12.

The function does not normalize these counts to one shared value.

### Append without replacement

Suppose Map address is M, Map count is eight, and Descriptor B’s fourth word is M + 12.

The calculated final entry is M + 28, so the trailing-space path is selected.

Expected effects:

- Descriptor B’s fourth word is first changed to M + 16.
- The new block address is written at M + 16.
- Descriptor construction receives the new block address and M + 16.
- Descriptor B is then replaced by the dependency’s four-word output.
- There is no direct Map count change or old-map dependency call.

### Replace a full map

Suppose the active entries extend from M + 8 through M + 28, and M + 28 is the calculated final map entry.

Distance is five, Entry count is six, and Placement offset is twelve.

For a replacement allocation at N:

- The requested allocation size is 48 bytes.
- Six entries are copied into N + 12 through N + 32.
- The new block address is written at N + 36.
- The first descriptor construction uses N + 12 as its map-entry address.
- The second uses N + 36.
- Map count becomes twelve after both descriptor updates.

### Dependency-produced return words

If the final descriptor construction produces first words `0x89ABCDEF` and `0x01234567`, the return bit-pattern is `0x0123456789ABCDEF`, independently of the remaining descriptor words.
