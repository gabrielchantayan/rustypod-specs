# F-09ca072cf5f2

## Purpose

F-09ca072cf5f2 conditionally updates a caller-supplied object, invokes dependencies using values read from that object, and clears selected fields.

Three controls determine its direct behavior:

- A nonzero byte at offset `0x17` prevents all other work.
- An initially zero byte at offset `0x14` enables a dependency lookup and conditional reset processing.
- Final clearing of the bytes at `0x0e` and `0x1a` depends on the path taken, a later read of `0x14` on the lookup path, and, on some paths, the current 32-bit value at `0x20`.

The combination of dependency calls and field clearing suggests state transition and resource cleanup. Those meanings are **inferred intent**, not established ownership or lifecycle guarantees. The evidence establishes accesses and control flow, but not the semantic identities of the object or its fields.

## Behavior

The ordering below describes the direct accesses and calls established by the supplied representation. It does not establish atomicity, synchronization, or instruction-level implementation.

### Entry gate and initially nonzero `0x14`

The first object access is a read of the byte at `0x17`. Any nonzero value causes immediate return, with no dependency calls, no direct writes, and no further object-field reads.

If that byte is zero, the function reads the byte at `0x14`.

When this initial `0x14` value is nonzero, all lookup and main reset processing is bypassed. The function reads the 32-bit field at `0x20`:

- A nonzero value causes return without direct writes.
- A zero value permits the final writes: zero to `0x0e`, followed by zero to `0x1a`.

No dependency is called on this path.

### Lookup and initial state update

An initially zero byte at `0x14`, after passing the entry gate, selects the lookup path.

F-85680e5d3504 receives the 32-bit value read from `0x6c` as its first argument and zero as its second argument. Its 32-bit result is retained for decisions later in the same invocation.

A nonzero result is written to `0x20`. A zero result causes no direct write to `0x20` at this stage. In either case, the next direct write is the 32-bit all-ones pattern to `0x24`.

Thus, a zero lookup result does not immediately discard an existing value at `0x20`. Conversely, the optional write of a nonzero result occurs after the lookup returns and replaces any value then present at `0x20`.

### First conditional dependency pair

After the write to `0x24`, the function reads the byte at `0x04`.

If the byte is zero, neither call in this pair occurs, and this pair performs no direct write to `0x54`.

If it is nonzero, the pair has the following observable order:

1. F-b8b7f726dd02 receives the 32-bit value read from `0x70`.
2. The byte at `0x04` is cleared.
3. F-05434e19c03a receives the 32-bit value read from `0x54`.
4. The 32-bit field at `0x54` is cleared after that call returns.

The argument from `0x54` is read after F-b8b7f726dd02 returns and after the direct clearing of `0x04`. It is not an entry-time snapshot. Changes made by the first dependency can therefore affect the second dependency’s argument.

Neither argument is checked for zero before being passed. The controlling byte is not rechecked between the calls: once this pair is entered, a change to `0x04` does not cancel its remaining operations.

### Main reset admission

The function next reads the current 32-bit value at `0x20`. This read occurs after the first conditional pair, if that pair ran.

A zero value skips the entire main reset block. A nonzero value admits the block.

On admission, the retained lookup result determines whether the function clears `0x20` before calling F-b298e5737ac6:

- If the retained lookup result was zero, `0x20` is cleared first.
- If that result was nonzero, there is no additional direct write to `0x20` here.

F-b298e5737ac6 then receives the original object address.

This separates the admission condition from the value visible to that dependency. An existing nonzero `0x20` can admit the block even when the lookup returned zero, but the dependency then observes any effects of the intervening clear. A nonzero lookup result does not guarantee admission if an intervening dependency changes `0x20` to zero.

Once admitted, the block is not canceled or restarted by subsequent changes to `0x20`.

### Second conditional dependency pair and reset writes

After F-b298e5737ac6 returns, the function reads the byte at `0x08`.

If it is nonzero, F-b8b7f726dd02 receives the 32-bit value read from `0x74`. After that dependency returns, F-05434e19c03a receives the 32-bit value read from `0x58`. The function then clears the 32-bit field at `0x58`.

The read of `0x58` is therefore sensitive to changes made by the preceding dependency. Neither argument is checked for zero.

Unlike the first pair, this pair has no intervening direct clear of its controlling byte. A dependency may change `0x08`, but the function does not recheck it before the remaining call and the clear of `0x58`.

If the initial read of `0x08` for this pair is zero, both calls and the direct clear of `0x58` are skipped.

Regardless of whether the pair ran, the admitted main reset block ends with these direct zero writes, in order:

| Order | Offset | Width |
|---:|---|---:|
| 1 | `0x08` | 8 bits |
| 2 | `0x09` | 8 bits |
| 3 | `0x98` | 32 bits |
| 4 | `0x9c` | 32 bits |
| 5 | `0x05` | 8 bits |
| 6 | `0x0a` | 8 bits |
| 7 | `0x28` | 32 bits |

Clearing `0x08` does not imply that `0x58` was cleared. If the pair was skipped, this function makes no direct write to `0x58`.

### Final decision after the lookup path

After lookup-path processing, whether or not the main reset block ran, the function freshly reads the byte at `0x14`.

If this later value is zero, the function clears `0x0e` and then `0x1a`, without another read of `0x20`.

If the later value is nonzero, the function reads the current 32-bit value at `0x20`. A nonzero value suppresses both final writes; a zero value permits both, in the same order.

The later `0x14` read need not equal the initial read. Dependency changes can therefore affect the final decision without changing the already-completed path selection.

## Side effects

All direct writes are confined to the fields described above. In particular, the function does not directly write `0x6c`, `0x70`, `0x74`, `0x14`, or `0x17`.

Dependency calls may introduce effects beyond those direct writes. The evidence does not establish that any dependency preserves object fields or globals.

No direct allocation, deallocation, or explicit ownership-transfer operation is visible. Passing a value to F-05434e19c03a does not establish that the value is a pointer or that the dependency releases memory. Clearing `0x54` or `0x58` afterward establishes only the corresponding field write.

F-b298e5737ac6 receives the object address directly. The other dependencies may also access the object through aliases or global state; their argument shapes do not prove isolation.

There is no visible rollback or lifetime protection. If a dependency fails to return normally, later described operations are not guaranteed to occur. If it invalidates the object and returns, the function contains no visible check before subsequent accesses.
