# F-996438dc40e8

## Purpose

F-996438dc40e8 obtains a four-byte value through an object-associated indirect operation. It accepts the value only when that operation reports a result exactly equal to four. On that successful path, an object flag determines whether the value is passed through F-589dbb4c0fdf before being returned.

For every normally returning indirect-operation result other than four, this function returns the 32-bit pattern `0xFFFFFFFF`.

The fourth incoming argument supplies the initial contents of the four-byte destination. The function does not establish that the indirect operation replaces all four bytes. Consequently, the initial value can affect a successful result if the operation leaves any destination bytes unchanged.

These are static behavioral findings. Interpreting the indirect operation as a stream read, or F-589dbb4c0fdf as a byte-order conversion, is inferred intent rather than an established contract.

## Behavior

### Destination initialization

Before invoking the indirect operation, the function initializes a local four-byte destination from the fourth argument.

This initialization is significant even though the operation receives a destination address. There is no subsequent completeness check on the destination’s contents. The operation’s reported result, not observed write coverage, determines whether the function accepts those contents.

### Indirect operation

The function reads the dispatch-table address from the object, resolves the callable entry at table offset `0x2C`, and invokes that entry with three explicit arguments, in this order:

1. The original object address.
2. The address of the initialized four-byte destination.
3. The value four.

The third argument establishes a requested amount of four at the call boundary. The surrounding function does not independently enforce a four-byte write limit or prove that the operation honors that amount.

The dispatch information is obtained before the call. If the operation changes the object’s dispatch-table field, that change cannot alter the already selected invocation. Such a change is not undone by this function.

### Result classification

After the indirect operation returns normally, its reported result is compared with exactly four.

If the result is not four:

- The local destination is replaced with the 32-bit pattern `0xFFFFFFFF`.
- The object flag is not read by this function.
- F-589dbb4c0fdf is not called.
- The sentinel is returned.

There is no distinction among zero, negative results, positive short results, or positive results greater than four. There is also no retry, accumulation of partial results, or second indirect invocation.

If the result is four, the destination is accepted for further processing regardless of how many bytes the operation actually wrote.

### Post-operation flag

Only on the exact-four path does the function read the word at offset `0x08` from the original object address and convert it to an eight-bit character.

The read occurs after the indirect operation. Therefore, a modification made by that operation to the relevant flag value can affect this invocation. The function does not use a flag snapshot captured before dispatch.

When the converted flag is zero, the destination is returned without calling F-589dbb4c0fdf.

When the converted flag is nonzero, the current destination value is passed to F-589dbb4c0fdf. Its returned four-byte value replaces the destination and becomes this function’s return value. No additional status check or transformation follows.

The value `0xFFFFFFFF` is a four-byte bit pattern. Calling it “negative one” depends on a consumer’s signed interpretation; the function’s return representation does not require that interpretation.
