# F-407e183dc5cd

## Purpose

F-407e183dc5cd conditionally processes an input object, either through a selected callback or through one of two dependencies, and then performs shared completion against an associated context.

An initial gate can instead cause a single-byte update to the input object followed by immediate return. This early path bypasses context capture and shared completion.

The established contract concerns field accesses, branch precedence, argument construction, dependency calls, explicit writes, and their order. Domain interpretations such as scheduling, locking, reference counting, or notification are not established.

The function receives one input-object address and has no explicit return value. It does not return a status distinguishing early return, skipped processing, callback invocation, or delegated processing.

The supplied representation uses 32-bit addresses and 32-bit integer words. Byte fields are 8 bits. All layout offsets below are byte offsets.

Two dependencies produce results represented as 64 bits. The function examines their lower and upper 32-bit halves independently. This representation does not establish whether the underlying interface returns a logical 64-bit quantity or two separate values.

## Behavior

### Initial gate

The function first calls F-58f0d766845f with no explicit arguments and tests its 32-bit result.

If the result is zero, the function writes the 8-bit value 1 at input +12 and returns immediately. It performs no explicit context read, processing call, completion decrement, or final global-slot read on this path. Effects of F-58f0d766845f itself remain possible.

Every nonzero result, including a negative 32-bit result, continues to context processing.

### Context capture and preliminary calls

The function reads the 32-bit context address from input +4 and retains that address.

It then calls F-4a19e3742733 with the address of context +4. The argument identifies the field’s storage, not the pointer currently stored there. The return value is unused.

Next it calls F-4ff2968434b6 with the captured context address and the original input-object address.

A zero 32-bit result from F-4ff2968434b6 goes directly to shared completion. No processing callback or delegated-processing dependency is selected on that path.

A nonzero result enters callback selection.

### Direct callback selection

Selection observes the following precedence:

1. A zero byte at context +16 selects input-table entry +12. The distinguished-object fields are not needed for this selection.
2. Otherwise, equality between context +32 and the input address selects input-table entry +20.
3. Only if that comparison fails does equality between context +36 and the input address select input-table entry +24.
4. If neither address matches, processing enters the general decision path.

Consequently, if both distinguished-object fields equal the input address, entry +20 wins. If the discriminator is zero, entry +12 wins regardless of either distinguished-object value.

For a selected direct callback, the function reads the table address from input +0 and obtains the selected entry from that table. It invokes the callback with the original input-object address. The result is unused. Normal return leads to shared completion.

### General decision path: derive a query argument

This path requires a nonzero discriminator and two failed distinguished-object comparisons.

The function first calls F-0827b08a6d41 with the captured context and a 32-bit zero. The upper 32 bits of its represented result provide an initial candidate argument.

If the lower 32 bits are zero, that candidate is retained. No F-a6553fa7836d call or distinguished-object callback occurs during this argument-derivation stage.

If the lower 32 bits are nonzero, the function calls F-a6553fa7836d with the captured context. The upper half of this new result replaces the candidate.

If this new result’s lower half is nonzero, its upper half remains the candidate.

If this new result’s lower half is zero, a callback supplies the candidate instead:

- The function rereads the object address at context +32.
- It reads that object’s callback-table address from object +0.
- It obtains table entry +40 and invokes it with no explicit arguments.
- The callback’s 32-bit result replaces the candidate.

This context +32 access occurs after the preceding dependencies. It is not reuse of the address read for the earlier equality comparison. Any intervening mutation may therefore change which object supplies the callback.

### General decision path: choose processing

The function calls F-0827b08a6d41 again, passing the captured context and the derived 32-bit candidate. Only the lower 32 bits of this result affect the next branch.

If those bits are zero, the function calls F-8bf796272128 with the captured context and original input-object address. Its result is unused. Normal return leads to shared completion without a direct input-object callback or final mask query.

If those bits are nonzero, the function calls F-a6553fa7836d again with the captured context. It tests whether the upper 32-bit half contains any set bit absent from the lower 32-bit half. The operation complements the lower half across exactly 32 bits, intersects that complement with the upper half, and tests the result for nonzero.

This is a bit-coverage test, not a signed comparison, equality test, or test that either half is nonzero.

- If an uncovered upper-half bit exists, the function calls F-1cd05d9f8b66 with the context and input-object address, then proceeds to shared completion.
- Otherwise, it invokes input-table entry +12 with the input-object address, then proceeds to shared completion.

The fallback selection of entry +12 does not reread context +16 or repeat either distinguished-object comparison. Its callback-table address is obtained from the input object when that callback is selected.

### Shared completion

Every normally returning path after a nonzero initial gate reaches shared completion, including the path where F-4ff2968434b6 returns zero.

Completion has this observable ordering:

1. Read the 32-bit word at captured context +12.
2. Decrement it by one and write the result to the same location.
3. Read the 32-bit pointer at captured context +4.
4. If that pointer is null, return without dereferencing it or reading the final global slot.
5. Otherwise, read the first 32-bit word at the pointed-to address.
6. If that word is zero, return without reading the final global slot.
7. Only after both checks succeed, read the current function pointer from the unresolved global slot.
8. Invoke the target obtained by that read with no explicit arguments, then return if the invocation returns normally.

The function does not establish that the global target was captured earlier or remains constant. Any preceding dependency or callback may change the slot; the final invocation uses the value read at step 7.

The decrement uses the word present after prior processing returns. Similarly, the context +4 pointer is read after the decrement, rather than captured before processing.

There is no positive-value guard on the completion word. Representable ordinary values decrement by one, including zero becoming negative one. The supplied representation does not independently establish behavior when decrementing the signed 32-bit minimum; wraparound at that boundary is not guaranteed.

## Side effects

The body explicitly writes only:

- The 8-bit value 1 at input +12 on the initial zero-result path.
- The decremented 32-bit word at captured context +12 during shared completion.

The byte write does not establish changes to adjacent bytes. The decrement is not shown as atomic or synchronized.

Dependencies and callbacks may perform additional writes, mutate the final global slot, change ownership, or invalidate storage. Their side effects are not bounded by the explicit writes above.

The final global-slot access is a conditional read, not an explicit write. It occurs after the completion decrement, the context +4 pointer read, and the nonzero pointed-to-word check. No local null check of the resulting function pointer is shown.

Normal continuation requires storage used later to remain valid. For example, a callback that invalidates the captured context would make completion unsafe; this function provides no visible recovery.

There is no explicit error result, rollback, retry, exception handler, or abnormal-exit cleanup. If a dependency does not return normally, subsequent operations, including shared completion, are not established as occurring.
