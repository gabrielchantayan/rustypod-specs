### Initial publication and shared-destination history

The first access writes the incoming value as 32 bits at auxiliary base + `0x70`. Only afterward is the link word read from fixed storage. The first write can therefore affect that read if their storage overlaps.

The incoming value is next written as 32 bits at primary base + `0x64`.

The address third base + auxiliary offset then receives a 16-bit value narrowed from the auxiliary anchor. Before that address receives its next write, three 32-bit writes occur, in this order:

1. Link word at third base + `0x74`.
2. Link word at third base + link word.
3. Auxiliary base at link word + `0x74`.

The shared address third base + auxiliary offset subsequently receives three 32-bit values in order: link word, third base, and incoming value.

Between the first and second of those 32-bit writes, the routine writes the incoming value at link word + `0x64`. Between the second and third, it repeats that same 32-bit write at link word + `0x64`.

These are distinct accesses. Equal values or coincident destinations do not remove accesses from the represented sequence.

### Primary-base updates and replacement-related writes

After the preceding shared-destination history, the initial object word is read from fixed storage.

The primary-base destinations are then updated in this order:

- Third base is written as 32 bits at primary base + `0x34`.
- Replacement word is read from its fixed location.

### Aliasing and retained values

No disjointness guarantee exists among destinations, fixed storage, or derived addresses. Partial overlap is also possible.

Earlier writes can affect later fixed-storage reads. Once a value has been read and retained, a later write to its original storage does not itself cause a fresh read. The explicitly described reload is the exception.

Consequently:

- The two reads of the second fixed location may produce different values.
- The destination word reflects its load point, before the final two initial-object-word writes at link word + `0x34`.
- The transfer word reflects its load point, before the repeated-slot writes and final two assignments.
- A destination-word self-addressed write can overwrite a previous destination, including the repeated slot.
- Unknown fixed-storage access widths prevent a complete byte-level overlap analysis.

There are no represented branches or loops before the indirect transfer. That does not establish that every access succeeds.
