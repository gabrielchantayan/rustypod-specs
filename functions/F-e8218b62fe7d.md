# F-e8218b62fe7d

## Purpose

F-e8218b62fe7d updates an existing object, configures an embedded subobject with a classification-dependent 32-bit value, and conditionally inserts that subobject into a global singly linked list.

The established behavior consists of ordered memory accesses, dependency calls, conditional list updates, and a possible indirect callback. A scheduling or timer-registration purpose is plausible but inferred: neither the application meaning of the fields nor the units of the calculated values are established.

The function has no explicit return value. Its observable results are memory changes and dependency effects.

This contract describes static evidence only. No runtime tests have been performed.

## Acceptance examples

These are conditional static acceptance scenarios, not executed tests. Each assumes valid storage, returning dependencies, and no unspecified mutation affecting the stated outcome.

1. **Shifted-read provenance.** If the first primary read yields 5001 and the second yields 9000, classification `0x603B` selects 2500. It does not select 4500.

2. **Default-read provenance.** With those same primary observations, an unlisted classification selects 9000, not 5001.

3. **Additional-read provenance.** If classification is `0x6036` or `0x6039`, and the first, second, and third primary reads yield 5001, 9000, and 12000 respectively, the selected value is 12000. All three reads occur in that order.

4. **Constant selection still reads primary twice.** Classification `0x6032` or `0x6033` selects 2000 after the two unconditional primary reads. Those reads are not omitted merely because neither supplies the selected value.

5. **Alternate selection order.** Classification `0x6034` selects alternate A as read after both unconditional primary reads. The second primary read is not the selected value.

6. **Already-marked object.** If membership is nonzero when tested, preliminary configuration and the `0x8C` write have occurred. F-338d16f9ce72, optional insertion, the exit operation, and final dispatch processing are skipped.

7. **Zero insertion value.** If membership is zero and offset `0x70` is zero after preparation, F-unresolved-02 and explicit insertion writes are skipped. The exit operation and dispatch checks still occur.

8. **Empty-list insertion.** With insertion value three, F-unresolved-02 result 100, and a null head when read, the key is 3100. No comparison occurs. The head is written first, membership becomes one second, and the node’s next link becomes null third.

9. **Comparison-controlled position.** Any nonzero first comparison inserts before the head, regardless of result sign. Zero results for every candidate followed by null append the node after the last candidate.

10. **Dispatch gating.** After the exit dependency, a null dispatch structure suppresses both its first-word read and the callback. A nonnull structure with a zero first word suppresses only the callback. A nonzero first word permits the call through the separate target.
