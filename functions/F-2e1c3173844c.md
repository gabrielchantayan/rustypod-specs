# F-2e1c3173844c

## Purpose

F-2e1c3173844c transfers selected fields of an object through an external context. A nonzero mode selects an ordered emission path; zero selects a token-driven ingestion path.

The emission path surrounds its work with operations identified by tag 9 and optionally surrounds a sequence of values with operations identified by tag 16. The ingestion path processes tokens until it encounters a particular tag-9 terminator or a dependency reports failure.

“Emission,” “ingestion,” “opening,” and “closing” describe inferred intent. The established behavior is the sequence of dependency calls, object-relative addresses, token tests, and returned statuses described below. The supplied material does not establish a wire format, complete object type, or dependency implementations.

## Interface

### Inputs

Four arguments are visible:

| Argument | Represented width | Role |
|---|---:|---|
| Object base | 32-bit address-bearing value | Basis for field addresses and an embedded collection-like object. |
| Context | 32 bits | Passed unchanged to every direct dependency call. Its internal type is unknown. |
| Mode | 32-bit signed integer | Zero selects ingestion; every nonzero value selects emission. |
| Initial scratch value | 32-bit unsigned integer | Initializes a mutable scratch word used for tokens or emitted sequence values. |

These widths describe the supplied representation, not an independently verified ABI. Address-bearing values must be usable as addresses in the execution environment.

### Result

The result is a 32-bit integer status.

- A nonzero result from a status-returning dependency is returned unchanged.
- Successful emission returns the result of the final tag-9 closing operation.
- Ingestion returns zero when it recognizes the tag-9 terminator.
- No independent validation-error code is generated by this function.

The unresolved indirect collection-access operation is different: its result is treated as an address, not a status.

### Preconditions

Each executed path requires valid memory and dependency behavior for the accesses it actually performs.

For emission involving sequence access:

- The object must permit reading the signed count at offset 52.
- Each executed indirect lookup requires a readable dispatch-table address at offset 48 and a callable entry at byte offset 64 within that table.
- Each lookup result must point to a readable 32-bit address-bearing slot.
- A nonzero address contained in that slot must identify a readable unsigned 32-bit word.

The function does not check these requirements. It does not establish that invalid input produces a status rather than a memory or execution fault.

## Behavior

### Common status handling

Direct operations are sequential and fail-fast. After a status-returning dependency yields nonzero, this function returns that exact status without making later calls in the normal sequence.

There is no visible rollback, compensating close, retry, or restoration of earlier state. Dependencies may have already changed the context or object before reporting an error.

### Emission mode

Every nonzero mode value follows the same path. The magnitude and sign of the mode do not select additional behaviors.

The established operation order is:

1. Call F-56ffc99ff66d with the context and tag 9.
2. Call F-7de8e89baf04 with the context, tag 10, and the object address at offset 8.
3. Call F-7de8e89baf04 with tag 11 and the address at offset 12.
4. Call F-7de8e89baf04 with tag 13 and the address at offset 20.
5. Call F-7de8e89baf04 with tag 14 and the address at offset 24.
6. Call F-7de8e89baf04 with tag 15 and the address at offset 28.
7. Call F-ca8adbaca715 with the context and the address at offset 36.
8. Read the signed 32-bit count at offset 52.
9. Perform the optional tag-16 sequence described below.
10. Call F-77aa48fed92a with the context and tag 9, returning its status.

Each step after a dependency call is conditional on that call returning zero. In particular, the count is read only after all preceding transfer operations succeed. Those dependencies could change the object before that read; the function does not snapshot the count at entry.

No explicit tag-12 operation appears. The transfer at offset 36 does not receive an explicit tag argument from this function. Its relationship to the tag-18 ingestion operation is inferred, not established.

### Optional emitted sequence

The count is captured once for controlling this sequence.

**Count equal to zero:** no tag-16 opening or closing operation occurs, and no elements are accessed.

**Count nonzero:** F-56ffc99ff66d is called with tag 16. If it succeeds, iteration starts at index zero and continues while the index is less than the captured count under a signed comparison.

Consequently:

- A positive count produces that many lookup-and-transfer attempts, unless an earlier operation fails.
- A negative count produces no element lookup, but still causes tag-16 opening and closing calls if both are reached successfully.

For each executed iteration:

1. Read the dispatch-table address from the embedded object at offset 48.
2. Obtain the callable entry at byte offset 64 in that table.
3. Invoke it with the embedded object’s address and the current index.
4. Read a 32-bit address-bearing value through the returned address.
5. If that value is zero, assign zero to the scratch word. Otherwise, read an unsigned 32-bit word through that value and assign it to the scratch word.
6. Call F-7de8e89baf04 with the context, tag 17, and the scratch word’s address.
7. Continue only if that call returns zero.

After all iterations, F-77aa48fed92a is called with tag 16. Its failure is returned immediately; its success permits the final tag-9 closing operation.

The dispatch-table address and element data are obtained anew for each iteration. The captured count is not refreshed. Dependencies may therefore affect later lookups or values without changing the iteration limit.

There are two distinct levels of indirection after the lookup. A zero value in the returned slot emits zero; a zero lookup-result address itself is not handled safely.

The index is a signed 32-bit quantity. For a positive count representable by that type, the final increment reaches at most the count, so the visible loop does not require signed overflow.

### Ingestion mode

Mode zero initializes the scratch word from the fourth argument, then repeatedly calls F-4b3a084696b2 with the context and the scratch word’s address.

A nonzero status from this dependency ends processing immediately. On zero, the function dispatches using the scratch word’s low 24 bits.

| Low 24 bits | Action |
|---:|---|
| 9 | Inspect the high byte as described below. |
| 10 | Call F-7d397109ac66 with the context and object address at offset 8. |
| 11 | Call F-7d397109ac66 with the address at offset 12. |
| 13 | Call F-7d397109ac66 with the address at offset 20. |
| 14 | Call F-7d397109ac66 with the address at offset 24. |
| 15 | Call F-7d397109ac66 with the address at offset 28. |
| 16 | Call F-7d76b30e06c5 with the object base and context. |
| 18 | Call F-28d90095099b with the context and object address at offset 36. |
| Every other value, including 12 and 17 | Call F-fa92e3e1239e with the context. |

For tag 9:

- If the high byte is exactly hexadecimal C0, return zero immediately.
- Otherwise, perform no dispatch operation for that token and request another token.

Thus the recognized terminating scratch value is exactly hexadecimal C0000009. Other high-byte values attached to low tag 9 are ignored.

For every tag other than 9, dispatch ignores the high byte entirely. This function does not independently distinguish opening, closing, or other token classifications for those tags.

Following a successful dispatched operation, the function requests another token. A nonzero dispatch status is returned unchanged.

There is no visible requirement to encounter an opening tag 9 before accepting fields or the terminator. There is also no local enforcement of field order, uniqueness, required fields, sequence nesting, or a maximum number of tokens. Repeated recognized tags cause repeated dependency calls. What those calls do with repeated values is dependency-defined.

### Scratch initialization and termination

In emission mode, the initial scratch value is overwritten before every executed tag-17 transfer. It is not otherwise passed to a dependency. Its numeric value therefore has no visible effect on emission behavior.

In ingestion mode, the initial value remains relevant unless F-4b3a084696b2 overwrites it. The function does not reset the scratch word before subsequent token reads. Whether a successful token read always writes a complete new word is unknown.

The loop has no independent iteration bound. If dependencies continue returning zero without yielding the terminating token, ingestion need not return.

## Side effects

### Direct memory effects

The visible body directly initializes and updates its scratch word. It does not directly assign to object fields.

That does not make either mode read-only with respect to the object:

- Several dependencies receive object-relative addresses.
- F-7d76b30e06c5 receives the entire object base.
- The indirect operation receives the embedded object’s address.
- Other dependencies may access shared state not visible in the supplied material.

Emission directly reads the sequence count, dispatch information, returned address slots, and non-null sequence values. Most scalar-field access is delegated rather than performed by this function itself.

### Context and partial progress

Every direct dependency receives the context. Its reads, writes, position changes, buffering, and error-state behavior are unknown.

A failure can occur after earlier operations have succeeded. The function does not undo emitted material, restore ingested fields, rewind context state, or close containers after an intermediate failure.

### Ownership and lifetime

No explicit allocation or release operation appears in this body. That observation does not establish that dependencies allocate nothing or release nothing.

The scratch address passed for tag 17 refers to temporary storage used by this invocation. Retention of that address beyond the call would require a lifetime arrangement not established here. Whether any dependency retains pointers is documented_only.

The function neither explicitly frees nor visibly transfers ownership of the address returned by the indirect lookup.

## Acceptance examples

These are conditional acceptance criteria derived from static evidence, not executed tests.

1. **Emission with zero count.** If all dependencies return zero and the count read at offset 52 is zero, the observed direct-call sequence contains tag-9 opening, the five tagged field transfers in order 10, 11, 13, 14, 15, the offset-36 transfer, and tag-9 closing. It contains no tag-16 operation or element lookup.

2. **Emission with a negative count.** With a captured count of minus one and successful dependencies, tag-16 opening and closing both occur, but no index is requested. Final tag-9 closing still occurs.

3. **Two-element emission.** With a captured count of two, successful dependencies, and stable lookup data, indices zero and one are requested in that order. A zero address value in the first returned slot supplies zero to the first tag-17 transfer. A nonzero address in the second slot supplies the unsigned 32-bit word read there.

4. **Failure during an element transfer.** If a tag-17 transfer returns status 7, this function returns 7. It does not attempt later elements, tag-16 closing, or tag-9 closing.

5. **Immediate ingestion completion.** If the first successful token read supplies hexadecimal C0000009, the function returns zero without invoking a field, unknown-tag, or sequence handler.

6. **Nonterminating tag-9 token.** If a successful token read supplies hexadecimal 80000009, the function requests another token without invoking a dispatch handler for that value.

7. **High-byte-insensitive field dispatch.** Successful token reads supplying hexadecimal 0000000A and C000000A both select the offset-8 field handler. This function does not reject either based on its high byte.

8. **Unknown or context-specific tags.** Low tag 17 outside any dependency-managed processing goes to F-fa92e3e1239e, not directly to a collection insertion operation. Low tag 12 follows the same route.

9. **Partial ingestion failure.** If the offset-8 handler succeeds and a later offset-12 handler returns a negative status, the negative status is returned unchanged. No restoration of the earlier field is performed by this body.
