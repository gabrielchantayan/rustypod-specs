# F-59f3c98e2772

## Purpose

F-59f3c98e2772 performs a conditional operation on a caller-supplied state object, followed by unconditional completion bookkeeping.

The established behavior has three paths:

- If the byte at object offset 9 is zero, skip the conditional operation and select a zero result.
- Otherwise, if the byte at offset 20 is zero, delegate to F-3ed70cf3ca2d and retain its four-byte result.
- Otherwise, traverse a linked structure, conditionally invoke two dependencies for each visited entry, clear the corresponding entry field, copy an object field, invoke F-779292dbb800, and select a zero result.

Both paths with a nonzero byte at offset 9 subsequently invoke F-2cc17aa57f70. All normally completing paths then clear the byte at offset 10 and decrement the four-byte field at offset 224.

The structure-processing path resembles resource cleanup, but resource type, ownership transfer, and actual release semantics are not established. Those interpretations are not prerequisites for the observable contract.

## Interface

### Input and result

The function accepts one value represented as a 32-bit integer and used as the base address of a mutable object. Denote that address as **P**.

The result is a four-byte value:

- Zero on the path selected by a zero byte at P + 9.
- The four-byte result returned by F-3ed70cf3ca2d on the delegation path.
- Zero on normal completion of the structure-processing path.

No result interpretation beyond these bit-level rules is established. In particular, zero is not established as a success status, and the delegated result is not established as an error code.

### Structure-entry layout

For each nonzero traversal position, denote its current four-byte value as **R**. The function reads the current four-byte value at P + 60 and adds it to R to form an adjusted address, **A**.

The accessed entry fields are:

|---|---:|---|
| R + 52 | 4 bytes | First argument to the external dependency, when processing is required |
| A + 60 | 4 bytes | Conditional processing value; subsequently passed to dependencies and cleared |
| A + 64 | 4 bytes | Next traversal position |

R and A are distinct address expressions. The first external argument comes from R + 52, not A + 52. Treating the two as interchangeable is not supported unless the caller’s layout makes them equivalent.

### Preconditions

Normal completion requires every address actually accessed on the selected path to be valid for the required read or write. There are no explicit null checks for P, bounds checks, alignment checks, or structural validation.

The byte at P + 10 and the four-byte field at P + 224 must be writable even when the initial selector is zero. Additional memory requirements depend on the selected path and on dependency behavior.

On the structure-processing path, termination requires the sequence of next-position reads eventually to produce zero. No cycle detection or iteration limit is present.

## Behavior

### 1. Entry dependency and branch selection

The first action is an invocation of F-b93e3fe564f6 with no explicit arguments. Its return value, if any, is not used.

Only after that call returns does this function read the byte at P + 9. Consequently, branch selection uses memory as it exists after the entry dependency has executed. The contract does not assume that dependency preserves globals, reachable object memory, or other external state.

If the byte at P + 9 is zero:

1. Select a zero result.
2. Do not read the secondary selector for branch selection.
3. Do not invoke F-3ed70cf3ca2d, F-779292dbb800, or F-2cc17aa57f70 from this path.
4. Proceed to final bookkeeping.

If the byte at P + 9 is nonzero, read the byte at P + 20 and select one of the following two paths. The first selector is not rechecked.

### 2. Delegation path

If the byte at P + 20 is zero:

1. Invoke F-3ed70cf3ca2d with P as its sole explicit argument.
2. Retain its four-byte return value as the eventual function result.
3. Invoke F-2cc17aa57f70 with P.
4. Perform final bookkeeping.
5. Return the retained result.

The result of F-2cc17aa57f70 is not used. A change to either selector by either dependency does not trigger a new branch decision.

This path contains no direct linked-structure traversal or direct copy from P + 44 to P + 36. Dependencies may have additional effects, but those are not established here.

### 3. Structure-processing path

If both selector bytes are nonzero, read the four-byte field at P + 140 once to obtain the initial traversal position.

For each nonzero position R:

1. Read the current four-byte adjustment at P + 60.
2. Form A by adding that adjustment to R.
3. Read the four-byte value at A + 60 and test it against zero.
4. If that value is nonzero, perform the conditional entry processing described below.
5. Read the four-byte next position at A + 64.
6. Continue with that next position.

The adjustment at P + 60 is reread on every iteration; it is not captured once for the whole traversal. A dependency that changes it can therefore affect address formation for later entries.

By contrast, the current iteration’s A is retained across the dependency calls. Changes to P + 60 during those calls do not relocate the current iteration’s subsequent field clear or next-position read.

#### Conditional entry processing

When the initial read of A + 60 is nonzero:

1. Invoke the external dependency designated **F-EXT-01** with three four-byte arguments:
   - The value read from R + 52.
   - The value read from A + 60.
   - The value read from P + 64.
2. After F-EXT-01 returns, reread A + 60.
3. Invoke F-94cb53877c15 with that reread value.
4. After F-94cb53877c15 returns, write four zero bytes at A + 60.

The supplied representation does not establish the relative evaluation order of the three argument reads for F-EXT-01. It does establish that they provide the arguments to that call, that F-94cb53877c15 follows it, and that the clearing write follows both calls.

The nonzero condition is not retested before invoking F-94cb53877c15. If F-EXT-01 changes A + 60 to zero, F-94cb53877c15 is still invoked, with zero. If it replaces that field with another value, the replacement is passed instead.

If the initial read of A + 60 is zero, both calls and the clearing write are skipped. Traversal still reads A + 64.

The next-position read occurs after conditional processing. Dependency changes to A + 64 therefore affect where traversal proceeds.

#### After traversal

Once the current traversal position is zero:

1. Read four bytes from P + 44.
2. Write those bytes to P + 36.
3. Invoke F-779292dbb800 with P.
4. Select a zero result.
5. Invoke F-2cc17aa57f70 with P.
6. Perform final bookkeeping.

These actions also occur when the initial position is zero and no entries are visited. There is no direct write resetting the head field at P + 140.

### 4. Final bookkeeping

On every normally completing path:

1. Write one zero byte at P + 10.
2. Read the four-byte field at P + 224.
3. Subtract one.
4. Write the resulting four-byte value back to P + 224.
5. Return the previously selected result.

The decrement uses the value present after all preceding dependencies return. It does not use a value saved at entry.

No lower-bound test, saturation, or zero special case is present. Exact overflow behavior at the signed 32-bit boundary is not established by the supplied representation; callers requiring a portable arithmetic contract must avoid that boundary or obtain additional machine-level evidence.

## Side effects

Direct writes are limited to the following locations, subject to aliasing:

- A + 60 for each visited entry whose initial processing value is nonzero.
- P + 36 on the structure-processing path.
- P + 10 on every normally completing path.
- P + 224 on every normally completing path.

These are address expressions, not a guarantee that the storage regions are disjoint. If the caller supplies overlapping object and entry storage, an earlier write can influence a later read.

Every dependency may have additional side effects. This function provides no established guarantee about preserved globals, resource lifetimes, synchronization, allocation, or ownership changes.

In particular, the function continues accessing the current adjusted entry after both conditional dependencies return. Any ownership or release behavior implemented by those dependencies must be compatible with those later accesses for normal execution to remain valid.

There is no explicit rollback. If a dependency fails to return normally, the remaining calls and final bookkeeping are not guaranteed to occur. If traversal does not terminate, the post-traversal copy and final bookkeeping are not reached.
