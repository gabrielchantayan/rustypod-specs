# F-50400636e0d4

## Purpose

The available static evidence describes a routine that interleaves indirect calls, computed-address word stores, two input-derived word reads, another word read, and two byte reads followed by byte stores. Several intermediate values are scaled and passed to later calls.

No application-level purpose is established. In particular, the evidence does not establish that this routine constructs an object, manages a collection, serializes a value, or operates on ordinary allocated memory. Its computed addresses could refer to mapped data, device registers, or invalid memory.

The supplied representation explicitly reports invalid instruction data and truncates control flow at the end. This contract therefore describes the visible prefix and its conditional effects. It does not establish successful completion or a normal return.

## Acceptance examples

These are conditional static acceptance examples, not executed tests.

### Initial publication

If the first input is `0x100`, the first word write targets `0x414` and stores `0x100`.

If both subsequent word reads at `0x114` produce `0x12345678`, F-U01 receives:

- `0x00012345`.
- `0x00000100`.
- `0x48d159e0`, assuming 32-bit left-shift results.

Those arguments are not guaranteed if the two reads observe different values.

### Distinct scaled addresses

If F-U30 returns 3, the following direct word store targets `0x44` and stores 12. The later unsigned word read targets `0x20`.

An implementation that reads back from `0x44` instead would change the visible address calculation.

### Captured word survives intervening memory changes

If the read producing \(R\) yields `0xabcdefff`, the subsequent shifted-word publication stores `0x000abcde`.

Changing the original read location during an intervening dependency does not, by itself, change that already captured value.

### Bit-derived call arguments

Under 32-bit arithmetic, if \(G=7\) and \(H=3\), F-U41 receives:

- `0x00070000`.
- `0x0000000c`.
- `0xc0000000`.

The first argument uses the low six bits of \(W(G)\), not the low six bits of \(G\) before scaling.

### Byte truncation and separate destination reads

Suppose \(J=\texttt{0x1234567f}\). If the first byte read at \(H(G)\) yields `0x20`, the first byte store targets `0x31` and stores `0xfc`.

If an intervening dependency changes that byte to `0x80`, the second byte store targets `0x91` and stores `0x23`. F-U63 later receives `0x80` as its second explicit argument.

Reusing the first byte value for the second store would violate the visible reread.

### Prefix failure

If the first computed word-store address is inaccessible, the evidence provides no recovery path permitting an assertion that F-U01 is still called. Conversely, a later fault does not imply reversal of earlier successful stores.
