# F-f03658903e83

## Purpose

F-f03658903e83 conditionally invokes a dependent operation while marking a selected record as active. It admits the operation only when a requested unsigned quantity does not exceed a caller-supplied 16-bit quantity. On successful completion, it checks and publishes the dependent operation’s updated quantity.

The function returns a 64-bit value assembled from two independent 32-bit words. The low word distinguishes success from rejection or dependent-operation failure. The high word depends on whether the admission check passed, not on whether the dependent operation succeeded.

**Established static evidence:** The function performs an unsigned admission comparison, writes a per-record byte around a dependency call, supplies that call with a writable 32-bit quantity, and conditionally updates the caller’s 16-bit quantity.

**Inferred intent:** The record byte appears to mark an operation in progress, and the quantity appears to express a capacity, limit, or available amount. Neither interpretation is required for the behavior below.

## Interface

### Inputs

The function takes five arguments, in this order:

| Argument | Representation | Established use |
|---|---|---|
| Record selector | Signed integer, represented as 32 bits in the supplied source | Selects a record using a stride of 276 bytes. |
| First opaque word | 32 bits | Passed to F-89645f8d06ad; also becomes the return value’s high word if admission fails. |
| Requested quantity | Unsigned 32-bit integer | Compared with the caller’s 16-bit quantity and passed to F-89645f8d06ad. |
| Second opaque word | 32 bits | Passed to F-89645f8d06ad; becomes the return value’s high word on normal return after admission. |
| Quantity pointer | Pointer to an unsigned 16-bit object | Read for admission, read again before the dependency call, and conditionally read and written after a successful dependency result. |

The two opaque words have no established interpretation as pointers, handles, flags, or ordinary integers. Their bit patterns matter; their application-level meanings are unknown.

The quantity pointer is dereferenced even when admission fails. A null or otherwise unreadable pointer is therefore not a supported rejection mechanism.

### Record layout

A global value supplies the base for record addressing. The selected record is located using:

- A record stride of 276 bytes.
- A one-byte field at displacement 19 within that record.

Only this byte is explicitly accessed within the selected record. The function does not establish the record’s full layout, the number of records, or the selector’s valid range.

There is no visible selector bounds check. Valid record addressing, sufficient writable storage, and any required arithmetic-range constraints are caller or surrounding-system preconditions.

### Return value

The result is a 64-bit bit pattern composed as follows:

| Path | High 32 bits | Low 32 bits |
|---|---|---|
| Admission fails | First opaque word | 9 |
| Admission passes; dependency returns nonzero | Second opaque word | 9 |
| Admission passes; dependency returns zero and the quantity check passes | Second opaque word | 0 |

Equivalently, the high word occupies bits 63–32 and the low word occupies bits 31–0. This specifies bit placement, not an in-memory byte order.

The dependency’s nonzero result is not propagated. All normally returning nonzero dependency results produce low word 9.

The invariant-violation path invokes F-a817d8d58c10, which is represented as non-returning. No ordinary return value is established for that path.

## Behavior

### 1. Admission

The function first reads the unsigned 16-bit object addressed by the quantity pointer. That value is compared against the requested quantity as an unsigned quantity.

Admission passes when the requested quantity is less than or equal to the value read.

Consequences of the widths and comparison include:

- A requested quantity greater than 65,535 cannot pass admission.
- Equality passes.
- A requested quantity of zero passes for every readable 16-bit quantity.
- A stored quantity of zero admits only a requested quantity of zero.

If admission fails:

- Neither dependency is called.
- The selected-record address is not formed by the visible admitted-path operations.
- The record byte is not explicitly written.
- The caller’s quantity is not explicitly written.
- The function returns low word 9 and the first opaque word as its high word.

These are statements about this function’s operations, not about changes caused independently by another execution context.

### 2. Record selection and activation

After admission passes, the function obtains the global record base and selects the byte at displacement 19 within the record identified by the selector and 276-byte stride.

It writes the value 1 to that byte.

The selected address is retained for later clearing. The function does not reload the global record base after the dependent operation. If a dependency changes that global, the later clearing write still targets the address selected before the call.

The previous byte value is neither saved nor restored. A prior nonzero value does not prevent entry, and normal completion replaces it with zero.

### 3. Preparation of the dependency quantity

After writing the record byte to 1, the function reads the caller’s 16-bit quantity again. It zero-extends this second reading into a writable 32-bit temporary.

The admission reading and the dependency-initialization reading are distinct accesses. Their values need not agree if the underlying storage changes between them.

This distinction also matters if the record byte overlaps the caller’s quantity storage: the activation write occurs before the second reading and may change the quantity supplied to the dependency.

The function does not repeat admission using the second reading.

### 4. Dependent operation

F-89645f8d06ad is called with six ordered arguments:

1. Zero.
2. Zero.
3. The first opaque word.
4. The original requested quantity.
5. The second opaque word.
6. A pointer to the writable 32-bit temporary quantity.

The last argument points to temporary storage belonging to this invocation. F-89645f8d06ad can affect the subsequent success check through writes to that object.

The function distinguishes exactly two result classes:

- Zero: proceed to the post-call quantity check.
- Any nonzero result: retain low-word status 9 and skip the explicit caller-quantity update.

There is no visible retry, interpretation of distinct nonzero results, or rollback of dependency side effects.

### 5. Successful dependency result

When F-89645f8d06ad returns zero, the function reads the caller’s 16-bit quantity again and compares it with the current unsigned 32-bit temporary.

If the temporary exceeds that current 16-bit value, F-a817d8d58c10 is invoked.

The check uses the caller’s quantity **at this post-call reading**. It does not use either earlier reading. A dependency-induced or concurrent change can therefore affect whether the check passes.

If the temporary does not exceed the current 16-bit quantity:

- The low-word status becomes zero.
- The temporary is converted to 16 bits and written through the caller’s quantity pointer.

On this path, the comparison establishes that the temporary is at most 65,535. Consequently, the 16-bit conversion does not discard nonzero upper bits.

There is no established check that the returned temporary is less than or equal to the original requested quantity. The only post-call numerical bound is the current caller-supplied 16-bit quantity.

### 6. Normal completion after admission

After either a nonzero dependency result or a successful quantity update, the function writes zero to the retained record-byte address.

It then returns with the second opaque word in the high 32 bits and the selected status in the low 32 bits.

The order on the successful path is significant: the caller’s quantity is written **before** the record byte is cleared. If those storage regions overlap, the clearing write can modify the quantity that was just stored.

## Side effects

### Explicit access order

For an admitted invocation whose dependency returns zero and whose quantity check passes, the relevant source-level order is:

1. Read the caller’s 16-bit quantity for admission.
2. Obtain the global record base and calculate the selected field address.
3. Write 1 to the selected one-byte field.
4. Read the caller’s 16-bit quantity again.
5. Initialize the 32-bit temporary from that reading.
6. Call F-89645f8d06ad.
7. Read the caller’s 16-bit quantity for the post-call bound check.
8. Read the temporary as needed for comparison and publication.
9. Write the accepted quantity through the caller’s 16-bit pointer.
10. Write 0 to the selected one-byte field.
11. Return the assembled 64-bit result.

The supplied representation does not establish a particular machine-instruction count for temporary accesses. It does establish the separate caller-quantity reads and the ordering of the explicit record and quantity writes.

For a nonzero dependency result, the post-call quantity check and explicit quantity write are absent; the record byte is still cleared on normal return.

### Aliasing and external mutation

No non-aliasing guarantee is established between the quantity object, the record storage, or memory accessible to dependencies. Therefore:

- The activation write may affect the second quantity reading.
- Dependency side effects may affect the post-call quantity reading.
- The final record-byte clearing may affect the final stored quantity.
- A nonzero dependency result does not prove that the caller’s quantity remains unchanged; it proves only that this function skips its explicit 16-bit publication write.

For nonoverlapping storage and dependencies that leave the caller’s quantity alone, the simpler interpretation holds: failure preserves that quantity, while success replaces it with the accepted temporary.

### Ownership and lifetime

The visible function does not allocate or release storage. It does not visibly transfer ownership of the caller’s quantity or record storage.

The dependency receives a pointer to invocation-local temporary storage. That storage’s lifetime ends with the invocation. Whether the dependency retains the pointer, allocates memory, releases resources, or changes unrelated state is unknown. No preservation or ownership guarantee is implied.

### Abnormal completion

The record byte is cleared only on the visible normal-return paths after admission. There is no visible cleanup around dependency failure to return, a fault, or invocation of F-a817d8d58c10.

On the represented non-returning invariant-violation path, this function has already written the record byte to 1 but has not performed its quantity-publication write or final clearing write.

No atomicity, locking, memory-ordering, or reentrancy guarantee is established.

## Acceptance examples

These are conditional specifications derived from static evidence, not executed tests. Except where stated otherwise, assume valid addresses, nonoverlapping quantity and record storage, and no external mutation of the caller’s quantity.

### Rejected request

Given a requested quantity of 101 and a caller quantity of 100:

- Admission fails.
- Neither dependency is called.
- No record-byte or quantity write occurs.
- The return has high word equal to the first opaque word and low word 9.

### Equal boundary with successful reduction

Given a requested quantity of 100 and a caller quantity of 100, suppose F-89645f8d06ad returns zero and leaves the temporary at 60:

- The record byte is written to 1 before the call.
- The dependency receives an initial temporary value of 100.
- The post-call check accepts 60.
- The caller’s quantity is written as 60, then the record byte is cleared.
- The return has high word equal to the second opaque word and low word 0.

### Accepted quantity greater than the request

Given a requested quantity of 10 and a caller quantity of 100, suppose the dependency returns zero with temporary 80:

- Admission passes.
- The post-call check accepts 80.
- The caller’s quantity becomes 80.

The function does not reject this outcome merely because 80 exceeds the request of 10.

### Nonzero dependency result

Given an admitted request, suppose the dependency returns a nonzero result after changing the temporary:

- The temporary is not published through the explicit quantity write.
- The post-call quantity check is skipped.
- The record byte is cleared.
- The return has high word equal to the second opaque word and low word 9.

Any independent dependency effects remain outside this function’s rollback behavior.

### Excessive successful result

Given a caller quantity that remains 100, suppose the dependency returns zero with temporary 101:

- F-a817d8d58c10 is invoked.
- The explicit quantity-publication write and normal record-byte clearing have not occurred.
- No normal return is established.

### Maximum-width boundary

A request of 65,536 fails admission for every possible 16-bit caller quantity.

A request and caller quantity both equal to 65,535 pass admission. A successful temporary of 65,535 is accepted; a successful temporary of 65,536 invokes F-a817d8d58c10 if the caller quantity remains 65,535.

### Changed post-call bound

Suppose admission passes with caller quantity 100, but the dependency changes that object to 40 and returns zero with temporary 50:

- The post-call check uses 40, not the earlier 100.
- F-a817d8d58c10 is invoked.
