# F-32be0a849d78

## Purpose

F-32be0a849d78 searches two ordered collections associated with an input context and classifies the first matching result.

The collection designated by the descriptor field at byte offset 4 has priority. A match during that search returns **2**. Only if that search is skipped or finishes without a match does the function search the collection designated by the descriptor field at byte offset 0. A match there returns **1**. If neither search produces a match, or the context has no descriptor, the function returns **3**.

A match is equality between the caller-supplied target and a value returned by F-2eb743f270d1. The source does not establish the domain meaning of either value.

The function performs no explicit writes to externally addressed storage. Its dependencies may change shared state, including storage that this function subsequently reads.

## Interface

### Inputs and representation

The function receives two arguments:

| Argument | Recovered representation | Use |
|---|---|---|
| Target | Signed 32-bit integer | Compared for equality with values acquired during either search |
| Context address | 32-bit address-bearing argument | Locates the attached descriptor pointer at byte offset 80 |

No target value is explicitly rejected. Zero, negative values, and both signed 32-bit endpoints participate in the same equality test.

The layout described here is the recovered 32-bit representation. It is not a portable declaration for other pointer widths or object layouts.

### Required storage layout

At byte offset **80**, equivalently **0x50**, from the context address is a **32-bit descriptor pointer**.

A non-null descriptor provides two 32-bit fields:

| Descriptor byte offset | Contract name | Use |
|---|---|---|
| 0 | Fallback field | Handle for the second search |
| 4 | Priority field | Handle for the first search |

These names identify search precedence, not established domain roles.

A field value of zero skips that field’s search when the initial field check occurs. A nonzero field value enables the search. Field values are passed as collection handles to dependencies; the source does not establish whether those handles are addresses, integer tokens, or encoded references.

### Output

The normal result is a 32-bit value:

| Result | Condition |
|---|---|
| **2** | A value acquired during the priority search equals the target |
| **1** | The priority search did not return a match, and a value acquired during the fallback search equals the target |
| **3** | No executed search returns a match |

There is no visible error result distinct from these classifications. In particular, **3** is not a promise that invalid memory or invalid dependency inputs are handled safely.

## Behavior

### Descriptor acquisition

The first externally addressed read obtains the descriptor pointer from context offset 80.

If that pointer is null, the function returns **3** without reading descriptor fields or calling any of the three dependencies.

Otherwise, the function retains the captured descriptor address for both possible searches. It does not reload the descriptor pointer from the context.

Consequently, a dependency that replaces the descriptor pointer stored in the context does not, by that action alone, redirect subsequent field reads. Those reads continue to address the originally captured descriptor. This is not a lifetime guarantee: releasing or invalidating that descriptor can make a later access invalid.

### Priority search

The function first reads the priority field at descriptor offset 4.

If the field is zero, the priority search is skipped. Execution proceeds to the fallback-field check.

If the field is nonzero, the priority search begins with signed index **0**. Before every possible indexed operation, the function:

1. Reads the priority field again.
2. Calls F-10b760faca36 with that freshly read handle.
3. Compares the current index with the returned signed 32-bit bound.

If the index is greater than or equal to the bound, the priority search ends without a match.

If the index is strictly less than the bound, the function:

1. Reads the priority field again.
2. Calls F-6bbddce1b930 with that handle and the current index.
3. After that call returns, calls F-2eb743f270d1 with no explicit arguments.
4. Compares the acquired signed 32-bit value with the target.

Equality causes an immediate return of **2**. The function does not increment the index, read the fallback field, or perform further dependency calls after that match.

On inequality, the index increases by one and the next count query occurs.

The result of F-6bbddce1b930, if any, is not used directly in the equality comparison. A relationship between that call and the subsequent value acquisition is plausible, but no explicit argument carries such a relationship.

### Fallback search

The fallback field at descriptor offset 0 is read only if the priority search is skipped or finishes without a match.

If that field is zero, the function returns **3**.

Otherwise, the fallback search begins with a new signed index of **0**. It follows the same count-query, signed comparison, indexed-operation, value-acquisition, and increment sequence as the priority search, but uses fresh reads of the fallback field.

A matching acquired value returns **1** immediately. If the fallback search ends without a match, the function returns **3**.

The fallback index does not inherit the number of priority-search iterations.

### Repeated observations and mutation

Neither the active handle nor the count is held constant throughout a search.

The initial field check and the first count query use separate field reads. Each count query and its following indexed operation also use separate field reads. A dependency can therefore cause later calls to receive a different handle from earlier calls.

The initial nonzero check is not repeated inside an entered search. If a dependency changes the active field to zero, a later count query or indexed operation can receive zero. The function supplies no local guard or recovery for that case.

A fresh count query occurs:

- Before the first possible indexed operation.
- After every nonmatching iteration, before deciding whether another indexed operation is permitted.

Changing counts may shorten or extend a search relative to an earlier count. A changed handle may also make a count query and the subsequent indexed operation refer to different collections. No snapshot, consistency check, or restoration is visible.

### Integer boundaries and termination

The index starts at zero and increases by exactly one after each nonmatch. Both the index and the bound used in the comparison have a recovered signed 32-bit interpretation.

For an indexed operation to occur, the current index must be strictly less than the current bound. Since a signed 32-bit bound cannot exceed **2,147,483,647**:

- The greatest index that can enter the body is **2,147,483,646**.
- Incrementing that index produces **2,147,483,647**, which is representable.
- At that resulting index, no signed 32-bit bound can satisfy the strict comparison.
- The next count query therefore ends the search, regardless of how the returned bounds changed earlier or change at that final query.

Thus each search executes at most **2,147,483,647 indexed operations**, assuming dependency calls return normally and execution otherwise remains defined. Dynamic bounds cannot cause an unbounded number of iterations.

A zero or negative bound ends an entered search immediately because its current index is nonnegative. A bound equal to the current index also ends the search.

These bounds establish finite local iteration counts, not a wall-clock limit. A dependency can take an unknown duration or fail to return.

## Acceptance examples

These are conditional requirements derived from static control flow, not runtime observations. Unless an example states otherwise, storage remains valid, fields are stable, dependencies return normally, and execution remains defined.

1. **Absent descriptor.**  
   The descriptor pointer read from the context is null. The result is **3**. No descriptor-field reads or dependency calls occur.

2. **Both fields zero.**  
   The descriptor exists and both fields are zero. The function reads the priority field, then the fallback field, and returns **3** without dependency calls.

3. **Immediate priority match.**  
   The priority field is nonzero, its first bound is positive, and the acquired value for index 0 equals the target. The result is **2**. The fallback field is not read.

4. **Fallback after an empty priority search.**  
   The priority field is nonzero, but its first bound is zero. No priority indexed operation or value acquisition occurs. If the fallback field is nonzero, its first bound permits index 0, and that acquired value matches, the result is **1**.

5. **Matches possible in both collections.**  
   A priority-search value matches before that search ends. The result is **2**. Whether the fallback collection could also produce a match has no effect because it is not searched.

6. **Stable count of three without a match.**  
   An entered search repeatedly receives bound three. Indexed operations occur at indices 0, 1, and 2. After three nonmatches, another bound query occurs at index 3 and ends the search. If neither collection matches, the final result is **3**.

7. **Negative bound.**  
   An entered search’s first bound is negative. No indexed operation occurs in that search. Execution advances to the fallback check or returns **3**, depending on which search was active.

8. **Shrinking bound.**  
   Index 0 is permitted and does not match. The next bound is one. The comparison at index 1 fails, so index 1 is not passed to F-6bbddce1b930.

9. **Handle changes during a count query.**  
   A count query changes the active descriptor field and returns a bound permitting the current index. The following indexed operation receives the changed handle, including zero if zero was stored. Whether that input is valid is a dependency precondition.

10. **Context attachment changes.**  
    A dependency replaces the descriptor pointer stored in the context. Provided the original descriptor remains valid, subsequent field reads still use the originally captured descriptor.

11. **Zero target.**  
    The target and an acquired value are both zero. The equality is a match, returning **2** or **1** according to the active search.

12. **Maximum signed bound.**  
    Every count query in an entered search returns **2,147,483,647**, and every acquired value differs from the target. The search performs indexed operations from 0 through **2,147,483,646** inclusive. It then increments to **2,147,483,647**, makes one final count query, and ends. No index overflow occurs.
