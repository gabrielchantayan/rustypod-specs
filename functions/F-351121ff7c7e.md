# F-351121ff7c7e

## Purpose

F-351121ff7c7e examines a byte sequence and returns a 32-bit success or failure indicator. Examination ends successfully when the supplied byte budget is exhausted at a group boundary or when a zero byte is encountered as the first byte of a group.

The grouping rules resemble a restricted multibyte text check, but the behavior is **not a strict UTF-8 validator**. Some high-bit prefixes require continuation-shaped bytes; other high-bit prefixes consume three bytes without checking either following byte. Overlong encodings and surrogate encodings are not rejected by the established checks.

The contract below describes those observable rules independently of any intended encoding.

## Interface

### Inputs

| Input | Representation | Meaning |
|---|---|---|
| Byte-sequence address | Pointer to 8-bit bytes | Address of the next group to examine. The function reads but does not write this storage. |
| Byte budget | Signed integer, modeled as 32 bits | Number of bytes available for bounded examination. The defined contract below covers nonnegative values. |
| Incoming scalar | Unsigned integer, modeled as 32 bits | Has no effect on the established result or read sequence. Whenever a byte value is needed, the incoming value is replaced by a byte read. |

The supplied representation explicitly exposes a four-byte return value and byte-oriented reads. Its integer types support the 32-bit model used here, but no independent ABI declaration is supplied.

### Output

The return value is exactly one of:

- **1:** Successful termination at an exhausted budget or a zero byte at a group boundary.
- **0:** Insufficient budget for the selected group, or a required following byte lacking the continuation-bit pattern.

There is no returned position, consumed-byte count, decoded character, or error classification.

### Preconditions

For a nonnegative byte budget:

- Every byte actually read must be readable for the duration of that read.
- A zero budget requires no byte storage to be read.
- A positive budget does not guarantee that every budgeted byte will be read. Early termination or rejection can occur.
- The function does not establish that the address is valid, that the allocation contains the budgeted bytes, or that the storage remains stable during examination.

Negative budgets, invalid addresses, inaccessible storage, and concurrent changes to the byte sequence are outside the established safe-input contract. They are not represented by a distinct error result.

## Behavior

### 1. Group boundaries and termination

Examination proceeds through groups. Each group starts at the current address with the current remaining budget.

At each group boundary:

1. If the remaining budget is zero, return **1** without reading another byte.
2. Otherwise, read the first byte of the group.
3. If that byte is zero, return **1** immediately.
4. If that byte is nonzero and has its high bit clear, consume one byte and continue at the next group boundary.
5. Otherwise, select one of the high-bit group behaviors below.

The zero-byte rule applies only to a byte read as the **first byte of a group**. It does not independently terminate examination when a zero occurs in a following-byte position.

A buffer need not contain a zero terminator to succeed. Exact budget exhaustion at a group boundary is sufficient.

### 2. One-byte groups

A nonzero first byte in the range `0x01` through `0x7F` forms a one-byte group.

No following-byte check is performed. The next group begins one byte later with a budget reduced by one.

A byte of `0x00` is not treated as an ordinary one-byte group: it ends the entire examination successfully, leaving all later bytes unread.

### 3. Two-byte groups

A first byte in the range `0xC0` through `0xDF` selects a two-byte group.

The behavior is:

- If only one byte remains, return **0** without reading the second byte.
- Otherwise, read the second byte.
- Require its two highest bits to be `10`, equivalently a value from `0x80` through `0xBF`.
- If that requirement fails, return **0**.
- If it passes, consume two bytes and continue at the next group boundary.

No further restriction is placed on the first byte or on the payload bits of the second byte. Consequently, prefixes `0xC0` and `0xC1` are accepted when followed by a continuation-shaped byte.

### 4. Checked three-byte groups

A first byte in the range `0xE0` through `0xEF` selects a checked three-byte group.

The read and decision order is significant:

1. If only one byte remains, return **0** without reading a second byte.
2. Otherwise, read the second byte.
3. If exactly two bytes were available at the group boundary, return **0** without reading a third byte.
4. Otherwise, read the third byte.
5. Check whether the second byte is in `0x80` through `0xBF`. If not, return **0**.
6. Check whether the third byte is in `0x80` through `0xBF`. If not, return **0**.
7. If both checks pass, consume three bytes and continue.

Thus, when three bytes are available, the third byte is read **before** rejection based on an invalid second byte.

There are no additional restrictions for particular first-byte values. In particular:

- `0xE0` does not impose a higher minimum on the second byte.
- `0xED` does not impose a lower maximum on the second byte.
- No scalar value is reconstructed.
- No overlong-encoding or surrogate exclusion is performed.

### 5. Unchecked three-byte groups

A high-bit first byte outside both `0xC0`–`0xDF` and `0xE0`–`0xEF` selects an unchecked three-byte group. This comprises:

- `0x80` through `0xBF`;
- `0xF0` through `0xFF`.

The behavior is:

1. If only one byte remains, return **0** without reading a second byte.
2. Otherwise, read the second byte.
3. If exactly two bytes were available at the group boundary, return **0** without reading a third byte.
4. Otherwise, read the third byte.
5. Consume all three bytes and continue, without validating either following byte.

The two following bytes may have any values, including zero, ASCII values, or other high-bit prefixes. They do not begin nested groups.

This behavior does not implement four-byte UTF-8 handling. A prefix from `0xF0` through `0xFF` consumes three bytes under this rule, not four.

### 6. Budget arithmetic

For nonnegative budgets, each successful group reduces the remaining count by exactly its group width: one, two, or three bytes.

The implementation tests for insufficient budget before reading beyond that group’s permitted extent. Its intermediate arithmetic includes subtracting one, two, and sometimes three from the group-start count. On the nonnegative input domain, these operations do not require signed overflow to obtain the behavior described above.

Negative budgets do not act as immediate exhaustion. For example, a negative initial count does not take the zero-budget return before the first read. Continued processing can involve unsupported pointer access or problematic signed arithmetic. No wrapping, unbounded-scan, or recovery behavior is promised for such inputs.

## Side effects

### Memory reads

All established sequence reads are individual 8-bit reads, in ascending address order within and across groups.

For a stable buffer and nonnegative budget:

- No byte beyond the budget is read.
- No byte after a group-start zero is read.
- A one-byte high-bit remainder is rejected after reading only its first byte.
- A two-byte remainder beginning with a three-byte-group prefix reads its second byte before rejecting truncation.
- A checked three-byte group reads all three bytes before validating its second byte.
- An unchecked three-byte group reads all three bytes even though its following-byte values impose no acceptance constraint.

These distinctions matter when specifying accessibility requirements and early rejection. They do not establish hardware-level timing, compiler ordering beyond the supplied representation, or memory-mapped-I/O semantics.

### Writes and ownership

The supplied body contains:

- No writes to the input sequence.
- No explicit global-state writes.
- No allocation, deallocation, or ownership transfer.
- No retention of the sequence address after return.
- No explicit diagnostic, logging, callback, or exception-handling operation.

The caller remains responsible for storage lifetime. No claim about hidden external machinery or an unavailable callee’s ownership behavior is needed: the supplied body contains no ordinary outgoing function call.

### Input scalar

The incoming scalar has no established externally observable effect. With zero budget, the function returns before using it to make a decision. With positive budget, the first-byte read replaces it before any byte-dependent decision.
