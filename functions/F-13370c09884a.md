# F-13370c09884a

## Purpose

F-13370c09884a conditionally stores a 32-bit value in one of two indexed records. The value must first satisfy a bitmask restriction. A permitted value is written only when the selector is exactly 1 or 2; all other selectors produce no direct write. A prohibited value invokes F-a817d8d58c10 regardless of the selector.

The established behavior is a mask gate followed by a selector gate and, when both gates pass, one full-width store. Interpreting the stored value as flags, configuration, or device state is inferred intent, not established semantics.

This contract describes the supplied static representation. No runtime tests have been performed.

## Behavior

### Value validation has precedence

The first visible decision tests the candidate value against the 32-bit mask 0xFFFFE040.

A candidate is permitted exactly when none of the bits selected by that mask are set. With bit positions numbered from 0 at the least significant bit:

- Bits 0 through 5 may be either zero or one.
- Bit 6 must be zero.
- Bits 7 through 12 may be either zero or one.
- Bits 13 through 31 must be zero.

Equivalently, the candidate may contain only bits present in 0x00001FBF.

This is a bit-pattern restriction, not merely an upper-bound check. For example, 0x00000040 is prohibited even though it is numerically smaller than the permitted value 0x00000080.

The function does not clear prohibited bits and continue. Any prohibited bit selects the dependency-invocation path.

### Prohibited-value path

If the candidate has any prohibited bit set, F-a817d8d58c10 is invoked.

The selector does not suppress this invocation. A selector outside the accepted record set, including zero or a negative value, still reaches the dependency when the candidate is prohibited.

No explicit arguments are supplied to the dependency in the visible call. This establishes only the absence of explicit call operands; it does not establish the dependency’s complete interface or its access to ambient state.

There is no direct record store on this path. Any memory changes, resource actions, or control-flow effects caused by the dependency remain unknown. In particular, the contract does not promise that record storage or the external base remains unchanged.

If the dependency returns normally, the supplied body contains no further explicit work before function completion. Its actual return behavior is not established.

### Permitted-value path

If the candidate is permitted, the selector is tested.

The represented selector test subtracts one with unsigned 32-bit arithmetic and accepts a result less than two. Consequently:

- Selector 1 is accepted.
- Selector 2 is accepted.
- Every other 32-bit selector value is rejected.

The subtraction is modulo 2³². For example, selector zero produces 0xFFFFFFFF after subtraction and is rejected. Negative signed selectors are also rejected; they do not select records before the base.

For a rejected selector:

- No direct record write occurs.
- F-a817d8d58c10 is not invoked.
- The function returns without an explicit error indication.
- The external base is not needed by the visible path.

For an accepted selector, the function obtains the external base value, computes the corresponding destination, and stores the complete candidate value as one 32-bit field assignment. It then returns.

### Store semantics

The assignment replaces the destination’s entire 32-bit value. It is not a bitwise merge and does not preserve previously set bits.

In particular, a candidate of zero writes zero. It is not treated as an instruction to skip the update.

The visible body does not read the old destination value. It also contains no comparison against the old value, no suppression of redundant writes, and no visible update to neighboring fields.

The offsets do not wrap for either accepted selector. Address overflow could still arise from the external base value, but the representation does not establish the execution model or a checked failure behavior for that case.
