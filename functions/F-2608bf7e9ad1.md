# F-2608bf7e9ad1

## Purpose

F-2608bf7e9ad1 performs state-dependent selection and control operations on an externally obtained service object, using a temporary collection and fields in a caller-supplied object.

The established behavior includes:

- An immediate return when the object’s initial state byte is 4.
- Construction and preparation of a temporary collection for all other initial states.
- Selection by a stored two-word value, by collection index, or by matching entry properties.
- An optional preliminary selection and readiness check for state 0.
- Either a shared pair of service operations or a fallback service operation.
- A state-byte write to 1 only on the fallback path.
- Finalization of the temporary collection on every normally returning path that constructed it.

The apparent intent is to update a selection or navigation state. That interpretation is inferred, not required: the identities of selected entities, the meaning of the service operations, and the meaning of the state values are not established.

## Interface

### Input and return

The function accepts one address, represented as a 32-bit integer in the supplied source. The address identifies an object with relevant storage through offset `0x14f`.

There is no explicit return value and no explicit error result.

The input must support at least the reads required by its executed path. Paths that write the state or stored value also require writable storage. Null pointers, invalid addresses, and insufficiently sized objects are not checked.

## Behavior

### Initial guard and common preparation

The first observable operation is an 8-bit read at input offset `0x144`.

If that byte is 4, the function returns immediately. It performs no dependency call, collection initialization, service operation, or input-object write.

Otherwise, operations occur in this order:

1. Obtain the service object through F-b7af80e829ec.
2. Pass the 72-byte temporary region and two zero arguments to F-df2422ba76c2.
3. Pass that same region to F-d82ce7cd783e.
4. Obtain a context address through F-6f828c57a429.
5. Follow the global pointer and read the 32-bit resource value at offset `0x30`.
6. Read the input state byte again and dispatch on this second value.

The second state read is significant. The initial check does not freeze the state for dispatch. If an intervening dependency changes the byte to 4, dispatch reaches the fallback behavior rather than repeating the immediate return.

No preservation of global or input-object state by the intervening dependencies is assumed. The service address, context address, and resource value obtained during preparation are retained for subsequent use; changes to their originating locations do not themselves replace those retained values.

### State 0: resource-derived selection

The function first passes the context address plus `0x1c` to F-7659445fb1e0. Its result, together with the retained resource value, is passed to F-841405d28309.

If F-841405d28309 returns zero, execution takes the fallback path. The stored value at `0x148` is not cleared on this branch.

If the result is nonzero:

1. Write a zero 32-bit word at `0x148`.
2. Write a zero 32-bit word at `0x14c`.
3. Call F-7659445fb1e0 again with the context address plus `0x1c`.
4. Pass its fresh result and the retained resource value to F-bc89f750ed18.
5. Write the returned 64-bit value at `0x148`, spanning both stored words.

The separate zero writes precede the second context conversion and resource lookup. They are observable even if a later dependency fails to return.

If the returned 64-bit value is zero, execution takes the fallback path. The comparison uses the returned value, not a subsequent reread of the object field.

For a nonzero result, F-2b8ccbb8ab5f constructs a selection descriptor using the temporary collection and the stored low and high words read from the input object. The service method at table offset `0x20` is then invoked with:

- The service object as receiver.
- The selection descriptor.
- Three explicit zero arguments.

The source also assigns the values 2 and 0 to adjacent temporary words before this invocation. Whether those assignments convey additional ABI-level arguments is unresolved.

Next, the service method at table offset `0xec` is called with the service object as receiver.

If its result is zero, execution takes the fallback path. Otherwise:

1. Call F-7659445fb1e0 a third time with the context address plus `0x1c`.
2. Pass its result and the retained resource value to F-dfe07ab81e0a.
3. If its 64-bit result is nonzero, call F-26d1da26cf7b.

F-26d1da26cf7b receives four explicit arguments, in order: the retained resource value, the high 32 bits of the latest 64-bit result, its low 32 bits, and its high 32 bits again.

If F-26d1da26cf7b returns a signed 32-bit value greater than zero, the service method at offset `0x20` is invoked again. This second invocation uses the already constructed descriptor, that positive return value, and two zero arguments.

Whether or not this second invocation occurs, execution then performs the shared completion operations. A zero result from F-dfe07ab81e0a, or a zero or negative result from F-26d1da26cf7b, does **not** take the fallback path.

The three context conversions are distinct calls. Their results must not be assumed equal.

### State 1 and otherwise unhandled states

State 1 takes the fallback path directly after common preparation.

State 4, if observed by the second state read, also takes the fallback path. All other unhandled 8-bit values do likewise.

### State 2: selection from the stored value

F-2b8ccbb8ab5f receives the selection-descriptor storage, the temporary collection, and the stored low and high words.

The resulting descriptor is passed to the service method at offset `0x20`, with three explicit zero arguments. Execution then performs shared completion.

There is no zero-value check on the stored value in this state.

### State 3: selection at the reported final index

F-a3532bdc80a5 is called with the temporary collection.

If its first result is zero, execution takes the fallback path.

Otherwise, F-a3532bdc80a5 is called again. The second result, reduced by one and represented as a 32-bit unsigned index, is passed to F-e478ae4ee528 together with the collection and descriptor storage.

The resulting descriptor is passed to the service method at offset `0x20`, with three explicit zero arguments, followed by shared completion.

The second result is not checked again. A changing collection can therefore cause the first result to be nonzero and the second to be zero. In that case, the represented index is `0xffffffff`; no local bounds rejection is shown.

### States 5 and 6: search by entry properties

Both states start with a 32-bit unsigned index of zero.

Before every iteration, F-a3532bdc80a5 is called again. Its result is used as a 32-bit unsigned bound. The iteration proceeds only when the current index is strictly less than that bound.

For each visited index:

1. F-62412cb7cfd8 receives the eight-byte entry storage, the collection, and the index.
2. F-45ba275d4fcc receives that entry storage and returns a 32-bit property.
3. The input object’s high stored word is read and tested for zero.
4. Only if that word is zero is the low stored word read and compared with the returned property.
5. Only if both tests succeed is F-3f2e817b9ef7 called on the entry storage.

A match requires:

- In state 5: F-3f2e817b9ef7 returns zero.
- In state 6: F-3f2e817b9ef7 returns nonzero.

Every extracted entry is passed once to F-c1466ea05103 before normal control leaves that iteration, including a matching entry. The entry is therefore finalized before a matching index is used to construct a descriptor.

On a match, the current index is retained. On a nonmatch, the index is incremented and the loop condition is reevaluated using a fresh bound call.

When the loop exits without a match, the current index is still used. There is no explicit “not found” fallback and no clamp to the last valid index.

F-e478ae4ee528 constructs the descriptor for the retained index. The service method at offset `0x20` then receives that descriptor and three explicit zero arguments, followed by shared completion.

### Shared completion and fallback

Shared completion consists of these service calls, in order:

1. Method-table offset `0x28`, with the service object and one zero argument.
2. Method-table offset `0xa4`, with the service object, the 32-bit value `0xffffffff`, and three zero arguments.

This path contains no direct write to the input state byte.

Fallback instead performs:

1. The service method at offset `0xa8`, with the service object as receiver.
2. An 8-bit write of 1 at input offset `0x144`.

The state write occurs after the fallback service call returns.

Both paths then call F-ccf4fcd3c34d on the temporary collection and return. This finalization is also performed when state 0 reaches shared completion without making its optional second selection call.

## Side effects

### Direct memory effects

The function directly writes caller-object storage only in these places:

- State 0, after a nonzero F-841405d28309 result: two zero-word writes followed by a 64-bit result write at `0x148`.
- Every fallback path: state byte set to 1.

No local restoration is performed if a later operation takes the fallback path. In particular, a state-0 lookup result already stored at `0x148` remains stored unless a dependency changes it.

Dependencies and service methods may have additional effects on the caller object, globals, collection, or other memory. Those effects are not constrained by this function’s visible operations.

### Lifetime and ownership

The temporary collection is initialized and later passed to F-ccf4fcd3c34d on normal completion. Each extracted search entry is passed to F-c1466ea05103 before normal search continuation or exit.

These call pairings establish lifecycle operations, not their internal allocation or release semantics. They do not establish that either dependency owns or frees memory.

No explicit descriptor-finalization call is shown. No acquisition or release operation for the service object is shown beyond obtaining its address. Whether service calls retain references to temporary descriptors or entries is documented_only.

### Failure behavior

There is no explicit exception handling, invalid-pointer handling, rollback, or dependency-error propagation.

The explicit control decisions depend on zero/nonzero tests, an unsigned loop comparison, and one signed-positive comparison. The meanings of those results beyond their branch effects are unknown.

If a dependency does not return normally, subsequent writes and finalization calls are not guaranteed by the shown behavior.

## Acceptance examples

These are conditional acceptance scenarios derived from static evidence, not executed tests.

1. **Initial state 4:** The function returns after the initial state read. No dependency is called.

2. **State changes to 4 during preparation:** Given an initial state other than 4, if the second state read sees 4, the function calls the fallback service method, writes state 1, and finalizes the collection.

3. **State-0 initial gate rejects:** If F-841405d28309 returns zero, the function performs fallback without its own writes to either stored-value word.

4. **State-0 stored lookup returns zero:** After an accepted initial gate, the function clears both words, stores the zero 64-bit result, then performs fallback. It does not construct a selection descriptor.

5. **State-0 readiness rejects:** With a nonzero stored result, the preliminary selection call occurs. If slot `0xec` returns zero, fallback follows; the stored result is not locally restored.

6. **State-0 optional operation is unavailable:** If readiness succeeds but F-dfe07ab81e0a returns zero, the function skips F-26d1da26cf7b and the second selection call, but still invokes slots `0x28` and `0xa4`.

7. **State-0 positive optional result:** If the later 64-bit result is nonzero and F-26d1da26cf7b returns 7, the second slot-`0x20` call receives 7 as its nonzero control argument before shared completion.

8. **State 2 with a zero stored value:** The descriptor constructor still receives both zero words, and the selection and completion calls proceed.

9. **Stable state-3 count:** If both count calls return 5, descriptor construction uses index 4. If the first returns zero, fallback occurs without the second count call.

10. **State-5 first match:** Given stable contents, a zero high stored word, and qualifying entries at indices 2 and 4, index 2 is selected. Entries through index 2 are individually finalized; index 4 is not visited.

11. **State-6 nonzero predicate:** An entry whose key matches qualifies only when F-3f2e817b9ef7 returns nonzero.

12. **Stable unsuccessful search:** If the bound remains 3 and no entry matches, entries 0, 1, and 2 are examined and finalized. Descriptor construction receives index 3, not index 2 and not a fallback indication.

13. **Empty search collection:** If the first bound is zero, no entry is extracted. Descriptor construction receives index zero, followed by selection and shared completion.
