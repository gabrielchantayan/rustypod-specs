# F-2fa533c64831

## Purpose

F-2fa533c64831 performs a two-phase operation over an inclusive range of unsigned 32-bit positions:

1. Prepare a request-like record for each position, stopping on a dependency-reported error.
2. Set corresponding bits in one or more bitmap regions, acquiring another region when the current region does not cover the position.

After completing the bitmap phase and obtaining a final zero status, it updates three fields in a state object and returns zero. On a represented error path, it invokes F-b0f922796692 twice and returns the selected status.

The record’s semantic purpose, the meaning of the state fields, and the resources affected by the two final calls are not established. “Request,” “bitmap,” and “region” describe observable structure, not a proven application-level protocol.

## Behavior

### 1. Capture the record value

The function extracts bits 16–31 of the second explicit argument by an unsigned right shift of 16. The resulting value is retained for repeated 16-bit record writes.

A preparation cursor begins at the initial position. The bitmap phase uses a separate position value that also begins at the initial position; advancing the preparation cursor does not itself advance the bitmap position.

### 2. Prepare the inclusive range

Each iteration starts by calling F-b00cf3174ef8.

- A nonzero result immediately selects the error path.
- A zero result permits the three record writes described above.

After the writes, the function compares the preparation cursor with the inclusive final position, then increments the cursor by one using unsigned 32-bit arithmetic.

If the comparison was equal:

- F-f7c5b7585b2d is called.
- A zero result enters the bitmap phase.
- A nonzero result selects the error path.
- F-946cac4b59bc is not called for this final-position iteration.

If the comparison was not equal:

- F-946cac4b59bc is called with the incremented cursor and the request-record base.
- Its returned value, if any, is not used by the visible body.
- F-f7c5b7585b2d is then called.
- A zero result starts another preparation iteration; a nonzero result selects the error path.

The preparation phase has no visible ordered-range check. In particular, an initial position greater than the final position is not rejected. If dependencies continue returning zero, the preparation cursor advances modulo \(2^{32}\) until it equals the endpoint.

### 3. Ensure bitmap coverage

At the start of each bitmap-processing attempt, the function computes the unsigned 32-bit difference between the current bitmap position and the current region base.

If that difference is smaller than the current region capacity, the function proceeds to set a bit.

Otherwise it attempts to acquire another region:

1. Call F-4055be9c3f18 with the region object.
2. Obtain a 32-bit fallback value from an opaque static-data location.
3. If F-4055be9c3f18 returned zero, select that fallback value and take the error path.
4. Otherwise call F-f7c5b7585b2d. A nonzero result selects the error path.
5. Otherwise call F-5f9a16493218. A nonzero result selects the error path.
6. Read the unsigned 16-bit field at state-object offset 0x1c.
7. Use that field to address a signed 16-bit displacement at region-object base plus the field value minus two bytes.
8. Add the sign-extended displacement to the region-object base to obtain the new bitmap pointer.
9. Call F-c4c1afdb3fb3.
10. Derive the new bit capacity from its result multiplied by eight.
11. Set the new region base to the region frontier as it stood for this acquisition, and advance the frontier by the new capacity.
12. Repeat the coverage check for the same bitmap position.

The return convention of F-4055be9c3f18 therefore differs from that of the status checks: zero triggers failure here, while nonzero allows processing to continue.

No visible check rejects a zero capacity. A zero-capacity acquisition can lead to another acquisition without setting a bit. No finite acquisition bound is established.

### 4. Set the selected bitmap bit

For a covered position, let the region-relative difference be the unsigned 32-bit position minus the region base.

The target is the 16-bit bitmap word at index equal to that difference divided by 16, discarding the remainder. Within that word, the untransformed mask selects bit \(15-r\), where \(r\) is the difference modulo 16.

Consequently, before the dependency’s transformation:

- Relative position 0 selects 0x8000.
- Relative position 15 selects 0x0001.
- Relative position 16 selects 0x8000 in the next word.

The function calls F-0ec8efa9c769 with this mask, limited to 16 bits. Its returned 16-bit value is ORed into the target word.

The observable ordering is significant:

1. Compute the target-word address.
2. Call F-0ec8efa9c769.
3. Increment the bitmap position using unsigned 32-bit arithmetic.
4. Read the target word.
5. Write the OR of that word and the dependency result.

Thus the old bitmap word is read after the dependency call. A dependency-induced change to that word can affect the value written back.

After setting the bit, the function compares the incremented position with the inclusive final position using an unsigned comparison:

- If the incremented position is greater than the endpoint, bitmap processing ends.
- Otherwise coverage checking resumes.

This is not a prechecked empty-range loop: the first bitmap position is processed whenever the phase is reached and coverage acquisition succeeds. An endpoint of 0xffffffff cannot be exceeded by an unsigned 32-bit position, so the visible termination comparison cannot end bitmap processing for that endpoint.

### 5. Commit completion fields

After bitmap processing ends, F-f7c5b7585b2d is called once more.

A nonzero result selects the error path without performing the following completion writes. On a zero result, the function:

1. Writes the completion value to state-object offset 0x20.
2. Reads the existing 32-bit value at offset 0x24 and writes it back increased by the completion value minus the first accounting operand minus the second accounting operand.
3. Reads the 32-bit value at offset 0x2c and writes it back with bit zero set.
4. Returns zero.

The accounting expression is represented using signed 32-bit quantities. Its intended overflow semantics are not established by the supplied representation; callers requiring an unambiguous mathematical result must keep its intermediate and final values within the applicable signed range.

### 6. Handle errors

Every represented error path converges on two consecutive calls to F-b0f922796692, followed by return of the selected status.

The visible body does not roll back record writes, bitmap updates, region acquisitions, or dependency side effects already performed.

For a zero result from F-4055be9c3f18, the selected result is the opaque fallback value. Its value is unknown. If that value is zero, this error path can return zero after the two final calls without executing the completion writes.

## Acceptance examples

These are conditional static acceptance cases, not executed tests.

1. **One covered position.**  
   Given initial and final position 10, region base 0, capacity at least 11, all relevant status results zero, and F-0ec8efa9c769 returning its input unchanged: one record preparation occurs, F-946cac4b59bc is not called, and bitmap word zero is ORed with 0x0020. A zero final status permits the three completion updates.

2. **Upper-half extraction.**  
   Given second argument 0xabcd1234, each reached variable-offset 16-bit record write stores 0xabcd. This example specifies the numeric stored value, not its byte order.

3. **Crossing a word boundary.**  
   Given a covered range from relative position 15 through 16 and an identity mask dependency, the first bitmap word receives an OR with 0x0001 and the second receives an OR with 0x8000. Existing set bits remain set at each read-modify-write.

4. **Failure before record preparation.**  
   If the first F-b00cf3174ef8 call returns 7, no direct record write occurs. F-b0f922796692 is called twice, and the selected return value is 7.

5. **Failure after visible preparation.**  
   If the status check after a record preparation returns 9, that preparation’s direct writes have already occurred. The bitmap phase is not reached, and the selected return value is 9 after the two final calls.

6. **Region acquisition failure.**  
   If coverage is insufficient and F-4055be9c3f18 returns zero, the function selects the opaque fallback value. It does not proceed to the subsequent acquisition status check, signed-displacement read, or capacity query on that attempt.

7. **Mutation during mask conversion.**  
   If F-0ec8efa9c769 changes the already-selected bitmap word, the subsequent OR uses the word value read after that call, not a pre-call snapshot.

8. **Final status failure.**  
   If all bitmap updates finish but the final F-f7c5b7585b2d call returns nonzero, those bitmap updates are not visibly undone. The three direct completion writes are skipped.
