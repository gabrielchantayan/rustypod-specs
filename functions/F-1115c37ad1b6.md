# F-1115c37ad1b6

## Purpose

F-1115c37ad1b6 is a read-only predicate over a supplied key and a small linked-memory structure. It produces a 32-bit result whose value is either zero or one.

The established behavior is:

- A null outer reference produces one.
- A non-null outer reference produces one only when its first referenced object has the supplied key and its second reference satisfies one of three conditions: it is null, it is the distinguished all-ones reference, or its second word references that same first object.
- Every other normally completing case produces zero.

The apparent intent is to recognize an absent structure or a particular key-and-link relationship. That interpretation does not establish what the structure represents or whether a result of one means valid, empty, matching, or some application-specific condition. Consumers must not substitute those interpretations for the predicate defined below.

## Interface

### Inputs

The function receives two inputs:

1. **Key:** a 32-bit integer compared for exact equality with a word read from a referenced object.
2. **Outer reference:** a reference that may be null or may identify a word-oriented record.

For description, this contract assigns semantic labels to the memory involved:

| Label | Meaning |
|---|---|
| Outer record | The record addressed by the outer reference |
| Primary reference | The reference stored in the outer record’s first word |
| Primary object | The object addressed by the primary reference |
| Secondary reference | The reference stored in the outer record’s second word |
| Secondary object | The object addressed by an ordinary, non-null, non-sentinel secondary reference |

These labels describe relationships, not ownership or a declared application-level type.

### Widths and layouts

The supplied representation uses 32-bit integer words and a 32-bit reference model. Under that model:

| Memory location | Offset | Interpretation |
|---|---:|---|
| Outer record, first word | 0 bytes | Primary reference |
| Outer record, second word | 4 bytes | Secondary reference |
| Primary object, first word | 0 bytes | Key to compare |
| Secondary object, second word | 4 bytes | Reference to compare with the primary reference |

Only the locations required by the selected branch are read. The function does not establish a complete object size or layout beyond these accessed fields.

Null is the zero reference. The distinguished secondary-reference sentinel has the 32-bit representation `0xFFFFFFFF`. It is not treated as a dereferenceable secondary object.

The 32-bit reference model is supported by the supplied representation, rather than independently confirmed target ABI documentation. Endianness and other ABI details are not established. The offsets above are relative to the supplied four-byte-word model.

### Output

The result is a 32-bit value:

- **One:** the outer reference is null, or the specified key-and-reference conditions are satisfied.
- **Zero:** a required condition fails on an otherwise normally completing execution.

No other normal return value is present.

### Preconditions

A null outer reference requires no accessible record.

For a non-null outer reference, each location actually read must be accessible and suitable for the corresponding word access. Requirements are path-dependent:

- Reading the primary reference requires the outer record’s first word.
- A non-null primary reference requires the primary object’s first word.
- A matching primary key requires the outer record’s second word.
- An ordinary secondary reference requires the secondary object’s second word.

The function does not check whether a non-null address is mapped, readable, aligned, or associated with a live object.

## Behavior

### Null outer reference

The function first determines whether the outer reference is null.

If it is null, the function returns one immediately. No record field is read, and the key has no effect on the result.

This case is distinct from a present outer record whose primary reference is null: that latter case returns zero.

### Primary-reference and key checks

For a non-null outer reference, the function reads its first word and interprets that word as the primary reference.

If the primary reference is null, the function returns zero. It does not read the outer record’s second word.

If the primary reference is non-null, the function reads the first word of the primary object and compares it with the supplied key.

If the values differ, the function returns zero. It does not read the outer record’s second word or follow any secondary reference.

This comparison is an exact 32-bit integer equality comparison. There is no range check, ordering comparison, masking, arithmetic, or normalization. Negative key values are not excluded.

### Secondary-reference classification

Only after observing a non-null primary reference and a matching primary key does the function read the outer record’s second word.

That word is interpreted as the secondary reference and classified into three cases:

1. **Null secondary reference:** return one without accessing a secondary object.
2. **All-ones secondary-reference sentinel:** return one without accessing a secondary object.
3. **Any other secondary reference:** read the secondary object’s second word.

The sentinel exception is specific to the secondary reference. The function does not provide the same exception for the outer reference or primary reference.

### Link equality

For an ordinary secondary reference, the function interprets the secondary object’s second word as another reference and compares it directly with the previously obtained primary reference.

- Equal references produce one.
- Unequal references produce zero.

The function does not dereference the reference obtained from the secondary object. It does not compare the contents of two candidate primary objects. Two distinct references to objects containing equal keys do not satisfy this final condition merely because their contents match.

The secondary object’s first word is not read.

### Read order and short-circuiting

At the abstract level represented by the supplied source, memory reads occur in this order:

1. Outer record’s first word, unless the outer reference is null.
2. Primary object’s first word, unless the primary reference is null.
3. Outer record’s second word, only if the primary key matches.
4. Secondary object’s second word, only if the secondary reference is neither null nor the sentinel.

The primary reference obtained in the first read is retained for the final comparison. The source does not express a second read of the outer record’s first word.

These are source-level access requirements, not guarantees about processor speculation, bus transactions, compiler transformations, or synchronization with concurrent writers.

There is no traversal beyond the one secondary-object field access, no recursion, and no loop.

## Side effects

The supplied function contains no explicit memory writes. It does not modify the outer record, primary object, secondary object, or the key.

It contains no allocation, release, ownership transfer, reference-count update, global-variable access, or call to another function. It does not retain a reference for later use.

Accordingly, this function itself neither takes ownership of the supplied objects nor releases them. Their lifetime and accessibility remain external preconditions.

Invalid memory access has no explicit handling path. A bad reference may prevent normal completion, but the resulting fault or language-level behavior is not specified by this function. It must not be represented as a guaranteed zero result, one result, or structured error.

Reads could have external effects if the caller supplies memory with special access semantics, such as device-backed memory. Such behavior is outside the established ordinary-memory contract.

The function provides no locking or atomic snapshot mechanism. If another actor changes the relevant memory concurrently, the source does not establish a coherent multi-field view.

## Acceptance examples

These examples are conditional specifications derived from static evidence. They are not reports of executed tests. Unless stated otherwise, all required reads are assumed valid and memory remains stable during the call.

| Conditions | Required result | Access boundary |
|---|---:|---|
| Outer reference is null, for any key | One | No object memory is read |
| Outer reference is non-null; primary reference is null | Zero | Only the outer record’s first word is required |
| Primary reference is non-null; primary key differs from the supplied key | Zero | The secondary-reference field is not read |
| Primary key matches; secondary reference is null | One | No secondary object is accessed |
| Primary key matches; secondary reference is `0xFFFFFFFF` | One | The sentinel is not dereferenced |
| Primary key matches; ordinary secondary object’s second word equals the primary reference | One | The secondary object’s second word is read |
| Primary key matches; ordinary secondary object’s second word differs from the primary reference | Zero | The unequal reference is not followed |

Additional boundary cases clarify the contract:

- **Matching negative keys:** A negative supplied key and an equal primary key permit evaluation of the secondary-reference conditions. Sign alone does not cause rejection.
- **Key mismatch with an unusable secondary field:** The mismatch path does not require reading the secondary field. This does not waive the validity requirements for the earlier reads.
- **All-ones primary reference:** This is not a recognized absence marker. The function attempts to read its first word rather than returning a defined Boolean solely because of that representation.
- **Secondary object points to a different object with the same key:** The result is zero. The final test is reference equality, not key equality.
- **Secondary reference equals the primary reference:** This alone does not establish success. The second word at that shared address must itself equal the primary reference.
- **Final reference is null or all ones:** The final reference receives no special sentinel treatment. Since the primary reference is already known to be non-null, a null final reference fails equality. Other values are handled solely by direct equality.

## Uncertainties

The following remain **documented_only**:

- The application-level meaning of the key, objects, sentinel, and Boolean result.
- The complete record definitions, allocation sizes, and ownership relationships.
- Independently verified target ABI, byte order, alignment rules, and pointer-conversion rules.
- Behavior for unreadable, misaligned, stale, or otherwise invalid references.
- Concurrency guarantees and validity of accesses during concurrent mutation.
- Whether broader caller invariants restrict keys, aliasing, or reference values.

No invariant requires the outer record, primary object, and secondary object to occupy disjoint storage. Aliasing is not explicitly rejected; any such case must still satisfy the ordered reads and reference comparisons described above.

The sentinel suggests a distinguished structural state, but its application-level interpretation is inferred intent, not established behavior.

## Evidence

**Established static evidence:** The supplied body contains a null outer-reference early return; a guarded primary-reference read and key comparison; a conditional secondary-reference read; null and all-ones secondary-reference exceptions; and a final reference-equality test after reading the secondary object’s second word. Its explicit return values are zero and one. It contains no writes or calls.

**Representation-dependent evidence:** Four-byte words, four-byte field spacing, a 32-bit result, and the all-ones secondary sentinel follow from the supplied representation. Independent ABI validation is unavailable.

**Inferred intent:** The function appears to recognize an absent outer structure or a matching key with an acceptable secondary-link relationship. No stronger semantic interpretation is required by this contract.

**Runtime evidence:** None. No runtime tests have been performed.
