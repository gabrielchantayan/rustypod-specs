# F-1fef2d51727b

## Purpose

An application-level purpose cannot be established. In particular, the available evidence does not establish that this routine initializes an object, manages a collection, allocates memory, or implements a conventional service. The contract below describes its observable operations without assigning those meanings.

**Evidence status:** static evidence only. No runtime tests have been performed. Some arithmetic conclusions require a 32-bit machine interpretation, identified explicitly below. Indirect-call behavior, entry-register requirements, and the validity of the recovered control flow remain documented_only where unresolved.

## Behavior

For this contract:

- A **byte** is eight bits.
- A **word** is 32 bits.
- A **wide result** is a represented 64-bit dependency result, split into low and high 32-bit halves.
- A byte write retains only the low eight bits of its value.
- An unsigned right shift inserts zero bits.
- Conceptual names such as “initial base” and “late payload” identify values in this document, not program identifiers.

Arithmetic descriptions use the apparent 32-bit machine model: multiplication and left shifts retain the low 32 bits, and address additions are calculated in that width. This is a conditional machine-level interpretation, not a claim that all displayed signed expressions have defined portable-language behavior.

Byte order is not established. The evidence identifies byte accesses and word accesses, not the byte order of stored words.

### Iteration structure and call boundaries

The body contains numerous indirect calls, including runs with no explicit arguments. Those runs are observable and must not be removed merely because their results are unused.

“No explicit arguments” does not establish that a dependency reads no registers, stack storage, or global state. Likewise, a discarded result does not establish absence of side effects.

The following phases are ordered. Operations within later phases require all intervening calls and accesses to complete. This is not an atomic transaction: dependencies execute between the listed accesses and may modify shared storage.

### 1. Entry forwarding and initial word publication

The low byte of the fourth input is captured for the current iteration. The initial base is calculated as the incoming extra-register value multiplied by \(2^{28}\).

The routine then:

- Invokes the first dependency with the first, second, and third inputs.
- Performs a chain of additional indirect calls.
- Takes a returned word as an initial selector.
- Writes the first input to address \(4 \times \text{initial selector} + 20\).
- Passes \(4 \times \text{initial selector}\) to a subsequent dependency.

Further indirect calls produce an initial packed value.

The routine writes the captured byte first to initial base plus 17, then to initial base plus 1. These are two distinct ordered writes.

It passes the initial packed value shifted left by two to a dependency. Another dependency result is forwarded to the next call. Further calls produce another word, after which the same two byte writes occur again, in the same order. The newly returned word shifted left by two is then passed onward.

Intervening dependencies may have changed either byte location, so the second pair of writes is not redundant by contract.

### 2. Initial selector-dependent accesses

Another call chain produces a selector. The routine:

- Writes the initial selector shifted left by 31 to address \(16 \times \text{selector} + 20\).
- Reads a word at address \(20 + ((\text{initial packed value} \mathbin{\&} 0x3fffffff) \gg 20)\).
- Passes four times the selector to a dependency.
- Obtains and retains another returned word, called the retained field here.
- Passes the loaded word shifted right by 22 and then left by 28 to another dependency.

The word-read address lies between 20 and 1043 inclusive before any environmental address interpretation. It is not necessarily word-aligned.

Under 32-bit truncation, the shifted argument retains only bits 22 through 25 of the loaded word, placing them in bits 28 through 31.

Another call chain produces a zeroing selector. The routine writes a zero word at \(4 \times \text{zeroing selector} + 20\), then passes \(4 \times \text{zeroing selector}\) onward.

### 3. Byte-selected writes and global capture

A later dependency produces a packed byte-source value. The routine reads a byte from initial base plus 1 and uses that byte as an unsigned address component. It writes the low byte of four times the packed byte-source value at the byte-selected address plus 17.

The destination therefore lies between 17 and 272 inclusive. The byte read is not a pointer-sized load.

The routine then:

- Passes four times the packed byte-source value to a dependency.
- Obtains another result and forwards it together with the packed byte-source value shifted left by 30.
- Performs further calls.
- Reads initial base plus 1 again, retaining this second byte.
- Writes the low byte of \((\text{packed byte-source value} \mathbin{\&} 0x3fffffff) \gg 20\) at the second byte plus 17.
- Passes a newly returned selector shifted left by two onward.
- Performs more calls.
- Writes the retained field shifted left by two as a word at the second byte plus 20.
- Reads the global word.

The second byte remains the address component for the word write even though calls intervene. It is not reread immediately before that write. The word-write address is between 20 and 275 inclusive and may be unaligned.

The global read occurs after this word write and before the following call chain. A dependency invoked afterward may change the global without changing the captured value used in the next phase.

### 4. First wide result and low-address clearing

A dependency returns a wide result. Four times its low half becomes the first scaled wide value.

Before forwarding the high half to another dependency, the routine rereads initial base plus 1 and writes the low byte of the captured global shifted right by 22 at the selected byte plus 17.

It subsequently forwards a returned word together with the first scaled wide value shifted left by 28. Under 32-bit truncation, this shifted argument depends only on the bottom two bits of the wide result’s low half.

After further calls:

- Initial base plus 1 is reread.
- Zero is written at the selected byte plus 17.
- A returned selector shifted left by two is passed onward.
- More calls produce a selector whose fourfold value is supplied twice to the same dependency.

No deduplication of those equal arguments is justified.

### 5. First paired word publication

A later returned word, shifted left by two, becomes the middle payload.

The routine writes that payload:

1. At \(4096 \times \text{first scaled wide value} + 20\).
2. Later, after intervening calls, at \(4 \times \text{new selector} + 20\).

The first intervening dependency receives the first scaled wide value shifted left by 14. The dependency after the second write receives four times the new selector.

Both word stores use the same retained middle payload, regardless of changes dependencies make to memory.

A second wide result is then obtained. Four times its low half becomes the second scaled wide value.

Before forwarding this wide result’s high half, the routine:

- Reads a byte at \(16384 \times \text{first scaled wide value} + 1\).
- Writes the low byte of \((\text{middle payload} \mathbin{\&} 0x3fffffff) \gg 20\) at that byte plus 17.

### 6. Additional clearing and late payload

Subsequent dependencies receive a returned word and, later, the low and high halves of another wide result as separate arguments.

The next byte clear uses a freshly read byte from \(2^{28} \times \text{second scaled wide value} + 1\). Zero is stored at that byte plus 17.

After further calls, a returned word is retained as the late selector. The routine then clears a byte selected by a fresh read from \(4 \times \text{second scaled wide value} + 1\).

A dependency receives the second scaled wide value shifted left by 10. A subsequent dependency receives a returned word together with the retained field shifted left by 28. After another call chain, the byte selected from \(4 \times \text{second scaled wide value} + 1\) is reread and cleared again.

The late payload is the late selector shifted left by 14. It is written at \(16384 \times \text{late selector} + 20\).

A dependency then receives the late selector shifted left by 16. Further calls include an invocation with:

- The late payload shifted left by 28.
- The otherwise unresolved register-derived value.

Under the 32-bit machine interpretation, the first argument is necessarily zero: the late payload already has fourteen low zero bits, so shifting it left by another 28 discards every original bit.

Another selector is obtained. The late payload is written at four times that selector plus 20, followed by a call receiving four times that selector.

### 7. Final publications and next-iteration state

A subsequent call result becomes the final outer selector. The routine:

- Rereads the byte at \(4 \times \text{second scaled wide value} + 1\).
- Writes the low byte of \((\text{late payload} \mathbin{\&} 0x3fffffff) \gg 20\) at the selected byte plus 17.
- Passes the late selector shifted left by 26 to a dependency.
- Forwards a later returned word together with the final outer selector shifted left by 30.
- Forwards another wide result as separate low and high halves.
- Rereads the same byte-selection location and clears the selected byte.

Further calls produce a word whose fourfold value becomes the final payload. It is written at \(16384 \times \text{final outer selector} + 20\).

The next dependency receives four explicit arguments:

1. The final outer selector multiplied by 4096.
2. That same value again.
3. The final outer selector shifted left by 14.
4. The final payload.

After additional calls, the final payload is written at four times another returned selector plus 20. Four times that selector is passed onward.

A later returned selector produces a new fourfold value. That value is written at sixteen times the selector plus 20. The retained fourth input is set to zero before the next dependency is invoked with three copies of the fourfold value.

Further calls lead to another store of that retained fourfold value at four times a newly returned selector plus 20.

Finally, another selector is obtained. Four times this final selector:

- Is written at sixteen times the final selector plus 20.
- Becomes each of the first three inputs for the next iteration.
- Becomes the extra-register value used to calculate the next iteration’s initial base.

The next iteration’s first indirect target uses the link-derived state established at the end of the current iteration, rather than independently reusing the original incoming link value.

Consequently, from the second iteration onward, the captured fourth-input byte is zero. Other byte writes derived from dependency results need not be zero.

## Side effects

The established direct effects include:

- Ordered byte and word stores to calculated addresses.
- Byte reads that select destinations in the low address range.
- One calculated-address word read and one global word read per completed iteration.
- Repeated indirect calls, including calls with discarded results.
- Replacement of the inputs and hidden state used by subsequent iterations.

No allocation, release, ownership transfer, locking, or synchronization operation is directly established. Dependencies may perform any of these; their behavior is unknown.

There is no basis for assuming that dependencies preserve global memory. Every represented memory reread must therefore observe the state at that point, not a cached earlier value.

Calculated destinations may alias each other, the global location, executable storage, or dependency-owned storage. The evidence establishes no disjointness guarantee. Direct writes themselves may therefore affect subsequent reads.

These examples are conditional static acceptance criteria, not executed tests.

1. **Fourth-input truncation.** If the fourth input is `0x123456ab`, the two early pairs of direct byte writes use `0xab` during the first iteration. If the next iteration is reached, those pairs use zero.

2. **Initial selector addressing.** If the initial selector is 3, the first word store targets address 32 and contains the first input’s 32-bit value. The subsequent explicit address-like argument is 12.

3. **Packed word-read bounds.** An initial packed value of zero selects word-read address 20. A value whose low 30 bits are all ones selects address 1043. No alignment adjustment is represented.

4. **Fresh byte selection.** If the first read of initial base plus 1 yields 7, the associated byte write targets address 24. If a dependency changes that location to 9 before the next read, the later byte write targets address 26.

5. **Retained byte selection.** If the second byte read in phase 3 yields 9, the subsequent retained-field word store targets address 29 even if intervening dependencies change the byte-selection location.

7. **Iteration transition.** If the final selector is 5, the final store targets address 100 and stores 20. The next iteration’s first three explicit arguments are all 20; its initial base is `0x40000000` under 32-bit truncation.

8. **Interrupted execution.** If any dependency does not return, later stores are not required to occur. No rollback of earlier writes is represented.
