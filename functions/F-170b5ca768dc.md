# F-170b5ca768dc

## Purpose

No application-level purpose is established. In particular, the evidence does not justify describing this procedure as initialization, serialization, allocation, device control, or message processing. Repeated scaling and offset patterns suggest structured state manipulation, but that interpretation is **inferred intent**, not a behavioral guarantee.

The contract below records the behavior represented by the supplied material. That material also reports invalid instruction data and excluded control-flow regions. Consequently, it does not establish that every represented operation corresponds to reachable, executable machine behavior.

### Width and arithmetic conventions

Unsigned right shifts are logical. The transformations of the third input and unsigned state word therefore discard low-order bits rather than preserving a sign.

For describing numerical examples, this contract uses a **conditional 32-bit machine interpretation**: scaled values, left shifts, and address additions retain their low 32 bits. This interpretation is not a claim that the supplied signed arithmetic establishes portable overflow behavior. Signed multiplication, signed left shifts, pointer formation, alignment, and overflow semantics require instruction-level confirmation.

Byte-write values are their low eight bits. A byte loaded for an address calculation is unsigned and therefore ranges from 0 through 255.

### Transition into the infinite loop

From the latest sequence result, retain bits 25 through 29 as the **initial loop value**, represented as an unsigned integer from 0 through 31.

For a second selector mechanism, retain the second byte-source word shifted left two bits. Its selector address is that retained value multiplied by 1024, plus one.

Before entering the loop:

- Read an unsigned byte from this second selector address.
- Write zero at that byte value plus 17.
- Call with twice the initial loop value.
- Make another call with no explicit arguments shown; retain its result as the first loop-carried argument.

Under the conditional 32-bit interpretation, the second selector address is equivalently the second byte-source word shifted left twelve bits, plus one.

### Repeating loop

Each iteration performs these actions in order:

- Call with the loop-carried argument and the current loop value shifted right eight bits.
- Execute a four-call sequence.
- Read the second selector byte afresh and write zero at that byte value plus 17.
- Call with the latest sequence result shifted left two bits.
- Execute another four-call sequence.
- Use the final result shifted left two bits as the next loop-carried argument.
- Use the same final result shifted left twenty-six bits as the next loop value.

There is no represented conditional exit.

The second argument to the first call is zero on the initial iteration because the initial loop value is at most 31. On subsequent iterations, under the conditional 32-bit interpretation, it can contain the preceding result’s low six bits shifted left eighteen bits. It is not necessarily always zero.

2. **Third-input shift:** If the third input is `0xffffffff`, the later fourth argument derived from it is `0x0003ffff`. It is not `0x01ffffff`.

8. **No normal completion:** If all reached dependencies return and all accesses succeed indefinitely, reaching the loop does not produce a normal return.
