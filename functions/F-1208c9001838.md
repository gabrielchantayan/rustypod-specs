# F-1208c9001838

## Purpose

F-1208c9001838 performs an ordered sequence of memory updates, captures values from memory, follows several captured values as addresses, and ends with an unresolved indirect invocation. The established contract concerns these accesses and their value dependencies; no application-level purpose or returned result is established.

The opening sequence contains exactly **25 occurrences of a four-write pattern**, totaling **100 writes** before the first represented memory read. Repetition and ordering are part of the represented behavior, even where repeated writes would leave ordinary memory unchanged.

Four absolute-address globals occur at 0x3A, 0x67, 0x21, and 0xA9. **Their declarations are absent, so their access widths are unresolved.** An eight-bit conversion on an assignment’s right-hand side does not establish the destination’s storage width. Similarly, conversion of a global’s value into a 32-bit capture does not establish the width of the global read.

This contract distinguishes:

- **Established static evidence:** represented ordering, explicitly typed indirect-access widths, calculations, and captured-value relationships.
- **Inferred intent:** possible interpretations that are not requirements.
- **documented_only:** behavior that cannot be resolved from the supplied representation.

No runtime tests have been performed.

## Interface

### Explicit and implicit inputs

The explicit input is one represented signed 32-bit integer, called the **supplied word**. It is both a stored value and an address-like operand: the function later reads a word at its value plus byte displacement 0x74.

Three incoming machine-state values are designated **base A**, **base B**, and **base C**:

| Input | Represented arithmetic |
|---|---|
| Base A | Unsigned 32-bit |
| Base B | Signed 32-bit |
| Base C | Signed 32-bit |

These are descriptive contract labels, not recovered identifiers. Their initialization, calling-convention status, validity, and relationship to the supplied word are unknown.

Additional implicit inputs are the contents of reachable memory, the four absolute-address globals, and the unresolved target of the final invocation.

### Outputs and completion

No explicit return value is established. Following the final invocation, no further accesses are represented in the body. If that invocation returns normally, the body returns.

There are no represented validation failures, status codes, recovery paths, or rollback operations. Normal completion requires all reached accesses, address calculations, conversions, and the final invocation to complete under the execution environment’s rules.

### Widths and layout

Displacements in this contract are byte displacements.

| Access form | Established width |
|---|---:|
| Explicit byte access through a calculated address | 8 bits |
| Explicit halfword access through a calculated address | 16 bits |
| Explicit word access through a calculated address | 32 bits |
| Global at 0x3A, 0x67, 0x21, or 0xA9 | **documented_only** |

A 32-bit **capture from the global at 0xA9** means the value resulting from reading that global and converting or assigning it into the represented 32-bit temporary. It does not mean a proven 32-bit source load.

Byte order, address width, alignment rules, and physical access decomposition are unresolved. No object type, field meaning, or allocation boundary follows from the offsets.

## Behavior

### Preconditions and ordering

No null, bounds, permission, alignment, lifetime, or indirect-target checks are represented. Every reached location must support its required operation for normal completion.

Arithmetic on base A is unsigned 32-bit arithmetic. Its doubling and additions of offsets are reduced modulo 2³². Calculations using signed operands do not inherit that wrapping rule. Signed overflow and conversion of integer results into addresses remain **documented_only**.

No non-aliasing guarantee exists. Earlier writes can change later read sources, including globals and locations reached through other bases. Captured values retain the results of their designated reads; later live reads consult storage again.

The order specified below is the order of the supplied static representation. It does not establish machine instruction counts, atomicity, compiler barriers, volatility, or safe concurrent use.

### Opening sequence: 100 writes

Each of the 25 consecutive occurrences contains these four writes:

| Position | Destination | Width | Value |
|---:|---|---:|---|
| 1 | Twice base A plus 0x54 | 32 bits | Supplied word |
| 2 | Base B plus 0x19 | 8 bits | Base A converted to the represented character type |
| 3 | Base A plus 0x11 | 8 bits | Eight-bit conversion of base B |
| 4 | Base B plus 0x34 | 32 bits | Twice base A, modulo 2³² |

The character conversion of base A and the eight-bit conversion of base B are captured during the first occurrence and reused thereafter. No memory read or invocation is represented between these writes.

Character signedness and out-of-range signed-character conversion behavior are unresolved. Where this contract describes a character store as carrying a value’s low byte, that bit-pattern description is conditional on the target’s narrowing rules.

Every opening write precedes the read of the global at 0xA9. An access-trace implementation cannot replace the 25 occurrences with one merely because final ordinary-memory contents match.

### Initial captures and the global at 0x3A

After the complete opening sequence, the function obtains, in order:

1. A 32-bit captured value from the global at 0xA9, with the global’s read width unresolved.
2. A 32-bit word from the supplied word plus 0x74.

It next assigns a calculated value to the global at 0x3A. The calculation is twice the previously captured character conversion of base A, plus 0x30, after the character value’s arithmetic promotion.

This assignment does **not** establish an eight-bit destination:

- Character signedness can affect the promoted arithmetic value.
- The global’s declaration determines conversion and storage of that result.
- Reduction modulo 256 is justified only if the destination conversion has the corresponding eight-bit behavior.

For example, a character bit pattern of 0x91 could represent 145 or −111 under common character interpretations. The promoted results would then be 338 or −174, respectively. Both have low eight bits 0x52, but neither fact proves that only one byte is written or that the global stores the value 0x52.

After this assignment, the function captures a word from base C plus 0x14, followed by a word from base A plus 0x04.

### Base-linked updates and global propagation

The next effects occur in this order:

| Order | Destination | Width | Value |
|---:|---|---:|---|
| 1 | Base C plus 0x0D | 8 bits | Previously captured character conversion of base A |
| 2 | Base A plus 0x08 | 8 bits | 0x6C |
| 3 | Base A plus 0x0D | 8 bits | Previously captured eight-bit conversion of base B |
| 4 | Base A plus 0x09 | 8 bits | Same eight-bit conversion of base B |
| 5 | Base C plus 0x54 | 32 bits | Base C |
| 6 | Global at 0x67 | Unresolved | Eight-bit conversion of the capture from the global at 0xA9, then conversion required by the destination declaration |

The final row proves an eight-bit conversion of the assigned expression, not an eight-bit store to the global.

The function then reads a signed 32-bit word at base C plus 0x44, called the **shift-source word**. After that read, it reads the global at 0x67 and assigns its value to the global at 0x21. Both global access widths and any assignment conversion between their declared types remain unresolved.

This is a live read of the global at 0x67, not substitution of the original capture from 0xA9. Aliasing, intervening changes, and the global’s own assignment/read conversions can affect its value.

### Shift-derived update

The next four writes are ordered as follows:

| Order | Destination | Width | Value |
|---:|---|---:|---|
| 1 | Base A plus 0x10 | 8 bits | Character conversion of the shift-source word |
| 2 | Base B plus 0x54 | 32 bits | Shift-source word |
| 3 | Base C plus 0x01 | 8 bits | Character conversion of the shift result |
| 4 | Base B plus 0x54 | 32 bits | Base A |

The shift uses the signed shift-source word as its left operand. Its count is base A masked to its low eight bits, giving a range of 0 through 255.

For a nonnegative operand and count below 32, the ordinary signed 32-bit right-shift result is established. Negative operands require the target’s signed-right-shift rule. Counts of 32 or greater have no established portable result.

The two writes at base B plus 0x54 remain separate represented effects, despite the later overwrite.

### Word propagation and overlapping destinations

The function next captures the word at base A plus 0x40. It then performs these effects in order:

| Order | Effect |
|---:|---|
| 1 | Write the earlier capture from base A plus 0x04 as a word at base B plus 0x74. |
| 2 | Write the new capture from base A plus 0x40 as a word at base A plus 0x10. |
| 3 | Write base C as a word at base B plus 0x44. |
| 4 | Read the global at 0x67, then convert and write its value to the eight-bit destination at base A plus 0x09. |
| 5 | Write the captured character conversion of base A at base C plus 0x09. |
| 6 | Write the 32-bit capture from the global at 0xA9 at base A plus 0x44. |

The read in row 4 has unresolved width; its destination write is explicitly eight bits.

With ordinary byte-addressed storage and no address wrap, the word write at base A plus 0x10 covers offsets 0x10 through 0x13. It therefore overlaps both the preceding byte write at offset 0x10 and the opening byte write at offset 0x11. Individual resulting bytes depend on byte order.

The function then captures the word at base A plus 0x54 as the **selected destination address**. After this capture, it again reads the global at 0x67 and writes the converted value to the eight-bit destination at base A plus 0x09. This is a distinct live read and write.

### Selected destination and secondary traversal

The first update through the selected destination writes the eight-bit conversion of the supplied-word-relative capture at selected destination plus 0x0D.

The following effects then occur in order:

1. The earlier capture from base C plus 0x14 replaces the word at base C plus 0x54.
2. The word at base A plus 0x14 is captured.
3. The eight-bit conversion of the supplied-word-relative capture is written at base C plus 0x11.
4. A character conversion of the selected destination address is written at base A plus 0x09.
5. The selected destination address is written as a word at base A plus 0x44.

The next word read, at base C plus 0x04, provides the **secondary address**.

A 16-bit value of 0x0065 is then written at twice the secondary address. This is an explicitly halfword-sized store, not a byte store. Its address calculation uses signed multiplication, whose overflow behavior is unresolved.

The word read at secondary address plus 0x64 supplies the **link word**. After that read:

- A character conversion of the capture from base A plus 0x14 is written at selected destination plus 0x11.
- The 32-bit value 100 is written at selected destination plus 0x54.

The next two word reads are, in order:

1. Secondary address plus 0x74.
2. Base C plus 0x64, providing the **terminal address**.

The final three stores are:

| Order | Destination | Width | Value |
|---:|---|---:|---|
| 1 | Base C plus 0x09 | 8 bits | Character conversion of the secondary address |
| 2 | Terminal address plus 0x54 | 32 bits | Link word |
| 3 | Twice the link word | 32 bits | Terminal address |

The last destination uses signed multiplication. Modulo-2³² wrapping is not established for that calculation.

## Side effects

Established effects include 100 opening writes; later explicitly sized byte, halfword, and word accesses; accesses to four globals of unresolved width; address-like traversal; and one final indirect invocation.

The represented global-access order is:

1. Read at 0xA9.
2. Assignment at 0x3A.
3. Assignment at 0x67.
4. Read at 0x67 followed by assignment at 0x21.
5. Two later reads at 0x67, each feeding an explicit eight-bit write at base A plus 0x09.

Other accesses intervene as specified above. Missing declarations prevent assigning byte ranges to the global accesses. Consequently, overlap involving these globals cannot be determined solely from their starting addresses.

No allocation, release, lock, diagnostic output, or exception handler is represented in the body. This does not constrain F-INDIRECT-01.

No ownership transfer is established. Storing or passing address-like values does not prove borrowing, retention, consumption, or release. The dependency cannot be assumed to preserve globals, reachable memory, or ownership state.

No rollback is represented. Earlier writes can remain effective if a later operation fails or never returns.

## Acceptance examples

These are conditional requirements, not executed tests.

### Exact opening trace

Given an environment exposing the represented access sequence and valid destinations, exactly 25 four-write occurrences precede the read of the global at 0xA9. There are 100 writes and no represented memory reads or invocations within that prefix.

One, 24, or 26 occurrences would not preserve this trace, even if final ordinary-memory contents matched.

### Global widths remain declaration-dependent

A compatible contract must not require the access at 0xA9 to be a 32-bit load merely because its value becomes a 32-bit capture.

Likewise, the assignment at 0x67 must not be required to use an eight-bit destination solely because its assigned expression undergoes an eight-bit conversion. Its physical width remains **documented_only** until the declaration is supplied.

### Conditional arithmetic at 0x3A

Suppose the captured character conversion of base A has bit pattern 0x91. Under a target where conversion to the destination preserves the low eight bits as an eight-bit stored value, the assignment at 0x3A stores 0x52.

Without that destination rule, only the promoted character calculation followed by destination conversion is required. A wider stored result is not excluded. No digit-range validation is represented.

### Live global reads versus captures

If the global at 0x67 changes between its three later read occurrences, those occurrences use their respective current values, subject to the global’s declared read semantics and destination conversions. They cannot unconditionally be replaced with the initial eight-bit expression assigned to that global.

Conversely, changing memory at base C plus 0x14 after its capture does not change the third argument to F-INDIRECT-01.

### Defined small shift

If the shift-source word is 0x12345678 and the low byte of base A is 4, the shifted result is 0x01234567. Under the usual character conversion preserving its low eight bits, the byte at base C plus 0x01 receives 0x67.

A count of 32 has no deterministic result established here.

### Overlap and intermediate writes

Given ordinary byte-addressed storage, no address wrap, and no interfering aliases, the word write at base A plus 0x10 supersedes the earlier byte writes at offsets 0x10 and 0x11. Final individual bytes depend on byte order.

Separately, base B plus 0x54 receives the shift-source word before receiving base A. Checking only the final word does not establish preservation of that intermediate write.

Neither example establishes overlap involving an unresolved-width global.

### Failure before invocation

If a required operation cannot complete, invocation of F-INDIRECT-01 and normal return are not guaranteed. Earlier writes are not contractually undone.
