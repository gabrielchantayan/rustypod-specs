# F-a925704a7cb6

## Purpose

F-a925704a7cb6 conditionally writes two classification bytes and a marker byte into a destination object.

Five unsigned inputs are range-checked and packed into a numeric key. Classification depends on that key, literal comparison values, and eight referenced classification values whose contents are not supplied. A successful classification reaches three ordered byte writes: the first classification byte at offset `0x54`, the second at `0x55`, and `1` at `0x24`. An unsuccessful classification returns without resolving a default destination or writing object fields.

**Established static evidence:** input bounds, key construction, classification branches, repeated reads of referenced values, an optional destination-provider call, and the ordered stores.

**Inferred intent:** the two bytes encode a category, and the final byte marks an update or activation. Their domain-specific meanings are unknown.

The stable-value classification tables below are conditional contracts, not an unconditional enumeration of accepted inputs. The read-order description separately covers paths where successive reads of a referenced value differ.

## Behavior

### Validation and key construction

The digits are checked in input order, with rejection as soon as an out-of-range digit is encountered. Rejection precedes every classification-global read, dependency call, and destination write.

For admitted inputs, the key is

\[
K=(d_1\ll16)\mathbin{\vert}(d_2\ll12)
  \mathbin{\vert}(d_3\ll8)\mathbin{\vert}(d_4\ll4)\mathbin{\vert}d_5.
\]

Each digit occupies four bits. The shifts and combination fit within 32 bits; the key ranges from `0x00000` through `0x44444` and is nonnegative as a signed 32-bit value. Distinct admitted tuples produce distinct keys.

The key is a comparison and arithmetic operand. The function does not dereference it.

### Referenced values and interpretation

|---|---|

| B | Pivot on the lower outer route |
| C | Pivot on B’s lower route |
| D | Pivot on B’s upper route |
| E | Pivot on the upper outer route and subtraction operand |
| F | Pivot on E’s lower route |

### Established read order and changing-value behavior

Each read described here is a separate access visible in the supplied static representation. Repeated mentions of a label do not imply reuse of one sampled value. These sequences describe source-facing accesses, not an independently established hardware transaction or synchronization model.

#### Outer routing

A is first read for equality with K.

- Equality selects `(0, 1)` without another classification-global read.
- Otherwise, A is read again for the signed test “A is less than K.”
- A true ordering test enters the upper outer route.
- A false ordering test enters the lower outer route.

If those reads differ, entering the lower route does not prove that K is strictly below either sampled A. Stable-value tables may use strict regions because an earlier equality failure excludes equality only when the value remains unchanged.

#### Lower outer route

B is read for equality with K.

- Equality selects `(3, 1)`.
- Otherwise, B is read again to test whether B is less than K.

A true ordering test selects the D route; a false test selects the C route.

On the C route, C is read first for equality. Equality selects `(1, 2)`. Otherwise, C is read again to test whether C is less than K. A true result selects the C-upper literal group; a false result selects the C-lower literal group.

On the D route, D is read first for equality. Equality selects **`(0, 4)`**. Otherwise, D is read again to test whether K is less than or equal to D. A true result selects the D-lower literal group; a false result selects the D-upper literal group.

The non-strict D comparison matters when successive reads differ: equality against the second read can enter the literal group despite failure of the first equality test.

#### Upper outer route

E is accessed in this order:

1. An equality read compares E with K. Equality sets the prospective first classification byte to `5`; it does not finish classification.
2. A separate read supplies the operand for the signed 32-bit subtraction \(K-E\).
3. Another read tests whether K differs from E.
4. Only if that inequality is true, a further read tests whether K is less than E.

Thus, subtraction is evaluated on **every path entering the upper outer route**, including paths ultimately taking E equality or the below-E route. Its operand is the second E read, not necessarily the value used by either neighboring comparison. Arithmetic caveats apply at this point even if the difference is never subsequently used.

If the third E read equals K, classification proceeds with second byte `1`. When the first E read also equaled K, the pair is `(5, 1)`. When the first read differed, that path has not established the first classification byte. The supplied representation does not justify inventing a default value or treating the path as rejection.

If the third read differs and the fourth read places K below E, classification uses F:

- F is read for equality; equality selects `(2, 0)`.
- Otherwise, F is read again to test whether K is less than or equal to F.
- A true result selects the F-lower literal group.
- A false result reads G once and selects the adjustment group.

If the fourth E read does not place K below E, classification uses the already-computed difference. With changing values, this includes equality against that fourth E read; it need not mean K exceeds the E value used for subtraction.

H is first read for equality with the difference. Equality selects `(4, 3)`. Otherwise, H is read again to test whether H is less than the difference. A true result selects the H-upper difference group; a false result selects the H-lower group.

There is no second subtraction and no post-classification rereading of these values.

## Acceptance examples

These are conditional consequences of static evidence, not executed tests.

### Rejection before classification reads

Digits `(0, 1, 2, 3, 5)` are rejected before reading A–H, calling the dependency, or writing destination fields. The same applies to any digit equal to `0xFFFFFFFF`, regardless of the destination argument.

### Lower literal match

Digits `(0, 1, 2, 3, 4)` produce `0x01234`. With stable values placing the key below A, B, and C, the pair is `(1, 5)`.

For a valid nonzero destination, offsets `0x54`, `0x55`, and `0x24` receive `1`, `5`, and `1`, in that order.

### D equality

If stable values route an admitted key below A and above B, and the key equals D, the pair is `(0, 4)`. The second classification byte is `4`, not `1`.

### Zero classification bytes

Digits `(3, 2, 1, 0, 4)` produce `0x32104`. Under stable values placing the key above A, below E, and below F, the pair is `(0, 0)`. Both zero bytes are written, followed by marker `1`.

### Subtraction despite E equality

If stable values route K above A and make `K = E`, E is read for equality, again for subtraction, and again for inequality. The subtraction evaluates to zero. The inequality fails, no fourth E read occurs, and the pair is `(5, 1)`.

### Below-E route with a different subtraction operand

Suppose upper outer routing is reached, and successive E reads are `K+1`, `K-2`, `K+1`, and `K+1`, with representable values.

The subtraction evaluates to `2`, but the fourth read routes classification below E. F then determines the next group. The difference does not select a difference-group output.

### Changing E exposes an unresolved first byte

Suppose upper outer routing is reached and the first E read differs from K, while the third E read equals K. Assuming the intervening subtraction has an established result, the function reaches the writes with second classification byte `1`.

The supplied representation has not established the first classification byte on that path. Its value remains **documented_only**; the contract supplies no replacement value.

### Difference precedence

For a stable above-E route with difference `0x00F0`:

- H greater than the difference selects `(5, 0)`.
- H equal to the difference selects `(4, 3)`.
- H below the difference selects the upper difference group, where `0x00F0` is unmatched and therefore rejected.

### Default destination

If classification selects `(3, 2)` and the destination argument is zero, the dependency is called once. A valid returned destination receives `3`, `2`, and `1` at the specified offsets. An invalid result is not locally guarded.
