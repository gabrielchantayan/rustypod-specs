# F-d7f01184ca60

## Purpose

F-d7f01184ca60 invokes an extensive ordered chain of indirect dependencies, transforms their results, performs direct memory accesses through computed and fixed addresses, and finishes with a four-argument indirect transfer.

The supplied static representation does not establish a higher-level application purpose. Character-like constants, repeated offsets, and address-bearing words do not justify classifying the operation as formatting, initialization, parsing, or object construction.

This contract distinguishes:

- **Established static evidence:** represented operations, widths, data dependencies, and ordering.
- **Inferred intent:** possible interpretations that impose no behavioral requirement.
- **documented_only:** behavior lacking sufficient evidence for an executable acceptance criterion.

The requirements below describe the represented behavior, conditional on dependencies and memory accesses completing normally. No runtime tests have been performed.

## Interface

### Entry state

The represented interface has no explicit parameters and no declared scalar return value. It nevertheless consumes implicit inputs:

- An incoming control-link value determines the first indirect target by addition of 4094.
- An incoming register-carried 32-bit value supplies an early argument after a left shift of 12.
- Primary, secondary, and combined dependency results supply subsequent arguments, stored values, and addresses.
- Fixed-address storage, a global address-bearing word, and computed-address memory supply additional inputs during the direct-memory phase.

The ordinary parameter list therefore does not describe the complete input state.

### Results and completion

Observable results include dependency invocations, their arguments and order, direct memory accesses, and the terminal indirect transfer. No explicit scalar result is returned.

## Behavior

### Dependency-driven phase

The opening invocation order is:

- Three calls without explicit arguments.
- A call receiving the incoming register-carried word shifted left by 12.
- Two calls without explicit arguments.
- A call receiving the preceding combined result’s low word shifted left by eight and high word shifted left by three.

The remaining dependency-driven phase is a long represented straight-line chain. Calls receive zero to four arguments. Results are sometimes consumed immediately and sometimes retained across intervening calls. A retained result is not interchangeable with a later result occupying the same register or width.

Transformations include left shifts, unsigned right shifts, masks, repeated arguments, and explicit zeros. Combined results are extracted above bit positions 32, 34, 36, and 44. Masks select portions of several widths, including 24, 22, 20, 19, 17, 14, 13, 12, and 11 bits.

Calls with unused results, duplicate arguments, or zero arguments remain observable dependency boundaries. They are not established as pure calculations.

The supplied dependency map does not resolve the indirect targets. A complete site-by-site invocation and argument ledger is not certified by this document; that coverage remains **documented_only**, rather than permission to reorder or omit calls.

### Arithmetic constraints

Unsigned operations use their represented widths. Discarded high bits cannot be recovered by subsequently reversing a shift.

Some shifts and multiplications are represented using signed 32-bit operands. Negative operands, signed overflow, and signed left shifts do not acquire portable mathematical semantics merely from their notation. Examples using modular results below explicitly assume 32-bit bit-vector arithmetic.

A late dependency-produced word is shifted left by eight, masked with 0x7FFF, and logically shifted right by six. Under that assumption, the resulting **narrow index** is a multiple of four from 0 through 508. Its doubled value, the **indexed base**, is a multiple of eight from 0 through 1016. These bounds do not constrain other addresses.

### Opening direct-memory effects

The direct-memory phase begins after the final combined-result-producing call.

A retained transformed word is written at offset 0x14 from that combined result’s high word. A byte at offset nine from another retained address is then written twice: first from the high word, later from the retained transformed word. Between those byte writes, a word is stored at an address formed from the combined result’s low word multiplied by 256, plus 0x54.

For the following discussion, the **multiplication base** is a retained dependency result multiplied by 0x02000000. An **early shifted word** is another retained dependency result shifted left by eight.

The multiplication base’s word at offset 0x14 is cleared before its byte at offset five is read. A clear at indexed-base offset 0x14 intervenes before the byte is widened and written to multiplication-base offset 0x34. The cleared multiplication-base word is then read back.

A second clear at indexed-base offset 0x14 precedes two distinct byte stores at indexed-base offset 0x15, both sourced from that read-back word.

These accesses are incremental effects. Aliasing can make their intermediate values observable.

### Early fixed-address effects

The next fixed-address operations have explicit placement and sources:

- The byte at fixed address 5 is read and zero-extended.
- The byte at fixed address 1 receives the low byte of the indexed base.
- Using the captured byte from address 5 as a base, a byte at offset 0x15 receives the low byte of the narrow index.
- At multiplication-base offset 0x11, a byte receives the early shifted word’s low byte.
- At offset 0x54 from the earlier read-back word interpreted as an address, a word receives the early shifted word.
- The byte at multiplication-base offset 0x11 is overwritten with zero.

Only afterward is a word captured at offset 0x54 from the zero-extended fixed-address byte. This captured word is called the **anchor** below. Its location is then overwritten with the earlier read-back word, followed by a word write of the narrow index at indexed-base offset 0x34.

Further computed-address operations include a read at multiplication-base offset 0x74, stores through loaded address-bearing words, and repeated self-referential word and truncated-byte stores.

Within this region, indexed-base offset 0x14 first receives another dependency result shifted left by 26. The word at **fixed address 0x54** then receives the anchor shifted left by one. Indexed-base offset 0x14 subsequently receives the anchor twice as two separate word stores.

Two byte stores at indexed-base offset 0x15 follow, each sourced from four times the anchor. The byte at **fixed address 0x15** then receives the indexed base’s low byte. This fixed-address store precedes the word write of the early shifted word at offset 0x54 from four times the anchor, and the later word write of the anchor shifted left by two at indexed-base offset 0x34.

The fixed addresses 0x54 and 0x15 are not merely examples of unresolved global behavior. They are explicit direct stores, potentially overlapping computed destinations.

### Computed-address propagation and literal stores

Subsequent operations repeatedly treat loaded words as addresses. They include:

- Reads through offsets four, five, 0x64, and 0x74.
- Byte writes at offsets nine, 0x0D, 0x11, and 0x15.
- Word writes at offsets 0x14, 0x44, and 0x54.
- Repeated reads of a byte at offset five, whose zero-extended value becomes the base for a word read at offset 0x74.

Repeated reads are not established as returning identical values. Intervening writes may alias their locations.

For the remaining phases, define these document-level descriptions:

- **Link word:** the word obtained by the later offset-0x74 read whose base is a zero-extended byte read through offset five.
- **Link base:** twice the link word.
- **Literal base:** four times the link word.
- **Adjusted quantity:** four times the anchor, minus 150.
- **Working base:** four times the adjusted quantity.
- **Global base:** the address-bearing word captured from global storage before the repeated write region.

These names describe captured values, not object types or distinct allocations.

A literal sequence writes 0x3A as a byte at the literal base, as a halfword at eight times the link word, and as a word at literal-base offset 0x20.

At working-base offset 0x20, successive word stores carry 0x20 and 0x2F. A byte is then read at working-base offset four, widened, and written to that same word destination. Another word store of 0x20 follows.

After those computed-address operations, the global address-bearing word is read. Only then does the word at **fixed address 0x60** receive 0x20. The global read cannot be moved after this store: the storage may overlap.

### Repeated write region

A long repeated region follows the fixed-address 0x60 store. Each group updates, in order:

1. A computed word destination at offset 0x54.
2. The byte at global-base offset 0x19, sourced from the working base.
3. The byte at working-base offset 0x11, sourced from the global base.
4. The word at global-base offset 0x34.

The first group’s first destination uses eight times the anchor as its base; its last store also carries eight times the anchor. Subsequent groups use eight times the adjusted quantity for those roles. The offset-0x54 word value is the literal base throughout.

The byte sources are captured low bytes, not fresh reads of the pointed-to memory. Every represented group remains distinct. This document does not certify a numerical repetition count; count-specific acceptance remains **documented_only**. Deduplicating the region into final-state assignments is not an established equivalent.

### Final capture boundary

The following ordering is established after the repeated region:

- A 32-bit word is captured from **fixed address 0xA9**.
- A 32-bit word is captured at literal-base offset 0x74.
- The byte at **fixed address 0x3A** is written.
- Only afterward are words captured at link-base offset 0x14 and working-base offset four.

The byte written to 0x3A is the low eight bits of eight times the adjusted quantity’s low byte, plus 0x30. Under 32-bit bit-vector arithmetic, this is equivalently the low byte of eight times the adjusted quantity plus 0x30.

The 0x3A store is therefore an intervening memory effect, not a literal constant assignment. If it overlaps either subsequent capture, that capture must reflect memory after the byte write. The earlier captures from 0xA9 and literal-base offset 0x74 remain earlier snapshots.

### Final updates and fixed-address byte state

The first final updates write the working base’s low byte at link-base offset 0x0D, 0x6C at working-base offset eight, and the global base’s low byte at working-base offsets 0x0D and nine. Link-base offset 0x54 then receives the link base itself.

The byte at **fixed address 0x67** next receives the low byte of the captured word from 0xA9. A word is then read at link-base offset 0x44. Only after that read is the current byte at 0x67 read to supply a byte write at **fixed address 0x21**.

The captured offset-0x44 word supplies a byte at working-base offset 0x10 and a word at global-base offset 0x54. Its signed right shift supplies a byte at link-base offset one; the shift count is the working base’s low byte. The global-base word at offset 0x54 is subsequently overwritten with the working base.

A word is captured at working-base offset 0x40. The earlier captured working-base offset-four word is written to global-base offset 0x74, followed by a word write of the offset-0x40 capture at working-base offset 0x10. Global-base offset 0x44 then receives the link base.

At this point, the byte at 0x67 is read again to supply a byte store at working-base offset nine. This is a fresh read, not reuse of the byte initially written to 0x67.

Before another fresh read of 0x67 supplies a second byte store to working-base offset nine, three other operations intervene: a byte write at link-base offset nine, a word write of the captured 0xA9 word at working-base offset 0x44, and a word capture at working-base offset 0x54.

Any intervening destination can alias 0x67. The three reads of 0x67—one for 0x21 and two for working-base offset nine—must therefore remain separate reads with their represented placement.

### Terminal updates and transfer

The word captured at working-base offset 0x54 becomes another destination base. Its offset 0x0D receives the low byte of the earlier literal-base offset-0x74 capture. Link-base offset 0x54 is restored from the word captured after the 0x3A store.

A word read at working-base offset 0x14 supplies a later truncated-byte store. Intervening updates include a byte at link-base offset 0x11 and byte and word writes at working-base offsets nine and 0x44.

A word read at link-base offset four becomes the **terminal base**. A halfword at twice that value receives 0x65. The word at terminal-base offset 0x64 is then captured.

After a byte write to the destination base’s offset 0x11 and a word write of decimal 100 to its offset 0x54, a word is captured at terminal-base offset 0x74. A further word is read at link-base offset 0x64. The last updates include a truncated terminal-base byte at link-base offset nine, a word store through the latter loaded word at offset 0x54, and a word store at twice the terminal-base offset-0x64 capture.

## Side effects

All direct accesses are incremental. No transaction, rollback, cleanup boundary, or atomic publication is visible.

Computed bases may alias each other, fixed storage, or the global address-bearing word. In particular:

- A byte at offset 0x15 overlaps a word spanning offsets 0x14–0x17.
- Fixed storage at 0x67 is mutable state, not a constant source.
- Reads after fixed-address writes cannot be replaced with entry-time snapshots.
- Duplicate stores cannot be collapsed solely because their values match.

No allocation or release operation is identifiable from the direct-memory phase. Dependencies may nevertheless allocate, release, retain arguments, invalidate addresses, or mutate globals.

No ownership transfer, lifetime extension, synchronization, reentrancy, or idempotence guarantee is established. Invalid targets and inaccessible memory are not converted into a documented recoverable result.

## Acceptance examples

These are conditional static review examples, not executed tests.

### Width and extension

A byte store sourced from 0x123456AB writes 0xAB. An unsigned byte read of 0xFE widened into a word supplies 254, not −2.

### Narrow index

Under 32-bit bit-vector arithmetic, a dependency word with its low seven bits set produces narrow index 508 and indexed base 1016. Treating the result as an arbitrary 15-bit index is incorrect.

### Early fixed-address ordering

If the indexed-base-derived byte written at fixed address 1 overlaps storage relevant to a later computed access, that later access uses the post-write state. The byte read from fixed address 5 nevertheless remains the value captured before the address-1 write.

The word write at fixed address 0x54 and byte write at fixed address 0x15 must occur at their specified boundaries, not as delayed final-state updates.

### Global capture before 0x60

If the global address-bearing word overlaps the word at fixed address 0x60, the global base is captured before the 0x20 store changes that storage. Reloading it afterward is not equivalent.

### Intervening 0x3A write

Assume the adjusted quantity’s low byte is 2. The byte written at fixed address 0x3A is 0x40.

If a subsequent link-base offset-0x14 or working-base offset-four capture overlaps 0x3A, it observes the applicable post-write byte. Capturing either word before this write is incorrect. The resulting word depends on endianness and overlap.

### Fresh 0x67 reads

Assume 0x67 initially receives 0xAB from the captured 0xA9 word. If an intervening computed write changes 0x67 to 0xCD before one of its later reads, the corresponding destination receives 0xCD. Reusing 0xAB would violate the represented data dependency.

Each later read is evaluated independently; the two working-base offset-nine stores need not carry equal bytes.

### Literal sequence and terminal boundary

An observable working-base offset-0x20 trace includes word stores of 0x20 and 0x2F before the offset-four byte read and subsequent stores.

After normal completion of preceding effects, the terminal invocation receives the four arguments in the specified positions. Replacing it with a guessed output operation is not acceptable.
