# F-4d9289c8cc5e

## Purpose

F-4d9289c8cc5e dispatches on the leading byte of a descriptor and publishes a result associated with a context. Its established behaviors are:

- Constructing a result through a common dependency sequence for tags `X`, `}`, and `|`.
- Recursively processing a nested descriptor for tag `U`, then transforming three words of the returned object when the recursive status is zero.
- Constructing a result through a separate dependency sequence for tag `~`.
- Publishing null for a null descriptor or an unrecognized tag.
- Returning status `7` for a specific construction failure in the current invocation, and status `0` on all other paths that reach an ordinary return.

The `U` transformation resembles numeric negation across multiple representations. That is inferred intent, not an established object type or mathematical interpretation. The fixed-width transformations below define the behavior.

This contract is based on static evidence only. No runtime tests have been performed.

## Behavior

### Initial state and dispatch

A private result holder initially contains null.

For a null descriptor, the function writes zero to the output slot and returns `0`. It does not read a tag or directly call a dependency.

For a non-null descriptor, the leading byte is read for dispatch. The captured tag is also used for the later mode decision on the `X`/`}`/`|` path; that decision does not directly reread the descriptor’s tag after dependency calls.

### Tags `X`, `}`, and `|`

These tags share one construction sequence.

First, the function obtains the descriptor’s 32-bit field at offset `20` and the unsigned 32-bit field at offset `24`. The latter is logically shifted right by one, producing a value from `0` through `2147483647`.

It calls F-5fba96760515 with, in argument order:

1. The offset-`20` field.
2. The shifted offset-`24` quantity.
3. The auxiliary value.
4. The original mode.
5. The same auxiliary value again.

The relative evaluation order of the two descriptor-field reads is not established. Both supply this call.

After F-5fba96760515 returns, the function calls F-57e7ed96facd with the context and retains its candidate object address. This second call occurs even if F-5fba96760515 returned zero.

#### Explicit construction failure

If the F-5fba96760515 result is zero, the candidate object address is null, or both conditions hold, the following sequence occurs:

1. Write byte value `1` at context offset `30`.
2. Call F-94cb53877c15 with the F-5fba96760515 result.
3. Call F-c70de8d2b40e with the candidate object address.
4. Write zero to the output slot.
5. Return `7`.

Both failure-position dependency calls occur even when their respective argument is zero. Their treatment of zero is unknown.

The context-byte write precedes both calls. The function does not establish that this byte still contains `1` at return: either dependency may affect accessible state, and publication may affect it if storage aliases.

#### Successful construction

When both values are nonzero, the function performs these operations in order:

1. Call F-9744300c7ccc with the F-5fba96760515 result.
2. Call F-df71e640897e with:
   - The candidate object address.
   - The 32-bit bit pattern `0xffffffff`.
   - The F-5fba96760515 result.
   - The value `1`.
   - A value read from shared storage, whose type and width are unestablished.
3. Select the mode for F-b3a211f667d5:
   - For tag `|` or `}`, original mode `98` becomes `99`.
   - For every other applicable combination, the mode remains unchanged.
4. Call F-b3a211f667d5 with the candidate object address and selected mode.
5. Publish the retained candidate object address and return `0`.

The substitution affects only the later mode argument. F-5fba96760515 has already received the original mode.

No failure branch depends on return values from F-9744300c7ccc, F-df71e640897e, or F-b3a211f667d5. Their internal failure behavior and effects on the candidate object remain unknown.

### Tag `U`

The function reads the nested descriptor address at offset `8` and recursively calls F-4d9289c8cc5e with the same context, auxiliary value, and mode. The recursive output slot refers to this invocation’s private result holder.

If the recursive status is `0`, the returned object is transformed without checking whether its address is null.

Let \(L\), \(H\), and \(S\) denote the original 32-bit words at offsets `0`, `4`, and `12`. The directly written bit patterns are:

- Offset `0`: \((-L) \bmod 2^{32}\).
- Offset `4`: \(-(H + b) \bmod 2^{32}\), where \(b=1\) when the original \(L\) is nonzero and \(b=0\) otherwise.
- Offset `12`: \(S \mathbin{\mathrm{XOR}} \texttt{0x80000000}\).

Thus the high-word operation negates the sum of the original high word and the low-word nonzero indicator. It does not add that indicator after negation.

The visible access order is:

1. Read the original low word.
2. Write its transformed value.
3. Read and write the high word.
4. Read and write the word at offset `12`.

The high-word condition uses the saved original low word, not the newly stored low word. The offset-`12` operation toggles bit `31` and preserves the other bits in that word.

If the recursive status is nonzero, these object accesses are skipped.

In either case, the outer invocation publishes its private result holder and returns `0` if execution reaches that point. It does not propagate the recursive status.

Two distinct consequences follow:

- A child that takes the explicit status-`7` failure branch publishes null into the private holder. Its parent skips transformation, publishes null, and returns `0`.
- A child with a null or unrecognized descriptor returns status `0` and null. Its parent therefore attempts object accesses based on a null address. No checked failure or successful completion is established for this case.

Recursion has no visible depth limit or cycle detection.

### Tag `~`

This path performs the following sequence:

1. Call F-57e7ed96facd with the context and retain the returned object address.
2. Read the unsigned 32-bit descriptor field at offset `24`.
3. Logically shift that value right by one, subtract `3` at 32-bit width, and interpret the resulting bit pattern as a signed 32-bit length.
4. Call F-fff796fade0e with:
   - The context.
   - The descriptor’s offset-`20` address-like value advanced by two bytes.
   - The signed length.
5. Call F-518be8877b82 with:
   - The retained object address.
   - The result of F-fff796fade0e.
   - The signed length divided by `2`, truncating toward zero.
   - Zero.
   - A value read from shared storage, whose type and width are unestablished.
6. Publish the retained object address and return `0`.

The offset-`24` read occurs after F-57e7ed96facd returns. The offset-`20` field is also obtained for the subsequent F-fff796fade0e call, after object acquisition. Neither field is guaranteed to retain its entry-time value if the preceding dependency can mutate aliased storage.

The shifted quantity ranges from `0` through `2147483647`. The signed length consequently ranges from `-3` through `2147483644`. Negative lengths are possible and are not clamped. Signed division yields `-1` for length `-3`, `-1` for length `-2`, and `0` for length `-1`.

There is no visible check for:

- A null object address.
- A zero result from F-fff796fade0e.
- A negative length.
- Invalid storage at the adjusted address.

This path contains no explicit status-`7` return. The two-byte adjustment does not establish that the resulting address is valid or that the referenced data has any particular encoding.

### Other tags

An unrecognized tag is not reported through a nonzero status.

## Acceptance examples

These are conditional static acceptance cases, not executed tests. Unless otherwise stated, they assume valid storage and normally returning dependencies.

1. **Null descriptor.** The output slot receives zero and the function returns `0`, without a direct dependency call.

2. **Unrecognized tag.** A descriptor beginning with `A` produces null and status `0`, without direct dependency calls.

3. **Mode selection.** Successful tag `|` or `}` construction with mode `98` passes `98` to F-5fba96760515 and `99` to F-b3a211f667d5. Tag `X` with mode `98` passes `98` to both.

4. **Zero intermediate.** If F-5fba96760515 returns zero, F-57e7ed96facd is still called. The context-byte write precedes both failure-position calls; null publication and status `7` follow.

5. **Null candidate.** A nonzero intermediate and null candidate take the same failure path. F-94cb53877c15 receives the nonzero intermediate, and F-c70de8d2b40e receives null.

6. **Recursive failure masking.** A `U` child that returns `7` through the explicit failure path leaves null in the parent’s private holder. The parent skips transformation, publishes null, and returns `0`.

7. **Recursive null-success hazard.** A `U` descriptor with a null nested descriptor causes the child to return `0` and null. The parent attempts null-based object accesses rather than checking for this condition.

8. **Word transformation.** Original low and high words of `1` and `0` become `0xffffffff` and `0xffffffff`. Original words of `0` and `1` become `0` and `0xffffffff`. Bit `31` at offset `12` toggles in either case.

9. **Small encoded lengths.** On tag `~`, an offset-`24` value of `0` produces length `-3` and halved length `-1`. A value of `4` produces length `-1` and halved length `0`. A value of `6` produces zero for both lengths.

10. **Discarded low bit.** Offset-`24` values `6` and `7` produce the same shifted quantity and length, provided preceding dependencies do not change the field.

11. **Shared-state timing.** If preceding dependencies change the shared storage used by a later call, no entry-time preservation guarantee applies. Acceptance must not require a 32-bit shared argument: its width is unestablished.
