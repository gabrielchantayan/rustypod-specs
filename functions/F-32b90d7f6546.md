# F-32b90d7f6546

## Purpose

F-32b90d7f6546 selects a sequence of external operations for a caller-supplied input and result region. It initializes a two-byte result field, reads a one-byte input mode, and dispatches among three paths:

- Zero mode with a nonzero selection result: invoke a payload-oriented dependency, then replace the initial result field using an auxiliary byte read after that invocation.
- Zero mode with a zero selection result: invoke a destination/source-like dependency once.
- Nonzero mode: invoke the destination/source-like dependency twice, first with a fixed program constant and then with the input.

Null input or result references produce an immediate error return. Other explicit return paths produce zero, irrespective of the unchecked outcomes of the output-producing dependencies.

Path construction, prefix insertion, and alternate representation selection are plausible intent. The visible behavior establishes call arguments and ordering, not those dependencies’ transformations or output formats.

## Behavior

### Reference validation

Before writing the result or reading the mode byte, the function checks the result reference and input reference against zero.

If either is zero, it returns 0xFFFFFFCE without:

- Writing the result field.
- Reading input offset 36.
- Calling a dependency.
- Exposing auxiliary storage to a dependency.

This is a null check only. Nonzero invalid addresses are not rejected by any visible validation.

### Initialization and mode selection

After null validation succeeds, the function performs these actions in order:

1. Writes a two-byte zero at the original result base.
2. Initializes the 32-bit auxiliary storage from the fourth argument.
3. Reads one byte at input offset 36.
4. Selects the zero-mode or nonzero-mode path according to whether that byte is zero.

Only zero versus nonzero matters. No nonzero mode value receives separate treatment.

The initial result store precedes the mode read. If the result field overlaps input offset 36, branch selection therefore observes the mode byte after that store. For example, when the mode address is one of the two cleared bytes, the observed mode is zero, assuming those accesses are otherwise valid.

The function does not reread the mode after dependency calls. Subsequent changes to the input do not cause it to reconsider the already selected path, although dependencies receiving the input may observe changed contents.

### Zero-mode selection

For zero mode, the function invokes **F-d9dea262321d** with:

1. The original input reference.
2. The address of the 32-bit auxiliary storage.

Its return value is used only as a zero/nonzero discriminator. Any nonzero result, including a negative result, selects the same branch. No selection result is returned directly to the caller.

#### Nonzero selection result

When F-d9dea262321d returns nonzero:

1. The function invokes **F-0e73fdbe5e28** with:
   - Original result base plus 2 bytes.
   - Original input reference.
   - The numeric value 0x100, equal to 256.
2. After that dependency returns, the function reads the current auxiliary value.
3. It converts that value through a plain-character type, then to a two-byte integer, and stores the converted value at the original result base.
4. It returns zero.

The auxiliary read and final two-byte store occur after F-0e73fdbe5e28 returns. They are not performed between the two dependency calls.

Accordingly, a value written by F-d9dea262321d is insufficient by itself to predict the final explicit store. Such a prediction also requires the relevant auxiliary value to remain unchanged until the later read. F-0e73fdbe5e28 is not directly passed the auxiliary address, but that does not prove it cannot affect the storage: the earlier dependency received that address, and pointer retention, shared state, callbacks, and other indirect effects are unresolved.

Under the represented eight-bit character conversion, the low-order byte determines the value being narrowed. Values through 0x7F do not present a signedness ambiguity. For values 0x80 through 0xFF, signed versus unsigned plain-character interpretation affects the resulting two-byte value. The target’s exact conversion properties are not independently established.

No F-e7c5183babcf invocation occurs on this branch.

The initial zero field is not guaranteed to remain zero until the final store: dependencies may modify it through mechanisms outside the wrapper’s explicit operations. After F-0e73fdbe5e28 returns, the wrapper explicitly overwrites that field with the converted auxiliary value.

#### Zero selection result

When F-d9dea262321d returns zero:

1. The function invokes **F-e7c5183babcf** with original result base plus 2 bytes and the original input reference.
2. It returns zero.

F-0e73fdbe5e28 is not invoked. The wrapper does not subsequently read the auxiliary value or explicitly replace the initial two-byte zero.

The absence of another wrapper store does not guarantee that the field remains zero. Either dependency may have effects that are not established by this body.

### Nonzero-mode processing

For any nonzero mode byte:

1. The function invokes **F-e7c5183babcf** with original result base plus 2 bytes and a fixed program-supplied source address.
2. After that invocation returns, it selects original result base plus 21 bytes as the next destination.
3. It invokes **F-e7c5183babcf** with that destination and the original input reference.
4. It returns zero.

Neither F-d9dea262321d nor F-0e73fdbe5e28 is invoked.

The second destination is fixed. It does not depend on the first dependency’s return value, output length, or terminator position. The first invocation’s result is not used to decide whether the second invocation occurs.

The spacing of the destinations does not prove that the first output occupies 19 bytes, ends before offset 21, or leaves the second destination untouched.

The established address displacements are:

- Input mode: **36 bytes**.
- Initial payload destination: **2 bytes**.
- Nonzero-mode continuation destination: **21 bytes**.

The two-byte pointer increment used for the initial payload destination accounts for the displacement of 2. The continuation displacement is a separate byte-address calculation.

No address-range or overflow check is visible. The supplied representation uses 32-bit address-bearing values; safe behavior at address-space boundaries cannot be inferred. Mathematical offsets in this contract describe intended destinations only where the address calculations and resulting accesses are valid.

The ordering above applies to the wrapper’s explicit accesses and calls. It does not specify the dependencies’ internal access ordering or establish that they preserve memory or global state.

## Acceptance examples

These are **conditional static acceptance criteria**, not executed tests. Except where stated otherwise, they assume valid memory, valid address calculations, and normally returning dependencies.

1. **Null input.** With input zero and result nonzero, the return is 0xFFFFFFCE. The wrapper performs no result store, mode read, or dependency invocation.

2. **Null result.** With result zero, the return is 0xFFFFFFCE regardless of the remaining arguments. The wrapper does not read input offset 36.

3. **Nonzero selection with a stable final auxiliary byte.** Suppose the observed mode is zero, and F-d9dea262321d returns 7 after writing auxiliary value 0x1234007F. The next invocation is F-0e73fdbe5e28 with result plus 2, original input, and 256. **If the auxiliary low byte is still 0x7F when the wrapper reads it after that invocation returns**, the wrapper’s final explicit two-byte store writes 127. The wrapper then returns zero.

4. **Auxiliary modification during the intervening call.** Suppose F-d9dea262321d returns nonzero with auxiliary low byte 0x7F, but the low byte becomes 0x02 before the post-F-0e73fdbe5e28 read. If it is 0x02 at that read, the final explicit field store writes 2, not 127. This criterion does not assert that a dependency actually performs such a modification; it prevents treating an earlier value as immutable.

5. **Negative selection result.** A selection result of −1 takes the same branch as 7. It is not propagated as an error return.

6. **Zero-mode fallback.** When F-d9dea262321d returns zero, the next invocation is F-e7c5183babcf with result plus 2 and original input. There is no F-0e73fdbe5e28 invocation and no later explicit result-field store. Dependency writes remain outside this guarantee.

7. **Nonzero modes are equivalent for dispatch.** Mode bytes 1 and 255 both select two F-e7c5183babcf invocations: first at result plus 2 with the fixed source, then at result plus 21 with original input. No measured output length changes the second destination.

8. **Character-conversion boundary.** If the low byte at the final auxiliary read is 0xFF, a signed eight-bit plain-character interpretation yields −1 before the two-byte store; an unsigned interpretation yields 255. Acceptance must resolve the target conversion properties before requiring either value or its byte layout.

9. **Overlapping mode field.** If input offset 36 coincides with either byte cleared by the initial result store, the mode read observes zero. Dispatch expectations based solely on the pre-call mode byte are invalid.
