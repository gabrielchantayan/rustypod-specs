# F-5126e2cd0d6c

## Purpose

F-5126e2cd0d6c classifies a caller-supplied memory record into one of four numeric results.

Its established behavior is:

- Return **1** when the record’s initial 32-bit field is zero.
- Otherwise, invoke **F-15c3cd3220f6** using that field and a 16-bit field at byte offset 26.
- Return **2** when the dependency returns zero.
- When the dependency returns nonzero, inspect the low eight bits of a 32-bit field at byte offset 24. Return **3** if those bits are zero, or **4** otherwise.

These numbers are observable results, not established application-level meanings. The supplied evidence does not identify them as success codes, error codes, enumeration members, or ownership states.

The function is therefore specified as a conditional classifier. Any interpretation of the record as an object, handle, request, or resource remains inferred intent rather than established behavior.

## Interface

### Input

The function receives one pointer to a memory record. No length, version, discriminator, or independent validity indicator accompanies it.

The following layout describes the accesses under the recovered 32-bit integer model:

| Byte offset | Width | Interpretation |
|---|---:|---|
| 0–3 | 32 bits | Initially compared with zero; if nonzero, read again for the dependency’s first argument. |
| 24–27 | 32 bits | Read after a nonzero dependency result; its low eight value bits select result 3 or 4. |
| 26–27 | 16 bits | Supplied as the dependency’s second argument. |

Offsets are measured from the supplied pointer. Bytes not listed have no direct access established by this function.

The 16-bit field overlaps the final two bytes of the 32-bit field at offset 24. These are not established as independent storage locations.

### Output

The function returns a 32-bit result whose established values are exactly **1**, **2**, **3**, and **4**, provided all required accesses and the dependency invocation complete normally.

It has no separate output parameter. It does not directly write to the record.

### Preconditions

The pointer must permit the initial 32-bit read at offset 0. There is no explicit null-pointer check or other pointer validation before that read.

Additional access requirements depend on the executed path:

- If the initial field is zero, the function establishes no need to access the later fields.
- If the initial field is nonzero, the field at offset 0 must remain readable for the second read, and the 16-bit field at offset 26 must be readable while preparing the dependency call.
- If the dependency returns nonzero, the 32-bit field at offset 24 must be readable after the dependency returns.

A contiguous readable extent of 28 bytes covers all directly accessed fields in the recovered layout, but is not required by the zero-field path itself. Alignment, access permissions, object lifetime, and target-specific requirements still apply.

The dependency may impose additional requirements on its argument values or on memory reachable through them. Those requirements are unknown.

## Behavior

### Initial decision

The function first reads the 32-bit field at offset 0 and compares it with zero.

If that value is zero, it returns **1** immediately. On this path:

- F-15c3cd3220f6 is not invoked.
- The field at offset 26 is not read.
- The field at offset 24 is not read.
- No direct record write occurs.

This branch concerns the contents of the record, not whether the supplied pointer itself is null.

### Dependency invocation

If the initial comparison observes a nonzero value, the function prepares one call to F-15c3cd3220f6.

The arguments are:

1. A new read of the 32-bit field at offset 0.
2. A 16-bit read at byte offset 26.

The first argument is therefore not explicitly a saved copy of the value used by the initial comparison. Under stable memory, the two reads have the same value. If the memory can change between them, the first comparison and the dependency argument can differ; the supplied evidence establishes neither synchronization nor a stable snapshot.

The relative evaluation order of the two argument reads is not established. Both supply the call, but a contract must not require the offset-0 argument read to occur before the offset-26 argument read, or vice versa.

The 16-bit argument is read at that width. Its exact signedness and any extension to the dependency’s calling-convention width are not established by the supplied evidence.

### Dependency result

The dependency result is tested for equality with zero.

- A zero result causes the function to return **2**.
- Any nonzero result proceeds to the final record inspection.

The function does not distinguish among different nonzero dependency results. It does not propagate the dependency’s numeric result.

When the dependency returns zero, the function performs no subsequent direct read of the 32-bit field at offset 24.

### Final decision

After a nonzero dependency result, the function reads the 32-bit field at byte offset 24 and reduces its value to eight bits for a zero comparison.

- If the low eight value bits are zero, the function returns **3**.
- If those bits are nonzero, the function returns **4**.

The remaining 24 value bits do not affect this final choice. In particular, a nonzero 32-bit field can still produce result 3 when its low eight bits are zero.

This is a value-based low-byte test following a 32-bit field access. It must not be specified unconditionally as an independent byte read at physical offset 24:

- Under little-endian layout, the low eight value bits reside at byte offset 24.
- Under big-endian layout, they reside at byte offset 27.

The dependency completes before this field is inspected. If the dependency changes the field through an alias, the function uses the post-call contents. No pre-call copy of this field is established.

### Access ordering and arithmetic

The established source-level sequence is:

1. Initial offset-0 read and zero decision.
2. On the nonzero path, argument reads and one dependency invocation.
3. Dependency-result decision.
4. On a nonzero dependency result, the offset-24 field read and final decision.

This describes source-level dependencies, not a verified machine-level memory-access trace. Compiler load combining, instruction widths, volatile behavior, and hardware ordering have not been established.

There is no arithmetic on the record’s field values beyond comparisons and narrowing. The pointer arithmetic selects fixed offsets; the function does not compute a length or validate that the selected addresses lie within an allocated object.
