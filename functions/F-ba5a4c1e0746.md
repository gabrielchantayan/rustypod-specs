# F-ba5a4c1e0746

## Purpose

F-ba5a4c1e0746 performs a fixed sequence of writes to caller-supplied storage, invokes F-b7ada62a0646 with that storage, and, if the dependency returns normally, writes a supplied byte and returns the original storage pointer.

The established behavior is initialization-like, but the source does not establish an object type, field meanings, allocation policy, or lifetime protocol. In particular, the dependency call occurs between two writes to the same byte. The dependency therefore receives storage with that byte initially zero; the caller-supplied byte is applied only after the dependency returns.

This contract describes direct behavior visible in the supplied static evidence. It does not treat any initially written value as a guaranteed final value when the dependency could have changed it.

## Behavior

### Initialization before the dependency

The function first obtains a 32-bit value from a fixed global storage location and stores it at destination offset 0. The global’s numeric value, meaning, mutability, and initialization requirements are not established.

The function then makes the following writes in order:

1. A 32-bit zero at offset 4.
2. The supplied 32-bit word at offset 8.
3. A 32-bit zero at offset 12.
4. A 32-bit zero at offset 16.
5. An 8-bit zero at offset 20.

The offset-20 write affects one byte, not a full 32-bit slot. The direct initialization does not clear offsets 21–23 or any later bytes. It is therefore not equivalent to clearing a rounded-up 24-byte region.

The word input is stored as a 32-bit value without visible arithmetic, masking, range checking, or interpretation. Its signedness and semantic meaning are not established. All 32 input bits participate in the store.

The byte input does not determine the initial offset-20 value. That byte is zero immediately before the dependency call, regardless of the supplied byte value, assuming ordinary valid storage without external interference.

### Dependency invocation

After completing all six initial writes, the function invokes F-b7ada62a0646 once, passing the original destination pointer.

At this call boundary, the direct writes have established the layout above. This is a call-entry condition, not a promise about what the dependency will observe after beginning its own execution: the dependency’s reads, writes, and interactions with other state are unknown.

The function neither checks nor uses a result from F-b7ada62a0646. No result-dependent branch is visible.

The dependency may modify destination contents or other state. The supplied evidence provides no preservation guarantee for the first five 32-bit fields, the byte at offset 20, surrounding storage, or globals.

### Final byte write and return

If F-b7ada62a0646 returns normally, the function writes the supplied 8-bit byte at destination offset 20. This write takes place even if the supplied byte is zero or the dependency already placed that same value there.

The function then returns the original destination pointer.

There is no second initialization pass. In particular:

- Offset 0 is not restored from the global after the call.
- Offset 8 is not restored to the supplied word after the call.
- The zeroed 32-bit fields are not cleared again.
- Offset 20 is the only location directly written after the call.

Consequently, the final destination contents combine any surviving initial writes, any dependency changes, and the final supplied byte. A stronger final-state guarantee requires a separate contract for the dependency.

### Widths and access ordering

The directly established order is the global read and first destination write, the remaining initial writes, the dependency call, the final byte write, and the return. This is a behavioral ordering from the supplied representation, not a claim about individual processor instructions, atomicity, or synchronization.

The direct address calculations use fixed byte offsets through 20. There is no visible size-dependent multiplication, counter, loop, or arithmetic on either supplied value. The source does not establish the target’s byte order, so the byte-by-byte representation of the 32-bit fields remains unspecified here.

It does not visibly allocate storage, release storage, retain the pointer elsewhere, perform I/O, or write a global directly. Those observations do not constrain effects performed by F-b7ada62a0646.
