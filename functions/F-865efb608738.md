# F-865efb608738

## Purpose

F-865efb608738 consumes bytes in descending address order, assembles them into unsigned 32-bit words, stores those words in an externally supplied backing area, and updates a 16-bit logical word count.

For a conventional, non-overlapping input with a byte count between 1 and 65,535, the observed transformation is consistent with importing a big-endian unsigned integer into an array of least-significant-word-first 32-bit limbs. High zero words are excluded from the reported logical length. This interpretation is **inferred intent**, not a separately established format declaration.

The established behavior is more specific, and less general, than an unrestricted byte-array import:

- The byte-count argument is 32 bits, but the running count is reduced to 16 bits after each consumed byte.
- The initially reported word count is calculated from the original 32-bit argument, not from the number of bytes actually consumed.
- The backing-area address is loaded repeatedly from the destination descriptor.
- Normalization can read words that this invocation did not write, including a word before the backing area when the initially reported length is zero.

These distinctions are part of the contract and must not be replaced by a conventional arbitrary-length import algorithm.

2. **Destination descriptor address.** An address presented as a pointer to 16-bit units. The function directly uses:
   - Bytes 0–1: a writable 16-bit logical word count.
   - Bytes 4–7: a stored backing-area address, loaded as a 32-bit value.
   
   No direct access to descriptor bytes 2–3 is shown.
3. **Byte-count argument.** An unsigned 32-bit value.

The descriptor is not simply a pointer to the output word array. Its backing-area address is fetched from the field at byte offset 4.

## Behavior

### 1. Zero byte-count argument

If the original byte-count argument is zero, the function writes zero to the descriptor’s 16-bit logical count and returns.

On this path:

- It does not read the source.
- It does not load the backing-area address.
- It does not read or write backing words.
- It does not clear any existing backing contents.

The destination count field must nevertheless be writable.

### 2. Nonzero initialization

For a nonzero argument \(N\), the function retains a 32-bit unsigned addition result:

\[
A = (N + 3) \bmod 2^{32}.
\]

The first source byte is addressed relative to the original argument:

\[
\text{source address} + N - 1.
\]

It initializes the output-word index to zero.

The starting address uses the original 32-bit count. It is not adjusted to reflect the later 16-bit reduction of the running count. Behavior when this address calculation overflows the valid address space is not established.

### 3. Reverse byte consumption and word assembly

The function builds one output word at a time. Each word begins numerically at zero.

For each byte in a word, the observable sequence is:

1. Update the running remaining count by subtracting one and retaining only its low 16 bits.
2. Calculate the next lower source-byte address.
3. Read the current source byte.
4. OR that byte into the accumulating word at the current byte position.

The first byte read for a word occupies bits 0–7. The next occupies bits 8–15, then bits 16–23, then bits 24–31. Thus bytes are consumed from higher to lower source addresses while being placed from lower to higher significance inside each word.

A word finishes after either:

- The updated remaining count becomes zero; or
- Four bytes have been consumed for that word.

Any unfilled high bits of the final partial word remain zero.

The position increment includes a mask that clears bit 16. Because a word contains at most four bytes, this mask does not alter reachable byte positions.

### 4. Actual number of source bytes read

For nonzero \(N\), the number of consumed bytes is:

\[
E = ((N - 1) \mathbin{\&} 65535) + 1.
\]

Consequently, \(E\) ranges from 1 through 65,536.

The visited source addresses descend from:

\[
\text{source address} + N - 1
\]

through:

\[
\text{source address} + N - E.
\]

In particular:

- For \(1 \leq N \leq 65{,}535\), exactly \(N\) bytes are consumed.
- For \(N = 65{,}536\), exactly 65,536 bytes are consumed.
- For \(N = 65{,}537\), only one byte is consumed, at source offset 65,536.

This behavior is established by the masked running-count update. A requirement that callers restrict the count to a narrower range is not explicitly supplied.

### 5. Output-word stores

After assembling each word, the function:

1. Loads the backing-area address from descriptor byte offset 4.
2. Stores the assembled 32-bit word at that address plus four times the current output-word index.
3. Advances the output-word index.

The index increment clears bit 16. At most 16,384 words are produced by one invocation, so that mask does not change the indices actually reached.

The number of word stores is:

\[
W = \left\lceil \frac{E}{4} \right\rceil.
\]

For stable, non-overlapping storage, output word zero contains the least-significant group of up to four input bytes; subsequent words contain successively more significant groups.

The backing address is not captured once for the entire operation. If an earlier store modifies the descriptor’s backing-address field, a later word store uses the subsequently loaded value.

### 6. Initial logical-count publication

Only after all source bytes have been consumed and all output words stored does the function write the initial logical count:

\[
Q = \left(\left\lfloor \frac{A}{4} \right\rfloor\right) \bmod 2^{16}.
\]

This is a 16-bit store to descriptor bytes 0–1.

For counts from 1 through 65,536, \(Q\) equals the number of words written. For larger arguments, that equality is not guaranteed.

Both arithmetic details matter:

- The addition of three wraps at 32 bits.
- The shifted result is narrowed to 16 bits.

### 7. Zero-word normalization

After publishing the initial logical count, the function reads that 16-bit count and forms a signed index one less than it.

It then:

1. Loads the backing-area address.
2. Reads the 32-bit word at the calculated index.
3. Returns immediately if that word is nonzero.

If the first inspected word is zero, the function walks toward lower indices:

- It decrements the index.
- It stops without reading a word if the index is negative.
- Otherwise it reloads the backing-area address and reads the word at that index.
- It continues while the inspected word is zero.

It finally writes the index plus one to the 16-bit logical-count field.

For a stable backing area and a valid positive initial count, this leaves the count equal to one plus the highest nonzero word index, or zero if all inspected words are zero.

Normalization does not erase zero words. It changes only the logical count.

### 8. Initially zero logical count

The initial normalization read occurs before any negative-index check.

If \(Q=0\), the first inspected index is −1. The function therefore attempts to read the 32-bit word immediately before the backing address.

Conditional on that read being valid:

- If the word is nonzero, the function returns with the logical count already zero.
- If the word is zero, the index is decremented again, the negative-index check stops the scan, and the final 16-bit count becomes 65,535.

This behavior must not be silently replaced with an empty-result fast path.

## Side effects

### Direct memory effects

The function directly performs:

- Source-byte reads in descending address order.
- One backing-address-field read per output-word store.
- Output-word stores in increasing logical index order.
- A 16-bit count store after all output-word stores.
- A count-field read for normalization.
- Repeated backing-address-field and backing-word reads during normalization.
- A final 16-bit count store only when the first normalization word was zero.

The zero-input path performs only its count-field store.

### Aliasing

No overlap check or temporary copy is present.

If backing stores overlap source bytes not yet consumed, later source reads observe memory after those stores. If backing stores overlap the descriptor, they may change its count or backing-address field. The subsequent explicit count publication and repeated backing-address loads retain their described ordering.

Therefore the simple mathematical import interpretation requires stable, non-overlapping storage. It is not a general guarantee for aliased inputs.

- The zero second word remains in memory.
