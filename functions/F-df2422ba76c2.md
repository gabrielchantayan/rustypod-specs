# F-df2422ba76c2

## Purpose

F-df2422ba76c2 obtains an object, installs a metadata word and two byte-sized attributes, selects a 32-bit resource value, and conditionally performs shared-resource initialization.

The supplied representation establishes three selection paths, distinguished by the full-width third argument:

- Zero selects a value obtained from a global context.
- One selects a value from a shared slot.
- Every other value requests a value through F-431c272cd5ee and then passes that value to F-7c96094455b3 with the constant 5.

A later initialization condition is different: it combines the current contents of a captured shared slot with the object’s stored, truncated mode byte. Consequently, full-width selection and byte-width initialization need not classify an argument identically.

The apparent intent is to create an object associated with either a context resource, a shared resource, or a separately obtained resource. Resource types, ownership, and the meaning of the configuration calls are not established.

## Interface

### Arguments

| Position | Established representation | Use |
|---|---|---|
| First | 32-bit value | Not explicitly inspected, stored, or forwarded by the supplied body. |
| Second | 32-bit value | Its low eight bits are stored in the object. Its full 32-bit value is also forwarded to F-28d89f4ecafe if shared initialization occurs. |
| Third | 32-bit integer | Compared at full width against zero and one. Its low eight bits are stored as the object’s mode byte. |

The third argument’s signedness does not affect equality with zero or one. Values other than those exact 32-bit values take the third selection path, even when their low byte is zero or one.

### Return value

The function returns the object pointer obtained from F-a9abdf3a1b30.

No explicit failure return, null check, or alternate return path appears. A successful return does not independently establish that the stored resource is nonzero, valid, retained, or owned.

### Object fields

The following offsets are byte offsets from the returned object pointer:

| Offset | Width | Explicit use |
|---|---|---|
| 0x00 | 32 bits | Receives a global metadata word. |
| 0x40 | 32 bits | Receives the selected resource value. May be replaced during shared initialization. |
| 0x44 | 8 bits | Receives the low eight bits of the second argument. |
| 0x45 | 8 bits | Receives the low eight bits of the third argument; later consulted for initialization decisions. |

The supplied body does not explicitly initialize other object bytes. It requires an object region accessible through byte offset 0x45, but does not establish an allocation size or the initial contents of that region.

### Referenced state

For this contract:

- **Metadata source** means the global 32-bit value copied to object offset 0x00.
- **Context root** means the pointer obtained from a global location and then dereferenced to read a 32-bit value at offset 0x30.
- **Context value** means that captured 32-bit value.
- **Shared-slot reference** means the global pointer identifying a 32-bit shared slot.
- **Captured shared slot** means the slot addressed by the shared-slot reference captured early in this invocation.

These names describe observed access roles, not ownership or semantic types.

## Behavior

### Initial acquisition and ordered access

The explicit access and call sequence begins as follows:

1. Call F-a9abdf3a1b30 without explicit arguments and retain its returned pointer.
2. Read the metadata source and write that 32-bit value at object offset 0x00.
3. Write the low eight bits of the third argument at object offset 0x45.
4. Capture the shared-slot reference.
5. Read the context root and capture the 32-bit value at its offset 0x30.
6. Write the low eight bits of the second argument at object offset 0x44.
7. Select and store the resource using the full-width third argument.

The context value is read on every path, including the path that selects the shared slot. It is not fetched lazily only when needed.

The metadata source, shared-slot reference, and context root are obtained after F-a9abdf3a1b30 returns. The body therefore uses state visible after that dependency’s execution, not necessarily state from function entry.

### Resource selection

**Third argument equals zero**

The captured context value is written at object offset 0x40. There is no selection-path dependency call.

**Third argument equals one**

The current 32-bit contents of the captured shared slot are read and written at object offset 0x40. Zero is stored if the slot contains zero; no early validation or rejection occurs.

**Third argument has any other value**

A temporary 32-bit output word is first set to zero. F-431c272cd5ee receives the captured context value and the address of that word.

After the call:

- The temporary word is read and copied to object offset 0x40.
- Its value is supplied to F-7c96094455b3 with the 32-bit constant 5.

The object field is written before F-7c96094455b3 is called. The supplied body does not inspect a return status from either dependency.

Initialization of the temporary word to zero is established. It does not establish that zero represents failure or success, or that F-431c272cd5ee must replace it.

### Shared-initialization decision

After resource selection and any associated dependency calls, the function reads the captured shared slot again.

- If that read is nonzero, shared initialization is skipped. The object mode byte is not read for this condition.
- If that read is zero, the function reads the object byte at offset 0x45 as an unsigned eight-bit value.
- Shared initialization occurs only when that byte equals one.

This decision uses neither a fresh read of the global shared-slot reference nor the full-width third argument. Calls in the preceding selection path may have changed the shared slot, the global reference, or reachable object state; no preservation guarantee is supplied.

### Shared-initialization sequence

When the condition is satisfied, the function performs the following ordered operations:

1. Call F-431c272cd5ee with the captured context value and the **currently read global shared-slot reference** as the destination.
2. Call F-28d89f4ecafe with:
   - the address of a temporary workspace;
   - the full 32-bit second argument;
   - a fresh read of the captured shared slot.
3. Supply a temporary working value to F-cace740d16db, with the second argument zero.
4. Supply that working value to F-7c96094455b3, with the second argument 5.
5. Supply that working value to F-c3dfbb5b6dce.
6. Supply that working value to F-696840965473.
7. Supply that working value to F-ff98b8a60faa.
8. Read the object mode byte again. If it is still one, read the captured shared slot again and replace the 32-bit field at object offset 0x40.
9. Call F-ccf4fcd3c34d with the temporary workspace address.
10. Return the originally obtained object pointer.

The temporary working value is represented as a 32-bit word immediately following a 64-byte temporary workspace. Its initialization is not explicit in this function. F-28d89f4ecafe precedes its first use and receives the workspace address, but the supplied body alone does not prove that dependency’s output layout.

Each working-value argument is obtained from the temporary word at its respective call site. The contract does not assume that the word remains unchanged across calls, particularly if a dependency retains or can otherwise reach the workspace.

### Captured slot versus current destination

The destination passed to F-431c272cd5ee during shared initialization comes from a new read of the global shared-slot reference. Subsequent slot reads still use the earlier captured reference.

These addresses can therefore differ if an intervening dependency changes the global reference. The body neither checks their equality nor switches all later accesses to the newer destination.

### Final resource refresh

The resource refresh occurs before F-ccf4fcd3c34d. It is conditional on the mode byte at that later moment, not merely on having entered shared initialization.

If an intervening dependency changes the mode byte away from one, the refresh is skipped. If the byte remains one, the captured slot’s then-current value is copied without a nonzero check.

There is no further explicit resource-field update after workspace finalization.

## Side effects

### Explicit writes

The function explicitly writes:

- The four object fields described above.
- A zero to the temporary output word used for the nonzero, non-one selection path.

Dependencies receive addresses capable of supporting additional writes:

- F-431c272cd5ee receives either the temporary output address or the current shared-slot destination.
- F-28d89f4ecafe and F-ccf4fcd3c34d receive the workspace address.

Their complete write sets are unknown. No dependency is assumed to preserve globals, object fields, temporary storage, or other reachable state.

### Ownership and lifetime

The body returns the pointer supplied by F-a9abdf3a1b30 and does not explicitly pass that pointer to a release operation. This does not establish allocation ownership or transfer rules.

Likewise:

- Copying a resource word does not establish retention.
- Obtaining a resource through F-431c272cd5ee does not establish ownership.
- The five working-value calls cannot be classified as retain, configure, release, or destroy operations from this body alone.
- F-ccf4fcd3c34d cannot be assumed to free memory or release resources merely because it is last in the workspace sequence.

The workspace and output word are temporary storage associated with this invocation. Whether dependencies retain their addresses, and whether such retention is valid, remains undocumented.

### Errors and preconditions

There is no explicit validation of:

- The pointer returned by F-a9abdf3a1b30.
- The context root or its offset-0x30 access.
- Either captured or subsequently read shared-slot destinations.
- Resource values passed to dependencies.
- Dependency outcomes.

Safe normal execution requires valid accesses and dependency-compatible arguments throughout the executed path. A null or invalid pointer is not converted into a documented error result by this body.

No explicit retry, rollback, exception handling, synchronization, or partial-initialization recovery is shown. If a dependency does not return normally, completion of later writes and calls is not established.

The body does not assert that object storage, globals, shared slots, and dependency-visible storage are disjoint. Aliasing can affect later reads. No atomicity or concurrent-use guarantee is established.

## Acceptance examples

These are conditional acceptance scenarios, not executed tests. Unless stated otherwise, assume valid non-overlapping storage, normally returning dependencies, and no dependency mutations beyond the outputs named.

### Context selection

Given a third argument of zero and a context value of 0x11223344:

- The resource field receives 0x11223344.
- The mode byte receives zero.
- The captured shared slot is read for the common decision.
- Shared initialization does not occur, whether that slot is zero or nonzero.

### Existing shared resource

Given a third argument of one and a captured shared slot containing 0x55667788:

- The resource field receives 0x55667788.
- A subsequent shared-slot read is nonzero.
- No workspace initialization or working-value sequence occurs.

### Empty shared resource

Given a third argument of one and an initially zero captured shared slot:

- The resource field is first written with zero.
- Shared initialization is entered.
- If the shared-output dependency writes 0x10203040 into the same captured slot, F-28d89f4ecafe receives that value as its third argument.
- If the mode byte remains one, the resource field is later replaced with the captured slot’s current value.
- Workspace finalization follows that replacement.

### Truncation does not control initial selection

Given a third argument of 257:

- The stored mode byte is one.
- Initial selection takes the “other value” path, not the exact-one path.
- If the captured shared slot is zero at the later decision and the mode byte remains one, shared initialization also occurs.

Thus both the separate-resource sequence and shared-initialization sequence may execute in one invocation.

Given a third argument of 256, the initial selection still takes the “other value” path, but the stored mode byte is zero. Without subsequent mutation, that byte prevents shared initialization.

### Full-width second argument

Given a second argument of 0x123456AB:

- Object offset 0x44 receives 0xAB.
- If shared initialization occurs, F-28d89f4ecafe receives 0x123456AB, not merely 0xAB.

### Shared-reference replacement

Suppose the captured shared-slot reference identifies slot A. Before shared initialization, a dependency changes the global reference to slot B.

If slot A is zero and the mode byte is one:

- The shared-output call receives slot B’s address.
- The workspace argument and final resource refresh still read slot A.
- A value written only to slot B is not automatically selected from slot B.

### Mode mutation during initialization

If shared initialization begins with mode byte one, but a working-value dependency changes it to another byte:

- Remaining unconditional working-value calls still occur.
- The final resource refresh is skipped.
- F-ccf4fcd3c34d still runs if execution reaches it normally.
