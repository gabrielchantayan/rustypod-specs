# F-a045bb361346

## Purpose

F-a045bb361346 alternates between publishing a three-word record and processing a word obtained through an evolving traversal pointer. Both publication branches lead into processing, subject to completion of all intervening operations. Processing either repeats directly or returns to publication.

No ordinary return, explicit error result, or recovery handler is represented. This does not establish indefinite successful execution: a dependency may not return, an address may be inaccessible, arithmetic may lack a defined interpretation, or a software breakpoint may prevent continuation.

“Publication,” “record,” “payload,” and “traversal” describe observable roles. They do not establish an application protocol, device operation, or formal data structure.

This contract describes conditional consequences of the supplied static representation. Undeclared entry state and execution-model-dependent operations prevent an unconditional portable execution contract.

### Publication preparation and capture

At publication entry, working state shifted left by two produces the retained unsigned 32-bit **publication word**. This value remains distinct from the working state installed later during publication.

The low eight bits of carried state are written to the global **control location**. A fixed publication call anchor is established, followed by a separate one-byte read of the control location. The read produces the **captured byte**.

The captured byte equals the written byte only if the location’s storage and access semantics make the read observe that write.

The first call target is formed by adding `0xAE` to current signed 32-bit dispatch state, then converting the sum to a callable pointer. On initial entry, dispatch state is uninitialized within the function. A value exceeding the signed range after this addition therefore prevents a portable interpretation even before target conversion.

F-000000000001 receives the traversal-pointer address converted to unsigned 32 bits and shifted right by two.

After that call, dispatch state is set to the signed 32-bit publication continuation value `0x0897EE1D`. F-000000000002 is then called through the publication anchor plus its byte displacement.

### Publication memory effects

Two pointers are derived from F-000000000002’s result:

- The **publication result pointer**, converted from the complete 64-bit result.
- The **retained high-half pointer**, converted from the unsigned high half.

The following stores occur before the record stores:

1. The captured byte is stored at an address formed by converting the publication result pointer to signed 32 bits and multiplying by two.
2. A byte derived from the result’s high half is stored one eight-byte element beyond the publication result pointer.
3. The current record-destination pointer is stored through an address formed by doubling the previous signed address state.
4. The complete 64-bit result is stored through the publication result pointer.

The second store has an eight-byte displacement from the converted pointer. Under conventional low-bit byte narrowing, its stored bits are the high half modulo 256.

Neither the second nor fourth destination is independently derived from the low half. They reduce to low-half-based addresses only under an appropriate pointer-conversion model.

The adjacent-byte store lies immediately beyond the represented eight-byte result region. Other stores may alias either region. The captured byte is retained across both dependency calls; no explicit recapture occurs.

Address state is next replaced by four times the record-destination address after conversion to signed 32 bits. Working state becomes the traversal-pointer address converted to signed 32 bits and shifted left by eight.

The record’s three fields are then written at offsets zero, four, and eight, in that order.

### Publication branch

Because the signed right shift uses the operand’s represented width, ordinary portable rules do not determine which traversal addresses select either branch.

**Zero branch quantity**

The control location is cleared first.

The newly established signed address state is added to the unsigned publication word. The signed operand is converted to unsigned 32 bits, and the addition is modulo \(2^{32}\). Assignment of the result back to signed address state is a separate conversion, unresolved when the result exceeds the signed range.

The resulting signed address-state value is stored as a 32-bit word through the retained high-half pointer.

Processing starts with argument zero and carried state equal to the publication word. Working state remains the traversal-derived value installed during publication. Dispatch state remains `0x0897EE1D`.

**Nonzero branch quantity**

The branch quantity is stored as a 32-bit word at the address formed by multiplying the publication word by 256 and adding 32. Both operations are unsigned 32-bit arithmetic.

Dispatch state becomes `0x08790D52`. The initial processing argument is the publication word multiplied by 256 using unsigned arithmetic, converted to signed 32 bits, then shifted right by 29.

F-000000000008 performs a software breakpoint with immediate four. The branch-quantity store and dispatch-state replacement have already occurred.

### Processing accesses

Each processing pass calls F-000000000003 with the current processing argument. Its target is formed by signed 32-bit dispatch state plus `0xA1E`, followed by callable-pointer conversion.

Its result participates in this access order:

1. A 16-bit value derived from the result is stored through a pointer converted from the complete 64-bit result.
2. Working state multiplied by 64 is stored as a 32-bit word at the address represented by that same unsigned product.
3. One unsigned 32-bit payload is read through the current traversal pointer.
4. A 16-bit value derived from the old traversal pointer is stored at working state plus four.
5. A pointer-typed value is read from the address obtained by converting the result’s high half to signed 32 bits and adding 80. This replaces the traversal pointer.

Under conventional narrowing, the first store writes the result’s low 16 bits. Its destination remains a conversion of the complete result, not unconditionally a low-half address.

For the fourth access, the old traversal pointer is narrowed to signed 16 bits, four is added after integer promotion, and the result is narrowed again for storage. Under conventional low-bit narrowing, the stored bits equal the old pointer address plus four modulo \(2^{16}\). Pointer conversion and out-of-range signed narrowing remain unresolved.

Working state plus four uses unsigned 32-bit arithmetic. The replacement-pointer source instead uses the separately described signed conversion and addition.

The replacement-pointer read follows all four preceding accesses. Earlier stores can therefore affect its result through aliasing.

### Processing continuation

A candidate at most 19 causes processing to repeat. The next processing argument becomes zero, and carried state becomes the retained payload. The replacement traversal pointer and new record destination remain current. Dispatch state is `0x0897EDF1`.

Under low-bit-retaining conversion and an execution model interpreting the multiplication modulo \(2^{32}\), every candidate is a multiple of 32. Under those assumptions, zero is the only candidate at most 19. This is not an unconditional property of the represented signed multiplication.

A zero candidate still requires the preceding 32-bit store to address zero. Repetition does not bypass that access.

2. The replacement traversal-pointer address, narrowed to 16 bits, is stored at working state plus 14.

The exiting pass does not assign its payload to carried state. Carried state retains the publication word or the payload from the most recent pass that repeated.

## Acceptance examples

These are conditional static deductions, not executed tests. Each assumes preceding operations complete under the stated interpretation.

1. **Separate control capture.** Carried state `0x123456AB` causes a byte write of `0xAB`. If the subsequent read yields `0x6D`, the captured-byte store uses `0x6D`, including after dependency calls.

2. **Initial dispatch overflow.** Entry dispatch state `0x7FFFFFFF` cannot be increased by `0xAE` within signed 32-bit range. Ordinary signed arithmetic therefore provides no defined initial target. Callable-pointer conversion does not repair the preceding overflow.

3. **Record fields.** Publication-entry working state three and traversal address `0x00001000` produce fields `0x0000000C`, `0x00100000`, and `0x00001000`, assuming the pointer conversions and signed shift support those values.

4. **Unsigned accumulation.** Address state `2147483644` plus publication word eight produces unsigned bits `0x80000004`. The addition itself does not overflow signed arithmetic because it is unsigned. Under bit-preserving conversion back to signed state, the value becomes `−2147483644`.

5. **Full-result destinations.** For publication result `0x0000000200001000`, a low-bit-retaining 32-bit pointer model places the eight-byte store at `0x1000` and adjacent-byte store at `0x1008`. A model preserving the complete address places them at `0x0000000200001000` and eight bytes beyond it. Neither model is selected here.

6. **Processing result narrowing.** For that same numeric result from F-000000000003, conventional low-bit narrowing produces initial stored bits `0x1000`. The destination is still the pointer conversion of the complete result.

7. **Retained-pointer transformation.** Suppose the publication result’s high half is `0x00100000`. If conversion to the retained pointer and then to signed 32 bits preserves that value, the post-breakpoint shift by 18 produces working state four. Without that conversion assumption, directly shifting the high-half integer is not an established substitute.

8. **Breakpoint boundary.** If a nonzero branch reaches the breakpoint and cannot continue, its branch-quantity store and alternate dispatch assignment have occurred. Its retained-pointer-based working-state replacement and subsequent processing have not.

9. **Retained payload.** Payload `0x40` supplies `0x40` to F-000000000006 and eight to F-000000000007, even if the original storage changes afterward.

10. **Exit and repeat candidates.** A F-000000000007 result equal to one produces candidate 32 without signed overflow. Storing 32 at address 32 precedes comparison and the exit stores. A zero candidate instead requires a successful store to address zero before repetition.

11. **Aliasing and carried state.** If the working-state-offset-four store overlaps the replacement-pointer source, the later pointer read accesses memory after that store. If the pass exits, its payload does not replace carried state.
