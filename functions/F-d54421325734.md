# F-d54421325734

## Purpose

F-d54421325734 extracts a requested field of 1 through 32 bits from byte-addressed storage and returns it as an unsigned 32-bit value. Earlier selected bits occupy more significant positions in the result.

F-5480c9185606 supplies zero-versus-nonzero decisions that can cause individual candidate bytes to be skipped. Each nonzero decision causes at most one byte to be skipped; replacement bytes are not immediately reclassified.

The function initializes a one-byte indicator to zero and writes one after specified nonzero dependency results. It does not directly advance the context’s stored bit position.

The operations support an interpretation as a bit-field reader with conditional byte skipping. They do not establish a particular data format, the dependency’s classification rule, or deterministic behavior across calls.

### Return value

The return value is unsigned and 32 bits wide.

A width below 1 or above 32 returns zero after initializing the indicator. Zero is also a valid extracted value, so the return value alone does not distinguish invalid width from successful extraction of zero-valued bits.

## Behavior

### Entry and width validation

The first explicit memory operation is a one-byte write of zero to the indicator.

The function then checks the requested width. A width outside 1 through 32 causes an immediate zero return. On this path, the function does not read the context, read source bytes, or call F-5480c9185606.

Consequently, an invalid-width call does not require a readable context, but it still requires a writable indicator.

For accepted widths, any effect of indicator initialization on aliased storage is visible to subsequent reads.

### Initial position

The function reads the context’s bit-position field and then its storage-base field.

The initial source address is formed from the storage base plus the signed bit position shifted right by three places. An arithmetic signed right shift gives the conventional interpretation for the represented target; exact target semantics remain relevant for negative values.

The intra-byte offset is the low three bits of the bit-position value. Bits are numbered from the most-significant side for extraction:

- Offset zero makes all eight bits available.
- Offset one leaves seven available bits.
- Offset seven leaves one available bit.

The computed traversal address and alignment are retained locally. Later changes to the context’s base or bit-position fields do not cause them to be recomputed.

### Initial classification at an aligned position

When the intra-byte offset is zero, F-5480c9185606 is called before the initial source-byte read. It receives:

1. The initial source address.
2. The context field at offset 8, read for this call.

A zero result leaves the initial address unchanged.

A nonzero result advances that address by exactly one byte and causes a one-byte write of one to the indicator. The replacement byte is not immediately submitted to another classification call.

When the start is unaligned, this initial dependency call is omitted. The byte containing the initial bit is therefore not classified on that path.

### Extraction contained in the initial byte

If the requested width fits within the available portion of the initial byte, the function reads that byte and extracts the requested bits.

The bits preceding the intra-byte offset are discarded. The requested bits immediately following them become the low-order result bits.

For example, offset three and width four select the four bits after the byte’s three highest bits, leaving its lowest bit unused.

There is no classification call for the following byte on this path. An aligned start can nevertheless have made the initial classification call.

The source-byte read occurs after the initial dependency call and any resulting indicator write. Mutations made by either can therefore affect the byte that is extracted.

### Extraction crossing the initial byte boundary

When the requested width exceeds the initial byte’s available bits, the function uses all of those available bits as the first contribution.

It establishes the address immediately following the selected initial byte, reads the initial byte, and then calls F-5480c9185606 at that following address. The context field at offset 8 is read for this call.

The initial contribution consists of the already-read byte’s low-order available bits. Dependency mutations after that read cannot change this captured contribution.

A nonzero dependency result creates a pending one-byte skip and causes the indicator to be written to one. A zero result creates no pending skip.

### Complete following bytes

While at least eight bits remain, the next contribution is a complete byte.

Its selected address is:

- The current candidate address if no skip is pending.
- One byte after the candidate address if a skip is pending.

The function establishes the address immediately after the selected byte, reads the selected byte, and calls F-5480c9185606 at that following address. The context field at offset 8 is read anew for the call.

The captured byte is appended to the accumulated result: the existing result moves eight bits toward the high-order side, and the byte occupies the newly available low eight bits.

The dependency result replaces the previous pending-skip decision. A nonzero result also causes a one-byte write of one to the indicator after the byte has been appended.

This classification occurs even when the complete byte exhausts the requested width. A call beyond the final contributing byte can therefore affect the indicator or have dependency side effects without causing another source byte to contribute.

### Final partial byte

If one through seven bits remain, the function selects the current candidate byte, advancing by one byte first if a skip is pending.

It reads that byte’s highest remaining-width bits and appends them to the accumulated result.

No dependency call follows this final partial-byte read.

If no bits remain after complete-byte processing, the function returns without another source-byte read. The classification already performed after the last complete byte remains part of the behavior.

### Width and arithmetic constraints

For an accepted width:

- The initial contribution contains one through eight bits.
- Each complete following contribution contains eight bits.
- Any final partial contribution contains one through seven bits.
- Total contribution width equals the requested width and does not exceed 32.

Extraction and assembly use unsigned 32-bit result arithmetic. The effective shifts on accepted-width paths stay below 32; no accepted extraction requires a shift by the full result width.

Address arithmetic is separate. The supplied body does not establish valid behavior for signed address-calculation overflow, invalid pointer formation, or inaccessible resulting addresses.

## Side effects

### Direct writes and context state

The function directly writes only through the indicator address:

- Zero once at entry.
- One following each nonzero dependency result that reaches its corresponding update.

It does not directly assign new values to the context’s storage-base, bit-position, or dependency-argument fields.

This does not guarantee that the context remains unchanged. An indicator write can alias a context field, and F-5480c9185606 can have unknown memory effects.

### Indicator interpretation

If the indicator is disjoint from other accessed storage and the dependency does not modify it, its final value is:

- Zero if every dependency result is zero, including the case of no dependency calls.
- One if any dependency result is nonzero.

Without those conditions, the final value need not summarize prior decisions. For example, a later dependency call can overwrite an earlier one with zero and return zero; the function then performs no restoring write.

A nonzero trailing classification can set the indicator even though the classified byte never contributes to the returned value and no later byte is selected.

### Mutation-sensitive reads

The context field at offset 8 is reread for each dependency call. A preceding dependency effect or aliasing indicator write can change a later call’s argument.

By contrast, changes to the base and bit-position fields after their initial reads do not change the retained traversal position.

Source bytes are captured individually at their described read points, not as a snapshot of the whole extraction. A dependency can affect bytes read later, but cannot change a contribution already captured in a local value.

### Ownership and failure behavior

The visible body contains no allocation, release, ownership transfer, or pointer retention operation. This observation does not establish the dependency’s ownership or lifetime behavior.

Invalid widths have an explicit zero-return path.

There is no visible recovery path for invalid storage, invalid address arithmetic, dependency faults, or violated dependency preconditions. A zero dependency result means “no skip from this decision”; it is not propagated as an error. All nonzero dependency results have the same local skip and indicator effects.
