## Behavior

### Conditional byte read and coprocessor load

When the equal-condition holds, the byte-address input is reduced by `0x312F`, or 12,591 bytes. The represented operation then reads exactly one byte from that adjusted address.

The byte is interpreted as unsigned and widened into a 32-bit working value. Its range is therefore 0 through 255. It replaces the incoming value associated with general-register slot 10 for purposes of the later conditional save.

The adjusted address also replaces the incoming byte-address value for that save.

After the byte read, the representation performs a coprocessor load using:

- Coprocessor selector 5.
- Coprocessor register selector 10.
- An address 476 bytes, or `0x1DC`, above the memory-base input.

The load’s transfer width, destination-state layout, address-update behavior, and exception behavior are not established. It must not be described as an ordinary 32-bit load merely because nearby saved values are 32 bits.

When the equal-condition does not hold, neither this byte read nor this coprocessor load is represented. The later save instead uses the incoming byte-address value and incoming general-register slot 10 value.

### Coprocessor operations surrounding the memory writes

When the transfer-condition holds, the representation contains two groups of identical coprocessor operations:

- Four operations before the conditional memory writes.
- Twenty-seven operations after those writes.

Each uses the same represented selector tuple: coprocessor `0xE`, operation selectors 7 and 7, and register selectors 12 and 12.

The operations’ exact transfer direction, payload, architectural effects, and external visibility are unknown. Their repetition is nevertheless part of the static evidence: the two groups must not be collapsed into a single abstract operation without additional evidence.

When both the equal-condition and zero-condition hold, the byte read and coprocessor load precede the first group of four operations.
