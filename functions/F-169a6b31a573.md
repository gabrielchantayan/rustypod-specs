## Behavior

### External word capture

The function reads the four external words in first-to-fourth order and places them into the corresponding local payload positions.

All four reads occur before any payload shift and before any dependency call. The transformation consequently uses the captured local values, not values reread from the external locations between calls.

The reads are separate operations. No synchronization or atomic multiword snapshot is established. If another execution context can change these locations, the supplied function does not establish that the four captured values belong to one coherent external state.

There is no direct write back to these four source locations.

### Word transformation and adjacent initialization

The function updates the local payload words in descending address order: offsets 12, 8, 4, then 0.

Each operation is an unsigned, 32-bit logical right shift by exactly one bit:

- Input bit 0 is discarded.
- Input bits 1–31 become output bits 0–30.
- Output bit 31 is zero.
- No bit is carried between neighboring words.

For each word, the result is the original unsigned value divided by two with any fractional part discarded. The result lies between `0x00000000` and `0x7fffffff`, inclusive. There is no rounding upward, arithmetic sign extension, or variable shift count.

The descending update order does not reverse the payload’s word order. Each transformed value remains in the position of its corresponding captured input.

After all four shifts, the function writes zero to the byte at payload offset 16. It does not explicitly initialize the remainder of the following region.
