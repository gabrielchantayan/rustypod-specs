# F-870f58a212f1

## Purpose

F-870f58a212f1 combines an interpolated, interleaved two-channel source with an existing two-channel input and writes 16-bit output pairs. Depending on the entry gain values, it applies separate gains, one shared gain, or no gain multiplication.

The operation also updates a progress field, conditionally stops after producing a frame, replaces the requested frame count with the produced count, and saves the fractional portion of its source position.

Audio mixing is inferred intent. The established behavior is numerical processing of signed 16-bit pairs with interpolation, wrapping gain multiplication, and asymmetric output limiting. No sample rate, playback policy, or device relationship is established.

## Behavior

### Entry snapshots and mode selection

The entry reads, in order, are channel-one gain, channel-two gain, position step, and source position. These values are retained locally; later writes to their backing fields do not refresh them.

Gain mode is selected once:

| Entry gains | Processing mode |
|---|---|
| Unequal | Multiply each channel by its corresponding gain |
| Equal, shared value `0x00000000` through `0x00007FFE` | Multiply both channels by the shared gain |
| Equal, shared value `0x00007FFF` through `0xFFFFFFFF` | Bypass gain multiplication for both channels |

The equal-gain multiplication condition combines two unsigned tests: the gain is below `0x7F00`, or its unsigned difference from `0x7F00` is below `0xFF`. The first covers values through `0x7EFF`; the second covers `0x7F00` through `0x7FFE`. Their union is therefore every unsigned value below `0x7FFF`.

Consequently, `0x7F00` is a multiplied value, not a bypass value. Both `0x7FFE` and `0x7FFF` are important boundary cases: the former multiplies, the latter bypasses. Large equal gains also bypass; this is not a narrow near-unity interval.

Unequal gains always take the separate-gain path, regardless of either value’s membership in those ranges.

### Frame eligibility

The produced count starts at zero. Before each frame, the current unsigned loop count is compared with the value currently read from the frame-count address.

The requested count is not snapshotted. With stable, nonoverlapping storage it behaves as a fixed limit. If a preceding write changes that location through overlap, a later eligibility check can observe the changed limit.

A zero initial count produces no frame. Entry snapshots and final count and position writes still occur.

### Source selection and interpolation

Let \(P\) be the local unsigned 32-bit source position. Its upper 16 bits select a source-frame index. The indexed frame begins at the source base plus four times that index. The next frame is the immediately following four-byte pair.

The next-frame access does not wrap the frame index to zero when the selected index is 65535; storage for frame 65536 is then required.

Let \(f\) be the low 16 bits of \(P\). The interpolation weight is

\[
w=\left\lfloor f/2\right\rfloor,\qquad 0\leq w\leq32767.
\]

The lowest position bit has no effect on interpolation.

For each channel, let \(a\) be the signed 16-bit sample in the indexed frame and \(b\) the corresponding sample in the next frame. The interpolated value is

\[
x=a+\operatorname{ASR}_{15}\bigl(w(b-a)\bigr),
\]

where \(\operatorname{ASR}_{15}\) means signed arithmetic right shift by 15 bits. Negative products therefore round downward, not toward zero.

The endpoint difference is formed after signed extension to 32 bits. Its range is −65535 through 65535. Multiplying by a weight no greater than 32767 fits in signed 32 bits. The interpolated result remains within the signed 16-bit endpoint range.

Both source frames are read even when the weight is zero. A zero weight does not eliminate the next-frame memory requirement.

### Gain and combination

For a multiplied channel with unsigned 32-bit gain \(g\), the scaled value is

\[
y=\operatorname{ASR}_{15}
\left(\operatorname{signed32}\bigl((g x)\bmod 2^{32}\bigr)\right).
\]

Only the low 32 product bits survive before signed interpretation and shifting. This is not a widened multiplication followed by saturation. Large gains can wrap to negative or otherwise nonconventional results.

The scaled value is added to the corresponding signed 16-bit existing-input sample.

In bypass mode, the interpolated value is added directly to the existing-input sample. There is no gain multiplication or gain-related shift.

The shifted gain product ranges from −65536 through 65535. Adding a signed 16-bit input remains within signed 32-bit range. Bypass combination also fits in signed 32 bits.

### Output limiting

Each channel’s combined value is limited independently:

| Combined value | Written 16-bit result |
|---|---|
| Below −32768 | Bit pattern representing −32768 |
| −32768 through 32767 | That value |
| 32768 or above | Low 16 bits of an external 32-bit limiting datum |

The external datum’s value is not supplied. Positive overflow produces 32767 only if that datum’s low 16 bits are `0x7FFF`. Negative overflow is unconditionally limited to −32768.

### Progress and boundary termination

Let \(S\) be the entry step’s 32-bit bit pattern. The prospective next position is

\[
N=(P+S)\bmod 2^{32}.
\]

The progress increment is the difference between the unsigned upper 16-bit portions of \(N\) and \(P\), using 32-bit arithmetic:

\[
d=\bigl((N\mathbin{\mathrm{div}}65536)
       -(P\mathbin{\mathrm{div}}65536)\bigr)\bmod 2^{32}.
\]

The current progress field is read, increased by \(d\) modulo \(2^{32}\), and written back. Progress is therefore not a count of output frames. Position wraparound can produce a large negative increment when interpreted as signed.

The signed boundary is then compared with the updated progress, interpreted as signed, plus one. If the boundary is less than or equal to that sum, the stopping control is read.

- Control exactly `1` suppresses boundary termination.
- Any other control value causes the stop marker to be written as `1` and processing to exit.

If the boundary comparison is false, the stopping control is not read.

The signed addition of one is unresolved when updated progress is the maximum signed 32-bit value. Portable overflow behavior for that expression is not established.

The boundary is checked only after producing a frame. An already-reached boundary cannot prevent the first frame when the initial count permits one.

On boundary termination, progress already includes the increment based on \(N\), but the local source position remains \(P\). Otherwise, the local position becomes \(N\), including when the following count check ends processing.

1. Produced count to the frame-count location.
2. Low 16 bits of the local position, zero-extended to 32 bits, to state offset `0x4C`.

Thus even a zero-frame call discards the entry position’s integer portion. Overlap between these destinations can make the second write alter storage just written by the first.

## Acceptance examples

These are conditional static acceptance criteria, not executed tests. Unless specified otherwise, memory is valid, buffers and state are disjoint, external values remain stable, and boundary termination does not occur. Examples using bypass select equal gains of `0x7FFF`.

1. **Zero requested frames.**  
   With count zero and initial position `0x12345678`, no output or progress update occurs. Final count is zero, saved position is `0x00005678`, and the stop marker is unchanged.

2. **Separate gains.**  
   With gains zero and `0x8000`, fraction zero, indexed source frame `(100, −200)`, and existing input `(10, 20)`, one output frame is `(10, −180)`. The following source frame must still be readable.

3. **Equal-gain thresholds.**  
   With both neighboring source frames containing 1000 in both channels and zero existing input:
   - Shared gain `0x7EFF` produces `(992, 992)`.
   - Shared gain `0x7F00` also produces `(992, 992)`.
   - Shared gain `0x7FFE` produces `(999, 999)`.
   - Shared gain `0x7FFF` produces `(1000, 1000)`.
   - Shared gain `0xFFFFFFFF` also produces `(1000, 1000)` because equal gains in that range bypass multiplication.

4. **Half-position interpolation.**  
   With fraction `0x8000`, bypass selected, corresponding neighboring samples 0 and 1000, and zero existing input, the output channel is 500.

5. **Negative rounding and ignored low bit.**  
   With neighboring samples 0 and −1, zero existing input, and bypass selected, fraction `0x0002` produces −1. Fraction `0x0003` also produces −1. Rounding the negative interpolation product toward zero would incorrectly produce zero.

6. **Wrapping gain multiplication.**  
   With unequal gains `0x00020000` and zero, source frame `(32767, 0)`, fraction zero, and zero existing input, output is `(−4, 0)`. The first product’s low 32 bits represent −131072 before shifting.

7. **Output limits.**  
   In bypass mode, 30000 combined with 10000 produces the external datum’s low 16 bits, not unconditionally 32767. Conversely, −30000 combined with −10000 produces −32768 regardless of that datum.

8. **Boundary termination after output.**  
   With position zero, step `0x00010000`, progress zero, boundary two, control zero, and requested count three, exactly one frame is produced. Progress becomes one, the marker becomes one, and final count is one. The local position does not advance before exit.

9. **Exact control override.**  
   Under example 8’s conditions, control exactly one permits all three requested frames. Control two does not override the boundary and therefore still stops after one frame.

10. **Early-stop fractional position.**  
    With position zero, step `0x00008000`, progress zero, boundary one, control zero, and count one, the frame is produced but saved position remains zero. With control one instead, normal count exhaustion saves `0x00008000`.

11. **Position wrap affects progress.**  
    With position `0xFFFF0000`, step `0x00010000`, and progress zero, a produced frame updates progress to bit pattern `0xFFFF0001`, interpreted as −65535. With boundary termination suppressed, saved position is zero.

12. **Return packing.**  
    Equal entry gains place the state address in the return’s lower 32 bits. Unequal entry gains place the entry channel-two gain there. Both cases place the entry channel-one gain in the upper half.
