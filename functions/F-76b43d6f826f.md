# F-76b43d6f826f

## Purpose

F-76b43d6f826f scans a bounded sequence of 16-bit units and produces two integer results: a signed day component and a signed aggregate of hour, minute, and second components.

The recognized unit values correspond to the characters D, H, M, S, P, T, and the minus sign. D, H, M, and S cause conversion of the preceding span through dependency F-2798aeb143ba. P and T delimit spans without conversion. A minus sign makes both final results negative relative to the accumulated component values.

The apparent intent is to process a duration-like representation. That interpretation does not establish conformance to any external duration syntax. The observed behavior does not validate marker order, require a prefix, enforce component ranges, or reject unrecognized units.

## Interface

The function receives three arguments:

1. **Sequence descriptor address.** The descriptor contains two consecutive 32-bit slots:
   - Offset 0: the sequence start address.
   - Offset 4: the sequence end address.

   The supplied representation interprets both slots as addresses of 16-bit units. The end address is an exclusive boundary checked by address equality.

2. **Day-result destination.** An address at which an integer result is written.

3. **Time-result destination.** An address at which an integer result is written, representing hours multiplied by 3,600, plus minutes multiplied by 60, plus seconds, with the selected sign applied.

The displayed interface has no return value. Successful completion is observable through the two destination writes, not through a status result.

### Widths and representation

The descriptor slots are explicitly 32 bits, and each scanned unit is an unsigned 16-bit value. Component accumulators, the sign, dependency results, and output values are represented as integers. A 32-bit integer interpretation is consistent with the supplied representation, but the underlying ABI and signed-overflow rules are not independently established.

Recognition operates on numerical 16-bit values. It does not perform byte decoding, case folding, Unicode normalization, or locale-sensitive character matching. Byte order and alignment requirements are not established by the supplied evidence.

### Preconditions for ordinary completion

The descriptor must be readable. Each unit reached before the end comparison succeeds must be readable as a 16-bit value. Each output destination must be writable when its corresponding write occurs.

Any span passed to F-2798aeb143ba must satisfy that dependency’s requirements if normal conversion and return are expected. Those requirements are not supplied.

For a stable descriptor, the end address must be reachable by advancing from the initial start address in increments of one 16-bit unit. The function does not check that the end follows the start or that both belong to the same allocation.

## Behavior

### Initialization and scan boundaries

The function reads the descriptor’s start slot once. That address becomes both the initial scan position and the initial conversion-span start.

It initializes four component values—days, hours, minutes, and seconds—to zero. The sign begins at positive one.

Before reading each candidate unit, the function reads the descriptor’s end slot and compares that address with the current scan position.

- If the addresses are equal, scanning ends and the function writes its results.
- Otherwise, the function reads the 16-bit unit at the current position and processes it.

The end slot is therefore consulted repeatedly rather than captured once. The start slot is not reread. Changes made by a dependency to the descriptor or backing storage can affect subsequent observations where those changes are otherwise valid for the execution environment.

After processing a unit, the scan position advances by one 16-bit unit, or two bytes. No recognized unit stops the scan early.

### Recognized values

| Numerical value | Character interpretation | Effect |
|---|---|---|
| 0x0044 | D | Convert the current span and replace the day component. |
| 0x0048 | H | Convert the current span and replace the hour component. |
| 0x004D | M | Convert the current span and replace the minute component. |
| 0x0053 | S | Convert the current span and replace the second component. |
| 0x0050 | P | Move the conversion-span start past this unit without conversion. |
| 0x0054 | T | Move the conversion-span start past this unit without conversion. |
| 0x002D | Minus sign | Set the sign to negative one without moving the conversion-span start. |
| Any other value | Unrecognized unit | Leave components, sign, and conversion-span start unchanged. |

For D, H, M, and S, F-2798aeb143ba receives the current conversion-span start and the address of the marker. The marker is the supplied upper boundary; its own address is not advanced before the call.

On normal return, the dependency’s integer result replaces the selected component. The conversion-span start then moves to the unit immediately following the marker.

The function does not itself determine whether the span contains a valid number. It also does not check the dependency’s return value for an error indication.

### Ordering and repetition

Markers may appear in any order. There is no distinct date section or time section in the control flow. In particular, M always selects the minute component, whether or not T has appeared.

Repeated component markers replace earlier values rather than adding to them. A later H conversion, for example, replaces the previous hour value while retaining the current day, minute, and second values.

P and T discard any pending span by moving its start beyond themselves. They do not reset component values or restore a positive sign.

A minus sign sets the sign to negative one permanently for the remainder of this invocation. A second minus sign does not toggle it. No unit restores positive one.

The minus sign does not delimit a span. Consequently, a later conversion can receive a span containing the minus sign. Whether that dependency interprets it as a numeric sign is unknown.

Unrecognized units are not rejected or removed. They remain part of a pending span unless a later P, T, or component marker advances its start.

### Completion and arithmetic

When the scan position equals the currently read end address, the function performs these writes in order:

1. Write the day component multiplied by the sign to the day-result destination.
2. Write the sign multiplied by the sum of:
   - The hour component multiplied by 3,600.
   - The minute component multiplied by 60.
   - The second component.

Days are not incorporated into the time result. Components are not normalized before calculation. For example, an hour component of 25 is not converted into an additional day.

A pending span at the end is not converted. Only D, H, M, and S trigger dependency calls.

The supplied representation does not establish the treatment of signed overflow. A portable contract cannot require saturation, wrapping, a trap, or a particular result for arithmetic outside the supported integer range. Examples below use results that fit a signed 32-bit interpretation.

## Side effects

The function directly reads the descriptor and scanned sequence and directly writes the two output destinations. It contains no explicit writes to the descriptor or sequence.

For each component marker, the observable local sequence is:

1. Read the marker.
2. Call F-2798aeb143ba with the current span boundaries.
3. Store the returned value in the corresponding local component.
4. Advance the local span boundary and continue scanning.

Effects performed by the dependency can therefore occur before subsequent end-slot reads, sequence reads, and final output writes. No guarantee is available that the dependency preserves globals, leaves input storage unchanged, or avoids other externally visible effects.

If the two output destinations designate the same integer storage, the second write replaces the first. The final stored value is then the time result.

The function does not deliberately publish intermediate component values through either output pointer. If scanning or conversion fails before completion, no normal final-output guarantee follows. If the first output write succeeds and the second fails, the first write has already occurred.

There is no explicit allocation, deallocation, ownership transfer, or retention operation in this function. Its direct behavior is consistent with borrowing the descriptor and sequence for the duration of the call and writing caller-provided result storage. This does not establish memory-ownership behavior inside F-2798aeb143ba.

## Acceptance examples

These examples are conditional static predictions, not runtime results. Character notation denotes sequences of the corresponding 16-bit numerical values. Unless stated otherwise, the descriptor is stable, storage is valid, dependency calls return normally, and output destinations are distinct.

### Empty sequence

If the start and end addresses are equal initially:

- No sequence unit is read.
- No dependency call occurs.
- The day result is zero.
- The time result is zero.

### Conventional component sequence

For P2DT3H4M5S, if the four conversions return 2, 3, 4, and 5 respectively:

- Dependency calls occur for D, H, M, and S in that order.
- The day result is 2.
- The time result is 11,045.

P and T only advance the pending span boundary.

### Negative prefix after P

For P-2D, if conversion of the span beginning at the minus sign returns positive 2, the day result is negative 2.

If that same conversion instead returns negative 2, the day result is positive 2 because the caller also applies its negative sign. The supplied evidence does not choose between those dependency outcomes.

### Repeated components

For 1H2H, if the conversions return 1 and 2:

- The second hour value replaces the first.
- The day result is zero.
- The time result is 7,200.

### Trailing text without a marker

For P12, no dependency call occurs and both outputs are zero. Reaching the end does not convert the pending span.

For 1H99, if the H conversion returns 1, the time result is 3,600. The trailing 99 does not create another component.

### Empty component span

For PD, P moves the span start to D. D therefore invokes the dependency with equal boundary addresses. Whatever integer the dependency returns becomes the day component; the function supplies no special empty-span rule.

### Marker without a prefix

For 2M, if the conversion returns 2, the time result is 120. Neither P nor T is required before M.

### Sign after a completed component

For 2H-, if the H conversion returns 2:

- The minus sign causes no further conversion.
- The day result is zero.
- The time result is negative 7,200.

### Embedded zero-valued unit

A unit with value zero is not a terminator. If it occurs before the descriptor’s end address, scanning continues. If it remains within a later conversion span, its interpretation is delegated to F-2798aeb143ba.

### Aliased outputs

For a sequence producing day result 2 and time result 3, if both output arguments designate the same integer storage, the function first writes 2 and then writes 3. The final value is 3.
