# F-8166135a5e64

## Purpose

F-8166135a5e64 conditionally takes a node from a reserve chain and modifies an active structure. It performs guarded preparation before checking eligibility, then selects between two insertion paths using node fields, classification results, and a caller-supplied mask.

Both insertion paths advance the reserve slot before invoking a node-processing dependency. They finish with different link updates. The first path also replaces two other state slots and returns a fresh state-slot read; the second returns the captured reserve-node address.

“Active,” “reserve,” “classification,” and “insertion” describe inferred roles. The established behavior is the sequence of accesses, calls, branch conditions, and writes below. In particular, a zero return is not an unconditional indication that no insertion branch completed.

This contract is based on static evidence only. No runtime tests have been performed.

## Interface

### Arguments and representations

The visible interface has four arguments:

| Argument | Representation | Use |
|---|---|---|
| State address | Address of three consecutive 32-bit slots | Supplies and receives node-address representations. |
| Mask | Unsigned 32-bit value | Filters the first classification result and can independently enable the second insertion path. |
| Third argument | 32-bit value | Not referenced by the visible body. |
| Fourth argument | 32-bit value | Forwarded to the node-processing dependency only on the second insertion path. |

The state slots are designated **S0**, **S1**, and **S2**, at byte offsets 0, 4, and 8 from the state address.

Node addresses are held in 32-bit scalar storage. The following node fields are accessed:

| Byte offset | Width | Established access |
|---|---|---|
| `0x12C` / 300 | 32 bits | Read from the node named by S0 to test eligibility. |
| `0x134` / 308 | 32 bits | Read as a reserve successor; written as a link or zero. |
| `0x138` / 312 | 32 bits | Written as a link or zero. |
| `0x140` / 320 | 32 bits | Read for classification and arithmetic. |

The apparent forward-link, reverse-link, and coordinate meanings are inferred. A conventional doubly linked list, complete node layout, and fixed-point coordinate format are not established.

### Global references

The body uses three global references:

- **Guard reference:** identifies an object whose first word supplies the tested low bit and whose word at byte offset 4 can be updated.
- **Initialization reference:** identifies an object whose word at byte offset 4 supplies the preparation value.
- **Reference-value reference:** supplies a pointer argument to the first classification call and identifies a 32-bit value read on the first insertion path.

A dependency may modify these references or their targets. References consulted after a call must not be treated as preserved snapshots unless the body explicitly retains the earlier address.

### Return value

The return representation is 32 bits:

- The ineligible-node exit returns zero.
- The exit after unsuccessful second-path selection returns zero.
- The first insertion path returns a fresh read of S0 after all its explicit insertion writes.
- The second insertion path returns the reserve-node address captured before its node-processing call.

With suitable non-aliasing assumptions and state-preserving dependencies, the first path returns the selected reserve node. Without those assumptions, its final S0 read can differ from that node, including being zero.

Consequently, **zero alone is not a reliable insertion-status indicator**. A completed first insertion branch can return zero through permitted storage overlap. The return value is not a separate success or failure flag.

### Preconditions

For normal completion, every address actually accessed must support the indicated 32-bit access. This includes:

- The three state slots.
- The guard object and, when preparation completes, the initialization source.
- The nodes and fields consulted on the selected control-flow path.
- Objects accessed by dependencies through pointer arguments.

Dependencies must return normally, and storage subsequently accessed must remain usable.

No explicit null, reserve-exhaustion, alignment, bounds, or aliasing checks appear. A failed precondition is not converted into a defined error return. Distinct state and node storage is a simplifying condition for ordinary list interpretations, not an enforced requirement of the visible body.

## Behavior

### Guarded preparation

The function captures the guard-object address before invoking any dependency.

It reads the first 32-bit word of that object and tests bit 0:

- If bit 0 is set, both preparation dependencies are skipped.
- If bit 0 is clear, F-b255b26284e6 receives the guard-object address.
- If that call returns zero, the preparation write and completion call are skipped.
- If that call returns nonzero, preparation continues.

On the continuing branch, two local 32-bit words receive `0x000F0000`. The function reads the initialization object’s word at byte offset 4, adds `0x002D0000`, and writes the result to byte offset 4 of the captured guard object. F-d08d3ca17b81 then receives that captured address; its result is unused.

The initialization reference is consulted after F-b255b26284e6 returns. Its then-current target and contents therefore determine the source value. In contrast, the destination remains the guard object captured before the call, even if the global guard reference changes.

The visible body does not explicitly set the guard word’s low bit. Any such effect of a dependency is unknown.

Preparation occurs before node eligibility is checked. Either zero-return exit can therefore follow preparation effects.

### Eligibility

After preparation, the function reads S0 and then the 32-bit field at offset `0x12C` of the named node.

A zero field causes an immediate zero return. No classification, scaling, or node-processing call follows on that execution.

A nonzero field permits the first classification. The function does not require the field to equal any particular nonzero value.

### First classification

The function reads the `0x140` field of the node currently named by S1 and copies that 32-bit value into local storage. F-a09269e75221 receives:

1. The address of that local copy.
2. The pointer obtained from the reference-value reference.

The result is interpreted as a 32-bit bit pattern. The first insertion path is selected when the result has at least one bit set that is clear in the mask. Equivalently, intersecting the result with the 32-bit complement of the mask must produce a nonzero value.

Thus:

- A zero result never selects the first path.
- A zero mask selects it for every nonzero result.
- Mask `0xFFFFFFFF` prevents it for every result.
- Result bits already present in the mask do not select it.

The first pointer addresses a local copy, not the node field. A write through that pointer alone does not update the original node field. Other dependency effects remain unknown.

### First insertion path

The function rereads the `0x140` field of the node currently named by S1 and reads the current reference value. It passes their difference, together with `0x000F0000`, to F-b6d5b325ab94.

These are new reads after classification. Changes to S1, the selected node field, or the reference-value source can affect this arithmetic independently of the earlier local copy.

The scaling result is represented as a signed 32-bit value. The adjustment supplied to the node-processing dependency is the negation of one plus that result shifted right by 16. Signed-overflow and negative-shift limitations are retained under Uncertainties.

The function then captures the current S2 value as **N**, reads N’s `0x134` field, and writes that field value into S2. This reserve-slot advance occurs before F-22366f06e2a5.

That dependency receives three explicit arguments:

1. N.
2. The S0 value read for the call.
3. The derived adjustment.

Its return value is unused. After it returns, the body performs these writes in order:

1. Write zero to N’s `0x138` field.
2. Write zero to N’s `0x134` field.
3. Read S0 and write N to that node’s `0x138` field.
4. Write N to S0.
5. Read S1 and S2, then write the S2 value to the `0x134` field of the node named by S1.
6. Read S1 and write that value to S2.
7. Write N to S1.
8. Read S0 and return that value.

The description specifies the sequence of completed writes and the fresh reads required by each operation. It does not establish an order between independent operand reads within one operation.

With distinct storage and no relevant dependency mutations, completion leaves S0 and S1 naming N, S2 naming the former S1 node, and that former node’s `0x134` field naming the remaining reserve chain.

With overlapping storage, later writes can overwrite earlier state assignments. In particular, the write through the current S1 node can overwrite S0 after S0 has received N. The final return uses the resulting S0 value, not the retained N.

### Second classification and selection

If the first insertion path is not selected, the function prepares a second classification.

A local signed 32-bit value receives the current S0 node’s `0x140` value minus `0x000F0000`. Two other local words receive:

- `0xFF9C0000`, or −6,553,600 under signed 32-bit interpretation.
- `0x000F0000`, or 983,040.

F-a09269e75221 receives the address of the derived value and the address of the word containing `0xFF9C0000`.

The assigned local words and explicit pointer arguments are established. A complete multiword descriptor layout, including which neighboring words the dependency accesses, is not established.

The second insertion path is selected if either the classification result is nonzero or the mask is nonzero. The classification call occurs before this decision even when the mask already guarantees selection.

If both the classification result and mask are zero, the function returns zero without either insertion sequence being performed by the visible body.

### Second insertion path

The function captures the current S2 value as N, reads N’s `0x134` field, and writes that value into S2.

F-22366f06e2a5 then receives five explicit arguments:

1. N.
2. The S0 value read for the call.
3. `0xFFFFFFFF`.
4. The caller’s fourth argument.
5. `0x00640000`, or 6,553,600.

After the call returns, the function:

1. Writes zero to N’s `0x138` field.
2. Reads S0 and writes that value to N’s `0x134` field.
3. Reads S0 again and writes N to that node’s `0x138` field.
4. Writes N to S0.
5. Returns the captured N.

The two post-call S0 reads are not specified as a single preserved snapshot. Dependency mutations and overlapping writes can affect their values.

This path contains no direct assignment to S1. It does not guarantee that S1 remains unchanged: dependencies or writes to overlapping storage can change it.

## Side effects

### Direct mutations and ordering

The body can update the guard object, advance S2, clear or replace node links, and replace S0. The first insertion path additionally writes S1, assigns S2 from S1, and writes through the node named by S1.

On either insertion path, the initial S2 advance precedes node processing. Link completion follows that call. A dependency observing state during node processing can therefore observe an advanced S2 before the later link writes.

All direct writes can have additional effects when their destinations overlap state slots, other node fields, or globally referenced storage.

### Ownership and lifetime

No explicit allocation or deallocation is visible. The selected address comes from S2.

This does not establish ownership transfer, reference counting, or dependency allocation and release behavior. No dependency is assumed to preserve globals, state, node contents, or object lifetimes.

### Errors and atomicity

There is no separate error-reporting channel or explicit recovery path.

The two non-insertion exits return zero, but zero does not prove that execution took either exit. A first-path completion can also return zero because its final result is a fresh S0 read after potentially overlapping writes.

No transaction, full-operation lock, or rollback is visible. If a dependency does not return normally, earlier effects may already have occurred. The guard-related calls do not establish synchronization for the later state and link mutations.

## Acceptance examples

These are conditional static examples, not executed tests. Except where overlap is specified, assume valid, distinct storage and dependencies that return normally without changing relevant state.

1. **Ineligible node.** If the tested S0 node field is zero, the result is zero and classification and node processing are skipped. Preparation may already have changed the guard object or produced dependency effects.

2. **Unmasked result bit.** With first classification result `0x00000004` and mask zero, the first insertion path runs. The second classification is skipped.

3. **Masked result bit.** With first result `0x00000004` and mask `0x00000004`, the first path is not selected. The second classification runs, and the nonzero mask selects the second insertion path regardless of its result.

4. **Non-insertion exit.** With mask zero and both classification results zero, the function returns zero without performing either visible reserve-removal sequence. This is one cause of zero, not its exclusive meaning.

5. **All-bits mask.** Mask `0xFFFFFFFF` prevents the first path. If eligibility holds and the calls return normally, the second classification runs and the second path is selected.

6. **Adjustment values.** A scaling result of zero produces adjustment −1. A result of `0x00010000` produces −2. These cases do not require resolving negative signed-right-shift behavior.

7. **Ordinary second-path links.** Let initial S0 name A, S2 name N, and N’s `0x134` field name R. Completion leaves S2 naming R, N’s `0x138` field zero, N’s `0x134` field naming A, A’s `0x138` field naming N, and S0 naming N. The returned value is N.

8. **Fresh active-slot reads.** If node processing changes S0 to B and returns, subsequent writes that read S0 use B unless another intervening overlapping write changes it again. They need not target the node passed to the dependency.

9. **Completed first path returning zero.** Place the state array at address B plus `0x134`. Initialize S0 to A, S1 to B, and S2 to N. Let N’s `0x134` field be zero. Assume A, B, N, and all accessed storage are valid; dependencies preserve relevant state; and classification selects the first path.

   The reserve advance writes zero to S2. The later assignment writes N to S0. At the subsequent write through S1, S1 still names B, so the destination B plus `0x134` is S0 itself. The current S2 value is zero, so this write replaces S0 with zero. The remaining assignments set S2 to B and S1 to N without restoring S0. The branch completes and returns zero from its final S0 read.

   This example establishes why zero cannot unconditionally distinguish non-insertion from completed insertion.
