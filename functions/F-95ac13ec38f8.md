# F-95ac13ec38f8

## Purpose

F-95ac13ec38f8 resolves a zero-terminated byte string to a 32-bit unsigned result through three paths:

1. Direct conversion of certain lowercase-prefixed, uppercase-hexadecimal names.
2. Exact lookup in a globally referenced compact byte table.
3. Delegated resolution of a name prefix ending before a qualifying period.

A qualifying period causes bit 31 of the underlying result to be toggled. This is an exclusive-OR operation, not an unconditional “set flag” operation.

The established behavior is byte-oriented and case-sensitive. Interpreting the result as a character identifier, or interpreting a period as a naming suffix separator, is inferred intent rather than a verified semantic guarantee.

The numeric path does not enforce Unicode scalar-value restrictions. The table format returns 16-bit values. The delegated path can contribute any of the 32 result bits, subject to the dependency’s unknown contract.

## Interface

### Input

One pointer to a readable, zero-terminated byte sequence.

Each input element is an unsigned 8-bit byte. Relevant byte values are:

- Lowercase `u`, `n`, and `i`: `0x75`, `0x6E`, and `0x69`.
- Decimal digits: `0x30`–`0x39`.
- Uppercase hexadecimal letters: `0x41`–`0x46`.
- Period: `0x2E`.
- Terminator: `0x00`.

The function has no explicit length argument. The input must remain readable through every byte inspected, normally including its terminating zero.

A null pointer is not a supported empty-input representation. The function dereferences the input before reaching a later null comparison.

### Output

One unsigned 32-bit integer.

Established result categories:

| Resolution path | Result before any period transformation |
|---|---|
| Four-digit `uni` form | Parsed value, at most `0x0000FFFF` |
| Four- through six-digit `u` form | Parsed value, at most `0x00FFFFFF` |
| Successful table lookup | Zero-extended 16-bit table value |
| Failed table lookup or empty input | `0x00000000` |
| Delegated prefix resolution | Dependency result |

For a period-terminated numeric match or delegated prefix resolution, the final result is the underlying value exclusive-OR `0x80000000`.

Zero is not a unique failure indicator: direct numeric conversion and a terminal table entry can also produce zero.

### Ownership and validity

No allocation, release, ownership transfer, or input modification is directly visible in this function.

The input and global table storage must be valid for the reads performed. The function contains no bounds validation for the table and no protection against missing input terminators.

When delegation occurs, the dependency receives pointers into the original input. Whether that dependency writes through, retains, or otherwise acts on those pointers is unknown.

## Behavior

### 1. Numeric recognition precedes name lookup

Numeric recognition is attempted only when the first byte is lowercase `u`.

There are two candidate forms, tried in order.

#### Four-digit `uni` form

If the first three bytes are exactly lowercase `uni`, the function attempts to consume exactly four hexadecimal digits immediately afterward.

Only decimal digits and uppercase `A`–`F` are accepted. Lowercase hexadecimal letters are not accepted.

The four-digit form succeeds only when all four digits are present and the immediately following byte is either:

- Zero: return the parsed value unchanged.
- Period: return the parsed value with bit 31 toggled.

A period need not be followed by anything readable for this successful numeric path. The function does not inspect the bytes after that period.

If this attempt fails, the function still attempts the general `u` form from the byte immediately after the initial `u`. It does not continue from the point reached by the `uni` attempt.

In particular, the `n` in an ordinary `uni` prefix is not a hexadecimal digit, so a failed `uni` attempt normally also fails the subsequent `u` attempt.

#### Four- through six-digit `u` form

Starting immediately after the initial lowercase `u`, the function consumes at most six hexadecimal digits.

Recognition requires at least four digits. After four, five, or six digits, the next inspected byte must be zero or period:

- Zero returns the parsed value unchanged.
- Period returns the parsed value with bit 31 toggled.

An invalid byte after fewer than four digits prevents numeric recognition. An invalid non-period byte after four or five digits also prevents recognition. After six digits, any following byte other than zero or period prevents recognition, including a seventh hexadecimal digit.

Failure to recognize either numeric form does not immediately return an error. It falls through to general name processing.

#### Arithmetic

Digit values are accumulated by multiplying the current unsigned 32-bit value by 16 and adding the next digit.

The four-digit limit bounds the first form to 16 bits. The six-digit limit bounds the second form to 24 bits. Consequently, neither accepted numeric form overflows the 32-bit accumulator.

There is no filtering of surrogate values, noncharacters, values above `0x10FFFF`, or zero.

### 2. General period scan

After numeric recognition fails or is inapplicable, the function scans from the beginning of the input.

It stops at either:

- The terminating zero; or
- The first period strictly after the first byte.

A period at the first byte is not a separator. Scanning continues past it. A later period, including a second consecutive period, is a separator.

Therefore:

- `.name` has no separator unless another period appears later.
- `name.part` splits at the period.
- `..` splits at its second byte.
- An empty string has no separator and resolves to zero.

No trimming, escaping, case folding, or text-encoding conversion occurs.

### 3. Delegated prefix resolution

If the general scan finds a separator, the function calls F-b7dba3234669 with:

1. The original input pointer.
2. A pointer to the separator period.

The second pointer identifies a boundary inside the original storage. This function does not replace the period with zero or create a separate prefix buffer.

Once the dependency returns, the function toggles bit 31 of its 32-bit result and returns it. There is no local validation of the returned value.

This path takes precedence over direct table lookup for any general name with a qualifying period, even if the complete string might otherwise have a table entry.

The visible function does not scan the remainder after the separator. Any inspection of that remainder by the dependency is unknown.

### 4. Exact compact-table lookup

If the general scan reaches zero without finding a qualifying period, the function attempts an exact lookup of the entire nonempty input in a globally referenced table.

The global reference and referenced table must be valid. This path does not provide a missing-table fallback.

#### Table header and root index

The established header layout is:

| Byte position from table base | Meaning used here |
|---|---|
| 0 | Not interpreted by this function |
| 1 | Unsigned 8-bit root-entry count |
| 2 onward | Root offsets, two bytes per entry |

Each root offset is a big-endian unsigned 16-bit quantity relative to the table base. The first offset byte supplies the high eight bits.

The function performs a binary search over these root entries. It compares the first input byte against the low seven bits of the referenced node’s first byte.

Correct lookup depends on root entries being ordered by those seven-bit labels. Table ordering is a precondition, not something this function validates.

A zero root count produces lookup failure.

#### Node representation

The first byte of a node contains:

- Bits 0–6: the node’s input-byte label.
- Bit 7: a representation selector.

There are two node representations.

**Inline-continuation node — selector set**

The next node begins immediately at the next byte. To consume another input byte, the function advances there and compares that node’s low-seven-bit label.

A node in this representation cannot itself satisfy end-of-input: reaching the input terminator while positioned on such a node returns zero.

**Branch-capable node — selector clear**

The byte immediately after the label is a descriptor:

- Bits 0–6: child count, from 0 through 127.
- Bit 7: terminal-value-present flag.

If the terminal flag is clear, the child-offset list starts two bytes after the node’s beginning.

If the terminal flag is set:

- The next two bytes contain the terminal value as an unsigned big-endian 16-bit integer.
- The child-offset list starts four bytes after the node’s beginning.

Each child offset is a big-endian unsigned 16-bit quantity relative to the table base, just like a root offset.

A terminal node may also have children.

#### Traversal and matching

After matching the first input byte through the root index, the function processes the remaining bytes in order.

At an inline-continuation node, it advances to the adjacent node and requires that node’s label to match the next input byte.

At a branch-capable node, it examines child offsets sequentially until it finds a child with a matching label or exhausts the declared child count. Unlike the root index, the child search is linear and does not require sorted child labels. If multiple children have the same label, the first matching child in the stored list is selected.

A mismatch or exhausted child list returns zero.

Because stored labels are masked to seven bits but input bytes are not, an input byte from `0x80` through `0xFF` cannot match a node label.

#### End-of-input

After all input bytes have matched, lookup succeeds only when the current node is branch-capable and its terminal-value-present flag is set.

The returned value is the node’s big-endian 16-bit terminal value, zero-extended to 32 bits.

Matching only a prefix is insufficient. Conversely, a node can be terminal while still allowing longer names through its children.

## Side effects

### Established local effects

The function directly:

- Reads input bytes.
- Reads the global table reference and table bytes on the table-lookup path.
- Calls F-b7dba3234669 on the delegated-prefix path.

It contains no direct writes to input storage, table storage, or global state. It performs no visible allocation or deallocation.

### Observable ordering

The path order is significant:

1. Inspect the first input byte.
2. When applicable, attempt numeric recognition.
3. Only after numeric recognition fails, scan for a general separator.
4. Either delegate immediately or perform table lookup.
5. After delegation, toggle bit 31 and return.

Successful numeric recognition bypasses both the table and the dependency.

During table traversal, each next input byte is read before the corresponding continuation or child search is completed. Child candidates are examined in stored order; later candidates need not be read after a match.

These are logical access-order properties of the supplied representation, not a claim about processor-level transaction ordering or exact repeated-load counts.

### Dependency effects

No claim is established that F-b7dba3234669 preserves globals, leaves input unchanged, avoids allocation, or releases any memory. Its effects must be specified independently.

There are no table reads after the delegated call in this function’s visible return path.

### Table cases

Given a valid table:

- An exact terminal entry with value `0x1234` returns `0x00001234`.
- A matched path ending at a nonterminal branch node returns zero.
- A matched path ending at an inline-continuation node returns zero.
- An unmatched next byte returns zero even if an earlier node was terminal.
- If two children share a label, traversal follows the first matching child.
- Empty input returns zero without table lookup.
- A name containing a byte above `0x7F` cannot match the table’s seven-bit labels.
