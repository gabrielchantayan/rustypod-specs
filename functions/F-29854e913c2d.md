### Post-call conversion

If the dependency returns normally, the function reads the local 32-bit integer and computes the value for the final 16-bit store.

Under the apparent 32-bit bit-vector interpretation, the transformation selects bits 1 through 16 of that integer and places them in output bits 0 through 15:

- Input bit 0 is discarded.
- Input bits 1 through 16 become the stored 16-bit value.
- Input bits 17 through 31 do not contribute.
- There is no rounding, saturation, or clamping.

An equivalent mathematical description for a 32-bit input bit pattern \(q\) is:

\[
\text{stored pattern} =
\left\lfloor \frac{q \bmod 2^{17}}{2} \right\rfloor
\]

This is not generally equivalent to dividing the entire signed integer by two and storing an unrestricted result. In particular, higher bits are discarded.

There is an important qualification: the recovered expression first left-shifts a signed integer by 15 positions, then converts it to an unsigned value and right-shifts by 16 positions. A strict source-language interpretation does not define that signed left shift for every possible 32-bit input. The bit-selection description therefore expresses the apparent fixed-width operation, not an unconditional language-level guarantee for every input pattern. This distinction is addressed under Uncertainties.
