# F-134438cf811e

## Purpose

F-134438cf811e describes an ordered execution fragment that invokes dependencies, derives arguments from returned values, reads selected bytes and record fields, and performs memory writes before reaching one of two invalid-instruction boundaries.

No application-level purpose is established. Interpretations such as loading, parsing, allocation, or validation are **inferred intent**, not requirements.

This contract distinguishes:

- **Established static evidence:** represented operations, widths, data dependencies, and ordering.
- **Inferred intent:** interpretations not required by the evidence.
- **documented_only:** unresolved behavior for which no implementation rule is asserted.

The supplied representation contains invalid-instruction recovery warnings. The contract describes that representation without asserting that recovery is complete or that the original routine has no other behavior.

## Interface

### Explicit input and output

The represented interface accepts one opaque 32-bit argument. Its unchanged bit pattern is passed to the first dependency. Its signedness, interpretation, validity requirements, and ownership are unknown.

No explicit return value or normal return is represented. Both visible terminal paths end at invalid-instruction boundaries.

### Implicit inputs

Behavior also depends on:

- Incoming return-link state used to derive the first call target.
- An incoming value used to calculate a halfword destination by doubling it.
- Another incoming value used to calculate a record address.
- Secondary 32-bit result-register outputs from two dependencies.
- The address of a local auxiliary stack slot.
- Memory cells at `0x08400240` and `0x08400198`.
- Dependency-accessible memory and execution state.

Three distinct local 32-bit storage locations matter near the end:

| Contract name | Role |
|---|---|
| Control slot | Initially receives the word read from `0x08400198`; subsequently supplies the threshold operand, byte-store value, and halfword-destination operand through separate uses. |
| Auxiliary slot | Its address contributes to the conditional halfword value; it is subsequently written with zero. |
| Saved-record slot | Subsequently receives the captured record word from offset 16. |

The auxiliary slot is not the control slot.

### Widths and interpretation

Words are 32 bits, halfwords 16 bits, and bytes 8 bits. Captured wide results are 64 bits. Their low and high words are defined by bit position, independently of memory byte order.

Bit numbering starts at zero. Logical shifts insert zeros. The represented signed right shift by 31 produces zero or negative one. Byte and halfword stores retain the corresponding low-order bits.

Byte order, alignment tolerance, executable-address conventions, and the complete calling convention remain **documented_only**. A call described as having no explicit arguments may still depend on unrepresented machine argument channels.

### Bit-derived arguments and selected byte reads

The bit extractions in D-02, D-07, D-09, D-11, D-17, D-19, and D-21 produce exactly zero or one.

D-02 uses the same captured high word for both bit-28 deliveries. The intervening invocation does not introduce another wide-result capture.

D-06 reads one byte at:

- `0x10` when its captured word is nonnegative as signed 32-bit.
- `0x11` when that word is negative.

D-13 reads one byte at `0x10` plus bit 29 of its captured word.

These are memory reads, not Boolean constants. Each occurs after the full-word forwarding call and intervening call. Those dependencies can therefore change the byte subsequently delivered.

The two bit-24 stages use independent captured words. The two bit-63 stages use independent captured wide results.

### Distinct subtract-seven stages

D-14 subtracts seven from the captured high word using unsigned 32-bit arithmetic, modulo \(2^{32}\), then extracts bit 31.

| Captured high word | Delivered argument |
|---|---:|
| `0x00000000`–`0x00000006` | 1 |
| `0x00000007`–`0x80000006` | 0 |
| `0x80000007`–`0xffffffff` | 1 |

This is not an unsigned less-than-seven predicate.

D-16 instead represents signed subtraction by seven followed by an arithmetic sign extraction. Where subtraction is representable in signed 32-bit arithmetic:

- A negative difference selects byte address `0x11`.
- A nonnegative difference selects byte address `0x10`.

For signed high words from `-2147483648` through `-2147483642`, subtraction exceeds the signed range. Selection for those inputs is **documented_only**; wrapping is not assumed.

In both phases, duplicated low-word delivery and a separate no-explicit-argument invocation precede delivery of the high-word-derived argument.

### Incoming-value store and record address

Within D-22, the routine stores halfword `0x002f` at twice an implicit incoming value. This occurs after the final capture in that phase and before its final duplicated delivery.

The doubling is represented through signed arithmetic. Overflow behavior is unresolved. No bounds, destination, or alignment validation is visible.

D-23 calculates the record address by subtracting `0x33` from another incoming value modulo \(2^{32}\), then logically shifting right by 24. The resulting address is between `0x00` and `0xff`.

F-2cc1255261f3 receives bits 28–31 of D-23’s unary result, yielding an argument from zero through fifteen. Record reads occur only after this dependency and all six D-24 invocations.

### Record reads and fixed-address writes

Four 32-bit record words are read in order at offsets 0, 4, 8, and 16. There is no represented read at offset 12.

All four reads precede these 32-bit stores:

| Order | Address | Value |
|---:|---|---|
| 1 | `0xc3` | Secondary result-register output from D-24’s final unary call |
| 2 | `0xc7` | Address `0xc3` |
| 3 | `0xcb` | Captured record word from offset 8 |
| 4 | `0xcf` | Captured record word from offset 16 |

The routine then reads the 32-bit cell at `0x08400240`, retaining its value as the destination base.

D-25 receives, in order:

1. The captured record word from offset 0.
2. The secondary output stored at `0xc3`.
3. Address `0xc3`.
4. The captured record word from offset 4.

A later change to `0x08400240` does not itself cause a destination-base reload.

### Control-slot initialization and threshold

After D-25 returns, the represented order is:

1. Read the 32-bit cell at `0x08400198`.
2. Write that word into the control slot.
3. Store D-25’s secondary 32-bit output at destination base plus `0x68`.
4. Evaluate the control slot’s then-current contents as an unsigned 32-bit threshold operand.

The threshold is not necessarily evaluated against the initially loaded word. The offset-`0x68` store can overlap the control slot; no non-aliasing guarantee is established.

If the threshold operand exceeds eight, execution reaches the first invalid-instruction boundary. D-26 and D-27 are not reached.

If that operand is at most eight, execution continues to D-26. This condition constrains the slot at the threshold use, not all subsequent contents of the slot.

### Continuing-path stores and terminal behavior

After the threshold permits continuation:

1. D-26 produces a 64-bit result. Its other effects are unknown, including whether it changes the control slot.
2. The routine uses the control slot’s then-current contents and stores their low byte at destination base plus `0x0f`.
3. After that byte store, the routine uses the control slot’s then-current contents again to calculate the halfword destination.
4. It stores a halfword at that destination.
5. It writes zero to the auxiliary slot.
6. It writes the previously captured record word from offset 16 to the saved-record slot.
7. D-27 receives the captured wide result’s low word, high word, and `0x74`.
8. Execution reaches the second invalid-instruction boundary.

The halfword destination is the control value used at step 3 plus `0x28`, with unsigned 32-bit addition modulo \(2^{32}\). Its value is the low 16 bits of the auxiliary-slot address plus `0x398`, reduced to 16 bits.

Neither later control-slot use is established to equal the threshold operand or the initial load. D-26 can interfere before the byte-value use. The byte store can itself overlap the control slot before the halfword-address use.

Consequently:

- The byte does not unconditionally equal the initially loaded control value.
- The halfword destination is not unconditionally restricted to `0x28`–`0x30`.
- Those properties hold only under suitable preservation conditions.
- Later stores may overlap local storage or earlier destinations; their represented order remains significant.

## Side effects

- Three selected byte reads.
- One incoming-value-derived halfword store.
- Four record-word reads.
- Four fixed low-address word stores.
- Two fixed-cell word reads.

There is no established non-aliasing relationship among record storage, fixed addresses, destination storage, local slots, or dependency-accessible memory.

## Acceptance examples

These are conditional static consequences, not executed tests. Each assumes the relevant operations are reached, required dependencies return, and accesses succeed.

1. **First high-word delivery.** With bit 28 set in the first captured high word, D-02 forwards the low word, makes an intervening call, delivers arguments one and one, makes another call, then delivers the single argument one.

2. **Independent bit sources.** A bit-24 source of `0x01000000` yields one; `0x00ffffff` yields zero. The other bit-24 phase uses its own capture.

3. **Signed byte selection.** D-06 selects address `0x10` for source zero and `0x11` for source `0xffffffff`. The delivered value is the byte read at that address, not the address itself.

4. **Unsigned subtraction.** D-14 high words six, seven, and `0xffffffff` yield one, zero, and one. Signed-overflow behavior in D-16 is not inferred from this example.

5. **Record layout.** Incoming record-address state `0x80000033` yields record address `0x80`. Reads occur at `0x80`, `0x84`, `0x88`, and `0x90`, before the fixed-address stores.

6. **Retained destination base.** If the base load yields `0x1000`, a change to its source cell by D-25 does not itself redirect the represented word store away from `0x1068`.

7. **Threshold nine with preservation.** If the initial control load is nine and the offset-`0x68` store leaves the control slot unchanged, the word store occurs and the threshold terminates execution before D-26.

8. **Threshold eight with preservation.** If the initial load is eight, the offset-`0x68` store preserves the slot, D-26 preserves it, and the subsequent byte store preserves it, continuation stores byte eight and selects halfword address `0x30`.

9. **Threshold changed by aliasing.** If the offset-`0x68` word store exactly overlaps the control slot and writes nine, the threshold observes nine even when the initial load was eight.

10. **Post-threshold interference.** Suppose the threshold observes eight, but D-26 changes the control slot to `0x100`. If the byte store leaves that slot unchanged, the byte value is zero and the halfword destination is `0x128`, not an address in `0x28`–`0x30`.

11. **Byte-store interference.** If the byte store changes the control slot’s contents to some word \(m\), the subsequent halfword destination uses \(m + 0x28\) modulo \(2^{32}\). The resulting \(m\) depends on overlap and byte order; neither is guessed.
