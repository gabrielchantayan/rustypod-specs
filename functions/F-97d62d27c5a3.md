# F-97d62d27c5a3

## Purpose

F-97d62d27c5a3 performs an ordered sequence of byte writes and indirect calls. On its ordinary path, it writes twice to an input-derived address, invokes two dependencies, performs two additional byte writes, and returns its original fifth input.

The representation also contains a reset-and-repeat transition and a terminal continuation. Both require a pointer formed from the current stack context to compare equal to null. That condition is inconsistent with the ordinary interpretation of a valid stack-location pointer. These paths are therefore documented_only: their represented behavior is specified, but their reachability is not established.

No application-level purpose is established. The available evidence does not support describing the function as allocation, initialization, copying, validation, or cleanup.

## Behavior

### Ordinary-path ordering

The caller-visible sequence below excludes effects performed inside dependencies.

**Initial writes.** The function computes an address from C plus the ambient offset. It writes the low eight bits of the ambient offset to that address twice consecutively. Both accesses have width one byte. No represented call or other explicit data-memory access separates them.

The representation contains two stores, not a single assignment. Whether they become two independently observable physical transactions is unknown.

**Stack pointer and call selection.** Before F-U01 is invoked, the function forms the stack-derived pointer at offset `0x2A8` and establishes a selector value of `0x0840347F` for the subsequent F-U02 call. Forming the pointer does not read the contents of the stack location.

F-U01 is selected by adding `0xFFE` to the current dispatch state. It receives A followed by B as its two explicit arguments. No return value from F-U01 is consumed.

**Explicit dispatch-state update.** After F-U01 returns, and before F-U02 is invoked, the represented dispatch state is assigned `0x08403481`.

This is an explicit transition, not an inferred dependency effect. It occurs even though the ordinary path will subsequently return. It also determines the represented call destination on a repeat iteration and the destination of F-U03 in the terminal continuation.

F-U02 is then invoked through the selector established before F-U01:

- Selector: `0x0840347F`.
- Added displacement: `0xFFE`.
- Represented destination: `0x0840447D`.

No explicit arguments are shown for F-U02. Its result is consumed as a signed 32-bit integer.

**Post-call writes.** The function shifts F-U02’s signed result right by four positions, adds the ambient offset, and uses the resulting value as an address. It writes one byte containing the low eight bits of the ambient base.

It then writes the ambient byte to the address formed from the ambient base plus `0x1D`.

For a nonnegative F-U02 result, the right shift has the usual division-by-16 effect with truncation toward zero. For a negative result, the supplied representation does not establish the signed-right-shift rule. Address arithmetic overflow and integer-to-pointer interpretation are separate unresolved issues.

**Return decision.** After both post-call writes, the function compares the stack-derived pointer with null. If it is non-null, the function returns E immediately. D does not influence this path, and neither F-U03 nor F-U04 is invoked.

### Null-pointer transition: documented_only

If the stack-derived pointer compares equal to null, D determines the next transition:

- D greater than `−34` enters the terminal continuation.
- D less than or equal to `−34` selects reset and repeat.

The reset changes the represented values in this order: ambient byte, ambient offset, ambient base, D, C, B, then A are set to zero. E is unchanged. The dispatch state is not reset; its explicitly assigned value remains `0x08403481` in the representation.

Consequently, the next F-U01 invocation on the represented repeat path selects:

`0x08403481 + 0xFFE = 0x0840447F`.

This destination differs from F-U02’s `0x0840447D`. The repeat call receives zero for both explicit arguments.

Before that call, the repeated initial stores both target address zero and both store zero. The stack-derived pointer is formed again. After F-U01 returns, the same dispatch-state assignment to `0x08403481` occurs again, followed by F-U02 at `0x0840447D` and the subsequent writes.

Under the reset values, the result-derived write stores zero at an address determined by F-U02’s shifted result, and the final ordinary-path write stores zero at address `0x1D`.

If execution reaches another null-pointer decision, D is now zero, so it selects the terminal continuation rather than another reset. If the pointer instead compares non-null, execution returns E.

Thus the representation permits at most one reset transition. This is not a termination guarantee: an access may fail, a dependency may not return, or execution may otherwise fail to reach the decision.

### Terminal continuation: documented_only

The terminal continuation is reached only after the null-pointer comparison and the D boundary select it.

Before its first dependency invocation, the representation establishes a selector value of `0x08403491` for the later F-U04 call.

F-U03 is selected using the dispatch state explicitly assigned after F-U01:

`0x08403481 + 0xFDC = 0x0840445D`.

No explicit arguments are shown. Its result is consumed as an unsigned 32-bit value.

After F-U03 returns, the function performs these ordered memory effects:

1. Read one unsigned byte from the address obtained by converting the stack-derived pointer to a signed 32-bit integer, multiplying that integer by `0x100`, and adding `0x1F`.
2. Zero-extend the read byte to a value between 0 and 255.
3. At that value plus `0x1E`, write one byte derived from the pointer’s converted integer value shifted left by five positions.
4. At that same zero-extended byte value plus `0x70`, write a 32-bit integer derived from the pointer’s converted integer value shifted left by two positions.

The byte read supplies both subsequent destination addresses. Those addresses are not based on F-U03’s result.

F-U04 is then invoked at the represented destination:

`0x08403491 + 0xEFE = 0x0840438F`.

Its three explicit arguments, in order, are:

- F-U03’s unsigned 32-bit result shifted left by four, retaining the low 32 bits.
- The value 8.
- The low 28 bits of F-U03’s result shifted left by three.

The third value is at most `0x7FFFFFF8`. No result from F-U04 is consumed. If it returns, the function returns E.

Under conventional null-pointer-to-integer conversion, entry to this continuation gives a converted pointer value of zero. Conditional on that interpretation:

- The read address is `0x1F`.
- Both pointer-derived stored values are zero.
- The byte-write address ranges from `0x1E` through `0x11D`.
- The 32-bit-write starting address ranges from `0x70` through `0x16F`.

These consequences do not establish that any low-address memory is accessible.

## Side effects

### Memory and ordering

The ordinary path has four explicit byte writes: two initial writes to the same destination, one result-derived write after F-U02, and one ambient-byte write afterward.

There are no explicit data-memory reads on that path. This statement excludes instruction fetching, call machinery, and dependency-internal accesses.

The terminal continuation adds one explicit byte read, one byte write, and one 32-bit write. F-U03 precedes all three; F-U04 follows all three.

All computed destinations may alias. Later caller writes can overwrite earlier caller writes. Dependencies may also access overlapping memory, so the sequence does not imply uninterrupted ownership of any destination.

The 32-bit store establishes an access width, not a byte order or unaligned-access guarantee.

### State and dependency boundaries

The dispatch-state assignment to `0x08403481` is part of the represented state transition. The reset changes the specified inputs and ambient values but leaves that dispatch state unchanged.

These facts must be distinguished from machine-level preservation rules. No dependency contract establishes which registers, globals, memory locations, or resources a dependency preserves. The representation supplies the values used by its later expressions; it does not independently prove that actual machine execution preserves every carrier needed to realize those expressions.

The function contains no explicit allocation, release, or ownership-transfer operation. Dependencies may perform such operations; their ownership behavior is unknown.

### Failure behavior

There is no represented error return, rollback, access check, exception handler, or recovery sequence. A failing access or call can occur after earlier effects have happened. No explicit operation reverses those effects.

No atomicity, synchronization, thread-safety, or device-memory guarantee is established.

### Ordinary writes and dispatch-state ordering

### Byte truncation and aliasing

If C is `0x1000`, the ambient offset is `0x123`, and the ambient base is `0x1106`, the initial destination and final ordinary-path destination are both `0x1123`.

Each initial write stores `0x23`. If the final write is reached, it writes the ambient byte at `0x1123` after the result-derived write, irrespective of the byte previously stored there.

### Reset boundary and repeated dispatch

Assume the stack-derived pointer compares null and all required operations remain possible.

With D equal to `−34`, the function resets the specified values and repeats. The repeated initial writes store zero at address zero. The next F-U01 destination is `0x0840447F`, with arguments zero and zero.

With D equal to `−33`, no reset occurs. Execution enters the terminal continuation directly, whose F-U03 destination is `0x0840445D`.

If the pointer is non-null, either D value instead returns E on the ordinary path.

### Negative result

If F-U02 returns `−16`, arithmetic right shift would produce `−1`, making the result-derived address the ambient offset minus one, provided the addition is representable. That destination is not an unconditional requirement because the signed-right-shift rule remains unresolved.

### Terminal read and argument widths

Assume the terminal continuation is reached, the null pointer converts to integer zero, the byte read at `0x1F` yields `0xFF`, and F-U03 returns `0xFFFFFFFF`.

The caller writes a zero byte at `0x11D`, then a zero 32-bit value starting at `0x16F`. F-U04 receives `0xFFFFFFF0`, 8, and `0x7FFFFFF8`, in that order. If it returns, the function returns E.
