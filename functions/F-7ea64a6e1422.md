# F-7ea64a6e1422

## Purpose

F-7ea64a6e1422 selects one of three referenced records using a discriminator in an input object, then returns a 32-bit value from the selected record. If the discriminator is not exactly 0, 1, or 2, it returns the 32-bit value zero without reading a record reference.

The established behavior is a conditional lookup. The meanings of the discriminator, the referenced records, and the returned field are not established. Describing the result as a status, identifier, address, or owned resource would require evidence not supplied here.

This contract describes the supplied static evidence. No runtime tests have been performed.

## Interface

### Input

The function takes one argument, used as the base address of an object. The supplied representation gives this argument a 32-bit integer type, but its observed role is address-bearing: the function reads fields at fixed byte offsets from it.

The relevant object layout is:

| Byte offset from input base | Width | Observed role |
|---|---:|---|
| 0x138 | 32 bits | Discriminator selecting a record reference |
| 0x140 | 32 bits | Record reference selected when the discriminator is 0 |
| 0x144 | 32 bits | Record reference selected when the discriminator is 1 |
| 0x148 | 32 bits | Record reference selected when the discriminator is 2 |

Each selected reference is used as the base address of another record:

| Byte offset from selected record base | Width | Observed role |
|---|---:|---|
| 0x44 | 32 bits | Returned value |

Offsets are measured in bytes. No interpretation is established for the intervening bytes, for fields preceding these offsets, or for any surrounding object structure.

### Output

The function returns one 32-bit value:

- For discriminator 0, 1, or 2, it returns the value read at offset 0x44 from the selected record.
- For every other discriminator value, it returns zero.

The result is opaque. Its width is established; its signedness and semantic type are not. In particular, zero can be either the unsupported-discriminator result or an actual field value from a selected record. The return value alone does not distinguish those cases.

### Preconditions

For defined, successful access along a selected path:

- The input base must permit a readable 32-bit access at offset 0x138.
- If the discriminator is supported, the corresponding reference field must permit a readable 32-bit access.
- That reference must identify an address permitting a readable 32-bit access at offset 0x44.
- Address formation and access must satisfy the executing environment’s mapping, alignment, and protection requirements.

The function contains no explicit validation of these conditions. Unsupported discriminators do not require any selected-record reference or record field to be readable.

The 32-bit address-bearing representation is part of the supplied evidence. This contract does not establish compatibility with a wider address space or an ABI using wider pointers.

## Behavior

### Selection and observable read order

The first data read is the 32-bit discriminator at input offset 0x138.

Exactly one of four paths follows:

| Discriminator | Next data read | Final data read | Normal return |
|---:|---|---|---|
| 0 | Reference at input offset 0x140 | 32-bit field at selected reference + 0x44 | Field value |
| 1 | Reference at input offset 0x144 | 32-bit field at selected reference + 0x44 | Field value |
| 2 | Reference at input offset 0x148 | 32-bit field at selected reference + 0x44 | Field value |
| Any other value | None | None | Zero |

Thus, a successful supported path performs three explicit data reads: discriminator, selected reference, and selected field. An unsupported path performs one explicit data read.

The function does not read all three references before choosing one. Unselected reference values do not affect the result and are not dereferenced by the supplied behavior.

These ordering statements concern explicit data accesses established by the supplied representation. They do not assert processor-level speculation, bus transactions, or memory-ordering guarantees.

### Discriminator boundaries

Only exact equality with 0, 1, or 2 selects a record. There is no range folding, masking, clamping, or default selection.

Consequently:

- A value of 3 returns zero.
- A value with every bit set returns zero.
- A bit pattern interpreted as a negative signed 32-bit value returns zero.
- High bits are not discarded to turn an otherwise unsupported value into a supported value.

The distinction between signed and unsigned interpretation does not change the selected cases: the only accepted discriminator bit patterns represent 0, 1, and 2 in either interpretation.

### Returned field

On a supported path, the function returns the selected 32-bit field without an explicit comparison, transformation, or additional dereference. A field value of zero remains zero; a field with its high bit set retains that bit.

The function does not return the selected record reference itself merely because that reference is address-bearing. It reads another 32-bit value at byte offset 0x44 from the selected record and returns that value.

### Address arithmetic

All field locations use fixed byte offsets. No data-dependent multiplication, index scaling, or variable-length traversal is present.

The supplied evidence does not establish behavior when adding an offset exceeds the applicable address range. It therefore does not justify a contract promising either wraparound access or checked arithmetic failure. Valid accessible effective addresses are a precondition for the normal-return cases described here.

### Failure behavior

There is no explicit error result for an unreadable input object, unreadable reference slot, or invalid selected record address. Such conditions may prevent normal completion according to the execution environment.

A zero selected reference is not checked or treated as an absent-record result. It is used in forming the field address at offset 0x44. Whether that access succeeds is environment-dependent; this contract does not equate it with a guaranteed fault or a guaranteed zero return.

## Side effects

The supplied body contains no explicit memory writes, allocation, deallocation, callbacks, or updates to global state.

The input object and selected record are accessed only for reading. No ownership transfer or release operation is expressed. The caller cannot infer ownership of either the selected record or the returned value from this function.

The absence of explicit writes is not a guarantee that every possible underlying read is free of external effects. If these addresses refer to device-backed or otherwise special memory, read effects depend on that environment, which is not described.

No synchronization is present. The function does not establish a coherent snapshot across its three supported-path reads. If another agent changes memory during execution, the discriminator determines which reference slot is subsequently accessed, but the reference and returned field are read later. Stronger guarantees about concurrent mutation, atomicity, or object lifetime are not established.

## Dependencies

No called functions are present in the supplied body. There are therefore no callee dependencies to identify by opaque function ID, and no callee ownership or global-preservation guarantees to assume.

Successful execution depends on:

- Readable memory at the addresses required by the chosen path.
- The executing environment’s 32-bit data representation and address interpretation.
- Sufficient object and record lifetime for the accesses performed.

Allocation, initialization, lifetime management, and synchronization are outside this function’s established responsibilities.

## Acceptance examples

These are conditional acceptance cases derived from static evidence, not reports of executed tests. Unless stated otherwise, required addresses are valid and memory remains stable during the call.

| Condition | Expected result and accesses |
|---|---|
| Discriminator is 0; the reference at 0x140 points to a record whose field at 0x44 is 0x12345678 | Returns 0x12345678. Reference slots at 0x144 and 0x148 are not read. |
| Discriminator is 1; the selected record’s field is 0x80000000 | Returns the 32-bit value 0x80000000 without clearing its high bit. |
| Discriminator is 2; the selected record’s field is zero | Returns zero after reading the selected reference and record field. |
| Discriminator is 3; all three reference slots contain unusable addresses | Returns zero without reading those slots or their referenced records. |
| Discriminator is 0xFFFFFFFF | Returns zero after the discriminator read; no record is selected. |
| Discriminator is 1; only the reference at 0x144 and its selected field are usable | The other reference slots impose no additional access requirement on this path. |
| Discriminator is 2; its selected reference is unreadable | No normal result is established. The function provides no explicit recovery path. |
| Discriminator is 0; the selected reference is zero | The function attempts the field access using that reference plus 0x44; it does not explicitly return zero because the reference is zero. |

If all three reference slots contain the same valid address, each supported discriminator selects the same final field location. This does not remove the discriminator read or the read of the individually selected reference slot.
