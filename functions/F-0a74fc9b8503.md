# F-0a74fc9b8503

## Purpose

F-0a74fc9b8503 conditionally dispatches an operation using a signed 32-bit selector and an opaque 32-bit value.

It explicitly handles two distinct sentinel conditions:

- An **input selector of −1** causes an immediate return of the 32-bit value 1, without dependency calls or dispatch lookup.
- For any other selector, an **initial dependency result whose low 32 bits are all set** selects a global fallback target.

When the dependency-result sentinel is absent, a second dependency supplies a value used both as a record base for target lookup and as the selected target’s first argument.

The apparent intent is selector resolution followed by record-specific dispatch, with a global fallback for a distinguished resolution result. That interpretation is inferred. The established contract concerns branch conditions, argument values, memory reads, call ordering, and result forwarding; no application-specific meaning is established.

## Interface

### Inputs

The function receives two inputs, in this order:

| Input | Represented width and interpretation | Use |
|---|---|---|
| Opaque value | 32 bits; no established signedness or domain type | Forwarded unchanged as the selected target’s second argument |
| Selector | Signed 32-bit integer | Compared with −1; otherwise passed to F-0bcf7b6ea1b3 |

The opaque value is not visibly dereferenced or interpreted. Its representation does not establish that it is a pointer, handle, status, owned reference, or borrowed reference.

The selector’s all-ones 32-bit representation denotes −1. No other selector receives an explicit input rejection or bypass.

### Result

The function produces a represented 32-bit result:

- Exactly 1 when the input selector is −1.
- Otherwise, the selected target’s result, forwarded without an explicit transformation, provided execution reaches a normal return.

Neither 1 nor any target result has an established success or failure meaning.

### Intermediate values and layout

F-0bcf7b6ea1b3 produces a represented 64-bit value. This function uses its two halves as follows:

- **Low word:** bits 0–31, interpreted as a 32-bit integer for the sentinel comparison and first argument to F-602d12a7c592.
- **High word:** bits 32–63, extracted by an unsigned right shift of 32 bits and then converted to the represented 32-bit argument type.

The low-word sentinel is the bit pattern `0xFFFFFFFF`. Its interpretation here is −1. The complete 64-bit value need not be all ones for fallback dispatch to occur.

F-602d12a7c592 returns a represented 32-bit integer. This value supplies:

1. The base for a target read at a displacement of 8 bytes.
2. The first argument to the selected target.

The access supports interpreting the returned value as a record base, but does not establish the complete record type. No field other than the target slot at byte offset 8 is visibly accessed.

### Preconditions for normal completion

The immediate-return path does not require either dependency or either dispatch source to be usable.

For any other path, normal completion requires every reached call and memory read to be valid:

- F-0bcf7b6ea1b3 must accept the non-sentinel selector.
- On fallback, the global dispatch source must support the required target lookup.
- On record dispatch, F-602d12a7c592 must accept the two supplied words, and its result must support the target read at byte offset 8.
- The selected target must support the represented two-argument invocation and result.
- Applicable storage lifetime, address validity, alignment, and execution-context requirements must hold.

The function does not visibly validate these conditions. They are path-dependent preconditions, not guarantees supplied by the wrapper.

## Behavior

### Input sentinel

The selector comparison precedes every visible dependency call and dispatch lookup.

When the selector is −1, the function returns 1 immediately. On this path:

- F-0bcf7b6ea1b3 is not called.
- F-602d12a7c592 is not called.
- Neither dispatch source is read.
- No target is invoked.
- The opaque value has no effect on the result and is not forwarded.

This is explicit handling of an **input sentinel**, separate from the later dependency-result sentinel.

### Initial resolution

For every selector other than −1, F-0bcf7b6ea1b3 is called once with the original selector.

After that call returns, the function compares only the low 32 bits of its result with the 32-bit representation of −1. The high word does not participate in branch selection.

Thus, each of the following low/high combinations selects fallback:

- Low `0xFFFFFFFF`, high `0x00000000`.
- Low `0xFFFFFFFF`, high `0x12345678`.
- Low `0xFFFFFFFF`, high `0xFFFFFFFF`.

Conversely, a high word of `0xFFFFFFFF` does not select fallback when the low word differs from `0xFFFFFFFF`.

### Global fallback dispatch

If the low-word comparison matches the dependency-result sentinel:

1. F-602d12a7c592 is skipped.
2. The callable target is obtained through the global fallback dispatch source.
3. The target is invoked with the original selector first and the original opaque value second.

The original selector is necessarily different from −1 on this path. A sentinel in the dependency result does not replace the target’s first argument with −1.

The fallback target lookup occurs after F-0bcf7b6ea1b3 returns. Consequently, the contract does not assume that the fallback source retains its pre-call contents. If that dependency changes the relevant state, the subsequent lookup can observe the changed state.

The representation shows a dereferenced global-associated source for the fallback target. It does not establish the complete storage layout, initialization protocol, or independent validity rules for that source.

### Resolved-record dispatch

If the low word is not `0xFFFFFFFF`, F-602d12a7c592 is called with:

1. The low 32-bit word.
2. The high 32-bit word.

The high word comes from the upper half of the returned 64-bit pattern, not from sign-extending the low word. A set top bit in the high word does not trigger a separate branch or rejection.

After F-602d12a7c592 returns, its result replaces the selector-derived working value. The function then reads the target at that returned base plus 8 bytes.

The selected target receives:

1. The returned record-base value.
2. The original opaque value.

Neither the original selector nor either individual word from initial resolution is independently forwarded as the target’s first argument on this path.

The displacement is 8 bytes, not eight record elements. The representation uses a 32-bit integer value in forming the target address. It does not establish safe behavior for signed overflow, address wraparound, or out-of-range storage. A valid execution must satisfy the required address calculation and read without relying on an undocumented arithmetic policy.

There is no visible check of a record length, type tag, null value, or target validity before invocation.

### Completion

Both dispatch branches invoke one selected target with two arguments. If that invocation returns normally, its represented 32-bit result becomes the function result unchanged.

No result interpretation, retry, second target selection, explicit cleanup, or post-dispatch state update appears.

The supplied representation models the indirect transfer as an invocation followed by result forwarding. It does not independently establish the machine-level transfer form, register convention, stack layout, or whether the underlying transfer is implemented as a conventional call.

## Side effects

### Observable order

| Path | Ordered visible operations |
|---|---|
| Input selector is −1 | Return 1 |
| Dependency-result sentinel | Call F-0bcf7b6ea1b3; read fallback dispatch source; invoke selected target; return target result |
| Other dependency result | Call F-0bcf7b6ea1b3; call F-602d12a7c592; read target at returned base plus 8 bytes; invoke selected target; return target result |

The two named dependencies are not interchangeable. F-602d12a7c592 is reached only after initial resolution returns a non-sentinel low word.

These ordering constraints matter when calls modify dispatch storage, publish record contents, invalidate memory, or otherwise change observable state. Neither dependency is assumed to preserve globals.

- No synchronization, atomicity, or concurrency guarantee is established.

The function does not visibly allocate, copy an object, retain, release, or free storage. Its dependencies and target must not be assumed to share those properties.

### Errors and exceptional outcomes

Two explicit sentinel cases must be distinguished:

- **Input sentinel:** selector −1 causes immediate return of 1.
- **Dependency-result sentinel:** a low word of `0xFFFFFFFF` from F-0bcf7b6ea1b3 selects fallback dispatch.

The latter is the **only dependency-result sentinel explicitly handled**. It does not itself cause an immediate error return.

There is no visible handling for:

- An unusable result from F-602d12a7c592.
- An invalid fallback source or selected target.
- An invalid target slot at record offset 8.
- Other dependency-specific error encodings.
- A target result that might signify failure in some external contract.

An invalid record result does not visibly trigger fallback. If a call fails to return normally or a required access is invalid, no recovery mechanism is shown. The precise resulting behavior is not established.

## Acceptance examples

These are conditional acceptance examples derived from the static representation. They are not executed tests.

1. **Input sentinel bypasses all dispatch.**  
   Given selector −1 and any opaque value, the result is exactly 1. Neither named dependency is called, neither dispatch source is read, and no selected target is invoked.

2. **Dependency-result sentinel preserves the original selector.**  
   Given selector 7, suppose F-0bcf7b6ea1b3 returns low word `0xFFFFFFFF`. F-602d12a7c592 is skipped. The fallback target receives 7 first and the original opaque value second. If it returns 23 normally, the function returns 23.

3. **Fallback is independent of the high word.**  
   For the same non-sentinel selector, dependency results with low word `0xFFFFFFFF` select fallback whether their high word is zero, `0x12345678`, or all ones. This establishes the same branch, not necessarily the same target or result if dependency side effects differ.

4. **Upper all-ones bits do not independently select fallback.**  
   Suppose initial resolution returns low word `0x00000005` and high word `0xFFFFFFFF`. F-602d12a7c592 receives those two 32-bit word patterns in that order. The function takes the record-dispatch path.

5. **The resolved value replaces the selector for invocation.**  
   Suppose F-602d12a7c592 returns a valid record base. The target is read at that base plus 8 bytes and receives that base as its first argument, not the original selector.

6. **Fallback lookup follows dependency effects.**  
   Suppose F-0bcf7b6ea1b3 changes fallback dispatch storage and returns the low-word sentinel. The subsequent target lookup uses the state available after that call. Substituting a target cached beforehand requires an additional preservation guarantee not supplied here.

7. **An invalid record result has no documented recovery.**  
   Suppose initial resolution selects record dispatch, but the returned base cannot support the target read. The function does not visibly switch to fallback or return a fixed error. Normal completion is outside the established preconditions.

8. **Target results are not resolution sentinels.**  
   If a valid selected target returns `0xFFFFFFFF`, that result is forwarded unchanged. It does not trigger another fallback decision.
