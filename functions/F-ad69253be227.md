# F-ad69253be227

## Purpose

The supplied static representation describes an ordered sequence of indirect calls, byte and word memory accesses, and transformations of 32-bit values. It does not establish an application-level purpose.

Recurring operations publish the low byte of a word at offset `0x74` to offset `1`, use byte values to select absolute addresses, and update fields at offsets including `0x0D`, `0x14`, `0x24`, and `0x34`. These observations do not establish an object model, protocol, allocator, or device interface.

Invalid-instruction warnings bound the evidence. This contract describes the represented execution prefix, conditional on execution reaching each operation and preceding calls returning. It does not establish that the function boundary is correct, that every represented operation is executable, or that execution returns normally.

### Widths and layouts

Offsets are byte offsets. A word read at base plus `0x74`, for example, is a 32-bit access, not a byte read from that location. Publishing its low byte is a numeric truncation; the representation does not establish memory endianness.

For conditional arithmetic examples, multiplication and left shifts retain the low 32 bits. This models the apparent target-width operations, not portable signed-language semantics. Actual overflow, signed left-shift behavior, and address wrapping remain documented_only pending instruction-level confirmation.

Names such as “record base,” “payload word,” and “selector” describe value use, not established types, allocation boundaries, or ownership.

## Behavior

The phases below preserve the order of represented accesses and calls. A retained value is reused from an earlier computation; a reread is a new memory access. Dependencies are not assumed to preserve global memory or referenced storage.

### 1. Initial publication and argument forwarding

The initial arithmetic input is doubled. Before the first call, a word is read at the initial base plus `0x74`; its low byte is written at the initial base plus `1`.

F-100001 receives the doubled input, the second explicit argument unchanged, and the initial arithmetic input logically shifted right by two.

A dependency then supplies a displayed 64-bit result. The following dependency receives its low half, high half, low half again, and the initial arithmetic input masked with `0x7FFFFFFF` and shifted right by one.

Three calls without displayed explicit arguments precede a result-producing call. Four times that result becomes a base. A word at that base plus `0x74` is read, its low byte is written at the base plus `1`, and the base is passed onward.

### 2. Two reads of the initial selector location

After four more calls, a byte is read at the doubled initial input plus `1`. Its unsigned value plus `0x11` selects an absolute byte address, which receives zero.

A dependency receives an unestablished secondary-register word. The next dependency returns a word that is retained as a descriptor-container base and passed onward.

Three calls and a result-producing call follow. The byte at the doubled initial input plus `1` is read again. Its selected absolute address receives the top byte of the doubled initial input. Four times the latest result is passed onward.

The two selector reads are distinct: dependencies may change the selector or its containing storage between them.

### 3. Descriptor selection and payload capture

After three calls and a result-producing call, four times the result becomes a working base.

A word is read at the descriptor-container base plus `4`. This descriptor word supplies the address for a byte read at descriptor plus `1`; the byte selects an absolute address by addition of `0x11`, and zero is written there.

The working base is passed three times to one dependency. After three calls and a result-producing call, the retained descriptor word is logically shifted right by two. A byte read at that shifted address plus `1` becomes a retained small base. Zero is written at small base plus `0x11`. Four times the latest result is passed onward.

After three calls and another result-producing call, these accesses occur in order:

1. Read a packed word at working base plus `4`.
2. Read a payload word at small base plus `0x74`.
3. Write the payload word’s low byte at small base plus `1`.

The next dependency receives the payload word, two copies of the working base shifted left by 19, and four times the latest result.

### 4. Packed-field transformations

A dependency result is passed onward with the payload word logically shifted right by two. The packed word shifted right by 22 supplies a retained ten-bit field.

After three calls and a result-producing call, four times the result becomes a publication base. A word is read at publication base plus `0x74`, retained, and truncated into a byte store at publication base plus `1`. The publication base is passed onward.

After four calls, the retained word is stored at four times an unestablished secondary-register value plus `0x14`. That secondary-register value is then passed onward.

A subsequent result is passed to a dependency with two identical arguments: the retained ten-bit field masked with `0x1FF`, then shifted left by 21.

After three calls and a result-producing call, the ten-bit field shifted left by 23 is stored at four times the result plus `0x14`. Four times the result is passed onward.

The two field transformations differ. The duplicated arguments explicitly exclude the tenth retained bit; the word-store transformation instead loses high bits through the assumed 32-bit result width.

### 5. Separate saved scale, retained index, and field base

After three calls and a result-producing call, the returned word supplies an initial index.

Four times this initial index is retained as the **saved scaled value** and stored at sixteen times the initial index plus `0x14`. The initial index is then masked with `0x3FFFFFFF`; the masked value is passed onward, and its logical right shift by two is separately retained as the quarter-masked quantity.

After three calls and another result-producing call, the masked value is stored at four times the new result plus `0x14`.

**This new result is retained unchanged as the retained index.** Four times the retained index is only the argument passed to the next dependency. That scaled argument does not replace the retained index.

After three calls and a result-producing call:

- Eight times the retained, unscaled index becomes the field base.
- The field base’s low byte is written at the earlier payload word plus `1`.
- Four times the latest result is stored at field base plus `0x34`.
- That four-times result is passed onward.

A following dependency supplies another result. The preceding unscaled result—the one whose four-times value was just stored—is masked with `0x3FFFFFFF` and retained as the record base. The newly supplied result is passed onward.

After three calls and a displayed 64-bit result, the field base’s low byte is written at record base plus `1`. The wide result’s high half is then stored at field base plus `0x34`, and four times its low half is passed onward.

Thus, both stores at field base plus `0x34` use eight times the retained index as their base. The second may overwrite the first; intervening calls and both writes remain observable.

### 6. Expanded-base and record updates

After three calls and a result-producing call, sixteen times the same **unscaled retained index** becomes the expanded base. It is not sixteen times the earlier four-times call argument.

Two byte stores occur in order:

1. Store the expanded base’s low byte at record base logically shifted right by 20, plus `0x11`.
2. Store the saved scaled value’s low byte at expanded base plus `0x0D`.

Four times the latest result is passed twice to a dependency. A subsequent result is passed onward unchanged and logically shifted right by three.

After three calls and a result-producing call, the expanded base’s low byte is written to absolute address `0x11`. The saved scaled value’s low byte is again written at expanded base plus `0x0D`. Four times the latest result is passed onward.

After three calls and another result-producing call, the saved scaled value is stored as a word at record base plus `0x14`. The low byte of twice the record base is then written at record base plus `0x0D`.

The saved scaled value and retained index have different origins. The former comes from the first result in phase 5; the latter is the subsequent, unscaled result used to address the masked-value store.

### 7. New record and selector transitions

The latest result supplies three retained quantities:

- A new base equal to 32 times the result.
- A word value equal to the result shifted left by seven.
- A compact selector equal to the result masked with `0x07FFFFFF`, then logically shifted right by 17.

After two calls and a result-producing call, the word value is stored at new base plus `0x14`. The low byte of four times the latest result is written at new base plus `0x0D`; that four-times result is passed onward.

After four calls, the low byte of twice the quarter-masked quantity from phase 5 is written at compact selector plus `7`. A byte is then read at new base plus `1`; the compact selector’s low byte is written at the selected absolute address plus `0x11`.

The result used for the new-base byte store, shifted left by 21, is passed three times to a dependency. A subsequent result is retained as the full retained payload result and passed onward unchanged.

After three calls and a result-producing call, the byte at new base plus `1` is reread and retained as the saved selector. Zero is written at saved selector plus `0x11`. Four times the latest result is passed onward.

After four calls, the low byte of the full retained payload result logically shifted right by three is written at new base plus `0x0D`. This truncated byte is also retained for later reuse.

### 8. Absolute-byte and linked-word updates

Twice the saved selector becomes a small scaled base. The saved selector is written at absolute address `0x0D`.

A dependency receives the small scaled base, `0x98`, and `0x260`. After another call, a dependency receives an unestablished unsigned secondary-register value logically shifted right by three.

After three calls and a result-producing call, four times the result is passed to a dependency that itself returns a word. The retained truncated byte from phase 7 is written at small scaled base plus `0x0D`; absolute address `0x0D` is then written with `0xC0`. Four times the newly returned word is passed onward.

After three calls and another result-producing call:

1. Four times the result is stored at small scaled base plus `0x24`.
2. A word at small scaled base plus `0x74` is read and retained as the linked base.
3. The result shifted left by five becomes a saved word.

A dependency receives the linked base, twice the linked base, the saved word, and the linked base masked with `0x7FFFFFFF` then logically shifted right by two.

After four calls, the saved word is stored at linked base plus `0x24`. A word is subsequently read at linked base plus `0x74` and passed onward.

### 9. Wide results and final selector updates

After three calls and a displayed 64-bit result, four times its low half becomes a saved scaled word. The full retained payload result from phase 7, logically shifted right by three, is stored at four times the high half plus `0x14`.

A dependency receives three copies of the saved scaled word followed by the high half logically shifted right by three. The next displayed 64-bit result is passed onward as low half, high half, low half again, and high half logically shifted right by three.

After three calls and a result-producing call, the saved scaled word is stored at four times the result plus `0x14`; that scaled result is passed onward.

After three calls and another result-producing call, four times the result becomes the final scaled value. A byte at linked base plus `1` is read; its selected absolute address plus `0x11` receives the final scaled value’s low byte.

After two calls and a result-producing call, the selector at linked base plus `1` is reread. Its selected address receives the low byte of the preceding unscaled result masked with `0x3FFFFFFF` and shifted right by 20. Four times the latest result is passed onward.

After three calls and a result-producing call, a byte is read at final scaled value multiplied by `0x400`, plus `1`. Zero is written at its selected absolute address plus `0x11`.

A dependency receives two copies of the final scaled value shifted left by three, the final scaled value unchanged, and four times the latest result. After three calls and another result-producing call, the same selector location is reread and its selected address is cleared again.

Four times the latest result is passed onward. Four final calls precede the invalid-instruction boundary.

## Side effects

Explicit stores are either one byte or one 32-bit word. No explicit allocation, release, lock, or wider store is established.

Absolute addresses matter:

- `0x0D` and `0x11` receive byte writes.
- A byte selector plus `0x11` selects the inclusive range `0x11`–`0x110`, without byte-width wrapping of the addition.
- Byte-derived and compact-field-derived bases produce additional low-address accesses.

Aliasing may expose intermediate values. For example, a zero saved selector makes small scaled base plus `0x0D` coincide with absolute `0x0D`. Matching address expressions do not justify eliminating repeated accesses: calls intervene, selectors are reread, and memory may change.

No ownership transfer, borrowing duration, retention rule, or release obligation is established. Unknown dependencies may modify globals, invalidate storage, or terminate execution. No rollback or represented recovery protects prior side effects if a later access or call fails.

## Acceptance examples

These are conditional static criteria, not executed tests. Unless stated otherwise, arithmetic uses the 32-bit interpretation described above.

1. **Initial publication.** A word `0x123456AB` at initial base plus `0x74` produces byte `0xAB` at initial base plus `1` before the first call.

2. **Distinct initial transforms.** Arithmetic input `0x80000005` produces doubled value `0x0000000A`, logical quarter `0x20000001`, and masked half `2`.

3. **Selector range and rereads.** Selector `0xFF` selects `0x110`. If intervening calls change a selector from `3` to `9`, successive selected addresses are `0x14` and `0x1A`; retaining the first selector is incorrect.

4. **Packed-field boundary.** Packed word `0xFFFFFFFF` yields ten-bit field `0x3FF`. Masking with `0x1FF` and shifting left by 21 yields `0x3FE00000`; the separate left shift by 23 yields `0xFF800000`.

5. **Unscaled retained index.** If the result used to address the masked-value store is `3`, that store targets `0x20`, and the onward argument is `0x0C`. The retained index remains `3`: field base is `0x18`, expanded base is `0x30`, and field base plus `0x34` is `0x4C`. Bases `0x60` and `0xC0` incorrectly reuse the scaled argument.

6. **Dependent byte and word stores.** Under the preceding index example, both field-base byte publications carry `0x18`; the expanded-base publication carries `0x30`; and repeated saved-scaled-value byte stores target `0x3D`. Both paired word updates target `0x4C`, first receiving four times the later result and then the wide result’s high half.

7. **Independent saved scale.** If phase 5’s initial index is `5`, the saved scaled value is `0x14`, initially stored at `0x64`. A later retained index of `3` changes field and expanded bases, not that saved value.

8. **Absolute precedence and full-width reuse.** Phase 8 writes the saved selector to absolute `0x0D` before its later explicit `0xC0` write. Phase 9’s shifted payload word uses the full retained payload result, not the byte truncated from it.

9. **Inaccessible addresses.** Successful completion is not required when a represented access is inaccessible. No represented check or recovery makes low-address accesses safe.
