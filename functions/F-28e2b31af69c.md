# F-28e2b31af69c

## Purpose

F-28e2b31af69c retrieves one raw 16-bit value from an address calculated using two 32-bit fields in a caller-supplied structure and a caller-supplied index.

The established behavior is an indirect memory read. The function does not establish the meaning of the returned bits, the extent of the referenced storage, or whether the index denotes an element in a valid collection.

An inferred interpretation is that the two structure fields jointly locate a sequence of two-byte elements. That interpretation is not required by the observed address calculation: either field could instead be an address component or displacement.

## Interface

### Inputs

The function has two inputs:

- **Structure address:** an address-valued input locating a readable structure. The supplied representation uses a 32-bit input for this address.
- **Index:** a 32-bit integer input used to select a position at a stride of two bytes. Negative values are not explicitly rejected.

The structure has two relevant fields:

| Offset from structure address | Read width | Established role |
| --- | --- | --- |
| 88 bytes, hexadecimal 0x58 | 32 bits | First component of the target address |
| 96 bytes, hexadecimal 0x60 | 32 bits | Second component of the target address |

The fields are eight bytes apart. The supplied evidence does not show a read of the intervening four bytes or of any other structure member.

For terminology in this contract, the **target address** is the sum of the two field values and twice the index. This describes the address relationship; it does not independently settle overflow behavior, pointer validity, or the semantic type of either field.

### Output

The result is exactly 16 bits, obtained from the target address.

The evidence does not establish a signed or unsigned numerical interpretation. A result with its high bit set remains a valid raw 16-bit result; it is not, on that basis alone, an error indication.

No separate success flag, error code, output pointer, or length result is present. Behavior introduced by a caller when widening or interpreting the returned value is outside this function’s established contract.

## Behavior

### Address calculation

- Increasing the index by one advances the target address by two bytes.
- An index of zero contributes no displacement.
- A negative index moves the target address backward relative to the sum of the two fields.

These relationships do not imply that any resulting address is valid. There is no visible lower-bound check, upper-bound check, element count, or range metadata.

The representation uses 32-bit integer inputs and 32-bit field reads. It does not establish a wider intermediate calculation. In particular, this contract does not promise that large products or sums are evaluated in an unbounded or 64-bit domain.
