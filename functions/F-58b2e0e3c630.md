# F-58b2e0e3c630

## Purpose

F-58b2e0e3c630 selects an address-bearing slot associated with a supplied base address and, when that slot is nonzero, returns a four-byte value from the referenced storage.

The selector accepts four positions, numbered zero through three. An out-of-range selector produces zero without reading the base-associated storage. An accepted selector whose slot contains zero also produces zero. Otherwise, the function reads four bytes at displacement eight from the address obtained from the slot and returns those bits.

This is an indirect lookup, not a validation operation. The visible body does not establish that either reached address is accessible, properly aligned, or associated with a live object.

**Inferred intent:** the base may identify a containing structure with four references, and the returned value may be a field of the selected referenced object. Neither the structure’s identity nor the field’s application-level meaning is established.

## Interface

### Inputs

The function receives two integer-valued inputs:

- **Base address:** presented as a signed integer and used in address formation.
- **Selector:** presented as an unsigned integer. Only values less than four reach a memory read.

The supplied representation is consistent with a 32-bit integer and address model. Address-bearing slots have a four-byte stride, and their contents are read as integers before being used as addresses. The returned quantity is explicitly four bytes.

The exact ABI, address width, and integer representation are not independently established. Layout descriptions below use the apparent 32-bit model; they do not assert that the same representation is valid on other targets.

### Output

The result is a four-byte value:

| Condition | Result |
|---|---|
| Selector is outside zero through three | Zero |
| Selected slot contains zero | Zero |
| Selected slot contains a nonzero address | Four-byte value read at that address plus eight |

The returned bits have no established signedness or application-level interpretation. In particular, the final field may itself contain zero. The result alone therefore cannot distinguish an invalid selector, a zero slot, and a successfully read zero-valued field.

### Storage layout

For accepted selectors, the selected slot begins at the base plus the following byte displacement:

| Selector | Hexadecimal displacement | Decimal displacement |

| 0 | 0xF7C | 3964 |
| 1 | 0xF80 | 3968 |

Under the apparent four-byte slot model, the last slot occupies base-relative bytes 3976 through 3979.

A nonzero slot supplies the address for a second access. That access reads bytes eight through eleven relative to the stored address. The function does not inspect the preceding eight bytes.

## Behavior

### Selector gate

The selector is compared as an unsigned value against four before any slot access.

For every selector of four or greater, the function returns zero. Neither the base-associated storage nor any referenced field is read on this path. An invalid or zero base therefore does not prevent this path from returning zero in the represented computation.

There is no accepted negative selector at this interface. If an external caller converts a negative value into the unsigned input representation, the resulting unsigned value controls the comparison. Under a 32-bit unsigned conversion, negative one becomes 4,294,967,295 and takes the no-read, zero-return path.

### Selected-slot read

For a selector from zero through three, the slot address is formed from the base, the fixed displacement of 3964 bytes, and four bytes per selector position.

The function then reads the selected slot. It does not first test the base for zero or inspect any neighboring slot. No explicit accessibility, alignment, bounds, or lifetime check appears.

If the slot value is zero, the function returns zero without attempting the referenced-field read.

The zero check applies to the slot’s contents, not to the base or the computed slot address. Consequently, a zero base with an accepted selector is not an automatic zero-return case: it still leads to a slot access at the corresponding numerical displacement.

### Referenced-field read

If the selected slot contains a nonzero value, that value is used as an address. The function reads four bytes beginning eight bytes beyond it and returns the resulting bits.

There is no additional validity check. A nonzero stored address whose field is inaccessible still reaches the final read; it does not take the zero-slot shortcut.

The represented order of memory operations is:

1. Check the selector.
2. Read the selected slot, only if the selector is accepted.
3. Read the referenced field, only if the slot was nonzero.
4. Return the field value or the applicable zero result.

The supplied body contains one selected-slot read and, conditionally, one referenced-field read. It does not re-read the slot before forming the second address.

This order describes the represented control flow and data dependency. It does not establish hardware atomicity, synchronization, or a cross-thread consistency guarantee.

### Arithmetic and normal-operation preconditions

Within the accepted selector range, the selector-dependent displacement is zero, four, eight, or twelve bytes. Adding the fixed displacement yields exactly the four slot offsets listed above. The selector contribution therefore introduces no large intermediate value on a reached lookup path.

The remaining address calculations involve the supplied base and, conditionally, the nonzero value read from the slot. Their behavior near integer or address-representation limits is not established as a portable contract. In particular, wrapping to a low address must not be treated as a supported feature.

The base is presented as signed while the selector is unsigned. Exact arithmetic conversions depend on the target’s integer model. The later addition of eight uses the integer-valued slot contents. The supplied material does not justify treating every boundary case as uniform modular pointer arithmetic.

For an ordinary, defined lookup, the caller must arrange that:

An out-of-range selector does not require readable slot storage. A zero slot does not require valid referenced storage. These are consequences of the conditional accesses, not general validation guarantees.
