## Behavior

### 1. Prepare the fallback representation

The function first reads A, B, and C, in that order, into three consecutive local 32-bit words.

It then applies a logical right shift by one bit to each word. The processing order is reverse address order:

1. The word initialized from C.
2. The word initialized from B.
3. The word initialized from A.

Each operation independently discards that word’s least significant bit and inserts a zero at bit 31. There is no carry or bit transfer between adjacent words. This is three separate 32-bit shifts, not a shift of a combined 96-bit quantity.

Let the three shifted words be A′, B′, and C′. Each is an unsigned 32-bit value between zero and 0x7FFFFFFF.

The function later replaces the least significant 16 bits of C′ with the zero-extended value of C′’s least significant byte. The resulting third word therefore has:

- Bits 0–7 unchanged from C′.
- Bits 8–15 cleared.
- Bits 16–31 unchanged from C′.

This modification does not clear the entire word or its upper half.

The resulting fallback representation occupies three consecutive 32-bit words, totaling 12 bytes. It is prepared before the first dependency invocation, although it is used only if that invocation returns zero.

On a little-endian interpretation, the representation has the following layout:

| Byte offset | Contents |
|---|---|
| 0–3 | A′ |
| 4–7 | B′ |
| 8 | Least significant byte of C′ |
| 9 | Zero |
| 10–11 | Upper two bytes of C′ |

This byte layout is conditional on little-endian storage. The word-level transformation is the established behavior independent of that presentation. The presence of a zero byte does not establish that the dependency treats the representation as text.

### 2. Prepare the primary representation

After the initial shifts of the fallback representation, the function rereads A and B into a separate local region. It does not reuse their earlier captured values.

The shown ordering is:

1. Read A again.
2. Read B again.
3. Apply the fallback representation’s 16-bit replacement described above.
4. Read D.
5. Read E.

The primary region now contains four consecutive 32-bit words initialized from the later reads of A and B, followed by D and E.

The function logically shifts each of these words right by one bit, again in reverse address order:

1. The word initialized from E.
2. The word initialized from D.
3. The word initialized from the later B read.
4. The word initialized from the later A read.

It then writes a zero byte immediately after the four-word region.

The primary representation therefore contains 16 bytes of transformed word data followed by one explicitly initialized zero byte at offset 16. The function does not establish that bytes beyond this terminator are initialized or available for dependency access.

On a little-endian interpretation:

| Byte offset | Contents |
|---|---|
| 0–3 | Later A value, logically shifted right by one |
| 4–7 | Later B value, logically shifted right by one |
| 8–11 | D, logically shifted right by one |
| 12–15 | E, logically shifted right by one |
| 16 | Zero |

The terminator byte is separate from the shifted words. It remains zero regardless of the values produced by those shifts.
