# F-242037fff874

## Purpose

F-242037fff874 describes an ordered sequence of memory accesses, six call sites, conditional branches, and abnormal termination boundaries. The supplied representation does not establish a coherent application-level purpose or a successful-return path.

This contract specifies a **conditional observable trace**: each operation is required only if execution reaches it and preceding accesses and calls complete. It does not claim that the addressed memory exists, that the procedure constructs a valid object, or that any displayed path is executable on a particular processor.

Three evidence classes apply:

- **Established static evidence:** explicit access widths, value calculations, call arguments, ordering, and branches in the supplied representation.
- **Inferred intent:** interpretations such as initialization or descriptor construction. These are not acceptance requirements.
- **documented_only:** unresolved declarations, bindings, runtime behavior, and environmental requirements.

No runtime tests have been performed.

### Widths and storage layout

The representation uses 8-bit bytes, 16-bit halfwords, 32-bit words and addresses, and represented 64-bit call results. Explicitly typed pointer accesses establish their access widths. Pointer-indexed offsets below are expressed in bytes.

Arithmetic-derived addresses are described using their low 32 bits. This is a model of the displayed operations, not a claim that signed overflow or large shifts have portable language semantics. Endianness and alignment requirements are unknown.

**Symbolic global accesses require a separate qualification.** Their declarations are absent. A 16-bit conversion, a concatenation operand, or a 32-bit consuming expression establishes a value width, not necessarily the width of the underlying symbolic memory access. In particular:

- Assignments to `_Reset`, `_SUB_00000006`, `UndefinedInstruction`, and `Reset_1` do not establish halfword, word, or byte stores.
- `_FIQ` and `_DataAbort` have unresolved declarations and access widths.
- Direct symbolic accesses below retain this qualification even where a nominal location or a 32-bit value is specified.

Repeated accesses remain distinct. Neither equal values nor a fixed relative order within one expression is assumed unless the representation establishes them.

## Behavior

### 1. Initial branch

The procedure tests the lower 30 bits of the control word.

If any are set, it performs, in order:

1. A 16-bit store of the fourth input at the object address.
2. A 16-bit store of the object address’s low 16 bits at the same destination.
3. A 32-bit store of the complete control word at secondary base plus `0x1c`.
4. An invalid-instruction boundary.

The first store is observable even though the second overwrites it.

If all lower 30 bits are zero, the main path follows. The two highest bits alone do not select the early branch.

### 2. Main-path prefix and first call

The main path performs:

1. An 8-bit store of the third input at object address plus `0x80`.
2. A 16-bit store of the saved halfword at object address plus `0x0e`.
3. The same 8-bit store again at object address plus `0x80`.
4. A symbolic assignment to `_Reset` of the control word converted to 16 bits.
5. A symbolic assignment of the saved halfword to the global nominally at `0x00000088`.
6. A call to **F-000000000001**, passing the record address.

The value assigned to `_Reset` is zero because the main-path predicate excludes every set bit in the control word’s low halfword. This does **not** establish a 16-bit write at address zero: the global’s declaration and exact location are not supplied.

The call target is incoming link-derived state plus `0x800`. Its represented result is 64 bits; subsequent references distinguish its low and high 32-bit halves.

After the call returns, the procedure reads the global at **`0x0897fe70`**, consuming a signed 32-bit value. Call this the **post-call base value**. The read is after the call, not an entry-time snapshot.

### 3. Derived destinations and zero-scaled branch

The procedure next performs these ordered operations:

1. A 16-bit store to the address equal to bits 20–31 of the first result’s low word. The stored value is that same 12-bit quantity.
2. An 8-bit store of the record address’s low byte at record address plus `7`.
3. A read of the global nominally at **`0xa6000030`**. Adding `0x60` produces the **byte address**.
4. An 8-bit store of the byte address’s low byte to the byte address itself.
5. Formation of the **word address** by logically shifting the byte address right by two.
6. An 8-bit zero store at the post-call base value plus the byte address multiplied by `0x10000`.
7. Formation of the **scaled address** by multiplying the byte address by `0x200000`.
8. A 32-bit store of the scaled address to the scaled address itself.

The test for a zero scaled address occurs **after** the self-store.

If the scaled address is zero, the procedure reads the global at **`0x0897fea8`** for the second argument to **F-000000000002**; the first argument is zero. After that call returns, it calls **F-000000000003** with no displayed arguments, then reaches an invalid-instruction boundary.

The `0x0897fea8` read belongs to this branch and occurs after the scaled-address store. No later main-path operations occur on this branch.

### 4. Nonzero-path record-related writes

For a nonzero scaled address, the procedure:

1. Stores an 8-bit zero at first-result high word multiplied by `0x100`, plus `7`.
2. Assigns record address multiplied by `0x200000` to the global nominally at `0xffffffcc`.
3. Writes five consecutive 32-bit fields beginning at the word address:

| Offset | Value |
|---:|---|
| `0x00` | Zero |
| `0x04` | Record address |
| `0x08` | Value read from the global at `0xffffffcc` |
| `0x0c` | Record address |
| `0x10` | Incoming stack word |

The third field uses a global read, not an unconditional reuse of the earlier arithmetic result. Aliasing writes can matter.

The following operations then occur in order:

- A 16-bit zero store at post-call base value multiplied by `0x40000`, plus `0x0e`.
- A symbolic assignment of the record address’s low 16 bits to `_SUB_00000006`, nominally associated with `0x00000006`.
- A separate read of that symbolic global, whose value supplies a 16-bit store at the record address.
- An 8-bit store at record address shifted left by seven. Its value is the record address’s low byte multiplied by `0x40`, truncated to eight bits.
- A 32-bit store of token `0x0898033c` at record address plus `8`.
- A symbolic assignment of `0x86` to the global nominally at `0x0000008a`.
- A 32-bit store of `0x86` at the record address, interpreted as signed 32-bit and arithmetically shifted right by 16, then multiplied by `0x200` and increased by `8`.

The symbolic assignment and read involving `_SUB_00000006` do not establish halfword accesses. The subsequent store through the record pointer does establish a halfword access.

### 5. Low-memory assembly and overlapping updates

The procedure reads **`0x089801dc`**, consuming an unsigned 32-bit **secondary control** value. This occurs after the preceding record-related writes.

It then assembles a 32-bit value from three symbolic operands:

| Result bits | Logical fragment |
|---|---|
| 0–15 | 16-bit fragment associated with `0x00000002` |
| 16–23 | 8-bit fragment from `UndefinedInstruction` |
| 24–31 | 8-bit fragment associated with `0x00000005` |

Call the result the **assembled value**. These concatenation widths do not establish the globals’ access widths. Nor does the fragment from `UndefinedInstruction` establish a halfword object at `0x04`. The operands’ relative evaluation order is unresolved.

The next three symbolic assignments have this exact order:

1. The 32-bit value `4` to the global at `0xffffffc0`.
2. The 32-bit value `4` to the global at `0xffffffc8`.
3. The assembled value to the global at `0xffffffc4`.

They must not be reordered to increasing address order. Their symbolic storage declarations remain unavailable.

The procedure then:

1. Assigns the record address to the global at `0xffffffd0`.
2. Reads the global at `0xffffffcc` and stores 32-bit `4` at that value plus `0x30`.
3. Stores the record address as 32 bits at the record address itself.
4. Establishes **field address** as record address plus `4`.
5. Assigns `4` to `UndefinedInstruction`, then zero to the symbolic global at `0x00000005`.
6. Stores the field address as 32 bits at assembled value plus `0x14`.
7. Stores an 8-bit zero at secondary control multiplied by two.
8. Arithmetically shifts the assembled value right by the secondary control’s low eight bits, producing the **shifted value**.
9. Assigns zero to `_Reset`, then zero to the symbolic global at `0x00000002`.
10. Assigns the shifted value to the global nominally at `0x00000020`.

Next comes an explicit **32-bit store involving `_FIQ`**. One occurrence of that global supplies the destination base, increased by `0x20`; another occurrence supplies the value converted to 32 bits. These are separate read occurrences. Their relative evaluation order, equality, access widths, and the global’s location are unresolved. No vector-object interpretation is required.

The remaining operations in this stage are:

- A symbolic update of `_SUB_00000006` using a 32-bit concatenated value: upper 16 bits equal `8`, lower 16 bits supplied by a new read of that global. This does not establish a 32-bit memory update at `0x06`.
- A 32-bit store of record address plus `12` at the field address.
- A 16-bit store of `8` at record address plus `0x1e`.
- A 16-bit zero store at the field address.

The final halfword store overlaps the preceding 32-bit field store. Its resulting byte representation depends on endianness.

### 6. Eight-argument call and working-value selection

The procedure calls **F-000000000004** with:

1. `8`
2. Record address plus `8`
3. Zero
4. `0x20`
5. Field address
6. Secondary control
7. Shifted value
8. Zero

Its represented unsigned 32-bit result is used as both destination and value of a 32-bit store.

The result is then bitwise-ANDed with the field address, producing the **masked result**. Its low 16 bits are stored at field address plus `0x28`.

The procedure calls **F-000000000005** with tokens `0x08980358` and `0x089802e0`. Its represented 32-bit result is treated as an address. Three 32-bit stores follow:

1. Returned address at returned address plus `0x44`.
2. Returned address at the returned address itself.
3. Field address at returned address plus `4`.

If the masked result is nonnegative as signed 32-bit, a 16-bit unsigned read at field address plus `0x14` supplies the **working value**, zero-extended to 32 bits. Otherwise, the masked result is the working value.

Separately, if the secondary control arithmetically shifted right by 12 is nonnegative, the working value’s low 16 bits are stored at field address plus `0x14`. This predicate depends on the secondary control’s sign.

### 7. Final updates and termination

The procedure:

1. Stores a 16-bit zero at working value multiplied by `0x20000000`.
2. Assigns zero to `_Reset`.
3. Assigns to the symbolic global at `0x00000002` the 16-bit conversion of the working value shifted left by 21 with 32-bit truncation, then logically right by 16.
4. Assigns `4` to `UndefinedInstruction`, then zero to the symbolic global at `0x00000005`.
5. Assigns the 32-bit value `4` to the globals at `0x04000000` and `0x04000004`, in that order.

An explicit 16-bit store then uses **two separate occurrences** of the symbolic global nominally at `0x00000030`:

- One occurrence, converted to unsigned 32-bit, forms the destination.
- The other supplies the value converted to 16 bits.

The representation does not establish one shared read, equal observed values, halfword global accesses, or relative evaluation order between these occurrences.

The procedure calls **F-000000000006** with token `0x089803d8`. Its represented 64-bit result supplies:

- A 32-bit store of its high word at `0x0000000a`.
- A **final base** equal to its low word multiplied by four.

Subsequently, in order:

1. The final base’s low 16 bits are stored at final base plus `2`.
2. A 16-bit `4` overwrites that destination.
3. A 16-bit unsigned read at final base plus `0x20` supplies the **final index**.
4. The final index is stored as 16 bits at final index plus `0x20`.
5. It is stored as 32 bits at final index multiplied by four, plus `0x14`.
6. It is stored as 16 bits at final index plus `4`.
7. A read of `_DataAbort`, converted to unsigned 32-bit and multiplied by four, forms another destination. Neither its location nor a halfword access width is established.
8. A 16-bit `0x03d8` is stored there, then overwritten by the destination address’s low 16 bits.
9. The symbolic destination `Reset_1` is assigned `1`. Its destination resolution and store width are unresolved.
10. A 32-bit `0x0a` is stored at `0x00000a20`.
11. The symbolic global at `0x00000005` is assigned `3`, followed by assignment of `0x8c` to `UndefinedInstruction`.
12. The global at **`0x08980420`** is read, interpreted as signed 32-bit, and arithmetically shifted right by 31. Its low byte is stored at `0x08980d8c`.
13. Execution reaches an invalid-instruction boundary.

The final source read therefore occurs after the preceding symbolic assignments; it is not a constant captured earlier.

## Side effects

The trace includes overlapping stores, reads after writes, writes through dependency results, and arithmetic-derived destinations. No non-aliasing guarantee is established. Earlier writes can change subsequent global reads or destination calculations.

There is no established atomicity, rollback, allocation, release, ownership transfer, or retained-pointer lifetime contract. Passing or storing the record address does not prove ownership transfer.

Dependencies may mutate shared memory or invalidate pointers. Nothing supplied establishes that they preserve globals or release—or refrain from releasing—memory.

Low addresses and the `0x04000000` region do not by themselves establish device-register semantics.

## Acceptance examples

These are conditional requirements, not observed executions.

- **Control word `1`:** Two halfword writes occur at the object address, followed by the word write at secondary base plus `0x1c`, then the abnormal boundary. The main-path byte stores do not occur.
- **Upper bits only:** `0`, `0x40000000`, `0x80000000`, and `0xc0000000` select the main path. The repeated byte stores remain separated by the saved-halfword store.
- **Zero scaled address:** The 32-bit zero store to address zero precedes the branch-specific read at `0x0897fea8` and both branch calls.
- **Low-memory assignment order:** After assembly, the required order is `0xffffffc0`, `0xffffffc8`, then `0xffffffc4`, not increasing address order.
- **Changing `_FIQ`:** If its two occurrences observe different values, the destination and stored value need not derive from the same observation. Acceptance cannot require one cached read.
- **Changing global at `0x30`:** If its two occurrences observe different values, the halfword destination and stored halfword need not match. Their relative evaluation order remains unresolved.
- **Nonnegative masked result:** For masked result `0x10`, the working value comes from the unsigned halfword read, not directly from `0x10`.
- **Negative masked result and secondary control:** For masked result `0x80000010`, the conditional read is skipped. A negative secondary control suppresses the separate conditional write.
- **Unwritable returned address:** If the self-store following F-000000000004 faults, reaching F-000000000005 is not required.
- **Overwritten final destination:** The final-base-derived halfword must be written before `4`; similarly, `0x03d8` precedes its overwrite. Final contents alone do not demonstrate the required trace.
