# F-5490b22cfb61

## Purpose

F-5490b22cfb61 generates duplicated pairs of signed 16-bit values by interpolating between a persistent saved value and selected input values. It updates a persistent phase and saved value when processing reaches the input boundary.

Processing has two stages:

- A bridge from the saved value to the first selected input value.
- Interpolation between successive selected input values.

Each generated value occupies two adjacent 16-bit output elements. The reported output count measures pairs, not individual elements or bytes.

Fixed-point resampling, input-lane selection, and identical two-lane output are inferred intent. The established contract concerns arithmetic, memory accesses, and persistent state; no external media format is established.

## Interface

The function accepts four arguments and has no explicit return value.

| Argument | Established role |
|---|---|
| State address | Base address for persistent fields and inline output storage. |
| Input address | Base address of signed 16-bit elements. |
| Input extent | Signed 32-bit quantity used in boundary and final-element calculations. |
| Output-count address | Address of a signed 32-bit count, cleared on entry and incremented once per generated pair. |

### State layout

Offsets are in bytes from the state address.

| Offset | Width | Meaning |
|---|---:|---|
| `0x24` | 32 bits | Unsigned phase; captured on entry and replaced on normal return. |
| `0x28` | 32 bits | Signed phase increment; captured once on entry. |
| `0x2c` | 16 bits | Signed saved value; captured on entry and replaced on normal return. |
| `0x30` onward | 16-bit elements | Consecutive duplicated output pairs. |

There is no output-capacity argument. Generating \(K\) pairs writes \(4K\) bytes beginning at offset `0x30`.

### Input layout

For an ordinary positive extent \(N\), define the selected values as

\[
x_j=\text{signed 16-bit input element }2j,\qquad 0\le j<N.
\]

Selected values are four bytes apart. The visible input accesses select even-numbered elements; they do not select the intervening odd-numbered elements.

Input element zero is read unconditionally, including invocations that generate no output. Normal termination reads element \(2N-2\) again to obtain the next saved value.

### Caller obligations

The function performs no visible validation. Defined, finite operation requires:

- Readable state fields and writable phase, saved-value, count, and output storage.
- Readable input element zero and all later elements actually accessed.
- Sufficient output capacity for every generated pair.
- Valid address calculations and target-appropriate alignment.
- No signed count overflow or other arithmetic outside the established interpretation.
- Parameters that allow the boundary condition to be reached.

Disjoint state, input, and count regions make the ordinary value contract applicable. Disjointness is not checked. With overlapping regions, the access ordering described below governs what can be observed.

## Behavior

### Entry observations

The phase is read first, followed by the increment. The output count is then cleared to zero. Only after that clearing write are the saved 16-bit value and input element zero read, in that order.

The phase and increment are therefore already captured if clearing the count changes their backing storage. By contrast, an overlapping count can affect the saved value or initial input value before either is captured.

The output destination begins at state offset `0x30`. Captured phase and increment values are not refreshed from their state fields during processing.

### Phase arithmetic

One whole phase unit is \(65{,}536\), or `0x10000`.

The working phase is unsigned and 32 bits wide. Adding the signed increment has the effect of adding its unsigned 32-bit representation, modulo \(2^{32}\). The single whole-unit subtraction between stages also uses unsigned 32-bit arithmetic.

A negative increment is neither rejected nor interpreted as a separately supported reverse mode. Its modular effect can cause large jumps, wraparound, unusual boundary behavior, or nontermination. Zero increment can likewise prevent progress.

### Interpolation

For signed 16-bit endpoints \(a\) and \(b\), let \(f\) be the current fractional phase, between \(0\) and \(65{,}535\). Under the arithmetic-right-shift interpretation shown by the supplied representation, the generated intermediate value is

\[
q=\left\lfloor\frac{f}{2}\right\rfloor,
\qquad
y=a+\left\lfloor\frac{(b-a)q}{32{,}768}\right\rfloor.
\]

Consequences:

- The lowest fractional-phase bit does not affect the interpolation weight.
- Negative products are rounded downward by the signed right shift, not toward zero.
- Fractional phases \(2k\) and \(2k+1\) produce identical values when their endpoints are identical.

The endpoint difference lies in \([-65{,}535,65{,}535]\), and the weight lies in \([0,32{,}767]\). Their product fits in signed 32 bits. The resulting interpolation remains between the endpoints and fits in signed 16 bits.

These bounds apply to both stages: the bridge uses a phase below one whole unit, while the second stage removes the current integer phase base before deriving its fractional weight.

### Bridge stage

While the captured working phase is below one whole unit, the endpoints are the saved value and input element zero captured at entry. Neither endpoint is reread during this stage.

For each generated pair, interpolation precedes evaluation of a global symbol into a signed 32-bit temporary used by saturation selection. The supplied material does not declare the global symbol’s storage type or establish its access width.

The selected value is written first to the current 16-bit output element and then to the immediately following 16-bit element. The output destination advances by four bytes. The count is read and incremented in memory, after which the working phase advances by the captured increment.

Once the phase is at least one whole unit, one whole unit is subtracted exactly once. This subtraction also occurs when the bridge produces no output because the entry phase was already at or above `0x10000`.

### Input-pair stage

The integer input index is the upper 16 bits of the working phase:

\[
j=\left\lfloor\frac{\text{phase}}{65{,}536}\right\rfloor.
\]

It therefore lies between \(0\) and \(65{,}535\).

The function remembers the index associated with its cached endpoints. Its initial remembered value is outside that range, forcing a boundary check on the first pass through this stage.

Whenever the current index differs from the remembered index, the boundary condition is evaluated before new endpoints are read:

\[
\operatorname{uint32}(N)-1 \pmod {2^{32}}\ \le j.
\]

For \(1\le N\le65{,}536\), this is the ordinary condition \(j\ge N-1\).

If the boundary has not been reached, input element \(2j\) is read first and element \(2j+2\) second. These values become the cached endpoints. The corresponding integer phase base is retained.

An unchanged index reuses the cached endpoints without additional input reads. If modular advancement later returns to an earlier index after visiting another index, that earlier pair is read again.

Each generated pair uses the current fractional phase and cached endpoints. Global-symbol evaluation into the signed 32-bit saturation temporary follows interpolation and precedes output stores. The first 16-bit output store precedes the identical adjacent store. The output position then advances by four bytes.

Unlike the bridge stage, the working phase advances before the count is read and incremented. That phase advancement remains internal until the final phase store.

### Saturation selection

Each output iteration evaluates the global symbol into a signed 32-bit temporary before selecting the emitted value. This establishes the width of the temporary, not the global object or the underlying access.

The selection is:

| Intermediate value | Emitted 16-bit value |
|---|---|
| Below \(-32{,}768\) | \(-32{,}768\) |
| From \(-32{,}768\) through \(32{,}767\) | The intermediate value |
| At least \(32{,}768\) | The low 16 bits of the signed 32-bit temporary populated from the global symbol |

The supplied material does not establish the global value, its declared storage type, its access width, or any conversion needed to obtain the temporary’s value. In particular, the upper fallback must not be assumed to equal \(32{,}767\).

With the established signed 16-bit endpoints and interpolation arithmetic, the intermediate value stays in range. Thus the global-derived fallback does not affect ordinary emitted values. Its evaluation is nevertheless present in each output iteration in the supplied static representation.

### Normal return

When the boundary condition succeeds, no further output pair is generated. The function reads input element \(2N-2\) and stores that 16-bit value into the saved-value field. Only afterward does it calculate and store the final phase.

For ordinary positive extents, let \(P\) be the working phase at the successful boundary check, \(j\) its integer portion, and

\[
e=j-N+1.
\]

The successful check ensures \(e\ge0\). The low 16 bits of \(P\) are retained. If \(e>0\), the implementation adds \(e\times65{,}536\) to that fractional remainder.

Where this calculation is within the established signed-arithmetic range, the result is equivalently

\[
P_{\mathrm{out}}=P-(N-1)\times65{,}536.
\]

Overshoot is retained; the stored phase need not be below one whole unit. However, the visible signed multiplication used to restore a positive integer remainder exceeds signed 32-bit range when \(e\ge32{,}768\). Such cases require a target-arithmetic qualification rather than an unconditional portable result.

The next saved value is the final selected input value, not the last generated value and not necessarily the last endpoint used for interpolation.

## Side effects

### Writes and persistent state

The visible writes are:

- Clearing and subsequently incrementing the output count.
- Writing duplicated 16-bit output pairs from state offset `0x30`.
- Replacing the saved value on normal return.
- Replacing the phase after the saved-value update.

There is no explicit write to the increment field.

The count is not maintained solely in a private accumulator: its memory location is read for each increment. Aliasing can therefore change both its intermediate and final values.

### Ownership and lifetime

No function calls, allocation, deallocation, or ownership transfer are visible. All output storage is supplied through the state region. No separate output pointer is returned.

The visible persistent state consists of the updated phase, saved value, and output bytes. No broader ownership or lifetime guarantees are established.

### Overlap, failure, and concurrency

There is no overlap protection. Output stores can alter input values before later reads. Already cached endpoints remain unchanged by later writes to their original locations.

A count overlapping output storage can be changed by sample stores before its next increment. Final input reads can also observe earlier output or count writes when those regions overlap.

No rollback or error result is provided. If execution faults or fails to terminate, earlier output and count writes are not undone. Final saved-value and phase writes occur only after reaching the normal-return boundary.

No atomicity or synchronization guarantee is established. The ordering described here is the ordering exposed by the supplied static representation, not a promise about hardware bus transactions or concurrent observation.

## Acceptance examples

These examples are static deductions, not executed tests. Unless otherwise stated, assume disjoint valid storage, sufficient output capacity, arithmetic signed right shifts, and no relevant signed overflow.

### Whole-unit advancement

Given saved value \(100\), selected input values \(300,500\), extent \(2\), entry phase \(0\), and increment `0x10000`:

- The bridge emits \((100,100)\).
- The input-pair stage emits \((300,300)\).
- The next boundary check terminates processing.
- The count is \(2\), the saved value becomes \(500\), and the stored phase is \(0\).

### Half-unit advancement

Given saved value \(0\), selected input values \(1000,2000\), extent \(2\), entry phase \(0\), and increment `0x8000`, the output pairs are

\[
(0,0),\ (500,500),\ (1000,1000),\ (1500,1500).
\]

The final count is \(4\), saved value is \(2000\), and phase is \(0\).

### Negative interpolation rounding

A bridge from \(0\) to \(-1\) at phase `0x8000` emits \((-1,-1)\), not \((0,0)\). The negative product’s arithmetic right shift rounds downward.

### Discarded fractional bit

With identical endpoints, fractional phases `0` and `1` both emit the first endpoint. More generally, phases \(2k\) and \(2k+1\) have the same interpolation weight.

### Immediate boundary with one selected value

Given extent \(1\) and entry phase `0x10000`, the bridge is skipped. The subtraction leaves index zero, which immediately satisfies the boundary condition.

The count is cleared to zero, no output is written, input element zero is read at entry and again for the saved-value update, and the stored phase becomes zero.

### Preserved overshoot

Given extent \(2\) and entry phase `0x40000`, the bridge is skipped and the subtraction leaves `0x30000`.

The boundary is already reached. No output is generated, the saved value becomes input element two, and the phase becomes `0x20000`. This example’s residual calculation remains within signed 32-bit range.

### Global dependency does not establish a maximum constant

For an ordinary interpolation yielding \(123\), both output elements are \(123\), regardless of the value placed in the saturation temporary. The global symbol is still evaluated in the visible iteration.

This does not establish its storage width or justify replacing its value with a conventional saturation maximum.

### Zero increment

With entry phase below `0x10000` and increment zero, the bridge phase never progresses. No normal return occurs while the loop remains otherwise executable. Output and count operations continue until an external interruption or a violated memory or arithmetic precondition prevents further defined operation.
