# F-7b14b353e48f

## Purpose

F-7b14b353e48f performs a lookup or selection through F-4e6cefe281de and conditionally runs a three-stage operation on the selected record and the supplied object.

The established behavior is:

- A zero result from the initial dependency produces status **3**.
- A nonzero result permits inspection of one flag byte in the selected record.
- If that byte’s most significant bit is clear, the function returns **0** without performing the three subsequent calls.
- If that bit is set, all three subsequent calls occur in order, provided each preceding operation returns normally. The function returns the **last nonzero status** from those calls, or **0** if all three return zero.

The apparent purpose of the flag-gated sequence is inferred intent. The evidence does not establish that the calls perform initialization, cleanup, synchronization, notification, or any other particular domain operation.

## Interface

### Inputs

The interface has four argument positions:

| Position | Role established by the evidence |
|---|---|
| First | Address of an object whose first 32-bit word supplies an indirect-dispatch table address, and whose storage at byte offset 1004 is passed to F-4e6cefe281de. |
| Second | A 32-bit value forwarded unchanged to F-4e6cefe281de. Its interpretation is unknown. |
| Third | A 32-bit value that this function does not inspect or forward. |
| Fourth | A 32-bit value used to initialize a writable selection slot. F-4e6cefe281de receives the address of that slot and can replace its contents. |

The fourth argument is not necessarily the record ultimately inspected. The value left in the selection slot by F-4e6cefe281de determines the subsequent record access.

The third argument is unused by this function’s visible operations. That does not establish its intended role in a wider interface, nor does it justify removing the argument from the contract.

### Output

The function returns one 32-bit integer status:

- **3** if F-4e6cefe281de returns zero.
- **0** if that dependency returns nonzero and the selected record’s tested flag is clear.
- Otherwise, the last nonzero status returned by the three flag-gated calls, or zero if none returns a nonzero status.

Nonzero values are not normalized to a single error code. Negative statuses, if returned by the later calls, qualify as nonzero and can be returned unchanged.

### Widths and layout

The supplied representation uses 32-bit integer words and 32-bit address-bearing values. Within that representation:

- The object subregion passed to F-4e6cefe281de begins at byte offset **1004**, equivalently hexadecimal **0x3EC**, from the first argument. This is 251 four-byte words, not 251 bytes.
- The selected record’s tested flag is an **8-bit byte** at byte offset **28**, equivalently **0x1C**.
- The flag mask is **0x80**, selecting bit 7 of that byte.
- The indirect callback address is loaded from byte offset **48**, equivalently **0x30**, within the dispatch table addressed by the object’s first word. With four-byte entries, this is entry index 12 when counting from zero.

No other field widths, object size, record size, alignment requirements, calling-convention details, or byte order are established.

## Behavior

### Initial selection

The function first creates a writable 32-bit selection slot and initializes it with the fourth argument.

It then calls F-4e6cefe281de with these arguments, in order:

1. The address at byte offset 1004 within the object supplied as the first argument.
2. The second argument, unchanged.
3. The address of the writable selection slot.

The address passed as the first dependency argument identifies storage inside the supplied object. It is not a copy of that storage’s contents.

The dependency can overwrite the selection slot through its third argument. The function does not independently verify whether an overwrite occurred, whether the resulting value differs from the original fourth argument, or whether the resulting address is valid.

### Initial failure branch

If F-4e6cefe281de returns zero, the function returns **3**.

On this branch, the function itself does not:

- Read the selected record’s flag byte.
- Invoke F-7b1d16937fcc.
- Invoke F-4f50bb4f244a.
- Resolve or invoke the object’s indirect callback.

These exclusions concern operations performed by F-7b14b353e48f. They do not constrain what F-4e6cefe281de may do internally.

Any selection-slot update made by F-4e6cefe281de does not change the return value on this branch.

### Flag inspection

If F-4e6cefe281de returns nonzero, the function establishes an initial result of **0** and reads the flag byte at offset 28 from the address then held in the selection slot.

Only bit **0x80** controls the subsequent branch. Other bits in the byte do not affect this decision.

If bit 0x80 is clear, the function returns **0**. There is no later callback dispatch on this path.

There is no null-address check, bounds check, record-type check, or flag-read error conversion visible before this access. A nonzero result from F-4e6cefe281de must therefore leave a usable selected-record address if normal completion is required.

### Flag-gated sequence

If bit 0x80 is set, the function performs the following calls in this order:

1. F-7b1d16937fcc, with no explicit arguments.
2. F-4f50bb4f244a, with the address-bearing value from the selection slot.
3. An indirect callback resolved through the supplied object, with that object address as its sole explicit argument.

After each call returns, a nonzero returned status replaces the current result. A zero returned status leaves the current result unchanged.

Consequently:

- An early nonzero status does not prevent later calls.
- A later zero status does not clear an earlier nonzero status.
- A later nonzero status replaces any earlier nonzero status.
- The callback’s nonzero status, when present, has final precedence.

There is no flag recheck between the calls. Once the flag-gated branch is entered, later changes to the flag do not create another visible branch in this function.

### Late callback resolution

The indirect callback is resolved only after F-4f50bb4f244a returns.

At that point, the function reads the first word of the supplied object as a dispatch-table address, obtains the callback address at byte offset 48 in that table, and invokes it with the original object address.

The callback is therefore not visibly captured before the earlier dependency calls. Changes made by those calls to the object’s dispatch-table pointer or the applicable table entry can affect the eventual callback target.

Normal completion requires the object, its dispatch-table pointer, and the selected callback entry to remain usable at dispatch time. The function contains no visible fallback for an absent or invalid callback.

## Side effects

### Directly established effects

The function’s directly visible data writes are to its own writable selection slot and result bookkeeping. It does not visibly write an object field or selected-record field itself.

Its externally relevant direct reads occur in this order:

1. After a nonzero initial dependency result, the selected record’s flag byte is read.
2. Only on the flag-set path, and after the next two dependencies return, the object’s dispatch-table address and the callback entry are read.

Dependency-internal reads and writes are not specified by the supplied evidence.

### Effects delegated to callees

F-4e6cefe281de receives both an address inside the object and the address of the selection slot. F-4f50bb4f244a receives the selected-record value. The callback receives the object address. Each can have side effects not shown here.

F-7b1d16937fcc receives no explicit arguments, but that does not establish purity. It may access shared or global state.

There is no visible rollback. If a later call returns a nonzero status, effects of earlier calls are not undone by this function. Likewise, the initial dependency’s zero return does not imply that it left the object or other state unchanged.

- Return **0**.
- Do not invoke F-7b1d16937fcc, F-4f50bb4f244a, or the object callback.
