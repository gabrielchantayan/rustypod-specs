# F-9a45315b9740

## Purpose

F-9a45315b9740 classifies an opaque input through F-11c1b7e655b3. For three recognized classification results, it selects a signed 16-bit value from an object, conditionally negates that value, and invokes an indirect operation associated with the object. It then returns true. For every other classification result, it returns false without directly reading the object or invoking that operation.

The Boolean result indicates whether the classification was recognized and the indirect operation returned normally. It does not establish that the operation succeeded, changed the object, or accepted the supplied value.

This contract describes static evidence only. No runtime tests have been performed. Interpretation of the classifications as commands, directions, or events is not established.

## Interface

### Inputs

The function has two inputs:

1. **Object reference.** A pointer used both to obtain stored numeric values and to locate an indirect operation. The function does not inspect this pointer before calling F-11c1b7e655b3.
2. **Opaque classification input.** A four-byte value passed unchanged to F-11c1b7e655b3. Its semantic type, valid range, and whether it encodes an address are unknown.

The object reference is not passed explicitly to F-11c1b7e655b3. That dependency could nevertheless access the same object through aliases or shared state; its implementation is unavailable.

### Output

The output is a Boolean:

- **False:** F-11c1b7e655b3 returned a value other than `0x57`, `0x58`, or `0x5D`.
- **True:** F-11c1b7e655b3 returned one of those three values, and the selected indirect operation returned normally.

The source does not establish the Boolean’s physical return-register representation or calling-convention details.

## Behavior

### Classification occurs first

F-9a45315b9740 calls F-11c1b7e655b3 exactly once, forwarding the four-byte classification input without an explicit transformation.

No object field is directly read by F-9a45315b9740 before that call returns. Consequently, a recognized case uses object contents observed after the dependency call, not necessarily the contents present on entry.

There is no saved copy of the selected object field or dispatch-table address from before classification. Changes made by F-11c1b7e655b3 through shared state or aliases can therefore affect subsequent behavior.

### Classification determines the selected field and transformation

The classification result is compared as a complete integer value, not as a masked byte or truncated 16-bit quantity.

| Classification result | Selected object field | Transformation before dispatch |
|---|---|---|
| `0x57` | Byte offset `0xE8` | Convert to signed 16-bit, negate after integer promotion, then store the result as signed 16-bit |
| `0x58` | Byte offset `0xE8` | Convert to signed 16-bit |
| `0x5D` | Byte offset `0x58` | Convert to signed 16-bit |
| Any other value | None | Return false |

The recognized values are decimal 87, 88, and 93.

For an unrecognized result, the function returns false immediately. It does not directly read either numeric field, the object’s dispatch-table address, or the dispatch entry. It does not invoke the indirect operation.

In particular, resemblance in the low-order bits is insufficient. A classification result of `0x157` is not recognized as `0x57`.

### Signed conversion and arithmetic

For every recognized result, the selected 32-bit field is converted to a signed 16-bit value before it becomes the indirect operation’s numeric argument.

For `0x58` and `0x5D`, that signed 16-bit value is then widened to the recovered signed 32-bit argument type. Negative values remain negative; the argument is not an unsigned 16-bit magnitude.

For `0x57`, negation takes place after the first signed 16-bit conversion. Under the recovered 32-bit arithmetic model, integer promotion makes the negation itself a 32-bit operation. The result is then assigned back to signed 16-bit storage before being widened for the call.

This order matters:

- The operation does not negate the original 32-bit field and then perform its only narrowing conversion.
- Values outside the signed 16-bit range encounter a narrowing conversion before any negation.
- A converted value of `−32768` negates to `32768` in the promoted 32-bit type, but that result is outside the signed 16-bit range and encounters another narrowing conversion.

The source establishes the conversions but does not independently establish the target’s out-of-range signed-conversion rule. A two’s-complement wrapping interpretation would retain the low 16 bits and interpret them as signed, but that interpretation is conditional rather than an unconditional portability guarantee.

### Indirect invocation

After computing and storing the signed 16-bit value, the function:

1. Reads the dispatch-table address from the beginning of the object.
2. Obtains the callable address at table byte offset `0x164`.
3. Invokes that target with the original object reference and the selected value widened to the recovered signed 32-bit type.

The numeric value is therefore selected before the dispatch-table lookup. The source does not promise an atomic snapshot of the field and dispatch information, nor does it provide synchronization against concurrent changes.

Exactly one indirect invocation occurs for a recognized classification, provided execution reaches the invocation normally. Its return value, if any, is not used.

After the indirect invocation returns normally, F-9a45315b9740 returns true. There is no subsequent object-field read, success check, or verification of the operation’s effects.
