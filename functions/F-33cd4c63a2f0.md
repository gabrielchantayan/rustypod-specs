# F-33cd4c63a2f0

## Purpose

F-33cd4c63a2f0 is a fixed-size record dispatcher. It checks a supplied size, examines a one-byte discriminator, and either returns without further action, updates fields in an associated state region, or invokes a selected dependency or virtual method.

The established behavior is dispatch and data movement. The meanings of the record kinds, state fields, resource values, and operation numbers are not established. Descriptions such as “notification,” “status,” or “command” would be inferred intent, not additional requirements.

## Interface

The function has five inputs and no defined return value.

| Input | Representation in the supplied evidence | Role |
|---|---|---|
| State address | 32-bit address-bearing value | Identifies state fields and a related object located 64 bytes earlier. |
| Auxiliary value | Opaque 32-bit value | Not read by the visible body. |
| Initial payload value | Unsigned 32-bit integer | Initializes the first word of a temporary two-word payload; overwritten before the only visible use of that payload. |
| Record address | Byte-addressable pointer | Supplies the discriminator and selected record fields. |
| Supplied size | 32-bit integer | Must equal 72, represented by `0x48`. |

The related object address is the state address minus `0x40` bytes. This address calculation occurs before the size check, but the visible body does not dereference the related object until a branch requires a virtual call.

## Behavior

### Entry and size validation

Before dispatch, the function prepares a temporary payload containing two unsigned 32-bit words:

1. The initial payload value.
2. The constant `1`.

It then compares the supplied size with 72.

- If the size differs, it invokes F-a817d8d58c10.
- That dependency is represented as non-returning.
- No record byte is read before this check.
- There is no visible local error return or recovery path for a size mismatch.

The contract cannot identify whether the non-returning dependency terminates execution, throws, transfers control, or performs some other non-returning action.

For a matching size, the function reads the discriminator at record offset `+0x00` and dispatches as follows.

### Discriminator `0x00`

The function reads the byte at record offset `+0x04`.

- If it equals `0x12`, the function returns.
- Otherwise, the visible body reads that byte again and compares it with `0x05`.
- If it does not equal `0x05`, the function returns.
- If it equals `0x05`, the function reads the state byte at `+0x0E`.
  - If the state byte is zero, the function returns.
  - If it is nonzero, the function invokes F-3e9b7d634ec3, interprets its result as an object pointer, reads that object's virtual-table pointer, and invokes the method selected by virtual-table byte offset `0x6C`. It then returns if the call returns.

No explicit arguments are shown for the method at offset `0x6C`. An implicit receiver or other calling-convention details are not established.

There are no direct state writes in this branch.

### Discriminator `0x02`

This branch performs state updates before invoking any dependency:

1. Read the 32-bit record field at `+0x04` and write it to state offset `+0x08`.
2. Read the record byte at `+0x08` and write it to state offset `+0x0C`.
3. Read the record byte at `+0x09` and write it to state offset `+0x0D`.
4. Set the first temporary payload word to zero. The second word remains `1`.
5. Invoke F-120cb3bb1627 to obtain an object pointer.
6. Read that object's virtual-table pointer and invoke its method at byte offset `0x28`, with the object pointer and the value `1` as visible arguments.
7. Treat that method's result as another object pointer.
8. Read the second object's virtual-table pointer and invoke its method at byte offset `0x08`. No explicit arguments are shown for this call.
9. Compare that method's 32-bit integer result with `3`.
10. Replace the first payload word with `1` if the result equals `3`, or `0` otherwise.
11. Read the related object's virtual-table pointer and invoke its method at byte offset `0x10`, passing:
    - the related object address;
    - the 32-bit value `0x00020001`;
    - the address of the two-word temporary payload.

Thus, at the final call, the payload is exactly one of:

| Earlier method result | First word | Second word |
|---|---:|---:|
| `3` | `1` | `1` |
| Any other 32-bit value | `0` | `1` |

The initial payload input does not affect this visible call.

The three state writes have already occurred when F-120cb3bb1627 is invoked. No rollback is visible if a subsequent dependency fails or does not return.

### Discriminators `0x0A` and `0x13`

For discriminator `0x0A`, the function invokes the related object's virtual method at byte offset `0x54`, passing the related object address, then returns if the call returns.

For discriminator `0x13`, it first reads the 32-bit record field at `+0x04`.

- If that field has the all-one bit pattern, interpreted as signed `-1`, the function returns without invoking the method.
- Otherwise, it invokes the same related-object method at offset `0x54`.

Discriminator `0x0A` does not require a read of the record field at `+0x04`.

### Discriminator `0x19`

The function reads one unsigned byte at record offset `+0x04`. Three bits select at most one dependency, with strict precedence:

| Priority | Condition | Selected dependency |
|---:|---|---|
| 1 | Bit mask `0x02` is set | F-88c9f72acf81 |
| 2 | Mask `0x02` is clear and mask `0x04` is set | F-44d97cb41359 |
| 3 | Masks `0x02` and `0x04` are clear and mask `0x01` is set | F-286e8e65f24e |
| — | All three masks are clear | No dependency call |

If a dependency is selected, the function reads the 32-bit state field at `+0x04` and passes that value as its sole visible argument.

Other bits in the flag byte do not influence selection. Multiple selected bits do not produce multiple calls.

### Discriminator `0x1B`

The function reads the unsigned 32-bit record field at `+0x04` and tests mask `0x40000000`.

- If that mask is set, it reads the 32-bit state field at `+0x04` and invokes F-30ecb6545790 with that value and the 32-bit value `30`.
- If that mask is clear, the visible body reads the record field at `+0x04` again and tests mask `0x10`.
  - If mask `0x10` is clear, it returns.
  - If mask `0x10` is set, it reads the state field at `+0x04` and invokes F-30ecb6545790 with that value and the 32-bit value `4`.

When both masks are present in stable record storage, `0x40000000` takes precedence and selects `30`.

The repeated reads matter to the static access description. The evidence does not establish synchronization, volatile semantics, or behavior under concurrent mutation.

### Discriminators `0x1D` and `0x21`

Either discriminator invokes the related object's virtual method at byte offset `0x58`, passing the related object address. The function then returns if the call returns.

### All other discriminators

Every other value of the unsigned one-byte discriminator returns without a dependency call or direct state write after size validation and discriminator reading.

In particular, some values have explicit return branches while others reach the common return. This does not establish a semantic distinction between them.

## Side effects

### Direct writes

The only externally addressed writes visible in the body occur for discriminator `0x02`:

- Four bytes at state offset `+0x08`.
- One byte at state offset `+0x0C`.
- One byte at state offset `+0x0D`.

Their order is the order listed. Record reads and corresponding state writes are interleaved; the function does not visibly snapshot all source fields before beginning the updates.

If state and record storage overlap, an earlier write can affect a later read. There is no visible non-aliasing check. Acceptance examples involving independent source values therefore require non-overlapping storage, or an overlap arrangement that leaves those later reads unchanged.

### Indirect effects

Selected dependencies and virtual methods may produce additional effects. Their implementations are not supplied. This contract does not assume they preserve globals, preserve state fields, avoid reentrancy, allocate memory, release memory, or return normally.

For discriminator `0x02`, the related object's virtual-table pointer is read only after the earlier dependency calls. The contract does not substitute an entry-time virtual-table snapshot for that later read.

### Ownership and lifetime

The function contains no explicit allocation, deallocation, reference-count update, or ownership-transfer operation.

Pointers returned by dependencies are used without visible null checks. Required object validity and lifetime are caller/dependency obligations.

The two-word payload is temporary local storage. Its address is passed to the method at offset `0x10`, but the body does not establish a retention protocol. Safe use after this function returns requires behavior outside the supplied evidence; persistent ownership must not be assumed.

## Acceptance examples

These are conditional acceptance criteria derived from static evidence, not executed tests. Unless stated otherwise, assume size 72, valid required addresses, stable non-overlapping storage, and returning dependencies other than the designated non-returning dependency.

1. **Size rejection precedes record access.** With any size other than 72, F-a817d8d58c10 is invoked before any record byte is read. No ordinary return is specified.

2. **Inactive discriminator.** With discriminator `0x15`, the function returns after reading the discriminator. It does not read the record field at `+0x04`, write state, or invoke a dependency.

3. **Conditional discriminator `0x00`.** With subtype `0x05` and a zero state byte at `+0x0E`, no dependency is invoked. With a nonzero state byte, F-3e9b7d634ec3 is invoked, followed by the returned object's method at offset `0x6C`.

4. **State update and true payload.** With discriminator `0x02`, record word `0x12345678`, and trailing bytes `0xAB` and `0xCD`, the corresponding state fields receive those values before F-120cb3bb1627 is called. If the later method at offset `0x08` returns `3`, the final payload is the two words `1, 1`.

5. **False payload.** Under the same discriminator-`0x02` setup, a method result of `0`, `-1`, or any value other than `3` produces payload words `0, 1`. Changing the initial payload input does not change this outcome.

6. **Sentinel distinction.** Discriminator `0x13` with record word `0xFFFFFFFF` invokes no related-object method. Discriminator `0x13` with word zero invokes offset `0x54`. Discriminator `0x0A` invokes that method without consulting this record word.

7. **Byte-flag precedence.** Discriminator `0x19` with flags `0x07` selects only F-88c9f72acf81. Flags `0x05` select only F-44d97cb41359. Flags `0x81` select only F-286e8e65f24e. Flags `0x80` select none.

8. **Word-flag precedence.** Discriminator `0x1B` with flags `0x40000010` selects argument `30`. Flags `0x00000010` select `4`. Flags zero cause no dependency call.

9. **Shared virtual dispatch.** Discriminators `0x1D` and `0x21` each select the related-object method at offset `0x58`; neither directly writes state.
