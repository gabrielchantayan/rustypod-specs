# F-218e9455b42d

## Purpose

F-218e9455b42d describes a condition-dependent operation on four 32-bit inputs and additional incoming state. Its externally significant actions are a possible fixed-location write, a possible coprocessor-store request, a possible two-argument external call, a separately guarded coprocessor request, and a terminal invalid-instruction boundary.

The operation also derives working values and condition indicators that determine dependency operands and later selection decisions. These calculations are not established as independently observable outputs.

No ordinary return or usable return value is established. An earlier completed effect is not contingent on later successful completion; no rollback is represented.

**Established static evidence:** Operand widths, represented conditions, arithmetic, explicit effect order, dependency argument order, and the terminal boundary.

**Inferred intent:** The arithmetic resembles subtraction with a carry-related adjustment and condition-indicator updates. This does not establish an architecture, a conventional carry rule, or a valid executable entry boundary.

**Documented-only unknowns:** Dependency implementations, physical execution details absent from the representation, and the concrete outcome at the terminal boundary.

When arithmetic replaces the zero, negative, and overflow indicators, their new values express Boolean conditions.

## Behavior

### Condition model

The operation uses two complementary condition patterns:

- **Replacement condition:** zero is true, or the negative and overflow indicators differ directly.
- **Late condition:** zero is false, and the negative and overflow indicators are directly equal.

The replacement condition is checked before selection of the third working value and checked again at the auxiliary-arithmetic stage. The intervening region can contain a dependency interaction. The representation contains no explicit indicator assignment in that region, but this does not establish physical-state preservation by that dependency.

The late condition is also checked separately for F-L02 and F-L03. Selection of the first interaction is not an unconditional commitment to the second.

### Third-value selection and initial effects

When the first replacement-condition check succeeds, the third working value is the fourth input exclusive-ORed with the low 32 bits of the first input shifted left by four positions. Otherwise, it remains the third input.

This calculation uses the original first input, before any subsequent masking.

After this selection, true incoming carry selects a four-byte write of the link value to `0x08624FCC`. False incoming carry selects no such write.

The next branch depends on the incoming zero indicator:

| Incoming zero | Selected behavior |
|---|---|
| True | Apply the shifted-constant mask to the first working argument. |
| False | Submit the coprocessor-store request to F-L01. |

F-L01 receives three ordered operands: selector zero, associated value zero, and the current third working value. The third operand is not established as an address, count, or transfer length.

### Shifted-constant mask

On the incoming-zero-true branch, the least significant eight bits of the original second input supply a count from 0 through 255. The first working argument is masked by `0x08624FD0` shifted left by that count.

The constant is a literal operand, not a read from that address.

The shift has an unresolved semantic boundary:

| Count | Established interpretation |
|---|---|
| 0–3 | The result agrees under 32-bit logical shifting and signed 32-bit expression rules. |
| 4–31 | A logical 32-bit shift gives a determinate low-32-bit result, but the supplied constant is not explicitly unsigned and the corresponding signed result exceeds the positive range. Defined signed-expression behavior is not established. |
| 32–255 | No result is established. |

Neither masking the count to five bits nor substituting zero for a large-count result is justified. A zero first input does not remove uncertainty in evaluation of the shift itself.

### Auxiliary arithmetic and condition replacement

The working carry decision initially has the incoming carry value.

If the replacement-condition check at the arithmetic stage fails, this stage leaves the auxiliary value and condition indicators unchanged in the represented state.

If that check succeeds, the arithmetic has the following mathematical meaning. Let \(A\) denote the auxiliary value at this stage, and let \(c\) denote the incoming Boolean carry encoded as zero or one:

\[
D=(A-\texttt{0x00009800})\bmod 2^{32}
\]

\[
R=(D-(1-c))\bmod 2^{32}
\]

The auxiliary working value becomes \(R\). Thus the total subtraction is `0x00009800` for true carry and `0x00009801` for false carry, with 32-bit wrapping.

The replacement conditions are:

| Condition | Required value |
|---|---|
| Zero | True exactly when \(R=0\). |
| Negative | True exactly when the high bit of \(R\) is set. |
| Working carry decision | True exactly when \(A>\texttt{0x00009800}\) or \(D<c\), using unsigned comparisons. |
| Overflow | True exactly when the two signed-overflow determinations below differ. |

Both carry comparisons are strict. Equality with `0x00009800` does not satisfy the first comparison. A presumed architectural “no borrow” convention must not replace this definition.

The overflow determinations concern:

1. Signed 32-bit subtraction of `0x00009800` from the signed interpretation of \(A\).
2. Signed 32-bit subtraction of \(1-c\) from the signed interpretation of the **wrapped intermediate \(D\)**.

Their exclusive OR supplies the new overflow indicator. The second determination is not based on an unbounded intermediate.

### Final argument values

After the arithmetic stage, a true working zero indicator replaces the second working argument with the current third working value exclusive-ORed with `0x0000023C`. Otherwise, the second working argument retains the original second input.

A true working carry decision masks the current first working argument with the current auxiliary value. Otherwise, that argument is unchanged at this stage.

Consequently:

- The first working argument can receive both the shifted-constant mask and the auxiliary mask, in that order.
- The auxiliary mask uses the arithmetic result when arithmetic occurred.
- When arithmetic was omitted, the mask uses the unchanged auxiliary value.
- These transformations occur after the possible F-L01 interaction and do not retroactively change its supplied operand.

### Late interactions and termination

When its late-condition check succeeds, F-L02 receives the first and second working arguments, in that order.

If execution continues, a separate late-condition check selects F-L03. Its six ordered operands are:

1. Selector two.
2. Selector two.
3. Selector zero.
4. Associated value two.
5. Associated value two again.
6. Associated value zero.

There is no explicit condition-indicator assignment between these checks. Nevertheless, F-L02 is not known to preserve physical flags, globals, or other state. F-L03 requires both continuation and satisfaction of its own guard.

After the selected late interactions, or their omission, execution reaches F-L04.

## Acceptance examples

These examples are conditional static deductions, not executed tests. Each observation requires execution to reach it. Observations following a dependency additionally require that interaction to permit continuation. Numerical deductions use the represented state; they are not guarantees about undocumented physical-state changes.

### Recomputed indicators can enable a late call

Assume incoming zero is false, negative is true, overflow is false, carry is false, and the auxiliary value is `0x00009802`.

The initial replacement condition succeeds, so F-L01 receives the transformed third value. No fixed-location write is selected.

If the represented condition state remains applicable at the arithmetic check, the intermediate is two and the auxiliary result is one. Replacement zero, negative, and overflow are false. Working carry is true because the original auxiliary value exceeds `0x00009800`.

The first working argument is therefore the original first input masked with one; the second remains the original second input. The late condition succeeds despite the unequal incoming negative and overflow indicators.

### Equal incoming indicators can omit arithmetic

Assume incoming zero is false and incoming negative and overflow are directly equal.

The third value remains the original third input, which is supplied to F-L01. If the represented conditions remain unchanged through that interaction, arithmetic is omitted and the late condition succeeds.

With false incoming carry, F-L02 receives the original first and second inputs. With true incoming carry, the fixed-location write precedes F-L01, and the first call argument is masked with the unchanged auxiliary value.

### Zero result suppresses the late interactions

Assume incoming zero is true, carry is true, auxiliary is `0x00009800`, first input is zero, fourth input is `0x00000100`, and the shift count is between zero and three.

The third working value is `0x00000100`. The fixed-location write is selected; F-L01 is not.

The auxiliary result is zero. Working carry is true because the wrapped intermediate, zero, is less than one. Both overflow determinations are false.

The second working argument becomes `0x0000033C`, while the first remains zero. Working zero is true, so both late guards fail in the represented state.

### Equal auxiliary boundary with false carry

Assume incoming zero is true, carry is false, auxiliary is `0x00009800`, and the shift count is between zero and three.

The intermediate is zero and the final auxiliary result is `0xFFFFFFFF`. Working carry and zero are false; negative is true and overflow is false.

Neither the fixed-location write nor F-L01 is selected. The late condition fails.

### A positive result selects F-L02

Assume incoming zero is true, carry is true, auxiliary is `0x00009801`, first input is one, and second input is zero.

The shifted constant clears the first working argument because its least significant bit is clear. The auxiliary result is one; working zero, negative, and overflow are false, while working carry is true.

F-L02 receives zero and zero if reached. F-L03 still requires continuation and satisfaction of its separate guard.

### Overflow depends on the wrapped intermediate

Assume incoming zero is true, carry is false, auxiliary is `0x80009800`, and the shift count is between zero and three.

The intermediate is `0x80000000`. The first signed subtraction does not overflow. Subtracting one from the signed interpretation of that intermediate does overflow, producing `0x7FFFFFFF`.

Working overflow and carry are true; negative and zero are false. The late condition fails.

### Shift boundaries retain their qualification

A count of three gives `0x43127E80`.

A count of four gives `0x8624FD00` under a logical 32-bit interpretation, without establishing valid signed-expression behavior.

A count of 32 has no established result. Count reduction, a zero shifted result, or bypass based on a zero first input is unsupported.
