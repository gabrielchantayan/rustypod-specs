# F-d2964719b92c

## Purpose

F-d2964719b92c derives two boundary values from three fields in a caller-supplied object and writes those values through two output addresses.

The apparent intent is to choose an inclusive interval around a selected position, limited by an available item count and a requested interval width. That interpretation is inferred from the arithmetic; the supplied representation does not establish what the items are or how callers use the results.

The established behavior is more permissive than a validated interval API:

- An available count of zero produces two all-one sentinel values.
- A selected position of exactly −1 also produces those sentinels.
- Other negative positions are not rejected.
- Positions beyond the available count are not rejected.
- A requested width of zero is not rejected.
- Some inputs produce a reversed interval or a boundary outside the apparent item range.

These cases are part of the described behavior, not errors to be corrected by this specification.

## Behavior

### Input reads and early exits

The first observable input access reads the available count at offset `0x2B8`.

If that value is zero:

1. The end output receives `0xFFFFFFFF`.
2. The start output receives −1.
3. Processing ends.

This path does not read the selected position or requested width. The end-before-start store order is significant when outputs alias or a store faults.

If the available count is nonzero, the function next reads the selected position at offset `0x2B4`.

If the selected position is exactly −1:

1. The start output receives −1.
2. The end output receives `0xFFFFFFFF`.
3. Processing ends.

This path does not read the requested width. Its output-store order is the reverse of the zero-count path.

Only after both early-exit conditions have been excluded does the function read the requested width at offset `0x2C0`.

### Width at least as large as the available count

The comparison between requested width and available count is unsigned.

If the requested width is greater than or equal to the available count, the resulting boundaries are:

- Start: zero.
- End: available count minus one.

The count is already known to be nonzero, so this subtraction does not underflow.

The selected position has no further effect on this path. It need not be within the apparent item range. In particular, a negative selected position other than −1 does not prevent the function from returning the full available range.

### Width smaller than the available count

When the requested width is smaller than the available count, the function first interprets the requested width as signed and divides that signed value by two.

For ordinary widths below `0x80000000`, this produces the usual nonnegative half-width rounded down. For high-bit-set widths, it instead produces a negative half-width. Signed division truncates toward zero under the conventional interpretation used here.

The initial start candidate is:

**selected position minus signed half-width.**

The function tests this candidate as a signed value.

#### Negative initial start

If the initial start candidate is negative:

- Start becomes zero.
- End becomes requested width minus one, using unsigned subtraction.

This decision precedes the upper-bound check. Once this path is selected, there is no separate correction for the selected position or end boundary.

For a positive requested width, the result is the first interval of that width. For a zero requested width, the end becomes `0xFFFFFFFF`; zero is not treated as an invalid request.

#### Nonnegative initial start and upper-bound condition

If the initial start candidate is nonnegative, the function forms another signed expression:

**signed half-width plus selected position.**

That result is interpreted as unsigned for comparison with the available count. The upper-bound condition is satisfied when the available count is less than or equal to that unsigned value.

When the condition is satisfied:

- End becomes available count minus one.
- Start is derived by subtracting the requested width from that end and then adding one.

The subtraction and addition used to form this start are unsigned before the result is stored through the signed start-output address.

For ordinary positive widths and non-overflowing signed arithmetic, the start simplifies numerically to available count minus requested width. Thus this path places the interval against the upper end of the available range.

The comparison is inclusive. Equality selects this upper-aligned path.

#### Neither lower nor upper condition applies

If the initial start is nonnegative and the upper-bound condition is false:

- Start remains the initial start candidate.
- End becomes requested width plus that start, minus one.

The end calculation uses unsigned arithmetic.

For ordinary positive widths without problematic conversions or signed overflow, this yields an inclusive interval containing exactly the requested number of positions.

### Final output order

Every non-early-exit path writes:

1. The start output.
2. The end output.

No object fields are read after these stores begin. The function does not reread inputs to account for changes caused by output aliasing.

### Ordinary-range interpretation

With a positive requested width smaller than the available count, ordinary nonnegative positions, and representable signed intermediate arithmetic, the behavior is a centered interval with boundary adjustment:

- Near the beginning, return the first requested-width interval.
- Near the end, return the last requested-width interval.
- Otherwise, subtract half the width from the selected position and return an interval of the requested width.

For an even width, an interior interval places more positions before the selected position than after it. For example, width four around position five produces positions three through six.

This interpretation does not replace the arithmetic rules for zero widths, high-bit-set widths, invalid positions, or overflow-sensitive inputs.
