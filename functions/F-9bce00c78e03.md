# F-9bce00c78e03

## Purpose

The available static evidence describes a low-level routine that conditionally performs an iterative sequence of indirect calls, then performs four more indirect calls and four memory writes before reaching an undecoded terminal operation.

No application-level purpose is established. In particular, the evidence does not establish that the routine constructs an object, initializes a device, processes a buffer, or implements a conventional error path.

The recovered control flow is explicitly marked unreliable because of invalid instruction data. This contract therefore distinguishes:

- **Established static evidence:** operations and relationships represented in the supplied listing.
- **Inferred intent:** interpretations consistent with those operations but not independently established.
- **`documented_only` unknowns:** behavior that cannot be resolved from the available evidence.

This is a conditional description of the represented execution path, not a claim that the recovered routine is executable as shown.

## Behavior

### 1. Initial branch

The routine first evaluates whether the signed third input is greater than −64.

- At −64 or below, it skips the loop.
- At −63 or above, it enters the loop.
- No validation of the implicit state is visible before this decision.

If the loop is skipped, the incoming base state remains the source of the later word reads, subject to any effects of the intervening dependencies.

### 2. Iterative phase

Each represented iteration derives a replacement decision value from the current base and numeric states.

The numeric state is doubled using 32-bit arithmetic. If bit 31 of that doubled result is set, the calculation includes an additional one; otherwise it includes zero. Equivalently, under the bit-vector model, this additional value reflects bit 30 of the original numeric state. It is not a general sign test of the original numeric state.

The replacement decision value is the low 32 bits of:

- The address-valued base state;
- Plus the numeric state;
- Plus that zero-or-one adjustment.

The routine then invokes dependency **F-U01**. Its target is derived from the current control-flow state by adding 0xEB2. Before the call, the represented control-flow state is replaced with the fixed value 0x08570171.

The four represented arguments to F-U01, in argument-position order, are:

1. Four times the pre-update numeric state, plus 0x53.
2. The pre-update numeric state.
3. Twice the pre-update numeric state, minus 0x67.
4. The pre-update numeric state shifted left by three bits.

All four are 32-bit values. No visible return value from F-U01 is consumed.

After the call returns, the represented state updates are:

- The base state becomes the replacement decision value plus 0x35.
- The numeric state becomes the replacement decision value.

The replacement decision value is then interpreted as signed for the next comparison against −64.

Consequently, the initial third input controls only whether the first iteration occurs. It is not visibly a count, length, or decrementing budget. No finite iteration bound is established.

If the represented control-flow assignment survives the intervening execution as shown, later loop calls use the target derived from 0x08570171 plus 0xEB2. The validity of that target and the effect of the actual calling convention are not established.

### 3. Post-loop dependency sequence

After the loop is skipped or exits, the represented order is:

1. Invoke **F-U02**, at a target derived from the current control-flow state plus 0xFB8.
2. Invoke **F-U03**, at the target represented by 0x08570199 plus 0x7FA.
3. Invoke **F-U04**, at the target represented by 0x0857019B plus 0xFFA.
4. Read a 32-bit word from the base state at byte offset 16.
5. Read the 32-bit words at base offsets 0 and 4 for the next call’s arguments.
6. Invoke **F-U05**, at the target represented by 0x0857019D plus 0xF9A.

F-U02, F-U03, and F-U04 have no explicitly represented arguments. That does not establish a zero-argument machine-level interface: residual registers, stack contents, or implicit state may still matter.

The 32-bit result of F-U04 becomes the first represented argument to F-U05. The words at base offsets 0 and 4 become its second and third arguments, respectively.

The word at base offset 16 is captured before F-U05 and retained for the subsequent writes. Below, this captured word is called the **destination value**.

The relative order of the two argument-word reads is not established by the listing. Their association with the second and third argument positions is established.

### 4. Final memory writes

If F-U05 returns, its represented 32-bit result determines the first write address. The routine then performs these writes in order:

| Order | Address calculation | Width | Stored value |
|---|---|---:|---|
| 1 | Four times the F-U05 result, minus 0x4E | 16 bits | Low 16 bits of the destination value plus 0x94 |
| 2 | Destination value plus 0x97 | 32 bits | Value read from an unresolved external data location |
| 3 | Destination value plus 0x9B | 32 bits | Destination value plus 0xE6 |
| 4 | Destination value plus 0x9F | 32 bits | Twice the quantity “destination value plus 0x97” |

Address and full-width value calculations use the low 32 bits under the stated interpretation.

The fourth stored value is twice an address-like quantity. It is not represented as an address advanced by two bytes, nor as an element index.

The external value used in the second write is not shown as being captured before the dependency calls. Its value must not be assumed invariant across those calls.

No further ordinary operation is represented after these writes. The next event is the invalid-instruction terminal marker.

## Acceptance examples

These are conditional acceptance criteria derived from static evidence, not executed tests.

### Boundary: loop skipped

Given a third input of −64, the first visible phase is the post-loop dependency sequence. No F-U01 invocation is required by the represented control flow.

The same applies to any smaller signed 32-bit input.

### Boundary: loop entered

Given a third input of −63, the routine enters the iterative phase. This does not guarantee a second iteration: the replacement decision value determines the next branch.

### One-iteration exit

Assume a base-state bit pattern of 0xFFFFFFC0 and numeric state zero, and assume F-U01 returns without invalidating the represented execution.

The replacement decision value is 0xFFFFFFC0, interpreted as −64. F-U01 receives 0x53, zero, 0xFFFFFF99, and zero. The base state then becomes 0xFFFFFFF5, and the loop exits.

This example does not establish that the resulting base address is readable.

### Adjustment-bit boundary

With numeric state 0x40000000, doubling produces 0x80000000, so the additional adjustment is one.

With numeric state 0x80000000, doubling produces zero in 32 bits, so the adjustment is zero. Treating every negative numeric state as requiring the adjustment would therefore be incorrect.

### Final-store arithmetic

Assume the destination value is 0x1000, F-U05 returns 0x2000, all dependencies return, and all accesses are valid.

The ordered writes are:

1. A 16-bit value of 0x1094 at address 0x7FB2.
2. The external 32-bit value at address 0x1097.
3. The 32-bit value 0x10E6 at address 0x109B.
4. The 32-bit value 0x212E at address 0x109F.

This example requires support for the resulting access alignments; it does not establish such support.

### Dependency mutation

If F-U04 changes the word at base offset 16 before returning, the later read observes that changed word, assuming no intervening change or access failure. An acceptance criterion requiring the entry-time word would contradict the represented read ordering.
