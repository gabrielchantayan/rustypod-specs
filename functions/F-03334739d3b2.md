# F-03334739d3b2

## Purpose

F-03334739d3b2 performs an initialization sequence and then runs an unconditional processing loop. A byte in a caller-supplied state object selects between two processing modes:

- **Zero mode:** obtain a 32-bit value through an indirect callback, submit that value to a dependency, and record it in an indexed pair of state entries.
- **Nonzero mode:** alternate between two state-held 32-bit values, submit one, record it, and invoke another indirect callback with the opposite value.

These mode names describe the observed branch condition, not an established application-level meaning. The repeated size-like argument `0x1000` and callback argument `0x400` suggest fixed-unit processing, but their units and relationship are unknown.

The function has no reachable normal return in the supplied static representation. It does not inspect dependency return values or expose an explicit error result.

## Behavior

### Entry and initialization

The function first snapshots the first external global into a private four-byte cell and places the fourth argument into another private four-byte cell. Subsequent zero-mode callbacks receive the address of the latter cell.

It then performs this ordered initialization sequence:

1. Invoke an externally referenced dependency with the state address plus `0x3c`.
2. Invoke F-19c890fcf0ce with `6`.
3. Invoke an external dependency with the three arguments `0x10`, `0`, and `1`.
4. Read the second external global and pass its value to F-d34ed3423126.
5. Invoke F-515c23f9254b with `1`.
6. Invoke F-2290ce995e83 with the address of the private cell containing the first global’s entry snapshot.
7. Invoke F-557ed731ad0e with `0x5c`.
8. Read the four-byte field at `0x30` and pass it to F-34751ba0ae74.
9. Read the four-byte field at `0x2c` and pass it to F-34751ba0ae74.
10. Invoke another external dependency with `0x36`.

The `0x5c` passed in step 7 is a literal argument, not an address of the index field.

These calls are not known to preserve state or globals. Consequently, later reads use the contents present at those later points, not necessarily entry-time contents.

The function next reads the mode byte.

**If the byte is zero:**

1. Invoke F-9cd38f533e00 with `0x12`.
2. Read and invoke the callback target at `0x38`, passing `0x400` and the address of the fourth-argument working cell.
3. Read the handle at `0x30`.
4. Invoke F-b3f03f4809f5 with that handle, `0x1000`, and the working cell’s current value.

**If the byte is nonzero:**

1. Invoke F-9cd38f533e00 with `1`.
2. Invoke F-b3f03f4809f5 with the handle at `0x2c`, `0x1000`, and the value at `0x44`.
3. Write the marker byte at `0x60` as `0x41`.

There is no initial indexed-record write or index increment in either branch.

After either branch, invoke F-58b3b644ea3d with the state address plus `0x3c`. The unconditional loop then begins.

### Loop entry and mode selection

Every iteration starts by invoking the same externally referenced dependency used in initialization step 1, again with the address at offset `0x3c`.

Only after that call returns does the function read the mode byte for that iteration. Mode selection is therefore not fixed at entry. A mutation made by an earlier dependency or callback can affect a later branch.

Within one iteration, the function does not reselect the branch merely because a callback changes the mode byte. The next mode decision occurs in the following iteration.

### Zero-mode iteration

When the mode byte is zero:

1. Read and invoke the callback at `0x38` with `0x400` and the address of the persistent private working cell.
2. Invoke F-d4beacd67049 with the current handle at `0x30`, `0x1000`, and the working cell’s current value.
3. Record that working-cell value using the indexed procedure below.

The working cell is initialized only once, from the fourth argument. It is not reset before callbacks. If a callback leaves it unchanged, its previous contents remain available to the next call and submission.

F-d4beacd67049 executes before indexed recording. Its effects must not be assumed absent: the later index read occurs after it returns. If a dependency has retained and can validly access the working-cell address, the cell’s value at recording time is not guaranteed to equal its earlier submitted value.

### Nonzero-mode iteration

When the mode byte is nonzero, the marker at `0x60` selects a branch.

**Marker equals `0x41`:**

1. Invoke F-d4beacd67049 with the handle at `0x2c`, `0x1000`, and the value read from `0x48`.
2. Write the marker as `0x42`.
3. Read the value at `0x48` again and record it using the indexed procedure.
4. Read the value at `0x44` as the argument for the subsequent callback.

**Marker is anything other than `0x41`:**

1. Invoke F-d4beacd67049 with the handle at `0x2c`, `0x1000`, and the value read from `0x44`.
2. Write the marker as `0x41`.
3. Read the value at `0x44` again and record it using the indexed procedure.
4. Read the value at `0x48` as the argument for the subsequent callback.

After either branch, read and invoke the callback target at `0x34` with `0x400` and the opposite value selected in step 4.

The submitted value and recorded value are separate field reads, with F-d4beacd67049 between them. They need not match if that dependency changes the selected field.

The marker test is an exact comparison with `0x41`. There is no separate validation of `0x42`; any other byte takes the second branch.

### Indexed recording

All recording branches use this observable sequence:

1. Read the four-byte index at `0x5c` for destination selection.
2. Write the selected four-byte value at the state base plus `0x4c` plus four times that index.
3. Read the index at `0x5c` again.
4. Write its incremented value back to `0x5c`.
5. Using the index captured in step 3, write the four-byte constant `0x1000` at the state base plus `0x54` plus four times that captured index.
6. Read the current index field and compare it as an unsigned 32-bit value with `1`.
7. If it is greater than `1`, write zero to the index field.

For ordinary indices `0` and `1`, absent interfering mutation or unexpected aliasing, this alternates between the two apparent slot pairs.

The two index reads are distinct. An out-of-range first write can overlap the index field and thereby change the index used by the remaining operations. The comparison is also performed after the constant write, so that write may affect the index if addresses overlap.

The reset is not a pre-access bounds check. For example, initial index `2` causes the first recorded-value write to target offset `0x54`, not an ordinary recorded-value slot.

The observed storage widths and comparison are 32-bit. Exact signed-overflow and address-overflow behavior is not independently established for extreme index values; no portable mathematical-integer guarantee should be inferred.

### Iteration completion

After the selected branch finishes, invoke F-58b3b644ea3d with the address at offset `0x3c`. Then begin another iteration unconditionally.

There is no visible termination flag, loop count, cancellation check, or dependency-result check.

## Acceptance examples

These examples are conditional static expectations, not executed tests. Unless stated otherwise, assume valid storage, returning dependencies, and no mutation beyond the actions expressly described.

### Zero-mode initialization and first recording

Given mode zero, index zero, and a callback that writes value X during initialization:

- Initial submission uses the handle at `0x30`, `0x1000`, and X.
- Initialization does not record X into the slot pairs.
- If the first loop callback then writes Y, loop submission uses Y.
- Recording writes Y at `0x4c`, writes `0x1000` at `0x54`, and leaves the index as `1`.

If the next callback writes Z, the next recording writes Z at `0x50`, writes `0x1000` at `0x58`, and resets the index to zero.

### Callback leaves the working cell unchanged

### Stable nonzero mode

Given nonzero mode, index zero, value A at `0x44`, and value B at `0x48`:

- Initialization submits A and writes marker `0x41`.
- The first loop iteration submits and records B, writes marker `0x42`, and invokes the callback at `0x34` with A.
- The second iteration submits and records A, writes marker `0x41`, and invokes that callback with B.

The respective callback first argument is always `0x400`.

### Submission changes the selected value

Given a nonzero iteration selecting `0x48`, if F-d4beacd67049 changes that field from B to C:

- Its submitted argument is B.
- The subsequent recorded value is C.
- Recording must not be specified as necessarily reproducing the submitted argument.

### Unexpected marker

Given nonzero mode at loop selection and marker `0x00`, the iteration uses the `0x44` branch and writes marker `0x41`. It does not reject the marker.

### Invalid index is not repaired first

Given index `2`, recording first writes the selected value at `0x54`, increments the index to `3`, writes `0x1000` at `0x5c`, and then resets the index to zero because its unsigned value is greater than `1`.

This example demonstrates overlapping writes, not supported two-slot usage.
