# F-23ded9d093d9

## Purpose

F-23ded9d093d9 replaces two adjacent four-byte fields in caller-provided storage using two adjacent four-byte values from another supplied location. The destination fields occupy byte offsets 36–39 and 40–43 relative to the destination base. Their replacement values come from source offsets 0–3 and 4–7, respectively.

The operation has a fixed footprint. Neither the values being transferred nor the previous destination contents affect the field locations, transfer size, or completion path. Normal completion produces no return value or status.

Both replacement values are obtained before either destination field is modified. For valid accesses to stable ordinary memory, this preserves the selected values even when destination writes overlap the source.

**Inferred intent:** replacement of a two-field value within an existing object. The application meaning of the fields and the identity or lifecycle of the surrounding object are not established.

## Behavior

### Replacement contract

On normal completion, the first destination field contains the value obtained from the first source position, and the second destination field contains the value obtained from the second source position.

The old destination values are not consulted independently. They matter only if a source read reaches the same storage through aliasing.

All four-byte contents follow the same replacement rule. Zero values, identical source values, and values already present in the destination receive no special treatment. There is no content-dependent branch or identity-based early exit.

### Observation and modification order

The static evidence establishes these access relationships:

- The second source value is observed before the first source value.
- Both source observations precede the first destination modification.
- The first destination field is modified before the second destination field.

These are behavioral ordering constraints, not a requirement for a particular machine-instruction sequence or number of physical memory transactions.

The two reads do not constitute a simultaneous snapshot. If an execution environment legally permits the source to change between observations, the selected pair need not have existed together at one instant. This statement does not authorize data races or otherwise invalid concurrent access.

Likewise, the two writes do not establish an indivisible destination transition. Pair-wide atomicity, individual-access atomicity, and visibility to other observers are not established.

### Aliasing and overlap

The expressed operation does not require disjoint source and destination storage. For legal accesses to stable ordinary memory, overlap does not change which values are selected: both have already been obtained when destination modification begins.

In particular, when the second source value occupies the first destination field, overwriting that field does not replace the value already selected for the second destination field. The result is not a cascading copy in which the first replacement becomes the second replacement’s input.

When the source footprint exactly coincides with the destination fields, stable memory retains the same final values. This outcome does not imply an identity check or omitted accesses.

The source input is used only for reads. Nevertheless, destination writes can change source-designated storage when the two regions alias. “Source” identifies an access role, not a guarantee that those addresses remain unchanged.

Arbitrary partial overlap is not established as legal. Misaligned or otherwise invalid overlapping accesses remain outside the normal-completion preconditions.

### Address arithmetic

The destination displacements are fixed at 36 and 40 bytes. Source contents cannot redirect the writes.

Address formation uses the supplied signed destination-base representation. Its arithmetic must not be replaced by an assumed modulo-address-width calculation. If a required addition is outside the representable signed range, the evidence establishes no successful outcome.

Because the signed-integer width is not independently established, this contract does not specify a numerical maximum accepted base. Nor does representable arithmetic alone guarantee a usable address: conversion, mapped storage, permissions, bounds, and alignment remain separate requirements.

There is no boundary-aware shortening of the operation. Storage sufficient for only one source value or one destination field does not request a smaller transfer.

### Failure and interruption

There is no expressed diagnostic, failure return, exception handler, retry, recovery path, or rollback.

Under an execution model that reports a failed source read before allowing later accesses to proceed, that failure precedes destination modification. This is a conditional ordering consequence, not a general safety guarantee for invalid accesses. Where an invalid access leaves execution unconstrained, unchanged destination storage cannot be promised.

The destination update is not transactional. If the first field is replaced but the second replacement cannot complete, no restoration of the first field is expressed.

Failure delivery and the partial effects of an unsuccessful individual access are **documented_only**. The evidence does not choose among termination, a signal, an exception, or another environmental response.
