# F-13921f01a2ea

## Purpose

F-13921f01a2ea refreshes a four-word region of a supplied record, optionally processes that region with a corresponding region in a linked record, and passes the refreshed region and its saved predecessor to a second dependency. A nonzero result from that second dependency can trigger propagation of a flag through linked records.

The function also returns a 64-bit value assembled from the first two words of the saved predecessor **as they exist after the dependency calls**. Those words are initially copied from the record, but one dependency receives their address. The return value therefore cannot be specified unconditionally as the original contents.

The interpretation of the four-word regions is unknown. They might represent a composite value, but no geometric, numeric, or application-specific meaning is established. Likewise, the propagation flag’s meaning is unknown.

This contract distinguishes visible behavior from dependency behavior. It does not assume that either dependency preserves record contents, follows a particular ownership convention, or implements a comparison or combination operation.

## Interface

### Input

The function takes one argument representing the base address of a mutable record. The supplied representation uses a 32-bit integer for this address.

The following record-relative locations are accessed directly:

| Offset | Width | Observed role |
|---|---:|---|
| `0x34` | 32 bits | Link value; zero means no linked record for this operation |
| `0x48` | 32 bits | Flag word; bit mask `0x00000080` controls propagation |
| `0x80`, `0x84`, `0x88`, `0x8C` | Four 32-bit words | Source region used to refresh the working region |
| `0xD0`, `0xD4`, `0xD8`, `0xDC` | Four 32-bit words | Working region, initially saved and then overwritten |

The same `0x34`, `0x48`, and `0xD0` offsets are used relative to linked-record addresses where applicable.

These are minimum observed access requirements, not a complete record definition. The highest direct word access on the input record begins at `0xDC` and covers four bytes.

### Output

On normal completion, the function returns a 64-bit bit pattern:

- Bits 0–31 come from the first word of its local saved region.
- Bits 32–63 come from the second word of that region.
- The third and fourth saved words do not directly contribute to the return value.

This specifies word significance, not a byte-order requirement for external serialization. No numeric signedness, floating-point interpretation, or semantic value type is established for the returned pattern.

### Preconditions and validity

The function performs no visible null check on its input and no visible bounds, alignment, or lifetime checks. Its direct accesses require valid readable and writable storage at the relevant offsets. Dependencies can impose additional requirements that are not available here.

A nonzero linked-record value must support whichever accesses are actually reached. An invalid nonzero link is not rejected before use.

The address representation is 32 bits in the supplied evidence. Behavior for address arithmetic that overflows that representation, violates target addressing requirements, or refers outside valid storage is not established. This contract does not introduce widened address arithmetic or portable overflow guarantees.

## Behavior

### 1. Capture the initial link and working-region contents

The function first reads the input record’s link at offset `0x34`. It retains this value for both the optional dependency call and the start of any later flag propagation.

It then reads the four working-region words at offsets `0xD0`, `0xD4`, `0xD8`, and `0xDC`, in that order, into a local saved region.

These reads precede the working-region replacement. Consequently, in ordinary valid execution without external interference, the saved region initially contains the working region’s pre-refresh contents.

The retained link is not reloaded from the input record before propagation. A dependency’s later change to the input record’s link does not, by itself, change the retained starting link.

### 2. Refresh the working region

The four source words replace the corresponding working-region words in ascending offset order:

| Source offset | Destination offset |
|---|---|
| `0x80` | `0xD0` |
| `0x84` | `0xD4` |
| `0x88` | `0xD8` |
| `0x8C` | `0xDC` |

Each source word is read for its corresponding destination write. The visible sequence is not a single atomic 16-byte replacement and is not shown as a separate preliminary snapshot of all four source words.

All four replacements occur before either dependency is called. This refresh is unconditional: it happens even when the retained link is zero, the propagation flag is already set, or the second dependency will return zero.

### 3. Optionally process the linked working region

If the retained initial link is nonzero, the function calls F-ee8733a08210 with two addresses, in this order:

1. The input record’s working region at offset `0xD0`.
2. The retained linked record’s working region at offset `0xD0`.

The function does not inspect a return value from this call.

The call is skipped only when the retained initial link is zero. There is no visible flag-based gate for this call.

No precise transformation can be assigned to F-ee8733a08210 from this evidence. In particular, the contract does not assume that it leaves either argument unchanged. The next dependency receives the input record’s working region in whatever state exists after this call completes.

### 4. Invoke the result-producing dependency

The function next calls F-8b354e218ab8 with:

1. The address of the input record’s working region.
2. The address of the local saved region.

This call occurs regardless of whether the initial link was zero. If F-ee8733a08210 was called, it finishes before F-8b354e218ab8 is invoked.

The result used by F-13921f01a2ea is a 32-bit integer. Its only visible interpretation is zero versus nonzero. Negative nonzero values are not treated differently from positive nonzero values.

The second argument points to locally saved data, not the original working-region storage. Its first two words later supply the return value. Because this dependency receives their address, the evidence does not establish that those words remain unchanged.

### 5. Gate flag propagation

If F-8b354e218ab8 returns zero, the function performs no direct flag read or flag write in the propagation phase.

If it returns nonzero, the function reads the input record’s flag word at offset `0x48`.

- If mask `0x00000080` is already set, the function performs no direct propagation writes and does not traverse the retained link.
- If the mask is clear, the function sets it in the input record and then considers the retained linked record.

Setting the flag is a read-modify-write operation on the 32-bit word: the mask is ORed into a freshly read word, preserving its other bits as observed by that update. The condition read and update read are distinct visible operations. No atomicity or concurrency guarantee is established.

These decisions use record state after the dependency calls. The function does not preserve an entry-time copy of the input record’s flags.

### 6. Propagate through linked records

Propagation begins at the nonzero link captured before the refresh and dependency calls, not at a newly read input-record link.

For each candidate linked record:

1. A zero candidate ends traversal without a record access through that candidate.
2. Otherwise, its 32-bit flag word is read.
3. If mask `0x00000080` is already set, traversal ends at that record.
4. If the mask is clear, the function sets it using a read-modify-write operation.
5. Only after that write does it read the candidate’s link at offset `0x34` to obtain the next candidate.

An already-marked record is a stopping boundary. The function does not skip that record and continue to its successor. In particular, the stopping record’s link is not read by this traversal.

There is no explicit traversal count, recursion, separate visited set, or malformed-link diagnostic.

With stable, valid records and no interference, the flag itself also stops revisits. A self-link or finite cycle therefore terminates when traversal reaches a record whose flag has already been set, including the input record, whose flag was set before traversal began. This conditional termination property does not establish safety for invalid links or concurrently changing records.

### 7. Construct the return value

After the propagation decision and any traversal, the function constructs the return value from the first and second words of the local saved region.

It does not directly return:

- The result of F-8b354e218ab8.
- Any result from F-ee8733a08210.
- The refreshed working region.
- A propagation count or completion status.

If the saved first two words remain unchanged, the return contains the corresponding pre-refresh working-region words. If F-8b354e218ab8 changes them through the supplied address, the changed words determine the return.

## Side effects

### Direct record changes

The function directly performs these writes:

- Four unconditional 32-bit writes refreshing the input record’s working region.
- A conditional write setting `0x00000080` in the input record’s flag word.
- Conditional writes setting that same mask in a prefix of the linked chain, stopping at zero or an already-marked record.

There is no direct write to a link field or to the source region. Dependencies may change those locations; preservation is not established.

The function’s direct flag updates do not clear any flag bit. They preserve all bits other than the target mask according to the word read for each update.

### Local storage and ownership

The function uses a local saved region consisting of four 32-bit words. It exposes its address to F-8b354e218ab8 during the call.

No direct allocation, deallocation, record destruction, or ownership transfer is visible. This absence does not establish that dependencies allocate nothing, release nothing, or retain no addresses.

The function returns a value rather than the address of its local saved region. Any dependency retaining that address would require a separate lifetime contract; none is available.

### Errors and exceptional execution

There is no visible explicit error code, validation failure path, rollback, or recovery mechanism.

A zero dependency result is a propagation gate, not an established error indication. A nonzero result is not an established success indication beyond permitting the subsequent flag check.

If an access or dependency call prevents normal completion, the evidence provides no promise that earlier writes are undone. In particular, the working-region replacement precedes both calls.

## Acceptance examples

These examples are conditional behavioral checks, not reports of executed tests. Except where stated otherwise, they assume valid storage, normal dependency returns, and no external interference.

### No linked record and zero result

Given an initial zero link and a zero result from F-8b354e218ab8:

- The four working words are saved and then replaced.
- F-ee8733a08210 is not called.
- F-8b354e218ab8 is called with the refreshed working region and saved region.
- No direct flag read or write follows.
- The return is assembled from the saved region’s first two words after that call.

### Linked record and zero result

Given a nonzero initial link and a zero result from F-8b354e218ab8:

- F-ee8733a08210 is called before F-8b354e218ab8.
- No direct propagation occurs, regardless of the input or linked flags.
- Dependency side effects remain possible.

### Input already marked

Given a nonzero dependency result and an input flag word already containing `0x00000080` when checked:

- The refresh and applicable dependency calls have already occurred.
- The function does not directly rewrite the input flag.
- It does not inspect the retained linked record’s flags for propagation.

### Stop at a marked linked record

Suppose the input and its first linked record have the mask clear, while the following record has it set. Given a nonzero dependency result:

- The input and first linked record are marked.
- The following record’s flag is read but not directly rewritten.
- Its link is not read.
- No later record is reached by direct propagation.

### Preserve unrelated flag bits

If a record’s flag word is `0x00000201` when read for an eligible update, the written word is `0x00000281`. The update adds the propagation mask without clearing the other observed bits.

### Return-word significance

If the saved first word is `0x11223344` and the second is `0x55667788` at return construction, the result is `0x5566778811223344`.

This remains true whether those values came from the original working region or were written into the saved region by F-8b354e218ab8.

### Dependency changes the input link

Suppose the initially captured link identifies record A, and a dependency subsequently changes the input record’s link to record B. If propagation is enabled, it starts at A. Links used after marking A are read from the records visited during traversal.

### Self-linked input

Given an initial link back to the input record, a nonzero dependency result, and an initially clear input mask:

- The optional linked-region call receives the same working-region address twice.
- After the dependencies, the input is marked if its mask remains clear.
- Traversal then encounters that marked input record and stops without reading its link again.
