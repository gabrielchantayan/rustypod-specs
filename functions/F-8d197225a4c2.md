# F-8d197225a4c2

## Purpose

F-8d197225a4c2 performs a fixed sequence of indirect operations on a caller-supplied object and an embedded interface. It captures a 32-bit value through the embedded interface, invokes another operation on that interface, reads a word at byte offset 8 from the captured value interpreted as an address, stores that word into the caller-supplied object, and performs two dispatches through the outer object.

After those dispatches, a nonzero captured value causes a call to F-feee9156a257. That dependency is identified in the supplied static material as not returning. A zero captured value permits ordinary return only if all preceding accesses and calls have completed successfully.

The apparent intent is to transfer some state from an embedded interface into the outer object and then issue two notifications or updates. The meanings of the transferred state, the two dispatches, and the final nonreturning operation are not established.

## Behavior

### 1. Invoke the first embedded-interface operation

The function forms the address of the embedded interface at outer-object offset 252.

It obtains a callable address from byte offset 64 of that interface’s dispatch table. The supplied call expression also obtains the callable address from that same table entry as an explicit argument.

The operation receives five explicit arguments, in this order:

1. The embedded-interface address.
2. A zero value.
3. A callable address read from the interface table at byte offset 64.
4. The fourth input parameter.
5. The fourth input parameter again.

The fourth input’s two occurrences carry the same 32-bit input value.

The call target and the callable-address argument are expressed as separate table lookups. The supplied material does not establish their relative evaluation order or guarantee that both lookups observe the same table contents under external mutation. In a stable object and table, they identify the same entry.

The returned value is interpreted as the address of a readable 32-bit word. The function immediately reads that word and retains its value. In the remainder of this contract, that retained word is the **captured address value**.

No null or validity check precedes the read through the returned address.

### 2. Invoke the second embedded-interface operation

After capturing the word, the function obtains the embedded interface’s dispatch-table address again from outer-object offset 252. It selects the entry at table byte offset 44 and invokes it with:

1. The embedded-interface address.
2. Zero.

The table is therefore consulted again after the first dependency returns. A table replacement performed by the first operation can affect the second operation’s target.

The second operation’s return value, if any, is not used.

The captured address value remains the word read before this second operation. The function does not reread that word from the first operation’s returned address.

### 3. Read through the captured address and update the outer object

After the second embedded-interface operation returns, the function interprets the captured value as an address. It reads a 32-bit word at byte offset 8 from that address and writes the word to outer-object offset 248.

This is one explicit four-byte replacement, not a merge, increment, or conditional update. The previous destination value is not explicitly read.

The order is significant:

- The captured address value is acquired before the second embedded operation.
- The word at captured-address offset 8 is acquired after that operation.
- The destination write occurs before the external-value reads and outer dispatches described below.

Consequently, a change by the second embedded operation to the word at captured-address offset 8 can affect the copied value. A change to the word originally returned by the first operation does not, by itself, replace the already captured address value.

There is no check that the captured address remains valid after the second operation. The supplied body provides no evidence that the second operation preserves, releases, or transfers ownership of the referenced storage.

### 4. Perform the first outer dispatch

After updating the destination field, the function reads external location A and retains that 32-bit value for later use.

It then dispatches through the outer object’s table entry at byte offset 88. The explicit arguments are:

1. The outer-object address.
2. A value read from A for this first dispatch.
3. A value read from B.

The retained read of A and the first dispatch’s argument read of A are distinct evaluations. Both precede entry into the first outer operation, but the relative evaluation order of the call target, A argument, and B argument is not established by the supplied expression.

The first dispatch’s return value, if any, is not used.

### 5. Perform the second outer dispatch

After the first outer operation returns, the function again obtains the outer dispatch-table address from the object and selects its entry at byte offset 88.

The explicit arguments are:

1. The outer-object address.
2. The retained value from the earlier read of A.
3. A value read from C after the first outer operation returns.

The first outer operation can therefore affect the second call by changing the outer dispatch table or C. A change to A does not change the second call’s retained argument: that argument was captured before the first outer call.

Both outer calls occur after the destination-field write. Either callee may observe or modify that field. This function does not restore it afterward.

### 6. Select the terminal outcome

Only after the second outer operation returns does the function compare the captured address value with zero.

- If nonzero, it calls F-feee9156a257 with no explicit arguments. The supplied static material marks that dependency as nonreturning.
- If zero, it reaches ordinary return.

This comparison is not a guard for the earlier access at captured-address offset 8. That access has already occurred.

In the zero case, the earlier read targets numeric address 8 under the represented address calculation. Ordinary return therefore remains conditional on that address being readable and on all preceding calls completing. The function does not implement a safe null-result shortcut.

No rollback is shown.

## Acceptance examples

These examples are conditional static acceptance cases, not executed tests.

### Stable successful nonzero path

Assume valid objects and tables, all four indirect operations return, the first operation returns readable storage containing a nonzero address, and that address plus 8 is readable after the second embedded operation.

Expected behavior:

- The two embedded operations occur before either outer operation.
- The destination field receives the four-byte value read at captured-address offset 8.
- The outer operation is invoked twice.
- F-feee9156a257 is then invoked.
- No ordinary return is expected under the supplied nonreturning annotation.

### Mutation of the referenced data

Assume the captured address points to valid storage and the second embedded operation changes the four-byte word at that address plus 8.

Expected behavior: the changed word is copied to outer-object offset 248, because the data read follows that operation.

### Mutation of the returned word

Assume the second embedded operation changes the original word read through the first operation’s return address, but leaves the already captured address valid.

Expected behavior: the original captured address still controls both the offset-8 read and the final zero comparison.

### External values changed by the first outer operation

Assume the retained read of A produced value P. The first outer operation then changes A to Q and C to R.

Expected behavior:

- The second outer operation receives P as its second explicit argument.
- It receives R as its third explicit argument, provided C remains R until that read.
- A is not reread to construct the second operation’s retained argument.

### Dispatch-table replacement

Assume the first outer operation replaces the outer object’s table pointer with another valid table.

Expected behavior: the second outer operation uses byte offset 88 of the replacement table.

### Zero captured value

Assume the captured value is zero.

Expected behavior:

- The function still attempts the four-byte read at numeric address 8 before checking zero.
- If that read and the remaining operations succeed, both outer dispatches occur and the function returns without calling F-feee9156a257.
- If address 8 is inaccessible, the zero comparison is not reached through the shown normal sequence.
