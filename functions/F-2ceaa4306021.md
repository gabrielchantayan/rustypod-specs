## Behavior

### Payload construction

The function prepares a four-byte temporary region containing two adjacent 16-bit values.

| Offset from payload address | Extent | Stored value |
|---|---:|---|
| 0 | 2 bytes | A 16-bit value whose high-order byte is the second input and whose low-order byte is the first input. |
| 2 | 2 bytes | The upper 16 bits of the fourth input. |

The first value is numerically equivalent to 256 times the second input plus the first input, treating both as unsigned eight-bit quantities. The largest possible value is 65,535, so this construction fits exactly in 16 bits.

The second value is obtained by treating the fourth input as an unsigned 32-bit quantity, shifting it right by 16 bits, and retaining the resulting 16-bit value. This is a logical extraction of bits 31–16, not a signed division or arithmetic right shift. The lower half of the fourth input contributes nothing to the payload.

The construction explicitly establishes all four bytes through the two 16-bit stores. There is no visible gap between the stored values and no explicit read of prior temporary contents.

The visible initialization order is:

1. Store the upper half of the fourth input at payload offset 2.
2. Store the combined first and second inputs at payload offset 0.

Both stores occur before the first dependency call.

The numeric values and their relative offsets are established. Their byte representation depends on target byte order. On a little-endian target, the four bytes in increasing address order are the first input, the second input, bits 23–16 of the fourth input, and bits 31–24 of the fourth input. On a big-endian target, each 16-bit value has its high-order byte first. The supplied evidence does not independently establish target endianness.
