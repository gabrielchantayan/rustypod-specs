# F-c58426bb570e

## Purpose

Each raw candidate triggers acquisition of a stream prefix and callback-driven inspection. An accepted inspection returns zero without explicitly releasing that prefix. One acceptance branch also stores a numeric-conversion result.

Locating a CID-font resource’s data boundary is **inferred intent**, not a verified dependency contract. The established behavior consists of direct field accesses, call arguments, result-dependent branches, retained addresses, and return paths.

In particular:

- Zero can mean inspection acceptance **or** raw-scan exhaustion.

### Callback-driven inspection

Inspection maintains three distinct historical address roles:

- **Format address:** passed to the format-related call after marker acceptance.
- **Numeric address:** passed to numeric conversion if the format-related call returns zero.
- **Candidate address:** checked for eligibility and marker acceptance.

Initially, the format address is the retained acquired base. One callback pair runs, and destination offset 0 is captured as the numeric address. A second pair runs. The function then captures destination offset 8 as a fixed bound and reads offset 0 as the first candidate.

For every candidate, the address must be strictly below that captured bound. Only if this condition succeeds is destination offset 12 read and required to equal zero. Failure of either condition rejects the prefix.

For an eligible candidate, the function directly reads its first byte. If that byte is `S`, it calls F-fca51b715561 with the candidate, marker reference, and 9. A zero result accepts the inspection marker.

After marker acceptance, F-fca51b715561 receives the retained format address, format-reference constant, and 5. The format reference’s symbol suggests a parenthesized Hex designation, but the backing bytes and comparison semantics are unknown.

- A zero result causes F-cebbe699fc3e to receive the retained numeric address. Its 32-bit result is written to destination offset 88, and the function returns zero.
- A nonzero result causes return of zero without a direct write to offset 88.

Neither branch explicitly releases the prefix.

If an eligible candidate is not accepted, another callback pair runs. The address history advances: the previous numeric address becomes the next format address, the just-examined candidate becomes the next numeric address, and the newly read destination offset 0 becomes the next candidate.

The new numeric address is therefore **not** the current address produced by that latest callback pair. These transitions are established independently of any tokenization interpretation.

## Acceptance examples

These are conditional static criteria, not executed tests. They assume accessible storage, usable arithmetic, and normal return from dependencies except where specified.

4. **Excluded boundary candidate.** A candidate exactly ten bytes before the computed read end is not examined in that pass. Continuation passes that stopping address to the ten-byte transfer operation. 7. **Third inspection candidate.** If D is also eligible but unaccepted, acceptance at a subsequent candidate E uses C as the format address and D as the numeric address. Token semantics are not required for this progression.
