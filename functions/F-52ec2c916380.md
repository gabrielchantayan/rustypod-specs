# F-52ec2c916380

## Purpose

F-52ec2c916380 conditionally replaces one byte at displacement 44 from a caller-supplied address and returns one of two four-byte result values.

Its behavior is fully distinguished by three selector values:

- Selector **2** writes byte **4** and returns **2**.
- Selector **3** leaves memory untouched and returns **12**.
- Selector **4** writes byte **6** and returns **2**.
- Every other selector writes byte **7** and returns **12**.

These mappings are established by the supplied static evidence. The significance of the destination byte and the meanings of the returned values are unknown. In particular, neither result is established as a success or failure indicator: result 12 accompanies both a no-write case and a write case.

## Interface

### Inputs

The function accepts two integer-form arguments:

| Argument | Contract role |
|---|---|
| Object address | Supplies the address from which the destination byte is located. The destination is at byte displacement 44, equivalently hexadecimal displacement 0x2C. |
| Selector | Determines whether a byte is written, which value is written, and which result is returned. |

The supplied representation presents both arguments as integer values rather than declaring the first as a pointer. A 32-bit integer/address model is consistent with that representation, but the machine ABI, argument-passing convention, and precise pointer representation are not independently established.

The selector comparisons apply to the full integer argument. They are not comparisons of only its low byte. A value whose low byte equals 2, 3, or 4 therefore does not receive the corresponding special behavior unless the complete integer equals that value.

### Output

The function returns a four-byte value whose numerical value is either:

- **2**, for selectors 2 and 4; or
- **12**, for selector 3 and every other selector.

The evidence does not establish a signed return type. Both possible values have the same numerical interpretation under signed and unsigned 32-bit interpretations.

## Behavior

### Selector classification

The function distinguishes complete integer values 2, 3, and 4. All remaining values belong to a single default class.

The static control flow first distinguishes selector 2. For selectors other than 2, it distinguishes selector 3 and then selector 4. This ordering does not cause additional caller-visible memory accesses: classification uses only the supplied selector.

There are no dependency calls, callbacks, or intervening reads of external state.

### Selector 2

The function writes numerical value 4 into the destination byte at displacement 44 and then returns numerical value 2.

The previous byte value is irrelevant. The function does not read it, compare it, merge bits into it, or preserve any subset of its bits. All eight destination bits are replaced.

### Selector 3

The function returns numerical value 12 without reading or writing the destination.

This is not an instruction to write the byte’s current value back. There is no store on this path. That distinction matters for write-protected storage, memory-mapped devices, write monitoring, and concurrent observers.

The value 3 is not stored in the addressed object.

### Selector 4

The function writes numerical value 6 into the destination byte at displacement 44 and then returns numerical value 2.

As with selector 2, the old destination value is not read and does not influence the result.

### Every other selector

The function writes numerical value 7 into the destination byte at displacement 44 and then returns numerical value 12.

This class includes zero, negative values where supported by the argument type, and positive values other than 2, 3, and 4. There is no additional visible range validation.

For example, selector 258 belongs to this default class despite having a low byte equal to 2.

### Access and completion order

On each writing path, the destination-byte write precedes the return. There is exactly one destination write in the supplied behavior. On the selector-3 path, there are no destination reads or writes.

These statements describe the function’s visible operations. They do not establish machine-level atomicity, synchronization, memory barriers, or ordering guarantees for other threads or devices.

### Arithmetic and byte representation

The destination is obtained using a fixed byte displacement of 44. There is no indexing, scaling by an element size, or selector-dependent displacement.

The evidence does not establish what happens when that address calculation exceeds the representable or accessible address range. A portable wraparound rule must not be inferred.

The written values 4, 6, and 7 fit within one byte regardless of whether a character-sized storage type is interpreted as signed or unsigned. No selector value is directly truncated into the destination. Because the store occupies one byte, its value is independent of multibyte endianness.

Additional conditional criteria clarify boundaries:

2. **No-write behavior is specific to selector 3.** Selector 5 returns the same result as selector 3, but must write 7.
3. **Neighboring ordinary storage is preserved.** With a valid ordinary-memory destination and no external interference, bytes immediately before and after displacement 44 are not modified by this function.
4. **Repeated calls overwrite independently.** On valid storage, calls with selectors 2, 4, and 0 leave the destination containing 4, then 6, then 7, with respective returns 2, 2, and 12.
5. **Selector 3 does not probe accessibility.** The body does not access the address-derived destination on that path. This does not establish general safety for arbitrary argument representations.
6. **Invalid write destinations have no specified recovery result.** Acceptance must not require a normal return after an invalid destination access.
