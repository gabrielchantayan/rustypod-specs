# F-7e02bb903ae6

## Purpose

F-7e02bb903ae6 performs an ordered sequence of dependency calls, then waits for a two-part condition associated with a captured 32-bit value:

1. A predicate dependency must return a nonzero result for that value.
2. An 8-bit field at byte offset 38 from the address represented by that value must then contain a nonzero byte.

The function returns normally only after both conditions are observed during one iteration. Every unsuccessful iteration invokes a delay-like dependency with the numeric argument 100 before retrying.

This is a source-facing behavioral contract. The supplied static representation establishes call order, argument construction, conditional memory access, and loop structure. It does not establish the domain meaning of the object, the unit of the delay argument, the ownership of returned values, or the effects of dependencies.

“Preparation,” “acquisition,” “predicate,” and “delay-like” below are descriptive labels for roles visible at the call site, not established application semantics.

## Behavior

### Ordered setup

Before entering the polling loop, the function performs four dependency calls in this order:

1. It calls F-936a8728139d with the object base advanced by 2,480 bytes.
2. It calls F-76b7ec0cf6ba with no explicit arguments and obtains a 32-bit result.
3. It calls F-581aa3d0c697 with that result as its first argument and the caller’s forwarded 32-bit value as its second argument.
4. It calls F-76b7ec0cf6ba again with no explicit arguments and captures this second result for polling.

These two acquisitions are distinct calls. Their results need not be equal. In particular, F-581aa3d0c697 or any earlier dependency may change state consulted by the second acquisition.

The first acquisition result is used for the intervening call to F-581aa3d0c697. The second acquisition result is the value used throughout the loop. The visible function does not compare the two results or substitute the first for the second.

There is no visible success check on the first three calls. If they return normally, execution proceeds to the next call regardless of any result they may provide beyond the explicitly used acquisition value.

### Polling condition

Each iteration begins by calling F-80af6764be49 with the captured second acquisition result.

The predicate result determines whether the function performs its own byte read:

- If the result is zero, the function does not read the byte at offset 38 during that iteration. The iteration is unsuccessful.
- If the result is nonzero, the function reads one byte at offset 38 from the address represented by the captured value.
- If that byte is zero, the iteration is unsuccessful.
- If that byte is nonzero, the loop ends and the function returns normally.

Success requires both observations within the same iteration. A nonzero byte observed in a previous iteration is not retained as a successful condition for a later iteration.

Any nonzero predicate result qualifies, including a negative result under the visible signed-integer interpretation. Likewise, any nonzero byte qualifies. Signed versus unsigned interpretation of the byte does not affect the zero comparison.

The predicate call precedes the byte read. Consequently, any effects of that call occur before the direct read in the visible operation order. The function does not read the byte first and then validate it.

### Retry behavior

Every unsuccessful iteration invokes a delay-like dependency with the single numeric argument 100. After that call completes, the function begins the next iteration by calling F-80af6764be49 again.

The delay-like operation occurs in both unsuccessful cases:

- The predicate returns zero.
- The predicate returns nonzero, but the byte is zero.

It does not occur after a successful condition check. There is also no delay-like call before the first predicate evaluation.

The value supplied to the predicate and used as the address base remains the second acquisition result throughout the loop. F-76b7ec0cf6ba is not called again by this function during polling. Changes to whatever external state that dependency consults do not, by themselves, replace the captured value.

The numeric argument 100 is established; its unit and actual timing effect are not. The supplied evidence does not justify interpreting it as milliseconds, a minimum elapsed duration, or a guarantee that another execution context will run.

### Preconditions and validity

The function contains no explicit local validation of either acquisition result.

In particular:

- The first result is forwarded to F-581aa3d0c697 without a local null or sentinel check.
- The second result is passed to F-80af6764be49 without a local null or sentinel check.
- A nonzero predicate result permits the subsequent byte read without a separate local address-validity check.

A zero predicate result prevents this function’s direct byte read for that iteration. It does not establish that the predicate itself avoids memory access or can safely accept every possible captured value.

For normal completion, the captured address must remain valid whenever the predicate permits the byte read. No visible retention, locking, lifetime extension, or synchronization operation establishes that requirement.
