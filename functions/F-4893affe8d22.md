# F-4893affe8d22

## Purpose

F-4893affe8d22 implements a stateful transfer from an apparent circular buffer into a caller-supplied destination. It interprets the requested quantity in four-byte units, computes availability from two stored positions, processes per-region metadata and event flags, and delegates data movement to opaque dependencies.

The function distinguishes three outcomes:

- Sufficient effective availability: transfer the requested byte quantity and return `0`.
- Some effective availability, but less than requested: report a reduced unit count, transfer the available byte quantity, and return `0xfffffffe`.
- No effective availability: invoke an output-producing dependency for the requested byte quantity, increment two state words, and return `0xfffffffe`.

“Circular buffer,” “region metadata,” and the interpretation of the no-availability operation as filling output are inferred intent. The established contract below is expressed in terms of observable state accesses and dependency calls. The actual byte semantics of those dependencies are not supplied.

## Interface

The function has four arguments and a 32-bit return value:

1. **Context:** address of mutable state containing 32-bit words, addresses, indexed metadata, and an optional callback.
2. **Destination:** a 32-bit value used as the destination argument to transfer dependencies and as the base for destination-offset arithmetic.
3. **Count address:** address of a readable and writable unsigned 32-bit quantity. Its initial value specifies a request in four-byte units.
4. **Event-output address:** address of a writable single byte.

The return bit patterns are:

| Return | Established meaning |
|---|---|
| `0x00000000` | Initial effective availability was at least the computed requested byte quantity. |
| `0xfffffffe` | Initial effective availability was smaller than the computed requested byte quantity. |

The latter value is `−2` if interpreted as a signed 32-bit integer. The function does not expose a separate dependency-failure result.

### Preconditions and arithmetic domain

Defined use requires valid storage for every access actually reached, valid dependency arguments, and a valid callable target whenever the callback address is nonzero and invoked.

Ordinary ring-buffer operation additionally requires coherent positions, span, alignment, and indexed-table coverage. The function does not validate these conditions.

The request is multiplied by four as an unsigned 32-bit quantity. Only the low 32 bits survive. For example, a request of `0x40000000` produces a requested byte quantity of zero; there is no rejection of this overflow.

Distances, table indices, and alignment masks also use 32-bit quantities. Pointer-like addition and subtraction appear through recovered integer expressions. ## Behavior

### 1. Entry writes and captured values

The function first writes zero to the event-output byte.

It then reads the count and stores that value at context offset `48`. It reads the count again to obtain the request used for subsequent calculations. These are separate reads; the saved request and computational request are not guaranteed to match if aliasing or external mutation intervenes.

Next it captures the producer-position value from offset `16`, computes the requested byte quantity as four times the computational request, and reads the current read position from offset `8`.

The producer-position capture is retained for the final availability calculation on the successful path. It is not refreshed after dependencies execute.

### 2. Effective availability

Initial raw availability is calculated from the captured positions:

- If the read position is below the producer position, availability is their forward difference.
- If the positions are equal, availability is zero.
- If the read position is above the producer position, availability is the current ring span at offset `36` minus the difference between the positions.

The function then compares the unsigned availability shifted right by two with the unsigned threshold at offset `32`. If the shifted availability is less than or equal to the threshold, effective availability becomes zero. Otherwise, effective availability remains the original byte quantity, including any low two bits.

Consequently, the threshold is not subtracted from availability. It suppresses the entire available quantity when the comparison succeeds.

The main branch compares effective availability against the computed requested byte quantity. Equality is sufficient for success.

### 3. Selected-region processing

Every main path performs selected-region processing before its primary transfer or no-availability operation.

The region index is the unsigned 32-bit difference between a read position and the buffer base, shifted right by twelve. This groups offsets into nominal 4096-byte regions. No range check or modulo reduction is applied.

The position and base used to derive this index differ slightly by path:

- No availability and sufficient availability use the read position captured near entry, together with a newly read base.
- Partial availability first writes the reduced count, then reads the base and the current read-position field to derive the index.

For the selected index, processing occurs in this order:

1. Read the indexed metadata word and store it at offset `316`.
2. Read the indexed flags. If bit `0x2` is set, call F-2ed25d4ea98d with the context.
3. Read the indexed flags again. If bit `0x1` is set, write `1` to the event-output byte and read the callback address at offset `328`.
4. If that bit was set and the callback address is nonzero, invoke it with the current word at offset `332`.
5. Write zero to the entire indexed flags word.

The second flags read is significant: F-2ed25d4ea98d may change the flags before bit `0x1` is tested. The selected index remains the index already computed.

A zero callback address does not suppress the event-byte write or the flags clearing. Bits other than `0x1` and `0x2` do not trigger an identified action, but they are cleared with the rest of the word.

Dependencies can also modify the event byte if they can reach it. The function does not restore an earlier event-byte value after callback execution.

### 4. No effective availability

This path applies only when effective availability is zero and the computed requested byte quantity is nonzero.

After selected-region processing:

1. Call F-9f7f9de84b92 with the destination and requested byte quantity.
2. Read, increment, and write the word at offset `40`.
3. Read, increment, and write the word at offset `44`.
4. Call F-ca478df20950.
5. Return `0xfffffffe`.

This path does not itself update the read-position field, accounting field, or count output. Dependencies and aliasing can still affect them.

The two counter increments are sequential, not an atomic pair. Each reads its field after the preceding dependency calls or writes. Counter-overflow behavior is not sufficiently established by the recovered signed expressions.

### 5. Partial availability

When effective availability is nonzero but smaller than the computed requested byte quantity, the function first writes the effective availability shifted right by two to the count address.

After selected-region processing, it reads the current read position and determines whether adding the effective byte quantity extends strictly beyond the current end address.

**Strictly crossing the end:**

- Compute the first segment length as end minus read position.
- Call F-7b852511e094 with the original destination, current read position, and first segment length.
- Call F-7b852511e094 again with:
  - destination advanced by the first segment length rounded down to a multiple of four;
  - the buffer base read at that point;
  - the remaining byte quantity.
- Compute the new read position from a subsequently read base plus the remaining byte quantity rounded down to a multiple of four.

**Not strictly crossing the end:**

- Make one F-7b852511e094 call for the entire effective byte quantity.
- After the call, reread the current read-position and end fields for the equality check.
- If current read position plus effective byte quantity equals the end, choose the current base as the new read position.
- Otherwise, choose current read position plus four times the then-current count output.

The function writes the chosen read position, subtracts the original effective byte quantity from the accounting word at offset `24`, calls F-ca478df20950, and returns `0xfffffffe`.

This path does not perform additional region-zero event processing after a wrapped transfer.

For unaligned availability, the count reports whole four-byte units, but the transfer calls still receive the full available byte quantity. Rounded pointer advancement can therefore differ from the transferred byte count.

### 6. Sufficient availability

When effective availability is at least the computed requested byte quantity, selected-region processing occurs first. The transfer logic then uses the originally computed requested byte quantity.

For a strict end crossing, it performs two F-7b852511e094 calls using the same segment and destination-rounding rules as the partial path. It writes the new read position as a freshly read base plus the remaining byte quantity rounded down to a multiple of four.

After that read-position write, it processes **region-zero flags**:

- If bit `0x2` at offset `184` is set, call F-2ed25d4ea98d with the context.
- Reread bit `0x1`; if set, write `1` to the event-output byte and invoke the current nonzero callback with its current argument.
- Clear the entire word at offset `184`.

This additional processing does not copy region-zero metadata to offset `316`.

For a transfer that does not strictly cross the end, it makes one transfer call. Afterward, equality with the end is checked using reread context fields. Exact equality sets the read position to the current base; otherwise, advancement uses four times the then-current count output. Exact-end wrap does not trigger the additional region-zero flag processing.

The accounting word is then reduced by four times the request captured near entry. This is not necessarily the current count output.

Finally, availability is recalculated using:

- the updated read-position field;
- the producer position captured near entry;
- the current ring-span field where needed.

No threshold suppression is applied to this final calculation.

Notification selection is ordered:

- If remaining availability is less than the current unsigned ring span shifted right by two, call F-ca478df20950.
- Otherwise, if remaining availability exceeds the current unsigned ring span shifted right by one, call F-0cc3a52d7ec5.
- Otherwise, call neither.

The function then returns zero. Equality at either boundary does not satisfy that boundary’s strict comparison.

## Side effects

Direct writes can affect the event byte, count output, saved request, selected metadata, selected flags, region-zero flags, read position, accounting word, and two counters.

The order of dependency calls and intervening field reads is observable. The function does not operate on a fully isolated snapshot. Dependencies may change state later reread by the function, while captured values—especially the request, initial effective availability, selected index, and producer position—remain in use.

No allocation, deallocation, ownership transfer, or memory release is directly visible. The function does not establish whether dependencies perform any of these operations.

No non-aliasing guarantee is supplied. If argument storage overlaps context or destination storage, early writes can affect later reads. The ordinary behavioral examples below assume valid, non-overlapping argument storage and dependencies that do not unexpectedly mutate state.

There is no visible handling of dependency error results. Effects of dependency failure, exceptions, traps, or non-return are unknown.

## Acceptance examples

These examples specify conditional observations, not executed tests. They assume stable dependencies, valid aligned addresses, and no argument aliasing unless stated otherwise.

1. **Contiguous success.** With 32 effective bytes available and a request of four units, the transfer dependency receives one 16-byte operation if the end is not crossed. The count remains four, accounting decreases by 16, the read position advances by 16, and the return is zero.

2. **Partial transfer.** With 12 effective bytes available and a request of five units, the count becomes three before selected-region processing. Transfer operations total 12 bytes, accounting decreases by 12, F-ca478df20950 is called, and the return is `0xfffffffe`.

3. **Threshold suppression.** With 12 raw bytes available and threshold three, the shifted availability equals the threshold, so effective availability becomes zero. For a nonzero requested byte quantity, the function invokes F-9f7f9de84b92 rather than a transfer operation, leaves the count unchanged through its own writes, and increments both counters.

4. **Successful strict wrap.** If eight bytes remain before the end and the requested quantity is 16 bytes, two eight-byte transfer operations occur. The new read position is base plus eight. Region-zero flags are processed after the read-position write.

5. **Exact-end completion.** If the requested quantity exactly reaches the end, one transfer operation occurs and the read position becomes the base. Additional region-zero flag processing does not occur solely because of this exact-end wrap.

6. **Partial strict wrap.** If effective availability crosses the end but is insufficient for the request, the function splits the available quantity into two transfers. It does not perform the successful-path region-zero flags step.

7. **Flag-handler mutation.** If selected flags initially contain only bit `0x2`, and F-2ed25d4ea98d changes them to include bit `0x1`, the subsequent test observes that change. The event byte is set, the current nonzero callback is invoked, and the selected flags are then cleared.

8. **Zero request.** A zero computed requested byte quantity takes the sufficient-availability path even when effective availability is zero. Selected-region processing and a zero-length transfer call still occur; the no-availability counters are not incremented by this path.

9. **Request multiplication overflow.** A request of `0x40000000` is saved without reduction at offset `48`, but its computed byte quantity is zero. Branch selection follows that zero byte quantity rather than treating the request as an enormous transfer.

10. **Unaligned partial availability.** With six effective bytes available, threshold zero, and a larger requested byte quantity, the count becomes one while transfer operations total six bytes. In a nonwrapping case, ordinary advancement is four bytes, not six. This discrepancy is established behavior, not evidence that such input is intended.
