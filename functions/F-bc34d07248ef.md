# F-bc34d07248ef

## Purpose

F-bc34d07248ef conditionally updates a mutable record according to a captured 32-bit version value and a companion header. It invokes dependencies, initializes selected fields, augments bit masks, conditionally writes through a globally supplied pointer, and writes completion markers.

**Inferred intent:** the thresholds and replacement version value suggest migration of older record formats to version 62. The record’s domain meaning is not established.

**Established behavior:** migration requires both a captured version from 1 through 61 and a zero companion header. A zero version or nonzero companion header selects an additional dependency call instead. A version above 61 with a zero companion header skips both migration and that additional call. Entry calls and final marker writes remain applicable on these paths.

### Mask augmentation

Every migrating version reaches the mask update.

Three additional 32-bit globals are designated **mask-20**, **mask-21**, and **mask-22**. Their reads occur progressively:

- Mask-20 is always read.
- Mask-21 is read unless the captured version is 20.
- Mask-22 is read unless the captured version is 20 or 21.

The selected mask is:

| Captured version | Selected mask |
|---|---|
| 20 | Mask-20 |
| 21 | Mask-21 |
| 22 | Mask-22 |
| 1–19 or 23–60 | Zero |
| 61 | `0x7FFFFFFF` |

After selecting the mask, the function reads the current word at `0xB30` and writes back:

**current word OR ((selected mask XOR `0x7FFFFFFF`) AND captured baseline mask)**

All operands and the result are 32 bits. XOR with `0x7FFFFFFF` flips bits 0 through 30 and leaves bit 31 unchanged; it is not a full-width complement.

The baseline mask was captured before the dependency-derived operations. These three version-specific globals are read afterward. No dependency preservation of globals is assumed.

Relative to the word read for this update, the calculation can only add set bits. For version 61, the added mask is zero, but the word read and write still occur.

2. Reads a global destination pointer.

If bit 0 of the first read is set, neither conditional store occurs. The destination pointer has nevertheless already been read.

## Acceptance examples

These are conditional contract examples, not executed tests. All assume valid reached accesses and normal dependency completion. Versions are captured after the two entry calls.

**Every example described as migration additionally requires the word read at `0x008` to be zero.** A nonzero companion header instead selects the additional F-ee906fdf174e call and skips all migration operations. Final-value examples also assume no conflicting dependency effects, concurrent changes, or aliased writes.

1. **Captured version zero:** The companion header is not read for branch selection. F-ee906fdf174e is called a second time, migration is skipped, and final markers follow. There is no direct read at `0x014`.

2. **Version 6, nonzero companion header:** The additional F-ee906fdf174e call occurs. There is no migration write of 62, no direct read at `0x014`, and no copy to `0x00C`.

3. **Version 6, zero companion header:** Migration writes 62 and copies the word at `0x014` to `0x00C`. It does not clear `0xB08` or perform the below-6 tail stores. It does clear `0xB1A`.

4. **Version 62 or greater, zero companion header:** Migration and the additional F-ee906fdf174e call are skipped. The entry marker and final markers are still written. Unsigned values with bit 31 set also exceed 61.

5. **Version 40 migration:** With a zero companion header and a byte read of `1` at `0xB3F`, the function writes `0xFE` there. It writes `25` at `0xB4D` before replacing that byte with `1`. Any other byte suppresses the conversion writes.

6. **Versions 51 and 52, zero companion header:** Version 51 selects indirect dispatch, the `100` store, F-dc3d47838cf6, the `50` store, and F-2bcddcff51f2. Version 52 skips indirect dispatch and F-dc3d47838cf6 but still selects the `50` store and F-2bcddcff51f2. With a nonzero companion header, neither version selects these migration operations.

7. **High-bit mask distinction during version-20 migration:** With a zero companion header, captured baseline mask `0x80000001`, mask-20 equal to zero, and current `0xB30` equal to zero, the mask update writes `0x00000001`, not `0x80000001`.

8. **Conditional flag clearing during migration below 58:** With a zero companion header and stable `0xB00` value `0x00000002`, the captured result is zero, stored first at `0xB00` and then through the global pointer. A first-read value of `0x00000003` suppresses both stores.

9. **Versions 60 and 61, zero companion header:** Given `0x80000000` at `0xB8C` before these updates, version 60 replaces it with `2`; version 61 instead produces `0x80000002`. With a nonzero companion header, neither update occurs.

10. **Version 5, zero companion header:** F-dc3d47838cf6 receives the address at `0x8EE` before the later zero-halfword store there. The value stored at `0xB64` need not describe the final contents at `0x8EE`. With a nonzero companion header, neither that call nor the tail clear occurs.
