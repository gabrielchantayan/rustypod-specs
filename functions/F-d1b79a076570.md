# F-d1b79a076570

## Purpose

F-d1b79a076570 performs two pointer-based updates, sets selected bits in a record’s first word, invokes F-d9678c05967f with that record’s address, and returns the original record address if the invocation returns normally.

The two pointer updates have the shape of removing a record from a doubly linked structure: one referenced object receives the record’s backward reference, and another referenced object receives its forward reference. This interpretation is inferred intent, not an established data-structure contract. The supplied evidence does not identify the surrounding structure, establish membership invariants, or describe the dependency’s purpose.

The established local behavior is narrower:

- Two indirect 32-bit stores occur before the flag update.
- The flag update preserves every previously set bit.
- Input bits 2–4 select additional bits to set at positions 28–30.
- Bit 31 is set unconditionally.
- The dependency is then invoked once.
- Its result, if any, does not determine this function’s return value.

These statements describe the supplied static representation. No runtime tests have been performed.

Bit positions in this document are numbered from zero, with bit 0 being the least significant bit.

## Behavior

### 1. First indirect update

The function uses the record’s forward reference as an address base and stores the record’s backward reference as a 32-bit value at byte offset 4 from that base.

This is an unconditional store on the normal execution path. It does not first verify that the destination previously referred to the input record.

Both the forward and backward reference values needed for this assignment are obtained before its store takes effect. The supplied expression does not establish their relative read order within that assignment.

### 2. Second indirect update

After the first assignment, the function uses the record’s backward reference as an address base and stores the record’s forward reference as a 32-bit value at byte offset 8 from that base.

The values for this step are evaluated after the first assignment. They must not be specified as unconditional snapshots of the values present on function entry.

This distinction matters when the first destination overlaps the record itself. In such a case, the first store can change a reference that the second assignment subsequently uses.

As with the first assignment, the relative order of the source and destination-base reads within this assignment is not established by the supplied expression.

### 3. Flag update

After both indirect assignments, the function reads the record’s first 32-bit word and replaces it with the bitwise OR of:

- That word’s current value.
- A three-bit contribution derived from input bits 2–4.
- The constant `0x80000000`.

The three-bit contribution is formed by an unsigned right shift of two positions, masking with `0x7`, and shifting the resulting value left by 28 positions. Consequently:

| Input bit | Flag bit set when that input bit is 1 |
|---:|---:|
| 2 | 28 |
| 3 | 29 |
| 4 | 30 |

Bit 31 is always set.

The extracted value is between 0 and 7 inclusive. Its shifted contribution is between `0x00000000` and `0x70000000`; all contributed bits fit within a 32-bit unsigned word.

The operation is **set-only**, not field replacement:

- Bits 0–27 are preserved from the flag word read at this stage.
- Existing bits 28–30 remain set even if the corresponding input bits are zero.
- Bit 31 is set regardless of its previous value.
- No previously set flag bit is cleared.

If an earlier indirect store overlaps the flag word, the value preserved by this operation is the value after that store, not necessarily the value present on entry.

Input bits outside positions 2–4 have no effect on this local calculation. This does not establish identical whole-call outcomes under differing external state or dependency behavior.

### 4. Dependency invocation

After storing the updated flag word, the function invokes F-d9678c05967f once with the original record address.

The second input is not passed as a separate argument. Its selected bits have already contributed to the flag word.

The supplied evidence does not specify what the dependency reads or writes. In particular, it does not establish that the dependency preserves:

- Global state.
- The record’s allocation or lifetime.

Accordingly, the locally established flag and reference states describe the state before the invocation, not unconditional postconditions at final return.

### 5. Return

If F-d9678c05967f returns normally, F-d1b79a076570 returns the original record address. There is no further explicit record access in the supplied body.

If a preceding access fails or the dependency does not return normally, the supplied evidence does not establish a normal return from this function.

## Side effects

### Explicit memory effects

Before the dependency call, the function performs three explicit 32-bit stores in this order:

1. Backward-reference value to offset 4 of the forward-referenced object.
2. Forward-reference value to offset 8 of the backward-referenced object.
3. Updated flags to offset 0 of the input record.

These are three store operations, not necessarily three distinct memory locations. Aliasing can make destinations coincide with each other or with fields of the input record.

## Acceptance examples

The following examples are conditional static acceptance criteria, not reports of executed tests.

### Distinct neighboring objects

Assume the record’s backward reference identifies object A and its forward reference identifies object B. Assume neither destination overlaps the record or the other destination.

Before the dependency invocation:

- B’s word at byte offset 4 contains A’s address-valued representation.
- A’s word at byte offset 8 contains B’s address-valued representation.
- The input record’s reference words are unchanged by these two stores.
- The flag update has completed.

Whether those values remain after the dependency returns is unknown.

### All selected input bits set

Assume the flag word at the flag-update stage is `0x01234567`, and the second input is `0x0000001C`.

Input bits 2–4 are all set. The stored flag word is therefore `0xF1234567`.

This value must be established before the dependency invocation. A final-return assertion of the same value additionally requires the dependency not to modify it.

### No selected input bits set

Assume the flag word at the update stage is `0x21234567`, and the second input is zero.

The stored result is `0xA1234567`. Existing bit 29 remains set, and bit 31 is added. The operation does not clear the existing three-bit field.

### Unselected input bits

For a fixed flag value at the update stage, second-input values `0x00000004` and `0xFFFFFFE7` produce the same local flag contribution.

Both select bit 28 and neither selects bits 29 or 30. The differences outside input positions 2–4 are discarded by the local calculation.

### Self-references

Assume both reference words contain the input record’s own address representation.

The first store writes that representation to offset 4 of the record; the second writes it to offset 8. Under valid storage conditions, both references remain self-references before the flag update.

This does not establish whether F-d9678c05967f accepts such a record.

### Overlap affecting a later reference read

Assume the first indirect destination coincides with the record’s forward-reference word.

The first store replaces that word with the backward-reference value. The second assignment then uses the changed forward-reference value, rather than an entry-time snapshot.

A specification that always performs the second update using both original references would therefore be incorrect for this overlap case.

### Normal return after dependency mutation

If the dependency returns normally after changing the record or global state, this function still returns the original record address. No supplied behavior restores the pre-invocation state.
