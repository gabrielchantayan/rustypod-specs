# F-1099b027807c

## Purpose

F-1099b027807c conditionally selects and processes an item associated with a context, then either clears a context-associated field or requests a continuation. Paths reaching the common end perform a separately gated indirect dispatch.

This contract describes statically visible behavior. The application meanings of the context, items, state, and dispatch targets are unknown. “Processing,” “clearing,” and “continuation” identify observable control-flow roles, not established ownership or scheduling semantics.

## Interface

### Arguments and result

The function accepts two 32-bit arguments:

- **Context address:** interpreted as an address of mutable structured storage.
- **Mode:** compared with zero. Its magnitude and sign do not otherwise affect the explicit behavior; every nonzero value selects the same mode-dependent alternative.

There is no explicit return value. Execution can return, continue indefinitely in selection, encounter an invalid memory access, or reach a dependency marked non-returning. Indirect calls introduce additional unknown outcomes.

### Memory layout

All offsets are byte offsets. The supplied representation uses four-byte address-bearing fields and four-byte integer values.

| Storage | Offset | Width | Established use |
|---|---:|---:|---|
| Context | `0x58` | 4 bytes | Its address is passed to the entry dependency; its contents later provide the final dispatch gate pointer. |
| Context | `0x64` | 4 bytes | Associated-record pointer. |
| Context | `0x68` | 4 bytes | Opaque argument read for several dependencies. |
| Context | `0x6c` | 4 bytes | State tested against zero. |
| Associated record | `0x30` | 4 bytes | Pointer-like field used by processing, clearing, and continuation decisions. |
| Associated record | `0x34` | 1 byte | Character-sized argument widened for item processing. |

A pointer obtained from record offset `0x30` is used for a four-byte read at offset `+4`.

For a nonnull item-associated pointer, the function reads its first four-byte word, treats that word as another address, and reads an indirect-call target at offset `+4` from that address.

Three separate fixed-storage locations participate in later operations:

- **Continuation storage A:** supplies a four-byte argument on the processing branch’s continuation path.
- **Continuation storage B:** supplies a four-byte argument on the nonzero-mode alternate path.
- **Final-target storage:** supplies the final indirect-call target.

These are fixed **locations**, not established constant contents. The two continuation values need not differ, and their identities are unknown.

Local storage includes a four-byte selection region, a four-byte item-value slot, an item-pointer slot, and a separate 20-byte region. Their initialization is not established merely by their existence or by passing their addresses to dependencies.

### Preconditions

Every reached memory access must address accessible storage of the required width. Every reached indirect call requires a usable target and a compatible, unresolved calling convention.

The function does not establish these conditions through validation:

- A null associated record can bypass processing but does not protect an alternate clearing path.
- During selected-item processing, the `+4` read through record field `0x30` precedes that pointer’s null test.
- Selection output slots must contain usable values whenever consumed. Passing their addresses to a dependency does not establish that it writes them.

Byte order, alignment requirements, permitted aliasing, concurrency rules, and address-overflow behavior are not established. Offset expressions describe address calculations in the representation; they do not establish portable wrapping semantics.

## Behavior

### Entry and branch selection

The first call is F-338d16f9ce72, receiving the address of context field `0x58`.

After that call returns, the function reads the record pointer at context offset `0x64`. If nonnull, it reads record field `0x30`. Processing is selected only if:

1. The record pointer is nonnull.
2. The field read from `0x30` is nonzero.
3. The subsequently read context state is zero.
4. Mode is zero.

These tests short-circuit in that order. In particular, the processing eligibility test does not read state unless the two pointer-related conditions succeed.

If processing is not selected, the alternate condition reads context state and selects clearing when state is nonzero or mode is nonzero. With zero state and zero mode, an absent record or zero record field leads directly to final dispatch selection.

F-338d16f9ce72 may affect the fields subsequently read. No pre-call snapshot of them governs selection.

### Selection

On the processing branch, the function passes the address of the four-byte selection region to F-794506715e88. No explicit initialization of that region is shown. Any initialization or preparation necessary for later use is an unknown dependency obligation.

A processing-result value starts at zero. The function repeatedly calls F-37f0845bb2ad with:

- The selection-region address.
- The item-value slot address.
- The item-pointer slot address.

The returned 32-bit status controls selection:

- **Status `1`:** read the current context `0x68` value and the item-value slot, and call F-c5e3706cb2fd with them. A zero result repeats selection; a nonzero result ends selection.
- **Status `0`:** end selection without processing an item.
- **Any other status:** end selection and enter selected-item processing without calling F-c5e3706cb2fd for that iteration.

There is no explicit iteration bound. Repeated status `1` results paired with zero predicate results keep the loop running.

For status `1`, the item-value slot must already contain a usable value when F-c5e3706cb2fd consumes it. The source does not prove that F-37f0845bb2ad supplies such a value. If selection ends with any nonzero status, the later item-value and item-pointer uses likewise require usable slot contents. This applies to accepted status `1` and to every other nonzero status, including negative values. Freshness, initialization, and validity guarantees remain unknown.

Rejected iterations have no explicit item-pointer operation in this function.

### Selected-item processing

If the final selection status is nonzero, operations proceed as follows:

1. Reload the record pointer and its `0x30` field.
2. Call F-b5a86af15404 with that field and the item value.
3. Reload the record pointer and its `0x30` field.
4. Read four bytes at offset `+4` through the resulting pointer.

If that four-byte value is zero:

- A nonnull pointer causes F-50e458dae177 to be called, followed, if it returns, by F-feee9156a257, which is marked non-returning.
- A null pointer takes the explicit zero-write path to the current record’s `0x30` field, but only if execution has survived the preceding read through address `4`.

The null test therefore does not make the preceding dereference safe. Under a memory model where address `4` is inaccessible, a null pointer prevents defined execution from reaching that write.

F-50e458dae177 has no established purpose or effects beyond its visible placement before F-feee9156a257. Neither call is established as ordinary deallocation.

If execution continues, F-eed44a6a0bc2 receives:

1. The context address.
2. The item value.
3. The item-associated pointer.
4. The current record’s byte at `0x34`, widened to an integer.
5. A four-byte zero.

The byte’s signed versus unsigned widening is unresolved. The return value becomes the processing result.

After that call returns, the function tests the item-pointer slot. If nonnull, it reads the pointer’s first word, then the call target at offset `+4` from that word, and invokes the target. No explicit arguments for this indirect call are recovered. Its ownership effects are unknown.

Next, the function reads the current context `0x68` value and calls F-51c00ea72606. Its return value does not determine the later clearing-versus-continuation decision.

If selection ended with status zero, this entire selected-item sequence is skipped, leaving the processing result zero.

### Clearing or continuation after selection

The processing branch selects clearing using these short-circuited tests:

1. Processing result equals decimal `12`.
2. Otherwise, reload the record pointer and read its `0x30` field; clear if that field is zero.
3. Otherwise, read four bytes at offset `+4` through that field; clear if zero.
4. Otherwise, read context state; clear if nonzero.

A processing result of `12` avoids the record and pointee reads belonging to the remaining decision tests. It does not avoid the selected-item operations that already preceded this decision.

#### Clearing sequence

The sequence is:

1. Read context `0x68` and call F-2e61ab7b1a71 with that value.
2. After the call returns, reload the record pointer and read field `0x30`.
3. If the field is nonzero, call F-50e458dae177 and then, if it returns, F-feee9156a257.
4. Otherwise, reload the record pointer and write four-byte zero to field `0x30`.

There is no record-null guard in this sequence. A field that was nonzero before F-2e61ab7b1a71 is not itself evidence that the non-returning path will follow: that dependency may change the record pointer or field. The post-call read controls the branch.

Assuming the non-returning annotation holds, normal completion of clearing requires the post-call field read to be zero.

#### Continuation sequence

When clearing is not selected:

1. Call F-cb0c71a1fb59.
2. After it returns, read the current value from continuation storage A.
3. Call F-b36343a620db with the four-byte result from F-cb0c71a1fb59, that newly read value, and the context address.

The storage-A value is not cached before F-cb0c71a1fb59. That dependency may change it. Whether F-b36343a620db queues work, invokes a target immediately, or retains the context is unknown.

#### Processing-branch completion

After clearing or continuation returns, read context state again. If nonzero, call F-7333bca0c2ac with the context address.

Then call F-944b595e25e9 with the address of the separate 20-byte local region. No explicit initialization of that region is shown, and no relationship to the four-byte selection region is established.

### Alternate clearing branch

When processing was not selected and state or mode is nonzero, perform the same clearing sequence described above.

If it returns:

- With mode zero, call F-7333bca0c2ac with the context address.
- With mode nonzero, call F-cb0c71a1fb59; after it returns, read continuation storage B; then call F-b36343a620db with the returned four-byte value, the newly read storage-B value, and the context address.

F-cb0c71a1fb59 may change storage B before its read. This branch does not read storage A for continuation and does not call F-944b595e25e9.

### Final dispatch

Every path reaching the common end:

1. Reads the pointer at context `0x58`.
2. If nonnull, reads its first four-byte word.
3. Only if both the pointer and first word are nonzero, reads the indirect target from final-target storage and invokes it.

A null pointer suppresses both the first-word read and the target read. A zero first word suppresses the target read and call.

The first word is a gate, not the call target. The target comes from separate fixed storage only after the gate succeeds; it must not be treated as a value cached across preceding dependencies. No explicit call arguments are recovered. If the indirect call returns, the function returns.

## Side effects

The explicit context-reachable writes are four-byte zero writes to the current record’s `0x30` field. They occur only after the corresponding calls and reads complete.

Dependencies receive addresses into the context and local storage. Their writes, retained references, global effects, reentrancy, and ownership behavior are unknown. In particular:

- No dependency is assumed to preserve context fields or fixed-storage contents.
- Passing an item pointer to F-eed44a6a0bc2 does not establish ownership transfer.
- The item-associated indirect call does not establish release or destruction.
- Passing the context to F-b36343a620db does not establish a lifetime boundary.
- No allocation or ordinary deallocation is explicitly established.

The continuation-storage reads and final-target read are observable global reads with the ordering specified above. The visible function does not explicitly write those locations, but dependencies may do so.

There is no explicit error return, recovery protocol, or rollback. Invalid accesses, unusable output contents, incompatible indirect targets, unbounded iteration, and non-returning dependencies can prevent normal completion.

## Acceptance examples

These are conditional static acceptance cases, not executed tests.

1. **Inactive absent record.** If the entry dependency leaves the record null, state zero, and mode zero, neither main branch runs. Final dispatch selection still occurs.

2. **Selection initialization is not proved.** Calling F-794506715e88 alone does not establish usable selection-region contents. If F-37f0845bb2ad requires initialized contents, that obligation must be satisfied by its actual dependency contract.

3. **Status `1` consumes an item value.** If selection returns `1`, the item-value slot must be usable before F-c5e3706cb2fd. A zero predicate result repeats selection without the item-associated indirect call.

4. **Other nonzero status.** If selection returns `-1`, selected-item processing follows without a predicate call. Safe execution still requires usable item-value and item-pointer contents; no separate error path is established.

5. **Result `12`.** If item processing returns `12`, the optional item indirect call and F-51c00ea72606 still occur first. Clearing selection then skips its alternative record and pointee tests.

6. **Storage A changes during dependency.** If F-cb0c71a1fb59 changes continuation storage A before returning, the subsequent F-b36343a620db call receives the changed value, assuming no intervening mutation.

7. **Nonzero-mode continuation.** If alternate clearing completes and mode is nonzero, F-cb0c71a1fb59 precedes the read of storage B. F-7333bca0c2ac and F-944b595e25e9 are not called by that branch.

8. **Nonzero clearing field.** If F-2e61ab7b1a71 returns with the subsequently read field nonzero, F-50e458dae177 is reached, followed if it returns by F-feee9156a257. No zero write or final dispatch follows if the latter does not return.

9. **Null record during active clearing.** If mode is nonzero and the record remains null after F-2e61ab7b1a71, the field read is invalid under an ordinary memory model; this is not a safe no-op.

10. **Late final-target read.** If the final pointer and first word are nonzero, dispatch uses the target present in final-target storage at that later read. If either gate fails, that storage is not read by this path.
