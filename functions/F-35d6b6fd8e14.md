# F-35d6b6fd8e14

## Purpose

On normal completion:

- **Status 0:** no call to F-ab30f6ab4825 occurred. The result is the candidate slot’s value when that slot is read for the destination write, after extraction and final comparison.
- **Status 1:** F-ab30f6ab4825 was called. The result is the contents of the internal word supplied as its output argument, read after the call. The dependency is not established to initialize or modify that word.

**Inferred intent:** the traversal resembles an ordered-tree search followed by predecessor examination and conditional insertion. Neither ordering semantics nor successful insertion is established. In particular, status 1 identifies a call path, not allocation success, insertion success, or a freshly produced result.

## Behavior

### Search and retained candidate

The function obtains the initial search link through the header pointer at context offset `0x10`, reading the link at header offset `0x04`. It then reads context offset `0x10` again to initialize the retained search candidate.

These are separate header-pointer reads, not a single snapshot. The remembered comparison result initially equals 1.

For each nonnull search node:

- Two distinct internal 32-bit words are explicitly zeroed. They later serve as the early-path and ordinary-path output storage.
- F-bcefa5957e76 receives the context address plus `0x19`, the query word, and the current node address plus `0x10`, in that argument order.
- The current search node becomes the retained search candidate.
- A zero comparison selects the node’s link at `0x0c`; any nonzero comparison selects its link at `0x08`.

The selected link is read after the comparison call. Dependency changes to that link can therefore affect traversal.

When search ends, the retained search candidate is the last visited node, and the remembered result is its comparison result. If the initial search link was null, no comparison occurs, the retained candidate remains the second-read header pointer, and the remembered result remains 1. Neither internal output word has then been initialized by a search iteration.

### Control decision and candidate slot

The control byte at context offset `0x18` is read after search completion.

A nonzero byte selects the ordinary F-ab30f6ab4825 path immediately.

A zero byte causes the retained search candidate to be copied into a separate candidate slot. This slot is subsequently used for candidate checking. It is distinct from the retained search candidate supplied to F-ab30f6ab4825.

If the remembered search comparison is zero, candidate checking proceeds directly to extraction and final comparison.

If it is nonzero, the function reads the current header pointer from context offset `0x10`, reads that header’s 32-bit word at `0x08`, and stores the word in the ordinary-path output storage. It then calls F-75663d4eabfa with:

- The address of the candidate slot.
- The address of the ordinary-path output storage containing the header-derived word.

Both addresses expose internal storage. No supplied dependency contract establishes read-only use, preservation, or non-retention of either address.

A nonzero result selects the early F-ab30f6ab4825 path. A zero result selects navigation, starting from the candidate slot’s value after the call.

### Candidate navigation

Navigation begins by reading the candidate’s marker byte at `0x00`.

If the marker is zero, the function follows the candidate’s `0x04` pointer and reads that referenced object’s `0x04` pointer. If this second pointer equals the candidate, the candidate slot is replaced with the candidate’s `0x0c` link, and navigation ends.

If the marker is nonzero, or the equality fails, the function uses the candidate’s `0x08` link:

- It first reads that link into traversal storage.
- It reads the same link again to decide between downward and upward navigation.

With stable fields, the two cases are:

**Nonnull link:** move to that linked node and repeatedly follow `0x0c` links until a null link is encountered. The selected candidate is the last nonnull node.

**Null link:** read the candidate’s parent-like pointer at `0x04`. Compare that parent’s `0x08` link with the previous candidate, then promote the candidate slot to the parent. If they were equal, continue upward through `0x04`. The terminating candidate is the parent from the first unequal comparison; promotion occurs even on that terminating iteration.

The downward traversal also reads each selected candidate’s `0x0c` link twice: once to obtain the next traversal value and again to decide whether to continue. Consequently, the ordinary “last nonnull node” description assumes consistent repeated reads. The supplied body does not provide a snapshot or synchronization guarantee. If repeated reads disagree, traversal can use a value different from the value that determined its branch, including an invalid pointer.

The marker rule is established. Its interpretation as sentinel handling is inferred intent.
