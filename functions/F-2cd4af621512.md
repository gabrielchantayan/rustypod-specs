# F-2cd4af621512

## Purpose

F-2cd4af621512 coordinates a sequence of dependency calls using five caller-supplied arguments, two local temporary regions, a context-like value, and fields of a caller-supplied object. It conditionally publishes an auxiliary reference into that object, invokes a table-selected dependency, and selects one of two final processing dependencies according to a mode argument.

**Established behavior:** the function controls call order, tests dependency results, calculates a signed working width, passes references and values, and conditionally writes the object field at byte offset +64. Its signed 32-bit result starts at −1 and changes only when a mode-selected processing dependency returns.

**Inferred intent:** the call sequence resembles input conversion, a context-dependent mathematical operation, conversion of its result into temporary byte storage, and output processing. The source does not establish that the input is a byte sequence, that these dependencies perform conversions, or that they modify the supplied storage. These role descriptions do not constitute dependency contracts.

## Behavior

### Temporary setup and context acquisition

The function establishes a default result of −1 and a zero temporary-buffer reference.

It calls F-163f35978c12 first with the input temporary and then with the result temporary. These are initialization-role calls; the actual effects on either region are unknown.

Next, it calls F-2a7d78c39bfc without arguments.

If the returned context-like value is zero:

- No caller-object fields are read by this function.
- No width calculation, buffer-acquisition call, or processing call occurs.
- Both temporary regions are passed to their cleanup-role dependency.
- Neither buffer-cleanup dependency is called.
- The result is −1.

All subsequent behavior assumes a nonzero context-like value and normal return from invoked dependencies.

### Working-width calculation and buffer acquisition

The function reads the primary field at +16 and passes it to F-ae3bc1bfd2a8. Its returned signed 32-bit quantity determines the working width.

The arithmetic first adds seven. It then adds a correction determined by the sign of that intermediate sum: zero for a nonnegative sum, seven for a negative sum. A signed right shift by three produces the width.

Under an arithmetic-right-shift interpretation, and where the additions are representable as signed 32-bit values, this is division of the first adjusted sum by eight with truncation toward zero. In particular, for nonnegative returned quantities without overflow:

| Returned quantity | Working width |
|---:|---:|
| 0 | 0 |
| 1–8 | 1 |
| 9–16 | 2 |
| 17–24 | 3 |

The sign correction depends on the sum after adding seven, not directly on the original quantity. Negative values are not rejected here. For example, under the same arithmetic assumptions, −8 produces width 0 and −15 produces width −1.

The source representation does not settle signed-overflow behavior. Values near the signed maximum therefore cannot be specified by an unrestricted mathematical ceiling operation.

The function calls F-43da6b23bd44 with the working width, zero, and zero. Its return is retained as the temporary-buffer reference. “Allocation” is an inferred role; the call itself and subsequent treatment of the return are established.

This call occurs before the input-size check. If its return is zero, or if the signed working width is less than signed argument 1, the function calls F-4fc89ec41a6d with 4 and 103 and proceeds to common cleanup.

There is no independent rejection of zero or negative working widths.

### Input-role call and comparison gate

After a nonzero buffer return and a successful signed width check, F-3eaa60da10c7 receives, in order:

1. Argument 2.
2. Argument 1.
3. The input temporary’s reference.

A zero return leads directly to cleanup, without a local call to F-4fc89ec41a6d.

A signed return of zero or greater triggers F-4fc89ec41a6d with 4 and 103, followed by cleanup. A negative return permits further processing.

### Optional auxiliary preparation and publication

The function reads the auxiliary field at +64.

- A nonzero field permits the table-selected call without auxiliary preparation.
- A zero field causes the flags at +60 to be read.
- If mask 0x2 is clear, the table-selected call is permitted without preparation.
- If the field is zero and mask 0x2 is set, preparation is required for this path to continue.

Preparation begins with a no-argument call to F-550bd55240d2. If its return is zero, the function proceeds to cleanup; it does not invoke the table-selected dependency.

For a nonzero candidate, F-eec16aec09a9 receives:

1. The candidate.
2. A fresh read of the primary field at +16.
3. The acquired context-like value.

A zero return causes the candidate to be passed to F-6815ca43e6e1, after which processing ends in cleanup. No explicit generic error call occurs on either preparation-failure path.

A nonzero preparation return enables the publication sequence:

- The auxiliary field is read again.
- If already nonzero, the candidate is passed to F-6815ca43e6e1, and processing continues.
- If zero, F-890414d1fd99 is called with 9, 9, 0, 0.
- The auxiliary field is read again after that call.
- If still zero, the function stores the candidate at +64 and clears its local candidate-disposal marker.
- F-890414d1fd99 is then called with 10, 9, 0, 0.
- If the local candidate remains nonzero, it is passed to F-6815ca43e6e1.

Successful preparation permits the table-selected call whether the candidate was published or handed to F-6815ca43e6e1 because another value was observed.

The function does not overwrite a field observed as nonzero at either publication check. This is not a guarantee of atomic publication or thread safety. The paired F-890414d1fd99 calls suggest synchronization, but their effects are unknown.

### Common cleanup

Assuming normal returns, cleanup is ordered as follows:

1. If context acquisition returned nonzero, call F-87ceecb12e6c with that context-like value.
2. Call F-12979315a90f with the input temporary.
3. Call F-12979315a90f with the result temporary.
4. **Only if the retained buffer reference is nonzero**, call F-80308ee0e93f with that reference and the working width, then call F-5990a26eaaa3 with that reference.

Both buffer-cleanup calls share the nonzero guard. A zero acquisition result does not cause either call. Failed context acquisition likewise causes neither call.

For a retained nonzero buffer, the same calculated width is supplied during cleanup even if later processing failed. No explicit rollback of a published auxiliary reference occurs.

## Acceptance examples

These are conditional static acceptance cases, not executed tests. They assume normal dependency returns, valid storage for the selected path, and no unspecified mutations that invalidate the stated conditions.

1. **Context acquisition returns zero.** Both temporary setup calls and both temporary cleanup calls occur, in their stated orders. No object fields are read, no buffer acquisition occurs, neither buffer-cleanup call occurs, and the result is −1.

2. **Buffer acquisition returns zero.** With nonzero context, width calculation and F-43da6b23bd44 occur. The fixed error call follows. Context and temporary cleanup occur, but neither F-80308ee0e93f nor F-5990a26eaaa3 is called.

3. **Input-size parameter exceeds width.** If F-ae3bc1bfd2a8 returns 17, width is 3 under the stated arithmetic assumptions. With argument 1 equal to 4, buffer acquisition precedes rejection. If acquisition returned nonzero, cleanup calls both buffer dependencies, in order, using width 3 for the first.

4. **Comparison gate returns zero.** After successful earlier gates, zero from F-c0985d8666ae triggers the fixed error call. No auxiliary preparation or table-selected call occurs.

5. **Requested preparation cannot complete.** With auxiliary zero and flag mask 0x2 set, a zero candidate prevents the table-selected call. A nonzero candidate followed by zero from F-eec16aec09a9 is passed to F-6815ca43e6e1. Neither branch locally issues the generic error call; both return −1 after cleanup.

6. **Another auxiliary value appears.** After successful preparation, a nonzero field at either publication check prevents the explicit store by this invocation. The candidate is passed to F-6815ca43e6e1, and processing continues with a fresh auxiliary-field read for the table-selected call.

7. **Publication precedes later failure.** If the candidate is stored at +64 and the table-selected call subsequently returns zero, the function returns −1 after cleanup. It does not explicitly clear +64 or dispose of the published candidate.

8. **Mode 1 succeeds.** Following nonzero earlier gates, F-ffb5c1023f20 receives argument 3, width, buffer, the opaque result-role return, and width. A return of 6 becomes the function result, with no local generic error call afterward.

9. **Mode 3 returns a negative value.** A return of −7 from F-ba044e35967b triggers the fixed error call. If that call and cleanup return normally, the final result remains −7.

10. **Unsupported mode is rejected late.** Mode 2 does not bypass earlier processing. If all earlier gates permit it, the table-selected call and F-29c531f09e4a occur before the fixed error call. Neither final processor runs, and the result remains −1.
