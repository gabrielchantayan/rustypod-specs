# F-09010bad60aa

The established behavior is the sequence of calls and the data supplied to them. The source does not establish the business meaning of those operations. In particular, it does not establish that any call validates, initializes, destroys, releases, registers, or notifies anything.

This contract describes normal progression through the routine. Any dependency that fails to return normally can prevent later operations from occurring.

## Behavior

- Exactly zero selects the conditional indirect operation described below.
- Any nonzero result skips that operation.
- No distinction is made among positive, negative, or otherwise nonzero bit patterns.

No other use of this result is visible.

### 2. Conditionally dispatch through the primary object

If the first result is zero, the routine obtains a dispatch-table reference from offset `0x00` of the primary object. It selects the callable entry at byte offset `0x58` within that table and invokes it with:

1. The original primary-object pointer.
2. The integer constant `3`.

For this document, that unresolved callable is designated **F-indirect-01**. Its identity depends on the table contents at the time of this operation.

The table reference is obtained after F-b7abcf60c990 returns. If that dependency changes the object's table reference, the subsequent dispatch uses the resulting state rather than a table reference captured at routine entry.

When the first result is nonzero, this dispatch-table lookup and call are omitted. No fallback operation is visible.

F-unmapped-01 is a document-local opaque designation for the direct dependency that has no supplied dependency-map entry. Its behavior is undocumented here.

- F-indirect-01 must be invoked with the primary pointer and `3`.
