# F-4ab31ce53300

## Purpose

F-4ab31ce53300 obtains an object through a dependency, invokes an indirectly selected operation with three writable 32-bit cells, and returns a 64-bit result containing:

- An unsigned comparison result in the low 32 bits.
- The full resulting contents of one writable cell in the high 32 bits.

The comparison uses two different encodings. The requested value combines three original arguments using weights of 65,536, 256, and 1, with 32-bit unsigned wraparound. The observed value combines only the low bytes of the three cells after the indirect operation, in their pointer-argument order.

A plausible intent is to compare a requested three-component value against an externally supplied value. That interpretation is inferred, not established. In particular, neither byte-range inputs nor conventional component ordering may be assumed.

This contract describes static behavior only. No runtime tests have been performed.

### 4. Construct the requested comparison value

The requested value is the 32-bit unsigned result of:

- The original first requested component multiplied by 65,536.
- Plus the original second requested component multiplied by 256.
- Plus the original third requested component.

Multiplication and addition use 32-bit unsigned arithmetic. The result is therefore reduced modulo 4,294,967,296.

The calculation uses the original argument values, not the post-operation contents of the writable cells. No byte masks are applied to those arguments.

### 5. Construct the observed comparison value

The observed value is assembled from the cells after the indirect operation, using their pointer-argument order:

- Low byte of the first cell, multiplied by 65,536.
- Plus low byte of the second cell, multiplied by 256.
- Plus low byte of the third cell.

Each cell is masked to its low eight bits before weighting. The result ranges from 0 through 16,777,215, so this calculation does not overflow 32-bit unsigned arithmetic.

The component ordering is consequential. If the indirect operation makes no writes, the observed value uses the original requested components in reverse outer-component order: third, second, first.

### 6. Compare and pack the result

The low return half is 1 exactly when the requested value is less than or equal to the observed value under unsigned comparison. Otherwise it is 0.

The high return half is the complete resulting contents of the third cell—the cell initially containing the first requested component. Bits above that cell’s low byte affect the high return half but do not affect the observed comparison value.

The supplied representation does not establish an externally meaningful order between the post-call cell reads used for comparison and packing. Callers must not rely on coherent results if another actor modifies those cells concurrently.
