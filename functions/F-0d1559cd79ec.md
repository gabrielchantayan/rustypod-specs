# F-0d1559cd79ec

## Purpose

The supplied static representation does not establish an application-level purpose. Describing the function as a parser, allocator, initializer, or renderer would exceed the evidence. ## Behavior

### Opening calls and first exit decision

Each iteration begins with F-U01. Its target is obtained by clearing the low two bits of the current link-derived state and adding `0x4a8`. Its explicit arguments, in order, are:

1. The current third argument.
2. The current second argument.
3. A pointer to the beginning of the represented stack workspace.

F-U02 follows with no represented explicit arguments. Its result is represented as 64 bits, and both halves can be consumed.

After F-U02 returns, the function:

1. Computes the current second argument plus decimal 10.
2. Writes the current fourth argument as a 32-bit value at the current second argument plus `0x3e`.
3. Tests whether the incremented value multiplied by `0x10000` is negative.

The word write precedes the test. An early exit therefore includes both opening calls and that write.

Under wrapping 32-bit arithmetic, the test examines bit 15 of the incremented value: multiplication by `0x10000` moves that bit into the sign position. It is not a general negativity test on the original or incremented second argument.

If the test succeeds, the low word of F-U02’s result becomes the exit-specific value. The function proceeds directly to the shared return construction, including the return-high global read.

### Halfword writes and intermediate calls

If the first exit test fails:

1. The low 16 bits of F-U02’s low result word are written at the address given by its high result word plus `0x3c`.
2. F-U03 is invoked with no represented explicit arguments.
3. F-U04 is invoked with no represented explicit arguments.
4. The 16-bit value `0x0026` is written at F-U04’s returned address plus 2.

The two halfword destinations have independent validity requirements. Neither dependency result is checked before use. No explicit result from F-U03 is consumed.

### Derived base and captured XOR operand

The incremented second argument drives two address calculations:

- A signed intermediate is obtained by multiplying it by `0x10000000`, retaining 32 bits, and arithmetically shifting right by 9.
- A preliminary address is obtained by adding that intermediate to the incremented second argument.

The XOR global operand is then read and captured **before** F-U05.

F-U05 receives two explicit arguments:

1. F-U04’s result shifted left by one.
2. The incremented second argument multiplied by `0x10000`, then reduced by `0x51`.

After F-U05 returns, the preliminary address is XORed with the previously captured global operand. This produces the derived base.

A change to the XOR global during F-U05 does not change the already captured operand. This ordering does not imply that F-U05 preserves any other global or memory.

Separately, the signed intermediate is increased by `0x2f`. That adjusted intermediate is subsequently both passed to F-U06 and stored through the derived base.

### Workspace publication, byte read, and derived-base write

The derived base is written as a 32-bit value to the represented stack-workspace slot at offset `0x130`.

F-U06 then receives:

1. A fixed embedded address whose contents and interpretation are unknown.
2. The value obtained by reading one byte at the derived base plus 1.
3. The adjusted intermediate.
4. A secondary register output associated with F-U05.

The byte read occurs after F-U05 and the workspace-slot write, but before F-U06 begins. Its access width is one byte; the excerpt does not independently establish its extension to a wider calling-convention argument.

After F-U06 returns, the adjusted intermediate is written as a 32-bit value at the derived base plus `0x24`.

These are separate observable operations. In particular, the byte read and the word write are separated by F-U06. No check validates the derived base.

### Next-state construction and remaining calls

F-U07 is invoked with no represented explicit arguments.

Its relevant secondary register output is increased by `0x30`. The function then replaces:

- The third argument with the derived base shifted left by one.
- The fourth argument with the product of the adjusted F-U07 output, 2, that adjusted output again, and 2.

### Final decision and continuation

After F-U10 returns, the condition global is read and compared with zero. This is a separate global role from the XOR operand, F-U09 argument, and return-high operand; disjoint storage is not established.

If the condition is zero:

1. F-U10’s relevant secondary output is arithmetically shifted right by 9.
2. That shifted value becomes the exit-specific value.
3. The shared return operation shifts it left by one and reads the return-high operand.

The continuation write and replacement of the second argument do not occur on this path. The third and fourth arguments have already been replaced earlier in the iteration, but no next iteration begins.

If the condition is nonzero:

1. The new fourth argument is written as a 32-bit value at twice the adjusted F-U07 secondary output plus `0x34`.
2. The second argument is replaced with F-U10’s relevant secondary output.
3. Execution repeats using the updated second, third, fourth, and link-derived state.

No iteration bound, timeout, or additional termination condition appears.

Expected: the early-exit branch is not taken merely because the original second argument has its sign bit set.
