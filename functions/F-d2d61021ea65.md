# F-d2d61021ea65

## Purpose

F-d2d61021ea65 conditionally performs halfword memory transfers and arithmetic state changes, then enters an unconditional sequence of two indirect calls and a software interrupt.

No application-level purpose is established. The supplied representation does not justify classifying the function as a parser, allocator, renderer, or conventional returning service.

This contract distinguishes:

- **Established static behavior:** operations and control dependencies explicitly represented.
- **Arithmetic deductions:** consequences of interpreting addresses and scalar arithmetic as 32-bit machine quantities.
- **Syntactically represented but unreachable behavior:** operations present in the representation whose entry conditions contradict that arithmetic model.
- **documented_only:** matters not resolved by the supplied evidence.

There is no represented normal return. No runtime tests have been performed.

## Behavior

### Initial arithmetic and branch

Define:

\[
A=(256\times\text{Selector})\bmod 2^{32}
\]

\[
B=(512\times\text{Selector})\bmod 2^{32}
\]

The initial carry-like bit is selector bit 22.

The initial branch tests \(A\), not the selector directly. Consequently:

\[
A=0 \iff (\text{Selector}\mathbin{\&}\texttt{0x00FFFFFF})=0
\]

When \(A\ne0\), no preliminary memory access occurs. The subsequent arithmetic gates remain disabled, and execution proceeds to the terminal loop with the entry link address as its first call-base address.

When \(A=0\), both \(B=0\) and selector bit 22 being clear follow from the same 32-bit model.

### Preliminary transfer

On the \(A=0\) path, the function forms a special working address:

\[
\text{Special}=
\text{Link address}
+\text{selector bit 22}
+(\text{Slot address}\mathbin{\gg}1)
\pmod {2^{32}}
\]

It also forms a transfer destination equal to the entry source address plus the offset.

The represented transfer has this order:

1. Read an unsigned halfword from the entry source address.
2. Change the source working address to the transfer destination minus the adjustment.
3. Write the previously read halfword to the transfer destination.

Thus the updated source working address is:

\[
\text{Updated source}
=\text{Source address}+\text{Offset}-\text{Adjustment}
\pmod {2^{32}}
\]

The internal working-address change is not itself a memory write.

Source and destination may coincide or overlap. The source read precedes the destination write; this is a single halfword transfer, not evidence of a larger copy operation.

The next gate requires the entry link address to be zero. A nonzero link address bypasses the deeper arithmetic, but does not cancel the transfer already performed.

### First comparison cascade

Each comparison is entered only after the preceding required result is zero. The cascade requires, in order:

1. The special address to equal zero.
2. \(A\) to equal the special address.
3. \(A\) to equal \(B\).
4. The same \(A\)-versus-\(B\) comparison to succeed again.
5. The offset to equal the companion.
6. The adjustment to equal the updated source working address.

These comparisons are represented through exclusive-or and logical-right-shift expressions. Each shift count comes from the low byte of a value already required to be zero. Every shift actually entered in this cascade therefore has count zero. The corresponding carry-like state is retained.

Before this cascade, the preliminary-transfer path clears the initial carry-like state. It remains clear throughout a successful first cascade.

Under the stated model, reaching its end therefore requires at least:

- \(A=B=0\).
- Entry link address zero.
- Special address zero.
- Offset equal to companion.
- Adjustment equal to the updated source address.

Failure of a comparison is not an error return. It disables later gated work and leads toward the terminal loop.

### Gated additions

A successful first cascade enables an addition of:

- The accumulator.
- The selector’s low 24 bits multiplied by 128.
- The incoming carry-like bit.

The result is reduced to 32 bits. Carry-out is the disjunction of overflow from the first addition and overflow from adding the carry bit.

On a reachable entry to this addition, the selector-derived term and incoming carry are both zero. A zero result therefore requires an accumulator of zero and produces no carry.

Only that zero result enables the next addition:

\[
\text{Slot address}
+(2\times\text{Offset}\bmod 2^{32})
+\text{preceding carry}
\pmod {2^{32}}
\]

The represented carry checks apply to the additions of the already-width-limited operands. They do not independently report overflow discarded by multiplying the offset by two.

Only a zero result enables the exceptional transition.

### Exceptional transition

When the second addition produces zero, the function:

1. Assigns the machine-state location the slot address multiplied by 64.
2. Changes the link working address to the entry link address plus the slot address multiplied by 64.
3. Reads halfword data through the **entry** link address.
4. Uses an unsigned halfword read there as a destination address.
5. Writes a halfword corresponding to another represented read there plus 15, truncated to 16 bits.
6. Changes an \(A\)-derived working address to \(A+2\) bytes.
7. Clears the carry-like state.

The expression contains two references to the link halfword. Their relative evaluation order and physical access multiplicity are not established. If both reads observe the same stable value \(h\), the destination is address \(h\), and the stored halfword is \((h+15)\bmod 2^{16}\). Stable memory must not be assumed for device-backed or concurrently changing locations.

The entry link address must already be zero to reach this transition. The represented halfword reads therefore use address zero. This is not an implemented null rejection; it is a potentially faulting access.

### Second cascade and proven exclusion of later work

The second cascade differs materially from the first. Its second exclusive-or uses the working address changed to **\(A+2\) bytes**, not unchanged \(A\).

Its entry condition requires the updated link working address to be zero. If that address is nonzero, the entire cascade is skipped.

If it is zero, the following deductions apply:

- Reaching the exceptional transition already required \(A=0\) and the special address to be zero.
- The first exclusive-or combines the special address with the zero updated link value, using a zero shift count. Its result is zero.
- The second exclusive-or combines the updated \(A+2\) address with the zero special address, again using a zero shift count.
- Its result is therefore \(2\), not zero.

The cascade necessarily stops at that second comparison.

There is also a stronger address constraint under the same model. With entry link zero and selector bit 22 clear, special-address zero requires the slot address shifted right by one to be zero. The slot address is therefore either zero or one. The following zero addition requires it to be even, so reaching the exceptional transition requires slot address zero. The updated link address is then also zero.

Whether such a slot address is compatible with a real invocation is **documented_only**. It does not weaken the static contradiction: the second cascade cannot complete under the stated model.

### Syntactically represented but unreachable operations

Everything requiring completion of the second cascade is unreachable under the 32-bit model above. The following describes represented structure, **not established possible execution effects**.

The excluded arithmetic region contains:

- A sum of the special address, carry-like state, and `0x085740E8`.
- A left shift of that sum by its own low byte.
- Subtraction of the shifted quantity and an inverted-carry adjustment from \(B\).
- Further zero-gated subtractions involving \(A\), the updated source address, and \(B\) shifted right by one.
- Advancement of a companion address from \(B\) to \(B+36\) bytes.

The associated carry formulas contain explicit unsigned comparisons and must not be silently replaced by conventional borrow semantics. For example, the first formula tests whether the shifted quantity is less than \(B\), or whether the wrapped difference is less than the incoming carry bit.

The self-derived left-shift count is not constrained to zero by its expression alone. Nevertheless, **the shift cannot execute under the established reachability model**. Handling of counts at least 32 remains **documented_only** for any hypothetical interpretation that made this region reachable.

### Terminal execution

Provided preceding accesses complete, execution reaches an unconditional loop.

The first call-base address is the entry link address unless the exceptional transition changes it. Under the derived conditions for that transition, both the entry and updated link addresses are zero.

Each iteration performs, in order:

1. Call D-01 at the call-base address plus `0xEB6` bytes, supplying three represented 32-bit values: `0`, `0`, and `0xFFFFFFA5`.
2. After D-01 returns, call D-02 at address `0x0857A94B`.
3. After D-02 returns, invoke D-03 through software interrupt `0x5B`.
4. After normal continuation, replace the call-base address with `0x083D4CC2`.
5. Repeat.

The third argument to D-01 has the bit pattern of signed −91, but the dependency’s signed interpretation is unknown.

No explicit arguments are represented for D-02. This does not establish that it ignores entry registers or other machine state.

After one normally completed iteration, the represented D-01 target for subsequent iterations is `0x083D5B78`.

There is no termination condition, success result, or normal return.

## Acceptance examples

These are conditional static expectations, not runtime observations.

1. **Nonzero initial product.**  
   Selector `1` produces \(A=\texttt{0x100}\). No preliminary memory access occurs. The first D-01 target is the entry link address plus `0xEB6`.

2. **Nonzero selector with zero wrapped product.**  
   Selector `0x01000000` produces \(A=0\). The preliminary halfword transfer is required if its accesses complete. Testing selector equality to zero would produce the wrong branch.

3. **Transfer before link-based rejection.**  
   With \(A=0\) and a nonzero entry link address, the transfer occurs before the deeper cascade is rejected. The first terminal call still uses the entry link address.

4. **Identical transfer addresses.**  
   With \(A=0\) and offset zero, the source halfword is read and written back to the same address. Removing the accesses is not justified where reads or writes are observable.

5. **Exceptional path stops the second cascade.**  
   If the exceptional transition is reached and its accesses complete, the changed address is \(A+2=2\). With zero updated link and zero special address, the first comparison yields zero and the second yields 2. No subsequent subtraction, lookup, or record write occurs.

6. **Signed record interpretation is not a reachable example.**  
   In the excluded record-writing expression, a source halfword of `0xFFFF` would be sign-extended to `0xFFFFFFFF`, rather than zero-extended. This describes an unreachable expression’s width semantics, not an accepted execution producing that store.

7. **Completed loop iteration.**  
   If D-01, D-02, and D-03 permit normal continuation, the next D-01 target is `0x083D5B78`.

8. **Nonreturning dependency.**  
   If D-01 does not return, that iteration does not reach D-02 or D-03. If D-02 does not return, it does not reach D-03.
