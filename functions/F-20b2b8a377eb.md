# F-20b2b8a377eb

## Purpose

F-20b2b8a377eb conditionally obtains an object, changes one byte of its state, and passes it through initialization and two subsequent dependency calls. It returns the object pointer when the initialization dependency reports zero. It returns null when the input gate fails, the preliminary dependency returns zero, object acquisition returns null, or initialization reports a nonzero result.

The established behavior is the branching, argument forwarding, direct memory accesses, and dependency-call sequence described below. Names such as “acquisition,” “initialization,” and “cleanup” describe the apparent roles of dependencies, not independently established guarantees about their implementations.

In particular, returning a non-null pointer does not establish that the object is usable, that subsequent dependencies succeeded, or that ownership has transferred to the caller.

## Behavior

### Input gate

If the optional data pointer is null, the function returns null. It does not call the preliminary dependency, even if the primary value is nonzero.

If the pointer is non-null, the function reads its first unsigned 16-bit element and tests whether that element is zero:

- Zero causes an immediate null return, without dependency calls.
- Any value from 1 through 65,535 permits the preliminary dependency call.

The primary value is not substituted for this element in any reachable non-null-pointer decision. A zero primary value does not by itself reject the request.

Only one direct read of the first 16-bit element is visible. The function does not directly modify that element. It later passes the original pointer, rather than a copy of the element, to initialization. Dependencies could therefore observe different contents if the pointed-to storage changes between these events.

### Preliminary dependency

After a nonzero first element is observed, the function calls F-1115c37ad1b6 with five arguments:

1. The original primary value.
2. The third value.
3. The third value again.
4. The fourth value.
5. The fourth value again.

The repeated arguments are exact value repetitions. They are not read from the optional data buffer.

A zero result causes a null return. Any nonzero result permits object acquisition. No narrower success convention, such as accepting only positive values or exactly one, is visible.

The function neither retries this call nor reports its result separately.

### Object acquisition

After a nonzero preliminary result, the function calls F-704d91f94e04 with the original primary value.

If the returned pointer is null, the function returns null immediately. No object-byte update, initialization call, subsequent call, or cleanup call occurs on this path.

A non-null result is retained as the candidate return pointer. Whether this dependency allocates a new object, returns shared storage, or retrieves an existing object is unknown.

### Direct state-byte update

For a non-null candidate pointer, the function reads the byte at offset 29 and writes a modified byte back to that same location.

The update:

- Sets bit 0.
- Clears bit 4.
- Preserves bits 1–3 and 5–7.

This is an 8-bit read-modify-write, not a write of the entire surrounding word. The supplied material does not establish atomicity or synchronization. The update can leave the byte numerically unchanged if bit 0 is already set and bit 4 is already clear, but the visible operation still includes a write.

The byte update occurs before F-74b007a29cb7 is called. It is not delayed until initialization succeeds, and this function contains no direct rollback of it.

### Initialization and its result

After updating the byte, the function calls F-74b007a29cb7 with:

1. The candidate object pointer.
2. The original optional data pointer.

A zero result selects the continuation path. Any nonzero result selects the cleanup path.

On the cleanup path, the function calls F-f9fbf4d34e67 with the candidate pointer and then returns null. Its result, if any, is not used. The visible caller does not independently restore the changed byte or perform another object access after that call.

Calling F-f9fbf4d34e67 does not, by itself, establish that the object is freed, that all resources are released, or that prior side effects are reversed.

### Continuation after a zero initialization result

The function first calls F-493743038bd6 with:

1. The candidate object pointer.
2. The third value.
3. The integer value one.

After that call returns, it obtains the first 32-bit word of the candidate object and forms an argument by adding 72, equivalent to hexadecimal 0x48.

It then calls F-ebd0ee53699f with five arguments:

1. The computed first-word-plus-72 value.
2. A value obtained from a fixed static datum.
3. The candidate object pointer.
4. Zero.
5. Zero.

The static datum’s meaning and type beyond its use as a call argument are not established. It must not be assumed to be a callback, handle, or immutable constant.

The return values of F-493743038bd6 and F-ebd0ee53699f do not affect the visible branch decisions or returned pointer. After the latter call returns, the function returns the candidate pointer.

The first object word is read after F-493743038bd6, not before it. Consequently, if that dependency changes the first word while preserving accessible storage, the later calculation uses the changed value. The relative evaluation order of that object-word read and the static-datum read is not established.

## Side effects

### Direct effects

The only direct write established for this function is the byte update at object offset 29.

The direct reads are:

- The first 16-bit element of a non-null optional data pointer.
- The byte at object offset 29, when acquisition succeeds.
- The first 32-bit object word, on the initialization-zero path after F-493743038bd6.
- The fixed static datum used in the final dependency call.

There is no visible direct output to files, a terminal, a network, or caller-provided output storage other than potential aliasing with the object byte. All dependency effects remain additional and unknown.

### Dependency effects and state visibility

Dependencies are invoked sequentially, subject to the branch conditions above. Their side effects are not undone by this function unless a called dependency itself does so.

No dependency is assumed to preserve global state, preserve pointed-to contents, or preserve object lifetime. In particular:

- The preliminary call can affect state later observed during acquisition or initialization.
- Initialization can modify the object or input storage.
- F-493743038bd6 can affect the object word subsequently read.
- Earlier calls can affect the static datum consumed by the final call.
- The final call can affect the object before its pointer is returned.

The return value is therefore a pointer identity, not a guarantee of object validity or unchanged state.

### Arithmetic and access requirements

The first 16-bit element is interpreted unsigned; a set high bit does not make it negative or reject it.

The offset-29 operation acts on eight bits only.

The first object word is represented as a 32-bit integer. Adding 72 is not visibly a scaled object-index operation, and this function does not dereference the computed result before forwarding it. The supplied material does not establish a portable signed-overflow rule for this addition. Overflow behavior is documented_only rather than specified as wrapping, trapping, or rejection.

For execution to reach the return on the continuation path without an invalid access, the object must remain readable at offset 0 after F-493743038bd6 returns. That is a necessary access condition, not a proven dependency guarantee.

## Acceptance examples

These are conditional static acceptance cases, not reported executions. They assume that invoked dependencies return normally and that required accesses are valid.

1. **Null data pointer:** A null optional data pointer yields null with no dependency calls, regardless of the primary, third, and fourth values.

2. **Zero first element:** A readable first element equal to zero yields null with no dependency calls, even when the primary value is nonzero.

3. **Zero primary remains eligible:** With primary zero and a first element equal to seven, the preliminary dependency is called with zero as its first argument. Later progress depends on dependency results.

4. **Unsigned upper boundary:** A first element equal to 65,535 passes the initial gate. The function does not interpret it as a negative signed value.

5. **Preliminary rejection:** With a nonzero first element and preliminary result zero, acquisition is not called and the result is null.

6. **Acquisition failure:** With a nonzero preliminary result and null acquisition result, no state-byte write or initialization call occurs.

7. **Byte transformation:** An acquired object whose offset-29 byte is hexadecimal B4 has that byte changed to A5 before initialization. A byte of FF becomes EF; a byte of 10 becomes 01.

8. **Initialization failure:** If initialization returns any nonzero 32-bit result, cleanup is called once with the candidate pointer. Neither continuation dependency is called, and the function returns null. The earlier byte write has already occurred.

9. **Successful branch:** If initialization returns zero, the ordered dependency calls are preliminary check, acquisition, initialization, F-493743038bd6, and F-ebd0ee53699f. Cleanup is not called. The returned pointer equals the acquisition pointer.

10. **Post-call field visibility:** If the first object word is 4,096 after F-493743038bd6 returns, the first argument supplied to F-ebd0ee53699f is 4,168. An earlier value of that word is irrelevant to this calculation.

11. **Unchecked later results:** If both continuation dependencies return normally but report failure through their return values, this function still returns the candidate pointer. No visible branch consumes those results.
