# F-43325adca6a6

## Purpose

F-43325adca6a6 invokes an ordered sequence of indirect dependencies, derives address-like quantities from their results, performs mixed-width memory updates, and ends with an unresolved four-argument indirect transfer.

**Established static evidence:** no explicit parameters or returned value are represented. Observable operations include indirect invocations, dependency-result transformations, fixed-address state accesses, transitive memory accesses, repeated stores, and a final invocation whose first argument is `0x72`.

**[INFERENCE]** Some updates resemble packed-field processing, linkage maintenance, or publication of shared state. These similarities do not establish an application purpose, object model, or synchronization protocol.

This is a static behavioral contract. It does not establish that the represented execution is reachable, that its addresses are valid, or that it completes successfully.

### Derived quantities and initial stores

The following descriptive roles are used only within this contract:

- **Primary base:** a dependency result multiplied by `2^25`.
- **Packed base:** the low word of an earlier paired result shifted left by 25.
- **Bounded index:** a dependency result shifted left by eight, masked with `0x7fff`, then unsigned-shifted right by six.
- **Index base:** twice the bounded index.
- **Final pair:** the last represented 64-bit dependency result before direct mutation.

Under the conditional model, the bounded index is four times the original result’s low seven bits. Its range is `0`–`508` in multiples of four. The index base ranges from `0` through `1016` in multiples of eight.

The initial direct effects have a significant access order. A 32-bit store writes the packed base at offset `0x14` through the final pair’s high word. Next, packed-base offset `9` receives the high word’s low byte. A 32-bit store then writes the primary base at offset `0x54` from the final pair’s low word multiplied by `256`. Packed-base offset `9` is subsequently written again, now with the packed base’s low byte.

That second byte value is zero under the conditional model. Both stores remain part of the access trace.

The primary-base word at offset `0x14` is then cleared, followed by an unsigned-byte read at primary-base offset `5`. The index-base word at offset `0x14` is cleared before the captured byte is written as a 32-bit value at primary-base offset `0x34`.

A later read revisits primary-base offset `0x14`. **For ordinary, stable memory, this reread yields zero:** the intervening index-base store writes only zero, even if it overlaps that word, and the primary-base offset-`0x34` word does not overlap the same base’s offset-`0x14` word. Address aliasing alone does not justify a different result.

External modification, read-sensitive memory, or write-sensitive memory can invalidate that ordinary-memory conclusion. Those environmental behaviors remain unresolved.

After the reread, the index-base offset-`0x14` word is cleared again. Two consecutive byte stores to index-base offset `0x15` use the reread value’s low byte.

### Fixed-address state and transitive updates

The next phase captures the state associated with fixed address `0x05` through an unsigned 32-bit conversion. Call this the **converted state base**. Its capture precedes the assignment of the index base’s low byte to fixed address `0x01`.

Subsequent accesses use the converted state base at offsets `0x15` and `0x54`. This use establishes neither the width of its original read nor a byte-sized range.

The function reads the converted-state-base word at offset `0x54` before overwriting it. Call the captured word the **previous field**. Later calculations use twice, four times, and eight times this captured value as stored values and address-like bases.

This phase also includes:

- Byte writes at primary-base offset `0x11`, first with a previously shifted dependency result and then with zero.
- A 32-bit write through the primary-base offset-`0x14` reread value at offset `0x54`.
- Reads through offset `0x74`, followed by writes at the loaded values’ offset `0x54`.
- Repeated self-reference stores at previous-field offset `0x24`.
- Repeated byte writes at offset `9` through a captured transitive base.
- Successive index-base offset-`0x14` stores, including two stores of the previous field.
- A 32-bit fixed-address assignment at `0x54` using twice the previous field.
- A byte assignment at fixed address `0x15` using the index base.

Repeated identical writes are distinct represented effects.

Further updates use four times the previous field as a base. They mix byte reads at offset `5`, word reads at offsets `4`, `0x64`, and `0x74`, and stores at offsets `9`, `0x0d`, `0x14`, `0x15`, `0x44`, and `0x54`. Explicit unsigned-byte reads can become bases for offset-`0x74` word reads.

Several fields are reread after intervening writes. Captured values and fresh reads are not interchangeable where aliasing or externally observable memory behavior matters.

### Constant writes and repeated publication

A later transitive word, obtained through an unsigned-byte-based offset-`0x74` read, supplies scaled destinations for three stores of `0x3a`: one 8-bit store at four times that word, one 16-bit store at eight times it, and one 32-bit store at offset `0x20` from four times it.

The function also subtracts `0x96` from four times the previous field. Call this the **adjusted quantity**, and call four times it the **adjusted base**.

Adjusted-base offset `0x20` receives successive 32-bit values `0x20`, `0x2f`, a zero-extended byte read from adjusted-base offset `4`, and `0x20` again. The byte read occurs after the first two stores, not before them.

**The shared publication base is captured from its fixed global location before the 32-bit assignment of `0x20` at fixed address `0x60`.** The subsequent publication sequence uses that captured base. It does not reread the global after the `0x60` assignment. This distinction matters if the assignment or later derived-address writes overlap the global’s storage.

Each publication group comprises, in order:

1. A 32-bit link store at a scaled-base offset `0x54`.
2. A byte store of the adjusted base’s low byte at captured-shared-base offset `0x19`.
3. A byte store of the captured shared base’s low byte at adjusted-base offset `0x11`.
4. A 32-bit store of the scaled base at captured-shared-base offset `0x34`.

The first group uses eight times the previous field as its scaled base. Subsequent groups use eight times the adjusted quantity. Their link value is the earlier transitive word multiplied by four.

The later groups are statically repeated, without an explicit loop counter or conditional branch. Their multiplicity cannot be reduced to one group merely because ordinary-memory final values might coincide. An independently validated exact repetition count remains `documented_only`.

### Final captures, rereads, and transfer

After publication, the function captures the 32-bit fixed-address word at `0xa9`, then a word at offset `0x74` from the scaled transitive base. A byte assignment at fixed address `0x3a` follows, using the low byte of eight times the adjusted quantity plus `0x30`. Additional captures read a word at offset `0x14` from twice the earlier transitive word and a word at adjusted-base offset `4`.

Later effects include a byte store of `0x6c` at adjusted-base offset `8`, byte stores at offsets `9` and `0x0d`, and a 32-bit self-reference store at a derived-base offset `0x54`.

Fixed-address state at `0x67` has a distinct write/read history:

- It is assigned the low byte of the captured `0xa9` word.
- A derived-base offset-`0x44` word is then read.
- The state at `0x67` is read for assignment to fixed address `0x21`.
- After intervening derived-address writes and a word-copy operation, `0x67` is read again for a byte store at adjusted-base offset `9`.
- After further derived-address writes and a word read at adjusted-base offset `0x54`, `0x67` is read a third time for another byte store at adjusted-base offset `9`.

These are separate represented reads, not unconditional reuse of the captured `0xa9` word’s low byte. Intervening writes may overlap `0x67`; either later read can therefore observe changed state even with ordinary memory.

Other ordered effects include overwriting one shared-base offset-`0x54` destination first with a loaded word and then with the adjusted base, copying a captured word from adjusted-base offset `0x40` to offset `0x10`, and propagating captured values through offsets `0x44`, `0x54`, and `0x74`.

A byte store at a derived-base offset `1` uses a signed right shift. Its count is the adjusted base’s low eight bits, potentially exceeding 31. Actual shift semantics and the resulting byte are `documented_only`.

Near completion, the function reads an address-like word at a derived-base offset `4`, writes 16-bit `0x65` at twice that value, and reads its offset-`0x64` word. Further effects include a byte store at offset `0x11`, a 32-bit store of decimal `100` at offset `0x54`, another offset-`0x74` capture, and a final 32-bit store through twice a loaded word.

The final indirect invocation receives:

1. `0x72`;

## Acceptance examples

These are conditional static examples, not executed tests.

1. **Bounded maximum.** If the relevant result’s low seven bits are all set, the bounded index is `508` and the index base is `1016`. A bounded-index result of `511` does not match the represented arithmetic.

2. **Explicit byte widening.** An explicit unsigned-byte dereference yielding `0xff` widens to `255`. This rule does not establish how the undeclared state at `0x05` is read or extended.

3. **Ordinary-memory zero reread.** With stable ordinary memory and successful accesses, primary-base offset `0x14` rereads as zero. Even an overlapping index-base zero store does not supply a nonzero value.

4. **Externally sensitive reread.** If that location is externally modified or has read/write-sensitive semantics, the zero result is not guaranteed. This uncertainty is environmental, not a consequence of ordinary aliasing alone.

5. **Shared-base capture.** If the `0x60` assignment overlaps the shared-base global, publication still uses the value captured before that assignment. Moving the global read afterward changes the contract.

6. **Separate `0x67` observations.** Suppose `0x67` receives `0xab`, but an intervening derived-address store changes it to `0xcd` before a later offset-`9` store. That store uses the later read value `0xcd`, not necessarily `0xab`. The two later reads can also differ from each other.

7. **Distinct packed overwrites.** Packed-base offset `9` receives the final high word’s low byte and subsequently zero under the conditional model. Keeping only the final store loses an observable access.

8. **Repeated publication.** Write-sensitive observers can distinguish all publication groups even when ordinary-memory final values match.

9. **Partial failure and captures.** A later inaccessible address does not imply rollback. If a captured final-argument source changes afterward, the final invocation still uses the represented captured value.

10. **No implied text output.** Constants resembling characters do not establish a string, encoding, terminator, or output stream.
