# F-798e1776e621

## Purpose

F-798e1776e621 repeatedly adds one interpolated contribution to two adjacent signed 16-bit input samples and stores two 16-bit results. Each result passes through a range-selection operation before storage.

The routine also advances a 32-bit phase value, updates a position field in a caller-supplied state object, and stops after either:

- A position-boundary condition becomes true while a mode field is not equal to one.
- An externally supplied unsigned iteration threshold is reached.

**Inferred intent:** the two adjacent samples appear to form an interleaved pair, plausibly two audio channels, and the byte table appears to provide interpolation endpoints. Neither channel semantics nor an audio-specific contract is established.

This is not a complete, self-contained four-argument interface. The supplied representation consumes several additional machine-state values without initializing them. Their entry values are necessary to determine behavior.

## Behavior

### Entry and minimum work

The loop has no preliminary threshold or boundary check. It begins by processing a pair of samples.

Consequently, a zero threshold, an already-reached position limit, or an initially advanced threshold-progress counter does not prevent the first pair from being processed. Valid buffers and arithmetic inputs are still required for that pair.

The first iteration uses the interpolation endpoints and weight supplied in implicit entry state. It does **not** initially derive those values from the explicit phase or fetch them from the table.

### Interpolated contribution

Each iteration computes one contribution shared by both samples.

Let:

- \(a\) be the current endpoint.
- \(b\) be the next endpoint.
- \(w\) be the signed initial weight carrier shifted right by 16 bits.

Where signed arithmetic is representable and signed right shifts behave arithmetically, the contribution is:

\[
c = 256a +
\operatorname{ASR}_{15}\!\left(w\left(256b-256a\right)\right).
\]

The right shift occurs after multiplication. In particular, a negative intermediate must not be treated as though division necessarily truncates toward zero.

This mathematical description is conditional on the arithmetic interpretation discussed under **Uncertainties**. Arbitrary implicit entry values can exceed the safe ranges established for table-derived endpoints and weights.

### Pair processing and range selection

The first signed 16-bit source sample is read and added to the contribution. The result selects the first destination value:

- Below −32768: store the low 16 bits of the lower fallback.
- From −32768 through 32767 inclusive: store the result as a 16-bit value.
- At least 32768: store the low 16 bits of the upper fallback.

The first destination store occurs before the second source sample is read.

The second signed 16-bit source sample is then read, receives the same contribution, and undergoes the same selection before the second destination store.

**Established behavior:** this is fallback selection, not an unconditional guarantee of conventional signed saturation. It becomes conventional saturation only if the lower fallback represents −32768 and the upper fallback represents 32767.

After pair processing, both source and destination cursors advance by four bytes.

### Phase advance and position update

The routine forms a candidate phase by adding the phase increment to the current phase modulo \(2^{32}\).

It then calculates the difference between the candidate and current upper 16-bit phase components. The subtraction is unsigned 32-bit arithmetic. That difference is added to the position field at offset `0x88`, and the updated position is written back before either termination decision.

For an ordinary forward advance that does not wrap the entire phase, this difference measures the change in the integer portion of the phase. Across a full 32-bit wrap, it is the unsigned difference between two extracted 16-bit values; it is not an independently tracked, unbounded source-position advance.

The produced-count accumulator is incremented modulo \(2^{32}\) once per emitted pair.

### Boundary termination

After the position update, the routine checks whether the signed position limit is less than or equal to the updated position plus one.

Only if that comparison succeeds does it read the mode field. If the mode is not exactly one, the routine:

1. Writes one to the status byte at offset `0x8c`.
2. Leaves the loop.
3. Performs the common final writes.

This boundary exit precedes both the threshold-progress increment and the threshold read.

An important phase distinction follows: on this exit, the candidate phase has affected the position field, but it has **not** replaced the retained phase. The saved fractional phase therefore comes from the phase used to process the just-emitted pair.

A mode value of one suppresses this boundary exit. Other mode values do not.

### Threshold termination and continuation

If no boundary exit occurs, the routine:

1. Increments the threshold-progress counter modulo \(2^{32}\).
2. Replaces the retained phase with the candidate phase.
3. Reads the unsigned threshold word.
4. Exits if the threshold is less than or equal to the updated progress counter.

The threshold is read again on every iteration that reaches this check. It is not captured once at entry.

The threshold-progress counter and produced-count accumulator are separate state values. The supplied body neither initializes them nor requires them to match.

If the threshold does not stop processing, the routine prepares the next interpolation state:

- The retained phase’s upper 16 bits select a byte-table index.
- Two adjacent bytes at that index and the following index are loaded as endpoints.
- The low 16 phase bits are multiplied by 32768 to form the next weight carrier.

For this table-derived carrier, the next iteration’s weight is:

\[
w=\left\lfloor\frac{\text{fraction}}{2}\right\rfloor,
\]

where the fraction is the retained phase’s unsigned low 16-bit value. Its range is 0 through 32767. Thus the fractional component’s lowest bit does not affect the weight.

The table accesses occur only when another iteration will execute. A terminating iteration does not refresh endpoints.

### Common exit writes

Both exit paths perform these writes in order:

1. Store the produced-count accumulator through the threshold/result address.
2. Store the retained phase masked to 16 bits into the 32-bit field at offset `0x4c`.

On threshold termination, the retained phase includes the most recent increment. On boundary termination, it does not include that iteration’s candidate increment.

## Side effects

### Observable memory order

Within an iteration, the visible access sequence is:

1. Read the first source sample.
2. Write the first destination unit.
3. Read the second source sample.
4. Write the second destination unit.
5. Read the position field.
6. Write the updated position field.
7. Read the position limit.
8. Conditionally read the mode.
9. Either write the boundary-status byte, or read the threshold after advancing the counters and retained phase.
10. If continuing, read the current table endpoint and then its adjacent endpoint.

The common exit stores follow the loop exit.

This ordering matters if storage overlaps. For example, a first destination store that overlaps the second source sample changes the value subsequently read for that second sample. The routine does not snapshot the pair before writing.

Similarly, aliasing among destination storage, state fields, the table, and the threshold/result word can alter later reads. No non-aliasing check is present, and the contract does not silently substitute a disjoint-buffer model.

### Preconditions and failure behavior

The caller must provide accessible storage for every access that execution reaches:

- Two source samples and two destination units per iteration.
- The listed state fields.
- The threshold/result word.
- Both adjacent table bytes for every continuation refresh.

No pointer, bounds, alignment, or arithmetic-validity checks are visible. There is no explicit error return, rollback, or partial-output recovery path. Invalid accesses have no established handled outcome.

Termination is not guaranteed by the body alone. Counter wraparound, threshold contents, mode, phase progression, and position state can prevent either exit condition from being reached.

## Acceptance examples

These are conditional specification examples, not executed tests. Unless stated otherwise, storage is valid and disjoint, arithmetic is representable, and signed right shifts are arithmetic.

1. **Zero contribution preserves an in-range pair.**  
   With both initial endpoints equal to zero, source samples −123 and 456 produce destination values −123 and 456.

2. **Both samples receive the same contribution.**  
   With both endpoints equal to one, the contribution is 256 regardless of the interpolation weight. Source samples 10 and −10 produce 266 and 246.

3. **Fallback values control overflow output.**  
   With a contribution of 256 and a source sample of 32767, the sum is 33023. The output is the upper fallback’s low 16 bits—not necessarily 32767. With a contribution of −256 and a sample of −32768, the lower fallback is selected.

4. **The inclusive in-range endpoints remain direct results.**  
   A mixed result of −32768 is stored directly. A mixed result of 32767 is also stored directly. Results of −32769 and 32768 select the lower and upper fallbacks respectively.

5. **A zero threshold still permits one pair.**  
   With progress and produced count initially zero, threshold zero, and no boundary exit, one pair is processed. Both counters become one, the threshold check stops execution, and one is written to the threshold/result word.

6. **Boundary termination retains the previous fraction.**  
   Let the phase be `0x0000ffff`, the increment be one, the initial position be zero, the limit be two, and the mode be zero. The candidate phase is `0x00010000`, so the position becomes one. The boundary comparison succeeds because \(2 \leq 1+1\). The status byte becomes one, and the saved fractional phase is `0xffff`, not zero.

7. **Mode one permits the threshold path instead.**  
   Under the preceding phase and position conditions, setting mode to one suppresses the boundary exit. If the threshold then stops processing, the saved fractional phase is zero because the candidate phase has been retained.

8. **Adjacent fractional values can share a weight.**  
   Following a continuation refresh, fractional values two and three both produce weight one. With identical endpoints, they therefore produce identical contributions despite differing saved fractions.

9. **Threshold termination does not clear status.**  
   If the status byte initially contains one and execution exits through the threshold path without an aliasing write to that byte, it remains one.
