# F-d0f88f4a6898

## Purpose

F-d0f88f4a6898 conditionally acquires one required resource and, when an object flag is nonzero, a second resource. It records returned resource values and their requested sizes in an existing object.

The function returns a 32-bit status:

- **0:** the required acquisition returned a nonzero value, and any optional acquisition selected by the flag also returned a nonzero value.
- **3:** an existing resource prevented acquisition, the shared provider was unavailable, or an acquisition returned zero.

These statuses describe this function’s control flow. They do not establish that a returned resource is valid beyond being nonzero, that an unsuccessful operation leaves the object unchanged, or that cleanup has released any particular resource.

The terms “resource,” “provider,” and “size” describe inferred roles. The established behavior consists of field accesses, dependency calls, zero/nonzero decisions, and status returns.

## Behavior

### 1. Reject an object that already records either resource

After capturing the provider-slot address, the function reads the required-resource field at `0x65c`.

- If that value is nonzero, it returns 3.
- Only if that value is zero does it read the optional-resource field at `0x63c`.
- If the optional-resource value is nonzero, it returns 3.

These rejection paths perform no explicit object writes and call no dependencies. In particular, this is not an idempotent “already initialized means success” interface.

The optional-resource field is not read on the path where the required-resource field is already nonzero.

### 2. Clear both recorded sizes

If both resource fields were observed as zero, the function writes:

1. Zero to the required-resource recorded size at `0x660`.
2. Zero to the optional-resource recorded size at `0x640`.

These writes precede the provider-slot test and any dependency call.

This step does not explicitly clear either resource field. It relies only on the earlier observations that both were zero. It does not repeat those observations after a dependency runs.

### 3. Establish eligibility to request a resource

The function reads the captured provider slot.

- If the provider value is nonzero, it proceeds directly to the required acquisition.
- If the provider value is zero, it calls F-eec2f37c6975 with no explicit arguments.

Following F-eec2f37c6975:

- A nonzero return value causes this function to return 3.
- A zero return value permits another read of the captured provider slot.
- If that read is zero, this function returns 3.
- If that read is nonzero, it proceeds to the required acquisition.

Consequently, a zero return from F-eec2f37c6975 is necessary but not sufficient when the provider was initially zero. Conversely, a nonzero return causes failure even if that dependency changed the provider slot to a nonzero value.

The provider slot is read again when forming the acquisition call. The preceding nonzero test is not a guarantee that the same value, or a nonzero value, is passed to the dependency.

2. `0x20000`, equal to 131,072.

### 5. Decide whether to request the optional resource
