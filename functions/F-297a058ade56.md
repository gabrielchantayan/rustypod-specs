# F-297a058ade56

## Purpose

F-297a058ade56 polls a selected register bank, records observed conditions in seven caller-provided 32-bit words, and writes an acknowledgement mask after each iteration containing monitored status bits. One monitored condition additionally causes value-dependent register programming and, for rejected values, a call to F-3f5ace521ed4.

**Established static behavior:** polling continues until a status read contains none of the bits in `0x178`. The function initializes the output words to zero, then conditionally writes ones. It uses distinct address snapshots for polling and certain later register accesses; those addresses need not agree.

**Inferred intent:** the banks appear to contain device registers, the status writes appear to acknowledge conditions, and the output words appear to summarize events. Device semantics and eventual acknowledgement are not established.

The function provides no explicit error result, timeout, allocation, or selector rejection.

## Interface

### Inputs and completion

- **Selector:** a 32-bit integer. Values `0`, `1`, and `2` have individual selection rules. Every other value, including a negative value, uses the fallback rule.
- **Output region:** caller-provided storage for seven writable 32-bit words, covering byte offsets `0x00` through `0x1B`.

There is no visible validation of the output address, alignment, capacity, access permissions, or bank references.

The function has no explicit return value. Normal completion returns control after observing a status value with no monitored bits set.

### Address terminology

- **Fixed bank:** the literal bank address `0x3CC00000`.
- **Primary reference:** a global address value that is read several times during setup.
- **Alternate reference:** a separate global address value.
- **Entry primary snapshot:** the first primary-reference value read by this invocation.
- **Polling bank:** the address selected during setup and retained for all polling, secondary-status reads, acknowledgement writes, and accepted-value writes at offsets `0x38` and `0x34`.
- **Retained fallback address:** an independently sampled primary-reference value plus `0x4000` bytes, formed after polling-bank selection.
- **Shared value:** a global 32-bit value read during accepted-value programming.

These names distinguish separate reads. They do not imply that successive reads return equal values.

### Initial selection and global-read order

The first operation relevant to address selection is a read of the primary reference, retained as the entry primary snapshot.

Initial polling-bank selection then proceeds as follows:

| Selector | Additional reads during polling-bank selection | Polling bank |
|---|---|---|
| `0` | None | Fixed bank |
| `1` | Read the alternate reference | That alternate-reference value |
| `2` | Read the alternate reference; read the primary reference and form a tentative address plus `0x4000`; read the primary reference again | The newest primary-reference value, without displacement |
| Any other value | Read the alternate reference; read the primary reference and add `0x4000` | That newly sampled primary value plus `0x4000` |

For selector `2`, both the alternate-reference result and the tentative displaced address are discarded. For other fallback selectors, the alternate-reference result is discarded.

After this selection, **every selector**, including `0` and `1`, causes another primary-reference read. This final setup read supplies the retained fallback address after addition of `0x4000`. It is not derived from the entry primary snapshot or necessarily from the primary value used for polling.

All these reads and address formations precede output initialization. The primary-reference read counts are therefore:

- Selector `0` or `1`: two.
- Selector `2`: four.
- Any other selector: three.

Every nonzero selector also causes one alternate-reference read during setup.

### Later bank reselection

Each later reselection has this behavior:

| Selector | Global read performed by that reselection | Resulting selected bank |
|---|---|---|
| `0` | None | Fixed bank |
| `1` | Read the alternate reference | That newly read address |
| `2` | Read the alternate reference, then discard its result | Entry primary snapshot |
| Any other value | Read the alternate reference, then discard its result | Retained fallback address |

No later reselection rereads the primary reference.

Consequently:

- Selector `1` can use different addresses for polling, sampled-value reading, and programming.
- Selector `2` can poll at a newer primary-reference value while later accesses use the entry primary snapshot.
- Fallback selectors can poll at one sampled primary value plus `0x4000` while later accesses use a separately sampled primary value plus `0x4000`.
- Even an alternate-reference read whose value is discarded remains part of the established read sequence.

## Behavior

### Initialization

After all setup reference reads and address formation, the function writes full-width zeros to the output words in this exact order:

1. Word 3.
2. Word 0.
3. Word 2.
4. Word 6.
5. Word 1.
6. Word 4.
7. Word 5.

This is an ordered sequence of stores, not an atomic reset. The first status read occurs only after these stores finish.

### Polling and exit

Each iteration starts with a 32-bit status read at polling-bank offset `0x10`.

If none of the bits in `0x178` are set, the function returns. That terminating read causes no secondary-status read and no acknowledgement write.

Otherwise, the function:

1. Reads secondary status at polling-bank offset `0x14`, even when status bit `0x40` is absent.
2. Processes the saved status and secondary-status values in the order below.
3. Writes the accumulated acknowledgement mask at polling-bank offset `0x10`.
4. Performs another status read.

The acknowledgement contains exactly the monitored bits present in the saved status: `0x40`, `0x10`, `0x08`, `0x20`, and `0x100`. Other bits are not copied into it.

There is no iteration limit, delay, timeout, or independent exit condition.

### Secondary-status conditions

Status bit `0x40` contributes `0x40` to the acknowledgement regardless of secondary status.

If that status bit is present and the secondary low nibble is nonzero, the function performs these operations in order:

1. Stores `1` to word 3.
2. If secondary bit `0x08` is present, stores `1` to word 4.
3. If secondary bit `0x01` is present, stores `1` to word 1.
4. If secondary bit `0x04` is present, stores `1` to word 5, then calls F-3f5ace521ed4.

No explicit argument is shown for this call context. That does not establish that the dependency has no parameters.

Secondary bit `0x02` alone sets word 3 but no other secondary-derived output. Bits outside the low nibble do not satisfy the low-nibble condition.

The dependency call occurs before all direct-status flag processing and before value-dependent processing.

### Direct-status conditions

The function next processes the original status snapshot in this order:

1. Bit `0x10`: store `1` to word 0 and include `0x10` in the acknowledgement.
2. Bit `0x08`: store `1` to word 0 and include `0x08`.
3. Bit `0x20`: store `1` to word 2 and include `0x20`.

When both word-0 conditions are present, two distinct stores occur. Status is not reread between them.

### Sampled-value classification

If the original status contains `0x100`, the function reselects a bank using the later-reselection rules and reads its 32-bit value at offset `0x2C`. Bit `0x100` is included in the acknowledgement.

This path performs no writes at polling-bank offsets `0x38` or `0x34` and does not itself set word 6. It also does not clear a word 6 previously set during the invocation.

## Acceptance examples

These are **conditional static expectations**, not executed tests. Except where reference changes are specified, assume valid nonoverlapping output storage, stable globals, normally returning dependency calls, no external output modification, and a subsequent status read containing no monitored bits.

1. **No pending condition.**  
   A first status value of zero causes return after initialization. Setup reference reads still occur. There is no secondary-status read, acknowledgement, or dependency call. A first status of `0x02` behaves identically.

2. **Two stores to one output.**  
   Status `0x18` causes a secondary-status read, then two stores of `1` to word 0. The acknowledgement is `0x18`.

3. **Secondary condition without a dedicated flag.**  
   Status `0x40` with secondary `0x02` sets only word 3 and acknowledges `0x40`, without a dependency call.

4. **All represented secondary conditions.**  
   Status `0x40` with secondary `0x0D` stores ones to words 3, 4, 1, and 5 in that order, then calls F-3f5ace521ed4 before acknowledgement.

5. **Accepted boundaries and rejection.**  
   Sampled value `185` programs `12`; `1209` remains accepted and programs `75`; `1375` programs `85`. Each accepted case clears the two polling-bank registers and sets word 6. Values `184` and `1376` instead program `12`, call the dependency with the selector, and do not themselves set word 6.

6. **Two shared-value snapshots.**  
   Sampled value `264` rounds to `17` and programs `19`. If the first shared read yields `0x11223344` and the second yields `0x55667788`, offset `0x38` receives `0x55667788` and offset `0x34` receives `0x11223344`, following their zero writes.

7. **Single shared-value read.**  
   Sampled value `360` rounds to `23` and programs `25`. The shared value is read once; offsets `0x38` and `0x34` remain zero absent other writers.

8. **Selector `2` with changing primary reference.**  
   Suppose successive setup primary reads yield `0x10000000`, `0x20000000`, `0x30000000`, and `0x40000000`. An alternate-reference read occurs between the first and second primary reads and is discarded. The tentative displaced address is also discarded. Polling uses `0x30000000`; later selected-bank accesses use `0x10000000`. The retained fallback address is `0x40004000`, although selector `2` does not use it. Every later reselection still reads and discards the alternate reference.

9. **Fallback selector with separate snapshots.**

10. **Selector `0` still reads primary state.**  
    Selector `0` reads the primary reference once at entry and again after choosing the fixed polling bank. It performs no alternate-reference reads. Its later selected-bank accesses use the fixed bank.

11. **Accumulation is conditional.**  
    If one accepted iteration sets word 6 and a later rejected iteration occurs, this function does not clear word 6. Its final value remains one only if the dependency and external actors leave it unchanged.
