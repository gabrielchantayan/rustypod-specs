# F-26ff4a9b1180

## Purpose

F-26ff4a9b1180 selects a subordinate object from a parent object, conditionally performs preparation and a marked-state operation, invokes a final dependency, and publishes the selected object through an output location.

The established behavior is an ordered sequence of field reads, field writes, and dependency calls. Semantic interpretations such as “initialization,” “refresh,” or “locking” are not established by the supplied evidence. The contract therefore describes fields by byte offset and dependencies by opaque function ID.

The function reports success with a zero return value. Three dependency results can instead cause an immediate nonzero return. On these early-return paths, the function does not perform its final publication of the selected object.

## Interface

### Inputs and output

The function accepts two arguments:

| Argument | Role |
|---|---|
| Parent reference | An address-like value used to access the parent fields listed below and passed to preparation dependencies. |
| Output location | Writable storage receiving an initial zero and, on the successful terminal path, the selected subordinate reference. |

The return value is an integer status. Zero denotes completion of the visible sequence. A propagated nonzero status retains the value returned by the dependency that caused the early return; there is no visible translation or normalization.

The supplied representation uses integer-valued references rather than typed object pointers. Its field accesses are consistent with a 32-bit address and integer model, but the exact target ABI is not independently supplied. The four-byte accesses explicitly shown in the evidence are established. Interpretation of every address-like integer as a native 32-bit pointer is an ABI inference.

| Offset | Access width | Visible role |

### Preconditions

The output location must support the initial integer store before any parent field is read. The parent must support the accesses reached on the selected path.

A valid subordinate reference must ultimately be available for the unconditional subordinate-field access following selection. There is no visible null check at that point. In particular, if both initial parent references are zero, the function proceeds toward an access at offset `0x1d` from a zero reference rather than returning a defined missing-object status.

If preparation runs, the later value read from parent offset `0x7c` must also be suitable for subsequent accesses. The earlier nonzero check does not establish that it remains nonzero after intervening calls.

Additional validity, lifetime, alignment, and synchronization requirements imposed by dependencies are unknown.

## Behavior

### 1. Clear the output before selecting an object

The first visible action is to write integer zero to the output location.

Only afterward does the function read the parent reference at offset `0x84`. This ordering matters if the output location aliases parent storage: the initial output write can affect which reference or condition is subsequently observed.

The initial zero is not a guaranteed final output on failure. A dependency may modify the output through an alias or another available reference. The established guarantee is the initial write and the absence of a later publication by this function on early-return paths.

### 2. Prefer the reference at parent offset `0x84`

If the initial reference at offset `0x84` is nonzero, it becomes the selected subordinate reference. The fallback preparation sequence is skipped.

If that reference is zero, the function reads parent offset `0x7c`:

- A nonzero value enters the fallback preparation sequence.
- A zero value skips preparation and leaves the selected reference zero.

The fallback field is not read for this decision when the preferred reference is nonzero.

### 3. Prepare the fallback path when entered

The fallback preparation sequence has this observable order:

1. Read the four-byte parent field at offset `0x6c`.
2. Pass that value to F-8497b1f74739 and retain its returned unsigned value.
3. Call F-eae643b3e145 with the parent reference.
4. If its result is nonzero, return that result immediately.
5. Otherwise, read the parent byte at offset `0x0c`.
6. Consider optional preparation only when that byte is nonzero.

Optional preparation is performed when both of these conditions hold:

- The newly read parent byte at `0x0c` is nonzero.
- Bit `0x200` is clear in the value previously returned by F-8497b1f74739.

When optional preparation is performed, the function first writes four-byte zero to parent offset `0x30`, then calls F-e6b20755bfcb with the parent reference. A nonzero result from that dependency is returned immediately.

There is no restoration of the cleared field before such a return.

If the fallback sequence reaches its end, the function rereads parent offset `0x7c` and uses that value as the selected subordinate reference. Consequently:

- The value used for selection need not equal the earlier nonzero value that enabled preparation.
- Changes to this field made by either preparation dependency can affect selection.
- Parent offset `0x84` is not reread. A preparation dependency populating that preferred field does not redirect this invocation to it.
- The mask decision uses the retained result of F-8497b1f74739, not a recomputed value after preparation.

### 4. Conditionally perform the marked-state operation

The function reads the selected subordinate’s byte at offset `0x1d`.

If the byte is zero, this operation is skipped.

If the byte is nonzero, the function performs the following ordered actions:

1. Call F-d0d75bd453b2 with the selected subordinate reference.
2. Write byte value one to subordinate offset `0x1d`.
3. Write four-byte zero to subordinate offset `0x24`.
4. Call F-d1a694e844e1 with the selected subordinate reference.
5. After that dependency returns normally, write byte value zero to subordinate offset `0x1d`.
6. If the dependency’s result is nonzero, return that result immediately.

The write of one occurs after F-d0d75bd453b2 returns. That dependency therefore does not necessarily observe the marker normalized to one; it receives the object while the original nonzero value, or some other externally modified value, may still be present.

F-d1a694e844e1 is called after the explicit marker and four-byte clearing writes. On ordinary return, the marker is cleared before its status is tested. Thus a nonzero status does not bypass that clearing write.

The previous marker value is not restored. Any original nonzero value becomes zero on a normally returning marked-state path, subject to later writes by other actors.

No exception handling, nonlocal-exit cleanup, or recovery from invalid memory is visible. The post-call clearing write is established only when F-d1a694e844e1 returns normally.

### 5. Propagate a subordinate flag to the parent

After the marked-state operation is either skipped or completed with zero status, the function reads subordinate offset `0x1f`.

If the byte is nonzero, it writes byte value one to parent offset `0x13`.

If the byte is zero, it makes no direct write to that parent field. This is a conditional set, not an assignment of the subordinate byte’s truth value: a zero subordinate byte does not clear an already-set parent field.

This read occurs after any marked-state dependencies. Changes they make to subordinate offset `0x1f` therefore affect this decision.

### 6. Perform the final call and publish

The function calls F-faf498a4a7fe with the selected subordinate reference.

After that call returns normally, the function writes the retained selected reference to the output location and returns zero.

No result from F-faf498a4a7fe is inspected. The visible caller provides no status-based failure branch after that call.

The selected reference remains the one retained during selection. This function does not reload it from the parent after any subordinate dependency. If a dependency replaces a parent reference, publication still uses the retained value.

## Side effects

Direct writes attributable to this function are limited to the following, in their applicable paths:

- Initial zeroing of the output location.
- Clearing parent offset `0x30` before optional preparation.
- Setting subordinate offset `0x1d` to one.
- Clearing subordinate offset `0x24`.
- Clearing subordinate offset `0x1d` after F-d1a694e844e1 returns.
- Conditionally setting parent offset `0x13` to one.
- Publishing the selected reference to the output location.

There is no general rollback on failure. Preparatory writes and dependency side effects preceding an error remain observable unless another actor changes them.

The function does not directly allocate, release, or copy an object. Returning a reference through the output does not, by itself, establish ownership transfer, reference-count adjustment, or a lifetime guarantee. Any such behavior inside dependencies is unknown.

Dependencies must not be assumed to preserve global state, unrelated fields, or object lifetime. In particular, this function continues to access its retained subordinate reference after several dependency calls. Whether those dependencies guarantee that continued use is valid is undocumented here.

Aliasing can make nominally separate fields overlap with the output location or with another object. The visible access order remains authoritative; independent-object interpretations require an explicit non-aliasing assumption.

No atomic operations, locking protocol, memory barriers, or concurrent-access guarantees are established by the supplied evidence.

## Acceptance examples

These are conditional static acceptance scenarios, not executed tests. Unless stated otherwise, they assume valid, disjoint storage, normal dependency returns, and no dependency mutations beyond those explicitly described.

1. **Preferred reference bypasses fallback preparation.**  
   Parent offset `0x84` contains a valid reference, and its subordinate byte at `0x1d` is zero. None of F-8497b1f74739, F-eae643b3e145, F-e6b20755bfcb, F-d0d75bd453b2, or F-d1a694e844e1 is called. The final dependency receives the preferred reference, which is then published with a zero status.

2. **Fallback selection uses the post-preparation value.**  
   The preferred reference is zero and the fallback reference initially names one object. F-eae643b3e145 returns zero and changes the fallback field to a different valid object. With optional preparation skipped, subsequent subordinate operations and final publication use the replacement object.

3. **A nonzero first preparation result stops later work.**  
   F-eae643b3e145 returns a nonzero status. That exact status is returned. The parent byte at `0x0c` is not subsequently read by this function, optional preparation is not called, and neither subordinate processing nor final publication occurs.

4. **The mask suppresses optional preparation.**  
   The parent byte at `0x0c` is nonzero, but the retained mask has bit `0x200` set. This function neither clears parent offset `0x30` nor calls F-e6b20755bfcb.

5. **Optional preparation failure leaves its preceding clear in place.**  
   The parent control byte is nonzero and mask bit `0x200` is clear. Parent offset `0x30` is cleared before F-e6b20755bfcb receives the parent. If that dependency returns a nonzero status, it is propagated without a restoration write by this function.

6. **Marked-state failure still clears the marker.**  
   Subordinate offset `0x1d` initially contains any nonzero byte. F-d0d75bd453b2 is called, the marker becomes one, and offset `0x24` becomes zero before F-d1a694e844e1 is called. If the latter returns a nonzero status normally, the marker is cleared before that status is returned. The later flag propagation and final dependency are skipped.

7. **A zero flag does not clear parent state.**  
   Subordinate offset `0x1f` is zero and parent offset `0x13` is already one. This function leaves that parent byte unchanged before calling the final dependency.

8. **Two absent references do not produce a checked failure.**  
   Both parent reference fields are zero. No preparation dependency is called. The subsequent subordinate-field access lacks a valid selected object; no defined error status or successful publication is established for this input.
