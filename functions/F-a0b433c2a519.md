### Address capture and aliasing

The time of each address read matters.

E is read before either C field is written. Once read, E remains the destination base for the byte clear even if a subsequent write changes the memory at B + 100.

D is read after the writes to C + 84, E + 17, and C + 20. Consequently, if any of those writes overlap A + 100, D can differ from the value stored there at function entry. An equivalent implementation must preserve this dependency rather than assuming both address-bearing fields can be read at the start.

After D has been read, the zero store at P + 20 occurs before the two stores through D. If that zero store modifies A + 100, it does not change the already captured D used by those later stores.

No non-aliasing guarantee is visible. A, B, C, D, E, P, Q, and G may designate overlapping storage unless a separate caller contract forbids it. Where destinations overlap, later writes determine the final contents of the overlapping bytes, subject to target representation and successful execution.

For example, a byte written at Q + 17 can subsequently be overwritten by the final store at A + 9 if those addresses are equal. The function does not preserve the earlier byte merely because the two fields have different contract names.
