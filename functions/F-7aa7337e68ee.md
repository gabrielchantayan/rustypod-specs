# F-7aa7337e68ee

## Purpose

F-7aa7337e68ee selects an indirect callable using a value read from its input, invokes that callable, and returns the four-byte value stored at the address supplied by the invocation.

The selection calculation has an important ordering constraint: the input supplies a **signed 32-bit integer**, the function adds 64 in that integer domain, and only then converts the result to the pointer used to read the callable entry. The established operation is not pointer-width address arithmetic.

The function returns the contents of the storage identified by the callee, not the address of that storage.

A dispatch-table lookup is a plausible interpretation. The evidence does not establish an object model, a property name, or an application-level meaning for the returned value.

## Behavior

### Observable sequence

The established sequence is:

1. Read the signed 32-bit integer at the input address.
2. Add the integer constant 64 to that value in the signed 32-bit integer domain.
3. Convert the addition result to the pointer used to locate the callable entry.
4. Read the callable reference from that location.
5. Invoke the selected callable without explicit arguments in the supplied representation.
6. Use the invocation result as the address of a four-byte value.
7. Read that value and return it.

The pointer used for the callable-entry read is therefore formed **after** the integer addition. The input pointer itself is not the base of this calculation.

The function performs one callable-entry lookup and one indirect invocation. No iteration, second lookup, or alternate return path is visible.

### Layout and arithmetic

Three storage roles are distinguishable:

- **Input storage:** a signed 32-bit integer at byte offset zero.
- **Callable-entry storage:** a callable reference at the address obtained by converting the integer addition result.
- **Result storage:** a four-byte value at the address supplied by the indirect invocation.

The integer displacement is exactly 64. There is no multiplication by a table-entry size, no scaling by the width of the input integer, and no pointer-indexing operation before the conversion.

Where the target’s integer-to-pointer interpretation maps these integer values to corresponding byte addresses, this calculation can describe an entry 64 bytes beyond the address represented by the initial value. That address interpretation is conditional; it must not replace the established integer-addition-then-conversion order.

The addition is not established as an unsigned 32-bit operation or as a wider-pointer operation. In particular, the evidence does not authorize:

- Widening the initial value to pointer width before adding 64.
- Reinterpreting the initial signed value as unsigned before the addition.
