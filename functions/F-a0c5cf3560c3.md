# F-a0c5cf3560c3

## Purpose

F-a0c5cf3560c3 conditionally obtains a value from a four-byte-entry table, passes that value and a one-byte attribute to a dependency, and supplies the dependency’s result to another dependency together with an earlier result.

The condition uses an unsigned 32-bit index and a wrapped subtraction from a 32-bit count-like field. It is not an ordinary bounds check against that field: the comparison is against the field minus one, and a zero field wraps the threshold to the largest unsigned 32-bit value.

The function has no explicit return value. Its externally visible effects occur through dependency calls and memory reads. The meanings of the resulting values, table contents, and final operation are not established.

## Behavior

### Initial dependency call

The first operation is a call to F-1c06d0a5910b with:

- A as its first argument;
- a 32-bit zero as its second argument;
- zero as its third argument.

The returned 32-bit value is retained for possible use by the final dependency call.

This call occurs before the function’s direct read at B plus `0x40`. Consequently, any dependency side effect that changes the record can affect the subsequent read. The function does not establish that this dependency preserves memory, global state, or the object associated with A.

### Obtaining an address and scalar

The function reads four bytes from B plus `0x40` and passes that value to F-8ff48652068d.

The 64-bit result is retained and divided by bit position:

- the low 32 bits supply the address used for later reads at `0xF64` and `0xF68`;
- the high 32 bits are passed to F-11fd26e92e31 as a 32-bit signed argument.

The high-half conversion does not introduce a wider numeric quantity or a range check. Its 32-bit pattern is supplied as a signed value. For example, a high half of `0xFFFFFFFF` is presented as −1 under the recovered representation.

This is a numeric split of the dependency result. It does not establish the byte order or memory layout of any structure internal to F-8ff48652068d.

### Producing the index

After F-8ff48652068d returns, the function reads B plus `0x40` again. It does not reuse the earlier field value.

F-11fd26e92e31 receives, in argument order:

1. the newly read four-byte field;
2. the signed 32-bit interpretation of the retained high half;
3. C;
4. D.

Its result is interpreted as an unsigned 32-bit index.

The two reads of B plus `0x40` are observably distinct. If F-8ff48652068d changes that field, the two dependencies receive different values. The later index calculation still uses the high half of the earlier 64-bit result; the function does not obtain a replacement result to match the second field value.

### Evaluating the threshold

After F-11fd26e92e31 returns, the function reads the four-byte field at the retained low-half address plus `0xF68`.

Let:

- \(i\) be the unsigned 32-bit index;
- \(n\) be the 32-bit pattern read from the count-like field;
- \(t = (n - 1) \bmod 2^{32}\).

The accepted branch is taken exactly when:

\[
i < t
\]

The comparison is unsigned. Although the field is presented through a signed 32-bit load in the supplied representation, subtraction by an unsigned one makes the relevant operation unsigned 32-bit arithmetic.

Consequences include:

- For \(n = 0\), the threshold is `0xFFFFFFFF`.
- For \(n = 1\), the threshold is zero, so no index is accepted.
- For ordinary positive \(n\), the accepted indices are zero through \(n-2\).
- An index equal to the threshold is rejected.
- An index of `0xFFFFFFFF` is always rejected.
- Field patterns with the top bit set are not rejected as negative counts; they participate in the unsigned subtraction.

The count-like field is read after F-11fd26e92e31 completes. Changes made by that dependency can therefore affect the branch. The base address itself remains the low half retained from the earlier dependency result.

### Accepted branch

When the comparison succeeds, the function obtains:

- the four-byte table base at the retained low-half address plus `0xF64`;
- the four-byte entry selected by the index;
- the one-byte attribute at B plus `0x44`.

The entry address is the table base plus four times the index. The recovered arithmetic is 32-bit; there is no explicit widening or overflow check. A large accepted index can wrap the entry displacement or final address.

The function calls F-1c06d0a5910b a second time with:

1. a pointer to a local 20-byte storage region;
2. the selected four-byte table entry;
3. the one-byte attribute.

The function itself does not initialize the local region before this call. The source establishes the region’s size and address passing, but not what the dependency writes there or how much storage it requires.

The returned 32-bit value is passed to F-047d22db5c73 as its second argument. The first argument is the result retained from the initial F-1c06d0a5910b call.

After F-047d22db5c73 returns, this function returns without inspecting that call’s result.

### Rejected branch

When the comparison fails, the function returns immediately after the condition.

On that path, this function does not:

- read the table base at `0xF64`;
- read a table entry;
- read the byte at B plus `0x44`;
- make the second F-1c06d0a5910b call;
- call F-047d22db5c73.

The initial F-1c06d0a5910b call and both index-preparation dependency calls have already occurred. Rejection does not undo their effects.

## Acceptance examples

These are conditional static examples, not executed tests. They assume preceding dependencies return normally and every reached access is valid.

1. **Ordinary accepted index.**  
   With count-like field 5 and returned index 3, the threshold is 4. The branch is accepted. The selected entry begins 12 bytes after the table base, and the two conditional calls occur.

2. **Excluded upper entry.**  
   With count-like field 5 and index 4, the comparison fails. No table-base, entry, or attribute read occurs in this function.

3. **Count-like field of one.**  
   With field 1 and index 0, the threshold is zero. The branch is rejected. In fact, every unsigned index is rejected for this field value.

4. **Zero-field underflow.**  
   With field 0 and index 0, the threshold wraps to `0xFFFFFFFF`, so the branch is accepted. This demonstrates the arithmetic, not table safety: a valid selected entry is still required for normal completion.

5. **Maximum index.**  
   With field 0 and index `0xFFFFFFFF`, equality with the threshold rejects the branch. No possible field value produces a threshold larger than this index.

6. **Top-bit field pattern.**  
   With field `0x80000000` and index `0x7FFFFFFE`, the threshold is `0x7FFFFFFF`, and the branch is accepted. The field is not treated as an invalid negative count.

7. **Changed record field.**  
   Suppose the first read at B plus `0x40` yields X, and F-8ff48652068d changes that field to Y. F-8ff48652068d receives X; F-11fd26e92e31 receives Y together with the high half returned from the call made using X.

8. **Wrapped displacement.**  
   With field 0 and index `0x40000000`, the comparison accepts. Multiplication by four wraps to zero in 32-bit arithmetic, selecting the table-base address rather than a distinct four-gigabyte displacement.
