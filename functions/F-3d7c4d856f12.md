# F-3d7c4d856f12

## Purpose

F-3d7c4d856f12 performs an ordered dispatch over objects supplied by an iteration dependency. It first invokes a receiver-specific operation, initializes iteration using an interior address of that receiver, and then invokes an operation on each object yielded. Each per-object invocation receives the two original 32-bit input values and a final zero argument. Normal termination is followed by a finalization call.

The iteration interpretation is inferred from the initialize–advance–finalize call pattern. The established behavior is the call sequence and its data flow; the meanings of the receiver, yielded objects, and two forwarded values are not established.

The initial object pointer is not directly dereferenced merely because it was supplied. Its local copy becomes the current object pointer, subject to any changes made by dependencies. In particular, the advance dependency receives the address of that slot and may replace its contents.

No count, status, last-object pointer, or updated iteration state is explicitly returned to the caller. An updated local object-pointer slot is not copied back into the caller’s fourth argument storage.

## Behavior

### 1. Establish local state

Before the first dependency call, the function:

1. Copies the first 32-bit value into local storage.
2. Copies the second 32-bit value into separate local storage.
3. Copies the initial object pointer into a local pointer slot.

The address of the first value’s local copy is subsequently used as an iteration-state address. The address of the local pointer slot is subsequently used as an output-capable argument to the advance dependency.

The shown function does not itself overwrite either local value copy after these initial assignments. That does not establish their later contents: dependencies receiving the state address may mutate memory through it.

The two local value copies and pointer slot are shown as stack locals, but a complete public state-record layout is not established. In particular, the extent of storage that the state dependencies may access is unknown.

### 2. Invoke the preliminary dependency

F-61ab63585c22 is called with no explicit arguments.

No return value from this call is consumed. No success or failure branch follows it.

This call occurs before the receiver’s indirect-call table is read. Consequently, the initial indirect dispatch is not established as using a table value captured before F-61ab63585c22 ran. Any effect that dependency has on relevant memory can precede the table lookup.

The purpose and side effects of this dependency are unknown.

### 3. Invoke the receiver operation

The function reads the receiver’s first word as a table base, obtains the callable target at offset 0x150, and invokes that target with the receiver as its sole explicit argument.

There is no null check on the receiver, table base, or callable target. No result from the target is used.

This operation completes before initialization of the iteration state. Its effects may therefore influence what the initializer or later dependencies observe.

### 4. Initialize iteration state

F-8ca21d3a8cca is called with:

- The address of the local copy of the first 32-bit value.
- The receiver-derived address at byte offset 0xA8 under the represented integer width.

No return value is inspected. There is no explicit branch for initialization failure.

The second argument is an interior address, not a value loaded from that address by this function. Any reading or writing of the associated receiver region is performed by the dependency, if at all.

### 5. Advance and dispatch

The function calls F-b38a3aba0e18 with:

- The same local-state address supplied to initialization.
- The address of the local object-pointer slot.

Its result is interpreted as an integer zero/nonzero condition:

- **Zero:** stop iterating.
- **Any nonzero value:** perform one per-object invocation, then call the advance dependency again.

There is no requirement in this function that the result equal one. Negative nonzero results also enter the dispatch path under the represented signed integer interpretation.

On each nonzero result, the function uses the current contents of the local object-pointer slot. It reads that object’s first word as an indirect-call table base, obtains the callable target at offset 0x90, and invokes it with these explicit arguments, in order:

1. The current object pointer.
2. The original first 32-bit input value.
3. The original second 32-bit input value.
4. Zero.

The two forwarded values come from the function’s original input values, not from the potentially modified local copies used by the iteration dependencies. The function applies no arithmetic, conversion, filtering, or normalization to their 32-bit contents.

No result from the per-object operation is inspected. After that operation returns, the function immediately attempts another advance. There is no independent iteration limit, cancellation condition, duplicate suppression, or accumulated result.

A nonzero advance result does not itself prove that the object-pointer slot was updated. If a dependency leaves it unchanged, the function uses whatever pointer the slot currently holds, including the initial pointer on the first iteration.

### 6. Finalize

When an advance call returns zero, F-d0d3f100effc is called with the local-state address.

The object-pointer slot is not dereferenced as a consequence of that terminating result. The finalization dependency is the next explicit call.

After finalization returns, the function returns normally.

This finalization is established only for the normal path reaching a zero advance result. The supplied body contains no explicit recovery mechanism ensuring finalization after a fault, exception, nonlocal exit, or nonreturning dependency.

## Side effects

### Direct accesses and writes

The function directly establishes the three local values described above. It exposes addresses of local storage to dependencies.

Its direct receiver-related memory reads are:

- The receiver’s table-base word.
- The callable table entry at offset 0x150.

For each nonzero advance result, its direct yielded-object memory reads are:

- The current pointer from the local object-pointer slot.
- That object’s table-base word.
- The callable table entry at offset 0x90.

It does not explicitly write to receiver fields, yielded-object fields, or global storage. This does not imply those locations remain unchanged: all direct and indirect callees may have side effects not visible in the supplied body.

### Ordering

The established call order is:

1. F-61ab63585c22.
2. Receiver operation at table offset 0x150.
3. F-8ca21d3a8cca.
4. Alternating advance calls and, for each nonzero result, one yielded-object operation.
5. F-d0d3f100effc after the first zero advance result.

Each yielded-object table lookup occurs after the advance call that enables it. It is not cached across iterations.

The receiver operation is called even if the first advance result is zero, provided preceding calls return normally.

### Ownership and lifetime

The function contains no explicit allocation or deallocation. It does not establish ownership transfer for the receiver, the initial pointer, or yielded objects.

The finalizer’s name in this contract describes its position in the sequence, not a proven resource-release guarantee. It may release resources, mutate state, or perform some other action; those semantics are unknown.

Addresses of local storage are available to dependencies during this invocation. If a dependency retains an address for use after the function returns, that address would refer to expired local storage. The supplied evidence does not establish whether any dependency retains such addresses.

The implementation also does not establish that callbacks preserve globals, collection membership, object lifetime, or iteration validity.

## Acceptance examples

These examples are conditional contracts derived from the supplied static evidence. They are not runtime results.

### Empty iteration

If all preparatory calls return normally and the first advance call returns zero:

- The preliminary dependency runs once.
- The receiver operation runs once.
- Initialization runs once.
- No yielded-object operation runs.
- Finalization runs once, followed by normal return.

The initial object pointer need not be dereferenceable for the loop body in this scenario because that body is not entered. Dependencies may impose additional requirements.

### Two yielded objects

If successive advance results are nonzero, nonzero, and zero, and the first two calls leave valid object pointers in the slot:

- Exactly two yielded-object operations run.
- Each uses the pointer present after its corresponding advance call.
- Each receives the original first and second 32-bit values and a final zero.
- Finalization occurs only after the third advance call returns zero.

### Negative continuation result

If an advance call returns negative one and supplies a valid object pointer, the yielded-object operation runs. The function does not treat that result as a distinct error category.

### Unchanged pointer slot

If the first advance call returns nonzero without changing the local pointer slot, the yielded-object dispatch uses the initial object pointer, subject to any other mutation of that slot by dependencies.

If that pointer is invalid, there is no explicit guard preventing an invalid table access.

### Mutated state values

If initialization or advancement changes the local copy of either 32-bit value, later per-object calls still receive the original input values. The altered state may affect iteration through dependency behavior, but it is not the source of the forwarded callback arguments.

### Repeated object

If separate successful advance calls supply the same object pointer, the function dispatches to it once per successful advance. It does not suppress repeats.

### Nonterminating advancement

If every advance call returns nonzero and each subsequent operation returns normally, iteration continues without an internal bound. The finalization call is not reached.
