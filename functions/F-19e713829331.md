# F-19e713829331

## Purpose

F-19e713829331 searches a linked, tree-shaped structure and either reports an existing candidate or delegates an insertion-like operation. It writes a four-byte result followed by a one-byte outcome marker to caller-provided storage.

**Established static behavior:** the function descends through node links using F-31a0b2b5649a, conditionally examines a neighboring candidate, and invokes F-a7dd7848f4b0 on paths marked with outcome byte `1`. A path that reports a candidate without invoking F-a7dd7848f4b0 produces outcome byte `0`.

**Inferred intent:** the structure resembles an ordered tree with a header or sentinel, and the context byte at offset `0x18` appears to select whether an existing equivalent entry may prevent insertion. Neither the comparator’s ordering semantics nor the insertion dependency’s actual effects are established here.

The outcome byte is therefore an observable branch marker, not independently proven evidence that allocation or insertion succeeded.

## Behavior

### Initial descent

Before the first comparison, the function obtains the initial node by reading the context’s header reference and then the four-byte field at header offset `0x04`. It separately reads the context’s header reference again to establish the initial saved candidate.

Thus, the initial node and initial saved candidate are obtained through separate context reads. Their equality to values from one stable header is not enforced by the function.

The saved comparison outcome starts as nonzero. This matters when the initial node is null: no comparison occurs, and the later logic treats the descent outcome as nonzero.

For each nonnull node:

1. Two local four-byte scratch values are cleared.
2. F-31a0b2b5649a is called with:
   - the address at context offset `0x19`;
   - the subject;
   - the current node’s data address at offset `0x10`.
3. The current node becomes the saved candidate.
4. A zero dependency result selects the link at node offset `0x0c`.
5. A nonzero dependency result selects the link at node offset `0x08`.

The chosen child link is read after the dependency returns. A dependency mutation of that node’s links can therefore affect the next step.

Descent stops at a null child. There is no balancing, explicit mutation, or allocation performed directly during this loop.

### Mode selection after descent

The byte at context offset `0x18` is read only after descent finishes.

- If it is nonzero, the function proceeds directly to the common insertion-like path.
- If it is zero, the saved candidate is placed in a local candidate slot, and additional checking occurs.

A dependency that changes the mode byte during descent can therefore affect this decision. The function does not cache the mode at entry.

### Zero-mode handling after a nonzero descent outcome

If the last descent result is nonzero—or descent made no comparisons—the function reads the context’s header reference again and copies the four-byte field at header offset `0x08` into a local boundary slot.

It then calls F-16fc12967f5e with:

- the address of the local candidate slot;
- the address of the local boundary slot.

Both arguments are addresses of local storage, not merely the contained values. The dependency’s signature and implementation are unknown; changes to those slots cannot be ruled out.

If F-16fc12967f5e returns nonzero:

- F-a7dd7848f4b0 is invoked immediately;
- its first argument addresses a local four-byte output slot;
- its remaining arguments are the context, literal zero, the saved descent candidate, and the subject;
- the resulting local four-byte value is written to result storage;
- the marker byte is written as `1`;
- the function returns.

This path uses the saved descent candidate as the fourth dependency argument, not the potentially modified local candidate slot.

If F-16fc12967f5e returns zero, the function performs a predecessor-like adjustment using the candidate slot’s current contents.

### Predecessor-like candidate adjustment

The adjustment first reads one unsigned byte at candidate offset `0x00`. Only whether that byte is zero matters.

If the byte is zero, the function reads the candidate’s offset-`0x04` address and then reads offset `0x04` from that referenced object. If the resulting address equals the candidate, the candidate becomes the address stored at its own offset `0x0c`. No general left-subtree or parent-climbing traversal is performed in that special case.

Otherwise, the adjustment uses the link at candidate offset `0x08`:

- **Nonnull link:** follow that link, then continue through offset-`0x0c` links until reaching a node whose offset-`0x0c` link is null. That last node becomes the candidate.
- **Null link:** follow the parent-like address at offset `0x04`. At each step, compare the parent’s offset-`0x08` link with the prior candidate, then replace the candidate with that parent. Continue climbing while the comparison matches. On the first nonmatch, the candidate remains the parent reached on that step.

There is no explicit root boundary, null-parent guard, depth bound, or cycle detector in this adjustment. Correct termination depends on the structure and its sentinel conventions.

The first-byte test is a byte test, not a four-byte pointer or tag read. A nonzero byte bypasses the special parent-based test regardless of the other bytes at that address.

### Final candidate comparison in zero mode

The function reaches the final comparison either:

- directly after descent when the last descent result was zero; or
- after the boundary check returned zero and candidate adjustment completed.

It clears two local four-byte scratch values, then calls F-31a0b2b5649a with:

1. the address at context offset `0x19`;
2. the candidate’s data address at offset `0x10`;
3. the subject.

The second and third arguments are reversed relative to descent.

If the dependency returns zero:

- the current candidate address is written as the four-byte result;
- the marker byte is written as `0`;
- F-a7dd7848f4b0 is not called;
- the function returns.

A zero result here is the complete observed condition for reporting the candidate. The function does not independently compare payload bytes or invoke a separate equality operation.

If the dependency returns nonzero, execution proceeds to the common insertion-like path.

### Common insertion-like path

This path is taken when:

- the mode byte is nonzero; or
- zero-mode candidate checking ends with a nonzero final comparison.

F-a7dd7848f4b0 receives:

1. the address of a local four-byte output slot;
2. the context;
3. literal zero;
4. the saved final descent node, or initial saved header when descent was empty;
5. the subject.

The function copies the local four-byte output to result storage, then writes marker byte `1`.

The adjusted candidate used for the final comparison does not replace the saved descent node supplied to this dependency.

## Acceptance examples

These examples are conditional on valid accessible storage, terminating structure links, and the stated dependency behavior. They are static acceptance scenarios, not executed tests.

### Nonzero mode bypasses candidate checking

Given a traversal ending at a null child and a nonzero mode byte when read afterward:

- No F-16fc12967f5e call occurs.
- No reversed-argument final comparison occurs.
- F-a7dd7848f4b0 receives the saved descent candidate.
- If that dependency writes value `V` to its output slot and returns normally, result storage receives `V` and marker `1`.

### Zero-mode existing candidate

Given zero mode and a final descent comparison returning zero:

- No boundary-helper call or predecessor adjustment occurs.
- The final comparison receives candidate data before the subject.
- If that comparison returns zero, the candidate address is reported with marker `0`.
- F-a7dd7848f4b0 is not invoked.

### Boundary-helper nonzero result

Given zero mode and a nonzero descent outcome, suppose F-16fc12967f5e returns any nonzero value:

- Candidate adjustment and final comparison are skipped.
- Insertion-like delegation uses the saved descent candidate, even if the helper changed the separate candidate slot.
- Normal completion reports the dependency-produced value with marker `1`.

### Rightmost node of the left subtree

Suppose candidate adjustment reaches its ordinary subtree case and the candidate’s offset-`0x08` link is nonnull.

The final candidate is the node reached by taking that link and then following offset-`0x0c` links until null. A zero final comparison reports that adjusted node, not the original descent candidate.

### Parent-climbing boundary

Suppose the offset-`0x08` link is null and the immediate parent’s offset-`0x08` link does not equal the original candidate.

The adjustment stops after reaching that parent. The parent becomes the final-comparison candidate.

### Empty initial descent

If the initial header offset-`0x04` link is null:

- No descent comparison occurs.
- The saved descent outcome remains nonzero.
- Nonzero mode leads directly to insertion-like delegation using the saved header.
- Zero mode first invokes F-16fc12967f5e with the saved header candidate and the freshly read boundary value.

A false helper result is not independently guaranteed safe; subsequent traversal depends on valid header and sentinel relationships.

### Width and publication boundary

For a normally returning invocation, with dependencies that do not independently write result storage, the direct result publication modifies exactly four bytes at offset `0` and one byte at offset `4`. It does not initialize padding after the marker.
