# F-0b90d48d906b

## Purpose

F-0b90d48d906b conditionally derives an unsigned result from two fields of an addressable object. A dependency result and a one-byte discriminator determine whether those fields participate in the result.

Three outcomes are established:

- A zero input produces the constant **7**, without calling the dependency or accessing object fields.
- A nonzero input for which F-767b181ec9e1 returns zero produces the constant **21**, without subsequently accessing object fields.
- A nonzero input for which F-767b181ec9e1 returns nonzero produces either **7** or the bitwise intersection of two unsigned fields, depending on the discriminator read after that call.

These constants have no established semantic labels. In particular, neither is proven to mean success, failure, availability, or a specific capability.

The function accepts one integer-valued argument used both as a zero/nonzero selector and, on some paths, as an object address.

For a nonzero argument, the same value is passed to F-767b181ec9e1. The argument is not established to be a handle rather than an address, nor is there evidence of a particular object type beyond the accessed layout.

### Output

The return type is unsigned. The possible results are:

- **7**, also written as hexadecimal **0x07**.
- **21**, also written as hexadecimal **0x15**.
- The bitwise AND of two unsigned fields.

The mask-derived result can equal either constant. Consequently, the returned number alone does not uniquely identify the branch taken.

## Behavior

### Zero input

When the input is zero, the function returns 7.

On this path, it does not call F-767b181ec9e1 and does not read any of the three listed object fields.

### Nonzero input and dependency gate

When the input is nonzero, the function first calls F-767b181ec9e1 with that input.

The dependency’s returned integer is tested only for equality with zero:

- A zero return causes an immediate return of 21.
- Any nonzero return allows evaluation of the discriminator.

No particular nonzero value is required. A negative dependency result, if representable by its return type, follows the same branch as a positive nonzero result.

If the dependency returns zero, neither the discriminator nor either mask field is subsequently read by this body.

### Discriminator gate

After a nonzero dependency return, the function reads the character-sized field at offset +30.

- If that field is nonzero, the function returns 7.
- If that field is zero, the function evaluates the two mask fields and returns their bitwise AND.

This is a test against zero, not a test against one. Every nonzero discriminator representation follows the constant-7 branch. Character signedness does not change that zero/nonzero distinction.

The discriminator is read after the dependency returns. Its value is not captured before the call. If the dependency changes that location, the later read is the value relevant to this body’s decision, subject to the execution environment’s memory rules.

### Mask result

When the discriminator is zero, the function reads the unsigned fields at offsets +20 and +24 and returns their bitwise intersection.

Each result bit is set exactly when the corresponding bit is set in both operands. The operation is not a logical conjunction, minimum, arithmetic multiplication, or union of bits.

The source-level evaluation does not establish which mask operand is read first. Both are evaluated on the mask-result path, but their relative read order must not be made part of a stronger behavioral guarantee.

There is no retry, second discriminator check, or explicit consistency check around the two mask reads. The function does not establish an atomic snapshot of all three fields.

### Arithmetic boundaries

The field offsets are address displacements. They are not additions to either mask value. The mask combination itself performs no arithmetic addition and has no carry or arithmetic-overflow behavior.
