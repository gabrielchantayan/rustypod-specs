# F-95caa07de452

## Purpose

F-95caa07de452 selects an unsigned 16-bit quantity and an unsigned 8-bit divisor from externally supplied memory, then returns their unsigned quotient and remainder packed into a 64-bit result.

A selector value of 8 uses a distinct data-selection rule: a stored byte is multiplied by a factor derived from a control field before reduction to an 8-bit divisor. Other selector values use a stored byte directly.

A zero effective divisor does not produce an ordinary quotient/remainder pair. It invokes F-dd3f3ec55291 with arguments 2 and 2. A zero status from that dependency permits a return with a zero low word; a nonzero status leads to a software interrupt and, if execution resumes, an infinite loop.

The ordinary nonzero-divisor behavior is supported by static arithmetic analysis. No runtime tests have been performed.

## Interface

### Input

The function accepts one integer selector. The supplied representation uses a signed 32-bit integer model for this input.

The selector is not validated. In particular, the function does not establish that it belongs to a fixed channel range, is nonnegative, or selects readable memory.

### External memory inputs

The following names describe memory roles, not source symbols:

- **Configuration base:** the base address used for byte-sized configuration reads.
- **Control location:** an externally supplied location containing the control field used only when the selector equals 8.
- **Table base:** the base address used for an unsigned 16-bit table read.

These addresses are obtained through external pointer-bearing storage. Their initialization, lifetime, and stability are outside the visible function.

All offsets below are byte offsets.

| Selection case | Table-index byte | Divisor source |
|---|---|---|
| Selector equals 8 | Configuration base − 15 | Configuration base + 2, multiplied by one plus the control field’s low four bits |
| Any other selector | Configuration base + selector − 17 | Configuration base + selector |

The table-index byte is unsigned. The dividend is the unsigned 16-bit value at:

**Table base + 2 × table-index byte − 2**

The effective divisor is the low eight bits of the divisor source, including after multiplication in the special case.

### Output

For a nonzero effective divisor, the function returns an unsigned 64-bit value with this numeric layout:

| Bits | Meaning |
|---|---|
| 63–32 | Unsigned remainder |
| 31–0 | Unsigned quotient |

Equivalently, the returned numeric value is:

**remainder × 2³² + quotient**

This specifies the return value, not the byte order of a memory serialization or the physical registers used by the calling convention.

For a zero effective divisor, the result and termination behavior depend on F-dd3f3ec55291, as specified below.

The selected configuration bytes and selected 16-bit table entry must be readable. The special selector additionally requires the control location to be readable.

Address calculations must be meaningful in the target execution environment. The function provides no checked-pointer or bounds-error behavior.

No ownership transfer is visible. The function does not directly allocate, release, or retain a buffer. Ownership effects of F-dd3f3ec55291 are unknown.

## Behavior

### 1. Select configuration data

The function first distinguishes selector 8 from every other value.

For selector 8:

1. It reads an unsigned byte at configuration base − 15. This byte selects the table entry.
2. It obtains the low four bits of the control field and adds one, yielding a multiplier from 1 through 16.
3. It reads the unsigned byte at configuration base + 2 and multiplies it by that multiplier.

The multiplication is represented with unsigned 32-bit arithmetic. Its mathematical result is between 0 and 4,080, so it does not overflow that width.

For any other selector:

1. It reads the unsigned table-index byte at configuration base + selector − 17.
2. It reads the unsigned divisor byte at configuration base + selector.

There is no special rejection of values outside an apparent intended selector range. Such values still select addresses through this rule, subject to the unresolved address-arithmetic and memory-validity constraints.

### 2. Read the dividend

After obtaining the configuration values, the function reads one unsigned 16-bit quantity from the table.

The table-index byte is effectively one-based:

- Index 1 selects the value at table base.
- Index 2 selects the value at table base + 2.
- Index 255 selects the value at table base + 508.
- Index 0 selects the value at table base − 2.

Index 0 is not rejected or converted to a zero dividend. Its validity depends on whether the preceding two bytes are a valid readable entry in the surrounding memory layout.

The selected quantity is zero-extended for subsequent unsigned arithmetic. Its range is 0 through 65,535.

### 3. Form the effective divisor

The function retains only the low eight bits of the divisor source.

For an ordinary selector, this leaves the already byte-sized value unchanged.

For selector 8, the effective divisor is:

**stored byte × multiplier, reduced modulo 256**

The reduction is wrapping, not saturation. Consequently:

- A product of 255 produces divisor 255.
- A product of 256 produces divisor 0.
- A product of 257 produces divisor 1.

A nonzero stored byte can therefore produce a zero effective divisor.

### 4. Nonzero-divisor result

For a nonzero effective divisor, the returned quotient and remainder satisfy:

- **dividend = quotient × divisor + remainder**
- **0 ≤ remainder < divisor**
- **quotient = floor(dividend / divisor)**

The visible implementation uses magnitude comparisons and conditional subtraction rather than a visible division dependency. It chooses different arithmetic paths according to the dividend’s magnitude relative to the divisor. Those paths converge on the same quotient/remainder contract.

The arithmetic comparisons are unsigned. The source representation contains signed-looking accumulator values in one path, but they serve the quotient-building mechanism; they do not make the operation signed division.

The widths matter:

- Dividend: 16 bits, unsigned.
- Effective divisor: 8 bits, unsigned.
- Intermediate arithmetic and quotient construction: 32-bit words.
- Packed return: 64 bits.

For valid nonzero-divisor inputs, the quotient is at most 65,535 and the remainder is at most 254. Thus the upper unused bits of each returned 32-bit component are zero.

The ordinary result depends only on the values already read. No additional external data read or function call is visible during nonzero-divisor arithmetic.

### 5. Zero-divisor handling

An effective divisor of zero reaches the exceptional path regardless of the dividend, including when the dividend is also zero.

The selected 16-bit table value has already been read before this handling occurs. A zero divisor therefore does not bypass a potentially invalid table access.

The function calls F-dd3f3ec55291 with two integer arguments, both equal to 2. It treats the dependency’s return as containing a low 32-bit status and an upper 32-bit payload.

If the low 32 bits are zero:

- The function returns.
- Bits 31–0 of its return are zero.
- Bits 63–32 are copied from the dependency’s return.

The upper word in this case is not established to be a mathematical remainder.

If the low 32 bits are nonzero:

- The function requests a software interrupt with immediate value 0x123456.
- If execution proceeds past the interrupt, it enters an unconditional infinite loop.
- No normal return is visible on that path.

The dependency’s own failure, non-return, or exception behavior is not specified by the available evidence.

## Side effects

### Direct memory activity

The function directly reads configuration, control, and table data. No direct write to externally visible data memory is present.

The data-read ordering established by the supplied representation is:

1. Read the table-index byte.
2. Obtain the divisor source, including the control-derived multiplier for selector 8.
3. Read the selected unsigned 16-bit table value.
4. Perform arithmetic.
5. Only for a zero effective divisor, invoke F-dd3f3ec55291.

For selector 8, the representation does not establish a reliable relative order between the control-field access and the divisor-byte access inside their multiplication expression.

The table entry is read before zero-divisor handling. The function does not reread it after the dependency call.
