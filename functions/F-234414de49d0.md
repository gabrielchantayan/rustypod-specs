# F-234414de49d0

## Purpose

F-234414de49d0 conditionally obtains a writable record, copies one 32-bit word from a caller-supplied address into that record, and stores the result of a second operation into two record fields. It returns the record address only when that second operation returns a nonzero value.

Three distinct conditions produce a null return: an initial dependency returns zero, a record-producing dependency returns null, or the second operation returns zero. Only the last condition causes the obtained record address to be passed to a cleanup-like dependency.

This is a static behavioral contract. The descriptions “record-producing,” “second operation,” and “cleanup-like” identify observed roles, not established allocation, construction, or ownership semantics.

## Interface

The function does not explicitly validate the input address. A null or otherwise unreadable input address is not rejected by a dedicated branch. However, the input is not directly dereferenced if the initial dependency returns zero or the record-producing dependency returns null.

The accessible extent and other requirements imposed by F-a08c4da10b41 are unknown. Readability of the first four bytes alone is therefore not a sufficient established precondition for the entire successful path.

## Behavior

If that dependency returns zero, the function returns null immediately. On this path, it performs no direct input read, no direct record write, and no call to any of the other three dependencies.

### 2. Record acquisition

If that dependency returns null, the function returns null. It does not call F-a08c4da10b41 or F-66819ba2201a, and it performs no direct input dereference.

A nonnull returned address becomes the record address used for subsequent direct stores, possible cleanup, and the successful return. The function does not independently check its capacity, validity, or relationship to the input address.

### 3. Ordered initialization

After obtaining a nonnull record address, the function performs the following direct memory operations in the order represented by the supplied static evidence:

1. Store a 32-bit zero at record offset 20.
2. Read one 32-bit word from the input address.
3. Store a 32-bit zero at record offset 16.
4. Store the word captured by step 2 at record offset 0.

The input word is therefore captured after the offset-20 store but before the offset-16 and offset-0 stores.

This ordering matters if the input and record storage overlap. The function does not establish disjointness. If the first record store changes the input word, the later input read observes the changed storage, subject to the platform’s memory semantics. Conversely, the offset-16 store cannot retroactively change the already captured word used for the offset-0 store.

There is no direct initialization of the word at offset 4. There is also no direct initialization of offsets 8 or 12 before the next dependency call.

### 4. Secondary operation and result storage

After the offset-0 store, the function calls F-a08c4da10b41 with the original input address.

The returned result is represented as a 32-bit integer. The function:

1. Stores that result at record offset 8.
2. Stores the identical 32-bit result at record offset 12.
3. Selects success or failure according to whether the retained result is nonzero or zero.

These stores occur after F-a08c4da10b41 returns. They therefore overwrite any values that dependency may have placed at those two record locations, provided the record remains writable.

The function does not reread the input word after this call. It also does not restore the earlier values at offsets 0, 16, or 20. If the dependency can reach and modify those locations, its changes are not undone by the function’s remaining direct stores.

### 5. Success and failure completion

If the retained result is nonzero, the function returns the record address without calling F-66819ba2201a. Negative results are accepted just as positive results are.

If the retained result is zero, both result fields are first written with zero. The function then calls F-66819ba2201a with the record address and, if that call returns normally, returns null. It does not use a return value from F-66819ba2201a.

There is no observed retry, fallback, or rollback. In particular, the function does not directly restore the record’s previous contents or undo changes made by dependencies.
