# F-91f805664874

## Purpose

F-91f805664874 prepares linked records, derives signed 16-bit position bounds, and processes paired records over successive positions. It uses three local collection heads, three opaque helper functions, and four context callbacks.

“Pending,” “positive-class,” “negative-class,” “position,” and “endpoint” describe observed roles. Their application-level meanings are inferred, not established.

The function has two normal return outcomes:

- **1:** context +52 is zero at the first check after initial input traversal. Before returning, context +48 is written with decimal 20.
- **0:** that check finds a nonzero value and execution subsequently reaches the normal exit.

These values are not established error or success codes. An initially zero count does not alone determine the return path: opaque helpers execute before the deciding check.

### Preconditions and ownership

A positive-list pairing traversal requires a corresponding valid negative-list cursor for every visited positive record. Extra negative records do not independently produce pair callbacks.

Traversals require terminating links if they are to finish. Helpers and callbacks must leave subsequent accesses valid, including accesses through saved links. Passing a pointer does not establish ownership transfer, retention rights, allocation, or release.

## Behavior

### Numeric rules

Unless explicitly narrowed, arithmetic and stored words are 32 bits. Sums, differences, negation, and table-address calculations use their resulting 32-bit bit patterns.

A signed 16-bit reduction retains the low 16 bits and interprets them as −32768 through 32767. Position increments and several differences use this reduction. Incrementing position 32767 therefore produces −32768.

Initial bounds are obtained by signed right shifts of the 32-bit values at context +80 and +84. The supplied shift count is the low byte of context +0. Results for counts of 32 or more are **documented_only**: the supplied representation does not establish a portable result.

No positive-value or power-of-two restriction is checked for context +4.

### Initial bounds and input traversal

The three local collection heads start null.

The function derives the initial upper bound from context +80 and the initial lower bound from context +84. Subsequent bound comparisons use their signed low 16 bits. Their stored full-width values need not initially be sign extensions of those low bits.

Starting at context +96, each input record is handled in this order:

1. Read the signed low 16 bits of record +20.
2. Read and save record +4 as the next input pointer.
3. Replace the lower bound when that starting position is smaller than the current signed low-16-bit lower bound.
4. Calculate an inclusive end from the 32-bit sum of record +20 and record +16, minus one, reduced to signed 16 bits.
5. Replace the upper bound when that end exceeds its current signed low-16-bit value.
6. Write zero to record +0.
7. Call F-795a1ebd3a79 with only the pending-head address explicitly supplied.
8. Continue through the saved next pointer.

The initial helper call must not be treated as an established two-argument insertion. Its record-selection mechanism is unknown.

The function does not directly replace or clear context +96. Helpers may nevertheless change shared state.

### First count check

Only after initial traversal finishes does the function check context +52.

If the checked word is zero, it writes 20 to context +48 and returns 1. No preparation, pair, or completion callback is directly invoked on this branch. Helper-internal calls are unknown.

An initial count of zero is insufficient to guarantee this outcome because initial helper calls precede the check. Conversely, an initially nonzero count can reach this outcome if dependency effects leave the checked word zero.

### Preparation and pending offsets

For a nonzero checked count, the preparation callback receives the context and the lower-bound temporary’s address. Its writes to that temporary affect subsequent behavior.

The pending collection is then traversed. Each record +24 receives the low 16 bits of:

the record’s +20 word minus the low 16 bits of the current lower-bound temporary.

The stored result is zero-extended to 32 bits, ranging from 0 through 65535. Each next link is read after the corresponding offset write.

After normalization, the current position becomes the signed low 16 bits of the lower-bound temporary. The initial pending-subtraction amount is zero.

### Count gate and initial equality shortcut

The count is reread after preparation and normalization. Ordinary processing begins only if it is signed-positive.

For this first entry only, the function reads a full 32-bit table word at:

the context +36 address minus four times the count, with 32-bit address arithmetic.

If that full-width word equals the sign-extended current position, the count is decremented and control moves directly to the outer continuation check. This shortcut performs no pending activation, active update, interval processing, cleanup, or completion callback.

The initial full-width comparison is not repeated for later iterations. Later boundary reads use only the table word’s signed low 16 bits.

A signed-negative count skips ordinary processing but does not undo preparation or pending normalization.

### Pending activation and boundary selection

Each ordinary pass traverses the pending collection. For each record:

1. Save its next link.
2. Subtract the pass’s subtraction amount from record +24 and store the full 32-bit result.
3. If the result is nonzero, continue through the saved link.
4. If zero, call F-de4cd2e0ed1f with the pending-head address and record pointer.
5. Read record +12 after that call.
6. For −1, call F-795a1ebd3a79 with the negative-head address and record pointer.
7. For +1, call it with the positive-head address and record pointer.
8. For any other classification, make no active-insertion call.

The subtraction does not explicitly narrow the stored offset to 16 bits. A record with an unsupported classification may have received a removal-like call without an insertion-like call; its subsequent reachability is unknown.

The function then calls F-a0cc82434842 on the positive-head address, followed by the negative-head address.

After both calls, it rereads context +52, writes that value minus one back, and reads the table entry selected by the pre-decrement value. The table origin is read after the count write. The boundary is the signed low 16 bits of the loaded word.

The next pass’s subtraction amount is the signed-16-bit reduction of boundary minus current position. There is no fresh positivity check between the active-update helpers and this count decrement/table access.

### Pair processing within an interval

Positions are processed while the current signed position is strictly less than the selected signed boundary.

At each position, traversal begins at the current positive and negative heads. Positive records drive traversal; the negative cursor advances once per positive record.

For each pair, the function reads positive-record +0, then negative-record +0, and orders those values by signed 32-bit comparison. Let the ordered values be the lower and upper endpoints.

The immediate callback is selected when the signed context +4 parameter is less than the signed interpretation of the wrapped 32-bit difference between upper and lower.

Otherwise, two masks are calculated:

- Lower endpoint AND the 32-bit negation of the parameter.
- The wrapped sum of parameter plus upper endpoint minus one, AND that same negation.

The immediate callback is also selected if either:

- The low byte at context +184 is zero; or
- The first mask is signed-less-than-or-equal to the second, and parameter plus the first mask does not equal the second as a 32-bit value.

All remaining cases are deferred. In order, the function:

1. Writes the ordered lower endpoint to positive-record +0.
2. Writes the ordered upper endpoint to negative-record +0.
3. Writes 1 to positive-record +24.
4. Increments a signed-16-bit deferred counter.

These are bitwise classification rules, not a validated alignment operation.

Immediate processing does not directly clear an existing +24 marker. Pair links are read after the pair’s processing, so callback changes to those links can affect traversal.

### Deferred callbacks and position completion

After the first pair traversal, the function reloads both active heads. A second paired traversal occurs only if the final deferred counter is signed-positive.

For every visited positive record with a nonzero +24 word:

1. Clear that word.
2. Invoke the deferred callback with the records’ then-current +0 values.

This traversal selects every nonzero marker it encounters, not exclusively markers created during the immediately preceding traversal. Its endpoint arguments are not freshly sorted.

The counter wraps at 16 bits. For example, 32768 deferred classifications leave it negative, suppressing the second traversal despite recorded markers.

The position-completion callback follows pair processing even when no positive records were present. The position is then incremented with signed-16-bit wrap. If another position remains strictly below the boundary, F-a0cc82434842 is called on the positive head and then the negative head before the next position.

### Post-interval cleanup

Cleanup traverses the positive collection first, then the negative collection.

Every evaluation of the positive cleanup loop’s condition assigns the current negative head to the secondary cursor. This includes the final condition evaluation that ends positive traversal.

For each positive record visited, the function identifies its +16 word, saves its next pointer by advancing the positive cursor, and then tests the identified word. If it is zero, F-de4cd2e0ed1f is called with only the positive-head address explicitly supplied.

When positive traversal ends, the secondary cursor therefore holds the then-current negative head—not an interior address from the last positive record.

Negative cleanup starts there. For each visited negative record, it identifies record +16, advances through the saved record +4 link, tests the identified word, and calls F-de4cd2e0ed1f with only the negative-head address if the word is zero.

Both traversals continue through links saved before the corresponding helper call. The helper’s actual removal target, effects, and ownership behavior remain unknown.

After cleanup, the outer loop continues only if the then-current context count is signed-positive.

### Final completion phase

After ordinary processing ends or is skipped, the function invokes the position-completion callback while the current signed position is less than or equal to the signed low 16 bits of the upper bound. Each call is followed by a signed-16-bit position increment.

This phase performs no direct pair callbacks or active-update helper calls. Position is not an explicit completion-callback argument.

If reached with upper bound 32767, the inclusive condition cannot become false through these wrapped increments alone. Normal termination is therefore not guaranteed.

## Side effects

Direct writes include:

- Initial clearing of input-record +0.
- Context +48 becoming 20 on the zero-count branch.
- Pending-offset and deferred-marker writes at record +24.
- Ordered endpoint writes for deferred pairs.
- Context +52 decrements.
- Marker clearing before deferred callbacks.

Helpers receive writable addresses of local collection heads. The preparation callback receives a writable local-bound address. No explicit allocation or deallocation appears in this function.

There is no direct bounds checking, pair-null validation, rollback, callback-error handling, or recovery path. Helper and callback return values do not determine the return value.

No dependency is assumed to preserve context fields, records, links, globals, or memory ownership. Callback addresses and relevant context fields are read when their paths execute rather than frozen for the entire operation.

## Acceptance examples

All examples require valid memory and dependency behavior sufficient to reach the stated observations.

1. **Zero at the deciding check.** If initial traversal finishes and context +52 is zero at the first post-traversal check, each visited input record has already received its +0 clearing and initial helper call. The function then writes 20 to context +48 and returns 1. An initially zero count alone is not sufficient.

2. **Inclusive record end.** Starting word 10 and record +16 value 3 produce candidate upper bound 12. It replaces the bound only if greater than the bound’s current signed low 16 bits.

3. **Pending-offset representation.** If preparation leaves the lower-bound temporary at 7, starting word 10 produces stored offset 3. Starting word 6 produces 65535, not a full-width representation of −1.

4. **Activation classification.** When subtraction yields zero and classification remains −1 after the pending helper call, the negative insertion-like call follows. Classification 2 produces no active insertion-like call.

5. **Deferred pair.** With parameter 8, endpoints 0 and 8, and nonzero enable byte, the span comparison does not select immediate processing. The masks are 0 and 8; their difference is exactly one parameter unit. The pair is deferred. If the final counter is positive and the marker survives until visited, it is cleared before the deferred callback.

6. **Disabled deferral.** The same endpoints and parameter select immediate processing when the enable byte is zero.

7. **Full-width initial comparison.** With current position 1, an initial table word of 65537 does not trigger the equality shortcut, although its signed low 16 bits are 1 when used as an ordinary boundary.

8. **Cleanup starts at the negative head.** With one positive record and two negative records, stable links, and no helper mutations, cleanup tests the positive record’s +16 word followed by each negative record’s +16 word. The second traversal does not begin inside the positive record.

9. **Final completion only.** If the post-normalization count is signed-negative, current position is 3, and upper bound is 5, three completion callbacks occur without direct pair callbacks.

## Uncertainties

The following remain **documented_only**:

- Initial pending construction from the helper’s single explicit argument.
- Helper internals, hidden state, ordering, allocation, release, and ownership.
- Removal-helper behavior when only a collection-head address is supplied.
- Callback side effects and pointer-retention behavior.
- Shift results for low-byte counts of 32 or more.
- Intended units and admissible values of the pair-classification parameter.
- External meanings of return values 0 and 1 and stored status 20.

Termination additionally depends on linked structures, dependency mutations, count evolution, and signed-16-bit position wrap. There is no established interior-record cleanup traversal.
