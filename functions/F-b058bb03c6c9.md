# F-b058bb03c6c9

## Purpose

F-b058bb03c6c9 conditionally processes a record designated by a caller-supplied slot. It derives a decremented 32-bit value from a record field, stores that value through a separately evaluated slot value, and selects further processing according to whether the saved arithmetic result is zero.

An initially zero slot causes an immediate normal return without dependency calls or direct writes. Every normal-return path taken after an initially nonzero slot observation explicitly clears the slot. The returned value is always the address of the caller’s slot, not a record address or counter value.

Reference counting and lifecycle cleanup are plausible intent, not established ownership semantics. The supplied body does not establish memory release, destruction, locking, or ownership transfer.

## Interface

### Input and result

The sole explicit input is the address of a slot containing a 32-bit value. A zero value selects the empty path. A nonzero value is subsequently used as an address-bearing value for record accesses.

The supplied representation uses 32-bit integer fields and address-bearing values. It does not establish a portable interface for wider pointers.

On normal return, the result is the original slot address. There is no separate success indicator, error code, counter result, or returned record.

The function performs no explicit input validation. The slot must be readable even for the empty path. Later access requirements depend on the path reached and on the slot values observed at each separate evaluation.

### Accessed layouts

The record layout is established only for the fields actually accessed:

| Byte offset | Width | Use |
|---|---:|---|
| 0 | 32 bits | Optional address initiating indirect callback resolution |
| 4 | 32 bits | Source or destination of the counter-like update |
| 8 | 32 bits | Terminal-path selector and, conditionally, terminal-call argument |

The record supplying the offset-4 source need not be the record receiving the offset-4 write: the caller’s slot is evaluated separately for those accesses.

For callback resolution, a nonzero record field at offset 0 designates an intermediate structure. Its first 32-bit field supplies another address. The 32-bit field at offset 4 from that second address supplies the indirect callable target.

These accesses do not establish complete structure sizes, allocation boundaries, alignment requirements, or semantic types.

### Access preconditions

Successful execution requires valid storage and callable targets for every operation actually reached:

- The slot must remain readable for its successive evaluations.
- After the initial dependency returns, the slot value used for the counter read must designate readable 32-bit storage at offset 4.
- The separately evaluated slot value used for the counter write must designate writable 32-bit storage at offset 4. It is not established to equal the read-side address.
- On the zero-result branch, the slot value used for the callback-presence check must designate a record with a readable offset-0 field.
- If that check selects the callback, the separately resolved address chain must be readable, and its final target must be callable under the applicable convention.
- A retained nonzero address used for terminal processing must support the offset-8 reads reached on that path.
- Normal completion after an initially nonzero observation requires the slot to be writable for the final zero store.

These are requirements imposed by the accesses, not checks implemented by this function. A nonzero value alone does not establish address validity. No guarantee is supplied that callees preserve any required storage.

## Behavior

### Empty entry

The first operation relevant to branch selection is a 32-bit read of the caller’s slot.

If that observation is zero, the function returns the slot address. It makes no dependency call, accesses no record field, and performs no explicit store. In particular, it does not perform the final slot-clearing store used by the nonempty path.

### Entry into processing

An initially nonzero observation causes a call to F-b086f9ee5ad4. No explicit arguments are shown.

The initial record address is not retained as the basis for the subsequent counter access. After F-b086f9ee5ad4 returns, the function evaluates the slot again. If the dependency has changed the slot, this later value controls the counter read.

There is no repeated nonzero check before that access. Changing the slot to zero therefore does not select the empty path; it instead leaves zero as the address-bearing base for the reached offset-4 read.

### Counter source, destination, and branch value

The counter update has a material distinction between its source and destination. The established order is:

- Evaluate the slot to obtain the address used for the offset-4 read.
- Read the 32-bit counter-like field at that address.
- Subtract one, retaining the arithmetic result.
- Evaluate the slot again to obtain the address used for the offset-4 write.
- Store the saved result at that destination.
- Test the saved arithmetic result for equality with zero.

Thus, the operation is not established as a read-modify-write of one retained record address. If the two slot evaluations produce different addresses, the value read from one record is decremented and written into another record. The body itself contains no dependency call between these two evaluations, but that does not convert them into a single address snapshot or establish supported concurrent mutation.

The branch uses the saved arithmetic result. It does not reread either record’s counter after the store. Consequently, a later field change does not itself change this branch decision.

The accesses are ordinary reads and writes in the supplied representation. No atomic decrement, synchronization guarantee, or lower-bound check is established.

For signed 32-bit values whose subtraction by one is representable, the arithmetic is unambiguous. In particular, an observed counter of zero produces −1 and selects the nonzero-result branch. The minimum signed 32-bit input raises an overflow uncertainty described below.

### Nonzero arithmetic result

When the saved result is nonzero, F-66e1118d7fc7 is called with no explicit argument shown.

If this call returns normally, the function writes a 32-bit zero to the caller’s slot and returns the slot address. There is no callback-chain access or offset-8 read on this branch.

The final clear is not conditional on the slot still naming either the counter source or the counter destination. Any value left in the slot by the dependency is overwritten.

### Zero arithmetic result: callback selection

When the saved result is zero, the function evaluates the slot again and reads the designated record’s offset-0 field.

A zero field skips the indirect callback. A nonzero field selects callback resolution.

Resolution evaluates the slot again and follows the address chain: the record’s offset-0 field yields an intermediate address, its first field yields a second address, and the field at offset 4 from that second address yields the callback target. The target is invoked without explicit arguments shown, and its return value is not visibly consumed.

The callback-presence check and target resolution are separate accesses. The checked record or intermediate address is not established as a retained snapshot for resolution. If relevant values change, the resolved chain may differ from the checked chain.

Only the first record field receives an explicit null check. The body does not validate the remaining address-bearing fields or the target. The lack of explicit arguments does not establish the absence of implicit ABI inputs.

### Zero arithmetic result: dependency and terminal processing

After the callback returns, or immediately after it is skipped, F-66e1118d7fc7 is called with one explicit argument: the current 32-bit slot value.

That value is not necessarily the counter-read address, the counter-write address, or the address used for callback selection. The callback may have changed the slot.

After F-66e1118d7fc7 returns, the function reads the slot again and retains that value for terminal selection.

If the retained value is zero, no offset-8 access is made. The function reaches normal completion, explicitly writes zero to the slot, and returns its address.

If the retained value is nonzero, the function reads the 32-bit field at offset 8 from that retained address:

- A zero field selects F-feee9156a257 with the retained record address as its argument.
- A nonzero field selects a call to F-a600efb7b035 with no explicit arguments. If that call returns, the offset-8 field is read again from the same retained record address, and the newly read 32-bit value is passed to F-feee9156a257.

Both calls to F-feee9156a257 are marked as not returning in the supplied source. Under those annotations, neither reaches the final slot clear.

The two offset-8 reads on the second path have different purposes. The first chooses the path; the second supplies the argument. F-a600efb7b035 may change the field between them. There is no second zero test, so the eventual argument may be zero.

The address used for that second field read is retained across F-a600efb7b035. The caller’s slot is not reevaluated to choose a replacement record for this read.

## Side effects

Two kinds of direct write are established:

1. On a reached counter update, one 32-bit store of the saved subtraction result to offset 4 of the address obtained from the write-side slot evaluation.
2. On normal completion after an initially nonzero observation, one 32-bit zero store to the caller’s slot.

The first write is not guaranteed to target the record from which the counter was read. Describing it as an unconditional write-back to the source record would impose an unsupported slot-stability assumption.

The initially empty path performs neither write. A terminal path can perform the counter store without ever clearing the slot.

All called dependencies and the indirect callback may have additional effects not constrained by this body. They must not be assumed to preserve globals, slot contents, record fields, or allocation validity.

No explicit allocation, identified deallocation primitive, error-reporting operation, exception handler, or rollback appears. If execution fails or terminates after the counter store, the function provides no visible restoration of the source or destination field and no guaranteed slot clear.

No non-aliasing rule is established. If the slot overlaps a record field or callback-chain storage, the ordered writes may affect later reads. Such aliasing does not remove the requirement that each reached access be valid.

## Acceptance examples

With a readable slot containing zero, the result is its address. There are no dependency calls, record accesses, or explicit writes.

- F-66e1118d7fc7 is invoked without an explicit argument.

- The saved arithmetic result is 1.
- The second record’s offset-4 field receives 1, regardless of its previous value.
- The counter update does not directly write the first record’s field.
- The nonzero-result branch is selected from the saved value 1.

### Zero input counter

With a stable record whose counter is zero, the update stores −1. The nonzero-result branch is selected. If F-66e1118d7fc7 returns, the slot is cleared and its address returned.

There is no explicit rejection of an already-zero counter.

### Saved zero result controls the branch

Conditionally, if the source record supplies counter 1 while the write-side evaluation designates a different valid record whose previous counter is 9, the destination receives zero. The zero-result branch is selected because the saved subtraction result is zero, not because the destination’s old value was decremented.

Callback selection then uses another slot evaluation, not a retained counter-source or counter-destination address.

### Callback changes the slot

F-66e1118d7fc7 receives that replacement value. Terminal selection uses the slot value observed after this dependency returns. Neither stage is guaranteed to use either counter-update address.

### Dependency clears the slot

On the zero-result branch, suppose F-66e1118d7fc7 returns with the slot equal to zero.

No offset-8 read follows. Neither terminal dependency is invoked. The function still performs the common zero store and returns the slot address.
