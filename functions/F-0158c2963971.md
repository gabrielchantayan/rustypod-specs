# F-0158c2963971

## Purpose

F-0158c2963971 performs an ordered sequence of indirect calls interleaved with memory updates. It uses one explicit 32-bit input and several additional pieces of incoming machine context. It does not expose a conventional return value.

The established behavior includes:

- An initial 32-bit store to an input-derived address.
- A 32-bit load whose value is retained for two later byte stores.
- Twenty-two indirect calls before the final clearing operations.
- Two byte stores through byte-valued address selectors.
- A result assignment to a named state destination.
- A byte clear and a 16-bit clear.
- A final attempted call through address zero with three zero arguments.

No application-level purpose is established. In particular, the visible operations do not establish that this function initializes an object, decodes a format, performs a system call, or releases resources.

This contract describes the supplied static representation. Completion is conditional on every preceding access and call completing normally. It does not establish that the final call is executable in any particular environment.

## Behavior

### 1. Initial store and retained word

The first visible operation stores the 32-bit initial store value at the address obtained by multiplying index by four and adding 20.

Only after that store does the function load a 32-bit word from word-source base plus 20. Call this retained value **source word**.

This ordering matters if the two locations overlap. For example, if they identify the same valid 32-bit location, the load observes the newly stored value, absent an external intervening modification.

The initial store does not use word-source base as an implicit destination base. Its destination is derived directly from index.

### 2. Initial five-call sequence

The function next invokes five dependencies in sequence:

1. **F-D01**, passing the four-times-scaled index as its sole explicit argument.
2. **F-D02**, with no explicit arguments shown.
3. **F-D03**, with no explicit arguments shown.
4. **F-D04**, with no explicit arguments shown.
5. **F-D05**, with no explicit arguments shown and a represented 64-bit result.

The target of F-D01 is derived from the incoming link value plus hexadecimal offset 0xFFE. The other targets in this group are derived from fixed image-relative anchors and an offset.

Split the result from F-D05 into:

- **Lower result**: bits 0–31.
- **Upper result**: bits 32–63.

These are bit slices. No byte-order assumption is needed to describe that split.

### 3. First byte-selected store

After F-D05 returns, the function:

1. Loads an unsigned byte from first-selector base plus 1.
2. Adds decimal 17 to that byte value.
3. Stores the low eight bits of source word at the resulting address.

The byte is used directly as a small address selector. It is not an index into a separately visible destination array.

Consequently, the destination is in the inclusive address range 17–272. This is a low-address write, not a write relative to first-selector base.

The selector load occurs after all five preceding calls. If those calls modify the selector location, the later value is relevant. Source word, however, comes from the earlier retained 32-bit load; it is not reloaded here.

### 4. Four-argument call and result forwarding

The function calls **F-D06** with four explicit arguments, in this order:

1. Upper result.
2. Upper result.
3. Upper result.
4. Lower result shifted left by two bits.

The first three arguments are identical 32-bit bit patterns. The fourth is a 32-bit shift result; bits shifted beyond bit 31 do not belong to the retained 32-bit result.

It then performs:

1. **F-D07**, producing a represented 32-bit result.
2. **F-D08**, receiving that result as its sole explicit argument.
3. **F-D09**, with no explicit arguments shown.
4. **F-D10**, with no explicit arguments shown.
5. **F-D11**, with no explicit arguments shown.
6. **F-D12**, producing a represented signed 32-bit result.

Returns from F-D06 and F-D08 through F-D11 are not explicitly consumed by the visible data flow.

### 5. Second byte-selected store

After F-D12 returns, the function performs another selector load and byte store.

The selector’s address is one plus the nine-bit field extracted from bits 21–29 of lower result. Bits 30 and 31 are excluded before extraction.

Thus:

- The selector load address is in the inclusive range 1–512.
- The loaded selector is an unsigned byte.
- The destination address is that byte plus 17, again in the inclusive range 17–272.
- The stored value is the low eight bits of source word shifted right by 22: equivalently, bits 22–29 of source word.

This operation does not use first-selector base. Its selector address comes from lower result and a constant offset.

The selector is read before the corresponding destination byte is written. If the selector address and destination address coincide, the previously read selector determines the write.

### 6. Shifted-result calls

The function next calls **F-D13** with the result from F-D12 shifted left by two bits.

It then invokes:

1. **F-D14**, with no explicit arguments shown.
2. **F-D15**, with no explicit arguments shown.
3. **F-D16**, with no explicit arguments shown.
4. **F-D17**, producing another represented signed 32-bit result.
5. **F-D18**, receiving two explicit arguments, both equal to that latest result shifted left by two bits.

The two F-D18 arguments are equal; they are not separately obtained values.

For F-D13 and F-D18, the source representation types the unshifted results as signed 32-bit integers. Behavior for negative operands or operands whose mathematical multiplication by four exceeds the signed range cannot be settled from portable language rules. A machine-level wrapping interpretation may apply, but is not established independently by the supplied material.

### 7. Final pre-clear call sequence

The remaining pre-clear calls occur in this order:

1. **F-D19**, with no explicit arguments shown.
2. **F-D20**, producing a represented 32-bit result.
3. **F-D21**, receiving that result as its sole explicit argument.
4. **F-D22**, with no explicit arguments shown.

The ordinary result of F-D22 is assigned to a named state destination before either final clear.

An additional byte-pointer result is visible following this call sequence. The representation uses it for the next store. It does not establish whether this pointer is a formal secondary return value, an incidental register result, or a value with another ABI-specific meaning.

The name attached to the state destination is not sufficient evidence that an architectural supervisor operation occurs.

### 8. Final clears and terminal call

If execution reaches this point:

1. One zero byte is written through the additional byte pointer.
2. A zero 16-bit value is written at the address obtained by extracting bits 7–29 of lower result.
3. **F-D23** is invoked through address zero with three explicit zero arguments.

The 16-bit clear address ranges from 0 through hexadecimal 0x007FFFFF. It is not multiplied by two and need not be naturally aligned. The store affects that byte address and the following byte if the environment permits it.

The function has no further explicit operation after the terminal call. A normal return is possible in the represented control flow only if that call itself returns normally.

## Acceptance examples

These are conditional acceptance examples, not executed tests. Each assumes valid accesses and normally returning dependencies up to the observation being described.

1. **Initial store/load aliasing.**  
   If index is 100, the initial destination is address 420. If word-source base is 400, the following 32-bit load reads the same address. If the initial store value is hexadecimal 0xA1B2C3D4, source word becomes that value absent an external intervening write.

2. **First selector controls an absolute low destination.**  
   If the byte read from first-selector base plus 1 is 5 and source word is hexadecimal 0x123456AB, the first byte store writes 0xAB to address 22. It does not write to first-selector base plus 22.

3. **64-bit result halves have different roles.**  
   If F-D05 produces upper result 0x11223344 and lower result 0xC0200080, F-D06 receives three copies of 0x11223344 followed by 0x00800200 under the represented 32-bit shift interpretation.

4. **High bits are excluded from selector extraction.**  
   For lower result 0xC0200080, the second selector load is from address 2. Bits 30 and 31 do not contribute. If that selector byte is 7, the second destination is address 24.

5. **Second stored byte comes from a distinct source-word field.**  
   If source word is 0x2AC00000, the second byte store writes 0xAB. This is neither the low byte nor the highest byte of source word.

6. **Final clear uses a separate extraction.**  
   For lower result 0xC0200080, the final 16-bit clear starts at address 0x4001. An environment requiring aligned 16-bit accesses may fault there; alignment is not corrected.

7. **Later write wins when byte destinations coincide.**  
   If both selector reads yield 5, both byte stores target address 22. With source word 0x2AC00011, the first writes 0x11 and the second writes 0xAB, assuming no intervening modification changes the observation.

8. **Terminal-call failure does not imply rollback.**  
   If all preceding operations succeed but address zero is not callable, the terminal call cannot complete normally. The two final clears have already occurred.
