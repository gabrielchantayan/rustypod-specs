# F-038c180e906a

## Purpose

F-038c180e906a prepares a selector-dependent operation using a context, an encoded selector, a 32-bit address value, and a requested length. It updates continuation bookkeeping, reads and writes register-like locations, conditionally invokes dependencies, and returns a packed 64-bit result.

A transfer-oriented interpretation is inferred from the address and length programming. The established contract is the access sequence, arithmetic, branching, and result construction below. Device acceptance, completion, and register meanings are not established.

A zero low result word indicates normal return from this routine, not successful completion of an external operation.

## Interface

### Inputs and widths

| Input | Representation | Use |
|---|---|---|
| Context | 32-bit address | Provides a length limit, a secondary-state address, and continuation fields. |
| Selector | Pointer-shaped, treated as a 32-bit encoded value | Bits 0–6 select an index; bit 7 selects a bank. Full-value comparisons also affect behavior. |
| Address value | Unsigned 32-bit word | Used in continuation bookkeeping and address programming. |
| Requested length | Unsigned 32-bit word | Compared with the limit and potentially clipped. |

The selector is not dereferenced as a caller-provided buffer. Its full value matters: `0`, `0x80`, and `0x100` take different paths despite sharing some extracted fields.

Unsigned 32-bit additions and subtractions wrap modulo \(2^{32}\). The count calculation also contains signed intermediates; its language-level overflow and shift limitations are documented under Uncertainties.

## Behavior

### 1. Apply the length limit

The first visible memory access reads the context limit. The requested length and limit are compared as unsigned 32-bit values.

If the request is below the limit:

- A nonzero request clears offset `0x98`, then offset `0x9C`.
- A zero request leaves both fields untouched.
- Effective length remains the request.

If the request is at least the limit:

1. Write request minus limit to offset `0x98`.
2. Write limit plus the original address value to offset `0x9C`.
3. Use the limit as effective length.

Both arithmetic results are unsigned 32-bit words. Equality therefore writes zero remaining length and still writes a continuation address. A zero limit takes this branch for every request, including zero.

These writes precede later rejection and are not rolled back.

### 2. Capture state and read initial control

Next, read the secondary-state address from context offset `0x34`.

Extract the index from selector bits 0–6 and choose the control bank using bit 7. Read that indexed control word once. Subsequent calculations and control writes use this saved word rather than refreshing it after dependencies or intervening writes.

### 3. Handle index zero

For index zero, reject an effective length greater than 64. Return low word `0xFFFFFFFF` and high word equal to the original selector.

At rejection, continuation processing, the secondary-state address read, and the initial control read have already occurred. No dependency call or later register programming described here occurs.

For effective length at most 64, distinguish the full selector value.

**Selector exactly zero:**

- If effective length is nonzero, write it to secondary-state offset `0xA0`, then write the original, unmasked address to offset `0xA4`.
- If effective length is zero, write neither field.
- Write the saved control word OR `0x04000000` to Control-clear[0].
- Read Shared control.
- Write that observed value back to Shared control.
- Return zero in both words.

This shortcut does not read either address-offset reference and does not perform general transfer or address programming.

**Selector nonzero:**

- Call F-8f180221fee0 with no explicit arguments visible.
- Store its 32-bit result at offset `0x80` of the previously captured secondary-state address.
- Continue to general programming with calculation parameter 64.

This includes selectors such as `0x80` and `0x100`, but only after the effective-length check succeeds.

### 4. Program transfer and address registers

Nonzero indices reach this stage directly. Their calculation parameter is the saved control word AND `0x7FF`, including the possibility of zero.

Calculate a count:

- Effective length zero: use count 1 without calling the arithmetic dependency.
- Effective length nonzero: call F-d7be9cfb4000 with effective length minus 1 and the calculation parameter, then add 1 to its primary result.

The transfer-word expression ORs effective length, count shifted left by 19, and `0x20000000`. It contains no explicit length-field mask or count-field mask. Subject to the signed-intermediate uncertainty, overlapping bits are combined rather than checked or rejected.

Write this word to the selected transfer register.

Then perform the address-reference accesses in this exact order:

1. Unconditionally read the set-address reference.
2. If selector bit 7 is clear, read the clear-address reference and use this second value instead.
3. Use the selected reference value to form the indexed address-register destination.
4. Write the original address AND `0x7FFFFFFF` to that destination.

Thus the bit-7-clear path still reads the set-address reference, even though it discards the value. Neither read may be omitted from the behavioral description because its numeric contents are unknown. The accesses occur after the transfer-register write and before the address-register write.

General address programming clears address bit 31. The all-zero-selector shortcut instead stores the unmasked address in secondary state.

### 5. Perform bit-7-set bookkeeping

Only selectors with bit 7 set perform this stage.

After address programming, call F-d7be9cfb4000 with effective length and the calculation parameter. This call occurs even when effective length is zero.

Use the dependency’s secondary 32-bit result, not its primary result:

- Add 3 with unsigned 32-bit wrapping.
- Clear the low two bits.
- Write the result to secondary-state offset `0x38 + 4 × index`.

If the calculated word is zero and effective length is nonzero, overwrite that same field with the calculation parameter. This decision uses the calculated word; no intervening read of the stored field is shown. A zero effective length suppresses the overwrite.

Next, read the global-object reference and then read one byte at offset `0x04` from the address obtained.

#### Special control path

Take this path only if that byte is zero and the saved control word AND `0x03CC0000` equals `0x000C0000`.

In order:

1. Read the global-object reference again.
2. At offset `0x18` from this newly obtained address, store the original selector as a 32-bit word.
3. Write `0x39` to the Auxiliary register.
4. Write the saved control word OR `0x04000000` to Control-set[index].
5. Read Shared control.
6. Write that observed value back to Shared control.
7. Return low word zero and high word equal to the address of Control-set[index].

The second reference read is distinct from the reference read used for the byte check. The selector store is not guaranteed to target the same object whose byte was tested.

This path bypasses the optional dependency call and final selector handling.

#### Optional dependency call

If the special path is not taken and saved control bits 18–19 are both set, call F-9c06a5856a0f with:

- First argument: saved control bits 22–25, yielding 0 through 15.
- Second argument: zero.

Its returned value is not used.

### 6. Perform final control handling

This stage follows general programming unless the special path returned.

**Selector not exactly `0x80`:**

1. Write the saved control word OR `0x84000000` to the selected control register.
2. Read Shared control.
3. Write that observed value back.
4. Return low word zero and high word equal to the original selector AND `0x80`.

The control write does not incorporate changes made to that register after its initial read.

**Selector exactly `0x80`:**

1. Read Transfer-clear[0] and extract bits 29–30, producing a value from 0 through 3.
2. Read Shared control.

If the extracted value is not 3, write the observed Shared control value back unchanged and return the extracted value as the high word.

If the extracted value is 3:

3. Read Transfer-clear[0] again and repeat the extraction.
4. Read Shared control again and form that value OR `0x84000000`.
5. If the second extraction is 3, write this formed word and return high word 3.
6. Otherwise, read Shared control a third time, form this latest value OR `0x8C000000`, write it, and return the entire formed word as the high word.

The low word is zero throughout. Even when the second extraction is not 3, the second Shared control read still occurs before the third read replaces its contribution.

## Side effects

Visible effects include continuation updates, secondary-state writes, reference reads, global-object reads and writes, register accesses, and dependency calls.

Ordering matters:

- Continuation writes precede possible rejection.
- The initial control read precedes every dependency call.
- Transfer programming precedes both address-offset reference reads and address programming.
- Bit-7-set bookkeeping follows address programming.
- The special path reloads the global-object reference before its selector store.
- Every normal return includes a Shared control write, including read-and-write-back cases.
- Rejection does not perform that final Shared control write.

A discarded reference value still requires its read. A write of a just-read register value remains an observable write.

No direct allocation, release, payload-buffer copy, or ownership transfer is visible. Dependencies may have additional effects; they are not assumed to preserve globals, reference contents, or pointed-to memory, nor to retain or release resources in any particular way.

Captured values remain captured across dependencies. Conversely, later reference reads observe their contents at those later access points, subject to unresolved environmental ordering and concurrency rules.

## Acceptance examples

These are conditional static cases, not executed tests. They assume valid reached accesses, normal dependency returns where applicable, and no unmentioned interfering mutations.

1. **Zero request below a positive limit.** With limit 100, request zero, and selector zero, continuation fields and secondary-state offsets `0xA0` and `0xA4` are not written. Control-clear[0] and Shared control are still written.

2. **Clipping permits index-zero processing.** With limit 32, request 100, selector zero, and address `0xFFFFFFF0`, continuation fields receive 68 and `0x00000010`. Effective length is 32, and secondary state receives length 32 and the unmasked address.

3. **Rejection follows bookkeeping.** With limit 100, request 65, and any index-zero selector, both continuation fields are cleared before the initial control read and rejection. The result has low word `0xFFFFFFFF` and high word equal to that selector.

4. **Equality is not the below-limit case.** With limit and request both 64, remaining length becomes zero and continuation address becomes address plus 64 modulo \(2^{32}\).

5. **Clear-bank address references are both read.** On a reached general path with bit 7 clear, the transfer write is followed by a set-address reference read, then a clear-address reference read, then an address write using the latter value. The first reference read remains required even if the two values happen to match.

6. **Secondary-result alignment can wrap.** A secondary helper result of 5 produces 8. A result of `0xFFFFFFFF` produces zero after wrapping addition and masking. For nonzero effective length, that zero is then overwritten with the calculation parameter.

7. **Conditional count packing.** For a nonzero index, effective length 65, and primary helper result 1, the incremented count is 2 and the transfer word is `0x20100041`. This does not assert which helper inputs produce that result.

8. **Upper selector bits affect accepted index-zero handling.** With selector `0x100` and effective length at most 64, F-8f180221fee0 is called and general programming uses parameter 64. Normal completion returns high word zero. With effective length above 64, the earlier rejection occurs instead.

9. **Special-path object references may differ.** If the first global-object reference read yields one object whose byte at `0x04` is zero, and the special mask condition holds, a later reference read supplies the object for the selector store at `0x18`. If that second value names another object, the store targets the latter.

10. **Exact-selector observations can change.** For selector `0x80`, suppose the first Transfer-clear[0] extraction is 3, the second is 2, and the third Shared control read yields `0x10`. The final write and high result word are `0x8C000010`; the low word is zero. The first two Shared control reads still occur.
