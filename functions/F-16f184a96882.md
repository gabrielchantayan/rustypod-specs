# F-16f184a96882

## Purpose

F-16f184a96882 conditionally updates one byte at a fixed offset from a caller-supplied base address and returns a 32-bit result.

The established behavior has three cases:

- A selector equal to 3 produces result 12 without accessing memory through the base address.
- A selector equal to 4 causes a one-byte write of 6, then produces result 2.
- Every other selector causes a one-byte write of 7, then produces result 12.

The byte’s application-level meaning is unknown. Its values might represent states, but interpreting them as named states, errors, or completion codes would exceed the available evidence. Likewise, neither return value has an established success or failure meaning.

## Interface

### Inputs

The function accepts two inputs:

| Input | Established representation | Role |
|---|---|---|
| Base address | A 32-bit integer-shaped value used to form a memory address | Identifies the location relative to which a byte may be written |
| Selector | A 32-bit integer value | Determines whether a write occurs, the byte written, and the result |

The base-address input is not dereferenced to obtain another address. The write destination is formed directly from that input by adding 44 bytes, hexadecimal 0x2C.

The selector is compared for equality with 3 and 4. No selector is rejected explicitly. Signedness does not affect the distinction between those two values and all other 32-bit patterns: a selector represented as a negative integer takes the same branch as any other value unequal to 3 and 4.

### Output

On normal return, the function produces a 32-bit value:

| Selector | Returned value |
|---|---:|
| 3 | 12, hexadecimal 0x0000000C |
| 4 | 2, hexadecimal 0x00000002 |
| Any other value | 12, hexadecimal 0x0000000C |

There is no separate output buffer, returned pointer, or exposed count.

The return representation is established as 32 bits. Whether a surrounding interface labels that representation signed or unsigned does not change either returned value.

### Memory layout and preconditions

For selectors other than 3, the required destination is the single byte at offset 44 from the supplied base address.

The visible behavior does not require reading bytes at offsets 0 through 43. It also does not establish a complete object layout, an allocation size, a field type beyond the one-byte access, or alignment requirements for a containing object.

Normal completion of a writing case requires the computed destination to permit the observed byte store. No explicit validation establishes this condition. The contract therefore does not promise a normal return for an invalid, inaccessible, or otherwise unsuitable destination.

For selector 3, the function performs no memory access through the base-address input. In that case, the visible behavior imposes no dereferenceability requirement on that input.

## Behavior

### Selector equal to 3

When the selector equals 3:

- No destination byte is read.
- No destination byte is written.
- The function returns 12.

The base-address input does not affect this result. In particular, the function does not inspect a preexisting byte to decide whether to leave it unchanged.

This case preserves the destination only in the limited sense that this function performs no write. It does not provide synchronization or prevent another actor from changing the same memory.

### Selector equal to 4

When the selector equals 4:

- The function writes the value 6 to the byte at base address plus 44.
- After that write, normal execution returns 2.

The store is unconditional within this case. It is not contingent on the previous byte value, and the function does not first compare that byte against 6.

The store width is exactly one byte. The value written is hexadecimal 0x06. No neighboring byte is explicitly written by the visible operation.

### Every other selector

For every selector unequal to both 3 and 4:

- The function writes the value 7 to the byte at base address plus 44.
- After that write, normal execution returns 12.

This case includes zero, negative signed values, and the largest 32-bit unsigned pattern. There is no additional range check, lookup, or fallback result for such values.

The store width is exactly one byte. The value written is hexadecimal 0x07.

### Observable ordering and arithmetic

In both writing cases, the byte store precedes normal return. There is no visible read of the old destination value, and the returned result is not calculated from memory contents.

The offset is measured in bytes. It is not multiplied by a word size or an element size. Because both possible stored values fit within one byte, neither store requires a meaningful truncation of the value being written.

The address calculation uses a 32-bit integer-shaped base representation in the supplied static evidence. That evidence does not establish a portable rule for address overflow, out-of-range address formation, or translation to a host with a different pointer width. Acceptance of a writing case therefore requires a valid destination under the actual execution environment rather than an assumed wrapping-address interpretation.

## Acceptance examples

These are conditional acceptance criteria derived from static evidence. They are not reports of executed tests.

### Selector 3 leaves storage untouched

Given an otherwise ordinary writable memory region whose byte at offset 44 initially contains 91:

- Calling with selector 3 must return 12.
- This function must not write that byte.
- This function must not read that byte.

The same no-access behavior applies regardless of the initial byte value.

### Selector 4 overwrites the destination

Given a valid writable destination at base address plus 44, initially containing 91:

- Calling with selector 4 must replace that byte with 6.
- Normal return must produce 2.
- No adjacent byte may be explicitly modified by this function.

The initial value 91 is not special; the same replacement is required for every possible initial byte.

### An unrecognized selector follows the default writing case

Given a valid writable destination, calling with selector 0 must store 7 and return 12.

The same outcome is required for selectors 2, 5, and a 32-bit pattern interpreted as −1. These examples distinguish the full default case from a narrower interpretation limited to nearby positive values.

### Matching destination contents do not eliminate the specified store

Given selector 4 and a destination already containing 6, the visible behavior still specifies a write of 6 before returning 2.

Similarly, a default-case selector specifies a write of 7 even if the byte already contains 7. Unchanged final contents alone do not demonstrate that no store occurred.

### An unusable base does not affect the no-access case

Given selector 3, an address value that would be unsuitable for dereferencing must not trigger a destination access by this function. Normal execution returns 12 without using that address for a load or store.

This does not imply that the same base is acceptable for selector 4 or any default-case selector.

### Invalid writing destinations have no specified normal outcome

Given selector 4 or a default-case selector and a destination that cannot accept the byte store, the evidence does not establish a recoverable error result. Acceptance criteria must not require a particular fault, exception, or returned status for that situation.
