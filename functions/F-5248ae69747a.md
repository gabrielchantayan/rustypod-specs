# F-5248ae69747a

## Purpose

F-5248ae69747a follows wrapper-tagged objects until it encounters a non-wrapper, then conditionally scans bytes associated with that object. Each consumed byte is translated through externally supplied table storage and incorporated into a 32-bit rolling accumulator. Comparisons against external words can change private recognition state or end the scan.

The established external behavior is a sequence of memory reads followed, when execution terminates normally, by return of control. The body contains no explicit writes to shared storage, function calls, or returned status value.

Sequence recognition is **inferred intent**. Neither a validation result nor a parsed value is exposed by the supplied interface.

## Interface

**Input:** one object address.

**Output:** no explicit return value. Normal return does not distinguish a non-scan object, an endpoint encounter, or a terminating comparison.

### Representations and arithmetic

- Object tags, input elements, and translation entries occupy one byte.
- Input elements and translation entries are interpreted as unsigned 8-bit values.
- The encoded length, accumulator, and comparison operands are unsigned 32-bit values.
- Private recognition state takes the integer values 99, 97, 98, and 101.
- Stored addresses use the supplied representation’s 32-bit address model.
- Object offsets and cursor increments are measured in bytes.
- Effective extent is the unsigned encoded length shifted logically right by one.
- Accumulator updates wrap modulo \(2^{32}\).

Pointer arithmetic is separate from accumulator arithmetic. The source does not establish defined behavior for address overflow, invalid pointer arithmetic, or accesses outside valid storage.

### Accessed object fields

Only fields actually accessed are specified.

| Object category | Byte offset | Representation | Meaning |
|---|---:|---|---|
| Every examined object | 0 | Byte | Object tag |
| Wrapper object | 56 | Stored address | First link in indirect resolution |
| Scan object | 20 | Stored address | Initial cursor and endpoint base |
| Scan object | 24 | Unsigned 32-bit word | Encoded extent |

The wrapper tag is 110. The scan tag is 31.

Resolving a wrapper requires four dependent memory reads:

1. Read an address from the wrapper’s offset-56 field.
2. Read an address-valued word at that address.
3. Read an address from 12 bytes beyond the address obtained in the second read.
4. Read the next object address through the address obtained in the third read.

The offset-56 field therefore does not directly contain the next object address. Each intermediate location must support its particular read before the next object’s tag can be examined.

### External lookup and comparison storage

The scan uses:

- A global storage location holding the translation-table base value.
- Byte entries selected relative to each evaluated table base.
- Eight unsigned 32-bit comparison words.

This contract names the first seven comparison words **W0** through **W6**, and the final word **E**. They occupy consecutive four-byte positions in one comparison region: W0 at offset 0, W6 at offset 24, and E at offset 28.

The translation-base storage is evaluated for every consumed byte. It is distinct from both the input-byte storage and the selected table-entry storage.

Concrete table contents, comparison values, byte order, and alignment requirements are not provided.

## Behavior

### Object traversal and scan selection

The function examines the current object’s tag. While that tag equals 110, it resolves the next object through the four dependent link reads and repeats the tag examination.

There is no explicit null check, link validation, cycle detection, or depth bound. A stable readable cycle containing only wrapper-tagged objects can continue indefinitely without reaching scan selection.

After a traversal-condition evaluation observes a non-wrapper tag, a separate tag evaluation determines whether the object is scan-tagged. Only a value of 31 in this second evaluation enters scanning.

These are distinct source-level evaluations. The contract does not require both tag evaluations to yield the same value if the storage can change.

If the scan-decision tag is not 31, the function returns without reading scan fields, translation storage, or comparison storage.

### Initialization and endpoint evaluation

For a scan object, private recognition state starts at 99 and the accumulator starts at zero. The initial retained cursor is read from object offset 20.

Before each possible byte consumption, the function evaluates an endpoint:

\[
\text{endpoint}=\text{fresh base}+(\text{fresh encoded length}\gg1).
\]

The base is read from offset 20 and the unsigned encoded length from offset 24. Their relative evaluation order is not established by the expression. Both participate in the endpoint check before that iteration consumes an input byte.

The initial cursor read is separate from the first endpoint-base read. Later endpoint calculations do not reset the retained cursor.

If the retained cursor equals the evaluated endpoint, the function returns immediately. The check is equality only; it is not a less-than comparison or a bounds check. An endpoint behind the cursor does not itself cause return.

For stable scan metadata, valid storage, and defined pointer arithmetic:

- Lengths 0 and 1 give zero effective extent.
- An odd length discards its low bit.
- If no earlier terminating comparison succeeds, exactly the encoded length shifted right by one bytes are consumed.
- A terminating comparison can reduce consumption below that fixed extent.

Metadata stability is a **sufficient assumption for this fixed-extent guarantee**, not a source-established requirement for termination or bounded consumption. Changing metadata can still produce cursor/endpoint equality. A terminating E comparison can also end scanning independently of future endpoint values.

### Translation and rolling accumulation

When the cursor differs from the endpoint, the function forms a private successor cursor one byte beyond the current cursor.

The translation expression requires three distinct memory dependencies:

- The unsigned byte at the current cursor.
- The global translation-table base value.
- The unsigned table byte at that evaluated base plus the input-byte value.

The expression does not establish whether the input-byte read or the global-base read occurs first. The selected table-entry read depends on both.

For prior accumulator \(A\) and translated byte \(T\), the updated accumulator is:

\[
A_{\text{new}}=(256A+T)\bmod2^{32}.
\]

The newest translated byte occupies the low eight bits. After four bytes, the accumulator contains the most recent four translated bytes in consumption order. Further updates discard the oldest byte. Before four bytes have been consumed, unused high bits remain zero.

Comparisons occur after every consumed byte, including the first. There is no minimum four-byte window. Recognition-state changes do not reset the accumulator.

### First comparison group

Every consumed byte reaches the following source-level read trace:

1. Read W0 and retain whether the updated accumulator differs from that value.
2. Read W0 again, unconditionally, as an initial selected comparison value.
3. If the first comparison mismatched, read W1 and replace the selected value.
4. Initialize a second comparison value from the selected value.
5. If the first comparison mismatched and the accumulator differs from the selected value, read W2 and replace the second comparison value.
6. Advance the retained cursor to the previously formed successor.
7. The group fails only when the first comparison mismatched, the accumulator differs from the selected value, and it also differs from the second comparison value.

If the group succeeds, state becomes 97 and execution returns to the next endpoint check. W3 through E are not read for that byte.

Consequently:

- W0 is evaluated twice for every consumed byte.
- A match against the first W0 evaluation guarantees group success, regardless of the second W0 value.
- Following a first W0 mismatch, W1 replaces the second W0 value before that selected value affects the group outcome.
- W2 is read only if the first W0 comparison mismatched and the W1 comparison also mismatches.

This trace is not equivalent to unconditionally reading W0 through W2 or comparing against a single coherent snapshot.

### Remaining comparisons and state changes

Only failure of the first group reaches the remaining rules.

**W3 rule.** W3 is read and compared before the state condition is evaluated. A match changes state to 98 only if the prior state is 99 or 101. Success returns execution to the next endpoint check.

**W4 rule.** If the W3 rule fails, W4 is read. A match changes state to 101 only when the prior state is 99. Success returns execution to the next endpoint check.

**W5 rule.** If the combined W4 comparison and state condition fail, W5 is read. A match with state 99 changes state to 101 and resumes at the next endpoint check.

**W6 rule.** If the combined W5 rule fails, W6 is read. A match with state 99 changes state to 101 and resumes at the next endpoint check.

**E rule.** Only after all state-changing rules fail is E read. The function compares the entire 32-bit E value with the low 24 bits of the accumulator. Equality returns immediately. Inequality preserves state and resumes at the next endpoint check.

A state other than 99 does not bypass W4–W6 reads. If execution reaches W4 in such a state, all three combined rules fail, so W4, W5, W6, and then E are read.

Every successful state-changing rule skips the E read for that byte. A comparison match whose state condition fails does not skip later rules.

### Stable-data recognition summary

When the relevant comparison values remain stable, the logical priority is:

| Priority | Condition | Effect |
|---:|---|---|
| 1 | Accumulator equals W0, W1, or W2 | Set state to 97; continue |
| 2 | Accumulator equals W3 and state is 99 or 101 | Set state to 98; continue |
| 3 | Accumulator equals W4, W5, or W6 and state is 99 | Set state to 101; continue |
| 4 | All earlier rules fail and low 24 accumulator bits equal E | Return |
| 5 | Every rule fails | Preserve state; continue |

This summary does not replace the source-level read trace.

No rule restores state 99. State 97 prevents subsequent W3 and W4–W6 transitions. State 98 also prevents those transitions, but either state can subsequently become 97 through the first comparison group.

Because E is compared as a full 32-bit value against a masked 24-bit value, an evaluated E with any high-byte bit set cannot match.

### Completion and errors

Normal return occurs when:

- The scan-decision tag is not 31.
- An endpoint check observes cursor equality.
- A reached E comparison succeeds.

These paths expose no distinct status.

The body provides no explicit error handling for unreadable storage, invalid addresses, unsuitable alignment, or invalid pointer arithmetic. Their consequences are not specified by the supplied source.

## Side effects

There are no explicit writes to objects, links, input bytes, translation-base storage, table entries, comparison words, or other shared memory.

The current object address, cursor, accumulator, recognition state, and comparison temporaries change only as private working state. The cursor is not written back to the object.

There is no allocation, release, reference-count operation, ownership transfer, or resource cleanup. The function does not establish ownership of any reachable storage. No callee behavior needs to be assumed because the body contains no calls.

The selection and order of source-level reads matter to this contract. Hardware transactions, compiler coalescing, device-memory behavior, and the validity of concurrent mutation are not established.

## Dependencies

**Function dependencies:** none.

**Storage dependencies:**

- Object tags and selected wrapper-link cells.
- Scan base and encoded-length fields.
- Each consumed input byte.
- The translation-base global, evaluated for each consumed byte.
- Each selected translation entry.
- Both W0 evaluations and every subsequently reached comparison-word evaluation.

Every reached access depends on readable storage and valid addressing. A readable 256-byte translation table at each evaluated base is sufficient to cover all possible input-byte indices, but an individual execution reads only selected entries.

Stable scan metadata, valid storage, and defined pointer arithmetic are sufficient for a fixed-extent scan: absent earlier E termination, consumption equals the initial encoded length shifted right by one. This is a conditional guarantee, not a requirement checked or imposed by the function.

Stability is not necessary for bounded consumption or termination. Changing endpoint metadata may cause a later equality check to succeed; a reached matching E may terminate scanning regardless of subsequent metadata. Conversely, the supplied body does not establish termination for arbitrary changing metadata.

Treating translation and recognition data as fixed mappings additionally requires stability of the relevant table-base, table-entry, and comparison evaluations. Those assumptions support particular interpretations; the function performs no stability validation.

## Acceptance examples

These are conditional static expectations, not executed tests.

### Non-scan object

If the traversal-condition tag is not 110 and the separate scan-decision tag is not 31, the function returns without reading wrapper links or scan metadata. No shared storage is modified.

### Wrapper resolving to an empty scan

Suppose four valid dependent link reads resolve a wrapper to a scan object with stable length 0 or 1 and valid base arithmetic.

The initial cursor is read, then the first endpoint check reads base and length and observes equality. No input byte, translation-base value, table entry, or comparison word is read.

### Stable odd extent

With stable length 5, valid scan storage and pointer arithmetic, and no successful E termination, exactly two bytes are consumed. Each byte evaluates the translation-base global independently. The next endpoint check returns before a third input-byte read.

### Changing metadata that still terminates

Suppose the initial cursor is address \(B\). The first endpoint evaluation uses base \(B\) and encoded length 4, yielding \(B+2\), so one byte is consumed. Assume that byte does not terminate scanning.

If the next endpoint evaluation uses base \(B\) and encoded length 2, it yields \(B+1\), which equals the advanced cursor. The function returns after one consumed byte.

This demonstrates termination despite changing length metadata. It does not establish that concurrent mutation is supported.

### E termination without stable metadata

Suppose an endpoint check permits consumption, all state-changing rules fail for that byte, and the evaluated E equals the accumulator’s low 24 bits.

The function returns after the E comparison. It performs no subsequent endpoint check, so termination does not depend on a stable future base or length.

### Translation-base changes

If two bytes are consumed and their global-base evaluations yield different valid table addresses, each translation uses its own evaluated address. The source-level contract does not permit replacing those evaluations with one scan-wide snapshot.

No order between an input-byte read and its corresponding global-base read is asserted.

### First W0 match despite a different second value

If the accumulator matches the first W0 evaluation but not the second:

- Both W0 reads occur.
- W1 and W2 are not read.
- State becomes 97.
- W3 through E are skipped for that byte.

### W1 match

If the first W0 evaluation mismatches and the subsequent W1 evaluation matches, W0 is still read twice. W1 is read, W2 is skipped, state becomes 97, and later comparison words are not read.

### State-gated comparison reads

If state is 98 and the first comparison group fails, W3 is read but cannot trigger its transition. W4, W5, and W6 are then read regardless of their values, followed by E. State remains 98 for that byte.

### Priority over E

If the first comparison group succeeds, an otherwise matching E value does not terminate that iteration: E is not read. State becomes 97 and the next endpoint check is reached.

### Wrapper cycle

A stable, readable cycle of wrapper-tagged objects repeatedly traverses its links. It never reaches scan selection and reports no cycle error.
