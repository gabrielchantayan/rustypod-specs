# F-0f491de32d8e

## Purpose

F-0f491de32d8e performs an ordered sequence of memory reads and writes through three explicit inputs, three implicit machine-state inputs, and addresses obtained from memory. It then invokes an unresolved indirect target with three arguments.

The established behavior is memory manipulation, including overlapping byte and word writes, pointer-chain traversal, self-referential stores, and accesses at computed addresses. The supplied evidence does not establish a higher-level operation such as initialization, list maintenance, serialization, or device control.

This contract describes the visible access sequence. It does not assume that the memory represents valid conventional objects or that apparently redundant accesses may be removed.

## Interface

### Explicit inputs

| Input | Width | Established use |
|---|---:|---|
| Payload | 32 bits | Stored as a full word at several locations; its low eight bits are also stored separately. |
| Tag | 8 bits | Written to an offset within the primary region at entry. |
| External base | 32 bits in the supplied representation | Used as an address and stored into its own region. |

There is no explicit return value in the supplied representation. A return is shown after the indirect invocation, but whether that invocation returns normally is unknown.

### Implicit inputs

Three incoming machine-state values are consumed without being established inside this function:

- **Auxiliary base:** used for writes at offsets `0x10` and `0x60`.
- **Primary base:** used repeatedly as an address, a stored 32-bit value, and a source of low-byte values.
- **Linked base:** used as an address and stored into fields of the primary region.

These labels identify operand roles, not inferred ownership or object types.

The function also reads three fixed-location 32-bit storage values near its end. This contract calls them **fixed word A**, **fixed word B**, and **fixed word C**, in order of their first reads. Their values, initialization, and relationship to other memory are unknown.

An unresolved indirect control-transfer target is another implicit input.

### Memory layout and preconditions

The visible accesses use:

- 8-bit fields at offsets `0`, `0x09`, `0x0D`, `0x10`, `0x11`, `0x15`, `0x19`, and `0x1D`.
- 16-bit accesses at computed addresses.
- 32-bit fields at offsets `0x04`, `0x10`, `0x14`, `0x20`, `0x24`, `0x30`, `0x34`, `0x40`, `0x44`, `0x50`, `0x54`, `0x60`, `0x64`, and `0x74`.
- A late 32-bit write at an address displaced by `0x45`, which need not be naturally aligned.

These offsets do not establish a single structure layout. Some accesses overlap, and different base roles may designate the same storage.

For normal execution, every accessed address must support the access width and permissions used at that point. Valid initial bases alone are insufficient: earlier stores can change subsequently loaded addresses.

There are no visible null checks, bounds checks, alignment checks, allocation checks, or error returns. Address validity, arithmetic behavior, and target-specific alignment requirements are caller or environment preconditions rather than validated conditions.

## Behavior

### Interpretation rules

The sequence below preserves the order of visible accesses while grouping them into phases.

A **captured** value remains the value obtained by its particular read. A **fresh read** observes memory at that later point, including intervening writes and any aliasing effects. Locations described as “the object reached through” a field are address roles only; they do not imply actual allocated objects.

Eight-bit and sixteen-bit stores of wider values retain the low eight or sixteen bits respectively. A byte store at the start of a word does not necessarily replace that word’s least significant byte: that relationship depends on endianness.

### 1. Entry writes and replacement of the primary link

The tag is first written to primary offset `0x11`. The word at primary offset `0x74` is then captured as the **entry link value**.

Next, in order:

- The low byte of the linked base is written to primary offset `0x0D`.
- The payload is written as a word to auxiliary offset `0x10`.
- The linked base is written as a word to primary offset `0x44`.
- The low byte of the payload is written to auxiliary offset `0x10`.
- The payload is written to primary offset `0x54` and then auxiliary offset `0x60`.

The word at primary offset `0x74` is read again to obtain the **entry-linked region**. These two reads of the same field are distinct observations.

Primary offset `0x74` is replaced with the linked base. The payload is written to entry-linked offset `0x40`, followed by a byte write of the entry link value to primary offset `0x0D`.

The word at entry-linked offset `0x44` is captured. Primary offset `0x54` receives the primary base, and external offset `0x54` receives the external base.

### 2. Initial descendant traversal

The address at entry-linked offset `0x14` is loaded. The low byte of the captured entry-linked `0x44` word is written to linked offset `0x11`.

The word at linked offset `0x14` is read, and its low byte is written at offset `0x15` of the address just obtained from the entry-linked region. Linked offset `0x14` is then read again; this second result defines the **first descendant**.

Primary offset `0x64` is captured as the **first primary data word**. The word `0x00000073` is written to first-descendant offset `0x20`.

Primary offset `0x64` is read again as the **second primary data word**. Its low byte is written to first-descendant offset `0x09`.

The address at first-descendant offset `0x74` becomes the **second descendant**. The low byte of the primary base is written to its offset `0x0D`.

Second-descendant offset `0x54` is read as a word and that captured word is immediately written back to the same address. This is an observable read followed by an observable write, not an omitted operation. The byte `0x74` is then written to second-descendant offset `0x09`.

### 3. Data propagation and refreshed traversal

The first primary data word is written to primary offset `0x44`. The primary base is written to second-descendant offset `0x34`.

The address at second-descendant offset `0x04` becomes the **third descendant**. The second primary data word is written to its offset `0x24`, followed by a byte write of the first primary data word to primary offset `0x19`.

Third-descendant offset `0x74` supplies the **saved branch value**. Its offset `0x04` supplies the **replacement primary data word**. Primary offset `0x74` is then read afresh to establish the **refreshed link**.

The address at refreshed-link offset `0x14` is loaded, and the saved branch value is written to offset `0x54` of that address. The address at refreshed-link offset `0x04` is then loaded as the **branch region**.

The low byte of the second primary data word is written twice consecutively to primary offset `0x0D`. Primary offset `0x64` then receives the replacement primary data word. Branch-region offset `0x30` receives the word `0x00000074`.

Refreshed-link offset `0x04` is read again. Offset `0x74` of that newly obtained address supplies the **deep branch**.

### 4. Primary-field rewrites

The low byte of a fresh word read from primary offset `0x64` becomes the **current data byte**. It is written to primary offset `0x1D`.

Primary offset `0x44` is read as an address, and offset `0x14` of that address supplies the **replacement child**. This matters because primary offset `0x44` was previously assigned a data word; the later operation nevertheless uses its current contents as an address.

The saved branch value is written to deep-branch offset `0x34`. The replacement child is written to primary offset `0x14`.

Primary offset `0x54` is captured as the **prior primary self-field**. The low byte of the primary base is written to replacement-child offset `0x09`.

The address at deep-branch offset `0x04` is loaded, followed by its offset `0x74`; the result is the **terminal descendant**. Its byte at offset `0x15` receives the low byte of the saved branch value.

Primary offset `0x54` receives the primary base. Primary offset `0x11` receives the low byte of the deep-branch address. Terminal-descendant offset `0x11` receives the low byte of the prior primary self-field.

Terminal-descendant offset `0x64` is captured as the **terminal data word**. The current data byte is then written to primary offset `0x09`.

### 5. Byte-region updates and final conventional traversal

A fresh read of deep-branch offset `0x04` establishes the **byte region**.

Its byte at offset `0x09` receives the low byte of the primary base. Its word at offset `0x50` is captured as the **byte-region header word**. Its byte at offset `0x11` receives the low byte of the terminal data word. Its byte at offset `0x09` receives the low byte of the primary base a second time.

Primary offset `0x14` receives the terminal data word. Primary offset `0x0D` receives the low byte of the byte-region address. Byte-region offset `0` receives the low byte of the byte-region header word.

Deep-branch offset `0x74` is captured as the **indexed base value**. Deep-branch offset `0x14` supplies the **final parent**. Byte-region offset `0x54` receives the byte-region address itself.

Final-parent offset `0x04` supplies the **final child**. The byte `0x64` is written to final-child offset `0x10`. The word `0x00000064` is written to primary offset `0x54`, then to final-child offset `0x40`.

Primary offset `0x0D` receives the low byte of the terminal data word. Final-parent offset `0x09` receives the low byte of the final-child address. Primary offset `0x24` receives the terminal data word. Final-parent offset `0x11` receives the low byte of the primary base.

### 6. Computed-address writes and final dispatch

Fixed word A is read. Primary offset `0x74` is then read afresh as the **late link value**.

The remaining accesses occur in this order:

1. A 16-bit store writes the low half of the late link value at the address formed by adding the late link value to the primary base.
2. A 16-bit store writes the low half of fixed word A at twice the final-child address.
3. A character is read at the address formed by adding the indexed base value to the primary base. Its conversion to a 32-bit unsigned value produces the **dispatch value**.
4. A 16-bit store writes the low half of the late link value at fixed word A plus the late link value.
5. The first 16-bit store is repeated at late link value plus primary base.
6. The word `0x00000045` is written at dispatch value plus `0x45`.
7. Fixed word B is read, then fixed word C.
8. Primary offset `0x44` is captured as the **dispatch data word**.
9. The byte `0x44` is written at dispatch value plus `0x44`.
10. Fixed word C is written as a word at twice fixed word B.
11. The low half of fixed word B is written at saved branch value plus fixed word B.

The unresolved target is then invoked with three arguments, in order:

- The dispatch value bitwise-ORed with `0x44`.
- Fixed word B.
- The dispatch data word.

The visible representation contains no subsequent memory operations before return. Effects performed by the indirect target are not specified here.

## Side effects

All established effects are memory accesses and the final indirect invocation. No allocation, release, explicit synchronization, or explicit resource acquisition appears before that invocation.

Stores of addresses into offset `0x54` create self-valued fields at several points. They do not establish ownership transfer, reference counting, or lifetime extension.

No rollback is visible. If an access faults or the indirect target fails, the evidence does not establish recovery, cleanup, or restoration of earlier writes.

Aliasing can materially alter behavior. In particular:

- A store may change a field before its later fresh read.
- Byte stores may partially alter words subsequently used as addresses.
- Computed-address stores may overlap previously accessed regions or fixed storage.
- Duplicate writes and the word read/write-back can be significant for memory-mapped or externally observed storage.

The contract therefore does not provide unconditional final field values independent of the memory map.

## Acceptance examples

These examples are conditional observations, not executed tests. Each requires the specified address validity and isolation from unintended aliasing.

### Payload and byte-width behavior

With payload `0x123456AB`, the auxiliary word write at offset `0x10` carries all 32 bits. The following write at that same address carries only byte `0xAB`.

On a little-endian target with ordinary memory, the second write leaves that word numerically unchanged. On a big-endian target, it changes the word’s first-addressed byte, producing different word contents. Endianness must therefore be supplied before asserting a final numerical word value.

### Distinct early observations

If the two reads of primary offset `0x64` return different values, the first value is propagated to primary offset `0x44`, while the second is propagated to third-descendant offset `0x24`. Their low bytes also have distinct destinations described above.

An implementation that merges these observations does not preserve the stated access contract.

### Repeated and self-valued writes

For non-overlapping ordinary regions, external offset `0x54` receives the external base and byte-region offset `0x54` receives the byte-region base.

Primary offset `0x54` receives the primary base earlier, but later receives `0x00000064`. A self-valued intermediate store is not an unconditional final-state guarantee.

### Low-valued dispatch character

If the indexed character read yields `0x12`, both signed and unsigned character interpretations produce dispatch value `0x00000012`.

The late word write targets address `0x57`, the byte write targets address `0x56`, and the first indirect argument is `0x56`. Normal completion requires those low addresses to be writable under the execution environment.

### High-bit dispatch character

If the indexed byte is `0x80`, unsigned-character interpretation produces dispatch value `0x00000080`. Signed eight-bit interpretation followed by conversion to 32-bit unsigned produces `0xFFFFFF80`.

These interpretations lead to different addresses and first arguments. Acceptance must remain conditional until character signedness and address arithmetic are established.

### Indirect-target mutation

If the indirect target returns after changing primary memory, those changes must not be rejected merely because they differ from the pre-invocation stores. The supplied evidence imposes no preservation contract on that target.
