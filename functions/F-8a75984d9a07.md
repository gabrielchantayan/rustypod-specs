# F-8a75984d9a07

## Purpose

Its observable policy is:

1. Offer one specific initial object category to a preliminary handling path.
2. If that path does not produce a nonzero result, select and invoke one of two main handlers.
3. If the main handler returns zero, conditionally invoke a final handler based on the object’s then-current category and its relationship to receiver state.
4. Return the first nonzero handling result, or zero if no invoked handling stage produces one.

This is an inferred description of intent. The established behavior is the sequence of reads, calls, comparisons, and returns specified below. The evidence does not identify the objects’ domain, assign semantic names to their category values, or establish whether nonzero results mean success, failure, consumption, or another condition.

## Behavior

### Preliminary handling

The function first reads the input-object category at offset 4.

If this value is not 13, neither statically identified dependency is called at this stage. Processing proceeds to main dispatch.

If the value is 13:

1. F-468ee00d626a is called with the input-object address.
2. Its result is compared with 111.
3. If the result is not 111, processing proceeds to main dispatch.
4. If the result is 111, F-cca02640048b is called with the receiver and input-object addresses.
5. If F-cca02640048b returns nonzero, that exact result is returned immediately.
6. If it returns zero, processing proceeds to main dispatch.

The original category is not read again between the result comparison against 111 and the call to F-cca02640048b. Consequently, a category change made by F-468ee00d626a does not cancel that call when its result is 111.

Conversely, neither the original category nor any original payload is retained for main dispatch. That stage reads the category again.

### Main-handler selection

On reaching main dispatch, the function reads the input-object category at offset 4 again.

If the newly read category is 22:

1. It reads the address-bearing payload at input-object offset 8.
2. Through that address, it reads the secondary discriminator at offset 4.
3. A secondary discriminator equal to 42 selects dispatch-region offset 268.
4. Any other secondary discriminator selects dispatch-region offset 272.

If the newly read category is not 22:

- Dispatch-region offset 272 is selected.
- The input-object payload and secondary discriminator are not read for this selection.

After deciding which dispatch offset applies, the function reads the dispatch-region address from receiver offset 0 and obtains the handler address from the selected slot. It then calls that handler with the receiver and input-object addresses.

The read order matters: the category and any required nested discriminator are read before the receiver’s dispatch-region address is loaded for this call.

If the handler returns nonzero, that result is returned unchanged. The final-stage category, payload, receiver-state, and handler reads are then skipped.

If the handler returns zero, processing continues to final-handler eligibility.

### Final-handler eligibility and invocation

After a zero main-handler result, the function reads the input-object category at offset 4 again.

If the category is not 15, the function returns zero. It does not read the input payload or receiver comparison state for this stage.

If the category is 15:

1. The input-object field at offset 8 is read as an integer value.
2. Receiver state at offset 80 is read.
3. The two values are compared for equality.

If they differ, the function returns zero without invoking the final handler.

If they are equal:

1. The dispatch-region address is read again from receiver offset 0.
2. The final handler address is read from dispatch-region offset 224.
3. That handler is called with the receiver and input-object addresses.
4. A nonzero result is returned unchanged.
5. A zero result leads to a zero return.

The final-handler dispatch address is not reused from main dispatch. A main handler that changes the receiver’s dispatch-region address can therefore affect the final call.

### Cross-stage state

Relevant state is read at each stage where it is needed:

- Main dispatch uses the category visible after any preliminary dependency calls.
- Final eligibility uses the category visible after the main handler returns zero.
- For category 15, the comparison uses payload and receiver-state values read after that main-handler call.
- The final handler is resolved through the receiver’s then-current dispatch-region address.

The supplied evidence provides no basis for assuming that any dependency preserves these fields or other global state.

There are no loops or retries. In the ordinary returning case, each eligible call site is executed at most once per invocation.
