### Initial repeated stores

The function extracts the low 16 bits of the first argument’s represented pointer value. A fixed, explicitly repeated prefix then stores that same 16-bit value through the first argument.

The destination does not advance. The stored value does not depend on the destination’s previous contents. This is not an array traversal or a data-dependent loop.

Every represented store belongs to the prefix. Replacing the entire prefix with one store is not justified where repeated writes are observable. The numeric repetition count is not separately tabulated in this contract.

For ordinary memory without interference, the destination contains the pointer’s low 16 bits after this prefix. That final state does not capture its repeated-access behavior.

### Selector-derived write and reconstruction

The retained unsigned 32-bit selector value is multiplied by 131,072. This multiplication wraps modulo 2³². Adding 14 remains within the represented unsigned arithmetic.

An 8-bit zero is written at the address obtained from that sum. The integer arithmetic is established; the validity and meaning of the resulting address are not.

The function then:

- Assigns zero to the second clear-only global.
- Obtains the upper 8-bit component from the reconstruction source.
- Forms a 16-bit composition with that component in bits 15–8 and a pointer-derived component in bits 7–0.
- Assigns the composition to the selector global.
- Reads one character-sized unit through the byte base and retains it.

The low component is obtained through a plain-character conversion of the byte-base pointer. Under ordinary truncating pointer-to-character behavior, it corresponds to the pointer’s low eight bits. Exact pointer conversion rules remain target-dependent.

The 16-bit composition establishes the expression’s width, not the selector global’s write width. Its assignment may involve an additional destination conversion. Component placement within the expression does not establish memory byte order.

The character read through the byte base is an explicitly byte-sized access. Its retained plain-character interpretation can be signed or unsigned.

Selector reconstruction does not replace the earlier retained unsigned selector value. The later second invocation argument still uses the earlier value.

A shift count equal to the represented operand width has no portable, uniquely established result. The derived address cannot be declared zero, unchanged, or sign-filled without additional target evidence.

The following operations are represented after that derivation:

2. The retained character is converted to signed 32 bits and assigned to the sampled-byte global.

## Acceptance examples

### Repeated destination

If the first argument’s pointer representation has low 16 bits 0xABCD, every store in the initial prefix writes the 16-bit value 0xABCD to the same destination.

Advancing the destination, reading its old contents to obtain the value, or substituting zero does not match the represented behavior.

### Explicit relative widths versus global assignments

With valid, disjoint ordinary storage, the explicit clears affect:

- Two bytes starting at state base plus 34.
- One byte at fourth argument plus 13.
- Four bytes starting at state base plus 20.
- One byte each at byte base plus 50 and plus 51.

These accesses do not imply clearing adjacent bytes.

By contrast, assigning the 8-bit copy conversion to its global destination does not establish that exactly one byte is written. Assigning the 16-bit reconstruction does not establish that exactly two bytes are written.

### Selector scaling

If the selector conversion yields unsigned 32-bit value 3, the scaled product is 393,216. The byte-clear address is 393,230, and the second invocation argument is 393,216.

If that conversion instead yields either 0x00008000 or 0xFFFF8000, multiplication by 131,072 modulo 2³² yields zero in either case. The byte-clear address is then 14.

This agreement does not establish the selector source’s width or signedness.

### Retained character

If the byte-base access returns bit pattern 0xFF, conventional eight-bit plain-character interpretations produce:

- Signed 32-bit conversion result −1 when plain characters are signed.
- Signed 32-bit conversion result 255 when plain characters are unsigned.

That result supplies the third argument and is assigned to the sampled-byte global. It does not establish the global’s write width or final stored representation.

### Final staging reread

Suppose the final source converts to signed 32-bit value 2. The function assigns that result to staging, assigns 118 through the overwrite view, then rereads staging.

If additional type evidence establishes a signed 32-bit staging object, the reread remains 2, and the shift has ordinary representable signed semantics, the first argument is 131,072.

If the same established type instead yields a reread of 3, the first argument is 196,608.

Neither result follows from the initial conversion alone. A different staging declaration can change the stored value, promoted operand, or shift semantics even without intervening modification.
