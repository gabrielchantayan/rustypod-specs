# F-5103ec33a232

## Purpose

The supplied static representation describes a stateful operation that repeatedly calls unresolved dependencies, derives addresses from returned words, and writes word-sized and byte-sized values to those addresses. Its visible tail is an unconditional loop containing further calls and byte writes.

No application-level purpose is established. In particular, the evidence does not establish that this operation allocates objects, decodes a format, manages references, or traverses a conventional data structure.

This contract distinguishes:

- **Established static evidence:** operations and ordering explicitly present in the supplied representation.
- **Inferred interpretation:** a 32-bit machine-word model used to explain address calculations and truncation.
- **Documented-only unknowns:** unresolved calling conventions, dependency behavior, memory validity, and completeness of the recovered control flow.

No runtime tests have been performed.

## Behavior

### Arithmetic model

Unsigned right shifts in the representation are logical shifts. Important derived quantities are:

- **Saved source word:** the initial 32-bit read from source base plus `0x14`.
- **Upper half:** saved source word shifted right by 16; range 0–65,535.
- **Scaled middle quantity:** saved source word shifted right by 8, then multiplied by 8; range 0–134,217,720.
- **Top byte:** saved source word shifted right by 24; range 0–255.
- **Shifted third input:** third input shifted right by 21; range 0–2,047.

The scaled middle quantity is **not** an isolated byte multiplied by eight. It retains all 24 bits remaining after the first shift.

The representation also contains signed-looking multiplication and left shifts of dependency results. A conventional 32-bit machine interpretation retains the low 32 bits. However, overflow and negative-shift behavior cannot safely be specified using high-level signed arithmetic rules. Exact machine semantics remain documented-only where those cases matter.

### Initial capture and first derived destinations

The following order is explicit:

1. Write the implicit entry value as a word at destination base plus `0x14`.
2. Read the saved source word from source base plus `0x14`.
3. Execute nine-call sequence `F-01`, with no explicit opening arguments and no additional fifth-call argument.
4. Write the same implicit entry value again at destination base plus `0x14`.
5. Execute five-call sequence `F-02`, passing four times the `F-01` result to its first call.

The first write precedes the source read. If those locations alias, the saved source word reflects the preceding write, subject to the actual memory semantics.

Let the `F-02` result be the **first index**, and let four times that result be the **first scaled index**.

Next:

1. Write the first scaled index at address `16 × first index + 0x14`.
2. Read a word from `first scaled index + 0x14`; this is the **captured destination word**.
3. Execute nine-call sequence `F-03`, opening with the first scaled index twice.
4. Write the captured destination word shifted right by 8 back to `first scaled index + 0x14`.
5. Execute five-call sequence `F-04`, opening with four times the `F-03` result.

The read in step 2 occurs before all `F-03` calls. The later write uses that captured value, not a fresh read after the dependencies return.

### Indirect byte destinations

Define the **selector address** as:

`((masked-address source AND 0x7fffffff) logically shifted right by 7) + 1`.

A selected byte destination is obtained by reading one unsigned byte at the selector address and adding `0x11` to that byte’s numeric value.

Consequently, each such destination lies between `0x11` and `0x110`, inclusive. The representation does **not** read a pointer-sized address from the selector location.

Each destination use below performs a fresh selector-byte read:

1. Take the `F-20` result and multiply it by 4. Write its low byte to the selected byte destination.
2. Call `F-21-1` with that scaled result three times.
3. Call `F-21-2`, obtain a word, and pass it to `F-21-3`.
4. Call `F-21-4`, `F-21-5`, and `F-21-6` without explicit arguments.
5. Call `F-21-7` and retain its returned word.
6. Reread the selector byte. Write the low byte of `(F-20 result AND 0x3fffffff) >> 20` to the resulting destination.
7. Execute five-call sequence `F-22`, opening with four times the `F-21-7` result.

The second stored value is effectively bits 20–27 of the `F-20` result. Although the masked and shifted intermediate can occupy ten bits, the final byte write discards the upper two.

Next, define the **late scaled result** as four times the `F-22` result:

1. Write its low byte at `(top byte >> 7) + 0x1c`.
2. Reread the selector byte and write zero to the selected byte destination.
3. Call `F-23-1` with `top byte >> 7`.
4. Call `F-23-2` without explicit arguments.
5. Call `F-23-3` with `(F-22 result AND 0x3fffffff) >> 6`.
6. Call `F-23-4`, `F-23-5`, and `F-23-6` without explicit arguments.
7. Call `F-23-7` and retain its returned word.
8. Reread the selector byte and write zero to the selected byte destination.
9. Execute five-call sequence `F-24`, opening with four times the `F-23-7` result.

The direct byte destination in step 1 is exactly `0x1c` or `0x1d`, since the top byte shifted right by seven is either zero or one.

### Loop setup and indefinite tail

Define the **loop selector address** as:

`late scaled result × 0x400 + 1`.

The ensuing indirect destination is again an unsigned byte read from this address, plus `0x11`.

Before entering the loop:

1. Derive the **initial loop quantity** as `(F-24 result AND 0x3fffffff) >> 25`. Its range is 0–31.
2. Read the byte at the loop selector address and write zero to the resulting indirect destination.
3. Call `F-25-1` with twice the initial loop quantity.
4. Call `F-25-2`, retaining its returned word as the initial carried result.

Each loop iteration then:

1. Executes five-call sequence `F-26`, opening with the carried result and the current loop quantity shifted right by 8.
2. Rereads the byte at the loop selector address and writes zero to the resulting destination.
3. Executes five-call sequence `F-27`, opening with four times the `F-26` result.
4. Replaces the carried result with four times the `F-27` result.
5. Replaces the loop quantity with the `F-27` result shifted left by 26.
6. Repeats without a visible exit condition.

On the first iteration, the second opening argument to `F-26` is necessarily zero. Under a 32-bit low-word shift interpretation, later iterations pass only information originating in the low six bits of the preceding `F-27` result, shifted into the upper portion of the word.

## Side effects

Dependency calls are interleaved with these accesses. No dependency is known to preserve memory, globals, selector bytes, or unrelated state. In particular:

- A later selector read may choose a different destination from an earlier one.

## Acceptance examples

These examples are conditional static acceptance criteria, not executed tests.

1. **Initial aliasing:** If source base plus `0x14` equals destination base plus `0x14`, and ordinary readable/writable memory semantics apply, the saved source word must reflect the initial write rather than the previously stored word.

2. **Source-field arithmetic:** For saved source word `0x12345678`, the upper half is `0x1234`, the scaled middle quantity is `0x0091a2b0`, and the top byte is `0x12`. The scaled middle quantity must not be reduced to `0x56 × 8`.

3. **Third-input width:** A third input of `0xffffffff` contributes `0x7ff` to the fourth opening argument of `F-11`. A value of `0x001fffff` contributes zero.

4. **Captured-word behavior:** If the captured destination word is `0xabcdef12`, the later direct write uses `0x00abcdef`, even if an intervening dependency changes that destination’s contents.

5. **Fresh selector reads:** If one selector read returns `0x20` and a later read returns `0x30`, their respective byte destinations are `0x31` and `0x41`. Reusing the first destination would not match the visible behavior.

6. **Byte truncation:** If the `F-20` result is `0x12345678`, its first scaled byte store writes `0xe0`; the later masked-and-shifted byte store writes `0x23`.

7. **Direct byte boundary:** A top byte below `0x80` selects direct destination `0x1c`; a top byte from `0x80` through `0xff` selects `0x1d`.

8. **Loop entry:** If all preceding operations complete normally, the first `F-26` opening call receives zero as its second explicit argument. The visible tail contains no input-dependent normal exit.
