## Acceptance examples

### Shared 25-bit-shift value

Assume 32-bit bit-vector semantics for the signed 25-bit shift, valid mapped destinations, and a producing paired result whose low word is 1. The shifted base and retained shifted word both equal **0x02000000**, not 0x00000100.

The initial word store at the final pair’s high word plus 0x14 carries 0x02000000. Both initial offset-0x09 byte stores address **0x02000009**. The first carries the low byte of the final pair’s high word; the second carries zero, the low byte of the same shifted-base value retained for the word store.

The two roles must remain equal even when the signed-shift semantics are otherwise unresolved. The numerical values above require the stated bit-vector assumption.

### Unsigned narrowing

Selecting the low 24 bits of unsigned word 0xFFFFFFFF and shifting left six produces 0x3FFFFFC0. Preserving the original higher bits changes the argument.

### Conditional extraction bound

Under 32-bit bit-vector semantics for the preceding signed eight-bit shift, input pattern 0xFFFFFFFF produces extraction 508, double 1016, and destination 1036 for the doubled-extraction-plus-0x14 store. Extraction 511 would incorrectly ignore introduced low zero bits.

### Fixed-location read width

If the undeclared object at 0x05 yields converted value 0x1234, computed addressing uses 0x1234 rather than an assumed byte value 0x34. Explicit computed byte reads still access eight bits.

### Capture versus reread

If the 0x60 assignment overlaps the global-base storage, repeated stores use the previously captured base.

If an intervening computed write changes 0x67 from 0x12 to 0x34, a later byte store sourced from a reread uses 0x34, assuming ordinary coherent storage and no further change.

### Retention, widths, and partial progress

Changing anchor memory after the retained offset-0x14 read does not change final argument 3. Halfword constants 0x3A and 0x65 remain 16-bit stores, not byte or word substitutes. If execution stops before the final transfer, earlier writes are not rolled back.
