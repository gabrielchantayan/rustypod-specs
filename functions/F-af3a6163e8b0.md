# F-af3a6163e8b0

## Purpose

F-af3a6163e8b0 performs type-dependent destination preparation, optionally processes a collection of records, and conditionally copies two words from a context-derived object into the destination.

Established responsibilities are:

- Clear a word in the primary object after initial classification.
- Obtain or create a destination for initial classifications 0x16, 0x17, and 0x18.
- Process an optional collection for initial classifications 0x16 and 0x18.
- Reclassify the primary object before deciding whether a final lookup and copy are required.
- Clean up temporary processing resources and return a 32-bit completion indicator.

Two dependency arguments come from global storage, not established constants. Each is read at its respective call site; preceding dependencies may change its value.

This contract describes static evidence. It does not resolve the missing assignment of a record-search candidate pointer or establish the ownership and mutation contracts of dependencies.

## Interface

### Inputs and return value

| Input | Established use |
|---|---|
| Primary object | A 32-bit address used to access the object layout below and follow subordinate addresses. |
| Lookup context | An opaque 32-bit value used as the starting context for each eligible record’s search and for the final lookup. |

The function returns a 32-bit completion indicator:

- **One:** execution reached the completion assignment, either after the final copy or after a successful type-0x16 completion gate.
- **Zero:** an explicit failure path or zero auxiliary-output path reached normal cleanup.

One does not certify that every dependency succeeded. Several dependency results are ignored. Invalid accesses or dependencies that do not return normally may prevent any return.

### Preconditions and ownership limits

The function provides no general null, bounds, alignment, lifetime, or allocation-failure validation. Every reached access requires valid memory and dependency-compatible handles.

The final copy requires a destination supporting writes at +0 and +8 and an output object supporting reads at +0 and +4. These requirements are not enforced.

No ownership transfer or release behavior may be inferred merely from a dependency’s position in the sequence. In particular, retaining a destination address does not prove that an intervening dependency leaves the destination alive.

## Behavior

### Entry

Before the first dependency call, the completion indicator, retained destination, worker address, and final-output pointer are initialized to zero.

F-99497b78e41d initializes the temporary processing object. The function then reads primary +16 and passes that word to F-2eb743f270d1. Only after classification returns does it clear primary +8.

The initial classification selects destination preparation.

### Initial classification 0x16

The function captures the collection handle from subordinate +16 before calling F-467cb0c60ff3 with the value at subordinate +20. Its return value becomes the retained destination.

The primary-to-subordinate-to-nested pointer chain is then followed again. The nested +16 word is classified through F-2eb743f270d1.

If that classification equals 0x15, primary +12 is read. When it is nonzero:

1. F-6c81b0b12feb receives the retained destination.
2. After that call returns, the pointer chain is followed again and the currently reached nested +20 word is cleared.

The destination retained locally is neither cleared nor replaced. Its subsequent usability depends on the unknown behavior of F-6c81b0b12feb. The pointer-chain rereads also mean that the cleared field need not belong to the same nested object inspected before that call.

This path proceeds to collection processing.

### Initial classification 0x17

F-f9450f0778b9 receives 4. Its result becomes the destination and is installed at +8 of the object then reached through primary +20 and subordinate +8.

This path does not process a collection.

The argument 4 has no established allocation-size meaning. Later destination accesses extend through offset +8.

### Initial classification 0x18

The collection handle is captured from subordinate +16. F-f9450f0778b9 receives 4, and its result becomes the destination.

After that call returns, the result is installed at +8 of the object reached through primary +20 and subordinate +20. Collection processing follows.

### Other initial classifications

No destination is obtained, so the retained destination remains zero. Execution nevertheless reaches final processing.

This is not evidence that other classifications are safely supported. A final copy on this path attempts destination accesses through the retained zero address. A later classification of 0x16 and a nonzero completion-gate result can instead bypass those accesses.

### Collection traversal and candidate search

A zero captured collection handle bypasses worker acquisition and traversal.

For a nonzero handle, F-83f21a307fbe obtains the worker. A zero result enters explicit failure reporting.

With a nonzero worker, traversal starts at signed 32-bit index zero. Before each iteration, including the first and the terminating check, F-10b760faca36 obtains the current count. The index is compared with that count using a signed comparison. The count is not cached.

For an admitted index, F-6bbddce1b930 returns a record address. Record +28 is read:

- Zero skips all remaining processing for that record.
- Nonzero enters candidate search.

For an eligible record, the function follows record +8, reads the addressed word, and classifies it through F-2eb743f270d1. Search starts from the original lookup context for every eligible record.

Each search step has this visible order:

1. F-2200228f531d receives the current search context and selector 0x208.
2. A zero result enters failure reporting.
3. Otherwise, F-a5253d33ff6f receives the search result, selector 0x78, and zero.
4. A candidate pointer is tested. Zero enters failure reporting.
5. For a nonzero candidate, its first word is interpreted as an address. The word at that address is compared with the record’s classification.
6. Equality ends the search. Otherwise, F-4a2b7d2440e4 receives the search result and supplies the next search context.

The supplied representation does not establish any initialization or assignment of the candidate pointer. It also does not show an output-pointer argument on the selector-0x78 call. Successful candidate traversal is therefore conditional on unresolved behavior; it cannot be promised from the explicit inputs alone.

After a match, F-ef3ab54e3806 receives the processing object and candidate. Record +28 is then read again and passed to F-f160bf832b18. That conversion result and the worker are supplied to F-9a8ea7637eda. A zero result enters failure reporting.

The later +28 read is not contractually interchangeable with the earlier eligibility read.

### Auxiliary processing

After worker preparation, record +12 is captured. Auxiliary processing occurs only when this captured handle is nonzero and F-10b760faca36 returns a nonzero count for it.

This is a nonzero test, not a positive-count test. A negative signed count also satisfies this gate.

The auxiliary sequence is:

1. Initialize a separate 32-bit output quantity to zero.
2. Reread record +12 and call F-3a1cdd4c1ec9 with that value and selector 0x34.
3. If the result is zero, call F-e778e7a06884 with two zeros. Pass its result to F-e549ea198d52 with the address of record +12, selector 0x34, and value 0x17.
4. Save the processing object’s first word.
5. Call F-0b1e8b902739 with the processing object, the 36-byte temporary region, and the address of a separate 32-bit export-output slot.
6. Call F-f9450f0778b9 with 4.
7. Call F-bbc440b3aefa with the newly returned object, the temporary region, and the export-output value. Ignore its return.
8. Call F-e549ea198d52 with the address of record +12, selector 0x33, value 4, and the new object.
9. Call F-e3ef981e414f with the processing object, its saved first word, and zero.
10. **After F-e3ef981e414f returns, read the auxiliary-argument global.** Supply that current value to F-211bb2c8ea63 with the earlier-captured auxiliary handle and the output quantity’s address.

The captured handle in the last call is not replaced by a later record +12 value. Conversely, the global argument is not an earlier snapshot: any preceding dependency, including F-e3ef981e414f, may have changed it. Each reached auxiliary invocation obtains its argument at this call site.

If the output quantity is zero after F-211bb2c8ea63, execution goes directly to cleanup with completion still zero. This branch does not explicitly report failure.

For any nonzero output quantity, F-2cfb687bb8ab receives the processing object, that quantity, and F-211bb2c8ea63’s return value. F-5990a26eaaa3 then receives the quantity. No positivity requirement is visible.

### Completing a record

F-d4720ffa0ebc receives the processing object, worker +4, and the worker address. A zero return enters failure reporting.

Otherwise, F-bbc440b3aefa receives the record’s current +20 value, worker +4, and worker +0. These worker values are read after F-d4720ffa0ebc returns; they are not stipulated to equal earlier values.

A zero return enters failure reporting. Otherwise, traversal advances.

The signed 32-bit index increases by one after each completed or skipped iteration. No overflow handling is visible. Search termination and signed-index exhaustion behavior are not established.

### Final processing

After preparation and any completed collection traversal, primary +16 is reread and classified again.

If the new classification is 0x16, F-5ae03d3507dc receives the primary object, 2, zero, and zero. A nonzero result skips the final lookup, flag update, and copy, and sets completion to one.

For any other classification, or when that gate returns zero:

1. **Read the final-selector global at the final lookup call site.** This occurs after reclassification and after any applicable F-5ae03d3507dc call has returned zero.
2. Call F-2200228f531d with the original lookup context and the just-read global value.
3. A zero result enters failure reporting.
4. Call F-a5253d33ff6f with the lookup result, selector 0x73, zero, and the final-output pointer’s address.
5. Read lookup-result +20, OR it with 0x200, and write it back.
6. Call F-a5253d33ff6f with the lookup result, selector 0x82, zero, and zero.
7. Read final-output +4 and write that word to destination +8.
8. Read final-output +0 and write that word to destination +0.
9. Set completion to one.

The final-selector global is not an invariant selector. Earlier dependencies, including the final classifier and completion gate, may change it. The bypass path does not perform this global read.

Neither selector-based call’s return value is checked. The final-output pointer is not explicitly validated. The flag write precedes the selector-0x82 call, which is not known to preserve it.

The two copies are sequential, not an atomic snapshot. Aliasing can make the first write affect the second source read. Destination +4 is not directly written by this copy sequence.

### Failure and cleanup

Explicit failures call F-4fc89ec41a6d with 0x21 and 0x6a. If it returns normally, cleanup follows with completion zero.

Cleanup calls F-990a2f44da95 on the processing object. If the retained worker is nonzero, F-28097aea1ffc receives it afterward. The completion indicator is then returned.

Cleanup does not explicitly release the destination or undo prior field installations, record changes, or flag writes. Cleanup is not guaranteed after invalid accesses or nonlocal dependency exits.

## Side effects

Directly established writes are:

- Clearing primary +8.
- Conditionally clearing the currently reached type-0x16 nested +20 field.
- Installing destinations for initial types 0x17 and 0x18.
- Updating final-lookup +20 with an OR of 0x200.
- Copying final-output +4 to destination +8, then final-output +0 to destination +0.

Dependencies receive object addresses, field addresses, and temporary-output addresses and may cause additional changes. Their global preservation, ownership, allocation, retention, release, and reentrancy properties are unknown.

The two global argument reads occur at different stages and must not be specified as entry-time snapshots or immutable values. Repeated classifications, counts, and pointer-chain reads likewise remain distinct observations.

No synchronization or rollback is visible.

## Acceptance examples

These are conditional static cases, not executed tests.

1. **Type 0x17 with valid final output.** The destination is installed before reclassification and final lookup. The lookup flag update precedes selector 0x82. Destination +8 is written before destination +0. Normal cleanup follows, and the function returns one.

2. **Type 0x18 with zero collection.** Destination creation and installation still occur. No worker is acquired. Final classification and applicable completion processing still occur.

3. **Successful completion gate.** If final classification is 0x16 and F-5ae03d3507dc returns nonzero, the final-selector global is not read, and no final lookup or copy occurs. Completion becomes one.

4. **Changed auxiliary global.** If F-e3ef981e414f changes the auxiliary-argument global, F-211bb2c8ea63 receives the value read after that call returns, not a value captured before auxiliary processing.

5. **Changed final-selector global.** If final classification is 0x16 and the gate changes the final-selector global before returning zero, the subsequent lookup uses the post-gate read. For another classification, it uses the read after reclassification.

6. **Worker acquisition failure.** A zero worker result invokes the reporter with 0x21 and 0x6a. If it returns, processing-state cleanup occurs and zero is returned. Earlier mutations remain.

7. **Ineligible record.** Record +28 equal to zero skips candidate search, auxiliary processing, and per-record output. The next traversal condition obtains the count again.

8. **Zero auxiliary output.** A zero output quantity after F-211bb2c8ea63 stops traversal and final processing. Cleanup occurs without an explicit diagnostic at that branch.

9. **Candidate-path limitation.** Given an eligible record, successful matching cannot be required without resolving how the candidate pointer obtains a valid value. A zero candidate at the visible test enters failure reporting.

10. **Aliased final copy.** If destination +8 aliases final-output +0, the first copy overwrites the word subsequently read for the second copy. The contract requires sequential accesses, not preservation of both original source words.

## Uncertainties

The following remain **documented_only**:

- Initialization and population of the record-search candidate pointer.
- The values and allowed domains of both global argument locations.
- Whether dependencies mutate either global before its call-site read.
- Dependency ownership, lifetime, global mutation, and error behavior.
- Destination validity after F-6c81b0b12feb.
- The meaning of argument 4 to F-f9450f0778b9.
- Whether export initializes its output slot and stays within the 36-byte region.
- Whether failure reporting returns normally.
- Safe support for initial classifications outside 0x16–0x18.
- Search termination, signed-index overflow behavior, and practical collection limits.

The global-read locations and their ordering are established; the global values and immutability are not.

Inferred intent is type-directed transformation with optional auxiliary processing and final attachment. That interpretation adds no ownership or success guarantees.
