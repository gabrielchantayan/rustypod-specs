# F-b5bee446b938

## Purpose

F-b5bee446b938 searches a sequence of variable-stride records for a record whose dependency-produced value equals a requested value. It returns the address-like value of the first matching record it examines, or zero when its continuation condition fails.

The search has two important characteristics:

- The first candidate is examined without an initial boundary check.
- After a nonmatching candidate, the continuation check uses that candidate’s stride contribution **again after advancing the cursor**. It does not merely check whether the next candidate starts below the boundary.

This contract describes the supplied static representation. It does not establish the intended file format, the meaning of the requested value, or the safety of malformed inputs.

## Interface

### Inputs

The function receives three integer-valued arguments:

1. **Context address** — identifies storage containing a pointer-like field at byte offset 4.
2. **Sequence address** — identifies storage relative to which the initial candidate is located at byte offset 12.
3. **Requested value** — the value compared for equality with the result of F-76bf07f4ac67.

The exposed representation uses integer arguments and an integer return value rather than typed address parameters. Address arithmetic is therefore part of the visible behavior.

### Representation and layout

The supplied representation supports the following 32-bit interpretation:

| Location or value | Role |
|---|---|
| Context address + 4 | Pointer-like field identifying a descriptor |
| Descriptor + 0 | First 32-bit integer used in computing the boundary |
| Descriptor + 4 | Second 32-bit integer used in computing the boundary |
| Sequence address + 12 | Initial candidate address |
| Candidate address + 4 | Address passed to F-c223c8c1cf8e |
| Candidate address | Address passed to F-76bf07f4ac67 |

The descriptor’s first two integers are added to form the boundary used by the continuation comparison. Interpreting them as a region base and a region size is plausible, but their semantic names and units are not independently established.

The offsets and four-byte element spacing are static evidence. The original declarations, ABI, signed-overflow behavior, and pointer-conversion rules are not independently available. Arithmetic described below is exact where the relevant signed intermediate results are representable; overflow-dependent behavior remains documented_only.

### Output

The function returns:

- The current candidate’s address-like integer immediately when F-76bf07f4ac67 returns a value equal to the requested value.
- Zero when a nonmatching candidate is followed by a failed continuation comparison.

There is no separate status output, match object, or returned record length.

A successful match at a candidate address represented by zero would produce the same return value as an unsuccessful search. Whether such an address can arise in a valid execution is unknown.

### Preconditions

For an ordinary, defined execution of the represented operations:

- The context field at offset 4 must be readable.
- Each descriptor reached by the initial pointer-field reads must support the relevant four-byte integer read.
- Signed address and boundary arithmetic must remain representable where signed operations occur.
- Every dependency invocation must satisfy that dependency’s own access and argument requirements.
- Any required alignment must be satisfied by the supplied storage.

The function does not validate these conditions. In particular, it performs no null check, minimum-size check, or initial candidate-range check.

## Behavior

### 1. Capture the boundary inputs

Before making any dependency call, the function obtains two descriptor values in this order:

1. It reads the pointer-like field at context offset 4 and obtains the descriptor’s first integer.
2. It reads that context field again and obtains element index 1 of the descriptor then referenced, corresponding to byte offset 4 in the 32-bit interpretation.

The pointer-like field is therefore accessed through two separate expressions. The representation does not establish that it is loaded once and reused. If memory can change between these accesses, the two integers need not come from the same descriptor.

The two captured integers are retained for subsequent boundary comparisons. The function does not explicitly reread them after a dependency call.

### 2. Select the first candidate

The initial candidate address is the sequence address plus 12 bytes.

No condition is evaluated before examining this candidate. A nominally empty range, a boundary below the candidate, or a candidate already at the boundary does not by itself prevent the first two dependency calls.

### 3. Examine the candidate

For every candidate actually visited, the function makes these calls in order:

1. **F-c223c8c1cf8e**, receiving the candidate address plus 4.
2. **F-76bf07f4ac67**, receiving the candidate address itself.

The first result is retained as a signed integer stride contribution. The second result is compared for equality with the requested value.

The second call occurs before the equality test can succeed, and after the first call has returned. There is no early match path that bypasses F-c223c8c1cf8e.

The function assigns no special meaning to a negative, zero, or otherwise unusual result from either dependency. In particular:

- Every returned stride contribution is used if the candidate does not match.
- Any value returned by F-76bf07f4ac67 can match the requested value, including a value that the dependency might otherwise use as an error indicator.

Whether either dependency has such error indicators is unknown.

### 4. Return a match immediately

If the second dependency’s result equals the requested value, the function returns the current candidate address.

On this path:

- The cursor is not advanced.
- The continuation comparison is not evaluated.
- No later candidate is examined.
- Side effects already performed by either dependency are not undone.

Thus, “first match” means the first match in the actual visitation order. It does not imply lowest address, earliest physical record, or a match found within a validated range.

### 5. Advance after a nonmatch

For a nonmatching candidate, the function advances the cursor by the retained stride contribution plus 8 bytes.

For example, where signed arithmetic is representable:

- A contribution of 0 advances by 8 bytes.
- A contribution of 4 advances by 12 bytes.
- A contribution of −8 leaves the cursor unchanged.
- A contribution less than −8 moves the cursor backward.

The function does not enforce forward progress or record alignment.

### 6. Decide whether to continue

After advancing, the function checks whether:

> the advanced cursor plus the previous candidate’s stride contribution plus 8 is strictly below the sum of the two captured descriptor integers.

The comparison is unsigned. Its left side is not just the advanced cursor.

Equivalently, for ordinary non-overflowing positive arithmetic, a candidate at address A with stride contribution L advances the cursor to A + L + 8, but continues only when A + 2L + 16 is strictly below the captured boundary. This equivalence describes the arithmetic, not a second read of the next candidate’s size.

The condition uses:

- The already advanced cursor.
- The stride contribution returned for the candidate just examined.
- The descriptor values captured before the first dependency call.

It does not call a dependency to obtain the next candidate’s stride before making the decision.

Equality with the boundary fails the comparison. On failure, the function returns zero. On success, it examines the advanced cursor as the next candidate.

### Integer-width and overflow details

The represented arithmetic mixes signed integer addition with an explicitly unsigned comparison.

For the continuation condition:

- The advanced cursor and retained stride contribution are added as signed integers first.
- Adding the unsigned constant 8 then produces an unsigned expression.
- The two captured descriptor integers are added as signed integers, and their sum is converted to unsigned for the comparison.

Consequently, a representable negative signed intermediate may become a large unsigned value in the comparison. The condition is not equivalent to an all-signed less-than comparison.

The cursor update itself uses signed additions, including a signed addition of 8. The initial sequence offset, dependency argument offset, and descriptor sum also involve signed arithmetic in the supplied representation.

It is not justified to specify blanket modulo-\(2^{32}\) behavior for all these operations. Unsigned conversion and unsigned addition have that behavior in the 32-bit interpretation; signed-overflow behavior requires evidence not present here.

## Side effects

### Direct effects

The function directly reads the context and descriptor storage described above. It contains no explicit store through an input address, allocation, deallocation, or ownership-transfer operation.

Its changing search cursor and retained intermediate values are internal state. No cursor update is explicitly written back to the caller.

### Dependency-mediated effects

Each visited candidate causes both dependencies to execute, including the candidate that eventually matches or causes termination.

Those dependencies may read or modify memory, change global state, allocate or release resources, or perform other observable actions. Their implementations and contracts are unavailable. This contract therefore does not guarantee:

- Input immutability.
- Preservation of global state.
- Preservation of memory ownership.
- Continued validity of a candidate after either call.
- Absence of externally visible effects.

The first dependency’s effects can be observed by the second dependency because their order is fixed.

If a dependency changes descriptor storage, the outer search does not explicitly refresh its captured boundary inputs. Such a change may still affect other behavior, including later dependency calls.

### Failure and termination

There is no explicit exception handling, error translation, rollback, iteration limit, or cycle detection.

Termination is not guaranteed. For example, a stride contribution of −8 can keep the cursor fixed while the continuation condition remains true. Whether repeated calls eventually change the outcome depends on dependency behavior.

## Acceptance examples

These are conditional examples of the static contract, not reports of executed tests. Addresses are illustrative integer values, and arithmetic is assumed representable unless stated otherwise.

### Immediate match despite the boundary

Suppose the sequence address is 1000, making the first candidate 1012. Suppose the captured boundary is 900.

If F-76bf07f4ac67 returns the requested value for candidate 1012, the function returns 1012. F-c223c8c1cf8e must have been called first with 1016. The boundary does not prevent this match because no initial range check occurs.

### Continuation uses the old contribution twice

Suppose the first candidate is 1012, its stride contribution is 4, and it does not match.

The cursor advances to 1024. The continuation comparison tests 1036 against the boundary.

- With boundary 1037, candidate 1024 is examined next.
- With boundary 1036, the function returns zero without examining candidate 1024.

The second case remains true even though 1024 itself is below the boundary.

### Match precedes advancement

Suppose a candidate matches and its stride contribution would otherwise move the cursor backward or cause problematic subsequent arithmetic.

The function returns the matching candidate without performing that advancement or its continuation comparison. Arithmetic already required to form the dependency arguments is still part of the execution.

### Zero contribution

A nonmatching candidate at 1012 with contribution 0 advances to 1020. Continuation tests 1028 against the boundary. A zero contribution is not itself treated as an error or terminator.

### Repeated candidate

A nonmatching candidate at 1012 with contribution −8 leaves the cursor at 1012. The continuation expression is then 1012.

With boundary 1013, continuation succeeds. If dependency behavior remains unchanged on each visit, the function repeatedly examines the same candidate and does not terminate.

### Unsigned comparison

Suppose the advanced cursor is 4, the retained contribution is −8, and the boundary sum is 100. The signed intermediate 4 + (−8) is −4; its unsigned conversion followed by adding 8 yields 4 in the 32-bit interpretation.

The comparison therefore succeeds. Treating this as a purely signed comparison or rejecting the negative contribution would not reproduce the represented behavior.

## Evidence

**Established static evidence:** The supplied representation shows the two initial descriptor accesses, initial 12-byte offset, dependency order and arguments, equality-based immediate return, signed cursor advancement, post-advancement unsigned boundary comparison, and zero return on comparison failure.

**Inferred intent:** A variable-stride search over records, with one dependency supplying a size-like contribution and another supplying a match value. The descriptor sum appears to provide a search boundary.

**Verification status:** No runtime tests have been performed. The acceptance examples are arithmetic consequences of the supplied representation under their stated conditions, not observed executions.
