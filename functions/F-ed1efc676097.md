# F-ed1efc676097

## Purpose

F-ed1efc676097 is a 13-argument routine with a 32-bit unsigned result. Its visible actions can obtain a resource-like word, pass that word plus eight to a downstream operation, publish the base word through an output pointer, and invoke another dependency with a resource-related word.

These actions belong to a state dispatcher. Unavailable global values and secondary dependency results determine the transitions. The supplied static evidence therefore establishes action-local behavior and ordering, but not a complete execution sequence, successful lifecycle, or termination guarantee.

An allocation-and-initialization wrapper is **inferred intent**, not an established contract. Neither heap allocation, initialization, deallocation, nor ownership transfer is established by the available dependency interfaces.

## Behavior

The established entry-time sampling order is:

1. A word retained for the argument-capture selector.

3. A control word later used by fixed-result routing.
4. Another control word later used by result-scaling routing.
5. A control word later involved in conditional routing.
6. The initial selector seed.

These are local snapshots, not promises that the underlying global storage remains unchanged. Some snapshot-derived control words are subsequently modified.

Every dispatcher iteration adds a **freshly read global offset** to the current selector word. The offset is not cached at entry. This also applies when a default-path helper result becomes the next selector.

The dispatcher has explicit selections numbered 0 through 17, with selection 2 sharing the default behavior. Missing global contents and secondary-result semantics prevent resolution of reachability, repetition, and action order.

All subsequent global references are live reads at their indicated action points unless expressly described as saved state. Dependencies are not assumed to preserve globals. The evidence establishes sampling boundaries around calls; it does not establish a particular ordering between independent operands of a single arithmetic expression.

## Acceptance examples

These are conditional static criteria, not executed tests.

1. **Acquisition ordering.** If acquisition returns `0x00001000`, the current resource-related slot receives that word before either helper call. The saved resource slot retains its prior value through both calls and is assigned `0x00001000` afterward.

2. **Acquisition sampling.** If the first acquisition helper changes a global used by an intervening control update, that update uses the post-call read. If the second helper changes a selector global, the final selector expression uses its post-second-call read. No particular mutation is asserted.

3. **Entry snapshot versus live capture read.** If the capture-selector snapshot was sampled as A at entry and the relevant capture-time global is later B, capture forms its selector seed from A exclusive-or B. Re-reading the entry snapshot’s storage instead would not match the evidence.

4. **Per-iteration dispatch offset.** If a dependency changes the additive dispatch-offset global, the next dispatcher iteration reads the changed word. Reusing the previous iteration’s offset is not equivalent.

5. **Publication value and order.** With saved resource `0x00001000` and a valid publication destination, publication stores `0x00001000`, then reads its selector global. It does not store `0x00001008`.

6. **Downstream offset and wraparound.** A saved resource of `0x00001000` yields downstream position 7 equal to `0x00001008`. At 32-bit unsigned width, `0xFFFFFFFC` yields `0x00000004`. Neither result proves address validity.

7. **Acquisition predicates.** A zero acquisition result produces true; `0x00000001` and `0x80000000` produce false. Subsequent lifecycle behavior remains unresolved.

8. **Unchanged output.** If execution returns without publication and dependencies do not modify the destination, the caller’s existing output word remains unchanged.

9. **Null output.** Capture records false for a null pointer. This does not establish null safety for the complete routine; publication itself would still dereference the saved pointer.

10. **Opaque forwarding.** Following capture, downstream positions 4, 6, 8, 9, 11, and 13 receive the saved inputs from positions 8, 11, 13, 3, 10, and 6 respectively, unless later capture replaces them.
