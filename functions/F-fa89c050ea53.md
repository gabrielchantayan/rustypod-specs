# F-fa89c050ea53

## Purpose

F-fa89c050ea53 operates on an object through several dependencies and returns a packed 64-bit value. The result initially combines the first argument’s 32-bit representation with two 16-bit fields extracted from the second argument. Depending on a signed comparison and subsequently observed object state, the function either retains that record or reconstructs it from auxiliary storage with fields set to 320 and 240. Reconstruction may be followed by one record-modification dependency.

The established behavior includes an initial lookup, an optional control operation with value 1, and an unconditional pair of operations ending with control value 0. The second argument supplied to the lookup is **read from global storage**, not established as an immutable constant.

“Record,” “lookup,” “control,” and “reconstruction” describe the observed structure. They do not establish rendering semantics, resource types, ownership, or the meanings of object modes.

## Behavior

### Initial preparation and lookup

The function first initializes the two 16-bit packed fields from the second argument. It then reads and saves the signed 32-bit object field at `+0x218`.

After that capture, it initializes the local record word, auxiliary storage, and lookup-input storage from the corresponding arguments. It reads the global lookup-argument value and calls F-f79d2cf69ee3 with:

1. The address of the local lookup-input word.
2. The value read from global storage.

The returned value is treated as an address of signed 32-bit data. There is no intervening null check or status check.

The saved object field is not reread for the comparison, even if the lookup changes the object. Conversely, the lookup argument is not established as a value captured before the object-field read.

### Two signed comparisons

A comparison marker initially contains the saved signed object field. The function then performs two comparisons, each reading the lookup result’s referent separately:

- If the saved field is less than the first signed value read, the marker becomes 0.
- If the second signed value read is less than or equal to the saved field, the marker becomes 1.

The second assignment, when applicable, supersedes the first.

When both reads observe the same value, the marker is 0 for a strictly smaller saved field and 1 otherwise, including equality. When the values differ, that simplification is not valid. Both assignments may occur, or neither may occur. If neither occurs, the marker retains the original signed object field.

Subsequent decisions test only whether the marker is zero or nonzero. A retained negative value is therefore true for those decisions.

### Optional control value 1

The function evaluates an eligibility condition using current object state:

- First, read the secondary-object address and its flag.
- A nonzero flag satisfies the first part.
- Otherwise, the first part requires a nonzero comparison marker and mode 3.

Only when that part succeeds does the function evaluate the second part:

- A nonzero field at `+0x130` satisfies it.
- Otherwise, mode 7 or mode 6 satisfies it.

If both parts succeed, F-77d6a06893dd is called with a newly read secondary-object word and control value 1.

The conditions short-circuit. In particular:

- A nonzero flag avoids the mode-3 check.
- A zero marker avoids the mode read used for that check.
- A nonzero `+0x130` field avoids both mode checks in the second part.
- If the mode-7 comparison succeeds, the mode-6 comparison is skipped.
- If the mode-7 comparison fails, the mode is read again for the mode-6 comparison.

The secondary-object word passed to the dependency is not a saved copy of the word used for the flag access.

### Unconditional operation pair

Next, provided execution continues normally, the function calls:

1. F-85ae53ac577b with a freshly read secondary-object word.
2. F-77d6a06893dd with another freshly read secondary-object word and control value 0.

Control value 0 is issued whether or not control value 1 was issued. These calls are not established as an acquisition/release pair, nor as operations on an unchanged secondary object.

No dependency is assumed to preserve object fields or global state.

### Retention or reconstruction

After the unconditional pair, the function rereads the secondary-object address and flag.

It returns the current local record without reconstruction when:

- The flag is zero; and
- The comparison marker is zero, or the current mode is not 3.

A zero marker avoids the mode read in this decision.

Otherwise, reconstruction is selected: either the current flag is nonzero, or the marker is nonzero and the current mode is 3.

On the retention path, the function itself has not overwritten the initially prepared record. Its nominal result is therefore the concatenation of the second argument above the first argument. That statement is conditional on dependencies not modifying the record through reachable storage or other unestablished effects.

### Reconstruction

F-3de7a0e08c4b receives the address of auxiliary storage. Its return value is not used.

After it returns, the function performs these record updates in order:

1. Write 320 to the first 16-bit field.
2. Write 240 to the second 16-bit field.
3. Read the current 32-bit auxiliary word and copy it into the record word.

Both constants fit their 16-bit destinations exactly. The auxiliary word need not equal the original third argument after the dependency call.

The function then reads the secondary-object address and flag again. This is a fresh observation after F-3de7a0e08c4b, not reuse of the flag that selected reconstruction.

### Final dispatch

The post-reconstruction flag and field at `+0x130` determine the final path.

| Newly observed flag | Current `+0x130` | Further behavior |
|---|---|---|
| Zero | Zero | Return a value assembled directly from the current auxiliary word, 320, and 240. |
| Nonzero | Zero | Check mode 7, then mode 6 if needed. Call F-57185abbf6ce with the record address if either comparison succeeds. Return the current record. |
| Either | Nonzero | Check mode 3, then mode 1 if needed. Call F-c3ae6ea6086e with the record address and a freshly read `+0x130` word if either comparison succeeds. Return the current record. |

In the zero-flag, zero-field path, the return expression reads the auxiliary word again rather than assembling the result from the record word.

The nonzero-flag, zero-field path never proceeds to F-c3ae6ea6086e, whether or not F-57185abbf6ce is called.

For the nonzero-field path, the value passed to F-c3ae6ea6086e is reread after the field’s nonzero test and mode checks. It is not guaranteed to remain nonzero if externally observable state changes between reads.

   Saved bits `0xffffffff` mean −1. Against lookup value 0, the marker becomes 0. With zero flag and mode 3, the retained-record path follows. Treating the saved bits as an unsigned value would not satisfy this behavior.

4. **The global argument is read after object-field capture.**

If that dependency changes the object field to 9 but returns storage containing 6 for both reads, comparison still uses captured 5 and produces marker 0. 5. **Early control does not guarantee reconstruction.**

6. **Mode-6 modification.**
