# F-950aea8f52f3

## Purpose

F-950aea8f52f3 performs one indirect operation on a supplied object and conditionally performs a second operation. The first operation returns an integer. If that integer equals −1, the function returns it without performing the second operation. Otherwise, the function invokes the second operation with the original object pointer and the first result, then returns that first result after the second operation returns normally.

The established contract is conditional dispatch and result preservation. The evidence does not establish what the integer represents or whether either operation acquires, releases, removes, acknowledges, or otherwise manages a resource.

The second target is resolved after the first operation returns, using a fresh read from the object. Consequently, the two operations need not be selected from the same dispatch structure.

- If the first result is −1, no second operation is invoked.

## Behavior

### Initial dispatch

The function first reads the integer-valued dispatch base from the beginning of the object. It obtains the first target from the location 76 bytes beyond that base and invokes the target with the original object pointer.

This first operation is unconditional once execution reaches valid dispatch. There is no preceding application-level status check or inspection of another object field.

The function retains the operation's integer result. Subsequent behavior depends only on whether that value equals −1.

### Sentinel outcome

When the first operation returns −1, the function returns −1 without resolving or invoking the second operation.

In particular, this path does not perform the later read of the object's initial field. The first operation's effects are not undone.

The lack of a subsequent object read is a limited access-order observation, not an ownership rule. It does not independently establish that the first operation may destroy the object or otherwise end its lifetime.

### Non-sentinel outcome

When the first result is any integer other than −1, the function reads the beginning of the original object again.

The newly read value supplies the dispatch base for the second operation. The function obtains the second target from the location 44 bytes beyond that base and invokes it with two arguments:

1. The original object pointer.
2. The unchanged first integer result.

After that operation returns normally, the function returns the retained first result. It does not replace that result with any value returned by the second operation.

Zero, positive values, and negative values other than −1 all take this path. The condition is not a truth-value test, a nonnegative-value test, or a general negative-error test.

### Required ordering

The established order of relevant actions is:

1. Read the initial dispatch base from the object.
2. Obtain the first target at displacement 76.
3. Invoke the first operation.
4. Determine whether its result equals −1.
5. For a non-sentinel result only, reread the object's dispatch base.
6. Obtain the second target at displacement 44 from that newly read base.
7. Invoke the second operation with the object pointer and retained result.
8. Return the retained result after normal completion.

The second target is not selected before the first operation. If the first operation changes the object's initial field, that change can affect the second target's selection. It can likewise affect target selection by changing dispatch storage that is read later.

These are source-level ordering requirements. They do not establish particular machine instructions, atomic accesses, memory barriers, or safe behavior under concurrent mutation.

Because the base is represented as an integer in the supplied interface, portable pointer arithmetic cannot be assumed. The evidence does not establish an overflow policy, address-wrapping rule, or general validity of integer-to-pointer interpretation. Successful access requires that the applicable arithmetic and pointer interpretation identify valid target storage.

There is no shown recovery path for an invalid memory access, invalid target, dependency exception, nonlocal exit, or failure to return. The function does not translate such behavior into −1 or another fabricated status.
