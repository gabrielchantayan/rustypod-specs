# F-4100b60c14d9

## Purpose

F-4100b60c14d9 selects and returns one 32-bit word from a caller-supplied record, or returns a 32-bit fallback value when no selection rule succeeds.

Selection depends on a signed integer selector and three externally stored comparison values. Those comparison values determine both direct matches and which groups of literal selectors are reachable. Consequently, the literal-selector mappings are conditional, not an unconditional lookup table.

The established behavior is word selection. Interpreting the words as attributes, flags, handles, or any particular application-level values would require evidence not supplied here.

## Interface

### Inputs

- **Record base:** an address used as the beginning of a sequence of 32-bit words.
- **Selector:** a signed integer. This contract uses the recovered 32-bit signed interpretation for comparisons. Literal selectors are positive hexadecimal integers and are representable without conversion loss.

The function also reads four external storage locations. This document gives them descriptive labels:

| Label | Role |
|---|---|
| Boundary A | First equality target and first ordered-comparison boundary |
| Boundary B | Second equality target and second ordered-comparison boundary |
| Boundary C | Third equality target and third ordered-comparison boundary |
| Fallback | Returned word when no record-selection rule succeeds |

The labels describe their observed roles, not their intended application meaning. Their actual values, initialization, storage qualifiers, and modification rules are not supplied.

### Output

The return value is a single 32-bit word:

- the exact word read from the selected record position; or
- the exact word read from Fallback.

There is no observed conversion, masking, sign extension, arithmetic adjustment, or interpretation of the returned word. A return value does not independently indicate success or failure: a record word may equal Fallback.

### Record layout

Record positions are zero-based. Position \(n\) occupies four bytes beginning at byte offset \(4n\).

The highest reachable position is 24, at byte offset 96. A record supporting every possible selection therefore requires 100 readable bytes beginning at its base. A particular call accesses only its selected position; the source does not establish a requirement to read all earlier words.

The base must support the selected 32-bit load under the target platform’s address-validity and alignment requirements. Exact ABI alignment and byte order are not established by the supplied material.

## Behavior

### Selection priority

The function first compares the selector with Boundary A.

- Equality selects record position 9.
- Otherwise, a signed comparison with Boundary A chooses the lower-selector group or continues toward Boundary B.

On the continuation toward Boundary B:

- Equality with Boundary B selects position 19.
- Otherwise, a signed comparison with Boundary B chooses the middle-selector group or continues toward Boundary C.

On the continuation toward Boundary C:

- Equality with Boundary C selects position 20.
- Otherwise, a signed comparison with Boundary C chooses one of the two remaining literal-selector groups.

A successful selection immediately returns its record word. A group containing no matching literal selector falls through to Fallback; it does not continue searching other groups.

### Stable-boundary decision table

The following table applies when Boundary A, Boundary B, and Boundary C remain unchanged during the call. Comparisons in the reach conditions are signed.

| Reach condition | Selection rule | Record position | Byte offset |
|---|---|---:|---:|
| Selector equals A | Direct boundary match | 9 | 36 |
| A < selector, and selector equals B | Direct boundary match | 19 | 76 |
| A < selector, B < selector, and selector equals C | Direct boundary match | 20 | 80 |
| Selector < A | Use the lower-selector table | See below | See below |
| A < selector < B | Use the middle-selector table | See below | See below |
| A < selector, B < selector < C | Use the upper-middle table | See below | See below |
| A < selector, B < selector, C < selector | Use the highest-selector table | See below | See below |

No ordering among A, B, and C is validated or guaranteed. The table’s reach conditions must be satisfied as written, even when the boundaries are equal or not ascending.

For example, matching Boundary B is insufficient if the selector does not first pass Boundary A. Likewise, Boundary C can select position 20 only after both earlier boundaries have been passed.

### Read order and changing boundaries

The supplied representation contains a separate boundary reference for equality and, if equality fails, another reference for the ordered comparison:

1. Boundary A is referenced for equality.
2. If equality fails, Boundary A is referenced for the ordered comparison.
3. If that comparison directs execution toward Boundary B, Boundary B is referenced for equality.
4. If that equality fails, Boundary B is referenced for the ordered comparison.
5. If execution continues toward Boundary C, Boundary C is referenced for equality.
6. If that equality fails, Boundary C is referenced for the ordered comparison.
7. The selected record word or Fallback is then read.

Thus, the representation does not establish a single snapshot of all boundary values. If a boundary can change between references, the stable-boundary table is insufficient: routing follows the values observed at the successive comparisons.

The supplied material does not establish whether these source-level references correspond to distinct physical loads, or whether concurrent modification is supported. Atomicity, synchronization, and compiler load reuse remain documented_only unknowns.

### Arithmetic and edge cases

Record addressing uses fixed positions, not the numeric selector as an index. The largest displacement is 96 bytes. No selector-dependent multiplication, subtraction, wraparound, or bounds calculation is shown.

Negative selectors participate in signed comparisons. They do not match any listed positive literal selector, but may match a reachable boundary value. If they reach a literal-selector group without a match, they return Fallback.

A selector outside the listed literal set can still select positions 9, 19, or 20 through boundary equality. Conversely, a listed literal may return Fallback if boundary routing sends it to a different group.

## Acceptance examples

These examples are conditional static expectations, not executed tests. Boundary values are assumed stable during each example, and all required reads are assumed valid.

1. **First boundary takes priority.**  
   If Boundary A equals `0x3021` and the selector is `0x3021`, the result is record position 9, not position 4.

2. **Lower-group selection.**  
   If Boundary A is `0x302C` and the selector is `0x3021`, the result is position 4 at byte offset 16. Boundaries B and C are not needed on this path.

3. **Middle-group selection.**  
   If A is `0x302C`, B is `0x3034`, and the selector is `0x3032`, the result is position 15 at byte offset 60.

4. **Explicit middle-group miss.**  
   With A equal to `0x302C`, B equal to `0x3034`, and selector `0x3030`, the result is Fallback. No record word is read.

5. **Second boundary equality.**  
   If A is `0x302C`, B is `0x3034`, and the selector is `0x3034`, the result is position 19.

6. **Upper-middle selection.**  
   If A is `0x302C`, B is `0x3034`, C is `0x3037`, and the selector is `0x3035`, the result is position 22 at byte offset 88.

7. **Highest-group selection.**  
   With those same boundaries and selector `0x3057`, the result is position 23 at byte offset 92.

8. **Wrong-group routing prevents a literal match.**  
   If A is `0x4000` and the selector is `0x3056`, execution reaches the lower-selector group and returns Fallback. The position-24 rule is not reachable.

9. **An earlier boundary hides a later one.**  
   If A and B both equal `0x3034`, selector `0x3034` selects position 9. It does not reach the Boundary B equality rule.

10. **Return values do not encode selection status.**  
    If the selected record word equals Fallback, both paths produce identical return bits. The return value alone cannot distinguish them.
