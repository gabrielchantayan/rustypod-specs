# F-98b1a775fd6a

## Purpose

F-98b1a775fd6a is a conditional dispatcher. It selects one of two dependencies using a field in an input object and a separate control input. One route forwards five numeric inputs unchanged; the other supplies those inputs shifted left by 16 bit positions. Both routes forward the object reference and three additional values unchanged.

The established behavior is routing and argument preparation. The supplied evidence does not establish what operation either dependency performs, what the object represents, or what the numeric inputs mean.

A plausible intent is conversion from integer quantities to a representation with 16 fractional bits for one object mode. That interpretation is inferred, not required by the observable dispatcher contract.

## Behavior

### Selection rule

The dispatcher first reads the object field at byte offset 8 and compares it with the integer value 32.

The shifted route is selected only when both conditions hold:

- The field equals 32.
- The route control is nonzero.

All other combinations select the unchanged route.

| Field value | Route control | Selected dependency | Numeric argument treatment |
|---|---|---|---|
| 32 | Zero | F-4f5e50c895c2 | Unchanged |
| 32 | Nonzero | F-ffaf8af0cd9b | Shifted left by 16 |
| Any value other than 32 | Zero | F-4f5e50c895c2 | Unchanged |
| Any value other than 32 | Nonzero | F-4f5e50c895c2 | Unchanged |

The control input is a zero/nonzero selector, not a requirement for the value one. Negative nonzero values also satisfy this test under the recovered integer interpretation.

The field comparison is exact. Nearby values, values with only some matching bits, and values whose low byte equals 32 are not established substitutes for a full-field value of 32.

### Established observation order

The object-field read precedes the selected dependency call. It is also the left-hand condition of a short-circuit conjunction: the route-control comparison is relevant to selection only after the field comparison succeeds.

Consequently, a call with route control zero still attempts the object-field read. This is not a control-first interface that can bypass object access.

The dispatcher makes no second explicit field read before dispatch. It does not pass the field value as a separate dependency argument.

No reliable order is established for evaluating individual outgoing arguments. The contract establishes their positions and values, not a left-to-right sequence of argument evaluation. The numeric transformations shown have no direct memory writes.

### Shifted route

F-ffaf8af0cd9b receives the same nine-position arrangement, except that each of the five numeric inputs is independently shifted left by 16 bit positions before being supplied.

The shift amount is sixteen, not a multiplication by sixteen. In the nonnegative, representable range, the numerical effect is multiplication by 65,536.

For example:

- Input 0 produces 0.
- Input 1 produces 65,536.
- Input 2 produces 131,072.
- Input 32,767 produces 2,147,418,112.

The dispatcher contains no visible saturation, rounding, clamping, validation, or overflow-reporting step.

Under a fixed-width 32-bit bit-vector interpretation, shifting left by 16 retains the original low 16 bits in the high 16 positions and fills the low 16 positions with zeros. Inputs that differ only in their original high 16 bits would therefore produce identical shifted bit patterns.

That bit-vector interpretation must not be mistaken for an unconditional language-level guarantee for every signed input. Negative operands and positive operands whose shifted result is not representable require the execution-semantics qualification in **Uncertainties**.

The object reference and three opaque values are unchanged on this route. No transformation of those values is established.
