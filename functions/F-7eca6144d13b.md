# F-7eca6144d13b

## Purpose

The established behavior is:

- If the recorded value already equals the requested value, return zero without consulting the second field or calling a dependency.
- Otherwise, use F-c2a4e6949719 when the second field is zero, or F-a5bc00364bd0 when it is nonzero.
- Update the recorded value only after the selected operation satisfies its branch-specific success condition.
- Return −108 when F-c2a4e6949719 returns zero.
- Propagate any nonzero result from F-a5bc00364bd0.

The second field plausibly represents an associated resource or handle, and the recorded value plausibly identifies its current configuration. Those meanings are inferred intent, not established interface semantics. In particular, the evidence does not establish that either dependency allocates, owns, releases, or preserves any resource.

## Behavior

### 1. Initial comparison

The function first reads the 32-bit recorded value at offset +16 and compares it with the requested value.

If they are equal:

- It returns zero.
- It does not read the association field.
- It does not call either dependency.
- It performs no direct state write.

This is an equality shortcut, not a consistency check. For example, a matching recorded value paired with a zero association field still takes this path. The function does not attempt to repair or validate that combination.

If they differ, the function proceeds to inspect the association field.

### 2. Mismatch with a zero association field

When the association field reads as zero, the function calls F-c2a4e6949719 with the requested value as its sole visible argument.

After that dependency returns:

1. The function writes its 32-bit result into the association field.
2. It determines whether that result is zero.
3. If the result is zero, it returns −108.
4. If the result is nonzero, it writes the requested value into the recorded field and returns zero.

The association-field write occurs even when the dependency returns zero. Consequently, failure on this path is not a “no writes” outcome.

The success decision uses the returned result, not a new read of the association field. The function does not reread that field to verify the write or reconcile any other state.

On a zero result, this function does not subsequently write the recorded field. That does not establish that the recorded field remains unchanged overall: the dependency may have affected it through mechanisms not visible here.

On a nonzero result, the returned association value is stored without a visible validity check, conversion, or sign restriction. The recorded field is then assigned the original requested value.

### 3. Mismatch with a nonzero association field

When the association field reads as nonzero, the function reads that field again to obtain the first argument for F-a5bc00364bd0. It passes the requested value as the second argument.

The branch-selection read and the argument read are distinct accesses in the supplied representation. The function does not visibly retain the branch-selection value for the call. Under stable memory they agree; under intervening modification they need not. Concurrency semantics and compiler-level access guarantees are unknown.

After F-a5bc00364bd0 returns:

- If its result is nonzero, the function immediately returns that result.
- If its result is zero, the function writes the requested value into the recorded field and returns zero.

There is no direct association-field write on this branch. This does not imply that the dependency preserves that field.

A nonzero dependency result prevents this function’s final recorded-field write. There is no visible rollback of dependency effects.

### 4. Final commit

Both successful mismatch paths converge on a direct 32-bit write of the requested value to the recorded field.

This write occurs after the dependency returns and after the branch-specific success decision. It uses the supplied request rather than a value derived from the association field or from a fresh recorded-field read.

If a dependency has changed the recorded field, a successful path overwrites that field with the requested value. There is no visible post-call equality check.
