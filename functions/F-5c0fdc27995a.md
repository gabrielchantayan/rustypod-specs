### Arithmetic constraints

Ordinary arithmetic is represented at 32-bit width, not unlimited precision. Under a 32-bit bit-vector interpretation:

- Left shift by eight retains only the original low 24 bits.
- Left shift by 25 retains only the original low seven bits.
- Successive left shifts by eight, 18, and eight produce zero.
- Successive left shifts by 28 and 28 produce zero.
- A 24-bit masked value shifted left six occupies at most 30 bits.
- Right-shifting after a narrowing left shift cannot recover discarded bits.

Several shifts and multiplications involve signed represented operands. Negative operands, signed overflow, and address arithmetic therefore require an execution-model qualification; the bit-vector consequences above are not portable signed-arithmetic guarantees.

A late signed right shift uses the low byte of an address-valued quantity as its count. That count can range through 255. Behavior for counts exceeding 31 is **documented_only**; reducing the count modulo 32 is not established.

### Initial explicit memory mutations

The following descriptive quantities identify relationships without assigning object semantics:

- **Packed base:** a retained result multiplied by \(2^{25}\).
- **Small index:** another result shifted left eight, masked to 15 bits, then shifted right six.
- **Doubled index:** twice the small index.
- **Retained link:** an earlier result shifted left 25.
- **Latest pair:** the low and high words of the last compound result before explicit memory mutation.
- **Shifted word:** another retained result shifted left eight.

Under bit-vector arithmetic, the small index is a multiple of four from 0 through 508; the doubled index is a multiple of eight from 0 through 1016.

The initial updates first place the retained link at offset 0x14 from the latest high word, then store the low byte of that high word at retained-link offset 9. Next, the packed base is written at offset 0x54 from the latest low word scaled by 256. Only afterward is retained-link offset 9 overwritten with the retained link’s own low byte.

The packed-base offset-0x14 word is then cleared before its offset-5 byte is read. The doubled-index offset-0x14 word is cleared before that captured byte is zero-extended into the packed-base offset-0x34 word. A subsequent read of packed-base offset 0x14 supplies a retained word. The doubled-index offset-0x14 word is cleared again, followed by two byte writes to doubled-index offset 0x15 using the retained word’s low byte.

These are ordered, non-atomic effects. Aliasing can affect the read-back value; repeated writes remain distinct accesses.

## Acceptance examples

These are conditional requirements, not observed executions.

### Width and extraction

A byte store supplied with 0x123456AB writes 0xAB, not an adjacent word. An unsigned byte read yielding 0xE1 contributes numeric value 225 when later stored as a word.

Under bit-vector arithmetic, a source value whose low seven bits equal 63 produces small index 252 and doubled index 504. The fixed-address writes at 0x01 and, later, 0x15 therefore receive 0xF8, provided execution reaches them. The 0x05 read precedes the first write; intervening accesses precede the second.

### Captured fixed-address value

If the captured base is positive 0x1234 and execution supports the represented accesses, its one-bit left shift is representable as 0x2468. Fixed address 0x54 receives that word between the surrounding doubled-index offset-0x14 stores. This example does not define overflowing or negative signed shifts.

### Global capture before fixed mutation

If the global-base storage overlaps the word destination at 0x60, the global-base read still occurs first. Repeated-region addressing uses the captured value, not a value freshly read after the 0x20 store.

### Intervening final-phase mutation

If the 0x3A byte destination overlaps the subsequently read final-working-base offset-0x14 word, that read occurs after the byte mutation. The terminal argument derived from the saved word must not use a pre-mutation snapshot.

### Reloads are independent observations

If the intervening offset-0x44 word read changes what a later 0x67 read returns, fixed address 0x21 receives the reloaded byte. The two later publication-base offset-9 stores each use their own 0x67 reload, not the original 0xA9 word’s low byte.

### Intermediate effects remain visible

For write-observing storage, the publication-base offset-0x20 values 0x20, 0x2F, the loaded byte value, and 0x20 remain ordered events. Keeping only the final 0x20 is not equivalent.

A failing late access does not imply rollback. A dependency that does not return prevents subsequent operations from being reached through the represented path.
