# F-2c367f61ccd2

## Purpose

F-2c367f61ccd2 invokes an operation selected through the supplied record, conditionally obtains a four-byte value through dependency F-63a239e63e43, and returns whether a designated record field is nonzero.

The result is a normalized indicator: exactly 1 or 0. It is not the invoked operation’s return value, the dependency’s return value, or the contents of the designated field.

The supplied evidence establishes a control-flow and memory-access contract. It does not establish the application-level meaning of the record, its fields, or the value obtained from the dependency. Describing the designated field as a cached value or readiness indicator would be an interpretation, not an established fact.

## Behavior

### Initial operation

Every ordinary execution first resolves the indirect callable through the dispatch reference and invokes it with the record address.

This invocation occurs before the function tests the field at +12. A field that is already nonzero therefore does not bypass the callback.

The callback’s result controls whether the dependency path is eligible:

- A zero result skips the dependency path.
- Any nonzero result enables a test of the field at +12.

Positive and negative nonzero callback results have the same branch effect. No callback result is propagated directly to the caller.

The record is observed after the callback returns. Consequently, callback changes to the field at +12 affect the subsequent decision. Changes to the field at +4 also affect the dependency argument if that argument is later needed.

### Nonzero callback result

When the callback returns nonzero, the function reads the four-byte field at +12.

If that field is nonzero, the function immediately returns 1. It does not invoke F-63a239e63e43, does not read the field at +4 for that dependency call, and does not directly write the state field.

If the field is zero, the function reads the four-byte field at +4 and invokes F-63a239e63e43 with that value.

This dependency is invoked at most once by the visible function. The callback is likewise invoked once on an ordinary path.

### Dependency result

The dependency’s result is tested against zero.

If it is zero, this function performs no direct assignment to the field at +12. It proceeds to the final state-field test.

If it is nonzero, the result is used as an address-like base. The function reads four bytes at an offset of eight bytes from that base and assigns the read value to the field at +12 of the original record.

The source read precedes the destination write. The value is copied as a four-byte quantity without a visible transformation or nonzero check. A zero source value is copied just as a nonzero source value is.

This assignment occurs after the dependency returns. If the dependency itself changed the field at +12, the explicit assignment replaces that value, provided the accesses complete normally. The supplied evidence does not justify assuming that the dependency leaves the record or globals unchanged.

No source-storage release, ownership transfer, or retention of the dependency’s returned base is visible.

### Final state-field test

The function reaches a final read of the field at +12 in each of these cases:

- The callback returned zero.
- The callback returned nonzero, the subsequent state-field test found zero, and the dependency returned zero.
- The callback returned nonzero, the subsequent state-field test found zero, and the dependency returned nonzero, followed by the four-byte assignment.

The final read determines the result: nonzero yields 1; zero yields 0.

The early-return path described above is different: it returns 1 directly after its state-field test and does not perform this final read.

The callback’s zero result therefore does not imply a function result of 0. Similarly, a zero dependency result does not necessarily imply a function result of 0: the dependency may have changed the state field before returning.

## Side effects

### Direct memory activity

The visible function directly performs:

- Reads required to resolve the indirect callable.
- One callback invocation.
- One or two reads of the field at +12, depending on the path.
- A conditional read of the field at +4.
- A conditional invocation of F-63a239e63e43.
- A conditional four-byte read from dependency-provided storage at offset +8.
- A conditional four-byte write to the field at +12.

The write occurs only when all three conditions hold:

1. The callback returns nonzero.
2. The following test of the field at +12 finds zero.
3. F-63a239e63e43 returns nonzero.

The function does not clear the state field merely because the callback returns zero or the dependency returns zero.

## Acceptance examples

These examples are conditional on valid accesses and ordinary callee returns. Where necessary, they assume no concurrent mutation between the stated observations.

1. **A previously populated field does not suppress the callback.**  
   The field at +12 is initially nonzero. The callback is nevertheless invoked. If it returns nonzero and leaves the field nonzero, the function returns 1 without calling F-63a239e63e43.

2. **A zero callback result can still produce success.**  
   The callback returns zero, but the final state-field read is nonzero. The function returns 1. The dependency is not called.

3. **A zero callback result can produce failure.**  
   The callback returns zero and the final state-field read is zero. The function returns 0 without calling the dependency.

4. **Callback mutation selects the dependency argument.**  
   The callback changes the field at +4, returns nonzero, and leaves the field at +12 zero. The dependency receives the updated field value, not a value captured before the callback.

5. **A zero dependency result preserves indirect effects.**  
   The dependency is called and returns zero after changing the field at +12 to nonzero. This function makes no explicit assignment to that field and returns 1 from the final test.

6. **A nonzero dependency result does not guarantee success.**  
   The dependency returns a valid nonzero base whose four-byte value at +8 is zero. That zero is written to the field at +12. With no intervening mutation, the function returns 0.

7. **The explicit assignment replaces dependency-side state.**  
   The dependency changes the state field to one value but returns a valid base containing a different four-byte value at +8. The latter value is written to the state field and governs the final test absent another change.

8. **Results are normalized.**  
   If the relevant state-field read contains any nonzero four-byte pattern, the returned result is 1, not that pattern.
