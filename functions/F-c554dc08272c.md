# F-c554dc08272c

## Purpose

F-c554dc08272c traverses a pointer-linked structure using a comparison dependency, selects a candidate, and either publishes an existing-node address or invokes an insertion-like dependency and publishes its result.

The output comprises a four-byte value and a one-byte disposition:

- **Zero disposition:** the routine selected its existing-node publication path.
- **One disposition:** the insertion-like dependency returned and its result slot was copied to the output.

Disposition one does not establish successful insertion, allocation, or a valid returned node.

The structure resembles an ordered tree with a header and predecessor navigation. Those names describe inferred intent. The established contract is the offset-based traversal, dependency calls, temporary-state handling, and publication behavior below.

Addresses and links have the represented width of four bytes. The body does not establish a native eight-byte-pointer layout.

Comparison and boundary-dependency results are represented as 32-bit integers and tested only for zero versus nonzero. Their sign and nonzero magnitude do not affect the decisions made here.

### Header and node layout

| Byte offset | Access | Use |
|---|---|---|
| +0x00 | One-byte read | Zero/nonzero discriminator during candidate navigation. |

The routine passes the address at node +0x10. It does not load a four-byte payload from that offset itself.

### Output and completion

On normal completion:

1. The routine writes four bytes at the result destination.
2. It writes one byte at result offset +4.

The four-byte value is either a candidate address or the contents of an insertion-result temporary. The routine contains no explicit writes to result offsets +5 and above. No scalar return value is established.

These two output writes are separate and ordered, not atomic.

### Preconditions and limits

There are no explicit null, alignment, bounds, cycle, or link-consistency checks. Normal completion requires valid memory for every access actually taken, a writable five-byte output region, terminating traversals, and normally returning dependencies.

The header is dereferenced even when the search is empty. Null links terminate the search but are not generally protected during subsequent navigation.

Address offsets do not imply checked arithmetic. No overflow handling, address-wrap semantics, endianness, or portable calling convention is established.

Output aliasing with container or node storage is not rejected. Such aliasing can alter that storage during publication.

## Behavior

### Search initialization

The saved comparison result initially has a nonzero value.

The routine obtains the initial search node by reading the container’s header address and then the header’s +0x04 link. It separately reads the container’s header address to initialize the retained search anchor.

These source-level accesses are not a synchronized snapshot. If the header changes between them, the search origin and retained initial anchor need not come from the same header value.

For an empty search, the retained anchor is the header obtained by the latter read, and the saved comparison remains nonzero.

### Search and temporary initialization

The routine maintains two distinct four-byte temporaries:

- An **early-insertion result slot**.
- A **boundary/general-result slot**, used first for a boundary argument on some paths and later for general insertion output.

At the beginning of **each executed search iteration**, both slots are set to zero. These are not unconditional entry initializations. If no search iteration executes, neither slot has an established initialization at this stage.

For each non-null search node, F-bcefa5957e76 receives, in order:

1. Container address +0x19.
2. Supplied value.
3. Current node address +0x10.

After the call, the current node becomes the retained search anchor. The returned comparison selects the next link:

- Zero: read current node +0x0c.
- Nonzero: read current node +0x08.

The selected link is read after the comparison returns. Changes made by the dependency can therefore affect traversal.

A zero result is not an immediate match. Search continues until the selected link is null. The retained anchor is then the last visited node, or the separately obtained header if no node was visited.

### Mode decision

After search, the routine reads the mode byte at container +0x18.

A nonzero mode goes directly to general insertion. It skips the boundary dependency, candidate navigation, and final comparison.

A zero mode initializes a mutable candidate-address slot with the retained search anchor and continues with candidate checking.

### Boundary decision for a nonzero saved comparison

When the saved search comparison is nonzero, including its initial value after an empty search, the routine:

1. Reads the current container header address.
2. Reads that header’s four-byte +0x08 field into the boundary/general-result slot.
3. Calls F-d5d901ed9cd8 with the address of the candidate slot followed by the address of the boundary/general-result slot.

Both temporary addresses escape to this dependency. It may modify either slot. Its return does not establish that it stops accessing those addresses during subsequent calls while this invocation remains active.

If its return is nonzero, the routine takes early insertion. F-dd27e24bc327 receives:

1. Address of the early-insertion result slot.
2. Container address.
3. Integer zero.
4. Original retained search anchor.
5. Supplied value.

The fourth argument is not reloaded from the mutable candidate slot.

After this call returns, the routine copies the early-insertion result slot to the output and publishes disposition one.

The early-insertion result slot was explicitly zeroed only if at least one search iteration executed. An empty-search early-insertion path has no established initialization of that slot. There is no new zeroing immediately before this insertion call.

If F-d5d901ed9cd8 returns zero, navigation starts from the candidate slot’s then-current value.

### Candidate navigation

Navigation first reads the candidate’s discriminator byte at +0x00.

If that byte is zero, the routine follows candidate +0x04 and reads the reached object’s +0x04 link. If this second link equals the candidate, the candidate slot is replaced with the candidate’s +0x0c link.

Both conditions are required for this special case. A zero discriminator alone is insufficient.

Otherwise, ordinary navigation applies:

- If candidate +0x08 is non-null, follow that link, then follow successive +0x0c links until reaching a node whose +0x0c link is null. Store that terminal node in the candidate slot.
- If candidate +0x08 is null, follow the +0x04 upward link. Compare the reached parent’s +0x08 link with the current candidate, then replace the candidate with that parent. Continue upward while the comparison was equal.

The upward replacement happens even on the terminating unequal comparison. The resulting candidate is that step’s parent, not the child from which the step began.

No null-parent guard or cycle detection is present.

When the saved search comparison is zero, the boundary dependency and all navigation are skipped. The candidate initially remains the retained search anchor.

### Final comparison and post-call candidate read

All zero-mode paths that did not take early insertion reach this stage.

The routine explicitly resets the boundary/general-result slot to zero, after any candidate navigation and before the final comparison. It also clears another four-byte scratch location whose address is not passed to a dependency in the supplied body.

F-bcefa5957e76 then receives:

1. Container address +0x19.
2. Address at the candidate’s current value +0x10.
3. Supplied value.

The operand order is reversed relative to search.

The candidate value used to construct the second argument is a **pre-call** value. If the comparison returns zero, the routine reads the candidate slot **after the call** and publishes that value with disposition zero.

On paths that called F-d5d901ed9cd8, the candidate slot’s address has escaped. The final comparison dependency is not established to preserve it: it could access that slot through an address retained or communicated by an earlier dependency. Consequently, the published address can differ from the address whose +0x10 location was supplied to the final comparison.

If the comparison returns nonzero, the routine proceeds to general insertion.

The zero reset of the boundary/general-result slot is also not an unconditional guarantee about its later contents. On paths that exposed its address to F-d5d901ed9cd8, the final comparison could modify it through that retained address before general insertion starts.

### General insertion

F-dd27e24bc327 receives:

1. Address of the boundary/general-result slot.
2. Container address.
3. Integer zero.
4. Original retained search anchor.
5. Supplied value.

Neither navigation nor a later mutation of the candidate slot substitutes a different fourth argument.

After the dependency returns, the routine copies the general-result slot to the output and publishes disposition one.

Initialization depends on the route:

| Route | Established initialization before insertion |
|---|---|
| Nonzero mode, nonempty search | Slot zeroed at the start of each search iteration; no further direct initialization before insertion. |
| Nonzero mode, empty search | No established initialization. |
| Zero mode reaching a nonzero final comparison | Slot explicitly reset to zero before that comparison. Its address may already have escaped, allowing the comparison to change it before insertion. |

Thus, an insertion dependency that leaves its result slot untouched does not universally produce a zero result.

## Side effects

### Direct writes and observable ordering

Outside dependency calls, direct caller-visible writes are confined to the four-byte output and the subsequent disposition byte. The routine also writes temporary storage.

There are no direct container-link updates. Allocation, insertion, balancing, count changes, and payload ownership changes, if any, belong to dependencies.

Relevant ordering includes:

- Both result temporaries are zeroed before each search comparison.
- Search links are read after the corresponding comparison returns.
- Mode is read after search.
- The boundary value is loaded before F-d5d901ed9cd8.
- Navigation occurs after that dependency returns.
- The boundary/general-result slot is reset after navigation and before final comparison.
- Existing-node publication reads the candidate after final comparison.
- Insertion-result publication reads the result slot after insertion returns.
- No dependency call occurs between the two output writes.

These are source-level ordering facts, not claims about volatile accesses, exact machine-read counts, or concurrency safety.

### Escaped storage and lifetime

F-d5d901ed9cd8 receives addresses of the candidate slot and boundary/general-result slot. F-dd27e24bc327 receives an insertion-result slot address.

The supplied body does not establish non-retention. Subsequent dependencies may affect escaped storage if they obtain and use those addresses. Such access is relevant while the containing invocation remains active; no validity after its return is promised.

No dependency is assumed to preserve globals, container fields, links, supplied data, or escaped temporaries.

### Ownership and errors

The routine itself neither allocates nor frees nodes and does not directly copy a payload.

Ownership of the supplied value is unresolved. Forwarding it does not establish borrowing, retention, transfer, copying, or release.

There is no explicit error result, rollback, exception handling, or success check:

- Disposition one records the insertion-call path, not insertion success.
- An untouched result slot can publish a known zero only when its initialization and preservation support that conclusion.
- An empty-search insertion path can read a result slot with no established initialization.
- The behavior of consuming such uninitialized storage is not assigned a defined result by this contract.
- Invalid memory, nontermination, and partial dependency effects are not recovered here.

## Acceptance examples

These are conditional static scenarios, not executed tests. Memory must be valid, dependencies must return normally, and stated preservation conditions must hold.

### Empty search with nonzero mode

If the initial search link is null and mode is nonzero:

- No search comparison occurs.
- Neither result temporary is initialized by a search iteration.
- General insertion receives the retained header as its fourth argument.
- If insertion writes a four-byte value, that value is published with disposition one.
- If insertion leaves its slot untouched, zero is not guaranteed; no four-byte result is established.

### Empty search with an early insertion decision

If search is empty, mode is zero, and F-d5d901ed9cd8 returns nonzero:

- The boundary slot is populated from the currently read header’s +0x08 field.
- Early insertion receives the original retained header, regardless of candidate-slot mutation.
- The separate early-result slot has no established initialization.
- An untouched early-result slot does not establish a zero output.

### Nonempty search with nonzero mode

If search ends at node A and mode is nonzero:

- Boundary processing and final comparison are skipped.
- General insertion receives A as its fourth argument.
- The general-result slot was zeroed before the last search comparison.
- If intervening effects preserve that zero and insertion leaves the slot untouched, zero is published with disposition one.

### Existing-node selection without navigation

If the final search comparison is zero, mode is zero, and final comparison returns zero:

- F-d5d901ed9cd8 and navigation are skipped.
- Final comparison receives candidate +0x10 before the supplied value.
- The post-comparison candidate-slot value is published with disposition zero.
- No insertion dependency is called.

### Downward navigation with candidate preservation

Suppose boundary processing returns zero, ordinary navigation follows +0x08 to B, and B’s +0x0c chain ends at C.

The final comparison operand is C +0x10. If that comparison returns zero **and preserves the candidate slot as C**, C is published with disposition zero.

If the comparison instead changes the escaped candidate slot to D, a zero return causes D—not C—to be published.

### Navigation does not change the insertion anchor

If navigation selects C but final comparison returns nonzero, general insertion still receives the original search anchor A.

If the final comparison also writes value V into the escaped general-result slot, and insertion leaves it untouched, V is published with disposition one despite the earlier zero reset.

### Upward and special-node boundaries

If ordinary navigation has a null +0x08 link and the first parent’s +0x08 link differs from the current candidate, that parent becomes the final-comparison candidate.

Separately, if a candidate has a zero discriminator and its upward-linked object’s +0x04 link points back to it, navigation selects the candidate’s +0x0c link instead of ordinary navigation.

In either scenario, publication after a zero final comparison uses the candidate slot’s post-call value.

## Uncertainties

### Inferred intent

The header, directional comparisons, and candidate adjustment are consistent with ordered-tree insertion supporting a duplicate-sensitive mode.

The +0x08 and +0x0c links resemble left and right links; +0x04 resembles a parent link in nodes and root link in the header. These interpretations do not replace the established offset rules.
