# F-c92f16c82728

## Purpose

F-c92f16c82728 performs memory writes and dependency calls consistent with preparing FAT12, FAT16, or FAT32 filesystem metadata. It modifies a context, a boot-record-like buffer, and buffers obtained through allocation-related dependencies.

The filesystem interpretation is inferred from offsets, signatures, and format-selection values. Established behavior consists of the visible accesses, arithmetic, branches, and call ordering. Return value 1 does not establish filesystem validity or persistence.

Two external operations resemble transfer and clearing operations, but their implementations are unavailable. This contract establishes their arguments and ordering, not that they copy or clear memory. Any resulting buffer contents attributed to those operations require an explicit additional dependency contract.

## Interface

The function accepts a 32-bit context address and returns a 32-bit value:

- **1:** the directory path and any subsequently selected FAT32 information path reach their successful endpoint.
- **0:** an explicit failure path is reached.
- **No normal return:** possible through invalid memory access, dependency behavior, or the designated nonreturning dependency.
- **Nontermination:** possible in candidate selection.

There is no visible context-address validation.

### Memory and lifetime conditions

Safe execution requires valid addresses for every reached direct access and satisfaction of each dependency’s actual preconditions. Stable boot and information buffers must accommodate direct accesses through offset `0x1FF`. A labeled directory requires direct access through offset `0x1F`.

No nonaliasing guarantee is supplied. Buffers, descriptors, context fields, and global storage may overlap. Consequently, even direct stores can affect later pointer or value reads. For example, serialization of context `0x40C` rereads both that field and the boot pointer between byte stores; it is not necessarily serialization of one snapshot into one buffer.

Descriptor ownership, data ownership, release obligations, and lifetimes are unresolved. No general rollback is present.

## Behavior

### Access and arithmetic conventions

Ordinary arithmetic results are 32-bit, with truncation modulo \(2^{32}\), except for the explicitly described wide product. Shifts used to extract unsigned quantities are logical. No overflow checks are visible.

Native 16- and 32-bit stores are distinguished from explicit byte stores; their byte representation depends on target byte order.

**B**, the initial total **T**, the search bound, the product words, and calculated candidates and extents are retained values. Context fields are not generally snapshots. Descriptions below identify important captured pointers; otherwise, separate direct boot-buffer accesses reload context `0x450`.

Dependencies are not assumed to preserve context, global storage, or referenced memory. The source does not establish operand-evaluation order within individual expressions.

### Initial boot-record preparation

After obtaining **B**, the function reads two global 32-bit words into adjacent local storage. It invokes F-unmapped-01 with boot pointer plus `0x03`, that local storage’s address, and length 8. The global values are unknown and not established immutable; the call does not itself prove that eight bytes reach the boot buffer.

Next:

- If the current context `0x444` is nonzero, its low byte is written at boot offset `0x0D`.
- The root count at `0x448` is read. If nonzero and the selector then read is not 32, its low byte is written at `0x11`; the context root count is reread for the byte written at `0x12`.
- Otherwise, boot bytes `0x11` and `0x12`, accessed through separately loaded boot pointers, form an unsigned little-endian count stored at context `0x448`.

Four byte stores follow at boot offsets `0x43–0x46`, extracting successive bytes from separate reads of context `0x40C`.

F-585268c94aea is called with boot pointer plus `0x47`, context address plus `0x410`, and 11. After this call, a global source-pointer value is obtained for F-unmapped-01, whose destination is the then-current boot pointer and length is 3. Neither the global pointer nor its referenced bytes are established immutable.

The function then:

1. Writes the low two bytes of retained **B** at boot `0x0B–0x0C`.
2. Reads the selector and stores a native 16-bit reserved count at `0x0E`: 32 for selector 32, otherwise 1.
3. Writes the low byte of current context `0x428` at `0x10`.
4. Reads context `0x420` once into retained **T**.

A signed comparison of **T** against 65,536 selects its initial representation:

- Below 65,536: write its low two bytes at `0x13–0x14`, then store native 32-bit zero at `0x20`.
- Otherwise: write zero bytes at `0x13–0x14`, then store **T** at `0x20`.

Negative signed totals take the first branch and are not rejected. Context `0x41C` is then stored natively at boot `0x1C`; explicit bytes `55 AA` follow at `0x1FE–0x1FF`.

### Available size and candidate search

The available-size value is retained **T** minus the unsigned 16-bit reserved field read through the current boot pointer. If the current selector is not 32, F-30320c560ef4 receives current context `0x448` shifted left five bits and **B**; its result is subtracted.

The search bound is then read from context `0x444` and retained. Zero becomes 128. A nonzero bound is also written, low byte only, at boot `0x0D`.

The available-size value and **B** produce retained low and high product words. The low word is the unsigned product’s low word. The high word is its unsigned high word plus either zero or negative **B**, selected by the available-size sign bit. This is consistent with sign-extending the available-size value before multiplication by unsigned **B**.

Each iteration calculates all three candidates in order. There is **no iteration-wide cluster-size snapshot**.

**12-bit candidate**

The boot pointer and its byte `0x0D` are freshly read for F-7071f254f784. That dependency receives the retained product words, wrapped **B × byte + 3**, and zero. Its result is **C12**.

F-30320c560ef4 receives wrapped **3 × C12 + 1**, logically shifted right one, and **B**. Its result is retained extent **E12**.

F-d7be9cfb4000 then receives wrapped **B × E12 × 2** and 3. After these calls, a global 32-bit cap is read. The capacity is limited by that cap, and **C12** becomes zero if the limited unsigned capacity is below **C12**. The cap’s value and immutability are unknown.

**16-bit candidate**

The boot pointer and cluster byte are read again, after the preceding calls. F-7071f254f784 receives the product words, wrapped **B × this byte + 4**, and zero, yielding **C16**.

F-30320c560ef4 receives **C16** shifted left one and **B**, yielding **E16**. Wrapped **B × E16**, logically shifted right one, is limited by a second global cap read after that dependency. **C16** becomes zero when the limited capacity is smaller.

**32-bit candidate**

A third fresh boot-pointer and byte read supplies the next F-7071f254f784 call. Its denominator-like argument is wrapped **B × this byte + 4**. Its arguments need not match those of the 16-bit call, and matching arguments would not establish matching results.

Its result **C32**, shifted left two, and **B** are passed to F-30320c560ef4, yielding **E32**.

The alignment flag is read afterward. If nonzero, the low four bits of **E32** are cleared, and **C32** becomes wrapped **B × (E32 shifted right two)**. Wrapped **B × E32**, logically shifted right two, is capped at literal `0x0FFFFFF6`; a smaller capacity invalidates **C32** by replacing it with zero.

### Selection and loop exit

Selection checks occur after all three candidates:

- Nonzero **C12** accepts current selector 12, or invokes automatic selection when a subsequent selector read is zero.
- Nonzero **C16** similarly accepts 16 or automatic selection.
- Nonzero **C32** accepts current selector 32.

Automatic selection writes 16 only if unsigned **C12 < C16**; otherwise it writes 12. It never chooses 32.

If no candidate is accepted, the function freshly reads the boot pointer and cluster byte **D**, after candidate calculations and selection checks. It writes the low byte of **2 × D** through another boot-pointer load. Continuation depends on whether **2 × (D AND 127)** is at most the retained **signed** search bound.

The write precedes that decision. Thus exhaustion may leave a byte different from every byte used for candidate calculation. A zero byte and nonnegative bound can sustain an unending loop when no candidate is accepted.

On ordinary exhaustion, a current zero selector still triggers automatic selection, including when both relevant candidates are zero.

- Captured cluster byte times the limited result;

## Acceptance examples

These are conditional static expectations, not executed tests.

1. **Total boundary:** If **T** is read as 65,535, the initial total branch requests bytes `FF FF` and native zero at `0x20`. At 65,536 it requests two zero bytes and native 65,536. One-buffer results require stable, noninterfering destination storage.

2. **Root precedence:** If root count is nonzero and selector is 32 at the relevant reads, and the two boot-byte reads yield `34` and `12`, context `0x448` receives `0x1234`.

3. **Separate candidate reads:** If the three cluster-byte reads yield 1, 2, and 4 with **B** equal to 512, the candidate calls receive respective third arguments 515, 1028, and 2052.

4. **Automatic tie:** When automatic selection is reached with retained equal nonzero **C12** and **C16**, selector 12 is written.

5. **Failure cleanup:** A null returned directory descriptor and current nonzero `0x46C` invoke the cleanup calls. A current zero `0x46C` instead reaches return zero.

6. **Final information bytes:** With stable, noninterfering information storage, the calculated bytes at `0x1E8–0x1EB` are overwritten by `FF FF FF FF`.

7. **Small allocation:** If the information allocation provides exactly **B < 512** accessible bytes, stable-pointer direct accesses through `0x1FF` exceed it. A full 512-byte transfer would additionally exceed it **if** F-unmapped-01 has ordinary copy semantics.
