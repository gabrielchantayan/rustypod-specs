# F-1bb8f43e914f

## Purpose

F-1bb8f43e914f conditionally computes two shared metrics, prepares temporary configuration storage, and invokes an ordered sequence of allocation-request and construction dependencies. It returns no explicit result or constructed-object handle.

Mode selects the construction branch. Input flag bit zero independently controls two early selection writes and a later optional construction call. These three flag observations occur at different times.

**Established static evidence:** explicit reads, writes, branch conditions, dependency arguments, storage offsets, and call ordering described below.

**Inferred intent:** the metrics and configuration records appear to support positioned visual elements. Allocation and construction terminology describes apparent call-site roles, not verified dependency implementations.

An unidentified external dependency receives destination, source, and length arguments resembling block copying. Exact copying is an explicit assumption where used below; its implementation and contract were not supplied.

The visible representation uses 8-bit bytes, signed 16-bit metric components, and 32-bit words and addresses. No byte-order interpretation beyond the supplied typed accesses is established.

Each construction call receives, in order:

1. The immediately preceding allocation-request result.
2. A 32-bit zero.
3. Context A.
4. Context B.
5. An address of invocation-local configuration storage.

Neither allocation-request results nor construction results are checked. Construction results are unused.

Ordinary completion requires readable storage for the explicit accesses and writable storage for the explicit writes. Temporary configuration addresses are not guaranteed valid after return. Retention, ownership transfer, and copying by callees are unknown. The visible routine releases no storage.

## Behavior

### Shared-state selection and initialization

The routine first captures a 32-bit address from the global state-base slot. This captured address is used for subsequent metric stores and later metric reads.

The initialization condition separately reads the state-base global again and examines the signed 32-bit field at offset `0x1c` of that separately obtained address. Consequently, the address tested is not established to equal the address used for subsequent metric accesses if the global changes between reads.

If the tested field is nonzero, both initialization sequences are skipped. Offset `0x20` has no independent initialization check.

If the tested field is zero, the following sequence occurs:

1. F-9d0ecc5f6adf produces one opaque value.
2. F-ed4b1fd8953e receives the input-object address and the first global lookup key.
3. The resolution-parameter global is read and its value captured for the **second** resolver call.
4. A 32-bit record address is loaded from offset `0x08` of the first lookup result.
5. The record’s first 32-bit word is read for F-5710a8628cba. That call receives the opaque value from step 1, a **separate fresh read** of the resolution-parameter global, and that first word.
6. **After F-5710a8628cba returns**, the record’s second 32-bit word and its byte at offset `0x0c` are read while preparing F-59c1430f85c2. The second word is masked to its low 16 bits; the byte is supplied as an 8-bit value.
7. F-59c1430f85c2 receives temporary output storage, the resolver result, the masked value, and the byte.
8. The first 32-bit output word has bit zero cleared. The resulting word is treated as an address.
9. Signed 16-bit values at offsets `0x52` and `0x54` of that address are sign-extended and added. The signed 32-bit sum is stored at offset `0x1c` of the initially captured state address.

The later record reads in step 6 are not snapshots taken before resolution. F-5710a8628cba may modify the referenced record; such changes can affect the arguments subsequently supplied to F-59c1430f85c2. The relative evaluation order among arguments to one call is not independently established.

After the first metric store:

1. F-ed4b1fd8953e receives the input object and the second global lookup key.
2. A record address is loaded from offset `0x08` of that lookup result.
3. F-5710a8628cba receives the original opaque value, the resolution parameter captured before the first record-address load, and the second record’s first word.
4. After that resolver returns, the second record’s low-16-bit word value and byte at offset `0x0c` are read for F-59c1430f85c2.
5. The same output-word masking and signed metric extraction are performed.
6. The sum is stored at offset `0x20` of the initially captured state address.

No second opaque-value acquisition occurs. No resolution-parameter global reload supplies the second resolver call.

Each metric sum lies between `−65536` and `65534`; adding the two sign-extended 16-bit components cannot overflow signed 32-bit storage. Only address bit zero is cleared. The bit’s meaning and the decoded object’s ownership are unknown.

There is no rollback between metric writes. A computed first metric of zero can cause another initialization attempt on a later invocation. A nonzero tested first metric suppresses initialization regardless of the second metric’s value.

### Initial configuration preparation

Seven calls to the unidentified external dependency occur before the first allocation request. Each supplies a distinct invocation-local destination, a corresponding global template-source value, and length `0x68`—104 bytes.

The descriptions below use semantic record labels solely to distinguish these destinations. They do not establish field meanings for unspecified bytes.

**First selected record**

1. The external dependency receives this destination, the first template source, and length 104.
2. The selection-table base global is read and captured for the second record’s selection.
3. Input flag bit zero is read. Index 1 is chosen only if that bit is set and mode equals exactly `1`; otherwise index 0 is chosen.
4. The table-base global is read **again** for the first entry access.
5. A 32-bit word at that fresh base plus four times the selected index is written to destination offset `0x48`.

**Second selected record**

1. The external dependency receives a second destination, a different template source, and length 104.
2. Input flag bit zero is read again, using the same index rule.
3. The selected 32-bit table word is read using the base captured after the first external call.
4. That word is written to this destination’s offset `0x48`.

These are distinct table-base observations. Equal indices do not guarantee equal values: the bases or table contents may differ. The two flag reads may also differ, including because the intervening external call has unknown effects.

**First positioned record**

The routine next reads, in order:

1. Signed 32-bit metric at captured state address plus `0x1c`.
2. Signed 32-bit metric at captured state address plus `0x20`.
3. Signed 32-bit input extent at offset `0x08`.

These are fresh reads, not guaranteed reuse of initialization results.

The default configuration global is then read **for every mode**. If mode equals exactly `1`, the alternate configuration global is read afterward and replaces the selected value. Mode one therefore does not skip the default-global read.

The external dependency receives the first positioned destination, its template source, and length 104. After that call returns, the routine writes:

| Offset | Width | Explicit value |
|---|---:|---|
| `0x3c` | 32 bits | Computed position |

For intermediate arithmetic within signed 32-bit range, the position is:

\[
m_1+\operatorname{trunc}_{0}
\left(\frac{e-(m_1+m_2)-2}{2}\right)

Here \(m_1\), \(m_2\), and \(e\) are the three values read above. Division truncates toward zero. Overflow behavior is not established; the expression must not be replaced by unqualified mathematical arithmetic or assumed wrapping arithmetic outside that range.

Three further external calls supply the optional-final, common, and nonzero-mode destinations, respectively, each with its corresponding template source and length 104.

## Side effects

Direct nonlocal writes comprise the two metric stores on the initialization path. Other explicit writes target invocation-local storage, some of which is passed to dependencies.

Allocation-request sizes, in call order, are:

- **Zero mode:** `0x230`, `0x230`, `0x220`, `0xa4`, `0x230`, `0x220`.
- **Nonzero mode:** `0x230`, `0x230`, global size, `0x230`, `0x220`.

The final flag-dependent sequence appends one `0x230` request. Thus normal completion reaches six allocation/construction pairs for zero mode and five for nonzero mode, plus the optional pair.

Dependencies may affect input storage, globals, or records they receive, subject to their unavailable contracts. No preservation or ownership guarantee is inferred. Later reads occur against whatever state then exists, while explicitly captured scalar arguments are reused where described.

There is no visible success test, compensation, destruction, synchronization, or transactional rollback. This does not establish leaks, successful construction, or thread safety.

## Acceptance examples

These are conditional static consequences, not executed tests. They assume the stated accesses and calls complete normally.

1. **Distinct state-base reads.** If the initial capture yields address A but the condition’s separate global read yields address B, the condition examines B plus `0x1c`. Initialization stores and later metric reads use A.

2. **Resolver mutation.** If F-5710a8628cba changes its referenced record’s second word or byte at `0x0c` before returning, the following F-59c1430f85c2 arguments use the post-call reads, not pre-resolver snapshots.

3. **Distinct resolution parameters.** If the captured parameter is X and the first resolver’s separate global read yields Y, the first resolver receives Y and the second receives X.

4. **Distinct table bases.** If the saved table base is A and the first entry access reloads B, the first selection reads B plus its index displacement; the second reads A plus its independently selected displacement.

5. **Mode one.** With mode `1` and set bits at both early flag reads, both selection writes use index 1. The default configuration global is still read before the alternate value is selected. The nonzero branch runs.

6. **Other nonzero mode.** With mode `2`, both selection writes use index 0 regardless of flag value. The default configuration value is selected, and the nonzero branch runs. A set final flag still enables the optional call.

7. **Signed arithmetic.** Metric components `−3` and `8` produce metric `5`. With metrics `10` and `20` and extent `25`, the positioning numerator is `−7`; division yields `−3`, producing position `7`.

8. **Late flag change.** Clear early flag observations cause entry-0 selection writes. If the final observation is set, the optional sequence runs. The earlier record contents need not remain unchanged after dependencies receive their addresses.

9. **Conditional extended contents.** If the external dependency performs an exact 104-byte copy and the positioned source still contains position `7`, the extended destination receives that value at `0x3c`. Without those conditions, preservation of `7` is not established.

10. **Partial initialization.** If the first metric store completes but the second lookup cannot complete, no visible rollback restores the first metric. Further behavior depends on the failure mechanism.
