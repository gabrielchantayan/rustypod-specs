# F-60943de1b32c

## Purpose

F-60943de1b32c selects among three operation paths using byte-sized flags in a caller-supplied object:

- **Temporary-storage path:** obtains a value from a size-taking dependency, queries another value, installs the obtained value through a state-setting dependency, performs an operation involving temporary objects, then invokes release-like, restoration-like, and cleanup dependencies.
- **Queried-storage path:** performs a similar temporary-object operation using a queried value, without explicitly obtaining temporary storage or invoking the state-setting dependency.
- **Fallback path:** invokes a fixed-mask operation, an optional hook, and two further dependencies.

If no path is enabled, it returns without invoking a dependency.

Rectangle processing, graphics operations, allocation, and state restoration are **inferred intent**. The established contract consists of field accesses, calculations, dependency arguments, call ordering, and temporary-address use. It does not establish that a dependency clears a surface, copies pixels, allocates memory, or succeeds.

## Interface

The function accepts one address-bearing argument identifying a **caller-supplied object**. The supplied representation uses a 32-bit argument and 32-bit address arithmetic.

**Ownership of the referenced storage is unspecified.** Supplying the address does not establish that the caller owns the object, and caller ownership is not a precondition. The function contains no explicit acquisition, transfer, or release of ownership of that object.

### External state and temporary storage

A 32-bit external descriptor is read at entry, including when the function subsequently returns without dependency calls. Both rectangle-related paths later pass that captured value to F-7627a10679c2.

A separate external configuration value is read when configuring the temporary context. It is not captured with the entry descriptor.

Fallback obtains two arguments by dereferencing externally stored addresses after its preceding dependency calls. Argument positions are established, but relative evaluation order of those argument-producing reads is not.

Temporary storage includes:

- Four-component rectangle records, with 32 bits per component.
- A 32-bit query-output slot on each rectangle-related path.
- A region of 184 bytes passed to F-7627a10679c2.
- A region of 68 bytes passed to F-1ade66241a82.
- Context storage passed to several dependencies.

The temporary-storage path provides a context region represented as fourteen 32-bit words. The queried-storage path uses a different temporary address whose complete context extent is not established. These observations do not establish internal object layouts or safe dependency access bounds.

## Behavior

### Selection and access precedence

The external descriptor is captured before branch selection. Forming the interior address at `0x80` does not itself require reading its contents.

Selection has the following precedence:

1. Read `0xB4`. If nonzero, read `0xB9`. A zero suppression byte selects the temporary-storage path immediately.
2. If that path was not selected, read `0xB5`. If nonzero, read `0xB9`. A zero suppression byte selects the queried-storage path.
3. Otherwise, read `0xBA`. Zero causes immediate return; nonzero selects fallback.

Consequently:

- A selected temporary-storage path does not require reads of `0xB5` or `0xBA`.
- When both enabling flags are zero, `0xB9` need not be read.
- `0xB9` can be read twice if both enabling flags are nonzero and the first suppression test rejects the temporary-storage path.
- The hook-control field at `0xAC` is not read on the immediate-return path.

No dependency runs between the selection reads. The function provides no synchronization or atomic snapshot guarantee. Selection is not reconsidered after dependency calls begin.

### Temporary-storage path

**Initial geometry and state selection.** Before any dependency call, the function calculates width and height from the object’s rectangle fields and retains both differences. It calls F-d33f6d597e5d with height × width × 2 and retains the returned 32-bit value.

Next, F-3de7a0e08c4b receives the address of a 32-bit output slot. After that call, F-0065c3d0f277 receives the value returned by F-d33f6d597e5d. The query therefore occurs after the size-taking call but before installation of its result.

**Fixed-mask operation and hook.** F-07fdf92fa582 receives `0x4000`. Only after it returns does the function read the 32-bit field at `0xAC`; a nonzero value causes a call to F-5f01813cb7ad with no explicit arguments.

**Context and rectangle preparation.** F-a4c26c2b4842 receives the context storage address. F-7fa874cbac7a then receives the supplied object and that context.

After these calls, the function constructs a temporary rectangle containing zero, zero, the retained width, and the retained height. F-ccb5d9751852 receives the context and the external configuration value read at this stage. F-92df7be8afd3 then receives the context and the zero-origin rectangle.

The function subsequently copies the object’s current rectangle fields into another temporary record, in increasing field-offset order: `0x80`, `0x84`, `0x88`, `0x8C`. This is a later observation than the initial dimension calculations.

**Opaque-object operation.** F-7627a10679c2 receives, in argument order:

- The 184-byte temporary region’s address.
- The copied rectangle’s address.
- The retained return value from F-d33f6d597e5d.
- Retained height × 2.
- `0x10`.
- The descriptor captured at entry.
- Four trailing zero values.

F-1ade66241a82 then receives the 68-byte temporary region’s address and the 184-byte region’s address.

F-b774eb6cb163 receives the context, the 68-byte region, the address at object offset `0x80` twice, `0xFF`, and zero. The two rectangle-address arguments alias exactly. Neither points to the copied temporary rectangle.

**Release-like and cleanup calls.** On ordinary return from the preceding dependencies, the remaining order is:

1. F-5e3309c9d083 receives the retained size-taking dependency result.
2. F-0065c3d0f277 receives the earlier query output.
3. F-282eebd7c413 receives the 68-byte region.
4. F-03144a4f049b receives the 184-byte region.
5. F-282eebd7c413 receives the context.

The function then returns.

Initial dimensions, the later rectangle copy, and contents observed through the aliased object addresses need not agree. Dependencies can potentially modify the supplied object between those observations.

### Queried-storage path

**Early geometry.** Before any dependency call, the function calculates width and height and constructs a zero-origin rectangle containing zero, zero, width, and height.

**Context preparation.** F-07fdf92fa582 receives `0x4000`. The function then reads `0xAC` and conditionally invokes F-5f01813cb7ad.

Next, the context is passed to F-a4c26c2b4842, followed by F-7fa874cbac7a with the supplied object and context. F-ccb5d9751852 receives the context and the external configuration value read at that stage. F-92df7be8afd3 then receives the context and the previously constructed zero-origin rectangle.

**Late geometry and query.** After those calls, the function copies the current object rectangle into a separate temporary record, reading `0x80`, `0x84`, `0x88`, and `0x8C` in that order. F-3de7a0e08c4b then receives a 32-bit output address.

After the query returns, height is calculated again from the object’s current `0x8C` and `0x84` fields. Twice this newly calculated height is passed to F-7627a10679c2.

That call otherwise receives the same argument arrangement as on the temporary-storage path: 184-byte region, copied rectangle, data-like value, doubled height, `0x10`, entry descriptor, and four zeros. Here the data-like value is the query output.

**Operation and cleanup.** F-1ade66241a82 receives the 68-byte region and the 184-byte region. F-b774eb6cb163 then receives the context, 68-byte region, the object’s `0x80` address twice, `0xFF`, and zero.

Cleanup calls occur in this order:

1. F-282eebd7c413 with the 68-byte region.
2. F-03144a4f049b with the 184-byte region.
3. F-282eebd7c413 with the context.

There is no explicit call to F-d33f6d597e5d, F-5e3309c9d083, or F-0065c3d0f277 on this path.

Three geometry observations remain distinct: the pre-call zero-origin dimensions, the post-configuration rectangle copy, and the post-query doubled height.

### Fallback path

Fallback invokes F-07fdf92fa582 with `0x4000`, then reads `0xAC` and conditionally calls F-5f01813cb7ad.

F-0741a8736e1f runs next with no explicit arguments. Finally, F-011cefb8445c receives the two externally dereferenced values in their established argument positions, and the function returns.

Those external argument reads occur after F-0741a8736e1f. Their relative evaluation order is not established. No rectangle-field read, temporary context construction, storage acquisition, or cleanup call is explicit on this path.

### Arithmetic and failure handling

Rectangle components and the displayed arithmetic are 32-bit. No wider intermediate is shown for subtraction, multiplication, or doubling.

The size expression is height × width × 2. The stride-like argument is height × 2, **not width × 2**.

There are no local checks for negative dimensions, zero dimensions, arithmetic overflow, allocation-like failure, unwritten query outputs, or dependency failure. No returned status controls continuation.

The representation alone does not establish overflow behavior. Neither unbounded mathematical arithmetic nor guaranteed modulo-\(2^{32}\) behavior may be assumed for overflowing cases.

The query-output slots have no visible initialization before their query calls. If a query does not write its slot, the function still has no local failure branch before subsequent use; a defined value for that use is not established.

## Side effects

The function performs no explicit stores into the supplied object. It does pass the object address and interior rectangle addresses to dependencies, which may write through them.

Temporary records receive explicit rectangle values, and dependencies receive writable-looking temporary addresses. Actual dependency writes, retained references, and global-state changes are unknown.

The temporary-storage path invokes its release-like dependency before the restoration-like call and before wrapper, opaque-object, and context cleanup. This ordering does not prove correct ownership management:

- The obtained value’s nature and ownership are unspecified.
- Temporary objects might retain it; whether their cleanup accesses it is unknown.
- Reinstalling a queried value does not prove restoration of all affected state.
- Intervening dependencies are not established to preserve globals.
- No explicit cleanup path is shown for abnormal dependency termination.

Temporary storage has invocation-local lifetime. The function supplies no explicit lifetime-extension mechanism. Whether dependencies retain temporary addresses is unresolved.

Neither the supplied object nor its storage is established to be owned by the caller, by this function, or by any dependency.

## Acceptance examples

These are conditional static criteria, not reported executions. Required valid accesses and ordinary dependency returns are assumed.

1. **Immediate return:** With `0xB4`, `0xB5`, and `0xBA` zero, no dependency is called. The external descriptor is still captured; rectangle fields and `0xAC` need not be read.

2. **First-path priority:** With `0xB4` nonzero and `0xB9` zero when tested, the temporary-storage path runs without requiring reads of `0xB5` or `0xBA`.

3. **Second-path selection:** With `0xB4` zero, `0xB5` nonzero, and `0xB9` zero, the queried-storage path runs without explicit size-taking, release-like, or state-setting calls.

4. **Suppression:** With both enabling flags nonzero and both suppression observations nonzero, `0xBA` determines fallback versus immediate return.

5. **Representable geometry:** Rectangle values 10, 20, 14, and 23 produce width 4 and height 3. The temporary-storage size argument is 24, doubled-height argument is 6, and zero-origin rectangle is 0, 0, 4, 3. A later copied rectangle remains unchanged only if intervening behavior leaves those fields unchanged.

6. **Late hook decision:** If F-07fdf92fa582 changes `0xAC` from zero to nonzero, the hook runs. The field is tested after that call.

7. **Separate geometry observations:** On the queried-storage path, a query-time change to the object’s height can change the doubled-height argument without changing the rectangle already copied before the query.

8. **Zero dimensions:** A representable zero width or height still causes the temporary-storage path to call F-d33f6d597e5d with zero. There is no local empty-rectangle shortcut.

9. **Zero returned value:** If F-d33f6d597e5d returns zero, it is passed onward and eventually to F-5e3309c9d083 if intervening calls return. Whether zero is valid remains unknown.

10. **Ownership-neutral invocation:** Storage made validly accessible by an arrangement other than caller ownership is not rejected by any visible ownership check. Dependency-specific requirements remain unresolved; caller ownership must not be added as a requirement.
