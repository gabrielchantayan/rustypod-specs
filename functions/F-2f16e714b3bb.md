# F-2f16e714b3bb

## Purpose

F-2f16e714b3bb interprets a byte range as a signed numeric quantity with an optional decimal fraction and exponent, applies a caller-supplied decimal adjustment, and returns a 32-bit result. On normal completion, it publishes the address at which interpretation stopped through the caller’s cursor slot.

The visible processing combines:

- An optional leading ASCII sign.
- An integer contribution obtained from F-9239ebb6c943, except when the post-sign byte is a decimal point.
- A table-defined fractional contribution.
- An optional exponent introduced by ASCII `e` or `E`.
- Repeated decimal scaling.
- Optional fractional conversion through F-73d099a86adb.

The integer dependency’s result is shifted left by 16 bits. Together with the separate numerator and denominator, this suggests a fixed-point representation with 16 fractional bits. That is **inferred intent**, not a complete numeric contract: dependency implementations, rounding rules, external data, and arithmetic-overflow behavior are unavailable.

This function does not independently establish a conventional decimal grammar. In particular, integer syntax and errors belong to an unknown dependency, while fractional digit recognition depends on an external table.

## Interface

### Inputs

**Cursor slot.** A writable location containing the initial byte address. The supplied representation uses a 32-bit address slot. The function reads it on entry and maintains a private cursor while processing. Normal completion replaces the caller’s slot with the final private cursor.

**End address.** The exclusive end of the intended input range. No length or terminating-zero requirement is supplied. A zero byte inside a fraction stops fractional scanning.

**Decimal adjustment.** A signed 32-bit value. A recognized exponent contributes another 32-bit value to this adjustment before scaling.

A positive effective adjustment repeats multiplication operations. A negative effective adjustment repeats calls to F-870c4fcf7295 and multiplication of the fractional denominator.

### Output

The function returns a signed 32-bit result. It has no separate success flag, error object, or consumed-length return.

Two explicit early-return cases produce zero without updating the caller’s cursor slot:

- The initial cursor equals the end address.
- Consuming one leading sign reaches the end address.

Zero can also be an ordinary result after normal completion. The return alone therefore does not distinguish these cases.

The cursor slot must be readable and writable. Input bytes that are examined must be readable. The function performs no pointer validation.

The intended bounded interpretation requires an ordered, contiguous range. Entry checks equality with the end address, not whether the cursor is below it. A starting cursor above the end is not safely rejected.

F-9239ebb6c943 receives the address of the private cursor and the end address. Subsequent behavior relies on the cursor it leaves behind. Bounds preservation, progress, and valid parsing are not enforced locally.

## Behavior

### Entry and leading sign

The first observable access is a read of the caller’s cursor slot.

If its value equals the end address, the function returns zero immediately. This path reads no input byte, calls no dependency, and performs no cursor publication.

Otherwise, it examines the leading byte:

- ASCII `-` selects a negative final result and advances the private cursor by one byte.
- ASCII `+` selects a nonnegative final result and advances it by one byte.
- Any other byte selects a nonnegative final result without advancing it.

If consuming a sign reaches the end address, the function returns zero. The private advance is not published, so the caller’s slot still points to the sign.

No leading-whitespace skip is visible in this function. Any whitespace handling later performed by F-9239ebb6c943 remains dependency-defined.

### Integer contribution

At the post-sign cursor:

- A decimal point selects an integer contribution of zero and bypasses F-9239ebb6c943.
- Any other byte causes a call to F-9239ebb6c943 with the private cursor address and end address.

The returned 32-bit integer value is shifted left by 16 bits to form the integer contribution.

There is no local check that the dependency consumed bytes, recognized a valid integer, returned a nonnegative value, or left the cursor within the range. The remaining stages use its returned value and cursor directly.

### Fractional scanning

After integer handling, the function checks that the private cursor is below the end address and points to a decimal point. Only then does fractional scanning begin.

The decimal point is consumed. The fractional numerator starts at zero, and the denominator starts at one.

For each subsequent byte before the end address, the function first treats the byte as an unsigned 8-bit value. The following values stop scanning without being consumed:

- Zero.
- Horizontal tab: 9.
- Line feed: 10.
- Form feed: 12.
- Carriage return: 13.
- Space: 32.
- Every value from 128 through 255.

Other bytes from 1 through 127 reach an external mapping-table lookup. Vertical tab, for example, is not an unconditional stopping byte.

The table entry is read as a signed 8-bit quantity and converted to an unsigned 32-bit comparison value. Only mapped values from zero through nine are accepted. Negative entries become large unsigned values and are rejected, rather than contributing negative digits.

Thus, fractional recognition is table-defined. The supplied material does not establish that ASCII decimal digits have their conventional mappings or that all other eligible bytes are rejected.

For each accepted mapped digit, the function reads an external 32-bit accumulation limit and compares the current denominator against it using a strict signed comparison:

- When the denominator is less than the limit, the numerator becomes ten times its previous value plus the mapped digit, and the denominator is multiplied by ten.
- Otherwise, neither accumulator changes.

An accepted byte is consumed whether or not its digit contributes. Reaching the accumulation limit therefore does not stop scanning. Further accepted digits may be consumed without affecting either accumulator.

There is no visible rounding based on ignored digits. The first rejected byte remains at the private cursor. If every remaining byte is accepted, the cursor reaches the end address.

A decimal point need not be followed by an accepted digit. A final decimal point is consumed, leaving the numerator zero and denominator one.

### Exponent handling

After optional fractional scanning, exponent recognition requires both:

- At least one byte after the current position remains before the end address.
- The current byte is ASCII `e` or `E`.

The boundary condition is evaluated before the marker byte is examined. Under a valid range and cursor, this prevents recognition of a final, unaccompanied marker.

For an eligible marker, the function advances past it and calls F-9239ebb6c943 with the private cursor address and the same end address. Its 32-bit return is added to the caller’s decimal adjustment.

The function does not locally require a decimal digit after the marker. It does not validate dependency progress, exponent syntax, or exponent range.

An `e` or `E` at the final byte is not consumed by this stage. Exponent recognition does not require that a preceding integer or fraction contributed a nonzero value; it depends on the current cursor.

A marker can reach this stage only if earlier processing leaves the cursor there. In particular, fractional table mappings can affect whether a marker is consumed during fractional scanning instead.

### Decimal scaling

Scaling follows all parsing and exponent addition.

For each positive unit of effective adjustment, in order:

1. Multiply the integer contribution by ten.
2. Multiply the fractional numerator by ten.

The denominator is unchanged. The adjustment is reduced by one after each iteration.

For each negative unit of effective adjustment, in order:

1. Call F-870c4fcf7295 with the current integer contribution and ten.
2. Replace the integer contribution with its return.
3. Multiply the fractional denominator by ten.

The numerator is unchanged. The adjustment is increased by one after each iteration.

These are repeated per-unit operations, not a single power-of-ten operation. This distinction matters for dependency side effects, rounding, overflow, and the number of calls. Negative scaling calls F-870c4fcf7295 even when the integer contribution is zero.

### Fractional conversion, sign, and publication

After scaling, the function tests the current fractional numerator.

If it is nonzero, F-73d099a86adb receives the scaled numerator and denominator. Its return is added to the integer contribution.

If the numerator is zero, fractional conversion is skipped, regardless of whether a decimal point or accepted fractional bytes were consumed.

The leading minus sign, if present, then negates the combined result. The function finally writes the private cursor into the caller’s cursor slot and returns the result.

Consequently, the cursor is published only after parsing, scaling, fractional conversion, and final sign application.

The fractional multiply-and-add includes an unsigned 32-bit mapped digit. Its resulting bit pattern is assigned back to the 32-bit numerator. This is not an arbitrary-precision decimal accumulator.

No local overflow check, saturation, or arithmetic-error return is visible. A strict denominator-limit test is not, by itself, proof that subsequent arithmetic is representable.

## Side effects

The directly visible caller-storage write is the final cursor publication on normal completion. The caller’s cursor slot is not incrementally advanced as input is consumed.

Neither explicit early-return path writes that slot.

The function reads input bytes but contains no explicit store through its input cursor. If the cursor slot overlaps input storage, its final publication can nevertheless modify overlapping bytes; no non-aliasing guarantee is established.

Fractional scanning reads external state in this order for each eligible byte:

1. Obtain the mapping-table reference and read the indexed entry.
2. If the entry is accepted, read the accumulation limit.
3. Conditionally update the private accumulators.
4. Advance to the next byte.

Rejected bytes do not trigger the accumulation-limit comparison. Bytes rejected by the initial byte filter do not require a table lookup.

The table reference and accumulation limit are not established as immutable or synchronized. A preceding dependency call must not be assumed to preserve them or any other global state.

Dependency calls can have additional unknown effects on input, global state, memory ownership, allocation, release, or error handling. No rollback is visible.
