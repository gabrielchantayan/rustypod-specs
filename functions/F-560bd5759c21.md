# F-560bd5759c21

## Purpose

F-560bd5759c21 performs an ordered sequence of object-field updates and dependency calls, then returns the original object address on normal completion.

Its established behavior includes:

- Reading a first 32-bit global source and storing the value read at object offset +0.
- Optionally invoking an indirect target selected through an associated object.
- Calling F-75a426b457cf.
- Reading a separate 32-bit global source and storing that value at object offset +0.
- Calling F-69f8c6fd83cc.
- Repeatedly calling F-9831b312a5f4 while an object field is nonzero.
- Optionally calling F-5e3309c9d083.
- Clearing two object fields and returning the original address.

The two global sources have different symbolic identities. Their 32-bit contents are **not established to be unequal**. The second write occurs even if both reads produce the same value.

**Inferred intent:** The sequence resembles staged teardown, including changes to a dispatch-related leading field and repeated processing of resource-bearing state. Neither destructor semantics nor resource ownership follows from the supplied evidence.

This is a static behavioral contract. No runtime tests have been performed.

## Behavior

### First global read and leading-field store

The function first reads the 32-bit contents of Source A. It then stores the value read into the 32-bit object word at +0.

The established order is:

1. Read Source A.
2. Store that value at object offset +0.
3. Test the associated-object field at +20.

No dependency call is visible between this global read and its corresponding store. The associated-object field does not gate either operation.

Later changes to Source A do not, by themselves, change the value already stored. The visible body does not reread Source A.

### Optional associated-object invocation

After the first leading-field store, the function tests the 32-bit word at +20.

If it is zero, the indirect call is skipped.

If it is nonzero, the function resolves a target by following the associated object’s leading address-bearing word to dispatch storage and selecting the callable entry at byte offset +28. It invokes that target before calling F-75a426b457cf.

The displayed invocation has no explicit argument expressions. It does not establish that either the associated object or the primary object is passed as a receiver. Implicit register inputs and receiver conventions remain documented_only.

The indirect call’s result is not explicitly consumed. Its identity and effects are unknown.

The supplied representation establishes the dispatch-resolution relationship, but not a synchronization guarantee or exact machine-load count for the field test and subsequent target resolution. A stable snapshot under concurrent mutation must not be assumed.

### First unconditional dependency

After the associated-object stage completes normally, the function calls F-75a426b457cf with the original object address.

This call occurs whether the associated-object invocation was taken or skipped. Its result is not explicitly used.

The dependency may change object fields, globals, or other state; no preservation contract is supplied.

### Second global read and leading-field store

After F-75a426b457cf returns normally, the function reads the 32-bit contents of Source B. It then stores the value read into object offset +0.

This read is ordered:

- After the optional associated-object invocation, if taken.
- After F-75a426b457cf.
- Before the second leading-field store.
- Before F-69f8c6fd83cc.

Consequently, the second store uses Source B as observed at this later read, not necessarily Source B’s entry-time contents. Either earlier dependency may have changed Source B. The function does not visibly capture Source B before those calls or restore an earlier value.

The second store overwrites whatever value is then present at +0, including a value written by an earlier dependency. It remains a store even if Source B yields the same value that Source A yielded.

There is no further explicit write to +0 in this body. Later dependencies may nevertheless change that word, so the second store does not establish its return-time value.

### Repeated dependency calls

The function reads the 32-bit word at object offset +12.

- Zero ends the loop.
- Any nonzero value causes one call to F-9831b312a5f4 with the original object address.
- After that call returns normally, the function reads +12 again and applies the same decision.

The condition examines the complete 32-bit value. It is not a signed-positive test. A value with only the high bit set is nonzero and selects another call.

The body does not decrement, clear, or otherwise directly modify +12. It imposes no iteration limit and contains no timeout or alternate exit.

Termination therefore depends on a later read observing zero. Dependency behavior or other memory changes may produce that observation; the evidence does not establish that they will.

If every reached read observes nonzero and every loop call returns normally, iteration continues indefinitely. The final-call test, trailing clears, and normal return are not reached.

The call has no displayed explicit arguments, and its result is not explicitly used. The evidence establishes that +8 gates invocation; it does not establish that the field is supplied as an argument or identifies a resource owned by the callee.
