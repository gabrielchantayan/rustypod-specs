# F-850578bcb4fe

The established result is binary: the function returns either zero or hexadecimal `0x24`. Zero means that all checks implemented here passed. The supplied evidence does not establish a broader meaning for `0x24`, or prove that a successful candidate is valid for every downstream consumer.

## Behavior

### 1. Capture the extent and obtain a limit

The function first reads the unsigned 16-bit extent at context offset `+0x1C`. Call this captured value **L**. It remains the extent used by this invocation even if a dependency later changes the context field.

It then invokes F-1e0edc6e0bc9 with:

1. The 32-bit value obtained from indirect-state offset `+0x10`.
2. The 32-bit value obtained from indirect-state offset `+0x14`.
3. L, zero-extended to 32 bits.
4. Zero.

The supplied representation does not establish the relative evaluation order of the first two argument expressions. Because each expression resolves the indirect state, this matters if the underlying memory can change between reads.

The dependency produces a 64-bit result. The function subtracts one and separates the resulting bit pattern into:

- A low unsigned 32-bit word, **limit**.
- A high 32-bit word, supplied to the next dependency as an integer argument.

The low word alone is subsequently used for local numeric comparisons. This is not a local 64-bit comparison against the full dependency result.

The subtraction’s behavior at the extreme signed 64-bit boundary is not independently established by the supplied evidence. Ordinary cases in which subtraction is representable have the behavior described above.

### 2. Check the first dependency-decoded value

F-4055be9c3f18 is invoked with the candidate address and the high word described above.

Its return is treated as an unsigned 32-bit value. If it exceeds limit, the function returns `0x24`.

No second invocation of F-4055be9c3f18, discriminator read, count read, or table traversal occurs on this rejection path.

### 3. Check the second dependency-decoded value and discriminator

If the first decoded value is at most limit, F-4055be9c3f18 is invoked again, this time with candidate address plus four. The supplied call representation shows only this one explicit argument for the second invocation.

If the second result exceeds limit, validation fails with `0x24`, without reading the discriminator at candidate offset `+8`.

If the second result is at most limit, the function reads that discriminator and interprets it as signed. Its accepted values are exactly:

- `−1`, represented by byte `0xFF`;
- `0`;
- `1`;
- `2`.

Other discriminator values cause rejection.

The discriminator is read and checked whether the second result is equal to or strictly less than limit. Equality is not a separate rejection case.

### 4. Check the header limit and count

After the discriminator passes, the function reads the unsigned candidate byte at offset `+9` and compares it with the unsigned 16-bit context value at offset `+2`.

If the candidate byte is larger, the function returns `0x24`. The context value is read after both dependency invocations; it is not part of the initial snapshot.

If that comparison passes, the function reads the unsigned 16-bit count parameter at candidate offset `+10`. Call it **N**.

N must be no greater than:

**((L − 14) modulo 2³²) shifted right by 3 bits.**

The subtraction is unsigned 32-bit arithmetic. In particular, an extent below 14 does not automatically fail this check: it produces a large unsigned bound after underflow. A caller must not rely on this expression to establish that a fixed-size header exists.

For extents of at least 14, the bound is the integer quotient of `(L − 14)` divided by eight.

### 5. Traverse the trailing offset table

If the count check passes, the function initializes an upper bound to:

**(L − 2N) modulo 2¹⁶.**

It then reads **N + 1** unsigned 16-bit offsets. The first read starts at candidate-relative position:

**L − 2N − 2.**

Subsequent reads advance by two bytes, ending at position **L − 2**.

This is an inclusive traversal. N equal to zero still causes one table read.

The 16-bit reduction applies to the initial upper bound, not to the table-address calculation. An underflowing table position is therefore not safely converted into an in-range candidate offset.

For every offset read:

1. If the offset is odd, return `0x24`.
2. If the offset is greater than or equal to the current upper bound, return `0x24`.
3. If the conditional record-length rule below applies, inspect and validate the record-length prefix.
4. Use the current offset as the next upper bound.

Consequently, the values must be strictly decreasing in the order they are read. Every accepted offset is even. The first offset must be strictly below the initial upper bound.

The traversal performs the first two checks before attempting any conditional record-prefix read for that entry.

### 6. Conditionally check length-prefixed records

Record-length checking applies only when the discriminator is `−1`.

Even then, it is skipped for the first table entry visited. It applies to each subsequent entry, giving N prefix checks if the whole traversal completes.

For each such entry, the available span is the previous upper bound minus the current offset. The earlier strict-order check ensures that this span is positive.

The function reads context offset `+0x30` for the entry:

- If bit `0x2` is clear, it reads one unsigned byte at the candidate-relative offset. Required size is that byte plus one.
- If bit `0x2` is set, it reads one unsigned 16-bit value at the candidate-relative offset. Required size is that value plus two.

If the required size exceeds the available span, the function returns `0x24`. Equality passes.

The prefix is read before its declared size is compared with the span. In particular, the two-byte-prefix path does not first verify that the span contains two bytes. Memory validity remains a precondition for that read.

The additions are performed in a wider integer type: the maximum required sizes are 256 and 65,537, respectively. A maximum 16-bit prefix is therefore not truncated back to 16 bits.

No equivalent record-prefix checks occur for discriminators `0`, `1`, or `2`.

The context flag is read separately for each inspected record. The function does not establish a single invocation-wide snapshot of the prefix-width mode.

### 7. Apply the final lower bound

After all N + 1 offsets pass, the final offset read must be greater than 13.

Because every accepted offset is even, the smallest possible successful final offset is 14.

If this final condition passes, the function returns zero. Otherwise, it returns `0x24`.

### Rejection boundaries

- A discriminator byte of `0xFF` is accepted; `0xFE` rejects.
- An odd table offset rejects.
- An offset equal to the preceding upper bound rejects.
