# F-758a0f6e0142

## Purpose

F-758a0f6e0142 conditionally prepares a resource for a requested numeric selection and exports a compact, 20-byte record of resource properties.

The established behavior is:

- Refuse processing when the observed global enable state is zero or a conditionally sampled resource identifier equals the signed 32-bit value −1.
- Invoke an initial dependency, resolve a resource, and obtain a secondary state object.
- If the requested selection differs from a cached 16-bit selection, invoke two operations in sequence. Both must report zero before the cache is updated.
- Populate the output record and return 1 after successful processing.
- Return 0 on the explicit refusal and dependency-failure paths.

“Enable state,” “resource,” “selection,” and “cache” are descriptive terms, not established domain meanings. The supplied material does not identify the underlying subsystem or the meanings of the exported properties.

## Interface

### Inputs

The function receives three arguments:

| Argument | Representation | Contract |
|---|---|---|
| Context address | Address represented by a 32-bit value in the supplied interface | Identifies storage containing a cached selection, resource identifier, and dependency argument at the offsets below. |
| Requested selection | Unsigned 32-bit integer | Compared in full against a zero-extended 16-bit cached value; passed without visible narrowing to a dependency. |
| Output address | Address of writable storage | On success, receives a 20-byte record. No size argument is supplied. |

The context fields visibly used are:

| Byte offset | Width | Use |
|---|---:|---|
| 96 | 16 bits | Cached selection, read as unsigned and conditionally overwritten with the low 16 bits of the requested selection |
| 100 | 32 bits | Resource identifier; initially tested as signed against −1, and later read again for resource resolution |
| 104 | 32 bits | Argument supplied to the first dependency |

The function also reads a global enable value through a globally referenced address. The supplied material establishes comparison with zero, but not the width or ownership of that value.

### Output record

A successful call writes the following layout, with offsets measured from the output address:

| Byte offset | Width | Value |
|---|---:|---|
| 0 | 32 bits | Zero |
| 4 | 32 bits | Raw property read from secondary-state offset 80 |
| 8 | 32 bits | Raw property read from secondary-state offset 76 |

All bytes in the 20-byte record are written on a normal success path. The function does not write beyond byte 19 through its explicit output stores.

These are native-width stores, not an explicitly serialized byte format. Byte order is not independently established by the supplied material.

### Return value

The return occupies 32 bits:

- **0:** an explicit early-refusal or dependency-failure path was taken.
- **1:** the output stores completed and control reached the success return.

No other normal return value is shown. Invalid memory, dependency faults, or non-returning dependencies are not converted into a documented return value.

## Behavior

### Entry gating

A local gate value starts at zero.

The function first reads the global enable value. If that observation is nonzero, it reads the 32-bit resource identifier from context offset 100 into the gate value. If the observation is zero, it does not perform that context read at this stage.

It then reads the global enable value again. Processing stops with return 0 if either:

- This second observation is zero; or
- The gate value equals signed −1.

No dependency is invoked and no explicit output store occurs on this refusal path.

The two global reads are distinct in the supplied behavior. The contract does not replace them with one stable snapshot. Consequently, conditional on a change between the observations:

- A first observation of zero followed by a nonzero observation permits processing using the initial gate value of zero. The context identifier was not checked against −1 during entry gating.
- A first observation of nonzero followed by zero refuses processing even if the sampled identifier was valid.

The source does not establish thread-safety, atomicity, or valid concurrent modification. These cases describe the consequences of differing observations, not a guarantee that concurrent modification is supported.

### Initial dependency and resource resolution

After passing the gate, the function:

1. Reads the 32-bit value at context offset 104 and invokes F-0eeabd45a2a0 with that value.
2. Reads the resource identifier at context offset 100 again and invokes F-f6358965d277 with that value.
3. Reads a 32-bit value at offset 84 of the resolver’s result. This value is subsequently used as the secondary-state address.

No return-value check for F-0eeabd45a2a0 is visible.

The later identifier read is not replaced by the earlier gate sample. In particular, F-0eeabd45a2a0 is not established to preserve the context or global state. The identifier passed to the resolver may therefore differ from the identifier sampled at entry.

Neither the resolver result nor the secondary-state address is visibly checked for validity.

### Selection comparison and conditional update

After obtaining the secondary-state address, the function reads the cached selection at context offset 96 as an unsigned 16-bit value.

The comparison uses that value zero-extended to 32 bits against the entire unsigned 32-bit requested selection. It is not a comparison of only the request’s low 16 bits.

If the values are equal, both selection-changing dependencies are skipped and output construction begins.

If they differ:

1. F-1422394ed772 is invoked with the resolver result, the full requested selection, and the constant 2.
2. A nonzero result causes immediate return 0.
3. Otherwise, F-6c10861922bc is invoked with the previously obtained secondary-state address and the constant 0.
4. A nonzero result causes immediate return 0.
5. Only after both dependencies return zero does the function write the low 16 bits of the requested selection to context offset 96.

The secondary-state address is obtained before either conditional dependency. The function does not reload it from the resolver result afterward, even if a dependency changes that field.

There is no visible rollback:

- If the first selection dependency fails, its own side effects may remain.
- If the second fails, effects of either dependency may remain.
- The function itself does not update the cached selection on either failure path.
- A successful cache update occurs before output population.

Requests above 65,535 can never compare equal to a zero-extended 16-bit cache value. Such a request always enters the conditional-update branch when entry processing succeeds. Although a successful update stores its low 16 bits, repeating the same out-of-range request still produces a mismatch.

### Output population

After a cache match or a successful conditional update, the explicit output accesses occur in this order:

1. Store 32-bit zero at output offset 0.
2. Read secondary-state offset 80 and store those 32 bits at output offset 4.
3. Read secondary-state offset 76 and store those 32 bits at output offset 8.
4. Read the signed 32-bit property at secondary-state offset 64, calculate its rounded result, and store 16 bits at output offset 12.
5. Read 32 bits at secondary-state offset 100 and store the low 16 bits at output offset 14.
6. Read 32 bits at secondary-state offset 104 and store the low 16 bits at output offset 18.
7. Store 16-bit zero at output offset 16.
8. Return 1.

The offset-18 store precedes the offset-16 store. Output is not assembled privately and committed atomically.

The property reads happen during output construction, after the conditional dependencies and any cache update. They are not a snapshot taken before those operations.

### Rounded property

For signed input values whose absolute value and subsequent addition of 32 are representable in signed 32-bit arithmetic, the property at secondary-state offset 64 is transformed as follows:

- Its magnitude is rounded to the nearest multiple of 64 by adding 32 and shifting right by six bits.
- Its original sign is restored.
- The result is stored in a 16-bit field.

Before narrowing, this corresponds to rounding the input divided by 64 to the nearest integer, with exact half-way cases rounded away from zero.

The straightforward signed-arithmetic interpretation is safe for inputs from −2,147,483,615 through 2,147,483,615. Values outside that range encounter either an unrepresentable signed absolute value or an overflowing addition.

There is no visible saturation or explicit overflow handling. Exact behavior at those arithmetic extremes is documented_only. Likewise, a mathematical rounded result outside the signed 16-bit range must not be described as a preserved full-range signed result: the destination contains only 16 bits.

## Side effects

### Directly established effects

The function can:

- Read the global enable value twice.
- Read context fields at offsets 96, 100, and 104 as described.
- Invoke up to four dependencies.
- Update the 16-bit cached selection.
- Write the 20-byte output record.

There is no explicit allocation, release, ownership transfer, or retained output-pointer assignment in the supplied function body.

### Failure and partial progress

All explicit return-0 paths occur before the function’s own output stores. With non-overlapping storage and dependencies that do not modify the output, a return of 0 therefore leaves the output unchanged.

That qualification matters: dependencies may affect memory or external state, and their effects are not specified here.

The function does not undo dependency effects on failure. A fault during output population can also occur after the cache was updated or after earlier output fields were written. No recovery behavior is shown.

### Aliasing and ownership

The supplied interface does not establish whether the context, output, resolved object, and secondary state may overlap.

If they overlap, earlier stores may affect later reads. For example, the initial output-zero store precedes every property read used to populate the output. Such overlap cannot be treated as though the function first captured all properties.

The caller’s provision of addresses does not establish that any dependency borrows, retains, owns, or releases their associated resources. No dependency is assumed to preserve globals, context fields, or secondary-state contents.

## Acceptance examples

These are conditional acceptance criteria derived from static evidence, not executed tests. Unless stated otherwise, assume valid, suitably aligned, non-overlapping storage; normal dependency returns; no external mutation; and no dependency modifications beyond those explicitly stipulated.

1. **Disabled entry.** If both global observations are zero, the function returns 0, invokes no dependency, and performs no direct context or output write.

2. **Invalid sampled identifier.** If the first global observation is nonzero and the sampled context identifier is −1, the function returns 0 without invoking dependencies, regardless of whether the second global observation is zero or nonzero.

3. **Matching selection.** With both global observations nonzero, a valid identifier, cached selection 37, and request 37, the initial dependency and resolver execute. The two conditional dependencies do not execute. The cache is not directly rewritten, and the output record is populated.

4. **Successful selection change.** With cached selection 37 and request 38, both conditional dependencies execute in order. If each returns zero, the cache becomes 38 before output population, and the function returns 1.

5. **First conditional failure.** If F-1422394ed772 returns any nonzero value, F-6c10861922bc is not invoked. The function returns 0 without directly changing the cache or output. Earlier dependency effects are not rolled back.

6. **Second conditional failure.** If the first conditional dependency returns zero and the second returns nonzero, the function returns 0 without its own cache update or output writes. Effects of both dependencies may remain.

7. **Full-width comparison.** With cached selection 1 and request 65,537, the conditional branch executes despite matching low 16 bits. If both dependencies succeed, the stored cache is 1. Repeating that request still enters the conditional branch.

8. **Rounding boundaries.** For the property at secondary-state offset 64, inputs 31, 32, 63, 64, −31, −32, −63, and −64 produce signed 16-bit results 0, 1, 1, 1, 0, −1, −1, and −1 respectively.

9. **Property narrowing.** A 32-bit property value of 65,538 at secondary-state offset 100 yields the 16-bit value 2 at output offset 14. High bits are not preserved.

10. **Changed identifier before resolution.** If F-0eeabd45a2a0 changes the context identifier, the resolver receives the identifier read after that dependency returns, not the earlier gate sample.

11. **Saved secondary-state address.** If a conditional dependency replaces the secondary-state address held at resolver-result offset 84, output population still uses the address obtained before those conditional calls.
