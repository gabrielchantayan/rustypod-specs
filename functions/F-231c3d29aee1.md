## Behavior

The following phases describe the required ordering of represented effects. They do not imply atomic execution.

Before reading the primary base slot, four writes occur in this order:

- A 16-bit write at the sum of the shifted input and offset input, containing the low 16 bits of the unsigned state.
- An eight-bit write at the shifted input minus the offset input, containing the low eight bits of the signed state.

The negated offset is retained between its uses. Its signed 32-bit negation is not safely defined for the minimum signed 32-bit value without additional execution-model evidence.

The shift count is extracted from the unsigned state’s low eight bits before the fourth write. Its represented range is therefore 0 through 255. This extraction does not establish any later reduction to a five-bit count.

After the initial writes, the primary base slot is read and its value retained. A separate use of that slot supplies the base for an eight-bit write displaced by the signed state. That write contains the low eight bits of the halfword state.

The payload slot is then read and its 32-bit value retained. Next, a signed 32-bit value is read from the retained primary base plus 89. This **loaded word** is retained independently of later changes to its source memory.

### Secondary-base effects

One byte is then read at twice the unsigned state. That retained byte has two later uses: an offset for a halfword-store destination and the first outgoing argument. Its signed interpretation is unresolved.

### Final local store

The last represented store writes the low eight bits of the unsigned state. Its destination combines:

- The value associated with the final-address slot.
- The retained loaded word.
- The final displacement.

This occurs after the payload byte store and before the indirect transfer. The fragment does not establish the final-address slot’s read width.

### Indirect transfer and outgoing arguments

After the twelve stores, control is transferred through the unresolved target.

**First argument:** the retained byte converted to a signed 32-bit integer after its character interpretation. A high-bit-set byte can therefore produce either a negative value or a value from 128 through 255, depending on unresolved character signedness.

**Second argument:** the value supplied by the argument slot at the transfer expression. It is not a snapshot captured before the preceding stores. Earlier writes may affect it if storage overlaps.

**Third argument:** twice the shifted input after right shift by the extracted count, plus a zero-or-one contribution. The contribution is one exactly when either of these conditions holds:

- The count is zero and the offset input is zero.
- The count is nonzero and the low bit obtained by right-shifting the shifted input by one less than the count is one.

Otherwise, the contribution is zero.

The zero-count condition depends on the **offset input**, not the shifted input. A conventional carry interpretation must not replace that condition.

The contribution is represented as unsigned 32-bit. Consequently, the final addition has a represented unsigned 32-bit conversion. This does not make an earlier overflowing signed multiplication well-defined: doubling the signed shifted result occurs before that final conversion.

The shifted expression occurs both in address formation and in the outgoing argument. Under stable inputs and defined arithmetic, those occurrences have the same mathematical result; the representation does not establish that a single machine computation is reused.

## Side effects

### Memory modification and aliasing

Earlier stores may change later memory inputs. Later stores may overwrite earlier outputs. The final memory state therefore depends on both address relationships and access order; it cannot be described as twelve independent assignments.

Relevant aliasing cases include:

- A destination overlapping either base slot.
- A destination overlapping the payload, argument, or final-address slot.
- A destination overlapping the source of the loaded word or retained byte.
- Several destinations sharing some or all bytes.
- A destination overlapping storage relevant to the indirect target.

Retained values remain snapshots after acquisition. For example, modifying the loaded word’s original address later does not update the retained loaded word used in subsequent stores.

No synchronization, atomicity, isolation, or reentrancy guarantee is established.

- **Oversized counts:** counts 32 through 255 exceed a 32-bit operand’s ordinary shift range. At count 32, the contribution’s separate shift uses 31, but the main shift remains unresolved.

- **Other address arithmetic:** missing declarations and relocation details prevent a universal rule for width, signedness, or wrapping, particularly for symbol-associated address components.
- **Character signedness:** affects both the byte-derived address offset and first outgoing argument.
- **Storage semantics:** byte order, alignment, address-space width, volatile or device behavior, and fault delivery are absent.
- **Repeated slot uses:** the representation does not prove physical load count, atomicity, or evaluation order within the secondary-base store.
- **Final slots:** exact read widths and declarations for the argument and final-address slots are absent.
- **Indirect control flow:** whether the representation faithfully distinguishes a call from another transfer, and whether execution returns, remain unresolved.

A carry-like interpretation of the final arithmetic is plausible intent, not established purpose.
