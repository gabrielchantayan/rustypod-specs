# F-caf575c7998f

## Purpose

F-caf575c7998f performs a read–transform–write operation on one of two regions associated with a caller-supplied object, then dispatches a notification through that object’s function table.

The region selected for the read is not necessarily the region selected for the write. Selection is performed again after the read dependency returns. Likewise, the contextual integer passed to the dependencies and notification is read separately at each stage. These distinctions matter if a dependency changes the object.

The transformation increments a dependency-supplied value using unsigned arithmetic, clears bit 16, and replaces results greater than 57 with 48. This establishes a numerical transformation; it does not establish that the values represent characters, digits, or any particular application concept.

This contract describes static evidence only. No runtime tests have been performed.

## Behavior

### 1. Select the region for the read

The function reads the selector and compares it with exactly 1.

- If equal to 1, it selects the interior address at byte offset 164 under the apparent 32-bit layout.
- For every other value, it selects the interior address at byte offset 108.

This is an equality test, not a truth-value test. For example, selector values 0, 2, and −1 all choose the alternate region.

The function obtains the contextual integer and invokes F-08e2860e8e52 with:

1. The selected interior address.
2. The contextual integer.

The selector decision precedes this call. The exact machine-level ordering of all argument preparation reads is not established beyond the sequencing visible in the supplied representation.

### 2. Transform the read result

The returned integer is transformed using unsigned arithmetic. Under the apparent 32-bit model, let \(r\) be its 32-bit bit pattern. The intermediate value is:

\[
t = ((r + 1) \bmod 2^{32}) \mathbin{\&} \text{0xFFFEFFFF}
\]

The mask clears bit 16 and preserves every other bit.

The value supplied to the write dependency is:

\[
w =
\begin{cases}
48, & t > 57 \\
t, & t \leq 57
\end{cases}
\]

The comparison is unsigned. The threshold is strict: 57 is retained, while 58 is replaced with 48.

Important consequences:

- Increment wraparound is part of the transformation under the 32-bit unsigned interpretation.
- The bit-clearing step occurs after the increment and before the comparison.
- The transformation does not enforce a lower bound of 48.
- Every value from 0 through 57 is a possible transformed result.
- Values outside that range after masking become 48, rather than being reduced modulo a range.

For example, an input bit pattern of all ones wraps to zero during the increment. It therefore produces zero, not 48.

### 3. Select the region again and write

After F-08e2860e8e52 returns, the function reads the selector again and repeats the same equality-based selection.

It does not preserve the first region selection for this stage. If the read dependency changed the selector, the write can target the other region.

The contextual integer is also obtained again for the write call. The value supplied to the read dependency is not guaranteed to equal the value supplied to the write dependency.

The function then invokes F-c47cf0b2619a with:

1. The newly selected interior address.
2. The contextual integer obtained for this call.
3. The transformed value \(w\).

The write dependency’s return value does not influence the remaining visible behavior. Provided the call returns normally, execution proceeds to notification.

### 4. Dispatch notification

After the write dependency returns, the function performs an indirect dispatch through the supplied object:

- It obtains the function-table pointer from the object’s first word.
- It uses the callable entry at table byte offset 88.
- It supplies the original object pointer as the first argument.
- It supplies an externally stored datum as the second argument.
- It supplies the contextual integer plus 22,421, hexadecimal 0x5795, as the third argument.

The contextual integer used here is read for the notification stage. It is not necessarily the value used by either earlier dependency.

The externally stored datum’s value, width, type, and application meaning are not established. It must be treated as an opaque notification argument, not as a known event code or pointer.

The addition used for the third argument is not shown with the explicit unsigned treatment used in the earlier numerical transformation. Consequently, signed-overflow cases cannot be assigned a portable wrapping result from this evidence alone.

The notification occurs after the write dependency returns normally. There is no visible conditional that suppresses notification based on the transformed value or a returned write status.

## Acceptance examples

These examples are conditional static acceptance criteria, not executed tests. Numerical examples assume the apparent 32-bit arithmetic model and normal return from dependencies.

### Stable selection and context

Given a selector of 1 and no relevant object changes during the read dependency:

- F-08e2860e8e52 receives the interior address at byte offset 164.
- F-c47cf0b2619a receives that same address.
- If the contextual integer remains 7 throughout both calls, each receives 7.
- If it remains 7 through notification argument preparation, the third notification argument is 22,428.

For any stable selector other than 1, both dependencies instead receive the address at byte offset 108.

### Exact transformation boundaries

| Read-result bit pattern | After increment and mask | Value passed to write |
|---|---:|---:|
| 0x00000000 | 1 | 1 |
| 0x0000002F | 48 | 48 |
| 0x00000038 | 57 | 57 |
| 0x00000039 | 58 | 48 |
| 0x0000FFFF | 0 | 0 |
| 0x00010038 | 57 | 57 |
| 0x00010039 | 58 | 48 |
| 0xFFFFFFFF | 0 | 0 |
| 0xFFFFFFFE | 0xFFFEFFFF | 48 |

The 0x0000FFFF case demonstrates that clearing bit 16 can produce zero without full-width increment wraparound. The 0xFFFFFFFF case demonstrates full-width wraparound.

### Selector changed by the read dependency

Suppose the selector initially equals 1. F-08e2860e8e52 receives the address at byte offset 164. If that call changes the selector to 2 before returning, F-c47cf0b2619a receives the address at byte offset 108.

An implementation that always reuses the first address would not satisfy this behavior.

### Context changed between stages

Suppose the contextual integer is 3 for the read call, becomes 4 before the write call, and becomes 5 before notification argument preparation.

The observable arguments are respectively:

- Read context: 3.
- Write context: 4.
- Notification third argument: 22,426.

This example assumes those changes occur before the relevant reads and that no further changes intervene.

### Write result does not gate notification

If F-c47cf0b2619a returns normally, notification follows regardless of its returned value. No success-status interpretation is visible in this function.

### Updated dispatch state

If the write dependency changes the object’s function-table pointer and leaves a valid compatible table installed, the subsequent dispatch uses the table state obtained after that dependency returns. The function does not establish use of a target captured before the write.
