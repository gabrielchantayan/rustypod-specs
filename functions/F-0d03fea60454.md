# F-0d03fea60454

## Purpose

F-0d03fea60454 performs a condition-dependent sequence of memory accesses and indirect calls. No application-level purpose is established. Pointer-shaped values and self-referential writes do not establish allocation, object construction, device initialization, or ownership transfer.

**Established static evidence:** the long path contains three indirect calls and extensive memory mutation. The short path contains two indirect calls. Both paths end at reported invalid-instruction boundaries, not represented normal returns.

**Inferred intent:** none sufficiently supported to include in the contract.

This is a conditional static behavioral specification. Invalid instruction data, removed blocks, overlapping storage, missing global declarations, and unresolved incoming processor state limit what can be established.

## Behavior

### Path selection and progress

No argument validation precedes this decision. All later behavior is conditional on reaching it: a fault, nonreturning dependency, or unresolved instruction behavior can prevent subsequent operations.

The sequence below follows the supplied representation. It does not impose an ordering between separate operands inside an expression where that ordering is not established.

### Short path

1. Invoke F-U05 at the incoming link-register value plus `0x16e`. No explicit arguments are represented.
2. If F-U05 returns, invoke F-U06 at `0x08980e9d`, again without represented explicit arguments.
3. If F-U06 returns, reach the reported invalid-instruction boundary.

No explicit memory writes are represented on this path. The dependencies may nevertheless read or modify memory. Their results are unused by the represented continuation.

### Long path: initial writes

First, write the first argument as an 8-bit value at the address formed from one incoming hidden register plus 7.

Next, multiply the numeric third-argument value by `0x200000` and assign the result to storage associated with `0xffffffcc`. This is a 32-bit computation; the named storage’s access width is unresolved.

Write five consecutive 32-bit words through the fourth argument, in order:

1. Zero.
2. The third argument’s address value.
3. A value read from the storage associated with `0xffffffcc`.
4. The third argument’s address value again.
5. The additional incoming register value.

The third output is a later read, not necessarily the originally assigned product. Earlier writes can affect it through aliasing.

Then perform these operations in order:

- Write 16-bit zero at the address formed from the other hidden register multiplied by `0x40000`, plus 14.
- Assign the low 16 bits of the third argument’s address to overlapping storage associated with address 6.
- Read that storage and write its converted 16-bit value through the third argument.
- Write one byte at the address formed by shifting the numeric third-argument value left by seven. The stored byte is the byte-sized result of multiplying its byte conversion by 64.
- Write the 32-bit constant `0x0898033c` at offset 8 from the third argument.
- Assign `0x86` to named storage associated with `0x8a`; its access width is unresolved.
- Write the 32-bit value `0x86` at the address formed by interpreting the third argument’s numeric value as signed, shifting it right by 16, multiplying by `0x200`, and adding 8.

The initial assignment to storage associated with address 6 supplies a 16-bit value, but does not establish a 16-bit physical global store.

2. Assign zero to the reset-associated storage.
3. Assign to storage associated with address 2 the 16-bit conversion of the working value shifted left by 21 and then logically right by 16.

- Convert its value-producing use to the 16-bit value required by the destination store.

## Side effects

Writes are sequential, not transactional. Aliasing may affect later reads. Repeated writes to one destination remain separate observable events, including where the second overwrites the first.

No dependency is assumed to preserve global memory. Later global reads can observe dependency mutations. Conversely, values explicitly retained before calls remain the values used by the represented continuation.

## Acceptance examples

These are conditional static criteria, not executed tests.

1. **Short path:** With the entry flag set and both calls returning, the represented order is F-U05, F-U06, then the terminal boundary. No long-path explicit writes occur.

2. **Output publication:** With the flag clear, accessible destinations, and no interfering aliasing, the fourth argument receives five ordered 32-bit writes. Its second and fourth words contain the third argument’s address.

3. **Partial overwrite:** On reaching F-U01, offset 4 has received a 32-bit address write followed by a 16-bit zero write. Checking only a presumed final pointer value is insufficient.

4. **Independent conditions:** A nonnegative signed AND result triggers the offset-24 halfword read. A negative signed retained value from `0x089801dc` suppresses the conditional offset-24 write under the represented arithmetic shift, independently of that read.

5. **Unchecked result:** If F-U01 returns zero, the next explicit operation attempts a 32-bit zero store at address zero.

6. **Unrestricted address-producing conversion:** If the address-producing use of storage associated with `0x30` converts to `0x12345678`, the represented destination is that address, not `0x5678`. The stored halfword comes from the separate value-producing use.

7. **Repeated stores:** Reaching the final phase produces two ordered halfword stores at derived address plus 2. Eliminating the first is not equivalent for every possible memory mapping.

8. **Final byte:** If conversion of storage associated with `0x08980420` to signed 32 bits produces a value with bit 31 set, the final byte is `0xff` under the represented arithmetic shift; otherwise it is zero. This does not require a 32-bit underlying global read.
