## Behavior

### Width and interpretation rules

The listing establishes the following access widths:

- Signed halfword reads: 16 bits, interpreted as signed before subsequent integer promotion.
- Halfword writes: 16 bits.
- Byte write: 8 bits.
- Full integer write: 32 bits.
- Embedded value selections: four bytes each.

The arithmetic is expressed using 32-bit integer and unsigned-integer operations. A signed 16-bit read contributes a value from −32,768 through 32,767 when promoted to a signed 32-bit integer.

For the unsigned comparison, the saved signed 16-bit value is first promoted to signed 32 bits and then converted to unsigned 32 bits. A negative saved value therefore becomes a large unsigned value, not a negative comparison operand.

The contract does not impose a universal wraparound rule on signed address arithmetic. Calculations that stay within the applicable signed range have the direct numerical meaning described below. Overflow behavior beyond that range requires execution-model information not present in the listing. The final argument calculation has an explicitly unsigned operand and therefore has a 32-bit modular interpretation.

   The resulting signed value is retained as the displacement for the later byte-write destination.

5. **Calculate an intermediate address component.**

   - Embedded value B.
