# F-eef328c1181f

## Purpose

F-eef328c1181f classifies a 32-bit encoded value in relation to a signed 32-bit selector and shared state. Before examining the encoding, it obtains a context and performs a prerequisite check using the selector.

The established normal-result set is **0, 1, 2, 4, and 5**. These are numeric outcomes; the supplied material does not establish their domain-specific meanings. In particular, result 0 is not enough evidence to label an operation successful, and result 5 is not enough evidence to identify a particular error class.

There are two encoding families:

- Values whose lowest five bits are zero are classified using a shared comparison value, a field in bits 17–23, and sometimes a dependency.
- Values whose lowest five bits are nonzero are classified using a different shared comparison value, selected bytes of an eight-byte-stride record, and sometimes another dependency.

This contract distinguishes behavior visible in the supplied representation from inferred intent and unresolved dependency behavior. No runtime tests have been performed.

## Interface

### Inputs

| Input | Width and interpretation | Use |
|---|---|---|
| Selector | Signed 32-bit integer | Passed unchanged to prerequisite checking and one classification dependency; also used in record-address arithmetic. |
| Encoded value | Unsigned 32-bit integer | Supplies dispatch bits, comparison fields, an upper-byte value, and dependency arguments. |

The function exposes no explicit buffer pointer, length, or ownership-transfer parameter.

Negative selectors are not rejected locally. There is also no visible upper-bound check before record addressing. A caller that reaches the record-reading path must therefore provide a selector and shared state that make the actual memory accesses valid.

### Output

The declared result occupies 32 bits. On normal completion through the visible return sites:

| Result | Conditions |
|---|---|
| 0 | A selected dependency reports zero; the zero-low-bits family selects field value 0x60000; or the record path does not produce result 2 and its final dependency does not report 9. |
| 1 | The zero-low-bits family selects a field other than 0x20000, 0x40000, or 0x60000; or the record path’s final dependency reports exactly 9. |
| 2 | Three record bytes are nonzero and a separately read record byte differs from the encoded value’s upper byte. |
| 4 | The zero-low-bits family selects 0x20000 or 0x40000 and its dependency reports nonzero. |
| 5 | The applicable shared-state comparison fails. |

Dependency nontermination, exceptional behavior, or invalid memory access may prevent any normal result.

### Shared-state labels

The following are contract-local labels, not implementation symbols:

- **S-A:** shared comparison value used when the lowest five input bits are zero.
- **S-B:** shared comparison value used when the lowest five input bits are nonzero.
- **S-T:** shared record-table base.

The representation establishes their uses in comparisons and address formation. It does not independently establish their storage declarations, ownership, lifetime, synchronization, or initialization rules.

## Behavior

### 1. Unconditional prerequisite sequence

Before inspecting any encoded-value field, the function:

1. Calls **D-01**, a dependency without a supplied mapped function ID.
2. Forms an address four bytes beyond D-01’s returned value.
3. Calls **F-b37968c9f644** with that address and the selector, in that argument order.
4. If the check returns zero, calls **F-a817d8d58c10**.

This sequence also occurs for inputs that will subsequently return 5. Encoding rejection does not bypass prerequisite processing.

The supplied material annotates F-a817d8d58c10 as nonreturning, but its implementation is unavailable. Its nonreturning behavior is therefore not independently established. If it does not return, classification never begins. If it returns normally, the displayed control flow continues into classification; it does not explicitly return a special result for prerequisite failure.

No assumption is made that any of these dependencies preserves shared state. Classification reads occur after this sequence and therefore use the state then observable.

### 2. Family with lowest five bits zero

This family applies when the encoded value, masked by 0x1F, is zero.

The function extracts bits 5–15 by masking the encoded value with 0xFFFF and shifting right by five. The extracted value ranges from 0 through 2047. It compares this value with S-A.

- If unequal, return **5**.
- If equal, classify the encoded value masked by **0x00FE0000**, selecting bits 17–23.

The selected field determines the next action:

| Masked field | Action |
|---|---|
| 0x00020000 | Call F-46e37d8455ab with the selector and the complete encoded value. Return 4 for any nonzero result; otherwise return 0. |
| 0x00040000 | Same dependency call and result mapping. |
| 0x00060000 | Return 0 without that dependency call. |
| Any other value | Return 1 without that dependency call. |

Bit 16 does not participate in either extraction above. Bits 24–31 also do not affect these local comparisons. Nevertheless, when F-46e37d8455ab is called, it receives the full encoded value, including those bits. Their significance to that dependency is unknown.

No record-table access is visible in this family.

### 3. Family with lowest five bits nonzero

This family applies when at least one of the encoded value’s lowest five bits is set.

The function multiplies the unsigned 32-bit encoded value by **65536**, using the 32-bit result, and compares that result with S-B. Equivalently, the comparison value contains the input’s lower 16 bits shifted into the upper half of a 32-bit word; the original upper 16 bits are discarded.

- If unequal, return **5**.
- If equal, inspect a record using the selector and S-T.

The multiplication is not an unbounded mathematical multiplication. For example, encoded values 0x00000001 and 0xABCD0001 both produce comparison value 0x00010000.

#### Record address and conditional reads

The function reads S-T and forms a record address by adding eight times the selector. The visible address arithmetic uses a 32-bit address-sized intermediate. This describes address formation, not a guarantee that the resulting address is valid.

Reads proceed in this order:

1. Read the byte at record offset **5**.
2. Only if that byte is nonzero, read the byte at offset **6**.
3. Only if both preceding bytes are nonzero, read the byte at offset **7**.
4. Only if all three bytes are nonzero, read S-T again, recompute the selector’s record address, and read the byte at offset **0**.

Offsets 1–4 are not read by this visible logic.

The first three bytes are tested only for zero versus nonzero. Their signed interpretation does not alter those tests. The byte at offset 0 is treated as an unsigned value from 0 through 255.

The second S-T read matters to the contract: the final byte read is based on the base value obtained at that later read. No stable-table or concurrent-update guarantee is established.

#### Direct result 2

If all three bytes at offsets 5, 6, and 7 are nonzero, compare the offset-0 byte with the encoded value shifted right by 24 bits.

If they differ:

- Return **2**.
- Do not call F-5449900ee365.

This comparison uses the encoded value’s uppermost byte, ranging from 0 through 255.

#### Remaining record cases

Call **F-5449900ee365** with the complete encoded value if either:

- Any of the three condition bytes is zero; or
- All three are nonzero and the offset-0 byte equals the input’s uppermost byte.

Then:

- Return **1** if the dependency returns exactly 9.
- Return **0** for every other returned integer value.

A nonzero return other than 9 does not produce result 1 here. This differs from F-46e37d8455ab’s zero-versus-nonzero mapping.

## Side effects

### Directly visible effects

F-eef328c1181f performs shared-state and record-memory reads. It makes no explicit shared-state write or record-memory write in the supplied representation.

Its observable interactions include:

- The unconditional context-producing call.
- The unconditional prerequisite-check call.
- A conditional call after a zero prerequisite result.
- Family-dependent shared-state reads.
- Ordered, short-circuited record-byte reads.
- At most one of the two normal classification dependencies after prerequisite processing.

The visible local logic does not allocate, release, retain, or transfer ownership of memory.

### Dependency effects

The absence of direct writes does not establish that the whole operation is read-only. Any dependency may have effects not visible here, including modifying shared state, affecting memory lifetime, or terminating execution.

In particular:

- D-01’s returned value is used for address formation, but no ownership transfer is established.
- F-b37968c9f644 receives an address derived from that value; its permitted access and lifetime requirements are unknown.
- No preservation of S-A, S-B, or S-T across prerequisite calls is assumed.
- No allocation or release behavior is attributed to any dependency without its contract.

### Invalid state and memory

There is no visible local recovery for an invalid context-derived address, invalid table base, out-of-range selector, or unreadable record byte. The representation does not establish whether such situations fault, are intercepted elsewhere, or are excluded by caller preconditions.

Short-circuiting limits the required reads. A zero at offset 5 prevents reads at offsets 6, 7, and 0. It does not establish that the whole record is valid or readable.

## Acceptance examples

These are conditional contract examples, not executed tests. Except where stated otherwise, assume prerequisite processing returns normally, required memory is valid, and shared state has the stated value when read.

1. **Zero-low-bits comparison failure.**  
   With encoded value 0x00000020, the extracted comparison value is 1. If S-A is not 1, return 5 without calling either normal classification dependency.

2. **Selected dependency reports nonzero.**  
   With encoded value 0x00020020 and S-A equal to 1, call F-46e37d8455ab with the original selector and 0x00020020. A return of −1, 1, or any other nonzero integer produces result 4.

3. **Same selected dependency reports zero.**  
   Under the preceding conditions, a dependency return of zero produces result 0.

4. **Direct zero result.**  
   With encoded value 0x00060020 and S-A equal to 1, return 0 without either normal classification dependency.

5. **Other field value.**  
   With encoded value 0x00000020 and S-A equal to 1, return 1. The selected bits 17–23 are zero, which is outside the three special field values.

6. **Unsigned multiplication discards upper bits.**  
   Encoded values 0x00000001 and 0xABCD0001 both require S-B to equal 0x00010000 to enter record processing. Their later upper-byte comparisons differ: 0x00 versus 0xAB.

7. **First condition byte is zero.**  
   For an accepted nonzero-low-bits input, if record offset 5 is zero, do not read offsets 6, 7, or 0. Call F-5449900ee365. Return 1 for result 9 and 0 for result 8.

8. **Second condition byte is zero.**  
   If offset 5 is nonzero and offset 6 is zero, do not read offset 7 or offset 0. Continue through F-5449900ee365.

9. **All conditions set, upper byte differs.**  
   For encoded value 0xAB000001, with S-B equal to 0x00010000 and offsets 5–7 all nonzero, an offset-0 value of 0xAC produces result 2. F-5449900ee365 is not called.

10. **All conditions set, upper byte matches.**  
    Under the preceding conditions, an offset-0 value of 0xAB causes F-5449900ee365 to be called. Exactly 9 produces result 1; all other returned values produce result 0.

11. **Prerequisite failure precedes rejection.**  
    Even if the encoding would fail its shared-state comparison, a zero prerequisite result first invokes F-a817d8d58c10. If that dependency does not return, no classification result is produced.
