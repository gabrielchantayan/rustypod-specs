# F-4bee99d148b1

## Purpose

F-4bee99d148b1 translates a 32-bit selector into two 32-bit output words and one trailing output byte. The translation is fixed: it does not depend on the previous destination contents.

A null destination causes an immediate return without writing output. With a valid non-null destination, every selector produces a complete three-field result. Unrecognized selectors produce zero in all three fields; they do not cause an explicitly reported error.

The output resembles a split bit mask plus a classification byte. That interpretation is **inferred intent**, not an established semantic meaning. The established behavior is the exact selector-to-field mapping below. In particular, the trailing byte must not be interpreted as a generic success indicator: many recognized selectors produce a trailing byte of zero.

There is no established scalar return value. Output is communicated through destination writes only. There is no output-size argument and no explicit error-status output.

### Access order and replacement semantics

For every valid non-null destination, the established write order is:

1. Write the complete 32-bit first word at offset 0.
2. Write the complete 32-bit second word at offset 4.
3. Write the marker byte at offset 8.

No existing destination field is read to compute the result. The function replaces each field rather than combining the result with prior contents. A zero-valued field is written explicitly; it is not left unchanged.

At completion, at least one of the two words is zero for every selector. The marker is one exactly for selectors 11, 22, 26, 27, 29, 36, 43, and 44; it is zero otherwise.

These are source-level access-order statements. They do not establish an atomic nine-byte update, hardware transaction boundaries, or synchronization guarantees for concurrent observers.

### Widths and arithmetic

Both words contain 32-bit values. The largest first-word constant is 0x40000000, and the largest second-word constant is 0x00800000. Every listed value fits within its field without truncation.

There is no established selector arithmetic, overflow handling, or saturation behavior. The operation consists of selecting fixed values and storing them at fixed offsets. Treating the two words as one 64-bit integer is not required by this contract and would introduce an interpretation not established by the evidence.

## Side effects

The only explicit externally visible state changes in the supplied evidence are the destination writes.

For a valid non-null destination:

- The function writes four bytes at offset 0, four bytes at offset 4, and one byte at offset 8.
- It overwrites all three fields regardless of their prior values.
- It does not explicitly access bytes beyond offset 8.
- It does not read or write explicit global state.
- It performs no explicit allocation, deallocation, logging, file access, or other external operation.

The caller supplies and retains the destination storage. There is no visible ownership transfer, storage retention, or release operation. The destination need not contain an initialized result before the call.

A null destination is the only explicitly handled invalid-storage case. A non-null pointer is not checked for capacity, writability, alignment, or lifetime. If those preconditions fail, the supplied evidence does not define a recoverable error result, fault behavior, or rollback guarantee.

Because the result is written through three ordered field writes, consumers must not assume that another observer can only see the complete old result or complete new result.

## Acceptance examples

These are conditional acceptance criteria derived from static evidence, not reports of executed tests.

1. **Null destination, recognized selector.** Given selector 11 and a null destination, the function returns without attempting any result write. It does not attempt to store the otherwise applicable marker value of one.

2. **Complete overwrite of prior contents.** Given valid storage whose first word, second word, and marker are all nonzero, selector 0 leaves those three fields equal to zero. Retaining any old field value would violate the contract.

3. **Default selector handling.** Given selector 45 and valid storage, the result is first word 0x00000000, second word 0x00000000, marker zero. The same result applies to the 32-bit selector value 0xFFFFFFFF.

4. **Marker set with a first-word result.** Given selector 11, the result is first word 0x00000100, second word 0x00000000, marker one. Producing marker zero merely because the second word is zero would be incorrect.

5. **Second-word result without a set marker.** Given selector 28, the result is first word 0x00000000, second word 0x00000001, marker zero. A rule that marks every nonzero second-word result with one would fail this case.

6. **Second-word result with a set marker.** Given selector 29, the result is first word 0x00000000, second word 0x00000002, marker one.

7. **Equivalent selectors.** Under identical valid destination conditions, selectors 7 and 32 each produce first word 0x00000004, second word zero, and marker zero. Their results do not depend on which selector was used previously.

8. **Composite first-word value.** Given selector 42, the first word is exactly 0x00000041, with the second word and marker both zero. Substituting a single-bit result is not acceptable.

9. **Trailing-byte boundary.** Given a larger valid writable buffer and selector 44, the result fields become first word zero, second word 0x00800000, and marker one. Bytes beginning at offset 9 remain unchanged by the function’s explicit writes.

10. **Field-write order.** In an environment capable of observing the source-level write sequence, the first-word write precedes the second-word write, which precedes the marker-byte write. This criterion does not assert atomic visibility to unsynchronized concurrent readers.
