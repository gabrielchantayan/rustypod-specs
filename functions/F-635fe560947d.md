# F-635fe560947d

## Purpose

F-635fe560947d repeatedly selects and processes portions of an input sequence, updates a caller-supplied context, and optionally creates one metadata record per admitted iteration.

Selection combines an unsigned capacity result, classifications of successive values returned by a pointer-taking dependency, and, for certain selections, classification of an integer loaded through a selected pointer. The numerical amount passed for processing can differ from the amount deducted from the remaining count.

These are operational descriptions. Sequence encoding, element boundaries, traversal direction, coordinate units, and the meanings of the dependency results are not established. In particular, describing dependency calls as decoding adjacent elements requires an additional dependency contract.

## Behavior

### Initial state and collection dispatch

Before any dependency call, the routine calculates a fixed span from bounds offset `+0x0c` minus bounds offset `+0x04`. Later changes to the bounds do not recalculate that span.

The initial remaining count is the signed interpretation of input 3’s low 16 bits, represented in a 32-bit working quantity:

- `0x0000` gives zero.
- `0x0001` through `0x7fff` give positive values.
- `0x8000` through `0xffff` give negative values.
- The upper 16 bits have no direct effect on this initialization.

If a collection exists, its field at `+0x04` is tested as signed. A positive value causes dispatch through table offset `+0x40`, with the collection and zero as arguments. The first 32-bit word at the returned address is then passed to F-feee9156a257. That call is annotated non-returning; no continuing normal path is established for this branch.

For a nonpositive collection field, dispatch through table offset `+0x30` receives the collection. There is no visible loop removing existing entries.

### Context and auxiliary initialization

F-7ec5c59748e6 receives the context. Its result plus input 6 becomes the fixed per-iteration advance.

Context initialization has an observable capture boundary:

1. The bounds word at `+0x04` is captured.
2. F-f445983e29a8 receives the address of context storage at `+0x20`.
3. The bounds word at `+0x00` is read and added to that dependency’s result.
4. The sum is stored at context `+0x04`.
5. The previously captured bounds word is stored at context `+0x00`.

Consequently, a dependency that changes the bounds can affect the later first-word read without changing the earlier captured second word.

When an auxiliary object exists, its `+0x2c` field is increased by the advance, and its `+0x30` field is assigned the advance. F-8157a180d901 then receives a request for `0x18` bytes. Its result and the auxiliary-object pointer are passed to F-766f4e9f2b42.

The latter result becomes the optional wrapper. A null result is supported by subsequent branches: it suppresses wrapper-dependent progress handling and final wrapper handling. The routine does not establish allocation-failure recovery or ownership transfer.

F-42388505f940 is then called with the address obtained by reading context `+0x1c` and adding four bytes.

This setup occurs even when the initial remaining count is nonpositive, provided the earlier calls return.

### Iteration admission and stopping

Admission checks occur in the following order:

- A remaining count less than one, interpreted as signed 32-bit, stops the loop.
- Otherwise, processing stops if the current context `+0x04` exceeds the current bounds `+0x08` plus the fixed advance.
- Otherwise, F-40859ed81aa5 receives the context, current sequence pointer, remaining count masked to 16 bits, fixed span, and zero.
- A zero unsigned 32-bit capacity result stops the loop.

Equality at the position boundary permits the capacity call. The position check reads live bounds and context values, whereas the span remains the initial calculation.

On stopping, F-d9bb88a0a8d3 receives the address obtained from a fresh read of context `+0x1c`, plus four bytes. It need not receive the same address as F-42388505f940.

Without a wrapper, the routine then returns. With a wrapper, F-d0d3f100effc receives its address at `+0x04`; four is subtracted from the returned value, and that result is passed to F-feee9156a257. The latter call is annotated non-returning.

### Pointer snapshots and classification search

For an admitted iteration, the current sequence pointer is retained as the segment-start pointer. A separate tracked pointer initially has that same value.

F-2be305f439e7 receives the address of the working cursor and returns an initial value. Its access to that pointer slot permits it to change the cursor. The visible body does not establish whether it changes the cursor, whether any change is forward, or whether it reads an encoded element.

The comparison index starts at zero. The provisional selected amount starts at the unsigned capacity. No classified boundary is initially selected.

A comparison is attempted only while both conditions hold:

- The index is less than the unsigned capacity.
- Its signed interpretation is less than the remaining count minus one.

For each attempted comparison, the routine captures the cursor value immediately before another call to F-2be305f439e7. It then passes the preceding returned value and the newly returned value, in that order, to F-f684e1462ef9.

The classification controls selection:

- Result `1` selects the current index and the current tracked pointer, then ends the search.
- Result `2` selects that index and tracked pointer as a replaceable candidate, but only when capacity differs from the remaining-count value.
- Other results do not create a new candidate.

After a comparison that does not terminate the search, the index is incremented and masked with `0xfffeffff`. The tracked pointer becomes the cursor snapshot captured before that comparison’s F-2be305f439e7 call. The newly returned value becomes the preceding value for the next comparison.

Thus, the tracked pointer is not unconditionally the latest cursor value. Its relationship to returned values or sequence elements requires a dependency contract.

A later eligible result `2` replaces an earlier candidate. Result `1` overrides any candidate and ends the search. If no boundary is selected, the amount remains capacity.

The selected-pointer slot initially contains null. After searching, if that slot is null, it is replaced with the current tracked pointer. This fallback also applies when classification selected a pointer whose value happened to be null; the selected amount and boundary-selected flag are not cleared by that substitution.

The mask clears bit 16, not all bits above bit 15. During the search, the positive remaining-count limit keeps the index below the affected bit.

### Processing amount and deducted amount

A selected amount of zero skips F-5f277fc1f85f entirely. It also skips the selected-pointer integer load and F-191acd2fadfa.

For a nonzero selected amount without a classified boundary, the processing amount is the selected amount.

For a nonzero selected amount with a classified boundary:

- The routine loads a **32-bit integer** through the selected pointer.
- That loaded integer is converted through the target’s plain-character type.
- The converted value is supplied to F-191acd2fadfa.
- A nonzero result leaves the processing amount equal to the selected amount.
- A zero result increases the processing amount by one.

This is not a byte-sized memory read. Equivalence to reading a byte at the selected address is not established without target representation and conversion rules. Plain-character signedness and conversion behavior for unrepresentable values remain unresolved.

F-5f277fc1f85f receives the context, saved segment-start pointer, processing amount masked with `0xfffeffff`, fixed span, input 5, and zero.

The amount deducted from the remaining count is determined separately:

- If the selected amount is less than capacity, it is incremented and masked with `0xfffeffff`. F-2be305f439e7 is then called with the address of the selected-pointer slot; its return value is ignored.
- Otherwise, the selected amount and selected pointer are retained without this additional call.

The resulting numerical amount is used for progress and count deduction. Calling it “consumed” does not establish how far any pointer moved or how many encoded elements were traversed.

### Progress, records, and next-iteration state

When a wrapper exists, its first pointer-bearing word is read, and the deducted amount is added to the 32-bit field at `+0x34` in the reached object. The source does not prove that this object is the original auxiliary object.

When a collection exists, F-8157a180d901 receives a `0x10`-byte request. The returned record is populated in this order:

| Offset | Stored value |
|---|---|
| `+0x00` | Saved segment-start pointer |
| `+0x04` | Current context `+0x00` |
| `+0x08` | Current context `+0x04` |
| `+0x0c` | Current wrapper-reached progress, only when a wrapper exists |

Without a wrapper, the fourth word is not initialized by this routine.

Collection dispatch at table offset `+0x1c` receives the collection and the address of the local record-pointer slot. This is a pointer-to-pointer argument. No subsequent use establishes what the dispatch did with that pointer or allocation.

After dispatch returns, or immediately after progress handling when no collection exists:

- Context `+0x00` is assigned the current bounds `+0x04`.
- Context `+0x04` is increased by the fixed advance.
- The working cursor is replaced by the selected-pointer value, including any change made by the additional F-2be305f439e7 call.
- The deducted amount is subtracted from the remaining quantity; the low 16 bits of the result are retained and sign-extended.

The cursor used during the search is therefore superseded at the iteration boundary. Records capture context fields before the final reset and advance, but after earlier dependencies may have modified them.

## Side effects

Direct writes include context initialization, auxiliary-field initialization, wrapper-reached progress updates, record initialization, and end-of-iteration context updates.

The visible routine does not directly write sequence storage. Records contain sequence pointers, not copies of pointed-to data.

Optional allocation consists of one `0x18`-byte request during auxiliary setup and one `0x10`-byte request per admitted iteration when a collection exists. No explicit record release follows collection dispatch. Allocation ownership, retention, copying, and release by dependencies are unknown.

Dependency calls may have additional effects. No preservation of globals, bounds, context, auxiliary state, or aliased memory is assumed. In particular, live reads after calls must not be replaced contractually with earlier snapshots.

Count masks, unsigned increments, and unsigned subtraction have 32-bit modular effects. Wrapper progress addition uses the unsigned deducted amount and produces a 32-bit result. Signed span, coordinate, and advance calculations lack an established overflow policy; this contract does not promise wrapping for those calculations.

There is no explicit error result, rollback, or recovery path.

## Acceptance examples

These are conditional static expectations, not executed tests. Unless stated otherwise, they assume valid accesses, returning dependencies where continuation is described, and representable signed arithmetic.

1. **Nonpositive initial count.** Input 3 with low half `0x8000` still permits initialization and F-42388505f940. Admission then stops without a capacity call or search call.

2. **Position equality and zero capacity.** Equality between context `+0x04` and bounds `+0x08` plus advance permits F-40859ed81aa5. A zero result stops without search, processing, progress increment, or record allocation for that iteration.

3. **Immediate result `1`.** With positive capacity and at least two remaining count units, the first pair classification returning `1` selects amount zero. Processing and boundary-integer classification are skipped. The deducted amount becomes one, and F-2be305f439e7 receives the selected-pointer slot. One-element traversal is not implied.

4. **Different processing and deducted amounts.** With capacity five and a boundary selected at index two, a nonzero F-191acd2fadfa result yields processing amount two and deducted amount three. A zero result yields three for both. Either case requires a readable 32-bit selected location.

5. **Insufficient readable storage.** For that same nonzero classified selection, having only one readable byte at the selected address does not satisfy the visible access requirement.

6. **Null candidate fallback.** If classification records a null pointer, the final null check substitutes the then-current tracked pointer. Selection remains classified, so a nonzero selected amount still follows the integer-load classification path.

7. **Capacity three, remaining count five, no selected boundary.** Three pair comparisons occur, requiring four search calls to F-2be305f439e7 including the initial call. Processing and deducted amounts are three. The next cursor is the snapshot captured before the fourth search call. **Only if** the dependency returns the element at its incoming cursor and advances exactly one element per call may this be described as fourth-element lookahead with the next segment beginning at that fourth element.

8. **Metadata without a wrapper.** A supplied collection receives a record with its first three words initialized. The fourth word is not initialized by this routine, regardless of whether its underlying allocation contains incidental data.

9. **Positive collection field.** A positive initial collection field causes dispatch `+0x40`, a 32-bit read through its result, and F-feee9156a257. Continuing initialization is not established.
