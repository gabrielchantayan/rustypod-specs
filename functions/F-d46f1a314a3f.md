# F-d46f1a314a3f

## Purpose

F-d46f1a314a3f obtains an initial integer result from a dependency, optionally performs work associated with a caller-provided word, and either returns the initial result or obtains a replacement result from another dependency.

Its established behavior concerns dependency selection, argument relationships, memory-access ordering, and result selection. The available evidence does not establish a domain operation such as allocation, copying, decoding, or formatting.

Three rules determine the externally relevant outcomes:

- An initial result of exactly −1 produces a return value of zero, without subsequent dependency calls or direct access through the optional word reference.
- A status of 16, 17, or −3 selects the **direct-result category**. Every other status selects the **converted-result category**.
- A null word reference suppresses word-associated work, but does not suppress conversion when the converted-result category applies.

“Context,” “descriptor,” “position,” and “selector” are descriptive labels, not established application types.

## Interface

### Inputs

| Input | Representation and contractual use |
|---|---|
| **Context** | An opaque 32-bit quantity forwarded unchanged as the first argument of each invocation of F-f75738ed2bcb. |
| **Position reference** | A nullable reference to a 32-bit integer word. Applicable paths pass the reference to F-208392f0520a and directly read and update the referenced word. |
| **Descriptor address** | A 32-bit integer-represented address. A 32-bit field at byte offset 4 supplies the initial status. The address is also forwarded to F-f75738ed2bcb. |
| **Selector** | A 32-bit integer. Exactly −1 requests use of the status observed after the initial dependency invocation. Every other value is retained. |
| **Auxiliary value** | A 32-bit integer quantity supplied to the preparation dependency and used as a later dependency argument on converted-result paths. Its interpretation is unknown. |

The supplied representation supports these integer widths. It does not establish a complete calling convention, a general pointer width, or platform-specific address conversion and alignment rules.

### Result

The function returns a 32-bit integer:

- Zero when the initial dependency result is −1.
- The initial dependency result for a continuing direct-result invocation.
- The result of F-1393b2e3d099 for a continuing converted-result invocation.

“Continuing” means that the initial result is not −1. An initial result of zero continues normally. Negative results other than −1 also continue.

There is no additional interpretation of the returned conversion result. In particular, a conversion result of −1 is returned as −1 rather than changed to zero.

### Storage and validity requirements

The only directly accessed descriptor field occupies four bytes beginning four bytes beyond the descriptor address. It is read once, before the initial dependency invocation. No other descriptor field access or direct descriptor write is established.

A private 32-bit status word receives that field’s value. Each invocation of F-f75738ed2bcb receives the address of this same private word.

On a continuing invocation with a non-null position reference, the function directly reads the referenced 32-bit word twice and writes it once. The first read supplies a dependency argument. The second read supplies the base for the update.

Normal execution requires:

- A readable descriptor field before the initial dependency invocation.
- Readable and writable position storage whenever the continuing, non-null path reaches its direct accesses.
- Continued validity of storage needed after dependency calls.
- Dependencies that accept the supplied arguments and return normally for the remaining behavior to occur.

The initial-result −1 path makes no direct position access. A non-null position reference therefore does not, by itself, imply that this function dereferences it on every invocation.

The function provides no visible validation or lifetime repair if a dependency invalidates storage required later.

## Behavior

### Status categories and selector selection

The relevant status is the private status word as observed after the initial F-f75738ed2bcb invocation. It need not equal the descriptor field originally read: that dependency receives the private word’s address and may change it.

The categories are exhaustive:

| Observed status | Category |
|---|---|
| 16, 17, or −3 | Direct-result |
| Any other 32-bit integer | Converted-result |

There is no unresolved category or ordinary status value that leaves result selection unspecified.

For a continuing invocation, an input selector of −1 is replaced by this observed status. Otherwise, the selector is unchanged. This establishes the **effective selector** used by subsequent dependencies.

The replacement happens only once. If the observed status is itself −1, an input selector of −1 remains −1.

The category and effective selector are fixed before any preparation or later F-f75738ed2bcb invocation. Later changes to the private status word do not revise either decision.

### Initial failure boundary

An initial dependency result of exactly −1 overrides the status category. The function returns zero and performs none of the following:

- Preparation through F-208392f0520a.
- A second invocation of F-f75738ed2bcb.
- Direct position reads or writes.
- Conversion through F-1393b2e3d099.

This is not a rollback boundary. The descriptor read and initial dependency invocation have already occurred, and any effects of that invocation remain possible.

The same special treatment does not apply to the second F-f75738ed2bcb invocation or to conversion.

### Continuing outcomes

For an initial result other than −1, the required behavior is:

| Category | Position reference | Required additional behavior | Result |
|---|---|---|---|
| Direct-result | Null | No additional dependency invocation | Initial result |
| Direct-result | Non-null | Second F-f75738ed2bcb invocation and position update | Initial result |
| Converted-result | Null | Conversion only | Conversion result |
| Converted-result | Non-null | Preparation, second F-f75738ed2bcb invocation, position update, then conversion | Conversion result |

Preparation is exclusive to the converted-result, non-null case. Conversion is required for every continuing converted-result invocation, including those with a null position reference.

The second F-f75738ed2bcb result is discarded. It cannot replace the initial result, prevent the position update, or suppress conversion merely by returning an error-like value.

### Position update

A continuing invocation with a non-null position reference updates the word by adding the initial result to the value read **after** the second F-f75738ed2bcb invocation returns.

The earlier word value supplied to that dependency is not the saved addition base. Consequently:

- Preparation can influence the argument supplied to the second invocation.
- The second invocation can influence the base of the subsequent addition.
- The increment remains the initial result, regardless of the second invocation’s return.

For example, if preparation leaves the word at 40, the second invocation receives 40. If that invocation changes the word to 90 and the initial result is 5, the function’s direct write stores 95, not 45.

Both operands and the directly written result are represented as 32-bit integers. No overflow check or saturation is visible. The applicable behavior when the mathematical sum lies outside the signed 32-bit range is unresolved.

An initial result of zero does not eliminate the word accesses or dependency invocation. The function still reads the post-call word and writes the result of adding zero.

Conversion, when required, occurs after the direct position write. Because its effects are unknown, the value written by this function is not necessarily the value present when the function returns.

## Side effects

### Observable memory ordering

The established direct-access ordering is:

- The descriptor field read precedes all dependency invocations.
- The private status word is initialized before its address is passed to the initial dependency.
- Any preparation completes before the direct position read supplying the second dependency invocation.
- That invocation completes before the position word is read again and updated.
- Any conversion follows the position update.

The descriptor field is not directly reread. A later change to descriptor memory therefore does not itself refresh the private status word. Dependencies can nevertheless modify that private word through its supplied address or another route made available by a dependency.

No atomic update or synchronization protocol is established. The position accesses are separate reads and a write.

### Ownership and lifetime

No direct allocation, release, ownership transfer, or cleanup operation is established for F-d46f1a314a3f itself.

This does not imply that its dependencies preserve memory, ownership, or global state. Their unavailable contracts do not justify assuming preservation of:

- The position word or descriptor contents.
- Other reachable storage or globals.
- Object ownership.
- Storage validity required by subsequent accesses.

The private status address refers to invocation-local storage. Its use during the shown dependency invocations is established; permission to retain it, and any valid use after the invocation ends, are not.

Preparation does not receive the private status address directly. That alone does not prove preservation: the initial dependency could have made the address reachable elsewhere.

### Errors and partial completion

The only explicit failure-like rule is replacement of the initial result −1 with zero.

There is no visible recovery based on a preparation result, the second dependency result, or the conversion result. There is also no visible rollback after partial external effects.

Invalid accesses, abnormal dependency termination, and arithmetic behavior outside the applicable execution model do not have established normal-return outcomes.

## Acceptance examples

These are conditional acceptance cases derived from static evidence, not recorded executions. They assume normal dependency returns, valid required storage, and representable arithmetic unless stated otherwise.

### Initial failure excludes all later work

Suppose the initial result is −1 and the observed status is 16. Even with a non-null position reference, the required result is zero, with no preparation, second invocation, conversion, or direct position access.

Changing the observed status to any other value does not change this outcome. Effects of the initial invocation remain possible.

### Direct result with a position update

Suppose the initial result is 6, the observed status is 17, and the position reference is non-null. The word supplied to the second invocation is 100, and that invocation leaves the word at 100.

The second invocation receives the descriptor address as its final argument. The direct position write stores 106. Neither preparation nor conversion occurs, and the function returns 6.

Statuses 16 and −3 have the same category behavior.

### Preparation and post-call state both matter

Suppose the initial result is 5, the observed status is 4, and the input selector is −1. Preparation leaves the position word at 40. The second invocation changes it to 90 and returns −1.

The effective selector is 4. Preparation receives that selector and the auxiliary value. The second invocation receives 40 as its second argument and the auxiliary value as its final argument.

The direct write stores 95. The discarded −1 result does not trigger early failure. Conversion receives zero, 5, and 4; its result is returned. A final position value of 95 is guaranteed only if conversion does not subsequently change it.

### Later status changes do not reclassify the invocation

Suppose the initial result is 8, the observed status is 9, and the selector is −1. If the second invocation changes the private status to 16, conversion is still required with effective selector 9.

Conversely, an observed status of 16 remains direct-result behavior even if the second invocation changes the private status to 9.

### Null position reference preserves conversion requirements

Suppose the initial result is 12 and the position reference is null.

With status −3, no further dependency is required and the result is 12. With status 2, conversion is required and its result is returned. Neither case directly accesses position storage.

### Exact sentinel and zero boundaries

Suppose the initial result is −2, the status is 16, and the second invocation leaves the position word at 20. The direct write stores 18, and the result is −2.

If the initial result is instead zero, the same non-null direct-result path still requires the second invocation and direct word update; zero is not an early-exit sentinel.

If both the input selector and observed status are −1 while the initial result is 3, the category is converted-result and the effective selector remains −1. If conversion returns −1, the function returns −1 unchanged.
