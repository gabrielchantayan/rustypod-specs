# F-9fad63590e30

## Purpose

F-9fad63590e30 interprets selected bytes of an input sequence as date/time-like fields and passes those fields, a month-table entry, and a suffix object to a formatting dependency. It returns a normalized 32-bit success indicator.

Its established behavior is not strict timestamp validation:

- The first twelve bytes undergo an upper-bound check that admits bytes below ASCII `0`.
- Only the derived month is range-checked.
- Day, hour, minute, year, and optional seconds receive no calendar or clock validation.
- Optional seconds reads are not bounded by the declared length.
- The last declared byte selects between two suffix objects.
- Local rejection produces a fixed diagnostic; an unsuccessful formatting result does not.

Rendering a compact timestamp is inferred intent. The available evidence does not establish exact output text, time-zone conversion, or how the formatting dependency interprets numeric argument words.

## Behavior

### Initial access and length gate

The function first reads the input address from descriptor offset 8. It retains that address for subsequent input accesses.

It then reads the signed 32-bit declared length. A value greater than 11 permits parsing. Every other value, including zero and negative values, takes the diagnostic path without reading input bytes.

The minimum accepted declared length is therefore 12. That gate does not bound later input accesses.

### Leading-byte screen

Input offsets 0 through 11 are examined in increasing order. Each byte is promoted to an integer, 48 is subtracted, and the result is compared against 9.

Rejection occurs when that result exceeds 9. There is no corresponding lower-bound check.

Consequently:

| Byte values | Result |
|---|---|
| Hexadecimal `00` through `2F` | Pass |
| ASCII `0` through `9`, hexadecimal `30` through `39` | Pass |
| Hexadecimal `3A` through `FF` | Reject |

The first rejected byte ends the scan. No later byte is read by this screening loop. Rejection invokes F-8d1c9f620c59 and returns 0.

Passing this screen does not establish decimal syntax. In particular, NUL, whitespace, punctuation below `0`, and slash are not rejected by this comparison.

### Month calculation and acceptance

After the complete leading screen passes, offsets 4 and 5 are read again.

For mathematical description, define the month value as:

**10 × (byte 4 − 48) + (byte 5 − 48).**

The actual expression includes unsigned 32-bit arithmetic. Its intermediate word corresponds to the mathematical month plus 48. The subsequent unsigned 32-bit comparison accepts exactly mathematical month values 1 through 12.

For stable bytes admitted by the screen, the mathematical month can range from −528 through 99. Values outside 1 through 12 take the diagnostic path.

Ordinary decimal pairs `01` through `12` are accepted, but they are not the only accepted spellings. For example, `1/` computes to 9 and passes.

The accepted month determines a zero-based table index of month minus one. It does not immediately establish the table entry’s contents or interpretation.

### Optional seconds

The seconds local initially contains zero.

The function reads offset 12 and checks whether its integer value minus 48 is less than 10. This admits all byte values from hexadecimal `00` through `39`, including values below ASCII `0`.

If that check fails, offset 13 is not read by the seconds logic and seconds remain zero.

If it passes, offset 13 is read once and retained. This second byte must be within ASCII `0` through `9`, inclusive. A failing second-byte check also leaves seconds zero.

If both checks pass, offset 12 is read again. The retained offset-13 byte and the newly read offset-12 byte produce the mathematical value:

**10 × (byte 12 − 48) + (byte 13 − 48).**

The calculation includes unsigned 32-bit arithmetic and stores its result into a signed 32-bit local. For stable input satisfying these checks, the signed local ranges from −480 through 99. Negative values have the corresponding modulo-\(2^{32}\) argument words.

Failure of either optional check is not a local validation error. It causes neither a diagnostic nor rejection.

These accesses are independent of the declared length once the month has been accepted. A declared length of 12 still causes the offset-12 read and may cause both the offset-13 read and the second offset-12 read.

### Suffix selection

After optional-seconds processing, the function reads the descriptor’s declared length again. It uses that value, not a retained copy of the initial length, to read the final declared byte.

- ASCII uppercase `Z`, hexadecimal `5A`, selects one fixed suffix object.
- Every other byte selects a different fixed suffix object.

Lowercase `z` does not match. No other trailing syntax is validated.

The input address remains the address obtained at entry. Thus, if the descriptor changes during execution, the final-byte access combines that retained input address with the later length value. No synchronization or consistency check is provided.

The suffix contents are unavailable. This selection establishes neither emitted suffix text nor time-zone conversion.

### Numeric values and argument-word representation

Day, hour, and minute use these input pairs:

| Field | Byte offsets |
|---|---|
| Day | 6 and 7 |
| Hour | 8 and 9 |
| Minute | 10 and 11 |

Their mathematical values are:

**10 × (first byte − 48) + (second byte − 48).**

For stable bytes admitted by the leading screen, each mathematical value lies between −528 and 99. The actual expressions include unsigned 32-bit arithmetic, so the arguments are these values reduced modulo \(2^{32}\). For example, a mathematical value of −5 produces argument word `0xFFFFFFFB`, or 4,294,967,291 when described as unsigned.

The year’s mathematical value is:

**1000 × (byte 0 − 48) + 100 × (byte 1 − 48) + 10 × (byte 2 − 48) + (byte 3 − 48).**

The year expression contains signed 16-bit conversions and unsigned 32-bit arithmetic. The 16-bit conversions do not alter the relevant byte-derived values: those operands fit within signed 16-bit range. For stable admitted bytes, the mathematical year lies between −53,328 and 9,999. The final year argument is the corresponding value modulo \(2^{32}\).

Ordinary decimal fields therefore produce their usual nonnegative numeric words, including a four-digit year with leading zeroes. There is no century adjustment. Below-`0` bytes can instead produce large unsigned argument words corresponding to negative mathematical values.

These ranges do not require signed 32-bit overflow. Unsigned wrapping is nevertheless part of the actual field expressions and must not be replaced with an assumption of exclusively signed arithmetic.

Without the formatting object’s contents and the dependency contract, none of these argument words is guaranteed to be interpreted or rendered as signed, unsigned, decimal, or negative. The signed seconds local likewise does not establish the formatter’s interpretation of its argument.

There is no validation of day-of-month limits, leap years, hours below 24, minutes below 60, or seconds below 60.

## Acceptance examples

These are conditional acceptance examples, not executed tests. Unless stated otherwise, descriptor and input storage are stable, all actual reads are valid, and dependency data is available. “Entry 1” means the first table entry, not an entry whose stored value is 1.

1. **Ordinary decimal input.**  
   `20240102030405Z`, declared length 15, reaches formatting with the first month entry, day word 2, hour word 3, minute word 4, seconds word 5, year word 2024, and the uppercase-`Z` suffix object. A positive formatting result yields 1; a nonpositive result yields 0.

2. **No accepted seconds pair.**  
   `202401020304Z`, declared length 13, reaches formatting with seconds zero. Offset 12 contains `Z`, so the seconds logic does not read offset 13. The final-byte comparison selects the uppercase-`Z` suffix object.

3. **Short declared length.**  
   Length 11 invokes the diagnostic dependency and returns 0 without reading input bytes. The input-address descriptor field is still read first.

4. **Upper-bound rejection.**  
   A colon in any leading position 0 through 11 invokes the diagnostic dependency and returns 0. Screening stops at that position.

5. **Rejected decimal months.**  
   Month pairs `00` and `13` pass the byte screen but fail the month check. Each invokes the diagnostic dependency and returns 0 without formatting.

6. **Contrasting malformed month spellings.**  
   `20240:02030405Z` invokes the diagnostic dependency and returns 0 without formatting: its colon at offset 5 fails the leading-byte screen.  
   `20241/02030405Z` passes the screen and computes month 9 from `1/`. It reaches formatting with the ninth table entry.

7. **Unchecked calendar and clock ranges.**  
   `20240299259999Z` reaches formatting with day word 99, hour word 25, minute word 99, and seconds word 99. These values do not cause local rejection.

8. **Negative mathematical seconds.**  
   `202401020304/5Z` reaches formatting. Slash passes the first seconds condition and `5` passes the second. The seconds local is −5, and its argument word is `0xFFFFFFFB`. No negative textual rendering is implied.

9. **Wrapped day argument.**  
   With otherwise accepted input and day bytes `/5`, the mathematical day is −5. The formatting dependency receives day word `0xFFFFFFFB`; interpretation of that word remains unknown.

10. **Declared length does not bound seconds reads.**  
    With declared length 12 and readable backing storage containing `20240102030405`, seconds become 5. Suffix selection examines offset 11, which is `4`, and selects the non-`Z` object. Only twelve readable bytes would not satisfy this path’s access preconditions.

11. **Formatting failure is not local rejection.**  
    If locally accepted input reaches F-912957aafb79 and that dependency returns zero or a negative signed result, the function returns 0 without calling F-8d1c9f620c59.
