# F-c6550d8332dd

## Purpose

F-c6550d8332dd performs a conditional, stateful operation using a caller-supplied object, an opaque 32-bit request value, two controls, and an option byte.

The established behavior has two paths:

- When an entry-state byte is nonzero, the function directly records the request value and returns without calling dependencies.
- When that byte is zero, the function records the option, obtains a required intermediate result, invokes several dependencies, constructs temporary state, conditionally invokes an operation, records the request, and finalizes the temporary state.

“Request,” “construction,” “submission,” and “finalization” are descriptive labels for the observed roles. Their application meaning and resource-management implications are not established.

There is no explicit return value or recoverable error result. A zero result from the initial resolver invokes a dependency annotated in the supplied representation as nonreturning. That annotation is not independent evidence of the dependency’s implementation.

## Behavior

### Entry decision and immediate recording

The first direct object access reads the byte at `0xF4`.

If that byte is nonzero, the function writes the request value to the 32-bit field at `0xEC` and returns. No dependency is invoked on this path. The function does not directly write `0xF0`, read `0xF2`, or construct temporary state.

Every nonzero byte selects this path; its signed interpretation is irrelevant. The entry-state byte is not rechecked later.

### Option recording and resolution

If the entry-state byte is zero, the function first writes the option byte to `0xF0`. It then invokes F-1f46730b1ced with:

1. The address of the embedded region at `0xBC`.
2. The original 32-bit request value.

The resolver’s 32-bit result is tested against zero.

For a zero result, the function invokes F-a817d8d58c10 with no explicit arguments. The supplied representation annotates that dependency as nonreturning. Under that annotation, this path has no normal continuation.

The option write precedes the resolver and the failure call. The function’s request write has not occurred at this point. Dependencies may have performed their own writes; the function provides no rollback.

A nonzero resolver result proceeds without further local validity checks. No ownership or lifetime property follows from the nonzero test.

2. F-bf557f07179f receives the original object address and that returned value.

- No third call to F-fdd8589eca2d occurs.

## Acceptance examples

These are conditional criteria derived from static evidence. They are not executed tests. Unless otherwise specified, required storage is valid and dependencies preceding the stated observation return normally.

1. **Immediate recording.** With an entry byte of `0x80`, the complete request bit pattern must be written to `0xEC`. No dependency may be called, and the option must not be directly written.

2. **Resolution failure.** With a zero entry byte and zero resolver result, the option write must precede F-a817d8d58c10. Under the supplied nonreturning annotation, no later construction, submission, request write, or finalization occurs.

3. **Gate suppression overrides control selection.** With successful resolution and gate result `8`, construction must occur, but submission and the third F-fdd8589eca2d call must not. This holds even if override is nonzero or primary control is zero. The request write must still precede finalization.

4. **Field-derived auxiliary value.** With gate result different from `8`, override zero, and primary control nonzero, submission must receive the 16-bit field value read after the third lookup. A field bit pattern of `0xFFFF` is not replaced with zero.

5. **Zero auxiliary when submission is enabled.** With gate result different from `8`, either nonzero override control or zero primary control must select a 16-bit zero for submission without directly reading `0xF2`. The third lookup and submission call must still occur.

6. **Distinct construction inputs.** If the first two lookups return different bases, construction must receive the byte read from the first base and the 32-bit value read from the second. A later change to the first byte does not replace its already retained value.

7. **Non-Boolean primary control.** With enabled submission, override zero, and primary control represented as `0xFFFFFFFF`, the auxiliary field must be read and the primary control forwarded unchanged.

8. **Late auxiliary mutation.** If the third lookup changes `0xF2` before returning, and the controls select the field-derived auxiliary, submission must use the value read after that lookup rather than an entry-time value.

9. **Finalizer effects remain visible.** If finalization changes `0xEC` through reachable state, that does not violate the required request write. The ordering requirement is the write before finalization, not an unconditional post-return field value.
