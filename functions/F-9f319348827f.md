# F-9f319348827f

## Purpose

F-9f319348827f returns a Boolean-valued, 32-bit result indicating whether a selected bit is set in byte-addressed storage described by a nullable descriptor.

For selectors whose 32-bit signed interpretation is nonnegative, the operation resembles a bounded bitmap query: the selector chooses a byte and then a bit within that byte, with the most significant bit numbered first.

That description is not sufficient for selectors with the high bit set. The byte displacement is derived from a **signed interpretation** of the selector, rounded toward zero after division by eight. Such selectors can therefore select the first byte or bytes before the supplied storage address. The function does not independently reject negative displacements.

The function reports only zero or one. It does not distinguish an absent descriptor, a failed bound comparison, an absent storage address, and a clear bit.

## Interface

### Inputs

The function receives two arguments:

1. **Descriptor address.** A nullable address referring to a record containing at least the fields used below.
2. **Selector.** A 32-bit unsigned value whose complete bit pattern participates in selection.

The relevant recovered record layout is:

| Byte offset | Width | Interpretation |
|---|---:|---|
| 0 | 32 bits | Signed bound used in the eligibility comparison |
| 4 | 32 bits | Not accessed by this function |
| 8 | 32 bits | Storage address, with zero treated as absent |

This is the relevant layout under the supplied 32-bit representation. No meaning is established for the intervening field or for any additional fields.

A nonzero storage address identifies byte-addressed data. The selected byte is read as an unsigned 8-bit value.

### Output

The return value occupies 32 bits and is exactly:

- **1:** The descriptor passes the eligibility comparison, the storage address is nonzero, and the selected bit is set.
- **0:** Any of those conditions is false.

There is no separate status value, error object, or reported byte count.

### Memory preconditions

A null descriptor is supported and requires no descriptor access.

A nonnull descriptor must permit the initial 32-bit bound read. If the comparison succeeds, its storage-address field must also be readable. If that field is nonzero, the selected byte address must be readable.

Passing the comparison does **not** establish that the selected byte lies within an allocated object. In particular, negative byte displacements are possible. The caller remains responsible for the validity of the actual address reached.

Alignment requirements, if any, depend on the execution environment and are not independently established by the supplied evidence.

## Behavior

### Selector interpretation

The selector has two distinct interpretations:

- Its full 32-bit pattern is interpreted as a signed two’s-complement value to derive the byte displacement.
- Its lowest three bits determine the bit position within the selected byte.

Let the signed interpretation be \(s\). The byte displacement is:

\[
d = \operatorname{trunc}(s / 8)
\]

where truncation is toward zero.

The low-three-bit value is:

\[
r = \text{selector} \bmod 8
\]

The tested bit has numeric weight:

\[
m = 2^{7-r}
\]

Thus low-three-bit values zero through seven select weights 128, 64, 32, 16, 8, 4, 2, and 1, respectively.

For nonnegative signed selectors, this is ordinary most-significant-bit-first indexing across consecutive bytes. For negative signed selectors, the byte displacement and within-byte selection must still be computed separately as specified above. They must not be replaced with an unsigned byte index or a signed floor division.

### Eligibility comparison

If the descriptor is null, the function returns zero without reading through it.

Otherwise, it reads the signed 32-bit bound at byte offset zero. Access proceeds only if:

\[
d + 1 \leq \text{bound}
\]

This is a signed comparison. There is no separate requirement that the bound be positive or that the displacement be nonnegative.

The displacement ranges from −268,435,456 through 268,435,455. Consequently, adding one to it remains representable in signed 32-bit arithmetic. The bound comparison does not require an overflowing addition.

For nonnegative displacements, the comparison accepts byte positions strictly below a positive bound. For negative displacements, it can accept zero or negative bounds. The comparison therefore cannot be treated as a general memory-safety check.

If the comparison fails, the function returns zero without accessing the storage-address field or backing data.

### Storage and bit inspection

After a successful comparison, the function reads the 32-bit storage-address field at descriptor byte offset eight.

If that address is zero, the function returns zero and does not read a backing byte.

If it is nonzero, the function reads one unsigned byte at a displacement of \(d\) bytes from that address. A negative displacement selects storage before the supplied address.

The function returns one if the selected byte contains the bit of weight \(m\); otherwise it returns zero. Other bits in that byte do not affect the result.

The readable backing byte is accessed even when its value is zero. There is no preliminary metadata check that could avoid this read once the nonzero storage address and successful bound comparison have been established.

### Observable access order

The established logical access order is:

1. Determine the displacement and bit selection from the selector.
2. Check whether the descriptor is null.
3. For a nonnull descriptor, read its bound.
4. If the signed comparison succeeds, read its storage address.
5. If the storage address is nonzero, read the selected byte.
6. Return the corresponding zero-or-one result.

Only the fields and byte reached by this path are read. There is no second read of the bound or storage-address field in the supplied representation.

This access sequence describes the supplied function logic. It does not establish processor-level ordering, atomicity, or synchronization guarantees.

## Side effects

The function contains no explicit writes to the descriptor, backing storage, or global state. It does not allocate or release memory, transfer ownership, retain an address, invoke a callback, or call another function.

Both input addresses are borrowed for the duration of their relevant accesses. Neither becomes owned by this function.

There is no explicit error-reporting side effect. A failed eligibility condition or zero storage address produces a normal zero result.

An invalid nonnull descriptor or invalid selected byte address is different: the function contains no recovery path for a failed memory access. Whether such an access traps, faults, or has another platform-specific consequence is not established here. It must not be specified as a guaranteed zero return.

No concurrency contract is established. In particular, the function does not provide a consistent snapshot of a descriptor and its backing storage when another agent modifies them concurrently. The same caution applies if the selected byte aliases part of the descriptor.

Reads of device-backed or otherwise side-effecting memory may themselves have external effects. The supplied evidence does not characterize such memory.

## Uncertainties

The field at offset zero appears intended to express a byte count or byte-access limit. The storage-address field appears intended to identify a bitmap with most-significant-bit-first ordering.

Those interpretations fit nonnegative selectors but are not established semantic names or validation guarantees. In particular, the function does not enforce an unsigned bitmap-index domain.
