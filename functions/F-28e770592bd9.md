# F-28e770592bd9

## Purpose

F-28e770592bd9 updates six fields in caller-designated storage. The fields form two corresponding groups of three. Two preparation dependencies produce temporary values from a shared input; a combining dependency supplies the results used to replace the first group with differences and the second group with sums.

The defining behavioral distinction is between **retained first-group inputs** and **fresh second-group reads**. All three first-group inputs are retained before the function’s first destination write. Those retained inputs also support the second-group updates, despite the intervening replacement of the first group. Second-group inputs are read separately for each use.

**Established static evidence:** the supplied representation establishes the direct data flow, dependency order, memory-access order, and arithmetic relationships described below.

**Inferred intent:** the paired differences and sums suggest a two-component transformation over three corresponding positions. They do not establish multiplication, rotation, normalization, linearity, or a numeric encoding.

**Verification status:** static analysis only. No runtime tests have been performed.

## Behavior

### Preparation and temporary state

Both preparation dependencies receive the second argument. F-c40fc30517fa runs before F-440135f92be7. Its result replaces the primary slot’s contents; the later result replaces the secondary slot’s contents.

Both calls finish before this function directly reads any of the six fields. A preparation dependency’s changes to caller storage, if possible through independently available references, can therefore affect the inputs subsequently read. The absence of a base-address argument to either preparation call does not prove that caller storage is inaccessible to it.

The slots are distinct addressable storage. The same primary address is reused whenever the primary role is selected, and likewise for the secondary address. Their prepared contents are not restored between combining calls. The preparation results therefore establish initial combining state, not immutable coefficients.

### Retained inputs and fresh reads

The first-group inputs are retained in position order **1, 3, 2**, corresponding to offsets **+0x04, +0x0C, +0x08**. These are separate reads, not an atomic snapshot.

For each position, the retained value supplies both updates associated with that position. The function does not reread a first-group field to obtain the input for the later second-group update. Its own replacement of that field therefore does not change the retained input.

Second-group inputs have different timing. Each position has one read during its first-group update and another during its second-group update. In both cases, the read occurs after the first combining call for that destination has returned and before the second combining call begins.

This timing is significant even without assuming concurrent access: the first combining call may change the pending second-group field through another reference. Preloading that field before the call would not preserve the established ordering.

### Destination relationships

Each destination uses two combining results. The slot roles and arithmetic are:

| Destination | First result uses | Second result uses | Immediate replacement |
|---|---|---|---|
| First-group field | Primary-slot address and retained first-group input | Secondary-slot address and freshly read second-group input | First result minus second result |
| Second-group field | Secondary-slot address and retained first-group input | Primary-slot address and freshly read second-group input | First result plus second result |

Each interaction selects the inputs for the same position. The first result remains available across the second combining call. Subtraction order is significant.

All first-group replacements precede all second-group replacements. Within each group, destinations are written in position order 1, 2, 3. The direct write order is therefore:

**+0x04 → +0x08 → +0x0C → +0x24 → +0x28 → +0x2C.**

Each write follows its two combining calls and precedes the combining calls for the next destination. Consequently, every direct first-group write has completed before the combining interactions for the first second-group destination begin.

These are immediate-write requirements. They do not guarantee the values remaining in memory at return, because later dependencies may modify earlier destinations.
