# F-36fc8318175d

## Purpose

F-36fc8318175d consumes two 32-bit words and returns one 32-bit word. The field layout, sign manipulation, significand alignment, and rounding operations indicate an intended software floating-point subtraction: first operand minus second operand.

That numerical interpretation is inferred intent, not an unrestricted IEEE 754 guarantee. The visible behavior discards the magnitude of zero-exponent operands, returns positive zero on certain normalization failures, delegates NaN encodings to an unresolved indirect target, and obtains one exceptional result from external storage.

The overflow-result expression also depends on an addressed object whose declaration is absent. Its element size and the applicable address-arithmetic semantics are not established. Consequently, an unconditional claim that every overflow-result path returns signed infinity is unsupported.

This contract describes the supplied static representation. No runtime tests have been performed.

## Behavior

### Classification and precedence

Special-case handling precedes normal significand arithmetic whenever either exponent is zero or 255.

Within special handling, exponent-255 operands take precedence over zero-exponent behavior. A zero-exponent operand paired with infinity or NaN therefore does not enter the ordinary zero-exponent return rules.

### Zero-exponent operands without exponent-255 operands

When at least one operand has exponent zero and neither has exponent 255:

| Condition | Result |
|---|---|
| First operand has nonzero exponent | First operand unchanged |
| First operand has exponent zero; second has nonzero exponent | Second operand with bit 31 toggled |
| Both exponents are zero; first is exactly negative zero and second is not exactly negative zero | Negative zero, `0x80000000` |
| Every other combination with both exponents zero | Positive zero, `0x00000000` |

Thus, nonzero subnormal fractions do not contribute magnitude on these paths. However, the exact negative-zero word receives distinct treatment; substituting an arbitrary negative subnormal for negative zero can change the result.

No alignment or rounding occurs before these returns.

### Exponent-255 operands

If either operand is a NaN encoding, the function invokes the unresolved indirect dependency F-000000000001. The target is derived from implicit return-link-related state with its two low bits cleared.

The representation does not establish explicit arguments for that call. It also does not establish NaN payload selection, quieting, signaling behavior, or canonicalization. If the call returns normally, its 32-bit return word becomes the result unchanged.

If neither operand is a NaN encoding:

| Condition | Result |
|---|---|
| Only the first operand is infinity | First operand unchanged |
| Only the second operand is infinity | Second operand with bit 31 toggled |
| Both are infinities with opposite signs | First operand unchanged |
| Both are infinities with the same sign | External 32-bit result word |

The external word is not established to be a NaN, constant, or immutable value.

### Normal operands: ordering and alignment

For two normal encodings, the original sign relationship selects magnitude subtraction or magnitude addition.

**Equal signs:** magnitudes are subtracted. If the first full unsigned word is smaller than the second, the operands are exchanged and both signs are toggled. This arranges the larger encoded magnitude first while preserving the subtraction direction.

**Different signs:** the second sign is toggled, after which the words are ordered by unsigned comparison and their magnitudes are added.

Within the sign relationships established by these transformations, full-word ordering also orders encoded magnitudes.

The alignment distance is the difference between the transformed operand words shifted right by 23 bits. Those shifted quantities include the original sign position as a ninth bit; they are not separately masked eight-bit exponents. The established equal-sign relationship makes their difference the intended exponent distance.

The smaller working significand is shifted right by the low eight bits of this distance. Boundary-sensitive rounding later examines a separate left shift of that smaller significand, using the low eight bits of the complementary distance.

This is finite-width tail handling, not an unlimited-precision remainder or a general sticky-bit accumulator. In particular, the complementary shift can request a count of 32 or more. Its target semantics must be resolved before all normal-path results can be made unconditional.

### Magnitude subtraction

The aligned smaller significand is subtracted from the larger one. Three result-position cases follow.

**Bit 31 set.** The difference is packed after a right shift by eight bits, with the corresponding scale adjustment. Working bit 7 provisionally increments the retained result. If that bit is clear, or if any of bits 6–0 is set, the packed result returns immediately. Otherwise, the alignment-tail decision described below applies.

**Bit 31 clear, but doubling sets bit 31.** Subject to the visible low-exponent check, the difference is doubled and packed using a signed right shift by eight bits. Bit 7 of the doubled value controls provisional incrementing. A clear rounding bit returns immediately; a nonzero value in bits 5–0 of the original difference also returns immediately. The remaining boundary case uses the alignment-tail decision.

**Further normalization required.** A zero result returns positive zero. The visible low-exponent rejection also returns positive zero rather than producing a subnormal.

For other nonzero differences in this case, the function halves the original difference, counts leading zeros in that reduced word, and subtracts the count from the transformed scale quantity. The adjusted scale is accepted only when its upper bits agree with the original scale above bit 7. An accepted value is packed through a rotation-style combination and scale addition; a rejected value returns positive zero.

This deeper-normalization return does not pass through the shared rounding-tail adjustment.

For the two boundary-sensitive subtraction cases:

- A zero alignment-tail expression clears the provisional result’s least significant bit.
- A nonzero alignment-tail expression decrements the provisional result by one.

The decrement is observable and must not be replaced by the addition path’s tail rule. Discarded bits from a subtracted operand affect the exact difference in the opposite direction.

Equal normal operands with matching signs return positive zero.

### Magnitude addition

The aligned significands are added as 32-bit words, with an explicit unsigned carry test.

**With carry:** the wrapped sum is shifted right once and bit 31 is restored. Bit 7 of that normalized value controls provisional rounding before packing at the increased scale.

When the rounding bit is clear, the retained normalized significand provides a nonzero continuation value. When the rounding bit is set, the low eight bits of the original wrapped sum provide that value instead. A nonzero continuation value bypasses the alignment-tail correction and proceeds directly to the overflow threshold decision.

**Without carry:** the sum is packed at the lower scale. Bit 7 controls provisional incrementing. A clear rounding bit returns the packed word immediately, without a later overflow check. With the rounding bit set, nonzero bits 6–0 permit an immediate return when the doubled provisional result is below the overflow threshold. Otherwise, processing reaches the tail and overflow decisions.

On addition paths reaching the alignment-tail decision, a zero tail clears the provisional result’s least significant bit. A nonzero tail leaves the provisional word unchanged.

These mechanisms resemble nearest-even rounding, but that resemblance does not establish complete IEEE 754 rounding correctness.

### Overflow selection and unresolved result construction

The overflow decision is branch-dependent; it is not applied to every packed result.

Where reached, the threshold compares twice the provisional packed word, retained modulo \(2^{32}\), against `0xff000000` using unsigned ordering. A value below the threshold returns the provisional word, possibly after the tail adjustment. A value at or above the threshold enters the address-based result construction.

That construction forms an address by adding the provisional word as an element offset to an external object’s address. It then converts the resulting address to an unsigned 32-bit value, shifts right by 23, sets the low eight bits, and shifts left by 23.

There is no explicit dereference of the resulting address. However, the object’s declaration is absent. Pointer addition can scale by the object’s element size, and the applicable address width, overflow rules, and address-to-integer conversion are not established. The exact returned word is therefore **documented_only**.

A narrower, conditional interpretation is possible. If all of the following hold:

- The base address has numeric value `0xa0000000`.
- The element size is one byte.
- Address arithmetic and conversion to the 32-bit unsigned word are equivalent to retaining the low 32 bits of the address sum.

Then, for provisional packed word \(P\), the result is:

\[
\left(
\left(
\left((P+\texttt{0xa0000000})\bmod 2^{32}\right)\gg23
\right)
\mathbin{\mathrm{OR}}\texttt{0xff}
\right)\ll23
\]

with a 32-bit retained result. Under those conditions, words selected by the overflow threshold produce the infinity encoding with the provisional word’s sign. Without those conditions, neither this modular formula nor the signed-infinity conclusion is guaranteed.
