# F-c9d0d0002367

## Purpose

F-c9d0d0002367 handles one recognized request discriminator by decoding a selector and index range, obtaining supporting state, invoking a selected callback for each eligible index, and performing a sequence of buffer-related and submission-related dependency calls.

The apparent intent is to export indexed records. Actual copying, transmission, delivery, and endpoint semantics are not established: the relevant dependency implementations are absent. The contract therefore distinguishes calls and argument values from inferred effects.

The function also defines early status returns, a three-stage predicate-and-fallback sequence, ordinary cleanup order, and several paths to a dependency represented as non-returning.

## Interface

### Arguments and request layout

The function accepts two 32-bit arguments:

- **Context:** a value passed to dependencies and used as a base address for callback-object adjustment.
- **Request address:** an address interpreted through 32-bit fields.

The request fields used are:

| Byte offset | Interpretation |
|---|---|
| 0 | 32-bit endpoint-related value, read only after validation, acquisition, and callback selection |
| 8 | 32-bit payload address |
| 12 | Discriminator field; only its low 16 bits participate in recognition |

A low-16-bit discriminator value of 9 selects the processing path. Other values return status 4 without accessing the payload.

For a recognized request, the payload supplies:

| Byte offset | Established use |
|---|---|
| 0 | One-byte selector read |
| 1 | Address passed to F-c25a2fcc75b5 for a 32-bit start value |
| 5 | Address passed to F-c25a2fcc75b5 for a 32-bit extent value |

The spacing of the decoder arguments does **not** establish its read width. Its byte order, alignment requirements, number of bytes accessed, and side effects remain unknown.

No request or payload length is checked locally. The caller must provide addressable storage sufficient for the accesses actually performed by this function and its dependencies. Continuing paths also require valid callback-related object and table addresses. No local addressability checks establish these conditions.

### Return value

The ordinary result is a 32-bit status.

| Result | Established cause |
|---|---|
| 4 | Discriminator mismatch or later rejection of the range, callback representation, or endpoint |
| Any nonzero validation result | Returned directly from F-b9eeaece20cb |
| 3 | F-fab3799b3190 returns zero |
| 2 | The third working-object predicate evaluation for an index returns nonzero |

These conditions overlap numerically: validation itself may return 2, 3, or 4.

Some paths invoke F-a817d8d58c10, represented as non-returning. Those paths have no ordinary result in the supplied listing.

## Behavior

### Recognition, decoding, and validation

The initial status is 4. The discriminator is examined before the payload address is used.

For discriminator 9, the established order is:

1. Obtain the payload address and read its selector byte.
2. Call F-c25a2fcc75b5 with the payload address plus 1; retain its 32-bit result as the start.
3. Call F-c25a2fcc75b5 with the payload address plus 5; retain its 32-bit result as the extent.
4. Set a separate 32-bit range-bound field to zero.
5. Call F-b9eeaece20cb with the context and selector.

A nonzero validation result returns immediately. Working-object initialization, supporting-value acquisition, and their cleanup calls are not performed on this path.

### Supporting state and callback-table selection

After validation returns zero, F-5b24edfb22c0 receives the working-storage address. F-be45cd43f92d is then called with zero. If acquisition returns zero, F-a817d8d58c10 is invoked immediately.

On the continuing path, both words of a callback representation are initialized to zero.

For selector \(s\) from 1 through 9, two 32-bit words are read from a shared callback table, in this order:

1. **Target word**, at byte offset \(8s-4\) from the table base.
2. **Adjustment/flag word**, at byte offset \(8s\) from the table base.

Thus selector 1 reads offsets 4 and 8; selector 9 reads offsets 68 and 72. Different selectors identify different table locations, but the stored values need not differ.

Selector 0 and selectors 10 through 255 perform no selected-pair reads and leave both words zero.

The representation supports direct or virtual dispatch. It is not simply a pair of callable addresses.

### Range interpretation and local rejection

The extent has a special case: if its 32-bit representation is all ones, interpreted as signed −1, and the unsigned start is strictly below the current range bound, replace the extent with bound minus start. Otherwise, retain the original extent bits.

Next, the function reads the endpoint-related value from request offset 0, computes the exclusive end as start plus effective extent modulo \(2^{32}\), and saves a copy of the acquired supporting value for callback use.

Status 4 is assigned if any of the following holds:

- The effective extent is zero.
- The unsigned range bound is less than the unsigned exclusive end.
- The callback target is zero and the adjustment/flag word has a clear low bit.
- The endpoint-related value is zero.

A zero target with a set low flag bit passes the callback-representation check. Virtual dispatch at table offset zero is therefore not rejected merely because the target word is zero.

The function does not independently reject other negative signed interpretations of the extent. There is no explicit addition-overflow rejection. Except for the −1 special case, the extent participates by its 32-bit bit pattern.

The bound is explicitly initialized to zero, and no later direct assignment to it appears. Its storage is adjacent to working storage passed by address to dependencies. Whether a dependency legitimately updates it is unresolved; neither a nonzero bound nor preservation of zero may be assumed without further contracts.

### Buffer-related acquisition

After local checks pass:

1. F-1a836ac93559 receives the captured endpoint and 4.
2. Its 32-bit result is retained as a capacity-like value.
3. F-fab3799b3190 is called without visible arguments.

If the latter returns zero, status becomes 3 and iteration is skipped. Otherwise, its result is retained as the outgoing-buffer value.

The listing supplies no local check that the capacity-like result is at least 4, nonnegative, or consistent with accessible storage. Calling it a capacity is inferred intent.

### Per-index callback and fallbacks

Iteration continues while the current unsigned index is below the unsigned exclusive end. After a successful iteration, the index increases by one.

Each iteration first reads an indirect operation through the working object’s first word, at table byte offset 12, and invokes it with the working-object address. Reset or preparation is inferred intent; its actual effects are unknown.

The selected callback is then resolved:

- Interpret the adjustment/flag word as signed 32-bit and shift it right arithmetically by one.
- Add that adjustment to the context address using the represented 32-bit address arithmetic.
- If the flag’s low bit is clear, use the target word directly as the callable address.
- If the low bit is set, read the adjusted object’s first word as a table base. Clear the bottom two bits of the target word and use the remaining value as a byte offset into that table to read the callable address.

The callback receives the adjusted object address, saved supporting value, current index, and working-object address. Its return value is ignored.

F-6d70e45e29c9 is then called on the working object. If its result is nonzero, the first fallback performs:

1. Obtain an object through F-7059d7649c5a.
2. Read its indirect operation at table byte offset 32.
3. Invoke that operation with temporary-result storage, the obtained object, and zero.
4. Extract a value from the temporary result through F-44362605ab79.
5. Pass the working-object address and extracted value to F-151ab4bfe553.
6. Finalize the temporary result through F-289ec4311c64.

There is no visible null check on the obtained object.

The predicate is evaluated a second time, regardless of its first result. A nonzero second result invokes F-438680ffebfe with the working-object address and a static-text reference.

The predicate is evaluated a third time, regardless of its second result. A nonzero third result assigns status 2 and exits iteration before that index’s buffer-related processing.

The predicate’s domain meaning is unknown. “Empty,” “invalid,” and “missing” are not established synonyms for its nonzero result.

### Per-index buffer and submission-related calls

For an index whose third predicate result is zero, the established sequence is:

1. Call F-b9d9c0b9bfab with the outgoing-buffer value and current index.
2. Call F-8810f53aaa0b with the current second 32-bit word of the working object.
3. Form a 32-bit unsigned threshold from capacity-like value minus 4.
4. Compare the first query result unsigned against that threshold.
5. If the first result is at most the threshold, call F-8810f53aaa0b again with the working object’s then-current second word and select this second result. Otherwise, select the threshold.
6. Reduce the selected value to its low 16 bits.
7. Call F-44362605ab79 with the working-object address.
8. Invoke an unidentified external operation with outgoing-buffer value plus 4, the extracted value, and the reduced length.
9. Call F-5ca71e377766 with the context, outgoing-buffer value plus 4, and the same reduced length.

The external operation’s implementation is not supplied. A copy-like operation is inferred intent only. The listing does not establish that it reads the extracted value as a source address, writes the buffer, or copies exactly the supplied length.

Likewise, the plus-4 argument establishes an address offset, not a guarantee that the first four bytes are reserved, contain an index, or remain unchanged.

The repeated length query is observable. The second result is not compared against the threshold again. No stability or purity of either query is established. The low-16-bit reduction also is not a general buffer-safety guarantee.

The function next stores a transformed length into a local two-word submission-related record, then stores the outgoing-buffer value into its first word. The layout is:

| Record offset | Stored value |
|---|---|
| 0 | Outgoing-buffer value |
| 4 | \((\text{reduced length}+4)\mathbin{\&}\text{0xFFFEFFFF}\) |

The reduced length lies between 0 and 65,535. Adding 4 yields at most 65,539; the mask clears bit 16. Consequently, transformed lengths wrap to 0 through 3 for reduced lengths 65,532 through 65,535.

F-cd7e1905512f is then called with the captured endpoint, 0, 4, and 27. A zero result invokes F-a817d8d58c10. Otherwise, F-79a086cb6f01 receives the context and that result. A nonzero result from F-79a086cb6f01 also invokes F-a817d8d58c10.

The local record is not explicitly present among these visible call arguments. Its connection to the calls, and whether any transmission occurs, remain unresolved.

### Ordinary cleanup

If outgoing-buffer acquisition succeeded, F-58ba61416cc9 receives that buffer value once after ordinary loop completion or a status-2 break.

All ordinary paths following nonzero supporting-value acquisition then perform:

1. F-54033250428c on the address of the original supporting-value slot.
2. F-289ec4311c64 on the working-object address.

This includes local rejection and buffer-acquisition failure. The callback uses a saved supporting value, whereas cleanup receives the original slot by address.

No cleanup is visible after invocation of the non-returning failure dependency.

## Side effects

Established effects include explicit local-state assignments, reads of request and callback-related storage, indirect callback invocation, and the ordered dependency calls described above. Dependencies receive addresses through which storage may be modified.

No direct assignment to the request or payload appears. This does not guarantee their immutability: dependency implementations and alias relationships are unknown.

The captured endpoint and saved supporting value are reused rather than reread from their original slots during iteration. The selected callback words are retained after selection; virtual resolution still reads the adjusted object’s table on each iteration.

Buffer mutation, copying, transmission, allocation, reference counting, and release are not independently established. Cleanup-shaped calls establish invocation order and arguments, not ownership transfer or successful reclamation. Unknown callees must not be assumed to preserve globals, tables, or aliased storage.

## Acceptance examples

These are conditional static criteria, not executed tests. Continuing-path examples assume valid addresses and the stated dependency outcomes.

1. **Unrecognized request:** A low discriminator value of 8 returns 4 without accessing the payload.

2. **Validation rejection:** If validation returns 7, the function returns 7 after both decoder calls, without working-object initialization or supporting-value acquisition.

3. **Table selection:** Selector 3 reads the target at table byte offset 20 before the adjustment/flag word at offset 24. Selector 0 performs neither read.

4. **Unsupported selector:** Selector 10 leaves a zero representation. Even if validation succeeds, a continuing acquisition path is locally rejected with status 4 and ordinary cleanup follows.

5. **Remainder extent:** If the bound at interpretation time is 10, start is 4, and extent is −1, the effective extent is 6 and the exclusive end is 10. The loop considers indices 4 through 9 if subsequent operations continue normally. This example does not establish how the bound became 10.

6. **Wrapped zero-iteration range:** With bound zero, start 4, and extent bits representing −4, the end is zero. With a nonnull callback representation and endpoint, local checks can pass. Successful buffer acquisition is followed by no iteration, buffer cleanup, supporting-slot cleanup, working-object cleanup, and status 0.

7. **Fallback exhaustion:** Three nonzero predicate results cause both fallbacks, status 2, and no buffer-related processing for that index.

8. **Threshold selection:** Capacity-like value 100 and first length result 120 select 96. The external operation receives reduced length 96; actual copying is not established.

9. **Changing query result:** Capacity-like value 100, first result 80, and second result 110 select reduced length 110 without another comparison against 96.

10. **Length transformation:** Reduced lengths 65,532 and 65,535 produce stored transformed lengths 0 and 3, respectively. These local values do not prove corresponding transmitted lengths.

11. **Submission-related failure:** A zero F-cd7e1905512f result invokes the non-returning failure operation without calling F-79a086cb6f01 or following visible ordinary cleanup.
