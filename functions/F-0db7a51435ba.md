# F-0db7a51435ba

## Purpose

F-0db7a51435ba dispatches a selector against a state object. A recognized path performs one of these actions:

- Copies one, two, or three 32-bit state words to caller-provided output storage.
- Writes one or two words containing 65,536.
- Calls a dependency with an address within the state or with a temporary four-word sequence.
- Calls a dependency with an integer calculated from two state words.

The function returns the 32-bit value **1** after a recognized action completes normally. It returns **0** after rejection. Dependency return values are not inspected, so recognition does not certify dependency success.

Rejection conditionally records `0x500` in the first state word: zero is replaced; an existing nonzero value is preserved.

A query interface and fixed-point conversion operations are inferred intent. Field meanings and dependency semantics are not established.

## Behavior

### External reads and dispatch ordering

For each reached K0–K5 decision, the body first evaluates that external location for an equality test. If equality fails, and dispatch continues through that decision, the body evaluates the **same location again** for an ordering comparison.

The ordered decisions are:

| External location | First evaluation | Second evaluation after equality fails |
|---|---|---|
| K0 | Selector equals the value read from K0 | Selector is signed-less-than the newly read K0 value |
| K1 | Selector equals the value read from K1 | Newly read K1 value is signed-less-than-or-equal-to the selector |
| K2 | Selector equals the value read from K2 | Selector is signed-less-than the newly read K2 value |
| K3 | Selector equals the value read from K3 | Newly read K3 value is signed-less-than the selector |
| K4 | Selector equals the value read from K4 | Selector is signed-less-than-or-equal-to the newly read K4 value |
| K5 | Selector equals the value read from K5 | Selector is signed-less-than the newly read K5 value |

K0 is evaluated first. Its lower branch reaches K1, then either K3 or K2. Its other branch reaches K4 and, if the K4 ordering comparison is false, K5. An equality match performs its action without the corresponding second evaluation. Unreached locations are not evaluated by this dispatch.

These are distinct evaluations in the supplied static body. The evidence does not establish volatile access semantics, synchronization, or a particular machine-level load implementation.

**The dispatch table below applies only when each reached K0–K5 location remains unchanged between its equality evaluation and its ordering evaluation.** It does not require the six locations to have any particular relative ordering.

Without that stability condition, equality failure cannot be combined with a later non-strict comparison to infer strict inequality against the later value. For example, a failed K0 equality followed by a false less-than comparison establishes that the selector is at least the *second* K0 value, not necessarily greater than it. Likewise, failed equality followed by the false K3 or K5 less-than test does not exclude equality with the newly read value.

Changing-value behavior outside these explicit evaluation and comparison facts remains **documented_only**. The stable-value regions must not be used to specify its final action.

## Acceptance examples

These are conditional static acceptance criteria, not executed tests. Table-based examples require the stated external-value stability and all applicable dispatch gates.
