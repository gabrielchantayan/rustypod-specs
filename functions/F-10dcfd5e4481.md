# F-10dcfd5e4481

A nonzero input value causes an eight-byte storage request, followed by initialization of a two-field record and publication of that record’s address through the output location.

The function returns the address of the caller’s output location, not the address of the newly initialized record.

This describes the supplied static evidence. The apparent use of the second record field as a count or flag is inferred intent, not an established semantic contract. Allocation policy, ownership transfer, and eventual release are unknown.

## Interface

The recovered interface has two inputs:

- **Output location:** a pointer to writable integer storage. The function writes through this pointer on every ordinary execution path.
- **Input value:** an integer passed by value. Zero selects the no-request path; every nonzero value selects the record-creation path.

The return value has the same pointer type as the output-location argument. On normal completion, its address equals the address supplied by the caller.

There are two distinct outputs:

1. The integer representation written into the caller’s output location.
2. The pointer returned by the function, which identifies that output location.

These must not be confused. In particular, when the input is zero, the stored output is zero, but the returned pointer is still the caller’s output-location pointer.

## Behavior

### Entry and unconditional clearing

The first visible memory operation is a write of integer zero to the output location.

This happens before the input value is tested and before any dependency invocation. There is no visible read of the output location’s previous contents. An existing stored address or other value is overwritten without a visible attempt to inspect, preserve, or release anything it might identify.

The input value is already a by-value argument. Clearing the output location does not replace that argument’s value, even if the caller obtained it from the same storage before making the call.

A valid, writable output location is therefore required for both branches. Supplying a zero input does not make a null or otherwise invalid output location acceptable.

### Zero input

If the input value equals zero:

- The function makes no visible dependency call.
- It performs no visible record-field writes.
- It returns the original output-location pointer.
- In an otherwise undisturbed execution, the output location contains zero.

No new record address is published on this path.

### Nonzero input

If the input value is nonzero, the visible sequence is:

1. Invoke F-8157a180d901 with the integer argument 8.
2. Treat the dependency’s returned value as a pointer to integer-addressable storage.
3. Write integer 1 to the second integer field.
4. Write the original input value to the first integer field.
5. Convert the record pointer to the output integer type and store that result in the caller’s output location.
6. Return the original output-location pointer.

The field-write order is significant: the second field is initialized before the first field. Publication through the output location follows both field writes.

The function does not branch on the sign or magnitude of a nonzero input. Negative values and positive values follow the same visible path. The input is copied into the first field; it is not visibly incremented, multiplied, normalized, or used as a requested storage size.

The dependency argument remains 8 regardless of the input value.

- The second record field equal to 1.

The non-overlap qualification matters. The source contains no visible overlap check. If the dependency returns storage overlapping the output location, the final publication write may overwrite one of the fields just initialized. The operation order remains established; the usual final record contents do not.
