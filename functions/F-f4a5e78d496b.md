# F-f4a5e78d496b

## Purpose

F-f4a5e78d496b initializes a caller-provided destination using a selector and an optional source address.

For an accepted selector, the function first stores that selector in the destination’s first byte. It then takes one of two paths:

- With a nonzero source address, it decodes exactly 32 hexadecimal character bytes into 16 destination bytes.
- With a zero source address, it delegates processing of the 16-byte destination region to an external dependency.

The explicit-source path accepts decimal digits and either case of the six hexadecimal letters. It stops at the first invalid character. It does not roll back earlier destination writes.

**Established behavior:** selector validation, hexadecimal conversion, access order, destination offsets, and return bit patterns are visible in the supplied static evidence.

**Inferred intent:** the destination appears to contain a one-byte selector followed, after a three-byte gap, by a 16-byte value. The meaning of that value and the intended operation for an absent source are not established.

## Behavior

### Selector validation and initial write

Selector validation precedes all direct memory accesses.

If the selector is not exactly 1, 2, or 3, the function immediately returns `0xFFFFFFFC`. It does not write the selector, read source bytes, or invoke the dependency.

For an accepted selector, the function writes its value to destination offset 0 as one byte. All accepted values are exactly representable in that byte, so no information is lost.

This write occurs before testing whether the source argument is zero. It also occurs before any hexadecimal character is read. Consequently, an accepted selector can leave a visible destination change even when subsequent processing fails.

### Zero-source path

When the source argument is zero, the function invokes **F-000000000001**, the opaque dependency identifier used in this contract, with:

1. The address of destination offset 4.
2. The integer value 16.

The selector byte has already been written when this call occurs.

The function does not inspect or propagate any dependency return value. If the dependency returns normally, F-f4a5e78d496b returns `0x00000001`.

The dependency’s implementation and contract are unavailable. In particular, the supplied evidence does **not** establish that it:

- Clears or initializes the 16 bytes.
- Writes exactly 16 bytes.
- Preserves destination offsets 0–3.
- Preserves global state.
- Retains, releases, or otherwise changes ownership of the supplied address.
- Always returns normally.

The argument pair identifies the apparent target region and its size, but it is not sufficient evidence for any particular resulting byte contents.

### Explicit-source path

When the source argument is nonzero, the function processes 16 character pairs in increasing address order.

For output position 0 through 15:

- The first character is read from source offset twice the output position.
- That character is validated and converted to a high-nibble contribution.
- Only if it is valid is the second character read.
- The second character is validated and converted to a low-nibble value.
- Only if both are valid is the resulting byte written to destination offset 4 plus the output position.

The accepted character bytes are:

| Character range | Byte range | Numeric value |
|---|---|---|
| `0`–`9` | `0x30`–`0x39` | 0–9 |
| `A`–`F` | `0x41`–`0x46` | 10–15 |
| `a`–`f` | `0x61`–`0x66` | 10–15 |

Acceptance is based on these byte values. There is no visible locale-dependent classification, whitespace handling, prefix recognition, separator handling, or case normalization of the source storage.

The first character contributes its numeric value multiplied by 16. The second contributes a value from 0 through 15. The supplied operation combines these using exclusive OR. Because the two contributions occupy disjoint nibbles, the result is the ordinary hexadecimal byte value.

For valid input, the high contribution ranges from 0 to 240, the low contribution from 0 to 15, and the final value from 0 to 255. No accepted pair requires a value wider than the destination byte.

The range checks use unsigned arithmetic in the supplied representation. Values below a tested range do not become accepted through a negative intermediate: unsigned wraparound leaves them outside that range. Bytes outside the three listed ranges are rejected.

### Invalid-character handling

The first invalid character causes an immediate return of `0xFFFFFFF9`.

If the first character of a pair is invalid:

- The second character of that pair is not read.
- The corresponding destination byte is not written.
- No later source characters are read or destination payload bytes written.

If the second character is invalid:

- The first character has already been read and accepted.
- The corresponding destination byte is still not written.
- No later pair is processed.

The selector write and all completed earlier output-byte writes remain visible. There is no clearing, restoration, or transactional commit.

### Successful completion

Success on the explicit-source path means all 32 source characters were accepted and all 16 output bytes were written.

The function then returns `0x00000001`. It does not append a terminator, inspect a 33rd source byte, or perform a final destination-wide operation.

### Overlapping storage

The function does not reject overlapping source and destination ranges and does not copy the source into temporary storage before conversion.

Its established ordering therefore matters:

1. Destination offset 0 is written before the first source read.
2. Each completed output byte is written before the next pair is read.
3. Later reads observe whatever bytes exist at their addresses at that time.

An overlapping destination write can replace a source character that has not yet been consumed. Such a replacement can change a later decoded value or cause an invalid-character return.

For a stable conversion of the source’s original 32 bytes, the caller must ensure that the function’s earlier writes do not alter unread source bytes. Nonoverlapping storage is sufficient.

## Side effects

### Direct memory effects

With an invalid selector, there are no direct memory accesses.

With an accepted selector and a nonzero source address:

- Destination offset 0 is written once.
- Between 1 and 32 source-character reads occur before a normal return.
- Between 0 and 16 payload bytes are written.
- Destination offsets 1–3 are not directly accessed.
- A payload byte is written only after both of its source characters are accepted.

The lower bound of one source read assumes execution reaches the explicit-source path without a memory-access failure.

With an accepted selector and a zero source address:

- Destination offset 0 is written once before the call.
- The dependency receives destination offset 4 and the size value 16.
- Additional effects depend on that dependency.

There are no visible direct accesses to global state. This observation does not establish that the dependency preserves globals, memory ownership, or other process state.

The function provides no synchronization or atomicity guarantee for its sequence of accesses. Concurrent mutation of the same storage requires an external contract not present in the supplied evidence.
