# F-a2a686313150

## Purpose

F-a2a686313150 searches a singly linked sequence for the first node whose 16-bit key equals a supplied 32-bit unsigned search value.

Its defining behavior is a special fallback after an unsuccessful search:

- For search value **0** or **4,294,967,295**, return the original input head.
- For every other search value, return null.

A successful match always returns the matching node, including when the search value is zero. The special values do not bypass traversal.

This is a source-facing behavioral contract based on static evidence only. No runtime tests have been performed.

## Interface

### Inputs

**Initial head**

A pointer to the first node, or null. The routine retains this original pointer as the fallback result while using a separate traversal position.

The visible node layout is:

| Byte offset | Width | Meaning |
|---|---:|---|
| 0 | 32 bits | Link representation used to obtain the next node pointer |
| 4 | 16 bits | Unsigned node key |

Only these fields are accessed. The source does not establish a complete node size, the existence of other fields, or a packed serialization format.

The link occupies one 32-bit word in the supplied representation. Its contents are interpreted as the next node pointer. Null ends the sequence. This contract describes that representation; it does not establish portability to a different pointer width.

**Search value**

An unsigned 32-bit integer, with range 0 through 4,294,967,295 inclusive.

The search value is compared against the unsigned 16-bit node key without truncating the search value. Consequently:

- Values from 0 through 65,535 can match a node key.
- Values from 65,536 through 4,294,967,295 cannot match any node key.
- In particular, 4,294,967,295 cannot match a key whose stored bits are all ones; that node key has value 65,535.

### Output

The routine returns a node pointer or null:

1. The first matching node in traversal order, if one is found.
2. Otherwise, the original head when the search value is zero or 4,294,967,295.
3. Otherwise, null.

The returned pointer is not a copy of a node. It identifies an existing node supplied through the input structure. A non-null result alone does not prove that a match occurred: for either special search value, an unsuccessful search can return the original head.

### Preconditions

For normal execution, each visited non-null node must support an unsigned 16-bit read at byte offset 4. Each visited node whose key does not match must also support a 32-bit link read at byte offset 0, and that link must yield either null or another usable node pointer.

The source does not establish alignment rules or define recovery from invalid addresses, inaccessible memory, or representations unsupported by the target environment.

## Behavior

### Traversal and comparison

The traversal begins at the initial head. Before accessing a node, the routine checks whether the current traversal pointer is null.

For a non-null node, the routine reads its 16-bit key and compares the resulting unsigned value with the complete 32-bit search value. A match ends the search immediately and returns that node.

For a mismatch, the routine reads the node’s link and continues at the resulting pointer. Thus, among nodes that match, the earliest one encountered is returned. There is no uniqueness check, collection of later matches, or continued traversal after success.

The comparison is numeric, not a comparison limited to the low 16 bits of the search value. For example, a search value of 65,537 does not match a node with key 1.

### Exhaustion and fallback

When the traversal pointer becomes null, the result depends on the search value:

| Search value | Result after reaching null |
|---|---|
| 0 | Original head |
| 4,294,967,295 | Original head |
| Any other value | Null |

The original head is not replaced by the last visited node or otherwise advanced for purposes of this fallback.

For an initially empty sequence, every search returns null. The special fallback values still select the original head, but that head is itself null.

For a search value of zero, an actual zero-key match takes precedence over fallback. If no zero-key node exists and traversal reaches null, the original head is returned even if its key is nonzero.

For a search value of 4,294,967,295, a node-key match is impossible because keys are unsigned 16-bit values. Nevertheless, the routine follows the sequence until null before returning the original head. It does not immediately return the head merely because the search value is special.

For other search values greater than 65,535, matches are likewise impossible, but the routine still traverses until null and then returns null.

### Observable read order

For each visited node, the established logical order is:

1. Check the current pointer for null.
2. If non-null, read and compare the key.
3. Only after a mismatch, read the link.
4. Repeat at the linked node.

The matching node’s link is not read by this routine. No subsequent node is examined after a match. A null traversal pointer is not dereferenced.

This describes the reads established by the supplied source, not a guarantee about generated machine-instruction scheduling, hardware speculation, or memory-mapped-device behavior.

### Termination

A finite, valid sequence ending in null terminates. A sequence containing a matching node also terminates when that node is reached, even if the structure beyond it is cyclic or otherwise unusable.

There is no visible cycle detection or traversal limit. A cycle with no matching key does not reach the fallback branch. This is especially relevant for search value 4,294,967,295: because no node can match, a cycle prevents termination rather than producing the original-head fallback.

No arithmetic is applied to keys or the search value. The relevant width distinction is the unsigned 16-bit key versus the unsigned 32-bit search value.

## Side effects

The routine performs reads of node keys and, following mismatches, node links. No explicit writes to node memory, global state, or caller-provided output storage are present.

There are no visible allocations, deallocations, ownership transfers, callbacks, or dependency calls. The routine itself neither acquires nor releases node storage. It also does not establish a lifetime guarantee for the returned pointer.

No error status is returned separately from the pointer result. Null can mean an empty input or an unsuccessful ordinary search. A non-null special-value fallback is not accompanied by a flag distinguishing it from a successful match.

The source contains no synchronization. Behavior when another actor modifies keys, links, or node lifetime during traversal is **documented_only**: the available evidence does not establish a concurrency contract.

Additional boundary cases:

- **Matching node with an unusable link:** If the node pointer and key field are usable and its key matches, the routine returns the node without reading its link. This does not establish validity of the unused link.
- **Unusable link after a mismatch:** The routine attempts to read and follow that link. No graceful error result is established.
- **Cycle containing a match:** If the matching node is reached through usable links, it is returned on its first encounter.
- **Cycle without a match:** With stable node contents, traversal repeats indefinitely. The original-head fallback requires reaching null and therefore is not triggered.
- **Repeated zero keys:** A search for zero returns the first zero-key node, not necessarily the original head.
