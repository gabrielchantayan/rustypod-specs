# F-b05552b91301

## Purpose

F-b05552b91301 conditionally computes the address of a fixed-stride entry in a collection described by a header.

For a nonnegative index strictly below the header’s signed count, it reads a backing address and returns that address plus twenty times the index. For a negative index, an index equal to the count, or an index above the count, it returns zero.

The function does not read the selected entry, copy its contents, allocate storage, or modify the collection. Its bounds check concerns only the index and stored count; it does not establish that the resulting address refers to accessible storage.

The collection interpretation is inferred intent. The conditional reads, comparisons, address calculation, and return selection are established by the supplied static representation.

## Behavior

### Rejection without header access

A negative index produces zero without reading either header field.

This rejection precedes the header-dependent portion of the behavior. The incoming third argument cannot alter it. An invalid header address therefore does not, by itself, create a read on the negative-index path.

### Count acquisition and classification

For every nonnegative index, the function first reads the signed count from offset `0x0C`.

That single read determines acceptance:

- An index equal to the count is rejected.
- An index greater than the count is rejected.
- An index strictly less than the count is accepted.

Together with the initial negative-index rejection, the accepted range is zero through count minus one.

Consequences include:

- A count of zero accepts no index.
- A negative count accepts no index.
- Index zero is accepted only when the count is positive.
- The count itself is never an accepted index.
- No one-past-the-end address is returned as a successful boundary result.

For any rejected nonnegative index, the return is zero and the backing-address field is not read.

### Accepted-index address calculation

For an accepted index, the function reads the backing address from offset `0x14`, then calculates an address displaced by twenty bytes per index.

The displacement is formed as an index multiplied by five and then by four. Where all arithmetic is representable, the result is:

\[
\text{returned address}=\text{backing address}+20\times\text{index}
\]

This calculation establishes a twenty-byte stride, not the structure or meaning of an entry. The function does not inspect an entry’s contents.

For index zero, the returned value is the backing address without a displacement. For larger accepted indices, the function returns the corresponding computed address.

The function does not verify:

- That the backing address is nonzero.
- That the backing storage contains as many entries as the count claims.
- That the address calculation stays inside an allocation.
- That the resulting address is aligned.
- That the resulting address is readable or writable.

Consequently, passing the index check is not a general pointer-validity guarantee.

### Read order and retained values

The observable memory-read order is:

1. Count field, for every nonnegative index.
2. Backing-address field, only for an accepted index.

The count is not read again after the backing-address read. Acceptance and subsequent calculation use the count already obtained.

No entry memory is read before return. In particular, a selected entry may be inaccessible without that inaccessibility being detected by this function, provided the required header reads and address arithmetic complete.
