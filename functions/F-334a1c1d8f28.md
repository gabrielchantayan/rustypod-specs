# F-334a1c1d8f28

## Purpose

F-334a1c1d8f28 conditionally obtains a byte-addressed value and delivers a derived argument to an object through an indirect method call. A one-byte selector in a separate input object determines which of three lookup inputs is used.

The established behavior has three outcomes:

- A selector other than 1, 2, or 3 causes an immediate return without accessing the recipient object.
- A supported selector whose lookup returns either no address or an address containing a zero first byte causes a fallback method call on the recipient.
- A supported selector whose lookup returns an address containing a nonzero first byte causes a conversion dependency and a primary recipient method to run. A nonzero result from that method additionally triggers a global indirect call.

Names such as “lookup,” “conversion,” “primary,” and “fallback” describe call positions, not independently established application semantics. In particular, the evidence does not establish that the value is a string, that the fallback clears anything, or that a nonzero primary result denotes success or failure.

## Interface

### Inputs

The function takes two machine-level inputs:

1. **Selector-object address.** The function reads one byte at offset 124, hexadecimal 0x7C, from this address.
2. **Recipient-object address.** On supported-selector paths that reach recipient dispatch, the function reads the recipient’s first machine word as a dispatch-table address.

The supplied representation supports a 32-bit interpretation of addresses and machine words. The contract below uses that interpretation for pointer-bearing words, dependency results, and dispatch arguments. It does not establish a portable interface for a different pointer width.

The relevant layouts are:

| Structure | Offset | Access |
|---|---:|---|
| Selector object | 124 bytes | One-byte selector read |
| Recipient object | 0 bytes | 32-bit dispatch-table address read |
| Recipient dispatch table | 8 bytes | Primary method address read |
| Recipient dispatch table | 12 bytes | Fallback method address read |
| Lookup result, when nonnull | 0 bytes | One unsigned byte read |

Only these fields are accessed directly by F-334a1c1d8f28. Dependencies may access other memory.

### Output

No explicit return value is established. Results are observable through calls and their side effects, rather than through a value returned by this function.

The function contains explicit return paths, but their execution depends on invoked callees returning normally. The evidence does not establish that every indirect target returns.

### Preconditions

For any invocation, the selector byte must be readable at the supplied selector-object address plus 124 bytes. A null selector-object address is not checked.

For selectors 1, 2, or 3:

- The three direct dependencies and the selected global lookup-input storage must be usable as required by the path taken.
- A nonnull lookup result must designate at least one readable byte when the first-byte check occurs.
- When recipient dispatch is reached, the recipient must designate a readable dispatch-table pointer, and the selected table entry must designate a callable target.
- If the primary method returns nonzero, the global indirect target used afterward must be callable.

There is no explicit recipient null check. For unsupported selectors, however, the recipient is not accessed and need not be valid for this function’s own operations.

Required memory lifetime extends through each actual use. A valid lookup address at the first-byte check is not, by itself, sufficient to establish that it remains valid after subsequent callees execute.

## Behavior

### 1. Selector read and early return

The first established memory access is a one-byte read at offset 124 from the selector-object address.

The byte is compared with the values 1, 2, and 3:

- Value 1 selects the first global lookup-input word.
- Value 2 selects the second global lookup-input word.
- Value 3 selects the third global lookup-input word.
- Every other byte value causes an immediate return.

The signedness of the selector’s reconstructed character type does not affect this classification: only the three positive byte values are accepted.

On the unsupported-selector path, there are no dependency calls, no lookup-result reads, and no recipient-object accesses by this function.

### 2. Context acquisition and lookup-input selection

For a supported selector, the function calls F-9d0ecc5f6adf with no explicit arguments.

After that call returns, it obtains the global lookup-input word associated with the selector already read. It then calls F-c0b020cd3882 with two arguments, in this order:

1. The 32-bit result returned by F-9d0ecc5f6adf.
2. The selected 32-bit global lookup-input word.

The ordering matters. The selected global word is obtained after F-9d0ecc5f6adf returns. It is not established as a value captured before that call. If that dependency changes the relevant global storage, the subsequent lookup uses the post-call value.

The selector itself is not read again. Changes to the selector byte during the dependency call do not reselect the branch within this invocation.

### 3. Lookup-result classification

The result of F-c0b020cd3882 is interpreted as a byte address.

If that address is null, the function does not read through it and proceeds to fallback dispatch.

If the address is nonnull, the function reads exactly one unsigned byte at that address:

- A zero byte causes fallback dispatch.
- Any nonzero byte causes primary processing.

The byte is used only as a zero/nonzero gate. It is not passed as a value to a later callee, used as a length, or dereferenced as an address. The supplied representation temporarily casts this byte through a pointer-shaped value, but the observable decision is simply whether the first byte is zero.

This function does not directly inspect subsequent bytes. No terminator search, length calculation, encoding validation, or content comparison is established.

### 4. Fallback dispatch

Fallback dispatch occurs in either of these cases:

- F-c0b020cd3882 returned null.
- It returned a nonnull address whose first byte was zero.

The function reads the dispatch-table address from the recipient’s first word, obtains the callable target at byte offset 12 in that table, and invokes it with the recipient address as the sole explicit argument.

No return value from this target is used. If the target returns normally, F-334a1c1d8f28 returns.

The fallback path does not call F-8810f53aaa0b or the primary method. It also does not invoke the final global indirect target.

No meaning such as “clear,” “reset,” or “report missing data” is established for this dispatch slot.

### 5. Primary processing

When the lookup result is nonnull and its first byte is nonzero, the function calls F-8810f53aaa0b with the lookup-result address as its sole explicit argument.

After that dependency returns, the function reads the recipient’s dispatch-table address and the callable target at byte offset 8 in that table. It invokes that target with three arguments:

1. The recipient address.
2. The 32-bit result returned by F-8810f53aaa0b.
3. A machine-word zero.

The recipient dispatch-table access occurs after F-8810f53aaa0b returns. The evidence does not establish that the recipient or its dispatch table was cached before that call.

The function compares the primary method’s 32-bit result with zero:

- A zero result causes an immediate return.
- A nonzero result causes the final indirect call described below.

Only zero versus nonzero is tested. No sign, range, or bit-field interpretation is established.

### 6. Final global indirect call

For a nonzero primary-method result, the function obtains a callable target from a global location and invokes it with:

1. The nonzero 32-bit primary-method result.
2. The original lookup-result address.

The second argument is not a fresh lookup and is not the result of F-8810f53aaa0b. It is the address previously returned by F-c0b020cd3882.

The global target is consulted after the primary method returns. No assumption may be made that earlier dependencies or the primary method preserve that target’s global storage.

The supplied representation identifies this transfer as an indirect call while also reporting incomplete recovery of the underlying indirect control flow. The two explicit arguments are evidenced; exact calling convention and return behavior remain uncertain. If control returns normally, this function then returns.

## Side effects

F-334a1c1d8f28 contains no established direct writes to caller-visible data or global storage. Its direct data accesses are reads.

Observable effects may nevertheless occur through every invoked dependency and indirect target. In particular:

- F-9d0ecc5f6adf may change the globals subsequently used for lookup.
- F-c0b020cd3882 may change the recipient or other shared state before dispatch.
- F-8810f53aaa0b may change the recipient’s dispatch table before the primary target is resolved.
- The primary method may change the global target subsequently used by the final call.
- Either recipient method may change the recipient or other state.

These possibilities are not assertions that such changes occur. They are reasons not to assume preservation in the absence of callee contracts.

No allocation, deallocation, ownership transfer, reference-count adjustment, copying of the lookup contents, or explicit synchronization is established in this function. Passing an address to a dependency does not establish whether that dependency borrows, retains, consumes, or releases the referenced storage.

There is no local error recovery, retry, null-recipient handling, or explicit error reporting. A null lookup result is a defined branch condition leading to fallback; invalid memory and invalid call targets have no specified handling here.

## Acceptance examples

These examples are conditional on valid memory, valid callable targets, and normal returns from invoked callees. They are specification examples, not executed tests.

1. **Unsupported selector.**  
   Given selector byte 0, 4, or 255, the function returns after the selector check. It does not access the recipient or invoke any dependency.

2. **Supported selector with null lookup result.**  
   Given selector 1 and a null result from F-c0b020cd3882, the call order is F-9d0ecc5f6adf, F-c0b020cd3882, then recipient slot 12. No lookup byte is read.

3. **Nonnull address containing zero.**  
   Given selector 2 and a lookup address whose first byte is zero, that byte is read and recipient slot 12 is invoked. F-8810f53aaa0b is not called, regardless of later bytes.

4. **Nonzero first byte and zero primary result.**  
   Given selector 3, a first lookup byte of 128, and a zero primary-method result, the call order is F-9d0ecc5f6adf, F-c0b020cd3882, F-8810f53aaa0b, then recipient slot 8. The global indirect target is not invoked.

5. **Nonzero primary result.**  
   Given a qualifying lookup address and any nonzero primary result, the global indirect target receives that result and the original lookup address. No additional first-byte check occurs.

6. **Global lookup input changes during context acquisition.**  
   If F-9d0ecc5f6adf changes the global word selected by the original selector, F-c0b020cd3882 receives the changed word.

7. **Recipient dispatch changes during conversion.**  
   If F-8810f53aaa0b installs a different valid recipient dispatch table, the primary target is resolved from the table present after that dependency returns.
