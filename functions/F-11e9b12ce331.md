# F-11e9b12ce331

## Purpose

F-11e9b12ce331 searches a pointer-linked structure using a supplied operand, then either returns an existing-node address or invokes F-da7db4beaf5e. It publishes a four-byte result word followed by a one-byte outcome flag.

**Established behavior:** flag 0 identifies the existing-node return path. Flag 1 identifies a completed call to F-da7db4beaf5e; it does not independently establish successful insertion, allocation, or structural change.

**Inferred intent:** the structure resembles an ordered tree with a header, parent links, child links, and node payloads. The function appears to support insertion with a conditional duplicate check. These interpretations do not replace the field-level behavior below.

## Interface

### Arguments and result

| Argument | Representation | Established role |
|---|---|---|
| Result destination | Address of at least five writable bytes | Receives the result word and flag |
| Container address | Four-byte address represented by an integer-sized argument | Supplies structural fields and comparison context |
| Supplied operand | Four-byte value | Passed unchanged to dependencies |

There is no explicit return value.

At the result destination:

- Bytes 0–3 receive a four-byte word.
- Byte 4 receives 0 or 1.
- No direct write beyond byte 4 is established.

The word is written before the flag. Publication is not atomic. On the existing-node path, the word is an address loaded from the iterator slot after the final comparison returns. On insertion-related paths, it is read from the corresponding temporary result word after F-da7db4beaf5e returns.

The supplied operand is not directly dereferenced by this function. Its interpretation is dependency-defined.

### Directly used layouts

All offsets below are byte offsets.

| Container offset | Access |
|---|---|
| +16 | Four-byte header pointer |
| +24 | One-byte control value |
| +25 | Address supplied as comparison context |

The comparison receives the address at container +25, not a value loaded there. No context size is established.

| Header or node offset | Access |
|---|---|
| +0 | One-byte discriminator used during adjustment |
| +4 | Four-byte link: initial search link in the header; parent-like link elsewhere |
| +8 | Four-byte branch link; also a header-derived boundary value |
| +12 | Four-byte branch link |
| +16 | Address supplied as a payload operand |

The payload address is formed by addition; this function does not load a payload value from it. Full object sizes and payload representations are unknown.

### Temporary storage

The function uses distinct four-byte storage locations with these roles:

- **Early-result word:** receives output from the early F-da7db4beaf5e call; its first byte also stages the outcome flag.
- **General-result/boundary word:** holds a header-derived boundary value during F-10d8d7d1cfaa and later receives output from the general F-da7db4beaf5e call.
- **Auxiliary word:** explicitly cleared before the final comparison.
- **Iterator storage:** has room for two four-byte slots, but only the first receives an explicit initialization before its address is passed to F-10d8d7d1cfaa.

These are not all initialized at function entry. Their initialization and reuse affect the returned result.

### Preconditions

Defined operation requires valid storage for every executed access, valid dependency arguments, and terminating traversal or adjustment paths. Four-byte links and result words, one-byte fields, and the stated address additions must be valid in the target’s four-byte address model.

There are no explicit null-argument, alignment, bounds, cycle, or corruption checks. A non-null traversed address must expose every field subsequently accessed. Structural invariants must also make parent-walking and special-case dereferences valid.

Supported aliasing, synchronization, and concurrent mutation are **documented_only**. This contract does not assume they are safe.

## Behavior

### Initial state and search

The saved comparison result starts at 1.

The function reads the header pointer from container +16 and reads that header’s +4 link as the initial search address. It then separately reloads container +16 as the retained candidate.

These are distinct header-pointer reads. With an empty initial search, the candidate is the value from the second read, which need not equal the first under unstable storage.

For each non-null search node, the function performs this sequence:

1. Clears the early-result word to four-byte zero.
2. Clears the general-result/boundary word to four-byte zero.
3. Calls F-257a89ed2c43 with the context address at container +25, the supplied operand, and the current node’s payload address at +16.
4. Retains the compared node as the candidate.
5. Reads the next link from that node: +12 for a zero comparison result, +8 for any nonzero result.

The selected link is read after the call. Dependency changes to that field can therefore affect the next step.

The comparison result is retained for later branching. Its use is exclusively zero versus nonzero, not signed three-way ordering.

When the next link is null, traversal ends. If traversal was empty, neither result word has received these clearing stores, no traversal comparison has occurred, and the saved result remains 1.

### Control-byte decision

After traversal, the function reads container +24.

- A nonzero byte selects the general insertion-related path directly.
- A zero byte selects candidate checking.

Because this read occurs after traversal comparisons, changes made by those calls can affect the decision.

### Candidate checking

For a zero control byte, the function initializes the iterator’s first slot with the retained candidate.

If the saved comparison result is zero, boundary processing and adjustment are skipped.

Otherwise, it:

1. Reloads the header pointer from container +16.
2. Reads the four-byte value at that header’s +8.
3. Stores that value into the general-result/boundary word, replacing its previous contents.
4. Calls F-10d8d7d1cfaa with the iterator-storage address and the address of the general-result/boundary word.

A nonzero return selects the early insertion-related path immediately. No adjustment or final comparison occurs.

A zero return selects adjustment. The adjustment uses the iterator slot’s value after the call, not necessarily the candidate originally stored there. The dependency receives writable addresses; preservation of either argument is not established.

The general-result/boundary word’s address has now escaped to a dependency. Later dependencies may be able to modify that storage through a retained address. Subsequent clearing stores do not establish its value permanently.

### Adjustment: discriminator special case

The function reads the byte at the current iterator address.

Only if that byte is zero does it read:

1. The iterator’s +4 link.
2. The reached object’s +4 link.

If the second link equals the iterator address, the iterator is replaced by its +12 link and adjustment finishes.

If the byte is nonzero, or the second link does not equal the iterator, adjustment continues with the branch processing below.

### Adjustment: branch descent

The +8 branch is read twice:

1. Its first value is retained as a prospective descent address.
2. A separate +8 read determines whether to take the null-link case.

If the second read is nonzero, descent uses the **first** value. The second value is only tested; it is not adopted as the descent address.

At each descending step:

1. The iterator is set to the retained descent address.
2. The iterator’s +12 link is read into the next descent address.
3. The iterator’s +12 link is separately reread for the continuation decision.

A nonzero second read continues using the first read’s value. A zero second read stops at the current iterator.

Under stable link values across each pair of reads, this follows +8 once and then follows +12 until reaching a node with a null +12 link. Without stability, that terminal-node characterization is not guaranteed. A first read of null followed by a nonzero test read can lead to a subsequent invalid dereference; there is no intervening validation.

### Adjustment: parent walking

If the second +8 read is zero, the previously retained +8 value is not used for descent. Instead, the function reads the iterator’s +4 link as a prospective parent.

For each parent-walking step, it:

- Tests whether that parent’s +8 link equals the current iterator.
- Assigns the parent to the iterator regardless of the test result.
- Continues through the parent’s +4 link only when the test was true.

The final iterator is therefore the parent assigned on the step whose test was false. The function does not retain the child from that stopping step.

This walk has no explicit null or cycle protection.

### Final comparison

After any required adjustment—or immediately when the saved traversal result was zero—the function:

1. Clears the auxiliary word to four-byte zero.
2. Clears the general-result/boundary word to four-byte zero.
3. Calls F-257a89ed2c43 with the context address at container +25, the iterator payload address at +16, and the supplied operand.

The operand order is reversed relative to traversal.

If the result is zero, the function reads the iterator slot after the call and writes that address to output bytes 0–3. It then stages and writes flag 0.

The address returned need not be the address whose payload was compared if a dependency changes the iterator slot through a previously retained address. No such mutation is established, but preservation is not guaranteed.

A nonzero comparison result selects the general insertion-related path.

### Insertion-related calls and output

Both insertion-related paths call F-da7db4beaf5e with:

1. The address of a four-byte temporary result word.
2. The container address.
3. A literal zero.
4. The candidate retained from initial traversal.
5. The supplied operand.

The early path uses the early-result word. The general path uses the general-result/boundary word.

After return, the function reads that temporary word and writes it to output bytes 0–3. It then stages flag 1 in the first byte of the early-result word and writes the flag to output byte 4. On the existing-node path, the same flag-staging byte receives zero after the result-word write.

The insertion candidate is not replaced by an adjusted or dependency-modified iterator.

### Result when the insertion dependency does not write

A dependency return without writing its result word does **not** universally make the output word unknown:

| Path | Established prior writes to the result temporary |
|---|---|
| General path, nonzero control, nonempty traversal | Cleared before every traversal comparison |
| General path, nonzero control, empty traversal | No established initialization |
| Early path, nonempty traversal | Early-result word cleared before every traversal comparison |
| Early path, empty traversal | No established initialization of the early-result word |
| General path after final comparison | General-result/boundary word cleared immediately before that comparison |

Where a clear is established, a no-write insertion call produces zero **provided no intervening access changes that word**. In particular, after boundary processing, the general-result/boundary word is address-exposed. The final comparison or another dependency may change it through retained access despite its preceding clear.

No initialization value is assigned by this contract where the source establishes none.

## Side effects

Direct effects include conditional reads of structural fields, temporary-storage writes, dependency calls, and the ordered result-word and flag writes.

No direct allocation, deallocation, link update, element-count update, or explicit global-variable access is established.

Dependencies may mutate accessible storage, retain addresses, allocate or release memory, change globals, or fail to return. Their implementations are unavailable. Previously retained addresses are not automatically refreshed following such calls; only the explicit reloads described above occur.

The source establishes no ownership transfer or release obligation. Returning a node address does not grant ownership. Flag 1 does not establish allocation, insertion success, or result lifetime.

Temporary addresses supplied to dependencies are not guaranteed valid after this function returns. Whether dependencies retain them, and whether such retention is permitted, remain unknown.

There is no explicit error status, validation failure, recovery, or rollback path. Invalid accesses and nonreturning dependencies have no specified normal output.

## Acceptance examples

These are conditional static scenarios, not executed tests.

### Nonempty traversal and nonzero control

Given valid terminating traversal, a nonzero control byte, and no intervening modification of the general-result word:

- Boundary processing and final comparison are skipped.
- F-da7db4beaf5e receives the retained search candidate.
- If it returns without writing its result word, output is four-byte zero followed by flag 1.

The zero follows from the traversal clearing stores, not from an insertion-success guarantee.

### Empty traversal and nonzero control

Given a null initial search link and nonzero control:

- No traversal comparison or result-word clearing occurs.
- The separately reloaded header pointer is supplied as candidate.
- If F-da7db4beaf5e writes a word, that word is returned with flag 1.
- If it does not write, no initialized result value is established.

### Early insertion with and without traversal

Given zero control, a saved nonzero result, and a nonzero boundary-call result:

- Adjustment and final comparison are skipped.
- The retained search candidate is supplied to F-da7db4beaf5e.
- After nonempty traversal, the early-result word has been cleared; absent intervening modification, a no-write call returns zero with flag 1.
- After empty traversal, that word has no established initialization.

The boundary value stored in the general-result/boundary word does not initialize the distinct early-result word.

### Existing-node return without adjustment

Given zero control and a final traversal comparison of zero:

- No boundary call or adjustment occurs.
- The auxiliary and general-result/boundary words are cleared before the reversed-operand comparison.
- If that comparison returns zero and the iterator slot remains unchanged, the candidate address is returned with flag 0.
- F-da7db4beaf5e is not called.

### Address-exposed general result

Given boundary processing followed by adjustment:

- F-10d8d7d1cfaa has received the general-result/boundary word’s address.
- The function later clears that word before the final comparison.
- Suppose the final comparison changes the word to a particular four-byte value through retained access and returns nonzero.
- If F-da7db4beaf5e then leaves the word unchanged, that value—not necessarily zero—is returned with flag 1.

### Distinct iterator and insertion candidate

Given an adjustment that changes the iterator:

- The final comparison uses the adjusted iterator’s payload.
- A zero comparison result returns the post-call iterator-slot value with flag 0.
- A nonzero result invokes F-da7db4beaf5e with the original retained search candidate.

### Unequal paired link reads

If the first +8 read yields one node address and the second yields a different nonzero address, descent uses the first address. The same distinction applies to paired +12 reads.

If a descending step’s first +12 read is nonzero but its second read is zero, the walk stops at the current node. Without stability, that node cannot be described unconditionally as having a null +12 link.

### Non-Boolean comparison results

A comparison result of 2 or a negative nonzero integer selects the same branch as 1. Only equality to zero matters.
