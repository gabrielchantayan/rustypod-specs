# F-dd25b77923ee

## Purpose

F-dd25b77923ee conditionally updates one 32-bit field in a selected record associated with a context obtained from F-7fba0909c452. It accepts eight consecutive target identifiers and five operation selectors.

Two selectors validate the supplied value before storing it. Three selectors store any supplied 32-bit value without a range check. One validated operation also invokes F-e4e2db384d33 after the store.

For invalid targets, unsupported selectors, and rejected values, the function may record an error in the first 32-bit word of the acquired context. That reporting preserves an already nonzero error word. Some rejected values can produce no error write because their reporting value comes from mutable global state and may be zero.

This is a static behavioral contract. The supplied material does not establish the application-level meaning of the records, fields, values, or dependency calls.

## Interface

### Inputs

The function has three inputs:

| Input | Width and interpretation | Role |
|---|---|---|
| Target identifier | 32-bit integer; eligibility uses unsigned 32-bit subtraction and comparison | Selects one of eight eligible records |
| Operation selector | 32-bit value, matched against exact numeric constants | Selects the field and validation rule |
| Supplied value | Signed 32-bit integer for validation; stored as a 32-bit word when accepted | Replacement field value |

The eligible target identifiers are exactly `0x4000` through `0x4007`, inclusive.

The operation selectors are `0x1205`, `0x1206`, `0x1207`, `0x1208`, and `0x1209`. Other selector values are unsupported.

### Result

There is no explicit return value. Observable results consist of:

- An invocation of F-7fba0909c452.
- Conditional reads of global state.
- A possible 32-bit record-field write.
- A possible invocation of F-e4e2db384d33.
- A possible read and write of the context’s first 32-bit word.
- Return to the caller, unless execution does not return from F-e4e2db384d33 or otherwise fails outside the established behavior.

### Context and addressing model

F-7fba0909c452 supplies either a null pointer or a context pointer. A null pointer causes immediate return.

For a nonnull context, let:

- **Context address** mean the returned pointer.
- **Record displacement** mean the value read from the global displacement location.
- **Reporting value** mean the value read from the global reporting location.
- **Callback argument** mean the 32-bit value read from the global location used as the argument to F-e4e2db384d33.

These names identify distinct source-level storage roles, not guaranteed nonaliasing regions.

For an eligible target, the record anchor is calculated from the context address, the record displacement, and the target identifier multiplied by `0xA8` bytes. The original target identifier is used directly; the function does not first subtract `0x4000` for record addressing.

The selected field address is that anchor plus the field offset listed below. The record displacement therefore participates in interpreting the relatively large target-derived displacement.

## Behavior

### 1. Acquire context before validation

The function first invokes F-7fba0909c452, without explicit arguments.

If that dependency returns null, the function returns immediately. It does not validate the inputs, read the record-displacement or reporting globals, write an error, or invoke F-e4e2db384d33.

The dependency itself may have effects; its behavior is not supplied.

### 2. Determine target eligibility

With a nonnull context, the target is tested using unsigned 32-bit subtraction:

- Subtract `0x4000`, with unsigned 32-bit semantics.
- Accept the target only when the result is less than eight.

This admits exactly `0x4000` through `0x4007`. Negative signed inputs and every other 32-bit target value are ineligible.

For an ineligible target:

- No record-displacement or reporting-global read occurs on this path.
- No operation-specific record-field write occurs.
- The error-reporting value is `0x500`.
- Execution proceeds to conditional error recording.

### 3. Prepare an eligible target

For an eligible target, the function:

1. Reads the record-displacement global and combines it with the target multiplied by `0xA8`.
2. Reads the reporting global and retains that value for a possible later error-reporting attempt.
3. Dispatches on the operation selector.

These global reads occur even when the selected operation later succeeds without using the reporting value. An unsupported selector also reaches these reads before replacing the reporting value with `0x500`.

The target multiplication itself is within signed 32-bit range for every eligible target. Its result ranges from `0x2A0000` through `0x2A0498`. This does not establish that adding the global displacement or context address is free of overflow.

### 4. Execute the selected operation

All offsets in the following table are byte offsets from the calculated record anchor. Each accepted update is a single 32-bit store.

| Selector | Field offset | Accepted supplied values | Behavior after accepted store |
|---|---:|---|---|
| `0x1205` | `0x64` | Signed values from zero through `0x800000`, inclusive | Return immediately |
| `0x1206` | `0x68` | Signed values from zero through `0x5A0000`, inclusive, plus exactly `0xB40000` | Read the callback argument and invoke F-e4e2db384d33 |
| `0x1207` | `0x58` | Every 32-bit value | Return immediately |
| `0x1208` | `0x5C` | Every 32-bit value | Return immediately |
| `0x1209` | `0x60` | Every 32-bit value | Return immediately |

For `0x1205`, the maximum accepted value is 8,388,608. Negative values and values above that bound are rejected.

For `0x1206`, the contiguous accepted interval ends at 5,898,240. The isolated additional accepted value is 11,796,480. Values strictly between those two positive bounds are rejected. Negative values and values above the isolated accepted value are also rejected.

A rejected value causes no operation-specific field write and no call to F-e4e2db384d33. It proceeds to conditional error recording using the previously captured reporting value.

The three unconditional-store selectors do not clamp, normalize, or reject negative values. They write the supplied 32-bit representation.

For an unsupported selector, no operation-specific field write occurs. The error-reporting value becomes `0x500`, regardless of the earlier reporting-global value.

### 5. Handle the dependency call for `0x1206`

For an accepted `0x1206` value, the order is:

1. Store the supplied value at offset `0x68`.
2. Read the callback argument from its global location.
3. Invoke F-e4e2db384d33 with that value as its single explicit argument.

The field write precedes both the callback-argument read and the invocation. The callback argument is not a value captured before the field write. If the destination overlaps that global storage, the argument read can therefore observe the write, subject to the actual memory layout.

The supplied material annotates F-e4e2db384d33 as nonreturning. That annotation is not an independently established dependency contract.

If the dependency does not return, this function performs no subsequent error-recording step. If it does return, the displayed continuation reaches conditional error recording using the reporting value captured before the field write and dependency call.

### 6. Conditionally record an error

When execution reaches error recording:

1. If the selected reporting value is zero, return without reading the context’s first word.
2. Otherwise, read the first 32-bit word at the retained context pointer.
3. If that word is zero, write the reporting value into it.
4. If that word is nonzero, leave it unchanged.
5. Return.

This is a conditional read followed by a possible write, not an established atomic operation.

An existing nonzero error word takes precedence over both `0x500` and the global reporting value. No sign restriction is applied to a nonzero reporting value.

The reporting value is retained from its earlier read; it is not reread after F-e4e2db384d33. The context pointer is likewise retained rather than reacquired. If that dependency returns, its effects on context lifetime or memory validity remain unknown.

## Acceptance examples

These examples are conditional static expectations, not executed tests. Unless stated otherwise, assume a nonnull context, valid addresses, and no interfering concurrent or dependency effects.

1. **Null context:** With any inputs, if F-7fba0909c452 returns null, processing ends without record/global reads or writes by this function after that call.

2. **Lower target boundary:** Target `0x4000`, selector `0x1205`, and value zero produce a 32-bit zero store at the selected record’s offset `0x64`, followed by return.

3. **Upper target boundary:** Target `0x4007`, selector `0x1209`, and value `-1` produce a 32-bit store of the supplied negative value’s representation at offset `0x60`. There is no range rejection.

4. **Ineligible target:** Target `0x4008` produces no record-field update. If the context’s first word is zero, it becomes `0x500`; if already nonzero, it remains unchanged.

5. **First validated maximum:** For selector `0x1205`, value `0x800000` is accepted. Value `0x800001` is rejected and reaches error recording with the captured reporting-global value.

6. **Zero reporting value:** For a rejected `0x1205` value, if the captured reporting value is zero, the function returns without reading the context’s first word.

7. **Preserved error:** For a rejected value and a nonzero captured reporting value, an already nonzero first context word is not replaced.

8. **Second validated boundary:** For selector `0x1206`, value `0x5A0000` is accepted; `0x5A0001` is rejected. The rejected case performs neither the offset-`0x68` store nor the dependency call.

9. **Isolated accepted value:** For selector `0x1206`, value `0xB40000` is stored at offset `0x68`, then the callback argument is read and F-e4e2db384d33 is invoked.

10. **Unsupported selector:** With an eligible target and an unsupported selector, the displacement and reporting globals are read, but error recording uses `0x500`, not the captured reporting value.

11. **Returning callback:** If F-e4e2db384d33 returns and the retained context remains valid, a nonzero captured reporting value causes the subsequent first-word check. Whether a write occurs depends on that word’s value at that time.
