# F-ad862549a0f2

## Purpose

F-ad862549a0f2 performs a conditional unsigned comparison between a value returned by F-3803ab006ceb and a threshold obtained from a referenced object.

The operation first checks an outer reference and its stored object address. A null outer reference produces a fixed failure result. A nonnull outer reference containing a null object address instead returns a shared fallback word, without checking the remaining arguments.

When the object address and both auxiliary arguments are nonzero, the operation selects one of two metadata interpretations using a flag in the object. It adjusts that metadata value, passes the resulting signed 16-bit value and an opaque argument to F-3803ab006ceb, and compares the dependency’s unsigned result against half of a 16-bit object field. The comparison produces either zero or 35.

These mechanics are established by the supplied static representation. The meanings of the object, metadata, dependency result, and numeric return codes are not established. Interpreting them as a capacity check, validation operation, or resource calculation would be inferred intent, not part of this contract.

## Interface

### Inputs

The operation has four inputs:

1. **Outer reference.** A nullable address of a slot containing a 32-bit object address.
2. **Metadata address.** A 32-bit address-like value. Zero is rejected on the ordinary object-present path. A nonzero value is used as the base of a metadata read.
3. **Gate value.** A 32-bit value tested only for equality with zero. It is not dereferenced, passed to the dependency, or otherwise used in the supplied body.
4. **Opaque dependency argument.** A 32-bit value forwarded to F-3803ab006ceb without an explicit transformation.

The static representation describes a 32-bit address and integer environment. A portable interface for a different address width is not established.

### Relevant layouts

The outer-reference slot contains the object address at offset zero.

The referenced object has these relevant fields:

| Byte offset | Width | Interpretation |
|---|---:|---|
| 0x1c | 16 bits | Unsigned threshold source |
| 0x30 | 32 bits | Flags; mask 0x00000002 selects the metadata interpretation |

The metadata region has a field beginning at byte offset 0x1c:

| Object flag condition | Read width | Interpretation before adjustment |
|---|---:|---|
| Mask 0x00000002 clear | 8 bits | Unsigned |
| Mask 0x00000002 set | 16 bits | Signed |

These offsets describe only the accessed fields. They do not establish complete structure definitions, allocation sizes, alignment rules, or byte order.

### Output

The return value is a 32-bit word:

- **0xffffffce** for a null outer reference, or for a zero metadata address or zero gate value after a nonnull object address has been obtained. This bit pattern represents −50 when interpreted as signed 32-bit.
- **The shared fallback word** when the outer-reference slot contains a null object address.
- **0x00000023**, decimal 35, when the dependency result exceeds the derived threshold.
- **0x00000000** otherwise.

The fallback word’s value is not supplied. It may coincide with another return value; the operation does not distinguish such a collision.

## Behavior

### Early decisions

The first decision concerns whether the outer reference is null.

If it is null, the operation returns 0xffffffce. It does not read an outer-reference slot, inspect either referenced region, read the shared fallback word, or call F-3803ab006ceb.

If the outer reference is nonnull, the operation reads its stored object address once.

If that address is zero, the operation reads and returns the shared fallback word immediately. This branch takes precedence over validation of the metadata address and gate value. In particular, zero values for either of those inputs do not change this result.

If the stored object address is nonzero, both the metadata address and gate value must be nonzero to continue. If either is zero, the result is 0xffffffce. No object flag or metadata-field read is required on this rejected path, and the dependency is not called.

A nonzero address is not a validity guarantee. The operation contains no explicit checks for accessibility, allocation extent, alignment, lifetime, or address-arithmetic overflow.

### Metadata selection and adjustment

For the continuing path, the operation reads the object’s 32-bit flags field at offset 0x30 and tests mask 0x00000002. Other flag bits do not affect the visible decision.

When the mask is clear:

- The metadata field at offset 0x1c is read as an unsigned byte.
- One is added.
- The adjusted value is held as a signed 16-bit value.

The byte ranges from 0 through 255, so the adjusted value ranges from 1 through 256. This branch has no 16-bit representability boundary.

When the mask is set:

- The metadata field at offset 0x1c is read as a signed 16-bit value.
- Two is added.
- The adjusted value is held as a signed 16-bit value.

The mathematical adjusted range is −32766 through 32769. Results through 32767 fit the stated signed 16-bit destination. The two larger results require narrowing. The supplied representation establishes that narrowing occurs, but does not independently establish its out-of-range conversion rule. Under a low-16-bit, two’s-complement interpretation, source values 32766 and 32767 become dependency arguments −32768 and −32767 respectively. Those boundary outcomes are conditional, not unqualified portability guarantees.

Negative source values are not rejected. For example, a signed metadata value of −2 produces an adjusted value of zero.

Only the selected metadata width is read. The byte branch does not require the following byte to participate in the value.

### Dependency call

The operation calls F-3803ab006ceb once, passing:

1. The adjusted signed 16-bit value.
2. The opaque fourth input.

The dependency result is treated as an unsigned 32-bit value.

The supplied body does not establish the dependency’s declared interface, internal interpretation of either argument, ownership behavior, or state effects. In particular, the opaque argument must not be assumed to remain unused merely because the caller does not inspect it.

### Threshold read and comparison

After the dependency returns, the operation reads the object’s unsigned 16-bit field at offset 0x1c. It shifts that value right by one bit, equivalent to unsigned integer division by two with any fractional part discarded.

The resulting threshold ranges from 0 through 32767.

The comparison is unsigned:

- If the threshold is strictly less than the dependency result, return 35.
- Otherwise, return zero.

Equality therefore returns zero.

The object address used for this final read is the address captured before the dependency call. The outer-reference slot is not reread. Consequently, changing the slot during the dependency call does not redirect the final read.

The threshold field itself is read after the call, not saved before it. If the dependency changes that field and leaves the referenced storage valid, the changed value participates in the comparison. The flag and metadata values are not reread after the dependency returns.

1. Read the object address from the outer-reference slot.
2. Read the object flags.
3. Read the selected metadata field.
4. Call F-3803ab006ceb.
5. Read the threshold source through the previously captured object address.
