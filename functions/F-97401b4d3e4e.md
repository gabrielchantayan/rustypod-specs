# F-97401b4d3e4e

## Purpose

The established behavior is a short, incomplete execution fragment: derive two integer arguments from an explicit input and an additional incoming execution-state value; invoke an indirectly selected destination; if that invocation returns normally, write the additional value into memory at an offset from itself; then reach a boundary identified as invalid instruction data.

No application-level purpose is established. In particular, the evidence does not establish that the write initializes an object, links a structure, records ownership, or repairs state. Those interpretations would require additional evidence.

This contract distinguishes behavior directly represented in the supplied fragment from conditional machine-width interpretations. The invalid-instruction warning limits confidence in the recovered function boundary and terminal behavior.

## Behavior

### 1. Construct the indirect-call arguments

The first argument is formed from P using these represented operations:

- Shift P left by 13 bit positions.
- Shift that intermediate right by 8 bit positions.
- Subtract the original P.
- Multiply the difference by 1,048,576, which is 2²⁰.

The second argument is R shifted left by 2 bit positions.

There are no visible arithmetic checks, saturation operations, or alternative paths for large, negative, or otherwise exceptional inputs.

The supplied representation does not establish an observable order between the independent calculations of the first argument, second argument, and indirect destination. It does establish that their resulting values are available for the indirect invocation.

### 2. Select and invoke the destination

The indirect destination is obtained by adding 3,764, hexadecimal 0xEB4, to L. The resulting value is treated as a code destination and invoked with the two arguments described above.

This is not visibly a load of a function pointer from a memory slot at that offset. The represented operation uses the computed address itself as the destination.

No null check, executable-address check, destination classification, or fallback destination is visible.

The invocation’s return value, if any, is not visibly consumed. A normal return leads to the subsequent write. A fault, nonreturning transfer, or other failure to resume prevents this fragment from reaching that write through the represented path.

### 3. Perform the post-call write

After the indirect invocation returns, the fragment writes R to the address obtained by adding 116, hexadecimal 0x74, to R.

The offset is a byte-address displacement in the supplied representation, not an index scaled by the size of the stored integer.

The write is unconditional on the visible continuation. There is no intervening status check or branch based on a return value.

The supplied representation uses the same R for the pre-call argument calculation and the post-call address and stored value. This establishes their relationship within that representation. It does not independently establish the underlying calling convention or prove which physical execution state an arbitrary destination preserves.

### 4. Reach the invalid-instruction boundary

Immediately after the write, the supplied fragment ends at a marker for bad instruction data and truncated control flow.

The strongest supported conclusion is that no subsequent valid instruction sequence or ordinary return is provided by this evidence. It is not established that execution necessarily halts the processor, terminates a process, raises a particular exception, or invokes an actual termination routine.

### Conditional 32-bit arithmetic model

If the integer operations are interpreted as fixed-width 32-bit operations with discarded high bits, the first argument has a useful equivalent description:

**First argument = the low 32 bits of 31 × P × 2²⁰.**

Equivalently, take the low 12 bits of 31 × P and place them in bits 20–31; bits 0–19 are zero.

This equivalence holds for either arithmetic or logical right shift in this particular expression under the stated fixed-width assumptions: any difference introduced into the high bits by right shifting is discarded by the final multiplication and truncation.

Consequences under that model include:

- Only the low 12 bits of P affect the first argument.
- Inputs differing by a multiple of 4,096 produce the same first argument.
- The first argument is always a multiple of 1,048,576 as an unsigned bit pattern.
- The second argument is four times R modulo 2³².

These are conditional bit-vector results, not a claim that signed source-language overflow or negative left shifts have defined behavior.

### Ordering

1. Prepare the call destination and arguments.

This sequencing is not a concurrency or memory-barrier guarantee. Atomicity, visibility to other execution contexts, and ordering relative to external agents are not established.
