# F-d92e879159c4

## Purpose

F-d92e879159c4 updates a caller-owned cursor using address-bearing links in a node structure.

The established behavior has two paths:

- If the current node’s link at byte offset 12 is nonzero, follow that link once and then follow links at byte offset 8 until a zero link is encountered. Publish every visited node address to the cursor.
- Otherwise, examine links at byte offset 4, publishing ancestors while a particular offset-12 relationship holds. At the stopping point, either publish the candidate ancestor or leave the cursor unchanged, according to a second offset-12 comparison.

This resembles movement to an in-order successor in a parent-linked binary tree, potentially with a sentinel convention. That interpretation is inferred intent, not an established input invariant. The contract below uses offsets and address relationships rather than requiring tree terminology.

The function does not return a node address directly. Its result is the final value stored in the caller’s cursor.

## Behavior

### Initial decision

The function reads the cursor and then reads the field 12 bytes beyond the node address obtained from it.

That field’s value determines the path. This initial read is not replaced by a later re-read before entering the nonzero-link path.

### Nonzero initial offset-12 link

When the initially read offset-12 link is nonzero, that link becomes the first selected node address.

For each selected node, the function:

1. Writes the selected node address into the caller’s cursor.
2. Reads the selected node’s offset-8 link.
3. Continues with that link if it is nonzero.

A zero offset-8 link ends this path, and the function returns immediately.

Consequences:

- The cursor is written at least once on this path.
- The final cursor identifies the last selected node whose offset-8 link is zero.
- The function publishes intermediate selections rather than waiting to publish only the final result.
- Offset-4 links are not used on this path.
- After the initial branch-selection read, offset-12 links are not used on this path.
- The first offset-8 read occurs after the corresponding cursor write.

That last ordering matters when storage aliases or another observer can see writes. It is not equivalent, in all memory arrangements, to performing a read-only traversal followed by one final cursor assignment.

### Zero initial offset-12 link

When the initial offset-12 link is zero, the function reads the cursor again and obtains an upward candidate from that current node’s offset-4 field.

It then compares the candidate’s offset-12 field with the current cursor value.

If those values are equal:

- The candidate address is written to the cursor.
- The next candidate is read from that candidate’s offset-4 field.
- The relationship comparison repeats.

Thus, each successful relationship comparison publishes one upward step before the following candidate is fetched.

If the candidate’s offset-12 field is not equal to the cursor, the upward loop stops. The candidate that caused the mismatch has not yet been written to the cursor by that iteration.

### Final decision after upward traversal

After the upward loop stops, the function reads the offset-12 field of the node currently identified by the cursor.

- If that field differs from the stopping candidate, the function writes the candidate to the cursor.
- If that field equals the stopping candidate, the function performs no final cursor write.

The function then returns.

The stopping candidate is therefore not unconditionally the output. The final relationship check can preserve the current cursor instead.

On this path, the number of cursor writes is the number of successful upward-loop comparisons, plus either zero or one final write.

### Read and write ordering

The established source-level sequence includes these ordering constraints:

- Initial offset-12 read precedes either branch.
- On the nonzero-link path, each cursor write precedes the selected node’s offset-8 read.
- On the upward path, each successful comparison precedes its cursor write.
- Each upward cursor write precedes the next candidate’s offset-4 read.
- The loop’s stopping comparison precedes the final offset-12 comparison.
- The final comparison precedes any final cursor write.

The two operands of an equality comparison are not given a source-level evaluation order. In particular, the supplied representation does not establish whether a candidate’s offset-12 field or the cursor is read first within the loop comparison.

These are source-level observations, not a claim about individual machine loads, compiler optimizations, atomicity, or hardware memory ordering.
