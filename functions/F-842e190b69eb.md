# F-842e190b69eb

## Purpose

- A **primary update** writes a marker and replaces a stored value.
- A **secondary update** either copies a stored value into another field or clears that field and writes a different marker.

Some decisions use direct equality of 32-bit values. Others compare results from dependency F-f4ffd1965bfa. Several paths return without any direct record writes.

“Primary,” “secondary,” and “marker” are descriptive labels for this contract, not established application-level meanings. The evidence does not identify the surrounding feature, the semantic types of the input values, or the meaning of the dependency’s results.

## Behavior

### Primary-path selection

The first direct operation reads the four-byte field at +0x14 and compares it with B.

If they are equal, the function selects the primary update immediately. It makes no dependency calls on this route.

If they differ, the function performs two dependency calls in this order:

1. F-f4ffd1965bfa with no explicit argument shown in the supplied evidence.
2. F-f4ffd1965bfa with B as the explicit argument.

Each result is represented as a 32-bit integer for comparison. The first result is retained across the second call.

If those results are equal, the function selects the primary update. If they differ, it enters the secondary eligibility checks.

The dependency comparison is not evidence that the two input values themselves are equal, nor that the dependency implements a stable equivalence relation. The established condition is equality of these particular returned values.

### Primary update

The primary update performs two four-byte stores, in this order:

1. Write integer value 1 at +0x0C.
2. Write A at +0x20.

The function then returns.

It does not directly clear +0x10 or +0x24 on this path. Any earlier values in those fields remain untouched by this body, although preceding dependency calls may have changed them.

A may be zero. There is no zero-value exclusion on the primary update; writing zero to +0x20 is permitted by the observed behavior.

### Secondary eligibility checks

This path is reached only when the initial +0x14 comparison failed and the first pair of dependency results differed.

The function reads +0x20. If that value is zero, it returns without a direct write.

Otherwise, it reads +0x1C and compares the result with A. If they differ, it returns without a direct write.

If +0x1C equals A, it reads +0x18 and compares that value with B:

- If equal, secondary eligibility is satisfied without further dependency calls.
- If different, the function makes another pair of dependency calls.

That additional pair is ordered as follows:

1. Call F-f4ffd1965bfa with B.
2. Read +0x18 again and call F-f4ffd1965bfa with the newly read four-byte value.

The second read of +0x18 matters. Its value is not necessarily the value used by the earlier direct comparison: the intervening call may have changed accessible state.

If these additional dependency results differ, the function returns without a direct write. If they are equal, it proceeds to the secondary update.

### Secondary update

The function reads +0x24 and records whether the value read is zero.

If that value was zero:

1. Read +0x20 again.
2. Write that newly read four-byte value to +0x24.
3. Return without directly writing +0x10.

The copied value is the value observed at this later read of +0x20. It is not necessarily the nonzero value observed during the earlier eligibility check. Intervening dependency calls may have changed it.

If the value read from +0x24 was nonzero:

1. Write zero to +0x24.
2. Write integer value 1 to +0x10.
3. Return.

The choice between these branches is based on the zero test already performed on +0x24. It is not recomputed after writing that field.
