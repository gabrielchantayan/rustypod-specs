# F-2ea2b66f82a0

## Purpose

F-2ea2b66f82a0 consumes a signed-length sequence of bytes and modifies caller-supplied state. Each iteration shifts a selected 32-bit word left by eight bits, writes that intermediate value, and then writes the shifted value combined with the current unsigned input byte. A position field controls destination selection.

After incrementing the position, the function invokes F-2d7ef8651bbe if the updated position’s lowest six bits are zero. Following normal return, it resets the position to zero. It then updates two 32-bit count fields using an addition of eight and a carry.

**Inferred intent:** ordinary positions from 0 through 63 describe a 64-byte accumulator with a two-word bit count. This does not establish a particular algorithm or the dependency’s transformation.

**Important qualification:** positions outside that ordinary range are not visibly rejected. Their calculated destinations can overlap other state fields, including the count fields. Consequently, preserving the count fields across the dependency is not sufficient to establish that the combined count advances by exactly eight relative to its value before the iteration.

## Behavior

### Widths and arithmetic interpretation

Input bytes are loaded unsigned and contribute values from 0 through 255.

Destination selection interprets the position as signed and divides it by four. Under the supplied representation’s signed-division semantics, division truncates toward zero. The resulting quotient is multiplied by four and added to the state address and `0x14`.

This calculation is not generally interchangeable with unsigned division, rounding down, masking the position, or restricting it to six bits. For example, positions −1, −2, and −3 all have a quotient of zero under truncation toward zero.

For describing word contents, this contract uses a 32-bit bit-pattern model: shifting left eight discards the former highest byte, and inserting the input byte places it in bits 7–0. Position and count stores likewise have 32-bit width.

The supplied representation contains signed arithmetic and a signed left-shift expression. Exact originating-language overflow rules and executable behavior at arithmetic boundaries are not independently established. Examples involving such operations are conditional on the stated 32-bit bit-pattern model rather than claims about unrestricted source-language definedness.

### Per-iteration accesses and updates

Iterations visit input offsets in ascending order, beginning at zero.

Each iteration has the following behavior:

1. **Select the initial destination.** Read the position at `0x154`. Use its signed quotient by four to calculate the destination word.

2. **Read, shift, and write that word.** Read the selected 32-bit value, shift it left eight bits, and write the shifted result back to the initial destination. Retain that shifted result for the later combination.

3. **Recalculate the destination and obtain the byte.** Read the position again to calculate a second destination. Read the current unsigned input byte. The supplied expression does not establish an ordering between this position reload and the input-byte read. Both occur after the first word write.

4. **Write the combined result.** Write the retained shifted value, combined with the input byte using bitwise OR, to the second destination. This operation does not reload the second destination’s current word value.

5. **Advance the position.** Read the position after the combined write, add one, and store the 32-bit result at `0x154`.

6. **Handle a position boundary.** Test the updated position’s lowest six bits. If all are zero, call F-2d7ef8651bbe with the state address. If it returns normally, write zero to `0x154`.

7. **Update the lower count.** Read the field at `0x15C`, add eight, and store the 32-bit result there.

8. **Update the upper count.** After the lower-count store, read the field at `0x158`. Add one if the newly calculated lower result is less than eight under unsigned comparison; otherwise add zero. Store the 32-bit upper result in either case.

The first destination-word write precedes the current byte’s read. It is therefore behaviorally distinct from computing a combined result and performing only one write.

### Ordinary, non-overlapping accumulation

When the position is not changed between the two destination calculations, both calculations select the same word.

Positions 0–3 select offset `0x14`; positions 4–7 select `0x18`; subsequent groups of four select successive words. Four consecutive byte insertions into one word replace all of its previous bits. The first inserted byte becomes bits 31–24, and the fourth becomes bits 7–0.

This describes a word’s numeric bit pattern. It does not establish the order of bytes at physical memory addresses.

### Boundary handling

The boundary condition is a low-six-bit test, not an equality check against 64.

In the ordinary range, an iteration starting at position 63 selects offset `0x50`, incorporates the byte, and stores position 64. It then calls F-2d7ef8651bbe, resets the position to zero after normal return, and performs the explicit count updates.

The dependency therefore runs after the position increment but before this iteration’s count increment. It can observe count fields that do not yet include that explicit increment.

Any position value written by the dependency is overwritten by the subsequent reset. Count fields are instead read after the call and are not restored from pre-call snapshots. Other dependency changes are likewise not generally undone.

### Aliasing and calculated destinations outside the ordinary range

The function takes no input snapshot. An input byte can reflect writes from earlier iterations, the current iteration’s first word write, or a dependency call.

Calculated destinations can also overlap fields used by later operations:

- A destination overlapping the position field can change the position used for the second destination calculation or the later increment.
- A destination overlapping the upper count can change the value subsequently read for the upper-count update.
- A destination overlapping the lower count can change the value subsequently read for addition of eight and carry detection.

In particular, position 324 selects offset `0x158`, and position 328 selects offset `0x15C`. These are direct overlaps with the upper and lower count fields, respectively.

If the first destination write changes the position, the second destination need not equal the first. Its combined value still uses the shifted result obtained from the first destination, not a freshly shifted value from the second destination.

The wider interface’s policy on these arrangements is unknown. The visible function neither rejects unusual positions nor enforces non-overlap.

## Side effects

### Direct writes

Each normally completed iteration performs:

- One shifted-word write.
- One combined-word write.
- One position-increment write.
- One lower-count write.
- One upper-count write.
- An additional position-reset write if a boundary call returns normally.

The two destination-word writes remain distinct even when their addresses are equal. When a destination aliases another state field, these writes can affect that field before its separately described update.

### Count behavior and its limits

At the explicit count-update stage, the function adds eight to the lower field and adds the resulting unsigned carry indicator to the upper field. The upper field is stored even when there is no carry.

Under the 32-bit bit-pattern model, this stage advances the combined two-field value by eight modulo \(2^{64}\), relative to the field values immediately before that stage, assuming no intervening mutation.

For that relationship also to hold relative to the count at the beginning of each iteration, all of the following must hold:

- Neither calculated destination-word write overlaps either count field.
- The dependency, if invoked, does not change either count field.
- No other mutation changes the count fields during the relevant accesses.

Dependency preservation alone is insufficient. An unusual position can cause this function’s own destination writes to alter a count field before the explicit addition.

There is no third count field or separately reported overflow. A carry out of the upper 32-bit field is discarded under the bit-pattern model.

### Errors, interruption, and concurrency

No error-reporting, rollback, or recovery path is visible. Invalid accesses or abnormal dependency behavior have execution-environment-dependent consequences.

Updates are not transactional. Interruption can leave the shifted write visible without the combined write, the incremented position visible without a count increment, or the lower count updated without the upper-count store.

No synchronization mechanism is visible. Atomicity, thread safety, and guarantees for concurrent or special-purpose memory are not established.

- Position 64 is stored before the dependency call.

### Carry and upper wrap

Given lower count `0xFFFFFFFC`, upper count 7, and no preceding count mutation:

- The lower-count addition produces 4.
- Since 4 is less than 8 under unsigned comparison, the upper count becomes 8.

With upper count initially `0xFFFFFFFF` instead, that carry produces upper count zero under the bit-pattern model.

### Boundary outside the ordinary range

Given position 127 and valid calculated storage:

- The destination is offset `0x90`.
- Position advances to 128.
- The dependency is invoked because the updated position’s lowest six bits are zero.

There is no visible rejection merely because the initial position exceeds 63.

### Destination overlapping the upper count

Given position 324, upper count 7, lower count zero, and input byte `0xAB`:

- The calculated destination is `0x158`, the upper-count field.
- The first word write changes the upper count to `0x00000700`.
- The combined write changes it to `0x000007AB`.
- Position becomes 325, so no dependency is called.
- The explicit lower-count update produces 8.
- There is no carry, so the upper-count store leaves `0x000007AB`.

The final combined count is not the entry combined count plus eight, despite there being no dependency call.

### Destination overlapping the lower count

- Position becomes 329; no dependency is called.

- The carry test is false, so upper count remains 7.
