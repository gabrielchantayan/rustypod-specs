# F-f423878c9263

## Purpose

F-f423878c9263 conditionally stores a supplied 32-bit value through a destination selected by a two-word mutable record, then replaces the record’s second word with that supplied value.

A zero supplied value is rejected without accessing the record. A nonzero supplied value selects one of two update paths:

- If the record’s second word is zero, the supplied value is written into the record’s first word.
- If the record’s second word is nonzero, that word is interpreted as an address, and the supplied value is written to the addressed location.

After either successful path, the supplied value is written into the record’s second word. The function then returns zero.

**Inferred intent:** The record resembles an append-state pair consisting of an initial value and a current link destination. The operation may initialize or extend a linked structure. That interpretation is not required by the observed behavior. The supplied value is not dereferenced during this invocation, and the evidence does not establish a node layout.

## Interface

### Inputs

The function receives two arguments:

1. **Record address.** An address used to access a mutable record with two consecutive integer-sized fields:
   - **First word:** offset 0.
   - **Second word:** offset 4 in the recovered 32-bit model.

2. **Supplied value.** An integer-sized value tested against zero and, when nonzero, copied into one or two destinations.

The recovered representation uses 32-bit integer words. The return value is also four bytes wide. Interpreting a stored word as an address follows the recovered 32-bit address model; the evidence does not establish portability to a different pointer width or ABI.

The supplied value is not subject to a positivity check. Any nonzero 32-bit representation takes the update path, including values represented as negative signed integers.

### Output

On normal return, the result is:

| Condition | Return value |
|---|---:|
| Supplied value is zero | 1 |
| Supplied value is nonzero and the selected memory operations complete | 0 |

These results distinguish the zero-input path from the completed update path. No additional error codes are established.

### Required accessible memory

For a zero supplied value, the function does not access the record. No record-memory validity requirement is imposed by that path’s explicit operations.

For a nonzero supplied value:

- The record’s second word must be readable and writable.
- If the second word is zero when checked, the first word must be writable.
- If the second word is nonzero, the address obtained from that field must permit an integer-sized write.

Alignment and address-validity requirements depend on the execution environment. The function does not check them.

There is no explicit requirement that the supplied value itself designate accessible memory during this invocation. It is stored as data, not followed as a pointer.

## Behavior

### Zero supplied value

The supplied value is checked before any record access.

If it is zero, the function returns 1. On this path:

- Neither record field is read.
- Neither record field is written.
- No address stored in the record is followed.
- No memory is allocated or released.

Consequently, even an unusable record address is not dereferenced on the zero-input path. This describes the function’s explicit behavior, not a broader guarantee about argument handling by a caller or execution environment.

### Nonzero supplied value with a zero second word

The function reads the record’s second word and tests it against the null-address representation.

If that word is zero:

1. The supplied value is written into the record’s first word.
2. The supplied value is written into the record’s second word.
3. The function returns 0.

The two stores are ordered in the recovered expression sequence: the first-word store precedes the second-word store. The first word’s previous contents are not read before being overwritten.

Successful completion leaves both record fields equal to the supplied value.

The zero test concerns only the second word. The first word need not initially be zero or agree with any other state.

### Nonzero supplied value with a nonzero second word

If the checked second word is nonzero, the function uses the address represented by that field as the destination of an integer-sized store.

The recovered expression sequence accesses the second word again to obtain this destination. It then:

1. Writes the supplied value to the addressed location.
2. Writes the supplied value into the record’s second word.
3. Returns 0.

The destination’s previous contents are not read before the store.

The record’s first word receives no direct store on this path. It can nevertheless change if the selected address aliases it.

For ordinary memory with no intervening mutation, the checked second-word value and the destination address are the same. The evidence does not justify a stronger claim about the number of physical loads, compiler-generated instructions, or behavior under concurrent modification.

### Aliasing

No distinctness check separates the indirect destination from the record.

If the second word points to the first word, the indirect store updates the first word, and the later store updates the second word. Both finish equal to the supplied value.

If the second word points to itself, the indirect store and final record store target the same word. Both write the same supplied value. The first word is unchanged by the explicit operations.

Other overlaps receive no special handling. Their effects depend on the represented addresses, access alignment, and memory semantics. In particular, this contract does not infer support for unaligned or partially overlapping writes merely because no explicit check rejects them.

### Arithmetic and value handling

There is no arithmetic on the supplied value, no capacity calculation, and no traversal.

The observable value handling consists of:

- Comparing the supplied integer with zero.

Within the recovered 32-bit model, the stores preserve the supplied value’s 32-bit representation. There is no narrowing conversion, increment, range restriction, or overflow calculation in the shown operation.

## Side effects

### Memory writes

For zero input, there are no explicit memory writes.

For nonzero input, successful execution performs two integer-sized stores:

| Initial checked second word | First store | Second store |
|---|---|---|
| Zero | Record’s first word | Record’s second word |
| Nonzero | Location addressed through the second word | Record’s second word |

The selected first store precedes the final second-word store. Aliasing can make both stores target the same location.

The function provides no explicit transactional mechanism. If a memory operation fails after an earlier store has taken effect, no rollback is shown. The evidence does not establish which effects an execution environment preserves or exposes after a fault.

### Ownership and lifetime

## Acceptance examples

These examples are conditional on a compatible 32-bit representation, accessible memory for every selected operation, and no concurrent mutation unless stated otherwise. They describe expected behavior; no runtime tests have been performed.

### Zero input bypasses the record

Given any record address and a supplied value of zero:

- The result is 1.
- The function does not read or write through the record address.

An inaccessible record address does not, by itself, cause an explicit dereference on this path.

### Zero second word initializes both fields

Given a writable record whose first word is 9 and whose second word is zero, with a supplied value of 37:

- The first word is written with 37.
- The second word is subsequently written with 37.
- The result is 0.

The original first-word value does not affect this behavior.

### Nonzero second word selects an external destination

Given a record whose first word is 9 and whose second word represents an accessible external word, with a supplied value of 37:

- The external word is written with 37.
- The record’s second word is subsequently written with 37.
- The first word remains 9, provided the destination does not alias it.
- The result is 0.

The external word’s previous value is irrelevant to the selected operations.

### A nonzero value need not be a valid address now

- The current invocation still stores that value into both record fields.
- It returns 0 if those stores complete.

A later nonzero invocation may attempt to use the stored second word as an address. Success of the current invocation does not establish validity for that later operation.

### Self-referential destination

Given a second word that represents its own address and a supplied value of 37:

- The indirect store writes 37 into the second word.
- The final store writes 37 into that same word.
- The first word receives no explicit write.
- The result is 0 if the accesses complete.

### Invalid indirect destination

- A normal return, the final second-word update, and recovery behavior are not guaranteed.
