# F-a9e7346d7015

## Purpose

F-a9e7346d7015 compares two explicitly counted sequences of unsigned 16-bit units, using either a restricted direct comparison or dependency F-2bd864ccf2c1.

The directly implemented comparison is lexicographic. Options can remove leading units below `0x0021`, fold ASCII lowercase letters to uppercase, force delegation, or make eligible ASCII digits trigger delegation. Direct comparison is available only for pairs that satisfy a numeric bound and shared classification-table checks.

The direct path returns these 32-bit patterns:

| Result | Meaning |
|---|---|
| `0x00000000` | The effective sequences compare equal. |
| `0x00000001` | The first effective sequence orders after the second. |
| `0xFFFFFFFF` | The first effective sequence orders before the second. |

Delegated results are returned unchanged. The supplied evidence does not establish that F-2bd864ccf2c1 follows this three-value convention.

An optimized comparison with a more general fallback is **inferred intent**. The fallback’s collation, numeric treatment, encoding assumptions, and error behavior remain unknown.

## Interface

### Arguments and representation

The function accepts five arguments, in this order:

| Argument | Representation | Meaning |
|---|---|---|
| First sequence | Pointer to unsigned 16-bit units | Beginning of the first counted sequence |
| First count | Signed 32-bit integer | First sequence length in units |
| Second sequence | Pointer to unsigned 16-bit units | Beginning of the second counted sequence |
| Second count | Signed 32-bit integer | Second sequence length in units |
| Options | Unsigned 32-bit integer | Comparison and delegation controls |

Counts measure 16-bit units, not bytes. Advancing a pointer by one unit advances its byte position by two. Units are interpreted as unsigned values from `0x0000` through `0xFFFF`; no text encoding is established.

There is no separate capacity, output buffer, encoding parameter, or error-result parameter. The representation supplied here does not independently establish pointer width or byte order.

### Options

| Mask | Established behavior |
|---|---|
| `0x01` | Fold ASCII lowercase letters during direct comparison; pass a zero-or-one value to F-2bd864ccf2c1. |
| `0x02` | Remove leading units below `0x0021`, independently from each sequence, before either comparison path. |
| `0x04` | Delegate after optional leading removal, bypassing the shared initialization check and direct comparison. |
| `0x08` | Pass a zero-or-one value to F-2bd864ccf2c1; no direct-comparison effect is established. |
| `0x10` | Delegate when an eligible pair contains an ASCII decimal digit on either side; also pass a zero-or-one value to F-2bd864ccf2c1. |

Other option bits have no visible use in this function. The complete option word is not forwarded.

### Result and preconditions

The result occupies 32 bits. The direct-path all-ones result is conventionally interpreted as signed `-1`, but its established representation is `0xFFFFFFFF`.

For ordinary counted-sequence behavior:

- Both counts must be nonnegative.
- Every unit actually read must be accessible through the corresponding pointer.
- Pointer advancement must remain valid for the represented sequence.
- Reached shared-pointer reads, their target accesses, and classification lookups must be valid.
- Any invoked dependency must satisfy its own, separately unknown requirements.

The function performs no explicit argument validation. A zero count suppresses this function’s own sequence dereference on that side, but does not bypass direct-path initialization or establish that a delegated dependency accepts an invalid or null sequence pointer.

Negative counts are not rejected or treated as empty. Loop conditions test for nonzero counts, not positive counts. Negative-count traversal and eventual signed-arithmetic overflow are outside the valid-input contract.

## Behavior

### Leading-unit removal

When option `0x02` is set, the function processes the first sequence completely before processing the second.

For each sequence, it reads the current unit only while the count is nonzero. A value below `0x0021` is removed from the effective sequence by reducing the count by one and advancing the pointer by one unit. Processing stops at a zero count or a current unit at least `0x0021`.

This threshold includes every value from `0x0000` through `0x0020`. It is not a demonstrated locale or Unicode whitespace classification. A zero unit is removable data, not a terminator.

Only leading units are removed. Interior and trailing units are unaffected. The function neither clears removed units nor writes updated positions back to the caller.

The resulting pointer/count pairs are the **effective sequences**. They are retained as the argument values for any later delegation, even if direct comparison advances separate working positions.

Leading removal occurs before any initialization dependency. Consequently, initialization cannot retroactively change which positions were removed, although it may change storage at positions that will subsequently be read.

### Forced delegation

With option `0x04` set, the function delegates immediately after optional leading removal.

F-2bd864ccf2c1 receives seven arguments:

1. Effective first pointer.
2. Effective first count.
3. Effective second pointer.
4. Effective second count.
5. Zero or one derived from option `0x01`.
6. Zero or one derived from option `0x08`.
7. Zero or one derived from option `0x10`.

On this path, F-a9e7346d7015 does not read the shared initialization pointer, its target byte, or the shared classification-table base pointer. It performs no direct pair comparison.

The dependency’s 32-bit result becomes the result without normalization or error translation.

### Initialization before the direct path

When option `0x04` is clear, the function creates working positions and counts from the effective sequences.

It then obtains a pointer from shared initialization-pointer storage and reads the byte at that pointer’s target. If the byte is zero, it calls F-9b7bef8bbc6d with no explicit arguments. A nonzero target byte skips that call.

This involves two distinct memory reads: the pointer-valued global read and the target-byte read. Describing only a read of an initialization flag would omit part of the established access behavior.

The check occurs even when either or both effective counts are zero. Empty comparisons can therefore invoke F-9b7bef8bbc6d.

After the call, the function does not recheck the initialization pointer or target byte and does not inspect a dependency result. It proceeds using the working positions and counts already established.

The dependency’s effects are unknown. In particular, it may alter input storage, the shared classification-table base pointer, or classification bytes. No classification-table base is captured before initialization. Later sequence and classification accesses use the state available when those accesses occur.

### Pair reads and direct-path eligibility

A pair is examined only while both working counts are nonzero.

The function first reads the current first-sequence unit, then the current second-sequence unit. Both unsigned 16-bit values are extended to 32 bits. Both sequence reads occur before the eligibility checks below.

Eligibility checks proceed in this order:

1. Reject the pair if the first value exceeds `0x007A`.
2. Otherwise obtain the shared classification-table base pointer, read the byte at the first value’s numeric index, and reject the pair if that byte is zero.
3. If the first side passed, reject the pair if the second value exceeds `0x007A`.
4. Otherwise obtain the shared classification-table base pointer again, read the byte at the second value’s numeric index, and reject the pair if that byte is zero.

Each reached lookup includes its own pointer-valued global read followed by its indexed byte read. The first lookup precedes the second. There is no established table-base snapshot shared across the two lookups or across pairs.

Short-circuiting matters:

- A first value above `0x007A` prevents both classification lookups.
- A zero first classification byte prevents the second-side bound check and lookup.
- A second value above `0x007A` prevents the second lookup.
- Both sequence units have nevertheless already been read.

Classification bytes are tested only for zero versus nonzero. Their actual contents are not supplied. An ASCII letter, digit, punctuation mark, or space is not automatically eligible merely because of its character identity.

Any eligibility failure causes fallback delegation.

### Digit-triggered delegation

After both sides pass eligibility, option `0x10` makes an ASCII decimal digit on either side trigger delegation.

The tested interval is `0x0030` through `0x0039`, inclusive. The first value is tested first; the second needs testing only if the first is not a digit.

The range test uses 32-bit unsigned subtraction and comparison. A value below `0x0030` wraps on subtraction and does not qualify as a digit.

This behavior is only a delegation trigger. Numeric ordering, digit-run handling, leading-zero treatment, and mixed alphanumeric comparison are not implemented by this function and cannot be inferred from the option alone.

### Folding and direct ordering

For an eligible pair that does not trigger digit delegation, option `0x01` folds values from `0x0061` through `0x007A` by subtracting `0x20`. Other values remain unchanged.

The lowercase-range test uses unsigned 32-bit arithmetic. Values below the lowercase interval do not qualify through a negative difference.

Eligibility and digit checks precede folding. Folding cannot rescue an ineligible unit.

The resulting values determine the outcome:

- First greater than second: return `0x00000001`.
- First less than second: return `0xFFFFFFFF`.
- Equal: consume one working unit from both sides and continue.

The ordering comparisons are signed 32-bit comparisons in the supplied representation. Eligible values, including folded values, are nonnegative and at most `0x007A`, so signed and unsigned order agree.

No case mapping beyond ASCII lowercase-to-uppercase folding is established.

### Exhaustion

If the pair loop ends without an earlier return or delegation:

| Remaining first count | Remaining second count | Result |
|---|---|---|
| Zero | Zero | `0x00000000` |
| Zero | Nonzero | `0xFFFFFFFF` |
| Nonzero | Zero | `0x00000001` |

For valid nonnegative counts, this gives ordinary equal-prefix ordering by remaining length.

No remaining sequence units or classification entries are read to obtain this result. A digit, ineligible value, or out-of-range value in an unexamined suffix cannot trigger fallback.

### Fallback restart

An eligibility failure or digit trigger delegates using the effective beginnings and effective counts, not the advanced working positions or remaining counts.

Thus a directly examined equal prefix is included again in the dependency’s arguments. The dependency may revisit that prefix, but its actual reads are unknown.

The seven argument positions and option normalization are identical to forced delegation. The function returns the dependency result unchanged, with no subsequent input or classification access of its own.

## Side effects

The function itself has no established writes to sequence storage, shared pointer storage, the initialization target, or classification bytes. Pointer advancement and count reduction are local bookkeeping.

Its observable access order can include:

1. Leading-unit reads from the first sequence, then the second.
2. A shared initialization-pointer read and a read of its target byte.
3. A call to F-9b7bef8bbc6d.
4. First-unit and second-unit reads for a pair.
5. A first shared table-base-pointer read and indexed byte read.
6. A separate second shared table-base-pointer read and indexed byte read.
7. Further pairs or delegation.

Branches suppress the accesses described above where specified. A first nonremoved unit can be read during trimming and again during direct comparison. Fallback passes already examined prefixes to the dependency.

No explicit allocation, release, or ownership-transfer operation appears in this function. This does not establish that dependencies preserve storage, retain no pointers, or avoid allocation or release. No ownership guarantee may be derived for their effects.

There is no visible locking or snapshot mechanism. Atomicity, race behavior, and thread safety are not established. In particular, independently reached table-base reads must not be described as necessarily returning the same pointer.

## Acceptance examples

These are conditional consequences of static evidence, not executed tests.

Unless an example states otherwise, counts and reached accesses are valid, direct comparison is selected, and relevant shared state remains stable during the described accesses. For examples involving particular unit values, initialization is either skipped or preserves those units until they are read. Reached classification lookups return nonzero bytes unless otherwise specified. A normally returning initializer with usable classification state alone is insufficient to justify those input-value assumptions.

1. **Two empty sequences.**  
   With both counts zero, the result is `0x00000000`, provided any invoked initialization dependency returns normally. The shared initialization pointer and its target byte are still read. No sequence unit or classification-table base is read.

2. **One empty sequence.**  
   A zero first count and positive second count produce `0xFFFFFFFF`; reversing the counts produces `0x00000001`. After initialization, the result requires no sequence-unit or classification access.

3. **Leading threshold.**  
   With option `0x02`, trimming reads `[0x0020, 0x0000, 0x0041]` and `[0x0041]` as effective one-unit sequences. If the retained units remain `0x0041` through comparison, the result is equality. A leading `0x0021` is not removed.

4. **Trailing data remains.**  
   With option `0x02`, `[0x0041, 0x0020]` is not shortened by trimming. If the first pair is read as equal against `[0x0041]`, the result is `0x00000001` without reading the trailing space during direct comparison.

5. **ASCII folding after initialization.**  
   If the units actually read for a one-unit pair are `0x0061` and `0x0041`, option `0x01` produces equality. Without that option, the result is `0x00000001`. Entry-time values alone do not establish these results if initialization may change them.

6. **Forced delegation.**  
   Option `0x04` delegates with the effective sequences, including zero counts. This function performs no initialization-pointer or classification-base read on that path.

7. **Initializer changes the table base.**  
   If F-9b7bef8bbc6d changes the shared table-base pointer and returns, a subsequent reached classification lookup obtains the pointer then present. It does not use a base captured before initialization.

8. **Independent lookup bases.**  
   An eligible first-side bound causes a table-base read followed by its indexed-byte read. If that byte is nonzero and the second value is within range, a separate table-base read precedes the second indexed-byte read. The contract does not require the two obtained pointers to be equal.

9. **Short-circuit after both input reads.**  
   If the first value actually read is `0x0080`, the second sequence unit is still read. Neither classification lookup occurs, and fallback receives both effective sequences.

10. **Fallback after an equal prefix.**  
    If an eligible equal pair is followed by a pair containing `0x0080`, delegation receives the effective beginnings and full effective counts, including the previously compared prefix.

11. **Either-side digit.**  
    With option `0x10`, an eligible pair containing `0x0035` on either side delegates before ordering, even when that pair would otherwise differ.

12. **Delegated result preservation.**  
    If F-2bd864ccf2c1 returns `0x12345678`, this function returns exactly `0x12345678`.
