# F-36b67cc7bb38

When the indirect function returns any nonzero value, it invokes F-d9206b7d1e39 and returns that function’s four-byte result.

This is a behavioral description of the supplied static representation, not a statement of application intent. Interpreting the indirect call as a readiness check, authorization check, or object-validity check would require evidence not supplied here.

**Output.** A four-byte value:

- All zero bits if the indirect call returns zero.
- The result supplied by F-d9206b7d1e39 if the indirect call returns nonzero and the subsequent call returns normally.

The supplied representation treats the indirect call’s result as an integer and the wrapper’s result as an uninterpreted four-byte value. The wrapper performs no visible conversion, normalization, or interpretation of the second dependency’s result.

## Behavior

### Dispatch and decision

The first externally relevant operation is resolving and invoking the indirect dependency:

1. Read the address-bearing field at the input address.
2. Use that value as the base for locating the function-address entry at byte offset 16.
3. Read the target address from that entry.
4. Invoke the selected target.
5. If it returns normally, compare its integer result with zero.

These reads are dependent: the dispatch-entry address cannot be determined from the visible expression until the first field has been read. The indirect call occurs before any possible call to F-d9206b7d1e39.

The branch distinguishes only zero from nonzero. It does not test positivity, match a particular nonzero code, or mask individual bits. A negative result and a positive result therefore take the same branch, provided each is represented as nonzero under the actual return convention.

### Zero-result branch

If the indirect dependency returns zero, F-d9206b7d1e39 is not invoked by this wrapper. The wrapper returns a four-byte zero value.

Any effects already performed by the indirect dependency remain relevant. Returning zero from the wrapper does not establish that execution was side-effect-free, that the input was rejected, or that no work occurred.

### Nonzero-result branch

If the indirect dependency returns nonzero, the wrapper invokes F-d9206b7d1e39 once. If that dependency returns normally, its result becomes the wrapper’s result.

The nonzero result from the indirect dependency is used only to select this branch. It is not returned as the wrapper’s result and is not visibly supplied as an argument to F-d9206b7d1e39.

F-d9206b7d1e39 may itself return zero. Consequently, a zero wrapper result does not reveal which branch executed. It may mean that the indirect dependency returned zero, or that both dependencies were invoked and the second returned zero.

These counts describe calls made directly by the wrapper. They do not constrain recursion, callbacks, or further calls made inside either dependency.
