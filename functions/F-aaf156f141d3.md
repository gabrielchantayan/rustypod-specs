# F-aaf156f141d3

## Purpose

F-aaf156f141d3 searches a descriptor-backed sequence of 32-bit integer slots for a requested value. If the value is already present, it returns −1 without directly modifying the descriptor or slot storage. Otherwise, it may invoke F-6d8420276e17, then searches for the first zero-valued slot within the descriptor’s current scan range.

When a zero-valued slot is found, the function increments the descriptor’s third field, writes the requested value into that slot, and returns the slot’s zero-based index. If no zero-valued slot is found, it returns −1.

The observed behavior is not an ordinary append operation:

- The function does not directly increase the field that bounds its scans.
- It increments the third descriptor field when filling a zero slot.
- It can invoke its dependency before discovering that no usable zero slot exists.
- A zero-valued slot counts as an existing match when the requested value is zero.

Interpreting this operation as “insert a unique value into a free slot” is plausible intent, not an independently established data-structure contract.

## Interface

### Inputs

The function receives two inputs:

1. A reference to a writable descriptor containing at least three consecutive 32-bit fields.
2. A requested 32-bit integer value.

The descriptor has the following observed layout:

| Byte offset | Field | Observed use |
|---|---|---|
| 0 | Storage address | Address of the slot sequence. |
| 4 | Scan bound | Signed bound used for slot searches. |
| 8 | Third field | Compared with the scan bound before the dependency call; incremented on a successful slot write. |

Each slot occupies four bytes and is interpreted as a 32-bit integer. Slot index \(k\) is accessed at the storage address plus \(4k\) bytes.

The address is represented through an integer-width field in the supplied representation. This supports a 32-bit address-bearing layout; it does not establish portability to a wider-pointer execution environment.

The third field’s semantic name is unknown. Its comparison with the scan bound may resemble a fullness check, but calling it “capacity,” “count,” or “occupancy” would imply invariants not established here.

### Output

The return value is a signed integer:

- A nonnegative value identifies the first zero-valued slot found by the second search and subsequently written.
- −1 means either:
  - the requested value was found during the initial search; or
  - the second search found no zero-valued slot.

The return value alone does not distinguish these two outcomes. It also does not reveal whether F-6d8420276e17 was invoked.

### Preconditions for defined, ordinary operation

The descriptor must be accessible for its required reads and, on a successful slot write, writable at byte offset 8.

For each executed slot access:

- The storage address must identify accessible slot storage.
- The computed four-byte access must lie within that storage.
- Address calculation must be valid for the target execution model.
- Alignment must meet that target’s requirements, if any.

The function performs no visible null check, allocation-size check, or bounds validation against an independently known storage extent.

The supplied representation uses signed integer comparisons and integer arithmetic. Normal behavioral claims below assume that executed index, offset, address, and third-field arithmetic remain representable. Behavior at arithmetic overflow is not established.

## Behavior

### 1. Initial duplicate search

The function first searches slots in ascending index order, starting at index zero and continuing while the index is less than the descriptor’s scan bound.

For each visited slot, it reads the slot value and compares it with the requested value. On the first equality, it immediately returns −1.

On this early-return path:

- F-6d8420276e17 is not called.
- The function makes no direct descriptor write.
- The function makes no direct slot write.
- No second search occurs.

Zero is not excluded from this equality comparison. Consequently, requesting zero when a scanned slot already contains zero causes the same early return as any other existing value.

The initial search references the descriptor’s scan bound as its loop condition. The supplied representation does not establish that this bound is captured once for the whole search. This is a source-level access distinction, not a guarantee about machine-level loads, volatile semantics, or concurrent behavior.

### 2. Conditional dependency invocation

If the initial search completes without finding the requested value, the function compares the descriptor’s third field with its scan bound.

If the fields are equal, it calls F-6d8420276e17 with the descriptor reference.

If the fields are unequal, it proceeds without that call.

The comparison is equality only. No separate greater-than or less-than condition triggers the call.

The function does not use a return value from F-6d8420276e17. It does not visibly inspect a success indicator or perform rollback after the call.

The dependency is invoked before the zero-slot search. Therefore, even when a zero slot already exists, equality of the two fields is sufficient to cause the call.

Conversely, the presence of no zero slot does not itself trigger the dependency: if the two fields are unequal, the function proceeds directly to the search and may return −1.

### 3. Post-call search state

After the optional dependency call, the function reads the descriptor’s scan bound and uses that value as the bound for the second search.

This is a new read. The second search is not necessarily restricted to the same range as the initial search.

The second search also obtains its slot storage through the descriptor’s storage-address field. The supplied evidence does not establish that F-6d8420276e17 preserves either field.

Accordingly, the second search may observe a different address, a different bound, or different slot values from those examined initially. There is no duplicate search after the dependency returns. If the dependency introduces the requested value into the post-call storage, the function does not explicitly reject that newly introduced duplicate before attempting a zero-slot write.

### 4. First-zero selection

The function searches the post-call range in ascending index order for a slot whose value equals zero.

If a zero is found, its index is selected. The search stops at that first zero; later zero slots are not considered.

If no zero is found, the selected result is −1, and the function returns −1 without a direct descriptor or slot write.

For a nonpositive post-call scan bound, the second search visits no slots and produces −1.

For an ordinary positive bound, a found index is necessarily nonnegative and strictly below that bound. The subsequent write guard accepts such an index, including index zero. There is no exclusion of the first slot.

### 5. Successful mutation

When the second search finds a zero slot, the function performs these direct mutations in order:

1. Reads the descriptor’s third field.
2. Adds one to that field’s value.
3. Writes the incremented value back to the third field.
4. Obtains the slot storage address from the descriptor.
5. Writes the requested 32-bit value to the selected slot.
6. Returns the selected index.

The direct third-field write precedes the direct slot write.

The scan-bound field is not directly changed by this function. The storage-address field is not directly changed by this function either, although the dependency may change either field.

No check prevents the third field from exceeding the scan bound after the increment. No check ties the increment to an independently established occupancy or allocation invariant.

If the increment or subsequent storage access cannot complete normally, no transactional recovery is visible. In particular, the evidence does not support a guarantee that a failed slot write leaves the third field unchanged.

## Side effects

### Direct effects

The function directly modifies memory only when it finds a zero slot during the second search:

- It increments the descriptor’s third 32-bit field.
- It writes the requested 32-bit value into the selected slot.

All other direct accesses are reads.

The function does not directly allocate or release memory. It does not directly clear a slot, move existing elements, or extend the scan bound.

### Indirect effects

F-6d8420276e17 may execute when the third field equals the scan bound after the initial duplicate search.

## Acceptance examples

These examples are conditional static expectations, not runtime test results. Unless otherwise stated, they assume accessible nonoverlapping storage, stable memory outside the described dependency effects, representable arithmetic, and normal completion of all accesses.

- The initial search finds the value at index 1.
- The result is −1.
- The dependency is not called, regardless of the third field.
- No direct memory mutation occurs.

- The second search selects index 0.
- The third field becomes 2 before slot 0 is written.
- The slots become `[44, 27, 0]`.
- The result is 0; the scan bound remains 3.

- The third field becomes 3.

- The result is 1.

### No zero and no dependency call

- No duplicate is found.
- The dependency is not called.
- No zero is found.

- The initial duplicate search completes without a match.
- The dependency is called.

If that dependency returns with accessible slots `[12, 27, 0]`, a scan bound of 3, and a third field of 2, the function then selects index 2, increments the third field to 3, writes 44 at index 2, and returns 2.

### Requesting zero

Given any positive scan range containing a zero and requested value zero:

- The initial search treats that zero as an existing match.
- The result is −1 before any dependency call.

If the initial range has no zero but the dependency later exposes a zero, the second search can select it. In that conditional case, the function increments the third field and writes zero back to the selected slot, returning its index even though the slot’s numeric value remains unchanged.

### Empty scan range

- If the third field is also zero, the dependency is called.
