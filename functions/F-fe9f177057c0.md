# F-fe9f177057c0

## Purpose

F-fe9f177057c0 conditionally updates two externally managed objects when either of two observed 32-bit values differs from its cached value.

On a change, it:

1. Derives two even-valued size quantities from the first observed value.
2. Caches both observed values.
3. Calls a geometry-related dependency for one object.
4. Calls a second dependency for both objects with complementary values in the range 0–255.
5. Calls a third dependency once for each object, supplying associated context fields.

If both observed values match their caches, the function performs none of those writes or dependency calls.

The apparent intent is coordinated geometry and complementary visual-intensity updates. That interpretation is inferred from the argument relationships; the actual meanings of the dependency operations are not established.

The function returns the 32-bit value 1 whenever it reaches its normal return. This is not evidence that the dependencies succeeded.

The function accepts one address identifying a context record. The supplied representation uses 32-bit integers, addresses, handles, and return values.

The result is a 32-bit value equal to 1 on every normal-return path. No alternate return value or local error report is visible.

## Behavior

### Observation and change detection

The function first obtains the first observed value through the address stored at context offset `0x50`, then obtains the second through the address at `0x54`.

It then reads the cached first value at `0x58`.

- If the first observed value differs from its cache, an update is required. The cached second value need not be read.
- If the first observed value matches, the function reads the cached second value at `0x5c` and compares it with the second observed value.
- Only when both comparisons match does the function skip the update.

Both observed values are read even when the first comparison would already be sufficient to require an update.

Change detection concerns only these two observed values. A change solely to the selector, object fields, extent-like fields, or associated values does not trigger the dependency calls when both observations still match their caches.

### Derived quantities

Let:

- \(S\) be the first observed 32-bit value, interpreted as signed for its initial arithmetic.
- \(T\) be the second observed 32-bit bit pattern.
- \(A\) be the first derived size.
- \(B\) be the second derived size.
- \(Q\) be the complementary-value input.

The first derived size is formed by:

1. Adding 32,767 to \(S\).
2. Shifting that signed result right by 16.
3. Clearing the least significant bit of the resulting 32-bit pattern.
4. Treating the result as an unsigned 32-bit quantity.

For nonnegative values whose addition does not overflow, this is:

\[
A = 2\left\lfloor
\frac{\left\lfloor(S+32767)/65536\right\rfloor}{2}
\right\rfloor.
\]

The second derived size is formed by multiplying \(A\) by 3 using unsigned 32-bit arithmetic, shifting the result right by 2, and clearing its least significant bit:

\[
B =
\operatorname{clearLowBit}
\left(
\left((3A)\bmod 2^{32}\right)\mathbin{\mathrm{logicalShiftRight}}2
\right).
\]

Consequently, both sizes have their low bit clear. There is no visible minimum-size enforcement, rejection of zero, or clamping against the supplied extents.

The complementary-value input is:

\[
Q =
\frac{\left((T+32767)\bmod 2^{32}\right)
\mathbin{\mathrm{AND}} 16777215}{65536},
\]

where division here denotes the unsigned right shift by 16.

Thus \(Q\) is always between 0 and 255 inclusive. Its computation masks away all but 24 bits before the shift; it is not a general clamp to the 0–255 range. Values outside an intended input range can wrap or alias into that range.

The complementary value is \(255-Q\), also within 0–255.

### Cache update

Before calling any dependency, the function writes:

1. The second observed value to context offset `0x5c`.
2. The first observed value to context offset `0x58`.

These stores record the raw observed values, not the derived sizes or \(Q\).

This ordering matters: dependency execution begins after both cache stores. No rollback is visible if a dependency fails to return normally or fails to accomplish its presumed operation.

### Geometry dependency

The function next calls F-a05963f65233 with nine arguments, in this positional order:

| Position | Value |
|---:|---|
| 1 | Context field at `0x24` |
| 2 | Zero |
| 3 | Zero |
| 4 | Even-masked half-difference between the field at `0x2c` and \(B\) |
| 5 | Even-masked half-difference between the field at `0x28` and \(A\) |
| 6 | Context field at `0x28` |
| 7 | Context field at `0x2c` |
| 8 | \(A\) |
| 9 | \(B\) |

The half-differences use unsigned 32-bit subtraction because the derived sizes are unsigned. For an extent bit pattern \(E\) and derived size \(D\), the corresponding argument is:

\[
\operatorname{clearLowBit}
\left(
\left((E-D)\bmod 2^{32}\right)
\mathbin{\mathrm{logicalShiftRight}}1
\right).
\]

This is not signed division by two. If the extent is smaller than the derived size, subtraction wraps before the logical shift and can produce a large positive bit pattern.

The apparent intent is an even-aligned placement calculation. The association between these positional arguments and physical axes is not proven.

The extent-like fields appear separately in the placement expressions and as full-extent arguments. The evidence does not establish the evaluation order of individual argument expressions or require those repeated reads to be consolidated into a single snapshot.

### Complementary-value dependency calls

After the geometry call returns, the function reads the selector byte at `0x48`.

If that byte is zero:

1. F-460b2abbbbbe receives the current field at `0x20` and \(Q\).
2. F-460b2abbbbbe receives the field at `0x24`, reloaded after the first call, and \(255-Q\).

If that byte is nonzero:

1. F-460b2abbbbbe receives the current field at `0x20` and \(255-Q\).
2. F-460b2abbbbbe receives the field at `0x24`, reloaded after the first call, and \(Q\).

Every nonzero selector byte takes the same branch. The selector is not restricted locally to the value 1.

The branch is selected once. A selector change during the first complementary-value call does not cause the branch to be reconsidered.

The second object field is read after the first call returns, then retained for the second call. The geometry dependency and the first complementary-value dependency must not be assumed to preserve the context fields.

### Final dependency calls

After both complementary-value calls return, the function calls F-1d891874186d twice:

1. With the current context fields at `0x20` and `0x1c`.
2. With the current context fields at `0x24` and `0x18`.

The second pair is obtained after the first call returns. These are not necessarily the same object values used by earlier calls if a dependency has modified the context.

The return values of all dependency calls are unused. After the final call returns, the function returns 1.

## Acceptance examples

These are conditional static expectations, not executed tests. Unless stated otherwise, they assume valid memory, normally returning dependencies, and no intervening mutation of relevant fields.

### Unchanged observations

If both observed values equal their respective caches:

- Neither cache is written.
- No dependency is called.
- The result is 1.

Changing only the selector or an extent-like field does not alter this outcome.

### Only the second observation changes

If the first observation matches its cache but the second does not:

- Both caches are written in second-then-first order.
- The full five-call update sequence occurs.
- Geometry is recalculated from the unchanged first observation.
- The complementary values are recalculated from the new second observation.

### Ordinary nonnegative geometry

With first observation 6,553,600:

- Adding 32,767 and shifting right by 16 yields 100.
- \(A=100\).
- \(B=74\), because \(300\) shifted right by 2 is 75 and clearing its low bit yields 74.

With extent fields `0x28` = 640 and `0x2c` = 480, the geometry arguments are:

1. The field at `0x24`.
2. Zero.
3. Zero.
4. 202.
5. 270.
6. 640.
7. 480.
8. 100.
9. 74.

### Selector reversal

With second observation 8,388,608, \(Q=128\).

- Selector zero assigns 128 to the first object call and 127 to the second.
- Any nonzero selector assigns 127 to the first and 128 to the second.

### Masking rather than saturation

With second observation 16,777,216, \(Q=0\). It does not saturate at 255.

With second observation 16,744,449, adding 32,767 reaches 16,777,216; the 24-bit mask again produces \(Q=0\).

### Undersized extent

If \(A=100\) and the field at `0x28` is 80, the corresponding placement argument is 2,147,483,638.

This follows unsigned subtraction, logical halving, and low-bit clearing. A negative placement or zero clamp would not match the represented arithmetic.

### Dependency mutation

If the first complementary-value call changes the field at `0x24`, the second complementary-value call receives the changed value.

If the geometry dependency changes the selector before returning, the subsequent branch uses that changed selector.
