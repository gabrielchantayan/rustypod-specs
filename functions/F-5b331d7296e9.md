# F-5b331d7296e9

## Purpose

F-5b331d7296e9 transforms a sequence of 16-bit source elements into a sequence of 16-bit destination elements. Two signed 32-bit parameters control the inner and outer iteration counts.

For an inner count of at least two, each outer iteration produces:

- One bit-mask-based blend for each adjacent pair of source elements.
- A final copy of the last source element captured during that iteration.

The blend favors the later element. Its masks make it different from ordinary integer averaging. A packed-component interpolation operation is a plausible intent, but no particular color format or channel interpretation is established.

For an inner count of one or less, the behavior is substantially different: each outer iteration reads one source element but writes the low 16 bits of the original source address, rather than that element’s value. This behavior must not be replaced with a singleton copy without an independent requirement authorizing that change.

All behavior below is derived from static inspection of the supplied source. No runtime tests have been performed.

### Memory preconditions

When the outer count is positive, the source must support the reads and the destination must support the writes described below. No length or null-pointer validation occurs.

For an inner count of at least two, each outer iteration consumes and produces exactly that many elements. For an inner count of at most one, each outer iteration consumes and produces one element, subject to the arithmetic limitation below.

Required storage must therefore cover the full sequential access range, not merely the first logical row. There is no independent row stride, padding argument, or per-row destination reset.

The expression that subtracts one from the inner count is evaluated using signed 32-bit arithmetic. ## Behavior

### Empty outer range

If the outer count is zero or negative, the function returns without reading source elements or writing destination elements.

In particular, this path does not evaluate the inner-count subtraction. The problematic minimum signed inner count therefore does not affect the no-access behavior when the outer count is nonpositive.

### Sequential layout

For an outer count greater than zero and an inner count of at least two, the source is treated as contiguous groups of the inner count. The destination receives equally sized contiguous groups.

Each next outer iteration begins immediately after the preceding iteration’s final source element. Each next destination group begins immediately after the preceding group’s final output. Both element advances correspond to two addressable bytes under the stated width model.

For an inner count of at most one, excluding the signed-overflow case, each outer iteration advances the source and destination by one element.

The term “group” describes iteration boundaries only. There are no separately stored row descriptors or stride values.

### Blend definition

For an ordinary adjacent-pair output, let:

- \(a\) be the previously captured source value, zero-extended from 16 bits.
- \(b\) be the current source value, zero-extended from 16 bits.
- \(r\) be the value obtained by reading the current source location again before the destination write.

Define the 32-bit mask:

\[
M = \mathtt{0xFFFFF7DF}.
\]

The intermediate value is:

\[
t =
\left[
(a \mathbin{\&} b)
+
\left(
((a \mathbin{\oplus} b) \mathbin{\&} M)
\mathbin{\gg} 1
\right)
\right]
\mathbin{\&}
\mathtt{0xFFFEFFFF}.
\]

The destination receives the low 16 bits of:

\[
(r \mathbin{\&} t)
+
\left(
((b \mathbin{\oplus} t) \mathbin{\&} M)
\mathbin{\gg} 1
\right).
\]

Here, \(\&\) is bitwise AND, \(\oplus\) is bitwise XOR, and \(\gg\) is a logical right shift on an unsigned 32-bit value.

The first mask clears bit positions 5 and 11 before shifting. It is not a general rounding adjustment that may be discarded. In particular, values that differ only across one of those masked positions can produce results unlike ordinary arithmetic averaging.

For stable ordinary memory, the repeated read yields \(r=b\). Under that condition, the operation can be understood as a masked average of \(a\) and \(b\), followed by a masked average of that intermediate result and \(b\). This interpretation does not authorize replacing the exact formula with a conventional weighted average.

For 16-bit \(a\) and \(b\), the intermediate addition is at most 65,535. Thus the intermediate mask’s clearing of bit 16 does not change that value in this input domain. The formula nevertheless records the mask present in the supplied behavior.

### Per-group processing for an inner count of at least two

At the start of each group, the first source element is read and retained as the previous sample. No output is written yet.

For each remaining source position, in increasing address order:

1. The current 16-bit source value is captured.
2. The intermediate blend is calculated from the retained previous sample and that captured current value.
3. The same current source location is read again for the first term of the final blend.
4. The resulting 16-bit pattern is written to the next destination position.
5. The captured current value becomes the retained previous sample.

The two source reads occur before the corresponding output write. The second read does not replace the captured value used as the previous sample for the next pair.

After all adjacent pairs have been processed, the final destination element receives the last captured source value. This terminal write does not reread the final source element.

Consequently, a group of \(n\geq2\) elements produces \(n-1\) blended outputs followed by one terminal value. At the source-expression level, it performs \(2n-1\) source reads and \(n\) destination writes.

### Per-group processing for an inner count of at most one

For inner counts of one, zero, or negative values other than the minimum signed 32-bit value:

- The first source element of the group is read.
- The adjacent-pair loop is skipped.
- One destination element is written.
- Both source and destination advance by one element.

The written pattern is the low 16 bits of the original source-base address. It is not the value just read.

The original source-base address remains the value used for every such terminal write. Advancing the source read position across groups does not cause the output to become the low 16 bits of each successive source address.

This means a zero inner count is not a zero-work request when the outer count is positive.

## Side effects

### Destination modification

The only explicit memory writes are sequential 16-bit writes through the destination pointer. No destination contents are read to form an output.

For valid, nonoverlapping memory, the function modifies exactly:

- Inner count × outer count destination elements when the inner count is at least two.
- Outer count destination elements when the inner count is at most one and its subtraction is representable.

These are mathematical counts, not an assertion that their product is computed internally or that arbitrary resulting address ranges are valid.

### Source reads and overlap

There are no explicit writes through the source pointer. Nevertheless, if source and destination overlap, destination writes may modify memory that will subsequently be read as source data.

The behavior is forward and incremental. It does not operate on a snapshot and does not provide general overlap protection.

Two details matter for overlapping storage:

- A sample already captured for use as the previous value remains captured even if its source location is subsequently overwritten.
- A future source sample, including the first sample of a later group, can reflect an earlier destination write.

Exact in-place operation, with equal source and destination bases and an inner count of at least two, preserves the adjacent-pair inputs under ordinary stable-memory conditions. Each current sample is read before the preceding source position is overwritten, and its captured value is retained for the next pair. This does not imply that other relative offsets are safe.

## Acceptance examples

These examples are conditional static expectations, not executed test results. Unless stated otherwise, assume valid, stable, nonoverlapping buffers and the representation model described above. Destination values are expressed as 16-bit patterns.

### Nonpositive outer count

With an outer count of zero or −3, the destination remains unchanged and no source element is read, regardless of the inner count.

This includes a minimum signed 32-bit inner count, because the subtraction is not reached.

### Two ordinary samples

With inner count two, outer count one, and source values:

- `0x0000`
- `0x0008`

The intermediate blend is `0x0004`. The second blend is `0x0006`.

The destination is:

- `0x0006`
- `0x0008`

The terminal output is the captured second sample.

### Mask-sensitive input

With inner count two, outer count one, and source values:

- `0x0000`
- `0x0020`

The masked XOR contribution is zero in both blend stages. The destination is:

- `0x0000`
- `0x0020`

An ordinary three-quarter weighting of the later sample would not satisfy this case.

### Equal samples with the high bit set

With inner count two, outer count one, and both source values equal to `0xFFFF`, both outputs have pattern `0xFFFF`.

A signed interpretation of the destination may display these values as −1. That display does not change the stored pattern.

### Group boundary

With inner count two, outer count two, and source values:

- `0x0000`, `0x0008`
- `0x0008`, `0x0000`

The destination is:

- `0x0006`, `0x0008`
- `0x0002`, `0x0000`

No blend is computed across the boundary between the two groups.

### Singleton and nonpositive inner counts

Assume the original source-base address has low 16 bits `0x2468`.

For inner count one and outer count three, the function reads three successive source elements and writes:

- `0x2468`
- `0x2468`
- `0x2468`

The same expectation applies to inner count zero or −7. Source element values do not determine these outputs.

### Overlap changing a future source value

Assume inner count three, outer count one, source values `0x0000`, `0x0008`, `0x0010`, and a destination beginning one element after the source base. Assume enough writable storage for all outputs.

The first blend writes `0x0006` over the second source element. The second pair still uses the previously captured `0x0008`, so its blend is `0x000E`. The terminal output is `0x0010`.

The three destination patterns are therefore `0x0006`, `0x000E`, `0x0010`. This example depends on capture order, not on rereading an overwritten previous sample.
