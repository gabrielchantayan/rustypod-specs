# F-4767ad7d4c70

## Purpose

F-4767ad7d4c70 transfers four-byte elements forward from a supplied source position to a supplied destination position, performs a second traversal without accessing elements, and updates a stored end-address representation. On normal completion, it returns the original destination pointer.

The operation is consistent with removing a range from a contiguous sequence: the suffix following the removed range moves toward the beginning, and the stored end retreats by the removed range’s byte length. This is inferred intent, not an established public container contract.

The function performs no explicit validation, allocation, destruction, clearing, or error reporting. Its final metadata assignment is also a memory write: if the end field overlaps element storage, that assignment can modify an element, including one before destination, even when the transfers never overwrite metadata.

## Interface

### Inputs and represented layout

The function receives three pointers:

| Input | Role |
|---|---|
| Descriptor | Identifies metadata containing beginning- and end-address representations. |
| Destination | Initial location receiving transferred elements; also the returned pointer. |
| Source | Initial location supplying transferred elements. |

The visible descriptor layout is:

| Byte offset | Width | Interpretation |
|---|---:|---|
| 0 | 32 bits | Signed integer converted to the beginning pointer for the initial comparison. |
| 4 | 32 bits | Signed integer converted to an end pointer and later assigned an arithmetic result. |

No other descriptor fields are accessed. The signed interpretation matters to the final arithmetic; these fields are not uniformly treated as unsigned addresses.

Each transferred element occupies four bytes and is handled as a raw 32-bit value. Both traversal cursors advance by one four-byte element.

This is a represented 32-bit integer/address model. It does not establish a target architecture, byte order, language version, or portable behavior with wider pointers.

### Output

On normal completion, the return value is exactly the supplied destination pointer. It is not the advanced destination cursor, updated end, transfer count, or status.

### Conditions for the ordinary removal interpretation

A sufficient ordinary-use contract requires:

- A readable descriptor with a writable end field.
- Supported conversions between the stored signed representations and the intended pointers.
- Valid alignment, access types, and permissions for every element access.
- Beginning, destination, source, and captured end positions in one compatible contiguous region, ordered in that sequence.
- Defined pointer advancement through every position visited by both traversals.
- Stable metadata during the traversals, including no transfer write that changes the descriptor fields.
- Supported conversion of the original source and destination pointers into signed 32-bit integers.
- A representable signed difference between those converted integers.
- A final unsigned-to-signed conversion that stores the intended end representation.
- Separation of the end field from every element location claimed to remain unchanged or retain a transferred value.

The last condition concerns the **final metadata write**, not transfer-induced metadata corruption. Preventing transfers from overwriting metadata does not, by itself, protect elements from the later end-field assignment.

Full separation between descriptor storage and sequence element storage is a simple sufficient condition. A weaker separation condition is possible when only particular element locations require preservation.

None of these conditions is checked by the function.

## Behavior

### Initial metadata reads and empty branch

The end field is read and converted into a pointer. This captured pointer becomes the boundary for the transfer phase.

The beginning field is then read, converted into a pointer, and compared with the captured end.

If the two pointers compare equal:

- Neither traversal runs.
- No source element is read.
- No destination element is written.
- The end field is not assigned.
- The original destination pointer is returned.

The descriptor reads and conversions still occur. This branch does not require source or destination to identify elements in the represented sequence, because neither is dereferenced or advanced.

If beginning and captured end differ, execution proceeds without checking ordering, membership, alignment, or available storage.

### Forward transfer

The transfer cursors start at source and destination. Transfers continue until the source cursor equals the captured end.

For each element:

- The current source value is read.
- That value is written to the current destination.
- The destination cursor advances by four bytes.
- The source cursor advances by four bytes before the next transfer comparison.

The corresponding source read precedes its destination write. Transfers proceed forward; the function does not preserve a snapshot of the complete source range.

The transfer boundary remains the initially captured end. A destination write that changes the stored end field does not replace that boundary.

Termination depends on equality, not an ordering test or a validated count. A source position beyond the captured end, or otherwise unable to reach it through defined four-byte increments, has no general defined-completion guarantee.

### Transfer overlap

With destination before source in a valid common region, the forward direction supports ordinary range removal: destination writes do not overwrite elements needed by later source reads.

With destination equal to source, each visited element is read and then written back to the same location.

With destination after source and overlapping transfer regions, an earlier destination write may change a later source value. Snapshot-copy semantics and backward copying are not supported by the visible operation.

Destination-after-source geometry may also leave the destination cursor unable to reach the second traversal’s boundary through valid forward increments. Observing the transfer pattern alone would not establish successful completion.

### Address-only traversal

After transfer, the destination cursor advances until it equals the pointer represented by the descriptor’s then-current end field.

This traversal performs no element read, write, clearing, initialization, or destruction through the cursor. Its pointer increments must nevertheless be valid for a defined execution.

The boundary differs from the transfer boundary:

- Transfer uses the captured initial end.
- The second traversal refers to the descriptor’s current end field in its comparison expression.

Consequently, transfer-induced changes to the end field can affect this phase.

The source-level reference to the field does not establish a volatile-access contract, one physical load per comparison, or support for concurrent modification. Generated load counts and loop transformations are unresolved.

For ordinary ordered inputs with stable metadata, the destination cursor reaches the prospective new end after transfer. The address-only traversal then advances across the number of element positions between the original destination and source.

### End adjustment: signed difference

After both traversals, the adjustment uses the **original** source and destination pointers.

Each is converted to a signed integer. The converted destination value is subtracted from the converted source value before the unsigned mask is applied.

Two restrictions are independent:

1. Pointer-to-signed-integer conversion depends on the implementation and may not support every pointer value.
2. The mathematical difference of the converted values must fit the signed integer type.

An overflowing signed subtraction is not made defined by the subsequent unsigned mask. The function therefore does not establish ordinary modular address subtraction for every pair of 32-bit address patterns.

A small positive address distance does not prove representability. Under conventional signed interpretation of 32-bit patterns, crossing the signed-address boundary can produce an unrepresentable signed difference.

### End adjustment: unsigned operations and assignment

If the signed subtraction is defined, its result participates in a bitwise operation with the unsigned 32-bit mask `0xfffffffc`.

Within the represented model:

- The signed difference is converted to unsigned.
- Its lowest two bits are cleared.
- The current signed end-field value is converted to unsigned.
- The masked amount is subtracted using unsigned arithmetic modulo \(2^{32}\).
- The unsigned result is assigned to the signed end field.

For a defined negative difference, conversion to unsigned occurs before masking. This does not imply wrapping of the preceding signed subtraction.

The final assignment introduces a separate conversion boundary. A representable unsigned result retains its value when stored as signed. For a result outside the signed range, the applicable language and implementation rules are required. Under pre-C23 signed-conversion rules, the result is implementation-defined or an implementation-defined signal may be raised. Neither a language version nor a target rule is established here.

The mask is not validation. It does not make invalid traversal, misaligned access, or unsupported pointer representations acceptable.

### Conditional ordinary result

Under the ordinary-use conditions, including arithmetic validity and sufficient metadata separation:

- The source suffix up to, but excluding, the captured end transfers to destination in its original order.
- The stored end represents the old end minus the byte distance from destination to source.
- Elements before destination remain unchanged.
- Storage beyond the new logical end is not cleared or destroyed.
- The original destination pointer is returned.

The element-preservation statements require qualification when metadata aliases element storage. In that case, the final end-field assignment may change an element before destination, overwrite a transferred value, or modify trailing storage. Such a write is not clearing or destruction; it is an aliased metadata update.

## Side effects

### Logical access order

The established source-level order is:

1. Read and convert the initial end representation.
2. Read and convert the beginning representation; compare the pointers.
3. For a nonempty descriptor, perform forward source reads and destination writes.
4. Perform the address-only traversal.
5. Evaluate the end adjustment and assign the end field.
6. Return the original destination.

The final assignment follows both traversals. No stronger ordering between all operand evaluations inside the final arithmetic expression is established.

These are logical operations, not machine-instruction counts or hardware timing guarantees.

### Metadata and element aliasing

Two aliasing effects must be distinguished.

**Transfers modifying metadata:** A destination write overlapping the descriptor can change its beginning or end representation. Transfer still uses the captured end, but later comparisons and final arithmetic may use a changed end field. Meaningful termination and a usable resulting descriptor are not guaranteed.

**Metadata assignment modifying elements:** Even if no transfer touches metadata, the final end-field assignment can change overlapping element storage. This includes an element before destination. Stable metadata during traversal therefore does not imply preservation of all elements outside the transfer destinations.

Source reads that overlap metadata observe the values present when those reads occur. There is no protected metadata snapshot beyond the captured transfer boundary, and no complete element snapshot.

Absent transfer aliasing, the end field is the only descriptor field explicitly assigned. This does not imply that the write affects only metadata from the caller’s perspective.

### Ownership and failure behavior

No allocation, deallocation, ownership transfer, constructor, destructor, callback, or reference-count operation is visible.

Elements are copied as raw 32-bit values. Resource-management obligations associated with those values are unknown.

There is no explicit error result, rollback, or recovery path. Invalid accesses, invalid pointer operations, unsupported conversions, and signed overflow do not produce a specified status. If execution fails after transfers have begun, earlier destination writes need not be undone.

No synchronization is visible. Concurrent mutation is not an established supported use.

## Acceptance examples

These are conditional static expectations, not executed tests. Unless specified otherwise, assume valid aligned storage, separate stable metadata, defined traversal, supported address conversions, representable signed subtraction, and a final conversion preserving the intended end representation.

### Interior removal

An eight-element sequence contains A, B, C, D, E, F, G, H. Destination identifies C; source identifies F.

Expected:

- F, G, and H transfer into the original C, D, and E positions.
- The address-only traversal advances three element positions.
- The stored end retreats twelve bytes.
- The logical sequence becomes A, B, F, G, H.
- Trailing storage is not cleared.
- The original C position is returned.

### Suffix removal

A six-element sequence has destination at its fourth element and source equal to end.

Expected:

- No element transfer occurs.
- The address-only traversal advances three positions.
- The adjusted end represents destination.
- The first three elements remain logical elements.
- Suffix storage is neither cleared nor destroyed.

### Whole-sequence removal

For a nonempty sequence, destination equals beginning and source equals end.

No element transfer occurs. The address-only traversal reaches end, and the adjustment stores the beginning representation. The original beginning pointer is returned.

A large valid allocation does not eliminate the signed-difference requirement.

### Empty removal range in a nonempty descriptor

Destination equals source at a valid interior position.

The suffix is read and written back to itself. The transfer finishes with destination at the captured end, so the address-only traversal performs no increments when metadata is stable.

The signed difference is zero, but the final end-field assignment still occurs. This is not an early return. Preservation of the stored signed representation remains subject to the unsigned-to-signed conversion rule.

### Empty descriptor

Converted beginning and end pointers compare equal.

Neither traversal nor the final assignment occurs. No source or destination element is accessed, and the original destination pointer is returned.

### End metadata overlapping an earlier element

Assume a memory model permitting the described overlapping word accesses and address conversions.

A six-word region begins at address `0x1000`. The descriptor occupies its first two words:

- Element index 0 stores beginning representation `0x1000`.
- Element index 1 stores end representation `0x1018`.
- Destination is element index 2, at `0x1008`.
- Source is element index 3, at `0x100c`.

Expected:

- Original elements 3, 4, and 5 transfer to elements 2, 3, and 4.
- These transfers do not overwrite either descriptor field.
- The address-only traversal advances from `0x1014` to `0x1018`.
- The final adjustment stores `0x1014` in the end field.
- Element index 1 consequently changes from `0x1018` to `0x1014`, although it is before destination.
- The return value is `0x1008`.

This demonstrates why transfer-safe metadata placement alone is insufficient for an unconditional “elements before destination remain unchanged” guarantee.

### Signed-address-boundary crossing

Conditionally assume conventional two’s-complement interpretation of 32-bit pointer patterns.

Destination has pattern `0x7ffffffc`; source has pattern `0x80000000`. Their address separation is four bytes, but their signed values are 2,147,483,644 and −2,147,483,648.

The mathematical signed difference is −4,294,967,292, outside the signed 32-bit range. Even if all preceding memory operations are valid, acceptance must not require a four-byte end retreat from literal source semantics.

### Final result outside the signed range

If the final unsigned subtraction produces an unrepresentable signed value, the stored result depends on the applicable conversion rules.

Acceptance must not require bit-pattern preservation or recovery of the intended end pointer without an established implementation rule.
