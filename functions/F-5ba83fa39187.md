# F-5ba83fa39187

## Purpose

F-5ba83fa39187 performs an indefinitely repeated sequence of indirect dependency calls and ordered memory transfers. The transfers use 8-bit, 16-bit, and 32-bit accesses. Each complete iteration includes a software breakpoint and changes a register-like address base used by later iterations.

No application-level purpose is established. The accessed regions are described by their observable roles, not assumed to be device registers, application objects, or allocator structures.

The supplied representation has an unconditional outer loop and no ordinary return path. Whether execution reaches the end of an iteration depends on unresolved dependencies, memory accessibility, and breakpoint handling.

## Interface

**Declared interface:** no explicit parameters and no explicit return value.

**Implicit inputs and state:**

- An incoming link/control value used to calculate the first indirect-call target.
- A register-like **frame base** used for accesses at offsets `0x258`, `0x26c`, `0x280`, and `0x320`.
- An incoming register-held **transfer base** used for a late byte store.
- Pointer-bearing global locations at `0x087120b4` and `0x08712120`.
- Memory reached through fixed addresses, dependency results, auxiliary register outputs, and calculated addresses.
- Any additional state observed or changed by the dependencies.

The terms “frame base” and “object” are descriptive labels. They do not establish stack discipline, an object model, ownership, or allocation provenance.

**Widths and interpretation:**

- Byte accesses transfer 8 bits.
- Halfword accesses transfer 16 bits.
- Word accesses transfer 32 bits.
- Represented addresses and pointer-bearing values are 32 bits.
- **Three dependency results are represented as 64-bit containers:** those produced by **F-U05**, **F-U09**, and **F-U28**. Both 32-bit halves of each result are consumed.
- The two selector reads and the later small-value read are unsigned 16-bit reads. Their subsequent wider uses are zero-extended.
- Stores narrower than their source retain the low 8 or 16 bits.
- The right shift extracting the upper six bits of the F-U09 low half is logical.
- Several other address calculations involve signed 32-bit expressions. Their intended low-bit machine interpretation is distinguishable from a portable source-language guarantee; see Uncertainties.

**Output:** there is no ordinary returned result. Observable behavior consists of dependency invocations, memory reads and writes, breakpoint execution, and changes to represented control and address state.

**Conditions for uninterrupted execution:** every reached call target must support the represented invocation; every reached address must permit the stated access width and direction; applicable alignment requirements must hold; dependencies must permit continuation; and the breakpoint must resume for post-breakpoint effects to occur. The body contains no explicit checks enforcing these conditions.

## Behavior

Dependency IDs identify call sites in execution order. They do not establish distinct implementation identities. A complete iteration visits **F-U01** through **F-U37** once each.

The ordering below includes explicit memory accesses and dependency boundaries. Dependencies may themselves access or change memory. Capturing an address before a call is not evidence that its target remains valid afterward.

### Initial calls and captured-object writes

Each iteration initializes two byte-sized internal values to zero.

**F-U01** is invoked with two zero arguments. Its target is formed from the current link/control value plus `0xffe`. **F-U02** and **F-U03** follow, with no explicit arguments represented.

After F-U03, the function reads a 32-bit initial-object address from `0x087120b4`. This address is captured before **F-U04** and **F-U05** execute.

F-U05 produces the first represented 64-bit result. **F-U06** receives its low 32-bit half as the first argument. Its second argument is formed by adding the high and low 32-bit halves and an explicitly zero byte. The zero contributes nothing. Under a wrapping 32-bit machine interpretation, this argument contains the low 32 bits of the sum; signed-expression limitations remain documented below.

After F-U06, an auxiliary byte associated with that call is stored at captured initial-object offset `0x11`. **F-U07** then executes, followed by a zero-byte store at offset `0x15` of the same captured address.

**F-U08** produces a 16-bit result and an auxiliary address. The function stores the result as a halfword at auxiliary-address offset `0x0c`.

Changing the initial-object global during an intervening call does not, by itself, change the captured address used by these stores. No global reread is represented.

### Second paired result and frame-relative accesses

**F-U09** produces the second represented 64-bit result. Its high 32-bit half is used as an address base for a zero-halfword store at offset `0x2c`.

Next, the function stores the low half logically shifted right by 26 as a word at current frame-base offset `0x26c`. This value is between 0 and 63, inclusive.

After **F-U10**, a 32-bit object address is read from frame-base offset `0x320`. **F-U11** and **F-U12** execute before a word is stored at offset `0x54` of that captured object. The stored value is the F-U09 low half shifted left by two as an unsigned 32-bit value; bits shifted beyond the word width are discarded.

The frame-loaded object address is not reread between its capture and that store.

### Fixed-address selector and breakpoint boundary

**F-U13**, **F-U14**, **F-U15**, **F-U16**, and **F-U17** execute in that order.

The function then reads an unsigned halfword from `0x21c48994`. This captured value is the **first selector**. **F-U18** executes after the read.

A word is then read from frame-base offset `0x280` and supplied as the explicit argument to **F-U19**. The function executes a software breakpoint with immediate value `0x92` after F-U19 returns.

If the breakpoint does not resume, none of the subsequent accesses or calls in the iteration is reached.

After continuation, the F-U19 result is shifted left by two to form an **indexed displacement**. A separate constant calculation, logically shifting `0x21c48960` right by 18 and multiplying by four, yields `0x21c4`.

### Selector-based addressing and halfword writes

The first post-breakpoint memory access reads a 32-bit **selected-object address** from the numeric address equal to the first selector plus `0x44`.

The first selector is itself the address base. There is no preceding load of a pointer from a slot identified by that selector.

**F-U20** executes, followed by **F-U21**, whose word result is retained. A word is then read from first-selector address plus `0x04`. **F-U22** receives the F-U21 result and this newly read word.

After F-U22, the function captures the 32-bit **table base** from global location `0x08712120`. **F-U23** executes before a halfword store to table base plus indexed displacement. The stored halfword is the low 16 bits of the captured table base itself.

This is a truncated-address store, not a store of the index or an independently loaded table element. A change to the table-base global during F-U23 does not itself replace the captured base.

After **F-U24**, a 32-bit address is read from absolute address `0x2218`, obtained by adding `0x54` to `0x21c4`. **F-U25** then returns an address. The function stores halfword `0x21c4` at offset `0x04` of that returned address.

**F-U26** and **F-U27** execute next. An unsigned halfword is then read at offset `0x34` of the address previously captured from `0x2218`. This is the **second selector**. The pointer is captured before F-U25, but the halfword is read after F-U27; intervening dependencies may therefore affect the eventual halfword read.

### Final paired result and frame-base movement

**F-U28** produces the third represented 64-bit result:

- Its low 32-bit half is the **payload**.
- Its high 32-bit half is the **result base**.

The payload is stored as a word at current frame-base offset `0x258`. Only after this store does the function read an unsigned halfword from result-base offset `0x14`. This zero-extended halfword is the **small value**.

The subsequent calculations form a payload displacement by shifting the payload left by six, and a **scaled result base** by multiplying the result base by four. These calculations have signed-expression limitations.

The frame base is then decreased by `0xf4`. No matching restoration appears before the next iteration.

The second selector is multiplied by four, and the payload is stored as a word at that scaled selector plus `0x74`. Because the selector is an unsigned halfword, this destination ranges from `0x74` through `0x40070`, inclusive, in steps of four. This selector calculation does not require treating the selector as negative.

### Selected-object updates and continuation

**F-U29** precedes a word store of the zero-extended small value at selected-object offset `0x54`. **F-U30** precedes a second word store of the same value at offset `0x64`.

After **F-U31**, the low 16 bits of the selected-object address are stored as a halfword at the sum of the payload displacement and an auxiliary address associated with F-U31.

**F-U32** and **F-U33** then execute. A byte is read from the numeric address equal to five times the second selector. This follows from adding the selector to its fourfold scaled value; the address ranges from zero through `0x4fffb`.

**F-U34** executes between that byte read and its destination write. The captured byte is stored at transfer base plus small value plus `0x19`. Consequently, a change to the byte’s source memory during F-U34 does not itself replace the captured byte.

After **F-U35**, the scaled result base is stored as a word at selected-object offset `0x44`.

**F-U36** executes next. The represented link/control value is then assigned `0x08712031`. A word is read at scaled-result-base offset `0x44` and supplied to **F-U37**.

The final argument read occurs after F-U36, so that dependency can affect the memory value observed there. The preceding selected-object store and this read use different address formulas; they coincide only if the relevant addresses happen to alias.

The loop then repeats unconditionally. In the literal represented state flow, the next F-U01 target is formed from `0x08712031 + 0xffe`, equal to `0x0871302f`. The frame base remains reduced by `0xf4`; its original value is not restored.

## Acceptance examples

These are conditional consequences of the static representation, not executed tests. They assume execution reaches the stated operation and that required accesses are valid.

1. **Unsigned extraction and defined word shift.** If the F-U09 low half is `0xfc000003`, the frame-offset `0x26c` store contains `63`. The later captured-object offset `0x54` store contains `0xf000000c`.

2. **First selector is an unsigned address component.** If the first selector is `0xffff`, the selected-object pointer is read from `0x10043`. The selector is neither sign-extended nor first dereferenced as a pointer slot. Whether that address supports a word read is environment-dependent.

3. **Captured initial pointer.** If `0x087120b4` contains address A when read, and F-U04 replaces the global with B, the subsequent explicit byte stores still target A at offsets `0x11` and `0x15`, provided A remains valid.

4. **Table-base narrowing and displacement.** If the captured table base is `0x12345678` and F-U19 returns `3`, the indexed displacement is `12`. The halfword store targets `0x12345684` and writes `0x5678`. A later change to the global does not itself change either captured operand.

5. **Unsigned small value and selector scaling.** If the second selector is `3` and the small value is `0x8001`, the selector-indexed payload destination is `0x80`, the byte source is address `15`, and the selected-object stores at `0x54` and `0x64` contain `0x00008001`.

6. **Breakpoint boundary.** If the breakpoint permanently suspends execution, earlier calls and stores may already be visible. The selected-object pointer read, F-U20–F-U37, and all later iteration stores do not occur.

7. **Frame movement across iterations.** If the frame base begins an iteration at B, execution reaches the next iteration, and unresolved effects do not otherwise change that state, the next frame-offset `0x26c` store uses B minus `0xf4` as its base.

8. **Late read observes intervening changes.** If F-U36 changes the word at scaled-result-base offset `0x44`, the subsequent explicit argument read for F-U37 observes the resulting memory state, subject to the environment’s memory model.
