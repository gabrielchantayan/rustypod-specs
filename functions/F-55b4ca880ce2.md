# F-55b4ca880ce2

## Purpose

F-55b4ca880ce2 builds a collection of newly constructed objects, installs object references into a caller-supplied state record, initializes one central object, and attempts to initialize up to three objects in each of two directions. It then writes two status bytes and a derived 32-bit value into the state record.

The established behavior is structural: object construction, link writes, dependency calls, and state updates. Interpreting the objects as a navigable window or cache is **inferred intent**, not an established semantic requirement. The meanings of the directional operations, status bytes, and initialization arguments are not available.

This contract describes static evidence only. No runtime tests have been performed.

| Base value | Signed 32-bit integer | Passed unchanged to the initialization dependency; used in a final addition |

The state record must provide at least 29 accessible bytes for the directly observed accesses. Its observed layout is:

|---|---:|---|

## Behavior

### Initial state adjustment

The existing 32-bit word at state offset 20 is interpreted as unsigned for comparison with the limit value.

- If the limit is strictly less than that word, the word at offset 20 is cleared to zero.
- If the values are equal, the word is preserved.
- If the limit is greater, the word is preserved.

The limit value is then stored at state offset 16.

This is a strict unsigned comparison over the full 32-bit range. A state word with its high bit set is therefore treated as a large unsigned value, not as a negative signed value.

No other state fields are explicitly initialized before construction begins.

### Construction and installation of the first object

The function calls F-8157a180d901 with a request of 628 bytes. Its result is supplied as the first argument to F-aec5dec77dbd, whose second argument is zero.

The reference returned by F-aec5dec77dbd is installed in the state record in this order:

1. State offset 4 receives the reference.
2. State offset 0 receives the same reference.
3. The 32-bit field at offset 312 of the returned object is cleared.
4. The object reference at state offset 0 is read again, and its field at offset 308 is cleared.

The final object reference is explicitly reloaded from the state record; it is not established solely by retaining the earlier construction result. With valid, nonoverlapping storage and no external interference, both object-field writes affect the first constructed object.

There is no check for a null allocation result or a null construction result before these object writes.

### Construction of the separate chain

The function next performs another allocation-and-construction pair with the same arguments: a 628-byte request, followed by construction with a zero second argument.

The resulting reference is stored at state offset 8. Its 32-bit field at object offset 308 is cleared.

An additional 21 allocation-and-construction pairs follow. For each new object:

- Its field at offset 308 receives the reference currently stored at state offset 8.
- State offset 8 is then replaced with the new object reference.

Consequently, under noninterfering dependency behavior and ordinary nonoverlapping storage, this phase produces a 22-object chain. The most recently constructed object is the head; the earliest object in this chain has a zero link.

The first constructed object is separate from this chain in the directly observed writes. Its reference is held at state offsets 0 and 4, rather than being inserted into the chain at offset 8.

Before directional processing begins, normal execution has made exactly 23 calls to F-8157a180d901 and exactly 23 calls to F-aec5dec77dbd. This count covers only calls made directly by F-55b4ca880ce2; dependencies may perform additional work internally.

No field at offset 312 is explicitly cleared on the 22 chain objects by this function. Their other contents depend on the dependencies.

### Initialization of the central object

After all construction calls, F-7cb8ec6f6858 is invoked with:

- The object reference then held at state offset 0.
- The original base value.
- A relative value of zero.
- The 32-bit value then held at state offset 20.

The state word used here is read after the construction phase. It must not be assumed to equal the value produced by the initial comparison if dependencies can modify the state through aliases or shared state.

The initialization dependency’s return value, if any, is not used.

### First directional phase

The function attempts up to three calls to F-085efd4ef014. Each receives the state-record address and the integer value 1.

For each attempt:

- A zero result ends this directional phase immediately.
- A nonzero result identifies an object whose 32-bit field at byte offset 300 is read.
- F-7cb8ec6f6858 is called with that object, the original base value, the current positive relative value, and the field value just read.

The positive relative values are 1, 2, and 3, in that order. There is no fourth attempt.

A zero result prevents both the field read and the corresponding initialization call. It does not prevent the second directional phase from starting.

### Second directional phase

After the first directional phase, the function independently attempts up to three calls to F-8166135a5e64. Each receives the state-record address and the integer value 1.

Its termination rule is the same: a zero result ends this phase without reading an object field or initializing that result.

For nonzero results, F-7cb8ec6f6858 receives:

- The returned object reference.
- The original base value.
- A relative value of −1, −2, or −3, in that order.
- The 32-bit field read at byte offset 300 of that object.

The second phase begins at relative value −1 regardless of how many successful results the first phase produced.

The returned references are not checked for uniqueness. The visible function neither rejects repeated references nor prevents an object from being initialized more than once.

### Final state writes

After both directional phases finish, the function performs these writes in order:

1. The byte at state offset 28 becomes 1.
2. The 32-bit word at state offset 24 receives the base value plus 300.
3. The byte at state offset 12 becomes 1.

It then returns without an explicit result.

The addition is represented as signed 32-bit arithmetic. For base values from −2,147,483,648 through 2,147,483,347, its mathematical result is representable. Behavior outside that range is **documented_only**: the supplied representation does not establish a portable overflow rule.

## Side effects

The function directly modifies the state record and selected fields of constructed objects. It also invokes dependencies that may have additional effects not visible here.

Important state and ownership properties:

- Existing references at state offsets 0, 4, and 8 are overwritten without any visible release operation.
- No explicit deallocation occurs.
- Allocation ownership, ownership transfer through construction, and eventual reclamation are unknown.
- The allocation-like result is passed directly to the construction dependency. It is not independently retained by this function.
- There is no visible rollback or cleanup path for partial completion.
- The two status bytes are not cleared on entry. If either already contains 1, observers may see that value throughout construction.
- The final writes do not establish that earlier state values survived dependency calls unchanged.
- No locking or synchronization is visible. Concurrent observation is not established as safe.

## Acceptance examples

These are conditional acceptance scenarios, not executed tests. Unless stated otherwise, dependencies return valid, distinct objects, do not modify unrelated state, and return normally.

### Existing position exceeds the limit

Given an initial word of 12 at state offset 20 and a limit of 10:

- Offset 20 is cleared before construction.
- Offset 16 receives 10.
- The central initialization receives zero as its fourth argument, provided construction dependencies do not change offset 20.

With an initial word of 10 and the same limit, offset 20 is preserved instead.

### Unsigned comparison boundary

Given the 32-bit pattern `0xFFFFFFFF` at state offset 20 and a limit of 1, offset 20 is cleared. The comparison treats that pattern as 4,294,967,295.

Given the same pattern and a limit of `0xFFFFFFFF`, it is preserved because equality does not trigger clearing.

### Both directions terminate immediately

If each directional dependency returns zero on its first call:

- All 23 construction pairs have already occurred.
- Only the central initialization occurs.
- Neither directional result is dereferenced.
- The final status and derived-value writes still occur.

### One direction stops early

If F-085efd4ef014 returns one valid object and then zero, its object is initialized with relative value 1 only.

F-8166135a5e64 still starts independently. If it returns three valid objects, they are initialized with relative values −1, −2, and −3.

### Both directions remain available

If all six directional calls return nonzero references:

- The initialization relative values occur in order: 0, 1, 2, 3, −1, −2, −3.
- No fourth directional request is made in either phase.
- Each noncentral initialization receives the field value read from offset 300 of its returned object.

### Final field widths

With a base value of 700, the final word at state offset 24 becomes 1,000.

The bytes at offsets 28 and 12 become 1. Neighboring bytes are not modified by those two byte writes themselves.
