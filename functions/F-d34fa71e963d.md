# F-d34fa71e963d

## Purpose

F-d34fa71e963d conditionally retrieves a 32-bit value from an indexed record and stores it through a caller-supplied output pointer. Retrieval requires all of the following:

- An initial dependency call returns zero.
- The signed index passes the function’s explicit checks.
- The selected record has a one-byte discriminator equal to 3.
- The record’s 32-bit comparison field equals the supplied comparison value.

The function returns a 32-bit status. Status 0 requires a matching record whose retrieved value is nonzero, followed by a final dependency call returning zero. Status 2 covers every other normally returning outcome.

**Inferred intent:** the two dependency calls appear to bracket protected access to a record table. Their actual synchronization semantics are not established. This contract therefore describes them by their observable calls and results, without assuming lock ownership, exclusion, or release behavior.

The output pointer is dereferenced only after the discriminator and comparison checks succeed. An unused output pointer is not validated by this function, although dependency behavior remains unknown.

## Behavior

### Initial dependency call

Before inspecting the index or accessing a record, the function:

1. Loads the 32-bit value at context offset `0xA08`.
2. Calls F-f0216cff9365 with that loaded value and the address at context offset `0xA00`.

Only an exact zero result permits further processing.

If F-f0216cff9365 returns any nonzero result, the function returns 2. It does not directly access a record, write the output, or call F-2bb3dbfa7286 on this path. This includes both positive and negative nonzero dependency results.

Effects performed inside the dependency are not constrained by this function.

### Index eligibility

Following a zero result from F-f0216cff9365, the function considers a record only when both conditions hold:

- The signed index is less than 128.
- The index is not −1.

Consequently:

- Indices 0 through 127 pass.
- Index −1 does not pass.
- Indices 128 and greater do not pass.
- Indices −2 and below pass the explicit checks.

For an ineligible index, the function skips its direct record reads and output write, but still makes the final dependency call.

The acceptance of negative indices other than −1 is established behavior, not evidence that those indices designate valid records. Such indices ordinarily direct accesses before the context base. Whether those addresses are valid is an external precondition.

### Record selection and conditional reads

For an eligible index, the record is selected using a 20-byte stride from the context base.

The function’s direct record accesses occur in this order:

1. Read the one-byte discriminator at record offset `0x08`.
2. Only if the discriminator equals 3, read the 32-bit comparison field at record offset `0x10`.
3. Only if that comparison field equals the supplied comparison value, read the 32-bit retrieved value at record offset `0x00`.
4. Store the retrieved value through the output pointer.

A discriminator other than 3 prevents both later record reads and the output write. A comparison mismatch prevents the retrieved-value read and output write.

The comparison is exact equality of the recovered 32-bit integer values. No range test, normalization, or partial-field comparison is shown.

The retrieved value is written even when it is zero. The local candidate status becomes:

- 0 if the retrieved value is nonzero.
- 2 if the retrieved value is zero.

Thus, a zero-valued matching record causes an output write but does not produce a successful status. Conversely, an output left unchanged is not a separate status category.

### Final dependency call and return

Whenever the initial dependency returns zero, the function subsequently:

1. Loads the 32-bit value at context offset `0xA08` again.
2. Calls F-2bb3dbfa7286 with that newly loaded value and the address at context offset `0xA00`.

This call occurs after any direct output write. It also occurs for skipped indices, discriminator mismatches, comparison mismatches, and matching records containing zero.

If F-2bb3dbfa7286 returns zero, the function returns its candidate status. If that dependency returns any nonzero result, the function returns 2 regardless of the candidate status.

A nonzero final dependency result does not cause this function to undo an earlier output write.

These statements concern normal returns. No exception handling, fault recovery, or compensating action is shown for an invalid memory access or a dependency that does not return normally.

## Side effects

### Direct memory effects

The function’s only explicit memory write is a single 32-bit store through the output pointer on a fully matching record.

It directly reads:

- The dependency argument at context offset `0xA08` before the initial call.
- Up to three selected record fields, subject to the conditions above.
- The dependency argument at context offset `0xA08` again before the final call, if the initial call returned zero.

The second dependency argument load is not a cached reuse of the first. Its value may differ because of dependency effects, concurrent activity, or aliasing with the output location.

### Aliasing

No non-aliasing requirement is visible in the supplied representation.

If the output points to context storage, the matching-record write occurs before the final dependency argument is loaded. In particular, if the output aliases the 32-bit field at context offset `0xA08`, the final dependency receives the newly stored retrieved value, assuming no intervening mutation.

If the output aliases record storage, the write may modify that storage. The discriminator, comparison field, and retrieved value needed for the current selection have already been read before this store.

Aliasing can therefore affect later dependency behavior even though it does not change the already selected candidate status.

### Ownership and external state

Neither dependency may be assumed to preserve global state, preserve context contents, or refrain from owning or releasing memory. Their internal effects are documented only as unknown.
