# F-29578640674e

## Purpose

F-29578640674e conditionally detaches a node from a pointer-linked structure, performs state-dependent structural repair, and prepends the detached node to a container-maintained list. It writes a 32-bit result to caller-provided storage.

**Established static behavior:** the function accesses parent and child links, a header containing a root and two cached extrema, one-byte node states, a list head, and a 32-bit counter. A preliminary dependency can bypass all direct structural mutations.

**Inferred intent:** the structure resembles a red-black tree, and the detached-node list resembles a reuse list. These interpretations do not establish key ordering, allocation ownership, or conformance to a standard tree-erasure algorithm.

The contract below preserves the observed repair choices, including use of the parent as the repair cursor after leaf removal and use of the moved successor when its former right child is absent.

## Behavior

### Preliminary decision and result selection

The function first reads the node-reference word into a private 32-bit result temporary. It then reads the container’s header word into a second private temporary.

It calls **F-a1ecaae6738a** with the addresses of those two temporaries.

If the dependency returns nonzero, the function:

- Rereads the header word at container offset +16.
- Assigns that newly read word to the result temporary.
- Writes the result temporary to the result destination.

This path makes no direct tree, state, list, or counter mutation. Dependency effects are not excluded. In particular, the returned result need not equal the header word captured before the call.

If the dependency returns zero, the function calls **F-dcbd5e1e578f** with the first temporary’s address. Only afterward does it reread the node-reference word to obtain the removal target. Thus, dependency effects can make the removal target differ from the initially captured word.

On the removal path, the visible body does not subsequently replace the result temporary with a calculated removal result. The final output is its **then-current value when the final store reads it**. A value installed by either preliminary dependency is not guaranteed to survive later dependency calls: a previously supplied address could have been retained and used again.

### Structural case selection

The target’s left link is read first.

- If absent, the right link determines whether removal is a leaf case or a one-child case.
- If present, an absent right link produces the other one-child case.
- If both children are present, the function follows left links from the right child until reaching a node whose left link is absent.

That last node is called the **successor** here solely because of its structural position. No key comparison or ordering validation occurs.

The supplied body contains repeated reads of some child links and traversal conditions. These are not atomic snapshots, and no concurrent-mutation behavior is established.

### Leaf removal

For a target with no children, its parent becomes the repair cursor.

If that parent equals the current header, the writes occur in this order:

1. Header rightmost becomes the header.
2. Header leftmost becomes the header.
3. Header root becomes zero.

Otherwise, the parent’s left link is compared with the target. Equality selects the left link; inequality selects the right link, without separately checking that the right link names the target.

The selected link is cleared by four successive one-byte zero writes, in increasing address order. This is not represented as a single four-byte write.

The same child-side decision selects one extrema cache:

- Left-child removal selects the leftmost cache.
- Right-child removal selects the rightmost cache.

If that selected cache equals the target, it is changed to the target’s parent. The other cache is not examined in this branch.

The original target remains the detached node. Repair starts from its parent, not from a separate representation of the removed null-child position.

### Removal with one child

The sole child becomes the replacement and repair cursor. Its parent field is written to the target’s parent before the root or incoming parent link is redirected.

If the header root names the target, the root becomes the replacement. Otherwise, the target’s parent left link is compared with the target; equality redirects that link, and inequality redirects the right link.

Extrema handling follows:

- If the leftmost cache names the target, the function examines the target’s right link. If absent, the cache becomes the target’s parent; otherwise, it becomes the leftmost node reached from the replacement.
- If the rightmost cache names the target, the function examines the target’s left link. If absent, the cache becomes the target’s parent; otherwise, it becomes the rightmost node reached from the replacement.

These tests use fields read at that stage. Under the ordinary distinct-object model, they reflect the target’s original child configuration.

The original target, not the replacement, is ultimately inserted into the detached list.

### Removal with two children

The successor is moved into the target’s structural position. No payload copy is visible.

The mutation order is:

1. The target’s left child receives the successor as parent.
2. The successor’s left link receives the target’s left child.
3. The successor’s old position is handled.
4. The root or incoming parent link is redirected from target to successor.
5. The successor’s parent receives the target’s parent.
6. The target and successor state bytes are exchanged.

Handling of the old position depends on whether the successor is the target’s immediate right child:

- **Immediate right child:** a present successor right child has its parent written to the successor. The successor’s right link is otherwise retained.
- **Deeper successor:** a present successor right child receives the successor’s former parent; that former parent’s left link becomes the successor’s right child; the successor takes the target’s right subtree; that subtree’s parent becomes the successor.

The successor’s former right child becomes the repair cursor if present. If absent, the moved successor itself becomes the cursor.

The original target remains the detached node. Consequently, its state after the exchange is the successor’s former state, and that exchanged state governs repair entry.

This branch contains no direct extrema-cache update.

### State-dependent repair

Repair is entered only if:

- The repair cursor differs from the current header; and
- The detached node’s state is nonzero.

Each iteration first checks the current root and cursor state. If the cursor is the root, or its state is not exactly one, repair proceeds to completion, where the cursor’s state is written to one.

Otherwise, the cursor’s parent and that parent’s left link determine the side. If the left link does not equal the cursor, the right-side branch is used without an additional right-link membership check.

The two branches use these roles:

| Cursor position | Sibling | Near child of sibling | Far child of sibling | Outer dependency | Inner dependency |
|---|---|---|---|---|---|
| Left | Parent’s right child | Left | Right | F-3a03d48e47fa | F-f76ef3e16f1e |
| Right | Parent’s left child | Right | Left | F-f76ef3e16f1e | F-3a03d48e47fa |

The branch behavior is:

- **Missing sibling:** write zero to the cursor’s state and continue from the loaded parent.
- **Zero-state sibling:** write one to the sibling, write zero to the cursor’s parent, and call the outer dependency. Reload the parent through the cursor’s parent field, then reload the sibling. A now-missing sibling takes the missing-sibling path.
- **Both sibling children absent or exactly state one:** write zero to the sibling and continue from the cursor’s parent, reread from its field.
- **Otherwise, far child absent or exactly state one:** write one to a present near child, write zero to the sibling, and call the inner dependency. Reload the sibling through the cursor’s current parent. If absent, proceed to completion.
- **Final adjustment with a present sibling:** copy the cursor parent’s state to the sibling; write one to the cursor’s parent; write one to a present far child; call the outer dependency; then proceed to completion.

Completion writes one to the current cursor’s state.

The missing-sibling case differs observably from a present sibling with two absent children: the former changes the cursor’s state, while the latter changes the sibling’s state.

Dependency effects occur between the specified writes and reloads. The contract does not assume that a call preserves the header, links, state bytes, result temporary, or other reachable storage.

### Detached-list insertion and final store

After structural work and any repair, the direct operations occur in this order:

1. Read the current detached-list head.
2. Write that word to the original target at offset +12.
3. Write the target address to the container’s list-head field.
4. Read the counter, subtract one, and write the counter.
5. Read the result temporary’s then-current value and write the result destination.

The detached node’s parent and left fields are not generally cleared. Its right field becomes the detached-list link.

The counter is a 32-bit field with no visible zero check, saturation, refusal, or error branch. Under 32-bit word arithmetic, decrementing zero produces all one bits. Portable higher-level signed-overflow guarantees are not established by this representation.

## Acceptance examples

These examples are conditional static expectations, not reported executions. They require valid storage, normal dependency returns, and the stated stability conditions.

1. **Bypass with a changed header.**  
   F-a1ecaae6738a changes the container’s header word and returns nonzero. The output is the subsequently reread header word, not the initial snapshot. F-dcbd5e1e578f is not called, and the function directly performs no removal or decrement.

2. **Sole-node removal.**  
   The target has no children, its parent is the header, and preliminary dependencies leave the structure unchanged. Rightmost becomes the header, then leftmost becomes the header, then root becomes zero. Repair is skipped because the cursor is the header. The target is prepended to the list and the counter decremented.

3. **Zero-state non-root leaf.**  
   With stable, consistent links and a zero-state target, the selected parent link is cleared by four byte writes. Only the corresponding extrema cache is considered. Repair is skipped, but insertion and decrement still occur.

4. **One-child removal.**  
   With stable links, the child’s parent changes before the root or incoming parent link changes. The original target enters the detached list. Extrema follow the branch-specific rules rather than an unconditional scan of the whole tree.

5. **Childless successor.**  
   With two target children and no successor right child, the successor moves into the target’s position, state bytes are exchanged, and the moved successor becomes the repair cursor. Substituting a conventional null-position repair cursor does not preserve this behavior.

6. **Dependency-written result preserved until completion.**  
   F-dcbd5e1e578f writes a distinct word into the result temporary. If that temporary remains unchanged until the final store reads it, that word is output. Normal completion alone is insufficient to establish this condition.

7. **Later modification through a retained address.**  
   Suppose a preliminary dependency retains the result temporary’s address and a subsequently executed repair dependency uses it to install another word. If no further change occurs before the final read, the later word is output. The earlier dependency-written value has no special priority.

8. **Missing sibling during repair.**  
   A state-one, non-root cursor has no sibling. The cursor is changed to zero before ascent to the loaded parent. Treating absence identically to a present sibling with two absent children would omit an observable write.

9. **Zero counter under word arithmetic.**  
   With completed removal and a zero counter, the 32-bit word-arithmetic decrement produces all one bits. No visible validation branch prevents the removal. Execution-model guarantees beyond that width-level observation remain unresolved.
