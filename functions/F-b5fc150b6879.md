# F-b5fc150b6879

## Purpose

F-b5fc150b6879 selects one of several dependency-call sequences using a source address, a destination address, and a 32-bit selector. On paths that reach completion, it writes the selector’s low-order byte at destination offset 36 and returns zero.

The function also returns the 32-bit status pattern `0xFFFFFFCE` in two circumstances: either address argument is zero, or a result obtained on the nonzero-selector path is unsigned-less-than 36.

The established behavior is a dispatch-and-finalization operation, not a proven copy or string-conversion operation. Several dependencies receive addresses and numeric arguments resembling buffer-operation parameters, but their implementations and contracts are unavailable. Their effects must not be inferred from those argument shapes.

## Behavior

### Initial rejection

Before making a dependency call or performing its explicit byte store, the routine checks whether either address argument is zero.

If either is zero, it returns `0xFFFFFFCE`.

This rejection is independent of the selector. It does not invoke a dependency, inspect source memory, or explicitly modify destination memory.

The check provides no validation beyond rejecting the zero values.

### Zero-selector path

When both addresses are nonzero and the full 32-bit selector equals zero:

1. F-7a47d707217e is called with the address at source offset 2.
2. Its result is compared with zero.
3. Exactly one of the following calls is made:
   - If the result is zero, F-fac138f80b6d receives the destination address, the address at source offset 2, and the numeric value 35.
   - If the result is nonzero, F-67e3e1748620 receives the destination address, the address at source offset 2, and the numeric value 36.
4. If the selected call returns normally, the routine stores a zero byte at destination offset 36.
5. It returns zero.

Every nonzero result from F-7a47d707217e selects the second alternative, including any negative value under a signed interpretation. No particular nonzero result is treated as an error by this routine.

The results of F-fac138f80b6d and F-67e3e1748620 do not participate in a visible status check. Consequently, the enclosing routine’s zero return does not establish that either dependency completed its intended operation successfully.

### Nonzero-selector path

When both addresses are nonzero and the full 32-bit selector is not zero:

1. F-fac138f80b6d is called with the destination address, the address at source offset 21, and the numeric value 35.
2. After that call returns, F-1cb585febd84 is called with the address at source offset 2.
3. The latter result is interpreted as an unsigned 32-bit value.
4. If that unsigned value is less than 36, the routine returns `0xFFFFFFCE` immediately.
5. Otherwise, the routine stores the selector’s low-order byte at destination offset 36 and returns zero.

The order is significant: the first dependency call occurs before the unsigned comparison can reject the operation. This is not a validate-before-modify sequence.

The threshold comparison is strictly less than 36. A result of exactly 36 passes. A result whose high bit is set also passes because the comparison is unsigned, regardless of whether the same bit pattern would be negative under a signed interpretation.

### Selector truncation

Branch selection uses all 32 bits of the selector. The final store uses only its low-order eight bits.

A nonzero selector can therefore take the nonzero-selector path but still produce a zero byte. For example, selector 256 follows that path and, if accepted, stores zero.

This distinction prevents treating the selector as either a simple Boolean output or an already-normalized byte.
