# F-4c45c0247ab4

## Purpose

F-4c45c0247ab4 constructs a partial output description from a context. It conditionally appends up to four entries in a fixed order, writes selected attributes, obtains destinations for up to two auxiliary payloads, and records an entry count and bounded aggregate.

This is not whole-object initialization. Fields not written on the selected path retain their prior contents unless affected by dependencies or overlapping storage. An early error leaves partial output writes visible.

The apparent intent is to describe media or stream components. That interpretation is inferred; numeric kinds, field offsets, and observed operations define this contract.

## Interface

The function receives two addresses:

- **Context:** storage containing 32-bit words and pointers, byte flags, halfwords, and references to nested objects.
- **Output:** writable storage containing two leading words, entry fields, auxiliary address/length pairs, and primary-format metadata.

The observed return width is 32 bits.

| Return | Meaning |
|---|---|
| `0` | Normal completion, including completion without entries. |
| `3` | A primary entry was eligible, but neither primary source pointer was present. Later entries and final aggregate processing are skipped. |

No argument validation or output-capacity argument is visible.

### Widths and layout

The representation uses 8-bit bytes, 16-bit halfwords, and 32-bit words and pointer representations. Thresholds and aggregate bounds use unsigned 32-bit comparisons. The selector passed to F-a2a686313150 is a signed 16-bit quantity extended to the argument width.

All offsets below are byte offsets. Target byte order and exact alignment requirements are not independently established.

For entry index \(i\), define its field base as output plus \(0x60i\). Entry-relative offsets are measured from that address; the first kind field is at relative `0x08`. This addressing rule does not establish independently allocated `0x60`-byte entry objects.

Fields at relative `0x60`, `0x64`, and `0x66` extend into the next stride. This overlap is part of the observed layout and must not be normalized away. Auxiliary pairs instead occupy absolute output offsets `0x188 + 8i` and `0x18C + 8i`.

### Storage requirements

The two successful primary-source paths have different explicit-write extents:

- The `0x48` source path writes through output byte `0x1B3`, requiring storage through at least `0x1B4` bytes.
- The `0x4C` source path writes through output byte `0x1AF`, requiring storage through at least `0x1B0` bytes. It does not directly write bytes `0x1B0`–`0x1B3`.

These are successful-path extents, not the extent of the early missing-source error. Storage of at least `0x1B4` bytes is sufficient for all direct output writes across the available paths, but is not the exact extent of every primary-containing path. Additional dependency writes remain unknown.

### Preconditions

Every selected dereference and write must address valid storage of the required width. Selected nested objects must expose the accessed fields. Dependency-returned addresses must support their subsequent use, and consumed scratch fields must have been initialized by the decoder.

No overlap checks are visible. Straightforward field-mapping expectations therefore require stable, non-overlapping context, output, source objects, globals, and dependency-visible storage. Overlap otherwise makes earlier writes relevant to later reads.

## Behavior

The context pointer at `0x1B8` is read first. If nonzero, its nested word at `0x08` is read. A primary entry is attempted only if both are nonzero.

An attempted primary entry first receives kind byte `0` at output `0x08`. Context pointer `0x48` then selects the preferred source. Only when it is zero is context pointer `0x4C` tested.

If both source pointers are zero, the direct writes following the kind write are, in order:

| Output offset | Width | Value |
|---|---|---|
| `0x09` | Byte | `255` |
| `0x00` | Word | `0` |
| `0x04` | Word | `0` |

The function returns `3`. No dependency is called on this path, neither context cache is updated, and later entry gates and final aggregate processing are not reached.

Without primary eligibility, processing continues with an initial count of zero.

### Primary source at context `0x4C`

**Global-read order is distinct from limit selection.** Global word K₁ is read after the subtype write and before any of the four format-byte copies. This read occurs even when a later nonzero request replaces its value.

Four individual source bytes at `0x05`, `0x06`, `0x07`, and `0x08` are then copied, in that order, to output `0x1AC`–`0x1AF`. The context source pointer is read afresh for each copy.

After those copies, the source pointer is acquired again. The following fields are obtained in this order:

| Source offset | Width | Use |
|---|---|---|

### Final count and aggregate

Normal completion writes the final count, from zero through four, to output `0x00` before computing the aggregate.

The initial candidate is zero unless the current context pointer `0x1B8` is nonzero, in which case the nested unsigned word `0xC8` supplies it. The pointer is tested and then read again for the nested access.

The candidate is raised to context unsigned lower bound `0x5C` when necessary, then lowered to context unsigned upper bound `0x58` when necessary. Each taken replacement reads its context bound again. With stable bound storage, the result is:

\[
\min(\text{upper bound},\ \max(\text{candidate},\text{lower bound})).
\]

The result is stored at output `0x04`, and the function returns `0`. Contradictory bounds are not diagnosed; the upper bound wins.

## Side effects

Direct context writes are limited to primary cache `0x68` and kind-1 cache `0x6C`. Other context changes, if any, arise from dependencies or aliasing.

Output updates are incremental, with no rollback or bulk clearing. Existing auxiliary addresses may be overwritten without a visible release. No direct release operation is present, but this does not establish dependency ownership or leak behavior.

Global reads remain observable even when their values are discarded:

- K₁ precedes the primary `0x4C` format-byte copies.

Primary payload address and length, by contrast, are captured before the primary dependency sequence.

## Acceptance examples

These are conditional static cases, not executed tests. Unless stated otherwise, they require valid, non-overlapping storage and dependencies that preserve relevant inputs and output beyond their specified results.

1. **No entries:** All gates false yields return `0`, count zero, and the bounded aggregate. Entry storage is not cleared.

2. **Missing primary sources:** Primary eligibility with both sources zero yields return `3`, kind `0`, subtype `255`, and zero header words. Enabled later kinds are skipped.

6. **Primary limit floor:** On `0x48`, requests `0`, `1`, `32768`, and `40000` select `128000`, `32768`, `32768`, and `40000`.

7. **Decoded boundary and wraparound:** With category `5` and the required doubled relationship, first values `0`, `32768`, and `48000` select subtype `7` and block value `2048`. First `48002` with second `24001` selects subtype `0`, rate `24001`, and block `1024`. First `0` with second `0x80000000` also satisfies the relationship because doubling wraps to zero.

9. **Discarded K₄:** A kind-1 `0x50` request of `200000` selects `200000`, but K₄ is still read after the request and before the limit store.

11. **Partial initialization:** A kind-2 entry leaves its subtype and auxiliary pair unwritten by that path.

12. **Conflicting bounds:** Stable lower bound `100` and upper bound `50` yield aggregate `50`.
