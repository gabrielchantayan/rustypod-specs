# F-f4fc13b35b20

## Purpose

F-f4fc13b35b20 conditionally updates three integer fields in caller-provided state according to a caller-provided record.

For stable, non-overlapping inputs, records with discriminator 11 increment a counter and, when no nonzero marker is present, store the record’s value as that marker. Records with discriminator 12 add the difference between the record’s value and an existing nonzero marker to an accumulator, then clear the marker. Other discriminator values leave the state unchanged.

The interpretation of these fields as an event count, interval start, and accumulated duration is **inferred intent**, not an established domain contract. In particular, zero is used as the marker’s inactive sentinel even if zero could otherwise be a meaningful record value.

The discriminator is read more than once. An implementation must not replace those reads with a single cached value unless the applicable memory and aliasing contract makes that transformation behaviorally equivalent.

## Behavior

### Initial discrimination and counter update

The function first reads the record’s discriminator and compares it with 11.

If that read equals 11, the function reads the counter, adds one, and writes the result back to the counter. This increment occurs **before** determining whether a marker will be stored, whether an existing marker will cause an early return, or whether the subsequent discriminator read still equals 11.

After the increment, the discriminator is read again and compared with 11.

If the first discriminator read was not 11, no counter increment occurs, and this second comparison with 11 is not performed.

There are consequently two ways to leave this initial decision:

- The first and post-increment discriminator reads both equal 11: take the discriminator-11 handling path.
- The first read is not 11, or the post-increment read is no longer 11: proceed to the alternative discriminator check.

### Discriminator-11 handling

This path first reads the marker.

- If the marker is nonzero, the function returns immediately. The earlier counter increment remains in effect. The record value is not read on this path.
- If the marker is zero, the function reads record element 2 and then writes that value into the marker.

There is no accumulator update on this path.

A record value of zero is stored without special treatment. The marker therefore remains zero, and a subsequent ordinary discriminator-12 record will not be accepted as closing an active interval.

### Alternative discriminator check

On this path, the function reads the discriminator again and compares it with 12.

This is a fresh read, not a comparison against the value obtained by an earlier discriminator access.

- If the discriminator is not 12, the function returns.
- If it is 12, the function reads the marker.
- If that marker read yields zero, the function returns without reading the record value or changing the accumulator.
- If the marker is nonzero, the function proceeds with the accumulator update.

An earlier counter increment is not undone if this path returns.

### Discriminator-12 accumulator update

Once the discriminator-12 path has observed a nonzero marker, the accumulator assignment uses:

- Record element 2;
- A new read of the marker; and
- The accumulator’s existing value.

The assigned result is:

**accumulator = (record value − marker) + previous accumulator**

The subtraction is grouped before the addition. The source representation does not establish a left-to-right evaluation order among the operand reads used to calculate this assignment. It does establish that the marker is read again for the arithmetic rather than requiring reuse of the value read for the nonzero guard.

After the accumulator write completes, the function writes zero to the marker.

Thus, the accumulator write precedes the marker-clear write. There is no counter update on an ordinary, stable discriminator-12 invocation.

### Arithmetic boundaries

The function contains no range checks, saturation, overflow detection, or monotonicity test.

A closing record value smaller than the marker produces a negative difference when that difference is representable. The function does not reject such a value.

A negative marker is nonzero and therefore qualifies for discriminator-12 processing.

Counter increment, subtraction, and addition each have their own overflow boundary. In a signed 32-bit interpretation, for example, subtracting a negative marker from a positive record value may overflow even if some rearranged expression would have a representable final mathematical result. The observed grouping must not be replaced with reassociation on the assumption that overflow is harmless.

Whether overflowing execution wraps, traps, or lacks defined behavior is **documented_only** here; the supplied excerpt does not resolve it.
