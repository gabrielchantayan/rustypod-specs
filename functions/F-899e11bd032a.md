# F-899e11bd032a

## Purpose

F-899e11bd032a conditionally submits an eight-bit value to a downstream dependency after a byte at a captured address becomes nonzero.

The established behavior has three stages:

1. Reject a zero first argument without calling any dependency.
2. Ask F-f864d4b0c549 to process the first argument and a writable, initially four-byte value.
3. If that dependency returns nonzero, wait for a particular byte to become nonzero, then invoke F-b4c8a64376c1 with the low eight bits of the writable value and a zero second argument.

“Process,” “wait,” and “submit” describe the visible structure, not established application semantics. The evidence does not identify the first argument as a handle, pointer, descriptor, or object. It also does not establish that the observed byte is a readiness flag, although its role is consistent with one.

This contract describes static evidence only. No runtime tests have been performed.

## Behavior

### Zero first argument

When the first argument equals zero, the function returns normally without entering the conditional work.

On this path, the function does not:

- initialize the scratch word as part of the conditional work;
- invoke F-f864d4b0c549;
- read the address slot;
- read the observed byte;
- invoke the waiting dependency;
- invoke F-b4c8a64376c1.

The values of the remaining three arguments do not change this outcome.

### Initial dependency call

When the first argument is nonzero, the function initializes the scratch word with the fourth argument’s complete 32-bit unsigned value.

It then calls F-f864d4b0c549 with:

1. the first argument, unchanged;
2. the address of the scratch word.

The scratch word is writable through that address. Consequently, subsequent selection of its low eight bits uses the value present after this call, not necessarily the original fourth argument.

The function does not itself constrain what F-f864d4b0c549 writes. Its implementation, write width, validation behavior, and side effects are unavailable. In particular, this contract does not assume that the dependency preserves globals, preserves the scratch word on a zero result, or confines its effects to the supplied storage.

The scratch object remains local to this invocation. Passing its address does not establish an ownership transfer or permission for later asynchronous access.

### Address capture and status decision

After F-f864d4b0c549 returns normally, the function reads the address slot and retains the resulting value as the captured base.

This read occurs **before the dependency’s result is used to decide whether to enter the polling path**. Therefore, the address slot is read even when the dependency returns zero.

If F-f864d4b0c549 changed the address slot before returning, the subsequent read observes the value then available according to the execution environment. The contract does not treat the address slot as preserved across the call.

A zero dependency result causes normal return after that address-slot read. On this path, the captured base is not used to read the observed byte, and neither remaining dependency is called.

Every nonzero result takes the polling path. There is no distinction here between positive and negative nonzero results.

### Value selection

On the nonzero-result path, the function selects the scratch word’s low eight bits.

This operation is a bit mask, not saturation, signed conversion, or validation. Its result is always in the inclusive range 0–255:

- A scratch word of 0 selects 0.
- A scratch word of 255 selects 255.
- A scratch word of 256 selects 0.
- A scratch word of 511 selects 255.
- A scratch word with all 32 bits set selects 255.

The selected value is established before polling begins. This function does not reread the scratch word after a waiting call.

### Polling

The function reads one byte at the captured base plus a byte offset of two.

If that byte is nonzero on the first read, no waiting call occurs.

If that byte is zero, the function calls F-unresolved-01 with two integer arguments, 0 followed by 1. When that call returns normally, the function reads the observed byte again. It repeats this sequence for as long as the byte reads as zero.

For each iteration that observes zero, there is one waiting call before the next byte read. The function provides no timeout, iteration limit, cancellation check, or alternative exit within this loop.

The captured base remains fixed throughout polling. Changes to the address slot during a waiting call do not cause this function to select a new base. The byte contents at the captured address may change, and repeated reads are what determine loop termination.

The zero/nonzero distinction does not depend on whether the source representation treats a byte as signed. A byte whose high bit is set is nonzero and therefore ends polling.

The source-level sequence establishes repeated reads, but does not establish atomicity, volatility, memory barriers, inter-thread synchronization, or hardware-access semantics. Any requirements for observing concurrent changes are environmental prerequisites, not guarantees supplied here.

### Final dependency call

After a read observes a nonzero byte, the function calls F-b4c8a64376c1 with:

1. the previously selected value, in the range 0–255;
2. zero.

It then returns if that dependency returns normally. No dependency result is used to produce an outward status or a retry.

For an invocation that reaches this point, this function directly calls F-b4c8a64376c1 once. That statement does not constrain recursive behavior or additional calls initiated inside dependencies.

## Side effects

The directly established memory and call effects are:

- Initialization of one local four-byte scratch object on the nonzero-first-argument path.
- Exposure of that object’s address to F-f864d4b0c549.
- One read of the address slot after that dependency returns normally.
- On a nonzero dependency result, one or more one-byte reads at captured base plus two.
- Zero or more calls to F-unresolved-01, each with arguments 0 and 1.
- One call to F-b4c8a64376c1 if polling terminates normally.

No direct write to the address slot or observed byte is shown. No direct allocation, deallocation, logging, or caller-buffer write is shown.

These statements do not limit dependency side effects. In particular, no evidence establishes that any dependency preserves global state, avoids allocation, avoids releasing memory, or leaves the captured address valid.

### Preconditions and failure exposure

To reach normal completion on the polling path:

- F-f864d4b0c549 must return normally.
- The address-slot read must be valid.
- The captured base plus two must identify readable storage for every attempted byte read.
- Every waiting call that is reached must return normally.

There is no explicit check for a null, stale, or otherwise invalid captured base. A nonzero first argument is likewise not proof of validity for F-f864d4b0c549.

If the observed byte remains zero and waiting calls continue returning, this function continues polling indefinitely. If a dependency fails to return, the function does not advance beyond that call. Invalid memory access and abnormal dependency termination have no locally expressed recovery path.
