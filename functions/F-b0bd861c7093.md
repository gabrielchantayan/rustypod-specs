# F-b0bd861c7093

## Purpose

F-b0bd861c7093 performs eight ordered lookup stages using a caller-supplied object address.

The first seven stages pass their lookup results to a destination-handling dependency at successive object-relative addresses. The eighth stage treats its result as a byte pointer and selects between two indirect operations on a receiver within the object. One operation returns a status-like value; a nonzero value triggers a further indirect invocation through a separately stored global function pointer.

The established contract concerns call order, global reads, object-relative addressing, a conditional byte read, indirect dispatch, and zero/nonzero decisions. The evidence does not establish configuration keys, property names, string formats, concrete classes, or the semantic purpose of the operations.

This specification describes the supplied static representation. It does not establish the internal behavior of dependencies or report runtime observations.

## Behavior

### Ordered lookup and destination stages

The function uses eight distinct global selector locations, identified here by stage number. Their names and meanings are unknown.

For each of the first seven stages, the established order is:

1. F-9d0ecc5f6adf is invoked without explicit arguments.
2. After that invocation returns, the corresponding global selector is read.
3. F-c0b020cd3882 is invoked with the fresh 32-bit result and the selector just read.
4. After the lookup returns, F-151ab4bfe553 is invoked with the stage’s destination address and the lookup’s 32-bit result.

The destination offsets are +0x40, +0x48, +0x50, +0x58, +0x60, +0x68, and +0x70, in that order. Each destination call returns before the next stage begins, assuming normal continuation.

The selector-read timing is part of the contract. A selector is not captured at function entry, nor before its own stage’s F-9d0ecc5f6adf invocation. If that invocation changes the corresponding global, the subsequent lookup uses the value read after the change.

Each stage obtains a new result from F-9d0ecc5f6adf. Results are not reused across stages. Likewise, dependencies may change globals between selector reads; the eight selectors are not an entry-time snapshot.

There is no explicit branch on a lookup result in these seven stages. A zero lookup result is passed to F-151ab4bfe553 just like any other 32-bit result. No return value from the destination dependency is inspected.

If any dependency fails to return normally, the evidence establishes no continuation or recovery beyond that point.

### Eighth lookup

After the seventh destination call, the function forms the receiver address at object offset +0x78. Forming this address does not read its dispatch table.

The eighth lookup then follows the same dependency and selector ordering:

- F-9d0ecc5f6adf is invoked.
- After it returns, selector 8 is read from its global location.
- F-c0b020cd3882 is invoked with the fresh result and that selector.

This lookup result is treated as a byte pointer.

The branch distinguishes three cases:

| Eighth result | Direct content access | Selected path |
|---|---|---|
| Null | No byte read through the result | Receiver operation at +0x0c |
| Nonnull, first byte zero | One byte read | Receiver operation at +0x0c |
| Nonnull, first byte nonzero | One byte read | Conversion followed by receiver operation at +0x08 |

All byte values from 1 through 255 select the same nonzero path. The function itself does not scan for a terminator, compute a length, decode characters, or interpret a numeric value at this decision point.

### Null-or-zero-byte path

For a null result or a readable result beginning with a zero byte, the function:

- Reads the dispatch-table address from the receiver at object offset +0x78.
- Obtains the callable entry at table byte offset +0x0c.
- Invokes that entry with the receiver address as its sole explicit argument.
- Reaches its return if the invocation returns normally.

There is no call to F-8810f53aaa0b, no invocation of the +0x08 operation, and no read of the separate final-dispatch global on this path.

The evidence does not establish whether the +0x0c operation clears, releases, resets, or otherwise changes receiver state.

### Nonzero-first-byte path

For a nonnull eighth result whose first byte is nonzero:

- F-8810f53aaa0b is invoked with the lookup pointer.
- After that dependency returns, the receiver’s dispatch-table address is read.
- The callable entry at table byte offset +0x08 is obtained.
- That entry is invoked with three explicit arguments: the receiver address, the 32-bit conversion result, and zero.
- Its 32-bit result is compared with zero.

The dispatch-table read occurs after F-8810f53aaa0b returns. No preservation of receiver contents or dispatch-table identity across that dependency is assumed.

If the +0x08 result is zero, the function returns without invoking the +0x0c operation or the final-dispatch target.

If the result is nonzero, the function reads a function pointer from a **separate global location after the receiver operation has returned and the nonzero condition has been established**. It then invokes the target obtained by that read with:

- The nonzero 32-bit receiver-operation result.
- The original pointer value returned by the eighth lookup.

The global target is not an entry-time snapshot and is not captured before conversion or receiver dispatch. If a preceding dependency—including the +0x08 operation—changes that global, the subsequent read observes the value present at that later point.

The final target’s identity and control-transfer semantics remain unresolved. The supplied representation shows the arguments and a return afterward if the invocation returns normally; it does not establish that the target actually returns, throws, terminates, or transfers control elsewhere.

## Acceptance examples

These are conditional consequences of static control flow, not executed tests.

1. **A same-stage dependency changes its selector.**  
   If stage 3’s F-9d0ecc5f6adf invocation changes selector 3 before returning, stage 3 reads that selector afterward and passes the resulting value to F-c0b020cd3882. Reading selector 3 before that invocation would not match the established ordering.

2. **A first-seven lookup returns zero.**  
   Zero is passed to F-151ab4bfe553 at that stage’s destination. If the dependency returns normally, processing continues. The eighth-result pointer test does not apply to these earlier stages.

3. **The eighth lookup returns null.**  
   No byte is read through the result. The +0x0c operation is selected. Conversion, +0x08 dispatch, and the final global-target read do not occur.

4. **The eighth result points to a zero byte followed by other data.**  
   The first byte selects +0x0c. This function does not directly inspect subsequent bytes; accesses performed by dependencies are outside that statement.

5. **The eighth result begins with byte 255 and +0x08 returns zero.**  
   Conversion occurs, followed by +0x08 dispatch with the conversion result and zero. The function then returns without reading the final-dispatch global.

6. **The +0x08 operation returns a negative nonzero value.**  
   The final-dispatch global is read and its target invoked. The condition is nonzero, not positive.

7. **Conversion changes the receiver’s dispatch table.**  
   Assuming the resulting storage is valid, +0x08 is selected from the table read after conversion returns, not from a table captured beforehand.

8. **The +0x08 operation changes the final-dispatch global and returns nonzero.**  
   The subsequent global read supplies the changed target. Using a target captured before the receiver invocation would violate the observed ordering.

9. **The eighth result is nonnull but unreadable.**  
   The function attempts a first-byte read. No explicit validity check or recovery path establishes successful behavior.

10. **A later operation fails after earlier destinations were modified.**  
    This function performs no explicit restoration. Whether dependencies preserve, commit, or undo changes remains unresolved; the visible sequence alone proves neither atomicity nor nontransactionality.
