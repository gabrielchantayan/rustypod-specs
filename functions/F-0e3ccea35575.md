# F-0e3ccea35575

## Purpose

F-0e3ccea35575 is an indefinitely repeating sequence of indirect calls, byte accesses, and 32-bit word accesses. Its visible behavior constructs addresses from shifted or scaled values, writes selected data to those addresses, and carries selected call results into the next iteration.

The supplied representation establishes no application-level purpose. In particular, it does not establish that the accessed locations are ordinary objects, hardware registers, an allocator, or a dispatch table. Those interpretations must not become requirements.

There is no visible successful return, failure return, or terminating condition. Completion of one iteration leads directly into another.

## Interface

### Explicit inputs

The visible interface has four positional inputs:

| Input | Width | Established use |
|---|---:|---|
| First | 32 bits | Forwarded to the first indirect call; replaced near the end of each iteration by a call result. |
| Second | 32 bits | Forwarded to the first indirect call; later replaced by another call result, then shifted before the next iteration. |
| Third | 32 bits | No visible use. |
| Fourth | 32 bits | Used to construct an early word-write address and a shifted call argument; replaced before the next iteration. |

The first and third inputs are presented as uninterpreted 32-bit quantities. The second and fourth are presented as signed integers, but their visible uses are predominantly bit manipulation and address construction. Signed-overflow behavior is not established by this representation.

### Additional entry state

The four explicit inputs are insufficient to determine execution. The function also consumes incoming machine state that supplies:

- An 8-bit value used by the first byte write.
- A base used for an indirect byte read.
- A value shifted left by 12 bits to produce an early word payload.
- A control-flow value used to determine the first indirect-call destination.
- An additional call-produced machine word forwarded alongside a computed zero argument.

These are genuine dependencies in the supplied representation, not documented optional inputs. A source-level interface that discards them would not preserve the visible behavior.

### Output and termination

There is no ordinary return value. The function’s outputs are its memory accesses, dependency invocations, and state carried between iterations.

An indirect call may fail to return, trap, or transfer control elsewhere. The function contains no visible mechanism for recovering from such behavior.

### Access conventions

This contract distinguishes:

- **Byte access:** an 8-bit load or store.
- **Word access:** a 32-bit load or store.
- **Byte-selected destination:** read one unsigned byte from a specified address, then use that byte’s numeric value plus 17 as the destination address.

A byte-selected destination therefore lies between addresses 17 and 272 inclusive. It is not the original base plus a field offset.

Unless otherwise qualified, arithmetic descriptions below use 32-bit bit-vector arithmetic: left shifts discard bits above bit 31, and address construction retains the resulting 32-bit pattern. This is a description of the visible machine-oriented operations, not a claim that equivalent signed expressions are portable in a higher-level language.

## Behavior

### Execution model

The following phases describe one iteration in visible execution order. Indirect-call sequences remain observable even where none of their returned values is subsequently used.

For readability, “four preliminary calls followed by a result call” means five distinct calls, with the fifth supplying the result discussed in that phase. It does not imply that the preliminary calls are pure, interchangeable, or removable.

### 1. Entry calls and initial stores

The iteration starts with an indirect call receiving the current first and second inputs. Its target depends on incoming control-flow state on the first iteration and on a value assigned near the end of the preceding iteration thereafter.

Four more calls follow. The last supplies a word that is shifted left by two bits for the next call.

Before that next call, the function reads an unsigned byte at the incoming base plus one and writes the incoming 8-bit value to the corresponding byte-selected destination.

After the call receiving the shifted result, four further calls occur. The function then:

- Forms an initial word payload by shifting the incoming carried value left by 12 bits.
- Writes that payload to the address formed from the fourth input multiplied by 4,096, plus 20.
- Calls a dependency with the fourth input shifted left by 14 bits.
- Performs another call.
- Calls a dependency with two explicit arguments: the initial payload shifted left by 28 bits, and an additional call-produced machine word.

Under 32-bit truncating arithmetic, the first of those two arguments is always zero: the payload already has twelve low zero bits.

### 2. Initial payload replication and byte update

Three calls without explicit arguments precede a result-producing call. Its result selects a word address by multiplication by four and addition of 20. The initial payload is written there.

A call receives that result multiplied by four. Three further calls precede another result-producing call.

The latter result, multiplied by four, is retained for later address construction. The function rereads the byte at the original incoming base plus one and writes a truncated byte derived from the initial payload:

- Clear the payload’s top two bits.
- Shift right by 20.
- Retain the low eight bits for the store.

A call then receives the incoming carried value shifted left by 24 bits.

### 3. Pair forwarding and clearing the selected byte

A call produces a word. The next call receives that word and the retained scaled result shifted left by 28 bits.

Another call produces a 64-bit result. The following call receives its low 32 bits first and high 32 bits second.

Two more calls follow, with the second producing a result. The original incoming base plus one is read again, and zero is written to its byte-selected destination.

The next call receives the most recent result shifted left by two bits.

### 4. A second word payload

Three calls precede a result-producing call. Its result, shifted left by two bits, becomes a second word payload.

That payload is written to the retained scaled result multiplied by 4,096, plus 20.

The next call receives four explicit arguments, in order:

1. The retained scaled result multiplied by 1,024.
2. The same value again.
3. The unscaled result underlying that retained value shifted left by 14 bits.
4. The second payload.

Four calls follow, the last producing an address selector. The second payload is written to that selector multiplied by four, plus 20. A call then receives the selector multiplied by four.

### 5. Two scaled-value store sequences

Three calls precede a result-producing call. The returned word is multiplied by four. That scaled value is written at the unscaled result multiplied by 16, plus 20.

A call receives three identical arguments, each equal to that scaled value.

Four calls follow, the last producing a selector. The scaled value is written at the selector multiplied by four, plus 20. A call receives the selector multiplied by four.

Three further calls precede another result-producing call. Its result is likewise multiplied by four and stored at the unscaled result multiplied by 16, plus 20.

This second unscaled result also establishes a retained base by multiplication by \(2^{30}\). Under 32-bit arithmetic, that base can only be one of four values: zero, \(2^{30}\), \(2^{31}\), or \(3 \times 2^{30}\).

A call receives the second scaled value three times. Four calls follow, the last producing another selector. The second scaled value is written at that selector multiplied by four, plus 20. A call receives the selector multiplied by four.

### 6. Two pairs of explicit zero stores

Three calls precede a result-producing call whose returned word is retained for a later memory read.

The function writes zero first at the retained base plus 17 and then at the retained base plus one. These are direct byte stores, not byte-selected stores.

A call receives the retained returned word shifted left by two bits. Another call produces a word, which is passed to the next call.

Four further calls occur, the last producing a result. The function again writes zero at the retained base plus 17, then zero at the retained base plus one. A call then receives the most recent result shifted left by two bits.

The repeated stores are separate visible operations. Intervening calls may have changed the locations between them.

### 7. A word store followed by a word read

Three calls precede a result-producing call. Its result multiplied by four is retained as a later call argument.

A word is written at this result multiplied by 16, plus 20. The payload is the selector from the end of phase 5 shifted left by 31 bits. Consequently, the payload is either zero or a word with only bit 31 set.

The function then reads a 32-bit word from an address constructed from the retained return value obtained at the start of phase 6:

- Clear its top two bits.
- Shift right by 20.
- Add 20.

The resulting read address lies between 20 and 1,043 inclusive and is not necessarily word-aligned. This word read occurs after the preceding word store; overlap must not be ruled out.

A call receives the retained scaled argument. The next call supplies the replacement second input. Another call receives the loaded word shifted right by 22 bits and then left by 28 bits.

### 8. Zero word store and two byte payloads

Three calls precede a result-producing call. Zero is written as a 32-bit word at its result multiplied by four, plus 20. A call receives that result multiplied by four.

Three calls precede another result-producing call. Its returned word is retained.

The function reads the byte at the retained base plus one and writes the low eight bits of the retained word shifted left by two to the corresponding byte-selected destination.

A call receives the retained word shifted left by two. Another call produces a word, and the next call receives that result together with the retained word shifted left by 30 bits.

Three calls precede a result-producing call. The function reads the byte at the retained base plus one again. This selected byte is saved across subsequent calls.

At the saved byte’s value plus 17, the function writes the truncated result of clearing the retained word’s top two bits and shifting right by 20.

### 9. Store through a saved selector and snapshot shared state

A call receives the latest result shifted left by two bits. Four further calls occur.

The function writes the replacement second input shifted left by two as a 32-bit word at the **saved byte value plus 20**. It does not reread the byte selector for this word store. Calls between the selector read and this store may change memory without changing the saved numeric selector.

A shared 32-bit location is then read and its value retained. The supplied representation warns of overlapping global symbols; this location must not be assumed disjoint from other accesses.

A call receives the scaled argument retained in phase 7. Four calls follow, the last producing a 64-bit result. Its low half, shifted left by two, is retained.

The function rereads the byte at the retained base plus one and writes the low eight bits of the shared-state snapshot shifted right by 22 to the byte-selected destination.

A call receives the high half of the 64-bit result. Another call produces a word. The following call receives that word and the retained shifted low half shifted left by 28 bits.

### 10. Final payload construction

Three calls precede a result-producing call. The function rereads the byte at the retained base plus one and writes zero to the selected destination. A call receives the latest result shifted left by two bits.

Three calls precede another result-producing call. The next call receives two identical arguments, both equal to this result shifted left by two bits.

Four calls follow, the last producing another result. That result shifted left by two becomes the final payload.

The final payload is written at the retained shifted low half from phase 9 multiplied by 4,096, plus 20. A call receives that retained shifted low half shifted left by 14 bits.

Four calls follow, the last producing a selector. The final payload is written at the selector multiplied by four, plus 20. A call receives the selector multiplied by four.

### 11. Final byte updates and next-iteration state

Three calls precede a 64-bit result-producing call. Its low half shifted left by two is retained.

The function reads a byte at the retained shifted low half from phase 9 multiplied by 16,384, plus one. It writes a truncated byte derived from the final payload—top two bits cleared, then shifted right by 20—to the selected destination.

A call receives the high half of the latest 64-bit result. Another call produces a word, which is passed to the next call. A further call produces a 64-bit result, and the following call receives its low and high halves in that order.

Two calls follow, the second producing a result. The function reads a byte at the retained shifted low half from this phase multiplied by \(2^{28}\), plus one, and writes zero to its byte-selected destination. A call receives the latest result shifted left by two.

Three calls precede a final result-producing call. That result shifted left by two becomes both the next iteration’s carried value and its fourth input.

The next iteration’s incoming byte-selector base is the retained shifted low half from this phase multiplied by four. The function reads a byte at that new base plus one and writes zero to the selected destination.

A call receives the retained shifted low half shifted left by ten bits. A final call supplies the next first input.

Before repeating, the replacement second input is shifted left by 28 bits, the incoming byte payload is set to zero, and the next first-call control-flow value is established.

## Side effects

All direct stores and indirect calls are externally relevant unless a stronger environmental contract proves otherwise.

- No allocation, release, reference-count adjustment, or ownership transfer is explicitly visible.
- Passing a value to an unknown dependency does not establish whether it is a pointer, whether ownership transfers, or whether memory is retained.
- Dependencies may read or write globals and any accessible memory. Their preservation of selector bytes, shared state, or prior stores is unknown.
- Selector bytes are reread at the stated points. Replacing repeated reads with one cached value would change behavior when intervening calls modify them.
- The saved selector in phase 8 is an exception: the later word store deliberately uses the saved value.
- No bounds checks, null checks, alignment checks, status checks, rollback, or explicit synchronization are visible.
- An earlier write can alias a later selector read, word read, or shared-state access. The contract does not assume disjoint objects.
- Word byte order, access atomicity, and hardware-specific effects are not established.

Execution requires valid call destinations and an environment that supports every reached access. The function does not visibly enforce those preconditions.

## Acceptance examples

These examples are conditional static consequences, not executed tests.

1. **Initial payload truncation.** If the incoming carried value is 1, the initial payload is 4,096. Its subsequent left shift by 28 produces zero under 32-bit truncation. A nonzero forwarded value at that point would contradict the visible arithmetic.

2. **Byte-selected addressing.** If a selector read returns 255, the ensuing selected byte store targets address 272. It does not target the selector’s source address plus 17.

3. **Selector mutation between calls.** If an intervening dependency changes the byte at the retained base plus one from 3 to 9, subsequent fresh byte-selected writes use address 26 rather than 20.

4. **Saved selector exception.** If phase 8 saves selector 3 and a later call changes the source byte to 9, phase 9’s saved-selector word store still targets address 23.

5. **Byte truncation.** If a retained word is 63, its left shift by two yields a stored byte of 252. If it is 64, that byte store receives zero after truncation.

6. **Restricted word payload.** The phase 7 shift by 31 yields zero for an even selector and \(2^{31}\) for an odd selector, under 32-bit arithmetic.

7. **Unaligned access.** If phase 7’s computed word-read address is 21, the function attempts a word read at 21. No alignment correction or rejection is visible.

8. **Continued execution.** If all calls return and all accesses succeed, the end of phase 11 starts another iteration. No visible input value selects normal termination.
