# F-52d507a33d28

## Purpose

F-52d507a33d28 conditionally changes a 16-bit logical extent associated with an externally supplied array of 32-bit words. It rejects a requested extent greater than a stored limit. Otherwise, it clears words between the previous extent and the requested extent, stores the requested extent, and changes two high-order bits in the word immediately preceding the requested end.

This is a behavioral description of the supplied static evidence. The meanings of “extent,” “limit,” and “end” are descriptive interpretations of field usage, not established application-level semantics. In particular, the evidence does not establish that the stored limit accurately represents allocated storage.

A requested extent of zero is not rejected. On that path, the final word access is four bytes before the stored array base.

## Interface

### Inputs

The function receives two address-bearing arguments.

The first argument identifies a mutable descriptor with the following accessed layout:

| Byte offset | Width | Access | Descriptive role |
|---|---:|---|---|
| 0 | 16 bits | Read and written | Current extent |
| 2 | 16 bits | Read | Limit |
| 4 | 32 bits | Read | Array base address |

The descriptor occupies at least eight accessible bytes for the fields shown. No other descriptor fields are evidenced.

The second argument identifies storage containing the requested extent:

| Byte offset | Width | Access | Descriptive role |
|---|---:|---|---|
| 4 | 16 bits | Read | Requested extent |

The function does not access bytes at offsets 0 through 3 of this second region. The evidence does not identify the enclosing object or its complete layout.

The extent, limit, and request are interpreted as unsigned 16-bit values, each ranging from 0 through 65,535. Array elements and the internal loop index are 32-bit unsigned quantities.

The supplied representation uses a 32-bit field for the array base and a 32-bit address-bearing second argument. A wider native-pointer ABI is not established.

### Output

The function returns a 32-bit value:

- `0x00000010` if the request read for the initial comparison exceeds the descriptor’s limit.
- `0x00000000` after completing the accepted path.

The evidence does not assign an application-level name to either status.

These return guarantees assume execution completes normally. Invalid memory accesses are not converted into an evidenced error return.

### Preconditions for ordinary defined use

The caller must provide storage supporting every access actually reached:

- Readable 16-bit request and limit fields for the initial comparison.
- On acceptance, a readable current-extent field.
- A readable 32-bit array-base field whenever an array access is performed.
- Writable 32-bit words for every clearing operation.
- A writable 16-bit current-extent field.
- A readable and writable 32-bit final marker word.

The evidence establishes no alignment checks, address checks, allocation-size checks, synchronization, or fault recovery. Required alignment and the effects of invalid addresses depend on the execution environment.

A nonzero request and a truthful storage limit would support conventional array usage, but neither is fully validated by this function.

## Behavior

### 1. Admission decision

The function compares the 16-bit requested extent at offset 4 of the second input with the descriptor’s 16-bit limit at offset 2.

If the request is greater than the limit, it returns `0x00000010`.

On this rejected path:

- It performs no evidenced writes.
- It does not need to read the current extent or array-base field.
- It does not access array elements.

The relative order of the two field reads within the comparison is not established by the supplied expression.

The comparison does not validate the relationship between the existing extent and the limit.

### 2. Clearing range

If the initial request is no greater than the limit, the function reads the descriptor’s current extent and zero-extends it into a 32-bit loop index.

Before each possible clearing write, it reads the requested extent again. If the index is less than that value, it:

- Reads the descriptor’s array-base field.
- Writes a full 32-bit zero to the word at the base plus four times the index.
- Advances the index using the evidenced masked increment.

The increment adds one and then applies the mask `0xFFFEFFFF`. This clears bit 16; it is not a general 16-bit mask. However, because the initial index is a zero-extended 16-bit value and every subsequent increment follows this rule, the reachable index values remain between 0 and 65,535. Advancing from 65,535 yields zero.

With stable inputs and noninterfering storage, the request is at most 65,535, so an index of 65,535 cannot satisfy the loop comparison. Consequently, ordinary stable-input execution does not take the wrapping increment.

For stable fields:

- If the old extent is less than the request, words at indices from the old extent through one less than the request are zeroed in increasing index order.
- If the old extent equals or exceeds the request, there are no clearing writes.

The limit is not checked again during the loop. The request is not captured once for all loop comparisons. The array base is also read again for each clearing write.

These distinctions matter if array storage overlaps either input region, or if an external actor changes input memory during execution. The simple contiguous-range description applies only when those reads remain stable.

### 3. Extent update

After the loop terminates, the function reads the requested extent again and retains that 16-bit value for the remaining operations.

It writes that value to the descriptor’s current-extent field.

This final request read is separate from the request read that caused the loop to terminate. There is no further comparison against the limit. If the request storage changes between reads, the stored extent need not equal the request admitted initially or the request used by the last loop comparison.

### 4. Final marker update

After writing the current extent, the function reads the descriptor’s array-base field and computes the address:

**array base + four times the retained request − four bytes**

At that address, it reads a 32-bit word, modifies its bits, and writes a full 32-bit result back:

- Bit 31 is cleared.
- Bit 30 is set.
- Bits 0 through 29 retain their read values.

Thus, the resulting word always has its two highest bits equal to binary `01`.

For a positive request, this is the word at index request minus one. For a zero request, this is the word immediately before the array base.

The marker operation occurs even if the clearing loop performed no writes, and even if the resulting word equals its previous value.

### 5. Successful return

After the marker write, the function returns zero.

There is no additional evidenced work, callback, validation, or rollback.

## Side effects

### Normal nonoverlapping, stable-input case

For an accepted request:

1. Zero or more array words are cleared in ascending index order.
2. The descriptor’s current extent is written.
3. The final marker word is read and rewritten.

This order is significant. If expansion clears the eventual marker word, that word first becomes zero and is subsequently written as `0x40000000`.

If the operation shrinks the extent, words beyond the new end are not cleared. The function only updates the extent and marks the new final word.

No general cleanup of old marker bits is evidenced. Existing words outside the cleared range and the new final marker location remain untouched. In particular, a marker in a previously used word can remain present.

### Aliasing and changing storage

The implementation does not isolate the operation from overlapping storage.

A clearing write may overwrite:

- The request field, affecting subsequent loop conditions and the final request read.
- The array-base field, affecting subsequent destination addresses.
- The current-extent or limit field.
- Other caller-owned data at the computed address.

The initial loop index is retained independently after it is loaded; changing the current-extent field during the loop does not directly reload that index.

The stored limit is consulted only for admission. A later change to it does not trigger another limit check.

The final marker read occurs after the current-extent write. If their storage overlaps, the marker reads the memory resulting from that earlier write and may subsequently overwrite descriptor bytes.

No atomicity is established for the individual accesses or the operation as a whole. The listed ordering describes the supplied static operation sequence, not a synchronization guarantee for concurrent observers.

### Address arithmetic

Each array word is four bytes. With a reachable 16-bit index, the index-times-four term is at most 262,140 bytes.

The supplied representation performs the address calculation in a 32-bit address/integer domain. Base addition can wrap at that width. The function does not detect overflow or establish that the resulting address belongs to an allocation.

The final subtraction is four bytes, not a 16-bit decrement of the request. A zero request therefore addresses before the base; it does not select array index 65,535.

### Ownership and resources

No allocation, deallocation, ownership transfer, or retained registration is evidenced.

The function reads and mutates caller-supplied storage. This does not establish who owns that storage or who must eventually release it.

## Acceptance examples

The following examples are conditional static expectations, not runtime test results. Unless stated otherwise, they assume stable request storage, nonoverlapping descriptor and array storage, sufficient accessible memory, and ordinary aligned 16-bit and 32-bit accesses.

### Request exceeds the limit

Given a current extent of 2, a limit of 4, and a request of 5:

- The return value is `0x00000010`.
- The current extent and array contents are unchanged.
- No array access is required by this path.

### Expansion clears newly included words

Given a current extent of 2, a limit of at least 5, and a request of 5:

- Array indices 2, 3, and 4 are first written as zero, in that order.
- The current extent becomes 5.
- Index 4 is then written as `0x40000000`.
- Indices 0 and 1 retain their values.
- The return value is zero.

This example also demonstrates that the final newly included word receives two writes.

### Unchanged extent still rewrites the marker

Given a current extent and request both equal to 3, with a sufficient limit, and word 2 initially equal to `0xA1234567`:

- No words are cleared.
- The current-extent field is written with 3.
- Word 2 becomes `0x61234567`.
- The return value is zero.

The high bit is cleared, the next-highest bit is set, and the low 30 bits are preserved.

### Shrinking leaves later storage intact

Given a current extent of 5, a limit of at least 3, and a request of 3:

- No words are cleared.
- The current extent becomes 3.
- Word 2 receives the marker transformation.
- Words 3 and 4 are unchanged.

No release or destruction of the removed logical range occurs in the supplied behavior.

### Zero request reaches before the base

Given a request of zero and a valid readable/writable 32-bit word immediately before the array base:

- The admission comparison succeeds for every possible unsigned 16-bit limit.
- The clearing loop performs no writes.
- The current extent becomes zero.
- The preceding word receives the marker transformation.
- The return value is zero.

If that preceding word is inaccessible, a normal return is not established. The function supplies no special zero-request error.

### Maximum request

Given a current extent of 65,534, a limit of 65,535, and a request of 65,535:

- Word 65,534 is cleared.
- The loop stops when the index reaches 65,535.
- The current extent becomes 65,535.
- Word 65,534 becomes `0x40000000`.
- The return value is zero.

No index wrap occurs in this stable-input example.

### Existing extent above the limit

Given a current extent of 9, a limit of 4, and a request of 3:

- Admission succeeds because only the request is compared with the limit.
- No clearing occurs.
- The current extent becomes 3.
- Word 2 receives the marker transformation, assuming it is accessible.

The function does not reject the inconsistent initial descriptor.
