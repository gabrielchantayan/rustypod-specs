# F-16ea63117549

## Purpose

F-16ea63117549 updates a one-byte field in caller-supplied storage and, for two exact input values, sets the immediately following byte to one.

The established behavior is asymmetric: the first byte is always written; the second byte is written only when the original value argument equals 2 or 3. Other values do not clear or otherwise update the second byte. In particular, matching the byte representation of 2 or 3 after narrowing is insufficient to trigger the second write.

The interpretation of these bytes as a mode, status, flag, or other application-level concept is unknown. Such interpretations are not part of this contract.

## Behavior

### Unconditional first-byte update

The routine first writes one byte at offset 0xB8.

The stored value is obtained by converting the value argument to the character-sized type shown in the supplied representation. The destination’s previous contents do not affect the result and are not explicitly read.

For values representable by that character-sized type, the numeric conversion is direct. For values outside its representable range, the exact conversion rule depends on the target’s character signedness and conversion semantics. Under conventional eight-bit truncating target semantics, the stored bit pattern is the low eight bits of the input. That target-specific interpretation must not be mistaken for an independently established ABI fact.

No masking, range check, rejection, or error return is shown.

### Conditional second-byte update

After the first write, the routine evaluates whether the original value argument equals 2 or 3.

- If either equality holds, it writes numeric one as a single byte at offset 0xB9.
- Otherwise, it performs no access to offset 0xB9 in the supplied body.

The condition is not based on reading back offset 0xB8, and it is not based on the narrowed value. An input that narrows to the same byte as 2 or 3 does not qualify unless the original integer itself equals 2 or 3.

When the conditional write occurs, it is an overwrite, not a bitwise update. Any previous contents of the second byte are replaced by one.

When the condition is false, the routine preserves the second byte in the limited sense that it performs no write there. Its contents are not necessarily zero, valid, or initialized.

### Ordering and repeated calls

The supplied body places the first-byte write before the equality-controlled second-byte write. For qualifying inputs, this is a two-write update, not a single atomic replacement of a two-byte value.

The routine provides no locking, publication barrier, rollback, or transactional guarantee. Compiler and hardware visibility to concurrent observers are not established by the supplied representation.

Repeated successful calls behave as follows, assuming no external modification:

- Each call replaces the first byte.
- A call with value 2 or 3 sets the second byte to one.
- A later call with any other value does not undo that second-byte setting.

This persistence follows from the absence of a nonqualifying-path write; it does not establish that the second byte is intended to be a permanent latch.

### Invalid storage and interrupted execution

There is no explicit null check, bounds check, permission check, or error-reporting path.

If the required storage is invalid, the outcome depends on the execution environment and is outside the normal-success contract. No particular exception, signal, return behavior, or diagnostic is established.

There is also no supplied recovery mechanism for failure during the conditional second write. The routine does not promise that the first write will be reverted. Exact fault visibility remains environment-dependent.

## Side effects

The routine explicitly modifies caller-supplied memory at the offsets listed above.

On normal completion:

- For value 2 or 3, it performs two one-byte writes.
- For every other value, it performs one one-byte write.
- No other explicit data-memory writes are shown.
- No explicit reads of either destination byte are shown.

No allocation, release, ownership transfer, address retention, callback, external call, or global-state access appears in the supplied body. The contract therefore assigns none of those operations to this routine. ## Acceptance examples

These are conditional specification examples, not executed tests. Unless stated otherwise, assume valid writable storage, successful address formation, normal completion, and no concurrent modification. Let the initial bytes at offsets 0xB8 and 0xB9 be A and B.

| Value argument | Final byte at 0xB8 | Final byte at 0xB9 | Required behavior |
|---:|---:|---:|---|
| 2 | 2 | 1 | Write the first byte, then write one to the second |
| 3 | 3 | 1 | Same two-write behavior |
| 0 | 0 | B | Do not clear the second byte |
| 1 | 1 | B | Leave the second byte untouched |
| 4 | 4 | B | Leave the second byte untouched |

Additional boundary and sequence examples:

1. **Previously set second byte.** With B equal to one and input zero, the final pair is zero and one. Treating the second byte as a Boolean expression that must become false for nonqualifying values would violate the contract.

2. **Previously noncanonical second byte.** With B equal to seven and input four, the final second byte remains seven. The routine does not normalize it.

3. **Repeated updates.** A successful call with value two followed by a successful call with value four leaves the first byte equal to four and the second byte equal to one.

4. **Narrowing does not control the branch.** If the value argument can represent 258 and the target uses eight-bit low-bit truncation, input 258 stores byte value two at offset 0xB8 but leaves offset 0xB9 unchanged. Input 259 analogously stores byte value three without triggering the second write.

5. **Unused second location.** For a nonqualifying value, the supplied body performs no access at offset 0xB9. An acceptance requirement that every call explicitly validate or touch that location would add behavior absent from the evidence.
