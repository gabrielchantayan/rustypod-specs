# F-25f41314de41

## Purpose

F-25f41314de41 conditionally updates storage references and capacity fields in a descriptor reached through an enclosing object. It uses a requested increment and two signed descriptor components to decide whether to resize a primary group of regions. If its initial comparison permits further processing, it also checks a secondary region using a separate pair of signed components.

The established behavior is an ordered sequence of reads, dependency calls, reference replacements, status checks, and capacity writes. The operation is not atomic. A dependency result is stored before its status is checked, and later failure does not roll back earlier writes.

Coordinated storage reservation is an inferred purpose, not an established allocation contract. The resource represented by each reference, the meaning of each numeric region parameter, and the purpose of final maintenance remain unknown.

## Interface

### Inputs

The function receives two 32-bit values:

- **Object address:** used to locate an enclosing object.
- **Requested increment:** interpreted as an unsigned 32-bit quantity in the primary-demand calculation.

If the requested increment is zero, the function returns without accessing the object.

Otherwise, it reads a 32-bit descriptor address from byte offset `0x0C` of the object. All descriptor offsets below are relative to that captured address.

### Output

The result is a 64-bit value containing two 32-bit words:

- **High word:** initially the requested increment. Immediately before each resizing call, it is replaced with the storage reference supplied to that call.
- **Low word:** zero on an early return; otherwise, the bit pattern read from a local 32-bit status location at return.

The high word is not the dependency’s returned replacement reference. When resizing occurs, it is the reference supplied to the last resizing call reached.

The status location is initialized once to zero and passed by address to every resizing call. It is not reset between calls. A nonzero observed status terminates resizing processing.

Final maintenance precedes the final status read on paths that reach it. Consequently, zero status at the last resizing check does **not** establish a zero low return word: a resizing dependency might retain the status address and arrange for it to be modified during final maintenance. No supplied dependency contract excludes that behavior.

## Behavior

### Arithmetic and comparisons

Each signed 16-bit component is sign-extended before addition. The sum of two components lies between −65,536 and 65,534 and fits in signed 32 bits.

Primary demand adds the unsigned requested increment to the two-component sum, producing a 32-bit word modulo \(2^{32}\). Alignment additions also wrap modulo \(2^{32}\).

Two different primary comparisons are required:

1. The initial comparison interprets primary demand and primary capacity as signed 32-bit values.
2. The later growth comparison interprets both as unsigned 32-bit values.

These comparisons are not interchangeable. A path can pass the initial test for further processing yet skip primary growth.

Secondary demand is the sum of its two signed components, interpreted as an unsigned 32-bit word for comparison. A negative sum therefore becomes a large unsigned demand.

### 1. Early exit

A zero requested increment produces a zero 64-bit result. There is no object read, descriptor access, or dependency call.

For a nonzero increment, the function obtains the descriptor address and computes primary demand using the fields at `0x16` and `0x36`.

If signed primary demand is less than or equal to signed primary capacity at `0x04`, it returns immediately:

- High word: original requested increment.
- Low word: zero.
- No dependency calls.
- No descriptor writes.
- No secondary-demand or secondary-capacity check.

Secondary storage is therefore not independently examined on every invocation.

### 2. Prepare further processing

If the signed comparison does not cause an early return, the function:

- Captures the context at `0x00`.
- Initializes the local status to zero.
- Reads primary capacity again.
- Recomputes primary demand using the original requested increment.
- Records locally that no primary-capacity update has completed.

The repeated descriptor reads are real accesses; the values used in this phase are not necessarily the values used by the early comparison.

The captured context, old primary capacity, and subsequently computed primary target are retained across primary resizing calls. They are not refreshed between those calls.

### 3. Primary growth

If captured primary capacity is at least recomputed primary demand under unsigned comparison, all primary resizing is skipped.

Otherwise, the primary target is obtained by adding seven to demand modulo \(2^{32}\), then clearing the lowest three bits. Without wraparound, this rounds demand upward to a multiple of eight. Wraparound is neither rejected nor corrected.

Primary resizing proceeds in this order.

#### First mandatory region

The function reads the reference at `0x18`, captures it as the high return word, and calls F-6dd003795db7 with:

- Captured context.
- Numeric parameter `8`.
- Captured old primary capacity.
- Aligned primary target.
- Reference read from `0x18`.
- Address of the local 32-bit status.

It stores the dependency’s 32-bit result at `0x18`, then checks status. A nonzero status causes immediate return.

#### Second mandatory region

If the first status check observes zero, the function reads `0x1C` and uses that reference as the new high return word.

It calls F-6dd003795db7 with the same captured context, old capacity, and target, but numeric parameter `1`. It stores the result at `0x1C` before checking status.

A nonzero status causes immediate return. The conditional-region flag and secondary region are not subsequently examined.

The second reference is read after the first dependency call and its result store. It is not an advance snapshot.

#### Conditional region

After both mandatory checks observe zero, the function reads the byte at `0x10`.

If it is zero, no reference is read from `0x28` and no call is made for that region.

If it is nonzero, the function reads `0x28`, updates the high return word, and calls F-6dd003795db7 with numeric parameter `8`, the captured context and old capacity, the primary target, that reference, and the same status address.

It stores the result at `0x28` before checking status. Nonzero status causes immediate return.

#### Primary-capacity commit

Only after every required primary call has an observed zero status does the function record primary completion and store the aligned target at `0x04`.

There is no rollback if a previous call replaced a reference and a later call reports nonzero status.

### 4. Secondary processing

Unless an earlier status check returned, the function reads secondary capacity at `0x08` and the signed components at `0x14` and `0x34`.

If unsigned secondary capacity is less than unsigned secondary demand, it:

1. Reads the reference at `0x20`, making it the high return word.
2. Recomputes the secondary component sum for target calculation.
3. Adds three modulo \(2^{32}\) and clears the lowest two bits.
4. Calls F-6dd003795db7 with the captured context, numeric parameter `2`, secondary capacity read for the call, computed target, captured secondary reference, and status address.
5. Stores the dependency result at `0x20`.
6. Checks status and returns immediately if nonzero.
7. Otherwise stores the target at `0x08`.

Without overflow, the target rounds demand upward to a multiple of four. The comparison and target calculation use separate component reads. Secondary capacity is also read for the call rather than guaranteed to reuse the comparison value.

The secondary call uses the context originally captured before primary processing. It does not reload context from the descriptor.

If no secondary growth is required and primary completion was not recorded, the function returns without final maintenance.

### 5. Final maintenance and return

F-eafa9af4344c is called once with the captured descriptor address if either:

- Primary-capacity update completed; or
- Secondary-capacity update completed.

An observed nonzero resizing status prevents this call. Its return value is ignored.

After maintenance returns, this function reads the local status for the low result word. There is no subsequent status-based branch or rollback. A nonzero final status is therefore possible without having been observed by a resizing status check, if dependency behavior permits modification during maintenance.

## Side effects

### Direct writes

Depending on the path, the function writes replacement references at `0x18`, `0x1C`, `0x28`, and `0x20`, and capacities at `0x04` and `0x08`.

Every replacement reference is written before its associated status check. Capacity writes occur only after the required checks observe zero.

Failure paths can therefore include:

- One mandatory primary-reference replacement without a primary-capacity write.
- Two mandatory replacements without a primary-capacity write.
- Three primary-reference replacements without a primary-capacity write.
- A completed primary-capacity write followed by a secondary-reference replacement and nonzero status.
- A secondary-reference replacement without a secondary-capacity write.

These describe this function’s own writes. They do not guarantee that a capacity or other field remains unchanged: dependencies may independently modify descriptor memory.

### Ownership and dependency access

No explicit resource-release operation appears in this function. It overwrites reference fields with dependency results but does not establish whether either old or replacement references represent allocations, borrowed storage, handles, or another resource.

No guarantee is established that F-6dd003795db7 preserves old storage on failure, frees it on success, copies contents, or returns a usable reference when status is nonzero.

Neither dependency is known to preserve descriptor fields, global state, or resources. Reads after a dependency call use then-current descriptor memory, except for values already captured locally.

The status address is exposed to resizing calls. Its retention and use during the remainder of this invocation are not ruled out. Retention beyond the invocation is not a promised lifetime extension.

No synchronization is visible; safe concurrent use is not established.

## Acceptance examples

These are conditional deductions from static evidence, not runtime observations. Unless stated otherwise, descriptor fields remain stable except for this function’s specified writes, dependencies return normally, and resizing calls produce the stated status values.

### Zero increment

With increment zero, even an unusable object address is not dereferenced.

Expected: result zero, no descriptor accesses, and no dependency calls.

### Sufficient primary capacity suppresses secondary checking

With increment `1`, primary components `8` and `7`, and primary capacity `16`, signed demand equals capacity.

Expected: high word `1`, low word zero. Secondary capacity is not examined, even if it would be insufficient.

### Successful mandatory primary growth

With increment `1`, primary components `8` and `8`, capacity `16`, conditional byte zero, and sufficient secondary capacity:

- Primary target is `24`.
- Calls occur for `0x18` with parameter `8`, then `0x1C` with parameter `1`.
- If both checks observe zero, primary capacity is written as `24`.
- Final maintenance runs once.
- High word is the reference supplied to the second call, not its returned replacement.

The final low word is unspecified without an additional dependency assumption. If no dependency modifies status after the last zero check, it is zero.

### Second primary call reports failure

Under the preceding growth inputs, let the second call leave status `5`, with no subsequent modification before return.

Expected: both mandatory reference results are stored; this function does not write primary capacity; it does not inspect the conditional byte, process secondary storage, or call maintenance. The result contains the second supplied reference as high word and `5` as low word.

### Primary and secondary growth

After successful primary growth, let secondary components be `2` and `3`, with capacity `4`.

Expected: secondary demand `5`, target `8`, and a call using parameter `2`. Its reference result is stored first. If the status check observes zero, secondary capacity becomes `8` and maintenance runs once.

### Maintenance changes exposed status

Suppose resizing checks all observe zero, but a resizing dependency retained the status address and maintenance causes that location to contain `9`.

Expected: completed capacity writes are not rolled back; maintenance returns; the low return word is `9`. No additional failure branch runs.

This case documents permitted uncertainty, not an assertion that either dependency actually behaves this way.

### Signed early bypass

Expected: immediate return with high word `0x80000000` and low word zero, despite the large unsigned demand.

### Failed early comparison without growth

### Wrapping targets

Separately, if secondary processing is reached with components `−1` and `0` and capacity `0`, unsigned demand is `0xFFFFFFFF`; its aligned target also wraps to zero.

Expected: zero is passed as the applicable target. Whether that argument is acceptable to the dependency is unknown.
