# F-3444622fad17

## Purpose

F-3444622fad17 adjusts a position associated with a caller-supplied state record. It accepts a displacement and an origin selector, computes a nonnegative target, and represents that target either through an existing buffered region or through a separately stored position.

The established behavior includes:

- Rejecting state whose flags have neither of the two lowest bits set.
- Calling a preliminary dependency before interpreting the origin selector.
- Supporting origin selectors 0, 1, and 2.
- Consulting an external position or extent for selector 2.
- Returning a 32-bit status of 0, 1, or 2.
- Updating cursor, count, position, and flag fields on accepted operations.

A seek-like operation on a buffered object is inferred intent, not an established interface name or a guarantee of compatibility with any particular I/O API.

## Behavior

### 1. Entry and preliminary checks

The function first reads and saves the 32-bit field at offset 20.

It then reads the flags at offset 12. If neither bit `0x1` nor bit `0x2` is set, it returns 2 immediately. The read at offset 20 therefore precedes even this early rejection.

Otherwise, it calls F-fb3ef5873263 with no explicit arguments. Its result is represented as a 64-bit value:

- A nonzero low 32-bit half causes an immediate return of 2.
- A zero low half allows processing to continue.
- The high half has no eventual effect on this function’s output or direct state updates.

This dependency runs before selector validation. An unsupported selector can therefore still cause dependency side effects.

No preservation of the state record, globals, or other memory across this dependency is established. Later field reads use the state visible after the call. The saved offset-20 value remains the value captured before the call.

### 2. Target calculation

#### Selector 0: direct target

The displacement itself becomes the target. No origin-relative addition is performed.

#### Selector 1: current-position-relative target

The function examines flag `0x20`.

- If clear, it derives a current position from the cursor at offset 4, the buffered-region position at offset 24, and the reference at offset 16:

  **current position = cursor + buffered-region position − reference**

- If set, it uses the separate position at offset 40 instead.

It then reads the flags again for bit `0x80000`. If that bit is set and the derived current position is strictly positive as a signed value, it subtracts one from that position.

The displacement is then added to the resulting current position to form the target.

The one-unit adjustment applies to the derived position before adding the displacement. It does not apply merely because the eventual target is positive.

#### Selector 2: external-extent-relative target

The function calls F-29c47234b7bc with the offset-20 value saved at entry.

After that call returns, it reads the flags, saves that flag value locally, and immediately stores the same flags with `0x10` set.

If the dependency result is negative as a signed 32-bit value:

1. F-b66fa5cebc4a is called with the state-record pointer.
2. The function returns 1.
3. No common target-placement processing occurs.

The cleanup dependency receives the record after the `0x10` store. Its effects, including any change to that flag, are unknown.

For a nonnegative dependency result, the function computes a buffered extent:

- Select the unsigned maximum of the high-water value at offset 44 and the cursor at offset 4.
- Add the buffered-region position at offset 24.
- Subtract the reference at offset 16.

If the flags saved immediately after the dependency call had `0x20` set, the separate position at offset 40 is also considered. It replaces the buffered extent only when it is strictly larger under signed comparison.

The resulting extent is compared with the nonnegative dependency result as signed 32-bit values. The larger becomes the selector-2 origin position. Adding the displacement produces the target.

Thus selector 2 does not necessarily use the external result alone: buffered or separately stored state can raise the origin position.

#### Other selectors

Any selector other than 0, 1, or 2 returns 2 after the preliminary dependency succeeds.

### 3. Negative-target rejection

After target calculation, the function rejects a target that is negative as a signed 32-bit value, returning 2.

This rejection occurs before the common high-water and position-placement updates. For selector 2, however, the external dependency and the earlier `0x10` flag store have already occurred.

There is no separate arithmetic-overflow error. An arithmetic result whose final 32-bit signed interpretation is negative is rejected here; a wrapped result that remains nonnegative can continue.

### 4. High-water reconciliation

For a nonnegative target, the function reads the current flags and cursor.

If the high-water field is unsigned-less-than the cursor:

- It writes the cursor into the high-water field.
- If the flags contain `0x20000`, its pending final flag value clears `0x20000` and sets `0x10`.

This flag transformation is initially local. Unlike selector 2’s earlier `0x10` store, it is not written to the record until final flag publication.

The high-water comparison is unsigned. A value with its top bit set is therefore ordered differently here than it would be under signed comparison.

### 5. Choosing the target representation

The function attempts an in-buffer representation only if the buffered-region position is signed-less-than-or-equal-to the target.

For that attempt, it obtains:

- The reference at offset 16.
- The unsigned maximum of the cursor and the current high-water field.
- A derived buffered endpoint equal to that maximum plus the buffered-region position minus the reference.

The selected strict upper boundary depends on the target:

- If the target is greater than the derived buffered endpoint, that endpoint is the boundary.
- If the target is less than or equal to the endpoint, the boundary is the buffered-region position plus the capacity-like field at offset 48.

The in-buffer representation is accepted only when this selected boundary is **strictly greater** than the target under signed comparison.

In particular, equality with the capacity-derived boundary is not accepted as in-buffer. The capacity field is not consulted on every path.

### 6. In-buffer update

For an accepted in-buffer target, the function first expresses the target relative to the buffered-region position.

Unless flag `0x1000000` was set in the flags read at the start of common processing, it updates count fields in this order:

1. **Offset 8:** set to relative target minus the selected boundary contribution when bit `0x2` is set and neither `0x200` nor `0x400` is set; otherwise set to zero.
2. **Offset 0:** set to relative target minus the difference between the unsigned-selected cursor/high-water value and the reference when bit `0x1` is set and `0x400` is clear; otherwise set to zero.

For an accepted in-buffer path, the boundary contribution used for offset 8 is the capacity-like value at offset 48.

If `0x1000000` is set, both count fields are left untouched by this function.

It then:

- Clears `0x20` in the pending flags.
- Writes the cursor at offset 4 as reference plus relative target.
- Leaves the separate position at offset 40 unchanged.
- Publishes the final flags as described below.
- Returns 0.

### 7. Separate-position update

If the in-buffer test is not accepted:

- Unless `0x1000000` is set, offset 8 is written as zero, followed by offset 0 as zero.
- `0x20` is set in the pending flags.
- The target is written to offset 40.
- The cursor at offset 4 is not directly changed on this path.
- Final flags are published.
- The function returns 0.

### 8. Final flag publication

Both successful placement paths store the pending flags ANDed with `0xffd7cfbf`.

This final mask clears:

- `0x40`
- `0x1000`
- `0x2000`
- `0x80000`
- `0x200000`

Other bits survive except for the earlier conditional transformations of `0x20`, `0x20000`, and `0x10`.

## Acceptance examples

These examples are conditional on valid storage, the stated dependency results, and no unmentioned dependency mutations. Ordinary numeric examples avoid overflow.

1. **Initial rejection.**  
   If flags have both `0x1` and `0x2` clear, the result is 2. The offset-20 read still occurs; none of the three dependencies is called.

2. **Preliminary rejection precedes selector handling.**  
   With qualifying initial flags, if F-fb3ef5873263 returns a nonzero low half, the result is 2 regardless of selector. F-29c47234b7bc is not called.

3. **Unsupported selector.**  
   Selector 3 returns 2 after a successful preliminary dependency. No common high-water or placement writes occur.

4. **Current-position adjustment.**  
   For selector 1, suppose `0x20` and `0x80000` are set, the separate position is 10, and displacement is −3. The target is 6. If the separate position is zero instead, no one-unit subtraction occurs.

5. **External failure is not write-free.**  
   For selector 2, a negative F-29c47234b7bc result causes a store setting `0x10`, then a call to F-b66fa5cebc4a, then return 1. Final flags after that dependency are not specified by this function alone.

6. **Buffered extent can exceed the external result.**  
   For selector 2, suppose the external result is 100, the derived buffered extent is 120, `0x20` is clear, and displacement is 5. The target is 125, not 105.

7. **Strict capacity boundary.**  
   Suppose the buffered-region position is 100, the reference is 1000, cursor and high-water are both 1008, and capacity is 16. A direct target of 107 is accepted in-buffer and writes cursor 1007. A direct target of 116 is not accepted in-buffer and instead stores 116 at offset 40 with `0x20` set.

8. **Count preservation.**  
   With `0x1000000` set, a successful operation leaves offsets 0 and 8 untouched by this function, while still performing applicable high-water, cursor or separate-position, and flag writes.

9. **High-water flag transition.**  
   If the cursor exceeds high-water under unsigned comparison and `0x20000` is set, a successful completion advances high-water, clears `0x20000`, and sets `0x10`.
