# F-4ed56e8b59b4

## Purpose

F-4ed56e8b59b4 dispatches input processing according to a one-byte descriptor kind. Its observable behavior includes dependency calls, destination initialization, private and caller-visible cursor updates, optional callback events, temporary input modification, and failure diagnostics.

The function is not transactional. Failure does not establish that input positions, destination contents, dependency state, or callback effects have been restored.

“Sequence,” “alternative,” “classification,” and “initialization” are inferred roles for the established operations. They do not define an external input format or establish dependency-internal behavior.

## Behavior

### Initial reads and retained addresses

For a nonnull destination slot, nonzero metadata causes metadata `+16` to be read and retained as the optional event callback. This occurs before reading the kind discriminator. An unsupported kind returns `0` without failure reporting, but not before these initial metadata accesses.

The initially obtained metadata address is retained:

- Kind 1 later reads flags from that address after its preliminary dependency call.
- Kind 3 later loads its handler from that address after any preliminary call and temporary-byte write.
- Kind 4 loads its handler from that address.

These accesses do not reread descriptor `+16`. The captured event callback also is not refreshed before events `4` or `5`. Kind 4 nevertheless performs its own handler load from metadata `+16`, rather than using the captured callback value.

### Kind 0: delegation

Descriptor `+8` controls the path:

- Zero: call F-070f1d04f181 with all eight arguments and return its result unchanged.
- Nonzero, selector `−1`, and mode zero: call F-9853388f4d99 with the destination slot, caller cursor slot, original extent, descriptor `+8` value, zero mode, and context. Return its result unchanged.
- Otherwise: ordinary failure with type-only diagnostics.

The second delegation does not receive the auxiliary value.

### Kind 1: sequence processing

The caller cursor is copied into a private cursor. Selector `−1` is replaced with `16`, and the auxiliary value is then replaced with zero.

F-38f7a73546d9 receives the private cursor address, original extent, effective selector, auxiliary value, mode, and context. It also receives output addresses for working extent, a 32-bit framing value, and a four-byte status area; its other two output positions are null.

Its result determines continuation:

- Zero: ordinary type-only failure.
- `0xFFFFFFFF`: immediate return of that value.
- Any other value: continue.

If the retained metadata address is nonzero, flags are now read at its `+4`. With flag `0x4` set, working extent becomes original extent minus the displacement between the private cursor and the **then-current** caller cursor, and a separate completion-permission value becomes `1`. Otherwise, permission becomes the low eight bits of the framing value.

Entry checks then occur in this order:

1. Require a nonzero first status byte.
2. Inspect the destination word. If zero, require a nonzero result from F-a02344ca9fe7, supplied with destination slot and descriptor.
3. If an event callback was captured, require a nonzero result from its event-`4` invocation with destination slot and descriptor.

Failure is ordinary and type-only. Only after these checks is descriptor `+8` read as the table base. That address advances locally thereafter; descriptor `+8` is not reloaded for each field.

#### Consuming fields

A signed index starts at zero. Each loop condition rereads descriptor `+12` and compares the index with that signed count.

For each entered iteration:

- F-23eebec8340f receives destination slot and current table address. A zero resolution result causes **unmarked, type-only** failure.
- F-50a87c4da87c receives destination slot and resolved field, yielding the field destination.
- The current private cursor is retained as the displacement baseline.
- Working extent is checked. If zero, consuming stops without advancing the index or table address. Resolution and destination derivation have already occurred.
- F-04d7b0f7c6e9 is called with the private cursor address.

If this cursor check returns nonzero:

- A zero low framing byte causes ordinary type-only failure.
- Otherwise, cursor displacement is subtracted from working extent, the entire framing value is cleared, and processing proceeds directly to completion-permission checking and remaining-field handling. The later framing check is bypassed.

If the cursor check returns zero, F-9853388f4d99 receives the field destination, private cursor address, working extent, resolved field, field mode, and context. Field mode is zero when a fresh descriptor-count read minus one equals the current index; otherwise it is the field’s low flag bit.

Its result is handled as follows:

- Zero: **unmarked failure with the resolved field as diagnostic context**.
- Signed `−1`: call F-a8ecb9fc98cf with field destination and field; do not locally subtract displacement.
- Any other nonzero result: subtract displacement from working extent.

For this subtraction, displacement includes any cursor movement made by the preceding cursor check. After a completed iteration, the table address advances by 20 bytes and the index increments.

#### Completion

On ordinary exit from the consuming loop, a nonzero low framing byte requires a nonzero result from F-04d7b0f7c6e9, now supplied with private cursor address and working extent. Rejection is ordinary type-only failure.

Completion then requires nonzero permission or exactly zero working extent. Negative extent does not satisfy the latter condition. Rejection is ordinary type-only failure.

Remaining fields start at the current index and table address. Each iteration uses a fresh signed count read:

- Resolve through F-23eebec8340f with destination slot, table address, and additional argument `1`.
- Zero resolution causes unmarked type-only failure.
- A clear low flag bit causes ordinary failure with that resolved field as context.
- Otherwise derive the field destination and call F-a8ecb9fc98cf.
- Advance the table address by 20 bytes and increment the index.

Finally, F-8d8a7f2b862f receives destination slot, the caller’s then-current input address, private-cursor displacement from that address, and descriptor. Zero causes ordinary type-only failure; nonzero reaches shared success.

### Kind 2: alternative processing

Entry order differs from kind 1:

1. Invoke captured event `4`, if present, requiring nonzero.
2. Inspect the destination word and, if zero, require successful F-a02344ca9fe7.

Entry failure is ordinary and type-only.

After entry, copy the caller cursor into a private cursor and read descriptor `+8` once as the alternative-table base. A signed index starts at zero. Loop conditions reread descriptor `+12`.

For each entered iteration:

- Derive an alternative destination through F-50a87c4da87c.
- Call F-9853388f4d99 with that destination, private cursor address, working extent, current alternative, mode `1`, and context.
- Signed `−1` advances the table address by 20 bytes and increments the index.
- Any other signed result below `1` causes ordinary failure with the current alternative as diagnostic context.
- A positive signed result breaks the loop without incrementing the index.

There is no local cursor restoration between attempts and no local extent reduction. Later attempts receive the current private cursor and unchanged locally held extent.

**Post-loop selection depends on a fresh count comparison, not directly on a positive result.** The function rereads descriptor `+12`:

- Count unequal to current index: call F-439afd1f5b71 with destination slot, index, and descriptor; ignore its result; reach shared success.
- Count equal to current index: treat as exhaustion. Nonzero mode calls F-bd0a5082b3f8 and returns `0xFFFFFFFF`; zero mode causes ordinary type-only failure.

Consequently, dependency changes to the count can turn a positive-result break into exhaustion, or permit success after an exit without a positive result. No local check establishes that the post-loop index identifies an actually successful or in-range alternative.

### Shared success for kinds 1 and 2

Write the private cursor into the caller cursor slot. Then:

- No captured callback: return `1`.
- Event-`5` callback returns nonzero: return `1`.
- Event-`5` callback returns zero: ordinary type-only failure.

Cursor publication precedes the callback. No local rollback follows rejection. The callback and failure dependencies may themselves modify the cursor slot.

### Kind 3: indirect handler and temporary byte

When mode is nonzero, copy the caller cursor into a private cursor and call F-38f7a73546d9 with no output addresses except that cursor address. Supply original extent, auxiliary value, forced mode `1`, and context. Its selector is the supplied selector unless that equals `−1`, in which case descriptor `+4` is read and used.

A zero result causes ordinary type-only failure. Signed `−1` returns `0xFFFFFFFF`. Other results continue. The preliminary private cursor is not published and does not locally reduce the handler’s extent.

If the original selector is not `−1`, reread the caller cursor, save that address and its byte, and write a replacement byte equal to the original byte’s `0x20` bit OR the low byte of descriptor `+4`.

Next, load the handler at retained metadata address `+8` and invoke it with destination slot, caller cursor slot, and original extent. Descriptor `+16` is not reread.

After normal handler return, restore the saved byte at the saved address, regardless of changes to the caller cursor. A nonzero handler result becomes `1`; zero causes ordinary type-only failure. Restoration is not established for faults or nonlocal exits. Metadata and handler presence are not checked.

### Kind 4: unrestricted delegation

Load the handler at retained metadata address `+16`, invoke it with all eight arguments, and return its result unchanged. Neither metadata nor handler presence is checked on this path.

### Kind 5: classification gate

Copy the caller cursor into a private cursor. F-38f7a73546d9 receives output addresses for a 32-bit classification and four-byte status area, the private cursor address, original extent, selector `0xFFFFFFFF`, auxiliary zero, mode `1`, and context. Its other output positions are null.

Zero causes ordinary type-only failure. Every nonzero result, including `0xFFFFFFFF`, continues.

If the first status byte is zero, call F-9f826953b442 with the classification. **After that call returns**, read descriptor `+4` and intersect it with the returned bits.

A nonzero intersection delegates to F-070f1d04f181 with destination slot, original caller cursor slot, original extent, descriptor, classification as selector, auxiliary zero, mode zero, and context. Return its result unchanged.

If status or mask rejects classification, nonzero incoming mode returns `0xFFFFFFFF`; zero mode causes ordinary type-only failure. The preliminary private cursor is not locally published.

## Side effects

### Failure reporting

Ordinary failure first calls F-4fc89ec41a6d with `13` and `120`, then enters common failure. Unmarked failure skips that first call.

Common failure:

1. Calls F-bd0a5082b3f8 with destination slot and descriptor.
2. Reads diagnostic values and calls F-968c88301966.
3. Returns `0`.

Diagnostic selection is:

| Failure edge | Marker | Context |
|---|---|---|
| Kind-1 field resolution, either phase | No | Type only |
| Kind-1 field processing returns zero | No | Resolved field |
| Kind-1 remaining field has clear low flag bit | Yes | Resolved field |
| Other kind-1 ordinary failure, including cursor checks, completion, and event `5` | Yes | Type only |
| Kind-2 non-retry processing result below `1` | Yes | Current alternative |
| Other kind-2 ordinary failure, including event `5` | Yes | Type only |
| Ordinary failures in kinds 0, 3, and 5 | Yes | Type only |

Type-only reporting supplies count `2`, a type-label value, and descriptor `+24`. Field reporting supplies count `4`, a field-label value, field or alternative `+12`, a type-label value, and descriptor `+24`.

These record values are read after F-bd0a5082b3f8. Their preservation or continued accessibility is not established.

## Acceptance examples

These are conditional static expectations, not runtime observations. Assume valid storage and no dependency mutations except those stated.

1. **Early null check:** A readable descriptor and null destination slot produce `0`, after reading descriptor `+16` but without dereferencing metadata.

2. **Unchanged delegated result:** Kind 0 with nonzero descriptor `+8`, selector `−1`, and mode zero returns `7` if F-9853388f4d99 returns `7`.

3. **Retained metadata:** If a kind-1 preliminary call changes descriptor `+16` from address A to B, flags are nevertheless read from A. The analogous kind-3 handler load uses A.

4. **Retained table, live count:** If a kind-2 processing call changes descriptor `+8`, retry still advances the retained table address by 20 bytes. A changed descriptor count affects the next loop condition and final comparison.

5. **Positive result becomes exhaustion:** At kind-2 index zero, processing returns positive but changes count to zero. The final equality takes exhaustion; F-439afd1f5b71 is not called.

6. **Success without a positive result:** With kind-2 count `−1`, the loop is skipped. The final unequal comparison against index zero calls F-439afd1f5b71 with zero and reaches shared success.

7. **Diagnostic distinctions:** Kind-1 field-processing zero reports that field without the marker. Field-resolution zero reports only the type without the marker. A remaining field with clear low flag bit reports that field after the marker.

8. **Post-callback rejection:** If shared success publishes address A and event `5` rejects it, failure reporting starts after that write. The diagnostic context is type-only.

9. **Temporary byte:** Kind 3 with non-sentinel selector, original byte `0xA5`, and descriptor low byte `0x02` writes `0x22` before the handler and restores `0xA5` at the saved address after normal return.

10. **Late classification mask:** If F-9f826953b442 changes descriptor `+4`, kind 5 tests the changed mask. A preliminary result of `0xFFFFFFFF` does not itself bypass this classification logic.
