# F-4517f195e857

## Purpose

F-4517f195e857 subtracts two equal-length sequences of unsigned words, propagating a borrow from lower-indexed words to higher-indexed words. It writes the resulting words into caller-provided storage and returns the final borrow encoded in a pointer-typed result.

The established behavior is forward, word-by-word subtraction with an initial borrow of zero. Interpreting the sequences as little-endian, multiword unsigned integers is inferred intent: index zero acts as the least-significant word. This interpretation concerns word significance, not byte order within a word.

A nonpositive count produces a zero return without accessing either source or the destination.

## Interface

The function has four inputs:

| Input | Role | Required properties when the count is positive |
|---|---|---|
| Destination | Address of the first result word | Writable storage for every word actually processed |
| First source | Address of the first minuend word | Readable storage for every word actually processed |
| Second source | Address of the first subtrahend word | Readable storage for every word actually processed |
| Count | Signed integer specifying the number of words | Positive values request exactly that many word operations |

The destination is presented through a signed-integer pointer type, while both sources are presented through unsigned-integer pointer types. The subtraction nevertheless uses unsigned source values and modular word arithmetic. The observable result is best specified as stored word bit patterns, not as signed decimal values.

The return is pointer-typed but is used as a borrow indicator:

- Zero means no final borrow, or no work because the count was nonpositive.
- The nonzero case is formed from the integer value one and means a final borrow of one.
- The return is not a destination pointer, allocation, or documented dereferenceable object.

### Width and layout

Let \(W\) be the width, in bits, of a source word, and let \(M=2^W\).

The supplied representation is consistent with 32-bit words and a 32-bit signed count. The underlying ABI and type definitions are not independently provided, so those exact widths are **inferred**, rather than independently established. The equations below specify the behavior in terms of \(W\); hexadecimal acceptance examples explicitly assume \(W=32\).

On that 32-bit interpretation:

- Each source and destination element occupies four bytes.
- Successive elements are four bytes apart.
- Source values range from zero through \(2^{32}-1\).
- A result word retains the low 32 bits of the subtraction.
- The count is interpreted as signed, not as an unsigned size.

The arrays are contiguous word sequences. No length metadata, stride, byte-order conversion, or terminator is consulted.

## Behavior

### Nonpositive count

If the count is less than one, the function returns zero.

On this path:

- Neither source is read.
- No destination word is written.
- No pointer validity check is performed.
- The destination argument is not returned.

Null or otherwise unusable data addresses therefore do not cause a data access on this path. This statement concerns the function’s body; it does not establish rules for how a surrounding language or calling environment constructs those arguments.

### Positive count

The function initializes an internal borrow to zero and processes exactly the requested number of words in increasing index order.

For each index \(i\), let:

- \(A_i\) be the unsigned value read from the first source at that index;
- \(B_i\) be the unsigned value read from the second source at that index;
- \(b_i\) be the incoming borrow, either zero or one.

The stored result is:

\[
R_i=(A_i-B_i-b_i)\bmod M.
\]

The outgoing borrow is:

\[
b_{i+1}=
\begin{cases}
1 & \text{if } A_i<B_i,\\
0 & \text{if } A_i>B_i,\\
b_i & \text{if } A_i=B_i.
\end{cases}
\]

Comparisons between the two source words are unsigned.

The equality case is important. Equal source words do not necessarily clear the borrow:

- Equal words with an incoming borrow of zero produce a zero result and leave the borrow clear.
- Equal words with an incoming borrow of one produce an all-ones result and retain the borrow.

The borrow decision uses the two source values already read for the current word. It does not reread the destination or derive the borrow from a signed interpretation of the stored result.

After the final requested word is stored, the function returns the resulting borrow through its pointer-typed return value.

### Observable access order

For each processed word, the established access order is:

1. Read the current word from the first source.
2. Read the current word from the second source.
3. Write the current destination word.

These operations complete for the current word before the next word’s source reads begin. The function does not first snapshot either complete source sequence.

Consequences include:

- A destination write can alter a source value that will be read at a later index.
- Both current source values are read before the current destination write.
- Neither source is read beyond the requested count.
- No result word beyond the requested count is written.

The processing is organized internally in groups of up to four words. Within each group, count checks prevent accessing an unrequested next word. Continuing groups advance all three data positions by four elements.

This grouping does not change the forward access order or the subtraction rule. In particular, counts of one, two, and three do not require storage for a complete four-word group.

For a positive signed count, the observed count decrements remain representable: the small decrements used to decide whether another word is needed do not require signed wraparound.

### Multiword interpretation

If each source is stable during the operation, including freedom from destination writes that change unread source words, define:

\[
A=\sum_{i=0}^{n-1} A_iM^i,\qquad
B=\sum_{i=0}^{n-1} B_iM^i.
\]

Then the destination represents:

\[
R=(A-B)\bmod M^n.
\]

The returned borrow is one exactly when \(A<B\).

This whole-number interpretation is conditional on source stability. With destructive partial overlap, the individual word reads and writes remain the relevant behavioral description; subtraction of the source arrays’ original contents is not guaranteed.

## Side effects

### Memory writes

For a positive count \(n\), the function writes one word at each destination index from zero through \(n-1\), in that order.

It does not explicitly clear, initialize, or modify any additional destination words. If destination storage overlaps source storage, the destination writes also modify the corresponding source storage.

### Aliasing and overlap

No overlap detection or rejection is present.

At the algorithmic level, exact in-place operation is compatible with the access order:

- The destination may start at the first source’s address.
- The destination may start at the second source’s address.
- All three addresses may be equal.

For these cases, the two current source words are read before the current word is overwritten. This does not establish language-level aliasing or alignment guarantees absent from the supplied evidence.

Partial overlap requires more care. A destination positioned ahead of a source can overwrite an unread source word. That changed value is then used when its turn arrives. There is no temporary full-source copy and no reverse traversal to preserve original contents.

## Acceptance examples

The following are conditional acceptance examples derived from static evidence. They have not been executed.

Unless stated otherwise, words are 32 bits wide, lists are in increasing index order, and all requested accesses are valid.

### 1. Empty and negative requests

With a count of zero, the return is zero and no source or destination word is accessed.

The same holds for a count of negative one. No unsigned reinterpretation turns the negative count into a large request.

### 2. Single-word subtraction without borrow

Given:

- First source: [9]
- Second source: [4]
- Count: 1

The destination becomes [5], and the return is zero.

No second word is read or written.

### 3. Single-word underflow

Given:

- First source: [0]
- Second source: [1]
- Count: 1

The destination becomes [0xFFFFFFFF], and the return is the pointer-typed encoding of one.

The stored all-ones pattern may be displayed as negative one through a signed 32-bit view, but its arithmetic role is the low word of the unsigned difference.

### 4. Borrow persists through equal words

Given:

- First source: [0, 5]
- Second source: [1, 5]
- Count: 2

The destination becomes [0xFFFFFFFF, 0xFFFFFFFF], and the final borrow is one.

The second pair of source words is equal. Its incoming borrow is therefore preserved, not cleared.

### 5. A larger higher word clears the borrow

Given:

- First source: [0, 5, 7]
- Second source: [1, 5, 6]
- Count: 3

The destination becomes [0xFFFFFFFF, 0xFFFFFFFF, 0], and the final borrow is zero.

At the final word, the first source exceeds the second source by one. Subtracting the incoming borrow produces zero while clearing the outgoing borrow.

### 6. Borrow crosses a four-word boundary

Given:

- First source: [0, 0, 0, 0, 1]
- Second source: [1, 0, 0, 0, 0]
- Count: 5

The destination becomes [0xFFFFFFFF, 0xFFFFFFFF, 0xFFFFFFFF, 0xFFFFFFFF, 0], and the final borrow is zero.

This establishes the expected carry-through behavior across the internal group boundary.

### 7. Exact in-place destination

Given:

- Shared first-source and destination storage initially containing [0, 1]
- Separate second source containing [1, 0]
- Count: 2

The shared storage becomes [0xFFFFFFFF, 0], and the final borrow is zero, provided the environment permits these word accesses and aliases.

### 8. Forward overlap changes a later input

Suppose a backing array initially contains [5, 9, 12]. The first source begins at its first word, while the destination begins at its second word. The separate second source contains [1, 2], and the count is two.

The backing array becomes [5, 4, 2]:

- The first destination write replaces the middle word with 4.
- The next first-source read obtains that 4, not the original 9.
- Subtracting 2 produces the final word 2.

The final borrow is zero. A snapshot-based result would differ and is not the behavior established here.
