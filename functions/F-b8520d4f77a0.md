# F-b8520d4f77a0

## Purpose

F-b8520d4f77a0 performs a callback-driven recursive traversal controlled by a descriptor and a shared control block.

Each visit begins with an indirect entry callback. Classification then selects one of three behaviors:

- Recursively visit one subordinate descriptor using the same object address.
- Traverse selected records in a descriptor table, calculating a child object address for each accepted record.
- Perform no recursive visit.

Unless a table-child return triggers the shared stop condition, the visit ends by considering an optional completion callback.

The interpretation as an object-layout or type-descriptor traversal is inferred intent. The established behavior consists of the accesses, calls, branching, address calculations, and stop-check placement described below.

The two classification reference operands are read from separate global-memory locations at specific points during classification. They are not established constants or entry-time snapshots.

## Interface

### Inputs and result

The visible interface has three inputs represented as 32-bit values:

| Input | Established use |
|---|---|
| Object address | Identifies the current object; used in child-address calculations and passed to completion. The indirect calculation also reads its first 32-bit word. |
| Descriptor address | Identifies classification input, subordinate-descriptor storage, and any table records. |
| Control-block address | Identifies callback encodings, selection control, and shared stop state. |

No explicit result value is produced. Normal completion is a return without an established status or payload.

Recursive call sites additionally supply a fourth machine-level value:

- Zero for a single-child visit.
- The current table-record address for a table-child visit.

The visible body does not declare or read this fourth value. Its significance is **documented_only**; it must not be assigned an invented context, ownership, or callback role.

### Control-block layout

The following offsets are measured in bytes from the control-block address:

| Offset | Width | Established use |
|---|---:|---|
| 0 | 32 bits | Entry-callback encoding; its lowest two bits are cleared to form the call target. |
| 4 | 32 bits | Optional completion-callback encoding; tested for zero before a masked target is called. |
| 8 | — | Not explicitly accessed by this body. |
| 12 | 32 bits | Table-selection control; zero accepts every record, while nonzero requires metadata bit 1. |
| 16 | 32 bits | Stop field; checked after each accepted table-child visit. |

These fields are live state. The routine does not copy the control block at entry.

### Descriptor and record layouts

| Descriptor offset | Width | Established use |
|---|---:|---|
| 8 | 32 bits | Subordinate descriptor for the single-child branch. |
| 12 | 32 bits | Signed count operand used when recalculating the table bound. |
| 16 onward | 8 bytes per record | Table storage. |

Each table record contains:

| Record offset | Width | Established use |
|---|---:|---|
| 0 | 32 bits | Descriptor value supplied to the recursive visit. |
| 4 | 32 bits | Metadata supplying selection, addressing mode, and signed displacement. |

The metadata has three independently relevant interpretations:

- Bit 1 permits the record when selection control is nonzero.
- Bit 0 selects indirect rather than direct child-address calculation.
- Interpreting the whole word as signed 32-bit and shifting it arithmetically right by eight yields the displacement.

The displacement therefore occupies the signed upper 24 bits and ranges from −8,388,608 through +8,388,607. The low eight bits do not contribute to it. Selection bit 1 is distinct from addressing-mode bit 0.

### Global classification references

Two distinct global-memory locations supply the reference operands for classification:

- The first reference location is read after the first F-e3253cb77678 invocation returns and before the first F-061c2693b838 invocation receives its arguments.
- The second reference location is read only if the first classification returns zero, after the second F-e3253cb77678 invocation returns and before the second F-061c2693b838 invocation receives its arguments.

Neither reference is captured on entry. A preceding callback or dependency invocation may change the value subsequently read. The supplied body does not establish the globals’ initial values, semantic identities, or declaration details.

## Behavior

### Entry callback

The first explicit operation reads the entry-callback encoding at control offset 0, clears its two lowest bits, and calls the resulting target.

There is no zero check. An encoding whose only set bits are among the lowest two produces target address zero.

The call supplies no explicit arguments. This does not establish that argument registers are cleared, that ambient calling-convention state is inaccessible, or that the callback has no parameters under the actual binary interface.

Classification begins only after the entry callback returns.

### Classification and global-read order

Classification proceeds in this order:

1. Invoke F-e3253cb77678 with the current descriptor value.
2. After that invocation returns, read the first global reference operand.
3. Invoke F-061c2693b838 with the transformation result and the reference value just read.
4. Test the classification result for zero.

A nonzero first classification result selects the single-child branch. The second transformation, second global-reference read, and second classification are not performed.

If the first classification result is zero:

1. Invoke F-e3253cb77678 again with the same current descriptor value.
2. After this second invocation returns, read the second global reference operand.
3. Invoke F-061c2693b838 with this new transformation result and the second reference value just read.
4. Test the second classification result for zero.

A nonzero second result selects table traversal. A zero second result skips recursion and proceeds to completion processing.

The first transformation result is not reused. The two transformations need not return the same value. In particular:

- A write to the first reference location by the entry callback or first transformation can affect the first classification operand.
- A write to the second reference location by the first classification or second transformation can affect the second classification operand.
- A later write does not retroactively change a value already supplied to a completed classification call.

The meanings of the transformation and classification operations are unknown. Nonzero must not be described as equality, membership, or a particular descriptor class without additional evidence.

### Single-child branch

When the first classification result is nonzero, the routine reads the 32-bit subordinate descriptor at descriptor offset 8 and recursively invokes F-b8520d4f77a0 with:

- The unchanged object address.
- The subordinate descriptor value.
- The same control-block address.
- Zero as the additional fourth call-site value.

After the child returns, the parent proceeds to completion processing.

There is no stop-field check after this recursive call. A stop value left nonzero by the child does not itself suppress this parent’s completion callback.

### Table traversal and bounds

When the first classification is zero and the second is nonzero, the current record begins at descriptor offset 16.

The loop condition compares the current record address against a bound formed from the descriptor address, the count at descriptor offset 12, an eight-byte record size, and the sixteen-byte prefix.

The count is read whenever the loop condition is evaluated. It is not captured once for the traversal. If a returning child changes it, the next condition uses the changed count.

For valid, nonwrapping layouts, records are considered in increasing address order, eight bytes apart. A zero count causes no record visits.

The count is read as signed 32-bit, and its multiplication by eight participates in the bound expression. The supplied representation does not establish a portable contract for multiplication overflow, address wrap, negative counts, or comparisons involving invalid table ranges. These are not accepted as safe inputs merely because the operands have 32-bit representations.

### Record selection

For each record admitted by the loop condition:

1. Read selection control at control offset 12.
2. If it is zero, accept the record without requiring a bit-1 selection read.
3. Otherwise, read record metadata and accept only if bit 1 is set.

A rejected record advances traversal by eight bytes. It causes no child-address calculation, recursive visit, or stop-field check.

For an accepted record, bit 0 of metadata determines the addressing mode, except that an explicitly null record address leaves the addressing-mode selector zero.

That null comparison is not general pointer validation. Subsequent processing still requires metadata and the record’s descriptor word. It does not make a null record safely traversable.

### Direct child-address calculation

When the addressing-mode selector is zero, the routine reads metadata for the signed displacement and adds that displacement to the current object address.

The result becomes the recursive child object address.

Negative displacements are permitted by the displacement representation. Whether the resulting address is valid depends on the supplied object layout; the routine performs no range check.

### Indirect child-address calculation

When the addressing-mode selector is nonzero:

1. The first signed 32-bit word of the current object supplies an address base.
2. Metadata supplies the signed displacement.
3. A signed 32-bit word is read from that base plus the displacement.
4. The fetched word is added to the original object address.

The final sum becomes the recursive child object address.

The fetched word is therefore used as an object-relative offset, not directly as an absolute child address. It can represent a negative offset, subject to valid arithmetic and addressability.

The expression establishes the data dependency between the intermediate address and the fetched word. It does not establish a total machine-level order between every independent operand read, including the initial object-word and metadata reads.

### Table-child invocation and stop handling

After calculating the child object address, the routine recursively invokes F-b8520d4f77a0 with:

- The calculated child object address.
- The descriptor value from the record’s first word.
- The same control-block address.
- The current record address as the additional fourth call-site value.

After that recursive invocation returns, the routine reads the stop field at control offset 16.

- Zero permits traversal to continue.
- Nonzero immediately returns from the current frame, omitting its completion callback.

There is no stop check on entry, before classification, before the first accepted table child, after a rejected record, after a single-child visit, or immediately before completion.

Consequently, a preexisting nonzero stop value does not prevent an accepted table child from being visited. If no child is accepted, that frame does not inspect the stop field at all.

### Completion callback

If the frame reaches normal completion, it reads the completion encoding at control offset 4 and tests it for zero.

- Zero returns without calling completion.
- Nonzero causes the completion encoding to be read for target formation, its lowest two bits to be cleared, and the resulting target to be called with the current object address and current descriptor value.

The source contains separate accesses for the zero test and target formation; it does not establish a single saved encoding used for both. No intervening explicit call appears between them, and no concurrent-update guarantee is provided.

An unchanged encoding of 1, 2, or 3 passes the zero test but produces target address zero. No guard rejects this case.

The completion callback’s return value is ignored.

## Side effects

The supplied body contains no explicit store to object storage, descriptors, table records, control fields, or the two reference globals.

This does not establish read-only execution:

- Entry and completion callbacks may mutate reachable memory or globals.
- Both classification dependencies may mutate those same resources.
- Recursive visits share the control block.
- Later reads may observe changes made by earlier calls.

Metadata is not captured once per record. Selection, addressing-mode selection, and displacement extraction can use separate reads. Count, selection control, stop state, and completion encoding are also read at their respective use points. There is no explicit synchronization.

No allocation, release, ownership transfer, locking, or error-reporting operation is explicitly performed by this body. Unknown callees must not be assumed to preserve allocations, globals, or input storage.

Successful execution requires every actually used memory location and call target to remain valid when accessed. The routine does not validate callback targets, table extent, descriptor relationships, recursion depth, or cycles.

There is no established recovery or status-reporting path for invalid accesses, failed indirect transfers, nonreturning dependencies, or exhausted recursion resources.

## Acceptance examples

These are conditional static expectations, not runtime test results. Unless stated otherwise, they assume valid memory, nonoverflowing arithmetic, returning callees, stable relevant storage, and stop remaining zero.

1. **No recursive branch selected.**  
   If both classification results are zero, the order is entry callback, first transformation, first reference-global read, first classification, second transformation, second reference-global read, second classification, then optional completion. No recursive visit occurs.

2. **First transformation changes the first reference.**  
   If the first transformation writes a new value to the first reference location before returning, and nothing changes it before its subsequent read, that new value is supplied to the first classification. An earlier value present on function entry is not used as a snapshot.

3. **Second reference changes during preceding calls.**  
   If the first classification returns zero and changes the second reference location, that change can affect the second classification. If the second transformation subsequently replaces that value before returning, the later value is the one read and supplied.

4. **First classification selects the single child.**  
   A nonzero first classification causes a visit using the unchanged object address and descriptor offset 8. There is no second transformation, second reference read, or second classification. Normal child return leads to optional parent completion.

5. **Two unfiltered direct records.**  
   With count two, selection control zero, and direct displacements +12 and −4, the two recursive object addresses are the parent address plus 12 and minus 4, in record order. Parent completion follows both returning visits.

6. **Filtered record with indirection set.**  
   With nonzero selection control, a record lacking bit 1 is skipped even if bit 0 is set. No indirect object read or stop check occurs for that record.

7. **Indirect offset lookup.**  
   For an accepted indirect record with displacement −8, the routine reads a signed 32-bit offset eight bytes before the address held in the object’s first word. If that offset is 20, the child object address is the parent address plus 20.

8. **Stop raised by a table child.**  
   If a returning table child leaves stop nonzero, the current frame returns without considering another record or calling its completion callback.

9. **Stop raised by a single child.**  
   If a returning single child leaves stop nonzero, its parent still considers completion because that branch has no post-child stop check.

10. **Stop already set but no accepted child.**  
    A zero-count table, or a table whose records are all rejected, can reach completion despite stop already being nonzero.

11. **Live count reduction.**  
    If the first child reduces the count so that the next record is outside the recalculated valid bound, traversal ends after the child returns and the zero stop check permits continuation.

12. **Completion replacement.**  
    If a child replaces the parent’s completion encoding and the parent reaches completion, the parent reads the current encoding rather than an entry-time copy.
