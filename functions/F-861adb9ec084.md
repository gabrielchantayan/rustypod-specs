# F-861adb9ec084

## Purpose

F-861adb9ec084 writes the difference between two sampled integer fields to a caller-provided destination, obtains a second result from F-2f6d9e541ca0, writes that result to another destination, and finally updates a previously selected state object.

State selection is significant: the supplied representation evaluates the global state pointer **three times**. The captured object used for the dependency argument and final writes need not be the object supplying either subtraction operand.

The established ordering is:

- Sample the state pointers and subtraction operands.
- Store the difference.
- Read the dependency argument from the captured object and invoke the dependency.
- Store the dependency result.
- Write the saved current value to the captured object and clear its first byte.

An inferred interpretation is “report a change, obtain an associated value, then acknowledge progress and clear a flag.” Field meanings, units, and the significance of the cleared byte are not established. This interpretation supplies no additional guarantees.

## Behavior

### State selection and operand sampling

The supplied representation establishes three global-pointer evaluations, in this order:

1. Capture a base address for subsequent dependency-argument access and final state writes.
2. Evaluate the global pointer again and read the four-byte current value at offset 12 of that selected object.
3. Evaluate the global pointer again and read the four-byte value at offset 16 of that selected object.

The current value obtained by the second evaluation is saved for both the subtraction and the final offset-16 write.

The third evaluation is not replaced by the captured base. Consequently, there are three distinct selection roles:

- **Captured object:** supplies the dependency argument and receives finalization writes.
- **Current-source object:** supplies the saved current value at offset 12.
- **Subtrahend-source object:** supplies the value at offset 16 that is subtracted.

With a stable global pointer across all three evaluations, these roles identify the same object. Without that stability, all three may identify different objects.

This distinction describes the supplied access expressions; it does not establish a supported concurrent-update mechanism. No synchronization, atomicity, or reentrancy protocol is visible.

### Difference output

The function subtracts the sampled offset-16 value from the saved current value and writes the result to the difference destination.

For operands whose mathematical difference fits the signed 32-bit range, the stored result is that difference. The operation is not an absolute difference, comparison, unsigned-distance calculation, or saturating subtraction. Negative results are possible.

For example, a saved current value of 10 and a sampled subtrahend of 15 produce −5 under the stated integer model.

Signed-overflow behavior is unresolved. The supplied representation shows signed integer subtraction but does not independently establish wrapping semantics. This contract therefore does not specify a numeric result when the mathematical difference is outside −2,147,483,648 through 2,147,483,647.

The difference store occurs after both operands have been sampled. If that store overlaps an operand’s source storage, it does not change the already sampled operand used in this invocation.

### Dependency argument and invocation

After the difference store, the function reads four bytes at offset 32 of the captured object and passes that value as the sole visible argument to F-2f6d9e541ca0.

The argument is not sampled at entry. A difference destination overlapping those four bytes can therefore change the argument received by the dependency.

A change to the global pointer after initial capture does not, by itself, redirect this argument read. The read uses the captured base rather than a new evaluation of the global pointer.

On the normal path, F-2f6d9e541ca0 is invoked once. Its four-byte returned value is written to the dependency-result destination.

No visible branch interprets that result as success, failure, zero, or a sentinel. Every normally returned value follows the same subsequent direct path.

The dependency’s internal effects are unknown. It must not be assumed to preserve the global pointer, any selected object, output storage, or allocation lifetimes.

### Finalization

After storing the dependency result, the function:

- Writes the saved current value to the four-byte location at offset 16 of the captured object.
- Writes zero to the single byte at offset 0 of that same object.

The final offset-16 value is the value sampled through the **second** global-pointer evaluation, not a fresh read from the captured object.

Accordingly:

- If the current-source object differed from the captured object, the function copies the sampled value between those objects.
- If the subtrahend-source object differed from the captured object, the field supplying the subtrahend is not necessarily overwritten.
- Changes to any offset-12 field after sampling do not refresh the saved value.
- A dependency-induced global-pointer replacement does not redirect finalization.

The last store clears exactly one byte. It does not directly clear adjacent bytes, a complete word, or the entire object.

## Side effects

### Observable access order

The direct access sequence supported by the supplied representation is:

1. Read the global pointer and capture its value.
2. Read the global pointer again and obtain the current value from the selected object’s offset 12.
3. Read the global pointer a third time and obtain the subtrahend from the selected object’s offset 16.
4. Store the difference at the first destination.
5. Read the dependency argument from the captured object’s offset 32.
6. Invoke F-2f6d9e541ca0.
7. Store its returned value at the second destination.
8. Store the saved current value at the captured object’s offset 16.
9. Store one zero byte at the captured object’s offset 0.

This is the logical order visible in the supplied representation. It does not establish machine-level atomicity, memory barriers, or cross-thread visibility guarantees.

### Aliasing

No explicit non-aliasing restriction or overlap check is visible. Subject to execution-environment validity requirements, overlapping storage can make earlier results temporary.

Established consequences include:

- Identical output destinations receive the difference first and the dependency result later.
- A first destination overlapping the captured object’s offset-32 field can alter the dependency argument.
- Either destination overlapping the captured object’s offset-16 field can be overwritten by finalization.
- Either destination overlapping the captured object’s first byte can be partially changed by the final byte clear.
- Overlap with the subtrahend-source object’s offset 16 does not imply that finalization targets that object. Finalization still uses the captured base.

If an output store validly changes the global pointer itself, the later direct argument read and final writes still use the already captured base. The dependency may independently inspect or modify the global pointer.

For partial overlaps, exact resulting bytes depend on address relationships and target representation. Endianness is not supplied, so representation-dependent numeric results are not asserted.

### Ownership and lifetime

No direct allocation, explicit release, or ownership-transfer operation is visible in F-861adb9ec084. The output pointer arguments are used as store destinations; they are not explicitly forwarded to the dependency or retained by the direct body.

That observation does not constrain indirect access. The dependency may have another route to the same storage, and its retention, release, allocation, and ownership behavior remains unknown.

### Errors and interruption

There is no visible validation, rollback, recovery branch, or explicit error-status return.

If the dependency does not return normally, the direct body does not proceed to the dependency-result store or final state writes. The difference store has already been reached. The dependency’s own effects may nevertheless have modified that output or other storage.

The operation is not established as transactional. Invalid accesses and arithmetic outside the supported range have no defined recovery behavior in this contract; no particular fault, exception, or preserved partial state is promised for invalid execution.

## Acceptance examples

These are conditional consequences of static evidence, not executed tests. Unless an example states otherwise, assume valid disjoint storage, a global pointer stable across **all three** initial evaluations, representable subtraction, and a dependency that returns normally without changing relevant storage.

### Ordinary positive difference

With offset 12 equal to 150 and offset 16 equal to 110:

- The first destination receives 40 before the dependency runs.
- The dependency receives the captured object’s offset-32 value.
- Its return value is stored at the second destination.
- The captured object’s offset 16 becomes 150.
- Its first byte becomes zero.

### Equal or decreasing values

With both sampled operands equal to 72, the first result is zero. The dependency call and finalization still occur.

With a saved current value of 10 and sampled subtrahend of 15, the first result is −5. No visible branch rejects the negative result or skips finalization.

### Three different selected objects

Conditionally suppose the three pointer evaluations validly select different objects:

- The first evaluation captures an object whose offset 16 initially contains 7.
- The second evaluation selects an object whose offset 12 contains 90.
- The third evaluation selects an object whose offset 16 contains 25.

Assuming no other interference:

- The difference is 65, not 83.
- The dependency argument comes from offset 32 of the first, captured object.
- Finalization writes 90 to offset 16 of the captured object.
- The third object’s offset-16 value remains 25 unless another effect modifies it.
- The captured object’s first byte is cleared.

This example describes the consequences of the represented selections, not a guarantee that unsynchronized pointer changes are valid.

### Shared output destination

If both output arguments identify the same valid four-byte location:

- That location first receives the difference.
- It subsequently receives the dependency result.
- Its final value is the dependency result, provided neither final state write overlaps it and the dependency causes no conflicting change.

### Difference output changes the argument

If the first destination exactly identifies the captured object’s offset-32 field, and the difference is 40, the four-byte store occurs before the dependency argument is read. The dependency receives the resulting four-byte representation, interpreted according to its unresolved argument type.

### Dependency changes the current field

Suppose the saved current value is 80. If the dependency changes an offset-12 field to 95 while leaving all required storage valid, finalization still writes 80 to captured-object offset 16.

The direct body does not restore that offset-12 field to 80.

### Dependency replaces the global pointer

If the dependency installs another global state pointer but leaves the captured object valid, finalization still targets the captured object. The replacement object receives no direct finalization writes merely because it is now globally referenced.

### Dependency does not return

If the dependency does not return normally, the direct result store and finalization are not reached. No rollback of the earlier difference store is established, and dependency effects remain unconstrained.
