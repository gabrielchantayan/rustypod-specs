# F-8d94de31c650

## Purpose

F-8d94de31c650 specifies a routine that interleaves computed-address memory accesses with 74 indirect call occurrences. Its visible effects include publishing scaled values, projecting selected bits from words, forwarding an opaque result, and performing two byte-selected writes. The supplied representation ends at an invalid-instruction boundary rather than an established normal return.

A domain-specific purpose is not established. Repeated offsets and scaling do not, by themselves, establish object construction, allocation, serialization, or device access.

This contract distinguishes:

- **Established static evidence:** access widths, expressions, call ordering, captured values, and the terminal invalid-data annotation.
- **Conditional interpretation:** arithmetic and address examples evaluated as 32-bit bit patterns.
- **Unknowns, marked documented_only:** actual execution validity, dependency behavior, memory mappings, and machine-level details not established by the supplied representation.

No runtime tests have been performed.

### Widths and notation

The following notation defines the conditional 32-bit interpretation:

- **W(x):** the low 32 bits of x.
- **scaled(x):** W(4 × x).
- **word address(x):** W(4 × x + `0x14`).
- **wide address(x):** W(16 × x + `0x14`).
- Right shifts of explicitly unsigned words are logical.
- A byte read produces an unsigned value from 0 through 255.
- A byte write preserves only the low eight bits of its data.

These definitions make address calculations and examples precise without asserting that all displayed signed operations have defined language-level behavior. Several dependency results are represented as signed 32-bit integers and participate in multiplication or left shifts. Their interpretation as wrapping machine arithmetic remains conditional.

A word access is four bytes wide. Endianness and the correspondence between a word value and its individual memory bytes are not established.

## Behavior

Calls listed without arguments have no explicit arguments in the representation. This does not prove that their machine-level interfaces consume no registers or implicit state. Results are ignored unless capture or forwarding is described.

All ordering below is conditional on preceding operations completing. Dependency effects may occur between the routine’s explicit memory accesses.

### 1. Initial publication and masked-input publication

Before F-D001, the routine writes a 32-bit word:

- Destination: W(input word × `0x10000000` + `0x14`).
- Data: W(input word × `0x04000000`).

It also retains the input word masked by `0x1FFFFFFF`.

F-D001 receives W(input word × `0x04000000`). F-D002, F-D003, and F-D004 follow without explicit arguments. F-D005 then returns the **first index**.

The routine writes the masked input logically shifted right by nine to word address(first index), then calls F-D006 with scaled(first index).

The published value is at most `0x000FFFFF`: input bits 29–31 are removed before the shift.

### 2. First payload and two argument reads

F-D007, F-D008, and F-D009 precede F-D010, whose result is the **second index**.

The **first payload** is scaled(second index). It is written as a word to wide address(second index).

F-D011 receives three explicit arguments:

1. An unsigned word read from W(first payload + `0x14`), logically shifted right by 12.
2. First payload.
3. A separate unsigned word read from W(first payload + `0x14`), shifted left by two and reduced to 32 bits.

Both read expressions follow the wide-address store and precede entry into F-D011. Their relative evaluation order is not established. The contract retains both expressions; it does not require them to observe one common snapshot.

The store destination is based on sixteen times the second index, whereas the read address is based on four times that index. They must not be treated as the same location merely because both include `0x14`. Equality is possible for some index bit patterns.

### 3. First-payload propagation and input-derived argument

### Layout and alignment

Under the conditional 32-bit address model, **every explicit word-access address is divisible by four**. This applies to the twelve word stores and three word-read expressions only.

Selector-byte source addresses are congruent to 1 modulo 4. Byte-store destinations may have any residue modulo 4.

The recurring `0x14` offset does not establish a field layout, object boundary, allocation size, or valid memory region. Four-byte arithmetic alignment does not prove access validity or atomicity.

### Aliasing limits

Computed word-access addresses have no general distinctness guarantee. A store may overlap a location subsequently read, and byte-store destinations may overlap bytes belonging to a word-access region.

The selector-source addresses have the exact conditional numeric set:

{1 + k × `0x10000000` | k is an integer from 0 through 15}.

Byte-store destinations instead occupy `0x11` through `0x110`. **These numeric address sets are disjoint.** Consequently, neither byte store numerically targets the selector-source byte under this model.

An environment could map different numeric addresses to shared backing storage, but such aliasing is **documented_only**, not established behavior. Dependency effects or external changes may also make the two selector reads differ.

## Acceptance examples

These are conditional arithmetic and ordering examples, not executed tests. They assume the stated 32-bit interpretation, valid reached accesses, and dependencies returning as stipulated.

1. **Input truncation and projection.** For input word `0xFFFFFFFF`, the initial store writes `0xFC000000` at `0xF0000014`. The later first-index store writes `0x000FFFFF`. F-D021’s third argument is `0xFC000000`.

2. **Different address scales.** If second index is 1, first payload is 4. The wide-address store writes 4 at `0x24`; both F-D011 read expressions address `0x18`. Substituting a read from `0x24` would change the represented behavior.

3. **Separate argument observations.** If F-D011’s right-shift read observes `0x00012000` and its left-shift read observes `0x80000003`, the corresponding arguments are `0x12` and `0x0000000C`. Its middle argument remains first payload. Neither read is assigned precedence over the other.

4. **Retained value, not reread.** If the retained-word read observes `0xABCDEF01`, the ninth-index store writes `0x000ABCDE`. A later change to the original read location does not itself change that captured value.

5. **Split argument construction.** For ninth index 3, ninth base is 12. F-D051’s first argument is `0x00030000`, and its third is `0xC0000000`.

6. **Byte truncation.** For final word `0xFEDCBA98`, the first byte store writes `0x60`, and the second writes `0xED`. F-D061 receives `0xFB72EA60`, `0xFB72EA60`, and `0xEDCBA980`.

7. **Fresh selectors.** If the first selector is `0x20` and the second is `0x40`, the byte destinations are `0x31` and `0x51`. F-D073’s second argument is `0x40`, not the first selector.

8. **Selector-source separation and alignment.** If ninth index is 0, both selector-source addresses are `0x00000001`. If it is 1, both are `0x10000001`. Neither source lies in the destination range `0x11`–`0x110`. A destination of `0x11` is valid within that range without being four-byte aligned; no word-alignment claim applies to it.

9. **Early nonreturn.** If F-D001 never returns, the initial word store precedes that call, but none of the subsequent explicit memory accesses is reached. No rollback is specified.
