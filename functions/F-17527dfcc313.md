# F-17527dfcc313

## Purpose

F-17527dfcc313 performs an initial byte-directed zero write, invokes two dependencies, and enters an unconditional loop containing ten dependency calls and another byte-directed zero write.

**The first call in the loop changes recipient after the first iteration.** Its first invocation targets D-03. Every subsequent iteration targets D-13 at that position. The argument-producing expressions remain the same, but their recipient does not. The remaining nine loop-call positions have fixed targets in the supplied representation.

No application-level purpose is established. Initialization, polling, protocol processing, and hardware control are possible interpretations, not supported contracts.

The supplied static representation includes warnings about invalid instruction data and removed unreachable regions. This specification describes the visible control flow and dataflow, not a validated reconstruction of all machine-level behavior.

## Behavior

### Arithmetic interpretation

The seed-derived state is represented as an unsigned 32-bit quantity. Its right shifts are logical shifts.

Results retained from D-02, D-07, and D-12 are represented as signed 32-bit integers. Left shifts of the latter two results require particular care:

- The shift counts and subsequent uses are established.
- Nonnegative values whose shifted results remain representable as signed 32-bit integers admit direct numeric interpretation.
- Negative operands and results outside that signed range have no independently established machine-level interpretation here.
- Low-32-bit truncation examples below are explicitly conditional on ordinary 32-bit machine-shift behavior.

Assignment of a shifted result to unsigned state does not, by itself, resolve the semantics of the preceding signed shift.

### Entry sequence

The visible entry sequence is:

1. Derive the initial unsigned state by shifting the seed right by 20 bits.
2. Read the selector byte.
3. Write a zero byte to the selected destination.
4. Invoke D-01 with the initial unsigned state shifted left by one bit.
5. Invoke D-02 without explicit arguments and retain its integer result as the initial carried value.
6. Enter the loop with D-03 selected as its first-call recipient.

D-01’s target is the entry target base plus 0xF74. Its return value, if any, is not consumed.

The initial unsigned state ranges from 0 through 4,095. D-01 therefore receives a value from 0 through 8,190, without loss of bits in the represented unsigned shift.

The selector state choosing D-03 for the first loop invocation is established after D-01 returns and before D-02 is invoked. This is internal call-target state, not the byte selector used for memory writes.

### Loop operation order

Each reached iteration performs the following sequence:

| Order | Operation | Arguments or result use |
|---|---|---|
| 1 | Invoke D-03 on the first iteration; D-13 thereafter | Carried value; current unsigned state shifted right by 8 |
| 2 | Invoke D-04 | No explicit arguments |
| 3 | Invoke D-05 | No explicit arguments |
| 4 | Invoke D-06 | No explicit arguments |
| 5 | Invoke D-07 | No explicit arguments; retain its integer result |
| 6 | Read the selector byte again | Same represented index-based address calculation |
| 7 | Write one zero byte | Destination selected by this fresh byte read |
| 8 | Invoke D-08 | D-07’s result shifted left by 2 |
| 9 | Invoke D-09 | No explicit arguments |
| 10 | Invoke D-10 | No explicit arguments |
| 11 | Invoke D-11 | No explicit arguments |
| 12 | Invoke D-12 | No explicit arguments; retain its integer result |

Immediately before invoking D-12, the state selecting the loop’s first-call target is changed to select D-13. That selection survives the represented back edge. There is no visible restoration of D-03.

After D-12 returns:

- Its result shifted left by 2 becomes the next carried value.
- Its result shifted left by 26 becomes the next unsigned state.
- Execution repeats at the first loop-call position, now targeting D-13.

Thus D-03 is reached at most once in the represented execution. D-13 is first reached only if the first iteration progresses through D-12 and the state updates following its return.

The visible sequence does not consume results from D-03, D-13, D-04 through D-06, or D-08 through D-11. This does not establish that those dependencies lack return values or side effects.

### Argument dataflow across iterations

For the first loop call, targeting D-03:

- The first argument is D-02’s retained result.
- The second argument is the seed shifted right by 28 bits.
- The second argument therefore ranges from 0 through 15.

For every later loop call, targeting D-13:

- The first argument derives from the preceding D-12 result shifted left by 2.
- The second argument derives from the preceding D-12 result shifted left by 26, assigned to unsigned 32-bit state, then shifted logically right by 8.

Under ordinary truncating 32-bit machine-shift semantics, the later arguments can be described more precisely:

- The first argument retains the low 32 bits of the preceding result shifted left by 2.
- The unsigned state retains only that result’s low six bits, placed at bit positions 26 through 31.
- The second argument places those six bits at positions 18 through 23.

Under that conditional interpretation, D-13’s second argument ranges from zero through 0xFC0000 in steps of 0x40000. It is not restricted to D-03’s first-iteration range.

D-07’s result supplies D-08’s argument only. D-12’s result supplies both next-iteration argument paths. These result sources must not be interchanged.

## Acceptance examples

These are conditional acceptance observations, not executed tests. They assume relevant memory and call targets are valid and dependencies return as specified.

### Initial extraction and first recipient

Given a seed of 0xABCDEF01:

- Initial unsigned state is 0xABC.
- The entry write precedes D-01.
- D-01 receives 0x1578.
- If D-02 returns 7, the first loop-call position invokes D-03 with arguments 7 and 0xA.

The seed’s lower 20 bits do not affect these initial arguments.

### First-to-later target transition

Suppose the first D-12 invocation returns 1 and execution continues normally:

- The next carried value is 4.
- The next unsigned state is 0x04000000.
- The next loop-call position invokes **D-13**, with arguments 4 and 0x00040000.
- It does not invoke D-03 at that position.

If another iteration completes, its successor also uses D-13. These numeric values avoid signed-overflow ambiguity.

### Distinct result paths

If D-07 returns 5 and D-12 later returns 1:

- D-08 receives 20.
- D-13 receives 4 and 0x00040000 at the next iteration’s first-call position.

Using D-07’s result for the next iteration, or delivering the next arguments to D-03, would contradict the visible dataflow or target selection.

### Byte-selected destination

If a selector read yields 0xFE, the corresponding zero-byte write targets 0x10F.

It must not load a pointer-sized selector, multiply the selector value by 1,024, or perform a pointer-sized zero store.

### Changed selector

Suppose the entry selector read yields 3 and the first D-07 changes that byte to 9:

- The entry write targets decimal address 20.
- Absent an intervening change, the loop read observes 9.
- The loop write targets decimal address 26.

Reusing the entry selector value would contradict the fresh read.

### Interrupted progress

If D-04 does not return during the first iteration, D-05 and all later operations are not reached. The loop’s selector read and write have not occurred, and D-13 has not been invoked.

If D-12 does not return, no next-iteration first call occurs, even though the internal target selection has already changed to D-13.

### Conditional shift boundary

If D-12 returns 64, ordinary truncating 32-bit machine-shift behavior produces:

- Next carried value: 256.
- Next unsigned state: zero.
- Next D-13 arguments: 256 and zero.

The shift by 26 exceeds the represented signed range. This outcome is conditional, not established solely by the signed expression notation.
