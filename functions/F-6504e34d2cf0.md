# F-6504e34d2cf0

## Purpose

F-6504e34d2cf0 performs an extended sequence of unresolved indirect calls, transforms returned and secondary machine values, and then performs ordered mixed-width memory accesses before a final unresolved indirect transfer.

No higher-level purpose is established. Printable constants do not establish formatting or text output; address-like values do not establish allocated objects.

This contract distinguishes:

- **Established static evidence:** interactions, widths, value relationships, and ordering visible in the supplied representation.
- **Inferred intent:** interpretations not supported strongly enough to become requirements.
- **documented_only:** executable details that remain unresolved.

The contract describes represented behavior, not a guarantee of successful execution. No runtime tests have been performed.

## Behavior

### Interaction model

The represented body has an indirect-call phase followed by a direct-memory phase. No explicit input-dependent branch or loop is shown. Repeated interactions are represented individually.

Order matters. Matching final memory contents alone is insufficient: intervening reads, duplicate writes, dependency effects, aliasing, and faults can distinguish executions.

Dependencies must not be assumed pure, memory-preserving, resource-preserving, or guaranteed to return. A call with no represented arguments is not necessarily without implicit inputs.

### Initial calls and value transformations

The initial indirect target is derived from incoming execution context. Its three represented arguments are the first input, the second input, and the second input shifted left by six. Later targets are derived from fixed continuation-related locations rather than solely from explicit inputs.

The call phase exchanges individual 32-bit results and 64-bit containers whose low and high 32-bit halves are used separately. Common relationships include:

- A low half shifted left by eight.
- A high half forwarded unchanged or shifted left by six.
- Additional arguments derived from low halves shifted left by fourteen.
- Explicit zero arguments.
- Values retained across intervening calls.

Other transformations include fixed left shifts through thirty-one bits, unsigned right shifts, low-bit masks, and unsigned extraction from 64-bit positions thirty-four, thirty-six, and forty-four. Masks select distinct fields, including low 24, 22, 21, 20, 19, 18, 17, 16, 15, 14, 13, 12, and 11 bits. They are not interchangeable.

Retained quantities initialized to zero and subsequently only shifted remain zero under ordinary fixed-width word semantics. This does not make their receiving calls removable.

### Arithmetic and widths

The representation predominantly uses 32-bit words and address calculations, 64-bit result containers, and explicitly typed 8-, 16-, and 32-bit memory accesses.

For a conditional 32-bit machine-word interpretation, left shifts, multiplication, addition, and subtraction retain only the low 32 bits before later transformations. Widening intermediate calculations can change both values and addresses.

Examples of width-sensitive relationships:

- Two successive left shifts by twenty-eight discard every original bit.
- A left shift by thirty-one followed by a left shift by thirty also discards every original bit.
- A left shift by eight followed by an unsigned right shift by eight clears the original high byte.
- Selecting the low twenty bits, shifting right by ten, and shifting left by six retains a selected ten-bit field rather than an unrestricted shifted word.

Several expressions are represented using signed arithmetic that can overflow. The supplied material does not establish portable executable semantics for those expressions. Modular 32-bit treatment is therefore a **conditional machine-model requirement**, not a claim that every displayed signed expression independently defines that behavior.

Explicit byte stores retain the low eight bits; explicit unsigned byte loads widen values in the range zero through 255. Halfword stores retain sixteen bits.

The final call results and retained values supply several address-like quantities, including a result multiplied by \(2^{25}\), another result shifted left by twenty-five, and a retained word shifted left by eight.

A separate small quantity is obtained by shifting a word left by eight, masking with 0x7fff, and shifting logically right by six. Under the 32-bit model, it ranges from zero through 508 in multiples of four. Its doubled value ranges from zero through 1016 in multiples of eight.

The first direct effects establish this ordering:

- The low byte of that high half is written at offset nine from a retained shifted base.

### Early global-state dependencies

After a word read and repeated stores through the doubled small base, the function reads the named global located at 0x05 and converts its value to an unsigned 32-bit word. **The global’s storage width is not established:** its declaration is absent. This is not equivalent evidence to an explicitly typed byte dereference.

That global read precedes the byte-directed write at fixed address 0x01. The latter receives the low byte of the doubled small quantity. The converted global value is retained as an address base for subsequent accesses at offsets 0x15 and 0x54.

Consequently:

- The global is sampled before the write at 0x01.
- The retained converted value, not a fresh global read, supplies those later bases.
- Whether accesses overlap depends partly on the unresolved global width and actual address relationships.

A word loaded at offset 0x54 from that retained base is itself retained before that field is overwritten. Call this loaded value the **retained field value**.

Subsequent fixed-global effects include a 32-bit write at 0x54 containing the retained field value shifted left by one, followed later by a byte-directed write at 0x15 containing the doubled small quantity’s low byte. Computed writes occur around these effects and may alias them.

The function writes 0x3a as a byte at the fourfold lookup address, as a halfword at the eightfold lookup address, and as a word at offset 0x20 from the fourfold address. These destinations are related by scaling, not established to coincide.

The fourfold retained field value is reduced by decimal 150. Call the result the **adjusted quantity**. Four times that adjusted quantity is the **adjusted base**.

At offset 0x20 from the adjusted base, the represented word-write order is 0x20, 0x2f, a widened explicit byte read from offset four of that base, and 0x20 again. The read occurs after the first two writes.

The function then loads the 32-bit **repeated-region base global**, located at 0x087fbbbc, before writing the word 0x20 at fixed address 0x60. The loaded base is retained for the repeated region; the global is not visibly reloaded there. A possible overlap with the write at 0x60 therefore does not justify replacing the retained base with post-write global contents.

Each repeated group has the same observable shape: a word payload store, two byte stores linking the repeated-region base and adjusted base by their low bytes, and a word store at offset 0x34 from the repeated-region base.

The initial group uses eight times the retained field value as its scaled destination base and final stored scaled value. Later groups instead use eight times the adjusted quantity. The repeated payload remains the fourfold lookup value.

## Acceptance examples

These are conditional static examples, not executed tests.

1. **Initial forwarding:** With second input one, the initial interaction receives the original first input, one, and 64.

2. **No zero bypass:** With second input zero, the third initial argument is zero; no visible early return follows from that input.

3. **Width-sensitive extraction:** Under 32-bit semantics, selecting the low twenty bits of 0xffffffff, shifting right by ten, and shifting left by six yields 0xffc0.

4. **Global-width restraint:** An account that treats the 0x05 global read as necessarily an 8-bit load is unsupported. If a declaration later establishes a wider object, the converted value may exceed 255.

5. **Early sampling:** If a permitted memory model makes the write at 0x01 overlap the 0x05 global, subsequent bases still use the value sampled before that write.

6. **Repeated-base snapshot:** If the write at 0x60 overlaps the repeated-region base global, the repeated region uses the already loaded base, not a replacement read after the store.

7. **Adjusted-byte relationship:** If the adjusted quantity is one and execution reaches the relevant write, the value written at 0x3a is 0x38. This does not imply character output.

8. **Current global changes:** If a computed store after initialization changes 0x67 to 0xab before one of its later reads, that consumption uses the current value, subject to any subsequent overlapping write. Reusing the original 0xa9 low byte is not equivalent.

9. **Duplicate effects:** Instrumented destinations can distinguish consecutive identical stores from a single store.

10. **Partial completion:** An inaccessible computed destination provides no clean-status or rollback guarantee.

11. **Final interaction:** If execution reaches a callable final target, its first represented argument is 0x72; normal return depends on that target.
