# F-72bae63f34c1

## Purpose

F-72bae63f34c1 conditionally updates a selector associated with a caller-supplied object, performs one of two selection-related actions, and invokes two subsequent operations in a fixed order.

The selector is a 32-bit value. The all-ones value, `0xffffffff`, selects a distinct path that bypasses validation and writes a 16-bit zero at an object-relative location obtained from shared state. Other values are accepted only when they are nonnegative under a signed 32-bit interpretation and strictly below a bound returned by a dependency.

**Established behavior:** rejection returns `0xffffffce`; completion of the accepted path returns zero.

**Inferred intent:** the all-ones selector may represent clearing or disabling a selection, while ordinary values may identify entries in a collection. Those meanings are not established by the available evidence. The contract below uses “sentinel” and “ordinary selector” without assigning application-level semantics.

## Interface

### Inputs

The function accepts two machine-width inputs:

| Input | Width | Interpretation |
|---|---:|---|
| Object address | 32 bits | Base address used to construct object-relative addresses and passed to dependencies. |
| Selector | 32 bits | Unsigned value for equality and bound comparisons; also interpreted as signed 32-bit for one validation condition. |

The object’s complete type, allocation size, alignment, and ownership are not supplied. The evidence establishes these object-relative locations:

| Relative offset | Use |
|---|---|
| `0x1c` | Destination of a 32-bit selector write on every accepted path. |
| `0x82c` | Address supplied as the third argument to F-8062d2b34921 on the ordinary-selector path. |
| `0xebc` | Address supplied to F-40e8ba582a34 during ordinary-selector validation. |
| Shared displacement | Destination of a 16-bit zero write on the sentinel path. The displacement is read from a shared 32-bit datum. |

The addresses at `0x82c` and `0xebc` are dependency arguments. Passing those addresses does not, by itself, establish the size or interpretation of the storage the dependencies access.

### Output

The result is a 32-bit value:

- `0x00000000` after the accepted path and all applicable dependency calls complete normally.
- `0xffffffce` when selector validation rejects the request. Under a signed 32-bit interpretation, this is −50.

No other explicit return value is established. Faults, nonreturning dependencies, or other abnormal execution can prevent either result from being returned.

### Preconditions and ownership

For defined, normally completing execution:

- Every direct read and write described below must address valid, suitably accessible storage.
- Object-relative address formation must be valid for the target execution environment.
- The shared displacement datum must be readable on the sentinel path.
- Each invoked dependency must receive arguments satisfying its own requirements.

This function contains no explicit allocation, deallocation, ownership-transfer operation, or null-address check. It does not establish whether any dependency retains a supplied address, releases storage, or changes object lifetime. Callers must not infer ownership guarantees from the absence of an explicit release in this function.

## Behavior

### Selector classification

The sentinel is exactly `0xffffffff`, interpreted as a 32-bit bit pattern.

All other selectors are classified using signed 32-bit interpretation before the bound dependency can be called:

- `0x00000000` through `0x7fffffff` proceed to bound validation.
- `0x80000000` through `0xfffffffe` are rejected immediately.
- `0xffffffff` bypasses both the signed-negative rejection and bound validation.

Thus, the sentinel is an explicit exception to the otherwise rejected signed-negative range.

### Immediate rejection

For a selector in `0x80000000` through `0xfffffffe`, the function returns `0xffffffce`.

On this path:

- F-40e8ba582a34 is not called.
- The shared displacement is not read.
- No object-relative write is performed by this function.
- None of the other listed dependencies is called.

The evidence contains no direct dereference of the object address on this path. This is a path-specific observation, not a general guarantee that arbitrary object addresses are valid inputs.

### Bound validation for ordinary selectors

For selectors from zero through `0x7fffffff`, the function calls F-40e8ba582a34 with the object address plus `0xebc`.

The available representation exposes a 64-bit result from this dependency. Only its low 32 bits affect acceptance. Let those low 32 bits be the bound.

The comparison is unsigned:

- A selector strictly less than the bound is accepted.
- A selector equal to or greater than the bound is rejected with `0xffffffce`.

No selector increment, multiplication, or narrowing precedes this comparison.

If the bound is zero, every ordinary selector is rejected. If the bound exceeds `0x7fffffff`, every selector in the ordinary nonnegative range is accepted. Larger non-sentinel selectors remain rejected by the earlier signed check, regardless of what bound the dependency might otherwise produce.

A rejection after bound validation performs no direct object write and invokes no later dependency. However, F-40e8ba582a34 has already run. Its side effects, if any, are not rolled back or characterized by this function.

The upper 32 bits of the dependency’s represented result do not affect any subsequent observable operation on the ordinary-selector path.

### Accepted ordinary selector

After successful bound validation, the function performs the following ordered actions:

1. Writes the selector as a 32-bit value at object offset `0x1c`.
2. Calls F-8062d2b34921 with the object address, the selector, and the object address plus `0x82c`, in that argument order.
3. Calls F-a96742fec78e with the object address.
4. Calls F-087700124fe9 with the object address.
5. Returns zero if all calls complete normally.

The selector write occurs after F-40e8ba582a34 returns and before F-8062d2b34921 is invoked.

This function does not inspect a result from any of the three post-validation dependencies. It contains no explicit rollback if those calls change state or encounter an error.

The write establishes the contents of offset `0x1c` at that point in execution. It does not guarantee that the same value remains there at return: any subsequent dependency may modify that storage.

### Sentinel selector

For selector `0xffffffff`, the function does not call F-40e8ba582a34 or F-8062d2b34921.

Instead, it performs these ordered actions:

1. Reads a shared 32-bit datum used as an object-relative displacement.
2. Writes `0xffffffff` as a 32-bit value at object offset `0x1c`.
3. Writes zero as a 16-bit value at the object address plus the previously read displacement.
4. Calls F-a96742fec78e with the object address.
5. Calls F-087700124fe9 with the object address.
6. Returns zero if both calls complete normally.

The shared displacement is read before either direct object write. The zero-write address therefore uses the value captured by that read, even if a subsequent write aliases and changes the shared datum.

No check establishes that the 16-bit destination is separate from offset `0x1c`. If the destinations overlap, the later zero write replaces the overlapping bytes of the earlier selector write. Consequently, the function does not unconditionally leave `0xffffffff` at offset `0x1c`, even before the final dependencies run.

The 16-bit write does not establish that adjacent bytes are cleared. Its direct write width is two bytes.

## Side effects

### Direct memory accesses

The function’s established direct accesses are:

- One shared 32-bit read on the sentinel path.
- One 32-bit write at object offset `0x1c` on every accepted path.
- One additional 16-bit zero write on the sentinel path.

No direct object-memory read is exposed in the supplied body. Dependencies may perform reads and writes that are not visible here.

### Dependency ordering

For an accepted ordinary selector, call order is:

F-40e8ba582a34 → selector write → F-8062d2b34921 → F-a96742fec78e → F-087700124fe9.

For the sentinel:

Shared displacement read → selector write → 16-bit zero write → F-a96742fec78e → F-087700124fe9.

These are function-level sequencing requirements. They do not establish atomicity, synchronization, cross-thread visibility, or machine-level memory barriers.

### Errors and partial progress

Validation rejection does not undo effects of a validation dependency that has already executed.

After acceptance, there is no explicit transactional protection. A failure during a later operation may occur after the selector write or sentinel zero write. The available evidence does not specify recovery, exception handling, or a returned error for such failures.

## Acceptance examples

These are conditional static acceptance criteria, not executed tests. Unless otherwise stated, addresses are valid and invoked dependencies return normally.

1. **Negative non-sentinel selector.**  
   Given selector `0xfffffffe`, return `0xffffffce` without calling any listed dependency and without a direct memory write.

2. **Zero bound.**  
   Given selector zero and a low 32-bit bound result of zero, call F-40e8ba582a34, then return `0xffffffce`. Do not write the selector field or call the remaining dependencies.

3. **Strict boundary.**  
   Given a bound of five, selector four is accepted; selector five is rejected. Acceptance writes four at offset `0x1c` before calling F-8062d2b34921 and the two final dependencies.

4. **Unsigned bound interpretation.**  
   Given selector `0x7fffffff` and bound `0x80000000`, accept the selector. Interpreting the bound as signed would produce the wrong decision.

5. **Signed selector gate remains independent of the bound.**  
   Given selector `0x80000000`, reject immediately without requesting a bound.

6. **Sentinel bypass.**  
   Given selector `0xffffffff`, read the shared displacement, write the sentinel at offset `0x1c`, write a 16-bit zero at the displacement-selected location, and call only F-a96742fec78e followed by F-087700124fe9.

7. **Sentinel destination overlaps the selector.**  
   If the shared displacement is `0x1c`, the sentinel write is followed by a two-byte zero write at the same starting address. Immediately before F-a96742fec78e, the first two addressed bytes of that field are zero. The numeric interpretation of the complete field depends on byte order.

8. **Later dependency changes the selector field.**  
   If an accepted-path dependency overwrites offset `0x1c` and returns normally, this function does not restore the earlier selector write. It proceeds with the remaining calls and returns zero.
