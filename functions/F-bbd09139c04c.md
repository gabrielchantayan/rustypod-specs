# F-bbd09139c04c

## Purpose

A more specific application purpose is not established. The representation contains unresolved indirect calls, incoming machine state not described by the formal arguments, overlapping global symbols, and truncated control-flow paths. It does not establish a conventional callable API with a complete calling convention.

This contract distinguishes:

- **Established static behavior:** reads, writes, value transformations, and call ordering explicitly represented.
- **Inferred intent:** possible interpretations that are not requirements.

The outer repetition is unconditional. No normal return, success result, or recoverable error result is represented.

## Behavior

### 1. Iteration entry and record sampling

Each outer iteration begins with an indirect call derived from the incoming address state. The returned pointer is treated as the base of a record containing 32-bit words.

The routine reads, in order:

1. A 32-bit word at record offset `+0`.
2. A 32-bit word at record offset `+8`.

The first word is retained for a possible later 16-bit store. The second word controls the main branch and also serves as a numeric address base on one path.

Three conditions are derived from the second word:

- Whether bit 13 is set.
- Whether its signed 32-bit value is negative.
- Whether its signed 32-bit value, arithmetically shifted right by 14, equals zero.

The last condition is true exactly for unsigned values from `0` through `0x00003fff`. In particular, negative signed values do not satisfy it.

The routine then invokes an indirect dependency with the address at record offset `+12`, followed by another indirect call, F-fd74adab24b4, F-172f180ab937, and two further indirect calls, in that order.

No record layout beyond these accesses is established. Passing the address at `+12` does not prove that the record has a particular total size or that the callee retains that address.

### 2. Path for second words outside `0..0x3fff`

When the shifted-value condition is false, the routine executes a sequence of unresolved calls. During this sequence it retains:

- The low 16 bits of the third argument.
- The 32-bit saved value from incoming frame offset `+0x26c`.

One call receives a fixed address token. The object, code, or data represented by that token is unknown.

After the call sequence, the routine compares the sampled negative condition against the incoming overflow-condition value. The branch expression also includes the shifted-value condition, but that condition is already false on this path.

#### Mismatched negative and overflow conditions

Under the literal represented dataflow, a mismatch enters an inner loop whose condition remains true. Each repetition:

1. Extracts the low byte of the retained 32-bit value.
2. Replaces that retained value with a fixed address token.
3. Executes two unresolved calls.

The first extracted byte therefore comes from the saved value; later extracted bytes come from the fixed token. The represented loop condition is never assigned a new value.

Consequently, under this literal model, this loop does not reach its following tail. External faults or non-returning dependencies can still interrupt it.

The representation nevertheless includes a tail after the loop: four unresolved calls, a byte write at saved-base offset `+13`, another call, a byte write at offset `+9`, another call, a byte write at offset `+17`, another call, a breakpoint with immediate `0xc9`, and invalid-instruction termination. The first two writes use the last extracted byte; the third uses an incoming byte of unknown provenance.

That tail is **not established as reachable**. Its existence is evidence of an incomplete or inconsistent control-flow representation, not a requirement that the byte writes or breakpoint occur.

#### Matching negative and overflow conditions

When the comparison does not select the inner loop, an unresolved call returns a base address. The routine writes the retained low 16 bits of the third argument at offset `+4` from that base.

Three further unresolved calls follow. The carried second-word value is then replaced by the saved 32-bit value at incoming frame offset `+0x260`, and execution reaches the shared iteration tail.

The narrowing is modulo `2^16`: upper bits of the third argument do not participate in the 16-bit write.

### 3. Path for second words in `0..0x3fff`

When the shifted-value condition is true:

1. An unresolved call produces a byte.
2. That byte is written at numeric address `second word + 21`.
3. Another unresolved call returns a base address.
4. The low 16 bits of the second word are written at that base’s offset `+60`.
5. An unresolved call executes.
6. A 16-bit value is read from `third argument + 52` and passed to another unresolved call.

Using the second word as an address is an explicit property of the representation. No validation of that address is shown. This contract does not reinterpret small numeric values as safe pointers.

An inner cycle then performs five unresolved calls. The fifth call’s result replaces the saved 32-bit value associated with frame offset `+0x260`.

#### Bit 13 clear

If bit 13 of the originally sampled second word is clear, the inner cycle exits after those five calls and reaches the shared iteration tail.

Given this path’s range restriction, this case corresponds to second-word values `0..0x1fff`.

#### Bit 13 set

If bit 13 is set, the routine continues with:

1. Setting the represented negative-condition temporary to false.
2. Calling F-a6f0b173d7d7.
3. Calling F-5ea954168e6c.
4. Calling F-e703b76f5649 and assigning its result to a global region.
5. Writing `199` to another global region.
6. Writing the current fourth argument to a third global region.
7. Writing the sampled second word to a fourth global region.
8. Executing an unresolved call.
9. Updating the first global region with a two-byte concatenation: the low byte of the current fourth argument becomes the high byte, and a byte read from the first global region supplies the low byte.
10. Calling an unresolved dependency and writing the low 16 bits of the retained first record word at its returned base’s offset `+28`.
11. Executing another unresolved call.
12. Reading an unsigned 16-bit value at offset `+20` from an additional register result, then zero-extending it to replace the retained first-word value.
13. Executing another unresolved call.
14. Reading an unsigned 16-bit value at offset `+12` from another additional register result, then zero-extending it to replace the fourth argument.
15. Executing another unresolved call.
16. Reading 16 bits at `third argument + 60` and passing that value to another unresolved call.
17. Executing two further unresolved calls.

The global-byte read in step 9 occurs after an intervening call. It must not be replaced conceptually with the low byte of the earlier F-e703b76f5649 result: the intervening dependency may modify that region.

A conditional exceptional path follows. It would call F-645d55f3a7e5 with the last returned address reduced by `201`, then enter invalid-instruction termination. Under the literal representation, however, its condition was set false earlier and is not reassigned. This exceptional path is therefore not reachable under that dataflow.

The inner cycle repeats. Its bit-13 condition is likewise never reassigned. Thus, for second-word values `0x2000..0x3fff`, the literal representation repeatedly performs this cycle rather than returning to the outer loop.

### 4. Shared iteration tail

Paths reaching the shared tail perform these actions in order:

1. Invoke an unresolved dependency with the current saved value associated with frame offset `+0x260`.
2. Replace the third argument with the saved value associated with offset `+0x268`.
3. Execute another unresolved call.
4. Replace the incoming call-base state with a fixed internal address token.
5. Replace the fourth argument with the saved value associated with offset `+0x270`.
6. Execute another unresolved call.
7. Replace the saved value associated with offset `+0x260` with the carried second-word value.
8. Begin the next outer iteration.

The saved value passed at step 1 and the value assigned at step 7 need not be equal. In the small-value path, step 1 uses an inner-cycle call result, while step 7 uses the sampled second word.
