# F-639865e28f2b

## Purpose

F-639865e28f2b conditionally dispatches a rectangular, row-oriented transfer through a configured callback and one of two data-processing paths.

The established behavior consists of:

- Checking whether a configuration pointer is present.
- Rejecting an odd width or a source address that is not four-byte aligned.
- Obtaining a 32-bit token from F-d0e18541f136.
- Invoking an indirect callback with two caller-supplied values and the requested dimensions.
- Processing each row according to a mode selector.
- Passing the token to F-daf9d4e01656 and returning zero if execution reaches the normal end.

One mode expands each consumed source byte into four 16-bit table values and passes those values individually to F-524e254fe930. Another delegates each row to F-798d9dab5826. Other modes perform no row-data calls but still execute the callback and token-related calls.

**Inferred intent:** the dimensions, row stride, two-bit extraction, and lookup table suggest a packed-data transfer operation. The evidence does not establish a particular device, pixel format, color interpretation, or destination.

## Interface

The function has seven arguments and a 32-bit return value.

| Position | Meaning used in this contract | Established representation |
|---|---|---|
| 1 | Source base address | Unsigned 32-bit value interpreted as an address |
| 2 | Row stride | Signed 32-bit value, used in 32-bit row-address arithmetic |
| 3 | Width | Unsigned 32-bit value |
| 4 | Row count | Unsigned 32-bit value |
| 5 | First callback value | Opaque 32-bit value |
| 6 | Second callback value | Opaque 32-bit value |
| 7 | Mode | Signed 32-bit value, compared against 2 and 52 |

The caller does not supply the destination of the transfer directly through an identified output pointer. Observable output is through the indirect callback and dependency calls.

The return values established by the supplied evidence are:

| Value | Condition |
|---|---|
| 11 | The configuration pointer read from the global root is null |
| 9 | Configuration is present, but the width is odd or the source address is not four-byte aligned |
| 0 | Validation passes and execution reaches the end after processing and the final dependency call |

Zero does not establish that a device accepted data, that a dependency succeeded, or that any source bytes were consumed. Dependency results other than the token are not used to determine the return value.

### Referenced layouts

Two global references are used.

**Configuration root**

The function first reads a global root address. At byte offset 4 from that root is a configuration pointer. A non-null configuration exposes at least:

- A one-byte field at byte offset 5.
- A callable pointer at byte offset 12.

The root must itself be readable even when its configuration pointer is null. The explicit null check applies to the configuration pointer, not to the root address.

**Lookup table**

A separate global reference supplies the base address of a table whose accessed entries are 16 bits wide and spaced two bytes apart. Only indices 0 through 3 are selected, so the accesses span an eight-byte table region.

No byte order, signed interpretation of table entries, or alignment tolerance is established beyond the displayed 16-bit accesses.

## Behavior

### 1. Configuration and argument checks

The function snapshots the global root address, then reads the configuration pointer at root offset 4.

If that pointer is null, the function returns 11. This takes precedence over argument validity: a missing configuration produces 11 even if the source address is misaligned or the width is odd.

If configuration is present, both of the following must hold:

- The width is even.
- The low two bits of the source address are zero.

Failure returns 9 without invoking the callback or any identified dependency.

These checks are limited. The function does not establish that:

- The source address is nonzero, mapped, readable, or large enough.
- Later row addresses remain four-byte aligned.
- The stride is positive or suitably aligned.
- The mode is supported.
- The width is a multiple of four.
- The callback pointer or table reference is valid.

A zero source address satisfies the alignment check. Whether later execution can safely use it depends on the selected mode, dimensions, and dependencies.

### 2. Token acquisition and callback

After successful validation, the function calls F-d0e18541f136 with the value zero and retains its 32-bit result.

The indirect callback is then invoked with five arguments, in this order:

1. The one-byte configuration field at offset 5.
2. The first caller-supplied callback value.
3. The second caller-supplied callback value.
4. The width.
5. The row count.

The callable address comes from configuration offset 12.

The callback is invoked once, before row processing, including when the width or row count is zero and when the mode is unsupported.

The configuration used here is read through the saved root after F-d0e18541f136 returns. Consequently, the initial non-null check does not guarantee that the same configuration remains installed for the callback. No second null check is shown.

The evidence identifies separate configuration-pointer accesses for locating the callback and its one-byte argument. It does not establish an atomic snapshot of the entire configuration or a guaranteed order between evaluation of those callback components.

### 3. Row iteration and address calculation

Rows are visited in increasing order, starting with row zero and stopping before the unsigned row count.

For each row, its source address is the source base plus the row index multiplied by the stride, calculated in the displayed 32-bit address domain. Multiplication and addition may wrap modulo \(2^{32}\); there is no overflow check.

Although the stride is declared signed, multiplication by the unsigned row index gives the displayed arithmetic unsigned 32-bit behavior. A negative stride can therefore describe descending addresses through its two’s-complement bit pattern, subject to wrapping and address validity.

The row address is calculated even for an unsupported mode. Calculating that address does not itself establish a source-memory read.

No comparison prevents rows from overlapping or revisiting the same address. A zero stride repeatedly selects the source base.

### 4. Mode 2: four table emissions per source byte

For mode 2, each row uses a counter that starts at zero and advances by four. A group is processed while that counter is less than the width.

Each completed group:

- Uses one source-byte address.
- Selects four two-bit indices in most-significant-to-least-significant order.
- Reads one 16-bit table value for each index.
- Calls F-524e254fe930 once per value, in that same order.
- Advances the source-byte address by one.

For a stable source byte, the selected fields are bits 7–6, 5–4, 3–2, and 1–0.

The body contains two distinct reads of the current source-byte address before the first emission:

- One byte is retained for the lower three indices.
- Another byte read supplies the uppermost index.

If memory remains stable, both reads observe the same byte. If it changes between those accesses, the first index can correspond to a different byte value from the other three. The function provides no synchronization guarantee for such changes.

#### Table-reference timing

The table reference is not treated as a single immutable value for the entire transfer.

At every inner-loop condition evaluation, the current global table reference is captured. For a group that executes:

- The first 16-bit value is read through another load of the global table reference.
- The remaining three 16-bit values are read through the reference captured at the condition.

Each table value is read before its corresponding F-524e254fe930 call. The function does not preload all four values before making those calls.

Thus, if F-524e254fe930 changes table contents, subsequent reads can observe the changed contents. If it changes the global table reference, the remaining three accesses in that group still use the previously captured reference. A later group captures the global reference again.

The table reference is also loaded on the final condition evaluation that ends a row. For width zero, each row still evaluates that condition and loads the reference, but performs no source-byte or table-entry reads.

#### Width rounding and nontermination boundary

For a positive width that terminates normally, each row consumes:

\[
\left\lceil \frac{\text{width}}{4} \right\rceil
\]

source-byte addresses and makes four times that many emission calls.

Only even widths pass validation. Therefore:

- Widths divisible by four produce exactly that many emissions per row.
- Widths congruent to two modulo four produce two more emissions than the width.

No partial final group is implemented.

There is an important 32-bit counter boundary. The largest reachable counter value before adding four wraps is `0xFFFFFFFC`.

For the accepted width `0xFFFFFFFE`, the counter never reaches a value greater than or equal to the width. It wraps to zero and continues. If at least one row is requested, this loop has no normal termination under the displayed arithmetic, assuming no dependency or memory access interrupts execution.

### 5. Mode 52: delegated rows

For mode 52, each row causes one call to F-798d9dab5826 with:

1. That row’s calculated source address.
2. The original width.

This includes calls with width zero.

The function does not inspect the dependency’s result or establish how many bytes it reads. In particular, the source-span requirement from mode 2 must not be applied to this mode without a separate contract for F-798d9dab5826.

### 6. Other modes

For any mode other than 2 or 52, the function iterates over the rows but invokes neither row-processing dependency.

It still:

- Performs the initial validation.
- Acquires the token.
- Invokes the callback with the original dimensions.
- Calculates row addresses.
- Calls the final token-taking dependency.
- Returns zero if execution reaches the end.

There is no unsupported-mode error.

### 7. Normal completion

After all rows finish, F-daf9d4e01656 is called once with the exact 32-bit token returned by F-d0e18541f136. The function then returns zero.

This final call is not shown as exception-safe cleanup. No guarantee is established that it executes after a fault, nonlocal exit, nonreturning dependency, or nonterminating row loop.

## Side effects

The function contains no direct writes to caller memory or the referenced global structures.

Its observable effects consist of reads and calls:

- Global-root and configuration reads.
- Callback-pointer and one-byte configuration-field reads.
- Mode-dependent source-byte and table reads.
- Calls to the identified dependencies and indirect callback.

Dependency and callback side effects are unknown. They may affect subsequent observations; the contract does not assume they preserve globals, table contents, or source memory.

No allocation, release, ownership transfer, or retention of caller memory is explicitly performed by this function. That does not establish the ownership behavior of its callees. In particular, the names “token acquisition” and “final token-taking call” describe the visible pairing, not a proven locking, interrupt-control, or resource-management protocol.

## Acceptance examples

These are conditional acceptance cases derived from static evidence, not executed tests. Except for early returns, they assume valid required addresses and normally returning callees.

1. **Missing configuration takes precedence.**  
   With a null configuration pointer, an odd width, and a misaligned source address, the result is 11. No identified dependency or callback is invoked.

2. **Odd width is rejected.**  
   With configuration present, an aligned source address, and width 3, the result is 9. Token acquisition and the callback do not occur.

3. **Misalignment is rejected even without rows.**  
   With configuration present, width zero, row count zero, and a source address whose low two bits are nonzero, the result is 9.

4. **Zero rows still execute setup and completion.**  
   With valid alignment and an even width, row count zero produces token acquisition, one callback, and the final token-taking call. Neither row-processing dependency is called. The result is zero.

5. **Stable mode-2 expansion.**  
   For width 4, one row, source byte `0x1B`, and stable table entries \(T_0\) through \(T_3\), the four emission arguments are \(T_0, T_1, T_2, T_3\), in that order.

6. **An accepted width need not be divisible by four.**  
   For mode 2, width 6, and one row, two source-byte addresses are consumed and eight emission calls occur. The function does not stop after six emissions.

7. **Zero-width mode 2 differs from zero-width mode 52.**  
   With a positive row count and width zero, mode 2 makes no emission calls. Mode 52 calls F-798d9dab5826 once for every row, passing zero as the width.

8. **Unsupported mode succeeds without row-data calls.**  
   For mode 7 and otherwise valid arguments, neither F-524e254fe930 nor F-798d9dab5826 is called. Setup, callback, and normal completion still occur, and the return value is zero.

9. **Negative stride can select descending rows.**  
   With source base `0x1000`, stride −4, and three rows, row addresses are `0x1000`, `0x0FFC`, and `0x0FF8`.

10. **Maximum accepted width can prevent completion.**  
    With mode 2, width `0xFFFFFFFE`, and a positive row count, the inner counter wraps without satisfying its exit condition. Normal completion and a zero return are not reached if execution otherwise continues.
