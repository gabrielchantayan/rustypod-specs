# F-e214f63ae031

## Purpose

F-e214f63ae031 conditionally narrows a stored interval, invokes an external operation on an embedded four-word region, advances two coordinates by 18, and conditionally applies further boundary handling.

The established behavior is an ordered sequence of state accesses and dependency calls. Interpreting the four-word region as a rectangle, the requested extent as a width, and the mode as an alignment choice is inferred intent, not a verified interface definition.

The function has no explicit result value. Its observable results consist of memory changes, dependency invocations, and any effects of those dependencies.

## Behavior

### 1. Determine whether to narrow the interval

The function first reads the interval start and then obtains the difference between the interval end and that saved start.

The requested extent is compared with this difference using a signed comparison.

- If the requested extent is greater than or equal to the difference, the entire mode-controlled adjustment is skipped.
- If the requested extent is strictly smaller, the mode word is read and converted to an eight-bit character value.

The initial interval start remains the saved value used by the narrowing calculation. This is not an unconditional reread of that slot.

Equality does not trigger narrowing. The mode is not examined on the skipped path.

### 2. Apply the selected narrowing behavior

Only character values 0, 1, and 2 have defined adjustment actions in the visible body. Other values leave both interval endpoints unchanged during this stage.

The character conversion, rather than the whole 32-bit mode word, controls selection. Under the evident eight-bit, low-bit-preserving interpretation, mode words with the same low eight bits select the same branch. Exact out-of-range signed-character conversion semantics are not independently established.

#### Mode 0: retain the start

The interval start is not directly written in this stage.

The interval end is replaced with the saved interval start plus the requested extent.

Provided the arithmetic is defined, this produces the requested endpoint difference while retaining the original start.

#### Mode 1: move both endpoints

The function calculates the excess of the original endpoint difference over the requested extent. It adds one to that excess, divides by two, and adds the result to the saved interval start.

The resulting start is written first. The interval end is then written as that new start plus the requested extent.

When the arithmetic remains representable, the narrowing condition makes the excess positive. The division therefore gives half the excess rounded upward. An odd excess shifts the start one unit farther than rounding downward would.

This produces a slightly biased centered narrowing, not necessarily a geometrically symmetric operation over integer coordinates.

#### Mode 2: retain the end

The interval start is replaced with the current interval end minus the requested extent.

The interval end is not directly written in this stage. Control proceeds immediately to the common dependency call.

#### Other mode values

Neither endpoint is directly changed during this stage. Execution still continues through the common processing below.

### 3. Invoke the dependency unconditionally

Every path reaching this point invokes F-d156b0b83eb3 with:

- A pointer to the embedded region at state offset 8.
- The 32-bit value 0xfffffff7.
- The same 32-bit value again.

Interpreted as signed 32-bit integers, the latter two values are both −9. Their semantic meaning is unknown.

This call occurs after any narrowing writes and before either subsequent addition of 18.

The call is unconditional with respect to the requested extent, mode, and later external-byte flag. Normal continuation nevertheless depends on the call returning.

### 4. Advance two boundaries

After the first dependency call returns, the function:

1. Reads the third boundary.
2. Adds 18 and writes that result to the third boundary.
3. Reads the interval end, adds 18, and writes the result to the interval end.

These operations use post-dependency state. The function must not be specified as preserving endpoint values across the call.

The incremented third-boundary value is also the value used for the later threshold decision. That decision is not based on a fresh third-boundary read.

### 5. Check the referenced object

The function next reads the referenced-object word from the state and reads a byte 168 bytes into the referenced object.

- Any nonzero byte causes an immediate return.
- A zero byte permits the remaining boundary handling.

The pointer-like word is read after the dependency call and after both additions of 18. It is not an entry-time snapshot.

A nonzero flag does not suppress the initial narrowing, the first dependency call, or the additions. It suppresses only the subsequent conditional call and first-boundary correction.

### 6. Optionally invoke the dependency again

If the external byte is zero, the function compares the previously calculated incremented third boundary with 235.

- A value strictly greater than 235 triggers another invocation of F-d156b0b83eb3.
- A value equal to or below 235 does not.

The supplied representation shows only the embedded-region pointer for this second invocation. It does not establish additional argument values, even though the earlier invocation visibly supplies three arguments.

The second call must not be described as implicitly repeating the two −9 arguments. Its full calling contract remains unknown.

### 7. Correct the first boundary when necessary

After the optional second call returns, or immediately if it was not required, the function checks whether the first boundary is less than 5 using a signed comparison.

If it is at least 5, execution returns without this correction.

If it is below 5:

- A correction equal to 5 minus the first boundary is calculated.
- The first boundary is increased by that correction.
- The interval start undergoes a visible read-and-write-back of its current value.
- The third boundary is increased by the correction.
- The interval end undergoes a visible read-and-write-back of its current value.
- The function returns.

For stable ordinary memory and representable arithmetic, the first boundary becomes exactly 5, and the third boundary moves by the same amount.

If the second dependency call ran, the correction uses the state after that call. No preservation of earlier coordinate values is assumed.

The self-assignments are present in the supplied representation. Whether distinct physical accesses survive compilation is not established.
