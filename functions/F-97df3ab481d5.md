# F-97df3ab481d5

## Purpose

F-97df3ab481d5 updates a caller-supplied memory region. It conditionally replaces five 32-bit fields with all-one bit patterns, then clears one byte-sized field and sets the following byte-sized field to one.

The condition is the initial value of the byte at offset `0x4D5` from the supplied base address. Any nonzero value selects the five-field update; zero skips that update. Both paths finish by writing zero at offset `0x4D5`, followed by one at offset `0x4D6`.

This describes a state transition, not an established application-level operation. The fields might represent reset markers, validity indicators, or another protocol, but their meanings are not established by the supplied evidence.

## Behavior

### Condition evaluation

The function first reads the single byte at offset `0x4D5` and compares it with zero.

This is a zero-versus-nonzero test, not a test for the particular value one. Values such as `0x02`, `0x80`, and `0xFF` select the same branch as `0x01`. Whether a byte is interpreted as signed or unsigned does not change this distinction.

No initial read of the byte at offset `0x4D6` is shown. Nor does the conditional update depend on the previous contents of the five 32-bit destinations.

### Nonzero condition

When the condition byte is nonzero, the function performs these writes in the following established order:

1. A 32-bit all-one pattern at offset `0xD4`.
2. A 32-bit all-one pattern at offset `0xE0`.
3. A 32-bit all-one pattern at offset `0xDC`.
4. A 32-bit all-one pattern at offset `0xD8`.
5. A 32-bit all-one pattern at offset `0xE4`.

Each written value has exactly 32 bits and is `0xFFFFFFFF`. This is the unsigned value 4,294,967,295; a signed interpretation may instead treat the pattern as −1. The function establishes the bit pattern, not the fields’ signedness or semantic meaning.

Because every bit is one, byte order does not affect the resulting four bytes of an individual destination: each becomes `0xFF`. Byte order also does not alter the ordering between the five destinations.

After those five writes, the function performs the common completion writes described below.

### Zero condition

When the condition byte is zero, the function skips all five 32-bit writes.

Their contents remain unchanged by this function on that path. The function still performs both common completion writes; the zero condition does not cause an early return.

### Common completion

On either path, the function:

1. Writes the 8-bit value zero at offset `0x4D5`.
2. Writes the 8-bit value one at offset `0x4D6`.
3. Returns without an explicit result.

These are full-byte assignments. They do not preserve other bits of either byte. For example, an initial value of `0xFE` at offset `0x4D6` becomes `0x01`, not `0xFF`.

Under valid, ordinary memory access with no interference, the final condition byte is therefore always zero and the following byte is always one.

### Repeated invocation

After a normally completed invocation, another invocation on the same unchanged region reads zero at offset `0x4D5`. It consequently skips the five 32-bit writes and repeats only the two byte writes.

Thus, absent intervening changes, repeated invocations preserve the state produced by the first invocation. This is a final-state property, not an absence of subsequent writes: the two byte assignments still occur.

These examples are conditional acceptance criteria derived from static evidence. They have not been executed. Unless stated otherwise, they assume valid ordinary memory, no concurrent modification, and normal completion.

### Nonzero byte selects every conditional write

Given an initial byte of `0x01` at offset `0x4D5`, arbitrary previous values in the five 32-bit fields, and any initial byte at offset `0x4D6`:

- All five 32-bit fields finish as `0xFFFFFFFF`.
- The conditional write order is `0xD4`, `0xE0`, `0xDC`, `0xD8`, then `0xE4`.

### Zero byte preserves the five fields

Given an initial zero byte at offset `0x4D5`, suppose the five 32-bit fields contain distinct values.

After completion, those five values are unchanged. Offset `0x4D5` is zero, and offset `0x4D6` is one regardless of its previous value. No writes to the five fields belong to this execution path.

### Existing all-one values do not suppress writes

Given a nonzero condition byte and five fields already containing `0xFFFFFFFF`, the conditional writes still occur. The function does not compare the fields with their intended replacement values.

### Adjacent bytes remain outside the write set

On normal execution over ordinary memory, bytes outside the five 32-bit destinations and the two byte destinations are unchanged by this function. In particular, writing one at offset `0x4D6` does not establish a wider write to neighboring bytes.

### A second invocation skips conditional replacement

After one successful invocation, change one of the five 32-bit fields without changing offset `0x4D5`. A subsequent invocation preserves that changed field because the condition byte remains zero.
