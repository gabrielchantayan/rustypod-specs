# F-479b289100a4

## Purpose

F-479b289100a4 adapts a caller-provided 16-bit unsigned value to a dependency that receives a writable 32-bit unsigned value. It converts the dependency’s outcome into one of two ordinary return values, or invokes a non-returning dependency when a successful operation produces a full-width zero.

The established behavior is a width-conversion and result-handling contract:

- Read the caller’s 16-bit value and zero-extend it to 32 bits.
- Pass that temporary value by address to F-3c7753130546, together with an opaque first argument.
- Return the 32-bit value 9 if that dependency returns a nonzero status.
- If the dependency returns zero, inspect the resulting 32-bit temporary. A zero value invokes F-a817d8d58c10 rather than returning normally.
- Otherwise, write the low 16 bits of the temporary to the caller’s location and return the 32-bit value 0.

The domain meaning of the input value, the transformed value, and the return codes is not established. Interpreting zero as an invalid or unavailable result is plausible intent, not a demonstrated domain rule.

## Behavior

### Initial read and widening

Before calling either dependency, F-479b289100a4 reads the unsigned 16-bit value at its second argument.

The temporary is distinct from the caller’s 16-bit storage. F-3c7753130546 receives the address of this temporary, not the second argument directly. A write through the supplied temporary address therefore does not itself constitute a write to the caller’s storage.

The initial read is unconditional on ordinary entry. In particular, a dependency outcome that would eventually select return value 9 does not remove the requirement for a valid initial read.

### Dependency invocation

1. The original opaque first argument.
2. The address of the initialized 32-bit unsigned temporary.

The dependency’s status is represented as a 32-bit integer in the supplied evidence. The wrapper distinguishes only zero from nonzero. It does not propagate individual nonzero status values.

### Nonzero dependency status

If F-3c7753130546 returns any nonzero status, F-479b289100a4 returns 9.

On this branch, the wrapper does not use the post-call temporary to decide whether to invoke F-a817d8d58c10, and it does not copy that temporary back to the caller.

Thus, a zero temporary does not by itself trigger the non-returning path. The dependency must also have returned zero.

The precise nonzero status is discarded. Positive and negative nonzero statuses have the same wrapper-level result.

### Zero dependency status

If F-3c7753130546 returns zero, the wrapper evaluates the full 32-bit unsigned temporary.

If that value is zero, it invokes F-a817d8d58c10 without explicit arguments. According to the supplied non-return annotation, control does not subsequently reach the caller-output write or an ordinary return.

If the value is nonzero, the wrapper narrows it to 16 bits and writes that result to the original second-argument address. It then returns 0.

### Width-sensitive behavior

The zero check precedes narrowing and covers all 32 bits. The later output conversion retains only the low 16 bits, equivalent to reduction modulo 65,536 for an unsigned 32-bit value.

Consequently:

- Values from 1 through 65,535 are written unchanged.
- Values above 65,535 are not rejected merely because they exceed the destination width.
- A nonzero value whose low 16 bits are zero produces a stored output of zero and an ordinary return of 0.
- The full-width value zero invokes F-a817d8d58c10 instead of storing zero.

There is no visible range check, saturation, overflow error, or retry.
