# F-65ddf49a9824

## Purpose

F-65ddf49a9824 conditionally dispatches an object-associated callback, constructs a four-word temporary record, and may pass that record through a sequence of processing functions. Its result is a 64-bit composition of the record’s first two words as they exist at return.

The established behavior is the conditional dispatch, record construction, ordered dependency calls, and final word composition. The meaning of the object, the record, the processing eligibility checks, and the returned pair is not established. In particular, the result must not be described as a success flag, owned allocation, or guaranteed pair of unchanged addresses.

This contract describes normal-return paths. It does not establish behavior after invalid memory access, dependency failure to return, or other exceptional control transfer.

## Interface

### Inputs

The function has four source-visible inputs:

| Input | Established use |
|---|---|
| Object address | Used for fixed-offset reads, address derivation, callback dispatch, and dependency arguments. |
| Second 32-bit word | Not referenced by the supplied function body. |
| Third 32-bit word | Stored in the temporary record, except that the optional callback path replaces it with the value 1. |
| Fourth input, represented as a callable address | Stored in the temporary record, except that the optional callback path replaces it with the callable address selected from the object. The incoming value is not directly invoked by this function. |

The supplied representation uses 32-bit integer words and a 64-bit return value. The four-word temporary record also supports a 32-bit pointer/address interpretation. These are properties of the supplied static representation, not an independently verified calling-convention specification.

The second input has no source-visible effect here. This does not imply that changing it is safe under every external ABI or that dependencies cannot observe unrelated process state.

### Object layout accessed directly

Offsets are byte offsets from the supplied object address:

| Offset | Access |
|---|---|
| `0x000` / 0 | Read as the base address of a dispatch table, only on the optional callback path. |
| `0x034` / 52 | Read as a 32-bit parent-like address or value, only after all processing gates pass. |
| `0x080` / 128 | Address derived and supplied to dependencies. This function does not directly read the contents at this offset. |
| `0x0A0` / 160 | Read as a 32-bit word, then narrowed to a character-sized value for a zero comparison. |
| `0x1E0` / 480 | Read as a 32-bit word and compared with zero to select the optional callback path. |

When dispatch occurs, a callable address is read at byte offset `0x16C` / 364 from the dispatch-table base obtained from object offset 0.

These accesses do not establish the complete object size or the complete layout of any nested structure. Nevertheless, every access reached during an invocation requires valid readable storage of the applicable width. Dependency calls may impose additional requirements not visible here.

### Temporary-record layout

The function creates a local record containing four consecutive 32-bit words:

| Record offset | Initial value |
|---|---|
| 0 | Original object address |
| 4 | Original object address plus 128 bytes |
| 8 | Effective third input |
| 12 | Effective callable address |

“Effective” means the incoming value unless the optional callback path has replaced it.

Dependencies receive the address of this record and may change its contents. The function performs no visible restoration of the initial values afterward.

### Output

On normal return, the function produces a 64-bit value with:

- the record’s current word at offset 0 in bits 31–0;
- the record’s current word at offset 4 in bits 63–32.

This is a composition of word values, not a specified in-memory serialization. No byte order for storing the 64-bit result is established.

If no dependency changes the first two record words, the low word is the original object address and the high word is the address 128 bytes beyond it.

## Behavior

### 1. Optional callback dispatch

The first source-visible operation is a read of the 32-bit word at object offset 480.

If that word is zero, the function skips the callback path. The third input and fourth input retain their incoming values for subsequent record construction.

If the word is nonzero, the function performs the following ordered actions:

1. Calls F-004c5654fd0a with no source-visible explicit arguments.
2. Retains that call’s 32-bit result for the callback.
3. Replaces the effective third input with 1.
4. Reads the dispatch-table base from object offset 0.
5. Reads the callable address at dispatch-table offset 364 and replaces the effective fourth input with that address.
6. Calls the selected callable with the original object address and the result from F-004c5654fd0a.

The callable is resolved **after** F-004c5654fd0a returns. Consequently, any changes that dependency makes to the object’s dispatch-related state can affect the callback selection.

The initially read nonzero word controls entry into this path. The function does not reread it to reconsider dispatch after the dependency call.

No callback return value is used by the remaining visible logic. No null check or callable-validity check is visible before invocation.

### 2. Record construction

After the optional callback returns, or immediately if dispatch was skipped, the function initializes the four-word temporary record described above.

The record uses the original object address and the address 128 bytes beyond it. It does not copy the contents of the object’s region at offset 128.

The callback runs before record construction. It can therefore affect object fields and external state that will be examined later, but it has not been passed this record by the visible function at that point.

### 3. Ordered processing gates

The function next calls F-3fac671648b8 with no source-visible explicit arguments.

Further processing occurs only if all of the following conditions hold, in order:

1. F-3fac671648b8 returns nonzero.
2. The character-sized narrowing of the 32-bit word read at object offset 160 equals zero.
3. A byte read through an external global pointer is nonzero.

These conditions use short-circuit evaluation:

- If F-3fac671648b8 returns zero, neither the offset-160 test nor the external-byte test is performed by this gate.
- If the offset-160 test fails, the external-byte test is not performed.
- The external byte is examined only after both earlier tests succeed.

The offset-160 condition is not a test that the whole 32-bit word equals zero. Under the represented character narrowing, the low eight bits determine whether the narrowed value is zero. For example, a word value of `0x00000100` satisfies that zero test, whereas `0x00000101` does not.

The gate call occurs after record initialization. Its effects on object or external state are not assumed absent merely because it receives no explicit arguments.

If any gate fails, the function skips all processing described below and proceeds to compose its return value from the record.

### 4. Processing when all gates pass

First, the function reads and saves the 32-bit value at original object offset 52. This saved value determines a later optional call.

It then calls F-e57b05520b65 with three explicit arguments:

- the address of the temporary record;
- the original object address plus 128 bytes;
- that same original object address plus 128 bytes again.

The second and third arguments are equal addresses. Their equality does not establish whether the dependency reads, writes, copies, or otherwise interprets the referenced region.

If the previously saved offset-52 value was nonzero, the function then calls F-ee8733a08210 with:

- the address of the same temporary record;
- the saved value plus `0xD0` / 208 bytes.

The offset-52 value is captured **before** F-e57b05520b65 runs. A change to that object field during the call does not alter whether the subsequent call occurs or the base value used for its second argument.

Next, the function calls F-ffe0d92c57b7 with the original object address.

If its result is zero, the remaining two processing calls are skipped. If its result is nonzero, the function makes these calls in order:

1. F-c9b5d17d8d1e, receiving that result and the temporary-record address.
2. F-4d037ecf0f82, receiving the same saved result and the same temporary-record address.

There is no visible retest or recomputation of the saved result between these two calls. Changes made to the record by the first call are available to the second. The first call’s return value does not control whether the second is invoked.

Throughout this processing sequence, directly derived object arguments continue to use the original object address. Changing the record’s first word does not redirect those arguments.

### 5. Return composition

After the selected call sequence completes, the function composes its return value from the record’s current first and second words.

The third and fourth record words are not directly included in the return value. They may still influence the result through dependency behavior.

## Side effects

The function’s direct writes are to its local record and local effective input values. No direct assignment to object storage or to the external global byte is visible.

Observable effects can nevertheless include:

- reads from the object and dispatch table;
- a conditional indirect callback;
- a conditional read through an external global pointer;
- ordered calls to dependencies;
- changes made by those callees to the object, record, globals, or other reachable state.

No dependency is assumed to preserve globals, preserve object contents, or leave record fields unchanged.

The function does not visibly allocate, release, or transfer ownership of heap storage. It passes addresses, but that alone does not establish ownership transfer.

The temporary record has invocation-local lifetime. The visible body does not extend that lifetime. Whether dependencies retain its address is unknown; retaining it for use after this invocation returns would require a lifetime mechanism not shown here.

The object address, derived addresses, and callback-related addresses have no visible ownership annotations. The function does not establish whether they are borrowed, shared, or managed under another convention.

## Acceptance examples

These examples are conditional static expectations, not reports of executed tests. All assume valid reached memory accesses and normal return from every invoked dependency.

### Dispatch skipped and processing rejected

Given a zero word at object offset 480 and a zero result from F-3fac671648b8:

- F-004c5654fd0a and the indirect callback are not called.
- The record receives the incoming third and fourth values.
- The gate does not read object offset 160 or the external byte.
- None of the five gated processing dependencies is called.
- If no invoked dependency changes the first two record words through another means, the return contains the original object address below the address advanced by 128 bytes.

### Dispatch enabled

Given a nonzero word at offset 480:

- F-004c5654fd0a runs before dispatch-table resolution.
- The selected callback receives the original object address and that dependency’s result.
- The subsequently constructed record contains 1 in its third word and the selected callable address in its fourth word.
- The incoming fourth input is not the callback selected by this path merely because it was supplied as an argument.

If F-004c5654fd0a changes the object’s dispatch-table address, callback selection uses the subsequently read address.

### Character narrowing controls the second gate

Given a nonzero result from F-3fac671648b8:

- An offset-160 word of `0x00000100` permits evaluation of the external-byte gate.
- An offset-160 word of `0x00000101` blocks processing and suppresses that external-byte read.

These expectations concern the narrowed value, not an assumed byte location within the word.

### Captured parent-like value remains decisive

Suppose all gates pass and the value read at offset 52 is a nonzero address value P.

If F-e57b05520b65 then changes the object’s offset-52 field to zero, F-ee8733a08210 is still called using P advanced by 208 bytes.

Conversely, if the captured value was zero, changing that field to nonzero during F-e57b05520b65 does not enable the optional call.

### Record changes propagate and determine the return

Suppose F-ffe0d92c57b7 returns a nonzero value H.

Both final dependencies receive H and the same record address, in the stated order. If the first changes record fields, the second observes those changes unless it changes or ignores them itself.

If the final first two words are A and B, the returned 64-bit composition has A in its low half and B in its high half. It is not required to retain the initially stored addresses.
