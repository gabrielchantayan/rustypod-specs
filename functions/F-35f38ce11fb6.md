# F-35f38ce11fb6

## Purpose

F-35f38ce11fb6 performs a forward transfer of three-word records from a source range into consecutive destination positions. It returns the destination position reached after traversal.

Each word is 32 bits, making each record 96 bits, or 12 bytes. Record contents are copied without arithmetic conversion or interpretation.

Traversal stops when the current source position equals the supplied exclusive end position. The function does not determine a record count, compare address ordering, validate the range, or handle a partial final record.

The established behavior is an ordered sequence of record transfers, not a general overlap-safe move. All three values of the current record are read before that record’s writes, but earlier destination writes can change source records that have not yet been read.

A null current destination suppresses that iteration’s record reads and writes. It does not stop traversal or suppress pointer advancement. This conditional branch does not establish support for a null destination over a nonempty range.

## Interface

### Inputs

The function receives three pointer-valued arguments:

| Input | Meaning |
|---|---|
| Source start | Initial position of the source traversal |
| Source end | Exclusive stopping position, tested by equality |
| Destination start | Initial position of the destination traversal |

Source and destination positions advance in units of 32-bit words. A record has the following layout:

| Record component | Byte offset | Access width |
|---|---:|---:|
| First word | 0 | 32 bits |
| Second word | 4 | 32 bits |
| Third word | 8 | 32 bits |

No application-level field meanings are established. In particular, these words are not established as integers, pointers, characters, floating-point values, or resources requiring special treatment.

The representation and width of the pointer arguments are not established by the supplied evidence. The 32-bit width of a transferred word must not be taken as evidence that pointers are also 32 bits.

### Return value

The return value is the destination position after one three-word advancement for each completed iteration.

For a traversal of \(N\) records with valid pointer arithmetic, the returned position is \(3N\) words, or \(12N\) bytes, beyond the initial destination position. This describes the displacement; the body does not calculate an integer record count or multiply it by 12.

When source start equals source end on entry, the return value equals destination start, without advancement.

There is no separate status result, error code, source position, or transferred-record count.

### Preconditions for ordinary successful use

For a conventional transfer into a nonnull destination:

- The source end must be reachable from the source start by a finite sequence of three-word advances.
- Every encountered source record must permit the required three 32-bit reads.
- Every encountered destination record must permit the required three 32-bit writes.
- Alignment must satisfy the execution environment’s requirements for those accesses.
- All pointer advances must be valid, including advances after the last transferred record.
- Source values must remain available when their reads occur. If initial source contents must be preserved in the output, destination writes must not corrupt unread source records.

The function does not check these conditions.

The final source and destination positions need not themselves be dereferenced. For example, a destination position immediately beyond its writable region can be a valid return position if forming that pointer is permitted.

Accessible, valid storage is an execution precondition. It does not establish who owns the storage or which party has a contractual obligation to manage its lifetime.

## Behavior

### Range control

Before the first iteration, the function compares the current source position with source end.

If the positions are equal, it returns immediately. There are no record reads, record writes, or pointer advances on this path.

If they differ, it processes one iteration. The destination advances by three words after the conditional transfer. The source then advances by three words, and the equality comparison is repeated.

The termination condition is equality only. There is no ordered comparison that stops traversal when the current position passes an address boundary.

Consequently:

- An end position below the source start is not explicitly rejected.
- An end position that is not reachable by three-word steps is not explicitly rejected.
- A trailing region shorter than one record is not recognized or copied specially.
- Such inputs have no established successful finite-range interpretation. Invalid access, invalid arithmetic, or other environment-dependent consequences may occur before equality is reached.

No wrapping behavior may be assumed to make an otherwise unreachable end reachable.

### Nonnull destination: per-record access sequence

For an iteration whose current destination is nonnull, the static representation establishes this logical sequence:

1. Read the source word at byte offset 4.
2. Read the source word at byte offset 8.
3. Read the source word at byte offset 0.
4. Write the first source value to destination byte offset 0.
5. Write the retained second source value to destination byte offset 4.
6. Write the retained third source value to destination byte offset 8.

All three source values for the current record are obtained before any destination word is written for that record.

The words are transferred without content-dependent branching, transformation, comparison, or validation.

After the last write, destination advancement occurs, followed by source advancement and the next source/end comparison. The advanced destination is not accessed if the next comparison ends traversal.

This sequence describes the supplied static representation. It does not establish physical bus transactions, instruction scheduling, access atomicity, or ordering guarantees for concurrent or device-memory observers.

### Null destination: skipped transfer, continued traversal

The current destination is tested for null separately on every iteration.

If it is null:

- None of the current record’s three source words is read.
- None of the current record’s destination words is written.
- The destination still advances by three words.
- The source still advances by three words.
- Traversal continues subject to the next source/end comparison.

The check applies to the current destination, not permanently to the original destination argument. A null initial destination therefore does not establish a discard-output mode.

The evidence does not establish whether advancing a null pointer is valid or what position results. Under an explicitly assumed flat-address model where zero advances to byte address 12, a second iteration would test that new position and could attempt a transfer there. That is a conditional illustration, not a supported portable contract.

### Overlap

Within a single record, the read-before-write sequence preserves the three values obtained for that iteration even when its destination overlaps its source.

Across records, preservation is not guaranteed. An earlier destination record can overwrite a later source record. The later iteration then reads the modified contents rather than the original contents.

Exact source/destination identity is not a special case. For every nonempty iteration with a nonnull destination, the function still performs the stated reads and writes.

The output for overlapping ranges must therefore be determined from the forward access sequence, not from an assumption that the entire original source range was retained before writing began.

### Invalid accesses and partial effects

The body contains no explicit access validation, fault handling, rollback, or recovery path.

If an access fails or execution is interrupted, earlier writes may already be visible. Neither whole-range atomicity nor whole-record atomicity is established.

For example, in the logical access sequence, failure while reading the second source word occurs before any write for that iteration. Failure during the second destination write can occur after the first destination word has already changed. Actual fault delivery and recoverability remain properties of the execution environment.

## Side effects

For each completed iteration with a nonnull destination, the body explicitly reads three 32-bit source words and writes three 32-bit destination words.

For an iteration with a null destination, it performs no record-content accesses through either position. It still compares and advances traversal positions as described above.

Destination writes can affect source storage or other caller-visible storage when the supplied regions alias. There is no separate explicit write through the source position.

## Acceptance examples

These are conditional expectations derived from static evidence. No runtime tests have been performed. Unless a case states otherwise, assume accessible ordinary memory, valid alignment and pointer arithmetic, and no concurrent modification.

### Empty range

**Given:** Source start equals source end. Destination start may be null or nonnull.

**Expected:** No record contents are read or written. Neither traversal position advances. The returned destination equals destination start.

This case does not require interpreting null-pointer advancement because no advancement occurs.

### One disjoint record

**Given:** The source contains three distinct 32-bit values A, B, and C. Source end is one record beyond source start. The destination is a separate writable record.

**Expected:** The destination contains A, B, and C in that order. The return value is one record, or 12 bytes, beyond destination start.

The logical source-read order is B, C, A; the destination-write order is A, B, C.

### Two disjoint records

**Given:** The source records contain A/B/C and D/E/F. The end position follows the second record. The destination has two writable records.

**Expected:** The output records contain A/B/C and D/E/F. The first record’s writes precede the second record’s reads. The returned destination is 24 bytes beyond its initial position. No third record is accessed.

### Identical source and destination

**Given:** Source and destination start at the same nonnull position, with one complete record in the range.

**Expected:** The three values are read and written back to the same positions. The destination advances by 12 bytes and is returned.

Skipping all memory accesses solely because the starting positions match would not reproduce the established access behavior.

### Overlap within one record

**Given:** A single source record contains A/B/C. Destination start is one word after source start, and sufficient storage exists for all accesses.

**Expected:** The three destination words become A/B/C. Although the writes overlap the original second and third source words, those values were read before writing began.

### Earlier output overwrites the next input

**Given:** Two source records initially contain A/B/C and D/E/F. Destination start is the beginning of the second source record, with sufficient writable storage beyond it.

**Expected:** The first iteration replaces the second source record with A/B/C. The second iteration reads that replacement record and writes A/B/C into the next destination record. Both output records contain A/B/C.

Expecting D/E/F in the second output would incorrectly assume whole-range overlap protection.

### One-record range with null destination

**Given:** Source start differs from source end by one record, and destination start is null.

**Established behavior:** The record transfer is skipped. No source-word read or destination-word write occurs. Destination advancement and source advancement are still attempted.

**Conditional result:** Successful completion and the returned destination depend on a defined interpretation of null-pointer advancement. Without that prerequisite, no portable successful-result expectation is established.

### End position between record boundaries

**Given:** Source end is one word beyond source start rather than a whole-record displacement.

**Expected limitation:** The function does not perform a one-word transfer or report a malformed range. It begins a three-word iteration if the positions differ. No valid finite completion is guaranteed; further consequences depend on storage and pointer rules.
