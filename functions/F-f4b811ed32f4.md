# F-f4b811ed32f4

## Purpose

F-f4b811ed32f4 coordinates two dependency calls and conditionally writes a 32-bit output value. Its established behavior is:

- Prepare a zero-initialized 32-bit intermediate value and a separate 32-bit working value initialized from the third argument.
- Invoke F-4e6cefe281de with an address derived from the first argument, the second and fourth arguments, and access to the intermediate value.
- If that dependency returns zero, return the 32-bit value 3 without invoking F-549523844097 or directly writing the caller’s output location.
- Otherwise, invoke F-549523844097 with the intermediate value, two quantities derived by unsigned shifts, access to the working value, and the final two arguments.
- After the second dependency returns normally, write the working value shifted left by nine bits to the caller’s output location, then return the second dependency’s result.

The shifts and rounding expression suggest a conversion involving units of 512. That interpretation is inferred intent, not an established semantic designation: the supplied evidence does not identify the quantities as bytes, sectors, blocks, offsets, or lengths.

## Interface

The interface has seven positional arguments and returns one 32-bit value. The descriptive names below identify argument roles within this contract; they do not establish external domain meanings.

| Position | Contract name | Representation and use |
|---|---|---|
| 1 | Base value | Shown as a signed 32-bit integer. Used to derive an address-like value by adding 0x3EC, and also passed unchanged to the first dependency. |
| 2 | Context word | An uninterpreted 32-bit value. Passed twice to the first dependency. |
| 3 | Initial quantity | An unsigned 32-bit integer. Copied into a working value and independently shifted right by nine bits for the second dependency. |
| 4 | Extent word | Shown as a signed 32-bit integer. Passed unchanged to the first dependency; separately interpreted through unsigned 32-bit arithmetic when constructing an argument for the second dependency. |
| 5 | Output location | A pointer to a 32-bit integer object. Receives one direct write only on the path where the first dependency returns nonzero and the second dependency returns normally. |
| 6 | Auxiliary word A | An uninterpreted 32-bit value forwarded to the second dependency. |
| 7 | Auxiliary word B | An uninterpreted 32-bit value forwarded to the second dependency. |

The return value is a 32-bit word. The supplied evidence does not establish a signed interpretation or a complete status-code vocabulary.

Two temporary 32-bit objects are used:

- An intermediate word, initially zero, whose address is supplied to the first dependency.
- A working word, initially equal to the initial quantity, whose address is supplied to the second dependency.

These are distinct storage objects. Neither is the caller’s output object.

### Preconditions

The wrapper performs no explicit argument validation.

For a normal execution that reaches the final output write, the output location must designate writable storage suitable for a 32-bit integer store. The wrapper does not read that object before overwriting it.

The base value and other dependency arguments must satisfy whatever requirements the dependencies impose. Their validity rules are not available here. In particular, the wrapper’s failure to dereference a derived address directly does not establish that an invalid derived address is safe to pass.

No null-output exception is implemented. A null or otherwise invalid output location can avoid a direct wrapper write if the first dependency returns zero, but that does not establish safety for the execution as a whole.

## Behavior

### 1. Prepare temporary state

Before invoking either dependency, the wrapper establishes:

- The intermediate word contains zero.
- The working word contains the original unsigned 32-bit initial quantity.

This initialization matters independently of dependency behavior. The intermediate word remains zero if the first dependency returns without changing it through its supplied address. Similarly, the working word retains the original initial quantity if the second dependency returns without changing it.

The working word is not initialized to the initial quantity divided by 512.

### 2. Invoke the first dependency

F-4e6cefe281de receives six arguments, in this positional order:

1. The base value plus 0x3EC, an offset of 1004.
2. The context word.
3. The address of the intermediate word.
4. The extent word, unchanged.
5. The original base value.
6. The same context word supplied in position 2.

The address-like first argument and the original base value are both passed. One is not substituted for the other. The two context arguments carry the same input value.

This positional order does not specify the machine-level order in which argument expressions are evaluated. The established sequencing is that the temporary initialization precedes the call, and the call completes before its return value is tested.

The first dependency’s result is used only as a zero-versus-nonzero discriminator. Its particular nonzero value is not returned by this wrapper.

### 3. Handle a zero result

If F-4e6cefe281de returns zero:

- F-549523844097 is not called.
- The wrapper returns the 32-bit value 3.
- The wrapper performs no direct write through the output location.
- The initialized or subsequently modified temporary values are not returned as outputs.

The value 3 is an established wrapper-selected result. Calling it a particular error category would require additional evidence.

“No direct output write” is narrower than “no side effects.” The first dependency has already run and may have effects that are not described by the supplied material.

### 4. Construct the second call

If F-4e6cefe281de returns any nonzero value, F-549523844097 receives six arguments:

1. The intermediate word as it exists after the first dependency returns.
2. The original initial quantity shifted right by nine bits.
3. The extent word after unsigned 32-bit addition of 511, followed by a right shift of nine bits.
4. The address of the working word.
5. Auxiliary word A.
6. Auxiliary word B.

The second argument uses an unsigned logical right shift. For an initial quantity \(Q\),

\[
\text{second argument}=\left\lfloor Q/512\right\rfloor.
\]

Consequently, its low nine input bits are discarded. No alignment check or rejection of those bits is present.

For the third argument, let \(E\) be the extent word interpreted as an unsigned 32-bit value:

\[
\text{third argument}
=
\left\lfloor
\frac{(E+511)\bmod 2^{32}}{512}
\right\rfloor.
\]

The unsigned addition is performed before the shift. The operation is not an unbounded mathematical ceiling division. It behaves like rounding a nonnegative quantity upward to a count of 512-unit groups only where the addition does not overflow.

The original signed presentation of the extent word does not cause a signed right shift here. The unsigned addition determines the arithmetic used for this expression.

The working word passed by address still starts from the original initial quantity. It is separate from the shifted copy supplied as the second argument.

### 5. Write the output and return

After F-549523844097 returns normally:

1. Its 32-bit return value is retained for the wrapper’s return.
2. The current working word is read.
3. That unsigned 32-bit word is shifted left by nine bits.
4. The resulting 32-bit pattern is written through the output location.
5. The retained dependency result is returned.

For a working value \(W\), the written bit pattern is:

\[
(W \times 512)\bmod 2^{32}.
\]

The upper nine bits of \(W\) do not survive this transformation. The output’s low nine bits are always zero after a completed direct write.

The output object is presented as a signed 32-bit integer object. The stored pattern may therefore be interpreted by consumers as a negative value. The wrapper contains no saturation, overflow rejection, or nonnegative-range check.

The second dependency’s return value does not gate the write. Zero, nonzero, and any externally interpreted failure result all lead to the same direct output-write step if the dependency returns normally.

## Side effects

The wrapper’s established direct externally visible memory effect is one 32-bit store through the output location on the second-call path.

Its sequencing guarantees are:

- The first dependency runs before any second dependency call.
- The first dependency can update the intermediate word before that word is supplied to the second dependency.
- The second dependency can update the working word before the wrapper reads it for the output conversion.
- The final output store occurs after the second dependency returns and before the wrapper returns normally.

The wrapper does not directly read or write fields at the derived address. It passes that address-like value to the first dependency.

The caller’s previous output value is not used to compute the replacement. There is no direct read-modify-write operation on that object.

Both dependencies may have additional effects, including effects on shared state or storage reachable through their arguments. No preservation of globals, resources, or unrelated memory is established. In particular, statements about absence of wrapper writes must not be expanded into claims that dependencies leave the same storage unchanged.

The wrapper contains no explicit allocation, deallocation, resource release, or ownership-transfer operation. It supplies addresses of temporary storage during dependency calls. Those objects do not become caller-owned persistent outputs. Whether either dependency retains those addresses is unknown; the wrapper provides no visible mechanism to make retained access valid after its invocation ends.

No rollback is shown. A dependency’s effects are not undone when the wrapper returns 3 or when the second dependency returns a result interpreted elsewhere as an error.

## Acceptance examples

These examples are conditional static acceptance criteria, not reports of executed tests. Unless stated otherwise, assume valid storage, normally returning dependencies, and no dependency effects beyond those specified in the example.

1. **First dependency returns zero.**  
   The first dependency observes an intermediate word initially equal to zero. If it returns zero, the wrapper returns 3, does not call the second dependency, and does not directly modify the output object. A caller-provided sentinel remains unchanged if the first dependency does not independently affect it.

2. **Nonzero first result without an intermediate update.**  
   If the first dependency returns a nonzero value without changing the intermediate word, the second dependency receives zero as its first argument. The wrapper does not reject that combination.

3. **Distinct shifted and address-passed quantities.**  
   With initial quantity 1537 and extent word 513, the second dependency receives 3 as its second argument and 2 as its third argument. At call entry, its fourth argument points to a working word containing 1537, not 3.

4. **Second dependency supplies an output quantity.**  
   If the second dependency changes the working word to 7 and returns a 32-bit result \(R\), the wrapper writes 3584 to the output and returns \(R\).

5. **Second dependency leaves the working word unchanged.**  
   With initial quantity 1537, if the second dependency does not modify the working word, the wrapper writes 786944. This follows from shifting the original working value, not from shifting the separately computed value 3.

6. **Extent rounding boundaries.**  
   Extent words 0, 1, 512, and 513 produce third arguments of 0, 1, 1, and 2, respectively.

7. **Extent addition overflow.**  
   An extent bit pattern of 0xFFFFFFFF produces zero as the third argument: adding 511 wraps to 510 before shifting. A contract that instead requires a large ceiling-divided result would not match the supplied expression.

8. **Output truncation.**  
   A post-call working word of 0x00800000 produces an output pattern of zero. A working word of 0x00400000 produces 0x80000000; the wrapper does not reject that sign-bit-setting result.

9. **Unconditional write after the second call.**  
   If the second dependency returns zero and sets the working word to 2, the wrapper writes 1024 and returns zero. No wrapper-level interpretation of zero suppresses the store.
