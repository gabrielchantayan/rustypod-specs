# F-4a97cdd4a498

## Purpose

F-4a97cdd4a498 replaces two selected bytes with the least significant sixteen bits of an input value. Its destinations come from implicit address-bearing state, not from either explicit argument. Normal completion produces a 32-bit zero result.

When the relevant state remains unchanged, the replacements occupy byte offsets 8 and 9 from the supplied base, with the less significant byte at the lower address. This establishes a little-endian arrangement of the selected bits. It does not establish the identity or meaning of a containing field.

The operation is not necessarily a contiguous two-byte update. Destination selection uses two observations of the implicit state: an earlier observation determines the destination at displacement 9, and a later observation determines the destination at displacement 8. Different observations can therefore select separate or overlapping destinations.

## Interface

### Explicit inputs and result

The represented interface has two 32-bit inputs and a 32-bit result.

The first input is unused. It supplies neither replacement data nor an address, and its value does not influence the represented behavior. In particular, this function imposes no requirement that the first input identify valid storage. Requirements imposed by callers or an external calling convention are outside the available evidence.

The second input supplies two eight-bit replacement patterns:

- Bits 0 through 7 supply the byte written first.
- Bits 8 through 15 supply the byte written second.
- Bits 16 through 31 do not contribute to either replacement.

The second replacement is selected using an unsigned interpretation of the 32-bit input. A caller’s signed interpretation of that input does not introduce sign extension into the selected byte.

The normal result is zero across all 32 bits. It is not a byte count, a previous value, a validation result, or an indication that the two destinations were adjacent.

### Implicit input and storage layout

An external address-bearing state supplies both destination bases. Its declaration, initialization, ownership, and permitted values are unavailable.

For this contract:

- The **earlier base** is the first represented observation of that state.
- The **later base** is the observation used to select the first write’s destination.
- The **first destination** is at byte displacement 8 from the later base.
- The **second destination** is at byte displacement 9 from the earlier base.

The earlier base is retained in a signed 32-bit representation. The declaration governing the later base is not supplied, so its full arithmetic and conversion rules are unresolved.

Each destination receives one byte. The offsets do not establish a structure type, a minimum allocation size, or permission to access any other part of an object.

### Preconditions and ownership

For normal completion, both effective destinations must support their respective byte writes when accessed. Their storage must remain live, and all required address calculations and conversions must be valid in the applicable execution environment.

The body performs no allocation, release, ownership transfer, or lifetime management. It does not establish who owns either destination or who must eventually release its storage.

A valid first destination does not imply a valid second destination. Nor does a successful write establish the validity of the containing object beyond that access.

## Behavior

### Replacement semantics

Each selected destination byte is replaced completely. Existing destination contents do not contribute to the replacement value. There is no merge, increment, mask preserving old bits, or conditional omission of a write whose replacement equals the existing value.

The first write carries the less significant input byte. The second write carries the next input byte. Both writes precede a normal return.

Under stable-base conditions, successful completion places the input’s least significant sixteen bits at offsets 8 and 9 in little-endian order. This describes byte arrangement only; it does not identify a numeric field, device register, protocol element, or application operation.

### Observation and write ordering

The represented access relationships are:

- The earlier base observation precedes the later base observation.
- Both observations precede the first destination write.
- The first destination write precedes the second destination write.
- The second destination continues to depend on the retained earlier base.

These relationships matter independently of final memory contents. There is no comparison of the two base observations, consistency check, retry, or repair.

A change in the implicit state between observations can redirect the first destination without redirecting the second destination to the same new base. A change after both observations does not itself change either already-selected destination.

This is a contract for the represented access relationships, not a claim about a particular number of machine load instructions. Volatile qualification and compiler or hardware ordering guarantees are not supplied.

### Separate and overlapping destinations

Different base observations need not produce adjacent destinations or increasing address order. The less significant byte is still written first, even if its effective address is greater than the second destination’s address.

The destinations can also coincide. If the later base is one byte greater than the earlier base, both displacements select the same address, assuming valid arithmetic and address conversion.

For ordinary memory at a coincident destination, successful completion leaves the second replacement byte as the final value. The first replacement is nevertheless part of the represented behavior. This distinction must be retained where individual writes can have externally visible effects.

No guarantee is made that another observer sees an indivisible sixteen-bit replacement. The operation contains an intermediate state after the first write and before the second. Whether another observer may legally observe that state depends on environmental rules absent from the evidence.

### Arithmetic boundaries

Input-bit selection and destination arithmetic are separate concerns. Ignoring the input’s upper sixteen bits does not establish any particular address width or wrapping rule.

The signed 32-bit retention of the earlier base is significant. It does not justify treating that base as an unrestricted wider pointer or treating displacement 9 as an unsigned modular addition. The later base’s arithmetic type is unavailable.

The following remain **documented_only**:

- Behavior when signed address arithmetic exceeds its representable range.
- Whether an address requiring more than 32 bits can be represented without information loss.
- The address interpretation of negative retained values.
- Wrapping at address-space boundaries.
- Integer-to-address conversion outside cases supported by the target environment.
- Full language-level conversion rules for byte values and address-bearing state.

No required success case relies on overflow, truncation, or wrapping to obtain a usable destination.

### Completion and failure

There is no explicit validation or alternate error result. Zero is required on normal completion; it is not promised for executions in which an access cannot complete.

The failure mechanism is **documented_only**. The evidence does not select a fault, trap, exception, recoverable error, or other response.

There is no rollback. If the first write completes and the second does not, no restoration of the first destination is provided. Neither a normal return nor a recoverable partial-update state is guaranteed.

## Side effects

The explicit modifications are two ordered byte writes. For distinct destinations in ordinary writable memory, with no relevant aliasing, these writes replace exactly the selected bytes. There are no other explicit destination writes.

The previous contents of those destinations are not read to construct the replacement values. This does not exclude aliasing between destination storage and storage read for another purpose.

In particular, a destination may overlap the implicit state’s storage. There is no direct assignment to that state, but preservation of its contents is conditional on the absence of such overlap. If the first write changes that storage, both represented base observations have already occurred; the second destination still derives from the retained earlier observation.

The legality and broader consequences of overlap remain **documented_only** because the relevant declarations, object boundaries, and memory rules are unavailable.

No calls, allocation, release, logging, explicit locking, barriers, or recovery actions appear in the body. Special memory may attach additional effects to a byte access. An unchanged final value therefore does not establish that a write was effect-free.

## Acceptance examples

These are conditional requirements derived from static evidence, not runtime observations. Unless stated otherwise, assume ordinary writable memory, valid representable addresses, no relevant aliasing, stable implicit state, and successful completion.

### Ordinary replacement

For a second input of hexadecimal **1234ABCD**, offset 8 receives **CD** and offset 9 receives **AB**. The normal result is a 32-bit zero.

Inputs **0000ABCD** and **FFFFABCD** produce the same replacement bytes under matching destination conditions. Their different upper sixteen bits do not affect the update.

### Selection boundaries

For input **00000100**, offset 8 receives **00** and offset 9 receives **01**.

For either **00000000** or **80000000**, both replacements are **00**. The highest input bit lies outside the selected portion.

For **0000FFFF**, both replacements have all eight bits set. Prior destination contents do not alter these outcomes.

### Unused first input

Holding the second input and relevant environment fixed, changing only the first input does not change either destination, either replacement, or the normal result.

This remains true when the changed first input would not identify valid storage, because the body does not use it as an address.

### Different base observations

Suppose a defined environmental mechanism supplies an earlier base of hexadecimal **1000** and a later base of **2000**, with both resulting destinations valid.

For input **0000ABCD**, the first write stores **CD** at **2008**. The second write stores **AB** at **1009**. Successful completion returns zero.

Acceptance must not require adjacency or a shared base. This example does not authorize an otherwise invalid concurrent modification.

### Coincident destinations

Suppose the earlier base is **1000** and the later base is **1001**, with both destination calculations valid.

For input **0000ABCD**, address **1009** receives **CD** first and **AB** second. In ordinary memory, its final value is **AB**.

Acceptance must retain both writes rather than replacing them with a single final-value requirement.

### Existing values and partial completion

If a destination already contains its replacement value, the represented write still occurs.

If the first write completes but the second cannot complete, acceptance must not require restoration of the first byte or delivery of the normal zero result. Failure delivery and subsequent control flow remain **documented_only**.
