# F-7f8725d25c5c

## Purpose

F-7f8725d25c5c repeatedly invokes unresolved dependencies and performs interleaved byte and four-byte memory accesses. Its established behavior is an ordered sequence of calls, address calculations, reads, writes, and loop-carried state updates.

No application-level purpose is established. Describing the routine as an allocator, serializer, initializer, or container operation would exceed the evidence.

The visible loop has no exit condition or normal return. Continued execution depends on dependencies returning and memory accesses completing. No recovery behavior is shown for invalid targets, inaccessible memory, dependency failure, or external interruption.

## Interface

### Explicit inputs

| Position | Represented width | Established use |
|---|---:|---|
| First | 32 bits | No explicit use in the visible body. |
| Second | 32 bits | Initially supplied twice to the iteration’s first dependency call and stored as a four-byte value. Replaced at each completed iteration. |
| Third | 32 bits | Initially supplied as the third argument of that call. Replaced with the updated second input at each completed iteration. |
| Fourth | 8 bits | Used in four byte stores per iteration. Its working value becomes zero near the iteration boundary. |

The second and third inputs are represented as signed integers. The fourth is an uninterpreted byte, not an established Boolean. The absence of explicit use of the first input does not establish independence from ambient register state at dependency boundaries.

### Implicit inputs and loop-carried state

The routine also depends on:

- An incoming link/control value.
- Dependency results, including represented 64-bit results.
- An additional register-derived argument without a complete producer contract.
- One global word sampled during each completed iteration.
- Memory at calculated addresses, including bytes used to select subsequent destinations.

The link/control value is working state, not an immutable entry input. Only the first iteration’s first call uses its incoming value. Before the final no-explicit-argument call of an iteration, the routine replaces that working control value with the fixed embedded anchor `0x0882d167`. Consequently, a subsequent iteration’s first target is calculated from that anchor.

### Outputs, access widths, and prerequisites

There is no visible normal result. Observable outputs consist of calls and memory effects.

Direct memory accesses are one byte or four bytes wide. Represented 64-bit dependency results are split into low and high 32-bit halves; they do not establish eight-byte memory accesses.

Safe progress requires callable calculated targets and accessible storage for every reached access. No visible validation enforces these requirements. Ownership, lifetime, alignment rules, byte order, and fault behavior are not established.

### Arithmetic conventions

The descriptions below distinguish represented operations from conditional fixed-width conclusions.

For acceptance examples and explicitly qualified simplifications, **word arithmetic** means 32-bit arithmetic retaining the low 32 bits after multiplication or left shift. Unsigned right shifts insert zeros. This is not a claim that every represented signed expression has defined overflow or left-shift behavior in a source language.

A **scaled-word destination** selected by a result means address \(20 + 4 \times \text{result}\).

A **byte-selected destination** means: read an unsigned byte from the stated source address, then add 17 to its value. Such a destination ranges numerically from 17 through 272.

Four-byte reads and writes describe width only. They may be unaligned, overlap other accesses, or fault.

## Behavior

### Call notation and ordering

**F-unresolved-01** identifies the unresolved dependency target set. It does not assert that different call sites invoke the same function.

A **four-call continuation** means four consecutive calls with no explicit arguments; its result, when used, is the fourth call’s result. Every call remains observable, including those whose results are discarded.

“No explicit arguments” describes the supplied representation, not a verified ABI. It does not establish independence from registers, memory, globals, or earlier calls.

The following phases occur in order on every reached iteration. Descriptive labels identify retained values, not source-level identifiers.

### 1. Initial word propagation and byte-base selection

The iteration’s first call receives the working second input twice and the working third input once, in that order. Its target is the working link/control value plus `0xffe`.

On the first iteration, this calculation uses the incoming control value. On subsequent iterations, it uses the fixed anchor installed near the preceding iteration’s end, making the calculated target `0x0882e165`.

A four-call continuation follows. Its final result selects a scaled-word destination where the working second input is stored.

The routine calls a dependency with four times that result, then performs another four-call continuation. Call its final result the **initial selector**. The routine writes four times the initial selector at address \(20 + 16 \times \text{initial selector}\).

The **initial byte base** is the initial selector multiplied by \(2^{30}\). Under word arithmetic, this base depends only on the selector’s lowest two bits; it is not established as an object pointer.

A dependency then receives three identical arguments, each four times the initial selector. A four-call continuation produces the **early destination selector**. At its scaled-word destination, the routine stores four times the initial selector.

A call receiving four times the early destination selector, followed by a four-call continuation, produces the unsigned **first packed value**.

Finally, the working fourth input is written first at the initial byte base plus 17, then at that base plus 1.

### 2. Repeated byte initialization and packed lookup

A dependency receives the first packed value shifted left by two. A no-explicit-argument call follows, and its result is passed to another dependency. A four-call continuation follows that call.

The routine repeats the byte stores at the initial byte base plus 17 and then plus 1. These stores are not redundant: intervening dependencies may have changed either location.

The latest continuation result, shifted left by two, is passed to a dependency. Another four-call continuation produces the **lookup destination selector**. The routine stores the early destination selector shifted left by 31 at address \(20 + 16 \times \text{lookup destination selector}\).

It then reads an unsigned four-byte word at:

\[
20 + ((\text{first packed value} \mathbin{\&} \text{0x3fffffff}) \gg 20).
\]

This is the **lookup word**. The offset ranges from 0 through 1023, so its starting address ranges from 20 through 1043. Four-byte alignment is not guaranteed.

Four times the lookup destination selector is retained for a later dependency call.

### 3. Lookup-derived arguments and separately sampled selectors

A dependency receives four times the lookup destination selector. A no-explicit-argument call produces the **retained value**.

The next argument-bearing call receives the lookup word shifted right by 22 and then left by 28. Under word arithmetic, only lookup-word bits 22 through 25 survive in this argument. A four-call continuation follows, and the routine writes a zero four-byte word to its final result’s scaled-word destination.

A call receiving four times that destination selector, followed by a four-call continuation, produces the unsigned **second packed value**.

The routine reads the byte at the initial byte base plus 1 and writes the low byte of the second packed value shifted left by two to the corresponding byte-selected destination.

A dependency receives that full shifted value. A no-explicit-argument call follows; its result and the second packed value shifted left by 30 become the next call’s two arguments. A four-call continuation follows.

The routine reads the byte at the initial byte base plus 1 again, retaining this reading as the **saved selector**. At the saved selector plus 17, it writes the low byte of:

\[
(\text{second packed value} \mathbin{\&} \text{0x3fffffff}) \gg 20.
\]

The latest continuation result, shifted left by two, is passed to a dependency, followed by four no-explicit-argument calls whose results are not used for the next destination.

The retained value shifted left by two is then stored as four bytes at the saved selector plus 20. This store uses the saved byte; it does not reread the selector source after the intervening calls.

The routine next samples the global word.

### 4. Global-derived byte propagation and first expansion

The routine reads the byte at the initial byte base plus 1. At the corresponding byte-selected destination, it stores the low byte of the sampled global word shifted right by 22. Changes to the global after its sampling do not change this retained word.

A dependency receives the 64-bit result’s high half. A no-explicit-argument call follows. Its result and the first expanded value shifted left by 28 become the next call’s arguments. A four-call continuation follows.

The routine rereads the byte at the initial byte base plus 1 and writes zero at the corresponding byte-selected destination.

A call receiving the latest continuation result shifted left by two, followed by another four-call continuation, completes this phase.

The **second propagated word** is the third selector shifted left by 14. It is stored at:

A four-call continuation follows. The second propagated word is stored at its final result’s scaled-word destination.

The routine reads the byte at the secondary byte base plus 1 and stores the low byte of:

\[
(\text{second propagated word} \mathbin{\&} \text{0x3fffffff}) \gg 20

at the corresponding byte-selected destination.

A dependency receives the third selector shifted left by 26. A no-explicit-argument call follows. Its result and the final expanded value shifted left by 28 become the next call’s arguments.

The next no-explicit-argument call produces a represented 64-bit result. Its low and high halves are passed, in that order, to another dependency. Two no-explicit-argument calls follow.

The routine rereads the byte at the secondary byte base plus 1 and writes zero at the corresponding byte-selected destination.

A dependency receives the latest result shifted left by two, followed by a four-call continuation. Four times its final result becomes the **final propagated word**, which is stored at \(20 + 4096 \times \text{final expanded value}\).

The next dependency receives four arguments:

- The final expanded value multiplied by 1024.
- The same value again.
- The unscaled result underlying the final expanded value, shifted left by 14.
- The final propagated word.

A four-call continuation follows. The final propagated word is stored at its final result’s scaled-word destination.

A dependency then receives four times that destination selector. Four no-explicit-argument calls follow, but there is an important state update between the third and fourth:

- The first three calls complete in order.
- The working link/control value becomes the fixed embedded anchor `0x0882d167`.
- The fourth call is invoked using its separately established call-site target.

The newly assigned control value is not the target base for that fourth call. It is carried into the next iteration’s first target calculation. The assignment precedes the fourth call, so it has already occurred if that call fails to return.

If the fourth call returns, four times its result becomes the working second input. The working fourth input becomes zero. The updated second input is stored at address \(20 + 16 \times \text{fourth-call result}\). The working third input then becomes equal to the updated second input.

Execution repeats. Thus every iteration after a completed first iteration begins with three equal explicit call arguments and the fixed-anchor-derived first-call target.

## Side effects

No direct allocation, release, cleanup, or ownership transfer is shown. Dependencies may perform such operations; their contracts are unavailable.

There is no visible transaction or rollback. If execution stops partway through an iteration, preceding calls and writes have already occurred.

Aliasing is unrestricted by the evidence. A store may affect a later selector source, another destination, or dependency-visible state. No atomicity, synchronization, volatility, or permission to reorder accesses across calls is established.
