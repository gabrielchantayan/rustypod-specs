# F-f0413c7c1c9d

## Purpose

F-f0413c7c1c9d processes a token stream, applies an opening gate, incrementally updates a caller-associated result record, and handles selected sections according to numeric token classifications.

Font-metrics parsing is inferred intent. The opening gate passes an address whose supplied source label suggests `StartFontMetrics` to a dependency. The stored bytes at that address and the dependency’s comparison semantics are not supplied. Consequently, this contract does not establish an exact textual opening marker.

The function is not transactional. Successful field assignments can survive later failures. Some exits invoke a common cleanup sequence; others return without it. A zero return can follow cleanup and does not necessarily establish that a normal termination token was encountered.

## Interface

### Context input

The function accepts one context address. Its directly observed layout contains at least three consecutive 32-bit words:

| Byte offset | Width | Direct use |
|---|---:|---|
| 0 | 32 bits | Captured at entry and later supplied as the first argument to F-bf7242c98d06. |
| 4 | 32 bits | No direct access established. |
| 8 | 32 bits | Result-record address, captured at entry. |

The result-record address is read first, followed by the word at offset 0. Both reads occur before the null-result check returns.

There is no explicit null-context check. A readable context is therefore a precondition, including when its result-record address is zero.

The context is also passed to dependencies. Their additional layout and accessibility requirements are unknown.

### Result-record layout

A nonzero result-record address must support the accesses below. The directly accessed extent is 44 bytes.

| Byte offset | Width | Direct behavior |
|---|---:|---|
| 0 | 8 bits | Receives the low byte of a parsed value; cleared by common cleanup. |
| 1–3 | — | No direct access established. |
| 4 | 32 bits | Receives the first value of an accepted four-value parse. |
| 8 | 32 bits | Receives the second value. |
| 12 | 32 bits | Receives the third value. |
| 16 | 32 bits | Receives the fourth value. |
| 20 | 32 bits | Receives the value parsed for class 0. |
| 24 | 32 bits | Receives the value parsed for class 14. |

| 32 | 32 bits | Cleared by common cleanup. |
| 36 | 32 bits | Read for a second cleanup dependency call, then cleared. |

The context values and result address captured at entry remain the function’s direct operands. They are not reloaded from the context after dependency calls.

The supplied representation uses 32-bit address-bearing values and 32-bit scalar values. Valid storage, suitable alignment, and valid dependency-accessible objects are preconditions rather than validated properties.

### Return value

The return is a 32-bit status-like value. Its pointer-shaped representation does not establish that callers should dereference it.

| Value | Established circumstance |
|---:|---|
| 0 | Direct accepted termination, or certain cleanup exits after a successfully consumed class-45 section. |
| 2 | Opening gate fails. |
| 6 | Captured result-record address is zero. |
| 7 | A successful class-40 scalar read yields a value other than 0 or 2. |
| 160 | Initial retained status; also restored during class-45 consumption and nested-loop reads. |

No separate error-output parameter is established.

## Behavior

### Entry and opening gate

After capturing the result address and context word, the function returns 6 if the result address is zero. No dependency is called on that path.

Otherwise, it calls F-d170ccdbf474 with the context, mode 1, and an address for a 32-bit length output.

Opening acceptance requires:

1. A nonzero return from F-d170ccdbf474.
2. A reported length equal to 16.
3. A zero return from F-fca51b715561 when called with the acquired value, the fixed marker address, and the numeric argument 16.

The third call is made only if the first two conditions hold. Any opening-gate failure returns 2 directly, without common cleanup or direct result-record writes.

This establishes an exact numeric length check and a dependency call-and-return condition. It does **not** establish byte equality, how the dependency interprets 16, which memory it accesses, or whether it implements comparison at all. The apparent marker text `StartFontMetrics` is inferred from a source label, not independently supplied storage contents.

### Main dispatch

Each main-loop iteration calls F-d170ccdbf474 with the context, mode 1, and a length-output address. A zero return enters common cleanup using the retained status.

A nonzero return is passed with the reported length to F-6493565b29fa. Its classification determines the following action:

| Class, decimal | Action |
|---:|---|
| 0 | Request one tag-2 value; on exact count 1, write its 32-bit value at offset 20. |
| 14 | Request one tag-2 value; on exact count 1, write its 32-bit value at offset 24. |
| 20 | Return 0 directly. |
| 26 | Request four tag-2 values; on exact count 4, write offsets 4, 8, 12, and 16 in that order. |
| 30 | Request one tag-4 value; on exact count 1, write its low eight bits at offset 0. |
| 40 | Read a scalar and accept only 0 or 2. |
| 45 | Consume a counted region and then scan for a terminator. |
| 49 | Enter the nested-section loop. |
| Any other value | Continue the main loop without another direct action. |

Unrecognized classes are not errors in this loop.

### Descriptor-based value parsing

F-a6914e5780de receives the context, temporary descriptor storage, and the requested value count.

The observed descriptor slots are eight bytes apart. Each contains a one-byte tag at its start and a 32-bit result location four bytes after that start. Initialization of the intervening bytes is not established.

For classes 0, 14, and 30, the function requires a return count exactly equal to 1. For class 26, it requires exactly 4. Any other return count enters common cleanup without replacing the retained status with that count.

Direct record assignments happen only after the exact count is accepted. In particular, a class-26 parse returning fewer or more than four produces none of the four direct assignments. On acceptance, all four writes occur in ascending offset order.

Class 30 explicitly narrows the parsed result to eight bits. Its upper 24 bits are not written to the record.

### Class-40 scalar restriction

The function calls F-fba1a377729c with the context and a 32-bit output location.

A nonzero dependency return enters common cleanup with the existing retained status; the dependency’s return is not propagated.

A zero dependency return permits inspection of the output:

- Output 0 or 2 resumes main parsing without a direct record write.
- Every other 32-bit value selects status 7 and enters common cleanup.

### Class-45 counted region

The function first calls F-fba1a377729c for a 32-bit count. A nonzero return enters common cleanup with the existing retained status.

After a zero return, the count controls an unclassified discard phase:

- Count zero skips directly to the terminator scan.
- A nonzero count causes a token request in mode 1 with no length-output address.
- After that request returns, the retained status is set to 160 and the count is decremented by one.
- A zero token result returns 160 directly, without common cleanup.
- A nonzero token result repeats the discard phase unless the decremented count is zero.

Discarded tokens are not classified. A token that would classify as a terminator has no special effect while it is being discarded.

The subsequent terminator scan requests tokens with length outputs. After each request and before testing its result, it sets the retained status to 160.

A zero result returns 160 directly, without common cleanup. A nonzero result is classified. Classes other than 17 and 20 continue this scan. Either class 17 or class 20 sets the retained status to zero and resumes the main loop.

Thus class 20 ends the entire function in the main loop, but ends only the scan when encountered inside this section.

There is no explicit rejection of negative counts. The behavior of decrementing across the signed minimum is unresolved by the supplied representation; no wraparound-based termination guarantee is made.

### Class-49 nested loop

Class 49 transfers control to a separate token-processing loop. Successful nested processing does not return to the main dispatch loop.

Each iteration requests a token and length, then sets the retained status to 160 before examining the result. A zero token result enters common cleanup.

For nonzero results:

| Class, decimal | Action |
|---:|---|
| 50 or 51 | Call F-8565c7c8dcf8 with the context. |
| 53 | Call F-b559a2688dcc with the context. |
| 75 | Continue the nested loop. |
| 20 or 21 | Return 0 directly, without common cleanup. |
| Any other value | Enter common cleanup with status 160. |

Each section dependency’s return replaces the retained status. Zero continues the nested loop; nonzero enters common cleanup and is returned afterward. Before the next nested token is examined, the loop restores status 160.

### Retained-status effects

The retained status initially equals 160. Main-loop token acquisition, classification, successful record assignments, and accepted class-40 outputs do not independently reset it.

A completed class-45 scan changes it to zero. Consequently, a later main-loop input failure, an unexpected descriptor count, or a nonzero scalar-reader return can enter common cleanup and still return zero.

This is established behavior, not an interpretation of zero as proof that all parsing succeeded.

### Common cleanup order

When reached, common cleanup performs this sequence:

1. Read the 32-bit field at offset 28 and call F-bf7242c98d06 with the captured context word and that field value.
2. Clear the 32-bit field at offset 28.
3. Clear the 32-bit field at offset 32.
4. Read the 32-bit field at offset 36 and call F-bf7242c98d06 with the captured context word and that newly read value.
5. Clear the 32-bit field at offset 36.
6. Clear the 32-bit field at offset 40.
7. Clear the byte at offset 0.
8. Return the retained status.

Both dependency calls occur even if their second arguments are zero. Their return values are ignored.

The offset-36 value is read after the first dependency call and the first two clears. It is not snapshotted alongside the offset-28 value. Any mutation by the first dependency can therefore affect the second argument.

The cleanup sequence does not directly clear offsets 4 through 24. Those fields retain earlier values unless a dependency changes them.

## Side effects

Record updates are incremental. Repeated recognized tokens overwrite their corresponding fields after successful parsing. There is no direct initialization of the entire record.

Stream position and other context state may change through dependency calls. The function performs no visible direct allocation and no explicit release of acquired token values.

The two calls to F-bf7242c98d06 occupy release-like positions, but their actual ownership and lifetime effects are unknown. No ownership transfer or preservation guarantee is established for the context, record, tokens, descriptor outputs, or shared state.

Common cleanup is bypassed by:

- The null-result exit.
- Opening-gate failures.
- Main-loop class 20.
- Nested-loop classes 20 and 21.
- Failed token acquisition during either class-45 consumption phase.

A class-45 scalar-reader failure instead enters common cleanup.

Dependencies must not be assumed to preserve result fields, context contents, globals, or other reachable memory. Direct-write statements in this contract describe this function’s own accesses, not the complete effects of its callees.

## Acceptance examples

These are conditional static acceptance cases, not executed tests. Dependencies are assumed to complete normally and provide the stated outputs. Record observations additionally assume no unmentioned dependency mutation.

1. **Null result address.** A readable context with zero at offset 8 returns 6. The word at offset 0 is still read. No dependency is called.

2. **Opening length rejection.** A nonzero opening acquisition with reported length 15 returns 2. F-fca51b715561 is not called, and common cleanup is bypassed.

3. **Opening dependency controls acceptance.** With a nonzero acquisition and reported length 16, F-fca51b715561 receives the acquired value, fixed marker address, and 16. A nonzero return produces status 2; zero permits main parsing. Neither outcome establishes a byte-equality relation.

4. **Immediate main termination.** An accepted opening followed by main-loop class 20 returns zero without direct clearing of existing record fields.

5. **Byte narrowing.** Class 30 with exact parse count 1 and result 0x123 writes 0x23 at offset 0. A subsequent main-loop class 20 leaves that byte in place.

6. **Four-value boundary.** Class 26 with return count 3 performs none of its four direct assignments and enters cleanup. Count 4 writes all four results in offset order.

7. **Restricted scalar.** A successful class-40 scalar read yielding 1 selects status 7 and cleanup. Outputs 0 and 2 continue main parsing.

8. **Counted discard.** Class 45 with count 2 and two nonzero discarded acquisitions performs no classification of those two values. Only subsequent scan acquisitions are classified.

9. **Zero-count scan.** Class 45 with count zero immediately starts the terminator scan. Scan class 17 or 20 resumes main parsing with retained status zero.

10. **Zero-status cleanup.** Following a completed class-45 scan, a zero main-loop acquisition invokes common cleanup and returns zero.

11. **Discard failure.** Class 45 with count 2 and a zero first discarded acquisition returns 160 without common cleanup.

12. **Nested propagation.** After class 49, nested class 53 followed by dependency status 9 invokes cleanup and returns 9.

13. **Cleanup read timing.** If the first cleanup dependency changes offset 36, the second call receives the changed value, subject to any effects of the intervening clears. The function does not reuse a value read before the first call.
