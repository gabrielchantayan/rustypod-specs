# F-c094d2e457a6

## Purpose

F-c094d2e457a6 performs an ordered sequence of initialization, indirect dispatch, state checking, and two external operations on an object-like memory region.

On the normal path, it clears a 32-bit state field, passes two existing 32-bit fields through a helper, and invokes an external routine with a destination at offset +0x30. It then reads the resulting fields at +0x30 and +0x34, constructs a second pair of 32-bit values, and invokes the same external routine with a destination at +0x40.

**Inferred intent:** the second pair resembles a view of the latter half of a range: its first value is a base advanced by half a length, and its second value is that half-length. This interpretation is not an established ownership, buffer, or range contract. Neither external operation is established to be a copy.

The alternate path invokes two dependencies when a state field is nonzero. The supplied static representation marks the second dependency as non-returning.

### 5. Construction of the second pair

After the first external invocation returns, the function constructs a new temporary pair from the object’s then-current fields.

For its first element:

- It reads the 32-bit value at +0x30.
- It reads the 32-bit value at +0x34 as unsigned.
- It logically shifts that unsigned value right by one bit.
- It adds the shifted result to the value from +0x30.

The addition operates in the recovered 32-bit unsigned arithmetic domain. Its low 32 bits become the stored first element; carry beyond bit 31 is discarded. No overflow check is visible.

For its second element, the function reads +0x34 again and logically shifts that unsigned value right by one bit.

Thus, the two halves are not necessarily derived from the same memory read. If +0x34 remains stable, both calculations use the same floor-divided-by-two value. If it changes between reads, the resulting pair can reflect different values.

The relative evaluation order of the +0x30 read and the first +0x34 read within the addition is not established by the supplied representation. Both precede the separate +0x34 read used for the second element.

### 6. Second external operation and return

No result from this operation is consumed. If it returns, the function returns normally.

## Acceptance examples

These examples are conditional predictions from static evidence, not runtime results.

1. **State changed by dispatch.** If the indirect target sets +0x2c to a nonzero value and returns, the subsequent state check selects the alternate path. An entry-time zero does not guarantee normal completion.

2. **Nonzero state remains decisive.** If the state check reads 7, F-de99289388aa is invoked. If that dependency clears the field and returns, F-feee9156a257 is still invoked because there is no second check.

3. **Normal-path ordering.** If the state check reads zero and all normal-path dependencies return, the explicit zero write precedes capture of +0x20 and +0x24. The helper precedes the first external operation, and both external operations precede normal return.

4. **Stable odd length.** If, after the first external operation, +0x30 contains 0x00001000 and both reads of +0x34 yield 9, the second temporary pair contains 0x00001004 and 4. The odd remainder is discarded.

5. **Unsigned high bit.** If both reads of +0x34 yield 0x80000000, each shifted value is 0x40000000. The operation is not an arithmetic right shift of a negative signed value.

6. **32-bit wraparound.** If +0x30 supplies 0xfffffffe and both reads of +0x34 yield 8, the second temporary pair contains 0x00000002 and 4. No visible overflow error is generated.

7. **Separate length observations.** If the first +0x34 read yields 10 and the second yields 6, the first pair element uses an increment of 5, while the second element is 3. This example requires an environment capable of changing the field between reads; such an environment is not itself established.

8. **Conditional transfer interpretation.** If an independently verified contract establishes F-opaque-02 as a 13-byte copy, its destination intervals begin at +0x30 and +0x40, respectively. The final five source bytes of the second operation remain unspecified by this function.
