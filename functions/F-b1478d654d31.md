# F-b1478d654d31

## Purpose

F-b1478d654d31 prepares a temporary two-word value, invokes an object-selected operation with a pointer-bearing descriptor, performs a subsequent dependency call on the temporary value, and returns a packed 64-bit result.

The returned low word reports whether the object-selected operation returned anything other than signed 32-bit −1. The returned high word contains the final contents of the pointer-bearing descriptor slot. It is not the object-selected operation’s unmodified result.

The established behavior is the sequencing and data flow described below. Interpreting the dependencies as initialization, synchronization, destruction, or ownership transfer would require evidence not present here.

## Interface

### Inputs

The function receives four arguments:

1. **Object reference.** A pointer to storage whose first 32-bit word supplies the base address used for indirect dispatch. The selected callable is obtained from byte offset 0x48 within that dispatch region.
2. **Initial pointer value.** A pointer represented in the supplied model as pointing to 32-bit words. It is initially stored in a temporary pointer slot, but that slot is explicitly overwritten before the indirect operation.
3. **First payload word.** An uninterpreted 32-bit value copied into temporary storage.
4. **Second payload word.** Another uninterpreted 32-bit value copied into the immediately following temporary word.

No signed arithmetic, range validation, or interpretation of either payload word is visible. All 32 bits of each word participate in its initial copy.

The supplied representation uses a 32-bit address model for the dispatch and packed pointer value. This contract describes that model; it does not establish behavior for a wider-pointer environment.

### Temporary layout

The visible temporary storage has this relative layout:

| Relative byte offset | Width | Initial contents |
|---|---:|---|
| −4 | 32 bits | Initial pointer value |
| 0 | 32 bits | First payload word |
| +4 | 32 bits | Second payload word |

Offset 0 is the address supplied to both F-b9acea4b06ad and F-289ec4311c64.

Before the indirect operation, the slot at offset −4 is overwritten with the address of offset 0. The indirect operation receives the address of this pointer slot, rather than receiving the payload address directly.

These offsets describe the supplied temporary-storage representation. They do not authorize dependencies to access neighboring storage, establish a larger public structure, or imply that any temporary address remains valid after return.

### Output

The function returns a 64-bit packed value:

- **Bits 0–31:** 1 if the indirect operation’s signed 32-bit result differs from −1; otherwise 0.
- **Bits 32–63:** the 32-bit contents of the pointer slot as observed after F-289ec4311c64 returns.

The low word is fully normalized: it is exactly 0 or exactly 1.

The high word is not independently validated. Unless some intervening action changes the pointer slot after its explicit reset, it contains the address of the temporary two-word payload. Such an address does not identify storage with a caller-visible lifetime beyond this invocation.

### Preconditions

For ordinary completion:

- The object reference must support the dispatch reads described below.
- The dispatch entry at byte offset 0x48 must identify a callable compatible with the observed invocation.
- The three called operations must return normally.
- Their memory accesses must be valid under their own contracts.

The wrapper performs no visible null check, dispatch validation, or recovery from invalid memory access. The second argument is not explicitly dereferenced by this function.

## Behavior

### 1. Establish temporary state

The function first stores the initial pointer value in the pointer slot and copies the two payload arguments into their respective 32-bit slots.

These are local copies. Later changes to the payload slots do not constitute writes back to the storage from which the caller originally obtained its argument values.

The initial pointer value is therefore present in temporary storage during the first two dependency calls. However, neither of those calls explicitly receives the address of the pointer slot. The source establishes its presence, not that a dependency reads it.

### 2. Invoke F-b9acea4b06ad

The function calls F-b9acea4b06ad with the address of the first payload word.

This provides direct access to that word. The second payload word is adjacent at byte offset +4, but the callee’s permitted access extent is unknown.

Any return value from this dependency is ignored. Its effects are not otherwise constrained by the supplied evidence: it may alter accessible payload storage or external state. Its role cannot be established merely from its placement before the indirect operation.

### 3. Invoke F-cec639934d47

After F-b9acea4b06ad returns, the function calls F-cec639934d47 with no explicit arguments.

Any return value is ignored. The absence of explicit arguments does not establish absence of side effects. In particular, this contract does not assume that the dependency preserves global state, the object’s dispatch state, or memory reachable through previously available aliases.

This call occurs before the object’s dispatch entry is read. Consequently, the dispatch uses the object state present after both preceding dependencies have completed, not necessarily its entry-time state.

### 4. Replace the pointer slot

After F-cec639934d47 returns, the function overwrites the pointer slot with the address of the first payload word.

This replacement is unconditional on the visible normal-return path. The initial pointer argument is not the pointer value explicitly presented to the indirect operation.

The payload address is unchanged by this assignment; the payload contents may already have changed through dependency effects.

### 5. Resolve and invoke the object-selected operation

The function obtains the indirect callable through two dependent reads:

1. Read the first 32-bit word of the referenced object to obtain the dispatch-region base.
2. Read the callable entry at byte offset 0x48 from that base.

It then invokes the selected operation with these explicit arguments, in this order:

1. The original object reference.
2. The address of the pointer slot.
3. The integer value 4.

The value 4 is a literal argument. The available evidence does not establish whether the callee interprets it as a byte count, an element count, a mode, or another quantity. It must not be silently reinterpreted as the eight-byte extent of the two-word payload.

At entry to this operation, the addressed pointer slot contains the address of the first payload word. The operation can therefore receive a pointer-to-pointer-shaped argument. Whether it is permitted or expected to rewrite that slot is a property of the unknown operation’s contract. The wrapper itself does not prevent such a rewrite.

The operation’s result is retained as a signed 32-bit value for the later comparison. The wrapper does not branch around the subsequent dependency call based on that result.

### 6. Invoke F-289ec4311c64

After the indirect operation returns normally, the function calls F-289ec4311c64 with the address of the first payload word.

This address is the same payload-storage address used in the first dependency call. It is not loaded from the pointer slot. Therefore, if the indirect operation replaces the pointer slot with a different address, that replacement does not redirect the explicit argument to F-289ec4311c64.

This call occurs even when the indirect operation returns −1.

Its return value is ignored. The supplied evidence does not establish that this operation releases memory, destroys an object, restores prior state, or undoes earlier effects.

### 7. Construct the return value

After F-289ec4311c64 returns, the function forms the packed 64-bit result.

The low word depends solely on the retained indirect-operation result:

- Signed 32-bit −1, whose bit pattern is 0xFFFFFFFF, produces 0.
- Every other signed 32-bit result produces 1.

Thus, zero and negative values other than −1 all produce 1. The predicate is not “positive,” “nonnegative,” or “nonzero.”

The high word comes from the pointer slot’s contents at this final stage. It is not necessarily the value initially placed there before the indirect operation. Neither the indirect operation nor F-289ec4311c64 is assumed to preserve that slot through every possible alias.

## Side effects

### Explicit local writes

The function explicitly:

- Initializes the pointer slot from the second argument.
- Initializes both payload words from the third and fourth arguments.
- Replaces the pointer slot with the payload address before dispatch.

No explicit allocation, deallocation, persistent-object write, or global-variable write appears in the wrapper.

### External effects

All three named dependencies and the object-selected operation may have effects not described by this function’s visible body. The wrapper provides no visible rollback.

The order of externally significant calls is fixed:

1. F-b9acea4b06ad.
2. F-cec639934d47.
3. The object-selected operation.
4. F-289ec4311c64.

This sequence describes normal returns. No exception handler, fault recovery, cancellation handling, or nonlocal-exit cleanup is visible. If an earlier call does not return normally, completion of later calls is not established.

### Ownership and lifetime

The wrapper creates temporary storage and lends its addresses to callees during the invocation. No ownership transfer is established.

In particular:

- The initial pointer argument is not visibly released.
- The payload words are not established to be resource handles.
- Passing the payload address to F-289ec4311c64 does not prove deallocation.
- Returning temporary-address bits in the high word does not extend the storage’s lifetime.
- A replacement pointer written into the pointer slot has no established ownership or validity guarantee.

## Acceptance examples

These are conditional acceptance cases derived from the supplied static evidence, not executed tests.

### Sentinel result

Given valid dispatch and normally returning dependencies, if the object-selected operation returns signed 32-bit −1, the final low word must be 0. F-289ec4311c64 must still be invoked before return.

### Zero result

If the object-selected operation returns 0, the final low word must be 1. Treating zero as failure would contradict the visible predicate.

### Other negative result

If the object-selected operation returns −2, the final low word must be 1. The wrapper distinguishes only −1, not the complete negative range.

### Unchanged pointer slot

If neither the indirect operation nor subsequent effects alter the pointer slot after its reset, the final high word must contain the 32-bit address of the temporary payload. That observation does not make the address safe to dereference after return.

### Replacement pointer

If the indirect operation writes a different 32-bit pointer value into the pointer slot, and F-289ec4311c64 leaves that slot unchanged, the final high word must contain the replacement value.

F-289ec4311c64 must nevertheless receive the original temporary payload address, not the replacement address.

### Payload modification

If F-b9acea4b06ad changes either payload word through valid access, and no later effect overwrites that change before the indirect operation reads it, the operation sees the changed contents through the pointer slot’s payload address. The wrapper does not restore the entry-time payload values.

### Dispatch mutation before lookup

If either preliminary dependency validly changes the dispatch state reachable through the object, the subsequent lookup must use the state present after those calls. Resolving and caching the entry before them would change the visible ordering.

### Invalid object reference

If the object reference is invalid for dispatch access, this contract provides no ordinary failure result. Returning a normalized low-word zero as a substitute is not established behavior.
