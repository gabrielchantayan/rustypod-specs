# F-455544658bc7

## Purpose

F-455544658bc7 updates a byte in caller-provided storage using a selector held in another byte. The update has two stages: clear a selected region, then combine the cleared value with a contribution from the replacement argument.

**Inferred intent:** replace one of four two-bit fields in a packed byte.

**Established limitation:** that interpretation describes the result only when the selector identifies one of those fields and the replacement is restricted to two bits. The function does not enforce either restriction. Larger replacement values can affect neighboring bits, and larger selectors can cause invalid integer shifts.

The intermediate cleared value is assigned to storage before the final value. The final combination uses the retained cleared value, not a fresh reading of the destination.

## Behavior

### Selector meaning

Each selector observation supplies a position from its low seven bits. The high bit is excluded from position selection.

The resulting bit displacement is twice that position. Consequently, possible displacements are the even values from zero through 254. This range is a description of the requested displacement, not a guarantee that every displacement is valid for the integer operands.

The ordinary packed-field positions are:

| Low seven selector bits | Bit displacement | Destination region selected for clearing |
|---:|---:|---|
| 0 | 0 | Bits 0–1 |
| 1 | 2 | Bits 2–3 |
| 2 | 4 | Bits 4–5 |
| 3 | 6 | Bits 6–7 |

Bit zero is the least significant bit of the destination byte.

A stable selector of 0x82 selects the same displacement as 0x02. This equivalence concerns position selection only; it assigns no domain meaning to the high bit.

### Clearing effect

For an ordinary packed-field position, the first assigned destination value has the selected pair cleared and every other bit preserved from the original destination.

The first selector observation determines this clearing region. The original destination value is read once for this purpose.

For positions beyond the four ordinary fields, the result depends first on whether the underlying integer shift is valid. If it is valid, a clearing contribution located entirely above bit seven disappears when narrowed to an eight-bit byte. In that case, the clearing assignment preserves the original destination.

Byte narrowing happens after integer shifting. It cannot make an invalid shift valid.

### Replacement effect

The replacement contribution is positioned using a second selector observation, taken after the clearing assignment.

The function does not restrict the replacement to its lowest two bits. Under the unsigned eight-bit model, all replacement bits that remain within the destination byte after positioning can contribute to the final value. Bits beyond the byte are discarded.

The final value combines that contribution with the retained cleared byte using inclusive OR. This has two important consequences:

- A zero replacement contribution leaves the cleared byte unchanged.
- A set replacement bit can set a destination bit outside the pair cleared during the first stage.

The final combination cannot clear additional bits from the retained cleared value.

For a stable ordinary selector and a replacement from zero through three, the result is the expected two-bit-field replacement: the selected pair receives the replacement, and all other destination bits retain their original values.

### Selector rereading and retained state

The selector is not captured once for the entire operation. It is read separately for clearing and insertion.

If the two reads legitimately observe different selector values, the cleared region and replacement position can differ. Such a change is not an input-validation event and does not trigger recovery.

The destination, by contrast, is not reread before the final assignment. An intervening modification of destination storage is not merged into the result. The final assignment uses the function’s retained cleared byte.

These are access-order properties, not a guarantee that unsynchronized concurrent modification is supported.

### Direct aliasing

When both locations identify the same byte, the second selector read observes storage after the clearing assignment.

In the eight-bit model, direct aliasing alone does not change the selected displacement during an otherwise defined execution:

- For selector positions zero through two, the selected clearing region contains no set bits in the corresponding selector value, apart from bits outside the selector’s low-seven-bit position encoding.
- For position three, clearing can remove the high bit, but that bit does not contribute to position selection.
- For larger positions with defined shifts, the byte-sized clearing contribution is zero.

The stored selector byte can therefore change without its selected displacement changing. Direct aliasing must not be treated as evidence that the two stages necessarily use different positions.

### Integer boundaries

Both positioned contributions are formed through integer shifts before byte narrowing. Their validity depends on the width and signed-shift rules of the integer model.

Under a 32-bit signed model that requires the mathematical result of a nonnegative left shift to remain representable as a nonnegative signed integer:

- A displacement of 32 or greater is invalid.
- A clearing displacement of 30 is also invalid because the clearing contribution exceeds the positive signed range.
- Clearing displacements through 28 do not exceed that range.
- The replacement operation has a separate representability requirement. A safe clearing displacement does not establish that an arbitrary replacement can be shifted safely.

Negative replacements have no guaranteed result under signed-shift rules that prohibit shifting negative values.

No shift-count wrapping, saturation, or hardware-specific masking is established. The eventual byte-sized result must not be used to justify an invalid earlier operation.

## Acceptance examples

These examples are conditional deductions, not runtime observations. Except where stated otherwise, they assume unsigned eight-bit bytes, valid storage and address arithmetic, defined shifts, stable selector storage, and no intervening modifications.

### Ordinary field replacement

| Original destination | Selector | Replacement | Clearing assignment | Final assignment |
|---:|---:|---:|---:|---:|
| 0xFF | 1 | 2 | 0xF3 | 0xFB |
| 0xFF | 3 | 0 | 0x3F | 0x3F |
| 0xA5 | 0 | 2 | 0xA4 | 0xA6 |

The first row replaces bits 2–3. The second clears bits 6–7 and makes two equal assignments. The third preserves every bit above the lowest pair.

### High-bit exclusion

For an original destination of 0xFF and replacement one, a stable selector of either 0x02 or 0x82 produces a clearing assignment of 0xCF and a final assignment of 0xDF.

An implementation that gives those selectors different positions would violate the established selection rule.

### Replacement spill

For an original destination of 0x00, selector zero, and replacement seven, the clearing assignment is 0x00 and the final assignment is 0x07.

The third-lowest bit is set even though only the lowest pair was cleared. Restricting the replacement to two bits and producing 0x03 would not preserve the supplied behavior.

### Defined position beyond the byte

For an original destination of 0xA5, selector four, and replacement one, both assignments are 0xA5 if the relevant shifts by eight are defined.

The positioned clearing and replacement contributions have no remaining bits after byte narrowing. This example does not authorize arbitrary larger selectors.

### Direct destination-selector aliasing

Suppose both locations identify one byte initially containing 0x83, and the replacement is one.

The first selector observation chooses bits 6–7. The clearing assignment changes the shared byte to 0x03. The second selector read therefore obtains 0x03, not 0x83, but still chooses bits 6–7. The final assignment is 0x43.

This case distinguishes rereading selector storage from retaining the original selector value, without claiming a change in displacement.

### Different selector observations

If a permitted execution environment supplies selector one for clearing and selector two for insertion, an original destination of 0xFF and replacement one produce a clearing assignment of 0xF3 and a final assignment of 0xF3.

Bits 2–3 remain cleared. The replacement contributes at bit four, which was already set. This is not equivalent to an ordinary replacement at either single stable position.

This example is conditional on a valid way for those different observations to occur; it does not authorize a data race.

### Invalid arithmetic

Under an ordinary 32-bit model, a selector whose low seven bits are 16 requests a displacement of 32. No destination result is specified.

Likewise, no byte result is guaranteed for a negative replacement when the applicable signed-shift rules prohibit that operand. A successful-looking byte truncation is not an acceptance criterion for invalid arithmetic.
