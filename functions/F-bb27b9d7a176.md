# F-bb27b9d7a176

## Purpose

F-bb27b9d7a176 initializes selected fields in caller-provided storage, invokes two initialization dependencies on different interior addresses, and modifies storage reached through their results.

The established behavior includes:

- Installing a 32-bit header value.
- Clearing selected words and bytes in the supplied storage.
- Obtaining and configuring a structure with two self-referential links under ordinary non-overlapping conditions.
- Obtaining another address and writing a discriminator, a header-like value before that address, an optional table-selected word, and a caller-supplied byte.

These operations are consistent with construction of a compound object, but that interpretation is inferred intent. Object type, ownership model, allocation policy, and the meanings of the installed values are not established.

## Interface

The function receives three arguments:

| Argument | Established representation | Use |
|---|---|---|
| Destination | Address of storage accessed in 32-bit words and individual bytes | Receives direct initialization writes and supplies interior addresses to dependencies |
| Byte value | 8-bit value | Written at offset `0x24` from the second dependency’s returned address |

The function has no explicit return value. Its results are memory changes and dependency side effects.

The representation uses four-byte words and 32-bit address arithmetic. Numeric offsets below are byte offsets. Byte order is not established by the supplied evidence.

### Storage requirements

Let **D** denote the supplied destination address.

Direct initialization writes cover selected locations from D through D + `0x1D`. The function also passes D + `0x04` and D + `0x20` to dependencies. Requirements for the regions accessed by those dependencies are unknown.

The first dependency must return an address suitable for the accesses described below. The second must return an address supporting both negative and positive offsets: the function writes as far back as `0x20` bytes before that address and writes a byte `0x24` bytes after it.

There are no explicit checks for null pointers, allocation failure, alignment, available storage, or address overflow. Valid storage and successful dependency behavior are therefore preconditions for ordinary completion, not conditions enforced by this function.

## Behavior

### Initial destination writes

Before invoking either dependency, the function performs the following writes in the listed order:

| Order | Destination | Width | Value |
|---:|---|---:|---|
| 1 | D + `0x00` | 32 bits | Initial header value |
| 2 | D + `0x04` | 32 bits | Zero |
| 3 | D + `0x14` | 32 bits | Zero |
| 4 | D + `0x18` | 32 bits | Zero |

This is not a whole-object clear. In particular, this phase does not directly write bytes D + `0x1E` and D + `0x1F`, or storage beginning at D + `0x20`.

The function does not read prior destination field contents to preserve them during these assignments. The evidence does not identify the initial header value’s numeric content or semantic type.

### First dependency and linked-structure writes

After the initial writes, the function calls F-4fa4ec01302c with D + `0x04`.

The dependency’s return value R is then stored as a 32-bit value at D + `0x14`. The function next performs these writes:

1. Write a 32-bit zero at R + `0x04`.
2. Read the address held at D + `0x14`, and use that address plus `0x08` as the destination of a 32-bit write. The written value is also obtained from D + `0x14`.
3. Read the address held at D + `0x14`, and use that address plus `0x0C` as the destination of a 32-bit write. The written value is also obtained from D + `0x14`.

Under non-overlapping conditions, with no intervening external modification, this produces:

- D + `0x14` contains R.
- R + `0x04` contains zero.
- R + `0x08` contains R.
- R + `0x0C` contains R.

That layout is consistent with a sentinel or circular-list anchor. The interpretation is not necessary to the contract.

The repeated reads of D + `0x14` matter. The first write uses the locally retained return value R, whereas the two later writes obtain their addresses and values from destination storage. If R + `0x04` or a later write overlaps D + `0x14`, subsequent accesses need not continue to use R.

Within each individual link assignment, the evidence does not establish the relative evaluation order of the address read and value read. It establishes the assignment sequence, not a finer-grained order between those constituent reads.

### Second dependency and associated writes

After completing the preceding writes, the function calls F-72538fc0941d with D + `0x20`.

Let S be its returned address. The function then performs the following operations in order:

1. Write the 8-bit value 2 at S + `0x1C`.
2. Write the secondary header value as a 32-bit word at S − `0x20`.
3. If the unsigned selector is less than 2, obtain and copy a table word to S + `0x20`.
4. Write the caller-supplied byte at S + `0x24`.
5. Return without an explicit result value.

The returned address S is retained for these operations. The function does not reread a destination field to recover S.

The location S − `0x20` is exactly 32 bytes before S. The write is not at S itself. Whether this location belongs to a containing object, a header, or another storage region is unknown.

### Selector-dependent table access

Only selectors 0 and 1 enable the table access.

For an enabled selector, the function:

- Reads the base address supplied through the table root reference.
- Reads a 32-bit address at offset `0x30` from that base.
- Reads a 32-bit word at offset `0xF7C + 4 × selector` from the resulting address.
- Writes that word at S + `0x20`.

Thus the final source-word offsets are:

| Selector | Offset from the intermediate address |
|---:|---:|
| 0 | `0xF7C` |
| 1 | `0xF80` |

The selector comparison is unsigned. Values from 2 through `0xFFFFFFFF` skip this table-read-and-copy operation.

The multiplication cannot overflow on an executed table-read path: the accepted selectors produce only offsets 0 or 4 before the fixed offset is added. Validity of the resulting addresses remains a precondition.

For selectors of 2 or greater, there is no direct write to S + `0x20` in this conditional step. This does not guarantee that its final contents equal its entry contents: dependencies, aliasing, or other writes may affect the same storage.

### Ordering and dependency-visible state

F-4fa4ec01302c is called only after all nine initial writes. F-72538fc0941d is called only after the first dependency returns and the subsequent linked-structure writes complete.

The function does not restore the initially cleared fields after either dependency. A dependency may alter destination fields or global state unless its separate contract says otherwise.

The table access occurs after both dependency calls and after the two preceding writes relative to S. Its inputs must not be treated as snapshots taken at function entry. Changes made by dependencies, or by overlapping earlier writes, can affect the values subsequently read.

The caller-supplied byte is written last among the function’s explicit memory operations.

## Acceptance examples

These are conditional acceptance criteria derived from static evidence, not executed tests.

### Ordinary initialization with selector 0

Assume all accesses are valid, destination storage does not overlap either returned region, the returned regions do not overlap each other, and relevant global values remain stable during their reads.

Expected observations:

- Initial destination writes occur in the specified order.
- F-4fa4ec01302c receives D + `0x04`.
- D + `0x14` receives R.
- R + `0x04` receives zero; R + `0x08` and R + `0x0C` receive R.
- F-72538fc0941d receives D + `0x20`.
- S + `0x1C` receives byte value 2.
- S − `0x20` receives the secondary header value.
- S + `0x20` receives the table word at intermediate-base offset `0xF7C`.
- S + `0x24` receives the supplied byte.

### Selector 1

Under the same conditions, selector 1 selects the word at intermediate-base offset `0xF80`. The other direct operations are unchanged.

### Selector 2 or `0xFFFFFFFF`

The table-read-and-copy step is skipped.

If no dependency or overlapping write modifies S + `0x20`, that word retains its prior contents. The final byte write at S + `0x24` still occurs.

In particular, `0xFFFFFFFF` does not qualify as a negative selector: the comparison is unsigned.

### Full-range byte input

For a supplied byte of `0xFF`, the last explicit write places the byte `0xFF` at S + `0x24`. There is no visible range check, masking to a smaller field, or substitution based on the selector.

### Dependency changes destination state

If F-4fa4ec01302c changes D + `0x08`, and no later operation aliases that location, the change remains. The function does not repeat the initial zero write after the call.

### Overlapping first result

If R + `0x04` overlaps D + `0x14`, the zero written through R changes the field subsequently used for link destinations. An implementation that always uses a cached R for both later link writes would not preserve the demonstrated read behavior.

This example establishes the importance of rereading the field; it does not assert that such an overlapping configuration completes safely.
