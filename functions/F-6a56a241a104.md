# F-6a56a241a104

## Purpose

F-6a56a241a104 performs a long, environment-dependent sequence of indirect invocations, followed by direct storage mutation and a final unresolved indirect dispatch.

The supplied static representation establishes access patterns and value relationships, but not an application-level purpose. Formatting, initialization, message handling, and maintenance of a linked data structure are not established. Character-like constants and self-address stores do not supply those interpretations.

This contract distinguishes:

- **Established static evidence:** represented access widths, conversions, value relationships, and ordering.
- **Inferred intent:** possible interpretations that are not acceptance requirements.
- **documented_only:** behavior unresolved by the supplied evidence.

Reaching the terminal dispatch requires every preceding dependency to return and every reached memory access to succeed.

## Interface

### Inputs and outputs

The represented interface has no explicit parameters and no explicit result value. Implicit inputs nevertheless include:

- Entry control state used to derive the first indirect target.
- Dependency results, including additional machine-state result channels.
- Existing contents of fixed-symbol and computed-address storage.
- The environment’s address interpretation, permissions, alignment, byte order, and arithmetic rules.

Observable outputs include indirect invocations, their displayed arguments, direct writes, and the terminal four-argument dispatch. Effects inside dependencies are additional, unresolved outputs.

The terminal dispatch receives, in order:

1. `0x72`.
2. A retained 32-bit word from offset `0x64` of a late-loaded base.
3. A retained 32-bit word from offset `0x14` of an earlier linked base.
4. A retained 32-bit word from offset `0x74` of the same late-loaded base used for argument two.

No argument is established to represent a length, status, owned pointer, or handle. A return is represented after dispatch, but normal return behavior remains **documented_only** because the target and transfer convention are unresolved.

## Behavior

### Invocation phase

The opening phase is a long straight-line sequence of indirect invocations. The first target depends on entry control state plus displacement `0xFFE`. Most later targets derive from embedded control references using the same displacement.

Invocations display zero through four arguments. No displayed arguments does not mean no implicit machine-state inputs.

Established argument relationships include:

- Retained 32-bit results shifted left, frequently by eight bits.
- Upper 32-bit halves passed unchanged or shifted.
- Values reused across intervening invocations.
- Literal zeros and duplicated arguments.
- Low-order fields masked before placement shifts.
- Additional result channels consumed without an available calling-convention contract.

The invocations are not established to be pure arithmetic helpers. Their order matters independently of argument calculations. No local conditional branch or loop is visible in this phase; dependencies may branch, mutate storage, or fail to return.

### Arithmetic boundaries

Masks retain low-order fields of 24, 22, 21, 20, 19, 18, 17, 16, 14, 13, 12, and 11 bits. Masking before a shift is not interchangeable with masking afterward.

Explicitly unsigned right shifts are logical. Combined-result extractions shifted by 34, 36, or 44 bits operate on 64-bit quantities, not 32-bit halves.

A recurring extraction retains bits 10 through 19 of a 32-bit quantity, yielding zero through 1023 before further shifts.

Near the direct-mutation boundary, a result is shifted left by eight, restricted to its low 15 bits, then logically shifted right by six. Under 32-bit bit-vector semantics, this equals four times the original result’s low seven bits: a multiple of four from zero through 508. Doubling it yields a multiple of eight from zero through 1016.

These bounds are conditional on that arithmetic interpretation. Signed left shifts, signed overflow, and integer-to-address conversion remain **documented_only** where original machine semantics are unavailable. Unlimited-precision arithmetic must not replace narrow arithmetic silently.

Locally initialized zeros remain zero through their visible shifts unless replaced. This supplies no global-preservation guarantee across dependencies.

### Opening mutation

The following descriptive labels identify retained values, not source identifiers or proven objects:

- **Primary base:** an earlier result multiplied by `0x02000000`.
- **Secondary base:** an earlier result shifted left by 25.
- **Small base:** twice the bounded extraction above.
- **Final pair:** the two 32-bit halves of the last combined dependency result.
- **Shifted payload:** another retained result shifted left by eight.

The first computed word write places the secondary-base value at offset `0x14` through the final pair’s upper half. It precedes a byte write at secondary-base offset `0x09` using the upper half’s low byte.

A word write places the primary base at offset `0x54` through 256 times the final pair’s lower half. Secondary-base offset `0x09` is then overwritten with the secondary base’s low byte.

Primary-base offset `0x14` is cleared before an explicit unsigned-byte read at primary-base offset `0x05`. That byte supplies a zero-extended word write at primary-base offset `0x34`.

Small-base offset `0x14` is cleared twice, with a word read from primary-base offset `0x14` between the clears. The retained word subsequently serves as both data and an address base. Its low byte is written twice at small-base offset `0x15`.

These are separate represented accesses. Aliasing, overlapping widths, or device-backed storage can make apparently redundant stores observable.

### Linked and scaled mutation

The next region uses retained words and words read at offsets `0x54`, `0x64`, and `0x74` as further address bases. Related values are doubled, quadrupled, or multiplied by eight.

The fixed-symbol input associated with `0x05` is converted to unsigned 32 bits and used as a base for computed accesses at offsets `0x15` and `0x54`. Its source width and signedness are unavailable; a zero-through-255 bound is unsupported.

Other established effects include:

- Assignment of the small base’s explicitly converted low byte to the fixed symbol associated with `0x01`.
- Retention of a computed offset-`0x54` word before replacement.
- Repeated self-address word writes at offset `0x24`.
- Writes through bases obtained from offset-`0x74` word reads.
- Assignment of a doubled linked value to the fixed symbol associated with `0x54`.
- Assignment of the small base’s explicitly converted low byte to the fixed symbol associated with `0x15`.
- Computed word writes at offsets `0x14`, `0x34`, `0x44`, and `0x54`.
- Computed low-byte writes at offsets `0x09`, `0x0D`, and `0x15`.

The fixed-symbol assignments do not establish byte or word destination accesses.

By contrast, explicitly unsigned-byte reads at computed offset `0x05` are established 8-bit reads. Their zero-extended values become bases for 32-bit reads at offset `0x74`. Repeated reads remain distinct observations when intervening writes can overlap their storage.

Retained values continue to represent their earlier observations even if subsequent writes change the original storage. A later explicit reload instead observes storage at that later point. No list, tree, reference-count, or ownership invariant is established.

### Literals and repeated updates

A later region writes `0x3A` through a fourfold-scaled base as a byte, through an eightfold-scaled base as a halfword, and at offset `0x20` of the fourfold-scaled base as a word. These widths are established by explicit computed-address accesses.

Another retained base, called the **mutation base**, is formed by subtracting `0x96` from an earlier scaled quantity and multiplying by four. Its offset-`0x20` word receives, in order:

- `0x20`.
- `0x2F`.
- A zero-extended byte read from mutation-base offset `0x04`.
- `0x20` again.

The byte read occurs after the first two writes and before the final write.

A value is retained from fixed storage as the **anchor base**, before assignment of `0x20` to the fixed symbol associated with `0x60`. Neither fixed-symbol access has an established storage width.

The repeated-update region uses four-access groups: a computed word write at offset `0x54`, reciprocal low-byte writes at offsets `0x19` and `0x11`, then a computed word write at anchor-base offset `0x34`.

The first group uses different scaled quantities for its word destination and offset-`0x34` payload than later groups. Repetition is statically present, not an established runtime loop. Exact multiplicity is not enumerated by this contract and remains **documented_only** as a standalone acceptance requirement; collapsing the region into one logical update is unsupported.

### Final mutation and three fresh observations at `0x67`

For this region:

- **Linked base** is an earlier doubled linked value.
- **Fixed payload** is the 32-bit value retained from the symbol associated with `0xA9`.
- **Saved linked word** is retained from linked-base offset `0x14`.

These bases need not designate disjoint storage.

Before the `0x67` sequence, additional computed word reads are retained. The fixed symbol associated with `0x3A` receives the character-conversion arithmetic expression described above. Computed byte writes place `0x6C` at mutation-base offset `0x08` and low-byte values at offsets `0x09` and `0x0D`. Linked-base offset `0x54` receives a self-address word.

The symbol associated with `0x67` then participates in an initial assignment and **three separate source-read occasions**:

1. **Initial propagation.** The fixed payload is explicitly converted to one byte and assigned to the symbol associated with `0x67`. A computed word read from linked-base offset `0x44` intervenes before a fresh read of that symbol supplies assignment to the fixed symbol associated with `0x21`.
2. **First later reload.** A fresh read of the symbol associated with `0x67` supplies an explicitly 8-bit computed write at mutation-base offset `0x09`.
3. **Second later reload.** Another fresh read supplies another explicitly 8-bit computed write at that same retained destination.

The initial right-hand-side conversion is 8-bit. The storage widths of the initial fixed-symbol assignment, all three fixed-symbol reads, and the propagation assignment to `0x21` remain **documented_only**. The two later computed destinations are established bytes and retain the low eight bits of their respective freshly read values.

Before the first later reload, intervening computed writes include:

- A byte at mutation-base offset `0x10`.
- Two words at anchor-base offset `0x54`.
- A byte at linked-base offset `0x01`, derived from a signed right-shift expression.
- A word at anchor-base offset `0x74`.
- A word at mutation-base offset `0x10`, supplied by a fresh word read at offset `0x40`.
- A word at anchor-base offset `0x44`.

Between the first and second later reloads, the first reload’s low byte is stored, a byte is written at linked-base offset `0x09`, and the fixed payload is written as a word at mutation-base offset `0x44`. A word read at mutation-base offset `0x54` precedes the second reload.

Computed writes may overlap any part of the unresolved fixed-symbol storage footprint. Consequently, neither later read may be replaced by the initial payload, the propagation read, or the other reload.

After the second reload’s byte store, mutation continues: linked-base offset `0x54` is restored from the saved linked word; mutation-base offset `0x14` is freshly read; additional computed byte writes occur. Mutation-base offset `0x09` is overwritten again using the low byte of the word retained from offset `0x54`.

A late base read from linked-base offset `0x04` supplies a halfword destination at twice that base, receiving `0x0065`. Subsequent accesses retain its offset-`0x64` word, write decimal 100 as a word through another loaded base’s offset `0x54`, retain its offset-`0x74` word, update a linked offset-`0x54` word, and write a word through twice the retained offset-`0x64` value.

Terminal dispatch follows these mutations without visible rollback.

## Acceptance examples

These are conditional analytical examples, not executed tests.

1. **Computed byte truncation.** An explicitly 8-bit computed destination supplied with `0x123456AB` receives `0xAB`. This does not establish the width of an undeclared fixed-symbol destination.

2. **Bounded extraction.** Under 32-bit bit-vector semantics, an applicable result whose low seven bits are 127 produces extraction value 508 and small base 1016.

3. **Fixed-source conversion.** A value read from the symbol associated with `0x05` is converted to unsigned 32 bits. Without a declaration, rejecting a converted base solely because it exceeds 255 is unsupported.

4. **Fixed-destination limitation.** Assignment of an explicitly converted low byte to the symbol associated with `0x01`, `0x15`, or `0x67` establishes the supplied value, not an 8-bit storage footprint. Assignments at `0x54` and `0x60` similarly do not establish 32-bit writes.

5. **Literal overwrite history.** With successful accesses, mutation-base offset `0x20` receives `0x20`, `0x2F`, the zero-extended computed byte observation, and `0x20`, in that order. Checking only the final word is insufficient.

6. **Fresh fixed-symbol observations.** Suppose the first later `0x67` read supplies a value whose low byte is `0xA1`, and the second supplies one whose low byte is `0xB2`. Their corresponding computed byte stores use `0xA1` and `0xB2`. Neither source read is thereby established to be byte-sized.

7. **Stable fixed storage.** If the entire source storage footprint remains stable and conversions are unchanged, all three `0x67` observations can agree. Equality does not remove the separate reads. Stability of only one byte is insufficient when the source width is unknown.

8. **Propagation limitation.** Assignment from the `0x67` symbol to the `0x21` symbol establishes a fresh source observation. Without declarations, it does not establish byte copying, zero-extension, or either access footprint.

9. **Dispatch boundary.** If all preceding operations complete, dispatch follows the mutations with first argument `0x72` and the retained words described under Interface. Application-level success is unresolved.
