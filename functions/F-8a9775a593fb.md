# F-8a9775a593fb

## Purpose

F-8a9775a593fb selects a record from a caller-supplied collection and stores the selected record address in the caller’s context.

The established selection rule is:

- Inspect collection entries in descending index order.
- Consider only records whose 32-bit classification field equals a comparison value obtained from global storage.
- Prefer a qualifying record with either of two specific 16-bit field combinations.
- Stop at the first preferred record encountered during the descending scan.
- If no preferred record is found, select the qualifying record at the lowest index.
- If no qualifying record exists, return `0x26` without writing the selection field.

The apparent intent is a preference-based lookup with a fallback. The business meaning of the classification value, the two preferred combinations, and status `0x26` is not established.

## Interface

### Inputs

The function accepts three arguments:

| Argument | Established use |
|---|---|
| Context address | Base address of a structured memory region containing the collection description and selection destination. |
| Auxiliary value A | A 32-bit argument that does not affect the ordinary non-null path. On the null-context path, its incoming value is replaced before the diagnostic dependency is called. |
| Auxiliary value B | A 32-bit argument that does not affect the ordinary non-null path. On the null-context path, its incoming value is replaced before the diagnostic dependency is called. |

The supplied representation uses 32-bit collection entries as record addresses. Address interpretation therefore depends on the represented target’s pointer model; it must not be silently widened into a different collection layout.

### Context layout

Offsets are byte offsets relative to the context address.

| Offset | Width | Meaning |
|---|---:|---|
| `0x24` | 32 bits | Signed collection count used to establish the initial scan boundary. |
| `0x28` | Target pointer width, represented here as 32 bits | Address of the collection-entry array. A null value causes an immediate `0x26` return. |
| `0x5c` | 32 bits | Selection destination. Receives the selected record-address value on success. |

Each collection entry occupies four bytes and holds a 32-bit record-address value.

### Record layout

Only the following record fields are inspected:

| Offset | Width | Meaning |
|---|---:|---|
| `0x04` | 32 bits | Classification field compared against global comparison storage. |
| `0x08` | 16 bits | Primary preference discriminator, interpreted as signed for the supplied comparisons. |
| `0x0a` | 16 bits | Secondary preference discriminator. Compared with `10` for primary value `3`, and with `4` for primary value `0`. |

The representation treats the secondary discriminator as signed in the primary-`3` case and unsigned in the primary-`0` case. Because both comparison constants are small positive integers, the accepted bit patterns are exactly `0x000a` and `0x0004`, respectively.

No meaning is established for other record bytes.

### Outputs

The return value is 32 bits:

- `0`: a record-address value has been written to context offset `0x5c`.
- `0x26`: the collection address was null, or the scan completed without finding a qualifying record.

The function does not clear the selection destination when returning `0x26`.

### Preconditions for a defined ordinary scan

The caller must provide:

- A non-null, accessible context with readable collection metadata.
- A writable selection destination if success is possible.
- A collection count and array address for which the represented pointer arithmetic and descending boundary checks are valid.
- Readable array entries throughout the visited range.
- Valid record addresses for all entries whose classification field is inspected.
- Readable discriminator fields for every classification-matching record.

There is no explicit validation of individual record addresses, collection capacity, arithmetic overflow, alignment, or memory accessibility.

## Behavior

### 1. Null-context handling

A null context triggers a call to dependency F-540af0155702.

The dependency receives three diagnostic arguments:

1. A fixed diagnostic-text address.
2. The 32-bit value `0x360`, equivalent to decimal `864`.
3. A value obtained from separate global diagnostic storage.

The original auxiliary arguments are not forwarded on this path.

There is no explicit return after the diagnostic call and no replacement context is established. If the dependency returns normally, execution proceeds toward a context-relative collection-address read despite the context remaining null. The function therefore does not establish a safe ordinary return for a null context.

Whether the dependency terminates execution, transfers control elsewhere, raises an error, or returns is unknown. Null input must not be documented as reliably returning `0x26`.

### 2. Collection setup

For a non-null context, the collection address at offset `0x28` is read first.

If that address is null:

- The function returns `0x26`.
- The collection count is not needed.
- No array entry or record field is inspected.
- The selection destination is not written.

For a non-null collection address, the signed 32-bit count at offset `0x24` determines the initial scan boundary. The boundary is advanced from the array base by that many four-byte entries.

The source does not check that the count is nonnegative, that multiplication by the entry size is representable in the target address space, or that the computed address belongs to a valid array.

### 3. Descending examination

For an ordinary valid count of \(N\), entries are considered in this order:

\(N-1, N-2, \ldots, 0\).

Before each array-entry read, the scan moves backward by one four-byte entry and checks whether the resulting position is below the collection base. Once that condition is detected, scanning ends without reading that position.

For each position that passes the boundary check:

1. Read the 32-bit record-address value from the array entry.
2. Read the record’s 32-bit classification field at offset `0x04`.
3. Compare it with the global classification comparison value.

The global comparison is part of each candidate’s classification test; the supplied representation does not establish a single saved comparison value for the entire scan. The precise evaluation order between the record-field read and the corresponding global-value read is not established.

If the classification does not match:

- The entry cannot become the fallback.
- Its discriminator fields are not inspected.
- Scanning continues toward lower indices.

### 4. Qualifying records and preference

A classification-matching record becomes the current fallback candidate before its preference fields are evaluated. The remembered fallback is the address of its array slot, not an independently retained final record-address value.

The primary discriminator at record offset `0x08` determines the preference check:

- Primary value `3`: read the secondary discriminator at offset `0x0a`; the record is preferred if that value equals `10`.
- Primary value `0`: read the secondary discriminator at offset `0x0a`; the record is preferred if that value equals `4`.
- Any other primary value: the record is not preferred, and the secondary discriminator is not read.

A primary value of `3` with a secondary value other than `10` remains a fallback candidate but does not stop the scan. The corresponding rule applies to primary `0` with a secondary value other than `4`.

The two preferred combinations have equal priority. Their relative positions determine which wins: the first encountered during descending traversal is selected immediately.

### 5. Scan completion and fallback

If the scan reaches below the array base without encountering a preferred record:

- If no record qualified by classification, return `0x26`.
- Otherwise, select the remembered fallback slot.

Because each qualifying record replaces the fallback while indices decrease, the final fallback is the qualifying record at the lowest index.

This is not a “last array element” fallback. It is the last qualifying record encountered by this particular descending traversal.

### 6. Success commit

Both preferred selection and fallback selection reread the chosen array slot to obtain the value written to the context.

The function then:

1. Writes that 32-bit slot value to context offset `0x5c`.
2. Returns `0`.

This final slot read is observable and distinct from the earlier read used to inspect the record.

Under stable-memory conditions, the committed value is the address of the record that satisfied the selection rules. If the array slot changes between inspection and commitment, the committed value can instead be the replacement slot value. The function performs no final classification or preference validation of that reread value.

## Side effects

### Established writes

On the ordinary non-null path, the only explicit write is the 32-bit selection write at context offset `0x5c` on success.

There are no explicit writes to:

- The collection count.
- The collection address.
- Array entries.
- Record fields.
- The global classification comparison storage.

Returns of `0x26` do not modify the selection destination through an explicit function write. A previous selection can therefore remain present even though the current lookup failed.

### Reads and early stopping

Only entries reached before selection or exhaustion are inspected. Once a preferred record is found, lower-index entries are not visited.

A classification mismatch prevents reads of that record’s discriminator fields. A classification match with a primary discriminator other than `0` or `3` prevents the secondary-field read.

A selected array slot is read again before the output write. The selected record itself is not revalidated at that point.

### Ownership and lifetime

The function contains no explicit allocation, deallocation, reference-count operation, or ownership-transfer operation.

For a successful ordinary call, it stores an existing address-sized value from the array. No record data is copied into newly allocated storage.

This does not establish that the selected record remains alive after return. Lifetime, ownership, and synchronization remain caller obligations. The diagnostic dependency’s memory-management behavior is unknown.

### Aliasing and concurrency

The source provides no locking, atomicity guarantee, or consistency protocol.

If context fields, array entries, records, or global comparison storage change during execution, the stable-memory selection rules do not guarantee a coherent snapshot. In particular, a changed chosen slot may cause success to store a value that was never validated.

If the output location aliases other input storage, the final write has its ordinary memory effect at that location. The function does not impose or enforce a non-aliasing rule.

## Acceptance examples

These examples assume a valid target memory model, stable readable inputs, a stable comparison value, and a writable selection destination unless explicitly stated otherwise. They are conditional behavioral expectations, not executed tests.

1. **Null collection address**  
   With a non-null context whose collection address is null, expect return `0x26`. The selection destination retains its previous value. The count and record storage need not be inspected.

2. **No classification matches**  
   With three valid entries whose classification fields all differ from the comparison value, expect return `0x26`, no selection write, and no discriminator-field reads.

3. **One nonpreferred qualifying record**  
   If only index `1` qualifies and its primary discriminator is neither `0` nor `3`, expect success with the address reread from slot `1`. Its secondary discriminator is not needed.

4. **Multiple fallback candidates**  
   If indices `0`, `2`, and `4` qualify but none is preferred, expect index `0` to supply the committed slot value.

5. **Both preferred combinations present**  
   If index `5` qualifies with primary `0` and secondary `4`, while index `2` qualifies with primary `3` and secondary `10`, expect index `5` to win. The primary-`3` combination has no overriding priority.

6. **Preference requires classification**  
   If index `5` has discriminator values `3` and `10` but fails classification, it is ignored. A lower-index qualifying preferred record may still be selected.

7. **Nonpreferred match does not stop traversal**  
   If index `4` qualifies with discriminator values `3` and `9`, and index `1` qualifies with values `0` and `4`, expect index `1` to win.

8. **Early selection limits reads**  
   If the highest visited entry qualifies and is preferred, expect success without examining lower-index entries. Those lower entries do not participate in that invocation’s selection.

9. **Zero count**  
   If the target’s address arithmetic permits the represented decrement and below-base boundary test, a non-null collection address with count zero produces `0x26` without reading an array element. Strict language-level validity of forming the below-base position is not established.

10. **Chosen slot changes before commitment**  
    If external activity replaces the chosen slot after record inspection but before the final slot read, the function stores the replacement 32-bit value without validating it. This is an observation of the read sequence, not a concurrency-safety guarantee.

11. **Null context**  
    Expect the diagnostic dependency to be invoked with the described arguments. No particular normal return value is guaranteed.
