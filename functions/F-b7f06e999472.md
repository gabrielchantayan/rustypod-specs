# F-b7f06e999472

## Purpose

F-b7f06e999472 expands alternating runs encoded as four-bit quantities into a packed, one-bit output arranged in rows.

The established behavior is:

- Consume each encoded byte’s high nibble before its low nibble.
- Interpret high-nibble runs as zero bits and low-nibble runs as one bits.
- Skip zero-length runs while retaining their effect on which bit value the next run represents.
- Pack output bits most-significant bit first.
- Flush and advance to the next row when the configured row width is reached.
- Stop after the requested number of output bits, independently of whether the encoded input has been exhausted.
- When input runs out before the requested output count is satisfied, produce one bits for the remainder.

The apparent intent is a nibble-based run-length decoder for a monochrome image or similar bit plane. That interpretation is inferred; no particular image format, color meaning, or caller protocol is established.

## Interface

### Inputs

The function accepts three arguments and has no explicit return value:

1. A writable control record.
2. A pointer to the next encoded input byte.
3. An exclusive input-end pointer.

The input pointers are passed by value. Their advancement is local and is not returned to the caller.

### Control-record layout

The supplied representation exposes a record indexed in integer-sized slots:

| Slot | Meaning | Access |
|---|---|---|
| 0 | Output row-base address, represented as an integer | Read initially; read and overwritten at each completed row |
| 1 | Signed output row stride, in bytes | Read when advancing between rows |
| 2 | Signed row width, in output bits | Read initially and reloaded after each completed row |
| 3 | No established meaning | Not directly accessed |
| 4 | Signed total number of output bits to produce | Read initially; not explicitly updated |

Under the represented 32-bit integer model, these slots begin at byte offsets 0, 4, 8, 12, and 16. Each output element is an eight-bit byte.

The source representation does not independently establish the deployed ABI, byte order, alignment requirements, or pointer-conversion rules. Those remain integration prerequisites rather than portable guarantees.

### Output layout

Within each output byte, bits are populated in the order:

- Bit 7 first.
- Then bits 6 through 0.

Each row starts in a fresh output byte. Rows are not bit-contiguous when the row width is not a multiple of eight.

A completed row advances the stored row-base address by the configured stride. The stride is not the number of bytes written automatically; it is a separately supplied displacement. Positive, zero, and negative strides are not rejected.

### Preconditions

For defined, useful decoding, the caller must provide:

- A readable control record, with slot 0 writable when a row can complete.
- Writable output storage covering every byte the operation will flush.
- Input pointers for which the address comparison and any performed byte reads are valid.
- Address arithmetic and integer-to-pointer conversions supported by the execution environment.
- A positive row width if ordinary positive-width rows are intended.

The function performs no capacity checks on the output and supplies no error result for invalid storage, invalid pointers, or invalid dimensions.

## Behavior

### Initialization and early termination

The function first obtains the total output-bit count, the initial row width, and the initial output address from the control record.

It initializes a pending output byte to zero, with the next output position at bit 7. The input starts in the phase that requests a high nibble. No run is active initially.

If the total output-bit count is zero or negative, the function returns without reading encoded input or explicitly writing output. The initial control-record reads still occur.

The total count is a local countdown. It is not written back to slot 4.

### Encoded-input interpretation

Each input byte represents two consecutive runs:

| Nibble | Run value | Run length |
|---|---|---|
| High four bits | Zero | 0–15 output bits |
| Low four bits | One | 0–15 output bits |

When a new encoded byte is needed, the function:

1. Checks whether the current input position has reached or passed the exclusive end.
2. If a byte is available, advances its local input position by one byte.
3. Extracts the high nibble as the current run length.
4. Retains the low nibble for later use.

When the low nibble is selected, no new input byte is needed.

A run length of zero does not produce an output bit. Instead, the function immediately selects the following nibble. Consequently, zero runs can suppress one phase entirely, and a sequence of zero nibbles may consume several bytes before any output is produced.

The bit-value phase continues across row boundaries. Completing a row does not restart the encoded stream at a high nibble or discard the remainder of an active run.

### Producing an output bit

For every output bit requested:

- A nonzero run is obtained if no run remains, unless input exhaustion takes over.
- A one-run sets the current output bit.
- A zero-run leaves that bit clear in the initially zero pending byte.
- The remaining row width decreases by one.
- The bit mask advances toward the least-significant bit.

The output byte is accumulated locally. Existing destination-byte contents are not read or merged.

After the output operation and any required byte or row flush, the current run count decreases and the total output-bit count decreases.

### Byte boundaries

If the current row has not ended but eight bits have accumulated:

- The completed byte is written to the current destination address.
- The local destination address advances by one byte.
- The pending byte is cleared.
- The next bit position returns to bit 7.

This local byte advance does not update the row-base address stored in the control record.

### Row boundaries

A row ends when its remaining-width counter becomes less than one after producing a bit.

Row completion takes precedence over ordinary byte completion. Thus a row ending exactly at an eight-bit boundary causes one write of that byte, not two.

At every completed row, the function:

1. Writes the pending byte, including any unused low bits as zeros.
2. Reads the current row-base address from control slot 0.
3. Reloads the row width from control slot 2.
4. Clears the pending-byte state.
5. Updates control slot 0 by adding the current stride.
6. Uses the advanced row-base address as the next local output destination.

The represented sequence reads the stride for the stored-address update and again for the next local destination calculation. It does not cache one initial stride for the entire call.

The row-base update occurs even if the bit that completed the row was also the final requested output bit. On return after an exact row completion, slot 0 therefore normally identifies the following row.

A width of zero or a negative width is not rejected. Where subtraction is representable, such a width causes the first produced bit to end the row. This is established behavior, not evidence that nonpositive widths are a supported caller convention.

### Total-count termination

The total output-bit count is checked before each next output bit.

When the count has been exhausted:

- If a partial byte is pending, that byte is written.
- If no byte is pending, no additional output write occurs.
- The function returns.

An incomplete final row does not cause a row-base update merely because the call ends.

Unused low-order bits of the final partial byte are zero. They are not preserved from the destination buffer.

### Input exhaustion

Input-end checking occurs only when requesting a new byte. A retained low nibble remains usable after the local byte pointer has reached the end.

If a new byte is required but the input pointer is at or beyond the end:

- No byte is read.
- The current output bit is set to one.
- Subsequent requested bits are also produced as ones.
- Normal byte packing, row advancement, and total-count termination continue.

Input exhaustion does not produce an error and does not cause an early return.

For an initially empty input interval and a positive output count, the function therefore fills the requested output positions with ones.

### Integer behavior

Run lengths originate from four-bit fields and are at most 15. The pending byte and mask use wider unsigned arithmetic, but only the low eight bits are stored.

The run counter is decremented with unsigned arithmetic. Exhaustion handling can decrement zero to the maximum unsigned value; its subsequent signed interpretation selects the need-for-another-run path. In the represented 32-bit execution model, this sustains the end-of-input one-fill behavior.

The following require separate care:

- A positive total count decreases toward zero without requiring signed overflow.
- A positive row width likewise decreases toward zero.
- Decrementing the most-negative signed width is not covered by a portable signed-arithmetic contract.
- Adding a stride to the integer-held output address may exceed the signed range.
- No explicit validation, saturation, or overflow recovery is present.

These cases must not be silently generalized into a portable wraparound guarantee.

## Side effects

### Output writes

The function writes complete bytes, including partial logical bytes whose unused low bits are cleared.

A byte may be written because:

- Eight bits have accumulated within a row.
- A row has ended.
- The total output count has ended with a partial byte pending.

The function does not initialize untouched output bytes.

A zero stride can cause later rows to overwrite earlier rows. A negative stride can move output toward lower addresses. Insufficient stride can cause rows to overlap. None of these arrangements is checked.

### Control-record mutation

The only explicit control-record assignment is to slot 0 at a completed row.

Slots 1, 2, and 4 are read but not explicitly updated. Slot 3 is not directly accessed.

These statements assume output storage does not overlap the control record. With overlap, ordinary output-byte writes can alter any record bytes they reach.

### Aliasing and read order

No non-aliasing guarantee is established.

If output overlaps the control record, a row-ending byte write occurs before the function rereads the row-base address and width. Those rereads may therefore observe record contents modified by that output write.

The total output count is captured initially and is not reloaded. Altering slot 4 through overlap does not change that local countdown.

If output overlaps unread encoded input, output writes may change bytes consumed later. The routine does not copy the input stream in advance.

### Ownership and external state

The function performs no allocation or release and makes no visible calls. It establishes no ownership transfer for the control record, input, or output storage.

No explicit global-state access is shown. Effects on memory are through the supplied record and derived output addresses.

## Acceptance examples

These examples assume eight-bit bytes, the represented 32-bit arithmetic model, valid non-overlapping storage, and no concurrent mutation. Byte values are hexadecimal.

### One high run followed by one low run

Given:

- Input: `35`.
- Row width: 8.
- Total output count: 8.

The output is `1F`: three zero bits followed by five one bits.

The row completes, so slot 0 advances by one configured stride.

### Zero-length high run

Given:

- Input: `03`.
- Row width: 8.
- Total output count: 3.

The zero-length high run produces nothing. The low run produces three ones.

The output is `E0`. The row is incomplete, so slot 0 is not advanced by the normal row-boundary mechanism.

### Partial-byte clearing

Given:

- Input: `21`.
- Row width: 8.
- Total output count: 3.
- The destination byte initially contains `FF`.

The output byte becomes `20`: two zero bits, one one bit, and five cleared padding bits.

The existing destination contents do not survive.

### Run continuation across rows

Given:

- Input: `08`.
- Row width: 3.
- Total output count: 6.
- Stride: 2.

The active one-run continues across the row boundary.

The function writes `E0` at the initial row base and `E0` two bytes later. Bytes between those row starts are untouched. Slot 0 advances by two strides because both rows complete.

### Retained low nibble at input end

Given:

- Input: `12`, with the end pointer immediately after that byte.
- Row width: 8.
- Total output count: 3.

The output is `60`: one zero followed by two ones.

Reaching the input end after fetching the byte does not discard its low nibble.

### Exhaustion after completed encoded runs

Given:

- Input: `11`.
- Row width: 8.
- Total output count: 5.

The first run produces zero, the second produces one, and exhaustion supplies three additional ones.

The output is `78`, with three cleared padding bits.

### Empty input

Given an empty input interval, row width 8, and total output count 10:

- The first output byte is `FF`.
- The second output byte is `C0`.
- Slot 0 advances once, when the first row completes.
- The final partial row does not cause another row-base advance.

### Nonpositive total count

Given a total output count of zero or less:

- No encoded byte is read.
- No output byte is explicitly written.
- No explicit row-base update occurs.
- The initial control-record reads still require valid record storage.
