# F-99b22bf8cf25

## Purpose

F-99b22bf8cf25 accepts an integer selector and two output-storage addresses. It either rejects the selector without accessing the output storage or writes a fixed pair of 32-bit values and reports success.

The established selector mapping is:

| Selector | Returned 32-bit value | Output-storage accesses |
|---|---:|---|
| 1 | 0x00000031, decimal 49 | None |
| 2 | 0x00000000, decimal 0 | Two ordered writes |
| 3 | 0x00000031, decimal 49 | None |
| Any other representable selector | 0x0000001A, decimal 26 | None |

The values may represent application-specific statuses and a pair of related quantities. Their meanings are not established. In particular, zero is the result associated with the writing path, but no broader status-code convention is supplied.

## Interface

The interface has three inputs:

1. **Selector:** an integer tested against the exact values 1, 2, and 3.
2. **First output address:** an address used as the destination of one 32-bit write when the selector is 2.
3. **Second output address:** an address used as the destination of another 32-bit write when the selector is 2.

The return value is a 32-bit quantity. No input is passed through as the return value.

For selector 2, the output values are:

| Destination | Written bit pattern | Unsigned interpretation | Signed two’s-complement interpretation |
|---|---:|---:|---:|
| First output address | 0xFFFFFFC2 | 4,294,967,234 | −62 |
| Second output address | 0x0000003F | 63 | 63 |

The bit patterns are the primary contract. Signed interpretations describe how a caller might interpret those patterns; they do not establish the application’s intended numeric type.

Each destination designates one 32-bit storage unit. With eight-bit bytes, that is four bytes per destination. The evidence does not establish byte order, a surrounding structure layout, or any relationship between the two addresses.

The selector’s exact ABI width and the pointer width are not independently established by the supplied representation. The observable comparisons do not require either width to be guessed.

### Preconditions

For selector 2, both addresses must support the indicated 32-bit writes under the applicable execution environment. This includes any required address validity, permissions, alignment, and object-access rules.

For every other selector, the function performs no dereference of either output address. Consequently, writable output storage is not required by those execution paths. Whether particular pointer representations can validly be passed through the calling convention remains outside the supplied evidence.

The function performs no explicit address validation. Invalid destinations are not converted into a returned error status.

## Behavior

### Rejected selectors

When the selector is not 2, the function chooses a return value without reading or writing either output location.

Selectors 1 and 3 both produce 0x00000031. Every other selector apart from 2 produces 0x0000001A.

This is an exact-value classification, not a range check. Negative selectors, zero, and values above 3 all belong to the latter category if they are representable by the selector’s actual type. There is no masking, normalization, truncation, or arithmetic transformation of the selector within the supplied behavior.

Output contents do not influence this classification. They need not be initialized for a rejected-selector invocation because this function does not read them.

### Accepted selector

When the selector is exactly 2, the function performs these observable operations in order:

1. Writes the 32-bit pattern 0xFFFFFFC2 to the first output destination.
2. Writes the 32-bit pattern 0x0000003F to the second output destination.
3. Returns the 32-bit value zero.

Both writes are unconditional within this path. The function does not inspect previous output contents, compare the addresses, or skip a write because the destination already contains the intended value.

No output value is calculated from the other output. There is no addition, subtraction, multiplication, shift, or narrowing operation that could introduce a value-dependent arithmetic overflow. The two stored patterns and the return value are fixed constants.

### Aliasing and overlap

The function does not enforce distinct output destinations.

If both addresses designate the same valid 32-bit object, that object first receives 0xFFFFFFC2 and then receives 0x0000003F. After normal completion, its value is therefore 0x0000003F. Returning zero does not imply that two distinct objects were updated.

The evidence establishes the order of the two stores but does not establish support for partially overlapping, differently aligned storage regions. Any byte-level result for such a call depends on memory layout and whether the accesses are valid in the execution environment. Such overlap is documented_only rather than an unconditional supported case.

### Abnormal completion

The zero return follows both writes. It is not an advance indication that either write will succeed.

If a destination cannot be written, the evidence provides no recovery path, rollback, translated error, or guarantee of normal return. In particular, callers must not rely on all-or-nothing output updates: the first write precedes the second, and no compensating write is present.

The precise behavior of an invalid memory access is outside this contract. It must not be inferred that a particular exception, signal, partial update, or return value is guaranteed.

## Side effects

For a normally completed selector-2 call with distinct, valid destinations, the direct memory effects are the two specified 32-bit stores. Previous contents of those storage units are replaced without being read.

For other selectors, no output-storage reads or writes appear in the supplied behavior.

There is no visible allocation, deallocation, ownership transfer, pointer retention, or invocation of another function. The output addresses remain caller-provided storage; the function does not establish a new owner or lifetime for them.

No global variable access, logging operation, or external notification appears in the supplied body. This statement describes the visible operations, not every possible consequence of writing an address. For example, caller-supplied destinations could refer to shared state or special memory whose writes have effects beyond ordinary storage. Such arrangements require environment-specific contracts not provided here.

The two writes are ordered but are not established as a transaction. No synchronization, locking, atomicity, or inter-thread visibility guarantee is supplied. An observer’s ability to detect the intermediate value, including in the exact-alias case, is not established.
