# F-41aa86c4f954

## Purpose

F-41aa86c4f954 replaces the first integer word of a supplied record with a scaled, signed position obtained by scanning an associated array backward. Normal completion returns zero.

Three global coefficients have distinct roles:

- The **initial coefficient** scales the incoming count and determines the scan extent and sign basis.
- The **scan coefficient** participates in each examined element’s zero-product test.
- The **result coefficient** scales the signed retained position before the record is updated.

The scan discards trailing positions whose element multiplied by the scan coefficient equals zero. This is not unconditionally equivalent to discarding zero-valued elements: that equivalence requires suitable coefficient values and arithmetic semantics.

**Inferred intent:** the operation resembles normalization of a signed word count by removing trailing insignificant words. Neither that interpretation nor a particular array data format is established.

## Interface

### Record and array representation

The function receives one pointer to record storage. The supplied representation supports the following apparent 32-bit layout:

| Byte offset | Field | Explicit use |
|---|---|---|
| 0 | Signed incoming count | Read initially; replaced after scanning |
| 4 | Integer-encoded array base address | Read for each reached array-element expression |

Array elements are integer words with a four-byte stride. Candidate position \(K\), using one-based positions, refers to array index \(K-1\), at byte displacement \(4(K-1)\) from the represented base address.

The integer-encoded address is not evidence of a portable native-pointer field. A wider-pointer layout, pointer extension rules, and a general ABI are not established. The four-byte field interpretation is supported by the supplied representation but remains dependent on its accuracy.

The input must designate storage suitable for the accesses actually reached. There is no explicit check for:

- A null or invalid record pointer.
- Insufficient record storage.
- An invalid encoded array address.
- Array bounds or alignment.
- An extent larger than the available array.

A zero scan extent avoids the array-address expression entirely. Consequently, that path does not require a readable address field or valid array storage for the function’s explicit accesses. The count word and reached global accesses must still be valid.

### Global inputs

The three coefficients occupy distinct global locations. Their values, initialization, allowed ranges, and semantic meanings are unknown.

The initial coefficient contributes to one initial product. The scan coefficient appears in every reached element predicate. The result coefficient is used after scanning finishes.

These are storage dependencies, not function dependencies.

### Outputs

On normal completion:

- The record’s first word contains the calculated replacement count.
- The function returns a four-byte result with value zero.
- No separate status distinguishes an initially empty extent, an entirely discarded extent, or an early stop on a nonzero product.

There is no explicit store to the array-address field or array elements. Overlapping storage can make the final count store affect those locations indirectly.

## Behavior

### 1. Establish the signed initial extent

Let \(C\) be the incoming count and \(A\) the initial coefficient. The function forms the signed initial extent:

\[
E=A\times C.
\]

The supplied expression does not establish the relative evaluation order of the count read and the initial-coefficient read.

The sign of \(E\), rather than the sign of \(C\) alone, controls both the initial magnitude calculation and the final sign selection. The original count is not reread for that sign decision.

Under representable ordinary signed arithmetic, the starting extent is:

\[
N=
\begin{cases}
-E,&E<0,\\
E,&E\geq0.
\end{cases}
\]

Thus a negative initial coefficient can reverse the sign associated with the incoming count. An initial coefficient with magnitude greater than one can also enlarge the scanned range beyond the incoming count’s magnitude.

### 2. Scan candidate positions in descending order

At the start of each candidate evaluation, the function checks whether the current extent is zero.

If it is zero, scanning stops without evaluating an array-element expression or reading the scan coefficient for another predicate.

Otherwise, for a positive current extent \(K\), the function examines the element at index \(K-1\). Let that element be \(W_{K-1}\), and let \(B\) be the scan coefficient used for that predicate. The decision is based on:

\[
B\times W_{K-1}=0.
\]

- A nonzero product stops scanning with retained position \(K\).
- A zero product discards that position and advances to candidate extent \(K-1\).

For an ordinary nonnegative extent, examined indices therefore descend from \(N-1\). If all products are zero, index zero is the last element examined; the following zero-extent check terminates the scan without accessing a negative index.

No lower index is examined after a higher candidate produces a nonzero product.

The array-address field and scan coefficient participate in each reached predicate expression. The body does not establish a single snapshot of either value for the entire scan. Nor does it establish the relative evaluation order of the scan-coefficient read and the reads needed to obtain the element. Exact physical load counts and compiler caching behavior are not specified.

The predicate is multiplication followed by comparison with zero, not a short-circuit Boolean test. A zero scan coefficient does not create a source-level path that omits the element expression.

### 3. Determine the retained position

Let \(R\) denote the position at which scanning stops.

For stable storage, valid accesses, and representable arithmetic:

- \(R=0\) when \(N=0\).
- \(R=0\) when all examined products are zero.
- Otherwise, \(R\) is the greatest position in \(1\) through \(N\) whose corresponding element has a nonzero product with the scan coefficient.

This last characterization assumes a stable scan coefficient and stable relevant array values. The stepwise scan description remains the appropriate contract when values can change between accesses; a single-array snapshot is not promised.

With a nonzero scan coefficient and representable multiplication, a product is zero exactly when its element is zero. With a zero scan coefficient, every reached product is zero and all \(N\) candidates are discarded, provided the required accesses remain valid.

### 4. Apply the sign and result coefficient

The saved initial extent supplies the sign:

\[
S=
\begin{cases}
-R,&E<0,\\
R,&E\geq0.
\end{cases}
\]

After scanning, the function uses the result coefficient \(D\) to calculate:

\[
Q=D\times S.
\]

It stores \(Q\) into the record’s first word, then returns zero.

Consequences under ordinary representable arithmetic:

- A negative result coefficient reverses the signed retained position.
- A zero result coefficient produces zero but does not bypass scanning.
- A zero retained position produces zero regardless of the selected sign branch.
- The incoming count is not progressively overwritten as candidates are discarded. There is one explicit count store, after the scan.

## Acceptance examples

These are conditional acceptance examples derived from static evidence, not executed tests. Unless stated otherwise, they assume stable storage, valid reached accesses, the apparent four-byte word layout, and representable ordinary arithmetic.

### Zero initial extent avoids the scan

Given incoming count zero and any initial coefficient:

- The initial extent is zero.
- No array-address or array-element expression is reached.
- No scan-coefficient read is needed for a predicate.
- The result coefficient is still used in the final calculation.
- The count becomes zero and the function returns zero.

A zero initial coefficient has the same effect for any incoming count whose initial multiplication is defined. An invalid unused array address does not by itself invalidate this explicit access path.

### Trailing zero elements are discarded

Given count 5, all three coefficients equal to 1, and array prefix \([7,0,9,0,0]\):

- Indices 4, 3, and 2 are examined, in that order.
- The first two products are zero; the third is nonzero.
- The retained position and replacement count are 3.
- Indices 1 and 0 are not examined.
- The return value is zero.

### Negative extent retains backward traversal

Given count \(-5\), initial coefficient 1, scan coefficient 1, result coefficient 2, and the same array:

- The initial extent is \(-5\), and the starting magnitude is 5.
- Indices 4, 3, and 2 are examined.
- The retained position is 3.
- Sign application produces \(-3\).
- The stored result is \(-6\), and the return value is zero.

A negative extent does not reverse traversal toward increasing array indices.

### Initial scaling affects both extent and sign

Given count 2, initial coefficient \(-2\), scan coefficient 1, result coefficient 1, and a nonzero element at index 3:

- The initial extent is \(-4\).
- Index 3 is examined first.
- Its nonzero product stops the scan.
- The replacement count is \(-4\).

Storage sufficient for only two elements would not satisfy the reached access requirement.

### Entire extent is discarded

Given initial extent 4, scan coefficient 1, and four zero elements:

- Indices 3, 2, 1, and 0 are examined.
- The retained position becomes zero.
- No negative index is examined.
- The replacement count and return value are zero.

### Zero scan coefficient does not excuse invalid reads

Given initial extent 3 and scan coefficient zero:

- The reached element expressions are for indices 2, 1, and 0.
- Every product is zero.
- The retained position and replacement count are zero.

An invalid array cannot be accepted merely because multiplication by zero determines the predicate result mathematically.

### Zero result coefficient does not bypass scanning

Given initial extent 3, scan coefficient 1, a nonzero element at index 2, and result coefficient zero:

- Index 2 is examined.
- Scanning stops at retained position 3.
- The final count becomes zero.

An unconditional early return based only on the result coefficient would not preserve this access behavior.

### Minimum signed extent is unresolved

If the initial product is \(-2^{31}\) in a 32-bit signed model, the ordinary positive-magnitude scan interpretation does not apply without additional execution-model evidence. No particular scan result or normal return is accepted unconditionally for that case.
