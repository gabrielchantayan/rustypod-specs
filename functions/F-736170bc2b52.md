The invocation sequence includes sites with no explicitly represented arguments and sites with one through four explicitly represented arguments. A site with no represented arguments is not evidence that all machine argument locations contain zero or that the target has an independently established zero-argument interface.

Several preparation patterns recur:

- A 32-bit result is shifted left by eight bits and supplied to a later invocation.
- A represented 64-bit result is separated into lower and upper 32-bit portions.

### 3. Transition to direct memory mutation

The final preparation results establish several address-like quantities:

- A value formed from a dependency result scaled by 2²⁵.
- A small value formed by shifting another result left eight bits, masking to 15 bits, then shifting right six bits.

These are descriptive roles, not established object types.

Under 32-bit bit-vector arithmetic, the small value is at most 508 and is divisible by four. Twice that value is at most 1016 and divisible by eight. Consequently, some represented accesses target small numeric addresses rather than offsets within an established caller-provided allocation.

The direct-mutation phase begins with a 32-bit store at an upper-result-derived base plus 0x14. It then performs an 8-bit store at the left-shift-derived base plus 9, a 32-bit store at a lower-result-scaled address plus 0x54, and another 8-bit store at the same base-plus-9 location.

## Acceptance examples

These are conditional static acceptance criteria, not executed tests.

1. **Initial argument forwarding.** If the first argument is 1 and the second is an arbitrary 32-bit token, F-unknown-entry receives represented arguments 1, that unchanged token, and 128.

2. **Input truncation under machine arithmetic.** If the first argument has bit pattern 0x02000000, its seven-bit left-shifted argument is zero under 32-bit bit-vector semantics. Unlimited-precision multiplication would not be equivalent.

3. **Paired-result separation.** If a dependency produces represented 64-bit value 0x1122334455667788, its upper portion is 0x11223344 and lower portion is 0x55667788. A subsequent eight-bit left shift of the lower portion produces 0x66778800 under 32-bit semantics.

4. **Masked field extraction.** For a value 0xABCDEF12, masking to 24 bits before shifting right 20 bits yields 0xC. Retaining the original high byte would produce a different result.

5. **Small-address derivation.** If the result used to derive the small value has low seven bits equal to 0x7F, the derived value is 508 and its doubled base is 1016, conditional on the represented 32-bit shifts.

6. **Overlapping writes.** If a zero word at base plus 0x14 is followed by a byte write at base plus 0x15, acceptance requires preservation of both events. The final word interpretation requires target byte order.

7. **Unsigned byte expansion.** If the byte read for an offset-0x34 word store is 0xFE, the stored word is 254, not a sign-extended negative value.

8. **Aliased reload.** If an intervening write overlaps a word previously set to zero, a later load observes the memory then present. Acceptance must not substitute the earlier zero assignment.

9. **Partial failure.** If execution faults during direct mutation, this contract supplies no requirement to undo earlier dependency effects or stores.

10. **Terminal arguments.** If execution reaches F-unknown-terminal, its first represented argument is 0x72. The remaining arguments retain their distinct saved or recently loaded provenance rather than being interchangeable current-memory values.
