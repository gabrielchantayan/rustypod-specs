# F-b83721fe9bd3

## Purpose

F-b83721fe9bd3 performs four construction-like operations, selects a handle through a context-dependent lookup, writes two signed context values into the third operation’s result, and returns that result. The fourth operation’s result is discarded.

The construction chain suggests assembly of related objects. Allocation, presentation, layout, parent-child relationships, and registration are inferred roles, not established semantics.

Established behavior includes the order of dependency calls, reads of mutable global reference slots, temporary-storage accesses, handle-selection branches, two direct object writes, and the normal return value. There is no explicit success indicator, rollback, or caller-side release.

## Behavior

### Preparation and first construction

F-9fb2b387607a is called with the context and preparation-region address.

After that call returns, the function reads the **first-template global slot** and passes the retrieved reference to F-U01 as the source for a transfer into the first descriptor, with extent `0x5C`. The reference is not established as a fixed template address; preparation may have affected the slot.

A second F-U01 call receives:

- Destination: first-descriptor offset `0x1C`.
- Source: the twelve-word temporary region.
- Extent: `0x30`.

If F-U01 performs an ordinary byte copy, this replaces first-descriptor bytes `0x1C` through `0x4B`, inclusive. At this time the caller has not explicitly initialized the twelve-word source region. Its later assignments do not determine the earlier transfer’s contents.

F-8157a180d901 is then called with `0xE8`. Its 32-bit result is passed to F-da04303b789f, followed by literal zero, the second input, the third input, and the first-descriptor address. The resulting value is retained as the first constructed value.

Neither result is checked for failure.

### Second construction

After the first construction returns, the function reads the **second-template global slot**. F-U01 receives that reference, the second-descriptor destination, and extent `0x5C`.

After this transfer returns, the function reads the 32-bit preparation word at offset `0x08`, bitwise-ORs it with `0x80000000`, and writes the result to second-descriptor offset `0x10`.

This is a 32-bit mask operation: bit 31 is set and bits 0–30 are preserved. It is not addition and produces no carry.

F-8157a180d901 is called with `0xEC`. F-c47b7ab19be0 then receives, in order:

1. That dependency result.
2. Literal zero.
3. The first constructed value.
4. The third input.
5. The second-descriptor address.

Its result is retained as the second constructed value. There is no explicit failure check.

### Twelve ordered source reads and destination writes

Only after the second construction returns does the caller explicitly initialize the twelve-word temporary region.

Each assignment independently reads the **data-source global slot**, reads one 32-bit word through the reference just obtained, and writes that value to the next destination word. The source-index sequence is:

| Destination word indices | Source word indices, in assignment order |
|---|---|
| 0–2 | 0, 1, 2 |
| 3–5 | 0, 1, 2 |
| 6–8 | 3, 4, 5 |
| 9–11 | 0, 1, 2 |

Destination word index `n` denotes byte offset `4n`. Source indices 0–5 denote byte offsets `0x00`, `0x04`, `0x08`, `0x0C`, `0x10`, and `0x14` from the reference obtained for that assignment.

This is **not** a single read of a global reference followed by use of a stable six-word snapshot. There are twelve ordered reference reads and twelve corresponding source-word reads, each preceding its destination write.

Reference stability and source/destination disjointness are unknown. If a destination write aliases a source word used later, that later source read can observe the write. If a destination write can affect the global reference slot, a later assignment can obtain a different reference. No intervening dependency call is visible, but that does not establish non-aliasing.

These assignments do not retroactively initialize the source of the earlier transfer. No later explicit call argument directly identifies this twelve-word region; effects through retained addresses or aliasing remain unknown.

### Handle selection

The function reads context offset `0xC4` and calls F-ccabec065f5e with that 32-bit value and the lookup-output-region address.

The first lookup-output word controls selection:

- **Zero:** F-9d0ecc5f6adf is called, and its return becomes the selected handle.
- **Nonzero:** That word is passed to F-283eda65a14c.
  - A zero resolver result produces a zero selected handle.
  - A nonzero result is treated as an object address. The function reads the object’s leading 32-bit dispatch-table reference, reads the callable entry at dispatch-table byte offset `0x14`, and invokes F-U02 with the object address and literal `5`. Its return becomes the selected handle.

Resolver failure does not invoke the default provider. No validation of the resolved object, dispatch table, or callable entry is visible.

### Third construction and optional notification

F-8157a180d901 is called with `0x11C`. F-ef17ff017bee then receives:

1. That dependency result.
2. The selected handle.
3. The second constructed value.
4. The third input.
5. The preparation-region address.

Its result is retained for the direct writes and eventual return.

After this construction returns, the function reads context offset `0xB8`. If nonzero, it reads the **notification global slot** and calls F-5710a8628cba with the selected handle and the retrieved reference.

The notification-slot read occurs only inside this branch. It is not performed unconditionally or before the third construction. There is no selected-handle validity check: a zero handle is still passed when the context field is nonzero.

### Returned-object writes and final construction

After the optional notification has completed—or its branch has been skipped—the function reads the **final-template global slot** and retains the retrieved reference.

It then performs these direct accesses in order:

1. Read the signed 16-bit context field at `0x3C`.
2. Sign-extend it and write 32 bits at returned-object offset `0x20`.
3. Read the signed 16-bit context field at `0x3E`.
4. Sign-extend it and write 32 bits at returned-object offset `0x24`.

Each input halfword represents a value from −32768 through 32767. Widening preserves that signed value.

The final-template reference has already been read before these accesses. F-U01 subsequently receives that retained reference, the final-descriptor destination, and extent `0x70`. The source reference is not freshly loaded from its global slot after the object writes. This distinction matters if those writes alias that slot.

After the transfer returns, the preparation word at offset `0x08` is read again, ORed with `0x80000000`, and written to final-descriptor offset `0x68`. This fresh read need not equal the value used for the second descriptor.

F-8157a180d901 is called with `0x580`. F-ab1dbc69170e then receives its result, literal zero, the first constructed value, the third input, and the final-descriptor address.

The final construction’s result is discarded. Normal return delivers the earlier result of F-ef17ff017bee.

## Acceptance examples

These are conditional static criteria, not executed tests. Completion examples assume all required accesses are valid and invoked dependencies return normally.

1. **First-template timing.** If preparation changes the first-template slot, the first transfer receives the slot value read after preparation, not a presumed entry-time value.

2. **Second-template timing.** If the first construction changes the second-template slot, the next descriptor transfer uses the value read after that construction.

3. **Independent source reads.** With an unchanged data-source reference, disjoint source and destination regions, and stable source words, the destination follows the documented index sequence. Without those conditions, repeated source indices need not produce equal values.

4. **Aliasing during initialization.** If writing destination word 0 changes source word 1 through aliasing, the following assignment reads the changed source word 1. A preloaded six-word snapshot would not satisfy this behavior.

5. **Zero lookup word.** A zero first output word calls F-9d0ecc5f6adf and bypasses the resolver and indirect method.

6. **Failed nonzero resolution.** A nonzero output word followed by a zero resolver result yields a zero selected handle without calling the default provider.

7. **Successful resolution.** A valid resolved object is dispatched through table offset `0x14` with literal `5`; that call’s return becomes the selected handle.

8. **Notification branch.** A zero context field at `0xB8` causes neither notification nor its associated global-slot read. A nonzero field causes both, even with a zero selected handle.

9. **Final-reference timing.** If notification changes the final-template slot, the subsequent read observes that change. If the later object writes change the slot, the final transfer still receives the reference already retrieved.

10. **Signed widening.** Context halfwords `0xFFFF` and `0x8000` become 32-bit values `0xFFFFFFFF` and `0xFFFF8000`, respectively.

11. **Fresh mask inputs.** Preparation words `0x00000025` and `0x80000025` both produce `0x80000025` when masked. Different values at the two read times may produce different descriptor fields.

12. **Early transfer and return identity.** Under ordinary copy semantics, the early `0x30` transfer uses temporary contents present before explicit initialization. Independently, a different final-construction result does not replace the third result as the function’s return.
