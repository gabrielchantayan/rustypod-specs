# F-7ed325e66f98

## Purpose

F-7ed325e66f98 advances a mutable, fixed-point position to a supplied endpoint. Depending on a row-range overlap check and whether the movement crosses a row boundary, it invokes dependencies to process portions of the movement, update row-associated state, or both.

**Inferred intent:** The use of eight fractional bits, row transitions, and two accumulated quantities is consistent with incremental coverage or edge processing. The supplied evidence does not establish a public graphics API, a fill rule, or the meanings of the accumulators.

**Established behavior:** Even when the overlap check rejects processing, the function records the requested endpoint and its aligned row base. Rejection does not leave the position unchanged.

## Interface

### Inputs and result

The function receives four arguments:

1. A state-object address represented by a 32-bit machine value.
2. A signed 32-bit target horizontal coordinate, denoted \(X_t\).
3. A signed 32-bit target vertical coordinate, denoted \(Y_t\).
4. An uninterpreted 32-bit value, denoted \(A\).

There is no defined return value. Observable results are state writes and dependency calls.

Coordinates use an apparent fixed-point scale of 256 units per integer coordinate. For a value \(v\), this contract uses:

- \(\operatorname{row}(v)=v\mathbin{\text{arithmetic-right-shift}}8\);
- \(\operatorname{frac}(v)=v-256\operatorname{row}(v)\).

Under arithmetic right-shift semantics, negative coordinates are partitioned using floor division, not truncation toward zero. For example, a coordinate of \(-1\) has integer part \(-1\) and fraction 255.

## Behavior

### 1. Entry observations and overlap decision

Before invoking any dependency, the function derives:

- Target row \(r_t=\operatorname{row}(Y_t)\).
- Starting vertical fraction \(f_s\): stored vertical coordinate minus stored row base.
- Starting row \(r_s=\operatorname{row}(\text{stored row base})\).
- Target vertical fraction \(f_t=\operatorname{frac}(Y_t)\).
- Starting horizontal coordinate \(X_s\).
- Horizontal displacement \(\Delta X=X_t-X_s\).
- Vertical displacement \(\Delta Y=Y_t-\text{stored vertical coordinate}\).

The visible read sequence samples the stored vertical coordinate and row base for their difference, reads the row base again for the starting row, reads the stored horizontal coordinate, and reads the stored vertical coordinate again for the displacement. No snapshot or synchronization mechanism is shown.

Let \(r_{\min}\) and \(r_{\max}\) be the smaller and larger of the starting and target rows. Processing is admitted only when:

\[
r_{\min}<\text{upper bound}
\quad\text{and}\quad
\text{lower bound}\le r_{\max}.
\]

The upper bound is read first. The lower bound is read only if the first condition succeeds.

This is an overlap test, not geometric clipping. Once admitted, processing is not visibly trimmed to the bounds, and individual rows are not checked again.

If the check rejects processing, no dependency is invoked and neither accumulator is directly modified. Endpoint recording still occurs.

### 2. Movement within one row

If processing is admitted and \(r_s=r_t\), the function makes one call to F-12a769ff3c30 with these six arguments, in order:

1. State address.
2. Starting row.
3. Starting horizontal coordinate.
4. Starting vertical fraction.
5. Target horizontal coordinate.
6. Target vertical fraction.

No row-transition call or quotient-like calculation occurs. This includes a zero-length movement: equal endpoints do not suppress this call when the overlap check admits the row.

### 3. Row-crossing movement with unchanged horizontal coordinate

If processing is admitted, the rows differ, and \(\Delta X=0\), the function uses direct accumulator updates instead of F-12a769ff3c30.

It derives the integer horizontal coordinate \(c=\operatorname{row}(X_s)\) and twice the horizontal fraction:

\[
w=2\operatorname{frac}(X_s).
\]

Direction is selected from \(\Delta Y\), not from a direct comparison of the row indices:

- If \(\Delta Y<0\), row step \(s=-1\) and boundary fraction \(b=0\).
- Otherwise, row step \(s=1\) and boundary fraction \(b=256\).

The initial vertical contribution is \(b-f_s\). The function:

1. Adds \(w(b-f_s)\) to accumulator `0x1c`.
2. Advances the local row by \(s\).
3. Adds \(b-f_s\) to accumulator `0x20`.
4. Calls F-b443dcf6eb72 with the state address, \(c\), and the advanced row.

For each additional row transition needed to reach the target row, the full-row contribution is \(2b-256\), hence either \(256\) or \(-256\). Each transition advances the local row, adds \(w(2b-256)\) to `0x1c`, adds \(2b-256\) to `0x20`, and invokes F-b443dcf6eb72 for that row.

After the transition into the target row, the final contribution is:

\[
f_t+b-256.
\]

That contribution, multiplied by \(w\), is added to `0x1c`; the unmultiplied contribution is added to `0x20`. No F-12a769ff3c30 call follows.

Each accumulator update reads the field’s current memory value. Consequently, changes made by F-b443dcf6eb72 can affect later additions.

### 4. Row-crossing movement with changing horizontal coordinate

If processing is admitted, the rows differ, and \(\Delta X\ne0\), the function divides the movement into a starting-row portion, optional full-row portions, and a target-row portion.

For nonnegative \(\Delta Y\), it chooses:

- Row step \(s=1\).
- Ending boundary fraction \(b=256\).
- Initial vertical distance \(h=256-f_s\).
- Divisor-like magnitude \(D=\Delta Y\).

For negative \(\Delta Y\), it chooses:

- Row step \(s=-1\).
- Ending boundary fraction \(b=0\).
- Initial vertical distance \(h=f_s\).
- Divisor-like magnitude \(D=-\Delta Y\).

Under the conventional state invariant and representable arithmetic, differing rows imply a nonzero vertical displacement, so \(D\) is positive. That is not independently checked.

#### First boundary calculation

F-870c4fcf7295 is called with four visible arguments:

1. \(\Delta Xh\), computed at 32-bit width.
2. \(D\).
3. A fresh read of the upper-bound field at `0x18`.
4. \(A\).

The returned 64-bit value is interpreted both as a signed whole and as separate low and high 32-bit words. This contract does not assume that those words actually represent a quotient and remainder.

The low word becomes a horizontal increment; the high word becomes a remainder-like state. If the complete 64-bit result is negative, the function independently subtracts one from the low word and adds \(D\) to the high word. These are separate word corrections, not a single 64-bit subtraction.

The corrected low word is added to \(X_s\), producing the first boundary coordinate \(X_b\).

The function then calls:

1. F-12a769ff3c30 for the starting row, from \((X_s,f_s)\) to \((X_b,b)\).
2. F-b443dcf6eb72 after advancing one row, with horizontal integer coordinate \(\operatorname{row}(X_b)\) and the newly entered row.

If this reaches the target row, no second F-870c4fcf7295 call is made.

#### Intermediate boundary calculation and remainder distribution

If more row transitions remain, F-870c4fcf7295 is called again. This invocation has only two visible arguments:

1. \(\Delta X\cdot256\), computed at 32-bit width.
2. \(D\).

Its result receives the same sign-dependent, independent low-word and high-word corrections. Let the resulting words be \(Q\) and \(R\). Let \(E\) initially be the corrected high word from the first result minus \(D\).

For each remaining full-row traversal:

- \(R\) is added to \(E\).
- The horizontal increment is \(Q+1\) if the resulting \(E\) is nonnegative, and \(Q\) otherwise.
- In the nonnegative case, \(D\) is subtracted from \(E\).
- The increment is added to the current boundary coordinate to obtain the next boundary coordinate.
- F-12a769ff3c30 processes the current row from vertical fraction \(256-b\) to \(b\).
- The row advances by \(s\).
- F-b443dcf6eb72 is called using the next boundary coordinate’s integer part and the newly entered row.

The loop stops when the local row equals the target row. The branch condition is signed nonnegativity, including zero.

#### Target-row portion

After entering the target row, F-12a769ff3c30 is called once more, from the latest boundary coordinate at vertical fraction \(256-b\) to \((X_t,f_t)\).

### 5. Endpoint recording

Every normally returning path finishes with three direct writes, in this order:

1. Store \(X_t\) at `0x38`.
2. Store \(Y_t\) at `0x3c`.
3. Store the target row shifted left by eight bits at `0x40`.

These writes occur after all dependency calls. A dependency’s earlier modifications to these three fields are therefore overwritten on normal completion. Modifications to other state are not similarly restored.

There is no rollback path.
