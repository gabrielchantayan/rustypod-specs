# F-4c48e56a48cf

## Purpose

F-4c48e56a48cf calls two dependencies and then writes three fields through the address returned by the second dependency.

The established sequence is:

- Call F-8157a180d901 with the value 72.
- Pass its 32-bit result, two zero arguments, and three ambient values to F-bb27b9d7a176.
- Use the second dependency’s result as the destination address.
- Copy a fixed-location source word to destination offset 0.
- Evaluate a global root-pointer designator, dereference the slot it locates, follow two further address relationships, and copy the final word to destination offset 64.
- Store one zero byte at destination offset 68.

The request value and field placement suggest object initialization. That is **inferred intent**, not evidence that either dependency allocates memory, that the destination is a particular object type, or that ownership transfers.

The global root-pointer evaluation is part of the later lookup. It must not be silently replaced with a root-slot address captured before the dependencies or before the offset-0 store.

## Behavior

### Dependency calls

F-8157a180d901 is called once with 72, equivalently hexadecimal 0x48.

F-bb27b9d7a176 is then called once with six supplied arguments, in this order:

1. The first dependency’s 32-bit result.
2. Zero.
3. Zero.
4. The first ambient 32-bit value.
5. The second ambient 32-bit value.
6. The third ambient 32-bit value.

The result of the second call supplies the destination address. The first result is not independently used as the destination.

There is no conditional branch or explicit success check between these calls. Neither dependency may be assumed to preserve the fixed source, global root-pointer state, pointed-to slot, later lookup storage, or destination contents.

### First destination update

After both dependencies return, the routine obtains the fixed-location source word and stores its 32-bit value at destination offset 0.

This is a data read at this stage, not an established compile-time constant or a snapshot from function entry.

The store completes before the root-based lookup is evaluated. Consequently, if destination offset 0 overlaps storage used to hold the global root-pointer value, the store can affect which slot the later lookup locates. If it instead overlaps the pointed-to slot or a later lookup field, it can affect those reads.

### Global root-pointer evaluation and lookup

The root-derived source is obtained through four logically distinct stages:

1. **Evaluate the global root-pointer designator.** Its pointer value locates the slot to be dereferenced.
2. **Read the located slot.** The slot supplies the first base value.
3. **Read the intermediate address-bearing value.** Its location is 48 bytes, hexadecimal 0x30, beyond the first base.
4. **Read the final word.** Its location is 3996 bytes, hexadecimal 0xF9C, beyond the intermediate address-bearing value.

The final word is copied to destination offset 64 as a 32-bit value.

The first two stages are not interchangeable. Obtaining the pointer that locates a slot is distinct from reading the base stored in that slot. A description beginning only with a designated root slot would omit a potentially observable input to the lookup.

The supplied data declarations are absent. Therefore, whether evaluating the global designator entails a separate read of a stored pointer, rather than another form of address resolution, remains **documented_only**. This uncertainty does not permit omitting the evaluation or moving it earlier. If the designator denotes stored pointer state, that state is consulted at this later stage and can reflect dependency effects or the preceding destination store.

The intermediate address-bearing load is represented through a signed 32-bit integer interpretation. The final source load is 32 bits. The exact declared type and read width of the earlier slot dereference cannot be independently recovered without the missing declaration.

Offsets 48 and 3996 belong to different address bases. They must not be combined into a single displacement from the first base.

No root-pointer value, slot value, or later lookup value is explicitly captured before the dependencies or before the offset-0 store.

### Final destination update

After the offset-64 word store, the routine writes zero to the byte at destination offset 68.

This is not a four-byte clear. At this stage, the routine performs no direct store to offsets 69–71.

It then returns without an explicit value.

### Observable ordering and aliasing

1. First dependency call.
2. Second dependency call.
3. Fixed-location source read and destination offset-0 store.
4. Global root-pointer evaluation.
5. Dereference of the slot located by that pointer.

- Dependencies can affect the global pointer value itself, not merely the slot it locates.
- The offset-0 store can affect that pointer value, the located slot, or later lookup storage.
- The final root-derived value is read before the offset-64 store.
- The last byte store can alter aliased source storage, but the routine does not subsequently repeat the lookup.

This describes the supplied operation sequence, not hardware transactions. Atomicity, synchronization, concurrency behavior, and exact bus-level accesses are not established.
