# F-1dd3c3549936

## Purpose

F-1dd3c3549936 forwards an input word through an initial dependency, executes an ordered series of calls and address-derived memory accesses, and writes a six-word record. Further calls follow the record writes. The supplied static representation ends at an invalid-instruction boundary; it does not establish a normal return.

**Established static evidence:** explicit call/result relationships, mixed-width memory accesses, capture of two image-defined words, and six consecutive 32-bit record stores.

**Inferred intent:** the sequence may perform low-level initialization or configuration. Neither the meaning of the addresses nor an application-level purpose is established.

**Contract scope:** the following requirements describe the supplied operations conditionally on their being reachable and correctly represented. A control-flow warning prevents treating the entire sequence as a verified executable path.

### 2. Early memory accesses

The following regions occur without an intervening visible call. Ordering across the described operations is established by the supplied representation; ordering within individual compound expressions is qualified below.

**Byte-derived address**

1. Read a signed byte from the address formed by shifting the signed secondary byte left by two.
2. Sign-extend the loaded byte to a 32-bit value.
3. Store that value as a word at the value plus `0x70`.
4. Read a word at the value plus `0x20`.

The loaded byte, not its original address, supplies both later address bases.

**Word- and halfword-derived addresses**

Using the word just read:

- Multiply it by `0x01000000`, then store the resulting word at that result plus `0x40`.
- Read a signed halfword from the address formed by shifting the preceding loaded word left by 25.
- Store the sign-extended halfword as a word at that signed value plus `0x138`.
- Multiply the signed halfword value by `0x10000`.
- Store this scaled word at itself plus `0x10`.
- Store a zero halfword at the scaled value plus `0x138`.

The halfword-load address is derived from the preceding **loaded word**, not from its product with `0x01000000`.

**First image-defined data cell**

A 32-bit snapshot is read from a distinguished image-defined cell. A later word store refers to that same cell again for both its destination base and payload: the destination is the referenced base plus `0x40`, and the stored word is the referenced value.

Those references must not be replaced by the earlier snapshot without additional evidence. Earlier stores may alias the cell. The representation does not establish the relative evaluation order of the destination-base reference and payload reference within that store.

Afterward, the low 16 bits of the earlier snapshot are stored at the snapshot minus `0x130`.

**High-byte-derived location**

The earlier snapshot is logically shifted right by 24, yielding a value from zero through 255. At the address obtained by shifting that value left by 17:

1. Store a word equal to the value multiplied by `0x10000`.
2. Store a zero halfword at the same address.
3. Read a word to obtain an indirect destination, read a word from that same source address to obtain the payload, and store the payload through the destination.

The final operation contains two separate word reads from the same location. Their relative order is not established, and their values need not match if the memory changes or has read side effects.

The word write followed by the halfword write must remain distinct. Their combined final byte pattern depends on byte order and memory behavior.

**Reset-associated value**

This use does not establish a call to a reset routine.

### 3. Ambiguous shift, retained words, and derived values

Another image-defined word is multiplied by `0x10000000`. A word is read at that product minus `0x130`.

The representation applies a signed right shift of **32 positions** to this loaded 32-bit word. That is not an established ordinary 32-bit shift operation. Its result remains `documented_only`; it must not silently be replaced with zero, a sign fill, or the unshifted input.

Conditional on a concrete execution interpretation supplying a result:

1. Store that result as a word at itself minus `0x130`.
2. Read the **first retained image-defined word**.
3. Read the **second retained image-defined word**.
4. Derive a base from the shift result:
   - Add four and retain the bits selected by `0xF0000000`.
   - Interpret that masked quantity as signed and shift right by 24.
   - Multiply by `0x100`, subtract `0x130`, and retain the low 16 bits.
   - Shift that quantity right by four and multiply by `0x10000`.
5. Read a word at the derived base plus `0x10`.

The order of the two retained-word reads is significant. Their later record placement is deliberately not in read order: the **first read supplies offset `0x10`**, while the **second read supplies offset `0x0C`**.

Two values are formed independently from the word loaded at the derived base plus `0x10`:

- **Scaled value:** multiplication by `0x10000`.
- **Shifted value:** left shift by 12.

The shifted value is derived from the loaded word, not from the scaled value. Under a low-32-bit interpretation, the derived base is a multiple of `0x10000` and is within `0x00000000`–`0x0FFF0000`. This bound establishes neither address validity nor that every value in the interval can occur.

### Width-sensitive writes

### Non-returning dependency
