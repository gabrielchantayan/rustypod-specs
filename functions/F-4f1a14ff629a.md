# F-4f1a14ff629a

## Purpose

The available static evidence does not establish a higher-level purpose. In particular, the numeric constants do not establish text formatting, a device protocol, or a conventional object model. ## Behavior

### Initial writes and global-base capture

The first observable operation writes the initial payload as a word at the initial destination base plus `0x20`.

The selector-derived word destination is selector base plus `0x20`. Before the record base is read, that destination receives these ordered word values:

1. `0x00000020`.
2. `0x0000002F`.
3. A zero-extended byte read from selector base plus `0x04`.
4. `0x00000020`.

The byte read occurs after the first two writes. Its value must therefore reflect any applicable aliasing or externally observable memory behavior at that point, rather than an assumed entry-state snapshot.

The record base is then read from the global base slot and retained for subsequent uses. Later writes do not cause this captured base to be refreshed.

A word write of `0x00000020` to absolute address `0x60` follows. The function then writes doubled context as a word at doubled secondary index plus `0x54`.

### Repeated record and selector updates

The next region repeatedly writes the same small set of destinations. It does not visibly advance through an array.

Each update group writes, in order:

- The low byte of selector base at record base plus `0x19`.
- The low byte of record base at selector base plus `0x11`.
- A word at record base plus `0x34`.

For the first group, the final word is doubled secondary index. For subsequent groups, it is selector span. Word writes of doubled context at selector span plus `0x54` separate successive groups.

The region ends after the final group’s write to record base plus `0x34`; the later tail then begins. Repeated writes are part of the visible access sequence even when they leave ordinary memory unchanged. They cannot generally be collapsed where write counts, aliases, or device-side effects are observable.

The exact repetition count is **documented_only**: it is not independently established here. This limits any acceptance criterion requiring an exact full access trace.

### Tail captures and byte propagation

After the repeated region, several values are captured in a specific order:

- A word from absolute address `0xA9`, called the **captured global word**.
- A word from doubled context plus `0x74`, called the **captured link word**.
- A byte write to absolute address `0x3A`, containing the low byte of eight times the selector plus `0x30`.
- A word from context base plus `0x14`, called the **saved context word**.
- A word from selector base plus `0x04`, called the **saved selector word**.

The read at selector base plus `0x04` is now a word read. It is distinct from the earlier byte read at the same starting address and occurs much later.

The function then makes these byte writes, in this order:

- Low byte of selector base to context base plus `0x0D`.
- `0x6C` to selector base plus `0x08`.
- Low byte of record base to selector base plus `0x0D`.
- Low byte of record base to selector base plus `0x09`.

It next writes the context base itself as a word at context base plus `0x54`, then writes the low byte of the captured global word to absolute address `0x67`.

### Context-field capture and overlapping updates

A word is read from context base plus `0x44`, called the **captured context field**. After that read:

- The byte currently at absolute address `0x67` is copied to absolute address `0x21`.
- The low byte of the captured context field is written at selector base plus `0x10`.
- The captured context field is written as a word at record base plus `0x54`.
- A shifted byte derived from the captured context field is written at context base plus `0x01`.
- Selector base is written as a word at record base plus `0x54`, replacing the preceding word there unless other aliasing changes the situation.

The shift count is the low byte of selector base, giving a represented range of 0 through 255. The operand is represented as signed. Behavior for counts of 32 or greater, and the exact treatment of negative operands, are **documented_only**. The evidence does not justify imposing a masked shift count or a portable arithmetic-shift rule.

A word is then read from selector base plus `0x40`. Subsequently:

- Saved selector word is written at record base plus `0x74`.
- The newly read word is written at selector base plus `0x10`.
- Context base is written at record base plus `0x44`.
- A fresh byte read from absolute address `0x67` is written at selector base plus `0x09`.
- Low byte of selector base is written at context base plus `0x09`.
- Captured global word is written at selector base plus `0x44`.

The word write at selector base plus `0x10` covers offsets `0x10` through `0x13`. It can therefore replace both the earlier byte at offset `0x10` and the repeated-region byte at offset `0x11`. Those earlier writes remain observable events even when later overwritten.

### Pointer-derived destinations and final captures

The function next reads a word from selector base plus `0x54`, treating it as a **linked destination**. It then:

- Again copies a freshly read byte from absolute address `0x67` to selector base plus `0x09`.
- Writes the low byte of captured link word at linked destination plus `0x0D`.
- Writes saved context word at context base plus `0x54`.
- Reads a word from selector base plus `0x14`, retaining it as a **selector tail word**.
- Writes the low byte of captured link word at context base plus `0x11`.
- Writes the low byte of linked destination at selector base plus `0x09`.
- Writes linked destination as a word at selector base plus `0x44`.

These destinations are not guaranteed to be independent. In particular, writes through linked destination may affect later reads if the underlying ranges overlap.

The final preparation uses two more memory-derived addresses:

- A word read from context base plus `0x04` supplies a **tail base**.
- A halfword write of `0x0065` is made at twice tail base.
- A word read from tail base plus `0x64` supplies a **tail value**.
- The low byte of selector tail word is written at linked destination plus `0x11`.
- The word `0x00000064` is written at linked destination plus `0x54`.
- A word read from tail base plus `0x74` supplies the **final captured word**.
- A word read from context base plus `0x64` supplies a **final destination base**.
- Low byte of tail base is written at context base plus `0x09`.
- Tail value is written as a word at final destination base plus `0x54`.
- Final destination base is written as a word at twice tail value.

The accesses at `0x64` and the value `0x64` are decimal 100. The doubled-address writes do not have an additional object-relative offset.
