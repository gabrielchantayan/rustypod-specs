# F-21116018347c

## Purpose

F-21116018347c conditionally retrieves a 32-bit result for a signed 32-bit index. Lookup requires both an initially nonzero entry-table address and an index strictly below a signed limit. For an eligible index, a flag selects one of two result sources:

- A 32-bit word from a parallel value table.
- The 32-bit result of an indirectly selected function invoked with the index and an auxiliary argument.

The function returns zero when the initial entry-table address is zero or the signed comparison rejects the index. Zero is also a possible successful result from either result source, so the return value alone does not distinguish rejection from successful retrieval.

The eligibility condition has **no lower-bound check**. Negative indices can pass and select storage before the nominal table bases, subject to 32-bit address arithmetic. This is not a fully bounds-checked array accessor.

Indexed lookup with optional per-entry computation is inferred intent. The static evidence establishes the reads, selection, and invocation behavior, but not the application-level meaning of the descriptor or tables.

## Interface

### Inputs

The function accepts three arguments:

| Argument | Width and interpretation | Use |
|---|---|---|
| Descriptor address | Address in the represented 32-bit addressing model | Locates the fields described below |
| Index | Signed 32-bit integer | Compared with the signed limit, used in address calculations, and forwarded on the indirect-call path |
| Auxiliary argument | Uninterpreted 32-bit value | Forwarded as the second argument on the indirect-call path |

The function does not directly inspect or dereference the auxiliary argument. A selected dependency may interpret it differently; that interpretation is unknown.

### Descriptor layout

The supplied representation establishes these field accesses:

| Byte offset | Width | Meaning established by use |
|---|---:|---|
| 0 | 32 bits | Entry-table address; its initial value controls whether lookup is enabled |
| 4 | 32 bits | Signed limit used for eligibility |
| 8 | 32 bits | Value-table address, accessed only on the direct-value path |

These accesses do not establish a complete descriptor type or allocation size. The entry-table address is read twice on an eligible path: once for the initial nonzero check and again for entry selection.

### Entry-table layout

Entries have a 24-byte stride.

| Offset within selected entry | Width | Meaning established by use |
|---|---:|---|
| 0 | 32 bits | Indirect call target, read only when the selection flag is set |
| 6 | 8 bits | Flag byte; bit 0 selects the result source |

The remaining entry bytes have no established meaning. The function does not read or copy an entire entry.

### Value-table layout

The parallel value table is addressed with a four-byte stride. A selected element is read as one 32-bit word and returned without an established signed interpretation.

### Output

On normal return, the result is a 32-bit value:

- Zero if the initial entry-table word is zero.
- Zero if the initial entry-table word is nonzero but the signed index is not strictly below the signed limit.
- The selected value-table word if eligibility passes and flag bit 0 is clear.
- The selected dependency’s result if eligibility passes, flag bit 0 is set, and the invocation returns normally.

### Preconditions for successful execution

Every reached memory access must satisfy the target environment’s validity and alignment requirements:

- The descriptor’s first word must be readable.
- The limit field must be readable if the first word is nonzero.
- An eligible index must produce a readable flag-byte address.
- The direct-value path requires a readable value-table address field and selected value word.
- The indirect-call path requires a readable target word and a callable target compatible with the represented invocation.

A null descriptor is not treated as an empty descriptor. Its first word is accessed before any disabling condition can be established.

No general requirement that both tables be valid is imposed by every path. For example, the value-table address field is not accessed on the indirect-call path.

## Behavior

### Initial guard and signed eligibility

The first direct read obtains the descriptor’s entry-table address. If this word is zero, the function returns zero without reading the limit, entry flag, value-table address, or call target.

If the first word is nonzero, the function reads the signed 32-bit limit. Entry processing occurs precisely when:

**The initial entry-table word is nonzero, and the signed index is strictly less than the signed limit.**

Equality is rejected. An index greater than the limit is also rejected. These rejection paths return zero without reading an entry or value-table element.

The represented comparison accounts for signed subtraction overflow and excludes equality. Its behavior is therefore a strict signed comparison, not merely a test of the sign of a wrapped subtraction.

There is no separate requirement that the index or limit be nonnegative:

- A zero limit rejects index zero but accepts negative indices.
- A negative limit can accept a more-negative index.
- A positive limit can accept negative indices.

### Entry selection and flag read

After eligibility passes, the function reads the descriptor’s entry-table address again. This second value, rather than the value used for the initial nonzero check, supplies the base for entry selection.

The selected entry address is the reread base plus a displacement of 24 bytes per index. The function then reads the flag byte six bytes into that entry.

There is no second nonzero check. If the second entry-table address differs from the first, selection uses the second value, including when that replacement is zero.

Only bit 0 of the flag byte matters. Other bits do not affect the selected path.

### Direct-value path

If flag bit 0 is clear, the function reads the descriptor’s value-table address at byte offset 8. It adds a displacement of four bytes per index, reads the selected 32-bit word, and returns that word.

On this path:

- The entry’s call-target word is not read.
- The auxiliary argument is not inspected or forwarded.
- No validity check is performed on the value-table address.
- No transformation of the selected result is established.

An invalid call-target word does not itself prevent successful direct retrieval because that word is not accessed.

### Indirect-call path

If flag bit 0 is set, the function reads the 32-bit target word at the beginning of the already selected entry. It invokes that target with two arguments, in order:

1. The signed 32-bit index.
2. The auxiliary 32-bit value.

If the invocation returns normally, its 32-bit result becomes this function’s result without an established transformation.

On this path:

- The descriptor’s value-table address is not read.
- There is no null-target check or other target validation.
- There is no fallback to direct retrieval.
- The flag and eligibility condition are not reevaluated after the invocation.
- No further descriptor or table reads are established after the invocation returns.

If the dependency does not return normally, no normal result from F-21116018347c is established.

### Integer widths and address arithmetic

The supplied representation uses 32-bit address-bearing words and 32-bit arithmetic. Entry displacement is 24 times the index; value displacement is four times the index. The flag address includes a further six-byte offset.

The represented arithmetic uses the resulting 32-bit bit patterns, including reduction of products and sums to 32 bits. It is not unbounded mathematical indexing. Large positive or negative indices can consequently produce wrapped displacements or addresses.

The index is interpreted as signed for eligibility. That signed comparison does not prevent address arithmetic from wrapping.

A computed address is not thereby known to be mapped, aligned, inside an allocation, or safe to access. An implementation using wider pointers would need to preserve the represented arithmetic explicitly to claim equivalent addressing behavior.

## Acceptance examples

These are conditional consequences of static evidence, not executed tests. Unless otherwise stated, all reached accesses and invoked targets are assumed valid.

### Initially disabled lookup

If the descriptor’s initial entry-table word is zero, the result is zero for every index and auxiliary argument.

The limit and value-table address fields need not be readable for this path because they are not accessed. In particular, a nominal limit of 5 and index of 2 do not enable lookup when the initial entry-table word is zero.

### Boundary rejection

If the initial entry-table word is nonzero, the signed limit is 5, and the index is 5, the result is zero. The entry flag and value-table element are not read.

Index 6 is likewise rejected under those conditions.

### Direct retrieval

If the **initial entry-table word is nonzero**, the signed limit is 5, and the index is 2, eligibility passes.

The function rereads the entry-table address and reads the flag 54 bytes from that reread base: two 24-byte strides plus six bytes.

If flag bit 0 is clear, it reads the descriptor’s value-table address and returns the 32-bit word eight bytes from that value-table base. The auxiliary argument does not affect the direct retrieval. The selected entry’s target word is not read.

### Indirect retrieval

If the **initial entry-table word is nonzero**, the signed limit is 5, and the index is 2, eligibility passes.

If the flag read from the reread entry-table base has bit 0 set, the target is read 48 bytes from that same base. The target receives index 2 and the auxiliary argument.

If it returns the 32-bit value 37, this function returns 37. The descriptor’s value-table address is not read.

### Other flag bits

For an otherwise eligible and valid selection, flag values 0 and 2 both select direct retrieval. Flag values 1 and 3 both select indirect invocation. These pairs differ in an ignored flag bit, not in bit 0.

### Negative index

With an initially nonzero entry-table word, a signed limit of 0, and index −1, eligibility passes.

Without address-boundary wraparound, the selected flag is 18 bytes before the reread entry-table base. On the direct-value path, the selected word is four bytes before the value-table base.

Successful execution requires these addresses to be valid. The function does not reject them merely because they precede the bases.

### Signed comparison extremes

With an initially nonzero entry-table word, limit 2,147,483,647, and index −2,147,483,648, eligibility passes despite overflow in a 32-bit subtraction used to express the comparison.

With the limit and index reversed, eligibility fails and the result is zero. These outcomes distinguish the established signed comparison from a wrapped-subtraction sign test.

### Entry-table address changes between reads

If the initial entry-table word is nonzero and eligibility passes, but the second read produces a different address, entry selection uses the second address.

A second value of zero does not cause graceful rejection. The function still calculates and accesses the selected flag address; successful execution remains conditional on that address being valid.
