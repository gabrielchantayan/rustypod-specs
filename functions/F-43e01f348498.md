# F-43e01f348498

## Purpose

F-43e01f348498 computes a masked, right-shifted value from a 32-bit word reached through an address-bearing input cell.

**Established static evidence:** The operation reads an address from the supplied cell, reads a word through that address, shifts that word right, and retains low-order bits using a separately calculated mask. Both shift counts are reduced to their low eight bits before use.

**Inferred intent:** The signed input appears to designate an inclusive upper bit position, and the unsigned input appears to designate a lower bit position. For a supported, ordered range, the result is the selected field, moved down to bit zero.

That interpretation does not establish a general-purpose bit-range API. There is no visible range validation, and several natural requests—including extracting all 32 bits—produce shift expressions whose portable behavior is not established by the supplied source.

## Behavior

### Derived counts

Two different counts are calculated.

The **source shift count** is the low eight bits of the lower-position input. Its numerical range is therefore 0 through 255. It is not reduced explicitly to the range 0 through 31.

The **mask shift count** is the low eight bits of the upper-position input minus the lower-position input plus one.

Under the 32-bit integer model, mixing the signed upper-position input with the unsigned lower-position input converts the arithmetic to unsigned 32-bit arithmetic. Subtraction and addition therefore wrap modulo \(2^{32}\). The subsequent eight-bit mask retains only the low eight bits of that wrapped result.

Equivalently, the mask shift count is the difference-plus-one reduced modulo 256. This equivalence describes the resulting count; it does not imply that the implementation validates either input as a bit position.

Consequences include:

- Negative upper-position inputs are not rejected.
- An upper position below the lower position is not rejected.
- Large lower-position inputs are not rejected.
- Inputs differing by multiples of 256 can produce the same counts.
- Reducing a count to eight bits does not make a 32-bit shift safe.

### Source-word transformation

The source word is interpreted as unsigned. Where its right shift is defined, the vacated high-order positions become zero.

For a mask shift count that produces a defined left shift, the mask is formed by shifting the integer value one left by that count and then subtracting unsigned one. The final result is the bitwise intersection of this mask and the right-shifted source word.

For ordinary, supported field requests:

- The source shift count identifies the lowest selected source bit.
- The mask shift count gives the number of retained result bits.
- Higher result bits are zero.
- The function does not sign-extend the extracted field.

A mask shift count of zero produces a zero mask. Subject to valid accesses and otherwise defined evaluation, the returned value is consequently zero. This is not a designated empty-range error.

### Shift boundaries

The source uses an unsuffixed integer value of one for mask construction. Under a conventional 32-bit signed-integer interpretation:

- Mask shift counts from 0 through 30 have representable left-shift results.
- A mask shift count of 31 attempts to produce a value not representable as a positive signed 32-bit integer. A portable numerical result is not established by that expression.
- Mask shift counts from 32 through 255 exceed or equal the operand width and likewise do not establish a portable result.
- Source shift counts from 32 through 255 do not establish a portable right-shift result for a 32-bit source word.

The unsigned subtraction after mask construction does not retroactively make an invalid signed left shift defined.

Accordingly, the fully portable numerical subset described here requires a mask shift count from 0 through 30 and a source shift count from 0 through 31, together with valid memory accesses.

A target may implement additional count behavior, but no instruction-level evidence establishes such behavior here. In particular, this contract does not promise that hardware reduces shift counts modulo 32.
