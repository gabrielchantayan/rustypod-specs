# F-07d627a6a5a3

## Purpose

F-07d627a6a5a3 replaces a resource-like field in a caller-supplied object, conditionally invokes operations involving a related object, applies a computed update through the caller’s operation table, and conditionally constructs and forwards a local descriptor.

“Resource,” “related object,” and “descriptor” describe their uses here. They do not establish concrete types, ownership, destruction semantics, or application-level purpose.

The function returns a 64-bit value assembled from the first two 32-bit words of the descriptor. This is not an established success indicator or a direct return of the acquired resource.

This contract describes static evidence. Dependency behavior remains unspecified except for the calls, arguments, and result uses visible here.

## Interface

### Input object

The function accepts one pointer to a mutable object. The supplied representation uses 32-bit integer words and 32-bit pointer-bearing words.

Offsets are in bytes from the input object’s beginning:

| Offset | Represented access | Role |
|---|---|---|
| 0x000 | 32-bit pointer-bearing word | Pointer to the input object’s dynamic-operation table. |
| 0x034 | 32-bit word | Optional value saved before descriptor construction. |
| 0x038 | 32-bit word | Selects the acquisition dependency; also an argument on the nonzero branch. |
| 0x044 | 32-bit word | Argument to either acquisition dependency. |
| 0x080 | Address within the object | Beginning of an embedded region passed to descriptor construction. |
| 0x0A0 | 32-bit field converted to a character | Its low eight bits participate in forwarding eligibility. |
| 0x0E8 | 32-bit pointer-bearing word | Optional related-object pointer. |
| 0x1E0 | 32-bit word | Resource-like field replaced by this function. |

The condition at 0x0A0 tests whether the low eight bits are zero. Upper bits do not affect this predicate. The representation does not establish that the original memory access is only one byte wide.

The input pointer is not checked for null. No bounds, alignment, operation-table, or target-pointer validation is visible. Valid execution requires the object and every reached dependent object, table, and memory location to support their accesses. Dependencies must leave subsequently accessed objects valid; this function does not enforce that requirement.

The embedded region’s size and type are unknown. Passing its address does not establish how much memory a dependency may access.

### Local descriptor and result

The represented descriptor begins with three consecutive 32-bit words:

| Descriptor offset | Initial value |
|---|---|
| 0x00 | Input object pointer. |
| 0x04 | Address of the input object’s embedded region at 0x080. |
| 0x08 | 1. |

These words are initialized after the input object’s update operation returns and before the forwarding-eligibility dependency is called.

At normal return:

- Bits 0–31 contain the descriptor’s final word at offset 0x00.
- Bits 32–63 contain its final word at offset 0x04.
- The word at offset 0x08 is not directly included.

This defines logical high-word and low-word placement, not memory byte order.

When the descriptor is not exposed to any dependency, its first two words retain their initialized pointer values under valid execution. On the conditional path, descriptor-receiving dependencies may change the returned words. Descriptor size beyond the represented three words is not established.

## Behavior

### 1. Invoke the existing resource’s operation, then clear the field

The function first tests the resource field at 0x1E0.

If nonzero, that value is used as an object pointer. The function reads that object’s operation-table pointer and invokes the operation at table byte offset 0x004. After the operation returns, the input object’s resource field is cleared to zero.

No explicit arguments are shown for this operation. Its complete calling convention, including any implicit receiver, is unresolved.

The clear happens after the call. The called operation may therefore observe the existing field before the clear. If it changes that field and returns normally, the clear overwrites its change.

If the tested resource field is zero, both the operation and the clear are skipped.

This sequence suggests retirement of an existing resource, but does not establish deallocation, destruction, reference-count changes, or ownership transfer.

### 2. Acquire and install a replacement

The acquisition branch is selected using offset 0x038 after the preceding operation and clear, if any:

- When the selector is zero, F-4c155d03660c receives the value at 0x044.
- When the selector is nonzero, F-a9ad53981123 receives the values at 0x038 and 0x044, in that argument order.

Changes made by the preceding resource operation can affect these reads. The relative evaluation order of argument reads within a call is not independently established.

The 32-bit acquisition result is assigned to offset 0x1E0 twice consecutively, without an intervening call. Both assignments have the same final-state effect. The representation does not establish whether two distinct machine stores occur, nor supply volatile or synchronization semantics.

Zero is accepted as an acquisition result. There is no visible retry, rollback, or immediate error return.

The acquisition dependencies are not assumed to preserve other object fields or global state. In particular, either may change offset 0x0E8 before the related-object pointer is read.

### 3. Read the related pointer and conditionally invoke three operations

After installing the acquisition result, the function reads and saves offset 0x0E8.

If this saved pointer is zero, the entire related-object branch is skipped. An initially zero value at 0x0E8 is insufficient to establish that outcome: the acquisition dependency may have changed it.

If the saved pointer is nonzero, operations run in this order:

1. The input object’s operation at table offset 0x190 receives the input object, 0, and 1.
2. The input object’s operation at table offset 0x198 receives the input object.
3. The saved related object’s operation at table offset 0x0A4 receives that related object and the current resource field at input offset 0x1E0.

The input operation table is consulted separately for the first two calls. The first call is not assumed to preserve that table or any object field.

The related pointer is a snapshot. Changes to input offset 0x0E8 during these calls do not redirect the third call. Its operation table is accessed through the saved related object when preparing that call.

The resource argument to the third call is read after the first two operations. It need not equal the acquisition result. The related-object operation itself may also change the resource field before the subsequent update computation.

### 4. Compute an update and invoke the input object’s update operation

After the related-object branch, the function tests the current resource field:

- If zero, the update value is zero; F-004c5654fd0a is not called.
- If nonzero, F-004c5654fd0a receives the resource field and a second 32-bit argument. Its result becomes the update value.

The second argument has two distinct represented sources:

- If the related-object branch was skipped, it is the saved acquisition result.
- If that branch ran, it comes from an additional register output associated with the related-object operation.

The latter source has no established application-level meaning. It must not be described as an ordinary return value or assumed to equal the acquisition result.

The input object’s operation at table offset 0x16C is then invoked with the input object and the update value. On the nonzero-resource path, this operation is selected after F-004c5654fd0a returns. Consequently, changes that dependency makes to the input operation table can affect selection.

A zero acquisition result does not by itself guarantee a zero update: a subsequently executed related-object operation can make the resource field nonzero.

### 5. Initialize the descriptor and test forwarding eligibility

After the update operation returns, the descriptor is initialized as specified in the interface.

The function calls F-3fac671648b8 without explicit arguments. Conditional descriptor processing occurs only when all three predicates hold, in this order:

1. F-3fac671648b8 returns a nonzero 32-bit value.
2. The low eight bits of the input field at 0x0A0 are zero.
3. A byte read through a separate global pointer is nonzero.

Evaluation short-circuits:

- A zero first result prevents both later predicate reads.
- A nonzero low byte at 0x0A0 prevents the global-byte read.

The object-field predicate is evaluated after F-3fac671648b8 returns. That dependency is not assumed to preserve the field or the global pointer.

The global pointer’s identity, initialization, and lifetime are unknown. When reached, the pointer and its byte-sized pointee must be readable.

If any predicate fails, descriptor construction, adjustment, target lookup, and forwarding are skipped.

### 6. Construct and optionally adjust the descriptor

When eligibility succeeds, the current 32-bit value at input offset 0x034 is saved before any descriptor-construction call.

F-e57b05520b65 then receives:

1. The descriptor address.
2. The embedded-region address at input offset 0x080.
3. The same embedded-region address again.

The last two arguments are equal. Their equality does not establish empty-range, in-place, or ownership semantics.

If the saved value from offset 0x034 is nonzero, F-ee8733a08210 receives the descriptor address and that saved value plus 0x0D0.

The adjustment decision and argument use the saved value, not a reread after construction. Changes made to offset 0x034 by F-e57b05520b65 therefore do not affect either.

The addition is represented in a 32-bit integer/address model. No wider arithmetic, overflow check, saturation, or explicit overflow-error path is shown. Exact behavior outside the valid arithmetic and address range is unresolved; wraparound must not be promised from this representation alone.

### 7. Obtain a target, forward twice, and return

F-ffe0d92c57b7 receives the input object.

If its result is zero, both forwarding calls are skipped. Construction and optional adjustment have already occurred, and their descriptor changes may still affect the return value.

If the result is nonzero:

1. F-c9b5d17d8d1e receives that result and the descriptor address.
2. F-4d037ecf0f82 receives the same saved result and the same descriptor address.

The target is not reacquired between calls. No independent status check gates the second call after the first returns normally. Descriptor changes made by the first forwarding call are available to the second.

The final first two descriptor words are then packed into the 64-bit result.

## Side effects

Directly established effects are:

- A conditional clear of input offset 0x1E0 after the existing-resource operation returns.
- Installation of the acquisition result at that offset.
- Initialization of the local descriptor.
- The ordered direct and indirect calls described above.

Dependency side effects are not bounded by the visible body. No dependency is assumed to preserve globals, object fields, operation tables, or memory ownership.

The descriptor has local storage duration. Its address is passed to dependencies only on the eligible path. Retaining that address for use after return is not established as safe.

No explicit descriptor cleanup is visible. This neither establishes that cleanup is unnecessary nor proves that any dependency performs cleanup or accepts ownership.

There is no visible transactional guarantee. Earlier effects are not undone if a later dependency fails or does not return normally. No exception handling, locking, atomicity, memory ordering, or reentrancy protection is established.

## Acceptance examples

These are conditional static acceptance criteria, not executed tests. Each assumes valid memory and normally returning dependencies.

### Zero acquisition with no related object at the actual read

Suppose:

- The initial resource field is zero.
- The acquisition selector is zero when tested.
- F-4c155d03660c returns zero.
- Offset 0x0E8 is zero when read after acquisition and installation.

Then the existing-resource operation is skipped, the acquisition result is installed as zero, and the related-object branch is skipped. With no intervening dependency call between that skipped branch and the resource test, F-004c5654fd0a is skipped and the update operation receives zero.

The related-pointer condition is expressly post-acquisition. Its initial value alone cannot justify this result.

### Acquisition installs a related object despite returning zero

Suppose the resource and related-pointer fields are initially zero. F-4c155d03660c installs a nonzero related pointer and returns zero.

The zero result is installed in the resource field, but the subsequent related-pointer read sees the newly installed pointer. All three related-branch operations execute. If those operations leave the resource field nonzero, F-004c5654fd0a is called. The update argument then comes from that dependency’s result and is not required to be zero.

### Related-pointer replacement does not redirect the saved target

Suppose the post-acquisition related-pointer read is nonzero, and the first input-object operation changes offset 0x0E8.

The related-object operation still targets the saved object. That object must remain valid. Its resource argument uses the current resource field after the first two operations, not necessarily the acquisition result.

### Eligibility short-circuits

If F-3fac671648b8 returns zero, neither the object-field predicate nor the global-byte predicate is evaluated.

If it returns nonzero and the low byte at 0x0A0 is nonzero, the global-byte predicate is skipped.

A field value with zero low byte and nonzero upper bytes passes the object-field predicate; eligibility still requires the other predicates.

### Construction changes the adjustment field

If the saved value from 0x034 is nonzero and construction clears that field, adjustment still occurs using the saved value plus 0x0D0.

Conversely, a saved zero suppresses adjustment even if construction later makes the field nonzero.

### No forwarding target after descriptor mutation

Suppose descriptor construction changes its first word and F-ffe0d92c57b7 returns zero.

Both forwarding calls are skipped, but the changed first word is still used as the low 32 bits of the result unless another reached operation changes it.

### Forwarding mutations propagate

With a nonzero target, if F-c9b5d17d8d1e changes the descriptor’s second word, F-4d037ecf0f82 receives the same descriptor containing that change. Unless subsequently changed, that word becomes the high 32 bits of the return value.
