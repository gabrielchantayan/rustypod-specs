# F-80904409371a

## Behavior

### Admission

The function first tests whether either of option bits 0 and 1 is set.

If either bit is set, it returns 1 immediately. No dependency is called.

Otherwise, initialization begins.

### Initialization

1. First input.
2. Third input.
3. Signed second input.
4. Address of the primary state.
5. Address of the bound.
6. Address of the first metadata field.
7. Address of the second metadata field.

A nonzero initialization status is returned immediately. This function then makes no resource request or cleanup call.

A zero status permits execution to continue without additional validation of initialized storage.

### First resource request

After successful initialization, F-d33f6d597e5d receives the fixed 32-bit request value 512.

A zero result causes immediate return of 1. That zero result is not submitted to F-5e3309c9d083.

Any nonzero result is accepted as the first resource handle. The local test does not require positivity; a negative nonzero 32-bit result is not rejected.

The first bound comparison occurs **after** this request returns. It uses the bound present at that comparison, which need not equal the value present when initialization returned. For example, the resource dependency could modify the bound through an address retained by initialization.

### Bound comparison and scanning

Before each scan attempt, the function reads the current signed bound and compares the signed second input against it.

If the second input is less than the bound:

1. The first resource handle is passed to F-5e3309c9d083.
2. The function returns 7.

Equality passes. This comparison is not an unsigned range check.

When the comparison passes, F-79487c4f97b1 receives:

1. Third input.
2. Signed second input.
3. Current first metadata value.
4. Address of the primary state.
5. Address of the bound.
6. Address of the size-like field.
7. Address of the secondary state.
8. First resource handle.
9. Address of the completion indicator.

The metadata value is read for that invocation; it is not guaranteed to equal its initialization-time value. The function does not reset exposed storage between scans.

After the scan returns, its status is checked before the completion indicator:

- A nonzero status causes a cleanup call for the first handle, followed by return of the scan status. No second resource is requested.
- A zero status causes the completion indicator to be read.
- An indicator exactly equal to 1 enters final processing.
- Every other indicator value returns control to the bound comparison.

Thus a scan error takes precedence over a completion indication. Indicator values such as 0, 2, and −1 do not count as completion.

There is no local iteration limit, progress requirement, increment, or forced bound update. Repeated zero-status scans can continue indefinitely if they never produce indicator 1 and each subsequent bound comparison passes.

Call this the **request-time size value**. The function performs no local range, sign, or zero check on it.

The second resource result is accepted without a zero/nonzero test. A zero result does not cause the first-request failure path.

After this resource request returns, F-00066d1b3db8 receives:

1. Signed second input.
2. Second metadata value read after the request.
3. Size-like value read after the request.
4. First metadata value read after the request.
5. Address of the primary state.
6. Address of the bound.
7. Second resource result, including zero.
8. Complete fourth input, unchanged.

The **final-processing size value** is a separate read from the request-time size value. They need not match. Scanning has exposed the size-like field’s address, so the intervening resource request may modify it through retained-address or shared-state behavior.

Likewise, neither metadata argument is guaranteed to be an initialization-time snapshot. Initialization exposed both metadata addresses, and the second resource request occurs before the final-processing arguments are obtained. The primary state and bound are passed by address rather than copied as earlier snapshots.

2. F-5e3309c9d083 receives the first resource handle.

## Acceptance examples

These are conditional static acceptance criteria, not executed tests. Dependencies are assumed to return normally unless otherwise stated.

1. **Rejected option bits.** With option value 1, 2, or 3, return 1 without calling any dependency.

2. **Higher option bits.** With option value 4, admission succeeds. If final processing is reached, its eighth argument is 4.

3. **Initialization failure.** If initialization returns 23, return 23 without requesting resources or making cleanup calls.

4. **First request failure.** If initialization returns zero and the request for 512 returns zero, return 1 without scanning or cleanup.

5. **Signed bound rejection at the actual comparison.** If the second input is −1, the first handle is nonzero, and the bound equals 0 **when the first comparison occurs**, submit the first handle for cleanup and return 7. A bound of 0 only at initialization return is insufficient to establish this outcome.

6. **Intervening bound mutation.** If initialization leaves the bound at 0, the second input is −1, and the first resource request changes the bound to −2 before returning a nonzero handle, the first comparison passes and scanning is invoked.

7. **Equality permits scanning.** If the second input and bound both equal 12 at a loop-entry comparison, scanning is invoked rather than selecting status 7.

8. **Scan error overrides completion.** If scanning returns 9 while the completion indicator equals 1, submit the first handle for cleanup and return 9. Do not request the second resource.

9. **Exact completion requirement.** If scanning returns zero and the indicator is 2 when examined, perform another bound comparison rather than entering final processing.

10. **Updated bound on continuation.** If a zero-status, noncompleting scan leaves the bound at 21, the second input is 20, and the bound remains 21 at the next comparison, submit the first handle for cleanup and return 7.

11. **No completing-scan bound rejection.** If scanning returns zero with indicator 1, proceed to the second request even if the bound then exceeds the second input.

12. **Distinct size reads and refreshed metadata.** Suppose the size-like field is 64 when the second request argument is obtained. That request receives 64. If the request changes the size-like field to 96 and the metadata fields to new values that remain present during final argument preparation, final processing receives 96 and those new metadata values—not the earlier size or metadata.

13. **Zero second result.** If the second request returns zero, final processing receives zero as its seventh argument. After normal return, cleanup receives zero first and the first handle second.

14. **Final status survives cleanup.** If final processing returns 31 and both cleanup calls return normally, return 31 after submitting the second result before the first handle.
