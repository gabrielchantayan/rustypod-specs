# F-6e23bd067b9e

## Purpose

F-6e23bd067b9e changes a descriptor’s accounted length, updates related aggregate accounting, and conditionally obtains and records additional extents. It returns a 32-bit status and reports the difference between the descriptor length observed during finalization and the length saved at entry.

**Established behavior:** sizing interactions, format-dependent guards, direct accounting, preliminary adjustment, allocation fallback, extent coalescing or insertion, partial-progress retention, and final difference reporting.

**Inferred intent:** storage-growth management. This interpretation does not establish conventional error meanings, persistence, transactionality, or resource ownership.

## Interface

### Arguments and result

| Input | Representation | Role |
|---|---|---|
| Context | 32-bit address | Signature, allocation unit, optional sizing limit |
| Descriptor | 32-bit address | Related-object address, flags, accounted length, secondary sizing value |
| Request low word | Unsigned 32 bits | Low half of request |
| Request high word | 32 bits | High half; initial guard interprets the pair as signed 64 bits |
| Options | 32-bit mask | Directly examines `0x01`, `0x02`, and `0x04` |
| Change output | Address of two writable 32-bit words | Final difference, low word first |

The return value is 32 bits. Explicitly selected statuses are `0`, `17`, and `-34`; dependency results and an externally configured status can also be returned.

Lookup status `16` selects allocation processing, not a retained return status. Allocation processing replaces it before ordinary return. A returned `16` can nevertheless originate from another dependency or the configured status.

Split 64-bit quantities place the low word first. Unless a signed comparison is identified below, comparisons are unsigned. Fixed-width arithmetic wraps modulo \(2^{32}\) or \(2^{64}\). Products of two unsigned 32-bit quantities retain all 64 product bits.

## Behavior

### Entry and option capture

The function clears the change-output low word, then its high word. It reads and retains the allocation unit, captures options `0x04` and `0x02`, then reads the descriptor’s entry length low and high words.

A signature observation of `0x482b` selects capacity eight and bypasses the initial special-format guards. Otherwise, capacity three is selected and a separate signature observation determines whether those guards apply. These observations need not agree.

| Option | Direct effect |
|---|---|
| `0x01` | Enables the sizing limit; rejects rather than adjusts a later special-format boundary |
| `0x02` | Disables fallback and stops after one successfully recorded extent |
| `0x04` | Supplies zero as the allocator’s preferred start |
| Other bits | No direct visible effect |

### Initial special-format guards

If the second signature observation is `0x4244`, the configured status is read before either guard, including when both permit continuation.

The first guard rejects a signed 64-bit request greater than or equal to `-2,147,483,648`. Zero and every nonnegative request therefore reject. This is not a conventional positive-size upper bound.

For a request that passes, the second guard combines separately observed descriptor words:

- Descriptor high word plus request high word plus carry from adding request low to one descriptor low-word observation produces a wrapping 32-bit high word.
- Only if that high word is `0xffffffff` does another descriptor low-word read occur.
- That additional low-word observation plus request low, modulo \(2^{32}\), rejects when greater than `0x7fffffff`.

The high-word read and carry-producing low-word read have no established relative order. The threshold read is distinct and conditional.

With stable descriptor words, the second guard rejects a sum in the signed interval `[-2,147,483,648, -1]`. Under mutation, its carry and low result can derive from different observations.

Either rejection retains the previously read configured status and proceeds directly to finalization.

### Sizing and later boundary

F-3594f32e3fe8 receives request low, request high, and the captured allocation unit. Its unsigned 32-bit result multiplied by that unit produces the 64-bit primary amount. The secondary amount initially equals the primary amount.

If the captured unit is below the descriptor’s secondary sizing value, a second sizing call receives only the primary product’s low and high words as explicit arguments. Its result is multiplied by a post-call reread of the secondary sizing value to replace the secondary amount. The effective second-call interface remains unresolved.

A later independent signature read tests for `0x4244`. On a match, primary amount plus then-current descriptor length is checked for the same forbidden signed interval. This check uses the portions of one computed sum, without a separate low-word threshold reread. The underlying 64-bit length access is not established as atomic.

A matching boundary reads configured status before examining option `0x01`:

- With `0x01`, processing stops with that status.
- Without `0x01`, the sizing result is decremented and one captured allocation unit is subtracted from the primary amount. The secondary amount is unchanged.

The decrement wraps zero to `0xffffffff`; its auxiliary high component becomes `-1` for that wrap and zero otherwise.

With `0x01`, a sizing result above the context limit selects `-34`. Continuing paths with this option cannot have taken the decrement. Without `0x01`, the limit is not read.

### Lookup and direct accounting

Primary amount plus a current descriptor-length observation becomes the saved proposed length. F-0c688a5353e6 receives proposed length minus one, context, descriptor, and writable record-prefix, extent-array, selected-index, cursor, and allocation-position storage.

Subtraction wraps: proposed length zero supplies position `0xffffffffffffffff`. There is no zero-size bypass.

| Lookup status | Result |
|---|---|
| `0` | Direct accounting |
| `16` | Preliminary adjustment, then allocation |
| Other | Finalization with that status |

Direct accounting proceeds in this order:

1. Store the saved proposed length in the descriptor.
2. Add the primary amount to an observed related aggregate and store the result.
3. Set descriptor flag `0x80`, preserving the other bits then observed.

The saved proposed length is used even if lookup changed descriptor length.

The aggregate assignment separately reads Descriptor+`0x08` to obtain the address used for the aggregate **load** and the address used for the aggregate **store**. Their relative evaluation order is not established. If these pointer observations differ, the aggregate read from one object contributes to the value stored in another. The assignment does not imply one captured related-object address.

### Preliminary adjustment

After lookup status `16`, the returned unsigned allocation position is multiplied by the captured unit.

The difference from descriptor length uses separate observations: its low word subtracts one descriptor low-word observation; its high word subtracts a descriptor high-word observation and borrow determined using another low-word read. With stable fields, this is product minus current length. Under mutation, it need not represent one coherent subtraction.

If the assembled difference is nonzero, the function:

1. Stores the product as descriptor length.
2. Captures Descriptor+`0x08` once.
3. Updates that captured object’s aggregate, storing its low word before its high word.
4. Sets flag `0x80`.
5. Subtracts the difference from the primary amount.

Unlike direct and post-record accounting, both aggregate-word updates use the **same captured related-object address**. The old aggregate low word supplies the carry for the high-word update.

The secondary amount is unchanged. Preliminary adjustment can decrease length and is not rolled back after later failure.

Allocation performs at least one attempt even if the primary remainder is zero. Nonzero remainder controls repetition, not initial entry.

### Allocation and fallback

Allocation starts in mode `1`; fallback mode is `0`.

Before each F-b775eff8d313 call, the selected extent’s start and count are read and cached. Their wrapping 32-bit sum is the preferred start unless option `0x04` substitutes zero.

The allocator also receives context, primary remainder, secondary amount, mode, and writable returned-start and returned-count storage.

| Allocator status | Condition | Consequence |
|---|---|---|
| `-34` | `0x02` set | Stop with `-34` |
| `-34` | Primary mode, `0x02` clear | Skip recording, select zero status, switch to fallback |
| `-34` | Fallback mode, returned count zero | Stop with `-34` |
| `-34` | Fallback mode, returned count nonzero | Process returned extent |
| Other nonzero | Any mode | Stop with allocator status |
| `0` | Any mode | Process returned extent, including zero count |

After switching modes, another attempt occurs only if primary remainder is nonzero. A primary `-34` with zero remainder and `0x02` clear can therefore finish with zero status without a fallback call.

For a processed extent, returned start is compared with the cached extent end. Option `0x04` does not change that comparison. Subsequent record operations reread selected-index and extent fields; a cached end can select coalescing while changed exposed storage selects the pair or count modified.

### Recording extents

If returned start equals the cached extent end, returned count is added modulo \(2^{32}\) to the reread count at the current selected index.

Otherwise, the current selected count is reread. A nonzero count advances the selected index. If the resulting index differs from capacity, the returned start and count are written there. The capacity comparison tests equality only, not bounds.

Both existing-record cases call F-855dbfd33a25 with:

- Context and descriptor.
- Record-prefix storage and extent-array storage.
- The current 32-bit cursor **value**, not writable cursor storage.

A nonzero update status stops before accounting the returned extent. Temporary record mutations are not undone.

At capacity, related-object identifier `3` selects status `17`. No explicit release of the returned extent occurs.

For another identifier, a new record is constructed. The discriminator is `0xff` when current descriptor flag `0x02` is set, otherwise zero. Identifier and allocation position use current observations. Pair zero receives the returned extent; pairs one through seven are cleared, even for capacity three. The selected index becomes zero.

F-19b2a8daad37 receives context, record-prefix storage, extent-array storage, and **writable cursor storage**. It receives no explicit descriptor argument.

Insertion status `17` invokes F-78d86e98287a with context and the returned start and count, ignores its result, and selects `-34`. Other nonzero insertion statuses stop without this explicit compensating call.

Successful insertion records a requirement for the final F-22d5d80d8e4d call. Failed recording or insertion does not explicitly account that allocation and does not undo earlier progress.

### Post-record accounting and continuation

After a successful update or insertion, returned count is added to the 32-bit allocation position. Returned count multiplied by the captured unit produces the full 64-bit allocated byte count.

An overflow-aware signed 64-bit comparison determines whether primary remainder is less than allocated bytes:

- If less, primary remainder becomes zero; secondary amount is unchanged.
- Otherwise, allocated bytes are subtracted from both amounts modulo \(2^{64}\).

The full allocated byte count is then added to current descriptor length, followed by related aggregate accounting, followed by setting flag `0x80`. Accounting is not capped at the requested remainder.

As in direct accounting, the aggregate assignment independently reads Descriptor+`0x08` for its load address and its store address. Their relative evaluation order is unspecified by the supplied representation. Distinct observations permit a value derived from one object’s aggregate to be stored into another object’s aggregate. This differs from preliminary adjustment’s single captured pointer.

Post-record accounting uses values available after the record dependency returns. Previously exposed writable storage is not assumed preserved.

With `0x02`, processing stops after this accepted extent: nonzero remainder selects `-34`; zero remainder retains the successful record-operation status. Otherwise, repetition continues only while primary remainder is nonzero. Successful zero-count allocations need not make progress.

### Finalization

Every ordinary return reads current descriptor length and subtracts the entry snapshot modulo \(2^{64}\). Both current length words are read before either output store. Difference low is written before difference high.

If any insertion succeeded, F-22d5d80d8e4d receives context after difference reporting. Its result does not replace the selected status.

The output describes length change before that final call. It can differ from the request, be nonzero on error, and cease to match shared state if the final dependency changes that state.

## Side effects

Direct writes affect output words, descriptor length, related aggregates, descriptor flags, and temporary record storage exposed to dependencies. No atomicity guarantee is established for 64-bit accesses.

Aggregate targeting has two distinct contracts:

- **Direct and post-record accounting:** separate related-pointer observations for aggregate load and store; observation order unresolved.
- **Preliminary adjustment:** one captured pointer, with aggregate low stored before high.

Configured-status reads occur on initial special-format entry and on a matching later boundary, including paths that continue.

The operation is nontransactional. Preliminary adjustments, earlier accounting, record mutations, and successful insertions can survive later errors.

No explicit heap-memory acquisition or release is visible. Allocator and compensating-call roles do not establish general ownership or release guarantees. Dependency retention of temporary-storage references is unresolved; safe retention is not promised.

## Acceptance examples

These are conditional static expectations, not executed tests. Assume accessible, nonoverlapping storage and stable observations except where variation is specified.

1. **Initial rejection:** Initial special-format signature `0x4244` and request zero read configured status and reject before sizing. Unchanged length produces zero difference.

2. **Second guard:** Request `-2,147,483,649` with length zero passes both initial guards. Length one instead produces the forbidden lower boundary and rejects.

3. **Distinct guard reads:** Request high `0xffffffff`, low `0x7fffffff`, and descriptor high zero pass the first guard. Carry-producing descriptor low zero followed by threshold low one rejects. Reversing those observations permits continuation. If computed high is not `0xffffffff`, the threshold low read does not occur.

4. **Later adjustment:** A matching later boundary reads configured status even with `0x01` clear, then decrements sizing result and reduces only the primary amount. With `0x01` set, it rejects instead.

5. **Direct accounting:** Non-special signature, unit `4096`, sizing result `3`, no secondary replacement, and lookup success increase stable descriptor length and aggregate by `12,288`, set `0x80`, and report `12,288`.

6. **Cross-object direct store:** Under example 5, suppose the aggregate-load pointer observation identifies an object with aggregate `100`, while the aggregate-store observation identifies another with aggregate `900`. The assignment stores `12,388` in the latter object. It does not add to `900`. This example does not prescribe which pointer observation occurs first.

7. **Cross-object post-record store:** A successfully recorded one-unit extent with unit `4096`, aggregate-load object value `40`, and a distinct aggregate-store object writes `4,136` to the store object. Preliminary adjustment does not have this split-pointer behavior.

8. **Cursor distinction:** If insertion writes a new cursor value and a later existing-record update occurs, that update receives the then-current cursor value by value. Its explicit interface does not expose cursor storage for replacement.

9. **Lookup `16`:** Lookup `16`, zero preliminary adjustment, successful sufficient allocation, and successful recording complete with zero, not retained lookup status `16`. Allocator `16` instead stops and returns that dependency status.

10. **Cached coalescing:** Initial pair start `100`, count `5`; returned start `105`, count `2`; exposed count changed to `9`. With unchanged index, cached end selects coalescing and the modified count becomes `11`.

11. **Zero remainder:** Unit `4096`, sizing result zero, length `8192`, lookup `16`, and allocation position `2` produce zero preliminary adjustment but still call allocation. A successfully recorded unit raises length to `12,288` and reports `4096`.

12. **Fallback and errors:** Primary allocator `-34` with `0x02` clear selects zero and fallback; only nonzero remainder triggers another attempt. With `0x02`, a successfully recorded insufficient extent is accounted before returning `-34`. Insertion `17` instead invokes compensation and selects `-34` without accounting that extent.
