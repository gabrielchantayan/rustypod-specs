# F-f6d6f6d14101

## Purpose

F-f6d6f6d14101 either writes a zero-valued 16-bit destination element, returns without accessing pointed-to storage, or invokes an unresolved indirect dependency obtained from a global dispatch slot.

Selection depends on source-pointer presence, a mode argument, and, when the source is present, its first unsigned 16-bit element:

- In zero mode, only the element’s low-order 8 bits affect dispatch.
- In any nonzero mode, the complete 16-bit element participates in the decision, and dispatch is always selected.
- A null source bypasses source evaluation and dispatch selection entirely.

The global dispatch slot is read only on the indirect-dispatch path, after the source-derived decision and before invocation. Neither an immediate return nor a direct zero write evaluates that slot.

The evidence does not establish copying, conversion, string processing, or any other operation performed by the indirect dependency. In particular, it does not establish that source contents reach the destination.

## Behavior

### Null-source handling

The source pointer is tested first.

If it is null, the destination pointer is tested next:

- If the destination is also null, the function returns immediately.
- Otherwise, the function writes one 16-bit zero at the destination and returns.

The mode does not affect these outcomes. Neither path reads source storage or evaluates the global dispatch slot.

The both-null case is therefore a visible no-operation with respect to pointed-to storage and dispatch state. This does not establish that a null destination is acceptable when the source is present.

### Present-source evaluation

If the source is nonnull, the first source element is evaluated before any explicit destination write or dispatch-slot read.

In zero mode, the selected numerical value is the low-order 8 bits of that element. This is narrowing of the represented source value, not an established instruction to read the first byte at the source address. The correspondence between numerical low-order bits and byte-address order depends on endianness.

In nonzero mode, the selected value is the complete unsigned 16-bit element.

The destination is not checked for nullness before this decision.

### Decision arithmetic

The function increases the selected value by one using unsigned 32-bit arithmetic. In nonzero mode, it also doubles that incremented value. Dispatch is selected exactly when the resulting value exceeds one.

| Mode | Selected value | Resulting decision value | Outcome |
|---|---:|---:|---|
| Zero | 0 | 1 | Direct zero write |
| Zero | 1–255 | 2–256 | Indirect dispatch |
| Nonzero | 0–65,535 | 2–131,072 | Indirect dispatch |

No permitted source value causes overflow in the established 32-bit arithmetic. In particular, the maximum 16-bit source value in nonzero mode produces 131,072. Neither the increment nor the doubling wraps at 16 bits.

All nonzero mode values select the same explicit branch behavior, including negative mode values in the represented signed interface.

### Direct zero-write behavior

A direct write occurs in either of these cases:

- The source is null and the destination is nonnull.
- The source is present, the mode is zero, and the source element’s low-order 8 bits are zero.

The function writes exactly one represented 16-bit zero value and then returns. It does not explicitly clear a larger region or copy source data.

A nonzero source element can select this path. For example, an element whose numerical value is 0x1200 has a zero low-order byte.

On the present-source direct-write path, no destination-null check intervenes. A null destination therefore leads to an attempted write rather than the harmless return provided when both pointers are null. The execution environment’s response is not established.

The global dispatch slot is not evaluated on either direct-write path.

### Indirect dispatch and global target selection

Dispatch occurs whenever the source is present and either:

- The mode is zero and the selected low-order byte is nonzero; or
- The mode is nonzero, regardless of the source value.

After the source-derived decision selects dispatch, the function reads the indirect callable from the global dispatch slot. It then invokes the obtained target with these visible arguments:

1. The original destination pointer.
2. The original source pointer.

Neither pointer is explicitly advanced or replaced. The source is necessarily nonnull; the destination may be null.

The target-selection mechanism is therefore partially established: the callable is obtained by reading a global slot on the dispatch path. The evidence does not establish how that slot was initialized, who may modify it, where its contents originate, or whether any synchronization protects it.

The mode and calculated decision value are not shown as explicit invocation arguments. The arithmetic establishes branch selection, not a dependency-visible size or count.

There is no explicit destination write before invocation. If the dependency returns normally as represented, this function then returns without another explicit destination write. The recovered indirect transfer’s complete control-flow semantics remain uncertain; unconditional normal return is not promised.

### Access order and aliasing

The established logical ordering is:

| Path | Ordered visible operations |
|---|---|
| Both pointers null | Test source pointer; test destination pointer; return |
| Null source, nonnull destination | Test source pointer; test destination pointer; write destination zero; return |
| Present source, direct write | Test source pointer; evaluate first source element and derive decision; write destination zero; return |
| Present source, dispatch | Test source pointer; evaluate first source element and derive decision; read global dispatch slot; invoke obtained target; conditionally return |

No non-aliasing requirement is established.

If source and destination identify the same valid 16-bit element and the direct-write path is selected, the decision uses the original element before it is replaced by zero.

On dispatch paths, the source-derived decision precedes the global-slot read, and both precede invocation. No explicit destination mutation occurs before the dependency receives the pointers. Further aliasing consequences depend on the dependency.

These are logical access-order claims, not guarantees about physical transactions, atomicity, or compiler-selected load instructions. The evidence does not resolve behavior under concurrent mutation of source storage or the dispatch slot.

## Side effects

The both-null path performs none of those accesses. Direct-write paths do not read the dispatch slot. Dispatch paths do not explicitly write the destination before invoking the dependency.
