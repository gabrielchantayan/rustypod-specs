# F-b34985657ed0

## Purpose

F-b34985657ed0 dispatches an event-like record for an object. Its established behavior has three branches:

- Event type 15 selects between two embedded object addresses, with different prerequisite checks and follow-up actions.
- Event type 22 extracts a nested record, selects an action from its identifier, and sometimes constructs and submits a derived value.
- Other event types are delegated through two virtual dispatches when a delegate is available.

Most paths return the 32-bit value 1. The general delegation path instead returns either 0, when no delegate is obtained, or the result of the delegate’s handler.

Names such as “event,” “identifier,” “object,” and “submission” describe apparent roles. The supplied static evidence does not establish the application domain, the meanings of the numeric identifiers, or whether a return value of 1 means success, consumption, or merely completion.

## Interface

### Inputs

The function takes two address-valued inputs:

| Input | Required accessible structure |
|---|---|
| Object address | A base address used for embedded-address comparisons, direct dependency calls, and virtual dispatch. The word at offset 0 supplies a virtual-table address on the general delegation path. |
| Event address | A record containing a 32-bit type field at byte offset 4. For type 15, byte offset 8 contains a pointer used for address comparisons. For type 22, the event address is passed to a record-extraction dependency. |

The supplied representation uses four-byte integers and four-byte pointer-bearing fields. All offsets below are byte offsets unless explicitly identified as virtual-table slots.

Two addresses within the object are significant:

- **First embedded address:** object base plus 148 bytes, or hexadecimal 0x94.
- **Second embedded address:** object base plus 192 bytes, or hexadecimal 0xC0.

These are addresses computed from the input object, not pointers loaded from fields at those offsets. Address equality selects the branch; equality of the pointed-to contents is insufficient.

For type 22, F-682adfd5a561 returns an address whose field at offset 8 supplies a nested-record address. The nested record contains a 32-bit identifier at offset 4.

### Output

The return is a 32-bit value:

- 1 for every explicitly completed type-15 or type-22 path.
- 0 when general delegation produces a null delegate.
- The delegate handler’s 32-bit result otherwise, without normalization to 0 or 1.

No explicit error return is established for allocation failure, invalid addresses, or dependency failure.

### Preconditions

The function performs no visible validation of its top-level inputs or of addresses obtained on the type-22 path. Valid execution therefore requires all locations reached by the selected path to be readable, and all indirect call targets reached by that path to be callable.

The visible logic does not establish an ownership transfer for either input. It also does not establish that dependencies preserve either input’s storage, global state, or pointer validity.

## Behavior

### Entry state and event selection

Before inspecting the event type, the function reads a 32-bit global value and retains it for later comparisons or submission. This contract calls that retained value the **entry selector**. Later modification of its underlying global does not change the already retained value.

The event type at offset 4 is first compared with 15. If that comparison fails, the field is read again and compared with 22. Consequently, two reads are visible on the non-type-15 path. No snapshot or synchronization guarantee is established for concurrent modification.

### Type 15: embedded-address handling

The pointer-bearing event field at offset 8 is first compared with the first embedded address.

**When it matches the first embedded address:**

1. F-938c950e5046 is called with no explicit arguments.
2. F-12667b8f9274 is called with no explicit arguments.
3. If the second call returns zero, F-8a4515a6add2 is called with the original object address, and the function returns 1.
4. If the second call returns nonzero, F-ec4cfa552cce is called with the first embedded address, and the function returns 1.

The first dependency’s return value is not used. Its effects may nevertheless influence the next dependency; the visible call order must be preserved.

**When the initial comparison does not match:**

The event field at offset 8 is read again and compared with the second embedded address. If it does not match, the function returns 1 without invoking the type-15 action dependencies.

If it matches, the function reads a separate global pointer-bearing location, dereferences the resulting address to obtain a word, and passes that word to F-6e4f9a39b210.

- A nonzero result causes F-ec4cfa552cce to receive the second embedded address. The function then returns 1.
- A zero result enters the construction-and-submission path described below. That path uses the original object address and the retained entry selector.

The first embedded-address path does not call F-6e4f9a39b210. The second embedded-address path does not call F-938c950e5046 or F-12667b8f9274.

### Type 22: nested-record dispatch

The function calls F-682adfd5a561 with the event address and the literal selector 0xF00. It then:

- Reads a nested-record address at offset 8 of the returned structure.
- Reads the nested record’s 32-bit identifier at offset 4.

Neither address is checked for null before the corresponding dereference.

The identifier selects behavior in this precedence order:

| Identifier condition | Observable action |
|---|---|
| Equal to 0x6380002E | Call F-eba05a4457d1 with the original object address, then F-19c0dbbb52a4 with that same address; return 1. |
| Equal to 0x66000003 | Proceed directly to construction and submission. |
| Otherwise equal to the retained entry selector | Call F-5ced4c169c92 with the original object address; return 1. |
| Equal to one of 0x66000004, 0x66000005, 0x66000006, or 0x66000007 | Call F-d189d16d5a68 with no explicit arguments, pass its result and zero to F-5812b0720631, then proceed to construction and submission. |
| Equal to 0x6600000C | Call F-88567bb82e2a with the original object address; return 1. |
| Any other value | Return 1 without further visible action. |

Precedence is significant when the entry selector equals a listed constant:

- 0x6380002E always selects its two-call action.
- 0x66000003 always selects direct construction and submission.
- An entry selector equal to one of the four grouped values selects F-5ced4c169c92 instead of the grouped two-call action.
- An entry selector equal to 0x6600000C selects F-5ced4c169c92 instead of F-88567bb82e2a.

For the grouped values, the result of F-5812b0720631 is not used. Its invocation completes before the construction dependency is called.

### Construction and submission

Two cases reach this shared behavior:

- Type 15, second embedded-address match, with a zero result from F-6e4f9a39b210.
- Type 22, through identifier 0x66000003 or an eligible grouped identifier.

The function first calls F-0a77364c41cc with the literal value 12. The supplied evidence does not establish whether this is allocation, factory construction, or another operation, nor whether 12 denotes a byte count.

The resulting value becomes the first argument to F-4e95b66bff0e. Its remaining arguments are:

- The selected 32-bit identifier.
- Zero.

The source and timing of the selected identifier differ by branch:

- **Type 15:** the retained entry selector is used. The underlying global is not reread for this purpose.
- **Type 22:** the identifier at offset 4 of the previously obtained nested record is reread **after** F-0a77364c41cc returns. This reread occurs after the grouped dependencies too, if those were selected.

Thus, for type 22, the identifier that determined branch selection need not equal the identifier passed to F-4e95b66bff0e. A dependency may have changed the nested record between those reads. The nested-record address itself remains the previously obtained address; the extraction dependency is not called again.

Finally, F-8e50f265e4fa receives:

1. The original object address.
2. The result of F-4e95b66bff0e.
3. Zero.

Its return value is ignored, and the function returns 1.

There is no visible check on either intermediate result before it is passed onward.

### Other event types: delegation

For an event type not selected as 15 or 22:

1. The object’s virtual-table address is read from offset 0.
2. An indirect function is invoked through the table entry at offset 0xCC.
3. If the returned delegate address is null, the function returns 0.
4. Otherwise, the delegate’s virtual-table address is read from its offset 0.
5. The function at that table’s offset 0x30 is invoked with the delegate address and the original event address.
6. Its return value is returned unchanged.

The first indirect call has no explicit arguments in the supplied representation. Whether an implicit receiver is supplied through the actual calling convention is not established.

The second indirect call explicitly receives the delegate and event addresses. This contract does not infer that the delegate owns the event or preserves the original object.

## Acceptance examples

The examples are conditional static acceptance criteria, not reported runtime results. Unless stated otherwise, referenced storage remains valid and dependencies return normally.

1. **First embedded address, zero decision.**  
   Given type 15 and an event pointer field equal to object base plus 148, F-938c950e5046 precedes F-12667b8f9274. If the latter returns zero, F-8a4515a6add2 receives the original object, F-ec4cfa552cce is not invoked by this path, and the result is 1.

2. **First embedded address, nonzero decision.**  
   Under the same address match, a nonzero decision causes F-ec4cfa552cce to receive object base plus 148, not the original object base.

3. **Second embedded address, failed prerequisite.**  
   Given type 15, a pointer-field match with object base plus 192, and a zero result from F-6e4f9a39b210, the construction chain uses the entry selector captured at function entry. A subsequent change to that global does not replace the captured value.

4. **Unrecognized embedded address.**  
   Given type 15 and neither address comparison matching, the function returns 1 without any type-15 action call.

5. **Ordered two-action identifier.**  
   Given type 22 and identifier 0x6380002E, F-eba05a4457d1 precedes F-19c0dbbb52a4. This remains true if the entry selector is also 0x6380002E.

6. **Selector collision with a grouped identifier.**  
   Given type 22, identifier 0x66000005, and entry selector 0x66000005, only the selector-match action F-5ced4c169c92 is selected. The grouped action and construction chain are not selected.

7. **Late identifier mutation.**  
   Given type 22 initially selecting 0x66000003, suppose F-0a77364c41cc changes the nested identifier to another 32-bit value while preserving the record’s validity. F-4e95b66bff0e receives the changed value. Branch selection is not repeated.

8. **Unknown identifier.**  
   Given type 22 and an identifier matching neither the entry selector nor any listed constant, extraction and identifier reads occur, but no action or construction call follows. The result is 1.

9. **Null delegate.**  
   Given another event type and a null result from the first virtual call, the result is 0 and the second virtual call is not made.

10. **Non-Boolean delegated result.**  
    If the delegate handler returns 0x80000002, this function returns that same 32-bit pattern rather than converting it to 1.
