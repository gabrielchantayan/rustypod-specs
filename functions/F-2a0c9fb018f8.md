# F-2a0c9fb018f8

## Purpose

F-2a0c9fb018f8 selects between two synchronous processing paths using six 32-bit integer inputs:

- A **fallback path** when either of two input pairs contains equal values, or either of two additional inputs is not strictly positive.
- A **construction-and-consumption path** otherwise, using a 68-byte temporary storage region shared between two dependency calls.

These path names describe the visible call structure, not an established application-level meaning. The supplied evidence does not establish whether the inputs describe coordinates, dimensions, ranges, or another domain. In particular, the function does not require either member of an unequal pair to be greater than the other.

This contract describes the behavior established by the supplied static representation. No runtime tests have been performed.

## Behavior

### Path selection

The construction-and-consumption path is selected exactly when all four conditions hold:

1. The first pair’s members differ.
2. The second pair’s members differ.
3. The first positivity input is greater than zero.
4. The second positivity input is greater than zero.

Every other combination selects the fallback path.

Pair ordering is immaterial to this decision. Reversing either unequal pair does not change the selected path, provided the other conditions remain unchanged. The original argument order is nevertheless preserved when values are forwarded to the construction dependency.

Zero and negative positivity inputs have the same branch-level consequence: fallback. There is no visible absolute-value conversion, clamping, normalization, or retry.

### Integer arithmetic and boundary behavior

The supplied representation includes 32-bit pair subtractions and signed-overflow bookkeeping during condition evaluation. The resulting dispatch condition does not impose a sign or magnitude requirement on either pair’s difference.

The final path decision therefore must not be specified as requiring a positive pair span, a nonnegative pair span, or a safely representable signed subtraction. Such requirements would reject inputs that the visible dispatch permits.

For example, a pair containing −2,147,483,648 and 2,147,483,647 is unequal and therefore satisfies its pair condition. A mathematical difference outside the signed 32-bit range does not itself select fallback.

The subtraction results are not passed to either dependency. The original six integer arguments are passed on the construction path.

### Construction-and-consumption path

This path uses a 68-byte local temporary storage region. The visible function performs no explicit initialization of that region before passing it to a dependency.

The call order is fixed:

1. F-18462c514b4d receives access to the temporary storage region, followed by arguments 2 through 7 in their original order and without visible transformation.
2. After that call returns, F-a056fe41b970 receives the original context followed by access to the same temporary storage region.
3. After the second call returns, the function returns.

The context is not passed to F-18462c514b4d by this call site. F-a056fe41b970 receives the temporary region rather than receiving the six integer inputs directly.

There is no visible inspection of the region between the two calls. In particular, the function does not check a field, validate a status marker, or branch on a result from F-18462c514b4d before invoking F-a056fe41b970.

The names “construction” and “consumption” reflect the ordering and shared storage. They do not establish which bytes the first dependency writes, which bytes the second reads, or whether either dependency stores indirect resources in the region.
