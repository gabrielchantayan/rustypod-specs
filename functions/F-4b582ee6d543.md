# F-4b582ee6d543

## Purpose

F-4b582ee6d543 performs an ordered transition on a caller-supplied mutable object. It replaces dispatch-related fields, invokes direct and indirect dependencies, conditionally processes an associated record and its collection-like member, conditionally clears a reference in a provider-returned object, and processes a final optional member.

On normal completion, it returns the original input pointer. One conditional path instead reaches a dependency marked as non-returning.

“Teardown” is inferred intent, not an established ownership contract. The visible operations do not establish that the input object is deallocated, that indirect calls release their receivers, or that associated pointer fields are cleared. The contract below describes observable accesses and call ordering without assigning those unverified semantics.

## Behavior

All sequences below are conditional on preceding calls returning. Descriptive field names do not imply verified class or ownership semantics.

### 1. First dispatch transition and service call

The function first reads a global dispatch-base word and saves that value. It then separately evaluates the same global for the assignment to input-object offset 0.

The observable sequence is:

1. Read the global into a saved value.
2. Read that global again and assign this second evaluation to object offset 0.
3. Assign the saved value plus 272 to object offset 28.
4. Assign the saved value plus 284 to object offset 40.

Thus, the offset-0 assignment and the two additions do not all use one captured read. This distinction records the supplied representation; it does not assert that the two global evaluations differ in ordinary execution.

The additions are numeric byte-offset additions to a four-byte word, not element-scaled pointer additions. The evidence establishes the constants and represented widths, but not portable behavior for arithmetic outside the expected address range.

F-15643c36365d is then called without explicit arguments. From its result, the function selects dispatch-table entry 12 and invokes it with:

- The returned object pointer.

The callee receives the field's address, not just its stored value. Modification or retention of that address is not established.

## Acceptance examples

These are conditional static criteria, not executed tests. Unless a scenario specifies otherwise, selected dependencies return and leave all subsequently accessed storage valid. That assumption does **not** imply preservation of field values. Conditions below apply at the stated reads.

1. **Optional branches absent.** If object offsets 36, 12, and 4 are each zero at their respective branch reads, the corresponding optional phases are skipped. The initial service call, notification, and final dispatch assignment still occur, followed by return of the input pointer.

2. **State bypassed.** If offset 4 is zero at the final outer branch read, even a nonzero offset-8 value does not cause either terminal dependency to be called.

3. **Record with zero predicate and no traversal.** If a record is selected, F-a1a48bd3fbde returns zero, and saved-record offset 8 is zero when tested, both conditional processing and traversal are skipped. The later provider comparisons, one F-65528ded3450 call, and F-8349c252c168 still occur.

4. **Nonzero predicate, zero context field.** If the predicate is nonzero and the first provider offset-40 test is zero, the nested indirect call and F-a5514b9f24f7 are skipped. The first F-65528ded3450 and F-a82ec4b43e2f calls still occur.

5. **Both saved-value conditions hold.** If the predicate is nonzero and the later provider offset-40 comparison equals the input pointer, F-a82ec4b43e2f receives the same saved record value twice.

6. **Null traversal item.** A nonzero traversal result followed by an initialized null first output pointer causes no item indirect call for that iteration. Traversal continues. A zero result does not require the caller to consume either output pointer.

7. **Collection changed during traversal.** If saved-record offset 8 is zero at the post-traversal test, the final collection call is skipped. If it instead identifies a different valid receiver at dispatch selection, that receiver supplies the call target.

8. **Final member cleared by helper.** If offset 4 is nonzero at the outer test but zero after F-c719314a16bb, its indirect call is skipped. Offset 8 is still tested afterward.

9. **Provider identity changes.** If one provider result matches the input pointer at offset 36, the next provider result receives the zero write at offset 36, without a second equality requirement.

10. **Dispatch-base evaluations.** In each of the first two phases, offset 0 receives the separately evaluated global value, while the additions use the earlier saved value. Under an explicit assumption that the global is unchanged between those reads, the resulting words share the same base.
