# F-0b8d64ead624

## Purpose

F-0b8d64ead624 searches an ordered collection of range descriptors for a requested unsigned key. A descriptor qualifies when the key lies within its inclusive range and its lookup table supplies an index other than the reserved value 65,535.

For the first qualifying descriptor, the function invokes an external operation on a 20-byte record, invokes a second dependency with descriptor-associated context, performs a finalization call, and returns the 32-bit value 1. If no descriptor qualifies, it performs the same finalization call and returns 0.

The established behavior is a search followed by dependency calls. Interpreting those calls as copying a record, constructing an output, or acquiring and releasing a lock is inferred intent, not an established dependency contract.

## Behavior

### Entry and search eligibility

The first operation is a call to F-4a19e3742733 with the object address plus 24. Its return value does not determine any later branch or returned result.

Only after this call returns does the function read the signed indexed count from object offset +8. Consequently, changes made by the entry dependency can affect the count used by this invocation.

When the count is zero, the function also reads the fallback address at offset +20 to decide whether any search should occur:

- Zero count and zero fallback address lead directly to finalization and result 0.
- Zero count and nonzero fallback address enter the search.
- A nonzero count enters the search without this preliminary fallback-address read.

The count is retained for the traversal. Later changes to the count field do not replace that retained value.

A negative count enters the search region but fails the first signed loop-bound check. It therefore examines no descriptor, including no fallback descriptor, and proceeds to finalization with result 0.

### Descriptor order

For a nonnegative count, indexed descriptors are considered in increasing index order, starting at zero and stopping before the count. The optional fallback descriptor is considered afterward, at the traversal position equal to the count.

Each indexed access performs a fresh indirect dispatch using the embedded object at object offset +4. The function does not establish that the dispatch table, returned entry, or descriptor remains unchanged between accesses.

For the fallback position, the function reads the fallback address from object offset +20. A zero value terminates the search without examining a descriptor.

This fallback read is distinct from the preliminary eligibility read used when the count is zero. If an intervening operation or concurrent writer changes the fallback field, the later read can observe a different address.

### Range and table selection

For each descriptor:

1. The unsigned 16-bit lower bound is compared with the unsigned 32-bit requested key.
2. Only if the key is not below that bound is the unsigned 16-bit upper bound used for the upper-bound comparison.
3. Only if both comparisons pass is the descriptor's table used.
4. The table entry is selected by the key's displacement from the lower bound, with two bytes per entry.
5. A table value of 65,535 rejects this descriptor and continues the search.
6. Any other table value selects a record and ends descriptor searching.

The bounds are inclusive. No sorting or non-overlap requirement is checked. Earlier descriptors take precedence only when they have both a matching range and a non-sentinel entry. A matching range with a sentinel entry does not prevent a later descriptor from succeeding.

The lower bound is accessed again for the table displacement. The implementation does not establish one immutable snapshot of descriptor contents across all these accesses.

With stable descriptor fields, a key above 65,535 cannot pass a descriptor's upper-bound comparison, because that upper bound is only 16 bits wide. The input key is not first truncated to 16 bits.

### Successful selection

For a selected table value, the record address is formed from the descriptor's record base plus 20 times that value.

The function then invokes the external record operation with these three arguments, in this order:

1. The first output argument.
2. The calculated record address.
3. The constant length 20.

Its result, if any, is ignored.

After that operation returns, the function reads the context address from descriptor offset +16. It invokes F-8a2ae74ef867 with eight arguments:

1. The second output argument.
2. The context address plus 152.
3. The 32-bit field at context offset +4.
4. The 32-bit field at context offset +8.
5. The 32-bit field at context offset +12.
6. The 16-bit field at context offset +20.
7. Zero.
8. Zero.

The argument positions are established. The relative evaluation order of the individual context-field reads is not established by the supplied evidence.

After F-8a2ae74ef867 returns, the function calls F-fd58bea73663 with the original object address plus 24, ignores that dependency's result, and returns 1.

### Unsuccessful search

If no descriptor qualifies, the function calls F-fd58bea73663 with the original object address plus 24 and returns 0.

No external record-operation call or F-8a2ae74ef867 call occurs on this normal no-match path. This does not imply that all memory or outputs remain unchanged: the entry, indexed-access, and finalization dependencies may have side effects.

## Side effects

### Established call and access ordering

On every normal execution, the following ordering applies:

- F-4a19e3742733 precedes the indexed-count read.
- Indexed candidates precede the fallback candidate.
- A candidate's range checks precede its table lookup.
- A successful table lookup precedes the external record operation.
- The external record operation returns before the descriptor's context-address read.
- F-8a2ae74ef867 returns before F-fd58bea73663 is called.
- F-fd58bea73663 returns before the function returns either result.

The target function contains no direct object-field assignment or explicit allocation/free operation. Its dependencies may write memory, allocate, release resources, mutate shared state, or fail to return; their implementations are not supplied.

### Ownership and lifetime

No ownership transfer is established. Addresses are passed to dependencies, but the evidence does not show whether those dependencies retain, release, or merely inspect them.

For defined normal behavior, every address actually dereferenced must identify suitably accessible storage at the time of the access. This includes:

- The object fields used on the selected path.
- The dispatch table and callable slot for each indexed access.
- Each returned entry wrapper and descriptor.
- The selected table entry.
- The descriptor's context and required context fields after the external record operation.

The record and output arguments must additionally satisfy the dependencies' own, unknown contracts.

Because the context address is read after the record operation, that operation can affect subsequent behavior if it mutates or invalidates the descriptor or related storage. No dependency-preservation guarantee may be assumed.

### Arithmetic and errors

The interface and addresses are 32-bit; bounds and table entries are 16-bit.

With stable fields and a successful range check, the table displacement is at most 65,535, requiring at most 131,070 bytes of displacement from the table base. A selected record index is at most 65,534, giving a maximum record displacement of 1,310,680 bytes. These products fit within 32 bits, but adding either displacement to an arbitrary address is not validated.

The function performs no explicit checks for:

- Null indexed-entry results or indexed descriptor addresses.
- Null table, record-base, or context addresses.
- Table or record allocation sizes.
- Invalid dispatch targets.
- Output capacity or overlap.
- Dependency-reported errors.

A malformed descriptor is not converted into a clean “no match” result unless it happens to fail a range check or return the sentinel before the invalid access would occur.

At the maximum signed 32-bit count, a failed, non-null fallback can lead to an attempted increment beyond the largest signed 32-bit index. The supplied evidence does not justify a portable result for that boundary. Normal bounded traversal requires avoiding that case or terminating earlier.

## Acceptance examples

These are conditional static acceptance examples, not executed tests. Unless stated otherwise, they assume stable valid memory and dependencies that return normally.

### Empty collection

Given a count of zero and a null fallback address:

- The entry dependency runs.
- The count and fallback eligibility fields are read.
- No descriptor access, record operation, or context-processing call occurs.
- Finalization runs.
- The result is 0.

### Inclusive endpoints

Given one descriptor spanning keys 100 through 102, with non-sentinel entries at both endpoints:

- Key 100 selects the first table entry.
- Key 102 selects the third table entry.
- Key 99 is rejected by the lower-bound comparison.
- Key 103 is rejected by the upper-bound comparison.

No out-of-range table entry is read for the rejected keys.

### Sentinel allows later success

Given two descriptors whose ranges both contain the key:

- If the first descriptor's entry is 65,535, the second descriptor is examined.
- If the second descriptor's entry is 7, the external record operation receives its record base plus 140.
- Context processing uses the second descriptor.
- The result is 1 after finalization.

### Zero is a valid record index

Given an in-range key whose table entry is zero, the record address equals the descriptor's record base. Zero is not a missing-entry marker.

### Fallback after indexed misses

Given two indexed descriptors that do not qualify and a valid fallback that does:

- Indexed positions zero and one are examined first.
- The fallback is examined next.
- Its selected record and context are used.
- No further candidate is examined after success.

### No implicit key truncation

Given key 65,536 and any stable 16-bit descriptor bounds, that descriptor cannot qualify. The key does not become zero.

### Negative count

Given a count of −1 and a non-null fallback:

- No indexed accessor is called.
- The fallback is not examined.
- Finalization runs and the result is 0.

### Output effects remain dependency-dependent

Given a successful selection, the established acceptance condition is the record-operation call followed by the context-processing call and finalization. Exact final output bytes require additional dependency contracts. A result of 1 alone does not establish those bytes.
