# F-1c7710595b35

## Purpose

F-1c7710595b35 converts a 32-bit two’s-complement integer representation into the 32-bit encoding of its IEEE 754 binary32 value, using round-to-nearest with ties to even.

The interface carries both input and output as unsigned integer words. The input’s most significant bit nevertheless determines a signed interpretation. The output is a floating-point **encoding**, not an integer approximation of the input and not an established floating-point ABI return value.

This conversion interpretation is inferred from the arithmetic structure. The directly established behavior is the sign extraction, unsigned magnitude transformation, leading-zero normalization, integer construction of the result, and final rounding correction described below.

No runtime tests have been performed.

## Interface

One 32-bit unsigned word is supplied by value.

Its interpretation for conversion is:

- Words from `0x00000000` through `0x7fffffff` represent integers from zero through 2,147,483,647.
- Words from `0x80000000` through `0xffffffff` represent integers from −2,147,483,648 through −1.

Every 32-bit input pattern is within the conversion’s intended domain. There is no pointer, length, buffer, object handle, or caller-provided output location.

## Behavior

### Sign and magnitude

The function first retains the input’s bit 31 as the prospective output sign.

If that bit is clear, the input word itself is used as the magnitude. If it is set, the function obtains the magnitude by 32-bit unsigned negation.

This distinction matters at the negative endpoint. Input `0x80000000` produces magnitude `0x80000000`, representing \(2^{31}\). The operation does not require a positive signed 32-bit representation of that magnitude and is not a saturating absolute-value operation.

Input zero has a clear sign bit. There is no separate input representation for negative integer zero.

### Normalization and zero handling

The function counts leading zero bits in the magnitude and shifts the magnitude left by that count.

For every nonzero input magnitude:

- The count is between 0 and 31.
- The normalized word has bit 31 set.
- No significant magnitude bits are discarded by normalization.
- The position of the highest set bit in the original magnitude is encoded by the count.

The normalized word is then compared with zero. If it is zero, the function returns the all-zero word immediately.

Importantly, normalization occurs **before** this zero check. The supplied evidence therefore does not show an early guard that avoids counting leading zero bits or shifting when the input is zero.

On an execution model where normalization of a zero magnitude produces zero, input `0x00000000` returns `0x00000000`, the positive-zero binary32 encoding. This result is conditional on the zero-operation semantics rather than on an earlier zero-input branch.

For nonzero magnitudes, the normalized word cannot be zero under the stated 32-bit operation meanings, so result construction proceeds.

### Result construction

For a nonzero magnitude, the function constructs a preliminary result using the retained sign, the normalization count, and the upper bits of the normalized word.

An equivalent unsigned description of that construction is:

\[
R =
S
+ \mathtt{0x4e800000}
- c\cdot\mathtt{0x00800000}
+ H
+ q
\pmod{2^{32}},
\]

where:

- \(S\) is either zero or `0x80000000`, according to the original input sign.
- \(c\) is the leading-zero count of the magnitude.
- \(H\) is the unsigned value of normalized bits 31–8.
- \(q\) is the value, zero or one, of normalized bit 7.

This is a behavioral equivalence, not a claim that the implementation uses this exact arrangement. The supplied arithmetic instead combines a fixed term with an arithmetic right shift of the normalized word interpreted as signed. Because the normalized word has bit 31 set, that signed interpretation is negative. Accounting for its sign extension yields the expression above.

For magnitude \(m>0\), the highest set-bit position is \(31-c\). The intended unbiased binary32 exponent is therefore \(31-c\), with the usual bias of 127. Normalized bits 30–8 supply the fraction before rounding.

The construction uses addition, not independent insertion of already-finalized exponent and fraction fields. A rounding carry can therefore pass through the fraction and increment the exponent.

### Rounding

The function distinguishes three portions of the normalized magnitude:

- Bits 31–8: retained significand bits.
- Bit 7: the first discarded bit.
- Bits 6–0: the remaining discarded bits.

It first adds the value of bit 7 to the provisional result. It then handles the exact-halfway case:

- If any of bits 6–0 is set, the preliminary result is retained.
- If bits 6–0 are all clear and bit 7 is set, the result’s least significant bit is cleared.
- If bit 7 is clear, no final clearing occurs.

The resulting behavior is:

| Discarded portion | Rounding result |
|---|---|
| Below halfway | Retain the lower-magnitude representable value |
| Above halfway | Increment the retained significand |
| Exactly halfway, retained significand even | Retain it |
| Exactly halfway, retained significand odd | Increment to the even neighbor |

Thus the rounding rule is nearest, ties to even. The final least-significant-bit clear is essential: adding the first discarded bit alone would round every halfway case upward in magnitude.

Rounding is performed on the magnitude representation. Negative inputs use the same magnitude rounding, with the original sign retained. Consequently, increasing the rounded magnitude of a negative input makes its represented numerical value more negative; this is not directed rounding toward positive infinity.

### Range and special encodings

Under the conversion interpretation:

- Larger magnitudes may require rounding.
- Every nonzero result is a normal finite binary32 value.
- No input requires a subnormal result, infinity, or NaN.
- The largest positive input rounds to \(2^{31}\), even though that value is outside the positive signed 32-bit integer range.
- The most negative input is exactly representable as \(-2^{31}\).

The finite input range therefore needs no overflow status or saturation behavior.
