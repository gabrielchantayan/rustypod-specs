# F-8f820412f17a

## Purpose

F-8f820412f17a reads a nested 32-bit state field and returns a 32-bit classification:

| Observed state | Returned value |
|---|---:|
| 1 | 2 |
| 2 | 1 |
| Any other 32-bit value | 0 |

The established behavior is a numeric mapping, not a validated interpretation of an object type. The meanings of the enclosing structure, nested structure, state values, and returned classifications are unknown.

The function does not modify the state it reads. In particular, it does not exchange stored values 1 and 2; it only reverses their correspondence in the returned result.

## Behavior

### Observable access order

The supplied static representation establishes two ordered reads:

1. A 32-bit value is read from the input address plus `0xF00`.
2. That value is used as the nested address, and a 32-bit state value is read from it plus `0x18`.

The second read depends on the result of the first. No separate read at the unadjusted input address is shown, and the input itself is not first dereferenced to obtain an outer address.

Both reads precede classification. There is no early return based solely on the first value.

The supplied representation shows one read of each field. Subsequent decisions use the state value already obtained; they do not show another read of the nested field. This describes the visible static access structure, not a concurrency, atomicity, or hardware bus guarantee.

### Classification

Classification is based on exact equality of the complete 32-bit state value:

- State 1 produces result 2.
- State 2 produces result 1.
- State 0 produces result 0.
- Every other state produces result 0.

No mask, range test, truncation to a smaller field, or normalization is shown. A value whose low byte is 1 but whose remaining bits are nonzero does not qualify as state 1.

The source represents the state as a signed 32-bit integer. Signedness does not change this mapping because only equality with 0, 1, and 2 is relevant. Values represented as negative signed integers fall into the result-0 case.

Although zero is distinguished during the visible decision process, its final result is the same as that of every unrecognized state. There is no separate error result for an unrecognized state.

Behavior for overflow, address wraparound, or an address outside the valid execution address space is not established. A portable implementation must not infer a defined wrapping-address contract from this source representation.

### Failure behavior
