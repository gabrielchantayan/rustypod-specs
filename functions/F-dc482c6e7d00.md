## Behavior

The normal-return behavior has three ordered stages.

First, F-ab4e0c01f068 is invoked with no explicit argument. This invocation precedes the invocation of F-95b79f0a129e. There is no visible branch that skips it and no visible decision based on a value it returns.

Second, after F-ab4e0c01f068 returns normally, F-95b79f0a129e is invoked with no explicit argument. Its 32-bit result is retained as the value to be returned by F-dc482c6e7d00.

Third, after F-95b79f0a129e returns normally, F-e5e0e3dec811 is invoked with the original 32-bit input. Only after this final dependency returns normally does the wrapper return the previously obtained 32-bit result.

Each dependency is invoked once on this normal-return path. The visible wrapper contains no loop, retry, alternate dependency, conditional dispatch, or early return. Neither the input bits nor the result bits affect the visible call sequence.

The distinction between obtaining and returning the result is observable and material. F-95b79f0a129e produces the result before F-e5e0e3dec811 runs, but the caller does not receive normal completion until the latter call has returned. An implementation that returned immediately after obtaining the result would omit a required invocation.

The first dependency may affect state subsequently observed by the second or third dependency. The second may likewise affect state observed by the third. The evidence does not establish such effects, but it also does not justify treating the dependencies as independent or reordering them.

## Acceptance examples

These examples are conditional contract checks, not reports of executed tests. Each normal-return example assumes all three dependencies return normally.

1. **Ordinary forwarding and result propagation.** With input `0x12345678`, if F-95b79f0a129e returns `0x89ABCDEF`, the invocation order is F-ab4e0c01f068, F-95b79f0a129e, then F-e5e0e3dec811. The final dependency receives `0x12345678`, and the wrapper returns `0x89ABCDEF`.

2. **Zero is not visibly filtered.** With input `0x00000000` and a result of `0x00000000` from F-95b79f0a129e, the final dependency is still invoked with the zero input, and the wrapper returns zero. This does not establish that zero is valid for the dependency’s own purposes.

3. **High bits remain significant.** With input `0xFFFFFFFF`, the final dependency receives that same 32-bit pattern. If the second dependency returns `0x80000000`, the wrapper returns that pattern without a visible signedness-based branch.

4. **Final-call completion remains required.** If the second dependency has returned but the final dependency has not, the wrapper has not yet completed normally. The availability of the result alone does not permit skipping or bypassing that invocation.

5. **Returned error indicators do not create a branch.** If a separately documented dependency contract identifies a particular result as an error, that interpretation does not alter this wrapper’s visible sequence. The final call still occurs following a normal return from the second dependency.

6. **An interrupted sequence has no established cleanup guarantee.** If F-95b79f0a129e does not return normally, this contract does not require F-e5e0e3dec811 to run. Such a guarantee would need additional evidence.
