# F-767b181ec9e1

## Purpose

F-767b181ec9e1 is a predicate over an integer field associated with a supplied object address. It returns the integer value **1** when that field matches any of three externally stored candidate values, and **0** otherwise. A zero input returns **0** without reading the object or the candidates.

This membership interpretation is established for stable, readable storage. The supplied representation also contains a repeated read of the first candidate location. The source-level read sequence is specified below because it matters independently of the simplified membership interpretation.

The apparent intent is to recognize objects belonging to one of three categories. That interpretation is inferred, not established: the evidence does not identify the object type, the field’s meaning, or the meanings of the candidate values.

- **Any nonzero value** proceeds to an object-field read. No other validation is shown.
- The field is located **64 bytes from the supplied address**, at offset **0x40**.
- The field is read as one integer value, not as a byte, string, pointer-following operation, or aggregate.

The supplied representation uses `int` for the argument, the field value, intermediate integer values, and the return value. It is consistent with a 32-bit integer/address model, but no independent ABI or type declaration establishes the exact machine width. Consequently:

The integer declaration does not establish that the input is an ordinary numeric identifier. Its observed use is as the base of a memory access.

### External inputs

The function reads three distinct external integer storage locations. This contract calls them **candidate A**, **candidate B**, and **candidate C**. These labels identify their roles and order; they do not imply literal constants or particular numeric values.

Their contents are not supplied. The evidence does not establish that they are immutable, initialized by this function, distinct from one another, or disjoint from the addressed object.

### Output

The function does not return the original matching value, a candidate index, a pointer, or a bit mask. Matching a candidate whose value is zero still produces **1**.

## Behavior

### Zero-input path

The function first tests the supplied argument against zero.

If it is zero, the function returns **0**. No object-field read or candidate-location read is shown on this path. No initialization, cleanup, or external call precedes the return.

### Nonzero-input path

The function reads the integer at the supplied address plus 64 bytes. That value is retained for the comparisons; the object field is not read again.

The supplied representation then establishes this source-level sequence:

1. Read candidate A and compare the captured object field with that value.
2. Read candidate A again.
3. If the first comparison was a mismatch, read candidate B and use that value for the next comparison. Otherwise, the next comparison uses the second read of candidate A.
4. Compare the captured field with the selected value.
5. If both preceding comparisons were mismatches, read candidate C and compare against it.
6. Produce **1** if the first comparison matched, the second comparison matched, or the applicable final comparison matched. Otherwise, produce **0**.

On a stable-memory interpretation, this is an ordered membership check against A, B, and C. Candidate B is needed only after failure to match A. Candidate C is needed only after failure to match both A and B.

The repeated read of candidate A is significant to the stated access sequence but not to the normal return value:

- If the first A comparison matched, the result is already determined to be **1**, regardless of the second A read.
- If the first A comparison did not match, candidate B replaces the value obtained by the second A read before the next comparison.

Thus, changing only the second value obtained from A cannot change the normal return result. It may still matter where reads can fault or have externally visible effects. Whether the executable actually performs this otherwise redundant load requires machine-level evidence not supplied here.

### Stable-storage result rule

When the field and candidate locations are readable and stable, the result is **1** exactly when the captured field equals at least one candidate. If it equals none, the result is **0**.

Equality is the only value classification performed. There is no ordering comparison, range check, masking, normalization, or special treatment of negative values.

Duplicate candidate values are permitted by the observed logic. They do not change the membership result, although an earlier match prevents access to later candidate locations.

### Changes during execution

No snapshot of all candidate values is taken. If external storage changes during execution, comparisons use the values obtained at the applicable reads.

The captured object field is different: later changes to the field do not cause it to be reread within this invocation.

These observations do not establish a concurrency guarantee. The evidence supplies no atomics, locking, volatile qualification, memory barriers, or language-level rules making concurrent modification defined.
