# F-440135f92be7

## Purpose

F-440135f92be7 transforms one signed integer through conditional range adjustment, two opaque helper operations, a table lookup, and final signed scaling. Its observable result is a 64-bit value assembled from two 32-bit words.

The lower result word is derived from a helper result and a table entry. The upper result word is assigned the constant 11,796,480 on some paths and has no established initialized value on another reachable path. Consequently, the supplied evidence does **not** establish a deterministic 64-bit result for every input and dependency outcome.

The constants, conditional reflection, table interpolation-like structure, and sign restoration suggest a fixed-point periodic numeric operation. That interpretation is **inferred intent**, not an established mathematical contract. No angle units, period, accuracy guarantee, or named mathematical function can be specified from the available evidence.

## Interface

### Input

One signed 32-bit integer, referred to here as the **input**.

The directly observed entry decision is a signed comparison:

- Inputs greater than 11,796,479 select the **upper-input branch**.
- All other inputs select the **lower-input branch**.

Thus 11,796,480 is the first input selecting the upper-input branch. Negative inputs select the lower-input branch.

There is no explicit input validation, rejection range, or error return.

### Output

One 64-bit result assembled by concatenating:

- An upper 32-bit word.
- A lower 32-bit word containing the final transformed integer’s bit pattern.

This is a bitwise assembly, not an established sign extension of the lower word. For example, when the upper word is assigned and the lower word represents a negative signed integer, the upper word still contains 11,796,480 rather than an all-ones sign-extension word.

The upper word is assigned 11,796,480 if either:

1. The input selects the upper-input branch; or
2. The first dependency returns a nonzero status.

If neither condition holds, the supplied representation shows no initialization of that word before return. Such a result is **documented_only**: no particular upper-word value, stability, or caller-visible portability is promised.

### Referenced storage

The function uses two externally stored values:

- A **helper parameter**, read as the second argument of the first call to F-a04224da5d98.
- A **table base**, read after that call returns.

The evidence does not establish either value’s initialization, ownership, constancy, or permitted range.

Each selected table entry has an observed stride of eight bytes:

| Byte offset within selected entry | Observed role |
|---|---|
| 0 | Address passed to F-a04224da5d98; the callee’s interpretation is unknown |
| 4 | A signed 32-bit value read directly after that call returns |

Only the read at offset four has an established direct-access width. An eight-byte stride does not establish that the dependency reads exactly one 32-bit field at offset zero.

## Behavior

### 1. Capture the input branch and initialize working state

The function determines whether the original input is greater than 11,796,479. This decision is retained for the final sign adjustment; it is not recomputed from later working values.

The initial **working value** is:

- The input itself on the lower-input branch.
- The input minus 11,796,480 on the upper-input branch.

For a signed 32-bit input, the subtraction on the upper-input branch is representable: that branch only admits inputs at least 11,796,480.

A second signed 32-bit local value, the **threshold value**, is initialized to 5,898,240.

On the upper-input branch, the upper result word is also initialized to 11,796,480. No corresponding initialization is visible on the lower-input branch.

There is only one initial subtraction. The function does not directly perform repeated subtraction, modulo reduction, clamping, or negative-input normalization.

### 2. Invoke the first dependency

F-a09269e75221 is called with addresses of the working value and threshold value, in that order.

Both objects contain initialized signed 32-bit values at call entry. Because writable addresses are supplied, subsequent behavior must use the working value as it exists after the dependency returns, not necessarily its pre-call value.

The dependency returns a status interpreted solely as zero or nonzero:

- **Zero:** no reflection is performed at this stage.
- **Nonzero:** the working value is replaced by 11,796,480 minus its post-call value, and the upper result word is assigned 11,796,480.

A nonzero status is not treated as a reported error. It selects a transformation and execution continues.

Changes to the threshold value are not directly consulted afterward. Its storage is later reused for a helper return value.

The subtraction on the nonzero path is not guaranteed representable for every possible post-call working value. In ordinary signed 32-bit arithmetic, it is representable when that value is at least −2,135,687,167. The supplied evidence provides no dependency contract ensuring that condition.

### 3. Obtain the table-selection result

F-a04224da5d98 is called with:

1. The address of the current working value.
2. The current helper parameter read from external storage.

The return is treated as a signed 32-bit value. Its upper signed portion determines table selection by a right shift of 16 bits.

The working value may be modified through the supplied address. The value used by the following helper call is the one present after this call returns.

The helper parameter is not shown as an entry-time snapshot. In particular, the earlier dependency may have changed its external storage before this read.

### 4. Select a table entry

After the preceding helper returns, the function reads the table base and forms the selected entry address using:

- The helper return shifted right by 16 bits.
- A scale of eight bytes per index.
- Addition to the table base.

Under arithmetic signed-right-shift semantics, the index ranges from −32,768 through 32,767. The corresponding scaled offsets range from −262,144 through 262,136 bytes.

Negative indices are not rejected. There is no direct bounds check, null check, alignment check, or table-length check.

The table base is read after the helper call. A dependency-side change to that base can therefore affect entry selection. Once the entry address has been formed, that address is retained for the next call and the later offset-four read; there is no visible reload of the table base between them.

### 5. Obtain an entry-dependent value

F-a04224da5d98 is called again, now with:

1. The selected entry address.
2. The current working value passed as a scalar.

The same opaque dependency is therefore used with two visibly different argument patterns: first a writable local address plus an external value, then a computed table address plus a working integer.

Its second return is treated as a signed 32-bit value. The supplied evidence does not establish the dependency’s mathematical operation, pointer interpretation, access width, purity, or preservation of external state.

### 6. Read the entry adjustment and scale

After the second helper call returns, the function directly reads the signed 32-bit value four bytes beyond the retained selected entry address.

This ordering is observable. The adjustment read is **after** the helper call, not before it. If that call validly changes the selected entry’s adjustment field, the later read observes the changed storage.

The helper return and adjustment value are added, and the resulting signed value is shifted right by eight bits. The addition precedes the shift.

Under arithmetic signed-right-shift semantics, this acts as division by 256 rounded toward negative infinity for negative values, not division rounded toward zero.

The supplied evidence does not establish wrapping behavior for an overflowing signed addition. A well-defined arithmetic acceptance case must either keep the sum within the signed 32-bit range or rely on a separately established target-level overflow contract.

### 7. Apply the retained sign decision and return

If the original input selected the upper-input branch, the scaled value is negated. Otherwise it is retained unchanged.

The first dependency’s status does not directly select this final negation. It controls the earlier reflection and upper-word assignment; the original input branch independently controls final negation.

With arithmetic right shift of a representable signed 32-bit sum, the scaled value lies between −8,388,608 and 8,388,607. Its final negation is therefore representable as a signed 32-bit integer.

The final value’s 32-bit pattern becomes the lower result word. The upper result word is concatenated with it as described in the interface.

### Dependency-mediated effects

Absence of direct external writes does not establish purity.

The first dependency receives writable local addresses. The first invocation of the second dependency receives a writable working-value address. The final dependency invocation receives a table-derived address.

Their effects on reachable memory, global state, I/O, ownership, and error handling are unknown. They must not be assumed to preserve either external value or table contents.

The local addresses refer to storage associated with this invocation. The supplied evidence does not authorize persistent use of those addresses after return. It also does not establish that the dependencies refrain from retaining them.

No ownership transfer, release obligation, or deallocation behavior is established for the table-derived address. The wrapper itself does not explicitly release it.
