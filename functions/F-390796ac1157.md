# F-390796ac1157

## Purpose

F-390796ac1157 conditionally processes an object whose visible state includes bucket storage, a traversal cursor, and a count-like field. It first obtains a 32-bit result from F-0b31936eccf4. If that result equals the object’s field at offset `0x18`, processing ends. Otherwise, it initializes temporary state, traverses bucket slots, invokes dependencies using node metadata, replaces bucket heads, updates object state, and performs final processing.

A bucketed-container rebuild or redistribution is **inferred intent**. The available evidence does not establish preservation of logical contents, node detachment, ownership transfer, or resource release.

This contract describes direct accesses and dependency ordering on normal execution. Completion is conditional on valid storage, compatible dependency behavior, and terminating traversal.

### Bucket and node layout

A bucket slot is a four-byte word interpreted as either zero or a node address.

For each nonzero head initially observed in a slot:

- Four-byte metadata words are read at offsets `−0x10` and `−0x0c` from that head.
- Two dependencies execute.
- The bucket slot is read again to select the address used for head replacement.
- The four-byte word at offset zero from that selected address supplies the replacement head.

The metadata source need not be the subsequently selected node. The function does not establish node validity, exclusive membership, or acyclic links.

## Behavior

### Entry decision

F-0b31936eccf4 first receives the comparison input. The object field at `0x18` is read only after that invocation returns.

If the field equals the returned 32-bit value, the function returns without visible temporary initialization, bucket access, or direct object writes. The initial dependency may nevertheless have side effects, including changing the field subsequently compared.

On inequality, processing continues. The first result is not reused as the value stored in temporary field `+0x08`.

### Initialization and captured state

On the mismatch path, temporary field `+0x04` is set to zero. F-0b31936eccf4 is then called again, and its result is stored at temporary offset `+0x08`. Temporary fields `+0x0c` and `+0x10` are subsequently set to zero. F-52c0ed1ccba4 then receives the temporary-state address.

The second F-0b31936eccf4 invocation has no explicit argument in the supplied representation. Its effective inputs and calling requirements are **documented_only**. It is not established to repeat the first invocation’s result.

After F-52c0ed1ccba4 returns, the object fields at `0x04`, `0x14`, and `0x18` are read in that order.

The captured `0x04` value is used with the object address to form the first argument to each F-58cc241cfb6b call. This field is not refreshed during traversal.

The retained traversal endpoint is formed from the captured `0x14` value plus four times the subsequently read `0x18` value. Later changes to either object field do not recompute that endpoint.

The captured `0x14` value also supplies the initial carried argument for per-node processing. After the first processed node, this carried value has a different source described below.

### Traversal boundaries

Each outer-loop check reads the current object field at `0x1c` and compares it with the retained endpoint.

Equality ends traversal. Inequality selects the current cursor value as the address of a bucket slot. There is no ordering comparison, alignment check, or independent range check.

The selected slot address remains fixed throughout that slot’s inner loop. A dependency can change the object’s cursor field without changing the slot currently being processed.

A zero value in field `0x18` does not itself suppress traversal. The cursor must equal the calculated endpoint. Likewise, a cursor beyond the endpoint is not rejected merely for being beyond it.

### Processing a nonzero head

The retained bucket slot is read. A zero value leads to cursor advancement. A nonzero value identifies the node from which the two metadata words are read.

F-58cc241cfb6b receives four arguments:

- The object address plus the captured `0x04` offset.
- The current carried argument.
- The metadata word at offset `−0x10` from the initially observed head.
- The metadata word at offset `−0x0c` from that head.

Both metadata reads precede the call. Their relative evaluation order is not established.

F-4c621b77f8a9 then receives the temporary-state address and the result of F-58cc241cfb6b.

**Only after both dependencies return is the retained bucket slot read again. The address present at this reread determines the selected node.** Earlier head replacements do not determine this selection unless their value remains present until the reread.

The selected node’s first four-byte word is then read and written into the retained bucket slot. The function next reads the current object field at `0x20`, subtracts one, and writes the result back.

F-09c9a6de563d subsequently receives:

- The temporary-state address.
- The selected node address from the post-dependency bucket-slot reread.
- The result of F-4c621b77f8a9.

An additional machine-register output associated with F-09c9a6de563d becomes the carried argument for the next F-58cc241cfb6b invocation. Its meaning and calling-convention status are unresolved. The carry is not reset when traversal advances to another bucket.

There is no zero check between the post-dependency slot reread and the selected node’s first-word read. If the slot has become zero, the function still attempts that next access.

The original metadata-source address and its original first word are not retained as mandatory inputs to head replacement. The replacement uses the selected address’s first word as read after both preceding dependencies.

### Repetition and cursor movement

After F-09c9a6de563d returns, the same retained bucket slot is read again. A nonzero value repeats node processing. Zero ends that slot’s inner loop.

When zero is observed, the function reads the current object field at `0x1c`, adds four, and stores the result back. This increment uses the field’s current value, not necessarily the retained slot address.

The next outer-loop check rereads the cursor and compares it with the unchanged endpoint. Dependency-induced cursor changes can therefore affect later slot selection and termination.

### Final state changes

F-f673c27f3127 is then called with the address of temporary field `+0x08` and the address of object field `0x18`. Its operation on these values is unknown; a swap must not be assumed.

The remaining direct updates have this order:

1. Save the current object field at `0x1c`.
2. Replace object field `0x1c` with temporary field `+0x0c`.
3. Save the current object field at `0x20`.
4. Replace object field `0x20` with temporary field `+0x10`.
5. Store the saved cursor value into temporary field `+0x0c`.

These are ordered operations, not an established atomic transaction. Initial temporary zeros do not predict the final installed values because intervening dependencies may modify temporary storage.

## Side effects

### Direct writes and visibility

On the mismatch path, direct writes include temporary initialization, bucket-head replacement, decrementing field `0x20`, advancing field `0x1c`, and final object/temporary exchanges.

Before each F-09c9a6de563d invocation, the selected node’s first word has already been written into the retained bucket slot, and field `0x20` has already been decremented.

These writes do not prove node detachment. A selected node whose first word points to itself remains the bucket head after replacement. Other references may also continue to reach it. The function does not directly clear node metadata or the selected node’s link.

The evidence does not establish portable overflow behavior, signedness rules for every operation, or valid interpretations of wrapped addresses. In particular, subtracting one from a zero field at `0x20` is not explicitly rejected; a portable resulting value is not specified here.

There is no visible failure-result check, range guard, cycle detection, recovery branch, or rollback. Opaque dependency results forwarded to later dependencies are not checked for failure.

## Acceptance examples

These are conditional static expectations, not executed tests.

1. **Equal comparison result.**  
   If the first F-0b31936eccf4 result equals field `0x18` when that field is read, no other listed dependency is called. This function performs no direct object write. Side effects of the initial dependency remain possible.

2. **Cursor already at endpoint.**  
   If the first traversal check finds the cursor equal to the retained endpoint, no bucket head is read. Final field updates and the final three dependency calls still occur.

3. **One empty slot remains.**  
   If the cursor is four bytes before the endpoint, the selected slot is zero, arithmetic is valid, and no relevant interference occurs, the cursor advances by four and traversal ends. No per-node dependency or count decrement occurs.

4. **Stable single-node bucket.**  
   Suppose the cursor is one slot before the endpoint, the head identifies a valid node, and storage does not alias in a way that disturbs these observations. If both pre-replacement dependencies preserve that head and the node’s first word remains zero until read, the replacement head is zero. Field `0x20` is decremented before F-09c9a6de563d receives that node. If this call preserves the zero head and relevant cursor, the slot then finishes and traversal reaches the endpoint.

5. **Changed successor without changed head.**  
   If the head remains the same but a preceding dependency changes that node’s first word, the replacement uses the changed word as observed at the successor read. An initially zero first word does not alone predict a zero replacement.

6. **Replacement head survives until the reread.**  
   Suppose metadata is read from node A. If a dependency changes the retained slot to node B, and B remains in that slot until the reread after F-4c621b77f8a9 returns, B determines the successor-read address and the node argument to F-09c9a6de563d. Metadata arguments still came from A.

7. **Earlier replacement is reversed.**  
   Suppose metadata is read from A, F-58cc241cfb6b changes the head to B, and F-4c621b77f8a9 restores A. If A is present at the subsequent reread, A—not B—determines the successor-read address and the node argument to F-09c9a6de563d. Selection depends on the actual reread value, not replacement history.

8. **Self-linked selected node.**  
   If the selected node’s first word equals its own address when read, head replacement leaves that address in the slot. The decrement still occurs. Without later relevant mutation, inner-loop processing repeats; detachment and termination are not established.

9. **Zero count-like field.**  
   A nonzero head can reach the decrement even when field `0x20` is zero. There is no explicit underflow rejection. The arithmetic result and broader safety require additional platform and structural guarantees.
