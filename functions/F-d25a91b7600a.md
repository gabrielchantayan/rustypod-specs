## Behavior

### Initial decision

The function first reads a 32-bit integer at A plus 4 bytes and compares it with zero.

If the value is zero, the function returns `0xFFFFFFFF`. No deeper field is read on this branch. In particular, the contents or validity of any would-be linked object do not affect this branch because the function does not follow that link.

Every nonzero 32-bit pattern selects the lookup branch. A value with its high bit set is not rejected merely because a signed interpretation would make it negative. The decision is zero versus nonzero, not positive versus nonpositive.

### Address-chain lookup

After a nonzero initial observation, the supplied representation reads the field at A plus 4 bytes again. It does not visibly retain the value used for the branch decision.

The value from this second read supplies the base for an access 28 bytes later. That access obtains another 32-bit address-bearing value. The function then reads 32 bits at 4 bytes beyond that newly obtained address and returns those bits directly.

The source-level read order on this branch is therefore:

1. The discriminator at A plus 4 bytes.
2. The address-bearing field at the same location.
3. The next address-bearing field at an offset of 28 bytes from the second observation.
4. The final value at an offset of 4 bytes from the address obtained in the preceding step.

The latter accesses depend on earlier results. There is no visible retry, alternate lookup, range check, or recovery path.

The distinction between the first and second observations matters to the represented behavior. If the field changes after the nonzero decision, the later chain uses the second observation, not necessarily the first. There is no second zero check. A second observation of zero consequently leads toward an access at address 28 rather than toward the fallback return.
