# F-7d6ed32294de

## Purpose

F-7d6ed32294de performs a gated, ordered sequence of record processing, recursive relationship processing, conditional resource dispatch, reference clearing, and finalization calls.

“Teardown,” “owner,” “resource,” and “notification” describe inferred roles. The established behavior consists of the accesses, branches, and calls specified below. The supplied body does not establish that record storage is freed, that dependencies release memory, or that relationships are successfully removed.

Two independent gate calls control execution:

- The entry gate controls all target-record processing.
- The later gate controls only the resource-processing phase. Rejection by this gate does not skip common finalization or applicable final owner processing.

Descriptors supplied to several dependencies are **values read from global storage at their respective call sites**, not immutable constants captured on entry. Earlier calls may change those globals. In particular, the two resource dispatches read the same descriptor global separately and may receive different values.

This contract is based on static evidence only. No runtime tests have been performed.

## Behavior

### Entry gate and captured values

The routine first copies the fourth argument into local storage and calls F-3b037d560480 without explicit arguments.

If the gate returns zero, execution returns without visible target-field access or any subsequent dependency call. The gate itself may have side effects.

If the gate returns nonzero, the routine proceeds in this order:

1. Reads the 32-bit owner address from target +0x0c.
2. Reads the opaque 32-bit value from target +0x2c.
3. Calls F-07ea9a85c466 with the captured owner address, including when it is zero.
4. Sets the local control storage to zero.
5. Reads descriptor global D1 for a call to F-ebd0ee53699f with target +0x48, that descriptor value, and the target address.

The owner address and the value from +0x2c are snapshots. Later changes to those target fields do not replace the captured values.

D1 is read at this dispatch site, after F-07ea9a85c466 returns. Its value is not established by the state of global storage before that earlier call.

### Owner-associated processing

If the captured owner address is nonzero, the routine:

1. Reads the byte at owner +0x21 and writes it back with bit 0x40 set. Other bits from that read are preserved.
2. Repeatedly checks the 32-bit field at target +0x24.
3. For a nonzero check, reads target +0x24 again for a recursive invocation of F-7d6ed32294de, forwarding the second argument.
4. Repeats until a subsequent check reads zero.
5. Resets the local control storage to zero.
6. Reads descriptor global D2 and calls F-ebd0ee53699f with owner +0x54, the descriptor value, the captured owner address, and the target address.
7. Calls F-03b35c352059 with the target address.

The loop does not directly advance a cursor or clear target +0x24. Progress depends on recursive execution or other behavior changing the field. If recursive processing returns without changing a persistent nonzero reference, the loop may repeatedly process it. Cycles or repeated entry-gate rejection can prevent termination.

The loop condition and recursive argument use separate field reads. Their values coincide under stable storage; behavior under intervening concurrent mutation is not established.

D2 is read only when its dispatch is reached, after recursive processing finishes. It is not snapshotted before the recursive calls.

If the captured owner is zero, this entire phase is omitted, including all recursive processing of target +0x24.

### Conditional resource processing

This phase executes only if the second gate returns nonzero.

The routine initializes a 32-bit local control word to the second argument’s low eight bits shifted left by eight positions. The local storage has previously been set to zero on every path reaching this initialization. Consequently:

- Bits 8–15 contain the second argument’s low byte.
- Bits 0–7 and 16–31 are initially zero.
- The second argument’s higher bits do not contribute.
- A low byte of 0xff produces 0x0000ff00, without sign extension.

Resource processing then occurs in this order:

1. Check the 32-bit field at target +0x40. If nonzero, read that field for the resource argument, read descriptor global D4 for this call, and call F-1ecea458debe with the resource value, descriptor value, and address of the local control word. After normal return, write zero to target +0x40.
2. Check the 32-bit field at target +0x44. If nonzero, read that field for the resource argument, **read D4 again**, and call F-1ecea458debe with the resource value, newly loaded descriptor value, and the same local control-word address. After normal return, write zero to target +0x44.
3. Check the 32-bit field at target +0x3c. If nonzero, call F-2ff42e8572a4 without explicit arguments, then write zero to target +0x3c after normal return.
4. Call F-f20c359c7131 with the target address.
5. Call F-1dc7fdb390e6 with target +0xcc.
6. Call F-1dc7fdb390e6 with target +0x128.
7. Call F-dcc2e15850d5 with target +0x1b0.

These checks are sequential, not a snapshot of all three fields. The +0x40 dispatch may change the later +0x44 or +0x3c decisions.

The two resource calls share a **descriptor storage location**, not a guaranteed descriptor value. The first call may change D4. If the second call is reached, its load observes the global after the first call returns and after the explicit +0x40 clear. D4 is not read for a resource call whose field check is zero.

The control word is not reinitialized between resource dispatches. Mutations through its address during the first dispatch are available to the second. The supplied body does not establish permission to retain that local address after this invocation returns.

Each resource field check and its argument read are separate accesses. The evidence does not establish an ordering among the different argument reads within a single call expression.

Each explicit zero write follows its corresponding call. If that call replaces the same field, the subsequent write overwrites the replacement.

If the second gate returns zero, this entire phase is skipped. The routine does not itself clear these three target fields on that branch, although preceding dependencies may already have changed them.

## Acceptance examples

These are conditional criteria derived from static evidence, not observed executions. Unless stated otherwise, calls return normally and accessed storage remains valid.

1. **Entry rejection.** If the first gate returns zero, there are no target-field accesses or subsequent dependency calls from this routine. The gate’s own effects remain possible.

2. **Zero owner.** If the captured owner is zero, F-07ea9a85c466 still receives zero. Owner processing and recursion are skipped. Common processing, the second gate, and common finalization remain reachable.

3. **Recursive progress.** If a recursive invocation replaces target +0x24 with another address, the next loop check observes that replacement under stable storage. If it clears the field, the loop ends. Leaving a nonzero reference unchanged does not guarantee termination.

4. **Second-gate rejection.** A zero second-gate result skips resource processing but not the owner-reference comparison, F-c67cb20988a1, F-1137792fba7d, or applicable late owner processing.

5. **Control-word width.** A second argument of 0x123456ab initializes the word to 0x0000ab00. If the first resource call modifies it, the second eligible resource call receives the same storage with that modification.

6. **Resource descriptor mutation.** Suppose both resource fields remain eligible and D4 contains value A for the +0x40 dispatch. If that dispatch changes D4 to B, and nothing subsequently changes it before the second load, the +0x44 dispatch receives B, not A.

7. **Skipped descriptor load.** If +0x40 is zero, its resource dispatch and corresponding D4 load are omitted. An eligible +0x44 dispatch still reads D4 at its own call site.

8. **Sequential field visibility.** If the +0x40 dispatch clears +0x44, the later check skips its dispatch. If it replaces +0x44 with another nonzero value, that replacement is used under stable storage.

9. **Other descriptor timing.** If F-07ea9a85c466 changes D1, the following target-region dispatch uses the changed value, absent another intervening change. If the applicable F-83329683d376 call changes D6, the final owner dispatch likewise reads the changed value.

10. **Late owner decisions.** Equality at owner +0x3c causes a zero write; inequality does not. A set bit 0x02 at the final flags read suppresses F-83329683d376 but does not suppress the final owner dispatch.
