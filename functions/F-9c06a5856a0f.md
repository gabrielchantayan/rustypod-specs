# F-9c06a5856a0f

## Purpose

F-9c06a5856a0f conditionally writes a control value to a fixed global location and conditionally waits while bit 5 of that location remains set.

The second argument selects one of three behaviors:

- **Mode 1:** write the control value and return without polling.
- **Mode 2:** omit the control write and enter the polling path.
- **Every other mode:** write the control value, then enter the polling path.

The polling path terminates when either the observed control bit is clear or a dependency returns a nonzero result. These termination conditions are not distinguished in the function’s return value.

The interpretation of the location as a device command register, and of the polling dependencies as timing services, is inferred intent rather than an established interface guarantee.

## Interface

### Inputs

The function takes two integer arguments:

| Argument | Role | Relevant interpretation |
|---|---|---|
| First argument | Value used to construct the control write | Shifted left by six bit positions, then combined with the mask `0x20` using bitwise OR |
| Second argument | Mode selector | Compared for equality with 2 and, on the write path, with 1 |

The supplied representation uses integer arguments and a four-byte dependency result. The behavioral descriptions of numeric ranges below use a 32-bit integer model. Exact target language and ABI rules for signed shifts are not independently established.

The mode is not validated against a declared enumeration. Any value other than 1 or 2 follows the write-and-poll path, including negative values if representable by the argument type.

### Output

The function has no explicit return value.

A normal return does not report:

- Whether the control bit was observed clear.
- Whether the polling dependency returned nonzero.
- Whether any device operation completed successfully.
- How many polling iterations occurred.

No pointer argument, output buffer, or caller-owned memory region is exposed by the interface.

### Shared control location

The function accesses a global location at address `0x38400010`. This document calls it the **control location**.

The relevant operations use an integer view of that location and inspect mask `0x20`, corresponding to bit 5 when the least significant bit is numbered zero. The representation suggests a 32-bit access view, but does not independently establish physical bus transaction width, alignment behavior, endianness, or access atomicity.

A supplied annotation indicates that the global symbol overlaps smaller symbols at the same address. Consequently, the write must not be interpreted as affecting only an isolated logical flag. Other views of the same storage may observe changes.

## Behavior

### 1. Mode selection and optional control write

The mode check occurs before any dependency call.

If the mode is not 2, the function constructs a value from the first argument by shifting it left six positions and setting bit 5. It then assigns that value to the control location.

This assignment is a replacement write, not a read-modify-write that preserves existing control-location bits. The function does not first read the control location to merge its old contents with the new value.

For inputs whose shift is well-defined under the applicable integer rules:

- Bits 0 through 4 of the constructed value are zero.
- Bit 5 is set.
- Higher bits contain the shifted first argument.

Under a signed 32-bit interpretation, nonnegative first arguments from 0 through `0x01FFFFFF` can be shifted left six positions without exceeding the maximum positive signed value. Examples outside that range, and negative first arguments, require target-specific shift semantics before their write value can be contracted.

After the write:

- If the mode is 1, the function returns immediately.
- Otherwise, it proceeds to polling initialization.

If the mode is 2, the function skips both the control-value construction and the explicit control write, then proceeds to polling initialization. On this path, the first argument has no direct effect on the shown computation.

Skipping the explicit write does not guarantee that the control location remains unchanged: dependency calls may themselves affect shared state.

### 2. Polling initialization

Every polling path first calls dependency **F-d00000000001**, with no explicit arguments.

Its four-byte result is retained as an opaque token. The token is neither interpreted nor modified by this function. The same retained token is supplied to every subsequent invocation of the polling dependency.

This initialization happens before the first control-location read. Therefore, even when the control bit is already clear, entering the polling path still invokes F-d00000000001.

There is no visible check for a failed, invalid, null-like, or sentinel token value.

### 3. Control-bit observation

After initialization, the function reads the control location and tests bit 5.

If the bit is clear, the function returns immediately. In that case, no polling-dependency invocation follows that observation.

If the bit is set, the function calls dependency **F-d00000000002**, supplying:

1. The retained four-byte token.
2. The integer constant 100.

The meaning and units of 100 are not established. In particular, this document does not identify it as milliseconds, ticks, a retry count, or a duration.

### 4. Polling-dependency result

The polling dependency returns an integer result.

- **Zero:** the function repeats the control-location read and bit test.
- **Any nonzero value:** the function returns without another explicit control-location read.

Positive and negative nonzero results are treated identically. The function does not expose the result to its caller or distinguish a timeout-like outcome from an error-like outcome.

The control location is read again after each zero result. The function does not rely on a previously cached control value for subsequent iterations.

A nonzero dependency result takes precedence over any later control-location state because no subsequent read is performed by this function before returning.

### 5. Termination and nontermination

The visible logic has two polling exit conditions:

- An explicit read observes bit 5 clear.
- F-d00000000002 returns nonzero.

There is no explicit iteration limit, counter, delay operation, or independent timeout check in this function.

If every control read observes the bit set and every polling call returns zero, the loop continues indefinitely. If either dependency does not return, the function cannot progress beyond that call.

The supplied representation establishes no memory barrier, lock, interrupt mask, or other synchronization primitive around these operations. It does not establish how concurrent software or hardware updates become visible.

## Side effects

### Direct writes

Exactly one explicit control-location write occurs on modes other than 2, provided evaluation reaches and completes that write.

Mode 2 performs no direct write in the shown function.

The initial write sets bit 5. There is no explicit write that clears that bit, restores a previous value, or acknowledges completion during polling or on return.

### Direct reads

Mode 1 performs no explicit control-location read.

Every polling path performs its first explicit control-location read after F-d00000000001 returns. Additional reads occur only after a zero result from F-d00000000002.

The initial replacement write does not itself require an explicit read of the previous control value in the supplied representation.

### Dependency effects

Both dependencies may have side effects that are not described by the available evidence. Neither is assumed to preserve the control location or other global state.

This matters to ordering:

- Initialization may change the control bit before the first observation.
- A polling call may change it before the next observation.
- A nonzero polling result causes return even if that call leaves the bit set.

### Ownership and resource lifetime

The function shows no explicit allocation, deallocation, token release, or cleanup call.

The retained token is passed to the polling dependency but is not returned to the caller. Its four-byte representation does not establish whether it is a timestamp, handle, pointer encoding, counter, or other value.

No ownership transfer, borrowing rule, or release obligation can be inferred from this usage alone.
