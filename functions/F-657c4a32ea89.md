# F-657c4a32ea89

## Purpose

F-657c4a32ea89 traverses a linked structure using a comparison-like dependency. It then either returns a selected candidate address or delegates to F-550cd22693e0 and returns the contents of a private result slot.

The direct output consists of a 32-bit word and a one-byte discriminator. Discriminator 0 identifies the candidate-return path; discriminator 1 identifies a delegation path. Discriminator 1 does not independently establish successful allocation or insertion.

The structure resembles a sentinel-based ordered tree, and candidate adjustment resembles predecessor movement. These are inferred interpretations. The established contract is the field-access, branch, call, and write behavior below.

## Interface

### Arguments and output

The function takes three arguments:

| Argument | Established interpretation |
|---|---|
| Result-storage address | Destination for a 32-bit word at byte offset 0 and a one-byte discriminator at byte offset 4 |
| Container address | A 32-bit address-valued input used to locate the header, control flag, and comparison context |
| Supplied value | An opaque 32-bit value forwarded to dependencies |

There is no explicit return value. The meaningful direct result is written through result storage.

The result word is written before the discriminator. The discriminator write affects exactly one byte, not a 32-bit field. The function does not directly write result-storage offsets 5 and above; dependency effects and aliasing are separate concerns.

The supplied value is not directly dereferenced by this function. Its representation as a pointer, key, handle, or scalar is unknown.

### Relevant layout

All offsets are byte offsets. Address-valued fields and ordinary word fields are 32 bits.

| Object | Offset | Direct use |
|---|---:|---|
| Container | 0x10 | Header address |
| Container | 0x18 | One-byte control flag |
| Container | 0x19 | Address supplied as comparison context |
| Header | 0x04 | Initial search-node address |
| Header | 0x08 | Boundary word loaded on a conditional path |
| Record | 0x00 | One-byte value tested during candidate adjustment |
| Record | 0x04 | Parent-like address |
| Record | 0x08 | One child-like address |
| Record | 0x0c | Another child-like address |
| Record | 0x10 | Address supplied as an operand during search comparisons |

Passing container offset 0x19 or record offset 0x10 to a dependency does not establish the width of the object that dependency accesses there.

### Preconditions

Defined completion requires every address reached on the selected path to support the corresponding access. This includes writable result storage, readable container and header fields, and valid record relationships throughout any search or candidate adjustment.

A null initial search node is explicitly supported. Null container, header, or candidate addresses are not checked before their relevant accesses.

There is no explicit validation of alignment, address range, link consistency, or acyclicity. Address arithmetic uses the supplied 32-bit representation without explicit overflow handling. Behavior for invalid addresses, wrapped addresses, inaccessible memory, or malformed structures is not established.

## Behavior

### Initial reads and search

The remembered comparison outcome starts at the 32-bit value 1.

The function reads the container’s header address, then reads the initial search node from that header at offset 0x04. It separately reads the container’s header address again and uses this second value as the initial remembered record.

These are distinct header loads. Equality of their results is not enforced. If the initial search node is null, the remembered record remains the second-loaded header address.

For every nonnull search node:

1. Two private 32-bit words are set to zero.
2. F-31a0b2b5649a receives, in order:
   - The address at container offset 0x19.
   - The supplied value.
   - The current node’s address plus 0x10.
3. The current node becomes the remembered record.
4. The comparison result selects the next address:
   - Zero selects the word at node offset 0x0c.
   - Any nonzero value selects the word at node offset 0x08.

The selected link is read after the dependency returns. A dependency-induced link change can therefore affect traversal.

Zero is not an immediate match or termination condition. Search ends only when the selected node address is null. There is no depth limit or cycle detection.

The final remembered comparison outcome is the last dependency result, or 1 if no node was visited. Positive and negative nonzero results are treated identically.

### Control-flag decision

After search completes, the function reads the byte at container offset 0x18.

- A nonzero byte selects general delegation immediately.
- A zero byte selects candidate processing.

The flag is not captured before search. Changes made during search can affect this decision. Its semantic meaning, including whether it permits duplicates, is unknown.

### Candidate setup and boundary helper

Candidate processing initially places the remembered record into a writable private candidate slot.

If the remembered comparison outcome is zero, the boundary-helper call and structural adjustment are skipped. Processing proceeds directly to candidate conversion and final comparison.

If the remembered comparison outcome is nonzero:

1. The container’s header address is loaded again.
2. The word at that header’s offset 0x08 is loaded into one of the private 32-bit words.
3. F-eac694802fc1 receives the candidate-slot address and the boundary-word address.

Both arguments identify writable temporary storage. Subsequent processing uses the post-call candidate and, where applicable, the post-call boundary word. Neither is assumed preserved.

A nonzero helper result selects immediate delegation. A zero helper result selects candidate adjustment.

### Candidate adjustment: priority and movement

Adjustment starts from the candidate left by F-eac694802fc1.

The first branch has priority over both subtree descent and upward movement:

- Read the candidate’s first byte.
- Only if that byte is zero, read the candidate’s offset-0x04 address and then the word at offset 0x04 of that referenced record.
- If this second address equals the candidate, replace the candidate with its offset-0x0c link and end adjustment.

When this special branch is taken, the candidate’s offset-0x08 link is not consulted by the adjustment logic. The replacement applies whether that link would have been null or nonnull.

Only if the special branch is not taken does adjustment examine offset 0x08.

**Nonnull offset-0x08 link:** enter that linked subtree, then follow offset-0x0c links until a null link is encountered. The final record reached becomes the candidate.

**Null offset-0x08 link:** read the candidate’s parent-like address at offset 0x04. For each upward step:

- Compare the parent’s offset-0x08 word with the prior candidate.
- Replace the candidate with that parent regardless of the comparison result.
- Continue upward only when the comparison reported equality.

Thus the upward branch makes at least one parent transition. That statement applies only after the special branch has been excluded and the offset-0x08 link has been found null.

The body contains repeated link loads: offset 0x08 is loaded for the tentative descent address and loaded again for the null test; during subtree descent, offset 0x0c is loaded for the tentative next address and again for continuation testing. Under stable memory these reads agree. The body does not itself establish stability or synchronization.

### Candidate conversion and final comparison

After candidate setup or adjustment:

1. F-13c76c75fae4 receives the current candidate address.
2. Its 32-bit result becomes the second argument to F-31a0b2b5649a.
3. The first argument is the comparison-context address at container offset 0x19.
4. The third argument is the original supplied value.

The supplied value occupies the second position during search but the third position during this final comparison.

If the final comparison returns zero, the function writes the current candidate address to result-storage offset 0 and then writes discriminator 0 at offset 4. F-550cd22693e0 is not called on this path.

If the comparison returns nonzero, the function takes the general delegation path.

Calling this an equality check requires an external comparison contract and valid structural invariants. The direct body only establishes the zero/nonzero decision.

### Delegation paths

Both delegation paths call F-550cd22693e0 with:

1. A writable private 32-bit destination.
2. The container address.
3. A 32-bit zero argument.
4. The remembered record from the original search.
5. The supplied value.

The adjusted candidate is not substituted for the remembered record, including when the boundary helper has changed the candidate slot.

After normal return, the function reads the selected destination word, writes it to result-storage offset 0, and writes discriminator 1 at offset 4. It does not inspect a separate success or failure return from F-550cd22693e0.

The two delegation paths use different destinations:

| Delegation path | Destination and prior direct initialization |
|---|---|
| Immediate delegation after a nonzero boundary-helper result | Uses the first private word, reset to zero on every search visit; no direct initialization occurs on an empty search |
| General delegation after a nonzero control flag | Uses the second private word, reset to zero on every search visit; no direct initialization occurs on an empty search |
| General delegation after candidate comparison, without a boundary-helper call | Uses the second private word, reset to zero during search; this path necessarily follows a nonempty search |
| General delegation after a zero boundary-helper result and nonzero final comparison | Uses the second private word, previously loaded with the boundary word and exposed to the boundary helper |

These prior contents matter if the delegation leaves its destination unchanged. A determinate delegated result does not always require F-550cd22693e0 to write that destination. For example, after a nonempty search with a nonzero control flag, an unchanged destination that retains its initialized value produces result word zero and discriminator 1.

There is nevertheless no universal zero-initialized fallback. Some empty-search delegation paths have no direct destination initialization, and boundary-helper paths can carry a boundary-derived or helper-modified word into general delegation.

## Side effects

### Direct effects and ordering

The function directly modifies private temporary storage and the two output fields. It does not directly update container fields, relink records, allocate persistent memory, or free memory.

No direct result-storage write occurs before the selected processing and dependency calls complete. On every normally completing path, output writes occur in this order:

1. The 32-bit result word.
2. The one-byte discriminator.

Result storage is not checked for overlap with the container or records. If it aliases them, the direct writes still occur in this order, after all direct structural reads on that path. Broader safety under such aliasing is not established.

### Dependency effects and failure

Dependency calls may affect memory, container state, or globals. No purity or preservation guarantee is supplied.

Relevant ordering includes:

- Search-link reads follow each search comparison.
- The control-flag read follows all search comparisons.
- The conditional boundary load follows the flag decision.
- Candidate adjustment follows the boundary helper and uses its candidate value.
- Candidate conversion precedes the final comparison.
- Delegation precedes both output writes on delegation paths.

There is no explicit locking, rollback, exception handling, or cleanup. If a dependency fails to return normally, the normal-completion output contract does not apply. Partial dependency effects are not undone by this body.

### Ownership

No ownership transfer is established for the container, supplied value, candidate, or result word. Whether a returned word is borrowed, newly owned, reference-counted, or container-bound is documented_only.

Temporary addresses supplied to dependencies refer to private storage used during this invocation. The source supplies no contract authorizing retention of those addresses beyond their valid lifetime.

## Acceptance examples

These are conditional static examples, not runtime test results.

1. **Empty search, nonzero flag.**  
   No search comparison occurs. General delegation receives the second-loaded header as its remembered-record argument. If it writes word R and returns normally, output is R with discriminator 1. The direct body supplies no initialized destination fallback on this path.

2. **Nonempty search, nonzero flag, unchanged destination.**  
   The general-path destination has been reset to zero during the last search visit. If it remains zero until delegation and F-550cd22693e0 leaves it unchanged, output is zero with discriminator 1. A dependency write is not required for this result.

3. **Negative search-comparison result.**  
   A negative nonzero result selects offset 0x08, just like any positive nonzero result.

4. **Zero search-comparison result.**  
   Search follows offset 0x0c rather than returning immediately. If traversal then ends, the flag is zero, and the final candidate comparison returns zero, output is the remembered candidate with discriminator 0.

5. **Boundary helper returns nonzero.**  
   No candidate adjustment, conversion, or final comparison follows. Immediate delegation receives the original remembered record, even if the helper changed the candidate.

6. **Special adjustment branch overrides a nonnull subtree.**  
   Suppose the helper returns zero, the candidate’s first byte is zero, and its parent-like record’s offset-0x04 word equals the candidate. Adjustment selects the candidate’s offset-0x0c link even if its offset-0x08 link is nonnull.

7. **Special adjustment branch overrides upward movement.**  
   Under the same special-branch conditions, a null offset-0x08 link does not cause a parent transition. Adjustment selects offset 0x0c instead.

8. **Subtree descent after special-branch rejection.**  
   If the special branch is not taken and offset 0x08 is nonnull, adjustment enters that subtree and follows offset 0x0c links to the terminal record, assuming stable, valid links.

9. **Upward movement after special-branch rejection.**  
   If the special branch is not taken and offset 0x08 is null, adjustment moves to the parent at least once. It continues while each tested parent’s offset-0x08 word equals the prior candidate.

10. **Boundary word survives into delegated output.**  
    Suppose the boundary helper returns zero and leaves the boundary word B unchanged. If candidate processing reaches general delegation, no intervening effect changes that word, and delegation also leaves it unchanged, output is B with discriminator 1—not necessarily zero.

11. **Final comparison is nonzero.**  
    The candidate is not returned directly. General delegation receives the original remembered search record, and normal completion writes discriminator 1.
