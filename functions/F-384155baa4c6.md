# F-384155baa4c6

## Purpose

F-384155baa4c6 conditionally invokes three direct dependencies, then selects an ordered sequence of indirect calls using a character-sized discriminator in a mutable object.

Its established behavior is structural:

- An initial discriminator of 2 invokes a preparation dependency. A zero result selects two additional direct calls; a nonzero result selects one indirect call.
- The discriminator is reread after that handling. A value that remains 2 selects a two-call indirect sequence.
- Otherwise, separate discriminator tests select the two-call sequence for 1, the four-call sequence for 3, or no further calls.
- Each indirect target is obtained through the object’s current dispatch structure. In either sequence, the final target is explicitly resolved and saved **before** the final third-argument value is read.

“Preparation,” “notification,” and the argument labels below describe positions in this behavior. They do not establish application semantics such as rendering, logging, persistence, or successful state initialization.

## Interface

**Input:** one pointer to a mutable object.

**Output:** no explicit return value. The preparation dependency’s integer result controls a branch but is not returned to the caller. Results from the other calls are not used.

### Object and dispatch layout

The supplied representation accesses an integer-word-indexed object. Under its apparent four-byte integer-word model:

| Location | Representation and use |
|---|---|
| Object byte offset 0 | Integer word interpreted as a dispatch-table address |
| Object byte offset 0x18, decimal 24 | Integer word converted to a character-sized discriminator |
| Object byte offset 0x8B8, decimal 2232 | Integer word passed by value to two direct dependencies |
| Dispatch-table byte offset 0x58, decimal 88 | Indirect function target |

The two nonzero object offsets derive from word indices 6 and 558 multiplied by four bytes. The dispatch offset is a byte offset, not a word index.

This is an apparent 32-bit representation, not independently supplied ABI documentation. Pointer width, calling convention, alignment, and endianness remain unresolved beyond what this representation implies.

The discriminator tests apply after conversion to a character-sized value, rather than comparing the complete integer word. Under the apparent eight-bit truncating character model, only the low eight bits determine equality with 1, 2, or 3. Signed versus unsigned eight-bit interpretation does not change equality with these three positive values. Broader language-level conversion guarantees are not established independently.

### Temporary storage

The function provides the preparation dependency with the address of a 40-byte automatic buffer.

- The visible body does not initialize the buffer.
- It does not inspect the buffer after the call.
- The buffer remains local to this invocation, and its lifetime ends when the invocation returns.
- No supplied dependency contract establishes permitted writes, required initial contents, or whether the address is retained.

The absence of visible initialization is not proof that the dependency accepts arbitrary initial contents.

### Indirect-call arguments

Every indirect call receives the original object pointer followed by two data arguments. The following labels identify static-data sources or entry-captured values without assigning application meaning:

| Label | Role |
|---|---|
| **E** | Four-byte value captured first at entry; used for the nonzero-result notification and the first three calls of the four-call sequence |
| **T** | Four-byte value captured second at entry; used for the final call of either sequence |
| **Failure** | Third argument of the nonzero-result notification |
| **Common class** | Second argument of the first call in the two-call sequence |
| **Common first** | Third argument of that first call |
| **Common final** | Third argument of the final call in the two-call sequence |
| **Three first**, **Three second**, **Three third** | Third arguments of the first three calls in the four-call sequence |
| **Three final** | Third argument of the final call in the four-call sequence |

These labels refer to distinct backing locations, not necessarily distinct runtime values.

The representation explicitly retains **E**, **T**, and the selected final third argument in four-byte storage. The semantic types of all these values are unknown. In particular, none is established to be a string, pointer, identifier, or ownership-bearing handle. The declarations and independent widths of the other static-data sources are not supplied.

## Behavior

### Entry reads

Before testing the discriminator, the function reads and retains **E**, then reads and retains **T**.

Later uses of these two values use the entry captures. Changes to their backing locations during a dependency call do not refresh them.

The remaining static-data arguments are obtained later, at the relevant call sites. The final argument sources have an additional established ordering relative to dispatch resolution, described below.

### Initial discriminator equal to 2

When the initial discriminator test yields 2, invoke **F-bfda5fbfe0b0** with:

1. The original object pointer.
2. The address of the 40-byte automatic buffer.
3. The current integer word at object offset 0x8B8.
4. The integer constant 3.

The object word is passed by value. This argument does not expose the address of that field, although the object pointer separately permits whatever object access the dependency performs.

The returned integer is tested for equality with zero. All nonzero values select the same branch.

**Zero result:**

1. Invoke **F-97a072757e44** with the object pointer.
2. After that call returns, read the object word at offset 0x8B8 again.
3. Invoke **F-52cae007644e** with the object pointer and the newly read word.

The field value supplied to F-52cae007644e need not equal the value previously supplied to F-bfda5fbfe0b0. Either preceding dependency may have changed it.

**Nonzero result:**

Resolve an indirect target through the current object dispatch reference and slot 0x58, then invoke it with:

1. The original object pointer.
2. Captured **E**.
3. The **Failure** value obtained for this call.

Neither F-97a072757e44 nor F-52cae007644e is called on this branch.

After either branch returns normally, reread the discriminator:

- If it equals 2, select the two-call sequence.
- If it does not equal 2, continue to the discriminator-1/discriminator-3 selection.

The preparation result alone does not determine the final sequence, and a nonzero result does not cause immediate return.

### Discriminator-1/discriminator-3 selection

This selection is reached when the initial discriminator is not 2, or when the post-preparation discriminator is no longer 2.

Read the discriminator to test for 1:

- A value of 1 selects the two-call sequence.
- Otherwise, perform another discriminator evaluation to test for 3.
- A value of 3 on that evaluation selects the four-call sequence.
- Otherwise, return without further calls.

These are separate evaluations in the supplied representation. No volatile, atomic, or synchronization semantics are established, and separate source-level evaluations do not by themselves prove distinct machine loads.

### Two-call sequence

The argument order is:

| Call | Second argument | Third argument |
|---|---|---|
| First | Current **Common class** | Current **Common first** |
| Final | Captured **T** | **Common final**, read after saving the final target |

Both calls receive the original object pointer as their first argument.

For the first call, resolve the target from the object’s dispatch reference and slot 0x58 and obtain its data arguments for that call. The supplied representation does not impose a total order among the independent reads within that call expression.

After the first call returns, the final call has this explicit ordering:

1. Read the current dispatch reference and its slot 0x58, and save the resulting target.
2. Read and retain **Common final** as a four-byte value.
3. Invoke the saved target with the original object pointer, captured **T**, and the retained **Common final** value.

The final target is not resolved again after reading **Common final**. The target-resolution-before-data-read order is established by separate statements, not left to argument evaluation order.

The first call may change the dispatch reference or slot used for the final target resolution. There is no discriminator check between the two calls. Once selected, a discriminator change during the first call does not cancel the final call.

### Four-call sequence

The argument order is:

| Call | Second argument | Third argument |
|---|---|---|
| First | Captured **E** | Current **Three first** |
| Second | Captured **E** | Current **Three second** |
| Third | Captured **E** | Current **Three third** |
| Final | Captured **T** | **Three final**, read after saving the final target |

All four calls receive the original object pointer as their first argument.

For each of the first three calls, resolve the target through the then-current object dispatch reference and slot 0x58. Obtain that call’s third argument at its own call site. Earlier calls can therefore affect later targets and later argument values.

After the third call returns, the final call has this explicit ordering:

1. Resolve and save the current target through the object and slot 0x58.
2. Read and retain **Three final** as a four-byte value.
3. Invoke the saved target with the original object pointer, captured **T**, and the retained **Three final** value.

There is no second target lookup between the **Three final** read and invocation. The final target resolution precedes that data read.

No discriminator test occurs inside the selected sequence. State changes during its first three calls do not suppress the remaining calls.

### Ordering boundaries

Established ordering includes:

- The **E** capture before the **T** capture, both before discriminator testing and calls.
- The stated order of all separate calls.
- The fresh offset-0x8B8 read after F-97a072757e44 returns.
- The final target capture before the final third-argument read in both indirect sequences.
- Invocation of that saved target after the final third-argument read.

The supplied representation does not establish a total machine-level ordering among independent reads contained within other individual call expressions. This limitation does **not** apply to the explicit, separate final-target and final-data reads.

## Side effects

The visible body performs no explicit assignment to an object field or static-data location. It captures values locally and delegates observable effects to callees.

Possible callee effects are not constrained by the supplied evidence. They include:

- Changes to the discriminator, offset-0x8B8 word, dispatch reference, or dispatch slot.
- Changes to static-data sources read by later calls.
- Writes to the automatic buffer.
- External effects, allocation, release, or ownership changes.

The function itself has no explicit heap allocation or release. This does not establish that callees preserve memory ownership.

For defined normal execution, the object must remain valid for each subsequent access. Dispatch references and targets must likewise be valid whenever resolved or invoked. A saved target must remain callable through its later invocation; saving it does not provide a lifetime guarantee. The visible function provides no protection against a callee invalidating the object or dispatch structures.

There are no visible null checks, bounds checks, target validation, error recovery, exception handling, or rollback. A nonzero preparation result selects an indirect notification and then continued state selection; it is not propagated as a return value.

All stated complete sequences assume every invoked callee returns normally. Effects of a fault, exception, or nonreturning call are not established.

## Acceptance examples

These are conditional expectations from static evidence, not executed tests.

1. **Stable discriminator 1.**  
   With valid storage and normally returning callees, discriminator evaluations that select 1 produce exactly the two-call sequence. None of the three direct dependencies is invoked.

2. **Stable discriminator 3.**  
   The indirect argument pairs are **E/Three first**, **E/Three second**, **E/Three third**, then **T/Three final**. Each call resolves its own target. The last resolution occurs before reading **Three final**.

3. **Stable unrelated discriminator.**  
   If all relevant evaluations yield 0, the function captures **E** and **T**, makes no calls, and returns. Other stable values outside 1, 2, and 3 behave likewise.

4. **Initial 2, zero result, state remains 2.**  
   The order is F-bfda5fbfe0b0, F-97a072757e44, F-52cae007644e, and the two-call sequence. Only the first dependency receives the temporary-buffer address.

5. **Changed field during preparation handling.**  
   If preparation receives field value A and F-97a072757e44 leaves the field containing B, F-52cae007644e receives B, provided the later read observes B.

6. **Initial 2, nonzero result, transition to 3.**  
   If the notification returns and the following tests select 3, the notification is followed by four indirect calls: five indirect calls total. Neither zero-result-only dependency runs.

7. **Post-preparation unrelated state.**  
   If the post-handling tests consistently observe 4, neither final sequence runs. Already completed preparation-side effects remain observable.

8. **Dispatch replacement during a sequence.**  
   If the first call of the two-call sequence installs a different valid dispatch target, the final target resolution uses that replacement. A concurrent discriminator change by that call does not cancel the final call.

9. **Two-call final-read order.**  
   After the first call returns, the required order is final target resolution and capture, **Common final** read, then invocation of the captured target. Resolving the target only after reading **Common final** would not match the supplied behavior.

10. **Four-call final-read order.**  
    After the third call returns, the required order is final target resolution and capture, **Three final** read, then invocation of that captured target. Re-reading the dispatch slot after the data read is not part of this sequence.

11. **Captured versus later-read data.**  
    A callee’s change to the backing location for **T** does not change the final call’s captured second argument. A change to **Common final** or **Three final** before its designated read can affect the final third argument.

## Uncertainties

The following remain **documented_only**:

- Exact ABI, pointer width, alignment, endianness, and character-conversion guarantees beyond the apparent representation.
- Static-data contents, semantic types, and independently unspecified widths.
- Application meaning of discriminator values, data arguments, and the offset-0x8B8 field.
- Preparation-result meanings beyond the zero/nonzero distinction.
- Buffer initialization requirements, write extent, and address-retention behavior.
- Callee effects on globals, dispatch structures, ownership, and external state.
- Thread safety, reentrancy, synchronization, and correspondence between source-level evaluations and machine loads.
- Invalid-pointer, fault, exception, and nonreturning-call behavior.
- Relative ordering of independent reads within individual call expressions where no separate statements establish an order.

The last uncertainty excludes the final target-before-data ordering in both sequences, which is established.

**Inferred intent:** the function appears to perform state-2 preparation and then emit state-dependent indirect-call sequences. No acceptance condition depends on that interpretation.

## Evidence

Established static evidence consists of the supplied function representation: entry captures, discriminator conversions and branches, three direct dependencies, a 40-byte automatic buffer, repeated dispatch-slot access, and absence of explicit object-field or global assignments.

In particular, each indirect sequence explicitly captures its final dispatch target in one statement, reads its final third-argument value in a subsequent statement, and then invokes the captured target. That ordering is part of the contract, not an unspecified aspect of call-expression evaluation.

Layout offsets depend on the apparent four-byte integer-word model. Dependency semantics, static-data meanings, and independent ABI details were not supplied.

No runtime observations or runtime tests have been performed.
