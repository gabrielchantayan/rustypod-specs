# F-f1674f0b4231

## Purpose

F-f1674f0b4231 obtains a result-storage address, classifies a cursor-like value, and performs one of three branches:

- Classification **1** passes temporary storage to a dependency, reads two 16-bit values from that storage, publishes them to result storage, and calls another dependency with the temporary’s address.
- Classification **24** prepares resource representations, invokes a receiver operation, and conditionally submits a descriptor with a requested count of **65,536**.
- Any other classification calls an error dependency with category **2**, code **5**, and a payload read from a global at that point.

On the classification-24 branch, a zero tested resource field, a nonzero receiver return, or a submission return other than exactly 65,536 selects category **2**, code **11**, payload **0**.

“Cursor,” “resource,” “descriptor,” and “submission” describe how values are used. They do not establish parsing rules, allocation, transfer direction, ownership, initialization, or release semantics.

## Interface

### Arguments and return

The function accepts three arguments and has no explicit return value.

| Argument | Established representation and use |
|---|---|
| Result context | A 32-bit value passed to F-603a53835f04 with three zero arguments. The returned address is retained for result operations. |
| Receiver reference | Address of a 32-bit word containing a receiver-object address. Passed unchanged to F-10dc70ffafa7; dereferenced for receiver dispatch on classification 24. |
| Interface object | Object address whose first 32-bit word supplies a dispatch-table address. Operations at table byte offsets **8** and **16** are used. Also passed to F-10dc70ffafa7. |

The supplied representation uses 32-bit addresses and integer values. Compatibility with wider-pointer environments is not established.

### Result storage

The address returned by F-603a53835f04 is used as follows:

- Classification 1 directly writes 16-bit values at byte offsets **0** and **2**, in that order.
- An exact-count submission result causes a call to F-8450167df120 with the address.
- Error paths call F-7f008c1060db with the address and an error tuple.

Obtaining this address does not establish initialization. The complete result layout and the effects of the result-related dependencies are unknown.

### Preconditions and temporary storage

Normal continuation requires valid access to every address used on the selected path. These include object and dispatch-table addresses, result storage, cursor byte offset 2, resource fields at offsets 4 and 8, and receiver-related addresses when receiver dispatch is reached.

On classification 1, the function passes temporary storage to F-10dc70ffafa7 and subsequently reads two adjacent 16-bit values from it. The function does **not** directly initialize those values. Valid subsequent reads are a prerequisite on the caller/dependency environment, not evidence that F-10dc70ffafa7 writes or initializes the temporary.

Likewise, other dependency-provided representations must support the reads subsequently performed. Their initialization guarantees are not supplied.

Resource field reads precede resource-address null checks. Consequently, the later checks do not establish safe handling of a null resource-construction return.

Temporary-storage addresses are exposed to dependencies during the invocation. Permission to retain them, and validity after this invocation, are not established.

## Behavior

### Result acquisition and classification

The initial sequence is:

1. Call F-603a53835f04 with the result context and three zeros; retain its returned address.
2. Invoke D-02 through the interface object’s dispatch table at byte offset **8**, passing the interface object.
3. Store its 32-bit return in mutable temporary cursor storage.
4. Call F-22959c398a0b with the cursor-storage address and arguments **1**, **0**, **5**.
5. Branch on the classifier’s return.

Because F-22959c398a0b receives the cursor-storage address, later cursor reads use the value then stored there. They need not use D-02’s original return.

### Classification 1: delegated temporary and publication

The function calls F-10dc70ffafa7 with:

- The address of temporary storage.
- The receiver reference.
- The interface object.
- The cursor-storage address.

There is no intervening success test after this call. If it returns normally, the function:

1. Reads a 16-bit value from the temporary’s beginning and writes it to result offset **0**.
2. Reads the adjacent 16-bit value at temporary offset **2** and writes it to result offset **2**.
3. Calls F-9b718979506d with the temporary’s address.
4. Returns if that dependency returns normally.

Both result writes precede F-9b718979506d. The first read/write pair precedes the second read/write pair.

These are native 16-bit accesses, not an established byte-order-independent serialization. The source shows the temporary’s address being passed and its contents later read; whether F-10dc70ffafa7 initializes, modifies, or leaves that storage untouched remains unknown. F-9b718979506d’s ownership and release behavior are also unknown.

### Unsupported classifications: late global payload

For any classification other than **1** or **24**, the function calls F-7f008c1060db with:

- The retained result-storage address.
- Category **2**.
- Code **5**.
- A payload obtained from a global read while forming this call.

The global read occurs after result acquisition, D-02 dispatch, and classification. It is not an entry-time snapshot. Earlier dependencies may have changed the global; no preservation guarantee is supplied.

The global’s declaration, storage width, value, and mutability guarantees are unknown. It must not be treated as a fixed constant, known address, or static message.

After the error dependency returns normally, the function returns. No classification-24 resource preparation occurs.

### Classification 24: large-resource preparation

The function performs these operations in order:

1. Call F-8157a180d901 with **16**.
2. Call F-a19af7977535 with that return, **1,048,576**, and **3**.
3. Read the returned resource’s 32-bit field at byte offset **8**.
4. Read its 32-bit field at byte offset **4**.
5. Form a two-word temporary whose first word is the offset-4 value and whose second word is the offset-8 value.
6. Call F-32f6272d7d46 with an output-storage address and the field-pair address.

The output storage’s first 32-bit word is subsequently used as a receiver argument and as a base-like value for region selection. The construction arguments alone do not prove an accessible allocation of the requested extent.

### Cursor sampling and parser calls

After the first F-32f6272d7d46 call, the function:

1. Reads an unsigned byte at offset **2** from the current stored cursor address.
2. Calls F-28377ed279d9 with the cursor-storage address and **3**.
3. Calls it again with that address and **3**.
4. Calls it again with that address and **6**.

The three returns are 32-bit values. Whether the arguments 3, 3, and 6 represent lengths, widths, selectors, or something else is unknown.

Only after these calls does the function freshly read the large resource’s 32-bit offset-4 field and compare it with zero. The test does not reuse the earlier copied value. Intervening dependencies are not assumed to preserve the field.

A zero fresh value selects category **2**, code **11**, payload **0**, followed by shared large-resource cleanup. The initial byte read and all three parser calls therefore occur even when this test fails.

### Receiver dispatch and packed arguments

If the fresh field is nonzero, the function writes **1,048,576** into a temporary 32-bit word before receiver dispatch. The temporary’s address is not visibly passed to that operation; the assignment’s purpose is unknown.

D-03 is resolved through the receiver object’s dispatch table at byte offset **108**. It receives the receiver object followed by four 32-bit arguments:

1. The first word of the earlier F-32f6272d7d46 output.
2. The initially sampled byte shifted right by four bits.
3. A combination of that entire byte and part of the first parser return.
4. A combination of the second and third parser returns.

Let \(b\) be the initially sampled unsigned byte and \(x,y,z\) the successive parser-return bit patterns. The three derived arguments are represented by:

\[
b \gg 4
\]

\[
(b \ll 8)\;|\;((x \mathbin{\&} \mathrm{0x00ffffff}) \gg 16)
\]

\[
((z \gg 8) \mathbin{\&} \mathrm{0xff00ffff})\;|\;(y \ll 16)
\]

The second expression places the entire byte \(b\) in bits 8–15 and bits 16–23 of \(x\) in bits 0–7. The third uses an unsigned right shift of \(z\); the mask leaves original bits 8–23 of \(z\) in the low 16 result bits. The low 16 bits of \(y\) contribute the upper half under the represented bit-pattern interpretation.

The supplied representation treats \(y\) as signed. This relationship does not establish portable signed-left-shift behavior for all inputs.

Any nonzero D-03 return selects category **2**, code **11**, payload **0**, followed by shared large-resource cleanup. Only a zero return enables selected-region preparation.

### Selected-region preparation

After a zero receiver return, the function rereads the unsigned byte at offset **2** from the **current** stored cursor address.

This read occurs after all three parser calls and receiver dispatch. Neither the cursor address nor its contents are assumed unchanged. This new byte, rather than the initial sample, selects the region. It is sampled before the subsequent small-resource dependencies.

The function then:

1. Calls F-8157a180d901 with **16**.
2. Calls F-a19af7977535 with that return, **65,536**, and **3**.
3. Reads the new resource’s 32-bit offset-8 field, then its offset-4 field.
4. Forms another two-word temporary, offset-4 value first and offset-8 value second.
5. Calls F-32f6272d7d46 with a second output-storage address and that pair’s address.

D-01 receives:

- The first 32-bit word of the second output area.
- The first word of the earlier large-resource output area plus a selected offset.
- Count **65,536**.

For the newly sampled byte \(s\):

\[
\text{offset}=(s \mathbin{\&} 15)\times 65{,}536
\]

The selected offset ranges from **0** through **983,040**. If the base denotes an accessible contiguous 1,048,576-byte region, every selected 65,536-byte interval fits within it. That extent is a conditional prerequisite, not a proven construction effect.

The base addition uses represented 32-bit operands. No overflow or bounds check is visible. Portable wraparound semantics must not be inferred from the signed-looking address arithmetic.

No D-01 return-value check is visible. Its memory effects and transfer direction are unknown.

### Descriptor submission and result selection

After D-01, the function copies a **13-byte** representation from the second output area to separate temporary storage:

- A 32-bit copy at offset **0**.
- A 32-bit copy at offset **4**.
- A 32-bit copy at offset **8**.
- A one-byte copy at offset **12**.

These copies occur in that order. There is no intervening dependency call.

D-04 is then invoked through the interface object’s dispatch table at byte offset **16**, with:

- The interface object.
- Count **65,536**.
- The copied descriptor’s address.

A return exactly equal to **65,536** selects F-8450167df120 with the result-storage address. Every other return selects F-7f008c1060db with category **2**, code **11**, payload **0**.

There is no retry, partial-count accumulation, or separate negative-return branch.

### Cleanup and termination

After the submission’s result operation returns normally:

- If the small-resource address is nonzero, call F-de99289388aa with it, then call F-feee9156a257.
- Otherwise, proceed to shared large-resource cleanup.

Shared cleanup returns if the large-resource address is zero. Otherwise it calls F-de99289388aa with that address, followed by F-feee9156a257.

The supplied representation marks F-feee9156a257 as non-returning. Under that property, nonzero small-resource cleanup does not continue to large-resource cleanup. The function must not be described as unconditionally cleaning up both resources.

The calls themselves do not establish release, destruction, exception propagation, or process termination semantics.

## Side effects

Established direct effects include:

- Two ordered 16-bit result writes on classification 1.
- Reads through object, dispatch-table, cursor, resource, and temporary-storage addresses.
- The unsupported-classification global read when forming the error call.
- Writes to temporary cursor storage, resource-field pairs, the pre-dispatch extent word, and copied descriptor storage.
- Calls to the listed dependencies.

**Delegated-result storage is not an established direct-write destination.** The function passes its address to F-10dc70ffafa7 and later reads two 16-bit values. Any initialization or modification by that dependency is unknown. Valid reads remain an execution prerequisite, not proof of a dependency write.

D-01 receives two address-like values and a count, but its effects are unknown. D-04 receives temporary descriptor storage, but whether it reads, modifies, consumes, or retains it is unknown.

No unknown dependency is assumed to preserve globals or previously exposed storage. No ownership transfer or memory release is established.

No exception handler, rollback, or invalid-access recovery is visible. Abnormal completion prevents the subsequent normal-continuation operations described above.

## Acceptance examples

These are conditional static criteria, not executed tests. They assume valid accesses and normal dependency returns except where stated.

1. **Delegated publication without an initialization claim.** If classification is 1 and the subsequent valid temporary reads yield 0x1234 and 0xabcd, result offsets 0 and 2 receive those values in order, before F-9b718979506d. This criterion does not require or establish that F-10dc70ffafa7 wrote them.

2. **Late global payload.** If classification is 7 and an earlier dependency changed the global, the error call uses the value read after classification, not a presumed entry-time value. Category is 2 and code is 5. Resource preparation does not occur.

3. **Fresh field test.** If the initially copied offset-4 field is nonzero but the later read is zero, all three parser calls still occur. Receiver dispatch does not occur; category 2, code 11, payload 0 is selected.

4. **Receiver rejection.** Any nonzero D-03 return prevents small-resource preparation and descriptor submission. It selects category 2, code 11, payload 0.

5. **Changed selector.** If the initial byte is 0xa2 and the later byte is 0x3f, the receiver’s shifted-byte argument is 10. Region selection instead uses index 15 and offset 983,040.

6. **Packed arguments.** For initial byte 0xa2 and parser bit patterns 0x00123456, 0x00005678, and 0xabcdef12, the three derived receiver arguments are 0x0000000a, 0x0000a212, and 0x5678cdef.

7. **Exact count only.** A D-04 return of 65,536 selects F-8450167df120. Returns of 65,535, zero, or a negative signed value select category 2, code 11, payload 0.

8. **Non-returning cleanup.** If the small-resource address is nonzero and F-feee9156a257 does not return, no subsequent large-resource cleanup is observable in this invocation.
