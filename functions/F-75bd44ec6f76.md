# F-75bd44ec6f76

## Purpose

F-75bd44ec6f76 repeatedly invokes indirect dependencies, performs interleaved byte and 32-bit memory accesses, and carries calculated state into the next iteration. Dependency results determine later arguments, addresses, and stored values.

The supplied static body has an unconditional loop and no normal return. This does not guarantee endless execution: a dependency may fail to return, or a memory access may prevent further progress.

No application-level purpose is established. The visible operations do not establish allocation, object initialization, serialization, or device configuration.

This contract describes the represented behavior conditionally on each preceding dependency returning and each required memory access succeeding. No runtime tests have been performed.

### Widths and notation

The following notation describes the apparent bit-level dataflow:

- \(S_n(x)\): shift the low 32 bits of \(x\) left by \(n\), retaining only 32 bits.
- \(B(x)\): retain the low eight bits.
- \(\operatorname{lo}(x)\), \(\operatorname{hi}(x)\): low and high 32-bit halves of an apparent 64-bit result.
- \(E(x)=((x\mathbin{\&}\text{0x3fffffff})\gg20)\), with a logical right shift.
- All other right shifts below are logical shifts of 32-bit words.

Products and address sums are interpreted modulo \(2^{32}\) for this contract’s width-based calculations. This captures the apparent machine-width relationships; it is not a guarantee about portable signed arithmetic.

A **selector write through address \(a\)** means: read an unsigned byte at \(a+1\), zero-extend it, then write one byte at that value plus 17. Its destination lies between addresses 17 and 272 inclusive. It is not a pointer-sized indirection.

A **direct write** uses the stated calculated address without a selector read.

## Behavior

### Invocation conventions

Opaque IDs F-D01-01 through F-D26-07 identify call occurrences, not proven distinct dependency functions. The first number identifies a group; the second identifies a position within it.

Three invocation forms describe the ordering:

- **Five-call form:** the first call receives the stated arguments; four calls with no explicit arguments follow. The fifth supplies the group result.
- **Bridge form:** the first call receives the stated initial arguments; the second has no explicit arguments and supplies an intermediate 32-bit word; the third receives that word and any stated companion argument; four calls with no explicit arguments follow. The seventh supplies the group result.
- **Split form:** the first call receives the stated initial arguments; the second supplies an intermediate word; the third receives that word and any stated companion argument; the fourth supplies an apparent 64-bit result; the fifth receives its low half followed by its high half; two calls with no explicit arguments follow. The seventh supplies the group result.

“No explicit arguments” does not establish absence of register, stack, global, or memory inputs. Unused explicit results do not make calls removable.

The labels \(V_1\) through \(V_{26}\) below denote group results, not source identifiers. Unless a split result is specified, a consumed result is treated as a 32-bit word.

Each group completes before its listed memory effects. Those effects complete in order before the next group begins.

## Acceptance examples

These are conditional static examples, not executed tests.

1. **Byte truncation.** If \(V_1=65\) and the first selector is 7, the post-Group-1 write stores byte value 4 at address 24: the shifted word is 260, whose low byte is 4.

2. **Fresh and cached selectors.** If the first selector is 7 and Group 2 changes it to 9, the first two byte destinations are 24 and 26. The post-Group-3 word destination is 29, even if Group 3 subsequently changes the selector.

3. **Global snapshot timing.** If the captured global word is `0x00400000`, the post-Group-4 byte value is 1 even if Group 4 clears the global, provided execution reaches that store.

4. **Second-payload relationship.** If \(V_{11}=1\), second payload is 16384, and the post-Group-13 word destination is 16404.

5. **Zero argument without call elimination.** Group 14’s third call receives zero as its first explicit argument for every \(V_{11}\). Its additional register argument and side effects remain relevant and undocumented.

6. **Repeated clearing.** If Group 24 makes next base plus one nonzero, the second clearing pair first clears next base plus 17, then clears next base plus one.

7. **Final high-bit store.** The post-Group-25 stored word is zero for even \(V_{22}\), and `0x80000000` for odd \(V_{22}\), under the 32-bit model.

8. **Restricted next base.** The low two bits of \(V_{21}\) select next base from `0x00000000`, `0x40000000`, `0x80000000`, and `0xc0000000`.

9. **Iteration completion is not function completion.** Reaching the final zero-word store leads to another iteration. A complete iteration that reaches every call contains 146 invocations, not a normal return.
