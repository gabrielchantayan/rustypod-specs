# F-6e6f079a0945

## Purpose

F-6e6f079a0945 conditionally updates a state object obtained from a dependency. It has three observable paths:

- If no state object is returned, it exits without invoking the second dependency or directly accessing object storage.
- If a second dependency returns a value other than the 32-bit sentinel −1, it stores that result’s low byte and the caller’s second argument into two separate object fields.
- If the second dependency returns −1, it reads the object’s first 32-bit word and replaces that word with 0x00000500 only when the value read is zero.

The supplied representation establishes these branches and direct memory effects. It does not establish the application-level meanings of the object, the stored byte, the second argument, or the first-word value 0x00000500.

This contract distinguishes direct actions of F-6e6f079a0945 from effects of its dependencies. Neither dependency’s internal behavior is available.

## Behavior

### 1. Obtain the object

If that dependency returns a null address, F-6e6f079a0945 immediately returns:

- F-38ffb5fafd28 is not called.
- Neither input is directly written to object storage.
- No direct object-field read or write occurs.

Effects performed inside F-7fba0909c452 are not excluded by this early return.

If the address is non-null, the function retains that address for later accesses. It does not call F-7fba0909c452 again.

### 2. Obtain the decision value

With a non-null object address, the function calls F-38ffb5fafd28 with the first argument.

The returned value is compared with −1 as a full 32-bit integer. The sentinel corresponds to the bit pattern 0xFFFFFFFF. The comparison occurs before any narrowing to one byte.

Consequently, a value whose low byte is 0xFF is not necessarily the sentinel. For example, 0x000000FF takes the non-sentinel path, whereas 0xFFFFFFFF takes the sentinel path.

There is no second object-address lookup or validity check after this call. Later accesses use the address obtained before it.

### 3. Non-sentinel result

If the result is not −1, the function performs these direct writes in order:

1. It writes the result’s low eight bits to the byte at object offset 0x9C9.
2. It writes the second argument’s complete 32-bit bit pattern to the field at offset 0x9CC.

It then returns.

There is no direct read of either destination before these writes. There is no direct read or write of the first object word on this path.

The one-byte conversion discards the upper 24 result bits. It is not saturation, clamping, or a range check. Values differing only above bit seven therefore produce the same stored byte, provided neither is the full-width sentinel.

The two stores are separate operations. The representation provides no transaction or rollback if the first store succeeds and the second cannot complete.

### 4. Sentinel result

If the result is −1, the function reads the first 32-bit word at the retained object address.

- If the value read is zero, it writes 0x00000500 to that same word.
- If the value read is nonzero, it performs no direct write.

It then returns.

The byte at 0x9C9 and the field at 0x9CC receive no direct writes on this path. The second argument is not used to update the object.

The zero test uses the word read after F-38ffb5fafd28 returns. It is not based on an earlier snapshot. If that dependency changed the word, the changed value is the one examined, assuming the retained address is still valid.
