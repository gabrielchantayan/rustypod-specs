# F-d37fc1934c72

## Purpose

F-d37fc1934c72 performs address-derived memory reads and writes, invokes six indirect call sites, and ends at a represented bad-instruction termination marker. No application-level purpose, normal return, success result, or error-reporting protocol is established.

The supplied static representation includes small computed addresses, a shift by the nominal operand width, signed arithmetic with possible overflow, and indirect destinations whose executable validity is unknown. This contract preserves those operations rather than substituting safer behavior.

Three evidence levels apply throughout:

- **Established static evidence:** access widths, arithmetic expressions, explicit call destinations or destination derivations, ordering, and the single conditional write shown in the supplied representation.
- **Conditional interpretation:** numeric consequences under explicitly stated arithmetic, address, and execution assumptions.
- **documented_only:** behavior not resolved by the supplied material.

No runtime tests have been performed.

## Behavior

### Initial writes and retained snapshots

The routine first multiplies incoming register 6 by 512. It stores the low 16 bits of that product at the numeric product plus 8 bytes.

It then writes the stack-supplied halfword from offset `0x260` at the incoming register-3 address plus 2 bytes. Next, it reads a 32-bit word from the address obtained by multiplying incoming register 6 by 2,097,152. This word is retained for later use.

After that read, a 16-bit zero is stored 32 bytes beyond the read address. The displacement is **32 bytes**, not 8: the represented offset advances eight 32-bit elements before the halfword store.

The first halfword at the incoming register-3 address is then written twice, with a global read between the writes:

- First, it receives the low 16 bits of the incoming address itself.
- The first global 32-bit value is read and retained.
- The halfword then receives the low 16 bits of the previously captured word.

These are two distinct writes. The first must not be removed from the behavioral contract merely because the second ordinarily replaces it. Aliasing, externally observed memory, or faults can make the intermediate effect significant.

The numeric incoming register-3 address is doubled for the first call argument. Its signed multiplication and address conversion remain subject to the arithmetic qualifications above.

### First and second calls

F-U01 is invoked at the destination obtained by clearing the incoming link register’s lowest two bits and then adding 4. The addition has unsigned 32-bit arithmetic in the represented model.

Its explicit arguments, in order, are:

1. The doubled numeric incoming register-3 address.
2. The captured first global value.
3. The register-6 product by 512.

After F-U01 returns, incoming register 7 is shifted right by 32, and the result is assigned to an unsigned 32-bit quantity. This contract calls that quantity the **shift-derived value**. Its value is **documented_only**: zero, sign fill, and an unchanged operand must not be selected without additional target evidence.

F-U02 is then invoked at the embedded code-reference base plus `0xFDC`, with the sole explicit argument `0x0897EFF4`.

### Third and fourth calls

After F-U02 returns, the routine reads the second global 32-bit value. It combines that value with the retained initial word and a byte displacement of `0x10`, then reads a 16-bit quantity at the resulting address.

That halfword is the sole explicit argument to F-U03, whose represented destination is **`0x0897F745`**. The supplied expression establishes this address as `0x0897EF57 + 0x7EE`.

F-U04 is invoked next, with no explicit arguments shown. Its represented destination is **`0x0897FF65`**, established by `0x0897EF67 + 0xFFE`.

No alignment mask is shown for either destination. Their low bits must not be cleared merely because executable-address interpretation is unknown. The full ABI-level extension of the halfword argument to F-U03 is also unknown.

Later operations use register-1 state associated with this call sequence. The representation does not establish an ordinary declared return value for F-U04 or a complete account of how this state is produced.

### Global-derived and result-dependent writes

The retained first global value is multiplied by 2048 to obtain the **region basis**. This uses the earlier snapshot, not a fresh global read after the calls.

The routine stores the low 16 bits of the region basis at region basis plus `0x38`. It then reads an unsigned byte at region basis plus incoming register 6. This is the **selected byte**.

Only after that byte read does the conditional write occur: if the register-1 state equals zero, a 32-bit value equal to region basis plus `0x14` is stored at region basis plus `0x54`. Nonzero register-1 state omits this particular write.

The shift-derived value and register-1 state are added as an unsigned 32-bit sum. Doubling that sum produces the **doubled result**, subject to the conversion qualification in the interface.

Three writes follow in this order:

- A 32-bit doubled result is stored at the numeric address selected byte plus `0x28`.
- The same 32-bit result is stored at the address numerically equal to the doubled result.
- A 16-bit value is stored at the address obtained by clearing the unsigned sum’s top bit, shifting right by 17, and adding 8. The stored value is the low 16 bits of the doubled result’s 32-bit pattern shifted logically right by 18.

The first destination uses the selected byte’s **value**, not its source address. Its numeric range is `0x28` through `0x127`.

The second write is self-addressed: the result serves as both the destination and the stored word. No zero-address guard is represented.

The third destination ranges from `0x8` through `0x4007`. Its stored value ranges from zero through `0x3FFF` under the stated 32-bit bit-pattern interpretation.

### Fifth call, returned-address write, and sixth call

The selected byte is exclusive-ored with the shift-derived value. The unsigned result is multiplied by 512, with 32-bit modular arithmetic, and used as the address of a character-sized read.

The character is converted to an integer and passed to F-U05. Values below `0x80` do not depend on character signedness; higher-byte values may produce different integer arguments depending on that unresolved property.

F-U05’s represented destination is **`0x0897F9ED`**, established by `0x0897EF69 + 0xA84`.

The returned value is treated as an address. A 16-bit zero is written there before F-U06 is invoked with that same address.

F-U06’s represented destination is **`0x0897F9D8`**. Its derivation clears the lowest two bits of `0x0897F3D5`, yielding `0x0897F3D4`, then adds `0x604`.

There is no represented null check, alignment check, allocation check, or ownership transition between the return, the halfword write, and the sixth call.

### Final writes and termination

After F-U06 returns, the final effects occur in this order:

1. A 16-bit value `0xF484` is stored at the address obtained by shifting incoming register 6 right by 4.
2. A 32-bit zero is stored at the address obtained by shifting the unsigned shift-derived value left by 3.
3. Incoming register 6 is shifted right by 31 and interpreted as an address. The low 8 bits of that shifted value are stored at that address.
4. That address is stored as a represented 32-bit pointer value through the destination supplied at stack offset `0x140`.
5. The low 16 bits of the same shifted register-6 value are stored at that address plus `0x34`.

The representation then reaches a bad-instruction termination marker. It shows no normal return or recovery path. Whether execution reaches this point, faults earlier, or has behavior absent from the supplied representation is unresolved.
