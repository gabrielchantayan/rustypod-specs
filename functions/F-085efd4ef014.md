# F-085efd4ef014

## Purpose

F-085efd4ef014 conditionally selects an object addressed by a context’s reserve-head field and rewrites endpoint and link fields. Two transfer paths are visible:

- **Rebase:** makes the selected object both active endpoints and assigns the former first endpoint to the reserve head, subject to intervening dependency effects and aliasing.
- **Append:** makes the selected object the last endpoint without directly assigning the first-endpoint field.

Before checking capacity, the function may update a shared-state value through a guard-controlled sequence. A zero return therefore does not establish that no state changed.

“Reserve,” “active,” “rebase,” and “append” are descriptive names for reference updates, not established application semantics. In particular, advancing the reserve-head field does not necessarily remove the selected object from a structure: its link may point back to itself, and structural invariants are not supplied.

## Interface

### Arguments and result

The function accepts:

1. An address of mutable context storage containing at least five consecutive 32-bit words.
2. An unsigned 32-bit caller mask.

The declared result is a signed 32-bit integer:

| Outcome | Result |
|---|---|
| Capacity rejection | Zero |
| Neither selection chooses a transfer | Zero |
| Rebase | The context’s last-endpoint word read after the transfer writes |
| Append | The saved 32-bit address-bearing value identifying the selected object |

With valid, nonoverlapping storage and dependencies that do not alter surrounding state, both transfer paths return the selected object’s address bits. The result is not a separate Boolean success flag. Interpretation as a portable pointer or as a positive signed integer is not established, particularly when bit 31 is set.

### Context layout

| Byte offset | Width | Contract name | Direct access |
|---|---:|---|---|
| 0 | 32 bits | First endpoint | Read; replaced on rebase |
| 4 | 32 bits | Last endpoint | Read; replaced on either transfer |
| 8 | 32 bits | Reserve head | Read; replaced on either transfer |
| 12 | 32 bits | Unused context word | No direct access |
| 16 | 32 bits | Limit | Read for the capacity bound |

Address-bearing context fields are 32 bits in the supplied representation. This layout is not pointer-width independent.

### Referenced object fields

| Byte offset | Width | Use |
|---|---:|---|
| 300, or 0x12C | 32 bits | Unsigned count-like field read from the last endpoint |
| 308, or 0x134 | 32 bits | Address-bearing link read and written during transfers |
| 312, or 0x138 | 32 bits | Address-bearing link cleared or assigned during transfers |
| 320, or 0x140 | 32 bits | Coordinate-like field used in signed arithmetic |

The two link fields are not established to be conventional forward and backward links.

### Shared storage

Three shared pointer-bearing locations are involved:

- **Shared-state pointer:** its target contains a 32-bit guard at offset 8 and a 32-bit value at offset 12.
- **Shared-reference pointer:** its target supplies a signed 32-bit value at offset 4.
- **Shared-coordinate pointer:** its target supplies a signed 32-bit coordinate.

The shared-coordinate pointer is loaded before the capacity gate and loaded separately after that gate for the first selection. The earlier pointer is retained for possible rebase arithmetic. These observations must not be collapsed into one pointer snapshot.

### Preconditions

Each address actually dereferenced must be valid for the relevant read or write at that point. There are no direct null checks, reserve-empty checks, alias checks, or structural validation.

Dependencies must return normally for normal completion. Any storage accessed after a dependency returns must still be valid. No dependency preservation or ownership guarantee is supplied.

## Behavior

### Guard-controlled shared-state update

This stage occurs before capacity checking.

The function first captures the shared-state pointer as the possible initialization destination. It then tests bit 0 of the guard reached through the shared-state pointer-bearing location.

If that bit is set, initialization is skipped. If it is clear, F-b255b26284e6 receives a guard address obtained through that shared pointer-bearing location. A zero result skips initialization but does not prevent subsequent capacity checking or selection.

A nonzero result enables initialization. On this path, two separate 32-bit temporaries are assigned 0x000F0000; neither address is explicitly passed to a dependency. These assignments establish no persistent state change or aggregate layout.

The function then obtains the current shared-reference pointer, reads the signed 32-bit field at offset 4, adds 0x002D0000, and stores the result at offset 12 of the **previously captured shared-state object**. F-d08d3ca17b81 is subsequently called with the guard address at offset 8 of that captured object.

Thus, replacement of the shared-state pointer during F-b255b26284e6 does not redirect the initialization destination or the later F-d08d3ca17b81 argument. Replacement of the shared-reference pointer during that dependency can affect the initialization value because the reference is read afterward.

The initial destination capture, guard test, and acquisition argument are not established to form an atomic snapshot. Under pointer instability, they need not identify the same object.

The function does not directly set the guard bit. Synchronization, publication, waiting, and guard-state transitions remain unresolved. Overflow behavior of the signed initialization addition is also unresolved.

### Capacity gate

After the guarded stage, the function captures the shared-coordinate pointer without yet dereferencing its target.

It compares the unsigned 32-bit field at offset 300 of the current last endpoint against the context limit minus one, with the subtraction performed in unsigned 32-bit arithmetic. Selection proceeds only when the count-like field is strictly less than that bound.

The subtraction wraps modulo 2³²:

- Limit zero produces a bound of 0xFFFFFFFF.
- Limit one produces a bound of zero, so every unsigned count fails.

Capacity failure returns zero. It causes no direct transfer-related writes and does not dereference the captured coordinate pointer. Earlier initialization or dependency effects may nevertheless have occurred.

### First selection

After capacity passes, the function reloads the shared-coordinate pointer-bearing location and dereferences the newly obtained pointer. The negation of that signed 32-bit coordinate is placed in temporary storage.

The first endpoint’s 32-bit coordinate at offset 320 is then copied into a separate temporary. F-5552a4ebb581 receives:

1. The address of the endpoint-coordinate temporary.
2. The address of the negated-coordinate temporary.

These arguments do not directly address the originating coordinate fields. Writes within the designated temporary objects therefore do not, merely by virtue of those arguments, modify the originating fields.

The dependency’s 32-bit result is treated as a mask. Rebase is selected if the result contains any bit absent from the caller mask. Equivalently, its intersection with the 32-bit complement of the caller mask must be nonzero.

The coordinate sources remain distinct:

- First selection uses the pointer reloaded after capacity passes.
- Rebase arithmetic uses the pointer captured before the capacity gate.

Even when those pointers are equal, their target contents need not remain unchanged between reads.

### Rebase transfer

If the first selection chooses rebase, the function rereads the current first endpoint’s signed coordinate and dereferences the earlier captured shared-coordinate pointer.

F-b6d5b325ab94 receives:

1. The negated current first-endpoint coordinate minus the coordinate read through the captured pointer.
2. The constant 0x000F0000.

The source establishes the argument expression, not the dependency’s mathematical operation. It does not independently establish the relative evaluation order of the two coordinate reads within that expression.

After this dependency returns, the function saves the current reserve-head value. It reads the selected object’s offset-308 link and assigns that value to the context’s reserve-head word. **That assignment, rather than guaranteed removal from a chain, is the established pre-call transition.**

F-22366f06e2a5 is then called with the saved selected-object value, the then-current last endpoint, and a step derived from the signed result of F-b6d5b325ab94: shift right by 16, then add one.

After F-22366f06e2a5 returns, the selected object’s offset-308 field is cleared, followed by its offset-312 field. The selected-object value is written into offset 308 of the context’s then-current last endpoint, and the context’s last endpoint is then assigned the selected-object value.

Next, the context’s then-current reserve head is written into offset 308 of its then-current first endpoint. The reserve head is assigned the then-current first endpoint, and the first endpoint is assigned the selected-object value. Finally, the function reads and returns the context’s last-endpoint word.

The second selection does not run on this path.

For a nonnegative signed result from F-b6d5b325ab94, the step equals the integer quotient by 65536, rounded down, plus one. The target rule for right-shifting negative signed values is not independently established. If the shift is arithmetic, the step range is −32767 through 32768 inclusive.

### Second selection

If the first selection does not choose rebase, the function initializes two separate 32-bit temporaries to 0x00640000 and 0x000F0000, respectively. It also forms a signed 32-bit candidate from the current last endpoint’s coordinate plus 0x000F0000.

F-5552a4ebb581 receives:

1. The address of the candidate.
2. The address of the individual temporary containing 0x00640000.

Only the address of the latter temporary is passed. The separate initialization to 0x000F0000 does **not** establish that this other temporary is adjacent, part of an aggregate, or accessible as a second word through the passed address. No two-word input region is established.

Append is selected when the dependency’s result is nonzero **or** the caller mask is nonzero. The dependency call still occurs when a nonzero caller mask already guarantees append.

If both are zero, the function returns zero without direct transfer writes.

### Append transfer

On append, the function saves the current reserve-head value, reads the selected object’s offset-308 link, and assigns that link value to the context’s reserve-head word.

F-22366f06e2a5 then receives the saved selected-object value, the then-current last endpoint, and one. As on rebase, the established pre-call state is the reserve-head assignment. It does not by itself establish removal of the selected object.

After the dependency returns, the selected object’s offset-308 field is cleared. Its offset-312 field is assigned the context’s then-current last endpoint. The selected-object value is then written into offset 308 of the context’s then-current last endpoint, after which the context’s last endpoint is assigned the selected-object value.

The return value is the saved selected-object value, not a final reload of the last-endpoint field.

There is no direct assignment to the first-endpoint field on this path. Dependency effects or overlapping storage can nevertheless change its contents.

## Side effects

Direct persistent writes can affect:

- The captured shared-state object’s field at offset 12.
- The context’s first endpoint, last endpoint, and reserve head.
- Referenced objects’ fields at offsets 308 and 312.

The function does not directly assign the context limit, an object’s count-like field, or an object’s coordinate field. Aliasing can cause another addressed write to affect the same storage.

The reserve-head assignment precedes F-22366f06e2a5 on both transfer paths. In valid, distinct storage without intervening mutation, that call begins with the reserve head equal to the selected object’s previously read offset-308 link. If that link equals the selected object, the reserve head still identifies it.

Dependencies are not assumed to preserve shared pointers, context words, object contents, or lifetimes. In particular:

- Changes during first selection can affect subsequent endpoint reads.
- Replacing the shared-coordinate global does not replace the saved rebase pointer.
- Changing the coordinate at the saved pointer can affect rebase arithmetic.
- F-22366f06e2a5 receives a pre-call last endpoint; subsequent link writes use context values obtained after it returns.
- Later rebase assignments use the first endpoint and reserve head present at those later stages.

No rollback is visible if a dependency fails to return normally. Earlier writes, including initialization or reserve-head assignment, may remain.

No direct allocation or release is visible. Reference rewriting does not establish ownership transfer, reference counting, or permission to release an object. Allocation, release, and retention by dependencies remain unknown. Temporary addresses are supplied to dependencies, but no permission to retain them beyond their valid lifetime is established.

## Acceptance examples

These are conditional static examples, not executed tests. Unless an example states otherwise, assume valid nonoverlapping storage, representable signed arithmetic, normal dependency returns, stable shared pointers, and no dependency mutation of surrounding state.

1. **Initialization despite zero result.**  
   The guard bit is clear, F-b255b26284e6 returns nonzero, and the shared-reference value is 0x00100000. The captured shared-state destination receives 0x003D0000 at offset 12, followed by F-d08d3ca17b81. Count 4 with limit 5 then rejects transfer because 4 is not less than 4. The function returns zero despite the persistent initialization.

2. **Capacity boundaries.**  
   With limit zero, count 0xFFFFFFFE passes and count 0xFFFFFFFF fails. With limit one, every unsigned count fails. Failure does not dereference the previously captured coordinate pointer.

3. **Uncovered mask bit.**  
   Caller mask 0x00000002 and first result 0x00000006 select rebase because bit 0x00000004 is uncovered. The second selection is not called.

4. **Caller mask guarantees append, not call avoidance.**  
   Caller mask 0xFFFFFFFF prevents every first result from selecting rebase. The second selection still executes. After it returns normally, append is selected regardless of its result.

5. **Second-selection argument extent.**  
   If first selection declines rebase, the second call receives the candidate’s address and an address identifying a temporary initialized to 0x00640000. A separate temporary is initialized to 0x000F0000. An acceptance condition requiring that latter value to be readable at the next word after the second argument is unsupported.

6. **Ordinary rebase structure.**  
   Initially, first endpoint is A, last endpoint B, and reserve head C; C’s offset-308 link is D. All four objects are distinct. If F-b6d5b325ab94 returns 0x00020000, F-22366f06e2a5 receives C, B, and 3, with reserve head already assigned D. Completion leaves both endpoints C, reserve head A, A’s offset-308 link D, B’s offset-308 link C, and both C links zero.

7. **Ordinary append structure.**  
   With the same distinct objects, zero caller mask, zero first result, and nonzero second result select append. F-22366f06e2a5 receives C, B, and one after reserve head becomes D. Completion leaves first endpoint A, last endpoint C, reserve head D, C’s offset-308 field zero, C’s offset-312 field B, and B’s offset-308 field C.

8. **Self-referential reserve link.**  
   Suppose reserve head is C and C’s offset-308 link is C. On either transfer path, the pre-call reserve-head assignment writes C back into that field. F-22366f06e2a5 therefore begins with reserve head still C under the stated preservation assumptions. Describing C as already removed would be incorrect.

9. **No transfer selection.**  
   Capacity passes, both selection results are zero, and caller mask is zero. The result is zero without direct transfer writes. Earlier initialization and dependency effects remain possible.

10. **Distinct coordinate-pointer observations.**  
    The pre-gate capture yields P, but the post-gate reload yields Q. P contains 0x00010000, Q contains 0x00030000, and the first endpoint coordinate is 0x00020000. First selection receives a temporary containing −0x00030000. If rebase follows with unchanged coordinates, F-b6d5b325ab94 receives −0x00030000, derived from the endpoint and P, rather than −0x00050000 derived from Q. This does not establish concurrency safety.

11. **Global replacement during first selection.**  
    Both initial pointer observations identify P. First selection replaces the shared-coordinate global with R and chooses rebase. Rebase still dereferences P. If that dependency instead changes P’s target coordinate, the changed value can affect rebase because only the pointer was saved.

## Uncertainties

The following remain **documented_only**:

- Application meanings of coordinates, masks, limits, guards, and links.
- Any fixed-point interpretation of the constants.
- Dependency contracts beyond visible arguments and result uses.
- Signed-overflow behavior for coordinate negation, subtraction, candidate addition, and shared-state initialization.
- The target rule for right-shifting negative signed values.
- Permitted aliasing, structural invariants, pointer stability, synchronization, and object lifetimes.
- Dependency access beyond the individual initialized temporary objects.
- Adjacency or aggregate relationships among separate temporaries.
- Behavior for invalid addresses, empty reserve state, malformed structures, or nonreturning dependencies.

Unsigned capacity subtraction and mask complement are explicitly 32-bit operations. Signed arithmetic is not assigned saturation or modular wrapping without further evidence.

## Evidence

Established static evidence consists of the supplied argument and field widths, offsets, pointer-load placement, branch conditions, dependency arguments, direct assignments, and return expressions.

Separate temporary initializations establish their individual values, not adjacency or a two-word aggregate. The pre-call transfer assignment establishes replacement of the reserve-head word with the selected object’s previously read link, not unconditional structural removal.

Structural terminology and possible fixed-point intent are interpretations, not established domain contracts. Unknown dependency behavior has not been used to complete missing guarantees.

No runtime tests, dependency inspections, or independent implementation verification have been performed.
