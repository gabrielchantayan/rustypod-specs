# F-50fff3996655

## Purpose

F-50fff3996655 conditionally updates two 32-bit fields in a destination region using two caller-supplied records.

Its established behavior is:

- If the destination address is zero, or either record’s first word is zero, perform no destination write.
- Otherwise, inspect bit 0 of each record’s second word, in first-record order.
- If either inspected bit is set, write zero to destination offset `0x1C`.
- If both inspected bits are clear, write the previously sampled first-record first word to destination offset `0x1C`, then replace destination offset `0x20` with a calculated word that preserves that field’s previous bit 0.

The records’ semantic roles are unknown. Their words must not be assumed to represent addresses, lengths, ownership flags, or validity indicators beyond the operations specified here.

This contract describes static evidence. No runtime tests have been performed.

## Behavior

### Initial gates

The destination-address check precedes all memory accesses.

1. **Zero destination:** return without reading either record or writing memory.
2. **Nonzero destination:** read the second record’s first word. If it is zero, return without reading the first record or writing the destination.
3. **Nonzero second-record first word:** read the first record’s first word. If it is zero, return without reading either second word or writing the destination.

These gates test word contents for equality to zero. They do not require positive values; negative signed values also pass.

There is no separate null-address check for either record. In particular, a nonzero destination causes the second record’s first-word read even if the second record address is null or otherwise invalid.

The first-record first word obtained during gating is retained for a possible write to destination offset `0x1C`. That particular write does not reread the first record.

### Ordered low-bit checks

After both first-word gates pass, read the first record’s second word and inspect bit 0.

If bit 0 is set:

- Do not read the second record’s second word.
- Write a 32-bit zero to destination offset `0x1C`.
- Return.

Otherwise, read the second record’s second word and inspect bit 0.

If that bit is set:

- Write a 32-bit zero to destination offset `0x1C`.
- Return.

Neither rejection path explicitly accesses destination offset `0x20`. An overlapping source read may nevertheless access that same storage.

Only bit 0 affects these decisions. Bits 1–31 of the first record’s second word do not otherwise contribute to the calculation. Bits 1–31 of the second record’s second word do contribute on the successful path.

### Successful update

If both checked low bits are clear, the routine completes the following destination operations in order:

1. Write the retained first-record first word to destination offset `0x1C`.
2. Read the operands needed for the final calculation and write the resulting 32-bit word to destination offset `0x20`.

The operand reads for the second assignment occur after completion of the first destination write. They include fresh reads of:

- The first record’s first word.
- The second record’s first word.
- The second record’s second word.
- Destination offset `0x20`.

The earlier gate and flag samples do not replace these fresh arithmetic reads.

For the calculation, let:

- \(p\) be the word read from destination offset `0x20`.
- \(a\) be the fresh first-record first word, interpreted as signed 32-bit.
- \(b\) be the fresh second-record first word, interpreted as signed 32-bit.
- \(r\) be the fresh second-record second word, interpreted as unsigned 32-bit.
- \(h = r \mathbin{\mathrm{logical\ right\ shift}} 1\).

Provided the signed difference \(b-a\) is representable in 32 bits, the final word is:

\[
w =
(p \mathbin{\&} 1)
\mathbin{|}
\left(
2 \times
\left(
\operatorname{uint32}(b-a)+h
\right)
\bmod 2^{32}
\right).
\]

The unsigned addition inside the doubled expression also wraps modulo \(2^{32}\). The notation \(\operatorname{uint32}\) denotes conversion to the corresponding unsigned 32-bit value.

Consequences:

- The resulting bit 0 equals the sampled destination bit 0.
- Previous destination bits 1–31 are discarded.
- The calculated contribution has bit 0 clear.
- The right shift is logical, including when the second-record word’s high bit is set.
- Unsigned addition and multiplication wrap modulo \(2^{32}\).
- Doubling discards the high bit of the preceding 32-bit sum.

The subtraction occurs as signed arithmetic before unsigned combination. Later unsigned operations do not establish wrapping semantics for an overflowing signed subtraction. Such overflow remains a documented-only uncertainty.

### Repeated reads, overlap, and ordering

The successful path is not based on an immutable input snapshot.

The second record’s first word is read once for gating and again for arithmetic. The first record’s first word is read once for gating and the retained destination write, then again for arithmetic. The second record’s second word is read once for its flag check and again for arithmetic.

Therefore, destination offset `0x1C` may overlap a source operand whose later value changes because of the first destination write. A conforming description must retain the fresh reads rather than calculate exclusively from gate-time values.

Record adjacency also constrains overlap. If the second record begins at destination offset `0x1C`, its second word is the destination word at `0x20`. With stable ordinary storage, reaching success requires that shared word’s low bit to be zero. It cannot simultaneously be an even second-record flag word and an odd previous destination word.

The body does not establish a relative order among the operand reads within the final calculation. They follow the first destination write and precede the final destination write; no finer read order is promised.

No revalidation occurs after the first destination write. Values obtained by fresh arithmetic reads need not satisfy the earlier gates or flag checks if intervening alias effects or externally permitted changes alter them.

## Acceptance examples

These are conditional acceptance cases derived from static evidence, not observed executions. Unless stated otherwise, assume valid ordinary storage, stable contents, nonoverlapping records and destination, and representable signed subtraction.

### Zero destination suppresses memory access

Given a zero destination and arbitrary remaining inputs:

- Neither record is read.
- No memory is written.
- The auxiliary scalar has no effect.

Either record address may be unusable because neither is dereferenced.

### A zero second-record first word stops before the first record

Given a nonzero destination and a readable second-record first word equal to zero:

- Only that record word is read.
- The first record is not accessed.
- No destination field is accessed.

The first record address and destination fields need not be usable on this path.

### A zero first-record first word does not clear the destination

Given a nonzero second-record first word and a zero first-record first word:

- Both first-word gate reads occur.
- Neither second word is read.
- Neither destination field is written.

In particular, destination offset `0x1C` is not cleared merely because the first-record gate fails.

### First-record rejection skips the other flag

Given nonzero first words and a first-record second word of `0x00000003`:

- The set low bit selects rejection.
- The second-record second word is not read.
- Destination offset `0x1C` becomes zero.
- Destination offset `0x20` remains unchanged under the nonoverlap assumption.

### Second-record rejection preserves the adjacent destination field

Given nonzero first words, an even first-record second word, and a second-record second word of `0x00000005`:

- Both low-bit checks occur.
- Destination offset `0x1C` becomes zero.
- Destination offset `0x20` remains unchanged.

### Ordinary success preserves only the old low bit

Given:

| Word | Initial value |
|---|---:|
| First-record first word | `100` |
| First-record second word | `0` |
| Second-record first word | `140` |
| Second-record second word | `12` |
| Destination offset `0x20` | `0xFFFFFFFF` |

The result is:

- Destination offset `0x1C`: `100`.
- Logical half of the second-record second word: `6`.
- Difference plus half-word: \(140-100+6=46\).
- Doubled contribution: `92`, or `0x0000005C`.
- Destination offset `0x20`: `0x0000005D`.

### Success can produce a zero adjacent word

Given equal nonzero first words, both second words zero, and an even previous destination word:

- Destination offset `0x1C` receives the nonzero first-record value.
- Destination offset `0x20` becomes zero.

A zero word at `0x20` therefore does not identify rejection.

### Unsigned doubling wraps

Given first-record first word `1`, second-record first word `2`, second-record second word `0xFFFFFFFE`, and an even first-record second word:

- The logical half-word is `0x7FFFFFFF`.
- Adding the signed difference of `1` produces unsigned `0x80000000`.
- Doubling wraps to zero.
- Destination offset `0x20` becomes exactly its previous bit 0.

This example does not involve signed-subtraction overflow.

### Overlap changes the later calculation and constrains the preserved bit

Assume the second record begins exactly at destination offset `0x1C`, while the first record is separate:

| Storage | Initial value |
|---|---:|
| First-record first word | `100` |
| First-record second word | `0` |
| Second-record first word, also destination `0x1C` | `140` |
| Second-record second word, also destination `0x20` | `12` |

Both first-word gates and both low-bit checks pass. The shared word at destination `0x20` is `12`, so its previous bit 0 is zero.

The first destination write replaces `140` with `100`. The fresh second-record first-word read therefore obtains `100`, not `140`. The remaining arithmetic is:

\[
2 \times (100-100+(12 \mathbin{\mathrm{logical\ right\ shift}} 1))=12.
\]

The final destination values are:

- Offset `0x1C`: `100`.
- Offset `0x20`: `12`.

A result of `13` would require preserving a previous low bit of one, which contradicts the shared word’s stated initial value of `12`. With stable contents, making that shared word odd would instead cause second-record low-bit rejection.
