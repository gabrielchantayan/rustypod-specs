## Behavior

### Call and memory-access order

On a normal complete execution, the dependency is called exactly three times, sequentially. No result is reused to eliminate a later call, even when selectors are equal.

The first invocation receives the source-derived address at byte offset 16 and selector zero. After it returns, its four-byte return word is written to result offset 4.

Only then is the integer at source offset 4 read. One is subtracted from the observed value, and the result supplies the second invocation’s selector. That invocation receives the same source-derived address. Its return word is written to result offset 8.

After the second return word has been stored, the function selects the final selector and classification according to the mode. The classification is written to result offset 12 before the third invocation begins.

The third invocation receives the same source-derived address and the mode-dependent selector. Its return word is written to result offset 0. The function then returns the original result address.

Consequently, the direct result-write order is **4, 8, 12, 0**. The source-relative integer is observed between the writes to offsets 4 and 8; it is not captured at function entry.

The expressions are not interchangeable at all boundaries merely because they agree mathematically over a restricted range. The mode-zero branch uses a left shift; the mode-one branch uses multiplication and addition. Their exceptional behavior depends on the execution semantics.
