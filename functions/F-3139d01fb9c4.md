# F-3139d01fb9c4

## Purpose

F-3139d01fb9c4 conditionally reduces a signed 16-bit record count by one, then conditionally records the resulting last-record index in a separate signed 16-bit array.

The reduction requires all of the following:

- The record count exceeds one.
- A selected record and the last counted record have equal first 32-bit fields.
- Their second 32-bit fields also compare equal as pointer values.
- The flag byte associated with the last counted record is exactly 1.

The function does not remove, clear, copy, or release the excluded record. Its observable removal operation is solely a count change.

**Inferred intent:** the function appears to eliminate a specially marked duplicate at the end of a record collection and update an endpoint associated with the current group. The meanings of “record,” “group,” and “endpoint” are descriptive interpretations, not established application semantics.

## Interface

The function accepts one argument identifying a writable parent object. It has no explicit return value and exposes no status or error result.

The supplied representation uses 32-bit addresses, 32-bit integer fields, signed 16-bit fields, and single-byte flags.

### Parent object

| Byte offset | Width | Meaning |
|---|---:|---|
| +20 | 32 bits | Address of the descriptor, or zero |

A zero descriptor address is explicitly supported. A zero or invalid parent address is not explicitly supported: the function must read the field at parent offset +20 before it can discover whether a descriptor exists.

### Descriptor

| Byte offset | Width | Meaning used by this contract |
|---|---:|---|
| +0 | Signed 16 bits | Group count, denoted **G** |
| +2 | Signed 16 bits | Record count, denoted **N** |
| +4 | 32 bits | Address of the record array |
| +8 | 32 bits | Address of the flag-byte array |
| +12 | 32 bits | Address of the signed 16-bit endpoint array |

These names describe how the fields participate in this function. They do not establish their wider application meaning.

### Referenced arrays

Each record occupies eight bytes:

| Record-relative offset | Width | Use |
|---|---:|---|
| +0 | 32 bits | First equality key |
| +4 | 32 bits | Second equality key, compared as a pointer value |

The second field is not dereferenced. Its equality does not require the value to identify readable storage.

The flag array contains one byte per indexed position. Only the byte corresponding to the original last counted record can affect this invocation.

The endpoint array contains signed 16-bit entries. Depending on **G**, the function can read entry **G − 2** and write entry **G − 1**.

### Preconditions

Every address actually accessed must designate storage suitable for the access. This includes writable descriptor storage when the count changes, and writable endpoint storage when **G** is positive.

The function does not validate:

- Descriptor or array addresses.
- Array capacities.
- Alignment.
- Whether a selected record index is within the counted collection.
- Whether a stored endpoint is consistent with **N**.
- Whether referenced regions overlap.
- Concurrent modification of the parent, descriptor, or arrays.

The behavior below assumes stable readable memory during a call, except for the function’s own writes. Effects involving overlapping storage are discussed separately.

## Behavior

### Absent descriptor

The first observable data access is the read of the descriptor address from parent offset +20.

If that address is zero, processing ends. There are no descriptor or array accesses and no writes.

### Conditional comparison

For a nonzero descriptor, the function reads **N** as a signed 16-bit value and widens it to a signed 32-bit value.

If **N ≤ 1**, it skips the record comparison and flag check entirely. This does not necessarily end the function: the endpoint update remains eligible.

If **N > 1**, the function obtains the record-array address and reads **G** as a signed 16-bit value.

The last record considered by the comparison is record **N − 1**, using an eight-byte stride.

The selected record is determined as follows:

- If **G ≤ 1**, select record zero.
- If **G > 1**, read endpoint entry **G − 2** as a signed 16-bit value, widen it, add one, and use the result as the selected record index.

There is no clamping or consistency check. A negative stored endpoint can produce a negative selected index; a large endpoint can select a record beyond the counted range. Such an access is not converted into a graceful failure.

The comparison is staged:

1. Compare the selected record’s first 32-bit field with the last record’s first 32-bit field.
2. Only if those fields are equal, read and compare the two second fields as pointer values.
3. Only if both fields match, obtain the flag-array address and inspect flag entry **N − 1**.
4. Only if that byte equals exactly 1, decrease the descriptor’s record count by one.

A zero flag prevents the decrement. Any other value, including 2 or 255, also prevents it.

The first fields are compared for exact equality. Although the representation uses 32-bit integers, signed ordering is irrelevant because no ordering comparison is performed.

The second fields are compared as pointer values. The function does not follow either pointer or compare the contents of the addressed objects.

When a decrement occurs under ordinary non-overlapping storage, **N** was greater than one, so the new count is at least one. This decrement cannot underflow the signed 16-bit count.

### Endpoint update

After the optional decrement, the function reads the descriptor’s group count again.

If the current **G ≤ 0**, processing ends without an endpoint write.

If the current **G > 0**, the function writes the current record count minus one to endpoint entry **G − 1**.

Consequently:

- The update occurs even when the record comparison was skipped.
- The update occurs even when the records differ.
- The update occurs even when matching records have a flag other than 1.
- If the count was decremented, the endpoint reflects the decreased count.
- The first **G − 1** endpoint entries are not directly written by this function.

The endpoint value is stored in a 16-bit destination. For current record counts from −32767 through 32767, subtracting one produces a representable signed 16-bit result. A current count of −32768 instead produces the 32-bit value −32769 before narrowing; the exact signed 16-bit result is not established portably by the supplied source representation.

### Arithmetic and indexing

Signed 16-bit fields are widened before the arithmetic shown here.

For **G > 1**, the endpoint value used to select a record can range from −32768 through 32767. Adding one therefore yields a selected index from −32767 through 32768. Nothing requires this index to be less than **N**.

The count-derived and endpoint-derived integer offsets fit in signed 32-bit arithmetic for all signed 16-bit inputs. This does not establish that the resulting addresses are valid, that pointer arithmetic remains within an allocated object, or that address calculation cannot encounter target-specific boundary behavior.

## Side effects

The function has at most two direct writes:

1. A signed 16-bit write to descriptor offset +2, decreasing the record count.
2. A signed 16-bit write to endpoint entry **G − 1**, recording the current count minus one.

When both occur, the count write precedes the endpoint write.

There is no explicit write to:

- The parent’s descriptor-address field.
- Record data.
- Flag bytes.
- Other descriptor fields.
- Other endpoint entries.

No allocation, deallocation, ownership transfer, logging, callback, or external function call appears in the supplied body.

The descriptor and referenced arrays remain caller-provided storage. The function neither establishes ownership of them nor releases them.

### Access ordering and conditional reads

The established ordering constraints are:

- The parent field is read before any descriptor access.
- The initial count is read before deciding whether to access comparison data.
- For **G > 1**, the prior endpoint is read before accessing the selected record.
- First-field equality gates second-field reads.
- Equality of both fields gates the flag-byte read.
- The flag check precedes a count decrement.
- The optional decrement precedes the final group-count check and endpoint write.

The supplied representation does not establish an exact machine-level order between the two operand reads within an equality comparison. Nor does it establish a total ordering among address and value reads used to prepare the final endpoint store.

These accesses are not atomic as a group. No synchronization or rollback is present.

### Overlapping storage

No explicit disjointness check exists.

The final group-count check is a fresh read, and the endpoint update obtains the current count rather than promising an immutable entry-time snapshot. Implementations must not replace these observable dependencies with assumptions about independent storage without an additional precondition.

The final endpoint write could physically overlap descriptor fields or other referenced data if the caller supplies overlapping addresses. The simple count-and-endpoint interpretation assumes ordinary non-overlapping layout. A general contract for arbitrary overlap is **documented_only** because access validity and target memory semantics are not established.

## Acceptance examples

These examples are conditional static expectations, not executed tests. Unless stated otherwise, all addresses are valid, arrays are sufficiently large, storage is non-overlapping, and no concurrent modification occurs.

### Null descriptor

Given a readable parent whose descriptor field is zero:

- The function returns without writing memory.
- No descriptor or array storage is required.

### Matching records with the exact qualifying flag

Given **G = 1**, **N = 3**, identical first and second fields in records 0 and 2, and flag entry 2 equal to 1:

- The selected record is record 0.
- The count becomes 2.
- Endpoint entry 0 becomes 1.
- Record 2 remains physically unchanged.

### Matching records with a nonqualifying flag

Given the same counts and record equality, but flag entry 2 equal to 2:

- The count remains 3.
- Endpoint entry 0 becomes 2.

This example distinguishes an exact-byte test from a general nonzero test.

### First-field mismatch

Given **G = 1**, **N = 3**, and different first fields in records 0 and 2:

- The count remains 3.
- The second record fields and flag byte are not needed for this comparison path.
- Endpoint entry 0 becomes 2.

### Second-field mismatch

Given equal first fields but unequal second-field pointer values:

- The count remains unchanged.
- The flag byte is not read.
- A positive group count still causes the endpoint update.

### Selection from a previous endpoint

Given **G = 3**, **N = 6**, and endpoint entry 1 equal to 2:

- The selected record is record 3.
- The last compared record is record 5.
- If both fields match and flag entry 5 equals 1, the count becomes 5 and endpoint entry 2 becomes 4.
- Otherwise, the count remains 6 and endpoint entry 2 becomes 5.
- Endpoint entry 1 is not directly modified.

### Small counts still update endpoints

Given **G = 1** and **N = 1**:

- No record or flag data is accessed.
- The count remains 1.
- Endpoint entry 0 becomes 0.

Given **G = 1** and **N = 0**:

- No record or flag data is accessed.
- Endpoint entry 0 becomes −1.

### Nonpositive group count does not disable comparison

Given **G = 0** and **N = 2**:

- Record 0 is selected for comparison with record 1.
- Matching fields and flag entry 1 equal to 1 reduce the count to 1.
- No endpoint entry is written.

### Out-of-range selected record

Given **G = 2**, **N = 3**, and endpoint entry 0 equal to 100:

- The comparison attempts to use record 101, not record 0 or a clamped record.
- Whether that access is valid depends on the supplied allocation.
- No bounds-error result or recovery behavior is established.
