# F-151ab20ff1a3

## Purpose

F-151ab20ff1a3 searches a sentinel-based linked structure for an entry whose extracted 32-bit key equals the supplied search key. It then passes either the selected entry’s payload or a temporary initialized from the search key to an output-related dependency.

The result is a packed 64-bit value. Its low 32 bits indicate whether the final current pointer differs from a freshly loaded sentinel pointer. Its high 32 bits contain the final contents of a local 32-bit search-key slot.

The terms “search,” “entry,” “payload,” and “sentinel” describe the structure supported by the supplied static evidence. The exact container type, payload type, output representation, and ownership rules are not established.

The visible representation uses four-byte pointer-sized fields and four-byte integer accesses. The search compares the entire 32-bit key value; it performs no ordering comparison, sign extension for comparison, or range validation.

### Structure layout used by this function

Only the following layout requirements are established:

- At byte offset 40 in the referenced structure: a four-byte pointer-like field identifying the sentinel.
- At byte offset 0 in that sentinel: a four-byte pointer-like field used as the initial current entry.
- At byte offset 0 in each traversed entry: a four-byte pointer-like field used to advance traversal.

The payload’s size and internal layout are unknown. The eight-byte displacement does not establish the meaning of either preceding four-byte field beyond the traversal link at offset 0.

### Return value

The function returns a 64-bit packed value with these logical fields:

| Bits | Meaning |
|---|---|
| 0–31 | Exactly 1 if the final current pointer differs from the freshly loaded sentinel pointer; otherwise exactly 0. |
| 32–63 | The final 32-bit contents of the local slot initially set to the search key. |

This is a value-level bit layout, not a claim about the byte order used when a caller stores the result in memory.

On the sentinel branch, dependencies receive the address of the local key slot. They may change its contents before the return value is assembled. Consequently, the upper half must not generally be specified as an unconditional echo of the input key.

## Behavior

### Initial state and traversal setup

The function first reads the sentinel pointer from structure offset 40, then reads the sentinel’s first four-byte field to obtain the initial current pointer.

It also creates a local four-byte slot containing the search key. This slot later serves as the temporary passed to the sentinel-branch dependencies and supplies the upper half of the return value.

No candidate key is read during initial setup.

### Search progression

At the beginning of every search iteration, the function reloads the sentinel pointer from structure offset 40 into a local comparison slot.

It then calls F-f27df610be05 with two arguments:

1. The address of the local current-pointer slot.
2. The address of the local comparison-pointer slot.

These are addresses of local pointer values, not simply copies of the two pointer values. The dependency can therefore modify either local value. Subsequent operations use the resulting current-pointer value.

The dependency’s returned 32-bit integer is interpreted only as zero or nonzero:

- A zero result ends the search immediately. No key extraction is performed for that iteration.
- A nonzero result permits key extraction.

For key extraction, the function passes the address eight bytes after the current pointer to F-194cdec98e23. It interprets that dependency’s result as a pointer and reads one 32-bit integer through it.

That integer is compared with the original search key:

- Equality ends the search.
- Inequality causes the function to read the current entry’s first four-byte field and adopt that value as the next current pointer.

The next iteration again reloads the sentinel and calls F-f27df610be05.

The function does not independently check current-pointer equality with the sentinel before extracting a key. Safety of that decision depends on F-f27df610be05 and the supplied data.

There is no visible iteration bound. Termination requires a zero result from F-f27df610be05 or a matching extracted key. A cycle without either condition can continue indefinitely.

### Final branch selection

After leaving the search, the function reloads the sentinel pointer from structure offset 40 once more.

It compares the current pointer directly with that freshly loaded value:

- Unequal pointers select the non-sentinel branch.
- Equal pointers select the sentinel branch.

This final pointer comparison, rather than the reason traversal stopped, determines the returned low-half flag and the output path.

Accordingly, “key found” is a useful inferred interpretation, but it is not the complete established definition of the flag. Without a contract for F-f27df610be05 and constraints on changes to the sentinel field, a zero comparison result does not by itself imply that the flag will be zero.

### Non-sentinel branch

If the current pointer differs from the final sentinel pointer, the function calls F-6e673595197b with:

1. The original output argument.
2. The address eight bytes after the current pointer.

It does not visibly construct or finalize a local temporary on this branch.

The low half of the return value is 1. The local key slot has no explicit modification on this branch and is not passed by address to the visible dependencies on this path.

### Sentinel branch

If the current pointer equals the final sentinel pointer, the function performs these calls in order:

1. F-6e5ee90f2ebb receives the address of the local key slot and a 32-bit zero argument.
2. F-6e673595197b receives the original output argument and the address of that same local slot.
3. F-d62832ad54fc receives the address of that same local slot.

The low half of the return value is 0.

The first call resembles initialization, and the last resembles finalization, but their precise effects are unknown. In particular, the zero argument does not establish that the resulting temporary or output is numerically zero.

The return value uses the local slot’s contents after all three calls. A modification by the final call therefore affects the high half just as a modification by either preceding call would.

### Return assembly

The final flag is computed before output-related calls. The function does not recheck the structure, sentinel, current entry, or key after those calls.

The final 64-bit result combines that already-selected flag in the low half with the then-current local key slot in the high half. No dependency return value is directly propagated as the function’s return value.

## Side effects

### Direct memory activity

The function directly reads:

- The structure’s sentinel-pointer field during initial setup, at every iteration, and after search termination.
- The initial link through the initially loaded sentinel.
- Entry links when advancing after a nonmatching key.
- One four-byte key through each pointer returned by F-194cdec98e23 when extraction is reached.

Its visible direct writes are to local storage. It does not visibly assign to the structure’s fields, entry links, payload bytes, or output argument’s target.

This does not establish that the overall operation is read-only. Dependencies may modify memory or global state.

### Dependency-visible state and ordering

The traversal dependency receives writable access to two local pointer slots. The sentinel branch exposes the local key slot to three successive dependencies.

All dependency calls occur sequentially. On a nonmatching candidate, key extraction and its returned-key read occur before reading the next-entry link. A dependency that changes that link can therefore affect the next traversal step.

The sentinel field is repeatedly reloaded rather than captured once for the entire operation. Changes to it can affect both later iteration comparisons and final branch selection.

### Ownership and lifetime

No allocation or release is directly visible in this function.

Passing an entry payload address does not establish whether F-6e673595197b copies, moves, borrows, retains, or destroys anything. Similarly, the temporary-path calls do not establish allocation or release semantics.

The address of the local key slot is available only during the current invocation’s lifetime. Whether any dependency improperly or intentionally retains that address is unknown; this function provides no visible lifetime extension.

### Errors and abnormal execution

There is no visible error return, recovery path, or dependency-status handling beyond the traversal dependency’s zero/nonzero result.

Null or invalid pointers can be dereferenced without local rejection. Dependency failures, exceptions, nonlocal exits, and memory-fault behavior are not established. The final temporary-related call is only visibly reached if preceding calls return normally; no separate cleanup guarantee is shown.

## Acceptance examples

These are conditional static acceptance examples, not executed tests.

### Matching first entry

Assume a stable sentinel field, an initial current pointer distinct from the sentinel, a nonzero traversal-dependency result that leaves the pointer unchanged, and an extracted key equal to the search key.

Required observations:

- No next-entry link is read for advancement.
- F-6e673595197b receives the selected entry’s address plus eight bytes.
- Neither temporary-related dependency is called.
- The return value’s low half is 1.
- With no external mutation of the local key slot, its high half is the original key’s 32-bit pattern.

For a key of −1, that high-half pattern is all one bits; the equality comparison does not reject negative keys.

### Nonmatching entry followed by a match

Assume the first extraction produces a different key and its link identifies a second entry. Assume the next traversal call permits extraction and the second key matches.

Required order:

- First extraction and four-byte key read.
- First entry’s link read.
- Sentinel reload and second traversal-dependency call.
- Second extraction and key read.
- Final sentinel reload.
- Output call using the second entry’s payload address.

The function performs no additional advancement after the match.

### Stable empty structure

Assume the initial sentinel link points back to the sentinel, and F-f27df610be05 returns zero without changing the current pointer.

No key extraction or advancement occurs. The final pointer comparison selects the sentinel branch. Initialization-like, output-related, and finalization-like calls occur in that order using the same local slot address. The low return half is 0.

The upper half is whatever remains in that slot after the final call, not necessarily the input key.

### Zero traversal result with a non-sentinel current pointer

Assume F-f27df610be05 returns zero while leaving the current pointer distinct from the finally reloaded sentinel.

The function performs no key extraction in that iteration but still selects the non-sentinel output path and returns a low-half value of 1. A specification requiring an extracted matching key for every such result would be stronger than the visible evidence.

### Finalization changes the temporary

Assume the sentinel branch is selected and F-d62832ad54fc leaves the local slot containing the 32-bit pattern 7.

The packed return has a high half of 7 and a low half of 0, regardless of the slot’s earlier contents. This follows from return assembly occurring after finalization.

### No terminating condition

Assume traversal continually returns nonzero, every extracted key differs, and entry links form a cycle.

No bounded completion is promised. This function contains no independent cycle detection or search limit.
