# F-b8647e80d50a

## Purpose

F-b8647e80d50a performs a short, ordered sequence of memory updates and then transfers control to a target determined by incoming machine state.

The established behavior consists of:

- Writing a 16-bit constant through the fourth input.
- Assigning three constants to global storage locations.
- Reading another global value as an address and writing a 32-bit constant through that address.
- Placing the first input in a recovered 32-bit stack location.
- Invoking an unresolved indirect dependency with four derived or constant arguments.

The evidence does not establish a higher-level purpose. The global updates might participate in low-level control-state setup, but that interpretation is **inferred intent**, not an acceptance requirement. In particular, this contract does not identify the global locations as a verified hardware vector table, device register bank, or operating-system structure.

The visible body has no explicit success result, validation branch, or recovery path.

### Integer-width consequences

Under ordinary 32-bit wraparound machine arithmetic, the first indirect argument is:

- P plus `0x10`, reduced to 32 bits;
- multiplied by `0x01000000`, with the low 32 bits retained.

Under that interpretation, only the least significant byte of P plus `0x10` contributes to the result. That byte becomes the most significant byte of the argument; the lower 24 bits are zero.

This is a **conditional machine-width interpretation**, not a claim that equivalent signed arithmetic is defined in every source language. The recovered multiplication uses a signed 32-bit view, and multiplication can exceed that signed range. The supplied evidence does not include instructions sufficient to independently establish overflow handling.

Likewise, forming an address from the fourth input plus 2, advancing P by 16, and forming the indirect target may cross address-space boundaries. Wraparound, trapping, instruction-set state selection, and pointer validity at those boundaries remain architecture-dependent unknowns.

As a boundary case, if P is `0x200000F0`, P plus 16 is `0x20000100`, and the first argument is zero under the same interpretation. A wider multiplication result must not be substituted for the recovered 32-bit argument.
