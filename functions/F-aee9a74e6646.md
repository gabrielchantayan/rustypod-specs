# F-aee9a74e6646

## Purpose

F-aee9a74e6646 interprets a 32-bit control word, updates selected fields in shared state, and issues an ordered sequence of dependency calls.

Its established behavior is to:

- Capture a state reference.
- For exactly zero input, read the state-reference source a second time and write an initialization byte through that second reference.
- Capture a configured 32-bit value.
- Make an unconditional initial dependency call.
- Select either the captured configured value or the fixed value 2400.
- Compute, retain, or normalize an 8-bit state value through the originally captured reference.
- Conditionally invoke a value-change dependency and update a 32-bit cache through that original reference.
- Issue seven configuration calls in a fixed order.
- Make a final dependency call when control mask `0x400` is set.
- Return a 32-bit zero after normal completion.

The call pattern suggests configuration of an external subsystem. The subsystem, units, selector meanings, and success conditions are not established. This contract describes observable values, accesses, and ordering without assigning hardware semantics.

### Shared storage and layout

The routine accesses three shared sources:

1. **State-reference source:** read once at entry and, for zero input only, read again before the preliminary byte write.
2. **Configured-value source:** supplies a 32-bit value captured before the initial dependency call.
3. **Final-argument source:** read only when `0x400` is set, after the seven configuration calls.

Two state references must be distinguished:

- **Captured reference:** obtained by the first state-reference read. All main byte accesses and cache accesses use this reference.
- **Preliminary reference:** obtained by the second state-reference read, which occurs only for zero input. Only the preliminary byte write uses this reference.

The references may designate the same object, but that requires a stability assumption. The routine does not compare them or make the second reference replace the first.

The accessed state fields are:

| Byte offset | Access width | Use |
|---|---:|---|
| `+0x04` | 8 bits | Preliminary initialization through the preliminary reference; main byte handling through the captured reference. |
| `+0x0C` | 32 bits | Cached selected value, accessed only through the captured reference. |

The complete object layout, allocation size, reference representation, and alignment requirements are not established.

## Behavior

### 1. Capture references and perform conditional initialization

The established access order is:

1. Read the state-reference source and retain the captured reference.
2. If the entire control word is zero, read that source again and write `0xFF` to offset `+0x04` through the preliminary reference.
3. Read and retain the configured 32-bit value.
4. Make the initial dependency call.

For nonzero input, the second reference read and preliminary byte write do not occur.

For zero input, the preliminary write is separate from the later computed-byte write. They target the same byte only if both reference reads designate the same object. Even under that stability assumption, the writes occur on opposite sides of the initial dependency call and must not be collapsed into one observable operation.

The configured-value read occurs even when control bits will subsequently cause the selected value to be 2400.

### 2. Make the initial dependency call

F-2b7310b4ccea is called with:

1. `0x77`;
2. false if control mask `0x400` is clear, or true if it is set.

The Boolean’s logical value is established; its formal parameter width and calling convention are not.

This call occurs before main byte handling and before the cache comparison. It may therefore affect storage read by those later operations. In particular, the contract does not assume that it preserves the captured object’s byte, cache field, or lifetime.

The captured reference and configured value are already retained. Changes to their shared sources during this call do not replace those retained values. For zero input, the preliminary write has already occurred through the separately obtained preliminary reference.

### 3. Select the 32-bit value and configuration payloads

The selected value is 2400, equivalently `0x00000960`, if any of masks `0x001`, `0x080`, or `0x100` is set. Otherwise, it is the configured 32-bit value captured before the initial call.

The later configuration payloads are:

| Selector | Mask argument | Payload |
|---|---:|---|
| `0x02` | `0x0E` | `0x0E` when `0x001` is clear; zero otherwise. |
| `0x03` | None | The chosen byte described below. |
| `0x0B` | `0xFF` | Bitwise combination of `0x58` when `0x400` is set and `0x80` when `0x040` is set. |
| `0x08` | `0x0F` | `0x0F` when `0x080` is set; zero otherwise. |
| `0x10` | `0x80` | `0x80` when `0x100` is clear; zero otherwise. |
| `0x11` | `0x80` | Same value as for selector `0x10`. |
| `0x0F` | `0x80` | Same value as for selector `0x10`. |

The selector-`0x0B` payload is exactly one of `0x00`, `0x58`, `0x80`, or `0xD8`. The combination is bitwise; it is not an unbounded arithmetic accumulation.

No dependency result determines these payloads.

### 4. Choose and store the state byte

All accesses in this stage use the captured reference, not the preliminary reference and not a new read of the shared source.

#### Retention disabled: `0x200` clear

The routine computes a byte and writes it to offset `+0x04`. For nonzero input:

| `0x002` set? | `0x004` set? | Chosen byte |
|---|---|---:|
| No | No | `0xFF` |
| No | Yes | `0xFA` |
| Yes | No | `0xAF` |
| Yes | Yes | `0xAA` |

For zero input, the chosen byte is also `0xFF`.

This path does not read the stored byte to determine the result. The byte supplied later to selector `0x03` is the computed value, not a subsequent reread of the field. A later mutation of the stored byte therefore does not change that already chosen argument.

For zero input there are two byte writes overall: the preliminary write through the second reference and this main write through the original reference. They need not affect the same object.

#### Retention enabled: `0x200` set

The routine:

- Reads the byte at offset `+0x04`.
- Tests whether its bit pattern is `0xFF`.
- Writes `0xAF` to that field if the test succeeds.

Masks `0x002` and `0x004` do not affect the retained value.

Without external mutation, an initial `0xFF` becomes `0xAF`; any other initial byte remains unchanged. The second read is distinct from the first and follows any normalization write. No atomic read-modify-write behavior or exclusion of concurrent mutation is established.

In both paths, the chosen byte is retained before the optional value-change dependency call.
