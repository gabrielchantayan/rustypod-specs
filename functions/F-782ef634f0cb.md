# F-782ef634f0cb

## Purpose

F-782ef634f0cb coordinates a context-associated operation on a caller-supplied object. It first obtains a context value and passes that value, the object address, and a zero argument to a dependency. It then performs the principal delegated operation and retains its 32-bit result for return.

A nonzero second argument enables an additional dependency call and a conditional transfer of a 16-bit field from the supplied object to a context object. That transfer occurs only after a nonzero source-field observation and a zero destination-field observation. The context used for the eventual write is obtained separately from the context used for the zero check.

The sequence and conditions above are established by the supplied static evidence. Descriptions such as “initialization,” “refresh,” or “default propagation” would imply purposes that are not established here.

## Behavior

### Delegated operation and retained result

The following order is established on a normally progressing invocation:

1. F-fdd8589eca2d is called without explicit arguments.
2. Its 32-bit result is passed to F-3e5212464798 as the first argument. The supplied object address is the second argument, and zero is the third.
3. F-fce19146a7a1 is called with the supplied object address and the original mode value.
4. Its 32-bit result is retained as the eventual return value.
5. If mode is nonzero, F-5c5958cfd5fe is called without explicit arguments.

The first three calls occur regardless of mode. The conditional call to F-5c5958cfd5fe occurs after F-fce19146a7a1 has returned and before the function directly examines the object’s 16-bit field.

No return-value test gates progress through these calls. In particular, this function does not recognize an error result from F-fce19146a7a1 or skip later work because of one.

### Conditional field transfer

After the calls above, the function reads the 16-bit field at object offset 0xE6.

- If that observation is zero, no destination lookup or direct field write follows.
- If that observation is nonzero but mode is zero, no destination lookup or direct field write follows.
- If that observation is nonzero and mode is nonzero, the function obtains a context through another call to F-fdd8589eca2d and reads its 16-bit field at offset 0x80.
- If the observed destination field is nonzero, no direct field write follows.
- If the observed destination field is zero, the function calls F-fdd8589eca2d once more. It then rereads the object field at offset 0xE6 and writes those 16 bits to offset 0x80 of the context returned by this final call.

The source-field check precedes the mode condition. Consequently, mode zero does **not** eliminate the source-field read.

The source value used for the write is a new observation, not the value retained from the nonzero check. The destination address used for the write is also newly obtained, not retained from the zero check.

This distinction is part of the contract:

- A nonzero source observation permits further evaluation; it does not guarantee that a nonzero value is ultimately copied.
- A zero destination observation permits a write; it does not establish that the destination selected by the final context lookup is zero.
- The contexts returned by separate calls are not required by this evidence to be identical.

## Side effects

The function performs:

- One 16-bit source-field read on every normally progressing path after the delegated calls.
- At most one 16-bit destination-field read.
- One additional 16-bit source-field read if the copy branch is reached.
- At most one direct 16-bit write.

The direct write targets offset 0x80 of the context returned by the final F-fdd8589eca2d call. The function does not directly write the supplied object’s field as a separately designated action.
