### Width and combination rules

The eight-bit shift does not imply eight-bit operands. Neither dependency result is visibly truncated to a byte before combination, and the completed result is not visibly truncated to 16 bits.

Consequently:

- High bits in the unshifted contribution can survive into the return value.
- A shifted contribution greater than 255 can set bits above bit 15.
- The two contributions may overlap.
- Overlapping set bits remain set once; they do not produce an arithmetic carry.

The operation is therefore not generally equivalent to addition. It becomes equivalent to adding a high byte and a low byte only when the operand ranges keep their set bits disjoint.

The shifted result is held in a represented signed 32-bit intermediate. The unshifted result is held in an unsigned 32-bit intermediate, and the combined return is unsigned. This distinction prevents a general, source-only promise that every possible dependency result is handled by a wrapping unsigned shift.
