## Behavior

### Selection and ordering

During a normal invocation, F-7652e3d11db1 calls F-3fdd14ecd250 once, with no explicit arguments shown in the supplied source. The call completes before the caller chooses its destination or performs its own write.

The result is represented as a 32-bit integer in the source. Its only selection criterion is equality to zero:

- Zero selects the globally supplied destination.
- Every nonzero result selects the destination at byte offset 8 from the returned address.

There is no positive-value requirement, validity check, range check, or alternate handling for particular nonzero values.

On the zero-result branch, the global destination pointer is obtained after the dependency call returns. Consequently, if the dependency changes that pointer and then returns zero, the subsequent write uses the pointer available after the call. A contract that snapshots the pointer before invoking the dependency would not preserve this ordering.

On the nonzero-result branch, the visible caller behavior does not read the global destination pointer. The returned value supplies the base address directly.

### Write semantics

Once the destination has been selected, the function writes the complete 32-bit input value there. The supplied source shows one caller-level four-byte write and no destination-content read.

This is replacement behavior, not accumulation or merging. The previous four-byte contents are not consulted. There is no conditional suppression based on the old value or on whether the input matches it.

For the nonzero branch, the displacement is eight **bytes**. It is not eight four-byte elements. The write therefore occupies the four-byte field beginning at that byte offset.

The input is not visibly transformed before storage. The contract establishes preservation of its 32-bit value, but does not independently establish a byte-order convention for interpreting the resulting four bytes.
