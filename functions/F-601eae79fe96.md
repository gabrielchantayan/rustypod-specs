# F-601eae79fe96

## Purpose

F-601eae79fe96 conditionally obtains a textual representation associated with an object, requests that it be copied into caller-supplied storage, and returns a signed measurement result or accumulated measurement total.

Two substantive paths are established:

- **Lookup path:** obtain a selected text pointer, request copying, then measure that text and return the measurement.
- **Numeric path:** read seven-bit groups from object-referenced bytes, request formatting of an initial fragment and completed subsequent fragments, and accumulate their measured lengths.

Nonpositive capacity returns zero without accessing the object or destination. With positive capacity, a null object or null initially observed data pointer causes one zero byte to be written to the destination and returns zero.

**Inferred intent:** the numeric path resembles rendering a component-based identifier. Exact output syntax is not established because the format descriptor contents and dependency implementations are unavailable.

Neither input ownership nor dependency preservation of referenced memory is established.

## Behavior

### Entry gate and empty-output fallback

Capacity is examined before any object dereference or dependency call.

If capacity is zero or negative, the function returns zero. Neither supplied address is dereferenced.

With positive capacity:

- A nonnull object causes its offset-16 pointer to be read.
- A null object or null initially observed pointer selects the fallback.
- The fallback writes one zero byte at the destination and returns zero.
- Otherwise, lookup is attempted.

Positive capacity does not validate the destination. Even the fallback requires one writable byte.

### Lookup path

F-2eb743f270d1 receives the object reference.

A nonzero result selects the lookup path, with this observable call order:

1. F-5b103afaa2d2 receives the lookup result and supplies the preferred text argument.
2. If that argument is zero, F-85ea43423066 receives the same lookup result and supplies the fallback text argument.
3. F-c73847cd39ec receives the destination, selected text argument, and original capacity.
4. F-1cb585febd84 receives the selected text argument.
5. The measurement result is returned.

The fallback text result is not checked. If both providers return zero, zero is passed to both copying and measurement.

Copying precedes measurement. Consequently, the return reflects whatever F-1cb585febd84 observes after the copy dependency has executed, not necessarily the text’s earlier state. Preservation of selected text, object storage, or global state is not established.

No numeric bytes are directly traversed on this path. Source/destination overlap is not rejected.

### Numeric metadata and read-time values

A zero lookup result selects numeric processing.

The function reads the count at offset 12 and then rereads the data pointer at offset 16. No further direct reads of those fields occur. Changes made during lookup can therefore affect both saved values. A newly null pointer is not explicitly rejected.

Retaining the count and pointer does not snapshot the input bytes. All group descriptions below apply to byte values **when actually read**.

This distinction matters across fragment boundaries. After reading the initial group, the function invokes component calculation, formatting, measurement, and copying before reading any subsequent byte. Each completed subsequent group likewise invokes dependencies before traversal continues. Those calls are not established to preserve unread encoded bytes or their lifetime. The destination may also overlap the encoded storage.

An entry-time byte sequence therefore determines later components only under an additional preservation assumption.

### Initial group

The traversal index and unsigned accumulator begin at zero.

While the index is less than the saved signed count, the function reads the current byte and combines its low seven bits into the accumulator using bitwise OR.

- If the high bit is clear, the initial group ends at that index without another shift.
- If the high bit is set, the accumulator is shifted left by seven bits, the index advances, and the count comparison is repeated.

A completed multibyte group therefore incorporates each continuation byte before shifting and incorporates its terminating byte without a following initial-group shift.

Accumulation is limited to 32 bits. Long groups can lose high-order information; no excessive-length or overflow error is reported.

If the saved count is zero or negative, no encoded byte is read and the accumulator remains zero. Initial formatting nevertheless occurs.

If every available byte has its high bit set, the last byte is incorporated and shifted before exhaustion is detected. The incomplete initial group is still formatted.

### Subsequent groups

After initial-fragment processing, the accumulator is reset to zero.

The traversal index is incremented before each subsequent count comparison. If the initial group terminated normally, the next read therefore addresses the byte following its terminator.

Each byte contributes its low seven bits through bitwise OR. A clear high bit completes a subsequent group. For each completed group:

1. F-ff84c77c15bc receives the reused scratch region, size 26, the subsequent format descriptor, the accumulated value, and the second component retained from initial construction.
2. F-1cb585febd84 measures the scratch contents.
3. F-c73847cd39ec is invoked only if remaining capacity is strictly positive.
4. Remaining capacity is reduced by the measurement.
5. The destination advances by the measurement.
6. The measurement is added to the numeric total.
7. The accumulator is reset to zero.

After every processed subsequent byte, the accumulator is shifted left by seven bits. For a terminating byte, formatting and reset occur first, so this shift acts on zero.

The subsequent copy invocation visibly supplies destination and scratch arguments, but no capacity argument. Its complete calling contract is unresolved; the capacity supplied on other paths cannot be assumed to apply here.

An incomplete subsequent group at exhaustion is not formatted, measured, copied, or added to the total. This differs from an incomplete initial group.

### Capacity and continued processing

Remaining capacity gates only each subsequent copy request. It does not gate formatting, measurement, bookkeeping, destination advancement, or total accumulation.

The gate is evaluated before subtracting the current measurement:

- Zero or negative capacity skips that fragment’s copy.
- A negative measurement can subsequently restore positive capacity.
- Restored capacity can enable copying for a later completed group.
- It does not retroactively enable the skipped copy.
- Positive capacity permits a copy request even when the measurement is negative or exceeds that capacity.

Permanent suppression after exhaustion follows only if later measurements are nonnegative and arithmetic remains defined.

## Acceptance examples

These are conditional static acceptance cases, not runtime results. Each assumes valid required accesses, valid dependency execution, and defined arithmetic. Byte values refer to values observed at their respective reads, not merely to an entry-time storage snapshot.

1. **Nonpositive capacity.** Capacity zero or negative returns zero without object-field reads, destination writes, or dependency calls, even if the supplied addresses cannot safely be dereferenced.

2. **Missing object.** Positive capacity and a null object cause the single direct zero-byte destination write and return zero. No dependency is called.

3. **Initially null data pointer.** A nonnull object whose first offset-16 read yields zero takes the fallback without lookup.

4. **Preferred lookup text.** Nonzero lookup and preferred-text results bypass fallback and numeric processing. Copying precedes measurement, whose result is returned.

5. **Null fallback text.** If both text providers return zero, zero is passed to copying and measurement. Safe empty output is not guaranteed.

6. **Single initial byte.** With lookup zero, saved count 1, and the byte read as 5, the initial accumulator is 5. F-d7be9cfb4000 receives 5 and 40. If it returns zero, initial formatting receives components 0 and 5. No subsequent byte is read.

7. **Multibyte initial group.** With saved count 2 and successive reads yielding 129 and 2, the initial accumulator is 130. Both bytes belong to the initial group.

8. **Completed subsequent group.** With saved count 2, an initial read yielding 5 and the later second-byte read yielding 3 produce an initial fragment and a subsequent fragment for value 3. Both measurements contribute to the total regardless of whether the subsequent copy is requested. An entry-time sequence of 5 and 3 establishes this outcome only if intervening dependencies and overlapping writes leave the unread byte unchanged.

9. **Incomplete subsequent group.** With saved count 2, an initial read yielding 5 and the later second-byte read yielding 129 produce only the initial fragment. The trailing incomplete group contributes no measurement. An entry-time sequence of 5 and 129 alone does not establish this outcome because intervening calls may change the second byte.

10. **Persistent copy suppression.** If the initial measurement exhausts capacity and every later measurement is nonnegative, subsequent copies remain skipped. Formatting and measurement continue.

11. **Capacity recovery.** Initial capacity 1 and initial measurement 1 leave capacity zero and advance the destination by one. A subsequent measurement of −1 has its copy skipped, then restores capacity to 1 and moves the destination back by one. A following completed group requests copying if execution reaches it.

12. **No initial bytes.** A saved count of zero or a negative count causes no encoded-byte reads, but still triggers initial component calculation, formatting, measurement, and copying.

13. **Incomplete initial group.** Saved count 1 and a byte read as 129 produce accumulator 128 after shifting. Initial formatting proceeds despite the absent terminator.
