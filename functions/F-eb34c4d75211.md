# F-eb34c4d75211

## Purpose

F-eb34c4d75211 maps one 32-bit input word to a 32-bit result. Most paths compute the result directly from the input. A restricted class of inputs instead selects an unresolved indirect dependency, with its explicit arguments determined by a shared control word and, on some paths, additional shared words.

The input’s bit partition and several thresholds are consistent with an unsigned conversion of a binary32 floating-point encoding. This is **inferred intent**, not an established interface guarantee. The supplied representation uses integer operations, does not establish a floating-point type for the input, and does not establish all shift or indirect-transfer semantics needed to promise a complete numeric conversion.

This contract distinguishes:

- **Established static evidence:** branches, constants, arithmetic dependencies, explicit shared-state reads, and displayed return values.
- **Conditional interpretation:** results that depend on 32-bit arithmetic, sign-propagating right shifts, or unresolved machine shift behavior.
- **documented_only unknowns:** dependency identity, indirect-transfer fidelity, shared-state ownership, and behavior not recoverable from the supplied material.

No runtime tests have been performed.

## Behavior

### 1. Construct the initial candidate

The function first obtains a 32-bit word from the input shifted right by 23 positions. Under the sign-propagating interpretation, call this derived value \(e\).

It also constructs a candidate word by shifting the input left by eight positions, retaining the low 32 bits. If \(e\) is nonzero, it sets bit 31 of that candidate.

The decision to set bit 31 depends on the entire derived value, not on a separately masked eight-bit exponent field. For negative inputs, the sign-propagating interpretation makes \(e\) nonzero.

These computations do not visibly access shared state.

### 2. Apply the sign-dependent early paths

If the signed interpretation of \(e\) is negative, the function compares the doubled input bit pattern, modulo \(2^{32}\), against `0x7F000000` as unsigned.

- If the doubled word is strictly smaller, the function returns zero.
- Otherwise, it proceeds to the classification in the next subsection.

If the signed interpretation of \(e\) is nonnegative, the function compares \(e\), as unsigned, against `0x9F`.

- If \(e < \texttt{0x9F}\), it returns the initial candidate shifted right logically.
- Otherwise, it proceeds to the next classification.

The shift count for that early nonnegative return is:

\[
(158-e)\mathbin{\&}255.
\]

For nonnegative 32-bit inputs on this branch, \(e\) ranges from 0 through 158. Consequently, the displayed count ranges from 158 down to 0.

Counts below 32 have an ordinary 32-bit logical-shift interpretation. **Counts of 32 or greater are documented_only:** the supplied material does not establish whether the executing machine produces zero, masks the count, or applies another rule. The eight-bit mask does not resolve this issue. A portable promise that every such input returns zero would exceed the evidence.

### 3. Classify inputs that did not return early

The function computes the input multiplied by two and interprets the retained 32-bit result as unsigned.

If that result is below `0xFF000001`, the function returns the 32-bit complement of the input shifted right by 31 positions.

A displayed equality check distinguishes doubled input `0xFF000000`, but both outcomes return the same expression. It does not establish a different error code or result for that boundary.

Under sign-propagating right-shift semantics:

- A nonnegative input reaching this path returns `0xFFFFFFFF`.
- A negative input reaching this path returns `0x00000000`.

No shared-state read or indirect dependency invocation is visible on these direct-return paths.

If the doubled input is at least `0xFF000001`, execution enters shared-state dispatch. Because doubling modulo \(2^{32}\) produces an even word, the smallest reachable doubled word in this class is `0xFF000002`.

Under an IEEE 754 binary32 interpretation, this dispatch class corresponds to NaN encodings of either sign. That interpretation is useful context, not a guarantee that the input is supplied as a floating-point object.

### 4. Select an indirect-dependency path

The function reads the control word and retains its low four bits as the selector.

Later flag tests are represented as additional control-word reads. The contract does not collapse those observations into one immutable snapshot. Without a synchronization or immutability guarantee, the low-nibble selection and later flag decisions need not reflect identical control-word contents.

All displayed indirect transfers use a target formed by clearing the lowest two bits of the inherited link-state value. Their representation as ordinary calls is uncertain; see **Dependencies**.

#### Selector nine

The function reads the control word to test bit 20, whose mask is `0x00100000`.

- If that bit is clear, the displayed dependency invocation has one explicit argument: zero.
- If that bit is set, the displayed invocation has two explicit arguments:
  1. The value eight.
  2. A value derived from another control-word read by shifting that word left 15 bits, complementing the resulting word, and then shifting left one bit.

Under the 32-bit interpretation, the second argument is:

\[
2\cdot\left(\operatorname{NOT}_{32}
\left((C\cdot2^{15})\bmod2^{32}\right)\right)\bmod2^{32},
\]

where \(C\) is the control word observed for that argument calculation.

The function returns the result attributed to the dependency invocation.

#### Selector eight

The function reads the control word to test bit 6, mask `0x00000040`.

If that bit is set, the displayed dependency invocation has two explicit zero arguments.

If that bit is clear, the visible order is:

1. Read the default argument word.
2. Read the control word to test bit 4, mask `0x00000010`.
3. If bit 4 is clear, invoke the dependency with the default argument word and the doubled input word.
4. If bit 4 is set, read the alternate argument word and invoke the dependency with zero and that alternate word.

The default argument word is therefore read even when bit 4 subsequently causes its value to be discarded. Whether that read has externally observable hardware or synchronization effects is unknown.

The function returns the result attributed to the dependency invocation.

#### Selector ten

The visible order is:

1. Read the mode-ten argument word.
2. Read the control word to test bit 6.
3. If bit 6 is clear, use the previously read word as the sole explicit argument.
4. If bit 6 is set, replace it with `0x80000000`.

The shared argument word is read even when the flag overrides its value. The function returns the result attributed to the dependency invocation.

#### All other selectors

The displayed dependency invocation supplies no explicit arguments. The function returns its attributed result.

“No explicit arguments” does not establish that argument registers or other machine state have been cleared.
