# F-c423733eb93d

## Purpose

F-c423733eb93d performs a machine-state-dependent conditional prefix, then enters a repeating sequence of two indirect calls and a software interrupt.

The established behavioral split is:

- A nonzero first argument bypasses all conditional prefix memory accesses.
- A zero first argument causes an initial 16-bit transfer, provided the required memory accesses complete.
- Further arithmetic conditions may permit a second halfword operation. Its source accesses necessarily use address zero.
- No displayed execution reaches the later pointer extraction, paired 32-bit stores, or final conditional writes.
- Every path that completes the reachable prefix enters the repeating dispatch sequence. No normal return is represented.

No application-level purpose, validated data format, ownership protocol, or recoverable error interface is established.

The absence of explicit uses of the second and third arguments does not establish a complete calling convention. Their relationship to incoming register state is unspecified.

## Behavior

### Arithmetic and address interpretation

This contract uses unsigned 32-bit modular arithmetic for ordinary address representations, additions, subtractions, and products, unless a narrower width is stated. Halfword reads and writes are 16 bits.

This interpretation supports the reachability deductions below. It is not a claim that every displayed signed cast or pointer expression has portable language-level semantics.

Offsets are distinguished by unit:

- The initial transfer displacement is measured in bytes.
- The later link-address advancement is 64 times the fifth argument’s storage address, measured in bytes.
- The first dispatch target is the dispatch base plus `0xEB6` bytes.

A loaded unsigned halfword used as an address is zero-extended to 32 bits. A halfword value increased by fifteen and written as a halfword is reduced modulo \(2^{16}\).

### Nonzero first argument

A nonzero first argument bypasses the entire conditional prefix.

No prefix load, store, or special machine-state assignment occurs. The initial dispatch base remains the incoming link address. The first argument is not explicitly dereferenced on this path.

### Zero first argument: initial transfer

A zero first argument activates arithmetic preparation and a halfword transfer.

The replacement first quantity is formed from:

- The incoming link address.
- The incoming carry bit.
- The fifth argument’s storage address, logically shifted right by one.
- The address-shaped numeric operand.

The first three components are added. The resulting 32-bit intermediate is multiplied by the numeric operand and then added once more to that product. Equivalently, under the stated modular interpretation, the intermediate is multiplied by one plus the numeric operand.

The arithmetic accumulators are then updated:

- The first accumulator increases by the fourth argument.
- The second accumulator increases by the address-shaped numeric operand.
- The third accumulator increases by the paired addend.

The transfer destination is the initial halfword source address plus the incoming byte displacement. The observable memory ordering is:

1. Read one unsigned 16-bit value from the initial source.
2. Derive an adjusted address by subtracting the address-comparison operand from the transfer destination.
3. Write the previously read 16-bit value to the transfer destination.

The adjusted-address calculation is not another memory access. The source and destination may alias; aliasing does not eliminate the represented read or write.

After the transfer, the modeled carry is cleared. The incoming link address becomes the next gate value.

This transfer precedes every later gate. A failed later comparison does not undo it.

### First comparison sequence

Progress beyond the initial transfer requires the incoming link address to be zero. A nonzero incoming link address skips the remaining prefix and proceeds to dispatch with that incoming address as the base.

When the incoming link address is zero, the sequence conditionally requires:

1. The replacement first quantity to be zero.
2. The fourth argument to equal that replacement quantity.
3. The updated first accumulator to equal the address-shaped numeric operand.
4. The updated second accumulator to equal the paired addend.
5. The updated third accumulator to equal the byte displacement.
6. The adjusted transfer address to equal the address-comparison operand.

Each comparison is reached only if its predecessor succeeded.

The displayed exclusive-or comparisons include shifts controlled by the preceding result’s low eight bits. Every reached comparison has a zero preceding result, so every such shift count is zero. These shifts preserve the cleared carry.

Consequently, passing this entire sequence establishes both:

- Replacement first quantity: zero.
- Fourth argument: zero.

These are required values, not merely possible examples.

### Addition gates

After all first-sequence comparisons pass, two additions must each produce a zero 32-bit result.

The first combines the additional arithmetic addend, half the fourth argument, and the current carry. Because the fourth argument and carry are already zero, passing this gate requires the additional addend itself to be zero. Its resulting carry is also zero.

The second combines the fifth argument’s storage address with twice the byte displacement and the preceding carry. Thus its zero-result requirement is that the storage address plus the doubled displacement equal zero modulo \(2^{32}\).

The carry calculated by this second gate does not affect any reachable later decision: the following block clears it before the next comparison sequence.

Failure of either addition gate skips the remaining prefix without performing the zero-address halfword operation.

### Zero-address halfword operation

If both addition gates succeed, the displayed behavior:

- Assigns the special machine-state location a value derived from 64 times the fifth argument’s storage address.
- Forms an advanced link-derived address by adding that same byte quantity to the old link address.
- Performs a halfword update whose source references use the old link address.
- Increases the fourth argument by two.
- Clears carry.
- Replaces the working link address with the advanced address.

Reaching this block requires the incoming link address to be zero. The halfword source references therefore necessarily access **address zero**, not an arbitrary caller-selected nonzero address.

The operation uses an unsigned halfword obtained from address zero as the destination address. It stores a halfword value obtained from address zero plus fifteen, truncated to 16 bits.

The expression contains repeated source references. Static evidence does not establish the exact hardware load count or evaluation order between the source evaluations. If the source is stable, a value \(v\) at address zero produces a halfword store of \((v+15)\bmod 2^{16}\) at address \(v\). If reads can return different values, equality between the destination-selecting value and the incremented value is not guaranteed.

The store must follow the source evaluations needed to determine its address and data. It may itself target address zero.

Continuation requires environment-specific semantics permitting the source accesses at address zero, as well as the derived destination store. Ordinary null-pointer validity cannot be assumed. The representation supplies no fault recovery.

The advanced link-derived address is 64 times the fifth argument’s storage address modulo \(2^{32}\), because the old link address is necessarily zero.

### Forced failure of the second comparison sequence

After this block completes, the replacement first quantity remains zero and the fourth argument is exactly two.

There are two cases:

- If the advanced link-derived address is nonzero, the second comparison sequence is not entered.
- If it is zero, the first comparison succeeds because the replacement first quantity is zero. The second comparison then evaluates the exclusive-or of two and zero, producing two rather than zero.

The second comparison sequence therefore cannot pass. Its later comparisons and every subsequent conditional operation are unreachable under the stated arithmetic interpretation.

This is a deduction from the displayed control flow and value changes, not an unresolved question of whether sufficiently unusual inputs could satisfy the later gates.

### Unreachable displayed operations

The representation contains additional arithmetic gates, a character-dependent pointer extraction, paired pointer-shaped stores, and final conditional writes. None belongs to the reachable behavioral contract.

In particular, the function cannot, through the displayed control flow:

- Execute the self-counted left shift in the later arithmetic gate.
- Read the special machine-state location in the later extraction gate.
- Extract a 32-bit value through the character-derived address.
- Read a signed halfword through the replacement first quantity and store its sign-extended value in the paired-store phase.
- Perform the final signed-halfword-derived pair of 32-bit writes.
- Apply the later thirteen-byte or twenty-seven-byte adjustments to the dispatch base.

The displayed paired stores occupy adjacent four-byte slots, and their first value is represented as a sign-extended halfword. Those are properties of unreachable displayed operations, not achievable side effects or acceptance scenarios.

### Repeating dispatch

After the reachable prefix completes, the function repeatedly performs:

1. Call **F-ext-01** at the current dispatch base plus `0xEB6`, supplying three 32-bit argument patterns: `0x00000000`, `0x00000000`, and `0xFFFFFFA5`.
2. If that call returns, call **F-ext-02** at computed address `0x0857A94B`. No explicit arguments are shown.
3. If that call returns, request **F-ext-03**, software interrupt `0x5B`.
4. If the interrupt returns, set the dispatch base to `0x083D4CC2` and repeat.

The first call uses the computed address directly. No intervening load of a function pointer from that address is shown.

For the first iteration, the base is:

- The incoming link address if the zero-address operation was not completed.
- The advanced link-derived address if that operation completed.

Every subsequent iteration reached after the base reset calls F-ext-01 at `0x083D5B78`.

A nonreturning call or interrupt prevents the remaining actions of that iteration. The body contains no alternate normal exit.

## Acceptance examples

These are conditional static criteria. No runtime observations are asserted.

1. **Nonzero first argument.**  
   Given a nonzero first argument, no prefix memory access or special assignment occurs. The first dispatch call targets the incoming link address plus `0xEB6`.

2. **Zero first argument, nonzero incoming link address.**  
   If the initial transfer accesses complete, the source halfword is written to the calculated destination. The remaining prefix is skipped, and dispatch retains the incoming link-address base.

3. **Aliased initial transfer.**  
   With zero byte displacement, the initial transfer reads and writes the same halfword location. The read precedes the write.

4. **First comparison fails.**  
   Given zero first argument and zero incoming link address, a nonzero replacement first quantity fails the first comparison. The initial transfer has already occurred. No zero-address update follows, and the first dispatch target is `0xEB6`.

5. **Zero-address source operation.**  
   If all first-sequence comparisons and both addition gates pass, the later source references use address zero. Continuation is conditional on the environment permitting those accesses; the contract does not treat them as an ordinary valid-pointer case.

6. **Stable zero-address halfword.**  
   If that block is reached, all source evaluations return `0xFFFF`, and the destination store is permitted, the halfword store places `0x000E` at address `0x0000FFFF`.

7. **Second sequence cannot complete.**  
   If the zero-address block completes and its advanced link-derived address is zero, the next sequence’s first comparison succeeds and its second comparison fails with result two. No later extraction or 32-bit store occurs.

8. **Dispatch continuation.**  
   If both indirect calls and the interrupt return, the next iteration targets `0x083D5B78` for F-ext-01. If F-ext-01 does not return, F-ext-02 and the interrupt are not reached in that iteration.

## Evidence

This contract rests solely on static examination of the supplied representation. Embedded prior prose and feedback are not independent behavioral evidence.

The reachability conclusion follows from explicit value constraints: the first comparison sequence requires both the replacement first quantity and fourth argument to be zero; the zero-address block leaves the former unchanged and increases the latter to two; the second comparison sequence therefore cannot pass.

The forced address-zero source access follows independently: entry to that block requires the original incoming link address to be zero, and the source references precede replacement of that working address.
