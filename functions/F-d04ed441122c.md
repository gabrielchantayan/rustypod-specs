# F-d04ed441122c

## Purpose

F-d04ed441122c examines a discriminator in an input record and conditionally invokes operations associated with a receiver.

Two discriminator values have defined behavior:

- **0x0000000F:** compare a record field against two addresses derived from the receiver. A match invokes F-1c60e26b3436 with a corresponding selector and produces a return value of 1.
- **0x00050006:** perform a service query, conditionally invoke F-1c60e26b3436, perform two indirect receiver operations, and optionally notify another object. This path returns 0 even when it performs those operations.

Other discriminator values cause no dependency calls and return 0.

These statements describe the supplied static evidence. An event-handler interpretation is plausible, but event names, application purpose, and the meaning of the return value are not established.

## Interface

### Inputs

The function accepts two 32-bit values used as addresses:

| Input | Role |
|---|---|
| Receiver address | Base address used to derive an embedded dispatch receiver and two comparison addresses; also passed to F-1c60e26b3436. |
| Record address | Base address of a record containing a discriminator and an address-like comparison field. |

The relevant record layout is:

| Byte offset | Width | Observed use |
|---|---:|---|
| +0x04 | 32 bits | Discriminator, compared with 0x0000000F and 0x00050006. |
| +0x08 | 32 bits | Compared with receiver address +0x6C and receiver address +0x98, only on the 0x0000000F path. |

No record field at offset zero is accessed by the supplied body.

The relevant receiver layout is:

| Byte offset | Observed use |
|---|---|
| +0x48 | Address of an embedded dispatch receiver. Its first 32-bit word supplies a dispatch-table address. |
| +0x6C | Derived address used for equality comparison, not directly dereferenced by this function. |
| +0x98 | Derived address used for equality comparison, not directly dereferenced by this function. |

Each observed indirect dispatch uses the function pointer at byte offset **+0x58** within a dispatch table. The same table offset is used on different objects; that does not establish a shared operation or signature.

### Output

The result is a 32-bit value:

- **1** after a recognized address match on the 0x0000000F path, provided the ensuing dependency call returns normally.
- **0** on every other normally returning path.

The result does not propagate dependency return values. In particular, 0 does not establish that no action occurred or that an operation failed.

### Shared values

Four externally stored values are used as arguments on the 0x00050006 path. For this contract, they are labeled:

- **Shared A:** used by both embedded-receiver operations, with a captured value used by the second.
- **Shared B:** an additional argument to the first embedded-receiver operation.
- **Shared C:** an additional argument to the second embedded-receiver operation.
- **Shared D:** an additional argument to the optional final notification.

These labels identify distinct storage locations, not their contents or semantic types. The representation is consistent with 32-bit argument values; whether any value is a pointer, integer, identifier, or handle is unknown.

### Preconditions and validity

The caller must provide storage sufficient for every access on the path actually taken:

- The discriminator field must be readable.
- The comparison field must be readable if the first discriminator read equals 0x0000000F.
- On the 0x00050006 path, returned objects, dispatch tables, function entries, embedded receiver storage, and shared argument storage must support the accesses and calls described below.

There are no explicit null, bounds, alignment, or dispatch-entry checks except for the final optional object check.

Addresses and accessed words are represented at 32-bit width. The source uses fixed byte-offset address formation, not element-scaled indexing. Behavior at address-space boundaries, on arithmetic overflow, or for misaligned accesses is not established. A portable valid-input contract should require the derived addresses to be representable and the accessed storage to be valid rather than assume wrapping or trapping behavior.

## Behavior

### 1. Discriminator selection

The function first reads the 32-bit discriminator at record offset +0x04.

If that read equals **0x0000000F**, execution proceeds directly to address matching.

Otherwise, the function reads the same discriminator field again and compares that second value with **0x00050006**:

- If equal, execution proceeds to the service-and-notification sequence.
- If unequal, the function returns 0 without calling a dependency.

The two reads are distinct in the supplied representation. The function does not establish a stable snapshot of the record. If the discriminator changes between reads, the second read controls only the 0x00050006 comparison; it does not restart selection for 0x0000000F.

### 2. Address matching for discriminator 0x0000000F

The function reads the 32-bit comparison field at record offset +0x08 and compares it with the receiver address plus **0x6C**.

If equal:

1. It invokes F-1c60e26b3436 with the receiver address and selector **0x00000000**.
2. If that invocation returns normally, it returns **1**.

If the first comparison does not match, the function reads the comparison field again and compares this new value with the receiver address plus **0x98**.

If the second comparison matches:

1. It invokes F-1c60e26b3436 with the receiver address and selector **0x0000000E**.
2. If that invocation returns normally, it returns **1**.

If neither comparison matches, it returns **0** without calling a dependency.

Consequences:

- The +0x6C match has precedence.
- A successful first comparison avoids the second comparison-field read.
- The compared receiver-relative addresses are not dereferenced by this body.
- The second comparison may observe a different record-field value from the first.
- The return value of F-1c60e26b3436, if any, is ignored.

### 3. Service-and-notification sequence for discriminator 0x00050006

This path performs the following stages in order.

#### 3.1 Acquire and query the first service object

The function invokes **F-cdd33263ee89** with no explicit arguments shown.

Its result is treated as an object address. Without checking that address for null, the function:

1. Reads the object’s first 32-bit word as a dispatch-table address.
2. Obtains the callable entry at table byte offset +0x58.
3. Invokes that entry with no explicit arguments shown in the supplied representation.
4. Compares the 32-bit result with zero.

A zero result causes a call to **F-1c60e26b3436** with the receiver address and selector **0x00000017**.

A nonzero result skips that call.

Either result proceeds to the embedded-receiver operations if all invoked dependencies return normally. The selector-0x17 call is therefore not an early-return path.

The lack of explicit arguments on the first indirect invocation is not enough to establish its complete machine-level calling convention or whether the callable uses implicit context.

#### 3.2 Capture a shared argument and perform the first embedded-receiver operation

After the service query and any selector-0x17 call, the function captures the current value of **Shared A** for later use.

It then performs an indirect call through the embedded receiver at receiver address +0x48:

- The embedded receiver’s first word supplies the dispatch-table address.
- The callable is obtained from table offset +0x58.
- The explicit arguments are:
  1. The embedded receiver address.
  2. A read of Shared A for this first call.
  3. Shared B.

The initial capture of Shared A is separate from its use as an argument to this first operation. In ordinary stable storage, both reads yield the same value. The evidence does not establish that the storage cannot change between reads.

The first embedded operation’s return value is ignored.

#### 3.3 Perform the second embedded-receiver operation

After the first embedded operation returns, the function performs another indirect call through the embedded receiver at receiver address +0x48.

It obtains the dispatch information again rather than using a previously captured callable. The explicit arguments are:

1. The embedded receiver address.
2. The value of Shared A captured before the first embedded operation.
3. Shared C, read for this second operation.

This distinction is observable if the first operation changes relevant state:

- A change to the embedded receiver’s dispatch-table pointer can affect the second call’s target.
- A change to Shared A does not replace the second call’s captured Shared A argument.
- A change to Shared C can affect the second call’s third argument.

The second embedded operation’s return value is ignored.

#### 3.4 Obtain and optionally notify another object

After both embedded operations, the function invokes **F-ac356e5603c7** with no explicit arguments shown.

If its result is null, the notification is skipped.

If its result is non-null, the function:

1. Reads the returned object’s first word as a dispatch-table address.
2. Obtains the callable at table offset +0x58.
3. Invokes it with the returned object address and Shared D.

The notification’s return value is ignored.

After this stage, the function returns **0**, provided execution has returned normally from all dependencies.

## Side effects

### Direct effects

The supplied body performs reads and dependency calls. It contains no explicit store into the receiver, input record, shared argument storage, or returned objects.

This is not a claim that those locations remain unchanged. Dependencies may mutate them, mutate unrelated state, reenter other code, or have externally visible effects.

No allocation, release, ownership transfer, or reference-count adjustment is directly visible.

### Observable ordering

The established sequencing is:

- Discriminator selection occurs before dependency calls.
- On the address-match path, the matching comparison precedes F-1c60e26b3436, which precedes return value 1.
- On the 0x00050006 path, the first service acquisition and query precede any selector-0x17 call.
- Any selector-0x17 call completes before Shared A is captured.
- The first embedded operation completes before the second operation’s dispatch lookup and call.
- Both embedded operations complete before F-ac356e5603c7 is invoked.
- The optional final notification completes before return value 0.

The supplied expression structure does not establish a complete ordering among argument-value reads and dispatch-related reads within an individual call expression. No stronger concurrency, atomicity, or memory-ordering guarantee is evidenced.

### Errors and abnormal completion

There is no visible error reporting, exception handling, rollback, or cleanup.

Invalid addresses, invalid dispatch entries, or dependency failures are not converted into a defined error result by this body. If a dependency does not return normally, the stated final return value is not reached.

## Acceptance examples

These are conditional expectations derived from static evidence, not executed tests. Each example assumes valid storage and normal return from invoked dependencies.

1. **First address match**

   The initial discriminator read is 0x0000000F, and the first comparison-field read equals receiver +0x6C.

   Expected: one call to F-1c60e26b3436 with selector 0, followed by return value 1. No second comparison-field read or service sequence occurs.

2. **Second address match**

   The initial discriminator read is 0x0000000F. The first comparison does not match receiver +0x6C; the second read matches receiver +0x98.

   Expected: one call to F-1c60e26b3436 with selector 14, followed by return value 1.

3. **No address match**

   The discriminator selects address matching, but neither comparison matches.

   Expected: return value 0 and no dependency calls.

4. **Service query returns zero**

   The discriminator selects 0x00050006, and the first indirect query returns zero.

   Expected call order: F-cdd33263ee89; its indirect query; F-1c60e26b3436 with selector 23; two embedded operations; F-ac356e5603c7; an optional notification if its result is non-null. Final return value: 0.

5. **Service query returns nonzero**

   The same path is selected, but the query returns any nonzero 32-bit value.

   Expected: selector 23 is not dispatched. Both embedded operations and the final object lookup still occur.

6. **Shared values change during the first embedded operation**

   Shared A is captured as value A₀. The first embedded operation changes Shared A to A₁ and Shared C to C₁.

   Expected: the second embedded operation receives A₀ as its second explicit argument and C₁ as its third, assuming no further changes. It does not substitute A₁ for the captured value.

7. **Final lookup returns null**

   Both embedded operations complete, and F-ac356e5603c7 returns null.

   Expected: no final indirect notification; return value 0.

8. **Discriminator changes between reads**

   The first discriminator read is neither recognized value, and the second read is 0x00050006.

   Expected: the service sequence runs. Conversely, if the second read is 0x0000000F, address matching does not run; the function returns 0.
