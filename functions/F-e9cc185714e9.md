# F-e9cc185714e9

## Purpose

F-e9cc185714e9 is represented as a four-input, non-returning sequence of indirect calls and memory operations. The visible sequence:

- Stores the first input at an address derived from the second input.
- Passes portions of a word associated with the first input to an unresolved dependency.
- Uses dependency results to compute further addresses and values.
- Performs several word stores and two byte stores.
- Ends at an explicitly reported invalid-instruction boundary rather than a normal return.

No application-level purpose is established. In particular, the evidence does not establish that the computed addresses identify allocated objects, that the values are handles, or that the byte stores implement a particular encoding.

This contract describes the visible static sequence, conditional on execution reaching each operation. The supplied representation warns about invalid instruction data; consequently, the sequence is not an independently validated executable specification.

## Acceptance examples

These are conditional static acceptance examples, not runtime test results. Each assumes valid accessed memory, returning dependencies, and the stated arithmetic interpretation.

1. **Initial aliasing.** If the first input equals the second input scaled by four, the initial store destination and both initial word-read addresses coincide. The store must precede those reads. The reads must not be described as reading a pre-store snapshot.

2. **Different store and read scales.** If selection 6 is 3, payload 3 is 12. The word store is at address 68, while the captured-word read is at address 32. Treating both as address 68 violates the visible addressing behavior.

3. **Unsigned captured-word shift.** If the captured word is hexadecimal F1234567, the later shifted-word store writes hexadecimal 000F1234, not a sign-extended value.

4. **Fourth-input truncation.** Under 32-bit shifts, a fourth input of 1 contributes hexadecimal 04000000 to F-d0000000000b. A fourth input of 64 contributes zero. No range validation is shown.

5. **First byte truncation.** If selection 10 is 65, its scaled value is 260 and the first byte store writes 4. If the preceding byte read yields 200, that store targets address 217.

6. **Second byte extraction.** If selection 10 is hexadecimal 3AB00000, the second byte store writes hexadecimal AB. The ten-bit intermediate is hexadecimal 3AB; retaining all ten bits in memory would violate the byte-store width.

7. **Byte-base changes.** If the first byte read yields 200 and the second yields 7, the byte-store destinations are 217 and 24 respectively. The final two-argument dependency receives 7 as its second argument, not 200.

8. **Failure ordering.** If the captured-word read faults, the immediately preceding word store has already been attempted. F-d0000000001f and all later calls are not reached through the visible sequence.

9. **Completion boundary.** If every call returns and every access completes, the expected visible endpoint is the invalid-instruction boundary, not successful normal return.
