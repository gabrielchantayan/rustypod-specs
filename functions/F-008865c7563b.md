# F-008865c7563b

## Purpose

F-008865c7563b advances a caller-supplied traversal state through indexed, inclusive numeric ranges. It seeks the next candidate whose calculated 32-bit mapped value is nonzero.

On success, it records the candidate, mapped value, and range index in the supplied state. If traversal is disabled by a sentinel or the search exhausts the available ranges, it clears a one-byte field.

The apparent intent is an iterator over ranges with linear mappings, skipping candidates mapped to zero. That interpretation is inferred. The established behavior is the arithmetic, traversal order, and memory updates described below; no particular application-level meaning is established for the candidates or mapped values.

## Interface

**Input:** one address identifying a readable and writable state object.

**Return:** no explicit value. The observable result consists of writes to the state object, or failure to return if the search does not terminate.

## Behavior

### Search gate and initial position

The function first reads the 32-bit field at `0x1C` and compares it with the all-ones sentinel.

If it equals the sentinel, the function does not inspect the range pointer, starting index, or index limit. It clears the byte at `0x18` and returns.

Otherwise, it reads the candidate field again and initializes a working candidate to the previous candidate plus one. The traversal thereafter uses unsigned 32-bit candidate values.

The displayed representation expresses this initial addition through a signed 32-bit value before assigning the result to an unsigned value. At a previous candidate of `0x7FFFFFFF`, the exact overflow semantics require confirmation from the executable. Ordinary machine-width wraparound would produce `0x80000000`; that boundary is not unconditionally established by the supplied representation alone.

The function then reads the unsigned starting index from `0x24`.

### Range traversal

Before processing each range, the function reads the unsigned index limit at `0x28`. The range is processed only if the working index is strictly less than that limit.

For each processed range:

1. The function reads the address field at `0x10` and calculates the entry anchor for the current index.
2. It reads and decodes the entry’s lower bound.
3. If the working candidate is less than that lower bound, it raises the candidate to the lower bound.
4. It tests candidates against the entry’s inclusive upper bound, looking for a nonzero mapped value.

The working candidate is retained across ranges. It is not reset to each range’s lower bound. Consequently, an earlier range can cause later ranges to begin above their own lower bounds or to be skipped entirely.

There is no validation that ranges are sorted, disjoint, nonempty, or compatible with the incoming candidate.

### Candidate evaluation

Before each candidate evaluation, the upper bound is read and decoded again. The candidate is evaluated only when it is less than or equal to that bound under unsigned comparison.

For an evaluated candidate \(c\), cached lower bound \(l\), and freshly decoded mapping origin \(b\), the mapped value is:

\[
m = (b + c - l) \bmod 2^{32}.
\]

The arithmetic has a 32-bit result. Carries and borrows do not extend the value beyond that width. Although the result is represented through a signed 32-bit temporary, only its equality or inequality to zero affects control flow. A high-bit-set result is accepted just as any other nonzero bit pattern is.

If \(m\) is nonzero, the function performs these writes in order:

1. The candidate to state offset `0x1C`, as 32 bits.
2. The mapped value to state offset `0x20`, as 32 bits.
3. The current range index to state offset `0x24`, as 32 bits.

It then returns immediately. It does not write the byte at `0x18` on this path. In particular, success does not establish that this byte is nonzero.

If \(m\) is zero, the function increments the working candidate by one using unsigned 32-bit arithmetic and tests the upper bound again.

### Moving to another range

When the candidate exceeds the current range’s upper bound, the function increments the unsigned range index and repeats the outer index-limit test.

The lower bound of the completed range is not read again. The candidate retains its current value, including any increments made while rejecting zero mappings.

If the index test fails, the function clears the byte at `0x18` and returns.

### Exhaustion and unusual boundaries

An initial index equal to or greater than the unsigned index limit produces immediate unsuccessful completion, without reading any range entry.

A range whose lower bound exceeds its upper bound is not diagnosed. After the candidate is raised to at least the lower bound, the unsigned upper-bound test ordinarily skips that range.

Candidate increment wraps from `0xFFFFFFFF` to zero. If a candidate of `0xFFFFFFFF` maps to zero while the upper bound is also `0xFFFFFFFF`, the next candidate is zero. The lower-bound adjustment is not repeated inside the same range, so the function can then evaluate candidates below that range’s lower bound.

This is not a saturating traversal. In the stable-memory case, an upper bound of `0xFFFFFFFF` cannot be exceeded by an unsigned 32-bit candidate. The function will leave such a range only by returning a nonzero mapped value, not by advancing past its upper bound.

A successful candidate of `0xFFFFFFFF` is stored normally. On the next invocation, that stored bit pattern triggers the sentinel path, clearing the byte at `0x18` without searching.

Termination is not guaranteed for mutable backing memory, invalid memory, or other violated preconditions. There is no explicit iteration limit or recovery path.

## Side effects

### State changes

On success, the only explicit writes are the three 32-bit result writes at `0x1C`, `0x20`, and `0x24`, in that order.

On sentinel rejection or search exhaustion, the only explicit write is zero to the byte at `0x18`. The previous candidate, mapped value, and saved index remain unchanged on that path.

In particular, unsuccessful traversal does not save its final working candidate or index. A subsequent invocation can repeat the search unless the caller changes the state.

### Read timing and consistency

The implementation does not take a single snapshot of the state or entries:

- The previous-candidate field is read for the sentinel test and again for initialization.
- The starting index is read once.
- The index limit is read on each outer-loop test.
- The entry address field is read for each range processed.
- The lower bound is decoded once per processed range.
- The upper bound is decoded on every inner-loop test.
- The mapping origin is decoded on every candidate evaluation.

The function therefore does not promise consistent results if another actor modifies these locations during traversal.

The representation establishes which logical reads precede candidate evaluation and result writes. It does not establish an externally observable order among the separate byte reads used to decode one big-endian integer.
