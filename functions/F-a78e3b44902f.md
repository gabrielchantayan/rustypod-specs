# F-a78e3b44902f

## Purpose

F-a78e3b44902f adapts a caller-provided record, output buffer, and integer to a single invocation of F-5ef10d079522. It passes the dependency an output address two bytes beyond the beginning of the buffer and the address of a local copy of the input integer. After normal dependency return, it derives a value from that local integer, converts the result to a signed 16-bit value, and writes the leading 16-bit output field.

The established behavior is structural. The meanings of the record fields, dependency-produced data, and leading field are unknown. Calling the leading field a length, status, count, or protocol header would be inferred intent, not an established contract.

Two arithmetic qualifications are independent:

- The left shift operates on a signed integer before conversion to an unsigned integer.
- The later conversion to signed 16-bit storage may encounter a value outside that type’s representable range.

Consequently, a fixed-width interpretation of the shift alone does not establish all possible stored bit patterns. No runtime tests have been performed.

## Behavior

The fourth input is copied into invocation-local signed integer storage. The dependency receives the address of this copy.

A dependency write through that address does not directly update a caller-owned integer object merely because the caller supplied the initial value. The adapter subsequently uses the local value present after normal dependency return.

If the dependency leaves the local integer unchanged, the original fourth input controls the final calculation. If the dependency changes it, the replacement value controls that calculation.

2. The value of record element 18.

No overflow check is visible, and behavior above the representable upper boundary is not established by the adapter.

### Post-call arithmetic

After the dependency returns normally, the function reads the local integer and applies these operations in order:

1. A signed left shift by 15 positions.
2. Conversion of that result to a 32-bit unsigned integer.
3. A logical right shift by 16 positions.
4. Conversion of the resulting unsigned value to a signed 16-bit value.
5. Storage of the converted result in the leading output field.

The unsigned conversion occurs after the left shift. It does not retroactively make that signed shift portable or defined.

### Signed-left-shift limitation

Under strict signed arithmetic semantics, the left shift is defined here only when its operand is nonnegative and multiplication by \(2^{15}\) remains representable in the signed 32-bit type.

That gives an operand range of 0 through 65,535 inclusive.

For this range, the later unsigned right shift produces the integer quotient on division by two:

\[
Q=\left\lfloor S/2\right\rfloor
\]

where \(S\) is the post-call local integer. The resulting \(Q\) ranges from 0 through 32,767.

Negative operands and operands above 65,535 do not have an established result under those strict signed-shift semantics. A fixed-width machine interpretation is possible, but it requires target evidence or an explicit conditional assumption.

### Final signed 16-bit conversion

The final conversion is a separate limitation, not a consequence resolved merely by choosing fixed-width shift behavior.

The unsigned value immediately before this conversion is at most 65,535 because it follows a logical right shift of a 32-bit value by 16 positions.

- Values from 0 through 32,767 are representable as signed 16-bit values. The conversion preserves their numeric value.
- Values from 32,768 through 65,535 are not representable as signed 16-bit values. Under the strict source-language conversion rules relevant here, the result is implementation-defined, or an implementation-defined signal may be raised.

There is therefore no unconditional guarantee that an out-of-range unsigned intermediate becomes the same low 16-bit pattern in storage. If a signal prevents execution from reaching the store, even completion of the leading-field write is not established.

For the defined signed-left-shift range of 0 through 65,535, the unsigned intermediate never exceeds 32,767. Those cases avoid the out-of-range conversion issue entirely.

### Conditional bit-selection interpretation

A broader bit-pattern rule is available only under both assumptions:

1. The left shift behaves as a 32-bit bit-vector shift, discarding bits beyond that width.
2. The final signed 16-bit conversion preserves the intermediate’s low 16-bit pattern and permits execution to continue through the store.

Under those assumptions, the stored field contains bits 1 through 16 of the post-call integer’s 32-bit pattern:

- Input bit 1 becomes stored bit 0.
- Input bit 16 becomes stored bit 15.
- Input bit 0 and bits 17 through 31 do not contribute.

Writing \(U\) for the unsigned interpretation of that 32-bit pattern, the resulting stored pattern is:

\[
H=\left\lfloor U/2\right\rfloor\bmod 65{,}536
\]

This describes a conditional storage pattern, not an unconditional signed numeric result. In particular, a pattern above 32,767 must not be presented as a representable positive signed 16-bit value.

No saturation or range validation is visible.
