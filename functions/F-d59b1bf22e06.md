# F-d59b1bf22e06

## Purpose

F-d59b1bf22e06 repeatedly transforms execution state through indirect dependency calls, byte writes, and 32-bit memory accesses. Dependency results determine addresses, stored values, subsequent call arguments, and state carried into the next iteration.

No application-level purpose is established. The visible accesses do not establish an object model, device protocol, allocation scheme, or ownership relationship.

The supplied representation contains an unconditional loop and no normal return. This contract describes its visible behavior without assuming that unresolved dependencies return, preserve memory, or preserve global state.

### Widths and notation

A **word** is 32 bits; a **byte** is eight bits. A represented wide result is 64 bits, with its low and high words distinguished explicitly.

Arithmetic descriptions below use the apparent target-width interpretation: multiplication and left shifts retain the low 32 bits, and unsigned right shifts insert zeros. Address calculations use those word-sized results. This is an interpretation of the recovered operations, not a claim that signed overflow or signed left shifts have portable language-level semantics.

A **selector-directed store through a base** consists of:

1. Reading one unsigned byte at base plus one.
2. Writing one byte at the selector’s numeric value plus 17.

The destination does not include the base. Its starting address is between 17 and 272 inclusive. Each such store performs a fresh selector read unless explicitly described otherwise.

The behavior sections introduce descriptive names for retained values. Those names distinguish dataflow roles and do not imply object identities.

## Behavior

### Ordering rules

The six phases below occur in order on every completed iteration. All described dependency calls remain observable, including calls without displayed arguments and calls whose displayed results are unused.

Where an acquisition is described as having three intervening calls, those three calls precede the result-producing call. No purity, preservation, or successful return is assumed for any of them.

### 1. Initial selector operations and first paired word update

The first dependency receives the current first argument. Four further calls follow; the fourth supplies an **initial index**.

A selector-directed store through the incoming base writes the low byte of the fourth argument masked with \(0x3fffffff\) and shifted right by 20.

The next dependency receives the incoming auxiliary value shifted left by 12. A following call supplies a word, which is passed to another dependency as its first argument; the second argument is the initial index shifted left by 30.

A subsequent call supplies a represented 64-bit result. Its low word and high word are passed, in that order, to the next dependency. One intervening call follows, then another call supplies a **clear-stage result**.

The function clears a freshly selected byte through the incoming base. Immediately after that selector-directed clear, the next dependency receives the clear-stage result shifted left by two. Three intervening calls then precede the call supplying the first paired-update payload source.

The **first payload** is that source shifted left by two. It is stored as a word at:

\[
16384 \times \text{initial index} + 20.
\]

The next dependency receives four arguments, in this order:

- Initial index multiplied by 4096.
- Initial index multiplied by 4096 again.
- Initial index shifted left by 14.
- First payload.

After three intervening calls, another call supplies a destination index. The same retained first payload is stored at four times that destination index plus 20. The next dependency receives four times that destination index.

### 2. Two propagation groups

Three intervening calls precede acquisition of a **first propagation index**. Four times that index is stored at sixteen times that index plus 20. The next dependency receives the scaled value in all three argument positions.

After three intervening calls, a destination index is obtained. The retained scaled value is stored at four times that destination index plus 20, and the next dependency receives four times the destination index.

A second propagation group follows the same structure:

- Three intervening calls precede acquisition of a **second propagation index**.
- Four times this index is stored at sixteen times the index plus 20.
- The scaled value is passed three times to a dependency.
- Three intervening calls precede acquisition of a **second propagation destination**.
- The retained scaled value is stored at four times that destination plus 20.
- Four times that destination is passed onward.

The second propagation index also establishes a **retained base** equal to the index multiplied by \(2^{30}\), under the stated word-width interpretation.

### 3. Direct clears, derived read, and retained result

After three intervening calls, a dependency supplies an **address-source word**.

The function directly clears the byte at retained-base-plus-17, then the byte at retained-base-plus-one. These are direct stores; neither reads a selector.

The next dependency receives the address-source word shifted left by two. A following result-producing call supplies a word that is forwarded to another dependency. Three intervening calls then precede acquisition of a **second clear-stage result**.

The same two direct byte clears are repeated, in the same order. Immediately afterward, a dependency receives the second clear-stage result shifted left by two. Only then do three intervening calls and a result-producing call supply the **retained slot index**.

At sixteen times the retained slot index plus 20, the function stores the second propagation destination shifted left by 31.

It next reads a word at:

\[
((\text{address-source word} \mathbin{\&} 0x3fffffff) \gg 20) + 20.
\]

The starting address ranges from 20 through 1043 inclusive. Alignment is not established.

The next dependency receives four times the retained slot index. A following call supplies a **retained result**, used later in both a word store and a call argument. Another dependency receives the loaded word shifted right by 22 and then left by 28. With 32-bit truncation, only loaded-word bits 22–25 contribute to that argument.

After three intervening calls, a call supplies another index. The word at four times that index plus 20 is cleared. The scaled index is passed to the next dependency.

The retained base is not reloaded between its direct-clear pairs. Dependencies can nevertheless change the addressed memory between those pairs.

### 4. Selector operations and captured-selector word store

After three intervening calls, a dependency supplies a **control word**.

A selector-directed store through the retained base writes the low byte of the control word shifted left by two. A dependency receives that same shifted word. Another call supplies a word, which is passed to a two-argument dependency together with the control word shifted left by 30.

After three intervening calls, another result is obtained. The selector byte at retained-base-plus-one is then read and **captured**. The function writes the low byte of the masked control word shifted right by 20 at captured-selector-plus-17.

The latest dependency result shifted left by two is passed onward. Four calls with no displayed arguments follow.

The function then stores the retained result from phase 3, shifted left by two, as a word at captured-selector-plus-20. This address uses the captured byte, not a new selector read. Its starting address ranges from 20 through 275 inclusive, and it need not be aligned.

### 5. Global-derived update and second paired word update

Immediately after the captured-selector word store, the function reads and retains the global word.

The first dependency after that global load receives **four times the retained slot index from phase 3**. This is the same scaled index passed to the phase-3 call immediately before acquisition of the retained result.

After three intervening calls, a dependency supplies a represented 64-bit result. Its low word becomes the **global-stage index**.

Before forwarding the high word, the function performs a fresh selector-directed store through the retained base. The byte written is the low byte of the saved global word shifted right by 22. The next dependency receives the wide result’s high word.

A subsequent call supplies a word that is passed to another dependency together with the global-stage index shifted left by 30. Three intervening calls precede acquisition of another clear-stage result.

A freshly selected byte through the retained base is cleared. The next dependency receives that clear-stage result shifted left by two.

Three intervening calls precede acquisition of an index. A dependency receives that index shifted left by two in both argument positions. After three more intervening calls, another result is acquired and shifted left by two to form the **second payload**.

The second payload is stored at:

\[
16384 \times \text{global-stage index} + 20.
\]

The next dependency receives the global-stage index shifted left by 16. After three intervening calls, a destination index is obtained. The retained second payload is stored at four times that destination index plus 20, and the next dependency receives four times that destination index.

The global is not reread for the selector value described above. Later dependency changes to global storage do not change the saved word. Conversely, if the preceding captured-selector word store overlaps the global, the subsequent global load observes storage after that store, subject to target memory semantics.

### 6. Final selectors and next-iteration state

After three intervening calls, a dependency supplies another represented 64-bit result. Its low word becomes the **next-base index**.

Before forwarding the high word, the function performs a selector-directed store through a base equal to the global-stage index shifted left by 16. The stored byte is the low byte of the second payload masked with \(0x3fffffff\) and shifted right by 20.

The high word is passed to a dependency. A subsequent call supplies a word that is forwarded to another dependency. A following call supplies another represented 64-bit result, whose low and high words are passed onward in that order.

One intervening call precedes acquisition of another result. A selector-directed clear is performed through the next-base index shifted left by 30. The acquired result shifted left by two is then passed onward.

Three intervening calls precede acquisition of the **final payload index**. The next incoming selector base becomes the next-base index shifted left by four. A selector-directed clear is performed through this new base.

The next dependency receives the next-base index shifted left by 12. A subsequent call supplies a word that is passed to a two-argument dependency; its second argument is the phase-3 retained result shifted left by 28.

After three intervening calls, another result is acquired. A freshly selected byte through the new base is cleared again. The next dependency receives that result shifted left by two, followed by four calls without displayed arguments.

The function stores the final payload index shifted left by 14 at:

\[
16384 \times \text{final payload index} + 20.
\]

That shifted value becomes both the next iteration’s fourth argument and its incoming auxiliary value.

A dependency receives the final payload index shifted left by 16. One call follows, then a two-argument call receives:

- The updated fourth argument shifted left by 28.
- An additional call-output register value whose defining ABI behavior is unresolved.

Under the stated 32-bit interpretation, the first argument is zero because the updated fourth argument already has fourteen trailing zero bits.

Three intervening calls precede acquisition of the closing result. Four times that result becomes the next first argument. The updated fourth argument is stored at that scaled address plus 20.

Execution then begins another iteration. The first indirect-call target uses the control-address state established at this loop tail.

## Acceptance examples

These are conditional static criteria, not executed tests. They assume returning dependencies, valid accesses, and the stated word-width interpretation.

1. **Byte narrowing.** A fourth argument of \(0x12300000\) produces an initial stored byte of \(0x23\), not the full extracted value \(0x123\).

2. **Initial clear-stage argument.** If the phase-1 clear-stage result is 3, the dependency immediately after the selector-directed clear receives 12. Payload-acquisition calls occur afterward.

3. **Second direct-clear argument.** If the result acquired immediately before the second direct-clear pair is 5, both clears occur before the next dependency receives 20.

4. **Retained phase-3 argument.** If the retained slot index is 7, the first dependency after the global load receives 28. The order is captured-selector word store, global read, then that invocation.

5. **Captured versus fresh selector.** A captured selector of 7 places the phase-4 word store at address 27. A dependency changing the selector storage to 9 before that store does not redirect it. A later fresh selector-directed byte store using 9 targets address 26.

6. **Paired payload preservation.** Each paired word-update group stores the same retained payload twice, despite acquiring its second destination later. Dependencies can independently change memory between those stores.

7. **Unaligned read.** An extracted phase-3 read offset of 1 requests a word at address 21. The body does not round it to an alignment boundary.

8. **Saved global.** Changing the global after its load does not change the retained value used for the global-derived selector byte.

9. **Access accounting.** A completed iteration contributes 14 explicit byte stores, 13 word stores, and 10 selector-byte reads, excluding dependency accesses.

10. **Continuation and failure.** Successful completion of the closing store leads to another iteration. A fault after an earlier write has no visible rollback guarantee.
