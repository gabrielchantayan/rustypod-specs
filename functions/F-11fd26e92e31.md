# F-11fd26e92e31

## Purpose

F-11fd26e92e31 searches an ordered table of 32-bit values for a nonzero value obtained from a dependency. It returns the zero-based index of the first matching entry, or the 32-bit sentinel `0xFFFFFFFF` when the dependency returns zero or the search reaches its current bound without finding a match.

This is a source-facing behavioral contract. Established behavior comes from the supplied static representation; no runtime tests have been performed. The application-level meanings of the context, dependency argument, and table entries are not established.

### Output

The result is an unsigned 32-bit value:

| Result | Meaning |
|---|---|
| `0x00000000` through `0xFFFFFFFE` | Index of the first matching entry reached by the search. |
| `0xFFFFFFFF` | The search value was zero, or the search terminated without a match. |

Index zero is a successful result, not an error indicator.

## Behavior

### Dependency resolution and initial read

F-8ff48652068d is called first, without explicit arguments. Its returned value is retained as the context address for the rest of this invocation.

The function then reads four bytes at context offset `0xF60` and calls F-fed763d460a8 with that value. The table base and bound are not read by this function before that call.

The context address is not reacquired afterward. If F-fed763d460a8 changes some external mechanism used to select the current context, this function still uses the address already returned by F-8ff48652068d. Conversely, changes that the dependency makes to memory at that retained address can affect the later search.

The result from F-fed763d460a8 is the search value. The supplied representation treats it as a signed 32-bit integer for the zero check and entry equality comparison. Negative nonzero values remain eligible search values; there is no positivity requirement.

### Zero-result branch

If F-fed763d460a8 returns zero, the function returns `0xFFFFFFFF`.

On this branch, the function does not read the table-base field, the bound field, or any table entry. A zero-valued entry in the table cannot produce a successful result because searching is bypassed when the search value is zero.

A zero value in the field at offset `0xF60` does not itself bypass F-fed763d460a8. That dependency is called with the field value regardless of whether it is zero.

### Search

For a nonzero search value, the search starts at unsigned index zero.

Before each candidate entry is examined, the current index is compared with the unsigned 32-bit bound at context offset `0xF68`. If the index is not less than that bound, the search ends and the function returns `0xFFFFFFFF`.

For an index that passes the bound comparison, the function obtains the table base from context offset `0xF64` and reads the four-byte entry at that base plus four times the index.

If the entry equals the search value, the function returns the current index immediately. Otherwise, the index advances by one and the next bound comparison is reached.

Consequences include:

- Entries are considered in increasing index order.
- The earliest matching entry reached is returned.
- No later entries are examined after a match.
- An empty range causes no table-base or table-entry read.
- The bound is exclusive: an entry whose index equals the bound is not examined.
- Equality, not ordering or magnitude, determines a match.

The static representation places the bound read in the loop condition and the table-base read in the candidate-entry access. It does not explicitly take a single snapshot of both fields before searching. For stable context memory, this is an ordinary first-match search over indices zero through bound minus one. Guarantees for concurrent mutation are not established.

### Width and arithmetic boundaries

The bound and index are unsigned 32-bit quantities. The bound comparison is therefore unsigned, including when the bound’s high bit is set.

The largest possible bound is `0xFFFFFFFF`. Even with that bound, index `0xFFFFFFFF` does not satisfy the exclusive comparison. Accordingly, the sentinel cannot also be a successful index.

The index need not wrap to finish a search: the largest eligible index is `0xFFFFFFFE`; after an unsuccessful comparison there, advancing to `0xFFFFFFFF` makes the next bound comparison fail for every representable bound.

The four-byte stride does not establish that every representable index has a valid address. Large bounds can require more addressable storage than the represented address width permits. Exact overflow, pointer interpretation, and resulting fault behavior require additional evidence; this contract does not promise safe traversal merely because the bound comparison succeeds.
