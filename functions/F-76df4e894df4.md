# F-76df4e894df4

## Purpose

F-76df4e894df4 traverses a fixed-stride sequence, selects entries through a classification dependency, extracts up to six attributes from each selected entry, creates an associated object, and passes that object to a registration dependency. A recognized sixth attribute can subsequently overwrite a 16-bit field in the created object.

The result is **not an unconditional “any entry matched” indicator**. The function maintains a masked count of selected entries. On normal termination, it returns whether that count is nonzero. The count wraps to zero after every 65,536 selected entries.

The apparent roles of attribute lookup, text handling, allocation, construction, and registration are inferred from argument flow. Their full semantics are not established by the supplied body.

## Interface

### Inputs

The supplied representation exposes three arguments:

1. **Owner address:** a 32-bit address-like argument. The function reads and writes a 32-bit field at byte offset `0x5c`.
2. **Sequence reference:** an address of a 32-bit slot containing a sequence-descriptor address. From that descriptor, the function:
   - Reads the initial entry address at byte offset `0x14`.
   - Reads the end address at byte offset `0x18` before each iteration.
3. **Registration context:** an opaque 32-bit value passed to F-3d38deb4f0e1 for each selected entry.

These widths describe the supplied representation, not a portable ABI guarantee.

### Output

A Boolean result, produced only when the current entry address equals the descriptor’s then-current end address:

- `false` when the number of selected entries is congruent to zero modulo 65,536.
- `true` otherwise.

No separate error result is visible. Dependency failure, invalid memory, or nontermination is not converted into a defined Boolean failure response by this body.

| Region | Offset or size | Visible use |
|---|---:|---|
| Sequence-reference slot | 4 bytes | Supplies the descriptor address once at entry |

The body does not establish complete layouts, alignment requirements, byte order, or the interpretation of the other fields.

### Preconditions for ordinary completion

Required storage must remain valid for every access actually performed. In particular:

- The sequence-reference slot and descriptor must be readable.
- Traversed entries must be valid inputs to the classification and lookup dependencies.
- Successful attribute lookup must supply a record whose relevant payload is accessible after the temporary lookup key has been released.
- The owner counter field must be readable and writable.
- An object receiving a recognized sixth-attribute value must have a writable 16-bit field at offset `+4`.

The function performs no visible validation of these conditions. Dependency contracts may impose additional preconditions.

## Behavior

### Traversal and termination

The function first reads the descriptor address from the sequence-reference slot, then reads the initial entry address from the descriptor. Both addresses are retained locally.

Before processing each entry, it rereads the end address from the retained descriptor. Equality with the current entry address terminates processing immediately. The end check is equality-only: there is no visible ordering, bounds, or stride-alignment check.

For each nonterminal entry, F-2fb175a232ca receives the current entry address and a global classification operand. Only a result **exactly equal to 1** selects the entry. Zero and every other result skip all per-entry extraction, construction, and registration work.

After either skipping or fully processing an entry, the current entry address advances by `0x28` bytes.

Changes to the original sequence-reference slot do not redirect traversal: that slot is not reread. Changes to the descriptor’s start field likewise do not change the retained current address. Changes to its end field can affect the next termination check.

### Selected-entry count

Selection immediately updates a local 32-bit unsigned accumulator by adding one and clearing bit 16 with mask `0xfffeffff`.

Starting from zero, the accumulator remains in the range 0 through 65,535. Thus, its observable effect is a selected-entry count modulo 65,536. This update occurs before attribute extraction, allocation, owner-counter mutation, or registration.

The returned Boolean reflects selection, not a separately checked construction or registration success status. Abnormal exit before the next termination check produces no established Boolean result.

### Attribute roles and defaults

For clarity, the six lookup operands are designated **A1** through **A6** in their access order. These are specification labels, not recovered attribute names.

The first five attributes populate:

| Attribute | Destination role | Default | Successful lookup handling |
|---|---|---|---|
| A1 | Primary numeric value | 0 | Load a 32-bit payload from result offset `+4`; convert through F-b902b5c89b26 |
| A2 | First text-like value | Shared global default | Pass the address of result offset `+4` to F-4fcc06b56813 |
| A3 | Second text-like value | Shared global default | Same address-based handling |
| A4 | Secondary numeric value | 0 | Same numeric conversion as A1 |
| A5 | Third text-like value | Shared global default | Same address-based handling |
| A6 | Post-registration selector | No local replacement default | Compare its payload against up to three global operands |

The three text-like holders are initialized by three separate reads of the same global default slot before the first lookup. This establishes a shared source for their defaults, not a complete string or ownership contract.

Each numeric conversion result is narrowed to a signed 16-bit value and then sign-extended into a 32-bit argument. Values with bit 15 set therefore become negative. The body does not establish how the converter handles malformed, empty, or out-of-range payloads.

### Ordered lookup protocol

A1 through A5 are looked up in that order. Each lookup follows the same visible lifecycle:

1. F-9b9c1c7483f4 prepares a temporary key using the corresponding global operand and temporary storage.
2. Its returned value is passed to F-92c0da5f24b7 with the current entry and an output-record location.
3. F-8a5aadac202f is called on the temporary key.
4. Only afterward is the lookup result tested.
5. Any nonzero result triggers attribute consumption; zero leaves the corresponding default unchanged.

This ordering matters: successful-result consumption occurs **after** temporary-key release. A conforming dependency combination must make that consumption valid. The body itself neither proves nor enforces the necessary lifetime relationship.

For numeric attributes, the payload value is loaded before conversion. For text-like attributes, the payload-field address is passed to F-4fcc06b56813. These are observably different interfaces.

### Allocation, argument preparation, and owner mutation

After the first five lookups:

- F-8157a180d901 is called with a request size of 24 bytes.
- F-f4fd698ba468 prepares three temporary text-like arguments, in the order third, second, then first.
- The owner’s 32-bit field at offset `0x5c` is read.
- That field is written with its old value plus one.
- The old value, not the incremented value, is supplied to F-aed053512e82.

F-aed053512e82 receives, in order:

1. The allocation dependency’s returned value.
2. The primary signed numeric value.
3. The prepared first text-like argument.
4. The prepared second text-like argument.
5. The prepared third text-like argument.
6. The old owner-counter value.
7. The secondary signed numeric value.

Its return value becomes the object value used for registration and any subsequent selector-field write. The body does not establish that this return value equals the allocation result.

The three prepared text-like arguments are then released through F-8a5aadac202f, in first, second, third order.

There is no visible null-allocation check, constructor-result check, or rollback of the owner counter.

### Registration before selector processing

F-3d38deb4f0e1 is called with:

- The registration context.
- The primary signed numeric value.
- The object value returned by F-aed053512e82.

Only after that call returns does the function look up A6.

Consequently, registration occurs before any selector-field overwrite performed by this function. The registration dependency may observe the object’s earlier field value. Its own side effects and ownership behavior are unknown; the body nevertheless continues using the returned object value after registration.

### Sixth-attribute matching

A6 uses the same temporary-key and lookup lifecycle as the earlier attributes.

If lookup succeeds, the 32-bit payload at result offset `+4` is compared against three global operands in priority order. The comparison dependency is treated as a match only when it returns zero:

- First match: write the 16-bit value 0 at object offset `+4`.
- Otherwise, second match: write the 16-bit value 1 there.
- Otherwise, third match: write the 16-bit value 2 there.
- No match: perform no direct write to that field.

A missing A6 likewise causes no direct selector-field write. It does **not** establish a default value of zero.

Each later comparison is conditional on earlier nonzero results. The payload is loaded again for each attempted comparison; it is not visibly cached across comparison calls.

After selector processing, the original text-like holders are released through F-8a5aadac202f in third, second, first order. Traversal then advances.

## Side effects

### Directly established effects

For each selected entry reaching the relevant stages, the function:

- Calls the attribute, text-management, allocation, construction, registration, and comparison dependencies in the order described above.
- Increments the owner’s 32-bit counter field once.
- May write exactly two bytes at offset `+4` of the returned object.
- Releases temporary keys, prepared text-like arguments, and original text-like holders through explicit dependency calls.

Skipped entries cause no direct owner-counter or object-field writes in this body, although their classification call may itself have side effects.

The function performs no visible direct write to the sequence-reference slot, descriptor, or entry storage. Such storage may still be modified by dependencies or by aliasing with explicitly written regions.

### Ownership and lifetime

Allocation and construction do not establish ownership transfer by themselves. The body contains no visible object deallocation.

The text-like release calls establish cleanup-call ordering, not whether resources are freed, reference counts are adjusted, or the calls are harmless for default values. Likewise, prepared text-like arguments are released after construction, but this does not prove whether construction copies or retains their contents.

Registration is not proven to retain, borrow, or consume the object. Normal continuation requires that any later object write remain valid.

There is no visible cleanup or rollback mechanism for a dependency that does not return normally.

### Arithmetic limits

The selected-entry accumulator has established modulo-65,536 behavior.

The owner increment and entry-address advance are represented as 32-bit integer arithmetic. Their behavior at signed overflow or address-space wrap is not sufficiently established by this body. Portable signed-overflow behavior must not be inferred.

## Acceptance examples

These examples are conditional static expectations. No runtime tests have been performed.

1. **Initially empty sequence.**  
   If the initial entry address equals the end address on the first check, return `false`. Make no classification, lookup, construction, or registration calls.

2. **Classification returns 2.**  
   That entry is skipped even though the result is nonzero. Advance by 40 bytes without this body incrementing the owner counter.

3. **One selected entry, all attributes absent.**  
   If dependencies return normally and the next address is terminal, use zero for both numeric arguments and the shared-default-initialized text-like holders. Increment the owner counter once, construct and register one object, perform no direct selector-field write, and return `true`.

4. **Signed numeric boundary.**  
   If a numeric conversion is consumed as the 16-bit pattern `0xffff`, the corresponding constructor argument is −1, not 65,535. For A1, registration also receives −1.

5. **Owner-counter sequencing.**  
   If the owner field is 7 when read, and no relevant dependency changes it during this interval, write 8 before construction and pass 7 as the constructor’s counter argument.

6. **Second selector operand matches.**  
   If A6 exists, its first comparison returns nonzero, and its second returns zero, write 16-bit value 1 after registration. Do not perform the third comparison.

7. **Unknown selector value.**  
   If all three comparisons return nonzero, do not directly write the selector field. Do not substitute zero or another fallback.

8. **Selection-count wrap.**  
   If exactly 65,536 entries are selected and traversal terminates normally, return `false` despite the per-entry work performed. With 65,537 selected entries, return `true`.

9. **End address changes during processing.**  
   If a dependency changes the descriptor’s end address to the next current address, the next loop check terminates traversal. The original end value is not retained.
