# F-1a12413a717b

## Purpose

F-1a12413a717b dispatches a requested identifier against an ordered table of ten entries. Each entry associates a 32-bit identifier value with a 32-bit mask.

The first entry whose comparison returns zero determines the outcome. For that entry, the function either delegates a state query or updates a captured object's flag word and then sends a notification. A matched entry is reported as handled even if object resolution fails.

The return value distinguishes **a table match** from **no table match**. It does not distinguish successful resolution, successful mutation, or successful notification.

The query, flag-setting, and notification interpretations describe inferred intent. The established behavior is the sequence of calls, reads, writes, branches, and return values below.

## Interface

### Inputs

The function receives three arguments:

1. **Object-slot reference.** An address from which one 32-bit object-address value can be read after an identifier matches. The same reference is passed to F-9b3ea8470521 and, on the query path, F-a07c7b917f8f.
2. **Requested identifier.** An opaque 32-bit value passed to F-e6db2171781a for comparison with each table entry's identifier.
3. **Mode or value argument.** A 32-bit value tested against zero:
   - Zero selects the query/delegation path.
   - Any nonzero value selects the update path and is passed unchanged to F-5629f8ce6df1.

The third argument is not itself interpreted as the desired Boolean state. On the update path, only the low bit of the result from F-5629f8ce6df1 controls the update.

### Result

The function returns a 32-bit value:

| Result | Meaning |
|---|---|
| 0 | All ten comparisons returned nonzero. |
| 1 | At least one comparison returned zero; processing stopped at the first such entry. |

There is no separate error result in the supplied body. A match followed by a zero result from F-9b3ea8470521 still returns 1.

### Relevant layouts

The function uses these layouts:

| Storage | Layout used |
|---|---|
| Dispatch table | Ten consecutive entries, each eight bytes wide. |
| Table entry | Identifier word at byte offset 0; mask word at byte offset 4. Both are 32 bits. |

| Captured object | A 32-bit flag word at byte offset 12 from the captured object address. Other fields are not accessed directly. |

Table traversal advances by eight bytes per unsuccessful comparison. A complete unsuccessful search uses 80 bytes of table-entry storage, although the masks are not read on that path.

The representation of identifiers is unknown. They must not be assumed to be strings, numerical names, or pointers with any particular ownership rule.

## Behavior

### Ordered lookup

The table base is obtained once before searching. The function examines entries in order, starting with the first.

For each reached entry, it reads that entry's identifier and calls F-e6db2171781a with:

- The requested identifier.
- The identifier read from the current entry.

A zero comparison result constitutes a match. A nonzero result causes the function to advance to the next entry.

There are at most ten comparison calls. If all ten results are nonzero, the function returns 0 without directly reading the object slot or the object flag word.

The table is not copied into a stable snapshot. Reads occur as execution reaches them. A dependency that can modify the table may therefore affect subsequent reads.

The first zero comparison result terminates the search. Later entries are not examined, even if they carry the same identifier or would also compare equal.

### Matched-entry resolution

After a comparison returns zero, the function performs these actions in order:

1. Reads the object-address value from the object slot and retains that address.
2. Calls F-9b3ea8470521 with the original object-slot reference.
3. Tests that dependency's result against zero.

The object-address capture occurs **before** the resolver call. If the resolver changes the object slot, that change does not replace the captured address used for subsequent direct flag access.

If the resolver returns zero, the function returns 1 immediately. It does not directly read the matched entry's mask or the captured object's flag word, call the query dependency, decode the third argument, or send the notification.

A nonzero resolver result enables one of the two paths below. The result also becomes the first argument to the notification dependency on the update path.

### Query/delegation path

This path is selected when the third argument is zero and resolution returned nonzero.

The function calls F-a07c7b917f8f with three values:

- The original object-slot reference.
- The identifier obtained by rereading the matched entry.
- A Boolean indicating whether the captured object's flag word and the matched entry's mask share any set bit.

The Boolean is exactly false or true: numerically 0 or 1. It is true when at least one masked bit is set, not only when every bit in the mask is set.

The entry identifier supplied to this dependency is read again after resolution. It is not necessarily the identifier previously supplied to the comparison dependency if intervening calls modified the table.

Likewise, the mask and flag word are read for this path after resolution. Their values are not snapshots taken before the resolver call.

The relative ordering among the identifier, mask, and flag reads used to prepare this call is not established by the supplied expression. They must not be assigned a more precise ordering in an implementation-independent contract.

The function does not directly write the flag word on this path. It does not use the query dependency's return value and returns 1 after the call returns.

### Update path

This path is selected when the third argument is nonzero and resolution returned nonzero.

First, the function calls F-5629f8ce6df1 with the unchanged third argument. It interprets the returned value as a 32-bit bit pattern and tests bit 0:

- If bit 0 is clear, it clears every bit selected by the matched entry's mask.
- If bit 0 is set, it sets every bit selected by that mask.

The flag word and mask used for this operation are read **after** F-5629f8ce6df1 returns. Consequently, changes made by that dependency can affect both the current flags and the mask used for the update.

All mask operations cover 32 bits:

- Clearing retains the current flag bits selected by the 32-bit complement of the mask.
- Setting retains the current flag bits and adds all bits selected by the mask.
- Bits outside the mask are preserved relative to the flag value actually read for this update.

The function then writes the resulting 32-bit value to byte offset 12 of the captured object.

After the write, it calls F-2ea344827b50 with five arguments:

1. The nonzero result previously returned by F-9b3ea8470521.
2. The constant 14.
3. Zero.
4. Zero.
5. Zero.

The notification is issued even when the computed flag word equals its previous value, including when the mask is zero. Its return value is not used. The function returns 1 after the call returns.

## Side effects

- The table-base value used to begin traversal.
- One identifier per reached table entry.
- The object slot once, after the first matching comparison.

- On a successfully resolved update path, the matched mask and the captured object's flag word.

Its only direct external memory write is the 32-bit flag-word write on the update path.
