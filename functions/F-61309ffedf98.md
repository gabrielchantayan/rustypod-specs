# F-61309ffedf98

## Purpose

F-61309ffedf98 first attempts to drain output already pending in an associated state object. If that succeeds and the caller supplies a nonzero input address with a positive signed length, it processes the input in chunks of at most 4096 bytes and drains the output produced for each chunk.

The established behavior is an ordered sequence of state updates and dependency calls. Interpreting those calls as transformation, output, and finalization is inferred intent; the dependencies’ internal behavior is not supplied.

The return value is not uniformly an output-byte count. On the new-input path, it can report input bytes assigned to processing calls even when output for the last assigned chunk was not fully drained.

## Behavior

### 1. Entry and initial pending-output drain

The function first reads and caches the state-object address from context offset `0x20`.

It then reads the 32-bit flags word at context offset `0x14` and writes it back with bits 0 through 3 cleared. This occurs even when the input address is zero, the input length is nonpositive, or the first output attempt subsequently fails.

The initial remaining-output amount is the signed 32-bit difference between the state’s total at offset `0x00` and cursor at offset `0x04`. Only a strictly positive difference enters the drain loop. A zero or negative difference skips it; inconsistent state is not rejected.

For each initial-drain iteration:

- F-8d1c9f620c59 receives the current output-target value, the output-region base plus the current cursor, and the remaining-output amount.
- If the dependency returns zero or a negative value, F-aeffcebde61f is called with the context address. The function then returns that same nonpositive result.
- If the dependency returns a positive value, that value is added to the state’s cursor. The loop’s remaining amount is reduced by the same value.

The remaining amount is maintained independently after its initial calculation. It is not recalculated from the total and cursor on every iteration.

The cursor update reads the cursor after the output dependency returns. Consequently, if that dependency changes the cursor, the positive result is added to the changed value. The output target and cursor used for later output calls are also read again; they are not fixed snapshots for the entire function.

There is no explicit rejection of a positive result larger than the amount requested. Under such a result, the cursor still advances by the reported amount, and the loop exits if the resulting remaining amount is nonpositive. Correct bounds and output semantics therefore depend on the dependency contract.

Successful completion of the initial drain does not itself reset the total or cursor and does not invoke F-aeffcebde61f.

### 2. New-input eligibility

After the initial drain, new input is processed only when both conditions hold:

- The input address is nonzero.
- The input length is strictly positive as a signed 32-bit value.

Otherwise, the function returns zero.

In particular:

- A nonzero address with length zero returns zero after the initial drain.
- A nonzero address with a negative length also returns zero after the initial drain.
- A zero address suppresses processing regardless of length.

These returns do not undo the flag update or any successful initial output.

### 3. Chunk processing

For eligible new input, the function first writes zero to the state cursor.

Each iteration selects a chunk equal to the smaller of the remaining input length and 4096. Because this path begins with a positive length and decreases it by positive chunks, every selected chunk is between 1 and 4096 bytes.

F-890b553af23e is then called with five arguments, in this order:

1. The state address plus `0x14`.
2. The state address plus `0xA0`.
3. The state address itself.
4. The current input address.
5. The selected chunk length.

The function does not use a return value from this dependency. In particular, it has no direct success or failure test for the processing call.

The state total is not explicitly cleared before this call. Its pre-call value may therefore include the state left by the initial drain. Any requirement that F-890b553af23e replace, accumulate, or otherwise interpret that value belongs to the dependency’s unknown contract.

After F-890b553af23e returns, the function performs these actions before attempting to drain the chunk’s output:

1. Writes zero to the state cursor.
2. Decreases the remaining input length by the selected chunk length.
3. Advances the current input address by that chunk length.
4. Reads the state total to initialize the chunk’s output-drain amount.

Thus, input accounting advances for the entire chunk before output success for that chunk is known.

### 4. Per-chunk output drain

A strictly positive produced-output count enters an output loop using F-8d1c9f620c59. The output target, output address, positive-result cursor update, and independent remaining-count reduction follow the same rules as the initial drain.

A zero or negative produced-output count skips this loop. The function does not report that condition as an error.

If an output call returns zero or a negative value:

- F-aeffcebde61f is called with the context address.
- The function returns the original input length minus the remaining input length, provided those values differ.
- Otherwise, it returns the nonpositive output result.

For ordinary execution of this path, without arithmetic failure, the values already differ: at least one positive chunk has been subtracted before any per-chunk output call. The observable failure result is therefore a positive input count, including the whole chunk whose output drain failed.

This count is not evidence that all corresponding output was delivered. It also does not establish how much input F-890b553af23e actually consumed internally.

After a chunk’s output loop completes, including when its initial output count was nonpositive, the function writes:

1. Zero to the state total.
2. Zero to the state cursor.

It then processes another chunk if any input remains. No such pair of completion writes is performed after a failing output call.

### 5. Successful completion

After all new-input chunks complete, the function calls F-aeffcebde61f with the context address and returns the original positive input length.

The return value of F-aeffcebde61f, if any, is ignored. Its effects on memory, resources, or externally visible output are unknown.

## Side effects

### Direct memory changes

The function directly performs the following writes:

- Clears the context flags’ low four bits on every entry that reaches the flags access.
- Advances the state cursor after each positive output result.
- Clears the cursor before the first processing call.
- Clears the cursor after every processing call.
- Clears the total and then the cursor after each completed chunk.

On initial-drain failure, there is no direct cursor increment for the failing call and no direct reset of the total or cursor. Any earlier successful increments remain unless a dependency changes them.

On new-input output failure, the chunk-completion resets are bypassed. The state may retain a produced-output total and a partially advanced cursor, subject to dependency side effects.

### Dependency-visible ordering

The following ordering is established:

- State-address capture precedes the flags update.
- The flags update precedes all output and processing calls.
- Initial pending output is handled before any new-input processing.
- Each processing call precedes all output calls for its chunk.
- Input accounting advances before the chunk’s first output call.
- A chunk is fully drained before the next processing call is made.
- Failure finalization occurs before returning the failure-path result.
- Finalization after successful new-input processing occurs after the last chunk’s direct state resets.

No stronger order is specified for independent argument reads within a single call expression.
