### Bitmap assignment and evaluation order

The bitmap assignment contains two separate source-level evaluations of the address-valued field at object offset 8:

- A **destination-base evaluation**, used to calculate the address that will receive the write.
- A **source-base evaluation**, used to calculate the address of the word supplying the assignment’s existing bits.

Each resulting address uses the same word displacement, \(4q\).

The established ordering is partial:

- The count-field update completes before either bitmap-base evaluation.
- The source-base evaluation precedes the corresponding source-word read.
- The destination address must be determined, and the right-hand-side value must be obtained, before the final word write.
- The assignment does not establish whether the destination-base evaluation occurs before or after the source-base evaluation or the source-word read.

Consequently, the source does **not** establish the fully ordered sequence “read one bitmap base, read its selected word, write that same word.”

The right-hand-side value combines the source word with a mask selecting bit \(r\). That combined value is written to the separately calculated destination address.

Under the explicit assumptions of a stable bitmap base, valid storage, and ordinary 32-bit mask semantics, the source and destination addresses coincide. In that case, the assignment sets bit \(r\) in the selected word and preserves that word’s other bits.

Without the stable-base assumption, equality of those addresses is not established. If an execution permits the evaluations to yield different bases, the write uses bits read from the source-selected word; it does not necessarily preserve the previous contents of the destination-selected word.
