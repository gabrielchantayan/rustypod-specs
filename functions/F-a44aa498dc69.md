# F-a44aa498dc69

## Purpose

F-a44aa498dc69 consumes a length-delimited encoded value and replaces the representation held by a selected record. The caller may provide an existing record indirectly; otherwise, a dependency supplies one.

The encoded value contains a one-byte header followed by zero or more payload bytes. The function stores three header bits in the record’s flags, obtains separate storage for a nonempty payload, invokes a transfer dependency, and masks the final destination byte. Successful completion publishes the selected record and the resulting input position.

This is a static behavioral contract. Directly established effects, conditional consequences, inferred intent, and unresolved dependency behavior are distinguished below. No runtime tests have been performed.

## Interface

### Inputs

| Input | Width and interpretation |
|---|---|
| Optional record slot | Nullable address of a slot containing a 32-bit record address. A nonzero contained address selects an existing record. |
| Input-cursor slot | Address of a slot containing a 32-bit input address. Required during positive-length processing after record selection succeeds. |
| Encoded length | Signed 32-bit integer. Includes the header byte. Values below one are rejected. |
| Context | Opaque 32-bit value, passed twice to the record-supply dependency. |

A nonpositive encoded length is rejected without directly dereferencing either caller slot. Dependencies invoked on that path have their own unresolved effects.

The input-cursor slot is also an argument to the record-supply dependency. Consequently, the cursor used to read the encoded value need not equal its value at function entry.

### Record layout

The selected record exposes four 32-bit fields:

| Byte offset | Meaning established by this function |
|---|---|
| 0 | Payload length, excluding the header |
| 4 | Representation discriminator, assigned the value 3 |
| 8 | Payload-storage address, assigned zero for an empty payload |
| 12 | Flags |

These offsets describe the supplied 32-bit representation. They do not establish a layout using native-width pointers on other targets.

At its direct flags update, the function preserves bits 4–31, replaces bits 0–2 with the header’s low three bits, and sets bit 3. Preservation refers to the value read at that update, not necessarily the value at entry.

### Outputs and failure results

Successful completion returns the selected record address. It also writes that address to the optional record slot, when present, and writes the pending input address to the input-cursor slot.

The explicit null-return cases are:

- Encoded length below one.
- Failure to obtain a required record.
- A zero storage result for a nonempty payload.

These outcomes are conditional on invoked dependencies returning normally. A null result is not an assurance that records, slots, allocations, or other state remain unchanged.

### Preconditions

Normal completion requires readable and writable storage for the accesses actually reached:

- A selected record must support all four field accesses.
- The input-cursor slot must support its reads and final write.
- A supplied record slot must support its selection, failure-condition, and publication accesses as applicable.
- The header address must identify a readable byte, including when the encoded length is one.
- Nonempty payload storage must satisfy the transfer dependency and final-byte access requirements.
- Address calculations must be valid under the target address model.

The interface supplies no independent input-capacity bound. The function does not establish that the declared encoded length fits the available input.

## Behavior

### Record selection and input origin

An existing nonzero record address in the optional slot is reused. If the slot is absent or contains zero, F-f9450f0778b9 is asked to supply a record, receiving the discriminator 3, the input-cursor-slot address, the encoded length, and the context twice.

A null supply result ends processing immediately. This function does not then issue a diagnostic, invoke its conditional record cleanup, or read the header.

After successful selection, two distinct cursor-slot reads determine the input locations:

- The first supplies the address of the header byte.
- The second supplies the address from which the pending payload position is formed by adding one.

The header is read as an unsigned byte and widened to 32 bits. The payload length is the encoded length minus one.

For positive signed 32-bit lengths, the payload length lies between zero and 2,147,483,646. This subtraction does not overflow.

The two cursor reads are not a single snapshot. If their values differ, the header and payload positions need not describe contiguous portions of one encoded value. No synchronization or consistency check is established.

### Payload and flags

The flags update occurs before any nonempty-payload storage request. Therefore, later storage failure does not undo that direct update.

An encoded length of one represents an empty payload. The function requests no payload storage, invokes no transfer dependency, and performs no final-byte masking. The replacement payload address is zero. The pending input address remains one byte beyond the second cursor value.

For a nonempty payload, F-43da6b23bd44 receives the payload length and two zero arguments. A nonzero result becomes the destination address supplied to the transfer dependency. That dependency also receives the saved payload-source address and payload length.

The transfer’s return value is not used. Normal return is followed by advancement of the pending input address by the payload length and modification of the final destination byte. The destination address is the storage result, not a replacement address returned by the transfer operation.

Only the final destination byte is directly masked by F-a44aa498dc69. The transfer dependency’s effects on other bytes remain a separate contract boundary.

### Final-byte mask

The mask uses the entire unsigned header value, not only the three bits retained in the flags.

The supplied expression shifts the signed 32-bit value 255 left by the header value, then converts the result to an eight-bit byte. An unsigned shift count does not make the left operand unsigned.

| Header value | Established result under signed 32-bit shift rules |
|---|---|
| 0 | Mask 255; the final byte is unchanged by masking |
| 1–7 | The corresponding number of low bits is cleared |
| 8–23 | Mask zero; the final byte becomes zero |
| 24–31 | No portable mask result: the shifted value exceeds the signed 32-bit range |
| 32–255 | No portable mask result: the count is outside the permitted range for a 32-bit operand |

The upper established boundary is 23: 255 shifted left by 23 equals 2,139,095,040, within the signed 32-bit range. Shifting by 24 would produce 4,278,190,080, outside that range.

A subsequent byte conversion does not resolve an invalid preceding signed shift. For nonempty payloads with headers 24–255, a portable successful post-mask state is therefore not established. Verified target semantics would be needed to specify one. The function does not explicitly reject these headers.

Empty payloads do not evaluate the mask, so their behavior does not depend on this shift uncertainty.

### Replacement and publication guarantees

When payload preparation reaches completion, the record replacement has an observable ordering constraint: the new payload length is stored before the existing payload-address field is examined.

A nonzero value in that field triggers F-5990a26eaaa3 without explicit arguments. At this dependency boundary:

- The direct flags update has already occurred.
- The new payload length has already been stored.
- The new discriminator and payload address have not yet been stored.

After that dependency returns, the discriminator is assigned 3 and the payload-address field is assigned the pending destination address, or zero for an empty payload. The earlier flags and length assignments are not repeated. Thus, any dependency mutation of those fields may survive successful completion.

Publication writes the optional record slot before writing the input-cursor slot. The selected record address is then returned. Publication is ordered, not atomic.

With stable cursor storage and noninterfering dependencies, the resulting cursor is the header position plus the encoded length. More generally, it is the second cursor value plus the encoded length, subject to valid address arithmetic. Neither description necessarily refers to the entry cursor if record supply changed it.

### Error behavior

A nonpositive encoded length invokes F-4fc89ec41a6d with the ordered arguments 13, 141, 152, zero, zero. The function then returns null. No record has been selected, so its conditional record cleanup is not invoked.

A zero payload-storage result invokes F-4fc89ec41a6d with 13, 141, 65, zero, zero. After the diagnostic returns, cleanup depends on the optional record slot’s current state:

- With no optional slot, F-6c81b0b12feb receives the selected record.
- With a slot containing a different address, F-6c81b0b12feb receives the selected record.
- With a slot still containing the selected record address, that cleanup call is omitted.

This comparison occurs after the diagnostic. It is not based on a saved entry value.

Storage failure returns null without directly performing the replacement length, discriminator, or payload-address writes, or successful publication. The earlier flags write remains a completed direct effect, although dependencies or aliasing may subsequently alter the same storage.

## Side effects

### Nontransactional state changes

The operation provides no established rollback guarantee. In particular:

- Flags can change before storage failure.
- Record supply can affect the cursor before input is read.
- Diagnostics can affect the later cleanup decision.
- Replacement cleanup can observe the new length alongside the previous payload-address field.
- Publication can expose the record before exposing the new cursor.

A caller must not equate a null return with preservation of its original record or cursor.

### Ownership

The function distinguishes records currently referenced by the optional slot from records not currently referenced there when deciding failure cleanup. That distinction suggests an ownership policy but does not prove one.

The available evidence does not establish that:

- Record supply allocates a fresh or exclusively owned record.
- Payload storage is newly allocated, exclusive, or initialized.
- F-5990a26eaaa3 releases the old payload.
- F-6c81b0b12feb frees the selected record or subordinate storage.

The old payload address controls whether F-5990a26eaaa3 is called, but it is not explicitly passed to that dependency. Its cleanup target remains unresolved.

### Aliasing and interference

No explicit non-aliasing checks are established.

If the two caller slots occupy the same storage, successful publication writes the record address first and the pending input address second. The second write can replace the first.

If slots overlap record fields or input bytes, earlier writes may influence later reads. Source/destination overlap behavior is unresolved because the transfer contract is unavailable.

Accordingly, straightforward final-state guarantees require suitable distinct storage and noninterfering dependencies. Other arrangements are documented_only, not established as supported.

No dependency is assumed to preserve globals, caller slots, record fields, or input memory merely because those objects are absent from its explicit arguments.

## Acceptance examples

These are conditional static consequences, not observed executions. Successful content examples assume valid distinct storage, intended byte-transfer behavior, normal dependency returns, valid address arithmetic, and no interfering mutations.

1. **Rejected length.** For zero or any negative signed 32-bit length, the diagnostic arguments are 13, 141, 152, zero, zero. The result is null, without a direct caller-slot dereference.

2. **Empty payload.** Length one produces payload length zero, discriminator 3, and payload address zero. No storage request, transfer, or masking occurs. A nonzero previous payload-address field triggers F-5990a26eaaa3 after the new length is visible.

3. **Flags.** Flags initially equal to `0x12345670` and header 5 produce `0x1234567D` at the direct flags update.

4. **Ordinary masking.** Length three, header 3, and payload bytes `A5 FF` require storage for two bytes. With the intended transfer behavior, the resulting bytes are `A5 F8`. A stable input cursor advances by three bytes.

5. **Full-header mask input.** Length two and header 8 set the flags’ low nibble to `0x8` and force the final payload byte to zero. Masking only by the header’s low three bits would not satisfy the established expression.

6. **Signed-shift boundary.** Length two and header 23 yield a zero final byte through a representable signed shift. Header 24 does not establish a portable final-byte value or successful post-mask state.

7. **Large header without masking.** Length one and header 255 set the flags’ low nibble to `0xF`. The unresolved shift is not reached because the payload is empty.

8. **Record supply failure.** A null result from F-f9450f0778b9 produces an immediate null return, without a subsequent direct header read, diagnostic, or successful publication. Effects inside record supply remain unconstrained.

9. **Storage failure with retained reference.** If the optional slot still identifies the selected record after the storage-failure diagnostic, F-6c81b0b12feb is omitted. The earlier flags update is not rolled back.

10. **Storage failure after reference change.** If the diagnostic changes that slot to a different address, F-6c81b0b12feb receives the selected record. Its presence in the slot before the diagnostic does not prevent cleanup.

11. **Cleanup mutation during replacement.** If F-5990a26eaaa3 changes the record’s length or flags, those changes need not be repaired. The subsequent direct writes cover only the discriminator and payload address.

12. **Shared publication slot.** If both caller slots are the same writable location and no earlier aliasing effect prevents completion, its final published value is the pending input address, not the selected record address.
