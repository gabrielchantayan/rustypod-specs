## Behavior

### Dispatch, bounds, and arithmetic

Processing begins at unsigned offset zero. Before each opcode fetch, the function compares the current offset with the extent. If the offset is at least the extent, it returns; otherwise, it reads and dispatches one opcode byte.

An extent of zero therefore causes immediate return without a stream read or dependency call.

Once an opcode has been fetched, there is no further extent check until that record has been processed. A record beginning within the extent can read operands or payload beyond it.

Offset arithmetic is 32-bit unsigned arithmetic and can wrap modulo \(2^{32}\). There is no wrap detection. Ordinary forward traversal consequently requires nonwrapping offsets and valid effective addresses. Without those conditions, a computed next offset need not exceed the previous offset, and eventual completion is not guaranteed. Exact machine behavior for invalid or overflowing effective addresses remains unresolved.
