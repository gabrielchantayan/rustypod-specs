# F-c10fc14b63f2

## Purpose

F-c10fc14b63f2 conditionally modifies memory and exposed register state, then enters a repeating sequence of indirect calls and software-interrupt requests.

The established behavior is low-level. Depending on incoming machine state, the function:

- Copies one 16-bit value.
- On a narrower path, writes an auxiliary register-state slot and performs an indirect 16-bit store.
- Repeatedly invokes two execution targets and requests software interrupt `0x5B`.

No application-level purpose is established. The supplied material does not justify identifying this function as an allocator, decoder, initializer, or error handler.

The conditional register-state write is part of the contract. It is not treated as an ordinary local calculation, and its possible visibility to subsequent execution targets remains unresolved.

## Behavior

### Conditional initial copy

The first gate multiplies the selector word by \(2^{19}\), retaining the low 32 bits.

If the result is nonzero, the conditional prefix performs no established data-memory access or auxiliary register-state write. Execution proceeds to the repeating tail.

If the result is zero, the function copies a halfword:

1. It reads 16 bits from the copy-source address.
2. It writes that value to the copy-source address plus the copy offset, with byte-address addition modulo \(2^{32}\).

The read precedes the write. The destination can equal the source. There is no overlap, bounds, alignment, or null-address check.

A later comparison uses the copy destination minus the adjustment word. That adjustment does not change the address used for the initial source read or destination write.

The initial gate is satisfied exactly when the selector’s low 13 bits are zero. Consequently, the selector bit used by the subsequent carry-related logic is also clear.

### Conditions for the secondary block

Under the stated arithmetic model, the secondary block is reached exactly when all of these arithmetic conditions hold, provided earlier execution completes:

- The selector’s low 13 bits are zero.
- The entry link address is zero.
- The entry stack address is zero.
- The copy offset equals the companion word.
- The copy offset is either `0x00000000` or `0x80000000`.
- The copy-source address plus the copy offset equals twice the adjustment word, modulo \(2^{32}\).
- The accumulator word is zero.

These are reachability conditions, not assurances that the associated machine state is valid.

The reductions have several important consequences:

- The early link-address gate requires a zero entry link address.
- The next gate requires the logically halved entry stack address to be zero, initially allowing stack addresses zero and one.
- Selector-derived intermediate values and the carried Boolean value are zero on the surviving path.
- The word-comparison gates require equality between the offset and companion, and between the adjusted copy destination and adjustment word.
- The accumulator gate requires zero and produces no carry.
- The final stack gate requires the entry stack address plus twice the copy offset to be zero modulo \(2^{32}\).

Twice a word is even. It cannot cancel the remaining candidate stack address of one. The stack address must therefore be zero, and twice the copy offset must be zero. This permits precisely the two offsets listed above.

### Ordered register-state write and secondary memory operation

Once the secondary block is reached, the initial copy has already completed.

The block then explicitly writes the auxiliary register-state slot. The assigned address representation is the entry stack address multiplied by 64, retaining the 32-bit representation.

Under the reduced reachability conditions, the entry stack address is zero, so the assigned representation is `0x00000000`.

This write occurs **before either link-addressed halfword use in the secondary memory operation**. It is a distinct state effect, not merely an intermediate value used to compute the store destination. If execution subsequently fails while evaluating the halfword operation, the preceding register-state write has already been reached in the visible sequence.

The block also computes an adjusted link address by adding 64 times the entry stack address in bytes. That adjustment is zero on every reachable instance of this block, so it does not change the link-derived first execution target.

The secondary memory operation has two halfword uses:

- One halfword obtained through the entry link address supplies the destination address, zero-extended to 32 bits.
- A halfword obtained through the same address supplies the stored value after adding 15 and retaining the low 16 bits.

The destination is therefore in the byte-address range `0x00000000` through `0x0000FFFF`. The write width is 16 bits. On the reachable path, the link-addressed halfword is located at address zero.

The supplied expression does not establish a portable evaluation order between the destination-producing and value-producing uses. It also does not establish a guaranteed physical read count. If the two uses observe different halfwords, the destination and stored value need not derive from the same value.

If both uses observe one stable halfword, the destination is its zero-extended value and the stored halfword is that value plus 15 modulo \(2^{16}\).

The initial copy precedes both the auxiliary state write and this operation. A copy destination that aliases address zero can therefore change the halfword subsequently used here.

### Excluded later prefix effects

Additional conditional reads, address adjustments, and stores appear later in the supplied body. They are not reachable under the stated model.

If the secondary block does not execute, the immediately following gated sequence does not begin.

If it does execute, the relevant zero-derived halfword address is advanced by one element, giving byte address two. The subsequent gates first retain a zero intermediate, then compare that intermediate against the advanced address. The result is nonzero, stopping the chain.

The later apparent 32-bit stores and signed-halfword-derived writes are consequently not established effects of this function. Nor is the later displayed use of the auxiliary register-state slot reached.

This exclusion does not make the earlier register-state write unobservable. Its significance to subsequent machine execution is unknown.

### Repeating tail

After the prefix, the function enters an unconditional loop.

On its first iteration, the first execution target is the original entry link address plus `0xEB6` bytes, modulo \(2^{32}\). It receives three explicit argument bit patterns:

- `0x00000000`
- `0x00000000`
- `0xFFFFFFA5`

The third pattern represents 4,294,967,205 as an unsigned 32-bit value or −91 as a signed 32-bit value. The callee’s interpretation is unknown.

If the first target returns, the function invokes a second target at `0x0857A94B`. No explicit arguments are shown for this call.

If the second target returns, the function requests software interrupt `0x5B`.

If execution resumes after the interrupt, the loop base is assigned `0x083D4CC2`. Thus, on subsequent iterations, the first target is `0x083D5B78`. The same second target and interrupt request follow in the same order.

There is no termination condition and no visible test of either call’s returned value. Each later action depends on the preceding action returning or resuming control.

## Acceptance examples

These are conditional static examples, not executed tests. Later actions require all preceding accesses and control transfers to complete.

### Prefix bypass

With selector word one, the initial product is `0x00080000`.

Expected behavior:

- No prefix data-memory access occurs.
- No secondary auxiliary register-state write occurs.
- The first tail target is the entry link address plus `0xEB6`.

### Copy without the secondary block

With selector zero, accessible copy addresses, and a nonzero entry link address:

- The source halfword is read and copied to the computed destination.
- The secondary block is not reached.
- The auxiliary register-state slot is not written by that block.
- Execution proceeds to the tail.

### Source and destination coincide

With selector zero and copy offset zero, the initial copy reads and then writes the same address.

The written halfword is the value obtained by the preceding read. Aliasing does not suppress the operation. This is not a guarantee that the operation has no external effect, especially for device-backed memory.

### Secondary state write and store

Assume:

- Selector, entry link address, entry stack address, copy offset, companion word, and accumulator word are zero.
- The copy-source address equals twice the adjustment word modulo \(2^{32}\).
- Every reached memory address is accessible.
- The link-addressed halfword remains `0x1234` after the copy.

Expected order:

1. The initial halfword copy completes.
2. The auxiliary register-state slot receives the zero address representation.
3. The secondary halfword operation writes `0x1243` at byte address `0x00001234`.
4. No later prefix stores execute.
5. The first tail target is `0x00000EB6`.

The example requires accessible address-zero memory and does not establish what the register-state assignment means architecturally.

### Secondary halfword overflow

Under the same prerequisites, if both halfword uses observe `0xFFF8`, the destination is `0x0000FFF8` and the stored halfword is `0x0007`.

The auxiliary register-state write still precedes those uses.

### Wrapped nonzero offset

An offset and companion of `0x80000000` also satisfy the doubled-offset gate when the entry stack address is zero.

For example, a copy-source address of `0x00002000` and adjustment word of `0x40001000` satisfy the destination/adjustment equality modulo \(2^{32}\). With the other secondary prerequisites satisfied and all accesses supported, the same zero register-state assignment and secondary operation are reached.

### Continued loop

If both targets return and the interrupt resumes execution, the next first target is `0x083D5B78`, regardless of the original link address. The second target and interrupt request repeat afterward.
