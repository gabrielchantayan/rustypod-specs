# F-9f68671aabd8

## Purpose

F-9f68671aabd8 performs one of two ordered sequences of external operations, selected by whether its second input is zero. Both sequences begin with the same dependency call and include a call receiving two 32-bit fields from the object addressed by the first input.

The distinguishing behavior is ordering:

- For a nonzero selector, the object-field call occurs early, followed by a lookup-like chain, a six-argument operation, and a final operation using a freshly obtained value.
- For a zero selector, four additional calls precede the object-field call, which is the final explicit operation.

These descriptions concern observable call structure, not application meaning. The supplied evidence does not establish whether the routine initializes, activates, resets, renders, or destroys anything. Such interpretations are not part of this contract.

## Acceptance examples

The following are conditional acceptance scenarios, not executed tests. Each assumes readable required storage and normal dependency returns unless otherwise stated.

### Zero selector with changing object fields

An implementation that captured both fields before those four calls would not satisfy this timing requirement when the intervening calls change them.

Suppose the selector is nonzero. At the first object-field call, the fields contain A and B. F-938c950e5046 returns address P, the 32-bit field at P plus 0x30 contains C, and F-682adfd5a561 returns address Q.

The required behavior is:

- F-9b5a149ab944 receives A and B before F-938c950e5046 is invoked.
- F-682adfd5a561 receives C and the external datum.
- F-a925704a7cb6 receives the field at Q plus 0x124, followed by zero, three, one, two, and four.
- If F-fdd8589eca2d returns R, F-52a80dd62763 subsequently receives R and one.

The zero-branch-only dependencies are not invoked.
