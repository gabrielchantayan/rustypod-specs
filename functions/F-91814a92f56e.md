# F-91814a92f56e

## Purpose

F-91814a92f56e exposes a sequence of indirect calls, computed-address memory accesses, and bit-field transformations. The supplied static evidence does not establish an application-level purpose.

The observable behavior includes:

- Forwarding the first explicit input to an indirect dependency.
- Writing 32-bit values to addresses formed from dependency results.
- Reading one-byte selectors and using them to choose byte destinations.
- Passing shifted, masked, or scaled values to dependencies.
- Splitting one represented 64-bit result into two 32-bit components.
- Repeatedly storing scaled indices and forwarding related values.
- Reaching a terminal invalid-instruction indication rather than an evidenced normal return.

This is a source-facing contract for the represented behavior, not a claim that the complete sequence executes successfully on a particular machine. Invalid instruction data is explicitly reported in the supplied material. Consequently, the actual instruction boundaries, calling convention, and terminal behavior remain material uncertainties.

## Behavior

### Ordering conventions

The phases below follow the supplied static order.

A **four-call acquisition sequence** means four consecutive indirect calls with no explicit arguments shown, with the fourth call supplying the value used next. The first three calls still occur; their return values are not explicitly consumed. Absence of displayed arguments does not establish that a dependency receives no machine-level inputs.

Every dependency may have additional effects. No dependency is assumed to preserve memory, globals, registers, ownership, or previously accessed storage.

### 1. Initial forwarding and word publication

The first indirect call receives the first explicit input. Its target depends on the continuation-related entry state.

A four-call acquisition sequence follows. Its resulting 32-bit index determines a word destination:

- Destination address: four times the index, plus 20.
- Written value: the entry-context 32-bit word.

After that write, another indirect call receives four times the index.

This ordering is significant: the write precedes the call receiving the scaled index.

### 2. First pair of selector-directed byte writes

A four-call acquisition sequence supplies a 32-bit value, called the **first packed value** here.

The function then:

- Reads one byte at the entry-context address plus 1.
- Writes the low eight bits of four times the first packed value to address 17 plus that byte.
- Calls a dependency with four times the first packed value.

The selector-directed destination is therefore between addresses 17 and 272 inclusive. The selector is an absolute-address contributor, not an evidenced offset within an allocated object.

Another four-call acquisition sequence supplies a separate index. Before forwarding four times that index, the function:

- Reads a byte at 64 times the first packed value, plus 1.
- Retains that byte as a selector.
- Writes a byte at address 17 plus the selector.

The written byte is obtained by clearing the top two bits of the first packed value, shifting right by 20, and retaining the low eight bits. Thus the stored byte corresponds to original bits 20 through 27. The top-two-bit mask does not make the entire shifted result fit within eight bits; byte truncation remains relevant.

A further four-call acquisition sequence supplies another index. A dependency receives, in order:

1. Four times that index.
2. The retained selector from the preceding byte read.

### 3. Fourth-input forwarding, zeroing, and auxiliary-value extraction

One indirect call with no explicit arguments follows. The next call receives the fourth explicit input shifted left by 10 in both of its displayed argument positions.

After another call with no explicit arguments, the function reads a byte from absolute address 1 and writes zero to address 17 plus the byte read.

It then calls a dependency with three displayed arguments:

1. The auxiliary 32-bit result.
2. The same auxiliary result.
3. Sixteen times that result.

A four-call acquisition sequence supplies an index. The function reads a selector byte at sixteen times the auxiliary result, plus 1, and writes to address 17 plus that selector. The written byte is the auxiliary result shifted right logically by 22, truncated to eight bits.

The next call receives four times the newly acquired index.

A further four-call acquisition sequence supplies another index. The following dependency receives:

1. The selector just read.
2. Four times that index.

The argument order differs from the corresponding selector-bearing call in the preceding phase.

One call with no explicit arguments follows. The next dependency receives two explicit zero values. Its successor, also shown without explicit arguments, supplies a represented 64-bit result.

### 4. Publication of the wide result

The function writes a zero word to four times the high component, plus 20. It then calls a dependency with the high component itself, not its fourfold scale.

A four-call acquisition sequence supplies an index. The function writes the high component to four times this index, plus 20, then calls a dependency with four times the index.

Four more indirect calls with no explicit arguments occur. Their results are not explicitly consumed at this point.

The low component then determines both a word address and its contents:

- Destination: the low component multiplied by 268,435,456, plus 20.
- Value: the low component multiplied by 67,108,864.

A dependency receives that written value.

A four-call acquisition sequence supplies another index. At four times that index, plus 20, the function stores the low component masked to 29 bits and shifted right by 9. The next dependency receives four times the index.

These are separate writes; they do not establish a contiguous record layout.

### 5. Scaled-index records and word extraction

A four-call acquisition sequence supplies a new index. The function writes four times this index at sixteen times the index, plus 20.

It then uses a different address—four times the index, plus 20—for two represented word reads. A dependency receives:

2. Four times the index.
3. A word from that address shifted left by 2.

A four-call acquisition sequence supplies a destination index. The previously computed fourfold scale is written at four times this destination index, plus 20. A dependency then receives four times the destination index.

The next four-call acquisition sequence supplies another index. Again, four times the index is stored at sixteen times the index, plus 20. A dependency receives that fourfold value twice, followed by the low component of the earlier 64-bit result shifted left by 26.

Another four-call acquisition sequence supplies a destination index. The fourfold value is published at four times that destination index, plus 20, followed by a call receiving four times the destination index.

### 6. Further scaled-index publication and payload capture

A four-call acquisition sequence then supplies a destination index. The fourfold value is written at four times this destination index, plus 20. The next call receives four times the destination index.

A further four-call acquisition sequence supplies another index. The function:

- Writes four times this index at sixteen times the index, plus 20.
- Reads a word at four times the index, plus 20.
- Retains that word as a captured payload.

The read is after the write, but the read and write addresses are generally different. Equality must not be assumed.

Another four-call acquisition sequence supplies a **retained index**. At four times this retained index, plus 20, the function writes the captured payload shifted right logically by 12. It then calls a dependency with four times the retained index.

### 7. Narrow-field argument formation

A four-call acquisition sequence supplies another index. Four times that index is stored at sixteen times the index, plus 20.

The following dependency receives:

1. The low six bits of four times the retained index, shifted left by 14.
2. Four times the newly acquired index.
3. The retained index shifted left by 30.

Under 32-bit bit-vector arithmetic, the first argument can contain information only in bits 16 through 19: multiplication by four clears the bottom two bits before the six-bit mask. The third argument depends only on the retained index’s bottom two bits.

A four-call acquisition sequence supplies a destination index. The latest fourfold value is written at four times this destination index, plus 20. The next dependency receives four times the destination index.

### 8. Final selector-directed writes and termination

A four-call acquisition sequence supplies the **final packed value**.

The function reads a selector byte at the retained index multiplied by 268,435,456, plus 1. It writes the low byte of four times the final packed value to address 17 plus that selector.

The following dependency receives:

1. Four times the final packed value.
2. The same fourfold value.
3. Sixteen times the final packed value.

This call uses a target-calculation displacement different from the predominantly repeated displacement elsewhere in the body. It must not be presumed to share a target with neighboring calls.

A call with no explicit arguments supplies a 32-bit result. The next call receives that result unchanged.

A four-call acquisition sequence supplies another index. The selector address derived from the retained index is read again. The new selector is used to write the byte corresponding to bits 20 through 27 of the final packed value.

The next call receives four times the newly acquired index.

A final four-call acquisition sequence supplies another index. A dependency receives four times that index followed by the selector from the second read. One further indirect call with no explicit arguments precedes the terminal invalid-instruction indication.

The two final selector reads are separated by multiple dependency calls. They are not interchangeable or guaranteed to return equal bytes.

## Acceptance examples

These examples are conditional static checks, not runtime test results. They assume execution reaches the relevant phase, dependencies return as required, and all relevant memory accesses are valid.

1. **Initial word publication.** If the first acquisition sequence returns index 3 and the entry-context word is `0x12345678`, the direct word write targets address 32 with that value. The following dependency receives 12.

2. **Byte truncation.** If the first packed value is 65 and the entry-context selector byte is 7, its first byte write targets address 24 and stores 4. The following dependency receives 260, not 4.

3. **High-byte extraction.** A packed value of `0x12345678` produces `0x23` for the byte extracted through masking, right shift by 20, and byte truncation. This applies to the corresponding early and final extraction operations.

4. **Absolute low-address access.** If the byte at address 1 is 255 when the zeroing phase reads it, the function writes zero at address 272. The evidence does not authorize treating address 1 as a null-relative field of an implicit object.

5. **Auxiliary extraction.** If the auxiliary result is `0xFFFFFFFF`, its right-shift-by-22 byte write stores `0xFF`. The untruncated shifted value is `0x3FF`.

6. **Wide-result separation.** If the represented 64-bit result is `0x0000000300000005`, the first write based on its high component stores zero at address 32, and the next call receives 3. A later low-component-based write targets `0x50000014` and stores `0x14000000`, under 32-bit address arithmetic.

7. **Distinct record addresses.** For an acquired index of 2, a scaled-index write targets address 52 and stores 8. A subsequent payload read at four times the index, plus 20, targets address 28, not 52.

8. **Narrow-field arguments.** For retained index 3, the narrow-field call’s first argument is `0x00030000` and its third is `0xC0000000`, under the stated bit-vector interpretation.

9. **Selector mutation between calls.** If the first final selector read returns 2 and intervening dependencies change that byte to 9, the two final byte destinations are addresses 19 and 26 respectively. Reusing the first selector would not preserve the represented behavior.
