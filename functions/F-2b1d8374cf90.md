# F-2b1d8374cf90

## Purpose

F-2b1d8374cf90 performs an ordered sequence of memory mutations using explicit arguments, additional incoming state, externally stored values, and addresses obtained from previously accessed memory. It ends with an unresolved indirect transfer receiving three arguments.

No application-level purpose is established. Repeated offsets and self-references suggest linked records, but do not establish a list, tree, allocator, text format, or ownership protocol. Doubled addresses, overlapping narrow and word accesses, and addresses derived from signed bytes also prevent assuming an ordinary, safely callable record-processing operation.

This contract distinguishes:

- **Established static evidence:** represented accesses, widths, arithmetic, capture boundaries, and ordering.
- **Inferred intent:** possible interpretations, not acceptance requirements.
- **documented_only:** unresolved behavior or access detail not fully modeled here.

No runtime tests have been performed.

## Behavior

### Ordering and retained values

The represented body is a long straight-line sequence. Comparisons contribute numeric values rather than selecting alternative high-level paths.

Aliasing is not excluded. Consequently:

- A narrow write can change a subsequent pointer-bearing word read.
- A retained value remains distinct from a later read of its source.
- Repeated writes remain observable even when the final bytes are identical.
- An external location can be changed by an earlier address-derived write.

The phase descriptions below establish the stated ordering relationships. They do not define a complete instruction-level trace for every intermediate graph mutation; omitted intermediate access details are **documented_only**, not permission to reorder the original accesses.

An external address value is then captured. Next, the routine captures a word at the primary address plus the incoming displacement. An external value supplying a byte contribution is obtained after that word read.

### Carry-sensitive address formation

The incoming unsigned value is compared with the primary address using unsigned less-than-or-equal. Equality contributes one.

The retained doubling operand is doubled, and that comparison bit is added, with a 32-bit result. A combined carry indicator records overflow from either the doubling or addition of the comparison bit.

An external carry-source value, incremented by this carry indicator, supplies the base for the later offset-`0x9E` byte write. A separate carry condition concerns addition of `0x59` and the combined carry indicator to the carry source. The represented condition includes unsigned comparison with `0xFFFFFFA6` and carry detection for the subsequent addition.

For stable reads of the carry source, this second condition represents whether that combined addition carries out of 32 bits. The source is referenced more than once; a single immutable snapshot must not be assumed. Exact evaluation details among repeated references are **documented_only** here.

The first displacement combines the incoming displacement, the doubled-and-adjusted operand, and the second carry condition.

Before the two primary-relative stores, the routine evaluates and retains a different unsigned comparison: **incoming unsigned entry value less than or equal to a fresh read of the external doubled-address halfword source**. This is not a comparison against the retained earlier copy.

The subsequent mutations occur in this order:

2. The incoming unsigned value is added to form the second displacement, whose low halfword is stored at its primary-relative address.
3. Twice the doubled-and-adjusted operand receives the retained doubled-address source’s low halfword.
4. The carry-adjusted external base receives byte `0x45` at offset `0x9E`.

The external region base and additional halfword operand are loaded only after these writes.

The terminal sequence includes, in order:

- The link’s low halfword written at the sum of the link and current-region addresses.
- The late external address’s low halfword written at twice another retained traversed address.

## Acceptance examples

These are conditional static criteria, not executed tests.

1. **Opening write:** With writable address-component sum and incoming displacement low halfword `0xABCD`, the first represented access writes that halfword there.

2. **Capture across overwrite:** If the opening offset-`0x54` write aliases the doubling source, doubling still uses the earlier captured operand. A following external-word capture may instead observe the overwrite.

3. **Comparison boundary:** Equality of the incoming unsigned value and the primary address contributes one to doubling. The distinct later comparison uses a fresh external-source read and is retained before both displacement stores.

4. **Retained comparison:** If either displacement store changes that comparison source, the later external byte still uses the already evaluated comparison result.

5. **Offset-`0x45` aliasing:** If the external halfword destination overlaps the primary-relative pointer word, its write occurs before the second word read and can change the address receiving word `0x45`. Moving it after that read is incompatible.

6. **Late propagated capture:** If either consecutive offset-`0x09` byte write changes the propagated external word’s storage, the subsequent external capture observes the resulting storage, subject to unresolved concurrent behavior.

7. **Repeated markers:** Under valid, non-aliasing access conditions, both `0x79` and `0x68` writes occur at the offset-`0x1C` destination. A final-state-only account omits an established effect.

8. **Signed terminal byte:** Terminal byte `0xFF` converts to `0xFFFFFFFF`; the first transfer argument is consequently `0xFFFFFFFF`. This does not establish that its derived memory accesses are valid.

9. **Transfer isolation:** Reaching the target does not establish successful return, preserved globals, or unchanged ownership.
