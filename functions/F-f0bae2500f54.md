# F-f0bae2500f54

## Purpose

F-f0bae2500f54 conditionally invokes an indirect callback associated with a three-word record. It returns the callback’s result unchanged and, after a normal callback return, updates the record’s third word.

Invocation requires a non-null record, a non-null callback address stored in that record, and a third word whose signed 32-bit interpretation is nonnegative. If any requirement fails, the function returns zero without invoking a callback or writing the record.

The record’s stored callback takes precedence over the callback address supplied as the third argument. A null record does not cause the supplied callback to be invoked.

The third word appears to combine a count with a negative disabled-state marker. That interpretation is **inferred intent**, not an established application-level meaning.

## Interface

### Inputs

The function accepts three arguments:

1. **Record address.** A nullable pointer to a record containing at least three consecutive 32-bit words.
2. **Unused word.** A 32-bit argument that is not inspected, forwarded, or otherwise used by the supplied body.
3. **Supplied callback address.** An address-sized value presented as a callback pointer. It is replaced by the record’s first word whenever the record address is non-null. When the record address is null, callback invocation is prohibited. Consequently, this argument does not select an invoked callback on any established execution path.

The record layout is:

| Byte offset | Width | Established use |
|---|---:|---|
| 0 | 32 bits | Callback address representation |
| 4 | 32 bits | Single argument passed to the selected callback |
| 8 | 32 bits | Signed eligibility value before invocation; update destination after callback return |

These offsets follow from indexing consecutive four-byte words. Byte order is not established by the supplied body.

### Output

The function returns an integer, treated here as a 32-bit value consistent with the supplied representation:

- Zero when invocation is skipped.
- The callback’s integer result, unchanged, when invocation occurs and the callback returns normally.

A zero return therefore does not distinguish “callback not invoked” from “callback invoked and returned zero.” The record may distinguish those cases: a normally returning callback that returns zero causes a write of `0xffffffff` to the third word; a skipped invocation causes no record write.

### Preconditions

A null record is explicitly supported. For a non-null record:

- The first word must be readable.
- If the first word supplies a non-null callback address, the third word must also be readable.
- If the signed eligibility check passes, the second word must be readable and the selected callback must be callable with one word-sized argument under a compatible calling convention.
- Following a normal callback return, the third word must remain writable.
- Following a nonzero callback return, the third word must also remain readable because its value is read again for the update.

No bounds, pointer-validity, executable-address, alignment, or calling-convention validation is shown. Behavior when these preconditions fail is not established as a controlled error.

## Behavior

### Selection and eligibility

The following order is established by the supplied body:

1. If the record address is non-null, read its first word and use that value as the selected callback address. This replaces the supplied callback argument even when the stored value is null.
2. If the record address is null, return zero.
3. If the selected callback address is null, return zero.
4. Read the record’s third word and interpret it as a signed 32-bit integer. If it is negative, return zero.
5. Read the record’s second word and pass that word as the callback’s sole argument.

The conditional evaluation prevents unnecessary record reads. A null record causes no record access. A non-null record with a null stored callback requires the first-word read but does not require reading the second or third word. A negative third word prevents reading the callback argument.

The eligible initial third-word patterns are `0x00000000` through `0x7fffffff`. Patterns `0x80000000` through `0xffffffff` fail the signed nonnegative check.

The callback address is selected before invocation. Changes to the first word during the callback do not cause this invocation to select another address.

### Callback result and update

After the callback returns normally:

- If its result is zero, write `0xffffffff` to the record’s third word.
- If its result is nonzero, read the record’s third word **again**, add one at the word’s width, and write the resulting 32-bit word back.
- Return the callback result unchanged.

The nonzero branch does not necessarily increment the value observed during eligibility checking. The callback may have changed the third word, and the subsequent update uses the value present after the callback returns.

There is no second eligibility check. If the callback changes the third word to a negative value and returns nonzero, the function still takes the increment branch.

The zero-result branch does not need the previous third-word value. It overwrites that word with all bits set, including when the callback changed it.

### Arithmetic boundary

The destination and source field are 32-bit words. Under the unsigned four-byte-word interpretation of the supplied representation, the nonzero-result update adds one modulo \(2^{32}\):

- `0x7fffffff` becomes `0x80000000`.
- `0xffffffff` becomes `0x00000000`.

The latter transition can occur if the callback changes the field to `0xffffffff` before returning nonzero, despite that pattern being ineligible at initial entry.

The original language type and executable overflow behavior are not independently available. Exact overflow interpretation is therefore qualified in **Uncertainties** and in the relevant acceptance examples.

### Reentrancy and abnormal completion

No “in progress” marker is written before the callback is invoked. If the callback reenters this function using the same record, the nested invocation evaluates the record as it exists at that time.

No exception handling, fault recovery, or nonlocal-exit handling is shown. If the callback does not return normally, the post-callback field update and ordinary return are not established to occur.

## Side effects

### Direct effects

The function directly:

- Reads the record’s first word when the record is non-null.
- Conditionally reads the third word for eligibility.
- Conditionally reads the second word as the callback argument.
- Invokes at most one callback per ordinary invocation.
- After a normal callback return, writes the third word exactly once.
- On the nonzero-result branch, reads the third word again before that write.

No direct writes to the first or second word are shown. No direct allocation, release, global access, logging, or I/O is shown.

These are source-level access-order claims. They do not establish atomicity, volatile semantics, hardware transaction boundaries, or a concurrency memory-order guarantee.

## Acceptance examples

These are conditional acceptance criteria derived from static inspection. **No runtime tests have been performed.**

### Null record

Given a null record, with any values for the other arguments:

- Return zero.
- Do not invoke the supplied callback.
- Do not access record storage.

### Null stored callback

Given a readable record whose first word is zero:

- Return zero.
- Do not invoke any callback, even if the supplied callback argument is non-null.
- Do not read the second or third word through the shown path.
- Do not write the record.

### Initially negative eligibility value

Given a non-null stored callback and a third word of `0xffffffff`:

- Read the stored callback and eligibility word.
- Return zero without invoking the callback.
- Leave the record unchanged by this function.

The same rejection applies to every third-word pattern with its high bit set.

### Callback returns zero

Given a callable stored callback, an initially eligible third word, and a callback that returns zero normally:

- Invoke the stored callback with the second word.
- Write `0xffffffff` to the third word after callback return.
- Return zero.

If the callback changes the third word before returning, the final write still replaces it with `0xffffffff`.

### Callback returns a nonzero value

Given an initially eligible third word of 7 and a callback that leaves that word unchanged and returns −3:

- Invoke the callback once.
- Store 8 in the third word.
- Return −3 unchanged.

Negative callback results are nonzero results; they do not select the zero-result update.

### Callback modifies the update source

Given an initially eligible third word of 7 and a callback that writes 40 there and then returns 1:

- Store 41 after callback return.
- Return 1.

Storing 8 would violate the post-callback reread behavior.

### Callback makes the field negative

Given an initially eligible record and a callback that writes `0xfffffffe` to the third word and returns 1:

- Do not repeat the eligibility check.
- Increment the callback-modified word.
- Store `0xffffffff` and return 1.

### Crossing the signed boundary

Given an initially eligible third word of `0x7fffffff`, an unchanged field during the callback, and a nonzero callback result:

- Under 32-bit unsigned-word addition, store `0x80000000`.
- A later invocation with that field unchanged skips the callback because the signed eligibility check is negative.
