# F-a3a8cd986a49

## Purpose

F-a3a8cd986a49 processes an event-like record against state held in a mutable receiver. It has three established behaviors:

- For event kind 21, clear one receiver byte and invoke two dependencies on an embedded receiver region.
- For event kind 19, recognize a primary coordinate match and invoke a receiver-dispatched operation.
- If the primary match does not succeed, recognize an enabled secondary match and invoke a different receiver-dispatched operation with a one-byte value obtained from a dependency.

The function returns a 32-bit result whose established values are 0 and 1. A result of 1 follows either successful kind-19 dispatch. A result of 0 does not mean that nothing changed: the kind-21 path performs writes and calls before the eventual event-kind decision.

These are structural descriptions. The meanings of the event kinds, coordinates, embedded region, and dispatched operations are not established.

## Behavior

### Initial event-kind handling

The function first reads the 32-bit event kind at event offset 4.

If this initial value is 21, it performs the following actions in order:

1. Writes zero to the single receiver byte at offset 168.
2. Calls F-6904f7699031 with the address of receiver offset 364 and the integer value 100.
3. After that call returns, calls F-ec4cfa552cce with the same embedded-region address.

Neither dependency’s return value controls the next decision.

After this conditional sequence, the function reads the event kind again. If this second reading is not 19, it returns 0.

The second read is behaviorally significant. The first reading is not reused. In particular, an initial kind of 21 does not itself guarantee an immediate return after the two calls. If the event record has become kind 19 by the later read, processing continues into the matching logic.

Conversely, if the event remains kind 21, the function returns 0 after the write and both dependency calls.

### Primary kind-19 match

Once the second event-kind read equals 19, the function reads the event’s second coordinate at offset 12. It retains this value for later comparisons.

It compares that value with the receiver’s 32-bit field at offset 68.

If they differ, the primary route fails without reading event offset 8 or receiver offset 64 for that route.

If they are equal, the function reads:

1. The event’s first coordinate at offset 8.
2. The receiver’s primary first-coordinate value at offset 64.

The primary first-coordinate test succeeds when either:

- The event’s first coordinate equals the receiver value at offset 64; or
- Those values differ, and the event’s first coordinate equals the primary-alternative global.

The primary-alternative global is read only when the direct first-coordinate comparison differs.

On a successful primary match, the function obtains a receiver-dispatched operation using the dispatch-table entry at byte offset 212. It invokes that operation with the receiver as its argument. If the operation returns normally, this function returns 1 immediately.

A successful primary match takes precedence over the secondary route. The secondary-enable field, secondary comparison field, secondary-selector global, and F-5710a8628cba are not needed on that path.

### Secondary kind-19 match

The secondary route is considered only after the primary route fails.

The function reads the receiver’s 32-bit field at offset 156. If it is zero, the function returns 0.

If it is nonzero, the function compares the previously captured event second coordinate with the receiver’s 32-bit field at offset 152.

If these differ, the function returns 0. This failed comparison does not require a secondary read of event offset 8 or a read of the secondary-selector global.

If they match, the function reads:

1. The event’s first coordinate at offset 8.
2. The secondary-selector global.

The secondary route succeeds only if these two 32-bit values are equal.

On success:

1. F-5710a8628cba is called without explicit arguments.
2. A one-byte value is obtained from its result.
3. The receiver’s dispatch-table pointer and the operation at table byte offset 160 are accessed.
4. That operation is invoked with the receiver and the one-byte value.
5. If the operation returns normally, this function returns 1.

The dispatch lookup occurs after F-5710a8628cba returns. The contract therefore does not assume that the receiver’s dispatch state remains unchanged across that dependency call.

If the secondary first-coordinate comparison fails, the function returns 0 without either secondary-path call.

## Acceptance examples

These examples are conditional on valid memory, normal-returning dependencies, and stable comparison state unless a change is explicitly stated.

### Unrecognized stable kind

If both reads of event offset 4 yield a value other than 19 or 21:

- The function returns 0.
- It performs no explicit receiver write.
- It invokes none of the listed dependencies or dispatch operations.

If the initial and second event-kind readings are both 21:

- Receiver byte 168 becomes zero before either dependency call.
- F-6904f7699031 receives receiver offset 364 and 100.
- F-ec4cfa552cce then receives receiver offset 364.
- The function returns 0.

### Kind 21 becomes kind 19

If the initial event kind is 21, a dependency changes it to 19, and the second read observes 19:

- The clear and both embedded-region calls occur first.
- Kind-19 matching then proceeds using subsequent field reads.
- A successful match can cause the eventual return value to be 1.

### Direct primary match

If the second event kind is 19, both primary coordinates match, and the primary dispatch returns normally:

- Dispatch-table offset 212 is invoked with the receiver.
- The function returns 1.
- The primary-alternative global need not be read.
- No secondary-route operation occurs.

### Alternative primary match

If the second coordinate matches receiver offset 68, the first coordinate differs from receiver offset 64, and it equals the primary-alternative global:

- The primary dispatch is invoked.
- The function returns 1.
- Secondary eligibility does not affect the result.

### Enabled secondary match after primary failure

If the primary route fails, receiver offset 156 is nonzero, the captured second coordinate equals receiver offset 152, and the first coordinate equals the secondary-selector global:

- F-5710a8628cba is invoked.
- Its one-byte result is passed to the operation selected at dispatch-table offset 160.
- The function returns 1 after that operation returns.

### Disabled secondary route

If the primary route fails and receiver offset 156 is zero:

- The function returns 0.
- Neither F-5710a8628cba nor the secondary dispatch is invoked.

### Secondary second-coordinate mismatch

If secondary processing is enabled but the captured second coordinate differs from receiver offset 152:

- The function returns 0.
- The secondary-selector global is not needed.
- No secondary dependency or dispatch occurs.

### Both routes are eligible

If both routes would match under otherwise stable state, the primary route wins. Only the primary dispatch occurs.
