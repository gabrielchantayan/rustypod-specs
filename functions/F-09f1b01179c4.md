# F-09f1b01179c4

## Purpose

F-09f1b01179c4 selects one of four arithmetic offsets. For an unsigned selector from zero through three, it adds twelve times the selector to a signed base value, using the applicable unsigned arithmetic and signed-conversion rules. For every other selector, it returns zero.

The established operation is scalar arithmetic, not memory access. A four-position layout with a twelve-unit stride is a plausible interpretation, but the evidence does not establish records, byte units, an allocation, or a dereference.

Zero is not a distinct error indicator. Both rejected selectors and accepted computations can produce zero.

## Interface

### Inputs

- **Base:** a scalar value with a signed integer type.
- **Selector:** a scalar value with an unsigned integer type.

No additional input restrictions appear in the supplied body. In particular, the body does not reject negative bases or require the base to denote valid storage.

The selector is already unsigned when the function receives it. Any conversion from a caller’s negative or wider value occurs outside this function’s body and must be assessed using the caller’s interface rules.

### Output

The function returns one scalar value with the same signed integer type as the base. There is no separate status result, output parameter, or error object.

For an accepted selector, the unsigned arithmetic result is converted to the signed type before return. That conversion is part of the behavior; the return must not be specified merely as an unrestricted mathematical sum.

### Widths and arithmetic model

## Behavior

### Selector classification

The function first determines whether the unsigned selector is less than four.

| Selector | Branch | Offset used |
|---:|---|---:|
| 0 | Accepted | 0 |
| 1 | Accepted | 12 |
| 2 | Accepted | 24 |
| 3 | Accepted | 36 |
| 4 or greater | Rejected | None |

There is no negative value within the unsigned selector domain. If a caller converts a negative value into that domain, the resulting unsigned value controls the branch.

### Accepted selectors

For selectors zero through three, the function forms an unsigned offset equal to twelve times the selector and adds it to the base after the required conversion of the base to the unsigned arithmetic type.

The offset is always one of zero, twelve, twenty-four, or thirty-six. These values fit within the unsigned integer range relevant to the supplied declarations. Large-selector multiplication cannot occur because the comparison excludes larger selectors before this calculation.

For a corresponding signed/unsigned model with unsigned modulus \(M\), let:

- \(B\) be the signed base value;
- \(S\) be an accepted selector;
- \(U\) be the actual unsigned addition result.

Then the unsigned arithmetic is described by:

\[
U = \bigl((B \bmod M) + 12S\bigr) \bmod M.
\]

Here, each remainder is the nonnegative representative in the unsigned range. The function then converts \(U\) to the signed destination.

This separates two cases:

1. **The actual unsigned result is representable in the signed destination.** The conversion preserves its numerical value.
2. **The actual unsigned result is not representable in the signed destination.** The supplied evidence alone does not establish the resulting signed value or other implementation-defined conversion behavior. The target policy is required.

A negative base does not necessarily produce an uncertain result. For example, under 32-bit arithmetic, base −20 and selector two yield an actual unsigned result of four. Conversion to the signed destination is therefore unambiguous.

Conversely, a representable negative mathematical sum does not guarantee an unambiguous signed return. Under the same width, base −20 and selector zero produce the actual unsigned value 4,294,967,276. That value is outside the signed destination’s range, even though the mathematical sum −20 fits in it. The return therefore depends on the target conversion policy.

Selector zero is consequently not an unconditional identity operation for negative bases. The expression still involves the unsigned selector, and the negative base still passes through unsigned arithmetic before conversion back to signed.

There is no explicit saturation, clamp, arithmetic-error check, or replacement with zero when the unsigned result lies outside the signed range.

### Rejected selectors

For every unsigned selector of four or greater, the function assigns and returns signed zero.

This branch does not perform the selected multiplication or addition. Its return value is independent of the base, including whether the base is negative or near a signed limit.

The same rule applies to the smallest rejected selector, four, and to the maximum selector value supported by the deployed unsigned type.

There are no reads through the calculated result and no writes through either input. A result that resembles an address is still only a returned integer in this function.
