# F-51cc8431136c

## Purpose

F-51cc8431136c is an unconditionally repeating sequence of indirect calls and explicitly sized memory accesses. It transforms values supplied by callees into addresses, shifted call arguments, and byte or word stores. At the end of each completed iteration, it replaces its four working arguments and carries additional register-derived state into the next iteration.

The supplied representation establishes no higher-level purpose such as allocation, serialization, device control, or object construction. Repeated offsets do not establish a record type, and small computed addresses must not be reinterpreted as offsets within an unstated allocation.

There is no represented successful return, error return, or conditional loop exit. Completion of an iteration depends on every preceding indirect call and memory access completing.

## Interface

### Explicit inputs and output

The displayed interface has four 32-bit integer inputs and no returned value.

On the first iteration, the first indirect call receives those four inputs in their original order. Subsequent uses of the inputs are replaced by values obtained during execution. On later iterations, the first call receives the four values constructed at the preceding iteration’s end.

The absence of a return value does not mean that the function returns normally: the represented control flow repeats forever.

The four explicit arguments are insufficient to describe the entry requirements:

- The first explicit word store uses an incoming register value not initialized within the function.

## Behavior

### Control and sequencing

Execution follows one unconditional cyclic path. Calls and explicit memory accesses occur in the represented order. There is no visible branch selecting an alternative path based on an argument, loaded value, or call result.

Many indirect calls have no explicit arguments in the supplied representation. That does **not** establish that they have no machine-level inputs or side effects. Their results are sometimes ignored, but their execution cannot be omitted.

For describing dataflow without assigning meanings to unknown callees, this contract uses descriptive labels for selected call results. These labels are specification notation, not dependency identities or source identifiers. Each denotes the value captured at its particular call occurrence; separate occurrences need not agree.

### Initial word-store sequence

| Order | Address | Stored 32-bit value |
|---|---|---|
| 1 | \(4 \times \text{first index} + 20\) | Incoming carried register value |
| 2 | \(16 \times \text{second index} + 20\) | \(4 \times \text{second index}\) |
| 3 | \(4 \times \text{third index} + 20\) | The value stored in row 2 |
| 4 | \(16 \times \text{fourth index} + 20\) | \(4 \times \text{fourth index}\) |
| 5 | \(4 \times \text{fifth index} + 20\) | The value stored in row 4 |
| 6 | Occurs later, after the first byte-clearing groups | Described below |

The first index is obtained after the opening four calls. After the first store, a call receives four times that index.

The second index is obtained after another group of calls. Following the second store, a call receives three identical explicit arguments, each equal to four times the second index.

The third store similarly precedes a call receiving four times the third index.

After the fourth store, another call receives three identical arguments, each equal to four times the fourth index. The function also retains an address base equal to the fourth index multiplied by \(2^{30}\). Call this the **initial byte base**.

After the fifth store, a call receives four times the fifth index.

All multiplication and later address formation remain width-sensitive. In particular, the initial byte base has only four possible bit patterns under 32-bit wraparound; it is not an ordinary unconstrained allocation base.

1. A zero byte is stored at initial byte base plus 17.
2. A zero byte is stored at initial byte base plus 1.

The next call receives the lookup selector shifted left by two bits.

An intervening call returns an opaque 32-bit value that is passed to the following call. More calls then produce another index. The same two zero-byte stores occur again, in the same order, before a call receiving four times that index.

Another group of calls supplies a **sixth index**. The function then:

- Stores a word at \(16 \times \text{sixth index} + 20\).
- Uses the fifth index shifted left by 31 bits as the stored value.
- Reads a 32-bit word at
  \[
  20 + ((\text{lookup selector} \mathbin{\&} \texttt{0x3fffffff}) \gg 20).

The store precedes the read. The read address ranges from 20 through 1043 and is not inherently word-aligned.

A subsequent call receives four times the sixth index. Another call supplies a **retained word value**. The next relevant explicit argument is the loaded lookup word shifted right by 22 bits and then left by 28 bits. With 32-bit truncation, only the loaded word’s bits 22 through 25 survive that transformation.

Further calls supply a **zero-store index**. A zero word is written at four times that index plus 20, followed by a call receiving four times that index.

## Side effects

The function directly performs byte and word stores, selector-byte reads, a computed word read, and a global word read. Its callees may perform additional effects not represented here.

Observable ordering matters:

- Repeated selector reads are fresh reads, not substitutions of an earlier value.
- Repeated zero stores remain distinct operations.
- Stores separated by calls cannot be combined merely because their addresses appear equal.
- A retained selector remains retained even if a callee changes the location from which it was originally loaded.
- Explicit addresses may alias one another, the global location, or callee-managed state. No separation guarantee is present.

Byte-selected write addresses range from 17 through 272. Byte-selected word-store starting addresses range from 20 through 275. These ranges describe computed numeric addresses, not verified accessible memory.

No explicit allocation, deallocation, ownership transfer, or resource release is established. Unknown callees must not be assumed to preserve globals, preserve pointed-to memory, or acquire or relinquish ownership.

There is no visible rollback, retry policy, exception handler, or failure-status translation. Faults, traps, nonlocal transfers, and nonreturning callees have no specified recovery behavior.

## Acceptance examples

These are conditional static examples, not executed tests.

1. **Opening store.** If the first index is 3 and the incoming carried value has bit pattern `0x11223344`, the first explicit store writes that 32-bit pattern at address 32. Its byte ordering is unspecified here.

2. **Lookup bounds.** A lookup selector of zero selects address 20. A selector of `0x3fffffff` selects address 1043. The contract must not silently round the latter address to word alignment.

3. **Unsigned selector.** If a selector-byte read yields 255, the subsequent selected byte-store address is 272, not an address formed using −1.

4. **Byte truncation.** If the byte payload is 65, shifting it left by two produces 260, but the corresponding byte store writes 4.

5. **Calls may change selectors.** If an initial selector read yields 7 and an intervening callee changes the selector location to 9, a later explicit reload selects address 26 rather than 24. A store using the captured selector still uses the earlier captured value.

6. **Global snapshot.** If the global read captures `0x00400000`, the later byte derived from that snapshot is 1. A callee changing the global after the read does not change the retained snapshot.

7. **Iteration handoff.** If the next-iteration index is 2 and the terminal index is 3, with all calls and accesses completing, the next iteration’s opening explicit arguments are 8192, 8192, 32768, and 12. Its first carried-value store uses 12.

8. **No normal completion.** Successful completion of every operation in one iteration leads to another iteration, not a successful return.
