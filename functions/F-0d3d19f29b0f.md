# F-0d3d19f29b0f

## Purpose

F-0d3d19f29b0f searches a sequence by advancing a captured cursor and testing successive candidate positions through an opaque comparison dependency. It returns the first tested position whose comparison result is zero, or −1 when an explicit unsuccessful-completion condition occurs.

A position counts calls to the cursor-advance dependency that complete normally. It is not established to count bytes, characters, or code points. The routine performs no direct character decoding and does not establish ordinary substring-search semantics.

The search uses two measurements obtained before any cursor-byte inspection. Dependencies may have side effects, including changing bytes that later reads observe. Consequently, sequence contents at function entry alone do not determine which candidates are tested.

The object has a pointer-valued field at byte offset +4. In the recovered 32-bit representation, this field occupies four bytes. No meaning is established for the preceding four bytes or any subsequent fields.

The field supplies a cursor used for single-byte reads. The routine initially captures its value, then reads the field again after the first measurement call. These are distinct accesses and can yield different values.

The search operand is not directly dereferenced by this routine. Whether it is an address, handle, or another representation is unknown.

### Result

The result is a signed 32-bit integer:

- The current position when the comparison dependency returns zero.
- −1 when the initially captured pointer is null, initial advancement encounters a zero byte before reaching its target, or candidate eligibility fails.

For ordinary, non-overflowing execution, successful positions are nonnegative. The routine provides no separate status for the different unsuccessful paths.

Invalid memory access, dependency failures, abnormal control transfer, and nontermination are not shown being translated into −1.

### Preconditions for ordinary completion

The caller must provide memory and dependency arguments sufficient for every access that actually occurs:

- The pointer field at object offset +4 must be readable at the initial access.
- If the initial pointer is non-null, that field must also be readable after the first measurement call.
- Every cursor-byte read must address readable memory at the time of that read.
- Every dependency invocation must satisfy that dependency’s requirements.
- Any updated cursor must remain suitable for subsequent operations that execution reaches.
- Arithmetic must remain within the established signed range if behavior is to be determined without resolving the overflow uncertainty.

The routine does not check the object address for null before reading its field. A readable object containing a null field is handled explicitly; a null object address is not equivalent.

No ownership transfer is specified by the visible interface.

## Behavior

### Initial capture and null path

The first established data access reads the pointer field at object offset +4 and captures its value as the cursor.

If that value is null, the routine returns −1 immediately:

- No dependency is called.
- No cursor byte is read.
- The requested starting position has no effect.
- The search operand is not directly inspected.

This path still requires the initial field read to be valid.

### Measurements and the second field read

For a non-null captured cursor, the following operations occur in order:

1. F-d8cbf9aa79a9 receives the search operand.
2. Its result is retained as a signed 32-bit **operand measure**.
3. The object’s pointer field at offset +4 is read again.
4. F-d8cbf9aa79a9 receives that newly read value.
5. Its result is retained as an unsigned 32-bit **sequence measure**.

These labels describe how the results are used, not their semantic units.

The second measurement does not necessarily describe the sequence referenced by the initial cursor. If the first measurement call changes the object field, the second call receives the changed field value. The second field read does not itself replace the captured cursor.

There is no second null check on the field. If the first measurement changes it to null, null is passed to the second measurement dependency.

Both measurement calls finish before the routine directly reads any cursor byte. They may change sequence contents, invalidate memory, or otherwise affect later execution; no preservation guarantee is established. Neither an initially zero byte nor an initially nonzero byte is guaranteed to retain that value until inspection.

The position counter is initialized to signed 32-bit zero after these measurements.

### Initial advancement

The routine advances while the position is less than the requested starting position under signed comparison.

For each required advance:

- It reads the byte at the current cursor.
- If the observed byte is zero, it returns −1 immediately.
- Otherwise, it calls F-d3922c7fe0ec with the address of the local cursor slot.
- After that call returns normally, it increments the position by one.

The dependency’s return value is ignored. Because the dependency receives the cursor slot’s address, it can replace the cursor used by subsequent reads.

This phase does not apply the measurement-based candidate bound. Even an operand measure or sequence measure that would exclude the eventual candidate does not prevent initial advancement.

For a positive requested position, normal completion of this phase reaches that position. For zero or any negative requested position, the phase performs no advances and leaves the position at zero. Negative inputs neither cause backward traversal nor produce an explicit input error.

Encountering zero before a required advance prevents that advance and prevents any comparison at that point.

### Candidate eligibility

After initial advancement, each candidate is evaluated in this order:

1. Read the byte at the current cursor.
2. If the observed byte is zero, stop searching and return −1.
3. Otherwise, add the signed 32-bit position and signed 32-bit operand measure.
4. Interpret the addition result as unsigned 32-bit and require it to be less than or equal to the sequence measure.

A failed arithmetic bound ends the search with −1. The routine does not advance past an ineligible candidate to seek a later one.

The bound is inclusive: equality permits comparison. It is not an independent memory-safety check. The cursor byte has already been read before the bound is considered, and the bound does not establish the comparison dependency’s memory-access extent.

The arithmetic is not an unbounded mathematical sum. When the signed addition is representable, its conversion to unsigned 32-bit is determined; for example, −1 converts to 4,294,967,295. Exact behavior when the signed addition overflows is unresolved.

A zero byte observed during eligibility excludes comparison even if the operand measure is zero. There is no explicit empty-operand success rule.

### Comparison and subsequent advancement

For an eligible candidate, F-53a48a666ef7 receives:

- The current cursor value.
- The unchanged search operand.
- The stored operand measure.

If the result is zero, the routine immediately returns the current position. It performs no subsequent advance or position increment on that path.

Every nonzero result has the same control-flow effect, regardless of sign or magnitude:

- F-d3922c7fe0ec receives the address of the cursor slot.
- After normal return, the position increments once.
- Eligibility is evaluated again, beginning with another cursor-byte read.

A comparison dependency may mutate memory before returning. Such mutation does not trigger a repeat of the eligibility check before the zero/nonzero result is acted upon. A zero result still causes immediate return.

### Position and progress

Each normally completed advance call is followed by one position increment, whether the call occurs during initial advancement or after a failed comparison.

The routine does not measure pointer displacement. If an advance moves several bytes, leaves the cursor unchanged, or moves backward, the position still increases once. Such behavior is not validated here.

Termination is therefore conditional on observed bytes, arithmetic eligibility, and dependency behavior. Forward progress is not independently enforced.

## Side effects

### Direct memory effects

The routine directly:

- Reads the object field once on every reached execution.
- Reads it a second time only when the initially captured value was non-null.
- Reads one cursor byte for each reached initial-advancement check.
- Reads one cursor byte for each reached candidate-eligibility check.
- Updates its local cursor and integer state.

No explicit store to the object field or sequence bytes appears in the routine.

The address of the local cursor slot is exposed to F-d3922c7fe0ec. This permits an update during the call. Whether the dependency retains that address is unknown; the routine establishes no permission to use a local-storage address after its lifetime ends.

### Dependency effects and ordering

No dependency is established to preserve globals, input memory, object fields, or ownership state.

Observable consequences include:

- The first measurement can affect the second field read.
- Either measurement can affect the first cursor-byte read.
- A comparison can affect the subsequent advance or later byte reads.
- An advance can affect the cursor and any later observed memory.

Stored measurement values are not recomputed after advancement or comparison. Changes to the underlying data do not automatically update those retained values.

### Ownership and lifetime

There is no explicit allocation, release, reference-count operation, or ownership transfer in the visible routine. This does not establish that dependencies perform none of those actions.

The routine neither acquires nor extends the lifetime of the object, sequence, or search operand. Their required lifetimes depend on the accesses and calls actually reached. Dependency-induced invalidation can prevent ordinary completion.

## Uncertainties

### documented_only: Measurement semantics

Neither measure is established as a byte length, character count, capacity, or terminator-inclusive size. Compatibility between either measure and advancement-count positions is unknown.

### documented_only: Overflow

The candidate addition and position increments use recovered signed 32-bit values. The supplied representation does not resolve behavior when these operations overflow.

No wraparound, saturation, checked failure, or unbounded arithmetic is specified here. Conversion of a representable negative sum to unsigned 32-bit is distinct from signed overflow.

### documented_only: Encoding and traversal

Direct byte tests distinguish only zero from nonzero. Encoding, multibyte boundaries, malformed-input behavior, and advance distance belong to unresolved dependency contracts.

### documented_only: Failures, aliases, and ownership

No dependency error protocol is established. Measurement results are accepted without validation; advance results are ignored; comparison results have only a zero/nonzero interpretation.

Memory mutation, retained aliases, exceptional control transfer, allocation, release, and global-state effects remain unresolved.

### documented_only: Progress and safety

The routine does not verify cursor progress, establish a readable extent for the sequence, or prove that an eligible comparison is memory-safe. Ordinary termination and access validity require conditions beyond the visible checks.

### Inferred intent

The structure is consistent with searching a terminated sequence from a logical starting position while rejecting candidates believed to lack sufficient remaining extent. This interpretation does not establish substring semantics, consistent units, or safe bounds.
