# F-7720e7e55f8d

## Purpose

F-7720e7e55f8d incrementally examines input bytes, conditionally retains their original values in an embedded state buffer, and selects occasions to pass that buffer to F-22f5795a2978. It reports a call-local output count and saves buffering, line-counter, and boundary state.

**Established static behavior:** indirect byte classification, selective buffering, ordered flush selection, padding-related accounting, early stopping, and ordered state writeback.

**Inferred intent:** incremental decoding of an encoded representation. Literal `=` handling and four-byte alignment support this interpretation, but neither a particular encoding nor the dependency’s transformation is established.

The operation is not transactional. A stopping return can follow input reads, buffer writes, dependency effects, output accounting, and state changes.

## Interface

The function accepts five arguments:

| Argument | Established role |
|---|---|
| State pointer | Addresses mutable state containing four 32-bit fields and an embedded byte buffer. |
| Destination value | A 32-bit value supplied to F-22f5795a2978 and advanced after qualifying flushes. Interpretation as an output address is inferred. |
| Output-count pointer | Receives the 32-bit call-local output count on every normal return. Its incoming contents are not accumulated. |
| Input pointer | Addresses bytes examined during this invocation. |
| Input count | Signed 32-bit iteration bound. Zero and negative values behave differently. |

Normal return values are:

| Bit pattern | Established control-flow meaning |
|---|---|
| `1` | The iteration bound was exhausted, including a skipped loop for negative input count when preliminary inspection did not stop processing. |
| `0` | Zero input count, preliminary special-class stop, negative dependency result, or a post-flush stopping condition. |
| `0xffffffff` | The signed line-counter limit rejected an iteration; interpreted as signed, this is `-1`. |

## Behavior

### Entry and preliminary inspection

The call-local output count and padding count start at zero. A distinct first-padding marker starts at `0xffffffff`.

The function reads the buffered count, line counter, and pending flag, in that order, before testing the input count. The previous-result field is not read at entry.

An input count of zero returns `0` through normal writeback. No input byte, classification resource, or transformation dependency is accessed.

For nonzero input count and an empty buffer, the first input byte undergoes preliminary classification. Its low seven bits select an index from `0` through `127`. A global location supplies the table-base pointer, and one classification byte is read from that table.

The preliminary expression establishes that the input byte and table pointer are both obtained before the indexed table-byte read. Their relative read order is not independently established.

Preliminary classification `0xf2` causes return `0` without entering the loop. Otherwise:

- A positive count enters the loop. The first input byte and classification resource are read again.
- A negative count executes no iterations and returns `1`.

With nonempty buffering, a negative count returns `1` without input or classification reads. With empty buffering, a negative count still requires preliminary inspection and can return either `0` or `1`.

These paths all perform normal writeback.

### Per-iteration limit and lookup

Before reading each loop byte, the function interprets the cached line counter as signed 32-bit and compares it with `79`. A value greater than `79` returns `0xffffffff` before that iteration’s input-byte or classification lookup.

This check precedes boundary recognition. Even a byte that would reset the counter cannot do so when the counter already fails the check.

An append can raise the counter from `79` to `80`. Rejection then occurs before a later iteration unless intervening processing resets the counter or stops the call. Bit patterns with the high bit set compare as negative and are not rejected solely for their unsigned magnitude.

For an iteration that passes the limit, lookup order is:

1. Read the raw input byte.
2. Read the current table-base pointer from the global location.
3. Read the classification byte indexed by the raw byte masked with `0x7f`.

The table-base pointer is reloaded for each lookup. It is not preserved across iterations or dependency calls.

### Buffering and literal padding

Exactly these classification values exclude a byte from buffering:

- `0xe0`, `0xe1`, `0xe2`, `0xe3`;
- `0xf0`, `0xf1`, `0xf2`, `0xf3`.

All other classification values take the append path. Classification `0xff` is therefore appendable. A rejection comparison against `0xff` exists only inside a branch whose predicate excludes that value; it supplies no reachable additional rejection.

Before appending, the function compares the buffered count **unsigned** with `79`. Values `0–79` allow the append. Larger unsigned values invoke the nonreturning failure dependency.

For an allowed append, the observable sequence is:

1. Increment the cached line counter.
2. Store the original eight-bit input byte at the current buffer position.
3. Increment the cached buffered count.

The stored byte is not reduced to seven bits.

After classification and any append, raw byte `0x3d`, literal `=`, increments the call-local padding count. If the first-padding marker still equals `0xffffffff`, the function records the current buffered count in that marker.

This happens even when classification excluded the literal `=` from buffering. A high-bit variant of `=` uses the same classification index but does not count as literal padding.

The marker is later interpreted as signed; it is not used as a buffer index. Malformed state can produce a negative recorded marker, including the sentinel itself. Existing trailing `=` bytes in the incoming buffer do not initialize it.

### Boundary transitions

Classification `0xf1` resets the cached line counter to zero:

- With a zero pending flag, processing reaches flush selection.
- With a nonzero pending flag, flush selection is skipped and the flag remains unchanged.

Classification `0xf0` also resets the line counter:

- With a nonzero pending flag, the flag is cleared and flush selection is skipped.
- With a zero pending flag, processing reaches flush selection.

Every other classification reaches flush selection. Whenever flush selection is reached, the pending flag is first cleared.

Concrete byte mappings are **documented_only**. “Boundary” and “line counter” describe structural roles, not established mappings to particular newline characters.

### Flush selection

Flush selection uses this precedence:

1. On the final input iteration, a buffered count divisible by four or a nonzero call-local padding count selects an explicit flush after padding recomputation.
2. Otherwise, classification `0xf2` selects an explicit flush without padding recomputation.
3. Otherwise, a signed buffered count below `64` retains the buffer. A signed count of at least `64` sets the pending flag to `1` and selects a transformation call.

Boundary handling can skip this entire selection, including on the final iteration.

Padding recomputation first reads the final buffered position, then the preceding position. Each independently contributes one if it contains literal `=`. The preceding position can contribute even if the final position does not.

There is no minimum-length guard:

- Buffered count zero reads state offsets `7`, then `6`.
- Buffered count one reads offsets `8`, then `7`.

The recomputed padding count replaces the existing call-local value. The first-padding marker is unchanged.

### Flush execution and accounting

An explicit flush calls F-22f5795a2978 only when the buffered count is signed-positive. The threshold path calls it after establishing a signed count of at least `64`.

The dependency receives, in order:

1. The current 32-bit destination value.
2. The address of the live embedded buffer.
3. The current 32-bit buffered count.

A signed-negative result causes return `0` through normal writeback. For that attempt, this function does not add output, clear cached buffering, update the previous-result field, or advance its destination value. Earlier effects and dependency effects remain.

For a nonnegative result, the function adds the result minus the current padding count to its call-local output count, then clears the cached buffered count.

There is no check that the result covers the padding subtraction. Accounting is 32-bit and can wrap.

An explicit flush with a signed-nonpositive buffered count makes no transformation call. It uses current result zero and forces the padding count to one. It neither adds output nor clears the cached buffered count, but still performs post-flush handling.

### Post-flush stopping and advancement

Following a nonnegative dependency result, or the explicit no-call case, the function:

1. Reads the previous-result field live from state.
2. Compares current and previous results as signed 32-bit.
3. Returns `0` if the current result is smaller and padding is nonzero, without overwriting the previous-result field.
4. Otherwise stores the current result in that field.
5. Returns `0` if the first-padding marker is signed-nonnegative.
6. Otherwise advances the destination value by the full current result.

Destination advancement uses the unadjusted result, not its padding-adjusted contribution to the output count.

A stop can therefore follow dependency writes, output accounting, buffer-count clearing, and possibly a previous-result update.

The padding count and first-padding marker serve different purposes. Recomputed padding can reduce output without causing a marker stop. Conversely, a marker recorded from input can cause a stop even if later padding recomputation yields zero.

Neither value is reset after a successful flush or saved between invocations.

### Completion and normal writeback

A non-stopping iteration advances the internal input pointer by one byte. Exhausting the signed iteration bound returns `1`. No consumed-input count or updated input pointer is returned.

Every normal return writes, in order:

1. Call-local output count through the output-count pointer.
2. Cached buffered count to state offset `0`.
3. Cached line counter to state offset `88`.
4. Cached pending flag to state offset `92`.

The previous-result field is not part of this final writeback.

Counts, accounting, destination advancement, and represented address calculations use 32-bit arithmetic. No wider or checked arithmetic is established.

## Side effects

Direct effects include input reads, global table-pointer reads, classification-table reads, state reads, raw-byte buffer writes, trailing-position reads, conditional previous-result writes, and final writeback.

F-22f5795a2978 receives an address inside live state. Its preservation of the buffer, other state fields, classification-pointer global, table contents, or unrelated storage is not established.

The buffered count, line counter, and pending flag remain cached across the call and are subsequently written back. In contrast, the previous-result field is read live after a nonnegative dependency result.

A changed classification pointer can affect a later lookup, but that lookup occurs only if another iteration exists and passes its signed line-counter check. Successful transformation alone does not guarantee either condition.

Aliasing can expose access order. An output-count pointer overlapping a final state field first receives the output count and can then be overwritten by state writeback. Buffer writes can affect later input reads when input overlaps the buffer. No alias-safety guarantee is established.

Normal stopping returns do not roll back effects. The nonreturning failure path does not reach normal writeback.

## Acceptance examples

These are conditional static expectations, not executed tests. Unless otherwise specified, storage is valid and nonoverlapping, classifications are stable, and dependencies have only the stipulated effects.

1. **Zero input count.** Return `0`, report output zero, and perform normal state writeback. No input or classification lookup occurs, regardless of the cached line counter.

2. **Preliminary special-class stop.** With empty buffering, nonzero input count, and preliminary classification `0xf2`, return `0` before any loop iteration or transformation call.

3. **Short accumulation.** Starting with empty buffering, line counter zero, and pending flag zero, process three appendable non-`=` bytes. Return `1`, report output zero, and save buffered count three and line counter three.

4. **Aligned final flush.** From empty buffering and line counter zero, four appendable non-`=` bytes select a final flush. With dependency result `3`, previous result zero, and no inspected trailing `=`, report output three, clear buffering, store previous result three, and return `1`.

5. **New padding.** From empty buffering and line counter zero, three appendable non-`=` bytes followed by appendable literal `=` record marker four. With result `3` and previous result zero, report output two, clear buffering, store previous result three, then return `0` because the marker is nonnegative.

6. **Preexisting padding.** Start with buffered count four, pending flag zero, previous result zero, and an initial line counter interpreted as signed 32-bit **at most `79`**. Only the final of the last two buffered positions contains `=`. Process one non-`=` byte classified `0xe0`. It is excluded, and final aligned selection recomputes padding one. With dependency result `3`, report output two, clear buffering, store previous result three, and return `1`. No marker was recorded. If the initial line counter is instead `80`, return `0xffffffff` before the loop-byte read, trailing inspection, or flush.

7. **Line limit before the next byte.** Start empty with line counter `79` and provide two appendable non-`=` bytes. The first raises the counter to `80` and leaves buffered count one. The next iteration returns `0xffffffff` before its input or classification read, saving those counts.

8. **Negative dependency result.** A selected transformation call returning a signed-negative value causes return `0` without counting that attempt or clearing cached buffering. Dependency effects and earlier effects remain.

9. **Explicit flush without transformation.** Start empty with previous result zero, pending flag zero, and an initial line counter interpreted as signed 32-bit **at most `79`**. One non-`=` byte classified `0xe0` leaves buffering empty. Final selection reads offsets `7` and `6`, makes no transformation call, forces padding one and result zero, stores previous result zero, and returns `1` with output zero. An initial line counter of `80` instead causes return `0xffffffff` before those iteration accesses.

10. **Negative input count.** With nonempty buffering and input count `-1`, return `1` without input or classification reads. With empty buffering, preliminary inspection still occurs.

11. **Replacement classification pointer.** Suppose a successful, non-stopping threshold call replaces the global table pointer. **If another iteration exists and its cached line counter, interpreted as signed, is at most `79`**, that iteration reads its input byte, reloads the replacement pointer, and uses the replacement table. This is not unconditional: starting with buffered count `63` and line counter `79`, the first of two appendable non-padding bytes can trigger a threshold call while raising the counter to `80`. Even if that call succeeds without stopping, the next iteration returns `0xffffffff` before either read.

12. **Append-bound failure.** With buffered count `80`, signed line counter at most `79`, and an appendable input byte, invoke the nonreturning dependency with zero, zero, and the diagnostic-data address. No append or normal writeback follows.
