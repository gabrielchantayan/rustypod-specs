# F-962a06457085

## Purpose

F-962a06457085 converts three byte-oriented input planes into an output surface using two 32-bit stores per processed 2×2 block. Four primary samples share contributions derived from one addressed sample position in each auxiliary plane.

**Established static behavior:** block traversal, derived plane spacing, position-dependent component quantization, numeric packing, and interleaved reads and writes.

**Inferred intent:** planar luminance/chrominance conversion to RGB565 with ordered dithering. The arithmetic and output fields support this interpretation, but the supplied evidence does not establish a named input format, colorimetry, target byte order, or ordinary operating values for the numerical globals.

The function neither clips incomplete edge blocks nor validates dimensions, addresses, storage capacity, or overlap. Its quantization is not an unconditional saturating conversion: rounding can cross the signed 32-bit boundary even when every preceding signed component expression is representable.

## Behavior

### Traversal and edge handling

With nonpositive height, the function performs no plane reads, global numerical reads, or output stores. Initial spacing calculations still precede the height check.

With positive height and nonpositive width, row-pair traversal occurs, but pixel-block processing does not. There are no sample reads, numerical-global reads, or output stores. Address and spacing expressions remain part of the represented execution; this is not a general guarantee that invalid addresses or overflowing expressions are harmless.

For positive dimensions within arithmetic limits:

- Top-row indices advance as \(0,2,4,\ldots\), while less than height.
- Within each row pair, left-column indices advance as \(0,2,4,\ldots\), while less than width.
- Every visited block processes four primary samples and produces two output words.
- The top word of a block is stored before its bottom word.
- Both stores complete before processing the next horizontal block.

The number of blocks is:

\[
\left\lceil W/2\right\rceil\left\lceil H/2\right\rceil
\]

There is no partial-block clipping. An odd width causes the last block to include column \(W\); an odd height causes the last block to include row \(H\). Output spacing nevertheless remains \(2W\) bytes. Consequently, odd-width stores can overlap nominal rows and other output stores.

### Packing

\[

\[

Thus the left pixel occupies the low 16 bits and the right pixel the high 16 bits. Memory byte order remains target-dependent.

Outside those bounded conditions, independent 16-bit pixels are not a sufficient description. The actual packing combines six masked 32-bit component values by bitwise OR:

- Left red contributes without a shift.

4. **Neutral samples and zero bias.** With both auxiliary bytes 128, all primary bytes zero, and stable zero bias, every component is zero. Both output words are zero, independently of coefficient and phase.

   - Bottom-left: `0x0000`.

6. **Threshold equality.** A red/blue selected quantity equal to its threshold receives no increment. Bottom-left green with selected quantity 512 likewise receives no increment.

7. **Ordinary upper clamp.** If every initial component equals 100,000, all arithmetic remains within the ordinary quantization range and every numeric pixel becomes `0xFFFF`, regardless of phase.

8. **Odd-width overwrite order.** Width 3 and height 2 produce stores covering these output byte ranges, in order:
   - 0–3: first block’s top word.
   - 6–9: first block’s bottom word.
   - 4–7: second block’s top word.
   - 10–13: second block’s bottom word.

   The third store overwrites bytes 6–7 of the already-written first bottom word. The fourth store does not overwrite those bytes. Final bytes 6–7 therefore come from the second block’s top word, not from a later bottom-row store.

9. **Odd height.** Width 2 and height 1 still process a full block, reading two primary rows and storing two output words. The nominal second row is not clipped.

10. **Auxiliary row-pair spacing.** Width 10 gives \(A=4\). Successive row pairs start eight auxiliary bytes apart, and each row pair addresses five consecutive sample positions per auxiliary plane.

11. **Rounding-induced signed-boundary crossing.** With neutral auxiliary bytes, zero primary bytes, stable bias `0x7FFFFF00`, and phase zero, all initial components equal that representable positive value. Their signed interpretations are negative, so neither positive upper clamp applies. This case disproves an unconditional 0–31/0–63 level guarantee even though preceding signed component expressions are representable.
