# F-af78757952a7

## Purpose

F-af78757952a7 marks an input object, captures an associated record, invokes two unconditional dependencies, conditionally invokes a third dependency based on the record’s current state, and then overwrites that state with a four-byte replacement value.

After the overwrite, it examines a descriptor reached through a global root. A non-null descriptor whose first 32-bit word is nonzero enables an indirect call through a separate global target.

This is a source-facing behavioral contract. The memory accesses, call ordering, and conditions below are established by the supplied static representation. Semantic interpretations such as “initialization,” “cleanup,” or “notification” are not established.

The function then reads the four-byte field at object offset `0xC0` and retains that value as the associated record address.

This order matters. The marker write precedes both the record-address read and every dependency call. If a subsequent operation fails, no rollback of the marker is shown.

The captured record address is used throughout the remainder of this invocation. Later changes to the object’s field at `0xC0` do not redirect this invocation to a different record.

This is an address snapshot, not a snapshot of record contents. The record’s fields are read later and can reflect changes made by dependencies.

### 2. Invoke the unconditional dependencies

- Changes to Root made by F-da2d75c0df8d can affect that argument.

Neither dependency’s return value is visibly consumed.

### 3. Evaluate the conditional record operation

### 4. Overwrite the captured record’s state word

After the comparison and any conditional call have completed, the function stores the Replacement word at captured record offset `0x20`.

This store occurs on both comparison outcomes, provided execution reaches it.

The write is four bytes wide. It is not a byte-by-byte string operation and does not establish writes to neighboring bytes.

If the conditional dependency does not return normally, this store is not reached. If the dependency invalidates the captured record, the subsequent store has no defined successful outcome established by the supplied evidence.

### 5. Inspect the current global descriptor

After writing the replacement, the function obtains the current Root and reads the descriptor address stored at that address.

This is a fresh access through Root. It is not specified to reuse the Root value previously passed to F-338d16f9ce72. Changes made by any completed dependency can therefore affect the descriptor lookup.

Two gates control the indirect call:

1. The descriptor address must be non-null.
2. The first 32-bit word at the descriptor address must be nonzero.

If the descriptor address is null, its first word is not read and the indirect call is skipped.

If the descriptor address is non-null, its first word is read once for this decision. A zero word suppresses the indirect call; any nonzero 32-bit value enables it. Negative values are not excluded.

The descriptor’s first word is an enablement condition. It is not shown being used as the call destination.

### 6. Invoke the indirect target when enabled

No explicit arguments are visible for this call. The full effective interface remains unknown because the supplied representation does not establish the target’s calling convention or possible use of ambient state.

There is no visible check that the Indirect target is non-null or otherwise callable. A valid destination is a precondition for successful dispatch, not a condition enforced here.

After the indirect invocation returns, this function returns without further explicit memory access or state change.
