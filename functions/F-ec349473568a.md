# F-ec349473568a

## Purpose

The established local behavior is five ordered 32-bit writes followed by a control transfer. The writes install a fixed value, copy the second explicit argument, store a representation of the record’s own address, clear one word, and capture an additional machine-state value that is not an explicit argument.

The record resembles a structure prepared for subsequent processing. That interpretation is inferred intent, not an established type or lifecycle contract. The evidence does not establish that the fixed value is a function pointer, that the record is an object, or that the dependency consumes the record.

## Behavior

### Ordered preparation

The observable local write order is:

1. The fixed 32-bit value is stored at offset 0.
2. The second explicit argument is stored at offset 4.
3. The destination’s own address representation is stored at offset 8.
4. A 32-bit zero is stored at offset 12.
5. The additional machine-state value is stored at offset 16.

Only after these writes does the function invoke its dependency.

This order matters when writes are individually observable or an access fails partway through preparation. There is no visible rollback. A failure on a later store can leave earlier stores completed.

The contract describes the order exposed by the supplied static representation. It does not establish atomicity across the record or a cross-thread publication guarantee.

### Treatment of existing contents

No existing field is visibly inspected, preserved, compared, or merged. Each of the five destination words is overwritten by its corresponding value.

Consequently, the local preparation does not branch according to whether the destination was zero-filled, previously initialized, or populated with unrelated data. This does not make reuse lifecycle-safe: any obligations attached to overwritten contents are outside the available evidence.

### Self-reference

The word at offset 8 receives the destination address itself, not a value read from the destination.

This creates a self-reference in the supplied representation. It does not prove that later operations dereference this field, that the record cannot be moved, or that the record owns itself.

The field is 32 bits wide. Porting this behavior to an environment with wider pointers requires an externally established address-representation rule; silent truncation cannot be justified from this evidence.

### Dependency boundary
