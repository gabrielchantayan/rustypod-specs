# F-5684c579e02e

## Purpose

F-5684c579e02e conditionally transforms an in-place sequence of 32-bit payload words and updates a separate 32-bit header. An unsigned packed control specifies a whole-word displacement and a residual bit shift.

A dependency runs after the initial header inspection but before this function writes any buffer storage. A nonzero dependency result suppresses this function’s writes. It does not establish that the dependency preserved the buffer, configuration, allocation, or other state.

**Inferred intent:** the header encodes a signed length, and the payload represents a variable-length integer in least-significant-word-first order. With appropriate configuration and arithmetic semantics, the transformation resembles a right shift. This interpretation is not an independently established representation guarantee.

## Interface

### Arguments and result

The function accepts:

- A pointer to 32-bit signed integer storage:
  - Position 0 is the **header**.
  - Positions 1 onward, when accessed, are **payload words**.
- An unsigned 32-bit **packed control**:
  - Its low five bits select the **residual shift**, between 0 and 31.
  - Its upper 27 bits select the **whole-word displacement**, between 0 and 134,217,727.

There is no return value, capacity argument, allocation-size argument, or returned error status.

### Shared configuration

Four signed 32-bit configuration words participate:

| Contract name | Role |
|---|---|
| **Count factor** | Scales header readings used for extent and sign decisions. |
| **Header factor** | Scales reconstructed headers. |
| **Store factor** | Scales assembled residual-path payload values. |
| **Load factor** | Scales residual-path source values and participates in the final-word zero test. |

Their values, stability, aliasing constraints, and preservation by the dependency are not established.

### Arithmetic requirements

Unsigned 32-bit arithmetic is modular, with modulus \(2^{32}\). Conversion from signed to unsigned preserves the value’s residue modulo that modulus.

Conversion from unsigned to signed is exact through 2,147,483,647. Behavior for larger unsigned values is **documented_only**: the supplied evidence does not establish the target’s conversion rule or whether such conversion can interrupt execution.

Signed multiplication, negation, and indexing require representable results for an ordinary defined interpretation. A signed left shift additionally requires a nonnegative left operand and a signed-representable result. An in-range shift count alone is insufficient.

### Path-dependent storage preconditions

Storage must be valid for the accesses actually selected, not for every payload word suggested by the initial header.

- Before the dependency, this function requires a readable header and readable configuration.
- The dependency’s own storage requirements are **documented_only**.
- If the dependency returns nonzero, this function performs no subsequent header or payload access. It still reads three configuration words.
- If the dependency returns zero and displacement is at least the initial extent, this function requires a writable header but performs no payload access.
- If the dependency returns zero and displacement is smaller than the initial extent, this function requires valid storage for the selected header accesses, source payload reads, and destination payload writes.

In that last case, source reads cover positions displacement plus 1 through the initial extent, and destination writes cover positions 1 through the retained extent. Discarded prefix words need not be readable merely because they lie below the initial extent.

Dependency changes must leave any subsequently accessed storage valid. No visible null-pointer, capacity, or allocation-validity check enforces these requirements.

## Behavior

### Initial extent and dependency boundary

The function first captures the count factor. It separately reads the count factor again and multiplies that second reading by the original header using signed 32-bit multiplication.

If the product is negative, it is negated. Under representable signed arithmetic, the result is the **initial extent**: the absolute value of that product.

A product equal to the minimum signed 32-bit value cannot be made positive by representable signed negation. Behavior beyond that arithmetic violation is not established.

The two count-factor readings are distinct source-level accesses. Their equality is not guaranteed. The relative evaluation order of the factor and header operands within the initial multiplication is not established.

F-3530d7b2a2e7 is then invoked once with the original buffer pointer. After it returns, configuration is captured in this order:

1. Load factor.
2. Store factor.
3. Header factor.

Only after these captures does the function inspect the dependency result.

A nonzero result causes return without any buffer write by this function. A zero result permits further processing. The initial extent is not recomputed after the call.

Consequently, later behavior combines a pre-call extent and captured count factor with post-call factors and later header readings.

### Extent selection

The whole-word displacement is converted to signed form for comparison with the initial extent. Its maximum value fits signed 32-bit storage, so this conversion is exact.

If displacement is at least the initial extent, the function writes zero to the header and returns. It performs no payload read or write of its own on this path.

Otherwise, the **retained extent** is initial extent minus displacement. The subtraction uses unsigned arithmetic followed by assignment to signed storage. Given a valid nonnegative initial extent and this branch condition, the result is positive and signed-representable.

Residual shift zero selects whole-word processing. Residual shifts 1 through 31 select residual-bit processing, subject to the conversion qualification below.

The branch selector evaluates unsigned 1 minus the residual shift and assigns the result to signed storage. For residual shifts above 1, this produces an out-of-range unsigned-to-signed conversion before the selector is explicitly replaced with zero. The overwritten value does not determine the subsequent branch, but the target behavior of that conversion is still unresolved. Descriptions of these paths assume the conversion completes without interrupting execution.

### Whole-word processing

The function rereads the header and multiplies it by the pre-call captured count factor using signed arithmetic. This produces the **current signed count**.

Header reconstruction then uses unsigned arithmetic:

- A nonnegative current signed count selects the modular negation of displacement as the adjustment.
- A negative current signed count selects displacement itself.
- Adding the adjustment converts the current signed count to unsigned and performs modular addition.
- The function reads the header factor afresh and multiplies it by the unsigned adjusted count using modular multiplication.
- The unsigned result is converted to signed form and written to the header.

This fresh header-factor reading replaces the captured header factor for this path. The signed count multiplication still requires a representable result. The final conversion remains target-dependent when the unsigned result exceeds the signed maximum.

The header write precedes all payload copying.

Exactly the retained extent of payload words is then copied in increasing destination order. Destination position 1 receives source position displacement plus 1; each following destination receives the corresponding following source.

These copies apply neither the load factor nor the store factor. Each source position is at or above its destination, so forward traversal does not overwrite a source needed by a later copy under ordinary distinct-word storage.

Displacement zero still reconstructs the header and performs payload self-assignments. It is not an unconditional no-op.

This path performs no final-word trimming and does not clear trailing storage.

### Residual-bit processing

Destinations are written in increasing position order. Every destination except the last combines two adjacent source words:

- The lower-position source is multiplied by the captured load factor using signed multiplication.
- That product is converted to unsigned and logically shifted right by the residual shift.
- The next source is multiplied by the captured load factor using signed multiplication.
- That signed product is shifted left by 32 minus the residual shift.
- The two contributions are combined by bitwise OR, with unsigned conversion of the left contribution.
- The combined unsigned value is multiplied by the captured store factor using modular unsigned arithmetic.
- The result is converted to signed form for storage.

For residual shifts 1 through 31, both shift counts are between 1 and 31. The additional mask applied to the left-shift count does not change that range.

The left shift remains a signed operation. A negative load product, or a shifted result outside the signed range, has no established portable behavior here. Subsequent unsigned conversion does not repair an invalid earlier signed shift.

Increasing destination-write order is established. The relative order of the two source reads within one combined-word expression is not established.

The last destination uses only one source word:

- Multiply the source by the captured load factor using signed arithmetic.
- Convert to unsigned and logically shift right.
- Multiply by the captured store factor using unsigned arithmetic.
- Convert to signed form and write the result at the retained-extent position.

No source beyond the initial extent is read. When retained extent is one, no two-source combination or signed left contribution is evaluated.

### Trimming and final residual header

After the last payload write, the function multiplies the final converted signed value by the captured load factor using signed arithmetic.

If this product is zero, the reported result extent is reduced by exactly one. Otherwise, the result extent remains the retained extent.

This operation:

- Does not scan earlier words.
- Removes at most one reported word.
- Does not erase the final word already written.
- Is not generally interchangeable with testing the stored word alone without constraints on the load factor and arithmetic.

The function then rereads the header and multiplies it by the pre-call captured count factor using signed arithmetic.

- A product below 1 selects the negative result extent.
- A product of at least 1 selects the positive result extent.

The selected extent is multiplied by the post-call captured header factor using signed arithmetic and written to the header.

Thus, residual-path header reconstruction differs from whole-word reconstruction: it uses signed arithmetic and the captured header factor. Its header write follows all payload writes.

When result extent is zero, either sign selection produces zero under valid arithmetic.
