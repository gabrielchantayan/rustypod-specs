# F-a05d8425207d

## Purpose

Construct a structured value by traversing an input collection and dispatching entries through ordered comparisons against `explicitText`, `organization`, and `noticeNumbers`.

These literals are comparison operands, not an established exhaustive set of accepted spellings. Dispatch depends on zero results from an opaque comparison dependency whose equivalence rules and side effects are unknown.

The function constructs a root and payload, may attach a notice reference, updates text destinations, and converts and appends parsed numeric entries. At completion, an absent notice reference is acceptable. A present notice reference must have nonzero organization and number-container fields.

Success returns the root address in the low 32 bits of a 64-bit result and the original input-collection word in the high 32 bits. Failure returns a zero low word; some failures retain an entry-name word in the high word.

**Inferred intent:** the structure represents a notice with optional explicit text and an optional organization-and-number reference. This interpretation adds no requirements beyond the visible operations.

## Interface

### Arguments and result

Four 32-bit arguments are visible.

| Position | Established use |
|---|---|
| First | Not read by the supplied body. |
| Second | Input-collection handle; retained as the successful return’s high word. |
| Third | Signed mode selector: zero selects organization type `0x1A`; any nonzero value selects `0x16`. Also forwarded on generic and structural diagnostic paths. |
| Fourth | Forwarded on generic and structural diagnostic paths. |

The return is a 64-bit bit pattern with the following composition:

| Outcome | High word | Low word |
|---|---|---|
| Success | Original second argument | Root address |
| Checked construction failure | Zero | Zero |
| Text-update failure | Zero | Zero |
| Final structural rejection | Zero | Zero |
| Numeric conversion or append failure | Zero | Zero |
| All three name comparisons fail | Name word read after the base diagnostic | Zero |
| Number parser returns zero, or its initial count is zero | Name word read after the base diagnostic | Zero |

The high word is not a uniform status code. In particular, a nonzero 64-bit result does not establish success; the low word identifies whether a root was returned.

### Global inputs

Five global words supply indirect construction or cleanup arguments:

- Root descriptor.
- Payload descriptor.
- Notice-reference descriptor.
- Number-container cleanup callback.
- Parsed-collection cleanup callback.

Each word is loaded at its individual use site. They are not established constants or stable values captured at function entry. Calls between two uses may change them.

### Preconditions

The body depends on externally provided validity:

- Collection handles must support the count and indexed-access operations performed.
- Retrieved entries must expose the accessed words.
- Name and value operands must satisfy the dependencies receiving them.
- Construction must produce usable object layouts and initial field values. The body does not initialize every field it later reads.
- Processing an organization entry requires a dereferenceable organization-text address in the notice reference.
- Numeric append requires a suitable number-container handle.
- Current descriptor and callback global values must be acceptable to their respective dependencies.

Only selected construction, parsing, conversion, append, and text-update results are checked for zero. There is no general entry-address, organization-address, or container-validity check.

## Behavior

### Root and payload construction

The function loads the current root-descriptor global and passes that word to F-e12621595ccc.

If construction returns zero, processing immediately takes generic failure. Root cleanup is still requested with a zero root address.

For a nonzero root:

1. F-83fcd2d25cd8 receives `0xA5`.
2. Its returned word is written to root offset 0.
3. The current payload-descriptor global is loaded and passed to F-e12621595ccc.
4. A zero payload result takes generic failure.
5. Otherwise, the payload address is written to root offset 4.

The payload descriptor is therefore read after both root construction and F-83fcd2d25cd8 have returned. Their effects on global state cannot be excluded.

No explicit initialization of the payload’s notice-reference or explicit-text fields appears.

### Outer traversal and name dispatch

The outer index is a signed 32-bit value starting at zero. Before each iteration, F-10b760faca36 receives the original input-collection handle. An iteration occurs only while the signed index is less than that newly returned signed count.

For each admitted index, F-6bbddce1b930 retrieves the entry. Name dispatch then performs up to three comparisons:

1. Read entry offset 4 and compare that word against `explicitText`.
2. If the first result is nonzero, read entry offset 4 again and compare the newly read word against `organization`.
3. If the second result is nonzero, read entry offset 4 again and compare the newly read word against `noticeNumbers`.

A zero result selects the associated branch and suppresses later comparisons. Three nonzero results select contextual failure.

There is no single captured name shared by the three comparisons. The first comparison may change the name subsequently supplied to the second; the second may change the name supplied to the third. Their equivalence rules are also unknown.

The count is likewise not a snapshot. Later iterations observe subsequent count results. After each successfully processed entry, the index is incremented by one. No explicit overflow guard is visible.

### Explicit-text branch

F-f9450f0778b9 receives `0x1A`. Its result is written immediately to payload offset 4, without a separate zero check.

The current entry value is passed to F-1cb585febd84. After that dependency returns:

- Payload offset 4 is read again for the text destination.
- Entry offset 8 is read again for the text value.
- Those operands and the previously returned length-like word are passed to F-bbc440b3aefa.

A zero text-update result takes generic failure; a nonzero result resumes outer traversal.

The length-like result may therefore describe a value different from the subsequently reread value if the dependency changes the entry. Similarly, the text-update destination need not equal the address originally returned by F-f9450f0778b9.

Repeated selection of this branch overwrites the explicit-text field. No separate cleanup of its previous value is visible.

### Organization branch

The payload’s notice-reference field is read. If zero, the function loads the current notice-reference descriptor and calls F-e12621595ccc. A zero construction result takes generic failure; a nonzero result is stored in the payload’s notice-reference field.

Using the retained notice-reference address, the function reads its organization-text address and writes that text object’s offset-4 type word:

- `0x1A` when the third argument is zero.
- `0x16` for every nonzero third argument, including negative values.

It then passes the current entry value to F-1cb585febd84. After that call, it rereads the organization-text address from the retained notice reference and rereads the entry value. F-bbc440b3aefa receives these newly read operands and the previously obtained length-like word.

The payload’s notice-reference field is not reread to select this text-update destination. A dependency that changes that field does not, by itself, redirect the retained notice-reference address.

A zero text-update result takes generic failure. Otherwise traversal continues. Repeated organization selections reuse the notice reference found at each branch entry; duplicates are not independently rejected.

### Notice-numbers branch

The payload’s notice-reference field is read. If absent, the current notice-reference descriptor is loaded for construction. A zero result takes generic failure; a nonzero result is attached to the payload.

The current entry value is passed to F-9ac226943a1d.

- A zero parser result takes contextual failure.
- A nonzero result is passed to F-10b760faca36.
- An initial count equal to zero takes contextual failure.
- Any other initial count proceeds, including a negative count.

Only after parsing and the initial count check does the function load the number-container handle from notice-reference offset 4. It uses the notice-reference address retained before parsing, not a fresh read of the payload field. The container field itself can reflect changes made during parsing or counting.

The numeric index is signed 32-bit and starts at zero. Each loop condition calls F-10b760faca36 again on the parsed collection. While the index is less than the newly returned signed count:

1. F-6bbddce1b930 retrieves the parsed entry.
2. Its offset-4 word is passed to F-aaeeb0735be1 with a leading zero argument.
3. A zero conversion result selects numeric-conversion failure.
4. Otherwise, F-754616bec4de receives the retained container handle and converted result.
5. A zero append result selects numeric-append failure.

The index increments after a successful append. There is no explicit overflow guard.

The initial count only gates entry into this processing phase; it does not determine the number of numeric iterations. Even a positive initial count can be followed by no iterations if the next count is nonpositive. A negative initial count is not rejected, and later counts govern whether any elements are accessed.

On normal numeric-loop completion, the current parsed-collection cleanup-callback global is loaded and supplied with the parsed collection to F-fb5bc2dc656c. Outer traversal then continues.

The container handle is retained across numeric-loop dependency calls. Repeated notice-numbers selections reload the container field at their own post-parser load point; the body does not clear it beforehand.

### Final structural check

After outer traversal, the payload’s notice-reference field is read again.

- Zero permits success immediately.
- A nonzero notice reference must have nonzero words at offsets 0 and 4.

More precisely, the number-container word at offset 4 is read first. If nonzero, the organization word at offset 0 is read. The number-container word is read again for the final condition. There is no intervening dependency call in this check.

Success does not require explicit text, nonempty organization text, or a positive container element count. The check establishes pointer or handle presence only.

On success, the root is returned without a visible destruction request.

### Failure paths

**Generic failure:** checked construction failure or zero text-update result.

The high-word carrier is set to zero. F-4fc89ec41a6d receives `0x22`, `0x84`, `0x41`, zero, zero, the original third argument, and the fourth argument. After that call, the current root-descriptor global is loaded and supplied with the root to F-ac669dc5909f. The returned bit pattern is zero.

**Structural failure:** failed final presence check.

The sequence is the same as generic failure, except the third diagnostic word is `0x8E`.

**Contextual failure:** three unsuccessful comparisons, zero parser result, or zero initial parser count.

F-4fc89ec41a6d first receives `0x22` and `0x84`. Only after it returns is entry offset 4 reread and retained as the return high word.

F-968c88301966 then receives a leading `6` and alternating labels and values: `section:` with entry offset 0, `name:` with the retained name word, and `value:` with entry offset 8. The relative evaluation order of the context and value reads is not established.

After the contextual call, the current root-descriptor global is loaded for F-ac669dc5909f. The low result word is zero; the retained name word remains the high word.

**Numeric failure:** zero conversion or append result.

The high-word carrier is set to zero. Conversion failure selects diagnostic reason `0x85`; append failure selects `0x84`.

The observable call and global-load order is:

1. F-4fc89ec41a6d receives `0x22` and the selected reason.
2. After the diagnostic returns, the current number-container cleanup-callback global is loaded.
3. F-fb5bc2dc656c receives the retained number-container handle and that callback word.
4. After container cleanup returns, the current parsed-collection cleanup-callback global is loaded.
5. F-fb5bc2dc656c receives the parsed collection and that callback word.
6. After parsed cleanup returns, the current root-descriptor global is loaded.
7. F-ac669dc5909f receives the root and that descriptor word.

The result is zero. Neither callback value is assumed preserved across an earlier call.

## Side effects

Direct writes establish root initialization, payload attachment, notice-reference attachment, explicit-text pointer replacement, and organization type mutation. Dependencies may additionally change text, containers, objects, globals, or input-related state; their preservation guarantees are unavailable.

Construction and destruction need not receive equal root-descriptor words. Failure cleanup reloads the global after intervening diagnostics and any applicable collection cleanup. Payload and notice-reference construction also use their globals’ values at the respective invocation points.

Visible lifetime actions are limited:

- Success returns the root without explicit cleanup.
- Every visible failure requests root cleanup, including initial construction failure with a zero root.
- Normal numeric completion requests parsed-collection cleanup.
- Numeric failure requests container cleanup, then parsed-collection cleanup, then root cleanup.
- A nonzero parsed collection whose initial count is zero has no separate collection-cleanup call on its immediate contextual-failure path.
- Failed append has no separate visible cleanup of the converted object.
- Replacing explicit text has no separate visible cleanup of the overwritten destination.
- Numeric failure does not visibly clear the notice reference’s container field.

These are cleanup requests, not proof of deallocation, ownership transfer, or safe overlap. A leak or double release cannot be established without the dependency contracts.

## Acceptance examples

These are conditional static acceptance criteria, not executed tests.

1. **Empty collection:** With successful construction, a first outer count of zero, and an absent notice reference, return the root low word and original collection high word.

2. **Mutable name between comparisons:** If the explicit-text comparison returns nonzero and changes entry offset 4, the organization comparison receives the changed word. If that comparison returns zero, select organization processing without a notice-numbers comparison.

3. **Comparison equivalence:** If the comparison dependency returns zero for an operand not byte-identical to its literal, dispatch still follows that zero result. This contract does not independently require literal byte equality.

4. **Explicit text only:** A successful explicit-text update may lead to success without any notice reference. If the length-like dependency changes the destination field, the update receives the reread destination.

5. **Organization mode:** Zero selects `0x1A`; both positive and negative nonzero third arguments select `0x16`. Eventual success still requires the final presence check.

6. **Incomplete notice reference:** If either required word is zero at final validation, issue the diagnostic carrying `0x8E`, reload the root descriptor for cleanup, and return zero.

7. **Contextual mutation:** If the base contextual diagnostic changes the entry-name word, the subsequent contextual diagnostic and return high word use the post-diagnostic name, not a name captured during comparisons.

8. **Zero initial parsed count:** A nonzero parser result with initial count zero takes contextual failure. Do not require a separate parsed-collection cleanup call.

9. **Numeric conversion failure after prior appends:** Issue reason `0x85`, load the container callback after the diagnostic, clean the retained container, then load the parsed callback and clean the parsed collection before root cleanup.

10. **Callback-global mutation:** If container cleanup changes the parsed cleanup-callback global, the subsequent parsed cleanup receives the changed word.

11. **Descriptor-global mutation:** If an intervening dependency changes the root-descriptor global, failure cleanup receives its then-current word, even if root construction received a different word.

12. **Repeated branches:** Repetition alone causes no rejection. Explicit-text fields are replaced, organization updates reuse the branch-entry notice reference, and numeric processing does not explicitly reset its destination container.
