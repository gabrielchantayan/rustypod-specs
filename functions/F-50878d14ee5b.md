# F-50878d14ee5b

## Purpose

F-50878d14ee5b consumes a bracket-delimited sequence of encoded byte fragments and incrementally copies their decoded contents into an output buffer associated with a destination object.

The output is assembled in three phases: a 12-byte prefix, a directory whose extent is derived from that prefix, and a body whose expected extent is derived from directory entries. Output-buffer resizing occurs only when another payload byte reaches a phase boundary. A closing bracket can therefore terminate processing before the output is complete or before a pending phase transition occurs.

**Established behavior:** the function advances parser state, invokes parser callbacks, copies payload bytes, requests buffer resizing, updates destination metadata, and reports selected failures through a parser error field.

**Inferred intent:** the structure resembles reconstruction of a table-based binary object from textual fragments. That interpretation does not override the arithmetic, termination behavior, or error handling specified below.

## Interface

The function takes two 32-bit address-valued arguments and has no returned result:

- A destination-object address.
- A parser-context address.

The visible representation uses 32-bit words for addresses, integers, callback slots, and stored buffer references. Individual payload and header accesses are byte-wide.

### Destination-object fields

| Byte offset | Width | Role |
|---|---:|---|
| `0x1EC` | 32 bits | Output-buffer reference, read during copying and replaced after resize requests |
| `0x1F0` | 32 bits | Expected total output extent, written when the directory-to-body transition occurs |

Other destination fields are not directly accessed.

### Parser-context fields

| Byte offset | Width | Role |
|---|---:|---|
| `0x00` | 32 bits | Current input cursor |
| `0x08` | 32 bits | Input-end reference |
| `0x0C` | 32 bits | Parser error/status |

The input-end reference and resource-context value are captured before the first callback. Subsequent decisions use those captured values, even if callbacks change the corresponding parser fields.

The callbacks receive the parser-context address. The fragment-decoding callback additionally receives a destination buffer reference, a signed 32-bit capacity-like value, a reference to a 32-bit output-length slot, and the value one.

## Behavior

### 1. Opening delimiter

Before examining input, the function captures the input-end and resource-context fields, initializes its local assembly state, and invokes the normalization callback.

It then reads the current cursor:

- If the cursor is before the captured end, it advances the parser cursor by one byte and examines the byte at the former cursor.
- If that byte is an opening square bracket, processing continues.
- Otherwise, including when the cursor is not before the captured end, it calls F-4457a9a44a68 with a diagnostic and then stores error value **3** in the parser error field.

Thus, a present but incorrect opening character is consumed before the opening-delimiter failure is reported. An initially exhausted input is not advanced by this opening check.

After a valid opening bracket, the normalization callback is invoked again.

### 2. Fragment selection and closing delimiter

Each iteration reads the current parser cursor and compares it against the captured input end.

If the cursor is at or beyond that end, processing terminates with parser error **3**. This exhaustion path does not issue the diagnostic used for an invalid opening delimiter.

If the current byte is a closing square bracket:

- The parser cursor advances by one byte.
- Processing terminates without checking output completeness.
- The function does not assign a new parser error value on this path.
- Any applicable temporary-buffer cleanup is attempted.

The function does not inspect input following the consumed closing bracket.

For any other byte, fragment handling depends on whether the byte is a less-than sign.

### 3. Less-than-prefixed fragments

For a less-than-prefixed fragment:

1. The token-advance callback runs.
2. The parser error field is inspected. A nonzero value terminates processing through the cleanup path without replacing that value.
3. A signed 32-bit size is calculated from the advanced cursor and the original fragment-start address: subtract the start address, subtract one, then divide by two using signed integer division.
4. F-6dd003795db7 is called with the captured resource context, element width one, the previous size for this temporary buffer, the newly calculated size, the current fragment-buffer reference, and a reference to an error-result slot.
5. The dependency result immediately becomes the current fragment-buffer reference.
6. If the error-result slot is nonzero, that value is copied to the parser error field and processing terminates.
7. Otherwise, a cleanup-required flag is set, the parser cursor is restored to the original fragment start, and the fragment-decoding callback runs.
8. The decoder’s 32-bit output length becomes the fragment length. The calculated signed size becomes the previous size used by a later resize request.

The function does **not** check the parser error field immediately after the fragment-decoding callback. It proceeds to inspect and copy the reported fragment.

Calling this a hexadecimal-fragment path is inferred intent. The callback’s accepted syntax, decoding rules, output guarantees, and cursor behavior are not established here.

### 4. Other fragments

For a fragment not beginning with a less-than sign, F-cfad0582408b is called without explicit arguments.

If its result is nonzero:

1. The binary-length callback supplies a 32-bit fragment length.
2. The token-advance callback runs.
3. If the parser error field is nonzero, the function returns immediately. This return bypasses temporary-buffer cleanup.
4. The fragment’s payload reference is set to one byte beyond the resulting parser cursor.
5. The parser cursor is set to that same starting position plus the fragment length.
6. If this resulting cursor is at or beyond the captured input end, the function calls F-4457a9a44a68 with an excessive-binary-data diagnostic, stores error **3**, and terminates through cleanup.

The boundary test is inclusive: a resulting cursor exactly equal to the captured input end is rejected.

If F-cfad0582408b returns zero, the function does not establish a new fragment reference or length. It proceeds using the previous reference and length; initially, both are zero. No visible guard makes this case safe or guarantees forward progress.

### 5. Fragment-tail adjustment

Before copying any fragment bytes, the function reads the byte at:

**fragment reference + fragment length − 1**

This read occurs even when the fragment length is zero.

If that byte is zero, the length is masked with `0x80000001`. The length is reduced by one only if the masked result equals one. Consequently, the adjustment removes one trailing zero only for lengths that:

- Are odd; and
- Have their 32-bit sign bit clear.

A zero byte at the end of an even-length fragment is retained. A length with its high bit set does not receive this adjustment.

The copy loop compares its signed 32-bit index against the fragment length interpreted as signed. A length with its high bit set therefore does not produce ordinary positive-length iteration, although its last-byte inspection has already occurred.

### 6. Output assembly

The output byte count begins at zero. It advances only when a fragment byte is written. Fragment boundaries do not reset the output count or assembly phase.

#### Prefix phase

The first 12 payload bytes are copied to the destination buffer at offsets zero through eleven.

When a further payload byte is available, the function reads destination-buffer bytes at offsets four and five and computes a directory-entry count:

**count = 16 × byte[4] + byte[5]**

Both bytes are treated as unsigned. This is multiplication by sixteen, not a conventional two-byte big-endian interpretation. The count ranges from zero through 4,335.

The expected directory-end offset becomes:

**directory end = 12 + 16 × count**

The function then changes to the directory phase and requests a resize through F-6dd003795db7, passing:

- Captured resource context;
- Element width one;
- Old size twelve;
- New size equal to the directory-end offset;
- Current destination-buffer reference;
- Error-result reference.

The returned reference is stored into destination offset `0x1EC` before the error result is checked. A nonzero error result is copied to the parser error field and terminates processing.

On success, the same pending payload byte continues through directory-phase handling.

#### Directory phase

While the output count is below the directory-end offset, payload bytes are copied sequentially.

Once another payload byte is available at that boundary, the function calculates the expected total output extent. It starts with the directory-end offset and, in entry order, reads a four-byte unsigned big-endian value from each entry’s length position.

For entry index zero, that position is output offsets `0x18` through `0x1B`. Each following position is sixteen bytes later.

For each value, the function adds its four-byte-rounded extent:

**rounded extent = (value + 3) masked with `0xFFFFFFFC`**

The addition of three and the total accumulation use 32-bit unsigned arithmetic. They can wrap. There is no visible overflow rejection.

The function then:

1. Changes to the body phase.
2. Stores the calculated total at destination offset `0x1F0`.
3. Requests a resize through F-6dd003795db7, using the directory-end offset as old size and **total + 1** as new size.
4. Stores the returned reference at destination offset `0x1EC`.
5. Checks the resize error result.

A resize error is copied to the parser error field. The total-size field has already been written at that point.

On success, the pending payload byte continues through body-phase handling.

#### Body phase

If the output count is less than the calculated total, the payload byte is copied.

Otherwise, the function reports excessive binary data through F-4457a9a44a68, stores parser error **3**, and terminates through cleanup.

The extra byte requested by the final resize is not explicitly initialized or written as a terminator by this function.

### 7. End-of-fragment processing and termination

After a fragment’s copy loop completes, the normalization callback runs, and delimiter/fragment selection repeats.

There is no final check that:

- Twelve prefix bytes were received;
- The directory was completed;
- The calculated total was reached;
- Either resize transition occurred;
- The parser error field is zero.

On cleanup paths, if any less-than-prefixed fragment successfully passed its temporary resize, F-bf7242c98d06 is called with the captured resource context and the **current** fragment reference.

That reference is not necessarily still the temporary allocation: a subsequent binary fragment can replace it with an input-derived address.

## Side effects

Observable direct effects include:

- Parser-cursor advancement, replacement, and restoration.
- Parser error-field assignments on selected failures.
- Sequential byte writes to the destination buffer.
- Replacement of the destination-buffer reference after resize calls, including failed resize calls.
- Assignment of expected total size before the final resize error is checked.
- Diagnostic dependency calls.
- Conditional cleanup calls.

Output writes and metadata changes are not rolled back after later errors. No output-byte count is stored in the visible destination fields.

Callbacks and dependencies can have additional effects not established by this source. In particular, callback preservation of parser fields, destination fields, memory contents, or external state must not be assumed.

## Acceptance examples

These are conditional, static acceptance examples, not executed tests. Assume valid storage and the stated dependency behavior.

1. **Empty bracketed sequence.** If normalization leaves the cursor at an opening bracket and then at a closing bracket, both delimiters are consumed. No payload bytes are written, no resize is requested, and no new parser error is assigned.

2. **Wrong opening byte.** If the current byte is an ordinary non-opening character before the input end, the cursor advances one byte, the opening-failure diagnostic dependency is called, and parser error becomes three.

3. **Exactly twelve payload bytes.** If fragments yield exactly twelve copied bytes followed by a closing bracket, those bytes are written, but no prefix-to-directory resize occurs. The expected-total field is not directly updated.

4. **Nonstandard count arithmetic.** If prefix bytes four and five are one and two, respectively, the directory count is eighteen and its end offset is 300. It is not derived as a count of 258.

5. **Deferred directory completion.** With count one, exactly 28 copied bytes followed by a closing bracket do not trigger total-size calculation or the final resize. Those actions require another payload byte.

6. **Rounded body length.** With count one and a directory length value of five, the expected total becomes 36 when the next payload byte triggers the transition. The resize request is for 37 bytes. At most 36 payload bytes are accepted before a subsequent byte causes excessive-data failure.

7. **Zero-length body.** With count one and a directory length value of zero, a 29th payload byte triggers total-size assignment to 28 and a resize request for 29. That pending byte is then rejected because the output count already equals the total.

8. **Trailing zero adjustment.** A three-byte fragment ending in zero contributes two bytes. A four-byte fragment ending in zero contributes all four.

9. **Binary boundary equality.** If the binary-fragment cursor calculation lands exactly at the captured input end, the excessive-data diagnostic is called and error becomes three, before fragment copying.

10. **Token error after earlier temporary allocation.** If a prior less-than-prefixed fragment set the cleanup flag, but a later binary token-advance callback leaves a nonzero parser error, the immediate return does not call F-bf7242c98d06.
