# F-065f2521242a

## Purpose

F-065f2521242a performs an ordered lookup through a collection associated with an input object. It converts a supplied lookup value through a dependency, compares the converted value against successive records, and stops at the first record whose comparison result is zero.

A matching record does not necessarily produce a nonzero result. Its second word can prohibit returning a value; its associated collection can report zero elements; or the selected value itself can be zero. These outcomes all return the same 32-bit zero result.

The established behavior is a first-match selection with additional gates, not a search for the first usable or nonzero result. Once a match occurs, the function never resumes scanning later records.

The interpretation of the records as names, symbols, strings, properties, or another application-specific structure is unknown. Such meanings are not required by this contract.

## Interface

The function receives two inputs:

- **Object address:** A 32-bit address used to read one 32-bit field at byte offset 12.
- **Lookup value:** An opaque 32-bit value passed unchanged to F-83fcd2d25cd8.

There is no established null check on the object address. The read at offset 12 occurs before any dependency is called. A caller therefore must provide readable storage for that field even when the lookup conversion will return zero.

The object field at offset 12 supplies the outer collection handle. This field is captured once. Subsequent changes to the object’s field do not replace the captured handle during this invocation.

### Output

The function returns one 32-bit value:

- Zero for a failed lookup conversion, absent outer collection, exhaustion without a match, or a match rejected by one of the subsequent gates.
- Otherwise, the 32-bit word obtained through the matched record’s associated collection, as described below.

A successful lookup can also yield zero. The interface provides no separate success indicator, error code, or distinction between these cases.

## Behavior

### Initial capture and conversion

The first observable data read obtains the outer collection handle from the input object at offset 12.

The function then calls F-83fcd2d25cd8 with the supplied lookup value. This call occurs even if the captured outer collection handle is zero.

Traversal occurs only when both the conversion result and the captured outer collection handle are nonzero. Otherwise, the function returns zero.

The conversion result is retained and used for all comparisons. The function does not repeat the conversion between candidates.

### Outer traversal

The candidate index starts at signed 32-bit zero.

Before each candidate access, the function calls F-10b760faca36 with the captured outer collection handle. It interprets that call’s result as a signed 32-bit bound and compares the current index against it.

If the index is not less than the returned bound, traversal ends with a zero return. Consequently:

- An initial bound of zero produces no candidate access.
- An initial negative bound also produces no candidate access.
- The collection bound is not cached.
- A changed bound can shorten or extend traversal at later checks.

When the index is less than the current bound, the function calls F-6bbddce1b930 with the outer collection handle and the current index. Its result is treated as the address of a candidate record.

The function reads the candidate’s word at offset 0 and passes that value, followed by the retained conversion result, to F-9878699bd825.

A nonzero comparison result means the candidate does not match. In that case, the index advances by one and the next bound query occurs.

A zero comparison result means the candidate matches. The function then follows the matching-record path and returns from that path; it does not examine later candidates.

### Matching-record gate

After the comparison dependency returns zero, the function reads the matched record’s word at offset 4.

If this word is nonzero, the function returns zero immediately. It does not query the matched record’s associated collection and does not continue searching.

The test is against zero, not against a particular flag bit. Positive, negative, and otherwise nonzero 32-bit patterns all take this rejection branch.

### Associated collection query

If the gate word is zero, the function reads the matched record’s word at offset 8 and passes that value to F-10b760faca36.

There is no preceding null check for this call. A zero associated collection handle is still passed to the dependency.

If this dependency returns exactly zero, the function returns zero immediately.

This test differs from the signed bound comparison used during outer traversal. Here, any nonzero result permits further processing, including a negative signed result. It would therefore be inaccurate to specify this condition as “the associated collection has a positive count.”

### Final extraction

After a nonzero associated-collection query result, the function reads the matched record’s field at offset 8 again.

If that read is zero, the function returns zero.

Otherwise, the function reads the field at offset 8 again for the final address calculation. From the associated collection designated by this last read, it reads the 32-bit address at byte offset 4. It then reads and returns the 32-bit word at that address.

This is a two-level memory read after obtaining the associated collection handle. The return value is neither the associated collection handle nor necessarily the address stored at its offset 4.

The final extraction does not use F-6bbddce1b930 to obtain an element. Although the layout may suggest access to the first stored entry, that interpretation is inferred rather than established.

### Arithmetic and termination

The supplied representation uses 32-bit integer and address values. The traversal index and outer-bound comparison are signed.

For an ordinary finite traversal, the index is incremented only when it is below a signed 32-bit bound. With conventional signed 32-bit results, an index at the maximum signed value cannot satisfy that comparison. The visible traversal therefore does not require a signed increment beyond that maximum.

Address offsets are byte offsets. This contract requires valid reached addresses rather than assigning behavior to invalid address arithmetic or inaccessible memory.

Termination is not guaranteed independently of dependencies. A dependency may fail to return. Collection growth or other dependency behavior may also affect which indices are reached. No timeout or iteration limit is established.

## Side effects

That observation applies only to the function’s own visible operations. Its dependencies may have side effects. In particular, this contract does not assume that they:

- Preserve global state.

- The outer collection handle is captured before conversion.
