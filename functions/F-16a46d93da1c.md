# F-16a46d93da1c

## Purpose

F-16a46d93da1c replaces two adjacent 32-bit fields in caller-supplied storage. The field at the lower address receives a pattern obtained from a fixed global location during the invocation. The other field receives the caller’s 32-bit pattern.

The replacement is unconditional within the domain of valid accesses. Previous destination contents do not affect the selected values, and neither replacement is conditional on whether the field already contains the desired pattern.

The contract includes access ordering, not merely a final memory image. The global pattern is obtained before destination modification, and the higher-addressed field is written before the lower-addressed field. Consequently, valid source–destination overlap can affect the global storage without changing which source pattern the invocation has already selected.

**Inferred intent:** this may initialize or refresh a two-field record. The supplied evidence does not establish a record type, field meanings, or a lifecycle transition.

## Interface

### Inputs

There are two explicit inputs:

- **Destination address:** identifies writable storage containing the two affected fields.
- **Caller pattern:** an opaque 32-bit value copied in full into the higher-addressed field.

There is one implicit input:

- **Global pattern:** a 32-bit value obtained from one fixed global storage location during the invocation.

“Fixed” describes the source location, not a constant value. Its contents may differ between invocations.

The destination layout is:

| Displacement from destination | Field width | Value required on normal completion |
|---|---:|---|
| 0 bytes | 32 bits | Global pattern obtained by this invocation |
| 4 bytes | 32 bits | Caller pattern |

The affected destination span is eight bytes. No additional fields or containing allocation size are established.

Both values are treated as complete bit patterns. The evidence does not establish signedness, numeric meaning, pointer interpretation, flag semantics, or application-level validity constraints. No narrowing, widening, arithmetic, or masking is represented.

### Output

There is no return payload or explicit success indicator. The result is communicated through the two destination writes.

Previous field contents are neither returned nor otherwise used to select the replacement values. The operation does not report whether either field changed.

### Preconditions for normal completion

The global source must permit the represented four-byte read. The destination must permit four-byte writes at displacements zero and four.

Those accesses must satisfy the execution environment’s requirements for address validity, storage lifetime, alignment, permissions, and permitted aliasing. No initial destination value is required.

These are preconditions, not checks performed by the operation. The supplied evidence contains no destination validation or source-access validation.

Pointer width, exact alignment requirements, and address-overflow behavior are **documented_only**. The four-byte displacement describes the second field’s location; it does not authorize wrapping an address or writing outside valid storage.

## Behavior

### Completed result

For a normally completed invocation, the lower-addressed field contains the global pattern obtained during that invocation, and the higher-addressed field contains the caller pattern.

Every bit of each 32-bit pattern is preserved. Zero, all-one patterns, and patterns with the high bit set receive the same treatment as other values.

The replacement does not depend on either field’s previous contents. There is no represented equality check, rejection rule, or alternate path for particular patterns.

An already-correct destination still has both writes as represented effects. An unchanged final memory image therefore does not establish that the operation performed no writes.

### Ordering and intermediate state

The global-source read precedes both destination writes. The higher-addressed destination write precedes the lower-addressed destination write.

This ordering has two contractual consequences:

- A destination write cannot change the pattern already obtained from the source for the same invocation.
- Where an intermediate observation is valid, there can be a point at which the higher-addressed field has its replacement value while the lower-addressed field has not yet received its replacement.

These are ordering properties of the supplied static representation. They do not establish an atomic eight-byte update, atomic four-byte accesses, a memory barrier, or a synchronization protocol.

No permission for concurrent observation follows from this contract. Whether a particular observer may legally read the storage, and which values it can observe under the applicable memory model, remain **documented_only**.

### Source–destination overlap

No overlap detection or alternate overlap path is represented. If an overlap arrangement is valid in the execution environment, the same value-selection and ordering requirements apply.

When the source is exactly the higher-addressed destination field, the lower-addressed field receives that source field’s earlier pattern. The higher-addressed field receives the caller pattern. The source storage therefore ends with the caller pattern, not necessarily the pattern obtained earlier.

When the source is exactly the lower-addressed field, the operation obtains its existing pattern and later writes that pattern back. In the absence of outside interference, that field’s final value is unchanged. Its write nevertheless remains a represented effect.

For a valid partial overlap, the source pattern is obtained before any destination modification. Both destination fields must still have their specified final patterns. Bytes shared with the source can change as a consequence of the destination writes.

The final interpretation of a partially overlapping source region depends on its placement and the environment’s byte order. No particular partial-overlap arrangement is assumed valid.

### Repeated invocations

Each invocation obtains a global pattern anew. No retained source snapshot or invocation counter is represented.

With disjoint source and destination storage, previous destination values do not determine subsequent replacement values. With overlap, an invocation may alter the source through its destination writes, changing the pattern available to a later invocation.

The operation does not itself establish a rule preventing another component from changing the source between invocations.
