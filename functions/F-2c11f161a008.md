# F-2c11f161a008

## Purpose

F-2c11f161a008 performs an ordered sequence of byte accesses and indirect calls, then enters an unconditional loop containing **ten calls per completed iteration**.

The visible behavior includes:

- Writing two selected bytes of the first input through freshly read address selectors.
- Writing a dependency-derived byte to an address calculated from the fourth input.
- Clearing byte destinations selected by further byte reads.
- Transforming dependency results into call arguments and selector-read addresses.
- Carrying two argument values and an indirect-call destination selector between loop iterations.

The first call site in the loop, F-U27, does not use the same destination on every iteration. Its first invocation uses a control-location value established immediately before F-U26. Later invocations use a different control-location value established immediately before F-U36.

No application-level purpose is established. In particular, the evidence does not identify the low-address accesses as ordinary memory, device registers, protocol operations, or intentional valid accesses.

The supplied static representation reports invalid instruction data and removal of unreachable regions. This contract describes its visible behavior without asserting that the representation completely or correctly recovers the original executable.

## Behavior

### Widths and arithmetic

Selector reads are unsigned eight-bit reads, producing values from 0 through 255. Every direct write stores one byte; input-derived and result-derived writes retain only the low eight bits.

The explicit inputs and designated unsigned dependency results are 32 bits wide. Their right shifts are logical. Unsigned left shifts discard bits beyond bit 31.

Several other results are represented as signed 32-bit values before left shifts. The retained selector-address basis also passes from an unsigned shifted value into a signed 32-bit quantity before multiplication.

Exact executable behavior for signed overflow, signed left shifts, and out-of-range unsigned-to-signed conversion is not independently established. Modular examples below are conditional on a 32-bit machine interpretation that retains the low 32 bits. They do not assert that corresponding high-level signed expressions are defined for every operand.

### Selector-based writes

A **state-selected write** has this observable access order:

1. Read one unsigned byte at the incoming state base plus one.
2. Add 17 to the byte value.
3. Write one byte at the resulting address.

The final destination is between address 17 and address 272 inclusive. The state base locates the selector; it is not added to the final destination.

A **result-selected clear** has this observable access order:

1. Read one unsigned byte at a selector address derived from F-U12.
2. Add 17 to the byte value.
3. Write zero at the resulting address.

Its final destination is also between 17 and 272 inclusive.

Every occurrence performs a fresh selector read. Earlier selector values cannot be reused: preceding writes or dependency effects may change the byte subsequently read.

### Prefix: first-input propagation

The initial sequence is:

1. Perform a state-selected write of the first input’s low byte.
2. Invoke F-U01 with three copies of the full first input.
3. Invoke F-U02 and pass its 32-bit result to F-U03.
4. Invoke F-U04, F-U05, and F-U06, in that order.
5. Invoke F-U07 and retain its signed 32-bit result.
6. Perform a state-selected write of the low byte of the first input shifted right by 22.
7. Invoke F-U08 with the F-U07 result shifted left by two.
8. Invoke F-U09, F-U10, and F-U11, in that order.
9. Invoke F-U12 and retain its unsigned 32-bit result.

The second input-derived byte contains bits 22 through 29 of the first input. It is not the highest byte.

Unless explicit arguments are specified, the representation shows no arguments. This does not establish that the machine-level dependency has no hidden inputs.

### Prefix: fourth-input destination and additional clears

After F-U12 returns:

1. Shift its result left by two as an unsigned 32-bit operation. Retain that shifted bit pattern as the basis for later selector-address calculations.
2. Shift the fourth input right by seven.
3. Write the low byte of the shifted F-U12 result at address 28 plus the shifted fourth input.
4. Perform a state-selected write of zero.
5. Invoke F-U13 with the fourth input shifted right by seven.
6. Invoke F-U14.
7. Invoke F-U15 with bits 6 through 29 of the original F-U12 result, repositioned into bits 0 through 23.
8. Invoke F-U16, F-U17, and F-U18, in that order.
9. Invoke F-U19 and retain its signed 32-bit result.
10. Perform another state-selected write of zero.
11. Invoke F-U20 with the F-U19 result shifted left by two.
12. Invoke F-U21, F-U22, and F-U23, in that order.
13. Invoke F-U24 and retain its unsigned 32-bit result.

The fourth-input-derived write destination ranges from 28 through 33,554,459 inclusive. That unsigned address calculation does not overflow 32 bits.

F-U15’s argument is formed by clearing the F-U12 result’s highest two bits and then shifting right by six. Its range is 0 through 16,777,215.

Later results do not visibly replace the selector-address basis retained from F-U12.

### Prefix: initializing loop state

After F-U24 returns:

1. Clear its highest two bits and shift right by 25. The resulting unsigned value is between 0 and 31 inclusive.
2. Perform a result-selected clear. The selector-read address is the retained shifted F-U12 value multiplied by 1,024, plus one.
3. Invoke F-U25 with twice the extracted F-U24 value, producing an argument between 0 and 62 inclusive.
4. Establish the initial-loop control-location value immediately before invoking F-U26.
5. Invoke F-U26 and retain its signed 32-bit result as the first loop-carried argument.

Under wrapping 32-bit arithmetic, the selector-read address is equivalent to the original F-U12 result shifted left by 12, plus one, modulo the 32-bit address space. This selector-read address must not be confused with the low-address destination selected by its byte contents.

The initial-loop control-location value established before F-U26 is used by the subsequent F-U27 invocation. It is not the control-location value selecting F-U26 itself.

### Repeated cycle and carried state

The loop carries **three** components:

| Component | Initial value | Value for subsequent iterations |
|---|---|---|
| First argument | F-U26’s result | F-U36’s result shifted left by two |
| Unsigned shift state | Five-bit field extracted from F-U24 | F-U36’s result shifted left by 26, then retained as unsigned 32 bits |
| F-U27 control-location state | Initial-loop value established immediately before F-U26 | Different repeat-loop value established immediately before F-U36 |

Each completed iteration performs these ordered actions:

1. Invoke F-U27 using the carried control-location state to select its destination. Its explicit arguments are the carried first argument and the unsigned shift state shifted right by eight.
2. Invoke F-U28, F-U29, and F-U30, in that order.
3. Invoke F-U31 and retain its signed 32-bit result.
4. Perform a result-selected clear using the selector-address basis retained from F-U12.
5. Invoke F-U32 with the F-U31 result shifted left by two.
6. Invoke F-U33, F-U34, and F-U35, in that order.
7. Establish the repeat-loop control-location value immediately before F-U36.
8. Invoke F-U36 and retain its signed 32-bit result.
9. Derive the next first argument and unsigned shift state from that result.
10. Repeat, carrying the repeat-loop control-location value into the next F-U27 invocation.

There are ten calls: F-U27 through F-U36 inclusive. The state assignments and byte clear do not change that count.

F-U27’s destination is calculated by adding 4,094 to its carried control-location value. The initial-loop and repeat-loop values differ, so the displayed destination calculation changes after the first iteration. Later iterations reuse the repeat-loop value; the target is not selected from F-U36’s return value.

The first F-U27 invocation always receives zero as its second argument because the initial shift state is at most 31.

Under the stated wrapping interpretation, subsequent second arguments equal the preceding F-U36 result’s low six bits shifted left by 18. F-U24 controls only the initial shift state.

There is no visible loop exit, cleanup phase, accumulated return result, or normal return.

- Four state-selector byte reads and four corresponding byte writes.

## Acceptance examples

These are conditional contract examples, not executed tests. They assume valid accesses and returning dependencies wherever later behavior is described.

1. **Fresh state selectors.** If the first state selector is 5, the initial byte write targets address 22. If the selector is 9 at the next state-selected write, that write targets address 26. Reusing 5 would violate the displayed access behavior.

2. **First-input field.** For first input hexadecimal A5C000AB, the initial byte write stores AB and the second input-derived write stores 97. F-U01 receives the full value A5C000AB three times.

3. **Fourth-input boundaries.** Fourth-input values 0 through 127 select address 28. Value 128 selects address 29. The maximum unsigned 32-bit value selects address 33,554,459.

4. **F-U12 propagation.** If F-U12 returns hexadecimal 00000123, the fourth-input-derived byte write stores 8C and F-U15 receives 4. Under wrapping arithmetic, subsequent result-selector reads use address hexadecimal 00123001.

5. **Initial numeric loop state.** If F-U24 returns hexadecimal 3E000000, the extracted state is 31 and F-U25 receives 62. The first F-U27 invocation nevertheless receives zero as its second argument.

6. **Changing F-U27 destination.** If execution completes two iterations, the first F-U27 invocation uses the control-location value established before F-U26, plus 4,094. The second uses the different value established before the first F-U36, plus 4,094. A third invocation uses that repeat destination again. Using the first destination throughout would not match the representation.

7. **Numeric loop transition.** If F-U36 returns 3, the next F-U27 invocation receives 12 and hexadecimal 000C0000, under the wrapping interpretation. Its destination is the repeat destination, independently of those argument values.

8. **Iteration call count.** An iteration reaching its back edge has invoked F-U27, F-U28, F-U29, F-U30, F-U31, F-U32, F-U33, F-U34, F-U35, and F-U36: ten calls.

9. **Dynamic clear destination.** A result-selector byte of 255 causes a zero write at address 272. If it is 0 at the next read, that clear targets address 17.

10. **Interrupted prefix.** If F-U13 does not return, the preceding fourth-input-derived write and state-selected zero write have already occurred. Later prefix calls and the loop are not reached.
