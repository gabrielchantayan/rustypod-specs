# F-5306c1e4a5ff

## Purpose

F-5306c1e4a5ff repeatedly traverses a context-resident 256-bit selection map. Each selected position can produce one call to F-44c2d260d7a4, using a calculated source value and destination address. A signed 16-bit mode field controls validation and source-index calculation.

The visible return paths produce a 32-bit result of either:

- **1:** An outer-loop entry observes that the requested iteration count has been reached, and F-4042d12a1376 returns from its completion call.
- **0:** A selected position fails the mode-8 bound check, or F-44c2d260d7a4 returns zero and the subsequent F-3ba698310ee1 call returns.

These results describe this function’s control flow. They do not independently establish successful data transfer, memory clearing, error reporting, or resource release.

## Behavior

### Outer-loop admission and completion

The outer index starts at zero.

At each outer-loop entry, the function reads the unsigned byte at `0x1D2`. If the current outer index is greater than or equal to that observed limit, the function:

1. Calls F-4042d12a1376 with the address of the selection map, the value 32, and the value 0.
2. Returns 1 after that call returns.

This check precedes the iteration’s stride, source-base, and map-byte reads. An initially observed limit of zero therefore reaches completion without scanning the map.

When another iteration is admitted, the function reads the 32-bit stride at `0x1E0`, followed by the 32-bit source base at `0x80`. Both values are retained for that iteration. A dependency’s later changes to those fields do not replace the captured values used in the current iteration.

The iteration limit is not captured for the invocation. Each subsequent outer-loop entry reads it again.

### Selection-map traversal

Each admitted iteration visits 32 map-byte positions in ascending address order, from `0x92` through `0xB1`, unless execution returns early or fails to continue normally.

Each map byte is read once when that byte’s scan begins. Its captured value is then examined from least significant bit toward most significant bit. Processing stops within that captured byte when no set bits remain; trailing zero bits have no further effect.

For a byte position \(b\), numbered 0 through 31, and bit position \(k\), numbered 0 through 7, the selected index is:

\[
j = 8b + k
\]

The visible index construction uses bitwise OR. It is equivalent to this addition because the byte contribution has its low three bits clear.

Selected positions are therefore processed in increasing index order within each outer iteration. A zero bit produces no lookup or dependency call. A zero map byte produces no per-selection lookup.

Map mutation follows the timing of reads:

- Changing the currently captured byte does not alter its remaining selected positions in the current scan.
- Changing a later byte can affect that byte when it is read.
- Later iterations reread the map.
- An earlier write does not guarantee a later read’s value if another dependency or external actor changes the storage again.

### Initial lookup and first mode decision

For every selected index, the function first reads the unsigned byte at `0xB8 + j`. This initially supplies the destination selector.

It then reads the signed 16-bit mode at `0x6C`.

If this first mode read equals 8:

- The destination selector becomes the selected index itself.
- The unsigned 16-bit field at `0x90` is read as an exclusive bound.
- If the bound is less than or equal to the selected index, the function immediately returns 0.

Thus a mode-8 rejection still follows an initial byte lookup. It does not perform the word lookup or invoke F-44c2d260d7a4 for that rejected position. Neither F-3ba698310ee1 nor F-4042d12a1376 is called on this rejection path.

If the first mode read is not 8, this bound check is absent and the initial byte value remains the destination selector.

### Second mode decision and source calculation

The mode is read again before selecting the source calculation. This is a distinct observation, not an invocation-wide or per-position snapshot guarantee.

If the second mode read is not 8, the effective source index is the selected index.

If the second mode read equals 8, the effective source index is:

\[
\text{selected index}
+
\text{factor}\times
\bigl(\text{word entry}\mathbin{\&}\texttt{0x7FFFFFFF}\bigr)
\]

Here:

- The factor is an unsigned 16-bit read from `0x90`.
- The word entry is an unsigned 32-bit read from `0xB8 + 4j`.
- The high bit of the word entry is excluded before multiplication.
- The multiplication and addition produce a 32-bit unsigned result.

The supplied expression does not establish the relative order of the factor and word-entry reads. The factor read for this calculation is distinct from the earlier bound read, when that earlier check occurs.

For stable mode 8, the bound check necessarily precedes this calculation. For changing observations, the two decisions remain separate: the first mode read controls selector replacement and validation; the second controls source calculation. In particular, a second observation of 8 does not by itself establish that the first observation performed validation.

### Per-selection arguments

The source argument is the 32-bit combination of:

- The source base captured for the current iteration;
- The outer index multiplied by the captured stride;
- The effective source index.

The destination argument is the 32-bit combination of:

- A fresh read of the destination base at `0x1B8`;
- The destination selector’s low seven bits multiplied by 512.

The displacement therefore ranges from 0 through 65,024, in multiples of 512. Different selectors can map to the same destination displacement. No destination-capacity check is visible.

Arithmetic involving the unsigned 32-bit quantities retains the low 32 bits. Neither the mode-8 product nor the source and destination additions are checked for overflow. Clearing the table entry’s high bit does not prevent subsequent multiplication overflow.

F-44c2d260d7a4 receives five arguments:

1. The 16-bit field read at `0x78`.
2. The calculated source value.
3. The calculated destination address.
4. The constant 1.
5. The constant 0.

The dependency’s parameter meanings and precise ABI extension rules for the 16-bit field are not supplied. The constant 1 does not establish a byte count, block count, or operation size.

The separate argument-expression reads of the field at `0x78` and destination base at `0x1B8` have no established relative order in the supplied representation.

### Per-selection result and advancement

If F-44c2d260d7a4 returns zero, the function calls F-3ba698310ee1 with the single argument 0, then returns 0 after that call returns. The notification dependency’s return value, if any, is not used.

Any nonzero per-selection result permits traversal to continue. There is no distinction among nonzero results.

After all map-byte positions have been visited, the outer index advances and the outer-entry check repeats.

The visible counter arithmetic includes these masks:

- The bit-position increment retains its low eight bits. The captured byte allows at most eight relevant bit positions, so this does not wrap during a byte scan.
- The byte-position contribution and outer-index increments apply `0xFFFEFFFF`, which clears bit 16 rather than truncating to 16 bits.

The latter mask does not change reachable progression here. Byte contributions used for processing range from 0 through 248. The outer index cannot admit an iteration at 255 because the freshly read limit is an unsigned byte with maximum value 255.

Consequently, with valid accesses and normally returning dependencies, at most 255 outer iterations and 65,280 per-selection calls can occur.

## Acceptance examples

These are conditional static acceptance cases, not executed tests. Each assumes accessible reached storage and normal return from dependencies unless otherwise stated. Stability assumptions constrain the scenario; they are not guarantees made by this function.

### Initially zero limit

If the first limit read yields zero:

- No map byte, stride, or source base is read for an iteration.
- No per-selection call occurs.
- F-4042d12a1376 receives the map address, 32, and 0.
- Its normal return is followed by result 1.

### Empty map for two iterations

If the outer-entry reads yield 2, 2, and 2, and every map-byte read in both admitted iterations yields zero:

- Both iterations visit all 32 map-byte positions.
- No per-selection lookup or F-44c2d260d7a4 call occurs.
- The third outer-entry check invokes completion.
- The result is 1 after completion returns.

### Direct-mode order with explicit observation conditions

Assume:

- The first and next outer-entry limit reads both yield 1.
- During the admitted iteration, the map-byte reads yield only selected indices 1 and 8.
- Both mode reads for each position yield a value other than 8.
- The byte lookup for index 1 yields `0x83`.
- Both per-selection calls return nonzero.

Then index 1 is processed before index 8. Their source arguments use the captured base plus 1 and plus 8, respectively, modulo \(2^{32}\). Index 1’s destination displacement is 1,536.

Completion follows after the full scan. This conclusion requires the stated later map-byte and limit observations: the first call’s nonzero result alone does not preserve index 8 or the outer limit.

### Mode-8 equality rejection

If a selected index is 5, its first mode read yields 8, and its bound read yields 5:

- Its initial byte lookup occurs.
- Equality causes immediate result 0.
- No word lookup or per-selection call occurs for index 5.
- Neither failure notification nor completion is called on that path.

A bound of zero rejects every position reaching this mode-8 check, but an empty map performs no such check.

### Mode-8 high-bit masking

If selected index 3 observes mode 8 at both checks, both bound/factor reads yield 10, and its word lookup yields `0x80000002`:

- The bound check passes.
- The masked entry is 2.
- The effective source index is 23.
- The destination displacement is 1,536.
- The initial byte lookup occurs but does not determine that displacement.

### Failure after progress

If earlier per-selection calls return nonzero and a later reached call returns zero:

- The earlier calls remain part of the execution.
- F-3ba698310ee1 receives 0.
- After it returns, this function returns 0.
- No further positions or completion call are processed.

### Mutation during traversal

If a per-selection dependency writes zero to the outer limit, that write alone does not stop the current scan.

Completion follows at the next outer-entry check **if execution reaches that check and the limit read there still yields zero**. Earlier rejection, a later zero per-selection result, nonreturning dependencies, or another write to the limit can invalidate that conclusion.

Similarly, a later map byte is processed according to its eventual read, not necessarily according to either its initial value or an intermediate write. Changes to the currently captured byte do not alter its remaining captured bits.
