# F-89471e78566a

## Purpose

F-89471e78566a coordinates three externally observable operations on a caller-supplied object:

1. Obtain a value from F-08e2860e8e52 using one of two embedded object regions and a companion object field.
2. Transform that value through a 16-bit decrement-and-substitution rule, then pass the result to F-c47cf0b2619a using a newly selected region and a freshly read companion field.
3. Invoke an object-associated indirect callback with the object, an unresolved externally supplied value, and a freshly read companion field increased by `0x5795`.

The region choice is made independently before each named dependency call. It is not a single selection retained throughout the operation. Changes made by the first dependency can therefore affect the second call; changes made by either dependency can affect the final callback.

The arithmetic substitution is established behavior. A possible interpretation as moving backward through a character or symbol sequence is inferred intent only. The available evidence does not establish a character encoding, a valid input range, or the meanings of either embedded region.

## Behavior

### 1. First region selection and value acquisition

The function reads the selector at object offset `0xA0`.

- If the value is exactly one, it selects the embedded region beginning at offset `0xA4`.
- For every other value, including zero, negative values, and other positive values, it selects the embedded region beginning at offset `0x6C`.

It calls F-08e2860e8e52 with:

1. The selected embedded-region address.
2. The companion integer read from object offset `0x8C` for this call.

The selector read precedes this dependency invocation. The companion field supplies the second argument; it is not a previously captured entry-time value.

The returned value is consumed as a signed 16-bit value. The available evidence establishes the 16-bit value used by this function, but not the dependency’s complete native return declaration or the meaning of any wider return bits.

### 2. Sixteen-bit decrement and substitution

The function subtracts one from the signed 16-bit value, then converts the result to an unsigned 16-bit quantity.

The conversion retains the result modulo 65,536. In particular:

- A consumed value of zero produces `0xFFFF`.
- A consumed value of negative one produces `0xFFFE`.
- A consumed value of −32,768 produces `0x7FFF`.

The subtraction ranges from −32,769 through 32,766. It fits in the represented 32-bit integer arithmetic; the significant boundary behavior comes from conversion to 16 bits, not from a required signed-overflow event in this step.

The unsigned 16-bit result is then compared with `0x30`:

- If it is less than `0x30`, it is replaced by `0x39`.
- Otherwise, it remains unchanged.

Thus, consumed signed return values **one through 48 inclusive** all become `0x39`. A consumed value of 49 becomes `0x30`.

This is not general range validation or a clamp to a bounded alphabet. Values outside the substitution interval remain possible, including `0xFFFF`, `0xFFFE`, and `0x7FFF`. The final value `0x39` can arise either through substitution or through an ordinary decrement, as when the consumed return value is 58.

### 3. Second region selection and update invocation

After F-08e2860e8e52 returns, the function reads the selector at offset `0xA0` again and applies the same exact-one rule.

It then calls F-c47cf0b2619a with:

1. The region address selected by this second selector read.
2. The companion integer freshly read from offset `0x8C`.
3. The transformed unsigned 16-bit value.

The first selection does not constrain the second. For example, if the first dependency changes the selector from one to zero, the first call uses offset `0xA4` and the second uses offset `0x6C`.

Likewise, the companion integer used for this second call may differ from the one passed to F-08e2860e8e52.

The third argument’s established numerical range is zero through 65,535, although the transformation does not produce every value in that range. Its physical argument-passing width and the callee’s declared parameter type are not independently established. No interpretation as a signed 16-bit argument is justified merely because the acquisition result was consumed as signed.

No return value from F-c47cf0b2619a is used by the represented caller.

### 4. Indirect callback

After F-c47cf0b2619a returns, the function performs an indirect callback through the structure referenced by the object’s first word. The callable entry is at byte offset `0x58` within that structure.

The callback receives three arguments:

1. The original input object pointer.
2. A value supplied by an unresolved external data reference.
3. The current companion integer from object offset `0x8C`, increased by `0x5795` decimal 22,421.

The companion field is read again for this final expression. The function does not reuse either earlier companion argument.

The callback target is also obtained after the named dependency calls. A dependency that changes the object’s first word or callback-bearing structure can therefore change the final dispatch, provided the resulting state remains valid.

The addition is represented as integer addition in the reconstructed 32-bit model. For a signed 32-bit interpretation, values at or below 2,147,461,226 avoid upper overflow; adding this positive constant cannot cause lower signed overflow. The evidence does not resolve the behavior for larger field values. In particular, it does not establish whether such inputs are forbidden, whether the executable wraps, or whether another integer interpretation applies.

The callback’s return value is not used. Normal completion consists of returning after that callback returns.
