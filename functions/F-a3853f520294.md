# F-a3853f520294

## Purpose

The available static evidence describes a procedure that interleaves four coprocessor operations with seventeen indirect calls, propagates selected 32-bit and 64-bit results between those calls, attempts one 16-bit memory write, and reaches a boundary marked as invalid instruction data.

No application-level purpose is established. In particular, the evidence does not establish that this is a valid initialization, device-control, decoding, or memory-management routine. Such interpretations would require additional evidence.

The contract below describes the visible sequence, conditional on the supplied control-flow reconstruction being valid and each preceding operation completing normally. The invalid-instruction warning materially limits confidence in that reconstruction.

### Final memory write and termination boundary

After F-000000000017 returns, the procedure attempts one 16-bit store of numeric value `0x00CD`.

Let:

\[
N = R \mathbin{\text{logical-right-shift}} 52
\]

The destination’s numerical address is:

\[
N + \left\lfloor N/4 \right\rfloor
\]

This simplification follows from the visible two-stage shift. The intermediate produced by shifting `R` right by 41 is nonnegative as a signed 32-bit quantity, so its subsequent signed right shift by eleven does not introduce sign extension.

Consequently:

- Only bits 52–63 of `R` determine this destination.
- \(0 \leq N \leq 4095\).
- The numerical address lies between 0 and 5118 inclusive.
- There is no visible base pointer added to that address.
- The store width is two bytes, not one byte and not four bytes.

The address range is a bound, not a claim that every address in the interval is reachable.

No address validation, alignment adjustment, or explicit fault handling precedes this store. If it succeeds, the visible reconstruction next reaches the invalid-instruction boundary. An ordinary return is not shown.

## Acceptance examples

These are conditional static acceptance examples, not runtime test results. They assume the reconstructed path is valid, 32-bit shifts behave as specified, required operations are permitted, and earlier calls return normally.

1. **Zero-valued explicit inputs**

   With first and fourth inputs both zero, the first call’s first, third, and fourth displayed arguments are zero. Its second argument remains the supplied second input. This does not force later dependency results or the final destination to zero.

2. **Shift truncation**

   With `A = 0x80000001`, shifting left by one yields `0x00000002`, and `T` is `0x00000010`. F-000000000005 therefore receives `0x00001000` and `0x00010000` as its first two displayed arguments. Its third argument still depends on F-000000000004.

3. **Fourth-input bit selection**

   With `D = 0x00000001`, the first call’s fourth argument is `0x00400000`, and the second coprocessor request’s data value is `0x80000000`. With `D = 0x00000400`, both quantities are zero after 32-bit truncation.

4. **Invariant zero arguments**

   For every first-input bit pattern, F-000000000008 receives zero, and F-000000000016 receives zero as its second displayed argument. This follows from the cleared low bits of `T`, not from any dependency result.

5. **Result splitting**

   If F-000000000006 yields `0x0123456789ABCDEF`, F-000000000007 receives `0x89ABCDEF`, `0x01234567`, and `0x13579BDE`, in that order.

6. **Address endpoint cases**

   If bits 52–63 of `R` are zero, the attempted store targets numerical address zero. If those bits are all one, \(N=4095\), and the attempted store targets address 5118. Neither case establishes that the write is permitted.

7. **Alignment-sensitive destination**

   If \(N=1\), the destination is address one. The visible behavior does not round it to an aligned address. Whether the 16-bit store succeeds, faults, or has architecture-specific behavior is documented_only.

8. **Selected address bits**

   If two results from F-000000000013 have identical bits 52–63, they produce the same directly derived store address. Differences in lower bits can still change the argument to F-000000000014 and thereby affect whether execution reaches the store.

9. **Interrupted execution**

   If F-000000000015 does not return, F-000000000016, F-000000000017, and the final store are not reached on this path. No compensating operation is visible.
