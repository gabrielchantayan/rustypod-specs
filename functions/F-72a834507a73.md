# F-72a834507a73

## Purpose

F-72a834507a73 repeatedly obtains a 32-bit value through a dependency and distinguishes a termination marker from an ordinary record. For an ordinary record, it performs an ordered sequence of resource-related calls and conditional callbacks. For a termination marker, it either follows a nonreturning path or clears a control field, invokes a final dependency, and returns.

The apparent intent is a record-processing and teardown loop. That interpretation is inferred from the repeated acquisition and cleanup-shaped call sequence; the identities of the records, resources, and control structure are not established.

This contract describes the supplied static representation. It does not establish the behavior of dependencies, prove memory ownership, or report runtime observations.

## Interface

### Entry and return

- The represented interface has no formal parameters and no return value.
- An incoming machine-register value initializes a local 32-bit output slot before the first dependency call. Its meaning and validity are unknown. It is not established as a public argument.
- A global pointer supplies the initial control-block address.
- Normal return occurs only through the termination-marker branch whose associated control field is zero.
- Ordinary processing and zero-result acquisitions do not themselves cause return.
- A separate termination-marker branch invokes a dependency marked nonreturning.

## Behavior

### 1. Capture control state and initialize the acquisition slot

The function reads the global control pointer once and retains that initial address for its loop accesses. Later changes to the global pointer do not replace this retained loop address.

The local acquisition slot initially contains the incoming machine-register value. Its address is subsequently exposed to F-7cb85bea67e9.

### 2. Begin an outer iteration

At the beginning of each outer iteration, the function:

1. Reads the word at offset 0 from the retained control address.
2. Calls F-8d37083d6a96 with that word.
3. Starts attempting acquisition.

The offset-0 word is read again on each outer iteration. It is not a function-entry snapshot.

### 3. Attempt acquisition

For each attempt, the function:

1. Reads the word at retained-control offset +4.
2. Calls F-7cb85bea67e9 with that word, the address of the local acquisition slot, and the numeric argument 4.
3. Reads the global control pointer again, retaining this new value as a separate snapshot.
4. Tests the acquisition result as a 32-bit zero/nonzero value.

Every nonzero result takes the record-or-marker path, including negative values if the result is interpreted as signed. No distinct error classification is visible.

A zero result ends the inner acquisition loop. Execution immediately begins another outer iteration, including another F-8d37083d6a96 call. There is no visible delay, retry limit, return, or additional error handling.

The supplied representation does not prove that F-7cb85bea67e9 writes the local slot on every nonzero result, nor that it leaves the slot unchanged on zero. Correct processing requires the slot to contain a usable marker or record value when a nonzero result is processed.

### 4. Distinguish a termination marker

For a nonzero acquisition result, the function reads the marker word at retained-control offset −12 and compares it with the acquisition slot.

This comparison precedes all record dereferences.

If the values match:

- The function reads retained-control offset +4 again.
- If that word is nonzero, it calls F-43dfd83d7fa1 and then F-feee9156a257. The latter is marked nonreturning. No normal continuation from that call is established.
- If that word is zero, the function explicitly writes a 32-bit zero to retained-control offset +4, calls F-1bf9985dc121 with the global-pointer snapshot obtained immediately after the acquisition call, and returns if that dependency returns.

The final call does **not** necessarily receive the original control pointer. It receives the post-acquisition global snapshot. Conversely, a later change to the global pointer does not by itself replace that snapshot.

The marker is not processed as a record. No explicit marker release is visible.

### 5. Process an ordinary record

When the acquisition slot does not match the marker, processing follows this order:

1. Read the associated-object address from record offset +12 and retain it for this processing sequence.
2. Read record offset +16 and pass its word to F-ca4f8eb7b449.
3. Read associated-object offset +16 and call F-8349c252c168 with that word and numeric argument 9.
4. Read associated-object offset +20. If nonzero, call F-8349c252c168.
5. Read associated-object offset +24. If nonzero, call F-8349c252c168.
6. Read the byte at associated-object offset +80. If nonzero:
   - Call F-a600efb7b035 with the address at associated-object offset +60.
   - After that call returns, write a zero byte at associated-object offset +80.
7. Read associated-object offset +28. If nonzero, call F-ade1ebf0703a.
8. Read associated-object offset +32. If nonzero, call F-14b2569b8148.
9. Read associated-object offset +44. If nonzero, invoke the callable selected through that target’s dispatch table at offset +4.
10. Read associated-object offset +56. If nonzero, invoke the callable selected through that target’s dispatch table at offset +4.
11. Call F-8349c252c168 with the retained associated-object address and numeric argument 8.
12. Obtain the record address from the acquisition slot, read its offset-0 word, and call F-8349c252c168 with that word and numeric argument 7.

After ordinary processing, the next acquisition attempt occurs without an intervening F-8d37083d6a96 call. That dependency is reached again only after an acquisition returns zero and restarts the outer loop.

### Temporal requirements

The field reads occur at their respective stages, not as one initial snapshot. A dependency may therefore affect a later condition or argument by modifying memory that will subsequently be read.

The associated-object address is retained after its initial read. Changing the record’s associated-object field later does not redirect that retained address.

The acquisition slot is address-exposed to F-7cb85bea67e9. Whether that dependency retains the address, or whether later calls can alter the slot through other access, is unknown. The late record operations use the slot’s then-current value; immutable record identity across all calls is not an established guarantee.

## Acceptance examples

These examples are conditional static acceptance criteria, not executed tests.

1. **Zero acquisition result.**  
   If F-7cb85bea67e9 returns zero, the function does not inspect the acquisition slot as a marker or record for that attempt. It reloads the outer-iteration argument and calls F-8d37083d6a96 before attempting acquisition again.

2. **Nonzero is not restricted to positive success.**  
   If acquisition returns a negative 32-bit value and the output slot contains a valid non-marker record, the record-processing path is taken. The visible branch does not classify the negative result separately.

3. **Normal termination uses two control addresses distinctly.**  
   Suppose the initially retained control address differs from the global pointer read after acquisition. If the output matches the marker and retained-control offset +4 is zero, the zero write targets the retained control address, while F-1bf9985dc121 receives the newer global snapshot.

4. **Marker with a nonzero control field.**  
   If the output matches the marker and the subsequent control-field read is nonzero, F-43dfd83d7fa1 precedes F-feee9156a257. Ordinary record accesses, the normal-path zero write, and F-1bf9985dc121 are not reached along the represented nonreturning path.

5. **Optional object features absent.**  
   If the optional fields remain zero when individually read, their gated calls are skipped. The mandatory call using object offset +16 and the final calls using 8, 7, and 5 still occur, assuming all preceding calls return and required memory remains valid.

6. **Flagged embedded resource.**  
   If the byte at object offset +80 is nonzero when read, F-a600efb7b035 receives object address +60. The byte is zeroed after return. If that dependency does not return, the subsequent write is not reached.

7. **Earlier calls affect later decisions.**  
   If an earlier dependency changes object offset +32 to nonzero before its condition is evaluated, F-14b2569b8148 is called. A contract that snapshots all optional fields before cleanup would not match this read ordering.

8. **Record processing does not restart the outer iteration.**  
   After one ordinary record completes, another acquisition is attempted directly. F-8d37083d6a96 is not called between those attempts unless acquisition first returns zero.
