# F-0b94fb767a8f

## Purpose

F-0b94fb767a8f selects between processing a table-supplied value and making a fallback call that receives numeric argument 1. Selection depends on successive results from an indirect callback on an input object.

The recognized comparison values are 0x3C, 0x3E, and 0x26. Their correspondence to ASCII “<”, “>”, and “&” suggests substitution or escaping intent. The supplied body does not establish an encoding, the table contents, or the semantic purpose of the operation.

The comparisons use separate callback invocations. They do not classify one saved result against three alternatives. The first result is compared only with 0x3C, the second only with 0x3E, and the third only with 0x26. If all three comparisons fail, a fourth callback occurs before fallback.

Table selection also has an observable distinction between paths: after the first callback, the function captures the global table reference, but a first-comparison match reads that global reference again to select the first entry. The second- and third-comparison paths instead use the captured reference.

## Interface

### Arguments

| Argument | Established use |
|---|---|
| First | A 32-bit value unused by the visible body. It is not forwarded to any visible dependency. |
| Second | A 32-bit value forwarded unchanged to F-70f4a053b9ed on fallback or F-6693aefb6551 on a selected-entry path. Its concrete interpretation is unknown. |
| Third | An object address used to resolve an indirect callback. The same object address is passed as that callback’s sole explicit argument. |

For each callback invocation, dispatch resolution reads a dispatch-table address through the beginning of the object, then obtains the callable entry at byte offset 0x0C from that table. This resolution is repeated for every invocation; the callable entry is not visibly cached across calls.

The supplied representation uses 32-bit scalar values and four-byte table entries. Callback results are compared as returned integers, without a visible conversion or mask to eight bits. No comparison depends on signed ordering.

Each selected entry is read as a 32-bit value. The callback result is not used as a general array index.

### Return value

The function returns a 32-bit value.

On fallback, it returns the result of F-70f4a053b9ed unchanged.

On a selected-entry path:

| Condition | Return |

### Preconditions

Normal completion requires valid dispatch storage and a callable entry for every callback reached. It also requires the global reference location to be readable after the first callback.

A matched comparison additionally requires readable selected-entry storage. On the first-entry path, the reference used for that access is obtained by the additional global read. On the second- and third-entry paths, the earlier captured reference must still support the selected access.

Arguments must satisfy the requirements of every reached dependency. The visible body does not validate these conditions or define recovery for invalid memory, invalid dispatch, or abnormal dependency exits.

## Behavior

### Initial callback and reference capture

The function first resolves and invokes the object callback. After the callback returns, it reads the global table reference and saves that reference for possible later selection.

Only then does it test whether the first callback result equals 0x3C.

This initial global-reference read occurs on every normally progressing path, including fallback. Capturing a reference does not itself read a table entry or establish that the referenced storage is valid.

### First comparison: first-entry selection

If the first result equals 0x3C, the function reads the global table reference again and reads the 32-bit entry at offset 0 through this second reference value.

The saved reference is not the source of this first-entry access. Thus, the source-visible sequence includes:

- The first callback.
- The initial global-reference read and capture.
- The successful first comparison.
- An additional global-reference read.
- The entry read through that additional read’s result.

The two global reads must remain distinct in this contract. The supplied body does not establish that they must observe equal values. It also contains no intervening callback or other dependency call between them.

After selecting the entry, the function proceeds to selected-entry processing. There is no second object callback on this path.

### Second comparison: second-entry selection

If the first result is not 0x3C, the function resolves and invokes the callback again. It compares this second result only with 0x3E.

If the comparison succeeds, it reads the 32-bit entry at byte offset 4 through the reference captured after the first callback. It does not reload the global reference for this selection.

Consequently, replacement of the global reference during the second callback does not redirect the visible selection to the replacement table. Mutation of the originally referenced table can affect the entry subsequently read from it. Its continued validity is not guaranteed by this caller.

A second result of 0x3C does not select the first entry.

### Third comparison: third-entry selection

If the second result is not 0x3E, the function resolves and invokes the callback a third time. It compares this third result only with 0x26.

If equal, it reads the 32-bit entry at byte offset 8 through the reference captured after the first callback. There is no additional global-reference read for this selection.

A third result of 0x3C or 0x3E does not select either earlier entry. There is no loop, restart, or reconsideration of previous comparisons.

The offsets 4 and 8 follow from selecting the second and third four-byte entries. There is no input-dependent index calculation, length calculation, or arithmetic overflow decision in this selection.

### Fallback

If the third result is not 0x26, the function resolves and invokes the callback a fourth time.

It then calls F-70f4a053b9ed with, in order:

- The unchanged second argument.
- An address within the current invocation’s stack storage.
- Numeric argument 1.

The fourth callback result is not visibly tested, forwarded as an explicit argument, or assigned to the storage whose address is passed. The supplied body does not establish the contents of that storage or a relationship between those contents and the callback result.

The value 1 is established only as a numeric argument. It is not established as a byte count, element count, or other quantity.

The function returns F-70f4a053b9ed’s result unchanged. It reads no table entry and calls none of the four selected-entry dependencies on this path.

### Selected-entry processing

After any successful comparison, the function retains the selected 32-bit entry and makes three calls in this order:

1. F-1cb585febd84 receives the selected entry and returns an auxiliary 32-bit value.
2. F-e7f9d47b9573 receives no explicit arguments and returns an integer used as a zero/nonzero gate.
3. F-6693aefb6551 receives the unchanged second argument and returns another integer used as a zero/nonzero gate.

F-6693aefb6551 is called even when F-e7f9d47b9573 returned nonzero.

If F-6693aefb6551 returns zero, or the saved F-e7f9d47b9573 result is nonzero, the function returns 6 without calling F-cfc99440de00.

Otherwise, F-cfc99440de00 receives:

- The nonzero result from F-6693aefb6551.
- The selected table-entry value.
- The auxiliary result from F-1cb585febd84.

A nonzero result from F-cfc99440de00 maps to return 0. A zero result maps to return 0x18.

The selected entry and auxiliary value are retained across intervening calls. This preserves their scalar values; it does not establish the lifetime, contents, or ownership of anything they might reference.

## Side effects

### Direct accesses and local state

The visible body:

- Reads object dispatch state for every callback invocation.
- Reads the global table reference after the first callback.
- Reads that global reference a second time only on the first-entry path.
- Reads exactly one table entry on a matched path.
- Reads no table entry on fallback.
- Retains intermediate values in invocation-local state.
- Supplies an invocation-local stack address to F-70f4a053b9ed.

There is no explicit caller-side write to the object, global table reference, or table storage. Local retention and argument passing do not establish writes to externally referenced data.

### Dependency effects and ownership

The implementations of the callback and other dependencies are unavailable. Their effects cannot be restricted to their returned values. They may alter dispatch state, globals, table contents, referenced memory, or external state.

In particular, the contract does not assume that:

- Successive callbacks return the same value.
- A later callback uses the same dispatch table or callable entry.
- A saved table reference remains valid after another call.
- A selected entry denotes immutable data.
- The preliminary selected-entry calls are effect-free when the eventual return is 6.
- Dependencies preserve global state.

The visible caller performs no explicit allocation or release. It establishes no ownership transfer or release responsibility for the second argument, table entries, or dependency results.

The fallback stack address has invocation-local lifetime. Whether F-70f4a053b9ed retains it, and whether such retention would be valid, are not established.

There is no visible retry, rollback, or compensation. Returns 6 and 0x18 do not imply that earlier effects were absent or reversed.

## Acceptance examples

These are conditional consequences of the supplied body, not executed tests. Each assumes that reached accesses and calls complete normally.

### First-entry selection includes two global reads

If the first callback returns 0x3C:

- Exactly one object callback occurs.
- The global table reference is read and captured.
- The successful comparison is followed by another global-reference read.
- The first entry is obtained through the second read’s reference.
- Selected-entry processing occurs; fallback does not.

If both reads yield the same valid table reference, its offset-zero entry is selected.

Conditionally, if the first read yields reference A and the second yields distinct reference B, the entry comes from B, not A. This example does not assert that such a change occurs in an ordinary execution or that concurrent mutation is safe.

### Second-entry selection preserves the captured reference

Suppose the first callback returns 0x41, after which the captured reference is A. The second callback changes the global reference to B and returns 0x3E.

The function selects the entry at offset 4 through A, provided that access remains valid. It does not use B merely because B is now stored globally. Exactly two callbacks occur.

### Third-entry selection and final zero result

Given callback results 0x41, 0x42, and 0x26:

- Exactly three callbacks occur.
- The entry at offset 8 through the captured reference is selected.
- If F-e7f9d47b9573 returns zero and F-6693aefb6551 returns nonzero, the final dependency is called.
- If F-cfc99440de00 returns zero, the function returns 0x18.

### Recognized values at the wrong positions

Given results 0x3E, 0x26, and 0x3C, all three comparisons fail. A fourth callback occurs, then F-70f4a053b9ed receives the second argument, stack address, and numeric 1. Its result is returned unchanged.

### No low-byte classification

A first callback result of 0x13C fails the first comparison despite having low byte 0x3C. Later callback results determine the path.

### Nonzero preliminary gate does not suppress the next call

On any selected-entry path, if F-e7f9d47b9573 returns nonzero, F-6693aefb6551 still executes. F-cfc99440de00 does not execute, and the function returns 6.

If F-e7f9d47b9573 instead returns zero but F-6693aefb6551 returns zero, the function likewise returns 6 without the final call.

### Final nonzero result

If both gates permit the final call and F-cfc99440de00 returns any nonzero integer, including a negative value in the supplied integer representation, the function returns 0.
