# F-dd410c6b2f60

## Purpose

F-dd410c6b2f60 obtains a 32-bit value through an indirect operation, conditionally derives a second value through another indirect operation and F-d7be9cfb4000, and writes a fixed 30-byte record into caller-provided storage.

The record contains a constant prefix, two 16-bit fields written most-significant byte first, an 18-byte zero region, and a constant suffix. The first field contains the low 16 bits of the first indirect result. The second contains a value derived only when that result is nonzero.

The function also returns an integer selected from the third input. That return value is not generally the number of bytes written. In particular, the function writes all 30 bytes even when the third input is zero, and can return 33 despite writing 30 bytes.

The record’s protocol, application-level meaning, and intended consumer are not established by the supplied evidence.

| Destination | Address of writable byte storage | Receives writes at offsets 0 through 29 inclusive. |
| Control value | Unsigned 32-bit integer | Determines the return value only; it does not bound or suppress destination writes. |

The supplied representation uses 32-bit object-reference and dispatch-table address accesses. The caller must provide a valid object-handle address, a valid referenced object, and a dispatch table containing the required callable entries.

At minimum, the dispatch entry at byte offset 36 must be callable. If that call returns a nonzero value, the entry at byte offset 40 must also be callable when it is subsequently resolved.

The destination must provide at least 30 writable bytes for ordinary completion. No destination-size argument is enforced. Treating the control value as an available-buffer length would therefore be unsafe.

### Return value

For an unsigned control value \(c\), the returned signed 32-bit integer is:

- \(c + 1\), when \(0 \le c \le 32\);
- 32, when \(33 \le c \le 4{,}294{,}967{,}295\).

Every possible returned value is between 1 and 33 inclusive. The addition occurs only for values at most 32, so it cannot overflow either the unsigned input width or the signed return width.

There is a discontinuity: control value 32 returns 33, whereas control value 33 returns 32.

## Behavior

### Indirect input acquisition

The function first initializes its prospective derived field to zero.

It reads the object reference from the object-handle address, reads the dispatch-table reference from the beginning of that object, resolves the callable entry at byte offset 36, and invokes it. This unresolved dependency is designated F-indirect-A in this contract.

The result of F-indirect-A is treated as a signed 32-bit integer. Denote its captured value by \(n\).

The branch condition examines the entire 32-bit value:

- If \(n = 0\), neither the second indirect operation nor F-d7be9cfb4000 is invoked. The derived field remains zero.
- If \(n \ne 0\), both additional calls occur. Negative values take this branch just as positive values do.

The branch does not examine only the 16 bits later emitted into the record. Consequently, a nonzero result whose low 16 bits are zero still triggers both additional calls.

### Conditional derivation

For nonzero \(n\), the function resolves the object and dispatch table again through the object-handle address. It then invokes the callable entry at byte offset 40. This unresolved dependency is designated F-indirect-B.

This second resolution occurs after F-indirect-A returns. It must not be described as necessarily using the original object or dispatch table: F-indirect-A could have changed the handle, the object, or its dispatch table. The supplied function does not preserve and reuse the first resolution for the second call.

F-indirect-B supplies a 32-bit value. That value is passed as the first argument to F-d7be9cfb4000. The second argument is formed by multiplying the captured \(n\) by 16,065, hexadecimal `3EC1`.

The multiplication uses the signed integer expression shown in the supplied evidence. For products representable as signed 32-bit integers, its value is established. Overflow handling is not sufficiently established to promise either mathematical widening or modulo-\(2^{32}\) behavior for products outside that range.

The result of F-d7be9cfb4000 is assigned to 16-bit storage. Only the resulting low 16 bits contribute to the destination record. The dependency’s full return width, signedness, and semantic meaning are not established.

### Record construction

After the required calls have returned normally, the function writes the destination in ascending byte-offset order, starting at offset 0 and ending at offset 29.

The two variable fields are encoded as follows:

- Offsets 6–7 contain bits 15 through 0 of the captured \(n\).
- Offsets 8–9 contain bits 15 through 0 of the derived value.
- In each field, the byte containing bits 15 through 8 precedes the byte containing bits 7 through 0.

For the first field, the observed extraction uses an unsigned view of the 32-bit value before shifting. Thus the record retains the low 16-bit representation even when \(n\) is negative. It does not clamp negative values to zero or reject them.

The function does not read existing destination bytes to construct the record. Each of the 30 bytes is assigned independently of its prior contents.

### Return selection

After completing the destination writes, the function selects its return value from the control value using the rule in the interface section.

There is no alternate short-record path for small control values. The return selection neither limits the preceding writes nor reports failure because the control value is below 30.

## Side effects

### Direct memory effects

On normal completion, the function overwrites exactly destination offsets 0 through 29 through its own explicit stores. The observable store sequence is ascending by offset.

All dependency calls precede the function’s first destination store. Accordingly:

- A dependency can observe the destination’s prior contents if it has another way to access that memory.
- Dependency writes to the destination may be overwritten by the subsequent record construction.
- If a dependency fails to return normally, the supplied function has not yet begun its own record writes.
- A fault during record construction can leave a partially written prefix. There is no rollback or atomic-record guarantee.

The function itself performs no explicit write to the object-handle storage or referenced object. Its dependencies may do so.

### Aliasing and lifetime

The supplied function contains no explicit overlap check.

If the destination overlaps the handle or object metadata, the destination writes can overwrite those structures after dependency resolution has finished. This timing does not establish that such overlap is valid under the surrounding runtime’s object and memory rules.

The function shows no explicit allocation, deallocation, ownership transfer, or retained destination reference. This observation applies only to its own visible operations. No ownership or lifetime behavior is established for the dependencies.

The caller must ensure that all required reads, calls, and destination writes remain valid for their respective execution periods. In particular, validity before F-indirect-A is not sufficient to establish validity of the later dispatch-table resolution.

### Errors and exceptional behavior

No explicit error status, null check, bounds check, multiplication-overflow check, or dependency-result validation appears.

A zero result from F-indirect-A is handled as an ordinary branch outcome, not as an error. Other dependency results are used without visible validation.

Invalid addresses, invalid callable entries, insufficient destination storage, abnormal dependency exits, and arithmetic overflow outside the established range have no specified recovery behavior in the supplied evidence.

## Acceptance examples

These are conditional acceptance criteria derived from static evidence, not reports of executed tests.

### Zero first result

Given valid storage and an F-indirect-A result of zero:

- F-indirect-B and F-d7be9cfb4000 are not called.
- Offsets 6–9 are all zero.
- The fixed fields and zero region match the interface layout.
- All 30 destination bytes are written regardless of the control value.

With control value zero, the return value is 1. With control value 32, the return value is 33.

### Nonzero result with a known derived value

Given that F-indirect-A returns 2, F-indirect-B returns some 32-bit value \(x\), and F-d7be9cfb4000 returns a value whose low 16 bits are hexadecimal `1234`:

- F-d7be9cfb4000 receives \(x\) first and 32,130 second.
- Destination offsets 6–7 become `00 02`.
- Destination offsets 8–9 become `12 34`.
- All fixed bytes retain the specified layout.

With control value 33, the return value is 32.

### Nonzero full-width result with a zero encoded field

Given an F-indirect-A result of 65,536:

- The nonzero branch is taken.
- Both subsequent dependencies are invoked, assuming normal execution.
- Destination offsets 6–7 are nevertheless `00 00`.

This distinguishes the full-width branch condition from the truncated output representation.

### Negative first result

Given an F-indirect-A result of −1:

- Both subsequent dependencies are invoked.
- The multiplication argument is −16,065, which is representable as a signed 32-bit integer.
- Destination offsets 6–7 become `FF FF`.
- The derived field depends on F-d7be9cfb4000’s result.

### Changed object handle

Given that F-indirect-A changes the object reference stored at the object-handle address and returns a nonzero result:

- The second indirect operation is resolved through the changed reference.
- Its identity is not required to match the entry that was reachable before the first call.

This criterion requires the changed reference and its dispatch metadata to remain valid.

### Insufficient destination storage

Providing fewer than 30 writable bytes is outside the established successful-call preconditions. A small control value does not make such a call safe. No acceptance criterion promises truncation, a clean error return, or preservation of adjacent memory.
