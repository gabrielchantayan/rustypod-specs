# F-4c05775b039e

## Purpose

F-4c05775b039e conditionally copies a four-byte field, conditionally writes a state byte, and returns a four-byte field from a caller-supplied region.

The function reads a shared pointer twice. It saves the first pointer value as the address for any subsequent byte write. It uses the second pointer value to locate the byte tested for the branch decision. These addresses are equivalent only if both pointer reads produce the same value.

With a stable shared pointer, the behavior resembles a state transition:

- A zero request and a nonzero tested byte cause a byte write of 0.
- A nonzero request and a zero tested byte cause a four-byte copy, followed by a byte write of 1.
- Otherwise, neither write occurs.

Without pointer stability, this is not necessarily a transition of one indicator: the byte tested and the byte written can occupy different locations.

Calling the operation “enablement” or the copied field a “snapshot” is inferred intent, not established application meaning.

### Region layout

Offsets are byte offsets from the supplied base.

| Offset | Access width | Role |
|---|---:|---|
| `0x42C` | 4 bytes | Result field, read on every completing invocation. |
| `0x488` | 4 bytes | Copy source, read only on the copy-taking branch. |
| `0x494` | 4 bytes | Copy destination, written only on the copy-taking branch. |

For a valid, non-wrapping region, these ranges are disjoint. The copy source and destination start 12 bytes apart; their respective four-byte ranges therefore do not overlap.

The copied four-byte value undergoes no visible arithmetic, scaling, or normalization. The representation establishes a four-byte value transfer, not an independently specified byte order or physical bus-access sequence.

### Implicit shared input

A shared storage location holds a pointer. This contract distinguishes:

- **Pointer storage:** the memory holding the shared pointer value.
- **Saved address:** the pointer value obtained by the first read of that storage.
- **Test address:** the pointer value obtained by the second read.
- **Tested byte:** the byte read through the test address.

Any conditional byte write uses the saved address. It does not use a new read of pointer storage and need not target the tested byte.

The function does not normalize an already-nonzero tested byte merely because the request is nonzero.

### Output

The function returns the four-byte value read at base offset `0x42C`, after any selected writes.

The result is not established as a success code, Boolean, pointer, or signed quantity. Its application interpretation remains unknown.

### Preconditions for completing execution

The selected accesses must be valid under the target’s memory rules:

- Pointer storage must support both pointer-value reads.
- The test address must identify a readable byte.
- If a byte write is selected, the saved address must identify writable byte storage.
- The result field must support a four-byte read.
- If copying is selected, the source must support a four-byte read and the destination a four-byte write.
- Address formation, alignment, and access permissions must permit the selected operations.

The saved address is not dereferenced on a branch that performs no byte write. Requiring its pointee to be readable on every path would exceed the visible behavior.

No bounds check, pointer check, address-overflow check, or alignment check appears in the supplied body. The constants specify byte offsets; they do not establish whether address arithmetic wraps, traps, or has another target-specific consequence outside the valid-address case.

## Behavior

### Decision table

The branch decision depends on the request and the byte read through the second pointer value.

| Request | Tested byte | Four-byte copy | Byte write |
|---|---|---|---|
| Zero | Zero | None | None |
| Zero | Nonzero | None | Write 0 through the saved address |
| Nonzero | Zero | Source at `0x488` to destination at `0x494` | Write 1 through the saved address, after copying |
| Nonzero | Nonzero | None | None |

Every completing path subsequently reads and returns the result field.

“Nonzero” includes every nonzero byte representation, not just 1. The byte comparison is unaffected by whether the target treats a byte as signed or unsigned.

### Observable ordering in the supplied representation

The established order is:

1. Read pointer storage and retain that value as the saved address.
2. Select the zero-request or nonzero-request branch.
3. Read pointer storage again to obtain the test address.
4. Read the byte through the test address and decide whether writes are required.
5. On the nonzero-request, zero-tested-byte path, read the four-byte source and write that value to the four-byte destination.
6. If selected, write 0 or 1 through the saved address.
7. Read the four-byte result field and return it.

There is no later read of pointer storage to choose the byte-write target.

These are the accesses and dependencies expressed by the supplied representation. They do not establish compiler-preserved physical access counts, atomic operations, synchronization, or hardware memory barriers.

### Zero request

A zero request still follows both pointer-value reads and the tested-byte read.

If the tested byte is zero, no write occurs. If it is nonzero, the function writes byte value 0 through the saved address. Neither copy field is accessed.

If the two pointer values differ, the tested byte need not be cleared. A different byte can receive the zero write.

### Nonzero request

If the tested byte is nonzero, the function performs neither the copy nor a byte write.

If the tested byte is zero, the function:

- Reads the four-byte source.
- Writes that value to the four-byte destination.
- Writes byte value 1 through the saved address.
- Reads and returns the result field.

A repeated nonzero request does not inherently refresh the destination. Each invocation copies only if its own tested byte is zero. With a stable shared pointer and no intervening mutation, the first such copy sets that byte to 1 and a subsequent nonzero request skips copying.

### Aliasing with pointee storage

No supplied restriction prevents the saved address or test address from pointing into the supplied region.

Consequences depend on which address aliases which field:

- If the saved address lies in the source, the copy reads the source before the later byte write can change it.
- If the saved address lies in the destination, the copy writes four bytes first; the later byte write may replace one of them.
- If the saved address lies in the result field, the final result read can reflect the byte write.
- If the test address lies in a field, the branch uses that field’s byte as observed before the copy and conditional byte write.

The saved and test addresses may differ. An alias involving the test address alone does not make that location the byte-write target.

Exact numeric effects of changing one byte inside a four-byte value depend on byte order and byte position.

### Aliasing with pointer storage

Pointer storage itself is not established as disjoint from the supplied region or from either pointee.

A four-byte destination write can overlap some or all of pointer storage. Likewise, the byte write through the saved address can modify pointer storage if that address points into it.

Such writes mutate the stored pointer representation; they do not replace the pointer value already retained as the saved address. In particular, overwriting pointer storage during the four-byte copy does not retarget the subsequent byte write.

The function performs no further pointer-storage read after the copy. A modified shared pointer can nevertheless affect later invocations or other users of that storage. Whether the modified representation is a valid pointer is unknown.

If pointer storage overlaps the source or result field, those field reads observe the corresponding overlapping bytes at their specified positions in the access order. Pointer width is not established, so a four-byte overlap must not be assumed to cover an entire pointer.

### Errors and partial effects

There is no visible explicit error return, recovery path, or rollback.

A failing access is governed by the target environment. The body does not undo completed writes. On the copy-taking path, the destination write precedes the saved-address byte write; failure of the latter can therefore leave the copy visible without the intended byte update. Failure of the final result read can occur after earlier selected writes.

The representation does not establish whether a faulting four-byte access can have partial effects.

## Side effects

The function’s explicit writes are limited to:

- Four bytes at base offset `0x494`, when copying is selected.
- One byte through the initially saved address, when a byte write is selected.

These describe write addresses, not disjoint logical objects. Aliasing can make either operation modify pointer storage or other overlapping data.

The source and result fields are not direct assignment destinations. They can still change if overlapped by the saved-address byte write. Pointer storage has no explicit replacement operation but can change through an overlapping destination or byte write.

No allocation, deallocation, ownership transfer, or dependency call appears. The function neither acquires ownership of the supplied region nor establishes ownership of pointer storage or its pointees.

No previous value is restored before return. No thread-safety guarantee is established. In particular, the two pointer reads, tested-byte read, optional copy, optional byte write, and result read do not constitute an atomic state transition.

## Acceptance examples

These are conditional expected behaviors, not executed tests. Unless an example says otherwise, assume successful accesses, stable pointer storage, no external mutation, ordinary memory, and disjoint storage.

### Zero request with a zero byte

Given a shared pointer to a byte containing 0 and a zero request:

- Pointer storage is read twice in the supplied representation.
- The byte is tested.
- Neither the destination nor the byte is written.
- The four-byte result field is returned.

### Zero request with a noncanonical nonzero byte

Given a shared pointer to a byte containing 7 and a zero request:

- The byte is tested as nonzero.
- Byte value 0 is written through the saved address.
- Neither copy field is accessed.
- The result is read afterward.

### Nonzero request with a zero byte

Given a shared pointer to a byte containing 0 and any nonzero request:

- The source value is copied to the destination.
- Byte value 1 is written afterward.
- The result is then read.

The request’s magnitude does not become the byte value.

### Nonzero request with a nonzero byte

Given a shared pointer to a byte containing 7 and a nonzero request:

- No copy occurs.
- No byte write occurs.
- The byte remains 7.
- The result field is returned.

### Repeated requests under a stable pointer

Given an initial byte of 0, a first nonzero request copies the source and sets the byte to 1. If the source then changes but the pointer and byte remain otherwise unchanged, a second nonzero request does not refresh the destination.

### Different saved and test addresses

Conditionally assume the environment permits the two pointer reads to produce different valid addresses.

If the first read identifies byte A, the second identifies byte B, byte B contains 0, and the request is nonzero:

- The function copies the source to the destination.
- It writes 1 to byte A.
- It does not directly write byte B.

If instead the request is zero and byte B is nonzero, it writes 0 to byte A without copying.

These examples specify address selection; they do not assert that unsynchronized concurrent pointer changes are valid on an unspecified platform.

### No write despite a different saved byte

Under the same differing-address condition, let byte A contain 0, byte B contain 7, and the request be nonzero.

No copy or byte write occurs. Byte A is not normalized to 1: its value did not control the branch.

### Saved address inside the destination

Given a stable pointer whose value identifies one byte of the destination, an initially zero tested byte, and a nonzero request:

- The full four-byte destination receives the source value.
- The selected destination byte is then overwritten with 1.

The final destination need not equal the source.

### Copy overlapping pointer storage

Assume the destination overlaps pointer storage, the saved address identifies separate writable byte storage, the tested byte is zero, and the request is nonzero.

The copy modifies the overlapping pointer-storage bytes. The following byte write still targets the saved address, regardless of the pointer representation now in shared storage. This invocation does not read that modified pointer again.

### Saved-address write overlapping pointer storage

Assume the saved address identifies a byte within pointer storage and the selected branch requires a byte write.

That write modifies the pointer representation after both pointer reads have occurred. It does not retroactively change either address used by this invocation. Validity of the resulting stored pointer remains unspecified.
