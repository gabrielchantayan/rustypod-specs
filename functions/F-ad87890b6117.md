# F-ad87890b6117

## Purpose

F-ad87890b6117 records a requested mode in an object, optionally configures three associated targets, and then performs a common two-stage virtual operation.

The established mode-dependent behavior is:

- **Mode 0:** Prepare each target and apply its corresponding externally stored fixed selector.
- **Mode 1:** Acquire a record, prepare each target, and conditionally apply a selector according to a byte read from that record.
- **Other modes:** Skip target preparation and selection.

Every path that continues normally reaches the common virtual operations. The final operation receives flag 1 for mode 0 and flag 0 for every other mode.

“Prepare,” “selector,” and “lookup” describe observable roles, not established business semantics. The recognized record characters suggest date-format components, but that interpretation is **inferred intent**, not part of the required behavior.

## Interface

### Inputs and result

The function accepts:

1. An object reference.
2. An unsigned 32-bit mode.

It has no explicit return value. Its observable results are a direct byte write, reads from object and external storage, dependency calls, and effects delegated to those dependencies.

The supplied representation uses 32-bit object fields, address values, and dispatch-table entries. This contract describes that representation; it does not prescribe a portable object layout.

There is no explicit null check, error return, validation of target values, or recovery path.

### Object storage accessed directly

All offsets are byte offsets from the supplied object.

| Offset | Width or form | Role |
|---|---|---|
| 0x000 | 32-bit dispatch-table reference | Used by the common final lookup |
| 0x140 | 32-bit value | Target 1 |
| 0x144 | 32-bit value | Target 2 |
| 0x148 | 32-bit value | Target 3 |
| 0x14C | Interior object address | Shared configuration argument |
| 0x178 | One byte | Stored, narrowed mode |

The function passes the address at 0x14C to a dependency. It does not establish the size or layout of the region beginning there.

Only the byte at 0x178 is directly written. The surrounding bytes are not directly overwritten by this function.

### External storage

The function reads five distinct external 32-bit storage locations:

- Three fixed-selector locations, one per target in mode 0.
- One selector-base location, read repeatedly in mode 1.
- One lookup-key location used in the common final stage.

The numeric contents and semantic types of these locations are not supplied.

Mode 1 also obtains a record address. It reads one byte at each of the following offsets, in target order:

| Target | Offset from acquired record |
|---|---:|
| Target 1 | 0x457 |
| Target 2 | 0x45C |
| Target 3 | 0x461 |

These are separate, staged reads, not a string read or an entry-time snapshot.

### Preconditions for normal completion

The caller and surrounding environment must provide valid storage and callable dependencies for the selected path:

- The object must permit the initial byte write.
- Its dispatch-table reference and the required entry must be valid when the final stage accesses them.
- Modes 0 and 1 require usable target values and a valid shared configuration argument under the preparation dependency’s contract.
- Mode 1 requires a usable record address and readable record bytes at their respective read times.
- The final lookup must return an object supporting the subsequent virtual operation.
- Earlier calls must return normally for later accesses and calls to occur.

The function does not enforce these conditions.

## Behavior

### Initial mode write and branch selection

Before any dependency call, the function stores the mode narrowed to one byte at object offset 0x178.

For the represented eight-bit byte layout, this records the low eight bits. The stored byte’s signed interpretation is not subsequently used by this function.

Branch selection uses the original unsigned 32-bit mode, not the stored byte. Thus:

- Mode 0 selects the mode-0 branch.
- Mode 1 selects the mode-1 branch.
- Every other 32-bit value skips both branches, even if its low byte is 0 or 1.

The original mode also determines the final flag. A dependency changing the stored byte does not change that decision.

### Mode 0: fixed selectors

Targets are processed in order: target 1, target 2, target 3.

For each target, F-08381bb55f88 receives the target value and the shared configuration address. After that call returns, F-8ef069adf52b receives the target value and that target’s fixed selector.

The observable call sequence is therefore alternating preparation and selection:

- Target-1 preparation, then target-1 selection.
- Target-2 preparation, then target-2 selection.
- Target-3 preparation, then target-3 selection.

It is not a preparation pass followed by a selection pass.

Each selection uses a target-field read made after that target’s preparation call. Preparation is not assumed to preserve that field.

Fixed selectors are read at their respective stages rather than captured together at entry. Earlier dependencies may therefore affect later-read external storage.

For the first two selection calls, the supplied representation does not independently establish the relative evaluation order of the target-field read and fixed-selector read within the call arguments. For target 3, it explicitly obtains the target value and then the fixed selector before the selection call.

After target-3 selection returns, processing continues to the common final stage.

### Mode 1: acquisition

Mode 1 first performs these calls in order:

1. F-9d0ecc5f6adf, with no explicit arguments.
2. F-682adfd5a561, with the preceding call’s 32-bit result and the constant 0x80.
3. F-9b45bb70831a, with no explicit arguments.

The third call’s result supplies the record address retained for subsequent reads. The function does not inspect a status from F-682adfd5a561.

The value 0x80 is an argument, not an established allocation size, record length, or flag interpretation.

### Mode 1: selector-base reads

After acquisition, the function prepares target 1 using F-08381bb55f88. It then performs the following ordered reads and computations:

1. Read the external selector base and save that value as the **saved direct selector**.
2. Read the record byte at offset 0x457.
3. Read the external selector base again and compute the **incremented selector** by adding 1.
4. Read the external selector base again and compute the **twice-incremented selector** by adding 2.

These are three separate external-base reads. They occur even when the first record byte is unrecognized, provided execution continues normally through those operations.

The additions are represented as signed 32-bit additions. Their defined behavior at signed-overflow boundaries is not established by the supplied representation. A portable overflow or wrapping rule must not be inferred.

The three values need not share a common numerical base if external storage changes between reads. For example, the saved direct selector can reflect one observed base value while the incremented selectors reflect later ones.

There is an additional, conditional read:

- If the first record byte is `d`, the function first reloads the target-1 field, then reads the external selector base a fourth time, and passes that newly read value to F-8ef069adf52b.

This fourth read occurs **after both incremented-selector computations and after the target-1 field reload**. It does not replace the saved direct selector.

If the first record byte is not `d`, this fourth read does not occur.

### Mode 1: target-specific character mapping

Each target’s record byte determines whether a selector call occurs.

| Record byte | Target 1 | Targets 2 and 3 |
|---|---|---|
| `d` | Additional base read after reloading target 1 | Saved direct selector |
| `m` | Incremented selector | Incremented selector |
| `Y` | Twice-incremented selector | Twice-incremented selector |
| `y` | Twice-incremented selector | Twice-incremented selector |
| Any other byte | No selector call | No selector call |

Matching is exact. Uppercase `D` and `M` do not match. Both `Y` and `y` select the same retained value.

For a recognized first byte, the target-1 field is reloaded after the initial three base reads and the increment computations. The `d` case then performs the fourth base read described above. The other recognized cases use their already computed incremented selector.

After target-1 handling:

- Target 2 is prepared.
- Its record byte at 0x45C is read.
- If recognized, its target field is reloaded and its selector call occurs.
- Target 3 is then prepared.
- Its record byte at 0x461 is read.
- If recognized, its target field is reloaded and its selector call occurs.

An unrecognized byte skips only that target’s selector call. It does not skip that target’s preparation or cancel later target processing.

The saved direct selector and both incremented selectors remain available for targets 2 and 3. They are not recomputed after later preparation or selection calls. In particular, target 1’s additional `d` read does not change the direct selector subsequently used for targets 2 and 3.

The record address is retained, but the bytes are not captured together. Earlier dependencies may change a later byte before it is read.

### Other modes

For modes other than 0 and 1:

- The initial byte write still occurs.
- No target preparation or selection occurs.
- No mode-1 acquisition calls occur.
- No mode-1 record or selector-base reads occur.
- Execution proceeds to the common final stage.

There is no explicit unsupported-mode diagnostic.

### Common final stage

After the selected branch completes, the function invokes the original object’s virtual entry at dispatch-table byte offset 0xE4. It supplies the original object and the externally read lookup key.

The returned value is treated as another object reference. The function then invokes that object’s virtual entry at dispatch-table byte offset 0xA0, supplying the returned object and a 32-bit flag:

| Original mode | Final flag |
|---|---:|
| 0 | 1 |
| Any other value | 0 |

Although the supplied representation includes a subtraction in forming this flag, modes greater than 1 are explicitly assigned zero. Their final flag is not a wrapped subtraction result.

The original object’s dispatch information is accessed after branch-specific calls. Those calls are not assumed to preserve it.

There is no check of the lookup result before using it for the second virtual dispatch. The final virtual operation’s result is not used.

## Side effects

### Direct effects

The function directly:

- Writes one byte at object offset 0x178.
- Reads target fields on paths that prepare or select targets.
- Reads external fixed selectors in mode 0.
- Reads the external selector base three times in mode 1, plus a fourth time when target 1’s record byte is `d`, subject to normal continuation.
- Reads the three record bytes at their respective processing stages in mode 1.
- Reads dispatch information and the lookup key for the common final stage.

The initial mode write precedes all dependency calls. There is no visible rollback if later execution fails.

### Delegated effects and ownership

Dependency effects are unknown. They may mutate object fields, targets, record contents, external selector storage, dispatch information, or unrelated state.

The retained selector values are not recomputed merely because a dependency changes their external source. Conversely, later target and record reads can observe changes made by earlier dependencies.

No explicit allocation, release, reference-count operation, or ownership transfer appears in the visible body. This does not establish that dependencies allocate nothing, retain no references, or release no memory.

Passing the interior configuration address does not establish whether it is borrowed, retained, copied, mutated, or used to release associated resources. Those ownership and lifetime rules remain unresolved.

No transaction, synchronization, or atomic multi-field update is established.

## Acceptance examples

These are conditional static acceptance criteria, not executed tests. Unless stated otherwise, they assume valid storage, normal dependency returns, representable arithmetic results, and stable external values.

### Mode 0

For mode 0:

- The stored mode byte becomes 0.
- Each target receives preparation followed by its corresponding fixed selector.
- Target order is 1, 2, 3.
- No mode-1 acquisition occurs.
- The final operation receives flag 1.

### Stable mode-1 base

For mode 1, a stable base of 40, and record bytes `d`, `m`, `Y`:

- The stored mode byte becomes 1.
- Acquisition precedes target preparation.
- Target selectors are 40, 41, and 42.
- Four base reads occur: three initial reads and the additional target-1 `d` read.
- The additional read follows both increment computations and the target-1 field reload.
- The final flag is 0.

Replacing the third byte with `y` leaves its selector unchanged.

### Distinct base observations

Suppose the initial three base reads observe 40, 50, and 60, respectively. The retained choices are then:

- Saved direct selector: 40.
- Incremented selector: 51.
- Twice-incremented selector: 62.

If all three record bytes are `d` and the additional target-1 base read observes 70, target 1 receives 70, while targets 2 and 3 each receive 40.

The additional read does not update the saved direct selector.

### No additional base read

With first record byte `m`, target 1 uses the incremented selector. It does not perform the additional base read reserved for `d`.

With an unrecognized first byte, target 1 receives preparation but no selection. The three initial base reads and both additions still occur, and later targets can use the retained values.

### Unrecognized middle byte

For stable base 40 and bytes `m`, `D`, `d`:

- Target 1 receives selector 41.
- Target 2 is prepared but receives no selector call.
- Target 3 receives selector 40.
- The final stage executes with flag 0.

This does not guarantee preservation of target 2’s earlier selection, because its preparation dependency may change it.

### Full-width mode and later mutation

Mode 256 stores byte 0 but skips both specialized branches and produces final flag 0. Mode 257 similarly stores byte 1 without entering mode 1.

If preparation changes a target field, a later selection uses the subsequently reloaded field. If an earlier dependency changes the third record byte before its read, target 3 follows that later byte rather than an entry-time value.
