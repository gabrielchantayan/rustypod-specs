# F-841dc33ee157

## Purpose

F-841dc33ee157 processes a nonnull object through an ordered sequence of conditional resource calls, recursive calls on two references, and two further resource calls. It then adjusts global accounting, validates allocation metadata, updates allocator-context accounting, and submits an allocation-header address to a dependency.

The apparent intent is recursive destruction followed by allocation release. That intent is inferred. The supplied representation establishes calls and memory operations, but does not establish resource types, exclusive ownership, actual memory release, or synchronization guarantees.

The global accounting phase does **not** consistently use one captured context pointer. It captures one pointer for the eventual high-word destination and separately evaluates the global pointer for other accesses. Those evaluations and the delayed high-word read are part of the observable contract.

## Interface

### Input and result

The function accepts one 32-bit value interpreted as an object address.

- Zero causes immediate return without object accesses or dependency calls.
- A nonzero address is used without local validation of type, lifetime, alignment, extent, or accessibility.
- There is no explicit return value or recoverable error result.
- A rejected allocation header invokes a dependency identified as nonreturning.
- Invalid memory access, recursion exhaustion, and dependency failures have no locally established recovery behavior.

Addresses and accounting words are represented as 32-bit values. Two allocation selectors are unsigned 16-bit values. Arithmetic results described below are 32-bit results; exact target-language rules for signed overflow and invalid address arithmetic are not independently established.

## Behavior

### Initial cleanup and recursion

For nonzero input, the first decision reads the flag word at `+0x20`. If bit 0 is set, F-94cb53877c15 receives the value read at `+0x1c`. Otherwise that call is skipped.

After any such call returns, the function reads the flag word at `+0x18`. If bit 0 is set, F-94cb53877c15 receives the value at `+0x14`.

Other flag bits do not affect these decisions. A selected resource value of zero is still passed. Neither resource field nor flag is explicitly cleared.

These decisions use successive reads, not an entry-time snapshot. The first dependency can therefore change the second decision or its argument.

The subsequent call order is:

1. F-841dc33ee157 on the reference read at `+0x08`.
2. F-841dc33ee157 on the reference read at `+0x0c`, after the first recursion returns.
3. F-e5380ae57ea1 on the value read at `+0x10`.
4. F-6c7ac9769d41 on the value read at `+0x38`.

Each argument is read when its stage is reached. Earlier calls can affect later arguments. All four calls occur when their stages are reached, including calls with zero-valued arguments. Recursive calls with zero return immediately under this function’s own null rule.

Traversal is depth-first, processing the `+0x08` reference before the `+0x0c` reference. The current object’s allocation phase begins only after all these calls return.

There is no visited set, duplicate suppression, cycle detection, or local recursion limit. Shared references can be processed repeatedly. Cycles can cause unbounded recursion. No local mechanism prevents repeated allocation processing of an address.

### Adjusted base and accounting amount

After the resource calls, the function saves the current value of the global accounting-context pointer. This saved value will identify the destination of the high accounting-word write.

It then derives the adjusted base using the displacement immediately before the original object. The subtraction has no explicit overflow, underflow, alignment, or range check.

Next it reads the 32-bit accounting amount from eight bytes before the adjusted base.

The saved accounting-context pointer precedes these metadata reads. Later accounting accesses do not all use that saved pointer.

### Global accounting: distinct pointer evaluations

The accounting phase has four distinct evaluations of the global accounting-context pointer, in this order:

| Evaluation | Use |
|---|---|
| Initial capture, before allocation-metadata reads | Retained for the high-word destination at `+0x3c` |
| Evaluation after reading the accounting amount | Reads the low word at `+0x38` |
| Next evaluation | Forms and retains the high-word source address at `+0x3c`; does not yet read that word |
| Next evaluation | Selects the low-word destination at `+0x38` |

The low-word destination receives the difference between the previously read low value and the retained accounting amount. The destination’s existing contents are not separately read for that subtraction.

**Only after the low-word write** does the function read the high word through the retained high-source address. It writes the adjusted high value to `+0x3c` relative to the initially saved pointer.

Thus:

- The low-word source and destination can belong to different contexts.
- The high-word source and destination can belong to different contexts.
- The high-word source address is retained before the low-word write, but its contents are read afterward.
- The low-word write, aliasing, or intervening external mutation can affect the high value subsequently read.
- This is not an atomic two-word operation.

For the arithmetic, let:

- \(L\) be the low value actually read.
- \(S\) be the retained 32-bit accounting amount.
- \(H\) be the high value read **after** the low-word write.
- \(b=1\) if \(L<S\) under unsigned comparison, otherwise \(0\).
- \(a=0\) if bit 31 of \(S\) is clear, otherwise \(-1\).

The written values are:

\[
\text{low result}=(L-S)\bmod 2^{32}
\]

\[
\text{high result}=(H-a-b)\bmod 2^{32}.
\]

The sign contribution comes from the represented arithmetic right shift of the signed 32-bit interpretation of \(S\). Consequently, this is not generally subtraction of a zero-extended unsigned amount from a conventional 64-bit counter.

Equivalence to updating two words in one captured context is conditional on the global pointer remaining unchanged across its evaluations. Equivalence to a single stable counter subtraction also requires no interfering mutation or relevant aliasing.

No underflow rejection, saturation, synchronization, or rollback is visible.

### Allocator-context acquisition and special base

After both global accounting writes, F-2fd8826557a4 is invoked without explicit arguments.

After it returns, the function reads the allocator-context pointer through a separate global pointer location. The value obtained here is retained for subsequent allocator-context accesses and calls.

If the adjusted base equals numeric address `0x00000008`, the function now returns.

This special case still performs:

- All earlier resource and recursive calls.
- The displacement and accounting-amount reads.
- Both global accounting writes.
- F-2fd8826557a4.
- The allocator-context pointer read.

It skips header validation and all later allocator-context operations. Its accounting-amount read is at address zero. Whether that address is usable is unknown.

### Header validation

For any other adjusted base, the header address is 16 bytes before that base.

The function first reads the header word and rejects zero. If that check does not reject, it reads the header word again and rejects a value with bit 0 set. Rejection invokes F-a817d8d58c10, identified as nonreturning.

The two checks are not established as using one retained header value. For example, a nonzero first read followed by a zero second read does not trigger either represented rejection condition: the first read passed the zero test, and zero has bit 0 clear.

Global accounting has already been changed when rejection occurs. No rollback is visible.

### Allocator-context accounting

After validation, F-c0fc6d033caa receives the retained allocator-context address.

On return, the first unsigned 16-bit selector is read from adjusted base `−0x0c`. The header is then read again and masked with `0x3ffffffc`. This mask clears bits 31, 30, 1, and 0. Call the resulting value the **retained masked size**.

The function applies the following ordered 32-bit accounting updates:

| Order | Allocator-context offset | Update |
|---:|---|---|
| 1 | `0x224 + 4 × first selector` | Subtract retained masked size |
| 2 | `0x30c` | Subtract retained masked size |
| 3 | `0x0e0 + 4 × second selector` | Subtract retained masked size |
| 4 | `0x220` | Subtract retained masked size |

The second unsigned 16-bit selector is read from adjusted base `−0x0a` after update 2 and before update 3. Both selectors are zero-extended before scaling. Their scaled values range from zero through `0x3fffc`; no selector bounds checks establish that the selected words belong to valid tables.

Each update uses the word present at its target when reached. Overlapping targets therefore receive successive updates, not independent updates from a common snapshot.

F-09dcb55e8e0a is then invoked without explicit arguments. Its 32-bit result is used as an index with a four-byte stride, without a local range check.

After that call returns, the function:

1. Decrements the word at allocator-context offset `0x310 + 4 × index` by one.
2. Decrements the word at `+0x390` by one.
3. Rereads the header, masks it with `0x3ffffffc`, and subtracts that newly derived value from the word at `+0x08`.

Stored accounting results wrap at 32 bits in the represented arithmetic. The source treats the returned index as a signed 32-bit integer; no nonnegative or bounded-index guarantee is supplied. Exact consequences of overflowing signed address calculations remain target-dependent.

The final size subtraction does not necessarily use the retained masked size. Header mutation during F-09dcb55e8e0a, or aliasing with earlier writes, can change it.

The allocator-context pointer itself is not reloaded after the intervening dependencies.

## Side effects

Directly established effects include ordered dependency calls, recursive processing, global accounting writes, allocator-context accounting writes, and a nonreturning rejection path.

The function does not explicitly clear object fields, mark an object as processed, invalidate caller references, or record completed cleanup stages. It supplies no local rollback if a later stage fails after earlier effects.

Ownership is unresolved:

- Flag bits select resource calls; they do not prove ownership.
- Recursive references are processed independently of those flags.
- Shared references receive no special handling.
- No dependency may be assumed to preserve globals, metadata, object fields, or memory lifetime.
- No release or ownership transfer is established solely by passing an address.

Synchronization is also unresolved. The placement of F-c0fc6d033caa and F-e586bff64fb7 may suggest a protected allocator phase, but their bodies and contracts are unavailable. The earlier global accounting accesses visibly precede F-c0fc6d033caa.

## Acceptance examples

These are conditional static acceptance criteria, not executed tests.

### Null input

For input zero, expect immediate return with no direct data-memory accesses or dependency calls.

### Selected resources and live reads

With both relevant flag bits set and dependencies preserving later inputs, expect calls for the `+0x1c` resource and then the `+0x14` resource, followed by the first recursion, second recursion, F-e5380ae57ea1, and F-6c7ac9769d41.

If the first resource call clears bit 0 at `+0x18`, expect the second resource call to be skipped. A selected zero resource value is still passed.

### Stable-context accounting

Assuming all accounting-pointer evaluations yield the same context and no interfering mutation:

- For \(L=3\), \(H=5\), \(S=4\), expect low `0xffffffff` and high `4`.
- For \(L=0\), \(H=5\), \(S=\texttt{0x80000000}\), expect low `0x80000000` and high `5`.

The second result reflects cancellation between the sign contribution and unsigned borrow.

### Distinct accounting contexts

Suppose the initial capture identifies context A, the low-source evaluation identifies B, the high-source-address evaluation identifies C, and the low-destination evaluation identifies D. Assume these fields are accessible and nonoverlapping.

If B’s low word is `3`, C’s high word when eventually read is `5`, and the amount is `4`, expect:

- D’s low word becomes `0xffffffff`.
- A’s high word becomes `4`.
- B’s low word and C’s high word are not directly written by this phase.

Using only A for both source reads would not match the represented behavior.

### Delayed high-word read

If the retained high-source address aliases the low-word destination, the high computation must use the value present **after** the low-word write. It must not use a high value prefetched when that source address was formed.

### Special base and rejected header

For adjusted base `0x00000008`, provided all preceding accesses succeed, expect global accounting, F-2fd8826557a4, and allocator-context acquisition before return. Expect no header validation.

For a nonspecial base with a stable zero header or a stable odd header, expect F-a817d8d58c10 after global accounting, without subsequent normal-path allocator accounting.

### Header mutation during index acquisition

If F-09dcb55e8e0a changes the header, expect the four earlier size-based updates to retain their earlier masked size. The subtraction at allocator-context `+0x08` must use the later header read.
