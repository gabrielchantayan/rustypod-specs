# F-d34857dd0073

## Purpose

F-d34857dd0073 searches a caller-supplied sequence backward for an entry that satisfies two conditions relative to a reference value obtained from a dependency:

1. A dependency-derived 32-bit value for the entry equals the corresponding value obtained for the reference.
2. A second dependency, called with the entry value and the reference value, returns zero.

For a valid, stable sequence with a nonnegative representable count, the function returns the greatest qualifying zero-based index. It returns −1 if no entry qualifies or if no reference value is available.

The interpretation as a search is established by the visible control flow. The semantic meanings of the entries, reference, derived values, and zero-result comparison are not established. In particular, the first comparison is not sufficient by itself to establish a match.

### Output

The visible result is a signed 32-bit integer.

For an ordinary sequence whose count is nonnegative and whose addressing arithmetic is valid:

- A result from zero through count minus one identifies the selected record.
- −1 means either that the reference-producing dependency returned zero or that all eligible records were rejected.

The result does not distinguish those two causes of −1. It also does not expose a separate dependency-failure status.

Malformed negative counts do not necessarily produce −1. Where count minus one is representable and negative, that negative value is returned after the final dependency call, without examining a record.

## Behavior

### Reference acquisition and preparation

The function first establishes −1 as its prospective result and calls F-e7c4e7dd076d with no explicit arguments.

If that call returns zero, the function returns −1 immediately. There is no direct descriptor read, record read, derived-value call, comparison call, or finalization call on this path.

If the returned reference is nonzero, the function passes it to F-1cb585febd84. The result becomes the reference-derived value used throughout the search. This value is computed once; it is not refreshed for each entry.

Only after that call returns does the function read the descriptor count. It subtracts one to obtain the starting index, then reads the descriptor’s record-base field and computes the address corresponding to that starting index.

Consequently, any dependency-visible effects occurring during reference acquisition or reference-value derivation precede the descriptor reads. The function does not capture the descriptor fields before those calls.

### Backward search

The function considers records in descending index order, beginning at count minus one. It tests whether the current index is nonnegative before reading a candidate record.

For each eligible index:

1. It reads the record’s leading 32-bit word and passes that value to F-1cb585febd84.
2. It compares the returned value with the previously obtained reference-derived value.
3. If the values differ, the record is rejected without calling F-e6db2171781a.
4. If the values are equal, it reads the record’s leading word again and passes this newly read value, followed by the reference, to F-e6db2171781a.
5. A zero result from F-e6db2171781a accepts the record. Any nonzero result rejects it.

The second read is behaviorally significant. The function does not guarantee that the entry value used for derived-value calculation is the same value supplied to the comparison dependency. If the first dependency call changes the record’s leading word, the subsequent comparison receives the changed word.

On rejection, the search index decreases by one and the current record address moves backward by 24 bytes. The descriptor count and base are not reread during traversal. Changes to those fields after their initial reads do not directly redirect this traversal.

The first accepted record ends the search. With stable contents and dependencies, this selects the highest qualifying index, not the lowest.

If every record is rejected, the index reaches −1 and the search ends without reading a record at that negative index.

### Completion

Whenever reference acquisition returned nonzero, the function calls F-94cb53877c15 with that reference after the search terminates. This happens for a match, an exhausted sequence, an empty sequence, and a negative initial search index.

On a normal return from that dependency, the function returns the index determined by the search. The final dependency’s return value is not used.

No exceptional-control-flow cleanup is established. If an earlier call does not return normally, the visible normal path provides no guarantee that F-94cb53877c15 will run.

### Integer and address boundaries

The count and index are treated as signed 32-bit quantities. The backward step is 24 bytes per record.

For a nonnegative count within the signed range, count minus one is representable, and ordinary exhaustion stops at −1. However, record-address computation may still exceed the supported address range or the bounds of valid storage.

The minimum signed 32-bit count cannot be reduced by one within the signed range. The supplied representation does not settle the execution model’s overflow behavior. No wrapped result is promised for that case.

The initial record-address calculation occurs even when the starting index is negative. For count zero, it corresponds arithmetically to 24 bytes before the record base, although no record word is then dereferenced. Likewise, rejection of index zero includes a backward address step before termination. The validity or consequences of forming such an address are not established by the visible logic alone.
