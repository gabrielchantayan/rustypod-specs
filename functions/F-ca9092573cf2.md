### Unconditional repeating phase

Immediately before the loop, a returned word is masked with `0x3fffffff` and shifted right by twenty-five. This produces an unsigned value between zero and 31 inclusive.

A call receives twice that value. A following call produces a value used as the first argument of the first loop iteration’s opening call.

Each visible iteration then:

- Makes an opening indirect call with two explicit arguments.
- Makes four further calls, using the last result in a two-bit left shift.
- Performs a byte-selector read and writes zero to the selected destination.
- Calls another target with the two-bit-left-shifted result.
- Makes four more calls.
- Uses the final result to establish the following iteration’s first argument and shifted state.

The selector source used for the loop’s zero store remains derived from the retained pre-loop two-bit-left-shifted word. It is not replaced by the latest loop result. Nevertheless, the selector byte is reread in every iteration.

The opening call’s second argument is the current unsigned loop state shifted right by eight. On the first iteration this argument is necessarily zero, because the initial state is at most 31.

For subsequent iterations, the state is derived from a returned word shifted left by twenty-six. Conditional on low-word 32-bit arithmetic, only the low six bits of that returned word affect the state. The next iteration’s second argument is those six bits shifted left by eighteen. It need not remain zero.

These examples are conditional static consequences, not executed tests.

1. **Explicit third-argument shift.**  
   If execution reaches the four-argument call, original third-argument values from zero through 16,383 produce a fourth argument of zero. An original value of 16,384 produces one. An original value of `0xffffffff` produces 262,143.

2. **First direct word store.**  
   If the incoming value-like word is `0x12345678` and the incoming base permits the write, the first direct store writes the 32-bit value `0x00123456` at that base plus 20.

3. **Byte truncation.**  
   If the returned word used for the first selector-based byte store is 65, shifting it left by two produces 260; the stored byte is 4. This does not imply that a call receiving the shifted word receives only 4.

4. **Fresh selector reads.**  
   If a selector read yields 10, that store targets address 27. If an intervening callee changes the selector byte to 20, the next selector-based store targets address 37. Reusing the earlier destination would not match the represented behavior.

5. **High-field byte extraction.**  
   If the retained word is `0x12345678`, masking with `0x3fffffff`, shifting right by twenty, and retaining one byte produces `0x23`.

6. **Fixed-offset byte destination.**  
   If the shared input word is `0xffffffff`, its twenty-three-bit logical right shift is 511. The fixed-offset byte destination is therefore 539, subject to the address being valid.

7. **First versus later loop arguments.**  
   The first loop opening call has second argument zero. If a later loop result is one, then under 32-bit shift semantics the following iteration has second argument `0x00040000`. A contract requiring that argument always to be zero would be incorrect.

8. **No-op substitution is unacceptable.**  
   Even when every visible stored byte happens to be zero, execution still includes the intervening calls, selector reads, and repeated writes. Their observable effects must not be discarded.
