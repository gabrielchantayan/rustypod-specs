# F-1394c41998ed

## Purpose

F-1394c41998ed combines a long indirect-call prefix with arithmetic transformations and an alias-sensitive sequence of direct memory accesses. It ends with an unresolved indirect transfer represented as a four-argument invocation.

No reliable application-level purpose is established. Repeated offsets do not establish a valid object layout, and constants resembling characters do not establish text processing.

This contract distinguishes:

- **Established static evidence:** represented accesses, widths, argument construction, and ordering.
- **Inferred intent:** possible interpretations, not behavioral requirements.
- **documented_only:** unresolved semantics or explicitly delimited coverage.

The indirect-call prefix is documented only partially; its unenumerated invocation order and individual dataflow remain outside this contract. This is a coverage limitation, not a claim that those relationships are absent from the supplied representation. The direct-access account below preserves the consequential captures, repeated reads, fixed-storage updates, and final stores.

All behavior is conditional on execution reaching the relevant operation.

## Interface

### Entry and effective inputs

The represented interface has no explicit parameters and no declared return value. Effective inputs include:

- Incoming execution context used to construct the first indirect target.
- Results and secondary result state from indirect dependencies.
- Memory reached through those results and subsequent arithmetic.
- Fixed byte storage, including address `0x05`.
- Fixed word storage at `0xA9`.
- A fixed 32-bit word at `0x087FBBBC`, captured after the constant-write group and before publication.

The last fixed word supplies the publication base and later access destinations. Its value is not established at entry: preceding dependency effects and potentially aliasing stores can affect the value eventually read.

### Outputs, widths, and layout

There is no explicit ordinary return value. Outputs consist of dependency effects, direct stores, and the final indirect invocation.

| Representation | Width and interpretation |
|---|---|
| Byte read or store | 8 bits |
| Halfword store | 16 bits |
| Word read, store, or ordinary result | 32 bits |
| Combined dependency result | 64 bits |
| Each component of a combined result | 32 bits |

A byte converted into a word is zero-extended. Narrow stores retain the low bits of their supplied value. Splitting a combined result into low and high words is numerical; it does not establish an eight-byte memory layout or endianness.

Offsets are byte displacements. An access at an offset from one base does not establish that another base has the same layout. No object boundaries, alignment guarantees, or disjointness requirements are supplied.

Arithmetic descriptions involving multiplication, subtraction, or left shifts are conditional on a suitable 32-bit execution interpretation. Where modular examples are given, intermediate results are explicitly treated as 32-bit bit vectors. Signed overflow and address wrapping are otherwise unresolved.

### Preconditions and errors

Normal continuation requires callable targets, compatible result conventions, accessible memory at every reached address, and supported widths and alignments. No visible validation enforces these prerequisites.

No status-based recovery, error result, rollback, or cleanup path is represented. Invalid targets, invalid accesses, or dependency non-return can prevent completion after an arbitrary prefix of effects.

## Behavior

### Dependency-prefix coverage

The first invocation targets an address derived from incoming context plus `0xFFE` and receives one explicit zero argument. Later targets are predominantly constructed from code-position-derived values with the same displacement.

The prefix contains separate indirect invocations with zero through four explicit arguments. It consumes ordinary 32-bit results, combined 64-bit results, and secondary result state. Captured values sometimes survive multiple intervening invocations.

Established transformation families include:

- Eight-bit left shifts of low result words, sometimes paired with unchanged high words.
- Repeated arguments derived from the same captured result.
- Masks retaining low 24, 22, 20, 19, 17, 14, 13, 12, 11, or one bit.
- Logical right shifts and numerical extraction from combined results at shifts of 34, 36, and 44 bits.
- Further left shifts, including shifts that discard previously retained bits.

These families are not a substitute for the missing ordered invocation trace. This contract does **not** enumerate most invocation positions, argument tuples, result producers, or secondary-result producers. An implementation cannot claim full prefix equivalence merely by matching these families.

No explicit conditional branch, retry, or loop is represented in the prefix. Unknown dependency effects cannot be discarded because a result is unused or two invocations look similar.

### Captured quantities entering direct access

The following descriptive names identify captured values, not object types:

| Name | Meaning |
|---|---|
| **Shifted base** | A dependency result shifted left 25 bits |
| **Scale result** | A separate 32-bit dependency result |
| **Scaled base** | Scale result multiplied by `0x2000000` |
| **Small index** | A result shifted left eight bits, masked with `0x7FFF`, then logically shifted right six bits |
| **Doubled index** | Twice the small index |
| **Retained value** | Another captured result shifted left eight bits |
| **Final pair** | Low and high words of the last combined dependency result |

Under 32-bit bit-vector arithmetic, the small index is a multiple of four between 0 and 508; the doubled index is a multiple of eight between 0 and 1016. These are numeric address ingredients, not validated heap pointers.

### Initial stores and low-address input

The first word store writes the shifted base at offset `0x14` from the final pair’s high word. The shifted base’s offset-`0x09` byte then receives the low byte of that high word. Between this byte store and a second byte store to the same location, a word at 256 times the final low word plus `0x54` receives the scaled base. The second byte store carries the low byte of the shifted base.

The scaled-base offset-`0x14` word is cleared before its offset-`0x05` byte is read. Next, the doubled-index offset-`0x14` word is cleared, and the captured byte is written as a zero-extended word at scaled-base offset `0x34`. A fresh word read at scaled-base offset `0x14` supplies the **initial field value**. The doubled-index word is cleared again, followed by two byte stores of the initial field value at doubled-index offset `0x15`.

A byte is then read from fixed address `0x05`, producing the **low-address base**. Immediately afterward, fixed byte `0x01` receives the low byte of the doubled index. Subsequent effects, in represented order, are:

- The low-address base’s offset-`0x15` byte receives the small index’s low byte.
- The scaled-base offset-`0x11` byte receives the retained value’s low byte.
- The initial field value is used as a base for a retained-value word store at offset `0x54`.
- The scaled-base offset-`0x11` byte is cleared.

The low-address base’s offset-`0x54` word is now read and captured as the **anchor** before that field is overwritten with the initial field value. The doubled-index offset-`0x34` word receives the small index.

### Anchor construction and repeated field accesses

A word read at scaled-base offset `0x74` supplies another base. Its offset-`0x54` word first receives the scale result shifted left 26 bits.

A separate nested assignment contains **two represented word reads of doubled-index offset `0x74`**: one supplies a destination base for an offset-`0x54` store, and the other supplies the stored word. They are not one captured read. Their within-expression evaluation order is unresolved; both are inputs to the store.

The anchor then governs two repeated pairs of effects: a word self-value store at anchor offset `0x24`, followed by a byte store of the anchor into offset `0x09` of the previously loaded scaled-base child. Between the pairs, that child’s offset-`0x54` word receives the retained value.

The doubled-index offset-`0x14` word next receives the scale result shifted left 26 bits. **Fixed word `0x54` then receives the anchor shifted left once.** After that fixed update, doubled-index offset `0x14` receives the anchor twice.

Define the **anchor-derived base** as four times the anchor and the **wide anchor value** as eight times the anchor. Two byte stores place the low byte of the anchor-derived base at doubled-index offset `0x15`; **fixed byte `0x15` then receives the doubled index’s low byte**.

The anchor-derived base’s offset-`0x54` word receives the retained value. Doubled-index offset `0x34` receives four times the anchor. A further, distinct read of doubled-index offset `0x74` is doubled to produce the **first doubled child**; it is not reuse of either nested-assignment read.

Further writes establish transient, potentially overlapping values:

- Anchor-derived offset `0x54` receives the anchor-derived base itself.
- Its offset-`0x15` byte receives the wide anchor value.
- Anchor offset `0x44` receives the first doubled child.

A byte read at anchor-derived offset `0x05` becomes the unsigned numeric base for a word read at offset `0x74`. The resulting **nested child** receives the first doubled child at offset `0x44`.

The anchor-derived offset-`0x15` byte is subsequently overwritten with the anchor-derived base’s low byte. Its offset-`0x0D` byte receives the nested child’s low byte; its offset-`0x14` and offset-`0x54` words receive self-values.

A word loaded at anchor-derived offset `0x64` supplies another base whose offset-`0x0D` byte receives the nested child’s low byte and whose offset-`0x14` word receives its own base value. A separate word read at anchor-derived offset `0x04` supplies the **byte-field base**.

### Repeated byte reads and constant-write group

The first doubled child receives the nested child’s low byte at offset `0x09` and the wide anchor value at offset `0x44`.

The byte-field base’s offset-`0x05` byte is read **twice at distinct positions**:

- After the first read, the anchor-derived offset-`0x09` byte receives the first doubled child’s low byte; nested-child offset `0x44` receives the zero-extended byte; anchor-derived offset `0x14` receives the wide anchor value; and first-doubled-child offsets `0x15` and `0x44` receive the byte-field base’s low byte and the anchor-derived base, respectively.
- Only then is the offset-`0x05` byte read again. After a byte store of the wide anchor value at anchor-derived offset `0x15`, the second byte supplies the unsigned base for a fresh offset-`0x74` word read.

Call that last word the **constant-group child**, and twice it the **final doubled child**. Before the constant group, anchor-derived offset `0x15` receives the byte-field base’s low byte, offset `0x54` receives the anchor-derived base, offset `0x09` receives the final doubled child’s low byte, and offset `0x14` receives the wide anchor value.

The constant group writes numeric `0x3A`:

- As a byte at four times the constant-group child.
- As a halfword at eight times that child.
- As a word at four times that child plus `0x20`.

The **adjusted value** is the anchor-derived base minus `0x96`; the **adjusted base** is four times the adjusted value. At adjusted-base offset `0x20`, four successive word stores carry `0x20`, `0x2F`, a zero-extended byte freshly read at adjusted-base offset `0x04`, and `0x20`.

### Fixed publication input and repeated publication

After the final constant-group word store, the function reads the fixed word at **`0x087FBBBC`** and captures it as the **publication base**. This read precedes the word store of `0x20` to **fixed address `0x60`**, which precedes publication.

The publication payload is four times the constant-group child. The initial publication has four ordered stores:

1. A payload word at wide-anchor-value offset `0x54`.
2. The adjusted base’s low byte at publication-base offset `0x19`.
3. The publication base’s low byte at adjusted-base offset `0x11`.
4. The wide anchor value as a word at publication-base offset `0x34`.

A finite, explicitly repeated group follows. Each instance preserves that four-store ordering, but its first destination is eight times the adjusted value plus `0x54`, and its last stored word is eight times the adjusted value. The byte destinations and byte values remain based on the captured publication and adjusted bases.

The exact repetition count is **documented_only** in this contract. Repetition is not established as a data-dependent traversal. The fixed publication input is captured once here; later uses are not represented as rereading that fixed word.

### Final captures and fixed byte updates

After publication:

- Fixed word `0xA9` is read and captured.
- A word is read at publication-payload offset `0x74`.
- **Fixed byte `0x3A` is updated** from the adjusted value multiplied by eight plus `0x30`, with byte truncation.
- Only afterward are words captured from final-doubled-child offset `0x14` and adjusted-base offset `0x04`.

Under modular arithmetic, the `0x3A` byte value is the low eight bits of that calculation. The fixed-word and payload-field reads precede this update; the two subsequent captures must not be moved before it.

The final doubled child’s offset-`0x0D` byte receives the adjusted base’s low byte. Adjusted-base bytes at offsets `0x08`, `0x0D`, and `0x09` receive `0x6C`, the publication base’s low byte, and that same low byte. Final-doubled-child offset `0x54` receives its own base value.

Fixed byte **`0x67`** then receives the low byte of the captured fixed word. A word read at final-doubled-child offset `0x44` supplies the **captured field word**.

There are **three later reads of fixed byte `0x67`**:

1. The first supplies the byte store to fixed `0x21`.
2. The second supplies a later adjusted-base offset-`0x09` store.
3. The third supplies another adjusted-base offset-`0x09` store.

These are fresh represented reads, not interchangeable uses of the byte initially written.

### Final field replacement and transfer

Between the first and second `0x67` reads, adjusted-base offset `0x10` receives the captured field word’s low byte. Publication-base offset `0x54` receives that word, then receives the adjusted base. Between those word stores, final-doubled-child offset `0x01` receives the low byte of the captured field word right-shifted by the low eight bits of the adjusted base. Shift signedness and large-count behavior remain unresolved.

A word is read at adjusted-base offset `0x40`. The earlier captured offset-`0x04` word is stored at **publication-base offset `0x74`**, and the offset-`0x40` word is stored at adjusted-base offset `0x10`. Publication-base offset `0x44` receives the final doubled child. The second `0x67` read then supplies its byte store.

Next, final-doubled-child offset `0x09` receives the adjusted base’s low byte, and **adjusted-base offset `0x44` receives the captured fixed word**. A fresh word read at adjusted-base offset `0x54` supplies the **late destination**. The third `0x67` read supplies its byte store after that capture.

The late destination’s offset-`0x0D` byte receives the low byte of the captured publication-payload offset-`0x74` word. **Final-doubled-child offset `0x54` is restored from the earlier captured offset-`0x14` word**, not reread from that field.

A fresh adjusted-base offset-`0x14` word supplies a later byte value. Subsequent writes place:

- The captured payload-field low byte at final-doubled-child offset `0x11`.
- The late destination’s low byte at adjusted-base offset `0x09`.
- The late destination as a word at adjusted-base offset `0x44`.

A word read at final-doubled-child offset `0x04` supplies the **terminal base**. A halfword `0x65` is stored at twice that base, followed by a word read at terminal-base offset `0x64`, producing the **terminal value**.

The late destination’s offset-`0x11` byte receives the low byte of the freshly read adjusted-base offset-`0x14` word; its offset-`0x54` word receives decimal 100. Terminal-base offset `0x74` is then read for the final argument. A word read at final-doubled-child offset `0x64` supplies another destination base.

The remaining stores put the terminal base’s low byte at final-doubled-child offset `0x09`, the terminal value at offset `0x54` of that last destination, and that destination value as a word at twice the terminal value.

The final invocation receives, in order:

1. `0x72`.
2. The terminal value.
3. The earlier captured final-doubled-child offset-`0x14` word.
4. The terminal-base offset-`0x74` word.

A return is represented afterward, conditional on that invocation returning.

## Side effects

The contract preserves represented access widths, repeated accesses, and ordering between distinct expressions. It does not establish hardware atomicity, memory barriers, volatility, or observability by another execution agent.

Aliasing is not excluded. Fixed addresses, derived addresses, byte fields, and word fields can overlap. Later reads therefore use memory at their own represented positions, not presumed earlier values.

No explicit allocation or release is identifiable in the direct-access portion. Dependency contracts are absent, so allocation, release, retention, and global mutation by dependencies remain unknown.

## Acceptance examples

These are conditional checks, not executed tests.

- **Small-index boundary:** Under 32-bit bit-vector semantics, a relevant result with low seven bits all set produces index 508 and doubled index 1016. Its offset-`0x14` address is 1036; no pointer validation is implied.
- **Publication capture:** If the fixed publication word yields a particular base, publication and later accesses use that captured base even if subsequent aliasing stores overwrite the fixed word.
- **Fixed updates:** If the anchor is `0x12345678`, the fixed `0x54` word receives `0x2468ACF0` under modular arithmetic. This occurs between the scale-derived doubled-index store and the later anchor stores.
- **Adjusted byte:** If the adjusted value has low byte `0xFF`, fixed `0x3A` receives `0x28` under modular arithmetic. The fixed `0xA9` and payload offset-`0x74` captures already occurred; the child offset-`0x14` and adjusted offset-`0x04` captures have not.
- **Fresh reads:** If an intervening aliasing write changes the byte-field base’s offset-`0x05` byte, the second read can differ from the first. Likewise, each of the three later fixed-`0x67` reads supplies its own store.
- **Restoration:** If final-doubled-child offset `0x14` changes after capture, its later offset-`0x54` restoration still uses the captured word.
- **Non-return:** If any dependency fails to return, later accesses are not reached. No local recovery is established.
