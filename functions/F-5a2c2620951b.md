## Behavior

### Observable ordering and notation

This contract names retained values by their role, not by source identifiers. A “retained result” means a value reused later in the supplied representation. It does not assert that an unknown callee preserves the physical register that originally held it.

For concise layout descriptions:

- A **byte-selected write** first reads one byte at a specified selector address, zero-extends that byte, and writes one byte at the resulting address plus 0x11.
- A **scaled word slot** for an index is the address obtained by multiplying that index by four and adding 0x14.

A byte-selected destination therefore lies between 0x11 and 0x110 inclusive. It is not a pointer-sized load, and the selector is not visibly added back to its original base.

Dependencies can alter memory between events. Two reads from the same selector address must not be assumed to return the same byte.

## Side effects

The direct effects comprise byte writes to byte-selected low addresses and 32-bit writes to arithmetically derived addresses. There is no demonstrated isolation between these regions.

Important aliasing consequences include:

- A byte-selected destination can overlap another selector.
- Byte and word accesses can overlap.
- Two scaled word slots can alias after arithmetic wrapping.
- The sixteen-scaled store and four-scaled read can coincide for some indices but must not generally be treated as the same location.
- Dependencies can change memory before a later reread.

Endianness and memory-mapping attributes are not established. Where differently sized accesses overlap, those properties affect subsequent observations.

No allocation, release, ownership transfer, lock acquisition, or resource cleanup is directly established. Such effects may occur inside dependencies, but their contracts are unavailable. Passing an integer that resembles an address does not establish ownership or even that the callee interprets it as an address.

There is no visible error result or recovery path. Faults, nonreturning dependencies, and invalid targets can prevent all later effects. Earlier writes are not visibly undone.

## Acceptance examples

These are conditional static acceptance criteria, not executed tests.

1. **Initial truncation.** If the input word is 0x123456AB and the first selector read returns 0x20, the first direct store writes 0xAB at address 0x31 before any visible dependency invocation.

2. **Fresh selector on the second write.** If the first selector read returns 0x20 and the second returns 0x21, the two initial writes target 0x31 and 0x32 respectively. Reusing the first selector would violate the visible access sequence.

3. **High input-byte extraction.** With input word 0xFFFFFFFF, the second input-derived byte is 0xFF. With input word 0xC0000000, it is zero: bits 30 and 31 do not survive the final byte truncation.

4. **Collapsed arithmetic address.** Under 32-bit wrapping arithmetic, shifting any entry base left by 26 and then multiplying by 0x400 produces zero. The subsequent zero-byte operation therefore reads its selector at address 1, not at an entry-base-relative address.

5. **Distinct scaled locations.** If a repeated-stage index equals one, the sixteen-scaled store is at address 0x24, while the four-scaled read is at address 0x18. The read is not justified as reading back that store.

6. **Split-result independence.** If the split high word is three, its zero store targets 0x20. The split low word independently determines the later high-scale store; it must not be replaced by the high word.

7. **Retained read before calls.** If the word captured in the fourth repeated stage is 0xABCDEF01, its later shifted store contains 0x000ABCDE, conditional on reaching that store and preserving the represented retained value.

8. **Interrupted execution.** If any dependency does not return, later direct stores are not required to occur. No rollback of preceding stores is established.
