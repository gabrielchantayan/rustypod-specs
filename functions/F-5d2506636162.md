### Ordered memory operations

The visible prefix performs five writes and two reads. The reads occur while deriving the fourth write’s destination.

#### 1. Store the incoming byte

The first operation writes the implicit 8-bit value to the address two bytes beyond the implicit address base.

There is no preceding check that the destination is valid, writable, or part of a larger structure. The representation shows a byte write, not a read-modify-write of a larger field.

#### 2. Store the high ten bits of the incoming unsigned word

The routine logically shifts the implicit unsigned 32-bit value right by 22 bits and writes the resulting 32-bit word at byte offset 44 from the third explicit argument.

The stored value is between 0 and 1023 inclusive. The lower 22 bits of the incoming word do not contribute to it.

The write width is 32 bits even though only ten result bits can be nonzero. Its byte ordering in memory is not established.

#### 3. Store a byte at a scaled address

The implicit signed integer is multiplied by 1024 to derive another address. At that address, the routine stores a byte converted from the same integer.

Under the conventional 32-bit model, the destination is the integer multiplied by 1024 modulo \(2^{32}\), and the stored byte contains the integer’s low eight bits.

The representation does not test whether the derived address is null, aligned, mapped, or writable.

The routine then derives an intermediate address 158 bytes beyond this scaled address. This intermediate address supplies the value for the next byte store and participates in the later zero-store calculation.

#### 4. Follow two 32-bit reads and store an address-derived byte

The next destination is obtained in this order:

1. Logically shift the fourth explicit argument right by 12.
2. Add 104 bytes to obtain the first read address.
3. Read a 32-bit address-like value there.
4. Add 96 bytes to that read value to obtain the second read address.
5. Read an unsigned 32-bit word there.
6. Logically shift that word right by two.
7. Add four bytes to obtain the byte-store destination.

The routine writes a byte converted from the intermediate address derived in the preceding step.

Under the conventional model, the byte is the low eight bits of the scaled address plus 158. Because multiplication by 1024 contributes zero to the low eight bits, that byte is always 158, or hexadecimal `9E`, regardless of the implicit integer.

That constant-byte conclusion is conditional on the stated conversion and arithmetic model. The source representation expresses an address-derived conversion rather than an independently specified application-level constant.

Both reads occur after the first three writes. If an earlier write overlaps either read location, the read observes the resulting memory state, subject to the actual memory system’s semantics. The routine does not capture these source words before making the earlier writes.

The fourth argument is used as a shifted numeric value. The representation does not first dereference the unshifted argument.

#### 5. Store zero at a second scaled address

The intermediate address—158 bytes beyond the first scaled address—is converted to an integer and multiplied by 1024.

The routine writes a single zero byte at an address 94 bytes below this second scaled result.

It separately derives the initial loop-state word by subtracting 104 from the same second scaled result and converting the result to an unsigned 32-bit quantity. Under the conventional model, the zero-store destination is therefore ten bytes above the address-valued quantity used to initialize the loop state.

No load from either of these final addresses is visible. Their numerical values are used for address calculation and loop-state calculation.

### Nonterminating transfer phase

After the zero-byte write, the routine repeatedly:

- Forms a transfer value by logically shifting the current unsigned 32-bit loop-state word right by 11.
- Sets that loop-state word to zero.
- Invokes the represented coprocessor operation with fixed selectors 8, 5, and 4, the transfer value, and the two opaque incoming 32-bit quantities.

The first transfer uses the address-derived initial loop state. On every subsequent visible iteration, the transfer value is zero because the loop state was reset before the preceding operation.

This is a statement about the represented local dataflow. It is not a guarantee that the coprocessor operation preserves globals, memory, processor state, or other hidden state.

There is no visible loop exit, delay, status check, retry limit, or ordinary function return. The prefix’s memory accesses are not visibly repeated by the loop.
