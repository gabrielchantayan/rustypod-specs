# F-ea7659e759d5

## Purpose

F-ea7659e759d5 conditionally performs an ordered sequence of dependency calls using two pairs of 32-bit operands, an operation context, and fields reached through an owner object.

The established contract is the selection and ordering of those calls, their arguments, the memory reads used to select them, and the resulting return paths. The semantic meanings of operation selectors and dependency-produced values are not established.

The routine has three kinds of outcome:

- Return the initially read activation byte without calling dependencies.
- Enter construction, perform the applicable dependency calls, and return a selected or dependency-produced candidate because the final mode is unsupported.
- Enter construction and return the result of a completion dependency.

“Construction” names the dependency sequence described below. It does not establish that the routine allocates memory, emits instructions, evaluates an expression, or produces an encoded representation.

## Interface

The routine takes seven arguments in this order:

|---|---|---|
| 1 | Owner address | Supplies a state-object address from byte offset 8. |
| 2 | Operation-context address | Supplies a dependency-context value from byte offset 4 and is itself passed to operation dependencies. |
| 3 | Unused argument | A 32-bit value neither inspected nor forwarded. |
| 4 | Primary base | A 32-bit operand used for comparison and primary selection. |
| 5 | Primary alternative | A 32-bit operand; zero is replaced locally by the primary base. |

The supplied representation treats the primary operands as unsigned 32-bit values and the secondary operands as signed 32-bit values. This routine applies only zero tests, equality tests, and forwarding to the secondary operands. No signed ordering or signed arithmetic distinguishes their interpretation here.

Address-bearing arguments and loaded addresses have 32-bit representations. Accessed objects must be valid and readable when each access occurs. No null, bounds, alignment, lifetime, or address-overflow checks are present.

These alternatives do not establish a uniform success/error convention. In particular, zero is not established as an error indication.

## Behavior

### Initial reads and mode classification

Before making any dependency call, the routine:

1. Reads the dependency context from the operation context at offset 4.
2. Reads the state-object address from the owner at offset 8.
3. Reads the activation byte from that state object at offset 128, treating it as unsigned.
4. Tests the mode byte at offset 179.

The mode test has two possible accesses: first a test for zero, then, if that test fails, another read and test for one. Both accesses use the state-object address already obtained; the owner is not reread between them.

The resulting classification is:

- **First mode read is zero:** selected mask and full mask are both zero; no mode-specific secondary adjustment is enabled.
- **First mode read is nonzero and second mode read is one:** mode-1 behavior is selected. The selected mask is the state field at offset 160 bitwise ANDed with the external mask value. The full mask is then obtained through a separate reference to that external value. The mode-specific operand is 16.
- **First mode read is nonzero and second mode read is not one:** return the initial activation byte immediately.

Thus, an unsupported initial mode is rejected before operand normalization and without dependency calls. A transition from a nonzero first mode read to a zero second read also takes this rejection path.

The mode-1 mask derivation and full-mask capture reference the external value separately. If those references can observe different values, the selected mask need not be a subset of the captured full mask. The representation does not establish a concurrent-access model or the relative operand-read order within the bitwise expression.

### Normalization and the construction gate

For a supported initial classification:

- A zero primary alternative is replaced locally by the primary base.
- A zero secondary alternative is replaced locally by the secondary base.

All later references to alternatives in this contract mean these normalized values. No caller memory is updated by normalization.

Construction is entered exactly when either condition holds:

- The initial activation byte is nonzero **and** the primary base differs from the normalized primary alternative.
- The selected mask is nonzero **and** the secondary base differs from the normalized secondary alternative.

If neither condition holds, the routine returns the initial activation byte and calls no dependency. It also performs none of the later activation or mode reads.

A difference between supplied arguments is insufficient if normalization removes that difference. For example, secondary base 5 and supplied secondary alternative 0 become equal operands. They cannot trigger construction, even with a nonzero selected mask.

The full mask does not independently trigger construction.

### Conditional secondary construction

After construction has been entered, the selected mask is compared with the captured full mask.

If they are equal, the secondary construction below is skipped. The effective secondary operand is the normalized secondary alternative.

If they differ, the following sequence occurs. Each produced value is the result of a separate F-b35e541ebc78 call with the captured dependency context and a second argument of zero. Separate calls are required; distinct return values are not guaranteed.

1. Obtain a first value. Call F-fbf0cbff8cb3 with the operation-context address, selector 40, that value, and the full mask AND the 32-bit complement of the selected mask.
2. Obtain a second value. Call F-915779408ccb with the operation-context address, selector 2, that value, the secondary base, and the first value.
3. Obtain a third value. Call F-fbf0cbff8cb3 with the operation-context address, selector 40, that value, and the selected mask.
4. Obtain a fourth value. Call F-915779408ccb with the operation-context address, selector 2, that value, the normalized secondary alternative, and the third value.
5. Obtain a fifth value. Call F-915779408ccb with the operation-context address, selector 12, that value, the fourth value, and the second value.

The fifth value becomes the effective secondary operand. It is the return from F-b35e541ebc78, not the ignored return from the subsequent operation call.

All mask operations here are 32-bit bitwise operations. There is no signed-mask comparison, widening arithmetic, population count, or shift.

This stage depends on mask inequality, not on which operand pair triggered entry. A primary difference can therefore cause secondary construction even when the secondary operands are equal or the selected mask is zero.

### Mode-specific secondary adjustment

If the initial classification selected mode 1, the routine next:

1. Obtains a value from F-b35e541ebc78 using the captured dependency context and zero.
2. Calls F-fbf0cbff8cb3 with the operation-context address, selector 40, that value, and operand 16.
3. Obtains another value from F-b35e541ebc78 with the same arguments.
4. Calls F-915779408ccb with the operation-context address, selector 6, the latter value, the effective secondary operand, and the value associated with operand 16.

The latter produced value becomes the adjusted secondary operand.

In initial mode 0, this adjustment is skipped and the effective secondary operand is retained.

These decisions use the initial classification. A dependency changing the mode does not retroactively change either secondary stage.

### Primary selection from a later state read

The routine next rereads the state-object address from the owner and reads the activation byte from that object.

It selects the primary base if the later activation byte is zero or the primary operands are equal. Otherwise it selects the normalized primary alternative.

The activation read occurs even when the primary operands are equal. Neither the state-object address nor its activation byte is assumed to match the initial observations.

### Optional final combination

If the captured full mask is nonzero:

1. Obtain a value from F-b35e541ebc78 using the captured dependency context and zero.
2. Call F-915779408ccb with the operation-context address, selector 12, that value, the selected primary operand, and the adjusted secondary operand.
3. Make the produced value the final candidate.

If the captured full mask is zero, the selected primary operand is the final candidate.

This decision uses the previously captured full mask. It does not reread external mask storage.

### Completion using a later mode read

The routine rereads the state-object address from the owner again, then reads that object's mode byte once.

- Mode 0: call F-a40430e2991a with the operation-context address and selector 43.
- Mode 1: call F-a40430e2991a with the operation-context address and selector 44.
- Any other value: return the final candidate without calling F-a40430e2991a.

For a supported later mode, the result of F-a40430e2991a is returned. The final candidate is not an explicit argument to that call.

The completion mode is independent of the initial classification. For example, an initial mode-1 construction can finish with selector 43 if the later mode is zero.

## Side effects

The supplied body contains no direct writes to the owner, operation context, state object, or external mask storage. Normalization and candidate selection change only working values.

Dependencies can have observable effects:

- Every F-b35e541ebc78 call remains a separate call; purity or interchangeability is not established.
- Results from F-fbf0cbff8cb3 and F-915779408ccb are ignored.
- No dependency error result is checked, translated, retried, or rolled back.
- An unsupported later mode does not undo preceding effects.
- All F-b35e541ebc78 calls use the dependency context captured at entry, even if a dependency changes the corresponding operation-context field.
- Later state reads reacquire the owner’s state-object address. Dependency changes to that address can therefore affect subsequent selection and completion.

No ownership transfer, allocation policy, release obligation, retention policy, or global-preservation guarantee follows from these call shapes. A dependency-produced value is not established to be a heap address. The routine performs no explicit release.

If a dependency does not return normally, the later sequence is not established to occur. No local recovery mechanism is shown.

The described read sequence is static evidence, not a guarantee of synchronization, atomicity, volatile access, or defined concurrent mutation.

## Acceptance examples

These are conditional static acceptance criteria, not executed tests. Unless stated otherwise, assume readable objects, stable mask data, normal dependency returns, and no dependency mutation of the owner or state.

### Unsupported initial mode

With initial activation 173 and both applicable initial mode reads yielding 2:

- Return 173.
- The dependency-context field, state-object address, and activation byte have already been read.
- Call no dependency.
- Neither operand pair affects the result.

### No construction trigger

With initial mode 1, activation zero, and selected mask zero:

- Return zero without dependency calls.
- A primary difference does not trigger entry because activation is zero.
- A secondary difference does not trigger entry because the selected mask is zero.
- A nonzero full mask does not change this outcome.

### Normalization suppresses a supplied difference

With activation zero, secondary base 5, and supplied secondary alternative zero:

- The normalized secondary alternative is 5.
- No secondary trigger exists, regardless of whether the selected mask is partial, full, or zero.
- With no primary trigger, return zero without construction, adjustment, combination, or completion calls.

This remains true for full mask 15 and state mask field 3, or for full mask 15 and state mask field 15.

### Mode 0 with a primary trigger

With mode zero throughout, nonzero initial activation, and distinct nonzero primary operands:

- Enter construction.
- Skip both secondary stages and the final combination.
- Perform the later activation read.
- Call F-a40430e2991a with selector 43 and return its result.
- Call none of the other dependencies.

### Partial selected mask with a normalized secondary difference

With initial mode 1, activation zero, stable full mask 15, state mask field 3, secondary base 5, and secondary alternative 9:

- The normalized secondary alternative remains 9, differing from base 5.
- Selected mask 3 and that normalized difference trigger construction.
- The first two selector-40 mask operands are 12 and 3, in that order.
- Perform the five-value secondary construction, operand-16 adjustment, and final combination.
- Before completion, call F-b35e541ebc78 eight times, F-fbf0cbff8cb3 three times, and F-915779408ccb five times.
- If the later mode is 1, complete with selector 44.

### Full selected mask with a normalized secondary difference

With initial mode 1, activation zero, stable full mask 15, state mask field 15, secondary base 5, and secondary alternative 9:

- Selected and full masks are both 15.
- The secondary operands remain different after normalization, so construction is entered.
- Skip the five-value secondary construction.
- Feed normalized alternative 9 into the operand-16 adjustment.
- Perform the final combination.
- Before completion, call F-b35e541ebc78 three times, F-fbf0cbff8cb3 once, and F-915779408ccb twice.

### State replacement and unsupported completion

On an entered path, suppose a dependency replaces the owner’s state-object address before primary selection. The replacement object has activation zero and later mode 2.

- The later activation read uses the replacement object and selects the primary base.
- All applicable operations before completion still occur.
- The later mode read yields 2, so F-a40430e2991a is not called.
- Return the final candidate.
- If the captured full mask is nonzero, that candidate is the value produced for the final selector-12 call, not that call’s ignored result.
