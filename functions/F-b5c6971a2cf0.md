# F-b5c6971a2cf0

## Purpose

F-b5c6971a2cf0 produces a diagnostic report over a sequence of fixed-stride records, optionally pauses between groups of records, and normally follows the record report with kernel-region and high-water statistics.

For each record, it examines a contiguous prefix of two-word entries matching a particular fill pattern. It reports the original byte count, the byte count represented by that matching prefix, and the remaining whole-entry byte count.

**Inferred intent:** the paired-word entries describe fill-marked storage, and the report distinguishes unused storage from storage that has been used. The function establishes only a prefix-pattern measurement; it does not establish the contents or utilization of the unscanned remainder.

The function has two materially different stop behaviors:

- A stop response during record pagination abandons the remaining records but proceeds to the summary.
- A stop response at the final pagination prompt returns immediately, omitting the summary.

## Interface

### Explicit interface

- No explicit parameters.
- No explicit return value.
- Reporting and interaction occur through software interrupts and opaque dependencies.

### Implicit inputs

The function obtains the following from shared storage:

| Input | Role |
|---|---|
| Record-count address | Points to the signed count used by the record loop. |
| Fill-pattern word | Expected first word of each matching two-word entry. |
| Record-table base | Base address for fixed-stride record lookup. |
| Kernel-region address | Starting address for the fixed-size summary scan. |
| Nesting-statistic address | Supplies a value reported after the kernel-region summary. |
| Signal-list address | Starts a sequence of words terminated by a zero word. |
| Format and prompt objects | Supply reporting layouts and a pagination prompt. |

The count-address value, fill-pattern word, and record-table base are loaded before either of the initial software interrupts. Those saved values are then used during record processing. The count itself is not snapshotted: the saved count address is dereferenced for each record-loop condition.

### Record layout

The established record stride is **52 bytes**. Record numbering starts at **1**, so the first processed record is at base plus 52 bytes; the object at the unadjusted base is not processed.

The function uses these fields within each selected record:

| Byte offset | Interpretation |
|---|---|
| 20 | Pointer to the first two-word entry to inspect. |
| 24 | Unsigned 32-bit byte count. |

Each inspected entry occupies **8 bytes**, interpreted as two 32-bit words:

1. A fill-pattern word.
2. A word required to be zero.

Other record fields are not directly inspected by this function.

### Widths and validity requirements

The supplied representation uses 32-bit integer words for the calculations and entry fields. Record indices, record counts, and the signed reporting temporary are represented as signed integers; lengths and prefix counters are represented as unsigned 32-bit integers. Pointer width and platform-specific pointer arithmetic semantics are not independently established.

Normal operation requires:

- A readable record-count word.
- Valid address arithmetic for every selected record.
- Readable fields at offsets 20 and 24 of each selected record.
- Readable scan storage whenever the entry pointer is non-null and the whole-entry count is nonzero.
- A readable kernel region for every entry actually examined, up to 512 bytes.
- A readable, eventually zero-terminated signal list.
- Dependencies that correctly handle the provided formats, addresses, and values.

These are caller/environment preconditions, not validated conditions. There is no explicit error result for violating them.

## Behavior

### 1. Initial state and interrupts

The function first obtains, in order:

1. The record-count address.
2. The fill-pattern word.
3. The record-table base.

It then issues **two consecutive software interrupts**, each with immediate value **0x123456**.

Their purpose, arguments beyond that immediate, return behavior, and effects on shared state are unknown. No direct interpretation such as clearing a screen or printing a heading is established.

The record-loop index and pagination counter are each initialized to 1 after these interrupts.

### 2. Record traversal and pagination

Before each record, the function reads the signed count through the saved count address and continues only if the current signed record index is less than or equal to that count.

Consequences include:

- An initial count of zero or a negative value produces no record rows.
- A count changed by an interrupt or dependency can affect subsequent loop conditions.
- Changing the shared location that originally held the count address does not, by itself, replace the saved address used by this loop.

At the start of an eligible iteration, a pagination counter greater than 21 causes:

1. The pagination counter to be reset to 1.
2. F-c7198d86625a to be called with no explicit arguments.
3. Its integer result to be compared against **0x58** and **0x78**.

Either matching result skips the remaining records and transfers directly to summary generation. These values conventionally correspond to uppercase and lowercase “X”; their established significance here is the numeric comparison.

Any other result permits the current record to be processed.

With ordinary returns and no mutation of the record index through reporting, this check occurs before record 22, then before record 43, and so on. It is based on rows processed, not on the numerical value of the record index.

### 3. Per-record prefix measurement

For the current record, the function:

1. Reads the unsigned byte count at offset 24.
2. Initializes the matched-entry count to zero.
3. Reads the entry pointer at offset 20.
4. Scans a matching prefix.

The maximum number of entries considered is the byte count divided by eight, rounded down. A trailing remainder of one through seven bytes is not inspected.

Each candidate entry is evaluated in this order:

1. Check that the matched-entry count remains below the whole-entry limit.
2. Check that the current entry pointer is non-null.
3. Read the entry’s second word and require it to equal zero.
4. Only if the second word is zero, read the first word and require it to equal the saved fill-pattern word.

The scan stops at the first failed condition. A matching entry increments the matched-entry count and advances the pointer by eight bytes. Entries after the first mismatch are not examined.

A null entry pointer produces zero matched entries without an entry-memory read. It is not reported as an error.

The derived byte quantities are:

- **Matching-prefix bytes:** matched-entry count multiplied by eight.
- **Remaining whole-entry bytes:** whole-entry count minus matched-entry count, multiplied by eight.
- **Original bytes:** the unrounded byte count read from the record.

Thus the two derived quantities add to the original byte count rounded down to a multiple of eight, not necessarily to the original byte count.

The whole-entry count cannot exceed 536,870,911 for a 32-bit unsigned byte count. Both byte quantities therefore fit in unsigned 32-bit arithmetic and are multiples of eight, with a maximum of 4,294,967,288.

The remaining-byte quantity is stored in a signed integer temporary. For values exceeding the positive signed range, its subsequent signed interpretation and formatting are not established by this function alone.

### 4. Per-record reporting

After calculating the quantities, the function calls F-a3fdaba172fb with the current record index.

It then calls F-88996a971ccf with a record-report format and these arguments, in order:

1. Address of the record-index variable.
2. The 32-bit value returned by F-a3fdaba172fb.
3. Address of the current record’s field at offset 20.
4. Address of the original-byte-count temporary.
5. Address of the remaining-whole-entry-byte temporary.
6. Address of the matching-prefix-byte temporary.

The offset-20 argument identifies the field containing the entry pointer; it is not simply the entry pointer copied into a by-value argument.

The record field address is formed for this reporting call after F-a3fdaba172fb returns. The exact evaluation order of the individual reporting-call arguments is not independently established.

F-88996a971ccf receives addresses of writable local values, including the loop index. This function does not enforce read-only access. If the dependency changes the index, the loop’s subsequent increment and termination condition use the changed value.

After reporting returns, the pagination counter is incremented, followed by the record-loop increment.

### 5. Final pagination decision

After normal exhaustion of the record loop, the function checks whether the pagination counter is greater than 21.

If so:

1. It issues one more software interrupt with immediate **0x123456**.
2. It calls F-c7198d86625a with two explicit arguments: integer **4** and a prompt object denoting a continuation prompt.
3. It returns immediately if the result is **0x58** or **0x78**.

A different result proceeds to the summary.

If the pagination counter is at most 21, there is no final interrupt or input call.

The early transfer caused by a stop response inside the record loop bypasses this final pagination decision and proceeds directly to the summary.

### 6. Kernel-region summary

The summary begins with an original-byte-count value of **512** and a matched-entry count of zero.

The function obtains the kernel-region address and scans up to **64** consecutive eight-byte entries. Unlike the record scan, this scan has no null-pointer check.

For each entry:

1. Read the second word.
2. Stop if it is nonzero.
3. Otherwise read the first word.
4. Stop if it differs from the saved fill-pattern word.
5. Otherwise increment the matched-entry count and advance by eight bytes.

At least the first entry’s second word is read whenever this summary path is reached, assuming execution reaches that memory access normally.

The reported derived quantities are:

- Matching-prefix bytes: matched-entry count multiplied by eight.
- Remaining bytes: 512 minus matching-prefix bytes.

Both range from zero to 512 and are multiples of eight.

Before reporting, the function obtains the kernel-region address again. F-88996a971ccf receives:

1. A kernel-summary format.
2. Address of a local variable containing that newly obtained region address.
3. Address of the 512-byte total.
4. Address of the remaining-byte quantity.
5. Address of the matching-prefix-byte quantity.

### 7. Additional summary statistics

After the kernel-summary reporting call returns, the function reads the nesting statistic, converts it to an unsigned 32-bit reporting value, and passes its address to F-88996a971ccf with the corresponding format.

The underlying width and signedness of the nesting-statistic object are not established by the supplied declaration context. A 32-bit reporting destination does not prove a 32-bit source read.

After that reporting call returns, the function obtains the signal-list address and counts successive nonzero words until the first zero word. The zero terminator is read but is not included in the count.

The count is accumulated in an unsigned 32-bit value. No explicit maximum length, overflow detection, or independent termination bound is present.

Finally, F-88996a971ccf is called with a signal-list statistic format and the address of that count.

- Two initial software interrupts, plus a possible third interrupt at the final pagination boundary.
- Calls to the pagination, per-record auxiliary, and reporting dependencies.
- Reads of shared configuration, record fields, scanned entries, nesting state, and signal-list words.
- Writes to local counters, pointers, and report values.
- Exposure of writable local addresses to the reporting dependency.
- Exposure of a record’s offset-20 field address to the reporting dependency.

No direct write to record storage, kernel scan storage, or signal-list storage is visible. That does not establish that these objects remain unchanged: dependencies and interrupt handlers have unknown side effects.

There is no visible allocation, explicit release, ownership transfer, or retained-reference protocol. The function does not establish whether dependencies retain addresses or consume ownership. Addresses of local variables are valid during their calls, but their validity after this function returns cannot be promised.

A dependency’s modifications can affect later observations. In particular, the nesting statistic is read after kernel reporting, and the signal list is read after nesting reporting. Those reads must not be treated as a single entry-time snapshot.

## Acceptance examples

These examples are conditional on readable storage, ordinary dependency returns, stable relevant shared state, and a reporting dependency that does not modify the supplied values.

1. **No records.**  
   With a record count of zero, no record lookup or per-record auxiliary call occurs. The two initial interrupts still occur. No final pagination call occurs, and summary generation begins.

2. **Byte count smaller than one entry.**  
   A record byte count of seven produces no entry-memory reads, even with a non-null entry pointer. The original quantity is seven; both derived quantities are zero.

3. **Partial trailing bytes.**  
   A byte count of 19 permits inspection of two entries. If only the first matches, matching-prefix bytes are eight and remaining whole-entry bytes are eight. The final three bytes are excluded from both derived values.

4. **Second-word mismatch.**  
   If the first candidate’s second word is nonzero, the prefix length is zero. That candidate’s first word is not read by the explicit scan.

5. **Null record entry pointer.**  
   A byte count of 24 with a null entry pointer produces zero matching-prefix bytes and 24 remaining whole-entry bytes. The function still attempts record reporting.

6. **Exactly 21 processed records.**  
   No intermediate pagination call occurs. After the loop, the final interrupt and two-argument pagination call occur. A result of 0x78 returns without any summary reporting.

7. **Stop before record 22.**  
   When record 22 would otherwise be eligible, an intermediate pagination result of 0x58 prevents that record and subsequent records from being processed. Kernel and statistic reporting still follow.

8. **Kernel region fully matching.**  
   Sixty-four matching entries produce 512 matching-prefix bytes and zero remaining bytes. No sixty-fifth entry is inspected.

9. **Signal terminator first.**  
   A zero first signal-list word yields a reported count of zero.
