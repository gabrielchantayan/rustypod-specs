# F-2790da281ffe

## Purpose

F-2790da281ffe conditionally transfers a fixed-size byte sequence from an input cursor to a destination associated with a context, records a nonzero context state, and advances the caller’s cursor.

Two consumption lengths are supported:

- Five bytes when the extended-form selector is zero.
- Eight bytes when the extended-form selector is nonzero.

A context byte controls whether payload bytes are copied. A nonzero value suppresses copying but does not suppress length validation, successful cursor advancement, or the final state update.

**Established behavior:** The function returns numeric status `0` on success and `6` when either applicable input-length check fails.

**Inferred intent:** The context byte appears to indicate that a payload has already been captured, allowing subsequent invocations to consume input without replacing it. This interpretation is not required to describe the observable behavior and is not established by caller evidence.

An important property is that an eight-byte request can copy its first five bytes and then fail. Failure is therefore not generally transactional.

## Interface

The interface has four inputs, described here by role rather than implementation identifiers.

| Input | Role |
|---|---|
| Context reference | Identifies storage containing a destination pointer and a one-byte copy-control state. |
| Cursor-slot reference | Identifies a caller-owned slot containing the current input address. The slot is updated only on success, except for possible effects of aliasing. |
| Input-limit address | An address used as the upper boundary for the five-byte and eight-byte availability comparisons. |
| Extended-form selector | A 32-bit integer-like value. Zero selects five-byte consumption; every nonzero value selects eight-byte consumption. |

The result is a 32-bit value containing either `0` or `6`.

### Context layout

The supplied representation establishes these context-relative fields:

| Byte offset | Field | Access |
|---|---|---|
| `0x0c` | Destination-pointer field | Read at entry, before either length check |
| `0x10` | One-byte copy-control state | Read conditionally; written as byte value `1` on success |

No other context fields are explicitly accessed.

The cursor slot is represented as a four-byte cell carrying an address. The context reference and selector are also represented using 32-bit scalar forms. These facts support a 32-bit address-bearing interface interpretation, but a complete platform ABI, pointer representation, and alignment policy are not independently supplied.

Payload elements and the copy-control state are one byte wide. The payload is transferred byte by byte; it is not interpreted as a multibyte integer, string, or structured field.

### Storage requirements

For a well-defined invocation:

- The cursor slot must be readable at entry and writable on success.
- The destination-pointer field must be readable at entry, including on calls that subsequently fail a length check.
- The copy-control byte must be readable whenever execution reaches a copy decision and writable whenever execution reaches successful completion.
- If copying is enabled, the source bytes actually read must be readable and the corresponding destination bytes must be writable.
- Address additions and comparisons must have a meaningful interpretation in the execution environment.

The length checks do not validate that a pointer names accessible memory. A sufficiently large numeric limit does not establish source or destination validity.

No null-pointer checks, destination-capacity checks, allocation checks, or explicit alignment checks are present.

## Behavior

### Entry reads and retained addresses

The function first reads the input address from the cursor slot. It then reads the destination address from the context field at offset `0x0c`.

Both addresses are retained for the remainder of this invocation. The function does not fetch a new destination address after copying the first five bytes, and it does not fetch a new input address from the cursor slot before the final cursor update.

These entry reads occur even when the input later proves too short. The copy-control byte is not read until the initial five-byte check succeeds.

### Initial five-byte requirement

The input-limit address is compared with the retained input address advanced by five bytes.

- If the limit is lower than that address, the function returns `6`.
- Equality passes the check.

On this early-failure path, the function performs no explicit payload writes, no explicit state-byte write, and no explicit cursor-slot write.

For a conventional contiguous-buffer interpretation without address wraparound, this is a requirement for at least five available bytes. The function uses an address comparison rather than a supplied byte-count field.

### Initial copy decision

After the five-byte check passes, the function reads the context byte at offset `0x10`.

- If the byte is zero, the function transfers input offsets `0` through `4` to destination offsets `0` through `4`.
- If the byte is nonzero, it performs no payload-byte reads or writes for this portion.

The enabled transfer proceeds in increasing offset order. At each offset, the source byte is read and the corresponding destination byte is written before the next offset is transferred.

This is an ordered byte transfer, not an operation that first snapshots all five source bytes. Overlapping source and destination ranges can therefore affect later reads.

### Five-byte form

If the extended-form selector is zero, no eight-byte check is made and no tail-copy decision is made.

The successful cursor value is the retained input address advanced by five bytes. Completion then performs the final state and cursor writes described below.

### Eight-byte form

If the selector is nonzero, the function performs a second availability comparison: the input-limit address is compared with the retained input address advanced by eight bytes.

This comparison occurs **after** the initial copy decision and any initial five-byte transfer.

- If the limit is lower than the eight-byte boundary, the function returns `6`.
- Equality passes the check.

Consequently, an eight-byte request with only five, six, or seven available bytes can fail after the first five destination bytes have already been written.

After the eight-byte check passes, the function reads the context copy-control byte again.

- If this new reading is zero, it transfers input offsets `5`, `6`, and `7` to the corresponding destination offsets, in that order.
- If this new reading is nonzero, it skips these payload accesses.

The second decision is based on a fresh read, not on the result of the first decision. This distinction is observable if earlier destination writes alias the state byte. The retained destination address remains in use even if those writes modify the destination-pointer field in the context.

The successful cursor value is the retained input address advanced by eight bytes.

### Successful completion

After all applicable validation and copying, successful completion performs these explicit writes in order:

1. Write byte value `1` to the context copy-control field at offset `0x10`.
2. Write the selected advanced input address to the caller’s cursor slot.
3. Return status `0`.

An initially nonzero state byte is therefore normalized to `1` on success. This applies even when no payload bytes were copied.

The final write order matters when the state byte and cursor slot overlap. In that case, the cursor-slot write follows the state-byte write and may overwrite it.

### Address arithmetic and boundaries

The only cursor increments are five and eight bytes. The visible behavior does not derive a length by subtracting the input address from the limit.

With valid, nonwrapping addresses, a limit exactly at the required boundary is accepted. No terminator, sentinel byte, or payload value participates in validation.

The supplied representation does not establish how overflow, wrapped addresses, or comparisons across unrelated storage regions behave at the complete language-and-platform level. Such cases are not safe acceptance conditions.

## Side effects

### Explicit write sets

| Execution path | Explicit writes |
|---|---|
| Initial five-byte check fails | None |
| Eight-byte check fails after enabled initial copying | Destination offsets `0`–`4` |
| Eight-byte check fails after initial copying is suppressed | None |
| Five-byte success with copying enabled | Destination offsets `0`–`4`, then state byte, then cursor slot |
| Five-byte success with copying suppressed | State byte, then cursor slot |
| Eight-byte success | Any payload writes enabled by the two separate state reads, then state byte, then cursor slot |

Failure does not explicitly advance the cursor or set the state byte. However, destination writes performed before an eight-byte failure may indirectly modify either storage location if they overlap.

### Aliasing

No disjointness check is present.

Observable consequences include:

- Source/destination overlap can change bytes that have not yet been read.
- Initial copying can change the state value used for the tail-copy decision.
- Initial copying can overwrite the caller’s cursor slot without changing the retained input address used by the current invocation.
- Copying can overwrite the context’s destination-pointer field without changing the retained destination address.
- Final cursor publication can overwrite the state byte if their storage overlaps.

Thus, “failure leaves the cursor unchanged” and “success leaves the state byte equal to `1`” hold without qualification only when other writes do not alias those locations.

### Ownership and external effects

No allocation, deallocation, ownership transfer, I/O, callback, or external function call is visible. All explicit accesses are through supplied references and the retained destination address.

The function provides no visible mechanism for releasing either source or destination storage. Their lifetimes remain a caller-side prerequisite.

No synchronization or concurrent-access guarantees are established.

## Acceptance examples

These are conditional acceptance criteria derived from the supplied static representation, not observed runtime results. Unless stated otherwise, assume valid, nonwrapping addresses; disjoint context, cursor, source, and destination storage; adequate destination capacity; and no concurrent modification.

1. **Five-byte success at the exact boundary.**  
   Given a zero selector, a zero state byte, and a limit exactly five bytes beyond the initial cursor, the five input bytes are copied in order. The state becomes `1`, the cursor advances by five, and the result is `0`.

2. **Initial shortage.**  
   Given a limit four bytes beyond the initial cursor, either selector value yields `6`. No payload, state, or cursor writes occur. The cursor slot and destination-pointer field are still read at entry.

3. **Eight-byte success.**  
   Given a nonzero selector, a zero state byte, and exactly eight available bytes, all eight bytes are copied in increasing offset order. The state becomes `1`, the cursor advances by eight, and the result is `0`.

4. **Eight-byte shortage with a partial destination update.**  
   Given a nonzero selector, a zero state byte, and six available bytes, destination offsets `0`–`4` receive the first five source bytes. The result is `6`; destination offsets `5`–`7`, the state byte, and the cursor slot are not explicitly written.

5. **Copy suppression still consumes input.**  
   Given an initial state byte of `9`, a nonzero selector, and eight available bytes, no payload bytes are read or written. The state is written as `1`, the cursor advances by eight, and the result is `0`.

6. **Copy suppression does not bypass validation.**  
   Given a nonzero state byte, a nonzero selector, and seven available bytes, the function returns `6` without payload writes or explicit state/cursor updates.

7. **Forward overlap is not a snapshot copy.**  
   Given enabled five-byte copying and a destination beginning one byte after the source, each write replaces the next source byte before it is read. All five destination bytes consequently receive the original first source byte.

8. **A changed state can suppress the tail.**  
   Given an eight-byte request whose initial destination writes overlap the state byte, if those writes change the state from zero to nonzero before the second state read, the first five bytes are transferred but offsets `5`–`7` are skipped. With the eight-byte check satisfied, the call still advances by eight and returns `0`.
