# F-1aa1b16e0230

## Purpose

The supplied representation establishes the report’s construction order and the state fields it reads. It does not establish complete rendered text, output framing, the behavior of the arithmetic dependency, or the contents of the trailing item.

The apparent intent is to express light- and deep-sleep durations as percentages of a logged interval. That interpretation is inferred from the format-object labels and arithmetic, not independently verified.

## Behavior

### Temporary storage initialization

The third and fourth arguments are copied, in that order, into two successive four-byte words of local working storage. The address of the first word is passed to F-5b24edfb22c0.

This initialization call precedes all state-field reads used for percentage computation. Consequently, if the initializer changes shared state or the state object indirectly, the subsequent reads can observe those changes. Its side effects are not constrained by the supplied evidence.

The two words establish an eight-byte initial storage image. They do not establish a character-buffer capacity, an allocation size, or the complete storage requirements of the helper family.

### Percentage calculation

After initialization, the function reads:

1. The four-byte endpoint at offset `0x20`.
2. The four-byte endpoint at offset `0x1C`.

These endpoint values are retained for both percentage calculations. They are not visibly reloaded later.

If the two values are equal, both percentage result words are set to zero. Neither call to F-d7be9cfb4000 occurs in this branch. The duration fields are not read for percentage calculation in this branch, although they are still read later for report formatting.

If the endpoint values differ:

- The function reads the duration at offset `0x58`, multiplies it by 100 using the represented integer arithmetic, and calls F-d7be9cfb4000 with that product and the difference between the retained endpoint values.
- It retains the returned 32-bit value as the light-sleep percentage result.
- It then reads the duration at offset `0x64`, multiplies it by 100, and calls F-d7be9cfb4000 with that product and the same endpoint difference.
- It retains that returned 32-bit value as the deep-sleep percentage result.

The first arithmetic call therefore occurs before the deep-sleep duration read. A side effect of that call can affect the deep-sleep duration subsequently observed.

The denominator is the value at offset `0x20` minus the value at offset `0x1C`, not an absolute difference. No check requires chronological ordering, nonnegative durations, durations bounded by the interval, or a combined duration within the interval.

F-d7be9cfb4000 is consistent with an integer division operation, but its exact contract is not supplied. Rounding, signedness handling, exceptional inputs, and result conventions remain dependency-defined.

## Acceptance examples

These are conditional behavioral examples, not executed tests.

### Equal endpoints

- F-d7be9cfb4000 is not called.
- Both percentage-formatting calls receive a zero result word.
- Duration formatting still uses fresh reads from offsets `0x58` and `0x64`.
- All eight emissions still occur in the specified order.

Nonzero durations do not alter this branch decision.

### Ordinary percentages under a division contract

Suppose the retained endpoints are 1,000 and 1,200 at offsets `0x1C` and `0x20`, respectively, and the initial duration reads are 50 and 100.

The two arithmetic calls receive:

- 5,000 and 200.
- 10,000 and 200.

If F-d7be9cfb4000 performs ordinary integer division for these inputs, the retained results are 25 and 50. Those result words are supplied to the corresponding percentage-formatting calls. Exact displayed text remains dependent on the unavailable formats and formatter behavior.

### Mutation between calculation and display

Suppose the light-sleep duration is 50 during percentage calculation and becomes 60 during heading emission.

The light-sleep percentage remains based on the earlier value of 50. The light-sleep duration-formatting call receives the later value of 60. Recomputing the percentage during report emission would not match the established ordering.

### Mutation during the first arithmetic call

If the first F-d7be9cfb4000 call changes the deep-sleep duration, the subsequent deep-sleep percentage calculation uses the changed value. It still uses the already retained endpoint values.

### Reversed endpoints

The arithmetic dependency receives the represented subtraction result; subsequent numeric meaning is subject to the arithmetic uncertainties below.
