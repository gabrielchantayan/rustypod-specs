# F-9b6b8609de5c

## Purpose

F-9b6b8609de5c conditionally replaces an entry in, or appends an entry to, a collection referenced by an enclosing object.

The supplied static representation establishes this selection rule:

- If the object’s collection-reference field is zero on entry, obtain and store a collection reference, then construct and append an entry without searching.
- Otherwise, examine collection positions in ascending order. Replace the first examined entry whose extracted 32-bit key equals the requested key.
- If the search finishes without a match, construct and append an entry.

The function returns the 32-bit value **1** after either an append or a replacement completes normally. This is not an independently validated success result: no dependency result is checked for failure.

“Collection,” “entry,” “key,” and “replacement” describe the apparent roles of the operations. The dependencies’ internal representations, ownership rules, and success guarantees are not supplied.

No type, range, nullability, encoding, or ownership constraints for the two construction values are established. Either could represent a scalar, flags, or a reference; the body does not distinguish these possibilities.

### Object and entry layout

The only directly established enclosing-object layout is:

| Byte offset | Width | Use |
|---|---:|---|
| 12 | 4 bytes | Collection reference or handle; zero selects the initialization path. |

No enclosing-object size beyond the accessibility of this field is established. No other object fields are directly read or written.

An indexed-access dependency returns an address. The function reads the **first 4 bytes at that address** and supplies that value to the key-extraction dependency. On a matching key, it also passes the indexed-access address itself to a separate dependency.

Thus, two distinct values matter:

- The address returned by indexed access.
- The 32-bit value stored at that address.

They must not be treated as interchangeable.

### Output

There is no visible return of the created entry, collection reference, replaced value, or failure code. Abnormal termination, exceptions, traps, or non-returning behavior of dependencies are not specified.

## Behavior

### Initial collection decision

The function reads the 32-bit collection-reference field at object offset 12.

If that value is zero, it calls **F-c141a8d8555e** with no arguments and stores the returned 32-bit value into the collection-reference field. The store occurs before entry construction and insertion.

This branch does not inspect the resulting collection’s count or contents. In particular, even if the dependency returns a reference to a nonempty collection, the function proceeds directly to construction and append. It does not search that collection for an existing matching key.

The returned collection value is not checked for zero or any other failure representation.

If the collection-reference field is initially nonzero, the function instead enters the search described below.

### Search order and termination

The search begins with a signed 32-bit position of zero.

Before each potential entry access, including the check that terminates an ordinary unsuccessful search, the function:

1. Reads the current collection-reference field.
2. Calls **F-10b760faca36** with that value.
3. Interprets its result as a signed 32-bit bound.
4. Continues only if the current position is less than that bound under signed comparison.

The bound is not captured once at search entry. It is obtained again at every condition check. Consequently, the visible behavior depends on successive bound results, not necessarily on an initial snapshot of collection size.

When the condition permits an entry access, the function reads the collection-reference field again and calls **F-6bbddce1b930** with that value and the current position.

The separate field reads are significant. If a dependency or another actor changes the field, the count operation and indexed access need not receive the same collection reference.

The function then:

- Reads the 32-bit value at the address returned by indexed access.
- Passes that value to **F-2eb743f270d1**.
- Compares the returned 32-bit integer with the requested key for exact equality.

If the keys differ, the position increases by one and the next condition check occurs.

There is no explicit iteration limit beyond the repeatedly obtained signed bound. A collection that grows during traversal can extend the search. A bound that becomes zero, negative, or no greater than the current position stops it at the next check.

The signed position increment has no explicit overflow handling. Behavior requiring increment beyond the maximum signed 32-bit value is not established by the supplied representation.

### Matching-entry path

The first examined entry whose extracted key equals the requested key selects the replacement path.

The following ordering is established:

1. Call **F-5d1b5e970d51** with the indexed-access address for the matching entry.
2. After that call returns, call **F-610221d5244d** with the requested key, construction value A, and construction value B.
3. Read the current collection-reference field.
4. Call **F-c2674fa3e73d** with that collection reference, the matching position, and the 32-bit construction result.
5. Return **1**, provided the calls return normally.

No later entries are examined. If multiple entries have matching keys, only the first match encountered during this traversal selects a replacement.

The first dependency call precedes construction. It is not established whether this call releases an entry, destroys a value, resets a slot, or performs another operation. Whatever its effect, the function provides no visible rollback if construction subsequently fails or does not return.

The collection reference supplied to replacement is obtained after both the matching-entry operation and construction. It is not guaranteed to be the collection reference used to obtain the matching address. The saved position is reused without another count check or another key check.

### Append path

The append path is reached in either of two cases:

- The collection-reference field was initially zero and initialization has completed.
- The nonzero-field search ended without selecting a match.

The function then:

1. Calls **F-610221d5244d** with the requested key and the two construction values.
2. Reads the current collection-reference field.
3. Calls **F-754616bec4de** with that reference and the 32-bit construction result.
4. Returns **1**, provided the calls return normally.

No matching-entry operation is invoked on this path. There is no post-construction validation and no confirmation that insertion occurred.

### Integer and value handling

The directly visible data operations use 32-bit values:

- Zero testing of the collection-reference field.
- Entry-content reads.
- Requested-key comparison.
- Construction inputs and result.
- Search position and bound.
- Normal return value.

Key matching is exact equality; there is no visible masking, narrowing, normalization, or range conversion.

The search bound is used as signed. A result whose high bit is set is therefore negative in the supplied representation and does not admit position zero. It must not be described as an unsigned large collection size.

## Side effects

### Direct effects

The only explicit memory write in the body is the initialization-path write to the collection-reference field at object offset 12.

The function directly reads:

- That collection-reference field at the points described above.
- The first 4 bytes at each indexed-access address reached by the search.

No direct write to an indexed entry is visible.

### Dependency-mediated effects

Collection creation, indexed replacement, append, entry construction, and the operation on a matching entry are delegated. Their memory allocation, mutation, resource handling, global-state effects, and failure behavior are unknown.

The function’s call sequence does not establish ownership transfer. Specifically:

- The construction result is passed to append or replacement, but acceptance or ownership acquisition is not verified.
- The matching-entry address is passed to F-5d1b5e970d51, but release or destruction is not proven.
- No direct deallocation appears.
- No recovery path is visible for an uninserted construction result.

Dependencies must not be assumed to preserve the collection-reference field, other memory, or global state. The repeated field reads make some such changes observable, but do not make mutation safe.

There is no visible transaction, locking, exception handling, or rollback.

## Acceptance examples

These are conditional static acceptance scenarios, not executed tests. Unless a scenario states otherwise, dependencies return normally and do not mutate relevant state unexpectedly.

### Initially absent collection

Given an initially zero collection-reference field:

- F-c141a8d8555e is called once.
- Its result is stored in the field before construction.
- No count, indexed-access, key-extraction, or matching-entry operation occurs.
- One construction call precedes one append call.
- Normal return is **1**.

This remains the selected path even if the initialized collection already contains a matching key.

### Existing collection with zero or negative bound

Given an initially nonzero field and a first bound result of zero or a negative signed value:

- The count dependency is called once.
- No entry is accessed.
- Construction and append follow.
- Normal return is **1**.

### First entry matches

Given a positive first bound and a matching key at position zero:

- Position zero is accessed and its first 4-byte value is used for key extraction.
- F-5d1b5e970d51 receives the indexed-access address.
- Construction occurs after that call.
- Replacement receives position zero and the construction result.
- Append is not called, and position one is not examined.

### Later match with duplicates

Given stable bounds and matching keys at positions two and four, with no earlier match:

- Positions zero, one, and two are examined in order.
- Position two selects replacement.
- Position four is not examined.
- Only the selected matching address is passed to F-5d1b5e970d51.

### Stable unsuccessful search

Given a stable nonnegative bound of three and no matching key:

- Bound queries occur before positions zero, one, and two, and once more before termination at position three.
- Three indexed accesses and three key extractions occur.
- No matching-entry operation or replacement occurs.
- One construction and one append follow.

### Collection reference changes during construction

Given that construction changes the enclosing object’s collection-reference field:

- Append uses the field value read after construction on the append path.
- Replacement likewise uses the field value read after construction, while retaining the previously selected position.

Whether that combination is valid for the newly referenced collection is unknown.

### Zero initialization result

Given that initialization returns zero normally:

- Zero is stored in the field.
- The function does not reject it or retry initialization.
- Construction is attempted, followed by append using the field’s then-current value.

A successful insertion cannot be inferred from this call sequence.
