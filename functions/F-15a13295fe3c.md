# F-15a13295fe3c

## Purpose

F-15a13295fe3c returns a masked unsigned value associated with an optional object. Its behavior has three cases:

- An absent object produces the caller’s mask restricted to its low eight bits.
- A present object with a zero control byte supplies a 32-bit value to be filtered by the caller’s mask.
- A present object with a nonzero control byte triggers F-a061acf353ed, clears that control byte, and supplies a 32-bit value to be filtered by the fixed mask `0x00000007`.

The dependency invocation precedes both the explicit control-byte clear and the value read. Consequently, the returned value can reflect changes made by the dependency.

This is a static behavioral contract. “Control byte,” “value field,” and “mask” describe observed roles, not established application-level meanings. No runtime tests have been performed.

## Interface

### Inputs

The function accepts two inputs:

| Input | Representation and role |
|---|---|
| Object address | An integer-represented address. Zero selects the absent-object path; a nonzero value selects object-relative memory access. |
| Caller mask | An unsigned 32-bit value used in a bitwise AND, except that the nonzero-control-byte path replaces its contribution with the fixed mask `0x00000007`. |

The supplied representation uses integer and unsigned-integer types consistent with a 32-bit target model. Under that model, the object-address input occupies 32 bits and the mask occupies 32 bits. An independent target ABI declaration is not supplied; its absence is documented under uncertainties.

The function does not accept a buffer length, object size, ownership token, or explicit error-output argument.

### Object layout

Only two object-relative locations are established:

| Byte offset from the supplied address | Access width | Observed role |
|---|---:|---|
| `0x18` | 32 bits | Value read for the result on every normally completing present-object path. |
| `0x1E` | 8 bits | Control byte read to select behavior, and explicitly cleared after the dependency returns on the nonzero branch. |

These regions do not overlap. Their contents are not established as independent application-level fields merely because the accesses are separate.

No enclosing structure, total object size, packing rule, or byte order is established. The 32-bit read is a target-native unsigned load; it is not an explicitly byte-assembled or byte-swapped operation.

### Output

The result is an unsigned 32-bit value:

- Absent object: caller mask AND `0x000000FF`.
- Present object with an initially zero control byte: loaded value AND caller mask.
- Present object with an initially nonzero control byte: loaded value AND `0x00000007`, with the load occurring after the dependency returns and the explicit control-byte clear completes.

The result is not established as an error code or Boolean. In particular, the absent-object result is not an unconditional `0xFF` sentinel.

### Preconditions

Normal completion of a present-object call requires the applicable memory accesses to be valid:

- The control byte must be readable.
- The 32-bit value field must be readable when its later load occurs.
- On the nonzero-control-byte path, the control byte must remain writable after the dependency returns.

The address calculations and accesses must satisfy the target’s address-range and alignment requirements. The function performs no visible validation beyond checking whether the supplied object address is zero.

## Behavior

### Absent object

When the object address is zero, the function does not access either object-relative location and does not invoke F-a061acf353ed.

It uses `0x000000FF` as the value to filter, then returns that value AND the caller mask. Thus, the returned bits are precisely the caller mask’s bits numbered zero through seven. All higher bits are zero.

This path does not require valid storage corresponding to the object-relative offsets because it never accesses them.

### Present object with a zero control byte

For a nonzero object address, the first explicit object-memory access is the one-byte read at offset `0x1E`.

If that read yields zero:

1. F-a061acf353ed is not invoked.
2. This function does not explicitly write the control byte.
3. It reads the unsigned 32-bit value at offset `0x18`.
4. It returns that value AND the caller mask.

No second control-byte read is visible. If external activity changes the control byte after the initial read, the function does not visibly reconsider its branch decision.

A zero caller mask does not suppress the value-field read. The control decision and value load still occur on this path before the result becomes zero through masking.

### Present object with a nonzero control byte

Any nonzero eight-bit control value selects this path. No specific nonzero value is distinguished.

The observable operations explicitly attributable to this function occur in this order:

1. Read the control byte at offset `0x1E`.
2. Invoke F-a061acf353ed with the supplied object address, numeric argument `7`, and numeric argument `0`, in that argument order.
3. After the dependency returns normally, select `0x00000007` as the effective result mask.
4. Store a zero byte at offset `0x1E`.
5. Read the unsigned 32-bit value at offset `0x18`.
6. Return the loaded value AND `0x00000007`.

The original caller mask does not constrain the result on this path. Even a caller mask of zero can therefore accompany a nonzero result.

The dependency’s return value, if any, is not used. The supplied function contains no visible check for success, failure, or an error indication from the dependency. If the dependency returns normally, the explicit clear and subsequent value read proceed without a return-value-dependent branch.

The control-byte clear occurs after the dependency invocation. The function therefore does not clear the triggering byte before calling the dependency. If the dependency itself changes that byte and returns with the storage still accessible, the explicit zero-byte store overwrites its resulting contents.

The value field is read after the dependency invocation rather than saved beforehand. A dependency modification to that field can consequently affect the result. Nothing in this function restores an earlier value.

### Arithmetic and bit boundaries

The result operation is bitwise AND, not addition, multiplication, shifting, or a range clamp.

On the nonzero-control-byte path, only result bits zero through two can be set, so the unsigned result is in the inclusive range zero through seven. On the absent-object path, only bits zero through seven can be set, so the result is between zero and 255 inclusive. The zero-control-byte path has no narrower bound than unsigned 32-bit masking permits.

The object offsets are byte offsets. No index scaling, length computation, or bounds check is visible. The supplied representation does not establish defined behavior for invalid, wrapping, or otherwise unusable address calculations.

## Side effects

The only explicit memory write performed by F-15a13295fe3c is the zero-byte store at object offset `0x1E`, and it occurs only on the initially nonzero-control-byte path after F-a061acf353ed returns.

The function itself has no visible allocation, release, global-memory access, I/O, or synchronization operation. This observation does not constrain effects inside F-a061acf353ed.

The dependency receives the object address. Its access to object memory, global state, external resources, or other storage is unknown. The contract does not assume that it preserves globals, preserves the value field, or leaves the object allocated.

No ownership transfer is established by the call. Equally, the absence of a visible release in this function does not establish that the dependency cannot release storage. If the dependency invalidates the object address, the subsequent explicit store and load still appear in the supplied behavior; safe completion is then not established.

Repeated calls can take different paths because a normally completing triggered call clears the control byte. A later call will skip the dependency if its control-byte read sees zero. This is conditional on no intervening change, dependency effect, concurrent activity, or lifetime violation altering the relevant state.
