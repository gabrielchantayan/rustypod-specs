# F-6b395eb2339c

## Purpose

F-6b395eb2339c scans a bounded sequence of 16-bit units, accumulates a decimal value, and optionally classifies the remaining suffix through two dependencies.

The numeric prefix is not a conventional signed-integer grammar. Decimal digits contribute to the value; a minus unit sets the sign to negative wherever it appears before the suffix. Repeated minus units do not alternate the sign. The first unit that is neither a decimal digit nor a minus begins the suffix. That unit is included in the suffix rather than discarded.

The function produces two caller-visible outputs:

- A 32-bit classification value, initially set to zero.
- A 32-bit numeric value, written when scanning stops.

If a suffix exists, the function prepares a temporary context and tries up to seven classification candidates in order. The first dependency result that is nonzero selects its zero-based candidate index. Consequently, classification zero is ambiguous: it can represent no suffix, no successful candidate, or a successful candidate at index zero.

These are static behavioral observations. The suffix’s domain meaning, candidate contents, and dependency semantics are not established.

## Interface

The function has four inputs and no explicit return value:

| Input | Role and required layout |
|---|---|
| Range descriptor | Address of a readable descriptor containing two consecutive 32-bit words. The first is interpreted as the beginning address of a 16-bit-unit sequence; the second as its exclusive ending address. |
| Classification destination | Address of a writable 32-bit integer. Receives an initial zero and, on a successful suffix comparison, a candidate index from zero through six. |
| Numeric destination | Address of a writable 32-bit integer. Receives the signed accumulated value before any suffix processing. Its address is also supplied indirectly to the dependencies. |
| Auxiliary value | An opaque 32-bit value forwarded through a temporary context when a suffix exists. It is not otherwise interpreted here. |

The supplied representation uses 32-bit words for addresses and pointer-bearing fields. This supports a 32-bit address-model interpretation; portability to a different pointer width is not established.

The scanned elements are unsigned 16-bit units, not bytes. The function does not determine their encoding, validate Unicode, or search for a terminator. Only the units with values 0x002D and 0x0030 through 0x0039 receive numeric-prefix treatment.

For defined, ordinary use:

- The descriptor and output destinations must be valid for their stated accesses.
- The beginning and exclusive ending addresses must describe a readable, forward-traversable sequence of 16-bit units.
- The ending address must be reachable by advancing the beginning address in two-byte increments, unless scanning encounters a suffix earlier.
- Arithmetic must remain within the supported signed 32-bit range if a portable numeric result is required.
- When a suffix is present, the dependencies and seven candidate words must be usable.

No explicit validation enforces these requirements. Descriptor/output aliasing is not rejected, but it can change the effective input and observed outputs because reads and writes occur in a particular order.

No ownership transfer is explicit in this function. It neither visibly allocates nor visibly releases storage. Dependency ownership and lifetime requirements remain unknown.

## Behavior

### Entry and scan initialization

The first caller-visible action is a 32-bit zero write to the classification destination.

Only after that write does the function obtain the beginning address from the descriptor. Thus, if the classification destination overlaps the descriptor’s beginning word, initialization can alter the beginning address before it is read.

The numeric accumulator starts at zero, the sign starts positive, and no suffix is initially recorded. The numeric destination is not initialized at entry; its first direct write occurs when scanning stops.

### Range termination and read order

At each scan boundary, the current address is compared with the descriptor’s current ending address. The ending word is read again rather than being retained as one immutable snapshot for the whole scan.

The same boundary check also determines whether a suffix has already been recorded. Either reaching the ending address or having recorded a suffix ends numeric scanning.

The ending-address comparison precedes the suffix-presence check. Consequently, after the first suffix unit is encountered, the next boundary still reads the descriptor’s ending word before entering completion processing.

The range test is equality, not an ordered bounds test. The function does not reject a beginning address greater than the ending address, a mismatched alignment, or an ending address that cannot be reached by two-byte increments.

For an empty range, no input unit is read. The function writes numeric zero and returns without invoking either dependency.

### Numeric-prefix rules

While scanning remains active, the current 16-bit unit determines the action:

- A decimal digit from 0x0030 through 0x0039 extends the accumulated decimal magnitude.
- A minus unit, 0x002D, sets the sign to negative without changing the magnitude.
- Every other unit establishes the beginning of the suffix.

For a digit with value \(d\), the intended recurrence is:

\[
A_{\text{next}} = 10A + d,\qquad 0 \le d \le 9.
\]

The sign does not participate in this recurrence. The magnitude is accumulated independently, and the sign is applied only when the numeric destination is written.

A minus is accepted at any position before the suffix, including between digits or after the last digit. Multiple minus units leave the sign negative. There is no positive-sign counterpart: a plus unit begins the suffix.

The function advances the scanning address by one 16-bit unit after each processed unit, including the unit that first establishes the suffix. The saved suffix address remains the address of that unit, so the suffix dependency receives the unrecognized unit as part of its range.

The supplied representation includes a further current-unit read in the digit accumulation expression after the unit has been classified as a digit. Under stable input, both reads observe the same unit. There is no synchronization or snapshot mechanism establishing behavior for concurrently changing input.

### Numeric completion

When scanning stops, the function writes the sign multiplied by the accumulated magnitude to the numeric destination.

This write occurs for both termination conditions:

- The scan reaches the exclusive ending address without finding a suffix.
- A suffix has been recorded.

If there is no suffix, the function then returns. It does not invoke the dependencies or consult the candidate table.

If no digits were encountered, the value written is zero, including when one or more minus units were consumed.

The accumulator and sign are represented as signed 32-bit quantities. No overflow check, saturation, error flag, or wider accumulation is visible. The supplied representation alone does not establish a portable result for overflowing multiplication, addition, or final sign application. In particular, the ability to return a negative value does not establish that the magnitude of the minimum signed 32-bit value can be accumulated safely.

### Suffix preparation and classification

When a suffix exists, the numeric write happens before suffix preparation.

The function creates a temporary context with two initial 32-bit fields:

1. The address of the numeric destination.
2. The auxiliary value.

It calls F-3bb948305a79 with:

- The address of this temporary context.
- The saved suffix-beginning address.
- A newly read ending-address word from the descriptor.

The ending address passed here is not necessarily identical to an earlier observed ending address if aliased storage or external mutation has changed it. In particular, writing the numeric destination can affect this argument if that destination overlaps the descriptor’s ending word.

After F-3bb948305a79 returns, the function reads the global candidate-table base. It then considers seven entries, in index order zero through six. Each entry is a 32-bit word at a four-byte stride.

For each candidate, it calls F-a1e68ae27737 with the temporary context address and that candidate word.

- A zero result continues to the next candidate.
- Any nonzero result causes the function to write that candidate’s zero-based index to the classification destination and return immediately.
- If all seven results are zero, the function returns without another direct classification write.

The candidate-table base is obtained after suffix preparation and retained for the comparison loop. Individual candidate words are obtained as their comparisons are reached. The function does not copy the seven entries into a private snapshot.

No direct numeric write follows the dependency calls. However, the temporary context initially contains the numeric destination’s address, so its entry value is not guaranteed to remain the final value after suffix processing.

## Side effects

The directly established caller-visible writes are:

1. Zero to the classification destination at entry.
2. The signed accumulated value to the numeric destination when scanning stops.
3. A candidate index to the classification destination if a comparison succeeds.

The order is significant. If both output destinations are the same address, the numeric write replaces the initial classification zero. A subsequent successful comparison replaces that numeric value with its index. If no comparison succeeds, there is no final direct classification write to restore zero.

The function also writes its temporary context before calling the dependencies. That context is local to the invocation. Its address does not establish permission for a dependency to retain it after return.

The direct body contains no explicit writes to the input sequence or descriptor and no explicit update to the global candidate-table base. This does not prove those objects are preserved across dependency calls. Dependency effects through aliases, context contents, or global state are unknown.

There is no explicit error return, parse-success flag, exception handling, diagnostic output, or recovery path. An unrecognized unit is handled as a suffix boundary, not directly reported as an error. Invalid memory and arithmetic overflow have no specified recovery behavior.
