# F-0948a2604051

## Purpose

F-0948a2604051 obtains a context value, requests storage, delegates object initialization, and conditionally configures the returned object according to a selector byte in an input record.

Two selector values have explicit configurations:

- **1:** twelve ordered registrations, including ten digit identifiers.
- **2:** twenty-three ordered registrations, including ten digit identifiers and eight identifiers with a nonzero registration attribute.

Other selector outcomes return the initialized object without these additional writes or registrations.

The identifiers resemble character codes, and the registrations resemble resource-backed display entries. That interpretation is inferred intent, not an established dependency contract. The established behavior is the argument values, call ordering, memory accesses, and return value described below.

## Behavior

### Initial preparation and context selection

The following ordering is established:

1. F-6a4ff3d72a41 receives the fourth input and an address to temporary storage.
2. The 32-bit field at input-record offset `0x60` is read.
3. F-ccabec065f5e receives that field value and an address to a separate temporary output region.
4. The first 32-bit output word from that region determines context selection.

If that output word is zero, F-9d0ecc5f6adf is called, and its result becomes the context value.

If that output word is nonzero, it is passed to F-283eda65a14c:

- A null result selects a context value of zero.
- A nonnull result is treated as an object with a dispatch-table pointer in its first 32-bit word. The callable entry at dispatch-table byte offset `0x14` is invoked with the object and the integer 5. Its return value becomes the context value.

The null-result case does **not** call F-9d0ecc5f6adf as a fallback at this stage.

### Temporary state and initialization

After context selection, the function copies a second 32-bit word from the output region used by F-ccabec065f5e into another temporary word. It also reads a 32-bit global value, called **G-initialization** here, and stores it in a separate temporary word.

The supplied representation places these two destination words immediately after the four-byte temporary region passed to F-6a4ff3d72a41. Their relationship to a larger aggregate is not fully established; see **Uncertainties**.

F-8157a180d901 is then called with the requested size `0x2AC`.

F-27534e124406 receives, in order:

1. The storage-provider result.
2. The selected context value.
3. The second input.
4. The third input.
5. The address of the temporary region originally supplied to F-6a4ff3d72a41.
6. The fourth input.

Its result is the eventual return value and the target of subsequent configuration.

### Post-initialization context and selector reads

After initialization, F-9d0ecc5f6adf is called unconditionally. Its result supplies the first argument for later resource-resolution calls.

A second global 32-bit value, **G-resource-domain**, is then read and retained for use as the second argument to those calls.

Only after these operations does the function read the selector byte at input-record offset `0x64`.

- If the first selector read equals 1, the mode-1 path is selected.
- Otherwise, the selector byte is read again. If this second read equals 2, the mode-2 path is selected.
- Otherwise, the initializer result is returned immediately.

Consequently, even an unconfigured path performs the post-initialization F-9d0ecc5f6adf call and the G-resource-domain read.

The two selector reads must not be collapsed into an assumption that the record is immutable. If the first read is not 1 and the second is 2, mode 2 is selected. If the first read is not 1 and the second is 1, neither configured path is selected.

No direct release operation or rollback is visible. Storage ownership, resource ownership, retention of temporary addresses, and cleanup responsibilities are not established. In particular, the function does not establish whether F-27534e124406 takes ownership of the storage-provider result or whether registrations retain or copy resolver results.

Registration return values are ignored. No explicit failure-dependent interruption occurs between registrations. A dependency that fails to return normally can still prevent completion; its behavior is outside the visible contract.

Global values are read at separate times:

- G-initialization after context selection.
- G-resource-domain after the unconditional post-initialization context call.
- G-configuration after the configured-path byte write.
- Each resource key immediately before its corresponding resolution.

Unknown callees must not be assumed to preserve those globals. Conversely, the retained context and resource-domain values are reused rather than reacquired for every registration.

## Acceptance examples

These are conditional acceptance criteria derived from static evidence, not executed tests. Each assumes dependencies return normally and required memory accesses are valid.

1. **Zero context-selection output.** If the first output word from F-ccabec065f5e is zero, F-9d0ecc5f6adf supplies the initialization context. It is called again after initialization; the two results need not match.

2. **Unresolved nonzero context-selection output.** If that word is nonzero and F-283eda65a14c returns null, initialization receives context zero. There is no pre-initialization fallback call to F-9d0ecc5f6adf.

3. **Resolved context-selection output.** A nonnull resolved object causes the dispatch entry at offset `0x14` to be invoked with that object and 5. The invocation result is forwarded as the initialization context.

4. **Stable selector 1.** The object receives the byte write and configuration call, followed by exactly twelve resolver/registration pairs in mode-1 order. Identifier `0x31` uses parameter B `0x20`, unlike the other digit entries.

5. **Stable selector 2.** The object receives twenty-three registrations. Entries `0x61`–`0x68` use attribute 2. The final `0x20` entry uses payload zero without a resolver call.

6. **Stable unsupported selector.** For a stable selector such as 0 or 3, neither configured-path object write nor registration occurs. Initialization and the unconditional post-initialization context call still occur.

7. **Changing selector.** A first read of 3 followed by 2 selects mode 2. A first read of 3 followed by 1 returns without configuration.

8. **Distinct storage and initializer results.** If the two dependencies return different addresses, all later object accesses and the final return use the initializer result.

9. **Mutable resource keys.** If an earlier dependency changes a later entry’s global key before that key is read, the later resolution receives the changed value. Preloading all keys would not preserve the observed read order.
