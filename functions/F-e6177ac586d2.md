# F-e6177ac586d2

## Purpose

F-e6177ac586d2 conditionally updates two adjacent 32-bit fields in an indirectly referenced object, then invokes a dependency when an update is required.

Before comparing either field, it passes writable copies of the third and fourth arguments to F-08fb88178805. The resulting values, rather than necessarily the original arguments, determine whether an update occurs and what values are written.

The established behavior is a comparison-and-update operation with a subsequent dependency call. Interpreting the fields as coordinates, dimensions, cached settings, or another application-level pair is not supported by the available evidence. Likewise, the final dependency may be a notification or refresh operation, but that purpose is inferred rather than established.

## Behavior

### Preparation and transformation

The function first creates two independent writable 32-bit temporaries:

- one initialized from the third argument;
- one initialized from the fourth argument.

It then invokes F-08fb88178805 with pointers to those temporaries. Argument order is significant: the temporary initialized from the fourth argument is passed first, and the temporary initialized from the third argument is passed second.

For the remainder of this contract:

- **first candidate** means the post-call value of the temporary initialized from the fourth argument;
- **second candidate** means the post-call value of the temporary initialized from the third argument.

These names describe their destination-field order, not the original argument order.

The dependency is invoked on every normal invocation of F-e6177ac586d2, including invocations that ultimately perform no field writes. There is no preliminary check that could skip it.

The dependency’s transformation is unknown. It must not be assumed to preserve, swap, clamp, sort, validate, or otherwise normalize the supplied values. The function uses whatever values are present in the two temporaries after the dependency returns.

### Comparison

Only after F-08fb88178805 returns does the function read the root-reference slot at offset `0xF00`.

It retains that address for the comparison and the first possible write. It reads the first field at offset `0xB7C` from that referenced object and compares it with the first candidate.

The second comparison is conditional:

- If the first field differs from the first candidate, the function commits to the update path without reading the second field for comparison.
- If the first field matches, the function reads the second field at offset `0xB80` from the same retained object address and compares it with the second candidate.

Thus, a mismatch in the first field suppresses the second field’s comparison read. It does not suppress the later write to that field.

If both fields match their respective candidates, the function returns without either field write and without invoking F-e0ba31379901. Any effects already caused by F-08fb88178805 remain possible.

### Update and final dependency call

If either comparison establishes a mismatch, the function performs both field writes. It does not limit the write to the field that differed.

The observable order is:

1. Write the first candidate to offset `0xB7C` of the object whose address was retained for comparison.
2. Read the root-reference slot again.
3. Write the second candidate to offset `0xB80` of the object identified by that fresh reference.
4. Read the root-reference slot again.
5. Invoke F-e0ba31379901 with that most recently read 32-bit reference.

These repeated reads are part of the contract. The second write and the final dependency call are not required by the supplied body to use the same reference as the comparison or first write.

Under a stable, non-overlapping memory layout with no intervening mutation, all three references identify the same object. Under aliasing or external mutation, they may differ. In particular, if the first field write overlaps the root-reference slot, it can change the destination used for the second write. If the second write changes that slot, the final dependency can receive a different reference again.

The function does not recheck either field after writing. It also performs no visible verification after F-e0ba31379901 returns.
