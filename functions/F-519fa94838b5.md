# F-519fa94838b5

## Purpose

F-519fa94838b5 conditionally processes an object and a signed integer selection. On its ordinary path, it either rejects the request with −1 or returns an effective selection after a conditional sequence of dependency calls.

Three decisions govern processing:

- A character-sized conversion of an object control field can divert execution to a special handler followed by a dependency annotated as non-returning.
- Selection 2,147,483,647, combined with a positive object count, selects count minus one without validation.
- Every other ordinary request requires a nonzero validator result.

For an accepted effective selection other than −1, the function conditionally invokes one indirect dependency, then invokes a second indirect dependency and a final direct dependency.

“Selection,” “count,” and “range” are descriptive terms for the observed arithmetic and call arguments. The supplied body does not establish an application-level operation such as removal, resizing, notification, or ownership transfer.

## Interface

### Inputs and preconditions

The function receives:

1. **An object address**, used to access integer-sized fields and an indirect-dispatch table.
2. **A signed integer selection**, initially used unchanged.

There are no explicit checks for a null object, insufficient storage, invalid alignment, an invalid dispatch table, or an invalid callable entry.

A caller must provide accessible object storage for every field read reached on its execution path. Paths invoking indirect dependencies additionally require usable dispatch-table storage and callable entries. A dependency that returns must leave subsequent required accesses and calls valid; the outer function does not enforce this lifetime condition.

### Object and dispatch layout

The supplied representation exposes these object locations:

| Second integer-sized slot | Supplies the signed count used in comparisons and argument arithmetic |

Under a 32-bit integer layout, the corresponding byte offsets are 0, 4, and 16. Those byte offsets are conditional on that layout; the slot positions are directly visible.

Two indirect callable entries are selected using byte displacements from the dispatch-table base:

The representation is consistent with 32-bit integers and integer-held addresses. It does not independently establish the target ABI, pointer width, alignment, byte order, or character width. The dispatch displacements alone do not establish entry size or a complete table layout.

The initial control test applies a character conversion to the fifth integer-sized field. It is not a full-width nonzero test. On a conventional target where conversion retains an 8-bit low-order value, a field value such as 256 converts to zero despite the full field being nonzero. That example is conditional on the target’s conversion rules.

### Output

On normal return, the result is a signed integer:

- −1 if validation returned zero;
- otherwise, the effective selection.

An accepted effective selection of −1 also returns −1. Consequently, the result alone does not distinguish validation rejection from successful validation of selection −1.

The results, if any, of the two indirect dependencies and F-d6032bc0598f are not inspected.

## Behavior

### Initial control diversion

The first source-visible object-field read obtains the fifth integer-sized field. Its character-converted value is compared with zero.

When that converted value is nonzero:

1. F-c0e14e509280 is invoked with the object address and original selection.
2. If it returns normally, F-feee9156a257 is invoked with no explicit arguments.
3. F-feee9156a257 is annotated as non-returning.

This branch precedes both the distinguished-selection shortcut and validation. Selection 2,147,483,647 therefore does not bypass the control diversion.

The annotation supports an intended path with no normal return. It does not identify whether control ends through termination, exception, another transfer mechanism, or some other behavior. The actual input contract of F-feee9156a257 is unknown: a call with no explicit arguments is not evidence that it receives the object address, nor proof that it has no implicit inputs.

Behavior if the non-returning annotation is incorrect remains documented_only.

### Distinguished-selection shortcut

If the converted control value is zero, the function first compares the original selection with 2,147,483,647.

Only if that comparison succeeds does it read the second integer-sized field to test whether the signed count is positive. If positive, it reads that field again and sets the effective selection to the newly read count minus one. Validation is omitted.

Thus:

- A selection other than 2,147,483,647 does not require a count read for this shortcut decision.
- Selection 2,147,483,647 with a nonpositive count proceeds to validation unchanged.
- A successful shortcut uses separate source-visible count reads for the positivity test and the replacement calculation.

With stable storage and signed 32-bit arithmetic, a positive count yields an effective selection between zero and 2,147,483,646 inclusive. This representability guarantee depends on the count remaining positive for the replacement calculation.

### Validation

Every ordinary request not accepted by the shortcut invokes F-402eef64af83 with the object address and original selection.

A zero result causes an immediate return of −1. The outer function then performs neither indirect call nor the final direct call.

Any nonzero result permits processing to continue. The validator’s result is used only as a zero/nonzero decision; it does not replace the selection.

The call site does not establish the validator’s acceptance policy. In particular, it does not prove that an accepted selection is nonnegative, below the count, or safe for subsequent arithmetic.

The validator may modify the object or other state. Subsequent reads occur after its return and must not be specified as using pre-validation field values.

### Effective selection of −1

After shortcut selection or successful validation, an effective selection of −1 skips both indirect dependencies and F-d6032bc0598f. The function returns −1.

For stable positive count storage, the shortcut cannot produce this value. The ordinary established case is an original selection of −1 that receives a nonzero validation result.

Selection −1 does not bypass validation. Rejection and accepted −1 have the same numeric result but potentially different validator behavior and side effects.

### Conditional indirect call

For an effective selection other than −1, the function compares effective selection plus one with the current signed count.

If the former is strictly less than the latter, the indirect dependency at dispatch displacement 184 is invoked with:

1. The object address.
2. Effective selection plus one.
3. A count read for the invocation, minus one.
4. The all-ones value represented by the supplied hexadecimal constant.

The count used for the third argument is a separate source-visible read from the count used in the comparison. No single retained count snapshot is established.

Under stable storage and representable arithmetic, the second and third arguments resemble inclusive endpoints from immediately after the selection through count minus one. This is inferred intent, not an established interpretation imposed on the callee.

There is no additional local nonnegative-selection check or range validation. If validation accepts a negative selection other than −1, this comparison and call can still occur.

### Remaining calls and return

For every accepted effective selection other than −1:

1. The conditional indirect call completes, or is skipped.
2. The indirect dependency at displacement 188 is invoked with the object address and all-ones value.
3. If that call returns normally, F-d6032bc0598f is invoked with the object address and effective selection.
4. If the final call returns normally, the effective selection is returned.

The dispatch-table base is read again for the second indirect call. If the first indirect dependency changes the object’s dispatch-base field and returns, the second invocation uses the subsequently read value, assuming the resulting storage remains valid.

No control-field recheck occurs after validation or either indirect call. No further count read is shown after the conditional range operation.

### Arithmetic boundaries

The displayed count comparisons use signed integer values. Under a signed 32-bit interpretation:

- Count minus one is representable for a stable positive count.
- Selection plus one is representable for every signed selection except 2,147,483,647.
- Count minus one is not representable when the count is −2,147,483,648.
- The all-ones argument has the 32-bit pattern 0xffffffff, but its signedness and meaning at the indirect callee interface are not established.

A distinguished selection with a nonpositive count can reach validation unchanged. If validation accepts it, the later addition of one reaches the signed upper boundary.

The body supplies no explicit overflow handling. It does not establish executable wraparound, trapping, or another overflow behavior. Arithmetic outside the representable range, including arithmetic exposed by unstable count reads, remains documented_only.

## Acceptance examples

These are conditional static acceptance examples, not executed tests. Unless stated otherwise, they assume signed 32-bit arithmetic, a zero converted control value, stable relevant storage, valid indirect targets, and dependencies that return normally without invalidating subsequent operations.

### Positive-count shortcut

Given selection 2,147,483,647 and count 5:

- Validation is omitted.
- The effective selection becomes 4.
- The displacement-184 call is skipped because 5 is not less than 5.
- The displacement-188 call receives the object and all-ones value.
- F-d6032bc0598f receives the object and 4.
- The result is 4.

### Accepted selection followed by a range-shaped call

Given selection 1, count 5, and a nonzero validation result:

- Validation receives selection 1.
- The displacement-184 call receives the object, 2, 4, and all-ones value.
- The displacement-188 call follows.
- F-d6032bc0598f receives selection 1.
- The result is 1.

### Accepted selection at count minus one

Given selection 4, count 5, and nonzero validation:

- The displacement-184 call is skipped.
- The displacement-188 call and final direct call still occur.
- The result is 4.

### Rejection and accepted −1

If validation returns zero, the result is −1 and neither indirect call nor F-d6032bc0598f occurs.

If selection is −1 and validation returns nonzero, validation still occurs, the same later calls are skipped, and the result is also −1. Validator effects are not undone in either case.

### Accepted negative selection

Given selection −2, count 3, and nonzero validation:

- Selection plus one is −1, which is less than 3.
- The displacement-184 call receives the object, −1, 2, and all-ones value.
- The remaining indirect and direct calls follow.
- The result is −2.

This demonstrates the absence of a local nonnegative-selection restriction, not a guarantee that validation accepts −2.

### Validator changes the count

Given selection 1 and a validator that changes the count to 2 before returning nonzero:

- The later comparison uses the post-validation count.
- With that value stable, the displacement-184 call is skipped.
- The displacement-188 call and F-d6032bc0598f still occur.

### First indirect dependency changes dispatch

Given an accepted selection for which the displacement-184 call occurs, suppose that dependency replaces the dispatch-base field and returns while leaving the object valid.

The displacement-188 lookup uses the replacement base. The function does not retain the earlier table base for both calls.

### Special control state

- If the handler returns, F-feee9156a257 is called with no explicit arguments.

### Distinguished selection with zero count

- If validation accepts, subsequent addition reaches an unrepresentable signed 32-bit value; no wraparound-based result or call sequence is required by this contract.
