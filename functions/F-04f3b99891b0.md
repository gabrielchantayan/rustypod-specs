# F-04f3b99891b0

## Purpose

F-04f3b99891b0 constructs an object from an input record, then offers the construction result to handlers in two ordered phases:

1. An optional iterator-based phase.
2. A fallback traversal, reached only if the first phase does not produce a nonzero handler result.

The first nonzero handler result becomes the function’s return value. If no handler returns nonzero, the function returns zero. Before normal return, a nonnull constructed object receives a final virtual call.

“Object,” “handler,” “context,” and “gating” identify mechanical roles, not established application-level types. An ordered dispatch operation with optional fallback filtering is inferred intent; the observable contract below does not depend on that interpretation.

The function accepts one 32-bit value used as an input-record address. The supplied representation uses 32-bit addresses, pointer fields, and ordinary integer results. Two virtual-call results are represented as 64-bit quantities with separately used low and high 32-bit words.

Only these input-relative locations participate directly:

There is no explicit input-address validation, bounds checking, or arithmetic-overflow check. Valid address formation and readable storage are preconditions for the accesses actually reached. The supplied representation does not establish a portable address-wraparound rule.

### Return value

The result is a 32-bit handler-result value:

- Zero means no executed handler callback returned nonzero.
- A nonzero callback result is propagated without Boolean normalization.
- The semantic meaning of individual nonzero values is unknown.

A null construction result does not itself cause a return or establish an error code.

## Behavior

F-4d7c82c9282a then receives:

- The result of F-483a717208e6.
- The numeric argument 10.
- The input address advanced by 12 bytes.
- The 32-bit word read at input offset +20.

The completed first call therefore precedes both the input-relative address calculation and the input-word read. Only the relative evaluation order among the construction call’s argument expressions remains unspecified.

This ordering matters if F-483a717208e6 modifies the input through globals, aliases, or other reachable state: the +20 argument is obtained from storage after that call returns, not from an earlier snapshot.

There is no null check on the result of F-483a717208e6 before it is passed onward. The result of F-4d7c82c9282a becomes the object pointer retained for dispatch and finalization. A null result remains eligible to be passed to handler callbacks.

### Optional iterator phase

The running handler result starts at zero. F-3fdd14ecd250 supplies a context address, and the function reads its 32-bit field at +44.

If that value is zero, the iterator phase is skipped entirely.

Otherwise, F-538044b67754 initializes the local iterator state using the context’s +44 value and the 32-bit pattern 0xFFFFFFFE. The +44 field is read once for the initial test and again for initialization; it is not explicitly captured once and reused. No dependency call intervenes between those reads.

After initialization, F-6e4651b532dc repeatedly receives the iterator state and output area:

- A zero step result ends the phase without using that iteration’s output pointer.
- A nonzero step result authorizes use of the output area’s first pointer as a handler.
- That handler’s virtual callback at table offset +52 receives the handler pointer and the retained construction-result pointer.
- A zero callback result permits another step.
- A nonzero callback result ends the phase and is retained as the function result.

If a first-phase callback returned nonzero, fallback setup and traversal are omitted. Normal control proceeds to object finalization.

### Fresh fallback context and initial pointer capture

If the iterator phase is absent or produces no nonzero callback result, F-3fdd14ecd250 is called again. The initial fallback-handler pointer is read from offset +40 of this newly returned context.

The function does not reuse the first context address for this read. Effects of iterator dependencies, callbacks, or iterator termination can therefore influence the context or fallback pointer observed.

The initial fallback pointer is captured before the object query. Later changes to the context’s +40 field do not cause that field to be fetched again.

### Query and gating mode

If the constructed object is null, no query is performed and gating mode is disabled.

Otherwise, the function calls the object’s virtual method at table offset +20. The result is represented as 64 bits:

- A zero low 32-bit word disables gating.
- A nonzero low 32-bit word enables gating.
- The high 32-bit word does not independently select handlers or terminate traversal.

The query occurs even when the already captured fallback-handler pointer is null.

The high query word is carried alongside the current fallback pointer. On the null-object path, that high position instead begins with 0x00000A00. Neither value has an established effect on callback eligibility: disabled gating bypasses it, and enabled gating replaces the decision value with a read from the current handler’s gate object.

Gating mode is established once. It is not recomputed by repeating the query after callbacks or advancement.

### Fallback callback eligibility

A null current fallback pointer ends traversal. Otherwise, callback eligibility depends on the established gating mode.

With gating disabled, the function directly invokes the current handler’s virtual callback at table offset +48, passing the handler pointer and the retained construction-result pointer.

With gating enabled, the function first:

1. Reads the pointer at current handler offset +12.
2. Reads a 32-bit value at offset +12 from that pointed-to object.

A zero gating value permits the callback without calling F-35b8bd5fa9e0.

For a nonzero gating value, F-35b8bd5fa9e0 receives the construction-result pointer:

- A nonzero helper result permits the callback.
- A zero helper result skips the callback and leaves the running result zero.

The gate-object pointer is dereferenced without a preceding null check. A null +12 pointer is therefore not a safe traversal terminator on the gating-enabled path: the gating access is attempted before continuation eligibility is considered.

Each permitted callback returns a 32-bit result. A nonzero result ends traversal immediately. No continuation-field read or advancement call follows that successful callback.

### Continuation and advancement

After a skipped callback or a callback returning zero, the function reads the current handler’s +12 field again:

- Zero ends traversal.
- Nonzero permits a virtual advancement call at table offset +28 on the current handler.

This later read is distinct from the earlier gate-pointer read. A gating helper or callback may change what the continuation read observes. In particular, an earlier nonnull gate pointer does not guarantee advancement.

The advancement result is represented as 64 bits. Its low 32-bit word becomes the next handler pointer. A zero low word ends traversal at the next loop check.

The high advancement word is carried with that pointer but does not independently affect callback eligibility or termination. When gating is enabled, the next handler’s gating value supplies the relevant decision value; when disabled, that value is bypassed.

There is no cycle detection, visited-handler tracking, or iteration bound. Repeated advancement through a cycle can prevent return indefinitely if no callback returns nonzero and continuation remains permitted.

### Final call and normal return

After dispatch completes normally:

- A nonnull construction-result pointer receives one virtual call at table offset +4.
- A null construction-result pointer receives no such call.
- The retained 32-bit handler result is returned.

The final call’s return value, if any, is not used to replace the selected handler result.

These requirements cover normal control flow only. The supplied evidence does not establish cleanup or result behavior when a dependency faults, throws, exits nonlocally, or fails to return.

## Acceptance examples

These are conditional static acceptance criteria, not executed tests. Unless stated otherwise, all reached storage and call targets are valid, and dependencies return normally.

1. **The input word reflects effects of the first dependency.**  
   The input +20 word initially holds 3. F-483a717208e6 changes it to 9 before returning, and no other change intervenes. F-4d7c82c9282a receives 9 as its input-word argument. Passing the earlier value 3 would violate the established ordering.

2. **Construction arguments have no additional relative-order guarantee.**  
   F-483a717208e6 has returned. The input +12 address calculation and +20 read both belong to preparation of the construction call. The contract requires both to follow that return but does not prescribe their order relative to each other.

3. **First-phase success suppresses fallback.**  
   A yielded handler returns −7. Iterator termination runs before object finalization. No second context lookup or object query occurs. The function returns the same 32-bit result representing −7.

4. **Exhaustion reaches a fresh fallback context.**  
   Every yielded callback returns zero, then the iterator step returns zero. Iterator termination precedes the second context lookup. The +40 field of that second context supplies the initial fallback pointer.

5. **Null construction remains dispatchable.**  
   Construction returns null. Iterator callbacks may still receive null. If fallback is reached, gating is disabled; neither the object query nor final object call occurs.

6. **An empty fallback still permits a query.**  
   The captured fallback pointer is null and the object is nonnull. The object query runs, no fallback callback runs, and the final object call follows.

7. **Query mutation does not replace the captured fallback pointer.**  
   The initial fallback pointer identifies handler A. The query changes the context’s +40 field to handler B. Traversal still begins with A, provided A remains valid.

8. **A zero query low word bypasses gating.**  
   The query low word is zero, regardless of its high word. A fallback callback runs without an earlier gate-object dereference. If it returns zero, the handler’s +12 field is then read for continuation.

9. **A rejected gate can still advance.**  
   Gating is enabled, the gating value is nonzero, and F-35b8bd5fa9e0 returns zero. The callback is skipped. A nonzero later continuation field still causes advancement.

10. **Mutation can stop continuation.**  
    A fallback callback changes its handler’s +12 field to zero and returns zero. The later read observes zero, so advancement is omitted.

11. **Success suppresses continuation reads.**  
    A fallback callback returns 12. No later continuation-field read or advancement occurs for that handler. Normal finalization follows, and 12 is returned.

12. **A null gate pointer has no established safe result.**  
    Gating is enabled and the current handler’s +12 pointer is null. The function attempts the gate-object read before any continuation null check. Returning zero safely is not an established behavior.
