# F-2c4fc5b4a966

## Purpose

F-2c4fc5b4a966 processes a requested state transition for one indexed record. It updates record fields, checks an attempt counter and elapsed-value limit, invokes shared services, publishes the effective state, and conditionally emits events.

“Record,” “attempt,” “timestamp,” “duration,” “synchronization,” and “notification” describe inferred roles. Domain meanings for the numeric states and operations are not established.

This contract describes static evidence only. Dependencies may modify shared storage and supplied buffers; preservation, ownership, and release behavior are not assumed. No runtime tests have been performed.

## Interface

### Inputs and result

| Input | Representation | Established use |
|---|---|---|
| Context | Opaque 32-bit value | Forwarded to selected dependencies; not directly dereferenced |
| Selector | Unsigned 32-bit value | Selects entries in several shared tables |
| Requested state | Signed 32-bit value | Controls dispatch and full-width state publication; its low byte is stored in the record |

The initial selector check rejects values whose signed 32-bit interpretation exceeds 2, by invoking non-returning F-a817d8d58c10. Values 3 through `0x7fffffff` are rejected; high-bit-set values bypass this check.

**Storage precondition:** every address calculated for the selected path must identify accessible storage. The check does not establish this for arbitrary selectors. Values 0, 1, and 2 are the evident intended indices. Address calculations use the represented 32-bit arithmetic; this contract does not extend table validity to wrapped or out-of-range addresses.

The ordinary result is a signed 32-bit value, initially 62 and commonly changed to 0. Post-event classification can replace it with the low 32 bits of a dependency result. Some paths do not return. Neither 0 nor 62 has an established universal success or error meaning.

Dispatch uses the full requested state, not its low byte.

### Record and related storage

The selected record has a 36-byte stride:

| Byte offset | Width | Observed role |
|---|---:|---|
| 0 | 32 bits | Handle-like value |
| 4 | 8 bits | State; initially read as signed |
| 8 | 32 bits | Timestamp-like value |
| 12 | 32 bits | Duration-like value |
| 26 | 8 bits | Attempt counter |
| 27 | 8 bits | Unsigned attempt limit |
| 28 | 8 bits | Mode |
| 30, 31, 32 | 8 bits each | Resettable fields |

Other bytes are not directly assigned a role here.

Related storage includes a 28-byte-stride synchronization-associated table, byte-indexed status and notification tables, and a four-byte-stride eligibility table. Shared storage also supplies temporary-object setup data, conversion arguments, durations, and termination arguments.

## Behavior

### Setup and timestamp preparation

The record address is selected before the initial dependency calls and retained.

Two separate service-accessor calls provide offset-4 subobjects to F-1bc5bcdc9cca and F-62d1a359629f, respectively. Both queries receive the selector. Their 32-bit results are retained for the event payload; repeated accessors need not return the same object.

F-21db160d8c99 receives temporary-object storage and argument 1. A 32-bit shared value is then written through its returned address. A readable, writable returned address is required for this access.

Both 32-bit words of an output area are initialized to zero before the temporary object’s virtual operation at byte offset 12 receives that area. Afterwards:

- F-870c4fcf7295 receives the second output word and a shared argument read for that call.
- The computed timestamp is the first output word multiplied by 1000, plus the conversion result.

An output word left untouched therefore remains zero. Conversion still occurs when the second word is zero; its result for zero is unknown.

The timestamp expression has represented 32-bit operands and result. No explicit overflow check is visible. Exact target-level behavior where represented signed arithmetic overflows remains documented_only.

The event code is initialized to 15. A 32-bit metadata field is initialized to 16, except that selector 1 obtains it from byte offset 52 of a shared object. The previous state is then read as a signed byte. The synchronization-associated address is selected and retained.

### Initial publication and terminal-state shortcut

If the requested state is nonzero and the retained previous state is −2 or −1, processing enters common termination without first writing the requested state byte.

Otherwise, the requested state’s low byte is written before request-specific processing. Ordinary completion writes the final effective state byte again.

Initially:

- The result is 62.
- No service operation is selected.
- No deferred Boolean-like update is selected.
- Event code 15 suppresses final event emission.

### Request-specific processing

**Requested state 0.** If the previous state is not 3, 4, or 5, synchronization entry occurs and the handle is read. A nonzero handle causes F-ae524095c0b0 followed by non-returning F-feee9156a257.

For a zero handle, synchronization exit precedes clearing record bytes 26, 30, 31, and 32, in that order. Operation 0 is selected and the result becomes 0.

Previous states 3, 4, and 5 instead proceed to common termination without this reset sequence.

**Requested state 1.** No request-specific change to the initial result occurs. Common termination follows.

**Requested state 2.** The result becomes 0. No attempt-window check occurs.

**Requested state 3.** The counter is incremented and stored as an eight-bit value. Incrementing 255 stores 0. The stored value is compared unsigned with the limit.

If it exceeds the limit, the effective state becomes −2 and common termination follows. Otherwise, a deferred F-4944ce526800 call with final argument 1 is selected.

If the duration is zero, initialization proceeds in this observable order:

1. Store the computed timestamp at offset 8.
2. Read the default duration from shared storage.
3. Read the mode byte.
4. Only for mode 1, read an alternative duration from separate shared storage.
5. Store the selected duration at offset 12.

The result becomes 0 before the attempt-window check. Neither duration value is established as constant or nonzero.

**Requested state 4.** If the counter equals 1, operation 4 and event code 9 are selected. F-5fd97c30efdc supplies a first object, then F-cdd33263ee89 supplies a second object. The first object’s virtual operation at byte offset 24 is invoked.

If that operation returns nonzero, a fresh service supplies an offset-4 subobject for F-1bc5bcdc9cca. Unless its query result is 70, 3, or 15, the second object’s virtual operations at offsets 228 and 128 are invoked, in that order, each with argument 1. Query result 16 additionally causes F-c6cb91d68549 with context and selector.

The attempt-window check follows regardless of whether the counter equals 1.

**Requested state 5.** Processing proceeds directly to the attempt-window check.

**Requested state 6.** Operation 6, event code 10, and a deferred F-4944ce526800 call are selected. A fresh service supplies an offset-4 subobject for F-bc2b33235f5b.

The deferred call’s final argument is 1 exactly when both bits in mask `0x0c` are set in the query result; otherwise it is 0. The notification byte addressed through the notification-table base read after this query is written to 1. The result becomes 0. No attempt-window check occurs.

**Other full-width states.** Unless already diverted by the terminal-state shortcut, they retain result 62 and enter common termination. A state whose low byte matches a listed state does not thereby select that state’s processing.

### Attempt-window check

For effective states 3, 4, and 5, either condition causes termination:

- The unsigned counter exceeds the unsigned limit.
- The unsigned duration is at most the unsigned 32-bit difference between computed timestamp and stored timestamp.

Failure sets effective state −2 and result 62. Passing sets result 0.

Equality expires the window. Zero duration expires it. A timestamp that appears earlier than the stored value can yield a large unsigned difference.

The counter, limit, duration, and stored timestamp are read for this check; earlier dependencies are not assumed to preserve them. The duration comparison follows the counter comparison only if the latter does not already establish failure.

### Common termination

Termination selects a deferred F-4944ce526800 call with final argument 0, replacing any earlier selected argument 1.

It then performs these actions in order:

1. Obtain an object through F-cdd33263ee89 and invoke its virtual operation at offset 128 with argument 0.
2. Enter synchronization and read the handle. A nonzero handle invokes F-ae524095c0b0 followed by non-returning F-feee9156a257. Otherwise, exit synchronization.
3. Obtain an object through F-15643c36365d and invoke its virtual operation at offset 72. If the result is nonzero, obtain an object again through the same dependency and invoke its virtual operation at offset 68 with argument 0.
4. Retain effective state −2; replace every other effective state with −1.

Additional termination work is gated by the retained previous state. It occurs only when that state is neither −2, −1, nor 6.

**Within that previous-state gate, and only when the effective state is −2:**

- Store the computed timestamp at offset 8.
- Call F-b4b48080e55c.
- Pass its result and a subsequently read shared argument to F-d7be9cfb4000.
- Add 180000 to F-d7be9cfb4000’s auxiliary output and store the represented 32-bit result as duration. The ordinary return is not the identified duration source.
- Call F-43ce968102ca with context, selector ORed with `0x80`, a shared argument read for this call, 58, and 0.

Thus, F-43ce968102ca requires **both** an eligible previous state and effective state −2. Effective state −1 does not invoke it.

**Still within the previous-state gate, but regardless of whether the effective state is −2 or −1:**

- Call F-646d64bbe501 with context, selector, and 1.
- Perform termination-status processing below.
- Select operation −1 and event code 11.
- Obtain a fresh service and call F-39405f5827ef on its offset-4 subobject with the selector.

Skipping the previous-state-gated work does not independently clear an operation or event selected earlier.

### Termination-status processing

The notification-table base is captured after F-646d64bbe501 and before the eligibility checks.

The selected eligibility entry qualifies if its first byte is zero. Otherwise, its fourth byte is read and must exceed 63.

For a qualifying entry, status 5 or 3 causes status 4 to be written. The selected notification byte is then read through the captured notification base:

- If nonzero, no event is emitted by this step.
- If zero, payload code 14 is installed and F-c6c589453fa8 is called with arguments 0, 0, payload address, and length 20. Afterwards, notification byte 1 is written through the same captured base.

Changing the global notification-table base during this event call does not redirect that subsequent write. Event code 11 is installed later by the enclosing termination sequence.

### Final state and deferred operations

Ordinary completion proceeds in this order:

1. Store the effective state’s low byte at record offset 4.
2. Obtain a service and call F-2250ce450b3d with that service, selector, and full 32-bit effective state.
3. If a deferred update was selected, obtain a fresh service and call F-4944ce526800 on its offset-4 subobject with selector, 0, and the selected flag.
4. If an operation was selected, obtain a service and invoke its virtual operation at offset 20 with arguments 64 and the operation.
5. Inspect the payload’s event-code byte.

### Final event and post-event classification

Code 15 suppresses both final emission and its associated post-event processing. Any other code causes F-c6c589453fa8 with arguments 0, 0, payload address, and length 20.

After emission returns, the status-table base is captured and the payload’s code byte is tested again. Post-event processing requires all of:

- The post-call code is 9.
- The current unsigned status byte is at most 3.
- The current mode byte is nonzero.

Pre-emission code 9 is not sufficient if the dependency changes it. Without a preservation guarantee, another emitted code can also become eligible by changing to 9.

The captured status base is retained for the later status write. Synchronization entry occurs, then mode is reread:

- Mode 1 selects status 5, preserves the existing result, and supplies synchronization entry’s auxiliary output as synchronization exit’s second argument.
- Otherwise, mode is checked again. Mode 2 requires a nonzero handle. Any other mode, or mode 2 with a zero handle, invokes non-returning F-a817d8d58c10.

For mode 2, a 32-bit classification output is initialized to `0x7fffffff`. F-5a1076b07e3a receives the handle and its address, and returns a value with observable low and upper 32-bit halves.

Classifications 0, 4, 5, 6, 9, and 10 select status 5 and retain the returned upper half as synchronization exit’s second argument. Every other classification selects status 4 and replaces that argument with 1. In both cases, the returned low half becomes this function’s result.

Synchronization exit precedes the status write through the retained status base. For status 4, the notification-table base is read after exit and its selected byte is written to 1. Status 5 performs no corresponding notification write.

Finally, code 14 is installed and another event is emitted. No further classification gate follows that emission.

## Side effects

Direct writes affect the selected record, status bytes, notification bytes, temporary storage, and event payload. Dependencies may cause additional effects.

Each event receives the same 20-byte payload storage:

| Offset | Width | Initially established contents |
|---|---:|---|
| 0 | 1 byte | Event code, initially 15 |
| 1–3 | 3 bytes | Not visibly initialized |
| 4 | 32 bits | 16, or selector-1 shared metadata |
| 8 | 32 bits | Selector |
| 12 | 32 bits | Initial F-1bc5bcdc9cca result |
| 16 | 32 bits | Initial F-62d1a359629f result |

Uninitialized bytes prevent a deterministic specification of every emitted byte. Dependencies receive the payload address and may modify it. Later events reuse the storage without visibly rebuilding all fields.

The record address, synchronization address, termination notification base, and post-event status base are retained snapshots at their respective selection points. Other pointer reads use the shared values available when those reads occur.

No ownership transfer of context, handle, or payload is established. Temporary construction and destruction are visibly paired only on ordinary returning paths. Fatal paths have no visible temporary destruction.

## Acceptance examples

These are conditional static criteria, not executed tests. Unless stated otherwise, they assume accessible storage and no dependency mutations affecting the described outcome.

1. **Reset:** Previous state 2, request 0, and zero handle clear bytes 26, 30, 31, and 32, select operation 0, publish state 0, and return 0.

2. **Ordinary termination excludes F-43ce968102ca:** Previous state 4, request 0, and zero handle yield effective state −1 and result 62. F-646d64bbe501 and subsequent gated termination actions occur, but timestamp/duration initialization and F-43ce968102ca do not.

3. **Expired transition includes F-43ce968102ca:** Previous state 2, request 5, and elapsed difference equal to duration select effective state −2 and result 62. The eligible previous state permits timestamp/duration initialization, then F-43ce968102ca, then F-646d64bbe501.

4. **Previous-state gate remains decisive:** Previous state 6 with request −2 retains effective state −2 during termination, but skips both F-43ce968102ca and F-646d64bbe501.

5. **Untouched timestamp outputs:** If the temporary virtual operation leaves both initialized words unchanged, conversion receives zero. The timestamp equals the conversion result, subject to the represented arithmetic.

6. **Duration initialization:** Request 3, counter 0, limit 2, and zero duration store counter 1. Timestamp storage precedes the default-duration read. Mode 1 causes the alternative-duration read. Passing additionally requires duration to exceed the elapsed difference.

7. **Counter wrap:** Counter 255 increments to 0. Limit 0 accepts that counter comparison; the duration comparison remains decisive.

8. **State-6 flags:** Query results `0x0c` and `0x08` select deferred flags 1 and 0, respectively. Both write notification byte 1 and initially select event 10.

9. **Mutable event code:** An emitted code 9 changed to 10 skips classification. Another non-15 code changed to 9 can qualify if status and mode also permit it.

10. **Mode reread:** If synchronization entry changes an admitting nonzero mode to 1, status 5 is selected without the classification query.

11. **Classification halves:** Classification 9 selects status 5 and passes the query’s upper half to synchronization exit. Classification 7 selects status 4 and passes 1. Both use the query’s low half as the result.

12. **Pointer snapshots:** Changing the global status base during synchronization entry does not redirect the final status write. Changing the notification base during termination event 14 does not redirect the immediately following notification write.
