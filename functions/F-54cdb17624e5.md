# F-54cdb17624e5

## Purpose

F-54cdb17624e5 selects between two behaviors according to whether its second input is zero:

- For a nonzero second input, it constructs temporary state, invokes a related operation, incorporates the resulting temporary into a caller-supplied object, and performs two cleanup calls.
- For a zero second input, it dispatches through the caller-supplied object’s method table. A global byte determines whether this is a direct dispatch or a dispatch followed by an optional indirect operation.

The established contract is the sequence of calls, argument relationships, branch conditions, and returned bit patterns. The semantic meanings of the objects, global data, temporary representations, and most dependency results are not established.

Terms such as “construct,” “incorporate,” and “cleanup” describe apparent roles. They do not establish allocation, reference counting, destruction, or ownership transfer.

## Behavior

This branch is taken for every selector value other than zero.

The following call order is established:

1. F-9d0ecc5f6adf is called without visible arguments.
2. Its 32-bit result and a value read from a global configuration location are passed to F-c0b020cd3882.
3. The result of F-c0b020cd3882 is passed to F-7afe554bcf62 together with the address of the local region initially holding the position.
4. F-44362605ab79 is called with that same local address.
5. The target, the result of F-44362605ab79, and the position incremented by one are passed to F-1f62160dfd52.
6. F-5b24edfb22c0 is called with the address of the local region initially holding the context.
7. F-e1ebf2bee25b is called with the original selector and original position.
8. F-6fcfdcacdf24 is called with the original context, the result of F-e1ebf2bee25b, a literal zero, and the address of the context-initialized local region.
9. F-7c7fe4dcd370 is called with the target and that context-initialized local address.

There is no visible conditional branch based on any intermediate dependency result. In particular, a zero result from either value-producing dependency is still forwarded to its next consumer.

The original context, selector, and position used in later argument expressions are distinct from the local storage passed by address. The position-initialized local may have been changed before F-e1ebf2bee25b is called; that call nevertheless receives the original position.

Likewise, the return’s low word is read after both cleanup calls. It is not necessarily the word produced by F-6fcfdcacdf24 before cleanup.

The return’s high word starts as the selector. It may be treated as still equal to the selector only if the dependencies do not modify that storage through the exposed region or another alias. Such preservation is not established here.

### Zero selector and zero global byte

When the selector is zero, a separate global byte is examined.

If that byte is zero:

1. The method-table pointer is read from the target.
2. The callable entry at byte offset 12 is selected.
3. That entry is invoked with the target as its sole visible argument.
4. Its entire 64-bit result is returned.

None of the named dependencies used by the nonzero-selector branch is visibly called on this path.

The context and position inputs have no visible role in this dispatch.

### Zero selector and nonzero global byte

If the global byte is nonzero:

1. F-5cb57bbb2e0e is called with the address of that global byte.
2. Its 32-bit integer result is incremented by one.
3. The target’s method-table entry at byte offset 8 is invoked with the target, the incremented value, and a literal zero.
4. The low 32 bits of this indirect call’s 64-bit result are tested.

If those low 32 bits are nonzero:

- A callable is obtained from a separate global function-pointer location.
- It is invoked with the low 32-bit result word and the address of the global byte.
- Its full 64-bit result becomes the function’s return.

If those low 32 bits are zero:

- The global function-pointer call is skipped.
- The return retains the method call’s upper 32 bits and has zero in its lower 32 bits.

The failure-path masking does not imply a fully zero return. For example, a method result with a nonzero upper word and a zero lower word retains that upper word.

The second call receives the address of the global byte, not a captured copy of its initial value. F-5cb57bbb2e0e and the target method execute before that address is passed onward. Their effects on the global storage are unknown.

### Arithmetic and comparisons

The indirect-result test likewise distinguishes a zero low 32-bit word from any nonzero low 32-bit word. A word with its sign bit set still takes the nonzero path.

Exact behavior outside the signed 32-bit non-overflow range is not established by the supplied representation. In particular, a language-level overflow rule must not be inferred from the apparent integer type alone.

## Acceptance examples

These are conditional static acceptance criteria, not executed tests.

1. **Nonzero selector, ordinary position.** With selector 7 and position 3, F-1f62160dfd52 receives 4 as its third argument, while F-e1ebf2bee25b receives 7 and 3. The two cleanup calls occur after F-7c7fe4dcd370, in the specified order.

2. **Negative selector.** A selector of −1 takes the same branch as any other nonzero selector. There is no positive-only condition.

3. **Return observed after cleanup.** If the context-initialized word contains `0x11223344` after both cleanup calls, and the selector-initialized word remains 7, the returned bit pattern is `0x0000000711223344`. A value held before cleanup is insufficient to determine this return.

4. **Direct dispatch.** With selector zero and global byte zero, only the target entry at offset 12 is selected by this function. If it returns `0xAABBCCDD11223344`, that entire pattern is returned.

5. **Nonempty-global dispatch.** With selector zero, global byte nonzero, and F-5cb57bbb2e0e returning 5, the target entry at offset 8 receives target, 6, and zero.

6. **Zero low word.** If that entry returns `0xAABBCCDD00000000`, the global callable is not invoked. The function returns `0xAABBCCDD00000000`, not necessarily zero.

7. **Nonzero low word.** If that entry returns `0xAABBCCDD80000000`, the global callable is invoked with the low word `0x80000000` and the global-byte address. Its result replaces the entire prior result.

8. **Arithmetic boundary.** A position or dependency result at the largest signed 32-bit value reaches an unchecked increment. Acceptance of a particular overflow outcome requires additional evidence; this document does not prescribe one.
