# F-516a8b658c4b

## Purpose

F-516a8b658c4b processes join-related information across adjacent entries in a source list. It recognizes a natural-join flag, an explicit join-condition pointer, and a named-column list. It delegates matching-column predicate construction, transfers explicit join conditions into an accumulated expression, and reports certain incompatible or invalid join specifications.

**Established behavior:** processing is left-to-right over adjacent pairs. Successful work can modify the accumulated expression before a later error is discovered. There is no visible rollback.

**Inferred intent:** the accumulated expression is a query filter, the explicit condition represents an `ON` clause, and the named-column list represents a `USING` clause. These interpretations explain the diagnostic labels and dependency use, but do not establish the full contracts of the surrounding query engine.

The function returns a 32-bit zero when traversal completes and a 32-bit one after one of its explicit diagnostic paths. Zero does not independently prove that dependencies succeeded.

## Interface

### Inputs

The function receives two address-valued arguments in a 32-bit address model:

1. **Processing context.** An address passed to predicate-building and diagnostic dependencies. Its first 32-bit word is also read and passed to the expression-combination dependency.
2. **Query object.** An address with these observed fields:

| Byte offset | Width | Observed role |
|---|---:|---|
| +12 | 32 bits | Address of the source-list structure |
| +16 | 32 bits | Accumulated expression value, read and replaced during condition processing |

Neither argument is validated for nullness or accessibility.

### Source-list layout

The source-list address is fetched once from the query object. The observed layout is:

| Byte offset | Width | Observed role |
|---|---:|---|
| +0 | Signed 16 bits | Entry count |
| +8 | — | Start of the first entry |

Entries have a 48-byte stride. Only the following entry fields are observed:

| Offset within entry | Width | Observed role |
|---|---:|---|
| +8 | 32 bits | Opaque value passed with that entry’s table |
| +12 | 32 bits | Table address; zero causes pair processing to be skipped |
| +21 | 8 bits | Join flags, taken from the right entry |
| +24 | 32 bits | Opaque right-entry value passed to predicate-building or marking dependencies |
| +28 | 32 bits | Explicit condition address |
| +32 | 32 bits | Named-column-list address |

The first pair comprises entries zero and one. Each subsequent pair advances both positions by one entry.

Only two bits of the right entry’s flag byte affect this function:

- `0x04`: selects natural-column matching.
- `0x20`: converted to the numeric value zero or one and passed to predicate construction; when nonzero, also enables explicit-condition marking.

Other flag bits are ignored locally.

### Referenced layouts

A nonzero table address is used with:

| Byte offset | Width | Observed role |
|---|---:|---|
| +4 | Signed 32 bits | Column count for natural-column enumeration |
| +8 | 32 bits | Address of column records |

Column records have a 20-byte stride. Their first 32-bit word is the column identifier passed to dependencies. Its representation and ownership are not established.

A nonzero named-column-list address is used with:

| Byte offset | Width | Observed role |
|---|---:|---|
| +0 | 32 bits | Address of named-column records |
| +4 | Signed 32 bits | Record count |

Named-column records have an 8-byte stride. Only their first 32-bit word is read, as a column identifier.

### Result and preconditions

The result is a 32-bit status:

- **0:** traversal reached its count-based stopping condition.
- **1:** this function invoked a diagnostic dependency for an explicit rejected condition and then returned.

All accessed objects and record arrays must be valid for the reads and writes actually reached. Counts, addresses, alignment, and pointer arithmetic are not validated. No local handling exists for invalid memory, dependency exceptions, or dependency-specific failure states.

## Behavior

### 1. Traverse adjacent pairs

The function captures the source-list address, establishes positions for the first two entries, and starts with pair index zero.

Before accessing each pair’s table fields, it rereads the signed 16-bit source count. Traversal stops with result zero when the pair index is at least the count minus one.

Consequently:

- Counts of one, zero, or any negative signed 16-bit value produce no pair processing.
- A stable count of two permits one pair.
- A stable positive count of \(n\) permits \(n-1\) pairs.
- The count is not an entry-time snapshot; dependency-visible changes can affect later loop termination.

For each admitted pair, the function reads the left table address and then the right table address. If either is zero, it skips all join processing for that pair. In particular, it does not validate that pair’s natural/explicit-condition/named-column combinations.

After a skipped or completed pair, the index increases by one and both entry positions advance by 48 bytes.

### 2. Capture join mode

For a pair whose two table addresses are nonzero, the function reads the right entry’s flag byte and captures bit `0x20` as zero or one.

It separately reads the flag byte to test bit `0x04`. These are distinct reads. The captured `0x20` value is retained for the remaining processing of this pair; it is not recomputed after dependency calls.

### 3. Process natural-column matching

When bit `0x04` is set, the function first checks for incompatible attached clauses:

1. It reads the right entry’s explicit-condition address.
2. Only if that address is zero does it read the named-column-list address for this check.
3. If either checked address is nonzero, it invokes F-2022b0f73f3b with the context, a natural-join diagnostic, and a zero supplementary value, then returns one.

If both are zero, it enumerates the left table’s columns in increasing index order.

For each left column:

1. Read the left table’s column-array address.
2. Read the column identifier from the first word of the corresponding 20-byte record.
3. Call F-d6a5d01d0abb with the right table and identifier.
4. If the signed 32-bit result is nonnegative, invoke F-38d97d7c56e5 to construct or attach a predicate for that identifier.

The builder receives, in order:

- Processing context.
- Column identifier.
- Captured left table address.
- Current left-entry value at offset +8.
- Captured right table address.
- Current right-entry value at offset +8.
- Current right-entry value at offset +24.
- Address of the query’s accumulated-expression field.
- Captured zero-or-one mode.

The lookup result is used only to distinguish negative from nonnegative; its actual index is not forwarded.

The signed 32-bit left-column count is reread at each loop test. Zero or negative counts produce no iterations. Column-array addresses are likewise not globally snapshotted.

Natural processing does not directly return after successful enumeration. The function next examines the explicit-condition and named-column fields again. Unknown dependency mutations may therefore affect which later branches are reached.

### 4. Process an explicit condition

The function reads the right entry’s explicit-condition address. If it is nonzero:

1. Read the named-column-list address.
2. If that address is also nonzero, call F-2022b0f73f3b with the incompatible-clauses diagnostic and return one.
3. If the captured mode is one, call F-16635d5ac82e with the current explicit-condition address and the right entry’s value at offset +24.
4. Call F-8661793c1ec4 with:
   - The processing context’s first 32-bit word.
   - The query’s current accumulated-expression value.
   - The right entry’s current explicit-condition address.
5. Write the dependency’s 32-bit return value to the query’s accumulated-expression field.
6. Clear the explicit-condition field with two successive 16-bit zero writes: first its lower-addressed half, then its higher-addressed half.

The marking call’s result is not inspected. The condition supplied to the combination call is read after the optional marking call; it is not guaranteed to be the same pointer originally tested.

The accumulated-expression write precedes both condition-field clearing writes. No local success check separates these operations. A zero return value from the combination dependency is still stored, and the condition field is still cleared.

### 5. Process a named-column list

After explicit-condition processing, the function reads and captures the right entry’s named-column-list address.

If nonzero, it iterates records in increasing index order, rereading the captured list object’s signed 32-bit count at each loop test.

For each record:

1. Read the record-array address from the captured list object.
2. Read the identifier from the first word of the corresponding 8-byte record.
3. Look up the identifier in the captured left table using F-d6a5d01d0abb.
4. If the left lookup is negative, report the missing-column diagnostic and return one without performing the right lookup.
5. Otherwise, look up the identifier in the captured right table.
6. If the right lookup is negative, report the same diagnostic and return one.
7. Otherwise, call F-38d97d7c56e5 with the same argument structure used for natural-column matches.

The diagnostic receives the failing column identifier as its supplementary value.

A zero or negative list count causes no record processing. Repeated identifiers are not deduplicated: each occurrence that passes both lookups produces a builder call.

The captured list address remains the iteration target even if a dependency replaces the entry’s list field. Contents and count within that captured object are still reread.

## Side effects

### Direct writes

The function directly performs only these visible object updates:

- Replaces the query’s accumulated-expression field with F-8661793c1ec4’s result.
- Clears a processed explicit-condition field through two ordered 16-bit writes.

It passes the accumulated-expression field’s address to F-38d97d7c56e5, permitting that dependency to change it.

The function does not directly clear or release a named-column list, alter a table definition, or remove source entries.

### Partial progress and errors

Error handling is not transactional:

- Predicates from earlier pairs remain subject to dependency behavior when a later pair fails.
- Earlier valid identifiers in a named-column list can produce builder calls before a later identifier fails.
- Earlier explicit conditions may already have been combined and detached from their source entries.
- No direct restoration is attempted.

The function has no visible direct allocation or release operation. Clearing an explicit-condition field establishes detachment from that field, not proof of ownership transfer, retention, copying, or deallocation.

### Dependency-visible mutation

No callee-preservation guarantee is supplied. The contract therefore distinguishes captured values from reread fields:

- Source-list address and each pair’s table addresses are captured.
- The mode bit is captured once per eligible pair.
- Entry metadata supplied to builders is reread for each call.
- Source count, natural-column count, and named-column-list count are reread.
- The accumulated expression is read immediately for combination, subject to unspecified argument-evaluation ordering.

Behavior requiring concurrent or reentrant mutation of these structures is not fully established. The observed read placement must not be replaced by an assumption that all inputs remain immutable.

## Acceptance examples

These examples are conditional contracts, not executed tests. Unless stated otherwise, dependencies return normally and do not mutate inspected structures except through their intended expression effects.

1. **Empty or single-entry source list.**  
   With a signed source count of zero or one, return zero without reading pair table fields or invoking join-processing dependencies.

2. **Pair with an absent table.**  
   With two entries and either table address zero, return zero after skipping the pair. Even incompatible join fields on the right entry produce no local diagnostic on that skipped pair.

3. **Natural join with an explicit condition.**  
   With both tables present, natural mode set, and a nonzero explicit condition, invoke the natural-clause diagnostic and return one. Do not enumerate columns or combine that condition.

4. **Natural matching preserves left-column order.**  
   If left identifiers are A, B, C and right lookups are nonnegative for A and C but negative for B, perform lookups in A/B/C order and builder calls in A/C order.

5. **Explicit condition with mode clear.**  
   With an explicit condition and no named-column list, omit marking, call the expression combiner, store its result, and then clear both 16-bit halves of the condition field. Return zero if no later pair fails.

6. **Explicit condition with mode set.**  
   Under the preceding conditions but with bit `0x20` set, invoke marking before combination.

7. **Both explicit condition and named-column list.**  
   With both tables present and natural mode clear, report the incompatible-clauses diagnostic and return one. Do not mark, combine, or clear the condition on that path.

8. **Named identifier missing on the left.**  
   Report the identifier and return one after the left lookup fails. Do not perform its right lookup or builder call.

9. **Named identifier missing on the right after prior progress.**  
   If an earlier identifier passed both lookups and a later identifier passes the left lookup but fails the right, retain the earlier observable builder call and return one. No rollback is required.

10. **Duplicate named identifiers.**  
    Two identical records whose lookups succeed produce two builder calls. No local uniqueness requirement is enforced.

## Uncertainties

The following remain **documented_only**:

- Exact diagnostic text; the supplied labels identify categories but not complete messages.
- Full object types and meanings of opaque entry metadata.
- Identifier representation, comparison rules, case handling, and string lifetime.
- The semantic meaning of mode bit `0x20`.
- Whether expression combination performs logical conjunction.
- Allocation, destruction, reference ownership, and aliasing rules across dependencies.
- Dependency error conventions and whether they mutate global or context state.
- Required alignment and behavior for invalid addresses or corrupted layouts.
- Overflow behavior for malformed 32-bit column or list counts and their scaled address calculations.

The source count is signed 16-bit, so subtracting one after promotion stays within signed 32-bit range. With a stable valid count, pair traversal itself stays within that bound. This does not validate backing storage.

Column and named-list counts are signed 32-bit. Their 20-byte and 8-byte record-offset calculations require valid representable backing addresses; the function supplies no overflow or bounds checks.
