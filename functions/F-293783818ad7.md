# F-293783818ad7

## Purpose

F-293783818ad7 performs an unconditional address calculation and halfword write, then selects one of two represented paths:

- Seven ordered 32-bit writes followed by an invalid-instruction boundary.
- One byte clear followed by repeated coprocessor operations, with no represented exit.

The path depends on bits 11 through 20 of the first explicit input. The address calculation preceding that decision uses a signed ambient value and occurs on both paths, even though only the seven-word path subsequently uses the resulting pointer for memory writes.

No higher-level purpose is established. The consecutive words could represent a record, but record initialization, device programming, ownership transfer, and successful completion are not established semantics.

This contract describes static evidence and its limits. It does not resolve missing control flow, assign architectural meanings to coprocessor selectors, or assume ordinary return.

### Ambient inputs

The operation also consumes state outside its four explicit arguments:

- **Address selector:** a signed integer value used in an early multiplication by 2,048 and, on the seven-word path, a separate later left shift by 11.
- **State word:** a 32-bit unsigned value used as the final stored word on one path, or as the basis for the byte-clear address and first derived coprocessor operand on the other.
- **First coprocessor-associated value:** a represented four-byte value.
- **Second coprocessor-associated value:** a represented four-byte value.

The two coprocessor-associated values have known represented widths of four bytes each. Their architectural interpretation, register provenance, and actual architectural coprocessor-register widths remain unknown.

The signed address-selector operations are interpreted within the supplied 32-bit integer model. Their signedness matters: multiplication overflow and left shifting a negative or excessively large signed value cannot simply be treated as guaranteed unsigned modular arithmetic.

### Outputs and completion

No return value is represented.

Neither path establishes normal return:

- The seven-word path reaches an invalid-instruction boundary after its final write.
- The coprocessor path repeats without a represented termination condition.

A memory fault, coprocessor exception, external interruption, or invalid-instruction event may prevent later represented effects. Their handling is undocumented.

Successful accesses require suitable address interpretation, mapping, permissions, alignment support, and memory lifetime. The function performs no represented validation of those conditions.

## Behavior

### Unconditional address preparation

The first represented operation multiplies the signed address selector by 2,048 and converts the result into the base pointer later used by the seven-word path.

This preparation precedes:

1. The initial halfword write.
2. The path-selection decision.
3. Any byte clear or coprocessor operation.

It therefore occurs even when the coprocessor path is selected and the base pointer is never subsequently dereferenced.

This calculation does not itself read or write the memory designated by the resulting pointer. It is nevertheless part of the represented execution sequence and cannot be moved into a path-specific precondition.

The multiplication is signed. Where its mathematical result is outside the represented signed range, the supplied material does not establish a portable arithmetic result or continuation behavior. A low-32-bit machine interpretation may be useful for conditional examples, but is not an unconditional guarantee. This qualification applies on both paths.

The early multiplication is distinct from the signed left shift later used to produce the word at byte offset 8. The representation does not replace either operation with the other.

### Initial halfword write

After preparing the base pointer, the operation logically shifts the fourth input right by four bits.

It then writes a 16-bit value:

- **Destination:** the shifted unsigned value plus eight, converted to a pointer.
- **Contents:** the low 16 bits of the shifted value.

The stored bit pattern therefore consists of bits 4 through 19 of the fourth input, not its original low halfword.

The shifted value ranges from `0x00000000` through `0x0FFFFFFF`. Adding eight gives a numerical address value from `0x00000008` through `0x10000007`, without 32-bit unsigned overflow.

No destination read precedes this write. No alignment adjustment or access check is represented. If the access cannot complete, no later path effect is guaranteed.

### Path selection

After the initial halfword write, bits 11 through 20 of the first input select the path:

- All ten bits clear: seven-word path.
- At least one bit set: coprocessor path.

Bits 0 through 10 and 21 through 31 do not influence this decision. They may still influence words stored on the seven-word path.

### Seven-word path

The base pointer is the one prepared before the initial halfword write. Seven 32-bit writes follow in the order shown:

| Byte offset from the base pointer | Stored value |
|---:|---|
| 0 | First input, unchanged |
| 4 | Base pointer converted to a 32-bit unsigned value |
| 8 | Address selector shifted left by 11 |
| 12 | Fourth input logically shifted right by 8 |
| 16 | Zero |
| 20 | First input shifted left by 11 |
| 24 | Incoming state word |

The signed shift supplying offset 8 is a later operation, separate from the early signed multiplication. It occurs in the represented sequence after the writes at offsets 0 and 4, and before the write at offset 8. Its signed-arithmetic limitations must be considered independently.

Under a conventional 32-bit address model and low-32-bit machine interpretation, the values at offsets 4 and 8 may coincide because multiplying by 2,048 and shifting left by 11 produce matching bit patterns. This equivalence is conditional, not a replacement for the distinct represented calculations. Pointer conversion is an additional qualification for the value at offset 4.

The shift of the first input is unsigned. At offset 20, only the low 32 bits of its left-shifted result are retained; original bits 21 through 31 are discarded.

No read-back, verification, bounds check, allocation, or rollback is represented. After the seventh write, execution reaches the invalid-instruction boundary. Completion of the writes is not evidence of a successful return.

### Coprocessor path

After the common address preparation, halfword write, and path decision, this path clears one byte.

The numerical destination is obtained by adding ten to the incoming 32-bit unsigned state word, modulo \(2^{32}\), and then converting that result into a pointer. The stored byte is zero.

The unsigned wraparound is established. Pointer interpretation, mapping, permissions, and access success remain separate unknowns.

If execution reaches the loop, each represented iteration:

- Derives an unsigned operand by logically shifting the current state word right by 11.
- Replaces the local state-word value with zero.
- Issues the coprocessor operation.
- Repeats without a represented exit.

The coprocessor operation receives six arguments in this order:

| Argument position | Supplied value |
|---:|---|
| 1 | Selector 8 |
| 2 | Selector 5 |
| 3 | Selector 4 |
| 4 | Derived unsigned operand |
| 5 | First incoming four-byte coprocessor-associated value |
| 6 | Second incoming four-byte coprocessor-associated value |

The selector values and their order are established; their architectural meanings are not.

The first derived operand is the incoming state word shifted right by 11. Under the represented local-state progression, subsequent iterations derive zero because the state word was reset before the preceding operation.

The byte clear occurs once before the loop, not once per iteration. None of the seven word writes occurs on this path.

The local reset does not establish a write to a global variable, an external saved register, or the byte-clear destination. Its established role is in the represented operand progression. No assumption is made that the coprocessor operation completes, preserves globals, leaves machine state unchanged, or permits another iteration.

### Coprocessor path still performs early address preparation

- The base pointer is prepared from 4,096 before the initial halfword write.
- After that write, the nonzero selector field chooses the coprocessor path.

There are no seven-word-path writes, but the earlier base-pointer calculation is not omitted.

### Unsigned byte-address wraparound

For incoming state word `0xFFFFFFF8` on the coprocessor path, adding ten produces `0x00000002` modulo \(2^{32}\).

The byte-clear pointer is formed from `0x00000002`, not from an unbounded sum above the 32-bit range. Whether that pointer designates writable storage remains unknown.

If execution reaches the first coprocessor operation, its derived operand is `0x001FFFFF`. Later represented operands are zero.

### Bit outside the selector field

First input `0x00200000` has bit 21 set but no bits 11 through 20 set. It selects the seven-word path.

The word at offset 0 remains `0x00200000`. The word at offset 20 is zero because the unsigned left shift discards the set bit.

### Maximum fourth input

Fourth input `0xFFFFFFFF` produces initial halfword value `0xFFFF` and numerical destination `0x10000007`.

The destination is odd. Success is conditional on the target supporting that access. If execution subsequently reaches the seven-word path, offset 12 receives `0x00FFFFFF`.

### Signed overflow affects both paths

For address selector 1,048,576, the early mathematical product is 2,147,483,648, outside the signed 32-bit positive range.

Neither path has an unconditional continuation guarantee from signed-language arithmetic alone. Choosing the coprocessor path does not remove this issue: the multiplication precedes path selection. Any example continuing with a low-32-bit product must explicitly assume that machine interpretation.

### Overlap and partial progress

If the initial halfword destination lies within a later word destination, the later completed word write may replace those bytes.

If an access fails before a later write, that later write is not required to have occurred. Earlier completed writes are not rolled back by any represented recovery mechanism.
