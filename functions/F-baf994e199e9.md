## Behavior

### Target selection and argument sourcing

The represented operation obtains the first field from the input record, uses that value as an address base, and locates a function-pointer slot 24 bytes beyond that base. The contents of that slot identify the indirect target.

The argument comes from the second integer-sized field of the original record. The representation does not pass the record address itself as the explicit argument. It also does not show the address of the second field being passed: the field’s value is supplied.

The target-slot displacement is a byte displacement. It is not an index of 24 entries. Calling it a particular numbered table entry would require an independently established entry width and table layout.

No masking, range restriction, alternate-slot selection, or argument transformation is explicit in the supplied representation. This does not establish the machine-level handling of integer-to-address conversion or argument extension.

### Observable ordering

The following dependencies are established:

- Reading the first field is necessary to determine the target-slot address.
- Reading the target slot is necessary to obtain the selected execution target.
- Reading the second field is necessary to obtain the explicitly represented argument.
- The selected target receives that argument when control is transferred.

The supplied material does **not** establish a complete order between reading the second field and evaluating the target-selection expression. A contract requiring the argument read to occur before, between, or after the target-selection reads would exceed the evidence.

This distinction matters if the record or target slot is concurrently modified, resides in memory with read side effects, or can fault. No synchronization, snapshot guarantee, or volatile-access semantics are established. Stable ordinary memory is the condition under which the represented dispatch relationship can be interpreted without those additional uncertainties.

The representation contains one explicit indirect invocation. It shows no retry, secondary dispatch, fallback target, or conditional bypass.

If the selected target does not return, no later completion is established. If the target faults, terminates execution, or performs a nonlocal transfer, the supplied representation shows no recovery mechanism.
