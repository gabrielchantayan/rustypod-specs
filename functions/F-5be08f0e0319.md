# F-5be08f0e0319

## Purpose

F-5be08f0e0319 reports whether either of two selected bytes is nonzero, with the second selection considered only when the first byte is zero.

The selections depend on two separate index fields in caller-addressed storage and an externally stored lookup origin. The primary selection is sufficient to produce a true result. The secondary selection cannot affect the result when the primary byte is nonzero.

This is a byte-level predicate. The evidence does not identify the application meaning of either index, either selected byte, or the surrounding storage. Interpreting the result as validity, availability, permission, or any other domain-specific property would require additional evidence.

## Interface

### Input and referenced storage

The function accepts one unsigned integer-shaped value that it uses as an object address. It does not accept an explicit length, index range, or lookup-table extent.

Two fields relative to that address participate in the behavior:

| Field | Byte offset from object address | Represented interpretation | When needed |
|---|---:|---|---|
| Primary index | 36, hexadecimal 0x24 | Signed integer | Every normal invocation |
| Secondary index | 28, hexadecimal 0x1c | Signed integer | Only after a zero primary byte |

A separate shared location supplies the lookup origin. The supplied representation is consistent with 32-bit unsigned address values and 32-bit signed index fields. Under that model, each index occupies four bytes. The selected values are individual bytes, conventionally eight bits in this representation.

These widths describe the apparent representation, not an independently verified target ABI. Exact integer widths, address width, byte order, alignment requirements, and pointer-conversion rules remain **documented_only**.

The lookup layout is established only to the following extent:

- Adjacent integer index values change the calculated selection position by 20 bytes.
- The primary selection has an additional displacement of 16 bytes.
- The secondary selection has an additional displacement of negative 664 bytes.
- Only one byte at each selected position is inspected.

A 20-byte stride does not establish the existence of a declared 20-byte record type. Nor does it establish that the shared origin is an allocation boundary.

### Result

| Primary selected byte | Secondary selected byte | Result |
|---|---|---|

All required address calculations must be valid under the target’s arithmetic and memory-access rules. There is no visible validation of object identity, storage size, alignment, index bounds, or nullness.

## Behavior

### Selection geometry

Under exact arithmetic, the primary selected address is the lookup origin plus 20 times the primary index, plus 16 bytes.

Under the same interpretation, the secondary selected address is the lookup origin plus 20 times the secondary index, minus 664 bytes.

Both index fields are interpreted as signed. Negative indices are therefore possible inputs to the calculations; the function does not reject them. Zero is also an ordinary index value, not an established sentinel.

For example:

| Index condition | Selected position relative to lookup origin |
|---|---:|
| Primary index is zero | 16 bytes above the origin |
| Primary index is negative one | 4 bytes below the origin |
| Secondary index is zero | 664 bytes below the origin |
| Secondary index is 34 | 16 bytes above the origin |

An address below the lookup origin is not, by itself, evidence of an error. Whether it is readable depends on storage whose extent and placement are not supplied.

The secondary displacement is exactly 34 strides earlier than the primary displacement. Consequently, when the same origin is used, a secondary index 34 greater than the primary index selects the same address, provided the arithmetic is valid. This relationship describes address geometry only. It does not prove that the selections belong to one logical table.

### Decision and conditional access

A nonzero primary byte determines a true result without consulting the secondary index or secondary byte. Every nonzero byte pattern satisfies this condition; a possible signed interpretation of the primary byte does not change its equality or inequality with zero.

A zero primary byte makes the secondary selection necessary. The secondary byte is interpreted as unsigned and widened to an unsigned integer before its zero/nonzero value determines the result. Under the apparent eight-bit byte model, secondary values from 1 through 255 all produce true, and zero produces false.

The widening does not preserve the original address argument as a separate result. It also does not modify the caller’s argument storage: the visible replacement of a value within the function is not a write through the supplied address.

There is no visible additional decision based on the relationship between the two indices. In particular, neither index validates, limits, or substitutes for the other.

### Observable ordering

The primary byte is obtained and tested before the conditional secondary access. On the secondary path, the value determining the final result comes from the secondary selected byte.

The evidence does not establish an order between reading an index field and obtaining the lookup origin for the same selection. Both contribute to an address expression; their relative evaluation order must not be added to the contract.

The lookup origin is referenced separately for the two selections. This does not establish either:

- A single stable origin value shared by both selections; or
- Two guaranteed physical reads of the shared location.

There is no explicit snapshot or synchronization mechanism. A description using one unchanged origin across both selections is conditional on a stable environment, not an unconditional guarantee.

Likewise, the conditional-access description identifies the logical accesses required by the represented function. It does not establish a hardware speculation policy, device-read protocol, or exact bus transaction sequence.

### Arithmetic boundaries

The stride multiplication uses a signed index and a positive stride of 20. Under the apparent signed 32-bit model, multiplication alone is representable for indices from −107,374,182 through 107,374,182, inclusive. Values outside that interval exceed the signed range at the multiplication stage.

That interval is not a valid-index guarantee. Subsequent address arithmetic, pointer conversion, and actual storage extent impose separate requirements.

The evidence does not justify selecting wraparound, saturation, trapping, or a particular Boolean result for signed multiplication overflow. The precise arithmetic rules for combining the product with the shared origin also depend on the origin’s type and the target environment.

Object-relative field addressing has its own boundary concerns. Even a representable lookup product does not make a field access valid if adding its object offset produces an unsupported address or crosses inaccessible storage.

Additional acceptance conditions cover layout, conditional access, and boundaries:

- **Negative primary index.** A primary index of negative one selects four bytes below the lookup origin. If that byte is readable and nonzero, the result is true without a secondary selection.

- **Secondary index zero.** After a zero primary byte, the secondary selection is 664 bytes below the lookup origin. A readable nonzero byte there produces true. There is no special rejection of the zero index.

- **Same selected address.** If the secondary index is 34 greater than the primary index, both selections use the same origin, and the selected byte remains stable, a zero primary byte is followed by a zero secondary byte. The result is false.

- **Same address with changing contents.** Address equality alone does not require false. If the environment permits the selected byte to change between the two logical reads, the result depends on the values actually obtained. The function supplies no snapshot guarantee.

- **Invalid object address.** No graceful result is specified. In particular, a null input is not an accepted request to return false.

- **Signed multiplication overflow.** Under the apparent 32-bit model, an index of 107,374,183 exceeds the signed range when multiplied by 20. This contract assigns no Boolean result to that case.
