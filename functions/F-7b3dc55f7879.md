# F-7b3dc55f7879

## Purpose

F-7b3dc55f7879 conditionally records an opaque 32-bit value in an object. A nonzero entry gate selects an immediate write and return. A zero entry gate selects a longer sequence of dependency calls, temporary-storage preparation, an optional operation, and eventual recording of the same value.

The optional operation is controlled by a mode result. Its fifth argument is either zero or a two-byte object-field value. Selecting that field requires two separate reads: first an externally referenced displacement value, then the two-byte field at the resulting object-relative address. Both reads occur only on the selected branch, after a third accessor call.

These are structural observations. Interpreting the gate as a busy flag, the recorded value as a pending request, or the temporary storage as a resource-management object would be inferred intent, not an established behavioral guarantee.

## Behavior

### Entry gate

The first explicit object access is a one-byte read at object + 0x10C.

If the gate is nonzero, the function writes the supplied four-byte value to object + 0x104 and returns immediately. It invokes no dependencies and performs no other explicit object access on this path.

All nonzero gate values select the same behavior. The function neither rereads nor explicitly writes the gate later.

### Zero-gate initialization and lookup

If the gate is zero, the function first writes the byte argument to object + 0x108.

It then invokes F-1f46730b1ced with the address object + 0xD4 and the supplied 32-bit value. The returned 32-bit result is retained and compared with zero.

A zero result selects F-a817d8d58c10. The supplied static representation marks that dependency as non-returning. No normal continuation after that call is established. The byte-field write has already occurred; the later record-field write has not.

A nonzero result permits the remaining sequence. This saved lookup result is reused; no second lookup is shown.

### Processing the lookup result

For a nonzero lookup result, the following calls occur in order:

1. F-d2f99870cc43 receives the saved lookup result and returns an opaque 32-bit value.
2. F-bf557f07179f receives the object address and that returned value.
3. F-fa8898fa75ae receives the saved lookup result.

The saved lookup result may subsequently be passed to F-818c773e8c8a. The call to F-fa8898fa75ae therefore must not be described as ending this function’s use of that result. Whether the dependency releases, invalidates, retains, or otherwise affects an associated resource is unknown.

No dependency in this sequence is assumed to preserve object contents, globals, or the external displacement storage.

### Preparing temporary storage

The function calls F-fdd8589eca2d and reads one byte at offset 0x2C from its returned address. That byte is saved.

It calls F-fdd8589eca2d again and reads four bytes at offset 0x28 from this second returned address.

F-2c5a9f9c1eb3 then receives, in order:

1. The address of the 92-byte temporary region.
2. The four-byte value read through the second accessor result.
3. The saved byte read through the first accessor result.

These are distinct accessor calls and distinct observations. Their returned addresses need not be equal. The second call cannot retroactively change the byte already saved from the first result.

No direct initialization of the temporary region is visible before F-2c5a9f9c1eb3. Which bytes that dependency initializes, and what invariants it establishes, are unknown.

### Mode decision and optional operation

After temporary preparation returns, F-5c5958cfd5fe is called. Its 32-bit result is compared with 8.

If the result is exactly 8:

- There is no third accessor call.
- There is no explicit read of the external displacement value.
- There is no conditional two-byte object-field read.
- F-818c773e8c8a is not invoked.
- Execution proceeds to final recording.

For every other mode result, the function invokes F-fdd8589eca2d a third time. Its returned value is saved as the optional operation’s first argument.

The suppression selector determines which argument-selection branch is taken. On the zero-selector branch, the operation argument is tested after the third accessor returns. Selection is:

| Suppression selector | Operation argument | Fifth argument |
|---|---|---|
| Nonzero | Any value | 16-bit zero |
| Zero | Zero | 16-bit zero |
| Zero | Nonzero | Value obtained by the two-read sequence below |

The nonzero-selector and zero-operation cases do not explicitly read the external displacement storage or the selected two-byte field.

When the selector is zero and the operation argument is nonzero, the function performs the following ordered observations after the third accessor returns:

1. It reads the externally referenced displacement value.
2. It uses that obtained value with the object address to determine the selected field address.
3. It reads two bytes from that object-relative address.

The external read is not an entry-time snapshot or a constant established by this function. Earlier dependencies, including the third accessor, may change its contents. The displacement used is the value evaluated after those calls. Likewise, the two-byte field is read at that later point, not captured before the accessor.

When the mode is not 8, F-818c773e8c8a receives:

1. The third accessor result.
2. The temporary-region address.
3. The saved nonzero lookup result.
4. The original 32-bit operation argument.
5. The selected 16-bit value.

Neither a nonzero suppression selector nor a zero operation argument suppresses this call. They affect only the fifth argument. No return value from the operation is used.

### Final recording and final call

After the mode-dependent section completes normally, the function writes the original supplied value to object + 0x104.

It then invokes F-920630e53283 with the temporary-region address and returns.

This final dependency is reached on both normally completing zero-gate mode branches. It is not called on the immediate-return path or before the zero-lookup failure call.

The record-field write precedes the final dependency. Because that dependency’s side effects are unknown, the guaranteed observation is the ordered write, not an unconditional assertion that the field still contains the supplied value when the function returns.

## Acceptance examples

These are conditional acceptance criteria derived from static evidence, not executed tests.

### Nonzero gate

For a valid object with gate 1 or 255, the supplied four-byte value is written to object + 0x104, and the function returns without dependency calls. There is no explicit write to object + 0x108 and no external-displacement read.

### Zero lookup result

For a zero gate and lookup result zero, the byte-field write precedes F-1f46730b1ced, followed by F-a817d8d58c10. No normal return or later record-field write is established.

This does not require the record field to remain unchanged if a dependency independently modifies it.

### Mode equal to 8

For a zero gate, nonzero lookup result, and mode 8, normal execution includes two accessor calls, temporary preparation, final recording, and the final temporary-region call. It excludes the third accessor, external-displacement read, selected-field read, and optional operation.

Inaccessible displacement storage alone does not violate this function’s explicit memory-access requirements on this branch; dependencies have separate unknown requirements.

### Nonzero suppression selector

For a mode other than 8 and any nonzero selector, the third accessor and optional operation occur. The fifth argument is 16-bit zero, regardless of the operation argument. Neither the external displacement nor the selected field is explicitly read.

### Zero operation argument

For a mode other than 8, zero selector, and zero operation argument, the third accessor occurs before the operation-argument test. The optional operation receives zero as its fourth argument and 16-bit zero as its fifth. Both conditional memory reads are omitted.

### Changed displacement during the third accessor

Suppose the mode is not 8, the selector is zero, and the operation argument is nonzero. If the third accessor changes the external displacement from one valid value to another before returning, the subsequent external read must observe the later value under the assumed execution model.

The function then reads two bytes from the object-relative address determined by that later displacement. Using an entry-time displacement or a cached pre-accessor value would not match the established sequence.

### Changed selected field

On the same selected branch, if earlier dependencies change the two-byte field that the subsequently read displacement identifies, the value supplied to the optional operation is the later field value. The external-displacement read and field read remain separate required observations.

### Distinct accessor results

If the first two accessor calls return different valid addresses, temporary preparation receives the byte from offset 0x2C of the first result and the four-byte value from offset 0x28 of the second. Replacing both with reads through one cached result would change behavior.
