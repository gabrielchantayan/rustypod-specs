# F-6518403de3d0

## Purpose

F-6518403de3d0 calls a prerequisite dependency, clears bit 15 of a selected 32-bit word in a fixed-address region, and conditionally writes zero to a byte in an indirectly referenced state object.

Address selection depends only on the selector’s low eight bits. The later state-object comparison uses the entire unsigned 32-bit selector. Selectors can therefore address the same word while producing different conditional state updates.

The established behavior is a dependency call followed by a word read–modify–write and a conditional byte store. Describing these operations as disabling a hardware resource or clearing an activity flag would be **inferred intent**, not established behavior.

## Behavior

### Dependency execution and memory-state timing

F-ddf4a1f94e38 is called before the selected-word access and before the state-object comparison. The visible call supplies no explicit arguments, and this function consumes no result.

No preservation guarantee for relevant memory follows from that call. The dependency may change the selected word, the state-pointer cell, or referenced storage; its actual effects are unknown.

Consequently, the word transformation depends on the value **read after the dependency returns**, not necessarily on the value present at function entry. Likewise, the comparison depends on the pointer and byte obtained later, after the selected-word store. Entry-state values predict the result only under an additional preservation assumption.

If the dependency does not return, the subsequent operations are not reached. No local recovery or alternative path is shown.

### Word selection

Bits 0–6 of the selector form an index in the range **0–127**. Bit 7 chooses a displacement:

- Bit 7 clear: **0xB00**.
- Bit 7 set: **0x900**.

The selected word address is:

**0x38400000 + displacement + 0x20 × index**

Bits 8–31 do not affect this address calculation. They are neither rejected nor used to extend the index.

The scaled index ranges from **0x000** through **0xFE0**. The resulting word-start addresses are:

| Selector bit 7 | First word start | Last word start | Spacing |
|---|---|---|---|
| Clear | 0x38400B00 | 0x38401AE0 | 0x20 bytes |
| Set | 0x38400900 | 0x384018E0 | 0x20 bytes |

The largest selected word occupies **0x38401AE0–0x38401AE3**. These bounded address calculations do not overflow a 32-bit unsigned address space.

Only the selected 32-bit word is accessed. The remaining bytes of its 0x20-byte slot are not cleared or traversed.

The two address sets overlap. For example:

- Selector **0x00** selects **0x38400B00**.
- Selector **0x90** also selects **0x38400B00**.

More generally, a clear-bit-7 index from 0 through 111 aliases a set-bit-7 index that is 16 greater. The displacements must not be interpreted as proving disjoint banks.

### Word read–modify–write

The function reads the selected 32-bit word and writes back that read value masked with **0xFFFF7FFF**.

For ordinary memory, absent intervening modification:

- Bit 15 is cleared.
- All other bits retain their values from the read.
- A word whose bit 15 was already clear is written back unchanged.

The write occurs even when masking does not change the value. An unchanged final value does not mean that no store occurred.

This is a read followed by a masked write, not an established atomic bit-clear operation. There is no visible retry or conflict detection. An intervening update can be overwritten by the value computed from the earlier read.

For device-backed memory, the established behavior remains the read and masked write. The supplied evidence does not establish register-specific read effects, write-one-to-clear behavior, or the physical outcome of writing the masked value.

### Comparison after the word write

After the word store, the function obtains an object address from the global state-pointer cell and reads the unsigned byte at offset **+9**.

That byte is compared numerically with the **entire unsigned 32-bit selector**, not merely its low eight bits.

Because the byte is in the range 0–255:

- A selector in the range 0–255 can match.
- A selector greater than 255 cannot match.
- Matching low eight bits are insufficient when any higher selector bit is set.

For example, selector **0x100** addresses the same word as selector **0x00**, but cannot equal a comparison byte of zero.

### Conditional byte store

If the comparison succeeds, the destination is expressed through the global state-pointer cell again, and one zero byte is written at object offset **+5**.

If the comparison fails, this function performs no conditional store to offset +5. That does not establish that the byte is unchanged from function entry: the dependency or another actor may have modified it.

The supplied representation does not retain the comparison object as a guaranteed destination. If separate evaluations observe different state-pointer values, the comparison may concern one object while the store targets another. Whether such changes can occur, and whether execution performs distinct pointer-cell loads, are not established by the representation alone.

The selected-word read–modify–write occurs before this decision and is not conditional on a match.

## Side effects

The visible sequence is:

1. Call F-ddf4a1f94e38.
2. Read the selected 32-bit word.
3. Write the masked 32-bit value to the selected address.
4. Obtain the comparison object address and read its byte at +9.
5. On equality, evaluate the conditional destination and write zero as one byte at +5.
6. Return without an explicit value.

This is the ordering represented by the supplied static evidence. It does not establish processor barriers, device-bus ordering, atomicity, or synchronization with other actors.

The function contains no explicit allocation, release, ownership transfer, or lifetime-management operation. Reading and writing the regions does not establish ownership. The dependency’s allocation, release, and lifetime effects remain unknown.

There is no visible logging, error reporting, selector rejection, or recovery from failed accesses. High selector bits are ignored for addressing but remain significant for comparison.

The word write and conditional byte store are separate operations. No all-or-nothing guarantee is established. If execution fails after the word write, that earlier operation may already have occurred.

## Acceptance examples

These are conditional examples derived from static evidence, **not executed tests**.

For every example below, assume the dependency returns and the relevant accesses are valid when performed. Word values are specified **at the selected-word read after the dependency returns**. Comparison-byte values are specified **at the later byte read after the word write**. They are not claims about function-entry contents.

Unless an example states otherwise, assume ordinary memory, a stable state pointer during the comparison and conditional store, and no intervening changes that invalidate the stated outcomes. These conditions do not assert that the dependency preserved any entry-state values.

### Matching selector

Given selector **0x03**, the selected word is at **0x38400B60**.

If the post-dependency word read yields **0x1234FFFF**, and the later comparison-byte read yields **0x03**:

- The function writes **0x12347FFF** to the selected word.
- Equality succeeds.
- The function writes one zero byte at state-object offset +5.

The same result is not established merely by those values existing at function entry.

### Nonmatching selector with bit 7 set

Given selector **0x83**, the selected word is at **0x38400960**.

If the post-dependency word read yields **0xFFFFFFFF**, and the later comparison-byte read yields **0x03**:

- The function writes **0xFFFF7FFF** to the selected word.
- Equality fails because **0x83 ≠ 0x03**.
- This function performs no conditional store to offset +5.

The last condition does not imply that the dependency left offset +5 unchanged.

### High selector bits

Given selector **0x100**, the selected word is **0x38400B00**, the same address selected by zero.

If the post-dependency word read yields **0x00008001**, and the later comparison-byte read yields zero:

- The function writes **0x00000001** to the selected word.
- Equality fails because **256 ≠ 0**.
- No conditional store to offset +5 occurs.

Indeed, no possible unsigned-byte value can match this selector.

### Already-cleared word

If the selected-word read **after the dependency returns** yields **0x00000001**, the function still writes **0x00000001** back to that address.

For selector **0x03**, if the later comparison-byte read yields **0x03**, the conditional zero-byte store also occurs. If it yields another value, the store does not occur. Whether the word changed has no bearing on that decision.

### Dependency mutation

Suppose selector **0x03** is used. The selected word contains **0xFFFFFFFF** at function entry, but the dependency changes it so that the subsequent word read yields **0x12340000**.

The function writes **0x12340000**, not **0xFFFF7FFF**. The mask applies to the value actually read after the dependency, not to an entry-state snapshot.

Likewise, a comparison byte that equals **0x03** at entry does not guarantee a match. If the later comparison-byte read yields **0x04**, no conditional store occurs.

### Overlapping selections

Selectors **0x00** and **0x90** both address **0x38400B00**. A later comparison-byte value of zero matches the first selector but not the second. Address equality therefore does not imply identical overall behavior.

### Changing state pointer

Conditionally, if the comparison reads **0x03** from one object for selector **0x03**, and the subsequent destination evaluation observes a different object address, the zero-byte store targets offset +5 of that later object.

This example requires distinct observations of the pointer cell; their runtime occurrence is not established.
