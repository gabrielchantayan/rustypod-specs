# F-f80f1d4c41e3

## Purpose

F-f80f1d4c41e3 performs three ordered, 32-bit stores using one caller-supplied value and destinations obtained from global state.

The established effect is to:

1. Store the supplied value at the beginning of a globally selected memory region.
2. Store a globally supplied 32-bit value 32 bytes into the region selected at entry.
3. Store the 32-bit value two at a destination 12 bytes beyond a separately obtained global base address.

The function has no explicit return value. Its observable result is the memory modified by these stores.

The final store may represent a state transition, and the first two stores may populate associated data. Those interpretations are inferred intent, not established semantics. The evidence does not identify a state machine, record type, initialization protocol, or meaning for the value two.

## Interface

**Input:** One 32-bit value. Its interpretation is unspecified. The function does not visibly distinguish integers, addresses, flags, handles, or other bit patterns. It does not dereference the input as a pointer.

**Output:** No explicit return value or success indicator.

**Global inputs:** The operation uses three global roles:

- A **primary address source**, providing the base address used for the first store and captured for the second.
- A **secondary value source**, providing the 32-bit payload for the second store.
- A **final address source**, providing the base address to which a 12-byte displacement is applied for the third store.

These names describe roles in the contract, not source-level identifiers. The supplied evidence does not establish that the underlying storage locations are independent or that destination writes cannot overlap them.

## Behavior

### Address capture and first store

The function first captures the address supplied by the primary address source.

It then stores the input as a 32-bit value at the address supplied by that same global source. With no intervening external modification, this is the captured address.

The visible representation distinguishes the capture from the first store’s destination expression. It does not establish the exact number of machine-level reads of the primary address source. Consequently, behavior under concurrent changes between those operations is not specified here.

The captured address remains the basis of the second destination. A later change to the primary address source does not, by itself, replace that captured address.

### Second store

After the first store, the function obtains the 32-bit payload from the secondary value source and stores it 32 bytes beyond the captured primary base.

This ordering matters if the first destination overlaps the secondary value source. In that case, the first store can change the payload subsequently obtained for the second store. The contract does not assume that all global inputs are snapshotted at entry.

The input undergoes no visible arithmetic, masking, comparison, or conversion before its first store. Likewise, the secondary payload is transferred as a 32-bit value without visible transformation.

### Final store

After the second store, the function obtains the base address supplied by the final address source. It stores the 32-bit value two at byte offset 12 from that base.

This base is not visibly captured before the earlier stores. If either earlier store changes the final address source, the final destination can therefore depend on that changed value.

The value two is a complete 32-bit stored value. The evidence does not support describing the operation as setting a single bit, incrementing a counter, or preserving other bits of the previous destination value.

### Completion and control flow

The visible body has no conditional branch, loop, explicit validation, or explicit early return. On the ordinary successful path, all three stores occur in the stated order, followed by return.

There is no explicit check for null addresses, invalid addresses, insufficient storage, overlapping destinations, or pointer-arithmetic limits. There is also no explicit error return, rollback, or recovery path.

If an access cannot complete, behavior depends on the execution environment. The evidence does not establish whether execution traps, faults, resets, or behaves otherwise. It provides no basis for promising that earlier stores are undone.

### Aliasing and arithmetic boundaries

The function does not visibly reject overlapping storage. Aliasing can affect both later source values and the final contents of destinations.

If two stores reach the same location and both complete, the later store determines the final value there, subject to any external interference. Earlier stores still matter: they may change data read before a later store occurs.

The established access width is 32 bits. The two destination displacements are 32 bytes and 12 bytes. Pointer width, address wrapping, and behavior at the address-space boundary are not established. A contract for successful ordinary execution therefore requires meaningful, accessible destination addresses rather than assuming a particular wrapping rule.

## Acceptance examples

These are conditional acceptance criteria derived from static evidence. They are not reports of executed tests.

### Independent ordinary destinations

Assume that both address sources remain stable, all accesses are valid, and no destination overlaps another destination or a global source. Let the input be `0x12345678` and the secondary payload be `0xA5A5A5A5`.

After ordinary completion:

- The primary base contains the 32-bit value `0x12345678`.
- The location 32 bytes beyond the captured primary base contains `0xA5A5A5A5`.
- The location 12 bytes beyond the final base contains the 32-bit value two.

This example specifies values, not byte order.

### Zero input

Under the same validity and independence assumptions, an input of zero produces a zero first store. The second and third stores still occur. There is no visible zero-input bypass.

### Final destination overlaps the first destination

Assume valid, stable addressing and that the final destination equals the first destination. Also assume the earlier stores do not alter the sources used to determine subsequent accesses.

The shared location receives the input first and two last. Its final value is two. The second store still occurs between those writes.

### First store changes the secondary payload source

Assume the first destination is the storage location supplying the secondary payload, with valid accesses and no external interference.

The first store replaces that source with the input. The subsequent payload read therefore obtains the newly stored input, which is then written 32 bytes beyond the captured primary base.

### Second store changes the final address source

Assume the second destination overlaps the final address source and that the resulting stored representation supplies a valid address.

The final destination is determined from the changed address source. A requirement that the final store use the entry-time final base would not match the visible operation.
