# F-081f21d13249

## Purpose

F-081f21d13249 coordinates an initial context-dependent operation, a delegated operation on a caller-supplied object, and optional follow-up work. It returns the delegated operation’s 32-bit result.

For a nonzero control argument, the function also invokes a notification-like dependency and may copy a 16-bit field from the supplied object into a context object. That copy is conditional on an earlier source-field observation being nonzero and a context-field observation being zero.

These are structural descriptions, not established application semantics. The supplied evidence does not identify the object types, the meaning of either field, or the purpose of the control argument. “Context” and “notification-like” are descriptive labels, not guarantees about dependency behavior.

### Control-dependent dependency call

### Conditional field propagation

The function next reads the 16-bit field at object offset `0xE6` and tests whether it is nonzero.

That read occurs even when the control argument is zero. A zero control argument therefore does not make the function’s own object-field access disappear.

The remaining conditional work requires both:

- The observed object field is nonzero.
- The control argument is nonzero.

If either requirement is false, the function performs no further local dependency call or field access and returns the saved delegated result.

If both requirements hold, the function calls F-fdd8589eca2d again and reads the 16-bit field at offset `0x80` from the returned address.

If that observed context field is nonzero, no direct write occurs. The function returns the saved delegated result.

If the observed context field is zero, the function calls F-fdd8589eca2d a third time. The address returned by this third invocation supplies the destination base. The function then reads the object’s 16-bit field at offset `0xE6` again and writes those 16 bits to offset `0x80` of the third returned address.

The second object-field read is distinct from the first. The copied value is the value available at the later read, not necessarily the value that enabled entry into this path.

Likewise, the destination comes from the third context-provider invocation, not the second. The function does not establish that these two addresses are equal.

## Acceptance examples

These are conditional acceptance criteria derived from static evidence, not executed tests. Unless stated otherwise, they assume valid storage and normal completion of every dependency.

1. **Zero control still reads the object field.**  
   With control `0`, the function performs the initial context-provider call, the three-argument dependency call, and the delegated operation. It skips F-5c5958cfd5fe, then reads object offset `0xE6`. It performs no later context-provider call and no direct field write. It returns the delegated result.

2. **A nonzero control is forwarded unchanged.**  
   With control `-1`, the delegated operation receives `-1`. F-5c5958cfd5fe is called. Local conditional behavior treats this value as nonzero, just as it would treat `1`.

3. **A zero source field prevents propagation.**  
   With nonzero control and an observed source field of zero, F-5c5958cfd5fe has already run before that observation. The function makes no second context-provider call and performs no direct write.

4. **An occupied observed context field prevents the write.**  
   With nonzero control, a nonzero first source observation, and a nonzero field at offset `0x80` of the second provider result, the provider is called twice in total. There is no third provider call and no direct write.

5. **A stable context can receive the source field.**  
   If the second and third provider calls return the same valid address, its observed field is zero, and the source remains `0x1234`, the function writes `0x1234` to that address at offset `0x80`. It still returns the delegated result.

6. **The checked and written contexts can differ.**  
   If the second provider result identifies context A with a zero field, while the third identifies context B with field `0x9999`, the function writes to B without checking B’s field. Subject to aliasing, A remains unchanged by the direct write.

7. **The copied source can differ from the enabling observation.**  
   If the first source read observes `7` but the third provider call changes the source to zero, the later copy writes zero. The earlier nonzero observation does not require the copied value to remain nonzero.

8. **A delegated error-like result does not cause an early return.**  
   If the delegated operation returns a 32-bit value that its caller interprets as failure, this function still performs the subsequent conditional work. On normal completion, it returns that same value.
