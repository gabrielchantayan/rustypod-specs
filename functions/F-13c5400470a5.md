# F-13c5400470a5

## Purpose

F-13c5400470a5 conditionally performs indirect operations on a caller-supplied object, called the **subject**, and on two objects obtained from F-b7af80e829ec.

F-024726875d66 supplies the entry gate. Only a result equal to 3 enables the remaining work. On that path, the function:

- Obtains an object and invokes its dispatch-table entry at byte displacement 180.
- Obtains an object again and invokes its dispatch-table entry at byte displacement 288.
- If the second indirect operation returns nonzero, invokes a subject operation and then clears one byte within the subject.
- Performs two final subject operations.

Before the final pair, the function captures a 32-bit value from an external data cell designated **C**. The penultimate operation receives a **separate read of C**. The final operation receives the earlier captured value. These are two represented reads, not one shared read.

This describes established static behavior. The application meanings of the gate, operations, external data, and cleared byte are unknown.

## Behavior

### Entry gate

F-024726875d66 is called first, before any visible subject access or call to F-b7af80e829ec.

Its represented 32-bit integer result is compared with exactly 3:

- A result other than 3 causes an immediate return.
- A result equal to 3 enables the remaining sequence.

This is equality, not a nonzero test. Results such as 1, 2, and 4 do not enable the sequence.

The rejected path has no direct memory write in the visible body. Effects inside F-024726875d66 remain possible.

### First dependency-object operation

The function calls F-b7af80e829ec and treats its result as an object pointer.

Through that object’s leading table address, it resolves the entry at byte displacement 180 and invokes it with two represented argument positions:

1. The obtained object pointer.
2. Integer zero.

The indirect result is not used by the visible body.

The next operation obtains another result from F-b7af80e829ec rather than reusing the first result.

### Status-producing operation

After the displacement-180 operation returns, the function calls F-b7af80e829ec a second time.

Through this second result, it resolves the table entry at byte displacement 288. The supplied representation shows no explicit arguments for this invocation. In particular, it does not explicitly pass the second object pointer as a receiver.

That absence is a fact about the representation, not proof that the actual target consumes no receiver or other implicit register state.

The represented 32-bit integer result controls the optional subject operation:

- Zero skips the optional subject operation and the byte clear.
- Any nonzero result enables both.

No nonzero value receives separate treatment.

### Conditional subject operation

When the status result is nonzero, the function invokes the subject’s table entry at byte displacement 88. The represented invocation has five argument positions:

1. The subject pointer.
2. A 32-bit read of A.
3. A 32-bit read of B.
4. A function address read from the subject’s table entry at displacement 88.
5. An incoming 32-bit register value whose assignment is not visible in this function.

The fourth position is an explicit represented argument, even though its source is the same table location used for dispatch. It must not be omitted as redundant. The representation does not establish a complete ordering of the target lookup and argument reads, so equality between separately obtained target-address values must not be assumed under changing storage.

The fifth position is not established as a constant, an initialized local value, or a declared input parameter. Its origin, meaning, and validity remain unresolved.

After this invocation returns normally, the function writes zero to the single byte at subject displacement 28.

The call precedes the store. If the call changes that byte and leaves the storage valid, the subsequent store overwrites it with zero. If the call does not return normally, the byte store and final pair are not reached through the visible control flow.

### Capture and final pair

After the status branch has completed, the function reads C and retains that 32-bit value. On the nonzero-status path, this capture occurs after the conditional subject operation and byte clear.

The penultimate subject operation then resolves the subject’s table entry at byte displacement 88 and receives:

1. The subject pointer.
2. A **new, separate 32-bit read of C**.
3. A 32-bit read of D.

The captured value is not the represented source of this call’s second argument.

After the penultimate operation returns, the final subject operation again resolves the subject’s table entry at byte displacement 88 and receives:

1. The subject pointer.
2. The value from the **earlier capture of C**.
3. A 32-bit read of E.

Consequently:

- C is read twice in the visible sequence: once for retention and once for the penultimate call.
- Only the final call explicitly uses the retained value.
- The two calls’ second arguments are not required to be equal.
- Mutation of C during the penultimate operation does not replace the already captured value used by the final operation.
- E is read for the final invocation after the penultimate operation returns; it is not captured before that operation.

There is no explicit intervening dependency call between the capture and the separate C read for the penultimate operation. Nevertheless, the represented reads must remain distinct. Equality requires additional assumptions about storage stability and read semantics.

The subject’s dispatch target is resolved separately for each operation. The body does not cache one target across the subject calls. Changes to the subject’s table address or relevant entry can therefore affect later dispatches, provided the later accesses remain valid.

The terminal indirect operation is represented as a call followed by return, but its low-level transfer recovery is uncertain. The required final operation is visible; its exact call-versus-tail-transfer mechanism is not established.
