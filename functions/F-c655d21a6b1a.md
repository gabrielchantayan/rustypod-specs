# F-c655d21a6b1a

## Purpose

F-c655d21a6b1a processes a signed movement value using mutable state, conditionally updates a movement accumulator and a numeric state field, and dispatches a direction together with an event flag. A later condition can trigger additional state preparation and a sequence of dependency calls.

The established contract concerns explicit reads, writes, comparisons, calls, and their ordering. Describing the object as a selectable control, the numeric operations as conversions, or the final sequence as a settling transition is inferred intent, not an established semantic contract.

Every visible normal-return path returns the 32-bit value **1**. This is not evidence that a movement occurred, that a dependency succeeded, or that preparation ran.

## Behavior

### Movement observation and boundary checks

The function initializes a local 32-bit direction result to zero and calls F-8bb3020950cd with the event object. Only after that call returns does it read movement at event offset `0x0C`.

The movement used for branching is therefore a post-call observation, not necessarily the entry-time value.

For **negative movement**:

- The selection field at `0x124` is interpreted as signed.
- If selection is less than 1, accumulation and numeric processing are skipped. Direction remains zero.
- Otherwise, movement is added to the signed accumulator at `0x128`.
- If the computed sum is strictly below −12, direction becomes `0xFFFFFFFF`.
- The computed sum is written to `0x128`, including when it crosses the threshold.
- Numeric processing runs unless the sum is strictly below −12.

For **zero or positive movement**:

- The count field at `0x0A8` is reduced by one using 32-bit unsigned subtraction.
- Selection at `0x124` is interpreted as unsigned and compared against that limit.
- If selection is greater than or equal to the limit, accumulation and numeric processing are skipped. Direction remains zero.
- Otherwise, movement is added to the signed accumulator.
- Direction becomes 1 if the computed sum is strictly above 12, and zero otherwise.
- The computed sum is written to `0x128`.
- Numeric processing runs unless the sum is strictly above 12.

The threshold comparisons are strict. A sum of −12 is accepted on the negative branch; a sum of 12 is accepted on the nonnegative branch.

The threshold tested depends on movement’s sign, not the resulting accumulator’s sign. Negative movement can therefore reach numeric processing with an accumulator above 12. Nonnegative movement can reach it with an accumulator below −12.

Zero movement follows the nonnegative branch and is not inherently a no-op.

### Numeric processing and global observations

Numeric processing occurs only when the applicable selection boundary permits accumulation and the applicable threshold is not crossed.

Both movement branches begin this sequence by calling F-b3a54d881220 with no explicit argument in the supplied representation. Its result is represented as 64 bits.

After that call returns, the function prepares a call to F-c4b34006a13c with these arguments, in argument-position order:

1. Low 32 bits of the preceding result.
2. High 32 bits of that result.
3. The value read from G-01.
4. The value read from G-02.
5. Opaque argument A.
6. Opaque argument B.

Argument-position order does not establish evaluation order. In particular, the representation does not establish whether G-01 or G-02 is read first.

These are call-time global observations. They are not entry-time captures, and no constancy is established. F-b3a54d881220 or earlier dependencies may modify either location before these reads. The two branches use the same locations, but need not observe the same contents across invocations.

The branches then differ:

- On the **negative branch**, F-c4b34006a13c’s represented 64-bit result supplies a later operand.
- On the **nonnegative branch**, F-c4b34006a13c is still called, but its result is not used as that operand. F-f72114b90855 is called afterward, and its represented 64-bit result supplies the operand instead.

The remaining sequence is common:

1. Read the current 32-bit numeric field at `0x11C` and pass it to F-b3a54d881220.
2. Call F-1b22d7e17791 with four 32-bit words: the low and high words of that latest result, followed by the low and high words of the branch-specific operand.
3. Call F-baa332e06e32 without explicit arguments.
4. Write its 32-bit result to `0x11C`.

The read of `0x11C` occurs after the earlier numeric calls. It is not an entry-time snapshot. No dependency is assumed to preserve that field, either global location, or shared numeric state.

No return value from F-1b22d7e17791 is directly consumed here. A relationship between its effects and the following F-baa332e06e32 result is possible but not established.

### Mandatory direction dispatch

Every normally progressing path, including boundary-blocked and threshold-crossing paths, reaches this sequence:

1. Call F-8bb3020950cd with the event object.
2. Read the event flag word at `0x10`.
3. Test whether mask `0x40000000` is set.
4. Call F-36810e285910 with the state object, the local direction, and the Boolean test result.

The direction argument is exactly zero, 1, or `0xFFFFFFFF`. Interpreting the last bit pattern as a signed −1 within the dependency requires knowledge not supplied here.

Later dependency changes to state do not cause the local direction decision to be recomputed.

### Conditional reset and final flag observation

After direction dispatch, short-circuit conditions control accumulator reset and further event observations.

If direction is **nonzero**:

- Write zero to `0x128`.
- Perform neither of the two later event-refresh calls.
- Skip final preparation.

If direction is **zero**:

1. Call F-8bb3020950cd and read the event flag.
2. If mask `0x40000000` is clear, write zero to `0x128`.
3. If the mask is set, perform no direct accumulator write at this stage.
4. Call F-8bb3020950cd again and read the event flag again.
5. Enter final preparation only if the mask is clear at this last observation.

The two post-dispatch flag observations are distinct. Set followed by clear permits preparation without the intervening direct accumulator reset. Clear followed by set performs that reset but prevents preparation.

Absence of a direct reset does not establish that the accumulator remains unchanged: intervening dependencies may modify it.

### Final preparation

When direction is zero and the last flag observation is clear, the following ordered operations occur:

1. Read `0x11C`, shift it left by 16, and store the 32-bit result at `0x130`.
2. Store zero at `0x134`.
3. Resolve an indirect callable through the state object’s dispatch-table address, at table byte offset `0x114`.
4. Call it with the state object and the current selection value from `0x124`.
5. Shift its 32-bit result left by 16 and store the result at `0x148`.
6. Store zero at `0x14C`.
7. Call F-380d68353221.
8. Call F-eef117f98f87 with the interior address `0x180`, the preceding 32-bit result, decimal 50, and three zero arguments.
9. Call F-36785b3316b7 with interior addresses `0x15C`, `0x180`, `0x12C`, and `0x144`, in that order.

The representation does not establish a relative evaluation order between resolving the indirect target and reading its selection argument.

The shifted-value/zero pairs suggest fixed-point preparation, but that interpretation is inferred.

### Arithmetic boundaries

The unsigned count subtraction wraps within 32 bits. A count of zero therefore gives the comparison limit `0xFFFFFFFF`, rather than automatically blocking nonnegative movement.

Accumulator addition is represented as signed 32-bit arithmetic. Portable signed-overflow behavior is not established. Overflow cases remain documented_only.

The preparation shifts operate on values represented as signed 32-bit quantities and store 32-bit results. For nonnegative values with representable shifted results, the effect is multiplication by 65,536. Negative inputs and shifts outside the representable signed range remain documented_only; neither unrestricted multiplication nor wrapping behavior is established.

## Acceptance examples

These are conditional consequences of the static representation, not executed tests. Unless stated otherwise, assume valid storage, returning dependencies, no unmentioned dependency mutations, and arithmetic within the established range.

1. **Lower boundary blocks accumulation.**  
   Selection 0 and movement −1 leave direction zero without adding movement or running numeric processing. Mandatory dispatch still occurs.

2. **Negative threshold is strict.**  
   Selection 1, accumulator −10, and movement −2 store −12 and enter numeric processing. Movement −3 instead stores −13, dispatches `0xFFFFFFFF`, then directly resets the accumulator to zero. Preparation is skipped.

3. **Positive threshold is strict.**  
   Count 5, selection 1, accumulator 10, and movement 2 store 12 and enter numeric processing. Movement 3 instead stores 13, dispatches direction 1, and resets the accumulator after dispatch.

4. **Upper boundary blocks accumulation.**  
   Count 5, selection 4, and nonnegative movement skip accumulation and numeric processing. Direction remains zero; later flags determine reset and preparation.

5. **Zero movement can process numerically.**  
   Count 5, selection 1, accumulator 0, and movement 0 enter the nonnegative numeric path. F-c4b34006a13c runs before F-f72114b90855; the latter supplies the combining operand.

6. **Zero count wraps the limit.**  
   With count 0, unsigned selection 0 is below the limit `0xFFFFFFFF` and does not block accumulation. Unsigned selection `0xFFFFFFFF` does block it.

7. **Global inputs are observed after the preceding call.**  
   Suppose numeric processing runs and its first F-b3a54d881220 call changes G-01. With no intervening change, F-c4b34006a13c receives the resulting G-01 observation, not an entry-time capture. The same rule applies to G-02 and to either movement branch. This example assigns no width to either observation.

8. **Global read order is not an acceptance requirement.**  
   A consumer cannot require G-01 to be read before G-02 or vice versa. Both reads belong to preparation of F-c4b34006a13c after the preceding call returns; stronger sequencing remains documented_only.

9. **Post-dispatch flags can disagree.**  
   With direction zero, set then clear avoids the conditional direct reset but permits preparation. Clear then set resets the accumulator but prevents preparation.

10. **Representable preparation shifts.**  
    If preparation reads 3 from `0x11C` and the indirect dependency returns 7, the shifted fields receive 196,608 and 458,752, respectively. Their companion fields receive zero.
