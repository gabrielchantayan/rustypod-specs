# F-42103167ec3e

## Purpose

F-42103167ec3e conditionally clears or sets selected bits in a referenced storage location, after invoking dependency F-f120802e6343. It returns the dependency’s result combined, by bitwise OR, with a high-order contribution derived from the first argument and an unresolved byte-valued input.

The established distinction is **zero versus nonzero**, not positive versus negative:

- A zero first argument selects bit clearing.
- Any nonzero first argument selects bit setting.
- A negative first argument additionally contributes to the returned high-order bits.

The apparent intent is a protected or status-bearing bit update. That interpretation is **inferred**, not established. The available evidence does not identify the storage location, explain the dependency, establish synchronization, or show a later operation restoring any state.

## Behavior

### Observable sequencing

The visible body establishes this sequence:

1. Invoke F-f120802e6343 with no visible explicit arguments.
2. Retain its returned value for the eventual result.
3. Select the clear or set operation according to whether the selector is zero.
4. Read the target cell and compute the masked result.
5. Write the computed result to the target cell.
6. Return the dependency result ORed with the selector-derived and unresolved-byte-derived contribution.

There is one selected target-cell value read and one target-cell value write in the visible body. Reads used to obtain the target address are distinct from the target-cell value read.

The target address expression appears separately for the read and the write. The supplied declaration and memory model are insufficient to guarantee how those address-bearing accesses are emitted or whether a changing address-bearing object could redirect an access.

The dependency call occurs before the visible target-cell update. Therefore, the value used for the update is the value available after that call, not necessarily the value present at function entry. The same caution applies to any mutable state identifying the target.

No global-preservation guarantee may be attributed to F-f120802e6343. If it changes the target cell or its addressing state, those changes can affect the subsequent operation.

### Zero selector: clearing

When the selector is zero, the operation combines the target-cell value with the bitwise complement of the mask, using bitwise AND.

For a target whose relevant value and storage representation are 32 bits:

- Each mask bit equal to one clears the corresponding target bit.
- Each mask bit equal to zero leaves the corresponding target bit unchanged.

The mask complement is a 32-bit unsigned complement under the stated integer model. It is not an unbounded mathematical complement.

The computed result is assigned back to the target cell even when the mask is zero or the resulting numeric value equals the value read. There is no visible “write only if changed” condition. The physical consequences of that assignment depend on the target declaration and environment.

### Nonzero selector: setting

When the selector is nonzero, the operation combines the target-cell value with the mask using bitwise OR.

For a 32-bit target:

- Each mask bit equal to one sets the corresponding target bit.
- Each mask bit equal to zero leaves the corresponding target bit unchanged.

Positive and negative nonzero selectors select the same target-cell operation. Their difference appears in the returned high-order contribution, not in the choice of update.

As in the clearing branch, the assignment occurs without checking whether it changes the numeric value.

### Return construction

Before the left shift, a byte-valued contribution is formed by ORing together:

- Bit 4 when the selector is negative.
- Bit 3 when the selector is zero.
- Bit 2 unconditionally.
- Every bit supplied by the unresolved byte.

That byte is converted to the unsigned return-width type and shifted left by 27 positions. Under the 32-bit model, only its low five bits survive. The mapping is:

| Contribution before shifting | Return bit |
|---|---:|
| Unresolved byte bit 0 | 27 |
| Unresolved byte bit 1 | 28 |
| Constant bit 2, also possibly supplied by the unresolved byte | 29 |
| Zero-selector condition, also possibly supplied by the unresolved byte | 30 |
| Negative-selector condition, also possibly supplied by the unresolved byte | 31 |

Bits 5 through 7 of the unresolved byte do not affect the 32-bit result after this shift.

The resulting contribution is ORed with the dependency result. Consequently:

- Return bits 0 through 26 equal the corresponding dependency-result bits.
- Return bit 29 is always set on an ordinary return under this model.
- A zero selector forces return bit 30.
- A negative selector forces return bit 31.
- The unresolved byte or dependency result may set those same bits independently.

The return value is therefore not a reliable standalone encoding of the selector. For example, a set bit 31 does not prove that the selector was negative.

No addition, carry propagation, or signed arithmetic overflow is involved in this return construction under the stated model.
