# F-c3f27819a3be

## Purpose

The available static evidence shows a routine that interleaves indirect calls with byte-sized and 32-bit memory updates. It transforms input bits and call-produced words into addresses, stores links or encoded values at those addresses, and passes related values to subsequent calls.

No application-level purpose is established. In particular, the evidence does not establish that the memory represents objects, a collection, a device, or an allocator. Repeated offsets and scaling factors are insufficient to assign those meanings.

The visible path ends at an invalid-instruction boundary, not a normal return. This contract therefore describes the observable prefix represented by the supplied material. It does not promise successful completion or recover an intended algorithm beyond that boundary.

## Behavior

### Reading conventions

For the descriptions below:

- A **word slot indexed by a word** is the 32-bit location at address 20 plus four times that word.
- A **scaled record slot** is the 32-bit location at address 20 plus sixteen times an index.
- A **byte-selected destination** is formed by reading an unsigned byte at a stated selector address, then writing one byte at address 17 plus the byte read.

These are address formulas, not assertions about actual record types or array bounds. All address arithmetic follows the width qualification above.

Indirect calls occur between many of the operations below. They may change memory, including selector bytes and word slots. A value explicitly retained from an earlier read or result remains distinct from a later reread of memory.

### Entry and initial byte updates

The third input is shifted left by 26 bits before the first call. The first indirect call receives the first input. Another indirect call follows.

A further scale by 1,024 is then applied to the already shifted third input. Under 32-bit wrapping arithmetic, this scaled value is zero for every third input: the combined left shift is 36 bits.

Two 32-bit reads are represented at address 28 plus the shifted third input. Their values are supplied as the two arguments of the next indirect call. They must not be contracted into one read merely because their addresses agree. The evaluation order between these two argument reads is not established.

After another indirect call:

1. A selector byte is read at address 1.
2. Zero is written at address 17 plus that selector.

The next call receives zero, an auxiliary output word from earlier execution, and zero. Several indirect calls follow, the last producing a primary return word.

The selector at address 1 is then read again. The selected destination receives the low byte of the earlier auxiliary word shifted right by 22 bits. This is a fresh selector read, not reuse of the selector used for the zero write.

A call receives the primary return word shifted left by two bits. More indirect calls follow. A later call receives zero and another returned word shifted left by two bits.

### First word associations and byte encodings

A subsequent indirect call supplies a retained word used across the following operations. F-674e75a953e8 is called with that same retained word in both explicit argument positions.

After another indirect call, a 32-bit store writes the retained word to the word slot indexed by an auxiliary output word.

The next call receives:

- The result of masking it with `0x3fffffff` and shifting right by ten bits.

After a further call sequence produces a new index, the auxiliary word is stored in the word slot indexed by that new index. A subsequent call receives four times the new index.

- Its lower 32 bits become a retained low word.

This is the represented result decomposition; the actual calling-convention mechanism is not established.

The routine then performs these stores, with intervening indirect calls:

2. Pass the high word to an indirect call.
3. Obtain a new index and store the high word in that index’s word slot.

### Repeated scaled-record and word-slot updates

Five successive stages use a common observable pattern:

- An indirect-call result supplies an index.
- Four times that index is retained.
- That retained value is stored in the scaled record slot for the index.
- Intervening calls execute.
- Another call supplies a destination index.
- A word-slot store occurs using that destination index.

The stages differ as follows:

| Stage | Arguments supplied after the scaled-record store | Following word-slot value |
|---|---|---|
| First | A word read at address 20 plus the retained scaled value, shifted right by 12; the retained scaled value; and a separate word read at that same address, shifted left by two | The retained scaled value |
| Second | The retained scaled value twice, followed by the retained low word shifted left by 26 | The retained scaled value |
| Third | The retained scaled value | The retained scaled value |

In the first stage, the two word reads have the same address but are distinct represented reads. Their relative evaluation order is not established.

In the fourth stage, the captured word is read **after** the scaled-record store and **before** the following calls. It is not reread when later stored in shifted form.

For the fifth stage’s first argument, the fourth stage’s destination index is multiplied by four, masked with `0x3f`, then shifted left by 14 bits. Consequently, under 32-bit arithmetic, this argument is a multiple of 65,536 and depends only on the low four bits of that earlier index.

The scaled-record slot and the read location at address 20 plus four times the index are different formulas. They must not be treated as the same field without an independently established alias.

The representation then terminates at an invalid-instruction boundary.

## Acceptance examples

These are conditional static acceptance examples, not executed tests.

1. **Third-input truncation.** Under 32-bit wrapping arithmetic, third inputs differing only above their low six bits produce the same initial shifted value. The later multiplication by 1,024 produces zero for every input. This does not eliminate the earlier reads based on the shifted value.

2. **Fresh selector reads.** If the selector at address 1 initially contains 7, the first zero write targets address 24. If an intervening call changes that selector to 9, the subsequent byte write targets address 26.

3. **Byte truncation.** If an auxiliary word used in a right-by-22 byte update is `0xffffffff`, the stored byte is `0xff`, not a ten-bit value.

4. **Low-bit encoding.** If an encoding word is `0x41`, its multiply-by-four byte update stores `0x04`. Higher product bits are discarded by the byte store.

5. **Paired-result decomposition.** If the represented 64-bit result has upper word 3 and lower word 5, the first associated store writes zero at address 32. The later large-scale store writes `0x14000000` at address `0x50000014`, assuming valid memory and returning callees.

6. **Captured versus reread data.** If a word captured in the fourth repeated stage is `0x12345000`, the later word-slot value is `0x00012345`, even if an intervening callee changes the original location.

7. **Partial execution.** If an indirect call does not return, subsequent stores are not required to occur. Previously completed writes are not specified to be undone.

8. **Terminal behavior.** Reaching the end of the represented path does not demonstrate normal return or success. Acceptance of continued execution requires evidence beyond the supplied boundary.
