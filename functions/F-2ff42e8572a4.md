# F-2ff42e8572a4

## Purpose

F-2ff42e8572a4 conditionally waits for a caller-supplied object's status word to become zero, clears the object's first word, and performs a metadata-driven accounting and release sequence.

The established behavior is an ordered series of memory accesses and dependency calls. The apparent intent is to retire an object and return its backing allocation to a managed pool. That interpretation is inferred: the supplied evidence does not establish the allocator model, synchronization guarantees, or eventual ownership of the storage.

A zero result from the initial dependency suppresses all object accesses and all remaining work. A nonzero result enables the complete path, including potentially unbounded waiting and a fatal metadata check.

## Interface

**Input**

One address, designated **P**, is supplied. The visible representation uses 32-bit words and 16-bit metadata fields.

The accessed layout relative to P is:

| Relative address | Width | Established use |
|---|---:|---|
| P − 8 | 32 bits | Header subject to validation, then masked to obtain an accounting quantity; its address is later passed to a dependency |
| P − 4 | 16 bits | First accounting-table selector |
| P − 2 | 16 bits | Second accounting-table selector |
| P + 0 | 32 bits | Cleared after the wait completes |
| P + 12 | 32 bits | Repeatedly tested for zero during the wait |

The two 16-bit fields are loaded independently from their respective addresses and zero-extended for subsequent arithmetic. They are not interpreted as one combined 32-bit value. Byte order is not independently established by the evidence; the contract identifies the addresses and widths of the native loads.

**Output**

No return value is exposed.

Possible outcomes include:

- Normal return immediately after a zero initial result.
- Normal return after the entire enabled path completes.
- Continued waiting without termination.
- Nonreturning transfer to the invalid-header dependency.
- A fault or other abnormal outcome caused by invalid memory, an invalid computed address, or a dependency.

**Preconditions for defined completion of the enabled path**

P must designate storage supporting the reads and write above, including the metadata preceding P. In particular, P must already be readable at offset +12 before any later null-address check is reached.

A globally selected state address, designated **B**, must support every computed accounting access. Metadata selectors and the index returned by a dependency must identify suitable locations within that state. The function performs no visible range checks on those selectors or that index.

The evidence does not establish allocation extent, alignment requirements, address-space validity, or a concurrency protocol. These remain caller or environment obligations rather than validations performed here.

## Behavior

### 1. Initial gate

The function first calls F-8ff94386ac71 with no explicit arguments.

- If its result is zero, the function returns immediately.
- Otherwise, execution proceeds to the wait.

On the zero-result path, this function does not dereference P, read the global state selector, clear an object field, or perform accounting. F-8ff94386ac71 may itself have side effects; none are characterized by the supplied body.

### 2. Wait for the status word

The function reads the 32-bit word at P + 12.

If it is nonzero, the function calls F-8124f61dc7bb with no explicit arguments and then tests that word again. This repeats until a test observes zero.

Consequences:

- An initially zero status causes no call to F-8124f61dc7bb.
- Each observed nonzero status causes another call before the next test.
- The supplied behavior contains no retry limit, timeout, cancellation result, or explicit failure return.
- The loop does not visibly modify the status word itself.
- A dependency or another execution context may change the status word. The evidence does not establish which agent is responsible.

The contract does not require one dependency invocation per unit of elapsed time or imply any scheduling guarantee.

### 3. Clear the first word and obtain the state address

After the wait observes zero, the function stores a 32-bit zero at P + 0.

It then calls F-2fd8826557a4 with no explicit arguments. Only after that call returns does it read the global cell containing B.

This timing matters: B is selected from the global state after F-2fd8826557a4 has run. The supplied function does not establish whether that dependency changes the global cell.

Once captured, B is the address used by the subsequent accounting sequence. No second read of the global cell is visible.

### 4. Check the header

A null-address condition is present after the object accesses and global-state read. If that condition excludes the accounting body, execution returns.

This is not an effective null-input safeguard. When the initial gate is nonzero, the earlier read at P + 12 and write at P + 0 precede it. Consequently, a null input has no established safe enabled-path behavior.

For the accounting body, the header address is P − 8. The function rejects either of these header conditions:

- The 32-bit header is zero.
- Its least significant bit is set.

The zero check precedes the low-bit check. The supplied expression permits a second header read for the low-bit test when the zero check does not reject it. There is no established guarantee that both observations see the same value if another agent can modify the header.

On rejection, the function calls F-a817d8d58c10 with no explicit arguments. That dependency is identified as nonreturning. No accounting updates or later release calls are established after this transfer.

The earlier object clearing and F-2fd8826557a4 call have already occurred; rejection does not roll them back.

### 5. Enter the accounting sequence

After header acceptance, the function calls F-c0fc6d033caa with B.

The name or purpose of this operation is not established. It may be part of a synchronization protocol, but mutual exclusion, memory ordering, and preservation of memory contents cannot be assumed.

The function next obtains:

- The first unsigned 16-bit selector from P − 4.
- An accounting quantity from a new 32-bit header read at P − 8, masked with `0x3ffffffc`.

Call this retained quantity **Q**. The mask removes bits 31, 30, 1, and 0. Therefore Q is a multiple of four between zero and `0x3ffffffc`, inclusive.

Header acceptance does not imply Q is positive. For example, a header value of 2 passes the visible rejection checks but produces Q = 0.

The header used for Q is read after F-c0fc6d033caa returns. It is not necessarily the same value used in validation.

### 6. Apply four byte-quantity adjustments

The function performs the following 32-bit read-modify-write operations in this order:

1. Subtract Q from the word at B + `0x224` + four times the first selector.
2. Subtract Q from the word at B + `0x30c`.
3. Read the second unsigned 16-bit selector at P − 2, then subtract Q from the word at B + `0xe0` + four times that selector.
4. Subtract Q from the word at B + `0x220`.

The second selector is read after the first two accounting writes. It is not captured with the first selector before accounting begins.

Both selectors have the unsigned range 0 through 65,535. Their scaled offsets range from zero through 262,140 bytes. No narrower valid range is checked.

These are separate operations, not one transactional update. If computed addresses overlap, each operation acts on the value present when that operation executes. The source provides no non-aliasing guarantee between the metadata, object, global state, or accounting locations.

### 7. Decrement two counts

The function calls F-09dcb55e8e0a with no explicit arguments and uses its integer result as an accounting index.

It then performs these 32-bit updates in order:

1. Decrement the word at B + `0x310` + four times the returned index.
2. Decrement the word at B + `0x390`.

There is no visible check that the returned index is nonnegative or within a table's bounds. There is also no zero check before either decrement.

The dependency runs after all four Q-based adjustments and before these count updates. Its effects on state must not be assumed absent.

### 8. Apply the final header-based adjustment and invoke release dependencies

The function rereads the 32-bit header at P − 8 and masks it with `0x3ffffffc` again.

This freshly obtained quantity is subtracted from the 32-bit word at B + 8. It need not equal Q if the header changed after Q was captured.

The function then calls, in order:

1. F-cc6c9b4a0f68 with B and the address P − 8.
2. F-e586bff64fb7 with B.

If both return, the function returns normally. No further object or accounting access is visible after the second call.

## Side effects

The directly established writes are:

- Zeroing the first 32-bit word at P.
- Four accounting subtractions using retained quantity Q.
- Two 32-bit count decrements.
- One final accounting subtraction using a fresh masked header value.

All dependencies may have additional effects not characterized here.

**Arithmetic and widths.** Accounting destinations are 32-bit words. No underflow detection, saturation, or checked-arithmetic error path is visible. At the represented machine-word level, subtraction and decrement retain the low 32 bits; decrementing zero therefore produces `0xffffffff`. This is not a claim that such a transition is valid in the surrounding data model.

Selector scaling is by four bytes. Address calculations use the represented 32-bit address model. Address wrap or an out-of-range index does not establish valid memory access.

**Partial completion.** The visible sequence has no rollback. A failure after some writes can leave the object cleared and only part of the accounting changed.

**Ownership.** Passing P − 8 to F-cc6c9b4a0f68 suggests a release operation, but actual deallocation, ownership transfer, reuse, and post-return validity are documented_only unknowns. The caller cannot derive permission to reuse or access P from this function body alone.

**Concurrency.** Repeated status reads, repeated header reads, and dependency boundaries are visible. Atomicity, visibility between threads, lock ownership, and exclusion from concurrent updates are not established.

## Acceptance examples

These are conditional static acceptance cases, not reports of executed tests. Unless stated otherwise, addresses are valid, destinations do not overlap, relevant values remain stable, and all dependencies that are expected to return do so.

1. **Gate declines work.**  
   Given a zero result from F-8ff94386ac71, expect immediate normal return with no direct object access, even if P would otherwise be invalid. Effects of the gate dependency remain outside this guarantee.

2. **No waiting required.**  
   Given a nonzero gate result and an initially zero word at P + 12, expect no F-8124f61dc7bb calls. The next direct write is zero to P + 0.

3. **Two nonzero observations.**  
   Given successive status observations of nonzero, nonzero, and zero, expect exactly two F-8124f61dc7bb calls before clearing P + 0. If zero is never observed, accounting is never reached.

4. **Invalid header.**  
   Given a zero header, expect transfer to F-a817d8d58c10 after the object has been cleared and B loaded. An odd header likewise triggers that dependency. Neither case reaches F-c0fc6d033caa on the established nonreturning path.

5. **Ordinary accounting.**  
   Given a stable header of `0x44`, first selector 2, second selector 3, and returned count index 4, Q is 68. Expect subtraction of 68 at B + `0x22c`, B + `0x30c`, B + `0xec`, and B + `0x220`, in that order. Then expect count decrements at B + `0x320` and B + `0x390`, followed by subtraction of 68 at B + 8 and the final two dependency calls.

6. **Accepted header with zero masked quantity.**  
   Given a stable header of 2, expect header acceptance and Q = 0. The four quantity updates do not numerically change their destinations, but the two count decrements and final dependency calls still occur.

7. **Header changes before the final subtraction.**  
   Given Q = 68 when first captured, but a header of `0x84` when reread for B + 8, expect the first four quantity subtractions to use 68 and the final subtraction to use 132. This case demonstrates a fresh read, not an endorsement of concurrent mutation.

8. **Aliasing accounting destinations.**  
   Given first selector 58, the first computed destination is B + `0x30c`, the same as the next destination. With stable memory, the two consecutive operations subtract Q twice from that word.
