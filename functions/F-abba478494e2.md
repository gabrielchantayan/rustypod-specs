# F-abba478494e2

## Behavior

### Initial resolution and metadata

The root pointer is followed through three 32-bit loads: offset 0x14 from the root, offset 0x14 from that result, and offset 0x08 from the next result. The last result identifies a record.

The fragment reads that record’s offset-0x00 word, then its offset-0x08 pointer, then the 32-bit value addressed by that pointer. Treating the final value as an address, it writes the value’s low eight bits at address + 0x0b.

Only afterward does the fragment use the previously obtained offset-0x00 word as a base to read a **primary pointer** at offset 0x1c and an **associated word** at offset 0x24, in that order. The preceding byte store can affect those reads if addresses overlap.

The primary pointer, interpreted as signed 32-bit, is shifted right by 24 to obtain a **derived base**. Under arithmetic-shift interpretation, this is between −128 and 127.

The primary pointer’s most significant byte is converted to a character and then to a 16-bit value, which is stored at primary pointer + 0x2a. Its low eight value bits are established; the upper eight depend on character signedness.

Five consecutive 32-bit stores then target the derived base:

| Offset | Value |
|---|---|
| 0x00 | Derived base |
| 0x04 | Primary pointer |
| 0x08 | B + 0x324 |
| 0x0c | Primary pointer interpreted as signed and shifted right by eight |
| 0x10 | Associated word |

The table gives store order. These destinations are not established allocated storage.

### Working state and count storage

After those stores, the fragment obtains its working state in this order:

1. Read a working pointer from primary pointer + 0x04.
2. Read a 32-bit count from primary pointer + 0x08 and assign it to the represented slot at B + 0x110.
3. Read a working word from primary pointer + 0x0c.

The count assignment precedes the third read. With concrete stack backing, an overlap between B + 0x110 and primary pointer + 0x0c can therefore change the working word that is read.

If the working count is zero, the working pointer is adjusted by the derived base. The fragment then reads the primary pointer’s offset-0x00 word, interprets it as an address, and reads a 32-bit value there. The working word becomes that value minus the derived base. Finally, the working count at B + 0x110 is replaced with the adjusted working pointer logically shifted right by 16.

A nonzero initial count skips this adjustment and indirect read. Earlier writes remain relevant to all subsequent loads.

### Stack-derived addresses and pointer replacement

The fragment writes the primary pointer’s most significant byte at derived base + 0x0d. This overlaps the word previously stored at derived base + 0x0c; its effect on that word depends on byte order.

It then interprets B + 0x324 as signed 32-bit and shifts it right by 20. Call the result the **stack-derived value**. The initial **secondary destination** is four bytes below that value. The low byte of B + 0x324 is stored at stack-derived value + 0x09. The initial **auxiliary address** is B + 0x248.

If the working pointer is null at this stage:

- The secondary destination becomes B + 0x244.
- A byte derived from a fixed data-symbol value replaces the byte at derived base + 0x0d.
- The derived base is multiplied by 16; subsequent uses refer to this updated value.
- The auxiliary address becomes the arithmetic-right-shift-by-eight result of the entire quantity consisting of the value at B + 0x264 minus sixteen times the stack-derived value.
- The working pointer becomes secondary destination plus the updated derived base.
- The working word becomes that pointer logically shifted right by 20.
- The value at B + 0x1e8 replaces the working count at B + 0x110.

The fixed data symbol’s actual value and precise underlying load width are unresolved. The final assignment to B + 0x110 is represented state replacement, not merely a change to an unrelated count variable.

### Major branch and optional record

The next predicate tests whether the working pointer, interpreted as signed 32-bit and shifted right by 28, is nonzero. Under the represented arithmetic-shift interpretation, values 0x00000000–0x0fffffff skip this branch; all other 32-bit patterns enter it.

Skipping the branch reaches the final invalid-instruction boundary.

Entering it first stores the low 16 bits of the working count at secondary destination + 0x24. The fragment then tests the value at B + 0x264. This use must not be assumed to observe an immutable entry snapshot: preceding writes can matter if its represented storage is concretely backed and aliases them.

If that value is zero, the fragment writes a zero byte at the address obtained by adding the signed numerical value of B + 0x210 to B + 0x254, then reaches the final boundary. This is an address-sum operation, not an established bounded array access.

If the value is nonzero, a **combined value** is formed by bitwise OR of the current derived base shifted left by eight and the current derived base multiplied by 16. This is not addition.

A represented null test on B + 0x210 follows. A null result reaches an invalid-instruction boundary before the optional record and subsequent low-address accesses. The contract retains this branch without assuming conventional stack placement makes it unreachable.

If execution continues and the combined value is nonnegative as signed 32-bit, eight 32-bit stores target the incoming record destination, in index order:

| Word index | Value |
|---|---|
| 0 | B + 0x248 |
| 1 | 0x22 |
| 2 | B + 0x254 |
| 3 | Working word bitwise-OR auxiliary address |
| 4 | One incoming register value |
| 5 | The record destination’s own address |
| 6 | Another represented machine-register value |
| 7 | Literal 0x0860b3b4 |

A negative combined value skips all eight stores. It does not skip the following halfword store: the low 16 bits of the combined value are written to absolute address 0x5a.

### Pointer-slot update and low-address traversal

After the store at 0x5a, the fragment assigns B + 0x160 to the pointer slot at B + 0x70. Only then does it read the byte at absolute address 0x22. A nonzero byte reaches an invalid-instruction boundary.

This ordering matters under concrete backing: the assignment at B + 0x70 precedes, and could affect, the control-byte read if their storage overlaps.

A zero control byte permits traversal setup. The traversal value initially equals zero. The fragment tests the pointer state at B + 0x70 for null. If null, the alternate setup:

- Stores the arithmetic-right-shift-by-eight value of B + 0x2c2 as a 32-bit word at absolute address 0x7e.
- Assigns null to the pointer slot at B + 0x70.
- Sets the traversal value to 0x280.
- Assigns zero to the 32-bit slot at B + 0x74.

Those actions occur in that order. B + 0x74 is written state only; no incoming value is required. With stable ordinary memory and a nonzero B + 0x160, the earlier pointer assignment makes the alternate setup unselected. The representation nevertheless contains the null branch.

Traversal performs at least one iteration. Each iteration reads a 32-bit value at traversal value + 0x04 and adopts the loaded value as the next traversal value. Continuation depends on whether adding 126 to that loaded value would overflow signed 32-bit arithmetic. The sum itself is not retained.

Thus loaded values 0x7fffff82–0x7fffffff continue traversal; other values end it. No cycle detection, iteration limit, or invalid-address recovery is shown.

### Calls and final writes

After traversal, the fragment reads a 32-bit word at absolute address 0xa9 and writes it at absolute address 0x3c. It then reads a signed 32-bit value from a fixed data location and shifts it left by four. Call this the **shifted data value**; its numerical meaning requires an agreed interpretation where signed shifting is problematic.

The four dependencies described below are called sequentially, provided each predecessor returns.

After the fourth call returns, the fragment extracts bits 8–15 of the shifted data value and performs three byte stores:

1. At absolute address 0x440000.
2. At 0x220000 plus the arithmetic-right-shift-by-eight value of the shifted data value.
3. Again at that same computed address.

The duplicate store is represented behavior. It cannot be collapsed when writes have external effects.

Execution then reaches an invalid-instruction boundary. No normal return follows.

## Acceptance examples

These are conditional static criteria, not executed tests.

1. **Count assignment can precede an aliased input read.**  
   If B + 0x110 has concrete backing and aliases primary pointer + 0x0c, the count assignment occurs before the working-word read. Under ordinary sequential-memory semantics, that read observes the assigned bytes, interpreted according to the target’s byte order.

2. **Nonzero count.**  
   A nonzero count skips the pointer adjustment and two-level read through the primary object’s first word. The initial assignment to B + 0x110 still occurs.

3. **Zero count replacement.**  
   With an initial zero count and valid accesses, the adjusted pointer logically shifted right by 16 replaces the state at B + 0x110. The replacement working word comes from the indirect load minus the derived base.

4. **Null-pointer replacement.**  
   If the working pointer reaches the replacement branch, the value read at B + 0x1e8 replaces B + 0x110. A later count use is not specified as retaining the earlier count.

5. **Major-branch boundary.**  
   A final working pointer of 0x0fffffff skips the major branch. A value of 0x10000000 enters it and first performs the halfword store at secondary destination + 0x24.

6. **Record suppression.**  
   A negative combined value suppresses all eight record stores but not the subsequent halfword write at 0x5a.

7. **Pointer assignment before termination check.**  
   If the control-byte read returns nonzero, traversal and calls do not occur. The B + 0x70 assignment has already occurred.

8. **Alternate setup writes, rather than consumes, B + 0x74.**  
   If the null-pointer setup is selected, it assigns null to B + 0x70 and later zero to B + 0x74. Changing only the incoming value at B + 0x74 supplies no visibly consumed input.

9. **Traversal boundary.**  
   A loaded value of 0x7fffff81 ends traversal; 0x7fffff82 continues it because the signed addition predicate detects overflow.

10. **Call-chain completion.**  
    If all calls return and final destinations are writable, three byte stores follow, including two to the same computed destination. No normal return is represented.
