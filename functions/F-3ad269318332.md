# F-3ad269318332

## Purpose

F-3ad269318332 conditionally invokes an indexed callback and reports its outcome through two distinct channels:

- A 32-bit return value indicating success or failure.
- A 32-bit status written to a destination obtained immediately before publication.

The second input controls whether validation is attempted. If it is zero, the function selects status 26 and failure without validating the selector. Otherwise, a validator determines whether callback dispatch is permitted. A nonzero validation status prevents dispatch; a zero validation status permits it.

On the dispatch path, the function reads a global table-base value **after validation returns zero**, then reads the callback target from the selected entry. Neither the base nor the callback target is a pre-validation snapshot.

The wrapper returns zero only when validation and the callback both return zero. Every other ordinary outcome returns 0xFFFFFFFF. Detailed validation or callback statuses are preserved in the final destination write, not in the wrapper’s return value.

This contract is based on supplied static evidence. No runtime tests have been performed.

### Return value

The return occupies 32 bits and has two established values:

| Bit pattern | Condition |
|---|---|
| 0x00000000 | The operation argument is nonzero, validation returns zero, and the selected callback returns zero. |

## Behavior

### Zero operation argument

When the operation argument is zero:

- The selected status is 26.
- The selected return value is 0xFFFFFFFF.
- F-eb5289d344f1 is not called.
- The wrapper does not read the global table base or an indexed callback field.
- No callback is invoked.

The function then calls F-4af36158f863, writes 26 through its returned destination, and returns failure if those operations complete normally.

This branch takes precedence over selector validation. An invalid selector does not itself cause a table access on this path.

The numeric status 26 is established; its symbolic or platform-specific meaning is not.

### Nonzero operation argument and failed validation

When the operation argument is nonzero, the function first invokes F-eb5289d344f1 with the selector.

If validation returns any nonzero 32-bit value:

- That exact bit pattern becomes the selected status.
- The wrapper does not read the global table base or callback field.
- No callback is invoked.
- The selected return value is 0xFFFFFFFF.

Afterward, F-4af36158f863 supplies the destination, and the validator’s exact status is written there. The wrapper then returns 0xFFFFFFFF.

Thus, status preservation on this branch concerns the **final destination write**, not the wrapper return. Positive and negative nonzero validator results have the same failure classification while retaining their distinct published bit patterns.

### Nonzero operation argument and successful validation

If F-eb5289d344f1 returns zero, the function proceeds to dispatch.

The lookup has two separately observable reads:

1. Read the current global table-base value.
2. Read the callback target at that base plus the selector’s 20-byte entry displacement plus the 8-byte callback-field offset.

The selected target is then invoked with the unchanged operation argument.

The callback’s 32-bit result becomes the selected status. A zero result selects wrapper return zero; every nonzero result selects wrapper return 0xFFFFFFFF.

The function subsequently calls F-4af36158f863, writes the callback status through its returned destination, and returns the selected success or failure value.

There is no visible retry, alternative callback, second validation, or conversion of the callback’s detailed status into a different published code.

### Ordering and mutable state

On a normally completing dispatch path, the established order is:

1. Invoke F-eb5289d344f1 with the selector.
2. Receive its zero result.
3. Read the global table-base value.
4. Read the indexed callback target using that base.
5. Invoke the target with the operation argument.
6. Receive the callback status.
7. Invoke F-4af36158f863.
8. Receive the status destination.
9. Write the selected 32-bit status.
10. Return the selected wrapper result.

Validation may change the global base itself, not merely an entry in an existing table. If it changes that base before returning zero, the subsequent lookup uses the base read after validation. The contract does not substitute an earlier base or callback snapshot.

Likewise, the destination is acquired after validation and any callback have returned. It is not established as a destination cached before those calls. If earlier dependencies alter state used by F-4af36158f863, its subsequent behavior remains governed by that dependency’s actual contract.

These statements describe the wrapper’s static operation order. They do not establish synchronization, atomicity, or visibility guarantees across threads.

The callback-field address combines the table base, selector multiplied by 20, and an additional 8-byte offset. The source representation supplies no explicit overflow check, widened intermediate calculation, or independent range check after validation.

## Side effects

The wrapper’s explicit data write is the final 32-bit status store through the destination returned by F-4af36158f863.

That store is unconditional on ordinary returning paths. Success writes zero, replacing any previous destination contents; it does not merely leave the destination unchanged.

The wrapper also explicitly reads global table state on successful validation: first the base value, then the selected callback target. It does not perform those lookup reads on the zero-operation-argument or validation-failure paths.

All reached dependencies may have additional side effects. Their implementations are not supplied. In particular, none may be assumed to:

No recovery is established for an invalid callback target, an unwritable destination, a faulting dependency, or a dependency that never returns. Those cases are not guaranteed to produce the ordinary failure return.

## Acceptance examples

These examples are conditional requirements, not executed tests. Each assumes that reached calls return normally and reached memory accesses are valid.

| Conditions | Required behavior |
|---|---|
| Operation argument is zero; selector is arbitrary. | Skip validation and wrapper table-lookup reads. Obtain the destination, write 26, return 0xFFFFFFFF. |
| Operation argument is nonzero; validation returns 7. | Skip table lookup and callback invocation. Obtain the destination, write 7, return 0xFFFFFFFF—not 7. |
| Operation argument is nonzero; validation returns 0xFFFFFFFD. | Publish exactly 0xFFFFFFFD. Skip dispatch. Return 0xFFFFFFFF. |
| Validation returns zero; callback returns zero. | Read the global base after validation, read the callback target, pass the unchanged operation argument, obtain the destination afterward, write zero, return zero. |
| Validation returns zero; callback returns 26. | Publish 26 and return 0xFFFFFFFF. Unlike zero-argument rejection, validation and callback invocation occur. |
| Validation returns zero; callback returns 0x80000000. | Publish exactly 0x80000000 and return 0xFFFFFFFF. |

Additional ordering and boundary examples:

- **Base replacement during validation:** If validation replaces the global table base and returns zero, the wrapper’s subsequent base read observes the resulting base under otherwise valid, nonconcurrent execution. Callback selection is not required to use the former table.
- **Entry replacement during validation:** If validation changes the selected callback field and returns zero, target lookup occurs afterward. No pre-validation target snapshot is established.
- **Destination selection changed by the callback:** If the callback changes state consulted by F-4af36158f863, destination acquisition still occurs after the callback. Which destination that accessor returns depends on its unresolved contract.
- **Previous error followed by success:** If the acquired destination contains a nonzero value and the callback returns zero, the final write replaces it with zero.
- **Invalid selector with zero operation argument:** Validation and wrapper table lookup remain skipped. Normal completion still depends on the destination accessor and final write.
- **Out-of-range selector accepted by validation:** No additional bounds rejection is established. A clean failure return is not required for an invalid resulting memory access.
