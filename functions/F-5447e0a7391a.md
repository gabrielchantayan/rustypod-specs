# F-5447e0a7391a

## Purpose

F-5447e0a7391a compares an indexed integer with a reference integer and returns whether they are equal. Both integers are reached through storage associated with an object address supplied by the caller.

Selection uses four-byte spacing and a one-position forward bias: index zero selects four bytes beyond the selection base, while index negative one selects the base itself.

The established operation is an equality comparison, not a search, bounds check, or storage-validity check. Interpreting the selected storage as an array and the reference as an expected value is **inferred intent**, not an established application-level contract.

| Index | A signed integer-valued argument used to determine the selected location. |
| Result | A Boolean: true when the selected integer equals the reference integer, false when they differ, provided evaluation completes normally. |

There is no output buffer or separate error result.

The supplied representation declares both inputs and the memory-accessed values as integers. It declares the result as Boolean. It does not independently establish the original ABI, native pointer width, argument placement, or Boolean return encoding.

## Behavior

### Indexed selection

Increasing the index by one moves the selected location forward by four bytes, wherever the intervening arithmetic remains valid.

| Index | Selected location |
|---:|---|
| −2 | Four bytes before the selection base |
| −1 | At the selection base |
| 0 | Four bytes beyond the selection base |
| 1 | Eight bytes beyond the selection base |
| 2 | Twelve bytes beyond the selection base |

This table defines location selection, not an authorized input domain.

No length, capacity, lower bound, or upper bound is consulted. Negative indices are not explicitly rejected. Index zero has no special branch.

The value at the selection base has no established special meaning. It must not be described as a header, count, sentinel, or reserved element without additional evidence. It is selected when the index is negative one.

### Comparison and result

On normal completion, equality requires true and inequality requires false.

Zero has no special meaning. Equal negative integers compare equal, as do equal positive integers. A high-order bit does not independently cause rejection or change the operation into an ordering comparison.

Both operand accesses are part of the operation. Neither a zero selected value nor prior knowledge of the reference provides a specified short-circuit case. There is no separate result for an invalid index, missing value, or unavailable storage.

### Read dependencies and ordering

The selected-value access depends on obtaining a state address from the object and a selection-base address from that state. The reference access depends on obtaining a state address from the object and reaching the reference field within that state.

Those address dependencies are established. A total order between the two operand paths is not.

In particular, the contract does not promise:

- Which compared integer is read first.
- That the object’s state-address field is evaluated only once.

No volatile or atomic access qualification is visible. The representation contains separate references to the object’s state-address field, but that does not establish distinct observable machine loads.

If the execution environment permits defined changes between observable accesses, the operand paths may use different state storage. This is not permission for unsynchronized concurrent mutation: such mutation may instead invalidate execution under the applicable memory model.

## Acceptance examples

These examples are conditional requirements derived from static evidence, not observed executions.

Unless stated otherwise, assume signed 32-bit integers, stable readable storage, valid alignment and address interpretation, valid arithmetic, and no overlap that defeats an independently described change.

### Forward-biased selection

Suppose the integer at the selection base is 91, the integer four bytes beyond it is 37, and the reference is 37.

For index zero, the required result is **true**. The integer at the base is not selected.

Changing only the integer four bytes beyond the base to 38 makes the required result **false**. Neither execution authorizes a write to either compared integer.

### Adjacent indices

Suppose the integers four and eight bytes beyond the selection base are 10 and 20, respectively, and the reference is 20.

| Index | Required result |
|---:|---|
| 0 | false |
| 1 | true |

This distinguishes the established selection rule from one that selects the base for index zero.

### Zero and signed values

If both compared integers are zero, the required result is **true**. If exactly one is zero, it is **false**. Both locations must still be valid for access.

If both integers are −2,147,483,648 under the signed 32-bit interpretation, the required result is **true**. Changing only one to −2,147,483,647 requires **false**.

### Negative indices

For index negative one, a valid integer at the selection base is selected. If it equals the reference, the required result is **true**.

For index negative two, a valid integer four bytes before the base is selected. If it differs from the reference, the required result is **false**.

These requirements do not establish that negative indices belong to the intended public input domain.

### Arithmetic boundaries

At index −536,870,913, the signed 32-bit displacement is representable at its minimum value. At index 536,870,910, it is representable at the largest multiple of four below the signed maximum.

A normal result is required only if base-address combination, fixed-offset arithmetic, and all storage preconditions also hold.

### Invalid operand storage
