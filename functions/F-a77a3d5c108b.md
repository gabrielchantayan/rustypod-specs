# F-a77a3d5c108b

## Purpose

F-a77a3d5c108b traverses fixed-stride records, skips records whose handle is zero, and conditionally compares an indirectly stored 32-bit value with a mutable working word.

Before traversal, it calls F-391e3d30e634 with the numeric argument 96. A zero return prevents traversal. A nonzero return is reused as an address argument to subsequent dependencies, including a final call to F-94cb53877c15 after traversal. These calls do **not** establish that a 96-byte allocation exists, that the address identifies an owned region, or that the final call releases anything.

The function exposes two distinct outcome signals:

- A 64-bit return containing a binary traversal-result word and a context word.
- A one-byte write to the collection object on setup failure or either of two selected statuses.

A comparison mismatch clears the result word without directly setting the state byte. A special dependency status sets the state byte without directly clearing the result word.

**Inferred intent:** the traversal appears to check consistency across selected records. The domain meanings of the handles, statuses, context word, and state byte are not established.

## Interface

### Arguments

| Argument | Width | Established use |
|---|---:|---|
| Collection address | 32 bits | Locates the collection header and, indirectly, its records. |
| Incoming context word | 32 bits | Supplies the upper return word unless a nonzero handle is processed. It is not passed to the processing dependencies. |
| Auxiliary word | 32 bits | Passed unchanged as the sixth argument to F-80f420262fea. |
| Initial comparison word | 32 bits | Initializes a local working word whose address is passed to F-70fe47664dff. |

Addresses and stored pointers are represented by 32-bit quantities in the supplied body. Support for wider addresses is not established.

### Collection layout

Only these header fields are used directly:

| Byte offset | Width | Interpretation at this call site |
|---|---:|---|
| +4 | 32 bits | Signed record count, read at each reached loop-admission test. |
| +8 | 32 bits | Record-array address, read when selecting a record and again before a successful query’s comparison. |
| +30 | 8 bits | State byte, written with 1 on specified paths. |

Records have a 24-byte stride. The relevant fields are:

| Record-relative offset | Width | Interpretation at this call site |
|---|---:|---|
| +4 | 32 bits | Handle; zero skips processing. |
| +20 | 32 bits | Address of a 32-bit comparison value. |

The field at record offset +20 is an indirection, not the value compared directly. No other header or record fields have an established interpretation here.

### Return value

The result is a 64-bit bit pattern:

- Bits 31–0 contain a result word, always 0 or 1 on normal return.
- Bits 63–32 contain a context word.

The result word is 0 if F-391e3d30e634 returns zero. Otherwise, it starts at 1 and changes to 0 only upon a qualifying comparison mismatch.

The context word remains the incoming context word if no nonzero handle is processed. Once any nonzero handle is processed, it becomes the nonzero address word returned by F-391e3d30e634.

That address word remains in the return even though F-94cb53877c15 has subsequently received it. Returning the bits establishes neither address validity nor ownership transfer.

### Preconditions for normal completion

All reached memory accesses must be valid with the indicated widths. In particular:

- The count field must be readable at each reached admission test.
- An admitted record requires a readable array-address field and handle field.
- A comparison requires a readable array-address field, record pointer field, and pointed-to 32-bit value.
- The state byte must be writable whenever the corresponding branch is taken.

The function performs no explicit null checks on the collection address, array address, or comparison pointer. It does not check record capacity against the count.

Address calculations must be supported by the execution environment. Dependency calls must return normally for their following operations to occur. Fault, exception, and nonlocal-exit behavior are not specified.

## Behavior

### Initial working state and setup call

The local working word is initialized once from the fourth argument. F-391e3d30e634 is then called with 96.

If its return is zero:

1. The result word is 0.
2. The state byte at collection offset +30 is written with 1.
3. No count, record-array, handle, or comparison-value read is performed.
4. F-94cb53877c15 is not called.
5. The upper return word remains the incoming context word.

If its return is nonzero, that value is retained as the address word used in later calls. The result word starts at 1 and the traversal index starts at zero.

The setup call precedes the first collection-field read. The function therefore observes collection contents as they exist after that call returns; preservation by the dependency is not established.

The numeric argument 96 is established. Its interpretation as a requested size, and whether any corresponding storage exists, are **documented_only**.

### Loop admission and handle selection

At each reached admission test, the current signed 32-bit count is read from collection offset +4. The current index is admitted only if it is strictly less than that count.

Consequently:

- Zero and negative counts admit no records.
- The count is not snapshotted before traversal.
- Dependency changes to the count can affect later admission.
- A count reduction during record processing does not cancel the already-admitted record.

For an admitted index, the function reads the current array address from collection offset +8. It then reads the handle at the array address plus 24 times the index plus 4.

A zero handle skips every per-record dependency, the comparison-pointer read, and the context-word replacement. The index still advances.

A nonzero handle is retained for both processing-stage calls. The handle field is not re-read between those calls.

### Nonzero-handle processing

For each nonzero handle, these actions occur in order:

1. An unmapped dependency is called with the retained address word and 96.
2. The return context word is replaced with the retained address word.
3. F-80f420262fea is called with six ordered arguments: handle, 1, 0, 0, retained address word, auxiliary word.

The unmapped dependency’s result is unused. No initialization, clearing, allocation, or other memory effect is established for it.

If F-80f420262fea returns a nonzero 32-bit status:

- F-70fe47664dff is skipped.
- The comparison pointer and its target are not read.
- F-2106ab1fda38 is skipped.
- This processing status is selected for the special-status check.
- The result word is unchanged.

An ordinary nonzero processing status therefore does not itself cause a zero result.

If F-80f420262fea returns zero, F-70fe47664dff is called with the retained handle, 1, and the address of the local working word.

### Working-word persistence and comparison

The working word is not reset between records. Changes made through its address remain in that same local storage for later processing, including changes made by a query that returns a nonzero status. No dependency preservation guarantee is implied beyond the function’s own absence of a reset.

If F-70fe47664dff returns zero, the comparison path:

1. Re-reads the array address from collection offset +8.
2. Reads the pointer at offset +20 in the record at the current index.
3. Reads the pointed-to 32-bit value.
4. Tests that value for equality with the current working word.
5. Changes the result word to 0 if they differ.

Equality is over the complete 32-bit values; signedness does not affect equality.

The array used for comparison may differ from the array that supplied the handle. The index is retained, and the count is not rechecked before the comparison. A dependency that replaces the array or reduces the count must therefore leave the accesses on this already-selected path valid if normal completion is expected.

If the query status is nonzero, neither the comparison-pointer field nor its target is read.

### Post-query call and special-status check

Whenever F-80f420262fea returns zero, F-2106ab1fda38 is called with the retained address word after the query and any comparison. This call occurs whether the query succeeds or fails, and whether a successful query matches or mismatches.

The query status is retained for the subsequent special-status check. The result of F-2106ab1fda38 does not replace that status.

After a nonzero handle is processed, the function writes 1 to the state byte if the selected status equals either:

- 7.
- 3082, hexadecimal 0xC0A.

The selected status is the nonzero processing status, or the query status when processing returned zero.

For a query-stage special status, the state-byte write occurs after F-2106ab1fda38 returns. The write does not directly clear the result word or terminate traversal. Dependency effects on later admission remain possible.

### Advancement, stopping, and final call

The index advances after every admitted record, including a skipped record or one whose comparison mismatches.

After a mismatch, the result word is zero, so traversal stops without another count read. Otherwise, the next admission test uses the newly read count.

Following any normal traversal entered with a nonzero setup return, F-94cb53877c15 is called exactly once with the retained address word. This includes empty traversal, all-zero handles, status failures, and comparison mismatch.

The packed return is produced after that call returns. Its execution does not establish that any allocation was released.

## Side effects

### Direct writes

The function directly:

- Initializes its local 32-bit working word.
- Writes the value 1 to the collection state byte on setup failure or a selected status of 7 or 3082.

It never directly clears the state byte. On paths without such a write, it does not normalize a preexisting value.

There is no direct write to the record array or the pointed-to comparison values in the supplied body.

### Dependency-mediated effects

Dependencies may have additional effects not established by this function. In particular:

- Several receive the retained address word.
- F-80f420262fea also receives a record handle and the auxiliary word.
- F-70fe47664dff receives the working-word address.

No dependency is known to preserve globals, collection fields, records, state-byte contents, or other reachable memory. Direct-write descriptions therefore do not guarantee the final externally observed state when dependency mutations are allowed.

The retained address word is reused without checking whether intervening calls changed the validity or lifetime of anything it might identify.

## Acceptance examples

These are conditional static expectations, not executed tests. Unless stated otherwise, calls return normally, address calculations and accesses are valid, and dependencies make no additional changes relevant to the example.

1. **Zero setup return.**  
   F-391e3d30e634 returns zero. The state byte is written with 1. The returned low word is 0 and the upper word is the incoming context word. No collection-count read, record processing, or final dependency call occurs.

2. **Nonzero setup return with no admitted records.**  
   The first observed signed count is zero or negative. No record is read. F-94cb53877c15 receives the nonzero setup return. The packed return has low word 1 and the original context word. This establishes no allocation or release.

3. **All handles zero.**  
   Every admitted record has a zero handle. No per-record dependency is called. The final call still occurs, and the upper return word remains the incoming context word.

4. **Successful match.**  
   A handle is nonzero, both status-producing calls return zero, and the comparison target equals the current working word. F-2106ab1fda38 is called. The result remains 1, the upper return word becomes the retained address word, and traversal may continue.

5. **Successful mismatch.**  
   Both statuses are zero but the comparison values differ. The result becomes 0. F-2106ab1fda38 and the final dependency call still occur. No subsequent count read or record visit occurs. The mismatch itself causes no state-byte write.

6. **Ordinary processing failure.**  
   F-80f420262fea returns 5. Query, comparison, and F-2106ab1fda38 are skipped. This status neither clears the result word nor directly writes the state byte. Later records remain eligible.

7. **Special processing status.**  
   F-80f420262fea returns 7. The state byte is written with 1. The query stage is skipped. The result can remain 1, and traversal can continue.

8. **Special query status.**  
   Processing returns zero and the query returns 3082. No comparison-pointer read occurs. F-2106ab1fda38 is called before the state byte is written with 1. The result word remains unchanged.

9. **Persistent working value.**  
   A query changes the working word and returns a nonzero status. If no intervening dependency changes that storage, the next query receives the changed value through the same address; the fourth argument is not reapplied.

10. **Array replacement during processing.**  
    A dependency replaces the collection’s array address before a successful query’s comparison. The comparison reads the new array at the current index, while the query used the handle retained from the earlier array.

11. **Count reduction during a selected record.**  
    A dependency reduces the count below the current index. A successful query still reaches its comparison without another count check. If the result remains 1, the next admission test observes the reduced count and stops traversal.

The count and index are signed 32-bit quantities. The index begins at zero, and each admitted index is less than the signed count. Under those conditions, index advancement itself does not require exceeding the maximum signed 32-bit value. Record addressing nevertheless multiplies the index by 24 and adds field offsets; these calculations can exceed the supported range independently of valid loop admission.

Portable wrapping behavior for signed arithmetic or out-of-range addresses is not established. Normal-completion expectations require supported arithmetic and valid reached accesses, not a guessed wraparound rule.
