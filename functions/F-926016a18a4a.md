# F-926016a18a4a

## Purpose

F-926016a18a4a conditionally reads a two-byte descriptor, publishes its values into an output record, and derives a size and tag from a mode selector.

Processing is gated by a **32-bit integer read followed by conversion to the target’s character type**. The gate is not an explicit one-byte read. If the converted value is zero, the function returns 6 without accessing the descriptor or writing output.

After passing the gate, the function publishes both descriptor values before validating the mode. Supported modes produce two additional output fields. If both the derived size and the first descriptor value are nonzero, the function invokes F-a1215dd1ebde and returns its result. A zero dependency result additionally causes a one-byte write to the input record.

“Dimensions,” “packed row size,” “format tag,” and “completion-related field” are inferred interpretations. The established contract is the access sequence, arithmetic, mutation, dependency invocation, and return behavior below.

## Behavior

### Gate evaluation

The function first fetches the output pointer from input offset 8. It then reads the 32-bit integer at input offset 16, converts that integer to the target’s character type, and compares the converted value with zero.

If the converted value is zero, the function returns 6 immediately:

- No descriptor-pointer or descriptor-byte access follows.
- The fetched output pointer is not dereferenced.
- No separate mode-byte read occurs.
- No explicit write occurs.
- F-a1215dd1ebde is not called.

Although no separate mode-byte read occurs on this path, the full-width gate read covers the storage containing the mode and completion-related locations.

If the conversion produces a nonzero character value, processing continues.

A gate-source integer of zero converts to zero; a gate-source integer of one converts to a nonzero value. For other integers, especially values outside the target character type’s representable range, the exact conversion behavior is not established here. The test is neither an unqualified whole-integer nonzero test nor an established test of the byte at address offset 16.

### Descriptor acquisition and dimension publication

After the gate passes, the function:

1. Evaluates the descriptor-pointer field and obtains B from descriptor offset 1.
2. Evaluates that pointer field again and obtains A from descriptor offset 0.
3. Writes B to output offset 4 as a 32-bit value.
4. Writes A to output offset 0 as a 32-bit value.
5. Reads the mode at input offset 18.

Both descriptor values are obtained before either output write. There is no explicit write or dependency call between their acquisition operations.

The representation does not establish a single saved descriptor pointer shared by both reads. Under ordinary stable-memory assumptions, both pointer evaluations yield the same address; no concurrency or volatile-memory guarantee is supplied.

Mode validation is not transactional. An unsupported mode is detected only after the two dimension fields have been written.

### Supported modes and arithmetic

The mode determines R and the tag:

| Mode | Derived size R | Tag |
|---:|---|---:|
| 1 | ⌈B / 8⌉ | 1 |
| 2 | ⌈B / 4⌉ | 3 |
| 4 | ⌈B / 2⌉ | 4 |
| 8 | B | 2 |

For modes 1, 2, and 4, the arithmetic adds 7, 3, or 1 respectively, converts the sum to a signed 32-bit integer, and shifts right by 3, 2, or 1 positions. B is an unsigned byte, so the largest sum is 262. All these sums are nonnegative and fit in signed 32-bit storage. Consequently, the ceiling-division descriptions do not depend on how negative signed shifts behave.

For each supported mode, the function writes the one-byte tag at output offset 18 before writing R at output offset 8.

Any mode other than 1, 2, 4, or 8 returns 3. The function then makes no tag write, size write, context access, or dependency call. The earlier dimension writes remain.

### Empty and nonempty cases

After publishing a supported mode’s tag and size, the function evaluates the 32-bit unsigned product R × A.

There is no arithmetic overflow for these inputs:

- A is at most 255.
- R is at most 255.
- The product is at most 65,025.

The product is therefore zero exactly when A or R is zero. For every supported mode, R is zero exactly when B is zero.

If the product is zero, the function returns 0. It does not access the context or explicitly write the completion-related byte.

If the product is nonzero, the function obtains the context pointer, reads the 32-bit argument at context offset 84, and calls F-a1215dd1ebde once.

- A zero dependency result causes a one-byte write of 1 at input offset 17, followed by return value 0.
- A nonzero dependency result is returned unchanged, with no explicit completion-byte write.

Dependency results are not normalized. They may numerically equal the locally generated statuses 3 or 6.

## Side effects

### Explicit mutation order

1. Output offset 4: B, 32 bits.
2. Output offset 0: A, 32 bits.

### Overlap and access ordering

Disjoint records are not established as a general requirement. Where overlap is valid under the target’s access rules, operation order matters:

- The initial 32-bit gate read precedes all explicit writes. Later writes cannot change the gate decision already made.
- Both descriptor values are captured before output publication. Subsequent overlap with descriptor storage does not change those captured values.
- The mode is read after the dimension writes. If either write changes its storage, the resulting mode controls the branch.
- The output pointer is fetched once before the gate. Later modification of its stored field does not redirect this invocation’s output writes.
- The context pointer and context argument are obtained after output publication. Overlapping output writes can change the pointer or argument ultimately used.

The numerical effect depends on target byte order. Whether it changes that later invocation’s converted gate value additionally depends on character-conversion rules.

There is no explicit output write after the dependency call. Final output contents nevertheless remain conditional on dependency behavior and on any overlap with the completion write.
