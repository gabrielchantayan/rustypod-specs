# F-b480b7309435

## Behavior

### Selection rules

The return value is determined by these mutually exclusive cases, in the stated precedence order:

| Condition | Result |
|---|---|
| The value is strictly less than the lower candidate. | The lower candidate. |
| The value is not less than the lower candidate, and the upper candidate is strictly less than the value. | The upper candidate. |
| Neither condition above applies. | The original value. |

Both comparisons are signed and strict. Equality alone does not trigger replacement by the corresponding candidate.

The first case terminates selection immediately. The upper candidate cannot override that result, even when it is numerically smaller than the returned lower candidate.

The function performs no arithmetic on the inputs. It does not add, subtract, negate, multiply, divide, or calculate an interval width. Consequently, its visible logic introduces no arithmetic overflow, underflow, or division failure. Representable extreme values are handled through the same comparisons as other values.

### Ordered bounds

When the lower candidate is less than or equal to the upper candidate:

- A value below the lower candidate produces the lower candidate.
- A value within the inclusive interval produces the original value.
- A value above the upper candidate produces the upper candidate.

Under this condition, the result is guaranteed to lie within the inclusive interval.

If both candidates are equal, every representable value produces that common candidate value. Inputs below it select it through the first comparison; inputs above it select it through the second; an equal input is returned unchanged.

### Reversed bounds

When the lower candidate is greater than the upper candidate, no normalization, validation, swapping, or error reporting occurs.

Two cases describe the resulting behavior completely:

- A value below the lower candidate produces the lower candidate, regardless of its relationship to the upper candidate.
- A value equal to or above the lower candidate produces the upper candidate.

The second result follows because a value at least as large as the lower candidate must also be greater than the smaller upper candidate.

Therefore, for reversed bounds, the original value is never retained as an unchanged in-range value. The function selects one of the two candidates. This is established behavior, not evidence that reversed bounds are intended usage.

### Equality and evaluation order

The lower comparison is considered first. Only when it is false is the upper comparison considered.

Equality with the lower candidate does not cause an immediate return. The upper comparison still determines whether that value is retained. This distinction matters for reversed bounds: a value equal to the lower candidate returns the smaller upper candidate.

Equality with the upper candidate prevents replacement through the upper comparison, but it does not bypass the earlier lower comparison. With reversed bounds, a value equal to the upper candidate is below the lower candidate and therefore returns the lower candidate.
