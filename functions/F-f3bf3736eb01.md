### Combined-result partitioning

An offset-5 byte read of 0xFE supplies word value 0x000000FE where explicitly widened, not 0xFFFFFFFE.

### Early fixed-byte capture

If the read at fixed address 0x05 yields 0xFE, subsequent uses of that captured byte-derived base use 0x000000FE. A later write overlapping fixed address 0x05 does not retroactively change the saved base.

Acceptance also requires the fixed byte write at 0x01 before the following computed offset-0x15 byte store.

### Fixed-base capture before overwrite

If the read at 0x087fbbbc yields a particular base, the following fixed word store of 0x20 to 0x60 does not cause that base to be reread. Computed writes that later overlap 0x087fbbbc likewise do not replace the captured value.

### Saved word versus live fixed byte

Suppose the late read at 0xa9 captures 0x11223344. The explicit write to 0x67 supplies 0x44. Without intervening changes, the copy to 0x21 also receives 0x44.

If an intervening computed write changes 0x67 to 0x9a before the first later computed offset-9 store, that store must consume 0x9a. The adjusted-base offset-0x44 word store still receives the saved 0x11223344.

If another aliasing write changes 0x67 before its second later read, the second computed byte store must consume that newly read value.

### Trace-sensitive stores

A tracing environment must distinguish the offset-0x20 word sequence 0x20, 0x2f, contemporaneously widened byte, 0x20. Observing only the final value does not establish equivalent behavior.

Likewise, both the late offset-0x10 byte store and word store remain required even when they share a destination.

### Partial completion

If the final dependency does not return, normal return is not required. Earlier completed fixed-location and computed-address writes are not implicitly rolled back.
