# F-c7aad02b0442

## Purpose

F-c7aad02b0442 traverses a collection associated with an input object and conditionally replaces three caller-visible outputs: a destination object and two 32-bit result words.

Each yielded item is evaluated using dynamically dispatched operations. An item qualifies either through a nonzero unsigned classification value below a fixed upper boundary, or through a separate predicate when its classification value is zero. Every qualifying item triggers an output-update sequence; traversal does not stop at the first match.

**Inferred intent:** select information from the last qualifying item in traversal order.

**Established limitation:** that intent describes the explicit selection logic, not an unconditional final-state guarantee. Dependencies may modify shared state or aliased output storage, and their implementations are unavailable.

### Item qualification

For each yielded item, the function first invokes the dynamically dispatched operation selected by byte offset `0x178` in the item's dispatch table. Its result is interpreted as an unsigned 32-bit value for the selection decision.

If that result is zero:

- The function invokes the operation at dispatch-table byte offset `0xC4`.
- A zero predicate result rejects the item.
- A nonzero predicate result accepts the item.

If the classification result is nonzero:

- The predicate at offset `0xC4` is not called.
- Values below `0x68000` are accepted.
- Remaining values are accepted only when their unsigned difference from `0x68000` is less than `0x1780`.

For a stable 32-bit value, the complete nonzero acceptance interval is therefore **1 through `0x6977F`, inclusive**. Values from `0x69780` through `0xFFFFFFFF` are rejected.

The upper-bound calculation is:

- `0x68000 + 0x1780 = 0x69780`.
- The comparison is strict, so `0x69780` itself does not qualify.
- Subtraction is reached only when the value is at least `0x68000`; that subtraction does not underflow on the reached branch.

Zero is not accepted by this interval rule. It has its own predicate-controlled path.

A rejected item causes no explicit destination assignment or scalar-result store in this function. Calls already made while evaluating that item may nevertheless have side effects.

### Updating outputs for a qualifying item

Each qualifying item causes the following sequence:

1. Invoke the item's operation at dispatch-table byte offset `0x14`, passing the address of local temporary storage.
2. Compare the destination address with that temporary-storage address.
3. If the addresses differ, call F-151ab4bfe553 with the destination address and a 32-bit value read from a local slot adjacent to the temporary storage.
4. Call F-289ec4311c64 on the temporary-storage address, whether or not assignment was skipped.
5. Invoke the item's operation at offset `0x178` again.
6. Read a 32-bit value from a fixed static location and call F-d7be9cfb4000 with the newly obtained item value and that static value.
7. Store F-d7be9cfb4000's 32-bit result through the first result address.
8. Invoke the item's operation at dispatch-table byte offset `0x184`.
9. Store that operation's 32-bit result through the second result address.
10. Resume iterator advancement.

The second invocation at offset `0x178` is significant. The function does not reuse the value that qualified the item. If item state changes, or that operation is stateful, qualification and the first result calculation can use different values. The second value is not checked against the acceptance interval.

Likewise, the static value supplied to F-d7be9cfb4000 is read during each qualifying update. It is not visibly cached before traversal.

## Acceptance examples

These are conditional acceptance criteria derived from static evidence, not executed tests. Unless stated otherwise, assume valid storage, normal dependency returns, distinct outputs, and no unrelated dependency writes to those outputs.

1. **No yielded items.**  
   The first advancement returns zero. Destination initialization occurs before both result words are zeroed. Iterator initialization, advancement, and finalization occur. No item operation is invoked.

2. **Zero classification, false predicate.**  
   The first classification is zero and the predicate returns zero. The item is skipped. No temporary-producing operation, assignment dependency, or scalar-result update occurs for that item.

3. **Zero classification, true predicate.**  
   The first classification is zero and the predicate returns any nonzero value. The complete qualifying update occurs. The later classification value used for transformation need not be zero.

4. **Lower nonzero boundary.**  
   A classification of 1 qualifies without calling the predicate.

5. **Boundary between the two nonzero checks.**  
   Both `0x67FFF` and `0x68000` qualify. Neither causes a predicate call.

6. **Upper acceptance boundary.**  
   `0x6977F` qualifies; `0x69780` does not.

7. **Large unsigned value.**  
   `0xFFFFFFFF` is rejected as a nonzero unsigned classification. It does not enter the zero-classification predicate path.

8. **Classification changes between calls.**  
   The first classification is 1, qualifying the item. The later classification is `0xFFFFFFFF`. F-d7be9cfb4000 receives `0xFFFFFFFF`; the item is not rejected retroactively.

9. **Two qualifying items with a rejected item between them.**  
   Both qualifying items update outputs. The rejected item performs only its selection-related calls. Under the noninterference assumptions, the later qualifying item's assignments determine the final outputs.

10. **Identical scalar output addresses.**  
    For a qualifying item, the transformed first result is stored first. The result obtained at offset `0x184` is stored afterward to the same address and is the later explicit value.

11. **Destination equals temporary address.**  
    If this equality is possible in the execution environment, F-151ab4bfe553 is skipped. F-289ec4311c64 and both scalar-result computations still occur.
