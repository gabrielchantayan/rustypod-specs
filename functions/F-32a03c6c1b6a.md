# F-32a03c6c1b6a

## Purpose

F-32a03c6c1b6a constructs and returns a pair of 32-bit values through one of two dependency-call sequences. The sequence is selected solely by whether the third input is zero.

The zero-input path obtains one dependency result, submits it with a zero payload, and returns that result paired with the original context value.

The nonzero-input path obtains eight dependency results and submits a fixed sequence of operations involving those results, the third input, fixed numeric values, and one externally stored value. It returns the seventh and second dependency results as the low and high halves of a 64-bit result.

These are structural descriptions. The meanings of the generated values, operation selectors, and externally stored value are not established. Describing this routine as an allocator, evaluator, serializer, or instruction generator would require evidence beyond the supplied material.

The exact native calling convention, address-space rules, and treatment of invalid address arithmetic are not established. A valid-call precondition is that the context-relative read is meaningful in the execution environment; this contract does not invent wrapping or fault-recovery behavior.

### Output

The normal return is a 64-bit value assembled from two 32-bit halves:

- **Zero-input path:** high half is the original context value; low half is the single result obtained from F-b35e541ebc78.
- **Nonzero-input path:** high half is the second result obtained from F-b35e541ebc78; low half is its seventh result.

The halves contribute their 32-bit bit patterns. A high bit set in either half does not imply sign extension into the other half. “High” and “low” describe numeric bit positions, not byte order in memory.

No separate success flag or error return is visible.

## Behavior

### Common entry behavior

Before choosing a branch, the routine reads one 32-bit word from the context at byte offset 4. That captured word is the first argument to every subsequent F-b35e541ebc78 call made by this invocation. The second argument to each such call is zero.

The context-relative word is not visibly reread. If a dependency changes the context field after the initial read, later requests still receive the captured value.

This establishes argument selection only. It does not establish that dependencies preserve the context, external state, or the validity of resources represented by earlier results.

### Zero-input path

When the third input is zero, the observable sequence is:

1. Call F-b35e541ebc78 with the captured context word and zero.
2. Call F-fbf0cbff8cb3 with four visible arguments, in order:
   - original context value;
   - selector 40, hexadecimal 0x28;
   - the result of the preceding call;
   - zero.
3. Return the original context value as the high 32 bits and the obtained result as the low 32 bits.

There is exactly one visible request to F-b35e541ebc78 and one visible call to F-fbf0cbff8cb3. F-915779408ccb is not called on this path.

The result of F-fbf0cbff8cb3, if it has one, does not contribute to the visible return value.

### Nonzero-input path

For this path, “first result” through “eighth result” mean the results of the eight F-b35e541ebc78 calls, in their execution order. These ordinal names do not imply distinctness, successful allocation, ownership, or any particular numeric range.

The sequence is:

1. Obtain the first result.
2. Call F-fbf0cbff8cb3 with seven visible arguments:
   - original context value;
   - selector 40;
   - first result;
   - zero;
   - original context value again;
   - original third input;
   - first result again.
3. Obtain the second result.
4. Call F-fbf0cbff8cb3 with the original context, selector 40, the second result, and 17, hexadecimal 0x11.
5. Obtain the third result.
6. Call F-fbf0cbff8cb3 with the original context, selector 40, the third result, and 65,536, hexadecimal 0x10000.
7. Obtain the fourth, fifth, sixth, and seventh results, in that order, with no intervening visible submission calls.
8. Call F-915779408ccb with the original context, selector 16, hexadecimal 0x10, the fourth result, the original third input, and the first result.
9. Call F-915779408ccb with the original context, selector 15, hexadecimal 0x0F, the fifth result, the fourth result, and the third result.
10. Obtain the eighth result.
11. Read the externally stored value used by the next call.
12. Call F-fbf0cbff8cb3 with the original context, selector 40, the eighth result, and that externally stored value.
13. Call F-915779408ccb with the original context, selector 9, the sixth result, the fifth result, and the eighth result.
14. Call F-915779408ccb with the original context, selector 7, the seventh result, and the sixth result.
15. Return the second result as the high 32 bits and the seventh result as the low 32 bits.

Every “obtain” step is a call to F-b35e541ebc78 with the captured context word and zero.

This path therefore contains eight calls to F-b35e541ebc78, four to F-fbf0cbff8cb3, and four to F-915779408ccb.

The externally stored value is consumed late: after the eighth result is obtained and before its submission call. Earlier dependencies may affect the value observed there. Replacing this late read with an entry-time snapshot is not justified without additional dependency guarantees.

No visible conditional checks occur between these calls. In particular, a zero or repeated result does not trigger a different branch in this routine.

These examples are conditional specifications, not reports of executed tests. Dependency calls are assumed to return normally.
