# F-36f6239a66ad

## Purpose

F-36f6239a66ad performs a stateful sequence of dispatch-word updates, address recovery, conditional associated-state processing, and final object processing. On normal completion, it returns the recovered object’s address, which is not established to equal the input address.

**Established static behavior:** the function reads global words at distinct stages, writes three input-relative words, obtains another object through an ordered dependency chain, writes that object’s leading word twice, invokes direct and indirect dependencies, and conditionally clears a context field. Two branches lead to a dependency identified by the supplied representation as nonreturning.

**Inferred intent:** the sequence resembles teardown, destruction, or detachment. These interpretations do not establish ownership transfer, reference-count changes, memory release, or the semantics of any dispatch operation.

This contract describes the supplied static representation. No runtime tests have been performed.

## Behavior

### Initial reads, writes, and early branch

The initial sequence distinguishes two reads of the same global word:

1. Read the initial dispatch word and retain its value.
2. Read that global word again and write this second value to input `+0x00`.
3. Write the retained first value plus `0xCC` to input `+0x18`.
4. Write the retained first value plus `0xE4` to input `+0x1C`.
5. Read input `+0x98`.

The three writes therefore do not necessarily derive from one common observed value. Equality between the two global reads is not a contractual assumption.

If input `+0x98` is nonzero, invoke F-54385ab29a1f with no explicit arguments. If it returns, invoke F-feee9156a257, identified as nonreturning. No recovery calls or normal return follow on this represented path.

The initial writes precede this branch and are not rolled back.

### Object recovery

If input `+0x98` is zero, recover the object through this ordered chain:

1. Invoke F-289ec4311c64 with input address plus `0x8C`.
2. Subtract `0x20` from its result and pass that address to F-ac732fdfee54.
3. Subtract `0x3C` from that result and pass it to F-3803f6e40d17.
4. Subtract `0x0C` from that result and pass it to F-289ec4311c64.
5. Subtract `0x24` from the final result to obtain the recovered object.

No intermediate result is checked for nullness or validity.

### Intermediate dispatch state and initial dependencies

Read the intermediate dispatch global word and write its value to recovered-object `+0x00`. Then invoke F-408b56b8b7c8 with the recovered object.

Next, invoke F-3fdd14ecd250 to obtain a context address. Invoke F-77781c8e0ff9 with:

- The 32-bit word at that context’s `+0x1C`.
- A runtime read of the separate dependency-argument global word.

The supplied call expression does not establish the relative evaluation order of the context-field read and the global-argument read. Both supply arguments to the same call; neither read is specified here to precede the other.

Only after F-77781c8e0ff9 returns does the function read recovered-object `+0x0C`. Earlier dependencies can therefore affect whether associated-state processing occurs.

### Associated-state entry

If recovered-object `+0x0C` is zero, skip all associated-state processing.

Otherwise, retain that associated-state address and capture its `+0x04` word. The retained address remains the basis for subsequent associated-state accesses, except for the explicitly fresh object-field read described below.

Call F-a1a48bd3fbde with the recovered object. Its zero/nonzero result controls the following subpath, but not the rest of associated-state processing.

1. Invoke F-3fdd14ecd250 and test its context field at `+0x28`.
2. If that field is nonzero:
   - Invoke F-3fdd14ecd250 again.
   - Read this new context’s `+0x28` as an object address.
   - Read that object’s leading dispatch-table address and invoke the target at table byte offset `+0x48`.

The initial nonzero context-field test does not validate the field obtained from the next context-provider call. Likewise, the fresh recovered-object `+0x0C` read is not followed by another null check before its `+0x04` access.

### Traversal-related processing

### Final dispatch state and optional branch

After associated-state processing, or immediately after it is skipped, read the final dispatch global word and write it to recovered-object `+0x00`. This read occurs at this stage; it is not a value retained from entry.

Then test recovered-object `+0x04`.

If zero, return the recovered object without reading `+0x08` for the residual-state condition.

If nonzero:

1. Invoke F-c719314a16bb with the recovered object.
2. Reread recovered-object `+0x04`.
3. If nonzero, obtain the object from that field and invoke its dispatch-table slot at `+0x04`.
4. Read recovered-object `+0x08`.
5. If nonzero, invoke F-c8eefdf96f4b with no explicit arguments. If it returns, invoke nonreturning F-feee9156a257.

## Acceptance examples

These are conditional consequences of static evidence, not executed tests.

1. **Initial global reads differ.** If the retained first read yields `0x1000` and the second read yields `0x2000`, input `+0x00` receives `0x2000`, while `+0x18` and `+0x1C` receive `0x10CC` and `0x10E4`. A single-read description would be incorrect.

2. **Early condition is nonzero.** All three input writes precede F-54385ab29a1f. If it returns, F-feee9156a257 follows. Recovery is not reached.

3. **Later global values change.** If preceding dependencies change the dependency-argument or final dispatch global, the corresponding later read supplies that stage’s value. Neither is required to match an earlier value. No ordering is imposed between the context-field and global-argument reads for F-77781c8e0ff9.

4. **No associated state or final optional object.** With zero recovered-object `+0x0C` and a zero final `+0x04` test, associated-state processing is skipped and normal return follows the final dispatch write. A nonzero `+0x08` alone does not select the final exceptional path.

5. **Associated state exists, predicate and collection condition are zero.** Predicate-controlled calls and traversal are skipped. Later context comparisons still occur, followed by one F-65528ded3450 call and F-8349c252c168.

6. **Predicate succeeds and the later context comparison matches.** If execution continues normally and the post-traversal context `+0x28` equals the recovered object, F-a82ec4b43e2f receives the original captured value twice. F-65528ded3450 is also called twice.

7. **Traversal yields a null item.** A nonzero traversal return with a zero first output word causes another traversal attempt without a per-item indirect call. The second output word does not affect that decision.

8. **Context results differ.** If one context’s `+0x24` matches but the next provider call returns another context, the zero write targets the latter context without another equality check.

9. **Final optional field is cleared.** If F-c719314a16bb clears recovered-object `+0x04`, its indirect call is skipped. The residual `+0x08` test still occurs; a nonzero result leads to F-c8eefdf96f4b and, if it returns, F-feee9156a257.
