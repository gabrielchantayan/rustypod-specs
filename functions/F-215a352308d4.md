# F-215a352308d4

## Purpose

F-215a352308d4 conditionally compacts a region represented by a caller-supplied object, adjusts a sequence of 16-bit metadata entries, and replaces a stored 16-bit count.

**Established static behavior:** the function selects two boundaries through dependency calls, invokes a three-argument operation on derived addresses and a derived length, rewrites metadata in increasing index order, and finally updates the count. It returns either zero or the 32-bit pattern `0xFFFFFFCE`.

**Inferred intent:** the address operation and subsequent metadata adjustment are consistent with removing a contiguous region and closing the resulting gap. Neither the underlying data format nor the address operation’s actual copying or movement semantics is established. This contract therefore distinguishes the observed call sequence from that interpretation.

No runtime tests have been performed.

## Interface

### Input object

The function accepts one argument represented as a 32-bit address. The supplied evidence establishes access to these fields relative to that address:

| Byte offset | Width | Observed use |
|---|---:|---|
| 4 | 32 bits | Address of another structure containing a count field |
| 20 | 32 bits | Signed threshold used during the forward boundary search |
| 24 | 32 bits | Signed threshold used during the backward boundary search |

The structure referenced by the field at offset 4 contains a 16-bit field at byte offset 10. The function reads that field, passes its value to F-0ec8efa9c769, and retains the returned 32-bit result as its initial count.

The complete sizes, alignment requirements, ownership, and other fields of both structures are unknown. No null, range, alignment, or accessibility checks are visible before these accesses.

### Dependency-facing values

For clarity, this contract uses the following descriptive terms:

- **Initial count:** the 32-bit result obtained from the initial count-field conversion.
- **Boundary value:** the 32-bit result of F-ff0ead080160 for the object and an index.
- **Data address:** the result of F-cc3e58e43b8f.
- **Metadata address:** the result of F-f88598b51cc2, subsequently accessed as a 16-bit location.

Every index supplied to these three indexed dependencies is reduced to its low 16 bits. This is separate from the function’s own loop counters, which are 32 bits.

These terms describe observed uses, not verified meanings of the dependencies.

### Result

The returned value is a 32-bit bit pattern:

- `0x00000000`: the operation reached the final count write.
- `0xFFFFFFCE`: the function took one of its visible rejection paths.

The latter pattern is −50 when interpreted as a signed 32-bit integer. No symbolic error meaning is established.

There is no visible exception handling, dependency-status validation, or rollback mechanism.

## Behavior

### 1. Capture the initial count

The first observable operations are:

1. Read the 32-bit address at object offset 4.
2. Read the 16-bit field at offset 10 within the referenced structure.
3. Call F-0ec8efa9c769 with that field value.
4. Retain the returned 32-bit result as the initial count.

The initial count is not reread after subsequent dependency calls.

Although the stored field is 16 bits, the conversion dependency’s output is used as a full 32-bit value. A guarantee that the initial count is at most 65,535 cannot be established from this function alone.

### 2. Search forward for the first qualifying boundary

The function examines positions beginning at zero while the position is less than the initial count under a signed 32-bit comparison.

At each position:

1. Call F-ff0ead080160 with the object and the low 16 bits of the position plus one.
2. Subtract one from the returned boundary value and retain only the low 16 bits.
3. Read the signed 32-bit threshold at object offset 20.
4. Stop if that threshold is strictly less than the masked value.

The masked comparison operand is in the range 0 through 65,535. The comparison is not directly against the dependency’s unmodified return value.

In particular:

- A returned value of zero produces a comparison operand of 65,535.
- A returned value of one produces a comparison operand of zero.
- Return values with identical low 16 bits produce the same comparison operand.

When a qualifying position is found, the function retains that position minus one as a marker. The marker begins at −1.

This creates an important special case: **a match at position zero leaves the marker equal to −1**, indistinguishable from finding no qualifying position. Either case returns `0xFFFFFFCE` without entering the backward search.

If the initial count is zero, or its signed 32-bit interpretation is negative, the forward search performs no boundary calls and returns `0xFFFFFFCE`.

For the remaining behavior, let the **destination index** denote the first qualifying forward position. A successful path requires this index to be at least one. The retained marker is one less than that index.

### 3. Search backward for a source index

After an accepted forward match, the function searches backward beginning at the initial count minus one.

At each examined position:

1. Call F-ff0ead080160 with the object and the low 16 bits of that position.
2. Read the signed 32-bit threshold at object offset 24.
3. Continue backward while the threshold is less than or equal to the returned boundary value, interpreted as signed.

The first position whose boundary value is strictly less than the threshold establishes the **source index** as that position plus one.

Equality therefore continues the search; it does not select a source index.

If the search exhausts positions through zero without finding a strict inequality, it returns `0xFFFFFFCE`. It does not invoke the address operation or perform the direct metadata and count writes.

On the ordinary terminating path, the source index is between one and the initial count, inclusive.

There is no visible check that the source index is greater than or equal to the destination index.

### 4. Invoke the address operation

Once both indices have been selected, the function makes these calls in this order:

1. F-cc3e58e43b8f for the source index.
2. F-cc3e58e43b8f for the destination index.
3. F-ff0ead080160 for the initial count.
4. F-ff0ead080160 for the source index.
5. F-70a021fc7c24 with:
   - the first data-address result;
   - the second data-address result;
   - the boundary value for the initial count minus the boundary value for the source index.

All dependency indices in this sequence are truncated to 16 bits.

The third argument is derived from boundary values, **not** from the two data addresses. The function does not visibly validate its sign or range.

The result of F-70a021fc7c24, if any, is ignored. Its argument order is established; whether that means source followed by destination, destination followed by source, or another convention is unknown.

### 5. Rewrite metadata

The function computes an index displacement equal to:

**source index − destination index**

It then processes indices from the source index through the initial count, **inclusive**, using a signed 32-bit loop comparison.

For each processed index, the observable sequence is:

1. Call F-f88598b51cc2 for that index, reduced to 16 bits, obtaining the source metadata address.
2. Call F-f88598b51cc2 for the index minus the displacement, reduced to 16 bits, obtaining the destination metadata address.
3. Read 16 bits from the source metadata address.
4. Call F-0ec8efa9c769 with the value just read.
5. Subtract the difference between the previously obtained source and destination data addresses from that conversion result, retaining only the low 16 bits.
6. Call F-0ec8efa9c769 with the masked result.
7. Write the low 16 bits of that second result to the destination metadata address.

The source metadata read occurs **after both metadata-address calls**. Any changes caused by the second call can therefore affect the value subsequently read from the first returned address.

The data-address difference used here is distinct from the boundary-value difference supplied to F-70a021fc7c24.

The loop includes the entry at the initial count. This is consistent with an endpoint or sentinel entry, but that role is inferred rather than established.

The loop does not use a temporary array. If metadata locations alias, an earlier write may affect a later read. Preservation of original metadata values must not be assumed.

### 6. Replace the count and return

After the metadata loop terminates:

1. Subtract the index displacement from the initial count.
2. Retain the low 16 bits.
3. Call F-0ec8efa9c769 with that value.
4. Reread the 32-bit address at object offset 4.
5. Write the low 16 bits of the conversion result to offset 10 of the currently referenced structure.
6. Return zero.

The final write does not necessarily target the structure read at entry: the object’s address field is reread after all preceding dependency calls, including the final conversion call.

### Arithmetic and termination boundaries

The visible behavior combines 32-bit quantities, signed comparisons, and explicit low-16-bit reductions. These distinctions are contractual:

- Indexed dependency arguments wrap modulo 65,536.
- The forward comparison masks after subtracting one.
- The backward comparison uses the full signed boundary result.
- Metadata adjustment masks after subtracting the data-address difference.
- The replacement count is masked before its final conversion.

Arithmetic outside a signed 32-bit range is not sufficiently characterized by the supplied representation to promise portable overflow behavior. Valid callers should not rely on such cases without additional evidence.

There is also a visible extreme-count hazard. If the initial count is `0x7FFFFFFF` and execution reaches the metadata loop, its signed comparison admits every 32-bit loop-counter pattern. Under ordinary wrapping advancement, that loop does not terminate. A 16-bit stored input alone does not rule this out unless F-0ec8efa9c769 is known to constrain its output.

## Side effects

### Direct effects

The function directly performs:

- Reads of the count-address field and initial 16-bit count field.
- Repeated reads of the two signed threshold fields during their respective searches.
- One 16-bit metadata read and one 16-bit metadata write per metadata-loop iteration.
- One final 16-bit count-field write on a completing path.

The thresholds are not captured once at entry. Each is read after the relevant boundary dependency call, so dependency-induced changes can affect the current comparison.

### Dependency effects and ownership

All other side effects are delegated and unknown.

The function contains no explicit allocation, release, or ownership-transfer operation. This does not establish that its dependencies allocate nothing, release nothing, preserve globals, or leave the input object unchanged.

Returned addresses are retained across later dependency calls and then used. Their validity and lifetime are required for successful execution, but not verified here.

The visible rejection paths perform no direct metadata or count writes. They may nevertheless have observable effects through dependencies already called.

If execution fails after the address operation or during metadata rewriting, no restoration is visible. Atomicity is not guaranteed.

## Acceptance examples

These are conditional static expectations, not executed tests. Examples using identity conversion require F-0ec8efa9c769 to return its input unchanged.

### Empty count

If the initial conversion returns zero:

- No boundary search calls occur.
- No address operation or direct metadata write occurs.
- The result is `0xFFFFFFCE`.

### First-position qualification

If the initial count is positive and the first forward comparison qualifies:

- The boundary dependency receives index one.
- The function returns `0xFFFFFFCE`.
- The backward search is not entered.

This distinguishes the implemented marker behavior from an interpretation that accepts a removable region beginning at the first position.

### Forward masking at zero

If a forward boundary call returns zero, its comparison operand is 65,535. A current forward threshold of 65,534 qualifies; a threshold of 65,535 does not.

Qualification at position zero still follows the rejection behavior above.

### Backward equality

If the backward threshold and current boundary value are both 40, the search continues. A boundary value of 39 selects the following index, assuming the threshold remains 40.

### Completing compaction-shaped case

Assume:

- Identity conversion.
- Initial count six.
- Destination index two.
- Source index four.
- Source and destination data addresses 1,040 and 1,000.
- Boundary values at indices six and four of 100 and 60.
- Stable, nonaliasing metadata storage.

Then:

- F-70a021fc7c24 receives 1,040, 1,000, and 40, in that order.
- Metadata indices four, five, and six are processed in increasing order.
- Their destinations are indices two, three, and four.
- Each converted metadata value is reduced by 40 modulo 65,536 before being written.
- The final logical count supplied for conversion is four.
- The return value is zero if execution completes.

### No backward match

If every backward boundary value is at least the threshold, including at index zero, the function returns `0xFFFFFFCE` without the address operation or direct metadata/count writes.

### Changing the count destination

If a dependency changes the object’s offset-4 address field before the final write, that write uses the new address. An implementation that caches the entry-time address would not preserve the observed behavior.
