# F-e71d70bf6006

## Purpose

F-e71d70bf6006 invokes an ordered sequence of unresolved indirect dependencies, transforms returned and call-associated values, and then performs mixed-width memory accesses through computed addresses and fixed storage. Its final represented dependency invocation receives four arguments derived from literals and earlier memory captures.

No application-level purpose is established. Repeated offsets, self-referential writes, and character-like numeric values do not establish object initialization, text output, collection management, or a device protocol.

This is a conditional static behavioral contract:

- **Established static evidence:** explicit value relationships, access types, and ordering in the supplied representation.

## Interface

### Inputs and outputs

The represented interface has no explicit parameters and no explicit return value. It provides no status code, output-buffer parameter, length, or error result.

Implicit inputs include incoming return-link state, unresolved call results, additional call-associated register values, global contents, computed memory contents, and the final indirect destination.

Ordinary scalar and address-bearing values are represented as 32 bits. Selected dependency results are represented as 64 bits and separated numerically into low and high 32-bit portions. This numerical separation does not establish memory endianness.

Observable outputs consist of dependency invocations and memory mutations. A return is represented after the final call, conditional on that destination returning normally.

### Arithmetic model

Established transformations include masks, unsigned right shifts, left shifts through thirty-one positions, and multiplication by powers of two. Conversion and masking boundaries are significant.

Examples:

- Retaining twenty low bits and shifting right by ten yields 0–1023.
- Retaining twenty-four low bits and shifting right by twenty yields 0–15.
- An unsigned 64-bit right shift by forty-four is numerically equivalent to shifting its high 32-bit portion right by twelve.
- Masking to twenty-two bits before a left shift is not generally equivalent to shifting an unrestricted word.

**[INFERENCE]** Under a 32-bit bitvector model, left shifts, multiplication, and scaled-address arithmetic retain the low thirty-two bits. Under that model, a word shifted left by twenty-five and subsequently by seven becomes zero.

Signed-looking shifts and arithmetic can exceed their represented ranges. Portable signed-overflow behavior, address wrapping, and out-of-range shift behavior are not established.

## Acceptance examples

These are conditional static criteria, not executed tests.

### Explicit computed width

If scaled-root offset 5 yields unsigned byte 0xE2, its word publication supplies 0x000000E2. An explicitly computed byte destination receiving low byte 0xAB stores eight bits; this criterion does not apply to undeclared fixed globals.

### Fixed assignments do not establish footprints

If the small base’s low byte is 0xAB, fixed 0x01 receives an explicitly eight-bit-converted value of 0xAB. Acceptance does not require a one-byte access or preservation of neighboring bytes without its declaration.

### Read before fixed mutation

The address-bearing capture from fixed 0x05 precedes the assignment to fixed 0x01. If their actual footprints overlap, replacing the capture with a post-assignment read is not equivalent.

### Promoted 0x3A arithmetic

If character conversion of the adjusted base yields 0x21, the promoted expression supplies 0x138 to fixed 0x3A. Requiring an unconditional stored value of 0x38 would add an unestablished final truncation.

If the actual 0x3A assignment footprint overlaps a following word capture, that capture reflects the mutation according to the actual layout. Earlier captures are not post-assignment rereads.

### Separate 0x67 reads

If the second global read at 0x67 yields a value whose low byte is 0xE2, the corresponding computed offset-9 byte store receives 0xE2. The third read remains independent.

The first read instead supplies fixed 0x21; this contract does not impose eight-bit truncation there.

### Repetition and completion

An inaccessible reached destination does not require rollback or completion. If the final call is reached, its first argument is 0x72 and its third argument is the capture taken after the fixed 0x3A assignment.
