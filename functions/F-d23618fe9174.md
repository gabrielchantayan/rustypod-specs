# F-d23618fe9174

## Purpose

The established behavior is an unconditional loop of indirect calls, computed-address memory accesses, and state updates carried into the next iteration. There is no visible normal return.

No application-level purpose is established. Repeated scaling, byte selection, and stores at offset 20 do not establish an object layout, allocator protocol, device interface, or serialization format.

This contract describes operations visible in the supplied static representation. Every later operation is conditional on earlier calls returning and earlier memory accesses completing. The unconditional loop does not guarantee progress, successful completion of an iteration, or execution without faults.

## Interface

### Explicit arguments

The displayed interface has four 32-bit arguments.

| Argument | Established use |
|---|---|
| First | Not explicitly referenced in the visible body. |
| Second | Not explicitly referenced in the visible body. |
| Third | Supplies shifted values to a word store and an indirect call; replaced by a call result for the next iteration. |
| Fourth | Passed to an indirect call; replaced by four times a later call result for the next iteration. |

The first two arguments have no established direct effect. Their irrelevance to unknown callees or the complete calling environment is not established.

### Additional entry state

The first iteration also consumes:

- An incoming base used for unsigned-byte reads at offset 1.
- An incoming 32-bit seed used by the first word store.
- An incoming link-like value used to derive the first indirect-call target.
- A readable global 32-bit word, sampled partway through the iteration.

These values are not initialized from the four explicit arguments in the visible body.

A later two-argument call also consumes an **unresolved implicit 32-bit register value**. This is a requirement at that call site, not an established entry input. Its provenance is unknown. Intervening calls prevent an assumption that it retains an entry value, and no reliable register-output contract establishes that a particular preceding call produces it.

### Results, preconditions, and errors

There is no visible returned result, status code, completion flag, or explicit error-reporting path. Observable outputs consist of memory writes and callee effects.

For an operation to complete, its effective address must support the specified access, or its indirect target must support the attempted call. The body contains no visible validation of these conditions. Fault handling, exception propagation, and invalid-target behavior are not established.

No ownership transfer is established for arguments, addresses, or returned values.

### Widths and arithmetic

A **byte** is 8 bits, a **word** is 32 bits, and a **wide result** is 64 bits split into low and high 32-bit words.

The numerical descriptions below use low-32-bit multiplication, addition, and left shifts. Unsigned right shifts zero-fill. Byte stores retain only the low 8 bits. This is a machine-level interpretation of the visible operations, not a claim that signed-looking overflowing expressions have defined semantics in a particular source language.

Addresses are byte addresses. Word byte order, alignment requirements, and actual address-space restrictions remain unresolved.

## Behavior

### Access conventions

A **selector read at base** \(p\) reads one unsigned byte at \(p+1\). If its value is \(s\), a **selected byte destination** is the absolute address \(s+17\), ranging from 17 through 272. It is not an address relative to \(p\).

Define the byte projection:

\[
E(v)=\left(((v\mathbin{\&}0x3fffffff)\gg20)\mathbin{\&}255\right).
\]

A **word destination for index** \(q\) is \(4q+20\), using the arithmetic convention above.

Repeated selector reads are separate observations unless explicitly described as retained. Unknown calls between accesses may change memory and globals. A previously captured value is distinguished from a subsequent reread.

The phases below preserve the order of explicit memory accesses and argument-bearing call relationships. References to intervening calls denote actual call boundaries, including calls with ignored displayed results; those calls are not established to be removable or effect-free.

### 1. Entry, first payload, and retained selector

Each iteration starts with an indirect call derived from the current link-like state. A following indirect call returns an index.

The first explicit write stores the current seed word at the word destination for that index. A subsequent call receives four times the index. Following intervening calls, another call supplies the **first payload**.

The function reads a selector at the current incoming base and stores the low byte of four times the first payload at the selected byte destination. A call then receives four times the first payload. Another call supplies a word that is passed onward as the first argument of a two-argument call; its second argument is the first payload shifted left by 30.

After intervening calls, another word is obtained. The function then rereads the selector at the incoming base, retains this second selector, and writes \(E(\text{first payload})\) at its selected byte destination. A call receives four times the newly obtained word, followed by further calls.

The next explicit write is a 32-bit store of four times the current third argument at:

\[
\text{retained second selector}+20.
\]

This destination is not scaled by four. Its starting address ranges from 20 through 275. The selector is not reread after the intervening calls.

### 2. Global snapshot and first wide result

Immediately after that word store, the function reads and retains the global 32-bit word. The read occurs before the call receiving the current fourth argument.

Following that call and intervening calls, another call supplies the **first wide result**. Define the **first scale** as four times its low word; retain its high word separately.

The function next rereads the selector at the incoming base and writes the low byte of the global snapshot shifted right by 22 at the selected byte destination. It then passes the first wide result’s high word to a call.

A following call supplies a word passed to a two-argument call together with the first scale shifted left by 28. After intervening calls, another word is obtained. A fresh selector read at the incoming base determines the destination of a zero-byte write. A subsequent call receives four times that latest word.

After further calls, another word is obtained and four times that word is passed twice to a two-argument call. The global snapshot is not refreshed during this phase.

### 3. First pair of repeated-payload word stores

After further calls, define the **second payload** as four times a newly returned word.

The function stores this payload at:

\[
4096\times\text{first scale}+20.
\]

The next argument-bearing call receives the first scale shifted left by 14. After intervening calls, another index is returned. The same second payload is stored at that index’s word destination, and a call receives four times that index.

These stores need not be disjoint from each other or from earlier accesses.

### 4. Second wide result and selected-byte clearing

After further calls, another call supplies the **second wide result**. Define the **second scale** as four times its low word.

The next selector is read at:

\[
16384\times\text{first scale}+1.
\]

The function writes \(E(\text{second payload})\) at that selector plus 17, then passes the second wide result’s high word to a call.

A subsequent call supplies a word passed to another call. Another wide result is then obtained, and its low and high words are passed separately, in that order, to a two-argument call.

Following further calls, another word is obtained. The function reads a selector at base:

\[
2^{28}\times\text{second scale}
\]

and writes zero at its selected byte destination. A call receives four times the latest returned word.

After further calls, a word called the **branch value** is obtained. Define the **retained selector base** as four times the second scale. A selector read at this base determines another zero-byte destination.

A call receives the second scale shifted left by 10. A subsequent call supplies a word passed onward together with the current third argument shifted left by 28.

After further calls and another returned word, the function rereads the selector at the retained selector base and writes another zero byte. A call receives four times that latest word, followed by additional calls.

The two reads at the retained selector base are independent. Neither their equality nor preservation of the first cleared byte is guaranteed.

### 5. Branch-derived updates and unresolved register argument

Define the **branch scale** as four times the branch value and the **third payload** as the branch value shifted left by 14.

The function stores the third payload at:

\[
4096\times\text{branch scale}+20.
\]

A call receives the branch scale shifted left by 14. Following another call, a two-argument call receives:

1. The third payload shifted left by 28.
2. The unresolved implicit register value available at that call site.

Under the stated 32-bit arithmetic interpretation, the first argument is zero because the third payload already has at least 14 zero low bits. This imposes no constraint on the second argument. The preceding call’s occurrence does not establish that it produces that second argument.

After further calls, a returned index selects another word destination for the same third payload. A call then receives four times that index.

Following further calls, another returned word becomes the **next index**. Define the **next scale** as four times this index. The function rereads the selector at the retained selector base and writes \(E(\text{third payload})\) at the selected byte destination.

A call receives the branch value shifted left by 26. Another call supplies a word passed onward together with the next scale shifted left by 28. A wide result is subsequently obtained and its low and high words are passed separately, in that order, to another call.

After further calls, another word is obtained. A fresh selector read at the retained selector base determines a zero-byte write, and a call receives four times the latest word.

### 6. Remaining repeated-payload word stores

After further calls, define the **fourth payload** as four times a newly returned word.

The next six explicit stores are all 32-bit stores, in this order:

| Order | Destination | Value | Subsequent argument-bearing call |
|---|---|---|---|
| 1 | \(4096\times\text{next scale}+20\) | Fourth payload | Four arguments: \(1024\times\text{next scale}\), the same value again, next index shifted left by 14, fourth payload. |
| 2 | Word destination for a newly returned index | Fourth payload | Four times that index. |
| 3 | \(16\times\text{newly returned word}+20\) | Four times that word | The stored value repeated as three arguments. |
| 4 | Word destination for a newly returned index | Value stored in order 3 | Four times that index. |
| 5 | \(16\times\text{another newly returned word}+20\) | Four times that word | The stored value repeated as three arguments. |
| 6 | Word destination for a newly returned index | Value stored in order 5 | Four times that index. |

Intervening calls separate these operations. Retain the index from order 6 as the **final retained index**.

The returned word used in order 5 also determines the **next base**:

\[
\text{next base}=2^{30}\times\text{that word}.
\]

Under 32-bit arithmetic, the next base is one of \(0\), \(2^{30}\), \(2^{31}\), or \(3\times2^{30}\).

### 7. Direct clearing, final read, and loop-carried state

After further calls, another returned word becomes the **final payload**.

The function writes zero directly at next base plus 17 and then at next base plus 1. These are direct byte stores, not selector-based stores.

A call receives four times the final payload. A following call supplies a word passed to another call. After further calls, another word is obtained.

The function again writes zero directly at next base plus 17 and then at next base plus 1. A call receives four times the latest word. After further calls, another returned word becomes the **next fourth source**.

The next fourth argument is set to four times that source. The final explicit word store writes the final retained index shifted left by 31 at:

\[
16\times\text{next fourth source}+20.
\]

Under the 32-bit interpretation, the stored word is zero for an even final retained index and \(0x80000000\) for an odd one.

The function then reads a 32-bit word at:

\[
((\text{final payload}\mathbin{\&}0x3fffffff)\gg20)+20.
\]

This address calculation retains ten bits, not eight. Its starting address ranges from 20 through 1043.

A call receives the next fourth argument. Another call supplies the next third argument. The next seed is set to zero, and a subsequent call receives the word just read, shifted right by 22 and then left by 28.

Two further calls occur, with the next iteration’s link-like state established before the last of them. Execution repeats with the next base, next third argument, next fourth argument, and zero seed.

No call-preservation guarantee follows from the explicit zero stores. In particular, later calls may change the byte at next base plus 1 before the next iteration reads it.

## Side effects

Each fully reached iteration contains **27 explicit stores: 13 stores of 32 bits and 14 stores of 8 bits**. Callee effects are excluded.

| Phase | 32-bit stores | 8-bit stores |
|---|---:|---:|
| Entry and retained selector | 2 | 2 |
| Global snapshot and first wide result | 0 | 2 |
| Second-payload pair | 2 | 0 |
| Second wide result and clearing | 0 | 4 |
| Branch-derived updates | 2 | 2 |
| Remaining repeated-payload stores | 6 | 0 |
| Direct clearing and final store | 1 | 4 |
| **Total** | **13** | **14** |

The explicit reads comprise ten selector-byte reads, one global-word read, and one final computed-address word read.

All accesses occur in the stated order. Aliasing is not rejected: a byte write can affect a later word read, and an earlier word write can affect a later selector read if their addresses overlap. The global snapshot likewise reflects memory as it exists when sampled.

There is no visible rollback, synchronization primitive, allocation, release, or reference-count operation. Unknown callees may have such effects, but none is assigned to them by this contract.

## Dependencies

All unresolved indirect dependencies are designated **F-unknown**. This opaque designation covers unresolved targets; it does not assert that different call sites invoke the same function.

The dependency family includes:

- The initial target derived from link-like state.
- Targets derived from fixed site-specific anchors and offsets.
- Calls supplying displayed 32-bit and 64-bit results.
- Calls receiving one, two, three, or four explicit arguments.
- Calls with no displayed explicit arguments or with ignored displayed results.

No reliable callee contract is supplied. Return behavior, global preservation, memory preservation, ownership, exceptions, and argument interpretation are therefore unresolved.

The later implicit register operand is not an established output of any F-unknown dependency. A preceding call might affect it, but its producer and meaning remain undocumented.

Displayed arguments do not establish the complete calling convention. A call without displayed arguments may still consume implicit machine state.

## Acceptance examples

These are conditional static expectations, not executed tests. Each assumes execution reaches the relevant access and that the arithmetic interpretation applies.

1. **Byte truncation.** If the first payload is \(0x00000040\) and its selector is 5, the first selected-byte write stores zero at address 22. Four times the payload is 256.

2. **Retained selector.** If the second early selector read returns 7, the third-argument-derived word store starts at address 27. A subsequent callee changing the selector’s source byte does not change this retained destination.

3. **Fresh observations.** If two clearing reads at the retained selector base return 3 and 9, their writes target addresses 20 and 26, respectively.

4. **Global snapshot.** If the sampled global word is \(0x00400000\), the later snapshot-derived byte is 1. A callee changing the global after sampling does not cause a refresh.

5. **Different projection widths.** For \(0x3ff00000\), the byte projection is 255. If the final payload has that value, the final word-read starting address is 1043, not 275.

6. **Wraparound and store width.** If the word determining the next base is 4, the next base is zero. Each direct-clearing pair writes individual bytes at addresses 17 and 1; it does not clear a 32-bit word at either address.

7. **Unresolved register operand.** The branch-derived two-argument call has a zero first argument under 32-bit arithmetic. Its second argument cannot be accepted as zero, an entry value, or a preceding-call result without additional evidence.

8. **Final-index parity.** An odd final retained index produces a final stored word of \(0x80000000\); an even one produces zero.

9. **Interrupted execution.** If an F-unknown call does not return, later accesses are not reached. Earlier completed writes have no visible rollback.
