# F-bc89f750ed18

## Purpose

F-bc89f750ed18 retrieves an opaque 64-bit value through one of four address-bearing slots in a caller-provided memory region.

The operation has two explicit zero-result cases:

- The unsigned selector is outside the range 0 through 3.
- The selected slot contains a zero address representation.

Otherwise, the function returns the eight bytes beginning at offset 56 from the address stored in the selected slot. A stored value of zero is returned unchanged, so the result alone cannot distinguish that value from either zero-result case.

The established behavior is a conditional memory lookup. Interpreting the containing region as an object, the slots as owned references, or the returned bits as any particular application-level value is inferred intent, not an established contract.

The selector comparison is unsigned. In particular, a selector whose bit pattern is all ones represents 4,294,967,295 and takes the out-of-range path; it does not act as a negative index.

### Output

The result is 64 bits:

The supplied evidence does not establish whether callers interpret these result bits as an integer, floating-point value, address, handle, or compound representation. No sign extension, numerical conversion, masking, or reinterpretation is visible.

## Behavior

### Selector gating

The selector is checked before any memory access described by the supplied function.

For selector values 4 through 4,294,967,295, the function returns a 64-bit zero. It does not read a slot or a target field on this path. Consequently, this path does not require the supplied base to identify readable memory for the function’s explicit accesses.

Only selectors 0, 1, 2, and 3 reach address calculation and slot loading. Their selector-times-four contribution is respectively 0, 4, 8, or 12 bytes. This multiplication cannot overflow a 32-bit quantity within the admitted selector range.

### Slot access

For an admitted selector, the function reads the four-byte slot at the corresponding offset from the base. It reads only the selected slot; it does not scan, validate, or consult the other three slots.

The loaded slot value is tested against zero:

- A zero value terminates the lookup with a 64-bit zero result.
- A nonzero value enables the target-field read.

There is no explicit validation of a nonzero slot value. In particular, the function does not establish that it denotes an allocation, a complete object, an aligned address, or readable memory.

### Target access

For a nonzero selected slot, the function reads the eight-byte field at offset 56 from the address represented by that slot and returns those bits.

The established dependency order is:

1. Check the selector range.
2. Read the selected four-byte slot.
3. Check that loaded value against zero.
4. Read the selected eight-byte target field.
5. Return its contents.

The eight-byte read is one source-level access. The evidence does not establish whether it becomes one machine access, multiple narrower accesses, or an atomic access. It also does not establish the order of constituent machine reads if the implementation splits it.

The function does not visibly reread the slot after testing it. A later change to the slot therefore does not constitute a visible second selection step. Concurrent modification nevertheless requires platform-level rules not supplied here; this observation is not a thread-safety guarantee.
