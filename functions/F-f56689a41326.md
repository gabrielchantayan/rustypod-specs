# F-f56689a41326

## Purpose

F-f56689a41326 performs a finite sequence of indirect invocations, derives address-like values from their results, applies ordered memory mutations, and finishes with another unresolved indirect invocation.

**Established static evidence:** the supplied representation establishes explicit access widths, result extraction, arithmetic dependencies, repeated stores, and ordering among direct memory effects. It does not establish an application-level operation.

**Inferred intent:** repeated self-reference stores and recurring offsets suggest manipulation of cross-referenced state. This does not establish a container, text operation, initialization routine, serialization format, or device protocol.

This contract treats addresses as address-like values without assigning unsupported semantic types or ownership.

## Interface

### Entry and completion

No explicit parameters or return value are declared. Environmental inputs include:

- Incoming control state used to select the opening invocation target.
- An incoming 32-bit value used to construct the opening argument.
- Primary, paired, and secondary results from indirect dependencies.
- Existing contents of computed memory locations.
- A global associated with fixed address 0x05, whose value is converted to an unsigned 32-bit value.

The conversion of the global at 0x05 **does not establish its memory-access width or original signedness**. Its declaration is absent. In particular, the converted value is not established to lie between 0 and 255.

The represented return is reached only if the terminal invocation returns. The complete entry ABI and secondary-result convention remain **documented_only**.

## Behavior

### Invocation phase and arithmetic

The opening phase contains a finite ordered series of indirect invocations without represented conditional branches or loops. Targets are derived from incoming control state or embedded address-like operands, repeatedly using displacement 0x0ffe. This does not establish a function-pointer table.

Invocations have zero through four explicitly represented argument words. The opening argument is the incoming word shifted left by 22 positions. Later arguments include zeros, duplicated values, retained results, masks, left shifts, and logical right shifts. Results may be ignored, retained as words, split into paired-result halves, or supplemented by secondary result state.

An ignored result does not make an invocation removable. No dependency is established as pure or memory-preserving. The full invocation trace and unresolved dependency contracts are **documented_only** here.

Paired-result extraction must respect the original 64-bit width. Logical shifts of a complete paired result by 34, 36, or 44 yield its high word shifted logically right by two, four, or twelve respectively. The low word contributes to none of those results.

Under confirmed 32-bit bit-vector semantics, intermediate word shifts truncate at each step. Successive left shifts by 25 and seven therefore produce zero. Some represented expressions are signed; portable signed-overflow rules do not establish their machine behavior. Wrapping-based equivalences in this contract are conditional on confirmed machine semantics.

The direct-mutation phase uses these descriptive roles:

| Role | Derivation |
|---|---|
| Retained call-derived base | A retained result shifted left by 25 |
| Shifted base | Another result multiplied by 0x02000000 |
| Retained shifted word | A separate result shifted left by eight |
| Small quantity | A result shifted left by eight, masked to 15 low bits, then logically shifted right by six |
| Small base | Twice the small quantity |

Under 32-bit bit-vector semantics, the small quantity ranges from 0 through 508 in increments of four; the small base ranges from 0 through 1016 in increments of eight. These roles identify retained values, not objects or owned storage.

### Initial mutations and global-derived addressing

The final paired invocation result supplies a high-word base and a low-word-derived address scaled by 256. The initial effects include a word store of the retained call-derived base at high-word-base offset 0x14, followed by a byte store of the high word’s low byte at retained-call-derived-base offset 9. A word store of the shifted base at the scaled low-word address plus 0x54 precedes a second byte store at that same offset-9 destination, now containing the retained call-derived base’s low byte.

The shifted-base word at offset 0x14 is cleared before its offset-5 unsigned byte is sampled. The small-base word at offset 0x14 is then cleared, and the sampled byte is zero-extended into a word store at shifted-base offset 0x34.

The shifted-base word at offset 0x14 is subsequently captured. Another small-base offset-0x14 clear precedes the **first pair** of consecutive byte stores at small-base offset 0x15, both containing the captured word’s low byte. Aliasing or nonordinary memory semantics prevent an unconditional claim that this capture must be zero.

The global associated with fixed address 0x05 is then read and converted to unsigned 32-bit form. Call the retained conversion result the **converted-global base**. Its capture precedes the byte store of the small base’s low byte at fixed address 0x01. Later addressing uses the retained conversion result, not a newly read global and not an established unsigned-byte sample.

Converted-global-base offset 0x15 receives the small quantity’s low byte. Shifted-base offset 0x11 receives the retained shifted word’s low byte. The earlier shifted-base capture selects an offset-0x54 word destination for the retained shifted word; shifted-base offset 0x11 is then cleared.

The word at converted-global-base offset 0x54 is captured before replacement with the earlier shifted-base capture. This captured word is the **retained reference value**. Small-base offset 0x34 receives the small quantity. Subsequent changes to the capture’s original location do not replace the retained reference value.

### Cross-referenced updates

A word captured at shifted-base offset 0x74 selects another region. Its offset 0x54 receives a scaled call-derived value and later the retained shifted word. Two self-reference word stores at retained-reference offset 0x24 are interleaved with byte stores of that reference’s low byte at the selected region’s offset 9.

The small-base offset-0x74 word occurs separately as an address selector and as a stored value. Those occurrences are not established as a single snapshot.

Small-base offset 0x14 first receives a scaled call-derived value, then the retained reference value twice. A fixed word store at 0x54, containing twice the retained reference value, occurs between the first and second kinds of update.

Four times the retained reference value is the **quadrupled-reference base**. The **second pair** of consecutive byte stores at small-base offset 0x15 both contain this quadrupled value’s low byte.

**Immediately after that pair, fixed address 0x15 receives a byte store containing the small base’s low byte.** This precedes the word store of the retained shifted word at quadrupled-reference-base offset 0x54. It is not a third computed offset-0x15 store.

Further effects publish quadrupled and octupled retained-reference values through offsets 0x34, 0x44, and 0x54. They also include self-reference word stores and byte updates at offsets 9, 0x0d, and 0x15.

An unsigned byte sampled at quadrupled-reference-base offset 5 selects an offset-0x74 word read. Separately, a word captured at quadrupled-reference-base offset 4 selects a region whose offset-5 byte is read twice, with mutations between the reads. The samples must not be merged. The later sample selects another offset-0x74 word read, producing the **selected reference value**.

Twice the selected reference value is the **doubled-reference base**. Four times it is the **fourfold-selected base**. No reciprocal-link or container invariant is established by these updates.

### Constants and publication

The selected reference value determines three distinct constant stores:

- Byte 0x3a through four times that value.
- Halfword 0x003a through eight times that value.
- Word 0x0000003a at fourfold-selected-base offset 0x20.

Subtracting 0x96 from the quadrupled-reference base produces the **adjusted value**. Four times that value becomes the **publication base**, subject to the unresolved signed-arithmetic semantics.

Publication-base offset 0x20 receives four word stores in order: 0x20, 0x2f, the zero-extended unsigned byte sampled from publication-base offset 4, and 0x20 again. The sample occurs after the 0x2f store and before the store using it.

The publication address is captured from its fixed stored-address slot before fixed address 0x60 receives word 0x20. This captured address is the **publication target**. Later target accesses do not re-read the slot.

A finite repeated-store region follows. Each publication group contains, in order:

- An offset-0x54 word store of the fourfold-selected base through a scaled retained address.
- A byte store of the publication base’s retained low byte at publication-target offset 0x19.
- A byte store of the publication target’s retained low byte at publication-base offset 0x11.
- A word store at publication-target offset 0x34.

The first group uses eight times the retained reference value for the scaled address and offset-0x34 value. Subsequent groups use eight times the adjusted value. These are repeated represented events, not an established loop or atomic publication. Exact multiplicity is **documented_only** in this contract.

### Captures around fixed address 0x3a

Publication-target offset 0x44 receives the doubled-reference base. Next, publication-base offset 9 receives its **first copy sampled from fixed 0x67**. After that copy, **doubled-reference-base offset 9 receives the publication base’s retained low byte**. Only then does publication-base offset 0x44 receive the captured 0xa9 word.

If the selected-region address is 0x11223344, publication-base offset 9 receives byte 0x44 after the doubled-reference-base offset-0x11 update and before the publication-base offset-0x44 replacement. Keeping only the preceding fixed-0x67 copies is unacceptable.

### Last byte store and retained captures

If the terminal selected base ends in 0x78, doubled-reference-base offset 9 receives byte 0x78 after the later doubled-reference-base offset-0x64 capture and before the last two direct word stores. Even if this byte store overlaps the capture’s original memory location, those stores use the retained captured value, not a fresh read.

### Other ordering and width boundaries

If fixed address 0x60 overlaps the publication-address slot, later publication accesses still use the address captured before that store.

If fixed address 0x3a overlaps the later doubled-reference-base offset-0x14 capture, that capture includes the byte mutation under ordinary memory semantics. Earlier captures remain unchanged.

Byte, halfword, and word stores of 0x3a require different access widths. Three byte stores are not equivalent. For a paired result whose high word is 0x80000000, logical extraction after a 34-bit right shift yields 0x20000000 independently of the low word.
