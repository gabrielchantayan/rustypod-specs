# F-40f2211cf7c8

## Purpose

F-40f2211cf7c8 invokes a context-selected callback, conditionally invokes F-d8528f8db63b, and then selects one of two specialized operations or a default result. It returns a 32-bit result.

Two preliminary results control continuation:

- A nonzero callback result is returned immediately.
- After a zero callback result, a nonzero F-d8528f8db63b result is returned immediately.
- Only when both results are zero does the function perform dispatch selection and subsequently write the byte value 1 at context offset `0x260`.

That byte write records that execution reached the end of dispatch selection. It does not establish that a specialized operation was selected or succeeded: the write also follows a nonzero specialized result and the unmatched-selector result of 3.

The callback’s second argument comes from a global-data read performed during this invocation. It is not a second invocation parameter and is not specified as a value captured before entry.

The operational meanings of the context, global input, saved context value, selector, and marker are not established by the supplied evidence.

### Result

The function returns a 32-bit result obtained from one of five sources:

1. A nonzero callback result.
2. A nonzero F-d8528f8db63b result.
3. The result of F-654c616dab8e.
4. The result of F-bd252fa22770.
5. The literal value 3 for an unmatched selector.

Only equality or inequality with zero controls continuation through the first two calls. No positive-only requirement is present. Nonzero 32-bit patterns with the high bit set also take the immediate-return paths.

The function contains no established null, bounds, alignment, ownership, or lifetime checks. No recovery result is specified for invalid memory, invalid callback targets, or abnormal callee termination.

## Behavior

### Initial capture and callback inputs

The function first reads the 32-bit value at context offset `0x68`. This contract calls that value the **saved value**.

Before the callback is invoked, the function also:

- Evaluates the global-data input G-01.
- Obtains the callback target from context offset `0x1F8`.

Both occur after the saved-value capture and before callback entry. Their relative evaluation order is unspecified by the supplied evidence. No guarantee is made that the global input is read before the callback target, or vice versa.

The callback receives four arguments in this logical order:

1. The original context address.
2. The value obtained by evaluating G-01 for this callback invocation.
3. The saved 32-bit value.
4. Zero.

Logical argument positions are established. Machine-level argument placement, the width of the global-derived argument, and the width used to pass the literal zero are not independently established.

A later callback modification to G-01 does not cause this function to reevaluate it for the same callback call. This statement concerns argument evaluation only; it does not imply that memory potentially designated by the argument is copied or immutable.

### Callback early return

If the callback returns a nonzero 32-bit result, the function immediately returns that result.

On this path, the function does not:

- Read the selector at offset `0x1D0`.
- Invoke F-d8528f8db63b.
- Invoke either specialized dependency.
- Perform its byte store at offset `0x260`.

The initial saved-value read, global-data evaluation, and callback-target load have already occurred. The callback may have changed context, global state, or other memory; immediate return does not imply an unchanged state.

### Selector capture and preliminary dependency

If the callback returns zero, the function reads the 32-bit selector at context offset `0x1D0`.

It then invokes F-d8528f8db63b with:

1. The saved 32-bit value.
2. The constant `0x20`, numerically 32.

The selector capture precedes this dependency call. Consequently:

- Callback changes to the selector can affect this invocation’s dispatch.
- F-d8528f8db63b changes to the selector do not affect this invocation’s dispatch.
- The selector is read even when F-d8528f8db63b subsequently returns nonzero.

If F-d8528f8db63b returns nonzero, that result is returned immediately. No specialized dependency is invoked and no marker byte is written by this function.

### Dispatch selection

When F-d8528f8db63b returns zero, dispatch uses the captured selector:

| Captured 32-bit selector | Action | Selected result |
|---|---|---|
| `0x00020000` | Invoke F-654c616dab8e with the original context address and saved value | Dependency result |
| `0x00028000` | Invoke F-bd252fa22770 with the original context address and saved value | Dependency result |
| Any other value | Invoke neither specialized dependency | 3 |

The comparisons use exact full-width equality. They are not masks, subset tests, or range checks. Additional set bits prevent a match unless the entire value equals one of the two listed constants.

No specialized dependency is retried. A nonzero result from one specialized dependency does not cause invocation of the other.

The saved value is not reloaded from context offset `0x68`. Callback or dependency changes to that field do not replace the captured value used by this invocation.

### Marker store and final return

After dispatch selection, and after the selected specialized dependency returns normally if one was invoked, the function writes the 8-bit value 1 at the original context address plus `0x260`.

It then returns the selected 32-bit result unchanged.

The marker store occurs for:

- A specialized result of zero.
- A specialized nonzero result.
- An unmatched selector producing result 3.

No marker clear occurs on entry or on either preliminary early-return path. A marker already containing 1 cannot, by itself, establish that the current invocation reached dispatch selection.

The direct store is one byte wide. No direct store to adjacent bytes is established.

### Arithmetic and execution boundaries

The visible address calculations use fixed offsets from the original context address. No length-dependent calculation, iteration, multiplication, or checked arithmetic is present.

The evidence does not establish address-overflow behavior. The 32-bit representation must not be converted into a guarantee of safe modular addressing or a particular failure code.

If a callee does not return normally, subsequent selector reads, dependency calls, marker stores, or returns are not established to occur.

## Acceptance examples

These examples are conditional consequences of static evidence, not runtime observations. Unless stated otherwise, accesses are valid, callees return normally, and callees have no unmentioned effects.

### Global input and callback rejection

Suppose the initial saved value is A, G-01 evaluates to Q, and the callback returns 7.

- A is captured before G-01 is evaluated.
- The callback receives the original context, Q, A, and zero.
- Loading the callback target may occur before or after evaluating G-01.
- The function returns 7.
- No selector read, named dependency call, or marker store follows.

Q is not an additional invocation parameter.

### Global input across invocations

Suppose G-01 evaluates to Q on one invocation and R on a later invocation.

Each invocation supplies the value obtained by its own G-01 evaluation as the callback’s second argument. The function does not establish a persistent cached global value shared between invocations.

This example does not define the behavior of concurrent modification during a global read.

### Preliminary dependency rejects continuation

Suppose the callback returns zero and F-d8528f8db63b returns 9.

- The selector is captured after callback return and before F-d8528f8db63b is invoked.
- F-d8528f8db63b receives the saved value and 32.
- The function returns 9.
- Neither specialized dependency is invoked.
- This function performs no marker store.

### Specialized paths preserve results

Suppose both preliminary results are zero and the captured selector is `0x00020000`.

F-654c616dab8e is invoked once with the original context and saved value. F-bd252fa22770 is not invoked. Whether the selected dependency returns zero or 12, the function subsequently writes marker byte 1 and returns that same result.

For captured selector `0x00028000`, the corresponding behavior uses F-bd252fa22770 instead.

### Unmatched selector

Suppose both preliminary results are zero and the captured selector is `0x00020001`.

Neither specialized dependency is invoked. The function writes marker byte 1 and returns 3. The additional low bit prevents equality with `0x00020000`.

### Capture timing under callee mutations

Suppose the initial saved value is A. The callback changes the field at offset `0x68` to B, changes the selector to `0x00028000`, changes G-01, and returns zero. F-d8528f8db63b then changes the selector to `0x00020000` and returns zero.

- F-d8528f8db63b receives A.

- The specialized dependency receives A, not B.

### Existing marker and early return
