# F-9c21e6eb3c40

## Purpose

F-9c21e6eb3c40 conditionally replaces one 32-bit word in an object selected through a global-derived lookup structure. The replacement word packs three single-bit flags and three bounded integer fields from caller-provided memory.

For an unsigned element index below 18, the function computes and stores the packed word, then invokes an unresolved indirect dependency with one visible argument equal to zero. For an element index of 18 or greater, it returns without performing the lookup, reading the input bytes, writing the destination, or making that invocation.

The field names and application meaning are not established. Describing the operation as a configuration update is inferred intent, not an additional behavioral guarantee.

## Interface

### Inputs

The visible interface has three parameters:

| Parameter | Width and interpretation | Role |
|---|---|---|
| Selector | Signed 16-bit integer | Selects an entry in a global-derived structure using a stride of 396 bytes. |
| Element index | Unsigned 32-bit integer | Selects one of 18 destination words when its value is below 18. |
| Input address | Pointer to bytes | Supplies the fields used to construct the replacement word. |

The visible representation uses 32-bit address-bearing loads and 32-bit data words. The precise ABI, pointer provenance rules, alignment requirements, and target byte order are not independently established by the supplied material.

### Result

There is no explicit return value.

For an in-range element index, the function reaches an unresolved indirect invocation after the destination store. An ordinary return to the caller is visible after that invocation, but occurs only if control returns from the dependency. Its termination behavior is unknown.

### Global-derived lookup and destination layout

Let **B** denote the global-derived base used for selection. The function obtains an object address through a 32-bit address-bearing load at:

**B + selector × 396**

Within the selected object, the destination word begins at:

**object address + 2360 + element index × 4**

The first eligible destination word is therefore at object offset 2360, and the eighteenth is at offset 2428. Each write is four bytes wide.

Only the address-bearing word at the selected 396-byte stride is visibly used. No layout or meaning is established for the remaining bytes in that stride, or for other portions of the selected object.

### Input layout

For an in-range element index, the visible operation consumes these fields:

| Byte offset from input address | Access width | Effective contribution |
|---|---:|---|
| 0 | 8 bits | Least significant bit becomes destination bit 31. |
| 1 | 8 bits | Least significant bit becomes destination bit 30. |
| 2 | 8 bits | Least significant bit becomes destination bit 29. |
| 4 | 32 bits | Least significant 11 bits become destination bits 18–28. |
| 8 | 32 bits | Least significant 9 bits become destination bits 0–8. |

Input offset 3 has no explicit read. The three 32-bit fields are interpreted using the target’s native byte order; the supplied material does not establish a portable serialized byte order.

The highest explicitly consumed input byte is at offset 15. A readable 16-byte input region is sufficient for the visible input reads, subject to the platform’s access requirements.

## Behavior

### Index gate

The first established decision compares the element index, as an unsigned 32-bit value, against 18.

When the index is 18 or greater, the function returns immediately. In particular, an index with its high bit set is out of range; it is not interpreted as a negative index.

This branch does not require a valid selector, lookup entry, selected object, or input address for the visible body, because none of those are dereferenced there.

### Selection for an in-range index

For an index from 0 through 17, inclusive, the selector determines the address-bearing entry using the 396-byte stride.

The selector is signed. There is no visible rejection of negative values and no visible validation against an upper selector bound. A negative selector consequently selects an address before **B**, rather than becoming a large unsigned selector by an explicit conversion.

The selector-times-stride product fits within signed 32-bit arithmetic throughout the signed 16-bit selector range. Whether the resulting address is valid is a separate memory-layout precondition. The function does not visibly check that condition.

After obtaining the object address, the destination offset is 2360 plus four times the element index. Because the index has already been restricted to 0–17, this index-dependent offset calculation is bounded. The visible operation does not check whether adding that offset to the object address produces a valid writable address.

### Packed value

Let:

- **f₀**, **f₁**, and **f₂** be the low bits of the bytes at input offsets 0, 1, and 2.
- **a** be the low 11 bits of the native 32-bit word at input offset 4.
- **b** be the low 9 bits of the native 32-bit word at input offset 8.
- **c** be the low 9 bits of the native 32-bit word at input offset 12.

The stored unsigned 32-bit value is:

**f₀ × 2³¹ + f₁ × 2³⁰ + f₂ × 2²⁹ + a × 2¹⁸ + c × 2⁹ + b**

These fields occupy disjoint bit ranges and collectively define all 32 destination bits. The write replaces the complete destination word; it does not preserve any bits from its previous value.

Although the first byte is not explicitly masked before its left shift in the supplied expression, the operation is 32-bit unsigned arithmetic. Only that byte’s least significant bit survives the shift into bit 31. Thus, all three flag bytes behave according to parity, not according to whether they are nonzero.

The numeric fields are truncated by masking, not range-checked or saturated:

- The field at offset 4 contributes a value from 0 through 2047.
- The fields at offsets 8 and 12 each contribute a value from 0 through 511.

Bits above those widths have no effect on the visible packed value.

### Store and indirect invocation

The packed value is stored at the computed destination before the unresolved indirect dependency is invoked.

The visible invocation supplies one argument with numeric value zero. No destination address, input address, selector, or element index is explicitly passed in the supplied call expression. This does not establish that the dependency cannot access those values through globals, machine state, or other mechanisms.

If the dependency returns normally, the visible function then returns without another explicit memory operation.

## Side effects

### Established visible effects

For an in-range element index, the body explicitly performs:

- A lookup read used to obtain the selected object address.
- Three byte reads from the input.
- Three 32-bit reads from the input.
- One 32-bit destination write.
- One unresolved indirect invocation after the write.

The global-derived base must also be obtained as required by its actual storage representation. That representation is not fully established.

For an out-of-range element index, none of the above effects is visible.

### Ordering limits

The supplied expression does not establish a total order among the individual input reads or between those reads and the lookup read. A contract must not require a particular ordering among them.

The destination store uses the computed address and packed value, so the reads needed for that store precede its completion. The indirect invocation follows the store.

There is no visible synchronization, memory barrier, transactional boundary, or atomicity guarantee. A single 32-bit assignment does not, by itself, establish indivisibility or cross-thread visibility on an otherwise unspecified platform.

### Ownership and aliasing

The unresolved dependency’s ownership behavior is unknown. It must not be assumed to preserve globals, retain no pointers, or release no memory.

The store is based on the values read to construct it; there is no subsequent explicit input read in this body. More general guarantees for aliasing, concurrent mutation, volatile memory, or memory-mapped devices are not established.

## Acceptance examples

These are conditional static acceptance examples, not executed tests. Unless stated otherwise, assume valid lookup storage, valid readable input fields, a writable destination, compatible alignment, no concurrent mutation, and an indirect target that returns normally. Destination expectations refer to the store before any changes the indirect target might make.

### Index boundary

- With element index 17, the destination store is at selected-object offset 2428, followed by the indirect invocation with zero.
- With element index 18, there is no lookup or input dereference, no destination write, and no indirect invocation.
- With element index `0xFFFFFFFF`, the same out-of-range behavior applies.

### All fields clear or full

- If all six contributing fields have zero in their effective bit positions, the stored value is `0x00000000`.
- If all three flag bytes are odd, the word at offset 4 has its low 11 bits set, and the words at offsets 8 and 12 have their low 9 bits set, the stored value is `0xFFFFFFFF`.

### Flag-byte parity

With all numeric fields zero:

- Flag bytes 1, 1, and 1 produce `0xE0000000`.
- Flag bytes 2, 2, and 2 produce `0x00000000`, despite all being nonzero.
- Flag bytes 255, 0, and 0 produce `0x80000000`.

### Numeric placement and truncation

With all flags zero and unspecified numeric fields zero:

- A native word value of 1 at offset 4 produces `0x00040000`.
- A native word value of 1 at offset 8 produces `0x00000001`.
- A native word value of 1 at offset 12 produces `0x00000200`.
- A native word value of 2048 at offset 4 contributes zero.
- A native word value of 512 at either offset 8 or offset 12 contributes zero.

Changing input byte 3 alone does not change the visible packing result.

### Replacement and selector behavior

- If the previous destination contains `0xFFFFFFFF` and all effective input fields are zero, the store replaces it with zero.
- Selector −1 addresses the lookup location **B − 396**. This is an address-selection consequence, not a guarantee that the location is valid.
- If the indirect dependency later overwrites the destination, the final post-return value need not equal the packed value. The established guarantee concerns the preceding store.
