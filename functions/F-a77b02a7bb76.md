# F-a77b02a7bb76

## Purpose

F-a77b02a7bb76 selects one of three highlighted-content resources, resolves that selection through a helper, and supplies the resulting 32-bit value to an operation obtained from the receiver’s dispatch table. It also writes a fixed one-byte value into the receiver and invokes a final helper on an addressable local slot.

The selection depends on a global configuration field and, for two of the three paths, a query performed against a value returned by an initial dependency.

This is a static behavioral contract. The meanings “empty composers,” “no art music,” and “media content” are inferred from resource labels, not established from resource contents or runtime behavior. The receiver’s concrete type, the resource representation, and the dispatched operation’s purpose are unknown.

### Receiver layout

The visible accesses establish these layout requirements:

- At receiver byte offset **0**, a 32-bit value is read as the address of a dispatch table.
- At receiver byte offset **176** (`0xB0`), exactly one byte is written with the value **14** (`0x0E`).
- At dispatch-table byte offset **284** (`0x11C`), a callable entry is obtained and invoked with the receiver and a 32-bit resolved value.

The receiver offset of 176 bytes follows from advancing 44 elements of a 4-byte integer representation. It is not a 44-byte offset.

The field at offset 176 is not read or combined with its previous value. Neighboring bytes are not explicitly written by this routine.

The routine contains no explicit null, bounds, alignment, dispatch-entry, or resource-validity checks. Successful execution therefore requires the accessed storage and call targets to be valid for their respective operations. Exact platform fault behavior is outside the visible evidence.

## Behavior

The following order is established by the supplied body. Dependency-internal reads, writes, and calls are not available.

1. **Create an addressable copy of the fourth argument.**  
   A local 32-bit slot is initialized with the fourth argument’s value. Subsequent helper calls receive the address of this slot, not the original caller argument’s address.

2. **Obtain an initial value.**  
   Invoke **F-753f887b468d** without explicit arguments. Retain its 32-bit result for possible use by the query and preparation dependencies.

3. **Read the global base address.**  
   Read the address held at the referenced global location. This happens after F-753f887b468d returns.

4. **Write the receiver field.**  
   Store the byte value 14 at receiver offset 176.

5. **Read the configuration field.**  
   Read the 32-bit field at offset 1028 from the previously obtained global base address. The receiver byte write precedes this field read.

6. **Select a resource through the decision process below.**

7. **Resolve the selected resource.**  
   Invoke **F-9b9c1c7483f4**, passing:
   - the address of the local 32-bit slot; and
   - the selected resource address.

   Retain the dependency’s 32-bit return value. The visible body does not establish whether this call changes the slot.

8. **Dispatch the resolved value.**  
   Read the receiver’s dispatch-table address, obtain the entry at table offset 284, and invoke that entry with:
   - the receiver; and
   - the value returned by F-9b9c1c7483f4.

   The receiver’s dispatch information is obtained after resource resolution. It is not visibly cached before that dependency call.

9. **Invoke the final slot helper.**  
   After the dispatched operation returns, invoke **F-8a5aadac202f** with the address of the same local slot.

10. **Return 1.**

There is no visible post-dispatch check, post-helper check, or restoration of the receiver byte.

### Resource-selection decision

For this contract, the three selected resource addresses are designated:

- **Resource A:** the resource whose label suggests an empty-composers highlighted state.
- **Resource B:** the resource whose label suggests a no-art-music highlighted state.
- **Resource C:** the resource whose label suggests a media-content highlighted state.

These are descriptive designations, not claims about the resources’ exact text, encoding, length, or rendered appearance.

Selection proceeds as follows:

| Condition | Additional calls before resolution | Selection |
|---|---|---|
| Configuration field equals zero | None | Resource A |
| Configuration field is nonzero and the query returns zero | F-6904540d62b2 | Resource B |
| Configuration field is nonzero and the query returns nonzero | F-6904540d62b2, then F-5eac81954d4b | Resource C |

When invoked, **F-6904540d62b2** receives the retained result of F-753f887b468d and a second argument of zero.

Both branch tests distinguish only zero from nonzero. There is no positive-value requirement. A value represented as a negative signed 32-bit integer follows the nonzero path.

### Ordering and aliasing consequences

The initial dependency runs before the global base address is read. Any changes it makes to the relevant global state can therefore affect the subsequent access.

The global base address is obtained before the receiver byte write, but the configuration field is read afterward. If the written receiver byte aliases storage contributing to that field, selection uses the field value after the byte write. The contract does not assume disjoint storage.

There is no visible second read of the configuration field after the query or preparation call. Changes those dependencies make to that field do not trigger a new selection decision in this body.

Conversely, the receiver’s dispatch table is read after F-9b9c1c7483f4 returns. If that dependency changes dispatch information visible through the receiver, the later dispatch uses the information then present.
