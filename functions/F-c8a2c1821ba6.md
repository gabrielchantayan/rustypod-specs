### Integer interpretation and masks

The principal value path is 32 bits wide. Under 32-bit machine-word semantics, scaling and left shifts retain the low 32 bits; successive shifts do not widen intermediate values.

For example, shifting a 32-bit word left by eight and then eighteen preserves information only from its original low six bits. A further eight-position left shift produces zero under that interpretation.

Right shifts of explicitly unsigned operands are logical. Extracting an unsigned represented 64-bit result starting at bit 34, 36, or 44 corresponds to logically shifting its high 32-bit word right by two, four, or twelve.

Masks have several distinct roles and sizes:

- Larger low-bit masks include, as examples, 11-, 15-, 20-, 22-, and 24-bit masks. These examples are not an exhaustive width range.
- A **one-bit mask** selects the least significant bit of a retained unsigned quantity for later call arguments. Shifting that selection left by sixteen produces either 0 or 0x00010000.
- An **eight-bit mask**, 0xFF, selects the low eight bits of a computed base for a late variable signed-right-shift count.

Mask width is not necessarily the number of information-bearing bits remaining after subsequent shifts. Left shifts can discard selected bits, and right shifts can further reduce the value range.

The eight-bit count selection establishes a value between 0 and 255 before considering constraints inherited from base construction. It does **not** establish reduction modulo 32 or guarantee that the selected count is valid for a 32-bit shift.

Signed shifts, multiplication, subtraction, and a late signed right shift also occur. Portable signed-overflow behavior is not established. Wraparound examples are conditional on machine-word semantics, not universal promises about signed arithmetic.

## Acceptance examples

These are conditional static examples, not executed tests.

### Initial arguments

For fourth input 1, the initial call’s second explicit argument is 128. For fourth input zero, it is zero. The first input is forwarded unchanged. Neither case determines dependency results.

### Index boundary

Under 32-bit word semantics, return word 0x7F produces index 508 and doubled index 1016. Return word 0x80 produces zero. This transformation is not monotonic.

### One-bit call-argument selection

If the retained quantity used by a later one-bit selection is 2, the resulting argument after the sixteen-position shift is zero. If it is 3, the argument is 0x00010000. Bits above the least significant bit do not contribute to that selected argument.

This requirement concerns the selected argument, not the callee’s behavior or the other arguments.

### Eight-bit shift-count selection

If the computed base is 0x108, masking its low eight bits selects count 8. If it is 0x128, the selected count is 40, not 8.

The second case does not establish the resulting shifted value: handling a 40-position shift of a signed 32-bit operand remains unresolved. A model must not silently replace the eight-bit selection with a five-bit count mask.

### Explicit byte versus undeclared symbol

An explicit unsigned-byte read yielding 0xFF becomes unsigned 32-bit value 255.

That rule cannot be imposed on the 0x05 symbol read without its declaration. If its source were signed eight-bit value −1, conversion to unsigned 32 bits would yield 0xFFFFFFFF. If its source were unsigned eight-bit value 255, the result would be 255. Neither source type is established.

### Ordered overwrites and widths

A represented access trace reaching the four offset-0x20 stores preserves their order and the byte read between the second and third stores. With stable ordinary memory and no relevant interference, the last stored word is 0x20. That final value alone does not establish trace equivalence.

Replacing the explicit 16-bit store of 0x65 with an eight-bit store changes the access contract. Conversely, an eight-bit conversion before assignment to the 0x67 symbol does not establish an eight-bit symbol store.

### Aliasing and termination

If no intervening effect changes the initial base’s offset-0x14 storage after its zero store, a later ordinary-memory word read obtains zero. Aliasing or nonordinary memory can invalidate that conclusion.

If a dependency does not return, subsequent operations are not required to occur. No recovery result is established.
