# F-22e1b513fb3b

## Purpose

F-22e1b513fb3b performs two directional searches through a linked structure, constructs a four-word traversal descriptor from the first search result, and repeatedly invokes a traversal dependency until a separate dependency returns exactly one. It counts the traversal invocations and then calls a final dependency with the object and two endpoint snapshots.

The structure resembles a binary tree, and the two searches resemble boundary searches using opposite argument orders. Those are inferred interpretations, not established API semantics. In particular, the search results are sometimes the selected **child address**, including zero, rather than the address of the node being examined. A behavioral replacement must retain that distinction.

The supplied evidence does not establish that the operation erases elements, returns a match count, or identifies a conventional ordered range. Such interpretations require contracts for the dependencies.

## Interface

### Inputs

The function accepts two machine-word arguments:

- **Search operand:** An opaque 32-bit value. It is forwarded unchanged to the comparison dependency. The evidence does not establish whether it is an address, an encoded scalar, or another kind of handle.

There are no explicit checks for a null object, invalid addresses, malformed links, or inaccessible memory.

### Return value

The function returns a 32-bit integer count. Starting at zero, the count increases once for every loop iteration in which F-3b480a32387a returns a value other than exactly one. Each such increment occurs before an invocation of F-ce2e2e919fce.

For a normally returning execution without count overflow, the result is the number of F-ce2e2e919fce invocations made by this function. It is not independently established as a node count, a match count, or a modification count.

## Behavior

### 1. First directional search

Initialization uses two distinct reads of the object’s field at offset 0x10:

1. The first read supplies the header address from which the initial node address is read at offset 0x04.
2. A subsequent read supplies the initial first-search result.

The function therefore does not demonstrably use a single cached header value for both purposes. In ordinary stable memory they coincide; no synchronization or stability guarantee is shown.

For every nonzero current node, the function calls F-bcefa5957e76 with these arguments, in this order:

1. Object address plus 0x19.
2. Current node address plus 0x10.
3. The search operand.

The return value is interpreted only as zero or nonzero.

- **Zero:** The link at current node offset 0x08 is read. Its value becomes both the next current node and the first-search result.
- **Nonzero:** The link at current node offset 0x0C is read. Its value becomes the next current node, while the first-search result remains unchanged.

The selected link is read **after** the dependency returns. If that dependency changes the current node’s selected link, the subsequently read value determines traversal.

The search ends when the current node becomes zero. A final zero-result comparison can therefore set the first-search result to zero. If no comparison returns zero, the result remains the header value captured at initialization.

### 2. Second directional search

The function rereads the object’s header field rather than reusing the first search’s header.

As before, initialization first reads the initial node through one header-field read, then separately reads the header field to initialize the second-search result.

For every nonzero current node, F-bcefa5957e76 receives:

1. Object address plus 0x19.
2. The search operand.
3. Current node address plus 0x10.

Thus, the second and third arguments are reversed relative to the first search. The dependency is not assumed to be symmetric.

The branch behavior is:

- **Zero:** The link at current node offset 0x0C becomes the next current node. The second-search result remains unchanged.
- **Nonzero:** The link at current node offset 0x08 becomes both the next current node and the second-search result.

Again, the selected link is read after the dependency returns.

The second-search result can consequently be zero. If no comparison returns nonzero, it remains the header value captured for this search.

Neither search includes cycle detection, a depth limit, or structural validation.

### 3. Descriptor initialization

After both searches finish, the four 32-bit descriptor words have the following values in increasing address order:

| Word | Initial value |
|---:|---|
| 0 | First-search result |
| 1 | Zero |
| 2 | Zero |
| 3 | First-search result |

The separate endpoint word is initialized to the second-search result.

These are the values presented to the first traversal-check call. The evidence does not establish what the descriptor’s words mean to its consumers.

The count is initialized to zero.

### 4. Traversal-check loop

The function calls F-3b480a32387a with:

1. The address of the four-word descriptor.
2. The address of the separate endpoint word.

The loop stops only if the returned 32-bit value is exactly one. Zero, negative values, and positive values other than one all continue the loop.

For each continuing iteration:

1. The count is incremented.
2. F-ce2e2e919fce is called with the descriptor address.
3. F-3b480a32387a is called again with the same descriptor and endpoint-word addresses.

Neither temporary is reinitialized between these calls. Writes made through the supplied addresses can therefore affect subsequent iterations and the final snapshots.

F-ce2e2e919fce is not given the endpoint-word address directly. This does not establish that the endpoint word or other state is globally inaccessible to it.

There is no independent termination condition. If F-3b480a32387a never returns one, execution does not reach the final dependency through the displayed control flow.

### 5. Final snapshots and final dependency

After the terminating traversal-check call, the function performs these reads in order:

1. It copies the current separate endpoint word into one snapshot word.
2. It copies the current descriptor word 3 into another snapshot word.

These values are taken **after** the terminating call. They need not equal the original search results if dependencies have modified the temporary state.

F-4a26e0b6e8a2 is then called with four arguments, in this order:

1. Address of the four-byte output area.
2. Original object address.
3. Address of the snapshot copied from descriptor word 3.
4. Address of the snapshot copied from the separate endpoint word.

The output area is not initialized by this function before that call. Its contents after the call are not read by this function. Any return value from F-4a26e0b6e8a2 is also unused.

The function then returns the accumulated count.

## Side effects

### Direct memory access

Before passing temporary storage to dependencies, the function directly reads object, header, and node fields as described above. It makes no explicit direct write to the object, header, or nodes in the supplied representation.

Its direct writes initialize and update temporary descriptor words, endpoint storage, snapshots, and the count.

This does **not** establish that the operation is externally read-only. Dependencies receive addresses into the object and nodes, as well as the original object address during the final call.

### Dependency-visible ordering

The established call ordering is:

- All first-search comparisons precede all second-search comparisons.
- Both searches finish before the first traversal check.
- Every nonterminating traversal check is followed by a count increment and one traversal call.
- The terminating traversal check is followed by snapshot reads and the final dependency.
- The final dependency runs even when the count is zero, provided preceding calls return normally.

There is no rollback path shown for changes made by dependencies.

### Ownership and lifetime

The supplied body contains no explicit allocation or release operation. Allocation, release, reference-count changes, or ownership transfer inside dependencies remain unknown.

No dependency may be assumed to preserve global state, linked nodes, comparison context, or the object. Conversely, the supplied body alone does not prove that any dependency modifies or releases them.

## Acceptance examples

These examples are conditional behavioral checks, not reports of execution.

### Empty initial structure with stable header

Assume:

- Both searches observe the same nonzero header address H.
- Its initial-node field is zero for both searches.
- F-3b480a32387a returns one immediately without changing the supplied storage.
- The final dependency returns normally.

Then:

- No comparison calls occur.
- The first descriptor presented is `[H, 0, 0, H]`.
- The endpoint word initially contains H.
- F-ce2e2e919fce is never called.
- The final dependency receives snapshot values H and H, in descriptor-derived then endpoint-derived order.
- The returned count is zero.

### One node, both comparisons return zero

Assume a stable header H points to node N, both links of N are zero, and both comparison calls return zero.

The first comparison receives the node-associated address before the search operand. It follows offset 0x08 and sets the first-search result to zero.

The second comparison receives the search operand before the node-associated address. It follows offset 0x0C without changing the second-search result, which remains H.

The initial descriptor is `[0, 0, 0, 0]`, and the separate endpoint word contains H. Neither search result is automatically replaced with N.

### One node, both comparisons return nonzero

Under the same structural assumptions, let both comparison results instead be nonzero.

The first search follows offset 0x0C and leaves its result as H. The second follows offset 0x08 and changes its result to zero.

The initial descriptor is `[H, 0, 0, H]`, and the separate endpoint word contains zero.

### Only exactly one terminates

Assume successive traversal-check results are zero, negative one, two, and one, with normal dependency returns.

F-ce2e2e919fce is called three times, and the returned count is three, provided no count overflow occurs. None of the first three results is interpreted as an error by this caller.

### A terminating check changes endpoint state

Assume the first traversal check changes descriptor word 3 to A, changes the separate endpoint word to B, and returns one.

No traversal call occurs. The final dependency receives snapshots containing A and B, in that order, and the returned count is zero. The initial search results do not override those changes.
