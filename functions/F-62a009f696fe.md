# F-62a009f696fe

## Purpose

F-62a009f696fe invokes an initial operation, classifies the context’s current object reference, and selects one of three behaviors:

- **Nonzero classification:** inspect an object field; either return immediately or invoke an indirect operation, clear the context’s object reference, and pass an adjacent context region to another dependency.
- **Zero classification and nonzero initial result:** report the initial result with object fields and a global value, conditionally invoke an indirect operation, and clear the object reference.
- **Both results zero:** publish the current contents of a private 32-bit output cell, invoke a dependency using object fields, and replace the low byte of a status word with `0x04`.

Classification takes precedence over the initial result. A nonzero initial result is not reported when classification is nonzero.

These are established structural behaviors. Interpretations such as cancellation, destruction, failure reporting, or successful completion are inferred intent, not established semantics.

## Behavior

### Initial operation and private output cell

The function initializes a private 32-bit output cell to zero, then invokes F-70f203df26ce with six arguments:

1. The context address.
2. The 32-bit object reference read from context offset `0x48`.
3. The context address again.
4. Zero.
5. The address of the private output cell.
6. The third input argument.

The dependency’s 32-bit result is retained for later zero/nonzero testing and possible reporting. It is not returned directly to the caller.

F-70f203df26ce can write the output cell through the supplied address. If no write changes the cell during this initial call, the cell is zero when that call returns. This statement is limited to that point in execution; it does not establish that the cell remains zero until publication.

The supplied address could be retained in shared state and used by a later dependency while the cell is still live. In particular, F-0cde56e61f4c could modify it through such an alias. Whether any dependency actually retains or uses the address is unknown. The function does not establish ownership transfer or authorize access after the cell’s lifetime.

### Classification

After the initial operation returns, the function reloads the object reference from context offset `0x48` and passes it to F-0cde56e61f4c.

The classified reference can differ from the reference supplied to F-70f203df26ce. No preservation of the slot by the initial operation is assumed.

The classification result is tested for zero versus nonzero. A nonzero result selects the classification path regardless of the initial result. Classification may also have side effects, including changing the context, globals, or the private output cell if an accessible alias exists.

### Nonzero classification

The function reloads the object reference and reads its 32-bit field at offset `0x1C`.

If that field is nonzero, the function returns without further visible action. It does not report the initial result, load the reporting global, invoke the indirect operation, explicitly clear the reference slot, invoke F-b8a325ddd21b, publish output, or update status.

If the field is zero, the function checks the already selected reference for null. For a nonnull reference, it reads the operation-table reference at object offset `0x00`, obtains the callable target at table offset `0x04`, and invokes it.

After the indirect invocation returns—or after the null-check skip—the function:

1. Writes zero to context offset `0x48`.
2. Invokes F-b8a325ddd21b with the context-interior address at offset `0x4C`.
3. Returns.

The field access at `0x1C` precedes the null check. That check therefore does not make a null reference safe.

The explicit clear occurs after the indirect invocation. If the indirect operation installs a replacement reference in the context and returns, the clear overwrites that replacement. F-b8a325ddd21b runs after the clear, but its own effects are unknown; the function does not guarantee that the slot remains zero after that dependency returns.

### Zero classification and nonzero initial result

The function invokes F-d7901cd15a43 with six arguments:

1. The context address.
2. A 32-bit value read at object offset `0x08` through the context’s reference slot.
3. The contents loaded from the global data location.
4. A 32-bit value read at object offset `0x0C` through the context’s reference slot.
5. The retained nonzero 32-bit initial result.
6. Zero.

The global is read during preparation of this call, after both the initial operation and classification have returned. Either dependency may have changed it before the load. It is not an entry-time snapshot, a fixed constant, or an address argument.

The relative order of the individual argument reads is not established. No ordering is promised between the global load and either object-field read. The object-field expressions use accesses through the reference slot; a common stable object is not guaranteed under intervening external mutation.

After reporting returns, the function checks the context’s current object reference for null. If nonnull, it obtains and invokes the indirect target through the reference slot and the object’s operation table. The reference slot is accessed again to obtain that target; the null check does not establish stability against concurrent mutation.

After the invocation returns, or if the null check skips it, the function writes zero to context offset `0x48` and returns.

The object selected after reporting can differ from those used for reporting arguments. If reporting leaves the slot null, the indirect invocation is skipped but the explicit zero write still occurs.

This path does not invoke F-b8a325ddd21b, publish the private output cell, or update the status word.

### Zero classification and zero initial result

The function reads the private output cell and writes that 32-bit value to object offset `0x24`, using the context’s current reference slot.

The published value is the cell’s value at this read. It need not equal zero or the value present when F-70f203df26ce returned. Intervening dependency writes through a retained alias can change it.

After publication, the function invokes F-8457b1fa5923 with:

1. The 32-bit value read from object offset `0x24`.
2. The 32-bit value read from object offset `0x20`.

The first argument is read from the object field after publication; it is not simply forwarded from the private cell. Ordering between these two argument reads is not established. With stable storage and no intervening changes, the first argument equals the published value.

After F-8457b1fa5923 returns, the function reads a 32-bit status word at object offset `0x14`, preserves bits 8 through 31, replaces bits 0 through 7 with `0x04`, and writes the resulting 32-bit word to offset `0x14`.

This clears the other low-byte bits; it does not merely set the bit represented by `0x04`.

The status operation accesses the context’s reference slot again. F-8457b1fa5923 can therefore redirect it to a different object from the publication destination. The status source and destination expressions also access the slot separately; their identity under concurrent mutation is not guaranteed.

This path does not explicitly clear the reference slot, invoke the indirect operation, load the reporting global, or invoke F-b8a325ddd21b.

### Ownership and aliasing

The output value’s meaning is unknown. Publication does not establish whether it represents scalar data, an address, a handle, or an ownership-bearing token.

The private cell’s address is exposed to F-70f203df26ce. Its private storage location does not imply exclusive access once that address has been passed out. Consequently, an unchanged cell at the initial dependency’s return is insufficient to guarantee zero publication.

No ownership contract is established for the context, objects, operation table, global data, or adjacent context region.

### Errors and abnormal completion

No retry, rollback, exception handler, or validation layer is visible. An invalid access or dependency that does not return normally prevents guarantees about subsequent actions. In particular, an indirect operation that does not return prevents the later explicit reference clear.
