# F-188b4aa4cd05

## Purpose

F-188b4aa4cd05 performs an ordered configuration sequence, waits for a status condition, invokes an external dependency, and writes a previously obtained 32-bit value through a captured pointer.

The configuration uses four signed 16-bit inputs. Their arrangement is consistent with two starting coordinates and two extents: the function supplies each starting coordinate and an inclusive endpoint calculated as starting coordinate plus extent minus one. This geometric interpretation is inferred intent, not an established requirement of the dependencies.

The established behavior is narrower: six ordered calls submit selector/value pairs, a subsequent call receives a value obtained from global storage, a polling loop waits for bit mask 2 to become nonzero, an external call receives the value 1, and a final 32-bit store occurs.

The function does not validate its inputs, provide a timeout, or report a success or failure result.

### Pointer capture and polling

After F-d22a851ad449 returns, the function captures the current global pointer into a local pointer used later for the final store. The captured pointer is represented as pointing to 32-bit elements.

The function then repeatedly evaluates a status expression using element index 7 reached through the global pointer. The loop continues while:

- the indexed status value, bitwise-ANDed with 2, is zero.

Thus bit position 1 is the only bit relevant to the exit condition. Other status bits do not substitute for it.

There is at least one status evaluation, even if the condition is already satisfied when polling begins. The loop body performs no explicit operation. It contains no delay, yield, timeout, error check, or call to another dependency.

A distinction exists between the two pointer uses:

- The final destination pointer is captured once before polling.
- The polling expression refers to the global pointer rather than the captured pointer.

If the global pointer changes during polling and that change is observed, polling can follow the changed pointer. The final store still uses the previously captured pointer. The source does not establish that the global pointer remains constant.

The exact physical reads emitted for the loop depend on declarations and access qualifiers not included in the supplied material. Repeated expression evaluation is visible; volatile access, atomicity, memory ordering, and compiler treatment of externally changing storage are not established.

### Completion sequence

## Acceptance examples

These examples are conditional expectations derived from static evidence, not results of runtime tests.

### Ordinary positive inputs

10, 12, 20, 23, 10, 20.

The selectors must follow the ordered literal/global pattern described above. Completion additionally requires the polling condition and all dependency and memory preconditions.

### Single-unit extents

With either extent equal to 1, its calculated endpoint equals its corresponding start. Both the start and endpoint calls still occur; equal values do not collapse the sequence.

### Zero and negative extents

With horizontal start 10 and horizontal extent 0, the horizontal endpoint supplied is 9.

With vertical start 20 and vertical extent −2, the vertical endpoint supplied is 17.

The function must not be specified as rejecting these inputs or silently replacing their extents.

### Signed boundary inputs

With a start and its extent both −32,768, the corresponding endpoint expression is −65,537.

With both equal to 32,767, the corresponding endpoint expression is 65,533.

These are promoted arithmetic results, not 16-bit wrapped endpoints. Any later narrowing inside the receiving dependency remains outside the established contract.

### Status already ready

If the first evaluated status value has bit mask 2 set, the function exits polling after that evaluation, calls the external dependency with 1, and then performs the final store.

A status value of 2 satisfies the condition. A value of 1 does not.

### Status never ready

If every observed status evaluation has bit mask 2 clear, the function remains in polling. The post-poll external call, final store, and normal return are not reached.

### Changed global pointer

Suppose pointer A is captured before polling. If the global pointer later changes to pointer B and the status expression observes B, the loop’s exit condition can be satisfied using B’s indexed status.

After the external dependency returns, the saved 32-bit result is nevertheless written through A, provided A remains valid.

### Changed global-backed selector

If an earlier configuration dependency changes the global selector used by a later configuration call, that later call uses the value obtained when its own argument is evaluated. A contract requiring all selectors to reflect entry-time state would not match the visible body.
