# F-925357ba24ce

## Purpose

F-925357ba24ce transfers two consecutive 4-byte values from a supplied source region into two adjacent fields of a destination region. The destination fields begin at byte offsets 28 and 32 from the supplied destination base.

The established behavior is an ordered pair of transfers, not an independently established bulk-copy operation. The first destination write precedes the second source read in the supplied source-level sequence. Consequently, overlapping source and destination storage can change the value transferred by the second operation.

The meanings of the two values and the surrounding destination structure are unknown. Treating them as coordinates, lengths, pointers, or another semantic pair would be an inference unsupported by the supplied evidence.

## Behavior

For an execution satisfying the memory-access preconditions, the source-level sequence is:

1. Read the 4-byte value at the supplied source address.
2. Write that value into the destination field beginning at byte offset 28.
3. Read the 4-byte value beginning 4 bytes after the supplied source address.
4. Write that value into the destination field beginning at byte offset 32.
5. Return without a value.

The second read is therefore specified relative to memory state **after** the first write, rather than necessarily relative to memory state at function entry.

There is no branch, loop, comparison, explicit error path, or dependency call in the supplied body. Two values are transferred regardless of their contents. Zero values, all-one bit patterns, and values whose high bit is set do not select different behavior.

### Overlap

No non-overlap check is present. Overlap must be evaluated using the ordered accesses above, subject to the execution environment permitting the relevant aliasing and accesses.

If the first destination field occupies the same storage as the second source element, the first write replaces that source element before it is read. The second destination field then receives the value written by the first transfer. This differs from a transfer that captures both original source values before writing either destination field.

If the source begins at the first destination field, each transfer reads and writes its corresponding field. With ordinary stable memory, both fields retain their existing values, although the source-level body still expresses two reads and two writes.

The evidence does not support a general promise of safe operation for arbitrary partial-byte overlaps. Such cases depend on alignment, aliasing rules, and the actual memory-access semantics.

### Address and width considerations

The destination offsets are 28 and 32 **bytes**, not counts of 4-byte elements. The second source element is 4 bytes after the first because the source pointer addresses 4-byte elements.

The final destination field extends through byte offset 35. For ordinary contiguous backing storage beginning at the destination base, at least 36 bytes must therefore be available to contain both fields. The function does not access the preceding 28 bytes merely because they lie before the written fields.

No overflow handling is expressed for destination-address formation. The evidence does not establish wrapping address arithmetic as supported behavior, nor does it establish a checked failure for overflow.

### Distinct source and destination

Suppose the source contains two different 32-bit patterns, A followed by B, and neither source element overlaps either destination field.

After normal completion:

- Destination bytes 28–31 contain A.
- Destination bytes 32–35 contain B.
- The source remains unchanged.
- Other destination bytes are not directly written by this function.

A and B need not represent numbers; the contract concerns their 4-byte representations.

### First write replaces the second source element

Suppose the source begins at destination byte offset 24. Initially, bytes 24–27 contain A and bytes 28–31 contain a different pattern B.

The first transfer reads A and writes it to bytes 28–31. The second source read then reads those same bytes, now containing A.

After normal completion:

- Bytes 24–27 still contain A.
- Bytes 28–31 contain A.
- Bytes 32–35 contain A.

An implementation that instead writes the original B to bytes 32–35 would not match this ordered source-level behavior, assuming the environment permits the overlapping accesses.
