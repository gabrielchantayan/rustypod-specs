# F-8a808c58ca89

## Purpose

F-8a808c58ca89 performs a fixed-order sequence of indirect invocations, indexed word stores, selector-based byte updates, bit extraction, and shared-state publication. Its terminal operations clear a byte through a call-produced pointer, replace a shared word, clear a computed halfword location, and attempt an invocation at address zero.

No application-level purpose is established. The evidence does not establish initialization, collection management, service dispatch, or cleanup.

This contract describes the supplied static representation. It does not establish that execution is reachable, that the addressed memory is accessible, or that the function returns normally.

### Widths and descriptive terms

A **word slot** selected by an index has address four times that index plus 0x14. A **wide-stride slot** has address sixteen times its index plus 0x14. These formulas do not establish allocated arrays or record layouts.

A **selector update** reads an unsigned byte, adds 0x11 to its zero-extended value, and writes one byte at that destination. Its destination therefore lies between 0x11 and 0x110 inclusive.

The contract distinguishes several retained values:

- **Entry extraction:** the incoming extraction value logically shifted right by 22; range 0–0x3FF.
- **Masked-read extraction:** a later memory word logically shifted right by 22; independently range 0–0x3FF.
- **Early retained result:** a primary 32-bit call result obtained before two later absolute-address-1 selector clears.
- **Published result:** a different, subsequently obtained primary 32-bit result written to the second shared word.
- **Retained data word:** a later full 32-bit memory read propagated into two indexed slots.
- **Late payload:** a word read using a fresh value of the first shared word.

These names describe value provenance, not private implementation identifiers or semantic field types.

Direct memory operations include 8-, 16-, and 32-bit accesses. The terminal construction additionally consumes a represented three-byte quantity. Address arithmetic is represented using 32-bit quantities. Signed scaling and signed left shifts occur; portable behavior for overflow, negative operands, or invalid shifts is not established. Unsigned right shifts are logical. A numeric low byte means the least significant eight bits, independently of memory byte order.

## Behavior

### Execution order

The visible body is straight-line: no conditional branch, loop, retry, status test, or early return precedes the final invocation.

Indirect invocations intervene throughout. They must not be removed, merged, or treated as inert. A call with no displayed arguments is not proof that its target consumes no incoming machine state.

Except for the initial target and terminal zero target, targets are constructed from fixed anchors and offsets. Dependency identity cannot be inferred merely from similar call syntax or offsets.

The following phases preserve the order of direct accesses and significant argument transfers. Progress to each operation requires all preceding calls and accesses to complete.

### Initial publication and extraction

The first invocation receives the second explicit input. Its target is the incoming link-associated value plus 0xF38.

After intervening invocations, including forwarding a primary result to another invocation, a primary result supplies an index. The function:

1. Stores the incoming payload into that index’s word slot.
2. Reads and retains the first shared word.
3. Invokes a dependency with four times the index.

Further calls expose an index in a secondary register. The function computes the entry extraction and logically shifts the retained first shared word right by 23, yielding a 9-bit value.

It stores the entry extraction into the secondary index’s word slot. The next significant invocation receives, in order:

- The secondary index.
- The same secondary index.
- The 9-bit shared-word extraction.
- The entry extraction.

Following another invocation and result-forwarding sequence, the 9-bit extraction is itself shifted right by 23. This second shift necessarily produces zero.

A later primary-result index selects a word slot that receives the entry extraction. The following invocation receives four times that index.

Further invocations expose another secondary-register index. Its word slot is cleared to zero, and the index is passed to a subsequent invocation.

### Masked read and initial selector updates

A later primary-result index selects another word slot. That slot receives the double-shifted shared-word extraction: zero.

The function then reads a 32-bit word at an address formed by masking the most recent secondary-register index with 0x1FFFFFFF, shifting right by 19, and adding 0x14. The address ranges from 0x14 through 0x413 and need not be word-aligned.

After intervening invocations, that memory word is logically shifted right by 22 to form the masked-read extraction.

The next selector update:

1. Reads a byte at absolute address 1, because its computed selector base is the earlier double-shifted zero.
2. Writes the low byte of the masked-read extraction at the selector value plus 0x11.

A subsequent invocation receives one secondary-register value three times, followed by zero. Another later invocation receives zero explicitly.

After more calls, a selector byte is read at four times the **masked-read extraction**, plus 1. The selected destination is cleared to zero. This selector address depends on the masked-read extraction, not the entry extraction.

The next significant invocation receives a fresh primary result shifted left by two. Subsequent calls include an invocation receiving another shifted result in two argument positions.

A later primary 32-bit result becomes the early retained result and is passed onward unchanged.

### Two absolute-address-1 clears and the intervening extraction

After another invocation, the function reads a selector byte at absolute address 1 and clears the selected byte at selector plus 0x11.

It retains a secondary-register value and invokes a dependency with three copies of that value.

A following invocation produces a fresh primary 32-bit result. The next invocation has exactly two displayed arguments:

1. That freshly obtained primary result.
2. The **early retained result logically shifted right by 23**.

The second argument is a 9-bit quantity, ranging from zero through 0x1FF. It is not extracted from a newly read global or from the later published result.

After additional invocations, the function reads address 1 again and clears the byte at this new selector plus 0x11. This is a distinct read: intervening calls may have changed address 1.

The selector obtained by this second clear is retained for a later word-to-byte copy.

### Shared publication and repeated low-byte copies

Following the second clear, invocations consume shifted primary results, including one invocation receiving the same result shifted left by two in two argument positions.

A subsequent primary 32-bit result becomes the published result. The function writes it to the second shared word before passing it to another invocation.

The early retained result and published result are different acquisitions. Their equality is neither required nor implied.

After a further invocation, the function uses the selector retained from the second absolute-address-1 clear:

1. Reads a 32-bit word at retained selector plus 0x74.
2. Writes its numeric low byte at retained selector plus 1.

It does not reread address 1 for this copy.

The next significant invocation receives the retained secondary-register value shifted left by 11.

A subsequent represented 64-bit result is split into low and high 32-bit halves. The following invocation receives:

1. The low half.
2. The high half.
3. The **published result** logically shifted right by 23.

This extraction is separate from the earlier two-argument invocation’s extraction of the early retained result.

A later primary-result index is multiplied by four and retained as a base. The function reads a word at base plus 0x74 and copies its low byte to base plus 1. The base is then supplied to an invocation.

After further calls, a different primary result is shifted left by two and retained. The function repeats the word read and byte write at the earlier base. The second copy performs a fresh read.

The next significant invocation receives, in order:

- The retained secondary-register value shifted left by 12.
- The newly retained shifted result.
- That same shifted result again.
- Its original unscaled result shifted left by 18.

Further calls include result forwarding through a target using a different offset.

### Full-word propagation and linkage

A later primary-result index is multiplied by four. The function reads a word at that base plus 0x74, retains the complete value as the retained data word, and copies its low byte to base plus 1.

The retained data word is subsequently stored, in order:

1. Into a wide-stride slot selected by a later result.
2. Into a word slot selected by another later result.

Intervening invocations remain significant. One receives the previously retained shifted result logically shifted right by two, then left by 16. The right shift must not be treated as recovering bits already discarded by the earlier left shift.

A subsequent primary result is shifted left by two. The shifted value is stored at the address obtained by clearing the low two bits of the previously retained shifted result and adding 0x14. The newly shifted value is then passed twice to an invocation.

After another forwarding sequence, a later result selects a word slot that is cleared to zero.

A represented 64-bit result then supplies another low/high pair:

- The low half is shifted left by two.
- The high half selects a word slot.
- The shifted low half is stored into that slot.

The function freshly reads the first shared word. This read does not reuse the value captured near entry.

The following invocation receives the shifted low half, the high half, and two further copies of the shifted low half.

After more calls, another result selects a word slot that receives the same shifted low half. The function then reads the late payload at the freshly retained first-shared-word value plus 0x14.

### Final selector writes and terminal operations

A later represented 64-bit result supplies another low/high pair. Its low half is retained for later address calculations.

Before calling onward, the function:

1. Logically shifts the retained data word right by 23.
2. Reads a selector byte at that value plus 1.
3. Writes the low byte of the late payload to selector plus 0x11.

The next significant invocation receives the new high half three times, followed by the new low half shifted left by two.

After further calls, a second selector address is formed by masking that same low half with 0x3FFFFFFF, shifting right by 21, and adding 1. The selector read is therefore within addresses 1 through 0x200 inclusive. The selected destination receives the low byte of the late payload logically shifted right by 22.

Additional calls consume shifted results, including one invocation with the same shifted result twice. A later call uses a target formed with offset 0xB0; its result is forwarded. The final result-producing invocation supplies a represented 8-bit result.

Terminal operations occur in this order:

1. Clear one byte through a pointer exposed in a secondary result register.
2. Obtain the represented three-byte quantity beginning at absolute address 9.
3. Construct a 32-bit value whose low eight bits are the final 8-bit result and whose upper 24 bits are that three-byte quantity.
4. Store the constructed word into the second shared word.
5. Store 16-bit zero at the address obtained by masking the retained low half with 0x3FFFFFFF and shifting right by seven.
6. Attempt an indirect invocation at address zero with three explicit zero arguments.

The halfword destination ranges from zero through 0x007FFFFF inclusive and need not be aligned.

A return follows the zero-target invocation. Normal completion requires that invocation to return.
