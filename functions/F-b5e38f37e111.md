# F-b5e38f37e111

## Purpose

F-b5e38f37e111 conditionally updates a 32-bit field in a globally selected primary object, performs an ordered sequence of dependent operations, resolves an associated object if necessary, and conditionally requests a binary state on that associated object.

“Position,” “provider,” “notification,” and “state request” are descriptive roles, not established application semantics. The static evidence establishes numeric selection, object-field accesses, dispatch locations, argument dataflow, and control flow. It does not establish units, ownership, or the meaning of the final zero-or-one argument.

The numeric update is not ordinary saturating addition. The positive-displacement branch uses unsigned subtraction and comparison, may query the provider twice before committing, and queries it again before the final state request. Successive provider results need not agree.

## Interface

### Arguments and result

The recovered interface has two explicit inputs:

| Input | Width and interpretation | Established use |
|---|---|---|
| First argument | Opaque 32-bit value | Not observably used |
| Displacement | Signed 32-bit value | Selects the movement branch and supplies movement arithmetic |

No return value or status is established. Consumers must not rely on a particular return-register value.

- The primary object's notification operation is selected at table byte offset `0x58`.
- A nonnull acquisition result begins with a dispatch-table pointer. Its lookup operation is selected at table byte offset `0xF8`.
- The associated object begins with a dispatch-table pointer. Its final operation is selected at table byte offset `0xA0`.
- The associated object's 32-bit flags field is at object byte offset `0x48`.

These accesses do not establish complete object sizes or public types.

### Opaque global and incoming values

Three additional opaque global locations have distinct observable roles:

| Label | Width | Established use |
|---|---|---|
| Global A | 32 bits | Read once into a saved value, then read separately for the first notification |
| Global B | 32 bits | Read for the first notification's third argument |
| Global C | 32 bits | Read for the acquired object's lookup argument |

### Preconditions

Every pointer and dispatch entry actually dereferenced must be valid at the time of use. The function does not generally validate the primary object, provider, dispatch tables, or final associated object.

For zero displacement, only the initial global pointer location must be readable. The resulting primary-object pointer is not dereferenced on that path.

Two acquisition results are checked explicitly: a null acquisition-result pointer and a zero associated-object lookup result. Neither check rolls back earlier changes.

## Behavior

### Numeric model

Let:

- \(D\) denote the signed displacement.
- \(P\) denote the saved 32-bit position read before branch-specific calls.
- \(T\) denote the locally selected 32-bit value eventually committed.
- \(B_1\) and \(B_2\) denote successive pre-commit results from provider slot `0x60`, when present.

The displacement sign test is signed. Movement comparisons involving \(P\) are unsigned 32-bit comparisons. Arithmetic used as a 32-bit result is interpreted modulo \(2^{32}\).

These rules describe the recovered fixed-width behavior. They do not establish that every representable displacement or position is valid at the application level.

### Zero displacement

The primary-object pointer is obtained before testing for the immediate-return path.

If \(D=0\), the function then returns without:

- Reading the position field.
- Writing any object field.
- Reading Globals A, B, or C.
- Calling any dependency or indirect operation.

### Negative displacement

For \(D<0\), the position field is read into \(P\). The unsigned 32-bit magnitude of \(D\) is compared with \(P\).

If that magnitude is strictly less than \(P\):

- F-0fd549c24c37 is called with the primary object and the original negative displacement.
- After it returns, \(T\) is selected as \(P+D\), using the saved position.

Otherwise, \(T=0\), and F-0fd549c24c37 is not called.

Equality therefore selects zero without invoking the helper. A dependency's modification of the stored position does not change the saved \(P\) used for the addition.

For the most-negative signed displacement, the unsigned magnitude is `0x80000000`; it is not a representable positive signed 32-bit value.

### Positive displacement

For \(D>0\), the function saves the position as \(P\), then queries the provider through slot `0x60`, obtaining \(B_1\).

It tests:

\[
P < \bigl((B_1-D)\bmod 2^{32}\bigr)
\]

using an unsigned comparison.

If the comparison succeeds:

- F-0fd549c24c37 receives the primary object and the original positive displacement.
- After it returns, \(T=(P+D)\bmod 2^{32}\), using the saved position.

If the comparison fails:

- The provider is queried again through slot `0x60`.
- That second result, \(B_2\), becomes \(T\).

The second query is required on the failed-comparison path. Reusing \(B_1\) would remove an observable call and could change the committed value.

Underflow in \(B_1-D\) produces an unsigned 32-bit result. Consequently, a displacement larger than \(B_1\) does not necessarily select the provider-result branch.

### Commit and update sequence

Every nonzero path that proceeds normally commits and updates in this order:

1. Store \(T\) at primary-object offset `0x73C`.
2. Call F-3ac76db3f868 with no explicit recovered arguments.
3. Read the current provider pointer and invoke provider slot `0x88`.
4. Pass the primary object and that operation's 32-bit result to F-a47f88e3d6eb.
5. After F-a47f88e3d6eb returns, read Global A and retain that value locally.
6. Invoke the first primary-object notification through slot `0x58`.
7. Invoke the second primary-object notification through a fresh slot-`0x58` dispatch lookup.

The position store precedes all these calls. There is no established transaction or rollback.

### Notification argument dataflow

The first notification has eight explicit recovered argument positions:

| Position | Supplied value |
|---|---|
| 1 | Primary-object pointer |
| 2 | A separate read of Global A, not the previously saved value |
| 3 | A read of Global B |
| 4 | A separately loaded function value from the primary object's slot `0x58` |
| 5 | Incoming 1 |
| 6 | Incoming 2 |
| 7 | Incoming 3 |
| 8 | Incoming 4 |

The function value supplied in position 4 is a separate slot load from the load used to select the invocation target. Both refer to slot `0x58`; the source does not justify merging their accesses.

The second notification receives:

1. The primary-object pointer.
2. The value saved from Global A before the first notification.

It does not reread Global A for that second argument.

Thus, Global A has two distinct reads in this sequence: the earlier saved read and the first notification's argument read. The second notification uses the earlier one. Equality between the first and second notification arguments is not guaranteed without an assumption that Global A remains unchanged between those reads.

The source establishes the saved read before the first invocation and the two invocations in sequence. It does not establish a total evaluation order among the first invocation's individual argument reads and target lookup.

The recoverable argument positions are established even though their semantic meanings and a trustworthy high-level notification signature remain unknown.

### Associated-object acquisition

After both notifications return, the function reads primary-object offset `0x750`.

If the cache is nonzero, acquisition is skipped. In particular, F-1093fa967285 is not called and Global C is not read on this path.

If the cache is zero:

1. Call F-1093fa967285.
2. Store its pointer-sized result at primary-object offset `0x778`, including a null result.
3. Test the acquisition result. If null, return.
4. For a nonnull result, read Global C and invoke the acquired object's slot-`0xF8` operation with the acquired-object pointer and that global value.
5. Store the operation's 32-bit result at primary-object offset `0x750`.
6. If the lookup result is zero, return.

The Global C read belongs to the lookup invocation, after the acquisition result has been stored and found nonnull. It is not an incoming argument or an unspecified external value supplied independently of a global read.

The acquisition-result object and associated object have different roles. Their identities must not be assumed equal.

A zero lookup result is written to the cache. No separate “attempted” state is established, so a later invocation observing a zero cache can attempt acquisition again.

### Final state request

After the cached-object check or successful acquisition, the function queries the current provider through slot `0x60`.

Only after that query returns does it read the associated-object pointer from offset `0x750`. It does not retain the earlier cache value across this provider call.

The final provider result is compared with local \(T\), not with a fresh read of the committed position field.

- If the values are equal, the associated object's slot-`0xA0` operation receives that object and zero. The flags field is not read on this path.
- If the values differ, the associated object's flags at `0x48` are read.
  - If the flags masked by `0x1800` equal `0x0800`, the function returns without the final dispatch.
  - Otherwise, slot `0xA0` receives the associated object and one.

The flags condition suppresses only the unequal-value request. It does not suppress an equal-value request.

The final operation is represented as an indirect transfer with the stated arguments. Whether the underlying transfer is an ordinary call or a tail transfer remains unresolved.

## Side effects

### Direct writes

The body directly writes only these primary-object fields:

| Offset | Write condition |
|---|---|
| `0x73C` | Every nonzero-displacement path reaching commit |
| `0x778` | Acquisition is attempted; null is also stored |
| `0x750` | Acquisition returns nonnull and lookup returns; zero is also stored |

There is no explicit allocation, release, reference-count operation, or cleanup sequence in the body. Retaining F-1093fa967285's result does not establish that this dependency allocates memory.

### Dependency mutation and retained values

No dependency contract establishes preservation of globals, object fields, dispatch tables, provider identity, or object lifetimes.

The primary-object pointer, saved position, selected \(T\), and saved Global A value retain their respective local dataflow roles across intervening calls. In contrast:

- Provider pointers and dispatch entries are obtained at their later use sites.
- The second notification's target is looked up after the first notification returns.
- The final associated-object pointer is read after the final provider query.

Changing the global primary-object selection does not redirect subsequent accesses by this invocation. Changing the primary object's fields or dispatch table can affect later reads.

If a dependency changes the position after commit, the final equality test still uses \(T\). If the final provider query invalidates or clears the cached associated-object pointer, no subsequent null check protects its use.

### Errors and ownership

There is no explicit error status, exception translation, or recovery protocol.

Null acquisition, zero lookup, and flags-based suppression are ordinary early-return paths. All preserve preceding writes and calls.

Ownership transfer, reference retention, release obligations, synchronization, and lifetime protection are documented_only.

## Acceptance examples

These are conditional static acceptance scenarios, not observed executions. Unless otherwise specified, dependencies return normally and preserve the relevant objects and values.

1. **Zero displacement.** The initial primary-object pointer is obtained. No object field or Global A, B, or C is subsequently read, and no dependency runs.

2. **Negative movement inside the saved position.** For \(P=10\) and \(D=-3\), F-0fd549c24c37 receives −3, and 7 is committed. If that helper changes the position field, the committed value still derives from saved \(P=10\).

3. **Negative movement reaching or passing zero.** For \(P=3,D=-3\), or \(P=2,D=-3\), zero is selected without calling the movement helper. The common updates still occur.

4. **Most-negative displacement.** For \(D=-2147483648\), magnitude comparison uses `0x80000000`. A saved position equal to that magnitude selects zero without the movement helper; a larger unsigned position takes the helper-and-addition path.

5. **Positive strict comparison.** For \(P=4,D=2,B_1=10\), the comparison is \(4<8\); the helper receives 2 and 6 is selected.

6. **Positive boundary with changing provider.** For \(P=8,D=2,B_1=10\), the comparison fails. A second query returning 12 causes 12, not 10, to be committed.

7. **Unsigned subtraction underflow.** For \(P=0,D=5,B_1=3\), the subtraction yields `0xFFFFFFFE`. The helper runs and 5 is selected; automatic clamping to 3 would not match the evidence.

8. **Distinct Global A reads.** If the saved read obtains value \(X\), while the separate first-notification read obtains \(Y\), the first notification receives \(Y\) in position 2 and the second receives \(X\). A change made by the first notification does not replace saved \(X\).

9. **Notification argument structure.** The first notification receives the Global B read in position 3, the separately loaded slot-`0x58` function value in position 4, and the four incoming values in positions 5–8. The second notification has only its two explicit recovered arguments.

10. **Null acquisition after commit.** A null acquisition result is stored at `0x778`, then the function returns. Global C is not read. The position store, update calls, and both notifications have already occurred.

11. **Nonnull acquisition with zero lookup.** Global C is read after the acquisition-result store and successful null check. If lookup returns zero, zero is stored at `0x750`, and no final provider query occurs.

12. **Final equality and flags.** If the final provider result equals \(T\), slot `0xA0` receives zero without reading flags. If unequal, masked flags `0x0800` suppress dispatch; masked values `0x0000`, `0x1000`, and `0x1800` lead to argument one.

- Ownership and lifetime behavior of every dependency.

Inferred intent is limited to position adjustment, dependent update or notification, lazy associated-object resolution, and a binary state request. These interpretations add no guarantees.
