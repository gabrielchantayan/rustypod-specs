# F-871c676a9141

## Purpose

F-871c676a9141 advances a stateful, table-driven item processor, prepares sixteen-byte output records, and writes a batch trailer. Its visible behavior includes size and position lookup, two-word accumulation, selection checkpoints, deferred replay, table-window refreshes, cancellation checks, and path-dependent progress reporting.

**Established static evidence:** the supplied body consumes inherited machine and stack state, contains an internal processing loop, mutates externally supplied storage, and has both common and direct-return exits.

**Inferred intent:** the data resembles indexed media processing. Neither a media format nor particular time units are established; this contract uses neutral item, position, and time-like terminology.

The displayed no-argument interface is insufficient to establish an independently callable public API.

## Interface

- A pointer to an external one-byte stop indicator.

The function returns a 32-bit integer:

## Behavior

### Entry processing and record commitment

On each arrival at the visible entry point, a non-null control descriptor enables an upper-boundary check. The compared value is the sign extension of the 32-bit word at 0xb0, **not** the full accumulator at 0xb0/0xb4.

If that value is at least the signed two-word upper boundary:

1. The control counter at 0xc4 increases.
2. If the control descriptor’s signed first word is no greater than the new counter, status becomes 1.
3. F-b1214ca19495 is called.

If pending record length is positive, the processor increases the record count and, when status equals 1, increases the working slot. It then writes four consecutive words in this order:

1. Output base plus accumulated payload bytes minus pending length.
2. Pending length.
3. Previously converted time.
4. Selection flag.

The record cursor moves backward sixteen bytes, and committed bytes become prospective bytes.

Exact equality of committed bytes and capacity assigns status 0 and enters finalizer-mediated exit processing. Otherwise, status 1 prevents another item iteration. For other statuses, the slot increases; another iteration requires committed bytes below capacity and the resulting slot below 0x600. These bounds are signed comparisons. A status other than 1 does not itself prohibit continuation.

### Selection and checkpoint capture

Each item iteration clears pending length, then examines the selection cursor. If it is below the selection descriptor’s signed count and the indexed entry equals the current item, the cursor increases, the current item is saved at 0x240, and selection becomes 1. Otherwise selection becomes 0. There is no explicit nonnegative-cursor validation.

A selected item captures these words individually, in the following order:

| Live fields | Saved fields |
|---|---|
| 0x8c, 0x90, 0x94, 0x98, 0xa0 | 0x244, 0x248, 0x24c, 0x250, 0x254 |
| 0xa8, 0xac, 0xb0, 0xb4 | 0x260, 0x264, 0x268, 0x26c |
| 0xc0, 0xc4 | 0x258, 0x25c |
| 0xc8, 0xcc, 0xd0, 0xd4 | 0x278, 0x27c, 0x280, 0x284 |
| 0xd8, 0xdc | 0x270, 0x274 |

This is not an atomic snapshot. Neither selection cursor nor working slot is included.

### Size acquisition and immediate capacity guard

For a nonzero fixed-size word, the processor writes that word to the working size slot, then rereads the size-descriptor pointer and its first word to obtain pending length. This is not a reread of the working slot; aliasing can distinguish the accesses.

For a zero fixed-size word:

- The external stop byte is checked first. Exactly 1 selects the status-2 common exit.
- An item above the signed item limit receives working size 0xffffffff; pending length remains zero.
- Otherwise, the variable-size window is checked and, if needed, F-3563447b05c9 is called. A nonzero result selects status 1.
- Successful lookup rereads descriptor information and reads entry “current item minus window base minus one,” storing it as both pending length and working size.

Without arithmetic overflow, the size window admits items strictly greater than its base and no greater than base plus 0x8000.

After size processing, capacity is compared against **the first size-working-array word plus 32**, not necessarily the current slot. If capacity is smaller, the function immediately returns 4. Earlier checkpoint, size, or dependency effects remain; there is no trailer, finalizer call, progress write, or post-trailer call.

Only after this guard is the next-item value established as current item plus one.

### Control boundaries and replay

Without a control descriptor, the prospective record contribution is pending length plus sixteen bytes.

With a control descriptor, while both lower-boundary words equal 0xffffffff, the function adds the two-word control increment to the time-like accumulator, increments the control counter, and calls F-b1214ca19495. The condition checks the high boundary word first and checks the low word only when the high word is 0xffffffff. There is no visible iteration limit.

The sign-extended word at 0xb0 is then tested against the lower-inclusive, upper-exclusive interval. The high accumulator word at 0xb4 is not used.

Outside the interval:

- Selection 1 with replay byte zero sets the deferred byte to 1.
- Otherwise, replay byte exactly 1 permits a contribution of pending length plus sixteen.
- Without that permission, pending length and contribution become zero, and an item-local flag records suppression.

Inside the interval:

- If the deferred byte is zero or the current item is selected, deferred is cleared first, then replay is cleared.
- Otherwise, replay becomes 1; the saved item and checkpoint fields are restored in capture order; deferred becomes zero; F-94bd82ad6ce8 is called; and processing restarts at the item-iteration boundary.

Replay does not visibly restore selection cursor or working slot.

### Initial table checks and prospective capacity

Checks occur in this order:

| Table or decision | Admitted range without overflow | Refresh |
|---|---|---|
| Progression | Base through base + 0x8000, upper endpoint excluded | F-58e3c92f2660 |
| Grouping | Base through base + 0x7fff, upper endpoint excluded | F-bc4667302afc |
| Prospective capacity | Committed bytes plus contribution must not exceed capacity | None |
| Position | Greater than base through base + 0x4000, inclusive | F-40fcaf87b7ef |

A nonzero refresh result selects status 1 and common exit. Insufficient prospective capacity assigns status 0 and uses finalizer-mediated exit.

After the initial position-window check, the position word is read at index “position-table index minus base minus one.” The external stop byte is then checked again; exactly 1 selects status 2. Thus fixed-size processing bypasses the early stop check but not this later one.

### Item-state advancement

If the current item exceeds the size descriptor’s item limit, status becomes 1 and finalizer-mediated exit begins. Otherwise:

1. The progression repetition count increases if below the current entry’s threshold. Otherwise it becomes 1, the progression index increases, and that table is refreshed if required.
2. The within-group count increases. If above the current grouping entry’s second word, the position index increases, its table is refreshed if needed, and position is reread. Accumulated position becomes zero, then the within-group count becomes 1.
3. If another grouping entry exists and its first word is no greater than the position index, the grouping index increases once, with refresh if required.
4. The current progression entry’s second word is read as a signed 32-bit increment and added, with sign extension and carry, to 0xb0/0xb4.
5. Accumulated position plus the position-table value is stored in the working position slot.
6. Working size is added to accumulated position.
7. The time-like accumulator is converted.
8. Selected-item auxiliary writes are attempted.

Time conversion supplies F-1e0edc6e0bc9 with a two-word representation of the time-like accumulator multiplied by 1000 and the sign-extended divisor at 0x9c. The returned 32-bit value becomes converted time. Rounding, division semantics, and zero-divisor behavior are not established locally.

For a selected item, mode 1 writes auxiliary time, size, and position, in that order, using selection cursor minus one. Destination pointers and cursor fields are read for the respective operations; a single immutable index is not established.

Other modes call F-870c4fcf7295. Only a zero high word in its first two-word result permits writes. That result’s low word indexes the time write. Separate subsequent calls determine the size and position indices, with each corresponding write following its call.

### Final item handling: distinct progression reread

After conversion and auxiliary processing, the replay byte is read again.

- If replay is zero and the item-local suppression flag is set, working size becomes 0xffffffff. Processing returns to the visible entry without increasing payload bytes or performing the following time update.
- If replay is zero and suppression is not set, the function performs a **fresh progression-table lookup** for the time-like accumulator update.
- Any nonzero replay byte skips that time update and the suppression-sentinel branch.

The fresh lookup rereads the progression descriptor through context offset 0x30, the progression index at 0xc0, and the descriptor’s window base and data pointer at offsets 4 and 8. It reads the second word of the resulting eight-byte entry and adds that newly read signed increment to the then-current accumulator at 0xa8/0xac, using sign extension and low-word carry.

It does **not** reuse the increment previously added to 0xb0/0xb4. Conversion, auxiliary dependency calls, or aliased auxiliary writes can change the descriptor, index, table contents, or accumulator between these two lookups. No additional window-refresh check accompanies this late lookup.

On the remaining paths, the then-current working size is added to accumulated payload bytes before returning to the visible entry.

### Exit routing, trailer, and progress value

Capacity, terminal-item, status-stopping, and slot-limit exits use F-aeee487fad33. Its nonzero return replaces status; zero preserves status. Refresh failures and external-stop exits bypass this dependency.

The common trailer endpoint is output base plus capacity rounded toward zero to a multiple of four. Writes occur in this order:

1. Endpoint minus 4: constant 1.
2. Endpoint minus 8: record count.
3. Endpoint minus 12: initial timestamp.
4. After a fresh time-conversion call, endpoint minus 16: converted current time minus initial timestamp.

Next, context offset 0x88 receives the following path-dependent progress value:

|---|---|
| Any finalizer-mediated exit | Current item |
| Size-refresh failure | Current item |
| Either external-stop exit | Current item |
| Initial position-window refresh failure | Current item |
| Initial progression-window refresh failure | Next-item value established as current item plus one |
| Initial grouping-window refresh failure | Next-item value established as current item plus one |
| Progression refresh failure after progression-index advancement | Next-item value |
| Position refresh failure after position-index advancement | Next-item value |
| Grouping refresh failure after grouping-index advancement | Next-item value |

“Current item” refers to the processing value at that exit, including any earlier checkpoint restoration or entry advancement.

## Acceptance examples

These are conditional static acceptance cases, not executed tests.

1. **Exact fill.** A positive pending record that brings committed bytes exactly to capacity is written before status becomes 0. F-aeee487fad33 may replace that status. The explicit progress write uses the current item.

2. **Immediate capacity failure.** If the first working-size word is 100 and capacity is 131, with representable arithmetic, the guard returns 4. No trailer, progress write, or exit dependency follows.

3. **Cancellation timing.** With variable sizing and stop byte 1, cancellation precedes lookup and the capacity guard. With fixed sizing, cancellation can occur only at the later check, after intervening operations. Both stop exits explicitly write the current item to 0x88.

4. **Initial refresh distinctions.** For current item 25 and established next item 26, an initial progression or grouping refresh failure writes 26 to 0x88. An initial position refresh failure writes 25. Each assigns status 1 and bypasses F-aeee487fad33.

5. **Failure after advancement.** If position-index advancement requires refresh and that refresh fails, the index increment remains visible and progress receives the next-item value, not the current item.

6. **Fresh increment differs.** Suppose the first progression lookup yields increment 3. If time conversion changes the relevant entry to 7, and no other relevant state changes occur, 0xb0/0xb4 receives 3 while a permitted late update of 0xa8/0xac receives 7.

7. **Signed comparison.** A word of 0xffffffff at 0xb0 is compared as sign-extended −1 against control boundaries, irrespective of 0xb4.

8. **Deferred replay.** An outside-interval selected item with replay zero sets deferred. A later inside-interval unselected item with deferred nonzero restores the checkpoint, sets replay to 1, clears deferred, calls F-94bd82ad6ce8, and restarts selection processing without restoring the selection cursor.
