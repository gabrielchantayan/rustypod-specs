# F-6a27d653f3cc

## Purpose

F-6a27d653f3cc changes address-bearing memory through nine routing stages, a product-dependent memory phase, and external interactions. Its observable contract depends on access widths, retained values, fresh observations, and ordering under possible aliasing.

The established behavior does not identify an application-level result, a validated object layout, or an ownership transfer. Repeated cross-link and self-address installations suggest linked-storage manipulation; that interpretation is **inferred intent**, not a required data model.

Complete execution is not guaranteed. In particular, the product-dependent phase consumes a byte for which no preceding definition is established. Requirements beyond that point are conditional on meaningful continuation.

All offsets below are byte offsets. Bytes, halfwords, and words have widths of 8, 16, and 32 bits respectively. An address-bearing word is not thereby an established pointer or object reference.

## Behavior

### Observation and aliasing contract

The following are descriptive roles, not public fields:

- **Root:** the first input.
- **Region:** the address-bearing value continued between stages.
- **Carry:** the word continued between stages.
- **Selection:** the value supplied by a stage’s designated global.
- **Persistent word:** the selection-relative word retained in stage 4.
- **Link:** the region-relative word retained separately in stages 8 and 9.

Initially, region and publication address come from the additional incoming state; carry is the second input.

A retained observation continues to supply its specified operands even if its original storage changes. A required fresh observation instead sees the memory state after its ordering predecessors. Aliasing can therefore make repeated observations differ and apparently redundant writes significant.

The ordering below describes represented behavior, not atomicity, synchronization, or exact physical read multiplicity. Acquisition and publication refer to the same designated global source; an indivisible acquisition/publication transaction is not established.

### Distinguishing interference within stages 1–7

**Cross-link repairs, stages 1–2.** Root +0x54 receives the incoming cross-link after displacement acquisition and before continuation recovery. The recovered continuing region receives a selection-derived character at +0x0D.

Stage 2 additionally requires routing-base recovery after that character write. A root-value word write at cross-link address +0x54 lies between routing-base recovery and routing. The selection, recovered routing base, and continuing region are not required to coincide.

**Character routing, stage 3.** The routing character is retained before a cross-link-derived character reaches selection +0x1D. The routed halfword follows that byte effect.

**Persistent capture, stage 4.** Routing-character acquisition precedes a fresh root +0x64 observation whose word is installed at displacement-value address +0x54. An incoming-carry-derived character then reaches routing-character-value address +0x0D. The selection +0x64 observation follows these effects and precedes routing.

That selection-relative observation is the persistent word. It is distinct from the preceding root-relative observation.

**Persistent publication, stage 5.** Between routing-character acquisition and routing, the required precedence is: selection-derived character at root +0x01; incoming-carry-derived character at selection +0x0D; persistent word at selection +0x44; selection-derived character at routing-character-value address +0x0D.

The outgoing carry is still a fresh post-routing observation. It need not equal the persistent word installed earlier.

**Independent recoveries, stage 6.** Routing-base recovery precedes continuation recovery. A routing-base-derived character reaches retained-region-word address +0x0D before the routed halfword.

**Retained-word recovery, stage 7.** A selection-derived character at incoming-carry address +0x15 precedes installation of incoming carry at selection +0x44. Routing-base recovery follows both and uses retained-region-word address +0x74, not incoming-carry address +0x74.

### Link replacement in stages 8–9

Each stage retains its entering region +0x44 word as that stage’s link. Continuation recovery uses the displacement’s numerical value as the address base.

Stage 9 has additional effects between displacement acquisition and continuation recovery. In order, these are:

- Entering-region word at incoming-carry address +0x54.
- Explicit low byte of the newly retained root word at entering region +0x11.
- Selection word at link +0x44.

That explicitly extracted byte is retained for the terminal opening.

In both stages, continuation recovery precedes the link-replacement effects. The link’s self-address word at link +0x54 precedes persistent-word installation at selection plus retained incoming carry. That sum-addressed write precedes link installation at selection +0x14.

After link installation, a fresh word at persistent-word address +0x44 supplies a character for selection +0x0D. That character write precedes a link-derived character at continuing region +0x0D. Routing follows.

Replacing selection +0x14 does not replace the retained incoming carry used in the sum-addressed write. The persistent-word-relative observations in stages 8 and 9 are separate and may differ.

## Acceptance examples

These are conditional static criteria, not executed tests. They assume valid reached storage, applicable conversion semantics, and arithmetic within its valid domain.

- **Opening overlap:** If an opening byte overlaps the subsequent region-word observation, that observation incorporates the earlier byte write according to the actual byte order.
- **Negative displacement:** A displacement of −1 contributes −1, not 65535. Displacement-based continuation recovery uses that numerical address base.
- **Character interpretation:** Observed character bits 0xFF do not alone establish whether their promoted numerical value is −1 or 255.
- **Persistent-word identity:** If stage-4 root +0x64 and selection +0x64 observations differ, persistent-word consumers use the latter.
- **Fresh outgoing carry:** If stage-5 routing overlaps selection +0x44, outgoing carry reflects the post-routing word, not automatically the earlier persistent-word installation.
- **Recovery location:** If stage-7 incoming-carry +0x74 differs from retained-region-word address +0x74, the latter supplies the routing base.
- **Retained sum operand:** Replacing selection +0x14 during link replacement does not change the incoming carry already retained for sum-addressed storage.
- **Product dependence:** With factor and observation address unchanged, a different frame-value observation does not itself change the later product.
- **Repeated interference:** Overlap can make the five factor installations and the two later-product word observations independently observable.
- **Independent shifts:** The root shift by eight is not recovered by rereading the stored result of the root shift by four.
- **Dependency mutation:** If F-unknown-01 changes the late global and returns, F-cdec09f5d432 receives the later observation.
- **Undefined-before-use byte:** Acceptance must not substitute zero, invent an input, or promise continuation beyond its consumption.
