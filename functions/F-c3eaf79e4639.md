# F-c3eaf79e4639

## Purpose

F-c3eaf79e4639 constructs an object containing four supplied values, submits that object to up to two ordered dispatch mechanisms, and returns the first nonzero dispatch result. If neither mechanism produces a nonzero result, it returns zero.

The first mechanism uses iterator-related dependencies. The second traverses receivers and conditionally gates their dispatch operations. A nonzero result from the first mechanism prevents the second mechanism from running.

“Object,” “iterator,” “receiver,” “filter,” and “finalization” describe inferred roles. The established contract is the sequence of calls, memory accesses, conditions, and result propagation below. The application-level purpose is unknown.

The function returns a 32-bit integer. Nonzero dispatch results are preserved rather than normalized to a Boolean. Zero indicates that no dispatch operation on the completed path returned a nonzero result.

The first three arguments are copied without visible arithmetic or range checks. Their application-level signedness, possible address interpretation, and valid values are unknown. The fourth argument contributes one byte, not a four-byte field.

A numeric argument of 24 is supplied during acquisition. That does not independently prove the allocation size or the complete object layout. The direct writes require valid writable storage through byte offset 20.

The object’s first word is subsequently read as an indirect-call-table address. Dependencies may modify that word before later calls; the contract does not freeze the initially stored value.

### Preconditions and error model

Normal completion requires valid memory and callable entries for every executed access. In particular:

- The acquired object address must support the initial writes.
- Service results must support the fields actually read.
- Executed object and receiver operations must have valid indirect-call tables and entries.
- Iterator dependencies must accept the provided local storage.
- The unresolved receiver in the first dispatch mechanism must be valid when used.
- The associated pointer dereferenced during enabled filtering must support the nested read.

These are validity requirements, not checked errors. The function has no visible allocation-failure result, argument-validation result, or recovery protocol.

## Behavior

- The field value from the second read.

The function then repeatedly calls F-6e4651b532dc with the iterator-storage address and a separate local output address.

A zero dispatch result leads to another advance call. A nonzero result stops iteration.

- A nonzero dispatch result leads directly to object finalization.
- Exhaustion with a zero result leads to the second mechanism.

### Second mechanism: initial receiver and filtering mode

The second mechanism runs only when the first was skipped or exhausted with a zero result.

The function calls F-3fdd14ecd250 again and reads the initial receiver from byte offset 40 of this new result. It does not reuse the first service result. Calls made during the first mechanism may therefore affect the later lookup or its returned state.

The initial receiver is obtained before the filtering-mode query.

For a nonnull constructed object, the function invokes its table entry at byte offset 20 with the object as its argument. The supplied representation gives this operation a 64-bit result:

- A nonzero low 32-bit half enables filtering.
- A zero low half disables filtering.
- The high half is carried in represented traversal state but does not independently enable filtering.

The query is performed even if the initial receiver is null. An empty receiver traversal therefore does not suppress query side effects.

In the represented null-object branch, the query is skipped and filtering is disabled. That branch initializes the high half of traversal state to the numeric value 2560. Because object initialization already dereferences the acquired address, this is not an established allocation-failure recovery path.

Filtering mode is determined once. The function does not query it again for later receivers.

### Receiver selection and dispatch

At each iteration, traversal stops if the current receiver is null or the current dispatch result is nonzero.

With filtering disabled, the receiver dispatch is eligible without reading the nested filtering field.

With filtering enabled, the function reads a 32-bit pointer-like value from receiver offset 12, then reads a 32-bit value at byte offset 12 through that pointer:

- If the nested value is zero, receiver dispatch is eligible immediately.
- If the nested value is nonzero, F-35b8bd5fa9e0 is called with the constructed object.
- A nonzero result from that dependency permits receiver dispatch.
- A zero result skips dispatch and leaves the current dispatch result at zero.

There is no intervening null check on the associated pointer. With filtering enabled, a zero receiver offset-12 value is not a supported “no filter” shortcut: the nested read is attempted first.

An eligible receiver is called through its table entry at byte offset 48, with the receiver and constructed object as arguments. Its 32-bit return value becomes the current dispatch result.

A nonzero result stops traversal immediately. The function does not subsequently read that receiver’s continuation field or invoke its next-receiver operation.

### Continuation after a zero result or rejection

If dispatch returns zero, or filtering rejects the receiver, the function reads receiver offset 12 for the continuation decision.

This is a new read. Where enabled filtering previously read the same field, the earlier value is not reused. Filter and dispatch dependencies may have changed it.

If the freshly read field is zero, traversal ends. Otherwise, the function invokes the current receiver’s table entry at byte offset 28, passing the receiver.

The represented result of that call is 64 bits:

- Its low 32-bit half supplies the next receiver.
- Its high half is carried into the next iteration.

A null next receiver ends traversal at the following loop check. The carried high half does not independently select a receiver, control filtering, or determine dispatch eligibility.

There is no visible cycle detection, visited set, or iteration bound. A continuing sequence of receivers that never yields a nonzero dispatch result can prevent normal return.

### Finalization and return

After dispatch processing completes normally, the function checks the constructed object address. If it is nonnull, the function invokes its table entry at byte offset 4, passing the object.

That operation’s result is ignored. The function then returns the current 32-bit dispatch result.

No separate storage release is visible.

## Side effects

The global read is established; a direct write to that global by this function is not. Dependency calls may alter it or other application state.

2. The metadata read and offset-0 store precede the argument stores.
3. Object initialization precedes the first service lookup.
4. The first service’s offset-44 condition read precedes the separate read used for iterator initialization.

6. Iterator finalization precedes either fallback lookup or object finalization.
7. The fallback service’s offset-40 read precedes the object query.
8. The query precedes the initial receiver-null check.
9. Enabled filtering’s nested read, and any required gate call, precede receiver dispatch.
10. A nonzero receiver dispatch prevents continuation-field access.
11. Following a zero result, the continuation read occurs after the preceding gate or dispatch side effects.
12. Object finalization precedes return.

These are ordering properties of the supplied representation, not a synchronization or atomicity guarantee.

## Acceptance examples

These are conditional static acceptance criteria, not executed tests. Unless stated otherwise, required addresses and calls are valid and all invoked dependencies return normally.

1. **Acquisition changes metadata.**  
   Suppose the global metadata word initially contains one 32-bit value, but an acquisition dependency replaces it with another value that remains present at the post-acquisition read. Object offset 0 receives the latter value. Capturing the earlier value or substituting a presumed constant would not match the established behavior.

2. **Argument write widths.**  
   Initialization writes the first three arguments as 32-bit values at offsets 8, 12, and 16, then writes the fourth as one byte at offset 20. The direct initialization does not establish new values for bytes 21–23.

3. **First mechanism accepts.**  
   Given a nonzero collection condition, successful advance, valid unresolved receiver, and dispatch result 7, the function finalizes the iterator, skips the second service lookup, finalizes the object, and returns 7.

4. **Iterator exhaustion selects a fresh lookup.**  
   If an initialized iterator immediately reports exhaustion, iterator finalization precedes a second F-3fdd14ecd250 call. The fallback receiver comes from offset 40 of that second result.

5. **Empty fallback still queries.**  
   Given a nonnull object and null initial fallback receiver, the object’s offset-20 operation still executes. No traversal receiver is dispatched; finalization follows and the result is zero.

6. **Filtering disabled avoids the nested read.**  
   Given a zero low query half, a receiver is dispatched without the filtering-associated dereference. If dispatch returns zero and its subsequent offset-12 read is zero, traversal ends.

7. **Enabled filtering does not tolerate a null association by skipping it.**  
   Given a nonzero low query half and zero receiver offset-12 value, the function attempts the nested read through that value. Graceful rejection or successful return is not promised.

8. **Rejected receiver can continue.**  
   Given enabled filtering, a nonzero nested field, and a zero gate result, receiver dispatch is skipped. A nonzero freshly read continuation field still causes the offset-28 operation to run.

9. **Dispatch mutation controls continuation.**  
   If dispatch returns zero after changing receiver offset 12 to zero, the subsequent read stops traversal without invoking the next-receiver operation.

10. **Nonzero results retain their bit pattern.**  
    If dispatch returns the 32-bit representation of −3, the function returns that representation after normal finalization. It does not return one instead.
