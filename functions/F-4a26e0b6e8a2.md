# F-4a26e0b6e8a2

## Purpose

F-4a26e0b6e8a2 selects between a special cleanup operation and an iterative operation over a caller-supplied cursor. It writes a caller-supplied output slot and returns a value composed of two 32-bit components.

**Established static behavior:** The function performs preliminary dependency calls, conditionally invokes a cleanup dependency and resets several fields, or repeatedly invokes two other dependencies until a comparison dependency returns exactly 1.

**Inferred intent:** The accessed structure resembles a container with a sentinel-like header. The special path resembles whole-container cleanup; the iterative path resembles advancing a cursor before removing its former position. These interpretations do not establish the dependencies’ actual behavior, ownership rules, or abstract container semantics.

## Interface

The function has four inputs:

| Input | Established use |
|---|---|
| Output-slot address | Receives explicit 32-bit writes. Its address also initializes the low return component. |

| Cursor address | Passed to comparison and cursor-operation dependencies. Its first 32-bit word is read directly during each entered iteration. |
| Bound token | A 32-bit argument passed to the comparison dependency. The function does not directly dereference it. |

The return is 64 bits, with a 32-bit high component and a 32-bit low component. Their meanings depend on the path taken. The representation does not establish a success code, error code, public pair type, or ownership-bearing handle.

## Behavior

### Entry and preliminary comparison

Before calling a dependency, the function reads container offset 0x10 and writes that 32-bit header address to the output slot.

It then reads container offset 0x10 again and obtains the field at offset 0x08 of that header. This field value is copied into a temporary word for comparison. The header lookup is separate from the one used for the initial output write. Consequently, the initial write must be accounted for before interpreting later accesses.

The function initializes two persistent working words:

- A context word initially containing the original container address.
- A position word initially containing the output-slot address.

These working words supply the iterative return components. The position word also supplies the low component on the special path.

The first call to F-3b480a32387a receives the cursor address and the address of the temporary word containing the initial header-offset-0x08 value. That temporary is a copy, not a direct reference to the header field. A dependency write through this argument therefore changes the temporary itself, not automatically the original field.

### Special-path eligibility

A zero result from the first preliminary comparison bypasses the remaining special-path checks and leads to the iterative path.

A nonzero result causes a fresh read of container offset 0x10. The resulting address is placed in another temporary word. F-3b480a32387a is then called with the bound token and the address of that temporary word.

Only if this second comparison returns nonzero does the function read container offset 0x14. The special path is selected only when that field is also nonzero.

Thus the special-path conditions are:

- The first preliminary comparison returns nonzero.
- The second preliminary comparison returns nonzero.
- The subsequently read eligibility field is nonzero.

These are zero/nonzero tests, not positivity tests and not comparisons with 1. A 32-bit all-ones value satisfies either preliminary comparison’s nonzero test and also satisfies the eligibility-field test.

The comparison dependencies may change reachable storage. In particular, the eligibility read and later header reads are not established to observe their entry values.

### Special cleanup and ordered resets

On the special path, F-63337a3f6cce receives the original container address and the 32-bit field at offset 0x04 of the header obtained from a current read of container offset 0x10.

If the dependency returns normally, the function proceeds with the following ordered explicit writes:

| Order | Destination and value |
|---:|---|
| 1 | Header offset 0x08 receives a header address read from container offset 0x10. |
| 2 | Header offset 0x04 receives zero. |
| 3 | Header offset 0x0C receives a header address read from container offset 0x10. |
| 4 | Container offset 0x14 receives zero. |
| 5 | The output slot receives a fresh read of container offset 0x10. |

Each header destination is obtained through the container’s header-address field for that assignment. The function does not retain one header address for all resets. For the assignments that also store a header address, the supplied representation does not establish the finer evaluation order between the separate source and destination address reads.

These are post-dependency accesses. F-63337a3f6cce may have replaced the header address. Moreover, overlap between container and header storage can make one reset change the header-address field used by a later reset. The reset sequence therefore does not, by itself, establish that a single header ends with two self-references and a zero field.

The final output write can also overwrite an earlier reset. For example, an output slot at header offset 0x04 can replace that field’s zero with the final header address. An output slot at container offset 0x14 can similarly replace the cleared eligibility field.

The function returns immediately after the final output write:

- The high 32 bits contain the header-address value captured for that final write.
- The low 32 bits contain the position word, which has not been explicitly changed from the output-slot address on this path.

The high return component is the value written, not a later reread of the output slot or container field.

No loop comparison or iterative-body dependency is called after this special-path return. The eligibility field is not rechecked following F-63337a3f6cce.

### Iterative path

Every execution not returning through the special path reaches a loop comparison. This includes failure of either preliminary comparison and a zero eligibility field after two successful preliminary comparisons.

Each loop check calls F-3b480a32387a with the cursor address and bound token directly. Unlike the preliminary checks, this check terminates the loop only for a result of **exactly 1**. Zero, 2, and all other non-1 results enter the body.

For each entered iteration, the function first captures the 32-bit word at the cursor address. It then calls F-ce2e2e919fce with the cursor address. After that call returns, the captured word replaces the position working word.

F-419b965b7fec is then called with:

- The address of the context working word.
- The original container-address argument.
- The address of the position working word.

The captured position is therefore taken before F-ce2e2e919fce, even if that dependency changes the cursor word. The role suggested by the order—advance first, operate on the former position—is inferred rather than established.

Both working words are supplied through writable temporary storage. After F-419b965b7fec returns, the function writes the current context word to the output slot and performs the next loop check.

The context word is initialized once, not restored before each iteration. The position word is replaced by a newly captured cursor value in each entered iteration, after the cursor-operation call. Either word may subsequently be modified through the addresses supplied to F-419b965b7fec. The original container-address argument passed separately to that dependency remains unchanged.

### Iterative return

When a loop comparison returns exactly 1, the function returns the context word in the high 32 bits and the position word in the low 32 bits.

If no iteration ran, these remain the original container address and output-slot address, respectively, absent indirect mutation through mechanisms not specified here. The output slot has nevertheless already received the initial header address.

If iterations ran, an explicit output write followed each completed F-419b965b7fec call. However, the terminating comparison occurs after the last such write. Its side effects are unknown; it must not be assumed to preserve the output slot or any previously exposed working storage. Equality between the final output contents and the high return component is therefore conditional, not unconditional.

## Side effects

The function explicitly writes the output slot before any dependency call. It writes the slot again after special-path resets or after every completed iterative operation.

Only the special path directly resets header fields and container offset 0x14. The iterative path contains no equivalent direct structure reset.

Aliasing affects both paths. An output write overlapping cursor storage can affect the next comparison or captured cursor value. An output write overlapping container storage can affect later header lookups or dependency behavior. A special-path header write overlapping the container’s header-address field can redirect subsequent reset destinations.

There is no visible allocation request or direct memory-release operation. Cleanup, destruction, unlinking, allocation, and ownership transfer are not established from dependency calls alone.

Dependencies receive addresses of temporary words. Their use during a call is visible, but no permission to retain those addresses beyond the lifetime of the invocation is established. Nor is it established that dependencies refrain from retaining them during the invocation.

There is no explicit rollback, error-status translation, exception handling, or iteration limit. If an access faults or a dependency fails to return normally, earlier writes may already have occurred. Normal termination requires either completion of the special path or a loop comparison returning exactly 1.
