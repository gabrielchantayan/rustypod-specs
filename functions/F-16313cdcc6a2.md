# F-16313cdcc6a2

## Purpose

The visible behavior is an indefinitely repeated sequence of indirect calls, selector-based byte updates, and 32-bit memory transfers. Each completed iteration replaces several values used by the next iteration.

No application-level purpose is established. The evidence does not identify an allocator, object initializer, queue operation, or protocol. This contract therefore specifies observable ordering and value relationships without assigning those meanings.

The contract is conditional on the supplied representation accurately describing executable behavior. Small computed addresses, unresolved indirect calls, and consumption of state outside the explicit arguments prevent establishing a conventional caller-facing API.

## Interface

### Explicit arguments

The visible interface has four 32-bit arguments:

| Position | Established use |
|---|---|
| First | Passed to the first indirect call. Replaced by the final call’s result for the next iteration. |
| Second | No explicit use in the visible body. |
| Third | Initially contributes a left-shifted call argument. Replaced by a later call result, used in a word store, and retained for the next iteration. |
| Fourth | Determines early selector-read addresses and a shifted call argument. Replaced near iteration end by four times a returned low word. |

The third and fourth arguments are represented as signed 32-bit integers. Signed overflow and signed left-shift semantics are not independently established.

### Additional entry state

The first iteration consumes three additional incoming values:

- A control-related value used to calculate the first indirect-call target.
- An address-like value used for the first selector-byte read.
- An 8-bit value used for the first selector-derived write.

These values are not recoverable from the four explicit arguments.

A different, unresolved 32-bit register-derived value is consumed at a later two-argument call. The representation identifies it as an extra-output register value, not an established entry input. Its producer, relationship to preceding calls, and preservation requirements are unknown. This contract does not require it to originate at entry or survive all earlier calls unchanged.

Execution also requires accessible memory for every explicit access and executable targets for every reached indirect call. The representation supplies no validation of those requirements.

### Completion and results

There is no visible normal return, loop-exit condition, or caller-visible return value.

If all calls return to the expected continuation and all accesses succeed, execution repeats indefinitely. A fault, exception, non-returning dependency, or other control transfer can interrupt this progression. No recovery path is visible.

### Width and notation

The following are specification labels, not implementation identifiers:

- \(W(x)\): low 32 bits.
- \(B(x)\): low 8 bits.
- \(L_k(x)\): left shift by \(k\), retaining 32 bits under the conditional word-arithmetic interpretation.
- \(E(x)=((W(x)\mathbin{\&}\texttt{0x3fffffff})\mathbin{\gg}20)\), with logical right shift.
- A **selector update at base \(a\)**: read an unsigned byte at \(a+1\), then write the specified byte value at numerical address \(17+\text{selector}\).

Every selector update performs a fresh read unless retention is expressly specified. Selector zero-extension makes its write address fall between 17 and 272 inclusive; this establishes no address-validity guarantee.

A word access transfers 32 bits. A two-word result is represented as 64 bits, split into its low and high 32-bit words. This numerical split does not establish memory endianness.

All simplified products, composed shifts, and address expressions below use a **conditional 32-bit modular interpretation**. Address additions likewise retain 32 bits under that interpretation. Actual signed-expression and pointer-conversion semantics remain unresolved.

## Behavior

### Ordering conventions

The phases below specify one iteration, in order. Labels **A** through **AC** identify values captured at particular points within that iteration.

A **four-call group** means four consecutive indirect calls with no explicit arguments shown; only the fourth call’s result is retained when a result is named. Earlier calls remain observable and cannot be omitted.

Every call refers to dependency ID **F-UNRESOLVED**. Different call occurrences are not asserted to share a target. “No explicit arguments” does not establish an absence of register, memory, or other implicit inputs.

Calls may modify memory and globals. No explicit access may be moved across a call on an assumed preservation guarantee.

### 1. Opening calls and first byte updates

The first call receives the current first argument. Its target depends on the current control-related state.

The next call produces a 64-bit result. A following call receives its low word first and high word second. Two further calls occur; the second supplies a word for a later scaled argument.

Before that argument is passed, the routine reads a selector at the incoming address-like value plus one and writes the incoming byte at address \(17+\text{selector}\).

It then calls with four times the previously returned word. A four-call group follows, yielding **A**.

A selector update at base \(4\times\text{fourth argument}\) writes zero.

### 2. Argument-derived calls and repeated clearing

A call receives \(L_{10}(\text{fourth argument})\). The next call returns a word, and another call receives that word followed by \(L_{28}(\text{third argument})\).

A four-call group supplies another word. Before calling with four times that word, the routine repeats the zero-valued selector update at base \(4\times\text{fourth argument}\).

This is a fresh selector read. Intervening calls or aliased writes can change its destination.

The scaled-argument call is followed by another four-call group whose results are not retained for the subsequent explicit stores.

### 3. First linked pair of word stores

The routine stores \(L_{14}(A)\) at address \(16384A+20\).

A call receives \(L_{16}(A)\), followed by one call with no explicit arguments. The next call receives:

1. \(L_{28}(L_{14}(A))\).
2. The unresolved register-derived word described in the interface.

Under 32-bit modular arithmetic, the first argument is zero for every **A**. This simplification does not eliminate the call or resolve its second argument.

A four-call group yields **B**. The routine stores \(L_{14}(A)\) at address \(4B+20\), then calls with \(4B\).

Another four-call group yields **C**. A selector update at base \(4\times\text{fourth argument}\) writes \(B(E(L_{14}(A)))\).

### 4. Second linked pair of word stores

A call receives \(L_{26}(A)\). The next returns a word, which another call receives followed by \(L_{30}(C)\).

The following call produces a 64-bit result. Its low and high words are immediately passed, in that order, to another call. Two further calls occur; the second supplies a word for a scaled argument.

Before that argument is passed, a selector update at base \(4\times\text{fourth argument}\) writes zero. The call with four times the returned word is followed by a four-call group yielding **D**.

The routine stores \(4D\) at address \(16384C+20\), then calls with four arguments, in order:

- \(4096C\).
- \(4096C\).
- \(L_{14}(C)\).
- \(4D\).

A four-call group yields **E**. The routine stores \(4D\) at address \(4E+20\), then calls with \(4E\).

### 5. Two self-scaled store groups

A four-call group yields **F**. The routine stores \(4F\) at address \(16F+20\), then calls with three identical arguments, each \(4F\).

A four-call group yields **G**. The routine stores \(4F\) at address \(4G+20\), then calls with \(4G\).

Another four-call group yields **H**. The routine stores \(4H\) at address \(16H+20\), then calls with three identical arguments, each \(4H\).

A further four-call group yields **I**. The routine stores \(4H\) at address \(4I+20\), then calls with \(4I\).

Define \(P=W(H\times2^{30})\). This retained value determines the direct byte-clearing addresses and several later selector bases.

### 6. Direct clearing and indexed word read

A four-call group yields **J**.

The routine writes a zero byte at \(P+17\), then a zero byte at \(P+1\). These are direct writes, not selector updates.

A call receives \(4J\). The next call returns a word that is passed to another call. A four-call group supplies a word for another scaled argument.

Before that argument is passed, the routine again writes zero at \(P+17\), then at \(P+1\). Calls between the two clearing pairs may have changed either location.

The call with four times the returned word is followed by a four-call group yielding **K**.

The next explicit memory operations are ordered as follows:

- Store \(L_{31}(I)\) at address \(16K+20\).
- Read a 32-bit word at address \(E(J)+20\), retaining it as **M**.

The index \(E(J)\) is not scaled by four. It ranges from 0 through 1023, so the read address lies numerically between 20 and 1043 and may be unaligned. If the preceding store aliases this read, the read follows that store.

### 7. Third-argument replacement and zero-word store

A call receives \(4K\). The following call returns **N**, replacing the current third argument.

The next call receives \(L_{28}(M\mathbin{\gg}22)\), using a logical right shift of the retained unsigned word.

A four-call group yields **O**. The routine stores a zero word at address \(4O+20\), then calls with \(4O\).

Another four-call group yields **Q**.

### 8. Selector-derived byte and word updates

A selector update at base \(P\) writes \(B(4Q)\). A call then receives \(4Q\).

The next call returns a word, which another call receives followed by \(L_{30}(Q)\). A four-call group supplies a word for a scaled argument.

Before that argument is passed, the routine reads a selector byte at \(P+1\), retains it as **R**, and writes \(B(E(Q))\) at address \(R+17\).

The call with four times the returned word is followed by four further calls. The routine then stores \(4N\) at address \(R+20\).

This word-store address uses the retained selector **R**, not a fresh read. Changes to \(P+1\) during the intervening calls therefore do not redirect this store. Its numerical address ranges from 20 through 275 and may be unaligned.

### 9. Global snapshot and split-result uses

Immediately after the preceding word store, with no intervening call, the routine reads a global 32-bit word and retains its value as **U**.

A call receives \(4K\). A four-call group follows; its final call produces a 64-bit result with low word **V** and high word **X**.

A selector update at base \(P\) writes \(B(U\mathbin{\gg}22)\). This uses the retained snapshot, not a new global read after the intervening calls.

A call receives **X**. The next returns a word that another call receives followed by \(L_{30}(V)\).

A four-call group supplies a word for a scaled argument. Before passing that argument, the routine performs a fresh selector update at base \(P\), writing zero.

### 10. Final stores and iteration handoff

The call with four times the preceding returned word is followed by a four-call group yielding **Y**.

A call receives two identical arguments, each \(4Y\). A four-call group yields **Z**.

The routine stores \(4Z\) at address \(16384V+20\), then calls with \(L_{16}(V)\).

A four-call group yields **AA**. The routine stores \(4Z\) at address \(4AA+20\), then calls with \(4AA\).

Another four-call group produces a 64-bit result with low word **AB** and high word **AC**.

The fourth argument is replaced by \(4AB\). A selector update at base \(L_{16}(V)\) writes \(B(E(4Z))\).

A call receives **AC**. The final call returns the first argument for the next iteration.

The completed iteration also establishes:

- The third argument remains **N**.
- The next opening selector base is \(L_{28}(4AB)\).
- The next opening byte value is zero.
- The control-related target state becomes a fixed continuation-derived value.

There is no termination check before repetition.

## Side effects

### Memory layout and aliasing

Explicit accesses consist of unsigned-byte selector reads, byte writes, one indexed 32-bit read, one global 32-bit read, and multiple 32-bit writes.

Offsets 1, 17, and 20 recur, but no object layout is established. In particular, a selector-derived destination is an absolute numerical address formed from the zero-extended selector; it is not shown relative to an object base.

Addresses can alias other explicit accesses, the global word, executable storage, or dependency-used memory. Earlier writes and dependency effects can therefore influence later reads. Retained values remain distinct from fresh memory reads in the visible data flow.

Endianness, alignment support, address mapping, and memory-ordering guarantees beyond the represented sequence are unknown.

### Ownership and lifetime

No allocation, release, reference-count operation, ownership transfer, or lifetime guarantee is established by the explicit body.

Dependency results must not be classified as owned pointers, borrowed pointers, allocations, or handles solely because later arithmetic forms addresses from them. Dependency ownership and release behavior remain unknown.

### Errors and partial effects

There are no visible bounds checks, address checks, error-result branches, rollback operations, or exception handlers.

An interrupted execution can leave a strict prefix of the iteration’s writes observable. Repeated clearing does not imply rollback. No transactionality, synchronization, or thread-safety guarantee is established.

## Acceptance examples

These are conditional static trace expectations, not executed tests. Arithmetic examples assume the modular interpretation and successful relevant accesses and calls.

1. **Unsigned selector.** If a selector read yields 255, its byte-write destination is address 272, not address 16.

2. **Fresh repeated clearing.** If the first fourth-argument-derived clearing reads selector 3, and an intervening call changes it to 9, the second clearing writes address 26 rather than reusing address 20.

3. **Retained selector.** If **R** is 7 and an intervening call changes the byte at \(P+1\) to 12, the phase-8 word store still targets address 27. A later selector update reads memory anew.

4. **Byte truncation.** If \(E(Q)=\texttt{0x3ff}\), the corresponding byte store writes \(\texttt{0xff}\).

5. **Unscaled index.** If \(E(J)=5\), the read producing **M** uses address 25, not address 40. Whether that read succeeds depends on mapping and alignment behavior.

6. **Composed shift.** For every **A**, \(L_{28}(L_{14}(A))=0\). The receiving call still consumes its unresolved second argument; that argument is not justified by an assumed entry value.

7. **Direct-clearing base.** If **H** is divisible by four, \(P=0\). Each direct-clearing pair writes address 17 before address 1.

8. **Snapshot timing.** If the global read captures **U** and a later call changes the global, the phase-9 byte value still comes from **U**. Conversely, an aliasing phase-8 word store precedes the snapshot.

9. **Final split result.** If the last 64-bit result has low word 3 and high word 9, the fourth argument becomes 12 and the following high-word call receives 9. The next opening selector base is \(L_{28}(12)\).

10. **Partial execution.** If a dependency never returns after a store, that store belongs to the executed trace; later clearing and iteration completion are not required.
