# F-c5b4e5c64260

## Purpose

F-c5b4e5c64260 checks two supplied records against a mutable context, passes the records to an external dependency, initializes context fields, and invokes one or two processing passes.

Its observable outcomes distinguish several paths:

- `0x60`: the context pointer or one of two required context fields is zero.
- `0`: an early record condition declines processing, or all selected processing passes return zero.
- `0x14`: a later record or required-pointer check fails.
- `0x13`: an option check suppresses further work.
- Any nonzero processing result: returned unchanged.

The two suppression checks occur at different stages. One prevents the record-transfer calls; the other occurs after both calls. Neither zero nor `0x13` alone establishes whether the context or other memory changed.

“Record transfer,” “precision,” and “processing pass” are descriptive terms. The body establishes calls, field operations, and decisions, not the complete domain meaning of those operations.

## Interface

### Arguments and result

The function accepts four machine-level arguments:

| Argument | Established use |
|---|---|
| Context address | Mutable storage accessed through 32-bit words and selected byte and halfword accesses |
| Argument-record address | Supplies two 32-bit pointer representations and an option word |
| Third argument | A 32-bit integer whose incoming value does not affect a defined return path |
| Fourth argument | A 32-bit integer whose incoming value does not affect a defined return path |

The result is a 32-bit unsigned value. Nonzero results from F-c1d186dbeef6 are propagated without translation, so those results may overlap the function’s own status values.

### Argument-record layout

All offsets are byte offsets.

| Offset | Width | Meaning |
|---|---:|---|
| `0x00` | 32 bits | Primary-record pointer representation |
| `0x04` | 32 bits | Secondary-record pointer representation |
| `0x08` | 32 bits | Option flags |

Both pointer fields are read even on a context-rejection path. The option word is read only after secondary-record validation and is read again after the record-transfer calls.

### Record layouts

The secondary record has these directly accessed fields:

| Offset | Width | Meaning |
|---|---:|---|
| `0x00` | Signed 16 bits | Count |
| `0x02` | Signed 16 bits | Target value |
| `0x04` | 32 bits | Required nonzero pointer representation |
| `0x0C` | 32 bits | Pointer to signed-16-bit terminal-index storage |

The primary record has a directly checked 32-bit field at offset `0x0C`, which must be nonzero on the transfer path.

An external dependency receives the secondary-record address with a length argument of 20 and the primary-record address with a length argument of 24. These arguments do not establish copying, ownership, or the full storage requirements of either record.

### Memory preconditions

The argument record must permit its first two word reads even when the context is null.

After the context gate passes, the secondary record must permit a halfword read at offset `0x02`. A later explicit null comparison does not protect this earlier access. A null secondary-record pointer therefore does not have an established safe numeric-error outcome.

Paths reaching initialization require context storage through the 32-bit field at `0x404`, giving a directly accessed extent of at least `0x408` bytes. Dependencies may require more.

The second-pass decision includes a guarded **32-bit read at context offset `0xB8`**, spanning offsets `0xB8` through `0xBB`. This is distinct from the earlier byte-sized write at `0xB8`.

The evidence uses 32-bit pointer representations, 32-bit words, 16-bit halfwords, and 8-bit byte fields. It does not establish alignment allowances, memory-fault recovery, or portability to other pointer widths.

## Behavior

### Context gate and pointer capture

The initial access order is:

1. If the context address is nonzero, read its word at `0x20`.
2. Only if the context address and that word are nonzero, read its word at `0x24`.
3. Read the primary-record pointer from argument-record offset `0x00`.
4. Read the secondary-record pointer from argument-record offset `0x04`.
5. Return `0x60` if the context address, word `0x20`, or word `0x24` is zero.

No dependency call or direct context write precedes this return. An unreadable argument record can nevertheless prevent the intended return because its pointer fields are accessed first.

### Early no-processing decision

Read the signed-16-bit target at secondary-record offset `0x02` and sign-extend it into a 32-bit unsigned representation.

- If the target is zero, return zero without reading the count.
- Otherwise, read the signed-16-bit count at offset `0x00`.
- If the count is zero or negative, return zero.

These paths perform no dependency calls and no direct context writes. They are not structural-error returns.

### Secondary-record validation

For a positive count, read the array pointer at secondary-record offset `0x0C`. Only when that pointer is nonzero is the required pointer representation at `0x04` read.

Return `0x14` if either required pointer representation is zero. Otherwise, read the signed-16-bit terminal entry at array index count minus one.

The terminal comparison is:

- Sign-extend the terminal entry.
- Add one using 32-bit unsigned arithmetic.
- Compare against the previously sign-extended, unsigned target.

A mismatch returns `0x14`.

The positive count ranges from 1 through 32,767. The terminal-entry byte displacement is twice the count minus two, ranging from zero through 65,532. Address overflow and memory accessibility are not checked.

Negative targets are not categorically rejected. Target `−2` and terminal entry `−3` satisfy the comparison. Target `−32768` cannot satisfy it. Terminal entry `32767` produces 32,768, which cannot match the converted representation of any signed-16-bit target. A zero target has already exited before this comparison.

### First option check and primary-record validation

Read the option word at argument-record offset `0x08`.

If mask `0x02` is set, return `0x13`. This path does not dereference the primary record and does not invoke the record-transfer dependency. It still requires successful secondary-record validation.

Otherwise, require a nonzero primary-record pointer. If nonzero, read its word at offset `0x0C`; require that word to be nonzero as well. Either failure returns `0x14`.

These checks establish nonzero representations, not validity of the memory to which those representations may refer.

### Record-transfer calls and second option check

Invoke F-unknown-transfer twice, in this order:

| Call | Destination | Source | Length argument |
|---|---|---|---:|
| First | Context plus `0x84` | Secondary record | 20 |
| Second | Context plus `0x6C` | Primary record | 24 |

Neither return value is used.

After both calls, read the option word again. If mask `0x01` is set in this new observation, return `0x13`.

The second decision is not based on a saved option value. Dependency mutation or aliasing can change the option word between reads. Mask `0x02` is not retested at this point.

Both transfer calls precede the second suppression decision. Consequently, suppression by mask `0x01` does not guarantee unchanged context or unchanged external state.

### Mode-dependent initialization

Read context word `0x94` and test mask `0x100`. Use that single observation to make these 32-bit writes, in order:

| Offset | Mask clear | Mask set |
|---|---:|---:|
| `0x00` | 6 | 10 |
| `0x14` | 32 | 128 |
| `0x18` | 2 | 24 |

Then access the externally supplied verbosity-control pointer and read the signed-32-bit value at its offset `0x28`.

If that value exceeds 5, read context word `0x94` again, select one of two text arguments according to mask `0x100`, and invoke F-4457a9a44a68 with a fixed format argument and the selected text argument.

This is consistent with a precision-setting diagnostic. The dependency’s actual output and other effects are not established. Its fresh mode observation need not match the earlier observation if intervening effects change the context.

### Scale fields

After the optional diagnostic call:

1. Read context word `0x00`; its low eight bits supply the shift count for a 32-bit value of one.
2. Write the resulting value at `0x04`.
3. Read word `0x00` again and subtract six using 32-bit unsigned arithmetic.
4. Write the unsigned negation of the shift result at `0x0C`.
5. Write the subtraction result at `0x10`.
6. Write the result of signed division of the shift result by two at `0x08`.
7. Write the saved subtraction result at `0x1C`.

Absent intervening mutation of the relevant field, the results are:

| Offset | Initial mode mask clear | Initial mode mask set |

| `0x04` | 64 | 1,024 |
| `0x0C` | `0xFFFFFFC0` | `0xFFFFFC00` |

The supplied body does not establish a portable result for arbitrary abnormal shift counts introduced by dependency mutation.

### First-pass preparation

Preparation continues in this order:

- Write byte value 2 at context offset `0xB8`.
- Read word `0x94`, extract bit 9, invert that bit, and write the resulting zero-or-one byte at `0xB9`.
- Read and write the first set of four external 32-bit constants into `0xA8`, `0xAC`, `0xB0`, and `0xB4`, in that order.
- Write 32-bit zero at `0x404`.
- Write 16-bit zero at `0x3C4`.
- Read word `0x6C`; write its low 16 bits minus one, retaining 16 bits, at `0x3C6`.
- Read word `0x70`; write its low 16 bits at `0x3C`.
- Read word `0x78`; write its 32-bit value at `0x40`.

The byte write at `0xB8` does not initialize the entire word later read there. Likewise, writes at `0xB9`, `0x3C4`, `0x3C6`, and `0x3C` affect only their stated widths.

The relationship between fields `0x6C`, `0x70`, and `0x78` and the supplied primary record depends on F-unknown-transfer. A byte-copy interpretation is not required by the available evidence.

### First processing pass

Invoke F-c1d186dbeef6 with the context and selector zero.

If it returns nonzero, return that value unchanged. No second-pass decision reads or preparation occur.

There is no rollback of prior writes or dependency effects.

### Second-pass decision and execution

After a zero result from the first processing pass:

1. Read the byte at context offset `0xB9`.
2. If that byte is zero, return zero without reading the word at `0xB8`.
3. Otherwise, read the **32-bit context word at `0xB8`**.
4. Convert that word to an 8-bit character value and test the converted value for nonzero.
5. If the converted value is zero, return zero.

The second test is not a direct byte read at `0xB8`, nor is it a test of the full word for nonzero. It is a word read followed by truncation to the low eight value bits. The character type’s signedness does not change whether that converted value is zero.

Both observations occur after F-c1d186dbeef6 returns. That dependency may have changed either relevant storage region. The earlier byte initialization does not determine the eventual decision.

If both tests pass:

- Read and write the second set of four external 32-bit constants into `0xA8`, `0xAC`, `0xB0`, and `0xB4`, in order.
- Write 32-bit zero at `0x404`.
- Write 16-bit zero at `0x3C4`.
- Read word `0x70`; write its low 16 bits minus one, retaining 16 bits, at `0x3C6`.
- Invoke F-c1d186dbeef6 with selector one.

Return the second call’s nonzero result unchanged, or zero if it returns zero. The earlier writes to `0x3C` and `0x40` are not repeated.

## Side effects

Direct context mutation begins only after both record-transfer calls and the second option check.

External effects may occur through either transfer call, the optional diagnostic call, or either processing call. Their scope is unknown. No dependency is assumed to preserve globals, preserve context fields, retain no addresses, or refrain from allocating or releasing memory.

The function body contains no direct allocation, deallocation, ownership-transfer operation, or rollback. Passing addresses to dependencies does not establish their ownership contracts.

Aliasing is not rejected. Overlap among the context, argument record, supplied records, or externally supplied data can make earlier writes affect later reads. The specified access order therefore matters independently of ordinary non-overlapping use.

Invalid-memory accesses, dependency exceptions, and nonlocal exits are outside the established numeric-return contract.

## Acceptance examples

These are conditional static expectations, not executed tests. Unless stated otherwise, required accesses are valid and dependencies return normally.

1. **Null context.** With a readable argument record, both record-pointer fields are read before return `0x60`. Neither supplied record is dereferenced.

2. **First context field zero.** If context word `0x20` is zero, word `0x24` is not read. Argument-pointer capture still occurs before return `0x60`.

3. **Zero target.** After a successful context gate, secondary target zero returns zero without reading the count, calling dependencies, or directly writing context.

4. **Negative count.** A nonzero target with count `−1` returns zero without reading the terminal-array pointer.

5. **Terminal mismatch.** Count 3, target 5, and terminal entry 3 produce `0x14`, because the compared incremented entry is 4.

6. **Negative matching values.** A positive count, nonzero required pointers, target `−2`, and terminal entry `−3` pass terminal validation. Later gates still apply.

7. **First suppression bit.** After successful secondary validation, option mask `0x02` returns `0x13` without primary-record dereference or transfer calls.

8. **Second suppression bit.** With valid records and mask `0x01` set on the second option read, both transfer calls occur before return `0x13`. No processing call occurs.

9. **Changed options.** If both initial option masks are clear but a transfer dependency sets mask `0x01`, the second option read observes it and suppresses initialization.

10. **First-pass failure.** A first processing result of `0x2A` is returned unchanged, without reading byte `0xB9` for second-pass selection.

11. **Guarded word read.** If the first pass succeeds and byte `0xB9` is zero, return zero without reading the word spanning `0xB8` through `0xBB`.

12. **Truncation, not full-word truth.** If byte `0xB9` is nonzero and the word read at `0xB8` has value `0x00000100`, its character conversion is zero. No second pass occurs despite the nonzero word.

13. **Nonzero truncated value.** If byte `0xB9` is nonzero and the word read at `0xB8` has value `0x00000102`, the converted value is nonzero. Second-pass preparation and selector-one processing occur.

14. **Halfword decrement wrapping.** If the relevant source word’s low 16 bits are zero, the preparation write at `0x3C6` stores `0xFFFF`.
