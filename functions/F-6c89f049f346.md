# F-6c89f049f346

## Purpose

F-6c89f049f346 interprets an unsigned selector and updates selected fields of a caller-supplied output object. Depending on the selector, it:

- Decodes a fixed-width, big-endian integer.
- Records an eight-byte representation and classifies it through F-c87e8125aeb8.
- Produces one of two constant integer values.
- Writes only a type/status marker.
- Records an input address and a selector-derived length without reading the referenced payload.

Its return value is a 32-bit unsigned quantity. For fixed-width decoding branches, it equals the number of input bytes read. For other branches, it is either zero or a length derived from the selector. It is not established as a success/error indicator.

The names “type/status marker,” “integer,” and “descriptor” describe observed field use. Their application-level meanings are not established.

## Behavior

### Selectors 0, 10, and 11: marker-only result

These selectors write the 16-bit value 1 at offset 28 and return zero.

They do not directly read input bytes or write any other output field. Existing numeric words and descriptor fields remain untouched by the displayed function.

### Selectors 1 through 4: integer decoding

These selectors read exactly the selected number of input bytes and construct a numeric result. They then write:

1. The low 32-bit word at offset 0.
2. The high 32-bit word at offset 4.
3. The 16-bit marker value 4 at offset 28.

They return the number of bytes read.

The interpretation is selector-specific:

- **Selector 1:** Interpret the input byte as signed eight-bit data and sign-extend it. The low word contains its 32-bit sign extension. The high word is all zero bits for a nonnegative value and all one bits for a negative value.
- **Selector 2:** Combine the first byte as the most significant byte and the second as the least significant byte of a 16-bit quantity. The displayed expression does not sign-extend that quantity from 16 bits. The low word is in the range 0 through 65,535; the high word is zero.
- **Selector 3:** Interpret three bytes in big-endian order with signed 24-bit behavior. The first byte supplies the sign. The low word is the resulting 32-bit sign extension; the high word repeats its sign.
- **Selector 4:** Combine four bytes in big-endian order into a 32-bit bit pattern. The low word contains that pattern. The high word is zero when bit 31 is clear and all one bits when bit 31 is set.

Selector 2 therefore differs materially from a conventional signed, variable-width integer decoder. A two-byte input with its top bit set still produces a nonnegative result.

### Selector 5: six-byte decoding

This selector reads six input bytes.

- The first two bytes form an unsigned, big-endian 16-bit quantity stored as the high 32-bit word.
- The following four bytes form a big-endian 32-bit quantity stored as the low word.

The output writes occur in this order:

1. Low word at offset 0.
2. High word at offset 4.
3. Marker value 4 at offset 28.

The function returns 6.

The upper 16 bits of the stored high word are zero. The displayed behavior does not sign-extend a negative 48-bit value. Interpreted as a combined high/low numeric pair, the result ranges from zero through 281,474,976,710,655.

### Selector 6: eight-byte integer decoding

This selector reads eight bytes in big-endian order:

- Bytes 0–3 form the high 32-bit word.
- Bytes 4–7 form the low 32-bit word.

After both words have been assembled, the function writes the low word at offset 0, the high word at offset 4, and marker value 4 at offset 28. It returns 8.

The complete 64-bit input pattern is retained in the pair of words. The displayed operations alone do not establish whether consumers interpret that pair as signed or unsigned.

### Selector 7: eight-byte representation and classification

This selector assembles the same two big-endian words as selector 6, but uses different output fields and invokes a dependency.

The observable sequence is:

1. Read and assemble all eight input bytes.
2. Write the low word at offset 8.
3. Write the high word at offset 12.
4. Call F-c87e8125aeb8 with the low word first and the high word second.
5. After the call returns, write the marker at offset 28:
   - 8 if the dependency returned zero.
   - 1 if the dependency returned any nonzero value.
6. Return 8.

The function itself does not write offsets 0 or 4 on this branch.

The marker is written after the dependency call. The function does not subsequently rewrite the representation words. Their final contents therefore depend on whether the dependency can affect the output storage through some other means.

### Selectors 8 and 9: constant numeric results

Both selectors perform the following writes:

1. At offset 0, write zero for selector 8 or one for selector 9.
2. At offset 4, write zero.
3. At offset 28, write marker value 4.

Both return zero and do not directly read input bytes.

A zero return therefore does not imply that no meaningful output was produced.

### Selectors 12 and above: address-and-length descriptor

Every selector not handled above reaches this branch. Because selectors 0 through 11 are explicitly handled, its selector range is exactly 12 through 4,294,967,295.

The branch derives a length by subtracting 12 in unsigned 32-bit arithmetic and then shifting right by one bit. Within this branch the subtraction cannot underflow. The resulting length ranges from zero through 2,147,483,641.

Its direct effects occur in this order:

1. Store the supplied input address, converted to an unsigned 32-bit representation, at offset 20.
2. Determine whether the selector is odd and compute the derived length.
3. For an odd selector, evaluate a global datum used as an address-valued source for the marker.
4. Store the derived length at offset 24.
5. Write zero at offset 32.
6. Write the 16-bit marker at offset 28.
7. Return the derived length.

The marker depends on selector parity:

- **Even selector:** marker is 272, equivalently hexadecimal 0110.
- **Odd selector:** marker is the low 16 bits of the global address-valued datum.

The input address stored at offset 20 is the original supplied address for both parities. The odd-selector marker calculation does not replace that stored address with the global value.

This branch does not directly read any bytes through the input address and does not copy the referenced payload. Adjacent even/odd selectors share the same derived length: selectors 12 and 13 yield zero, selectors 14 and 15 yield one, and so on.

## Side effects

### Partial output updates

The function performs branch-specific stores only. Directly unwritten output bytes retain their prior contents unless an external effect changes them.

In particular:

- Marker-only branches do not clear prior values.
- Numeric branches do not initialize the representation or descriptor fields.
- Selector 7 does not initialize the ordinary numeric fields.
- Descriptor branches do not initialize either numeric pair.
- No displayed store covers bytes 30–31.

Consumers must not treat the result as a fully cleared object.

### Read/write ordering and overlap

For selectors 1 through 7, all input bytes needed by the branch are read before its first direct output store.

Two read sequences are explicitly separated in the supplied representation:

- Selector 2 reads byte 1 before byte 0.
- Selector 5 reads byte 1, then byte 0, before assembling the remaining four-byte word.

The order of separate byte reads appearing within a compound expression is not fully established by the supplied evidence. The contract does not impose left-to-right access for those expressions.

The read-before-store structure may matter when input and output storage overlap. It does not establish general overlap safety, especially where the dependency or global storage could also alias affected memory.
