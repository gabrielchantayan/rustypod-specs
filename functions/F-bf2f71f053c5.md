# F-bf2f71f053c5

## Purpose

For a valid execution that completes normally, the returned value is the field’s value **after the selected operation returns**. The field’s value at function entry does not determine the result if the operation changes it. An initially zero field does not suppress invocation.

## Behavior

### Invocation contract

The initial dispatch read and target-entry read select one operation. That operation receives the original caller-supplied pointer as its sole visible argument.

There is one selected invocation on the ordinary path. The result-bearing field is not consulted to decide whether invocation occurs. In particular, zero in that field does not constitute an early-return condition.

The target is selected before it executes. Changes made by the target to dispatch storage or the target entry do not trigger reselection during the current call. Such changes may affect a later call, but that later call must independently satisfy all access and arithmetic requirements.

For this document, the unresolved dependency is referenced as **F-indirect-01**. This is a local opaque reference, not an assertion that the supplied material identifies a concrete target.

### Result and clearing contract

After F-indirect-01 returns normally, F-bf2f71f053c5 reads the result-bearing field through the original input pointer. That post-call value determines the result.

The same field is then assigned signed-integer zero before normal return. This assignment is unconditional on the ordinary path, including when the captured value is already zero.

The returned value must survive the clear. For a nonzero captured value, returning the subsequently cleared contents would violate the contract.

The selected operation’s own return value is not visibly used. There is no branch based on that value. Consequently, an externally defined failure indication returned normally by the dependency does not, by itself, suppress extraction or clearing.

This does not guarantee that a dependency reporting failure leaves the object usable. Valid post-call access remains a separate requirement.

### Storage identity and lifetime

The fragment does not establish exception handling, signal handling, nonlocal recovery, or a fallback result.

Invalid dispatch arithmetic, an unusable converted address, inaccessible target storage, or an incompatible callable target has no specified successful outcome. There is no wrapping-address contract for signed overflow.

Likewise, an invalid post-call read does not establish that clearing occurs. An unsuccessful clear does not establish normal return. No general preservation guarantee can be assigned to an invalid execution.
