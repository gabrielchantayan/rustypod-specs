# F-2eeb079272cf

## Purpose

F-2eeb079272cf conditionally inserts a signed 32-bit value into a sequence of 32-bit entries whose storage grows toward lower addresses.

For a valid, nondecreasing input sequence, the established behavior is:

- If an equal entry is found, return zero without changing the sequence or its metadata.
- Otherwise, insert the supplied value while preserving nondecreasing order, provided the storage-boundary check succeeds.
- If that check fails, record the 32-bit status value 98 and return one.

The failure path is not transactional. Entries may already have been overwritten before the boundary check. A failed insertion can therefore leave the sequence contents changed even though its recorded count is unchanged.

The interpretation as sorted insertion is inferred intent. The reads, writes, comparisons, and return behavior below are established by the supplied static evidence.

## Interface

### Inputs

The function takes two inputs:

1. **State address:** a 32-bit address identifying a writable state object.
2. **Candidate value:** a signed 32-bit integer.

The state object exposes these fields:

| Byte offset | Width | Role established by access |
|---|---:|---|
| +0x24 | 32 bits | Address used as the exclusive high-address end of the sequence |
| +0x28 | 32 bits | Cursor or accounting value, reduced by four on an insertion attempt |
| +0x2C | 32 bits | Boundary compared with the updated cursor using unsigned ordering |
| +0x30 | 32 bits | Status field written with 98 on boundary failure |
| +0x34 | 32 bits | Entry count, interpreted as signed during the search |

The precise ownership and broader meanings of these fields are not established. In particular, the evidence does not prove that the field at +0x28 is a pointer into the same storage described by +0x24.

### Sequence layout

Let:

- **E** be the initial 32-bit address read at +0x24.
- **N** be the initial signed 32-bit count read at +0x34.
- **B** be the computed address E − 4N.

For a normal nonnegative count, the existing entries occupy N consecutive four-byte slots starting at B. Their addresses are B, B + 4, and so on through E − 4.

On successful insertion, the count increases by one and a value is written at E − 4(N + 1). Thus the sequence gains a slot immediately below its previous low-address end; its high-address end remains fixed unless aliasing changes that field.

### Outputs

The result is a 32-bit integer:

| Result | Meaning |
|---:|---|
| 0 | Either an equal value prevented insertion, or insertion completed |
| 1 | The updated cursor was less than or equal to the boundary under unsigned comparison |

The return value alone does not distinguish successful insertion from an equal-value no-op.

### Preconditions for the ordinary insertion contract

The sorted-insertion interpretation requires:

- A nonnegative count.
- Existing entries in nondecreasing signed 32-bit order from low address to high address.
- Readable state fields and readable existing entry slots.
- Writable slots for every overwrite actually performed.
- On a successful insertion path, a writable new slot immediately below the existing sequence.
- Address and count arithmetic that remains meaningful on the target platform.
- No unintended overlap between sequence storage and state metadata.
- No concurrent modification of the accessed state.

There are no explicit checks for null addresses, storage accessibility, sortedness, or valid counts.

## Behavior

### Search and equal-value handling

The initial reads obtain the count and the sequence-end address. The function computes the existing sequence’s low-address end from those values.

It searches from the highest-index entry toward the lowest-index entry. Each entry is compared with the candidate using signed 32-bit ordering.

Entries strictly greater than the candidate are passed over. The search stops when either:

- An entry less than or equal to the candidate is found; or
- The search moves below the first entry.

When a stopping entry exists, that entry is read again to determine whether it is strictly less than the candidate.

If it equals the candidate, the function returns zero immediately. It does not decrement the cursor, inspect the boundary, update the count, or clear or set the status field.

Consequently, for a valid sorted sequence, an existing equal value suppresses insertion even when the cursor is already at an exhausted boundary.

The scan is not a general duplicate search for unsorted data. An equal value elsewhere in an unsorted sequence need not be reached before a smaller entry stops the scan.

### Rewriting the lower-address prefix

If the stopping entry is strictly less than the candidate, the function rewrites the prefix from that entry backward toward the first entry.

The candidate is written into the stopping entry’s slot. Each successive lower-address slot receives the value displaced from its higher-address neighbor. Before each such write, the slot’s prior contents are read and retained for the next step.

After the first slot has been processed, its original value becomes the value to place in the prospective new low-address slot.

Entries passed over during the initial search are not rewritten. They remain in their original slots.

For a sorted sequence, this operation makes room for the candidate in its proper ordered position, but it does so before determining whether the additional slot is permitted.

If the scan passed below the first entry without finding an entry less than or equal to the candidate, there is no prefix rewrite. The candidate itself remains the value intended for the new low-address slot.

An empty sequence takes this latter path without reading any entry.

### Cursor update and boundary decision

Every path that attempts insertion next performs these actions in order:

1. Read the 32-bit field at +0x28.
2. Subtract four and write the resulting 32-bit value back to +0x28.
3. Read the boundary field at +0x2C.
4. Compare the updated cursor with the boundary using unsigned 32-bit ordering.

The insertion is rejected when the updated cursor is **less than or equal to** the boundary. Equality is a failure, not an accepted final position.

On this failure path:

- The field at +0x30 is written with the 32-bit value 98.
- The function returns one.
- The count is not incremented by the count-update operation.
- The prospective new low-address entry is not written.
- The cursor decrement remains in effect.
- Any prefix rewrites already performed remain in effect.

There is no rollback.

### Completing an insertion

If the updated cursor is strictly greater than the boundary under unsigned comparison:

1. The count field at +0x34 is read again.
2. One is added to that count.
3. The increased count is written to +0x34.
4. The end-address field at +0x24 is read again.
5. The retained insertion value is written at the address obtained by subtracting four times the increased count from that end address.
6. The function returns zero.

The final address calculation uses the reread count and end-address fields, rather than relying exclusively on their initial values.

No success-path write clears or replaces the status field at +0x30. A status value left by an earlier failure therefore persists unless some other actor changes it.

### Integer and ordering distinctions

The following distinctions are material:

- Candidate-to-entry comparisons use signed 32-bit ordering.
- Search termination uses a signed comparison with zero.
- The cursor-to-boundary comparison uses unsigned 32-bit ordering.
- Entry width and slot spacing are four bytes.
- The cursor changes by four, not by one.
- The count changes by one only after the boundary check succeeds.
- The failure status is decimal 98, represented in a 32-bit field.

The cursor subtraction stores a 32-bit result. A cursor below four can therefore produce a high unsigned value after subtraction. There is no separate underflow rejection; the subsequent unsigned comparison determines the branch.

The evidence does not establish a portable contract for overflowing signed count arithmetic or overflowing address calculations.

## Side effects

### State changes

For ordinary nonoverlapping state and sequence storage:

| Path | Cursor | Count | Status | Sequence |
|---|---|---|---|---|
| Equal entry found | Unchanged | Unchanged | Unchanged | Unchanged |
| Insertion succeeds | Reduced by four | Increased by one | Unchanged | Updated to include candidate |
| Boundary failure, no prefix rewrite | Reduced by four | Unchanged | Set to 98 | Existing entries unchanged |
| Boundary failure after prefix rewrite | Reduced by four | Unchanged | Set to 98 | Prefix changes remain |

These outcomes are not interchangeable. In particular, return one does not imply that the original sequence remains intact.

### Observable access order

The significant ordering constraints are:

- The initial count is read before the initial end-address read.
- Search reads precede any insertion-related cursor update.
- A found stopping entry is read again for the strict-less-than decision.
- Prefix entries are read and then overwritten while traversing toward lower addresses.
- All prefix rewrites occur before the cursor is decremented.
- The cursor write occurs before the boundary read.
- On failure, the status write follows the failed boundary comparison.
- On success, the count update precedes the end-address reread and final entry write.

These distinctions matter if memory is observed externally or if fields overlap. The function contains no synchronization that makes its sequence of changes atomic.

### Ownership and lifetime

The function directly reads and writes caller-addressed memory. It makes no explicit allocation or release call and does not establish or transfer ownership through an external dependency.

The caller must provide storage that remains usable throughout the operation. No lifetime guarantee, allocation size, recovery policy, or permission to release the storage can be inferred from this function alone.

If the boundary check succeeds, the function writes −7 one slot below the end address, sets the count to one, and returns zero. No existing entry is read.

If the boundary check fails, it leaves the count at zero, writes status 98, and returns one without writing an entry.
