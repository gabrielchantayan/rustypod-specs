# F-691903f2f0ed

## Purpose

F-691903f2f0ed performs an initialization sequence followed by nested, apparently unbounded processing loops. It invokes dependencies, consumes inherited register and stack state, and performs overlapping memory writes at fixed and computed addresses.

**Established static behavior:** the supplied representation has no explicit parameters, ordinary return value, or reachable normal-return path. Its observable behavior includes byte, halfword, word, and doubleword accesses, indirect calls, and a conditional software breakpoint.

**Inferred intent:** this may be a low-level state-processing routine. No application-level purpose, device protocol, interrupt role, or ordinary object model is established.

**Scope:** this contract describes the supplied static representation. Successful execution is conditional on the environment permitting the represented accesses and calls. It does not establish that initialization completes or that any loop executes indefinitely.

## Behavior

### 1. Entry operations

The function first calls F-00000001 with no explicit arguments.

After that call, the following accesses occur in order:

1. Store the auxiliary byte at the returned address plus the entry offset.
2. Select a halfword destination:
   - if the represented overflow condition is clear, use the entry word shifted left by 13;
   - otherwise, retain the returned address.
3. Store the entry halfword at that destination.
4. Store the same halfword 14 bytes later.
5. Store halfword `0x0010` at the address formed by clearing the entry word’s top bit and shifting the result right by one.

The first byte store always uses the original returned address. It precedes the conditional replacement of the halfword destination.

Next, the function:

1. Establishes the word cursor as the stack anchor shifted left by four.
2. Stores the low byte of the stack anchor shifted right by 12 at address `0x0000000B`.
3. Stores halfword `0xED38` at the stack anchor shifted right by 12, plus six.
4. Reads a signed 32-bit fixed-storage value and retains it for possible cursor initialization.
5. Stores the pointer value `0x97ED3800` into fixed storage beginning at that address.

The last store’s pointer value is established; its destination declaration does not independently establish the storage width. Overlapping global-symbol warnings preclude treating named locations as separate, nonaliasing objects.

### 2. Conditional initialization

The branch is taken when the entry word’s low 15 bits are nonzero.

Before the branch, the selected state is:

| State | Initial value |
|---|---|
| Accumulator seed | `0xFFFFFF0B` |
| Setup selector | Zero |
| Address seed | `0x97ED3800` |
| Entry displacement | Entry word shifted left by 14 |
| Record base | `0x000000A1` |
| Word cursor | Stack anchor shifted left by four |

On the taken branch, the function performs these operations in order:

1. Writes `0x10` to fixed storage identified with address `0x225FB880`.
2. Writes `0x18` to another named fixed location.
3. Rereads the signed fixed-storage index and stores byte `0xCE` at address `0x97ED3800` plus that index.
4. Reads fixed storage identified with address `0x0CE00026`, converts the value to unsigned, and selects it as the accumulator seed.
5. Writes zero to fixed storage identified with address `0x0CE00000`.
6. Calls F-00000002 with the masked low-15-bit entry value shifted right by one, `0xC0`, and address `0x0CE00000`.
7. Sets the cursor to twice the signed value saved before the branch.
8. Changes the address seed to `0x0897ECA0`.
9. Reads another signed 32-bit fixed-storage value and multiplies it by 32.
10. Stores halfword `0xECA0` at four times the auxiliary integer associated with F-00000002.
11. Sets the record base to zero.
12. Stores halfword `0xECA0` at the value from step 9 plus six.
13. Sets the setup selector to 16 and the entry displacement to zero.

The early saved index and the later byte-store index come from distinct reads. They can differ if intervening accesses alias their storage or the environment changes it.

The exact widths of the named fixed-storage accesses in steps 1, 2, 4, and 5 are not established by explicit access types in the supplied representation.

### 3. Shared setup and persistent state

After either branch:

1. Store the low halfword of the entry displacement at that displacement plus `0x30`.
2. Store the 32-bit product of the setup selector and `0x02000000` at that product plus `0x40`.
3. At the record base, store:
   - byte zero at offset zero;
   - the accumulator seed as a word at offset zero;
   - word `0x40` at offset 40;
   - the record-base address as a word at offset 44.

The byte store is an observable access despite being overlapped by the following word store.

The accumulator becomes the accumulator seed bitwise-ANDed with the address seed. Additional state is established:

| State | Derivation |
|---|---|
| Working displacement | Eight times the address seed, minus two |
| Stack-derived value | Cursor address plus incoming stack value plus eight |
| Initial output base | Address seed multiplied by `0x01000000` |
| Working word | Address seed multiplied by `0x02000000` |
| Payload | Zero |
| Current output pointer | Initial output base |
| Second output pointer | Initial output base |

The function then stores the stack-derived value as a word at twice that value, stores the address seed as a word at record-base offset four, and stores the low byte of the working displacement at output-base offset 20.

**The working word has successive roles, not independent storage slots.** Initially it is an accumulator addend. Each inner processing iteration overwrites it with a sampled memory word. An extended-result iteration subsequently replaces it with the working displacement shifted left by two. These replacements govern later saved bytes and any later outer addition.

### 4. Outer output sequence

The current output pointer receives, in order:

1. Byte zero.
2. The low halfword of the working displacement.
3. The 32-bit payload.

The accumulator is then increased by the current working word, and the resulting word is stored through the second output pointer.

Initially both output pointers are equal. In ordinary RAM, the accumulator store therefore replaces the payload store, but all four accesses remain part of the behavior.

After this sequence, execution enters an enclosing processing loop. Each entry to that enclosing loop sets the next F-00000003 argument to zero. The inner processing loop can repeat without that reset.

### 5. Inner processing and short-result transition

Each inner iteration performs the following ordered operations:

1. Save the low byte of the current working word.
2. Call F-00000003 with the current signed 32-bit argument.
3. Separate its result into low and high 32-bit halves.
4. Store the low halfword of the low result half at the address represented by that low half.
5. Store the word-sized product of the working displacement and 64 at the address represented by that same product.
6. Read a word through the current cursor, **overwriting the working word with the sample**.
7. Store a halfword at working displacement plus four, containing the low 16 bits of the old cursor address plus four.
8. Read the replacement cursor from address high result half plus `0x50`.
9. Call F-00000004 without explicit arguments.
10. Call F-00000005 without explicit arguments.
11. Call F-00000006 with the sampled working word.
12. Call F-00000007 with that sample shifted right by three as an unsigned value.
13. Separate F-00000007’s result into low and high 32-bit halves.
14. Form a 32-bit scaled value from its low half multiplied by 32.
15. Store the scaled value as a word at the address represented by that value.

The sample is read through the old cursor before the cursor is replaced. The later dependency arguments use the retained sample, not a fresh read after F-00000004 or F-00000005.

If the unsigned scaled value is below `0x14`, the inner loop exits to the enclosing loop, which immediately resets the F-00000003 argument to zero and starts another inner iteration. It does **not** revisit the outer output sequence.

Crucially, this transition does not restore the working word. It remains the sample read during the preceding iteration. The next saved byte is therefore that sample’s low byte.

Under 32-bit wrapping multiplication, the scaled value is a multiple of 32, so the below-`0x14` condition holds only for zero. Its word store to address zero occurs before the condition is tested.

### 6. Extended-result transition

For a scaled value at least `0x14`, processing continues:

1. Store the working displacement as a word at scaled value plus `0x58`.
2. Store the low halfword of the replacement cursor at working displacement plus `0x0E`.
3. Replace the working word with the working displacement shifted left by two.
4. Store the byte saved at iteration entry to a named fixed location.
5. Call F-00000008 with the cursor address shifted right by two.
6. Call F-00000009 without explicit arguments.

Using F-00000009’s low and high result halves, the function then:

1. Replaces the second output pointer with the high half.
2. Stores the saved byte at twice the low half.
3. Stores the low byte of the high half at low half plus eight.
4. Stores F-00000007’s retained high half as a word at twice the current accumulator.
5. Stores the full 64-bit F-00000009 result at its low-half address.
6. Replaces the accumulator with F-00000007’s high half shifted left by two.
7. Replaces the working displacement with the cursor address shifted left by eight.
8. Stores three consecutive words through F-00000007’s high-half address: the working word, updated working displacement, and cursor address.

The payload becomes the working word multiplied by 256. The current output pointer becomes zero.

### 7. Selector, breakpoint, and argument transition

The selector is derived from the cursor address by a signed 32-bit left shift by 31, a signed right shift by 32, conversion to unsigned, and a final right shift by 20.

The oversized shift prevents a unique portable interpretation. The contract does not choose an instruction-level shift rule.

Conditional on the actual selector:

- **Zero:** execution returns to the outer output sequence. Its first three stores target address zero; the accumulator store uses the second output pointer selected from F-00000009. Afterward, entry to the enclosing processing loop resets the next F-00000003 argument to zero.
- **Nonzero:** the selector is stored as a word at payload plus `0x20`. Retained call-target state changes. The next F-00000003 argument is set to the signed 32-bit interpretation of the payload shifted right by 29. F-00000010 is then executed with breakpoint immediate four.

If the breakpoint resumes normally, the working displacement becomes the signed interpretation of the second output pointer shifted right by 18. Execution continues directly into the next **inner** iteration, without passing through the enclosing argument reset.

Consequently, the resumed F-00000003 call receives the payload-derived signed argument, not necessarily zero. If that iteration subsequently takes the short-result transition, the enclosing loop resets the following argument to zero.

Retained target state is also reassigned during ordinary processing; F-00000003’s target must not be assumed constant merely because its argument is zero.

## Acceptance examples

These are conditional criteria, not executed tests.

1. **Initial destination selection.** If F-00000001 returns address A and the overflow condition is clear, the auxiliary byte is stored at A plus the entry offset. The two halfword stores instead use the entry word shifted left by 13 and that address plus 14.

2. **Branch masking.** Entry word `0x00008000` skips conditional initialization. Entry word one takes it and passes zero as F-00000002’s first argument.

3. **Taken-branch shared setup.** Assuming preceding operations succeed, shared setup stores halfword zero at `0x30`, word `0x20000000` at `0x20000040`, and performs the record stores beginning at zero.

4. **Outer overlap.** With initially equal output pointers and ordinary writable RAM, the accesses are byte, halfword, payload word, then accumulator word at the same address. Final contents alone are insufficient evidence of the sequence.

5. **Sample survives a short result.** Suppose an iteration begins with working word `0x11223344`, reads sample `0x556677A7`, and receives a zero low half from F-00000007. The saved byte for that iteration is `0x44`. After the short-result transition, the next saved byte is `0xA7`, and the next F-00000003 argument is zero.

6. **Wrapped short result.** Under 32-bit wrapping arithmetic, F-00000007 low half `0x08000000` produces scaled value zero. A word zero is stored at zero before the short-result transition.

7. **Extended result.** Low half one produces scaled value `0x20`. A word `0x20` is stored at `0x20` before entering the extended path.

8. **Resumed argument.** Conditional on a nonzero selector, breakpoint resumption, payload `0x80000000`, and arithmetic signed right shift, the next F-00000003 argument is −4. It is not reset merely because another inner iteration begins. A subsequent short-result transition resets the following argument to zero.

9. **Selector uncertainty.** Neither selector branch can be required unconditionally until the actual oversized-shift semantics are established.
