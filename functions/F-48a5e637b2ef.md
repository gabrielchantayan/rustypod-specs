# F-48a5e637b2ef

## Purpose

F-48a5e637b2ef constructs a result through mutable multiprecision objects, using either binary-style reduction or division-based reduction. It returns the selected destination handle only after a final copy-like or reduction-like operation reports success; otherwise it returns zero.

Modular inversion is the inferred mathematical intent. The established contract is the observable control flow, dependency arguments, representation tests, mutations, and cleanup described below. Without dependency implementations, the routine’s mathematical correctness and termination are not established.

The routine accepts an optional caller-owned destination. Failure does not imply rollback, and successful completion does not independently establish the lifetime of an internally acquired destination.

## Interface

### Arguments and result

| Position | Role |
|---|---|
| First | Optional destination handle. Zero requests internal acquisition. A nonzero handle is accepted without local validation. |
| Second | Source operand handle, initially passed as the source of a copy-like operation. |
| Third | Original modulus-like object. Used for an initial copy, branch selection, coefficient adjustments, direction correction, and final normalization. |

The visible interface uses 32-bit scalar slots for handles, addresses, integer arguments, and the result. A wider-pointer implementation must explicitly reconcile this representation rather than assume native pointers fit.

The result is either zero or the selected destination handle. Failure categories are not distinguished by the return value. Only failure of the terminal positive-one test causes an explicit diagnostic call.

### Directly accessed representation

| Byte offset | Observed meaning |
|---|---|

| 4 | 32-bit count or used-length field. |

Offset 8 is not directly accessed. Array words are 32 bits. Parity uses the low bit of the first word.

For loop termination, an object is recognized as zero when its count is zero, or when its count is one and its first word is zero. Sign-like metadata is not consulted for these zero tests. Counts other than zero or one do not receive a full zero-value check.

Terminal positive one requires exactly count one, first word one, and sign-like metadata zero. A first-word read occurs only after the relevant count condition. Parity checks require a signed-positive count before reading the first word.

These observations do not establish the complete object format, capacity rules, or canonical representation requirements.

### Preconditions and aliasing

All reached memory accesses and dependency calls require usable handles and storage. The routine does not validate the source operand, original modulus, context, or first six scratch acquisitions for nullness. Only the seventh scratch acquisition is explicitly checked.

## Behavior

### Storage selection and initialization

The recorded success result and selected destination initially contain zero.

The routine calls F-ea92bf179106 with the context, then calls F-834e12b6dfde with that context seven times. All seven acquisitions occur before any acquired handle is explicitly checked.

The first six acquisitions initially serve as:

1. working modulus;
2. working operand;
3. first coefficient;
4. quotient workspace;
5. remainder workspace;
6. second coefficient.

The seventh is an auxiliary temporary. These names describe roles, not permanent object identities: division-based reduction rotates several handles.

If the seventh acquisition returns zero, execution proceeds to failure cleanup. Otherwise, a nonzero caller destination is selected. When the caller supplied zero, F-7d962cda8fd4 is called without arguments; a zero result proceeds to failure cleanup.

After destination selection, F-d4e7c5a40239 is called first with the first coefficient and constant one, then with the second coefficient and constant zero. Both results are ignored.

F-cec6695e396c then receives the working operand and source operand. Only if that result is nonzero does another call receive the working modulus and original modulus. Either checked zero result causes failure cleanup.

Following successful copies, the routine directly writes zero to the working modulus’s sign-like field. It reads the working operand’s sign-like field:

- Zero permits F-c0985d8666ae to compare working operand against working modulus.
- A negative comparison skips initial reduction.
- A nonzero sign-like field, or a nonnegative comparison, selects F-c25affa40101 with arguments ordered as working operand destination, working operand source, working modulus, context.

Thus initial reduction explicitly aliases its destination and first source. A zero result causes failure cleanup.

No local rejection of a zero, negative, or noncanonical original modulus is present.

### Method selection

The signed direction marker begins at −1.

Binary-style reduction is selected only if the original modulus has signed count at least one, its first word is odd, and F-ae3bc1bfd2a8 applied to that original object returns a signed value no greater than 2048. The size query is skipped if either representation condition fails. Negative size results are not separately rejected.

All other cases select division-based reduction.

### Division-based reduction

Each iteration tests the current working operand for zero using the representation rules above. A recognized zero enters finalization. Otherwise, quotient/remainder construction proceeds.

F-ae3bc1bfd2a8 is called on the current working modulus, then on the current working operand. Equal results select a checked request to set the quotient workspace to one, followed by F-b3664dbf6599 with remainder workspace as destination, working modulus as first source, and working operand as second source.

When the first pair of size results differs, both size queries are repeated in the same object order. The second pair is used to test whether modulus size equals operand size plus one. Values from the first pair are not reused.

For this one-size-step case:

- F-b56279f86595 receives the auxiliary temporary as destination and working operand as source.
- F-c0985d8666ae compares working modulus against that temporary.
- A negative comparison selects the quotient-one construction described above.
- Otherwise, F-b3664dbf6599 receives remainder workspace, working modulus, auxiliary temporary.
- On success, F-ffdd608724b5 receives quotient workspace, auxiliary temporary, working operand.
- On success, the working modulus is compared against the quotient workspace.
- A negative comparison selects a checked request to set the quotient to two.
- Otherwise, a checked request sets the quotient to three, followed by F-b3664dbf6599 with remainder workspace as both destination and first source, and working operand as second source.

For other size relationships, F-d12d79e7b6c2 receives quotient workspace, remainder workspace, working modulus, working operand, context.

Every construction result described as checked must be nonzero. Zero causes failure cleanup, not finalization.

#### Coefficient construction and explicit aliases

After quotient/remainder construction, the **current working modulus is reused as the coefficient-construction destination**. Its previous arithmetic role does not imply that its contents are preserved.

The quotient’s count is inspected first:

| Quotient representation | Dependency and ordered arguments |
|---|---|
| Count other than one | F-db11f6cd6d48: working modulus, quotient workspace, first coefficient, context. |
| Count one, word one, sign-like field zero | No product construction; select the first coefficient directly. |
| Count one, word two, sign-like field zero | F-b56279f86595: working modulus, first coefficient. |
| Count one, word four, sign-like field zero | F-f38479822320: working modulus, first coefficient, constant two. |

Construction results are checked. In the copy-based alternative, the word passed to F-56335f371834 is a **fresh read after the copy**, not the word previously read for shortcut selection. Mutation by the copy dependency or unresolved storage aliasing can therefore change that argument.

Next, F-ffdd608724b5 is called with exactly two supplied arguments:

- destination working modulus, source first coefficient for the one-word, sign-zero quotient-one shortcut;
- destination working modulus, source that same working modulus for every other case.

A zero result causes failure cleanup. The three-argument and two-argument uses of this dependency do not establish a single complete arithmetic contract.

After success, the direction marker changes sign, and roles rotate:

- previous operand becomes working modulus;
- produced remainder becomes working operand;
- overwritten previous modulus becomes first coefficient;
- previous first coefficient becomes second coefficient;
- previous second coefficient becomes remainder workspace.

The quotient workspace and auxiliary temporary retain their storage roles. The direction marker alternates once per completed iteration.

### Binary-style reduction

Only the working-operand-zero checks at the top of this loop enter finalization. Arithmetic failures leave this branch for failure cleanup.

For a nonzero working operand, a signed 32-bit bit index begins at zero. F-a3d136098703 receives the operand and index. A zero query result increments the index and triggers coefficient adjustment:

- If the first coefficient’s signed count is positive and its first word is odd, F-782bee8991b2 receives first coefficient as destination, first coefficient as first source, and original modulus as second source.
- After any required successful combination, F-1035ffb4487d receives the first coefficient as both destination and source.

Each adjustment result must be nonzero. The bit query repeats until it returns nonzero. Every nonzero query result ends scanning; no distinct query-error interpretation is visible.

If the accumulated index is positive, F-820d34f1a0c3 receives working operand as destination and source, followed by that index. A zero result causes failure cleanup.

The same process then scans the working modulus, adjusting the second coefficient:

- F-782bee8991b2 receives second coefficient, second coefficient, original modulus when the coefficient meets the positive-count/odd-word condition.
- F-1035ffb4487d receives second coefficient twice.
- Any accumulated positive shift uses F-820d34f1a0c3 with working modulus twice and the index.

There is no preliminary working-modulus-zero exit before this scan.

After both scans and any shifts succeed, F-c0985d8666ae compares working operand against working modulus:

| Comparison | First checked call | Subsequent checked call |
|---|---|---|
| Negative | F-782bee8991b2(second coefficient destination, second coefficient first source, first coefficient second source) | F-e3b26f245f4c(working modulus destination, working modulus first source, working operand second source) |
| Nonnegative | F-782bee8991b2(first coefficient destination, first coefficient first source, second coefficient second source) | F-e3b26f245f4c(working operand destination, working operand first source, working modulus second source) |

The working-value update occurs only if the coefficient combination succeeds. Both operations explicitly alias destination with first source.

A zero result from coefficient adjustment, accumulated-bit adjustment, coefficient combination, or working-value update proceeds directly to failure cleanup. Even where such failure exits the loop structurally, it does **not** trigger direction correction, terminal-unit inspection, diagnostics for a nonunit, or normalization.

The direction marker remains −1 throughout this branch. No iteration bound, bit-scan bound, or checked bit-index increment is visible.

With a nonnegative marker, direction correction is skipped. After successful correction or that skip, the current working modulus must have the exact positive-one representation.

## Side effects

Established effects include context entry and exit, seven scratch acquisitions, optional destination acquisition, direct clearing of the working modulus’s sign-like field, dependency-driven object mutations, optional diagnostics, and conditional destination release.

No rollback is visible. A checked dependency may mutate its destination or other state before reporting zero. The final operation can therefore leave a caller destination changed despite an overall zero return.

Scratch objects are not individually released here. Their reclamation and lifetime depend on context behavior. A successfully acquired destination is not explicitly released here, but survival across context exit remains unestablished.

No dependency is assumed to preserve globals, inputs, context state, or unrelated object metadata. Argument ordering and fresh reads matter even when arithmetic intent suggests equivalent values.

## Acceptance examples

These are conditional static scenarios, not executed tests.

1. **Seventh acquisition returns zero.** All seven acquisitions occur. Destination acquisition and arithmetic are skipped. With no caller destination, release receives zero. Context exit occurs; return is zero.

2. **First copy fails.** Both initial constant-setting requests have already occurred. The modulus copy is skipped. A supplied destination is not released.

3. **Initial setter returns zero.** That result alone does not stop execution. Subsequent copies are attempted; usable coefficient contents are not thereby guaranteed.

4. **Branch boundary.** A signed-positive-count odd original modulus with size result 2048 selects binary reduction; 2049 selects division reduction. An even first word skips the branch-selection size query.

5. **Binary accumulated shift fails.** If F-820d34f1a0c3 returns zero for either working value, cleanup follows. No direction correction, unit check, terminal-nonunit diagnostic, or final normalization occurs.

6. **Binary operand compares smaller.** The coefficient call receives second coefficient, second coefficient, first coefficient. Only after success does the working-value call receive working modulus, working modulus, working operand.

7. **Division quotient-one shortcut.** With count one, word one, and sign-like field zero, no product construction occurs. The two-argument F-ffdd608724b5 receives working modulus as destination and first coefficient as source.

8. **Copy-based quotient changes.** If shortcut selection observes a word requiring the copy-based path, and the copy changes the quotient word, the later F-56335f371834 receives the post-copy word. If the copy fails, that later call is skipped.

9. **Terminal positive one.** After any required direction correction succeeds, a sign-zero candidate comparing below the original modulus selects final copying. Successful copying returns the selected destination.

10. **Terminal nonunit or final failure.** A terminal positive two triggers the diagnostic tuple. A failed final copy or reduction returns zero without restoration. Failure releases an internally selected destination, but not a caller-supplied one.
