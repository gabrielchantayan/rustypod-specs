# F-97f36d1a1364

## Purpose

F-97f36d1a1364 conditionally updates a selected tag byte and invokes an associated dependency with the requested value. Selection uses a context, a nonzero selector, two conversion calls, and an object-field read. Selected entries have a five-byte stride.

The function compares the existing tag against the requested tag. Only if those match does it obtain a 32-bit comparison operand from a dependency called with the selected address plus one. A detected difference triggers a prerequisite dependency. A zero prerequisite result permits a direct byte store followed by another dependency call with the adjacent address and requested value.

The adjacent address suggests a value field, but its storage width, encoding, and access behavior are not established. In particular, the supplied body does not prove that either dependency reads or writes four bytes.

A final dependency is called on every normally continuing path after successful resolution. Its argument is freshly obtained from an address-bearing temporary slot. Because that slot’s address has escaped to a dependency, the argument need not identify the same object used earlier.

- The nonzero result of F-133a6620fb39 if resolution fails.

Results from F-cfb711b78946 and F-44d249c54e70 do not determine the returned status. A zero result does not prove that any record was changed or that an associated value was successfully stored.

### Address-bearing slot

Subsequent operations use the slot’s contents as an address-bearing value. The supplied body does not establish that F-133a6620fb39 cannot retain the slot’s address or expose it to later dependencies. Consequently, later calls may change the slot while this invocation remains active.

The slot has three relevant subsequent read points:

2. After difference detection, if the prerequisite call is reached, for that call’s argument.
3. After the comparison and any prerequisite, direct store, and associated call, for the final dependency’s argument.

These reads need not produce the same value.

## Behavior

### Zero-selector exit

A selector of zero returns 11 immediately.

This path makes no dependency calls, does not initialize the resolution slot, and performs no explicit context or selected-storage access. The context and requested values do not affect this branch.

### Initial conversion and resolution

For a nonzero selector, the function initializes the temporary slot with the requested value and calls F-c76bdec3f9e1 with the context and selector.

After that call returns, the function reads the context’s first 32-bit word. Changes to context storage made by the first conversion can therefore affect this read.

F-133a6620fb39 receives, in order:

1. The context word just read.
2. The first conversion’s 32-bit result.
3. The address of the initialized temporary slot.
4. Zero.

The slot is not an initially empty output parameter. Its initial requested-value contents are available to the resolution dependency.

If F-133a6620fb39 returns nonzero, that result is returned immediately. There is no second conversion, selected-record access, prerequisite call, or final call. The body provides no rollback for effects already caused by dependencies.

A zero result enables subsequent processing. It does not itself demonstrate what the resolution dependency wrote into the slot or whether it retained the slot’s address.

### Record selection

After successful resolution, F-c76bdec3f9e1 is called again with the context and selector.

The first result is not reused, and the two results are not compared. The second result is interpreted as a signed 32-bit integer for the selection calculation:

**byte offset = 5 × (selector − second conversion result − 1)**

After the second conversion returns, the function reads the slot and accesses the 32-bit field at that address plus 52 bytes. Thus, a slot change during the second conversion affects which object supplies the record-storage address.

The field supplies a cached storage address. The selected address is that address plus the computed byte offset. Both the storage address and offset remain the operands used for the later direct tag store and adjacent-address call; they are not recomputed from a subsequently changed slot.

The displayed arithmetic uses 32-bit quantities. There are no explicit checks for subtraction overflow, multiplication overflow, negative offsets, or storage extent. The supplied evidence does not independently settle signed-overflow or invalid-address semantics. No wraparound behavior is assumed here.

### Difference detection

The function first reads the byte at the selected address. It compares that byte, zero-extended, against the full unsigned 32-bit requested tag.

If they differ, the adjacent-address comparison dependency is skipped.

If they match, F-d1e995cfb2d3 is called with the selected address plus one. Its signed 32-bit result is compared with the requested value. The body establishes the argument and comparison result width, not a particular underlying memory read.

A difference exists if either:

- The zero-extended tag byte differs from the full requested tag; or
- The tags match and the dependency’s result differs from the requested value.

A requested tag greater than 255 cannot match any existing byte. This remains true when its low eight bits equal the existing byte.

If both comparisons match, the prerequisite and explicit update operations are skipped. The pending return status remains the zero resolution result.

### Prerequisite and update operations

When a difference is detected, the function reads the slot again and passes its then-current contents to F-81c906bf6e3a.

If F-d1e995cfb2d3 was called, any slot mutation during that call can affect the prerequisite argument. The prerequisite is therefore not unconditionally called with the object used for the earlier field read.

The prerequisite result becomes the pending return status.

If it is nonzero, the direct tag store and F-cfb711b78946 call are skipped.

If it is zero, the function performs, in order:

1. A direct one-byte store of the requested tag’s low eight bits to the previously selected address.
2. A call to F-cfb711b78946 with the previously selected address plus one and the requested signed 32-bit value.

No slot reread or object-field reread redirects these two operations. If the prerequisite changes the slot or the object’s storage-address field, the cached storage address and offset still determine their target.

The direct byte store is established. The subsequent call’s memory effects are not. Its result is not checked or propagated. There is no demonstrated rollback if it fails, faults, or changes other state.

### Final operation

After every successful resolution, provided all intervening operations complete normally, the function reads the slot again and passes its current contents to F-44d249c54e70.

This occurs when:

- Both comparisons matched.
- A difference was detected but the prerequisite returned nonzero.
- The prerequisite returned zero and the direct store and associated call completed.

The final argument can reflect slot mutations during the second conversion, comparison dependency, prerequisite, associated call, or any other reached operation that can affect that storage. It need not equal either the earlier object-field address or the prerequisite argument.

The final dependency’s result is ignored. The function returns the pending status without rereading selected storage or interpreting final-operation effects.

## Side effects

### Explicit access order

On a successful-resolution path, the demonstrated sequence is:

1. Initialize the temporary slot.
2. Call the first conversion.
3. Read the context’s first word.
4. Call resolution with the slot’s address.
5. Call the second conversion.
6. Read the slot and the object field at offset 52.
7. Read the selected tag byte.
8. If tags match, call F-d1e995cfb2d3.
9. If a difference exists, read the slot and call the prerequisite.
10. If the prerequisite returns zero, store the tag byte and call F-cfb711b78946.
11. Read the slot and call the final dependency.

A tag mismatch suppresses step 8. Matching comparisons suppress steps 9 and 10. Prerequisite failure suppresses step 10, not step 11.

### Demonstrated and possible memory effects

The demonstrated writes are initialization of the temporary slot and, conditionally, the direct tag-byte store.

Resolution receives a writable slot address, but its actual writes are not supplied. Neither the comparison dependency nor the associated-value dependency has an established memory-access width or read/write contract.

At entry to F-cfb711b78946, the direct byte store has already occurred. This does not guarantee that the byte retains that value after the call or at function return.

### Ownership and lifetime

Passing the temporary slot’s address does not establish ownership transfer or permission to use it after its local lifetime ends. Possible retention matters here because it can affect later operations during the same invocation; valid post-return retention behavior remains unknown.

No dependency is assumed to preserve globals, context, object fields, selected storage, or an escaped slot. A path without a direct record store is not necessarily side-effect-free.

## Acceptance examples

These are conditional consequences of static evidence, not executed tests. Unless stated otherwise, assume valid reached accesses, representable arithmetic, normally returning dependencies, and no interfering mutation.

### Zero selector

With selector zero, the result is 11. No dependency is called and no context or selected storage is explicitly accessed.

- No prerequisite is called.
- No direct tag store or F-cfb711b78946 call occurs.

### Prerequisite failure

- No direct tag store occurs.
- F-cfb711b78946 is not called.
- The final dependency is called with the slot’s contents after the prerequisite.
- The result is 9.

### Requested tag outside byte range

With requested tag 258 and existing tag 2, the tag comparison fails and the comparison dependency is skipped.

If the prerequisite succeeds, the direct byte store writes 2. Even if that byte remains unchanged afterward, a subsequent invocation requesting 258 again cannot obtain a tag match.

### Different conversion results

No rejection occurs merely because the conversion results disagree.

### Slot changes across dependencies

Suppose resolution leaves object address A in the slot and retains access to the slot. During the second conversion, the slot changes to B.

The storage-address field is read from B plus 52, not A plus 52. Suppose the selected tag matches, the comparison dependency reports a differing value, and that dependency changes the slot to C. The prerequisite receives C.

If the prerequisite returns zero while changing the slot to D, the direct store and associated call still target the address cached from B’s field and the computed offset. If the associated call then changes the slot to E, the final dependency receives E.

All addresses and mutations in this example require valid lifetimes and accesses. The example establishes argument selection and caching behavior, not that any dependency actually performs these mutations.
