# F-751e5625a183

## Purpose

F-751e5625a183 prepares a destination object, invokes provider initialization and processing, and performs mode-dependent result writes when both status-returning operations succeed.

Two successful paths are visible:

- **Ordinary mode:** write initial metrics, invoke dependencies on a destination subregion and working vectors, optionally scale point coordinates and metrics, derive four result words, and invoke a final adjustment dependency.
- **Alternate mode:** store a four-word record and two displacement words in auxiliary storage, activate its representation marker, and write selected destination metrics.

The operation is not transactional. Destination writes occur before provider initialization. Either reported failure can follow changes made by this function or its dependencies; no rollback is visible.

“Transform,” “displacement,” “metric,” and “bounds” are descriptive interpretations of data roles, not established public types or mathematical contracts.

## Interface

### Arguments and return value

The interface contains four 32-bit argument words.

| Argument | Established use |
|---|---|
| Destination | Address of writable destination storage and a source of nested pointers. |

Preservation of the saved processing argument across provider initialization is **not established**. The initializer receives a pointer into temporary storage, whose complete layout and permitted modification range are unknown. The observed contract is a save followed by a later read, not guaranteed unchanged forwarding.

The returned 32-bit status is:

- The initialization status when initialization returns nonzero.
- Otherwise, the status returned by F-e682d285bb9a.

Only zero permits successful-result handling. Subsequent dependencies do not contribute an inspected error status.

## Behavior

### Entry preparation and global-read order

The function first captures the destination’s owner pointer and resolves the provider-table pointer through the owner’s intermediate object. It then:

1. Reads descriptor +0x10 and writes destination +0xac.
2. Reads descriptor +0x14 and writes destination +0xb0.
3. Establishes working flags: if flag 0x400 is present, force bits 0x01 and 0x02 on; otherwise retain the supplied flags.
4. Clears destination +0x6e with a 16-bit write.
5. Computes whether both low working-flag bits are clear.
6. Clears destination +0x6c with a separate 16-bit write.
7. Reads a global word into the third word of a four-word result-derivation record.
8. Initializes that record’s first word to one when both low working-flag bits are clear, otherwise zero.
9. Reads a different global word and writes it to destination +0x48.
10. Initializes the record’s second word from working-flag bits 16–19.
11. Reads owner +0x20c, then owner +0x1a0, into temporary storage.
12. Copies the Boolean-like first record word into a separate context field.
13. Saves the four original argument words in local storage.

The global read for the result record therefore occurs **after both 16-bit clears and before the global read supplying destination +0x48**. These globals are distinct.

The four-bit extraction excludes bits 20–31. Normalization changes only low bits, so original and working flags produce the same extracted value.

No direct initialization of the result record’s fourth word is visible before dependencies run. Initial values in temporary storage are not preservation guarantees.

### Initialization and processing

Provider slot 0 is invoked with, in order:

1. A pointer to temporary processing context.
2. The captured owner pointer.
3. The input descriptor.
4. The destination.

A nonzero initialization status is returned immediately. F-e682d285bb9a, provider slot 1, and successful-result handling are not reached.

After zero initialization status:

1. A one-byte context indicator is assigned zero or one according to working flag 0x400.
2. Owner +0x190, +0x194, and +0x198 are copied into temporary state, in that order.
3. The saved processing-argument slot is read.
4. F-e682d285bb9a receives the context pointer, that saved-slot value, and a pointer to a two-word result area.

A nonzero processing status is returned without calling provider slot 1.

After zero processing status:

1. Four context words are copied into a separate working record.
2. Provider slot 1 from the previously captured table is invoked with the context pointer.
3. Destination +0x7c is read and overwritten with only its current bit 0 preserved and bit 0x04 set.

For example, a value of 0xffffffff at the status read produces the direct write 0x00000005.

The four-word copy precedes provider slot 1. Metrics, displacements, and other context values used later are read after that callback. There is no explicit recopy of the four-word record after the callback. This establishes sequencing, not a general guarantee that unknown dependencies cannot alter accessible temporary storage.

### Ordinary mode: initial writes and descriptor condition

Ordinary mode applies when working flag 0x400 is clear.

The function:

1. Writes the context horizontal-like metric to destination +0x28, then +0x38.
2. Reads destination +0x9c and clears auxiliary +0x08 with a one-byte write.
3. Subtracts owner +0x1cc from owner +0x1d4 using 32-bit operands and applies a signed arithmetic right shift by 16.
4. Writes that result to destination +0x34, then +0x3c.
5. Reads the global associated with destination +0x48 into a temporary comparison operand.
6. Reads that same global again and writes this second value to destination +0x48.
7. If the descriptor address is nonzero, reads its unsigned 16-bit field at +0x0e, replacing the temporary comparison operand.
8. If the descriptor address is nonzero and the comparison operand is less than 24, reads destination +0x7c and writes it back with bit 0x100 set.

The two ordinary-mode global reads are distinct and consecutive in the visible sequence. Neither is established to equal the entry-time read or the other ordinary-mode read. The first value is replaced when the descriptor is nonzero; a zero descriptor prevents the threshold update regardless of that value.

### Optional ordinary-mode scaling

Scaling occurs only when working flag 0x01 is clear.

The function first examines the context Boolean-like field. If nonzero, it reads a companion indicator; otherwise the effective companion value is zero. It then captures destination +0xac and +0xb0 as the two scaling operands and reads the coordinate-array pointer from point-storage +0x04.

That pointer-field read occurs **even when point iteration will be bypassed**. The point-storage object must therefore be readable on this scaling path.

Point iteration is bypassed exactly when both the Boolean-like field and companion indicator are nonzero. Otherwise, the count at point-storage +0x02 is read as a signed 16-bit value:

- Positive counts determine the number of iterations.
- Zero and negative counts cause no coordinate iterations.

For each pair, in increasing storage order:

1. Read the first coordinate and call F-74efb2674226 with it and the captured first scaling operand.
2. Write the returned word to the first coordinate.
3. Read the second coordinate and call F-74efb2674226 with it and the captured second scaling operand.
4. Write the returned word to the second coordinate.
5. Advance eight bytes.

After iteration, including bypassed or empty iteration, the function scales current destination +0x28 using the first operand and writes the returned word there. It then scales current destination +0x34 using the second operand and writes that result.

When flag 0x01 is set, none of these scaling-path pointer reads or scaling calls occurs.

### Alternate mode

When working flag 0x400 is set, the ordinary-mode sequence is bypassed. The direct operations are:

1. Capture destination +0x9c as the auxiliary pointer.
2. Write a context-provided word to destination +0x20.
3. Write the context horizontal-like metric to destination +0x28.
4. Write the copied four-word record to auxiliary +0x0c through +0x18, in ascending offset order.
5. Write the two context displacement words to auxiliary +0x1c and +0x20.
6. Write one to auxiliary +0x08.

This path contains no direct writes to destination +0x18, +0x1c, +0x24, +0x34, +0x38, or +0x3c. Their preservation is not guaranteed across dependencies.

### Common completion

After either successful mode path, the function reads the two-word processing-result area and copies its words to destination +0x88 and then +0x8c. It returns zero.

These are late reads, not an immediate snapshot at the return from F-e682d285bb9a.

## Side effects

Direct effects include entry initialization, status replacement, mode-specific destination and auxiliary writes, and conditional in-place coordinate scaling.

The ordering has these consequences:

- Entry writes have occurred before provider initialization is invoked. Because the initializer receives the destination, their persistence when it returns nonzero is not established.
- Processing failure skips provider slot 1 and all subsequent direct result writes.
- Provider slot 1 runs before status normalization.
- Coordinate writes occur individually, with no visible rollback.
- Final processing-result copies follow all mode-specific work.

Unknown dependencies may modify accessible context, destination, owner, globals, or other shared state. No preservation, allocation, release, or retention contract is inferred.

Arithmetic uses 32-bit words without a visible checked-overflow or saturation path. Signed arithmetic right shift preserves a negative sign; it is not equivalent to division truncating toward zero. Overflow consequences at the original-language level are not established by the supplied representation. Aliasing can make individual read/write order significant; unrestricted aliasing safety is not established.

## Acceptance examples

These are conditional static acceptance cases, not executed tests. Valid accessed storage is assumed; numeric final-state claims require no intervening dependency or aliasing effect that changes the stated operands.

1. **Initialization failure:** If provider slot 0 returns 7, the function returns 7 without processing or provider slot 1. Entry writes occurred before the callback, but their values need not remain afterward.

2. **Saved processing argument:** If the saved slot still contains the original processing argument after initialization, F-e682d285bb9a receives that value. If initialization changes the slot through accessible temporary storage, the observed later slot value is supplied instead.

3. **Processing failure:** If initialization returns zero and processing returns −3, the function returns −3 without provider slot 1, direct status normalization, or final result copies.

4. **Global ordering:** If the +0x48-associated global yields 10 on entry, 20 on the first ordinary-mode read, and 30 on the second, the corresponding direct destination stores use 10 and 30. With a valid nonzero descriptor, its threshold field replaces 20 for comparison.

5. **Descriptor boundary:** Ordinary-mode descriptor values 23 and 24 respectively cause and do not cause the direct bit-0x100 update.

6. **Alternate mode:** Flag 0x400 forces both low working bits on and selects auxiliary-record output. Ordinary-mode transform, scaling, result-derivation, and final-adjustment calls are skipped.

7. **Point bypass:** With scaling enabled and both context indicators nonzero, the coordinate-array pointer field is still read, but the point count and coordinates are not read by the loop. Both metric-scaling calls still occur.

8. **Signed count and shift:** An eligible point count of −1 produces no coordinate calls. Separately, an owner subtraction result of −1 without overflow shifts to −1, not zero.

9. **Vector dependency uncertainty:** If F-baed69327072 leaves a vector unchanged, the caller uses its unchanged selected word plus displacement. The contract does not require that dependency to transform the vector.
