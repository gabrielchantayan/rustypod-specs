# F-7226c5f9cc42

## Purpose

F-7226c5f9cc42 performs an insertion-shaped update on a descriptor for contiguous, eight-byte records. It selects between allocating replacement storage and modifying existing storage, then incorporates a record supplied through a separate address.

**Established behavior:** the descriptor contains three 32-bit address fields; record spacing is eight bytes; the replacement-storage path publishes a new start, logical end, and storage limit; the existing-storage path advances the logical end before calling a dependency and moving record words.

**Inferred intent:** insertion into a growable sequence of two-word records. This interpretation does not establish the behavior of the dependencies, the validity of arbitrary insertion positions, or conventional sequence-insertion semantics.

The function has no explicit return value. Its observable results are descriptor changes, record-memory reads and writes, and dependency calls.

## Interface

### Inputs

The function accepts three addresses:

| Input | Required representation | Role |
|---|---|---|
| Descriptor | At least three accessible 32-bit fields | Describes storage and receives updates |
| Position | Address used as an eight-byte record boundary | Identifies where the supplied record is incorporated |
| Value | Address of at least two readable 32-bit words on the existing-storage path | Supplies the record contents |

The descriptor layout is:

| Byte offset | Width | Interpretation |
|---|---:|---|
| 0 | 32 bits | Storage start |
| 4 | 32 bits | Logical end |
| 8 | 32 bits | Storage limit |

Each record occupies eight bytes, divided into a first 32-bit word and a second 32-bit word. No field interpretation beyond these word positions is established. Byte order is not specified.

The visible representation uses 32-bit addresses and 32-bit arithmetic quantities. It must not be generalized to a native-width pointer layout on another platform.

### Output and ownership

There is no explicit success indicator, error code, or returned address.

On a normally returning replacement-storage path, the descriptor is overwritten with addresses derived from the allocation result and a later record-count query. The previous storage is passed to F-ff1bdc376dcd before those descriptor writes.

This call sequence suggests storage replacement, but it does not independently establish:

- Whether the allocation result represents owned storage.
- Whether F-ff1bdc376dcd releases storage.
- Whether record contents carry independent ownership.
- Whether copying, constructing, or releasing records affects referenced resources.

The caller supplies the value address; the visible body does not explicitly release it.

### Preconditions and validity limits

No explicit validation is present for null addresses, descriptor consistency, record alignment, insertion bounds, integer overflow, or allocation failure.

A conventional sequence interpretation requires accessible descriptor fields, coherent eight-byte record boundaries, and storage sufficient for all executed reads and writes. These are caller obligations or dependency obligations, not checked guarantees.

The existing-storage loop has a narrower visible operating shape than a generic insertion API: its initial comparison position is one record before the previous logical end. Inserting at the previous logical end is not visibly handled as an ordinary append operation.

## Behavior

### 1. Capacity decision

The function first reads the descriptor’s storage start and storage limit, in that order. It then calls F-8180d7378e16 with the descriptor.

The initial capacity-like quantity is formed by subtracting the saved start from the saved limit, applying a signed right shift by three, and interpreting the result as unsigned for comparison. The function selects replacement storage when this quantity is less than or equal to the dependency’s unsigned result.

Consequences:

- Equality selects replacement storage.
- A result smaller than the capacity-like quantity selects existing-storage modification.
- The start and limit used in this decision were read **before** the dependency call. Changes made by that call do not retroactively change those saved values.
- A negative or otherwise malformed address difference is not rejected; its shifted result participates in an unsigned comparison.

Calling F-8180d7378e16 a “record-count query” is an inferred role based on its uses. Its implementation and side effects are not supplied.

### 2. Replacement-storage path

#### Capacity selection

The function calls F-8180d7378e16 again. This second result, not the first, determines the requested capacity.

For an unsigned 32-bit result \(n\), it computes:

- A proportional candidate: \(n + (n \mathbin{\gg} 1) + (n \mathbin{\gg} 3)\).
- An additive candidate: \(n + 32\).
- The unsigned maximum of the two candidates.

The right shifts discard fractional portions separately. For non-overflowing values, the proportional candidate is therefore \(n+\lfloor n/2\rfloor+\lfloor n/8\rfloor\), not necessarily \(\lfloor 13n/8\rfloor\).

The additions are 32-bit unsigned operations. Their results may wrap before the comparison. The selected capacity is shifted left by three to form the byte-size argument to F-871e64ddc6de; high bits can be discarded. No overflow rejection is visible.

F-871e64ddc6de receives that byte-size quantity and zero. Its returned 32-bit value is retained as the replacement base address.

#### Dependency-mediated population

The function next makes three calls, in this order:

1. **F-f0cb51027742** receives the descriptor’s currently stored start, the supplied position, the replacement base, and the descriptor.
2. **F-d0393e5b7842** receives the descriptor, a computed destination, and the supplied value address.
3. **F-f0cb51027742** receives the supplied position, the descriptor’s currently stored logical end, a computed destination one record later, and the descriptor.

The destination for the second call is the replacement base plus the position’s displacement from the descriptor’s then-current start, with the displacement’s lowest three bits cleared.

The destination for the third call is recomputed using another read of the descriptor’s start, then advanced by eight bytes.

Thus, although the calls resemble prefix transfer, insertion, and suffix transfer, their actual effects are delegated. In particular:

- The start used for the first transfer is read after allocation returns.
- The start used to place the supplied value is read after the first transfer returns.
- The start and logical end used for the final transfer are read after the value-placement call returns.
- The supplied position itself remains the original argument; it is not adjusted if a dependency changes the descriptor.

The displacement masking rounds the 32-bit displacement down to a multiple of eight. It does not validate that the supplied position is aligned or within the original storage.

#### Old-storage processing and publication

After those three calls, the function calls F-8180d7378e16 a third time and retains that result for the final logical-end calculation.

It then reads the descriptor’s current start and performs an address-only traversal:

- The traversal begins at that saved start.
- It advances by eight bytes.
- It stops when its address equals the descriptor’s logical end.

The loop contains no visible record dereference, destructor call, or other body action. It must not be described as destroying records. If its equality condition is not reachable, normal completion is not established.

After traversal, F-ff1bdc376dcd receives:

1. The saved start used for traversal.
2. The descriptor’s then-current limit minus that saved start, signed-right-shifted by three.
3. Zero.

The function finally writes the descriptor fields in this order:

1. Start becomes the replacement base.
2. Logical end becomes the replacement base plus eight times the third query result, plus eight.
3. Limit becomes the replacement base plus eight times the selected capacity.

These writes occur after F-ff1bdc376dcd returns. A dependency inspecting the descriptor before that publication sees the descriptor as it then stands, not an already-published replacement descriptor.

The second and third query results have different roles. If they differ, the selected capacity and final logical end reflect different observations; the function does not reconcile them.

### 3. Existing-storage path

The function reads the descriptor’s logical end and saves that address as the previous end. It immediately writes the descriptor’s logical end to the previous end plus eight.

It then calls F-d0393e5b7842 with the descriptor and the previous end as the two visibly supplied arguments.

This call differs from the three-argument use on the replacement-storage path. The supplied evidence does not establish an additional value argument, a default value, or the record written by this call.

After the dependency returns, the function performs its explicit backward movement using addresses derived from the saved previous end, rather than rereading the descriptor’s logical end.

The comparison address initially identifies the record immediately before the previous end. If the supplied position equals that address, the movement loop executes zero times.

Otherwise, each iteration:

1. Selects the record one further position backward.
2. Reads that record’s first word.
3. Reads its second word and writes that second word to the corresponding destination one record later.
4. Writes the saved first word to the destination’s first-word location.

The first explicit movement therefore copies the record **two positions before the previous end** into the record immediately before the previous end. It does not explicitly copy the last existing record into the newly added slot.

For a valid earlier insertion position, movement continues backward until the record at the supplied position has been copied one record later. Preservation or construction of the record at the previous end depends on F-d0393e5b7842.

Finally, the supplied value is written at the position with this ordering:

1. Read the value’s second word.
2. Read the value’s first word.
3. Write the first word at the position.
4. Write the saved second word at the position plus four.

These reads occur after the dependency call and after all explicit movement. The value is not snapshotted on entry. If its address aliases moved storage, the inserted contents can reflect intervening modifications.

No further descriptor correction occurs after the dependency call. Changes that dependency makes to descriptor fields can therefore persist.

## Side effects

The function can produce the following observable effects:

- Multiple calls to F-8180d7378e16, with later calls occurring after other dependencies have run.
- An allocation-shaped call with a potentially wrapped 32-bit byte count.
- Dependency-mediated record-memory changes.
- Direct two-word record movement and overwrite on the existing-storage path.
- A release-shaped call concerning the descriptor’s then-current storage.
- Descriptor publication after old-storage processing on the replacement path.
- Early logical-end publication on the existing-storage path.

The function is not visibly transactional. There is no local rollback path. In particular, the existing-storage logical end is advanced before the construction-shaped dependency executes.

No explicit error recovery is present for dependency failure or abnormal control transfer. Behavior following an invalid allocation result is not separately guarded.

No global-memory preservation guarantee can be assigned to any dependency. The contract specifies the explicit reads and writes in this function without assuming unknown callees leave descriptor fields, globals, or record memory unchanged.

## Acceptance examples

The examples below are conditional static expectations, not executed tests.

### Capacity equality selects replacement storage

Given a coherent descriptor whose start-to-limit distance is 80 bytes, the capacity-like quantity is ten. If the first F-8180d7378e16 result is ten, replacement storage is selected. The existing-storage path is not selected.

### Small replacement growth

If the second query result is eight:

- The proportional candidate is thirteen.
- The additive candidate is forty.
- The selected capacity is forty records.
- The allocation-shaped call receives 320 bytes and zero.

If the third query result is also eight and all intervening calls return normally, the final logical end is the replacement base plus 72 bytes, and the final limit is the replacement base plus 320 bytes.

### Distinct query results remain distinct

If the second query returns eight but the third returns nine, the selected capacity remains forty records, while the published logical end becomes the replacement base plus 80 bytes. The function does not reuse the earlier count for that end calculation.

### Insertion at the last existing record

Assume spare capacity and a supplied position exactly eight bytes before the previous logical end.

The logical end is advanced by eight before F-d0393e5b7842 is called. The explicit movement loop performs no iterations. The supplied value then overwrites the record at the position.

The contents of the newly added slot cannot be specified without the dependency’s behavior.

### Earlier insertion and conditional sequence semantics

Assume four existing records, spare capacity, insertion at the second record, and a non-aliasing value. Also assume F-d0393e5b7842 preserves the previous last record in the newly added slot and makes no interfering changes.

The explicit loop moves the previous third record to the fourth position, then the previous second record to the third position. The final value overwrite fills the second position. Under those dependency assumptions, the result has ordinary insertion ordering.

Without the stated dependency behavior, only the explicit movements and final overwrite are established.

### Aliasing value address

If the value address lies within a record modified by the movement loop, the final value reads observe memory after that movement. Acceptance must not require preservation of the value’s entry-time contents.

### Overflow boundary

If the second query result is \(2^{32}-1\), unsigned arithmetic produces a proportional candidate of 2,684,354,557 and an additive candidate of 31. The selected candidate’s three-bit left shift yields a byte-size quantity of 4,294,967,272.

This establishes the arithmetic behavior, not the validity of such an allocation or descriptor.
