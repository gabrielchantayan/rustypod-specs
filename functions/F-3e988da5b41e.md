# F-3e988da5b41e

## Purpose

F-3e988da5b41e conditionally submits a request using shared state, then processes a nonzero submission result through one of two completion operations.

The request has either no payload or a three-byte payload. A shared-state flag selects the request form. When initially clear, that flag can lead to an auxiliary lookup and initialization of three state fields before payload preparation.

The function returns a 64-bit concatenation of two 32-bit words. The low word is a local status or a completion dependency’s result. The high word is the incoming second argument, zero, or the address of temporary storage.

Two distinct reads of the shared-root global are significant. The first root is retained for subsequent state-field accesses. A second root, read only on the active path, supplies the state pointer used to compute the address passed to the paired entry and exit dependencies. Those roots need not identify the same object.

Request semantics, status meanings, and synchronization guarantees are not established. All behavior below is based on static evidence; no runtime tests have been performed.

## Interface

### Arguments

All four arguments occupy 32 bits in the supplied representation.

| Position | Established use |
|---|---|
| First | No direct use is visible. |
| Second | Pointer-shaped word, not dereferenced by this function. Returned in the high word only when the prerequisite result is zero. |
| Third | No direct use is visible. |
| Fourth | Copied into a four-byte temporary before the prerequisite call. That temporary can later back the payload. |

The incoming second argument need not designate readable or writable storage for any direct access shown here. It is not an established output-buffer argument.

The fourth argument initializes all 32 bits of the temporary. On a payload path, a dependency receives the temporary’s address before this function replaces its third byte. The submitted bytes therefore cannot generally be derived from the fourth argument alone.

### Result

The 64-bit result is a bit-level concatenation, not an established source-language structure:

| Bits | Content |
|---|---|
| 31–0 | Status or completion-result word |
| 63–32 | Pointer-shaped word |

| Returning path | Low word | High word |
|---|---:|---|
| Prerequisite returns zero | 11 | Incoming second argument |
| Submission returns zero, no payload | 28 | Zero |
| Submission returns zero, payload prepared | 28 | Temporary address |
| Nonzero submission, no payload | Selected completion result | Zero |
| Nonzero submission, payload prepared | Selected completion result | Temporary address |

The payload choice determines the high word. A later flag read independently determines the completion operation.

The temporary address does not identify durable result storage. Its local storage lifetime ends when the invocation returns.

### Preconditions

For normal execution, each accessed pointer must designate suitable storage at the time of access.

- The shared-root global is read even when the prerequisite result is zero. That path does not dereference the root value.
- On the active path, the second root must permit reading its subordinate pointer at offset 4 and forming the address 732 bytes into that state.
- The retained first root must support each later subordinate-pointer reload. The selected subordinate objects must support the fields accessed on that path.
- An auxiliary result must permit reading its byte at offset 217.
- Triggered initialization requires writable fields at offsets 772–775.
- Indirect completion requires a readable dispatch pointer and usable callable slot at table offset 8.

There are no visible null checks, bounds checks, or local invalid-pointer recovery paths. Address calculations use the represented 32-bit address space. Defined application behavior for address wraparound or invalid resulting storage is not established.

## Behavior

### Initial state and prerequisite

The function establishes low-word value 11 and copies the fourth argument into its four-byte temporary. It then calls F-59599f67673b without explicit arguments.

After that call returns, it reads the shared-root global and retains the resulting root value. This read occurs before testing the prerequisite result.

If the prerequisite result is zero, the function returns immediately with low word 11 and high word equal to the incoming second argument. It does not dereference the retained root and does not call the entry, auxiliary, payload, submission, completion, or exit dependencies.

The prerequisite dependency may itself have side effects; its contract is not supplied.

### Separate root selection for entry and exit

For a nonzero prerequisite result, the outgoing pointer-shaped word and payload length are initially zero.

The function then reads the shared-root global a second time. Through this second root, it reads the subordinate pointer at offset 4 and forms the address 732 bytes into that subordinate object. It retains this computed address and passes it to F-unknown-01.

Request mode is initially 3.

The two root reads are not interchangeable:

- The **first root** is retained for later subordinate-pointer reloads.
- The **second root** supplies only the subordinate pointer used to compute the entry/exit address.
- F-unknown-03 later receives that exact saved address; it is not recomputed from either root.

If the two reads yield different roots, entry and exit can concern a state object different from those used for request preparation and completion. Even if the roots are equal, later changes to the retained root’s subordinate-pointer field can redirect subsequent accesses.

The paired calls suggest a protected region, but no synchronization guarantee follows from their presence alone.

### Initial flag and auxiliary lookup

After F-unknown-01 returns, the function reloads the subordinate pointer through the retained first root and reads its flag at offset 775.

If that byte is nonzero, it proceeds directly to payload preparation.

If the byte is zero, it calls F-unknown-02 and reads the returned object’s byte at offset 217.

For a nonzero auxiliary byte, it reloads the subordinate pointer through the retained first root. Using that one selected subordinate object, it performs these writes in order:

1. A 16-bit write of 511 at offset 772.
2. An 8-bit write of 3 at offset 774.
3. An 8-bit write of 1 at offset 775.

It then proceeds to payload preparation without another flag test.

For a zero auxiliary byte, it instead reloads the subordinate pointer through the retained first root and rereads the flag at offset 775. A nonzero reread selects payload preparation. A zero reread selects a request without a payload.

The second flag read matters: a zero flag before the auxiliary call does not fix the eventual request form. The auxiliary dependency may change the subordinate-pointer field or reachable state.

### Optional payload preparation

On a payload path, the function reloads the subordinate pointer through the retained first root, reads the 16-bit field at offset 772, and calls F-3a7a47316439 with:

1. The address of the four-byte temporary.
2. The read 16-bit field value.

After that dependency returns, the function selects mode 4, the temporary address, and payload length 3.

It then reloads the subordinate pointer through the retained first root and reads the byte at offset 774. That read is not necessarily from the same subordinate object that supplied the 16-bit field: the intervening dependency’s mutation contract is unknown.

The function replaces the temporary’s third byte with the newly read byte. This replacement preserves the low 16 bits and the highest byte of the temporary as they exist after F-3a7a47316439 returns. In the represented payload layout, the replaced byte occupies bits 16–23.

The first two payload bytes depend on F-3a7a47316439. Its encoding and write extent are not established. The fourth temporary byte is outside the advertised three-byte payload.

Without payload preparation, the request retains mode 3, pointer zero, and length zero. The temporary still exists but is not passed as the payload.

### Submission

After optional payload preparation, the function reloads the subordinate pointer through the retained first root and reads its 32-bit field at offset 720.

It calls F-cd7e1905512f with these six arguments:

| Position | Value |
|---|---|
| First | Field read at subordinate offset 720 |
| Second | Zero |
| Third | 9 |
| Fourth | Mode 3 without payload; mode 4 with payload |
| Fifth | Zero without payload; temporary address with payload |
| Sixth | Zero without payload; 3 with payload |

The first argument is read at this stage, not captured before auxiliary lookup or payload preparation.

A zero submission result sets the low return word to 28 and skips completion processing. There is no local retry and no explicit rollback of earlier state writes.

A nonzero result is passed to one completion operation.

### Completion selection

After a nonzero submission result, the function reloads a subordinate pointer through the retained first root and reads that object’s flag at offset 775.

If the flag is zero, it calls F-addc1a87ba34 with the submission result, zero, and 500. That dependency’s returned 32-bit word becomes the low return word. The meaning or units of 500 are unknown.

If the flag is nonzero, the function reads the dispatch-table pointer from the same selected subordinate object, obtains the target at table offset 8, and invokes F-unknown-04 with:

1. That subordinate pointer.
2. The nonzero submission result.

The returned 32-bit word becomes the low return word.

Completion selection does not reuse the earlier payload decision. A payload request can select F-addc1a87ba34, and a request without payload can select indirect completion.

### Exit and return

Every normally returning active path calls F-unknown-03 with the saved address computed through the second root.

The exit dependency’s returned value, if any, is not selected as the function result. The established low word and outgoing pointer-shaped high word are concatenated into the 64-bit return value.

No exceptional-cleanup guarantee is established if a dependency fails to return normally.

## Side effects

The only explicit persistent-memory writes performed by this function are the three initialization writes at subordinate offsets 772, 774, and 775. They occur before payload preparation and submission.

The function performs no explicit rollback if submission returns zero. This does **not** establish that the written values persist until return. Payload preparation, submission, completion where applicable, and exit invoke dependencies whose mutation contracts are unknown. Such dependencies may overwrite or reverse earlier writes.

Other effects include:

- Two shared-root global reads on the active path, but only one on prerequisite rejection.
- Repeated subordinate-pointer reloads through the retained first root.
- Writes to the local temporary.
- Calls to the prerequisite, entry, optional auxiliary and payload, submission, conditional completion, and exit dependencies.

No explicit allocation or deallocation is visible. Ownership transfer is not established for shared objects, the submission result, or the temporary payload.

In particular, the source does not establish that submission copies the payload before returning, that retaining its address is safe, or that either completion dependency consumes or releases the submission result. Returning the temporary address does not extend its lifetime.

## Acceptance examples

These are conditional static expectations, not executed tests.

1. **Prerequisite rejection.** If F-59599f67673b returns zero and the second argument is `0x12345678`, the result is `0x123456780000000B`. The function reads the root global once after the prerequisite call but does not dereference that root. No active-path dependency is called.

2. **Different roots.** Suppose the first global read yields root A and the second yields root B. Let B’s subordinate pointer designate state B. Entry receives the address 732 bytes into state B. Later subordinate-pointer reloads use root A, not root B or a fresh global-root read. Exit receives the saved state-B address even if intervening dependencies change either root or its subordinate pointer.

3. **No payload, failed submission.** With a nonzero prerequisite result, zero initial flag, zero auxiliary trigger, zero flag reread, and zero submission result, submission receives mode 3, pointer zero, and length zero. The return has low word 28 and high word zero. Exit is called with the saved entry address.

4. **Triggered initialization, failed submission.** With a zero initial flag and nonzero auxiliary trigger, the function writes 511, 3, and 1 in the stated widths and order to the subordinate object selected after auxiliary lookup. It selects a three-byte, mode-4 request. If submission returns zero, the low word is 28 and the high word is the temporary address. The function performs no explicit rollback; final state values remain dependent on subsequent dependency effects.

5. **Auxiliary lookup changes request selection.** With a zero initial flag and zero auxiliary trigger, a nonzero flag reread selects payload preparation without the three initialization writes. The reread uses the subordinate pointer then obtained through the retained first root.

6. **Payload byte replacement.** If F-3a7a47316439 leaves the first two temporary bytes as `0x12` and `0x34`, and the subsequent offset-774 read yields `0x56`, the prepared payload is the three-byte sequence `0x12`, `0x34`, `0x56`. This does not establish the transform’s encoding or the payload’s state after submission receives it.

7. **Independent completion choice.** A payload request with a nonzero submission result selects F-addc1a87ba34 if the completion-time flag is zero. Conversely, a request without payload selects indirect completion if that later flag is nonzero. The high return word still reflects the earlier payload choice.

8. **Result propagation.** If the selected completion returns `0x80000005`, that exact 32-bit pattern becomes the low return word. The exit dependency is still called; its own return value does not replace that word.

Inferred intent: paired entry and exit calls appear to surround request preparation and completion. That interpretation does not prove locking, nor does it ensure that the protected object and the objects accessed through the retained first root coincide.
