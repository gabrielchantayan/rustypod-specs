# F-06cb3ab4811d

## Purpose

F-06cb3ab4811d dispatches an event against a receiver object. Its established behavior consists of:

- Direct virtual dispatch for initial event types 19 and 20.
- Conditional processing of extracted codes for initial event types 6 and 7.
- A multi-dependency processing sequence for initial event type 21.
- A final matching path that is entered only when a fresh event-type read yields 19.

The function returns a 32-bit result. Some paths forward another function’s result unchanged; others return the literal values zero or one. Consequently, the result is not established as a normalized Boolean.

Names such as “event,” “receiver,” and “dispatch” describe the apparent roles of the inputs. More specific interpretations—keyboard input, selection movement, transfer processing, or user-interface actions—are inferred intent, not established requirements.

## Interface

### Inputs

The function accepts two address-valued inputs in the supplied 32-bit representation:

1. **Receiver address.** Refers to readable object storage whose first 32-bit word identifies a virtual-function table. Some dependencies receive this address and may modify the object.
2. **Event address.** Refers to readable event storage containing at least the fields accessed on the selected path. Dependencies receive this address and may modify the event.

No null, bounds, alignment, object-lifetime, or virtual-table validation is visible. Valid storage and callable dependency targets are preconditions for normal execution.

### Receiver layout

The following byte offsets are relevant. Each listed field occupies 32 bits in the supplied representation.

| Byte offset | Established use |
|---|---|

| 0x40 | First comparison value in the final matching path |

The availability expression subtracts the field at 0xAC from the field at 0xB0 and compares the result against signed −1. This is not an ordinary nonempty check, an ordering check, or a direct comparison of the two fields.

### Output

The function produces a 32-bit return value:

- A forwarded virtual-call result for initial types 19 and 20.
- A forwarded nonzero result from F-51eeedbffa7a on certain type-6/type-7 paths.
- One for particular consumed or matched paths.
- Zero when processing reaches an unmatched final path.

No output structure or explicit error object is supplied.

## Behavior

### Initial dispatch

The first operation relevant to dispatch is a 32-bit read of the event type at offset 0x04. The initial branch decision uses that value.

The supplied representation uses signed comparisons when distinguishing values below 20 from higher values. Negative type values therefore enter the lower-valued partition, but receive no special handling unless later mutation causes the final type read to become 19.

### Initial type 19

The function calls F-682adfd5a561 with the event address and the 32-bit constant 0xC00.

After that dependency returns, the function obtains the receiver’s current virtual-table entry at offset 0x134 and invokes it with the receiver address and the dependency’s 32-bit result.

The virtual call’s result is returned unchanged. There is no subsequent final matching check.

This ordering matters: mutations performed by F-682adfd5a561 can affect which virtual table and callback are used. The contract does not assume that dependency preserves the receiver or other shared state.

### Initial type 20

This path mirrors the direct dispatch for type 19, with two differences:

- F-682adfd5a561 receives 0xC80.
- The virtual-table entry is at offset 0x138.

The virtual call’s result is returned unchanged. Final matching is not performed.

### Initial type 6 or 7

F-11c1b7e655b3 is called with the event address before the availability expression is checked.

If the availability expression equals −1, the extracted result receives no special processing. Execution proceeds to the final matching path.

If the availability expression differs from −1, the extracted result determines the next action:

| Extracted result | Action |
|---:|---|
| 0x57 | Call F-51eeedbffa7a with the receiver and 32-bit value one |
| 0x58 | Call F-51eeedbffa7a with the receiver and 32-bit value zero |
| 0x6F | Return one immediately |
| Any other value | Proceed to final matching |

For either call to F-51eeedbffa7a:

- A nonzero result is returned unchanged.
- A zero result causes execution to continue to final matching.

The availability expression uses receiver state available after F-11c1b7e655b3 returns. No preservation guarantee for that state is established.

### Initial type 21

The type-21 sequence runs only when the availability expression differs from −1. If the expression equals −1, execution proceeds directly to final matching without invoking the type-21 dependencies.

When enabled, the sequence is:

1. Call F-8bb3020950cd with the event address. Its return value, if any, is not used.
2. Call F-aa672b15efb7 with the receiver field at 0xB4, the event field at 0x0C, and a 32-bit zero. Retain its 32-bit result.
3. Call F-c0a513a969e0 with the event address.
4. Call F-be0ad8f71bac with the receiver field at 0xB4 and the result of F-c0a513a969e0. Retain this new result.

Only after all four calls does the function test the retained result of F-aa672b15efb7.

If that result is zero, the function returns one. In particular, a zero result does **not** suppress F-c0a513a969e0 or F-be0ad8f71bac.

If it is nonzero, F-a4d024505709 is called with:

- The receiver address.
- The retained nonzero result of F-aa672b15efb7.
- The retained result of F-be0ad8f71bac.
- A 32-bit value one.

If F-a4d024505709 returns zero, the function returns one without an additional visible cleanup call.

If it returns nonzero, an unmapped external dependency is called with the retained result of F-aa672b15efb7, after which the function returns one.

The receiver field at 0xB4 is consulted separately for the two calls that use it. Dependencies between those calls may change it. Likewise, the event field at 0x0C used by F-aa672b15efb7 is accessed after F-8bb3020950cd has run.

The selected type-21 path always returns one if its dependencies return normally. It does not forward their results as the dispatcher’s result.

### Final matching path

Paths that have not already returned reread the event type at offset 0x04.

If the new value is not 19, the function returns zero. The initial type is not reused for this decision. Thus, dependencies reached from an initial type 6 or 7 can make this path relevant by modifying the event or shared storage.

If the reread type is 19, the function reads the event field at 0x0C and retains that comparison value.

#### Primary match

The primary match requires both:

- The retained event value from 0x0C equals the receiver field at 0x44.
- The event field at 0x08 equals either the receiver field at 0x40 or a first global 32-bit comparison value.

The global value is consulted only when the event field at 0x08 differs from the receiver field at 0x40.

On a primary match, the function calls the receiver’s virtual-table entry at offset 0xD4 with the receiver address, ignores the callback’s result, and returns one.

#### Alternative match

If the primary match does not succeed, the function tests the receiver field at 0x9C.

When that field is zero, the function returns zero.

When it is nonzero, the alternative match requires:

- The retained event value from 0x0C equals the receiver field at 0x98.
- The event field at 0x08 equals a second global 32-bit comparison value.

The event field at 0x08 and the second global are accessed for this alternative comparison only after the 0x0C comparison succeeds.

On an alternative match, the function calls F-5710a8628cba, retains its one-byte result, then obtains the receiver’s current virtual-table entry at offset 0xA0 and calls it with the receiver and that byte value. It ignores the callback’s result and returns one.

If neither match succeeds, it returns zero.

## Side effects

No direct writes to receiver fields, event fields, or global storage are visible in this function.

Nevertheless, the function is not established as side-effect-free:

- Dependencies receive addresses or receiver-associated values.
- Virtual callbacks may modify the receiver, event, global state, or external resources.
- The final external call in one type-21 branch may affect the resource represented by its argument.

Dependency calls and virtual callbacks occur in the order described above. Reads separated by those calls must not be treated as observations of an immutable snapshot.

Within a single call’s argument preparation, the supplied representation does not establish a portable ordering between independent argument reads. A conforming behavioral account must preserve the stated call sequence without inventing a more precise machine-level load order.

No ownership transfer is established for either input. The caller must provide valid storage for every access that remains reachable after dependency effects. The apparent cleanup operation in the type-21 path is insufficient evidence to declare allocation, release, borrowing, or transfer rules.

There is no visible recovery from invalid storage, invalid virtual targets, dependency failure to return, or exceptions. A nonzero or zero dependency result has only the branch meaning explicitly described; it is not independently established as an error code.

## Acceptance examples

These are conditional static acceptance examples, not executed tests.

1. **Direct type-19 forwarding.** Given initial type 19, if F-682adfd5a561 returns a particular 32-bit value and virtual entry 0x134 returns −7, the dispatcher passes that extracted value to the callback and returns −7. It does not normalize the result to one.

2. **Type-20 selector.** Given initial type 20, the extractor receives 0xC80 and the callback is selected at 0x138, not 0x134.

3. **Extraction before availability gating.** Given initial type 6 and an availability result of −1, F-11c1b7e655b3 still runs. If the final event-type read remains 6, the dispatcher returns zero.

4. **Nonzero helper forwarding.** Given initial type 7, enabled availability, and extracted result 0x57, F-51eeedbffa7a receives one. If it returns nine, the dispatcher returns nine without final matching.

5. **Zero helper continuation.** Under the same conditions, if F-51eeedbffa7a returns zero and the final event-type read is not 19, the dispatcher returns zero.

6. **Immediate consumption.** Given initial type 6 or 7, enabled availability, and extracted result 0x6F, the dispatcher returns one without final matching.

7. **Zero type-21 retained value.** Given enabled type 21, if F-aa672b15efb7 returns zero, F-c0a513a969e0 and F-be0ad8f71bac still run. F-a4d024505709 and the final external dependency do not run. The dispatcher returns one.

8. **Type-21 conditional external call.** Given a nonzero retained type-21 value, the final external dependency runs exactly when F-a4d024505709 returns nonzero. Both result branches return one.

9. **Mutation exposes final matching.** Given initial type 6, suppose extraction changes the event type to 19 and processing otherwise continues to final matching. If the primary comparisons match, virtual entry 0xD4 runs and the dispatcher returns one. An initially type-19 event instead takes direct dispatch.

10. **Alternative callback selection after dependency effects.** Given a reached alternative match, F-5710a8628cba runs before virtual entry 0xA0 is obtained. If that dependency changes the receiver’s table, the subsequent callback selection uses the resulting table.

The supplied representation alone does not establish source-language overflow guarantees. - **documented_only — External cleanup semantics:** The unmapped dependency’s effect is not established.
- **documented_only — Global meanings:** The two global comparison values have distinct comparison roles, but their initialization, mutability, and domain meanings are unknown.
- **documented_only — Concurrency:** No synchronization or concurrent-access contract is supplied.
- **documented_only — ABI details:** Exact callback conventions and byte-argument extension are unknown.

- **Inferred intent:** Return one often resembles “handled,” but arbitrary forwarded results prevent treating every return as a Boolean.
