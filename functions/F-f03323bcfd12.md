# F-f03323bcfd12

## Purpose

F-f03323bcfd12 requests 180 bytes of storage, performs initialization through external dependencies, installs two words relative to the initialization result, and invokes an indirectly selected service operation. If that operation returns normally, the function returns the pointer supplied by the initialization dependency.

The returned pointer is not necessarily the allocation result. Likewise, the address supplied to initialization, the destination of the secondary write, and the address passed to the service operation have distinct derivations. Their equality requires conditions not guaranteed by the supplied evidence.

Construction of an object with an interior component, followed by registration or attachment, is **inferred intent**. The established contract does not depend on that interpretation.

## Behavior

### Storage request and initial source selection

F-8157a180d901 is called with a size of 180 before the shared source pointer is acquired. The allocation result is used without a visible failure check or local clearing operation.

The supplied representation contains two distinct reads of the same shared pointer location. The first supplies a pointer retained for post-initialization accesses. The second supplies the pointer through which the initial word is obtained. That initial word is written at the allocation base.

These reads must not be collapsed into an unconditional single-source assumption. If their results differ, the initial word comes from the second pointer, while the later source accesses use the first pointer.

A subsequent change to the shared pointer location does not itself redirect accesses through the retained pointer. Conversely, retaining a pointer does not preserve its contents or keep its storage alive. The intervening dependencies have no supplied preservation contract.

The initial store establishes what is written at that time, not what must remain in the allocation afterward. Later dependency effects or overlapping accesses may change it.

### Initialization address and adopted result

F-af167f4d7e19 receives the allocation address advanced by 176 bytes. Its 32-bit result is then reduced by 176, and that derived value is supplied as the first argument to F-bf74dfda5df0. The original explicit input is the second argument.

The initialization argument equals the allocation base only under additional conditions—for example, when F-af167f4d7e19 returns exactly the address it received and the arithmetic is valid. No such return-value guarantee is supplied.

F-bf74dfda5df0 supplies the pointer adopted for the remainder of the function. The later direct object accesses and the final return use this pointer rather than the original allocation result.

There is no visible requirement check that the adopted pointer:

- Is non-null.
- Equals or lies within the original allocation.
- Refers to an extent of 180 bytes.
- Has any particular concrete object type.

There is also no explicit release of the original allocation. Its disposition cannot be inferred from that omission: a dependency may retain, replace, consume, or release storage.

### Post-initialization memory updates

After initialization returns, the function reads the primary word through the retained source pointer and stores it at the adopted object base.

The same captured primary value determines where displacement metadata is read: twelve bytes before the address represented by that value. The displacement obtained there selects the destination of a secondary 32-bit store relative to the adopted object. The stored value comes from four bytes beyond the retained source base.

The established ordering boundary is important: the primary source read and primary object store occur before the secondary assignment. Within the secondary assignment, the supplied evidence does not establish whether the displacement metadata or the secondary source word is read first. Both are obtained before that assignment’s store.

The displacement for this store is derived from the captured primary value, not from a newly required read of the object’s first word. Aliasing does not change that distinction.

These operations do not establish separate, non-overlapping fields. The secondary destination may coincide with the object base, precede it, extend beyond the original allocation, or overlap source or metadata storage. Successful execution requires valid arithmetic and accesses at the actual locations; the function does not enforce those conditions.

In particular, a zero displacement causes the secondary store to replace the primary word just installed at the object base.

## Side effects

### Direct accesses

There are three explicit 32-bit stores:

- The initial word at the allocation base.
- The primary word at the adopted object base.
- The secondary word at the displacement-selected destination.

These are three store operations, not necessarily three distinct locations.

Visible reads include the two shared-pointer accesses, the initial word read, the later retained-source reads, displacement metadata, service dispatch data, and the fresh object-word read used for callback preparation. They do not constitute one atomic snapshot.

Potential aliasing matters. For example, if the adopted object overlaps the retained source, the primary store can affect the later secondary source read. The contract provides no disjointness guarantee.

### Dependency effects and ownership

The function invokes four identified dependencies followed by one indirect dependency. Their internal effects are not supplied.

No ownership transfer, retention rule, release rule, or global-preservation guarantee can be established from this body alone. In particular:

- The allocation request does not establish caller ownership of the eventual result.
- Passing an address to a dependency does not establish whether it is retained.
- A retained source pointer is not a lifetime guarantee.
- Returning a pointer does not prove that the callback left its storage valid.

An external lifetime contract is necessary for safe use.

### Preconditions and failure behavior

Normal completion requires usable storage and callable dependencies at each point of use. This includes readable shared-pointer storage, readable source words, a writable allocation base, a usable adopted pointer, readable metadata, a writable secondary destination, and readable service dispatch information.

The address supplied to initialization must also satisfy that dependency’s unknown requirements. Arithmetic and conversions must produce valid addresses for the accesses actually performed.

These are execution requirements, not validations implemented by this function. There is no visible local failure status, rollback, null-result branch, or recovery path. Fault behavior, exceptions, nonlocal control transfer, and allocator failure semantics remain **documented_only**.

## Acceptance examples

The following are conditional acceptance criteria, not observed executions.

### Stable allocation-relative arrangement

Assume both shared-pointer reads yield the same valid source, relevant memory remains stable, F-af167f4d7e19 returns its received address, and F-bf74dfda5df0 returns the original allocation. Also assume both relevant displacement reads yield 176 and all arithmetic and accesses are valid.

Initialization then receives the allocation base and the unchanged explicit input. The secondary store targets allocation plus 176. The callback’s second argument is that same address, and normal completion returns the allocation base.

These conclusions depend on the stated conditions, not on an established general object layout.

### Distinct initial source pointers

Assume the first shared-pointer read yields one valid source and the second yields a different valid source.

The initial allocation word must come through the second pointer. The later primary and secondary source accesses must use the first, retained pointer. Replacing these with one unconditional pointer acquisition would lose an established distinction.

### Changed contents during initialization

Assume initialization changes the retained source’s contents without invalidating its storage.

The later primary read observes the contents available at its later access time. The secondary source read likewise uses its own later access time. Neither is required to reproduce the initial allocation word.

No criterion may require the secondary source read to precede or follow the displacement-metadata read within their shared assignment.

### Different adopted object

Assume initialization returns a valid address distinct from the allocation.

The post-initialization stores, callback address derivation, and final return must use that adopted address. The contract does not prescribe what happens to the original allocation.

### Overlapping source and object

Assume the adopted object base coincides with the retained source’s second word, and the relevant accesses remain valid.

The primary object store can change the value subsequently read as the secondary source word. Acceptance must not require an earlier snapshot of both source words.

### Zero secondary displacement

Assume the displacement used for the secondary store is zero.

The secondary value replaces the object’s first word. Callback preparation then uses that current word unless another effect changes it first. Normal callback preparation additionally requires valid metadata relative to the resulting word; the function supplies no overlap guard or repair.

### Mutation during service retrieval

Assume service retrieval changes the object’s first word to another metadata-bearing address.

The earlier secondary store remains completed at its original destination. The callback address is derived from the changed object word and may differ from that destination.

### Allocation failure without control transfer

Assume allocation returns null, execution continues, and the source accesses succeed.

The function attempts its initial store through the returned allocation value rather than taking a visible clean-failure branch. The resulting platform behavior is unresolved; an immediate normal null return is not established.
