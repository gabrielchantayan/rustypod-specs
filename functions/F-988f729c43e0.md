# F-988f729c43e0

## Purpose

F-988f729c43e0 selectively populates caller-provided storage using three input words, shared configuration, and five opaque dependencies.

Established behavior includes metadata initialization, two size resolutions, three value/companion resolutions, a computed final candidate with an optional replacement, a conditional shared-configuration mutation, and a two-word return value. Explicit pair values proceed only when F-d7be9cfb4000 reports a zero secondary result.

Descriptor construction, alignment checking, and quotient/remainder calculations are plausible interpretations, not established dependency semantics.

This contract describes static evidence. No runtime tests have been performed.

### Arithmetic and return representation

Unless explicitly widened, arithmetic retains the low 32 bits. Threshold and final-replacement comparisons are unsigned. An all-ones sentinel means the 32-bit pattern `0xFFFFFFFF`.

The return is a 64-bit quantity constructed from:

- **Low word:** zero on success, a propagated nonzero F-1a5b45bc2955 status, or local rejection status `0x55`.
- **High word:** B initially, changed to 1 by automatic first-pair resolution and to 0 by automatic second-pair resolution.

Success therefore does not imply that the entire 64-bit return is zero.

Native byte order is not established. In particular, adjacent halfword stores must not be assigned a combined numeric word value without a byte-order assumption.

## Behavior

### Initial reads, writes, and tag decision

After capturing the configuration address, the function performs these operations in order:

1. Clears output `0x000`.
2. Reads configuration `0x004` and writes output `0x004`.
3. Captures the shared relocation base.
4. Reads configuration `0x008` and writes output `0x010`.
5. Reads configuration `0x04C`, adds the captured relocation base with 32-bit wrapping, and writes output `0x030`.
6. Clears output `0x034`.
7. Reads configuration `0x014` and writes output `0x13C`.
8. Captures the shared 32-bit comparison marker.
9. Reads configuration `0x018` and writes output `0x144`.

These capture points matter if output aliases shared storage.

The function next reads configuration sentinel `0x020`. It reads sentinel `0x024` only if the first sentinel is all ones. It then reads the 16-bit configuration tag at `0x000`, zero-extending it for comparison with the captured marker.

The tag decision is:

- If either sentinel is not all ones, write a tag.
- If both are all ones, write a tag only when the configuration tag differs from the marker.
- For a differing tag, store its low nine bits.
- For an equal tag on a branch requiring a write, read the shared replacement tag at that point and store its low 16 bits.

A tag write to output `0x150` precedes a flags write of exactly `0x10`. If no tag is written, flags are zero immediately after this decision. No preservation of that value by later dependencies is established.

### Product, selected size, and byte region

The function forms a two-word product:

- Low word: the low 32 bits of A × C.
- High word: the high 32 bits of A × C plus the low 32 bits of B × C, with wrapping.

Together these represent the low 64 bits of \((A + 2^{32}B)C\).

The reusable 32-bit working word is initialized to C before the first dependency call. Its later uses are described below.

F-1e0edc6e0bc9 receives, in order, the product low word, product high word, zero, and `0x19`. Let its primary result be Q.

Configuration `0x01C` controls the initial output `0x140` assignment:

- If its comparison read equals `0x00800000`, store \((Q+1)\times\texttt{0x00800000}\), retaining 32 bits.
- Otherwise, reread configuration `0x01C` and store that value.

After this assignment, the function captures the shared byte-source argument. It then reads output `0x140` and, if that word is unsigned-greater-than `0x20000000`, overwrites it with `0x20000000`.

Thus the byte-source capture occurs between the initial size write and the cap check. The check observes the output word, not merely an abstract saved candidate. Arithmetic wrapping precedes the cap.

F-fac138f80b6d then receives the address of output `0x038`, the captured byte-source argument, and `0xFF`. Its return is ignored. After it returns, the function directly writes zero to output `0x137`. A bounded-copy interpretation is unproven.

### Two independent sizes

The return high-word indicator is initialized to B after the byte-region processing.

The first size uses configuration selector `0x044` and output `0x008`. The second uses selector `0x048` and output `0x00C`. Processing is sequential.

For a zero selector, the function reads the current configuration base at `0x004`:

- Base at most `0x1000`: write the base shifted left four bits.
- Larger base: call F-d7be9cfb4000 with the wrapping sum base + `0xFFFF`, followed by the saved base. Multiply its primary result by that saved base, retaining 32 bits, and write the destination.

For a nonzero selector, the selector is reread for a call to F-1a5b45bc2955 with the destination output-word address. Zero status continues; nonzero status returns immediately.

The function does not preinitialize either destination before an explicit resolution. If a zero-status dependency leaves the destination unchanged, its contents depend on caller-provided storage and earlier reachable effects. No local rejection is based on whether the dependency wrote it.

A first-size error prevents second-size processing. Either size error prevents all later stages.

### Conditional shared mutation

After both sizes, configuration `0x00C` is read. Only if it is zero does the function read the current base at configuration `0x004` and evaluate the additional condition:

- Base is unsigned-less-than `0x1000`; or
- The saved product high word is zero and its low word is unsigned-less-than `0x40000000`.

The product condition matters only when the base condition is false.

If the condition holds, two ordered 16-bit stores occur:

1. `0x1000` at configuration `0x028`.
2. Zero at configuration `0x02A`.

These stores are established independently of byte order. Their combined 32-bit numeric interpretation is not. No combined atomicity or rollback is established.

The base threshold here is strict; the size-default threshold is inclusive.

### Reusable working word and three pairs

The same initialized working word is used for all explicit pair resolutions and the final replacement. It is not reset before those calls. Automatic first- and second-pair results replace it; an automatic third pair sets it to zero. Otherwise it retains its previous contents unless changed by a dependency.

| Pair | Selector | Configuration companion | Output value / companion |
|---|---|---|---|
| First | `0x034` | `0x028` | `0x014` / `0x018` |
| Second | `0x038` | `0x02C` | `0x01C` / `0x020` |
| Third | `0x03C` | `0x030` | `0x024` / `0x028` |

For the first pair:

- Zero selector sets the return indicator to 1, then calls F-dbb054086e02 with current base, current first companion, A, and B. Its result replaces the working word.
- Nonzero selector is reread and passed to F-1a5b45bc2955 with the working-word address. Nonzero status returns immediately. Zero status is followed by F-d7be9cfb4000 with the current working word and current first companion. A nonzero secondary result returns `0x55`.

For the second pair:

- Zero selector sets the indicator to 0 and obtains a new working word from F-dbb054086e02 using current base, current second companion, A, and B.
- Nonzero selector follows the same explicit-resolution status and secondary-result rules, using the second companion.

For the third pair:

- Zero selector sets the working word to zero without changing the indicator.
- Nonzero selector follows the explicit-resolution rules using the third companion.

For each pair, after successful resolution and any required check, the function first writes the working word to the output value field. **Only afterward does it reread the configuration companion and write the output companion field.** Consequently, the stored companion need not equal the companion supplied to an earlier dependency: a dependency or the value-field store itself may affect it through aliasing.

A zero-status explicit call need not overwrite the working word for subsequent processing to be defined. For example, the first explicit pair can continue using its initial C value.

No local nonzero-companion test is present. Acceptance depends on the observed secondary result, not on an established alignment predicate.

### Final candidate and replacement

After all pairs are committed, the function saves the current configuration base and calls F-d7be9cfb4000 with that base and C.

Its primary result becomes the third argument to F-1e0edc6e0bc9, called with A, B, that result, and zero.

The resulting unsigned word is shifted right three bits, with one added if any low three bits were set. This computes the ceiling of that result divided by eight, without assuming anything about the preceding dependency’s arithmetic.

F-d7be9cfb4000 then receives that candidate and the saved base. Its primary result is not used here. If its secondary result is nonzero, the candidate becomes:

\[
\text{candidate}-\text{secondary result}+\text{saved base}
\]

with 32-bit wrapping.

Configuration selector `0x040` controls replacement:

- Zero: accept the computed candidate.
- Nonzero: reread the selector and call F-1a5b45bc2955 with the same working-word address used for explicit pairs. Nonzero status returns immediately. With zero status, accept the working word only if it is unsigned-greater-than-or-equal to the candidate; otherwise return `0x55`.

There is no fresh initialization of the working word before replacement. An unchanged word may therefore supply the replacement, including zero from an automatic third pair.

On acceptance, the accepted value replaces the working word and is written to output `0x02C`. The function then reads configuration `0x010`. If nonzero, it reads the current output flags and writes them ORed with `0x08`. Success returns low word zero and the current indicator.

## Side effects

There is no rollback. Errors can leave metadata, byte-region effects, sizes, earlier pairs, dependency mutations, and the shared halfword stores in place. A rejected pair is not directly committed by this function, but dependencies may already have modified reachable storage.

The final value store and success-only flags update are skipped on earlier failure.

Configuration is not snapshotted as a whole. Later reads observe storage at their respective stages. Output/configuration overlap is neither prohibited nor made safe by visible checks. Apart from the ordering stated above, evaluation order among reads supplying arguments to one dependency is not established.

No direct allocation or release is visible. Output remains caller-supplied storage; dependency ownership, retention, allocation, and release behavior are unknown. In particular, no dependency is assumed to preserve globals, unrelated output, or previously exposed storage.

No synchronization guarantee is visible.

## Acceptance examples

These are conditional static examples, not executed tests. Unless stated otherwise, relevant storage is accessible, dependencies return normally, and no unmentioned mutation changes the described values.

1. **Untouched tag.** Both sentinels are all ones and the zero-extended tag equals the captured marker. No direct tag write occurs. Flags are zero immediately after this decision, but later dependencies need not preserve them.

2. **Tag masking.** A tag of `0x03AB` differing from the marker produces stored tag `0x01AB`, followed by flags `0x10`.

3. **Threshold distinction.** With a zero size selector and base `0x1000`, that size becomes `0x10000`. The same base does not alone satisfy the strict shared-mutation threshold.

4. **Wrapping before cap.** With Q = `0x1FF` and the special size setting, the initial size wraps to zero. If output remains zero through the cap read, it is not capped upward.

5. **First-size failure.** Status 7 from its explicit resolver yields low word 7 and high word B. Byte-region processing has occurred; later stages do not run.

6. **Unchanged initialized temporary.** With first selector nonzero, C = 24, and an explicit resolver returning zero without changing the working word, validation receives 24, absent other mutation. A zero secondary result permits committing 24.

7. **Explicit rejection.** A nonzero secondary result during first-pair checking yields `0x55`; no direct first-pair commit occurs, and the indicator remains B.

8. **Indicator precedence.** Automatic first and second pairs set the indicator to 1 and then 0. Later success returns high word zero.

9. **Reused zero replacement.** An automatic third pair sets the working word to zero. If final replacement resolution leaves it unchanged, zero is compared against the candidate: accepted for candidate zero, rejected for a positive candidate.

10. **Post-value companion read.** If a pair’s value store aliases its configuration companion, the companion read follows that store and observes the resulting storage, rather than necessarily the earlier dependency argument.

11. **Replacement boundary.** A replacement equal to the candidate is accepted. For a nonzero candidate, one less is rejected with `0x55`.
