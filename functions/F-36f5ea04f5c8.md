# F-36f5ea04f5c8

## Purpose

The supplied static representation establishes a routine that performs ordered indirect calls, width-specific memory accesses, and condition-dependent control transfers. It does not establish an application-level purpose.

Its contract is conditional on valid execution context, callable targets, accessible memory, and continuation through intervening calls. One path includes a software interrupt, a condition-state-dependent loop, terminal byte writes, a breakpoint, and an invalid-instruction boundary. The other ends with an unresolved indirect transfer followed by a represented return.

No interpretation as allocation, serialization, protocol handling, or device control is established. Control-flow recovery warnings limit confidence in treating the representation as a complete executable function.

## Behavior

### Common prefix

The following observable order precedes branch selection.

F-P01 is invoked through a target derived from the incoming link-related value. Its low result byte is stored at the fourth input plus the context displacement.

F-P02 then produces a word. The previously written location is reread as a signed byte, sign-extended to 32 bits, and supplied with that word to F-P03. The reread is observable: it is not equivalent to reusing F-P01’s result.

The complete third input is then stored as a 32-bit word at context base plus 4.

F-P04 produces a word. A signed halfword is read at context base plus context displacement and sign-extended for the second argument to F-P05; the produced word is its first argument. After F-P05, the same address is independently reread as a signed halfword and passed, sign-extended, to F-P06.

Finally, an unsigned halfword is read at the third input plus 4 and zero-extended to form the initial field.

These accesses may alias. In particular, the word store can affect later reads if the supplied addresses overlap. Intervening calls can also change subsequently observed memory.

The path is selected by represented overflow condition state: nonzero selects the overflow path; zero selects the other path. No comparison with an explicit input or the initial field establishes this selection. The operation responsible for that condition state is unknown.

### Overflow-selected path: initial effects

The first write stores the low 16 bits of the fourth input at the secondary address associated with F-P06, offset 20.

F-O01, F-O02, and F-O03 follow in order, each followed by a halfword write:

| After call | Destination | Stored bits |
|---|---|---|
| F-O01 | Its secondary address plus 12 | Low 16 bits of that same secondary value |
| F-O02 | Its secondary address plus 28 | Low 16 bits of the context base |

After F-O04, the full fourth input is stored as a 32-bit word at its secondary address plus the initial field. The initial field is an unscaled byte displacement, not an element index multiplied by four.

F-O08 produces a represented 64-bit result. Its high 32 bits become an address base; the initial field is stored there at offset 4 as a halfword. Because the initial field is between 0 and 65535, the narrowing preserves its bits.

A software interrupt with immediate **0x73** follows. Every subsequent operation on this path is conditional on execution continuing beyond it.

The lookup sequence then proceeds as follows:

### Overflow-selected path: loop, target selection, and terminal bytes

The loop condition includes an 8-bit capture of an address-shaped working value, followed by testing whether represented zero condition state is clear. The byte capture occurs even when the body is skipped and again on the final condition evaluation if the loop exits.

Each iteration invokes F-O20 and then F-O21. **F-O20 does not have one invariant target:**

- Every subsequent iteration selects a different target, **F-T02**.

The body establishes a fixed working value whose low byte is **0x60**. It also changes the target-selection state used by the next F-O20 invocation and by the first post-loop call.

Consequently, if execution reaches the terminal writes:

| Loop history | Captured terminal byte | Target selected by F-O22 |
|---|---|---|
| Body skipped | Low eight bits of the captured lookup base | F-T03 |
| At least one iteration, followed by exit | **0x60** | F-T04 |

F-T03 and F-T04 are different represented targets. F-O22 is therefore history-dependent even though its call-site ID is unchanged. The target distinction is based on whether the body executed, not merely on the condition state observed at exit.

The represented body contains no explicit update of the zero-state variable. If that state remains clear, the represented loop does not terminate. Any machine-level flag effects permitting exit are unresolved. The executed-loop outcome above is conditional; it does not assert that such an exit is possible in the actual environment.

## Acceptance examples

These are conditional static criteria, not executed tests.

1. **Signed byte reread.** If F-P01 supplies low byte **0x80**, the write succeeds, and the location still contains **0x80** after F-P02, F-P03 receives −128 as its second represented argument. If F-P02 changes the byte, the reread controls the argument instead.

2. **Independent halfword observations.** If the first common-prefix halfword read observes **0xFFFF**, F-P05 receives −1. If F-P05 changes that location to **0x0002**, F-P06 subsequently receives 2.

3. **Unsigned initial field.** A halfword observation of **0xFFFF** produces initial field 65535. Its later halfword store on the overflow path preserves all 16 bits.

4. **Unscaled lookup.** A first lookup index of 3 selects a halfword at captured lookup base plus 3. Legality of that potentially unaligned access remains platform-dependent.

5. **Skipped loop.** If the loop is skipped and the captured lookup base has low byte **0xAB**, F-O20 and F-O21 are not invoked, F-O22 selects F-T03, and the terminal stores at offsets 13 and 9 contain **0xAB**, if reached.

6. **Executed loop.** If one iteration occurs and the next condition evaluation exits, F-O20 selects F-T01, F-O21 follows, F-O22 selects F-T04, and both terminal stores contain **0x60**. If two iterations occur, F-O20’s target sequence is F-T01 then F-T02; the terminal byte remains **0x60**.

7. **Terminal addresses and third byte.** If the terminal base is **0xFE** and the second lookup index is **0x1234**, the terminal stores target addresses 267, 263, and 271, in that order. The third stores **0x34**; the first two follow the loop-history rule.

8. **Successive signed shifts.** Under the represented arithmetic-shift semantics, an originally negative fourth input produces −1 for F-N18; an originally nonnegative input produces zero.

9. **Interrupted execution.** If the software interrupt never resumes this routine, post-interrupt effects do not occur. Earlier writes have no represented rollback.

10. **Persistent clear zero state.** If zero state remains clear indefinitely, the loop has no represented exit. Neither F-O22 nor the terminal writes are then required to occur.
