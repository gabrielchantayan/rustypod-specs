# F-8c36b92195c7

## Purpose

F-8c36b92195c7 conditionally retrieves a 32-bit word from an object obtained through an indirect call and a dependent operation.

Its observable decision structure is:

- Obtain an initial result through an indirect target associated with the first input.
- If that result is nonzero, invoke F-b3bed2dfc5ec to obtain a candidate object.
- If the candidate is non-null, obtain an unsigned comparison bound through one of its indirect targets.
- If the requested index is strictly below that bound, obtain an address through another indirect target and return the 32-bit word stored there.
- Otherwise, return zero.

A collection-element lookup is a plausible interpretation, but collection semantics, element type, and object identity are not established. The contract is therefore expressed in terms of objects, bounds, addresses, and word reads.

Zero is both a fallback result and a possible successfully retrieved value. The return value alone does not distinguish those cases.

The third input is interpreted as unsigned. Its range is 0 through 4,294,967,295. Values with the high bit set are not negative indices for purposes of the visible comparison.

### Output

The output is a 32-bit word:

- Zero when the initial indirect result is zero.
- Zero when F-b3bed2dfc5ec returns a null candidate.
- Zero when the index is greater than or equal to the candidate’s unsigned comparison bound.
- Otherwise, the 32-bit contents of the address returned by the candidate’s address-producing indirect target.

The successful return is a value read, not a returned reference or an established ownership transfer. Its interpretation as an integer, pointer, handle, or bit pattern is unknown.

## Behavior

### 1. Resolve and invoke the initial target

The function reads the dispatch-table address from the beginning of the first-input object. It resolves the target at byte offset 16 of that table and invokes it.

No explicit arguments are shown for this initial indirect call. In particular, the supplied material does not explicitly pass the first-input object as an ordinary argument. An implicit receiver or register-based argument convention is possible but not established.

The call’s result is tested against zero. No signed ordering test is performed.

If the result is zero:

- F-b3bed2dfc5ec is not invoked.
- Neither candidate indirect target is invoked.
- No final word is read.
- The function returns zero.

A nonzero result, including a result whose 32-bit representation has its high bit set, passes this gate.

### 2. Obtain a candidate

For a nonzero initial result, the function invokes F-b3bed2dfc5ec with four explicit argument positions:

1. The initial result.
2. A value read from one global location.
3. A value read from a second, distinct global location.
4. An all-ones 32-bit value, equivalent to 4,294,967,295 when interpreted as unsigned or −1 when interpreted as signed.

The two global values are read for this invocation, after the initial call has returned. They are not visibly captured before the initial call.

Their argument positions are established. Their relative read order is not established by the supplied material. The widths and meanings of these global values are also not established.

The all-ones argument is passed as a fixed bit pattern. Its meaning as a sentinel, mask, identifier, or other value is unknown.

The dependency’s return is treated as a candidate-object address and tested against null. No other validation is visible.

If the candidate is null, the function returns zero without invoking either candidate target.

### 3. Obtain and compare the bound

For a non-null candidate, the function reads its leading dispatch-table address, resolves the entry at byte offset 16, and calls that target with the candidate address as an explicit argument.

The result is used as an unsigned 32-bit comparison bound.

The requested index must be strictly less than this bound. Equality is rejected.

Consequences include:

- A bound of zero rejects every possible index.
- A bound of one accepts only index zero.
- A bound of 4,294,967,295 accepts indices 0 through 4,294,967,294.
- Index 4,294,967,295 is rejected for every possible 32-bit bound.

There is no visible addition, subtraction, scaling, or index-address calculation in this function. Consequently, this function introduces no arithmetic wraparound in determining whether the index is accepted. Any address calculation performed by a dependency is outside the established behavior.

If the comparison fails, the function returns zero.

### 4. Resolve an address and read the result

When the comparison succeeds, the function accesses the candidate’s leading dispatch-table field again and resolves the entry at byte offset 20.

This second dispatch lookup occurs after the bound-producing call. The visible behavior does not require reuse of the earlier dispatch-table address. If the bound-producing call changes the candidate’s dispatch-table field, the later lookup can observe the changed field.

The address-producing target receives:

1. The candidate address.
2. The original unsigned index, unchanged.

The returned address is dereferenced immediately to read a four-byte word. That word becomes the return value.

There is no visible null check on this returned address, no additional range check, and no conversion of an invalid address into the zero fallback result.

   For index 4,294,967,295, every possible unsigned 32-bit bound rejects the request. The address-producing target is not invoked.
