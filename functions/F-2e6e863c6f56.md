# F-2e6e863c6f56

## Purpose

F-2e6e863c6f56 dispatches an operation for a normalized 32-bit identifier. Its observable behavior consists of ordered dependency calls, shared-memory reads, selected byte-sized state updates, and delivery of record pointers to F-c6c589453fa8.

Every invocation performs two context-derived lookups before evaluating the selected operation. Consequently, an unsupported operation or a branch that ultimately does nothing can still have dependency-induced effects.

The established contract concerns these calls, memory accesses, record layouts, and their ordering. Interpretations such as lifecycle management, notification delivery, or synchronization are inferred intent, not established protocol semantics.

## Interface

### Arguments

| Argument | Width | Use |
|---|---:|---|
| Context token | 32 bits | Forwarded unchanged to selected dependencies. |
| Raw identifier | 32 bits | Normalized by clearing bit 7. |
| Auxiliary value | 32 bits | Its low 16 bits populate records for selectors `0x2E` and `0x30`. |
| Operation selector | 32 bits | Compared against supported selector values; dispatch also contains signed 32-bit ordering comparisons. |
| Option value | 32 bits | Used by selectors `0x2E` and `0x30`. |

The normalized identifier is the raw identifier masked with `0xFFFFFF7F`. No other bits are cleared. Normalization is not a bounds check and does not constrain the result to an 8-bit or nonnegative signed value.

### Result and failure behavior

No explicit return value or error code is established. Completion is observable through calls and memory effects.

The function performs no visible pointer validation, bounds validation, diagnostic reporting, rollback, or exception handling. Sequences described below assume dependencies return normally. Normal return does **not** imply that a dependency preserved shared memory, global base references, or records passed by pointer.

### Shared storage

Three shared regions are referenced:

- **Primary state:** indexed bytes, a status byte at offset `1`, a 32-bit word at offset `0x1A`, and a 32-bit handle at offset `0x42`.
- **Flags:** bytes indexed by normalized identifier.
- **Records:** entries at a stride of `0x14` bytes, indexed by normalized identifier.

These are roles within the observed address calculations, not guarantees of disjoint allocations. In particular, indexed primary-state bytes can overlap the separately described fixed-offset fields.

Allocation sizes, valid identifier ranges, alignment, and concurrency rules are not established. The target environment must support the observed 32-bit accesses at offsets `0x1A` and `0x42`.

## Behavior

### Common preparation and read-time state

Before selector-specific behavior, the function:

1. Normalizes the identifier and initializes the directly assigned header fields of a temporary 20-byte record.
2. Calls an external context accessor.
3. Calls F-1bc5bcdc9cca with that accessor’s result plus four bytes and the normalized identifier.
4. Calls the context accessor again.
5. Calls F-62d1a359629f with the second accessor result plus four bytes and the normalized identifier.
6. Captures the primary-state base reference for later paths that explicitly retain it.

The first lookup’s result is stored before the second accessor call. The two accessor invocations are distinct; their results need not match.

The default record has this layout:

| Offset | Width | Assigned value |
|---:|---:|---|
| `0x00` | 1 byte | `0x0E` |
| `0x01`–`0x03` | 3 bytes | No visible initialization |
| `0x04` | 4 bytes | `0x00000010` |
| `0x08` | 4 bytes | Normalized identifier |
| `0x0C` | 4 bytes | Result from F-1bc5bcdc9cca |
| `0x10` | 4 bytes | Result from F-62d1a359629f |

Both common accessor/lookup pairs precede all branch-specific shared-state reads. Any condition below involving shared state is therefore evaluated against the value observed at its specified read, **not necessarily the value at function entry**. The common dependencies may change both region contents and global base references.

The initializer is not established to clear memory. Bytes outside the explicitly assigned fields remain governed by the initializer and the temporary storage’s otherwise unspecified contents.

### Selector `0x30`

Call F-e3db96f62982 with the normalized identifier. A zero result ends the branch without constructing or submitting its branch-specific record.

Otherwise, construct a 12-byte record:

| Offset | Width | Assigned value |
|---:|---:|---|
| `0x00` | 4 bytes | Normalized identifier |
| `0x04` | 2 bytes | `0x0031` |
| `0x06` | 2 bytes | Low 16 bits of the auxiliary value |
| `0x08` | 4 bytes | Option-dependent word |

The final word is:

- `0x000F0300` if the complete 32-bit option value is zero.
- The zero-extended low 8 bits of the option value otherwise.

The full-width zero test is significant. A nonzero option with a zero low byte produces a zero final word.

Submit through F-c6c589453fa8 with arguments zero, `2`, the record address, and `0x0C`, then return.

### Selector `0x36`

Read the primary-state status byte at offset `1`, after common preparation. Return unless the observed byte equals `1`.

On the permitted path, retain the branch’s primary-state base and modify the default record:

| Offset | Width | Replacement |
|---:|---:|---|
| `0x00` | 1 byte | Zero |
| `0x04` | 4 bytes | Word read from primary-state offset `0x1A` |
| `0x08` | 4 bytes | `1` |
| `0x0C` | 4 bytes | Zero |
| `0x10` | 4 bytes | Zero |

Call F-c6c589453fa8 with arguments zero, zero, the record address, and `0x14`.

After that call returns:

1. Read the 32-bit word at offset `0x1A` using the primary-state base captured immediately after common preparation.
2. Restore record byte `0x00` to `0x0E`.
3. Choose byte value `5` if the newly read word equals `6` or `12`; otherwise choose `4`.
4. Write the chosen byte at offset `1`, then offset `2`, using the branch-retained primary-state base.
5. Call F-c6c589453fa8 again with arguments zero, zero, the same record address, and `0x14`.

The second word read is mandatory and occurs after the first submission. It is not replaced by the earlier value stored in the record.

The function restores only record byte `0x00` after the first submission. It does not refresh record offset `0x04` or reassign the other fields. If the dependency modifies the record through its pointer, those modifications can remain in the second submission except for the restored byte.

The post-submission read and the two state writes use retained bases, not a newly resolved primary-state global reference. Their retained references are captured at different points; they must not be conflated merely because they ordinarily identify the same region.

### Selector `0x37`

After common preparation, read the primary-state byte indexed by the normalized identifier.

- If the observed unsigned byte exceeds `3`, return.
- Otherwise, write `4` to the indexed entry and submit the default record through F-c6c589453fa8 with arguments zero, zero, the record address, and `0x14`.

The direct write precedes submission. No rollback is visible if submission fails or does not return.

The decision depends on the branch’s read, not an entry-time snapshot.

### Selector `0x38`

The branch performs this ordered sequence:

1. Read the 32-bit handle at primary-state offset `0x42` and call the first external handle operation with it.
2. Read the flag byte indexed by the normalized identifier.
3. If that observed flag is nonzero, compare the normalized identifier as a signed 32-bit value with `3`.
4. Only when it is signed-less-than `3`:
   - Read the first byte of the corresponding shared record.
   - If the observed byte is not `0x0F`, call F-c6c589453fa8 with the three visible arguments zero, zero, and the shared-record address.
   - Call F-88707f7d96dd with the context token and normalized identifier, whether or not that record submission occurred.
5. Read the handle at offset `0x42` using the primary-state base captured after common preparation.
6. Call the second external handle operation with that newly read handle and return.

The flag read occurs after the first handle operation, which may have changed the flags or their base reference. The flag is read even when the identifier will fail the signed comparison. A zero flag suppresses the signed comparison and the optional record work, but not the second handle operation on a normally completing path.

A high-bit-set normalized identifier is negative under the signed comparison and can pass it. This is not an unsigned bounds check.

The handle values are separately read and need not match. No guaranteed cleanup after an intervening failure is established.

## Side effects

### Direct memory changes

The function directly writes shared storage only on these paths:

- Selector `0x37`: one indexed primary-state byte becomes `4`.
- Selector `0x36`: primary-state offsets `1` and `2` become `4` or `5`, in that order.

Dependencies can cause additional changes on every path, including before a branch’s state condition is evaluated. No dependency is established to preserve globals, region contents, handles, or supplied record contents.

### Storage lifetime and ownership

The constructed 20-, 44-, and 12-byte records belong to the invocation’s temporary storage. No explicit allocation or release is visible.

The selector `0x38` record instead resides in shared record storage.

Neither copying nor ownership transfer by F-c6c589453fa8 is established. Whether it consumes records synchronously, modifies them, or retains their addresses is documented_only. Temporary record addresses must not be assumed valid after the invocation returns.

### Arithmetic and access requirements

Identifier masking and option handling use 32-bit values. Narrow record fields discard upper bits without rejection.

Shared-record indexing uses a 20-byte stride with 32-bit unsigned multiplication; products can wrap modulo `2³²`. No overflow or bounds check is visible. A signed-negative identifier that passes selector `0x38` still participates in this unsigned address calculation.

All indexed accesses, fixed-offset accesses, and context-plus-four calculations require suitable addressable storage. The function supplies no visible mechanism for establishing that requirement.

## Acceptance examples

These are conditional static expectations, not executed tests. They assume valid accessed storage and normally returning dependencies. Shared-state values below are values **observed by the named reads**, unless explicitly described as entry-time values. Normal return alone does not guarantee state preservation.

1. **Normalization:** Raw identifier `0x82` becomes `2`. Both common lookups and any identifier-taking selected operation receive `2`.

2. **Unsupported selector:** Selector `0x2F` still performs both accessor/lookup pairs. It makes no direct record submission afterward. This does not imply absence of dependency side effects.

3. **Selector `0x37` threshold:** If the branch’s indexed byte read observes `3`, the function writes `4` before submitting the default record. If that read observes `4`, it performs neither action. An entry-time value of `4` changed to `3` by a common dependency takes the submitting path; an entry-time value of `3` changed to `4` takes the returning path.

4. **Gate failure:** A zero result from F-e3db96f62982 for selector `0x2E` or `0x30` prevents branch-specific record construction and submission. Common preparation has already occurred.

5. **Truncation:** On a permitted selector `0x2E` path, auxiliary value `0x12345678` contributes `0x5678`, and option `0x1AB` contributes byte `0xAB`. Unassigned bytes are not presumed zero.

6. **Full-width option test:** On a permitted selector `0x30` path, option zero produces word `0x000F0300`; option `0x100` produces zero; option `0x1234` produces `0x34`.

7. **Selector `0x36` read timing:** Suppose its status read observes `1`, its first word read observes `6`, and its post-submission word read observes `7`. The direct state writes are `4`. If the first submission leaves the record unchanged, the second submission still carries `6` at offset `0x04`. An entry-time status of `1` alone does not establish branch entry.

8. **Optional shared-record submission:** For selector `0x38` and identifier `2`, suppose the flag read after the first handle operation observes nonzero and the subsequent record-byte read observes `0x0F`. The three-argument submission is skipped, but F-88707f7d96dd still runs before the second handle operation.

9. **Flag before range rejection:** For selector `0x38` and identifier `3`, the indexed flag is read after the first handle operation. Neither the record-byte read nor F-88707f7d96dd occurs, regardless of the observed flag.

10. **Independent handle reads:** If the first handle operation changes the handle stored in the retained primary region, the final handle read can observe the changed value. Equality of the two handle arguments is not required.

11. **Ordered operations:** For selector `0x3A`, F-ca1c4e2f14bb returns before F-a6e52da0a17c is invoked.
