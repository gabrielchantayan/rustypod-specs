# F-14775aa715ec

## Purpose

F-14775aa715ec selects one of two 32-bit values from a caller-supplied object, initializes a local dependency-facing state region, and repeatedly invokes a dependency that can update a separate 32-bit candidate word. Each nonterminal iteration examines one byte at offset 16 from the address represented by that candidate word.

Iteration ends when either:

- The iteration dependency returns zero.
- The examined byte, after the applicable integer conversions, compares equal to the original second argument.

Both normal exit paths invoke a finalization dependency. The function returns a 64-bit value assembled from the candidate word and, on the matching path, a candidate value captured before finalization.

The apparent roles of initialization, iteration, and finalization are inferred from call placement. Their actual semantics, resource handling, and effects are not established. In particular, the function cannot be specified as a conventional lookup returning a pointer without additional dependency evidence.

## Behavior

### Selection and initialization

Before calling any dependency, the function reads one 32-bit word from the selected object offset. The selection depends only on whether the third argument is zero.

The selected word is passed by value to F-8ca21d3a8cca. No second object-field read is shown, even if that dependency changes the object or the local state.

After selecting the word and before making that call, the function seeds the local words with the comparison value, selector/state seed, and auxiliary seed. It then calls F-8ca21d3a8cca with:

1. The address of the second local word.
2. The selected 32-bit object-field value.

The supplied code does not inspect a return value from this dependency. It does not establish that the seeded local words remain unchanged afterward.

### Iteration

After initialization returns normally, the function performs at least one iteration. There is no preliminary candidate-byte check and no preliminary termination check.

Each iteration calls F-b38a3aba0e18 with:

1. The same local-state pointer used during initialization.
2. The address of the candidate word.

After that call returns, the function reads the candidate word and captures its 32-bit value for a possible matching-path return.

The dependency’s returned status is interpreted only as zero versus nonzero:

- **Zero:** The function takes the terminal path immediately.
- **Any nonzero value:** The function proceeds to the candidate-byte comparison.

Negative nonzero status values are not given a separate error treatment. The function contains no status-specific retry, diagnostic, or error mapping.

### Zero-status termination

When F-b38a3aba0e18 returns zero:

1. The candidate word has already been read into a snapshot.
2. No byte at candidate offset 16 is read by this function.
3. F-d0d3f100effc is called with the local-state pointer.
4. After that call returns, the candidate word is read again.
5. That final candidate value becomes the high 32 bits of the return value; the low 32 bits are zero.

The earlier snapshot is not used in this return construction.

Consequently, a zero status does not establish that the complete return value is zero. A nonzero candidate word after finalization produces a nonzero high half.

### Candidate-byte comparison

For a nonzero iteration status, the function reads one byte at offset 16, hexadecimal `0x10`, from the address represented by the current candidate word.

The byte is read through a plain-character type and converted to an integer before comparison with the original 32-bit unsigned comparison argument. The original comparison argument is not replaced by the candidate word, even though the candidate word was initially seeded from that argument.

The supplied text does not establish the target’s plain-character signedness:

- If plain character is unsigned, byte values 0 through 255 compare against the same unsigned values.
- If plain character is signed and uses the expected 8-bit signed interpretation, bytes `0x80` through `0xFF` first become values −128 through −1. In comparison with a 32-bit unsigned operand, those values convert to `0xFFFFFF80` through `0xFFFFFFFF`.
- Bytes `0x00` through `0x7F` have the same comparison behavior under either interpretation.

A contract must therefore not silently describe this as an unsigned-byte lookup for all byte values.

If the comparison fails, another iteration begins. There is no iteration limit, cycle detection, or visible progress requirement.

### Matching termination

When the byte comparison succeeds:

1. The snapshot captured immediately after the iteration call is retained.
2. F-d0d3f100effc is called with the local-state pointer.
3. The candidate word is read after finalization.
4. The post-finalization candidate becomes the high 32 bits of the result.
5. The retained pre-finalization snapshot becomes the low 32 bits.

The two halves need not be equal. Equality requires the candidate value used for the snapshot to remain unchanged through the finalization call and any other relevant effects.

### Nontermination
