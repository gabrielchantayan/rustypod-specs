# F-e66b65585f8c

## Purpose

F-e66b65585f8c collects nonzero 32-bit values into temporary records, combines records satisfying ordered adjacency comparisons, extracts up to two reservation values under stable caller state, and submits the starts of remaining nonempty records through a newly obtained destination handle.

“Source,” “destination,” “unit size,” “range,” and “reservation” describe inferred roles. The underlying resource types and ownership rules are not established.

The function returns a 32-bit status:

- **0:** The initial unit-size result was zero, or collection stopped before reaching the calculated capacity.
- **1:** Collection reached capacity and processing reached its normal completion path.

A return of 1 does not establish successful destination creation, successful submission, complete range consolidation, or ownership transfer. Invalid memory accesses, nontermination, and abnormal dependency behavior are not converted into these statuses by any visible mechanism.

## Interface

| Byte offset | Width | Direct role |
|---|---:|---|

| 4 | 32 bits | Source handle |
| 8 | 32 bits | Unit size |
| 12 | 32 bits | First reservation |
| 16 | 32 bits | Second reservation |

The second input is represented as a 32-bit integer and participates in capacity calculation. Its units and valid domain are unknown.

The function does not explicitly validate the state address, its alignment or extent, or the source handle. Ordinary completion requires accessible storage for every executed access. Seven words suffice for the represented direct state accesses under stable state; a quota changed externally to exceed two can cause reservation writes beyond their intended slots.

### Temporary records

The function requests storage for capacity plus one records. Each record occupies eight bytes:

| Byte offset within record | Width | Role |
|---|---:|---|
| 0 | 32 bits | Start |
| 4 | 32 bits | Length |

A fetched start of zero terminates collection without accepting that record. Later processing uses an all-ones 32-bit start with zero length as an empty-record marker. Marked records are not excluded from adjacency comparisons.

No allocation-failure check is visible. A usable temporary-storage address and a sufficiently large allocation are prerequisites for paths that access records. Passing the address to F-58ba61416cc9 does not itself establish deallocation or ownership transfer.

### Arithmetic and interpretation

State words, record fields, counts, and capacity are represented with 32-bit operands. Capacity comparisons, quota comparisons, and minimum-length comparisons are unsigned.

The second input is shifted left by ten bits before the capacity dependency is called. No widening is shown. Its represented signed type leaves the valid shift domain and behavior outside that domain unresolved; unrestricted mathematical multiplication by 1,024 is not an established substitute.

The allocation request is eight times the result of adding one to capacity. The addition and multiplication use unsigned 32-bit arithmetic, giving a request reduced modulo \(2^{32}\). There is no overflow check.

Start-plus-length comparisons, merged lengths, start advancement, length reduction, and address calculations have no visible overflow or bounds checks. The supplied representation does not establish portable signed-overflow semantics for all these expressions. It also imposes no explicit alignment, divisibility, or resource-range validation.

## Behavior

The ordering below describes the represented accesses and calls. It is not a hardware memory-ordering or concurrency guarantee. Dependency side effects can affect subsequent reads unless separately excluded.

### 1. Initial setup

Before clearing caller-owned state, F-2c6f8cec7f23 receives:

1. The source-handle word.
2. A value read from unresolved global data.
3. Zero.
4. Zero.

The global-data argument is not established as an immutable constant. Its identity, value, and broader semantics are unknown. The relative evaluation order of the source-handle read and global-data read is not established.

The setup result is ignored.

After that call returns, the function directly clears offsets 12, 16, and 20, in that order. It then reads the source handle for an unidentified unit-size dependency and stores that dependency’s 32-bit result at offset 8.

If the result is zero, the function returns 0 immediately. It makes no direct allocation request, quota assignment, or destination assignment on this path.

Statements about fields not being assigned describe this function’s direct writes only. No dependency preservation guarantee is supplied.

### 2. Capacity and allocation

For a nonzero initial unit-size result, F-d7be9cfb4000 receives:

- The second input shifted left by ten bits.
- The unit-size result retained from the preceding call.

The returned value becomes the unsigned collection capacity. The dependency’s actual arithmetic is unknown.

F-fab3799b3190 receives the calculated byte request for capacity plus one eight-byte records. Its result becomes the temporary-storage address. The accepted-record count starts at zero.

### 3. Collection

Before each source availability call, the function compares the accepted count with capacity. Reaching capacity ends collection without another source call.

Otherwise:

1. F-1ef6194d50b0 receives the source-handle word read for that call.
2. A zero result stops collection without initializing another record.
3. A nonzero result permits F-be7637a45bd4 to receive a fresh read of the source-handle word.
4. The fetched value is written as the attempted record’s start.
5. If that value is nonzero, the accepted count increases.
6. The caller-owned unit-size word is read and written as the attempted record’s length.

The record position for that length write is the position selected before the possible count increment.

If the fetched start is zero, the function next overwrites that record’s length with zero and stops collection. That record is not accepted.

The length read follows the fetch call. It need not equal the initial unit-size result used for capacity calculation: dependencies have no supplied obligation to preserve caller-owned state. Availability and fetch calls likewise have no supplied obligation to preserve earlier temporary records.

If collection stops before capacity is reached, the temporary-storage address is passed to F-58ba61416cc9 and the function returns 0. No merge, quota assignment, reservation selection, destination creation, or submission is directly performed. Previously executed source operations are not visibly undone.

A capacity of zero succeeds without availability or fetch calls.

### 4. Quota assignment

After reaching capacity, the function writes 2 to offset 24. If the accepted count divided by two, rounded down, is below 2, it subsequently overwrites that word with the smaller value.

Under stable state:

| Accepted records | Resulting quota |
|---:|---:|
| 0–1 | 0 |
| 2–3 | 1 |
| 4 or more | 2 |

The quota depends on the accepted count before merging, not on the number of nonempty records remaining afterward. The initial write of 2 occurs even when the final value is zero or one.

Reservation processing rereads the quota word rather than relying exclusively on the calculated value.

### 5. Ordered adjacency merging

Records are processed in collection order. For each current record, every later record is considered once, in increasing index order.

The first comparison tests whether the current start plus current length equals the later start. On equality, direct writes occur in this order:

1. Increase the current length by the later length.
2. Set the later start to all ones.
3. Set the later length to zero.

Only when that comparison fails is reverse adjacency tested: later start plus later length equals current start. On that equality:

1. Replace the current start with the later start.
2. Increase the current length by the later length.
3. Set the later start to all ones.
4. Set the later length to zero.

There is no sorting or fixed-point iteration. An earlier pair is not reconsidered after a subsequent merge changes one of its records. Adjacent ranges can therefore remain separate.

Zero-length and already marked records still participate in comparisons. The marker is not guaranteed to be inert, particularly near arithmetic boundaries.

### 6. Reservation selection and consumption

The completed-reservation count starts at zero. If it already meets the currently read unsigned quota, processing proceeds to destination creation.

Otherwise, candidate selection scans all accepted records:

- Record zero is the fallback candidate.
- The initial unsigned length limit is 2,147,483,647.
- A record replaces the candidate only when its length is nonzero and strictly below the current limit.
- Equal qualifying lengths retain the earlier candidate.

Lengths of 2,147,483,647 or greater never qualify through this comparison. If no length qualifies, record zero remains selected regardless of its length.

The selected record is consumed repeatedly before another minimum-length search. For each consumption while its length is nonzero and the completed count remains below the currently read quota:

1. Store its start in the caller-state word at byte offset \(12 + 4 \times\) the completed count.
2. Increment the completed count.
3. Advance the selected start by the caller-owned unit-size word.
4. Reduce the selected length by another read of that unit-size word.

Those two unit-size accesses are distinct. No single preserved value is established under external mutation.

If the selected length becomes zero, its start is set to all ones before processing continues. If the quota is filled while the length remains nonzero, the remainder is retained for destination processing.

Under stable state, only offsets 12 and 16 receive reservation values. Offset 20 is cleared during initialization but receives no later direct reservation write. This limit depends on the quota remaining at its assigned value; no independent two-slot guard is visible.

The function does not check whether a selected length is a multiple of unit size or whether any usable candidate exists. If fallback record zero has zero length while the quota remains unmet, the function marks its start and repeats selection without increasing the completed count. This can continue indefinitely. Subtraction without a suitability check also leaves underflow or other out-of-domain arithmetic unresolved.

### 7. Destination creation and submission

Once the completed count meets the currently read quota:

1. F-8157a180d901 receives 920.
2. Its result is ignored.
3. F-123968dd7326 is called without explicit arguments.
4. Its result is stored at offset 0.

If the creation result is zero, submission is skipped. Otherwise, accepted records are scanned in original index order. For each record whose length is nonzero when checked, F-ef3e50369ccb receives:

- The destination-handle word read for that call.
- That record’s current start.

The record length is not passed. Submission results are ignored.

The initial submission gate uses the creation result, not repeated destination-word checks. A dependency can therefore change the handle used by later submissions without disabling the scan.

Destination setup, creation, or earlier submissions may also affect temporary records; no preservation guarantee excludes changes before later length and start reads.

Finally, the temporary-storage address is passed to F-58ba61416cc9 and the function returns 1. This return also occurs when creation returned zero.

- Reading unresolved global data for initial setup.
- Separately reading the source handle for source-related calls.
- Clearing three caller-state words after setup.
- Storing the unit-size result.
- Requesting temporary storage when that result is nonzero.
- Performing source operations before overall success is known.
- Writing and modifying temporary records.
- Assigning quota, reservation values, and destination on the capacity-reached path.
- Calling the submission dependency for records found nonempty after a nonzero creation result.
- Passing temporary storage to F-58ba61416cc9 on each normal post-allocation return.

The function does not directly dispose of an earlier destination before replacement, restore collected source values after incomplete collection, or roll back reservations following creation failure.

These omissions do not prove leaks or ownership errors. Ownership of fetched values, reservations, destination handles, submitted starts, and temporary storage remains unspecified. Dependencies are not assumed to preserve globals or memory, acquire ownership, or release resources.
