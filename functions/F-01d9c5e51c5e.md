# F-01d9c5e51c5e

The fourth explicit input controls both write locations and two dependency arguments. The second and third explicit inputs supply the first two stored words. An implicit incoming machine-state value supplies the third stored word. The first explicit input has no visible use.

**Important limitation:** the supplied representation explicitly reports bad instruction data and truncated control flow. This contract describes its recoverable path, not a runtime-validated instruction stream.

## Behavior

### Address arithmetic

The first destination is formed by logically shifting the fourth input right by two bits, then multiplying the result by `0x2000`.

Under the 32-bit unsigned interpretation, the multiplication wraps modulo \(2^{32}\). This matters: the mathematical product can exceed the address width. A model that retains the full product in a wider host integer would produce different addresses.

Consequences under this interpretation:

- The first destination is aligned to `0x2000`.
- Its possible values range from `0x00000000` through `0xFFFFE000`.
- Only input bits 2 through 20 determine that destination.
- Input bits 0 and 1 are discarded before multiplication.
- Input bits 21 through 31 do not survive the wrapped product.
- Adding four or eight to any resulting destination does not overflow the 32-bit address space.

A second shifted quantity is independently derived from the original fourth input by a logical right shift of six bits. It is **not** obtained by shifting the earlier right-by-two result by another six bits.

The two-byte destination is this second shifted quantity plus decimal ten, equivalently `0xA`. This addition is a byte-address offset, not a two-byte element index.

For a 32-bit fourth input:

- The second shifted quantity ranges from zero through `0x03FFFFFF`.
- The two-byte destination ranges from `0x0000000A` through `0x04000009`.
- Its second byte can extend through address `0x0400000A`.
- The destination is odd precisely when bit 6 of the original fourth input is set.

Consequently, the recovered path can request an unaligned two-byte store. It does not round that address down or otherwise correct its alignment.

### Ordered stores

The recovered operation order is:

1. Store the second explicit input as four bytes at the first destination.
2. Store the third explicit input as four bytes at that destination plus four.
3. Store the implicit incoming machine-state value as four bytes at that destination plus eight.
4. Store a two-byte value at the independently computed two-byte destination.

The two-byte payload is obtained by shifting the right-by-six quantity left by twelve and narrowing to two bytes. Under the ordinary machine truncation interpretation, its low twelve bits are zero. Its high four bits come from original input bits 6 through 9.

Thus the possible two-byte bit patterns are `0x0000`, `0x1000`, through `0xF000` in steps of `0x1000`.

The signed two-byte conversion shown in the representation does not establish a signed application-level value. The intended machine interpretation is a two-byte store of the narrowed bit pattern. Exact source-language conversion rules are not independently known.

Byte order is unspecified. Four-byte and two-byte values must be laid out according to the actual target’s endianness, not an assumed host endianness.

### Overlapping destinations

The two-byte destination is not guaranteed to be disjoint from the three four-byte destinations. If it overlaps, its write occurs later and replaces the affected bytes.

In particular, when the fourth input is zero:

- The three four-byte destinations begin at addresses zero, four, and eight.
- The two-byte destination begins at address ten.
- Its zero payload overwrites the last two addressed bytes of the third four-byte store.

The final four-byte contents at address eight therefore need not equal the incoming implicit value. Which numerical half is replaced depends on endianness.

No buffering, transactional grouping, or rollback is represented. If an operation faults, preceding completed writes may remain observable. The exact treatment of a faulting or misaligned individual access belongs to the execution environment.

Under 32-bit unsigned arithmetic, each of the first two arguments retains only original input bits 6 through 13, placed in argument bits 24 through 31. The lower twenty-four bits are zero.

The first two argument values are equal. This does not establish that their semantic roles are the same.
