## Purpose

### Important ordering constraints

The initial word write precedes every indirect call.

Each byte-indexed write reads its index before performing the write. The index is an unsigned byte used directly as a small address base, not as an offset into an established larger object. Consequently, these byte writes target addresses from `0x11` through `0x110`.

The two reads used to form F-X054’s first and third arguments are distinct displayed memory accesses. Their relative evaluation order is not established. Both follow the preceding word write and precede entry into F-X054. A contract must not replace them with one read when repeated reads can be observable.

The captured word in stage 20 is read before F-X084 and retained across the subsequent dependency calls. Stage 21 does not reload its source address.

The byte-index reads in stages 24 and 26 use the same address expression but occur on opposite sides of F-X104–F-X110. The second read must not be replaced by the first read’s value. Those dependencies may change the addressed memory.

### Arithmetic distinctions

The following distinctions affect observable values:

- Masking with `0x3FFFFFFF` before shifting right twenty positions yields at most ten bits. The subsequent byte write retains only the low eight.
- Shifting the unsigned auxiliary word right twenty-two positions also yields at most ten bits before byte truncation.
- `(packed low word AND 0x1FFFFFFF) >> 9` produces at most twenty significant bits.
- The stage-22 masked first argument depends on the low six bits of the scaled value, not on six unrestricted bits of the unscaled result.
- Under 32-bit word arithmetic, shifting `result(088)` left thirty positions retains only its lowest two bits.
- The stage-9 arguments and stage-10 stored value are zero in the displayed straight-line path. They are not values fetched from mutable global storage.

## Acceptance examples

These examples are conditional static checks, not executed tests.

1. **Initial write ordering.** Given valid entry storage and a returning F-X001, the entry stored word must already have been written at entry state base plus `0x14` when F-X001 begins.

2. **Byte truncation.** If the first sample is `0x41`, stage 2 supplies `0x104` to F-X006 but writes byte `0x04`. Retaining the full word in memory would violate the displayed access width.

3. **Mask and truncation.** If the first sample is `0x3FF00000`, stage 3’s masked shift is `0x3FF`, and its byte store writes `0xFF`.

4. **Low-address zero write.** If the byte at absolute address `1` is `0x80` when stage 6 executes, the zero byte is written at address `0x91`. No larger base address is added.

5. **Independent return halves.** If F-X033 produces low half `2` and high half `3`, stage 10 writes zero at `0x20`, and F-X034 receives `3`. Subject to intervening dependencies returning, stage 12 writes `0x08000000` at `0x20000014`.

6. **Repeated reads may differ.** If stage 14 reads a changing device-backed location, F-X054’s first and third arguments may derive from different observed words. A single cached read is not justified.

7. **Retained snapshot.** If stage 20 captures `0xABCDEF00`, stage 21 stores `0x000ABCDE`, even if an intervening dependency changes the original source location.

8. **Late index refresh.** If stage 24 reads index byte `4` and stage 26 reads index byte `9`, their byte writes target `0x15` and `0x1A`, respectively.

9. **Thirty-position shift.** Under 32-bit word semantics, a stage-22 source result of `3` contributes `0xC0000000` as F-X094’s third argument; a source result of `4` contributes zero.

10. **Interrupted prefix.** If F-X030 does not return, neither F-X031 nor any subsequent direct memory operation is established to occur. No rollback of earlier writes is visible.
