# F-0bf5b32a119a

## Purpose

F-0bf5b32a119a conditionally populates selected words of a caller-provided output array using an opaque input context. Its visible behavior comprises prerequisite checks, position-style operations, a two-stage numerical transformation, construction of up to 128 cumulative entries, and conditional population of four final fields.

Structured-input parsing is an inferred purpose, not an established format contract. Field meanings, units, encodings, and record boundaries are unknown.

This contract distinguishes explicit operations from dependency behavior. In particular, a dependency may retain a previously supplied address and modify its destination during a later call. A value assigned before a dependency call is therefore not necessarily the value read afterward.

## Behavior

### 1. Prerequisite checks

The function calls F-515aecae630e with the context and a local scratch address.

Only when that result is zero does it call F-66310ffff1d9 with the context, selector **3**, and the address of a local 32-bit temporary.

A nonzero result from either call ends the visible processing path. Neither early-exit path explicitly writes the output array. The dependencies may nevertheless have changed the context or other state.

The value produced through the selector-3 destination is not used before that temporary is explicitly reassigned later. However, the address has been exposed to a dependency; retention and subsequent mutation are not ruled out.

### 2. Initial position-style operation and primary output

After both prerequisite checks return zero, the function performs these operations in order:

1. Calls F-e1f67c338342 with the context and a second local scratch address.
2. Assigns **56** to the local 32-bit temporary previously supplied to selector 3.
3. Calls F-674655f0e759 with the context and captures its returned 32-bit value.
4. Reads the temporary **after F-674655f0e759 returns**.
5. Passes the captured return value plus that post-call temporary value to F-c019388e82bf, together with the context.
6. Calls F-9b88190fe3bf with the context and the address of output word 0.

The argument to F-c019388e82bf is therefore not unconditionally the preceding return value plus 56. That simplification requires F-674655f0e759 to preserve the temporary. Its address was previously supplied to F-66310ffff1d9, and the supplied material does not exclude retained-pointer mutation during F-674655f0e759.

“Position-style” describes the relationship between the calls, not verified seek semantics. The results from F-e1f67c338342, F-c019388e82bf, and F-9b88190fe3bf are not checked here.

### 3. Numerical transformation

The function reads output word 0, applies a left shift of three bit positions in a 32-bit expression, and supplies the result as the first argument to F-d7be9cfb4000.

The second argument is read from a separate local 32-bit quantity. The supplied body contains **no explicit defining write** to that quantity. Its initialization and validity are unresolved. Adjacency to scratch storage does not establish that a dependency initializes it.

The first numerical result is captured as a 64-bit value. Subsequent processing is:

- Extract the upper 32 bits and interpret them as a signed 32-bit value.
- Multiply that signed value by 1000.
- Call F-d7be9cfb4000 again, supplying the product and a fresh read of the unresolved local quantity.
- Use the second result as a 32-bit integer.
- Add it to the first result’s lower 32 bits, interpreted as a signed 32-bit integer and multiplied by 1000.
- Assign the resulting 32-bit expression to output word 1.

The two second-argument reads are separate observations. Their equality is not established across the first numerical call.

The body does not establish division semantics, quotient/remainder packing, physical units, or an equivalent higher-level formula. No portable out-of-range arithmetic rule is supplied.

### 4. Count acquisition and limit

The function calls F-66310ffff1d9 with selector **6** and the temporary’s address. Its return value is ignored.

It then calls F-9b88190fe3bf with output word 6’s address and reads that word as an **unsigned 32-bit count**.

The captured count determines a local processing limit:

- Counts from 0 through 128 select that many iterations.
- Counts greater than 128 select 128 iterations.

The function does not write the clamped value back to word 6. Later dependency mutation of that output word is not excluded, but it does not change the already captured local limit.

An all-ones 32-bit count selects 128 iterations. It is not treated as a negative count.

### 5. Cumulative-entry construction

The cumulative accumulator starts at zero. For each selected iteration, in increasing index order:

1. The current accumulator is written to output word 7 plus the iteration index.
2. F-9b88190fe3bf is called four times consecutively, each with the same local temporary destination.
3. The temporary is read after the fourth call and added to the accumulator.
4. F-9b88190fe3bf is called a fifth time with that temporary.
5. F-e1f67c338342 is called with the second scratch address.
6. F-9b88190fe3bf is called a sixth time with the temporary.
7. F-674655f0e759 is called, and its returned 32-bit value is captured.
8. The temporary is read **after F-674655f0e759 returns**.
9. F-c019388e82bf receives the context and the captured return value plus eight times that post-call temporary value.

Each iteration therefore contains six F-9b88190fe3bf calls.

The accumulation uses the temporary immediately after the fourth word-output call, with no intervening dependency call. In contrast, the position-style calculation does **not** capture the temporary immediately after the sixth word-output call. F-674655f0e759 intervenes. Equating the position contribution with the sixth call’s result requires an explicit preservation assumption.

The fifth word-output value has no direct arithmetic use before subsequent dependency calls. Its write and any associated dependency effects still occur.

Each cumulative entry records the prefix **before** adding that iteration’s contribution. When at least one iteration occurs, the first explicit cumulative write is zero. The final accumulator is not separately stored.

No loop dependency status is checked. An unwritten temporary may leave an earlier value available for later use. If the captured count exceeds 128, there is no explicit additional iteration or separate operation consuming the excess entries.

### 6. Optional final fields

After the loop, including a zero-iteration loop, the function calls F-66310ffff1d9 with selector **1** and the temporary’s address.

If the result is nonzero, the function returns it without the subsequent final-field operations.

If the result is zero, the function:

1. Calls F-e1f67c338342 twice, using the second scratch address both times.
2. Calls F-9b88190fe3bf twice, using the temporary’s address both times.
3. Reads the temporary and compares it with 1.

For discriminator **1**, it assigns word 2 to 1, then calls F-9b88190fe3bf with word 3, word 4, and word 5 as destinations, in that order.

For every other discriminator, the explicit order is:

1. Assign word 2 to zero.
2. Read word 0 and assign that value to word 3.
3. Assign word 4 to zero.
4. Read word 0 again and assign that value to word 5.

The two fallback copies are separate reads. There is no dependency call between them, but they are not represented as one captured value.

The return remains the saved zero selector status, regardless of the ignored results from these later dependency calls.
