# F-d066d4e59df7

## Purpose

F-d066d4e59df7 publishes a five-word memory record, samples two halfwords, and updates other storage according to whether an address argument is zero. Successful completion returns an opaque 64-bit token unchanged.

This is an ordered memory-update operation, not a checked record-construction interface. It has no visible capacity check, address validation, status result, or recovery mechanism. A zero address selects additional updates; it does not suppress the read four bytes beyond that address.

The record and several symbolic destinations suggest saved-state bookkeeping. That is **inferred intent**, not an established architectural effect. The available evidence does not establish exception delivery, processor-mode changes, or control transfer.

All behavior below is based on static evidence. No runtime tests have been performed.

## Interface

| Contract role | Representation | Meaning |
|---|---|---|
| Header | Unsigned 32-bit integer | Supplies the record’s four-bit header field. |
| Address input | Signed 32-bit integer | Supplies an address calculation and selects the zero-address behavior. |
| Record destination | Pointer to unsigned 32-bit words | Identifies writable record storage; its own address is also recorded. |
| Adjustment | Signed 32-bit integer | Supplies a record field after subtraction of 31. |
| Return token | Opaque 64-bit value | Returned without modification on normal completion. |

There is no explicit record length, capacity, ownership flag, or error-output parameter.

### Additional incoming state

Three incoming machine values also influence the operation:

- A signed 32-bit **region selector**.
- An unsigned 32-bit **first saved value**.
- An unsigned 32-bit **second saved value**.

These are contract descriptions, not additional declared parameters. Their delivery mechanism is unresolved. An adapter exposing only the five explicit inputs would be incomplete unless it also supplied this incoming state.

The **region base** is the region selector multiplied by 268,435,456, equivalently hexadecimal 10000000. This multiplication is represented as signed 32-bit arithmetic; behavior outside its representable range is not established.

### Initial record layout

The record occupies five consecutive 32-bit words, totaling 20 bytes.

| Byte offset | Value initially written |
|---:|---|
| 0 | Header’s highest four bits, expressed as an unsigned value from 0 through 15. |
| 4 | Record destination converted to an unsigned 32-bit integer. |
| 8 | Adjustment minus 31, converted to an unsigned 32-bit word after the subtraction. |
| 12 | First saved value. |
| 16 | Second saved value. |

The address field describes the record itself. It is not an address obtained by reading the record.

The table specifies initial writes, not an unconditional final-state layout. Subsequent destinations may overlap the record. Byte order within each word is not established.

### Output and completion requirements

Normal completion returns the exact incoming 64-bit token. No part of the return value reports whether a particular memory update occurred.

Successful execution requires all selected accesses to be supported by the environment, including their address interpretation, mapping, permissions, and alignment. The record must provide accessible storage for its five word writes.

Five additional symbolic destinations appear in the zero-address behavior. Their declarations are unavailable. Consequently, their assignment values and relative ordering are established, but their physical widths, address ranges, and destination-type conversions are not.

## Behavior

### Record publication and sampling

The five record writes occur in ascending byte-offset order. The region-base calculation follows those writes. Both halfword reads occur afterward, before the path-specific updates.

The two samples are:

| Sample | Access width | Address |
|---|---:|---|
| Address sample | Unsigned 16 bits | Address input plus 4 |
| Region sample | Unsigned 16 bits | Region base plus hexadecimal 28 |

The address sample is read first. The region sample is then read and zero-extended to 32 bits. Where the address sample is assigned to a symbolic destination, it is also zero-extended to 32 bits.

Both reads belong to both paths. In particular:

- A nonzero address input does not eliminate the address-sample read, even though that sample has no subsequent use on that path.
- A zero address input makes the first read target numeric address 4.
- No later update causes either sample to be read again.

These ordering rules matter when the record and sample locations overlap. A sample can observe bytes written during record publication rather than bytes present on entry.

The stated ordering is the order expressed by the available static body. It is not a separate guarantee of externally observable hardware ordering, access atomicity, or synchronization.

### Nonzero-address behavior

For a nonzero address input, the additional update is a 32-bit write at region base plus hexadecimal 30. Its value is the zero-extended region sample.

There are no explicit assignments to the five symbolic destinations on this path. Their storage is not necessarily preserved: the record or the additional word write could alias it.

After the word write completes, the operation returns the unchanged token.

### Zero-address behavior

For a zero address input, five symbolic assignments and two explicitly 32-bit stores follow the samples.

For this contract, the symbolic destinations are identified only as A through E. These labels do not assert architectural roles or independent backing storage.

| Destination | Assignment value, before any unresolved destination conversion |
|---|---|
| A | Region base minus 5 |
| B | Unsigned 32-bit value hexadecimal FFFFFB00 |
| C | Zero-extended address sample |
| D | Region base |
| E | Second saved value |

The first symbolic update is to A. A 32-bit store of the zero-extended region sample at region base plus hexadecimal 3B follows it. The update to B follows that store. The remaining symbolic assignments occur in C, D, E order.

After all five symbolic assignments, the operation writes the 32-bit value hexadecimal 0000008D to **absolute numeric address hexadecimal 30**. This address is independent of the region base.

Thus the two paths have different final-store destinations when the region base is nonzero:

- Nonzero-address behavior uses region base plus hexadecimal 30.
- Zero-address behavior uses absolute hexadecimal 30.

The token is returned unchanged after the final store completes.

### Integer widths and arithmetic limits

Header extraction is unsigned 32-bit arithmetic. Only the original header’s highest four bits contribute to the result.

The adjustment subtraction occurs in a signed 32-bit expression before the result is stored as an unsigned word. Its representable input range begins at −2,147,483,617. For example, an adjustment of zero produces −31, whose unsigned 32-bit representation is hexadecimal FFFFFFE1. An adjustment of −2,147,483,618 would require a subtraction result below the signed 32-bit minimum; wrapping is not an unconditional contract.

The region-base product is representable for selectors from −8 through 7 inclusive.

The address-input addition is representable when that input is no greater than 2,147,483,643. Its lower signed endpoint does not introduce an underflow because the added amount is positive.

For every selector whose region-base product is representable, the positive offsets hexadecimal 28, 30, and 3B also remain within signed 32-bit range. On the zero-address path, however, subtracting 5 from the base is not representable for selector −8. The combined representability range for that path is therefore −7 through 7.

Representable arithmetic does not establish usable memory. Negative calculated addresses, low numeric addresses, and pointer conversions still require an environmental interpretation.

Under a separately established low-32-bit wrapping model, the region-base bit pattern would depend only on the selector’s lowest four bits, shifted into the highest four bit positions. That is a **conditional machine-model consequence**, not a guarantee supplied by the signed expressions themselves.

## Acceptance examples

These examples are **conditional acceptance criteria derived from static evidence**, not executed tests. Unless stated otherwise, they assume representable arithmetic, successful accesses, no overlap, and compatible representations for symbolic destinations.

### Ordinary nonzero-address result

Given a header of hexadecimal A1234567, adjustment 63, saved values hexadecimal 11223344 and 55667788, and selector zero, the initial record is:

| Byte offset | Expected word |
|---:|---|
| 0 | Hexadecimal 0000000A |
| 4 | The environment-defined unsigned 32-bit conversion of the record destination |
| 8 | Hexadecimal 00000020 |
| 12 | Hexadecimal 11223344 |
| 16 | Hexadecimal 55667788 |

With a nonzero address input and region sample hexadecimal BEEF, the additional store writes hexadecimal 0000BEEF to numeric address hexadecimal 30.

The address sample must still be acquired before the region sample. The returned token must match all 64 incoming bits.

### Zero address with a nonzero region base

Let the selector be 1, the address input be zero, the halfword at numeric address 4 be hexadecimal 1234, and the region sample at hexadecimal 10000028 be ABCD.

The symbolic assignment values are:

| Destination | Value |
|---|---|
| A | Hexadecimal 0FFFFFFB |
| B | Hexadecimal FFFFFB00 |
| C | Hexadecimal 00001234 |
| D | Hexadecimal 10000000 |
| E | The second saved value |

The region-sample word store targets hexadecimal 1000003B and writes hexadecimal 0000ABCD. It occurs between the assignments to A and B.

The final word store targets absolute hexadecimal 30 and writes hexadecimal 0000008D. It does not target hexadecimal 10000030.

Acceptance requires support for the unaligned store and remains conditional on the unresolved symbolic-destination representations.

### Zero does not avoid a low-address read

If numeric address 4 is unreadable, choosing a zero address input does not permit successful completion by bypassing the sample.

In an otherwise valid execution, record publication precedes the attempted read. The zero-path assignments have not yet been reached. No rollback or successful return is established.

### Record and sample overlap

Suppose a nonzero address input is four bytes below the record destination, with valid arithmetic and address conversion. The address sample then targets the record’s first two bytes.

The sample follows publication of the header-derived word. Its precise value depends on byte order and memory semantics; it cannot generally be specified as the record’s entry contents.

### A later write replaces a record field

Suppose the nonzero path’s destination at region base plus hexadecimal 30 coincides with the record’s first word.

That word first receives the header-derived value and later receives the zero-extended region sample. Acceptance must therefore distinguish the initial layout from final memory.

### Representability boundary

Selector −8 has a representable region-base product. On the zero-address path, the required subtraction of 5 is outside signed 32-bit range.

A wrapped assignment to destination A is not an unconditional acceptance requirement. Such a result requires an independently established arithmetic model.
