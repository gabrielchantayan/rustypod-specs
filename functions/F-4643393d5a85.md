# F-4643393d5a85

## Purpose

F-4643393d5a85 performs a lookup and conditionally prepares and submits a new node. It reports a position descriptor and a 32-bit indicator through a caller-provided result destination.

The controlling distinction is whether F-347fcc605342 returns a zero or nonzero pointer-like value. A nonzero result is reported without allocation or insertion. A zero result causes allocation, initialization, a conditional growth sequence, and submission to F-09c9a6de563d.

“Lookup,” “node,” “growth,” and “insertion” describe inferred roles. The supplied body establishes the calls, arguments, arithmetic, memory accesses, and branches, but not matching rules, container invariants, successful insertion, or ownership transfer.

This contract covers the visible normal-return execution. Dependency failures, exceptions, nonlocal exits, and cleanup outside that execution remain unresolved.

### Growth decision

After allocation and initialization handling, the function reads the unsigned 32-bit count-like field at object offset +32. Let that value be \(n\). It calculates:

\[
q=(n+1)\bmod 2^{32}.
\]

It then reads the unsigned 32-bit threshold at object offset +12. Growth is selected when:

\[
\text{threshold}\le q.
\]

This decision is retained; it is not recomputed after growth-related dependencies run.

When growth is selected, the requested value is:

\[
r=\left(n+\left\lfloor n/2\right\rfloor\right)\bmod 2^{32},
\qquad
g=\max_{\mathrm{unsigned}}(r,q).
\]

The right shift is applied to an unsigned 32-bit value. Both additions and the comparisons use unsigned 32-bit behavior. No saturation, overflow rejection, or unbounded-integer capacity calculation is established.

The growth sequence is:

2. Pass \(g\) to F-9e5e664c8ae7, obtaining another 64-bit result.
3. Call F-596e18a33aec with four 32-bit arguments: the low half and high half of the second result, followed by the low half and high half of the first result.

## Side effects

The initialization sequence has two distinct zero stores:

- An unconditional 32-bit zero at temporary-region offset +16, immediately after the external initializer returns.
- A conditional 32-bit zero at allocation offset +16, after copying four temporary words into a nonzero allocation.

Only the second depends on allocation success. The first remains part of the observable contract because the initializer has received the temporary address.

For a nonzero allocation, this function directly writes its first 20 bytes; the first 12 bytes are written twice. It performs no direct write to allocation offsets +20 through +23.

There is no direct count increment, threshold change, link update, or result-destination dereference. Dependencies may perform such operations or mutate globals, object state, or aliased input memory.

Consequently, payload values may differ from the input values used for lookup. Count and threshold reads also occur after allocation and initialization dependencies have run.
