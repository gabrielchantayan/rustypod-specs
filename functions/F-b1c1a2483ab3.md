# F-b1c1a2483ab3

## Purpose

2. Four-byte `5` or `6` at the same offset.

No dependency result is treated as an explicit failure code; the shown result-dependent branches select configuration or optional action. If a dependency does not return normally, the remaining sequence is not guaranteed. If it invalidates retained storage, subsequent accesses may be unsafe.

## Acceptance examples

These are conditional criteria derived from static evidence, not executed tests.

1. **Exact initial comparison.** If the first F-e10d3ae06e3b result is `2`, F-ab0bc45e128a receives false. Replacing the comparison with a general nonzero test would violate the contract.

2. **Intermediate state is observable.** Before the second F-e10d3ae06e3b call, offset `0x8D0` receives `4`. A zero return is followed by `5`; any nonzero return is followed by `6`.

3. **Preparation replaces the subordinate pointer.** If F-7631c8a2a446 replaces outer offset `0x13C`, selection uses the pointer read after that call. If a later dependency replaces it again, the remaining sequence still uses the retained selection.

4. **Configuration reads current state.** Suppose the caller writes `6` at offset `0x8D0`, but a dependency before F-0f42e4e83c67 changes it to `9`. With no intervening change before the argument read, that call receives `9`.

5. **Zero branch rereads the configuration field.** Suppose F-3d7d83ce7f2a returns zero, the first F-ec4636593a88 argument read yields `12`, that call changes the field to `20`, and the second call changes it to `30`. The two component calls receive `12` and `20`; F-e7b5b40d1609 receives `30`.

6. **Nonzero branch supplies zeros selectively.** For any nonzero F-3d7d83ce7f2a result, the first F-ec4636593a88 call still receives the current field value. The second receives zero, and F-e7b5b40d1609 receives zero.

7. **Optional action precedes clearing.** A zero F-8521306e7404 result skips F-138b8a65f896. A nonzero result causes one call before the caller clears offset `0x8C8`.

8. **Byte boundary.** The direct write at offset `0x18` changes only that byte. Changes to adjacent bytes cannot be attributed to this direct write; dependency effects remain unrestricted.

9. **Distinct slot-C reads.** If the capture after the first dispatch yields `40`, while the separate read used by the second dispatch yields `41`, the second dispatch receives `41`; the third and fourth receive `40`. This is conditional on such read results being possible in the execution environment and does not assert any particular concurrent-memory mechanism.

10. **Captured value survives later slot changes.** If the second dispatch changes slot C, the third and fourth still use the value captured before second-call evaluation. Changes to E or F before their respective reads can affect those later arguments.

11. **Targets are reevaluated.** If a dispatch changes the subordinate object’s table pointer or the selected table entry, a later dispatch consults the then-current target rather than necessarily reusing the earlier one.
