# F-56d26bd66e23

- Returns a locally determined result of 0, 1, or 2.
- Calls F-34450fd9a80e with the same object address, then returns either that dependency’s result or 0.

## Behavior

### Initial gate

The first operation is a read of the primary flags at offset 0x24, testing bit 0x04.

- If that bit is clear, the gate permits further processing without reading the gate flags.
- If that bit is set, the function reads the gate flags at offset 0x2C and tests their bit 0x04.
  - If this second bit is clear, the function returns 0 immediately.
  - If this second bit is set, processing continues.

Thus, the only blocking combination is primary bit 0x04 set and gate bit 0x04 clear.

When the gate blocks, the function does not call F-34450fd9a80e and does not read the secondary flags. The selector cannot override a blocked gate.

### Zero-selector path

After the gate permits processing, a zero selector triggers local evaluation.

The function reads the primary flags again, this time testing bit 0x08. This is a separate source-level read, not an explicit reuse of the value used by the initial gate.

- If bit 0x08 is clear, the function returns 1. No secondary-flags read is reached.
- If bit 0x08 is set, the function reads the secondary flags and tests bit 0x20.
  - If bit 0x20 is set, the function returns 1.
  - If bit 0x20 is clear, the function reads the secondary flags again and tests bit 0x80.
    - If bit 0x80 is set, the function returns 2.
    - Otherwise, the function returns 0.

For stable memory, the local decision can be summarized as follows:

| Primary bit 0x08 | Secondary bit 0x20 | Secondary bit 0x80 | Result |
|---|---|---|---|
| Clear | Not read | Not read | 1 |
| Set | Set | Not tested | 1 |
| Set | Clear | Set | 2 |
| Set | Clear | Clear | 0 |

Bit 0x20 has precedence over bit 0x80. If both are set in a stable secondary word, the result is 1, not 2.

F-34450fd9a80e is never called on this path.

### Nonzero-selector path

After the gate permits processing, any nonzero selector causes exactly one direct call to F-34450fd9a80e, passing the original object address.

Subsequent behavior depends first on the returned integer:

- If the dependency returns 0, the function returns 0 without any further direct object reads.
- If the dependency returns a nonzero value, the function reads the primary flags again and tests bit 0x08.

For a nonzero dependency result:

- If primary bit 0x08 is clear:
  - A dependency result equal to 2 is replaced with 0.
  - Any other dependency result is returned unchanged.
  - The secondary flags are not read.
- If primary bit 0x08 is set:
  - The function reads the secondary flags and tests bit 0x02.
  - If that bit is set, the dependency result is returned unchanged, including a result of 2.
  - If that bit is clear, the function returns 0.

The delegated-path decision is therefore:

| Dependency result | Primary bit 0x08 after the call | Secondary bit 0x02 after the call | Result |
|---|---|---|---|
| 0 | Not read | Not read | 0 |
| Nonzero, other than 2 | Clear | Not read | Dependency result |
| 2 | Clear | Not read | 0 |
| Nonzero | Set | Set | Dependency result |
| Nonzero | Set | Clear | 0 |

The post-call reads occur after the dependency returns. No pre-call flag snapshot is explicitly retained for these decisions. If the dependency changes the object, those changes can therefore affect result filtering.

The initial gate is not rechecked after the dependency returns. Changes to primary bit 0x04 or gate bit 0x04 do not trigger another gate decision during the same invocation.

### Read ordering

At the supplied listing’s evaluation level, reads are ordered and conditional:

1. Primary flags for the initial gate.
2. Gate flags only if primary bit 0x04 was set.
3. Either local evaluation or the dependency call.
4. Further reads only as required by the selected path and preceding results.

Repeated reads of a word must not be treated as an established atomic snapshot. Conversely, the listing does not prove hardware load counts, volatile-access semantics, or synchronization guarantees.

## Acceptance examples

These are conditional acceptance cases derived from static evidence, not executed tests. Unless an example specifies a change during the call, flag storage is assumed stable and valid.

1. **Blocked gate.** Primary flags contain 0x04 and gate flags contain 0. Either selector must produce 0. The dependency must not be called.

2. **Gate-flags access bypassed.** Primary bit 0x04 is clear. The gate-flags word is not read, regardless of its hypothetical value.

3. **Local early result.** The gate permits processing, the selector is zero, and primary bit 0x08 is clear. The result must be 1 without reading secondary flags.

4. **Local precedence.** The gate permits processing, the selector is zero, primary bit 0x08 is set, and secondary flags contain both 0x20 and 0x80. The result must be 1.

5. **Local result 2.** With the same gate and selector conditions, primary bit 0x08 set, secondary bit 0x20 clear, and secondary bit 0x80 set must produce 2.

6. **Local result 0.** Under those conditions, clearing both secondary bits 0x20 and 0x80 must produce 0.

7. **Dependency returns zero.** With the gate open and any nonzero selector, a dependency result of 0 must produce 0 without post-call flag reads.

8. **Special filtering of 2.** A dependency result of 2 with post-call primary bit 0x08 clear must produce 0. Setting secondary bit 0x02 cannot change this outcome because that word is not read on this branch.

9. **Forwarding a negative result.** If the dependency returns −7 and post-call primary bit 0x08 is clear, the result must be −7, not 1 or 0.

10. **Conditional forwarding of 2.** If the dependency returns 2, post-call primary bit 0x08 is set, and secondary bit 0x02 is set, the result must be 2. Clearing secondary bit 0x02 instead must produce 0.

11. **Dependency mutation matters.** Suppose primary bit 0x08 is clear before delegation, but the dependency sets it and secondary bit 0x02 before returning 2. If storage remains valid, the post-call decisions must accept 2.

12. **All nonzero selectors share a branch.** Selectors 1 and −1 select the same control-flow path for otherwise identical conditions. The selector is not passed to the dependency.
