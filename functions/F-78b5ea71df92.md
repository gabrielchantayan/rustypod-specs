# F-78b5ea71df92

## Purpose

F-78b5ea71df92 conditionally modifies three signed-integer fields in caller-supplied storage. A signed-integer argument, designated **K**, determines which modifications apply. Each field has its own distinguished values and update rules.

The established contract concerns comparisons, arithmetic, conditional memory access, and ordered mutations. Interpreting the fields as positions adjusted after removal is plausible intent, not established behavior. In particular, the supplied representation does not restrict K or the fields to nonnegative values.

The function returns no value and provides no explicit success or failure indication. Its body contains no calls, allocation, or release operations.

## Interface

### Inputs and storage layout

The inputs are a reference to signed-integer storage and the signed integer K. The relevant storage comprises four consecutive integer slots:

| Slot | Contract designation | Role |
|---|---|---|
| 0 | Address-bearing field | Supplies an integer used to locate an indirect threshold |
| 1 | Field A | Conditionally decremented and normalized |
| 2 | Field B | Conditionally replaced or decremented |
| 3 | Field C | Conditionally decremented or replaced using the threshold |

The processing order is **A, C, B**, despite B preceding C in storage.

Each field is evaluated using the value obtained when that field is read. K is the supplied argument value, not a field reloaded from the state region.

Normal completion requires readable storage for A, C, and B. A selected mutation additionally requires writable storage for its destination. The address-bearing field and indirect threshold need to be readable only when C equals K and C is not −3.

### Widths and address formation

The supplied representation identifies signed integer operations but does not independently establish their width, the pointer width, alignment requirements, or endianness.

If the integers are 32 bits wide, the four slots begin at byte offsets 0, 4, 8, and 12, respectively, and their signed range is −2,147,483,648 through 2,147,483,647. These offsets and bounds are conditional on that interpretation, not unconditional ABI requirements.

The threshold location is obtained by adding the integer constant **4** to the value of the address-bearing field and then interpreting the sum as an address of a signed integer. This is integer addition before address conversion. It is not an advance by four integer slots, and native-width pointer arithmetic is not established.

On a path requiring the threshold, the addition must have defined semantics, the integer-to-address conversion must be supported, and the resulting location must permit the required integer read. A representable sum alone does not establish a usable address.

### Outputs and ownership

The outputs are mutations of A, C, and B. There is no returned status, replacement state reference, or separately produced object.

No ownership transfer is expressed. The function does not explicitly allocate, free, or replace the state region or threshold storage. Their allocation, initialization, lifetime, and ownership outside this function remain `documented_only`.

## Behavior

### Field A: adjustment with a negative-result sentinel

A has an unconditional exemption for the starting value −2. For any other starting value, it remains unchanged when K is greater than that value.

Otherwise, A is reduced by one. A nonnegative result remains as written; a negative result is replaced with −2.

This normalization does not mean that all initially negative values are immediately replaced. The comparison with K still controls eligibility. For example, an initial A of −3 remains −3 when K is −2, but becomes −2 when K is −4.

The decrement and normalization are separate represented writes. With A initially 0 and K equal to 0, the writes are first −1 and then −2. With A initially −1 and K equal to −1, both writes store −2. These distinctions belong to the represented access sequence; they do not guarantee distinct externally observable machine transactions.

The decrement must itself be defined. Normalization does not repair an arithmetic operation whose result is outside the applicable signed range.

### Field C: strict adjustment and threshold boundary

C has an unconditional exemption for −3. That value is preserved without consulting either the address-bearing field or the threshold, including when K is also −3.

For other values, the relationship to K determines the outcome:

| Starting relationship | Outcome |
|---|---|
| C is greater than K | C is reduced by one; no threshold access |
| C is less than K | C is unchanged; no threshold access |
| C equals K | The indirect threshold is read and determines whether C becomes −3 |

On the equality path, C is preserved if its sampled value is less than the threshold. It becomes −3 if its sampled value is greater than or equal to the threshold. Threshold equality therefore selects replacement.

C has no general negative-result normalization. A decrement may produce −3 or another negative value solely through arithmetic. For example, C initially −2 with K equal to −4 becomes −3 without any threshold read.

The comparison against the threshold uses C’s already sampled value. The representation does not show a fresh read of C after obtaining the threshold.

### Field B: equality and distinguished-value precedence

B initially equal to −4 is always preserved. No relationship between K and −4 overrides this exemption.

For other starting values:

| Starting relationship or value | Outcome |
|---|---|
| B equals K | B becomes −4 |
| B is less than K | B is unchanged |
| B is greater than K and equals −2 | B is unchanged |
| B is greater than K and is neither −4 nor −2 | B is reduced by one |

The −2 exemption is narrower than the −4 exemption. B equal to −2 becomes −4 when K is also −2; it is not preserved merely because its starting value is −2.

There is no normalization after a B decrement. Negative results remain as calculated. For example, B initially −5 with K equal to −6 becomes −6.

### Arithmetic limits

For A, the decrement is eligible when K is less than or equal to A, apart from A’s −2 exemption. Consequently, A and K can both equal the minimum representable signed integer while selecting a decrement. Its mathematical result is outside the signed range. The supplied representation does not establish wrapping or any defined final value for that case.

The B and C decrement conditions require the sampled field to be strictly greater than K. With ordinary signed ordering and representable inputs, neither decrement can therefore start at the minimum signed value.

The address-bearing addition has a separate boundary. Under an ordinary 32-bit signed model, values greater than 2,147,483,643 cannot be increased by 4 within the signed range. Neither wraparound nor a valid threshold address is established for those values.

## Side effects

### Access ordering

A is read and any A writes occur before C is read. C processing, including any indirect threshold access and C write, completes before B is read. Any B write is last.

On the threshold path, the address-bearing field is read before the threshold, and the threshold is read before any resulting C replacement.

No direct write to the address-bearing field appears. No write through the threshold address appears. An overlap between threshold storage and a state field does not create an additional write through the threshold reference.

These are ordering properties of the supplied representation, not promises of atomic execution, synchronization, or preservation of individual stores by every execution environment.

### Conditional access and aliasing

An unusable address-bearing value is not consulted when C is −3 or differs from K. The function does not validate that value on an unselected path.

The threshold storage is not established to be separate from the state region. Assuming a permitted overlap, coherent memory, valid accesses, and no external interference:

- A threshold overlapping A observes A after all of this invocation’s A updates.
- A threshold overlapping B observes B before this invocation updates B.
- A threshold overlapping C observes the sampled equality-path value of C. The threshold comparison is then equal, so C becomes −3.

These consequences do not establish that every such overlap is legal under the applicable memory model. Alias legality remains `documented_only`.

### Failures and partial mutation

There is no explicit validation, recovery handler, rollback, or error-reporting channel.

The body does not check storage validity, write permission, alignment, arithmetic representability, or the validity of the converted threshold address. For invalid arithmetic or memory access, this contract asserts no defined recovery or completed result.

The operation is not transactional. A may already have changed before a threshold access fails. A and C may already have changed before a later B access fails. No restoration of earlier values is shown.

No synchronization mechanism appears. Concurrent access permissions, visibility to other observers, and hardware-level atomicity are unresolved.

## Dependencies

There are no function-call dependencies in the supplied body, so no additional opaque function IDs are required.

The indirect threshold is a conditional memory dependency. Its producer, semantic meaning, initialization, ownership, lifetime, and permitted aliases are unknown.

Execution also depends on platform rules for signed-integer arithmetic, integer-to-address conversion, alignment, and memory access. The supplied representation does not independently resolve those rules.

Additional acceptance conditions distinguish mutation history, access selection, and arithmetic boundaries:

**A’s intermediate mutation.** Starting with A equal to 0 and K equal to 0 requires the represented writes −1 followed by −2. A final-state-only description does not capture the entire represented effect. Starting with A equal to −1 and K equal to −1 instead produces two writes of −2.

**B’s unconditional −4 exemption.** With B equal to −4 and K equal to −5, B receives no write. A rule that decrements every value greater than K except −2 is incorrect.

**B’s conditional −2 exemption.** With B equal to −2, K equal to −2 selects replacement with −4. K equal to −3 selects no write.

**Threshold boundary.** When C equals K and is not −3, a threshold one greater than C preserves C, while an equal threshold replaces it with −3. The “one greater” case presupposes representability.

**Threshold access exclusion.** With C equal to −3, neither the address-bearing field nor the threshold is read, for any K. With C differing from K, the same access exclusion applies, although a decrement may still occur.

**Threshold overlapping A.** With A and C initially 0 and K equal to 0, a valid threshold overlap with A observes −2 after A’s normalization. C consequently becomes −3.

**Threshold overlapping C.** If a valid overlap with C is used on the equality path, the threshold equals C’s sampled value and replacement with −3 follows.

**A’s arithmetic boundary.** With A and K both −2,147,483,648, no defined final state or normal completion is asserted under the ordinary 32-bit signed model.

**Address arithmetic boundary.** If threshold access requires adding 4 to an address-bearing value of 2,147,483,647 under that model, no threshold read result or completed state is asserted.
