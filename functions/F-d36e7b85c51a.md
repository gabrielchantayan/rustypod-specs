# F-d36e7b85c51a

## Purpose

F-d36e7b85c51a repeatedly invokes unresolved dependencies and performs byte and 32-bit memory accesses. Dependency results determine subsequent call arguments, addresses, stored values, and state carried into the next iteration.

The supplied static representation establishes no application-level purpose. It does not establish that the accessed addresses designate allocated objects, device registers, or valid memory. Repeated stores of the same payload are observable behavior, not evidence of a particular copying or synchronization operation.

This contract describes the represented ordering and dataflow. Arithmetic consequences that require a machine-width interpretation are identified separately from established static evidence.

## Interface

### Additional state

- **S**: a 32-bit incoming quantity used to address the first word read, later replaced.

- **G**: a global word sampled once per iteration that reaches that access.

These are document-level names, not assertions about object layout or ABI-defined parameter passing. In particular, the additional return-register quantity is not established as an entry input: its producer contract is unresolved.

### Completion and errors

There is no represented normal return or result value. Each completed iteration unconditionally begins another.

This does not guarantee continued execution. A dependency may fail to return, transfer control elsewhere, or fault; a target or memory address may be invalid. No explicit error return, timeout, recovery, validation, or rollback appears.

### Widths and arithmetic notation

A **byte** is eight bits; a **word** is 32 bits. Byte reads used as selectors are unsigned. Byte stores retain only bits 0–7.

For the formulas below, multiplication, addition, and left shifts use a **conditional 32-bit bit-pattern model**, discarding bits above bit 31. Right shifts described as logical insert zeros. This model makes the arithmetic consequences explicit; complete target arithmetic and address semantics remain unresolved. Signed operations in the supplied representation alone do not establish portable overflow behavior.

For a represented 64-bit result, **low word** means bits 0–31 and **high word** means bits 32–63. This is a numerical split, not a claim about memory byte order.

Two recurring access descriptions are used:

- **Selected-byte write at base X with value V**: read one unsigned byte at address **X + 1**, then store the low byte of **V** at the absolute address **selector + 17**. The destination is not relative to X.
- **Field byte of V**: the low byte of **(V AND 0x3fffffff) logically shifted right by 20**; equivalently, bits 20–27.

Successful traversal requires every encountered dependency to return and every encountered access to be permitted by the execution environment. No validity checks establish those preconditions.

## Side effects

### Access widths and layout limits

The direct body performs unsigned byte reads, byte stores, 32-bit word reads, and 32-bit word stores. It establishes no containing structure, allocation extent, or pointer-field layout.

A selected-byte destination ranges from absolute address **17 through 272**, inclusive. The saved-selector word destination ranges from **20 through 275**, inclusive, with the word occupying additional consecutive bytes according to the platform’s storage rules.

The latter store can be unaligned: selector 1 gives starting address 21. Alignment requirements and fault behavior are unresolved.

### Ordering and aliasing

All described direct accesses retain their order relative to dependency calls. In particular:

- The first word store precedes the source-word read.
- The saved-selector word store precedes the global sample.
- Each selected-byte write reads its selector before storing.
- The closing byte stores precede the next iteration’s calls.

Any computed addresses may alias each other, global storage, or memory accessed by dependencies. Unknown byte order prevents a complete expansion of overlapping byte and word effects.

No atomicity, inter-thread synchronization, transactional grouping, or rollback is established.

### Ownership

No direct allocation, retention, ownership transfer, or release is established. Dependency behavior remains unknown; absence of explicit pointer-like arguments does not prove that a dependency cannot access, retain, or release shared storage.

Captured represented values do not establish a general register- or global-preservation contract for dependencies.

## Acceptance examples

These are conditional static consequences, not runtime observations. They assume valid accesses, returning dependencies where needed, and the stated arithmetic model.

1. **Argument truncation.** A fourth argument of **0x123456ab** makes the first direct stores write **0xab** at B + 17 and then B + 1, regardless of intervening dependency changes to memory.

2. **Absolute selected destination.** A selected-byte operation reading **0xff** stores at absolute address **272**, not at its base plus 272.

3. **Retained selector.** If the selector captured after F-U05 is 1, the word store after F-U06 starts at address **21**, even if F-U06 changes B + 1.

4. **Fresh selector.** If dependencies between two selected-byte operations change their selector location, the later operation uses the newly read byte. Equal nominal bases do not permit eliminating the read.

5. **Field extraction.** U equal to **0x3ff00000** produces field byte **0xff**. U equal to **0xc0000000** produces field byte zero.

6. **Wide split.** Pair one equal to **0x1122334455667788** gives high word **0x11223344** and H equal to **0x5599de20** after 32-bit truncation.

7. **Restricted next base.** Fifth payload index 3 gives next B equal to **0xc0000000**. Under the arithmetic model, the replacement B has only four possible values, selected by the index’s low two bits.

8. **Interrupted iteration.** If F-U17-02 never returns, F-U17-03 and all subsequent listed accesses are not reached. No failure result or compensating write is represented.
