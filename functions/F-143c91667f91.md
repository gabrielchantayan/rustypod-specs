# F-143c91667f91

## Purpose

F-143c91667f91 conditionally submits a flag-bearing byte to a dependency, then submits the fixed value `0x0C`, and finally invokes another dependency with two selected 32-bit values and a late-read 32-bit context value.

The conditional byte is controlled by fields in a caller-supplied object. A nonzero 16-bit field at offset `0x24` takes precedence over the 16-bit field at offset `0x26`. Either qualifying field causes a value-producing dependency to run; one flag bit is then forced into the low byte of its result.

This describes the established selection and call sequence. The meanings of the submitted values, the object, and the final operation are unknown. In particular, the evidence does not establish that the submissions are output bytes, commands, protocol messages, or rendering operations.

## Behavior

### Entry reads

The function first captures S1, S2, and S3 from the seed word, in that order. These reads precede the object’s control-byte read and every dependency call.

It then reads the byte at object offset `0x29`.

If that byte is zero, the function bypasses both condition-field reads and all conditional-submission work. P remains S3 and Q remains S2.

### Higher-priority condition

When the control byte is nonzero, the function reads the 16-bit field at offset `0x24`.

If that field is nonzero:

1. F-20093902d86a is called with no explicit arguments.
2. Its result is captured as an unsigned 32-bit value, **R**.
3. Q becomes R, and P becomes S1.
4. F-89969fa9f4b8 is called with the object address and the value `(R OR 0x40) AND 0xFF`.

The field at offset `0x26` is not read on this path. Its value cannot override or supplement the higher-priority selection.

The conditional submission receives only the low eight bits of the flagged result. Q retains the full 32-bit result R; it is not replaced by the truncated submission value.

### Lower-priority condition

If the control byte is nonzero but the field at offset `0x24` is zero, the function reads the 16-bit field at offset `0x26`.

If this field is nonzero:

1. F-20093902d86a is called with no explicit arguments.
2. Its result is captured as an unsigned 32-bit value, R.
3. P becomes R, and Q becomes S1.
4. F-89969fa9f4b8 is called with the object address and the value `(R OR 0x20) AND 0xFF`.

Again, the conditional submission uses only the low eight bits after the flag is forced. P retains all 32 bits of R.

If both condition fields are zero, there is no call to F-20093902d86a and no conditional submission. P remains S3 and Q remains S2.

### Fixed submission and final invocation

Every path that reaches this stage calls F-89969fa9f4b8 with:

1. The original object address.
2. The fixed numeric value `0x0C`.

When a conditional submission occurs, it precedes this fixed submission.

After the fixed submission returns, the function reads the current context root and loads T as a 32-bit word from offset `8` relative to that root. It then calls F-7bfe7eab76c1 with these arguments, in positional order:

1. The original object address.
2. The fixed numeric value `4`.
3. P.
4. Q.
5. T.

The function then returns without an explicit result.

The supplied representation places the load of T in preparation for the final call. It establishes that the load follows the fixed submission and precedes entry into F-7bfe7eab76c1. It does not establish an otherwise observable order among independent argument evaluations.

### Arithmetic and value preservation

The conditional-submission arithmetic is unsigned, 32-bit bitwise arithmetic:

- The higher-priority path forces bit `0x40`.
- The lower-priority path forces bit `0x20`.
- Masking with `0xFF` limits the submitted numeric value to `0` through `255`.

No addition is used to set either flag. An already-set flag bit remains set without carrying into adjacent bits.

The mask affects only the argument sent to F-89969fa9f4b8. It does not narrow R when R is later passed to F-7bfe7eab76c1.

The address calculations use fixed byte offsets. Validity of the resulting addresses is a precondition; the evidence does not establish intentional address wraparound behavior.

## Acceptance examples

These are conditional acceptance criteria derived from the supplied representation, not runtime observations. Each assumes valid accessed memory and normally returning dependencies.

### Disabled conditional path

Given a zero control byte and entry captures S1 = `0x11`, S2 = `0x22`, S3 = `0x33`:

- Neither condition field is read.
- F-20093902d86a is not called.
- F-89969fa9f4b8 receives only the fixed submission, `0x0C`.
- The final call receives P = `0x33` and Q = `0x22`.

The distinct captures matter if the seed reads can observe different values. This example does not assert that concurrent unsynchronized mutation is supported by the original execution environment.

### Enabled, neither condition set

Given a nonzero control byte and zero values at both condition offsets:

- The reads occur in the order `0x29`, `0x24`, `0x26`, after the three seed reads.
- There is no value-producing call or conditional submission.
- The fixed submission and final invocation still occur.
- P and Q remain S3 and S2.

### Higher-priority condition wins

Given a nonzero control byte, a nonzero field at `0x24`, and R = `0x12345681`:

- Offset `0x26` is not read.
- The conditional submission value is `0xC1`.
- The next submission value is `0x0C`.
- The final call receives P = S1 and Q = `0x12345681`.

This remains true even if the lower-priority field would also be nonzero.

### Lower-priority condition

Given a nonzero control byte, zero at `0x24`, nonzero at `0x26`, and R = `0xABCDEF40`:

- The conditional submission value is `0x60`.
- The fixed submission follows.
- The final call receives P = `0xABCDEF40` and Q = S1.

The final argument selection retains the upper 24 bits that the conditional submission discards.

### Already-set flag

Given the higher-priority path and R = `0x00000040`, the conditional submission is `0x40`, not `0x80`.

Given the lower-priority path and R = `0x00000020`, the conditional submission is `0x20`, not `0x40`.

### Late context selection

Suppose the fixed submission changes the context root to another valid context before returning. The final call must receive the 32-bit word at offset `8` from that new root, rather than a value captured before the submission.

### Seed mutation during a dependency

Suppose a qualifying path captures S1, then F-20093902d86a changes the seed word before returning R. The selected baseline argument remains the captured S1. The function does not reread the seed to populate that argument.
