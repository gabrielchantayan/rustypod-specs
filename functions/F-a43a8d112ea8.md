## Behavior

### Ordering rules

The following order is the visible order within this function, not a claim about compiler barriers or bus transactions.

An **intervening call sequence** means the literal ordered indirect invocations occurring between the described accesses. These calls must not be removed, merged, or treated as pure. Many sequences contain several calls with no explicit arguments, with the last explicit result multiplied by four or shifted left by two for a subsequent call. A displayed no-argument invocation does not establish that its target has no machine-state inputs.

A **scaled registration store** below means the recurring four-byte write of four times a call result at the numerical address twenty plus sixteen times that same result. This phrase is only shorthand for an observed access pattern; it does not imply registration semantics or ownership.

### 1. Entry byte writes and initial calls

Before any visible call, the function:

1. Reads the byte at displacement one from the incoming address-like value.
2. Writes the low byte of the incoming data value to the resulting byte-selected destination.
3. Calls the first unresolved dependency with the first explicit argument.

Several further indirect calls follow. One produces a result used later as a left-shift-by-two argument.

The function then reads the selector byte again and writes the low byte of the incoming data value logically shifted right by 22. Consequently, this second payload consists of original bits 22 through 29, not the most significant byte.

The selector is reloaded. An intervening dependency can therefore redirect the second store by changing the selector.

### 2. Global capture and repeated parameter-derived store

After another call sequence, the function captures the globally addressed scalar through conversion to an unsigned 32-bit value.

It computes the destination:

**twenty plus four times the unsigned third argument shifted right by seven.**

It stores the captured value there, invokes a dependency with that captured value, and makes additional calls. It then writes the same captured value to the same previously computed destination a second time.

The second store does not reload the global scalar. It overwrites any intervening change to that destination if execution reaches it. The destination arithmetic for this particular expression fits within 32 bits for every unsigned 32-bit third argument.

### 3. First word snapshot

A later dependency result supplies the first scaled registration store. Immediately afterward, the routine loads a four-byte word at twenty plus four times that result. Call this the **first word snapshot**.

The store and load use different scaling factors. They are not interchangeable accesses to one location, although they coincide when the result is zero and can alias under other address interpretations.

A subsequent dependency receives four explicit values: the sixteen-scaled result, the four-scaled result, the result shifted left by 26, and the four-scaled result again.

Further calls pass two separately obtained return values onward to other dependencies. After the intervening sequence, the function repeats the earlier scaled registration store using the retained original address and payload.

### 4. Second word snapshot

Another result supplies a new scaled registration store. The function then loads a four-byte word at twenty plus four times this new result. Call this the **second word snapshot**.

An indirect call receives the four-scaled result twice. Subsequent calls obtain and forward further results.

After these calls, the function writes the second word snapshot logically shifted right by eight back to the address from which that snapshot was loaded. It does not reload that word before shifting it.

### 5. Operations derived from the first word snapshot

The next stages retain the first word snapshot independently of later memory changes:

- A new scaled registration store occurs.
- A dependency receives the first word snapshot shifted right by sixteen.
- After more calls, the function writes a retained four-scaled result at twenty plus that same four-scaled result.
- A further result produces another scaled registration store.
- A dependency receives that store’s sixteen-scaled address component.
- Later, a dependency receives a newly obtained value together with the first word snapshot shifted right by sixteen.
- The earlier scaled registration store is repeated with its retained payload.

A subsequent scaled registration store precedes a call receiving both its four-scaled result and eight times the first word snapshot shifted right by eight.

Following additional calls, the function writes that retained four-scaled result at twenty plus the eight-scaled snapshot-derived quantity.

The snapshot is shifted **before** multiplication by eight. This is not extraction of a single byte: all bits remaining above the low eight participate.

Another scaled registration store follows. A later dependency receives:

- The eight-scaled snapshot-derived quantity twice.
- The first word snapshot shifted right by sixteen.

The left shift occurs before the right shifts. Subject to 32-bit unsigned interpretation, the composite retains only the earlier result’s low six bits and shifts those bits left by five. It is not equivalent to an unrestricted left shift by five.

After more calls, the routine writes the eight-scaled snapshot-derived quantity at twenty plus that same quantity.

### 6. Secondary-result and further scaled writes

A subsequent result produces another scaled registration store. Retain its unsigned four-scaled payload as the **selector seed**. After further calls, the function stores the first word snapshot shifted right by 24 at a newly returned four-scaled destination.

### 7. Final word-stage transition

A new result produces a scaled registration store. Its sixteen-scaled component is passed twice to a dependency, together with the first word snapshot shifted right by 23.

After further calls, the function writes that sixteen-scaled component at twenty plus itself.

For the following byte operations, the routine computes a **selector base** by clearing the selector seed’s top bit and logically shifting the remainder right by seven. Its range is zero through 16,777,215.

### 8. Byte-output sequence

A dependency receives the full shifted value three times. Several calls follow. The selector byte is reloaded, and another byte is stored at the newly selected destination. This payload comes from the earlier result with its top two bits cleared, shifted right by twenty, then truncated to eight bits. It selects original bits 20 through 27.

Another call result supplies the next byte payload, again through left shift by two and low-byte truncation. The destination is twenty-eight plus the first word snapshot shifted right by 31. Thus the visible destination is either 28 or 29.

Immediately afterward, with no intervening dependency invocation, the function reloads the byte at selector base plus one and writes zero to its byte-selected destination.

The loop then repeats indefinitely in the displayed control flow:

- Several more calls occur.
- The terminal byte selector is reloaded, and zero is written to its selected destination.
