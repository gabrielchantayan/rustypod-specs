# F-472f505654a1

## Purpose

F-472f505654a1 obtains one status value, evaluates selected error fields, conditionally invokes a diagnostic dependency, and returns a Boolean result.

The established behavior is a status classification and diagnostic-dispatch operation. A true result means that none of the status conditions that this function treats as failure were present. It does **not** establish that the underlying operation succeeded in every respect: several status bits are ignored, and some field values are examined only when a separate error gate is active.

The diagnostic identities suggest CRC-related and end-bit-related errors in a data-transfer context. That interpretation is inferred intent, not evidence of any transfer, retry, recovery, or hardware access performed directly by this function.

## Behavior

### Single status acquisition

The function invokes F-a0d99869473e exactly once before making any diagnostic invocation.

All subsequent classification uses that returned value. The function does not refresh the status between diagnostics. A dependency’s possible changes to external status or other global state do not cause a second status acquisition in this invocation.

If the status provider does not return normally, subsequent behavior and a Boolean result are not established.

### Primary error gate

The function first determines whether either primary bit is set by testing mask `0x00C00000`.

If neither primary bit is set:

- No primary diagnostic is requested.
- The secondary selector in bits 19–21 is not used to request a diagnostic.
- Processing still reaches the independent final error-group test.

If at least one primary bit is set, the function processes the two primary conditions and then the secondary selector, in that order.

**Bit 22:** When set, it requests the diagnostic identified as a write-data CRC-response error.

**Bit 23:** When set, it requests the diagnostic identified as a read-data CRC error.

When both bits are set, both requests occur. The bit-22 diagnostic precedes the bit-23 diagnostic.

Either primary bit makes the eventual Boolean result false, provided execution returns normally. The absence or presence of a secondary diagnostic cannot reverse that failure.

### Secondary diagnostic selector

The selector is the status masked with `0x00380000`. It is examined for diagnostic dispatch only inside the active primary-error gate.

Exactly two selector values are recognized:

| Masked selector | Selected diagnostic identity |
|---|---|
| `0x00280000` | Write-data CRC error |
| `0x00380000` | Write-data card-CRC error |

For every other selector value, no secondary diagnostic is requested.

These are exact masked comparisons. Consequently:

- Bits outside positions 19–21 do not affect which secondary diagnostic is selected.
- The two recognized values select different diagnostics.
- No invocation requests both secondary diagnostics.
- A recognized selector without either primary bit set produces no secondary diagnostic.

When a secondary diagnostic is requested, it follows all applicable primary diagnostics. Processing then continues to the final error-group test.

The secondary diagnostic path explicitly maintains a false result. Because that path is reachable only when a primary bit has already established failure, the selector changes diagnostic output but does not independently enlarge the set of failing status values.

### Independent final error group

After the preceding processing, the function tests mask `0xFF000000`.

If any bit in positions 24–31 is set:

- The result is false.
- One diagnostic identified as a read-data end-bit error is requested.

This is one aggregate test, not one diagnostic per set bit. A status with several bits set in this group still produces only one final-group diagnostic.

This test is independent of the primary-error gate. It runs whether the gate was inactive, whether a secondary selector matched, or whether a primary diagnostic was already requested.

When present, the final-group diagnostic is the last diagnostic requested by this function.

### Overall result and ordering

On a normally returning execution, the result is true exactly when the status masked with `0xFFC00000` is zero.

That combined mask includes bits 22–31. It excludes the secondary selector and the low-order ignored bits.

The diagnostic order is fixed:

1. Write-data CRC-response diagnostic, if bit 22 is set.
2. Read-data CRC diagnostic, if bit 23 is set.
3. One selected secondary diagnostic, if the primary gate is active and the selector matches.
4. Read-data end-bit diagnostic, if any bit in positions 24–31 is set.

Conditions determine which entries are omitted. At most four diagnostic invocations occur.

A zero status produces true and no diagnostics. Nonzero status values can also produce true when their set bits are confined to positions 0–21.
