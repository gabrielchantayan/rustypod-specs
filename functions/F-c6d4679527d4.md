# F-c6d4679527d4

## Purpose

F-c6d4679527d4 conditionally processes a record using a mutable context, a byte-classification dependency, and three callbacks obtained from that context. It reports a size-like value and a payload-start-like address through caller-provided output locations, advances the context’s current position, and returns a 32-bit success indicator.

The established behavior is narrower than a complete binary-data reader. This function does not itself validate the returned size against the available region, copy payload bytes, or establish that the reported range is accessible. Any such work performed by callbacks is outside the visible contract.

The apparent intent is to recognize a permitted leading byte, obtain a size, process the associated prefix, and identify the following payload. Those roles are inferred from the operations and diagnostic reference. The ordering, state accesses, and return conditions below are established by the supplied static evidence.

## Interface

### Arguments and result

The function receives three address-valued arguments:

1. **Context:** a pointer to a mutable, word-indexed structure.
2. **Size output:** a pointer to a writable 32-bit location.
3. **Start output:** a pointer to a writable 32-bit location used to hold an address-like result.

It returns a 32-bit value:

- **1:** the recognized-input path completed, and the context’s status word was zero when checked at the end.
- **0:** either the recognition condition failed or the final status word on the recognized-input path was nonzero.

A return of zero does not imply that outputs or context state were left unchanged.

## Behavior

### 1. Capture the boundary and invoke the entry callback

The function first reads the boundary word at context offset 8 and retains its address value.

It then reads and invokes the entry callback at offset 28. No explicit argument is shown for this call. Its return value is not used.

The captured boundary remains the comparison boundary for this invocation. A callback change to the boundary field does not replace that captured value.

By contrast, the current position is read after the entry callback returns. A change to the current-position field can therefore change both the recognition decision and the byte examined.

No assumption is made that the entry callback preserves status, output storage, callback slots, or other global state.

### 2. Evaluate the recognition condition

Recognition requires both of the following:

1. The current position, read after the entry callback, compares strictly below the captured boundary as an address.
2. F-cfad0582408b returns a nonzero result when passed the byte read through the current-position field.

The comparison is strict. Equality with the captured boundary does not permit classification.

The conditions are short-circuited. If the position is not below the captured boundary, this function does not perform the recognition-byte read or call F-cfad0582408b.

When the first condition succeeds, the current-position field is read for the byte dereference, and one byte is supplied to F-cfad0582408b. The source represents the comparison access and the dereference access separately; it does not establish an atomic snapshot of the field across them.

The acceptance condition is any nonzero classification result, not specifically one. A zero result selects the error path.

Only the byte access is visibly checked against the captured boundary. There is no subsequent local check that a size, payload start, or advanced position fits within that boundary.

### 3. Recognized-input path

When recognition succeeds, the function performs these operations in order:

1. Read the size-callback slot at offset 36 and invoke that callback with the context.
2. Write its returned 32-bit value to the size output.
3. Read the processing-callback slot at offset 32 and invoke that callback with the context.
4. Read the current-position field, add one, and write the result to the start output.
5. Compute the next current position from the then-current position plus the then-current size-output value plus one.
6. Write that result to context offset 0.
7. Read the status word at offset 12.
8. Return one if that status is zero; otherwise return zero.

The processing callback’s return value is ignored.

Two distinctions are essential:

- The start output is based on the current position **after** the processing callback, not necessarily the position used for recognition.
- The advancement uses the size-output location again after the processing callback. It is not guaranteed to use the original size-callback return value.

Thus, if the processing callback changes the size-output storage through an alias or another accessible reference, that changed value participates in advancement.

The start-output write also precedes advancement. If it aliases the size output, the newly written start value becomes the value read as the size for advancement. If it aliases a relevant context field, it can change subsequent reads from that field.

The function does not branch on status between these operations. A nonzero status already present in the context, or set by a callback, does not locally prevent the output writes or position update. It only determines the final return value once those operations have occurred.

### 4. Recognition-failure path

If either recognition condition fails, the function:

1. Calls F-4457a9a44a68 with a fixed diagnostic reference.
2. Writes the 32-bit value three to the status word at offset 12.
3. Returns zero.

The diagnostic call occurs before the status assignment. Consequently, the final local assignment overwrites any status value that the diagnostic dependency leaves in that field, provided it returns normally and the context remains writable.

On this path, the function does not directly write either output location or advance the current position. The entry callback, classification dependency when reached, and diagnostic dependency may still have side effects.

## Side effects

The function’s direct writes are path-dependent:

- **Recognition failure:** status becomes three after the diagnostic call returns.
- **Recognized input:** the size output is written, then the start output, then the current-position field. The status field is read to determine the return value.

The recognized-input path does not directly clear or otherwise assign status.
