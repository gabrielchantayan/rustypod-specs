# F-e161286c58b5

## Purpose

F-e161286c58b5 conditionally performs an indirect call and returns the 32-bit word found at the address returned by that call, interpreting the word as a pointer.

The decision uses the signed value of the second word in an input descriptor and, when that value is nonnegative, a signed comparison against a word obtained through the descriptor’s first word. Failure of this comparison returns a null pointer without making the indirect call.

The supplied representation suggests a descriptor associated with an object and an index-like value. That interpretation is **inferred intent**, not an established type contract. In particular, the index-like value is not visibly used to calculate an element address or passed explicitly to the indirect callee.

## Interface

### Inputs

The represented interface has three input positions:

| Position | Represented form | Established use |
|---|---|---|
| First | Pointer to a descriptor containing 32-bit words | Supplies the decision value and, conditionally, an object address. |
| Second | Opaque 32-bit value | Not read by the visible function body. |
| Third | 32-bit integer | Its incoming value is not used. On the nonnegative path, the corresponding temporary storage is replaced with the object address read from the descriptor. |

The first input is not optional. The function reads its second word before it can return through any path. A null or otherwise unreadable descriptor therefore does not have an established graceful-failure outcome.

### Widths and representations

The supplied representation supports a 32-bit machine model:

- Integer comparisons operate on signed 32-bit values.
- The descriptor fields are four bytes each.
- Object addresses, dispatch addresses, and returned pointer values are represented as 32-bit quantities.
- The indirect result is dereferenced for one four-byte word.

These widths describe the supplied static representation. They are not evidence that an implementation using a different pointer width would preserve the behavior without adaptation.

### Output

The normal result is a pointer represented by a 32-bit value:

- Comparison rejection produces a null pointer.
- Comparison acceptance produces the word loaded through the indirect call’s returned address, interpreted as a pointer.

The function does not return the address returned by the indirect call itself. It returns that address’s first word.

No ownership transfer, lifetime extension, allocation guarantee, or release obligation is established for the returned pointer.

## Behavior

### Decision read

The first observable data read is the four-byte word at descriptor offset four. Its bit pattern is interpreted as a signed 32-bit integer.

If it is negative, the function returns null. On this path, the visible body does not read the descriptor’s first word, access an object, resolve a dispatch target, or make a call.

Thus values with the high bit set, including `0x80000000` and `0xffffffff`, take the rejection path. They are not accepted as large unsigned indices.

### Object and limit reads

If the decision value is nonnegative, the function next reads the object address from descriptor offset zero. It then reads a four-byte comparison limit from object offset twelve.

These reads occur even when the decision value is zero. Zero is not unconditionally rejected. Although the representation initially records whether the decision value is zero, that condition is replaced on the nonnegative path by equality between the decision value and the loaded limit.

The limit is interpreted as signed 32-bit. Acceptance requires the decision value to be strictly less than the limit. Equality rejects.

Consequently:

- A negative limit rejects every nonnegative decision value.
- A zero limit rejects every nonnegative decision value.
- A positive limit accepts values from zero through one less than that limit.
- A decision value equal to the limit rejects, including the case where both are zero.

There is no visible subtraction, increment, scaling, or index-based address calculation. The comparison itself therefore introduces no arithmetic overflow.

### Rejected comparison

When the nonnegative decision value is greater than or equal to the signed limit, the function returns null.

The object’s limit field has already been read on this path. Its dispatch field is not read, and no indirect call is made.

A rejection result does not distinguish a negative decision value from a failed comparison. Both are represented by a null pointer.

### Accepted comparison and dispatch

After acceptance, the function forms the address eight bytes beyond the object base and reads the dispatch-table address stored there. It reads the call target at byte offset sixty-four in that table and invokes the target.

The visible call expression supplies no explicit arguments. The representation is insufficient to establish the actual machine-level argument list or whether a receiver is supplied by a calling convention. Acceptance must not be interpreted as evidence that the decision value is passed to the callee.

The target is chosen from the dispatch state read after the limit comparison. The function does not visibly capture the dispatch field before deciding whether to proceed.

### Result extraction

If the indirect call returns normally, its return value is treated as an address from which one four-byte word is read. That word becomes the function’s returned pointer value.

The extraction is unconditional on the accepted path:

- There is no check that the callee’s returned address is nonnull.
- There is no check that it is readable or suitably aligned.
- There is no check that the extracted word denotes a valid object.
- An extracted zero word returns null despite successful comparison and dispatch.
- An extracted word with its high bit set is returned as a pointer representation; it is not subjected to the earlier signed comparison.

After the indirect call, the function does not visibly reread the descriptor, limit, or dispatch table. Changes to those locations during the call do not trigger another eligibility decision.

### Address arithmetic and memory preconditions

Object-relative and table-relative offsets are small positive byte displacements, but the representation does not establish checked address arithmetic.

For a defined successful execution, each required address calculation and access must be valid under the execution environment’s pointer, alignment, and memory rules. No portable wraparound behavior is established for addresses near the end of the address space.

The required readable locations depend on the selected path:

1. Every path requires the descriptor word at offset four.
2. A nonnegative decision additionally requires the descriptor word at offset zero and the object word at offset twelve.
3. An accepted comparison additionally requires the object word at offset eight, the table entry at offset sixty-four, a callable target, and a readable word at the returned address.

Invalid memory or an invalid call target is not converted into a null result by visible validation.

## Side effects

The visible body performs no stores to the descriptor, object, dispatch table, or returned storage. Assignments shown in the representation affect temporary computation state rather than those external locations.

On an accepted comparison, the indirect call can have effects not described by the supplied body. No assumption is justified that it:

- Preserves global state.
- Leaves the descriptor or object unchanged.
- Avoids allocation or deallocation.
- Retains or releases any particular resource.
- Preserves the lifetime of the storage it returns.
- Returns normally.

If the callee changes or releases memory, the subsequent result-word read still requires its returned address to designate readable storage at that moment.

The wrapper contains no visible cleanup or release operation. Reading a pointer value does not, by itself, establish ownership of either that pointer’s target or the storage holding it.

The ordering above describes accesses in the supplied representation. Atomicity, synchronization, volatile behavior, and interactions with concurrent mutation are **documented_only**.
