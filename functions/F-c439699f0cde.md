# F-c439699f0cde

## Purpose

F-c439699f0cde conditionally exposes an address eight bytes into a caller-supplied object. It accepts the object only when its first 32-bit word matches a global comparison value and its 32-bit word at byte offset 68 is nonzero.

The operation returns a 32-bit status:

- **0:** The acceptance checks passed. If an output location was supplied, the operation stored the interior address there.
- **7:** An acceptance check failed. The operation did not write the output location.

These are the only normal return values established by the supplied static representation. The operation does not copy the object or read the data at the address it exposes.

The interpretation of the first word as an object identifier, and of the word at offset 68 as an availability or validity flag, is **inferred intent**, not an established semantic contract. The established behavior is equality and nonzero testing.

## Interface

### Inputs

The operation takes two pointer-valued arguments:

1. **Object address:** A nullable address interpreted as the beginning of an array of 32-bit integer words.
2. **Output location:** A nullable address at which one 32-bit integer value can be stored.

The output location is optional. A null output location does not cause rejection and does not bypass object validation.

The operation also reads a global comparison value. Its numerical value, initialization, storage lifetime, and mutability are not supplied.

### Relevant layout

Under the 32-bit integer layout represented by the supplied source, the relevant object locations are:

| Byte offset from object address | Width | Role |
|---|---:|---|
| 0 | 32 bits | Compared with the global comparison value |
| 8 | No data read by this operation | Address returned through the output location |
| 68 | 32 bits | Must be nonzero for acceptance |

Offset 68 corresponds to word index 17. Offset 8 corresponds to word index 2. No contents at offsets 4, 8, or any intervening position are inspected by the supplied operation.

There is no length argument. The operation does not establish that the object contains a particular allocation size before accessing these locations.

### Output representation

On an accepted object with a non-null output location, the operation converts the interior address to an integer and stores it as a single 32-bit value. It does not write an entire object, a length, or multiple output fields.

For the apparent 32-bit address model, this value represents the object address plus eight bytes. Exact pointer-to-integer conversion behavior outside that model is **documented_only**: the supplied representation does not establish how wider addresses would be represented or whether such an execution environment is supported.

### Preconditions for normal completion

A null object address is an explicitly handled input. A non-null address is not necessarily safe merely because it is non-null.

Normal completion requires:

- The object’s first word to be readable when the object address is non-null.
- The word at offset 68 to be readable if the first comparison succeeds.
- The output location to support a 32-bit store if the object passes and the output location is non-null.
- Applicable alignment, pointer validity, and address-representation requirements to hold.

The supplied operation does not catch invalid accesses or translate them into status 7.

## Behavior

### Acceptance and read dependencies

Validation is short-circuited.

A null object address produces status 7 without reading the object or evaluating its comparison against the global value.

For a non-null object address, the operation compares the first 32-bit object word with the global comparison value. If the values differ, it returns 7 without reading the word at offset 68.

If the comparison succeeds, the operation reads the 32-bit word at offset 68. A zero value produces status 7. Any nonzero value satisfies this check; the supplied operation imposes no positivity requirement or narrower accepted range.

The static representation does not establish which operand of the equality comparison is read first. In particular, it does not justify a promise that the object’s first word is read before the global value, or vice versa. It does establish that the comparison must succeed before the word at offset 68 is evaluated.

### Output and successful return

After the acceptance checks succeed, the operation examines whether an output location was supplied.

- With a null output location, it performs no output store and returns 0.
- With a non-null output location, it stores the integer representation of the address eight bytes beyond the object address, then returns 0.

Thus, success reports that the checks passed; it does not imply that an output was requested or written.

The offset used for the result is eight **bytes**, arising from advancement by two 32-bit words. It is not two bytes. Likewise, the checked field is at byte offset 68, not byte offset 17.

There is no bounds check, allocation-size calculation, or explicit overflow detection. Address formation and conversion rely on the execution environment’s pointer rules and the validity of the caller’s storage.

### Rejection behavior

On every normal rejection path:

- The return value is 7.
- The output location is not written.
- The output location is not dereferenced.
- No fallback address is produced.

Consequently, a previously stored output value remains unchanged after rejection, provided no external actor changes it.

### Aliasing

The supplied operation does not reject overlap between the output location and the object.

Validation precedes the output store. If the output location aliases the first object word or the word at offset 68, the checks use values read before that store. The store can then replace a field that was just checked.

No second validation follows the store. Acceptance therefore does not guarantee that the object still satisfies the checks on return when the output aliases relevant storage.

More generally, the only explicit write is through the output location, but that write can affect any writable storage it aliases. There is no explicit protection against aliasing the global comparison storage.

## Side effects

### Reads

Depending on the path taken, the operation reads:

- The first 32-bit word of a non-null object.
- The global comparison value used with that word.
- The object’s 32-bit word at offset 68, only after the comparison succeeds.

It does not dereference the interior address that it returns.

### Writes

The operation performs at most one explicit store: a 32-bit write to a non-null output location after successful validation.

There is no explicit write to the object or global comparison value through their ordinary access paths. Aliasing through the output location can nevertheless modify them.

### Ownership and lifetime

No allocation, release, copying of object storage, or ownership transfer is shown.

The returned integer represents an address within the supplied object rather than newly created storage. The operation provides no lifetime extension, pinning, reference counting, or protection against later mutation. Any later use of that address depends on the underlying storage remaining valid.

### Concurrency

No synchronization or atomic access mechanism is established. The operation does not promise a coherent snapshot of the first word, the global comparison value, and the word at offset 68 under concurrent mutation.

The acceptance examples below therefore assume stable storage during the call.

## Dependencies

No calls to other functions are present in the supplied static representation. There are no additional opaque function dependencies to enumerate.

- The global comparison value.

- The execution environment’s 32-bit integer layout, pointer arithmetic, pointer-to-integer conversion, and memory-access rules.

## Acceptance examples

These examples specify expected behavior under the stated preconditions; they are not runtime test results.

| Conditions | Expected normal result |
|---|---|
| Object address is null; output location is null | Return 7; no object access or output store |
| Object address is null; output location is writable and contains a prior value | Return 7; prior output value remains unchanged |
| First object word differs from the global comparison value | Return 7; do not read offset 68; do not write output |
| First word matches; word at offset 68 is zero | Return 7; do not write output |
| First word matches; word at offset 68 is nonzero; output location is null | Return 0; no output store |
| First word matches; word at offset 68 is nonzero; output location is valid | Store the integer representation of object address plus eight bytes; return 0 |

Additional boundary and aliasing examples:

- **Nonzero field:** A field value with only its highest bit set passes the nonzero check just as a value of one does. No signed ordering comparison is performed.
- **Concrete address:** If the object begins at address `0x1000`, all checks pass, and address conversion preserves the apparent 32-bit address representation, the stored result is `0x1008`.
- **Short-circuit protection:** If the first word is readable and mismatches, an inaccessible location at offset 68 is not accessed on that path.
- **Output aliases the first word:** If validation passes and the output location is the first object word, the operation stores the interior address there and returns 0. It does not recheck the modified word.
- **Output aliases offset 68:** If that field is initially nonzero and the other check passes, the operation may replace it with the interior-address representation and still return 0.
- **Invalid output location:** If validation succeeds but the non-null output location is not writable, status 7 is not a specified recovery result. Normal completion is not guaranteed.
- **Invalid object address:** A non-null but unreadable object address is outside the normal-access preconditions. Null handling does not imply general pointer validation.
