# F-1875fb3f2c3b

## Purpose

F-1875fb3f2c3b specifies a state-dependent sequence of memory accesses, an indirect invocation, and two represented terminal paths. The supplied static representation does not establish a higher-level purpose such as initialization, allocation, registration, or device control.

The sequence writes address-derived values, accesses fixed low addresses, and derives further destinations from loaded values. Both terminal paths end at an invalid-instruction marker. This does not establish successful execution or a particular hardware exception on any platform.

This contract distinguishes:

- **Established static evidence:** operations, expression conversions, and ordering visible in the supplied representation.
- **Inferred intent:** possible interpretations that are not requirements.
- **documented_only unknowns:** unresolved types, execution semantics, dependency behavior, and environmental requirements.

No runtime tests have been performed.

## Behavior

The following order follows the supplied representation. Each later operation requires execution to reach it. Earlier accesses may fault; the indirect dependency may not return.

### 1. Initial writes

Perform three word stores in order:

1. Store A at the address represented by A + 0x44.
2. Store A at address A.
3. Store X at the address represented by A + 4.

No validation precedes these stores.

The additions involving A are represented as signed arithmetic. Address wraparound is not independently established. Aliasing remains significant: these writes may affect memory read later, including the halfword at X + 0x14 or persistent state.

### 2. Select a value and optionally write it back

Let S be the selected 32-bit value:

- If D converted to signed 32 bits compares greater than −1, read an unsigned halfword at X + 0x14 and zero-extend it into S.
- Otherwise, retain D’s original 32-bit pattern as S.

Interpreting D’s conversion by its signed two’s-complement bit pattern makes the first case the nonnegative case. The treatment of out-of-range unsigned-to-signed conversion remains an execution-model qualification.

Next, shift Y right by 12 using the represented signed operation and compare the result with −1. If the result is greater than −1, store the low 16 bits of S at X + 0x14.

Under arithmetic signed-right-shift semantics, that condition is equivalent to Y being nonnegative. The shift-and-compare expression, rather than that equivalence, is the direct evidence.

The optional halfword store does not narrow S for subsequent calculations.

### 3. Construct early destinations

Store a zero halfword at the address obtained from S × 0x20000000 using unsigned 32-bit multiplication.

Then store the word S shifted left by 21 bits at R.

Define:

- **Q:** the address represented by advancing R by one 32-bit integer; numerically R + 4 in the represented layout.
- **q:** Q’s low 16 bits.
- **T:** the address expression obtained by converting Q to signed 32 bits and multiplying by 0x01000000.

Perform these writes in order:

1. Store q as a halfword at Q.
2. Store the word 4 at T.
3. Store the low 16 bits of the address T + 4 as a halfword at T + 4.

The multiplication producing T is signed in the representation. If it overflows, the result is **documented_only**. Under a wrapping machine interpretation, T is the low 32 bits of Q × 0x01000000.

The halfword store at Q does not replace an entire word. Ordinary memory retains the other bytes unless another effect changes them.

### 4. Access persistent state and invoke a dependency

Use G30 in two roles within one store:

- Convert one reference to unsigned 32 bits to obtain the destination address.
- Convert the separately referenced value as required by an unsigned-halfword destination and store 16 bits there.

G30 is not established as an unsigned-halfword object. Its destination conversion therefore does not establish an address range of 0 through 65,535. The representation also does not establish an atomic snapshot or a relative evaluation order for the two references.

Next, assign GH the value obtained by taking Q’s upper 16 bits and explicitly converting that result to an unsigned halfword. This establishes the right-hand-side value conversion, **not GH’s write width or stored representation**.

Invoke **F-INDIRECT-01** at the address obtained from L by clearing its low two bits. The one explicitly represented argument is 0x089803D8.

The result is represented as 64 bits. Define:

- **Vlo:** the low 32-bit pattern.
- **Vhi:** the high 32-bit pattern.

The call’s ABI, additional inputs, effects, and actual return interpretation are unresolved. No later effect is guaranteed unless it returns.

### 5. Process the represented result

Store Vhi as a word at address 0x0000000A.

Convert the low result portion to signed 32 bits and multiply it by four; call the resulting address-like value **W**. Signed overflow and out-of-range conversion are unresolved. Under the wrapping interpretation, W is the low 32 bits of Vlo × 4.

Perform these operations in order:

1. Store W’s low 16 bits at W + 2.
2. Store q at W + 2, replacing the same halfword.
3. Read an unsigned halfword at W + 0x20 and zero-extend it; call the result **U**.
4. Store the word representation of R at R + 0x10.
5. Store U as a halfword at U + 0x20.
6. Store U as a word at 4 × U + 0x14.
7. Store U as a halfword at U + 4.

U is established as an unsigned 16-bit load result, so U ranges from 0 through 65,535. This restriction does not apply to G30 or GH.

The two stores at W + 2 remain distinct represented accesses. Their ordering may matter for faults, devices, or other observers even though the second replaces the first in ordinary memory.

### 6. Perform later address-derived writes

Read GH again and explicitly convert the resulting value to unsigned 32 bits. Let **H** be that converted value multiplied by four using unsigned 32-bit arithmetic.

GH’s underlying read width and signedness remain unknown. H is therefore not restricted to four times an unsigned-halfword value. The call and intervening writes may also have changed GH.

Perform two halfword stores at H:

1. Store 0x03D8.
2. Store H’s low 16 bits.

Next, convert Q to signed 32 bits and shift it right by two; call the resulting address-like value **J**. Its value depends on the signed-conversion and right-shift semantics.

Then:

1. Store J’s low 16 bits as a halfword at J.
2. Store the word 0x0000000A at address 0x00000A20.
3. Store the halfword 0x038C at the address represented by signed J × 4.

The last multiplication carries a signed-overflow qualification.

The fixed destination 0x00000A20 is derived from the retained address 0x0000000A, scaled by 256 and advanced by 0x20. It does not depend on the word previously written at 0x0000000A.

### 7. Select a terminal path

Convert J to unsigned 32 bits and test whether its low 29 bits are zero.

#### Zero-mask path

If the test succeeds, perform these operations in order:

1. Store q as a halfword at 0x00000A0E.
2. Assign GK a low-16-bit expression with value 0x0A00.
3. Read GK and convert its value for a halfword store at 0x00000A00.
4. Store the word 0x00000A00 at 0x00000A00.
5. Store the word 0x000000F4 at 0x00000A04.
6. Store the word 0x0898038C at 0x00000A08.
7. Store Q as a word at 0x00000A0C.
8. Store the word represented by −Q + 0xF4 at the address represented by −Q + 0xFC.
9. Assign integer zero to GZ.
10. Evaluate two references to GP with an addition of 0x4A: one expression supplies the destination of an unsigned 32-bit store; the other supplies its stored value.
11. Reach **F-TERMINAL-01**.

Step 2 does not establish a halfword write to GK. Step 3 is a halfword destination store, but does not establish a halfword read from GK or guarantee that its value equals the preceding right-hand-side expression.

The word store at 0x00000A0C overlaps the earlier halfword store at 0x00000A0E. Under ordinary memory semantics, the later word supplies all four final bytes at 0x00000A0C through 0x00000A0F.

The negation and additions involving Q require signed-arithmetic qualification. The GZ assignment’s access width is unknown.

GP’s missing declaration prevents an unconditional assertion of byte-address arithmetic, a 32-bit source read, or matching destination and value. Under a compatible numerical-scalar interpretation with stable equal references, both expressions can denote GP + 0x4A. If GP is pointer-typed, addition may be scaled; if the references observe different values, the destination and stored value need not match. Evaluation order is unresolved.

#### Nonzero-mask path

If the low-29-bit test fails:

1. Read GS.
2. Explicitly convert its value to signed 32 bits.
3. Shift that converted value right by 31.
4. Convert the result to a byte and store it at 0x08980D8C.
5. Reach **F-TERMINAL-01**.

The destination follows from a halfword-scaled offset added to the fixed base 0x00000A00.

Under arithmetic signed-right-shift semantics, a nonnegative converted value produces byte 0x00 and a negative converted value produces byte 0xFF. This does not establish that GS itself is a signed 32-bit object.

## Acceptance examples

These are conditional static expectations, not executed tests. Each assumes preceding operations complete and unmentioned aliases, concurrency, and device effects do not alter the stated values.

1. **Memory selection.** If D is 7 and the halfword at X + 0x14 is 0x1234 when read, S becomes 0x00001234 rather than 7.

2. **Negative selection retains all bits.** Under the signed-bit-pattern interpretation, D equal to 0x80000001 selects that full pattern without reading X + 0x14 for selection. If the Y condition permits the optional write, it stores 0x0001. The subsequent unsigned zero-store destination is 0x20000000.

3. **Early fault.** If the first store at A + 0x44 faults, no later operation in the represented sequence has occurred. No recovery path is shown.

4. **Return halves and replacement.** If the represented call result is 0x1122334400000100, the word store at 0x0000000A receives 0x11223344. W is 0x400 without multiplication overflow. Address 0x402 receives halfword 0x0400, then q.

5. **GH conversion controls scaling.** If GH’s later conversion to unsigned 32 bits yields 3, the consecutive stores target address 12 and write 0x03D8, then 0x000C. If that conversion instead yields 0xFFFFFFFF, unsigned scaling produces destination 0xFFFFFFFC and the second halfword is 0xFFFC. Neither case asserts GH’s storage width.

6. **Terminal overlap.** On a reached zero-mask path, 0x00000A0E first receives q. The later word store at 0x00000A0C replaces the four bytes through 0x00000A0F with Q’s representation.

7. **Sign-derived byte.** On a reached nonzero-mask path, if converting GS to signed 32 bits produces the pattern 0x80000000 and right shift is arithmetic, the final byte is 0xFF. This is conditional on the converted value, not on GS having a particular declared type.

8. **Global assignment versus destination width.** The GK assignment has right-hand-side value 0x0A00. If its subsequent read converts to halfword 0x0A00, that halfword is stored at 0x00000A00 before the word store there. This expectation does not require or establish a 16-bit GK object.
