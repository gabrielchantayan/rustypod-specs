# F-94964b40d6d6

## Purpose

F-94964b40d6d6 evaluates a counted sequence of unsigned 16-bit elements and returns a 32-bit Boolean result. Acceptance depends on flag-controlled restrictions and nonzero entries in a shared byte-valued classification table.

Established rejection rules are:

- Flag mask `0x00000004` rejects the entire invocation before any sequence or shared-state access.
- For a nonzero count, mask `0x00000002` rejects an initial observation of the first element if that value is below 33.
- Each element reached by the main scan must be at most 122 and select a nonzero classification-table byte.
- Mask `0x00000010` additionally rejects scanned values from 48 through 57, inclusive.

Before scanning, the function checks readiness through a shared address-bearing value. A zero readiness byte triggers dependency F-9b7bef8bbc6d.

**Inferred intent:** a table-based sequence predicate with optional restrictions and apparent lazy preparation of shared state.

The supplied evidence does not identify the table contents or establish a particular language, encoding, identifier grammar, or character category.

## Behavior

### Entry precedence

The first check is flag mask `0x00000004`.

If set, the function returns `0`. It does not read the sequence, readiness address, readiness byte, table base, or table bytes, and does not call F-9b7bef8bbc6d. This precedence applies to positive, zero, and negative counts.

If that mask is clear and the count is zero, the function returns `1`, again without any of those reads or the dependency call. The other recognized masks cannot change the zero-count result.

Thus, these paths do not dereference the sequence address. This access property does not establish that every possible pointer representation is valid in the calling environment.

### Preliminary first-element observation

For every nonzero count surviving the entry flag check, the function reads the initial unsigned 16-bit element.

If the observed value is below 33 and mask `0x00000002` is set, it returns `0` immediately. The rejected interval is 0 through 32, inclusive.

The element comparison precedes the flag test in the supplied expression. Clearing mask `0x00000002` therefore does not eliminate this preliminary element read.

This threshold restriction applies only to the initial observation. It is not repeated for later elements or when the first element is reread by the main scan.

A preliminary rejection occurs before any readiness-address or readiness-byte read and before any dependency call.

### Readiness handling

After the preliminary check passes, the function obtains the shared readiness address and reads the byte designated by that address.

- A zero byte causes one call to F-9b7bef8bbc6d.
- A nonzero byte skips the call.

No explicit arguments are shown, and no dependency return value is consumed. The readiness address and readiness byte are not rechecked after the dependency returns.

This stage precedes the first main-scan element read. It therefore occurs even when the first scanned value will be rejected immediately for exceeding 122.

The dependency has no supplied preservation contract. In particular:

- The first sequence element may differ between the preliminary read and the main-scan read.
- The classification-table base used after the call need not equal its pre-call value.
- Table contents, readiness state, and other shared memory need not be preserved.
- The dependency is not established to make readiness nonzero or to create a valid table.

The function itself does not read the table base before this stage. A subsequent lookup uses the base evaluated at that lookup, not an assumed pre-call snapshot.

### Main scan

The scan starts at the original sequence address, rereading the first element. For each reached position, the source-level observable access and decision order is:

1. Read the current unsigned 16-bit sequence element and widen it to an unsigned 32-bit value.
2. If the value exceeds 122, return `0`.
3. Otherwise, read the shared classification-table base and then the byte at that base plus the element’s numeric value.
4. If the selected byte is zero, return `0`.
5. Otherwise, if mask `0x00000010` is set and the value lies from 48 through 57, return `0`.
6. After all checks pass, decrement the local count by one and advance the local sequence cursor by one 16-bit element.
7. Continue when the updated count is nonzero; otherwise return `1`.

For values from 123 through 65535, rejection precedes both the table-base read and the table-byte read for that element.

For each reached in-range lookup, obtaining the table base and reading the selected byte are separate accesses. No preservation of the base across lookups is established. If the shared base changes between lookups, the body provides no snapshot or consistency mechanism.

Any nonzero classification byte passes membership; the byte need not equal `1`. Its signed interpretation does not change the zero-versus-nonzero test.

The additional digit restriction follows membership. An in-range digit therefore causes a table-base read and a table-byte read before digit rejection. If its classification byte is zero, rejection occurs at membership instead.

There is no terminator-based stopping rule. An element whose value is zero selects table entry zero; it does not automatically end the sequence.

### Count and arithmetic boundaries

For a positive count \(N\), assuming normal dependency completion and valid reached accesses:

- At most \(N\) main-scan elements are read.
- The first failing scan check returns `0`.
- Passing all \(N\) elements returns `1`.
- The preliminary first-element read is additional to the main-scan reads.

The cursor advances after every passing element, including the final one. Advancing the cursor does not itself read the next element.

The digit condition uses unsigned 32-bit subtraction of 48 followed by comparison with 10. Values below 48 wrap to large unsigned results and do not satisfy the comparison. For the possible element values, this selects exactly 48 through 57.

The count is signed 32-bit, but scan continuation tests nonzero rather than positivity. Negative counts therefore take the preliminary, readiness, and scanning paths unless an earlier rejection intervenes.

A negative count is not an empty sequence or an explicitly invalid input under this body. Continued decrement can encounter signed overflow. The supplied material does not establish behavior across that overflow, and no modular traversal length is promised. Address advancement beyond valid sequence storage is likewise not given a defined outcome.
