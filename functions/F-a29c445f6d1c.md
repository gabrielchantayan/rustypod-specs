# F-a29c445f6d1c

## Purpose

F-a29c445f6d1c returns a 32-bit Boolean decision after invoking three dependencies and consulting invocation-local state and a global-addressed field.

For executions in which the calls and required memory accesses complete normally, the decision is:

- Return **0** if the checked global field is nonzero.
- Otherwise, return **1** if the invocation-local value is nonzero.
- Otherwise, return **1** only if the second dependency’s captured result is nonzero and the third dependency’s captured result is **strictly greater than 4 in signed 32-bit ordering**.
- Return **0** in all other cases.

All three dependencies execute before the global-addressed check. Neither an initially nonzero local value nor a globally rejecting state bypasses those calls.

The apparent intent is a predicate with an overriding rejection condition and two alternative acceptance conditions. That interpretation is inferred intent only. The evidence does not identify the decision as authorization, readiness, validity, or any other application-level property.

## Behavior

### Ordered interactions

The established order on a normally completing invocation is:

1. Initialize the 32-bit local slot from the incoming r3 value.
2. Invoke F-f23023f237bd with the slot’s address.
3. Invoke F-unmapped-01 and capture its 32-bit result.
4. Invoke F-1dbbf5bbd9c8 and capture its 32-bit result.
5. Use the global-base value in the post-call field-address expression and read the 32-bit field at byte offset 12.
6. If that field is zero, check the local slot.
7. If the local slot is also zero, determine acceptance from the captured dependency results.

This sequence describes the recovered body’s interactions and control dependencies. It does not assert a machine-instruction trace or a distinct physical load for the global-base value.

All three calls occur before the shown rejection or acceptance decision, assuming earlier operations complete normally. Capturing the second and third results before the global check matters even when those results will not affect the return value.

The local value checked later need not equal the incoming register value. The first dependency receives a pointer to the initialized slot. The supplied body neither proves that the dependency writes it nor guarantees that it leaves it unchanged.

### Global-base resolution and field selection

The checked field is selected using the global-base value in an expression reached **after all three calls**. The field is not established as a fixed location selected before those calls.

No dependency is established to preserve:

- The global-base value.
- State determining that value.
- The contents of the selected field.

Consequently, dependency effects may influence the global check in two distinct ways: by changing which location is selected, or by changing the contents read at the selected location.

Resolving or caching the field location before the calls requires an additional invariant not supplied by this body. Such an invariant would need to establish that early resolution selects the same effective field and preserves the relevant access semantics. It cannot be justified merely by observing that this function contains no explicit assignment to the base.

The recovered expression does not settle whether the base is a fixed address, a mutable stored pointer, or another represented value. The contract therefore establishes the post-call address dependency without asserting a separate base-memory read.

### Global rejection

If the selected field’s value is nonzero, the function returns 0.

This condition overrides all other decision inputs:

- A nonzero local value cannot enable acceptance.
- A nonzero second result cannot enable acceptance.
- A third result greater than 4 cannot enable acceptance.

On this branch, the subsequent local-slot check is not reached. The three dependencies have already executed.

The relevant field value is the value read at the effective post-call location. Neither an entry-time field value nor the contents of a location selected from an earlier base is established as controlling the decision.

### Local acceptance

If the selected field is zero and the local value is nonzero, the function returns 1.

Any nonzero 32-bit local pattern qualifies, including one representing a negative signed value. The local value need not equal 1.

Neither captured dependency result affects the returned value on this branch. Both calls still occurred; their results are simply unnecessary to this branch’s decision.

### Acceptance from dependency results

If the selected field and local slot are both zero, acceptance requires:

- A nonzero captured result from F-unmapped-01.
- A captured result from F-1dbbf5bbd9c8 that exceeds 4 under signed 32-bit comparison.

The second result is tested only for zero. Its sign and magnitude otherwise have no established significance here.

The third result’s boundary is strict: 4 rejects, while 5 satisfies the threshold. Zero and all negative signed values reject.

### Arithmetic boundaries

The threshold logic uses a four-byte subtraction, a signed-overflow condition, and an explicit equality rejection. Together they implement signed comparison against 4.

The behavior must not be reduced to checking the sign of a wrapped subtraction. For sufficiently negative inputs, subtracting 4 overflows the signed 32-bit range; the overflow condition preserves the correct comparison outcome.

In particular:

- **−2,147,483,648** fails the threshold even though wrapping subtraction by 4 would produce a positive bit pattern.
- **2,147,483,647** satisfies the threshold.
- A sign-bit-set third-result pattern is negative under the required interpretation and therefore fails the threshold.

These are 32-bit comparison semantics, not evidence that arbitrary source-language signed overflow is permitted.

If an earlier call does not return, later calls and checks are not reached. If field access fails, no normal return value is established. The function provides no visible cleanup or rollback path for those cases.
