# F-93ed2dcf7110

## Purpose

F-93ed2dcf7110 specifies a visible execution fragment that interleaves indirect calls, byte accesses, and 32-bit memory accesses. It derives addresses and argument values from entry machine state, memory contents, and call results. Its visible control flow ends at a reported invalid-instruction boundary.

No application-level purpose is established. The evidence does not identify an allocation routine, serialization format, device protocol, or conventional standalone procedure.

This contract describes the supplied static representation, not verified runtime behavior. Every operation after an access or call is conditional on execution continuing through that earlier operation.

### Widths and arithmetic

Bytes are eight bits. Word accesses and ordinary result values are 32 bits. Two results are represented as 64-bit containers and separated into low and high 32-bit halves.

Byte stores retain the low eight bits of their supplied values. Selector-byte reads are unsigned and are zero-extended before adding 17. Their selected destinations therefore range from absolute address 17 through absolute address 272, inclusive.

In this contract, “scaled by” describes the indicated multiplication or left shift. It does not impose a single overflow rule on every expression:

- Explicitly unsigned 32-bit shifts, masking, and multiplication have 32-bit unsigned behavior in the supplied representation.
- Signed multiplication and left shifts do not establish defined behavior for overflow or negative operands.
- Conversion of an unsigned result outside the signed 32-bit range into a signed value is not resolved into a portable numeric interpretation.
- Pointer width, integer-to-address conversion, and address wrapping remain unresolved.

Examples using potentially problematic arithmetic are conditional on either remaining in a defined range or an explicitly stated machine-word interpretation. The byte order and alignment requirements of 32-bit accesses are unknown.

## Behavior

### Dependency notation and execution conditions

F-D001 through F-D053 label call occurrences in execution order. They do not establish distinct target identities: multiple occurrences could reach the same target.

“No explicit inputs” means that the representation supplies no argument expressions. It does not mean the target receives no implicit machine state or cannot inspect memory.

F-D001’s target is entry-control-address-relative. The remaining targets are computed from fixed address-like anchors and offsets. No dependency implementation is supplied.

### Initial byte writes and first call chain

The fragment first doubles the scale seed, producing the **initial derived base**, subject to the signed-arithmetic qualification above.

Before any call, it performs these byte stores in order:

1. Store the low byte of the entry payload at the entry destination base plus 13.
2. Store the low byte of the scale seed at absolute address 13.

The first eight calls then occur:

| Occurrence | Explicit inputs | Result subsequently consumed |
|---|---|---|
| F-D001 | Initial derived base; 152; 608 | No ordinary result used |
| F-D002 | None | Secondary unsigned 32-bit machine-result value |
| F-D003 | That secondary value logically shifted right by 3 | No ordinary result used |
| F-D004–F-D006 | None, in order | No ordinary results used |
| F-D007 | None | A 32-bit result |
| F-D008 | F-D007’s result scaled by 4 | A 32-bit result |

After F-D008, the fragment performs two more byte stores:

1. Store the low byte of the entry payload at the initial derived base plus 13.
2. Store 192 at absolute address 13.

Thus, the two explicit stores to absolute address 13 are separated by eight call occurrences. Callee activity may affect that address between the stores.

### Initial-base word store and loaded-address chain

F-D009 receives F-D008’s result scaled by 4. F-D010, F-D011, and F-D012 follow without explicit inputs. F-D013 then supplies a 32-bit result.

Next, the fragment:

1. Stores F-D013’s result scaled by 4 as a 32-bit word at the initial derived base plus 36.
2. Reads an unsigned 32-bit word from the initial derived base plus 116. This is the **loaded address word**.
3. Scales F-D013’s result by 32, producing the **derived word value**.

The store precedes the read. If their memory regions overlap under the actual address interpretation, that ordering matters.

F-D014 receives four explicit inputs:

1. Loaded address word.
2. Loaded address word shifted left by one bit as an unsigned 32-bit value.
3. Derived word value.
4. Loaded address word masked with 2,147,483,647, then logically shifted right by two bits.

F-D015 through F-D018 follow without explicit inputs.

The fragment then stores the derived word value as a 32-bit word at the loaded address word plus 36. After that store, it reads a 32-bit word at the loaded address word plus 116 and supplies the newly read value to F-D019.

F-D020 through F-D022 follow without explicit inputs.

The two reads at offset 116 use different bases. Neither a structure layout nor a relationship between the addressed objects is established.

### First paired result and entry-payload word store

F-D023 returns a value represented as a 64-bit container. The fragment separates it into:

- A low 32-bit half, scaled by 4 to produce the **first paired scaled value**.
- A high unsigned 32-bit half, called the **first paired index**.

Before F-D024, the fragment stores all 32 bits of the entry payload at:

**first paired index × 4 + 20**

The index arithmetic is unsigned 32-bit arithmetic in the representation; the resulting address interpretation remains subject to the interface qualifications.

F-D024 receives:

1. First paired scaled value.
2. First paired scaled value.
3. First paired scaled value.
4. First paired index logically shifted right by three bits.

The first three positions carry the same value; they remain three explicit argument positions.

### Second paired result and derived-value word store

F-D025 returns another value represented as a 64-bit container.

F-D026 receives:

1. Its low 32-bit half.
2. Its high unsigned 32-bit half.
3. Its low 32-bit half again.
4. Its high half logically shifted right by three bits.

Unlike F-D024, these first and third inputs are not scaled by 4 before being passed.

F-D027 through F-D029 follow without explicit inputs. F-D030 then returns a 32-bit value.

The fragment stores the first paired scaled value as a 32-bit word at:

**F-D030’s result × 4 + 20**

F-D031 receives F-D030’s result multiplied by 4. F-D032 through F-D034 follow without explicit inputs.

The payload store indexed by F-D023’s high half and this store indexed by F-D030’s result are distinct operations. No common allocation, bounds guarantee, or shared indexing scheme is established.

### Two selector-based packed-result byte stores

F-D035 returns an unsigned 32-bit value, the **packed result**. Its unsigned left shift by two bits produces the bit pattern used as the **packed scaled value**, which is subsequently held in a signed 32-bit location.

The fragment then:

1. Reads an unsigned byte at the loaded address word plus 1.
2. Adds 17 to the zero-extended byte.
3. Stores the low byte of the packed scaled value at that selected absolute address.

F-D036 and F-D037 follow without explicit inputs. F-D038 returns a 32-bit result.

Before the next call, the fragment:

1. Reads an unsigned byte at the loaded address word plus 1 again.
2. Adds 17 to this freshly read byte.
3. Stores the low byte of the packed result after masking with 1,073,741,823 and logically shifting right by 20.

F-D039 then receives F-D038’s result scaled by 4.

The selector is reread after the intervening calls. The two destinations need not match. The first selected store can itself affect the later selector if their addresses overlap.

### Two selector-based zero stores

F-D040 through F-D042 occur without explicit inputs. F-D043 returns a 32-bit result.

The next selector source address is:

**packed scaled value × 1,024 + 1**

This expression uses the signed packed scaled value in the representation. Its behavior for signed overflow is unresolved; it must not be silently replaced with unrestricted mathematical arithmetic.

The fragment reads an unsigned byte from that source address, adds 17, and stores zero at the selected absolute byte address.

F-D044 receives:

1. Packed scaled value shifted left by three bits.
2. The same shifted value.
3. Packed scaled value.
4. F-D043’s result shifted left by two bits.

F-D045 through F-D047 follow without explicit inputs. F-D048 returns a 32-bit result.

The fragment then repeats the selector operation in full:

1. Read another unsigned byte from packed scaled value × 1,024 + 1.
2. Add 17.
3. Store zero at the resulting absolute byte address.

This is a second source read and a second destination write. The representation does not establish either operation as redundant.

F-D049 receives F-D048’s result scaled by 4. F-D050 through F-D053 follow without explicit inputs. The visible representation then ends at its invalid-instruction boundary.
