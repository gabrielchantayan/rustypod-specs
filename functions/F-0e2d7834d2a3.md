# F-0e2d7834d2a3

## Purpose

F-0e2d7834d2a3 performs a bounded sequence of acquisition attempts using a supplied receiver. A successful acquisition triggers secondary-output retrieval and two preliminary checks. An attempt passing those checks constructs a temporary candidate, validates it, optionally delivers it through two calls, and then invokes candidate cleanup.

The function processes at most four successful acquisitions. An unsuccessful acquisition terminates the sequence immediately. If any candidate completes both delivery-related calls, two final dependencies are invoked, once each, after the sequence ends.

These are descriptive roles established by the visible call structure. The evidence does not identify the operation as polling, queue consumption, resource lookup, or any other domain-specific activity.

All normal-path guarantees below require reached dependencies to return normally and reached memory accesses to be valid.

## Behavior

### Initialization and the two global evaluations

Before the first dependency call, the function performs two separate evaluations of the same 32-bit global location.

The represented order is:

- Read the global and retain that first value for later candidate construction.
- Initialize an internal completion flag to false and a 32-bit unsigned attempt counter to zero.
- Set the working descriptor’s byte at offset 4 to zero.
- Read the global again and place this second value in the working descriptor’s first word.

The first retained value and the working descriptor’s initial first word therefore have different initialization provenance. They are equal only if the two evaluations yield equal values. The function performs no equality check and establishes no stability or synchronization guarantee for the global.

The working descriptor’s payload words and bytes 5–7 are not explicitly initialized. Neither the secondary-output storage nor the status slot is explicitly initialized.

Initialization occurs once per invocation. The working descriptor is not reset between attempts.

### Acquisition and attempt limit

Each acquisition begins with a call to F-eb6427c6a544 without explicit arguments. Its returned 32-bit value is passed to F-c1920b5d8253, followed by the status-slot address.

The 32-bit return from F-c1920b5d8253 is tested for zero:

- Zero terminates the loop immediately.
- Any nonzero value permits processing and increments the attempt counter.

No secondary-receiver call or candidate-related action occurs for an acquisition returning zero.

After processing a nonzero acquisition, another acquisition occurs only if the unsigned counter is below four. Thus:

- Between one and four acquisition pairs occur on a normally returning invocation.
- At most four nonzero acquisitions are processed.
- There is no fifth acquisition after four nonzero results.
- Failed preliminary checks and rejected candidates still consume processed attempts.
- The counter reaches at most four, so its 32-bit increment cannot wrap on the represented path.

The bound limits this function’s acquisition iterations. It does not bound work, recursion, or effects inside dependencies.

### Secondary output and preliminary checks

Every nonzero acquisition is followed by an indirect call through the input receiver’s dispatch entry at offset 0x140. The returned pointer is used as the secondary receiver. Its dispatch entry at offset 0x08 is then called with the secondary-output address followed by that receiver.

Next, F-d45d65316ed3 receives the working-descriptor address first and the secondary-output address second.

Construction is enabled only when:

- F-d45d65316ed3 returns nonzero; and
- the status slot is zero when subsequently tested.

The status test is short-circuited. A zero return from F-d45d65316ed3 prevents that conditional status read.

The tested status is the value visible after the secondary-receiver calls and F-d45d65316ed3. Although F-c1920b5d8253 receives its address earlier, the evidence does not establish that later dependencies preserve its contents or cannot reach it through aliases.

If either preliminary condition fails, the attempt ends without construction, validation, delivery, or candidate cleanup.
