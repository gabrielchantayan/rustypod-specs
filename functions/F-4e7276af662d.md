# F-4e7276af662d

## Purpose

F-4e7276af662d repeatedly performs an ordered sequence of indirect calls, memory accesses, a software breakpoint, and represented register-state changes. The supplied representation has an unconditional loop and no normal return path.

No application-level purpose is established. Descriptions such as initialization, dispatch, device servicing, or record maintenance would be inferred intent, not supported conclusions.

This contract describes static behavior in the supplied representation. Whether its recovered calling conventions and register model faithfully describe executable machine behavior remains unresolved.

## Interface

**Explicit inputs:** none are declared.

**Implicit inputs:**

- An incoming link-register value used to derive the first indirect-call target.
- An incoming retained 32-bit register value, called **A** here, used in a late byte-store address.
- A represented machine-state base, called **B**, used for fixed-offset accesses and explicitly decremented during each iteration.
- Two global 32-bit cells, **G-A** and **G-B**, whose contents are used as addresses.
- Memory reached through those cells, dependency results, residual register values, and computed addresses.
- Residual register outputs consumed after three calls.

**Outputs:** no explicit return value. Observable effects include indirect calls, memory reads and writes, the breakpoint event, and represented state changes.

**Widths and arithmetic:**

- Bytes are 8 bits; halfwords are 16 bits; words and represented addresses are 32 bits.
- Three dependency results are represented as 64-bit composites. Their low and high 32-bit portions are consumed independently; this does not establish a memory byte order or a machine-level return convention.
- Unsigned halfword reads produce values from 0 through 65,535.
- Byte and halfword stores retain only their destination width.
- The two Q-derived shifts described below are unsigned 32-bit operations.
- Other expressions include signed addition, signed left shifts, and signed multiplication. A universal wrapping-arithmetic contract is not established. Conditional examples involving these operations require valid arithmetic under the execution model or an explicitly assumed 32-bit machine interpretation.

There is no established allocation, release, ownership transfer, or object lifetime. A dependency argument must not be classified as an owned pointer merely because another value is used as an address.

## Behavior

### Naming and ordering

The 37 indirect-call occurrences have opaque IDs **F-000000000001** through **F-000000000037**, abbreviated **D01** through **D37**. These names identify call occurrences, not necessarily distinct targets.

The descriptions below preserve the order of explicit operations. A dependency may read or modify memory or implicit machine state. Capturing a value before a call is therefore distinct from reading its source again afterward.

Symbols such as **P**, **Q**, and **R** are contract labels for captured values, not application types. Retention describes the supplied representation; it does not independently prove machine-level register preservation.

### Initial calls and early writes

At the start of each iteration, the byte later stored at captured G-A plus `0x15` is initialized to zero. Call this the **early-store byte**.

D01 is then invoked with two explicit zero arguments. Its target is the current represented link-register value plus `0xFFE`.

**Only after D01 returns**, a separate byte used in D06’s second argument is initialized to zero. Call this the **argument byte**. D02 and D03 follow, in that order. The representation does not place the argument-byte initialization before D01; equivalence of that reordering must not be assumed.

After D03, G-A is read as a word and retained as an address. D04 executes, followed by D05, whose composite result is retained as **P**.

D06 receives P-low and the expression formed from P-high plus P-low plus the argument byte. The high and low portions are first interpreted as signed 32-bit values for their addition; adding the unsigned argument byte does not remove uncertainty about overflow in that preceding signed addition.

After D06, its residual byte is stored at captured G-A plus `0x11`. D07 then executes. The early-store byte is stored at captured G-A plus `0x15`. Both stores use the earlier captured address even if intervening dependencies modify G-A.

D08 supplies a halfword result, which is stored at offset `0x0C` from the residual 32-bit base exposed after that call. Neither this residual base nor D06’s residual byte is established as an ordinary return value.

D09 supplies composite **Q**. A zero halfword is stored at Q-high plus `0x2C`. Next, Q-low unsigned-shifted right by 26 is stored as a word at B plus `0x26C`. This word is between 0 and 63.

### Captured-base update and breakpoint

The constant **C** is `0x21C48960`.

D10 executes before the word at B plus `0x320` is read and retained as a base address. D11 and D12 follow. Q-low unsigned-shifted left by two is then stored as a word at that captured base plus `0x54`. The shift retains the low 32 bits.

D13, D14, D15, D16, and D17 execute in order. An unsigned halfword is then read at C plus `0x34`, namely absolute address `0x21C48994`; its zero-extended value is **H**.

D18 executes before the word at B plus `0x280` is read. That newly read word is the explicit argument to D19, whose 32-bit result is **J**.

Software breakpoint `0x92` follows D19. No handling or resumption policy is established. All subsequent behavior is conditional on execution continuing past the breakpoint.

The read producing H is before D18. The read supplying D19’s argument is after D18. Neither may be moved across that call on an assumption of memory preservation.

### Post-breakpoint reads and indexed stores

After resumption, J is shifted left by two to form a represented index. J is represented as signed for this operation; behavior for invalid signed shifts is unresolved.

A second index is obtained by unsigned-shifting C right by 18 and multiplying by four. Its value is exactly `0x21C4`.

The word at H plus `0x44` is read and retained as base **R**. D20 executes, followed by D21, whose word result is retained. The word at H plus `0x04` is then read and passed to D22 together with D21’s result, in that argument order.

G-B is next read as address **T**. D23 executes before a halfword is stored at T plus the shifted J index. The stored value is the low 16 bits of T, not a value read from memory at T.

After D24, the word at absolute address `0x2218` is read and retained as base **U**. This address is `0x21C4 + 0x54`.

D25 returns a word used as address **V**. Halfword `0x21C4` is stored at V plus `0x04`. D26 and D27 follow. The unsigned halfword at U plus `0x34` is then read and zero-extended as **N**.

H is used directly as an address-bearing integer despite coming from a halfword. No additional enclosing base is supplied. Likewise, `0x2218` is a direct address in this representation, not an established object field.

### Composite result and base-state change

D28 supplies composite **W**. Its low word is stored at the current B plus `0x258`.

An unsigned halfword is then read at W-high plus `0x14`; its zero-extended value is **K**. W-low is shifted left by six to form a later address component, and W-high is multiplied by four to form another retained value. Both operations use signed 32-bit interpretations in the representation; their overflow and shift boundaries remain unresolved.

B is explicitly decreased by `0xF4`. Only afterward is `4 × N` formed, and W-low is stored as a word at `4 × N + 0x74`.

Thus, the B-relative W-low store precedes the decrement. No matching restoration appears at the loop boundary. The decrement must not be silently converted into a balanced local-frame adjustment.

Because N is at most 65,535, `4 × N` is at most 262,140. That multiplication itself does not overflow 32 bits.

### Final writes and loop transition

D29 executes before K is stored as a word at R plus `0x54`. D30 then executes before K is stored as a word at R plus `0x64`. These are separate updates, not an atomic pair.

D31 follows. The low 16 bits of R are stored at the address formed from shifted W-low plus the residual 32-bit address component exposed after D31.

D32 and D33 execute in order. One byte is then read from `N + 4 × N`, equivalently `5 × N`, and retained. D34 executes before this retained byte is stored at K plus A plus `0x19`. A modification of the source location during D34 does not itself replace the already captured byte.

D35 executes before the retained value `4 × W-high` is stored as a word at R plus `0x44`.

The final transition has this required order:

1. D36 returns.
2. The represented link register is assigned **`0x08712031`**.
3. The word at `4 × W-high + 0x44` is read while preparing D37’s argument.
4. D37 is invoked with that word.
5. The next iteration begins unconditionally if execution continues.

The link-register assignment precedes the argument read. If that read faults, the assignment has already occurred in the represented sequence, but D37 has not been invoked.

No restoration of B or the prior link-register value appears before the loop repeats. In the represented state flow, the next D01 target is derived from the assigned link-register value. Whether actual implicit register effects alter that machine-level transition is unresolved.

## Acceptance examples

These are conditional static acceptance criteria, not executed tests. They assume execution reaches the relevant operation and that required preceding operations complete.

1. **Initialization boundary.** On each iteration, the early-store byte is initialized before D01. The argument byte is initialized after D01 returns and before D02. A description placing both initializations before D01 does not satisfy the ordering contract, even though both assigned values are zero.

2. **Unsigned Q extraction.** For Q-low `0xFC000003`, the store at B plus `0x26C` writes 63. The later unsigned left-shifted store writes `0xF000000C`.

3. **Captured global base.** If G-A supplies address X and D04 subsequently changes G-A, the early byte stores still use X plus `0x11` and X plus `0x15` in the represented value flow.

4. **Breakpoint interruption.** If breakpoint `0x92` never resumes this function, none of the post-breakpoint accesses described here is reached.

5. **Halfword-derived addresses.** If H is `0x1234`, R is read at `0x1278`; D22’s second argument is read at `0x1238`. No additional base is implied.

6. **Truncating store.** If T is `0x12345678` and J is 3, with valid address arithmetic, the halfword store targets T plus 12 and writes `0x5678`.

7. **Separated K updates.** If K is `0xBEEF`, both R-relative K stores write `0x0000BEEF`. D30 executes between them and may observe or change memory.

8. **Retained byte.** If N is 7, the late source-byte read is at address 35. Changing that location during D34 does not change the previously captured byte used by the subsequent explicit store.

9. **Base progression.** If B starts at B₀ and no additional effective base change intervenes, the explicit decrement leaves B at B₀ minus `0xF4` for the next iteration. No restoration is implied.

10. **Fault after link-register assignment.** If D36 returns but the final argument read faults, the represented link register has already been assigned `0x08712031`. D37 has not yet been called. Fault-handler behavior and eventual continuation remain unspecified.
