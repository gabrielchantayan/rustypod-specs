# F-565c06b2ad32

## Purpose

F-565c06b2ad32 invokes a long sequence of indirect dependencies, derives address-like values from returned and implicit machine state, performs mixed-width memory updates, and finishes with an unresolved indirect transfer.

**Established static evidence:** the supplied representation exposes three explicit 32-bit inputs, additional entry-state dependencies, represented 32-bit and 64-bit results, computed and absolute memory accesses, and no explicit scalar output.

**[INFERENCE]** Repeated offsets and cross-location stores suggest manipulation of interconnected state. They do not establish an application purpose, object model, collection type, ownership graph, or synchronization protocol. Character-valued constants do not establish text generation.

This is a partial, source-facing contract. It specifies supported value relationships and ordering constraints without treating unavailable dependency interfaces or global declarations as known. Behavior outside those constraints remains **documented_only**.

| Third input | Unsigned 32 bits | Supplies the initial invocation’s repositioned ten-bit field. |

The initial derived argument extracts bits 4–13 of the third input and places them in bits 18–27. All other bits of that argument are zero. Its range is 0 through 0x0FFC0000, in increments of 0x00040000.

Bits 0–3 and 14–31 do not affect this derived argument. Neither that fact nor the second input’s lack of explicit use establishes independence of the whole execution from other incoming machine state.

### Dependency-result processing

### Widths and arithmetic

Explicit memory-access forms establish eight-bit byte accesses, 16-bit halfword accesses, and 32-bit word accesses. Represented 64-bit results are split into two 32-bit halves.

An explicit byte store retains the source’s low eight bits. An explicit unsigned-byte read converted to an unsigned word yields 0 through 255; it does not read four bytes.

Unsigned right shifts are logical. Right shifts of represented unsigned 64-bit results by 34, 36, and 44 correspond to logical shifts of their upper 32-bit halves by 2, 4, and 12.

Under **32-bit truncating bit-vector arithmetic**, scaling and left shifts discard bits above bit 31. A word shifted left by eight and then logically right by eight retains only its original low 24 bits. Successive in-range left shifts whose total displacement reaches 32 eliminate all original bits.

Signed-looking arithmetic must not be treated as portable, fully defined source-language arithmetic. Its executable overflow and conversion semantics remain **documented_only**.

A late variable right shift uses the low eight bits of a computed address-like word as its count. Counts can exceed 31. Arithmetic versus logical shifting, count masking, and oversized-count behavior are unresolved. The resulting relative byte store is explicitly eight bits; that does not resolve the preceding shift.

### Initial memory effects and clear/readback interval

The memory phase first publishes a saved shifted result to +0x14 through the upper half of the final represented result. It then updates a computed base’s +9 byte, stores an earlier scaled result through a destination derived from the final lower result half, and overwrites that +9 byte.

For the following interval:

- **First base** denotes an earlier dependency result scaled by 0x02000000.
- **Small base** denotes twice a field derived from another result.

Under 32-bit truncating arithmetic, that field is four times the result’s low seven bits: 0 through 508 in increments of four. The small base is therefore 0 through 1016 in increments of eight. These ranges do not establish valid mapped storage.

The first base’s +0x14 word is cleared before its +5 byte is read and saved. The small base’s +0x14 word is then cleared. The saved unsigned byte is recorded, zero-extended, at the first base’s +0x34 word, followed by an actual word readback from the first base’s +0x14.

A second clear of the small base’s +0x14 follows that readback. Two consecutive byte writes then place the readback word’s low byte at the small base’s +0x15.

The two small-base clears bracket the recording store and readback. Moving them together changes the represented trace and can change behavior under aliasing. Replacing the readback universally with zero requires additional memory and observation assumptions.

### First global-derived base and absolute publications

After those two +0x15-relative byte writes, the value of the undeclared global at 0x05 is converted to unsigned 32 bits and saved as the **first global-derived base**. This establishes the resulting value width, not the physical load width.

The assignment at absolute 0x01 uses an explicitly eight-bit-converted value of the small base. Its destination declaration is absent, so its store width is unresolved.

Subsequent relative effects include a byte update through the first global-derived base, a byte update followed by a zero overwrite at the first base’s +0x11, and a +0x54 word update selected by the earlier readback.

A 32-bit word is read from +0x54 of the first global-derived base before that field is overwritten. Call this the **captured word**. Later use depends on this saved word, not on reloading the overwritten field.

Further accesses select bases through +0x74 words, publish self-derived words at +0x24, and repeat byte updates at +9. One compound assignment reads the same +0x74 field for destination selection and for the stored value. A single cached read is not established.

The small base’s +0x14 word then receives an earlier dependency result shifted left by 26. **Between that update and the next +0x14 update**, absolute location 0x54 is assigned the captured word shifted left by one. The small base’s +0x14 next receives the captured word and then receives that same saved word again.

Thus the absolute assignment at 0x54 is a meaningful publication of a transformed saved value. Its right-hand side is a represented word-shift expression, subject to the arithmetic caveats above; the absent destination declaration leaves the absolute store width unresolved.

Next, two consecutive explicit byte writes place the low byte of four times the captured word at the small base’s +0x15. Absolute location 0x15 is then assigned an explicitly eight-bit-converted value of the small base. Only afterward do the subsequent scaled-base +0x54 and +0x34 updates occur. The conversion at absolute 0x15 does not establish that destination’s store width.

### Cross-location updates and mixed-width constants

Four times the captured word supplies another working base. Associated updates include repeated +0x54 replacements, byte stores at +9 and +0x15, and cross-location word stores at +0x44.

Explicit unsigned bytes read from +5 are used as bases for 32-bit reads at +0x74. Those intermediate bases range from 0 through 255. They must not be widened conceptually into pointer fields.

Later, a loaded word supplies scaled addresses receiving 0x3A through three distinct forms: an eight-bit store, a 16-bit store, and a 32-bit store at +0x20 from a scaled address.

An **adjusted address** is obtained by subtracting 0x96 from four times the captured word. Four times this adjusted address becomes the **adjusted computed base**. Its +0x20 word receives, in order, 0x20, 0x2F, the zero-extended unsigned byte read from its +4, and 0x20 again.

A separate global-derived base is saved after that sequence and before absolute location 0x60 is assigned 0x20. The absolute destination’s store width is unresolved.

### Repeated publication region

Each repeated group preserves this ordering:

- A +0x54 word receives the saved scaled value.
- The separate global-derived base’s +0x19 byte receives the adjusted computed base’s low byte.
- The adjusted computed base’s +0x11 byte receives the saved low byte of the separate global-derived base.
- The separate global-derived base’s +0x34 word receives a scaled address.

The first group uses eight times the captured word for its +0x54 base and +0x34 value. Subsequent groups use eight times the adjusted address instead.

The exact repetition count is outside this partial contract and remains **documented_only** here. Repeated stores must not be collapsed into final-state assignments without additional equivalence assumptions.

### Late absolute assignments and terminal preparation

After the repeated region, the function saves the undeclared global at 0xA9 into a represented 32-bit word and saves a +0x74 word from an earlier scaled base.

Absolute location 0x3A then receives an expression formed by converting the adjusted address to a character-sized value, multiplying that converted value by eight, and adding 0x30. **Arithmetic occurs after the character conversion. No final eight-bit truncation is established.** Character signedness, promotion details, and destination width remain unresolved.

This assignment precedes the saves from +0x14 of another working base and +4 of the adjusted computed base.

Later explicit relative byte updates include +0x0D, +9, and the 0x6C store at +8. Absolute location 0x67 is assigned an explicitly eight-bit-converted value of the saved 0xA9-derived word. After a working base’s +0x44 word is read, absolute 0x21 is assigned a fresh read of the global at 0x67. Neither absolute store has an established access width. The fresh read is not unconditionally interchangeable with the earlier saved word.

A byte update at the adjusted computed base’s +0x10 precedes its later 32-bit replacement from +0x40. Other interleaved effects include two different +0x54 values through the separate global-derived base, the variable-shift byte store, a saved +4 word written to +0x74, and further +0x44 and +0x54 updates. Additional +9 byte stores consume fresh reads of absolute 0x67.

Near completion, a word read from +4 selects a base whose doubled address receives the halfword 0x0065. Its +0x64 word supplies the second terminal argument; its later +0x74 word supplies the fourth. Another +0x54 field receives decimal 100.

A +0x64 word from a different working base selects a further +0x54 destination. The final direct store writes that loaded base value as a 32-bit word at twice the saved second terminal argument. The terminal transfer is reached only if this store completes.

### Alias-sensitive early ordering

Assume ordinary valid memory, no external mutation, and a small base equal to the first base plus 0x20. If the saved +5 byte is 0xE1, the first base’s +0x34 word receives zero from the first small-base clear, then 0x000000E1, then zero from the second clear. The first-base +0x14 readback occurs between the latter two stores.

Grouping both small-base clears after the readback violates this trace.

### Absolute publication ordering

Assume the captured word is 0x00000123 and truncating 32-bit shift semantics apply. The right-hand-side value assigned at absolute 0x54 is 0x00000246. That assignment occurs between the small-base +0x14 update using the earlier shifted dependency result and the update using 0x00000123. It does not establish a four-byte absolute store.

The later absolute 0x15 assignment must follow both repeated +0x15-relative byte writes and precede the subsequent scaled-base updates.

### Character conversion is not final truncation

If the adjusted address converts to the positive character value 0x42, the arithmetic assigned at absolute 0x3A produces 0x240 before destination conversion. Requiring 0x40 as the stored numerical value would require an additional eight-bit destination assumption.

Likewise, an explicitly eight-bit-converted right-hand side at 0x01 or 0x67 does not prove an eight-bit memory write.

### Mixed widths and interruption

An explicit unsigned-byte value 0xE1 recorded in a word becomes 0x000000E1. This criterion does not determine the load width of the undeclared global at 0x05.

The adjusted computed base’s +0x20 word-write sequence is 0x20, 0x2F, the byte-derived value, then 0x20.

If execution stops after earlier stores, acceptance must not require restoration or terminal invocation.
