# F-4a940af17369

## Purpose

F-4a940af17369 returns a 32-bit classification determined by a gate word and, when that gate permits further processing, a classification word. An opaque dependency can modify these words before they are tested.

Every normally completing invocation makes two dependency calls in a fixed order. If bit 0 of the resulting gate word is clear, the function returns zero. Otherwise, it makes a third dependency call and selects one of five nonzero results using ordered bit tests on the classification word.

**Established static behavior:** the function captures an address-bearing value from the first argument, initializes two writable 32-bit temporaries, and passes derived addresses and temporary addresses to F-0951c41713db. Dependency return values do not determine any branch or returned classification.

**Inferred intent:** the temporaries may represent flags, and the derived addresses may identify fields or processing contexts. These interpretations are not required by this contract.

**Unknown:** the application meanings of the arguments, selected bits, return values, and dependency operations are not established.

## Interface

The function has four arguments and returns a 32-bit word.

| Argument | Representation in the supplied source | Established use |
|---|---|---|
| First | Signed 32-bit integer used in an address expression | Locates a readable 32-bit value at byte offset `0x3C`. That value becomes the captured base for dependency arguments. |
| Second | Uninterpreted 32-bit word | Not read or forwarded by this function. |
| Third | Unsigned 32-bit word | Initializes the gate temporary. |
| Fourth | Unsigned 32-bit word | Initializes the classification temporary. |

On an ordinary return, the result is exactly one of:

| Result | Selection |
|---:|---|
| `0x00000000` | Post-second-call gate bit 0 is clear. |
| `0x0000004C` | Classification bit 0 has highest matching priority. |
| `0x0000004F` | Classification bit 6 has highest matching priority. |
| `0x0000004D` | Classification bit 1 has highest matching priority. |
| `0x0000004E` | Classification bit 2 or bit 5 has highest matching priority. |
| `0x00000051` | Gate is set, but none of the selected classification bits is set. |

No character encoding, application enumeration, narrower return width, or signed interpretation of the result is established.

## Behavior

### Initial read and initialization

Before any dependency call, the function reads the 32-bit value at the first argument plus byte offset `0x3C`.

After that read, it initializes two distinct writable 32-bit temporaries:

- The **gate temporary** receives the third argument.
- The **classification temporary** receives the fourth argument.

These role names do not imply application-level meanings.

The base is captured once. The function does not reread the location at offset `0x3C` between dependency calls. If a dependency changes that location, later dependency first arguments still derive from the captured value.

This capture rule does not imply that memory reachable through the captured base remains unchanged.

### First dependency call

The function calls F-0951c41713db with:

- Captured base plus `0x20` as its first argument.
- The address of the classification temporary as its second argument.

The classification temporary has been initialized from the fourth argument. The dependency can inspect or modify the supplied word; its actual behavior is unknown.

The wrapper ignores the dependency return value. It does not restore or reinitialize the classification temporary after the call.

This call occurs regardless of the original third argument’s bit 0. There is no gate test before the first two dependency calls.

### Second dependency call and gate decision

After the first call returns, the function calls F-0951c41713db with:

- Captured base plus `0x1C` as its first argument.
- The address of the gate temporary as its second argument.

The dependency return value is ignored.

After this call returns, the function tests bit 0 of the gate temporary:

- If bit 0 is clear, it returns `0x00000000`.
- If bit 0 is set, it proceeds to the third dependency call.

Only bit 0 directly controls this decision. All other bits of the gate temporary are ignored by the wrapper’s gate test.

The decision uses the temporary’s contents after the second call, not the original third argument. Processing may therefore enable a gate that was initially clear or clear a gate that was initially set.

The second call is not established to affect only the gate temporary. In particular, the dependency may retain the classification-temporary address supplied during the first call and modify that temporary during the second call.

### Conditional third dependency call

When gate bit 0 is set, the function calls F-0951c41713db with:

- Captured base plus `0x04` as its first argument.
- The address of the same classification temporary supplied to the first call.

The wrapper performs no intervening reinitialization of that temporary. The third call receives its then-current contents, including any modifications made during earlier dependency calls.

This is not a guarantee that the value left by the first call survives until the third call. Retaining the temporary’s storage is different from preserving its contents.

The third dependency return value is ignored. Once that call returns, the wrapper classifies the resulting classification word. It does not test the gate again.

### Classification order

The first matching condition in the following table determines the return value:

| Priority | Condition on the classification word after the third call | Return |
|---:|---|---:|
| 1 | Bit 0 is set. | `0x0000004C` |
| 2 | Bit 0 is clear and bit 6 is set. | `0x0000004F` |
| 3 | Bits 0 and 6 are clear and bit 1 is set. | `0x0000004D` |
| 4 | Bits 0, 6, and 1 are clear, and at least one of bits 2 and 5 is set. | `0x0000004E` |
| 5 | None of the preceding conditions matches. | `0x00000051` |

The fourth condition uses mask `0x00000024`. Either selected bit is sufficient; both are not required.

The union of classification masks is `0x00000067`. Bits outside that mask do not directly affect the final selection. They may still influence dependency processing before the wrapper reads the final word.

## Side effects

### Direct reads and writes

The wrapper directly performs these operations in order:

1. Reads the 32-bit captured base from the first argument plus `0x3C`.
2. Writes the third argument into the gate temporary.
3. Writes the fourth argument into the classification temporary.
4. Makes the first and second dependency calls.
5. Reads the gate temporary for the gate decision.
6. If the gate is set, makes the third dependency call and reads the classification temporary for classification.

The classification tests occur in priority order; lower-priority tests are reached only when higher-priority conditions fail.

No direct write through the first argument is shown. The wrapper contains no explicit global write, allocation, release, logging, or external I/O. Those observations do not restrict effects performed by F-0951c41713db.

### Call relationships

Assuming all reached dependency calls return normally:

- A clear post-second-call gate produces exactly two dependency calls.
- A set post-second-call gate produces exactly three dependency calls.
- Their first-argument displacements are always `0x20`, then `0x1C`, then conditionally `0x04`.
- The first and third calls receive the same classification-temporary address.
- The second call receives the distinct gate-temporary address.

Effects of an earlier call may influence later calls through the supplied temporaries, retained pointers, globals, or other memory. The wrapper provides no rollback.

### Ownership and lifetime

The two temporaries are invocation-local storage. Passing their addresses provides writable access but does not establish ownership transfer.

The wrapper does not allocate or release these temporaries through a memory-management dependency. Their addresses are not caller-owned persistent output storage.

The dependency’s pointer-retention behavior is unknown. Retention between calls within this invocation must not be ruled out: the first call exposes the classification temporary before the second call occurs. Any retention or access after the invocation ends has no established valid lifetime under this contract.

Ownership, allocation, and release behavior associated with the dependency’s first argument remain unknown.

### Errors and abnormal completion

A dependency return value, by itself, does not select an error path. The dependency’s memory effects may still change the eventual classification.

Zero is the normal clear-gate result, not an established error code. Likewise, `0x00000051` is the normal set-gate fallback, not an established failure indication.

## Acceptance examples

These are conditional acceptance criteria derived from static evidence. They are not runtime observations. Each assumes meaningful address arithmetic, valid required storage, normally returning dependency calls, and the stated temporary contents at the relevant reads.

### Gate cleared after processing

If the gate temporary is `0x00000000` when tested after the second call:

- The result is `0x00000000`.
- The third call does not occur.
- The classification word does not affect the result.

This applies even when the original third argument was odd. A gate value of `0x80000000` also returns zero because bit 0 is clear.

### Gate enabled after processing

If the original third argument is zero but the gate temporary is `0x80000001` when tested after the second call, the third call occurs. The high bit does not inhibit the set bit 0.

### Individual classification cases

With the gate set, the following words at classification time produce these results:

| Classification word | Return | Reason |
|---:|---:|---|
| `0x00000000` | `0x00000051` | No selected bit is set. |
| `0x00000001` | `0x0000004C` | Bit 0 is set. |
| `0x00000040` | `0x0000004F` | Bit 6 is set. |
| `0x00000002` | `0x0000004D` | Bit 1 is set. |
| `0x00000004` | `0x0000004E` | Bit 2 alone satisfies the final mask. |
| `0x00000020` | `0x0000004E` | Bit 5 alone satisfies the final mask. |
| `0x80000000` | `0x00000051` | Only an untested bit is set. |

### Overlapping bits

With the gate set:

- `0x00000067` returns `0x0000004C`; bit 0 takes precedence.
- `0x00000066` returns `0x0000004F`; bit 6 outranks bits 1, 2, and 5.
- `0x00000026` returns `0x0000004D`; bit 1 outranks bits 2 and 5.
- `0x00000024` returns `0x0000004E`; both final-mask bits may be set without changing that selection.

### Intervening modification of the classification temporary

Suppose:

- The first call writes `0x00000001` to the classification temporary and retains its address.
- During the second call, the dependency uses that retained address to overwrite the classification temporary with zero and sets gate bit 0.
- The third call leaves the classification temporary at zero through the classification read.

The result is `0x00000051`, not `0x0000004C`.

The required invariant is that the wrapper does not reinitialize the classification temporary. The third call receives its then-current contents, including intervening dependency modifications. No preservation of the first call’s written value is guaranteed.

### Captured base

If the first call changes the value stored at the first argument plus `0x3C`, later dependency arguments still use the original captured base: plus `0x1C` for the second call and, if reached, plus `0x04` for the third.
