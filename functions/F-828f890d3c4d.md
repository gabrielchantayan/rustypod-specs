# F-828f890d3c4d

## Purpose

F-828f890d3c4d retrieves the two least-significant bits of a word reached through an indexed address table.

The supplied static evidence establishes a two-stage lookup: select an address-bearing entry using the input index, then read a word at a fixed offset from that address. The returned value is the word masked with hexadecimal `0x00000003`.

Interpreting the result as a status, mode, flag pair, or enumeration would be inferred intent. The evidence establishes only the bit extraction, not the meaning of either bit.

## Interface

**Input:** One signed short integer, used as an index without an explicit bounds check.

**Output:** An unsigned integer containing only the two least-significant bits of the final word read. If execution completes normally, the result is exactly one of 0, 1, 2, or 3.

**Apparent data model:** The supplied representation is consistent with a 16-bit signed input and 32-bit integers, unsigned words, and addresses. Under that model:

- The input range is −32,768 through 32,767.
- Each address-table read obtains four bytes.
- Each final data read obtains four bytes.
- The result is a 32-bit unsigned value, although only its lowest two bits can be nonzero.

These widths describe the apparent recovered model, not an independently verified ABI. The source fragment does not include type-size declarations or calling-convention information. Exact ABI widths remain `documented_only` where the apparent model cannot be assumed.

**Implicit input:** A shared base value identifies the origin of the indexed address storage. Its initialization, ownership, lifetime, and permitted range are not supplied.

**Caller preconditions for a successful lookup:**

- The input must select readable address storage under the platform’s address-arithmetic rules.
- The selected entry must contain an address usable for the subsequent offset read.
- Four bytes beginning 1,024 bytes beyond that address must be readable under the apparent 32-bit model.
- Any alignment requirements imposed by the execution environment must be satisfied.
- The storage must remain usable for the duration of both reads.

There is no explicit error return, output parameter, or accompanying validity indicator.

## Behavior

### Indexed address selection

The function uses the signed input directly as an index into storage with a stride of 396 bytes, hexadecimal `0x18C`.

The first read is located at the shared base plus the input multiplied by that stride. The function reads the address-bearing integer at the beginning of the selected stride position. It does not inspect the intervening bytes or read an entire 396-byte record.

Under the apparent 16-bit input and 32-bit arithmetic model, the multiplication itself fits in a signed 32-bit integer for every representable input:

- The minimum displacement is −12,976,128 bytes.
- The maximum displacement is 12,975,732 bytes.

This establishes that the index multiplication does not require overflow under that model. It does not establish that adding the displacement to the shared base produces a valid address.

A negative input produces a negative displacement. The function does not reject negative indices, convert them into positive indices, or clamp them to zero. Whether such a displacement selects valid storage depends on the shared base and its surrounding memory layout.

### Indirect word selection

The integer obtained by the first read supplies the address used for the second lookup. The function adds 1,024 bytes, hexadecimal `0x400`, to that address and reads an unsigned word there.

The layout therefore has two distinct offsets:

| Element | Location |
|---|---|
| Selected address-bearing entry | Shared base plus signed index multiplied by 396 bytes |
| Word whose low bits are returned | Loaded address plus 1,024 bytes |

The 1,024-byte offset is relative to the loaded address, not directly relative to the shared base or selected entry.

The evidence does not establish an object type for the pointed-to storage. It also does not establish that the selected address is the start of an allocation, that an allocation is at least 1,028 bytes long, or that the final word has any particular semantic role.

### Result formation

The final word is masked with the value 3. Bit 0 of that word becomes bit 0 of the result; bit 1 becomes bit 1 of the result. Every other result bit is zero.

This is a low-two-bit extraction, not a Boolean conversion. Words whose low two bits are binary `10` or `11` return 2 or 3 respectively.

No further lookup, normalization, or validation is visible after the word is read.

### Observable ordering

The address-table read precedes the final word read because its value determines the final read address. The result is formed from the word obtained by that second read.

The supplied representation contains no explicit retry, consistency check, lock, or snapshot mechanism. It does not establish that concurrent modifications are excluded. In particular, it provides no guarantee that the selected address and the word reached through it represent one coherent externally managed state.

The shared base is an implicit dependency. The fragment does not establish whether obtaining it entails an additional mutable-memory read or uses an already materialized address value. The two dependent data reads described above are established; the exact machine-level access sequence for obtaining the base is not.
