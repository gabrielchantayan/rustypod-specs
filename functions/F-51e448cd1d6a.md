# F-51e448cd1d6a

## Purpose

F-51e448cd1d6a updates a caller-provided integer record. It increments the first field, conditionally replaces a selected value while sometimes retaining its predecessor, and unconditionally stores a second supplied value.

The established behavior is a mutation of individual integer slots, not an atomic replacement of the record. Zero has special significance in the selected-value slot: replacing an initial zero does not update the predecessor slot.

Interpreting the fields as an invocation count, current selection, previous selection, and associated value is plausible intent, not an established application-level meaning. The contract below therefore identifies fields by slot number.

## Interface

The function accepts three inputs:

| Input | Role |
|---|---|
| Record address | Address of a writable sequence of integer slots. The function accesses slots 0, 1, 3, and conditionally 4. |
| Selection value | Integer compared with, and conditionally stored into, slot 3. |
| Associated value | Integer unconditionally stored into slot 1. |

There is no explicit return value or status result. The observable result is the mutation of the supplied record.

### Record layout

Slot numbering starts at zero.

| Slot | Established role |
|---|---|
| 0 | Incremented once per normal completion. |
| 1 | Replaced with the associated value. Its previous contents are not read. |
| 2 | Not explicitly read or written. |
| 3 | Read and conditionally replaced with the selection value. |
| 4 | Receives a displaced, nonzero slot-3 value only when that value differs from the selection value. |

The supplied declaration uses signed integer elements and signed integer value arguments. It does not independently establish their bit width, byte size, alignment, or byte order.

If the intended platform uses 32-bit integers occupying four 8-bit bytes, the slot starting offsets are respectively 0, 4, 8, 12, and 16 bytes. That layout is conditional, not a verified platform fact. More generally, each slot begins at its index multiplied by the size of the declared integer type.

### Preconditions

For ordinary, defined operation:

- The record address must designate live, suitably aligned storage for every accessed slot.
- Slot 0 and slot 3 must contain valid, readable integer values.
- Slots receiving writes must be writable.
- Incrementing slot 0 must be representable under the applicable arithmetic semantics.
- Concurrent or asynchronous modification must be excluded if the caller requires the deterministic state transitions described below.

Providing a writable five-element integer record is sufficient for the storage requirement. Slot 4 is written only on one branch, but callers should not infer a general short-record interface from that conditional access.

The value arguments are supplied by value. They are not addresses of additional objects and do not themselves establish any ownership relationship.

## Behavior

The following describes the normal sequential behavior established by the supplied function body. It assumes valid storage, valid arithmetic, and no external interference.

### Counter update occurs first

The function reads slot 0 and replaces it with its value plus one.

This happens before inspecting slot 3 and before storing the associated value. It occurs even when the selection value equals the existing slot-3 value.

The supplied body contains no overflow check. It also contains no explicit conversion to unsigned arithmetic or other mechanism establishing wraparound. Under ordinary signed-language arithmetic semantics, exceeding the signed maximum is not a defined wrapping operation. A machine-level wraparound guarantee cannot be derived from this material alone.

### Zero-valued selection initialization

The function next reads slot 3 to determine whether it is zero.

If that value is zero, the function writes the supplied selection value into slot 3. This write occurs even when the supplied selection value is also zero.

After that conditional write, the function reads slot 3 again and retains that value for its subsequent comparison and possible predecessor update.

With stable ordinary memory, an initially zero slot 3 therefore becomes equal to the supplied selection value before the comparison. This path does not update slot 4.

### Nonzero selection replacement

If the retained slot-3 value differs from the supplied selection value, the function:

1. Writes the supplied selection value into slot 3.
2. Writes the retained slot-3 value into slot 4.

The slot-3 replacement precedes the slot-4 write. The value written to slot 4 is the retained value from the earlier read, not a reread of slot 3 after replacement.

Without external interference, this replacement path is taken exactly when the original slot-3 value is nonzero and differs from the supplied selection value.

Consequences include:

- Repeating an existing nonzero selection leaves slot 4 unchanged.
- Replacing a nonzero selection with zero records the displaced nonzero value in slot 4.
- Replacing zero with a nonzero selection leaves slot 4 unchanged.
- Supplying zero when slot 3 is already zero leaves slot 4 unchanged.

Slot 4 is thus a conditionally updated predecessor field, not an unconditional copy of the entry value of slot 3.

### Associated-value write occurs last

After the selection handling, the function unconditionally writes the associated value into slot 1.

This is the final explicit record write. It occurs whether the selection was initialized, changed, or already equal.

### Normal final state

Under the stated preconditions and without external interference:

- Slot 0 equals its entry value plus one.
- Slot 1 equals the supplied associated value.
- Slot 2 is unchanged.
- Slot 3 equals the supplied selection value.
- Slot 4 equals the entry value of slot 3 only if that entry value was nonzero and differed from the selection value; otherwise slot 4 is unchanged.

These final-state rules do not imply that every field is always written. In particular, an already matching nonzero slot 3 is not written, whereas an already zero slot 3 is written when the selection value is zero.
