# F-462e250a410a

## Purpose

F-462e250a410a performs a state-dependent operation on a receiver. After an entry operation on an embedded receiver region, it checks an attachment and chooses between an unsigned comparison branch and a candidate-processing branch.

Its normal return is a 32-bit value:

- **0:** the initial attachment check finds zero, or candidate processing returns zero.
- **1:** the comparison branch completes, or the accepted-candidate path completes.

These values describe control flow, not general success. Returning 1 does not establish that any dependency succeeded, changed state, or released resources.

“Candidate,” “current,” “target,” and “transition” are descriptive role labels. Synchronization, construction, and destruction are possible interpretations of certain calls, not established effects.

## Behavior

### Entry and attachment check

The function computes the embedded address at receiver offset `0xA4C` and passes it to an unresolved entry operation. The same computed address is used for the exit operation.

Only after entry returns does it inspect the attachment field at `0x054`.

If that field is zero, it invokes the exit operation and returns **0**. No comparison calls, candidate lookup, buffer calls, or transition calls occur.

Otherwise, it derives an attached-subobject address from the attachment value plus four bytes. It then obtains, in order:

1. The receiver-side value through receiver slot `0x17C`.
2. The attachment-side value through attached-subobject slot `0x094`.

The subobject address for the second call is derived before the first call. The attachment is not reloaded between these calls. A change to the attachment field during the receiver call therefore does not redirect this particular attached-subobject call.

### Unsigned comparison branch

The attachment-side value is added to decimal **3000** using 32-bit unsigned arithmetic. The resulting wrapped value is compared with the receiver-side value as unsigned.

The branch is selected exactly when the wrapped sum is **strictly less** than the receiver-side value.

Consequences:

- Equality selects candidate processing.
- Addition wraps modulo \(2^{32}\).
- There is no widened, saturating, or explicitly wrap-aware elapsed-time calculation.

When this branch is selected, the function:

1. Obtains a value through receiver slot `0x158`.
2. Calls F-6542ebfeed7d with the receiver, that value, and zero.
3. Calls F-9585ac57a521 with the receiver.
4. Invokes the exit operation.
5. Returns **1**.

The candidate path and both 24-byte buffer sequences are skipped.

### Candidate lookup and rejection

When the comparison branch is not selected, the function initializes the candidate in/out word to zero. It then:

1. Obtains a value through receiver slot `0x158`.
2. Calls F-e41650e0b8d9 with the embedded address at `0x060` and that value.
3. Reads a 32-bit field at offset `0x10` from the returned address.
4. Calls F-bd703d4ee601 with the receiver, the field just read, the flags with bit `0x80` forced on, and the candidate word’s address.

Flag augmentation is a 32-bit bitwise OR. No caller-supplied flag bits are cleared.

If F-bd703d4ee601 returns zero, the function invokes receiver slot `0x0EC`, invokes the exit operation, and returns **0**. The candidate word cannot override this rejection result. Neither 24-byte buffer receives the later buffer-related calls.

A nonzero return continues along the accepted-candidate path and is retained for target derivation.

### First candidate-word read and optional sequence

The function reads the candidate word and tests whether its low eight bits are nonzero. Upper bits alone do not activate this sequence.

If the tested low byte is nonzero, these operations occur in order:

1. F-76b7ec0cf6ba, without explicit arguments.
2. F-cb37c5f052d2, without explicit arguments.
3. A read of receiver field `0x948`, whose value is passed to F-7deb104ce23c.
4. An unresolved operation receiving the embedded address at `0x088`.
5. F-b582c09a05ae with the receiver.

This condition uses the candidate word’s contents at this first read. It does not establish the value used later by F-6542ebfeed7d. The word’s address has escaped to F-bd703d4ee601, and preservation across intervening calls is not established.

### Target derivation and buffer processing

F-6fa4e01d8d29 receives the retained nonzero candidate result, `0x33`, and zero. Its 32-bit return supplies the target value.

For clarity, the first 24-byte buffer below is called the **current buffer**, and the second the **target buffer**. These labels describe subsequent arguments, not internal layout or ownership.

The observed order is:

2. Call F-ba5a4c1e0746 with the target buffer’s address and two zeros.
3. Obtain a fresh value through receiver slot `0x158`.
4. Invoke receiver slot `0x170` with that value and the current buffer’s address.
5. Invoke receiver slot `0x170` with the target value and the target buffer’s address.
6. Call F-6e482452607b with the current buffer’s address.

The fresh slot-`0x158` value need not equal the earlier lookup value.

F-ba5a4c1e0746 may have a construction-like role, but the established behavior is only the calls with the specified addresses and arguments. Initialization or resource acquisition is not established.

### Attached-state calls and second candidate-word read

The function reloads the attachment, derives its subobject at plus four bytes, and invokes slot `0x168` with the first attached-state output address.

It then reads the candidate word again and forms the F-6542ebfeed7d argument by masking that read to the low eight bits. F-6542ebfeed7d receives:

- The receiver.
- The derived target value.
- The masked value from this later read, in the range 0–255.

This is not a retained copy of the earlier branch condition. Intervening dependencies, including the first slot-`0x168` call, may have affected storage reachable through an escaped address. The optional sequence can therefore be selected using one low-byte value while the transition receives another. The value passed is not normalized to 0 or 1.

After F-6542ebfeed7d returns, the attachment is reloaded again. The corresponding attached subobject receives slot `0x168` with the second output address. Neither later attachment use has an explicit null check.

The function then compares the **32-bit contents of the two output slots at comparison time**. Equality selects F-9585ac57a521 with the receiver; inequality omits it.

This is not necessarily a comparison of immutable snapshots taken at the two calls. The first output address has already escaped, so later calls may modify its contents before comparison. The two subobject calls also need not address the same attachment; no identity comparison is performed.

### Final dispatch and exit

Receiver slot `0x190` is invoked next.

- If its result is zero, the function reads the then-current attachment and passes it, zero, and zero to F-04d3f7ecf9cb.
- Otherwise, it calls F-0edcc41cb6b7 without explicit arguments.

The function then calls F-4e292a3dd745 first with the target buffer’s address and then with the current buffer’s address. This reverses the order of the earlier F-ba5a4c1e0746 calls.

Finally, it invokes the exit operation and returns **1**.

## Acceptance examples

These are conditional static acceptance cases, not executed tests. They assume valid accesses and normal dependency returns.

1. **Absent attachment.** If the attachment is zero after entry, exit follows and the result is 0. No comparison dispatch occurs.

2. **Strict boundary.** Receiver value 10,000 and attachment-side value 7,000 select candidate processing because the sum equals 10,000. An attachment-side value of 6,999 instead selects the comparison branch.

3. **Unsigned overflow.** Attachment-side value `0xFFFFFFFF` plus 3000 yields 2999. Receiver value 3000 therefore selects the comparison branch.

4. **Flag preservation.** Flags `0x00000001` become `0x00000081`; flags `0x80000000` become `0x80000080`.

5. **Rejected candidate.** A zero candidate result selects slot `0x0EC`, exit, and return 0, regardless of the candidate word.

6. **Candidate word left unwritten.** If no dependency modifies the explicitly initialized word, both low-byte reads yield zero. Candidate acceptance does not require F-bd703d4ee601 to write it.

7. **Upper bits only.** A word of `0x00000100` at the first read skips the optional sequence. The transition receives zero only if the later read also has a zero low byte.

8. **Unnormalized low byte.** A first-read value of `0x123456A5` selects the optional sequence. If the later read still has low byte `0xA5`, the transition receives `0xA5`, not 1.

9. **Changed candidate word.** A zero low byte at the first read skips the optional sequence. If an intervening dependency changes it to `0x7E` before argument formation, the transition receives `0x7E`.

10. **Short-circuit evaluation.** A zero current-buffer evaluation skips target-buffer evaluation. A nonzero current result followed by a zero target result selects the ordered dependency pair.

11. **Repeated pair.** A nonzero first-read low byte, followed by nonzero current-buffer and zero target-buffer evaluations, causes each member of the pair to execute twice.

12. **Comparison-time storage.** If the first attached-state call writes 7, but a later dependency changes that slot to 9 and the second slot contains 9 at comparison time, F-9585ac57a521 is selected. Original write values alone do not determine the branch.

13. **Final ordering.** Either final-dispatch outcome is followed by F-4e292a3dd745 on target buffer, then current buffer, then exit and return 1. This establishes call order, not successful destruction.
