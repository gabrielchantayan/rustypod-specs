# F-a0f78003cb6f

## Purpose

F-a0f78003cb6f selects one of eight fixed numeric displacements using an unsigned selector and returns an adjusted scalar value. Selectors zero through seven are recognized. Every other selector returns zero without performing a selected adjustment.

The recognized selectors use two distinct arithmetic paths:

- Selectors zero through three use a displacement computed from the **unsigned selector**, followed by mixed signed/unsigned addition and conversion to the signed result type.
- Selectors four through seven add fixed constants directly to the signed first argument.

This distinction affects the established result for negative inputs and arithmetic boundaries. A mathematically representable signed sum is not, by itself, sufficient to establish the result of the first path.

The displacement pattern is consistent with selecting locations relative to a base, but that purpose is **inferred intent**, not an established storage contract. The function does not dereference the first argument or validate any resulting location.

Zero is both the result for unsupported selectors and a possible result for recognized selectors. The return value alone does not distinguish those cases.

### Selectors zero through three

For these selectors, the displacement is the unsigned selector multiplied by 32. Under the conditional 32-bit interpretation, the multiplication is unsigned and produces exactly zero, 32, 64, or 96. It cannot overflow because it is reached only for selectors below four.

The subsequent addition is also unsigned. The signed first argument is converted to the unsigned arithmetic type before addition. The unsigned sum is reduced modulo 4,294,967,296 and then converted to the signed type when stored for return.

The final conversion has two materially different cases:

- If the unsigned sum is at most 2,147,483,647, its signed value is representable and the conversion preserves that value.
- If the unsigned sum exceeds 2,147,483,647, the supplied representation does not establish a particular signed result. The applicable implementation-defined conversion behavior remains unknown. Depending on the governing language model, an implementation-defined signal may also be relevant.

This uncertainty is not signed-addition overflow. The addition on this path is unsigned and has defined modular arithmetic under the stated interpretation. The unresolved step is the conversion of an out-of-range unsigned result to the signed type.

Let the *mathematical sum* mean the first argument plus the selected displacement, evaluated without machine-width limitations. Within the stated input range:

- A mathematical sum from zero through 2,147,483,647 establishes that same returned value.
- A negative mathematical sum produces a large unsigned result before the final conversion. Its negative signed interpretation is not established without an additional conversion-model assumption.
- A mathematical sum above 2,147,483,647 also requires an out-of-range unsigned-to-signed conversion and has no established signed result.

A negative first argument does not necessarily make the result uncertain. For example, −32 with selector one reaches an unsigned sum of zero after modular addition, so the result is established as zero.

Conversely, selector zero is not unconditionally an identity operation. It has zero displacement, but a negative first argument still undergoes unsigned arithmetic followed by an out-of-range conversion back to signed. Returning that same negative value requires an additional implementation assumption.

### Selectors four through seven
