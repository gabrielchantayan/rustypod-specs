### Initial direct accesses and the cleared-word invariant

The initial access order is established as follows:

1. A word containing the anchor is written at the final pair’s high portion plus `0x14`.
2. The low byte of that high portion is written at anchor plus nine.
3. Wide base is written as a word at the final pair’s low portion multiplied by 256, plus `0x54`.
4. Anchor’s low byte overwrites the byte at anchor plus nine.
5. The word at wide base plus `0x14` is cleared.
6. The byte at wide base plus five is loaded.
7. The word at small base plus `0x14` is cleared.
8. The captured byte is zero-extended into the word at wide base plus `0x34`.
9. The word at wide base plus `0x14` is read.

In stable, ordinarily byte-addressed memory under 32-bit bit-vector arithmetic, the last read returns zero. Ordinary aliasing among these intervening writes cannot invalidate that conclusion:

- Wide base and small base are both multiples of eight.
- Their offset-`0x14` word starts therefore differ by a multiple of eight. The words are either disjoint or identical.
- If identical, the intervening small-base clear writes zero again.
- Wide-base offsets `0x14` and `0x34` are 32 bytes apart and do not overlap.

External mutation, read-sensitive devices, or unusual mappings in which distinct numerical addresses denote the same storage remain unresolved. Those possibilities are separate from ordinary address aliasing supported by these calculations.

The small-base word is then cleared again, followed by two distinct byte stores at small base plus `0x15`, both derived from the captured word.

## Acceptance examples

These are conditional static criteria, not executed tests.

### Distinct anchor and retained value

If the anchor-producing low portion is one, anchor is `0x02000000` under bit-vector arithmetic. The first direct word store contains that value, and both early offset-nine byte stores address `0x02000009`.

If the separate retained-value producer returns three, retained value is `0x00000300`; it does not replace anchor in those early accesses. The second early offset-nine store writes zero.

### Early argument transformation

If the incoming register value is three and the first dependency returns two, the next invocation receives 512 and 48 as its two explicit arguments, assuming 32-bit bit-vector semantics.

### Narrow-index boundary

If the narrow-index producer returns `0xFFFFFFFF`, its shifted-and-masked value is `0x7F00`; narrow index is 508 and small base is 1016.

### Guaranteed initial zero under ordinary memory assumptions

If execution reaches the initial wide-base offset-`0x14` read in stable byte-addressed memory, it returns zero under the conditional arithmetic model. This holds whether the intervening small-base clear is disjoint or addresses the same word.

A nonzero result requires behavior outside those assumptions, not merely ordinary aliasing among the specified intervening writes.

### Zero-extension and width

A captured byte of `0xFE` is written as word `0x000000FE`, not `0xFFFFFFFE`. The three `0x3A` stores retain their byte, halfword, and word widths.

### Capture timing

If a computed offset-four capture overlaps fixed address `0x3A`, acceptance uses the state after the fixed-address byte store. The fixed-address-`0xA9` capture and published-value offset-`0x74` capture precede that store.

### Fresh fixed-byte reads

If a computed write between the last two fixed-address-`0x67` reads changes that byte, the later publication-address offset-nine store uses the newly read byte. Reusing the first read is not equivalent.
