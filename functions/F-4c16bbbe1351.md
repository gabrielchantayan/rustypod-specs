# F-4c16bbbe1351

## Purpose

F-4c16bbbe1351 performs an unbounded sequence of indirect calls, selector-mediated byte writes, direct byte clears, and computed-address word accesses. Dependency results determine subsequent call arguments, memory addresses, stored values, and state carried into the next iteration.

The supplied static evidence establishes no application-level purpose. In particular, it does not establish an allocator, serializer, device interface, or ownership-management operation.

There is no visible normal return. If all dependencies return normally and all accesses succeed, execution begins another iteration.

### Width and layout conventions

The following notation describes represented 32-bit dataflow:

- \(L_n(x)\): left shift by \(n\), retaining the low 32 bits.
- \(T_k(x)\): multiplication by \(k\), retaining the low 32 bits.
- \(b(x)\): low eight bits.
- \(h(x)=((x\mathbin{\&}\mathrm{0x3fffffff})\gg20)\), with logical right shift.
- \(p(x)=T_4(x)+\mathrm{0x14}\).
- \(q(x)=T_{16}(x)+\mathrm{0x14}\).
- \(r(x)=T_{16384}(x)+\mathrm{0x14}\).

Address arithmetic is interpreted at 32 bits. This is a machine-width interpretation of the visible expressions, not a claim that equivalent signed-language expressions have portable overflow semantics.

A **selector operation from base \(a\)** reads one unsigned byte at \(a+1\), zero-extends it, and writes a byte at the selector value plus \(\mathrm{0x11}\). Consequently, its byte destination is between \(\mathrm{0x11}\) and \(\mathrm{0x110}\), inclusive. Each occurrence reads its selector afresh unless reuse of a saved selector is explicitly stated.

A **word** is 32 bits and occupies four bytes. Endianness, alignment requirements, and address-space interpretation are unresolved.

A represented 64-bit result is described as a low 32-bit word and a high 32-bit word. When both are forwarded, the low word precedes the high word in the explicit argument order.

## Behavior

### Ordering and dependency conventions

Every dependency event below is an occurrence of **F-UNRESOLVED**. That identifier does not imply that different occurrences share a target.

A **four-call acquisition** consists of four ordered calls without explicit arguments. The first three results are not explicitly retained; the fourth supplies the named result. A **four-call gap** has the same four calls but no explicitly retained result.

“No explicit arguments” describes only the supplied representation, not a complete ABI. Calls with unused results remain observable events and may affect memory or globals. The contract does not permit removing them or moving them across the described accesses.

### 1. Opening calls and fourth-input resets

The opening call receives the current first input. Its target is the current ambient dispatch value plus \(\mathrm{0xffe}\).

The following dependency sequence produces an **opening result**: a no-explicit-argument call returns a 64-bit pair; the next call receives its low and high words; one further no-explicit-argument call occurs; another supplies the opening result.

A selector operation from the ambient selector-source address then writes the ambient byte. Only afterward does a call receive \(L_2(\text{opening result})\). A four-call acquisition supplies the **primary index**.

A selector operation from \(T_4(\text{fourth input})\) writes zero. The following calls receive, in order:

- \(L_{10}(\text{fourth input})\);
- no explicit arguments, producing a word;
- that word followed by \(L_{28}(\text{third input})\).

A four-call acquisition supplies the **first reset result**. A fresh selector operation from \(T_4(\text{fourth input})\) writes zero before a call receives \(L_2(\text{first reset result})\). A four-call gap separates that call from the first word store.

### 2. First word propagation

The **first word value** is \(L_{14}(\text{primary index})\). It is stored at \(r(\text{primary index})\).

The following dependency sequence consists of:

- A call receiving \(L_{16}(\text{primary index})\).
- One no-explicit-argument call.
- A call receiving \(L_{28}(\text{first word value})\), followed by an additional register-supplied word whose producer is unresolved.
- A four-call acquisition of the **first mirror index**.

The first word value is then stored at \(p(\text{first mirror index})\). A call receives \(T_4(\text{first mirror index})\), followed by a four-call acquisition of the **secondary index**.

A fresh selector operation from \(T_4(\text{fourth input})\) writes \(b(h(\text{first word value}))\).

Next, a call receives \(L_{26}(\text{primary index})\); a no-explicit-argument call produces a word; and a call receives that word followed by \(L_{30}(\text{secondary index})\). Another no-explicit-argument call returns a 64-bit pair, whose low and high words are forwarded together. One further no-explicit-argument call occurs, and another supplies the **second reset result**.

A fresh selector operation from \(T_4(\text{fourth input})\) writes zero. A call then receives \(L_2(\text{second reset result})\). A four-call acquisition supplies the **second value index**.

Under the stated 32-bit interpretation, \(L_{28}(\text{first word value})\) is always zero: the first word value already has fourteen low zero bits.

### 4. Direct clears and computed word read

Two direct byte stores write zero: first at clear base plus \(\mathrm{0x11}\), then at clear base plus 1. Neither store reads a selector.

A call receives \(L_2(\text{lookup selector value})\). A no-explicit-argument call produces a word, which the next call receives unchanged. A four-call acquisition supplies the **clear reset result**.

The same two direct zero-byte stores occur again in the same order. A call then receives \(L_2(\text{clear reset result})\), followed by a four-call acquisition of the **fifth value index**.

A word store writes \(L_{31}(\text{fourth mirror index})\) at \(q(\text{fifth value index})\). With no intervening dependency call, a word is read at:

\[
h(\text{lookup selector value})+\mathrm{0x14}.
\]

The starting address lies between \(\mathrm{0x14}\) and \(\mathrm{0x413}\), inclusive, and is not necessarily aligned. Its calculation uses the captured lookup selector value, not a fresh memory read.

### 5. Third-input replacement and saved selector

A call receives \(T_4(\text{fifth value index})\). The next no-explicit-argument call supplies the **replacement third value**, replacing the current third input.

A call receives the computed word read’s value logically shifted right by 22 and then left by 28, retaining 32 bits. Only original bits 22–25 can survive, in output bits 28–31.

A four-call acquisition supplies the **zero-word index**. Zero is stored as a word at \(p(\text{zero-word index})\). A call receives \(T_4(\text{zero-word index})\), followed by a four-call acquisition of the **selector payload**.

A fresh selector operation from the clear base writes \(b(L_2(\text{selector payload}))\). A call then receives \(L_2(\text{selector payload})\); a no-explicit-argument call produces a word; and another call receives that word followed by \(L_{30}(\text{selector payload})\).

A four-call acquisition supplies the **saved-selector result**. A fresh byte read at clear base plus 1 supplies the **saved selector**. A byte store at saved selector plus \(\mathrm{0x11}\) writes \(b(h(\text{selector payload}))\).

Only after this byte store does a call receive \(L_2(\text{saved-selector result})\). A four-call gap follows. A word store then writes \(L_2(\text{replacement third value})\) at saved selector plus \(\mathrm{0x14}\).

This word store reuses the saved selector. Intervening changes to the original selector-source byte do not change its address.

### 6. Global capture and final clear-base reset

Immediately after the saved-selector word store, the function reads the global word location and retains a **global sample**.

A call receives \(T_4(\text{fifth value index})\). A four-call acquisition returns a 64-bit pair. The **tail index** is that pair’s low word shifted left by two.

A fresh selector operation from the clear base writes \(b(\text{global sample}\gg22)\), using logical right shift. The global is not reread for this byte value, even if intervening dependencies modify it.

A call receives the pair’s high word. A no-explicit-argument call produces a word, and the next call receives that word followed by \(L_{28}(\text{tail index})\).

A four-call acquisition supplies the **tail reset result**. A fresh selector operation from the clear base writes zero before a call receives \(L_2(\text{tail reset result})\). A four-call acquisition then supplies the **duplicated-argument result**.

### 7. Tail propagation and iteration transition

A call receives two copies of \(L_2(\text{duplicated-argument result})\). A four-call acquisition supplies the **tail value index**.

The **tail word value** is \(L_2(\text{tail value index})\). It is stored at \(T_{4096}(\text{tail index})+\mathrm{0x14}\). A call receives \(L_{14}(\text{tail index})\), followed by a four-call acquisition of the **tail mirror index**.

The same tail word value is stored at \(p(\text{tail mirror index})\). A call receives \(T_4(\text{tail mirror index})\), followed by a four-call acquisition of another 64-bit pair. The next fourth input becomes this pair’s low word shifted left by two.

Before forwarding the high word, the function performs its last explicit memory accesses of the iteration: a selector operation from \(T_{16384}(\text{tail index})\) writes \(b(h(\text{tail word value}))\).

A call receives the pair’s high word. The ambient dispatch value is then assigned the fixed anchor \(\mathrm{0x0882ced1}\), before the final no-explicit-argument call. That final call supplies the next first input.

At the back edge:

- The third input retains its replacement value.
- The fourth input retains its newly scaled low word.
- The ambient selector-source address becomes \(L_{28}(\text{next fourth input})\).
- The ambient byte becomes zero.
- The ambient dispatch value is the fixed anchor.

The next opening target is therefore represented as \(\mathrm{0x0882decf}\). Only the first iteration uses the unknown initial dispatch value.

## Acceptance examples

These are conditional static expectations, not executed tests.

1. **Per-iteration access counts.** If a complete iteration executes, and dependency-internal accesses are excluded, it contains ten selector-byte reads and fourteen byte stores. Four stores are direct clears; ten are selector-mediated.

2. **Fresh and saved selectors.** A selector value of \(\mathrm{0x80}\) produces byte destination \(\mathrm{0x91}\). A saved selector of \(\mathrm{0x20}\) produces the later word destination \(\mathrm{0x34}\), even if calls subsequently change its original source byte.

3. **Reset ordering.** If the first reset result is 3, the associated zero-byte store precedes the call receiving 12. Four further calls precede the first word store.

4. **Saved-selector ordering and truncation.** A saved-selector result of \(\mathrm{0x40000001}\) produces argument 4. Its consumer follows the saved-selector byte store; four calls then precede the saved-selector word store.

5. **First word propagation.** A primary index of 1 produces word \(\mathrm{0x4000}\), initially stored at \(\mathrm{0x4014}\). Its later left shift by 28 produces zero.

6. **Direct clears.** A fourth value index with low two bits equal to 3 produces clear base \(\mathrm{0xc0000000}\). Each clear pair writes first at \(\mathrm{0xc0000011}\), then at \(\mathrm{0xc0000001}\), without selector reads.

7. **Unaligned lookup.** A lookup selector value of \(\mathrm{0x00100000}\) produces word-read address \(\mathrm{0x15}\). Continuation requires the environment to permit that access.

8. **Captured global value.** If the global sample is \(\mathrm{0x00400000}\), its associated byte value is 1, even if a subsequent dependency changes the global before the store.

9. **Iteration transition.** If execution reaches the back edge normally, the next opening target is represented as \(\mathrm{0x0882decf}\). Successful accesses and returning dependencies cause repetition, not a success return.
