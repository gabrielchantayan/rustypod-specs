# F-9b6800b2a329

## Purpose

F-9b6800b2a329 updates shared allocation-like state from a caller-supplied record. It normalizes a record count, scans a bounded sequence of classification bytes, and conditionally writes two fixed 32-bit words followed by a variable number of table entries.

The established behavior is numerical and stateful. Interpreting the words as resource allocations, the low portions as starting positions, and the high portions as lengths is inferred intent, not an established external interface. In particular, the packing operations use addition rather than independently masked fields.

The function has no explicit return value. Its observable results are record mutation, shared-word writes, optional table writes, and an optional call to F-870c4fcf7295.

## Interface

### Input record

The sole argument identifies a writable, byte-addressed record. The following offsets are relative to its start:

| Offset | Width | Established use |
|---|---:|---|
| `0x05` onward | 8 bits per entry | Classification bytes scanned according to the normalized count |
| `0x17` | 8 bits | Enable flag; zero stops processing after the scan |
| `0x1A` | 8 bits, unsigned | Count; values above 8 are replaced with 8 |
| `0x20` | 16 bits, unsigned | Quantity from which the selected base is subtracted |
| `0x2B` | 8 bits | Mode flag, read at two separate stages |
| `0x31` | 8 bits, unsigned | Multiplier contributing four units per value to the base |
| `0x35` | 8 bits, unsigned | Replacement participant count when the later mode read is zero |

No null-pointer, bounds, alignment, or accessibility checks are shown. The caller must provide valid storage for the accesses actually reached. A full record covering every listed field extends through byte offset `0x35`, but early-return paths do not access every field.

The scan reads exactly the classification bytes for indices beginning at 1 and strictly below the normalized count. Consequently, its first byte is at offset `0x05`, and its maximum extent is through offset `0x0B`.

### Shared state

The following specification labels identify distinct roles without assigning semantic names not established by the evidence:

- **Base word:** a readable and writable unsigned 32-bit shared word.
- **First descriptor word:** a readable and writable 32-bit shared word. Its incoming low 16 bits constrain the first allocation.
- **Second descriptor word:** a readable and writable 32-bit shared word. Its incoming low 16 bits constrain the second allocation and all later table allocations.
- **Table reference:** shared state from which the table destination is obtained after the dependency call.
- **Descriptor table:** storage receiving 32-bit words at four-byte strides.

These labels do not establish non-aliasing, ownership, atomicity, or synchronization guarantees.

### Integer interpretation

Record bytes used as counts and multipliers are unsigned. The quantity at offset `0x20` is an unsigned 16-bit value. Shared-word arithmetic, remaining quantities, dependency arguments, and packed-word calculations use unsigned 32-bit values.

Unsigned subtraction and multiplication therefore retain their low 32 bits. In particular, subtracting a base larger than the 16-bit quantity wraps; it does not produce a checked error or a saturated zero.

Multibyte accesses follow the target’s native memory representation. The supplied evidence does not independently establish byte order or alignment requirements.

## Behavior

### 1. Normalize the count and scan classifications

The count at offset `0x1A` is inspected before any enable-flag check.

- Values from 0 through 8 remain unchanged.
- Values from 9 through 255 cause an 8-bit write of 8 to that field.

The comparison uses the byte value plus one after promotion. Thus, 255 is normalized to 8 rather than wrapping to zero during this check.

Two accumulators begin at zero:

- An **advance count**.
- A **participant count**.

For each scanned classification byte:

| Classification value | Advance count change | Participant count change |
|---|---:|---:|
| 0 | +1 | +1 |
| 1 | No change | +1 |
| 2 | +1 | No change |
| Any other value | No change | No change |

With stable record contents, a normalized count of 0 or 1 scans no entries. A count of 8 scans seven entries. Each accumulator is therefore at most seven.

The count field is consulted again for successive loop decisions; the supplied representation does not establish a single immutable snapshot of that field.

After scanning, the function reads the enable byte at offset `0x17`. If it is zero, the function returns. Count normalization may already have modified the record, but none of the descriptor-processing steps below occur.

### 2. Select and publish the base

For enabled processing, the candidate base is:

- 272;
- plus four times the unsigned byte at offset `0x31`;
- plus twice the advance count.

For stable input, this candidate lies between 272 and 1306 inclusive.

The selected base is the lesser of the candidate and the incoming unsigned Base word. The function writes the selected base back to the Base word, including when it equals the incoming value.

Next, the function reads the unsigned 16-bit quantity at offset `0x20` and subtracts the selected base using unsigned 32-bit arithmetic. This establishes the initial remaining quantity.

The Base word write precedes the quantity read. If the record aliases shared state, that ordering can affect the observed quantity.

### 3. Write the first descriptor

The function reads the mode byte at offset `0x2B`.

- Zero selects a nominal first-allocation limit of 256.
- Any nonzero value selects a nominal limit of 32.

The actual first allocation is the minimum of:

1. That nominal limit.
2. The incoming low 16 bits of the First descriptor word.
3. The current unsigned remaining quantity.

The First descriptor word is then overwritten with the low 32 bits of:

**selected base + first allocation × 65,536**

The remaining quantity decreases by the first allocation.

The previous upper 16 bits of the First descriptor word do not constrain this operation.

### 4. Write the second descriptor

After writing the First descriptor word, the function reads and caches the low 16 bits of the Second descriptor word. Call this cached value the **table cap**.

The second allocation is the minimum of:

1. 512.
2. The table cap.
3. The unsigned remaining quantity after the first allocation.

The Second descriptor word is overwritten with the low 32 bits of:

**selected base + first allocation + second allocation × 65,536**

A running position is established as:

**selected base + first allocation + second allocation**

The remaining quantity decreases by the second allocation.

The table cap remains the value captured before this overwrite. The function does not use the newly written Second descriptor word as a replacement cap.

### 5. Determine whether table distribution occurs

The mode byte at offset `0x2B` is read again, after both descriptor writes.

- If this later read is zero, the participant count is replaced with the unsigned byte at offset `0x35`.
- If this later read is nonzero, the participant count remains the count accumulated during classification scanning.

The two mode reads are distinct. A contract consumer must not assume they necessarily return the same value when aliasing or external mutation is possible.

If the resulting participant count is less than two, the function returns. The Base word and both fixed descriptor writes have already occurred.

### 6. Obtain a proposed allocation and write table entries

For a participant count of at least two, F-870c4fcf7295 is called once with two unsigned 32-bit arguments, in this order:

1. The remaining quantity after the first two allocations.
2. The participant count minus one.

The second argument is nonzero and lies between 1 and 254.

The function consumes a 32-bit result from this dependency. Its meaning is not established by the supplied evidence. A quotient-like interpretation is plausible but is not part of the unconditional contract.

After the call returns, the function obtains the Table reference. It caps the dependency result at the previously cached table cap, producing a proposed allocation for non-final entries.

The function then writes table entries with indices 2 through the participant count, inclusive, in increasing order. Each entry occupies four bytes. The destination for index 2 is therefore eight bytes beyond the table base.

For each non-final entry:

- The allocation is the capped dependency result.
- The written word is the low 32 bits of the running position plus the allocation multiplied by 65,536.
- The running position increases by that allocation.
- The remaining quantity decreases by that allocation using unsigned 32-bit arithmetic.

The non-final allocation is **not** additionally limited to the current remaining quantity. A sufficiently large dependency result can therefore cause remaining-quantity underflow.

For the final entry, the proposed allocation is replaced by the minimum of the current unsigned remaining quantity and the cached table cap. The same write and state-update rules then apply.

The function does not report any quantity left undistributed after the final entry. Table writes still occur when their allocations are zero.

### Packing is addition, not independent field replacement

Every descriptor word is constructed by adding a starting position to an allocation multiplied by 65,536. No mask is applied to the starting position before addition.

When the starting position fits within 16 bits, the result has the familiar interpretation of a low-half starting position and a high-half allocation. Once the running position exceeds 65,535, its upper bits also contribute to the resulting high half.

The contract therefore does not promise independently recoverable 16-bit position and length fields for every possible execution.

## Side effects

The function can perform the following direct effects, in order:

1. Normalize the count byte to 8.
2. Read classification bytes and the enable flag.
3. Write the Base word.
4. Write the First descriptor word.
5. Write the Second descriptor word.
6. Call F-870c4fcf7295, if the resulting participant count is at least two.
7. Read the Table reference.
8. Write ascending table entries from index 2 through the participant count.

Record-field reads and shared-state reads are interleaved with those writes as described in Behavior.

The supplied representation conditionally refers to the Base word again when the incoming base wins the minimum, and similarly refers to the First descriptor word again when its low half supplies the tighter limit. Exact machine-load counts, atomic access guarantees, and behavior under concurrent mutation are not established.

No explicit allocation, release, ownership transfer, rollback, or error-reporting operation is shown. This does not constrain effects performed internally by F-870c4fcf7295.

There is no explicit recovery path for inaccessible memory or invalid table storage. A fault or abnormal dependency exit can leave earlier writes in place.

## Dependencies

**Established interface at this call site:**

- Called only when the participant count is at least two.
- Receives the remaining quantity and participant count minus one as unsigned 32-bit quantities.
- Supplies a 32-bit result used to propose non-final table allocations.
- Executes after both fixed descriptor writes and before the Table reference is read.

**Not established:**

- Its arithmetic rule.
- Whether it can fail or terminate abnormally.
- Whether it modifies shared state.
- Whether it allocates, owns, transfers, or releases memory.

The table cap used after the call is the value cached before the call. The destination reference is obtained afterward. Thus, a dependency-side change to the Second descriptor word does not refresh the cached cap, whereas a change to the Table reference can affect the subsequent destination.

## Acceptance examples

These are conditional predictions from static evidence, not executed tests. Except where stated otherwise, they assume stable, non-aliasing record and shared storage, valid memory, and normal dependency return.

### Disabled processing still normalizes the count

Given a count of 255 and an enable byte of zero:

- The count becomes 8.
- Seven classification bytes are scanned.
- No direct Base word, fixed-descriptor, or table writes occur.
- F-870c4fcf7295 is not called.

Given a count of 0 instead, no classifications are scanned and no normalization write occurs.

### Classification effects are independent

Given a count of 4 and classification bytes 0, 1, and 2 at offsets `0x05` through `0x07`:

- The advance count is 2.
- The participant count is 2.

With enabled processing and a zero multiplier byte, the candidate base is 276. A smaller incoming Base word still lowers the selected base.

### Conditional equal-share result

Assume:

- The preceding classification example.
- Enabled processing.
- Both mode reads return zero.
- The multiplier byte is zero.
- The incoming Base word is at least 276.
- The 16-bit quantity is 2000.
- The First descriptor word has a low half of at least 256.
- The Second descriptor word has a low half of 512.
- The replacement participant count is 4.
- F-870c4fcf7295 returns 318.

Then:

- The selected base is 276.
- The first allocation is 256, beginning at 276.
- The second allocation is 512, beginning at 532.
- The dependency receives 956 and 3.
- Table index 2 receives an allocation of 318 beginning at 1044.
- Table index 3 receives an allocation of 318 beginning at 1362.
- Table index 4 receives an allocation of 320 beginning at 1680.

This example conditions on the dependency result; it does not establish that the dependency computes division.

### Unsigned underflow is not rejected

Given a selected base of 272 and a 16-bit quantity of 100, the initial remaining quantity is 4,294,967,124.

If the first mode read is zero and the First descriptor word permits 256, the first allocation is 256, not zero. The function does not reject the quantity for being below the selected base.

### Non-final allocation can exceed the remainder

Assume table distribution begins with:

- A remaining quantity of 10.
- A participant count of 3.
- A cached table cap of 100.
- A dependency result of 50.

Index 2 receives allocation 50, leaving an unsigned remaining quantity of 4,294,967,256. The final index 3 then receives allocation 100. The function does not constrain the first of these entries to the original remainder of 10.

### A small participant count does not suppress earlier writes

If the later mode read is zero and the replacement participant count is 1, the function returns after updating the Base word and both fixed descriptors. It neither calls the dependency nor writes table entries.
