# F-9947a2c8a627

## Purpose

F-9947a2c8a627 scans 32-bit words through an address held in a two-field mutable state record. It replaces the record’s second field with each inspected word. When an inspected word is zero, it advances the address in the record’s first field by four bytes and inspects the word at that updated address. It stops on the first nonzero inspected word.

After the scan stops, it writes the state record’s two entry values to a separate output record. The output therefore receives the saved entry state, not the final scan state or the nonzero word that stopped the scan.

This is a description of the visible operations, not an assertion of the data structure’s intended meaning. In particular, the initial inspection address comes from the second state field, whereas later inspection addresses come from advances of the first field. The supplied evidence does not establish why those two address sources differ.

## Interface

### Arguments and result

The function takes two pointer arguments, in this order:

1. **Output record:** storage receiving two saved integer values after successful scan termination.
2. **Mutable state record:** storage supplying the initial values and receiving scan updates.

There is no explicit return value and no status result.

### Record layout and widths

Both arguments are presented as pointers to integers. The recovered representation uses a 32-bit integer and address model:

| Byte offset | Output record | Mutable state record |
|---|---|---|
| 0 | Receives the saved first state field | Address-like scan cursor |
| 4 | Receives the saved second state field | Initial inspection address, then most recently inspected word |

Each record consequently requires two adjacent 32-bit fields in this model. A scan inspection reads one 32-bit word.

The four-byte advancement is explicit. It is an address advance of four bytes, not an addition of four to a pointer measured in integer elements.

The original target ABI, alignment requirements, and integer-to-pointer conversion rules are not independently supplied. Applying this contract to a different integer or pointer model requires additional evidence.

### Preconditions for ordinary completion

For a successful, fault-free invocation:

- Both state fields must initially be readable.
- The state’s second field must be writable for every scan iteration.
- Whenever an inspected word is zero, the state’s first field must be readable and writable.
- Every address actually inspected must support a 32-bit read.
- The two output fields must be writable when the final stores occur.
- The scan must eventually inspect a nonzero word.
- Address advancement and integer-to-address conversion must remain meaningful for the target execution environment.

The function performs no visible checks enforcing these conditions.

The output is not accessed until the scan terminates. Consequently, an unusable output address need not affect an invocation that never reaches its final stores.

## Behavior

### Entry observations

Before inspecting any candidate word, the function performs these state reads in order:

1. Reads and saves the first state field.
2. Reads and saves the second state field.
3. Reads the second state field again, using this observation as the initial inspection address.

The two reads of the second field are distinct in the supplied representation. With ordinary stable memory, they yield the same value. If another actor or unusual memory behavior changes that field between reads, the saved output value and initial inspection address can differ. The evidence supplies no synchronization or concurrent-access guarantees.

Once captured, the two saved values are not refreshed during the scan.

### Inspection and state updates

At each inspection, the function first reads a 32-bit word from the current inspection address. It then writes that word to the state record’s second field.

Only after that store does it decide whether to continue:

- A nonzero inspected word terminates the scan.
- A zero inspected word causes another address to be selected.

Thus even the terminating nonzero word is written to the state before the output record is written.

Zero is the only continuation value. Negative values, values with their top bit set, and values that would be unusable as addresses all terminate the scan if they are nonzero. An inspected nonzero word is not dereferenced.

### Address selection after a zero

After writing zero to the second state field, the function:

- Reads the state record’s first field at that time.
- Forms an address four bytes beyond that field’s address value.
- Writes the advanced address back to the first state field.
- Uses that same advanced address for the next inspection.

The first state field is therefore a live source of scan progression, not merely an entry value cached for all later iterations. The initial saved copy serves the eventual output; it does not supply every subsequent advance.

Absent interference or unusual aliasing, if the entry first field denotes an address called the cursor base, then the inspection sequence is:

- The address taken from the second entry-field read.
- Cursor base plus 4 bytes, if the first inspection was zero.
- Cursor base plus 8 bytes, if the second inspection was also zero.
- Further four-byte advances until a nonzero word is found.

The address initially supplied by the second field is not automatically incremented. For example, if the cursor base is 0x1000 and the initial inspection address is 0x2000, a zero at 0x2000 causes the next inspection at 0x1004, not 0x2004.

### Completion and output

After the first nonzero inspection, the function performs two output stores:

1. Writes the saved entry first field to output offset 0.
2. Writes the saved entry second field to output offset 4.

It then returns.

For disjoint ordinary records, the resulting state is:

- The first state field contains the last advanced cursor, or its entry value if the first inspection was nonzero.
- The second state field contains the terminating nonzero word.
- The output contains the two saved entry fields.

There is no additional output containing the terminating inspection address. Its relationship to the first state field depends on whether any zero inspection occurred.

## Side effects

### Mutation and ordering

The function can write to three logical destinations:

- The state’s second field, once per successful inspection.
- The state’s first field, once per zero inspection.
- The output’s two fields, after scan termination.

For a zero inspection, the write of zero to the second state field precedes the read and advancement of the first state field. For a nonzero inspection, the write to the second state field precedes both output stores.

No rollback is visible. A fault after an earlier successful store can leave partial mutations.

### Aliasing

No disjointness requirement or alias check appears in the evidence. Overlap must therefore be interpreted using the actual read and write order, rather than by assuming independent records.

If the output and state arguments identify the same two-field record, the scan still performs its state updates. After termination, however, the two output stores restore the saved entry values to that record. The final record then contains its entry values rather than the terminating scan state.

Partial overlap can produce other results. For example, if output offset 0 is the same location as state offset 4, the first final store replaces the terminating nonzero state value with the saved first field. The second output store then writes at the following field-sized location.

Inspection memory may also overlap state or output storage. In such cases:

- An inspection reads the word before that iteration’s state stores.
- A write to the state can change memory that a later inspection will read.
- A final output write occurs too late to affect an already completed scan, but can overwrite its visible results.

The ordinary linear-scan interpretation is therefore conditional on memory relationships that do not alter the progression.

## Acceptance examples

These are conditional behavioral examples derived from static evidence. They are not runtime test results. Unless stated otherwise, they assume stable ordinary memory, the 32-bit representation described above, disjoint output and state records, and valid accesses.

### Immediate nonzero inspection

Given:

- Entry first state field: 0x1000.
- Entry second state field: 0x2000.
- Word at 0x2000: 7.

Expected behavior:

- Inspect 0x2000 once.
- Write 7 to the second state field.
- Do not advance or write the first state field.
- Write 0x1000 and 0x2000 to the output, in that order.
- Return with state fields 0x1000 and 7.

### Zero followed by a nonzero word

Given:

- Entry first state field: 0x1000.
- Entry second state field: 0x2000.
- Word at 0x2000: zero.
- Word at 0x1004: 9.

Expected behavior:

- Write zero to the second state field after inspecting 0x2000.
- Advance the first state field to 0x1004.
- Inspect 0x1004 and write 9 to the second state field.
- Return output fields 0x1000 and 0x2000.
- Leave state fields 0x1004 and 9.

No inspection at 0x2004 is implied.

### Multiple zero inspections

Given zero words at the initial inspection address, cursor base plus 4, and cursor base plus 8, followed by a nonzero word at cursor base plus 12:

- There are four inspections.
- There are four writes to the second state field.
- There are three writes advancing the first state field.
- The final first state field denotes cursor base plus 12.
- The output still contains the two entry values.

### High-bit-set terminating word

Given an initially inspected word with bit pattern 0xFFFFFFFF:

- The scan terminates after that inspection.
- The bit pattern is stored in the second state field.
- That word is not treated as another address.
- The output receives the saved entry values.

### Identical output and state records

Given that both arguments identify the same record and the scan reaches a nonzero word:

- Scan mutations occur as usual.
- The final stores overwrite both fields with their saved entry values.
- The record’s final contents equal its entry contents.

This does not imply that the intermediate writes were absent.

### Fault after a zero inspection

Given a valid initial inspection yielding zero, followed by an invalid advanced inspection address:

- The second state field has already been written with zero.
- The first state field has already been written with the advanced address before the failing read.
- The final output stores have not been reached.

The mechanism and observability of the fault remain target-dependent.
