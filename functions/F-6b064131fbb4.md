# F-6b064131fbb4

## Purpose

F-6b064131fbb4 translates a requested mode and selected bits of an object’s flag word into two dependency arguments. It invokes two dependencies in a fixed order, stores the low byte of the requested mode in the object, and then performs an indirect callback using the original, full-width mode.

The mode is not validated against a closed set. Modes outside the recognized set still cause both dependency calls, the byte-sized state update, and the indirect callback. Their two derived dependency arguments are both zero.

This contract describes the supplied static representation. No runtime tests have been performed. Names such as “mode,” “flags,” and “handle” describe operational roles, not independently established domain semantics.

## Interface

### Inputs

The function receives:

- **Object reference:** a pointer to readable and writable object storage with the layout described below.
- **Requested mode:** a 32-bit integer. Recognition uses exact integer comparisons against 1, 2, 3, 4, and 11. The mode is not narrowed before these comparisons.

The represented function has no explicit return value.

### Relevant object layout

Under the 32-bit layout represented by the supplied source, the function accesses:

| Byte offset from object base | Width | Role |
|---|---:|---|
| 0x00 | 32 bits | Reference to a dispatch table |
| 0x44 | 32 bits | Value passed as the first argument to each of the two direct dependencies |
| 0x48 | 32 bits | Flag word used to derive dependency arguments |
| 0x54 | 8 bits | Stored low byte of the requested mode |

The indirect callback target is obtained from the dispatch table at byte offset 0x14. Under the represented 32-bit pointer layout, this is the sixth pointer-sized entry.

The function does not establish the overall object size, the identities of other fields, or the contents of other dispatch entries. It requires access to the stated fields and to a callable dispatch entry.

### Outputs and derived values

The function computes two values before invoking either direct dependency:

- **First derived value:** a 32-bit unsigned bitmask. Its possible values are 0, 1, 64, and 65, with a narrower set possible for some modes.
- **Second derived value:** an 8-bit quantity whose possible values are 0, 1, and 2.

The ABI-level representation of the second dependency’s argument is not independently established by the supplied representation. Its meaningful numeric value is limited to those three values.

The object’s byte at offset 0x54 receives the low eight bits of the requested mode. The indirect callback receives the original 32-bit requested mode, not the stored byte.

## Behavior

### Flag interpretation

The function uses these parts of the 32-bit flag word:

| Mask | Effect |
|---|---|
| 0x00000002 | Selects second derived value 1 for modes 1, 2, 4, and 11 |
| 0x00000004 | Selects second derived value 2 for mode 3 |
| 0x00030000 | Selects bit 0 of the first derived value for modes 2, 3, and 11 |
| 0x00400000 | Selects bit 6 of the first derived value for modes 2, 3, and 4 |

For the 0x00030000 mask, either constituent bit is sufficient. The test is whether the masked unsigned value exceeds 0x0000FFFF. Its possible masked values are 0, 0x00010000, 0x00020000, and 0x00030000, so every nonzero result satisfies the test. It does not require both bits to be set.

All other flag bits are irrelevant to the function’s own derived values.

### Mode-dependent results

For a flag word that remains unchanged during the function’s reads, the results are:

| Requested mode | First derived value | Second derived value |
|---:|---|---|
| 1 | 0 | 1 if mask 0x00000002 is set; otherwise 0 |
| 2 | Bit 0 if mask 0x00030000 is nonzero, combined with bit 6 if mask 0x00400000 is set | 1 if mask 0x00000002 is set; otherwise 0 |
| 3 | Bit 0 if mask 0x00030000 is nonzero, combined with bit 6 if mask 0x00400000 is set | 2 if mask 0x00000004 is set; otherwise 0 |
| 4 | 64 if mask 0x00400000 is set; otherwise 0 | 1 if mask 0x00000002 is set; otherwise 0 |
| 11 | 1 if mask 0x00030000 is nonzero; otherwise 0 | 1 if mask 0x00000002 is set; otherwise 0 |
| Every other integer | 0 | 0 |

The two contributions to the first derived value are combined with bitwise OR. There is no counter increment, arithmetic overflow, or carry-dependent behavior.

Mode 3 uses the 0x00000004 flag for the second value and ignores 0x00000002 for that purpose. Mode 11 does not use 0x00400000, even when that bit is set. Mode 4 does not use 0x00030000.

### Read and operation order

The supplied representation establishes this sequence:

1. Both derived values initially have value zero.
2. Mode-specific flag reads determine their final values.
3. The value at object offset 0x44 is read and passed with the first derived value to F-17e0ae5d408a.
4. After that call returns, offset 0x44 is read again and passed with the second derived value to F-5b039b1f816e.
5. After the second call returns, the low byte of the requested mode is written at offset 0x54.
6. The function performs the indirect dispatch using the object, an external argument value, and the original requested mode.
7. Following normal completion of that dispatch, the function returns without an explicit result.

The mode-specific flag reads appear in this order:

| Mode | Ordered flag tests |
|---:|---|
| 1 | 0x00000002 |
| 2 | 0x00000002, then 0x00030000, then 0x00400000 |
| 3 | 0x00000004, then 0x00030000, then 0x00400000 |
| 4 | 0x00000002, then 0x00400000 |

This is not a guaranteed atomic snapshot of the flag word. The representation contains separate field reads. If the field changes between reads, the derived values may reflect different observed states. Concurrent-access legality, synchronization, and machine-level load behavior are not established.

Both derived values are finalized before the first direct dependency call. Changes to the flag word made by either dependency do not cause these values to be recomputed.

By contrast, the value at offset 0x44 is deliberately described as two reads, not one cached value. If F-17e0ae5d408a changes that field, F-5b039b1f816e receives the value subsequently read.

### Stored mode and callback mode

The write at offset 0x54 is exactly one byte. The function itself does not write the other bytes of the surrounding word.

This creates two distinct mode representations:

- Object state stores the requested mode modulo 256 as a byte pattern.
- The callback receives the full original 32-bit mode.

For example, mode 257 is unrecognized during derivation, produces two zero derived values, stores byte 0x01, and is forwarded as 257. It is not treated as mode 1.

The callback is selected after both direct dependencies and after the byte write. The source does not establish that the dispatch table or external argument remains unchanged across dependency calls. It also does not establish a relative evaluation order among the callback’s target lookup and its argument reads beyond their placement after the preceding operations.

## Side effects

The function’s directly visible effects are:

- One invocation of F-17e0ae5d408a.
- One subsequent invocation of F-5b039b1f816e.
- One byte write to the object at offset 0x54.
- One subsequent indirect callback invocation.

These occur on every normal path, including unrecognized modes. An unrecognized mode is not an early-return condition.

The function contains no explicit allocation, deallocation, reference-count operation, or ownership-transfer operation. That does not establish the ownership behavior of any callee. The handle-like field and object reference are passed onward without a visible ownership annotation.

The direct byte write occurs after both direct dependencies, so neither is called with a guarantee that this function has already stored the new mode. Either dependency may independently modify the same byte; the later direct write would overwrite that modification if execution continues normally.

The callback begins after the byte write, but it may modify that byte again. Consequently, the function does not guarantee that offset 0x54 still contains the requested mode’s low byte when the entire call returns.

Dependency effects on object fields, global state, memory lifetime, I/O, or external resources are unknown. There is no visible rollback if a dependency fails to return normally.
