# F-3d8176ebd891

## Purpose

F-3d8176ebd891 conditionally performs an operation involving two acquired objects. A 16-bit discriminator in its second input enables the operation only when its value is 4.

Enabled execution obtains an operation value, acquires two object pointers, and queries whether preparation is required. Preparation may invoke resource operations and update global state. A final indirect operation determines the normal return status, after which a dependency receives the address of the stored resource reference.

The established normal returns are:

- **4:** the discriminator does not enable execution.
- **2:** enabled execution reaches a final operation that returns zero, followed by normal completion of finalization.
- **0:** enabled execution reaches a final operation that returns nonzero, followed by normal completion of finalization.

“Manager,” “resource,” “preparation,” and “finalization” name structural roles only. They do not establish application semantics, ownership, or dependency internals.

## Interface

### Inputs and accessible layouts

The supplied representation has two address-valued inputs in a 32-bit address model.

| Input | Access | Condition |
|---|---|---|
| First input | One byte at byte offset `0x2EC` | Only when enabled execution reaches preparation |
| Second input | A 16-bit discriminator at byte offset `0x0C` | Always |
| Second input | A 32-bit operation field at byte offset `0x08` | Only when the discriminator equals 4 |

The discriminator is represented as a signed 16-bit read. Its only comparison is equality with 4, so signedness does not affect the enabling bit pattern.

The first-input byte is also compared only for equality with 1. The comparison is not a general truth test: byte values 0, 2, and 255 all select the branch for values other than 1.

The operation field is passed by value to F-c25a2fcc75b5. Whether it denotes an integer, handle, address, or another word-sized value is unknown.

### Output

The function returns a 32-bit status on normal completion. The intermediate result supplied by F-c25a2fcc75b5 is retained for the final indirect operation; it is not directly returned.

Resource acquisition returning null leads to F-a817d8d58c10, which the supplied representation marks as non-returning. No ordinary error return is established for that path.

### Objects and temporary storage

Each acquired object is used through a dispatch-table pointer in its first word. The representation is consistent with 32-bit pointers, 32-bit object words, and four-byte dispatch entries. Dispatch offsets below are byte offsets, not entry indices.

The function provides a 16-byte temporary region to two resource operations. It does not explicitly initialize that region before the first operation or directly inspect its contents afterward. The region’s format, required initialization, alignment beyond the supplied frame, and ownership obligations are not established.

A separate local slot stores the resource pointer. Finalization receives the address of that slot rather than the resource pointer by value.

### Preconditions for ordinary completion

Every reached memory access must be valid, and each reached indirect target must support the presented call form. In particular:

- The second input must support the discriminator read even when execution is disabled.
- The manager must support dispatch access after successful resource acquisition; there is no explicit null-manager check.
- The first input need support its byte read only if preparation reaches that read.
- Each global-derived address used for a store must support that store.
- Dependencies on the ordinary completion path must return normally.

The function provides no explicit validation or recovery for violations of these conditions.

## Behavior

### 1. Apply the discriminator gate

The function initially selects status 4 and reads the second input’s 16-bit discriminator at offset `0x0C`.

If the discriminator is not 4, it returns 4 without invoking any dependency. This path does not explicitly read the first input, read the operation field, acquire objects, inspect dispatch tables, access the globals described below, or finalize a resource.

This early return does not make an invalid second-input address acceptable: the discriminator read still occurs.

### 2. Obtain the operation value and acquire objects

When the discriminator equals 4, the function proceeds in this order:

1. Reads the 32-bit field at second-input offset `0x08` and passes it to F-c25a2fcc75b5.
2. Retains that dependency’s 32-bit result for the final operation.
3. Calls F-b7af80e829ec without explicit arguments to obtain the manager pointer.
4. Calls F-be45cd43f92d with numeric argument 0 to obtain the resource pointer.
5. Checks the resource pointer against null.

A null resource causes a call to F-a817d8d58c10. The supplied non-returning annotation leaves no established normal continuation, finalization, or return status for that case. If the annotation is incorrect, the evidence does not supply a valid recovery contract.

The manager pointer is not checked for null before its later use.

### 3. Query whether preparation is required

The function invokes the manager’s indirect dependency at dispatch-table offset `0x108`, passing the manager pointer as its sole explicit argument.

- A zero result selects preparation.
- Any nonzero result skips preparation and proceeds directly to the final operation.

This query does not itself determine the returned status. Its nonzero result is not treated as an error return.

The function also retains the resource pointer for use by the second temporary-region operation described next. No stability or ownership guarantee follows from retaining that pointer.

### 4. Perform conditional preparation

#### Temporary-region operations

When the query returns zero, the function invokes the resource’s indirect dependency at offset `0x1B8` with these explicit arguments, in order:

1. Address of the 16-byte temporary region.
2. Resource pointer.
3. Numeric zero.

It then invokes the resource’s indirect dependency at offset `0x3C` with:

1. The retained resource pointer.
2. Address of the same temporary region.

No explicit initialization of the region precedes the first call. Whether the first dependency produces all data required by the second is part of their unresolved contracts.

After these calls, the function reads the byte at first-input offset `0x2EC`. Branch selection therefore uses the value observed at this later read, not an entry-time snapshot. Earlier dependencies are not assumed to preserve the input object.

#### Mode byte equal to 1

If the byte equals 1, the function invokes the resource’s indirect dependency at offset `0x5C` with:

1. Resource pointer.
2. A value read from a global location.

The meaning and ownership of that global value are unknown.

This branch performs neither of the explicit global-state stores described below and does not invoke the manager operation at offset `0x30`.

#### Mode byte other than 1

For every other byte value, the function invokes the resource’s indirect dependency at offset `0x5C` with:

1. Resource pointer.
2. Numeric zero.
3. Numeric zero.

The evidence presents different explicit argument counts for the two calls at offset `0x5C`. This contract preserves that difference; it does not infer a single normalized signature.

After that resource call returns, the global-state sequence is:

1. Read a pointer-valued global location and retain the resulting pointer.
2. Read that same global location again.
3. Use the pointer from the **second read** to address a 32-bit store of `0xFFFFFFFF` at byte offset `0x1C`.
4. Use the pointer retained from the **first read** to address a 32-bit store of zero at byte offset `0x20`.
5. Invoke the manager’s indirect dependency at offset `0x30`, passing the manager pointer and numeric argument 2.

Both global-pointer reads occur after the resource operation. The first read precedes the second read; the all-ones store precedes the zero store.

The two reads must not be collapsed into one snapshot. If they produce different pointers, the stores address different base objects: the all-ones store uses the later pointer, while the zero store uses the earlier pointer. No global-stability, synchronization, or concurrency contract is established that would require the two values to match.

The all-ones value is a 32-bit bit pattern. Its signed interpretation would be −1, but no arithmetic is performed on the stored value. Address offsets are byte displacements; the representation supplies no separate overflow or invalid-address handling.

### 5. Perform the final operation

After preparation, or directly after a nonzero query result, the function invokes the manager’s indirect dependency at offset `0xA4`.

Its explicit arguments, in order, are:

1. Manager pointer.
2. The retained 32-bit result from F-c25a2fcc75b5.
3. Numeric zero.
4. Numeric zero.
5. Numeric zero.

A zero result selects status 2. Any nonzero result selects status 0. Different nonzero results do not produce different statuses.

### 6. Finalize the stored resource reference

After selecting status 0 or 2, the function calls F-54033250428c with the address of its resource-pointer slot.

That dependency can potentially inspect or modify the slot. The evidence does not establish whether it releases the resource, adjusts a reference count, clears the slot, or performs another operation.

If finalization returns normally, the function returns the previously selected status. There is no explicit branch on a finalization result.

## Side effects

### Direct memory effects

The function directly reads:

- The second input’s 16-bit discriminator.
- Its 32-bit operation field on enabled execution.
- Object dispatch pointers and dispatch entries needed by reached indirect calls.
- The first input’s mode byte on the preparation path.
- The global argument value on the mode-equals-1 branch.
- The global-state pointer **twice**, in order, on the other preparation branch.

Its explicit persistent writes are the two 32-bit stores on the mode-not-equal-to-1 preparation branch:

| Write order | Address base | Byte offset | Value |
|---|---|---:|---:|
| First | Pointer obtained by the second global read | `0x1C` | `0xFFFFFFFF` |
| Second | Pointer retained from the first global read | `0x20` | `0` |

These stores need not target the same object. If their calculated addresses overlap, the later zero store occurs after the all-ones store; no non-aliasing guarantee is supplied.

The temporary region and resource-reference slot are local storage exposed to dependencies. Writes through those addresses, and any broader dependency effects, depend on contracts not supplied here.

### Ordering and state stability

The manager is retained rather than reacquired before later manager operations. Dispatch lookup occurs at the individual call sites; an immutable dispatch table is not established.

Input and global reads occur at their specified points. The function does not snapshot all state at entry. In particular, the mode byte is read after both temporary-region calls, and both global-state pointer reads occur after the resource call at offset `0x5C`.

The visible two-read sequence does not establish atomicity, memory ordering between threads, or well-defined concurrent mutation under an unspecified platform memory model.

### Ownership and abnormal completion

No explicit allocation or deallocation operation appears in the function itself. Acquisition and finalization occur through dependencies.

On ordinary enabled completion, finalization follows the final operation regardless of its zero/nonzero result. Cleanup after a dependency fails to return normally is not established.

Unknown dependencies must not be assumed to preserve globals, preserve reachable objects, or acquire or release ownership.

## Acceptance examples

These are conditional criteria from static evidence, not executed tests. Unless an example states otherwise, assume valid reached accesses, compatible indirect targets, and normal dependency completion.

1. **Disabled execution.** For any 16-bit discriminator pattern other than 4, the result is 4. No dependency is invoked, and neither the operation field nor the first-input byte is read.

2. **Preparation skipped.** With discriminator 4, a non-null resource, and a nonzero manager-query result, neither temporary-region operation occurs. The mode byte and preparation globals are not explicitly read. A zero final-operation result produces 2 after finalization; a nonzero result produces 0.

3. **Exact mode match.** With a zero query result and mode byte 1, both temporary-region operations precede the resource operation at `0x5C`. That operation receives the global value as its second explicit argument. Neither global-state store nor the manager operation at `0x30` occurs.

4. **Other mode values.** Mode byte 2 follows the same branch as mode byte 0. The resource operation receives the resource pointer and two zeros, followed by the two global-pointer reads, two stores, and manager operation with argument 2.

5. **Equal global-pointer observations.** If both global-pointer reads yield the same valid base address, the function writes `0xFFFFFFFF` at that base plus `0x1C`, then zero at that base plus `0x20`. This same-object outcome is conditional on the reads yielding equal values.

6. **Different global-pointer observations.** If the first read yields one valid base and the second yields a different valid base, the all-ones store targets the second base plus `0x1C`. The subsequent zero store targets the first base plus `0x20`. The retained first pointer is not replaced by the second observation.

7. **Late mode observation.** If a preceding dependency changes the mode byte before its explicit read, branch selection uses the later observed byte.

8. **Null resource.** A null acquisition result causes F-a817d8d58c10 to be invoked. No normal return status or finalization is established for this path.
