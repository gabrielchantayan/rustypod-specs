# F-ec4c12102158

## Purpose

F-ec4c12102158 is a configuration-driven routine that conditionally invokes two dependencies, writes a 32-bit word through its first argument, and returns a separately maintained 32-bit value.

The supplied static evidence establishes a dispatcher and its individual operations. It does not establish an application-level purpose such as parsing, conversion, validation, or resource creation. Neither the returned word nor the optional output word has an established success/error interpretation.

Configuration contents are unavailable. Consequently, the contract specifies behavior conditional on the selected operations, not a fixed call sequence. Dependency calls, output writes, and termination are not guaranteed.

## Behavior

### Working values and arithmetic

The following descriptive symbols are contract notation, not interface fields:

| Symbol | Meaning and initial state |
|---|---|
| \(M\) | Entry-captured signed 32-bit multiplier |
| \(P\) | Entry-captured signed 32-bit coefficient |
| \(N\) | Signed 32-bit value obtained by negating a separate observation of the coefficient’s global location |
| \(S\) | Unsigned 32-bit working value, initially zero |
| \(T\) | Unsigned 32-bit retained dependency argument, initially zero |

| \(W\) | Unsigned 32-bit auxiliary working word, initially zero |
| \(A\) | Unsigned 32-bit return accumulator, initially zero |
| \(X,Y\) | Distinct signed 32-bit local cells, initially zero |

Both active pointer slots initially contain null. The original arguments are saved separately.

For an unsigned 32-bit operand \(z\), define:

\[
H(z)=(Nz)\mathbin{\mathrm{OR}}(Pz).
\]

These products use unsigned 32-bit arithmetic because \(z\) is unsigned. They therefore reduce modulo \(2^{32}\), with signed coefficients converted to unsigned words. High-bit extraction is a logical right shift by 31, yielding zero or one.

This rule does **not** make all multiplication in the function unsigned:

- \(M\) times the saved third argument is a signed-int operation.
- \(M\) times either dependency’s integer result is a signed-int operation.
- In selectors 10 and 11, the initial product \(MN\) is signed; only its subsequent multiplication by an unsigned working word is unsigned.

For those signed products, the stated numeric results require representable signed intermediates. Assignment to an unsigned destination does not repair an earlier signed overflow. Exceptional signed negation, signed control arithmetic, and expressions involving globals whose declarations are absent also require the qualifications in **Uncertainties**.

### Entry and dispatch

Entry observes configuration in this order:

1. The multiplier, captured as \(M\).
2. The coefficient, captured as \(P\).
3. The coefficient again, for the negation producing \(N\).
4. The initial-state location, for forming a captured fallback state by subtracting two.
5. The initial-state location again, for the starting control state.

Separate observations need not agree. In particular, \(N=-P\) is not guaranteed, nor must the starting state and fallback derive from the same observed configuration value.

Each dispatch iteration first reads a default-successor global, then reads a dispatch-offset global. The selected operation is determined by the current signed control state plus that offset, subject to arithmetic qualifications.

Selectors 0 through 15 have explicit behavior. Every other selector performs the same result-forming operation as selector 3. The default-successor read occurs even when the selected operation does not use it, including an immediate return.

- The second observation supplies an undisplaced alternative.

| Selector | Displaced alternative | Selects undisplaced alternative when |

This differs from signed overflow during construction of an alternative or during dispatch-index arithmetic.

\[

(N\cdot Q_L\cdot Y-4)
\mathbin{\mathrm{OR}}
(P\cdot Q_R\cdot Y+4),

where \(Q_L\) and \(Q_R\) are separate reads of the same scale location, associated with the left and right arms.

The final subtraction and addition use unsigned constants, and the expression produces an unsigned 32-bit word. Those constants do not retroactively make any preceding signed products unsigned. Exact intermediate signedness depends in part on the omitted scale-global declaration.

The two scale reads need not agree. Their left/right labels do not assert temporal order: the supplied expression does not establish evaluation order between its operands.

After forming \(W\), the operation extracts its high bit, reads the undisplaced-successor observation, sets \(S=W\), and selects the successor. The displaced read therefore precedes the scale expression; the undisplaced read follows it.

No range-check or validation interpretation is established.

\[
\text{write scale}\cdot M\cdot X-\text{write bias}.

It assigns that result to unsigned \(S\), then writes \(S\) through the active first pointer. It subsequently selects the default successor already read at the start of the iteration.

The scale and bias are separate global reads within the expression. Their relative evaluation order is not established by the supplied representation. Their omitted declarations also prevent an unconditional claim that every intermediate operation wraps unsigned.

### Result formation and return

**Selector 3 and every unrecognized selector** compute:

\[
S=NW \pmod{2^{32}}.
\]

They then read a dedicated successor global and replace \(A\) with \(S\). **They do not change \(W\).**

This distinction is essential: the multiplication uses the auxiliary word, not the previous \(S\). Consecutive result-forming operations with unchanged \(W\) produce the same result rather than repeatedly multiplying the prior result.

**Selector 12** returns the current \(A\).

Therefore:

- Returning before any result-forming operation yields zero.
- An output write does not itself establish a returned status.
- Neither dependency result is returned directly.
- Result formation replaces the accumulator; it does not add to it.
- Unknown selectors are not rejected.

## Acceptance examples

These are conditional static examples, not executed tests. Each assumes the stated selectors are reached, accesses are valid, and any required signed intermediates are representable.

1. **Immediate return.** If selector 12 is selected first, the result is zero. Neither dependency is invoked and no argument pointee is directly accessed. The iteration’s default-successor and dispatch-offset reads still occur.

2. **Inactive original pointer.** If selector 1 precedes selector 5, it selects its displaced alternative even if the caller supplied a non-null first argument.

3. **Distinct successor observations.** In selector 1, suppose the first successor observation is 100 and the second is 200. A null active pointer selects 106; a non-null pointer selects 200, not 100.

4. **Constant-derived result.** Suppose a constant-loading operation puts 7 in \(W\), and \(N=3\). A subsequent result-forming operation sets \(S=A=21\), regardless of the earlier \(S\).

5. **Repeated result formation.** With the same \(N=3\) and unchanged \(W=7\), two result-forming operations leave \(A=21\), not 63. Neither operation changes \(W\).

6. **Defined zero dependency product.** If selector 9 obtains a defined signed product of zero, then \(R=W=S=0\). Its high bit is zero, so it selects the alternative formed from the first successor observation plus two.

7. **Complemented zero.** Under the corresponding defined zero-product condition in selector 14, \(W\) becomes \(2^{32}-1\). The selected state comes from the second successor observation. \(S\) remains unchanged.

8. **Output independent of return.** If selector 6 computes a defined value of 26, it writes 26. If selector 12 follows and no result-forming operation has occurred, the returned word is still zero.

9. **Unsigned final multiplication.** With \(N=-1\) and \(W=1\), result formation produces \(S=A=2^{32}-1\). Here multiplication is unsigned because \(W\) is unsigned; this does not justify treating \(M\) times a dependency’s signed return the same way.

10. **Signed-overflow boundary.** If \(M=2^{30}\) and the saved third argument is 4, selector 5 requires an overflowing signed product. This contract does not require a wrapped-zero result or a particular failure response.
