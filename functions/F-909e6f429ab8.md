# F-909e6f429ab8

## Purpose

F-909e6f429ab8 describes an ordered sequence of narrow memory writes, wider state writes, and calls to unresolved dependencies. Addresses and stored values are derived from implicit entry state and dependency results. The visible sequence ends at an invalid-instruction boundary rather than an established normal return.

No application-level purpose is established. In particular, the evidence does not establish that the writes initialize hardware, reset a device, decode data, or populate ordinary memory. Repeated writes and low numeric addresses make memory-mapped effects possible, but that interpretation remains inferred intent.

This contract distinguishes:

- **Established static evidence:** operations and ordering represented by the supplied artifact.
- **Conditional interpretation:** behavior under the apparent 32-bit address model and successful execution of all preceding operations.
- **documented_only unknowns:** facts that cannot be established from the artifact.

The artifact explicitly warns of invalid instruction data and overlapping global symbols. Consequently, this is a contract for the represented behavior, not a claim that a valid executable follows the entire sequence.

### Widths and notation

The represented data model uses:

- 16-bit narrow writes;
- 32-bit unsigned arithmetic for explicitly unsigned quantities;
- one initial 32-bit dependency result;
- thirteen subsequent 64-bit dependency results.

For a 64-bit result, **lower word** means bits 0–31 and **upper word** means bits 32–63. Passing the upper word through a signed 32-bit interpretation preserves its bit pattern; values with bit 31 set must not silently become positive mathematical integers.

The following derived quantities describe the observable interface:

- **S**: G shifted left by four bits, retaining 32 bits.
- **T**: G shifted left by eight bits, retaining 32 bits.
- **M**: G multiplied by sixteen, retaining 32 bits.
- **Q**: bits 18–27 of G, interpreted as an unsigned integer. Its range is 0–1023.
- **Z**: the distinguished global location assigned zero.

M and S have the same 32-bit bit pattern. M is used as an address base; S is passed as argument data.

Address width, alignment rules, byte order, and signed address-overflow behavior are not independently established. Concrete acceptance examples below assume a compatible 32-bit machine model.

## Behavior

### Ordering and execution conditions

All described effects are conditional on earlier stores and dependencies completing and returning as represented.

Repeated writes are distinct ordered operations. Even when destination and value match, an implementation of this contract must not collapse them merely because ordinary RAM would retain the same final value. A dependency call or a device-like destination could make multiplicity observable.

No visible validation precedes the stores. The represented sequence does not check whether an address is null, aligned, mapped, writable, executable, or associated with a sufficiently large object.

### Entry writes

Before the first dependency call, the function performs:

1. Two consecutive 16-bit writes to P. Each stores the low 16 bits of P.
2. One 16-bit write to the numeric address obtained by doubling P. Its value remains the low 16 bits of the original P.
3. One 32-bit write of G at B plus 20 bytes.

Doubling is numeric address arithmetic, not movement by two elements of a 16-bit array. Overflow behavior for this reconstructed signed-address expression is **documented_only**.

### Result-write forms

Each of fourteen acquisition stages obtains a dependency result and performs two consecutive 16-bit writes to a result-derived address.

Two forms occur:

| Form | Destination | Stored value |
|---|---|---|
| **A** | Lower 32-bit result word shifted right by eight | Low 16 bits of that destination |
| **B** | Lower 32-bit result word masked to its low 27 bits, then shifted right by three | Low 16 bits of that destination |

Form A addresses range from zero through `0x00ffffff`.

Form B addresses also range from zero through `0x00ffffff`. Its represented value calculation shifts the lower word left by five using 32-bit unsigned arithmetic, shifts that result right by eight, then narrows to 16 bits. This is equivalent to the value stated in the table. Treating the left shift as unbounded arithmetic would be incorrect.

For 64-bit results, the upper word does not contribute to these destinations or narrow values. It instead supplies an argument to the following preparation dependency.

### Q-derived writes

Stage 5 differs from the otherwise repeated zero-global pattern. After its two form-A writes, it performs:

- two consecutive 16-bit writes of Q to numeric address Q;
- one 16-bit write of Q to numeric address twice Q;
- the stage’s 32-bit write of G at B + 20.

There is no explicit zero assignment to Z in this stage.

The value calculation narrows bits 16–27 of G to 16 bits and then shifts right by two. Because the mask limits the intermediate to twelve bits, the result is exactly Q. Both Q and twice Q can be very low addresses, including zero.

### Terminal call sequence

After stage 14’s result writes and zero assignment, five further dependencies are invoked in this order:

1. A dependency receives four displayed arguments:
   - `0xffffff1c`;
   - stage 14’s upper word, interpreted as signed 32-bit data, minus `0x264`;
   - `0x4b`;
   - zero.
2. A dependency with no displayed arguments.
3. Three additional dependencies, each with no displayed arguments, in a fixed order.

The first argument has signed 32-bit interpretation −228. The third is decimal 75.

The signed subtraction in the second argument may exceed the signed 32-bit range. The artifact does not establish whether executable behavior wraps, traps, or differs from the reconstructed expression. Such cases are **documented_only**, not portable arithmetic promises.

The represented path then reaches an invalid-instruction termination marker. No normal return, cleanup path, or final status is established.

## Side effects

### Memory writes

If the entire represented path executes, it contains:

- **34 explicit 16-bit writes**:
  - three entry writes;
  - twenty-eight result-derived writes;
  - three Q-derived writes.
- **14 explicit 32-bit state writes**:
  - six at B + 20;
  - eight at M + 20.
- **13 assignments of zero to Z**, whose write width is not established.

The six B-based writes comprise the entry write and stages 1–5. The eight M-based writes comprise stages 6–13: five store G and three store T.

These counts describe explicit operations only. Dependencies may perform additional writes.

### Aliasing and intervening effects

All destinations may alias one another or storage used by dependencies. Z may overlap another symbol or a narrow-write destination. The artifact’s overlapping-global warning makes a disjoint-global assumption particularly unsafe.

Therefore:

- Later explicit writes can overwrite earlier data.
- A dependency can alter storage between explicit writes.
- Assigning zero to Z does not establish that Z remains zero after a later dependency call.
- Final memory content cannot generally be derived from the explicit writes alone.

No explicit reads from the written destinations appear. Implicit entry-state consumption, dependency execution, and retrieval of dependency results are still required.

### Ownership and errors

No allocation, release, ownership transfer, or lifetime protocol is explicitly established. A dependency result is used numerically as an address; that use does not prove the result denotes owned or allocated memory.

There is no represented error return, bounds check, retry, rollback, or recovery handler. A failing store, nonreturning dependency, or invalid call target can prevent all subsequent effects.

## Acceptance examples

These are conditional static acceptance examples, not results of executed tests.

### Entry value differs from doubled destination

Assume P is `0x00001234`, and both required destinations accept 16-bit writes.

The first two writes target `0x00001234` and store `0x1234`. The third targets `0x00002468` but still stores `0x1234`. Storing `0x2468` in the third write would violate the represented value calculation.

### Form A preserves duplicate writes

Assume an acquisition using form A returns lower word `0x12345678`.

Two distinct 16-bit writes must target `0x00123456`, each storing `0x3456`. The destination is not rounded for alignment.

### Form B masks before address formation

Assume an acquisition using form B returns lower word `0xf8001238`.

Masking to 27 bits leaves `0x00001238`; the destination is therefore `0x00000247`. Both stores write `0x0247`. High bits removed by the mask must not affect the address.

### Q-derived low-address writes

Assume G is `0x0abc0000`.

Q is `0x02af`. Stage 5 performs two writes of `0x02af` at address `0x02af`, followed by one write of `0x02af` at address `0x055e`. No Z assignment belongs between this stage’s result writes and its B-based state write.

Whether an odd destination is executable without fault depends on the target platform.

### State-base and payload transitions

Assume G is `0x00000123` and address calculations are representable.

M is `0x00001230`; T is `0x00012300`. Stages 6–10 write `0x00000123` at `0x00001244`. Stages 11–13 write `0x00012300` at that same address. Stage 14 makes no corresponding 32-bit state write.

### Faults preserve only a completed prefix

If stage 1’s first result-derived store faults, no contract requires its duplicate store, its Z assignment, stage 2, or terminal calls to occur. There is no represented rollback of the earlier entry writes.
