# F-0a855d8d955a

## Purpose

F-0a855d8d955a performs unconditional preparation, conditionally obtains a destination, and processes a sequence until its current byte is zero. Each decoded value identifies a bitmap word and bit. A separate dependency decides whether this function increments a destination counter and sets that bit.

The established behavior is the call sequence, conditional traversal, coordinate calculation, and query-controlled mutation. Font configuration, text decoding, and membership tracking are **inferred intent**, not independent guarantees. In particular, the function does not itself enforce uniqueness or establish that the counter equals the number of set bits.

This contract describes static evidence only. No runtime tests have been performed. Unresolved dependency behavior and execution-model questions remain **documented_only**.

### Selected mutation

On a zero query result, the signed 32-bit field at destination offset 4 is read, incremented, and written before the bitmap operation.

Every starting counter value below 2,147,483,647 has a representable increment. Incrementing 2,147,483,647 exceeds the signed 32-bit range. Portable wrapping behavior is not established.

The bitmap operation reads the selected unsigned word and combines it with a single-bit mask. For bit positions 0 through 30, the mask is representable under the visible signed-32-bit mask construction. With valid storage and defined arithmetic, the selected bit is set and all other bits of that word are preserved.

Bitmap addressing uses the destination’s bitmap-base field after the query and after the counter update. No pre-query base snapshot is retained by this function. If the query changes that field, the later operation is not constrained to the earlier base.

The bitmap-base field is referenced in both the read-side and write-side address expressions. The representation does not establish one immutable base snapshot or a stronger ordering among those constituent field reads, the selected-word read, and mask evaluation.

## Acceptance examples

These are conditional static deductions, not executed tests. Unless stated otherwise, they assume normal dependency returns, valid storage, defined arithmetic, and no intervening aliasing effects that invalidate the stated observation.

### Normalized-null input

With third input zero or one, all three preparation calls occur and the first cursor element is initialized. No dispatch lookup or traversal follows.

F-98e5c938e9b6 receives zero in the first case and one in the second, so identical overall effects are not required.

### Missing destination and empty sequence

If the indirect dependency returns zero, this function does not read a traversal-condition byte.

If it returns a usable destination and the first tested byte is zero, the byte is read, but neither the decoder nor the query is invoked.

### Ordinary word boundary

A decoded value of 32 selects word index 1 and bit position 0. With a zero query result and a representable counter increment, the counter increases before bit zero of the second bitmap word is set.

A decoded value of 31 selects word index 0 and bit position 31. Its query coordinates are established. A zero query result reaches the unresolved high-bit mask boundary rather than a guaranteed portable bitmap update.

### Repeated value

If two passes decode value 7 and both queries return zero, two representable counter increments occur. The second bitmap operation can leave an already-set bit unchanged.

The function has no independent rule preventing the second increment.

### Nonzero query result

For any decoded value, a nonzero query result skips this function’s counter and bitmap operations. This includes negative query results.

The query’s own side effects remain possible.

### Query changes the next condition

Suppose decoding leaves the cursor at a nonzero byte. If the query changes that byte to zero and returns nonzero, the next condition check ends traversal without a direct counter or bitmap update.

Cursor advancement is therefore not the only possible source of termination.

### Query replaces the bitmap base

If the query replaces the destination’s bitmap-base field and returns zero, subsequent bitmap addressing refers to that field after the query and counter update. The operation is not required to use the earlier base.

### Largest decoded value

A decoded value of 4,294,967,295 selects word index 134,217,727 and bit position 31. A nonzero query result skips direct counter and bitmap accesses, including mask formation.

A zero result additionally requires usable addressed storage and reaches the unresolved high-bit mask boundary. The decoded value itself is not rejected.

### Counter limit

A counter value of 2,147,483,646 can become 2,147,483,647. Another selected increment exceeds the signed range. Neither wrapping to the signed minimum nor completion of the bitmap operation is guaranteed.
