# F-f1d95153eae8

## Purpose

F-f1d95153eae8 performs a guarded processing pass over a linked, clause-bearing object. It delegates expression processing and clause resolution, records that an object has been entered, applies two structural restrictions, and may continue recursively through a linked object.

The established behavior is a sequence of memory accesses, dependency calls, and status returns. A query-analysis or semantic-validation role is inferred from the diagnostic categories and clause-like relationships; the exact application-level object types are not established.

The entry marker is not a success marker. It is written before processing begins and is not cleared on any visible failure path. Consequently, a later call on an object whose earlier processing failed can return success immediately.

## Interface

### Inputs and result

The function accepts three arguments:

1. A pointer to a mutable owner or processing-state object.
2. A pointer to a mutable current object.
3. An opaque 32-bit value, forwarded into a temporary context and to recursive calls.

It returns a 32-bit result. Its locally selected results are:

- **0:** the entry marker was already nonzero, or the visible processing sequence completed without a linked-object call.
- **1:** a gate, dependency result, missing required structure, or diagnosed restriction prevented completion.
- **7:** a specific owner-associated status byte was nonzero after clause resolution.

A recursive call’s result is returned unchanged. The supplied function body itself selects only 0, 1, and 7; these are not three interchangeable success/failure categories.

### Representation and memory preconditions

The supplied representation uses 32-bit integers and 32-bit address-bearing words. Byte fields are 8 bits; the inspected flag field is 16 bits. Offsets below are byte offsets.

The function does not validate either top-level pointer. Callers must provide readable and writable storage for every field reached on the selected path. In particular, the current object must be writable at offset 6 even when later processing will fail.

The owner object exposes:

| 64 | Signed 32-bit value. Processing proceeds only when this value is less than 1. |

### Collection layouts

The primary collection has:

- A 32-bit count at offset 0.
- A 32-bit record-array address at offset 12.
- Records of 12 bytes, with the first 32-bit word of each record supplied to expression processing.

The grouping collection has:

- A signed 32-bit count at offset 0.
- A record-array address at offset 12.
- Records of 12 bytes, whose first word points to another object.
- A 16-bit flag field at offset 2 in each referenced object.

No element-type tag, null-element check, array-capacity check, or address-overflow check is visible.

## Behavior

### 1. Entry guard and initial gate

The function first reads the current object’s byte at offset 6.

If it is nonzero, the function returns 0 immediately. It does not visibly consult the owner, validate clauses, or follow the linked-object pointer on this path.

Otherwise, it writes 1 to that byte. It then reads the owner’s signed 32-bit field at offset 64:

- If the value is 1 or greater, it returns 1.
- If the value is less than 1, it calls F-999eed91b576 with the owner and current-object pointers.
- If that dependency returns nonzero, it returns 1.

The signed comparison admits negative owner-state values; it is not merely an equality-to-zero check.

### 2. Context preparation and initial expression processing

After the initial gate succeeds, the function:

1. Calls the unmapped initialization dependency with the temporary-context address and 36.
2. Writes the owner pointer into context offset 0.
3. Calls F-efc2c252d6ce with the context and the current object’s value at offset 44.
4. Only if that call returns zero, calls F-efc2c252d6ce with the context and the value then read at offset 48.

A nonzero result from either expression-processing call becomes return value 1; the dependency’s numerical result is not propagated.

After both calls succeed, the function sets context byte 20 to 1 and copies the current object’s value at offset 12 into context offset 4.

### 3. Primary-collection traversal

The function next reads the primary-collection pointer at current-object offset 0. A null pointer produces return value 1 without a visible diagnostic call.

For a non-null primary collection, it stores the third argument at context offset 32 and traverses its records.

The primary count is loaded as 32 bits and interpreted as signed for comparison with the signed iteration index. Thus, a count whose top bit is set behaves as a negative bound and causes no record visits. A count of zero also causes no visits.

The count is reloaded at every loop condition, including the condition that ends traversal. For each visited record:

- The record-array address is read from primary-collection offset 12.
- The record’s first word is read using a 12-byte stride.
- F-efc2c252d6ce is called with the temporary context and that word.
- A nonzero dependency result immediately produces return value 1.

Because the count and record-array address are reread, mutations made by dependencies can affect subsequent traversal. The primary-collection pointer itself remains the pointer captured before the loop.

### 4. Grouping state and structural prerequisite

After traversal, the function captures the grouping-collection pointer from current-object offset 20.

If that captured pointer is null, it reads context byte 21:

- If the byte is zero, it changes context byte 20 to 0.
- If the byte is nonzero, it writes 1 to current-object byte 7.

If the captured grouping pointer is non-null, it writes 1 to current-object byte 7 without needing the context-byte test.

There is no visible clearing of current-object byte 7. An existing nonzero value can survive a path that performs no write to it.

The function then checks a structural prerequisite using the current object’s value at offset 24 and the captured grouping pointer:

- A zero value at offset 24 permits continuation.
- A non-null captured grouping pointer also permits continuation.
- A nonzero value at offset 24 with a null captured grouping pointer triggers F-2022b0f73f3b with a diagnostic concerning a required grouping clause, followed by return value 1.

The complete diagnostic text is not established by the supplied body.

### 5. Remaining expression and clause processing

If the structural prerequisite passes, the function copies the current object’s then-current primary-collection pointer into context offset 8. This is a new read and need not equal the pointer traversed earlier.

It then performs the following short-circuiting sequence:

1. F-efc2c252d6ce receives the value at current-object offset 16.
2. If successful, F-efc2c252d6ce receives the value at offset 24.
3. If successful and current-object offset 32 is zero, F-900edbc755cc receives the owner, current object, value at offset 28, mode value 1, and the address of context byte 21.
4. If the preceding applicable operations succeed, F-900edbc755cc receives the owner, current object, captured grouping pointer, mode value 0, and that same context-region address.

The second clause-resolution call is made even when the captured grouping pointer is null. No null rejection is imposed locally for that argument.

Every nonzero result in this sequence produces return value 1. No later operation in the sequence is performed after such a result.

### 6. Owner-associated status and grouping restriction

After the clause-resolution sequence succeeds, the function reads the owner’s word at offset 0, follows that address, and inspects the byte at offset 30.

If the byte is nonzero, it returns 7 immediately. This check precedes grouping-record validation and linked-object recursion.

If the captured grouping pointer is non-null, the function next captures its record-array address and scans its records. The grouping count is reread as a signed 32-bit value for each loop condition. Zero and negative counts produce no record visits.

For each visited record, the function follows its first word and tests bit mask 2 in the 16-bit field at offset 2 of the referenced object.

On the first set bit:

- F-2022b0f73f3b is called with a diagnostic concerning disallowed aggregate functions.
- The function returns 1.
- No later grouping records or linked object are processed.

The captured record-array address is advanced by 12 bytes per visited record; unlike the primary traversal, it is not reloaded for each record.

### 7. Linked-object continuation

After all preceding checks succeed, the function reads current-object offset 32 again.

- If it is zero, the function returns 0.
- If it is nonzero, F-f1d95153eae8 is called recursively with the same owner, that linked object, and the unchanged third argument. Its return value is returned directly.

The linked-object value used here is not guaranteed to match the value that previously controlled omission of the first clause-resolution call.

## Side effects

The established direct persistent writes are:

- Current-object byte 6 becomes 1 on first entry.
- Current-object byte 7 conditionally becomes 1.

Neither write is rolled back on failure. No direct write clears either byte.

Additional mutations may be performed by dependencies, including mutations of owner state, current-object fields, collection structures, or the temporary context. Their preservation properties are unknown.

The function performs no explicit allocation, release, or ownership transfer. Passing pointers to dependencies does not establish that those dependencies borrow, retain, allocate, or free the referenced storage. In particular, no dependency may safely be assumed to preserve globals or release memory.

The temporary context has invocation-local lifetime. Whether any dependency retains its address, and whether that is permitted by the broader system, is documented_only.

## Acceptance examples

These examples are conditional on valid reached memory and the stated dependency behavior.

1. **Previously entered object.** With byte 6 already nonzero, the result is 0. Owner-state checks and dependency calls are skipped, even if a prior attempt failed.

2. **Owner gate rejects processing.** With byte 6 initially zero and owner offset 64 equal to 1, byte 6 becomes 1 and the result is 1. F-999eed91b576 is not called.

3. **Negative owner-state value.** With owner offset 64 equal to −1, the signed gate permits F-999eed91b576 to run. Its outcome determines whether processing continues.

4. **Initial expression failure.** If the first F-efc2c252d6ce call returns nonzero, the result is 1 and the second initial expression call is skipped.

5. **Missing primary collection.** If the initial calls succeed but current-object offset 0 is null, the result is 1. No explicit diagnostic is emitted by this function.

6. **Primary count with its top bit set.** With an otherwise valid primary collection whose count is 0x80000000, primary records are not visited because the bound is interpreted as negative. Later processing can still occur.

7. **Required grouping structure absent.** With a null captured grouping pointer and a nonzero value at current-object offset 24, the grouping-required diagnostic is requested and the result is 1.

8. **Null grouping passed to resolution.** With a null grouping pointer, zero at offset 24, and successful preceding operations, the mode-0 F-900edbc755cc call still occurs with a null clause argument.

9. **Owner-associated status takes precedence.** If that status byte is nonzero after successful resolution, the result is 7, even if a grouping record would later violate the aggregate restriction.

10. **Disallowed grouping expression.** With owner-associated status zero and mask 2 set in a visited grouping expression’s 16-bit flags, the aggregate-related diagnostic is requested and the result is 1.

11. **Linked-object propagation.** With all local checks successful and a non-null final linked-object pointer, the recursive result is returned unchanged. If the linked object is already marked, that recursive call returns 0 immediately.
