# F-061ad70be17c

## Purpose

F-061ad70be17c supports two related operations selected by whether its fourth argument is null:

- With a null fourth argument, obtain an underlying object and construct or initialize an associated wrapper, returning the wrapper through the third argument.
- With a non-null fourth argument, optionally discover a related position, invoke a further operation when required, and return a position through the fourth argument. The third argument optionally receives an object produced by that operation.

These descriptions summarize the visible data flow. The domain meanings of “object,” “wrapper,” and “position” are not established. In particular, values represented as pointers in the supplied representation are sometimes used as numeric identifiers or byte-addressed positions rather than dereferenceable object addresses.

The contract below distinguishes direct static evidence from inferred intent and unknown dependency behavior. No runtime tests have been performed.

## Behavior

### Mode selection

The function tests the fourth argument for null before selecting either behavior below. Its local candidate-position value begins at zero.

The supplied representation contains unusual stack-slot manipulation in the null-fourth-argument branch. It supports a dependency output slot initialized to numeric value one, followed by consumption of that slot. It does not establish a stable public stack layout or an additional caller-visible interface.

### Null fourth argument: obtain and initialize a wrapper

1. Prepare a local output slot with the 32-bit value `1`.
2. Read the first 32-bit word of the context.
3. Call F-133a6620fb39 with:
   - that context word;
   - the second argument;
   - the address of the prepared output slot.
4. If the dependency returns a nonzero status, return that status immediately. There is no subsequent direct write through the third argument.
5. On zero status, call F-7871c7eca1be with the value in the dependency output slot. Its result is treated as the base address of writable wrapper storage.
6. Read the 32-bit field at offset `0x34` from the object identified by the dependency output slot.
7. Perform the following wrapper writes, in this order:

| Destination within wrapper | Width | Value |
|---|---|---|
| `0x48` | 32 bits | Underlying object value from the dependency output slot |
| `0x4c` | 32 bits | Second argument |
| `0x44` | 32 bits | Value read from underlying object offset `0x34` |
| `0x40` | 32 bits | First argument |
| `0x08` | 8 bits | Decimal `100` if the second argument equals numeric value `1`; otherwise zero |

8. Write the wrapper address to the third-argument output slot.
9. Return zero.

The underlying object's `0x34` field is read after F-7871c7eca1be returns. There is no visible null check on either the underlying object or the returned wrapper address. Successful completion therefore depends on the dependencies supplying usable values and storage.

The one-byte write at wrapper offset `0x08` does not establish the contents of adjacent bytes. Likewise, the function initializes only the listed wrapper fields; it does not visibly clear the wrapper.

### Non-null fourth argument: optional candidate discovery

The function first reads the context byte at offset `0x16`.

If that byte is zero, discovery is skipped and the candidate remains zero.

If the byte is nonzero, discovery starts from the second argument and proceeds as follows:

- Advance the position by one byte-address unit.
- Call F-c76bdec3f9e1 with the context and that advanced position.
- If the dependency returns exactly the same position, advance again and repeat this step.
- Once the returned value differs from the current position, call F-d7be9cfb4000 with numeric constant `0x40000000` and the context's 16-bit field at offset `0x1c`.
- Add one to that dependency's result using 32-bit unsigned arithmetic. If the resulting 32-bit value equals the current position, resume the search with another increment.

The value returned by F-c76bdec3f9e1 is used only for the equality test in this loop. It does not replace the current position.

The visible logic has no iteration limit or explicit exhaustion result. If the dependencies continually cause rejection, the search does not reach the later output writes.

After a position survives both filters:

1. Read the context's first 32-bit word and pass it to F-f3192f39e4f6.
2. Compare the current position with that dependency's result using the pointer-shaped ordering shown in the supplied representation.
3. Only if the position is less than or equal to that result, call F-4549cf6868d1 with:
   - the context;
   - the current position;
   - the address of scratch descriptor storage;
   - the address of a second scratch slot.
4. If F-4549cf6868d1 returns nonzero, return that status immediately. Neither public output slot receives a subsequent direct write from this function.
5. On zero status, inspect the first byte of the descriptor scratch storage.
6. Accept the current position as the candidate only if that byte equals `4` and the second scratch slot equals the original second argument.

A successful descriptor call that does not meet both acceptance conditions leaves the candidate zero. A position beyond the comparison bound likewise leaves the candidate zero; it does not itself produce an error.

- Do not call F-14f40f321d22.
- Do not call F-6cc778185718.
- Write the candidate to the fourth-argument output slot.
- Return zero.

The zero status for this path is established in the successful descriptor-processing branch. The path is not reachable without accepting a candidate there.

### Remaining processing

All remaining non-null-fourth-argument paths perform the following steps:

1. Initialize a local object-output slot to zero.
2. Call F-14f40f321d22 with:
   - the context;
   - the original second argument;
   - the address of that output slot;
   - a flag indicating whether the candidate is nonzero.
3. Retain the dependency's 32-bit result as the eventual return status.
4. If the candidate is still zero and the retained status is zero:

   - Use the returned 32-bit value as the position to be written through the fourth argument.
5. If the third argument is null, call F-6cc778185718 with no visible arguments.
6. Otherwise, write the local object-output value through the third argument.

A zero result from F-d1e995cfb2d3 remains a valid visible output value: this function does not convert it into an error.

## Side effects

### Direct writes

The direct caller-visible writes depend on the path:

- Successful null-fourth-argument mode: the listed wrapper fields, then the third-argument slot.
- Candidate-only early completion: the fourth-argument slot only.
- Remaining second-mode paths with a non-null third argument: third-argument slot, then fourth-argument slot.
- Remaining second-mode paths with a null third argument: a call to F-6cc778185718, then the fourth-argument slot.
- Early dependency-error returns: no later direct output writes by this function.

“Unchanged” on an early return is conditional on dependency behavior and aliasing. The dependencies receive some caller-provided values and may have effects not visible here.

### Aliasing and ordering

No non-aliasing guarantee is established.

If the third and fourth arguments identify the same four-byte slot in the second mode, and execution reaches both writes, the object output is written first and the position output overwrites it second.

If an output aliases the context or wrapper storage, the specified write order still matters. No validation prevents such overlap. Dependencies may add further aliasing constraints.

### Ownership and external state

The function stores references to the context and underlying object in the wrapper. This establishes retained values, not reference counting or ownership transfer.

There is no visible direct deallocation. F-6cc778185718 may have cleanup-related intent, but its no-argument call does not establish what it releases, if anything.

No dependency is known to preserve globals, preserve pointed-to storage, or transfer ownership. The effects of each call must therefore be considered separately from the direct effects listed above.

## Acceptance examples

These are conditional acceptance criteria derived from static evidence, not executed tests.

1. **Wrapper initialization with special second argument.**  
   Given a null fourth argument, second argument equal to numeric `1`, a successful F-133a6620fb39 result, and valid underlying and wrapper storage, the function writes decimal `100` to wrapper byte `0x08`, initializes the other listed fields, returns the wrapper through the third argument, and returns zero.

2. **Wrapper dependency failure.**  
   If F-133a6620fb39 returns nonzero, that exact status is returned. F-7871c7eca1be is not called, and the function performs no subsequent direct write through the third argument.

3. **Discovery disabled, successful fallback.**  
   With a non-null fourth argument and context byte `0x16` equal to zero, no discovery dependencies are called. If F-14f40f321d22 succeeds, its output object's `0x44` field is passed to F-d1e995cfb2d3, whose result becomes the fourth output.

4. **Accepted candidate without object output.**  
   If discovery accepts a nonzero candidate and the third argument is null, the fourth output receives that candidate and the result is zero. Neither F-14f40f321d22 nor F-6cc778185718 is called.

5. **Accepted candidate with object output.**  
   With the same accepted candidate and a non-null third argument, F-14f40f321d22 is called with its candidate-present flag set. The candidate remains the fourth output even if that dependency returns an error. F-d1e995cfb2d3 is not called.

6. **Descriptor failure.**  
   A nonzero result from F-4549cf6868d1 is returned immediately. The ordinary operation and final output writes are skipped.

7. **Ordinary-operation failure without a candidate.**  
   If F-14f40f321d22 returns nonzero and no candidate was accepted, the fourth output receives zero. A non-null third argument receives the dependency output slot's current value, including zero if the dependency left it untouched.

8. **Aliased public outputs.**  
   If both output arguments identify the same valid slot on an ordinary second-mode path, the final contents are the position, because that write follows the object-output write.

9. **Unsigned filter wraparound.**  
   If F-d7be9cfb4000 returns the 32-bit all-ones value, adding one yields zero for the filter comparison. No overflow error is generated by this arithmetic.
