# F-97ef1a3fa460

## Purpose

F-97ef1a3fa460 obtains a construction candidate, requests construction using source metadata and global settings, and conditionally applies up to two processing operations. Its normal result is exactly the construction dependency’s 32-bit result.

Construction failure is recognized only by a zero result. After nonzero construction, processing has two independent selection mechanisms:

- A source-format discriminator selects an optional first operation.
- The mode input and a context discriminator select an optional second operation.

The first operation, when selected, changes where the first payload argument for the second operation comes from. Disabling context processing does not disable construction, source-format processing, or the payload refresh following source-format processing.

**Inferred intent:** the function appears to construct an object and apply format-dependent and context-dependent transformations. The application domain and transformation meanings are not established. “Candidate,” “constructed object,” “payload,” and “metadata” describe call-site roles, not verified allocation, ownership, or data-format semantics.

## Interface

| Input | Behavioral role |
|---|---|
| Context reference | Supplies a one-byte discriminator at offset `0x1C4`, read only when construction succeeds and mode is zero or one. |

The construction candidate and construction result are separate values. The function neither requires nor checks that they are equal.

### Construction boundary

The global table selection and separate global-setting read are part of construction preparation after the two preceding calls. Their relative evaluation order is not established. They must not be modeled as values captured before those calls: neither preceding dependency has an established global-preservation guarantee.

A zero candidate does not short-circuit construction. The initial metadata query and construction still occur, with zero supplied as construction’s first input.

A zero construction result ends the function with zero and no explicit cleanup. A nonzero result becomes the reference used for subsequent constructed-object accesses and remains the eventual normal return value. The caller cannot infer successful later processing merely from that nonzero return.

### Payload provenance

The contract distinguishes two payload arguments supplied to a selected processing operation:

- The **retained payload** is captured before that operation’s metadata queries.
- The **current constructed payload** is read after both queries complete.

Immediately after nonzero construction, the retained payload comes from the source’s four-byte field at offset `0x04`. This observation is after construction, so construction’s changes to that field are visible.

If source-format processing occurs, the retained payload is replaced by a fresh read of the constructed payload after that operation returns. This refresh occurs even when the mode disables context processing.

If no source-format operation occurs, the retained payload remains the captured source payload. There is no corresponding refresh from the constructed object on that path.

Consequently, context processing may receive either a source-derived retained value or a post-source-format constructed value. These alternatives are observable and must not be collapsed into an unconditional constructed-payload read.

## Acceptance examples

These are conditional static acceptance examples, not executed tests. Each assumes valid reached accesses and arithmetic, and normal completion of reached dependencies.

1. **Construction failure.** If construction returns zero, the function returns zero after the candidate request and initial metadata query. It performs no subsequent source-payload, format, constructed-payload, or context-byte read and invokes no processing operation. No explicit cleanup is issued.

2. **Zero candidate, successful construction.** If F-8157a180d901 returns zero but construction returns nonzero, construction still receives zero in its first position. Its result determines further behavior and the eventual return. Rejecting the invocation before construction would violate this contract.

3. **Unrecognized stable format, disabled context.** With a stable unrecognized format and mode two, the source payload is captured, both format comparisons fail, and no processing operation occurs. The context byte and constructed payload are not read by this function.

4. **Recognized format, disabled context.** With stable format `0x0065` and mode two, F-24dc4d74c711 still runs. Its metadata queries precede its second payload argument, and a constructed-payload refresh follows the operation. No context byte is read.

5. **Two-stage processing.** With stable format `0x1888`, mode one, and context byte nine when observed, F-c3b9b1939a6a precedes F-3fcc6fd31697. The latter’s first argument is the constructed payload retained after the first operation; its second is observed after its own metadata queries.

6. **Context value twelve.** With an observed context byte of twelve, mode zero selects F-1c7c9f39bc69. Mode one selects no context operation and performs no context-stage queries. Applicable source-format work is unaffected.

7. **Payload mutation during queries.** If source-format processing leaves the constructed payload holding one value, and a later context metadata query changes it, the context operation receives the earlier value first and the updated value second. Replacing both with the updated value is not equivalent.

8. **Source mutation during construction.** If construction changes the source payload before returning nonzero, the changed value is captured. With no recognized format, it remains the retained first argument for a selected context operation.

9. **Distinct format observations.** If the first format observation is unrecognized and the second is `0x0065`, F-24dc4d74c711 is selected. If the first is `0x1888`, F-c3b9b1939a6a is selected without a second format read.

10. **Shift boundary.** An initial metadata result of `0x3FFFFFFF` supplies `0x7FFFFFFE` as construction’s fourth argument. This example provides no wrapping guarantee for values outside the established representable range.
