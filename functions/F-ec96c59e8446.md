# F-ec96c59e8446

## Purpose

F-ec96c59e8446 evaluates a selected comparison between signed, two-word integer operands and writes a Boolean result to caller-provided byte storage. Two selectors evaluate a range using a third operand. A separate flag complements the stored result.

The function returns a 32-bit status independently of the result byte. An unsupported selector produces an error status but can still leave the result byte equal to one when complementation is enabled. Consumers must therefore check the status before treating the byte as a valid comparison result.

This contract describes established static behavior. No runtime tests have been performed.

## Interface

The interface consists of nine positional arguments and one 32-bit return value.

| Position | Role | Width and interpretation |
|---|---|---|
| 1 | Operation and flags | Unsigned 32-bit word. Bits 0–23 select the operation; bit 25 enables result complementation. |
| 2 | Unused argument | One 32-bit word. Its value does not affect the established behavior. |
| 3 | First operand, low word | Unsigned 32-bit word. |
| 4 | First operand, high word | Signed 32-bit word, interpreted as the upper half of a signed 64-bit value. |
| 5 | Second operand, low word | Unsigned 32-bit word. |
| 6 | Second operand, high word | Signed 32-bit word, interpreted as the upper half of a signed 64-bit value. |
| 7 | Third operand, low word | Unsigned 32-bit word. Used only by the two range selectors. |
| 8 | Third operand, high word | Signed 32-bit word. Used only by the two range selectors. |
| 9 | Result destination | Pointer to writable storage for at least one byte, or null. |

For this specification, the three mathematical operand values are:

- **A:** argument 4 multiplied by \(2^{32}\), plus argument 3.
- **B:** argument 6 multiplied by \(2^{32}\), plus argument 5.
- **C:** argument 8 multiplied by \(2^{32}\), plus argument 7.

Each value lies in the signed 64-bit interval \([-2^{63}, 2^{63}-1]\). These definitions describe the operands’ interpretation, not additional arithmetic that a caller must perform.

The low and high words are supplied separately by value. There is no input buffer layout or byte-order requirement established by this function. The output is exactly one byte.

### Return values

| Return bit pattern | Meaning |
|---|---|
| `0x00000000` | Recognized selector and non-null result destination. |
| `0xFFFFFFCE` | Null result destination or unsupported selector. |

The error bit pattern represents −50 when interpreted as signed 32-bit. No more specific error taxonomy is established.

### Preconditions

A non-null result destination must designate live, writable byte storage. If complementation is enabled, that storage must also be readable.

A non-null but inaccessible destination is not converted into the documented error status by any visible validation. Fault behavior for such a pointer is outside the established contract.

The caller retains ownership of the destination. There is no allocation, transfer of ownership, or release operation.

## Behavior

### Operation decoding

The selector is the operation word masked with `0x00FFFFFF`.

Exactly these selectors are recognized:

| Selector | Result before complementation |
|---|---|
| `0x000001` | A equals B |
| `0x000010` | A is greater than B |
| `0x000020` | A is greater than or equal to B |
| `0x000040` | A is less than B |
| `0x000080` | A is less than or equal to B |
| `0x000100` | B is less than or equal to A, and A is less than or equal to C |
| `0x000200` | B is strictly less than A, and A is strictly less than C |

A true predicate produces byte value one; a false predicate produces byte value zero.

The selector is an exact value, not a set of independently combinable comparison flags. For example, `0x000003` is unsupported rather than a combination of operations.

Bits 24 and 26–31 do not affect selection or the result. Bit 25, represented by mask `0x02000000`, controls complementation. No other use of these upper bits is visible.

### Signed ordering

All ordering predicates use the signed 64-bit interpretations of A, B, and C.

Equivalently, two operands can be ordered by comparing their high words as signed 32-bit values, and—when the high words are equal—comparing their low words as unsigned 32-bit values.

The static expressions implement ordering through 32-bit subtraction, low-word borrow, and signed-overflow indicators. A faithful implementation must preserve the resulting full-width ordering at overflow boundaries. Merely checking the sign of an uncorrected high-word subtraction is insufficient.

Equality requires both corresponding words to be equal.

### Entry and initial write

The result destination is checked for null before any destination access.

If it is null:

- The function returns `0xFFFFFFCE`.
- No output byte is read or written.
- Neither selector processing nor complementation changes this outcome.

For a non-null destination, the function writes zero to the destination before determining whether the selector is supported. The caller’s original byte value is therefore discarded on every non-null path.

### Recognized selectors

A recognized selector computes the predicate specified in the table and then writes its Boolean result to the destination.

This write occurs even when the predicate is false and the destination already contains the initial zero. Thus, without complementation, a successful non-null call has two explicit byte writes: initial zero, then the predicate result.

The equality and two-operand ordering selectors do not use C.

For the inclusive range selector, the lower-bound comparison is evaluated first. The upper-bound comparison is reached only if A is at least B.

For the strict range selector, the lower-bound comparison is likewise evaluated first. The upper-bound comparison is reached only if A is strictly greater than B.

The range bounds are not sorted, exchanged, or validated separately:

- If B is greater than C, neither range predicate can be true.
- If B equals C, the inclusive range is true exactly when A equals that bound.
- If B equals C, the strict range is always false.

### Unsupported selectors

For any other selector, the status becomes `0xFFFFFFCE`.

The initial zero remains in the destination until any requested complementation is applied. There is no separate predicate-result write on this path.

Consequently:

- Unsupported selector without complementation: error status and output zero.
- Unsupported selector with complementation: error status and output one.

An error does not imply that the destination is unchanged.

### Complementation

After either recognized-selector evaluation or unsupported-selector handling, bit 25 determines whether the destination byte is complemented.

With stable caller storage, complementation maps zero to one and one to zero. It does not change the return status.

The supplied representation contains two explicit destination-byte reads during this step:

1. A read used to form a one-minus-byte candidate.
2. A subsequent read used to check whether the byte exceeds one.

The function then writes the complemented result. If the second read observes a value greater than one, the final written value is zero.

Ordinary execution reaches this step with a byte value of zero or one because the function has already written the destination itself. The greater-than-one handling does not preserve or validate the byte present at entry.

No synchronization is visible. Behavior involving concurrent modification or special read-sensitive storage is not established as a supported use case.

## Side effects

The only explicit externally visible state change is access to the single byte designated by argument 9.

For ordinary writable storage, the access patterns are:

| Path | Explicit destination accesses |
|---|---|
| Null destination | None |
| Recognized selector, complementation disabled | Write zero; write predicate result |
| Recognized selector, complementation enabled | Write zero; write predicate result; two byte reads; write complemented result |
| Unsupported selector, complementation disabled | Write zero |
| Unsupported selector, complementation enabled | Write zero; two byte reads; write complemented result |

The explicit reads in the complementation step occur after the preceding writes, not before them.

These sequences describe the supplied static representation. They are not a claim about physical memory transactions, compiler optimization, atomicity, or volatile-access semantics.

No neighboring output bytes are explicitly accessed. No global variable access, external call, allocation, deallocation, I/O, or persistent state update is visible.

All operand words are passed by value. Internal selection of the third operand for an upper-bound comparison does not modify caller-owned operand storage.

## Acceptance examples

These examples are conditional acceptance criteria derived from static behavior, not executed tests. Unless stated otherwise, assume a valid, stable result destination and complementation disabled.

### Comparison selection

For A = 5 and B = 7:

| Selector | Expected status | Expected byte |
|---|---|---|
| `0x000001` | `0x00000000` | 0 |
| `0x000010` | `0x00000000` | 0 |
| `0x000020` | `0x00000000` | 0 |
| `0x000040` | `0x00000000` | 1 |
| `0x000080` | `0x00000000` | 1 |

For A = B, equality and both non-strict ordering predicates produce one; both strict ordering predicates produce zero.

### Signed interpretation and low-word boundaries

If A has high word −1 and low word `0xFFFFFFFF`, A represents −1. If B has both words zero, A is less than B despite A’s low word being larger as an unsigned value.

If A has high word zero and low word `0xFFFFFFFF`, and B has high word one and low word zero, A is less than B. This case requires the low-word borrow to participate correctly in the full-width comparison.

At the full-width extremes, \(-2^{63}\) is less than \(2^{63}-1\). An implementation that reverses this result because a high-word subtraction overflows does not satisfy this contract.

### Range endpoints

For B = 10 and C = 20:

| A | Inclusive selector `0x000100` | Strict selector `0x000200` |
|---|---|---|
| 9 | 0 | 0 |
| 10 | 1 | 0 |
| 15 | 1 | 1 |
| 20 | 1 | 0 |
| 21 | 0 | 0 |

For B = C = 10 and A = 10, the inclusive selector produces one and the strict selector produces zero.

For B = 20 and C = 10, both selectors produce zero for every A; the function does not normalize the interval.

### Flags, errors, and output replacement

With A = B and operation word `0x02000001`, the status is zero and the final byte is zero: equality is true, then complemented.

With selector `0x000003`, the status is `0xFFFFFFCE` and the byte is zero, regardless of its entry value.

With operation word `0x02000003`, the status remains `0xFFFFFFCE`, but the final byte is one.

Adding `0x80000000` to an otherwise unchanged operation word does not change behavior. Changing argument 2 likewise does not change behavior.

With a null destination, every operation word returns `0xFFFFFFCE` without a destination access.
