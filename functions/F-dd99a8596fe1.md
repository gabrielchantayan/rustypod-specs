## Behavior

### Control-dependent primary-object operation

If the control value is nonzero, the function resolves the primary object’s dispatch-table reference and invokes the entry at byte offset `0x118`, explicitly passing the primary object.

If the control value is zero, this dispatch is skipped.

The subsequent flag test occurs after this operation returns. Consequently, the flag test observes the primary-object state then present, not necessarily the state that existed on function entry. An implementation that reads and caches the flag before the setup calls or the conditional dispatch would not preserve the established ordering.

### Flag-dependent operation

The function reads the four-byte field at primary-object offset `0xD4`, narrows it to a character, and compares that character with zero.

If the narrowed value is zero, the entire flag-dependent sequence is skipped. In particular, this branch performs no direct flag write and does not call F-6a21f4f07f67 or the dispatch entry at `0x90`.

If the narrowed value is nonzero:

1. F-6a21f4f07f67 is called.
2. A null result selects F-a817d8d58c10.
3. On the nonnull path, one zero byte is written at primary-object offset `0xD4`.
4. The returned object’s dispatch-table entry at `0x90` is then invoked.

The supplied representation identifies F-a817d8d58c10 as nonreturning. On that modeled path, the flag-clearing write and all remaining work are not reached. Whether the nonreturning operation terminates, throws, transfers control elsewhere, or has another mechanism is unknown.

On the nonnull path, clearing the flag byte happens after F-6a21f4f07f67 returns and before the indirect call at `0x90`. The dispatch-table reference is resolved from the returned object for that call. No preservation or non-aliasing guarantee is established between that object and the primary object.

The represented invocation at `0x90` supplies no explicit arguments. A receiver or hidden argument must not be invented from the apparent object-dispatch pattern.
