# F-d9b4fb08294c

## Purpose

F-d9b4fb08294c copies three 32-bit words from a source record into a destination object. It then rereads the destination’s middle word, converts it to the target’s plain character type, and compares that character with one obtained through global-associated state.

An equal comparison ends the operation after the copy. A differing comparison causes two ordered one-byte writes: the converted character, followed by the value 1. The address-bearing state used for the second write is reread after the first write.

Three qualifications limit this description:

- The declaration of the global root reference is absent. The value obtained by dereferencing it has an unknown type. Adding `0x30` to that value is therefore an unresolved typed addition, not an established byte displacement.
- The declaration of the separate comparison-address operand is also absent. Its representation, evaluation requirements, mutability, and effect on address arithmetic are unresolved.
- Conversion to the target’s plain character type does not, by itself, establish low-eight-bit truncation for every 32-bit input.

The application meanings of the record, comparison character, and conditional writes are unknown. A “changed value” or “dirty flag” interpretation is inferred intent, not established behavior.

## Interface

### Inputs

**Destination address.** An integer-like address argument used to access three consecutive 32-bit fields:

| Destination byte offset | Width | Access |
|---|---:|---|
| `0x78` | 32 bits | Written with the first source word |
| `0x7C` | 32 bits | Written with the second source word, then reread |
| `0x80` | 32 bits | Written with the third source word |

The destination argument is not checked for null. Its total object extent and other fields are not identified.

**Source record address.** A nullable address identifying the following record:

| Source byte offset | Width | Destination |
|---|---:|---|
| `0x00` | 32 bits | Destination byte offset `0x78` |
| `0x04` | 32 bits | Destination byte offset `0x7C` |
| `0x08` | 32 bits | Destination byte offset `0x80` |

The represented accesses use 32-bit words and one-byte character or byte accesses. The contract does not establish a portable interface for different integer widths, character widths, or address representations.

### Output

There is no returned value or error status. Observable results consist of memory accesses and their effects.

A null source causes an immediate return without accessing the destination or evaluating the global lookup chain.

### Preconditions

For a non-null source to complete normally:

- The three source words must be readable.
- The three destination fields must be writable.
- The middle destination field must also be readable after the copy.
- Evaluation and dereferencing of the global root reference must be valid.
- The unresolved typed addition of `0x30` to the resulting root operand must produce a location from which the 32-bit state address can be read.
- The state field at byte offset `0xF00` must be readable.
- Evaluation of the comparison-address operand, the resulting address calculation, and the comparison-character read must be valid.
- The character conversion must permit execution to continue.

On a mismatch, the first conditional byte destination must be writable, the repeated state-field read must be valid, and the final byte destination must be writable.

Object lifetimes, alignment, address arithmetic, and access permissions must support these operations. The function does not validate them. In particular, “root plus `0x30` bytes” is not a sufficient specification of the root lookup without the missing declaration.

## Behavior

### Null-source path

The source address is checked before any other shown memory access.

If it is null, the function returns without:

- Reading source contents.
- Accessing the destination.
- Dereferencing the global root reference.
- Evaluating either unresolved address expression.
- Converting or comparing a character.
- Performing any write.

A usable destination is unnecessary on this path.

### Ordered three-word copy

For a non-null source, the represented access order is:

1. Read the second source word.
2. Read the third source word.
3. Read the first source word.
4. Write the first word to destination byte offset `0x78`.
5. Write the previously obtained second word to destination byte offset `0x7C`.
6. Write the previously obtained third word to destination byte offset `0x80`.

Each destination write preserves the complete corresponding 32-bit word. No numeric transformation or content validation occurs during the copy.

All source values are obtained before the first destination write. Consequently, ordinary overlap between the source record and these destination fields does not allow the copy’s own writes to replace a source value before it has been obtained.

This is an ordering property, not an atomic-snapshot guarantee. Concurrent mutation, device memory, and reads with side effects are not characterized.

### Global root evaluation and state-address read

After the destination writes, the function dereferences a global root reference. It then adds `0x30` to the resulting value and reads a 32-bit state address at the location selected by that expression.

The dereferenced root operand’s declaration is missing. Its width and type are not established by the body. The addition must therefore remain a **typed addition with unresolved units and scaling**:

- An appropriate integer-valued operand could make the addition an unscaled numeric address increment.
- A pointer-valued operand could make the addition advance by `0x30` elements of its pointed-to type.
- The supplied evidence does not select either interpretation or establish an element size.

Accordingly, the state-address read is not established to occur at a byte offset of `0x30` from a root address. The function performs the read after the unresolved addition; the location cannot be reduced further without the declaration.

This uncertainty is separate from overflow and address-representation uncertainty. Even an execution with no arithmetic overflow still requires the missing type to determine scaling.

The resulting 32-bit state address is retained for subsequent state-field accesses. The function does not repeat the global root lookup.

### Fresh middle-word read and character conversion

After obtaining the state address, the function rereads the 32-bit destination field at byte offset `0x7C` and converts that value to the target’s plain character type.

This is a fresh destination read, not a conversion of the previously saved second source word. Aliasing or external mutation can therefore affect the converted value.

The conversion depends on the target’s rules:

- A representable value retains its value.
- For an unsigned eight-bit plain character type, conversion produces the value modulo 256.
- For a signed plain character type and an unrepresentable input, the result or applicable signaling behavior is not resolved by the supplied body.

Low-eight-bit truncation is therefore conditional, not universal. The conversion also is not shown as a byte read from a particular position within the destination word.

### Initial state-field read and comparison

After conversion, the function reads a 32-bit address-bearing value from byte offset `0xF00` relative to the retained state address.

It then forms the comparison address by adding that value to a separate global-associated operand and reads one character there.

The comparison operand’s declaration is absent. It might identify an array address, a stored pointer, or another address-bearing value. The body does not establish:

- Whether evaluating it requires an additional memory read.
- Whether it is mutable.
- Whether the addition uses numeric address units or pointer-element scaling.
- The element size if pointer scaling applies.

Its evaluation belongs to the comparison expression, after the initial state-field read. If evaluation requires a memory read, that read must not be treated as having occurred before the destination writes or the initial state-field read.

The comparison tests equality between the loaded character and the converted destination character. It does not compare the complete 32-bit destination word.

### Equal comparison

If the characters are equal, the function returns.

At that point:

- All three destination writes have occurred.
- The global root expression has been evaluated.
- The 32-bit state address has been read.
- The middle destination field has been reread and converted.
- The state field at byte offset `0xF00` has been read once.
- Neither conditional byte write has occurred.

Equality does not suppress or undo the copy.

### Differing comparison

If the characters differ, the function performs these operations in order:

1. Write the converted character at byte offset `0xB52` from the initial state-field value.
2. Reread the 32-bit field at byte offset `0xF00` from the retained state address.
3. Write the one-byte value 1 at byte offset `0xB90` from the newly read value.

The first and final conditional writes need not use the same address-bearing value.

In particular, the first byte write may overlap the state field that is subsequently reread. The final destination must then be derived from the value read after that write, not automatically from the initial value. External mutation can also change the reread value; no synchronization protocol is shown.

The comparison address is not explicitly written. It can change through this function only if it aliases an actual write destination.

## Side effects

A non-null invocation that completes the copy performs three ordered 32-bit destination writes before any root lookup or comparison.

A mismatch additionally performs two ordered one-byte writes:

- The converted character at the initial-value-relative destination.
- The numeric value 1 at the reread-value-relative destination.

The first byte write is not unconditionally a write of the source middle word’s low eight bits. That interpretation requires an appropriate target conversion rule and a destination reread yielding the corresponding value.

One-byte writes do not explicitly replace adjacent bytes. If they overlap larger fields, their effect on those fields depends on byte order, layout, and aliasing.

No allocation, release, ownership transfer, callback, or explicit function call is shown. The source is not written through its own argument, but overlapping destination or conditional writes can modify its storage. The function neither acquires nor establishes ownership of supplied or globally reached memory.

### Errors and partial effects

Only a null source has explicit special handling. There is no reported error path for invalid addresses, misalignment, expired objects, or invalid arithmetic.

The operation is not transactional. Later failures do not undo earlier writes. For example:

- Failure while evaluating the root expression can follow all three destination writes.
- A conversion-related interruption can occur after the state-address read.
- Failure during the repeated state-field read can follow the first conditional byte write.
- Failure at the final destination can leave the first conditional byte write completed.

The evidence does not define platform fault handling or recovery. No rollback, locking, atomicity, or inter-thread ordering primitive is shown.

## Acceptance examples

These are conditional static acceptance examples, not executed tests. Unless varied explicitly, assume valid ordinary memory, valid arithmetic, stable non-overlapping storage, and target declarations that resolve the otherwise unknown address expressions.

### Null source

Given a null source and any destination argument:

- Return without dereferencing the destination.
- Do not evaluate the root or comparison-address expressions.
- Perform no writes.

The destination need not identify accessible storage.

### Equal representable character

Given source words `0x11223344`, `0x0000007E`, and `0x55667788`, and a comparison character with value 126:

- Copy the complete words to destination byte offsets `0x78`, `0x7C`, and `0x80`.
- Reread and convert the middle word to character value 126.
- Return without conditional byte writes.
- Read the state field at byte offset `0xF00` once.

This example assumes an ordinary eight-bit character type in which 126 is representable.

### Differing representable character

Given the same source words and a comparison character with value 32:

- Complete the same copy and middle-word conversion.
- Write character value 126 at byte offset `0xB52` from the initial state-field value.
- Reread the state field.
- Write one byte containing 1 at byte offset `0xB90` from that reread value.

No explicit write targets the comparison location.

### Conditional root scaling

Suppose the missing declaration makes the dereferenced root operand a pointer to four-byte elements. Under that stipulated declaration, adding `0x30` selects a location `0xC0` bytes beyond the pointer’s initial address, before the 32-bit state-address read.

If instead the missing declaration establishes an appropriate integer-valued address operand with unscaled addition, the increment can be `0x30` address units.

Neither outcome is unconditional. An implementation or specification that always substitutes a `0x30`-byte root displacement is not justified by the supplied body.

### Upper bits under a truncating conversion rule

Suppose the target establishes low-eight-bit conversion for both `0x0000007E` and `0xFFFFFF7E`.

For otherwise equivalent invocations:

- The complete middle destination words differ.
- Both conversions yield character value 126.
- Both select the same branch for an unchanged comparison character.

Without that target rule, the second conversion and branch remain unresolved.

### Overlapping source and destination

Suppose the source begins at destination byte offset `0x74` and initially contains words A, B, and C.

The destination fields at `0x78`, `0x7C`, and `0x80` receive A, B, and C. Writing A over the original location of B does not replace the already obtained B value.

### Mutable comparison operand

Suppose the missing declaration establishes that evaluation of the comparison operand reads a stored pointer, and a destination write changes that storage.

The comparison uses the operand evaluated after the initial state-field read, not a pointer cached before the copy. This example does not apply if the declaration instead establishes an array address with no stored-pointer read.

### State-field aliasing on mismatch

Suppose the first conditional byte destination overlaps the state field at byte offset `0xF00`.

The first write uses the initial field value. The repeated read then observes the field after that write, and the final destination uses the reread value. Its exact address depends on layout and byte order.
