# F-18cef3824d73

## Purpose

F-18cef3824d73 consumes a nibble-encoded numeric field from a bounded byte region and produces one unsigned 32-bit result.

The field supports decimal digits, a sticky negative marker, a fractional section, and a signed decimal exponent. A caller-supplied decimal adjustment is combined with the encoded exponent before the result is assembled.

The visible construction places an integer accumulator in the upper portion of the result and optionally combines it with a value obtained from a fractional conversion dependency. This suggests a fixed-point conversion, but the exact numeric representation is **inferred intent**, not an established contract: the fractional dependency’s behavior is unavailable, and its result is combined without a visible mask.

The function returns zero if it reaches the byte boundary while still needing input. Zero can also be a successful conversion result. There is no separate success indicator, error object, or consumed-length output.

## Interface

### Inputs

The function receives three inputs:

- **Starting address:** a byte pointer used as the position immediately before the first byte to parse. The function advances this address once before its first boundary check or byte read. The byte at the supplied address is not read.
- **Exclusive ending address:** a byte pointer against which each newly entered byte address is checked. A byte is readable only when its address is strictly below this ending address.
- **Decimal adjustment:** a signed integer added to any encoded exponent and subsequently used to control decimal scaling.

The recovered interface uses 8-bit bytes, 32-bit signed integer working values, and a 32-bit unsigned return value. Pointer width and the complete calling convention are not established by the supplied material.

### Input layout

Each consumed byte supplies two four-bit values, in this order:

1. High nibble.
2. Low nibble.

Parsing begins at the high nibble of the byte immediately following the starting address. A high-nibble terminator can finish conversion without consuming that byte’s low nibble.

The relevant nibble values are:

| Value | Meaning in the main digit section |
|---|---|
| 0–9 | Append a decimal integer digit |
| A | Enter fractional-digit scanning |
| B | Enter positive-exponent scanning |
| C | Enter negative-exponent scanning |
| D | Finish without an encoded exponent |
| E | Set the sticky negative flag and continue scanning |
| F | Finish without an encoded exponent |

These meanings are context-dependent. In particular, E is a sign marker only in the main digit section.

### Output

The only explicit output is an unsigned 32-bit word.

On successful completion, the function:

- Shifts the normalized integer accumulator left by 16 positions.
- Optionally combines that word with the complete return value of F-73d099a86adb using bitwise OR.
- Applies unsigned negation to the combined word if the sticky negative flag was set.

The function does not return the ending cursor, number of consumed nibbles, normalization count, or a validity flag.

## Behavior

### Initial state and first read

The function begins with:

- Integer accumulator equal to zero.
- Fractional accumulator equal to zero.
- Fractional scale equal to one.
- Negative flag clear.
- High nibble selected.

It advances past the supplied starting address. If the resulting address is at or beyond the exclusive ending address, it immediately returns zero without reading a byte.

Whenever parsing subsequently advances into another byte, the same boundary check occurs before that byte is read.

The visible implementation obtains each nibble through a byte dereference. It does not establish a single cached byte read shared by both nibble extractions. Consequently, stable input is a meaningful precondition; two nibble extractions from the same address should not be specified as observing one immutable snapshot.

### Main digit section

For each decimal nibble, the integer accumulator is multiplied by ten and the digit is added.

An E nibble sets the negative flag and otherwise contributes no digit. The flag is sticky:

- Repeated E markers do not toggle it.
- E can appear before or between main-section digits.
- Encountering E does not itself terminate the field.

A, B, C, D, or F leaves the main digit section. The subsequent behavior depends on which of these values was encountered.

There is no requirement for at least one integer digit. A field can proceed to termination, fractional scanning, or exponent scanning with the integer accumulator still zero.

### Fractional section

An A nibble starts fractional scanning at the immediately following nibble.

For each decimal fractional digit, the function compares the current fractional scale with an external threshold. If the comparison succeeds, it appends the digit to the fractional accumulator and multiplies the scale by ten. If the comparison fails, it consumes the digit but leaves both accumulator and scale unchanged.

Important consequences:

- The threshold is consulted during digit processing, not visibly copied once at entry.
- Acceptance is based on the scale **before** multiplication by ten.
- No rounding step is visible.
- Digits rejected by the threshold do not stop scanning.
- A long fractional section must still reach a nondecimal nibble; exhausting the byte region returns zero even if all later digits would have been discarded.
- The scale is not shown to be a decimal-digit count. It is an accumulated multiplier beginning at one.

The first nondecimal nibble ends fractional scanning and becomes the control value for the next phase:

- B starts positive-exponent scanning.
- C starts negative-exponent scanning.
- A, D, E, or F proceeds directly to normalization and result construction.

Thus, E encountered as the fractional terminator does **not** set the negative flag. A second A does not start another fractional section.

An empty fractional section is permitted by the visible control flow: the first nibble after A may already be nondecimal.

### Exponent section

B and C start exponent scanning. This can happen directly from the main digit section or after fractional scanning.

The exponent accumulator begins at zero. Every following decimal nibble is appended by multiplication by ten and addition. Unlike fractional digits, exponent digits have no visible threshold or precision limit.

The first nondecimal nibble terminates exponent scanning and is consumed. It is not reinterpreted as a sign, another exponent introducer, or another fractional introducer.

For C, the completed exponent accumulator is negated. For B, it is used without that negation. The resulting signed exponent is added to the caller’s decimal adjustment.

An empty exponent is accepted by the visible control flow. If the nibble immediately after B or C is nondecimal, the encoded exponent contributes zero.

A stream ending with exponent digits but no terminating nondecimal nibble fails at the boundary and returns zero. Reaching the boundary is not an implicit successful terminator.

### Decimal normalization

After any encoded exponent is incorporated, the effective adjustment determines normalization.

For a positive adjustment, each step:

1. Multiplies the integer accumulator by ten.
2. Multiplies the fractional accumulator by ten.
3. Reduces the adjustment by one.

The fractional scale is unchanged by positive normalization.

For a negative adjustment, each step:

1. Calls F-870c4fcf7295 with the current integer accumulator and the integer value ten.
2. Replaces the integer accumulator with that call’s result.
3. Multiplies the fractional scale by ten.
4. Increases the adjustment by one.

The fractional accumulator is unchanged by negative normalization.

These are sequential operations. The evidence does not justify replacing repeated dependency calls with a mathematically equivalent-looking division by a power of ten. The dependency’s treatment of signs, rounding, errors, and side effects is unknown.

No fractional-conversion call occurs until all normalization steps finish.

### Result construction

The normalized integer accumulator is shifted left by 16 positions and used to initialize the result word.

If the normalized fractional accumulator is nonzero, the function calls F-73d099a86adb with:

1. The normalized fractional accumulator.
2. The normalized fractional scale.

Its return value is ORed into the result.

If the fractional accumulator is zero, that dependency is not called. This includes a fractional section containing only retained zero digits, even when its scale has increased.

There is no visible mask limiting the dependency’s result to the low 16 bits. Any high bits returned by F-73d099a86adb participate in the OR operation.

Finally, if the negative flag is set, the whole unsigned result is negated modulo \(2^{32}\). Negation is applied after both result components have been combined, not separately to the integer and fractional accumulators.

The function then returns immediately. It does not inspect remaining nibbles or bytes.

### Width and arithmetic boundaries

The visible operations are finite-width operations, not arbitrary-precision decimal arithmetic. Potentially problematic operations include:

- Main-digit accumulation.
- Fractional-digit accumulation and scale growth.
- Exponent accumulation and exponent negation.
- Addition of the exponent to the caller’s adjustment.
- Positive normalization multiplications.
- Negative-normalization scale growth.
- The integer accumulator’s left shift.

The excerpt does not establish a portable overflow policy for signed arithmetic or all left-shift cases. A contract must therefore not silently promise saturation, rejection, or uniform modulo-\(2^{32}\) behavior for those operations.

The final negation is different: it operates on the unsigned result word, so its modulo-\(2^{32}\) interpretation is established by the recovered expression.

## Side effects

### Memory access

The visible body reads input bytes and reads an external fractional threshold. It contains no explicit writes to the input region and no explicit global-state writes.

Changing the local parsing address does not update a caller-owned cursor.

The function performs no visible allocation, deallocation, ownership transfer, or retention of the input pointer. Those observations apply to the visible body only; dependency internals are unavailable.

### Observable ordering

The established order is:

1. Advance to a new byte when required.
2. Check that address against the exclusive boundary.
3. Read and extract the selected nibble.
4. Update the relevant parsing state.
5. During fractional-digit handling, consult the threshold before any accepted accumulator and scale update.
6. After a terminator, complete normalization.
7. Perform fractional conversion if required.
8. Apply the sticky sign and return.

If parsing reaches the boundary before a terminating control nibble has completed the field, neither dependency has yet been called.

Unknown dependencies must not be assumed to preserve globals, avoid allocation, or avoid external side effects. In particular, negative normalization can make multiple ordered calls to F-870c4fcf7295.

### Errors and resource limits

The only explicit local failure path returns zero on input exhaustion.

There is no visible diagnostic for malformed control sequences, excessive digit counts, arithmetic overflow, an unsuitable threshold, or dependency failure. Many unusual control sequences are accepted through the context-sensitive rules above rather than rejected.

Execution time grows with the consumed nibble count and with the magnitude of the effective decimal adjustment. No visible limit caps normalization iterations.

## Acceptance examples

These examples use nibble sequences beginning at the first parsed nibble, after the skipped byte. They are conditional static expectations, not executed tests. Unless stated otherwise, assume zero caller adjustment, stable valid storage, and arithmetic within its established range.

1. **Integer-only field:** `1, 2, D` produces a normalized integer accumulator of 12 and no fractional call. The returned word is `0x000C0000`. Any remaining low nibble or later bytes are ignored.

2. **Sticky negative marker:** `E, 1, E, 2, D` produces the unsigned negation of `0x000C0000`, namely `0xFFF40000`. The second E does not cancel the first.

3. **Zero versus exhaustion:** `D` completes successfully with zero. A region with no first parsed byte also returns zero, but through the exhaustion path. The caller cannot distinguish these outcomes from the return value.

4. **No implicit end marker:** `1, 2` followed by the exclusive boundary returns zero, rather than the encoding of 12. The parser still requires another nibble.

5. **Fraction retention:** For `1, A, 2, 5, D`, if the threshold comparison accepts scales one and ten, the fractional call receives 25 and 100. The result is `0x00010000` ORed with that dependency’s return value. No exact fractional word is established independently of the dependency.

6. **Threshold-limited fraction:** For the same sequence, if the comparison accepts scale one but rejects scale ten, the fractional call receives 2 and 10. The digit 5 is still consumed. No rounding based on 5 is performed visibly.

7. **Context-sensitive E:** `1, A, E` completes without setting the negative flag. In contrast, `E, 1, A, D` retains the negative flag through fractional termination.

8. **Positive encoded exponent:** `1, 2, B, 2, D` adds two to the caller adjustment. With an initial adjustment of zero, the integer accumulator becomes 1200 and the result is `0x04B00000`.

9. **Negative encoded exponent:** `1, 2, C, 1, D` invokes F-870c4fcf7295 once with 12 and ten, then multiplies the fractional scale by ten. Only if the dependency returns one does the final result equal `0x00010000`.

10. **Consumed exponent terminator:** `1, B, E` has an empty exponent. E terminates exponent scanning and does not make the result negative.

11. **Caller adjustment participates:** `1, B, 2, D` with caller adjustment negative one has effective adjustment positive one, yielding an integer accumulator of ten before result assembly.

12. **Unmasked fractional contribution:** If fractional conversion returns `0x80000001`, both its high bit and low bit affect the result. A contract promising that only the low 16 bits are used would contradict the visible operation.

## Uncertainties

The following are **documented_only**, not resolved by assumption:

- Exact fractional threshold and its comparison semantics.
- Full contracts of both dependencies.
- Intended fixed-point format and numeric precision.
- Signed-overflow and exceptional left-shift behavior.

The integer and fractional accumulators are normalized separately. It is therefore unsafe to assert that negative adjustment preserves discarded integer remainders as fractional information. No such transfer is visible.
