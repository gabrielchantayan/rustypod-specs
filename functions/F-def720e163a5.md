# F-def720e163a5

## Purpose

F-def720e163a5 adapts a single dependency invocation into a three-value return-status interface while exporting a separate 32-bit working value.

Its established responsibilities are:

- Obtain two fields from a caller-supplied record.
- Initialize temporary 32-bit storage from a one-bit left shift of the first field.
- Invoke F-e70b426f24f7 with the second field, an opaque caller-supplied value, and the address of that temporary storage.
- Copy the temporary storage’s post-call contents to caller-supplied output storage.
- Normalize the dependency’s return status to 0, 1, or 3.

The meanings of the record, the shifted quantity, and the dependency statuses are not established. In particular, the shift does not establish that the quantity denotes a byte count, capacity, element count, or allocation size.

This contract describes static evidence only. No runtime tests have been performed.

## Behavior

### Preparation and field access

The function first reads the 32-bit integer at record offset 16. It shifts that value left by one bit and stores the result in temporary 32-bit storage.

This is not an evidenced widening operation. There is no visible wider intermediate intended to preserve an additional high bit, and no explicit overflow check, saturation, clamping, or rejection.

For nonnegative signed 32-bit inputs from 0 through 1,073,741,823, the shift agrees with mathematical multiplication by two and remains representable in a signed 32-bit integer. Negative inputs and larger positive inputs require qualification: the supplied source form alone is insufficient to establish a portable signed-language result. A target-level fixed-width shift may have a definite bit-pattern result, but this contract does not assume that interpretation without further evidence.

After initializing the temporary storage, the function obtains the 32-bit value at record offset 36 for the dependency call.

The established wrapper-level ordering is therefore:

1. Read the field at offset 16.
2. Initialize the temporary working value.
3. Read the field at offset 36.
4. Invoke the dependency.
5. After normal dependency return, write the working value to the output address.
6. Return the normalized status.

This ordering concerns the accesses and call visible in the supplied function. It does not establish synchronization, atomicity, or safe concurrent access.

### Dependency invocation

F-e70b426f24f7 is invoked once on the evidenced ordinary path, with these arguments in order:

1. The opaque 32-bit value read from record offset 36.
2. The caller’s opaque 32-bit argument, unchanged.
3. The address of the initialized temporary 32-bit working value.

The third argument provides access to storage whose initial contents are the shifted field value. The dependency’s implementation is unavailable. Its name, argument position, and writable address do not establish whether it treats the value as input, output, input/output, or something else.

The wrapper does not reload the field at offset 16 after the call. Consequently, changes to that record field during the dependency call do not independently cause the wrapper to recompute the working value.

The wrapper also does not reread the field at offset 36 after the call. Changes to that field during the call do not retroactively change the first argument already supplied.

### Post-call output

When F-e70b426f24f7 returns normally, the function copies the then-current 32-bit contents of the temporary working storage to the caller’s output address.

This copy occurs for every dependency status, including −24 and all other nonzero statuses. There is no success-only output rule and no wrapper rollback on a nonzero result.

If the dependency leaves the temporary value unchanged, the output receives the original shifted value. If the dependency changes it, the output receives that changed value. Neither behavior is assumed unconditionally.

### Status normalization

The dependency result determines the wrapper’s return status independently of the output contents:

- Exactly −24 becomes 1.
- Exactly 0 remains 0.
- Every other nonzero value becomes 3.

Thus, dependency status 1 becomes wrapper status 3, not wrapper status 1. Wrapper status 1 is reserved by this mapping for dependency status −24.

No retry, alternative dependency call, or error-reporting call is visible.

## Side effects

### Direct memory effects

The wrapper directly performs two record-field reads and one output write. It also initializes and exposes temporary storage to the dependency.

The output write happens after the dependency returns normally, even if its return status will be classified as 1 or 3.

No explicit record-field write occurs before the dependency call. However, the output address may alias the record. If it identifies a record field, the post-call output write modifies that field. The function contains no alias check and no separate preservation copy for the destination’s former contents.

For example, if the output address identifies the field at offset 16, that field is read to initialize the working value and is overwritten only after the dependency returns. If the output address identifies the field at offset 36, its original value is used as the dependency argument before the field is overwritten.

These examples require valid, appropriately aligned storage.

### Ownership and lifetime
