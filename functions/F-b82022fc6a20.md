# F-b82022fc6a20

## Purpose

F-b82022fc6a20 scans a bounded input region, processes slash-prefixed constructs, and conditionally populates parallel name and payload tables. On collection completion, it uses a dependency’s zero/nonzero result to choose whether to leave index zero unchanged, attempt an exchange with a remembered entry, or attempt insertion of a designated `.notdef` entry.

Interpreting those decisions as string equality and `.notdef` normalization is **inferred intent**, not an established dependency contract. The visible behavior establishes call arguments, return-value tests, and mutation order.

A nonzero state entry count suppresses collection at the points where that field is checked. It does not suppress scanning or payload extraction. Dependencies can change this field, so collection mode is not fixed at entry.

## Interface

The function receives a context address and a mutable state address. It has no direct return value.

The supplied representation uses 32-bit integers and address-bearing fields. Offsets are byte offsets; table address and length elements occupy four bytes. Signed comparisons are used for the context processing selector and the collection-index threshold.

## Behavior

### Entry and initialization

Before the initial callback, the function captures the resource handle, service-object address, input limit, and addresses of the embedded table objects. Later dependency changes to the original fields do not replace those captured values. Contents reachable through captured addresses are not established to remain unchanged.

The initial callback receives the state address. Its result becomes the retained sizing value.

1. A zero sizing value causes immediate return, before checking the error field.
2. Otherwise, a nonzero error field causes immediate return.
3. Otherwise, the state entry count is read.

A nonzero count skips initialization. A zero count causes sequential initialization calls through the captured service object:

1. Payload table, requested size equal to the sizing value plus six, captured resource handle.
2. Name table, the same requested size and handle.
3. Scratch table, requested size four, captured handle.

Each call must return zero before the next occurs. A nonzero result is written to the error field and terminates the function.

The sizing value is not checked for negativity. Addition of six has no visible overflow guard.

### Scanning and stop recognition

The local collected-entry count starts at zero, independently of the state count. The remembered-match flag also starts clear.

Each iteration invokes the scan/advance callback with the state address, then reads the current cursor. There is no immediate error-field check after this callback.

If the cursor is at or beyond the captured input limit, scanning ends.

Otherwise, stop recognition is attempted only if the address three bytes after the saved cursor is strictly below the captured limit. The byte at that address is passed to F-36b9d1fbbb1c. Only a nonzero result permits examination of the leading bytes:

- `end` stops scanning regardless of the local collected count.
- `def` stops scanning only if that count is nonzero.

The classifier is invoked before these leading-byte reads. Effects it has on input memory can therefore affect recognition. Its accepted byte set and high-bit character interpretation are unresolved.

A recognized stop skips the consume callback for that iteration. This function performs no explicit cursor update for the stop; dependencies may already have changed the cursor or other state.

If scanning does not stop, the consume callback receives the state address. The error field is then read. Nonzero causes immediate return without a local replacement status.

The function next reads the byte at the cursor address saved **before** consumption. This is not a saved byte value: changes to that memory during consumption can affect whether it is now `/`.

If that byte is not `/`, scanning repeats.

### Slash-prefixed constructs

For a slash at the saved address:

1. The following byte must lie strictly before the captured limit. Otherwise, status `3` is written and the function returns.
2. The name-start address is the saved address plus one.
3. The name length is computed from the current state cursor, read after consumption, minus the name-start address.
4. F-c6d4679527d4 receives the state and two output locations, subsequently used as payload length and payload address.

A zero result from F-c6d4679527d4 causes immediate return without a further local error assignment. The function does not separately check the error field after a nonzero result.

The state count is then reread. If nonzero, storage is skipped and scanning resumes. If zero, the entry is stored at the current local collected index. Consequently, dependencies can change later collection decisions even when initialization was skipped.

There is no visible validation that the post-consumption cursor follows the name start or that the computed name span is within the input limit.

### Name storage and match tracking

The name-table callback receives the embedded name-table address, local index, name-start address, and computed name length plus one.

A nonzero result is propagated to the error field and ends processing. On zero:

1. The name-address array is read.
2. The stored address at the local index is read.
3. A zero byte is written at that address plus the computed name length.

This explicit write requires valid writable storage independently of what the callback’s zero result means.

The byte at the original name-start address is then read. If it is `.`, F-opaque-01 receives the designated `.notdef` reference first and the stored name address second. A zero result sets the remembered-match flag and records the current index. Later zero results replace the remembered index; no duplicate rejection is visible.

The source does not establish that F-opaque-01 implements string equality. Mechanically, a leading dot and its zero result are sufficient to record a match.

### Payload storage

The context field at `0xA8` is read after name processing.

The direct path applies if that signed value is negative, or if the signed local index is at least the retained sizing value plus five. The payload-table callback then receives four explicit arguments:

- Embedded payload-table address.
- Local index.
- Payload address supplied by extraction.
- Payload length supplied by extraction.

Otherwise, the temporary-storage path executes:

1. F-3ce007b692cc receives the captured resource handle, payload length, and a status-output address. Its direct result is retained as a temporary address.
2. A nonzero output status is written to the error field, followed by return.
3. F-opaque-02 receives the temporary address, extracted payload address, and payload length, in that order. Its return value is not tested.
4. **G-01 is read after F-opaque-02 returns.** An indirect service call at captured service-object offset `0x10` receives the temporary address, payload length, and that global value. Its return value is not tested.
5. The context field at `0xA8` is reread and subtracted from the local payload length.
6. The payload-table callback receives three explicit arguments: table address, local index, and temporary address plus another read of context offset `0xA8`.
7. F-bf7242c98d06 receives the captured resource handle and the original temporary address.
8. The retained payload-table status is checked.

The adjusted length is computed, but the supplied representation shows no fourth explicit argument carrying it on this path. A contract cannot supply that missing argument.

F-opaque-02 resembles a copy operation by its arguments, but copying is not established. Likewise, no deallocation, invalidation, or ownership-transfer semantics are established for F-bf7242c98d06.

A nonzero payload-table status is propagated after the latter call. Zero increments the local collected count and resumes scanning. A name may therefore already have been written when payload processing fails.

### Completion decision

When scanning ends, the state count is reread. Nonzero causes return without normalization.

Otherwise, the local collected count is written to the state count. The function then reads name-address element zero and invokes F-opaque-01 with the designated `.notdef` reference first and that address second.

There is no zero-entry guard before this first-element access.

The branch matrix is:

| Final F-opaque-01 result | Remembered-match flag | Action |
|---|---|---|
| Zero | Set | Return. |
| Nonzero | Set | Attempt exchange. |
| Zero or nonzero | Clear | Attempt insertion. |

Thus insertion does not depend solely on a nonzero final comparison-like result. A zero result with no recorded match also reaches insertion.

| 2 | Scratch slot 1 | Payload address and length at index zero. |
| 3 | Scratch slot 2 | Name address and length at the remembered index. |
| 4 | Scratch slot 3 | Payload address and length at the remembered index. |

Array bases and source elements are read for their respective operations, not captured together before the sequence. Callback changes to those arrays can affect later arguments.

On complete success, the function returns without another count assignment. On failure, it writes the failing status. Actual preservation and exchange of bytes depend on the callbacks’ contracts.

### Insertion attempt

After the final F-opaque-01 call, and before any insertion-path scratch write, the function reads **G-02 and then G-03** into adjacent local 32-bit storage units.

These are unresolved global reads, not established immutable constants. Earlier dependencies, including the final comparison-like call, may have modified them.

The function then attempts six writes, each gated by the preceding zero status:

1. Scratch slot zero receives the first name’s current address and length.
2. Scratch slot one receives the first payload’s current address and length.
3. Name index zero receives the designated `.notdef` reference and length eight.
4. Payload index zero receives the address of the first local storage unit and length five.
5. Name at the local collected index receives scratch slot zero’s address and length.
6. Payload at that index receives scratch slot one’s address and length.

The five-byte payload is sourced from local storage initialized by the two global reads. Under the displayed adjacent-word layout, it spans the first four-byte unit and the first addressed byte of the second. Exact bytes and byte order are not established.

Only after all six statuses are zero does the function write the local collected count plus one to the state count. Failure publishes the failing status without rollback.

## Side effects

Direct effects include table-operation calls, explicit name-terminator writes, count assignments, and selected error-field assignments. Dependencies can additionally alter cursors, input bytes, tables, context, globals, or other shared state.

Failures do not undo earlier initialization, name storage, scratch writes, exchange writes, or insertion writes. The count is published before normalization begins; insertion adds one only after complete callback success.

F-bf7242c98d06 is called after temporary-path payload insertion and before checking its retained status, including when insertion reports failure. Its effect on storage lifetime is unknown. If it invalidates storage while a table retains the supplied address, that retention would create a lifetime risk; neither condition is established here.

The function passes local storage as an insertion payload source. Safe retention after return would require a suitable callback ownership contract. No such contract is supplied.

## Acceptance examples

These are conditional static expectations, not executed tests.

1. **Disabled entry:** If the initial callback returns zero, this function performs no initialization or scanning, regardless of the resulting error field.

2. **Initialization failure:** If payload-table initialization returns nonzero, that status is published. Name and scratch initialization are skipped.

3. **Immediate stop:** If scanning exposes `end` and its in-bounds fourth byte yields a nonzero classifier result, consumption is skipped. With state count zero, completion still attempts first-element access even when no entry was collected.

4. **Leading `def`:** With local collected count zero, `def` does not stop scanning. After a successful local entry increment, the same token can stop scanning if the classifier condition holds.

5. **Consumption changes the slash:** If consumption changes the byte at the saved cursor from `/` to another value, slash processing is skipped, assuming no intervening mutation changes it back.

6. **Trailing slash:** If consumption leaves a slash at the saved cursor but its following address is not below the captured limit, status `3` is written and extraction is not called.

7. **Mechanical match:** A leading-dot name whose F-opaque-01 call returns zero is remembered even without independently established string-equality semantics.

8. **Temporary-path ordering:** If its status output is zero, F-opaque-02 is called before G-01 is read. The payload callback precedes F-bf7242c98d06, and its retained status is checked afterward.

9. **Exchange selection:** A set remembered flag and nonzero final F-opaque-01 result select the eight-write exchange attempt. If callbacks implement stable value storage and all return zero, the indicated name/payload pairs exchange positions.

10. **Insertion data:** With no remembered match, insertion is selected even if the final F-opaque-01 result is zero. G-02 and G-03 are read in order before scratch writes; their local representations supply the five-byte payload argument.

11. **Partial failure:** A normalization callback failure publishes its status without reversing earlier writes. No final insertion count increment occurs unless all six insertion writes succeed.
