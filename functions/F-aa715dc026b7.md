# F-aa715dc026b7

## Purpose

F-aa715dc026b7 selects an entry from a fixed-stride table using an unsigned threshold comparison. It returns the zero-based index of the **first** entry whose comparison field is greater than or equal to the supplied value, provided that entry’s separate status field is nonzero.

The function returns −1 if the initial control field is zero, its dependency returns a negative result, no entry qualifies, or the first qualifying entry has a zero status field. In particular, a zero-status qualifying entry terminates the search: later entries are not considered.

The established behavior is an ordered scan, not a search for the smallest qualifying comparison value. Sorted comparison fields are not required for the observed selection rule.

## Behavior

### Initial gate

The function first reads the control field at byte offset 0.

If that value is zero, the function returns −1 immediately. It does not call F-766473d455b3 and does not directly read the table-address field or any table entry.

### Dependency call and result

After a nonzero initial control value, the function calls F-766473d455b3 with the same control reference.

Its signed result determines the subsequent scan:

- A negative result causes an immediate return of −1.
- Zero causes no entry accesses and a return of −1.
- A positive result establishes the number of entry indices considered by the scan.

The interpretation of this result as an entry count is inferred from its use as an exclusive loop bound. The dependency’s actual purpose and guarantees are unknown.

The original control field is not rechecked after the call. Consequently, a dependency change to that field does not introduce another gate in this function. Table-address reads occur after the dependency returns, so a table-address change made by the dependency can affect the scan.

### Ordered scan

For a positive dependency result, entries are considered in ascending index order, starting at index 0 and ending before the returned count.

For each reached entry:

1. The function reads the table-address field and obtains that entry’s unsigned comparison field at entry offset 20.
2. If the comparison field is less than the requested value, the entry is skipped. Its status field is not read.
3. Otherwise, the entry is the first qualifying entry. The function reads the table-address field again to address its status field at entry offset 4.
4. A zero status produces −1 immediately. A nonzero status produces the current index immediately.

No entries after the first qualifying entry are examined, regardless of its status.

If every considered comparison field is less than the requested value, the function returns −1 after exhausting the scan.

These steps describe the access order expressed by the supplied source representation. They do not establish a machine-instruction trace, volatile access semantics, or synchronization guarantees.

### Comparison semantics

**requested value ≤ entry comparison field**

Equality therefore qualifies.

Under the 32-bit model, values range from 0 through 4,294,967,295. A comparison field with its high bit set is a large unsigned value, not a negative threshold.

A requested value of zero qualifies at the first entry whenever the count is positive and that comparison-field read is valid. The result then depends only on that entry’s status. A requested value of 4,294,967,295 qualifies only against the same maximum comparison value.
