# F-02d4df4402f0

## Purpose

F-02d4df4402f0 makes two indirect calls, interleaves them with seven explicit word stores, and then enters an unconditional infinite loop.

The established behavior consists of unsigned shifts, address calculations, writes through incoming implicit state, and a final write whose address and data depend on a global word associated with address `0x0000003C`. No supported higher-level purpose—such as allocation, initialization, registration, or shutdown—is established.

There is no visible normal return. Reaching the terminal loop requires both dependencies to return and all preceding operations to complete. Dependency nontermination, invalid execution targets, memory faults, and other environment-dependent failures may prevent that outcome.

## Behavior

### Derived unsigned values

Three quantities are used repeatedly:

- **Third-quarter:** the third argument logically shifted right by two bits.
- **Third-sixteenth:** the third argument logically shifted right by four bits.
- **Fourth-quarter:** the fourth argument logically shifted right by two bits.

These are unsigned truncating divisions by four, sixteen, and four, respectively. Discarded low bits are not retained or used for rounding.

For a 32-bit unsigned third argument, third-quarter ranges from zero through `0x3FFFFFFF`; third-sixteenth ranges from zero through `0x0FFFFFFF`. Shifting third-quarter right by two more bits equals third-sixteenth.

The first dependency receives the original fourth argument, not fourth-quarter.

### Ordered interactions

The following order is established for the explicit calls and stores. Effects performed inside either dependency occur during its invocation and may affect later operations.

1. **Call F-000000000001.**

   Its target is the incoming control-address value plus byte offset `0x448`.

   The two explicit arguments, in order, are:

   - Original fourth argument.
   - Third-quarter.

   The returned value is represented as a signed 32-bit integer. It is subsequently used as an address base, stored as a word, and shifted for the second call.

2. **Store the auxiliary displacement at a displaced auxiliary address.**

   The destination is the auxiliary word pointer plus the auxiliary displacement in bytes. The stored word is the displacement’s 32-bit representation.

   A negative displacement is not visibly rejected. Its interpretation requires valid address arithmetic and an accessible resulting destination.

3. **Store the first result through its own derived address.**

   At the first dependency result plus `0x18`, store the first result as a 32-bit word.

4. **Store the auxiliary pointer at the fourth-quarter/base address.**

   Add fourth-quarter to the auxiliary address base, then store the auxiliary word pointer at that address.

   Fourth-quarter is used directly as an address contribution; it is not multiplied back by four.

   Under the recovered 32-bit integer types, this particular addition combines unsigned and signed operands and consequently uses unsigned 32-bit arithmetic. The auxiliary base is converted to its unsigned representation, and the addition is modulo \(2^{32}\). A resulting numeric address is not thereby guaranteed to be a valid pointer.

5. **Store fourth-quarter through another address derived from it.**

   At fourth-quarter plus `0x18`, store fourth-quarter as a 32-bit word.

   This destination does not include the auxiliary address base from the preceding store. The addition itself cannot overflow a 32-bit unsigned value because fourth-quarter is at most `0x3FFFFFFF`.

6. **Call F-000000000002.**

   The visible target calculation adds `0x1B0` to `0x08911367`, yielding `0x08911517`.

   The four explicit arguments, in order, are:

   - Third-sixteenth.
   - First dependency result shifted left by two bits.
   - Third-quarter.
   - Third-sixteenth again.

   The first and fourth arguments are equal.

   The first dependency result is represented as signed. Consequently, an unconditional unsigned wrapping multiplication-by-four rule is not established for the second argument. Nonnegative results no greater than `0x1FFFFFFF` provide a range in which the shifted result is representable as a signed 32-bit integer. Behavior outside that range remains qualified by the recovered signed expression and the unknown machine-level semantics.

   The second dependency returns a value represented as a signed 32-bit integer, subsequently used as an address base.

7. **Store third-quarter directly at the auxiliary word pointer.**

   This store occurs after the second dependency returns. It is required even when its data equals the word already present.

   If the auxiliary displacement is zero, this destination is the same as the destination of the first explicit store.

8. **Store third-sixteenth through the second result.**

   At the second dependency result plus `0x3C`, store third-quarter shifted logically right by two additional bits. For the unsigned third argument, this equals third-sixteenth.

9. **Perform the global-derived store.**

   Access the global word associated with address `0x0000003C`. Use its value as an address base, add `0x18`, and store the global word at the resulting address.

   This operation occurs after both calls and the preceding six stores. The global must not be treated as an entry-time snapshot: dependency effects or earlier explicit stores may have changed it.

   The recovered expression refers to the global for both destination formation and stored data. It does not establish the number or instruction-level ordering of physical loads. If the global changes during this operation, a single shared snapshot for address and data is not proven.

10. **Enter the unconditional terminal loop.**

    No additional explicit call, memory access, return, or exit appears in the loop.

    This establishes divergence if execution reaches the loop and remains under the function’s control. It does not establish sleeping, yielding, synchronization, or a device-wait protocol.

### Aliasing and final contents

Destinations are not visibly checked for overlap. Later writes may overwrite earlier writes, including writes to the global word itself.

A store’s occurrence and its position in the sequence are separate from the eventual contents of its destination. In particular, the direct auxiliary-pointer store in step 7 does not establish that location’s final value: either following store may alias it, and external mutation remains unspecified.

Equal data also does not eliminate a required store. If the third argument is less than four, third-quarter is zero, so the zero-displacement case includes two explicit stores of zero to the same address, separated by other operations.

## Side effects

There is no explicit allocation, deallocation, ownership-transfer protocol, reference-count operation, error report, or cleanup. This absence says nothing about whether either dependency performs such actions.

There is no visible rollback:

No synchronization, atomicity, or inter-agent visibility guarantee is established. Word-sized accesses do not by themselves prove atomicity, particularly for unaligned or special-memory addresses.

### Zero displacement requires an ordered store, not a particular final value

With auxiliary displacement zero, the first explicit store writes zero directly at the auxiliary word pointer. After the second dependency returns, the fifth explicit store writes third-quarter to that same address.

Acceptance requires both stores in that order. Final contents alone cannot establish whether the sequence occurred.

Two relevant cases:

- If the third argument is `3`, third-quarter is zero. The fifth store also writes zero. Observing zero afterward is compatible with the required sequence.
- If the third argument is `0x40`, the fifth store writes `0x10`. Zero afterward contradicts that value only if subsequent aliasing, external mutation, and other intervening effects are excluded.

For example, using the distinct-destination values above but changing the displacement to zero leaves `0x10` at `0x3000` after the explicit sequence, provided no later external mutation occurs.

### A subsequent visible store can replace the direct-pointer value

Assume the auxiliary pointer is `0x3000`, the displacement is zero, and the third argument is `0x40`.

The first store writes zero at `0x3000`; the fifth writes `0x10` there.

If the second dependency returns `0x2FC4`, its result plus `0x3C` is `0x3000`. The sixth store therefore writes `0x4` to the same location.

If the final store targets elsewhere and no other mutation occurs, the resulting word at `0x3000` is `0x4`, despite the required earlier store of `0x10`.

### Small fourth argument

If the fourth argument is `3`, fourth-quarter is zero.

The pointer-publication store targets the auxiliary address base. The following store writes zero at address `0x18`.

There is no visible branch avoiding that low-address access. Later operations are reached only if the access completes.

### Earlier store changes the global-derived destination

Assume the third argument is `0x40`, the second dependency returns zero, and the relevant low addresses are writable.

The sixth store writes `0x4` at address `0x0000003C`. If nothing changes the global before or during its final use, the seventh store writes `0x4` at address `0x1C`.

Using the global’s entry-time value instead would not match this sequence.

### Dependency nonreturn

If F-000000000001 never returns, no explicit store is reached.

If F-000000000002 never returns, exactly the first four explicit stores have been reached; the remaining three stores and terminal loop have not. Dependency-internal effects remain unconstrained.
