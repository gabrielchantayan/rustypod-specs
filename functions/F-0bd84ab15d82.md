## Behavior

### Initial reads and field writes

The function first reads a 32-bit initialization value from an external location. It then performs the following explicit writes and external read in order:

1. Writes the first boundary at offset 4.
2. Writes the previously read initialization value at offset 0.
3. Writes the second boundary at offset 8.
4. Reads an external table-base value.
5. Writes the associated value at offset 16.
6. Writes the original input flags at offset 12.

This order matters if the destination aliases either external location or table storage. The initialization value has already been captured before the first destination write. The table-base value is captured after the writes at offsets 4, 0, and 8, but before those at offsets 16 and 12.

No non-aliasing guarantee is established. Consequently, field writes can affect subsequently read table contents if the caller arranges overlapping storage.

### Table-driven descriptor calculation

The table base identifies two adjacent sequences of five 32-bit words:

- Five mask words at relative offsets 0, 4, 8, 12, and 16.
- Five descriptor words at relative offsets 20, 24, 28, 32, and 36.

The function processes corresponding mask-and-descriptor pairs in descending index order: 4, 3, 2, 1, then 0. For example, the first pair consists of the mask at relative offset 16 and, conditionally, the descriptor at relative offset 36.

The calculation begins with:

- A working flag value equal to the original input flags.
- An accumulated descriptor equal to zero.

At each of the five positions, the mask is read and tested against the **current working flag value**, not necessarily the original flags.

If their bitwise intersection is zero:

- The corresponding descriptor word is not explicitly read.
- Neither the working flags nor the accumulated descriptor is changed for that position.

If their bitwise intersection is nonzero:

- The corresponding descriptor word is read.
- The working flags are logically shifted right using the low eight bits of that descriptor as the shift operand.
- The entire 32-bit descriptor is bitwise-ORed into the accumulated descriptor.

The updated working flags are used for subsequent, lower-index mask tests. Earlier matches can therefore enable or disable later matches by changing which flag bits remain and where they are positioned.

The accumulated descriptor is a bitwise OR of all selected descriptor words. It is not their sum, the number of selected entries, or necessarily the total effective shift applied to the working flags. Descriptor bits above bit 7 contribute to the stored accumulated descriptor even though each individual shift uses only the descriptor’s low byte.

After all five positions have been processed, the accumulated descriptor is written at destination offset 20. The original flags stored at offset 12 are not explicitly replaced with the shifted working flags.

### Count calculation and remaining initialization

The element-count calculation uses the difference between the second and first boundaries, converted to a 32-bit unsigned value, then logically shifted right using the low eight bits of the accumulated descriptor.

For differences that are representable as signed 32-bit integers, the supplied representation establishes the subtraction followed by unsigned conversion. A negative representable difference therefore becomes a large unsigned value before the right shift. There is no explicit clamp to zero.

The evidence does not establish the result of signed subtraction overflow or the target’s behavior for shift operands of 32 or greater. Those cases require additional execution-model evidence.

After calculating the count, the function performs these writes in order:

1. Writes zero at offset 28.
2. Writes the computed count at offset 24.
3. Writes zero at offset 32.
4. Writes zero at offset 36.
5. Writes one zero byte at offset 40.

Thus the resource-result field is cleared before the count is published. The byte write at offset 40 does not establish that the following three bytes are cleared.

### Resource request and final delegation

### Selected shifts affect later selection

The first match changes the working flags from 8 to 4. The next mask therefore also matches, changing the working flags from 4 to 1.

This example distinguishes current-working-value tests from tests against the original flags.

### Descriptor accumulation is not addition

Both positions match. The working flags undergo two successive one-bit right shifts, but the accumulated descriptor is 1, not 2.
