# F-659492938155

## Purpose

F-659492938155 constructs a 32-bit unsigned value from four input bytes and conditionally sets selected bits according to the result of F-1cb585febd84.

The first input byte occupies the most significant eight bits of the constructed value; the fourth occupies the least significant eight bits. A dependency result of 1, 2, or 3 causes bit 5 to be set in a decreasing number of low-order byte positions. A dependency result of 4 leaves the constructed value unchanged. Any other dependency result causes the function to return zero.

This is a byte-packing and conditional bit-setting contract. No character encoding, text interpretation, validation scheme, or domain-specific meaning for the bytes is established. In particular, interpreting the operation as character case conversion would require evidence not present here.

## Behavior

### 1. Read and assemble the input bytes

The function obtains the bytes at offsets 0, 1, 2, and 3 from the second input and constructs P.

Their layout in P is:

| Input location | Result bits |
|---|---|
| Offset 0 | 31 through 24 |
| Offset 1 | 23 through 16 |
| Offset 2 | 15 through 8 |
| Offset 3 | 7 through 0 |

Each byte is treated as unsigned before being placed in the 32-bit value. There is no sign extension from a byte whose most significant bit is set.

The layout is big-endian in significance: the lowest-addressed byte contributes the highest-order byte of the result. This describes the numerical packing rule, not the native byte order of the execution platform. No storage of the resulting word back into memory is shown.

All four byte values needed for P are obtained before the dependency call. The source does not establish a relative evaluation order among those four reads. A conforming description therefore must not promise that offsets are read in ascending or descending order.

### 2. Invoke the dependency

The returned integer selects the subsequent behavior. No visible operation rereads the input bytes after this call.

The dependency is not called before input access, and it is not skipped for any particular set of byte values. Subject to valid input access and normal execution, it is called even when P is zero or already has every potentially affected bit set.

### 3. Select the result

The returned dependency value determines the output as follows:

| Dependency result | Mask | Function result |
|---|---:|---|
| 1 | `0x00202020` | P bitwise OR mask |
| 2 | `0x00002020` | P bitwise OR mask |
| 3 | `0x00000020` | P bitwise OR mask |
| 4 | No modification | P |
| Any other integer | Not applicable | `0x00000000` |

The masks set bit 5 within selected byte positions:

- Result 1 affects the bytes originating at offsets 1, 2, and 3.
- Result 2 affects the bytes originating at offsets 2 and 3.
- Result 3 affects only the byte originating at offset 3.
- Result 4 affects no bytes.

The byte originating at offset 0 is never modified by an accepted selector.

These operations set bits; they do not toggle bits, clear bits, or perform addition. A targeted bit already equal to one remains one. There is no carry into a neighboring bit or byte.

Selection depends only on exact equality with 1, 2, 3, or 4. Negative dependency results and positive results outside that set take the zero-return path.

### 4. Return

After selection, the function returns the corresponding unsigned 32-bit value.

Zero is not a unique failure indicator. It is also a legitimate result when all four input bytes are zero and the dependency returns 4. The function exposes no separate status output to distinguish those cases.
