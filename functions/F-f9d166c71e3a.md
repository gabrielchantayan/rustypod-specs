# F-f9d166c71e3a

## Purpose

F-f9d166c71e3a performs an ordered sequence of dependency calls and memory writes using a caller-supplied region and addressable copies of four input words. It returns a 64-bit value formed from the final contents of the first two copies.

The supplied static representation establishes access widths, offsets, branch conditions, explicit call ordering, and return construction. It does not establish an application-level object type or the meanings of the fields. Initialization or reconfiguration is inferred intent, not a required semantic interpretation.

The operation is not transactional. Calls and writes occur before later decisions, and no rollback path is shown.

## Behavior

The following sequence describes explicit operations in the supplied static representation. A stated store establishes the value at that point, not an invariant that unknown dependencies must preserve.

### 1. Capture a base, initialize local copies, then reread the global base

The function first reads an initialization-base global and saves its 32-bit value.

It then initializes the four local argument copies, in input order.

For the first F-438680ffebfe call, it independently reads the same initialization-base global again. It reads the 32-bit word at offset `+4` through this second base value and supplies that word to the call.

These are two distinct global-base reads:

- The earlier captured base is retained for later calls.
- The reread base is used for the first call’s offset-`+4` read.

No dependency call intervenes between the two base reads. Nevertheless, equality of their values is not an established invariant. The contract must not replace the reread with the earlier capture.

### 2. Perform three unconditional initialization calls

F-438680ffebfe is called in this order:

1. With caller-region address `+0x6C` and the 32-bit word read at offset `+4` through the independently reread base.
2. With caller-region address `+0x7C` and a fresh 32-bit read at offset `+4` through the earlier captured base.
3. With caller-region address `+0xA4` and another 32-bit read at offset `+4` through that captured base.

The second and third calls do not reread the initialization-base global. Their offset-`+4` contents are read separately rather than cached.

Consequently, two distinctions matter:

- A change to the global base does not redirect the second or third call’s explicit reads.
- A change to the contents at the captured base’s offset `+4` can affect a later call.

The first call may therefore read from a different base than the second and third calls.

### 3. Initialize and inspect the field around `+0x74`

F-151ab4bfe553 receives the caller-region address `+0x74` and a 32-bit value read from a separate global.

After that call returns, the function reads the 32-bit word at caller-region offset `+0x78` and passes it to F-d8cbf9aa79a9. The dependency’s represented 32-bit result is tested for equality to zero.

For a zero result, the sequence is:

1. Store 32-bit `1` at `+0x9C`.
2. Call F-438680ffebfe with address `+0x74` and a fresh 32-bit read from offset `+4` through the earlier captured base.
3. Store 32-bit `0` at `+0x98`.

For a nonzero result, the sequence is:

1. Store 32-bit `1` at `+0x98`.
2. Store 32-bit `0` at `+0x9C`.

Thus, the optional fourth F-438680ffebfe call uses the earlier captured base, not a new global-base read.

In the zero branch, that call occurs between the two stores. It may observe `+0x9C` already set to one while `+0x98` still contains its previous value. Moving the latter store before the call would change the established ordering.

### 4. Store common state and inspect one global byte

## Side effects

The function does not explicitly write the word at `+0x78` or any global location it reads. This does not imply those locations remain unchanged: they may alias other written memory or be modified by dependencies.

Branch stores establish complementary values at `+0x98` and `+0x9C` at their respective store points. Without dependency-preservation guarantees, those values are not unconditional postconditions at return.

## Acceptance examples

These are conditional criteria derived from static evidence, not runtime results.

1. **Distinct initial base reads.** Suppose the first global-base read yields address A, the independent reread yields address B, and their offset-`+4` words are respectively `7` and `11`. With those words otherwise unchanged, the first F-438680ffebfe call receives `11`; the second and third receive `7`. The optional fourth call also reads through A. Treating the first call as using A is incorrect.

2. **Fresh reads through the capture.** Suppose both initial base reads yield A. The first call receives `7` and changes A’s offset-`+4` word to `9`. If that word remains unchanged afterward, the second and third calls receive `9`. A later change to the global base alone does not redirect these reads.

3. **Zero inspection result.** If F-d8cbf9aa79a9 returns zero, the trace contains the `+0x9C` store of one, the additional F-438680ffebfe call, and then the `+0x98` store of zero, in that order.

4. **Nonzero inspection result.** Any nonzero 32-bit result, including `0x80000000`, selects the other branch: store one at `+0x98`, then zero at `+0x9C`, without the additional call.

5. **Low-byte decision.** A first local copy of `0x12345600` at the late test produces direct zero stores at `+0xB4` and `+0xB8`. A value of `0x12345601` produces direct one stores. The original region base remains the address source in both cases.

6. **Final-call mutation.** If the final first and second copies are `0x11223344` and `0xAABBCCDD`, the return is `0xAABBCCDD11223344`. A modification by F-289ec4311c64 must be reflected in these final values.

7. **Byte-store extent.** In the absence of other writes, the store at `+0x94` leaves bytes `+0x95` through `+0x97` unchanged. The store at `+0xB8` likewise leaves subsequent bytes unchanged.

8. **Transient state.** If no intervening effect changes `+0xB4`, a dependency between its provisional store and late replacement can observe `3`. A contract exposing only final zero/one stores would omit this state.
