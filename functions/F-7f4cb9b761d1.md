# F-7f4cb9b761d1

The established behavior is a fixed-layout memory update. The supplied value and source words are transferred without visible arithmetic, validation, interpretation, or conversion. The initial destination write precedes every source read. Consequently, overlapping source and destination regions can affect the values transferred. The function must not be specified as taking a snapshot of the source before making any destination changes.

## Behavior

### Access ordering

The supplied static representation establishes the following logical memory-access order:

1. Write the supplied 32-bit value to destination offset `0x1C`.
2. Read the source word at byte offset 4.
3. Read the source word at byte offset 8.
4. Read the source word at byte offset 12.
5. Read the source word at byte offset 0.
6. Write that last-read word to destination offset `0x34`.
7. Write the previously read word from source offset 4 to destination offset `0x38`.
8. Write the previously read word from source offset 8 to destination offset `0x3C`.
9. Write the previously read word from source offset 12 to destination offset `0x40`.
10. Return without a value.

This is the logical ordering represented by the evidence. It is not an independently verified machine-level, bus-level, or concurrent-observer ordering guarantee.

All four source values are obtained before the first write to the four-word destination block. Thus, overlap with that block does not cause its later stores to replace source values that the represented operation still needs to read.

The separate write at destination offset `0x1C` is different: it occurs before source acquisition. If that write overlaps source storage, the transferred values reflect the source state after the write, subject to the environment’s access semantics.
