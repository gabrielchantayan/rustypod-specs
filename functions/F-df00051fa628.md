# F-df00051fa628

## Purpose

F-df00051fa628 repeatedly performs an ordered sequence of indirect calls, memory reads, memory writes, and a software breakpoint. Returned values and additional register outputs supply data, addresses, and address components.

The established contract is this sequence and its data dependencies. An application-level purpose, record format, protocol, or completion condition is not established.

There is no visible normal return or loop-exit condition. A completed iteration immediately begins another iteration. Progress requires the dependencies to return, memory accesses to succeed, and execution to continue past the breakpoint.

## Interface

### Explicit and implicit inputs

The supplied representation declares no explicit parameters and no return value. This does not establish a machine-level interface without inputs.

The body consumes:

- **Link state:** an incoming 32-bit address-like value used to form the first call target.
- **Working base:** register-held state used for several 32-bit memory accesses and explicitly reduced by `0xF4` during each iteration reaching that update.
- **Auxiliary base:** incoming register-held state contributing to a late byte-store address.
- **Primary root:** a 32-bit global value captured before the first two byte stores.
- **Secondary root:** a separate 32-bit global value captured after the breakpoint.
- **Fixed-region contents:** memory addressed using the literal `0x21C48960`.
- **Dependency outputs:** ordinary return values and additional register outputs.

“Root,” “base,” “selector,” and “record” below are descriptive labels, not established object types. No ownership, allocation, validity, or lifetime follows from these names.

### Widths and arithmetic

The representation distinguishes:

| Quantity or access | Width |
|---|---:|
| Byte data and accesses | 8 bits |
| Halfword data and accesses | 16 bits |
| Word data, address components, and pointer-like values | 32 bits |

A 64-bit result is divided into its low and high 32-bit halves. This division is numeric; it does not establish memory endianness.

Unsigned halfword reads are zero-extended. A halfword store writes the low 16 bits of its source. A byte store writes eight bits. The payload halfword described below is widened to a full 32-bit unsigned value for two word stores.

The low half of the first retained 64-bit result undergoes explicitly unsigned 32-bit shifts: right by 26 and left by two. The latter retains the low 32 bits of the shifted result.

Other calculations include signed-looking 32-bit additions, left shifts, and multiplications in the supplied representation. Their behavior outside representable ranges is **documented_only**: the representation does not establish a portable overflow model. ## Behavior

Dependencies use opaque call-site IDs **F-000000000001** through **F-000000000037**, abbreviated **D01–D37**. Call-site IDs remain distinct even where their target addresses are equal. The target relationships are specified under Dependencies.

“No explicit arguments” means none are shown in the supplied representation. It does not exclude implicit register or memory inputs.

### Initial calls and primary-root writes

A zero byte intended for a later primary-root write is established before D01. D01 receives two explicit zero arguments. Its target initially depends on incoming link state.

After D01 returns, a separate zero byte is established as the final contribution to D06’s second argument. D02 and D03 execute, in that order, without explicit arguments.

The primary root is then read and retained. D04 executes, followed by D05, which produces a 64-bit result. D06 receives:

- First argument: the result’s low 32 bits.
- Second argument: the high 32 bits plus the low 32 bits plus the zero-byte contribution.

There is no visible carry-in beyond that zero contribution. Arithmetic overflow is subject to the qualifications above.

An additional byte-sized output associated with D06 is written at retained primary root plus `0x11`. D07 then executes, after which the previously established zero byte is written at retained primary root plus `0x15`.

The global supplying the primary root is not reread between these stores. Changing that global during an intervening call does not itself redirect either store.

### Initial halfword and working-base operations

D08 returns a halfword and exposes an additional address-sized output. The halfword is written at that output address plus `0x0C`.

D09 then returns a 64-bit result whose halves remain inputs to several subsequent operations:

- A zero halfword is written at the high-half address plus `0x2C`.
- The low half, logically shifted right by 26, is written as a word at working base plus `0x26C`.

D10 executes. A word is then read from working base plus `0x320` and retained as a destination pointer. D11 and D12 execute before a word is written at that retained pointer plus `0x54`. Its value is the D09 low half shifted left by two, retaining 32 bits.

D13, D14, D15, D16, and D17 follow, in order. The two shifted values both derive from D09; neither is replaced by a later dependency result.

Working-base accesses use the register state effective at their respective operations. Preservation of that state by unknown callees is not established.

### Fixed-region input and breakpoint

An unsigned halfword is read at fixed-region address `0x21C48994`, which is `0x21C48960 + 0x34`. This retained value is the **first selector**.

D18 executes. A word is then read from working base plus `0x280` and passed as D19’s explicit argument. D19 produces a 32-bit result.

A software breakpoint with immediate `0x92` executes next. No post-breakpoint operation described below precedes this event. If execution does not resume, the iteration has only its preceding effects; no recovery path or rollback is visible.

### Post-breakpoint roots and selectors

If execution resumes, the D19 result is shifted left by two to form an offset. A separate displacement is derived by shifting `0x21C48960` right by 18 and multiplying by four. This displacement is exactly `0x21C4`.

A word is read from zero-extended first selector plus `0x44`. It is retained as the **record base**. D20 executes, then D21 produces a 32-bit result. A word is read from first selector plus `0x04`. D22 receives the D21 result as its first argument and that newly read word as its second argument.

The secondary root is then read and retained. After D23, a halfword is written at:

**retained secondary root + shifted D19 result**

The stored value is the low 16 bits of the retained secondary root itself, not data read through that root.

D24 executes. A word is read at displacement plus `0x54`, namely address `0x2218`, and retained as the **selector-record pointer**.

D25 returns an address. A halfword containing `0x21C4` is written at that address plus `0x04`. D26 and D27 execute, in order. An unsigned halfword is then read at selector-record pointer plus `0x34`; this is the **second selector**.

The first selector directly participates in low numeric addresses. There is no visible pointer-table lookup or additional base before its two word reads.

### Final paired result and working-base transition

D28 returns a 64-bit result. Its low half is written as a word at working base plus `0x258`.

An unsigned halfword is read at the D28 high-half address plus `0x14`; this is the **payload halfword**.

The remaining operations retain three derived quantities:

- D28 low half shifted left by six.
- D28 high half multiplied by four.
- Zero-extended second selector multiplied by four.

The working-base register is explicitly reduced by `0xF4`, or 244 bytes. This occurs after the store at working base plus `0x258` and before the following word store:

**destination:** four times second selector plus `0x74`  
**value:** D28 low half

No matching restoration of the working base is visible in the iteration.

### Final record and byte operations

D29 executes. The payload halfword, zero-extended to 32 bits, is written at retained record base plus `0x54`.

D30 executes. The same retained, widened value is written at retained record base plus `0x64`.

D31 executes and exposes an additional address-sized output. A halfword is written at that output plus the D28 low half shifted left by six. Its value is the low 16 bits of the retained record base.

D32 and D33 execute. A byte is then read at:

**second selector + four times second selector**

Thus, the byte source is numerically five times the zero-extended second selector, without an additional visible base.

D34 executes before that retained byte is written at:

**zero-extended payload halfword + auxiliary base + `0x19`**

The auxiliary register state used at this store is not established to survive preceding calls unchanged.

D35 executes. The D28 high half multiplied by four is written as a word at retained record base plus `0x44`.

D36 executes. Link state is explicitly replaced with `0x08712031`. A word is read at four times the D28 high half plus `0x44` and passed to D37.

If D37 returns, the next iteration begins. Its D01 target is therefore formed from the replacement link value and is `0x0871302F`, rather than necessarily matching the first iteration’s target.

## Acceptance examples

These are conditional static consequences, not executed tests. Each assumes the relevant calls return, memory is accessible, and arithmetic has the required execution semantics.

1. **Unsigned extraction and shift.** If D09’s low half is `0xFC000003`, the word at working base plus `0x26C` receives `0x0000003F`. The later word at retained destination pointer plus `0x54` receives `0xF000000C`.

2. **Captured primary root.** If the primary root is captured as P and D07 changes the supplying global to Q, the explicit zero-byte write still targets P plus `0x15`.

3. **Breakpoint boundary.** If execution stops at breakpoint `0x92`, the first-selector read and D19 call have occurred, but none of the post-breakpoint memory operations has occurred.

4. **Direct halfword-derived addressing.** A first selector of `0x0030` causes the retained-record-base read at `0x0074` and the D22 second-argument read at `0x0034`.

5. **Payload widening.** A payload halfword of `0xFFFF` produces full word writes of `0x0000FFFF` at record base plus `0x54` and plus `0x64`.

6. **Selector-derived addresses.** A second selector of 3 produces a D28-low-half word-store destination of `0x80` and a later byte-source address of 15.

7. **Working-base ordering.** If working base is B at the D28-related word store, that store targets B plus `0x258`. The later explicit reduction changes the register to B minus `0xF4`. This does not guarantee what subsequent callees do to the register.

8. **Pointer-derived halfword.** A retained secondary root with low 16 bits `0xABCD` contributes `0xABCD` as the halfword value, regardless of its upper bits.

9. **Shared targets, separate observations.** D05 and D06 call the same target address, although D05’s paired result and D06’s additional byte output are consumed differently. The same distinction between target identity and call-site usage applies to the other four shared-target pairs.

10. **Iteration transition.** If D37 returns after link state is replaced, the following D01 targets `0x0871302F`, independently of the original incoming link value.
