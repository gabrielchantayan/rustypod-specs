# F-2f01ae013cd8

## Purpose

F-2f01ae013cd8 updates a mutable, word-oriented numeric object using an unsigned 32-bit operand and returns a 32-bit result.

**Established behavior:** An initial zero state selects direct unsigned addition with carry propagation. Before addition, the function may call a capacity-related dependency. An initial nonzero state selects a different path: clear the state, call another dependency, and conditionally transform the resulting state.

**Inferred intent:** The object resembles a signed arbitrary-precision integer whose magnitude is stored least-significant word first. The state field appears to represent sign or a related numeric property. Neither interpretation establishes the dependencies’ numeric semantics.

The distinction between the object’s initial fields and its fields after a dependency returns is material. In particular, an initially empty object does not necessarily remain empty when direct addition begins.

## Interface

### Inputs and layout

The function receives a mutable object pointer and an unsigned 32-bit operand. The operand ranges from zero through 4,294,967,295.

The visible header has four consecutive 32-bit fields:

| Byte offset | Contract name | Established use |
|---|---|---|
| 0 | Backing address | Locates storage accessed in four-byte words |
| 4 | Used count | Signed 32-bit value used for comparisons and extension |
| 8 | Capacity | Signed 32-bit value compared with used count plus one |
| 12 | State | Zero/nonzero branch selector and later transformation target |

This layout is consistent with a 32-bit address model. A wider-pointer layout, additional fields, alignment guarantees, and byte order within individual words are not established.

Word index zero refers to the first four-byte backing slot. Higher indices are visited when carry propagates. This establishes the arithmetic significance order of words, not the byte order within each word.

### Output

The function returns a 32-bit quantity:

- The direct-addition path returns zero when its pointer-valued gate is null, and one after completing its own addition.
- The delegated path returns the dependency’s 32-bit result unchanged. That result is not established as Boolean or as a success indicator.

The supplied object is modified in place. The function does not return a replacement object pointer.

### Preconditions

Ordinary execution requires:

- A readable and writable header.
- Valid backing storage for every word actually read or written.
- Representable count and index arithmetic.
- Valid backing-address calculations.

A conventional numeric representation would additionally require a nonnegative used count and storage consistent with the count and capacity. The function does not visibly validate those invariants.

The signed expression used count plus one must be representable for the capacity comparison to have an unambiguous ordinary interpretation. Behavior at signed-overflow and address-overflow boundaries is **documented_only**.

There is no initial null-header guard. The later nullness gate cannot make a null input safe because header accesses precede it.

## Behavior

### Initial selection

The function first examines the state field.

- Zero selects direct addition.
- Any nonzero 32-bit state selects delegation.

The initial decision does not require a nonzero state to equal one. The branch is not reselected if a dependency subsequently changes the state.

### Direct addition: capacity gate

Before writing a backing word, the function compares signed capacity with signed used count plus one.

If capacity is smaller, it invokes F-08bc2fc94856 with the original object pointer and the requested count, used count plus one. Otherwise, it makes no capacity call.

This check reserves room for a possible extra word regardless of the operand. It can therefore trigger even when the operand is zero or no carry would occur.

The gate then examines:

- The dependency’s pointer-valued result, if the dependency was called.
- The original object pointer, otherwise.

A null value causes an immediate return of zero. A nonnull value allows addition to proceed.

The dependency’s returned pointer is only a gate. It is not adopted as the object through which subsequent arithmetic is performed. Later accesses continue through the original object pointer and the fields then visible there. Returning a different valid object without leaving the original object usable is insufficient for ordinary continuation.

No preservation guarantee for F-08bc2fc94856 is established. It may change the original object’s count, backing address, capacity, state, or backing contents. Where later operations read those fields or contents, they observe the post-call values.

### Direct addition: word updates

Addition starts at word index zero, using the caller’s operand as the first addend.

For each visited index, the function compares that index with the current signed used count:

- If the index is below the count, it reads the existing word and adds the current addend.
- Otherwise, it uses the current addend without reading that slot’s previous contents for the calculation.

It writes the resulting 32-bit word before deciding whether to continue. The stored sum is the low 32 bits of the addition.

The continuation decision is unsigned:

- A stored result smaller than the current addend causes carry propagation.
- A stored result equal to or greater than the addend terminates the loop.

After carry, the next higher index is selected and the addend becomes exactly one. The original operand is not added again.

Consequently, an existing word containing 4,294,967,295 becomes zero when incremented by carry and propagates another carry. A smaller existing word increases by one and terminates propagation. At a position outside the current used count, the addend is written directly; because the stored result then equals the addend, propagation stops.

Every visited slot is written, including a slot whose value is unchanged by adding zero.

### Direct addition: count and return

After the final word write, the function compares the current used count with the final index.

- If the count is less than or equal to the index, it increments the count once.
- Otherwise, it leaves the count unchanged.

This is a single increment, not a general assignment of final index plus one. Malformed negative counts are not thereby normalized.

The function then returns one. It makes no explicit state-field write on this path.

**Empty-object consequence:** If the used count is still zero when the loop begins, the backing slot is valid, and no intervening mutation affects the operation, the function writes the operand directly to word zero and changes the count from zero to one. Operand zero receives the same treatment.

That consequence applies, for example, when an initially empty object has sufficient capacity to avoid F-08bc2fc94856. It also applies when that dependency returns nonnull and leaves the count zero with valid backing storage.

It is not an unconditional consequence of an initially empty object. If the capacity dependency changes the count before returning, the loop observes the changed count. It may add the operand to a now-existing word, propagate carry through a different representation, or finish with a count other than one.

### Delegation: clear, call, and inspect

For an initially nonzero state, the function first writes zero to the state field. It then calls F-7aafa3c67f00 with the original object pointer and the original operand.

The dependency’s 32-bit result is retained for return. The function does not test it for success before inspecting the resulting object.

After the call:

1. It reads the current used count.
2. If the count is zero, it returns the retained result without further state processing.
3. If the count is exactly one, it reads backing word zero. If that word is zero, it returns the retained result without further state processing.
4. All other cases proceed to state transformation.

Thus, only an empty representation and a one-word zero representation receive the zero exception. The function does not scan a multiword representation for all-zero contents.

For either early return, the final state is whatever the dependency left. The initially nonzero state is not restored.

### Delegation: state transformation

When the zero exception does not apply, the function transforms the post-call state as follows:

| State left by F-7aafa3c67f00 | State written by F-2f01ae013cd8 |
|---|---|
| 0 | 1 |
| 1 | 0 |
| Any other 32-bit bit pattern | 0 |

The comparison that excludes values above one is unsigned. Bit patterns interpreted as negative signed values therefore fall into the last row.

The externally relevant mapping is zero to one and every nonzero pattern to zero. It is not unrestricted arithmetic subtraction from one for arbitrary state values.

The retained dependency result is returned unchanged after this write.

## Side effects

### Observable ordering

On the direct path:

- The capacity decision and any capacity dependency call precede the function’s own backing-word writes.
- Existing word contents are read before their replacement is written.
- Backing-word writes proceed in increasing index order.
- Each word write precedes its carry decision.
- Any final used-count increment follows all loop writes.
- There is no explicit state write by this function.

The current used count determines whether each visited slot is existing. It is not contractually replaced by a snapshot of the count from before the capacity call.

On the delegated path:

- State is cleared before F-7aafa3c67f00 is called.
- The post-call count is inspected before any conditional first-word read.
- Word zero is read for the zero exception only when the post-call count equals one.
- Any final state transformation follows those checks.

Exact machine-level read counts and ordering beyond the supplied representation are **documented_only**.

### Failure and partial mutation

A null result from F-08bc2fc94856 prevents this function’s addition writes and returns zero. It does not establish that the dependency left the object unchanged. No rollback is visible.

The delegated path performs postprocessing regardless of the dependency’s returned bit pattern. A result interpreted externally as failure does not suppress the count inspection or conditional state transformation.

No transaction boundary, synchronization, recovery mechanism, or restoration of the original state is established.

### Ownership

The function directly mutates caller-supplied storage. No direct allocation or release operation is visible.

Either dependency may have allocation, relocation, release, or global effects not established here. Neither dependency may be assumed to preserve globals, retain ownership, transfer ownership, or leave backing storage unchanged.

## Acceptance examples

These are conditional acceptance criteria derived from static evidence, not executed tests. Unless stated otherwise, direct-path examples assume valid, nonaliasing storage, representable arithmetic, and no external mutation.

1. **No carry.** With state zero, count one, capacity at least two, word zero equal to 10, and operand 7, the function writes 17, leaves count one, and returns one.

2. **Carry into an existing word.** With state zero, count two, capacity at least three, words `[4,294,967,295, 8]`, and operand 1, the writes produce `[0, 9]` in that order. Count remains two.

3. **Carry extends storage use.** With state zero, count two, capacity at least three, words `[4,294,967,295, 4,294,967,295]`, and operand 1, the writes produce `[0, 0, 1]`. Count then becomes three.

4. **Zero operand still writes.** With state zero, count one, capacity at least two, word zero equal to 23, and operand zero, word zero is written as 23. Count remains one and the return is one.

5. **Empty object without a capacity call.** With state zero, count zero, capacity at least one, valid word-zero storage, and operand zero, word zero becomes zero and count becomes one. The return is one.

6. **Empty object preserved by the capacity dependency.** With initial state zero and count zero, suppose the capacity comparison triggers F-08bc2fc94856. If it returns nonnull, leaves count zero, and supplies valid backing storage, operand 7 is written directly to word zero and count becomes one.

7. **Initially empty object changed by the capacity dependency.** Suppose the same call instead returns nonnull after setting count two and providing words `[10, 20]`. With operand 7, the function writes 17 to word zero, leaves word one at 20, and leaves count two. Initial emptiness does not force a one-word result.

8. **Capacity failure.** If F-08bc2fc94856 returns null, the function returns zero without performing its own addition writes. Any effects already caused by the dependency remain unspecified.

9. **Delegated empty or one-word zero result.** If F-7aafa3c67f00 leaves count zero, or leaves count one with word zero equal to zero, no post-call state transformation occurs. Its result is returned unchanged.

10. **Delegated nonzero representation.** If the dependency leaves count one and word zero equal to 9, post-call states zero, one, and two become one, zero, and zero respectively. The returned dependency result is unchanged.

11. **Multiword zero is not the zero exception.** If the dependency leaves count two and both words zero, the function still applies the state transformation.
