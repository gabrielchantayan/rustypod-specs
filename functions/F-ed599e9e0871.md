# F-ed599e9e0871

## Purpose

F-ed599e9e0871 repeatedly invokes an operation on successive four-byte-spaced positions, stopping when its cursor satisfies a specific comparison against a supplied target cursor. Traversal can cross boundaries by loading the next region’s base address from a table.

**Inferred intent:** the arguments resemble two segmented-iterator descriptions, with an opaque operation or context value carried through the traversal. This interpretation explains the layout, but does not establish a container type, element type, or ownership model.

**Established behavior:** stopping is not exclusively a comparison of complete cursor descriptions. Equal current addresses terminate immediately, even when table pointers or region bounds differ. A secondary, boundary-sensitive comparison can also terminate traversal when current addresses differ.

The function returns the ninth argument unchanged whenever it terminates normally.

## Behavior

### 1. Stopping is checked before each operation

At the start of every iteration, the moving current address is compared with the target current address.

If they are numerically equal, the function immediately returns the opaque carried value. In this case:

- Neither dependency is called during that iteration.
- No table entry is read during that iteration.
- Region starts, region ends, and table-entry pointer equality do not affect the result.

Thus, matching current addresses are sufficient for termination even if the rest of the two cursor descriptions is inconsistent.

### 2. A secondary comparison is enabled only at a region start

If the current addresses differ, a secondary stopping calculation is considered only when at least one of these conditions holds:

- The moving current address equals its current region start.
- The target current address equals the target region start.

If neither condition holds, the function does not perform that calculation. It proceeds directly to the operation call.

This gate is an equality check against region starts. It is not a general bounds check and does not test whether either address lies within a region.

### 3. Secondary comparison with equal table-entry pointers

When the secondary comparison is enabled and the moving and target table-entry pointers are equal, the function subtracts the target current address from the moving current address and shifts the signed difference right by two bits.

If the resulting 32-bit value is zero, traversal terminates and returns the carried value. Otherwise, traversal continues.

F-f3aa841fbccc is not called for this equal-table-pointer case.

For normally aligned positions with representable differences, the shifted difference expresses a separation in four-byte units. For unaligned values, it must not be replaced by an abstract element-distance operation: under arithmetic-right-shift semantics, a positive byte difference of one, two, or three produces zero.

### 4. Secondary comparison with different table-entry pointers

When the secondary comparison is enabled and the table-entry pointers differ, the function first calls F-f3aa841fbccc with no explicit arguments.

Its 32-bit result supplies a scale for the following calculation:

\[
\begin{aligned}
\text{comparison value} ={}&
(\text{table separation in four-byte entries} - 1)
\times \text{returned scale}\\
&+ \text{moving offset from region start in four-byte units}\\
&+ \text{target distance to region end in four-byte units}.
\end{aligned}
\]

The component differences are specifically:

- Moving table-entry address minus target table-entry address.
- Moving current address minus moving region start.
- Target region end minus target current address.

Each difference is shifted right by two bits before its corresponding subsequent arithmetic.

The function terminates if the final comparison value is zero. Any nonzero value causes traversal to continue; its sign and magnitude have no further effect.

This calculation is directional. Reversing the two cursor descriptions does not preserve the expression in general.

### 5. The operation is called for a nonterminal position

If neither stopping route succeeds, the function invokes F-f83da43cc7d3 with:

1. The opaque carried value.
2. The moving current address.

The dependency’s return value, if any, is ignored.

F-ed599e9e0871 does not itself read or write the four-byte object at that current address. Any such access belongs to the dependency’s behavior and is not established here.

### 6. Advancement follows the operation

After F-f83da43cc7d3 returns, the moving current address is increased by four bytes.

The incremented address is then compared with the current region end:

- If they differ, the next iteration starts with the incremented address.
- If they are equal, the function performs a region rollover before the next stopping check.

The boundary comparison uses exact equality. An address already beyond the boundary, or one that steps past it without landing on it, does not trigger rollover merely because it is out of range.

### 7. Rollover loads the next region

A rollover has this observable order:

1. Call F-f3aa841fbccc with no explicit arguments.
2. Advance the local table-entry pointer by one four-byte entry.
3. Read the 32-bit value from that new entry as the next current address.
4. Set the local region end to that address plus four times the returned scale.
5. Set the local region start to the new current address.
6. Begin the next iteration with a fresh stopping check.

The dependency call precedes both table-pointer advancement and the next-entry read. Consequently, any effect that call has on the next table entry can affect the address subsequently loaded.

There is no stopping check between the four-byte increment and rollover. Even if that increment makes the current address numerically equal to the target, a boundary match still triggers rollover first.

A zero scale is not specially handled. It makes the newly computed region end equal the newly loaded region start; it does not itself cause termination or automatic skipping of the region.

## Acceptance examples

These examples are conditional predictions from the supplied static evidence, not executed tests. Arithmetic is assumed representable, and dependencies are assumed to return normally unless stated otherwise.

### Equal current addresses terminate immediately

Given equal moving and target current addresses, the function returns the carried value without calling either dependency, even if the table pointers and region bounds differ.

### One ordinary position is processed

Suppose the moving current address is `0x1004`, its region start is `0x1000`, its region end is `0x1010`, and the target current address is `0x1008` with target region start `0x1000`.

Neither cursor is at its region start on the first check. The function calls F-f83da43cc7d3 for `0x1004`, advances to `0x1008`, and returns at the next check. No rollover occurs.

### Equivalent boundary descriptions can terminate without an operation

Suppose:

- Moving current and region start are both `0x2000`.
- Moving table-entry pointer is `0x3004`.
- Target current and region end are both `0x1010`.
- Target region start is `0x1000`.
- Target table-entry pointer is `0x3000`.
- F-f3aa841fbccc returns four.

The table separation is one entry. Both remaining terms in the comparison are zero, so the complete comparison is zero. The function returns after the scale query, without calling F-f83da43cc7d3 or reading a table entry.

### Rollover occurs before reconsidering equality

Suppose the moving current address is `0x100C`, the moving region end is `0x1010`, and the target current address is `0x1010`. Choose starts so neither cursor is at its region start during this check.

The function invokes the operation for `0x100C`, increments to `0x1010`, and performs rollover. It does not return merely because the intermediate incremented address matches the target. The next stopping check uses the address loaded from the next table entry.

### Unaligned differences can collapse to zero

Under arithmetic-right-shift semantics, suppose the moving current address and moving region start are both `0x1001`, the target current address is `0x1000`, and the table-entry pointers match.

The initial current-address equality fails, but the secondary comparison is enabled. The positive difference of one byte shifts to zero, so the function returns without invoking either dependency.

### Skipping past a boundary does not roll over

Suppose a nonterminal operation is performed at `0x100E` while the current region end is `0x1010`.

Advancement produces `0x1012`, not `0x1010`. This iteration does not perform rollover. Safe behavior therefore cannot be inferred for arbitrary unaligned or inconsistent cursor descriptions.
