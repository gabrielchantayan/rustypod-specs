# F-7c0160ddbd95

## Purpose

F-7c0160ddbd95 transforms six signed 32-bit input fields into a 32-bit scalar. On an accepted path, it replaces those six fields with working values and writes three auxiliary fields. Explicit rejection returns `0xffffffff` without direct writes to the caller’s record.

**Established static behavior:** the transformation uses five ordered adjustment calls, byte-table traversal, four-year arithmetic, two range gates, and a final split-width representability check. Successful publication consists of six record writes, a further dependency call, and three additional record writes.

**Inferred intent:** the fields resemble seconds, minutes, hours, day of month, zero-based month, and an offset year. The auxiliary outputs resemble weekday, zero-based day of year, and an unspecified daylight-saving indicator. These interpretations are not sufficient to identify a standard calendar or time API.

The dependency implementations, table contents, and external arithmetic values are unavailable. No runtime tests have been performed.

## Interface

### Input and output record

The argument points to a record containing 32-bit words. The first six words are interpreted as signed inputs.

|---|---|---|---|
| 0 | Small unit | Read | Working small unit |
| 4 | Middle unit | Read | Working middle unit |
| 8 | Large unit | Read | Working large unit |
| 12 | Day | Read | Working day plus one |
| 16 | Month | Read | Working month |

These labels describe roles in the transformation; they do not establish civil-calendar semantics.

All six entry reads occur in increasing offset order, before the initial year check. The existing auxiliary values are not directly read.

Ordinary entry requires the first 24 bytes to be readable. Full successful publication requires all 36 bytes to be writable. There is no explicit null-pointer, alignment, or storage-size check. These storage requirements do not establish the safety of subsequent dependency calls or table accesses.

### Return value

The result is an unsigned 32-bit word.

- Every explicit rejection returns `0xffffffff`.
- Successful completion returns a scalar assembled from two 16-bit portions.
- The final acceptance check does not reserve `0xffffffff` exclusively for failure.

Whether an actual successful execution can produce `0xffffffff` is unresolved. Consumers must not assume that success and failure are necessarily distinguishable by the return word alone.

### Ownership

The function directly performs no allocation, release, or ownership transfer. Adjustment calls receive addresses of working words rather than the caller-record pointer.

Dependency retention, indirect memory access, and ownership behavior are **documented_only**. In particular, passing a working-word address does not establish that the dependency uses it only during that call or accesses only that word.

## Behavior

### Entry snapshot and initial gate

The function reads the six input words before invoking any dependency or directly modifying the record.

The original signed year must be within the inclusive range:

**−1,073,741,824 through +1,073,741,824.**

An original year outside this interval causes explicit rejection immediately after the six reads. That path performs no dependency calls and no direct record writes.

This gate does not establish that the other fields are valid, normalized, or safe as later indices.

### Ordered adjustment and global observations

After the initial gate passes, F-82594ed9ba4b is called five times:

| Call | Working-word address supplied | Second argument | Third argument |
|---|---|---|---|
| 1 | Small unit | Zero | 60 |
| 2 | Middle unit | Return from call 1 | 60 |
| 3 | Large unit | Return from call 2 | 24 |
| 4 | Day | Return from call 3 minus one | A separate read of the cycle global |
| 5 | Month | Zero | 12 |

The cycle global is observed **twice between calls 3 and 4**, in this order:

1. Its first 32-bit value is saved for the later day-count calculation.
2. Its second 32-bit value supplies call 4’s third argument.

Call 4 does not necessarily receive the saved first value. Equality requires a stability assumption not established by the supplied material. The saved first value, rather than a later reread, participates in the eventual day-count calculation.

The subtraction used for call 4’s second argument is a 32-bit operation. Overflow behavior at the original-language level is unresolved; fixed-width interpretation is discussed below.

No return from F-82594ed9ba4b is checked as an error status. Each is used as arithmetic data. The working words can be changed through the supplied addresses, but the dependency’s actual adjustment rule is unknown. Floor division, truncation toward zero, nonnegative remainders, and normalized field ranges must not be assumed.

After call 5, the adjusted year combines the original year, four times call 4’s return, and call 5’s return. The result is treated as an unsigned 32-bit quantity.

**Inferred intent:** these operations propagate carries between units and combine month and four-year-cycle adjustments. This interpretation does not establish the dependency’s behavior.

### Captured table address and table traversal

After call 5, the function reads a separate 32-bit **table-displacement global**. It adds the fixed address bias **`0x080313c8`** to derive the table base.

This is an additional global dependency, distinct from the three arithmetic globals. Its read occurs after the fifth adjustment call. The derived base is retained for both month advancement and later ordinal calculation; the displacement global is not reread for those accesses.

Capturing the base does not snapshot the table contents. Each table access reads an unsigned byte from the derived base plus an index.

At the current working month, traversal compares the table byte, promoted to a nonnegative integer, with the signed working day:

- A byte greater than the day ends traversal.
- A byte less than or equal to the day permits advancement.

An advancing iteration performs a **second byte read at the old month index** for the subtraction from the day. It does not necessarily subtract the byte used by the comparison. Those bytes agree only if the table location remains stable between reads.

The month advances by one. The following corrections apply to the new month:

- When it becomes 2, a year whose low two bits are nonzero causes the working day to increase by one.
- Otherwise, when it becomes 12, the adjusted year increases by one and the month becomes zero.

Traversal then repeats using the captured base. The year increment is unsigned 32-bit arithmetic.

There is no explicit table-index bound check, backward-month traversal, or iteration limit. A negative working day stops traversal immediately if the indexed byte read is valid, because every table byte is nonnegative. A negative month can nevertheless cause an access before the nominal base. Zero-valued table entries can allow advancement without reducing the day.

After traversal ends, a separate correction changes month 1 and day 28 to month 2 and day zero when the adjusted year’s low two bits are nonzero. No century or four-century exception is visible.

**Inferred intent:** the bytes are month lengths shared across a four-year cycle, with explicit corrections for a shorter February-like month. Their actual values and extent are unavailable.

### Adjusted-year gate

The adjusted year must be **70 through 208 inclusive**.

This is an unsigned gate: subtracting 70 in 32-bit unsigned arithmetic must yield a value below 139. Values below 70 do not become accepted through subtraction wraparound. Values with a negative signed interpretation are also rejected.

Rejection here occurs after all five adjustment calls and the preceding table activity, but before any direct caller-record writes.

### Day ordinal and day count

For an accepted adjusted year, the day ordinal starts with the current working day. Table bytes at indices zero through one less than the working month are then read, in increasing index order, and added.

These reads use the previously captured table base. They are fresh content reads, not reused traversal bytes. If the working month is nonpositive, this accumulation loop reads no bytes.

When the month is greater than 1 and the year’s low two bits are nonzero, the ordinal decreases by one. The ordinal receives no independent range check and is eventually published at offset 28.

The day count combines:

- The day ordinal.
- The saved **first** cycle-global value multiplied by the adjusted year’s quotient on division by four.
- A separately read residual-year global multiplied by the year’s low two bits.

If the year’s low two bits are zero, the day count decreases by one.

The represented quotient calculation includes signed handling for negative operands. At this stage, however, the accepted year range is nonnegative, so the quotient is the ordinary integer quotient by four.

Neither multiplier’s numeric value is supplied. The residual-year global is read during this later calculation, not snapshotted at entry.

### Scalar construction and acceptance

The following symbols are explanatory mathematical labels, not interface fields.

Let **M** denote the 32-bit minute-like intermediate:

**M = middle unit + 60 × (large unit + 24 × day count) − scalar-offset value.**

The scalar-offset global is read at this stage.

Let **L** denote:

**L = small unit + 60 × low16(M).**

Let **H** denote:

**H = 60 × arithmetic_shift_right_16(M) + unsigned_high16(L).**

The distinctions between these operations are material:

- `low16(M)` is the unsigned value of M’s low 16 bits.
- The shift of M interprets its 32-bit pattern as signed and extends its sign.
- The high-half extraction from L uses an unsigned shift.
- The represented intermediate arithmetic is 32-bit, not unbounded integer arithmetic.

The final gate accepts exactly those unsigned H values from zero through 65,535. Equivalently, H’s upper 16 bits must be zero. A negative signed interpretation of H therefore fails.

On acceptance, the returned word contains H in its upper half and L’s low 16 bits in its lower half. Rejection returns `0xffffffff`, performs no direct record writes, and skips F-870c4fcf7295.

The supplied representation establishes these widths and shifts. It does not independently resolve original-language signed-overflow rules. Mathematical calculations that ignore 32-bit wrapping are not a substitute for the represented operations.

### Successful publication

After the final gate passes, direct record writes occur in this order:

1. Working small unit at offset 0.
2. Working middle unit at offset 4.
3. Working large unit at offset 8.
4. Working day plus one at offset 12.
5. Working month at offset 16.
6. Adjusted year at offset 20.

The function then calls F-870c4fcf7295 with the 32-bit day count plus one and the value 7.

After that call returns, publication continues:

7. Its associated secondary result at offset 24.
8. The calculated day ordinal at offset 28.
9. Signed −1 at offset 32.

The assembled scalar is then returned. Day-plus-one and day-count-plus-one are 32-bit additions, subject to the arithmetic qualification above.

Publication is not atomic. If F-870c4fcf7295 does not return normally, the first six direct writes have occurred, but the last three writes and normal return have not.

## Acceptance examples

These are conditional static obligations, not executed tests. They assume required accesses and dependency calls complete normally unless stated otherwise.

1. **Initial rejection still reads all inputs.**  
   An original year of +1,073,741,825 or −1,073,741,825 causes rejection after all six input reads. No dependency is called and no direct record write occurs. The adjacent boundary values ±1,073,741,824 pass this gate only.

2. **Two cycle reads need not agree.**  
   If the first cycle-global read yields P and the second yields Q, call 4 receives Q as its third argument. If execution reaches day-count calculation, its cycle multiplier is P. Substituting Q for P, or P for Q, changes the specified observations unless equality is separately established.

3. **Table-base capture is distinct from content stability.**  
   If the displacement read after call 5 yields D, subsequent table accesses use the base derived from D and the fixed bias. A later displacement change does not itself rebase those accesses. A table-content change at that captured base can affect later byte reads.

4. **Comparison and subtraction can observe different bytes.**  
   If traversal compares a byte value 3 against day 5, advancement is selected. If the second read at that same index yields 4, subtraction uses 4, leaving day 1 before any month-specific correction.

5. **Adjusted-year boundaries.**  
   Years 69 and 209 fail the adjusted-year gate. Years 70 and 208 pass it, but still require scalar acceptance. Reaching this gate already entails the adjustment calls and preceding table activity.

6. **February-like correction.**  
   If traversal ends at month 1, day 28, year 71, the separate correction produces month 2 and day zero. Eventual success writes month 2 and day 1. Year 72 does not trigger that correction.

7. **Final arithmetic boundaries.**  
   H equal to 65,536 causes rejection without direct record writes or a call to F-870c4fcf7295. H equal to 65,535 passes. If L’s low half is also `0xffff`, the constructed successful result is `0xffffffff`; actual reachability remains unresolved.

8. **Partial publication is observable.**  
   An observer reached through F-870c4fcf7295 may see the first six fields already updated while the auxiliary fields have not yet received this function’s final writes. Dependency effects can independently alter that observed state.
