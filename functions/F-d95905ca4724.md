# F-d95905ca4724

## Purpose

F-d95905ca4724 scans fixed-size directory-like records from a mutable traversal context, matches a requested name, and installs an associated object in that context when a match can be obtained.

The record format strongly suggests a short-name/long-name directory scheme: records are 32 bytes, attribute value 15 identifies long-name fragments, first-byte value 229 identifies deleted records, and first-byte value zero terminates the scan. These filesystem interpretations are inferred intent. The byte tests and control flow below are established static evidence.

The function returns a 32-bit value of either 0 or 1. A return of 1 means that a matching record caused an object to be installed. A return of 0 covers several distinct outcomes, including end-of-records, acquisition failure, object-creation failure, and inability to advance traversal. No separate error code is exposed.

## Interface

The function has four arguments:

1. **Traversal context:** a pointer to a mutable array or structure accessed through 32-bit words.
2. **Search value:** an opaque 32-bit value passed to name-comparison dependencies.
3. **Accounting increment:** a signed 32-bit integer added to a global accounting location for each encountered nonterminal record.
4. **Comparison option:** an opaque 32-bit value forwarded to both comparison paths.

The visible context layout is:

| Byte offset | Width | Observed use |
|---|---:|---|
| 0 | 32 bits | Container or owner value passed to dependencies |
| 4 | 32 bits | Current installed-object reference |
| 12 | 32 bits | Traversal-position value used for acquisition, fragment accumulation, and object initialization |
| 16 | 32 bits | Record index within the acquired block |
| 24 | 32 bits | Most recently returned block reference |

Offsets 8 and 20 are not directly accessed by this function. The traversal dependency may access additional context fields; its implementation is unavailable.

An acquired block is used as follows:

- A 32-bit field at byte offset 12 is passed to the object-lookup dependency.
- Record storage begins at byte offset 24.
- Each record occupies 32 bytes.
- Ordinary in-block scanning is bounded by a signed comparison of the context’s record index against 16.

The function also uses:

- A local long-name state image whose first 32-bit word is tested as an activity marker.
- A checksum byte at apparent offset 8 within that state image.
- A 256-byte temporary buffer supplied to a name-materialization dependency.
- A 16-byte temporary buffer supplied to a short-name conversion dependency.
- A 20-byte state-transfer operation when initializing an object with accumulated long-name state.

### Preconditions

No argument, pointer, index, buffer length, or block extent is validated locally.

For defined execution, the context and any references returned by dependencies must support the reads and writes actually performed. The search value and comparison option must satisfy the relevant dependency contracts.

For conventional scanning, the record index should be in the range 0 through 15. This is not enforced as an unsigned range check: a negative signed interpretation satisfies the loop’s “less than 16” condition and may lead to an address outside the intended record area.

The supplied representation uses 32-bit integer and reference carriers. Pointer arithmetic and signed-overflow behavior outside valid operating ranges are not independently established.

## Behavior

### 1. Initialize scan-local state

The sequence-tracking value starts at zero. F-8e0ab1d7a3f2 is then called with the local long-name state.

This is a reset-shaped operation, but its exact writes are not shown. In particular, the visible function does not itself initialize every byte later included in the 20-byte state-transfer request.

### 2. Acquire a block

For each block attempt:

1. Call F-04b7df4e1a09 with the context’s owner value and traversal-position value.
2. Store the returned reference in the context at offset 24.
3. If that reference is zero, return 0 immediately.
4. Otherwise, compute the current record address as the returned block reference plus 24 plus 32 times the context’s record index.

The zero reference is stored before failure is reported. There is no release call for this acquisition-failure path.

### 3. Examine records in order

While the context’s record index, interpreted as signed 32-bit, is less than 16:

1. Read the current record’s first byte.
2. If it is zero, release the acquired block through F-2b1ba6d8de9d with second argument zero, then return 0.
3. Otherwise, add the accounting increment to the global accounting location.
4. Read the first byte again for classification.

The accounting update therefore includes deleted records, long-name fragments, and ordinary entries, but excludes a zero-byte terminator. It occurs before attribute inspection, matching, object lookup, or object creation.

The global location’s width and signedness are absent from the supplied declaration. Its update must not be assumed to be a 32-bit counter with a particular overflow policy.

If the classification byte is 229, call F-8e0ab1d7a3f2 on the local long-name state and continue to the next record.

For other first-byte values, byte offset 11 selects between an ordinary entry and a long-name fragment.

### 4. Process long-name fragments

A record with byte 11 equal to 15 is treated as a fragment.

#### Fragment with bit 6 set in its first byte

The function:

1. Calls F-51e448cd1d6a with the local state and the context’s traversal-position value.
2. Reads the record’s byte 13 into the local checksum byte.
3. Reads the record’s first byte again and stores that full byte as the sequence-tracking value.

No additional ordinal, reserved-bit, or checksum validation is visible on this branch. In particular, this function does not first reset existing accumulated state.

F-51e448cd1d6a is not directly passed the current record address. The source of any fragment data it obtains is outside this function’s visible contract.

#### Fragment without bit 6 set

If the local state’s first 32-bit word is zero, the fragment is ignored by this branch.

Otherwise, the function requires both:

- The current first byte, masked with 63, equals the preceding sequence-tracking value masked with 63 and then decremented by one.
- The current record’s byte 13 equals the stored checksum byte.

The decrement is unsigned 32-bit arithmetic. If the preceding masked value is zero, the expected result becomes 4,294,967,295, not 63. Since the incoming masked value is at most 63, that continuation cannot match.

If either check fails, the sequence-tracking value is set to zero and the local state is passed to F-8e0ab1d7a3f2.

If both checks pass, F-51e448cd1d6a is called with the local state and traversal-position value, and the sequence-tracking value becomes the full first byte captured for this record’s classification.

### 5. Match an ordinary entry

A record whose byte 11 is not 15 is considered through one of two comparison routes.

#### No active accumulated state

If the local state’s first word is zero:

1. Call F-33c0269d05fd with the 16-byte temporary buffer, the record address, and the record address plus 8.
2. Call F-a7d0f4365c39 with the search value, that buffer, and the comparison option.
3. Treat any nonzero result as a match.

The exact short-name encoding, output termination, and buffer-writing contract belong to F-33c0269d05fd.

#### Active accumulated state

If the local state’s first word is nonzero:

1. Call F-575c870e8340 with the owner value, local state, and 256-byte temporary buffer.
2. Pass its opaque 32-bit result to F-fd4d7060ab73, together with the search value, comparison option, and a literal fourth argument of zero.
3. If that comparison returns zero, perform the short-name comparison described above.
4. If it returns nonzero, call F-31748fbe220b on the current record and compare its full unsigned 32-bit result with the stored checksum byte.

A nonzero long-name comparison therefore does not alone establish a match. The checksum result must also equal the zero-extended checksum byte. There is no visible truncation of the dependency result to eight bits.

A checksum mismatch after a nonzero long-name comparison does **not** fall back to the short-name comparison. The entry is rejected.

When an ordinary entry is rejected, the local state is passed to F-8e0ab1d7a3f2 before scanning continues.

### 6. Obtain and install an object

For a matched entry, call F-b7aa346e402e with:

- The owner value.
- The acquired block’s 32-bit field at offset 12.
- The context’s current record index.

A nonzero result takes the existing-object path:

1. Call F-25bf76bbe81a with the context’s current object reference.
2. Store the lookup result as the current object.
3. Release the acquired block through F-2b1ba6d8de9d with second argument zero.
4. Return 1.

This branch does not visibly initialize the returned object from the record or transfer long-name state into it.

A zero lookup result takes the creation path:

1. Call F-7cc5cc748c2d.
2. If it returns zero, release the block and return 0.
3. Otherwise, call F-25bf76bbe81a with the context’s current object reference.
4. Store the newly returned object as the current object.
5. Call F-5c3b4734522b with that new object and the current record.
6. Call F-eacf2e4e8b78 with the context’s current object, owner value, traversal-position value, and record index.
7. Initialize or transfer state at byte offset 64 of the context’s current object:
   - If the local state is inactive, call F-8e0ab1d7a3f2 on that object location.
   - Otherwise, call F-31748fbe220b on the record again. If its result differs from the stored checksum byte, reset the local state through F-8e0ab1d7a3f2. Then invoke the external transfer-shaped operation with destination object-plus-64, source local state, and length 20.
8. Release the block and return 1.

Thus, an entry accepted by short-name fallback can still produce an object whose accumulated long-name state is discarded after checksum validation.

The old-object dependency is called before the context’s object field is overwritten. There is no identity check when the old and new references are equal.

### 7. Advance scanning

After any record that neither terminates scanning nor returns a match:

1. Advance the local record address by 32 bytes.
2. Increment the context’s record index by one.

At the end of an in-block scan:

1. Release the acquired block.
2. Call F-f915a78bdf25 with the traversal context.
3. If it returns zero, return 0.
4. Otherwise, set the context’s record index to zero and acquire another block.

The local long-name state and sequence-tracking value are not reset merely because a block boundary is crossed.

## Side effects

The directly visible context mutations are:

- Store each acquisition result, including zero, at offset 24.
- Increment the record index after each consumed nonterminal, nonmatching record.
- Set that index to zero after successful traversal advancement.
- Replace the current object after a successful lookup or creation.

Under dependencies that leave the traversal fields unchanged, a successful match leaves the index pointing to the matched record. A zero-byte terminator also leaves its index unconsumed. Dependencies may change these observations because their implementations are unavailable.

Each acquired nonzero block is passed to F-2b1ba6d8de9d on the visible normal paths that leave that block. The context’s block-reference field is not cleared afterward. Whether that field then denotes a usable reference depends on the release dependency’s semantics.

F-25bf76bbe81a is invoked on the previous object only after a replacement has been obtained. The visible function does not establish whether this dependency decrements a reference count, frees storage, or performs another action.

No dependency failures are checked except through the explicit return-value branches described above. There is no visible rollback, exception handling, or recovery after installation begins.

All ordering claims concern direct operations in this function. Opaque calls may mutate globals or reachable context memory. The contract does not assume they preserve either. Repeated context accesses after calls must therefore not be treated as guaranteed snapshots of earlier values.

## Acceptance examples

These are conditional static expectations, not executed tests. Unless stated otherwise, dependencies return normally and do not independently alter the fields being discussed.

1. **Acquisition returns zero.**  
   The block-reference field becomes zero and the function returns 0. No record is inspected and no block-release call follows that failed acquisition.

2. **First record is a terminator.**  
   With index zero and first byte zero, the block is released and the function returns 0. The accounting location is unchanged by direct operations, and the index remains zero.

3. **Deleted record followed by terminator.**  
   A first byte of 229 causes one accounting increment and a local-state reset. The index advances once. The following terminator causes release and return 0 without another accounting increment.

4. **Matching short-name entry with existing object.**  
   With inactive local state, a nonzero short-name comparison result and nonzero object lookup result cause old-object processing, object-field replacement, block release, and return 1. No creation or record-based initialization call occurs.

5. **Long-name comparison succeeds but checksum differs.**  
   The entry is rejected even if its short name would match. The short-name comparison is not called on that path; local state is reset and scanning continues.

6. **Long-name comparison fails but short-name comparison succeeds.**  
   The entry remains eligible for object lookup and creation. If creation occurs, the later checksum comparison determines whether the accumulated state is reset before the 20-byte transfer-shaped call.

7. **Matching record cannot obtain a new object.**  
   If lookup and creation both return zero, the block is released and the function returns 0. The previous object is not directly processed or replaced.

8. **Fragment continuation follows ordinal zero.**  
   With active state and a preceding masked sequence value of zero, no incoming six-bit ordinal can satisfy the unsigned decremented expectation. The state is reset.

9. **Fragment sequence crosses a block boundary.**  
   Successful traversal advancement does not itself discard accumulated state. Continuation in the next block remains possible, subject to the dependency behavior and ordinal/checksum checks.
