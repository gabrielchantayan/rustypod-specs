# F-94e2e30e208d

## Purpose

F-94e2e30e208d performs an ordered state transition over a caller-supplied record and an associated record. It invokes several dependencies, conditionally processes a value supplied through its fourth argument, updates state bytes and a counter-like field, and returns a 32-bit status.

The established behavior is the sequence of accesses and calls described below. Names such as “state byte,” “counter,” and “status” describe how values are used here; they do not establish the surrounding subsystem’s meaning. In particular, the evidence does not establish that this operation destroys an object, closes a resource, or releases every resource associated with either record.

## Behavior

The following sequence describes direct behavior, assuming each dependency returns normally and subsequent storage accesses remain valid.

The function first reads the 32-bit word at P offset 4 and retains that value as R.

It also copies the fourth argument into a private 32-bit working slot before invoking the first dependency.

R is not subsequently reselected from P. If a dependency changes P offset 4, later direct accesses still use the originally selected R.

It then calls F-533f1c9e9e0b with:

- a zero-valued second argument;
- a zero-valued third argument.

The returned integer becomes the current result status.

If that status is nonzero, the function calls F-9cd9181826b7 with P and that status. This is a conditional notification or processing call, not an early return. Its return value is not used.

The function next calls F-f566983924c8 with P, regardless of the current result status.

### 3. Perform the state-2 branch

After F-f566983924c8 returns, the function reads the byte at P offset 8.

If that byte is not exactly 2, this entire branch is skipped.

If it is exactly 2, the following actions occur in order:

1. Write a 32-bit zero to R offset 24.
2. Read the current 32-bit word at R offset 0 and pass it to F-d3c215f985ae.
3. If F-d3c215f985ae returns nonzero, replace the current result status with that return value. If it returns zero, retain the previous status.
4. Call F-14f40f321d22 with R, the integer value 1, the address of the private working slot, and a zero-valued fourth argument.
5. If F-14f40f321d22 returns zero, call F-6cc778185718 with the working slot’s current 32-bit contents. These contents may differ from the original fourth argument because the preceding dependency received the slot’s address.
6. Write the byte value 1 to R offset 48.

The return value of F-14f40f321d22 only controls whether F-6cc778185718 is called. It does not directly replace the function’s result status. The return value of F-6cc778185718 is not used.

The final byte write in this branch occurs whether F-14f40f321d22 returns zero or nonzero, provided all calls return normally.

### 4. Independently test the current state and conditionally decrement

The function reads P offset 8 again. This is a separate read, not reuse of the value that selected the state-2 branch.

If this later byte value is zero, the decrement operation is skipped.

If it is nonzero:

- Read the 32-bit integer at R offset 52.
- Compute that value minus one.
- Write the computed result back to R offset 52.
- If the computed result is zero, clear the byte at R offset 48.

Thus, entering the state-2 branch does not itself guarantee a decrement. A dependency in that branch may change P offset 8 before the later test. Conversely, every nonzero value observed by the later test selects the decrement, not just 2.

For an input field value of 1, the stored result is 0 and R offset 48 is cleared. For representable subtraction results other than zero, the function does not clear that byte at this step.

The supplied representation uses signed 32-bit integer arithmetic for this operation. Behavior at the most negative signed value is not established well enough to promise either language-defined wrapping or a trap. Callers requiring defined signed subtraction should exclude that boundary unless additional target evidence resolves it.

3. Call F-ce2b2a7a0121 with R.

## Side effects

### Direct memory changes

The function always attempts the copy from P offset 0 to R offset 4, followed later by the two one-byte clears at P offset 8 and R offset 16.

Additional direct changes depend on the state reads:

- First state read equal to 2: clear R offset 24 and later set R offset 48 to 1.
- Later state read nonzero: decrement R offset 52.
- Decrement result equal to zero: clear R offset 48.

The byte at R offset 48 can therefore be written twice in one invocation: first to 1, then to 0.

No non-overlap guarantee is present. If P and R overlap, earlier writes may affect later reads. The ordered access rules still apply; field names must not be interpreted as independent storage in that case.

### Ownership and lifetime

No allocation is directly visible. The function does not directly establish ownership transfer for P, R, or the fourth argument.

F-6cc778185718 receives the working value only when F-14f40f321d22 returns zero. Although this may suggest conditional cleanup, that interpretation is not established. The dependency might release a resource, consume a handle, or perform some other operation.

The working slot is private temporary storage. Passing its address makes synchronous modification possible; it does not establish a right for the dependency to retain that address beyond the slot’s lifetime.

No assumption is made that dependencies preserve globals, preserve either record, or leave their storage alive. Continued execution requires the later accesses to remain valid.

### Failure handling

There is no local rollback, retry, null-pointer guard, exception handler, or early exit based on a nonzero returned status.

If a dependency does not return normally, subsequent writes, calls, and the final return are not established for that execution.

## Acceptance examples

These are conditional acceptance criteria derived from static evidence, not executed tests. Unless otherwise stated, assume valid, non-overlapping records; normal dependency returns; and no dependency changes to the fields discussed.

1. **Zero-state path.** If the initial status is zero and P offset 8 is zero at both tests, the state-2 branch and decrement are skipped. The direct copy and final byte clears still occur. The returned status is zero.

2. **Initial failure without early exit.** If F-533f1c9e9e0b returns 7, F-9cd9181826b7 receives P and 7. Processing continues. If the state-2 branch is skipped, the returned status remains 7.

3. **Zero does not erase an earlier failure.** If the initial status is 7, the first state test sees 2, and F-d3c215f985ae returns zero, the final result remains 7.

4. **Later nonzero status takes precedence.** If the initial status is 7 and the selected F-d3c215f985ae call returns −3, the returned status is −3, assuming normal completion.

5. **Updated working value is forwarded.** If F-14f40f321d22 changes the working slot from value A to value B and returns zero, F-6cc778185718 receives B, not A. If it returns nonzero, that call is omitted, but R offset 48 is still set to 1.

6. **Set followed by clear.** If both state reads see 2 and R offset 52 contains 1 at the decrement, R offset 48 is first set to 1 and then cleared to 0. R offset 52 becomes 0.

7. **Other nonzero state.** If both state reads see 3 and R offset 52 contains 4, the state-2 branch is skipped, but the decrement stores 3. There is no direct write to R offset 48 in this case.

8. **Distinct state reads matter.** If the first state read sees 2 but a dependency in that branch changes P offset 8 to zero, branch processing occurs and the later decrement is skipped.

9. **Associated address remains selected.** If F-0b4658e20c99 changes P offset 4 to another address, the direct copy and later associated-record accesses still use the address selected before that call.

10. **Final clearing is not a return-state guarantee.** A call observer must see the two direct byte clears before F-ce2b2a7a0121 begins. If a final dependency subsequently changes either byte, a nonzero byte on return does not by itself violate this contract.
