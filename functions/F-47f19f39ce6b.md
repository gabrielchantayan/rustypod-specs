# F-47f19f39ce6b

## Purpose

F-47f19f39ce6b performs constructor-like initialization of caller-supplied storage, establishes a self-linked auxiliary structure, initializes a second region through a dependency, and submits an address within that second region to another dependency with the fixed value 6.

The observable return is an address 32 bytes before the address returned by F-72538fc0941d. The supplied evidence does **not** establish that this is the original input address.

The constructor, sentinel, and registration terminology describes inferred intent. The contract below is grounded in the visible calls, memory accesses, constants, and address relationships rather than those interpretations.

## Behavior

The numeric contents of the two static storage locations are not supplied. They must not be replaced with guessed type identifiers, table addresses, or constants.

All offsets below are byte offsets. A 32-bit write affects four bytes; a byte write affects only the specified byte. Endianness is not established, so this contract describes values and widths rather than a byte encoding for 32-bit values.

### 3. Establish the auxiliary structure

The function calls F-4fa4ec01302c with the address at destination offset 4.

After that call returns:

1. Its returned address is stored as a 32-bit value at destination offset 20.
2. A 32-bit zero is written at auxiliary address +4.
3. The pointer-bearing field at destination offset 20 is read to establish the next write target and value. A 32-bit self-reference is written at displacement +8 from that address.
4. The field at destination offset 20 is consulted again for a corresponding 32-bit self-reference at displacement +12.

In the ordinary non-overlapping, stable-memory case, the resulting auxiliary layout is:

| Auxiliary offset | Width | Value |
|---:|---:|---|
| 4 | 32 bits | 0 |
| 8 | 32 bits | Auxiliary address |
| 12 | 32 bits | Auxiliary address |

This resembles a self-linked sentinel, but no list operations or sentinel semantics are established.

The distinction between the original returned address and later reads of destination offset 20 is significant. The zero write uses the original auxiliary address. The self-reference writes use the destination field. If an earlier write aliases and changes that field, subsequent accesses need not use the original address.

No ownership transfer, allocation mechanism, or release obligation is visible.

### 4. Initialize the second region

Next, the function calls F-72538fc0941d with the address at destination offset 32.

The returned region address is then used as follows:

1. Write the byte value 2 at region address +28.
2. Read the region header value into a retained 32-bit value.
3. Read the same static location again and write that second value as 32 bits at region address −32.
4. Add 52 to the retained value and write the result as 32 bits at region address +32.

There are two represented reads of the region-header static location, with no intervening dependency call. If that location remains stable, the value at region address −32 and the base used for the +52 calculation are the same. If the location can change between reads, the evidence does not require equality.

The +52 operation belongs to the represented 32-bit computation; it must not be silently widened into arbitrary-precision arithmetic. Behavior when the addition exceeds the applicable arithmetic range is not established by the supplied representation. A portable signed-overflow guarantee cannot be inferred.

Likewise, subtracting 32 from the returned region address requires a valid address relationship. The function does not check that relationship.

### 5. Submit the embedded address

After the region writes, the function:

1. Calls F-95e21bd99c14 with no explicit arguments.
2. Passes its returned 32-bit value to F-bee4da2a68ae as the first argument.
3. Passes region address +32 as the second argument.
4. Passes the fixed value 6 as the third argument.

The return value of F-bee4da2a68ae is not used.

Neither dependency may be assumed to preserve the destination, the auxiliary structure, the region, or static storage. Consequently, the preceding writes describe effects at their respective execution points; they are not unconditional guarantees of final memory contents after these dependencies return.

### 6. Return the enclosing address

The function returns region address −32.

This result is derived from the retained region address, not by rereading a pointer field from Destination. Changes made by the final dependencies to destination fields do not, by themselves, change that retained address calculation.

If execution stops after some writes or dependency effects, the visible body provides no transaction guarantee. Earlier effects may remain.

These are conditional acceptance scenarios derived from static evidence, not reports of executed tests.

Assume all calls return normally, all addresses are valid, relevant storage does not overlap, and dependencies do not subsequently overwrite the described fields.

Acceptance requires:

- D-01 receives the five arguments specified above.
- The initial destination writes occur in the specified order.

- The byte value 2 is written at destination offset 60.

This is conditional on the dependency’s return relationship; it is not an unconditional contract.

### Unwritten trailing bytes

### Changing the unused argument

This does not claim that the function as a whole is deterministic in the presence of external state.
