# F-3d31f2719b34

## Purpose

The important behavioral distinction is that the shared argument is captured before the first dispatch and reused for dispatches two through six. The first dispatch instead obtains its shared argument from a separate read of the same external location. The dispatch target and position-specific argument are resolved separately for each dispatch, allowing earlier callees to affect later dispatches through externally visible state.

This is a source-facing contract based on the supplied static representation. It does not establish what the dispatched operations mean. In particular, the evidence does not identify the sequence as registration, initialization, notification, rendering, or any other application-level operation.

## Behavior

### Entry and capture

Before invoking any indirect dependency, the function reads the shared source and retains a four-byte copy for subsequent use.

This retained value is a snapshot of the value read at that point. It is not a live reference to the shared source. Changes to the shared source during a dispatched operation do not replace the retained value used by dispatches two through six.

There is a second read of the shared source when preparing the first dispatch. Consequently, the retained value and the first dispatch’s shared argument arise from distinct source-level reads.

No dependency call appears between those two reads. Under stable, ordinary memory conditions, they yield the same value. Their equality is not an unconditional contract for asynchronously modified or special-purpose storage. The excerpt does not establish volatile access, atomicity, synchronization, or exact generated load instructions.

### Dispatch sequence

The six dispatch positions are ordered as follows:

| Position | First argument | Second argument | Third argument |
|---|---|---|---|
| 1 | Original receiver | Separate read of shared source | Value from position 1 source |
| 2 | Original receiver | Retained four-byte shared value | Value from position 2 source |
| 3 | Original receiver | Retained four-byte shared value | Value from position 3 source |
| 4 | Original receiver | Retained four-byte shared value | Value from position 4 source |
| 5 | Original receiver | Retained four-byte shared value | Value from position 5 source |
| 6 | Original receiver | Retained four-byte shared value | Value from position 6 source |

For each position, the callable target is obtained through the receiver’s current table-address field and the slot at byte offset 88 in that table.

The target is not captured once for the entire sequence. Each dispatch expression consults the receiver-associated table again. Therefore, the six positions need not invoke the same callable.

Likewise, the position-specific values are not all captured before the first dispatch. Each is obtained while preparing its corresponding dispatch. An earlier dependency can therefore affect a later position by changing its external argument source before that later dispatch is prepared.

The receiver argument remains the original reference supplied at entry. A callee may change the object or its table-address field, but that does not substitute a different receiver reference in later argument positions.
