# F-640fc8739666

The established contract concerns calls, branches, memory accesses, and returned values. The domain meanings of the input, objects, and status codes are not established. “Source,” “target,” “first cursor,” and “execution token” identify roles within this function, not verified domain types.

Three distinctions are essential:

## Acceptance examples

These are conditional consequences of static evidence, not executed tests. Unless stated otherwise, dependencies return normally and accessed memory remains valid.

1. **Negative token:** An initial result of −1 produces return value 0 with no further dependency calls. An initial result of 0 is accepted instead.

2. **Preparation stops processing:** A zero preparation result skips source resolution and object releases. Closing receives the accepted token; reporting receives 2; return value is 0.

3. **Source gating:** A zero first source predicate prevents both the second predicate and target resolution. A nonzero second predicate also prevents target resolution. Either case releases the source and reports 2.

4. **Target predicate failure:** A zero target predicate selects status 13 without accessing the nested signed field. Target release precedes source release.

5. **Signed boundary:** A nested target value of 2 fails validation. Values of 1, 0, and −1 pass this particular check.

6. **No cursor:** If initial cursor acquisition returns zero and finalization returns 7, no cursor checks or cursor release occur. The function reports status 2 and returns 7 after target and source cleanup.

7. **Finalization outputs:** Finalization returning 0 produces status 28 and return value 0. Returning −7 produces status 2 and return value −7.

8. **Cursor rejection:** If both checks return zero in one iteration, no continuation call for that iteration and no finalization occur. Cursor, target, and source are released in order; status is 13 and return value is 0.

9. **Distinct continuation result:** If the first cursor is A and continuation returns distinct nonzero B, subsequent checks and continuation calls still use A. No cleanup call for B is added merely because it was returned.

10. **Field mutation:** If the primary check changes A’s offset-4 field and returns zero, the fallback evaluates its field expressions after that mutation. It does not use a required pre-primary snapshot.

11. **Global change before acquisition:** If a preceding dependency changes the global from X to Y, and it remains Y during acquisition-argument evaluation, both global-derived positions receive Y, not a value captured before that dependency.

12. **Global change before continuation:** If acquisition used X and a later cursor check changes the global to Y, a subsequent continuation call evaluates its global-derived arguments from the current state.
