# F-eed34362a0c5

## Purpose

F-eed34362a0c5 obtains an object-address value through a local output slot, conditionally operates on objects selected through that slot, and passes a wrapper-related value to an output dependency.

A configuration byte selects one of two paths:

- Zero selects a buffer-based object operation, a checked operation on two interior addresses, a flag update, and an optional two-field transfer.
- Nonzero selects two all-ones field writes, followed by conditional buffer construction and another object operation.

The local object-address slot is not an immutable acquisition result. Acquisition receives its address. Later object arguments and destination addresses use the slot’s then-current value after intervening calls. Whether a dependency retains the slot address or subsequently changes its contents is unknown. Consequently, the visible operations are not guaranteed to address one object throughout the invocation.

“Acquisition,” “configuration,” “lookup,” “wrapper,” and “output” describe inferred roles, not established domain semantics.

## Behavior

### Object-address selection rule

Every later object operation uses the value of the local object-address slot at that use, rather than a permanently captured copy of the initial acquisition result.

In particular, the slot is consulted for:

- The zero-path buffer-based object call.
- The zero-path interior address at offset `0x48`.
- The zero-path flag-byte access at offset `0x18C`.
- The optional transfer destinations at offsets `0x218` and `0x21C`.
- The nonzero-path all-ones destinations.
- The conditional nonzero-path buffer-based object call.
- The shared wrapper-related call.

An intervening dependency can therefore affect which object a later operation addresses if it can modify the escaped slot. The source does not establish whether any dependency actually does so.

Once an object value or interior address has been evaluated and passed to a call, changing the slot does not retroactively change that argument. It can affect later uses. An implementation must not replace these uses with a cached initial acquisition pointer without an additional preservation contract.

This is a source-level sequencing requirement. It does not establish volatile accesses, atomicity, synchronization, or well-defined concurrent mutation of the local slot.

### Path selection

After successful acquisition, the function reads the byte at A1 offset `0x40`.

- Exactly zero selects the zero path.
- Any nonzero byte selects the alternate path.

No individual configuration bits are tested. Because this read follows acquisition, it uses the configuration value available after that call, not a value captured before it.

### Zero path: optional field transfer

A zero lookup result causes no direct transfer to offsets `0x218` and `0x21C`.

For a nonzero result, the visible field-operation order is:

1. Read the 32-bit value at lookup-result offset `0x114`.
2. Read the 32-bit value at lookup-result offset `0x110`.
3. Write the latter value to offset `0x218`, using the object-address slot at that destination use.

## Acceptance examples

These are conditional static acceptance criteria, not executed tests. They assume valid accesses and normal dependency returns unless specified otherwise.

### Acquisition failure

If acquisition returns `7`, the function returns `7`. The initial buffer call and acquisition occur; configuration inspection and output do not. Acquisition side effects are not excluded.

### Checked-operation failure

If acquisition succeeds, the configuration byte is zero, and F-6caf95f9c95b returns `-3`, the function returns `-3`. The earlier F-bddf81dc2a03 call has occurred. The direct flag update, lookup, and shared sequence do not occur.

### Slot changes between zero-path calls

Suppose acquisition stores address P. F-bddf81dc2a03 receives P, then an intervening dependency changes the escaped slot to valid address Q.

If that change occurs before the checked call’s argument evaluation, F-6caf95f9c95b receives Q plus `0x48`, not P plus `0x48`. If the checked call subsequently changes the slot to R and succeeds, the flag access uses R.

This criterion is conditional on those mutations occurring; it does not assert that any dependency performs them.

### Flag preservation and lookup destination change

If the flag byte read is `0x25`, the function writes `0xA5` and supplies `0xA5` to lookup.

If lookup changes the slot from P to Q and returns a valid nonzero source with `0x12345678` at `0x110` and `0x9ABCDEF0` at `0x114`, the subsequent direct destination writes use Q, assuming no further slot change. The write values are respectively `0x12345678` and `0x9ABCDEF0`; the `0x114` source is read first.

A zero lookup result instead causes no direct two-field transfer.

### Alternate path with false predicate

For a nonzero configuration byte and zero predicate result, the two all-ones writes occur before the predicate. Construction and the alternate-path object call are skipped.

If a predicate-stage dependency changes the slot to Q, the shared wrapper call receives Q. It must not receive a cached earlier address solely because construction was skipped.
