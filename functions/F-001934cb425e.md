## Behavior

### Observable sequencing

The represented path has no conditional branch, retry, status-dependent recovery, or ordinary early return. This establishes an order of attempted effects; it does not guarantee that all effects occur.

The direct memory effects progress through these groups:

1. Writes of the incoming byte.
2. Six separate writes of literal zero.
3. A write whose byte value comes from its numerical destination.
4. Writes of a byte derived from a retained unsigned result, with the first sixteen-bit read and a global assignment.
5. A write selecting a different portion of the same unsigned result.
6. Writes of a retained three-bit value, including scaled-pointer accesses, the second sixteen-bit read, and a thirty-two-bit write through the pointer.
7. Remaining dependency interactions and the terminal transfer.

Dependencies occur between direct effects and within these groups. An interaction with no explicit arguments may still have hidden inputs and side effects. An unused ordinary result does not make its producing interaction removable.

Earlier modifications are not rolled back if a later access faults or a dependency fails to return. The dependency boundaries are observability boundaries: effects cannot be freely moved across them on the assumption that dependencies preserve memory or globals.

### Early writes and input-dependent interactions

The first direct effect stores the incoming byte at the numerical address obtained by doubling the second explicit input. This write precedes F-U001.

F-U001 receives two equal explicit arguments, each obtained by scaling the first input by 4,096.

Subsequent incoming-byte writes principally use ordinary dependency results. The usual relationship is a byte destination scaled by eight, followed by an interaction receiving the corresponding result scaled by 16,384 in both argument positions.

Three exceptions must remain distinguishable:

- F-U002’s ordinary result determines a destination scaled by two. The following interaction receives equal arguments scaled by 4,096.
- A later destination still uses a scale of eight, but its associated equal arguments use a scale of four.
- One write is associated with a four-argument interaction rather than an equal pair.

For that four-argument interaction, positions one, two, and four are equal and derive from the write-producing result at scale 16,384. Position three derives independently from the fourth explicit input at scale 1,024. The following single-argument interaction consumes a secondary output of this boundary at scale eight. Substituting the ordinary return for that secondary output would change the contract.

Other intervening interactions forward ordinary 32-bit results unchanged or after scaling, commonly by four. That common scale is not universal: a later interaction in the retained-byte portion uses two.

### Literal-zero and address-derived values

The six literal-zero writes are six independent one-byte modifications. Each destination derives from its corresponding ordinary result at scale eight; each associated interaction receives equal arguments derived from that result at scale 16,384.

No adjacency, common allocation, or contiguous clearing operation is established.

The next value-dependent write stores the low eight bits of its computed numerical destination. Its destination again derives from an ordinary result at scale eight. The associated interaction receives three arguments: two equal values derived from that result at scale 16,384, followed by the computed destination itself.

Only the stored byte is truncated to eight bits. The third argument is neither byte-truncated nor scaled by eight a second time.

### Distinct retained byte values

Three later stored values have different origins and must not be conflated:

| Value | Established relationship |
|---|---|
| Low-derived byte | Eight times the low five bits of a retained unsigned 32-bit result; possible values are zero through 248 in multiples of eight. |
| Selected-bit byte | Bits 19 through 26 of that same retained result, numbering the least significant bit zero. |
| Three-bit value | Bits 29 through 31 of an older retained 32-bit product; possible values are zero through seven. |

The selected-bit operation initially selects more than eight bits, but the eventual byte conversion discards the excess. Bits 27 and 28 therefore cannot affect the stored byte.

The three-bit value comes from the older product’s most significant byte. Its later reassignment preserves the same zero-through-seven value; it does not shift an already reduced value again.

### Width and arithmetic constraints

Direct byte stores modify eight bits. Each direct read accesses sixteen bits. The direct pointer write modifies thirty-two bits. Most integer operands and retained intermediates are represented at 32 bits.

Unsigned 32-bit scaling retains the low 32 bits. Conversion to a stored byte retains the low eight bits. Signed calculations must not automatically be widened or treated as modular.

Under an explicitly assumed 32-bit modular model for the relevant signed calculations, the older scaled quantity has fourteen low zero bits. Its further scales of 65,536 and 134,217,728 therefore yield zero. The retained product has twenty-nine low zero bits, so its further scales of 4,096 and 8,388,608 also yield zero.

Those conditional consequences can produce accesses to numerical address zero. No special handling is represented. They are not unconditional guarantees under an unspecified execution model.

Signed overflow, negative left shifts, signed right shifts, pointer conversions, effective address width, and alignment remain model-dependent constraints.
