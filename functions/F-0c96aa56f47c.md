# F-0c96aa56f47c

## Purpose

F-0c96aa56f47c dispatches an operation on two pointer-addressed objects according to scaled values derived from their first 32-bit words. It selects among seven dependencies, sometimes performs additional dependency calls after a successful result, and returns a normalized 32-bit status.

The established behavior is the dispatch and status propagation described below. The objects’ mathematical meaning and the dependencies’ effects are unknown. Interpreting this routine as a particular arithmetic operation would require evidence not supplied here.

The return convention is:

- **0:** the selected path completes without a checked dependency returning nonzero, or the first scaled value is zero.
- **1:** a dependency whose result is checked as a status returns any nonzero 32-bit value.

One dependency instead supplies a signed comparison result. Its negative versus nonnegative classification selects a branch; it does not directly determine the returned status.

## Interface

### Arguments

The routine receives four arguments:

| Argument | Established use |
|---|---|
| First object pointer, called **A** below | Its first 32-bit word is read initially. The pointer may subsequently be passed to dependencies. |
| Second object pointer, called **B** below | Its first 32-bit word is read initially. The pointer may subsequently be passed to dependencies. |
| Third argument | A 32-bit value that is not read or forwarded by this routine. |
| Fourth argument | A 32-bit integer whose incoming value is overwritten before it can affect a branch. |

The third and fourth arguments therefore do not affect the established result or dependency sequence.

### Object layout and pointer requirements

Only the following layout is directly established:

- Offset zero of each pointed-to object contains a readable 32-bit word.
- No other object fields are accessed directly by this routine.
- Dependencies receive the original object addresses and may require additional layout, validity, or mutability guarantees that are not available here.

Both initial object words are read even when the first scaled value is zero and the routine will return without calling a dependency. A zero first scaled value therefore does **not** make an invalid second pointer safe.

A and B may be exactly equal. Exact pointer equality affects one branch explicitly. Different pointers with overlapping storage are not otherwise distinguished by this routine; whether dependencies support such overlap is unknown.

### Shared input

A shared 32-bit multiplier participates in both initial products.

Define:

- **X:** the 32-bit product associated with A’s initial word.
- **Y:** the 32-bit product associated with B’s initial word.

The first product is obtained before the second. The evidence contains a multiplier access in each product expression; it does not establish one immutable multiplier snapshot covering both products. The evaluation order between the multiplier access and the object-word access within an individual product is not specified by the supplied representation.

### Result and widths

The result is a 32-bit value restricted to 0 or 1 on ordinary completion.

Dispatch uses both unsigned and signed interpretations of 32-bit values:

- Zero tests examine the product bit pattern.
- Sign classification treats the products as signed 32-bit values.
- Dependency statuses are tested for exact zero, not for positivity.
- The comparison dependency’s result is interpreted as a signed 32-bit integer.

The recovered operations are 32-bit. When multiplication overflows signed range, the supplied representation alone is insufficient to establish the original language-level overflow rules. The branch descriptions below apply to the resulting 32-bit product values; overflow-specific examples require confirmation of the executable’s arithmetic semantics.

## Behavior

### Initial reads and early completion

The routine obtains X from A and then Y from B before making its first return decision.

If X is zero, the routine returns 0:

- B’s initial word has already been read.
- No dependency is called.
- Y’s value does not change this result.

If X is nonzero and Y is zero, the routine calls **F-a743bb08af07(A, B)** and normalizes its result:

- Exact zero produces return value 0.
- Any nonzero value produces return value 1.

Y equal to one is **not** included in this special case. It proceeds through the sign-based dispatch.

### Status convention used below

Unless specifically identified as a comparison, each dependency result described below is a status:

- Zero permits the path to continue.
- Any nonzero value immediately returns 1.
- No later call on that path occurs after a nonzero status.

This includes negative-looking bit patterns such as all bits set. The routine does not distinguish different nonzero errors and does not return the original error value.

### Both products positive

When X and Y are both positive as signed 32-bit values, the routine calls:

1. **F-762df453eb50(A, B)**.

It then returns the normalized status of that call. There are no further calls on this path.

### Both products negative

When X and Y are both negative, the dependency sequence is:

1. **F-9128d4a7b39b(B)**.
2. If A and B are different addresses, **F-9128d4a7b39b(A)**.
3. **F-762df453eb50(A, B)**.
4. **F-268334470dda(B)**.
5. If A and B are different addresses, **F-268334470dda(A)**.

Every listed result is checked before proceeding. Any nonzero result returns 1 immediately.

If A equals B, the second and fifth calls are omitted. In that case, a zero result from the fourth call completes the routine with return value 0.

If A differs from B, a zero result from the fifth call completes the routine with return value 0.

The equality rule concerns addresses, not object contents. Two distinct objects containing equal data still take the five-call path when every status is zero.

### X negative and Y positive

The routine first calls:

1. **F-268334470dda(A)**.

A nonzero result returns 1 immediately. Otherwise it calls:

2. **F-61e238108dfa(B, A)**.

The second call supplies a signed comparison result.

#### Negative comparison result

The remaining sequence is:

3. **F-d0b1d84c27e6(A, B)**.
4. **F-268334470dda(A)**.
5. **F-268334470dda(B)**.

Each result is checked as a status. All three must be zero for the routine to return 0.

In particular, success from the second call on A does not complete this path: the call on B still occurs. If either preceding status is nonzero, that final call on B does not occur.

#### Zero or positive comparison result

The remaining sequence is:

3. **F-9c6cf2acef37(B, A)**.
4. **F-268334470dda(A)**.

Both results must be zero for return value 0.

A comparison result of exactly zero follows this branch, not the negative branch.

### X positive and Y negative

The routine first calls:

1. **F-268334470dda(B)**.

A nonzero result returns 1 immediately. Otherwise it calls:

2. **F-61e238108dfa(B, A)**.

Again, the comparison uses the argument order B, A.

#### Negative comparison result

The routine calls:

3. **F-d0b1d84c27e6(A, B)**.

It returns that call’s normalized status immediately. There is no subsequent call to F-268334470dda on either object along this path.

#### Zero or positive comparison result

The remaining sequence is:

3. **F-9c6cf2acef37(B, A)**.
4. **F-268334470dda(B)**.

Both results must be zero for return value 0.

### Dispatch remains based on the initial products

The routine does not reread either initial object word to choose a different sign branch after dependency calls.

Consequently:

- A dependency changing an object’s first word does not cause redispatch.
- A dependency changing the shared multiplier does not cause the products to be recomputed.
- Later dependencies receive the original pointer addresses but may observe whatever state earlier calls have left behind.

This establishes the caller’s control flow, not preservation of object contents or shared state by any dependency.

## Side effects

### Direct effects

The routine directly:

- Reads the shared multiplier as part of the two initial product expressions.
- Reads the first 32-bit word of A.
- Reads the first 32-bit word of B.
- Compares the object addresses on the both-negative path.
- Returns a normalized status.

No direct writes to object memory or shared memory are shown.

The internal change that selects B as the target of certain final calls does not write a pointer into either object or into caller-owned storage.

### Dependency-mediated effects

All externally visible mutation beyond the initial reads is delegated to dependencies. Their implementations are unavailable.

In particular, this contract does not assume that dependencies:

- Preserve either object.
- Preserve the shared multiplier or other globals.
- Avoid allocation or deallocation.
- Preserve ownership.
- Leave prior changes undone when returning a nonzero status.
- Are reentrant or thread-safe.

A nonzero result stops later calls; it does not establish rollback. Earlier calls may already have changed externally visible state.

### Ownership and lifetime

No allocation, release, retain, or ownership transfer is directly visible in this routine. Passing a pointer to a dependency does not, by itself, establish that dependency’s ownership contract.

Callers must satisfy the lifetime and access requirements of every dependency reached by the selected path. Those requirements remain documented_only because the dependency bodies are not supplied.

### Invalid inputs and exceptional completion

There are no explicit null checks, bounds checks, object-format checks, or recovery handlers.

Invalid initial pointers may fail during the initial reads. Invalid dependency inputs may fail later. The evidence does not define a returned status for memory faults, exceptions, nonlocal exits, or dependency calls that do not return normally.

## Acceptance examples

These are conditional acceptance cases derived from static evidence, not observed executions. Unless stated otherwise, every dependency returns normally and every status result is zero.

### Zero first product still requires both initial reads

Given X = 0 and a readable B:

- The routine obtains Y before returning.
- No dependency is called.
- The result is 0 regardless of Y.

An implementation that skips B’s initial read because X is zero would not preserve the established access sequence.

### Zero second product delegates directly

Given X = 7 and Y = 0:

- The only dependency call is F-a743bb08af07(A, B).
- A result of 0 yields 0.
- Results of 1, 2, or the all-ones 32-bit value each yield 1.

### Positive one is not the zero shortcut

Given X = 7 and Y = 1:

- The only dependency call is F-762df453eb50(A, B).
- F-a743bb08af07 is not called.

### Negative products with distinct addresses

Given X = −3, Y = −4, and A different from B, the successful sequence is:

1. F-9128d4a7b39b on B.
2. F-9128d4a7b39b on A.
3. F-762df453eb50 on A, B.
4. F-268334470dda on B.
5. F-268334470dda on A.

The result is 0. If the third call instead returns nonzero, the result is 1 and neither of the final two calls occurs.

### Negative products with the same address

Given A equal to B and both observed products negative:

- F-9128d4a7b39b is called once on the shared address.
- F-762df453eb50 receives that address in both argument positions.
- F-268334470dda is called once on the shared address.
- All-zero statuses yield 0.

There is no second per-object call merely because the address occupies two argument positions.

### Negative X, positive Y, negative comparison

Given X = −3, Y = 4, and a negative result from F-61e238108dfa(B, A), the successful sequence is:

1. F-268334470dda on A.
2. F-61e238108dfa on B, A.
3. F-d0b1d84c27e6 on A, B.
4. F-268334470dda on A.
5. F-268334470dda on B.

A nonzero result at step four returns 1 and suppresses step five.

### Positive X, negative Y, negative comparison

Given X = 3, Y = −4, and a negative comparison result:

1. F-268334470dda is called on B.
2. F-61e238108dfa is called on B, A.
3. F-d0b1d84c27e6 is called on A, B.

A zero status at step three yields 0 immediately. No final per-object call occurs.

### Comparison equality takes the nonnegative branch

For opposite-sign products, a comparison result of zero selects F-9c6cf2acef37(B, A).

After that call succeeds:

- Negative X and positive Y lead to F-268334470dda(A).
- Positive X and negative Y lead to F-268334470dda(B).

### Incoming unused arguments do not select behavior

For the same valid object state, multiplier observations, and dependency behavior, changing only the third or fourth incoming argument does not change the established call sequence or return value.
