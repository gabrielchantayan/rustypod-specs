# F-78a6ba689c62

## Purpose

F-78a6ba689c62 searches a linked structure using a supplied 32-bit value. It then either reports a selected position or calls F-52c957c08a17 and reports the post-call contents of temporary storage. The caller receives a four-byte result followed by a one-byte path indicator.

**Established behavior:** the indicator is zero only when the function reports a position without calling F-52c957c08a17. It is one after either call site for F-52c957c08a17 returns normally and execution reaches the output stores.

**Inferred intent:** the structure resembles a binary search tree with a header or sentinel. The control byte appears to select whether an existing-position check is required. Searching, predecessor selection, duplicate detection, and insertion are useful interpretations, not established semantics of the dependencies.

The indicator does not independently establish insertion success. Nor does calling F-52c957c08a17 establish that the dependency initialized its output argument: the reported word is whatever that temporary contains after the call.

## Behavior

### Initial search and temporary initialization

The retained search decision starts at one.

The function first reads the header address from structure offset 16 and reads the initial position from that header’s offset 4. It then separately rereads structure offset 16 to obtain the fallback candidate. These reads are not one atomic or stable snapshot.

Two distinct four-byte temporaries matter to later calls:

- The **early-output word**, passed to the early F-52c957c08a17 call.
- The **general-output word**, passed to the general F-52c957c08a17 call and also used as boundary storage.

Neither has established initialization before the search loop. At the start of **every** iteration, both words are set to zero, before the search comparison is called.

Consequently, after a nonempty search both have been initialized to zero. After an empty search, neither has established initialization at that point.

### Linked search

For each nonnull position, after zeroing those two words, the function calls F-98d1a792da29 with:

1. Structure address plus 25.
2. The original supplied value.
3. Current position plus 16.

The 32-bit result is distinguished only as zero or nonzero. Signed ordering is not used.

After the call, the current position becomes the remembered candidate. The next position is then read:

- Zero result: use the four-byte link at offset 12.
- Nonzero result: use the four-byte link at offset 8.

The link read follows the dependency call, so mutations made by that call can affect traversal.

When a null next position ends the search, the remembered candidate is the last visited record. If the search was empty, it is the fallback header from the second structure-field read. The retained decision is the last comparison result, or one for an empty search.

### Control byte and candidate preparation

Only after the search finishes does the function read the byte at structure offset 24.

A nonzero byte proceeds directly to the general F-52c957c08a17 call. No boundary check, adjustment, or existing-position comparison occurs.

For a zero byte, a separate temporary position is initialized to the remembered candidate.

If the retained search decision is zero, boundary checking and adjustment are skipped. Otherwise:

1. Structure offset 16 is read again.
2. The four-byte word at that header’s offset 8 is read into the general-output word, replacing its previous contents.
3. F-a1ecaae6738a receives the address of the temporary position and the address of the general-output word.

Both arguments designate writable temporary storage. Their contents after the call cannot be assumed unchanged.

If F-a1ecaae6738a returns nonzero, execution takes the early F-52c957c08a17 path. If it returns zero, execution adjusts the temporary position using its then-current contents.

### Early dependency path

The early call to F-52c957c08a17 receives, in order:

1. Address of the early-output word.
2. Original structure address.
3. A 32-bit literal zero.
4. Remembered search candidate.
5. Original supplied value.

The early-output word is zero on entry after a nonempty search. After an empty search, it has no established initialization. Loading and exposing the separate boundary word does not initialize this early-output word.

If the call returns, the function copies the early-output word’s post-call contents to result offset 0, then writes indicator one at offset 4. It does not perform adjustment or the existing-position comparison.

F-52c957c08a17 may read, partially modify, completely replace, or leave unchanged the supplied storage; its implementation is unavailable. In particular, an unchanged zero on a nonempty-search path is not evidence that the dependency wrote zero.

### Position adjustment

Adjustment occurs only after a nonzero retained search decision, a zero control byte, and a zero result from F-a1ecaae6738a.

First, the function reads the temporary position’s metadata byte.

If that byte is zero, it reads the position’s offset-4 link and then the referenced record’s offset-4 link. If the second link equals the temporary position, the position is replaced by its offset-12 link. This completes adjustment.

Otherwise, the ordinary adjustment proceeds. Its repeated reads are significant:

1. Read the position’s offset-8 link and retain that first pointer.
2. Separately reread the same offset-8 field to select climbing or descent.

If the **second** read is null, the first pointer is discarded and climbing begins. If the second read is nonnull, descent begins using the **first** pointer, not the second.

**Climbing:** read the starting position’s offset-4 parent-like link. For each examined parent, read its offset-8 link and compare it with the previous temporary position. Then replace the temporary position with that parent, even when the comparison is unequal. An unequal comparison ends climbing. An equal comparison causes the parent’s offset-4 link to be read for the next iteration.

**Descent:** each iteration first replaces the temporary position with the retained pointer. It then reads that position’s offset-12 link as the possible next pointer and separately rereads the same field for the continuation condition. A null second observation ends descent at the current position. A nonnull second observation continues using the pointer from the first observation.

With agreement between repeated observations, descent follows offset-12 links to a record whose offset-12 link is null. Without agreement, that simplified description does not hold. For example, a null first pointer followed by a nonnull continuation observation can cause the next iteration to attempt a null-based access. Conversely, a nonnull first pointer followed by a null continuation observation is not followed.

No stability, synchronization, or safe behavior under such changing observations is established.

If no intervening effect changes that word, F-52c957c08a17 receives storage containing the replacement value. If it leaves that storage unchanged, the replacement is reported with indicator one.

### Existing position without adjustment

### Repeated offset-8 observations disagree

Suppose ordinary adjustment first reads one nonnull pointer at offset 8, then separately reads a different nonnull pointer there. Descent starts at the first pointer. If the second observation is instead null, climbing is selected and the first pointer is discarded.

### Repeated descent observations disagree

Suppose a descent iteration first reads a nonnull offset-12 pointer but its second read is null. Descent stops at the current record; the first pointer is not followed.

### Adjustment does not replace the insertion candidate
