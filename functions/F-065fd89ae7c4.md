# F-065fd89ae7c4

## Purpose

F-065fd89ae7c4 conditionally adjusts a four-word state snapshot associated with an object, records a branch-specific value in that object, and invokes an object-provided callback. Some adjustment paths also invoke F-4dbae9395e1f.

The established behavior is a comparison followed by one of four adjustment paths. Interpreting the four words as geometric coordinates, or interpreting the request as a width, is plausible but not established. This contract therefore uses neutral names.

The function returns a 64-bit value assembled from two 32-bit temporary words. It does not directly return a success flag or a callback result.

## Interface

### Inputs

The function receives:

- **Object:** a pointer to storage accessed in 32-bit words. The same pointer is passed to both dependencies.
- **Request:** a 32-bit integer used in comparisons, additions, subtractions, and selected object-field writes.

The following object locations are relevant. Byte offsets are relative to the object pointer.

| Byte offset | Width | Role |
|---|---:|---|
| 0 | 32 bits in the supplied representation | Value used to locate the callback dispatch structure |
| 84 | 32 bits | Secondary classification |
| 88 | 32 bits | Secondary adjustment destination |
| 108 | 32 bits | Primary classification |
| 112 | 32 bits | Primary adjustment destination |
| 128 | 32 bits | First snapshot word |
| 132 | 32 bits | Second snapshot word |
| 136 | 32 bits | Third snapshot word |
| 140 | 32 bits | Fourth snapshot word |

The supplied representation uses four-byte integer slots. Pointer width, address interpretation, alignment requirements, and the callback ABI are not independently established.

For the remainder of this contract:

- **Start** means the temporary initialized from offset 128.
- **Companion** means the temporary initialized from offset 132.
- **End** means the temporary initialized from offset 136.
- **Trailing** means the temporary initialized from offset 140.

These names identify values and temporary storage, not private source identifiers.

### Output

The output is a 64-bit bit pattern:

- Bits 31–0 come from the final value of Start.
- Bits 63–32 come from the final value of Companion.

This is bit concatenation, not sign extension of Start. For example, a Start bit pattern of `0xFFFFFFFF` and a Companion bit pattern of `0x12345678` produce `0x12345678FFFFFFFF`.

The function does not use either dependency’s return value.

### Preconditions

The caller must supply readable storage for the locations actually accessed on the selected path. Adjustment paths that perform an object-field write also require writable storage at the selected destination.

Every non-no-op path requires a valid callback dispatch arrangement. The function obtains the dispatch base from the object’s first word and resolves an indirect callback at byte offset 104 within that dispatch structure.

The supplied body contains no null checks, bounds checks, dispatch validation, or explicit arithmetic-overflow handling. Invalid storage, invalid callback targets, and out-of-range signed arithmetic have no established recovery behavior.

## Behavior

### Initial snapshot and early exit

The function first reads four object words into temporary storage, in this order:

1. Offset 128 into Start.
2. Offset 132 into Companion.
3. Offset 136 into End.
4. Offset 140 into Trailing.

These reads precede the request comparison. Consequently, even an invocation that performs no adjustment still reads all four words.

It then compares the difference End minus Start with Request.

If they are equal, the function immediately constructs its return value from Companion and Start. On this path:

- Neither classification field is read by the shown body.
- Neither adjustment destination is written.
- The indirect callback is not invoked.
- F-4dbae9395e1f is not invoked.

The equality decision uses the captured values, not a later reread of the object.

### Classification matching

If the initial difference does not equal Request, branch selection begins.

Classification values are compared after applying the 32-bit mask `0xFFFFFFDF`. This clears bit 5 and retains all other bits. Accordingly:

- A masked match with `0x80000001` accepts either original bit pattern `0x80000001` or `0x80000021`.
- A masked match with `0x80000008` accepts either original bit pattern `0x80000008` or `0x80000028`.

Other differing bits are not ignored.

The primary classification is evaluated before the secondary classification. A successful primary match prevents any secondary-classification read.

The two primary tests are separate source-level field evaluations. If the first primary test fails, the primary field is evaluated again for the second test. Under ordinary, stable object storage, both evaluations see the same value. Concurrent mutation, volatile semantics, and exact machine-load behavior are not established.

### Path A: primary absolute-style match

If the primary classification, after masking, equals `0x80000001`:

1. The function writes Start plus Request to the 32-bit destination at offset 112.
2. It assigns Start plus Request to the End temporary.
3. It invokes the indirect callback.
4. After the callback returns, it invokes F-4dbae9395e1f.

Start is not directly changed on this path. The write to offset 112 occurs before callback dispatch.

The description “absolute-style” is only a mnemonic for the stored expression; it does not establish the application meaning of that field.

### Path B: primary request-style match

If Path A does not match, but the primary classification, after masking, equals `0x80000008`:

1. The function writes Request to the 32-bit destination at offset 112.
2. It assigns Start plus Request to End.
3. It invokes the indirect callback.
4. After the callback returns, it invokes F-4dbae9395e1f.

This path differs from Path A in the value written to offset 112. Both prepare the same End value from the same initial Start and Request.

### Path C: secondary request-style match

If neither primary test matches, the function reads the secondary classification at offset 84.

If its masked value equals `0x80000008`:

1. The function writes Request to the 32-bit destination at offset 88.
2. It assigns End minus Request to Start.
3. It leaves End at its captured value.
4. It invokes the indirect callback.
5. After the callback returns, it invokes F-4dbae9395e1f.

This is the only shown adjustment path that directly changes Start before invoking the callback. It does not directly write offset 112.

### Path D: unmatched classifications

If neither primary test nor the secondary test matches:

1. Neither adjustment destination is written by the shown body.
2. The function assigns Start plus Request to End.
3. It invokes the indirect callback.
4. It does not invoke F-4dbae9395e1f.

This is not an error or rejection path in the supplied body. An unmatched classification still produces a callback invocation.

### Callback invocation and return construction

Every non-no-op path makes one indirect callback invocation with three arguments:

1. The original object pointer.
2. A pointer to Start in temporary storage.
3. The integer value 1.

Before this call, the temporary values have the branch-specific state described above. Companion and Trailing have no direct assignments after their initial reads.

The callback receives a writable pointer to temporary storage. The function subsequently constructs its return value from the temporary values, rather than returning a saved copy of the original Start. Therefore, a callback modification of Start can affect the returned low 32 bits.

The supplied representation also suggests that the four snapshot words form adjacent temporary storage. The precise extent that the callback may validly access is not established by its untyped call site. In particular, Companion must not be assumed immune to dependency effects merely because this function makes no further explicit assignment to it.

Where F-4dbae9395e1f is selected, it runs after the callback and before return construction. No preservation guarantees for either dependency are supplied.

## Side effects

### Direct object writes

The shown body directly writes at most one object location:

| Selected path | Direct destination | Stored value |
|---|---|---|
| Initial equality | None | None |
| Path A | Offset 112 | Captured Start plus Request |
| Path B | Offset 112 | Request |
| Path C | Offset 88 | Request |
| Path D | None | None |

The shown body does not directly write the four snapshot source locations at offsets 128–140. Changes to those object locations, if any, would have to arise from dependencies or external activity.

### Observable ordering

The source-level order is:

1. Four snapshot reads.
2. Initial difference comparison.
3. Classification reads required by the selected path.
4. A branch-specific object write, if applicable.
5. Preparation of the changed temporary endpoint.
6. Callback dispatch lookup and invocation.
7. F-4dbae9395e1f, if selected.
8. Return-value construction.

Thus, a normally invoked callback can observe the branch-specific destination write already completed. F-4dbae9395e1f, when called, runs after any callback effects.

This order is not a synchronization guarantee. The supplied body establishes no locking, atomicity, or concurrent-access protocol.

### Ownership and lifetime

The shown body performs no explicit allocation or release. The object remains caller-supplied storage; no ownership transfer is declared.

The callback is given temporary storage, not the address of the object’s offset-128 field. There is no demonstrated ownership transfer for that temporary storage. Its validity after this invocation returns is not established.

No claim is made that either dependency avoids allocating, releasing memory, retaining pointers, modifying global state, or modifying the object.

### Errors and abnormal completion

There is no explicit error return or validation failure branch.

If a dependency fails to return normally, the supplied body provides no rollback or cleanup behavior. A destination write made before callback invocation may already have taken effect. The precise behavior of faults, exceptions, or other nonlocal transfers is documented_only.

## Acceptance examples

These examples are conditional static acceptance cases, not results from executed tests. Arithmetic examples use values well within the signed 32-bit range.

Unless stated otherwise, assume that dependencies return normally and do not alter the temporary words used to construct the return value.

### 1. Equality bypasses classification and dispatch

Given:

- Start = 10.
- Companion = `0x12345678`.
- End = 30.
- Request = 20.

The difference equals Request. The result is `0x123456780000000A`.

All four snapshot words are read. No classification read, direct destination write, callback, or F-4dbae9395e1f call is required on this path.

### 2. First primary match stores the computed endpoint

Given Start = 10, End = 30, Request = 7, and primary classification `0x80000001`:

- Offset 112 receives 17.
- The callback receives a temporary state whose Start is 10 and End is 17.
- F-4dbae9395e1f follows the callback.
- The returned low word is 10 under the dependency assumptions above.

Changing only the primary classification to `0x80000021` selects the same path.

### 3. Second primary match stores the request

With the same snapshot and request, but primary classification `0x80000008`:

- Offset 112 receives 7, not 17.
- The prepared End is still 17.
- The callback and F-4dbae9395e1f both run, in that order.

A matching secondary classification does not override this primary match and need not be read.

### 4. Secondary match moves Start instead of End

Given Start = 10, End = 30, Request = 7, an unmatched primary classification, and secondary classification `0x80000028`:

- Offset 88 receives 7.
- Prepared Start becomes 23.
- End remains 30.
- The callback precedes F-4dbae9395e1f.
- The returned low word is 23 under the stated dependency assumptions.

### 5. Unmatched classifications still invoke the callback

Given Start = 10, End = 30, Request = 7, with both classifications unmatched:

- Neither destination receives a direct write.
- Prepared End becomes 17.
- The callback runs once.
- F-4dbae9395e1f does not run.

An implementation that simply returns for unmatched classifications would not match the supplied behavior.

### 6. Zero and negative requests are not rejected

If Start = 10, End = 30, and Request = 0, the equality bypass does not apply. Classification processing and callback invocation still occur.

For Request = −5 on Path C, prepared Start becomes 35. The body contains no rule requiring Start to remain below End or requiring Request to be nonnegative.

### 7. Callback mutation can change the return

On Path D, suppose the callback writes 99 through its pointer to Start. If that value remains unchanged until return construction, the returned low 32 bits are 99, not the initially captured Start.

### 8. Signed overflow is not an accepted wraparound example

A case requiring a mathematical result outside the signed 32-bit range cannot be assigned a reliable wrapped result from this evidence alone. It remains documented_only pending target arithmetic evidence.

## Uncertainties

- **Arithmetic overflow:** The supplied expressions use 32-bit integer values, but do not establish reliable wraparound semantics for overflowing signed addition or subtraction. This affects both the initial comparison and endpoint preparation.
- **Temporary layout:** Four copied words and a pointer to the first are established. A four-word callback payload is strongly suggested, but its complete layout and valid access extent are not independently specified.
- **Callback ABI:** Pointer width, calling convention, argument typing, and result type are not established beyond the shown invocation.
- **Dependency preservation:** Neither dependency is known to preserve object fields, global state, temporary contents reachable through supplied or retained pointers, or memory ownership.
- **Application meaning:** Coordinate, interval, dimension, and anchoring interpretations are inferred intent, not established requirements.
- **Concurrency:** No supported concurrent-access model is supplied.
- **Invalid inputs and abnormal completion:** No defined error mapping, rollback, or recovery behavior is supplied.

Each unresolved item is documented_only, not an implied requirement to invent validation or fallback behavior.

## Evidence

The established behavior above comes solely from static inspection of the supplied function representation: four initial 32-bit reads, an early difference comparison, masked classification tests, branch-specific writes and temporary updates, one indirect callback on adjustment paths, conditional invocation of F-4dbae9395e1f, and concatenation of two 32-bit words into a 64-bit result.

Inferred intent is explicitly separated from those operations. Dependency internals, machine-level overflow behavior, full temporary-layout guarantees, and runtime failure behavior remain unknown.

No runtime tests have been performed.
