# F-60d9a4d52916

## Purpose

F-60d9a4d52916 coordinates shared flag updates, dependency calls, status encoding, arithmetic, and an invocation-local 256-byte workspace. It accepts five signed 32-bit inputs and returns an unsigned 32-bit word if execution reaches the return fragment.

The established behavior is a globally controlled dispatcher, not a fixed initialization/process/finalization sequence. Fragments may repeat, occur in different orders, or remain unreachable. Dependencies may change globals that later fragments read.

Initialization, acquisition, processing, and finalization are possible interpretations of particular operations. They do not establish resource ownership, successful completion, or a lifecycle contract.

## Interface

### Inputs and return value

All five inputs have signed 32-bit representations. Their domain meanings are unknown; they may represent scalar values, encoded addresses, handles, or selectors.

The first four inputs are saved at entry. Selector 32 subsequently distributes them into working state:

| Input | State populated by selector 32 |
|---|---|
| First | Context-source slot |
| Second | Saved second-input argument |
| Third | Saved third-input argument |
| Fourth | Saved fourth-input context |
| Fifth | Arithmetic intermediate |

These assignments occur only if selector 32 is reached. In particular, entry alone does not populate the corresponding working slots.

Return storage starts at zero. Selector 1 replaces both the arithmetic accumulator and return storage with a global coefficient multiplied by the incoming carry captured at the start of that dispatcher iteration. Selector 16 returns the stored result.

The returned word is therefore zero if no result assignment has occurred, or the most recently assigned product otherwise. It is not necessarily the latest status, token, accumulator, or carry. No success/failure interpretation is established.

### Local storage and terminology

The following names describe behavioral roles, not domain types:

- **Working context:** first argument of several dependencies.
- **Current argument:** another frequently forwarded argument.
- **Peer argument:** copied into saved working-argument state during selector 9.
- **Third-argument slot:** argument 3 of F-18c727f817dc.
- **Saved working argument:** argument state consumed by several calls and snapshotted by selector 20.
- **Auxiliary argument:** forwarded during token construction.
- **Final-call snapshot:** selector 20’s snapshot of the saved working argument.
- **Accumulator:** a 32-bit arithmetic value also overwritten by shared-flag operations.
- **Arithmetic intermediate:** receives the fifth input and later predicate calculations.
- **Saved arithmetic/status value:** receives either encoded status or a calculated product.
- **Encoded status**, **stored status**, and **saved status-related word:** distinct values.
- **Token** and **retained acquisition result:** distinct dependency-related values.

These slots start at zero. The persistent branch selector also starts at zero. The initial dispatch state instead comes from a global.

Two buffer pointers start null. A separate, uninitialized 256-byte workspace has invocation-local lifetime. Four additional 32-bit slots remain zero throughout the visible local assignments.

The representation uses 32-bit address-like expressions. Validity on wider-address systems is not established.

## Behavior

### Dispatch, reads, and carry

Every iteration performs these operations before selecting a fragment:

1. Snapshot incoming carry, working context, and auxiliary argument.
2. Read two global continuation values.
3. Calculate the unsigned selector from incoming dispatch state plus a global offset.
4. Load global fallback dispatch state.
5. Load global fallback carry.
6. Check whether the selector is at most 32.

The selector uses the incoming state, not the fallback state just loaded. All these reads occur even when selector 16 immediately returns.

A selector above 32 executes no fragment and begins another iteration with fallback state and carry. This is not an error return. Termination is unknown.

Most fragments restore the incoming carry snapshot. Exceptions are:

| Selector | Outgoing carry |
|---|---|
| 2, 9, 19 | Calculated predicate intermediate |
| 8 | Zero |
| 13, 21 | Calculated product |
| 18 | Already loaded fallback carry |
| 23 | Already loaded fallback carry; fallback state is also retained |
| 31 | Result of the unmapped dependency |

Selector 1 uses incoming carry for its product and restores that carry afterward. Selector 18 replaces dispatch state but leaves fallback carry intact.

Missing global values prevent deriving a complete execution trace, guaranteed reachability, or a termination bound.

### Shared flags and accumulator effects

A global supplies a shared structure address. Direct flag accesses use its 32-bit word at byte offset `0x80`.

Each update reads the flag word, ORs a mask into it, stores the **complete resulting word in the accumulator**, and writes that word back:

| Selector | Added mask | Further operation |
|---|---|---|
| 3 | `0x00010000` | F-d1228fe0890f receives interior address `+0xE0`, then 15 |
| 22 | `0x04000000` | Save interior address `+0x10C` as current and auxiliary arguments; call F-d1228fe0890f with that address and 9 |
| 24 | `0x00040000` | No dependency call |
| 28 | `0x08000000` | No dependency call |
| 29 | `0x02000000` | Set current argument to interior address `+0x18C`; call F-d1228fe0890f with that address and 15 |

Selector 3 likewise sets the current argument to its `+0xE0` interior address. Each callback-bearing fragment writes the flag word before calling the dependency.

Flag-test fragments instead store the **masked bit value**, not the full word or a Boolean, in the accumulator:

| Selector | Mask | Continuation if absent | Continuation if present |
|---|---|---|---|
| 4 | `0x08000000` | Global continuation | Continuation −23 |
| 5 | `0x00010000` | Global continuation | Continuation +27 |
| 10 | `0x00040000` | Global continuation | Continuation −20 |
| 30 | `0x04000000` | Global continuation | Continuation +7 |
| 32 | `0x02000000` | Global continuation | Continuation +17 |

Selector 32 also performs the input transfers described above and sets the persistent branch selector to one. Its accumulator remains zero or `0x02000000`; temporary branch calculations do not replace that masked value.

These local effects matter independently of memory updates and branches. A later selector can multiply this accumulator into a dependency argument, overwrite the token with that argument, or derive saved status-related state from it.

The updates are not established atomic operations. They preserve other bits from the word read, but concurrent changes can be lost. Test-before-update ordering, one-time initialization, and rollback are not established.

### Status representation and predicates

Signed 16-bit dependency results are multiplied by 235 and reduced to their low eight bits. F-4ee4bec28566 instead supplies a stored 32-bit result; encoding uses its signed-16-bit view.

Decoding multiplies a signed-16-bit view of the relevant status by 195 and retains the low byte. Since \(235\times195\equiv1\pmod{256}\), this recovers the original low byte, not the full dependency result.

Selector 25 assigns encoded status `0xEB`; selector 11 assigns `0x6D`. These decode to 1 and 7 respectively. Their meanings are unknown.

For precise predicate relationships, let \(A,B,C,D\) designate the four global coefficient roles, \(E\) the encoded status, and

\[
R=\mathop{\sim}(195\,\operatorname{s16}(E))\mathbin{\vert}255.
\]

The OR forces all low eight bits of \(R\) to one. It is not byte extraction.

Selectors 2, 9, and 19 establish arithmetic intermediate \(CE+D+B\mathop{\sim}R\), then accumulator equal to that intermediate plus \(DR\). Selector 8 instead establishes intermediate \(CE+2B+B\mathop{\sim}R\), then accumulator equal to that intermediate plus \(2BR\).

Selectors 2, 8, and 19 combine accumulator products using \(A\) and \(A\) XOR its explicitly signed right shift by 29. Selector 2 extracts bit 31 after complementing the combined word; selectors 8 and 19 extract it without that complement.

Selector 9 uses the coefficient \(A\) captured after F-18c727f817dc, combined with a later coefficient expression involving \(D\) shifted by 31. The signedness of that latter shift remains unresolved. These predicates are not interchangeable success/failure tests.

Predicate bit one chooses an unadjusted continuation; bit zero chooses adjustments −31, −2, −14, and −5 for selectors 2, 8, 9, and 19 respectively.

Unsigned 32-bit operations wrap modulo \(2^{32}\). The representation also contains signed arithmetic whose overflow-sensitive interpretation requires additional machine-level evidence. The 16-bit status multiplications themselves fit signed 32-bit range.

## Acceptance examples

These are conditional static criteria, not executed tests. Each assumes the stated fragment history is reachable and all reached accesses are valid.

1. **Flag update also changes arithmetic state.** If selector 3 reads flags `0x00000008`, both its accumulator and direct flag write become `0x00010008`. The write precedes F-d1228fe0890f.

2. **Masked value survives branch calculation.** If selector 32 reads a word containing `0x02000000`, its accumulator becomes exactly `0x02000000`, regardless of other set bits. It selects continuation +17, saves the input-derived state, and restores incoming carry.

3. **Context replacement timing.** If selector 0 begins with working context \(X\) and saved fourth-input context \(Y\), its dependency executes before working context becomes \(Y\). If selector 2 later begins with context \(Z\), it assigns \(Z\) to both current and peer arguments.

4. **Saved status transfer.** If selector 8 saves encoded status `0xEB` and selector 13 later consumes it without intervening replacement, selector 13 copies `0xEB` into saved status-related word and uses that value in its product.

5. **Second input reaches the unmapped call.** Selector 32 can save the second input; selector 13 can copy it into peer argument; selector 9 can copy that peer into saved working argument; selector 20 can snapshot it. A subsequent selector 31 receives this snapshot as its unmapped dependency’s first argument. Selector 20’s arithmetic calculation does not replace that snapshot.

6. **Snapshot is not live forwarding.** After selector 20 snapshots value \(V\), selector 27 may replace saved working argument with a global value. Without another selector 20, the final-call snapshot remains \(V\).

7. **Buffer divergence.** Selector 14 before workspace selection copies null. A later selector 27 alone leaves call buffer null while selected buffer designates the workspace.

8. **Status truncation.** Results 1 and 257 both encode as `0xEB` and decode to 1. Result −1 encodes as `0x15` and decodes to `0xFF`; no failure interpretation follows.

9. **Fallback affects return arithmetic.** Selector 33 executes no fragment but retains the already loaded fallback state and carry. A following selector 1 uses that fallback-derived incoming carry.

10. **Return and marker boundaries.** Selector 16 returns zero absent a preceding selector 1, after dispatcher fallback reads. A workspace-directed selector 11 writes only byte 248 after assigning encoded status `0x6D`.
