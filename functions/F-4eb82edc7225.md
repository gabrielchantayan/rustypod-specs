# F-4eb82edc7225

## Purpose

F-4eb82edc7225 conditionally processes a selector and a secondary value using shared state and external dependencies. Its two principal paths are:

- **Higher mode:** invoke an initial processing dependency, optionally initialize an object chain, then conditionally submit an allocated record or acquire and attach an object.
- **Lower mode:** conditionally consume a per-value indication, invoke an optional callback, construct packed local state, and conditionally expose a local descriptor to dependencies.

“Mode,” “selector,” “root,” and “pending indication” describe observable roles, not established application semantics.

The function has no explicit return value. Its rejection gates and early exits do not publish a success or failure status.

## Interface

### Inputs and result

| Input | Width | Observable use |
|---|---:|---|
| Selector | 32 bits | Optional remapping, byte-table indexing, and an argument to F-5b5a9d2f3a16 |
| Secondary value | 32 bits | Forwarded unchanged to dependencies and tested against zero |

Preliminary processing produces a **resolved value**, also 32 bits. That value becomes a dependency argument and, in lower mode, an index into several byte tables.

Neither input is visibly range-checked before the initial selector-table access. No valid selector or resolved-value domain is established. In particular, a later rejection does not prevent the initial lookup read.

There is no explicit error result, returned pointer, or ownership result.

### Preconditions

Every executed memory access requires accessible storage of the appropriate size and permissions. There are no visible null checks for the control object, initial traversal root, callback-state object, or allocated record before their relevant accesses.

Both chain traversals visit the initial root before checking a link. A null initial root is therefore not an empty-chain case.

Traversal terminates only on a null link or a link back to the original traversal root. A reachable cycle excluding that root has no visible termination safeguard.

## Behavior

### Preliminary processing

The function first reads a shared remapping byte. When nonzero, the effective selector is changed as follows:

| Incoming selector | Effective selector |
|---:|---:|
| 0 | 4 |
| 1 | 2 |
| 2 | 1 |
| 4 | 0 |
| Other | Unchanged |

It then reads and saves one byte from the selector lookup table at the effective selector. This access precedes every rejection gate below.

The gates execute in this order:

1. F-unresolved-01 is called without visible arguments. A nonzero result returns immediately.
2. A shared object’s byte at +2 is read. Zero returns immediately.
3. F-5b5a9d2f3a16 receives the effective selector and original secondary value.
   - A zero result establishes resolved value zero and skips F-914bf0453123.
   - A nonzero result causes F-914bf0453123 to receive the saved lookup byte and secondary value. Its result becomes the resolved value. Zero from this dependency returns immediately.
4. F-491bc4d42a31 receives the resolved value and secondary value. A nonzero result returns immediately.

Thus zero resolution can continue only through the zero-result branch of F-5b5a9d2f3a16.

### Mode selection

F-c6d86aad08a0 supplies a value compared as unsigned 32-bit:

- A first result greater than 45 selects higher mode.
- Otherwise the dependency is called again. A second result below 41 returns; a second result of at least 41 permits lower-mode processing.

These are separate observations. The second result need not be at most 45. A first result of 45 followed by 46 still selects lower mode.

### Higher-mode processing

F-d03768eedb4b receives the resolved value, secondary value, and zero. This call occurs even when either input value is zero.

After the call, the shared control pointer is captured. If either the secondary value or resolved value is zero, the function returns without further higher-mode work.

#### Conditional preparation and control-pointer identity

The 32-bit flags at +20 are read through the shared control pointer. If bit 0 is clear, F-b255b26284e6 receives the address of that field.

There is **no intervening dependency call** between capture of the control pointer, the flags read through the shared pointer, and evaluation of the address passed to F-b255b26284e6. Consequently, dependency side effects cannot explain different control addresses at these three observations. In the absence of asynchronous modification, they refer to the same control object.

If F-b255b26284e6 returns nonzero:

1. F-f99b15cea102 receives the then-current shared root pointer.
2. F-804adc29bbfb receives its result and two shared operands, in their visible argument order.
3. F-d08d3ca17b81 receives the address at +20 of the **captured** control object.

The final address remains tied to the captured object even if preceding dependencies replace the shared control pointer. Shared operands loaded after a dependency may reflect that dependency’s changes. Possible asynchronous replacement between adjacent reads is separate from dependency-caused replacement; no synchronization is visible.

F-bb58811af262 then runs. Its result is saved, and the current shared root pointer is captured after that call.

#### Conditional chain initialization

The initialization byte at +2 is read from the captured control object. If zero:

1. F-a6b82b58e9b2 is called.
2. F-a9f18648147b receives that result, zero, and the captured root.
3. The then-current shared assignment value is written to the captured root’s 32-bit field at +28.
4. F-2b20f2572237 receives that root and 1.
5. Starting at the root, each visited object’s byte at +60 is cleared. Its next pointer at +64 is read **after** the write.
6. Traversal stops at null or a return to the original root.
7. The captured control object’s byte at +2 is set to 1.

The root is not reloaded during this sequence. Dependencies may modify its fields or links before traversal begins. The final marker assignment establishes a write, not a guarantee that unknown future calls preserve it.

#### Flag-selected record submission

A shared flag source is read to retain bit 0. The source is separately read to test bit 1.

If bit 1 is clear:

- Retained bit 0 clear: return.
- Retained bit 0 set:
  1. F-d33f6d597e5d receives 24.
  2. F-unresolved-02 receives its returned address and 24.
  3. The record words at +16 and +20 are assigned 500 and 2.
  4. Indirect dependency F-unresolved-03 receives 2, the record address, 5, and 0.
  5. Return.

No allocation-failure check is visible. No initialization of the other record bytes is established independently of F-unresolved-02.

The two flag reads are not one atomic observation. With no intervening dependency, any difference between them would require asynchronous modification or another behavior outside the visible sequential calls.

#### Acquisition and attachment

If the second flag read has bit 1 set:

1. Byte +62 of the currently captured root is assigned 0 if retained bit 0 is clear, or 2 otherwise.
2. The shared root pointer is read again and captured for subsequent attachment.
3. An associated-object pointer is read from +72 through the shared root pointer.
4. F-unresolved-04 receives the saved result of F-bb58811af262.
5. F-unresolved-05 is called without visible arguments.

The +62 assignment may target a different object from the later attachment root: dependencies since the earlier root capture may have replaced the shared root. There is no dependency between the later root capture and associated-pointer read; a difference there would require asynchronous change.

If acquisition returns zero, this function returns without explicit rollback, attachment calls, or the +61 traversal. **It does not guarantee preservation of earlier writes.** Calls between initialization, the +62 assignment, and the acquisition result may modify the affected objects.

For a nonzero acquired value:

1. F-e7094617a462 receives the acquired value and attachment root.
2. F-c1c76d9cc652 receives the acquired value.
3. The attachment root’s byte at +62 is read. If bit 1 is set, F-e282dcfd746e receives 500 and 2.
4. If the captured associated pointer is nonzero:
   - F-66c822b72d41 receives the acquired value and associated pointer.
   - The attachment root’s 32-bit value at +68 is read.
   - F-unresolved-04 runs again, with no arguments recoverable at this call site.
   - F-unresolved-06 receives that result, 1, the captured associated pointer, and the saved +68 value.
5. Starting at the attachment root, each visited object’s byte at +61 is set to 1. Its next pointer at +64 is read afterward. Traversal stops at null or return to that root.

The +62 test follows dependency calls and need not observe the value previously assigned by this function.

### Lower-mode processing

After the second mode call, the pending-state pointer is captured before the second mode result is tested. A result below 41 returns. A nonzero secondary value also returns.

The packed local contribution is initially zero.

Unless the resolved value is 126, its pending byte at structure offset +4 plus the resolved value is read. Zero returns. Value 126 bypasses that preliminary read.

For a nonzero resolved value, the shared counter is incremented and the corresponding pending byte is cleared. The counter access uses the shared pending-state pointer; the clear uses the previously captured pointer. No dependency intervenes between capture and these accesses, so dependency side effects do not create a discrepancy, although asynchronous replacement is unresolved.

Resolved value zero, if its pending byte permits continuation, neither increments the counter nor clears that byte.

#### Callback and packed state

The callback-state pointer is captured. A non-null function pointer at +8 causes F-unresolved-07 to receive zero, the resolved value, and the address at callback-state +1. Its result supplies a 32-bit packed contribution; absent a callback, that contribution is zero.

After the optional callback, the function:

1. Loads the shared descriptor-gating table base.
2. Reads byte +1 from the captured callback state.
3. OR-combines the callback contribution, that byte shifted left by 24 bits, and the resolved value shifted left by 16 bits.
4. Sets byte 0 of the captured callback state to 1.
5. Captures the shared alternate-state table base.

The callback may replace shared pointers or change callback-state bytes. The byte read and flag write nevertheless use the captured callback-state pointer.

The resolved value is not visibly masked to eight bits before shifting. The callback result is not masked either. The packed value therefore cannot generally be interpreted as independent, cleanly separated byte fields.

#### Descriptor gating, captures, and clearing destinations

The gating byte is read at the resolved-value index using the gating-table base loaded after the callback. A nonzero byte skips all descriptor work.

For a zero gating byte:

1. The current shared descriptor value is copied into the descriptor’s first word.
2. The alternate-state byte is tested using a **separate read of the shared alternate-state base**, not necessarily the captured base.
3. If that byte is nonzero, F-8c9273cab988 receives the descriptor address. On return, the descriptor’s first word is explicitly set to zero.
4. The other clearing-table base is loaded.
5. The alternate-state byte is cleared using the base captured **before the gating-byte test**.
6. The other table’s byte at the resolved-value index is cleared using the newly loaded base.
7. Descriptor words at +12 and +16 are assigned zero.
8. If the descriptor’s first word is nonzero, F-5836e250b35a receives the descriptor address and zero.

These destinations matter when F-8c9273cab988 changes shared pointers: alternate-state clearing still targets the old captured table, whereas the other clearing base is loaded after that call and can reflect its changes. Replacing the shared alternate-state pointer does not redirect the captured-base clear.

Under sequential execution without external mutation of the local descriptor, the alternate-state path suppresses the final descriptor call because the first word is forcibly zeroed after F-8c9273cab988. That dependency’s writes to other descriptor locations are not thereby undone.

## Side effects

Direct writes include the pending counter and per-value bytes, callback-state flag, control initialization marker, root fields, linked-object bytes, allocated-record fields, and local descriptor fields.

There is no visible explicit rollback, deallocation, exception translation, or error-status publication.

Passing the allocated record to F-unresolved-03 establishes pointer exposure, not ownership transfer. Retention, release, and responsibility for failed submission are **documented_only**.

Descriptor storage is local to this invocation. Dependencies receive its address, including access to locations without visible initialization. Whether they read those locations, retain the address, or arrange a longer lifetime is **documented_only**. No unknown dependency is assumed to preserve globals or pointed-to storage.

## Acceptance examples

These are conditional static criteria, not executed tests.

1. **Lookup precedes rejection.** With remapping enabled and selector 0, index 4 is read before F-unresolved-01 can reject processing.

2. **Zero resolution.** Zero from F-5b5a9d2f3a16 skips F-914bf0453123 and passes zero to F-491bc4d42a31.

3. **Higher-mode zero input.** First mode result 46 and secondary value zero still cause F-d03768eedb4b to run, followed by return before object preparation.

4. **Distinct mode calls.** Results 45 then 46 permit lower-mode processing. Results 45 then 40 return before lower-mode state changes.

5. **Captured control address.** Without asynchronous replacement, the control capture, flags read, and F-b255b26284e6 argument identify one object. If that dependency replaces the shared control pointer and returns nonzero, F-d08d3ca17b81 still receives the original captured object’s +20 address.

6. **Special pending value.** Eligible lower mode with resolved value 126 skips the preliminary pending-byte test, increments the counter, and clears its indexed pending byte.

7. **Zero pending value.** Eligible lower mode with resolved value zero and a nonzero pending byte reaches callback handling without incrementing the counter or clearing that pending byte.

8. **Circular traversal.** For a root followed by one object linking back to the root, each traversal writes its designated byte once per object and stops, assuming links remain unchanged.

9. **Zero acquisition result.** If F-unresolved-05 returns zero, there is no explicit rollback, attachment call, or +61 traversal. Earlier values remain only if intervening dependencies and external actors have not changed them.

10. **Descriptor pointer replacement.** Suppose the captured alternate-state base is A. F-8c9273cab988 replaces the shared alternate-state base with B and the other clearing base with C. Clearing still targets A at the resolved index and targets C for the other clear. The forced-zero first word suppresses final descriptor submission under the stated sequential-local-storage assumption.

11. **Record submission.** With higher-mode eligibility, second flag read bit 1 clear, and retained bit 0 set, the function requests 24 bytes, prepares the address, writes 500 and 2 at +16 and +20, then submits arguments 2, address, 5, and 0.
