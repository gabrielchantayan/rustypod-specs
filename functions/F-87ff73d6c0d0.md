# F-87ff73d6c0d0

## Purpose

F-87ff73d6c0d0 coordinates an object-associated handle, exchanges an embedded member through a virtual interface, publishes one obtained value to two destinations, and delegates a main operation.

Two preparation modes precede the common operation:

- **Zero mode:** performs context-dependent processing, optionally supplies a constructed value to the associated receiver, then asks that receiver to act on the embedded member. The member is validated afterward.
- **Nonzero mode:** validates the embedded member first, then supplies its address to the associated receiver.

A zero member-validation result reaches a dependency marked non-returning. Successful preparation leads to a byte write, two ordered publications, the main operation, optional post-operation signaling, and a final handle-related call.

These are observable roles, not established application semantics. In particular, “validation,” “publication,” and “handle” do not establish validity guarantees, ownership, or transactional behavior.

### Local storage and dispatch layout

The function supplies dependencies with five distinct four-byte local areas: one handle area, two conversion temporaries, and two auxiliary areas. A separate 20-byte local area is used in the optional zero-mode stage.

The representation shows no explicit initialization of those areas before their first dependency calls. Whether a dependency initializes them fully or requires existing contents is not established.

A resolved receiver is treated as having a virtual-table address in its first 32-bit word. Two virtual call sites use entries at table byte offsets:

- `0x1EC`, or `492`: D-01.
- `0x1F4`, or `500`: D-02.

Each receives the resolved receiver as its first argument and one additional argument.

## Behavior

### 1. Handle preparation and initial context snapshot

Before branching on the mode, the function calls F-eb24201e389b with the address of the four-byte local handle area and the object address plus `0xB4`.

After that call returns, it reads the context-address global and saves that address locally. This read occurs in both modes.

The saved address is used only by the optional second conversion in zero mode. It is **not** the address used for the first conversion. Nonzero mode performs the initial global read but does not itself dereference the saved context address.

The handle area is subsequently supplied to F-e38e6836b640 for receiver resolution and, on the normal completion path, to F-24edd96d1422.

### 2. Zero-mode context processing

#### First conversion: a fresh context-address read

When the mode is zero, the function separately reads the context-address global again. Through this freshly read address, it reads the 32-bit field at byte offset `4`.

It calls F-9b9c1c7483f4 with:

- The first four-byte conversion temporary’s address.
- The field value obtained through the fresh context address.
- The first four-byte auxiliary area’s address.

The conversion returns a 32-bit value.

Consequently, zero mode contains two context-address global reads before the first conversion completes: the initial saved read after handle preparation, and the later read used to access the first field. No dependency call intervenes between these two reads in the shown sequence. Their equality is nevertheless not established under external mutation.

#### Two distinct descriptor reads

After the first conversion returns, the function reads the descriptor global and saves that first descriptor value locally.

It then reads the descriptor global a second time and supplies this second value, together with the first conversion’s return value, to F-8094c3d72052.

These are distinct reads. No dependency call intervenes between them, but the contract does not collapse them into one snapshot:

- The **second descriptor read** supplies F-8094c3d72052.
- The **saved first descriptor read** supplies the later F-1b0572bf841e call, if reached.

After F-8094c3d72052 returns, the function calls F-8a5aadac202f on the first conversion temporary. Only after that call returns does it act on the saved predicate result.

#### Optional second conversion and D-01

If F-8094c3d72052 returned zero, the optional stage is skipped.

For a nonzero result, the function reads the 32-bit field at offset `4` through the **initially saved context address**. It does not reread the context-address global for this second conversion.

It calls F-9b9c1c7483f4 with the second conversion temporary, that newly read field value, and the second auxiliary area. It then calls F-1b0572bf841e with the saved **first descriptor value** and the second conversion’s return value.

Next, in order:

1. F-8a5aadac202f is called on the second conversion temporary.
2. F-e38e6836b640 resolves a receiver from the local handle.
3. F-1c06d0a5910b receives the 20-byte local area, the lookup result, and integer zero.
4. D-01 is invoked on the previously resolved receiver, with F-1c06d0a5910b’s returned value as its additional argument.
5. F-c1466ea05103 is called on the 20-byte local area.

Receiver resolution therefore precedes F-1c06d0a5910b. There is no second resolution between that call and D-01. The representation supplies no guarantee that F-1c06d0a5910b preserves receiver storage or its dispatch table.

The two context-field reads are also distinct. They can address different contexts, and even if the addresses match, the field is read again after intervening dependency calls. Neither field contents nor descriptor globals are assumed preserved by those calls.

#### Member exchange and validation

After the optional stage, or directly after the first temporary’s lifecycle call when the stage is skipped, the function:

1. Resolves a receiver through F-e38e6836b640.
2. Invokes D-02 on that receiver, passing the object address plus `0xD4`.
3. Calls F-b7abcf60c990 with that same member address.

This receiver resolution is separate from any optional-stage resolution; equality of the returned receivers is not guaranteed.

A nonzero validation result enters the common continuation. Zero reaches the failure path. Validation therefore occurs after D-02, not before it.

### 3. Nonzero-mode preparation

For every nonzero mode, the function first calls F-b7abcf60c990 with the object address plus `0xD4`.

If that result is zero, it reaches the failure path without resolving a receiver or invoking either virtual dependency.

Otherwise, it resolves a receiver through F-e38e6836b640 and invokes D-01 with the embedded member address as the additional argument. It then enters the common continuation.

This branch performs no context-field read, conversion, descriptor read, descriptor predicate, lookup, 20-byte construction, or D-02 call. The initial context-address global read still occurs.

There is no second validation after D-01. Any mutation performed by receiver resolution or D-01 does not cause a further F-b7abcf60c990 call here.

### 4. Common continuation and publication

After successful branch-specific preparation, the function directly writes one byte with value `1` at object offset `0xC6`.

It then calls F-7d1048432426 with the embedded member address and saves its 32-bit return value. This accessor is called once.

The function reads the first publication-destination global and invokes D-03 with that destination and the saved value. After the first D-03 call returns, it reads the second publication-destination global and invokes D-03 again with that destination and the same saved value.

Thus:

- The second destination is obtained after the first publication call.
- Both publications use one saved accessor result.
- A change to the member during the first publication does not trigger another accessor call.
- A change to the second destination global during the first publication affects the subsequently obtained destination.

The function then calls F-4fd087f2325e with the original object address and original mode, saving its result.

The byte write and both publications precede the main operation. A zero main-operation result does not cause an explicit rollback.

### 5. Conditional post-operation action and completion

The post-operation action requires all three conditions, evaluated with short-circuiting:

- The saved main-operation result is nonzero.
- The original mode is zero.
- F-3f2e817b9ef7, called with the embedded member address, returns nonzero.

Only if all hold does the function call F-fdd8589eca2d, then call F-b8a0e35a1400 with that returned value and integer `1`.

A zero main result or any nonzero mode prevents F-3f2e817b9ef7 from being called. A zero result from that predicate prevents both subsequent signaling calls.

Finally, the function calls F-24edd96d1422 on the local handle area and returns the saved main-operation result. Neither the signaling calls nor the final handle-related call replaces that saved result.

### 6. Failure path

A zero branch-specific F-b7abcf60c990 result leads to F-a817d8d58c10, which the supplied representation marks non-returning.

At this point the handle has already been prepared. Zero mode has also completed its context-processing stage and D-02 invocation; nonzero mode has performed neither virtual call.

This path does not reach the direct byte write, publications, main operation, post-operation signaling, or explicit normal-path F-24edd96d1422 call.

The failure dependency’s actual mechanism and any cleanup it performs are unknown. No normal result is established if it behaves as marked; behavior if it unexpectedly returns is not established by the supplied representation.

## Side effects

The only established direct write to the supplied object is the one-byte assignment at `0xC6`. Dependencies receive addresses permitting other effects, whose extent is not specified.

Global reads are observably distinct in the supplied representation:

- One saved context-address read in both modes.
- One additional context-address read in zero mode, used for the first field access.
- Two descriptor reads in zero mode.
- Two publication-destination reads after successful preparation, separated by the first publication call.

Explicit lifecycle-related calls occur on the conversion temporaries, the 20-byte temporary when constructed, and the handle on normal completion. These calls do not independently prove destruction, reference counting, ownership transfer, or release.

Each reached conversion temporary receives one F-8a5aadac202f call after its conversion result has been consumed. The auxiliary areas receive no separate explicit lifecycle call here. The 20-byte area receives F-c1466ea05103 after D-01 returns.

The function establishes no safe-retention contract for pointers into local storage. In particular, the later lifecycle call on the 20-byte area does not prove that D-01 copies its argument or may retain it.

Unknown dependencies may change globals, pointed-to memory, or external state. The specified ordering does not imply purity, atomicity, synchronization, or rollback.

## Acceptance examples

These are conditional static acceptance examples, not executed tests. Reached dependencies are assumed to return normally unless identified as non-returning.

1. **Distinct context addresses.** If the initial context-address read yields address A and the zero-mode reread yields address B, the first conversion receives the field read at B plus `4`. If the optional stage is taken, the second conversion receives a later field read at A plus `4`. The second conversion does not use a newly obtained context address.

2. **Distinct descriptor values.** If the first descriptor read yields X and the immediately following read yields Y, F-8094c3d72052 receives Y. If it returns nonzero, F-1b0572bf841e receives X. This example is conditional on such read results being possible; concurrency legality is not established.

3. **Optional stage skipped.** If F-8094c3d72052 returns zero, the first temporary’s lifecycle call still occurs. There is no second conversion, lookup, 20-byte construction, or D-01 call. D-02 and member validation follow.

4. **Optional stage taken.** For a nonzero descriptor predicate, the second temporary’s lifecycle call precedes receiver resolution. Resolution precedes F-1c06d0a5910b; D-01 precedes the 20-byte lifecycle call. A separate resolution then precedes D-02.

5. **Nonzero mode preserved.** With mode `-1` and successful member validation, D-01 receives the member address. F-4fd087f2325e receives `-1`, not `1`. The post-operation member predicate is skipped regardless of the main result.

6. **Validation failure.** A zero member-validation result invokes F-a817d8d58c10 without reaching the common byte write or normal-path handle lifecycle call. In zero mode D-02 has already occurred; in nonzero mode neither virtual call has occurred.

7. **Main result zero.** Successful preparation still produces the byte write and both publications. Post-operation checking is skipped, the final handle-related call occurs, and the returned result is zero.

8. **Signaling enabled.** In zero mode, a nonzero main result and nonzero post-operation predicate cause F-fdd8589eca2d followed by F-b8a0e35a1400. The original main result remains the normal return value.

9. **Publication mutates shared state.** If the first D-03 changes the second destination global and the embedded member, the second call uses the subsequently read destination but retains the previously saved publication value.

10. **Predicate changes the descriptor global.** If F-8094c3d72052 modifies that global and returns nonzero, the optional lookup still receives the first descriptor value saved before the predicate call.
