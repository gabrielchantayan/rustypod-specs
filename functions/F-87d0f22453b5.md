# F-87d0f22453b5

## Purpose

F-87d0f22453b5 processes a bounded sequence of 32-bit pending-entry words associated with a caller-supplied object. For each nonzero entry, it reads a corresponding control word, sets selected control bits, writes the updated control word, and then clears the pending entry.

One control-word state additionally causes three ordered notification writes before the control-word update. Other states select one of two bit masks, with a special selection rule for entry zero.

These operations are established by the supplied static evidence. Describing the entries as “pending,” the control words as device controls, or the notification writes as a command protocol is inferred intent, not an established external interface.

## Behavior

### Iteration and bound handling

Processing begins with index zero and proceeds in ascending order.

At each loop-condition evaluation, including the final unsuccessful evaluation:

1. The function loads the notification-base source and captures its value for that condition evaluation.
2. It reads the current 8-bit upper bound from object offset `0x1A`.
3. It enters the body only if the current index is less than or equal to that bound.

The bound is reread for each condition evaluation; it is not captured once at entry. A change to the bound can therefore change which later entries are visited, provided that change is visible to these accesses.

Because the bound cannot exceed 255, the body cannot execute for an index above 255. At most 256 entries are processed. Once index 256 is reached, the next condition fails regardless of the current bound value. The index does not approach its 32-bit wraparound point.

The comparison is represented as signed after conversion, but all reachable index values and all zero-extended bound values are nonnegative and small. Signedness does not change the admitted range here.

### Zero pending entries

For an admitted index, the function reads the 32-bit pending-entry word at object offset `0x5C + 4 × index`.

If that word is zero:

- No corresponding control word is read.
- No branch-specific notification or command write occurs.
- The pending-entry word is not rewritten.
- Processing continues with the next index.

The notification-base source has still been loaded during the condition evaluation.

### Nonzero pending entries

Every nonzero 32-bit pending value follows the same path, regardless of its other bits or signed interpretation.

The function reads the selected 32-bit control word once and decides between the following branches using that captured value.

#### Branch A: control bits 18 and 19 are both set

This branch is selected exactly when both bits 18 and 19 of the captured control word are one. Other bits do not affect this decision.

The function performs these actions in order:

1. It obtains the notification base again from the notification-base source and writes the 8-bit value zero at that base plus `0x04`.
2. It writes the 32-bit value `index OR 0x80` at offset `0x18` from the notification base captured during the loop-condition evaluation.
3. It writes the 32-bit value `0x39` to the command word.
4. It sets bit 26 in the captured control word.
5. It writes that resulting 32-bit word to the selected control-table location.
6. It writes a 32-bit zero to the pending-entry word.

The first notification write and the second notification write need not use the same base if the pointer source changes between its two loads. The supplied behavior must not be simplified to one captured notification pointer.

The notification-index value is formed with bitwise OR, not addition. It is not necessarily a reversible encoding of the index. For example, indices 0 and 128 both produce `0x80`.

The entry-zero selector is not read in this branch, even for index zero.

#### Branch B: control bits 18 and 19 are not both set

This branch selects one of two masks.

For index zero only, the function reads the entry-zero selector and examines bits 29 and 30. Bit 31 is excluded by the mask; bits 0 through 28 do not affect the result.

- If index is zero and selector bits 29–30 are not both one, the selected mask is `0x88000000`.
- Otherwise, the selected mask is `0x84000000`.

For every nonzero index, the selector read is skipped and the selected mask is `0x84000000`.

The function then:

1. ORs the selected mask into the captured control word.
2. Writes the resulting 32-bit value to the selected control-table location.
3. Writes a 32-bit zero to the pending-entry word.

This branch does not perform the branch-A notification-byte, notification-index, or command-word writes.

### Bit-preservation rules

The control-word transformation never deliberately clears a bit:

| Branch | Bits forced to one |
|---|---|
| A | Bit 26 |
| B, mask `0x88000000` | Bits 31 and 27 |
| B, mask `0x84000000` | Bits 31 and 26 |

All other bits are copied from the earlier control-word read.

This is a read-modify-write sequence, not an established atomic bit-set operation. A change made by another agent after the control-word read can be overwritten by the later full-word write.

### Completion and interruption

After each nonzero entry completes its selected branch, its pending word is zero. Its original value is neither returned nor copied elsewhere.

The pending clear occurs after the control-table write. In branch A, it also occurs after all three notification-related writes.

No rollback is present. If an access faults or execution is interrupted, earlier writes may already have occurred while later writes, including the pending clear, have not.
