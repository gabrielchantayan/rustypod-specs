# F-7172e7a9ba84

## Purpose

F-7172e7a9ba84 conditionally updates regions of a caller-supplied object. Its selected path depends on an address-valued field and, for one path, a separate 32-bit discriminator.

The established behavior has three useful cases:

- When the address-valued field matches the embedded region at offset `0x04`, the function performs three ordered conversion-and-transfer sequences, targeting offsets `0x38`, `0x7C`, and `0xC0`.
- When that field instead matches the embedded region at offset `0x10`, it performs only the sequence targeting offset `0xC0`.
- Otherwise, discriminator value `0x1702` enables an indexed lookup followed by a one-byte copy into an indexed destination.

Other discriminator values on the third path cause an immediate return.

These descriptions concern visible operations and dependency calls. The meanings of the embedded regions, converted values, discriminator, and indexed bytes are not established. In particular, apparent conversion and transfer roles do not establish object types, copying semantics, or ownership.

## Interface

### Input

The function receives one argument representing the base address of an existing object.

The supplied representation declares this argument as an integer rather than a typed pointer. It uses the argument for address arithmetic and dereferences. This contract therefore treats it as an address-bearing value; it does not require callers to use any particular source-language pointer type.

No null check, object-size check, index check, or address-range check is visible.

### Output

There is no explicit return value. Observable results consist of:

- Calls to the dependencies listed below, including their order and arguments.
- Any memory or external-state changes made by those dependencies.
- On the indexed path, one explicit one-byte write performed by this function.

There is no visible error result or success indicator.

### Preconditions

For a defined, successful execution, all memory accessed on the selected path must be valid for the indicated operation. This includes any additional memory accessed by dependencies.

On the indexed path, the lookup result must support a one-byte read at offset `0x40`, and the computed destination must support a one-byte write.

The function does not establish these conditions itself.

## Behavior

### Selector handling

The function first reads the selector at offset `0x34` and compares it with the address at object offset `0x04`.

If that comparison succeeds, it takes the first embedded-region path. It does not subsequently reselect a path based on later changes to the selector.

If the comparison fails, the supplied representation reads the selector again and compares it with the address at object offset `0x10`. A successful second comparison selects the second embedded-region path. Otherwise, the alternate path is selected.

There is no dependency call between the two selector comparisons. For stable memory, these comparisons behave as a normal three-way selection. The representation nevertheless contains two field reads, not one cached selector value. It supplies no synchronization or atomicity contract for concurrent modification.

### First embedded-region path

When the first selector comparison succeeds, the following dependency calls occur in order:

1. F-0ff9271d6c39 receives the address at object offset `0x04`. Its four-byte result becomes an argument to F-e571c15425a7.
2. F-e571c15425a7 receives the scratch-region address, that result, and the byte read at object offset `0x904`.
3. F-cb38d8d650b2 receives the destination address at offset `0x38` and the scratch-region address.
4. F-0ff9271d6c39 is called again with the address at offset `0x04`.
5. F-663841ea0245 receives the scratch-region address and this second lookup result.
6. F-cb38d8d650b2 receives the destination address at offset `0x7C` and the scratch-region address.

Execution then continues into the common sequence described below.

The two lookups of the region at `0x04` are distinct calls. Their results need not be equal. The first lookup or intervening dependencies may change relevant state.

The byte at `0x904` is read after the first lookup returns, while preparing the arguments for F-e571c15425a7. Consequently, a change to that byte made by the first lookup can affect the supplied byte argument. No later read of that byte is visible.

### Second embedded-region path and common sequence

A successful second selector comparison enters this sequence directly. The first embedded-region path enters it only after completing both preceding transfers.

The calls occur in this order:

1. F-0ff9271d6c39 receives the address at offset `0x04`.
2. F-0ff9271d6c39 receives the address at offset `0x10`.
3. F-4fb4db0607d2 receives the scratch-region address, the result from offset `0x10`, and then the result from offset `0x04`.
4. F-cb38d8d650b2 receives the destination address at offset `0xC0` and the scratch-region address.

The function then returns.

The order of lookup execution differs from the order of the two lookup-derived arguments to F-4fb4db0607d2: lookup at `0x04` first, lookup at `0x10` second; result from `0x10` passed before result from `0x04`.

The first lookup result remains the argument derived from the first call even if the second call changes the underlying region. This does not establish that the result refers to an immutable snapshot: it may itself be an address or handle.

### Alternate path

If neither selector comparison succeeds, the function reads the discriminator at offset `0x104`.

If the discriminator is not `0x1702`, it returns without making any dependency call or performing an explicit object write.

If the discriminator equals `0x1702`, the function:

- Reads the index at offset `0x24C`.
- Forms a lookup address at object offset `0x1C + 12 × index`.
- Calls F-0ff9271d6c39 with that address.
- Uses the returned value as an address and obtains the byte at return-address offset `0x40`.
- Reads the index at offset `0x24C` again to form a destination at object offset `0xA48 + index`.
- Writes the obtained byte to that destination and returns.

The source-byte read and the second index read both occur after the dependency returns. Their relative evaluation order is not established by the supplied assignment expression. Both are needed before the explicit store.

The two index reads must not be collapsed into a single stable-index assumption. If F-0ff9271d6c39 changes the index, the lookup address uses the earlier index and the write destination uses the later index.

The lookup stride is 12 bytes. The destination stride is one byte. They describe different address calculations, not two accesses to an established common array layout.

### Arithmetic and exceptional cases

No bounds checking or clamping is visible. Negative indices are not explicitly rejected. Neither are values that produce addresses outside the object.

The multiplication by 12 and subsequent additions are integer/address arithmetic in the supplied representation. This evidence does not justify choosing between signed-overflow failure, machine-width wrapping, or another recovered execution behavior. Acceptance cases involving overflow or address wrap are therefore documented_only.

There is no visible special handling for a zero or otherwise invalid lookup result. On the indexed path, such a result is still used to derive the source-byte address.

## Side effects

### Direct effects

The only explicit write to caller-associated memory in the supplied body is the indexed path’s one-byte store.

The other paths invoke dependencies with scratch storage and destination addresses. Their actual writes cannot be bounded from this body alone.

### Scratch storage

One 68-byte automatic scratch region is reused throughout an invocation.

There is no visible initialization before its first use and no visible clearing between uses. Each conversion receives the same scratch address, and the following transfer receives that address as well.

This establishes neither complete initialization nor a fixed transfer size. Partial initialization, internal pointers, hidden metadata, or retained references remain dependency-contract questions.

No explicit allocation, release, or destruction operation appears in this function. It is not established whether dependencies allocate memory, transfer ownership, retain the scratch address, or release resources associated with the scratch contents.

### Dependency effects and partial completion

No dependency is shown to preserve global state, object fields, or reachable memory. Later reads and calls must therefore be interpreted against the state remaining after earlier calls.

There is no visible rollback. If execution fails after an earlier dependency has changed state, the function provides no established restoration behavior.

The body contains no explicit exception handling, error translation, retry, or cleanup path. Dependency failure behavior and abnormal-return behavior are unknown.

## Acceptance examples

These are conditional static acceptance examples, not executed tests. They assume valid addresses, representable arithmetic, and dependencies that return normally.

### Stable selector matching offset `0x04`

Given a selector equal to the address at offset `0x04`, the observable dependency sequence is:

- Lookup at `0x04`.
- F-e571c15425a7 with the lookup result and the byte at `0x904`.
- Transfer to `0x38`.
- Lookup at `0x04`.
- F-663841ea0245 with that new result.
- Transfer to `0x7C`.
- Lookup at `0x04`.
- Lookup at `0x10`.
- F-4fb4db0607d2 with the latter result before the former.
- Transfer to `0xC0`.

There are four lookup calls and three transfer calls. The indexed-byte operation does not occur.

### Stable selector matching offset `0x10`

Given a selector equal to the address at `0x10` but not the address at `0x04`, only the common sequence occurs.

The discriminator does not gate this path. Its value may differ from `0x1702` without preventing the transfer to `0xC0`.

### Unmatched selector and different discriminator

Given a selector matching neither embedded-region address and a discriminator different from `0x1702`, the function returns without dependency calls or an explicit memory write.

This example does not assert the absence of memory reads: selector and discriminator reads still occur.

### Indexed copy with a stable index of two

Given an unmatched selector, discriminator `0x1702`, and an index that remains two:

- The lookup address is object offset `0x34`, because `0x1C + 12 × 2 = 0x34`.
- The source byte is at offset `0x40` from the returned address.
- The destination byte is at object offset `0xA4A`.

The lookup address coinciding with the selector field is not prevented by a visible check. Whether that address is a valid dependency input is unknown.

### Index changed during lookup

Given an initial index of one, suppose F-0ff9271d6c39 returns a valid source address and changes the index to four.

The lookup receives object offset `0x28`. The explicit byte store targets object offset `0xA4C`, not `0xA49`.

This example distinguishes the established two-read behavior from an implementation that caches the index.

### Byte changed during the first lookup

On the first embedded-region path, suppose the first lookup changes the byte at `0x904` before returning. F-e571c15425a7 receives the changed byte.

### Invalid lookup result

On the indexed path, an invalid returned address has no established graceful outcome. Acceptance must not require a skipped write, default byte, or error return: none is visible.
