# F-7a1c296974df

## Purpose

F-7a1c296974df conditionally replaces a record’s selected value, updates associated metadata, optionally transforms the selected value, and performs up to two auxiliary updates. At completion, it sets a byte marker if the final selected value differs from the value saved at the start of enabled processing.

“Selected value,” “metadata,” “workspace,” and “auxiliary update” are explanatory labels, not established application types. The selected value is a 32-bit quantity; the evidence does not establish that it always denotes a string, an allocation, or valid addressable storage.

The established contract is the sequence of accesses, calls, and conditional writes described below. The function has no explicit result or error report and provides no visible rollback.

### Static storage and address arguments

One static region has the following established layout:

| Region-relative offset | Use |
|---|---|
| `0` | A 32-bit discriminator word, loaded during branch selection. |
| `4` | A 32-bit primary selector word, loaded during primary lookup argument preparation. |
| `8` | The fallback address installed in the selected-value field when primary lookup returns zero. |

The first two uses are **loads of stored words**. They are not established immutable constants. The fallback use is **an address eight bytes into the same region**; this function does not load the fallback’s contents.

A secondary selector is a 32-bit load from a distinct static storage location. Its value is unavailable and may equal the primary selector’s value. The function does not compare the selectors.

The transformation descriptor is passed by static address, not by loading its contents in this function.

These distinctions matter even though the static contents are unavailable: a dependency may change stored discriminator or selector words without changing the identity of the fallback or descriptor addresses.

## Behavior

### Eligibility and saved state

The first access reads the byte at `0xE8`.

- A nonzero byte ends processing immediately. There is no flags read, dependency call, or direct write.
- A zero byte permits a 32-bit flags read at `0xF0`.
- If those flags contain `0x10`, processing ends without direct writes or dependency calls.

Only after both gates permit processing does the function save the 32-bit value at `0xF8` for its final comparison. It then initializes the two-word local area from the third and fourth arguments.

The value saved at this point is not necessarily a function-entry snapshot under concurrent mutation; it is the value observed at this particular read.

### Selection branch

The function compares the record word at `0x40` with the discriminator word loaded from the beginning of the static region. The relative evaluation order of the two operands is not established. This discriminator read occurs at branch selection, not at function entry.

#### Matching discriminator

The function calls F-b782a0ff4f07 with the record and stores its 32-bit result at `0xF8`.

It then rereads flags at `0xF0`. If `0x400` is set, it reads the context at `0x38` and calls F-ae02327d03f2 with the record and that context value.

This branch makes no direct writes to `0xFC` or `0x100`. It does not establish that either dependency preserves those fields, flags, static storage, or other state.

#### Nonmatching discriminator

Before lookup, the function saves the current 32-bit metadata value at `0xFC`.

It calls F-5710a8628cba with three arguments:

- the value read from record offset `0x38`;
- the primary selector word loaded from static-region offset `4`;
- the value read from record offset `0x44`.

All three argument values are obtained before the call executes. Their relative read order is not established. In particular, the primary selector is a load at this argument-preparation point, not an invariant value inferred from the earlier discriminator load.

If the result is zero, the function writes the address at static-region offset `8` to `0xF8`, then writes zero to `0x100`. It makes no direct write to `0xFC` and does not call F-6489b8f5efca on this path. The lookup dependency itself is not known to preserve metadata.

If the result is nonzero, it is treated as a three-word descriptor:

| Descriptor byte offset | Destination |
|---|---|
| `0` | Record `0xF8` |
| `4` | Record `0xFC` |
| `8` | Record `0x100` |

The established access order is significant:

1. Read the descriptor word at offset `4`.
2. Read the descriptor word at offset `8`.
3. Read the descriptor word at offset `0` and store it at record offset `0xF8`.
4. Store the previously read metadata word at `0xFC`.
5. Store the previously read additional-metadata word at `0x100`.

Thus all three descriptor reads precede the first destination write. This ordering applies even if descriptor storage aliases record storage, although whether such aliasing is valid for callers is unknown.

The function next reads `0xFC`. If zero, it restores the metadata saved before lookup. It then reads `0xFC` for comparison with that saved value. If different, it calls F-6489b8f5efca with:

- the record;
- a further read of the current metadata at `0xFC`;
- the embedded address at `0xA4`;
- the embedded address at `0xE9`.

Absent intervening mutation, a zero descriptor metadata word therefore retains the pre-lookup metadata and causes no notification. No comparable retention rule exists for the selected value or additional metadata.

### Optional transformation

After either selection branch, the function rereads flags at `0xF0`. If `0x40` is clear, transformation is skipped. If set, the following calls occur in order:

| Order | Dependency | Arguments or result use |
|---|---|---|
| 1 | F-151ab4bfe553 | Embedded workspace address at `0x104`, and the current selected value read from `0xF8`. |
| 2 | F-398e0e9a318a | Local two-word area address, and the static transformation-descriptor address. |
| 3 | F-7c7fe4dcd370 | Workspace address and the preceding call’s 32-bit result. |
| 4 | F-289ec4311c64 | Local two-word area address. |
| 5 | F-ecd1af0519f9 | Workspace address. |

The fifth call’s 32-bit result is then stored at `0xF8`.

The fourth call is not established to release memory or perform cleanup. Neither the local area nor the workspace has a demonstrated ownership protocol. The transformation-descriptor argument is an address; its contents are not directly read here.

The selected value supplied to the first call is read at that point and may reflect earlier dependency effects.

### First auxiliary update

The function rereads flags at `0xF0`.

If `0x800` is set, it skips this update without reading metadata for the eligibility check. Otherwise it reads `0xFC`; zero suppresses the call.

For nonzero metadata, it reads `0xFC` again and calls F-35c2e4297234 with the embedded address at `0xF4` and the reread metadata value plus eight.

The displacement is eight bytes in an address-like calculation, not eight elements. The source representation uses a 32-bit integer-like metadata value. No widened calculation, overflow check, or guaranteed wraparound behavior is established. Acceptance of boundary values remains undocumented.

The value used for the nonzero test is not explicitly retained for the argument calculation. Concurrent mutation could therefore make the tested and supplied values differ; supported concurrency is unknown.

### Second auxiliary update

The function reads flags at `0xF0` again. If `0x2000` is clear, this stage ends without reading context for its gate.

If set, it reads `0x38`. A zero context suppresses the lookup. Otherwise it calls F-5710a8628cba with:

- the context value already read for this gate;
- the secondary selector word loaded from static storage during this call’s argument preparation;
- the current value read from `0x44`.

The relative order of the selector and record-argument reads is not established. This selector load occurs after all earlier executed dependencies, including the first auxiliary update when eligible. It must not be treated as an entry snapshot: earlier dependencies may have changed its storage.

A zero lookup result suppresses the auxiliary call. A nonzero result is passed unchanged to F-35c2e4297234, together with the address at `0xF4`. No eight-byte displacement is applied.

This stage is independent of flag `0x800`. Both auxiliary updates can occur, with the metadata-derived call first. Whether their effects replace, accumulate, or otherwise interact is dependency-defined.

### Final change marking

Finally, the function reads `0xF8` and compares its 32-bit value with the saved pre-selection value.

If different, it writes byte value one at `0x1F0`. If equal, it makes no direct marker write.

This is raw-value comparison, not comparison of referenced contents. Intermediate selected-value changes do not cause marking if the final value returns to the saved value. Metadata-only or auxiliary-only changes do not independently cause marking.

The function never directly clears the marker.

## Side effects

Direct record writes are confined to `0xF8`, `0xFC`, `0x100`, and `0x1F0`, in the conditional order above. Local initialization also writes the two-word local area. No direct static-storage write is shown.

Dependencies may modify record fields, pointed-to objects, globals, or other shared state. No dependency is established to preserve the discriminator or selector storage. Later flag checks, record reads, and the secondary selector load observe values available at their respective read points rather than a common snapshot.

No direct allocation, deallocation, ownership transfer, synchronization, retry, or rollback is established. Passing a local or embedded address does not establish permission to retain it beyond its valid lifetime.

Only the lookup results have explicit zero-result handling. Other returned values are consumed without visible failure checks. If a dependency does not return normally, later operations are not established to occur.

## Acceptance examples

These are conditional static expectations, not executed tests. Unless an example specifies otherwise, dependencies return normally and do not independently alter the fields or storage discussed.

1. **Byte gate:** With `0xE8` nonzero, no flags read, static selector load, dependency call, or direct write occurs.

2. **Flag gate:** With `0xE8` zero and flag `0x10` set, processing ends before the selected-value snapshot and discriminator comparison.

3. **Primary miss:** In the nonmatching branch, a zero lookup result installs the address at static-region offset `8` in `0xF8` and zero in `0x100`. No fallback contents are read. Existing metadata receives no direct write, and later optional stages remain eligible.

4. **Metadata retention:** With saved metadata `0x2000` and descriptor words `0x5000`, zero, and `0x77`, selection leaves `0xF8 = 0x5000`, `0xFC = 0x2000`, and `0x100 = 0x77`. No metadata-change call occurs.

5. **Replacement metadata:** With saved metadata `0x2000` and descriptor metadata `0x3000`, F-6489b8f5efca receives `0x3000`. If metadata remains unchanged and `0x800` is clear, the first auxiliary source argument is `0x3008`.

6. **Both auxiliary calls:** With eligible metadata, `0x800` clear, `0x2000` set, nonzero context, and nonzero secondary result, F-35c2e4297234 is called first with metadata plus eight and later with the undisplaced secondary result.

7. **Late selector mutation:** Suppose the primary call receives selector value `0x11` and changes secondary-selector storage to `0x22`. If the secondary stage executes and that storage is not changed again, its lookup receives `0x22`, not a saved earlier value.

8. **Equal selectors:** If both selector loads yield `0x11`, both eligible lookups receive `0x11`. Distinct storage locations do not require different contents.

9. **Address versus contents:** A dependency changing bytes at the fallback location does not itself change the fallback address installed on a primary miss. Effects of that content change on later dependencies remain unknown.

10. **Final equality:** If transformation restores the saved selected value, this function makes no marker write. An existing marker is not directly cleared. If the final value differs, it writes byte one.
