# F-91c23e79cde3

## Purpose

- Its 32-bit flag word satisfies a particular masked-bit condition.
- F-fe188ad6021a, called with an address inside that object and the caller’s second argument, returns a nonzero result.

The function returns the reference value of the first qualifying object encountered. It returns zero if traversal reaches the sequence’s current end before finding one.

This is a conditional search, not a search for a particular dependency return value: all nonzero results from F-fe188ad6021a are treated alike.

## Behavior

### Initialization and end checking

The function reads the sequence-start field at container offset +0x14 once, before traversal. That value initializes the traversal cursor.

Before every attempted slot read, the function reads the end field at container offset +0x18 and compares it with the current cursor.

If they are equal, the function returns zero immediately. It does not read a slot, read an object flag word, or call the dependency for that iteration.

The end field is therefore not captured once for the entire search. Each iteration uses a newly observed end value. Conversely, the start field is not reread after initialization.

This distinction matters if memory changes during execution. The routine does not establish snapshot semantics for the sequence.

### Candidate evaluation

If the cursor does not equal the observed end address, the function loads the object reference from the current four-byte slot.

It then reads the object’s 32-bit unsigned flag word at offset +0x48. The flag condition is:

- Mask the word with 0x1800.
- Accept the flag condition only if the masked result equals 0x0800.

Equivalently, bit 11 must be set and bit 12 must be clear. All other bits are ignored by this function’s flag test.

The four possible combinations of the relevant bits behave as follows:

| Flag word masked with 0x1800 | Flag condition |
|---|---|
| 0x0000 | Reject |
| 0x0800 | Accept |
| 0x1000 | Reject |
| 0x1800 | Reject |

If the flag condition rejects the object, the dependency is not called for that occurrence.

If the flag condition accepts the object, the function calls F-fe188ad6021a with:

1. The object address plus 0x80.
2. The unchanged four-byte second argument.

A zero dependency result rejects the candidate. Any nonzero result accepts it. There is no distinction between positive and negative nonzero results in the visible decision.

### Advancement and successful return

After either flag rejection or a zero dependency result, the cursor advances by one sequence slot: four bytes in the represented layout. The next iteration begins by rereading the end field.

The traversal is forward-only. There is no sorting, backward scan, deduplication, or retry of a rejected slot within the visible logic.

On a nonzero dependency result, the function immediately returns the object-reference value previously loaded from that slot. It does not:

- Reread the slot.
- Reread the flags.
- Check the end field again.
- Examine later slots.

Consequently, a dependency that changes the slot, flags, or container does not cause this function to revalidate a successful candidate before returning. Whether such mutation is permitted by the surrounding system is unknown.

### Boundary and arithmetic behavior

The end test is equality, not an ordering comparison. The function does not reject a cursor merely because its address is greater than the end address.

For a conventional unchanged sequence, the end address must be reachable from the start address through four-byte increments. An end address before the start, or one with an incompatible displacement, is not handled as an empty or invalid range. The routine continues attempting traversal until equality, success, or an execution failure occurs.

The represented reference values and flag values are 32 bits; the opaque second argument is four bytes. Slot advancement is four bytes, not one byte. The object-relative offsets are byte offsets.

No overflow check is visible for slot advancement or object-relative address formation. Exact behavior on address wraparound cannot be safely specified from this representation alone.
