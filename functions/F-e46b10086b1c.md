# F-e46b10086b1c

## Purpose

F-e46b10086b1c returns an eight-bit value through one of two paths:

- **Direct-result path:** returns one byte from an address selected by a descriptor-relative displacement and the input address. The result is not normalized to zero or one.
- **Lookup path:** searches a descriptor-selected structure using an unsigned 32-bit query. Normal returns are zero or one.

The lookup structure has three observed interpretations: a packed bitmap, a linear-probing table, and a child-pointer structure that changes both the node and the query.

**Inferred intent:** the lookup path implements membership testing. The application-level meanings of the objects, stored values, and arithmetic dependency are not established.

The direct-result address is unrestricted by this function. It can overlap fields otherwise used by the lookup path; direct selection is not necessarily independent of query storage.

## Behavior

### Entry and direct-result path

The descriptor address is read from the input before the selector byte is read from the descriptor.

A nonzero selector selects the direct-result path. The displacement is read from descriptor offset 60, the selected address is formed relative to the original input address with the additional 72-byte adjustment, and one byte is read and returned unchanged.

This path does not explicitly load the query word or initial-node pointer. It also does not reject a zero query or invoke the dependency.

Those statements concern field-width operations, not exclusion of overlapping storage. The selected byte may lie within the query word, the descriptor’s initial-node-pointer field, or another readable location. No requirement keeps it inside the input allocation or a dedicated result area.

Address formation uses signed 32-bit intermediates in the supplied representation. A mathematical displacement description does not establish defined behavior when an intermediate addition overflows, a pointer conversion is unsupported, or the resulting access is invalid.

### Lookup initialization and common checks

A zero selector selects lookup. The initial query is read from input offset 4 before the initial node address is read from descriptor offset 88. The query is used as an unsigned 32-bit value.

These become local traversal state. Child transitions replace both values. The original input query and descriptor address are not visibly reloaded during traversal.

A null current node returns zero without a node dereference. For a nonnull node, the admission bound is read and compared unsigned with the current query. A smaller bound returns zero. The zero-query rejection follows that comparison, so a nonnull node is accessed even when the query is zero.

Only an admitted, nonzero query reaches representation selection. The bound is evaluated again; a value below 4001 selects the bitmap, while a larger value causes the selector at offset 8 to be read.

These checks recur after every child transition, using the selected child and transformed query. Statements about a single stable bound do not imply consistency if storage changes between evaluations.

### Bitmap representation

The bitmap payload begins at node byte offset 12. For an admitted, nonzero query:

- The logical bit number is the query minus one.
- Its quotient on division by eight selects the payload byte.
- Its remainder on division by eight selects the bit within that byte.
- Bit zero is the least significant bit.

The selected byte is read, and the function returns one if the selected bit is set, otherwise zero. No complete-bitmap scan occurs.

With stable bounds, a reached bitmap query is between 1 and 4000 inclusive. Query 1 selects bit 0 at offset 12; query 4000 selects bit 7 at offset 511. The earlier zero-query rejection prevents unsigned subtraction underflow.

The 4000-query limit depends on compatible admission and representation observations. It is not guaranteed under intervening mutation.

### Table representation

A larger node with a zero selector uses 32-bit table entries, ordinarily beginning at node offset 12.

F-d7be9cfb4000 is called with two explicit inputs:

- The current query multiplied by 37 using unsigned 32-bit arithmetic.
- The value 125.

The multiplication is reduced modulo \(2^{32}\). A secondary 32-bit result associated with the call becomes the initial table index. The dependency’s full calling convention and semantics are unknown; no established contract restricts this result to indices 0 through 124.

For each probe, the selected entry is first evaluated for zero. Zero returns zero. The entry is then evaluated again for equality with the current query; equality returns one. Otherwise, the index is incremented using unsigned 32-bit arithmetic. If that incremented value exceeds 124, it is replaced by zero before the next probe.

Thus:

- Initial-index normalization does not occur before the first access.
- After a nonmatching probe at index 124, the next index is zero.
- Incrementing the maximum unsigned index wraps to zero before the comparison.
- The zero and equality checks are separate evaluations, not an established atomic read.

For ordinary indices, the selected address is node offset \(12 + 4 \times \text{index}\). More precisely, the unsigned index is first increased by three at 32-bit width to select a word relative to the node base. That addition can wrap for extreme values. Neither the ordinary offset formula nor an unbounded mathematical multiplication describes all extreme-index cases. Pointer validity remains a separate requirement.

An initial index of 125 selects the word at offset 512 without first being reduced to zero.

There is no probe limit or full-table detection. With an in-range initial index and stable, nonzero, nonmatching entries at every index from 0 through 124, probing repeats indefinitely.

### Child-pointer representation

A larger node with a nonzero selector calls F-d7be9cfb4000 with one explicit input: the current query minus one. The common checks establish that the current query is nonzero, so this unsigned subtraction does not underflow.

No second explicit argument is established. It must not be supplied by assuming that the selector is a divisor or that an argument from another call is retained.

Two 32-bit components of the dependency result are consumed:

- The low component determines the child-pointer word.
- The high component participates in construction of the next query.

For child selection, the low component is converted to a signed 32-bit integer, and three is added in signed arithmetic to obtain the node-relative word index. For an ordinary nonnegative component with defined conversion and addition, this selects node byte offset \(12 + 4 \times \text{component}\).

There is no range or nonnegativity check. Negative converted indices may select header or preceding storage. Out-of-range conversion, signed overflow while adding three, and invalid pointer arithmetic are unresolved. The selected child-pointer word is read after the dependency returns.

Consequently:

- A high component of 2147483647 reaches signed addition overflow. The supplied representation does not establish an unsigned-wrapping result for that case.
- High components above 2147483647 require an out-of-range unsigned-to-signed conversion whose target behavior is not established.
