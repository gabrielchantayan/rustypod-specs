# F-9563c0301556

## Purpose

F-9563c0301556 coordinates a primary operation with preliminary setup, optional follow-up processing, and conditional propagation of a 16-bit field into a context obtained through a dependency.

The established behavior is orchestration, not a self-contained transformation:

- Obtain an initial context-like value and pass it, the first input, and a zero argument to a setup dependency.
- Invoke the primary dependency with both original inputs and retain its 32-bit result.
- Invoke a separate dependency when the second input is nonzero.
- Under additional field-value conditions, copy a 16-bit value from the first input’s referenced storage into context storage.
- Return the retained primary result.

The semantic meanings of the referenced objects, the fields, and the dependency operations are not established. Terms such as “context,” “source,” and “destination” describe their roles here, not a proven object model or ownership relationship.

## Interface

The function takes two inputs represented as 32-bit integers in the supplied source representation.

The second input is not restricted to a Boolean representation. Zero disables the conditional paths. Every nonzero value, including a negative value in the represented signed interpretation, enables those paths subject to the field checks.

## Behavior

### Unconditional setup and primary operation

On an execution in which the relevant calls return normally:

1. F-fdd8589eca2d is called without explicit arguments.
2. Its returned value is passed as the first argument to F-3e5212464798. The first input is passed as the second argument, and a literal zero is passed as the third.
3. F-a3c410f12096 is called with the original first and second inputs, in that order.
4. The 32-bit result of F-a3c410f12096 is retained for the eventual return.

The return value of F-3e5212464798, if any, is not used by the visible caller. There is no visible error check between setup and the primary operation.

The initial value returned by F-fdd8589eca2d is not reused for the later field checks or write. Those operations obtain fresh values through further calls.

### Optional follow-up

After the primary operation returns, the function tests the original second input.

- If it is zero, F-5c5958cfd5fe is not called.
- If it is nonzero, F-5c5958cfd5fe is called without explicit arguments.

The follow-up call occurs before the direct source-field read described below. Consequently, any changes it makes to reachable storage can affect the later field checks. Its result, if any, is not used to alter the retained primary result or explicitly gate further execution.

### Conditional field propagation

After the optional follow-up call, the function reads the 16-bit field at the first input’s address plus `0xEA` and tests it against zero.

This source-field read occurs even when the second input is zero. The second input does not protect the first input from being dereferenced at this stage.

Further behavior depends on the conditions:

- If the source field is zero, there are no additional context lookups or direct writes.
- If the source field is nonzero but the second input is zero, there are no additional context lookups or direct writes.
- If the source field is nonzero and the second input is nonzero, F-fdd8589eca2d is called again.

For that additional lookup, the function reads the 16-bit field at the returned address plus `0x80`.

- If that field is nonzero, propagation stops. No further lookup or direct write occurs.
- If that field is zero, F-fdd8589eca2d is called once more.

After this final lookup returns, the source field at offset `0xEA` is read again, and its current 16-bit value is written at offset `0x80` from the final lookup’s returned address.

The final write is therefore not necessarily a copy of the source value that passed the initial nonzero test. The two source reads are separate observations, with dependency calls between them.

Likewise, the zero test and the write do not necessarily concern the same destination storage. The function tests a field through one context result and writes through a later result. It does not visibly check the final destination field before overwriting it.

## Side effects

### Direct memory effects

The function directly performs:

- One 16-bit source-field read on every execution that reaches the conditional-propagation stage.
- One 16-bit destination-field read when the source field is nonzero and the second input is nonzero.
- One additional 16-bit source-field read and one 16-bit destination-field write when the tested destination field is zero.

The propagated value is copied as a 16-bit quantity without visible arithmetic or conversion to a Boolean value. Its high bit does not change the zero-versus-nonzero decision. No wider field update is expressed by the supplied representation.

The function contains no explicit direct write to the source field. That does not establish that source storage remains unchanged: dependencies may modify it, and source and destination storage may alias.

## Acceptance examples

The following are conditional behavioral examples, not executed tests. They assume valid reached memory accesses and normal dependency returns.

1. **Zero second input with a nonzero source field.**  
   Initial setup and the primary operation occur. The follow-up dependency is skipped. The source field is still read. No destination lookup or write follows. The primary result is returned.

2. **Nonzero second input with a zero source field after follow-up.**  
   Setup, the primary operation, and follow-up occur in that order. The source-field read then observes zero. No additional context lookup occurs, and no direct field write occurs.

3. **Nonzero source and second input, occupied tested destination.**  
   After follow-up, the source field is observed as nonzero. A second context lookup returns storage whose field at `0x80` is nonzero. There is no third lookup and no direct write.

4. **Stable source and stable context, empty destination.**  
   Suppose the source remains `0x1234`, both conditional context lookups return the same address, and the destination field initially contains zero. The destination field is written with `0x1234`. The returned value remains the primary result.

5. **Source changes before the final read.**  
   Suppose the first source read observes `0x1234`, the tested destination field is zero, and a later dependency changes the source field to zero before the final read. The function writes zero. It does not reapply the initial nonzero condition to the newly read value.

6. **Context changes between test and write.**  
   Suppose the second lookup returns one address whose field is zero, while the third returns a different address whose field contains `0x7777`. The write targets the third lookup’s address and overwrites that field with the newly read source value. The third destination is not separately checked for zero.

7. **Negative second input.**  
   A represented value of negative one follows the same conditional branches as any other nonzero second input. It is also passed unchanged to the primary dependency.

8. **Primary result resembles an error value.**  
   If the primary dependency returns normally with a value a consumer interprets as an error, this function does not visibly branch on that interpretation. Applicable follow-up and field processing still occur before the retained value is returned.
