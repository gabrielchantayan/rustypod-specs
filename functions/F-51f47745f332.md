# F-51f47745f332

## Purpose

F-51f47745f332 passes a selected address within a caller-supplied state region to F-148f046b5d07. After that dependency returns, it reads a phase field, conditionally passes three ordered record addresses to F-3678c8e0bd6c, updates the phase, and advances a selector.

The established contract concerns call ordering, argument construction, field reads, and field writes. A three-position rotating history is a plausible interpretation, but the meaning of the records and the processing performed by either dependency remain unknown.

The function has no explicit return value or error result. Its externally relevant effects are the dependency calls and changes to accessible memory or other state.

## Interface

### Arguments

| Argument | Established use |
|---|---|
| State-region address | Base for field accesses and record-address calculations; passed as the first argument to both dependencies. |
| Opaque four-byte value | Passed unchanged as the second argument to F-148f046b5d07. Not otherwise inspected by this function. |

The supplied representation carries the state-region address in a 32-bit integer form. That representation does not independently establish the actual calling convention, pointer representation, or validity of arbitrary integer-derived addresses.

The opaque argument is a four-byte value, not an established pointer or ownership-bearing handle. If a dependency interprets it as such, that interpretation is outside the available evidence.

### State layout

All offsets below are relative to the state-region address.

| Offset | Width or spacing | Use |
|---|---:|---|
| `0xAB0` | 4 bytes | Phase field, read after the first dependency and written before final selector advancement. |
| `0xAB4` | 4 bytes | Selector field, read at multiple stages and updated at the end. |
| `0xB54` | Address origin | Record position zero. |
| Successive record positions | `0x94` bytes | Address stride, equivalent to 148 bytes. |

For an ordinary, representable index \(k\), the associated record address is the state-region address plus `0xB54` plus \(148k\).

| Index | Offset |
|---:|---:|
| 0 | `0xB54` |
| 1 | `0xBE8` |
| 2 | `0xC7C` |

The stride does not establish record contents, logical record size, or the memory extent accessed by either dependency.

The phase is interpreted through a signed 32-bit integer form. The selector is interpreted through a signed 32-bit form for the initial record selection and final advancement, but through an unsigned 32-bit form when preparing the conditional three-address call.

### Preconditions and results

The function performs no explicit validation of:

- A null or otherwise invalid state-region address.
- Region size, alignment, or accessibility.
- Phase or selector ranges.
- Calculated record addresses.
- The opaque argument.

Normal completion requires accessible storage for the direct field operations and satisfaction of both dependencies’ actual requirements. Accessible phase and selector fields alone do not establish that any record address is usable.

There is no explicit result value, allocation, deallocation, ownership transfer, or retention action in this function. Passing an address to a dependency does not establish whether that dependency retains it, releases associated resources, or modifies memory beyond the supplied record address.

## Behavior

### Initial selection and first call

The function reads the selector at `0xAB4` and uses that value to calculate the first record address.

It then calls F-148f046b5d07 with:

1. The state-region address.
2. The unchanged opaque four-byte argument.
3. The calculated record address.

This call occurs before the phase read that controls dispatch. Consequently, an entry phase of 2 or 3 does not by itself guarantee the conditional second call: F-148f046b5d07 may change the phase before returning.

The first record address is already determined when F-148f046b5d07 begins. A selector change during that dependency cannot retroactively alter the address supplied to that call.

### Phase dispatch

After F-148f046b5d07 returns normally, the function reads the phase at `0xAB0`.

| Phase observed at this read | Conditional call | Subsequent phase write |
|---:|---|---:|
| 3 | F-3678c8e0bd6c with phase-3 ordering | 2 |
| 2 | F-3678c8e0bd6c with phase-2 ordering | 3 |
| Any other value | None | Observed phase plus one, subject to signed-arithmetic limits |

The dispatch decision uses this post-call observation, not a saved entry phase. Values outside 0–3 are neither rejected nor normalized. For example, an observed phase of 4 selects no second call and produces a phase write of 5.

### Conditional record selection

For observed phase 2 or 3, the function reads the selector again. This read occurs after F-148f046b5d07 has returned and is independent of the initial selector read.

This branch interprets the selector as an unsigned 32-bit value and derives two predecessor positions:

- **One-back position:** unsigned subtraction of one; when that result is greater than the original selector, substitute the original selector plus two.
- **Two-back position:** unsigned subtraction of two; when that result is greater than the original selector, substitute the original selector plus one.

The subtraction and comparison use 32-bit unsigned arithmetic. Within the intended three-position range:

| Branch selector | One-back position | Two-back position |
|---:|---:|---:|
| 0 | 2 | 1 |
| 1 | 0 | 2 |
| 2 | 1 | 0 |

These are not general modulo-three calculations. For an unsigned selector of at least 3, the two predecessor results are simply the selector minus one and minus two. There is no range repair.

F-3678c8e0bd6c receives the following arguments:

| Observed phase | First argument | Second argument | Third argument | Fourth argument |
|---:|---|---|---|---|
| 3 | State-region address | One-back address | Two-back address | Current-selector address |
| 2 | State-region address | Two-back address | One-back address | Current-selector address |

Only the first two record-address positions are exchanged between the branches. The current-selector address is last in both.

All three addresses use the selector read for this branch. They can therefore differ from the record selection supplied to F-148f046b5d07.

### Phase write

After the optional dependency returns normally, the function writes the selected phase to `0xAB0`.

- Observed phase 3 produces a write of 2.
- Observed phase 2 produces a write of 3.
- Every other observed phase produces a write of that observed value plus one, where the signed increment is representable.

There is no phase reread after F-3678c8e0bd6c. A phase change made by that dependency is overwritten by the fixed branch result.

### Final selector advancement

After writing the phase, the function reads the selector again from `0xAB4`.

It increments that newly read signed value and writes the incremented value to the selector field. If the incremented value equals 3, it then writes zero to the same field.

| Selector at final read | Direct selector writes, in order | Final selector |
|---:|---|---:|
| 0 | 1 | 1 |
| 1 | 2 | 2 |
| 2 | 3, then 0 | 0 |
| 3 | 4 | 4 |

Only an increment result equal to 3 triggers the second write. This is not a general modulo-three update.

Because the final read follows both possible dependency calls, either dependency can affect the selector value that is advanced. The function does not advance a saved entry selector.

### Arithmetic boundaries

The unsigned predecessor subtraction and comparisons have 32-bit modular semantics in the supplied representation. For example, unsigned zero minus two produces `0xFFFFFFFE`, triggering substitution of position 1.

Other operations require separate treatment:

- The initial selector multiplication, phase increment, final selector increment, and signed portions of address formation use signed integer forms.
- The branch’s current-selector address includes unsigned arithmetic because its selector is unsigned. At the represented 32-bit width, unsigned arithmetic wraps modulo \(2^{32}\).
- Predecessor results are placed into signed integer forms before their address calculations. Results outside the signed range require conversion behavior not established by the supplied evidence.
- Integer wrap or conversion does not establish that the resulting value denotes valid accessible memory.

The ordinary-range behavior is established where the signed calculations are representable and the addresses are valid. A portable contract for signed overflow, out-of-range conversions, or wrapped address use is documented_only.

## Side effects

Excluding dependency internals, the established source-level order is:

1. Read the selector for the first record address.
2. Call F-148f046b5d07.
3. Read the phase.
4. For observed phase 2 or 3, read the branch selector and call F-3678c8e0bd6c.
5. Write the phase.
6. Read the selector for advancement.
7. Write the incremented selector.
8. If that increment equals 3, write selector zero.

The function itself does not inspect record contents or dereference the opaque argument. It computes addresses and passes them onward.

For a final selector read of 2, the source-level operations include a write of 3 followed by a write of zero. The evidence does not establish that an unsynchronized observer can see the intermediate value, that these accesses are atomic, or that a target implementation must expose distinct physical stores.

There is no visible synchronization, rollback, error translation, or explicit cleanup. Dependency return values are not used to gate later operations.

If a dependency fails to return normally, subsequent operations are not established as occurring. Earlier effects are not undone by any visible mechanism.

## Acceptance examples

These are conditional consequences of static evidence, not executed tests. Unless stated otherwise, they assume valid memory, representable arithmetic, normal dependency returns, and no external interference.

### Initial phase and selector both zero

If both fields start at zero and F-148f046b5d07 preserves them:

- The first dependency receives record position 0.
- The phase read observes 0.
- F-3678c8e0bd6c is not called.
- The phase becomes 1.
- The selector becomes 1.

### Observed phase 3 with selector zero

Suppose the initial selector is zero, the phase observed **after F-148f046b5d07 returns is 3**, and both dependencies preserve the selector through the final read.

Then:

- The first dependency receives record position 0.
- The second dependency receives record positions **2, 1, 0**, after the state-region argument.
- The phase is written as 2, regardless of any phase change by the second dependency.
- The selector becomes 1.

An entry phase of 3 and selector preservation alone are insufficient preconditions.

### Observed phase 2 with selector one

Suppose the initial selector is one, the phase observed **after F-148f046b5d07 returns is 2**, and both dependencies preserve the selector through the final read.

Then:

- The first dependency receives record position 1.
- The second dependency receives record positions **2, 0, 1**.
- The phase is written as 3, regardless of any phase change by the second dependency.
- The selector becomes 2.

An entry phase of 2 and selector preservation alone are insufficient preconditions.

### First dependency cancels an entry-phase dispatch

Suppose the entry phase is either 2 or 3, and F-148f046b5d07 changes it to zero while preserving the selector.

Then:

- Dispatch observes zero.
- F-3678c8e0bd6c is not called.
- The phase is written as 1.
- The unchanged selector is advanced according to its value at the final read.

This distinguishes entry state from the state actually used for dispatch.

### First dependency changes both fields

Suppose the entry selector is zero, and F-148f046b5d07 changes the phase to 2 and selector to 1.

Then:

- That first call received record position 0.
- The second call receives positions **2, 0, 1**.
- The phase is written as 3.
- If the second dependency preserves the selector, it becomes 2.

### Second dependency changes both fields

Suppose dispatch observes phase 3, and F-3678c8e0bd6c writes phase 99 and selector 2.

Then:

- The direct phase write replaces 99 with 2.
- The final selector read observes 2.
- The direct selector writes are 3, then zero.

### Out-of-range values are not normalized

If dispatch observes phase 4 and the final selector read observes 3:

- No second dependency call occurs.
- The phase becomes 5.
- The selector becomes 4.

If dispatch instead observes phase 3 with branch selector 3, the second dependency receives positions **2, 1, 3**. Whether position 3 is accessible is not established.
