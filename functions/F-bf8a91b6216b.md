# F-bf8a91b6216b

## Purpose

F-bf8a91b6216b returns a 32-bit Boolean result for matching a decoded pattern against a byte-addressed subject. Its operations include configurable variable-length and single-value wildcards, bracket expressions, an escape value, and optional table-based normalization.

**Inferred intent:** the function resembles a configurable glob matcher. This interpretation does not override its observable behavior, including unusual escape handling, mixed decoded-value and raw-byte access, and normalization-dependent termination.

Ordinary matching requires subject exhaustion when the pattern ends. A variable-length wildcard followed by an effective pattern end can instead accept the remaining subject without examining it.

This contract describes the supplied static representation. It does not establish an encoding, a safe-input validator, or conventional glob semantics.

## Behavior

### Entry observations and invocation state

At entry, the function obtains a normalization-table base from global storage. It then reads configuration offsets in this order: **1, 0, 2, 3**.

These observations are retained for the invocation. Escape state starts clear. Pattern and subject cursors are invocation-local.

Recursive calls receive the current configuration pointer and escape value, but initialize their own escape state and reread the global table base and configuration. They need not observe the same contents if shared state changes.

### Main dispatch and precedence

Each main iteration decodes a pattern value, allowing F-429a3f34f0b2 to update the pattern cursor.

A result of zero immediately performs a raw-byte subject-end check: return 1 if the byte at the current subject cursor is zero, otherwise return 0. No subject decoding occurs for this check.

For nonzero values with escape state clear, recognition order is:

1. Variable-length wildcard.
2. Single-value wildcard.
3. Bracket-expression opener.
4. Escape.
5. Ordinary literal.

With escape state set, both wildcard recognitions are bypassed. Bracket recognition remains active, while escape recognition is disabled.

Thus overlapping operator values are resolved by branch order, not by distinctness validation. In the main loop, decoded zero takes precedence over all configured operators.

### Single-value wildcard

The function decodes one subject value. Zero returns 0; any nonzero value satisfies the wildcard. No normalization occurs.

### Escape and ordinary literals

An escape recognized with escape state clear sets that state without consuming a subject value.

An ordinary literal decodes one subject value. If normalization is enabled, eligible pattern normalization occurs first, followed by eligible subject normalization. The resulting values are compared:

- Unequal values return 0.
- Equal values clear escape state and continue.

There is no independent rejection of a zero subject result on this path.

A trailing escape is not separately rejected. The following zero pattern result uses the ordinary raw-byte subject-end check, so a trailing escape can succeed against an exhausted subject.

An escaped bracket opener still begins a bracket expression. Successful bracket processing does not clear escape state. That state persists until a successful ordinary literal comparison or return.

### Normalization rules and widths

Normalization operates on 32-bit decoded values. Eligibility is determined by interpreting the value as signed 32-bit and testing whether it is less than 128. An eligible value selects one byte from the retained table; that byte is zero-extended to become the replacement value.

Consequently:

- Nonnegative values 0–127 are eligible.
- Nonnegative values 128 and above are unchanged.
- Values with the high bit set are also eligible under the signed test.

The table address expression uses the full 32-bit value, not an index first narrowed to one byte. The represented base-plus-index computation has 32-bit unsigned arithmetic behavior; this does not establish that the resulting address is valid. High-bit values must not be treated as safely bounded ASCII indexes.

Normalization applies only to ordinary literal comparisons and post-wildcard literal searches. It does not apply to operator recognition, bracket membership, or range endpoints.

The table is not established to be stable, idempotent, or a case-folding table.

### Bracket expressions

Bracket processing first decodes a subject value. Zero returns 0 before bracket contents are examined.

The syntax uses fixed decoded values:

| Value | Meaning |
|---|---|
| 94 | Leading negation marker. |
| 93 | Closing delimiter, except for the initial-literal rule and range endpoints. |
| 45 | Potential range separator. |

An initial 94 enables negation and causes another pattern decode.

If the first value after optional negation is 93, it contributes a literal closing-bracket member. It does not establish the previous-member value used for range recognition. Scanning continues with another decode.

For values processed as scanned members:

- Zero returns 0.
- 93 closes the expression.
- An ordinary value becomes the previous member and establishes membership if equal to the subject.
- 45 may introduce a range.

A hyphen introduces a range only when the raw byte at the current pattern cursor is neither zero nor 93, and the previous member is positive under a signed 32-bit interpretation. Otherwise the hyphen is an ordinary member.

For a recognized range, the next decoded value is consumed directly as the upper endpoint. The subject contributes range membership when its signed 32-bit value lies inclusively between the previous member and that endpoint. The previous-member state is then reset to zero.

**Endpoint decoding bypasses the scanned-member termination checks.** An endpoint of zero does not immediately fail. An endpoint of 93 does not close the expression. Either participates in the signed comparison, resets previous-member state, and is followed by another decode for ordinary scanning. The raw-byte guard does not prove these decoded endpoint values impossible.

Membership is cumulative: once established, it remains established while the expression is scanned. The function still requires a closing delimiter encountered as a scanned member; it does not stop after the first match.

At closing:

- A non-negated expression succeeds when membership was established.
- A negated expression succeeds when membership was not established.

Bracket processing performs no normalization and recognizes no escape syntax. A reversed range adds no range membership, although its previously scanned lower endpoint may already have matched as an ordinary member.

### Variable-length wildcard prefix processing

After recognizing a variable-length wildcard, the function decodes subsequent pattern values while they equal either configured wildcard.

Every subsequent value equal to the single-value wildcard causes one subject decode; zero fails. Additional variable-length wildcard values otherwise consume no subject.

If both wildcard values are equal, every subsequent occurrence of that shared value requires a subject decode. The initial occurrence that entered this path does not.

The wildcard-equality tests occur before the post-prefix zero test. Therefore a zero-valued configured wildcard can cause a decoded zero to remain in this scan. Main-loop zero precedence must not be generalized to this internal scan. Termination then depends on later decoder results and, where applicable, subject decoding.

Once a value unequal to both wildcards is obtained:

- Zero returns 1 without examining the remaining subject.
- Escape causes one additional pattern decode to obtain a literal target; a zero target returns 0.
- A bracket opener selects bracket-search retries.
- Any other value becomes a literal-search target.

Escape recognition precedes bracket recognition at this position, unlike main dispatch. A target obtained through escape is searched literally even if it identifies an operator elsewhere.

### Post-wildcard literal search

The pattern cursor now identifies the suffix after the target. Subject candidates are decoded successively. A matching candidate triggers recursive matching of that suffix against the subject cursor already advanced past the candidate.

A nonzero recursive result returns 1. A zero result begins another outer search attempt from the caller’s retained subject cursor. Recursive cursor progress does not directly replace that cursor.

#### Normalization disabled

The first subject decode of each outer attempt is checked for zero. Zero returns 0. Nonzero candidates are compared directly with the target.

Following a mismatch, another subject value is decoded and checked for zero before comparison. Thus decoded zero terminates this unnormalized search.

#### Normalization enabled

The first candidate of each outer attempt follows this order:

1. Decode the subject candidate.
2. Reject it immediately if the decoded result is zero.
3. Normalize the subject candidate if eligible.
4. Normalize the retained target if eligible.
5. Reject the normalized subject candidate if it is zero.
6. Compare normalized subject and target.

After a mismatch, each inner-search iteration decodes another subject value and normalizes it if eligible **before** checking whether the resulting subject value is zero. The retained target is not normalized again during these inner iterations.

This distinction is observable:

- An initial decoded zero fails before any candidate or target table access for that attempt.
- A subsequent decoded zero can become a nonzero candidate through table entry 0 and can match.
- A nonzero decoded value normalized to zero fails before comparison.
- Even if both normalized values would be zero, the subject-zero rejection prevents a match.

After a matching candidate whose recursive suffix fails, the next outer attempt again applies the initial decoded-zero check and then eligible subject and target normalization. The target therefore can be transformed repeatedly across outer attempts. Idempotence is not established.

Normalization is performed with the retained table base, but actual entries are read when each normalization occurs. No assumption is made that intervening calls preserve the table contents.

### Post-wildcard bracket search

The pattern cursor has already advanced past the decoded opener. Each recursive attempt starts **one byte before that cursor**, rather than at a saved pre-decode position.

Before each attempt, a raw zero byte at the current subject cursor returns 0. Otherwise the function recursively matches from the rewound pattern position and current subject position.

Following a failed attempt, it reads the current subject byte and advances one byte. If the byte read was greater than 191, it additionally skips following bytes while their top two bits equal binary 10.

This is a byte-oriented skip, not a decoder call or a validated encoding operation. Initial bytes from 128 through 191 advance only one byte.

Following a successful recursive attempt, the caller reads its current subject byte again. Zero returns 0; nonzero returns 1. This second read remains observable if dependencies mutate shared storage.

The one-byte rewind identifies the original opener only when the decoder’s representation and advancement make that true.
