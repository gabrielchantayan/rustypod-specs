# F-b90e950a0383

## Purpose

F-b90e950a0383 obtains a candidate 32-bit value, rejects a zero candidate or one already present in an associated sequence, and otherwise attempts to place the candidate in the sequence’s first zero-valued slot.

The established behavior is **hole filling, not appending**: after an optional dependency call, the function searches only within the sequence’s recorded scan length. If no zero-valued slot exists in that range, it returns −1 without directly inserting anything.

A successful insertion returns the selected zero-based index and increments a separate 32-bit metadata field. The meaning of that metadata field is not established. Interpreting it as capacity, occupancy, or another particular quantity would require additional evidence.

## Interface

### Inputs

The function has no explicit parameters.

Its effective inputs come from four dependencies and the memory reached through their results:

1. F-8157a180d901 receives the fixed value 72.
2. F-df2422ba76c2 receives the first dependency’s result followed by two zero arguments. Its result is the candidate value.
3. F-ecd921e533b1 receives the nonzero candidate and returns access to a descriptor.
4. F-1ee6cb5fd8a8 conditionally receives that descriptor.

No explicit context, sequence address, or length is supplied by the caller of F-b90e950a0383.

### Result

The result is a signed 32-bit integer:

- **−1:** the candidate was zero, a duplicate was found, or no zero-valued slot was found during the insertion search.
- **A nonnegative index:** the candidate was written to that indexed slot.

The three ordinary failure conditions share the same result. No distinct error code identifies which condition occurred.

The nonnegative result identifies the insertion-search index, not the candidate value or the metadata value.

### Descriptor layout

The supplied representation accesses a descriptor containing at least three consecutive 32-bit fields:

| Byte offset | Contract name | Observed use |
|---|---|---|
| 0 | Entry-array address | Address of the first four-byte entry |
| 4 | Scan length | Signed bound for both searches |
| 8 | Auxiliary counter | Compared with scan length; incremented on insertion |

Entries occupy four bytes each. Entry index zero is at the entry-array address; subsequent entries are separated by four bytes.

These names describe access patterns rather than recovered domain semantics. In particular, “auxiliary counter” does not establish what the field counts.

### Preconditions for ordinary completion

For behavior to complete without an invalid memory access or arithmetic ambiguity:

- Every dependency that is reached must return normally.
- F-ecd921e533b1 must provide a descriptor valid for the subsequent accesses.
- Every entry accessed under the current scan length must be readable.
- The selected insertion entry and auxiliary counter must be writable.
- Relevant address calculations, loop increments, and the auxiliary-counter increment must be valid in the execution environment.
- If F-1ee6cb5fd8a8 changes the descriptor or its backing storage, subsequent accesses through the retained descriptor reference must remain valid.

The function does not explicitly validate these conditions.

## Behavior

### Candidate acquisition

The function first calls F-8157a180d901 with 72. It passes the resulting 32-bit value to F-df2422ba76c2, together with two zero arguments.

The returned candidate is treated as a 32-bit integer. Zero causes an immediate return of −1. On that path:

- F-ecd921e533b1 is not called.
- No descriptor is accessed directly by this function.
- The optional descriptor dependency is not called.

Any nonzero candidate, including a negative signed value, proceeds. The function does not impose a positive-value requirement.

The literal 72 is an established argument value. Its purpose, and whether the first dependency allocates or looks up anything, are unknown.

### Descriptor lookup and duplicate rejection

For a nonzero candidate, the function calls F-ecd921e533b1 with that candidate.

It then searches the descriptor’s entry array in increasing index order, starting at zero. Each visited entry is compared with the candidate using the full 32-bit integer value.

If an equal entry is encountered, the function immediately returns −1. It does not call F-1ee6cb5fd8a8 and does not directly modify the descriptor or entries on that path.

The duplicate search uses the descriptor’s scan-length field as its loop bound. That field is consulted as the loop proceeds rather than explicitly captured once for the whole duplicate search. Entry addresses are derived from the descriptor’s entry-array field during the search.

Under stable memory, a positive scan length causes entries from index zero through one less than that length to be examined, stopping early on a match. A zero or negative signed scan length causes no duplicate-entry reads.

### Conditional descriptor operation

After duplicate rejection has completed without a match, the function compares the auxiliary counter with the scan length.

If those fields are equal, it calls F-1ee6cb5fd8a8 with the descriptor. Otherwise, it skips that call.

This comparison occurs **before** the search for a zero-valued insertion slot. Consequently, equality triggers the dependency even when an existing zero slot would already be available.

No return value from this dependency is used. There is no explicit failure check after it returns.

The function retains its descriptor reference. It subsequently rereads the scan length and accesses the descriptor’s entry-array field; it does not repeat F-ecd921e533b1. Changes made by the conditional dependency can therefore affect the following search, provided the retained descriptor remains valid.

### Insertion search

After the conditional operation, the function captures the descriptor’s current scan length for the insertion search.

It examines entries in increasing index order, starting at zero, looking for the first entry whose 32-bit value is zero. The search uses the captured bound, not a freshly read bound on every iteration.

Under valid, stable memory:

- If one or more entries are zero within the captured range, the first such index is selected.
- If no entry is zero in that range, the result is −1.
- If the captured scan length is zero or negative, no entries are examined and the result is −1.

The function does not search beyond the captured bound. It does not select an end position for append insertion.

The duplicate search is not repeated after F-1ee6cb5fd8a8. A dependency-induced change to the entries therefore does not receive another duplicate check before insertion.

### Insertion commit

When the insertion search finds a zero slot within its valid range, the function:

1. Reads the auxiliary counter.
2. Increments that value by one.
3. Writes the incremented value back to the descriptor.
4. Reads the entry-array address from the descriptor.
5. Writes the candidate into the selected four-byte slot.
6. Returns the selected index.

For an ordinarily completed search, the selected index is nonnegative and strictly below the captured scan length. The additional conditions governing the commit do not exclude index zero. A zero slot at index zero is a successful insertion location.

The scan-length field is not directly changed by this function.

If no zero slot was found, the function returns −1 without directly incrementing the auxiliary counter or writing an entry.

### Arithmetic and comparison boundaries

The scan lengths, indices, and auxiliary-counter operations are represented as signed 32-bit integer operations. Entries and the candidate are also four-byte values.

Important consequences:

- A negative scan length is not treated as a large unsigned length.
- A negative nonzero candidate remains eligible for insertion.
- Zero is the vacancy marker and cannot be inserted through the ordinary candidate path.
- The duplicate test is equality, not ordering.
- Entry addressing uses four-byte spacing.
- The auxiliary-counter increment has no visible overflow guard.

The supplied representation does not establish a portable outcome for signed overflow or invalid address arithmetic. In particular, this contract does not promise that incrementing the greatest signed 32-bit value wraps to the least signed value.

## Side effects

### Direct memory effects

On a successful insertion, the function directly performs two writes, in this order:

1. The incremented auxiliary counter.
2. The candidate at the selected entry.

It does not directly write the scan length or the entry-array address.

There is no explicit rollback mechanism. If execution fails during the entry write after the auxiliary-counter write has completed, the earlier write is not explicitly undone.

On the ordinary −1 paths, there are no direct descriptor or entry writes. This does **not** imply that the overall operation is side-effect-free: dependencies may already have changed other state, the descriptor, or its backing storage.

### Dependency effects and ownership

The supplied body establishes neither allocation ownership nor cleanup obligations.

Specifically:

- The value returned by F-8157a180d901 is passed onward without visible inspection or release.
- The candidate is stored as a four-byte value, not visibly copied as a separately described object.
- No explicit release operation occurs when a zero candidate, duplicate, or missing slot causes failure.
- The descriptor and entry storage are not explicitly released.
- Unknown dependencies must not be assumed to preserve global state, preserve descriptor contents, or leave memory ownership unchanged.

There is no visible synchronization. Thread safety, signal safety, and behavior under concurrent mutation are not established. Stable-memory acceptance examples below do not extend to unsynchronized changes between the duplicate check and insertion.

## Acceptance examples

These examples are conditional specifications, not runtime observations. Unless stated otherwise, assume valid memory, normal dependency returns, stable descriptor contents outside the described effects, and representable arithmetic.

### Zero candidate

If F-df2422ba76c2 returns zero:

- The result is −1.
- Descriptor lookup does not occur.
- No direct descriptor or entry write occurs.
- Effects already caused by the first two dependencies remain unspecified.

### Existing candidate

Suppose the candidate is 19, the scan length is three, and the entries are 8, 19, and 0.

The duplicate search finds the candidate at index one and returns −1. The zero slot at index two is not used. The conditional descriptor dependency is not called, even if auxiliary counter and scan length are equal.

### First hole at index zero

Suppose the candidate is 19, the scan length is three, the auxiliary counter is one, and the entries are 0, 8, and 0.

The fields compared for the conditional call are unequal, so that call is skipped. The function selects index zero, writes auxiliary counter two, writes 19 into entry zero, and returns zero.

The later zero entry remains unchanged.

### First hole after an occupied entry

Suppose the candidate is −7, the scan length is three, the auxiliary counter is one, and the entries are 8, 0, and 0.

The candidate is nonzero and not already present. The function selects index one, increments the auxiliary counter to two, writes −7 at index one, and returns one.

### No hole despite unequal metadata

Suppose the candidate is 19, the scan length is two, the auxiliary counter is one, and the entries are 8 and 9.

The conditional dependency is skipped. The insertion search finds no zero entry, so the function returns −1. It does not append an entry or directly change either metadata field.

### Conditional dependency changes the searchable range

Suppose the candidate is absent from the initial range and auxiliary counter equals scan length. F-1ee6cb5fd8a8 is called.

If it returns with a valid retained descriptor whose current range contains a zero slot, the insertion search can use that slot, including a slot outside the earlier duplicate-search range.

If it instead leaves a range containing no zero slot, the result is −1. Any dependency effects are not explicitly reversed.

### Empty or negative range

If the post-dependency scan length is zero or negative, the insertion search performs no entry reads and returns −1.

Before that point, the conditional dependency is still governed by equality of the two metadata fields. For example, two zero fields trigger it; a zero scan length alone does not determine whether it is called.

## Uncertainties

The following are **documented_only**:

- The domain meaning of the candidate, the literal 72, and both zero arguments.
- Whether the first two dependencies allocate, acquire, look up, or transfer anything.
- Whether the auxiliary counter denotes occupancy, capacity, or another quantity.
- Whether F-1ee6cb5fd8a8 grows storage or performs some unrelated operation.
- Null, invalid-address, exception, and other abnormal behavior of dependencies.
- Ownership and lifetime guarantees for the descriptor and entry storage.
- Whether descriptor storage can alias the entries.
- Whether dependencies modify global state or invalidate previously obtained references.
- Exact execution behavior on signed overflow or invalid address calculations.
- Concurrency guarantees and the effects of mutation between reads.

An inferred intent is to register a nonzero candidate into a sparse sequence while preventing duplicates. That interpretation is weaker than the established behavior: duplicate prevention covers the earlier search state, and the optional dependency can intervene before insertion.
