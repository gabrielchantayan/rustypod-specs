# F-3143474ecc5b

## Purpose

F-3143474ecc5b updates a caller-supplied object’s 32-bit accumulated value. If the signed interpretation of the updated value is below 10,000, it performs additional processing that can insert an embedded node into a globally reachable linked list.

The below-threshold path has observable effects even when no insertion occurs:

- Two preliminary dependencies run, and a global word is copied into the object before an existing-membership check.
- A nonzero membership word ends processing at that point.
- With zero membership, two more dependencies run before a scheduling quantity is read.
- A zero scheduling quantity skips insertion but does not skip the final dependency and dispatch decision.
- The final dispatch decision follows two levels of pointer access from a reread global value. The first dereference is unconditional on that path; only the resulting pointer is checked for null.

Scheduling, timing, and membership terminology describes apparent roles, not established application semantics.

## Behavior

### Accumulation and threshold

The function reads object offset `0x6c`, adds the increment, and writes the retained 32-bit result back to that offset. This write occurs before any dependency call and before the threshold-based return.

For the signed interpretation of the stored result:

- A value at least 10,000 returns without further processing.
- A value below 10,000 proceeds to preliminary processing.

The supplied arithmetic uses an intermediate boundary at 8,192 and subtraction-overflow predicates. Together, these establish the signed threshold above; 8,192 is not an additional externally visible processing threshold.

Negative results proceed. No lower-bound check, saturation, or overflow rejection is visible. The decision concerns the signed interpretation of the wrapped result, not the unbounded mathematical sum.

### Preliminary processing and membership check

For a below-threshold result, the observable sequence is:

1. F-6904f7699031 receives the embedded-node address, object address plus `0x30`.
2. F-936a8728139d is called with no explicit arguments.
3. G-state is read and its word is written to object offset `0x50`.
4. Object offset `0x4c` is read.

A nonzero membership-like word ends the function here. The accumulated-value write, both calls, and the state-word copy have already occurred.

The membership check observes the field after both dependencies return. It does not use an entry-time snapshot, and the dependencies’ effects on that field are unknown.

### Scheduling decision

If membership is zero, the function reads G-entry and passes that word to F-338d16f9ce72. It then calls F-add44d4e9aaa with the embedded-node address.

Only after both calls does it read the word at object offset `0x34`.

- Zero skips key construction and insertion.
- Any nonzero bit pattern selects key construction and insertion.

The zero case continues to the final dependency and dispatch decision; it is not an immediate return.

The captured scheduling quantity is retained for subsequent arithmetic. It is not reread after the key-producing dependency runs.

### Key construction and head capture

On the nonzero-scheduling path, the function calls U-1 and captures its 32-bit result. It then reads G-head-slot and retains the resulting address of the list-head word.

Next it writes the computed key to object offset `0x38`:

\[
\text{key}
=
\left(
\text{U-1 result}
+
1000 \times \text{captured scheduling quantity}
\right)
\bmod 2^{32}.
\]

It then reads G-tag, writes that word to object offset `0x48`, and reads the head-node address from the retained head-word location.

Multiplication and addition have no visible overflow check or saturation. Negative scheduling quantities are not rejected. The units, epoch, and interpretation of the returned word and key are unknown.

The order matters: U-1 runs before G-head-slot is read; the key and tag writes occur before the head-node word is read.

### Traversal and position selection

Traversal starts with the captured head-node address and no predecessor.

For each nonnull candidate, F-0d70d6f9010c receives five values:

1. The candidate-node address plus eight bytes.
2. The address of the object’s key at offset `0x38`.
3. Opaque input 3.
4. Opaque input 4.
5. A machine-state-derived value whose origin and validity requirements are not established.

The dependency’s result controls traversal solely by zero versus nonzero:

- Zero advances past the candidate.
- Nonzero stops before the candidate.

When the result is zero, the candidate’s first word is read **after** the dependency returns. That candidate becomes the predecessor, and the word just read supplies the next candidate.

Thus an empty list causes no comparison call. A nonzero first result selects head insertion. Zero results through a finite list select tail insertion.

No visible comparison in F-3143474ecc5b establishes numeric ordering, treatment of equal keys, or the meaning of positive versus negative results. All nonzero results have the same stopping effect.

Dependencies are not assumed to preserve links or keys. The traversal uses the post-call next word when advancing and does not reread the global head to restart traversal.

### Insertion writes

After traversal stops, the function publishes the embedded node in this order:

1. Write its address into the retained head-word location if no predecessor exists; otherwise, write its address into the predecessor’s first word.
2. Write exactly 1 to object offset `0x4c`.
3. Write the stopping candidate address, possibly null, into object offset `0x30`.

The inserted address is the object address plus `0x30`, not the object base.

The publication write precedes this function’s initialization of the embedded node’s next link. No explicit atomic operation, memory barrier, rollback, or synchronization guarantee is visible. Any protection supplied by surrounding dependencies remains unknown.

### Final dependency and dispatch decision

This path is reached after insertion or after the zero-scheduling skip, but not after either earlier return.

The function first reads G-exit and passes that word to F-5bcae2eff9a7. After that call returns:

1. G-entry is read again to obtain an **entry-slot address**.
2. The four-byte word at that address is read **unconditionally** to obtain a **dispatch-state pointer**.
3. If the dispatch-state pointer is null, dispatch is skipped without reading through that pointer.
4. If it is nonnull, its first four-byte word is read.
5. If that word is nonzero, U-2 is invoked through G-dispatch. Otherwise, dispatch is skipped.

The entry-slot address is not checked for null before its dereference. Consequently, a null final G-entry value is not an established safe skip.

The dispatch-state pointer and its first word gate the call; neither supplies the function target. The target comes from G-dispatch. No explicit arguments are shown for the indirect call, but its complete calling convention is unresolved.

The final G-entry read is independent of the earlier read used for F-338d16f9ce72. Intervening dependencies may change the global or the addressed storage.

## Acceptance examples

These are conditional examples, not executed tests. Unless stated otherwise, assume valid reached storage, normally returning dependencies, and no dependency mutation of the fields, globals, or links relevant to the example.

1. **Exact threshold.** An accumulated value of 9,990 plus an increment of 10 stores 10,000. No dependency runs and no other direct write occurs.

2. **Below threshold and intermediate boundary.** A result of 9,999 reaches preliminary processing. Results of 8,191 and 8,192 also reach that processing; neither causes a threshold return.

3. **Signed wraparound.** An accumulated value of 2,147,483,647 plus 1 stores the bit pattern representing −2,147,483,648. That signed result reaches preliminary processing.

4. **Existing membership.** If the checked membership value is 7, both preliminary dependencies and the `0x50` write occur before return. The later dependencies, insertion path, and final dispatch path are not reached.

5. **Zero scheduling.** With zero membership and a scheduling quantity read as zero, F-338d16f9ce72 and F-add44d4e9aaa run. U-1, comparisons, and insertion writes are skipped. F-5bcae2eff9a7 and the final pointer-access sequence still occur.

6. **Empty-list insertion.** A captured scheduling quantity of 2 and U-1 result of 5,000 produce key 7,000. If the captured head is null, no comparison runs. The head word is written with the embedded-node address, membership becomes 1, and the embedded next word becomes null, in that order.

7. **Negative scheduling arithmetic.** A captured scheduling quantity of −1 and U-1 result of 500 produce key \(2^{32}-500\). The nonzero scheduling quantity still selects insertion.

8. **Insertion between candidates.** If the first comparison returns zero and the second returns any nonzero value, the first candidate becomes the predecessor. Its next word is written with the embedded-node address; membership is then set to 1; the embedded next word is then written with the second candidate’s address.

9. **Valid entry slot containing null.** If the final G-entry value addresses a readable word containing a null pointer, that word is read and dispatch is skipped. No read through the null pointer occurs.

10. **Nonnull dispatch state.** If the entry slot contains a nonnull pointer, that pointer’s first word is read. Zero skips dispatch; nonzero selects U-2 through G-dispatch.

11. **Null final G-entry.** If the final G-entry value is null, the function still attempts its first dereference. This is not a successful null-skip case; the resulting behavior is outside the established valid-execution contract.

12. **Changed final entry.** If a dependency changes G-entry after its earlier use, final dispatch uses the reread value and the pointer found there, not the earlier argument to F-338d16f9ce72.
