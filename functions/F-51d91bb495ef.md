# F-51d91bb495ef

## Purpose

F-51d91bb495ef coordinates a mode-dependent operation on an existing object, issues a subsequent notification, and conditionally performs an additional operation using a newly obtained handle.

The established behavior consists of:

- Mapping a caller-supplied selector to one of three mode values.
- Calling the mode-dependent operation between two calls that each receive the object’s current word at offset `0x78`.
- Issuing a notification using the object’s current word at offset `0x70`.
- Obtaining a context and requesting a candidate handle.
- If that handle is nonzero, associating it with the caller’s payload and selecting a global value for a final context operation.
- Performing one additional handle operation for two of the three modes.

The semantic meanings of the object, payload, notification, candidate handle, and global values are not established. In particular, the first two dependencies cannot be identified as lock and unlock operations solely from their placement.

## Behavior

The function reads the four-byte value at object offset `0x78` and passes it as the sole argument to F-4a19e3742733.

This call precedes the selector-dependent operation. Its return value, if any, is not used explicitly.

The field value is not retained for the later call to F-fd58bea73663. That later call uses a fresh read.

### 2. Mode selection and primary operation

The selector determines a mode according to this complete partition:

| Selector | Mode |
|---|---:|
| Exactly zero | 2 |
| Exactly one | 3 |
| Any other 32-bit value | 4 |

F-8c28795990ad is then called with:

1. The original object address.
2. The original payload.
3. The selected mode.

There is no clamping, arithmetic transformation, or error branch for other selector values. Negative values, if interpreted as signed, and large positive values both fall into mode 4 unless equal to zero or one.

The selected mode also determines whether a later handle operation occurs. It is not recomputed from object contents or global state.

### 3. Second object-field operation

After F-8c28795990ad returns, the function reads the four-byte value at object offset `0x78` again and passes that value to F-fd58bea73663.

The two calls surrounding F-8c28795990ad therefore need not receive equal arguments. Any intervening permitted mutation of the field is visible to the second read.

The evidence does not establish whether either surrounding call acquires, releases, validates, or otherwise manages a resource. Their placement establishes ordering, not resource semantics.

### 4. Notification

After F-fd58bea73663 returns, F-fcf93acd4f3e is called with:

1. The current four-byte value at object offset `0x70`.
2. A value obtained from a notification-related global.
3. The original payload.

The object field and global are evaluated for this call after the preceding dependency returns. The supplied representation does not establish their relative read order within argument preparation.

The notification’s result is not explicitly inspected. This notification occurs before the context and candidate-handle requests, including when the eventual candidate handle is zero.

### 5. Context and candidate acquisition

1. F-f56d933c1225, retaining its result as an opaque context.
2. F-8157a180d901 with the literal argument 4, retaining its result.
3. F-8c34796da81c with that retained result followed by two literal zero arguments.

The return from F-8c34796da81c is treated as a 32-bit candidate value and tested against zero.

There is no explicit check of the context result or of the result from F-8157a180d901. Whatever the latter returns is forwarded to F-8c34796da81c.

The argument 4 is established. Its meaning—such as a size, kind, count, or identifier—is not.

### 6. Zero-candidate path

Specifically, it does not call:

- F-5399f0fd65ec.
- F-be88abc7b50c.
- F-277760632f43.

It also does not reach the two global-value reads used by that remaining work.

The preceding object operations, notification, context request, and candidate request have already occurred. No rollback or explicit failure report is present.

### 7. Nonzero-candidate path

If the candidate is nonzero, F-5399f0fd65ec is called with:

1. The candidate.
2. The original payload.

After that call returns, the function reads a first selection-related global value.

The selected mode then determines the remainder:

- **Mode 3:** The first global value is retained for the final call. F-be88abc7b50c is not called.
- **Mode 2 or mode 4:** F-be88abc7b50c is called with the candidate and an auxiliary machine-state value whose definition is unresolved. After that call returns, a second selection-related global is read, replacing the first value for purposes of the final call.

The first selection-related global is thus read on every nonzero-candidate path, including paths where its value is subsequently replaced. The second is read only for modes 2 and 4.

Finally, F-277760632f43 is called with:

1. The context previously returned by F-f56d933c1225.
2. The selected global value.

The function then returns.
