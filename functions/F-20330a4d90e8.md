# F-20330a4d90e8

## Purpose

F-20330a4d90e8 brackets an initial dependency call with writes to an object flag, optionally updates another object field, and selects between an immediate return and a dependency-driven continuation.

The supplied static representation establishes three outcomes:

- Return the 32-bit value `1` when either status comparison is nonzero.
- Complete the continuation and return the 32-bit value saved from the initial dependency call.
- Enter F-a817d8d58c10, which is marked non-returning.

The first status condition is derived by reading a **32-bit object word and converting its value to a character**. It is not represented as a one-byte memory read. The second status condition is an explicit character-sized memory read.

Domain meanings such as success, resource lookup, conversion, or notification are not established. The contract therefore uses opaque dependency IDs, object offsets, and dispatch-table offsets.

## Interface

### Inputs

The function receives:

1. **Object address:** a pointer to mutable storage containing fields and an initial dispatch-table pointer.
2. **Control word:** an unsigned 32-bit value.

The represented target uses four-byte integer words and a 32-bit address model. Offsets below are byte offsets calculated under that model. The representation does not establish byte order.

The control word is tested for zero, later passed unchanged to an indirect call, and also passed after bitwise exclusive-or with `1`. It is not restricted to Boolean values.

### Output

Normal return produces a 32-bit value:

- `1` on either status-triggered early-return path.
- The value saved from F-7e4c44a0943f on the completed continuation path.

The saved value is not tested before continuation. Its semantic type and meaning are unknown.

## Behavior

### Initial call and flag overwrite

The first direct effect is a one-byte write of `1` at object offset `+0xF8`.

The function then calls F-7e4c44a0943f with the object address and retains its 32-bit result. If that call returns normally, the function writes one byte containing `0` at `+0xF8`.

The prior flag value is neither read nor restored. Any value written there by the initial dependency is also overwritten by the subsequent zero write.

No cleanup or flag-reset guarantee is established if the dependency does not return normally. The saved result does not determine the following branch.

### Optional field refresh

When the control word is nonzero, the function:

1. Calls F-76b1c50b12f7.
2. Calls F-22be49cfb47c.
3. Writes the latter result as a 32-bit value at object offset `+0xC8`.

Neither call has an explicit argument in the supplied representation. The first call’s result is not directly consumed by this function.

This sequence precedes both status checks. Consequently, an execution that eventually returns `1` may already have performed the refresh and written `+0xC8`.

When the control word is zero, these two calls and this direct field write are skipped. This does not imply that other dependencies leave the field unchanged.

### First status: word access followed by narrowing

The function reads the 32-bit word beginning at object offset `+0x20`, converts its value to a character, and compares the converted value with zero.

This distinction is observable at the contract level:

- The represented memory access has word width.
- The comparison uses the converted character, not the original full-width word.
- A nonzero word does not necessarily produce a nonzero converted character.
- The representation does not establish that a particular physical byte alone is read.

If the converted value is nonzero, the function returns `1` without reading `+0x41`.

If the converted value is zero, execution proceeds to the second status read. Under a low-eight-bit narrowing convention, upper word bits do not affect this comparison. Without establishing that convention, out-of-range conversions remain a documented limitation.

### Second status: explicit character read

Only after the first converted value compares equal to zero does the function read the character at object offset `+0x41`.

If this character is nonzero, the function returns `1`. If it is zero, continuation begins.

Unlike the first condition, this access is explicitly character-sized and addressed directly at `+0x41`. Character signedness does not change whether an already obtained character value is zero or nonzero.

Thus the two conditions are short-circuited, but they do not have identical memory-access widths.

### Continuation gate and first indirect dispatch

After both status comparisons observe zero, the function calls F-d99467d4d2b3 with the zero-valued character from the second check.

If that invocation returns zero, the function enters F-a817d8d58c10.

For a nonzero result, execution proceeds in this order:

1. Call F-938c950e5046 and retain its returned pointer.
2. Call F-d99467d4d2b3 again.
3. Use the retained pointer as receiver for an indirect call through its dispatch-table offset `+0xE8`, passing the second F-d99467d4d2b3 result as the other explicit argument.

The second gate call is distinct from the first. Its result is neither required nor checked to equal the first result. No explicit argument is shown for this second invocation; the true dependency signature is unresolved.

The receiver from F-938c950e5046 is not checked for null before dispatch. The result of the `+0xE8` call is checked:

- Null selects F-a817d8d58c10.
- Non-null selects further processing of the returned object.

### Conditional processing of the returned object

The function invokes the non-null returned object’s dispatch-table slot at `+0x1C`, with that object as receiver, and examines its 32-bit result.

A zero result skips directly to the final continuation.

For a nonzero result, the function calls F-682adfd5a561 with that result and the constant `0x6800`, decimal `26624`. Its returned pointer selects between two paths.

**Null result:**

1. Call F-8157a180d901 with `0x1C`, decimal `28`.
2. Call F-2606ad6d534d.
3. Invoke the previously obtained object’s dispatch-table slot at `+0x2C`, passing that object and the result of F-2606ad6d534d.

**Non-null result:**

- Invoke the new pointer’s dispatch-table slot at `+0x58`.

No explicit arguments are shown for the `+0x58` call. Its receiver or implicit context cannot be reconstructed reliably from this call site alone.

Neither indirect call’s result is consumed. Both branches reach the final continuation if their callees return normally. A null result from F-682adfd5a561 therefore selects a nonterminal fallback sequence, not F-a817d8d58c10.

### Final continuation and saved return

The function next:

1. Calls F-fdd8589eca2d.
2. Calls F-8f9bd59e3ec5 with that result and the original object address.
3. Invokes the original object’s dispatch-table slot at `+0x124`.

The final indirect call receives these explicit arguments, in order:

1. Original object address.
2. The 32-bit value read from object offset `+0xF0`.
3. Original control word.
4. Zero.
5. Original control word bitwise-exclusive-or `1`.

Exclusive-or changes only the least significant bit. It is not logical negation, and no arithmetic overflow is involved.

The `+0xF0` value and final dispatch state are obtained for this later call, not saved at entry. Earlier dependencies can therefore affect them if they mutate the object. The representation does not establish the relative evaluation order of the field read and dispatch-pointer reads within the final call expression.

The final indirect result is ignored. On its normal return, the function returns the value retained from F-7e4c44a0943f.

The first status word is read after the optional refresh. The `+0x41` character is read only if the first narrowed comparison is zero. The final `+0xF0` read occurs only on the completed continuation path.

All other effects belong to dependencies and indirect targets. Their effects on globals, external resources, synchronization, callbacks, object state, and lifetime are unknown.

No explicit allocation, release, ownership transfer, or reference-count operation is established in this body. Returned pointers do not by themselves establish ownership. The absence of local release operations neither proves a leak nor proves that release is unnecessary.

## Acceptance examples

These are conditional static acceptance examples, not executed tests. They assume valid storage and normally returning dependencies unless stated otherwise. Status values refer to observations after the initial call and any refresh.

1. **First converted status is nonzero.** If the 32-bit word at `+0x20` has numerical value `1`, its character conversion is nonzero. The function returns `1` without reading `+0x41`. The established first access remains a word read.

2. **Zero word permits the second read.** If the word at `+0x20` is zero, its conversion is zero. The character at `+0x41` is then read. A value of `1` there causes return value `1`.

3. **Nonzero word can narrow to zero.** Under a low-eight-bit narrowing convention, a word value of `0x00000100` converts to zero, so the second status is consulted. This example is conditional on the conversion convention; it is not a claim that the full word is tested for zero.

4. **Physical-byte interpretation depends on byte order.** Under low-eight-bit narrowing and little-endian storage, the first condition corresponds numerically to the byte at `+0x20`. Under big-endian storage of a four-byte word, the low-order byte instead resides at `+0x23`. Neither interpretation changes the represented word-width access.

5. **Refresh precedes early return.** With control word `2`, both refresh calls occur and the second result is stored at `+0xC8` before a status-triggered return of `1`.

6. **Control transformation is not Boolean negation.** On completed continuation, control word `2` supplies final control arguments `2` and `3`. Control word `0xFFFFFFFF` supplies `0xFFFFFFFF` and `0xFFFFFFFE`.

7. **Zero processing result skips conversion.** If continuation is permitted, `+0xE8` returns a valid object, and its `+0x1C` call returns zero, F-682adfd5a561 is skipped. Final continuation still occurs.

8. **Fallback remains nonterminal.** A nonzero `+0x1C` result followed by a null F-682adfd5a561 result invokes the fallback sequence. If it returns normally, final continuation follows and the saved initial result is returned.

9. **Terminal selection.** A zero first F-d99467d4d2b3 result or a null `+0xE8` result selects F-a817d8d58c10. Neither case has an established normal return value.

10. **Flag overwrite, not restoration.** An entry flag value of `7` is replaced by `1`, then by `0` after the initial dependency returns normally. The value `7` is not restored.
