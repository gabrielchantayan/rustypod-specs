# F-a0f273c6176e

## Purpose

F-a0f273c6176e repeatedly obtains a descriptor, captures two of its 32-bit words, invokes dependencies, and selects processing behavior from the descriptor’s third word. Some paths begin another outer iteration; others repeat an inner sequence indefinitely under the explicitly represented state transitions.

The established contract concerns call order, memory accesses, value widths, state capture, and branch behavior. An application-level purpose is not established.

The supplied representation contains invalid-instruction boundaries and overlapping global symbols. Consequently, this contract distinguishes:

- **Established static behavior:** explicit operations and their ordering in the supplied representation.
- **Inferred intent:** a possible interpretation, not an additional requirement.
- **documented_only unknowns:** behavior that cannot be resolved from the supplied evidence.

No normal return is represented. This does not establish that every execution continues indefinitely: dependencies may not return, memory accesses may fault, and behavior at incomplete instruction boundaries is unresolved.

## Interface

### Entry state

The displayed interface has no explicit parameters or return value. It nevertheless consumes inherited state:

| Input or state location | Represented width | Use |
|---|---:|---|
| First-call base | Address-sized | Determines the first indirect target of an outer iteration |
| Overflow condition | Boolean-like condition | Compared with a captured sign condition |
| Inherited byte | 8 bits | Used by a terminal-looking, statically unreachable sequence |
| Carried slot | 32 bits | Updated by inner-loop results, read by the outer tail, and overwritten after the tail call |
| Context slot | 32 bits | Captured each outer iteration; interpreted as an address or narrowed to 16 bits |
| Seed slot | 32 bits | Captured in the nonzero-shift path for later low-byte extraction |
| Working slot | 32 bits | Captured each outer iteration; subsequently used or replaced |
| Destination slot | 32 bits | Read as an address by the terminal-looking byte-write sequence |

These descriptions do not establish a calling convention, stack layout, or ownership protocol.

The slots are not all sampled at entry. Their capture points are observable requirements because intervening dependencies have no supplied preservation contracts.

### Descriptor

An indirect dependency supplies an address interpreted as 32-bit unsigned words:

| Offset | Access | Meaning in this contract |
|---|---|---|
| 0x00 | Read 32 bits | Initial first-word working value |
| 0x08 | Read 32 bits | Selector |
| 0x0C | Address passed onward | Address immediately following the selector |

No read at offset 0x04 is represented.

Three conditions are captured from the selector:

- Whether bit 13 is set.
- Whether interpreting the selector as signed 32-bit and arithmetically shifting it right by 14 produces a negative value.
- Whether that shifted value is zero.

The zero condition holds exactly for unsigned selector values 0x00000000 through 0x00003FFF. The sign condition reflects bit 31. Bit 13 may be set while the shifted result is zero.

These are captured conditions, not repeated descriptor reads.

### Access requirements and widths

Reached indirect targets must be executable, and reached memory accesses must be valid for their explicit widths. No preceding null, bounds, alignment, or ownership checks are represented.

The supplied data does not establish byte order, alignment requirements, address-space mapping, or fault recovery. Explicit byte and halfword accesses establish widths of 8 and 16 bits respectively. Assignments to the overlapping globals do **not** establish their destination widths.

## Behavior

### Outer-iteration setup

Each outer iteration performs the following sequence:

1. Capture the current context slot as a 32-bit context value.
2. Invoke **F-U01**, whose target is the inherited first-call base plus byte offset 0xF30.
3. Capture the current working slot as a 32-bit working value.
4. Invoke **F-U02**.
5. Invoke **F-U03** and take its result as the descriptor address.
6. Read the descriptor’s 32-bit first word at offset 0x00.
7. Read its 32-bit selector at offset 0x08 and capture the three conditions described above.
8. Invoke **F-U04**, passing the descriptor address plus 0x0C.
9. Invoke **F-U05**.
10. Invoke **F-fd74adab24b4**.
11. Invoke **F-172f180ab937**.
12. Invoke **F-U06**.
13. Invoke **F-U07**.

Thus, the context capture precedes the first call, but the working-slot capture follows that call. A dependency’s modification of the working slot before its capture can affect this iteration. Modification of the context slot after its capture is not an explicit refresh of the captured context.

The selector and first-word values are captured before the later setup calls. Those calls do not cause explicit descriptor rereads.

The shifted-zero condition selects the zero-shift path when true and the nonzero-shift path otherwise.

### Nonzero-shift path: preparation

This path applies to selectors outside 0x00000000–0x00003FFF.

**Twelve indirect calls precede the sign/overflow conditional**, in this order:

1. Invoke **F-U08**.
2. Capture the low 16 bits of the already captured context value. Then capture the current 32-bit seed slot. Invoke **F-U09**.
3. Invoke **F-U10**.
4. Invoke **F-U11**, passing the fixed address-valued argument 0x0870E684.
5. Replace the 32-bit working value with 0x0870E403. Invoke **F-U12**.
6. Invoke **F-U13**.
7. Invoke **F-U14**.
8. Invoke **F-U15**.
9. Invoke **F-U16**.
10. Invoke **F-U17**.
11. Invoke **F-U18**.
12. Invoke **F-U19**.

The seed capture therefore occurs after the first preparatory call and before the second. It must not be treated as an immutable entry snapshot.

The captured halfword is the low 16 bits of the context **address value**, not a halfword read from memory at that address. The meaning and ownership of the fixed address-valued argument are unknown.

After these twelve calls, the represented condition is true when either the captured shifted-zero condition is true or the captured sign differs from the inherited overflow condition. Since this path requires a false shifted-zero condition, its effective test is sign versus inherited overflow.

### Nonzero-shift path: matching sign and overflow

When sign and inherited overflow match:

1. Invoke **F-U29** and use its result as a destination address.
2. Write the captured context halfword at destination offset 0x04.
3. Invoke **F-U30**.
4. Invoke **F-U31**.
5. Invoke **F-U32**.
6. Read the current 32-bit carried slot and replace the working selector value with it.
7. Continue to the outer tail.

The carried-slot read occurs **after all three post-write calls**. Its value cannot be replaced contractually with the slot’s entry value: any of those dependencies may have modified it.

### Nonzero-shift path: differing sign and overflow

When sign differs from inherited overflow, the represented execution enters a loop:

- Before each condition test, extract the low byte of the current seed-derived value.
- Continue while the captured shifted-zero condition is false.
- In each body, replace the seed-derived value with 0x0870E660.
- Invoke **F-U20**, then **F-U21**.

The first extraction uses the captured seed. Subsequent extractions use the low byte 0x60 of the replacement constant.

No explicit assignment changes the shifted-zero condition. Under the represented transitions, this loop does not exit. The computed target for F-U20 differs between its first and subsequent iterations; its label identifies the call role, not a guarantee of a constant function target.

A sequence following the loop is present but not reached through those transitions. If reached through behavior not established by the representation, its displayed order would be:

1. Invoke **F-U22**, **F-U23**, **F-U24**, and **F-U25**.
2. Read the destination slot and write the captured byte at its address plus 0x0D.
3. Invoke **F-U26**.
4. Read the destination slot again and write that byte at its address plus 0x09.
5. Invoke **F-U27**.
6. Read the destination slot again and write the inherited byte at its address plus 0x11.
7. Invoke **F-U28**.
8. Execute software-breakpoint operation 0xC9 and reach an invalid-instruction boundary.

The three destination-slot reads are separated by calls. A single preserved destination must not be assumed. The effects of the breakpoint operation and subsequent invalid instruction remain unresolved.

### Zero-shift path: initial effects

This path applies to selectors from 0x00000000 through 0x00003FFF:

1. Invoke **F-U33** and take an 8-bit result.
2. Write that byte at address selector + 0x15.
3. Invoke **F-U34** and take its result as a destination address.
4. Write the selector’s low 16 bits at destination offset 0x3C.
5. Invoke **F-U35**.
6. Read 16 bits at captured context + 0x34.
7. Invoke **F-U36**, passing that halfword.

The first write address lies between 0x15 and 0x4014 inclusive. This addition cannot overflow 32 bits within the branch’s selector range. Whether those low addresses are writable is unknown.

The destination halfword preserves all selector bits because this branch restricts the selector to values below 0x4000.

### Zero-shift path: inner-loop prefix

Each inner iteration invokes, in order:

1. **F-U37**
2. **F-U38**
3. **F-U39**
4. **F-U40**
5. **F-U41**

The 32-bit result of F-U41 is assigned to the carried slot.

If captured selector bit 13 is clear, the inner loop exits immediately after that assignment and continues to the outer tail. This covers selectors 0x0000–0x1FFF.

If bit 13 is set, the iteration continues with the body below. The computed target for F-U37 changes between the first iteration and later iterations. Its role label does not establish a single fixed target.

A final conditional examines the sign condition set false at step 1. No intervening explicit assignment sets it true. Consequently, the represented transitions do not reach the conditional call to **F-645d55f3a7e5** or its following invalid-instruction boundary. The displayed argument would be the final result minus 0xC9; overflow behavior for that represented integer operation is not established.

Captured bit 13 is unchanged. This inner loop therefore repeats under the explicit transitions, subject to dependency nonreturn, faults, and unresolved machine-condition behavior.

### Outer tail

Every path reaching the outer tail performs these operations in order:

1. Replace the inherited first-call base with a fixed internal anchor.
2. Read the current carried slot and invoke **F-U50** with that 32-bit argument.
3. After the call returns, assign the working selector value to the carried slot.
4. Begin another outer iteration.

The base replacement occurs **before** the tail dependency, not after it. The carried-slot assignment occurs **after** that dependency.

For the zero-shift, bit-13-clear path, the tail passes the F-U41 result and subsequently stores the captured selector into the carried slot.

For the matching-sign nonzero-shift path, the working selector was replaced by the late carried-slot read after F-U32. With no intervening slot modification, that captured value is both passed to F-U50 and written to the slot afterward. F-U50’s own changes to the carried slot can be overwritten by the post-call assignment.

## Acceptance examples

These are conditional static scenarios, not executed tests. Each assumes preceding dependencies return and reached accesses are valid.

1. **Selector 0x00000000.** The zero-shift path writes the byte result at address 0x15 and a zero halfword at the returned destination plus 0x3C. After the context-offset-0x34 operation and five-call prefix, bit 13 is clear and execution reaches the outer tail.

2. **Selector 0x00001FFF.** The byte-write address is 0x2014; the destination halfword is 0x1FFF. The inner loop exits after its prefix.

3. **Selector 0x00002000.** The byte-write address is 0x2015. The bit-13-set body executes and repeats under the captured conditions. Its later global assignment receives a 16-bit constructed value, but the number of bytes stored is not established.

4. **Selector 0x00004000; inherited overflow false.** The sign is false. All twelve preparatory calls occur before the matching-sign branch. The destination-plus-0x04 write precedes three more calls, and the carried slot is sampled only after those calls.

5. **Selector 0x80000000; inherited overflow false.** The sign is true, so execution enters the two-call repeating path. The later destination byte writes and breakpoint are not reached through explicit state updates.

6. **A preparatory dependency changes the seed slot.** A change by F-U08 affects the subsequent seed capture. A later change does not explicitly refresh that captured value.

7. **F-U42 changes byte 0xC7 to 0x5A while the working value’s low byte is 0xA6.** The constructed value assigned afterward is 0xA65A. This predicts neither destination width nor memory byte order.

8. **F-U50 changes the carried slot before returning.** The explicit post-call assignment overwrites that slot with the working selector value. The first-call base was already replaced before F-U50 was invoked.
