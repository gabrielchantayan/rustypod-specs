## Behavior

### Entry captures and mandatory control update

The function first captures the 32-bit reference field at `+0x10`.

It then selects the unsigned maximum of the endpoint fields at `+0x2C` and `+0x04`. This is an unsigned 32-bit comparison, not a signed comparison.

The supplied representation includes an initial read of `+0x2C`, another read of that field for the comparison, and a conditional read of `+0x04` when the comparison selects that endpoint. Thus, replacing this description with an unconditional assertion that each endpoint is read exactly once would be stronger than the evidence. Under stable storage, the selected value is their unsigned maximum. With concurrent or externally changing storage, the evidence does not establish a coherent snapshot.

Next, the function captures the control word at `+0x0C` and writes that captured value back after applying mask `0xFFD7FFFF`.

This mandatory write clears:

- `0x00080000`, bit 19.
- `0x00200000`, bit 21.

All other control bits retain their captured values in this write.

The write occurs before the function decides whether to return success immediately, return failure immediately, or continue toward reconciliation. Even a value that fails the subsequent control checks undergoes this update.

### Control-based early returns

The branch decisions in this stage use the captured, pre-update control word.

First, the function tests its lowest two bits:

- If the masked value under `0x00000003` is exactly `0x00000001`, it returns success.
- On this path, no dependency is called and no direct write is made to `+0x04`, `+0x08`, or `+0x2C`.
- Bit 16 is not cleared by a later reconciliation step, because that step is bypassed.

Otherwise, it tests the captured control word under mask `0x00000082`:

- The masked result must be exactly `0x00000002`.
- This requires bit 1 to be set and bit 7 to be clear.
- If the requirement is not met, the function returns failure.

The lowest-two-bit success condition has precedence. An object satisfying it is accepted without applying the second test, even if bit 7 is set.

After passing the second test, the function checks bit 16, `0x00010000`, in the captured control word:

- If bit 16 is clear, it returns success without reconciliation.
- If bit 16 is set, it enters the reconciliation path.

Accordingly, success alone does not establish that endpoints were reset or that a dependency was invoked.

### Optional range operation

On the reconciliation path, the previously selected endpoint is compared with the previously captured reference.

If they are equal, the dependency call is skipped.

If they differ, F-1dbebb93bf31 is invoked with three arguments, in this order:

1. The captured reference value.
2. The selected endpoint minus the captured reference, using 32-bit unsigned arithmetic.
3. The original object argument.

Subtraction wraps modulo \(2^{32}\). There is no visible check that the selected endpoint is greater than or equal to the reference. A numerically smaller endpoint therefore produces a large unsigned difference rather than a rejection.

The dependency's result is represented as 64 bits:

- The low 32 bits are tested for zero.
- A nonzero low half causes immediate failure.
- A zero low half permits reconciliation to continue.
- The upper 32 bits are extracted, but they do not determine any subsequent direct store, branch, or public result in the shown behavior.

If the dependency reports failure, this function does not perform the subsequent endpoint resets or final control-bit clearing. Effects already performed by the dependency are not rolled back.

### Reconciliation writes

After a skipped dependency call or a dependency result with a zero low half, the function performs these direct effects in order:

1. Write the captured reference to `+0x2C`.
2. Write the captured reference to `+0x04`.
3. Read the current control word and inspect bit 24, `0x01000000`.
4. If bit 24 is clear, write zero to `+0x08`.
5. Read the current control word again, clear bit 16 with mask `0xFFFEFFFF`, and write the result to `+0x0C`.
6. Return success.

The two endpoint writes use the reference captured before the dependency call. They do not reload `+0x10`. A dependency change to the reference field therefore does not change these two stored values.

The bit-24 decision, in contrast, uses a post-call control-word read. A dependency change to that bit can determine whether `+0x08` is zeroed.

If bit 24 is set at that read, this function leaves `+0x08` untouched. That does not guarantee that the field equals its entry value: the dependency may have changed it.

The final control update also uses a fresh read. It clears bit 16 while preserving the other bits from that final read. It does not restore the initially captured control word.

## Side effects

### Direct writes

The direct write set is restricted to:

- `+0x0C`: always written once after initial captures; written again after successful reconciliation.
- `+0x2C`: written after successful or skipped range processing.
- `+0x04`: written immediately after `+0x2C` on that same path.
- `+0x08`: zeroed only when reconciliation proceeds and the subsequent bit-24 test is clear.

There is no direct write to `+0x10`.

Without dependency mutation or external interference, bits 19 and 21 remain cleared after the initial update. If the dependency changes those bits, the final update does not necessarily clear them again: its mask clears only bit 16.

### Failure and partial effects

There are two explicit failure cases:

1. The captured control word fails the second control test after not taking the lowest-two-bit success path.
2. F-1dbebb93bf31 returns a nonzero low 32-bit result.

Both occur after the initial control-word write. The second may also follow arbitrary dependency effects. The operation is therefore not transactional.

No retry, compensating action, or error-detail write is shown.
