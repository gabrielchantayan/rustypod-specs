### Widths and arithmetic

Dependency results are represented using both 32-bit and 64-bit quantities. A byte read widened into a word contributes a value between 0 and 255. Byte stores retain the source’s low eight bits.

The 64-bit result extractions perform right shifts on an **unsigned 64-bit value before conversion** to a 32-bit signed or unsigned quantity. Conversion of an extracted portion to a signed quantity does not make the preceding shift signed.

Its treatment of negative values and out-of-range shift counts requires platform confirmation. The represented count is masked to eight bits, so it can still exceed 31.

### Entry into direct mutation

The last prefix result supplies a high word used as an address base and a low word scaled by 256. Other retained results supply a left-shift-by-25 value, a separately calculated product by 2²⁵, and a compact masked quantity.

The compact quantity is formed by shifting a 32-bit result left by eight, retaining its low 15 bits, and shifting right by six. Under 32-bit bit-vector semantics, its possible values are multiples of four from 0 through 508. Its doubled value is consequently a multiple of eight from 0 through 1016. These bounds establish no storage-validity guarantee.

The first direct effects include a word write at offset 0x14 from the final high-word base, two distinct byte writes at offset 0x09 from a retained shifted base, and a word write at offset 0x54 from the scaled low-word base.

A separate offset-0x14 word is cleared. A byte at offset 0x05 from that base is read and widened for a word write at offset 0x34. The cleared word is subsequently read and retained. Other computed writes occur between these operations, so concluding that the read returns zero requires checking overlap.

Repeated clears and repeated byte stores remain separate access events.

## Acceptance examples

These are conditional review examples, not executed tests.

1. **Third argument 3:** if the represented shift and invocations execute normally, both early transformed contributions are 12. No 12-byte operation follows from that fact.

2. **Third argument zero:** its transformed contribution is zero. No zero-input early exit is represented.

3. **Unsigned extraction:** for a 64-bit result of 0x8000000000000001, unsigned extraction of the high word yields the bit pattern 0x80000000 before any signed conversion. The extraction is not a signed right shift.

4. **Byte widening:** an explicitly byte-wide computed read of 0xFE produces the widened value 254. This example does not assert that the fixed read at 0x05 is byte-wide.

5. **Compact quantity:** under 32-bit bit-vector semantics, the masked extraction can produce 508 and its doubled base can be 1016. This does not make accesses through that base valid.

6. **Clear and read:** if the offset-0x14 clear and later read reach stable ordinary storage without an overlapping modification, the saved read is zero. A later write through that zero-derived base is not repaired or skipped.

7. **Fixed-access ordering:** the 0x05 read precedes the 0x01 byte write; the fixed 0x54 word write precedes the later 0x15 byte write; and the late stored-address read precedes the fixed 0x60 word write.

8. **Fresh fixed reads:** if an intervening computed store changes storage observed at 0x67, a subsequent read for a working offset-0x09 byte write can observe the change. Reusing the originally saved byte would not preserve the represented behavior.

9. **Overlapping write:** a working offset-0x10 word write can replace an earlier byte at that offset and affect adjacent bytes according to platform byte order. No offset-0x10 word read is required by this region.

10. **Repeated observable writes:** device-backed destinations can observe individual repeated stores even when their values match.

11. **Final invocation reached:** after all preceding operations complete, the destination receives 0x72 first and the saved linked offset-0x14 value third. Later storage mutations do not themselves refresh that saved argument.
