# F-29265b828f07

## Purpose

F-29265b828f07 attempts to insert an item into a context-managed representation. It selects between:

- An immediate path that obtains access through dependencies, allocates an item location, transfers data, and inserts a two-byte location entry into an existing index.
- A deferred path that records a data address and a truncated index in an inline descriptor area.

The immediate path can also initiate a secondary operation after the insertion has already modified state. A failure from that secondary operation is returned without an observable rollback.

These descriptions distinguish established operations from inferred intent. “Insert,” “index,” and “deferred descriptor” are behavioral labels inferred from the access pattern; the source does not establish the surrounding data format or ownership model.

## Interface

The supplied interface has six 32-bit arguments and a 32-bit return value:

| Argument | Contract role |
|---|---|
| Context address | Address of the mutable context and its referenced structures. |
| Index | Signed 32-bit value used in immediate-path index positioning; stored as its low 16 bits on the deferred path. |
| Data address | Address-like 32-bit value passed to a transfer dependency or retained in a deferred descriptor. |
| Requested amount | Signed 32-bit value used in capacity selection, allocation, and address/length arithmetic. |
| Alternate address | Optional address-like value. Zero disables the deferred-path transfer to this address. |
| Prefix adjustment | Signed 32-bit value added to source and destination addresses and subtracted from the requested amount. |

The routine returns zero on the ordinary completion paths. It propagates nonzero results from three checked dependency calls. No local validation error is defined.

### Context layout

Offsets are byte offsets from the context address. Multibyte context fields are read or written using the target’s native representation unless an explicit byte order is specified below.

| Offset | Width | Observed use |
|---|---:|---|

Each deferred record receives a 32-bit data address at its start and a 16-bit index at offset four. The remaining two bytes of its eight-byte stride are not written by this routine.

The auxiliary header is addressed using the saved backing base plus the unsigned byte at context offset +8. Relative to that header:

- Bytes +5 and +6 form a big-endian unsigned 16-bit quantity.
- Bytes +3 and +4 receive the current entry count in big-endian order.

### Preconditions and validity limits

The routine performs no null, range, alignment, capacity, index, or ownership checks beyond the branch conditions described below.

A caller requiring defined operation must provide valid storage for every accessed location, a valid descriptor slot on the deferred path, and valid source and destination ranges for the transfer dependency. For conventional immediate insertion, the index should identify an insertion position within the current index; the routine does not enforce that constraint.

Negative amounts, negative adjustments, overflowing signed arithmetic, and overlapping context/backing storage are not rejected. Their intended validity is unknown. Where the displayed signed arithmetic can overflow, a portable mathematical interpretation is not established by this source alone.

## Behavior

### 1. Initial arithmetic and path selection

Before selecting a path, the routine forms:

- The data address advanced by the prefix adjustment.
- The requested amount reduced by the prefix adjustment.

The first result is used as a source-like address in transfer calls. The second is explicitly supplied only on the deferred path.

The immediate path is selected only when both conditions hold:

1. The byte at context offset +2 is zero.
2. The requested amount plus two, compared as a signed 32-bit value, is no greater than the zero-extended 16-bit value at context offset +18.

The second condition is short-circuited when the first fails. It is not an unsigned “amount fits” check: a negative requested amount can satisfy it. Overflow in the addition of two is not resolved by the supplied evidence.

All other cases take the deferred path.

### 2. Immediate-path preparation

The routine reads the 32-bit field at context offset +72 and calls F-81c906bf6e3a with that value.

- A nonzero result is returned immediately.
- A zero result permits processing to continue.

Only after that call succeeds does the routine read and save the backing base, auxiliary-header displacement, index-base displacement, and entry count. Thus, mutations made by F-81c906bf6e3a can affect these later reads.

Using the values read at this stage, it determines:

- The auxiliary-header address.
- The index end displacement: index base plus twice the current entry count.
- The insertion displacement: index base plus twice the supplied index.

It reads the big-endian 16-bit quantity at auxiliary-header bytes +5 and +6. The 32-bit subtraction of the requested amount from that quantity is interpreted as signed for comparison with the index end displacement plus two.

If that signed result is less than the index end displacement plus two, F-48bafd709153 is called with the context address.

- A nonzero result is returned immediately.
- A zero result permits insertion to continue.

The backing base, auxiliary-header address, index end, and insertion displacement are not recomputed after F-48bafd709153. Any requirement that these saved values remain valid across that call is a dependency precondition, not a demonstrated guarantee.

### 3. Immediate allocation, state updates, and transfer

F-cec90b5dcee3 is called with the context address and requested amount. Its 32-bit result is treated as an item displacement. There is no local failure check on that result.

After the call, the routine:

1. Reads the current 16-bit entry count and writes its incremented low 16 bits.
2. Reads the current 16-bit capacity-like field and writes its value minus two, truncated to 16 bits.
3. Invokes the external transfer dependency with a destination-like address formed from the saved backing base, returned item displacement, and prefix adjustment, and with the previously computed adjusted data address.

The supplied source displays only two arguments for this immediate-path transfer invocation. It does not establish a length argument for that call. Treating it as an ordinary three-argument copy would add an unsupported contract.

The counter updates occur before the transfer invocation. No transfer result is checked.

### 4. Immediate index insertion

After the transfer dependency returns, the routine shifts index entries toward higher addresses to make room at the requested insertion displacement.

The shift uses the index end and insertion displacement computed before F-48bafd709153 and F-cec90b5dcee3. For each two-byte step, beginning at the old index end:

1. The byte two positions earlier is read and written to the current position.
2. The next source byte is read and written to the next destination position.
3. The working destination moves backward by two bytes.

This backward traversal preserves the ordinary right-shift behavior for overlapping entries. The comparison controlling the traversal is signed.

The routine then writes the low 16 bits of the returned item displacement at the insertion position, high byte first. The address used for the preceding transfer was not limited to those low 16 bits. Correctness of this representation therefore depends on an external constraint on the returned displacement.

It next:

1. Reads the current entry count and writes its high byte to auxiliary-header byte +3.
2. Reads the current entry count again and writes its low byte to auxiliary-header byte +4.
3. Writes 1 to context byte +1.

The index shift and location write are byte-oriented. The context’s 16-bit count and capacity updates use native-width accesses.

### 5. Optional secondary operation

After insertion, the routine reads the address-like field at context offset +64 and checks the byte at offset +22 of the referenced object.

If that byte is zero, the immediate path finishes with return value zero.

If it is nonzero, F-200380a3070f is called with:

- The context address.
- The original, unadjusted data address.
- An address into local scratch storage.

After that call, the routine reads context byte +3. If nonzero, it clears two adjacent 32-bit scratch words that otherwise participate as a low/high pair.

The observed scratch accesses, relative to the address supplied to F-200380a3070f, are:

| Relative offset | Width | Subsequent use |
|---|---:|---|
| +8 | 32 bits | Low word of an accumulated value; optionally cleared. |
| +12 | 32 bits | High word; optionally cleared. |
| +16 | Unsigned 32 bits | Added to the low word. |
| +26 | Unsigned 16 bits | Comparison threshold. |
| +28 | Unsigned 16 bits | Added to the original data address for a later call. |

The routine adds the unsigned word at +16 to the low word at +8 and carries into the high word at +12. It compares the resulting two-word quantity, under the signed subtraction/sign-overflow logic visible in the source, against the zero-extended threshold at +26.

For the ordinary signed two-word interpretation, the secondary operation is selected when the accumulated value is greater than that threshold. Equality does not select it. In particular:

- A zero high word selects the operation only when the resulting low word exceeds the threshold.
- A positive signed high word selects it.
- A negative signed high word does not.

The high-word arithmetic is 32-bit wrapping arithmetic; this is not an unbounded integer calculation.

When selected, the routine calls F-d1e995cfb2d3 with the original data address plus the unsigned 16-bit scratch value at +28. It then calls F-97f36d1a1364 with:

1. The then-current 32-bit field at context offset +64.
2. The result of F-d1e995cfb2d3.
3. The literal value 3.
4. The then-current 32-bit field at context offset +76.

A nonzero result from F-97f36d1a1364 is returned. Otherwise, the function returns zero. The ordering of the reads of the first and fourth arguments relative to one another is not established.

### 6. Deferred path

If the alternate address is nonzero, the external transfer dependency is invoked with:

- Destination-like address: alternate address plus prefix adjustment.
- Source-like address: data address plus prefix adjustment.
- Amount: requested amount minus prefix adjustment.

After that invocation, the alternate address becomes the data address stored in the descriptor. If the alternate address is zero, no transfer occurs and the original data address is retained.

The routine then reads the current unsigned byte at context offset +2 and selects a descriptor at context offset +24 plus eight times that byte. This read occurs after the optional transfer dependency, so a mutation of the counter by that dependency affects descriptor selection.

The subsequent observable writes are:

1. Increment context byte +2, retaining only eight bits.
2. Store the selected data address as 32 bits at the descriptor start.
3. Store the low 16 bits of the supplied index at descriptor offset four.
4. Clear the 16-bit field at context offset +18.

The routine returns zero. It does not locally update the immediate-path entry count, header count, or byte +1 on this path.

## Side effects

The immediate path can modify backing data through the transfer dependency, shift index bytes, insert a location entry, update two context fields and two auxiliary-header bytes, and set context byte +1.

The deferred path can transfer data to caller-supplied storage and writes one inline descriptor, the descriptor counter, and the capacity-like field.

Failure is not transactional:

- Early checked dependencies can have their own side effects before returning an error.
- The secondary-operation error occurs after local insertion state has already been changed.
- No restoration, descriptor removal, count correction, or reverse transfer is visible.

No explicit release operation appears in this routine. Deferred descriptors retain a data address beyond the immediate call, but neither ownership transfer nor the required retention lifetime is established. Unknown dependencies must not be assumed to preserve globals, retain pointers, or release memory.

The byte-at-a-time index and header updates expose intermediate states if another observer can access the same storage. No synchronization is visible.

## Acceptance examples

These are conditional static acceptance criteria, not executed tests. Unless noted, assume valid storage, nonoverflowing address arithmetic, and no unspecified dependency mutations.

1. **Immediate-path capacity boundary.** With context byte +2 equal to zero, requested amount 10, and capacity-like field 12, the immediate path is selected. With capacity 11, the deferred path is selected.

2. **Pending descriptors override apparent space.** With context byte +2 nonzero, the deferred path is selected regardless of otherwise sufficient capacity.

3. **First checked failure.** If F-81c906bf6e3a returns a nonzero status, that status is returned. The routine does not proceed to its own count updates, transfer, or index insertion. Effects inside that dependency remain unspecified.

4. **Conditional preparation failure.** If the space comparison selects F-48bafd709153 and it returns nonzero, that result is returned before F-cec90b5dcee3 is called.

5. **Middle insertion.** Given three two-byte entries and an insertion index of one, the last two entries move one slot higher. The new entry contains the low 16 bits of the returned displacement in big-endian order.

6. **Append.** When the insertion displacement equals the previously computed index end, no existing index entry is shifted. The new two-byte displacement is written at that end.

7. **Deferred retention without transfer.** With alternate address zero, the descriptor stores the original data address and the low 16 bits of the index. No local transfer call precedes those descriptor writes.

8. **Deferred adjusted transfer.** With requested amount 20, prefix adjustment four, and nonzero alternate address, the displayed transfer call receives addresses advanced by four and an amount of 16. The descriptor stores the unadjusted alternate address.

9. **Secondary threshold equality.** If the accumulated two-word value equals the unsigned 16-bit threshold, F-d1e995cfb2d3 and F-97f36d1a1364 are not called.

10. **Late failure preserves completed writes.** If F-97f36d1a1364 returns nonzero, that status is returned after the index insertion, count changes, header writes, and byte +1 update.

11. **Descriptor counter wrap.** A deferred-path counter value of 255 selects the slot for 255, then stores zero in the counter. This describes the arithmetic only; adequate descriptor storage is a separate precondition.
