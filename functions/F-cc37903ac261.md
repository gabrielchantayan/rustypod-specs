# F-cc37903ac261

## Purpose

F-cc37903ac261 is a three-input, event-selected state handler. Its established behavior includes identifier lookup, shared-state resets, linked-list processing, scanning a fixed-stride record region, repeated dependency-driven processing, message submission, and conditional expiration of a pending-state flag.

These descriptions are structural. The meanings of the event values, identifiers, records, messages, and time-like quantities are not established. In particular, the supplied evidence does not establish that list removal frees memory or that a notification successfully reaches an external consumer.

Ordinary completion returns a 32-bit zero. Several paths instead invoke dependencies marked as non-returning. Those paths do not have an established ordinary return value.

## Behavior

### Dispatch and unhandled events

The three global values are read before the event is examined.

Events other than 1, 4, 8, and 32 cause no further explicit work and return zero. There is no default diagnostic or explicit error result.

### Event 1

Selectors 5, 7, and 8 trigger nested local counting loops: three outer iterations, each containing sixteen inner increments. The counters are 8-bit quantities.

No explicit shared-memory write or dependency call occurs in these loops. Other selectors perform no branch-specific work. This establishes neither a calibrated delay nor a guaranteed externally meaningful timing effect.

### Event 4: lookup and conditional reset

The branch performs these actions in order:

1. Calls an unmapped dependency that returns an address-bearing value.
2. Calls F-b37968c9f644 with that value plus four bytes and the selector.
3. Writes the 32-bit lookup result to context +0x2D4.
4. If the result is nonzero, writes the selector to context +0x2D8.
5. Evaluates a fatal-path condition.
6. Only if that condition permits continuation, obtains the state-object pointer from shared-state +0xC, clears its 32-bit field at +0x300, and then clears its byte at +0x304.

The fatal-path condition is equivalent to:

- A zero lookup result always invokes F-a817d8d58c10.
- A nonzero lookup result invokes F-a817d8d58c10 when the selector is signed-greater-than-or-equal-to 3.
- A nonzero lookup result permits continuation when the selector is signed-less-than 3.

This interpretation accounts for the signed-overflow adjustment in the supplied subtraction comparison. It is not merely a test of whether the wrapped subtraction result is nonnegative.

Writes before the fatal-path decision remain part of the observable sequence. A zero result has already been stored at context +0x2D4 before the fatal dependency is invoked. A nonzero result with an unacceptable selector has already updated both context fields.

### Event 8: reset, drain, scan, and retry

The branch begins by calling F-bfade2068003 with arguments 0x2C and zero. It then reads the state-object pointer and clears +0x300 before clearing +0x304.

Next, it calls an unmapped dependency and supplies that result, together with the shared selector read from shared-state +4, to F-23aadb16b673.

#### Head-list processing

While shared-state +8 is nonzero:

1. F-41b5f0f17701 is called with the context as the one explicit argument visible in this call.
2. The head pointer is read again after that call.
3. The first 32-bit word of that newly read head is dereferenced.
4. That word is written to shared-state +8.
5. If the detached pointer is nonzero, F-f67091be6098 is called with no explicit argument visible here, followed by the non-returning F-feee9156a257.

The post-call reread matters. The dependency may change the head before the dereference. There is no null check protecting that dereference; the later nonzero test does not make a null reread safe.

Under the supplied non-return annotation, encountering a nonzero detached pointer prevents subsequent processing in this invocation. The visible loop therefore must not be specified as guaranteed to drain an arbitrary nonempty list.

#### Fixed-stride record scan

If execution reaches the scan, it starts at:

- Initially captured record-region base, plus selector × 0x2100 bytes.

It inspects sixteen 32-bit first words at successive 0x210-byte strides. For each inspected word that is nonzero, it calls F-4047fd399ee0 with the context and selector.

The call receives neither the current record address nor a record ordinal. The record read occurs when its iteration is reached, so dependency mutations may affect later reads.

No selector bounds check or multiplication-overflow rejection is present. Safe operation requires every computed read address to be valid.

#### Selector validation and processing loop

After the scan, context +0x2D8 is compared with the selector. A mismatch invokes F-a817d8d58c10.

On a match, writes occur in this order:

1. Context +0x2D4 becomes zero.
2. Context +0x2D8 becomes 0x7FFFFFFF.

The function then repeatedly calls F-704f99fd5e22 with the context, selector, and two addresses of 32-bit output storage. Before every call, both output words are reset to the initially captured seed. Another nearby word is zeroed, and a local pointer refers to it; no additional formal argument for that pointer is established.

A zero dependency result retries. Any nonzero result ends the loop. There is no retry limit or timeout in the supplied behavior.

Finally, F-85722f62e20a is called with 0x2C and 1000, and the function returns zero.

### Event 32: local object setup

Two local 32-bit output words are initialized to zero. F-7a117b899bf6 is called with a local object address. An indirect operation is then fetched at offset +0xC through that object's first pointer-sized word and invoked with the object address and the two-word output address.

The selector is subsequently compared with shared-state +4. Because the comparison occurs after these calls, the shared selector is not a pre-call snapshot.

### Event 32: selector matches shared selector

This branch filters a linked structure using the two-word output produced above.

For the head:

1. If the head is null, head processing ends.
2. F-927372e9397c is called with temporary output storage, the two-word output address, and head +8.
3. F-6489aed099b0 is called with that temporary and the current head +0x10.
4. Only a result exactly equal to 1 selects head removal.
5. Removal calls F-41b5f0f17701 with the context and the current head.
6. The head is read again, its first word is dereferenced, and shared-state +8 is replaced by that word.
7. A nonzero detached pointer leads to F-f67091be6098 and then non-returning F-feee9156a257.

The head is reread between operations. These are not guaranteed to operate on a stable node if dependencies mutate the list.

The successor pass begins from the then-current head. For each current node having a nonnull successor:

- F-927372e9397c uses successor +8.
- F-6489aed099b0 uses the then-current successor +0x10.
- A zero result retains that successor and advances to it.
- Any nonzero result selects removal.

For successor removal, the successor address is captured and passed with the context to F-41b5f0f17701. After that call, the current node’s successor is reread; that successor’s first word replaces the current node’s link. If the captured removed address is nonzero, F-f67091be6098 receives it, followed by non-returning F-feee9156a257.

The head and successor predicates differ: head removal requires exactly 1; successor removal accepts any nonzero value.

If traversal completes normally, F-f2a8d6327124 is called.

### Event 32: selector differs from shared selector

Context +0x2C8 must equal the selector. Otherwise, F-a817d8d58c10 is invoked.

On a match, processing repeats as follows:

1. Read context +0x2D8 into a local 32-bit selector word.
2. Initialize two local output words from the initially captured seed and another local word to zero.
3. Call F-e08f888de5db with the context and addresses of the selector word and the two output words.
4. End the loop if the result is nonzero.
5. Otherwise, inspect the low 16 bits of the second output word as an unsigned value.
6. Invoke F-a817d8d58c10 if that value exceeds 0x92.
7. Call an unmapped buffer-initialization dependency for a 0x410-byte local region.
8. Set byte 0 to 0x80, byte 8 to 0x0F, and byte 9 to the low eight bits of the saved output word.
9. Call an unmapped dependency with context +0x2E0.
10. Call F-c6c589453fa8 with 0xC, zero, the buffer address, and 0x410.
11. Call another unmapped dependency with context +0x2E0.
12. Repeat.

The buffer initializer’s fill semantics are unknown. Only the three explicitly overwritten bytes have established final values from this function alone.

The range check concerns the low 16 bits, not the entire 32-bit output. For example, 0x00010092 passes that check and contributes byte 0x92 to the message.

#### Conditional counter expiration

After the processing loop exits, the function reads the state-object flag at +0x304. If zero, expiration work is skipped.

Otherwise:

1. F-7a117b899bf6 initializes another local object.
2. Its indirect operation at +0xC produces a two-word output.
3. F-bf18a6a8124b receives that output address and returns a 64-bit quantity.
4. The state-object pointer is reread.
5. Its 32-bit field at +0x300 is read.
6. The low 32 bits of the returned quantity minus that field are computed modulo 2³².
7. If this unsigned difference exceeds 499, the flag byte is cleared first, then the 32-bit field is cleared.
8. F-ec22bd8215d3 is called for the second local object, with an additional visible argument equal to the returned high word minus the unsigned low-word subtraction borrow.

Exactly 499 does not clear the fields. Exactly 500 does. No time unit or maximum meaningful elapsed interval is established.

After either selector branch completes normally, F-ec22bd8215d3 is called for the first local object. No corresponding finalization is established on a non-returning path.

## Side effects

Explicit side effects include:

- Writes to context +0x2D4 and +0x2D8.
- Writes to shared-state +8.
- Writes to the state-object counter and flag.
- Reads from selector-indexed record memory.
- Submission of 0x410-byte buffers.
- Calls surrounding submission through context +0x2E0.
- Calls to indirect object operations and non-returning dependencies.

The ordering of counter and flag clears differs by branch: event 4 and event 8 clear the counter first; expiration clears the flag first.

Ownership is not established. List relinking does not prove deallocation, and the submission dependency’s retention or copying of the stack-backed buffer is unknown. Safe use requires a compatible lifetime contract from that dependency. Atomicity, locking coverage, and reentrancy are also unknown.

## Acceptance examples

These are conditional static acceptance criteria, not executed tests.

- **Unhandled event:** With readable initial globals and event 2, return zero without branch-specific calls or writes.
- **Event-4 continuation:** If lookup returns nonzero and selector is −1, store the result and selector, then clear the state counter followed by its flag.
- **Event-4 rejection:** If lookup returns nonzero and selector is 3, update both context fields before invoking the failure dependency. Do not require the subsequent state clears.
- **Failed lookup:** If lookup returns zero, store zero at context +0x2D4 and invoke the failure dependency without updating context +0x2D8.
- **Event-8 normal completion:** With an empty list, valid record region, matching stored selector, and retry results zero then nonzero, clear the context fields before both retry calls and perform the final 0x2C/1000 call afterward.
- **Distinct list predicates:** A comparison result of 2 does not remove the head, but does select removal when evaluating a successor.
- **Message boundary:** Following a zero processing result, low-16-bit output 0x92 permits submission with byte 9 equal to 0x92. Output 0x93 invokes the failure dependency before buffer initialization.
- **Expiration boundary:** With the flag set, unsigned modular difference 499 preserves the fields; difference 500 clears the flag before the counter.
- **Wraparound:** A returned low word of 3 and stored counter 0xFFFFFFFE yield modular difference 5, so this comparison alone does not expire the state.
