# F-42999360227b

## Purpose

F-42999360227b appends a null-terminated character sequence to another null-terminated character sequence in place. It locates the destination’s first null character, then copies successive source characters to that position, including the source’s terminating null character.

This description establishes the behavior visible in the supplied static source. It does not establish a standard-library identity, a particular character encoding, or safety for arbitrary overlapping regions.

The routine performs no capacity check, reports no status, and does not return a pointer or length.

## Interface

The routine accepts two character pointers, in this order:

1. **Destination:** identifies the first character of the sequence to extend.
2. **Source:** identifies the first character of the sequence to append.

The return type is void. Successful completion produces no return value; the result is the modified destination storage.

Both parameters have mutable character-pointer types. The routine directly writes only through its advancing destination pointer. It reads through its advancing source pointer. Aliasing can nevertheless cause destination writes to modify storage also reachable through the source pointer.

### Representation and widths

The unit of access and advancement is one character-sized storage unit. Each input read and output write operates on one such unit. Pointer advancement moves to the next character, not to the next multibyte character, Unicode scalar value, or encoded text element.

Termination is determined by a character value equal to zero. No encoding interpretation, case conversion, normalization, or multibyte processing occurs.

The supplied source does not establish the number of bits in a character-sized storage unit or the width of a pointer. An eight-bit byte model may describe a particular target, but is not established here. Character signedness is likewise unspecified; the routine performs only copying and comparison with zero.

There is no explicit integer length, capacity, offset, or accumulated count. Consequently, there is no exposed integer-length overflow policy. Validity instead depends on each pointer access and advancement remaining permitted by the execution environment.

### Preconditions for ordinary, defined completion

The caller must provide:

- A destination pointer from which the routine can read through a terminating null character.
- A source pointer supporting every source read actually performed.
- Writable destination storage for every character actually copied, including the terminating null character.
- Valid pointer advancement throughout both traversals.
- Storage whose lifetime covers the operation.

For independent, stable, nonoverlapping sequences, let the initial destination length be \(D\) and the source length be \(S\), each measured in non-null character units. The destination must accommodate \(D + S + 1\) units starting at its supplied pointer. This formula describes a storage requirement; the routine does not calculate or validate it.

The source must remain suitably readable and terminated under the actual effects of aliasing. Initial termination alone does not guarantee completion when writes can overwrite source characters that have not yet been read.

## Behavior

### Destination search

The routine first examines destination characters in increasing address order.

For each character:

- A nonzero value causes traversal to advance by one character.
- A zero value ends the search.

No destination writes occur during this search. No source character is read before the destination terminator is found.

The destination’s terminating character is therefore read before any copying begins. Its position becomes the first output position.

### Append operation

The copy phase always performs at least one source read and one destination write, even when the source is empty.

For each copied character, the established access order is:

1. Read the current source character.
2. Write that value to the current destination position.
3. Advance the source and destination positions by one character.
4. Decide whether to continue using the value already read.

A nonzero copied value causes another iteration. A zero copied value ends the operation.

The stop decision does not reread the just-written destination character or the current source position. Thus, a zero read from the source is written to the destination before completion, and no subsequent source character is read.

Both positions advance after the terminal write as well. Although these final pointer values are not returned or stored externally, their formation remains subject to the environment’s pointer-validity rules.

### Result for independent, stable sequences

When the source and destination regions do not interfere:

- The original destination prefix remains unchanged.
- The source’s non-null characters follow that prefix in their original order.
- The source terminator becomes the new destination terminator.
- The resulting sequence length is \(D + S\).
- Destination storage after the new terminator is not written.

The destination search performs \(D + 1\) character reads. The copy phase performs \(S + 1\) source reads and \(S + 1\) destination writes. These counts include both terminating-character accesses.

An empty destination receives a copy of the source starting at its first position. An empty source still causes a zero character to be written over the existing destination terminator.

### Overlapping regions

The routine provides a forward, character-at-a-time copy. It does not buffer the source sequence or establish an overlap-safe snapshot.

Overlap must therefore be evaluated using the actual read-before-write order. A destination write can change a source character that a later iteration would otherwise read. This includes overwriting the source’s original terminator with a nonzero value.

Some overlapping arrangements are compatible with ordinary completion. For example, copying toward lower addresses from a later source position can leave unread source characters intact. Other arrangements destroy termination or alter the copied sequence.

No blanket overlap guarantee is established. In particular, appending a nonempty sequence to itself does not implement finite sequence duplication under the ordinary stable-memory model: the first output write replaces the original terminator, and subsequent copying can keep overwriting the terminator before it is read.

## Side effects

The routine modifies consecutive destination character positions beginning at the first terminator found during the search. It writes every character read during the copy phase, including the terminating zero if one is reached.

Destination characters before that initial terminator are not directly written. If the source aliases destination storage, source-visible contents can change through these destination writes.

Pointer advancement changes only local traversal state. The routine does not update a caller-owned pointer variable through an additional level of indirection.

No allocation, deallocation, external function call, explicit global access, or input/output operation appears in the supplied body. No ownership transfer is expressed. The caller remains responsible for the supplied storage and its lifetime; the routine does not release it.

There is no explicit error path. Null pointers, inaccessible memory, missing terminators, insufficient capacity, and invalid pointer traversal are not detected or converted into status values. Their exact consequences are not specified by this routine. A particular crash, partial result, or diagnostic must not be assumed.

## Acceptance examples

These examples describe conditional expected behavior, not observed runtime results. Character labels denote nonzero character units; `0` denotes a null character.

### Ordinary append

Given independent source and destination regions:

- Destination initially contains `A B 0`, with capacity for six units.
- Source contains `C D 0`.

Expected destination content is `A B C D 0`. The sixth destination unit remains unchanged. The original destination terminator is read during the search and then overwritten by `C`.

### Empty source

Given destination `A B 0` and an independent source beginning with `0`, the resulting destination sequence remains `A B 0`.

The copy phase still reads the source’s zero and writes zero to the destination terminator. Sequence equality does not imply that no write occurred.

### Empty destination

Given a writable destination beginning with `0` and an independent source `X Y 0`, with sufficient destination capacity, the destination becomes `X Y 0`.

The first destination character is read during the search before being overwritten.

### Exact available capacity

Given destination length two, source length three, and a destination object containing exactly six character units, the append fits: two existing characters, three appended characters, and one terminator.

With only five units, the routine does not reject the request before copying. The required terminal write exceeds that capacity; no defined success or diagnostic follows from the supplied body.

### Source at the destination terminator

If the source pointer identifies the destination’s initial terminator, the copy phase reads zero and writes zero to that same position, then stops. The destination sequence is unchanged, provided the accesses and pointer advancements are valid.

### Nonempty self-append

If both pointers initially identify `A 0`, the first copied `A` overwrites the original terminator. The next source read then encounters that written `A`, not the original zero.

Finite duplication is therefore not an acceptance criterion. Under ordinary finite storage, traversal eventually exceeds the available region rather than reliably producing `A A 0`.
