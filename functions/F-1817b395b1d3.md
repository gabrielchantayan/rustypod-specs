# F-1817b395b1d3

## Purpose

F-1817b395b1d3 submits a sequence of packed 32-bit words to F-80812c986798. Depending on classification of the input, the sequence contains either:

- One word encoding part of the original input.
- One word encoding part of its 32-bit complement.
- An initial word and any necessary continuation words encoding selected windows of one of those representations.

**Established behavior:** classification determines the path; a signed comparison chooses the representation on the multiword path; successive window selections determine payloads and termination.

**Inferred intent:** the words resemble instructions for constructing a constant, with a comparison used to choose a cheaper representation. Neither the instruction-set interpretation nor the meaning of “cheaper” is established.

The contract below describes normal control flow and the arithmetic conditions under which packed words have defined results. It does not assign machine-specific behavior to invalid signed shifts or signed overflow.

## Interface

| Argument | Representation | Contractual role |

Bit positions are numbered from zero, with bit zero the least significant bit.

There is no explicit error result, emitted-word count, or success indicator. The function does not directly dereference the output context. Whether that value denotes memory, a handle, or another kind of object is **documented_only**.

### Arithmetic requirements

Unsigned arithmetic is 32-bit arithmetic modulo \(2^{32}\). Complementation flips all 32 bits. Unsigned right shifts fill with zeros.

Packing uses inclusive bitwise combination: contributions are ORed together, not added. The destination and upper-field arguments are not masked to nominal field widths. Consequently, a shift-valid oversized argument can affect other fields.

The signed shifts require these ranges for defined results under the displayed signed-integer semantics:

| Contribution | Shift distance | Permitted argument range for that shift |
|---|---:|---:|
| Destination contribution present in every word | 12 | 0 through `0x0007ffff` |
| Additional destination contribution in continuations | 16 | 0 through `0x00007fff` |
| Upper-field contribution | 28 | 0 through 7 |
| Window mask, whose unshifted signed value is 255 | Selected even offset | Offsets 0 through 22 |

These are arithmetic limits, not logical field-width guarantees. Negative destination or upper-field arguments do not satisfy the signed-shift requirements.

In particular, upper-field values 8 through 15 are not established as valid merely because they fit four bits. Likewise, window offsets 24 through 30 are below the word width but produce an unrepresentable signed mask.

## Behavior

### Path selection

F-4f304cbf4c44 is called once with the original input. Its result supplies a 32-bit classification.

The classification selects paths as follows:

| Classification bits | Selected path |
|---|---|
| Bit 31 clear and bit 0 set | Multiword |
| Bit 31 set, regardless of bit 0 | Complemented single word |
| Bit 31 clear and bit 0 clear | Original-input single word |

Bits 1 through 30 do not affect this choice. Thus `0x80000001` selects the complemented single-word path, not the multiword path.

The complemented representation is always the exact 32-bit complement of the original input.

### Packed-word layout

For shift-valid arguments, the following contributions describe the word format:

| Bit region or contribution | Meaning |
|---|---|
| Bits 0–7 | Eight-bit payload |
| Bits 8–11 | Four-bit position tag |
| Destination contribution beginning at bit 12 | Present in every word |
| Destination contribution beginning at bit 16 | Present only in continuation words |
| Bits 21–24 | Operation value |
| Bit 25 | Always set |
| Upper-field contribution beginning at bit 28 | Present in every word |

This table identifies where contributions begin; it does not impose masks on destination or upper-field arguments. For example, sufficiently large but shift-valid destination values can overlap the operation or upper region.

The operation values are:

| Path or representation | Initial operation | Continuation operation |
|---|---:|---:|
| Original-input single word | 13 | Not applicable |
| Complemented single word | 15 | Not applicable |
| Multiword, original representation | 13 | 12 |
| Multiword, complemented representation | 15 | 2 |

All these operation values have representable signed results when shifted into their stated positions.

### Original-input single word

The payload is an eight-bit window of the original input. Its logical right-shift distance is the additive inverse of the classification modulo 32. A classification of zero therefore selects the low byte.

The position tag is the four-bit value carried by classification bits 1 through 4.

The function submits one word using operation 13. There are no representation-comparison calls or window-selection calls on this path.

Classification values are not validated against an expected encoding domain. A classification can therefore select a payload window without any local check that this window adequately represents the input.

### Complemented single word

The payload is an eight-bit window of the complemented input. Its logical right-shift distance is the residue of the classification plus 34 modulo 32.

The position tag consists of bits 8 through 11 of a wrapping 32-bit product: the classification advanced by two, multiplied by negative 128. The additions and multiplication in this calculation are unsigned. Overflow wraps; it is not a signed-overflow condition.

The function submits one word using operation 15. Neither the comparison dependency nor the window dependency is called.

### Multiword representation selection

Before the first word is submitted, F-755b51fe8c4a is called:

1. With the original input.
2. With the complemented input.

Its two results are compared as signed 32-bit integers. The complement is selected only when its result is strictly smaller. Equality selects the original representation.

No result is clamped or validated. In particular, negative values participate in signed ordering rather than being treated as errors.

The selected representation becomes the remaining value. F-2eb20ef61e5a is called with that value even if it is zero.

### Window interpretation

Each result from F-2eb20ef61e5a undergoes a signed decrement before conversion to an unsigned 32-bit quantity. The minimum signed 32-bit result cannot be decremented representably; behavior for that case is not established.

For other results, the resulting unsigned quantity determines an even extraction offset:

- Only its low eight bits participate.
- Its least significant bit is discarded.
- The possible offsets are therefore the even numbers from 0 through 254.

A mask with eight consecutive set bits begins at that offset. Its construction uses a signed value of 255, so the offset must be 0 through 22 for a representable signed result. Counts of 32 or greater also violate the shift-count limit.

The selected bits are the intersection of the remaining value and that mask. The payload is those selected bits repositioned into the low byte.

The four-bit position tag is the residue modulo 16 of negative one-half the extraction offset. For example:

| Extraction offset | Position tag |
|---:|---:|
| 0 | 0 |
| 2 | 15 |
| 8 | 12 |
| 22 | 5 |

This tag description is an arithmetic equivalence of the supplied packing expression. The position calculation retains more bits of the adjusted result than extraction does, but its final four-bit restriction discards their influence.

For positive window results 1 through 32, consecutive pairs select the same offset:

- Results 1–2 select offset 0.
- Results 23–24 select offset 22.
- Results 25–32 select offsets 24, 26, 28, and 30, which fail the signed-mask representability requirement.

The function does not enforce that positive range. Other results can revisit an admissible offset after low-byte reduction. For example, result 257 selects offset zero. A result of zero instead leads to offset 254 and does not establish valid mask construction.

### Initial word, continuation, and completion

The initial multiword word uses the selected representation’s initial operation. It does not include the destination contribution beginning at bit 16.

After F-80812c986798 returns, the selected bits are removed from the remaining value. Only then is the remaining value checked for zero.

If it is zero, the function returns. Otherwise, F-2eb20ef61e5a is called again with the updated remaining value. The next word uses the continuation operation and both destination contributions.

Thus the observable dependency order is:

- Classification.
- Two representation comparisons.
- Initial window selection.
- Initial submission.
- Further window selection and submission pairs only while the post-submission remaining value is nonzero.

No remaining-value zero check precedes the initial window selection or initial submission.

When arithmetic is defined, selected bits are a subset of the remaining set bits. Removing them cannot introduce new set bits. If every iteration selects at least one set bit, the sequence contains at most 32 words.

Progress is not enforced. A window can select no set bits while the remaining value is nonzero. The function still submits that word and requests another window afterward. There is no local iteration limit, empty-window rejection, or error branch. The next window result need not equal the previous one because dependency determinism is unknown.

These termination properties apply only to executions whose arithmetic remains defined.

## Acceptance examples

These are conditional static calculations, not executed tests. Unless stated otherwise, dependencies return normally, destination is 3, and the upper field is 6. Those field values satisfy the signed-shift requirements for both initial and continuation words.

### 1. Original-input single word

Input `0x000000ab` and classification zero select the original-input path.

The payload is `0xab`, the position tag is zero, and the operation is 13. Exactly one word, `0x63a030ab`, is submitted after classification. Neither comparison nor window selection occurs.

### 2. Complemented single word

Input `0xffffff54` and classification `0xfffffffe` select the complemented path.

The complement is `0x000000ab`. Both the payload displacement and position tag are zero. The submitted word is `0x63e030ab`.

### 3. Two windows, original representation

Input is `0x00000101`, and classification is 1. The comparison results either tie or favor the original representation.

An initial window result of 1 selects the low set bit and produces `0x63a03001`. After that submission returns, the remaining value becomes `0x00000100`.

A subsequent window result of 9 selects offset 8, with position tag 12. The continuation word is `0x63833c01`.

After the second submission returns, the remaining value becomes zero. There is no third window-selection call.

### 4. Signed comparison selects the complement

Input is `0xffffff00`, and classification is 1. The comparison result for the original is zero; the result for its complement is negative one.

Signed ordering selects the complement, `0x000000ff`. With window result 1, the function submits `0x63e030ff` and completes.

If those comparison results instead tied, the original representation would be selected.

### 5. Zero still produces an initial submission

Input is zero, classification is 1, and the comparison results select the original representation.

With window result 1, the function submits `0x63a03000`. The remaining-value check occurs after the submission returns, so zero does not suppress this word.

### 6. An empty window does not cause an error

Input is `0x00000100`, classification is 1, and the original representation is selected.

An initial window result of 1 selects no set bits. The function nevertheless submits `0x63a03000`; the remaining value stays unchanged.

If the next window result is 9, it submits continuation `0x63833c01` and then completes. If every subsequent result continues selecting an empty window, no local termination guarantee applies.

### 7. Classification sign takes precedence

Classification `0x80000001` selects the complemented single-word path. Neither representation comparison nor window selection occurs.

### 8. Arithmetic limits remain acceptance conditions

A window result of 25 selects offset 24. Its count is below 32, but the signed mask is unrepresentable. No particular output is guaranteed under the displayed source-level semantics.

Likewise, changing the upper field in example 1 from 6 to 14 invalidates the signed upper-field shift. Under an additional unsigned-word or equivalent machine-bit interpretation, the calculated word would be `0xe3a030ab`. That interpretation is not established by the supplied representation.
