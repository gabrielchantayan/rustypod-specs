# F-d82460213e2d

## Purpose

F-d82460213e2d conditionally clears selected fields of a supplied record and, when enabled by a later flag observation, invokes operations obtained from a globally selected dispatch object.

The established behavior consists of three ordered phases:

1. Conditional processing of two leading record fields.
2. Conditional processing of another pair of record fields.
3. Conditional dispatch through two slots of a globally referenced object.

The field clearing and dispatch pattern suggests cleanup or teardown intent. That interpretation is **inferred**, not an established ownership contract. In particular, the supplied evidence does not establish that any call releases memory, destroys the record, or acquires and releases a lock.

A null record argument produces an immediate return.

## Behavior

### Null argument

The argument is checked before any record access.

If it is null, the function returns without reading the global dispatch reference, calling a dependency, or writing record fields.

### First phase: mask 0x00000004

The function reads the flags at offset +20 and tests mask 0x00000004.

If the mask is clear, this phase performs no further record access or write.

If the mask is set, the phase proceeds in this order:

1. Read the field at +0. If it is nonzero, call F-5990a26eaaa3.
2. After that call returns, if one occurred, read the field at +4. If it is nonzero, call F-5990a26eaaa3.
3. Write zero to +4.
4. Write zero to +0.

No explicit arguments are shown for either call to F-5990a26eaaa3. In particular, the evidence does not show either tested field value being passed to the dependency.

The second field test is a fresh read after the first possible call. A dependency-induced change to +4 can therefore change whether the second call occurs.

The writes are ordered: +4 is cleared before +0. Neither field is cleared by this function before the two possible calls have completed. A zero field suppresses its associated call but does not suppress the subsequent writes.

The first phase’s enablement decision is not repeated within the phase. If a dependency changes the flags after the phase has been entered, that change does not cancel the remaining operations of this phase.

### Second phase: mask 0x00000008

After the first phase completes, or is skipped, the function reads the flags at +20 again and tests mask 0x00000008.

This is not a decision based solely on entry-time flags. Changes made by F-5990a26eaaa3 during the first phase can affect it.

If the mask is clear, this phase performs no further record access or write.

If the mask is set:

1. Read the field at +16.
2. If that field is nonzero, call F-5990a26eaaa3.
3. Write zero to +16.
4. Write zero to +12.

The field at +12 is not tested before being cleared. Its value does not independently cause a dependency call.

As in the first phase, no explicit argument is shown for the dependency call. The function does not establish that the dependency acts on the value read from +16.

### Dispatch selection and mask 0x00000001

After both field-processing phases, the function reads the global dispatch reference and retains the resulting dispatch-object address.

This read precedes the final flags test. Consequently, a non-null invocation reaches this global read even when the dispatch-enable flag is clear at that point.

The function then reads the flags at +20 again and tests mask 0x00000001.

If the mask is clear, it returns without accessing a dispatch slot.

If the mask is set, dispatch continues as described below.

### Initial optional dispatch

The function checks the callable slot at byte offset +0x30 of the globally selected dispatch object.

If the slot is null, this initial call is skipped.

If the slot is non-null, the function invokes the target with two arguments:

- The original record address.
- Integer zero.

The supplied representation uses the global reference for this initial slot lookup and invocation rather than expressing them solely through the previously retained address. No dependency call is shown between capture of the address and this initial lookup. Exact load behavior under concurrent or asynchronous global mutation is not established.

The call target is otherwise unidentified. Its return value, if any, is not used.

### Required dispatch

After the optional initial call returns, or is skipped, the function obtains the target at offset +0x18 from the **retained dispatch-object address** and invokes it with the original record address as its sole shown argument.

There is no null check for this slot.

If the initial optional call changes the global dispatch reference, that change does not redirect this +0x18 lookup: the retained address is used. However, changes to the +0x18 slot within that retained object can affect which target is invoked.

### Final optional dispatch

After the +0x18 call returns, the function reads the slot at +0x30 from the retained dispatch object again.

If this newly read slot is null, the function returns.

Otherwise, it invokes that target with:

- Zero as the first argument.
- Integer one as the second argument.

It then returns if the target returns normally.

This final slot read is distinct from the initial +0x30 slot read. The final target need not match the initial target. The slot may become null, become non-null, or change to another target during either preceding indirect call.

The final operation is represented as an indirect call after an unresolved indirect-transfer warning in the supplied evidence. The target selection and shown arguments are supported; exact machine-level return mechanics are not fully established.

### Ownership and lifetime

In particular:

- Nonzero record fields are not proven allocation addresses.

## Acceptance examples

These are conditional acceptance criteria derived from static evidence, not executed tests.

1. **Null input.**  
   A null argument returns with no dependency calls, record accesses, or global dispatch-reference read.

2. **All controlling masks clear.**  
   With a valid record whose relevant flag bits remain clear, the function makes no calls and writes no fields. It still reads the global dispatch reference before the final flag decision. No dispatch-object dereference is required on this path.

3. **First phase enabled, fields already zero.**  
   If mask 0x00000004 is set, +0 and +4 are zero when tested, and later masks remain clear, no helper call occurs. The function nevertheless writes zero to +4 and then +0.

4. **First helper changes the second decision.**  
   If +0 is nonzero, the first helper is called. If that call changes +4 from nonzero to zero, the second helper call is skipped. Conversely, changing +4 from zero to nonzero enables the second helper call.

5. **Earlier helper enables the next phase.**  
   If a first-phase helper sets mask 0x00000008, the subsequent fresh flag read enables the second phase. If +16 is then nonzero, one additional helper call occurs before +16 and +12 are cleared.

6. **The untested field does not trigger a helper.**  
   With the second phase enabled, +16 zero, and +12 nonzero, no helper call occurs in that phase. The writes still clear +16 before +12.

7. **Enabled dispatch with no optional target.**  
   If mask 0x00000001 is set, +0x30 remains null, and +0x18 is callable, only the +0x18 target is invoked. It receives the original record address.

8. **Global replacement does not replace the retained object.**  
   If the initial optional dispatch changes the global reference from one object to another, the required +0x18 call and final +0x30 lookup still use the retained original object, provided that object remains valid.

9. **Final optional target changes.**  
   If the +0x18 target installs a new non-null +0x30 target in the retained object, the final call uses that new target with zero and one. If it clears the slot instead, the final call is skipped.

10. **Null required target.**  
    Enabled dispatch with a null +0x18 slot is not a supported graceful-return case. The function attempts the indirect call without a guard.
