# F-d15c1be26a89

## Purpose

F-d15c1be26a89 conditionally initializes a shared 32-bit cell, invokes an opening dependency, selects two operations using separately read flag bits, invokes a three-argument dependency between those selections, and invokes a closing dependency. On normal completion, it returns a 32-bit zero.

The established contract concerns memory accesses, call order, argument values, and branch selection. The application-level meanings of the shared value, input object, and dependencies are not established.

An important distinction governs initialization: the function first retains an address obtained from a global pointer, then separately evaluates that global pointer to obtain the address used for the zero test. The initialization store and subsequent shared-cell reads use the initially retained address. Without a stability assumption, the address used for the zero test need not equal that retained address.

“Initialization,” “opening,” and “closing” describe positions in the sequence. They do not establish allocation, locking, ownership acquisition, unlocking, or destruction.

### Shared pointer and cell inputs

The function obtains shared state through a global pointer to a 32-bit cell. Its initial access sequence distinguishes two addresses:

- **Retained address:** obtained by the first evaluation of the global pointer and retained for later use.
- **Test address:** obtained by a separate, subsequent evaluation of the same global pointer and dereferenced for the zero test.

These labels identify roles, not a requirement that the addresses differ. If the global pointer remains stable across both evaluations, they designate the same cell. Otherwise, the function can test one cell and subsequently write or read another.

After obtaining the retained address, the function does not redirect its later direct cell accesses by consulting the global pointer again. Changes to the global pointer during dependencies therefore do not redirect those accesses. Changes to the cell at the retained address can affect later reads.

### Preconditions for normal completion

The test address must permit the initial four-byte read. The retained address must permit the later four-byte reads and, when initialization is selected, the four-byte write. These requirements apply even when the two addresses differ.

The first argument must support the field accesses actually reached. The flag field must remain readable at both decision points. The field at offset `0x4C` must be readable if the second decision selects its branch.

No explicit null, bounds, alignment, or address-overflow checks are present. Defined completion requires suitable address calculations and valid memory throughout the reached accesses, including after dependency calls.

### Output

After all reached dependencies return normally, the function returns a 32-bit zero.

No dependency result is forwarded as the function’s return value. There is no visible alternate normal return, explicit error code, or direct object-field output.

## Behavior

### Initial pointer evaluations and zero test

The function first evaluates the global pointer and retains the resulting address.

It then separately evaluates that global pointer and reads the 32-bit cell designated by this second result. This cell value determines whether initialization occurs:

- A nonzero value skips initialization.
- A zero value selects initialization.

There is no intervening dependency call between the two pointer evaluations. Nevertheless, the supplied static body does not justify collapsing them into one evaluation or asserting address equality without a stability assumption. It also does not establish whether a compiled execution performs two distinct physical pointer loads.

The zero test is not necessarily a test of the cell later used by the opening and closing dependencies.

### Conditional initialization

When the cell at the test address contains zero, the function performs these actions in order:

1. Calls F-8157a180d901 with the integer value 8.
2. Retains that dependency’s 32-bit result.
3. Calls F-b00260d1087a with no explicit arguments.
4. Stores the retained result into the 32-bit cell at the retained address.

The destination is determined by the first global-pointer evaluation, not by the evaluation used for the zero test and not by the global pointer’s value after either dependency returns.

There is no second zero test before the store. If a dependency changes the destination cell, the eventual store overwrites that change. If a dependency changes the global pointer, the store still targets the retained address.

A zero result from F-8157a180d901 is stored without visible rejection or retry. The supplied body does not establish the meaning of 8, the result’s ownership, or whether zero denotes failure.

If the initial test is nonzero, neither initialization dependency is called and this function performs no initialization store—even if the cell at the retained address contains zero.

### Opening dependency

After initialization or its omission, the function reads the 32-bit cell at the retained address and passes that value to F-338d16f9ce72.

This is a fresh cell read. It is not a reuse of the value observed at the test address. On the initialization path, it also is not expressed as direct forwarding of the retained initialization result.

No return value from F-338d16f9ce72 is visibly inspected.

### First flag decision

After F-338d16f9ce72 returns, the function reads the unsigned 32-bit flag word at offset `0x50` from the first argument:

- If bit 0 is clear, it calls F-0bcd44f8074e with the original first argument.
- If bit 0 is set, it calls F-44af41b28801 with no explicit arguments.

Exactly one dependency is selected at this stage during normal traversal.

The decision uses the field value read after the opening dependency. It does not use an entry-time flag snapshot. Changes made by earlier dependencies can therefore affect the selection.

### Middle dependency

After the first selected dependency returns, the function calls F-2e33deb5cf86 with the three original argument values in their original order.

The call is unconditional with respect to both flag bits, provided execution reaches this stage. The first selected dependency’s return value does not visibly control it.

Unchanged argument values do not imply unchanged referenced storage. Earlier dependencies may have modified the object or other shared state.

### Second flag decision

After F-2e33deb5cf86 returns, the function reads the unsigned 32-bit flag word at offset `0x50` again:

- If bit 1 is clear, it reads the 32-bit field at offset `0x4C` and calls F-f9bd69deed01 with the original first argument and that field value.
- If bit 1 is set, it calls F-de83fe44e03c with no explicit arguments.

The second decision is independent of the earlier flag snapshot. Changes by the first selected dependency or the middle dependency can affect it.

The offset-`0x4C` field is read only after selecting the clear-bit branch. Its value is not captured at entry or before the middle dependency.

### Closing dependency and return

After the second selected dependency returns, the function reads the cell at the retained address again and supplies its current 32-bit value to F-1333331b2da1.

It then returns zero.

The opening and closing dependencies receive values read from the same retained address, but those values need not be equal. No comparison, restoration, or consistency check is visible.

## Side effects

### Direct memory access order

The function’s direct shared-state and object accesses occur in this order, with dependency calls interposed as described above:

1. Evaluate the global pointer to obtain the retained address.
2. Evaluate that global pointer separately to obtain the test address.
3. Read the 32-bit cell at the test address for the zero test.
4. If that test reads zero, call the two initialization dependencies and then write the retained result to the cell at the retained address.
5. Read the cell at the retained address for F-338d16f9ce72.
6. After that dependency returns, read the flag word for the bit-0 decision.
7. After the first selected dependency and F-2e33deb5cf86 return, read the flag word again for the bit-1 decision.
8. If bit 1 is clear, read the field at offset `0x4C`.
9. After the second selected dependency returns, read the cell at the retained address for F-1333331b2da1.

The conditional initialization store is the only established direct write. This does not restrict writes performed inside dependencies.

No disjointness between the shared cell and object storage is established. Descriptions of logical fields and shared state do not grant an aliasing guarantee.

The retained address remains in use across multiple calls. Dependencies must not invalidate storage required by later accesses if normal completion is expected. The function contains no visible mechanism for revalidating or refreshing that address.

### Errors and interruption

### Concurrency and reentrancy

## Acceptance examples

These are conditional consequences of static evidence, not executed tests. Each assumes valid reached memory accesses and normal dependency returns.

### Stable pointer, existing shared value

If both initial pointer evaluations yield the same address and its cell reads nonzero at the zero test, initialization is skipped.

If dependencies leave that cell unchanged, the opening and closing dependencies receive the same nonzero value.

With flags unchanged between decisions:

| Flag word | First selection | Second selection |
|---|---|---|
| `0x00000000` | F-0bcd44f8074e | F-f9bd69deed01 |
| `0x00000001` | F-44af41b28801 | F-f9bd69deed01 |
| `0x00000002` | F-0bcd44f8074e | F-de83fe44e03c |
| `0x00000003` | F-44af41b28801 | F-de83fe44e03c |

F-2e33deb5cf86 occurs between the selections in every row. Changing only higher flag bits does not change either selection.

### Stable pointer, initialization selected

If both initial pointer evaluations yield the same address and its cell reads zero, F-8157a180d901 is called with 8.

If it returns a 32-bit value R, F-b00260d1087a executes before R is stored. A change that F-b00260d1087a makes to that destination cell is overwritten by R. Without another change before the opening read, F-338d16f9ce72 receives R.

If R is zero, execution still proceeds without a visible retry.

### Different retained and test addresses

If the two pointer evaluations yield different addresses, and the test-address cell reads zero, initialization is selected regardless of the retained-address cell’s existing value. The result is stored at the retained address. The function does not directly store it at the distinct test address.

Conversely, if the test-address cell reads nonzero while the retained-address cell contains zero, initialization is skipped. If that retained cell remains unchanged, the opening dependency receives zero.

These examples are conditional on differing pointer evaluations being possible in the execution environment; the static body alone does not establish that they occur.

### Later pointer change

If an initialization dependency redirects the global pointer, the pending initialization store still targets the retained address. Later direct shared-cell reads also use that retained address.

### Changes between decisions

If bit 0 is clear at the first flag read, F-0bcd44f8074e is selected. If the middle dependency subsequently sets bit 1, the second selection is F-de83fe44e03c.

If bit 1 instead becomes clear before the second read, F-f9bd69deed01 is selected. It receives the offset-`0x4C` field value read after that decision, including any earlier dependency changes.

When bit 1 is set at the second read, this function does not directly read the offset-`0x4C` field.

### Shared-cell change between surrounding calls

If an intervening dependency changes the cell at the retained address after the opening read, the closing dependency receives the later value. No equality with the opening value is required.
