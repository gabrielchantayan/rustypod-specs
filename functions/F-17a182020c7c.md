# F-17a182020c7c

## Purpose

F-17a182020c7c modifies several memory regions, replaces a reached word while retaining its previous value, derives further addresses through multiplication, prepares invocation-associated storage, and dispatches to opaque dependencies.

The visible path does not provide an ordinary return or a success result. Progress depends on each preceding memory access and dependency invocation completing. Nothing establishes validation, transactional behavior, or a conventional ownership protocol.

This contract distinguishes:

- **Established:** behavior directly supported by the supplied static representation.
- **Inferred intent:** a possible interpretation, not an acceptance requirement.
- **documented_only:** behavior that remains unresolved.

All numerical and memory examples are conditional on the applicable arithmetic and memory semantics. No runtime tests have been performed.

### Publication and replacement boundaries

The initial word publication stores the third input at its own address plus `0x54`. The incoming byte is then stored at state-region offset `0x11`. Both stores precede all traversal reads.

At the reached node, the word at offset `0x14` is read before that field is replaced by the fourth input. The multiplication-input read occurs after replacement but uses the saved link as its base. It does not use the newly installed field value.

This distinction preserves the address used for the read, not necessarily the contents found there. If the replacement overlaps the multiplication-input location, the later read is governed by that overlap and the applicable memory semantics.

The third-input word publication occurs four times in total. Its ordering relative to other effects is significant:

| Publication | Required position |
|---|---|
| First | Before the initial state-byte store and traversal. |
| Second | After formation of the first product, before the selected-word read. |
| Third | After formation of the second product, before the first read at second product plus `0x44`. |
| Fourth | After the repeated read described below and its associated byte write, before the byte write through twice the second product. |

The state byte at offset `0x11` is assigned three successive values: the incoming byte, the saved link’s low byte, and the selected word’s low byte. The saved-link byte publication follows the second third-input publication and precedes selection. The selected-word byte publication follows the third third-input publication.

Selection occurs before formation of the second product. Its result is retained in a represented four-byte storage location for subsequent publications and preparation, subject to any actual aliasing with later writes.

### Distributed word reads and byte outputs

Two early reads provide values for later byte outputs. The word at second product plus `0x44` is read first; the word at first input plus `0x74` is read second.

Only after both reads does the state region receive the selected word as a full four-byte value at offset `0x64`. The low byte from the first of those two reads is then stored at state offset `0x09`.

The location at second product plus `0x44` is subsequently read again. This is a distinct read, separated from the first by the state-region publications. Its low byte is stored at second product plus `0x11`. The first result cannot unconditionally substitute for the second.

After the fourth third-input publication, the selected word’s low byte is written at twice the second product plus `0x11`.

Two further word reads occur after that byte output:

1. A word is read at the product of the third input and the second product, plus `0x44`.
2. The destination is read at first input plus `0x14`.

These reads precede the last three external byte writes, whose order is:

| Order | Address | Byte supplied |
|---|---|---|
| First | Selected word plus `0x01` | Low byte of the earlier word read at first input plus `0x74`. |
| Second | Destination plus `0x11` | Low byte of the word read through the third-input/second-product multiplication. |
| Third | Destination plus `0x09` | Low byte of twice the second product. |

The selected word therefore has three distinct roles: a complete word value, a source of truncated byte values, and an address base. The byte publications do not narrow its later address role to eight bits.

## Acceptance examples

### Replacement does not redirect the saved-link read

Assume the reached field initially contains one valid address and the fourth input supplies a different address. If execution reaches the multiplication-input read, its base is the original field value. Reading through the replacement instead would violate the established address relationship.

This example does not require the contents at the original address to remain unchanged: overlap with the replacement write may affect them.

### Full-word and byte publications differ

Assume the selected word is `0x12345678` and all relevant operations are valid. The state word at offset `0x64` receives all 32 bits. Selected-word byte publications supply `0x78`. The later address use is based on the full selected word under the applicable address semantics.

### Repeated reads are independently observable

Assume the two reads at second product plus `0x44` produce low bytes `0x12` and `0x34`, respectively. State offset `0x09` receives `0x12`; second product plus `0x11` receives `0x34`. Reusing the first result for both destinations is not equivalent.

### Overlap can alter the second read

Assume the state word publication overlaps the source of the repeated read. The second read occurs after that publication and the subsequent state-byte publication. Its result must follow the applicable memory semantics for all intervening overlapping writes; the descriptive region names do not imply independence.

### Failure does not imply rollback

Assume the first two stores complete and the first traversal read fails. The two initial publications have already occurred. No rollback is established, and no later output or dependency invocation is required through the visible path.

### Continuation requires dependency return

If F-U1 does not return, the seventh-input zero assignment and F-cdec09f5d432 invocation are not reached through the visible path. If both calls return and intervening operations complete, the terminal sequence is reached instead of an ordinary function result.

### Overflow examples require an arithmetic model

An example requiring signed overflow or an unresolved signed shift has no unconditional numerical-output expectation. A wraparound-based acceptance criterion requires independent evidence that wraparound is the applicable execution model.
