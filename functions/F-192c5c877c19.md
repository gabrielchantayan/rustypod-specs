# F-192c5c877c19

## Purpose

F-192c5c877c19 constructs coordinate-based groups from an ordered collection of fixed-size records, links each group’s members into a circular list, assigns member-to-group back-pointers, and derives group relationships and flags.

Grouping is greedy and input-order-dependent. An input record joins the nearest eligible group examined so far, subject to category equality, strict distance bounds, and conditional compatibility between primary references. If no group qualifies, the function requests group creation.

These structural operations are established by static evidence. The application meanings of coordinates, categories, conversion results, relationships, and flags are unknown. “Primary,” “secondary,” and “representative” identify observed roles, not verified domain semantics.

## Interface

### Arguments and return value

The function receives:

- A context address, accessed through 32-bit fields.
- A signed 32-bit selector.

It returns a signed 32-bit status. The status starts at zero and is replaced by each group-creation result. A nonzero creation result causes immediate return. Completion without such an error returns zero.

There is no explicit argument validation, independent error code, or recovery path.

The observed representation has 32-bit addresses, 32-bit integer fields, and signed 16-bit coordinates. All layout offsets below are byte offsets.

### Context and collection descriptor

| Context offset | Observed role |
|---|---|
| `0x00` | Opaque value captured at entry and passed to group creation |
| `0x04` | Conversion argument selected when the selector is zero |
| `0x0c` | Conversion argument selected when the selector is nonzero |
| `0x70` | Profile-array base address |

The collection descriptor is addressed at context offset `0x30 + 28 × selector`.

| Descriptor offset | Observed role |
|---|---|
| `0x00` | Input record count |
| `0x08` | Input array address |
| `0x0c` | Group count |

The group count is reset to zero before threshold conversion.

Profile selection uses the selector narrowed to signed 16 bits, multiplied by `0x188`. A 32-bit field at offset `0xf0` within that profile participates in threshold derivation. Collection selection does not use this narrowing. Consequently, selectors outside the signed 16-bit range can address a collection and profile through different effective indices.

## Behavior

### Input bounds and threshold

Before calling a dependency, the function captures the opaque context value, input base, profile address, and input end address. The end address is the input base plus `48 × input count`, using the observed 32-bit address arithmetic.

It then resets the selected descriptor’s group count and captures the conversion argument from context offset `0x04` or `0x0c`, according to whether the selector is zero.

F-74efb2674226 receives the selected profile field and the captured conversion argument. Its result is compared as a signed 32-bit value:

- A result below 17 causes the profile field to be read again and interpreted as the signed threshold.
- A result of at least 17 causes F-73d099a86adb to receive 16 and the captured conversion argument. Its signed result becomes the threshold.

The second profile-field read occurs after F-74efb2674226 returns. It is not guaranteed to equal the value passed into that call. The profile address and conversion argument have already been captured.

Threshold derivation occurs even for an empty input range.

### Input traversal and candidate selection

Input traversal advances by `0x30` bytes while the current unsigned address is below the captured unsigned end address. It is an address-bounded traversal, not a separately decremented count.

For each input record, selection starts with no chosen group and a fresh read of a global 32-bit best-distance bound, used as signed.

Groups are examined by increasing array index. The search condition reads the descriptor’s current group count as signed 32-bit, and candidate addressing reads the current group-array base. These descriptor fields are not captured once for the entire grouping phase.

A candidate qualifies only if:

- Its category byte equals the input category byte.
- Its representative-coordinate distance from the input is strictly below the threshold.
- That distance is strictly below the current best-distance bound.
- Any required primary-reference compatibility check succeeds.

Coordinates are sign-extended from 16 bits before subtraction. Their absolute difference is between zero and 65,535 and therefore fits in signed 32 bits.

When the incoming record has no primary reference, candidate-member compatibility is not checked. Otherwise, the candidate’s member list is traversed from its head. Each member with a nonzero primary reference must satisfy a strict threshold comparison between the coordinates of its referenced record and the incoming record’s referenced record. Members with no primary reference impose no constraint. The first distance at or above the threshold rejects the candidate.

This compatibility traversal enters the member body without a null-head check. A candidate reaching this check therefore requires a valid, nonempty circular list.

A qualifying candidate replaces the current selection and supplies the new best-distance bound. Equal distances never replace an existing selection; the first qualifying candidate wins a tie.

A threshold or initial signed best-distance bound of zero or less prevents any candidate from qualifying.

### Group creation

If no candidate qualifies, F-f95622508985 receives:

- The selected collection descriptor address.
- The incoming coordinate, sign-extended to 32 bits.
- The opaque context value captured at entry.
- An output location for a group address.

A nonzero result is returned immediately. This function performs no rollback and neither final pass. The resulting memory state includes all effects of the failed dependency, including any changes it made to previously touched storage.

On success, an unmapped external operation receives the returned group address and length 48. Its semantics are not supplied; clearing or initialization cannot be assumed.

After that operation, direct initialization proceeds in this observable order:

1. The input address is stored as group head, then group tail.
2. The input coordinate’s 16-bit representation is copied into the group representative field.
3. F-74efb2674226 receives a fresh signed-coordinate read and the captured conversion argument.
4. Its 32-bit result is stored at group offset `0x08`, then `0x04`.
5. The input successor is set to the input itself.
6. The input category is read and copied into the group category.

The input coordinate used for creation precedes the external operation; the representative copy and conversion argument are read afterward. The category read follows the conversion call. Unknown dependency effects can therefore affect these values.

This branch does not explicitly initialize either relationship field.

### Appending to an existing group

For a selected group, direct writes occur in this order:

1. The input successor receives the group head.
2. The old tail’s successor receives the input address.
3. The group tail receives the input address.

The append branch does not directly update the representative coordinate, category, or converted-coordinate fields. It performs no averaging or other representative recalculation.

Subsequent searches use the representative currently stored in each candidate. The value originally assigned at creation is not guaranteed to survive intervening dependency calls, because those calls are not established to preserve existing group storage.

### Back-pointer assignment

After input traversal, the function captures the current group-array base and an end address derived from the current group count and the `0x30`-byte group size. These bounds are used for both remaining passes.

The first pass visits groups in array order. A nonzero head starts circular traversal. Every encountered member receives the current group address at input offset `0x08`; traversal stops when the successor returns to the head.

A zero head is skipped by this pass. All visited groups complete this pass before relationship derivation starts.

### Relationship derivation

The second pass visits the same captured group range in array order. For each group, it enters member processing from the head without first checking for zero. Thus, a group skipped for a zero head in the first pass is not safely skipped in this pass.

Each member increments one of two signed 32-bit counters according to whether its flag bit 0 is set or clear.

A secondary reference is cross-group when it is nonzero and the referenced record’s group back-pointer differs from the current group. Relationship selection has this precedence:

- A cross-group secondary reference selects the secondary relationship.
- Otherwise, a nonzero primary reference selects the primary relationship.
- Otherwise, the member causes no relationship write.

A primary reference need not be cross-group.

For the selected relationship, a zero existing value causes adoption of the referenced record’s group back-pointer. For a nonzero existing value, replacement requires a strict comparison:

- Existing distance: current group representative to existing relationship group representative.
- Proposed distance: current member coordinate to selected referenced-record coordinate.

Replacement occurs only when the proposed distance is smaller. Equal distances retain the existing relationship. These different anchors do not establish nearest-group-representative selection.

The resulting address is written back to the selected relationship field even when the existing address is retained.

Every secondary selection then reads the resulting target group’s flag byte, ORs in bit 1, and writes it back. This marks the retained target if replacement did not occur. A secondary selection yielding zero still proceeds to the target flag access; no null-target guard is present.

After member traversal:

- The current group’s entire flag byte is written as zero.
- It is then written as one if at least one set-bit member exists and the clear-bit count is no greater than the set-bit count.
- If both relationship fields are nonzero, the secondary field is cleared through two successive 16-bit zero writes, first at `0x1c`, then at `0x1e`.

The final check reads the secondary relationship, conditionally reads the primary, and reads the secondary again before deciding to clear it.

Incoming bit-1 marks are order-sensitive. A mark written before the target’s own classification reset is erased by that reset; a mark written afterward remains unless another write changes it. Clearing a secondary relationship does not itself undo an earlier target mark.

## Side effects

Direct writes affect the selected group count, input successor links, input back-pointers, group initialization fields, relationship fields, and flag bytes.

Resetting the group count does not directly traverse, clear, or release previously represented groups. No direct allocation or release is visible. Dependencies may allocate, relocate, initialize, modify, retain, or release storage; their ownership contracts are unavailable.

Failure is nontransactional in the specific sense that this function provides no rollback. It does not guarantee preservation of earlier mutations: F-f95622508985 may change earlier links, groups, descriptors, or other storage before returning an error. No final back-pointer or relationship processing follows that error.

Ordinary successful behavior requires:

- Valid readable and writable storage for every accessed field.
- Successful creation to provide usable group storage and descriptor state.
- Valid nonempty circular lists for groups processed by relationship derivation.
- Valid relationship values whenever they are dereferenced.
- Writable, nonzero targets for secondary flag updates.
- Arithmetic and address ranges that support the described traversals.

The function supplies no protection against malformed cycles, invalid pointers, overlapping objects, address wraparound, or concurrent mutation.

## Acceptance examples

These are conditional static acceptance cases, not executed tests. Unless stated otherwise, storage is valid, arithmetic does not wrap, lists terminate, and dependencies leave unrelated state unchanged.

1. **Empty input.** With count zero, no input records are processed. Group-count reset and threshold derivation still occur. If dependencies leave the count zero, both final passes are empty and the result is zero.

2. **Strict boundaries.** With threshold 10 and initial bound 20, an otherwise compatible candidate at distance 9 qualifies; one at distance 10 does not. With initial bound 9, distance 9 also fails.

3. **Stable tie.** Two eligible groups at distance 3 select the first examined group. The second does not strictly improve the best distance.

4. **Reference incompatibility.** With threshold 10, a candidate is rejected if a member’s nonzero primary reference is distance 10 from the incoming primary reference. With no incoming primary reference, this compatibility traversal is omitted.

5. **Append structure.** A circular list A → B → A becomes A → B → C → A after C is appended. The head stays A. The append branch itself does not change the representative fields.

6. **Changed representative.** If an intervening dependency changes an existing group’s representative from 0 to 20, a later input at coordinate 19 is compared against the currently stored 20, yielding distance 1—not against the creation-time value.

7. **Creation failure with dependency mutation.** If creation changes an earlier record’s successor and then returns a nonzero status, this function returns that status without restoring the successor or running either final pass. No stronger final-state guarantee follows.

8. **Secondary precedence.** A member with a primary reference and a cross-group secondary reference contributes to secondary selection only. A secondary reference into the current group does not suppress a nonzero primary reference.

9. **Relationship tie.** If the existing group-to-group distance and proposed member-to-reference distance are both 4, the existing relationship remains. For secondary selection, that retained target still receives bit 1.

10. **Classification tie.** Two set-bit members and two clear-bit members cause the current group’s classification reset to finish at byte value one. No set-bit members causes it to finish at zero.

11. **Mark ordering.** A secondary mark targeting a later group is erased at that group’s classification reset. A mark targeting an already processed group survives that earlier reset.

12. **Both relationships present.** Nonzero primary and secondary relationships at the final check cause two 16-bit writes clearing the secondary field. That clearing does not reverse target flag updates already performed.

Input bounds use 32-bit address arithmetic and unsigned address comparison. Wrapped bounds cannot be interpreted as ordinary count-based iteration. Group-range calculations, selector-derived addresses, and signed counters likewise require appropriate range constraints; the source supplies no validation.

An empty group is tolerated only by the back-pointer pass, not by relationship derivation. A zero back-pointer adopted for a secondary relationship is not safely handled. These are observable missing guards, not established valid-input cases.
