# F-1229e62bf896

## Purpose

F-1229e62bf896 classifies an ordered sequence of up to three descriptors against seven lookup records. Each successfully classified descriptor contributes the flag byte of its first matching record. The function combines those bytes with bitwise OR, then either returns the combined byte or invokes F-2022b0f73f3b and returns `1`.

A descriptor that matches no record contributes failure bit `0x40` and stops further descriptor traversal. Certain accumulated flags also select a diagnostic, even when every visited descriptor matched.

Diagnostic-object labels suggest classification of join-type terms and rejection of unsupported combinations. This is **inferred intent**. The established contract is the lookup behavior, flag accumulation, diagnostic selection, and argument forwarding described below; neither the actual lookup vocabulary nor the complete diagnostic text is supplied.

This contract is based exclusively on static evidence. No runtime tests have been performed.

## Interface

### Inputs

The represented interface has four 32-bit arguments:

| Input | Established role |
|---|---|
| Context | Opaque value forwarded to F-2022b0f73f3b. Not directly dereferenced here. |
| First descriptor | Nullable address of the first descriptor. |
| Second descriptor | Nullable address of the second descriptor. |
| Third descriptor | Nullable address of the third descriptor. |

Descriptor traversal follows argument order and stops at the first null descriptor address. Null is a terminator, not an element to skip.

The original descriptor argument values also serve as diagnostic arguments. A later descriptor address can therefore be forwarded to F-2022b0f73f3b even if traversal never reaches it.

### Descriptor representation

Each visited descriptor exposes two 32-bit words:

| Byte offset | Width | Established use |
|---|---:|---|
| `0` | 32 bits | Opaque first argument to F-abcb7c332db0. |
| `4` | 32 bits | Unsigned encoded value, logically shifted right by one to obtain a comparison parameter. |

The shifted parameter remains 32 bits. It is not narrowed to the width of the table’s eligibility field.

The low bit of the encoded word does not affect this parameter. Encoded values `10` and `11`, for example, both yield parameter `5`.

The first word might represent an address, but F-1229e62bf896 does not itself dereference that value. Its interpretation and any associated accessibility requirements belong to F-abcb7c332db0.

### Lookup representation

A global storage location supplies the lookup-table base. F-1229e62bf896 reads that base once before descriptor traversal, including when the first descriptor is null. Subsequent searches use the captured base rather than reloading the global location.

The lookup contains seven candidate records, indexed `0` through `6`, with a ten-byte stride:

| Record-relative position | Width | Established use |
|---|---:|---|
| Start of record | Address | Second argument to F-abcb7c332db0. |
| Offset `8` | Unsigned 8-bit byte | Eligibility value compared with the shifted descriptor word. |
| Offset `9` | 8-bit byte | Flags incorporated after a successful comparison. |

Candidate starts are therefore at offsets `0`, `10`, `20`, `30`, `40`, `50`, and `60` from the captured base. The last directly readable flag position is offset `69`.

These accesses do not establish a string encoding, terminator, payload length, or independent structure for the beginning of each record.

### Output

The return value is an unsigned eight-bit value:

- Without a diagnostic call, it is the accumulated flag byte.
- After either diagnostic call returns normally, it is `1`.

The returned byte alone does not distinguish success from diagnosis. An ordinary classification can accumulate exactly `0x01` and return `1` without invoking F-2022b0f73f3b.

For the observed accesses to execute validly:

## Behavior

### Traversal and accumulation

The accumulated flag byte starts at zero. Descriptors are considered from first to third, subject to two early termination conditions: a null address or an unmatched descriptor.

Every visited descriptor starts a fresh search at record index `0`. A match for one descriptor does not change where the next descriptor begins searching.

If the first descriptor is null, no descriptor fields or table-record fields are read, and no comparison dependency is called. The table base is nevertheless captured. The zero accumulator does not select a diagnostic, so the return value is zero.

If the second descriptor is null, the third is not traversed. More generally, an address after any traversal terminator is not interpreted as a descriptor by this function.

### Eligibility and comparison

For each candidate record, eligibility compares two numeric values:

- The record’s unsigned byte at offset `8`, widened for comparison.
- The descriptor’s 32-bit second word, interpreted unsigned and logically shifted right by one.

**The relative order of these two reads is not established.** They appear in opposite operands of an equality expression. The contract requires both reads for eligibility evaluation but does not require the record byte to be read before the descriptor word, or vice versa.

Eligibility is evaluated before any corresponding call to F-abcb7c332db0. If the values differ, that candidate causes no dependency call.

If the values are equal, F-abcb7c332db0 receives three arguments:

1. The descriptor’s first 32-bit word.
2. The candidate record’s starting address.
3. The descriptor’s second 32-bit word, read again and logically shifted right by one.

The relative evaluation order of the descriptor reads used to construct these call arguments is also not established. Those argument values are obtained before the dependency executes.

The shifted word is not cached for the entire search, nor is the eligibility value necessarily reused as the call’s third argument. Under stable memory, the repeated reads agree. If descriptor storage changes between accesses, the supplied representation does not justify treating them as one immutable value. In particular, the parameter passed to the dependency need not equal the value that previously passed eligibility.

A zero dependency result establishes a match. Every nonzero result rejects that candidate and continues the search.

Because eligibility uses a full-width comparison against an unsigned byte, a stable shifted parameter greater than `255` cannot be eligible. For a stable unsigned encoded word, all values greater than `511` fall into that case. No truncation to eight bits makes them eligible.

### Selecting and combining a match

The selected record is the first candidate, in ascending index order, that both passes eligibility and produces a zero dependency result. No later candidate is examined for that descriptor.

After F-abcb7c332db0 returns zero, the selected record’s flag byte at offset `9` is read and ORed into the accumulator. This post-call read is established sequencing. The function does not capture the flag before calling the dependency.

Consequently, a dependency modification to the selected flag storage can affect the accumulated result. Preservation of table contents is not established.

Duplicate descriptors and repeated selection of the same record are allowed. Repeatedly ORing the same flag value has no additional effect, although repeated dependency calls and their effects can still occur.

A matched flag containing `0x40`, `0x10`, or both bits of `0x21` does not itself terminate descriptor traversal. These bits are examined for diagnostic selection after traversal ends.

### No matching record

If all seven candidates fail for a visited descriptor, the function ORs `0x40` into the accumulator and immediately ends descriptor traversal.

Earlier accumulated flags are retained. Later descriptor arguments are not dereferenced as descriptors, but their original values remain eligible for forwarding in the diagnostic call.

Each visited descriptor can cause at most seven calls to F-abcb7c332db0. Across three descriptors, the maximum is twenty-one. Eligibility mismatches reduce the number of calls because those candidates do not invoke the dependency.

### Diagnostic selection

After traversal, the first diagnostic category is selected when either condition holds:

- Both bits `0x01` and `0x20` are set in the accumulated byte.
- Bit `0x40` is set.

The first condition requires the complete mask `0x21`; either constituent bit alone is insufficient.

For this category, F-2022b0f73f3b receives seven argument values in this order:

1. Original context.
2. Reference to the first diagnostic object.
3. Original first descriptor address.
4. A static address selected according to whether the original second descriptor address is null.
5. Original second descriptor address.
6. A static address selected according to whether the original third descriptor address is null.
7. Original third descriptor address.

Both selectors use the same pair of static addresses. A non-null descriptor selects one address; a null descriptor selects the immediately following byte address. The contents at these locations are not supplied. They are not established to be particular separators, strings, or empty values.

The first category takes precedence over the second. When neither first-category condition holds, bit `0x10` determines the remaining outcome:

- If clear, the function returns the accumulated byte without calling F-2022b0f73f3b.
- If set, it calls F-2022b0f73f3b with the original context and a reference to the second diagnostic object.

After either diagnostic call returns normally, F-1229e62bf896 returns `1`. No diagnostic return value affects that result.

### Effects through dependencies

Neither dependency is established to preserve globals, descriptor contents, or table contents. Neither is established to be free of allocation, release, address retention, context mutation, external output, or nonlocal control flow.

If a dependency changes the global table-base location, this invocation continues using its previously captured base. Changes to storage reachable through that captured base can affect later eligibility and flag reads.

There is no explicit allocation, release, or ownership transfer in F-1229e62bf896 itself. Forwarding an address does not establish whether a dependency retains it, assumes ownership, or requires it to remain valid after the call. Those requirements remain documented_only.

No synchronization or atomic-access guarantee is established. The observations about repeated reads do not establish defined behavior for unsynchronized concurrent mutation.

## Acceptance examples

These are conditional static acceptance cases, not executed tests. Unless a case states otherwise, storage is stable and readable, dependency preconditions hold, and dependencies return normally. Hypothetical flag values do not assert actual table contents.

1. **Null first descriptor.**  
   With a null first descriptor, the table base is still read, but no record is searched and no comparison occurs. The result is `0`, even if later descriptor arguments are non-null.

2. **Null terminates rather than skips.**  
   If the first descriptor selects flags `0x02` and the second descriptor is null, the result is `0x02`. A non-null third descriptor is not traversed.

3. **Low-bit equivalence.**  
   Stable encoded words `10` and `11` both yield parameter `5`. Matching still depends on eligible records and dependency results.

4. **Full-width eligibility rejection.**  
   A stable encoded word `512` yields `256`. No eligibility byte can equal it, so the descriptor causes no comparison calls. After seven failed candidates, `0x40` is set, traversal stops, the first diagnostic category is invoked, and normal completion returns `1`.

5. **First successful candidate wins.**  
   If two candidates are eligible and would both return zero, only the earlier one is selected. The later candidate contributes no flags and is not compared for that descriptor.

6. **Post-call flag observation.**  
   If an eligible comparison changes its selected record’s flag to `0x02` and then returns zero, the subsequent flag read observes `0x02`, assuming that write is visible and no further change intervenes.

7. **Combined first-category bits.**  
   If matched descriptors contribute `0x01` and `0x20`, the accumulator contains `0x21`. The first diagnostic category is selected, although neither contribution alone requires it.

8. **Second diagnostic category.**  
   An accumulated byte of `0x10` selects the two-argument diagnostic call and then returns `1`.

9. **Diagnostic precedence.**  
   An accumulated byte of `0x31` selects only the first diagnostic category. Bit `0x10` does not cause an additional call.

10. **Matched failure bit does not stop traversal.**  
    If the first descriptor matches a record contributing `0x40`, a non-null second descriptor is still searched. The first diagnostic category is selected after traversal ends.

11. **Unvisited addresses remain diagnostic arguments.**  
    If the first descriptor is unmatched and both later addresses are non-null, neither later descriptor is traversed. Both original addresses are nevertheless forwarded in the first-category call, with the non-null static selector for each.

12. **Ambiguous returned byte.**  
    Accumulating exactly `0x01` returns `1` without a diagnostic. Normal completion after either diagnostic also returns `1`.
