# F-1f5f08393769

## Purpose

F-1f5f08393769 transforms an in-place pair of signed integer coordinates into two integer results:

- A horizontal-state result produced by a fixed sequence of shift-and-add vector updates.
- A signed, table-dependent angular-state result quantized to a multiple of 32.

The established behavior is the arithmetic transformation described below. The first result is not established to be a normalized Euclidean magnitude, and the second is not established to use any particular angular unit because the coefficient table is unavailable.

**Inferred intent:** the transformation resembles a fixed-point vectoring algorithm that derives a scaled magnitude and an angle. The constant used for negative-first-coordinate adjustment is consistent with 180 degrees represented with 16 fractional bits. Neither interpretation substitutes for the table-dependent contract.

## Interface

### Argument and result layout

The function takes one pointer to writable storage containing at least two consecutive signed integer words:

| Byte offset under the 32-bit interpretation | Entry value | Exit value |
|---|---|---|
| 0 | First coordinate | Final horizontal state |
| 4 | Second coordinate | Quantized angular state |

The function returns no explicit value. Its results are the two overwritten words.

The supplied representation uses signed integer operations together with unsigned masking by `0xffffffe0`. The detailed bit-level interpretation in this specification assumes 32-bit integer words. The source representation alone does not independently establish the target ABI; this qualification matters for overflow and right shifts.

### Preconditions

For ordinary, defined execution:

- The argument must permit both initial word reads and both final word writes.
- The two words must remain accessible for the duration of the call.
- The coefficient-table binding must provide a readable initial entry and a readable traversal of 23 subsequent entries.
- The argument and table must meet the implementation’s alignment requirements.
- Intermediate arithmetic must either remain representable or be governed by a separately established target overflow model.
- If exact results depend on right shifts of negative signed values, the target’s signed-right-shift behavior must be known.

No length, null-pointer, alignment, range, or table-validity checks are present.

### Ownership

The function overwrites caller-provided storage. No allocation, deallocation, ownership transfer, or retention of the argument pointer is shown.

The table is read, not explicitly modified. If the caller’s output storage aliases table storage, the final output writes can nevertheless modify that storage through the argument.

## Behavior

### 1. Capture the input

The first coordinate is read first. The second coordinate is read next. Both are captured before any output write.

Subsequent computation uses these captured values; the input words are not reread.

For the following description:

- \(x\) and \(y\) are the original first and second coordinates.
- \(X\) and \(Y\) are their normalized working values.
- \(H\) is the horizontal state.
- \(R\) is the residual state.
- \(A\) is the angular state.

These are explanatory mathematical names, not additional interface fields.

### 2. Normalize according to the first coordinate

If \(x\) is nonnegative:

\[
X=x,\qquad Y=y,\qquad B=0.
\]

If \(x\) is negative:

\[
X=-x,\qquad Y=-y,\qquad B=11{,}796{,}480.
\]

Thus a negative first coordinate causes both coordinates to be negated and selects a nonzero angular adjustment.

The test is strictly negative. An original first coordinate of zero does not trigger normalization, even when the second coordinate is negative.

Negating the most-negative signed 32-bit value is not representable in signed 32-bit arithmetic. Inputs or intermediate values requiring that operation are outside the ordinary representable-arithmetic contract unless target behavior is established.

### 3. Construct the initial vector state

Using the normalized coordinates, the initial states are:

| Condition | Residual state \(R\) | Horizontal state \(H\) |
|---|---|---|
| \(Y \geq 0\) | \(Y-2X\) | \(X+2Y\) |
| \(Y < 0\) | \(Y+2X\) | \(X-2Y\) |

In representable mathematical arithmetic, the horizontal expression is \(X+2|Y|\). That shorthand does not remove the overflow hazards of the actual doubling and addition operations.

These calculations occur before the first table-entry read.

### 4. Initialize the angular state

The initial coefficient is read through a globally supplied table pointer. Call this coefficient \(T_0\).

The initial angular state depends on the normalized second coordinate:

| Condition | Initial angular state |
|---|---|
| \(Y>0\) | \(T_0-B\) |
| \(Y=0\) | \(T_0+B\) |
| \(Y<0\) | \(-T_0+B\) |

The zero case is intentionally distinct from the positive case. When normalization selected the nonzero adjustment, a normalized second coordinate of zero retains a positive adjustment.

The table-pointer binding is fetched again to initialize traversal after the initial coefficient has been read. The function contains no intervening explicit global write or dependency call, but the two pointer fetches are distinct accesses. Without a stable-binding precondition, the initial coefficient and later coefficients need not come from the same table.

### 5. Perform 23 vector updates

There are exactly 23 iterations, indexed \(k=0\) through \(k=22\).

Each iteration advances the table traversal by one word and reads that entry. Under a stable table binding, these are \(T_1\) through \(T_{23}\), in increasing address order. The first coefficient is therefore not reused by the loop.

Let \(S_k(v)\) denote the target’s signed right shift of \(v\) by \(k\) bits. Every iteration uses the states from the beginning of that iteration.

For a negative residual, the next state satisfies:

\[
R_{\text{next}}=R+S_k(H),
\]

\[
H_{\text{next}}=H-S_k(R),
\]

\[
A_{\text{next}}=A-T_{k+1}.
\]

For a zero or positive residual, the next state satisfies:

\[
R_{\text{next}}=R-S_k(H),
\]

\[
H_{\text{next}}=H+S_k(R),
\]

\[
A_{\text{next}}=A+T_{k+1}.
\]

Important behavioral boundaries:

- A residual of exactly zero takes the nonnegative branch.
- The shift count begins at zero, so the first iteration uses unshifted state values.
- The last shift count is 22.
- The horizontal update uses the old residual, not the newly updated residual.
- The residual update uses the old horizontal state.
- A zero residual does not stop iteration.
- There is no convergence-based early exit.
- Every iteration reads its coefficient, even when a shifted vector contribution is zero.

Under an arithmetic-right-shift interpretation, negative values shift with sign extension. In particular, shifting \(-1\) remains \(-1\), rather than becoming zero. Consequently, late iterations can continue changing the horizontal state even when a residual is small. Replacing signed shifts with division truncated toward zero would not preserve this behavior.

Within each iteration, the horizontal shift is formed, the residual sign selects the branch, and the selected table entry is read. The residual state is then updated, followed by the angular state and then the horizontal state. These are internal updates; no caller-output write occurs during the loop.

### 6. Quantize the angular state

After the 23 updates, the function remembers whether the angular state is negative.

It then:

1. Forms its nonnegative magnitude by negation when necessary.
2. Adds unsigned 16.
3. Clears the lowest five bits with a 32-bit mask.
4. Restores the original sign using unsigned negation when necessary.

For values whose signed magnitude is representable and whose rounding does not encounter a range boundary, the numerical result is:

\[
Q(A)=
\begin{cases}
32\left\lfloor\dfrac{A+16}{32}\right\rfloor,& A\geq0,\\[6pt]
-32\left\lfloor\dfrac{-A+16}{32}\right\rfloor,& A<0.
\end{cases}
\]

This rounds to the nearest multiple of 32, with exact halfway cases rounded away from zero. Values from \(-15\) through \(15\) produce zero.

The actual mask-and-sign-restoration stage uses unsigned arithmetic. It is not saturation. Near signed range boundaries, the resulting bit pattern may not represent the mathematically expected signed rounded value.

### 7. Store the results

The function writes:

1. The quantized angular result to the second word.
2. The final horizontal state to the first word.

The final residual is discarded.

The write order is part of the observable behavior. There is no atomic pair replacement. If execution faults during the second write, the angular word may already have been changed.

## Acceptance examples

These examples are conditional on valid storage and representable arithmetic, except where a boundary limitation is explicitly being illustrated. They are static consequences of the supplied body, not runtime test results.

### Zero input remains vector-zero, but need not produce angular zero

For input \((0,0)\):

- The adjustment is zero.
- Initial horizontal and residual states are zero.
- Every iteration takes the nonnegative-residual branch.
- Both vector states remain zero.
- Before quantization, the angular state is \(T_0+\sum_{j=1}^{23}T_j\), assuming a stable table binding.
- The first output is zero.
- The second output is that sum after the specified quantization.

Therefore, angular zero for a zero vector must not be assumed without coefficient evidence.

### An all-zero table isolates the negative-first-coordinate adjustment

If every consumed coefficient is zero and arithmetic remains representable:

- A nonnegative original first coordinate produces angular output zero.
- A negative original first coordinate with normalized \(Y>0\) produces angular output \(-11{,}796{,}480\).
- A negative original first coordinate with normalized \(Y\leq0\) produces angular output \(11{,}796{,}480\).

That adjustment is already divisible by 32, so quantization leaves it unchanged. The first output remains governed by the vector updates.

### Angular rounding boundaries

If the loop finishes with one of these angular states:

| Angular state before quantization | Stored angular value |
|---:|---:|
| 15 | 0 |
| 16 | 32 |
| 47 | 32 |
| 48 | 64 |
| −15 | 0 |
| −16 | −32 |
| −47 | −32 |
| −48 | −64 |

These cases establish sign-symmetric rounding with ties away from zero.

### Zero residual selects a definite direction

If an iteration starts with residual zero, the angular coefficient is added, not subtracted. The next residual is the negative of the shifted horizontal contribution, subject to arithmetic representability.

An implementation that stops at zero residual or chooses the negative branch at zero would not match this contract.

### Minimum signed input is not an ordinary magnitude case

If the first input is the most-negative signed 32-bit value, normalization attempts an unrepresentable negation. This specification does not assign a valid numerical output by assuming wraparound.
