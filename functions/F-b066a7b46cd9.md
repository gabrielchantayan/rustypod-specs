### High-byte extraction and payload state

After the retained unsigned-derived payload is written at 4,096 times the retained product, the associated consumer receives duplicate arguments scaled by 8,388,608 from that same product.

Following that call, the representation extracts the retained product’s high byte using an unsigned 32-bit interpretation. This **original high byte** is the eight-bit slice at bit positions 24 through 31 of the retained product.

Its value is not established as constant. In particular, it is not established to be 0x08.

The later payload is the original high byte shifted right by five. The shift is applied to a nonnegative eight-bit value and produces a value from zero through seven. It selects the original high byte’s top three bits.

Three state roles must remain distinct:

- The original high byte, initially retained without that five-bit shift.
- The shifted payload, first computed for later byte writes and separately retained for reuse.
- A later reassignment replacing the original-high-byte state with the shifted payload.

Before that reassignment, several writes use either a fresh right-shift-by-five computation from the original high byte or the separately retained shifted payload. A later refresh of the separately retained payload again derives it from the original high byte; it does not shift an already shifted value.

Immediately before the byte write associated with the second halfword interaction, the original-high-byte state is reassigned to its right-shift-by-five result. Subsequent writes use that reassigned value directly. They do not apply another five-bit shift.

The representation thus preserves the same shifted payload across these later writes. Neither that payload nor the original high byte is established as a fixed zero.
