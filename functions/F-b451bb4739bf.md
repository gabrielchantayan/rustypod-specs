# F-b451bb4739bf

## Purpose

F-b451bb4739bf conditionally initializes three shared measurement fields, prepares invocation-local configuration storage, and performs an ordered sequence of allocation and construction calls. Mode and repeated reads of one context flag determine configuration selections and which constructions occur.

Established behavior consists of reads, explicit field writes, dependency calls, and retained values reused across calls. Template initialization, object construction, and layout positioning are inferred purposes, not established dependency semantics. In particular, the external transfer dependency has no supplied copying contract.

The function has no explicit result value. Allocation ownership, constructed-object lifetime, and dependency failure behavior are not established.

## Interface

### Inputs

| Input | Representation | Observed use |
|---|---|---|
| Context | 32-bit address-like value | Supplies a flag byte at offset `0x04`, a signed 32-bit dimension at offset `0x08`, and the first argument to two optional lookups. |
| Mode | Signed 32-bit integer | Zero selects one construction branch; every nonzero value selects the other. Exactly one has an additional role in first-table selection. |
| Caller value A | Opaque 32-bit value | Forwarded as the third argument of every construction call. |
| Caller value B | Opaque 32-bit value | Forwarded as the fourth argument of every construction call. |

Only bit zero of the context flag byte affects this function directly. The dimension’s units and application-level range are unknown.

### Shared state

An external value supplies a shared-state base. Relevant fields are:

| Offset | Width | Interpretation |
|---|---:|---|
| `0x3C` | 32 bits | First measurement; also used as an initialization sentinel |
| `0x40` | 32 bits | Second measurement |
| `0x44` | 32 bits | Cached positioning value |

The function first captures the external base, then independently reads that external base again for the sentinel check. All subsequent shared-cache accesses use the initially captured base.

Consequently, the checked sentinel and the subsequently accessed cache can belong to different storage if the two base reads differ. No identity check reconciles them.

Other external values supply lookup keys, a resource selector, source-like addresses for transfer requests, style-table bases, an extension word, an allocation size, and a separate data base.

Completing the described path requires accessible selected context, cache, descriptor, measurement-record, table, and external-data locations. Dependencies must accept the supplied arguments and return normally.

No local null checks, allocation checks, size validation, error result, rollback, or recovery path appear. Requirements imposed by the external transfer and construction dependencies remain **documented_only**.

### Conditional measurement initialization

After capturing the shared base, the function checks offset `0x3C` through an independently reread external base.

A nonzero checked value skips initialization, without validating the captured base’s fields. A zero checked value starts this sequence:

1. F-9d0ecc5f6adf returns a resource-context value.
2. F-ed4b1fd8953e receives Context and the first external lookup key.
3. After that lookup returns, the external resource selector is captured.
4. A 32-bit descriptor address is loaded from lookup-result offset `0x08`.
5. F-5710a8628cba receives the resource context, an **independent reread** of the external selector, and the descriptor’s first 32-bit word.
6. F-59c1430f85c2 receives temporary output storage, the resolution result, the low 16 bits of a 32-bit descriptor word at offset `0x04`, and the byte at descriptor offset `0x0C`.

The selector captured in step 3 is not the selector read used by the first resolution call. The capture precedes the descriptor-address load; the independent selector read occurs afterward when preparing the first resolution call. Relative evaluation order among that call’s argument reads is not otherwise established.

The descriptor-derived arguments to F-59c1430f85c2 are read after F-5710a8628cba returns. Preservation of the descriptor contents across that call is unknown.

The temporary output region has two 32-bit words in the supplied representation. The function consumes its first word, clears bit zero, and treats the resulting 32-bit value as an address. This establishes neither the meaning of the cleared bit nor alignment beyond that bit.

Two signed 16-bit fields at normalized-address offsets `0x52` and `0x54` are sign-extended and added. Their sum is written to offset `0x3C` of the **captured** shared base. Its possible range is `-65536` through `65534`, so this addition fits in signed 32 bits.

The second measurement then proceeds:

- F-ed4b1fd8953e receives Context and the second lookup key.
- A descriptor address is loaded from result offset `0x08`.
- F-5710a8628cba receives the retained resource context, the selector **captured after the first lookup**, and the second descriptor’s first word. It does not reread the external selector for this call.
- F-59c1430f85c2 receives the same temporary output region and corresponding descriptor-derived arguments.
- The first output word is normalized by clearing bit zero. Signed 16-bit fields at offsets `0x52` and `0x54` are summed.
- That sum is written to captured-base offset `0x40`.

The function next writes captured-base offset `0x44`. Under stable-memory conditions, let:

- \(D\) be the context dimension;
- \(H_1\) and \(H_2\) be the two measurement sums;
- \(A_1\) be the first measurement record’s signed field at offset `0x52`.

The mathematical value is:

\[
C=D-\operatorname{trunc}_0\left(\frac{D-(H_1+H_2)-2}{2}\right)-A_1
\]

Signed division truncates toward zero.

This formula is not an atomic snapshot:

- The first measurement is reread from captured-base offset `0x3C`.
- The second measurement is the locally retained sum, not a reread of offset `0x40`.
- The first record’s offset-`0x52` field is read again after the second measurement sequence.
- The dimension is read twice.
- Dependencies may have changed shared fields, Context, or returned records.

The order among independent reads within this expression is not established.

A first measurement of zero does not stop this invocation. Initialization continues, followed by construction. A later invocation initializes only if its own independently based sentinel check observes zero.

### Common spacing and first configuration preparations

After initialization or its omission, the function captures the first measurement from captured-base offset `0x3C` and computes:

\[
G=\operatorname{trunc}_0\left(\frac{D-(H_1+H_2)-2}{2}\right)
\]

Here, \(H_1\) is that captured measurement; \(H_2\) and \(D\) come from current cache and context reads. This calculation occurs on every invocation.

The following transfer requests occur in order:

| Destination region | Count argument | Explicit subsequent writes |
|---|---:|---|
| Primary | `0x68` | Style at `0x48`, then position at `0x3C` |
| Final | `0x68` | Style at `0x48` |
| Conditional | `0x68` | None at this stage |
| Initial | `0x68` | None |

Each request uses its own external source-like value.

After the Primary request returns, the function captures the current first-style-table base. It then reads the context flag and selects index one only when bit zero is set **and** Mode equals one; otherwise it selects index zero.

For the Primary entry read, it independently rereads the external first-style-table base. It reads the selected 32-bit entry through that reread base and writes Primary offset `0x48`. It then writes \(G+H_1\) at Primary offset `0x3C`, using values retained from before the transfer request.

After the Final request returns, the function reads the flag again and applies the same mode condition. Its selected entry is read through the table base captured after the Primary request, not through a new external-base read. It writes that entry at Final offset `0x48`.

Thus, both flag reads and both entry-content reads are distinct. A changed global table base during the Final request does not redirect Final’s read; changed contents at the captured table remain observable.

After the Conditional and Initial requests, the function requests `0x230` bytes from F-8157a180d901 and invokes F-60fe53f7ab39 with the result and Initial. This is the first construction call.

### Branch-layout preparations

Four further transfer requests, each with count `0x68`, occur before the mode branch is selected:

1. **Zero upper:** after its request returns, read captured-cache offset `0x44`, retain that value, and write its negation at configuration offset `0x3C`.
2. **Zero lower:** after its request returns, freshly read captured-cache offset `0x3C`; compute \(L=G+H_1+3\) using retained \(G\) and this fresh measurement; write \(L\) at offset `0x24`.
3. **Nonzero upper:** after its request returns, write the negation of the previously retained positioning value at offset `0x3C`. The cache is not reread for this value.
4. **Nonzero lower:** after its request returns, write retained \(L\) at offset `0x24`.

All four preparations occur in either mode. Intervening dependencies need not preserve globals; the stated retained values are nevertheless reused.

## Side effects

### Direct shared writes

Only the initialization path contains explicit shared-cache writes. They target the initially captured base, in this order:

1. First measurement at `0x3C`.
2. Second measurement at `0x40`.
3. Positioning value at `0x44`.

The independently based sentinel check does not redirect those writes. Later replacement of the external shared-base value also does not redirect subsequent cache accesses.

There is no rollback or completion marker. A nonzero first measurement can be published before the remaining fields are initialized. Dependencies may independently alter these fields.

## Acceptance examples

These are conditional static scenarios, not executed tests.

### Different shared-base observations

Suppose the initially captured base designates storage A and the independently reread base designates storage B.

- If B’s sentinel is zero, initialization writes A’s three fields, regardless of A’s prior sentinel.
- If B’s sentinel is nonzero, initialization is skipped, even if A’s first measurement is zero.
- Later spacing and branch-layout cache reads use A.

### Different selector observations

Suppose the selector capture after the first lookup observes `5`, while the independent read for the first resolution observes `9`.

The first F-5710a8628cba call receives `9`. The second receives retained `5`, even if the external selector changes again. The selector capture precedes the first descriptor-address load.

### Transfer effects remain conditional

If F-unmapped-01 copies exactly the requested bytes, each template request initializes its named destination before the explicit overrides. The Extended prefix request then transfers Primary’s first `0x68` bytes without touching its extension.

Without that copying contract, those contents and preservation claims do not follow. The explicit writes and subsequent calls still occur if the dependency returns normally.

### Cached, unflagged, zero mode

Given a nonzero checked sentinel, mode zero, a flag remaining clear, and normal dependency returns:

- Initialization is skipped.
- Construction order is Initial, Primary, Small, Zero upper, Zero lower, Final.
- Both first-table indices are zero.
- Six allocation/construction pairs occur.
- This function performs no explicit shared-cache writes.

Dependencies may still modify shared state.

### Flag and mode distinctions

With a flag remaining set:

- Mode one selects first-table index one.
- Mode two or any negative mode selects first-table index zero.
- All take the nonzero branch, select second-table index one, and perform Conditional construction.
- Six allocation/construction pairs occur, assuming normal returns.

If the Final transfer changes the first-table global base from table A to table B, Final still reads through the base captured after the Primary transfer. This conclusion requires that captured table to remain accessible, not unchanged.
