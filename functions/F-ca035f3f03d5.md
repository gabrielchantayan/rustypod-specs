# F-ca035f3f03d5

## Purpose

F-ca035f3f03d5 repeatedly performs indirect calls and ordered memory accesses without an explicit normal exit. Its established behavior is low-level state manipulation; the supplied representation does not establish a domain purpose, record schema, or application protocol.

Each iteration obtains several paired results, updates byte-, halfword-, and word-sized locations, encounters a software breakpoint, adjusts a frame-like base, and returns to the beginning if execution continues.

This contract distinguishes:

- **Established static evidence:** access widths, call occurrences, arithmetic expressions, ordering, and target relationships visible in the supplied representation.
- **Inferred intent:** interpretations consistent with those operations but not established by them.
- **Unknowns — documented_only:** dependency contracts, execution-environment behavior, and reconstruction details unavailable from the supplied evidence.

The apparent function boundary, register-derived values, low-address accesses, and persistent frame-base adjustment prevent treating this as an ordinary callable routine with a conventional stack discipline.

## Interface

### Entry state and completion

The apparent interface has no explicit parameters and no return value. Required implicit state includes:

- A control-address value used to determine the first indirect-call target.
- A frame-like base used for relative memory accesses.
- An incoming register-derived base used for a late byte write.
- Two global pointer slots.
- Memory accessible through returned pointers, secondary register outputs, literal-derived addresses, and index-derived addresses.

There is no explicit success result, error result, normal return, or loop-termination condition. An iteration reaches its successor only if all reached dependencies return, all accesses complete, and execution continues past the breakpoint.

Where this contract describes resulting 32-bit bit patterns, it does not imply checked arithmetic, saturation, or a defined language-level overflow guarantee.

## Behavior

### Initial acquisition and narrow record updates

At iteration entry, a retained byte value is set to zero. F-U01 receives two explicit zero arguments. Its target depends on the current control-address state.

A separate zero byte used in later addition is established after F-U01 and before F-U02. F-U02 and F-U03 then execute. Only after F-U03 is the first-record pointer read from its global slot. F-U04 executes before F-U05 supplies the initial pair.

F-U06 receives:

1. The initial pair’s low word.
2. Its high word plus its low word plus the separately established zero byte.

The second argument has a 32-bit destination representation. The expression includes signed arithmetic, so an overflowing case has no established portable signed-arithmetic interpretation.

F-U05 and F-U06 have the same statically determined target despite their different apparent call signatures.

After F-U06, an 8-bit secondary register output is written at `First record + 0x11`. This byte is not established as an ordinary return value.

F-U07 precedes a zero-byte write at `First record + 0x15`. F-U08 then supplies a halfword, which is written at offset `0x0c` from a secondary register-derived base. That base is not established to equal the first record.

The first-record pointer is retained from its earlier read. Intervening calls do not cause a new read of its global slot.

### Working-pair distribution

F-U09 supplies the working pair. Two writes occur before F-U10:

- A zero halfword at `Working high word + 0x2c`.
- A word at `Iteration frame base + 0x26c`, containing the working low word logically shifted right by 26 bits. Its value is therefore between 0 and 63.

After F-U10, a pointer is read at `Iteration frame base + 0x320`. F-U11 and F-U12 execute before a word is written at offset `0x54` from that saved pointer.

This word is the working low word shifted left by two bits as an unsigned 32-bit value. Its original top two bits are discarded. The pointer is not reloaded after F-U11 or F-U12.

F-U13 through F-U17 then execute in order. F-U13 uses the same statically determined target as F-U09.

### Selector acquisition and breakpoint boundary

After F-U17, the selector is read as an unsigned halfword from `0x21c48994`. It is subsequently used directly as a numeric address base; no intervening pointer-table expansion is shown.

F-U18 executes before F-U19. F-U19 receives the word read at `Iteration frame base + 0x280`.

A software breakpoint with immediate value `0x92` follows F-U19. All subsequent behavior is conditional on continuation past that event. The evidence does not establish whether the environment traps, resumes, terminates, or otherwise handles the breakpoint.

After continuation:

- The F-U19 result is shifted left by two bits.
- The fixed derived base is established as `0x21c4`.
- The destination-record pointer is read at `Selector + 0x44`.

The shift uses a signed intermediate in the supplied representation. A portable overflow interpretation is not established.

### Pointer-derived halfword updates

F-U20 executes before F-U21 supplies a word. F-U22 receives that word and the word read at `Selector + 0x04`.

The selector-relative argument read occurs after F-U21. It uses the earlier selector value, not a fresh load from the selector’s original address.

After F-U22, a pointer is read from the second global slot. F-U23 executes before the corresponding halfword store:

- The destination address is the saved global pointer plus the scaled lookup result.
- The stored value is the low 16 bits of that saved pointer itself, not data read through it.

F-U24 then executes. Its target equals F-U17’s target.

A pointer is next read from `Fixed derived base + 0x54`, namely address `0x2218`. F-U25 supplies another pointer, whose offset `0x04` receives halfword `0x21c4`.

F-U26 and F-U27 execute before the pointer saved from `0x2218` is used to read an unsigned halfword at offset `0x34`. That halfword becomes the late index. The pointer at `0x2218` is not reloaded after these calls.

### Final-pair processing and frame movement

F-U28 supplies the final pair.

Its low word is written at `Iteration frame base + 0x258`. A halfword is then read at `Final high word + 0x14` and zero-extended to produce the late value.

The remaining operations retain:

- The final low word shifted left by six bits.
- The final high word multiplied by four.
- The late index multiplied by four.

The frame-like base is reduced by `0xf4`, or 244 bytes. No explicit restoration appears later in the body.

A word containing the final low word is written at:

`0x74 + 4 × Late index`

Because the late index is an unsigned halfword, this address ranges from `0x74` through `0x40070`. This arithmetic range does not establish that any corresponding address is mapped or writable.

The final-word shift and high-word multiplication involve signed intermediates. Their portable overflow behavior remains unresolved.

### Destination updates and loop continuation

F-U29 precedes a word write of the late value at `Destination record + 0x54`. F-U30 precedes a second word write of the same retained value at `Destination record + 0x64`.

These are 32-bit zero-extended halfword values. Neither store rereads the original halfword.

After F-U31, a halfword containing the low 16 bits of the destination-record pointer is written to the address formed from the shifted final low word plus a secondary register output. F-U31 has the same statically determined target as F-U19, but its call site shows no explicit ordinary arguments.

F-U32 and F-U33 precede an 8-bit read at:

`Late index + 4 × Late index`

This is five times the late index, with a maximum numeric address of `0x4fffb`. F-U32 uses the same statically determined target as F-U25.

F-U34 executes between that byte read and its write. The retained byte is written at:

`Late value + Incoming register-derived base + 0x19`

F-U35 precedes a word write of the final high word multiplied by four at `Destination record + 0x44`.

F-U36 then executes. F-U37 receives the word read at:

`4 × Final high word + 0x44`

That argument read occurs after F-U36. It is not inherently a read from the destination-record field just written; equality requires address aliasing.

Before F-U37, the control-address state used for F-U01 is replaced by a fixed encoded value. Consequently, the first iteration’s F-U01 target is entry-state-dependent, while later iterations use the explicitly updated state.

If F-U37 returns and control reaches the back edge, execution repeats without an explicit frame-base restoration or normal return.

## Acceptance examples

These are conditional static consequences, not executed tests. Memory examples assume valid accesses and continuation through preceding operations.

1. **Working-pair extraction.** If the working low word is `0xfc000003`, the frame-relative extraction writes `63`, and the saved-pointer offset-`0x54` write receives `0xf000000c`.

2. **Non-overflowing initial addition.** If the initial low word is `7` and its high word is `9`, F-U06 receives `7` and `16`. F-U05 and F-U06 nevertheless address the same dependency target.

3. **Overflow qualification.** Initial low word `0xffffffff` and high word `2` yield second-argument bit pattern `1` under a 32-bit machine-addition interpretation. This is not an unconditional portable signed-overflow guarantee.

4. **Pointer truncation.** If the saved second global pointer ends in `0x5678`, its indexed halfword store writes `0x5678`, regardless of the pointer’s upper bits.

5. **Late-value widening.** A late halfword of `0xffff` produces word stores of `0x0000ffff` at destination offsets `0x54` and `0x64`.

6. **Index-derived addresses.** Late index `3` selects address `0x80` for the final-low-word store and address `0x0f` for the later byte read.

7. **Retained-byte ordering.** If F-U34 changes the byte’s source location after the read, the subsequent write still uses the already retained byte.

8. **Saved-pointer ordering.** If F-U11 changes the pointer slot at frame offset `0x320`, the later offset-`0x54` write still uses the pointer read before F-U11.

9. **Equal target, different occurrence.** F-U19 and F-U31 reach the same statically determined target. Only F-U19 visibly receives the frame-relative word and has its ordinary result consumed for scaling; no equivalent explicit interface is established for F-U31.

10. **Breakpoint interruption.** If execution does not resume from the breakpoint, no subsequent call or store in that iteration is reached. Earlier stores have no explicit rollback.

11. **Back-edge behavior.** Reaching the loop back edge starts another iteration with no explicit restoration of the frame-like base and with the updated control-address state.
