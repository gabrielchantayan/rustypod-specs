### Dependency-mediated value production

The first target is selected from incoming control state with a displacement of 0xFFE. Later targets are predominantly selected from embedded location references with that displacement. No private code addresses are needed to identify the dependency roles in this contract.

Calls display between zero and four explicit arguments. Argument construction includes:

- Scaling primary results by powers of two.
- Forwarding high words separately from transformed low words.
- Transforming secondary machine results whose complete return signatures are unavailable.
- Supplying a retained value in multiple argument positions.
- Supplying explicit zeros alongside independently derived values.
- Reusing results after intervening calls.

Field selections range from a single-bit selection to low-24-bit selections. These selections apply locally; they do not establish a common encoded-input format.

Left-shift counts range from 1 through 31. Some transformations combine multiple shifts or combine a mask with shifts. Intermediate width is significant: bits discarded from a 32-bit value do not reappear in a later right shift. Under 32-bit bit-vector semantics, sufficiently large cumulative left shifts eliminate the original contribution entirely.

Several chains explicitly begin at zero and continue to supply zero-valued arguments. The calls still occur.

For signed operands, exact overflow and shift behavior is **documented_only**. This contract does not universally replace those operations with either unlimited mathematical arithmetic or modulo-2³² arithmetic.

Another initial destination is based on the final low word scaled by 256. It receives a retained address-scale value derived from an earlier primary result.

These are address relationships, not ownership relationships. Nothing establishes that the affected regions are separate.

A small computed base comes from a retained result scaled by 256, restricted to 15 bits, shifted right by six, and doubled. Conditional on the preceding signed scaling having the represented 32-bit bit pattern, the intermediate restricted quantity is a multiple of four between 0 and 508; the doubled base is a multiple of eight between 0 and 1016.

The initial mutation has three important observation constraints:

- A zero word is written before a later read of that word location.
- Between those operations, accesses to other computed locations can overlap it.

Consequently, the later word read cannot be specified as returning zero regardless of aliasing. That read supplies an address-bearing value used subsequently. The small-base region also receives duplicate byte stores at offset 0x15; those are separate displayed accesses.

## Acceptance examples

These are conditional static criteria, not executed tests.

### Width preservation

If an unsigned byte load yields 0xE1, a subsequent zero-extended word store of that retained byte supplies 0x000000E1. Sign-extension to 0xFFFFFFE1 would violate the displayed widening.

If a byte store receives 0x12345678, its contribution is 0x78. Adjacent bytes are not written by that byte operation.

### Paired-result separation

If a paired result has high word 0x89ABCDEF and low word 0x12345678, unsigned extraction of the high word gives 0x89ABCDEF.

Where the low word is transformed by a 32-bit left shift of eight, the resulting bit pattern is 0x34567800, conditional on the signed operation, if any, having that defined target result. That transformation does not alter an independently retained high word.

### Intermediate truncation

For an unsigned 32-bit value 0x80000001, left shift by eight followed by logical right shift by eight yields 0x00000001. Restoring the original value would incorrectly recover discarded bits.

### Aliasing-sensitive readback

If a computed write overlaps the initially zeroed word before its readback, the read uses the resulting memory under the runtime’s access semantics. An implementation must not substitute unconditional zero.

### Ordered intermediate values

Where write observations are supported, the offset-0x20 word destination exposes the sequence 0x20, 0x2F, widened-byte value, and 0x20. A single final write does not satisfy that criterion.

### Retained global base

If the store at 0x00000060 overlaps the global address-bearing word, repeated updates still use the value retained by the preceding global read. They do not automatically use the newly stored 0x20.

### Same-region word copy

If the working region’s offset-0x40 word yields 0x11223344, the later word copy supplies that value at offset 0x10 of that same region. The intervening earlier byte write at offset 0x10 does not replace the copy’s source.

### Terminal argument retention

If the saved offset-0x14 word is subsequently overwritten in memory, the terminal third argument remains the saved word. A fresh read is not equivalent.

### Interrupted execution

If an earlier dependency does not return, later direct writes and the terminal call are not guaranteed. No local recovery path is visible.
