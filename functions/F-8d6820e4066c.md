# F-8d6820e4066c

## Purpose

F-8d6820e4066c performs an ordered prefix of indirect calls, four-byte stores, unsigned byte reads, and one-byte stores, then enters an unconditional repeating phase containing additional calls and byte writes.

**Established static evidence:** the represented control flow contains no normal return. Memory effects occur without visible validation of arguments, addresses, or dependency results. The repeating phase has no exit condition, although faults or dependency behavior can prevent further execution.

**Inferred intent:** scaling, bit extraction, and byte-selected destinations suggest manipulation of externally meaningful state. No particular protocol, device, data structure, registration operation, or application-level purpose is established.

**Evidence boundary:** the supplied representation reports problematic instruction data and excluded unreachable regions. This contract describes the visible represented path, not independently verified executable behavior.

## Interface

The explicit interface consists of four arguments and no returned value:

|---|---|---|
| A | Signed 32-bit integer | Four-byte store value, address arithmetic, and an argument to the first dependency |
| B | Opaque 32-bit value | No explicit use |

There is also an implicit entry-state input: the first indirect target depends on the incoming link-register value, with an added offset of decimal 3816. The four explicit arguments do not determine that target.

The declared interface returns no value, and the represented body never reaches a normal return. This does not establish that execution always continues indefinitely: a dependency may not return, or an access may fault.

### Width and arithmetic conventions

A byte is eight bits. Each four-byte store writes a 32-bit value; each byte read is unsigned and therefore yields a value from 0 through 255. Each byte store retains only the low eight bits of its value.

Unsigned right shifts insert zeros. Mask descriptions refer to 32-bit bit patterns.

Where examples or equivalent formulas use a **32-bit wrapping interpretation**, multiplication and left shifts retain the low 32 bits, and address additions are interpreted at that width. This is a conditional machine-level interpretation, not a claim that overflowing signed arithmetic or signed left shifts have defined portable semantics.

Several dependency results are represented as signed integers before scaling. Consequently, formulas such as “four times the result” describe the represented arithmetic, subject to the signed-overflow and shift uncertainties identified below. Native byte order, pointer representation, and alignment requirements are not independently established.

### Preconditions

For any operation to complete, its computed memory location must support the indicated access, and every reached indirect target must support the actual call. No visible check enforces these conditions.

The evidence establishes neither allocated-object bounds nor conventional pointer roles for A, D, or dependency results. Some byte stores target numerical addresses between 17 and 272. Their validity depends on the execution environment.

Each iteration begins with F-U065, which receives two visible arguments:

| Iteration | First argument | Second argument |
|---|---|---|

The Repeated lookup address remains based on R8 throughout the loop. Loop results do not replace it. Its contents are nevertheless reread on every iteration and may change because of dependencies, aliasing writes, or external effects.

## Acceptance examples

These are conditional static acceptance examples, not executed tests. They assume required accesses succeed, reached dependencies return, and arithmetic has the interpretation stated for each example.

1. **First memory effect precedes the first call.**  
   If A is 3, the first explicit store writes the four-byte value 3 at decimal address 32. F-U001 subsequently receives 3.

2. **The R4-derived location receives two different values.**  
   If R4 is 2, the first store at decimal address 52 writes 8. After F-U029 through F-U033, another four-byte store there writes 32. Observers within the intervening dependencies may distinguish these states.

3. **Unsigned lookup bytes do not wrap the destination addition.**  
   If a lookup reads 255, its selected destination is decimal 272, not 16. The store width is one byte, but the destination calculation is not an eight-bit addition.

4. **Bit extraction is followed by byte truncation.**  
   If R6 has pattern 0x3FF00000, clearing its top two bits and shifting right by 20 gives 0x3FF. The corresponding byte-selected store writes 0xFF.

5. **D-derived write precedes the following clear.**  
   If D is 128, its byte-store destination is decimal 29. If the subsequent fresh lookup selects 29, the later zero store overwrites that byte, absent intervening external effects.

6. **Lookup destinations are independently selected.**  
   If one read at Lookup base + 1 returns 4 and a later read returns 9, the corresponding destinations are 21 and 26. Reusing the first destination would not match the represented behavior.

7. **Initial loop carry is unscaled; subsequent carry is scaled.**  
   If F-U064 returns 7, the first F-U065 receives first argument 7 and second argument zero. If F-U074 then returns 1, under the 32-bit interpretation the next F-U065 receives first argument 4 and second argument 0x00040000. The latter follows from Selector 0x04000000 shifted right by eight.

8. **Subsequent scaling retains only 32 bits under the wrapping interpretation.**  
   If a raw F-U074 result has pattern 0x40000001, its next scaled first argument is 4 and its next Selector is 0x04000000. This example is conditional on machine wrapping; it does not resolve signed-shift semantics independently.

9. **B has no explicit dataflow use.**  
   Changing B alone changes no explicitly represented address formula, store value, or visible call operand. This does not prove that unresolved dependencies cannot observe argument-register or other hidden state associated with B.
