# F-04d7b0f7c6e9

## Purpose

F-04d7b0f7c6e9 conditionally inspects memory and replaces a caller-provided cursor. Normal completion returns a four-byte indicator: exactly 1 after cursor writeback, otherwise exactly 0.

Under a conversion model in which pointer value 2 converts to a signed integer greater than 1, the function behaves as a gated two-zero-byte recognizer:

- A second argument whose signed conversion is at most 1 causes rejection without argument-based memory access.
- Otherwise, the function loads the cursor, checks for two consecutive zero bytes, and advances the stored cursor by two bytes only when both checks succeed.

That summary is conditional. The function initially compares the second argument with pointer value 2. When the signed comparison does not select the cursor-loading path, that equality result remains effective. If pointer value 2 converts to a signed integer at most 1, the function can instead inspect only the byte one position beyond the original second argument and write an address derived from that argument.

Consumption of a two-zero-byte marker is plausible intent for the cursor-loaded path. No application format, encoding, or parser role is established.

### Widths and representation

The cursor slot is read as a four-byte value and its contents interpreted as a character pointer. Successful writeback stores the replacement pointer through the same four-byte slot. These operations support a 32-bit address representation for the represented program, but do not independently establish a complete ABI.

The second argument undergoes an explicitly signed integer comparison after conversion. The supplied representation does not independently specify the signed integer width or pointer-to-integer conversion rules. Pointer equality must therefore remain distinct from equality of converted integers. In particular, pointer value 2 must not be assumed to convert to integer 2 without an additional execution-model assumption.

Inspection and advancement use character-sized byte units:

- The first inspected position on the cursor-loaded path is the loaded candidate address.
- The next inspected position is one byte beyond the active candidate.
- The successful replacement cursor is two bytes beyond that candidate.

Each inspection compares one character-sized element with zero. Character signedness does not affect this comparison. The number of bits per byte is not independently established.

The second argument is not a byte count, remaining capacity, or advancement distance. A large converted value does not establish that any candidate storage is readable.

## Behavior

### Path selection

Before explicit argument-based memory access, the function compares the second argument with pointer value 2 and tests whether its signed conversion is greater than 1.

The pointer-equality result is provisional:

- A signed conversion greater than 1 selects the cursor-loaded path and replaces the provisional result with the first-byte zero comparison.
- A signed conversion at most 1 leaves the initial pointer-equality result effective.

This distinction determines both which address is inspected and whether the cursor slot is read.

### Cursor-loaded recognition

When the second argument converts to a signed integer greater than 1, the function reads the four-byte cursor slot and uses that loaded value as the candidate address.

The first candidate byte is read before any next-byte inspection. If it is nonzero, the function returns 0 without reading the next byte or writing the slot.

If the first byte is zero, the function reads the byte one position beyond the loaded candidate. A nonzero second byte causes return 0 without writeback. Two zero bytes cause the function to write the loaded candidate plus two bytes into the cursor slot and then return 1.

The loaded candidate supplies both inspection addresses and the replacement cursor. There is no explicit reload of the slot between its initial read and successful writeback.

The original second argument is not dereferenced on this path. Even when it equals pointer value 2, its initial equality does not bypass either required byte check.

### Retained-equality behavior

When the second argument converts to a signed integer at most 1, the cursor slot is not loaded.

If the original second argument is unequal to pointer value 2, the function returns 0 without explicit argument-based memory access.

If it equals pointer value 2, the function uses the original second argument as the active candidate. It reads only the byte one position beyond that candidate:

- A nonzero inspected byte causes return 0 without cursor writeback.
- A zero inspected byte causes the original second argument plus two bytes to be written into the cursor slot, followed by return 1.

This path does not inspect the byte at the original second argument and does not read the previous cursor value. Success therefore does not establish a two-zero-byte sequence.

Reachability requires a conversion model in which pointer value 2 converts to a signed integer at most 1. The supplied evidence does not establish whether the actual target has such a model.

### Conditional ordinary-model simplification

If pointer value 2 converts to a signed integer greater than 1, a second argument equal to that pointer necessarily selects cursor-loaded recognition. Under that assumption, every second argument whose conversion is at most 1 is unequal to pointer value 2 and rejects without explicit argument-based memory access.

Only with that assumption can the entire function be summarized as a signed-gated, two-zero-byte cursor consumer.

### Recognition extent and repeated calls

Cursor-loaded recognition inspects at most two candidate bytes. It does not search, consume a longer zero run, inspect a third byte, or return the replacement address directly.

Each successful call advances its active candidate by exactly two bytes. Multiple successes require the bytes inspected by each call to be zero when read. Initial zeros alone do not guarantee this across calls: writeback can modify later candidate bytes if the cursor slot overlaps candidate storage.

In particular, four initially readable zero bytes are sufficient for two cursor-loaded successes only with additional preservation conditions. Disjointness between the four-byte slot and that four-byte candidate region, together with no intervening modification and valid reached accesses, is one sufficient condition.

### Rejections and abnormal completion

Every ordinary rejection returns 0 and performs no explicit cursor-slot write.

Invalid pointer conversion, invalid address formation, inaccessible storage, and failed writeback have no established ordinary result. They must not be treated as guaranteed rejection.

If recognition succeeds but writeback fails, normal completion and transactional rollback are not established. Fault delivery and possible partial-store effects depend on the execution environment.

## Side effects

The sole explicit write is replacement of the four-byte cursor slot on success.

No non-aliasing restriction is expressed. The slot may overlap inspected memory if the execution model permits all reached accesses. All recognition reads for a call precede its writeback, so that write cannot change the comparisons already completed in the same call. It can, however, change data inspected by a subsequent call.

The current call’s replacement address remains derived from its active candidate, even if writeback overwrites memory containing part of that address’s stored representation.

No synchronization or atomicity mechanism is shown. Concurrent mutation, inter-thread visibility, and indivisibility of four-byte accesses are not established.

**Expected:** Load the cursor slot and perform cursor-loaded recognition. Two zero candidate bytes produce writeback of the loaded candidate plus two and return 1. A nonzero first candidate byte produces return 0 without the second-byte read.

**Expected:** Read the slot and first byte, return 0, and perform no explicit next-byte read or cursor write.

**Expected:** Attempt the next-byte read. Neither normal rejection nor successful completion is guaranteed.

### No partial advancement

**Expected:** Inspect the first two bytes, write the loaded candidate plus two, and return 1. Do not advance by 100 or inspect the third byte.

### Two successes with preserved candidate bytes

**Given:** Both calls select cursor-loaded recognition. The initial candidate identifies four readable zero bytes. The four-byte cursor slot is disjoint from those four bytes, remains readable and writable, and neither those bytes nor the slot are otherwise modified between calls.

**Expected:** The first call returns 1 and advances the stored cursor by two bytes. The second call reads that updated cursor, returns 1, and advances it by another two bytes.

**Limit:** This conclusion does not follow from four initial zero bytes alone when the slot overlaps them.

### Overlap can prevent the second success

**Given:** Assume a 32-bit little-endian address representation, eight-bit bytes, and permitted unaligned slot accesses. The candidate address is 0x10000. The four-byte cursor slot starts at 0x10002 and initially contains address 0x10000. The bytes at 0x10000 and 0x10001 are zero. Both calls select cursor-loaded recognition, and all reached accesses are valid.

**Initial state:** The stored address occupies bytes 00, 00, 01, 00 beginning at 0x10002. Thus the four candidate bytes from 0x10000 through 0x10003 are all initially zero.

**First call:** It reads zero at 0x10000 and 0x10001, writes address 0x10002 into the slot, and returns 1. The slot now begins with bytes 02, 00.

**Second call:** It loads candidate address 0x10002 and reads the nonzero byte 02 there. It returns 0 without reading 0x10003 or writing the slot.

This is a conditional aliasing example, not an assertion about the actual target’s byte order or alignment rules.

**Expected:** Read that one byte, write the original second argument plus two into the slot, and return 1. Do not read the previous cursor or the byte at the original second argument. The uninspected byte’s value does not affect the result.
