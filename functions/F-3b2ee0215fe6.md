# F-3b2ee0215fe6

## Purpose

F-3b2ee0215fe6 is represented as a nonterminating sequence of indirect calls interleaved with byte writes to selector-derived addresses. It accepts one explicit integer input and also depends on incoming machine state that is not represented by the explicit parameter.

The visible behavior has two phases:

- A one-time initialization phase that performs a byte write and two calls.
- A repeating phase that performs ten calls and one byte write per iteration, carrying selected call results into subsequent arguments.

No normal return, success result, error result, or explicit loop exit appears in the supplied representation. Completion of any particular call is not guaranteed.

This is a source-facing behavioral contract for the supplied static representation, not a claim that the original executable reliably follows that representation. The supplied material reports unreliable instruction recovery and omitted regions. Those limitations materially constrain the strength of the contract.

## Behavior

### Ordering conventions

The order below is the order established by the supplied representation, assuming that execution reaches each operation and that preceding dependencies return normally.

Each “selector-derived write” means:

- Read the current unsigned selector byte at selector base plus one.
- Add 17 to that byte’s numerical value.
- Write exactly one byte at the resulting destination.

The selector read occurs anew for every such write. Its value is not visibly cached across calls or iterations. A dependency can therefore affect a later destination by modifying selector memory. A write can also affect a later selector read if the addresses alias.

Call result names used below describe values in this contract, not identifiers from the supplied material.

### One-time initialization

Initialization performs these operations in order:

1. Perform a selector-derived write using the low eight bits of the incoming write word.
2. Call F-D01 with the explicit input shifted left by one.
3. Call F-D02 with no explicit arguments shown.
4. Retain the result of F-D02 as the carried value for the first iteration.

F-D01’s return value is not visibly consumed. Its execution is nevertheless observable, and its memory or other side effects must not be discarded.

The first call target is computed from the incoming dispatch base. The remaining call targets are represented as fixed address-derived targets, with the first call of the repeating phase changing target after the first iteration.

### First iteration

The first iteration proceeds as follows:

1. Call F-D03 with two explicit arguments:
   - The result retained from F-D02.
   - The original explicit input logically shifted right by eight.
2. Call F-D04 with no explicit arguments shown.
3. Call F-D05 with no explicit arguments shown.
4. Call F-D06 with no explicit arguments shown.
5. Call F-D07 with no explicit arguments shown and retain its result.
6. Perform a selector-derived write using bits 22 through 29 of the incoming write word.
7. Call F-D08 with the retained F-D07 result shifted left by two.
8. Call F-D09 with no explicit arguments shown.
9. Call F-D10 with no explicit arguments shown.
10. Call F-D11 with no explicit arguments shown.
11. Call F-D12 with no explicit arguments shown and retain its result.

The loop then establishes the state for the next iteration:

- The next carried value is the F-D12 result shifted left by two.
- The next input word is the F-D12 result shifted left by 26.
- The visible local write word becomes zero.
- The next iteration uses F-D13 instead of F-D03 for its first call.

These state transitions follow F-D12. They do not precede any call or write in the current iteration.

### Subsequent iterations

Every later iteration uses the same order as the first, with these changes:

- Its first call is to F-D13.
- Its first argument is the preceding iteration’s F-D12 result shifted left by two.
- Its second argument is the current input word logically shifted right by eight.
- Its selector-derived write stores zero, because the visible local write word was set to zero at the end of the first iteration and is set to zero again at every loop end.

Each iteration again calls F-D07 to obtain the value used for F-D08’s argument. Each iteration again calls F-D12 to generate the next carried value and next input word.

Under 32-bit bit-vector shift semantics, if the preceding F-D12 result is represented by word \(R\), the next iteration’s second argument is:

\[
(R \mathbin{\&} 63) \times 262144
\]

Thus it is one of 64 possible values, from zero through 16,515,072, in increments of 262,144. This simplification is conditional on the shift interpretation; it is not independent evidence about the original machine instructions.
