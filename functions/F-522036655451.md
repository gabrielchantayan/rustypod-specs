# F-522036655451

## Purpose

F-522036655451 writes a caller-supplied word into an object, examines a nested word, and selects between two paths:

- If the nested word’s low bit is clear, return that word unchanged.
- If its low bit is set, invoke diagnostic dependencies and, if execution continues, search tagged descriptors. The first matching descriptor triggers construction and publication of a table of relocated 32-bit values.

The accesses, comparisons, argument widths, and ordering below are established by the supplied static representation. “Acquisition,” “descriptor,” “positioning,” “allocation,” and “cleanup” describe inferred roles, not independently established dependency contracts.

Zero is not an unambiguous indication of table construction. It can be returned directly from the nested-word check or after table publication. Exhausting the descriptor search returns one. Several other paths return a dependency result or a writable status word.

### Directly accessed object layout

| Location | Access |
|---|---|
| Object + `0x58` | Write a 32-bit word. |
| Object + `0x9c` | Read a 32-bit address. |
| That address + `0x04` | Read a 32-bit nested word. |

The nested word is used as a pointer-shaped return value, but it is not itself dereferenced on the immediate-return path.

### Result

The represented result is a 32-bit, pointer-shaped value:

| Condition | Result |
|---|---|
| Nested word has low bit clear | Exact nested word, including zero. |
| Descriptor search finishes without a match | One. |
| Table loop completes and publishes its base | Zero. |
| Checked positioning operation reports nonzero | That operation’s result. |
| Checked reader leaves nonzero status | Status, subject to the cleanup behavior described below. |

A repeated flag check also guards a return of the low 32 bits of the acquisition result. Its ordinary reachability is unresolved.

No general success/error namespace, pointer validity rule, or ownership convention follows from these results.

### Working values and storage

The acquisition dependency returns 64 bits. The function uses:

- The low 32 bits as an address from which it reads one 32-bit context word.
- The high 32 bits as a handle supplied to subsequent parsing dependencies.

A writable, 32-bit status slot is passed by address to reader dependencies. Other operations assign their return values directly to that slot.

The prospective table consists of four-byte entries. A retained global address identifies a signed 32-bit count used during table construction. A separate fixed global slot receives the table base on successful completion.

## Behavior

### Entry and immediate return

The established order is:

1. Invoke F-69cd1e064ac0 with no visible arguments.
2. Write the stored-value argument at object offset `0x58`.
3. Read and retain a global address identifying the count location.
4. Read the address at object offset `0x9c`.
5. Read the nested word at that address plus `0x04`.
6. Test the nested word’s low bit.

If the bit is clear, return the nested word immediately. The diagnostic, acquisition, search, table-construction, and publication operations are not reached.

The entry dependency runs before the object mutation and subsequent reads. Its effects are unknown; the function does not establish that it preserves the object or any global state.

### Low-bit-set path and diagnostic argument reads

If the nested word’s low bit is set, the function establishes an address into its current stack region. The following sequence then occurs:

1. Read a 32-bit value from a global diagnostic-argument location.
2. Invoke F-72d6ac25a5a5 with that value as its first argument and a fixed opaque address as its second argument.
3. After that call returns, read the same global diagnostic-argument location again.
4. Invoke F-58e7ae060acf with the newly read value.
5. Invoke F-413e9e177c2e with the integer one and retain its 64-bit result.

The two diagnostic-argument values are not established constants and need not be equal. F-72d6ac25a5a5 has unknown side effects and may change the global location before the second read. The second call does not reuse a retained copy of the first argument.

The fixed second argument to F-72d6ac25a5a5 is also the distinguished value used later for exact tag comparison. Its textual interpretation does not define the comparison semantics.

After acquisition, the representation tests the earlier low-bit-derived flag again and conditionally returns the acquisition result’s low half. In the displayed ordinary flow, that flag was already false on entry to this path and has no visible intervening assignment. This is not an established, independently reachable acquisition-error case.

On the continuing path, the function reads a 32-bit context word through the acquisition result’s low half. The context word is retained for later table-production and cleanup calls.

### Initial positioning and search bound

F-e40a3ceddab2 receives the acquisition result’s high half and the established stack-region address. Its result becomes the status.

A nonzero result is returned immediately. Otherwise, F-8f49ed59b67e receives the same handle and the status-slot address.

If that reader leaves nonzero status, the function returns the status before processing descriptors. Otherwise, the reader’s numeric result supplies the descriptor-search bound:

- Retain its low 16 bits.
- Add one.
- Use the resulting value, from 1 through 65,536 inclusive.

The addition occurs after masking and is not truncated back to 16 bits. A low half of `0xffff` therefore specifies 65,536 descriptors.

### Descriptor search

Each descriptor reached requires these calls, in order:

1. F-10d2ce969adf for a 32-bit tag.
2. F-8f49ed59b67e for a first 32-bit descriptor value.
3. F-8f49ed59b67e for a second 32-bit descriptor value.

Each receives the handle and the status-slot address. Status is checked after every call. A nonzero status causes immediate return, without making the remaining calls for that descriptor.

After all three reads succeed, the function reads an externally referenced diagnostic-state base and a signed 32-bit level at offset `0x34` from that base. If the level exceeds one, it invokes F-4457a9a44a68 with a fixed format argument and three explicit numeric arguments derived from the tag:

- Bits 31–24.
- Bits 23–16.
- Bits 15–8.

No separate argument for bits 7–0 is visible. Additional behavior suggested by the format is not established.

This diagnostic call precedes the tag comparison. The tag is not visibly reloaded afterward.

The tag is compared for exact 32-bit equality with the distinguished fixed address. This is neither a string-content comparison nor a masked comparison.

For a nonmatching tag, the function advances to the next descriptor without an additional visible skip based on either descriptor value. If the search bound is exhausted, it returns one without publishing a new table.

### First matching descriptor

On the first matching tag, the function:

1. Masks the first descriptor value to 16 bits and adds one.
2. Stores that result through the retained global count address.
3. Masks the second descriptor value to 16 bits.
4. Adds that masked value as a byte offset to the retained stack-region address.
5. Calls F-e40a3ceddab2 with the handle and the resulting address.

The count written is between 1 and 65,536 inclusive. The offset is between zero and 65,535 bytes inclusive; it is not multiplied by an entry size.

A nonzero positioning result is returned immediately. The earlier count write is not undone.

If positioning succeeds, F-6dd003795db7 is called with:

- The retained context word.
- Four.
- Zero.
- A fresh read of the signed count through the retained global address.

The return value is retained as the prospective table base. The argument pattern suggests table allocation, but neither allocation semantics nor ownership is established.

The count supplied here need not equal the count originally written: the intervening dependency may have changed it.

No explicit null or capacity check is performed on the returned table base. Immediately afterward, the function checks the existing status slot, rather than assigning the table-producing result to it. If status is nonzero, that status is returned without invoking the cleanup dependency.

### Table-entry construction

The entry index starts at zero. At each loop test, the function rereads the signed 32-bit count through the retained global address.

If the count is no greater than the index, it publishes the table base and returns zero. Otherwise, the iteration performs:

1. F-d8528f8db63b with the handle and two; its result replaces status.
2. The same call again; its result again replaces status.
3. F-10d2ce969adf with the handle and status-slot address.
4. A status check.
5. On zero status, a four-byte entry write.
6. F-d8528f8db63b with the handle and four; its result replaces status.
7. Increment of the index before the next count test.

Neither of the first two operation results is independently checked before the entry reader. The trailing operation’s result is not checked before the next loop-bound test.

For index \(i\), the stored entry is:

\[
\left(\text{relocation base}
+ \left(\text{parsed entry}\mathbin{\&}\texttt{0x00ffffff}\right)\right)
\bmod 2^{32}.
\]

The destination is table base plus \(4i\) bytes. The parsed entry’s high byte is discarded. Its remaining 24 bits are treated as nonnegative, not sign-extended.

If the entry reader leaves nonzero status, the current entry is not written. F-bf7242c98d06 is called with the context word and table base, after which the status slot is returned. The cleanup dependency is not established to preserve that slot, so the returned value is not unconditionally the pre-cleanup error value.

### Publication and mutable count

Normal loop termination writes the table base into the represented 32-bit global publication slot at `0x00000108`, then returns zero.

The loop count is not snapshotted. Changes made by dependencies can affect subsequent iterations independently of the count supplied to the table-producing call. A nonpositive count observed at the first loop test causes publication without an entry write.

A nonzero result from the trailing F-d8528f8db63b call does not prevent publication if the next count test terminates the loop.

No visible operation releases the acquisition resource, cleans up a previously published table, restores the old count, or clears the publication slot on failure.

## Side effects

Established direct effects include:

- The unconditional 32-bit object-field write after the entry dependency returns.
- A global read retaining the count-location address before the nested-word decision.
- Two distinct reads of the same diagnostic-argument global on the low-bit-set path, separated by F-72d6ac25a5a5.
- Diagnostic-state base and level reads after successful descriptor reads.
- A count write on the first matching descriptor.
- A fresh count read for F-6dd003795db7 and repeated signed count reads during table construction.
- Four-byte table writes for successfully processed entries.
- A publication-slot write only on normal table-loop termination.

Dependencies may have additional effects. In particular, no preservation guarantee applies to the diagnostic-argument global between its two reads.

Failure is not transactional. An error return may follow object mutation, count replacement, a table-producing call, partial entry writes, and arbitrary dependency effects.

The function does not directly establish memory release or ownership transfer. There is no visible synchronization for count or publication accesses. Thread safety, reentrancy, and concurrent-reader guarantees remain unspecified.

## Acceptance examples

These are conditional static expectations, not executed tests.

1. **Immediate even return.** If the entry dependency returns and the nested word is `0x00002000`, the stored-value argument is written at object offset `0x58`, the count-location address is read, and the function returns `0x00002000`. Parsing dependencies are not called.

2. **Immediate zero return.** A zero nested word returns zero without table construction or publication.

3. **Diagnostic global changes between calls.** Suppose the diagnostic-argument global contains `0x11111111` at its first read, and F-72d6ac25a5a5 changes it to `0x22222222` before returning. Its first argument is `0x11111111`; the subsequent argument to F-58e7ae060acf is `0x22222222`. Equality is required only if the second read actually yields the same value.

4. **Initial positioning failure.** Given an odd nested word and normally returning preceding dependencies, a nonzero initial F-e40a3ceddab2 result is returned before the search-bound reader is called.

5. **Search-bound masking.** A search-bound reader result of `0x1234ffff`, with zero status, permits 65,536 descriptor iterations, not zero.

6. **Search exhaustion.** If all required reads leave zero status and every tag differs from the distinguished value, the function returns one without a direct count write or publication write. This does not assert that dependencies leave those globals unchanged.

7. **Matching count and byte offset.** A first descriptor value of `0xabcd0002` writes count three. A second value of `0x98760010` supplies a sixteen-byte offset for the second positioning call.

8. **Relocation arithmetic.** With stable count one, valid writable storage, successful entry reading, parsed entry `0xabfffff0`, and relocation base `0x00000030`, the stored word is `0x01000020`. With relocation base `0xfffffff0`, it is `0x00ffffe0` after 32-bit reduction.

9. **Entry-reader error.** If an entry reader leaves nonzero status, that iteration performs no table-entry write. Cleanup is called before return. The result equals the reader’s status only if cleanup leaves the status slot unchanged.

10. **Unchecked trailing result.** With stable count one and a successful entry write, a nonzero trailing F-d8528f8db63b result does not prevent publication and return of zero.

11. **Count changed before construction.** If the table-producing dependency changes the count to zero before the first loop test, the function publishes its returned base without entry reads or writes, assuming the intervening status check remains zero.
