# F-e85a9e627a8f

## Purpose

F-e85a9e627a8f updates one word in caller-accessible storage. It clears two selected bits of the word’s previous value and then combines that intermediate value with the entire supplied input using bitwise OR.

The central behavioral distinction is that the input is **not restricted to the two cleared bits**. Any input bit that is one becomes one in the stored result. Consequently, this operation can replace bits 11 and 12, and it can set—but cannot clear—any other bit.

A plausible intent is to update a two-bit field within a larger state word. That intent is not established by the supplied source. In particular, restricting the input to a two-bit field would change the observed contract unless callers already satisfy that restriction.

## Behavior

For an ordinary successful invocation under the 32-bit interpretation:

1. The function reads the unsigned word at the base address plus `0x48`.
2. It clears bits 11 and 12 of that value, numbering the least-significant bit as bit 0.
3. It combines the resulting value with the entire update value using bitwise OR.
4. It writes the combined word back to the same location.
5. It returns without a value.

These steps describe the observable data dependency, not an instruction sequence or an atomicity guarantee.

The clearing mask is `0xFFFFE7FF`. Its complement within 32 bits is `0x00001800`, identifying the two affected positions:

| Position | Bit value | Resulting behavior |
|---|---:|---|
| Bit 11 | `0x00000800` | Replaced by bit 11 of the update value |
| Bit 12 | `0x00001000` | Replaced by bit 12 of the update value |
| Every other bit | All remaining positions | Previous bit OR corresponding update bit |

Thus, bits 11 and 12 are independent of their previous values. Each is zero or one solely according to the corresponding input bit.

For every other bit:

- A previous one remains one, regardless of the corresponding update bit.
- A previous zero becomes one if the update bit is one.
- A previous zero remains zero if the update bit is zero.

There is no carry, addition, subtraction, or signed comparison in the word transformation. The address calculation is separate from that transformation.

### Input restrictions and edge cases

The function itself does not require the update value to be confined to `0x00001800`. Supplying bits outside that mask has a defined effect under the stated word model: those bits are ORed into the previous word.

If a caller wants only the two selected bits to change, it must supply an update value with every other bit zero. That is a condition for field-only behavior, not a validation performed by this function.

A zero update value clears bits 11 and 12 and preserves all other bits.

An all-ones update value produces an all-ones result, irrespective of the previous word.

Applying the same update repeatedly is idempotent at the word level when no other actor modifies the target between applications. Each application still contains a target read and a target write; the source contains no unchanged-value shortcut.
