# F-5a0e2e961d01

## Purpose

F-5a0e2e961d01 selects a 32-byte record and either returns a status, modifies part of that record, or submits a request identifying it.

Its decisions depend on:

- Equality between the record’s first 32-bit field and a 32-bit value obtained through a global reference.
- A signed 16-bit conversion of the record’s second 32-bit field.
- Whether the record’s third 32-bit field is zero.

The direct status results are 0, 9, and 10. On the request path, the result instead comes from a writable request word after F-c81f7910921f returns.

Two other dependencies surround the record decisions and direct modifications. Their placement suggests entry and exit operations, possibly synchronization, but their actual semantics are not established.

## Interface

### Argument and record selection

The function accepts one integer argument, the **record index**, represented as a signed 32-bit value in the supplied material.

The selected record address is calculated from a globally obtained table base using a byte displacement of:

**record index × 32**

The selected address is calculated before F-unknown-01 is called. Subsequent record accesses use that already selected address; the function does not visibly recalculate it after the dependency returns.

The original record index is also placed in the request on the request-submission path. That field contains the index, not the byte displacement or selected address.

No bounds check, negative-index rejection, alignment check, null check, or explicit arithmetic-overflow handling is visible. Successful normal execution requires accessible storage for the accesses actually performed and address arithmetic supported by the target. The valid index domain, table capacity, and behavior of overflowing address calculations are not established.

### Return value

The return is a 32-bit word.

| Condition | Returned value |
|---|---:|
| The comparison fields differ | 9 |
| The comparison succeeds and the threshold read converts to a signed 16-bit value of at least 2 | 10 |
| The comparison succeeds, the threshold value is below 2, and the third field is zero | 0 |
| The comparison succeeds, the threshold value is below 2, and the third field is nonzero | Request result word after F-c81f7910921f returns |

The meanings of 9 and 10 are not established beyond these branch outcomes. A zero return can arise either from direct record clearing or from the request path; it does not identify which operation occurred.

### Record layout

Records have a 32-byte stride. The directly accessed fields are:

| Byte offset | Access width | Established role |
|---|---|---|
| 0 | 32-bit read or write | Equality comparison; cleared on one path |
| 4 | 32-bit reads; 16-bit writes | Source for signed 16-bit conversions; partial-field update |
| 8 | 32-bit read | Zero/nonzero discriminator |

The function does not directly access the remaining record bytes.

A 16-bit store at offset 4 affects only the two addressed bytes beginning there. It does not directly write bytes 6 and 7. Relating those addressed bytes to the low-order half of the 32-bit field requires a little-endian target; byte order is not independently established.

### Request layout

The request path supplies writable local storage containing three consecutive 32-bit words:

| Byte offset | Initial value | Role |
|---|---:|---|
| 0 | 15 | Selector |
| 4 | 0 | Result word read after the dependency returns |

The represented request occupies 12 bytes. No additional request fields or permitted access beyond those bytes are established. The layout describes the supplied representation, not a separately verified external ABI.

## Behavior

### Record selection and entry call

The function calculates the selected record address and then calls F-unknown-01.

No record-field decision is made before that call. Consequently, any relevant changes made by F-unknown-01 before it returns may affect subsequent decisions. Changes to the table-base global do not, by themselves, cause this function to select a new address: it continues using the address already calculated.

This distinction does not establish that the old address remains valid. Storage validity across dependency calls is an external requirement not supplied here.

### Equality comparison

After F-unknown-01 returns, the function compares the selected record’s 32-bit field at offset 0 with the 32-bit value reached through the comparison reference.

The representation does not establish the relative evaluation order of those two operand reads. Neither value should be treated as a pre-entry-call snapshot.

If the values differ, the function calls F-unknown-02 and then establishes the return value 9. It performs no direct record write and does not submit a request on this path.

### Threshold read and conversion

If the comparison succeeds, the function reads the full 32-bit field at offset 4 and converts that value to signed 16-bit form for comparison with 2.

The branch partition is:

- Signed values −32768 through 1: inspect the field at offset 8.
- Signed values 2 through 32767: take the decrement path.

Zero and negative values are not independently rejected.

The condition is represented as a 32-bit field read followed by conversion. It is not established as a standalone 16-bit memory read. The target’s rules determine the result when conversion of the original 32-bit value is not representable directly as signed 16 bits.

### Decrement path: separate update read

When the threshold read converts to a signed 16-bit value of at least 2, the function performs a separate read of the 32-bit field at offset 4 for the update.

The established update has four distinct aspects:

1. A second 32-bit field read supplies the update operand.
2. That operand is converted to signed 16 bits.
3. The converted value is promoted to the represented 32-bit integer arithmetic domain and reduced by one.
4. The arithmetic result is narrowed for a 16-bit store beginning at offset 4.

The second read need not observe the value that passed the threshold check. No intervening dependency call appears between these reads, but the evidence does not establish exclusion of other writers, atomicity, or a single cached read.

For an arbitrary signed 16-bit update operand, the promoted mathematical subtraction ranges from **−32769 through 32766**. This range fits signed 32-bit arithmetic. It does not always fit signed 16-bit storage: an update operand of −32768 produces −32769 before narrowing. The resulting stored representation in that case depends on target narrowing rules and is not established here.

**Only under stable relevant memory**, where the update conversion yields the same value that passed the threshold check, does the written mathematical result necessarily range from **1 through 32766**. In that case the subtraction result is representable as signed 16 bits.

After the 16-bit store, the function calls F-unknown-02, establishes result 10, and returns it. The result 10 follows from taking this branch; the function does not recheck the updated value.

This path does not directly read offset 8, clear offset 0, or submit a request.

### Below-threshold path with a zero third field

When the threshold value is below 2, the function reads the 32-bit field at offset 8.

If that field is zero, the direct operation order is:

1. Store a 16-bit zero at offset 4.
2. Store a 32-bit zero at offset 0.
3. Call F-unknown-02.
4. Establish and return result 0.

The halfword clear precedes the comparison-field clear. Both stores occur before the dependency call.

The function does not directly modify offset 8 or bytes 6 and 7. There is no separate exclusion for a comparison value of zero: if both comparison operands are zero, equality succeeds and the remaining decisions still apply.

### Below-threshold path with a nonzero third field

If the field at offset 8 is nonzero, the function first calls F-unknown-02. Only after that call returns does it initialize the request:

- Selector 15.
- Result word 0.
- Original record index.

It then calls F-c81f7910921f with the request address. After that dependency returns, the function reads and returns the request’s result word.

F-c81f7910921f’s own return value is not used as this function’s result.

This path contains no direct record store. It does not revisit the equality, threshold, or third-field decisions after F-unknown-02 returns, even if that dependency changes relevant global or record state.

## Side effects

### Direct writes

The function directly changes record storage on only two paths:

- The decrement path writes 16 bits at offset 4.
- The zero-third-field clearing path writes 16 bits at offset 4, then 32 bits at offset 0.

Request initialization writes the three local request words on the request path.

There is no direct write to the comparison reference, the field at offset 8, or the table-base global. These statements limit this function’s direct operations, not effects of its dependencies.

### Calls and result ordering

Every normally returning path calls F-unknown-01 once and F-unknown-02 once.

F-unknown-02 occurs after the applicable record decisions and any direct record stores. On the request path it occurs before request initialization and submission. On the other paths, the constant result is established after it returns.

Only the request path calls F-c81f7910921f.

No explicit recovery or alternative result is shown for an inaccessible address, a dependency that does not return normally, or other execution failure.

### Ownership and lifetime

The table and comparison storage are externally supplied global state. This function contains no explicit allocation or deallocation operation.

The request uses local storage whose address is exposed to F-c81f7910921f during the call. Its result word must remain available for the subsequent read if execution is to return normally.

The evidence does not establish whether the dependency retains that address, copies request contents, changes other storage, or manages memory. It does not authorize durable use of the request after this function returns or establish an ownership transfer.

## Acceptance examples

These are conditional acceptance scenarios, not executed tests. Unless a scenario explicitly describes changing memory, assume accessible storage, stable relevant values, normal dependency returns, and no additional dependency-induced changes.

1. **Comparison mismatch.**  
   The record comparison field is 7 and the referenced value is 8. F-unknown-01 and F-unknown-02 are each called once. No direct record write or request submission occurs. The result is 9.

2. **Stable decrement at the boundary.**  
   Equality succeeds, and both reads of the field at offset 4 convert to signed 16-bit value 2. The function stores 1 in 16 bits at offset 4, calls F-unknown-02, and returns 10. Offset 8 is not directly read.

3. **Stable decrement at the upper boundary.**  
   Equality succeeds, and both field reads convert to 32767. The written 16-bit result is 32766, and the returned result is 10.

4. **Changed update operand.**  
   Equality succeeds. The threshold read converts to 2, but the second read converts to −32768. The decrement branch remains selected. The promoted subtraction produces −32769 before narrowing. A 16-bit store is performed, followed by F-unknown-02 and return value 10. The exact stored value remains conditional on the target’s narrowing rule; it is not constrained to 1 through 32766.

5. **Zero-third-field clearing.**  
   Equality succeeds, the threshold value is 1, and offset 8 contains zero. The halfword at offset 4 is cleared before the 32-bit field at offset 0. F-unknown-02 follows both stores. The result is 0.

6. **Negative threshold value.**  
   Equality succeeds and the threshold conversion yields −1. This selects third-field inspection, not decrement. A zero third field selects clearing; a nonzero third field selects request submission.

7. **Partial-field preservation.**  
   On a little-endian target where the word A5A50001 converts to signed 16-bit value 1, equality succeeds and the third field is zero. The direct halfword clear changes that word to A5A50000. It does not perform a full-word clear at offset 4.

8. **Request result propagation.**  
   Equality succeeds, the threshold value is zero, and the third field is nonzero. After F-unknown-02, F-c81f7910921f receives selector 15, result 0, and the original index. If it writes 23 to the result word and returns normally, this function returns 23.

9. **Request result left unchanged.**  
   Under the same request conditions, if the dependency leaves the result word unchanged, the function returns 0. That result does not establish what other work the dependency performed.

10. **Entry dependency changes record contents.**  
    F-unknown-01 changes the contents at the already selected record address. Subsequent decisions use the post-call contents. A change to the table-base global alone does not redirect this function’s selected address.

- **Request contract:** External ABI guarantees, permitted dependency writes, pointer retention, and longer-term lifetime requirements are not supplied.
- **Status meanings:** Selector 15 and results 9 and 10 have no established semantic names.
- **Failure handling:** No explicit handling is shown for invalid storage or abnormal dependency completion.

## Evidence

Established static evidence is limited to the supplied function representation: 32-byte-stride record selection; two surrounding calls; equality against indirectly referenced state; signed 16-bit threshold conversion; a separate update read with promoted subtraction and a narrowing store; branch-specific writes; and conditional submission of a three-word request.

The stable-memory decrement range follows only when the second conversion yields the same value that selected the decrement branch. Without that condition, the promoted subtraction can reach −32769, and the stored result requires target-specific narrowing semantics.

No runtime tests have been performed. The acceptance examples specify conditional behavior for later verification, not observed executions.
