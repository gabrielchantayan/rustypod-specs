# F-cd649951dc44

## Purpose

F-cd649951dc44 initializes a caller-supplied output slot and conditionally constructs a small linked record structure.

A zero payload produces a zero output without invoking either dependency. A nonzero payload causes creation and initialization of a three-word primary record. If an additional selector is nonzero, the function also creates a two-word auxiliary record, links it from the primary record, and invokes a separate no-argument dependency before publishing the primary record address.

The function returns the address of the caller’s output slot, not the address of either constructed record.

This contract describes statically established behavior. The apparent allocation role of one dependency and the apparent structural meaning of the initialized words are interpretations, not independently verified dependency contracts.

## Interface

The function has three inputs:

| Input | Role |
|---|---|
| Output-slot address | Address at which the function stores a 32-bit result word. Also the function’s return value on normal completion. |
| Payload | A 32-bit integer. Zero suppresses construction; any nonzero value is stored in the primary record. |
| Auxiliary selector | A 32-bit integer tested only for zero versus nonzero. It controls auxiliary construction only when the payload is nonzero. |

### Output-slot requirements

The output-slot address must identify storage suitable for a 32-bit integer write. The function writes zero there immediately, before inspecting the payload for the construction decision.

There is no explicit null check, accessibility check, alignment check, or capacity check. Invalid output storage therefore has no defined successful outcome under this contract. The function does not provide a separate error result for such an input.

The previous output value is overwritten without being read. No visible attempt is made to release, inspect, or otherwise act on anything previously represented by that value.

### Return value

On normal completion, the returned pointer is exactly the supplied output-slot address.

Consequently, these are distinct results:

- The direct return value identifies the output slot.
- The 32-bit word written into that slot is either zero or the encoded primary-record address.

A caller must not interpret the direct return value as the primary record itself.

### Widths and record layouts

The visible representation uses 32-bit words. Allocation-like requests use the numeric sizes 12 and 8, consistent with three-word and two-word records respectively.

The primary record has the following observed layout:

| Byte offset | Width | Value explicitly written |
|---|---:|---|
| 0 | 32 bits | The payload |
| 4 | 32 bits | The integer value 1 |
| 8 | 32 bits | Initially zero; replaced with the auxiliary-record address when that record is constructed |

The auxiliary record has the following observed layout:

| Byte offset | Width | Value explicitly written |
|---|---:|---|
| 0 | 32 bits | Zero |
| 4 | 32 bits | Zero |

Addresses are stored through 32-bit integer fields in the visible representation. The contract therefore requires a compatible address representation for those stored links. Porting the behavior to an environment with wider pointers cannot safely be treated as merely changing native pointer types while retaining these layouts.

The evidence does not establish byte order, a portable pointer-conversion rule, or the required alignment beyond that needed for the observed word accesses.

## Behavior

### Initial output clearing

The first explicit memory operation is a 32-bit zero write to the output slot.

This happens for every input combination, including a zero payload and a nonzero auxiliary selector. Construction does not preserve an existing output value while work is in progress.

The payload and selector are input values, not addresses to be dereferenced. Apart from zero comparisons and storing the payload, the function performs no arithmetic on them.

### Zero-payload path

When the payload is zero:

- Neither dependency is invoked.
- No primary or auxiliary record is constructed.
- No further explicit output write occurs.
- The function returns the output-slot address.

On normal completion without external interference, the output slot contains zero. The selector has no effect on this path, regardless of its magnitude or sign.

### Primary construction

When the payload is nonzero, the function invokes F-8157a180d901 with the numeric argument 12.

The returned value is immediately used as the address of writable primary-record storage. The function does not first check it for null or another failure indication.

The explicit primary-record writes occur in this order:

1. Store the payload at offset 0.
2. Store the 32-bit integer value 1 at offset 4.
3. Store zero at offset 8.

Every nonzero payload follows this construction path. The function does not impose positivity, a numeric range narrower than 32 bits, or any interpretation of individual payload bits.

The value 1 at offset 4 is an established initialization value. Its meaning is not established: it must not be labeled a reference count, length, status, or ownership marker without further evidence.

### Optional auxiliary construction

When both the payload and the selector are nonzero, the function invokes F-8157a180d901 a second time, now with the numeric argument 8.

The returned address is used without a visible failure check. The explicit writes then occur in this order:

1. Store zero at auxiliary offset 0.
2. Store zero at auxiliary offset 4.
3. Store the auxiliary address into primary offset 8.
4. Invoke F-b00260d1087a without explicit arguments.

The selector’s exact nonzero value is not stored or forwarded as an explicit dependency argument. A negative selector and a positive selector take the same visible branch.

The auxiliary record is linked only after both of its words have been explicitly cleared. The additional dependency is invoked only after that link has been installed.

### Publication and completion

After the applicable construction steps, the function writes the primary-record address into the output slot and returns the output-slot address.

For a nonzero payload with a zero selector, publication follows the three primary initialization writes directly.

For a nonzero payload with a nonzero selector, publication occurs only after F-b00260d1087a returns normally. There is no explicit reinitialization of either record after that call.

Accordingly, the function’s own earlier record writes are established, but the record contents at final return cannot be guaranteed independently of dependency behavior. F-b00260d1087a might affect accessible state; the available evidence does not define what it preserves.

The final explicit output write uses the primary address obtained earlier. It does not use a replacement address returned by F-b00260d1087a.

### Exceptional completion and failure handling

No explicit recovery path, status return, cleanup operation, or rollback is present.

If a dependency returns an unusable address, the next relevant word write attempts to use it. The function does not translate that condition into a documented zero result or a distinct error code.

If a dependency does not return normally, the function does not reach its subsequent explicit operations. In particular, the final primary-address publication requires all preceding dependency calls and writes on that path to complete.

The initial output-clearing write has already occurred before any dependency invocation. That ordering does not guarantee that the output remains zero during an abnormal exit: dependencies or external interference could affect it, and their behavior is unknown.

## Side effects

The function’s explicit side effects are limited to:

- Clearing the caller’s output word.
- Initializing the primary record when the payload is nonzero.
- Initializing and linking an auxiliary record when both control inputs are nonzero.
- Publishing the primary address after construction.
- Invoking the dependencies in the specified order.

For ordinary, non-overlapping storage, the explicit write counts are:

| Path | Output-slot writes | Primary-record writes | Auxiliary-record writes |
|---|---:|---:|---:|
| Zero payload | 1 | 0 | 0 |
| Nonzero payload, zero selector | 2 | 3 | 0 |
| Nonzero payload, nonzero selector | 2 | 4 | 2 |

These counts exclude any dependency-internal writes. Primary offset 8 is written twice on the auxiliary path: first with zero, then with the auxiliary address.

No explicit memory release occurs. The function neither releases the previous output value nor releases newly obtained storage before returning.

Ownership transfer, release responsibility, allocator compatibility, and lifetime are not established. Publishing an address makes it available through the output slot; it does not by itself prove that the caller owns the underlying storage.

No direct global access is visible in this function. That is not evidence that the dependencies preserve globals, avoid callbacks, or leave other memory unchanged.

The function provides no visible locking or atomic-publication mechanism. The listed ordering describes its explicit operations, not a synchronization guarantee for concurrent observers.

## Acceptance examples

These are conditional static acceptance examples, not executed tests.

### Zero payload with an arbitrary selector

Given a valid output slot initially containing a nonzero word, a zero payload, and any selector:

- The slot is overwritten with zero.
- Neither dependency is called.
- The returned pointer equals the supplied output-slot address.

The old word is not inspected or explicitly released.

### Nonzero payload without auxiliary construction

Given valid, non-overlapping output and primary storage, a payload of 37, a zero selector, and a successful first dependency result:

- The output is cleared before the dependency call.
- F-8157a180d901 receives 12.
- The primary words receive 37, 1, and 0 in that order.
- F-b00260d1087a is not called.
- The primary address is then published in the output.
- The direct return value remains the output-slot address.

Final record values assume no dependency or external mutation beyond the stated storage provision.

### Nonzero payload with auxiliary construction

Given a payload of −1, a selector of −7, and suitable dependency results:

- Both values are treated as nonzero.
- The first request uses 12; the second uses 8.
- The primary payload word receives −1 without payload arithmetic.
- Both auxiliary words are cleared before its address is linked.
- F-b00260d1087a runs after linking but before publication.
- If that call returns normally, the function subsequently publishes the primary address.

The selector −7 is not stored in either record by this function.

### Unusable first storage result

If the first dependency returns an unusable address, the function attempts the primary payload write without a preceding validity check. A graceful zero-valued failure result is not an acceptance requirement supported by the evidence.

### Mutation by the final dependency

If F-b00260d1087a changes a previously initialized record word and returns normally, this function does not explicitly restore that word. Acceptance must not require the earlier initializer value to survive arbitrary dependency effects.
