## Behavior

### Ordered execution

The visible sequence is:

1. The fourth input is copied into temporary four-byte storage.
2. The first input is increased by four.
3. F-e194f3fbdfaa is invoked with that adjusted value.
4. After the dependency returns, its returned address is used as B.
5. A shared four-byte value is read and written at P, four bytes before B.
6. The second input replaces the contents of the temporary four-byte storage.
7. F-dfabedd4a3d1 is invoked with B as its first argument and the address of the temporary storage as its second argument.
8. If that invocation returns normally, the function returns P.

The order matters. The shared value is obtained after F-e194f3fbdfaa returns. A change to that value during the first dependency call can therefore affect the value written at P.

The write at P occurs before the temporary storage is replaced with the second input and before F-dfabedd4a3d1 is invoked. The second dependency receives a pointer to storage containing the second input at call entry. It does not receive the fourth input through that pointer on the ordinary visible path.

The initial storage of the fourth input is an explicit operation in the recovered body, but its address is not explicitly passed to F-e194f3fbdfaa. The visible interface therefore does not establish a supported way for that dependency to consume the initial value. It would nevertheless be stronger than the evidence to claim that the temporary is unreachable through every possible hidden alias or execution-context mechanism.
