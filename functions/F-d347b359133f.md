# F-d347b359133f

## Purpose

F-d347b359133f conditionally obtains an object and a number associated with a context, performs additional preparation on one branch, invokes two final operations, and publishes a 32-bit number to the caller.

Established behavior includes:

- An initial state gate returning `1` or `8` without invoking dependencies.
- A direct acquisition branch and a search-and-preparation branch.
- Immediate propagation of specified nonzero dependency statuses.
- A metadata-dependent exit that returns `0` without publishing an output.
- A completion sequence that forces flag bit `0x00000008`, invokes two dependencies, then writes the current number temporary to the caller.

“Object,” “search,” “preparation,” and “reconciliation” describe roles, not established domain semantics. A return value of `0` does not by itself establish that output publication occurred.

The distinction between live temporary storage and saved values is material. Dependencies receive addresses of several temporaries. Their later contents cannot unconditionally be identified with the values initially placed there.

### Temporary storage and snapshots

The following descriptive roles distinguish separate storage:

- **Live number:** 32-bit integer storage used for the direct-path result or the search seed and subsequent search number. Its address is passed to a dependency on either branch. Final publication reads this storage.
- **Selected-object reference:** 32-bit storage used for the object passed to later operations. Its address is passed on the direct branch and on nonmatching-number acquisition paths.
- **Resolution-object reference:** separate 32-bit output storage used when resolving a search number.
- **Associated number:** separate 32-bit integer output storage from that resolution.
- **Metadata buffer:** four bytes, with only byte zero explicitly inspected or forwarded here.
- **Metadata word:** a separate 32-bit output value.
- **Search snapshot:** a saved value used for advancement and the outer search comparison. Its address is not passed to a dependency in the supplied representation.

An escaped temporary may be modified through a retained pointer while this invocation remains active. Every subsequent use of such storage means its then-current contents unless an explicit snapshot or copy is described. This qualification applies to references, numbers, and metadata, not just caller storage or object fields.

### Preconditions

There are no explicit checks for null references, alignment, accessible extent, or writability.

Every reached access must be valid. A dependency that changes an escaped object-reference temporary must leave an appropriate readable reference if execution subsequently dereferences it. Outputs must be initialized before any reached read; the function does not initialize them defensively.

Input references need not be distinct according to any visible check. The output destination may alias other reachable storage. Dependency contracts governing aliasing, retained pointers, and lifetime are unavailable.

## Behavior

### Initial state gate

The function reads the state reference from context offset `0x04`, then reads state byte `0x30`.

If that byte differs from `2`, it reads state byte `0x11`:

- Zero produces result `1`.
- Nonzero produces result `8`.

No dependency is called and no explicit output write occurs on these exits.

Otherwise, state byte `0x16` selects the next branch:

- Zero selects direct acquisition.
- Nonzero selects search and preparation.

The loaded state-reference value is retained for later state-based operations. The context’s state-reference field is not explicitly reloaded after dependency calls. Changes to the original context field therefore do not themselves change this retained reference, although dependencies may change the referenced state storage.

### Direct acquisition

F-66c60373345b receives the retained state reference, output addresses for the selected-object reference and live number, and numeric arguments `1` and `0`.

A nonzero status is returned immediately, without an explicit cleanup call or output publication.

A zero status leads directly to final completion. The search, metadata, reconciliation, and search-update stages are skipped.

The final stages read the selected-object reference and live number when required. They are not guaranteed to retain their acquisition-time values after intervening dependencies.

### Search initialization

F-230fa175dd80 is called with the retained state reference. No result is tested.

F-70fe47664dff then receives the context reference, selector `4`, and the address of the live number.

After that call returns, the function reads the live number into the search snapshot **before** testing the call’s status. Consequently, a failed call does not avoid this read. Defined execution requires readable, initialized contents even on that path.

If the status is nonzero, it is returned. Otherwise, search begins.

### Candidate search: live number versus snapshot

Each inner attempt advances from the saved search snapshot, not from an arbitrary later reread of the live number:

1. The snapshot plus one is stored into the live number.
2. F-c76bdec3f9e1 receives the retained state reference and the live-number value supplied for that call.
3. After the call returns, the function reads the live number and saves it as the new search snapshot.
4. The dependency result is compared with the then-current live number.

Equality repeats the inner search. The next increment uses the saved snapshot.

The post-call read is significant. F-c76bdec3f9e1 could, through a pointer previously retained by F-70fe47664dff, modify the live number. Thus neither the snapshot nor the equality comparison is unconditionally tied to the number passed into F-c76bdec3f9e1.

When the inner comparison is unequal, the function reads the 16-bit state field at `0x1C` and calls F-d7be9cfb4000 with `0x40000000` and that field value.

It then compares the dependency result plus one with the **saved search snapshot**, not with a fresh read of the live number.

- Equality resumes the search. The next advancement writes snapshot plus one into the live number.
- Inequality exits the search.

F-d7be9cfb4000 may affect escaped storage. If it changes the live number, that change does not alter the saved snapshot used in this comparison. If the search exits, subsequent processing uses the current live number, which may differ from the snapshot. If the search repeats, the next advancement overwrites the live number using the saved snapshot.

The state field at `0x1C` is read anew on every outer check.

Both additions are represented as signed 32-bit integer additions: snapshot plus one, and the boundary result plus one. Behavior beyond the signed range is not established; modulo wrapping must not be assumed. No iteration limit, exhaustion result, or termination guarantee is visible.

### Resolve the current live number

F-66c60373345b receives:

- The retained state reference.
- Output addresses for the resolution-object reference and associated number.
- The current live number.
- Numeric argument `1`.

A nonzero status is returned immediately.

After a zero status, the function compares the current associated number with the current live number. The latter may have changed during resolution through its escaped address.

If equal, the current resolution-object reference is copied into selected-object storage. Metadata and reconciliation are skipped.

If unequal, the following preparation sequence runs.

No rollback of prior effects is established.

### Final completion

Both successful branches converge on this sequence:

1. F-f6da3c4a0ea5 receives the current selected-object reference and the original flags with bit `0x00000008` forced on.
2. After that call returns, the function reads the selected-object reference again and loads its 32-bit field at `0x48`.
3. F-44d249c54e70 receives that loaded field value.
4. After both final calls, the function reads the current live number and writes it to the caller’s output as 32 bits.

Both rereads matter. A changed selected-object reference can redirect the field load to a different object. A changed live number can alter the published output. Completion does not necessarily publish an earlier search snapshot, the number passed to an update, or the direct acquisition’s original number.

## Side effects

Explicit temporary writes include search advancement, snapshot updates, and the matching-path reference copy. Dependencies may additionally modify output storage whose addresses they receive, including through retained pointers during later calls.

Call ordering and short-circuit behavior are established. Evaluation order among independent argument reads within one call is not established by the supplied representation.

There is no visible transaction, rollback, locking, or synchronization. Failures may follow state changes made by earlier dependencies.

F-6cc778185718 has a cleanup-like placement, but its ownership semantics are unknown. Its calls do not establish release, destruction, reference counting, or transfer. In particular:

## Acceptance examples

These are conditional examples, not executed tests. All reached memory accesses and arithmetic must be valid. Preservation assumptions apply only where explicitly stated.

1. **Initial rejection.** If state byte `0x30` differs from `2`, byte `0x11` equal to zero produces `1`; a nonzero byte produces `8`. No dependency call or explicit output write occurs.

2. **Direct completion with preservation.** Suppose direct acquisition succeeds with object reference A and number `27`, and later calls preserve both temporary values and required object validity. Flags `0x00000020` are supplied as `0x00000028`, output becomes `27`, and the result is `0`.

3. **Direct failure.** If direct acquisition returns `5`, the result is `5`; final operations and explicit output publication are skipped.

4. **Mutation during inner search.** Suppose the snapshot is `10`. The function writes and passes `11` to F-c76bdec3f9e1. If that dependency changes the live number to `40` through retained access and returns `40`, the post-call snapshot is `40`, equality repeats the inner search, and the next advancement writes `41`.

5. **Boundary comparison uses the snapshot.** Suppose the inner search exits with snapshot and live number both `12`. If F-d7be9cfb4000 changes the live number to `90` and returns `11`, the outer comparison is `12` against saved `12`, so search repeats. The next advancement writes `13`, not `91`.

6. **Boundary mutation survives search exit.** Under the same starting values, if the boundary dependency changes the live number to `90` and returns `10`, the outer comparison fails. Resolution receives `90`, absent further intervening changes.

7. **Zero without publication.** On the nonmatching path, successful metadata retrieval followed by inspection of byte `1` or `2` causes the object-associated F-6cc778185718 call and result `0`, without explicit output publication.

8. **Metadata changes before reconciliation.** Suppose the inspected metadata byte is `3`. If the successful object-check dependency changes it to `1`, reconciliation receives the current byte `1`; the earlier special-byte exit is not reevaluated.

9. **Update arguments can differ.** If the first update receives `20`, changes the live number to `21`, and succeeds, the second update receives `21`. A failure there triggers the object-associated call and returns that failure without established rollback.

10. **Final rereads.** Suppose F-f6da3c4a0ea5 receives object A but changes escaped selected-object storage to valid object B. The following field load uses B. If F-44d249c54e70 then changes the live number to `99`, final publication writes `99`.
