# F-81e60103e379

## Purpose

F-81e60103e379 updates a caller-supplied state object from a requested 32-bit setting and a force-update flag. Unless an initial equality check suppresses the update, it:

- Restricts the requested setting to the inclusive unsigned range 500–2000.
- Stores that setting in the state object and, conditionally, in a referenced object.
- Obtains a derived value through F-d7be9cfb4000.
- Establishes two representation fields, either directly or through additional dependencies.
- Selects a pair of 32-bit entries from a globally referenced table and stores them in the state object.

The field names used here describe their role in this function, not a recovered external interface. A rate adjustment, floating-point ratio, fixed-point increment, or processing-dispatch purpose is plausible but not established. In particular, dependency names and familiar bit patterns do not establish the dependencies’ mathematical contracts.

## Behavior

### 1. Initial suppression uses the unmodified request

The function first reads the stored setting at state +0x54 and compares its 32-bit value with the original requested setting.

If they are equal and the force-update flag is zero, the function returns immediately. This path performs no direct writes, invokes no dependencies, and does not read the global table pointer.

This comparison precedes normalization. Consequently:

- A stored out-of-range setting can suppress an update if the original request matches it.
- A request that normalizes to the stored setting does not suppress an update unless the original request itself matches.
- Any nonzero force-update value causes processing even when the original request equals the stored setting.

### 2. Normalize and publish the setting

If processing continues, the requested setting is restricted using unsigned comparisons:

| Original request | Setting used afterward |
|---|---|
| Below 500 | 500 |
| 500 through 2000, inclusive | Original request |
| Above 2000 | 2000 |

The normalized setting is written first to state +0x54.

The function then reads the pointer-valued field at state +0x90. If nonzero, it writes the normalized setting to the referenced object at +0x20. If zero, that write is omitted.

These writes precede the first dependency invocation. They are not rolled back by any visible mechanism.

Unsigned interpretation matters. For example, the 32-bit value 0xFFFFFFFF is above 2000 and normalizes to 2000 if processing reaches this stage.

### 3. Obtain the derived value

After the setting writes, the function reads the multiplicand at state +0x00. It multiplies that word by the normalized setting using the supplied 32-bit arithmetic model and passes the resulting 32-bit product, followed by 1000, to F-d7be9cfb4000.

The multiplication has no visible widening step. A product exceeding 32 bits therefore supplies its low 32 bits to the dependency; this contract does not replace it with an unbounded product.

The dependency’s result is treated as a 32-bit derived value. Its arithmetic meaning is unknown. In particular, the evidence does not establish division, rounding, signedness within the dependency, saturation, or its exceptional cases.

After this call returns, the function reads and retains the global table pointer. It then reads state +0x0C and compares that word with the derived value.

The timing matters: F-d7be9cfb4000 runs before the reference-field read and before the first global-pointer read. Its effects, if any, may influence either read.

### 4. Establish representation fields

#### Derived value equals the reference field

When the derived value equals the word read at state +0x0C:

1. State +0x3C receives the exact word 0x3F800000.
2. The global table pointer is read again, replacing the previously retained table base.
3. State +0x44 receives the exact word 0x00010000.
4. Selection proceeds through the unity table group.

No representation-conversion dependencies are called on this path.

The constants resemble binary floating-point one and a fixed-point unity marker, respectively. Only their exact stored bit patterns and their use in selection are established.

## Side effects

The function directly modifies only:

- State +0x54 on every update path.
- Referenced-object +0x20 when the state’s pointer-valued field is nonzero.
- State +0x3C and +0x44 on every normally completed update path.
- State +0x94 and +0x98 after successful table reads.

Dependencies may introduce additional effects. Their memory ownership, global-state behavior, allocation behavior, and release behavior are unknown.

The update is not visibly transactional. For example, the normalized setting is already stored before F-d7be9cfb4000 runs, and the representation fields are stored before the selected pair is committed. A failure partway through may leave a partially updated object.

No allocation, release, locking, notification, or explicit error reporting is directly shown. Absence of such operations in this function does not establish their absence inside dependencies.

Non-aliasing is not established. If the referenced object or selected table overlaps the state, earlier writes can affect later reads. The access order above governs such cases; this contract does not assume independent storage.

Likewise, no atomicity or concurrent-access guarantee is established. The logical read/write sequence described here is not a synchronization contract.

## Acceptance examples

These are conditional static acceptance cases, not executed tests. Unless stated otherwise, assume valid memory, normal dependency returns, and no dependency effects that alter the stated observations.

### Exact-match no-op

Given a stored setting of 750, a request of 750, and a zero force-update flag, the function returns without direct writes or dependency calls. Existing representation fields and selected entries remain untouched by this function.

The same suppression occurs for a stored setting and request both equal to 300, despite 300 being below the normalization range.

### Normalized equality does not suppress work

Given a stored setting of 500, a request of 300, and a zero force-update flag, processing continues because 300 differs from 500. The setting written is 500, and the dependency and selection stages remain reachable.

### Forced refresh

Given a stored setting and request both equal to 1000, any nonzero force-update flag bypasses suppression. A flag of −1 has the same bypass effect as a flag of 1.

### Unsigned upper-bound handling

Given a request of 0xFFFFFFFF and an initial comparison that does not suppress processing, the stored setting becomes 2000. It does not become 500 through a signed-negative interpretation.

### Product truncation

Given a normalized setting of 1000 and a multiplicand of 0x01000000, F-d7be9cfb4000 receives 0xE8000000 as its first explicit argument and 1000 as its second. The first value is the low 32 bits of the product.

### Direct unity path

Suppose F-d7be9cfb4000 returns the value subsequently read at state +0x0C. The function stores 0x3F800000 at +0x3C and 0x00010000 at +0x44 without calling the representation dependencies.

If the later discriminator reads yield 16 and 2, table entries at +0x08 and +0x0C are copied to state +0x94 and +0x98.

### Unequal comparison can still select unity entries

Suppose the derived/reference comparison differs, but F-eb34c4d75211 returns 0x00010000. The unity group is selected despite the earlier inequality.

With discriminator reads of 16 and a value other than 2, the selected offsets are +0x00 and +0x04.

### Non-unity selection

Suppose the unequal path returns 0x0000FFFF from F-eb34c4d75211, and the discriminator reads yield a value other than 16 followed by 2. The function stores 0x0000FFFF at state +0x44 and copies table offsets +0x30 and +0x34 into the final pair.

### Global-pointer changes during dependency calls

On the unequal path, suppose a representation dependency changes the global table pointer but leaves the previously captured table valid. Selection still uses the captured table base. Changes to that table’s contents before the actual entry reads can affect the copied values.
