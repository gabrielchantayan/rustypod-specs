# F-284bd9128452

The available evidence does not establish allocation, reference counting, exclusive ownership, destruction responsibilities, or the meaning of the stored values.

This contract describes the visible routine and its ordering. Dependencies may have additional effects that are not specified here.

## Behavior

### 1. Obtain the result record

The routine calls F-a83470f5febf with A and a second argument equal to zero.

It does not first read B, copy a field from B, or initialize any result field. Consequently, effects of F-a83470f5febf can influence the later reads of B and the global initializer value.

No null check or failure-result check is visible after this call. The returned address is immediately used for a 32-bit write.

The zero argument does not establish an allocation size, flag meaning, initialization mode, or ownership policy. Those meanings are documented_only.

### 2. Write the initial fields and capture an input field

After the dependency returns, the routine performs these operations in order:

1. Reads the fixed global initializer value and writes it at result offset 0.
2. Writes B’s pointer representation at result offset 8.
3. Reads the 32-bit word at B offset 68 and writes that value at result offset 12.

The value stored at offset 12 is a snapshot taken at this point. It is not visibly refreshed after subsequent calls.

No direct operation initializes result offset 4. Its content may originate from the initial dependency, preexisting storage, aliasing, or later dependency effects. The routine does not establish its value.

Aliasing is not prohibited by a visible check. If the result record overlaps B, either of the first two writes may affect the later read at B offset 68 or the later dispatch lookup. Thus, describing offset 12 as a copy of B’s value “on entry” would be incorrect without additional non-aliasing and dependency assumptions.

### 3. Invoke the first indirect operation

The routine next reads B’s first word as a dispatch-base address, obtains a callable entry at byte offset 392 from that base, and invokes the entry with B as an explicit argument.

The dispatch lookup occurs after the preceding result writes. A dispatch-base address captured before initialization is not visibly reused.

The call’s result is represented as a 32-bit integer and tested only for equality with zero:

- Zero selects the direct-zero path.
- Any nonzero value selects the additional-call path.

There is no visible positive-only condition, mask, range restriction, or special negative case.

### 4. Select the value for result offset 16

**Zero path:** If the first indirect operation returns zero, the routine writes a 32-bit zero at result offset 16. It does not visibly invoke either additional dependency described below.

**Nonzero path:** If the first indirect operation returns any nonzero value:

1. The routine calls F-unknown-01 with B.
2. It treats the returned value as an object address.
3. It reads that object’s first word as another dispatch-base address.
4. It obtains a callable entry at byte offset 84 from that base.
5. It invokes that entry.
6. It stores the returned 32-bit value at result offset 16.

The final indirect invocation has no explicit arguments in the supplied representation. That does not establish the absence of implicit receiver state, register inputs, or calling-convention-specific inputs.

No null check is visible for the object returned by F-unknown-01. No validation is visible for either dispatch base or callable entry.

The value stored at offset 16 on this path is the final indirect call’s result, not the nonzero status returned by the first indirect call. No conversion, masking, or interpretation of this 32-bit result is visible.

### 5. Finish initialization and return

After either branch has written offset 16, the routine writes:

1. Zero at result offset 20.
2. C at result offset 24.
3. D at result offset 28.

It then returns the original result address.

There are no further visible dependency calls between these three writes or between the final write and return.

## Side effects

### Direct memory effects

The routine directly writes seven 32-bit fields in the returned record. The write sequence is offsets 0, 8, 12, 16, 20, 24, and 28.

It directly reads:

- One fixed global 32-bit initializer value.
- B’s 32-bit word at byte offset 68.
- B’s first word and a dispatch entry at byte offset 392.
- On the nonzero branch, the returned object’s first word and a dispatch entry at byte offset 84.

The indexed input read corresponds to 17 words × 4 bytes = 68 bytes. The highest result write begins at byte 28 and spans bytes 28–31. For a conventional nonoverlapping record, the accessed result extent is therefore 32 bytes. This does not prove that the initial dependency allocates exactly 32 bytes.

### Dependency effects and retained state

The routine passes B to two possible calls and stores B in the result. It does not visibly retain B through a reference-counting operation, duplicate the referenced object, or release it.

Likewise, it does not visibly release the object returned by F-unknown-01. Whether that object is borrowed, owned, shared, or internally managed is unknown.

No dependency is established to preserve globals, input memory, or partially initialized result fields. In particular:

- The global initializer is read after F-a83470f5febf, not before it.
- The B field snapshot is taken before the first indirect call.
- Earlier result writes are not restored if later calls modify them.
- Later reads use memory as it exists at their point in the sequence.

### Errors and incomplete execution

There is no visible error return, cleanup path, rollback, retry, or exception handling.

If an address is invalid, a dispatch entry is unusable, or a dependency fails to return normally, the routine may not complete. The exact failure mechanism is not established.

Partial writes can remain observable when execution stops after initialization has begun. The routine does not undo them.

- F-unknown-01 and F-unknown-03 are not invoked by this routine.

No expected value is assigned to offset 4.

### Nonzero-status initialization

Under the same validity and noninterference assumptions, suppose F-unknown-02 returns `0xFFFFFFFF` and F-unknown-03 returns `0x76543210`.

The nonzero path is taken. F-unknown-01 is invoked before F-unknown-03, and offset 16 receives `0x76543210`. It does not receive `0xFFFFFFFF`.

This example also demonstrates that a value whose signed 32-bit interpretation is negative still selects the nonzero path.

### Snapshot timing

Suppose B’s field at byte 68 contains `0x00000010` when copied. F-unknown-02 later changes that field to `0x00000020`.

If no later effect changes result offset 12, that result field remains `0x00000010`. The routine does not refresh the snapshot.

### Global-read timing

Suppose F-a83470f5febf changes the global initializer from `0x00000001` to `0x00000002` before returning.

Absent another intervening modification, result offset 0 receives `0x00000002`, because the global read follows the call.

### Dependency modification of an earlier field

### Invalid prerequisite
