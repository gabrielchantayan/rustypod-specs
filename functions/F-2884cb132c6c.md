# F-2884cb132c6c

## Purpose

F-2884cb132c6c combines an existing sequence of 16-bit samples with an interleaved sequence of byte-sized contributions, producing interleaved 16-bit output pairs.

The two positions within each pair can use different gain values. When the gains are equal, a comparison with a shared control word selects either gain-scaled mixing or direct byte-to-16-bit mixing.

The structure suggests a two-channel sample mixer. That interpretation is **inferred intent**, not an established requirement: no sample rate, channel meaning, audio format, or physical unit is established.

The operation resembles signed 16-bit saturation, but its overflow replacement values come from a shared control word. Conventional saturation to −32768 and 32767 occurs only when the relevant control-word observations supply the corresponding bit patterns.

## Behavior

### Entry observations and branch selection

Before checking whether any pairs are requested, the function logically performs these observations in order:

1. Reads the shared 32-bit control word and retains it as the upper overflow replacement.
2. Reads the first gain from context offset 112.
3. Reads the second gain from context offset 116.
4. Reads the shared control word again and retains its 32-bit bitwise complement as the lower overflow replacement.

The two replacement values therefore need not derive from the same observation of the shared word. Assuming they are complements of each other requires the control word to remain stable across those observations.

Branch selection then follows this precedence:

| Condition | Processing mode |
|---|---|
| The two captured gains differ | Gain-scaled processing, using the first gain for the first element of each pair and the second gain for the second element. |
| The captured gains are equal, and their unsigned value is less than a further observation of the shared control word | Gain-scaled processing, using the common gain for both elements. |
| The captured gains are equal, and their unsigned value is greater than or equal to that further observation | Direct processing, without gain multiplication. |

The comparison in the equal-gain case uses a further logical read of the shared word, not the retained upper replacement. There is no such threshold comparison in the unequal-gain case.

Once selected, the mode remains fixed for the call. Context gain fields are not reread inside the loop. Later changes to context fields therefore do not change the captured gains or processing mode.

These are source-level observation boundaries. The supplied material does not establish volatile access, synchronization, or the exact number of physical memory transactions.

### Gain-scaled contribution

For each element in a gain-scaled mode, the function forms a product from:

- The selected unsigned 32-bit gain.
- The promoted contribution byte.
- A factor of 512.

The product is retained modulo \(2^{32}\). It is then interpreted as a signed 32-bit quantity and shifted right by 16 bits.

Under the arithmetic-right-shift interpretation, define the scaled contribution as:

\[
\operatorname{scaled}(g,b)
=
\left\lfloor
\frac{
\operatorname{signed32}\!\left((g \times b \times 512)\bmod 2^{32}\right)
}{65536}
\right\rfloor
\]

If the byte is signed and negative, its participation in the unsigned multiplication is equivalent to reduction modulo \(2^{32}\). If the byte is unsigned, values from 128 through 255 remain positive.

This is a wrapped fixed-width operation, not an unlimited-precision product followed by division. Large gains can wrap before the signed interpretation, producing negative or discontinuous contributions.

With arithmetic right shift, the scaled contribution lies between −32768 and 32767. Adding a signed 16-bit base sample yields a candidate between −65536 and 65534. Thus, under these widths, the candidate addition itself does not overflow a signed 32-bit range.

The apparent fixed-point scale is inferred intent. The wrapped arithmetic is the established behavior.

### Direct contribution

In direct mode, the contribution byte is multiplied by 256 and added to the signed 16-bit base sample.

The captured gain is not used in this per-element calculation. In particular, a gain larger than the shared threshold does not cause proportionally larger mixing in this mode.

If bytes are signed, direct contributions range from −32768 through 32512. If bytes are unsigned, they range from 0 through 65280. Both interpretations fit the subsequent signed 32-bit comparison range after addition to a base sample.

### Output selection

Each candidate is compared as a signed 32-bit value:

| Candidate | Selected output value before narrowing |
|---|---|
| Less than −32768 | Retained lower replacement |
| From −32768 through 32767, inclusive | Candidate itself |
| At least 32768 | Retained upper replacement |

The selected value is then narrowed to a 16-bit output element.

The comparisons use fixed signed 16-bit boundaries regardless of the shared control word. The shared word supplies replacement values; it does not redefine the accepted interval.

If the upper observation is 32767 and the later complemented observation also comes from 32767, the resulting output bit patterns are conventional signed 16-bit saturation endpoints. Other shared-word values can produce other replacement patterns.

### Pair processing order

Within each iteration:

1. The first base sample and first contribution byte are used to calculate the first result.
2. The first 16-bit output element is written.
3. The second base sample and second contribution byte are used to calculate the second result.
4. The second 16-bit output element is written.
5. The local output and base positions advance by four bytes, and the contribution position advances by two bytes.

## Acceptance examples

These are conditional deductions from the supplied static evidence, not executed tests. Unless stated otherwise, they assume stable control and count storage, valid non-overlapping buffers, the stated integer widths, and arithmetic right shift.

1. **Zero pairs**

   With a count of zero, no base samples or contribution bytes are consumed and no output elements are written. Context and control-word storage must still be accessible because they are observed before the first count check.

2. **Equal zero gains**

   With both gains zero and the shared control word stable at 32767, gain-scaled mode is selected. Every contribution is zero, so each output equals its corresponding signed 16-bit base sample.

3. **Equal gains at the threshold**

   With both gains equal to 32767 and the shared word stable at 32767, direct mode is selected. A pair with base values 100 and −100 and contribution bytes 1 and 2 produces 356 and 412.

4. **Unequal gains take precedence**

   With gains 0 and 128, shared word 32767, base values 100 and 100, and contribution bytes 2 and 2, unequal-gain mode is selected. The scaled contributions are 0 and 2, producing 100 and 102.

5. **Conventional positive overflow**

   With direct mode selected and shared-word observations all equal to 32767, a base value of 32700 plus contribution byte 1 gives candidate 32956. The output is 32767.

6. **Conventional negative overflow, conditional on signed bytes**

   Under signed-byte interpretation and the same replacement values, a base value of −32700 plus contribution byte −1 gives candidate −32956. The output has the signed 16-bit value −32768.

7. **Byte signedness changes behavior**

   In direct mode with base zero, a contribution byte with bit pattern 255 produces −256 under signed-byte interpretation. Under unsigned-byte interpretation it produces candidate 65280, which selects the upper replacement. The supplied evidence does not choose between these outcomes.

8. **Nonstandard replacement value**

   With equal gains of 128 and a shared word stable at 128, direct mode is selected. Base 32700 plus contribution byte 1 exceeds the upper boundary, but the stored result is 128, not 32767.

9. **Wrapped gain multiplication**

   With unequal gains, assign gain 8388608 to an element whose contribution byte is 1. The product with 512 is \(2^{32}\), which wraps to zero before shifting. That element’s scaled contribution is zero, rather than the unbounded-arithmetic result 65536.
