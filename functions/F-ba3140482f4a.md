# F-ba3140482f4a

## Purpose

F-ba3140482f4a describes a recovered execution fragment that performs ordered byte and word stores, interleaved with 53 indirect calls. Values obtained from entry-time machine state and call results are repeatedly scaled, used as addresses, and forwarded to later calls.

No application-level purpose is established. In particular, the evidence does not establish that these operations initialize an object, allocate memory, encode a message, or update a valid data structure.

The available representation ends at an invalid-instruction boundary. This contract therefore describes the visible prefix, not a proven complete function. A normal return is not established.

## Interface

### Explicit interface and implicit inputs

The recovered interface has no declared parameters and no declared result. It nevertheless consumes four entry-time machine values:

| Contract name | Meaning in this contract | Observed use |
|---|---|---|
| Entry word | A value represented as a 32-bit integer | Doubled for address calculations; its low byte is stored separately |
| Entry base | An address-sized value represented as a 32-bit integer | Destination base for the first byte store |
| Entry payload | A 32-bit uninterpreted value | Low-byte stores and a later full-word store |
| Entry link | An address-sized value represented as a 32-bit integer | Determines the first indirect-call target by adding 0xF60 |

These names describe dataflow only. They do not establish a public calling convention or identify ordinary function arguments.

Additional inputs are:

- Memory contents at addresses read during execution.
- Return values from selected indirect calls.
- A secondary 32-bit call-output value used after the second call.
- The behavior of every indirect target, including whether it returns.

### Widths and arithmetic

The representation distinguishes:

- One-byte reads and writes: 8 bits.
- Word reads and writes: 32 bits.
- Two selected call results: 64 bits, subsequently split into low and high 32-bit halves.
- Explicit unsigned right shifts: logical shifts, with zeros entering the high bits.
- Byte truncation: only the low eight bits are stored.

For compactness, subsequent sections use “fourfold,” “eightfold,” and “thirty-twofold” for left shifts by 2, 3, and 5 bits, respectively.

Several address calculations and left shifts are represented using signed 32-bit expressions. Their behavior on overflow is not established by the supplied representation. Conditional examples below use values that avoid those ambiguities, except where unsigned arithmetic is explicit. A wrapping 32-bit machine interpretation is plausible but is not promoted to an unconditional portable arithmetic guarantee.

The layout of a 32-bit word in memory, including endianness, is unknown.

## Behavior

Dependency identifiers below name call sites, not proven-distinct functions. Their numbering records invocation order.

### 1. Initial writes and first call chain

The fragment first doubles the entry word. That doubled value remains relevant to later address calculations.

Before any visible call, it performs these writes in order:

1. Store the low byte of the entry payload at entry base plus 0x0D.
2. Store the low byte of the entry word at absolute address 0x0000000D.

It then invokes:

1. F-000000000001, at the entry link plus 0xF60, with three represented arguments: the doubled entry word, 0x98, and 0x260.
2. F-000000000002, with no explicit arguments represented.
3. F-000000000003, with the secondary unsigned 32-bit output associated with the preceding call shifted right by three bits.
4. F-000000000004, F-000000000005, and F-000000000006, in that order, with no explicit arguments represented.
5. F-000000000007, whose 32-bit result is consumed.
6. F-000000000008, with the fourfold result of F-000000000007. Its own 32-bit result is consumed.

The secondary output used by F-000000000003 is not an ordinary declared return value in the supplied interface. Its exact ABI meaning remains unknown.

### 2. Derived-base stores and linked word access

After F-000000000008 returns, the fragment:

1. Stores the low byte of the entry payload at doubled entry word plus 0x0D.
2. Stores 0xC0 at absolute address 0x0000000D.
3. Calls F-000000000009 with the fourfold result of F-000000000008.
4. Calls F-000000000010, F-000000000011, and F-000000000012 in order.
5. Calls F-000000000013 and retains its 32-bit result.

It then performs a 32-bit store at doubled entry word plus 0x24. The stored value is the fourfold result of F-000000000013.

Next, it reads a 32-bit unsigned word from doubled entry word plus 0x74. Call this the **linked word**. Although subsequently used as an address base, its validity as a pointer is not checked.

F-000000000014 receives four represented arguments, in order:

1. The linked word.
2. The linked word shifted left by one bit.
3. The thirty-twofold result of F-000000000013.
4. The linked word with bit 31 cleared, then logically shifted right by two bits.

F-000000000015 through F-000000000018 are invoked in increasing identifier order.

Only after those calls return does the fragment store the thirty-twofold result of F-000000000013 as a 32-bit word at linked word plus 0x24.

It then reads a 32-bit word at linked word plus 0x74 and passes that value to F-000000000019. This read occurs after the preceding store and intervening calls; it is not a snapshot from the earlier linked-word read.

F-000000000020, F-000000000021, and F-000000000022 follow in order.

### 3. Split-result processing and indexed word stores

F-000000000023 produces a represented 64-bit result. The fragment separates its low and high 32-bit halves.

It retains the fourfold low half as the **retained scaled value**. Before the next call, it writes the entire 32-bit entry payload at:

- Four times the high half, plus 0x14.

F-000000000024 then receives four represented arguments:

1. Retained scaled value.
2. Retained scaled value.
3. Retained scaled value.
4. The high half logically shifted right by three bits.

F-000000000025 produces another represented 64-bit result. F-000000000026 receives:

1. Its low 32-bit half.
2. Its high 32-bit half.
3. Its low 32-bit half again.
4. Its high half logically shifted right by three bits.

The second split result does not replace the retained scaled value derived from F-000000000023.

F-000000000027, F-000000000028, and F-000000000029 follow. F-000000000030 then produces a 32-bit result.

The fragment writes the retained scaled value as a 32-bit word at four times the result of F-000000000030, plus 0x14.

F-000000000031 receives four times that same result. F-000000000032, F-000000000033, and F-000000000034 follow in order.

### 4. Byte-selected destinations and repeated reads

F-000000000035 produces an unsigned 32-bit result. Call this the **selector word**. Its fourfold value is retained as the **scaled selector**.

The fragment reads one unsigned byte at linked word plus 1. It treats that byte’s value as a small numeric address component, adds 0x11, and stores the low byte of the scaled selector at the resulting address.

Consequently, this destination is between 0x11 and 0x110 inclusive. The read byte is not used as an index relative to the linked word.

F-000000000036 and F-000000000037 are called, followed by F-000000000038, whose 32-bit result is retained for the next argument calculation.

The fragment then rereads the byte at linked word plus 1 and performs another byte store at that newly selected byte value plus 0x11. The stored byte is obtained by:

- Clearing the top two bits of the selector word.
- Logically shifting the remaining value right by 20 bits.
- Keeping only the low eight bits.

Thus the stored byte reflects bits 20 through 27 of the selector word. The reread can select a different destination from the preceding store.

F-000000000039 receives the fourfold result of F-000000000038. F-000000000040, F-000000000041, and F-000000000042 follow. F-000000000043 produces another 32-bit result.

### 5. Two zero stores and final call chain

The next byte-source address is formed from 0x400 times the scaled selector, plus 1.

The fragment reads one unsigned byte at that address, adds 0x11 to the byte value, and stores zero at the resulting address.

F-000000000044 then receives:

1. Eight times the scaled selector.
2. Eight times the scaled selector again.
3. The scaled selector.
4. Four times the result of F-000000000043.

F-000000000045, F-000000000046, and F-000000000047 follow. F-000000000048 produces a 32-bit result.

The fragment performs a second byte read from 0x400 times the scaled selector, plus 1. It again stores zero at the newly read byte value plus 0x11.

These are distinct reads and writes. Calls or aliasing may change the selected destination between them.

F-000000000049 receives four times the result of F-000000000048. F-000000000050, F-000000000051, F-000000000052, and F-000000000053 follow in order.

The available representation then terminates at an invalid-instruction marker. Behavior beyond that boundary is unknown.

## Side effects

### Direct memory operations

If the entire visible prefix executes, it contains 12 direct stores:

- Eight one-byte stores.
- Four 32-bit stores.

It also contains six explicit data reads:

- Two 32-bit reads at derived base plus 0x74.
- Two separate byte reads at linked word plus 1.
- Two separate byte reads at the scaled-selector-derived address.

These counts exclude instruction fetching, stack activity, and all operations performed inside dependencies.

The stores may alias one another or later read locations. No separation between regions is established. In particular:

- Absolute address 0x0D is written twice.
- The first two entry-derived byte stores may share a destination.
- Byte-selected stores may affect bytes used by subsequent reads.
- A full-word store may overlap a later read or byte destination.

The described ordering must therefore be preserved; these operations cannot safely be reduced to a final-memory summary.

### Ownership, external state, and failures

No allocation, release, reference-count adjustment, or ownership transfer is explicitly identified. Passing a value to a dependency does not establish whether it is an owned pointer, borrowed pointer, handle, or integer.

No dependency is assumed to preserve globals or memory. Unrepresented effects may include mutation, resource acquisition, resource release, nonlocal control transfer, or failure.

There is no visible error return, rollback, bounds check, null check, or recovery branch. If an access or call fails, earlier side effects may already have occurred. The fragment is not established to be atomic.

## Acceptance examples

These are conditional static examples, not executed tests. Each assumes valid accesses, returning dependencies, and no unspecified interference except where stated.

1. **Entry-byte truncation.** With entry word 0x123 and entry payload 0xA1B2C3D4, the initial store at entry base plus 0x0D writes 0xD4. The next store writes 0x23 at absolute address 0x0D. F-000000000001 receives 0x246, 0x98, and 0x260.

2. **Repeated absolute-address write.** If execution reaches the store after F-000000000008, absolute address 0x0D is written with 0xC0 regardless of its earlier written value. This does not guarantee that 0xC0 remains there after later dependencies execute.

3. **Distinct scales from one result.** If F-000000000013 returns 3, the direct word store at doubled entry word plus 0x24 writes 12. The third argument to F-000000000014 is 96, and the later store at linked word plus 0x24 also writes 96.

4. **Mask before logical shift.** If the linked word is 0x8000000C, the fourth argument to F-000000000014 is 3. Clearing the high bit occurs before shifting; the result is not 0x20000003.

5. **Split-result destination and payload.** If F-000000000023 returns low half 5 and high half 8, the retained scaled value is 20. The entry payload is stored as a full word at address 0x34. F-000000000024 receives 20, 20, 20, and 1.

6. **Destination reread is observable.** If the first byte read at linked word plus 1 yields 2, the first selector-derived store targets 0x13. If intervening calls change that source byte to 7, the second store targets 0x18, not 0x13.

7. **Narrowed selector extraction.** For selector word 0x12300000, the second selector-derived byte store writes 0x23. The intermediate shifted value is 0x123, but only its low byte is stored.

8. **Zero stores are independently selected.** If the first late byte read yields 0xFF, its zero store targets 0x110. If the second read yields zero, the second zero store targets 0x11.

9. **Failure does not imply rollback.** If the first indirect call does not return, both initial byte writes have already occurred. None of the later described operations is established to occur.
