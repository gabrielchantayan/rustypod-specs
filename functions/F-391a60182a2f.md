# F-391a60182a2f

## Purpose

F-391a60182a2f selects a processing route from a one-byte field in a caller-supplied object. For selector values 4 through 7, it obtains two 32-bit results from a selector-specific dependency and passes those results, an object-associated 32-bit value, and a caller-supplied fourth input to a downstream dependency. Other selector values produce an immediate return without dependency calls.

This contract describes behavior supported by the supplied static representation. It does not establish the application meaning of the selector, the object-associated value, or the dependency results. In particular, terms such as conversion, allocation, serialization, or transmission would imply semantics not established here.

No runtime tests have been performed.

## Behavior

### Route selection

The function first reads the selector byte at offset 100. That read determines the route for the remainder of the invocation.

The recognized selector values are the exact byte values 4, 5, 6, and 7. All other byte values cause a return without reading the four-byte field at offset 104 and without invoking any listed dependency.

Whether the selector byte is interpreted as signed or unsigned does not change which byte values match these four cases.

The selector is not read again. A preparation dependency that changes the selector therefore does not cause this invocation to switch routes.

### Selector 4

The externally relevant order is:

1. Invoke F-afa658d02e70 with the secondary value as its single explicit argument.
2. After that invocation returns, invoke F-afa658d02e70 with the primary value as its single explicit argument.
3. After both invocations return, read the four-byte object-associated value at offset 104.
4. Invoke F-d2f4138dec48 with five ordered arguments:
   - The original object address.
   - The value obtained by the late four-byte read.
   - The result of the second preparation invocation, which received the primary value.
   - The result of the first preparation invocation, which received the secondary value.
   - The auxiliary value.
5. Return after the downstream call completes.

Thus, preparation occurs secondary-first, but the resulting values are placed in the downstream call primary-first.

Both preparation results are represented as 32-bit values. This function shows no arithmetic, validation, or interpretation of those results.

### Ordering and mutation

The four-byte field is read after both preparation calls, not when the selector is read. If a preparation call validly changes that field, the downstream call receives the value present at the later read.

The first preparation result remains the designated fourth downstream argument even though a second dependency invocation occurs before dispatch. The contract does not require the dependencies to preserve global state or to be free of side effects.

There is no visible retry, alternate route, or result-dependent branch. Every recognized route has two preparation calls followed by one downstream call, provided preceding operations return normally and the required memory accesses remain valid.

## Acceptance examples

These are conditional contract examples, not reports of executed tests. Each recognized-route example assumes valid memory and normally returning dependencies.

### Selector 4: preparation order differs from result placement

Suppose the primary value is 11, the secondary value is 22, and the auxiliary value is 33. Suppose F-afa658d02e70 returns 220 for its invocation with 22 and 110 for its subsequent invocation with 11. If the late object-field read yields 44, the required downstream call is to F-d2f4138dec48 with:

### Selector 6: first invocation has no explicit argument

Suppose the first F-65630a061053 invocation returns 70 and its subsequent invocation with the primary value returns 80. F-c41a20765e01 must receive 80 as its third argument and 70 as its fourth.

An implementation must not invent an explicit secondary-value argument for the first invocation based solely on similarity to selector 4. Resolution of the actual low-level dependency signature remains a documented uncertainty.

### Late field observation

Suppose the object-associated field initially contains 100. The first preparation call changes it to 200, and the second changes it to 300. If the later four-byte read is valid and observes 300, the downstream dependency receives 300 as its second argument, not the initial value.

### Selector mutation does not reroute

Suppose the initial selector read yields 5, and the first F-6b28779cd5df invocation changes the object’s selector to 7. The second preparation invocation still uses F-6b28779cd5df, and dispatch still uses F-c41a20765e01. There is no second selector read.

### Unsupported selector

If the selector byte is 0, 3, 8, or 255, the function returns after the selector read. It neither reads offset 104 nor calls a listed dependency. A valid four-byte field at offset 104 is therefore not needed for this function’s direct accesses on that route.

### Unusual preparation result
