# F-72be6373ac24

## Purpose

F-72be6373ac24 forwards a 32-bit input into an ordered sequence of indirect calls, constructs further arguments from results and implicit machine state, performs alias-sensitive memory mutations, and ends with an unresolved four-argument indirect transfer.

The static evidence does not establish an application-level purpose. Character-like constants do not establish formatting or text output; repeated offsets do not establish object types.

This contract distinguishes:

- **Established static evidence:** represented operations, widths, data dependencies, and relative ordering.
- **Inferred intent:** interpretations not required for acceptance.
- **documented_only:** behavior or detail not resolved into an executable requirement here.

Requirements are conditional on execution reaching the operation, valid accesses and targets, and the representation accurately reflecting execution. No runtime tests have been performed.

## Behavior

### Ordered indirect interactions

The opening phase is a long expanded sequence of indirect calls without a represented input-dependent branch or loop. Calls with no explicit arguments, and calls whose visible results are unused, remain observable interactions.

Arguments include zeros, newly returned words shifted left by eight, halves of combined results, retained results, and secondary machine-result values. No failure-sentinel checks are represented between calls.

Established extractions include:

- Incoming-state bits 2–18, and incoming-state low fourteen bits shifted left by three.
- Result bits 8–23; elsewhere, result bits 12–23.
- Bits 11–17 of one retained upper half.
- Bits 4–16 of a later retained upper half.

Additional shifts use counts including 6, 7, 8, 9, 13–17, and 22–30. Successive shifts can discard all original bits under 32-bit truncation. Explicitly zeroed retained values remain zero through their represented transformations; this does not imply preservation of unrelated state by dependencies.

The complete per-call argument schedule is **documented_only** in this contract. Target identities and secondary-result conventions remain unresolved.

### Opening updates and fixed-byte-derived addressing

The opening stores establish an observable sequence: the upper half of the final pair addresses a word at offset 0x14 that receives the tag base; tag-base offset 0x09 then receives the low byte of that upper half. Next, lower-half-times-256 offset 0x54 receives the shifted base, and tag-base offset 0x09 is overwritten with the low byte of the tag base.

The shifted-base word at 0x14 is cleared before the unsigned byte at shifted-base offset 0x05 is read. A clear at doubled-index offset 0x14 precedes storing that widened byte at shifted-base offset 0x34. The shifted-base word at 0x14 is then loaded and retained as the **cleared-slot word**.

A second clear at doubled-index offset 0x14 precedes two identical byte stores at doubled-index offset 0x15, both using the cleared-slot word’s low byte. The name “cleared-slot word” does not guarantee zero: intervening accesses may alias the cleared storage.

The next fixed-location interaction is a byte read at **0x05**, widened as an unsigned address base. After that read:

- Fixed byte **0x01** receives the low byte of the doubled index.
- The fixed-byte-derived base at offset 0x15 receives the compact index’s low byte.
- Shifted-base offset 0x11 receives the shifted token’s low byte.
- The address supplied by the cleared-slot word, at offset 0x54, receives the shifted token.
- Shifted-base offset 0x11 is cleared.

Only after these mutations does the function load the old word at fixed-byte-derived base plus 0x54, retaining it as the seed. That word is then overwritten with the cleared-slot word. Reading the seed before this overwrite is required; reading the location later is not equivalent.

### Seed propagation and intermediate fixed writes

The compact index is stored as a word at doubled-index offset 0x34. A word loaded from shifted-base offset 0x74 supplies another address whose offset 0x54 first receives the original shifted-base-producing result shifted left by 26, and later receives the shifted token.

An intervening update uses the word at doubled-index offset 0x74 both as an address base and as the word stored at that base’s offset 0x54. The representation contains two reads of that slot for this update; their internal evaluation order is not established here.

The seed is written twice to seed-relative offset 0x24. Each write is followed by a byte store of the seed at offset 0x09 of the address loaded from shifted-base offset 0x74. The shifted-token word write occurs between these pairs.

At doubled-index offset 0x14, a word write of the shifted-by-26 result precedes a fixed word write at **0x54** of twice the seed. Two subsequent word stores at doubled-index offset 0x14 write the seed.

Two byte stores at doubled-index offset 0x15 then write the low byte of the fourfold seed. Fixed byte **0x15** subsequently receives the doubled index’s low byte. These fixed writes occur before the later seed-derived pointer traversal.

### Seed-derived loads and repeated byte probes

The fourfold-seed word at offset 0x54 is first written with the shifted token and later with the fourfold seed. Between these writes, doubled-index offset 0x34 receives the fourfold seed, and the word at doubled-index offset 0x74 is freshly read and doubled. Call that retained result the **doubled link**.

The eightfold seed is byte-stored at fourfold-seed offset 0x15. The doubled link is word-stored at seed offset 0x44.

A byte read at fourfold-seed offset 0x05 supplies a small address base; the word at that base plus 0x74 becomes the **first probe link**. Its offset 0x44 receives the doubled link. Subsequent stores propagate the first probe link’s low byte and self/address-like values through fourfold-seed offsets 0x0D and 0x14, and through an address loaded from fourfold-seed offset 0x64. Fourfold-seed offset 0x54 receives the fourfold seed.

A word loaded at fourfold-seed offset 0x04 becomes the **probe base**. Before probing its byte at offset 0x05, the function writes the first probe link’s low byte at doubled-link offset 0x09 and the eightfold seed at doubled-link offset 0x44.

The byte at **probe base plus 0x05 is read twice**, not retained once:

- The first read supplies the widened value written at first-probe-link offset 0x44. A byte store at fourfold-seed offset 0x09 precedes that word store.
- Before the second read, fourfold-seed offset 0x14 receives the eightfold seed, doubled-link offset 0x15 receives the probe base’s low byte, and doubled-link offset 0x44 receives the fourfold seed.
- After the second read, a byte store at fourfold-seed offset 0x15 precedes loading a word at the second byte’s value plus 0x74.

Call the last loaded word the **selected link**. Intervening writes may alias the probe byte, so the two reads need not agree.

### Constants and the anchor-based repeated region

The selected link supplies two retained scales: the **selected base**, four times that link, and the **selected doubled base**, twice that link.

Further seed-derived updates precede three mixed-width stores of 0x3A: a byte at selected base, a halfword at eight times the selected link, and a word at selected base plus 0x20.

At work-base offset 0x20, the ordered word values are 0x20, 0x2F, a widened byte freshly loaded from work-base offset 0x04, and 0x20 again.

The anchor is then loaded as a word from fixed storage at **0x087FBBBC**, before fixed word **0x60** receives 0x20 and before the repeated-write region. The anchor remains a retained value; its storage is not reread for each repetition.

The repeated region has an initial relationship and a recurring relationship:

- Initially, eightfold-seed offset 0x54 receives the selected base. Anchor offset 0x19 receives the work base’s low byte; work-base offset 0x11 receives the anchor’s low byte; anchor offset 0x34 receives the eightfold seed.
- Later groups use repeated-base offset 0x54 for the selected-base word write, followed by the same two byte writes, followed by an anchor-offset-0x34 word write of the repeated base.

There are no represented intervening calls or data-dependent termination checks. Exact repetition cardinality is **documented_only** here. The individual writes cannot be collapsed merely because ordinary-memory final values appear unchanged.

### Late fixed accesses, snapshots, and fresh rereads

After the repeated region, a word read at fixed address **0xA9** supplies the **fixed snapshot**. The next retained load is a word at selected-base offset 0x74, the **selected payload**. Fixed byte **0x3A** is then written with the low eight bits of eight times the adjusted seed plus 0x30.

Before the later fixed-byte mutations, the function retains:

- The word at selected-doubled-base offset 0x14, the **saved word**.
- The word at work-base offset 0x04.

Calculated-address writes then place the work base’s low byte at selected-doubled-base offset 0x0D, 0x6C at work-base offset 0x08, the anchor’s low byte at work-base offsets 0x0D and 0x09, and the selected doubled base itself at its offset 0x54.

Fixed byte **0x67** receives the fixed snapshot’s low byte. A word read at selected-doubled-base offset 0x44 follows that write and supplies the **late word**. Only then is fixed byte **0x67 reread** for the byte write at fixed address **0x21**. The intervening word read matters if reads have observable effects.

The late word is subsequently byte-stored at work-base offset 0x10 and word-stored at anchor offset 0x54. A byte at selected-doubled-base offset 0x01 receives the low byte of a signed-looking right shift of the late word, with count taken from the work base’s low eight bits. Anchor offset 0x54 is then overwritten with the work base.

A fresh word read at work-base offset 0x40 supplies the word written at work-base offset 0x10. Between that read and write, anchor offset 0x74 receives the previously retained work-base-offset-0x04 word. Anchor offset 0x44 then receives the selected doubled base.

Fixed byte **0x67 is reread again** for a byte store at work-base offset 0x09. Subsequent operations write the work base’s low byte at selected-doubled-base offset 0x09, store the full fixed snapshot at work-base offset 0x44, and load the word at work-base offset 0x54 as the **late pointer**. Fixed byte **0x67 is then reread once more** for another byte store at work-base offset 0x09.

These are three distinct reads after the 0x67 write: one for fixed 0x21 and two for calculated-address stores. Calculated writes between them may alias 0x67; reuse of one cached byte is not equivalent.

### Final mutations and transfer

The selected payload’s low byte is stored at late-pointer offset 0x0D. The saved word is restored to selected-doubled-base offset 0x54, after which work-base offset 0x14 is read as the **work word**. The payload’s low byte is then stored at selected-doubled-base offset 0x11. Work-base offset 0x09 receives the late pointer’s low byte, and work-base offset 0x44 receives the late pointer as a word.

A word loaded from selected-doubled-base offset 0x04 becomes the **terminal base**. A halfword value 0x0065 is written at twice that base before loading its word at offset 0x64 as the **terminal word**.

Late-pointer offset 0x11 receives the work word’s low byte, followed by a word write of decimal 100 at late-pointer offset 0x54. The terminal-base word at offset 0x74 is then retained as the **terminal payload**. A later word read at selected-doubled-base offset 0x64 supplies the **terminal link**.

The final mutations byte-store the terminal base at selected-doubled-base offset 0x09, store the terminal word at terminal-link offset 0x54, and store the terminal link at twice the terminal word.

The unresolved final transfer receives four 32-bit arguments, in order:

1. 0x72.
2. The terminal word.
3. The saved word.
4. The terminal payload.

## Acceptance examples

These are conditional static criteria, not executed tests.

- **Input forwarding:** Input 0x89ABCDEF reaches the first dependency unchanged as a 32-bit pattern.
- **Incoming masks:** An all-ones incoming state produces 0x1FFFF for bits 2–18 and 0x1FFF8 for the shifted low-fourteen-bit argument.
- **Middle extraction:** Extracting bits 8–23 from 0xAB123456 produces 0x1234.
- **Index boundary:** Contributing results 0x7F and 0x80 produce compact indices 508 and zero respectively. The doubled maximum is 1016, not 1022.
- **Read before overwrite:** If fixed-byte-derived base plus 0x54 contains 0x12345678 when loaded, that pattern becomes the seed even when the following store replaces the location.
- **Distinct probes:** If intervening stores change probe-base byte 0x05 from 0x10 to 0x20, the second probe uses base 0x20 for its offset-0x74 word read.
- **Fixed ordering:** The fixed-0x05 read precedes fixed-0x01 mutation; fixed-0x54 mutation precedes fixed-0x15 mutation. The anchor load precedes fixed-0x60 mutation and the repeated region.
- **Fresh global reads:** If an intervening calculated write changes fixed byte 0x67, its next represented reread supplies the changed byte. It need not equal the fixed snapshot’s low byte.
- **Overwritten writes:** Write-observable storage at work-base offset 0x20 must observe 0x20, 0x2F, the widened loaded byte, and 0x20 in order.
- **Partial failure:** A later invalid access imposes no restoration requirement on completed stores.
- **Final transfer:** Reaching the final transfer establishes its four argument sources, not successful completion or normal return.
