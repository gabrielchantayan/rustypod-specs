## Behavior

### 1. Initial write and flag-dependent entry

The first visible operation stores the low 16 bits of base B at base A plus 0x24.

The incoming overflow flag then selects one of two entries:

- **Overflow clear:** invoke F-indirect-01 with the first argument, the second argument, and the 32-bit result of shifting base B left by eight bits. The return value is not explicitly consumed.
- **Overflow set:** skip that call and enter the record-writing section directly.

No preservation guarantees are established for F-indirect-01. In particular, subsequent global reads must not be interpreted as reading values that existed before that call.

### 2. Record-writing loop

With overflow clear, the first normal loop iteration begins with a working word equal to 0x30. Each normal iteration:

1. Takes the top byte of the current working word and zero-extends it to 32 bits.
2. Stores that byte value as a 16-bit quantity at base B plus 4.
3. Selects base B plus 0x32 as the record address.
4. Uses the pre-replacement working word both as a saved word and as the base for a subsequent signed-halfword read.

Consequently, the first normal iteration writes zero at base B plus 4.

With overflow set, the first entry instead uses:

- Base B as the record address.
- The caller’s second argument as the first record word.
- Base B as both the saved word and the signed-halfword read base.

At the common record-writing section, the visible order is:

1. Read a 32-bit word from address 0x8b. This becomes the next working word.
2. Write five consecutive 32-bit words at the selected record address:

| Byte offset | Stored value |
|---:|---|
| 0 | Current second-argument value |
| 4 | Record address itself |
| 8 | Saved word |
| 12 | 0x27 |
| 16 | Word just read from address 0x8b |

3. Read a signed 16-bit value at the selected read base plus 0x27.
4. Evaluate the signed-overflow condition for subtracting 0x2c from the record address.

The loop continues when that subtraction does **not** overflow. This is not an unsigned threshold check and not an ordinary “address less than 0x2c” condition.

For a 32-bit record address, the subtraction overflows precisely when its signed interpretation lies from −2³¹ through −2³¹ + 43, inclusive. Only that condition exits the represented loop.

If another iteration occurs, execution returns to the normal loop prefix, including the halfword store at base B plus 4 and selection of base B plus 0x32 as the record address. The first overflow-set iteration therefore has different address selection from subsequent iterations.

No iteration bound or progress guarantee is established. In the represented state model, repeated use of an unchanged normal record address can prevent termination indefinitely.

### 3. Post-loop access and breakpoint

After loop exit, the routine:

1. Writes one zero byte at record address plus 0x1d.
2. Reads a 32-bit word from the address formed by:
   - multiplying the latest word read from address 0x8b by 0x10000; and
   - adding the current second-argument value minus 0x3b.
3. Executes software breakpoint number 99.

There is no established guarantee that execution resumes after the breakpoint. Everything below is conditional on continuation.

## Acceptance examples

These examples are conditional static obligations, not executed tests.

1. **Initial narrowing.** Given base B with low 16 bits equal to 0xabcd and a writable destination, the first visible store writes halfword 0xabcd at base A plus 0x24. Upper address bits do not enter that stored halfword.

2. **Overflow-clear entry.** If the incoming overflow flag is clear and F-indirect-01 returns, the first normal iteration writes halfword zero at base B plus 4 before writing the five-word record at base B plus 0x32.

3. **Overflow-set entry.** If the incoming overflow flag is set, F-indirect-01 is skipped. The first record begins at base B, and its first word is the caller’s second argument rather than a top-byte-derived replacement.

4. **Subtraction-overflow boundary.** A record address of 0x80000000 satisfies the loop-exit overflow condition for subtraction by 0x2c. A record address of 0x8000002c does not. A small positive address also does not exit merely because it is less than 0x2c.

5. **Breakpoint ordering.** If execution reaches the breakpoint, the byte-zero store and derived 32-bit read have already occurred. The pointer-like store following the breakpoint is not required unless execution resumes.

6. **Split-result write.** If F-bea9de7a03d5 returns lower word 0x11223344 and upper word 0x2000, the next visible store writes 0x11223344 at address 0x2008, provided that access is permitted.

7. **Aliased reread.** The halfword read after the byte store at working base plus L1 must observe the intervening stores if they overlap its location. It must not be replaced unconditionally with 0x0056.

8. **Final forwarding.** If all preceding operations complete and F-indirect-17 returns a 64-bit value, the represented function returns that value without a visible subsequent transformation.
