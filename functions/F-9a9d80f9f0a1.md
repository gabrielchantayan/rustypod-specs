# F-9a9d80f9f0a1

## Purpose

F-9a9d80f9f0a1 initializes three address-based object regions, conditionally establishes two shared objects, and invokes operations associated with two of the initialized regions. A nonzero third argument enables an additional operation on each of those regions.

On normal completion, it returns the address 80 bytes before the result of the second invocation of F-ff4dff756de0.

The apparent intent is construction of a composite object and attachment of shared resources. That interpretation is inferred. The established contract consists of the explicit reads, writes, branches, calls, and address calculations below; application-level types and operation meanings are not established.

## Behavior

### Initial storage and first region

The function calls F-477fcc5fcff8 without explicit arguments and takes its result as A.

Only after that call returns does it read the global location supplying T0. It writes that sampled four-byte value at A.

It then calls F-ff4dff756de0 with A + 36 bytes. The result becomes B. The body does not require or check that B equals the argument supplied to this dependency.

After this first initializer returns, the function reads the separate global location supplying T1 and writes the sampled value at B. It then writes the single byte `1` at B + 40 bytes.

The function next calls F-ff4dff756de0 with B + 44 bytes. Its result becomes C. Equality between this result and the supplied address is again unestablished.

### Second region and shared-state base

After the second initializer returns, the function reads the global shared-state-base location and retains that value as G.

After capturing G, it reads the separate global location supplying T2. It then performs these writes in order:

1. Write T2 at C as a four-byte value.
2. Write the single byte `1` at C + 40 bytes.
3. Write the four-byte integer `−1` at C + 44 bytes.

Thus, T0, T1, and T2 are sampled at different points separated by dependency calls. Dependency effects may influence later samples. T2 is specifically sampled after G, not before it.

G is retained for both shared-slot locations. The function does not reload the global shared-state-base location later.

### First shared-object establishment

The function reads Slot A and compares the value with zero.

If the tested value is nonzero, it skips establishment entirely. It does not validate the existing address or initialize the object it designates.

If the tested value is zero, the following operations occur in order:

1. Call F-8157a180d901 with the explicit integer argument `8`.
2. Call F-b45f9214930f without explicit arguments; use its result as the new shared-object address.
3. Read the first shared-object table-value global and retain that value as TA-call.
4. Read that same global again, obtaining TA-store.
5. Write TA-store into the first four bytes of the new shared object.
6. Publish the new shared-object address by writing it into Slot A.
7. Read the indirect-call target at byte offset 24 from the table address retained as TA-call, then invoke that target without explicit arguments.

The first table-value read caches the table address, not the eventual call target. The target selection occurs after object initialization and publication.

The two table-value reads must remain distinct in the behavioral contract. If unspecified external mutation changes the global between those reads, TA-call and TA-store may differ. The stored table value does not replace the cached table address used for the offset-24 call.

The argument `8` is established. Interpreting it as an allocation size, or interpreting the two direct calls as a combined allocation operation, is inferred intent. No such dependency contract is supplied.

### First attachment and optional operation

After either skipping or completing first-slot establishment, the function makes an indirect attachment call associated with L:

- Read the four-byte table address at L.
- Select the target at table byte offset 84.
- Pass L and a fresh four-byte read of Slot A as explicit arguments.

The Slot A value used for attachment is not cached from the zero test or publication. In particular, the offset-24 dependency may have changed it.

The supplied representation does not establish the relative evaluation order of the separate operand reads within this call expression. It does establish that they belong to this attachment call after any selected establishment sequence.

If the third argument is nonzero, the function subsequently:

- Reads the table address at L again.
- Selects the target at byte offset 92.
- Calls it with L and the explicit integer `1`.

The optional call therefore uses a table read made after the attachment call. An attachment dependency may change the table used for this later selection.

If the third argument is zero, this optional table lookup and call are skipped.

### Second shared-object establishment

Only after the first attachment and any selected first optional operation does the function read and test Slot B.

If the tested value is nonzero, second-slot establishment is skipped without validation.

If it is zero, the function performs the corresponding sequence:

1. Call F-8157a180d901 with `8`.
2. Call F-b45f9214930f without explicit arguments; use its result as the second new shared-object address.
3. Read the second shared-object table-value global and retain that value as TB-call.
4. Read the same global again, obtaining TB-store.
5. Write TB-store into the first four bytes of the new shared object.
6. Publish its address into Slot B.
7. Read the target at byte offset 24 from the table designated by cached TB-call and invoke it without explicit arguments.

TB-call and TB-store are independently sampled. Their equality is not guaranteed under unspecified external mutation.

Publication precedes the indirect call. That call uses the cached first table-value read, not the second read or a later reload from the new object.

### Second attachment and optional operation

The function then makes an attachment call associated with C:

- Read the table address at C.
- Select the target at table byte offset 84.
- Pass C and a fresh read of Slot B.

If the third argument is nonzero, it subsequently reads the table address at C again, selects the target at byte offset 92, and calls it with C and `1`.

The second slot’s zero test is not an entry-time snapshot. All first-region calls precede it and may affect its outcome. Likewise, the final optional call does not reuse the table previously read for the second attachment.

### Normal return

After all selected calls return normally, the function returns R, equal to C − 80 bytes.

L is derived from C, not taken directly from B. R is also derived from C, not taken directly from A. Relationships among these addresses require additional assumptions about initializer results.

## Side effects

### Direct memory effects

The body directly performs the six initial object-region writes listed in the interface. For each selected shared-object establishment, it additionally writes one four-byte table field and publishes one four-byte address into the corresponding shared slot.

It does not explicitly initialize the remaining bytes of any region or the second four-byte word of either newly obtained shared object.

The direct global reads include the three separately timed initialization-value reads, one shared-state-base read, and two reads of the corresponding shared-object table-value global for each selected establishment.

### Publication and failure visibility

Each newly obtained shared-object address becomes visible through its slot before the offset-24 indirect call.

There is no visible rollback, cleanup, or transactional boundary. If a later dependency fails, does not return, or transfers control abnormally, preceding stores and publications have already occurred.

No explicit checks handle invalid dependency results, insufficient storage, unusable table addresses, invalid targets, stale slot contents, or address wraparound. The body provides no explicit error code or recovery path.

### Dependency effects and aliasing

No direct or indirect dependency is assumed to preserve globals, table fields, shared slots, or memory lifetimes. Dependency return values ignored by this body do not establish absence of side effects.

Changing the global location that originally supplied G does not redirect later accesses: the retained G still supplies both slot addresses. Changing memory at G can affect later slot reads.

Non-aliasing is not established. Regions, shared objects, slots, globals, and table storage may overlap unless an external contract excludes that possibility. Consequently, an explicit store or dependency effect may alter data read later. The listed order remains significant even when an earlier value is overwritten.

No synchronization is visible. Separate reads do not establish atomicity, race safety, or a supported concurrent-mutation model.

### Ownership and lifetime

No explicit deallocation occurs. Neither obtaining an address nor returning R establishes allocation ownership or transfer of ownership.

Ownership, retention, and release obligations for all regions, shared objects, and table storage are unspecified. Normal execution requires each address to remain usable for every later access that actually occurs.

## Acceptance examples

These are conditional consequences of static evidence, not executed tests. Each assumes valid accesses, compatible call targets, normal dependency returns, and the stated conditions.

### Both slots populated; third argument zero

If both slots are nonzero when individually tested:

- Perform all initial region writes, sampling T0, T1, and T2 at their specified times.
- Skip both establishment sequences, including their table-value-global reads.
- Invoke F-U02 before F-U05.
- Invoke neither F-U03 nor F-U06.

### Both slots zero; third argument nonzero

If each slot is zero when tested and intervening effects do not change the relevant values:

- Establish the first shared object using two reads of its table-value global.
- Store the second sampled value and publish the object before F-U01.
- Resolve F-U01 through the first sampled table address.
- Invoke F-U02, then F-U03 with `1`.
- Only afterward test and establish the second slot using its own two-read sequence.
- Invoke F-U04 after publication, then F-U05 and F-U06.
- Return C − 80 bytes.

A third argument of `−1` selects the same optional calls and explicit arguments as a third argument of `1`.

### A shared table-value global changes between reads

Conditionally, suppose unspecified external mutation causes the first establishment’s two reads to produce different valid table addresses.

Required behavior:

- Preserve the first sampled address as TA-call.
- Store the second sampled address, TA-store, in the new shared object.
- Publish that object.
- Select F-U01 at offset 24 from TA-call, even though the object contains TA-store.

The corresponding rule applies independently to TB-call, TB-store, and F-U04. This example does not establish that concurrent mutation is safe or supported.

### Dependencies change later initialization samples

Suppose the first initializer changes the global supplying T1, and the second initializer changes the global supplying T2.

The stores at B and C use the values sampled after their respective initializer returns, not values captured at entry. G is captured after the second initializer and before the T2 read.

Similarly, a change to the T0 global made by F-477fcc5fcff8 precedes the T0 sample.

### First-region processing changes Slot B

Suppose Slot B initially contains zero, but F-U02 writes a nonzero value there, and any selected F-U03 leaves it nonzero.

The later Slot B test observes the then-current value and skips second establishment. F-U05 receives the value read for its own argument, not an entry-time snapshot.

### An initialization call replaces its published slot

Suppose F-U01 replaces Slot A with another valid address.

Publication of the original address still precedes F-U01. F-U02 receives a fresh Slot A read and is not required to receive the originally published address.

### An attachment changes its receiver’s table

Suppose F-U02 changes the table field at L and the third argument is nonzero.

F-U03 is resolved using the table read after F-U02. The same rule applies to F-U05 and F-U06 at C.

### Initializers return their input addresses

- C equals A + 80 bytes.
- L equals B.
- R equals A.
