# F-9a305cc01ef7

## Purpose

F-9a305cc01ef7 selects between a bulk operation followed by structural reset writes and a repeated per-element operation. It writes 32-bit values through its first argument and returns a separate 64-bit value assembled from two 32-bit words.

The visible operations suggest range removal from a structure with a header or sentinel and a whole-structure shortcut. That is **inferred intent**, not an established abstract contract. The available evidence establishes accesses, dependency calls, branch conditions, and result construction. It does not establish that any dependency removes elements, destroys objects, or releases memory.

All behavior below concerns normal execution unless otherwise stated. Dependency effects are not restricted to the fields directly accessed by this function.

## Behavior

### Initial output and comparison

Before calling a dependency, the function reads context offset 16 and writes that 32-bit value to the output address.

It then reads context offset 16 again and reads offset 8 of the header reached by that second lookup. The resulting word becomes a temporary comparison operand. The second header lookup is not replaced by the value used for the initial output write.

This distinction is observable under aliasing. For example, if the output overlaps storage used by the subsequent header-field access, the initial write may alter the comparison operand.

Two return-related scratch words are initialized before the first comparison:

- The context scratch word receives the original context address.
- The element scratch word receives the original output address.

F-425cd6ff9d42 is then called with the cursor address and the address of the temporary comparison word. Its 32-bit result is tested for zero versus nonzero.

A zero result skips all remaining bulk-eligibility checks. A nonzero result enables the second eligibility comparison.

### Bulk eligibility

When the first comparison is nonzero, the function reloads context offset 16 and places that header address in a temporary word. It calls F-425cd6ff9d42 with:

1. The boundary value.
2. The address of that temporary word.

Only if this second result is nonzero does the function read context offset 20.

The bulk path requires both:

- A nonzero second comparison result.
- A nonzero word read from context offset 20.

Consequently:

- A zero first result skips the second comparison and the eligibility read.
- A zero second result skips the eligibility read.
- A zero state word prevents the bulk path even when both comparisons are nonzero.

The temporary operands supplied by address may be modified by the comparison dependency. Their post-call contents are not used as the header addresses for the bulk operation or reset.

These early comparisons accept any nonzero result. Their condition differs from the loop’s exact-one stopping condition.

### Bulk operation and reset

On the bulk path, the function reloads the header address from context offset 16 and reads that header’s offset-4 word. It calls F-2e620b5c6f06 with the original context address and that word.

After the call returns, direct reset writes occur in this order:

1. Assign a current header address to offset 8 of a current header.
2. Clear offset 4 of a current header to zero.
3. Assign a current header address to offset 12 of a current header.
4. Clear context offset 20 to zero.

Header accesses use renewed reads of context offset 16. The header used before F-2e620b5c6f06 is not retained as the mandatory target of later reset writes. The dependency may replace the context’s header field, provided subsequent accesses remain valid.

Within either self-link assignment, the supplied representation does not establish the relative evaluation order of the header reads used for the destination and stored value. The ordering between the four listed assignments is established. Under ordinary stable, distinct storage, the first and third writes are self-links; aliasing or intervening state changes must not be silently excluded from a stronger interpretation.

After clearing context offset 20, the function reloads context offset 16 once more. It captures that header address, writes it to the original output address, and returns it as the high word above the original output address.

The captured high word is not reloaded after the final output write. If that write changes aliased context storage, the returned high word still contains the captured value.

The loop does not execute on this path.

### Repeated operation

If the bulk path is not taken, F-425cd6ff9d42 is called with the cursor address and boundary value before each possible iteration.

The loop stops only when the comparison result is exactly one:

- One exits.
- Zero enters the body.
- Any other nonzero value also enters the body.

Each iteration performs the following ordered operations:

1. Read and save the first 32-bit word at the cursor address.
2. Call F-d92e879159c4 with the cursor address.
3. Replace the element scratch word with the saved pre-call cursor word.
4. Call F-12dea72fc587 with the address of the context scratch word, the original context address, and the address of the element scratch word.
5. Write the current context scratch word to the original output address.
6. Call the comparison dependency again to decide whether another iteration occurs.

Thus F-12dea72fc587 receives the cursor word captured **before** F-d92e879159c4 runs, not a fresh word read afterward.

The context scratch word is initialized once. It is not restored between iterations. Changes made through its address can carry into subsequent iterations and the return.

The element scratch word is replaced from the current iteration’s saved cursor word after F-d92e879159c4 returns. F-12dea72fc587 may then modify it.

If the first loop comparison returns one, neither loop-body dependency runs. Only the initial direct output write has occurred, but comparison calls may have changed that storage.

After any body write, the next comparison call runs before a normal loop exit. Therefore, even the last body write is not a guarantee of the value remaining in output storage when the function returns.

No iteration bound or progress guarantee is visible.
