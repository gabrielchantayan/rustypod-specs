# F-17cd1c3347c8

## Purpose

The supplied representation establishes a low-level state transformation, not an application-level purpose. In particular, it does not establish that the first argument denotes a complete object, that the second argument is merely a numeric parameter, or that the calls form a recognized protocol.

The apparent two-argument interface is incomplete: execution also depends on incoming condition flags, three incoming register values, auxiliary call-result channels, global memory, and writable stack storage.

### 4. Common phase

1. Set the selector to the current first argument shifted left by one.
2. Calculate a pending word from the current second argument: multiply it by 2, multiply by the current second argument, then multiply by 2, retaining 32 bits throughout. Equivalently, its final bit pattern is four times the square modulo \(2^{32}\).
3. **Call F-000000000008.** Its target is the current call-target base plus `0xAAA`. Its explicit argument is the current first argument plus the third incoming register value.
4. Read the 32-bit call-argument global.
5. **Call F-000000000009**, passing that captured global value.
6. **Call F-00000000000a.** No explicit arguments are shown.
7. Read and test the zero-tested global.

If that global is zero:

- Arithmetic-right-shift the auxiliary output associated with F-00000000000a by 9.
- Shift that 32-bit result left by one to form the lower return word.
- Read the return-base global and subtract `0x54` to form the upper return word.

If that global is nonzero:

- Replace the second argument with the auxiliary output associated with F-00000000000a.
- Set the call-target base to `0x08573459`.

The current first argument remains in effect across this continuation. The selector and pending word calculated at the start of the common phase are reused by the next full iteration phase.

## Acceptance examples

These are conditional static acceptance criteria, not executed tests. Each assumes valid memory, valid call targets, returning dependencies, and the stated 32-bit arithmetic model.

1. **Equal incoming flags and immediate common-phase exit**  
   Given equal negative and overflow flags, and a zero global when the common phase tests it:
   - The entry halfword write occurs first.
   - The three common-phase calls occur in order.
   - No full-iteration call occurs.
   - No conditional common-phase word write occurs.
   - The lower return word derives from the final common-phase auxiliary output.

2. **First full-iteration exit at the sign-bit boundary**  
   Given unequal incoming flags and a second argument of `0x00007FF6`, adding 10 produces `0x00008000`. Its product with `0x10000` is `0x80000000`, interpreted as negative. The pending word is written before returning. The result-derived halfword write and subsequent full-phase calls do not occur.

3. **Adjacent candidate does not take that exit**  
   With a second argument of `0x00007FF5`, the candidate is `0x00007FFF`; its shifted product is `0x7FFF0000`. Execution continues past the first exit test, assuming preceding calls return.

4. **Truncation before signed right shift**  
   If the candidate is 8, multiplication by `0x10000000` produces `0x80000000`. Arithmetic right shift by 9 produces `0xFFC00000`, not the positive value that an untruncated wider calculation would produce.

5. **Negative common-phase auxiliary output**  
   If the zero-tested global is zero and the final auxiliary output is `0xFFFFFFFF`, arithmetic right shift by 9 remains `0xFFFFFFFF`. The lower return word is therefore `0xFFFFFFFE`.

6. **Nonzero common-phase continuation**  
   If the common-phase second argument is 3 and the zero-tested global is nonzero, the pending word is 36 and is written at address `0x3A`. The next full iteration uses the final auxiliary output as its second argument and retains the selector calculated from the current first argument.
