# F-8a2270f25b51

## Purpose

F-8a2270f25b51 encodes the magnitude of a signed 32-bit integer as a variable-length, most-significant-byte-first byte sequence in storage referenced by a caller-supplied descriptor. It records the resulting length in the descriptor.

For inputs whose nonnegative magnitude is representable as a signed 32-bit integer, the encoding omits leading zero bytes. Zero produces length zero and no payload writes. At most four payload bytes are written.

The routine also writes a descriptor marker. It initially writes `2`, before any buffer-related dependencies run. When negative-input processing is reached, it subsequently reads an external 32-bit value and writes that value to the marker. The external value is not established as different from `2`; the marker is therefore not a guaranteed sign discriminator.

The routine conditionally invokes dependencies associated with obtaining and preparing storage. Their ownership, memory-management, and descriptor-preservation contracts are unavailable.

Successful completion returns a 64-bit composite containing the original integer’s 32-bit bit pattern in the upper half and `1` in the lower half. The explicit failure path returns zero if its reporting dependency returns normally.

The first word is not established as a conventional capacity field. Its entry value selects a buffer path, but its successful exit value is a byte count from zero through four. The routine does not directly set this word to `5` when obtaining storage.

### Preconditions for ordinary completion

The descriptor must support the reads and writes performed on the selected path. In particular, the marker word must be writable even if the routine subsequently takes the explicit failure path.

If payload bytes are written, the current buffer address must support those writes. A nonzero pointer alone does not establish valid or sufficiently large storage.

For the ordinary encoding guarantees, descriptor storage, payload storage, and internal execution state must not overlap in a way that changes later reads or corrupts state. Dependencies and concurrent actors must not invalidate storage needed by subsequent operations. These are conditions on the guarantees, not preservation promises made by the dependencies.

The routine performs no explicit descriptor-null check, buffer-size validation, or overlap check. Invalid addresses and insufficient storage do not select a specified error return.

### Outputs

On successful completion under the ordinary storage conditions:

- The first descriptor word is the payload length, from zero through four.
- The first recorded-length bytes at the selected buffer contain the magnitude encoding.
- The successful 64-bit return is the original integer’s unsigned 32-bit bit pattern multiplied by `2^32`, plus `1`.

Marker behavior is defined by writes, not by an unconditional final-value guarantee:

- The routine initially writes `2`.
- For nonnegative input, it performs no subsequent direct marker write. A final marker of `2` requires preservation by invoked dependencies and absence of overlapping writes or other mutation.
- When negative-input processing is reached, it reads an external 32-bit value and writes that value to the marker. Under nonoverlapping storage and no subsequent mutation, that sampled value is the final marker.
- The sampled external value may equal `2` or a value previously written by a dependency.

For example, successful encoding of `−1` returns `0xFFFFFFFF00000001`, not the scalar value `1`. Successful encoding of zero returns `0x0000000000000001`.

On the explicit failure path, the return is `0x0000000000000000` if the reporting dependency returns normally.

## Behavior

### Initial state changes

Before inspecting the descriptor’s first word, the routine writes `2` to the marker at offset `4`.

The original integer is retained separately for construction of the successful return value. Magnitude processing uses a working value and does not ordinarily change this retained copy.

The initial marker write occurs before all buffer-path dependencies and before either explicit failure condition. Failure therefore does not imply an unchanged descriptor.

### Buffer-path selection

The routine reads the first descriptor word as an unsigned 32-bit value.

If that value is at least `5`, it skips the three buffer-related dependencies and proceeds to the common buffer-pointer check. Values with the high bit set are still at least `5` under this unsigned comparison.

If the value is below `5`, the following observable order applies:

1. Read the descriptor’s buffer-pointer word.
2. If that value is nonzero, invoke F-5990a26eaaa3 with no explicit arguments.
3. Invoke F-43da6b23bd44 with the arguments `5`, `0`, and `0`, in that order.
4. Write its 32-bit return value into the descriptor’s buffer-pointer word.
5. If the returned value is zero, take the explicit failure path without invoking F-EXT-01.
6. Otherwise, invoke F-EXT-01 with the returned value followed by `5`.
7. Proceed to the common buffer-pointer check.

F-EXT-01 is a document-local opaque identifier for the dependency without a supplied published ID.

The immediate zero-result decision uses the value returned by F-43da6b23bd44. It is not based on a later descriptor read. The common check, by contrast, reads the descriptor’s buffer-pointer word after F-EXT-01.

Consequently, a nonzero return from F-43da6b23bd44 does not guarantee that the common check succeeds. F-EXT-01 could change the descriptor through an alias or shared state; no preservation contract is supplied.

The write of the returned pointer also replaces any descriptor-pointer change made by an earlier dependency, provided execution reaches that write normally.

### Common buffer-pointer check

The routine reads the descriptor’s current buffer-pointer word.

If it is zero, the routine takes the explicit failure path. Otherwise, it continues to sign processing and encoding.

This requirement also applies to integer zero. Although zero needs no payload stores, a zero buffer pointer still causes failure.

### Sign processing

For a nonnegative integer, the working value is unchanged. The routine performs no marker write after the initial write of `2`.

For a negative integer, it first negates the signed 32-bit working value. It then reads an external 32-bit marker value and writes that value to descriptor offset `4`.

For inputs from `−2,147,483,647` through `−1`, the positive magnitude is representable in the working type.

For `−2,147,483,648`, the positive mathematical magnitude is not representable as a signed 32-bit integer. The supplied representation does not settle the underlying execution semantics of this negation. An unconditional result for that input is therefore not established.

The negative-path marker write occurs after all buffer-path dependency calls. It replaces their marker changes when that write is reached normally. It does not prove that the resulting marker differs from the nonnegative-path marker.

### Byte construction and output order

For representable nonnegative magnitudes, the routine extracts the least significant eight bits of the working value, then shifts the working value right by eight bits. Extraction stops when the remaining value is zero or four bytes have been extracted.

Zero yields no extracted bytes.

The routine writes the extracted bytes in reverse extraction order, starting at output offset zero and increasing the output offset by one for each byte. Thus the payload is most-significant-byte-first, without leading zero bytes.

The encoding step writes:

- Zero through four individual payload bytes.
- No terminator.
- No padding to a fixed width.
- No direct payload bytes beyond the recorded length.

Buffer-related dependencies may nevertheless have modified bytes outside that range.

The payload-store expression refers to the descriptor’s buffer pointer. The supplied representation does not justify a guarantee that one buffer base is captured and used for every store if descriptor/payload overlap or other mutation changes that pointer. Such cases are outside the ordinary encoding guarantees.

After every payload store has completed, the routine writes the number of bytes written to the first descriptor word. For zero, it performs this length write without any payload stores.

### Completion and failure

After recording the length, the routine returns the successful composite containing the retained original input and lower word `1`.

Either explicit failure condition leads to an invocation of F-4fc89ec41a6d with `13`, `118`, and `65`, in that order. The routine returns zero if that invocation returns normally.

There is no direct rollback, retry, restoration of the previous buffer pointer, or successful-length assignment on the failure path. Dependency effects remain subject to their unknown contracts.

## Side effects

Established direct descriptor and payload effects are:

- An initial marker write of `2`.
- On the below-`5` path, replacement of the buffer-pointer word with F-43da6b23bd44’s return value, including zero.
- On the negative-input encoding path, a read of the external marker followed by a marker write.
- Zero through four payload-byte writes.
- A final length write on success.

The routine can invoke dependencies before encoding, and it invokes the reporting dependency on explicit failure. These calls may have additional effects not visible in the supplied representation.

Failure is not transactional. In particular, when F-43da6b23bd44 returns zero, the old descriptor pointer has already been replaced with zero before failure reporting. The routine does not directly restore the old pointer or first word. The reporting dependency could itself change either field.

Ownership remains unresolved:

- F-5990a26eaaa3 receives no explicit old-buffer pointer. Its invocation does not prove that the old storage is freed.
- F-43da6b23bd44 returns a value used as an address, but allocation and ownership transfer are not established.
- F-EXT-01 receives an address-like value and `5`; this does not establish clearing, initialization, validation, or ownership transfer.
- The routine does not establish who must eventually release the resulting storage.

A successful call records a first-word value no greater than four. If that descriptor is passed again without intervening changes, the next call takes the below-`5` buffer path, even if its existing buffer is large enough.

It performs no payload writes or direct successful-length write. Final descriptor contents depend on the reporting dependency.

- **Preparation clears the descriptor pointer:** If F-43da6b23bd44 returns nonzero but F-EXT-01 leaves the descriptor pointer zero, the common check causes failure. Encoding is not reached.

- **Dependency changes a nonnegative marker:** Suppose the below-`5` path obtains usable storage, F-EXT-01 leaves the marker as `7`, and input `256` is encoded without overlap or further mutation. The result has length two, payload `01 00`, and marker `7`. The routine does not restore `2`.

- **External marker equals `2`:** If input `−256` reaches encoding and the sampled external value is `2`, the routine writes marker `2` and emits `01 00`. The marker alone does not distinguish this result from positive `256`.

- **Zero after buffer preparation:** If dependencies leave a nonzero usable pointer and input is zero, the routine performs no payload stores and records length zero. Earlier dependency writes to the buffer or marker are not undone.

- **Minimum signed integer:** If execution uses wrapping 32-bit negation and sign-propagating right shifts, the four-byte extraction bound yields `80 00 00 00`, length four, and the sampled marker. This remains conditional on those arithmetic semantics.
