# F-46f20b02342c

## Purpose

- If either status observation is nonzero, return the 32-bit value `1`.
- If both status observations are zero and the required lookups succeed, complete the remaining calls and return the saved 32-bit result of F-273364acf8ff.

The first status observation is a **32-bit field read followed by narrowing to an 8-bit character value**. The second is an explicit one-byte access. These are not interchangeable descriptions of memory access.

### Status gate

The first status operation reads the represented 32-bit field at `0x20` and narrows its value to an 8-bit character. The function tests this narrowed value for equality to zero.

- If the narrowed value is nonzero, return `1`. The explicit byte access at `0x41` is skipped.
- If the narrowed value is zero, read the character-sized value at `0x41`.
- If that second value is nonzero, return `1`.
- Continue only if both tested values are zero.

Thus a nonzero complete field at `0x20` does not necessarily cause an early return. Under 8-bit truncation, for example, field value `0x00000100` narrows to zero.

Whether a nonzero character is interpreted as signed or unsigned does not change its zero/nonzero classification under that narrowing model.

The gate uses values observed after the initial operation and optional update, not an entry-state snapshot. The static representation does not establish a particular physical load instruction for the first observation or a byte-order-independent correspondence between that observation and the byte located at `0x20`.

## Acceptance examples

These are conditional requirements derived from static evidence, not executed tests. Unless stated otherwise, all reached dependencies return normally and all required accesses and indirect targets are valid.

1. **First narrowed value is nonzero.**  
   The represented field read at `0x20` yields `0x00000001`. Its narrowed character is nonzero, so the function returns `1`, skips the explicit byte access at `0x41`, and does not begin the lookup sequence. This example specifies a field value, not a memory-byte arrangement.

2. **Nonzero full field, zero narrowed value.**  
   Under the represented 8-bit truncating interpretation, the field value is `0x00000100`. The narrowed value is zero, so the `0x41` byte must be read. If that byte is `2`, the function returns `1`; if it is zero, lookup begins. Testing the entire field for nonzero would violate this behavior.

3. **Optional update precedes early return.**  
   Control is `2`, and either status test subsequently causes an early exit. F-76b1c50b12f7 and F-22be49cfb47c still run, and the latter result is written at `0xF0` before the status decision.

4. **Zero control skips only the optional sequence.**  
   Control is zero. The initial marker writes and F-273364acf8ff still occur, but the two optional calls and direct `0xF0` write do not. Earlier dependency effects on that field remain possible.

5. **Conditional object work is skipped.**  
   Both status tests are zero, the first lookup succeeds, the `0xE8` result is nonnull, and its `0x1C` call returns zero. F-682adfd5a561 is skipped. Finalization and final dispatch still occur, and the saved initial result is returned even if zero.

6. **Handled null result.**  
   The `0x1C` call returns nonzero, but F-682adfd5a561 returns null. F-8157a180d901 receives `0x1C`, F-2606ad6d534d runs next, and its result is passed to the earlier object’s `0x2C` entry. Normal completion remains possible.

7. **Nonnull conditional result.**  
   F-682adfd5a561 returns a valid nonnull object. Its `0x58` entry is invoked. The handled-null branch is skipped.

8. **Control is not normalized.**  
   With control `2`, final dispatch receives `2` and `3` in the control-derived positions. With `0xFFFFFFFF`, those positions contain `0xFFFFFFFF` and `0xFFFFFFFE`.

9. **Explicit lookup failure.**  
   A zero first lookup result or null `0xE8` result reaches F-a817d8d58c10 without first performing finalization. Initial marker writes and any enabled optional update have already occurred.
