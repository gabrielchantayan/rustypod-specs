# F-58207c78719b

## Purpose

F-58207c78719b performs a fixed, access-order-sensitive transformation of memory, exposes partially populated stack storage to an indirect dependency, invokes F-cdec09f5d432 if that dependency returns, and then reaches a terminal operation.

No application-level purpose is established. In particular, the repeated field offsets and address-like values do not prove that the routine implements a list, allocator, serializer, constructor, or ownership protocol.

This contract describes established static behavior. It does not establish that an ordinary caller can satisfy the routine’s unusual entry-state and address-validity requirements.

### Width and address model

The visible accesses use 8-bit bytes, 16-bit halfwords, and 32-bit words. Halfword reads used in address calculations are signed: their interpreted range is −32,768 through 32,767.

Byte and halfword stores retain the low eight or sixteen bits, respectively. A signed halfword subsequently stored as a word is sign-extended.

Offsets denote byte displacements. Object extents, alignment requirements, byte order, and valid address mappings are unknown. A zero or negative address-like value receives no special handling.

The displayed integer operations are 32-bit operations, but this does **not** establish portable modulo-\(2^{32}\) semantics for signed overflow. Address sums, products, doubled values, and left shifts require a separately established execution model where their behavior is material.

### Result and termination

The incoming target is called first. F-cdec09f5d432 is reached only if that call returns. The terminal operation is reached only if F-cdec09f5d432 returns.

No validation or explicit error result precedes the memory accesses.

## Behavior

### Interpretation of the contract

The roles below distinguish captured values from later observations. Unless a fresh read is specified, a role denotes the value already obtained, not a request to reread its original location.

All effects are conditional on execution reaching them. An invalid earlier access can prevent every later effect. Aliasing can alter later observations and derived addresses; no disjointness assumption is part of the interface.

The descriptions are divided into behavioral regions. Their order is binding. Within each region, the stated read-before-write relationships and repeated accesses are also binding.

### Entry mutations and selector establishment

The first externally visible write is a byte at second-argument offset `0x15`, containing the initial link’s low byte. The next write stores the complete second argument at initial-link offset `0x44`.

A word from anchor offset `0x74` supplies an intermediate base. Before its offset-`0x44` word is read, the routine writes the anchor’s low halfword at the sum of that base and the third argument. Consequently, an overlap between this halfword destination and the subsequent word source can affect the word obtained. That word is the **initial carried word**.

The carrier is then written into carrier offset `0x54`.

The first selector supplies a captured base for the next region. Anchor offset `0x44` receives a value referenced directly from the first selector’s storage. These are separate references in the static representation; their equality must not be assumed if that storage can change between evaluations. The same distinction applies when the second and third selectors are established later. The representation alone does not establish the number of physical machine loads.

The captured first-selector base receives the initial carried word at offset `0x14`. Carrier offset `0x11` then receives the low byte of the carrier shifted left once.

### Two selector-linked update regions

The next two regions have a common relationship pattern, but different surrounding accesses:

| Contract role | First region | Second region |
|---|---|---|
| Captured selector base | First selector | Second selector |
| Incoming base | Carrier | First peer |
| Forward value | Word at incoming-base offset `0x44` | Word at incoming-base offset `0x44` |
| Signed displacement | Signed halfword at incoming base plus selector base | Same relationship |
| Peer | Word at signed-displacement offset `0x14` | Same relationship |
| Carried word | Initial carried word | Word captured from first-selector offset `0x44` |
| Outgoing carried word | Word read from first-selector offset `0x44` near the region’s end | Word read from second-selector offset `0x44` near the region’s end |

“First peer,” “second peer,” and the two forward values mean the values obtained in the corresponding region. They do not imply valid pointers or a linked-data-structure invariant.

For each region, the following relationships hold:

- The forward value is stored into its own offset `0x54` before the payload-related stores.
- The payload is stored at selector base plus carried word.
- Selector offset `0x14`, which initially held the carried word, is subsequently overwritten with the forward value.
- A fresh word read at payload offset `0x44` supplies the byte written at selector offset `0x0D`.
- Peer offset `0x0D` receives the forward value’s low byte.
- Selector base plus signed displacement receives the forward value’s low halfword.
- The outgoing carried word is read from selector offset `0x44` after these writes.
- The peer is then stored into its own offset `0x54`.

The payload-offset read occurs after the selector’s offset-`0x14` overwrite. It is not an entry-time snapshot. The outgoing carried-word read likewise observes any preceding overlapping writes.

The first region has these additional ordering requirements:

- First-argument offset `0x64` is read before the forward value, signed displacement, and peer are obtained.
- Those latter three observations occur in that order.
- The forward self-store follows the peer read.

After the first region, the second selector is captured. First-forward offset `0x44` receives a direct reference to the second selector’s external storage. The captured second-selector base receives the outgoing carried word at offset `0x14`.

First-peer offset `0x11` initially receives the low byte from the earlier first-argument offset-`0x64` read. A **fresh** read of that same argument-relative word then precedes the second forward-value read and second signed-halfword read.

Before the second peer is obtained, three further writes occur in this order:

1. The first peer is stored at offset `0x54` from the carried word.
2. First-peer offset `0x11` receives the fresh argument-relative byte.
3. Second-forward offset `0x44` receives the captured second-selector base.

The second peer read and the common update relationships then follow.

The two argument-relative reads and the two first-peer byte stores are distinct events. Even when their addresses coincide or their values are equal, the contract does not collapse them.

### Third selector and arithmetic traversal

After the second peer’s self-store, the third selector is captured. Second-forward offset `0x44` receives a direct reference to the third selector’s external storage. Captured-third-selector offset `0x14` receives the second region’s outgoing carried word.

Second-peer offset `0x11` receives the low byte from the fresh first-argument offset-`0x64` read. Only afterward are these obtained, in order:

- A word from second-peer offset `0x44`, called the **multiplicand**.
- A signed halfword from second peer plus captured third-selector base, called the **factor**.

The factor becomes both arithmetic input and address-like input. Before traversal, the following pair occurs **twice**, without being merged:

- A word store of the sign-extended factor at factor offset `0x54`.
- A byte store of the second peer at third-selector offset `0x11`.

The traversal has four dependent word observations. Its initial address is the factor–multiplicand product plus `0x44`. The returned word supplies the base for an offset-`0x74` read; that result supplies the base for an offset-`0x14` read. The resulting traversal node supplies a further word from its own offset `0x14`, called the **saved child**.

The saved-child read precedes overwriting traversal-node offset `0x14` with the second peer shifted left once. The later traversal therefore uses the captured child value, not a reload of the overwritten field.

A word at saved-child offset `0x14`, multiplied by the factor, produces the **first product**. Afterward, another factor self-store is followed by a byte store of the saved child at third-selector offset `0x11`.

A word read at first-product offset `0x74` supplies the **retained word**. This observation populates stack offset `0x108` at this stage, before the remaining arithmetic and memory mutations. It is not merely a late copy performed immediately before the indirect call.

The **second product** is the first product multiplied by the factor. Another factor self-store follows, then third-selector offset `0x11` receives the retained word’s low byte.

### Final memory observations and updates

Two separate word reads occur at second-product offset `0x44`.

The first precedes a word read at first-argument offset `0x74`. Third-selector offset `0x64` then receives the retained word, and third-selector offset `0x09` receives the first product-relative observation’s low byte.

The second read occurs afterward and supplies the byte written at second-product offset `0x11`. An overlapping preceding write can therefore distinguish the two observations.

Another factor self-store precedes the retained word’s low-byte store at offset `0x11` from twice the second product.

A further word is read at offset `0x44` from the factor–second-product product. This read precedes the word read at first-argument offset `0x14`. The final three byte destinations, in order, are:

|---|---|

## Acceptance examples

These are conditional static expectations, not execution results.

1. **Truncation:** If the initial link’s low byte is `AB`, the first write stores `AB` at second-argument offset `0x15`. The subsequent initial-link-relative word store still uses the entire second argument.

2. **Signed halfword:** A halfword bit pattern of `FFFF` denotes −1 when used as a signed displacement or factor. A factor self-store consequently writes `FFFFFFFF`, assuming execution reaches a valid destination.

3. **Early overlapping write:** If the anchor-derived halfword destination overlaps the immediately following word source, that word observation occurs after the halfword write. A contract based on the original word would be incorrect.

4. **Fresh observation:** If an intervening overlapping write changes first-argument offset `0x64`, the later read uses the changed word. The first peer’s two offset-`0x11` stores may differ.

5. **Duplicate access:** With access-sensitive destinations, the initial factor self-store and third-selector byte-store pair occurs twice. Equal values do not justify accepting only one pair.

6. **Saved-child preservation:** The traversal-node field is read before replacement. The subsequent child-relative word read is based on the captured child, not the replacement value.

7. **Defined shift example:** For first argument `1`, valid execution with no interfering alias writes presents `0x10` in the four-bit-shift slots and `0x100` in the eight-bit-shift slots. Unspecified stack bytes need not be zero.

8. **Dependency mutation:** If D-01 changes the external final-call argument and returns, F-cdec09f5d432 receives the later evaluated value, not an assumed entry-time snapshot.

9. **Control-flow cutoff:** If D-01 does not return, the post-call stack writes and F-cdec09f5d432 are not reached. Returning from both ordinary dependencies leads to the terminal region, not a successful-return status.
