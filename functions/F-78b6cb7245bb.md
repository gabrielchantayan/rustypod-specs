# F-78b6cb7245bb

## Purpose

F-78b6cb7245bb attempts a one-byte write to a numerical destination selected from implicit incoming state. If execution continues beyond that access, it invokes an opaque dependency with two fixed numerical arguments. A represented continuation uses the dependency’s result as an indirect-call destination.

The supplied static representation establishes these operations and their relative order. It does not establish an application-level purpose. Deliberate fault generation is a possible interpretation, but neither a fault nor process termination is a required outcome.

A static annotation describes the first dependency as non-returning. The representation nevertheless includes a continuation that consumes its result. This contract preserves that distinction: non-return is an annotated expectation; the indirect call is represented conditional behavior. Actual reachability is **documented_only**.

Destination selection removes the selector’s lowest 29 bits and offsets the remaining unsigned quantity by decimal seventeen. ## Acceptance examples

These are conditional expectations derived from static evidence, not executed tests. Unless stated otherwise, numerical examples assume a 32-bit unsigned selector, an eight-bit byte, and an environment that supports the stated numerical-address interpretation.

### Lowest destination and ignored selector bits

A selector of hexadecimal 00000000 with payload hexadecimal A5 selects hexadecimal 11 and attempts a one-byte write of A5 there.

A selector of hexadecimal 1FFFFFFF selects the same destination. This equivalence concerns destination selection and the attempted write, not the behavior of either dependency.

### Destination boundary

A selector of hexadecimal 1FFFFFFF selects hexadecimal 11. Increasing the selector to hexadecimal 20000000 selects hexadecimal 12.

Thus, crossing this interval boundary changes the numerical destination by one. Changes confined to the lowest 29 bits do not change it.

### Highest 32-bit interval

Selectors hexadecimal E0000000 and FFFFFFFF both select hexadecimal 18.

With payload hexadecimal FF, the direct operation is still a one-byte write. It is not a wider all-ones store, and the selector is not interpreted as negative.

### Wider-selector consequence

If the selector instead has 64 unsigned bits and its value is hexadecimal 100000000, removing its lowest 29 bits leaves decimal eight. The decimal-seventeen offset then selects hexadecimal 19.

This demonstrates why the eight-destination range requires the 32-bit assumption. It does not establish that the actual selector is 64-bit.
