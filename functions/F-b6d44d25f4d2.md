# F-b6d44d25f4d2

## Purpose

The visible body contains no conditional branches or loops. If every preceding operation completes, it attempts a call to address zero with three zero arguments.

No application-level purpose is established. Repeated scaling and bit extraction may suggest encoded references, but that is **inferred intent**, not a contractual interpretation. The function is not established as an initializer, destructor, serializer, or supervisor-call implementation.

This contract distinguishes:

- **Established static evidence:** visible accesses, value dependencies, widths, and operation boundaries.

Every described operation is conditional on execution reaching it.

## Behavior

The selector is not a full-width pointer. Ordinarily, each selected-byte operation performs its own selector read. Repeated expressions separated by dependencies do not justify caching. One important late operation explicitly retains the selector value for additional uses; that snapshot is described separately below.

Recurring word destinations include:

- Four times a dependency-supplied quantity plus `0x14`.
- Sixteen times a dependency-supplied quantity plus `0x14`.
- In one region, 256 times a dependency-supplied quantity plus `0x14`.

These are distinct address formulas, not proof of a common structure layout.

Near the end, the function stores a scaled dependency result at a four-byte-aligned retained base plus `0x14`, then later clears another four-times slot.

A paired result then establishes the following ordered boundary:

2. G1 is read and retained as an address-like snapshot.
3. Five dependency invocations occur, beginning with an invocation that receives the scaled low half, the high half, and two further copies of the scaled low half.

## Acceptance examples

These are conditional static criteria, not executed tests.

1. **Opening truncation.** If the first selector is `0x20` and incoming state is `0x12345678`, the first write stores `0x78` at `0x31`, before F-000000000001.

2. **Fresh opening selector.** If an intervening dependency changes that selector to `0x30`, the second selected write targets `0x41`, not `0x31`.

3. **Unsigned forwarding.** An explicitly unsigned byte read of `0xFF` becomes `0x000000FF` when retained or stored as a word.

4. **Bit-19 displacement.** The special word read uses zero displacement when base bit 19 is clear and `0x80000000` when it is set, subject to target address arithmetic.

5. **Retained address-1 base.** Suppose the late snapshot of address 1 is `0x20`, and a dependency subsequently changes address 1 to `0x70`. The snapshot-based clear targets `0x31`; after G2 publication and the intervening calls, the word read remains at `0x94` and its low-byte destination remains `0x21`. Bases derived from `0x70` would be incorrect.

6. **Late pointed-word observation.** In that example, if a dependency changes the word at `0x94` before the read, the byte stored at `0x21` comes from the changed word. Retaining the base does not retain the word.

7. **Final G1 boundary.** Suppose the final G1 snapshot is `0x1000`, then an intervening dependency changes G1 to `0x2000` and the word at `0x1014` to `0xAABBCCDD`. After the intervening scaled-slot store, the read uses `0x1014`, not `0x2014`, and observes `0xAABBCCDD` provided that store or another actor has not changed it again.

8. **Aliasing intervening store.** If that scaled-slot store targets `0x1014`, the subsequent dependent read observes its stored value rather than the word that existed when G1 was snapshotted.

9. **Early termination and terminal order.** A non-returning dependency prevents later operations. If all preceding operations complete, the final output-byte clear precedes composite G2 publication, then the halfword clear, then the address-zero invocation.
