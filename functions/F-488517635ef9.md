# F-488517635ef9

## Purpose

F-488517635ef9 conditionally invokes object operations based on a record containing a buffer address and a 16-bit discriminator.

Two discriminator values are handled:

- **1:** A leading buffer byte of 0, 1, or 255 triggers an indirect operation on an initially acquired object.
- **2:** A leading buffer byte of 0, 1, or 255 triggers a second object acquisition, an indirect query, conditional shared-state accesses, and an optional operation carrying the leading byte.

For stable input bytes and normally returning dependencies, the normal result is **0** for those handled special-byte cases and **4** otherwise. These numeric results have no established domain-specific meaning. In particular, 0 does not establish that the final indirect operation occurred or changed anything.

The shared-state behavior resembles recording whether a previous byte value has been saved. That interpretation is inferred intent, not a condition of this contract.

## Interface

### Inputs and record layout

| Input | Represented width | Established use |
|---|---:|---|
| First argument | 32 bits | No visible use. |
| Record address | 32-bit address | Supplies the two fields below. |

| Record offset | Field width | Established use |
|---|---:|---|
| +8 bytes | 32-bit address | Buffer base address. |
| +12 bytes | 16 bits | Discriminator compared with 1 and 2. |

The discriminator is represented as a signed 16-bit quantity. Only equality with 1 and 2 matters; all other bit patterns take the default branch.

The discriminator is not established to be a buffer length. No independent buffer-size check is visible.

Buffer elements and shared-state elements are **8-bit bytes**. All buffer, record, dispatch-table, and shared-state offsets in this contract are byte offsets.

### Result

The normal return value is 32 bits:

| Condition | Result |
|---|---:|
| Discriminator other than 1 or 2 | 4 |
| Discriminator 1 or 2, with a stable leading byte in 2–254 inclusive | 4 |
| Discriminator 1 or 2, with a stable leading byte of 0, 1, or 255, and all reached operations completing normally | 0 |

For discriminator 1, repeated references to the leading byte mean that a changing buffer is not covered by this simple value-based table.

Indirect-operation results are not propagated as this function’s result.

### Storage preconditions

Normal execution requires validity only for storage actually accessed, but the function does not visibly validate these requirements:

- The record fields at +12 and +8 must be readable on every path.
- Discriminator 1 requires the first buffer byte to be readable.
- Discriminator 2 requires both the first and second buffer bytes to be readable, even when the first byte causes return 4.
- Reached indirect calls require usable object, dispatch-table, and target storage.
- Shared-state requirements depend on the control byte and the observed state byte, as detailed below.

The shared-state phase uses two distinct forms of addressing:

- A **captured base**, obtained from the global shared-state pointer after the query.
- **Direct global references**, used for the offset-5 accesses.

The relevant shared-storage preconditions are:

| Shared-state branch | Required accesses |
|---|---|
| Control byte zero | Writable offset +5 through the direct global reference; writable offset +6 through the captured base. |
| Control byte nonzero, observed offset-5 byte zero | Readable offset +5 through the direct global reference; writable offset +5 through its subsequent direct global reference; writable offset +6 through the captured base. |
| Control byte nonzero, observed offset-5 byte nonzero | Readable offset +5 through the direct global reference. No shared-byte store is visible. |

These requirements do not imply that all accesses use one storage object. They also do not imply an exact machine-level count of global-pointer loads.

## Behavior

### Entry sequence

The visible sequence is:

1. Read the discriminator at record offset +12.
2. Read the buffer address at record offset +8.
3. Call F-b7af80e829ec to acquire an object-like address.
4. Check whether that result is zero.

These actions precede discriminator-specific processing. An unsupported discriminator therefore still causes the acquisition call.

If the first acquisition returns zero, F-a817d8d58c10 is called before any visible buffer-byte read. The representation identifies this dependency as non-returning, but its actual behavior is not independently established by the supplied body. No explicit local recovery or returned error is provided at that point.

The record fields have already been observed when acquisition runs. Buffer contents have not. A dependency may therefore affect subsequently read buffer contents; no preservation guarantee is assumed.

### Discriminator 1

The first buffer byte is interpreted as unsigned.

For a stable byte:

- Values **2 through 254 inclusive** cause return 4, without an indirect operation.
- Values **0, 1, and 255** cause an indirect operation through dispatch-table offset **100**, followed by return 0 if that operation returns.

The operation uses the initially acquired object. The object supplies a dispatch-table address, and the target is obtained at byte offset 100 from that table.

No explicit arguments are represented for this invocation. Its true calling convention, any implicit receiver, and any inherited register arguments remain unresolved.

The range expression separately references the first buffer byte for an upper-bound comparison and, when necessary, a lower-bound comparison. Consequently:

- This branch does not establish a single captured value for both comparisons.
- A changing buffer can invalidate the stable-byte classification above.
- The representation does not establish an exact machine-load count.

No direct shared-state access is visible on this branch.

### Discriminator 2: buffer observation

The function observes, in order:

1. The unsigned first buffer byte, used as the requested value.
2. The unsigned second buffer byte, used as the control value.

Both values are obtained before the range decision and before any second acquisition. Subsequent decisions on this branch use these captured byte values.

If the requested value is **2–254 inclusive**, the function returns 4. The second buffer byte has nevertheless been read. No second acquisition, query, or direct shared-state access is visible on this path.

If the requested value is **0, 1, or 255**, processing continues.

### Discriminator 2: second acquisition and query

F-b7af80e829ec is called again. Its second result supplies the object for the remaining indirect operations on this branch. The initially acquired object is not substituted.

There is **no visible zero check** for this second result.

The function resolves the query target through the second object’s dispatch table at byte offset **104**, then invokes it with the second object as an explicit argument.

The query result is represented at **32-bit address width**. Despite its address-like representation, its domain meaning is unknown. It has two established uses:

- Its full 32-bit representation is compared with the zero-extended requested byte.
- Its least significant eight bits may be stored in shared state.

A query result of 257 therefore does not compare equal to requested byte 1, even though its low byte is 1.

### Discriminator 2: shared-state addressing

After the query returns, the function captures the global shared-state pointer. That captured base is used for any offset-6 store.

The offset-5 accesses instead reference the global pointer directly in the representation:

- The zero-control branch directly references the global for its offset-5 store.
- The nonzero-control branch directly references the global for its offset-5 read.
- If that read observes zero, the ensuing offset-5 store also directly references the global.

These distinctions are part of the contract. A single post-query capture must not be described as the base for every shared-state access.

The query may change the global pointer before the capture. Later changes may also matter to direct references, subject to the unresolved execution and memory model. The representation neither guarantees that all accesses address the same object nor proves how many machine loads implement them.

### Discriminator 2: shared-state effects

**If the captured control byte is zero:**

1. Store zero at offset +5 using the direct global reference.
2. Store zero at offset +6 using the captured base.

There is no visible read of the previous offset-5 byte on this branch. Both stores occur irrespective of equality between the requested value and query result.

**If the captured control byte is nonzero:**

1. Read the unsigned byte at offset +5 through a direct global reference.
2. If that observed byte is zero:
   - Store 1 at offset +5 through a direct global reference.
   - Then store the query result’s low eight bits at offset +6 through the captured base.
3. If the observed byte is nonzero, perform no direct shared-byte stores.

A nonzero control byte is thus a condition, not a value copied into shared state.

The offset-5 read and conditional store are separate accesses. No atomic read-modify-write operation is established, and the representation does not guarantee a common base for them.

### Discriminator 2: optional final operation

After the shared-state phase, the requested byte, zero-extended to 32 bits, is compared with the full query result.

If they differ, the function resolves the target at dispatch-table byte offset **100** from the second acquired object and calls it with:

- The second acquired object.
- The zero-extended requested byte.

If they are equal, that operation is skipped.

The normal result is 0 in either case. Direct shared-state stores precede the optional operation. No rollback is visible if that operation fails or transfers control elsewhere.

The final target is resolved after the query and shared-state phase. No assumption is made that the query preserves the object’s dispatch table or its lifetime.

### Other discriminators

For every discriminator other than 1 and 2:

- The record-field reads and initial acquisition still occur.
- A zero initial acquisition still causes the failure-dependency call.
- No buffer-byte read or direct shared-state access is visible.
- The normal result is 4, provided control reaches the return.

## Side effects

### Direct writes and dependency effects

The only explicit data writes are the branch-dependent shared-byte stores described above.

No direct write to the input record, input buffer, or acquired objects is visible. This does not restrict dependency effects: acquisition and indirect calls may modify those locations, globals, dispatch tables, or unrelated state.

### Ordering

The representation establishes these material orderings:

- Record-field observations precede initial acquisition.
- Initial acquisition precedes buffer-byte observations.
- On discriminator 2, both buffer bytes are observed before second acquisition.
- The query returns before the shared-state pointer is captured.
- The pointer capture precedes the represented shared-byte accesses.
- An offset-5 store precedes the corresponding offset-6 store.
- Shared-state accesses precede the optional final operation.

These are not claims of cross-thread synchronization. No lock, atomic compound update, memory barrier, or reentrancy protection is visible.

### Ownership and lifetime

No explicit allocation, release, reference-count adjustment, ownership transfer, or cleanup is shown.

Acquisition does not by itself establish retained ownership. Neither indirect call is assumed to preserve object lifetime, global state, or memory ownership. Every reached access requires its target storage to remain valid at that access.

### Errors

The only explicit failure-related branch calls F-a817d8d58c10 after a zero first acquisition.

No local validation or recovery is visible for invalid record addresses, inaccessible buffer bytes, an unusable second object, invalid dispatch targets, or invalid shared-state storage. No returned error value is established for such failures.

## Acceptance examples

These are conditional static expectations, not executed tests. Unless stated otherwise, assume valid reached storage, stable input bytes, successful acquisitions, and normally returning indirect calls.

Where an example describes one shared object, additionally assume that **after the query**, the captured shared-state pointer and every relevant direct global reference identify that object throughout the shared-state phase. Any stated offset-5 value applies at the actual post-query read, not before acquisition or query.

1. **Unsupported discriminator**

   With discriminator 3, both record fields are read and F-b7af80e829ec is called once. The normal result is 4. No buffer-byte read is visible.

2. **Zero initial acquisition**

   For any discriminator, a zero first acquisition causes F-a817d8d58c10 to be called before a visible buffer-byte read. No normal completion is guaranteed for this case.

3. **Discriminator-1 boundaries**

   Leading bytes 2 and 254 produce 4 without the offset-100 operation. Leading bytes 0, 1, and 255 invoke that operation and then produce 0.

4. **Discriminator-2 ordinary byte**

   With first byte 100, both buffer bytes are read. The result is 4 without a second acquisition, query, or shared-state phase.

5. **Clear without a final operation**

   With bytes 255 and 0 and full query result 255, zero is stored at directly referenced offset +5, then at captured-base offset +6. The final operation is skipped and the result is 0. No prior shared-byte values are required.

6. **Capture and request a different value**

   With bytes 1 and 7, query result 42, and offset +5 observed as zero at the post-query read, the shared-object stability condition above yields stores of 1 at +5 and 42 at +6. The final operation receives the second object and requested value 1. The result is 0.

7. **Preserve an existing saved byte**

   With bytes 0 and 1, query result 9, and offset +5 observed as nonzero at the relevant post-query read, no direct shared-byte stores occur. Readable offset +5 suffices for this phase; writable offsets +5 and +6 are not required by the visible path. The final operation receives requested value 0, followed by return 0.

8. **Full-width comparison, byte-sized capture**

   With bytes 1 and 1, query result 257, and offset +5 observed as zero after the query, the shared-object stability condition yields stores of 1 at +5 and 1 at +6. The final operation still occurs because full-width 257 differs from zero-extended 1.

9. **Distinct bases are not collapsed**

   On a zero-control path, if the captured base identifies one valid object while the direct global reference for the offset-5 store identifies another, the visible addressing places the +5 zero in the directly referenced object and the +6 zero in the captured object. This expectation is conditional on an execution environment in which that pointer change is valid and observable; it asserts neither a race model nor an exact load count.

10. **Zero second acquisition**

    If the first acquisition succeeds and the second returns zero, no second-result failure check is shown. Usable query dispatch is no longer guaranteed; the contract supplies no normal result for that invalid-object case.

- The discriminator-1 indirect-call ABI.
- Concrete identities of indirect targets.
