# F-87bda57f63f9

## Purpose

F-87bda57f63f9 conditionally dispatches a length-prefixed byte sequence to F-865efb608738. Dispatch depends on three checks: whether a two-byte prefix is available, whether the declared payload length fits a **16-bit-truncated available-length calculation**, and whether a 16-bit field in a supplied state region permits the operation.

The prefix represents an unsigned, big-endian payload length. The state-field check treats a nonempty payload as requiring one capacity unit per four bytes, rounded upward. An empty payload has a separate rule: the state field must still be nonzero.

The function returns zero when a check fails. After dispatch, it returns a masked value derived from the payload length. **Zero does not uniquely identify rejection:** a dispatched payload of 65,534 bytes also produces zero.

“Payload” and “capacity” describe the apparent roles of the data. The supplied evidence does not establish the application-level meaning of either.

## Interface

The interface has three inputs and one unsigned 32-bit result:

| Input | Representation | Role |
|---|---|---|
| Byte-region address | Address of byte-accessible storage | Identifies the two-byte prefix and, immediately afterward, the payload |
| Available-length value | Unsigned 32-bit integer | Gates prefix access and participates in the payload-length check |
| State-region address | Address represented by the supplied integer-valued argument | Identifies a region containing a 16-bit field at byte offset 2 |

The byte-region layout is:

| Byte offset | Meaning |
|---|---|
| 0 | Most significant byte of the declared payload length |
| 1 | Least significant byte of the declared payload length |
| 2 onward | Payload passed to the dependency if dispatch occurs |

Let **L** denote the decoded payload length. Its range is 0 through 65,535.

The state region contains a 16-bit field beginning at byte offset 2. Let **C** denote that field interpreted as an unsigned value. Its range is 0 through 65,535. Unlike the prefix, the field is accessed as a native 16-bit memory value; the supplied evidence does not independently establish its byte order or alignment requirements.

The return value is:

- **0** if any dispatch check fails.
- **(L + 2) bitwise-AND 0xFFFEFFFF** if the dependency returns normally after dispatch.

The dependency’s return value, if any, does not determine this result.

## Behavior

### Prefix gate and decoding

An available-length value of 0 or 1 causes an immediate zero result. Neither the prefix nor the state field is read on that path, and the dependency is not called.

For any larger available-length value, the function reads the two prefix bytes and forms:

**L = 256 × first byte + second byte.**

This fixes the prefix’s byte order independently of the machine’s native byte order.

The supplied expression establishes that both prefix bytes are used before the subsequent checks. It does not establish a separately observable order between those two byte reads.

### Available-length check

The function subtracts 2 from the unsigned 32-bit available-length value, then retains only the low 16 bits. Let the resulting value be **A**:

**A = (available length − 2) modulo 65,536.**

The subtraction is reached only when the available-length value is at least 2, so it does not underflow on a reached path.

Dispatch remains possible only when **L ≤ A**. Otherwise, the function returns zero without reading the state field.

This is not an ordinary comparison against all remaining bytes. High bits of the remaining-length value are discarded. Consequently, increasing the available-length argument can cause a formerly accepted prefix to be rejected. The effective allowance cycles every 65,536 bytes once the initial prefix gate is passed.

For example, an available-length value of 65,537 gives an allowance of 65,535, whereas 65,538 gives an allowance of zero.

### State-field check

After the available-length check succeeds, the function reads the 16-bit state field at byte offset 2.

For an empty payload, **L = 0**, dispatch requires that the field’s bit pattern be nonzero. The shown empty-payload test uses a signed 16-bit interpretation, but comparison with zero has the same outcome for every bit pattern as an unsigned nonzero test.

For a nonempty payload, dispatch requires:

**ceil(L / 4) ≤ C.**

The required count is computed by adding 3 to L and shifting right by 2 bits. Since L is at most 65,535, the intermediate sum is at most 65,538; it does not overflow unsigned 32-bit arithmetic. The resulting requirement ranges from 1 through 16,384.

For this nonempty case, the state field is explicitly treated as unsigned. A field whose high bit is set is therefore a large capacity value, not a negative limit.

If the applicable state check fails, the function returns zero without calling the dependency.

### Dispatch and completion

Once all checks pass, the function calls F-865efb608738 exactly once with these arguments, in this order:

1. The byte-region address advanced by 2 bytes.
2. The original state-region argument.
3. L, the decoded payload length, supplied as an integer value.

An empty accepted payload still causes a call. The first argument then denotes the position immediately after the prefix, and the third argument is zero.

The wrapper does not inspect a dependency result. If the dependency returns normally, the wrapper computes its result from the previously decoded length. It does not reread the prefix or state field.

The return calculation clears bit 16 of **L + 2**:

| Payload length | Result after normal dependency return |
|---|---:|
| 0 through 65,533 | L + 2 |
| 65,534 | 0 |
| 65,535 | 1 |

All other bits are unchanged by the mask. Because L + 2 is at most 65,537, these are the only exceptional cases.

## Side effects

The shown body performs no direct memory writes, allocation, deallocation, or explicit global-state access.

Its established direct reads are limited to:

- Two prefix bytes, when the available-length value is at least 2.
- One 16-bit state field, when the prefix’s declared length passes the available-length check.

These reads precede any dependency call. Rejection performs no dependency call.

F-865efb608738 receives addresses into caller-supplied storage. Its reads, writes, global-state effects, ownership behavior, address retention, and allocation or release behavior are not established here. The absence of writes in this wrapper must not be interpreted as a guarantee that an accepted operation leaves either region unchanged.

No non-aliasing requirement is shown. If the byte and state regions overlap, the checks use the values read before dispatch. Subsequent dependency mutations do not cause this wrapper to repeat the checks.

The function provides no explicit error object or diagnostic channel. Check failures share a zero result. Invalid memory accesses and abnormal dependency completion have no established recovery behavior or guaranteed return value.
