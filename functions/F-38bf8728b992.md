# F-38bf8728b992

## Purpose

F-38bf8728b992 accepts two operands represented by pairs of 32-bit words and produces a 64-bit result. Its established behavior comprises:

- Classification using the operands’ high words and a shared mask.
- Direct selection of unchanged, zero, or sentinel bit patterns.
- A finite-width subtraction and normalization calculation.
- Exceptional dispatch to an implicit continuation, with arguments selected by shared control state.

The field positions and normalization suggest floating-point remainder-related processing. This is **inferred intent**, not an established numerical specification. No standard arithmetic operation, floating-point format, rounding mode, or exception model is assumed below.

All behavior described here comes from static evidence. No runtime tests have been performed.

## Interface

### Explicit inputs and result layout

The four explicit inputs are unsigned 32-bit words, in this order:

| Input | Meaning within this contract |
|---|---|
| First low word | Lower word of the first operand |
| First high word | Upper word of the first operand |
| Second low word | Lower word of the second operand |
| Second high word | Upper word of the second operand |

The result is represented as 64 bits. In every direct two-word result, the high word occupies bits 63–32 and the low word occupies bits 31–0. This establishes bit placement, not memory byte order.

Direct results can be:

- The first operand unchanged.
- All zero bits.
- A sign-only zero pattern.
- A calculated high word paired with the current calculation low word.
- A shared sentinel high word paired with low word `1`.

An indirect path forwards the continuation’s represented 64-bit result if the continuation returns.

### Implicit inputs

The body depends on:

- A shared 32-bit classification mask.
- A shared 32-bit control word.
- A shared sentinel high word.
- Three shared payload words, designated payload A, payload B, and payload C.
- An incoming continuation address.
- Bit 0 of an incoming processor-status quantity.

Their concrete values are unavailable.

### Widths and preconditions

Word arithmetic, including additions, subtractions, multiplication, negation, complements, and left shifts, retains only 32 bits. Ordinary comparisons and right shifts are unsigned unless explicitly identified as signed.

Signed comparisons and arithmetic right shifts interpret a word as a two’s-complement signed 32-bit quantity.

Exceptional dispatch requires a usable continuation address and compatible machine-level calling convention. The body does not validate either.

There are no explicit pointers, buffer lengths, allocation requests, or ownership-transfer parameters. Shared payload words must not be assumed to represent pointers.

## Behavior

### 1. Classification and shared-state observations

An operand satisfies the initial classification predicate when its high word, logically shifted right by four, contains every set bit of the observed classification mask.

The first operand’s predicate is considered first. The second is considered only if the first does not satisfy it. If either satisfies the predicate, processing takes the exceptional/classification path. Otherwise, processing takes the arithmetic-entry path.

This is mask containment, not merely a nonzero intersection. A zero mask satisfies the first predicate immediately.

The mask is read repeatedly. The descriptions below that use one mask value are conditional on those reads observing a stable value. The evidence supplies no atomic snapshot or synchronization contract.

### 2. Exceptional/classification path

For stable mask observations, define the threshold as the mask multiplied by `0x20`, retaining 32 bits.

Each operand is compared against that threshold using its high word doubled modulo \(2^{32}\), with its low word breaking equality. An operand exceeds the threshold if:

- Its doubled high word is unsigned-greater than the threshold; or
- Its doubled high word equals the threshold and its low word is nonzero.

The first operand is considered first. The second operand is considered when the first does not exceed the threshold. Exceedance by either selects exceptional dispatch.

The represented operations calculate a threshold for the first comparison and read the mask again for the second operand’s comparisons when those are needed. Therefore, the stable-mask description is not a replacement for the individual observations under mutation.

If neither operand exceeds the threshold, only the first operand determines the direct result. Its exponent-like field consists of high-word bits 30–20:

| Field value | Result |
|---|---|
| `1` through `0x7fe` | First operand unchanged |
| `0`, with low word zero and high-word bits 30–0 zero | First operand unchanged, including bit 31 |
| `0`, otherwise | All zero bits |
| `0x7ff` | Observed sentinel high word with low word `1` |

The final row is a literal bit-pattern rule. It is not established as a standard NaN encoding.

### 3. Exceptional dispatch

The continuation target is the incoming continuation address with its lowest two bits cleared.

A control-word observation supplies the low nibble that selects the dispatch mode. Further conditions and argument construction use additional control-word observations.

The following table describes stable control state. Arguments appear in their represented order.

| Mode | Additional condition | Explicit continuation arguments |
|---|---|---|
| `9` | Bit `0x100000` clear | `0`, payload A |
| `9` | Bit `0x100000` set; any bit of `0x70000` set | `8`, the wrapping transformation described below |
| `9` | Bit `0x100000` set; all bits of `0x70000` clear | `0x30000000`, payload A, `0x30000000` OR incoming status bit 0 shifted to bit 27 |
| `10` | Bit `0x40` clear | One argument: `0` |
| `10` | Bit `0x40` set | One argument: `0x80000000` |
| `8` | Bit `0x40` set | `0`, `0` |
| `8` | Bit `0x40` clear; bit `0x10` clear | Payload B, payload A |
| `8` | Bit `0x40` clear; bit `0x10` set | `0`, payload C |
| Any other mode | — | No explicitly represented arguments |

The mode-`9` transformation first shifts the observed control word left by 15, complements the resulting 32-bit word, and then shifts that complement left once. Both shifts retain only 32 bits.

For mode `8` with bit `0x40` clear, the represented read order is:

1. Payload B.
2. Payload A.
3. The control word for bit `0x10`.
4. Payload C, only if that bit is set.

When payload C is selected, the previously read payload B and payload A values are not passed.

The control observation used to construct the mode-`9` transformed argument is separate from the observations selecting its branch. Stable-state rows must not be used to claim that all these reads necessarily agree.

Every represented dispatch immediately returns the continuation result if it returns. No arithmetic processing follows. Unlisted argument registers and other machine state are not established as cleared.

### 4. Arithmetic entry and rejection

On the arithmetic-entry path, the second operand’s masked quantity is obtained by intersecting its high word shifted right four with the mask. Whether this quantity is nonzero is recorded before any sign adjustment.

The first operand’s masked quantity is obtained similarly. Arithmetic processing begins only if:

- The recorded second masked quantity is nonzero; and
- The first high word intersects the mask shifted left four.

If this gate fails, the second masked quantity is evaluated again using another mask observation:

- If it is nonzero, a sign-only zero first operand is returned unchanged; every other first operand produces all zero bits.
- If it is zero, the result is the sentinel high word with low word `1`.

Thus, a zero second masked quantity selects the sentinel under stable mask observations. Under changing observations, the later read still governs this fallback.

### 5. Arithmetic state and comparison boundaries

The arithmetic calculation maintains:

- A current first magnitude, as high and low words.
- A second magnitude, also as high and low words.
- A first exponent-like state.
- A second bookkeeping state.
- A boundary state.

Each initial magnitude high word retains the corresponding input high word except where bits are cleared by the mask shifted left five; bit 20 is then forced on. The magnitude low words initially equal the respective input low words.

The first exponent-like state starts as the first masked quantity.

The second bookkeeping state starts as the second masked quantity, with bits represented by `5` additionally set when the first input high word has bit 31 set. The source’s signed-overflow predicate establishes this bit-31 condition; no floating-point sign convention is needed.

The boundary state starts one `0x10000` step below the adjusted second bookkeeping state. Subsequently, its bit 0 may toggle, but the body does not replace it with later exponent values.

At each comparison boundary, the first exponent-like state and boundary state are compared as signed 32-bit values.

When the first exponent-like state is no greater:

- A zero current low word together with current high-word bits 30–0 all zero returns immediately. The result low word is zero; its high-word bit 31 comes from boundary bit 2.
- Otherwise, arithmetic-right-shifted-by-16 versions of those two states are compared. A strictly smaller first value selects finalization.
- If that comparison does not finalize, the two magnitudes are compared unsigned, high word first and low word as tie-breaker.
- Equal magnitudes finalize. Before finalization, boundary bit 0 is toggled if the logical upper 16-bit portions of the first exponent-like state and second bookkeeping state are equal.
- A smaller current first magnitude finalizes without that equality toggle.
- A larger current first magnitude causes the second magnitude to be doubled before subtraction. Doubling carries the old low-word bit 31 into the high word and wraps at word width.

When the first exponent-like state is greater than the boundary state in the initial signed comparison, subtraction occurs without this magnitude comparison or doubling.

### 6. Subtraction and normalization

Subtraction updates the current low word first. The unsigned borrow is then included in the high-word subtraction. Both words wrap to 32 bits.

The second bookkeeping state is next set to the first exponent-like state minus `0x10000`.

If the resulting high word has bit 31 set, the current two-word magnitude is negated and boundary bit 0 is toggled. The negation propagates the low-word carry correctly: negating a nonzero low word requires the corresponding extra adjustment to the high word.

Normalization then takes one of two forms.

**Single-bit normalization.** If any high-word bit selected by `0x1e0000` is set, the current two-word magnitude is shifted left until high-word bit 20 is set. Every shift decreases the first exponent-like state by `0x10000`. A high word already having bit 20 set requires no such shifts.

**Wider normalization.** Otherwise, high-word bit 31 is first cleared.

Two distinct low-word promotion conditions follow:

- If the high word is zero and the low word’s upper 20 bits are zero, the low word is shifted left 20 and the first exponent-like state is decreased by `0x140000`.
- If the high word is then still zero, the current low word shifted right 12 supplies the high word, its left-shift-by-20 form supplies the remaining low contribution, and another `0x140000` is subtracted from the first exponent-like state.

Both conditions can apply during one normalization.

The remaining high-word normalization chooses cumulative shifts as follows:

| Condition on the current high word | Additional left shift |
|---|---|
| Logical right shift by 5 is zero | 16 |
| After that step, logical right shift by 13 is zero | 8 |
| After that step, logical right shift by 17 is zero | 4 |
| After that step, logical right shift by 19 is zero | 2 |
| After that step, logical right shift by 20 is zero | 1 |

The accumulated count ranges from 0 through 31. The first exponent-like state decreases by that count multiplied by `0x10000`. The remaining low contribution is shifted left by the count to produce the new low word, and its cross-word contribution is ORed into the high word.

The cross-word contribution uses a right-shift count of 32 minus the accumulated count, restricted to its low eight bits. When the accumulated count is zero, this requests a right shift by 32. Its exact target-machine result is **documented_only**; no portable word-language interpretation is assumed.

Importantly, wider normalization also replaces the second bookkeeping state with **32 minus the accumulated shift count**. It does not retain the exponent-minus-`0x10000` value assigned just after subtraction. This affects later equal-magnitude sign/parity decisions.

No rounding increment, sticky-bit accumulation, saturation, or precision-loss exception is visible.

### 7. Arithmetic finalization

Finalization first tests the first exponent-like state as signed 32 bits.

If it is at most `0xffff`, the result is all zero bits.

Otherwise, the low result word is the current magnitude low word. The high result word is constructed in this exact order:

1. Subtract `0x10000` from the first exponent-like state.
2. Multiply that difference by 16.
3. Add the current magnitude high word.
4. XOR the sum with boundary bit 0 placed at bit 31.

Every arithmetic intermediate retains only 32 bits. Equivalently:

\[
\text{result high}
=
\left[
\text{current magnitude high}
+
16\left(\text{first exponent-like state}-\texttt{0x10000}\right)
\right]_{32}
\mathbin{\mathrm{XOR}}
\left((\text{boundary}\mathbin{\mathrm{AND}}1)\ll31\right).
\]

The subtraction is **inside** the quantity multiplied by 16. Subtracting `0x10000` after multiplication is not equivalent.

This finalization sign construction uses boundary bit 0. The earlier zero-pattern exit uses boundary bit 2; these exits must remain distinct.

## Acceptance examples

These are conditional consequences of static evidence, not executed tests.

1. **Ordinary field preservation.** With stable mask observations, exceptional/classification selection, no threshold exceedance, and first exponent-like field `0x3ff`, the first operand is returned bit-for-bit.

2. **Signed zero preservation.** Under the same branch conditions, first low word `0` and first high word `0x80000000` return unchanged. High word `0` also returns unchanged.

3. **Nonzero exponent-zero input.** Under those conditions, first high word `0` and first low word `1` produce all zero bits.

4. **Sentinel placement.** Reaching the classification field `0x7ff` without dispatch produces low word `1` and the observed sentinel high word.

5. **Threshold tie.** A doubled high word equal to the stable threshold does not exceed it when its low word is zero. Making that low word nonzero causes that operand to exceed it.

6. **Mode `10`.** Given dispatch and stable mode `10`, bit `0x40` selects one explicit argument: `0` when clear, `0x80000000` when set. A returned continuation result is forwarded.

7. **Discarded payload reads.** In stable mode `8`, with bit `0x40` clear and bit `0x10` set, payload B and payload A are read before payload C. The passed arguments are nevertheless `0` and payload C.

8. **Arithmetic rejection.** With stable nonzero second masked quantity but no first-high-word intersection with the mask shifted left four, a sign-only zero first operand is preserved; any other first operand produces zero.

9. **Correct finalization grouping.** Conditional on reaching finalization with first exponent-like state `0x00020000`, magnitude high word `0x00100000`, magnitude low word `0x89abcdef`, and boundary bit 0 clear, the result high word is `0x00200000`, and the low word is `0x89abcdef`. High word `0x002f0000` would incorrectly subtract `0x10000` after multiplication.

10. **Under-range finalization.** A signed first exponent-like state at most `0xffff` produces all zero bits, even if the current low magnitude word is nonzero.

11. **Wider-normalization bookkeeping.** If wider normalization accumulates a shift count of 4, its resulting second bookkeeping state is 28. Any later equal-magnitude upper-half comparison uses that replacement, not the previously assigned exponent-derived value.
