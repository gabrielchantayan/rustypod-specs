# F-516bfe0b85b7

## Purpose

F-516bfe0b85b7 performs a fixed sequence of indirect dependency calls interleaved with word, byte, and halfword memory accesses. It propagates a captured 32-bit word to several destinations, constructs additional stored values from dependency results, performs two byte-table-mediated writes, updates a global control slot, and finally attempts a call through address zero.

The supplied static representation establishes these operations and their order. It does not establish an application-level purpose, a successful completion path on a conventional memory map, or the semantics of the indirect dependencies. Descriptions such as allocation, object initialization, serialization, or privileged dispatch would be inferred intent, not established behavior.

This contract describes the visible operations conditionally: each later operation is reached only if all earlier calls and memory accesses complete and return normally.

## Interface

**Visible signature**

- Two leading 32-bit argument slots.
- One unsigned 32-bit third argument.
- No explicit return value.

The two leading arguments are not explicitly consumed by any visible expression. This does not prove they are irrelevant to dependencies: the representation does not establish all machine-register inputs to calls shown without explicit arguments.

The third argument is explicitly consumed in two ways:

1. A right shift by two followed by a left shift by sixteen produces a 32-bit dependency argument.
2. Clearing its two least-significant bits produces the base for a 32-bit write at byte offset 20.

**Additional execution inputs**

The function depends on state beyond its three visible arguments:

- An incoming execution-context value used to form the first indirect call target.
- The targets and behavior of numerous other indirect calls.
- Dependency return values, including two results represented as 64-bit quantities.
- A global pointer-like slot read partway through execution.
- Existing memory at computed addresses.
- An additional pointer-like result associated with the final control-slot-producing call.

These are required inputs to the observed behavior, but their validity and calling conventions are not established.

- “Low half” and “high half” of a 64-bit result: its low and high 32-bit portions.

Expressions involving explicitly unsigned 32-bit values use 32-bit unsigned shifts and truncation. The representation also contains signed-looking multiplications, additions, and left shifts used to construct addresses. Their overflow semantics are not established. For a nonwrapping interpretation of those operations, callers and dependency results must keep every intermediate representable and every resulting access valid.

No ownership transfer, allocation, release, or buffer length is declared by this interface.

## Behavior

### Dependency-site convention

The opaque identifiers F-01 through F-64 below identify dependency invocation sites in execution order. They do not assert that there are 64 distinct target functions. Several sites may resolve to the same target, but target identity is not established.

“No explicit arguments” means only that the supplied representation shows none. It is not a claim that the target receives no register or execution-state inputs.

### 1. Capture and initial propagation

1. Invoke F-01 and F-02, then invoke F-03 and retain its 32-bit result as the **first selector**.
2. Multiply the first selector by four to form the **first base**.
3. Read a 32-bit **captured word** from the first base plus 116.
4. Write the low byte of the captured word to the first base plus one.
5. Invoke F-04 with the first base.
6. Invoke F-05, F-06, and F-07, then invoke F-08 to obtain the **second selector**.
7. Write the complete captured word to the address formed by sixteen times the second selector plus 20.

The captured word is retained across these calls. It is not reloaded from its original address before subsequent uses. Dependencies may nevertheless change that original address or any destination.

### 2. Third-argument transformation and another word destination

1. Invoke F-09 with the third argument shifted right by two and then left by sixteen, evaluated as an unsigned 32-bit expression.
2. Invoke F-10 and pass its 32-bit result to F-11.
3. Invoke F-12 and pass its 32-bit result to F-13.
4. Invoke F-14, F-15, and F-16.
5. Invoke F-17 to obtain the **third selector**.
6. Write the captured word to four times the third selector plus 20.
7. Invoke F-18 with four times the third selector.

The F-09 transformation retains only original argument bits 17 through 2, moving them to bits 31 through 16. Its low sixteen output bits are zero. Original bits 31 through 18 and bits 1 through 0 do not affect that argument.

### 3. Store through the aligned third argument

1. Invoke F-19, F-20, and F-21.
2. Invoke F-22 and shift its 32-bit result left by two to form the **first scaled result**.
3. Clear the third argument’s two least-significant bits, add 20, and write the first scaled result as a 32-bit value at that address.
4. Invoke F-23 with two explicit arguments, both equal to the first scaled result.
5. Invoke F-24 and pass its 32-bit result to F-25.
6. Invoke F-26 and pass its 32-bit result to F-27.

Clearing the low two bits aligns the base downward; it is not validation of an address or a guarantee that the following access is permitted. The unsigned address addition can wrap at 32 bits.

### 4. Explicit word clearing

1. Invoke F-28, F-29, and F-30.
2. Invoke F-31 to obtain the **fourth selector**.
3. Write a zero word to four times the fourth selector plus 20.
4. Invoke F-32 with four times the fourth selector.

This is one 32-bit zero write. The representation does not establish initialization of a larger region.

### 5. Paired result, retained global base, and repeated word value

1. Invoke F-33, F-34, and F-35.
2. Invoke F-36 to obtain a result represented as 64 bits.
3. Shift its low half left by two to form the **retained scaled word**.
4. Write that word to four times the high half plus 20.
5. Read and retain the value of a global pointer-like slot as the **saved global base**.
6. Invoke F-37 with four explicit arguments, in order:
   - Retained scaled word.
   - High half of the F-36 result.
   - Retained scaled word.
   - Retained scaled word.
7. Invoke F-38, F-39, and F-40.
8. Invoke F-41 to obtain the **fifth selector**.
9. Write the retained scaled word to four times the fifth selector plus 20.
10. Read a 32-bit **payload word** from the saved global base plus 20.
11. Invoke F-42 with four times the fifth selector.

The global base is captured before F-37. The payload is read after F-37 through F-41 and after the second retained-word store. Consequently:

- A dependency’s modification of the global slot does not change the already saved base.
- A dependency’s modification of memory at the saved base plus 20 can affect the payload read.
- Aliasing between the immediately preceding write and the payload address can also affect that read.

6. Write the payload word’s low byte to the first byte destination.
7. Invoke F-47 with four explicit arguments:

The lookup address is in the inclusive range 1 through 512. The byte destination is in the inclusive range 17 through 272. The lookup byte supplies the entire destination base; it is not an offset added to an otherwise visible object pointer.

### 7. Second table-mediated byte write

2. Invoke F-50, F-51, and F-52.
3. Invoke F-53 and retain its 32-bit result for F-54.
4. From the retained low half of F-46, clear bits 31 and 30, shift right by 21, and add one. This produces the **second lookup address**.
5. Read an unsigned byte from that address.
6. Add 17 to the byte’s value to obtain the **second byte destination**.
7. Shift the payload word right by 22 and write the low byte of the result to the second byte destination.
8. Invoke F-54 with the F-53 result shifted left by two.

The second lookup address is also in the inclusive range 1 through 512. The written byte comprises payload bits 29 through 22; it is not the payload’s most-significant byte.

The first byte write precedes this second lookup. If the first destination aliases the second lookup address, and intervening dependencies do not change it, the second lookup observes the newly written byte.

## Acceptance examples

These examples are conditional static acceptance criteria, not executed tests. Unless stated otherwise, dependencies must return normally, accesses must be valid, and relevant memory must not be changed by intervening dependencies.

1. **Captured-word truncation.**  
   If the first selector is 64 and the word at address 372 is `0xA1B2C3D4`, the initial byte write stores `0xD4` at address 257. Later captured-word stores use the complete `0xA1B2C3D4`, even if the original source word subsequently changes.

2. **Unsigned argument packing.**  
   For third argument `0xFFFFFFFF`, F-09 receives `0xFFFF0000`. The result is not a full-width multiplication retaining all high input bits.

3. **Alignment followed by address wrap.**  
   For third argument `0xFFFFFFFF`, clearing its low two bits gives `0xFFFFFFFC`; adding 20 as unsigned 32-bit arithmetic yields address 16. If that address is writable, the first scaled result is stored there. No visible overflow rejection occurs.

4. **Payload captured after dependencies.**  
   If the saved global base is 4096, changing the global slot to 8192 during F-37 does not redirect the payload read. That read still targets address 4116. A change to the contents at address 4116 before the read does affect the payload.

5. **Lookup byte controls the destination.**  
   If the captured word is zero, the first lookup reads address 1. If that byte is 200 and the payload low byte is `0x7A`, the first byte write targets address 217 and stores `0x7A`.

6. **Second payload slice.**  
   If the payload is `0xC0000000`, the second written byte is zero. If the payload is `0x3FC00000`, it is `0xFF`. Bits 31 and 30 are excluded from this byte.

7. **Observable aliasing.**  
   Suppose the first byte destination is 100, it receives 7, and the second lookup address is also 100. With no intervening modification, the second lookup reads 7 and selects destination 24.

8. **Potentially unaligned terminal write.**  
   If the retained low half of F-46 is 128, the final halfword destination is address 1. Reaching that operation does not establish that the platform permits an unaligned halfword write.

9. **No guaranteed normal return.**  
   Completion of all data writes is insufficient to establish successful return. F-64 must also be executable at address zero and return normally.
