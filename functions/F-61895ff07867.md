# F-61895ff07867

## Purpose

F-61895ff07867 updates a destination descriptor from a source descriptor and returns the original destination-descriptor pointer.

The established behavior is a conditional sequence of dependency calls and descriptor updates. It distinguishes:

- Exact identity of the two descriptor pointers, which causes an immediate return without accessing descriptor fields.
- Insufficient destination capacity, which requests replacement storage and invokes transfer, cleanup, and release dependencies.
- Sufficient destination capacity but fewer destination elements, which invokes separate operations for an existing prefix and an additional suffix.
- Sufficient destination capacity and at least as many destination elements, which invokes a transfer operation followed by a trailing-range operation.

The inferred intent is assignment between contiguous, fixed-stride collections. This interpretation is not a guarantee about the dependencies’ element semantics or resource ownership.

A significant observable detail is that the sufficient-capacity, non-growing path writes the same computed address to both the destination’s end field and capacity-boundary field. It does not preserve the previous capacity boundary.

## Interface

**Inputs**

1. A destination-descriptor pointer.
2. A source-descriptor pointer.
3. An unsigned 32-bit value.
4. Another unsigned 32-bit value.

The third and fourth inputs are copied into temporary storage only when the descriptor pointers differ. They do not influence a subsequent dependency argument, branch decision, descriptor write, or return value: the relevant temporary values are overwritten before use.

**Return value**

The return value is the original destination-descriptor pointer on every path that returns normally. There is no explicit status or error return.

**Descriptor layout**

The supplied representation accesses three consecutive 32-bit fields:

| Offset | Interpretation used by this function |
|---|---|
| 0 bytes | Base address of element storage |
| 4 bytes | Current end address |
| 8 bytes | Capacity boundary |

Elements have a 16-byte stride for the arithmetic performed here. The function does not directly inspect element contents.

These are source-level observations about 32-bit words and address-valued fields. They do not establish an element type, alignment requirement, signedness of element data, or a portable host-language structure layout.

**Minimum access requirements**

For distinct descriptor pointers, both descriptors must support the reads reached on the selected path. The destination must also support the indicated writes. Dependencies may impose additional access, alignment, lifetime, and range requirements.

Exact pointer identity is checked before any descriptor-field access or dependency call. Consequently, the identity path does not itself require dereferenceable descriptor storage. This does not authorize invalid distinct descriptors.

Distinct descriptor addresses are not checked for partial overlap. Element-storage overlap is also not checked.

## Behavior

### Arithmetic and interpretation

The function uses 32-bit quantities and a 16-byte element stride.

A destination capacity count is obtained by subtracting its base address from its capacity boundary, shifting the signed difference right by four, and then interpreting the result as unsigned for comparison. This is not automatically equivalent to an unsigned byte-distance division for malformed descriptors.

The release call later receives a capacity count formed from a fresh capacity-boundary-minus-base calculation, again shifted right by four. Its treatment by the dependency is unknown.

The contract distinguishes:

- The arithmetic expressed in the supplied representation.
- The additional assumptions needed to interpret that arithmetic as valid collection sizes and addresses.

For conventional collection behavior, address differences must be meaningful, counts must fit the operations used, and computed storage addresses must remain valid. No explicit overflow, underflow, divisibility, or range checks appear.

### Exact descriptor identity

If destination and source pointers are equal:

- No descriptor fields are read.
- No dependency is called.
- No descriptor field is written.
- The destination pointer is returned.

Identity concerns descriptor addresses only. Two different descriptors referring to the same storage do not take this path merely because their fields match.

### Initial capacity decision

For distinct descriptors, the function first calls F-b75d62a4795b with the source descriptor.

It compares that returned unsigned quantity with the destination capacity count calculated from the destination’s base and capacity boundary.

The capacity fields used for this decision are read after the source dependency call. The function does not take a pre-call snapshot of those fields.

If the capacity count is smaller than the returned quantity, replacement storage is requested. Otherwise, execution proceeds to one of the reuse paths.

### Replacement-storage path

The following dependency-call order is established:

1. Call F-b75d62a4795b with the source descriptor again.
2. Call F-b75d62a4795b with the destination descriptor.
3. Call F-871e64ddc6de to request storage.
4. Call F-d713fa022b85 for the current source range and the returned storage address.
5. Call F-016c2259d265 for the current destination range.
6. Call F-ff1bdc376dcd with the current destination storage address, a capacity-derived count, and zero.
7. After installing the replacement base, call F-b75d62a4795b with the source descriptor once more.

The second source result and the destination result determine the requested capacity. Let the destination result be \(d\) and the second source result be \(s\). The candidate capacities are:

- \(d + 32\)
- \(d + (d \mathbin{\mathrm{>>}} 1) + (d \mathbin{\mathrm{>>}} 3)\)

The larger candidate is selected, followed by the larger of that result and \(s\). These are unsigned 32-bit additions and comparisons. The fractional terms are separate right shifts; this is not unrestricted real-number multiplication by 1.625.

The selected capacity is shifted left by four to form the byte-count argument to F-871e64ddc6de. Its second argument is zero. No explicit rejection of a wrapped byte count or failed allocation result appears.

F-d713fa022b85 then receives:

- The source’s current base.
- The source’s current end.
- The address returned by F-871e64ddc6de.
- The destination descriptor.

Next, F-016c2259d265 receives the destination descriptor and its then-current base and end.

Next, F-ff1bdc376dcd receives:

- The destination’s then-current base.
- A count derived from its then-current capacity boundary and base.
- Zero.

These calls do not operate on a single immutable snapshot. Earlier dependencies can affect the fields read for later calls.

After these dependencies return normally:

1. The destination base field is assigned the saved replacement-storage address.
2. F-b75d62a4795b is called again with the source descriptor.
3. The destination end field is assigned the then-current destination base plus 16 times that result.
4. The destination capacity boundary is assigned the then-current destination base plus 16 times the saved selected capacity.

The function does not restore the base after the final source query. A dependency that changes it can therefore affect the subsequent end and capacity calculations.

### Reuse path with a shorter destination

When initial capacity is sufficient, the function calls F-b75d62a4795b first with the destination and then with the source. It compares these two unsigned results.

If the destination result is smaller:

1. F-b75d62a4795b is called again with the destination. This fresh result supplies a prefix length.
2. F-06ed5961b431 is called with:
   - The current source base.
   - That base plus 16 times the fresh prefix length.
   - The current destination base.
3. F-b75d62a4795b is called again with the source.
4. The destination end is written as its current base plus 16 times that latest source result.
5. F-d713fa022b85 is called with:
   - The current source base plus 16 times the saved prefix length.
   - The current source end.
   - The current destination base plus 16 times the saved prefix length.
   - The destination descriptor.
6. The function returns the destination pointer immediately.

The end-field write occurs **before** the final range dependency. That dependency can observe the updated end.

There is no explicit capacity-boundary write on this path. Dependencies may still change that field; preservation is not independently guaranteed.

The prefix length comes from the second destination query, not from the earlier comparison result. If dependency results vary, the function does not clamp or reconcile them.

### Reuse path with an equal or longer destination

If the destination-query result is at least the source-query result:

1. F-06ed5961b431 is called with the current source base, current source end, and current destination base.
2. Its returned value is passed to F-016c2259d265 as the start of a range. The other arguments are the destination descriptor and its current end.
3. F-b75d62a4795b is called again with the source.
4. A single address is computed from the current destination base plus 16 times this latest source result.
5. That address is written first to the destination end and then to the destination capacity boundary.
6. The destination pointer is returned.

The range boundary passed to F-016c2259d265 is the actual return from F-06ed5961b431. It is not independently recomputed.

Even when logical lengths are equal, the trailing-range dependency is called. The function does not omit it on the assumption that the range is empty.

## Side effects

Directly observable effects include:

- Calls to the dependencies described above.
- Writes to destination descriptor fields.
- A replacement-storage request and a later release-like call on the replacement path.

No explicit source-descriptor writes appear. This does not establish source immutability: dependencies receive source descriptors or source storage, and aliasing can expose destination writes through other references.

### Ownership and lifetime

The replacement path suggests the following intended lifecycle:

- Obtain replacement storage.
- Populate it from the source.
- Process existing destination elements.
- Release existing destination storage.
- Install replacement descriptor fields.

Only the call sequence and field writes are established. It is unknown whether:

- F-871e64ddc6de returns owned, initialized, aligned, or non-null storage.
- F-d713fa022b85 creates objects, transfers ownership, or merely writes bytes.
- F-016c2259d265 destroys objects or performs another range operation.
- F-ff1bdc376dcd releases the supplied storage.
- Any dependency modifies global state, descriptors, or aliased memory.

The function does not itself provide rollback.

### Errors and interrupted execution

There is no explicit local error handling, null-result check, status check, or recovery branch.

If a dependency does not return normally, later calls and writes are not established. Earlier effects can remain visible. In particular, on the shorter-destination reuse path, the destination end has already been advanced before the final dependency is invoked.

Argument expressions read descriptor fields when preparing each call. The supplied representation does not establish an ordering among separate argument-expression reads within the same call.

## Acceptance examples

These examples are conditional static acceptance criteria, not runtime observations. Unless otherwise stated, dependencies return normally, preserve descriptor fields except for their intended range work, and return stable element counts. Address arithmetic is assumed valid and non-overflowing.

1. **Identical descriptor pointers**

   Given equal source and destination descriptor pointers, the function returns that pointer with no dependency calls and no descriptor accesses.

2. **Replacement capacity dominated by the source**

   Given destination capacity 4, destination count 4, and source count 50, the growth candidates are 36 and 6. Selected capacity is 50; the storage request is 800 bytes with second argument zero.

   Under the stated preservation assumptions, the final end and capacity boundary both equal the replacement base plus 800 bytes.

3. **Replacement capacity exceeds the source length**

   Given destination capacity 40, destination count 40, and source count 50, growth candidates are 72 and 65. Selected capacity is 72, so the request is 1,152 bytes.

   The final end is replacement base plus 800 bytes; the capacity boundary is replacement base plus 1,152 bytes.

4. **Reuse with additional elements**

   Given capacity 10, destination count 3, and source count 7, no replacement-storage request occurs.

   F-06ed5961b431 receives the source prefix spanning 48 bytes. The destination end is then set to base plus 112 bytes before F-d713fa022b85 receives the remaining source range and destination address at offset 48. No direct capacity-boundary write occurs.

5. **Reuse while reducing length**

   Given capacity 10, destination count 7, and source count 3, F-06ed5961b431 processes the source range. Its return value supplies the start boundary for F-016c2259d265.

   After the final source query, both destination end and capacity boundary are assigned base plus 48 bytes.

6. **Equal lengths with spare capacity**

   Given capacity 10 and both counts equal to 3, execution takes the equal-or-longer path. The range dependency is still called, and both destination end and capacity boundary become base plus 48 bytes.

7. **Changing source-query results**

   If replacement-path source queries return 50, then 60, then 55, while the destination query returns 4, the first result selects replacement, the second selects capacity 60, and the last determines the final end offset of 880 bytes. The capacity offset is 960 bytes. No consistency check rejects the differing results.
