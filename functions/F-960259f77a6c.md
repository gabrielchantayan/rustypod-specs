# F-960259f77a6c

## Purpose

F-960259f77a6c routes an object-associated operation according to a signed selector and, for nonnegative selectors, a dependency-produced lookup result. A separate action follows whenever the third input is nonzero.

The established routing is:

- Negative selector: invoke the receiver’s dispatch entry at byte offset `0x154`.
- Nonnegative selector with a zero lookup result: invoke the entry at `0x15C`.
- Nonnegative selector with a nonzero lookup result: perform additional processing, then invoke the entry at `0x158`.
- After normal completion of the selected operation and any applicable lookup-storage cleanup, perform the final action if the third input is nonzero.
- Return the 32-bit value `1` on every visible normal completion.

The application-level meanings of these operations are unknown. “Lookup,” “workspace,” “resource,” and “target” identify structural roles, not established domain semantics or ownership rules.

## Interface

### Inputs and output

| Input | Representation | Established role |
|---|---|---|
| Receiver | Pointer in the recovered 32-bit representation | Supplies a dispatch-table reference, embedded lookup context, and mode word. Passed to the selected operation. |
| Selector | Signed 32-bit integer | Its sign selects the initial path. Passed unchanged to the applicable lookup dependency and selected operation. |
| Option | 32-bit integer | Passed unchanged to the selected operation. Zero disables the final action; every nonzero bit pattern enables it. |

The selector range `−2,147,483,648` through `−1` takes the negative path. The range `0` through `2,147,483,647` takes the lookup path. There is no visible negation, absolute-value calculation, selector increment, or upper-bound check.

The option is not normalized to a Boolean before dispatch. For example, `−1` remains `−1` when forwarded and also enables the final action.

The return value is a 32-bit `1`. Results from selected dispatch operations do not determine this return value. A normal return is not established when a dependency faults, fails to return, or transfers control nonlocally.

### Receiver layout

Offsets are byte offsets from the receiver address.

| Offset | Required use on applicable paths |

| `0xD0` | Address of embedded context passed to F-7cbb8ae2646e. Its extent is unknown. |

The mode condition uses only the low eight bits of the recovered word. It does not establish that the underlying access is a one-byte memory read. Signedness of the narrowed character does not affect comparison with zero.

The dispatch table supplies callable entries at byte offsets `0x154`, `0x158`, and `0x15C` as required by the reached branch. Each selected operation receives the original receiver, selector, and option, in that order. Any returned result is ignored.

## Behavior

### Negative-selector path

A selector below zero causes immediate selection and invocation of the receiver’s dispatch entry at `0x154`, with all three original inputs.

This path does not visibly initialize lookup storage, read the mode word, construct a lookup value, query a lookup result, or invoke lookup-storage cleanup.

If dispatch returns normally, processing continues to the option-controlled final action. A negative selector does not itself suppress that action.

### Nonnegative-selector lookup

For a selector of zero or greater, the function first passes the address of four-byte primary lookup storage and two zero arguments to F-1c06d0a5910b.

Only after that call returns does it read the receiver’s mode word at `0xE4` and test its low eight bits:

- **Zero low byte:** F-7cbb8ae2646e receives a separate four-byte temporary-storage address, the receiver-relative address `0xD0`, and the original selector.
- **Nonzero low byte:** F-6a21f4f07f67 is called without explicit arguments. Its 32-bit result is passed to F-21712eedaa5c together with the temporary-storage address and selector.

Both alternatives then follow the same order:

1. F-047d22db5c73 receives the primary lookup-storage address and temporary-storage address.
2. F-c1466ea05103 receives the temporary-storage address.
3. F-1862b8feb88c receives the primary lookup-storage address and returns a value tested against zero.

The temporary’s cleanup-like call therefore precedes the lookup-result query. The association performed by F-047d22db5c73 is unknown: the evidence does not establish copying, moving, borrowing, retaining, or ownership transfer.

### Zero lookup result

If F-1862b8feb88c returns zero, the function reads the receiver’s dispatch-table reference and obtains the entry at `0x15C`.

It invokes that entry with the original inputs. After a normal return, it passes the primary lookup-storage address to F-c1466ea05103 and continues to the option-controlled final action.

A zero lookup result neither causes an early return nor changes the eventual normal return value.

### Nonzero lookup result

Any nonzero result takes the additional-processing path. Positive and negative nonzero values are not distinguished.

The processing order is:

1. F-5fb92c16ae07 receives an eight-byte workspace address and the primary lookup-storage address.
2. F-6a21f4f07f67 is called without explicit arguments.
3. F-664473a81df4 receives that newly returned value and the eight-byte workspace address.
4. F-289ec4311c64 receives the eight-byte workspace address.
5. The function reads global slot A to obtain a base address.
6. It reads a 32-bit value from that base plus `4`.
7. F-9b9c1c7483f4 receives a four-byte construction-temporary address, the resource value just read, and a separate four-byte workspace address.
8. After F-9b9c1c7483f4 returns, the function reads global slot B.
9. F-e475f4597093 receives the target read from slot B, the preceding dependency’s 32-bit return value, and an additional 32-bit local value.
10. F-8a5aadac202f receives the construction-temporary address.
11. The function reads the receiver’s dispatch-table reference and selects its entry at `0x158`.
12. It invokes that entry with the original inputs.
13. After a normal return, F-c1466ea05103 receives the primary lookup-storage address.

The additional local value passed to F-e475f4597093 has no visible explicit initialization. Its origin and validity remain unresolved; it must not be described as zero or as a known result of another dependency.

Slot B is read **after** F-9b9c1c7483f4 returns. Caching its target before that call would not preserve the established behavior: the dependency may change the slot. The contract does not require an ordering between the reads of separate arguments used by F-e475f4597093 beyond their occurrence after the preceding call.

If the nonzero mode path was used during lookup, F-6a21f4f07f67 is called twice overall. These are independent calls whose results need not match. The first result supplies lookup construction; the second supplies workspace processing.

### Option-controlled final action

After dispatch returns, and after primary lookup-storage cleanup when applicable, the function tests the original option.

If the option is zero, it returns `1` without this action.

If the option is nonzero, the sequence is:

1. Read global slot C to obtain a base address.
2. Read a 32-bit resource value from that base plus `8`.
3. Invoke F-9b9c1c7483f4 with a local construction-temporary address, that resource value, and another local workspace address.
4. After that call returns, read global slot D.
5. Invoke F-2b88fb7b0f1e with the target read from slot D, the preceding dependency’s 32-bit return value, and a further local workspace address.
6. Invoke F-8a5aadac202f with the construction-temporary address.
7. Return `1`.

Slot D must not be cached before F-9b9c1c7483f4. That dependency may change the global-held target before it is read.

The final action is reachable from every dispatch branch. It does not depend on a selected operation’s return value.

## Side effects

### Observable reads and call ordering

The four global-slot reads are conditional, distinct observations:

- Slots A and B are read only on the nonzero lookup-result path.
- Slots C and D are read only when the final action is reached with a nonzero option.
- When both auxiliary actions occur, the order is A, B, C, D, with dispatch and primary lookup-storage cleanup between B and C.
- Each base-slot read precedes its resource-field read and the corresponding F-9b9c1c7483f4 call.
- Each target-slot read follows that corresponding call and precedes its consumer.

Unknown callees are not assumed to preserve global state. In particular, moving the reads of B or D ahead of F-9b9c1c7483f4 is not permitted by this contract. Moving the reads of A or C across earlier calls is likewise not justified without additional dependency guarantees.

Receiver reads also occur at specific stages. Initialization precedes the mode-word read. Nonnegative dispatch selection occurs after lookup processing; selection of `0x158` additionally follows the auxiliary operation and its temporary cleanup. The dispatch reference and target must not be treated as cached before those intervening calls.

### Local storage and ownership

The recovered representation exposes four-byte primary lookup storage, a four-byte lookup temporary, an eight-byte workspace, additional four-byte auxiliary regions, and a separate 32-bit local argument. Final-action stack-object boundaries are less certain.

Dependencies receive local addresses and may write through them. Their exact write extents and initialization guarantees are not established.

F-c1466ea05103, F-289ec4311c64, and F-8a5aadac202f occupy cleanup-like positions. This does not establish that they free memory, destroy objects, release references, or own their arguments.

No direct assignment to a receiver field or global slot is visible. That does not imply state preservation: dependencies may modify receiver-associated or global state. Pointer retention, aliasing, allocations, ownership transfers, and release obligations remain unknown.

### Errors and abnormal completion

There is no visible error-code propagation, retry, fallback, or local recovery mechanism.

Cleanup is established only when preceding calls return normally. No exception-safe, fault-safe, or nonlocal-transfer-safe cleanup guarantee is supported. A call that does not return can prevent later cleanup, dispatch, final actions, and the normal result `1`.

## Acceptance examples

These are conditional static obligations, not executed tests. They assume valid applicable accesses and normally returning calls unless stated otherwise.

1. **Negative selector, zero option.**  
   Selector `−1` and option `0` invoke `0x154` with unchanged inputs. No lookup processing or reads of slots A–D occur. The function returns `1`.

2. **Minimum selector, enabled final action.**  
   Selector `−2,147,483,648` takes the negative branch without negation. With a nonzero option, dispatch is followed by the C/resource/F-9b9c1c7483f4/D/consumer sequence and temporary cleanup.

3. **Zero selector and zero lookup result.**  
   Selector `0` enters lookup processing. A zero query result selects `0x15C`. Primary lookup cleanup follows dispatch. Slots A and B are not read.

4. **Mode high bits only.**  
   A mode word of `0x00000100` has a zero low byte and selects F-7cbb8ae2646e. A word of `0x00000080` selects F-6a21f4f07f67 followed by F-21712eedaa5c.

5. **Independent provider observations.**  
   When both provider calls occur and return different values, lookup construction uses the first and workspace processing uses the second.

6. **Nonzero lookup result, zero option.**  
   The A/resource/F-9b9c1c7483f4/B/consumer sequence and its cleanup precede selection of `0x158`. Primary lookup cleanup follows dispatch. Slots C and D are not read.

7. **Slot B changes during construction.**  
   If F-9b9c1c7483f4 changes slot B and returns, F-e475f4597093 receives the value subsequently read from that slot, not a target cached before construction.

8. **Slot D changes during final construction.**  
   If the final action’s F-9b9c1c7483f4 changes slot D, F-2b88fb7b0f1e receives the subsequently read target.

9. **Dispatch changes final resource state.**  
   If dispatch changes slot C, the final action reads the slot after dispatch and applicable primary cleanup. It does not reuse an earlier base.

10. **Negative option.**  
    Option `−1` is forwarded unchanged and enables the final action.

11. **Abnormal completion.**  
    If a selected operation does not return normally, subsequent cleanup, global reads, final actions, and return value `1` are not guaranteed.
