# F-9a60a29c64c1

## Purpose

F-9a60a29c64c1 compares two explicitly counted byte sequences. It can skip leading bytes below `0x21` and can compare ASCII letters without distinguishing uppercase from lowercase. Some comparisons are delegated to F-1bcdd7a98973 rather than completed locally.

The local comparison is lexicographic over unsigned byte values, optionally folding ASCII lowercase letters to uppercase. It returns a four-byte result representing less than, equal to, or greater than. A delegated comparison returns the dependency’s four-byte result unchanged; the supplied evidence does not establish that dependency’s result conventions.

This is a source-facing behavioral contract based on static evidence only. No runtime tests have been performed. The dependency’s behavior is documented_only where its implementation or contract is unavailable.

## Interface

### Inputs

The function accepts five positional inputs:

| Position | Meaning | Representation |
|---|---|---|
| 1 | Address of the first byte sequence | Byte pointer |
| 2 | Count associated with the first sequence | Signed integer, treated as 32-bit in the presented interface |
| 3 | Address of the second byte sequence | Byte pointer |
| 4 | Count associated with the second sequence | Signed integer, treated as 32-bit in the presented interface |
| 5 | Comparison options | Unsigned 32-bit bitmask |

The three relevant option bits are:

| Mask | Established effect |
|---|---|
| `0x01` | Enables ASCII case folding in the local comparison. In combination with `0x04`, selects immediate delegation after optional leading-byte skipping. |
| `0x02` | Enables independent skipping of leading bytes with unsigned values below `0x21`. |
| `0x04` | Changes dispatch only when `0x01` is also set. |

Other option bits do not affect any visible decision and are not forwarded to the dependency.

The inputs describe counted byte regions, not necessarily null-terminated strings. A byte with value zero is ordinary sequence data unless it is removed by leading-byte skipping.

### Output

The return value occupies four bytes.

When comparison completes locally:

- `0xFFFFFFFF`, interpreted as signed 32-bit `−1`, means the first sequence sorts before the second.
- `0x00000000` means the sequences compare equal.
- `0x00000001` means the first sequence sorts after the second.

When comparison is delegated, the dependency’s four-byte return value is propagated without normalization or interpretation.

For supported, bounded comparison, counts should be nonnegative and each pointer should address at least its corresponding count of readable bytes. Negative counts are not rejected, but do not represent a safely bounded sequence under the visible control flow.

A zero count prevents local dereferencing of that sequence. It does not establish that a null pointer is accepted by a delegated comparison.

No local requirement for writable input storage is visible. The two regions may overlap without creating a local write conflict because the visible implementation only reads them. Compatibility of overlapping, read-only, or null regions with F-1bcdd7a98973 remains unknown.

## Behavior

### 1. Optional leading-byte skipping

If option `0x02` is set, the function first processes the first sequence and then the second.

For each sequence, it skips consecutive leading bytes whose unsigned values are less than `0x21`. Each skipped byte advances that sequence’s working address by one byte and reduces its working count by one.

The skipped range includes:

- Zero bytes.
- Control-byte values `0x01` through `0x1F`.
- The space byte `0x20`.

The byte `0x21` is not skipped. Neither are larger values, including bytes at or above `0x80`.

A count is tested for equality to zero before its leading byte is read. If the count reaches zero, skipping stops without another byte read. Skipping also stops at the first byte at or above `0x21`; that byte remains part of the comparison.

Only the leading run is removed. Interior and trailing bytes below `0x21` are retained.

The first sequence’s skipping completes before the second sequence’s skipping begins. Consequently, even if the first sequence becomes empty, the second sequence is still processed for leading-byte skipping before comparison or delegation is selected.

If `0x02` is clear, the original addresses and counts are used unchanged.

### 2. Establishing the delegation arguments

After optional skipping, the function retains the resulting start addresses and prepares a narrowed version of each remaining count for possible delegation.

Each delegated count is obtained by retaining the low 16 bits of the corresponding remaining count, interpreting those bits as a signed 16-bit value, and sign-extending that value to the dependency’s integer argument width.

Under the presented 32-bit integer model:

| Remaining count | Count supplied on delegation |
|---:|---:|
| 0 | 0 |
| 32,767 | 32,767 |
| 32,768 | −32,768 |
| 65,535 | −1 |
| 65,536 | 0 |
| 65,537 | 1 |

This narrowing does not constrain the local comparison. Local scanning continues to use the full working counts.

The values prepared here correspond to the entire sequences remaining after leading-byte skipping. They do not subsequently change to describe only an unmatched suffix.

### 3. Selecting immediate delegation

If both `0x01` and `0x04` are set, the function delegates immediately after optional leading-byte skipping.

This dispatch occurs before local empty-sequence checks. Thus, even two zero-length inputs are passed to F-1bcdd7a98973 in this mode.

If either of those two bits is clear, the function enters the local comparison.

### 4. Local empty-sequence decisions

At each local comparison position, the first remaining count is checked before the second:

- If both remaining counts are zero, return zero.
- If only the first remaining count is zero, return `0xFFFFFFFF`.
- If the first remaining count is nonzero and the second is zero, return one.

No bytes are read for that comparison position when either count is zero.

For ordinary nonnegative counts, these rules make a proper prefix sort before the longer sequence when all preceding compared bytes are equal.

### 5. Reading and classifying a byte pair

When both working counts are nonzero, the function reads the current byte from the first sequence and then the current byte from the second sequence. Both bytes are interpreted as unsigned values.

Before applying case folding or determining a local ordering, the function checks whether either byte is at least `0x80`.

If either is at least `0x80`, local comparison stops and delegation occurs. This happens even if the two raw byte values already appear sufficient to determine an unsigned ordering. There is no local comparison of high-byte values.

The second byte is read even when the first byte is already at least `0x80`.

### 6. Comparing an ASCII-range pair

If both bytes are below `0x80`, they are compared locally.

When `0x01` is set, bytes in the inclusive range `0x61` through `0x7A` are mapped to `0x41` through `0x5A`. This is ASCII lowercase-to-uppercase folding. Other ASCII bytes are unchanged.

When `0x01` is clear, both bytes retain their original values.

The resulting unsigned byte values determine the result:

- First value greater than second: return one.
- First value less than second: return `0xFFFFFFFF`.
- Equal values: advance both local cursors by one byte, decrement both full working counts by one, and continue.

The local result reports only ordering, not the numerical difference between bytes.

### 7. Delegating the comparison

Both immediate delegation and high-byte-triggered delegation invoke F-1bcdd7a98973 with these five positional arguments:

1. First sequence’s address after optional leading-byte skipping.
2. Second sequence’s address after optional leading-byte skipping.
3. First post-skipping count, narrowed through signed 16-bit interpretation.
4. Second post-skipping count, narrowed in the same way.
5. Integer zero.

In particular, encountering a high byte after an equal ASCII prefix does **not** pass advanced cursors or residual suffix counts. The dependency receives the post-skipping starts and counts for the whole remaining sequences.

The original options bitmask is not passed. No visible argument distinguishes immediate delegation from delegation caused by a high byte.

The function returns the dependency’s result unchanged.

## Acceptance examples

These examples specify conditional expectations from static evidence. They are not runtime test results. Byte regions are assumed stable and readable for every required local read.

### Empty inputs on the local path

With both counts zero and options zero, the result is zero and neither sequence is read.

With first count zero, second count positive, and options zero, the result is `0xFFFFFFFF` without reading either sequence.

With first count positive, second count zero, and options zero, the result is one without reading either sequence.

### Case-sensitive ASCII ordering

With one-byte sequences `a` and `A`, and options zero, the first sequence sorts after the second and the result is one.

With the same sequences and option `0x01`, they compare equal and the result is zero.

### Prefix ordering

With the byte sequences `ab` and `abc`, counts two and three, and options zero, the result is `0xFFFFFFFF`.

No third byte is read from the first sequence.

### Leading-byte skipping

With first bytes `[0x00, 0x20, 0x41]`, count three, second bytes `[0x41]`, count one, and option `0x02`, the sequences compare equal.

With first bytes `[0x41, 0x20]`, count two, second bytes `[0x41]`, count one, and option `0x02`, the result is one. The trailing space is not removed.

With first bytes `[0x21]` and second bytes `[0x22]`, both count one and option `0x02`, the result is `0xFFFFFFFF`; neither byte is skipped.

### Zero as counted data

With first bytes `[0x00, 0x41]`, second bytes `[0x00, 0x42]`, both count two and options zero, the result is `0xFFFFFFFF`.

The initial zero bytes do not terminate comparison.

### Immediate delegation

With both counts zero and options `0x05`, F-1bcdd7a98973 is called with the supplied sequence addresses, zero counts, and a final zero argument.

The wrapper’s result equals the dependency’s return value, whatever that value is.

### High-byte delegation after an equal prefix

With first bytes `[0x41, 0x80]`, second bytes `[0x41, 0x7F]`, both count two and options zero, the initial `0x41` bytes compare equal. At the next position, both bytes are read and delegation occurs.

The dependency receives the original sequence starts and counts two and two—not addresses advanced to the second bytes and not counts one and one.

### Narrowed delegated counts

For valid regions with counts 65,536 and 32,768, no leading-byte skipping, and options `0x05`, the dependency receives count arguments zero and −32,768.

No equality or ordering result is established without the dependency’s behavior for those arguments.

### Irrelevant option bits

For inputs that remain on the local path, setting an otherwise unused option bit does not change the visible comparison rules.

Option `0x04` alone does not force delegation. If the examined bytes remain below `0x80`, the local comparison proceeds without case folding.
