# F-30eab0f78d76

## Purpose

F-30eab0f78d76 performs a state-dependent update on a caller-supplied object, then updates a word in an associated record and conditionally invokes an indirect target.

The established behavior has three phases:

1. Capture an associated-record address and pass it to F-4a19e3742733.
2. Depending on the object’s subsequently observed state byte, optionally process a local copy of the fourth argument, invoke F-69897767c9a8, and possibly clear the state byte.
3. Decrement a word in the captured associated record, inspect a pointer stored in that record, and conditionally invoke an indirect target.

Names such as “object,” “associated record,” and “state” describe the visible structure without assigning a business purpose. A reference-counting or lifecycle interpretation of the final decrement is plausible but not established.

This contract describes static evidence only. No runtime tests have been performed.

## Behavior

### 1. Capture the record and preserve the fourth argument

The function first reads the associated-record pointer from object offset `+0x78`. It retains this address for later accesses.

It then copies the fourth argument into a local 32-bit slot and calls F-4a19e3742733 with the captured associated-record address.

The record address is not visibly reloaded from the object afterward. If a dependency replaces the object’s pointer field, the final record operations still use the captured address. This is an address-selection rule, not a guarantee that the original record remains alive.

The state byte controlling the next phase is read after F-4a19e3742733 returns. Consequently, changes made by that dependency can affect branch selection.

### 2. Evaluate the state-dependent branch

The visible comparison subtracts four from the byte read at object offset `+0x74` and tests whether the result is less than eight.

**Under the signed integer-promotion semantics of the supplied expression, the branch is taken for state values 0 through 11 inclusive.** The byte is promoted before subtraction; values 0 through 3 therefore produce negative results, which are also less than eight.

This must not silently be rewritten as a 4-through-11 range check. That narrower interpretation would require unsigned subtraction or equivalent machine-level evidence not supplied here. The uncertainty concerning the underlying comparison is documented in **Uncertainties**.

If the comparison is false, the function skips all operations in this phase and proceeds directly to the final record update.

If the comparison is true, it calls F-710e3fad34a6 with the address at object offset `+0x38`.

#### Nonzero predicate result

If F-710e3fad34a6 returns a nonzero integer, the following calls occur in order:

1. F-cd649951dc44 receives the address of the local 32-bit slot, followed by two zero-valued arguments.
2. Its 32-bit result is passed as the second argument to F-c7df69c08022. The first argument to that call is the address at object offset `+0x38`.
3. F-3325914cfb67 receives the address of the same local slot.

The slot initially contains the fourth argument. F-cd649951dc44 may change it through the supplied address, so F-3325914cfb67 receives access to the slot’s then-current contents, not necessarily the original value.

No explicit copy-back to a caller-provided location is shown. The fourth argument itself is a by-value input.

#### Zero predicate result

If F-710e3fad34a6 returns zero, all three calls above are skipped. In particular, F-3325914cfb67 is not invoked on this path.

#### Common branch completion

Regardless of whether the predicate result was zero or nonzero, the taken branch next calls F-69897767c9a8 with the original first argument.

After that call returns, the function reads the state byte at object offset `+0x74` again. If this newly read value is below six, it writes a zero byte to that location. Otherwise, it performs no explicit state-byte write.

The second state test uses a fresh read, not the value that selected the branch. Changes made by any intervening dependency can therefore determine whether the zero write occurs.

### 3. Update and inspect the captured record

After the conditional phase, the function reads the 32-bit word at offset `+0x08` in the captured associated record, subtracts one, and writes the result back.

There is no visible test for zero before the decrement and no visible saturation or underflow handling. Interpreting this as fixed-width unsigned arithmetic gives a result of `0xffffffff` when the word is initially zero. Exact machine overflow behavior remains subject to the arithmetic-representation qualification in **Uncertainties**.

Only after that write does the function load the pointer at record offset `+0x00`.

- If the pointer is null, the function does not dereference it and does not make the indirect invocation.
- If the pointer is non-null, the function reads its first integer word.
- If that word is zero, the function does not make the indirect invocation.
- If that word is nonzero, the function invokes the indirect target held in a separate statically referenced slot.

The indirect target is not visibly obtained from the record pointer or from the integer word just tested. Those values gate the invocation; they do not identify the target.

No explicit arguments are shown for the indirect call. There is no subsequent visible record access or state update. If the target returns normally, this function returns.
