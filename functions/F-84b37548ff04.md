# F-84b37548ff04

## Purpose

F-84b37548ff04 conditionally updates an integer-valued field in caller-supplied storage. If the stored value already equals the requested value, it returns without performing the update or invoking either downstream operation. Otherwise, it stores the requested value, invokes F-bf0d937c970b with the same object pointer, and then invokes an indirectly selected operation with that pointer.

This is a change-triggered operation: equality suppresses both downstream invocations, not merely the write.

The field’s application meaning is unknown. Interpreting the two downstream operations as recalculation, notification, invalidation, or rendering would go beyond the supplied evidence.

## Behavior

### Equality path

The function first reads the second integer element and compares it with the requested value.

If they are equal, it returns immediately.

On this path, the function itself performs:

- No assignment to the comparison field.
- No invocation of F-bf0d937c970b.
- No dispatch-base lookup.
- No indirect invocation.

Consequently, the equality path does not require the first element to contain a usable dispatch base. It still requires the comparison-field read to be valid.

### Changed-value path

If the comparison is unequal, the function performs these actions in the following program order:

1. Stores the requested value in the second integer element.
2. Invokes F-bf0d937c970b with the original object pointer.
3. After that invocation returns, obtains a dispatch base from the first integer element.
4. Selects the callable entry at a 16-byte displacement from that base.
5. Invokes the selected operation with the original object pointer.
6. Returns if the selected operation returns normally.

The store precedes the dependency invocation. Thus, at the call boundary, the caller has assigned the requested value before transferring control. This does not guarantee that the dependency observes or preserves that value: its implementation is unavailable.

### Post-dependency dispatch

The dispatch base is obtained **after** F-bf0d937c970b returns. The function does not preserve a pre-call dispatch base for later use.

If F-bf0d937c970b validly changes the first element, the later dispatch follows the resulting base. If it invalidates the object or installs an unusable base, this function supplies no recovery path.

Similarly, the function does not recheck or restore the comparison field after the dependency returns. If the dependency changes that field, the indirect operation runs without a second equality decision and without another assignment by F-84b37548ff04.

### No downstream suppression after a change

Once the initial inequality has selected the changed-value path, there is no further condition in this function that suppresses the indirect invocation.

Subject to F-bf0d937c970b returning and the dispatch remaining valid:

- Changing the comparison field again does not cancel dispatch.
- Restoring the old comparison value does not cancel dispatch.
- Changing the dispatch base can alter the selected operation.
- No visible return value from F-bf0d937c970b controls the next step.
