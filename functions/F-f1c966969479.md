# F-f1c966969479

## Purpose

F-f1c966969479 conditionally delegates an operation associated with an indexed object entry. It initializes a caller-supplied output header, checks the index against a count, resolves dependency arguments through two object relationships, and invokes F-5ef10d079522 with output storage immediately following that header.

On the delegated path, it returns the dependency’s 32-bit result unchanged and replaces the output header with a 16-bit value derived from a dependency-modifiable 32-bit quantity.

**Established behavior:** the wrapper performs initialization, validation, argument resolution, delegation, and header postprocessing.

**Inferred intent:** the output may be a two-byte header followed by a dependency-produced payload. Neither the meaning of the header nor the payload format is established.

This contract describes static evidence only. No runtime tests have been performed.

## Interface

### Inputs and result

The visible interface has three arguments:

| Argument | Source-facing interpretation |
|---|---|
| Object address | A 32-bit address identifying storage with the fields and indirect relationships described below. |
| Index | A 32-bit unsigned quantity, additionally checked through a signed 32-bit interpretation. |
| Output address | An address used first for a two-byte write, then as the base of output storage passed to a dependency. |

The function returns a 32-bit quantity:

- On validation rejection, the return bit pattern is `0xFFFFFFCE`, equivalent to −50 when interpreted as signed 32-bit.
- On delegation, the return bit pattern is exactly the result supplied by F-5ef10d079522.

No success-code convention for the delegated result is established.

### Addressed layouts

All offsets below are byte offsets. The visible accesses use 32-bit addresses and 32-bit pointer-bearing fields.

The object supplies:

- At offset `0xEF4`: a 32-bit unsigned entry count.
- At offset `0xEEC`: a 32-bit address of an entry-address table.

For an accepted index, the selected table slot is located at the table address plus four times the index. That slot supplies a 32-bit entry address. Further argument resolution reads:

1. A 32-bit address at entry offset `0x20`.
2. A 32-bit value at offset `0x28` from that address.

F-8ff48652068d supplies another address. At offset `0xF60` from that returned address, the wrapper reads a 32-bit address and adds `0xC0`. The resulting address is passed to F-5ef10d079522.

The output storage is addressed as:

- Bytes 0–1: the wrapper’s 16-bit header.
- Starting at byte 2: storage passed to F-5ef10d079522.

The dependency’s required payload capacity, alignment, and layout are not established.

### Preconditions for defined completion

The output address must support a two-byte write **before any validation occurs**. A null output address is therefore not a supported way to request validation without output.

On a delegated path, every traversed field, table slot, and indirect address must support the indicated access. The address derived from F-8ff48652068d must also be suitable for the subsequent field read and dependency invocation.

The wrapper provides no visible output-capacity argument. A caller must satisfy whatever storage requirements F-5ef10d079522 imposes; those requirements cannot be recovered from this wrapper alone.

## Behavior

### 1. Unconditional output initialization

The first visible operation writes the 16-bit value zero at the output address.

This write precedes:

- The output-address null comparison.
- Both index checks.
- The object count read.
- Either dependency invocation.

Consequently, an invalid output address can cause an invalid memory access before the function can take its rejection path. The later null comparison does not establish null safety.

The initial write also matters when output storage aliases object metadata or other inputs: any later reads observe storage after this write, subject to the execution environment’s memory semantics.

### 2. Validation

After initialization, the wrapper evaluates a short-circuit condition:

1. The output address must be non-null.
2. The index, interpreted as signed 32-bit, must be nonnegative.
3. The index, interpreted as unsigned 32-bit, must be less than the 32-bit count read at object offset `0xEF4`.

Thus the accepted numeric range is:

- Index at most `0x7FFFFFFF`; and
- Index strictly less than the count observed by this check.

A count greater than `0x7FFFFFFF` does not permit indices with the high bit set.

The count is read only after the preceding conditions pass. In particular, a high-bit-set index is rejected without the count read, assuming the initial output write completes.

If validation fails, the wrapper returns `0xFFFFFFCE`. It makes no visible call to either dependency on this path. Its own output effect is the initial two-byte zero write.

### 3. Resolve auxiliary state

For an accepted index, the wrapper calls F-8ff48652068d with the object address.

No validation of the returned address is visible. The wrapper subsequently uses it to locate the 32-bit field at offset `0xF60`.

The dependency call occurs after the count check. Nothing establishes that F-8ff48652068d preserves the object, its count, its entry table, output storage, or global state. The wrapper does not repeat validation after this call.

The wrapper then initializes a private 32-bit mutable quantity to the original index. Its address will be passed to F-5ef10d079522.

### 4. Resolve and pass delegation arguments

F-5ef10d079522 receives five arguments, in this positional order:

1. The address obtained by reading the field at offset `0xF60` from the F-8ff48652068d result, then adding `0xC0`.
2. The 32-bit value obtained through the selected entry-table slot and the additional offsets `0x20` and `0x28`.
3. The output address advanced by two bytes.
4. The address of the private 32-bit mutable quantity initialized to the original index.
5. The value supplied by a global datum.

These arguments must be resolved before F-5ef10d079522 begins. The displayed call does not establish the relative evaluation order among the independent argument expressions. In particular, it does not establish whether the global datum is read before or after the auxiliary-state field or entry-table chain.

Within the entry-table chain, each dependent address must be obtained before the next dependent read can occur.

The wrapper does not visibly check:

- Any address traversed during argument resolution.
- The selected entry’s validity beyond the earlier index/count comparison.
- Output capacity.
- The global datum’s validity or meaning.

### 5. Postprocess the mutable quantity

If F-5ef10d079522 returns normally, the wrapper saves its 32-bit result and reads the current value of the private mutable quantity.

It computes a 16-bit header from that current value using a 32-bit unsigned left shift by 15 followed by a logical right shift by 16, then a conversion to a 16-bit value.

The resulting stored bit pattern is equivalently:

**Bits 1 through 16 of the mutable quantity, placed into header bits 0 through 15.**

This is also expressible as the low 16 bits of the quantity shifted right by one. The distinction from an unrestricted right shift is important: original bits 17 through 31 do not contribute.

Specific consequences:

- Original bit 0 is discarded.
- Original bit 16 becomes the header’s high bit.
- The header can contain any 16-bit pattern, including `0x8000` through `0xFFFF`.
- No saturation, range check, or error interpretation is applied.

The wrapper writes this header over output bytes 0–1 and then returns the saved dependency result unchanged.

This final write occurs regardless of whether that result would conventionally denote success or failure. Only normal dependency return is required for the visible postprocessing path.

## Side effects

### Wrapper-owned effects

The wrapper visibly performs:

- One initial two-byte zero write to the output header.
- Conditional reads of object metadata and indirect entry storage.
- One call to F-8ff48652068d on the accepted path.
- Initialization of private four-byte mutable storage.
- One call to F-5ef10d079522 on that path.
- A final two-byte output-header write after normal dependency return.

The final header write is the wrapper’s last visible output-memory operation. It overwrites any changes the dependencies may have made to those same two bytes during their calls.

### Dependency-mediated effects

Both dependencies may have effects not visible in this wrapper. No preservation of globals, object state, or unrelated storage is assumed.

### Ownership and lifetime

The pointer to the private 32-bit quantity is usable during the F-5ef10d079522 call. Its validity after this invocation ends is not established; the wrapper provides no persistent allocation for it.

The dependencies’ retention or release of any other supplied or derived address is unknown. This contract does not infer ownership from pointer passing.
