# F-5f23e610a3a5

## Purpose

F-5f23e610a3a5 acquires access to a resource through a context, obtains a 64-bit saved value, queries a record, and requests a change using a 32-bit value read from that record plus a caller-supplied adjustment. If the change and a subsequent query both succeed, it writes a 32-bit difference to caller-provided storage.

The established contract concerns dependency calls, argument provenance, status handling, arithmetic, and memory accesses. Interpreting the operation as changing a file’s length while preserving its position is plausible intent, not an established dependency contract.

Two forms of mutable temporary storage are behaviorally significant:

- Each resource-token argument is read anew from the storage supplied to the acquisition dependency.
- The first query record’s relevant field is read at three distinct points on the fully successful path. These reads need not yield the same value.

The function initializes the result destination before calling any dependency. After the target-changing dependency succeeds, the function returns zero even if the second query reports failure.

## Interface

The function accepts four arguments and returns a 32-bit status-like value.

| Argument | Established representation and use |
|---|---|
| Context | A 32-bit address-bearing integer. The acquisition dependency receives an address formed by adding 40 bytes. The error dependency receives the original context value. |
| Selector | An opaque 32-bit value forwarded unchanged to the acquisition dependency. |

The directly selected return values are `3` when acquisition reports a zero low word and `0` after a successful target-changing call. On other handled failure paths, the return value is the low 32 bits supplied by F-10684331fba7.

### Preconditions and temporary layouts

The context-relative address must satisfy F-c17dbd9c1a69’s requirements. This function does not directly inspect the context-relative object. Validity of the address computation, including boundary and overflow behavior, is not established for arbitrary context values.

## Behavior

### 1. Initial write and acquisition

The first explicit caller-directed write stores a 32-bit zero at the result destination.

F-c17dbd9c1a69 is then called with:

1. The address 40 bytes beyond the context.
2. The selector.
3. The address of the temporary resource-token storage.

Its return value is 64 bits. Only its low 32 bits determine acquisition success:

- A zero low word causes immediate return of `3`.
- A nonzero low word permits execution to continue.

The high word does not affect this branch. On the continuing path, it becomes the second argument of the first F-58205e0d2cf0 call.

There is no call to F-10684331fba7 on the direct return of `3`.

Acquisition receives the token storage’s address, not merely a request to produce an immutable token. Its unavailable contract does not establish that it discards that address after returning.

### 2. Obtaining the saved 64-bit value

F-58205e0d2cf0 receives, in argument order:

1. The 32-bit word read from resource-token storage for this call.
2. The high 32 bits of the acquisition return value.
3. Zero.
4. Zero.
5. One.

The full 64-bit return is saved. The all-ones 64-bit representation is the failure sentinel. No other returned representation is visibly rejected.

If the sentinel is returned, F-10684331fba7 is called with the original context, and its low 32 bits become this function’s return value. No query, target-changing call, or final F-58205e0d2cf0 call follows.

The saved value is retained as a 64-bit value for a possible final call. It is distinct from the mutable token storage and query-record fields.

### 3. First query

After a non-sentinel saved value, F-fe10661921b5 is called with:

1. A fresh read of resource-token storage.
2. The address of the first query record.

A zero low return word indicates success for this function’s control flow. A nonzero low word causes F-10684331fba7 to be called with the original context; the function then returns that dependency’s low 32 bits.

There is no final F-58205e0d2cf0 call on this first-query failure path, despite the earlier successful saved-value call.

The first query receives the record’s address. No available contract prevents it from retaining that address or prevents later dependency activity from modifying the record.

### 4. Target calculation and target-changing call

On first-query success, the function reads the unsigned 32-bit field at offset 20 of the first record to calculate the target.

This is the **target-calculation read**. Its value is not captured as an immutable baseline for all subsequent uses.

The target is the target-calculation read plus the adjustment, reduced modulo \(2^{32}\). The unsigned field causes the addition to use unsigned 32-bit arithmetic. A negative adjustment participates through its corresponding 32-bit representation. There is no visible overflow error, negative-target rejection, saturation, or range check.

F-68f6a5ca4b63 receives:

1. A fresh read of resource-token storage.
2. The high 32 bits returned by the first query.
3. The calculated 32-bit target.
4. Zero.

The final argument remains zero even when target arithmetic wraps. No carry or sign extension is propagated into that argument.

The supplied source establishes the provenance of the token and target arguments, but not a relative evaluation order between the token read and the field read within this call’s argument preparation.

### 5. Target-changing failure

A nonzero 32-bit return from F-68f6a5ca4b63 selects the failure path.

F-10684331fba7 is called with the original context. Both words of its 64-bit return matter:

- The low word selects this function’s eventual return value.
- The high word selects the second argument of the final F-58205e0d2cf0 call.

No second query occurs, and this function makes no second explicit write to the result destination.

The final call still occurs if the error dependency returns normally.

### 6. Target-changing success and second query

A zero return from F-68f6a5ca4b63 causes another F-fe10661921b5 call, with:

1. A fresh read of resource-token storage.
2. The address of the separate second query record.

The second query’s low return word determines whether the function writes a difference.

#### Second query reports success

When the low word is zero, the function obtains operands from:

- The signed 32-bit field at offset 20 of the second record.
- A new read of the unsigned 32-bit field at offset 20 of the first record.

The latter is the **difference-calculation read**. It occurs after the second query has returned. It is not necessarily equal to the earlier target-calculation read: the target-changing dependency, the second query, or other dependency-visible activity may have modified the first record.

The function subtracts the difference-calculation read from the second record’s field using unsigned 32-bit arithmetic, then stores the resulting 32-bit value through the signed result pointer. No visible saturation or range rejection occurs. For values outside the signed range, the source’s conversion to signed storage does not itself establish a portable numeric interpretation; the modulo-\(2^{32}\) difference specifies the arithmetic result.

The operand-read order within the subtraction is not established here. Both operands are obtained before the result write.

After writing the result, the function reads the first record’s unsigned field again. This is the **final-forwarding read**. It selects the second argument of the final F-58205e0d2cf0 call.

This third read must not be replaced contractually by either earlier value. It follows the result write, so even equality with the difference-calculation read requires appropriate storage-stability and noninterference assumptions.

This path selects a return value of zero.

#### Second query reports failure

When the low word is nonzero:

- The function does not consume the second record’s field for a difference.
- There is no second explicit result write.
- The two later reads of the first record are not performed.
- F-10684331fba7 is not called.
- The second query’s high return word selects the final call’s second argument.
- This function still selects a return value of zero.

Thus, second-query failure is not propagated as a nonzero function return.

## Side effects

The explicit caller-directed writes are:

1. A 32-bit zero before acquisition.
2. A calculated 32-bit difference only after first-query success, target-changing success, and second-query success.

The second write precedes the final-forwarding read and final dependency call. Neither stored-result preservation nor first-record stability is guaranteed against dependency effects or aliases.

Resource-token storage is read independently for each executed call that takes a token:

- The initial F-58205e0d2cf0 call.
- The first query.
- The target-changing call.
- The second query, when reached.
- The final F-58205e0d2cf0 call, when reached.

## Acceptance examples

These are conditional static acceptance cases, not executed tests. Final result-storage expectations assume no independent dependency write overwrites that destination. Examples equating multiple first-record reads additionally assume that record’s relevant field remains unchanged across those reads.

1. **Acquisition failure.**  
   If acquisition returns a zero low word, the result is first initialized to zero, the function returns `3`, and no other dependency is called.

2. **Saved-value failure.**  
   If the first F-58205e0d2cf0 return is all ones and F-10684331fba7 returns low word `9`, the function returns `9`. No final call occurs.

3. **First-query failure.**  
   A nonzero first-query low word selects F-10684331fba7 and immediate return of its low word. There is no target-changing call, second query, or final call.

4. **Stable-record successful change.**  
   Assume the first record’s field remains `100` through all three reads, the adjustment is `25`, and the successful second query supplies `125`. The requested target is `125`, the difference written is `25`, the final call’s second argument is `100`, and the return is zero.

5. **Target wraparound.**  
   A target-calculation read of `0xFFFFFFF0` and adjustment `32` produce target `0x00000010`. The fourth target-changing argument is zero. No overflow status is generated by this function.

6. **Negative adjustment with stable record.**  
   Assume all three first-record reads yield `100`, the adjustment is `−20`, and the second record supplies `80`. The target is `80`; the modulo difference is `0xFFFFFFEC`. A signed interpretation as `−20` depends on the representation and conversion rules.

7. **First record changes between queries.**  
   Suppose the target-calculation read is `100`, the adjustment is `25`, and the first record becomes `110` before the successful second query returns `125`. If it then remains `110`, the target is `125`, the output difference is `15`, and the final second argument is `110`, not `100`.

8. **First record changes after the output write.**  
   If the difference uses first-record value `110`, but the final-forwarding read observes `120`, the difference still uses `110` while the final call’s second argument is `120`. This is conditional on an allowed mechanism actually changing that storage between the reads.

9. **Token storage changes.**  
   If acquisition writes token word `A` and a permitted dependency effect later changes the storage to `B`, calls before the change use their reads of `A`; calls afterward use their reads of `B`. The function does not require later arguments to reuse `A`.

10. **Second-query failure.**  
    A nonzero low word and high word `H` cause no second explicit output write. The final call receives `H` as its second argument, and the function returns zero.

11. **Target-changing failure.**  
    If the error dependency returns low word `7` and high word `H`, the final call receives `H` as its second argument, and the function returns `7`.

12. **Final-call failure.**  
    A failure-valued final return does not alter the already selected function status. Any independent memory effects of that call remain outside this function’s guarantees.
