# F-2b0e3ae2b483

## Purpose

F-2b0e3ae2b483 converts four byte-sized values in an input region into four canonical Boolean-mask bytes in an output region.

For each input byte, zero produces `0x00`; every nonzero value produces `0xFF`. The output preserves the positional correspondence of the four selected input bytes, even though their observable read order differs from their ascending address order.

This is a memory-writing operation with no returned value. The supplied static evidence establishes the byte transformation and access sequence. It does not establish the application meaning of these bytes.

## Behavior

### Value transformation

Each selected input byte is tested only for equality with zero. Its magnitude and sign do not otherwise affect the result.

Consequently:

- `0x00` produces `0x00`.
- `0x01` produces `0xFF`.
- `0x7F`, `0x80`, and `0xFF` also produce `0xFF`.

The output is a mask representation, not a numeric zero-or-one representation. Nonzero input values are not copied through.

Any uncertainty about whether the input byte is treated as signed or unsigned does not change this result: the relevant distinction is zero versus nonzero.

### Read order and retained values

The supplied static representation establishes this source-read order:

1. Source offset `0x7C`.
2. Source offset `0x7D`.
3. Source offset `0x7F`.
4. Source offset `0x7E`.

Each selected byte is read once in that representation. All four source reads precede every destination write.

The fourth-position input, at offset `0x7F`, is therefore read before the third-position input, at offset `0x7E`. Its observed value is retained for the later production of destination offset `0x03`; it is not read again after output writing begins.

This ordering is relevant when the input changes between reads or when source and destination overlap. The reads do not constitute an atomic snapshot: the four observed values need not have existed together at a single instant.

### Write order

After the source reads, destination writes occur in ascending offset order:

1. Destination offset `0x00`.
2. Destination offset `0x01`.
3. Destination offset `0x02`.
4. Destination offset `0x03`.

Each write stores the canonical mask corresponding to the mapped source byte. There is no conditional omission of a destination byte. On normal completion, all four bytes have been overwritten.

The static representation contains no additional memory writes.

### Overlapping regions

The function does not reject overlapping source and destination regions.

Because every source byte is read before the first destination write, overlap does not, by itself, cause an output write to replace an input value before that input has been observed. The transformation uses the values obtained during the initial read sequence.

If the destination overlaps the source region, the writes can nevertheless alter that region’s final contents. There is no promise that the source remains unchanged when the caller supplies aliases to it.

This overlap behavior is established by the supplied access sequence. It is not a broader guarantee about concurrent access, device memory, or compiler-level aliasing rules outside the supplied representation.

### Completion and interruption

With valid accessible memory and no intervening execution failure, the function completes after the fourth destination write.

There is no visible recovery path. If a memory access fails, no defined error result or rollback is provided here. The read-before-write sequence means that no destination write is represented before all four source reads have occurred. Once writing begins, however, the function provides no transactional protection: interruption can leave an already-written prefix of the destination updated.

The specific behavior of an invalid memory access—such as a process fault, an exception, or another platform response—is outside the supplied evidence.
