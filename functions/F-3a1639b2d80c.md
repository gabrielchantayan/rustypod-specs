# F-3a1639b2d80c

## Purpose

F-3a1639b2d80c conditionally clears two byte-sized fields in storage reached through a global base reference.

The condition compares the byte at offset 9 from the globally referenced base with a supplied 32-bit unsigned value. If the values are equal, the function writes zero to a byte at offset 9 and then writes zero to a byte at offset 5. If the values differ, it performs neither write.

**Inferred intent:** this may be a conditional reset of a selector and an associated status field. The supplied evidence does not establish either field’s meaning. Field names, object type, and any broader reset semantics are therefore outside this contract.

The function does not return a result indicating whether the comparison matched.

## Behavior

### Global-reference use and access order

The supplied body does not use one captured base consistently for every access. At the level of the represented operations, it:

1. Captures the global base for the possible later write at offset 5.
2. Consults the global reference for the byte read at offset 9.
3. Compares that byte with the full unsigned comparison argument.
4. On equality, consults the global reference for the byte write at offset 9.
5. Writes zero at offset 5 relative to the base captured initially.

The comparison read precedes both conditional writes. On the matching path, the offset-9 write precedes the offset-5 write.

This distinction matters if the global reference can change during execution. The base used for the comparison, the base used for the offset-9 write, and the initially captured base are not proven to be identical under such conditions.

The evidence establishes this source-level distinction, not a guarantee of separately observable hardware loads. Volatility, synchronization, compiler memory-order guarantees, and the legality of concurrent mutation are not provided.

### Comparison semantics

The stored comparison field is an unsigned eight-bit quantity, with a numeric range of 0 through 255. Its value is compared with the unsigned 32-bit argument without truncating that argument.

Examples of the comparison boundary:

- A stored value of 255 can match an argument of 255.
- A stored value of 255 cannot match an argument of 4,294,967,295.
- A stored value of zero cannot match an argument of 256.
- Any argument greater than 255 necessarily takes the nonmatching path, provided the required read completes normally.

There is no masking, signed-byte interpretation, range correction, or special sentinel treatment established by the body.

### Matching path

When the values compare equal:

- The function writes the eight-bit value zero at offset 9 relative to the global base consulted for that write.
- It then writes the eight-bit value zero at offset 5 relative to the initially captured base.
- It returns without a result value.

Both writes occur even if either destination already contains zero. The function does not first inspect the byte at offset 5.

With a stable global reference and ordinary valid memory, the two destinations belong to the same referenced region. Without that stability assumption, the function does not establish that relationship.

### Nonmatching path

When the values compare unequal, the function returns without either explicit byte write.

The function still reads the global reference and the byte needed for comparison. A nonmatching argument therefore does not make invalid comparison storage safe to access.

### Repeated calls

With a stable base and no intervening changes, a successful call leaves the offset-9 byte equal to zero.

A subsequent call with a nonzero comparison argument then takes the nonmatching path. A subsequent call with a zero argument takes the matching path and performs both zero writes again.

This is a conditional statement about unchanged external state, not a guarantee that callers or other execution contexts leave the storage untouched.
