## Acceptance examples

These are conditional static criteria, not executed tests.

1. **Extent masking.** If the initial word 6 is `0x12340080`, output preparation receives size 128 and the first terminal-table store targets **B + 126**, regardless of its upper 16 bits.

2. **Stable ordinary mode.** If word 79 remains zero, the header conversion receives 2, the common mode conversion receives 0, and construction ends after the **E − 6** entry. No extended secondary-field read is directly performed.

3. **Changing mode.** If successive mode reads observe zero, nonzero, then zero, the header uses 2, the common mode field uses 2, and extended construction is skipped. A single cached mode decision is not equivalent.

4. **Context timing.** If the conversion of 14 changes the shared context, the subsequent context load observes that changed value. Later changes to the shared context do not themselves cause a reload for another name call.

5. **Embedded-data mutation.** If conversion of a payload’s first embedded chunk changes the next chunk, the later read uses the changed next chunk. Preloading both chunks would not preserve this read order.

6. **Optional truncation.** If the optional branch is taken and word 84 reads as `0x12348001`, its 16-bit conversion receives `0xc001`.

7. **Initial name failure.** A nonzero initial status requires a fallback invocation using the named fallback object and captured context. Acceptance cannot require exact fallback bytes or a successfully repaired primary-name destination.

8. **Width and wrap.** An extended offset-41 assignment stores one byte, not two. A word-4 increment from `0xffffffff` supplies zero to the relevant 32-bit conversion. A signed-truncated cursor pattern of `0x8000` must not be treated as positive 32768.
