# F-0aae84e90f47

## Purpose

F-0aae84e90f47 coordinates an unconditional indirect operation with two independently conditional uses of another indirect-call slot.

The established behavior is an ordered sequence:

1. Capture a base address from shared storage.
2. If an optional target selected through shared storage is non-null, invoke it with the supplied argument and zero.
3. Invoke the mandatory target selected through the captured base address with the supplied argument.
4. Reload the optional slot through the captured base address. If it is non-null, transfer control to that target with zero and one.

The optional target used before the mandatory operation is not retained for the final invocation. The final target is read again after the mandatory invocation, so intervening changes can alter or suppress that invocation.

An inferred interpretation is that the optional slot implements a paired notification around the mandatory operation. That interpretation is not an established requirement: neither matching callback identities nor successful completion of a pair is enforced.

- One 32-bit argument, designated **X**.
- Its interpretation is unspecified. It may represent a number, token, address, or another four-byte value.
- The wrapper performs no visible arithmetic, range check, dereference, or conversion on X.
- X is supplied as the first argument to the initial optional invocation and as the sole argument to the mandatory invocation.
- X is not supplied to the final optional invocation.

**Result**

- No explicit result value is established for this function.
- Return values from the indirect invocations are not used by the visible behavior.
- Normal completion depends on the invoked targets returning or otherwise permitting the observed control flow to complete.

**Shared-state input**

The function reads a shared storage location containing a base address. Call this location **G**.

The selected region has two relevant slots:

| Byte offset from base | Role | Invocation arguments |
|---|---|---|
| +0x24, or 36 | Mandatory indirect target | X |
| +0x30, or 48 | Optional indirect target | Initially X and 0; finally 0 and 1 |

These are byte offsets, not element indices. The locations are separated by 12 bytes. No intervening fields, object header, allocation size, or surrounding structure layout is established.

The recovered representation uses a 32-bit integer for the captured base address and a four-byte input. A 32-bit address and function-pointer model is consistent with that representation, but the precise machine ABI and function-pointer storage width are not independently established.

**Preconditions for normal execution**

- Every base address actually used for a slot read must identify accessible storage at the required offset.
- The mandatory slot must contain a valid, callable target when it is read.
- A non-null optional target must be callable using the argument shape used at that particular invocation.
- The captured region must remain accessible for later reads even if a dependency changes G.
- Indirect targets must return normally if normal completion of the whole sequence is required.

These are execution requirements, not conditions that the wrapper checks or reports.

## Behavior

### Base capture and initial optional invocation

The function first reads G and retains that value as the **captured base**.

The initial optional-slot check is expressed through G again, rather than through the captured base. The slot at offset +0x30 from that selected base is read and compared with null.

If that slot is null, the initial optional invocation is omitted.

If it is non-null, the initial invocation target is obtained through G and its +0x30 slot, and is invoked with:

- first argument: X;
- second argument: integer zero.

The supplied representation does not retain the pointer used for the null check as the pointer necessarily used for invocation. Consequently, the contract must not strengthen the initial operation into a single atomic “read once, then call that same value” action.

No dependency invocation is shown between the initial null check and selection of its invocation target. In ordinary stable storage, both selections therefore identify the same target. Behavior under concurrent mutation, asynchronous modification, or unusual memory semantics is not established.

### Mandatory invocation

After the initial optional invocation returns—or immediately after its omission—the function reads the mandatory slot at offset +0x24 from the captured base.

It invokes that target with X as its sole supplied argument.

This invocation is unconditional within the normal path. There is no visible null check for the mandatory slot and no fallback target.

The slot is selected after the initial optional invocation. Therefore, an initial dependency can change the mandatory target that will be used by modifying the captured region.

Changing G alone does not redirect this invocation: its address calculation uses the captured base, not a fresh base read from G.

### Final optional invocation

After the mandatory invocation returns, the function reads the optional slot at offset +0x30 from the captured base.

If the resulting pointer is null, the function returns without another dependency invocation.

If it is non-null, control is transferred to that target with:

- first argument: integer zero;
- second argument: integer one.

The final target is selected independently of the initial optional target. In particular:

- An initially null slot may become non-null before the final selection.
- An initially non-null slot may become null before the final selection.
- The final target may differ from the initial target.
- The initial and final selections may use different base regions if G changes between the initial capture and the initial selection.

The final control transfer is represented as an indirect jump treated as a call. The established contract includes its target selection, null guard, arguments, and position after the mandatory operation. Whether this is implemented as a tail transfer, an ordinary call followed by return, or another equivalent mechanism is not established.

### Ordering and interruption

On a normally completing path, the observable dependency order is:

- initial optional invocation, if selected;
- mandatory invocation;
- final optional invocation, if selected.

Later slot reads occur only after preceding invocations return. The function does not prefetch the mandatory target or final optional target before those invocations.

If a dependency does not return, subsequent steps are not reached. There is no visible recovery, retry, compensation, or guaranteed final notification.

## Side effects

The wrapper itself visibly reads shared storage and indirectly invokes selected targets. It contains no explicit write to G or to either slot.

All additional externally observable effects depend on the invoked targets. Those effects are unknown and may include mutation of G, mutation of the captured region, allocation, release, I/O, or non-returning control flow. No preservation guarantee is established.

In particular:

- A dependency may change G. That does not replace the already captured base.
- A dependency may change either relevant slot in the captured region. Later reads observe the value available when those reads occur.
- A dependency may invalidate the captured region. The wrapper performs no visible lifetime validation before subsequent reads.
- No ownership of X or of the selected region is established.
- The wrapper performs no explicit allocation, retention, copying of an underlying object, or release.
- Passing X to a dependency does not establish whether that dependency borrows, owns, stores, or releases any resource represented by X.

The visible null guards apply only to the optional slot. A null base, inaccessible slot, invalid non-null target, or incompatible target signature has no defined recovery path in the supplied evidence.

## Acceptance examples

These are conditional acceptance scenarios derived from the static behavior. They are not reports of executed tests.

### 1. Stable non-null optional target

Given a stable base region containing optional target H and mandatory target M, with both targets returning normally and neither changing relevant storage:

- H receives X and 0.
- M receives X.
- H receives 0 and 1.
- No dependency return value affects the sequence.

### 2. Optional slot remains null

Given a stable base region whose optional slot is null and whose mandatory slot contains M, with M leaving the optional slot null:

- No initial optional invocation occurs.
- M receives X.
- No final optional invocation occurs.

A conforming implementation must not call a null optional target merely to preserve a paired sequence.

### 3. Initial invocation replaces the mandatory target

Given an initial optional invocation that changes the captured region’s mandatory slot from M1 to M2 before returning:

- The subsequent mandatory invocation selects M2.
- Selecting M1 before the initial invocation and calling that saved target afterward would not preserve the established ordering.

### 4. Mandatory invocation installs an optional target

Given an initially null optional slot and a mandatory target that writes H into that slot before returning:

- The initial optional invocation is omitted.
- The mandatory target receives X.
- H then receives 0 and 1.

A final invocation does not require a corresponding initial invocation.

### 5. Mandatory invocation clears the optional slot

Given an initial optional target H and a mandatory target that clears the captured region’s optional slot:

- H initially receives X and 0.
- The mandatory target receives X.
- The final optional invocation is omitted.

The wrapper does not retain H to force a closing invocation.

### 6. A dependency redirects G

Given captured region A, with the initial dependency changing G to point to region B while leaving A accessible:

- The mandatory slot is still read from A at +0x24.
- The final optional slot is still read from A at +0x30.
- Merely redirecting G to B does not redirect those later reads.

### 7. Input bit pattern and termination

Given X has the 32-bit pattern 0xFFFFFFFF and all dependencies return normally:

- The initial optional invocation, if present, receives that input pattern and zero.
- The mandatory invocation receives that input pattern.
- The final optional invocation, if present, receives zero and one instead.

If the mandatory invocation does not return, no final optional-slot read or invocation is reached.
