# F-98a286b89aba

## Purpose

F-98a286b89aba conditionally updates three adjacent four-byte fields within a caller-supplied memory region. A call to F-118f3b0c1b9a determines whether the function performs its own writes.

When that dependency returns zero, this function performs no direct field updates. When it returns nonzero, a signed control value selects between clearing all three fields and storing two supplied payloads together with the control value.

The apparent intent is a gated update of a small record. That interpretation is inferred, not an established semantic meaning for the fields. The available evidence does not identify the record type, explain the gate, or establish whether the control value represents a count, mode, duration, or something else.

## Behavior

### Gate evaluation

The first visible operation is one call to F-118f3b0c1b9a. No explicit arguments are supplied to that dependency.

The returned integer is tested for equality with zero:

- A zero result skips every direct destination write.
- Any nonzero result permits the update logic.
- A negative nonzero result permits the update just as a positive result does.

The gate is evaluated before the control value is used to select an update path. A nonpositive control value does not bypass the dependency call.

The dependency completes before this function performs its direct writes. Its implementation is unavailable. It may affect global state or memory, including the destination region; preservation of that state must not be assumed.

### Clearing path

If the gate result is nonzero and the control value is less than one, this function performs three four-byte stores in the following listed order:

1. Store zero at base plus `0xE8`.
2. Store zero at base plus `0xF0`.
3. Store zero at base plus `0xEC`.

Thus zero and all negative signed control values select clearing. Neither payload is used as a stored value on this path.

On normal completion, absent interference, all three fields contain four-byte zero values. The ordering is significant: the control field is cleared before the second payload field, despite appearing later in the memory layout.

### Positive-control path

If the gate result is nonzero and the control value is at least one, this function performs these stores in the following listed order:

1. Store the first payload at base plus `0xE8`.
2. Store the second payload at base plus `0xEC`.
3. Store the control value at base plus `0xF0`.

The payloads are copied as four-byte values. No interpretation as pointers, floating-point values, signed quantities, or owned resources is established.

There is no visible upper-bound check on a positive control value. It does not determine the number of writes: every permitted positive-control invocation performs the same three field stores. No loop, payload dereference, or control-dependent destination offset appears.
