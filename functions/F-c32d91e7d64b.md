# F-c32d91e7d64b

## Purpose

F-c32d91e7d64b prepares a value from three global 32-bit words, repeatedly transforms and probes a working object until a dependency returns zero, and then requests construction of a result. It returns that result only if it is nonzero and a 32-bit field at byte offset 28 is zero.

The function explicitly finalizes two temporary objects on its normal completion paths. It does not explicitly release either the storage requested for construction or a nonzero result rejected by the field check.

The transformation’s domain, the meaning of the probe, and the constructed object’s type are not established. Descriptions such as “search,” “allocation,” and “construction” below describe apparent roles, not verified dependency semantics.

## Behavior

### Seed preparation

The function first copies the first, second, and third global seed words into their respective local words, in that order.

It then updates the local words in reverse order: third, second, first. Each update is a logical right shift by one bit on a 32-bit unsigned value. Bits do not carry between words.

Consequently:

- Zero remains zero.
- One becomes zero.
- The most significant bit is replaced by zero.
- A word with only its most significant bit set becomes a word with the next-most-significant bit set.
- Each original least significant bit is discarded independently.

This is not established as a right shift of one combined 96-bit integer.

After the word updates, the function writes zero to the byte at offset 12. It then calls F-398e0e9a318a with the working-object area and the parameter region.

The return value of F-398e0e9a318a is not used.

### Transformation and probe phase

1. Calls F-1f62160dfd52 with the working-object area, the parameter region, and the current index.
2. Calls F-44362605ab79 with the working-object area.

The first iteration always occurs. There is no initial probe before the index-zero transformation, and no explicit early exit based on the return value of F-1f62160dfd52.

The parameter region is initialized only once. It is not restored between calls or between loop iterations. The working-object area is likewise reused. If a dependency modifies either area within its accessible extent, subsequent calls receive that changed state.

### Ordering and lifetime

2. Working-object area, after candidate validation or zero-candidate handling.

There is no explicit finalization during the probe loop. Nontermination, invalid memory access, or a dependency that does not return can prevent either finalization call.

The local areas cease to be usable once this function returns. Any dependency that retains their addresses needs an independently valid lifetime arrangement; none is demonstrated.
