# F-b03133ddbb47

## Purpose

F-b03133ddbb47 searches a linked structure, conditionally examines a candidate, and either returns a candidate word or invokes F-983b1880ceb6 to obtain a result word. It writes that four-byte word and a one-byte path flag to caller-provided storage.

The structure resembles an ordered tree with a header sentinel. Lookup or insertion with a mode-dependent duplicate policy is **inferred intent**, not an established dependency contract.

The flag distinguishes control-flow paths:

- **0:** the reverse comparison returned zero, selecting the candidate-return path.
- **1:** F-983b1880ceb6 was invoked and returned.

Flag 1 does not establish successful insertion, allocation, or even initialization of the produced word. Flag 0 does not unconditionally establish that the returned address identifies the node whose payload was compared: the candidate is read again after the comparison dependency returns.

## Interface

### Arguments and return

The function receives:

1. **Result destination:** an address for a four-byte result word followed immediately by a one-byte flag.
2. **Container address:** a 32-bit address-like value used to locate fields and form a comparison-context address.
3. **Operand:** an opaque 32-bit value passed unchanged to dependencies.

There is no explicit return value.

### Caller-visible output layout

| Offset | Width | Meaning |
|---|---:|---|
| 0 | 4 bytes | Candidate word reloaded after comparison, or word read from a dependency result slot |
| 4 | 1 byte | Candidate-return flag 0 or dependency-path flag 1 |

The result word is written before the flag. The body does not directly write offsets 5 through 7. At least five writable bytes are required; no fully initialized eight-byte result object is established.

The pair is not written atomically. Dependency writes and aliasing can create additional effects beyond this direct output footprint.

### Container and node fields

| Base | Offset | Width or use | Role |
|---|---:|---|---|
| Container | 0x10 | 4-byte pointer | Header address |
| Container | 0x18 | 1 byte | Mode |
| Container | 0x19 | Address formation | Comparison context |
| Header or node | 0 | 1 byte | Marker examined during candidate adjustment |
| Header or node | 4 | 4-byte pointer | Parent-like link; initial root when read from the header |
| Header or node | 8 | 4-byte pointer | One search direction and predecessor-like subtree |
| Header or node | 0x0c | 4-byte pointer | Opposite direction and subtree continuation |
| Node | 0x10 | Address formation | Payload argument |

The context argument is the container address plus 0x19, not a pointer loaded from that offset. Likewise, a payload argument is a node address plus 0x10; this body does not load a payload value there.

“Parent,” “left,” “right,” and “predecessor” describe the apparent structure. The established facts are the offsets, reads, and branches.

Visible pointer slots, staging words, and result words are four bytes. Marker, mode, and flag accesses are one byte. No eight-byte host-pointer substitution is justified. The supplied representation does not establish behavior for address arithmetic that overflows or produces an invalid address.

### Local storage relevant to dependencies

Two distinct four-byte staging locations matter:

- **Early result slot:** passed to F-983b1880ceb6 only on the early dependency path.
- **Ordinary result slot:** first used for a copied header word, when applicable, and later passed to F-983b1880ceb6 on the ordinary path.

The ordinary result slot is the **same storage** whose address is passed to F-dac28b48a0fc. It is not a separate copy reserved for the final dependency call.

A separate candidate location holds a four-byte pointer. Its address is also passed to F-dac28b48a0fc. No supplied contract forbids retention of either address.

## Behavior

### Search initialization

The remembered comparison result starts nonzero.

The function performs these reads in order:

1. Read the header pointer from container offset 0x10.
2. Read the initial node from that header’s offset-4 field.
3. Read the container’s header pointer again and retain that second value as the fallback search parent.

The two header reads are distinct. The initial root and fallback parent need not derive from the same header value if memory changes between reads.

If the initial node is null, no traversal comparison occurs. The remembered result remains nonzero and the retained search parent remains the second header value.

### Traversal and staging initialization

For every non-null current node, the function:

1. Writes zero to the early result slot.
2. Writes zero to the ordinary result slot.
3. Calls F-2c6a49ccf2ab with the context address, original operand, and current node’s payload address, in that order.
4. Retains the current node as the search parent.
5. Reads the next link according to the comparison result.

A zero result selects the offset-0x0c link. Any nonzero result selects the offset-8 link. Positive and negative nonzero results are not distinguished.

The selected link is read **after** the dependency returns. Changes made by the dependency can therefore affect traversal.

Both staging slots are zeroed before **every** traversal comparison, not merely once on entry. An empty traversal performs neither initialization. These writes are observable if a dependency has access to the storage; they are not a promise that dependencies preserve its contents.

Traversal ends when the selected node pointer is null. There is no visible cycle detection, depth bound, or structural validation.

### Mode selection

After traversal, the function reads the mode byte at container offset 0x18.

- **Nonzero:** proceed directly to the ordinary dependency path.
- **Zero:** initialize the candidate location with the retained search parent and perform candidate validation.

The mode is read after traversal callbacks. Its entry-time value is not authoritative if a dependency changes it.

### Boundary check for a nonzero remembered comparison

With zero mode and a nonzero remembered comparison result:

1. Read the container’s header pointer afresh.
2. Read that header’s offset-8 word.
3. Store the word into the ordinary result slot, replacing its previous contents.
4. Call F-dac28b48a0fc with the candidate-location address and ordinary-result-slot address.

If F-dac28b48a0fc returns nonzero, take the **early dependency path**. Candidate adjustment and reverse comparison are skipped.

If it returns zero, perform candidate adjustment using the candidate value present after the call. The dependency can modify that value through the supplied address.

With zero mode and a remembered comparison result of zero, this boundary check is omitted. Candidate adjustment is also omitted.

### Candidate adjustment

Adjustment occurs only after a zero result from F-dac28b48a0fc.

**Sentinel-like case**

First read the candidate’s marker byte.

Only if the marker is zero, read the candidate’s offset-4 pointer and then the pointed-to object’s offset-4 pointer. If that second pointer equals the candidate, replace the candidate with the word read from its offset-0x0c field.

A nonzero marker suppresses both parent-chain reads. If the marker is zero but the two-step pointer does not equal the candidate, use the general adjustment.

**General adjustment: preserve separate reads**

The candidate’s offset-8 field is read twice:

1. The first read retains a possible subtree pointer.
2. The second read decides whether to take the parent-climb branch.

These reads are not interchangeable.

If the **second** read is null, the retained first value is discarded. Read the candidate’s offset-4 pointer to begin climbing. At each parent:

- Read the parent’s offset-8 link and compare it with the current candidate.
- Replace the candidate with that parent, whether the comparison succeeds or fails.
- If equal, read that parent’s offset-4 link and continue.
- If unequal, stop.

There is no explicit null-parent guard.

If the **second** offset-8 read is nonnull, enter the subtree using the pointer retained by the **first** read. Each subtree iteration:

- Replaces the candidate with the retained subtree pointer.
- Reads candidate offset 0x0c once to retain a possible next pointer.
- Reads the same field again to decide whether to continue.

A null second read ends the loop with the current candidate. A nonnull second read continues using the first read’s retained pointer.

Under stable memory, this selects the rightmost node of the offset-8 subtree. Without stability, the branch decision and pointer used can disagree. For example, a null first read followed by a nonnull second read can lead to an attempted access through a null retained pointer. The function does not reconcile these observations.

### Reverse comparison and candidate reload

After candidate selection:

1. Zero a separate four-byte scratch location.
2. Zero the ordinary result slot.
3. Form a payload address from the candidate value available for argument evaluation.
4. Call F-2c6a49ccf2ab with the context address, that payload address, and the original operand.

The operand order is reversed relative to traversal.

The ordinary result slot reset occurs even when it previously held the copied header word or a value written by F-dac28b48a0fc. That slot’s address may already have escaped. A dependency retaining access can change it during the reverse comparison; the preceding zero store does not guarantee that it remains zero afterward.

If the reverse comparison returns zero, the function **reloads the candidate location after the call**, writes that four-byte value to the result destination, and then writes flag 0.

The payload argument and output word therefore come from different observations of the candidate location. F-dac28b48a0fc may previously have retained its address, and no supplied contract prevents a later dependency from modifying it through retained access. The returned word is not guaranteed to be the address used to form the compared payload.

If the reverse comparison returns nonzero, take the ordinary dependency path.

### Early dependency path

F-983b1880ceb6 receives, in order:

1. The early result slot’s address.
2. The original container address.
3. Literal zero.
4. The retained search parent.
5. The original operand.

After the call returns, the function reads the early result slot and writes its word to the output. It then stages flag 1 locally and writes that flag to output offset 4.

The search parent is not replaced by a candidate modified by F-dac28b48a0fc.

For a nonempty traversal, the early result slot was zeroed before the final traversal comparison. For an empty traversal, it has no established initialization before this call.

### Ordinary dependency path

This path follows either nonzero mode or a nonzero reverse-comparison result.

F-983b1880ceb6 receives the same five argument roles as on the early path, except that its first argument is the **ordinary result slot’s address**.

After return, the function reads that slot, writes the result word, stages flag 1, and writes the flag.

The slot’s incoming contents depend on the path:

| Path | Established preceding writes to the ordinary result slot |
|---|---|
| Nonempty traversal, nonzero mode | Zeroed before each traversal comparison |
| Empty traversal, nonzero mode | No established initialization |
| Reverse comparison returned nonzero | Zeroed immediately before that comparison; the comparison may subsequently modify it through retained access |

The third argument remains literal zero; it is not the remembered comparison result. The fourth remains the retained search parent, not the adjusted candidate.

## Side effects

The body directly writes caller output and local storage. It does not directly allocate, release, unlink, rotate, or update container and node fields.

Local writes include both staging-slot initializations, the copied header word, candidate changes, the scratch zero before reverse comparison, and flag staging. One byte of the early result storage is reused for the final flag after any needed result-word copy. This reuse does not initialize the full early slot before an empty-traversal early call.

Dependency side effects are unrestricted by the supplied contracts. No preservation guarantee exists for globals, container fields, node links, operand storage, escaped local storage, or caller output reachable through aliases.

No ownership transfer or lifetime guarantee is established for any argument or result. Dependencies must not be assumed to allocate, own, preserve, or release memory.

Normal completion requires every executed access to address valid storage and every required dependency call to return. There is no visible recovery for invalid pointers, corrupt links, cycles, dependency failure, or failure to populate a result slot.

An untouched uninitialized result slot has no specified fallback value. Flag 1 does not repair that missing guarantee.

## Acceptance examples

These are conditional static acceptance examples, not executed tests. They assume valid accesses and returning dependencies unless stated otherwise.

1. **Traversal direction and initialization.** Before each traversal comparison, the early slot is zeroed and then the ordinary slot is zeroed. Comparison zero selects offset 0x0c; any nonzero value selects offset 8.

2. **Mode bypass.** With nonzero mode, neither the boundary dependency nor reverse comparison runs. The ordinary result slot is passed to F-983b1880ceb6 with literal zero and the retained search parent. If that dependency writes word W, output is W followed by flag 1.

3. **Stable candidate return.** With zero mode, final traversal result zero, reverse comparison zero, and no modification of candidate storage during that comparison, output is the last visited node address followed by flag 0.

4. **Candidate changed during comparison.** Suppose the boundary dependency returns zero and retains the candidate-location address. Candidate adjustment selects address A. The reverse comparison receives payload address A + 0x10, changes the escaped candidate location to B, and returns zero. Output is B followed by flag 0, not necessarily A.

5. **Early result-slot distinction.** With zero mode and a nonzero boundary result, F-983b1880ceb6 receives the early slot, not the ordinary slot that held the copied header word. It receives the original search parent even if candidate storage changed.

6. **Ordinary slot reuse.** Suppose the boundary dependency retains its second argument’s address and returns zero. Before reverse comparison, that same storage is reset to zero. If the reverse comparison writes W there and returns nonzero, F-983b1880ceb6 receives a result slot containing W, unless another intervening effect changes it.

7. **Stable-memory subtree selection.** If the sentinel condition fails and both offset-8 reads yield the same nonnull child, adjustment enters that child. If each pair of offset-0x0c reads agrees, it selects the terminal node along those links.

8. **Disagreeing link observations.** If the first offset-8 read yields A and the second yields nonnull B, the subtree begins at A, not B. If the second is null, the parent-climb branch is taken instead. No consistency check is performed.

9. **Empty traversal.** No traversal comparisons or staging zero stores occur. Nonzero mode passes an uninitialized ordinary slot to F-983b1880ceb6. Zero mode copies the fresh header offset-8 word into that slot and calls the boundary dependency; a nonzero boundary result passes the distinct, uninitialized early slot to F-983b1880ceb6.

10. **Output footprint.** With non-overlapping output and no dependency writes to it, the body writes four result bytes and then one flag byte. The next three bytes remain untouched by the body.
