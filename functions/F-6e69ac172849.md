## Behavior

### Initial memory mutations

The direct-memory phase begins after the last prefix invocation, without visible validation.

An earlier retained word is stored at offset 0x14 from the latest paired result’s high component. A byte is then stored at offset 9 from another retained base. A word destination formed from the latest low component scaled by 256, plus 0x54, receives a separately retained scaled value. The offset-9 byte is subsequently overwritten.

The function then clears a word at offset 0x14 of a large scaled base, reads an unsigned byte at offset 5 of that base, clears another computed word, and stores the promoted byte at offset 0x34 of the large base. It rereads the cleared offset-0x14 word after those intervening accesses.

The reread is a memory observation at its actual position. An intervening destination may alias that word; its value cannot unconditionally be replaced by zero.

For the following ordering description:

- **Narrow base** means twice a retained masked-and-shifted field.
- **Byte-selected base** means the zero-extended byte loaded from fixed address 0x05.
- **Link word** means the word subsequently captured from byte-selected base plus 0x54.

These are descriptive roles, not established object types.

### Linked and scaled updates

The mutation phase scales captured words by two, four, and eight, and follows loaded words through additional fields. It also uses unsigned bytes as address contributions for word reads at offset 0x74.

## Acceptance examples

These are conditional static criteria, not executed tests.

### Width preservation

If a reached byte store receives 0x123456AB, it stores 0xAB. If an unsigned byte read yields 0xE7, its promoted word value is 231.

If the three 0x3A destinations are valid and distinct, acceptance requires byte, halfword, and word accesses in that order—not three byte stores.

### Fixed-width arithmetic

Under 32-bit bit-vector semantics, shifting 0x01000000 left eight produces zero. Two successive left shifts by 28 also produce zero after truncation between operations.

### Phase ordering

An observable trace must place the three 0x3A stores and the working-base 0x20/0x2F/promoted-byte/0x20 sequence before the repeated four-write region. The global-base load precedes the fixed 0x60 word write, which precedes repetition.

### Constant-word read

For ordinary memory without hardware aliases, the 0x2F store at working base plus 0x20 does not directly modify the byte at working base plus 4. That byte must still be read at its represented position.

### Aliased captures and rereads

If an intervening computed write aliases a cleared word, its later reread uses current storage rather than presumed zero.

If the fixed 0x3A write overlaps the later tail-linked offset-0x14 capture, that capture includes its effects according to byte order. The earlier 0xA9 and offset-0x74 captures remain earlier observations.

### Repeated reads of 0x67

If a computed write changes byte 0x67 after the copy to 0x21 but before a later read, the later working-base-plus-9 store uses the newly read byte. Retaining the original low byte of the 0xA9 capture would not preserve this behavior.

### Interruption and final transfer

If a dependency does not return, subsequent operations need not occur; earlier effects are not rolled back.

If execution reaches the final transfer, its arguments must have the numeric value and capture origins specified above. Interpreting 0x72 as an output character requires a separate dependency contract.
