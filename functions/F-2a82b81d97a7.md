# F-2a82b81d97a7

## Purpose

F-2a82b81d97a7 searches a linked, tree-shaped structure and then either delegates an operation or reports a cursor value. It writes a four-byte result followed by a one-byte disposition to caller-provided storage.

**Inferred intent:** the traversal and decisions resemble associative-container insertion with optional existing-entry detection. Tree, predecessor, and insertion terminology are descriptive interpretations, not established contracts for the dependencies.

**Established limitation:** disposition 1 identifies a delegation path. It does not independently establish insertion, allocation, structural change, or success. Disposition 0 identifies the path that reports the cursor after a final comparison returns zero.

## Behavior

### Initial acquisition and search

The remembered comparison disposition starts at nonzero.

The function reads the context’s header reference and then that object’s offset-4 field to obtain the initial search node. It separately reads the context’s header reference again to initialize the remembered search position. These are distinct reads, not an atomic snapshot.

Two independent four-byte scratch slots are relevant:

- **Early-delegation scratch:** supplied to delegation only on the boundary dependency’s nonzero-return path.
- **Final-delegation scratch:** supplied to delegation on the common final delegation path; also reused for the boundary dependency’s second argument.

These are descriptive names, not source identifiers.

Before **every search comparison**, the function explicitly writes zero to the early-delegation scratch and then zero to the final-delegation scratch. If the initial search node is null, neither initialization occurs.

For each nonnull search node:

1. Both scratch words are zeroed in that order.
2. F-bcefa5957e76 receives the comparison-state address, the request, and the current node’s offset-0x10 address.
3. After the call returns, the current node becomes the remembered search position.
4. A zero comparison result selects the node’s offset-0x0c link; a nonzero result selects its offset-8 link.

The selected link is read after the comparison returns. Dependency changes to the structure are therefore not excluded from affecting the next step.

A terminating nonempty search leaves the last visited node as the remembered position and the last comparison result as the disposition. An empty search leaves the separately acquired header reference as the remembered position and retains the initial nonzero disposition.

No direct allocation, balancing, count limit, or cycle detection occurs.

### Mode decision

After search termination, the function reads the context’s mode byte.

- Any nonzero byte selects final delegation immediately.
- Zero enables the boundary and existing-entry decisions.

The mode is not captured before the search. Comparison dependencies may affect the state subsequently read; their preservation of the context is not established.

In zero mode, the function initializes a local four-byte cursor with the remembered search position.

### Boundary decision and scratch reuse

The boundary decision occurs only in zero mode when the remembered search disposition is nonzero, including an empty search.

The function rereads the context’s header reference and copies that header’s offset-8 word into the **final-delegation scratch**, overwriting its previous contents. It then calls F-f063d8ade9f7 with:

- The address of the local cursor.
- The address of the final-delegation scratch.

Both arguments designate local storage. The dependency may read or modify either object; its contract is unknown.

A nonzero return selects early delegation:

- F-81c45e7142cf receives the address of the **early-delegation scratch**, the context, zero, the remembered search position, and the original request.
- After it returns, the early-delegation scratch is read and copied to result offset 0.
- Disposition 1 is staged and written to result offset 4.
- No navigation, operand extraction, or final comparison occurs.

The incoming early-delegation scratch differs by search history: a nonempty search explicitly zeroed it before the last search comparison; an empty search did not initialize it. The boundary operation does not explicitly initialize this slot.

A zero boundary return proceeds to navigation using the cursor as it then exists. The function does not restore either by-reference argument.

### Navigation and special-case precedence

Navigation begins by reading the cursor object’s marker byte.

If the marker is zero, the function reads the cursor’s offset-4 link and then the linked object’s offset-4 value. If that value equals the cursor, the **special case takes precedence**: the cursor becomes the original cursor’s offset-0x0c link.

This special case applies even when the original cursor’s offset-8 link is nonnull. That link does not force ordinary descent.

If the special case does not apply, ordinary predecessor-like navigation follows.

**Offset-8 descent:** the function reads the cursor’s offset-8 link to obtain a prospective descent node and reads that field again to test for null. When the tested value is nonnull, the prospective node becomes the cursor. Navigation then follows offset-0x0c links until the tested offset-0x0c value is null.

Each rightward iteration obtains a next candidate from offset 0x0c and separately rereads that field for the continuation test. Under stable links, this selects the terminal node reached by one offset-8 step followed by zero or more offset-0x0c steps. The repeated reads are not evidence of snapshot or concurrency guarantees.

**Parent-like ascent:** when the tested offset-8 link is null, navigation obtains a candidate parent from offset 4. For each candidate, it compares the candidate’s offset-8 link with the previous cursor and then replaces the cursor with that candidate, regardless of whether the comparison succeeds. If it succeeds, navigation obtains the next candidate through offset 4 and repeats.

Thus, the upward path retains the first candidate parent whose tested relationship fails, not the child from the preceding step.

No other marker encoding is established beyond zero versus nonzero.

## Side effects

### Direct writes and ordering

The body directly writes local scratch, cursor storage, and the caller’s result. It does not directly update context fields or tree links.

Relevant ordering is:

- Each search iteration zeroes both delegation scratch words before calling the comparison dependency.
- The search comparison returns before the selected branch link is read.
- The mode read follows search termination.
- The header offset-8 word is stored into final-delegation scratch before the boundary call.
- Operand extraction returns before the final comparison begins.
- A zero final comparison returns before the cursor is read for reporting.
- Delegation returns before its scratch word is read for reporting.
- The result word is written before the disposition byte.

After writing the result word, the function uses a one-byte portion of the early-delegation scratch to stage the disposition. Thus, that scratch is not preserved unchanged through completion: its disposition-bearing portion becomes 0 or 1. On early delegation, this occurs after the delegated word has already been copied to the caller.

The supplied body does not establish volatile semantics, synchronization, or an instruction-level memory trace.

## Acceptance examples

These are conditional static acceptance examples, not executed tests.

### Nonempty search with nonzero mode

Given a finite valid search and nonzero mode when read:

- Both delegation scratch words are zeroed before every search comparison.
- Search follows offset 0x0c for zero results and offset 8 otherwise.
- Boundary checking and operand extraction are skipped.
- Final delegation receives the last visited node and the final-delegation scratch.
- The word read from that scratch after delegation is reported with disposition 1.

If delegation leaves the scratch unchanged and intervening dependencies preserve it, the reported word is zero.

### Empty search with nonzero mode

Given a null initial search node and nonzero mode:

- No search comparison or per-iteration scratch initialization occurs.
- Final delegation receives the remembered header reference.
- Its scratch has no established initialized incoming word.
- Disposition becomes 1 on normal completion, but a defined result word requires a sufficient dependency contract.

### Boundary selects early delegation

Given zero mode, nonzero search disposition, and a nonzero boundary return:

- Final-delegation scratch first receives the freshly read header offset-8 word.
- The boundary dependency receives that scratch address and the cursor address.
- Early delegation instead receives the separate early-delegation scratch.
- Navigation and final comparison do not occur.
- The remembered search position is supplied regardless of cursor mutation.

The early scratch has a prior explicit zero initialization only if the search visited at least one node.

### Ordinary descent followed by reporting

Given zero mode, nonzero search disposition, a zero boundary return, valid stable links, and a nonnull cursor offset-8 link, **also require that the marker-zero/parent-offset-4 special case does not apply**.

Navigation then selects the node reached through offset 8 and subsequent offset-0x0c links.

If the final comparison returns zero, the reported word is the cursor’s then-current value. It equals the navigation-selected node only if subsequent dependencies preserve the cursor, including through any retained address.

### Special case despite a nonnull offset-8 link

Given a zero marker and a parent object whose offset-4 value equals the cursor:

- Navigation selects the cursor’s offset-0x0c link.
- A nonnull offset-8 link does not change that decision.
- Any later disposition-0 result still reports the cursor value read after extraction and final comparison.

### Ordinary descent followed by delegation

Under the ordinary-descent conditions above, including exclusion of the special case, a nonzero final comparison selects final delegation.

Delegation receives the original remembered search position, not the navigation-selected cursor. Its scratch contains the header-derived boundary value as potentially modified through the exposed address. The subsequently read scratch word is reported with disposition 1.

### Last search comparison zero

Given a nonempty search ending with comparison zero and zero mode:

- Boundary checking and navigation are skipped.
- Extraction receives the cursor initialized from the remembered search position.
- A zero final comparison reports the cursor read after that comparison, with disposition 0.
- A nonzero final comparison delegates using final-delegation scratch, whose last explicit initialization was zero before the last search comparison.
