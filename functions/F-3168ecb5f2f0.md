# F-3168ecb5f2f0

## Purpose

F-3168ecb5f2f0 describes an unconditional loop of indirect calls, memory accesses, arithmetic, and a software breakpoint. Each completed iteration performs several updates through externally supplied addresses before beginning another iteration. There is no represented normal return.

The application-level purpose is not established. Field-like offsets suggest manipulation of structured state, but that is **inferred intent**, not a guarantee that the addresses identify records, tables, devices, or allocated objects.

This contract distinguishes:

- **Established static evidence:** explicit operations, widths, ordering, retained values, and relationships between call-target addresses.
- **Inferred intent:** interpretations suggested by those operations.
- **Documented-only unknowns:** matters requiring dependency implementations, architectural information, or runtime evidence.

No runtime tests have been performed.

## Interface

### Inputs and outputs

The represented interface has no explicit parameters and no returned value. Execution nevertheless requires ambient inputs:

- A link-related value used to calculate the first indirect-call target.
- An ambient state-base value consulted separately at several points.
- An incoming register value used in a late byte-store address.
- Two global cells containing 32-bit address-like values.
- Memory accessible through constants, ambient values, loaded values, and dependency results.
- Additional register outputs associated with three calls.

These are execution prerequisites, not validated arguments.

The ambient state base is **not** captured once for an iteration. Its uses at offsets `0x26C`, `0x320`, `0x280`, and `0x258`, and its later decrement, each consult the then-current ambient value. Intervening dependencies are not established to preserve it.

There is no explicit success result, error result, or normal termination condition. A dependency that does not return, a nonresuming breakpoint, or an access fault can prevent further progress.

### Widths and descriptive names

The representation distinguishes 8-bit bytes, 16-bit halfwords, 32-bit words, and three 64-bit results. Each 64-bit result is consumed as low and high 32-bit portions.

Unsigned halfword reads produce values from 0 through 65535. Their subsequent word stores are zero-extended. Halfword stores retain only the low 16 bits; byte stores affect only one byte.

The following names identify retained values, not established object types:

- **Primary base:** the value captured from the first global cell.
- **Table base:** the value captured from the second global cell.
- **First pair**, **second pair**, **third pair:** the three 64-bit dependency results.
- **First halfword:** the unsigned halfword read from the fixed-address region.
- **Record base:** the word subsequently read through the first halfword.
- **Second halfword:** an unsigned halfword read through another captured address.
- **Third halfword:** an unsigned halfword read through the third pair’s high portion.

Address calculations use 32-bit quantities in the supplied representation. Actual address validity, alignment requirements, byte order, and fault handling are unknown. Unsigned shifts have the bit-level behavior described below. Exact architectural treatment of overflow in signed-looking additions, multiplications, and left shifts remains documented-only.

## Behavior

### Iteration entry and primary updates

Each iteration establishes a zero-valued byte before invoking **F-D01**. That call receives two explicit zero arguments, and its target is calculated from the current link-related value plus `0xFFE`. A second zero-valued byte is established after F-D01 returns.

The call order then proceeds through **F-D02** and **F-D03**. The routine reads the primary global cell and retains its 32-bit value as the primary base. **F-D04** follows that read, and **F-D05** supplies the first pair.

**F-D06** receives the first pair’s low word and the sum of its high word, low word, and the second zero-valued byte. No overflow check is represented. The intended width of the consumed pair portions is 32 bits; wraparound for the signed-looking sum is not independently established.

After F-D06 returns, an additional 8-bit register output associated with that call is stored at primary base plus `0x11`. **F-D07** is then invoked, followed by a zero-byte store at primary base plus `0x15`.

Both stores use the previously captured primary base. Changes to the global cell during F-D04 through F-D07 do not replace that retained value in the represented dataflow. This does not imply preservation of the pointed-to memory.

### Second-pair updates and ambient-state reads

**F-D08** supplies a 16-bit result, which is stored at an address formed from an additional register output associated with that call plus `0x0C`.

**F-D09** supplies the second pair. A zero halfword is first stored at its high word plus `0x2C`. The low word is then logically shifted right by 26, and the resulting 32-bit value is stored at the **then-current** ambient state base plus `0x26C`. This value ranges from 0 through 63.

The constant `0x21C48960` is established for later calculations. After **F-D10**, a word is read from the **then-current** ambient state base plus `0x320` and retained as an address. **F-D11** and **F-D12** execute before the next explicit store. That store writes the second pair’s low word, shifted left by two as an unsigned 32-bit value, to the retained address plus `0x54`. The shift discards the two highest bits.

The two ambient-state accesses are separate evaluations. F-D10 may change the ambient base between them. Once the address at offset `0x320` has been captured, later changes to the ambient base do not redirect the store through that captured address.

The next calls are **F-D13**, **F-D14**, **F-D15**, **F-D16**, and **F-D17**, in that order.

### Fixed-region read and breakpoint

The first halfword is read unsigned from `0x21C48960 + 0x34`, namely `0x21C48994`.

After **F-D18**, a word is read from the **then-current** ambient state base plus `0x280` and passed to **F-D19**. The routine then executes software breakpoint immediate `0x92`.

The breakpoint is observable. The remainder of the iteration occurs only if execution resumes at the following operation. No handler behavior or guarantee of resumption is established.

Following resumption, F-D19’s 32-bit result is shifted left by two. Independently, the fixed constant is logically shifted right by 18 and multiplied by four. This latter calculation is exact:

- The shifted value is `0x871`.
- The scaled value is `0x21C4`.

A word is then read from first halfword plus `0x44` and retained as the record base. The first halfword is used directly as an address component; no additional allocation base or implicit table base is established.

### Intermediate calls and halfword writes

**F-D20** executes, followed by **F-D21**. A word is then read from first halfword plus `0x04`. **F-D22** receives F-D21’s 32-bit result and that loaded word, in that argument order.

The second global cell is read next, capturing the table base. After **F-D23**, the low 16 bits of that captured base are stored at:

\[
\text{table base} + \text{the shifted F-D19 result}.
\]

The indexing operation has a four-byte scale, but the store is only two bytes wide. The neighboring bytes are not explicitly written.

After **F-D24**, a word is read from the scaled constant plus `0x54`, an effective address of `0x2218`. This loaded word is retained as an address for a later halfword read.

**F-D25** supplies another address. The routine stores the low 16 bits of the scaled constant, `0x21C4`, at that returned address plus `0x04`. **F-D26** and **F-D27** follow.

The word read at `0x2218` is a direct fixed-address access in the representation. It must not be reinterpreted as an access through the captured table base.

### Third pair and state-base adjustment

The second halfword is read unsigned from the address captured at `0x2218` plus `0x34`. **F-D28** then supplies the third pair.

The third pair’s low word is stored at the **then-current** ambient state base plus `0x258`. Next, the third halfword is read unsigned from the third pair’s high word plus `0x14`.

Two derived values are formed: the third pair’s low word shifted left by six, and its high word multiplied by four. Both use signed-looking 32-bit arithmetic in the representation; overflow behavior is not resolved by an architectural specification.

The routine then reads the ambient state base at the decrement point and assigns that value minus `0xF4` back to the ambient state base. This is not defined as subtracting from a saved entry value.

Afterward, the second halfword is multiplied by four, and the third pair’s low word is stored at that scaled halfword plus `0x74`. Since the halfword is unsigned, its multiplication by four ranges from 0 through 262140 and cannot overflow 32 bits.

The store at offset `0x258` precedes the explicit decrement. Dependencies executed earlier may have changed the base before either operation. Dependencies executed later may change it again; therefore, the value seen at the next iteration is not unconditionally the iteration-entry base minus `0xF4`.

### Record writes, byte copy, and continuation

After **F-D29**, the third halfword is stored as a 32-bit word at record base plus `0x54`. After **F-D30**, the same retained value is stored as a word at record base plus `0x64`. Both stores zero-extend the halfword; there is no intervening reload of its source.

**F-D31** then executes. The low 16 bits of the record base are stored at an address formed by adding an additional register output associated with F-D31 to the previously formed third-pair-low shifted value.

After **F-D32** and **F-D33**, one byte is read from second halfword plus four times second halfword. This source address is mathematically five times the second halfword, ranging from 0 through 327675 without overflow.

**F-D34** executes between this byte read and its destination store. The captured byte is stored at:

\[
\text{third halfword} + \text{incoming register value} + \texttt{0x19}.
\]

Changing the source memory during F-D34 does not change the already captured byte.

After **F-D35**, the previously formed third-pair-high multiplied value is stored as a word at record base plus `0x44`. **F-D36** follows. The link-related state is explicitly assigned `0x08712031`; then a word is read from third-pair-high multiplied by four plus `0x44` and passed to **F-D37**.

If F-D37 returns, another iteration begins. No normal exit is represented. The explicit link assignment precedes F-D37; whether that dependency preserves the relevant ambient machine state is not established by its unavailable implementation.

## Acceptance examples

These are conditional criteria derived from static evidence, not executed tests. They assume execution reaches the relevant operations and that required accesses succeed.

1. **Unsigned extraction and shift.** If the second pair’s low word is `0xFFFFFFFF`, the store at the then-current ambient base plus `0x26C` writes the word 63. The later store through the captured address writes `0xFFFFFFFC`.

2. **Independent ambient-base observations.** If the ambient base is \(A\) at the `0x26C` store, F-D10 changes it to \(B\), and the word at \(B+\texttt{0x320}\) is \(P\), the explicit accesses use \(A+\texttt{0x26C}\), then \(B+\texttt{0x320}\), then \(P+\texttt{0x54}\). They do not all use \(A\).

3. **Conditional decrement relationship.** If the ambient base is \(S\) after F-D28 and remains unchanged through the explicit decrement, the third-pair-low store uses \(S+\texttt{0x258}\), and the decrement assigns \(S-\texttt{0xF4}\). Carrying that value into the next iteration additionally requires preservation by the subsequent dependencies. Without those assumptions, no entry-to-entry decrement formula is established.

4. **Zero extension.** If the third halfword is `0xFFFF`, both record stores at offsets `0x54` and `0x64` write `0x0000FFFF`, not `0xFFFFFFFF`.

5. **Halfword width.** If the table base is `0x12345678` and F-D19 returns zero, the table store targets `0x12345678` and writes only the halfword `0x5678`.

6. **Fixed scaled constant.** The intermediate fixed-address word read uses `0x2218`. The following store through F-D25’s returned address plus four writes halfword `0x21C4`.

7. **Captured byte.** If the byte read before F-D34 is `0xA5`, and F-D34 changes its source to `0x5A`, the explicit destination store still writes `0xA5`.

8. **Breakpoint boundary.** If breakpoint `0x92` does not resume, subsequent operations in this invocation do not execute. Earlier calls and writes may already have taken effect.

9. **Equal targets, differing observations.** F-D05 and F-D06 must resolve to equal target addresses. That does not require their invocations to produce equal register values or effects.
