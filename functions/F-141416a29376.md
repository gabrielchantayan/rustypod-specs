## Behavior

The following order describes the function’s own accesses and dependency invocations. It is not a claim about atomic operations, memory barriers, or synchronization between threads.

### 1. Conditionally clear existing record state

The function first reads record slot four and tests whether it is nonzero.

If it is zero, this stage makes no direct writes and invokes no cleanup dependency.

If it is nonzero:

1. The current value of record slot one is supplied to F-58ba61416cc9.
2. After that dependency returns, the function writes zero to record slot one.
3. It then writes zero to record slot four.

The dependency is called even if slot one contains zero. The controlling condition is slot four, not slot one.

Both clearing writes occur after the dependency returns. Consequently, the dependency is entered before this function has cleared either field. If the dependency modifies these fields and returns, the subsequent direct writes overwrite its changes to slots one and four.

If the dependency does not return normally, the supplied representation establishes no execution of those clearing writes or of later stages.

### 2. Conditionally perform initialization-associated work

After the first stage, the function reads the initialization flag.

If its observed value is nonzero, it skips this stage’s write and dependency call.

If its observed value is zero:

1. The function writes one to the initialization flag.
2. It invokes F-0fd46b9a392f with the initialization-associated object or address.

The flag is set before the dependency is entered. There is no visible rollback if the dependency fails to return normally, and no explicit retry in the same invocation.
