# F-ba69a5506d0a

## Purpose

F-ba69a5506d0a refreshes a six-bit classification region in a caller-supplied object. It classifies three signed values against two limits derived from one signed threshold. Each value has an independent “below lower limit” flag and “above upper limit” flag.

The operation replaces the classification flags rather than accumulating them. Other bits in the same status word are preserved from the status value read during the operation. The compared values and threshold are not modified.

An interpretation as coordinate classification against a symmetric boundary is plausible but **inferred**. The supplied evidence establishes neither geometric field identities nor the meaning assigned to these flags by consumers.

This is a static behavioral contract. No runtime tests have been performed.

## Behavior

### Meaning of the threshold

The threshold supplies the upper limit directly. Its arithmetic negative supplies the lower limit. Both limits originate from one captured threshold value, rather than independently obtained threshold samples.

For a threshold of 4, the limits are −4 and 4. The operation does not change the input values, constrain them to this interval, or replace a negative threshold with its magnitude.

The comparison flags are defined as follows:

| Value | Below-lower flag | Above-upper flag |
|---|---|---|
| First | Bit 2: value strictly below the lower limit | Bit 3: value strictly above the upper limit |
| Second | Bit 4: value strictly below the lower limit | Bit 5: value strictly above the upper limit |
| Third | Bit 6: value strictly below the lower limit | Bit 7: value strictly above the upper limit |

All comparisons are signed and strict. Each flag is one when its own condition holds and zero otherwise. No flag takes priority over another.

The numerical contributions of bits 2–7 are respectively `0x04`, `0x08`, `0x10`, `0x20`, `0x40`, and `0x80`.

### Classification replaces previous results

The six flags occupy mask `0x000000FC`. Their previous contents do not affect their new contents. A flag that was previously set becomes clear when its current comparison is false.

The remainder of the status word is selected by preservation mask `0xFFFFFF03`. Preservation refers specifically to the status value read by this invocation. It is not a guarantee that another writer’s intervening changes survive.

Consequently:

- A caller need not clear old classification flags before invoking this operation.
- Changing one comparison value can change only that value’s two classification flags, provided the threshold and other inputs remain unchanged.
- An invocation may leave the numerical status value unchanged, but the supplied representation still contains a status assignment. Whether a redundant physical store occurs is not established.

### Nonnegative thresholds

When the threshold is positive, the limits form an inclusive interval. A value inside that interval, including either endpoint, has both flags clear.

A value below the interval sets only its below-lower flag. A value above the interval sets only its above-upper flag. The two flags for one value cannot both be set for a nonnegative threshold under the stated signed arithmetic model.

For a zero threshold, both limits are zero:

- Negative values set only the below-lower flag.
- Zero sets neither flag.
- Positive values set only the above-upper flag.

### Negative thresholds

A negative threshold is not rejected or normalized. When its negation is representable, the lower limit is numerically greater than the upper limit.

For example, threshold −2 gives a lower limit of 2 and an upper limit of −2. A value of zero is below 2 and above −2, so both flags for that value are set.

At these reversed endpoints:

- A value equal to the upper limit sets only the below-lower flag.
- A value equal to the lower limit sets only the above-upper flag.
- A value strictly between the limits sets both flags.

Thus, descriptions that require every pair to encode exactly one of “below,” “inside,” or “above” are valid only with an appropriate nonnegative-threshold precondition.

### Arithmetic boundaries

The comparison values are compared directly with the limits. The operation does not calculate a difference between a value and a limit, so a large separation between operands does not introduce subtraction overflow.

Threshold negation is a distinct arithmetic issue. Under signed 32-bit arithmetic:

- The supported numerical range is −2,147,483,648 through 2,147,483,647.
- Every threshold except −2,147,483,648 has a representable mathematical negative.
- Negating −2,147,483,648 would require 2,147,483,648, outside that signed range.

The supplied evidence does not establish successful behavior for that exceptional negation. No wraparound, saturation, exception, or final status value is promised for it.

For threshold 2,147,483,647, the lower limit is −2,147,483,647. A comparison value of −2,147,483,648 is therefore strictly below the lower limit.

## Acceptance examples

These are conditional consequences of the static evidence, not execution results. Unless stated otherwise, each example assumes stable valid storage, the recovered 32-bit field model, and defined threshold negation.

### Mixed classification and clearing old flags

With threshold 4, values −5, 4, and 5, and initial status `0xC37200FF`:

- The first value sets bit 2 only.
- The second value sets neither flag; equality with the upper limit is not above it.
- The third value sets bit 7 only.

The classification contribution is `0x84`. The final status is `0xC3720087`. Previously set classification flags that are no longer justified are cleared, while unrelated bits remain unchanged.

### Both endpoints are included

With threshold 9, values −9, 0, and 9, and initial status `0x104080FD`, no classification flag is set.

The final status is `0x10408001`. Equality with either limit does not satisfy the corresponding strict comparison.

### Zero threshold

With threshold zero, values 1, −1, and 0, and initial status zero, the final status is `0x00000018`.

Bit 3 represents the positive first value. Bit 4 represents the negative second value. The third value sets neither flag.

### Overlapping flags with a negative threshold

With threshold −2, values −2, 0, and 2, and initial status zero:

- The first value sets bit 2 only.
- The second value sets bits 4 and 5.
- The third value sets bit 7 only.

The final status is `0x000000B4`. This is an accepted consequence of reversed limits, not an error indication.

### Successive replacement

Start with threshold 3, values −4, 0, and 4, and status `0x80000002`. One invocation produces `0x80000086`.

If the values are then changed to −3, 0, and 3 without changing the threshold, a subsequent invocation produces `0x80000002`. No separate flag-clearing operation is required.

### Signed extreme

With threshold 2,147,483,647, values −2,147,483,648, 0, and 2,147,483,647, and initial status zero, the final status is `0x00000004`.

For threshold −2,147,483,648, no corresponding expected status is specified without additional evidence establishing negation semantics.
