# F-0444414dfb64

## Purpose

F-0444414dfb64 selects between an indirect operation on a resolved object and a fallback operation receiving a zeroed, temporary payload.

The second input determines which path is taken. It is supplied to F-6fe6e440b0b4. A null result selects the fallback; a non-null result selects an operation located through the returned object’s dispatch structure.

The first input is forwarded on both paths. The third and fourth inputs are copied into temporary storage in the recovered representation, but neither contributes a surviving value to the fallback payload: all three temporary words are cleared before that payload is passed onward. On the non-null path, the third and fourth inputs are not explicitly forwarded to the selected operation.

This is a static behavioral contract. No runtime tests have been performed. “Object,” “dispatch structure,” and “payload” describe observed roles, not established application-level types.

## Behavior

### Resolution and path selection

The returned reference is compared with null. There are two mutually exclusive paths, with no retry, iteration, or second resolution call.

### Null-result fallback

If F-6fe6e440b0b4 returns null:

1. The first temporary word is set to zero.
2. The second temporary word is set to zero.
3. The third temporary word is set to zero.
4. The unresolved external operation D-01 is invoked with:
   - the first input;
   - the address of the first temporary word;
   - the numeric value 10.
5. The function returns if D-01 returns normally.

The null result is treated as a branch condition, not as an error that is reported directly to the caller.

The fallback does not preserve the original second, third, or fourth input values in the passed temporary region. Clearing occurs after the resolution call, so the payload values shown at the fallback invocation are zero even if the initial copied inputs were nonzero.

The numeric argument 10 must not be silently replaced with 12 merely because the represented temporary region contains three 32-bit words. Conversely, the supplied material does not prove that D-01 treats this argument as a byte length or that it restricts its accesses to 10 bytes.

### Non-null indirect operation

1. A 32-bit integer value is read from the beginning of the referenced object in the recovered representation.
2. That value is used as the base for locating a dispatch entry at byte displacement 208, hexadecimal D0.
3. A callable target is obtained from that location.
4. The target, designated D-02 for this contract, is invoked with:
   - the first input;
   - the resolved object reference.
5. The function returns if the invocation returns normally.

There is no visible null check for the dispatch base or the target obtained from the entry. There is no alternate fallback if these reads or the invocation fail.

The third and fourth inputs are not explicit arguments to D-02. The original second input is not explicitly passed to D-02 either; its visible role is to produce the resolved reference.
