# F-c80cc0a8038a

## Purpose

F-c80cc0a8038a stores four caller-supplied 32-bit payloads into four fixed locations relative to a caller-supplied base address.

The payload-to-location mapping is sequential by increasing address, but the observable store sequence is not: the location for the third payload is written before the location for the second payload. This distinction matters when observing intermediate state, faults, or memory with externally visible write behavior.

The supplied static evidence establishes a fixed-offset storage operation. It does not establish the meaning of the containing object, the interpretation of the payloads, or a higher-level operation such as initialization, publication, or transaction commit.

## Behavior

### Ordered writes

The established store order is:

1. Write the first payload to the four-byte slot at base offset 0x8A4.
2. Write the third payload to the four-byte slot at base offset 0x8AC.
3. Write the second payload to the four-byte slot at base offset 0x8A8.
4. Write the fourth payload to the four-byte slot at base offset 0x8B0.
5. Return without a result value.

The distinction between address order and write order is part of the contract. Increasing-address inspection after completion shows the first, second, third, and fourth payloads, respectively. Observation during execution, where supported, instead follows first, third, second, fourth.

There is no conditional branch, loop, early successful exit, or payload-dependent choice in the supplied evidence. Every invocation that proceeds normally performs all four stores.

No explicit store targets bytes outside the listed 16-byte span. Under ordinary memory semantics, those other bytes remain unchanged by this function. This statement does not constrain effects imposed by special memory mappings or external observers.
