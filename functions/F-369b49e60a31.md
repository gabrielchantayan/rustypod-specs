# F-369b49e60a31

## Purpose

F-369b49e60a31 exposes an incompletely recovered, state-dependent sequence of memory accesses and indirect calls. The supplied representation establishes a byte write, an initial call producing a 64-bit result, further memory accesses, an ordered call sequence, and a final unresolved indirect transfer.

No application-level purpose is established. In particular, the evidence does not establish that the function initializes an object, decodes data, dispatches an event, or manages a resource.

A significant constraint is that the represented signed-overflow condition cannot become true under the stated operand widths. Its left operand is a zero-extended 16-bit value and its right operand is 67. Their mathematical difference always fits in signed 32 bits. Consequently, the represented software-interrupt path and later exceptional branch are unreachable under that arithmetic interpretation.

This is a static behavioral contract, not a claim that the supplied representation faithfully describes executable instructions. Invalid-instruction and unresolved-control-flow annotations materially limit that conclusion.

## Behavior

### 1. Initial byte write and first dependency

The first explicit memory operation writes one byte at an address obtained by adding 0x1D to the entry token. The byte written is the entry token’s low eight bits.

Next, F-U01 is invoked using a destination derived from the entry link. Its single represented argument is the four-byte stack word at displacement 0x324.

The represented result is 64 bits. Subsequent behavior treats it as two independent 32-bit portions:

- The low portion supplies a stored value and an address component.
- The high portion supplies another address component and a later candidate argument.

The evidence establishes no success indicator, pointer-validity guarantee, or relationship between those portions.

### 2. Four-byte write and low-address byte write

After F-U01 returns, a four-byte write stores its low 32-bit result at the address formed from the entry base plus its high 32-bit result.

The next explicit write stores the entry base’s low eight bits at absolute address 0x42.

The ordering matters: the result-dependent four-byte write precedes the byte write at 0x42. If the first write faults, the second is not reached. If destinations overlap, the later byte write may overwrite part of the earlier result.

No alignment check is represented. Whether an unaligned four-byte write is allowed is target-dependent.

### 3. Halfword read and overflow condition

The function forms a 32-bit intermediate from the high result portion plus 0x3F. It then reads an unsigned 16-bit quantity at an address constructed from:

- The low result portion.
- An additional displacement of 0x39.
- That intermediate.

Ignoring intermediate-width questions, the combined displacement is therefore the sum of the two result portions plus 0x78. This equivalent expression does not replace the represented sequence where address overflow or machine-specific behavior matters.

The loaded halfword is zero-extended to 32 bits. A signed-subtraction-overflow condition is then evaluated for that value minus 0x43.

Under the represented widths:

- The loaded value lies between 0 and 65,535.
- Its difference from 67 lies between −67 and 65,468.
- Every possible difference fits in signed 32 bits.
- The signed-overflow condition is therefore false.

This is an overflow test, not a comparison for equality, an unsigned borrow test, or a test for a value below 67.

The halfword read still occurs even though this arithmetic proves the condition false. It remains observable through faults, memory-mapped I/O, or aliasing with earlier writes.

### 4. Argument selection

The initial candidate argument for F-U02 is the zero-extended halfword value.

If the entry base is not equal to 65, that candidate is retained.

If the entry base equals 65, the candidate is replaced by the XOR of:

- The high result portion plus 0x3F, interpreted as a 32-bit value.
- The 32-bit stack-origin value shifted right by the low eight bits of the shift control.

If that XOR is nonzero, it becomes F-U02’s argument.

If that XOR is zero, the candidate is replaced again by the XOR of the entry token and the 32-bit stack-origin value.

The shift-count extraction allows values from 0 through 255. The supplied representation does not establish how counts of 32 or greater behave. A portable contract cannot silently select masking, zero-fill-to-zero, or an out-of-range language rule. Acceptance examples involving this expression use counts below 32.

The software interrupt is positioned after this selection and before F-U02. Its condition is the earlier signed-overflow result, so it is unreachable under the established 16-bit-to-32-bit arithmetic.
