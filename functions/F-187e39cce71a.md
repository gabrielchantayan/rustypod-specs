## Behavior

### Ordered dependency preparation

Before the first explicit direct-memory store, the function executes a long, straight-line sequence of indirect invocations. Most targets derive from embedded execution-location values plus 4,094 bytes; the first instead derives from the incoming control-link value.

Invocations display zero through four argument positions. Preparation includes:

- Passing dependency results shifted left by eight bits.
- Repeating transformed values across argument positions.
- Separating high and low words of 64-bit result containers.
- Retaining selected values across intervening calls.
- Consuming secondary register results with unavailable dependency contracts.
- Passing zero directly and through transformations of locally zero-valued quantities.

Calls with ignored results remain part of the invocation trace. Unknown dependencies may mutate shared memory, perform external operations, or prevent continuation. Equal arguments do not imply equal targets or effects.

The overall call ordering is represented. Individual preparation contracts and a complete per-invocation argument catalogue remain **documented_only** here.

### Arithmetic constraints

Ordinary calculations use 32-bit quantities unless a 64-bit container is explicitly involved.

Established width-sensitive properties include:

- Extraction of bits 10 through 19 yields zero through 1,023.
- Retaining the low 24 bits and then shifting right by 20 yields zero through 15.
- Right shifts by 34, 36, and 44 operate on 64-bit containers, not 32-bit operands.
- A left shift followed by a right shift need not recover discarded high bits.
- Byte and halfword stores truncate to eight and sixteen bits respectively; word stores retain their separate 32-bit contract.

Some represented signed shifts, additions, and multiplications can exceed the signed 32-bit range. A late signed right shift uses a count derived from an address’s low byte. Instruction-level overflow behavior, negative-operand behavior, and oversized-count handling are not independently established.

Machine wraparound and shift-count masking therefore remain conditional on actual instruction semantics. Unbounded mathematical arithmetic is not an equivalent default.

The initial access ordering is significant:

- A word at the final result pair’s high word plus 0x14 receives the packed address.
- Packed address plus nine receives a byte derived from that high word. Before a second byte write replaces it with the packed address’s low byte, a word at the pair’s low word scaled by 256 plus 0x54 receives the scaled address.
- The word at scaled address plus 0x14 is cleared before the byte at scaled address plus five is read.

### Shared-state capture and linked-address mutations

After those duplicate byte writes, the function evaluates the storage value associated with fixed address 0x05 and converts that value to unsigned 32-bit form. This converted value is the **converted shared base**.

Only the conversion result’s width and unsigned interpretation are established. The underlying read’s width, signedness, and extension behavior are **documented_only**. In particular, the converted shared base is not established as a byte-sized address.

This evaluation precedes the byte write of the small base’s low byte to fixed address 0x01. Subsequent accesses use the converted shared base at offsets 0x15 and 0x54 without an intervening reload of its source.

The small index’s low byte is written at converted shared base plus 0x15. Next, the saved shifted value’s low byte is written at scaled address plus 0x11, its full word is stored through the earlier loaded word plus 0x54, and the byte at scaled address plus 0x11 is cleared.

A word at converted shared base plus 0x54 is captured before that location is overwritten with the earlier word loaded from scaled address plus 0x14. Call the captured pre-replacement word the **saved link value**.

Further mutations establish these relationships:

- Small base plus 0x34 receives the small index.
- Offset-0x74 links supply bases for offset-0x54 writes.
- Saved link value plus 0x24 receives the saved link value twice.
- Another loaded base receives repeated byte writes at offset nine.
- Fixed address 0x54 receives the saved link value shifted left once.
- Small base plus 0x14 receives several word replacements, including duplicate stores of the saved link value.

One expression reads the same offset-0x74 location separately for its destination base and stored value. Operand-read order within that expression is unresolved. There is no stability guarantee permitting replacement of both reads with one snapshot.

The saved link value is scaled by four and eight. Related bases receive mixed-width writes at offsets including 0x09, 0x0D, 0x14, 0x15, 0x34, 0x44, and 0x54.

Unlike the unresolved 0x05 access, this region also contains explicit unsigned byte loads at offset five. Some of those byte values become bases for word loads at offset 0x74. Further links are loaded at offset 0x64, self-relative word stores occur at offset 0x14, and fixed address 0x15 receives the small base’s low byte.

## Acceptance examples

These are conditional static-review criteria, not executed tests.

1. **0x05 conversion without byte narrowing.** If the source evaluation and unsigned conversion produce 0x00000100, accesses through converted shared base plus 0x15 and plus 0x54 use 0x115 and 0x154, subject to valid storage. Substituting a base of zero by retaining only eight bits is unsupported.

2. **Unresolved 0x05 load semantics.** An observed byte pattern at 0x05 alone is insufficient to determine the converted shared base. Acceptance must not assume a one-byte load, zero extension, or a zero-through-255 range without additional evidence.

3. **Capture ordering at 0x05.** The storage evaluation supplying the converted shared base precedes the byte write at 0x01. A valid alias that makes this ordering observable must not be evaluated using a post-write reload instead.

4. **Small-index boundary.** If the relevant dependency result’s low seven bits are all set, the represented extraction yields small index 508 and small base 1,016, not index 511.

5. **Overlapping widths.** The small-base word clear precedes both offset-0x15 byte writes. Their numerical effect on the overlapping word depends on byte order.

6. **Shared-base boundary.** If the fixed-address-0x60 write changes storage backing the repeated-store shared word, repeated groups still use its previously captured value. If an earlier adjusted-base store affects that storage, the capture occurs after that store.

7. **Intervening byte load.** The byte supplying the third adjusted-base-plus-0x20 word store is loaded after stores of 32 and 47. An entry-time snapshot is not equivalent where aliasing or observable memory distinguishes them.

8. **Non-returning dependency.** If F-U001 does not return, later preparation calls and direct mutations are not required to occur.

9. **Invalid loaded address.** Graceful rejection is not established for an unusable loaded address. Such execution falls outside uninterrupted-completion preconditions.

10. **Final argument origins.** On reaching F-U003, the first argument is 114; the others retain their specified load origins even if equal in value.
