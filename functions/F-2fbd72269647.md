# F-2fbd72269647

## Purpose

F-2fbd72269647 describes a represented execution path that alternates indirect calls with byte and 32-bit memory accesses. Values obtained from inputs, incoming machine state, memory, and call results are shifted, masked, and reused as data or addresses.

No application-level purpose is established. The repeated offsets do not establish an object model, serialization format, allocator, collection, or device interface.

This contract separates three levels of confidence:

- **Established static evidence:** the displayed access widths, value transformations, call ordering, and argument preparation.
- **Inferred execution model:** 32-bit modular arithmetic used to interpret address calculations and overflowing shifts.
- **Documented-only unknowns:** executable decoding reliability, dependency behavior, calling conventions, ownership, and execution beyond the represented endpoint.

All behavior is conditional on execution following the represented path and each preceding operation completing. The supplied representation warns of invalid instruction data and ends without a represented normal return.

## Interface

### Inputs and incoming state

The displayed interface contains four positional 32-bit inputs:

| Input | Established use |
|---|---|
| First | No explicit body use. |
| Second | Supplied to the first indirect call. |
| Third | No explicit body use. |
| Fourth | Used as an address and shifted left by 19 bits for call arguments. |

Lack of explicit use does not prove that the first or third input is irrelevant to the executable ABI.

Additional incoming state is required:

- A control-link value determines the first call target by adding 4094.
- An unsigned 32-bit address value supplies the first byte-read address after a right shift by two.
- An unsigned 32-bit data value supplies the first byte written after a right shift by 22.
- Two later operations consume secondary call-result state whose producing interfaces are unresolved.

Consequently, the displayed four inputs are not a complete independently validated invocation interface.

### Widths and notation

A **word** is 32 bits; a **byte** is eight bits. All explanatory symbols below are document-local value labels, not source identifiers.

- \(L(x,n)\): left shift by \(n\), retaining the low 32 bits.
- \(U(x,n)\): unsigned right shift of a 32-bit value.
- \(\operatorname{byte}(x)\): the low eight bits.
- Address addition and scaling: modulo \(2^{32}\) under the inferred execution model.
- A two-word result has a low word and a high word, corresponding to bits 0–31 and 32–63 of the represented 64-bit value.

This arithmetic model is not a claim of portable signed-language overflow semantics. Two-word decomposition does not establish memory endianness or physical return-register placement.

### Outputs and preconditions

No ordinary return value is represented. Observable outputs are explicit memory writes and dependency interactions.

For the entire represented path to complete, every invoked target must be callable and return, and every explicit access must satisfy the actual machine’s mapping, permission, and alignment requirements. These conditions are not checked by the represented body.

The endpoint is an invalid-instruction termination marker. A real trap, omitted continuation, or decoding error remains unresolved.

## Behavior

### Sequence conventions

A **four-call group** means four consecutive indirect calls with no displayed arguments. When a result is named, it comes from the fourth call. A **three-call group** is defined analogously.

These groups are descriptive shorthand, not additional dependencies. “No displayed arguments” does not mean the callee cannot consume register state or other implicit inputs.

The following phases preserve the represented order of memory accesses and calls. No conditional branch, loop, validation path, or recovery path is displayed.

### 1. Incoming state and the first byte-derived destination

The initial indirect call receives the second input. A four-call group follows and supplies word **A**.

One byte is then read at the incoming address value shifted unsigned right by two, plus 1. Its zero-extended value is **B**, between 0 and 255. The procedure writes the low byte of the incoming data value shifted unsigned right by 22 at address \(B+17\).

A call receives \(L(A,2)\). A four-call group then supplies **C**.

The byte-derived write address is between 17 and 272 inclusive. Its small magnitude does not establish whether it denotes valid RAM, device memory, or an invalid address.

### 2. Two word reads and argument construction

The next explicit accesses are, in order:

1. Read word **P** at the fourth input plus 4.
2. Read word **Q** at \(B+116\).
3. Write \(\operatorname{byte}(Q)\) at \(B+1\).

A call receives four displayed arguments:

\[
Q,\quad L(\text{fourth input},19),\quad
L(\text{fourth input},19),\quad L(C,2).
\]

One call with no displayed arguments returns **T**. The next call receives \(T\) and \(U(Q,2)\). A four-call group supplies **D**.

The retained field derived from the earlier word read is \(H=U(P,22)\), so \(0\le H\le1023\). Later uses derive from this captured word; they do not reload the fourth-input address.

### 3. Word copying and nine-bit field placement

Let \(E=L(D,2)\). A word **V** is read at \(E+116\), then its low byte is written at \(E+1\).

A call receives **E**, followed by a four-call group. Secondary result state **S** available after that sequence supplies the next destination: the procedure writes **V** as a word at \(L(S,2)+20\). The exact producer and ABI interpretation of **S** remain unresolved.

A call receives **S**. One call with no displayed arguments returns **W**. The next call receives:

\[
W,\quad L(H\mathbin{\&}511,21),\quad L(H\mathbin{\&}511,21).
\]

A four-call group supplies **J**. The procedure writes \(L(H,23)\) as a word at \(L(J,2)+20\).

Both transformations of **H** retain exactly its low nine bits. The masked shift places them in bits 21–29; the shift by 23 places them in bits 23–31. **H**’s bit 9 is discarded by both, explicitly by masking in the first transformation and by 32-bit truncation in the second. Their destination bit positions differ, not their selected input bits.

### 4. Scaled storage and masking

A call receives \(L(J,2)\), and a four-call group supplies **K**.

The next word store places \(L(K,2)\) at \(L(K,4)+20\). The representation then retains:

\[
M=K\mathbin{\&}\texttt{0x3fffffff},\qquad N=U(M,2).
\]

A call receives **M**, followed by a four-call group returning **R**. The procedure writes **M** at \(L(R,2)+20\), calls with \(L(R,2)\), and obtains **X** from another four-call group.

The first store is represented before the call receiving **M**. That observable ordering matters. Its address does not require an arithmetic distinction between masked and unmasked **K**: under the stated model, \(L(K,4)=L(M,4)\), so either expression plus 20 denotes the same destination. Likewise, \(L(K,2)=L(M,2)\).

### 5. Two writes to one offset-52 address

Define:

\[
Y=L(R,3),\qquad Z=L(R,4),\qquad X_m=X\mathbin{\&}\texttt{0x3fffffff}.
\]

The procedure writes \(\operatorname{byte}(Y)\) at \(Q+1\), then writes word \(L(X,2)\) at \(Y+52\).

A call receives \(L(X,2)\). One call with no displayed arguments returns **AA**, which is passed to the next call. A four-call group supplies two-word result **AB**.

The next accesses write:

- \(\operatorname{byte}(Y)\) at \(X_m+1\);
- the high word of **AB** at \(Y+52\).

Both offset-52 stores have the same computed destination. The first cannot be treated as unobservable merely because the second replaces it: intervening calls can read or modify the location.

A call receives the low word of **AB** shifted left by two. A four-call group supplies **AC**.

### 6. Repeated byte stores and literal address 17

- \(\operatorname{byte}(L(K,2))\) at \(Z+13\).

A call receives \(L(AC,2)\) twice. One call with no displayed arguments returns **AD**. A call receives **AD** and \(U(AD,3)\), followed by a four-call group supplying **AE**.

The procedure then writes \(\operatorname{byte}(Z)\) at literal address 17 and repeats the byte store at \(Z+13\).

A call receives \(L(AE,2)\), followed by a four-call group supplying **AF**.

The earlier destination \(U(X_m,20)+17\) ranges from 17 through 1040. It equals the later literal destination only when \(U(X_m,20)=0\).

### 7. Further scaled writes and an independently read destination

### 8. Captured byte, clearing, and address 13

A fresh byte read at \(G+1\) supplies **B₂**. Zero is written at \(B₂+17\).

A call receives \(L(AI,2)\), followed by a four-call group. Define:

\[
D_b=\operatorname{byte}(U(AH,3)),\qquad D_a=2B₂.
\]

The procedure writes **D_b** at \(G+13\), then **B₂** at literal address 13. A call receives \(D_a\), 152, and 608.

One call with no displayed arguments follows. A further call receives an unsigned secondary result shifted right by three. Its producer and calling-convention meaning are unresolved.

A four-call group supplies **AJ**. A call receiving \(L(AJ,2)\) returns **AK**.

The procedure writes **D_b** at \(D_a+13\), overwrites literal address 13 with byte 192, and calls with \(L(AK,2)\).

The two reads at \(G+1\) are distinct. **B₂** is not necessarily equal to the byte used in phase 7. Also, because \(B₂\) is a byte, \(D_a\) ranges from 0 through 510 without overflow; when \(B₂=0\), the store at \(D_a+13\) itself aliases literal address 13.

## Acceptance examples

These are conditional static criteria, not executed tests.

1. **Initial byte destination.** With incoming address value 256, the first byte read is at 65. If it returns 5 and the incoming data value is `0xabc00000`, the next explicit access writes byte `0xaf` at address 22.

2. **Full word versus low byte.** If **Q** is `0x12345678`, the store at \(B+1\) writes `0x78`; the following four-argument call still receives full word `0x12345678`.

3. **Identical selected input bits.** If **P** is `0xffc00000`, **H** is 1023. The duplicated shifted argument is `0x3fe00000`, and the later shifted word store is `0xff800000`. If **H** instead equals 511, both outputs are unchanged: bit 9 contributes to neither transformation.

4. **Equivalent masked addressing.** If **K** is `0x40000001`, **M** is 1. Both \(L(K,4)+20\) and \(L(M,4)+20\) equal 36; the stored word is 4. Either address expression is acceptable under the modular model, with the store remaining before the subsequent call.

5. **Observable replacement.** The two stores at \(Y+52\) write \(L(X,2)\) and then the high word of **AB**. Acceptance does not require the first value to survive intervening calls, but does require its represented store.

6. **Independent destination reads.** If the phase-7 and phase-8 reads at \(G+1\) return 3 and 9, their byte-derived destinations are 20 and 26 respectively.

7. **Literal-address writes.** Phase 8 explicitly writes **B₂** and later 192 at address 13. Dependencies or aliased explicit accesses may add intervening writes; uninterrupted persistence is not guaranteed.

8. **Interrupted execution.** If F-U01 does not return, no later explicit access is established. If a later access faults, preceding writes are not required to roll back.
