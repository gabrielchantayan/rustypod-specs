# F-c8e72927a6ba

## Purpose

F-c8e72927a6ba performs a state-dependent operation on a receiver, using a signed adjustment input, a related object, several receiver fields, and indirect dispatches. It returns a 32-bit Boolean-like result.

The established behavior is narrower than a conventional “advance position” operation:

- One branch dispatches to a receiver operation with a value derived from an upper-bound-like field.
- The other branch computes a candidate value, conditionally replaces it, and compares it with a value obtained from a dependency.
- In that second branch, the computed candidate is **not visibly passed** to the receiver operation.
- The result depends on a final read of the receiver’s bound-like field and on a locally retained decision, not on a verified resulting position.

Position advancement, wrapping, and terminal-state handling are plausible interpretations of the arithmetic and dispatch structure. They are inferred intent, not established interface semantics.

## Interface

### Inputs

The visible interface has two inputs:

1. **Receiver address.** An address interpreted as a writable, word-addressed object containing 32-bit fields and addresses.
2. **Adjustment.** A signed 32-bit integer used only when the first dependency returns a nonzero value.

The supplied representation establishes a 32-bit object/address model. It does not establish compatibility with a native 64-bit object layout.

### Output

On ordinary completion, the function returns a 32-bit value of exactly zero or one.

It returns one precisely when both conditions hold:

- The receiver field at `0x104`, read after all branch-specific dispatches complete, is strictly positive under signed interpretation.
- The locally retained eligibility decision is true.

That decision is initialized to true. It remains true throughout the zero-result branch of the first dependency. In the nonzero-result branch, it becomes the comparison result between the final selected candidate and the value returned by F-000000000002.

- Invalid indirect-call targets.
- Arithmetic overflow.

No error code, recovery path, or exception translation is established. Faults, nonlocal exits, or nonreturning dependencies can prevent ordinary completion.

## Behavior

### Initial dispatch and status assignment

The function first obtains the related-object address from receiver offset `0x0EC`, reads that object’s dispatch-table address, and invokes F-000000000001 through table offset `0x174`.

No explicit arguments are shown for this invocation. An implicit receiver or other calling-convention inputs cannot be established from the supplied representation.

Only after this dependency returns does the function write the 32-bit value one to receiver offset `0x118`.

The dependency’s returned value is tested for zero. Its magnitude and sign otherwise have no visible effect.

The ordering is observable: the first dependency executes before the direct status assignment. Its changes to receiver memory may therefore affect the subsequent branch, field reads, or dispatches. Its own write to offset `0x118`, if any, would precede and could be overwritten by the direct assignment of one.

### Branch when F-000000000001 returns zero

The function reads the signed 32-bit field at receiver offset `0x104` and derives a value by subtracting one.

It then dispatches F-000000000003 through the receiver’s table offset `0x174`, with two explicit arguments:

- The receiver address.
- The derived value.

The adjustment input is not used on this branch. Neither the flags word at `0x048` nor the replacement field at `0x100` is read by the visible branch logic.

The locally retained eligibility decision remains true. No direct assignment of zero to offset `0x118` occurs on this branch.

After the dispatch returns, the function performs the final bound read and return decision. The receiver operation can change that final result by changing offset `0x104`.

### Branch when F-000000000001 returns nonzero

The function obtains the related-object address from receiver offset `0x0EC` again, reads its dispatch-table address again, and invokes F-000000000002 through table offset `0x170`.

This is a fresh lookup. The related object or table need not be the same as during the first dispatch if the earlier dependency changed accessible state.

No explicit arguments are shown for F-000000000002. Its result is treated as a signed 32-bit value, referred to here as the **reference value**.

The function forms an initial candidate by adding the signed adjustment input to the reference value. It then reads the signed bound at receiver offset `0x104` and compares the bound with that candidate.

#### Candidate below the bound

If the candidate is strictly less than the bound, the candidate is retained.

The flags word and replacement field are not read for candidate selection. The optional terminal dispatch is not selected.

There is no separate lower-bound check. A negative candidate can be retained.

#### Candidate at or above the bound

If the candidate is greater than or equal to the bound, the function reads the flags word at receiver offset `0x048` and tests mask `0x04000000`.

If the bit is clear:

- The candidate is replaced with a fresh read of receiver offset `0x100`.
- The optional terminal dispatch is not selected.

The replacement is used directly. It is not checked again against the bound, adjusted by the original excess, or constrained to any interval.

If the bit is set:

- The function reads receiver offset `0x104` again.
- The candidate becomes that newly read bound minus one.
- The optional terminal dispatch is selected.

The branch predicate includes equality. An initial candidate exactly equal to the bound takes this replacement logic.

### Equality decision and receiver dispatches

After candidate selection, the function compares the selected candidate with the reference value returned by F-000000000002.

If they are equal:

- The local eligibility decision becomes false.
- The function writes the 32-bit value zero to receiver offset `0x118`.

If they differ:

- The local eligibility decision becomes true.
- No additional direct status write occurs before the receiver dispatch.

The equality comparison concerns the **selected** candidate, not necessarily the initial sum. A nonzero adjustment can therefore lead to a false eligibility decision if replacement selects the reference value.

The function then invokes F-000000000003 through the receiver’s table offset `0x174`.

On this branch, only the receiver address is explicitly supplied. The selected candidate is not visibly supplied as a second argument and is not visibly written to a receiver field before the call. The contract must not equate this invocation with “set the selected candidate.”

If terminal dispatch was selected earlier, the function next invokes F-000000000004 through receiver table offset `0x184`, explicitly supplying the receiver address.

This optional invocation occurs after F-000000000003 returns. Its selection is retained locally: mutations by F-000000000003 do not cause the earlier flag or comparison to be reevaluated.

### Final return decision

After the branch-specific calls finish, the function rereads receiver offset `0x104`.

A nonpositive signed value produces return zero. A positive value produces one only if the locally retained eligibility decision is true.

Consequently:

- The first branch can return zero despite keeping eligibility true.
- The second branch can return zero despite a positive final bound.
- Neither the final status field nor any dependency’s receiver-operation return value determines the result directly.
- A dependency can change the final bound and thereby change the returned value.
- A dependency changing the status field cannot change the already retained eligibility decision.

### Integer-width boundary

All described integer fields, the adjustment, and the relevant dependency results are 32 bits. Bound comparisons and the final positivity check use signed interpretation. The flags test is a 32-bit mask operation.

Two calculations need qualification:

- Reference value plus adjustment.
- Bound minus one.

The first can exceed the signed 32-bit range. The second does so when its input is the minimum signed 32-bit value. The supplied representation does not independently establish an overflow contract. Modular wrapping, trapping, or another interpretation must not be silently selected.

Examples requiring a specific overflow outcome are therefore documented_only. Nonoverflowing arithmetic is sufficient for the examples below.

## Side effects

The function itself visibly writes only receiver offset `0x118`:

1. One, after the first dependency returns.
2. Optionally zero, after the selected candidate compares equal to the reference value on the nonzero-result branch.

These are 32-bit writes. Even the path that eventually writes zero first writes one.

The function visibly performs no allocation, deallocation, ownership transfer, or pointer retention. This does not establish that dependencies perform none of those actions.

All indirect calls may have additional effects not described by the supplied material. In particular, no preservation guarantee is established for:

- Receiver fields.
- The related-object address or contents.
- Dispatch tables.
- Global state.
- Memory ownership or object lifetime.

Ordinary continuation requires that memory needed by subsequent reads, writes, and dispatches remains valid. The function does not visibly enforce that requirement.

These examples are conditional static acceptance cases, not test results. Unless a mutation is specified, assume dependencies return normally, preserve fields relevant to subsequent decisions, and permit the stated memory accesses.

1. **Zero first result, positive bound.**

2. **Zero first result, nonpositive final bound.**

3. **Retained candidate differs from reference.**

F-000000000003 is called with only the receiver explicitly supplied. No terminal dispatch occurs. A final bound of ten yields one.

4. **Retained candidate equals reference.**  
   With reference three, adjustment zero, and bound ten, the selected candidate equals three. The direct status writes are one followed by zero. F-000000000003 still executes. The return is zero even if the final bound remains positive.

5. **Replacement without the flag.**  
   With reference eight, adjustment five, bound ten, flag bit clear, and replacement value eight, the initial candidate thirteen is replaced by eight. Equality with the reference clears the status and makes eligibility false. No terminal dispatch occurs; the return is zero.

6. **Replacement is not revalidated.**  
   With reference eight, adjustment five, bound ten, flag bit clear, and replacement value twenty, twenty is retained despite exceeding the bound. It differs from the reference. With a positive final bound, the return is one.

7. **Flagged upper-bound handling.**  
   With reference eight, adjustment two, bound ten, and the flag bit set, equality with the bound selects nine and enables terminal dispatch. F-000000000003 executes before F-000000000004. A positive final bound yields one because nine differs from eight.

8. **Terminal dispatch despite unchanged candidate.**  
   With reference nine, adjustment one, bound ten, and the flag bit set, replacement selects nine. Eligibility becomes false and the status is directly cleared, but both receiver dispatches still execute. The return is zero.

9. **Negative candidate without correction.**  
   With reference one, adjustment negative five, and bound ten, the selected candidate is negative four. No lower-bound correction occurs. It differs from the reference, so a positive final bound yields one.

10. **Mutation during receiver dispatch.**  
    In any otherwise eligible case, if a receiver dependency changes the final bound to zero, the return is zero. A status-field mutation alone does not revise eligibility.
