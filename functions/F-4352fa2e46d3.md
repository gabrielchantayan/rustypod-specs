# F-4352fa2e46d3

## Purpose

F-4352fa2e46d3 coordinates a provider query, context-dependent configuration, optional selection of a returned record, conditional publication of a trailing range, and four ordered notification slots.

Its established behavior is procedural, not transactional: configuration, selection, output writes, and notifications are not rolled back when a dependency returns a failure status. A nonzero record-query result suppresses record selection but does not suppress the range calculation or notifications.

The apparent intent is to configure a shared resource for an interval, select the first eligible record, and report any remaining range through a configured upper boundary. The resource’s meaning, the units of the interval, and the interpretation of record types are not established.

## Interface

The function accepts five arguments and returns a 32-bit status value.

| Argument | Representation | Established use |
|---|---|---|
| Origin | 32-bit integer | Added to the extent to form an endpoint. Otherwise unused directly. |
| Extent | 32-bit integer | Multiplied by a provider-supplied factor for configuration; also added to the origin. |
| Context | Opaque 32-bit value | Forwarded unchanged to three dependencies and, conditionally, a fourth. |
| Start output | Address of a writable 32-bit word | Written only when the trailing-range condition holds. |
| Length output | Address of a writable 32-bit word | Cleared before the provider callback, then conditionally replaced with a range length. |

Although the supplied representation declares the origin and extent as signed integers, the endpoint comparison, boundary sentinel, and scale shift use unsigned 32-bit values. Negative-looking input bit patterns are not rejected.

The return value is:

- the result of F-f5b72f3fca12 if that result is nonzero;
- zero if F-f5b72f3fca12 succeeds and no eligible record is found;
- the result of F-aab7e591cdc0 if an eligible record is found.

No separate return status represents the range calculation, configuration outcome, or notification outcomes.

The two output addresses are not checked for aliasing. Their observable behavior follows the write order specified below; they are not guaranteed to contain two independently meaningful results if they designate the same word.

## Behavior

### 1. Establish local defaults and obtain the provider factor

Two local 32-bit boundary words are initialized to 63. One is subsequently interpreted as an unsigned lower boundary, including a special sentinel value; the other is used as an additive span.

F-fbcf824e7197 is called without arguments. After that call returns, the function writes zero to the caller’s length output.

The function then reads the callable target at offset 8 in the returned provider object and calls it with the address of a local 32-bit factor. No explicit initial value is supplied for that factor. Its usable value therefore depends on the callback writing it.

This ordering is observable: F-fbcf824e7197 runs before the function clears the length output, while the provider callback runs after that clearing.

### 2. Resolve boundaries

F-83df1ae37791 is called with:

1. the unchanged context;
2. the address of the lower-boundary word;
3. the address of the additive-span word.

Both words initially contain 63. The function does not inspect a status from this dependency.

If the dependency leaves either word untouched, that word retains its default. This does not establish that retaining defaults is an intended success or failure convention.

The lower-boundary bit pattern `0xFFFFFFFF` disables subsequent trailing-range output. The additive span has no independently recognized sentinel in this function.

### 3. Configure the shared resource

After boundary resolution, the function obtains the address of a shared resource-handle cell. It reads the current handle from that cell and calls F-eecbce9995d1 with:

1. the current handle;
2. the literal value 1;
3. a scaled extent;
4. the unchanged context.

The scaled extent is formed by multiplying the extent by the provider factor, interpreting the 32-bit product as unsigned, and shifting it right by 10 bits. Thus the shift is logical, not signed, and discards the product’s lowest ten bits.

The supplied representation contains no wider intermediate or overflow check. The intended 32-bit-machine interpretation is the low 32 bits of the product, divided by 1024 with truncation toward zero as an unsigned quantity. Exact overflow behavior remains subject to the evidence limitation recorded under **Uncertainties**.

The result of F-eecbce9995d1 is not used to gate later work and does not become this function’s return value.

### 4. Query and optionally select a record

The current handle is read again from the captured handle-cell address. It is passed to F-f5b72f3fca12 together with the address of a local query area and the context.

The represented local layout is:

| Offset from query-area start | Size | Use |
|---|---:|---|
| 0 | 4 bytes | Passed as the beginning of the query area; not directly interpreted afterward by this function. |
| 4 | 4 bytes | Unsigned record count. |
| 8 | 96 bytes | Record storage, examined with a 12-byte stride. |

This establishes the layout consumed by this function, not the full dependency’s public schema. No zero-initialization of the query area is visible before the call.

If the query returns nonzero, the function performs no record scan and retains that result as its eventual return value.

If the query returns zero, the function examines records in ascending index order. For each examined record, it reads only the first byte. A record is eligible when that byte equals 1 or 2.

The scan stops at the first eligible record. It does not prefer type 1 over type 2 or inspect later records for a better match. If a match exists, F-aab7e591cdc0 is called with:

1. a freshly read handle from the same captured handle-cell address;
2. a pointer to the matched 12-byte record;
3. the unchanged context.

The selection result replaces the query result as the eventual return value.

If the count is zero, or all examined records have other first-byte values, selection is skipped and the retained result is zero.

There is no visible enforcement that the count fits the 96-byte record area. That area accommodates eight 12-byte records. A count greater than eight can cause an out-of-area read if the scan reaches index eight; an earlier eligible record can stop the scan before that happens.

### 5. Calculate and conditionally publish the trailing range

After the query and optional selection, the function forms an unsigned 32-bit endpoint from origin plus extent.

For this section, define:

- **Endpoint**: the 32-bit origin-plus-extent result.
- **Lower boundary**: the unsigned word produced by boundary resolution.
- **Terminal boundary**: the 32-bit sum of the lower boundary and additive span.

The function writes a trailing range exactly when:

- the lower boundary is not `0xFFFFFFFF`; and
- the endpoint is strictly less than the terminal boundary under unsigned comparison.

When both conditions hold, the writes occur in this order:

1. Write endpoint plus one to the start output.
2. Write terminal boundary minus endpoint to the length output.

Equality does not produce an output range. If the condition fails, this stage does not write either output. In the absence of intervening external modification, the length output remains zero from the earlier clearing, while the start output retains its previous contents.

The terminal boundary is compared after 32-bit addition; the function does not reject a wrapped sum or interpret it as a wider mathematical boundary.

For a successful range condition, the reported length is consistent with an inclusive interval from endpoint plus one through the terminal boundary. That interval interpretation is inferred intent; the established behavior is the two numeric writes.

If both output arguments identify the same word, the final length write overwrites the preceding start write.

### 6. Invoke notification slots and return

The function obtains the notification-table base after completing the range-output stage. It processes exactly four slots in ascending order.

Each slot occupies eight bytes:

- a callable-target field at offset 0;
- an opaque 32-bit argument field at offset 4.

For each slot, the function reads the callable target. A null target is skipped. For a nonnull target, it reads the associated argument and calls the target with:

1. the endpoint;
2. that slot’s associated argument.

Callback results are ignored. Notifications run regardless of query or selection status and regardless of whether a trailing range was published.

The function then returns the retained query or selection result.

The table is not copied before iteration. Consequently, earlier callbacks can affect later slots if they can access the table. The base used for iteration has already been captured, so changing a separate source of the base does not by itself redirect the remaining slot accesses.

## Side effects

Directly established side effects are:

- clearing the length output before the provider callback;
- conditionally writing the start output and then the length output;
- invoking configuration, query, optional selection, and notification operations in the stated order.

No direct allocation, deallocation, resource release, or ownership transfer is visible.

Pointers to local storage are passed to the provider callback, F-83df1ae37791, F-f5b72f3fca12, and optionally F-aab7e591cdc0. That storage is valid during this invocation; the supplied evidence does not establish permission for dependencies to retain those pointers after return.

The function must not be treated as preserving shared state across dependency calls. In particular, the shared handle is reread for configuration, query, and selection rather than assumed constant. Any mutation performed inside a dependency or callback is outside the directly established effects.

The output clearing occurs only after the provider lookup returns. An abnormal exit before that point need not clear the length output. An abnormal exit later can leave partial effects; no cleanup or rollback path is visible.

## Acceptance examples

These examples are conditional specifications, not observed executions. They assume valid storage, returning callbacks, and no external modification except where stated.

1. **Strictly trailing range.**  
   Origin 100 and extent 20 produce endpoint 120. A lower boundary of 100 and additive span of 50 produce terminal boundary 150. The start output becomes 121 and the length output becomes 30. Every nonnull notification receives endpoint 120.

2. **Boundary equality.**  
   Endpoint 150 with terminal boundary 150 causes no range-stage writes. The start output remains unchanged; the length output remains zero if dependencies have not modified it. Notifications still run.

3. **Disabled boundary.**  
   A lower boundary of `0xFFFFFFFF` suppresses trailing-range output regardless of the additive span. Query, optional selection, and notification processing are unaffected.

4. **First eligible record wins.**  
   With record first bytes 9, 2, and 1, selection receives the second record. The third record is not examined. The selection result is returned after notifications.

5. **Empty successful query.**  
   A zero query result and a zero record count cause no record access or selection call. The eventual result is zero, while range processing and notifications still occur.

6. **Query failure does not suppress later effects.**  
   If the query returns status 7, selection is skipped and the eventual result is 7. A qualifying trailing range is still written, and nonnull notification slots are still invoked.

7. **Logical scaling.**  
   An extent of 3 and factor 1024 yield a scaled extent of 3. Under the intended 32-bit arithmetic interpretation, a product bit pattern of `0x80000000` yields `0x00200000`, not a sign-extended result.

8. **Wrapped terminal boundary.**  
   A lower boundary of `0xFFFFFFF0` and additive span of 32 yield terminal boundary 16 under 32-bit wrapping addition. Endpoint 20 therefore produces no trailing range; the function does not compare it against an unbounded sum.

9. **Aliased outputs.**  
   If both output arguments identify one word and the qualifying endpoint and terminal boundary are 120 and 150, that word is first cleared, then written with 121, then written with 30. Its final value is 30 absent later external modification.

10. **Mutable notification table.**  
    If the first callback replaces the second slot’s target before that slot is visited, processing uses the second slot’s subsequently read target, not a snapshot taken before the first callback.
