# F-b1f76373caa0

## Purpose

F-b1f76373caa0 conditionally converts a four-argument invocation into a downstream dispatch operation. A signed selector and a global comparison value determine whether the function returns without calling any dependency or constructs one of three dispatch forms:

- A pointer to a 32-bit value, accompanied by the value 1.
- A null pointer, accompanied by the value 0.
- A pointer to a packed 32-bit value, accompanied by the value 8.

For a selected invocation, the function obtains a context-derived value, passes that value and the selected arguments to a dispatch dependency, and passes the dispatch result to a final dependency.

This is an established structural description, not an identification of the application protocol. Meanings such as “message,” “event,” “payload length,” or “ownership transfer” are not established by the supplied evidence.

## Behavior

### 1. Initial state

The function preserves the selector for later forwarding and initializes a local 32-bit forwarding value from the third argument.

It then compares the selector with the threshold.

The original selector remains the selector supplied to the dispatch dependency. The local arithmetic used for classification does not replace it.

### 2. Threshold equality has priority

If the selector equals the threshold at the initial comparison, the function selects the **packed form**.

This equality case takes priority over every numeric selector category described below. For example, if the threshold equals `0x000E0002`, that selector takes the packed form rather than the null-pointer form.

If the initial equality comparison fails, the function performs a further comparison to determine whether the selector is below the threshold. These are distinct source-level uses of the global value; a single immutable threshold snapshot is not explicitly established.

The decision tables below assume the threshold remains stable across those comparisons. Concurrent or asynchronous modification is addressed under Uncertainties.

### 3. Selectors below the threshold

When the initial equality comparison fails and the selector is less than the threshold, selection is as follows:

| Selector | Selected form |
|---|---|
| `0x000E0001` | Pointer form with accompanying value 1 |
| `0x000E0002` | Null-pointer form with accompanying value 0 |
| `0x000E0003` | Null-pointer form with accompanying value 0 |
| `0x000E0004` | Pointer form with accompanying value 1 |
| Other values | Return without dependency calls |

The check corresponding to `0x000E0003` is represented by subtracting `0x000E0000` and comparing the result with 3. At this named selector, the arithmetic is exactly representable as a signed 32-bit integer.

### 4. Selectors taking the other comparison branch

When the initial equality comparison fails and the subsequent “less than threshold” test is false, selection is as follows:

| Selector | Selected form |
|---|---|

The check corresponding to `0x000E0011` is represented by subtracting `0x000E0000` and comparing the result with 17. At this named selector, the arithmetic is exactly representable as a signed 32-bit integer.

A numeric selector is not accepted merely because it appears in either table. It must reach the corresponding comparison branch, unless initial threshold equality selects the packed form first.

### 5. Constructing the selected form

#### Pointer form with accompanying value 1

The local forwarding value remains equal to the third argument.

The function obtains a context-derived value through the first two dependency calls described below. It then dispatches:

- That context-derived value.
- The original selector.
- A pointer to the 32-bit local forwarding value.
- The 32-bit value 1.
- The original selector again.

No packing or truncation is applied to the third argument on this path.

#### Null-pointer form with accompanying value 0

Before obtaining the context-derived value, the function replaces the local forwarding value with the fourth argument.

The dispatch arguments are:

- The context-derived value.
- The original selector.
- A null pointer.
- The 32-bit value 0.
- The original selector again.

The assignment from the fourth argument does not itself expose a pointer to that local value. The dispatch receives null, not the address of the assigned storage.

The evidence does not establish a separate externally observable effect from this local assignment.

#### Packed form with accompanying value 8

The function constructs a 32-bit packed value with this layout:

| Bit range | Contents |
|---|---|
| 31–16 | Bits 31–16 of the third argument |
| 15–0 | Bits 15–0 of the fourth argument |

Equivalently, the packed value preserves the upper 16 bits of the third argument and replaces its lower 16 bits with the lower 16 bits of the fourth argument.

The lower half of the third argument and the upper half of the fourth argument do not contribute to this packed value. The operation is bitwise packing, not signed addition or sign extension.

The dispatch arguments are:

- The context-derived value.
- The original selector.
- A pointer to the local 32-bit packed value.
- The 32-bit value 8.
- The original selector again.

The accompanying value 8 is not established to be a byte count. The evidence identifies a 32-bit initialized object at the supplied pointer; it does not establish an eight-byte object layout.

The separate forwarding storage was initialized from the third argument, but adjacency between that storage and the packed object is not established. No contract for reading a second word through the packed pointer can be derived from the supplied material.

## Acceptance examples

These are conditional static acceptance examples, not runtime observations. Assume dependencies return normally and the threshold is stable unless stated otherwise.

1. **Equality overrides ordinary selector handling.**  
   If the threshold and selector both equal `0x000E0002`, the packed form is selected. The dispatch receives a pointer to the packed value and accompanying value 8, not null and 0.

2. **Preserve the full third argument on the pointer form.**  
   If the threshold is greater than `0x000E0001` and the selector is `0x000E0001`, the dispatch receives a pointer to a 32-bit value equal to the entire third argument, accompanied by 1.

3. **Null form below the threshold.**  
   If the threshold is greater than `0x000E0003` and the selector is `0x000E0003`, the dispatch receives null and 0. The fourth argument’s local assignment does not turn this into a pointer-bearing dispatch.

4. **Branch eligibility matters.**  
   If the threshold is less than `0x000E0001` and the selector is `0x000E0001`, the selector reaches the upper comparison branch and is rejected. No dependency is called.

5. **Packing preserves the specified halves.**  
   If the selector is `0x000E0007`, the threshold is lower, the third argument is `0xA1B2C3D4`, and the fourth argument is `0x55667788`, the packed value is `0xA1B27788`. Its address is accompanied by 8.

6. **Upper-branch null form.**  
   If the threshold is less than `0x000E0011` and the selector is `0x000E0011`, the dispatch receives null and 0.

7. **Unlisted selector rejection.**  
   With threshold `0x000E0005` and selector `0x000E0006`, no dependency is called.

8. **Opaque zero results are forwarded.**  
   If F-afb630a7107c returns zero on a selected path, F-9a5c97dc580d still receives that zero as its first argument. No visible zero-result rejection intervenes.

9. **Original selector is duplicated unchanged.**  
   On every selected path, the second and fifth dispatch arguments equal the original selector, regardless of classification arithmetic.
