- A 32-bit return value that is always `1` on every explicit normal-return path.
- A one-byte outcome that is `0` only when two dependent queries, invoked in sequence, both return zero. Otherwise, this outcome is `1`.

The function is not a transactional operation. Its object-field write, dependency calls, and callbacks precede the final outcome write. The shown behavior contains no rollback path.

## Behavior

### Initial update

The function first reads the unsigned byte at object offset `28` and retains that original value for later comparisons.

It then writes the low eight bits of the requested 32-bit value to the same byte location. This write precedes every dependency and callback shown in the body.

The retained original value is not refreshed after any dependency call. Later comparisons therefore use the entry-time byte, not a reread of the object field.

The distinction between storage and comparison is essential:

- Storage truncates the requested value to eight bits.
- Comparison promotes the retained unsigned byte to the requested value’s 32-bit unsigned comparison domain.
- The comparison does not truncate the requested value.

Consequently, an original byte of `1` and a requested value of `257` compare as unequal, even though the direct store writes `1` back to the object. Every requested value above `255` compares unequal to every possible original byte.

### Branch on the original byte and full requested value

After the offset-`48` callback returns, the function compares the retained original byte with the full requested value.

If they are unequal:

1. It invokes the callback at dispatch-table byte offset `8`.
2. After that callback returns, it invokes the callback at dispatch-table byte offset `12`.

If they are equal, both callbacks are skipped at this stage.
