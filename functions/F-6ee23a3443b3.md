## Behavior

### Dependency phase and arithmetic

The first indirect target depends on incoming control-context state with an added displacement of `0xFFE`. Its ordinary result is shifted left by eight bits for a subsequent call.

A long straight-line call sequence follows. Calls have zero through four represented arguments. Results may be forwarded unchanged, retained across calls, shifted, masked, split, or supplied in multiple argument positions. Explicit zero arguments are frequent. Additional machine-result state also supplies arguments.

There is no explicit branch or loop governing this sequence in the supplied representation. Calls without explicit arguments can still consume implicit state. Calls whose ordinary results are unused can still have observable effects.

The arithmetic includes:

- Low-field masks with widths including 11 through 24 bits.
- Extraction of bits 10–19 by retaining twenty low bits and shifting right ten.
- Extraction of bits 11–17 by retaining eighteen low bits and shifting right eleven.
- Movement of a selected single bit to bit 16.
- Scaling by two, four, eight, and `0x02000000`.
- Subtraction of `0x96` before further scaling.

**[INFERENCE]:** under a 32-bit machine-bit-vector interpretation, arithmetic truncates to 32 bits where represented as a word-sized operation. Consecutive shifts must retain their intermediate widths. A left shift by 25 followed by a left shift by eleven therefore produces zero under that interpretation, rather than preserving a 36-bit displacement in a wider temporary.

Portable signed-overflow rules do not establish the executable meaning of the represented signed operations. Signed overflow, negative-value shifts, and oversized shift counts remain **documented_only** without independent machine evidence.

### Opening memory updates

The direct-memory phase begins after the final ordinary dependency result. A word store through that result’s high portion precedes a byte store through a retained derived base. A separately scaled low portion supplies another word-store destination. The earlier byte destination is then written again.

A derived word at offset `0x14` is cleared before an unsigned byte is read at offset `0x05` of the same base. Another derived word at offset `0x14` is cleared before the captured byte is widened and stored as a word at offset `0x34` of the first base. The first cleared word is then read. Another clear and two repeated byte stores to a scaled base’s offset `0x15` follow.

These are access-order requirements, not unconditional final-state guarantees. Any computed destinations may overlap.

The first fixed-location accesses occur at this point:

- An unsigned byte is read from **absolute address `0x05`**.
- The low byte of the doubled derived base is written to **absolute address `0x01`**.
- The captured unsigned byte from `0x05` becomes a base for a computed byte write at offset `0x15`.
- Computed updates then include two writes at another base’s offset `0x11`, with a word store through the captured cleared-word value between them.

The absolute byte read at `0x05` is distinct from later reads at offset `0x05` of computed bases.

## Acceptance examples

These are conditional criteria, not executed tests.

### Unsigned widening

If a reached unsigned byte read yields `0xE3`, the associated widened word value is `0x000000E3`, not a sign-extended negative value.

### Fixed-word setup ordering

If accesses are individually observable, the read at `0x087FBBBC` precedes the word write of `0x20` at `0x60`. The repeated run uses the captured read value even if the later write changes the underlying mapped storage.

### Mutation between captures

If byte address `0x3A` overlaps the later linked-doubled-base offset-`0x14` word, that capture must reflect memory after the byte write, subject to the environment’s byte order and memory rules. Treating all four late captures as a single pre-mutation snapshot is unacceptable.

### Fresh propagation reads

Suppose the initial write to `0x67` stores `0x12`, but an intervening computed write changes that byte to `0x34` before a later propagation read. In ordinary memory without further interference, that later computed byte destination receives `0x34`, not the originally captured `0x12`.

### Width preservation

The three `0x3A` stores have widths of 8, 16, and 32 bits. The late update-base offset-`0x10` store is 32 bits despite an earlier byte store at that offset.

### Ordered replacements

The update-base offset-`0x20` word receives `0x20`, `0x2F`, the intervening byte-derived value, and `0x20`, in that order. An observable trace containing only the final store is insufficient.

### Aliased clear

A word cleared at offset `0x14` reads back as zero only if no intervening overlapping write or external mutation changes it. Zero is not unconditional.

### Truncation and interrupted execution

Under the 32-bit bit-vector interpretation, successive left shifts by 25 and eleven produce zero. If a dependency never returns, later calls, stores, and terminal arguments need not occur; rollback is not promised.
